# À propos

## Les booléens en Julia

Les valeurs vrai ou faux sont représentées par le type `Bool`.
Il ne contient que deux valeurs : `true` et `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

Contrairement à plusieurs autres langages, Julia a délibérément choisi de ne pas avoir de notion de _truthiness_, et seules les expressions qui s'évaluent à `true` ou `false` seront traitées comme un `Bool`.

Plus précisément, les tableaux ou les _strings_ vides ne seront *pas* interprétés comme `false`.
Il faut un test approprié, comme `isempty()`, si tu veux un traitement particulier des valeurs vides.

## Les opérateurs booléens

Il existe trois [opérateurs booléens][boolean-operators] en Julia.

`&&` est le « et » booléen.
Il s'évalue à `true` si les expressions des *deux* côtés de `&&` sont `true`.

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||` est le « ou » booléen.
Il s'évalue à `true` si une expression d'*un côté ou de l'autre* de `||` est `true`.

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!` est le « non » booléen.
Il échange (inverse) les valeurs `true` et `false`.

```julia-repl
julia> !true
false

julia> !false
true
```

Des opérateurs similaires seront conceptuellement familiers aux utilisateurs de nombreux autres langages, même si la syntaxe exacte peut varier d'un langage à l'autre.

## La priorité des opérateurs

Dans des expressions plus complexes, il peut être utile de savoir que `&&` a une [priorité][operator-precedence] légèrement supérieure à celle de `||` *(de la même façon que `*` est appliqué avant `+` dans les expressions arithmétiques)*.

S'appuyer là-dessus peut être déroutant et source d'erreurs.
Pour plus de clarté, utilise des parenthèses pour expliciter ton intention.

## Évaluation en court-circuit

L'expression `true || x` dépend-elle de la valeur de `x`, ou le compilateur peut-il ignorer `x` ?

Julia évalue les expressions booléennes de gauche à droite, et s'arrête dès que le résultat est sans ambiguïté.

Par exemple, `true || x` doit valoir `true`, quelle que soit la valeur de `x`, donc `x` n'est pas évalué.
De même, `false && y` vaut `false`, sans qu'il soit nécessaire d'évaluer `y`.

À l'inverse, `true && x` vaut `true` *uniquement si* `x` est `true`, donc `x` doit être évalué.

De même, si l'on enchaîne plusieurs opérateurs :

```julia-repl
julia> true && false && something_else
false
```

Comme `true && false` doit valoir `false`, `something_else` n'a pas d'importance et est ignoré par le compilateur.

Dans ce cas, `something_else` n'existait pas comme variable, mais le fait de l'inclure dans ce contexte n'a produit aucune erreur *(teste-le dans le REPL si tu en doutes)*.

Ce type d'évaluation en court-circuit est assez souvent utilisé par les développeurs Julia comme un raccourci pour intercepter les problèmes d'exécution et les cas limites :

```julia
all_ok || do_something()

is_problem && do_something_else()
```

Par exemple, `do_something` peut être un `return` anticipé de la fonction si `all_ok` est `false`, ou l'affectation d'une valeur par défaut à une variable avant de continuer.

C'est un léger abus de la syntaxe booléenne, mais cela peut être très pratique.

## Comment les Bool fonctionnent en interne

Si un Bool est inclus dans une expression *arithmétique*, `true` est interprété comme `1` et `false` comme `0`, ce qui reflète la façon dont ils sont stockés.

Si tu as l'habitude des langages de bas niveau (C et similaires), évite *vraiment* d'y recourir souvent.
Cela réduira la lisibilité du code et rendra le débogage plus difficile.

Il t'arrivera parfois de voir les valeurs numériques utilisées comme un moyen rapide de compter combien d'éléments sont `true`.

```julia-repl
julia> true + false + true
2
```
