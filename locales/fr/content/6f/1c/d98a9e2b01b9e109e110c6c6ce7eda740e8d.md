# Nombres à virgule flottante

`FLTD` contient un nombre qui peut comporter une partie fractionnaire. Un littéral doit comporter un point décimal et un `d` :

```sather
   440.0d
   0.5d
   -2.25d
```

`FLT` reprend la même idée avec deux fois moins de précision. Ce parcours utilise `FLTD` partout ; rien ne justifie de recourir à `FLT`, sauf si la mémoire est comptée.

## Arithmétique

| Opérateur | Signification |
| --- | --- |
| `+` `-` `*` | comme pour `INT` |
| `/` | division, en conservant la partie fractionnaire |

Il n'y a pas d'opérateur `%` pour `FLTD`.

Les deux opérandes doivent être de type `FLTD`. Mélanger un `INT` provoque une erreur de compilation, et non une conversion silencieuse, ce qui est voulu : le seul endroit où ça fait mal est précisément celui où on se trompe.

## Conversions

```sather
   7.fltd            -- 7.0, an INT made into an FLTD
   7.5d.int          -- 7, the fraction thrown away
   7.5d.round        -- 8, to the nearest whole number
   7.5d.floor        -- 7.0, down to a whole number
   7.5d.ceiling      -- 8.0, up to a whole number
```

Convertis avant de diviser, jamais après : `n.fltd / 2.0d` conserve la moitié, alors que `(n / 2).fltd` l'a déjà perdue.

## Routines utiles

```sather
   (-2.5d).abs       -- 2.5
   2.0d.sqrt         -- 1.41421
   (2.0d).max(3.0d)  -- 3.0
```

## Les nombres à virgule flottante sont approximatifs

Une valeur `FLTD` représente une approximation très proche, pas la valeur exacte. La plupart des fractions décimales ne peuvent pas être stockées exactement, de la même manière qu'un tiers ne peut pas s'écrire exactement en notation décimale. Ainsi :

```sather
0.1d + 0.2d          -- very nearly 0.3, but not exactly
```

Deux conséquences à retenir :

**Ne compare pas avec `=`.** Deux calculs censés donner le même résultat diffèrent souvent sur les derniers chiffres. Demande plutôt s'ils sont proches :

```sather
   (a - b).abs < 0.0001d
```

**Additionner beaucoup de petites valeurs fait perdre en précision.** Chaque addition arrondit un peu, et les erreurs s'accumulent.

Quand les valeurs doivent être exactes, en particulier pour l'argent, compte plutôt en unités entières avec `INT` (des cents plutôt que des dollars).

## Affichage

`.str` affiche environ six chiffres significatifs, ce qui est en dessous de la précision réellement conservée :

```sather
   #OUT + (1.0d / 3.0d).str;      -- 0.333333
```
