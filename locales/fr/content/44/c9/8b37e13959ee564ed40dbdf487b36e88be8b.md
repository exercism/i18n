# À propos

Elixir utilise les [comportements][behaviours] pour fournir des interfaces génériques communes tout en facilitant des implémentations spécifiques pour chaque module qui implémente le comportement. L'un de ces comportements est le comportement Access.

Le comportement Access fournit une interface commune pour récupérer des données à partir d'une clé dans une structure de données. Il est implémenté pour les _maps_ et les listes de mots-clés.

Le module [`Access`][access] définit les _callbacks_ requis pour l'interface. Les modules [`Map`][map] et [`Keyword`][keyword] implémentent ensuite les _callbacks_ requis [`fetch/2`][map-fetch], [`get_and_update/3`][map-get-and-update] et [`pop/2`][map-pop].

Pour utiliser le comportement, on peut faire suivre une variable liée de crochets, puis utiliser la clé pour récupérer la valeur associée à cette clé. Les _maps_ prennent en charge des clés de n'importe quel type, alors que les listes de mots-clés n'acceptent que des clés de type atome.

```elixir
# Atom as key
my_map = %{key: "my value"}
my_map[:key]
# => "my value"

# String as key
another_map = %{"key" => "my value"}
another_map["key"]
# => "my value"
```

Si la clé n'existe pas dans la structure de données, c'est `nil` qui est renvoyé. Cela peut être une source de comportement inattendu, car aucune erreur n'est levée.

```elixir
my_map = %{key: "my value"}
my_map[:wrong_key][:other_wrong_key]
# => nil
```

À noter que `nil` implémente lui-même le comportement Access et renvoie toujours `nil`, quelle que soit la clé.

```elixir
nil[:key]
# => nil
```

Les _structs_ n'implémentent pas le comportement Access.
