# À propos

Une déclaration `GENERIC:` introduit un mot dont le comportement dépend de la classe de l'un de ses arguments. Le comportement concret est fourni par des *méthodes* (`M:`) qui ciblent des classes précises.

```factor
GENERIC: stringify ( obj -- str )
M: integer stringify number>string ;
M: string  stringify ;
M: f       stringify drop "(none)" ;
```

Quand on appelle `stringify`, Factor inspecte le sommet de la pile, cherche la méthode la plus spécifique dont la classe correspond, puis l'exécute. Si aucune méthode ne correspond, une erreur est levée.

## Classe de répartition

Par défaut, la répartition se fait sur l'argument au sommet de la pile (la première entrée déclarée dans l'effet de pile). Pour une répartition à plusieurs arguments, voir `HOOK:` et `MATH:`, qui se répartissent respectivement sur le deuxième argument et sur la promotion numérique.

## Ajoute des méthodes à un générique

On peut étendre un générique à tout moment, même depuis un autre vocabulaire, à condition de pouvoir `USE:` le générique et la classe :

```factor
USING: math ;
M: ratio  area drop 0 ;     ! adds an `area` method for ratios
```

## Méthodes sur les classes intégrées

Les génériques fonctionnent tout aussi bien sur les classes intégrées (`integer`, `string`, `array`, `f`, `t`) que sur les tuples définis par l'utilisateur. Les méthodes sur `f` et `t` sont particulièrement utiles pour les prédicats du style « is-set? » qui ont des valeurs par défaut naturelles.

## Quand un générique est le bon choix

Utilise `GENERIC:` quand :

- Une même opération a des implémentations *vraiment différentes* selon les entrées (et pas seulement un `case` sur des étiquettes).
- On s'attend à ce que d'autres parties du code ajoutent de nouveaux types plus tard.
- On veut que le système de types garantisse que l'opération est définie pour chaque classe pertinente : Factor peut te lister les méthodes manquantes.

Si la variation se résume à une petite énumération figée d'étiquettes, un `case` est plus simple.
