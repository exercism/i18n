# Introduction

Une classe tuple peut en étendre une autre avec la syntaxe de parent `<`. La classe enfant reçoit les _slots_ du parent en plus des siens, et toute instance de l'enfant est aussi une instance du parent : `child?` implique `parent?`, et ainsi de suite jusqu'au sommet de la hiérarchie.

```factor
TUPLE: animal name age ;
TUPLE: dog < animal breed ;

"Rex" 4 "labrador" dog boa name>> .    ! => "Rex"   (inherited slot)
"Rex" 4 "labrador" dog boa dog? .      ! => t
"Rex" 4 "labrador" dog boa animal? .   ! => t       (also an animal)
```

Le constructeur `boa` (« dans l'ordre des arguments ») prend d'abord les _slots_ du parent, dans l'ordre de déclaration, puis les _slots_ propres à l'enfant. Les accesseurs générés automatiquement (`name>>`, `>>name`, `change-name`) sont eux aussi hérités : tout mot qui prend un `animal` fonctionne sur un `dog`.

Quand la classe à tester est une valeur plutôt qu'un nom fixe, `instance?` fait le même travail que le prédicat `name?`, mais prend la classe sur la pile :

```factor
USING: classes ;

"Rex" 4 "labrador" dog boa dog instance? .      ! => t
"Rex" 4 "labrador" dog boa animal instance? .   ! => t
```

`obj dog instance?` n'est que `obj dog?` avec la classe fournie à l'exécution, ce qui est pratique quand la classe est passée en argument ou choisie dynamiquement.

Les méthodes génériques dont la répartition se fait sur le parent se déclenchent pour chaque descendant, mais cette leçon appartient à [`generics`][generics] ; cet exercice reste centré sur l'aspect données.

[generics]: https://docs.factorcode.org/content/article-generic.html
