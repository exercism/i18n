# Installe Factor

Le parcours Factor utilise **Factor 0.101**. Les versions antérieures ne sont pas prises en charge.

Tu peux installer une version [stable](#stable) ou [nightly](#nightly), ou bien [compiler depuis les sources](#build-from-source).

Vérifie ton installation en lançant `factor -e='vm-version print'` : la commande devrait afficher `0.101` ou une version plus récente.

---
### Stable

<https://factorcode.org#stable-release> fournit des binaires stables dans la section « Stable release ».

---
### Nightly

<https://factorcode.org#development-release> fournit des binaires nightly dans la section « Development release ». Ces binaires sont compilés depuis git, mais seules les versions qui compilent correctement sont affichées.

---
### Compile depuis les sources

Si tu veux ce qui se fait de plus récent et que même la version nightly est trop ancienne pour toi, il te faudra un compilateur C++ moderne (GCC >=4.8 ou Clang >=3.5), `make` et `curl`.

Une fois ces quelques prérequis remplis, tu peux :

1. Télécharge le script shell `build` : [**ici** pour les systèmes de type Unix / les shells POSIX](https://raw.githubusercontent.com/factor/factor/master/build.sh) ou [**ici** pour Windows](https://raw.githubusercontent.com/factor/factor/master/build.cmd). Place-le dans le répertoire dans lequel Factor doit être installé. Un répertoire nommé `factor` contenant l'ensemble du code sera créé.

2. Lance-le avec `./build.sh install`, ou `.\build.cmd install` sous Windows. <sub>Cette commande va cloner le dépôt `git` de Factor, le compiler et télécharger une image de la VM Factor depuis <https://factorcode.org>. Ce processus peut prendre entre 2 et 20 minutes, selon ta connexion et la fréquence de ton processeur.</sub>

3. Tu peux maintenant lancer le binaire `factor` ou `factor.exe` généré dans le sous-répertoire `factor`. Essaie `factor --help` pour obtenir de l'aide. Tu peux aussi accéder à la documentation depuis la ligne de commande, ou en appuyant sur <kbd>F1</kbd> dans le Listener graphique, ce qui ouvrira le navigateur d'aide.

4. Par la suite, utilise le `build.sh` (ou `build.cmd` sous Windows) situé dans le sous-répertoire `factor` pour récupérer les dernières modifications depuis git et recompiler sur place, ainsi que pour télécharger une nouvelle image de la VM si nécessaire.

La structure des fichiers peut maintenant ressembler à ceci :

```
.
├── build.sh                   <- delete if you like
└── factor
    ├── basis
    ├── boot.unix-x86.64.image
    ├── build.cmd              <- use these from now on
    ├── build.sh               <-
    ├── core
    ├── extra
    ├── factor
    ├── Factor.app
    ├── factor.image
    ├── GNUmakefile
    ├── libfactor.a
    ├── libfactor-ffi-test.so
    ├── LICENSE.txt
    ├── misc
    ├── Nmakefile
    ├── README.md
    ├── unmaintained
    ├── vm
    └── work
```

Tu n'as plus besoin du script `build` de premier niveau, car par la suite, c'est celui qui a été téléchargé qu'il faudra utiliser.

---

### Compile manuellement depuis les sources (non recommandé)

Clone le [dépôt](https://github.com/factor/factor) et utilise `make` dans ce dossier.

Si `make` échoue avec une erreur indiquant qu'une cible est absente, essaie `make factor` ou, si tu sais lire un Makefile, cherche la cible make correspondant à ta plateforme dans `GNUmakefile`.

Si *ça* échoue, ouvre une _issue_ sur [factor/factor](https://github.com/factor/factor) en y incluant l'erreur : les développeurs, très sympathiques, se feront un plaisir de t'aider.
