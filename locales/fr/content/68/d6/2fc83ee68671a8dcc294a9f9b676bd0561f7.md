# Traits

Un _trait_ définit un ensemble de méthodes qu'un type peut implémenter.
Les _traits_ sont utiles pour définir des méthodes qui doivent être partagées entre plusieurs types.
Quand on utilise des _traits_ avec des types génériques, les méthodes définies peuvent être appelées sur un type particulier, mais il est aussi possible de les appeler sur un autre type de données.
De manière abstraite, grâce aux _trait bounds_, on peut préciser qu'un type générique doit partager un certain comportement.

> **Remarque :** les _traits_ sont proches de ce qu'on appelle des interfaces dans d'autres langages de programmation, avec quelques différences.

## Définition d'un _trait_

Définir un _trait_ permet d'identifier les signatures de fonctions qui constituent l'ensemble des comportements qu'un type peut implémenter pour obtenir un résultat.
Ces méthodes forment le comportement d'un type.
Si on peut appeler les mêmes méthodes sur des types différents, cela signifie que les types concernés ont le même comportement.

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

D'après la définition du _trait_ `Summary` ci-dessus, la méthode `summarize` est un comportement qui ne peut être appelé que par la structure `NewsArticle`.
Si on l'invoque sur des instances d'un autre type, cela provoque une erreur de compilation.
Déclarer le _trait_ avec le mot-clé `pub` l'expose, dans ce _crate_, aux autres _crates_ qui souhaitent eux aussi l'utiliser.
Remarque aussi qu'on utilise un point-virgule après la déclaration des signatures de méthodes dans un _trait_.

Un _trait_ peut être défini avec un argument générique, ce qui permet à une fonction de prendre en argument n'importe quel type de données.
Cela apporte une certaine souplesse à la signature des fonctions, qui peuvent ainsi gérer divers types de données.
Dans le cas du _trait_ `Summary` ci-dessous, celui-ci a été repensé pour fonctionner avec n'importe quel type de données, de sorte que, quand on invoque la méthode `summarize` dessus, elle renvoie un ByteArray.

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

Un _trait_ peut contenir plusieurs méthodes dans son corps ; chaque signature de méthode déclarée tient sur une seule ligne et se termine par un point-virgule.

## Implémentation d'un _trait_ sur un type

Une fois définies les signatures de fonctions qui composent un _trait_, le compilateur vérifie qu'une implémentation est bien définie pour les types qui adoptent ce _trait_.
On a écrit ci-dessous un _crate_ de bibliothèque `aggregator` pour les médias, qui résume certaines données d'instances de `NewsArticle` et `Tweet`.
Pour la structure `NewsArticle`, on utiliserait le titre, l'auteur et le lieu pour renvoyer la valeur de la méthode `summarize` du _trait_ `Summary`, tandis que pour la structure `Tweet`, on utiliserait le nom d'utilisateur et le contenu, en supposant que le contenu du tweet est limité à 280 caractères.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## Implémentations par défaut

Il arrive qu'un _trait_ soit défini avec une implémentation par défaut pour tout ou partie des méthodes qui le composent.
Cela évite d'avoir à implémenter toutes les méthodes pour chaque type et rend le code plus lisible.
Si un type particulier a besoin d'une implémentation spécifique d'une méthode du _trait_, il peut redéfinir l'implémentation par défaut.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## Comment utiliser et gérer des _traits_ externes

Les _traits_ et leurs implémentations peuvent être définis dans un module externe et utilisés dans d'autres modules, à condition d'être correctement importés.
Imaginons qu'on ait un _trait_ `ShapeGeometry` avec la méthode `boundary`, qui doit être implémentée à la fois pour les structures `Circle` et `Rectangle`.
Voici un exemple montrant comment le _trait_ et son implémentation sont importés, gérés et utilisés d'un module à l'autre.

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

La visibilité des implémentations `CircleGeometry` et `RectangleGeometry` n'a pas besoin d'être publique, puisque le _trait_ `ShapeGeometry` est rendu public et doit être facilement trouvé par le compilateur.

## Alias d'implémentation

On peut donner un alias à une implémentation lors de l'import, à l'aide du mot-clé `impl`.
C'est utile pour instancier une implémentation générique pour des types concrets.
Définissons une implémentation triviale du _trait_ `Two` pour tous les types qui implémentent le _trait_ `One`, en additionnant simplement deux fois la valeur de `One` et en renvoyant la somme.
On peut ensuite exposer l'implémentation de `Two` qui ne fonctionne que pour les types `u8` et `u128`.

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

L'implémentation générique peut être écrite dans un module privé et, grâce à un alias d'implémentation, on peut instancier l'implémentation générique pour ces deux types concrets.
L'intérêt d'utiliser une implémentation générique privée et non exposée est d'éviter la duplication de code d'un fichier à l'autre.
Cela permet aussi de garder une API publique simple et propre.
