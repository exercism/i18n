# Introduction

TypeScript, c'est JavaScript avec une syntaxe pour les types, ce qui en fait un langage de programmation fortement typé, qui prend en charge les styles orienté objet, impératif et déclaratif (par exemple la programmation fonctionnelle), et t'offre un meilleur outillage à toutes les échelles.

Comme [on ne peut pas apprendre TypeScript sans apprendre JavaScript][handbook-js-or-ts], une partie du contenu de ce parcours porte sur l'enseignement de concepts JavaScript, tandis que d'autres concepts ne portent que sur des fonctionnalités propres à TypeScript.

## (Ré-)affectation

Il existe quelques façons principales d'affecter des valeurs à des noms en TypeScript : en utilisant des variables ou des constantes.
Sur Exercism, les variables s'écrivent toujours en [`camelCase`][wiki-camel-case] ; les constantes s'écrivent en [`SCREAMING_SNAKE_CASE`][wiki-snake-case].
Il n'existe pas de guide officiel à suivre, et chaque entreprise ou organisation a ses propres conventions de style.
_Tu peux écrire tes variables comme tu veux_.
L'avantage d'écrire comme les exercices sont préparés, c'est qu'elles seront mises en évidence différemment dans l'interface web et dans la plupart des IDE (environnements de développement intégrés).

En TypeScript, on peut définir des variables à l'aide du mot-clé [`const`][mdn-const], [`let`][mdn-let] ou [`var`][mdn-var].

Avec `let` ou `var`, une variable peut référencer différentes valeurs au cours de sa durée de vie.
Par exemple, `myFirstVariable` peut être définie et redéfinie plusieurs fois à l'aide de l'opérateur d'affectation `=` :

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

Contrairement à `let` et `var`, une variable définie avec `const` ne peut être affectée qu'une seule fois.
C'est ainsi que l'on définit des constantes en TypeScript.

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

Comme TypeScript peut le détecter de manière statique, le compilateur TypeScript produira lui aussi une erreur :

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

Cela signifie que tu n'as pas besoin d'exécuter le code pour détecter la `TypeError`.

## Inférence de types

Sans entrer trop loin dans le sujet de l'[inférence de types][handbook-type-inference], tu dois savoir qu'une variable à laquelle on affecte une valeur a généralement un type inféré, même sans annotation de type.

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

Ce type est ensuite imposé dans tout le code.
Cela signifie aussi que là où le code suivant est du JavaScript valide :

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

Il proteste lorsqu'on utilise TypeScript :

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

Cette fonctionnalité garantit la sûreté des types même lorsque les annotations de type ne sont pas utilisées.

## Déclarations de fonctions

En TypeScript, les unités fonctionnelles sont encapsulées dans des _fonctions_, que l'on regroupe généralement dans un même fichier lorsqu'elles vont ensemble.
Ces fonctions prennent des paramètres (arguments) et peuvent _renvoyer_ une valeur à l'aide du mot-clé `return`.
Une fonction s'appelle avec la syntaxe `()`.

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

Les paramètres d'une fonction doivent généralement être annotés avec un type, à l'aide de deux-points (`:`) suivis du type.
La valeur de retour d'une fonction peut être annotée après la fermeture de la liste des paramètres, à l'aide de deux-points (`:`) suivis du type.

## Annotations de type

Comme le montre la déclaration de la fonction `add`, les paramètres ont une annotation de type explicite `: number`.
Les déclarations de variables, les propriétés de classe, les déclarations de fonctions et bien d'autres choses encore prennent en charge les annotations de type.

Les annotations de type explicites comme les types inférés sont vérifiés par le vérificateur de types.

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## Expose aux autres fichiers

Pour rendre une `function`, une constante ou une variable disponible dans _d'autres fichiers_, il faut les [exporter][mdn-export] à l'aide du mot-clé `export`.
Un autre fichier peut ensuite les [importer][mdn-import] à l'aide du mot-clé `import`.
C'est ce qu'on appelle le système de modules.
Un bon exemple est le fonctionnement de tous les tests.
Chaque exercice a au moins un fichier, par exemple `lasagna.ts`, qui contient l'_implémentation_.
Il y a en plus au moins un autre fichier, par exemple `lasagna.test.ts`, qui contient les _tests_.
Ce fichier _importe_ les entités publiques (c'est-à-dire exportées) pour tester l'implémentation :

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
