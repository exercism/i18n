# À propos

Le type `Result` est la solution qu'offre le langage Elm pour signaler les erreurs et s'en remettre. Il ressemble un peu au type `Maybe`, mais là où le `Nothing` de `Maybe` encode une forme d'échec, il ne te dit rien sur _pourquoi_ ça a échoué. `Result` apporte, lui, un contexte sur la raison de l'échec.

## Définition et variable de type

Le type `Result` est défini comme suit :

```elm
type Result error value
  = Ok value
  | Err error
```

En résumé, ce type encode le résultat d'une opération qui peut soit réussir et renvoyer une `value`, soit échouer et renvoyer une explication de l'échec (`error`).

C'est ce qu'on appelle une définition de « type personnalisé » dans la terminologie d'Elm.
Les types personnalisés sont présentés en détail dans un autre concept de ce parcours, mais on n'en a pas besoin pour comprendre `Result` en particulier.
Les `error` et `value` dans `OK value` et `Error error` représentent une variable de type, ce qui veut dire qu'il peut s'agir de n'importe quel type, comme `Int`, `Bool` ou `String`.
Ainsi, une valeur `Result String Int` est censée contenir un `Int` et, en cas d'erreur, celle-ci est représentée par une `String`.

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## Lis le contenu d'une valeur `Result`

Lire le contenu d'une valeur `Result` se fait par « filtrage par motif ».
Le filtrage par motif est lui aussi présenté plus en détail dans un autre concept, donc on se concentre ici sur la manière de filtrer un `Result` par motif.

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

Chaque fois que tu utilises une valeur `Result`, le compilateur Elm vérifie que ton code gère toutes les possibilités : impossible de filtrer un `Result` par motif en ne traitant que le cas où il y a une `Ok value`.
Cela peut sembler pénible au début, mais c'est l'une des plus grandes forces du langage Elm.
Ça permet d'éviter des centaines de bugs et fait de la réécriture guidée par le compilateur une expérience sereine et gratifiante.

## Manipule le contenu d'une valeur `Result`

Il existe diverses fonctions pour travailler avec les types `Result`, généralement préférables au filtrage par motif. `Result.map` permet de transformer la valeur, et `Result.andThen` permet d'enchaîner des fonctions susceptibles d'échouer.

Result.map sert à transformer la valeur Ok et est pratique pour enchaîner des fonctions sans avoir à se soucier de la présence d'une erreur dans le Result. Si la valeur est Ok, Result.map appelle la fonction enchaînée (`formatAge` ci-dessous), mais s'il y a une erreur, Result.map ne fait rien et renvoie simplement l'erreur.

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

Result.andThen sert à transformer la valeur Ok et est pratique pour enchaîner des fonctions sans avoir à se soucier de la présence d'une erreur dans le Result. Il est similaire à Result.map, mais Result.andThen travaille avec une fonction enchaînée (`formatSpecialBirthday` ci-dessous) qui renvoie elle aussi un Result. `Result.map` peut le faire également, mais on obtient alors une couche d'imbrication supplémentaire, qu'`andThen` évite avec élégance.

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
