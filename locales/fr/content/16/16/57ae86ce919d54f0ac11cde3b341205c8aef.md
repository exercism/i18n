# Instructions supplémentaires

## Processus Node

Contrairement aux autres exercices, `grep.js` n'est _pas_ importé dans le fichier de test `grep.spec.js`. À la place, il sera utilisé comme s'il s'agissait d'un exécutable. Pour faciliter cela, le fichier `grep.js` a été préparé avec un _shebang_ et un commentaire qui explique ce qu'il fait :

```javascript
#!/usr/bin/env node

// The above line is a shebang. On Unix-like operating systems, or environments,
// this will allow the script to be run by node, and thus turn this JavaScript
// file into an executable. In other words, to execute this file, you may run
// the following from your terminal:
//
// ./grep.js args
//
// If you do not have a Unix-like operating system or environment, for example
// Windows without WSL, you can use the following inside a window terminal,
// such as cmd.exe:
//
// node grep.js args
//
// Read more about shebangs here: https://en.wikipedia.org/wiki/Shebang_(Unix)
```

Les tests lancent un nouveau _process_ node, qui exécute `grep.js`.

## Lis les arguments

Pour récupérer les arguments avec lesquels le _process_ a été lancé, utilise `process.argv`.

## Lis les fichiers

La fonction `readLines` est fournie. Il n'est pas nécessaire de transformer le chemin de fichier pour l'utiliser. La fonction `readlines` _résout_ le chemin à partir du répertoire de travail courant, qui, pour les processus `grep.js`, est défini sur le répertoire de l'exercice.

## Écris la sortie

Pour écrire la sortie, utilise :

- `console.log` pour écrire sur le flux de sortie standard,
- `console.error` pour écrire sur le flux d'erreur standard.

Les tests considèrent l'exécution comme réussie (résolue) si rien n'est écrit sur le flux d'erreur standard, et comme non réussie (rejetée) si quelque chose est écrit sur le flux d'erreur standard.
