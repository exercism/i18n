# Tests

Chaque exercice contient un fichier de test.
Lance les tests avec le programme `bats`.
```bash
bats test-hello-world.bats
```

`bats` doit être installé.
Consulte la page [Tester sur le parcours Bash][bash] pour savoir comment installer `bats` sur ton système.

### bats est implémenté en bash

Le fichier bats est un script bash, avec quelques fonctions spéciales reconnues par la commande `bats`.
Tu verras des tests qui ressemblent à ceci :
```sh
gawk -f some-exercise.awk <<< "some,input,here"
```
Cette syntaxe `<<<` est un [Here String][here-string] de bash.
Elle envoie la _string_ qui se trouve à droite dans l'entrée standard du programme qui se trouve à gauche.
C'est ([à peu près][so]) la même chose que
```sh
echo "some,input,here" | gawk -f some-exercise.awk
```

## Aide pour les fonctions assert

Les tests utilisent des fonctions de la bibliothèque [bats-assert][bats-assert].
Tu y trouveras de l'aide pour les différentes fonctions `assert*`.

## Tests ignorés

Résoudre un exercice, c'est faire passer tous ses tests.
Par défaut, un seul test (le premier) est exécuté quand tu lances les tests.
C'est volontaire, car cela te permet de te concentrer sur la réussite de ce seul test.
Une fois qu'il passe, tu peux activer le test suivant en commentant ou en supprimant les

    [[ $BATS_RUN_SKIPPED == true ]] || skip

annotations qui précèdent les autres tests.

## Outrepasser les annotations skip

Pour exécuter tous les tests, y compris ceux qui portent une annotation `skip`, tu peux lancer :
```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Il peut être pratique d'utiliser une fonction d'enrobage pour taper moins : en `bash`, tu peux faire :
```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```
Ensuite, lance simplement les tests avec :
```bash
bats
```

## Sortie de débogage

```exercism/caution
Cela fonctionne en local avec `bats`, mais **pas** dans l'éditeur en ligne d'Exercism.
```

Quand on lance les tests, `bats` capture à la fois la sortie standard et la sortie d'erreur pour les comparer à la sortie attendue.
Si tu affiches des messages de débogage sur la sortie standard ou la sortie d'erreur, ils seront inclus dans la sortie capturée et pourront faire échouer le test.

Pour afficher des informations de débogage sans affecter les résultats des tests, `bats` fournit à cet effet le descripteur de fichier **3**.
Tout ce qui est écrit dans le fichier `/dev/fd/3` sera affiché pendant l'exécution des tests, mais ne sera pas inclus dans la sortie capturée utilisée pour les assertions.

Exemple :

```awk
BEGIN {
    # This debug message will not interfere with test output comparison
    print "a debug message" > "/dev/fd/3"

    # Normal program output (this is what your tests will see and compare)
    print "Hello, World!"
}
```

Exemple d'exécution :

```none
$ bats test-hello-world.bats
test-hello-world.bats
 ✓ Say Hi!
a debug message

1 test, 0 failures
```

Cela te permet de voir des sorties de débogage utiles sans affecter les tests.

Masquer les détails dans une fonction peut améliorer la lisibilité si tu l'utilises à plusieurs endroits dans ton code :

```awk
BEGIN {
    debug("starting ...")
}

# do stuff here ...

END {
    debug("... finished")
}

function debug(msg) {print msg > "/dev/fd/3"}
```
