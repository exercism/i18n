# À propos

## const

Le modificateur [`const`][constants] peut être appliqué (et devrait généralement l'être) à tout champ dont la valeur est connue à la compilation et ne change pas pendant toute la durée de vie du programme.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

Le compilateur t'indiquera quelles expressions peuvent être évaluées à la compilation. Les opérations arithmétiques simples sont autorisées, tout comme la concaténation de chaînes de caractères. Cela exclut toute évaluation qui nécessiterait l'usage du tas ou de la pile, si bien que tous les appels de méthodes et les références à des types non primitifs sont proscrits.

On trouve sur le web quelques discussions sur les avantages en matière de performance de `const` par rapport aux variables. Dans le cas d'une comparaison avec des champs d'instance non `const`, on peut observer une économie de mémoire notable, mais comparée à celle de variables statiques, elle est résolument négligeable. Toute considération sur les performances du processeur risque d'être vue par tes collègues comme de l'[optimisation prématurée][premature-optimization].

Une raison plus convaincante d'utiliser `const` est qu'il aide les mainteneurs à raisonner sur le code. Entrevoir qu'un champ est marqué comme `const` ou `readonly`, ou qu'une propriété n'a pas de _setter_, permet au mainteneur de l'écarter en grande partie de son analyse. Il est peu probable qu'il soit à l'origine de bugs. Il est peu probable qu'il pose des difficultés lors d'un exercice de réécriture. Ce [commentaire sur Stack Overflow][so-consts] traite de ce point.

Le modificateur `const` peut aussi s'appliquer à des valeurs à l'intérieur des méthodes :

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

Identifier une valeur avec `const` de cette façon peut être utile si elle est utilisée plusieurs fois dans la méthode ou si tu veux attirer l'attention sur sa signification. Il n'y a aucun gain de performance par rapport à l'utilisation de littéraux en ligne.

## readonly

Le modificateur [`readonly`][readonly-fields] peut être appliqué (et devrait généralement l'être) à tout champ qui ne peut pas être déclaré `const`, dont la valeur ne change pas pendant toute la durée de vie du programme et qui est initialisé soit par un initialiseur en ligne, soit lors de l'instanciation (par le constructeur ou par une méthode appelée par le constructeur).

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

L'usage du modificateur `readonly` est encouragé pour les mêmes raisons que celles qui s'appliquent à `const`. Le fait de contraindre les champs de cette manière aide les mainteneurs à raisonner sur le code.

Notons que l'ajout du modificateur `readonly` à un champ empêche uniquement la modification de la valeur de ce champ. Dans le cas de types agrégés, il ne protège ni les champs ni les propriétés de ce type. En particulier, il ne protège pas le contenu des tableaux.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

Pour garantir que tous les membres d'un type référence sont protégés, on peut déclarer les champs `readonly` et définir des propriétés automatiques sans accesseur `set`.

Tu devrais examiner les [collections en lecture seule][readonly-collections] de la bibliothèque de classes de base.

Pour les tableaux, ce qui se rapproche le plus d'une version en lecture seule est la méthode [`Array.AsReadOnly<T>()`][as-read-only].
