# Introduction

L'analyse syntaxique est le processus qui consiste à transformer du texte en données exploitables.
Les fonctions du paquet `String` sont limitées à cet égard, et les expressions régulières sont difficiles à utiliser ; c'est pourquoi la façon idiomatique de faire de l'analyse syntaxique en Elm est d'utiliser le paquet `elm/parser`.

Passons en revue un exemple : écrire un parseur pour (un sous-ensemble de) le langage de programmation [LOLCODE][lolcode].
Prenons le programme commenté suivant :

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

Pour commencer, écrivons un type Elm pour représenter les commandes possibles :

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

Notre programme LOLCODE peut alors être représenté par une `List Command`.
Commençons par un parseur pour la ligne `HAI 1` :

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP` est construit à l'aide d'un _pipeline de parseurs_.
L'opérateur `(|.)` signifie « analyser la _string_ mais jeter le résultat » et `(|=)` signifie « analyser la _string_ et conserver le résultat ».
Dans cet exemple, `Parser.keyword "HAI"` va consommer un « HAI », mais ce résultat est ignoré.
`Parser.spaces` va consommer un nombre quelconque de caractères ' ', '\n' et '\r', mais ce résultat sera lui aussi ignoré.
`Parser.int` va analyser un entier, et la valeur de cet entier (par exemple 1) sera transmise au `Parser.succeed Version` du haut, et le parseur parviendra à renvoyer la valeur `Version 1`.

Si l'un des parseurs du pipeline échoue, il renvoie un `Parser.DeadEnd` et tout le parseur échoue.
On peut exécuter un parseur avec `Parser.run` :

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

Attaquons maintenant la ligne « CAN HAS STDIO? » avec

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP` est aussi un pipeline de parseurs, mais cette fois il se termine par `Parser.symbol`, qui convient pour analyser des symboles tels que « ? ».
La valeur que l'on veut conserver (le nom du paquet à importer) est analysée par

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

Comme on ne sait pas quel sera le nom du paquet, on ne peut pas utiliser `Parser.keyword` ; à la place, on utilise `Parser.chompWhile`, qui va consommer des caractères un par un tant qu'ils satisfont une condition (ici, être un caractère alphanumérique).
Ces caractères ainsi consommés sont ensuite rassemblés par `Parser.getChompedString`, qui renvoie un `Parser String`.
Dans ce cas, on aimerait normaliser les noms de paquets, donc on utilise `Parser.map` pour modifier la _string_ contenue dans le parseur et la mettre en minuscules.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

Ensuite, `VISIBLE "HAI WORLD!"` est analysé par

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

On a maintenant un parseur pour chaque commande.
Bien sûr, dans un programme général, l'ordre de ces commandes ne peut pas être prédit, donc on construit un parseur de commandes générique

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf` va essayer un parseur, dans l'ordre donné.
Si un parseur échoue, le suivant est essayé, mais s'il réussit, son résultat est renvoyé sans essayer les parseurs restants.
Si tous les parseurs échouent, `Parser.oneOf` échoue.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

Remarque que chaque tentative échouée produit un `Parser.DeadEnd` qui est collecté par `Parser.oneOf`.

Pour analyser un programme complet, on doit analyser plusieurs commandes à la suite avec

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence` est un parseur très personnalisable, avec un certain nombre d'options.
`start`, `separator` et `end` prennent des _strings_ qui séparent les éléments de la séquence ; pour analyser une liste Elm, on utiliserait « [ », « , » et « ] ».
`spaces` offre de la souplesse en prenant un parseur qui gérera les espaces éventuels entre les éléments et les séparateurs ; pour analyser une liste Elm, on utiliserait `Parser.spaces`, mais ici on n'accepte aucun espace, donc on utilise `Parser.succeed ()`, qui réussit immédiatement sans rien consommer.
`item` prend le parseur d'élément et, enfin, `trailing` permet de décider si les séparateurs en fin de liste sont `Parser.Forbidden`, `Parser.Mandatory` ou `Parser.Optional`.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

Quand un parseur réussit, il arrête de consommer la _string_

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

Donc, si on veut s'assurer d'avoir tout analysé dans la _string_, on peut utiliser `Parser.end`

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

Enfin, il arrive qu'on ait besoin de faire échouer un parseur en fonction de son contenu analysé.
Par exemple, s'il nous fallait un parseur qui fait échouer les programmes commençant par deux commandes « HAI » à la suite, on pourrait utiliser

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen` peut inspecter le contenu d'un parseur et renvoie un nouveau parseur en fonction de sa valeur.
Ici, on fait échouer le parseur avec un message personnalisé via `Parser.problem` dans un cas, et on renvoie la valeur d'origine dans l'autre.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
