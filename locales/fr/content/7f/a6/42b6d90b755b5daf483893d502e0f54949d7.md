# Introduction aux fondamentaux du shell

## Les shells

Un _shell_ est un programme qui te permet de saisir des commandes pour interagir avec le système d'exploitation.
Un shell peut être graphique ; l'environnement de bureau que tu utilises avec une souris ou un pavé tactile est un shell.
On va se concentrer sur les interfaces en ligne de commande, où tu saisis des commandes et où les résultats s'affichent (généralement) dans ton terminal.

Il existe de nombreux shells en ligne de commande différents.
Windows propose **cmd** et **powershell**.
Mac et Linux proposent des « Unix shells », dont il existe de nombreuses variantes.
Le shell par défaut sur Mac est **zsh**.
**csh** est un shell ancien à la syntaxe proche de celle du C.
**bash** est l'un des shells les plus populaires, en particulier sous Linux.

L'un des tout premiers shells est le shell Bourne, **sh**.
Avec le temps, ce shell a été [normalisé][posix] pour être fourni sur tout système de type Unix.
De nombreux shells sont basés sur le shell Bourne et offrent souvent des fonctionnalités interactives ou de programmation supplémentaires.

**Bash** est basé sur le shell Bourne.
C'est pourquoi on l'appelle le « **B**ourne-**a**gain **sh**ell ».
C'est le shell par défaut sur de nombreux systèmes Linux.
Bash offre de nombreuses fonctionnalités qui en font un shell interactif agréable, notamment :

* une invite de commande entièrement personnalisable,
* la possibilité de rappeler et de modifier les commandes de l'historique,
* la possibilité de manipuler les processus en cours d'exécution,
* des alias qui réduisent la saisie,
* et bien d'autres choses.

Ce parcours ne porte pas sur l'utilisation de bash comme shell interactif.
Il s'agit d'apprendre à écrire des programmes en bash.
L'accent sera mis sur l'utilisation de bash _uniquement_ pour résoudre des problèmes, même s'il n'y a aucune restriction quant à l'appel à des outils externes.

## Les fondamentaux de Bash : commandes et arguments

Bash lit les commandes depuis son entrée (qui est généralement soit un terminal, soit un fichier).
Chaque ligne d'entrée qu'il lit est traitée comme une _commande_, c'est-à-dire une instruction à exécuter.
(Il existe quelques cas avancés, comme les commandes qui s'étendent sur plusieurs lignes, dont on parlera plus tard.)

Bash divise chaque ligne en **mots** délimités par un caractère d'espacement (espaces et tabulations).
Le premier mot de la ligne est le nom de la _commande_ à exécuter.
Tous les mots restants deviennent des _arguments_ de cette commande (options, noms de fichiers, etc.).

~~~~exercism/note
Dans les exemples ci-dessous, on va te montrer quelques commandes interactives que tu peux exécuter.

* Le caractère `#` commence un _commentaire_.
  Tous les mots qui suivent le commentaire sont ignorés par le shell ; le commentaire n'est là que pour être lu.
* Le caractère `$` indique une invite de commande. 
  Si tu copies la commande, n'inclus pas l'invite.
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm` est une application qui supprime les fichiers qu'on lui donne.
`*` est un caractère [glob][glob], un motif « joker » qui correspond à tous les fichiers du répertoire courant.
On reparlera plus en détail des globs plus tard.

As-tu remarqué qu'il y a plusieurs espaces entre `a` et `b`, et un seul entre `b` et `c` ?
Le nombre d'espaces entre les arguments n'a aucune importance !
Par exemple :

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo` est une commande qui affiche ses arguments sur la sortie standard (dans notre cas, le terminal).
Bash découpe la commande en cinq mots et appelle la commande `echo` avec quatre arguments.
Les espaces supplémentaires du second exemple ne changent rien.
`echo` ne sait pas comment les espaces étaient répartis à l'origine entre les mots.

Si on veut conserver les espaces supplémentaires, il faut passer la phrase comme un seul argument.
On peut le faire en utilisant des [guillemets][Quotes] :

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

Les guillemets regroupent tout ce qu'ils contiennent en un _seul argument_.
L'argument est `This    is    a    test.`, espaces compris.
Note que les guillemets ne font pas partie de l'argument : bash les retire avant de transmettre cet argument unique à `echo`.

Les arguments sont séparés du nom de la commande et les uns des autres par un espace.
C'est important à retenir.
Par exemple, ce qui suit est incorrect :

```bash
$ [-f file]
bash: [-f: command not found
```

C'est censé tester l'existence d'un fichier nommé `file`.
Il est raisonnable de penser que les espaces autour de `[` et `]` n'ont pas d'importance, mais `[` est en réalité une commande, et elle exige que son dernier argument soit `]`.
(On verra la commande `[` plus en détail plus tard.) 
Par conséquent, on doit séparer `[` de `-f` et `]` de `file`.
Sinon, bash croira qu'on essaie d'exécuter une commande nommée `[-f` avec un seul argument `file]`.
La commande correcte sépare tous les arguments par un espace :

```bash
$ [ -f file ]
```

(On voit beaucoup de personnes déroutées par ce comportement ; elles pensent que `[...]` n'est « que de la syntaxe » et qu'elles peuvent omettre les espaces ; or `[` est une commande et les espaces sont obligatoires.)

Si le nom de notre fichier contient des espaces ou d'autres caractères spéciaux, il faut aussi le mettre entre guillemets :

```bash
$ [ -f "my file" ]
```

## Les types de commandes

Bash distingue plusieurs types de commandes : les alias, les fonctions, les commandes internes, les mots-clés et les exécutables.
Ce sont toutes des _commandes_, et elles se comportent toutes de manière très similaire.

Par défaut, les alias ne sont activés que dans les shells interactifs, et non dans les scripts shell.
On ne les abordera pas ici.

### Les fonctions

Une fonction contient des commandes shell et se comporte un peu comme un petit script ; elle peut même prendre des arguments et créer des variables locales.
Quand une fonction est appelée, les commandes qu'elle contient sont exécutées.
On verra les fonctions en détail plus tard.

### Les commandes internes

Bash dispose de quelques commandes de base intégrées, comme : `cd` (changer de répertoire), `echo` (écrire une sortie), etc.
On peut les considérer comme des fonctions déjà fournies.

### Les mots-clés

Les mots-clés ressemblent aux commandes internes, à la différence près que les mots-clés font partie de la syntaxe de bash et peuvent être analysés selon des règles spéciales.
Par exemple, `[` est une commande interne de bash, tandis que `[[` est un mot-clé de bash ; les deux servent à tester diverses conditions.
Mais le mot-clé `[[` offre des fonctionnalités supplémentaires.
Par exemple, il fournit l'opérateur `=~` qui effectue des tests d'expressions régulières.

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

Les opérateurs de comparaison de _strings_ `<` et `>` sont un autre exemple de la façon dont les mots-clés analysent le code différemment.
À l'intérieur de `[[...]]`, ces opérateurs ne nécessitent aucun traitement particulier.

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

Mais à l'intérieur de `[...]`, tu dois les mettre entre guillemets ou les échapper pour éviter que le shell ne les interprète comme des opérateurs de redirection.

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### Les exécutables

Le dernier type de commande que bash peut exécuter est un _exécutable_.
Ce sont des fichiers exécutables (des programmes) présents dans le système de fichiers de ton ordinateur, que tu peux lancer.
(On les appelle aussi parfois des _commandes externes_ ou des _applications_.)
On invoque généralement un exécutable en tapant uniquement son nom ; le chemin complet du fichier n'est en principe pas nécessaire.
C'est possible parce que bash utilise une variable prédéfinie qui l'aide à trouver l'emplacement des fichiers exécutables courants.
Cette variable s'appelle `PATH`.
C'est un ensemble de noms de répertoires séparés par des deux-points (par exemple `/usr/bin:/bin`). 
Quand une commande est indiquée (par exemple `myprogram` ou `ls`) sans chemin de fichier (et qu'il ne s'agit pas d'un alias, d'une fonction, d'une commande interne ou d'un mot-clé), bash parcourt les répertoires de `PATH`.
Les répertoires sont parcourus dans l'ordre, de gauche à droite, pour voir s'ils contiennent un exécutable portant le nom donné.

Si l'exécutable se trouve en dehors d'un chemin connu, il faut indiquer le chemin de son fichier.
Pour l'exécutable `myprogram` du répertoire courant, utilise `./myprogram` ; s'il se trouve dans le répertoire `/opt/somedirectory`, utilise `/opt/somedirectory/myprogram`.

Astuce : la commande `type` permet d'obtenir des détails sur la commande :

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## Les scripts

Un _script_ est une suite de commandes stockées dans un fichier.
Bash lit le fichier et traite les commandes dans l'ordre.
Il ne passe à la commande suivante que lorsque la commande en cours est terminée.
La seule exception étant le cas où une commande a été définie pour s'exécuter de façon asynchrone (en arrière-plan).
Ne t'inquiète pas trop de ce cas pour l'instant ; on verra comment cela fonctionne plus tard.

Tout exemple de ligne de commande de ce guide peut aussi être utilisé dans un script.

Créer un script est facile.
Commence par créer un nouveau fichier, et place ceci sur la première ligne :

```bash
#!/bin/bash
```

Cette ligne s'appelle une _directive d'interprète_ (on l'appelle aussi _hashbang_ ou **_shebang_**).
Elle indique que `/bin/bash` doit être utilisé comme interprète lorsque le fichier sert d'exécutable dans une commande.
Quand le noyau du système d'exploitation exécute un _fichier non binaire_, il lit la première ligne du fichier.
Si la ligne commence par `#!`, le noyau s'en sert pour déterminer l'interprète auquel transmettre le fichier.
(Il existe d'autres façons valables de procéder, voir ci-dessous.)
Le `#!` doit se trouver tout au début du fichier, sans espace ni ligne vide avant.
Les commandes de notre script apparaîtront sur des lignes distinctes en dessous.

Astuce : au lieu de `#!/bin/bash`, tu peux utiliser

```bash
#!/usr/bin/env bash
```

`env` recherche dans `$PATH` l'exécutable nommé par son premier argument (ici, « bash »).
Pour une explication plus détaillée de cette technique et de ses différences avec le bon vieux `#!/bin/bash`, voir [cette question sur StackOverflow][env bash].

Ne te laisse pas tromper par les scripts ou les exemples trouvés sur Internet qui utilisent `/bin/sh` comme interprète.
**`sh` n'est pas `bash` !**
Bash lui-même est un shell « compatible sh », ce qui signifie qu'il peut exécuter la plupart des scripts `sh` et reprend une grande partie de la même syntaxe.
Cependant, l'inverse n'est pas vrai ; certaines fonctionnalités de bash échoueront ou provoqueront un comportement inattendu dans `sh`.
En fait, il n'existe pas un shell `sh` unique.
Il existe de nombreuses implémentations de shell qui prennent en charge la syntaxe POSIX-sh.
Selon ton système d'exploitation, quand tu lances `sh`, tu peux en réalité exécuter bash, ash, dash ou un autre shell.

Une fois le fichier de script créé, on peut l'exécuter ainsi :

```bash
$ bash myscript
```

Dans cet exemple, on exécute la _commande_ `bash` et on lui demande de lire le script qu'on a fourni comme _argument_.
Quand on procède ainsi, la ligne `#!` n'est qu'un _commentaire_.

Sinon, on peut donner à nos scripts les droits d'exécution.
Avec cette méthode, on peut exécuter le script comme n'importe quel autre exécutable au lieu d'appeler bash manuellement :

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

Quand on lance la commande de cette façon, le système d'exploitation utilise la ligne `#!` pour déterminer quel interprète utiliser pour exécuter ton script.
