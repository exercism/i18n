# À propos

Une [`list`][lists] en F# est une collection immuable de zéro ou plusieurs valeurs. Toutes les valeurs d'une liste doivent avoir le même type. Comme les listes sont immuables, une fois qu'une liste est construite, sa valeur ne peut plus jamais changer. Une liste a une _tête_ (le premier élément) et une _queue_ (tout ce qui suit le premier élément). La queue d'une liste est elle-même une liste.

On peut définir des listes comme suit :

```fsharp
let empty = []
let emptyAlternative = List.empty

let singleValue = [5]
let singleValueAlternative = List.singleton 5

let threeValues = ["a"; "b"; "c"]
```

La façon la plus courante d'ajouter un élément à une liste est d'utiliser l'opérateur `::` (cons) :

```fsharp
let twoToFour = [2; 3; 4]
let oneToFour = 1 :: twoToFour
// => [1; 2; 3; 4]
```

On peut concaténer des listes avec l'opérateur `@` ou `List.append` :

```fsharp
[6; 7] @ [8; 9]           // => [6; 7; 8; 9]
List.append [6; 7] [8; 9] // => [6; 7; 8; 9]
```

Les listes se manipulent à l'aide de fonctions et d'opérateurs définis dans le [module `List`][list-module]. Certaines de ces fonctions sont également disponibles sous forme de [propriétés][list-properties] d'une instance de `list` :

```fsharp
List.length [7; 8] // => 2
[7; 8].Length      // => 2
```

Il n'y a pas de bon ou de mauvais choix ici. En général, les fonctions du module `List` s'accordent mieux avec l'inférence de type, tandis que les propriétés permettent d'écrire un code plus concis.

Les fonctions et les opérateurs qui semblent modifier une liste (comme l'ajout d'un élément) renvoient en réalité une nouvelle liste. Les performances ne posent généralement pas de problème, car l'implémentation des listes évite les allocations et les copies superflues.

Comme les listes sont implémentées sous forme de listes simplement chaînées, ajouter un élément en tête (avec l'opérateur `::`) est très rapide, tandis que l'accès à un élément par son indice est potentiellement relativement lent.

On peut aussi traiter les listes avec le filtrage par motif, grâce au [motif de liste][list-pattern] et au [motif cons][cons-pattern] :

```fsharp
let describe list =
    match list with
    | [] -> "Empty list"
    | [ 1 ] -> "Singleton list with 1"
    | head::tail -> sprintf "Non-empty list with head: %d" head

describe []        // => "Empty list"
describe [1]       // => "Singleton list with 1"
describe [5; 7; 9] // => "Non-empty with head: 5"
```

On peut aussi _ignorer_ une valeur lors du filtrage par motif ; quand une valeur ne nous intéresse _pas_ dans un cas précis (autrement dit, quand on ne va pas _l'utiliser_), on peut le signaler avec un tiret bas (`'_'`) :

```fsharp
let describe list =
    match list with
    | [] -> "Empty list"
    | [x] -> "List with one item"
    | [_; y] -> "List with two items (first item ignored)"
    | _ -> "List with many items (all items ignored)"

describe []        // => "Empty list"
describe [1]       // => "List with one item"
describe [5; 7]     // => "List with two items (first item ignored)"
describe [5; 7; 9] // => "List with many items (all items ignored)"
```

Le `'_'` seul doit toujours venir _en dernier_ dans le filtrage par motif : toute valeur qui ne correspond à aucun des autres cas sera traitée par ce cas.
