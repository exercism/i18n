# À propos

Préparer une valeur pour la transmission, c'est trois choses à la fois : la sérialiser, en extraire le bon morceau, et éviter de la copier quand ce n'est pas nécessaire. Trois idiomes de Factor couvrent ce terrain.

## `unparse` : de la valeur au source

[`unparse`][unparse] (dans `prettyprint`) renvoie le texte sous forme source de n'importe quelle valeur. C'est l'inverse du parseur : l'aller-retour `dup unparse parse` reconstruit la valeur.

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

Par opposition à `>string` (qui ne fonctionne que sur les séquences de caractères) et à `number>string` (uniquement sur les nombres), `unparse` est l'outil universel, au prix d'une sortie en syntaxe Factor (les _strings_ entre guillemets conservent leurs guillemets) : c'est donc le bon outil quand le destinataire va re-parser le texte, et le mauvais pour produire une sortie lisible par un humain.

## _Slices_ : des vues, pas des copies

| mot           | effet                                          |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )` — copie les n premiers    |
| `head-slice`  | `( seq n -- slice )` — vue des n premiers       |
| `tail`        | `( seq n -- newseq )` — copie à partir de l'indice n |
| `tail-slice`  | `( seq n -- slice )` — vue à partir de l'indice n |
| `head*`       | `( seq n -- newseq )` — copie tout sauf les n derniers |
| `head-slice*` | `( seq n -- slice )` — vue de tout sauf les n derniers |
| `tail*`       | `( seq n -- newseq )` — copie les n derniers   |
| `tail-slice*` | `( seq n -- slice )` — vue des n derniers      |

Une `slice` est un tuple qui contient un indice de début, un indice de fin et la séquence sous-jacente : elle implémente le [protocole de séquence][sequence-protocol], si bien que n'importe quelle opération sur les séquences fonctionne dessus. Préfère les variantes _slice_ quand tu veux seulement lire sans rien allouer, et les variantes qui copient quand tu as besoin de conserver les données alors que la séquence sous-jacente peut changer.

## _Cleave_ à plusieurs entrées : `2bi`, `3bi`, `2tri`, `3tri`

Les mots _cleave_ ordinaires `bi` et `tri` appliquent deux ou trois _quotations_ à *une seule* entrée sur la pile. Les variantes préfixées par `2` et par `3` appliquent chaque _quotation_ à *deux* ou *trois* entrées :

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

Chaque _quotation_ reçoit *toutes* les entrées. Utilise donc `2bi` quand les deux projections dépendent de la paire, et non quand tu veux appliquer la même projection à chaque entrée séparément (c'est `bi@`).

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

Pour *une seule* _quotation_ appliquée à chaque entrée séparément, utilise plutôt `bi@` (deux entrées) ou `tri@` (trois entrées) : même famille, forme différente.
