# Introduction

## Optimisation des appels terminaux

À chaque appel d'une fonction, un nouveau cadre de pile est créé en mémoire pour stocker les arguments et les variables locales de la fonction, et ce cadre de pile est libéré lorsque la fonction se termine. Comme Gleam utilise des appels de fonction récursifs plutôt qu'une syntaxe de boucle, ces cadres de pile peuvent consommer une grande quantité de mémoire.

Pour éviter ce problème, Gleam prend en charge l'optimisation des appels terminaux, qui permet au compilateur de réutiliser le cadre de pile de la fonction courante lorsqu'un appel de fonction est la dernière chose que fait la fonction. Ainsi, une fonction peut s'appeler elle-même un nombre infini de fois sans utiliser de mémoire supplémentaire.

On peut souvent réécrire des fonctions récursives non optimisées pour qu'elles bénéficient de l'optimisation des appels terminaux, en utilisant un _accumulateur_.

Un accumulateur est une variable que l'on transmet en plus des données. Il sert à transmettre l'état courant de l'exécution de la fonction, jusqu'à ce que le cas de base soit atteint.

C'est l'auteur de la fonction qui doit initialiser l'accumulateur, pas celui qui l'utilise. Pour cela, déclare deux fonctions : une fonction publique qui prend uniquement les données nécessaires en arguments et qui initialise l'accumulateur, et une fonction privée qui prend aussi un accumulateur.

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
