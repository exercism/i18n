# À propos

Le code scalaire s'appuie sur des drapeaux positionnés par diverses instructions pour effectuer un branchement en réponse à une certaine condition.
Les valeurs compactées, quant à elles, ne représentent pas une seule valeur mais un grand nombre de valeurs en parallèle.
Une même condition peut être fausse pour une voie et vraie pour une autre.

C'est pourquoi le code SIMD est [sans branchement][branchless-code] par défaut.

Au lieu de s'appuyer sur des drapeaux, les comparaisons compactées produisent généralement un **masque** dans l'opérande de destination.
Pour chaque voie, la comparaison remplit toute la voie de uns lorsque la condition est vraie, et de zéros lorsqu'elle est fausse.
Lue comme un entier signé, une voie vraie vaut `-1` et une voie fausse vaut `0`.

Ce masque peut ensuite être combiné avec des [opérations bit à bit][simd-bitwise] pour filtrer des voies précises.

## Comparaisons compactées

Un `cmp` scalaire est générique au sens où il sert à positionner plusieurs drapeaux à la fois.
Une autre instruction peut ensuite exploiter ces drapeaux, soit pour brancher, soit pour effectuer des calculs.

Cependant, comme une comparaison compactée vérifie une condition et calcule un masque en même temps, elle n'est pas générique.
Il faut indiquer à la comparaison la condition exacte à tester.

Il y a deux façons de procéder :

- Pour les comparaisons d'entiers, la condition est donnée sous forme de suffixe : `eq` pour l'égalité, et `gt` pour « supérieur à ».
  Les autres variantes se construisent en combinant le résultat de l'une d'elles.
- Pour les comparaisons de nombres à virgule flottante, la condition est encodée dans un immédiat.
  Les différentes valeurs de cet immédiat correspondent à différentes conditions testées.

À part l'utilisation d'un suffixe conditionnel précis sur les comparaisons d'entiers, la syntaxe suit la même structure que celle que l'on a déjà vue :

- Pour les entiers, `p` + `cmp` + condition + taille (`b`, `w`, `d` ou `q`).
- Pour les nombres à virgule flottante, `cmp` + `p` + taille (`s` ou `d`).
  La condition est passée dans un immédiat, en opérande supplémentaire.

### Comparaisons d'entiers

Comme on l'a mentionné, il n'existe de comparaisons d'entiers que pour l'égalité et pour « supérieur à » :

| instruction                                | description                      |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | égalité voie par voie            |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | « supérieur à » **signé**, voie par voie |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

Pour créer une comparaison « inférieur à », utilise `gt` en inversant les opérandes : `a < b` == `b > a`.

Note que la comparaison est **signée**.
Pour effectuer une comparaison non signée, inverse le bit de poids fort des deux opérandes.
Cela est possible avec un XOR avec un masque dont seul le bit de poids fort est à 1.

~~~~exercism/note
Voici deux idiomes bien pratiques :

1. Faire un XOR d'un registre avec lui-même pour obtenir que des zéros.
2. Comparer un registre avec lui-même pour obtenir que des uns.

Par exemple :

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

Les masques tout à zéro et tout à un servent couramment à encoder respectivement « faux partout » et « vrai partout ».
Ils peuvent aussi représenter un `0` ou un `-1` compacté, qui sont des valeurs sentinelles courantes.
Par exemple, le NUL qui marque la fin d'une _string_ est un `0`.
~~~~

### Comparaisons en virgule flottante

Les voies en virgule flottante ont une forme différente : une seule instruction, `cmpps` (et `cmppd` pour les voies de 64 bits), avec la condition fournie sous forme d'immédiat :

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM dispose aussi de pseudo-instructions qui correspondent au bon immédiat et sont plus faciles à retenir.
Dans tout ce qui suit, le `x` de `px` peut être `s` (nombres à virgule flottante de 32 bits) ou `d` (nombres à virgule flottante de 64 bits) :

| pseudo-instruction | immédiat | comparaison            |
|--------------------|----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a est NaN ou b est NaN |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | ni a ni b n'est NaN    |

~~~~exercism/caution
NaN se compare comme non ordonné : il n'est ni inférieur, ni égal, ni supérieur à quoi que ce soit, y compris lui-même.
Les prédicats ordonnés, comme `cmpltps`, donnent faux lorsque l'un des opérandes est NaN, tandis que les prédicats non ordonnés donnent vrai.
C'est pourquoi `cmpordps` et `cmpunordps` existent : pour tester explicitement NaN.
~~~~

## Sélectionner avec un masque

Un masque encode le résultat d'une condition.
Il peut ensuite servir à choisir, voie par voie, entre deux ensembles de valeurs selon cette condition.
On prend la voie d'une valeur là où le masque est vrai, et celle d'une autre là où il est faux :

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

Ce schéma est la forme compactée de la sélection sans branchement.
Chaque voie est calculée, et le masque seul décide quelle valeur est conservée, sans le moindre `jcc`.

## Les _blends_ dédiés

Il existe des instructions qui effectuent directement cette même sélection, en lisant un bit par élément depuis un registre de masque.
On les appelle les instructions **_blend_** :

| instruction | élément     | source du masque |
|-------------|-------------|------------------|
| `pblendvb`  | octet        | `xmm0` implicite |
| `blendvps`  | voie de 32 bits | `xmm0` implicite |
| `blendvpd`  | voie de 64 bits | `xmm0` implicite |

Note que la première instruction suit la syntaxe des entiers, tandis que les deux autres suivent celle de la virgule flottante.
Cependant, comme ces instructions se contentent de sélectionner des octets bruts, n'importe laquelle d'entre elles peut servir aussi bien avec des entiers qu'avec des nombres à virgule flottante.

Pour chaque élément, le _blend_ conserve la destination lorsque le bit de poids fort de l'élément de masque correspondant est à 0, et prend la source lorsqu'il est à 1.
Seul ce **bit de poids fort** est examiné, ce que satisfait un masque de comparaison, puisque ses voies ne contiennent que des uns ou que des zéros.
Le registre de masque est toujours `xmm0`, de façon implicite :

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

Il est aussi possible d'utiliser `pblendvb` pour sélectionner des voies à partir d'un masque de comparaison, quelle que soit la taille.
Comme tous les octets d'une voie vraie valent 1, `pblendvb` les sélectionne tous.

~~~~exercism/note
Ces instructions ajoutent toutes un `v` après l'opération effectuée (`blend`).
Ce `v` signifie _variable_, car la sélection n'est pas statique : elle dépend d'un registre.

Il existe aussi des variantes sans `v`, qui sélectionnent selon un immédiat.
Elles suivent le même schéma : elles sélectionnent une voie `i` si le bit `i` de l'immédiat est à 1.
~~~~

## Revenir d'un masque à un scalaire

Bien que puissant, le code SIMD est loin d'offrir la souplesse du code scalaire.
Dans de nombreuses situations, il est nécessaire de passer d'un registre compacté au monde des instructions scalaires.

La famille d'instructions `movmsk` sert de pont entre ces deux mondes.
Ces instructions extraient le **bit de poids fort** de chaque voie vers un registre à usage général :

| instruction | rassemble                     | largeur du résultat |
|-------------|-------------------------------|---------------------|
| `pmovmskb`  | le bit de poids fort de chacun des 16 octets | 16 bits      |
| `movmskps`  | le bit de poids fort de chacun des 4 mots de 32 bits | 4 bits       |
| `movmskpd`  | le bit de poids fort de chacun des 2 mots de 64 bits | 2 bits       |

S'il est utilisé après une comparaison, chaque bit à 1 représente une voie « vraie » et chaque bit à 0, une voie « fausse ».
Ce résultat peut ensuite être manipulé comme d'habitude avec des instructions scalaires.
Par exemple, un `popcnt` compte le nombre de correspondances, et `tzcnt` trouve la première.

Le registre à usage général peut être de 32 ou de 64 bits.

## Tester un vecteur entier

Il existe aussi une variante compactée de l'instruction scalaire `test` : `ptest`.

Elle est semblable à son homologue scalaire en ce qu'elle effectue une opération AND entre deux opérandes, sans les modifier.
Contrairement à `test`, `ptest` effectue aussi une opération ANDN, qui inverse le premier opérande.

Ainsi, on peut voir `ptest` comme une version non destructive de `pand` et `pandn`, qui positionne les drapeaux selon le résultat.
De la même manière que ces deux instructions, `ptest` traite tout le registre SIMD comme une seule voie, et ne prend donc pas de préfixe de taille.

Si le résultat de l'opération AND est `0`, le `ZF` est positionné, et si l'opération ANDN donne `0`, c'est le `CF` qui est positionné.
Cela signifie que `ptest` permet de vérifier à la fois un masque entièrement à un et un masque entièrement à zéro :

1. Utiliser `ptest` sur un registre avec lui-même positionne `ZF` seulement si le registre est entièrement à zéro.
   Cela imite l'idiome scalaire courant qui consiste à utiliser `test` sur un registre avec lui-même pour vérifier qu'il vaut `0`.
2. Utiliser `ptest` sur un registre avec un masque entièrement à un positionne `CF` seulement si le registre est entièrement à un.
   De plus, il positionne `ZF` seulement si le registre est entièrement à zéro, ce qui permet de vérifier les deux masques d'un coup.

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

Le résultat d'un `ptest` peut servir à brancher, ou bien dans des instructions sans branchement telles que `setcc` ou `cmovcc`, comme d'habitude.

## AVX et au-delà

AVX donne aux comparaisons, aux _blends_ et à `ptest` une forme préfixée par `v` sur des registres plus larges.

Le _blend_ variable change de forme.
Le masque n'est plus le `xmm0` implicite, mais un quatrième opérande explicite :

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

Les extensions AVX-512 changent le modèle plus profondément.

D'abord, elles ajoutent une nouvelle classe de registres SIMD de 64 octets, appelés `zmm`.
Ils étendent les registres `ymm` correspondants, de la même façon que les registres `ymm` étendent les registres `xmm`.

Ensuite, ces extensions créent aussi toute une nouvelle classe de **registres _opmask_**, de `k0` à `k7`, dont le rôle principal est de servir de masques aux instructions SIMD.
Les comparaisons n'écrivent plus dans des vecteurs, mais dans l'un de ces nouveaux registres.
Ils peuvent aussi servir directement de prédicats sur de nombreuses instructions, avec un masque d'écriture `{k}`, pour sélectionner les voies _directement_ :

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

Enfin, de nouvelles instructions permettent d'opérer sur ces nouveaux registres, notamment de les copier dans des registres à usage général.
Cela rend les instructions `movmsk` inutiles, et les instructions `movmsk` ne sont pas prises en charge sur les registres `zmm`.

Ces extensions sont mentionnées pour être complet.
Les exercices de ce parcours utilisent les formes SSE.
