# Introduction

JavaScript dispose d'un objet intégré `Date`, qui stocke une date et une heure et fournit des méthodes pour les gérer.

<!-- prettier-ignore -->
~~~exercism/caution
Il est basé sur la classe `java.util.Date` de Java, qui a été remplacée au début des années 2010, mais pour des raisons de rétrocompatibilité, le `Date` de JavaScript est toujours là.

Parce qu'il est difficile de travailler avec les dates en général, et parce que la gestion des fuseaux horaires est mauvaise ou inexistante, il existe de nombreuses bibliothèques comme `moment.js`, `day.js`, `date-fns` et `luxon`.
Aucune d'entre elles n'est disponible sur Exercism.

Dans tes propres projets, n'utilise pas de paquet obsolète ou non maintenu comme `moment.js`, mais privilégie des alternatives plus modernes comme `luxon`, ou [Temporal][mdn-temporal], qui n'est pas encore largement disponible.
Cet exercice se concentre sur `Date`, qui restera pertinent jusqu'à la fin de JavaScript.

## Création

Un objet `Date` est une instance de la classe `Date`.
On peut le créer sans passer d'argument à la fonction constructeur.
On obtient alors un objet `Date` qui représente la date et l'heure actuelles :

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### Horodatage Unix (nombre)

Si on lui passe un nombre, celui-ci est interprété comme un `timestamp`.
Un horodatage est un nombre entier qui représente le nombre de **millisecondes** écoulées depuis le **1er janvier 1970 [UTC][defn-utc]+0**.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

On pourrait s'attendre à ce que `new Date(0)` produise l'objet date « le plus ancien », mais JavaScript convertit la date vers ton fuseau horaire local, ce qui signifie que seules les personnes situées autour du fuseau [GMT / UTC+0][defn-gmt] obtiendront réellement la valeur de l'[époque Unix][defn-unix-epoch].

### Horodatage ISO 8601 (_string_)

Tu peux passer au constructeur `Date` une valeur de type _string_ qui représente une date.
Le **seul** format cohérent d'une implémentation à l'autre est la [version simplifiée][mdn-date-string-format] de ce qu'on appelle les [chaînes d'horodatage ISO 8601][defn-iso8601], reconnues et normalisées au niveau international.

Un instant donné en [UTC][defn-gmt] s'écrit comme ceci :

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

Les substitutions suivantes s'appliquent :

| Clé  | Description                                       | Par défaut |
| ---- | ------------------------------------------------- | ---------- |
| YYYY | L'année civile, représentée sur 4 chiffres        |            |
| MM   | Le mois civil, représenté sur 2 chiffres          | 01         |
| DD   | Le jour civil, représenté sur 2 chiffres          | 01         |
| T    | Une lettre T littérale, qui sépare la date de l'heure |        |
| HH   | Les heures sur une horloge de 24 heures, 2 chiffres | 00       |
| mm   | Les minutes, 2 chiffres                           | 00         |
| ss   | Les secondes, 2 chiffres                          | 00         |
| mss  | Les millisecondes, 3 chiffres                     | 000        |
| Z    | Une lettre Z littérale, ou un décalage `+/-HH:mm` |            |

La lettre littérale `Z` indique UTC (pas de fuseau horaire, pas d'heure d'été).

Comme la plupart des composants ont des valeurs par défaut, il est valide d'omettre des parties à la fin :

```text
YYYY-MM-DD
```

Correspond par défaut à une heure de 00:00:00.000

Si l'horodatage ne se termine pas par `Z`, et ne se termine pas non plus par `+HH:mm` ou `-HH:mm` (ce qui indique un décalage de fuseau horaire), alors, pour des raisons historiques, la règle suivante s'applique :

> Lorsque le décalage de fuseau horaire est absent, les formes contenant uniquement une date sont interprétées comme une heure UTC, et les formes contenant une date et une heure sont interprétées comme une heure locale.
> Cette interprétation en heure UTC vient d'une erreur historique de la spécification, qui n'était pas cohérente avec ISO 8601 mais qui n'a pas pu être corrigée pour des raisons de compatibilité web.
> Voir [Broken Parser – A Web Reality Issue][ref-broken-parser].

### Objet Date

Un objet date existant peut aussi servir d'argument au constructeur.
Cela crée une copie de l'objet `Date` existant, avec la même date et la même heure.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### Fournis les valeurs individuelles des composants de date et d'heure

On peut créer une date représentant un jour donné en passant trois nombres.
Pour créer une date avec une heure, on passe six nombres.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

La deuxième valeur est le `month`, qui commence à `0` pour janvier et va jusqu'à `11` pour décembre.

## `Date.parse()`

Tu trouveras peut-être des mentions ou des références à une fonction d'analyse de dates, `Date.parse`.
Comme cette fonction n'a que quelques invariants (des vérités) et que le reste de son implémentation n'est pas spécifié (et donc pas standard), il ne faut pas l'utiliser.

## Accède aux composants de `Date`

Les objets date disposent de plusieurs méthodes qui renvoient les composants de la date :

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

Chacune possède une variante `set` correspondante (par exemple `setFullYear`) pour mettre à jour la valeur.
Toute valeur qui dépasse la plage déborde sur le composant suivant :

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

Il existe des variantes UTC pour toutes ces méthodes, qui ignorent le fuseau horaire local.

## Convertis une date

Les objets date ont une méthode `getTime()` qui renvoie l'horodatage UNIX en millisecondes, c'est-à-dire le nombre de millisecondes écoulées depuis minuit au début du 1er janvier 1970 UTC.
De plus, la méthode `toISOString()` permet de convertir un objet date en une chaîne d'horodatage ISO 8601.

## Compare des dates

Les opérateurs supérieur à (`>`) et supérieur ou égal à (`>=`), ainsi qu'inférieur à (`<`) et inférieur ou égal à (`<=`), peuvent s'utiliser directement entre deux dates, ou entre une date et un nombre.
Cela fonctionne parce que JavaScript essaie de convertir la date en une valeur primitive.

<!-- prettier-ignore -->
~~~exercism/advanced
Lors d'une comparaison entre deux dates, ou entre une date et un nombre, JavaScript appelle [`[Symbol.toPrimitive]("number")`][mdn-to-primitive], qui appelle en interne [`date.valueOf()`][mdn-date-value-of].
Cette dernière est équivalente à un appel à [`date.getTime()`][mdn-date-get-time].

Si tu ne veux pas dépendre de ce comportement, commence par convertir la date en nombre avec `getTime()`.

[mdn-to-primitive]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/Symbol.toPrimitive
[mdn-date-value-of]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/valueOf
[mdn-date-get-time]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/getTime
~~~

On ne peut pas comparer des dates avec les opérateurs d'égalité (`==` et `===`), mais on peut comparer le résultat de `.getTime()`.
