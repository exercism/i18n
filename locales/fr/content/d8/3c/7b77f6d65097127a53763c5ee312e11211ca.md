# Introduction

## Commentaires

Common Lisp permet au programmeur d'écrire des «\u00A0commentaires\u00A0» qui sont ignorés par l'ordinateur.
Les commentaires sur une seule ligne commencent par un ou plusieurs points-virgules (`;`) et, parfois, on peut voir ce qui suit\u00A0:

```lisp
(code...) ; => value
```

Où le commentaire est utilisé pour indiquer quelle valeur est renvoyée par Common Lisp après l'exécution du code sur cette ligne.

Il est idiomatique d'utiliser un seul point-virgule pour un commentaire court à la fin d'une ligne, deux pour un commentaire plus long au-dessus d'une section de code, trois pour un long commentaire décrivant quelque chose comme une fonction, et quatre pour un commentaire tel qu'un en-tête en haut d'un fichier source.

## Cons

Tous les objets Common Lisp sont soit des «\u00A0atomes\u00A0» (des valeurs uniques et indivisibles), soit des «\u00A0cons\u00A0» (construits par la fonction de construction `cons`).
Un cons est composé de deux parties\u00A0: le premier élément et le reste des éléments.
Pour des raisons historiques, ces deux parties sont appelées le `car` et le `cdr`.
Lorsque ces cons sont évalués comme du code, le premier élément (`car`) représente la fonction appelée, tandis que le reste des éléments (`cdr`) représentent les arguments de cette fonction\u00A0:

```lisp
(<function> <arg1> <arg2> ... <argN>)
; ^ car ^  |        ^ cdr ^
```

## Expressions

Tout le code Common Lisp est constitué de S-Expressions (Expressions symboliques). On les appelle sexprs en abrégé. Chaque sexpr est soit un atome, soit un cons. Lorsque les S-Expressions sont évaluées, elles renvoient automatiquement une valeur qui prend la place de l'expression. Lorsque tu écris tes propres fonctions (en utilisant `defun`), la dernière valeur dans le corps du `defun` est automatiquement renvoyée\u00A0:

```lisp
;; Defining a new function
(defun gimme-foo () 'foo)
;; Calling the function as an S-Expression
(gimme-foo) ; => FOO
```

## Symboles

Les symboles en Common Lisp sont des valeurs spéciales qui peuvent pointer vers d'autres valeurs ou, dans le cas des _mots-clés_, vers eux-mêmes.
Lorsque les symboles sont évalués par Lisp, ils sont remplacés par les valeurs vers lesquelles ils pointent\u00A0:

```lisp
foo  ; => <whatever-foo-points-to>
:foo ; => :FOO
```

Note que les mots-clés sont désignés par un deux-points (`:`) initial.

La citation (l'ajout de `'` devant une S-expression) indique à Lisp de ne pas évaluer cette expression.
En citant `'foo` dans notre exemple de `defun`, on a évité que Lisp tente de chercher (et échoue à trouver) ce vers quoi `FOO` était censé pointer, et on a renvoyé à la place la valeur `FOO` elle-même.
Si `FOO` n'a été défini nulle part dans notre programme\u00A0:

```lisp
foo  ; => <ERROR! Lisp doesn't know what foo points to!>
'foo ; => FOO
```

Pour l'instant, tu peux considérer cela simplement comme un moyen de renvoyer des symboles depuis une fonction, mais on reviendra sur la citation et on explorera davantage ses implications dans de futurs exercices d'apprentissage.
