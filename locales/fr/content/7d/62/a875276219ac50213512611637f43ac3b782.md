# Introduction

Une solution exemplaire t'est fournie pour chaque exercice que tu résous sur Exercism.
Dans le parcours Julia, ces solutions contiennent généralement des _docstrings_.
Après avoir résolu cet exercice, tu sauras comment structurer une _docstring_, comment l'écrire et comment accéder aux _docstrings_ depuis le REPL.

~~~~exercism/note
Tu n'es pas obligé d'écrire des _docstrings_ pour tes fonctions pendant que tu résous des exercices du parcours Julia, si tu n'en as pas envie.
~~~~

## Syntaxe

Une _string_ placée juste avant n'importe quel objet Julia, par exemple une fonction ou un type, est interprétée comme une _docstring_ qui documente cet objet.
Par exemple :

```julia
"Tell a joke."
joke() = ...
```

Les _docstrings_ de Julia sont mises en forme avec [Markdown](https://en.wikipedia.org/wiki/Markdown).
Cela permet d'utiliser, dans les _docstrings_, des fonctionnalités comme l'indentation, les blocs de code ou le texte en gras.

~~~~exercism/note
Tu trouveras la liste des fonctionnalités Markdown prises en charge dans la [documentation de la bibliothèque standard Markdown](https://docs.julialang.org/en/v1/stdlib/Markdown/).
~~~~

Une _docstring_ plus complexe peut ressembler à ceci :

````julia
"""
    mean(x, y)

Compute the mean value of `x` and `y`.
"""
mean(x, y) = (x + y) / 2
````

Le manuel Julia énonce quelques conventions à suivre :

> - Indique toujours la signature d'une fonction en haut de la documentation, avec une indentation de quatre espaces pour qu'elle soit affichée comme du code Julia.
> - Après le bloc de signature simplifié, ajoute une seule phrase d'une ligne qui décrit ce que fait la fonction ou ce que représente l'objet.
>    Si besoin, donne plus de détails dans un second paragraphe, après une ligne vide.
>    Lorsque tu documentes des fonctions, cette phrase d'une ligne doit être à l'impératif (« Fais ceci », « Renvoie cela ») plutôt qu'à la troisième personne (n'écris pas « Renvoie la longueur... »).
>    Elle doit se terminer par un point.
> - Ne te répète pas.
>    Comme le nom de la fonction est donné par la signature, inutile de commencer la documentation par « La fonction `mean`... » : va droit au but.
> - Utilise des accents graves pour délimiter le code et les équations.
> - Mets les caractères `"""` de début et de fin sur leurs propres lignes.

~~~~exercism/note
La liste ci-dessus ne couvre que les conventions dont tu pourrais avoir besoin ou que tu pourrais rencontrer dans le cadre d'Exercism.
Tu trouveras la liste complète et intégrale dans le [manuel Julia](https://docs.julialang.org/en/v1/manual/documentation/).
D'autres conventions pour documenter des concepts Julia plus avancés seront présentées en même temps que le concept, dans les exercices suivants.
~~~~

## Accède aux _docstrings_

Tu peux rechercher des _docstrings_ dans le REPL en tapant `?` suivi du nom de la fonction ou de l'objet, par exemple :

```julia-repl
help?> println
search: println printstyled print sprint isprint

  println([io::IO], xs...)


  Print (using print) xs followed by a newline. If io is not supplied, prints to stdout.

  Examples
  ==========

  julia> println("Hello, world")
  Hello, world

  julia> io = IOBuffer();

  julia> println(io, "Hello, world")

  julia> String(take!(io))
  "Hello, world\n"
```

Cela peut aussi servir de recherche de base, par exemple si tu n'es pas sûr de l'orthographe exacte d'une fonction :

```julia-repl
help?> printline
search:

Couldn't find printline
Perhaps you meant println, pipeline, @inline or print
  No documentation found.

  Binding printline does not exist.
```
