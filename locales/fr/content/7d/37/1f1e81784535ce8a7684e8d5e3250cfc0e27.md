# Instructions supplémentaires

## Messages d'erreur

Il est parfois nécessaire de [lever une exception](https://docs.python.org/3/tutorial/errors.html#raising-exceptions). Quand tu le fais, il faut toujours inclure un **message d'erreur explicite** qui indique l'origine de l'erreur. Cela rend ton code plus lisible et facilite grandement le débogage. Dans les cas où tu sais que l'origine de l'erreur sera d'un certain type, tu peux choisir de lever l'un des [types d'erreur intégrés](https://docs.python.org/3/library/exceptions.html#base-classes), mais il faut quand même inclure un message explicite.

Cet exercice exige en particulier que tu utilises [l'instruction `raise`](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement) pour « lancer » des `ValueErrors` quand on passe au constructeur `Queen` des nombres négatifs, ou des nombres qui ne correspondent pas à une ligne ou à une colonne valide. Les tests ne passeront que si tu `raise` l'`exception` et que tu y joins un message. Tu dois aussi `raise` une `ValueError` si les deux dames passées à la méthode `can_attack()` se trouvent sur la même case.

Pour lever une `ValueError` avec un message, écris le message comme argument du type `exception` :

```python
# if the row parameter is negative
raise ValueError("row not positive")

# if the row parameter is not on the defined board
raise ValueError("row not on board")

# if the column parameter is negative
raise ValueError("column not positive")

# if the column parameter is not on the defined board
raise ValueError("column not on board")

# if both the queens are on the same location
raise ValueError("Invalid queen position: both queens in the same square")
```
