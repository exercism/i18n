# À propos

La principale construction orientée objet en C# est la _classe_, qui combine des données ([_champs_][fields]) et un comportement ([_méthodes_][methods]). Les champs et les méthodes d'une classe sont appelés ses _membres_.

L'accès aux membres peut être restreint à l'aide de modificateurs d'accès, dont les deux plus courants sont :

- [`public`][public] : le membre est accessible depuis n'importe quel code (sans restriction).
- [`private`][private] : le membre n'est accessible que depuis le code de la même classe.

Il est d'usage de préciser un modificateur d'accès pour tous les membres. Si aucun modificateur d'accès n'est précisé, la valeur par défaut est `private`.

Ce regroupement de données et de comportements liés, auquel s'ajoute la restriction de l'accès aux membres, s'appelle l'[encapsulation][encapsulation], l'un des concepts fondamentaux de la programmation orientée objet.

L'ensemble des valeurs des champs d'un objet à un instant donné constitue l'[état][object-state] de cet objet.

On peut voir une classe comme un modèle servant à créer des instances de cette classe. Pour [créer une instance d'une classe][creating-objects] (aussi appelée _objet_), on utilise le [mot-clé `new`][new] :

```csharp
class Car
{
}

// Create two car instances
var myCar = new Car();
var yourCar = new Car();
```

Les [champs][fields] ont un type et peuvent être définis n'importe où dans une classe.
Les champs publics s'écrivent en [PascalCase][pascal-case] et les champs privés en [camelCase][camel-case], précédés d'un tiret bas `_` :

```csharp
class Car
{
    // Accessible by anyone
    public int Weight;

    // Only accessible by code in this class
    private string _color;
}
```

On peut éventuellement affecter une valeur initiale à un champ. Si un champ ne précise pas de valeur initiale, il reçoit la [valeur par défaut][default-values] de son type. Les valeurs des champs d'une instance sont accessibles et modifiables via la notation pointée.

```csharp
class Car
{
    // Will be set to specified value
    public int Weight = 2500;

    // Will be set to default value (0)
    public int Year;
}

var newCar = new Car();
newCar.Weight; // => 2500
newCar.Year;   // => 0

// Update value of the field
newCar.Year = 2018;
```

Les champs privés sont généralement mis à jour comme effet de bord de l'appel d'une méthode. Ces méthodes ne renvoient habituellement aucune valeur, auquel cas le type de retour doit être [`void`][void] :

```csharp
class CarImporter
{
    private int _carsImported;

    public void ImportCars(int numberOfCars)
    {
        // Update private field
        _carsImported = _carsImported + numberOfCars;
    }
}
```

Note qu'il n'est pas d'usage d'utiliser des champs publics dans les classes C#. On utilise soit des champs privés, soit d'autres types de membres qui seront abordés dans les exercices suivants.

À l'intérieur d'une classe, le [mot-clé `this`][this] fait référence à la classe courante. C'est particulièrement utile lorsqu'un paramètre porte le même nom qu'un champ :

```csharp
class CarImporter
{
    private int carsImported;

    public void SetImportedCars(int carsImported)
    {
        // Update private field from public method
        this.carsImported = carsImported;
    }
}
```

La structure en classes et méthodes offre un moyen naturel de limiter la visibilité d'éléments du programme tels que les champs et les méthodes, et d'éviter le fameux [problème de l'état global][so-global-state-problem]. Les champs publics, les méthodes et les autres membres publics doivent être qualifiés par le nom de l'objet, `object.field` ou `object.method()`, (ou le nom de la classe pour les membres statiques) pour être visibles depuis du code extérieur à la classe. Les variables et les paramètres déclarés dans une méthode ne sont visibles qu'à l'intérieur de cette méthode.

Un point auquel il faut faire attention avec cette approche : si le nom d'un champ est identique à celui d'une variable ou d'un paramètre d'une méthode, le code de la méthode ignorera le champ, ce qui n'est peut-être pas ce que tu veux. En général, mieux vaut l'éviter dans la mesure du possible, même si c'est un schéma courant dans les constructeurs. S'il est pertinent que le champ et la variable portent le même nom, qualifie le nom du champ avec le mot-clé `this` dans la méthode.

Ces [modificateurs d'accès][access-modifiers] permettent de restreindre davantage la visibilité.
