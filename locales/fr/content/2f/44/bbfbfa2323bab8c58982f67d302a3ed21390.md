# golint non satisfait

Il existe un excellent outil appelé [`golint`](https://github.com/golang/lint), qui examine le code pour y repérer les problèmes courants et les problèmes de style.
Exécute `golint` sur la solution, par exemple : `golint two_fer.go` ; il te fera quelques suggestions utiles.

C'est une bonne idée de toujours vérifier le code avec `golint`.
Quand on écrit du logiciel Go pour la production, de nombreux _pipelines de build_ échouent automatiquement si le code ne passe pas `golint`.

Si tu veux obtenir beaucoup plus de retours de la part des _linters_ de code, il existe le projet [golangci-lint](https://github.com/golangci/golangci-lint)
qui te permet de lancer un grand nombre de _linters_ avec une seule commande.
Un fichier de configuration du projet permet d'adapter le comportement aux besoins du projet.

```
> golint
%{golint}
```
