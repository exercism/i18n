# Directives de contribution

Si tu veux participer au développement du parcours Pharo, suis les instructions ci-dessous, qui t'aideront à démarrer.

Nous tenons à améliorer ce parcours et à montrer aux développeurs une autre façon d'aborder la programmation ! :tada:

Lis comment [t'impliquer dans un parcours Exercism](https://github.com/exercism/docs/tree/master/contributing-to-language-tracks) et pense aussi à lire le [code de conduite d'Exercism](https://exercism.io/code-of-conduct).

Nous accueillons avec plaisir les pull requests de toutes sortes. Aucune contribution n'est trop petite, en particulier celles qui apportent des corrections et des améliorations aux exercices existants. Note que les exercices de ce parcours doivent respecter les [normes communes à Exercism](https://github.com/exercism/docs/tree/master/language-tracks/exercises), mais si tu ne sais pas trop comment apporter une modification, ouvre une issue GitHub et on en discutera.

>__Note__ : l'organisation Exercism a décidé de [mettre en pause les contributions de la communauté élargie d'Exercism](https://exercism.org/blog/freeing-our-maintainers). Le parcours Pharo est exempté de cette politique, car notre communauté est plutôt petite (autrement dit : tout contributeur du parcours Pharo peut toujours créer des issues et soumettre des PR).

## Connaissances prérequises

On part du principe que tu es déjà [familier](./docs/RESOURCES.md) avec le développement en Pharo et avec l'utilisation d'[Iceberg Git](https://github.com/pharo-vcs/iceberg).

## Mise en place de l'environnement de développement

Pour commencer, assure-toi de disposer d'un environnement de développement Exercism complet et d'avoir installé les éléments suivants :

### __Image et IDE Pharo__

Tu as besoin d'un environnement de développement Pharo (une image Pharo en cours d'exécution, l'IDE) pour créer les exemples de code proprement dits.

1. Utilise [PharoLauncher](https://pharo.org/download) pour créer une image de développement stable toute neuve depuis la catégorie `Official distributions` (au 05/24, l'image stable est : Pharo 12.0 - 64bit (stable)), puis lance-la (tu peux aussi utiliser [zerconf](https://get.pharo.org/) si tu le connais).
2. Lance ton image pour vérifier que tout fonctionne correctement.

> __Note__ : si tu rencontres des problèmes de TIMEOUT, consulte les [instructions d'installation pour les utilisateurs](./docs/INSTALLATION.md).

### __Mise en place des dépôts git__

1. Si tu ne l'as pas déjà fait, fais un fork de `https://exercism/pharo-smalltalk` sur Github.
2. Pour cloner ton fork, évalue la commande suivante dans le Playground de l'image Pharo en cours d'exécution :
```
Metacello new
 baseline: 'Exercism';
 repository: 'github://exercism/pharo-smalltalk:main/releases/latest';
 load: 'dev'
```
Cela clone effectivement le dépôt git du parcours Pharo et charge le code source du parcours Pharo dans l'image Pharo, sa baseline de développement. Le dossier local contenant le dépôt cloné se trouvera dans (selon tes préférences Iceberg) : `<path-to-Pharo-image>/pharo-local/iceberg/<your-id/pharo-smalltalk`.
> __Note__ : les sources de l'image Pharo sont synchronisées et sérialisées dans des fichiers `*.st` situés dans le sous-dossier `src` du répertoire mentionné ci-dessus.

2. Une autre façon de faire la même chose est de cloner ton fork via la CLI : `git clone https://github.com/<your id>/pharo-smalltalk` en tant que projet GitHub, en indiquant `<your id>` comme nom de propriétaire et `pharo-smalltalk` comme nom de projet.
Installe ensuite la baseline Metacello `dev` (pas celle par défaut) dans Iceberg, via le menu contextuel Metacello de l'image Pharo en cours d'exécution. (par exemple, fais un clic droit sur le projet « pharo-smalltalk » que tu viens de cloner, sélectionne la deuxième option du menu Metacello et saisis `dev`)

3. Après avoir chargé le projet dans l'image Pharo, n'oublie pas d'__enregistrer l'image__ (élément de menu Pharo -> Save).

__Dépôts facultatifs__
1. Tu peux aussi lancer `git clone https://github.com/exercism/pharo-smalltalk` pour créer un dépôt de préparation dans lequel tu généreras les exercices et les ressources à valider (séparément du code écrit dans Pharo). Note que les modifications générées par l'outil Configlet dans ce dépôt devront être copiées dans le dépôt de ton fork local. Il est suggéré d'utiliser quelque chose comme `~/development/exercism/pharo-staging` pour éviter toute confusion (à noter : il peut se trouver n'importe où). Ce dépôt n'est pas indispensable : tu peux toujours générer les modifications de configlet directement dans ton dépôt forké (qui est synchronisé avec ton image Pharo), si tu sais quelles modifications inclure dans ton commit.
2. Tu peux aussi cloner les [spécifications de problèmes](https://github.com/exercism/problem-specifications) d'Exercism, si tu veux travailler sur des exercices d'entraînement à partir de zéro. Place-le également dans un sous-répertoire de l'espace de travail Exercism configuré ci-dessous (ce dépôt sert à générer les fichiers readme.md des exercices et constitue une référence pour les tests suggérés).

### __Note sur les branches de dépôt utilisées__

La branche `main` est la branche de développement principale, dans laquelle tout est fusionné. Si tu travailles sur une modification du code, crée une branche de fonctionnalité issue de `main` et fais-y tes commits. Une fois terminé, ouvre une PR sur GitHub pour qu'elle soit fusionnée dans `main` du dépôt de base (Exercism/pharo-smalltalk). Cette branche s'appelait autrefois `master`, __désormais obsolète__.

### __Mise en place des outils CLI d'Exercism__

Ces outils sont nécessaires pour interagir avec le projet Exercism :
1. l'[interface en ligne de commande exercism](https://exercism.io/cli-walkthrough), que tu configures vers le répertoire de développement des exercices Exercism appelé espace de travail (par exemple `exercism configure -w ~/development/exercism`). Cela peut être le chemin de ton dépôt fork local ou, en option, du dépôt de préparation.
2. le linter/générateur [configlet](https://github.com/exercism/configlet#usage) d'Exercism, qui sert à générer les métadonnées des exercices et à lancer les validations. Pour installer Configlet, suis les instructions du paragraphe [Utilisation dans ton parcours](https://github.com/exercism/configlet#use-in-your-track) (voir bin/fetch-configlet).

## Travailler sur les exercices Exercism

L'organisation Exercism distingue les exercices d'apprentissage (qui expliquent la théorie des langages) et les exercices d'entraînement. Les paragraphes ci-dessous se concentrent pour l'instant uniquement sur la contribution aux exercices d'entraînement.

### __Aperçu__

Étapes pour mener un exercice à bien :
1a. Créer un exercice d'entraînement à partir de zéro (à partir des spécifications de problèmes).
1b. Travailler sur la solution d'un exercice d'entraînement existant.
2a. Générer les fichiers sources sérialisés de la solution de l'exercice dans un répertoire et générer les métadonnées de l'exercice.
2b. Ajuster la baseline du projet pour inclure l'exercice tout juste terminé.
3. Faire tes commits dans ton fork de dépôt et publier les modifications en ouvrant une PR.

#### TLDR : guide rapide pour générer et exporter un exercice d'entraînement
En bref : tout ce dont tu as besoin, c'est de générer et d'exporter l'exercice depuis Pharo. Exécute dans le Playground :
```Smalltalk
"Obtain exercise from problem specification"
ExercismExerciseGenerator new generateExerciseFrom: 'path-to-problem-specifications/exercises/slug-name' asFileReference.

"Update exercise version within Pharo image  (with updated test cases) to output exercise directory (once you have solution class defined)"
ExercismGenerator new 
	exercisesDirReference: 'path-to-local-repository/exercises/practice' asFileReference;
	generateForExercise: 'slug-name'.
```
  > __Note__ : plus de détails dans les étapes ci-dessous. 

![Flux de travail pour mener à bien un exercice d'entraînement](/docs/images/overview-exercism-pharo-contribution.svg)

### __1. Créer un nouvel exercice d'entraînement__
*TLDR : tous les détails et la description de l'API liés à la génération d'exercices se trouvent dans le commentaire de classe de la classe `ExercismExerciseGenerator`.*  

__Nouveaux exercices à partir du dépôt de problèmes__
- Si tu veux créer un exercice d'entraînement entièrement nouveau (étape 1a.), tu peux utiliser le dépôt des spécifications de problèmes et générer la classe de test de l'exercice donné en lançant : 
`ExercismExerciseGenerator generateFrom: <path-to-problem-specifications/exercises>`, ce qui générera les classes de test de tous les exercices du dépôt des spécifications de problèmes dans le paquet `ExerciseWIP`.  

  > __Note__ : tu peux obtenir le même résultat via un élément de menu de l'image Pharo (World menu -> Exercism -> Generate test cases).
- Plus précisément, tu peux générer la classe de test d'un exercice donné avec : `ExercismExerciseGenerator generateExerciseFrom: '<path-to-problem-specifications/exercises/slug-name>' asFileReference`.

Le résultat de l'instruction précédente sera une nouvelle classe de test `<SlugNameTest>` (une sous-classe d'ExercismTest) contenant les méthodes de test générées, dans le paquet `ExerciseWIP`.

__Régénérer un exercice existant à partir du dépôt de problèmes__
Si tu veux régénérer les méthodes de test d'un exercice existant (déjà défini dans le paquet de solution, par exemple `Exercise@TwoFer`), tu peux utiliser le code suivant. Note que les autres méthodes ne seront pas touchées (par exemple uuid, version, etc.) 

 `ExercismExerciseGenerator new regenerateExerciseFrom: 'path-to-problem-specifications/exercises/exercise-slug' asFileReference`

__À partir de zéro__  
Si tu as une idée intéressante, consulte la documentation sur l'ajout de nouveaux exercices.

Il existe un exemple d'exercice défini par l'utilisateur dans le projet, voir : `DieTest`. En redéfinissant la méthode customData, le générateur créera les fichiers pertinents pour toi.

Note que :
- Chaque exercice doit être autonome. Ne fais pas référence à des fichiers en dehors du répertoire de l'exercice : ils ne seront pas inclus quand l'utilisateur récupère l'exercice.
- Les exercices doivent respecter les [normes communes à Exercism](https://exercism.org/docs/building/tracks/practice-exercises).
- Les exercices ne doivent utiliser que les bibliothèques de base de Pharo.
- Chaque exercice doit être :
  - stocké dans un projet de premier niveau nommé `Exercism@<ExerciseName>`
  - avoir un TestCase nommé `<ExerciseName>Test` (en `camelCase`) et une solution d'exemple nommée `<ExerciseName>`
  - le TestCase doit avoir un commentaire de classe au format markdown qui décrit l'exercice. Ce texte sert aussi à générer un fichier README.md.
- Ne fais de commit d'aucun fichier ni répertoire de configuration à l'intérieur de l'exercice (cela pourra être revu pour de futurs exercices ; dis-nous si cela pose problème).
- Pense à générer un nouvel UUID pour l'exercice avec `UUIDGenerator next`, et place cette valeur dans la méthode `uuid` du test.

> __Note__ : le générateur d'UUID actuel de Pharo n'est malheureusement pas conforme à la RFC 4122, version 4. Par conséquent, il faut utiliser l'UUID généré par configlet en évaluant : `/bin/configlet uuid`

### __2. Travailler sur un exercice existant__

S'il y a bien des façons d'aider, de loin la contribution la plus simple et la plus utile est de terminer la solution de l'un des exercices actuellement « ouverts ».

  * Assure-toi que ton image est à jour sur la branche main d'exercism/pharo-smalltalk (et renvoie toute modification vers ton fork).

  * Les exercices sont tous des TestCases générés automatiquement à partir du dépôt problem-specifications mentionné plus haut. Tu les trouveras sous forme de sous-classes d'ExercismTest dans le paquet ExercismWIP. Note que le test ExercismTest régénéré peut déjà se trouver dans le paquet de l'exercice donné, si la solution était déjà en place. Le paquet ExercismWIP sert aux exercices nouveaux ou en cours de développement qui n'ont pas encore été déployés, avec leur classe de solution.

  * Une fois que tu as choisi l'exercice sur lequel tu veux travailler, crée une Issue sur Github en indiquant « Convert Exercise <name> ». Cela permettra aux autres de savoir que tu travailles dessus et servira de base à ta future pull request.

  * Chaque exercice en cours de développement a déjà la description du problème dans son commentaire de classe ; lance ses tests et développe une solution en TDD (dans le débogueur si tu exécutes le premier test tout seul).

  * Il se peut que tu doives __ajuster le test s'il n'est pas de l'idiomatique Smalltalk__ (notre générateur est assez basique ; ceci dit, certaines corrections pourraient mériter d'être renvoyées en PR vers le texte amont des [spécifications de problèmes](https://github.com/exercism/problem-specifications)).

  * Mets à jour les métadonnées de l'exercice du côté classe de l'exercice en redéfinissant la méthode #exercise et en renseignant une difficulté, des thèmes, etc. Tu devrais aussi remplir un peu de texte d'indice dans l'onglet de commentaire du test (tout en bas, en remplaçant le texte TBD).

  * Mets à jour le paquet de l'exemple choisi en `Exercise@<ExerciseName>` (c'est-à-dire sors-le du paquet WIP), étape 1b.
  * Crée une nouvelle branche dans Iceberg portant le nom de l'exercice que tu as choisi (tu peux utiliser l'outil Iceberg pour cela, et y saisir le numéro de ton issue mentionné plus haut).
  * Avant de soumettre ta pull request, lance tous les tests des exercices Pharo et assure-toi qu'ils __passent tous__.


### Tests

Au niveau le plus élémentaire, Exercism repose avant tout sur les tests et sur l'usage de [suites de tests](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md).

Les exercices Pharo d'Exercism sont organisés en sous-paquets, chacun contenant un TestCase qui doit être compatible avec [SUunit](https://en.wikipedia.org/wiki/SUnit). C'est la bibliothèque xUnit d'origine, et aucun framework tiers supplémentaire n'est nécessaire pour les exercices.

Pour tester un exercice, exécute-le depuis l'exécuteur de tests intégré en cliquant sur l'orbe de test. L'orbe devient vert si les tests réussissent, ou orange ou rouge selon qu'il y a des échecs ou des erreurs, respectivement. Sinon, tu peux lancer les tests manuellement dans le Playground en évaluant :

```smalltalk
<ExerciseName>Test suite run. "single exercise"

AllExercismTests suite run. "all exercises"
```
> __Note :__ si tu veux définir ton propre cas de test (non généré), tu peux le placer dans le protocole `extra` de la classe de test.
Pour rester cohérents, nous utilisons l'ordre des paramètres de test suivant : `self assert: actual equals: expected` dans la méthode de test.


Pour tester dans une image qui n'est pas une image de développement, suis les [étapes d'installation pour les utilisateurs](./docs/INSTALLATION.md). Si tu
utilises cette image pour tester des baselines de développement ultérieures, il se peut que tu doives supprimer les répertoires de développement suivants pour être sûr d'obtenir le code le plus récent :
`./pharo/pharo-local/iceberg, ./pharo/pharo-local/package-cache`


### __3. Publier un exercice terminé__

Maintenant que tu as terminé la solution et fait tes commits sur ta branche de fonctionnalité locale, tu devrais suivre ces étapes :  
#### Générer le code source de l'exercice
Cela correspond à l'étape 2a : __générer les fichiers de code source__ de la solution et de la ou des classes de test.

__Générer les sources de sortie pour tous les exercices__ 
- `ExercismGenerator generate` -> cela génère tous les fichiers sources de tous les exercices. Il exécute la commande `generate` de configlet et régénère aussi `config.json`, qui liste tous les exercices valides. (Ou, dans le World menu, choisis : « Exercism » -> « Regenerate meta data »)

#### Générer les sources de sortie pour un exercice donné
- Pour utiliser le répertoire par défaut (`repository-root/exercises/practice`)
```
ExercismGenerator new generateForExercise: 'slug-name'
```

Quand il faut exporter vers un répertoire d'exercice donné :
```
ExercismGenerator new 
	exercisesDirReference: 'path-to-exercises/practice' asFileReference;
	generateForExercise: 'slug-name'
```

> __Notes__ : 
  - ExercismGenerator mettra à jour automatiquement le fichier config.json principal (il le crée s'il n'existe pas).
  - il synchronisera tous les docs, métadonnées et chemins de fichiers du ou des exercices indiqués, via la commande configlet. Voir les détails : [Utiliser sync lors de l'ajout d'un nouvel exercice](https://github.com/exercism/configlet#using-sync-when-adding-a-new-exercise-to-a-track)

####  Mettre à jour la baseline du projet Pharo-smalltalk
Étape 2b : mets à jour la baseline du projet Pharo-smalltalk en ajoutant le nom de l'exercice à la liste de la méthode `BaselineOfExercism>>exercisePackageNames`. Cela garantit que ton exercice sera chargé quand le projet est chargé, y compris le nouvel exercice, par la commande Metacello.

#### Soumettre une pull request
Étape 3 : avant de créer la PR, vérifie que les artefacts Exercism sont corrects en lançant la commande CLI :
`bin/configlet lint` (l'automatisation CI lancera de toute façon le lint quand la PR est soumise).  
Si tout est en ordre, la PR peut être créée :
- pousse ta branche vers ton fork, puis crée une pull request sur `exercism/pharo-Smalltalk` 

> __Détails finaux__ : 

- Il est important d'[autoriser les modifications des mainteneurs](https://help.github.com/en/articles/allowing-changes-to-a-pull-request-branch-created-from-a-fork), pour qu'on puisse collaborer avec toi sur ta branche.
-  Les pull requests doivent porter sur un seul exercice, une seule issue ou une modification conceptuellement cohérente. Consulte les [recommandations d'Exercism en matière de pull request](https://github.com/exercism/docs/tree/main/building/github#guides) pour plus de détails.
- Suis ta PR et réponds aux éventuelles questions qui suivent.
- Enfin, soumets tes éventuels ajustements et un mainteneur fusionnera ta pull request pour que la solution finale apparaisse sur le site.

## Informations complémentaires pour les mainteneurs

### Style de code

Dans la mesure du possible, le code de ce dépôt doit suivre les conventions de [Pharo with style](https://github.com/SquareBracketAssociates/Booklet-PharoWithStyle). Tu peux aussi te référer au document plus général [Smalltalk with style](http://sdmeta.gforge.inria.fr/FreeBooks/WithStyle/SmalltalkWithStyle.pdf).

Pense aussi à utiliser le formateur de code intégré (meta-t FO dans l'éditeur) quand tu crées des exercices, ainsi que les critiques de code.

### Changements incompatibles

Si tu prévois des changements importants ou incompatibles, ouvre une issue pour qu'on puisse en discuter avant de fusionner. Si cette discussion concerne plus que le parcours Pharo, ouvre aussi une issue dans [exercism/discussions](https://github.com/exercism/discussions/issues).
