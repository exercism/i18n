# Introduction

## Les _strings_

### Les caractères

Un **encodage de caractères** est une convention précise qui sert à représenter les éléments de texte d'une langue naturelle sous forme d'une séquence d'octets.
Un « élément de texte », ici, peut être n'importe quelle unité qui a un sens dans une langue naturelle : des lettres, des espaces, de la ponctuation, des émojis, des idéogrammes, etc.

NASM (The Netwide Assembler, l'assembleur utilisé par ce parcours) prend en charge la définition de données au moyen d'**ASCII**.

Les constantes de caractères en NASM peuvent faire jusqu'à 8 octets et peuvent être définies avec des guillemets simples (`'`), des guillemets doubles (`"`) ou des accents graves (`` ` ``) :

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Les caractères spéciaux doivent être définis entre accents graves et échappés avec `\` :

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Note que x86-64 n'offre aucune prise en charge native d'un encodage de caractères en tant que type distinct.
En assembleur, les données sont une séquence d'octets, et c'est au programmeur de décider comment interpréter ces octets, que ce soit comme un caractère, un nombre ou autre chose.

Par exemple, le caractère ASCII '0' est un octet unique de valeur 48.
Donc stocker 48 dans un octet revient exactement à stocker le caractère ASCII '0' :

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Pour cette même raison, manipuler des caractères revient à transformer directement les valeurs contenues dans ces octets :

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### Les _strings_

Une **chaîne de caractères** est une séquence de caractères.
En assembleur, elle est généralement implémentée sous forme d'un tableau.

Il est possible de déclarer une _string_ en NASM de la même manière qu'on déclarerait n'importe quel tableau :

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Une différence entre les _strings_ et les autres tableaux, c'est que NASM permet aussi de déclarer des _strings_ sans virgule (`,`) entre les valeurs.
Il est également possible de mélanger les deux, en séparant certaines valeurs par des virgules :

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Note que, comme déjà mentionné, les caractères ne sont que des octets (ou une séquence d'octets dans un encodage Unicode) :

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Comme chaque caractère ASCII occupe un seul octet, tout octet suivant dans une taille plus grande vaut `0`.
Par exemple, déclarer `'a'` en quadruple mot (8 octets) signifie que le premier octet vaut `'a'` (`97`) et que les sept autres octets valent tous `0`.

Pour cette raison, tous ces exemples sont équivalents :

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
En assembleur, les _strings_ ne se terminent pas automatiquement par un caractère NUL ASCII (valeur `0`).

Lorsqu'elles sont utilisées avec des langages de plus haut niveau, comme le C, il incombe au programmeur de veiller à ce que le bon terminateur, s'il existe, soit ajouté à la fin de la _string_.
~~~~

### Les instructions _string_

Comme les _strings_ sont des tableaux, on peut les manipuler de la même façon que n'importe quel tableau, en déréférençant explicitement la mémoire :

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

En plus de cela, il existe quelques instructions pour charger, déplacer et stocker des valeurs dans des séquences d'octets en mémoire.
Bien qu'on les appelle _string instructions_, elles peuvent être utilisées avec n'importe quelle séquence d'octets en mémoire, c'est-à-dire avec n'importe quel tableau.

Les trois instructions _string_ les plus importantes sont `lods`, `stos` et `movs` :

| instruction | ce qu'elle fait                                                                                                   |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | charge une valeur depuis un emplacement mémoire indiqué par `rsi` dans `rax`                                      |
| `stos`      | stocke une valeur de `rax` dans un emplacement mémoire indiqué par `rdi`                                          |
| `movs`      | copie une valeur depuis un emplacement mémoire indiqué par `rsi` et la stocke dans un emplacement mémoire indiqué par `rdi`    |

Note que ces instructions ne prennent _aucun_ opérande explicite.
Leurs opérandes sont implicites.

En règle générale :

1. Quand leur opérande source est un emplacement mémoire, son adresse doit être stockée dans `rsi` (`s` pour source).
2. Quand leur opérande destination est un emplacement mémoire, son adresse doit être stockée dans `rdi` (`d` pour destination).
3. Si l'un des opérandes n'est pas un emplacement mémoire, il s'agit du registre `rax`.

Note que ces instructions déréférencent automatiquement les adresses mémoire en fonction de l'opération précise qu'elles effectuent.

Toutes peuvent opérer sur différentes tailles.
Un suffixe est ajouté pour indiquer cette taille :

| suffixe | signification | taille  |
| :-----: | ------------- | :------ |
|   `b`   | octet         | 1 octet |
|   `w`   | mot           | 2 octets |
|   `d`   | double mot    | 4 octets |
|   `q`   | quadruple mot | 8 octets |

Par exemple :

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

Elles mettent également à jour toute adresse utilisée, de la taille de l'opération.
Cette mise à jour se fait en fonction de la valeur du **drapeau de direction (DF)** :

- Si le `DF` est effacé, les adresses sont _augmentées_ de la taille de l'opération.
- Si le `DF` est positionné, les adresses sont au contraire _diminuées_ de la même quantité.

L'ABI System V impose que le drapeau de direction soit effacé à l'entrée d'une fonction.
Ainsi, _le comportement par défaut est une lecture et une écriture de la mémoire dans l'ordre croissant des adresses_.

L'instruction `cld` permet d'effacer le drapeau de direction, tandis que l'instruction `std` permet de le positionner :

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
L'appelant s'attend à ce que le `DF` soit effacé après le retour de toute fonction appelée, conformément à l'ABI System V.
Si tu positionnes un jour le `DF`, veille à l'effacer avant `ret`.
~~~~

#### Rep

En dehors de celles-ci, l'instruction **rep** n'interagit pas directement avec la mémoire.
Elle peut au contraire être ajoutée comme préfixe aux autres instructions mentionnées, ce qui a pour effet de les _répéter_.

Lorsqu'elles sont préfixées par `rep`, les instructions _string_ sont répétées un nombre de fois égal à la valeur contenue dans `rcx`.
À chaque répétition, la valeur de `rcx` est diminuée de `1`.
Note que la valeur de `rcx` doit être définie avant d'utiliser l'instruction :

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
Sur les processeurs modernes, `rep movs` et `rep stos` sont généralement des options rapides pour déplacer des données par gros blocs.
Les autres instructions _string_, et même `movs` et `stos` lorsqu'elles opèrent sans `rep`, sont en revanche généralement plus lentes qu'une simple boucle.

Pour un point de vue plus approfondi sur ce sujet, voir [le chapitre 16.9, « String instructions », de ce livre de référence][agner-optimization-guide].
