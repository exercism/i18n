# Classes génériques

```sather
class LOST_BOX{T} is
   attr item : T;
   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;
end;
```

## Ce qu'est le paramètre

`T` représente un type fourni au moment de l'utilisation. Sather construit une classe distincte pour chaque combinaison réellement utilisée, au moment de la compilation du programme. Ainsi :

- `LOST_BOX{STR}` et `LOST_BOX{INT}` sont des types sans lien entre eux ;
- il n'y a aucune vérification à l'exécution, aucun _boxing_ et aucune conversion ;
- une erreur dans la classe apparaît pour chaque type avec lequel elle est utilisée.

C'est la même approche que les _templates_ C++ ou les génériques de Rust, et non celle des génériques de Java, où le type est effacé et où tout est en réalité un objet.

## Paramètres contraints

Un `T` nu peut être affecté, passé et renvoyé, et rien de plus, car on ne sait rien d'autre de lui. Pour appeler des routines sur ce type, il faut dire à quoi il doit se conformer :

```sather
class LOST_BOX{T < $STR} is
   describe : STR is return "a box holding " + item.str; end;
end;
```

`T < $STR` exige que `T` se conforme à `$STR` et permet, en retour, d'appeler `item.str`. Tout ce qu'un `T` nu ne peut pas faire, une contrainte permet de l'autoriser.

Sans la contrainte, `item.str` ne compilera pas, et le message désignera la ligne à l'intérieur de la classe générique, pas la ligne qui l'a utilisée.

## Des routines génériques ?

Il n'y en a pas. Seules les classes prennent des paramètres. Une routine qui doit fonctionner avec plusieurs types vit soit dans une classe générique, soit prend un type abstrait tel que `$STR`.

## Choisir entre les deux

| | classe générique | classe abstraite |
| --- | --- | --- |
| décidé | à la compilation | à l'exécution |
| contient | un type par instanciation | n'importe quel type conforme |
| coût | aucun | une répartition |

`ARRAY{$ACT}` utilise les deux : générique pour le type des éléments, abstraite pour ce que cet élément peut être.

Opte pour une classe générique quand le type est le même d'un bout à l'autre et que l'utilisateur de la classe le sait. Opte pour une classe abstraite quand plusieurs types doivent coexister dans une même collection.
