# Introduction

La fonction `switch()` peut être un remplacement concis d'une longue série de tests `if` ... `else if`.
La variable sur laquelle porte le `switch()` est le plus souvent une _string_, et dans ce cas les guillemets peuvent être omis dans le sélecteur.

```R
star <- function(type) {
  switch(type,
    M = , # will "fall through" if no value given
    K = "red dwarf",
    G = "Earth-like",
    "bigger star" # only correct for O,B,A,F
  )
}

> star("M")
[1] "red dwarf"
```

Note que l'option suivante n'est utilisée que si la valeur est laissée vide, comme avec `M` dans l'exemple ci-dessus.
Il n'est pas nécessaire d'inclure des instructions `break`, contrairement à certains autres langages.

Quand on fait un `switch()` sur des types `character`, la dernière valeur sert de valeur par défaut, comme ici.
Avec les types `integer`, aucune valeur par défaut n'est possible.

## Les fonctions de `dplyr`

Le `switch` de R de base est assez limité : il ne fait qu'une correspondance exacte avec une seule entrée.
Cela semblait raisonnable lors de la première version de R en 1993, mais mérite des améliorations pour un usage moderne.

~~~~exercism/note
Comme mentionné dans le concept [`Conditionals`][concept-conditionals], la collection de paquets `tidyverse` est conçue pour compléter (et parfois remplacer) les fonctionnalités de R de base sans compromettre la rétrocompatibilité.

Pour faire entrer le paquet `dplyr` dans la portée de ton code, ajoute `library(dplyr)` (pour ce seul paquet) ou `library(tidyverse)` (pour toute la collection) en haut de ton code.

La bibliothèque `dplyr` fournit deux fonctions supplémentaires liées à `switch`.

### Les fonctions `recode_values` et `replace_values`

Ces deux fonctions apparentées permettent une transformation vectorisée, semblable à un `switch`, des anciennes valeurs vers de nouvelles valeurs.

La principale différence entre elles est que `recode_values()` crée un vecteur entièrement nouveau, tandis que `replace_values()` permet des mises à jour partielles d'un vecteur existant.

La correspondance reste exacte, mais :

- Les options à gauche peuvent être des vecteurs, et l'entrée correspond si au moins un élément correspond.
- Les options à gauche et les résultats à droite sont reliés par un tilde `~` au lieu de `=`.
- Une valeur par défaut peut être spécifiée dans tous les cas.

```R
library(dplyr)

x <- c("a", "b", "a", "d", "b", NA, "c", "e", "z")
recode_values(
  x,
  "a" ~ 1,
  "b" ~ 2,
  "c" ~ 3,
  c("d", "e") ~ 4, # either "d' or "e" will match
  NA ~ 0,          # matches missing values
  default = 100   # note the different syntax for the default
)
#> [1]   1   2   1   4   2   0   3   4 100
```

### La fonction `case_when`

`case_when` pousse la syntaxe de `case_match` un cran plus loin, en autorisant n'importe quelle expression logique à gauche du `~`.

Le vecteur d'entrée (`x` dans l'exemple ci-dessous) n'est pas fourni comme argument : il doit simplement être déjà défini.

```R
x <- 1:10
case_when(
  x < 3 ~ "low",
  between(x, 3, 5) ~ "mid",
  between(x, 6, 8) ~ "high",
  .default = "what?"
)
#>  [1] "low"   "low"   "mid"   "mid"   "mid"   "high"  "high"  "high"  "what?" "what?"
```

La fonction `between()` fait aussi partie de `dplyr`.
