# À propos

## Représentation, caractères et entiers

Comme les autres types simples (`int`, `bool`, etc.), le `char` a un type compagnon, ou alias, en l'occurrence `System.Char`.

Il s'agit en fait d'une `struct` avec un champ de 16 bits, immuable par défaut.

`char` possède quelques méthodes d'instance telles que `Equals`, `ToString` et [`CompareTo`][compare-to].

`char` a la même largeur qu'un [`ushort`][uint16], mais on ne les utilise généralement pas de façon interchangeable comme c'est le cas dans certains langages. Un `ushort` doit être converti explicitement en `char`.

Pour ce que ça vaut, les `char` peuvent faire l'objet d'opérations arithmétiques. Le résultat de ces opérations est un entier.

Évidemment, il n'y a pas d'équivalence entre un `byte` de 8 bits et le `char` de 16 bits.

## Utilisation

Les `char` sont généralement faciles à utiliser.

On peut les définir comme des littéraux entre apostrophes :

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

On peut récupérer un `char` individuel dans une _string_ grâce à un indice (à partir de zéro) :

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

Parcourir une _string_ renvoie un `char` à chaque étape :

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

Comme montré ci-dessus, un `char` peut être converti en sa valeur `int`.
Cela fonctionne aussi (*au moins dans certains cas*) pour d'autres écritures :

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

C'est l'Int16 sous-jacent qui est utilisé pour comparer des caractères :

```fsharp
'A' < 'D'
// => val it: bool = true
```

De même, un `int` peut être converti en `char` :

```fsharp
char 77
// => val it: char = 'M'
```

La bibliothèque `System.Char` contient l'ensemble complet des [méthodes][Char-methods] attendues pour un langage .NET, comme les conversions majuscules/minuscules (mais voir les réserves de la section suivante) :

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

Les bibliothèques .NET aident à extraire des `char` à partir de _strings_, ici grâce aux méthodes de `Seq` :

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

Il existe plusieurs façons de convertir une liste (ou un tableau) de caractères en _string_, notamment celles-ci :

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

On trouvera des informations générales sur les `char` ici :

- [Documentation sur les `char`][chars-docs] : la documentation de référence pour `char`.

Cependant, les `char` présentent un certain nombre d'aspérités, détaillées ci-dessous. Ces aspérités tiennent surtout à l'opposition entre, d'un côté, la norme Unicode complète et, de l'autre, les représentations historiques du texte ainsi que les considérations de performance et d'usage de la mémoire.

## Problèmes liés à Unicode

Quand on manipule des _strings_, si les méthodes de la bibliothèque [`System.String`][System-string] sont disponibles, il faut les privilégier plutôt que de décomposer la _string_ en caractères.

Certains « caractères » textuels sont composés de plus d'un `char`, car la norme Unicode compte plus de 65536 points de code. Par exemple, les emojis qui apparaissent dans certains tests comptent 2 `char`, car ils sont constitués de caractères [de substitution][surrogates].

De plus, il existe des séquences combinantes : dans certains cas, un caractère accentué peut être composé d'un `char` pour le caractère de base et d'un autre `char` pour l'accent.

Si tu dois manipuler des caractères individuels, essaie d'utiliser des méthodes de bibliothèque telles que [`System.Char.IsControl`][is-control] et [`System.Char.IsDigit`][is-digit] plutôt que de faire des comparaisons naïves, par exemple vérifier qu'un caractère se situe entre '0' et '9'.

Par exemple, note que '٢' est le chiffre arabe 2. `IsDigit` renverra vrai pour la version arabe, tu dois donc préciser, lorsque tu valides, quelle plage d'entrées est acceptable.

Même les méthodes de la bibliothèque `System.Char` peuvent ne pas se comporter comme tu l'attends face à des langues plus obscures.

Une façon sûre de découper une _string_ en « caractères » affichables consiste à utiliser [`StringInfo`][string-info] et des méthodes telles que [`GetNexttextElement`][get-next-text-element].
Cela peut être nécessaire si tu travailles sur la globalisation ou la localisation.

Une autre piste, lorsque les valeurs scalaires des caractères Unicode importent (par exemple si tu écris ton propre système d'encodage), consiste à utiliser des [runes][runes]. Cependant, si tu sais que la plage de caractères que tu traites ne comprend ni substituts ni séquences de caractères combinants (par exemple l'ASCII latin) et que tes entrées sont bien validées, tu peux t'en passer.

Encore une fois, la meilleure situation est celle où tu peux utiliser les méthodes de bibliothèque de `String`.

Si tu te retrouves dans la position peu enviable de devoir gérer les détails les plus fins d'Unicode, alors [ceci][char-encoding-net] est un bon point de départ.

## Globalisation

Si tu travailles dans un environnement où tu as affaire à plusieurs cultures, ou si la culture importe dans certaines parties du code mais pas dans d'autres, sache qu'il existe des surcharges de [`ToUpper`][to-upper] et [`ToLower`][to-lower] qui prennent une culture, ainsi que [`ToUpperInvariant`][to-upper-invariant] et [`ToLowerInvariant`][to-lower-invariant], qui fournissent un résultat cohérent indépendamment de la [culture][culture-info] courante.
