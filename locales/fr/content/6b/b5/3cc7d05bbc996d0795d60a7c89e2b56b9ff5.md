# À propos

Les _slices_ de Go ressemblent aux listes ou aux tableaux que l'on trouve dans d'autres langages.
Ils contiennent plusieurs éléments d'un type précis (ou d'une interface).

Les _slices_ de Go reposent sur les tableaux.
Les tableaux ont une taille fixe.
Un _slice_, en revanche, est une vue flexible et de taille dynamique sur les éléments d'un tableau.

Un _slice_ s'écrit `[]T`, où `T` est le type des éléments qu'il contient :

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

On peut lire ou modifier un élément à un indice donné, en partant de zéro, grâce à la notation entre crochets :

```go
withData[1] = 5
x := withData[1] // x is now 5
```

On peut créer un nouveau _slice_ à partir d'un _slice_ existant en sélectionnant une plage d'éléments.
Là encore avec la notation entre crochets, mais en précisant à la fois l'indice de début (inclus) et l'indice de fin (exclu).
Si on ne précise pas d'indice de début, il vaut 0 par défaut.
Si on ne précise pas d'indice de fin, il vaut par défaut la longueur du _slice_.

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

On peut ajouter des éléments à un _slice_ avec la fonction `append`.
Ci-dessous, on ajoute `4` et `2` au _slice_ `a`.

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append` renvoie toujours un nouveau _slice_ et, lorsque l'on veut simplement ajouter des éléments à un _slice_ existant, il est courant de réaffecter le résultat à la variable de _slice_ passée en premier argument, comme on l'a fait ci-dessus.

On peut aussi utiliser `append` pour fusionner deux _slices_ :

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## Les indices dans les _slices_

La manipulation des indices d'un _slice_ doit toujours être protégée, d'une manière ou d'une autre, par une vérification qui s'assure que l'indice existe réellement.
Sans cette vérification, c'est toute l'application qui plante.

## Les _slices_ vides

Un _slice_ `nil` est le _slice_ vide par défaut.
Il n'a aucun inconvénient par rapport à un _slice_ sans aucune valeur.
La fonction `len` fonctionne sur les _slices_ `nil`, on peut y ajouter des éléments sans l'initialiser, et ainsi de suite.
Si on crée un nouveau _slice_, mieux vaut `var s []int` (_slice_ `nil`) que `s := []int{}` (_slice_ vide, non `nil`).

## Performance

Lorsqu'on crée des _slices_ que l'on va remplir de façon itérative, il existe un moyen simple d'améliorer les performances, si la taille finale du _slice_ est connue.
L'essentiel est de minimiser le nombre de fois où de la mémoire doit être allouée, une opération plutôt coûteuse qui se produit quand le _slice_ dépasse l'espace mémoire qui lui a été alloué.
La façon la plus sûre de faire cela est de préciser une capacité `cap` pour le _slice_ avec `s := make([]int, 0, cap)`, puis d'y ajouter des éléments avec `append` comme d'habitude.
Ainsi, l'espace nécessaire pour `cap` éléments est alloué immédiatement, alors que la longueur du _slice_ est nulle.
En pratique, `cap` est souvent la longueur d'un autre _slice_ : `s := make([]int, 0, len(otherSlice))`.

## `append` n'est pas une fonction pure

La fonction `append` de Go est optimisée pour les performances et ne fait donc pas de copie du _slice_ d'entrée.
Cela signifie que le _slice_ d'origine (premier paramètre de `append`) est parfois modifié.
