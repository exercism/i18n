# Instructions

Le travail avance bien chez _Instruments of Texas_ sur la calculatrice RPN. Ton équipe veut maintenant pouvoir écrire une version sous forme de _string_ de l'équation vers une ressource _IO_.

## 1. Ouvre un fichier

Ton équipe n'a pas encore décidé vers quel type de périphérique écrire l'équation, tu suggères donc d'utiliser une approche de _dynamic dispatch_ pour pouvoir injecter la ressource dans la fonction plutôt que de la coder « en dur » (utiliser une valeur fixe au lieu d'une variable que l'on peut modifier à tout moment). Implémente la fonction `write/3` pour ouvrir un _IO device_ à partir de la ressource et du nom de fichier.

Tu peux supposer que `resource` est toujours un atome qui représente un module possédant une fonction `open/1` qui renvoie `{:ok, io_device}`.

Quand la fonction réussit, renvoie un tuple ok contenant l'équation.

```elixir
RPNCalculator.Output.write(resource, "file_to_be_written", "1 4 +")
# {:ok, "1 4 +"}
```

## 2. Essaie d'écrire dans l'_IO device_

Maintenant que tu as ouvert l'_IO device_, essaie d'y écrire avec `IO.write/2`.

Étends la fonction `write/3` pour effectuer cette action. La tentative d'écriture peut lever une erreur ; dans ce cas, rattrape l'erreur et renvoie un tuple d'erreur :

```elixir
RPNCalculator.Output.write(resource, "bad_file", "1 4 +")
# {:error, "Unable to write to resource"}
```

## 3. Ferme l'_IO device_

C'est une bonne pratique d'essayer toujours de libérer les ressources que tu as ouvertes, même si la fonction qui utilise la ressource lève une erreur. Étends la fonction `write/3` pour appeler la fonction de fermeture de la ressource afin de fermer l'_IO device_.

Tu peux supposer que `resource` est toujours un atome qui représente un module possédant une fonction `close/1` qui prend un _IO device_.
