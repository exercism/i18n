# À propos

Un `Iterator` en Gleam est similaire à un tableau : c'est une collection ordonnée de valeurs, toutes du même type. Il diffère d'un tableau en ce qu'il est paresseux, c'est-à-dire qu'il ne stocke pas toutes ses valeurs en mémoire d'un coup, mais les calcule au fur et à mesure des besoins.

C'est utile lorsqu'on travaille avec des séquences très grandes, voire infinies, car cela permet de les manipuler même quand on ne dispose pas d'assez de mémoire libre pour les stocker entièrement.

Le module `gleam/iterator` définit le type `Iterator` ainsi que des fonctions pour manipuler les itérateurs.

Beaucoup de fonctions qui existent pour les tableaux existent aussi pour les itérateurs, comme `map`, `filter` et `take`. Ces fonctions renvoient des itérateurs : elles ne font donc aucun travail tant que l'itérateur n'a pas été consommé.

```gleam
let iter = 
  [1, 2, 3, 4, 5, 6]
  |> iterator.from_list
  |> iterator.filter(fn(x) { x > 2 })
  |> iterator.take(2)

// No work has been done yet as the iterator has not been consumed

// Consume the iterator and collect the values into a list
iterator.to_list(iter)
// -> [3, 4]
```

La fonction `unfold` permet de créer des itérateurs à partir d'une fonction appelée de façon répétée pour produire la valeur suivante de la séquence.

Ici, la fonction `unfold` est utilisée pour créer un itérateur qui produit la suite de Fibonacci :

```gleam 
iterator.unfold(#(0, 1), fn(pair) {
  let x = pair.0 + pair.1
  iterator.Next(element: x, accumulator: #(pair.1, x))
})
|> iterator.take(6)
|> iterator.to_list
// -> [1, 2, 3, 5, 8, 13]
```

La séquence est ici infinie : on utilise donc la fonction `take` pour la rendre finie avant de collecter les valeurs dans un tableau. Si on appelle `to_list` sur un itérateur infini, le programme tournera jusqu'à épuiser la mémoire et finira par planter.
