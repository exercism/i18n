# Introduction

Les spécificateurs de classe de stockage concernent la façon dont les variables sont stockées en mémoire.
Ils sont étroitement liés à la durée de stockage (également appelée durée de vie) d'une valeur.

## `auto` : la classe de stockage par défaut des variables de portée de bloc ou de fonction

Comme les variables définies dans un bloc ou une fonction sont `auto` par défaut, il est rare d'employer explicitement ce terme.
La durée de vie d'une variable `auto` commence à l'entrée dans son bloc et se termine à la sortie de ce bloc.
À l'entrée dans son bloc, une variable `auto` se voit allouer de la mémoire, _mais sans valeur par défaut_.

## `static` : le spécificateur de stockage à ne pas confondre avec le type de liaison `static`

Si une variable est définie en dehors d'un bloc ou d'une fonction et est marquée `static`, ce `static` désigne sa liaison, ce qui signifie qu'elle n'est accessible qu'à l'intérieur du fichier.
Si une variable est définie dans une fonction ou dans un bloc à l'intérieur d'une fonction et est marquée `static`, elle a une durée de stockage `static`.
La valeur de la variable `static` persiste entre les appels à la fonction ou au bloc.

## `extern` : comment accéder à une variable située dans une autre unité de traduction

Une unité de traduction se compose d'un fichier source et de tout autre fichier qu'il `#include`.
Bien qu'une variable de portée fichier puisse être déclarée et initialisée comme `extern`, le mot-clé `extern` sert généralement à faire référence à une variable existante, et non à en définir une nouvelle.
La variable à laquelle `extern` fait référence doit avoir une portée fichier.
Une variable de portée fichier a toujours une durée de stockage `static`.
Une variable située dans un fichier inclus doit avoir une liaison externe pour que le fichier qui l'inclut puisse y accéder.

## `register` : comment tenter d'accélérer l'accès à une variable

Une variable marquée `register` exprime le souhait du programmeur de voir sa valeur placée dans un registre pour y accéder rapidement.
Une variable `register` est comme une variable `auto` en ce qu'elle doit se trouver dans la portée d'une fonction ou d'un bloc.
Comme la valeur est censée être placée dans un registre plutôt qu'en mémoire, l'accès à l'adresse de la variable devrait être interdit par le compilateur, car on ne peut pas prendre l'adresse d'un registre.
Cependant, une adresse mémoire peut elle-même être placée dans un registre.
`register` est essentiellement une indication, car la valeur peut ou non être réellement placée dans un registre.

## `typedef` : le spécificateur de classe de stockage qui n'en est pas vraiment un

`typedef` est décrit comme un spécificateur de classe de stockage pour des raisons purement syntaxiques.
En effet, un spécificateur de classe de stockage ne peut pas être utilisé avec un autre spécificateur de classe de stockage.
Ainsi, `typedef auto int i = 42;` est tout aussi illégal que `static auto int i = 42;`.
