# Contrats

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| Clause | Dit | À qui la faute en cas de violation |
| --- | --- | --- |
| `pre` | ce qui doit être vrai à l'entrée | à l'appelant |
| `post` | ce qui est vrai au retour | à la routine |

Les deux prennent un `BOOL`, et toutes deux peuvent utiliser les arguments de la
routine et les attributs de l'objet. `post` peut aussi utiliser `result`, la
valeur renvoyée.

## assert

À l'intérieur du corps d'une routine, `assert` énonce quelque chose qui doit être
vrai à cet endroit précis :

```sather
      assert load <= limit;
```

Il est vérifié par la même option que les autres.

## Invariants de classe

Une classe peut énoncer quelque chose qui est vrai de chacun de ses objets entre
les appels :

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

Vérifié à l'entrée et à la sortie de chaque routine publique, quand la
vérification est activée.

## Active la vérification

| Option | Ce qu'elle vérifie |
| --- | --- |
| `-chk` | tout : pre, post, assert, invariant, bornes, arithmétique |
| `-chk_no` | rien |

Note que `-chk_pre` tout seul n'active *pas* la vérification des préconditions
dans ce compilateur ; c'est `-chk` qui fonctionne. Une violation affiche la
routine et la ligne source, puis arrête le programme. Ce n'est pas une exception,
et `protect` ne l'attrapera pas.

L'usage habituel consiste à développer et tester avec `-chk`, puis à livrer sans,
afin que les vérifications ne coûtent rien dans le programme livré. Cela ne vaut
le coup que si les tests passent réellement par ces chemins.

## Qu'est-ce qui fait un bon contrat

Dis ce dont la routine a besoin, pas comment elle fonctionne :

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

Un `post` qui répète le corps n'apprend rien à personne :

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## Héritage

Un sous-type peut affaiblir un `pre` et renforcer un `post` (accepter plus,
promettre plus), mais jamais l'inverse, sinon le code écrit pour le supertype
casserait. C'est précisément la règle que les contrats servent à rendre
vérifiable.
