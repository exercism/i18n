# Les bases d'Unison

## Termes et fonctions

Les termes et les fonctions sont les unités de base de l'écriture d'un programme Unison.

Un « terme » est ce qu'on appelle une valeur statique. On le définit avec `name = expression`, éventuellement précédé d'une signature de type de la forme `name : MyType`. Unison prend en charge l'inférence de type, donc il est possible que la signature de type soit omise pour les définitions simples.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Les fonctions Unison ressemblent à `myFunctionName argument1 argument2 = myImplementation` ; elles commencent par le nom de la fonction, suivi d'arguments séparés par des espaces.

```
getMax a b = Nat.max a b
```

Les fonctions peuvent, de manière facultative, inclure une signature de type. Le dernier type à droite est toujours le type de retour final de la fonction, et chaque argument est séparé par la flèche de fonction `->`.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Pour appeler une fonction, écris son nom suivi de ses arguments séparés uniquement par des espaces.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Lors de l'appel d'une fonction, Unison essaie de traiter ce qui se trouve juste à droite comme son argument, ce qui ne produit pas toujours l'ordre d'évaluation souhaité.

Imaginons que l'on veuille obtenir la valeur `1` à partir de l'expression suivante

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Telle qu'elle est écrite, `shouldBe1` s'évalue à `0`, car l'ordre d'application de fonction implicite est `getMax 1 10`, ce qui donne `10`, puis `10 - 10`, ce qui donne `0`.

Tu peux utiliser des parenthèses pour regrouper l'expression selon l'ordre d'opérations souhaité.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Les expressions _watch_

Unison propose un moyen d'évaluer rapidement du code, appelé une expression _watch_. Une expression _watch_ commence par un symbole `>` et est suivie de l'expression à évaluer. Les expressions _watch_ peuvent être écrites dans n'importe quel fichier avec l'extension `.u`. Dès que tu enregistres le fichier, tu devrais voir à quoi l'expression s'évalue dans la console de l'Unison Codebase Manager (UCM). Dans la mesure du possible, dans cette documentation, on essaiera de montrer une expression accompagnée de son résultat attendu après l'avoir évaluée dans une expression _watch_.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Les fonctions multilignes

Les fonctions multilignes d'Unison utilisent l'indentation ou des blocs `let` pour délimiter le code, c'est-à-dire la « portée lexicale ».

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Tout ce qui se trouve au même niveau d'indentation partage la même portée, c'est pourquoi on peut référencer la variable `newBeginning` dans la dernière ligne.

## Les espaces de noms et les instructions `use`

Les espaces de noms servent à regrouper et organiser les fonctions Unison. Tu peux les voir comme l'équivalent des « répertoires ». Ils apportent structure et regroupement logique.

Tu peux faire entrer les fonctions d'un espace de noms dans la portée courante avec une instruction `use`.

Imaginons que tu écrives une fonction qui utilise des valeurs `List` d'Unison. Tu sais que tu auras besoin de fonctions comme `List.map` et `List.flatMap`, où `List` est l'espace de noms et `map` et `flatMap` des fonctions. Pour éviter les répétitions, tu peux choisir de faire entrer tout le contenu de l'espace de noms `List` dans la portée lexicale de ta fonction, comme ceci :

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

La ligne `use List` lève l'ambiguïté sur les références à `map` et `flatMap`. Tu peux en savoir plus sur [les instructions `use` ici][use-statements].

## La bibliothèque standard d'Unison

La bibliothèque standard d'Unison s'appelle `base`. Si tu as suivi le guide de démarrage rapide et que tu as créé une base de code en local, la bibliothèque standard a normalement été téléchargée automatiquement. Tu peux parcourir la documentation de la bibliothèque standard en ligne sur [Unison Share][unison-share-base].

## Les commentaires et les littéraux de documentation

Les commentaires en Unison sont une fonctionnalité un peu inhabituelle. Quand tu écris du code Unison, tu peux créer dans ton fichier avec l'extension `.u` du texte qui n'est pas interprété, avec la syntaxe suivante :

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Cependant_, comme le code Unison est enregistré sous forme de hachage de son arbre syntaxique abstrait, et non sous forme de fichiers texte sur le système de fichiers, les commentaires, qui sont des « décorations » textuelles d'une fonction ou d'un terme Unison donné dans le fichier, ne peuvent pas vraiment être enregistrés et réaffichés pour être partagés. Si tu souhaites ajouter une information à ton terme Unison d'une manière qui sera conservée pour que d'autres puissent la lire et la comprendre, tu peux utiliser un littéral de documentation.

La documentation est une valeur de première classe dans le langage de programmation Unison. Cela signifie qu'un élément `Doc` peut être affecté à une valeur, passé comme valeur à une fonction, ou renvoyé comme valeur d'une fonction. Les éléments de littéral de documentation s'ouvrent et se ferment avec des doubles accolades. Voici comment on pourrait utiliser l'élément `Doc` comme commentaire.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
