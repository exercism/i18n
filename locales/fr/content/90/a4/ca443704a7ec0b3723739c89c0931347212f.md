# section sur les commentaires

Go dispose d'[excellentes recommandations](https://golang.org/doc/effective_go.html) sur la façon d'écrire des commentaires. Il existe un format standard que tu peux utiliser pour les commentaires de documentation, que l'outil `godoc` peut ensuite transformer automatiquement en une documentation soignée.

Le commentaire de paquet doit commencer par le mot `Package`, suivi du nom du paquet, comme ceci :

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

Pour les fonctions exportées, les méthodes, les constantes et les variables de paquet, le commentaire doit commencer par le nom, puis se poursuivre par une phrase verbale :

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

Le wiki [CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences) précise en outre que les commentaires de documentation doivent être des phrases complètes, terminées par un point.

En plus d'optimiser la lisibilité, suivre ces recommandations améliore l'aspect de ton code dans [les outils de documentation de Go](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/) tels que [godoc.org](http://godoc.org), `godoc` et `go doc`.

Prends un moment pour lire la section sur les commentaires de documentation dans le guide de style officiel, [Effective Go](https://golang.org/doc/effective_go.html), afin de comprendre le raisonnement qui sous-tend ces choix.
