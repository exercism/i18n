# À propos

L'exercice de programmation illustre un certain nombre de propriétés des paramètres :

- Les paramètres [passés][passing-parameters] sans modificateur (comme `out` ou `ref`) sont passés par valeur. Autrement dit, le paramètre peut être utilisé et recevoir une affectation dans la méthode appelée, mais aucune modification n'aura d'effet sur l'appelant.
- Lorsqu'une référence à un tableau ou à une instance de classe est un paramètre, les éléments ou les champs de cette instance peuvent être modifiés par la méthode appelée, et l'appelant voit ces modifications. Cela vaut que le modificateur `ref` soit présent ou non.
- Un paramètre doté du modificateur [`out`][out-parameter] renvoie une valeur de la méthode appelée vers l'appelant. Le paramètre peut être passé à la méthode appelée sans avoir été initialisé et, dans tous les cas, il y est traité comme s'il n'avait pas été initialisé à l'entrée. C'est en étudiant des exemples (voir ci-dessous) et les messages du compilateur que l'on comprend le plus facilement le comportement et les règles des modificateurs de paramètres.

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- Les paramètres `out` doivent recevoir une affectation dans la méthode appelée.

- Un paramètre doté du modificateur [`ref`][ref-parameter] transmet une valeur à la méthode appelée. Lorsque la méthode se termine, l'appelant retrouve dans ce paramètre les mises à jour effectuées par la méthode appelée.

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

- Les paramètres `ref` doivent être des variables, car la méthode appelée agit directement sur le paramètre tel que le voit l'appelant.

- Les modificateurs `out` et `ref` sont obligatoires à la fois dans la signature de la méthode appelée et au niveau de l'appel.
- Les paramètres `out` peuvent être déclarés directement au niveau de l'appel, à savoir : `Foo(out int importantValue);`
- Si tu appelles une méthode qui prend des paramètres `out` mais que la valeur affectée à l'un ou plusieurs d'entre eux ne t'intéresse pas, tu peux utiliser la variable factice `_` ([rejet][discard]), comme dans : `Foo(out int _);`

Toutes les règles concernant les paramètres `ref` et `out` sont appliquées par le compilateur.

Les paramètres [`in`][in-parameter] existent aussi, mais ils constituent avant tout une optimisation de performance et sont abordés dans l'exercice `structs`, où ils sont le plus pertinents.

La documentation liée ci-dessus est résumée ci-dessous :

- [transmission des paramètres][passing-parameters] : explique comment des valeurs peuvent être passées en arguments. À noter que le sujet des structs et des paramètres est traité dans l'exercice `structs`.
- [paramètres `ref`][ref-parameter] : décrit le fonctionnement des paramètres `ref`.
- [paramètres `out`][out-parameter] : décrit le fonctionnement des paramètres `out`.

En étudiant la documentation, note qu'elle emploie les termes suivants :

- paramètre / paramètre formel : désigne le paramètre tel que le voit la méthode appelée.
- argument : désigne le paramètre tel que le voit l'appelant.

[D'aucuns diront][so-tuples-vs-out] que l'essentiel de l'intérêt des paramètres `out` a disparu avec l'introduction des `tuples` en C# 7. L'exercice `tuples` montre des `tuples` utilisés pour renvoyer plusieurs valeurs.

Même si `ref` est simple à utiliser et n'entraîne aucune pénalité de performance, il vaut la peine de voir comment les problèmes qu'il résout sont traités dans une base de code donnée avant de l'employer à grande échelle. Il existe des alternatives, comme le passage par valeur et l'utilisation de la valeur renvoyée par l'instruction `return` de la méthode appelée. Là encore, les `tuples` peuvent jouer un rôle.

Tu verras dans la [documentation][ref-parameter] que `out` et `ref` ne peuvent pas être utilisés dans certaines situations, mais tu peux les ignorer pour l'instant. Le compilateur te préviendra lorsque de telles situations se présenteront.

Note que les `optional parameters` et les `named arguments` sont abordés dans l'exercice `method-overloading`.

Les sujets connexes de [`ref local`][ref-local] et [`ref return`][ref-return] sont traités ailleurs.

## Allocations sur la pile

Les règles concernant les paramètres et leurs modificateurs sont suffisamment simples pour qu'on puisse les prendre au pied de la lettre et les comprendre à leur niveau d'abstraction. Toutefois, si les mécanismes sous-jacents t'intéressent et que tu veux savoir pourquoi ces mots-clés peuvent faire une différence de performance, au moins dans le cas des `struct`, tu peux commencer par cet [_article Wikipédia_][calling-conventions], en notant que C# utilise `stdcall` sur x86/64.

L'essentiel, c'est que dans le cas de paramètres sans modificateur, la **valeur** d'une variable est copiée sur la pile du programme pour la rendre accessible à la routine appelée, tandis que pour les paramètres `ref`, `out` et `in`, un pointeur (**référence**) vers la mémoire contenant la valeur est placé sur la pile du programme, et les valeurs sont affectées à la mémoire pointée par la référence.
