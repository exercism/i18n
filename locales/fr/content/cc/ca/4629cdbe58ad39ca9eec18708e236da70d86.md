# À propos

[Les gardes][guards] servent de complément au [_pattern matching_][exercism-pattern-matching]. Elles permettent des vérifications plus complexes. On peut les utiliser dans [certaines situations, mais pas toutes][where-guards-can-be-used] là où le _pattern matching_ peut être utilisé, par exemple dans des clauses de fonction ou des clauses `case`.

```elixir
def empty?(list) when is_list(list) and length(list) == 0 do
  true
end
```

- Les gardes commencent par le mot-clé `when`, suivi d'une expression booléenne.
- Les expressions de garde sont des fonctions spéciales qui :
  - doivent être [pures][pure-function] et ne modifier aucun état global ;
  - doivent renvoyer les valeurs strictes `true` ou `false`.
- Une liste de gardes courantes se trouve dans la [documentation d'Elixir][kernel-guards]. Elle comprend :
  - Vérifications de type : [`is_integer/1`][guard-is-integer], [`is_list/1`][guard-is-list], [`is_nil/1`][guard-is-nil], etc.
  - Opérateurs arithmétiques : [`+/2`][guard-plus], [`-/2`][guard-minus], etc.
  - Comparaisons : [`==/2`][guard-equals], [`>/2`][guard-greater], [`</2`][guard-less], etc.
  - Opérateurs booléens : [`and/2`][guard-and], [`or/2`][guard-or], [`not/1`][guard-not]
  - Opérateur d'appartenance : [`in/2`][guard-in]
- Tu peux définir ta propre garde avec [`defguard`][defguard].

  - D'après la [convention de nommage][naming] d'Elixir, les noms de gardes doivent commencer par `is_`.

    ```elixir
    defmodule HTTP do
      defguard is_success(code) when code >= 200 and code < 300

      def handle_response(code) when is_success(code) do
        :ok
      end
    end
    ```
