# À propos

Les `struct` de C# sont étroitement liés aux `class`.
Ils ont un état et un comportement.
Ils peuvent avoir les mêmes types de membres : des constructeurs, des méthodes, des champs, des propriétés, etc.

Les champs et les propriétés peuvent être de types simples, des `struct` ou des types référence.
Les `struct` obéissent aux mêmes règles que les `class` en matière de portée, de lecture/écriture et de niveaux d'accès.

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

L'une des principales choses à retenir est que lorsqu'un struct est affecté à une variable ou passé en paramètre, les valeurs sont copiées, de sorte que les modifications apportées à la variable d'origine n'affectent pas la copie, et inversement.
En résumé, les `struct` sont des **types valeur**.

Cet [article][class-or-struct] traite des différences entre les `struct` et les `class`.
Tu verras dans cet article que les `struct` ont tendance à être légers et [immuables][structs-immutable], bien que cette recommandation ne soit pas imposée (par défaut) par le compilateur ou le runtime.

Il y a quelques points sur lesquels tu vas tomber (et que le compilateur te rappellera) :

1. Les membres d'un `struct` ne peuvent pas être initialisés en ligne.
2. On ne peut pas hériter d'un `struct`.
3. Un `struct` possède toujours un constructeur par défaut, même si un constructeur non par défaut est fourni, et on ne peut pas fournir de constructeur sans paramètre explicite.

Du fait des points 1 et 3 ci-dessus, le développeur d'un `struct` n'a aucun moyen d'empêcher la création d'instances invalides.

## Structs courants

Tu verras dans la documentation qu'il existe une relation étroite entre les types primitifs et les structs.
Voir [`Int32/int`][int32], par exemple.
Un exemple plus classique de `struct` est le type [`TimeSpan`][time-span].

Les instances de `TimeSpan` se comportent à peu près comme des nombres, avec des opérateurs de comparaison comme `>` et `<`, ainsi que des opérateurs arithmétiques.
Tu peux implémenter ces opérateurs pour tes propres `struct` quand tu en as besoin.

Une chose à noter à propos de `TimeSpan` est qu'il implémente plusieurs interfaces, par exemple `IComparable<TimeSpan>`.
Bien que les `struct` ne puissent pas dériver d'autres `struct`, ils peuvent implémenter des interfaces.

## Égalité

Le test d'égalité des `struct` peut souvent être bien plus simple que celui des `class`, car il compare simplement les champs par défaut.
Il n'est pas nécessaire de redéfinir `object.Equals()` (ni `GetHashCode()`).
N'oublie pas que si tu t'appuies sur `Object.GetHashCode()`, tu dois quand même t'assurer que les champs qui participent à la génération du code de hachage (c'est-à-dire tous les champs) ne changent pas pendant qu'une collection à base de hachage est utilisée.
Concrètement, cela signifie que les structs utilisés de cette manière doivent être immuables.

Contrairement à la méthode `Equals()`, il n'existe pas d'implémentation par défaut des opérateurs d'égalité `==` et `!=`.
Si ton `struct` en a besoin, tu devras les implémenter.

D'un autre côté, cet [article][equality] décrit comment on peut optimiser les performances en créant ses propres méthodes `Equals()` et `GetHashCode()` personnalisées, comme on le fait souvent avec les `class`.
Dans le cas de cet exercice, la différence était d'environ 20 % lors d'une comparaison peu rigoureuse, mais elle est peut-être sous-estimée, car tous les champs sont du même type, voir ci-dessous.

On trouve sur le [web][equality-performance] des discussions sur les gains de vitesse, lorsque la méthode `Equals()` n'est pas redéfinie, si tous les champs sont du même type.
Dans cet exercice, la différence en incluant des champs disparates était d'environ 60 %.
Ce n'est pas mentionné dans la documentation de Microsoft, ce qui en fait un détail d'implémentation non documenté, à exploiter avec discernement.

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
