# Introduction

Il existe principalement trois instructions conditionnelles en Julia :

- les expressions `if`
- l'opérateur ternaire
- l'évaluation par court-circuit

## Les expressions `if`

Les expressions `if` en Julia sont similaires à celles que l'on trouve dans d'autres langages :

```julia-repl
julia> function say_if_positive(n)
           if n > 0
               println("n is positive!")
           else
               println("n is not positive!")
           end
       end
say_if_positive (generic function with 1 method)

julia> say_if_positive(10)
n is positive!

julia> say_if_positive(-10)
n is not positive!
```

Si l'expression booléenne qui suit le `if` s'évalue à `true`, le premier bloc de code est exécuté et le second est ignoré.
Si l'expression booléenne qui suit le `if` s'évalue à `false`, le premier bloc de code est ignoré et le second est exécuté.
Le programme se poursuit à la première ligne de code qui suit le mot-clé `end`.

~~~~exercism/note
En Julia, le mot-clé `end` marque la fin de toutes les expressions de bloc.
Cette syntaxe n'est pas propre aux expressions `if` ni aux définitions de fonction.
~~~~

Dans les cas où le second bloc de code serait simplement une autre expression `if`, `elseif` permet d'éviter d'imbriquer des expressions `if` à l'intérieur du bloc :

```julia-repl
julia> function dessert(fruit)
           if fruit == "apple"
               return "Apple Crumble"
           elseif fruit == "lemon"
               return "Lemon Meringue Pie"
           else
               return "Fruit Salad"
           end
       end
dessert (generic function with 1 method)

julia> dessert("apple")
"Apple Crumble"

julia> dessert("lemon")
"Lemon Meringue Pie"

julia> dessert("peach")
"Fruit Salad"
```

Si une expression `if` n'a besoin d'exécuter du code que pour l'un des cas, nul besoin d'écrire la branche `else`.

## L'opérateur ternaire

Les instructions `if`/`if-else` simples peuvent aussi s'écrire avec l'opérateur ternaire `a ? b : c`.
Si `a` est vrai, alors `b` est évalué.
Sinon, on évalue `c`.

Par exemple, la fonction suivante

```julia-repl
julia> function diagnose(heartrate)
           if heartrate > 100
               println("Elevated heart rate.")
           else
               println("Nominal heart rate or dead.")
           end
       end
diagnose (generic function with 1 method)
```

peut aussi s'écrire ainsi :

```julia-repl
julia> diagnose(heartrate) = heartrate > 100 ? println("Elevated heart rate.") : println("Nominal heart rate or dead.")
diagnose (generic function with 1 method)
```

C'est particulièrement utile lorsqu'on veut affecter une valeur différente à une variable selon une condition.
`x = a ? b : c` affecte `b` à `x` si `a` est `true`, et `c` sinon.
Par exemple :

```julia-repl
julia> function patient_status(heartrate)
           status = heartrate > 0 ? "alive" : "dead"

           println("The patient is ", status)
       end

julia> patient_status(100)
The patient is alive

julia> patient_status(0)
The patient is dead
```

## L'évaluation par court-circuit

Si plusieurs expressions booléennes sont chaînées avec les opérateurs `&&` et `||`, Julia n'évalue que le minimum d'expressions nécessaires pour déterminer la valeur de toute la chaîne.

Prenons par exemple la chaîne d'expressions `n > 0 && k > 10`.
Si `n` vaut `5`, la première partie de la chaîne, `n > 0`, est `true`, et il faut évaluer la seconde expression `k > 10` pour déterminer si l'expression entière est `true`.
En revanche, si `n` vaut `-5`, on sait que la chaîne dans son ensemble **ne peut pas** être `true`, car sa première expression est `false`.

Si on considère plutôt `n > 0 || k > 10`, c'est l'inverse qui se produit.
Si `n` vaut `5`, la première partie de la chaîne, `n > 0`, est `true`, et on sait que toute la chaîne sera `true` quelle que soit la seconde expression.
En revanche, si `n` vaut `-5`, il faut évaluer la seconde expression.

On peut tirer parti de ce comportement pour écrire des instructions `x` très courtes :

```julia
if a
    b
end
```

équivaut à

```julia
a && b
```

La dernière expression d'une chaîne de `&&` et `||` n'a pas besoin d'être une expression booléenne.
On rencontre souvent cette fonctionnalité pour les erreurs ou les retours anticipés.
Par exemple, avec la fonction `dessert(fruit)` vue plus haut :

```julia-repl
julia> function whats_for_dessert(fruit, allergic_to)
           fruit == allergic_to && return "I can't eat that, guess I'll not have dessert tonight!"

           return dessert(fruit)
       end
whats_for_dinner (generic function with 1 method)

julia> whats_for_dinner("apple", "peach")
"Apple Crumble"

julia> whats_for_dinner("apple", "apple")
"I can't eat that, guess I'll not have dessert tonight!"
```
