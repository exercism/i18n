# Les fonctions en `jq`

Tu peux définir tes propres **fonctions personnalisées** en `jq` pour encapsuler la logique dont tu as besoin.
Les _fonctions_ se comportent exactement comme les fonctions natives : elles prennent une entrée et produisent zéro, une ou plusieurs sorties.

## Définir une fonction

Tu peux définir une _fonction_ `jq` avec la syntaxe suivante :

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- commence par le mot-clé `def`,
- un deux-points avant le corps de la fonction,
- le corps est constitué d'une seule expression,
- se termine par un point-virgule,
- comme pour le reste de la syntaxe `jq`, tu peux utiliser autant d'espaces que tu veux pour la lisibilité.

## Où placer les fonctions

Les _fonctions_ doivent être définies avant d'être utilisées : ceci provoque une erreur :

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Cela implique que tu dois placer les _fonctions_ en haut de ton code `jq`, avant l'expression « principale ».

### Fonctions imbriquées

Les _fonctions_ peuvent être imbriquées :

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Ici, la _fonction_ `B` n'est visible que dans le corps de `A`.

## Portée

Une _fonction_ introduit une nouvelle **portée** pour les variables et les fonctions imbriquées.

## Arguments

Les **arguments** d'une _fonction_ sont séparés par des _points-virgules_, et non par des virgules.
Par exemple, une _fonction_ qui prend un nombre, puis lui ajoute un nombre et multiplie le résultat par un nombre :

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
Les points-virgules sont nécessaires parce que la virgule a déjà une utilité en `jq` : c'est un opérateur qui assemble des flux.

Utiliser une virgule à la place d'un point-virgule va tenter de faire deux appels à une _fonction_ `add_mul` à _1 argument_, qui n'existe pas, et l'appel échouera donc dès la première tentative :

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

La virgule dans `5, 4` concatène les nombres 5 et 4 en un flux. 
Quand on appelle une fonction avec un flux comme argument, `jq` appelle cette fonction plusieurs fois, une fois pour chaque valeur du flux. 
C'est un exemple de l'« itération implicite » propre aux flux `jq`.
`10 | add_mul(5, 4)` est équivalent à ce qui suit.

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
On voit maintenant comment l'erreur `add_mul/1 is not defined` apparaît.
~~~~

<!-- prettier-ignore-end -->

### Les arguments sont des _expressions_

Les _arguments_ d'une fonction sont des filtres, pas des valeurs.
En ce sens, ils se comportent comme ce que d'autres langages appellent des _callbacks_ :

En prenant la fonction `add_mul` comme exemple :

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

Que se passe-t-il ici ?

- l'argument `adder` reçoit l'_expression_ `. + 5`
  - quand la fonction fait `. + adder`, cela devient `. + . + 5`
  - ce qui vaut 25 puisque `. == 10`
- de même, l'argument `multiplier` est l'expression `. - 2`
  - ce qui vaut 8
  - le résultat est donc `25 * 8 == 200`

### Les arguments en tant que valeurs

Parfois, tu voudras « matérialiser » un _argument_ dans une variable :

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Il existe une notation raccourcie pour cela :

```jq
def my_func($arg):
    other stuff ...
;
```

Note bien qu'il s'agit juste de « sucre syntaxique » : le nom `arg` sans `$` reste dans la portée de la _fonction_.

<!-- prettier-ignore -->
~~~~exercism/caution
Par exemple, j'ai écrit quelque chose comme ceci pour résoudre un exercice :

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

et j'ai été surpris que chaque valeur du tableau soit égale à la clé.

C'est arrivé parce que `jq` voyait la fonction `equals` comme

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

L'**argument** `code` _écrasait_ la **fonction** `code` définie précédemment.
Cela signifiait que `(. | code)` se contentait de produire l'**argument** au lieu de calculer un nouveau code à partir de la valeur d'entrée.
Ainsi, `$this_code` et `$code` étaient toujours identiques.
~~~~

## Arité

Une _fonction_ a une **arité**, c'est-à-dire le nombre d'_arguments_ qu'elle prend.

Plusieurs _fonctions_ peuvent porter le même nom avec des _arités_ différentes.
La fonction native [`range`][man-range] en est un exemple : `range/1`, `range/2` et `range/3` coexistent.

Cela peut être utile pour définir des fonctions récursives qui transportent un état via leurs arguments.
Par exemple, `map` _pourrait_ être implémenté comme ceci :

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Récursion

`jq` effectue une optimisation d'appel terminal, mais uniquement pour les fonctions à arité 0.

## Modules

Un module `jq` est un fichier qui ne contient que des fonctions.
Les modules sont inclus dans un programme jq avec les commandes [`include`][man-include] ou [`import`][man-import].
