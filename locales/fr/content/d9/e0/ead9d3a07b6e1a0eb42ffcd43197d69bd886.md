# À propos

Il est peu probable que tu tombes sur beaucoup de code de production qui n'utilise pas les espaces de noms.

Voici un exemple de syntaxe :

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

Les espaces de noms permettent de regrouper du code lié et d'éviter les collisions de noms.

D'après la [documentation officielle][namespaces], les espaces de noms ont deux rôles principaux :

- Premièrement, .NET utilise les espaces de noms pour organiser ses nombreuses classes
- Deuxièmement, déclarer tes propres espaces de noms peut t'aider à contrôler la portée des noms de classes et de méthodes dans de plus gros projets.

La bibliothèque de classes de base (BCL) s'appuie largement sur les espaces de noms pour organiser ses fonctionnalités.

## Références aux types d'un espace de noms

Pour référencer depuis l'extérieur un type contenu dans un espace de noms, on préfixe le nom du type avec la syntaxe à point. Autrement, et c'est plus courant, tu peux placer une directive `using` en haut du fichier (ou dans un espace de noms) : les types de l'espace de noms importé peuvent alors être utilisés sans préfixe. Au sein d'un même espace de noms, il n'est pas nécessaire de qualifier les noms de types.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

Cet [article][using] explique clairement les différentes façons d'utiliser la directive `using` :

- `using` : éviter de devoir qualifier les types avec leur espace de noms
- `using static` : éviter de devoir qualifier les membres avec leur type (un bon exemple est `Math.Max()`).
- `using MyAlias = YourNamespace;` : remplacer le nom de l'espace de noms par un nom plus lisible.

## Conflits entre espaces de noms

.NET résout le problème de deux espaces de noms portant le même nom dans des _assemblys_ différents, où les noms d'identificateurs pleinement qualifiés entreraient en collision (par exemple quand plusieurs versions d'un _assembly_ sont chargées). Ce problème se règle avec le [qualificateur d'alias d'espace de noms][namespace-alias-qualifier] et l'[alias extern][extern-alias].

Si l'on aborde ce sujet assez pointu, c'est notamment à cause de son utilisation de l'[opérateur `::`][dot-dot-operator]. Tu verras souvent le qualificateur `global::` préfixer des espaces de noms, en particulier dans du code généré. L'objectif est ici d'éviter une éventuelle collision avec un espace de noms imbriqué ou un nom de classe. En préfixant un espace de noms avec `global::`, on s'assure que c'est un espace de noms de premier niveau qui est sélectionné.

## Note pour les développeurs Java

Si on compare avec l'`import` des `packages` Java, quelques différences et ressemblances méritent d'être notées :

- Il n'existe pas d'équivalent en C# pour importer des types précis.
- `using static` et `import static` sont équivalents.
- En Java, les noms de packages ont un impact sur l'accessibilité entre les jars. En C#, ce sont les _assemblys_ qui comptent, et le fait d'appartenir au même espace de noms n'affecte pas le niveau d'accès.
- La relation entre les chemins du système de fichiers et les noms de classes pleinement qualifiés en Java ne se retrouve pas dans les espaces de noms C#, même s'il est de bonne pratique, quand c'est possible, de donner à un fichier le même nom que la classe principale qu'il contient.
