# Introduction aux types génériques

Un **type générique** est une classe ou une interface générique paramétrée par des types.
Cela permet au compilateur de garantir la sécurité de type sur la classe ou l'interface.

Prenons cette interface `Container` non générique :

```java
class Container {
    private Object object;

    public void set(Object object) { this.object = object; }
    public Object get() { return object; }
}
```

Comme elle accepte et renvoie des `Object`, elle fonctionne avec n'importe quel type non primitif.
Cependant, cela a un prix, car du code peut appeler `get` en s'attendant à des `Integer` pendant qu'un autre code appelle `set` en ajoutant des `String`, ce qui provoque une exception à l'exécution.

Une **classe générique** et une **interface générique** ont la forme suivante :

```java
class ClassName<T1, T2, ..., Tn> { ... }
interface InterfaceName<T1, T2, ..., Tn> { ... }
```

La section des paramètres de type, délimitée par des chevrons (`<>`) et placée après le nom de la classe ou de l'interface, spécifie les paramètres de type (aussi appelés variables de type) `T1`, `T2`, ..., et `Tn`.
On peut les utiliser dans le corps de la classe ou de l'interface pour obtenir une sécurité de type générique.

Voici la version générique de `Container` :

```java
class Container<E> {
    private E object;

    public void set(E object) { this.object = object; }
    public E get() { return object; }
}
```

Lorsqu'on la crée, il faut désormais déclarer le type qu'elle contient, et le compilateur fera respecter cette contrainte :

```java
// empty <> can infer from context
Container<String> stringContainer = new Container<>();
// compiler knows this is a String, so it is allowed
stringContainer.set("Some string");
// no cast needed, compiler knows it is a String
String result = stringContainer.get();
// this causes a compiler error:
stringContainer.set(42);
```
