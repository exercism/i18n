# Introduction aux conditions

## La notion de vérité en Bash

Bash n'a pas la notion de valeurs booléennes.
Il y a des _strings_ et des nombres, ainsi que des tableaux de _strings_ ou de nombres.
Alors, comment les commandes conditionnelles gèrent-elles le vrai et le faux ?

## Statut de sortie

Les commandes produisent un _statut de sortie_ lorsqu'elles se terminent.
Un statut de sortie est un entier compris entre 0 et 255 inclus.
Bash considère qu'un statut de sortie **zéro** représente un _succès_.
Tout autre statut de sortie représente un _échec_.

Cela s'applique à toutes les commandes, y compris les commandes intégrées de Bash, les mots-clés et les fonctions.

## La commande « if »

La syntaxe de base de la commande `if` est

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

Elle commence par `if` ; les commandes de condition sont séparées des commandes de « succès » par `then` ; et elle se termine par `fi`.
La clause `else` est facultative.

CONDITIONAL_COMMANDS peut être une seule commande ou une [liste de commandes][command-list].

Les CONDITIONAL_COMMANDS sont exécutées, et

* si le statut de sortie est zéro (succès), alors les TRUE_COMMANDS sont exécutées.
* si le statut de sortie est non nul (échec), alors les FALSE_COMMANDS sont exécutées, si elles sont présentes.

On peut écrire des branches en cascade avec `elif`
```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

Il doit y avoir un point-virgule ou un retour à la ligne avant les mots `then`, `elif`, `else` et `fi`.

Pour insister : c'est le **statut de sortie** des commandes conditionnelles qui contrôle le flux.
Par exemple, `grep` renvoie 0 si une correspondance est trouvée, et 1 si aucune correspondance n'est trouvée.
L'option `-q` supprime la sortie, en ne produisant que le statut de sortie.

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## Les commandes « [ » et « test »

Il n'y a pas de syntaxe spéciale autour des CONDITIONAL_COMMANDS.
Tu as peut-être l'habitude de voir des instructions `if` qui ressemblent à ceci :

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

`[` n'est pas une syntaxe spéciale.
C'est une _commande_ qui évalue l'expression conditionnelle et se termine avec un statut de succès ou d'échec.
Comme toutes les commandes, un espace est **obligatoire** entre elle et ses arguments.

`[` est en fait un synonyme de la commande `test`.
Ils sont exactement identiques, sauf que le dernier argument de `[` _doit_ être `]`.

### Expressions conditionnelles

Entre `[` et `]`, on écrit une expression conditionnelle.
Voici quelques expressions conditionnelles typiques :

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

Il existe de nombreuses autres opérations disponibles ; elles sont listées dans la section [Expressions conditionnelles de Bash][cond-expr] du manuel.

~~~~exercism/note
Dans les exemples ci-dessus, remarque que toutes les variables sont entre guillemets.
Les commandes `test` et `[` sont des commandes ordinaires, dont les arguments sont soumis au découpage de mots et à l'expansion des noms de fichiers comme toute autre commande.

Il est important de le signaler car les expressions conditionnelles sont évaluées différemment selon le _nombre d'arguments_ que tu fournis :

* 0 argument : le statut de sortie est non nul (échec)
* 1 argument : le statut de sortie est zéro (succès) si l'argument n'est pas vide, non nul s'il est vide.
* 2 arguments : le premier argument doit être un opérateur unaire (comme `[ -z "$name" ]`), ou un `!` (qui inverse le statut du test à 1 argument)
* et [plus d'informations][test].

Tu peux obtenir des résultats inattendus si tu oublies de mettre entre guillemets :

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## Le mot-clé « [[ »

La [construction conditionnelle `[[...]]`][cond-construct] n'est pas une _commande_, c'est un **mot-clé**.
Cela signifie que, bien qu'il soit traité comme toute autre commande, il a des règles d'analyse syntaxique spéciales.
Ce qui est spécial avec `[[`, c'est que les variables qui y sont développées ne sont **pas** soumises au découpage de mots ni à l'expansion des noms de fichiers.
Cela signifie que cette commande se comporte comme tu l'attends, même sans guillemets.

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

`[[` prend en charge toutes les expressions conditionnelles que `test` et `[` peuvent gérer.
De plus, `[[` fournit

* l'opérateur de correspondance d'expression régulière `=~`,
* `==` et `!=` fonctionnent comme un opérateur de correspondance de motif glob,
* `&&` et `||` comme opérateurs logiques (règle d'analyse syntaxique spéciale),
* `<` et `>` comme opérateurs de comparaison de _strings_ « nus » (règle d'analyse syntaxique spéciale : comme ce sont des symboles de redirection, dans `[` ils doivent être échappés).

On considère généralement que ces fonctionnalités spéciales offrent tant d'avantages que `[[` devrait être utilisé exclusivement.
(Par exemple, le [Google Shell Style Guide][goog-test].)

## La commande « case »

[`case`][case] est une autre commande de contrôle de flux.
Elle est similaire à une instruction _switch_ dans d'autres langages.

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

Le WORD est comparé à chaque PATTERN.
Quand l'un correspond, les COMMANDS sont exécutées.

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

Chaque clause COMMANDS doit se terminer par **deux** points-virgules, `;;`.
