# Introduction aux commandes et aux arguments

Ce parcours ne porte pas sur l'utilisation de bash comme shell interactif.
Il s'agit d'apprendre à écrire des programmes en bash, le langage de programmation.

Un programme bash, ou _script_, est une suite de commandes stockées dans un fichier.
bash (l'exécutable) lit le fichier et exécute les commandes dans l'ordre.

## Le shebang

La première ligne d'un script est généralement une _directive d'interprète_, aussi appelée _hashbang_ ou _shebang_ :

```bash
#!/usr/bin/env bash
```

Quand le système d'exploitation exécute un fichier non binaire, il lit la première ligne.
Si la ligne commence par `#!`, le noyau s'en sert pour déterminer quel interprète doit exécuter le fichier.
Le `#!` doit se trouver tout au début du fichier, sans espace ni ligne vide avant.

Ici, `env` recherche dans `PATH` l'exécutable `bash`.
Tu peux aussi rencontrer la forme plus simple `#!/bin/bash`, qui fige l'emplacement de l'interprète ; la forme avec `env` est plus portable.

~~~~exercism/note
Ne te laisse pas tromper par les scripts ou les exemples trouvés sur Internet qui utilisent `/bin/sh` comme interprète.
**`sh` n'est pas `bash` !**
Bash est « compatible sh » et peut exécuter la plupart des scripts `sh`, mais certaines fonctionnalités de bash échoueront ou se comporteront de façon inattendue dans `sh`.
~~~~

## Les commentaires

Une ligne qui commence par `#` est un _commentaire_, et bash l'ignore.
Un commentaire peut aussi suivre une commande sur la même ligne : tout ce qui va du `#` à la fin de la ligne est ignoré.
Les commentaires servent aux humains qui lisent le script.

## Les mots et les arguments

Bash lit les commandes depuis son entrée (qui est généralement soit un terminal, soit un fichier).
Chaque ligne d'entrée qu'il lit est traitée comme une _commande_, c'est-à-dire une instruction à exécuter.
(Il existe quelques cas avancés, comme les commandes qui s'étendent sur plusieurs lignes, dont on parlera plus tard.)

Bash divise chaque commande en **mots** délimités par des caractères d'espacement (espaces et tabulations).
Le premier mot est le nom de la _commande_ à exécuter.
Tous les mots restants deviennent des _arguments_ de cette commande (options, noms de fichiers, etc.).

Une commande peut être une commande _interne_ de bash, comme `echo`, ou un programme _exécutable_, comme `head`, `awk` ou `sed`.

## La commande `echo`

`echo` affiche ses arguments, séparés par un seul espace, et termine par un retour à la ligne :

```bash
echo flour sugar eggs
```

affiche :

```text
flour sugar eggs
```

Le nombre d'espaces entre les arguments n'a aucune importance :

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

Appeler `echo` sans aucun argument affiche une ligne vide.

## Les options ne sont que des arguments

Beaucoup de commandes acceptent des _options_ qui modifient leur comportement.
Pour bash, une option n'a rien de particulier : c'est un mot comme un autre, séparé de ses voisins par un espace.
C'est la commande elle-même qui décide comment interpréter ses arguments.
Par convention, les options commencent par un `-`.

La commande `head` affiche les premières lignes d'un fichier.
Avec un fichier `list.txt` :

```bash
head -n 2 list.txt
```

Bash découpe cette ligne en quatre mots :

| Mot        | Rôle                                                    |
| ---------- | ------------------------------------------------------- |
| `head`     | la commande à exécuter                                  |
| `-n`       | une option qui demande à `head` de compter des _lignes_ |
| `2`        | la valeur de l'option `-n`                              |
| `list.txt` | le fichier à lire                                       |

Bash transmet les trois derniers mots à `head` sans y toucher.
C'est `head` qui comprend que `-n` est suivi d'un nombre et que le mot restant est un fichier.

Comme c'est l'espace qui sépare les mots, l'endroit où on le met a son importance.
`head -n 2` donne deux arguments à `head` (`-n` et `2`), tandis que `head -n2` ne lui en donne qu'un (`-n2`).
Beaucoup de commandes acceptent les deux formes, mais cela dépend de la commande.
Bash ne s'en soucie pas ; il se contente de découper la ligne en mots.

## Mets les arguments entre guillemets

Les [guillemets][Quotes] regroupent les mots en un _seul argument_.
Les espaces à l'intérieur des guillemets sont conservés, et les guillemets eux-mêmes ne font pas partie de l'argument :

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

Si un argument comme un nom de fichier contient des espaces, il faut le mettre entre guillemets :

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## Lance un script

Pour lancer un script, passe-le comme argument à la commande `bash` :

```bash
bash myscript
```

Utilisée ainsi, la ligne `#!` n'est qu'un commentaire.
Tu indiques au système d'exploitation comment lancer le fichier.

Autrement, tu peux marquer le fichier de script comme exécutable et le lancer comme n'importe quel autre programme :

```bash
chmod +x myscript
./myscript
```

Désormais, le système d'exploitation utilise la ligne `#!` pour déterminer quel interprète employer.
