# Contribue à un concept et à un exercice d'apprentissage

Un [exercice d'apprentissage][product-concept] vise à enseigner un seul concept dans un langage donné.
Il doit avoir un objectif d'apprentissage clair et fournir suffisamment de code de base pour éviter à l'apprenant d'avoir à apprendre du code inutile.
Le concept associé possède sa propre documentation, indépendante de l'exercice d'apprentissage.
Un concept peut avoir d'autres concepts comme prérequis et rester verrouillé jusqu'à ce que les exercices d'apprentissage des concepts prérequis soient terminés.
La difficulté des exercices d'apprentissage ne doit pas augmenter au fur et à mesure que l'on progresse dans le parcours.
Un exercice d'apprentissage doit pouvoir être résolu en 5 à 10 minutes par n'importe quel développeur qui connaît les concepts prérequis.

Maintenant que l'on sait ce qu'est un exercice d'apprentissage, voyons en détail comment en implémenter un, ainsi que le concept qui lui est associé.
Pour référence, la [spécification détaillée d'un exercice d'apprentissage][concept-exercise-spec] et celle d'un [concept][concept-spec] sont disponibles dans le [dépôt de documentation][docs-repo] d'Exercism.
Ce document rassemble des informations issues de nombreuses ressources pour servir de guide pratique, étape par étape, sur la façon de contribuer à un exercice d'apprentissage.

## 2. Définis les objectifs d'apprentissage

Il est important de savoir ce qu'un exercice d'apprentissage vise à enseigner et ce qui est hors périmètre, alors créons notre premier fichier : `exercises/concept/<story-name>/.meta/design.md`.
Comme les exercices d'apprentissage portent le nom de l'histoire qu'ils utilisent et que nous ne la connaissons pas encore, nous garderons `story-name` pour l'instant et le remplacerons plus tard.
La [spécification de `design.md`][design-spec] indique que ce document doit définir l'objectif global de l'exercice, ses différents objectifs d'apprentissage, les éléments hors périmètre, le concept associé qu'il déverrouille et les concepts prérequis pour pouvoir terminer l'exercice.
Tu peux utiliser le [`design.md` de l'exercice d'apprentissage sur les booléens][design-bool] comme point de départ, en guise de modèle.

## 3. Rédige une introduction au concept pour l'exercice

Une fois les objectifs d'apprentissage clairs, il est temps de rédiger une introduction qui explique suffisamment le concept pour que l'apprenant puisse ensuite résoudre l'exercice.
Crée un fichier `exercises/concept/<story-name>/.docs/introduction.md`.
Le contenu détaillé de ce fichier est expliqué dans [sa spécification][exercise-intro-spec].
Tu peux t'inspirer du [`introduction.md` de l'exercice d'apprentissage sur les booléens][intro-bool] comme point de départ.

Les informations fournies doivent présenter le concept juste assez pour que l'apprenant trouve lui-même la solution de l'exercice.
Utilise des termes techniques précis pour faciliter les recherches en ligne de l'apprenant.
Essaie d'éviter les liens et d'expliquer les choses de façon concise directement dans le texte.
Présente la syntaxe du code à l'aide de blocs de code.

## 4. Trouve une histoire pour l'exercice

Chaque exercice d'apprentissage doit être basé sur une histoire ou un thème.
Nous essayons de les rendre aussi inclusifs que possible, sachant qu'Exercism est utilisé dans le monde entier.
La première option consiste à réutiliser une histoire existante parmi la [liste des histoires recensées dans la documentation][stories].
Si tu veux créer une nouvelle histoire, n'hésite pas à mentionner @exercism/leadership dans ta PR.
Tu peux maintenant renommer le répertoire `exercises/concept/<story-name>/` pour qu'il corresponde à ton histoire.

## 5. Rédige les instructions de l'exercice

Une fois l'histoire trouvée, il faut rédiger des instructions précises énumérant les tâches que l'apprenant devra accomplir.
L'histoire et les instructions sont toutes deux écrites dans le document `exercises/concept/<story-name>/.docs/instructions.md`.
Comme expliqué dans [la spécification de ce document][instructions-spec], chaque tâche a son propre titre Markdown de niveau 2 (`## 1. Do X`) suivi d'une description et d'un exemple d'utilisation du code.
Tu peux utiliser le [`instructions.md` de l'exercice d'apprentissage sur les booléens][instructions-bool] comme point de départ.

En plus de `instructions.md`, nous avons aussi besoin d'un fichier `hints.md`.
Il doit contenir les mêmes titres de niveau 2 (`## 1. Do X`) que le fichier d'instructions, afin que les bons indices soient donnés selon la tâche en cours.
Il peut aussi y avoir une section `## General` pour les indices qui s'appliquent à toutes les tâches.
Les indices ne doivent pas donner la solution directement.
De plus, garde à l'esprit que les personnes qui cliquent sur les indices sont peut-être déjà perdues, submergées ou frustrées par l'exercice.
Plus d'informations sur ce document sont disponibles dans [sa spécification][hints-spec], et tu peux utiliser le [`hints.md` de l'exercice d'apprentissage sur les booléens][hints-bool] comme point de départ.

## 6. Ouvre une pull request en brouillon pour valider la conception

C'est le bon moment pour ouvrir une pull request en brouillon pour ton exercice d'apprentissage !
Nous avons assez de matière pour évaluer l'exercice et le remanier si nécessaire avant de nous engager sur son état actuel pour le reste des fichiers requis.
Ne t'inquiète pas si les vérifications automatiques de la CI échouent à cause de documents manquants, nous les créerons plus tard !

## 7. Écris le code

Nous allons écrire le code comme si nous résolvions l'exercice, puis nous déplacerons les fichiers pour respecter les spécifications.
Commençons par copier le contenu du répertoire [`template/`][template] dans notre répertoire `exercises/concept/<story-name>/`.
Cela nous donne les fichiers suivants :

```txt
elm.json           # elm project configuration file
src/Exercise.elm   # code for the exercise
tests/Tests.elm    # tests for the exercise
```

Renomme ensuite `Exercise.elm` en utilisant le PascalCase du nom de l'histoire.
Par exemple, `annalyns-infiltration` devient `AnnalynsInfiltration.elm`.
Dans ce fichier source, tu peux maintenant écrire toutes les fonctions décrites dans le `instructions.md` que nous venons d'écrire.

Une fois l'exercice implémenté, mets à jour le contenu du fichier `tests/Tests.elm` pour y inclure des tests pertinents qui suivent naturellement l'ordre des tâches de `instructions.md`.
**Évite d'utiliser `Fuzz`** dans les tests des exercices d'apprentissage, car cela ne s'accorde pas bien avec la possibilité de déboguer le code avec `Debug.log`.
Inclus plutôt quelques tests unitaires pour les cas limites et les cas généraux.
**Évite d'utiliser des expressions `let` directement sous les appels de fonction `test` ou `describe`** dans les tests des exercices d'apprentissage, car [l'exécuteur de tests Elm ne prend pas encore cela en charge](https://github.com/exercism/elm-test-runner/issues/30).

Une fois l'exercice et les tests terminés et fonctionnels, fais ce qui suit :

- Copie `src/<ExerciseSlug>.elm` vers `.meta/Exemplar.elm`. Ton implémentation sert de référence, une implémentation « exemplaire » de l'exercice, utilisée lors de l'exécution des tests du parcours.
- Supprime toutes les implémentations à l'intérieur de `src/<ExerciseSlug>.elm` pour ne laisser qu'un fichier de départ prêt à ce que l'apprenant commence l'exercice.

## 8. Rédige la documentation du concept

Crée un répertoire `concepts/<concept>/` pour le concept associé à notre exercice `exercises/concept/<story-name>`.
Dans ce nouveau dossier, nous créons deux documents Markdown, [`introduction.md`][concept-intro-spec] et [`about.md`][concept-about-spec], ainsi qu'un fichier [`links.json`][concept-links-spec] (les liens mènent à leur spécification).

Le fichier `introduction.md` du concept contient la présentation que les apprenants verront sur la page du concept tant qu'ils n'ont pas terminé l'exercice d'apprentissage associé.
Il doit leur donner un bon aperçu de ce qu'ils apprendront s'ils commencent l'exercice associé.
En revanche, le fichier `about.md` du concept contient le résumé du concept que l'apprenant ne verra sur la page du concept qu'après avoir terminé l'exercice d'apprentissage associé.
À ce titre, leur contenu est similaire à celui du fichier `exercises/concept/<story-name>/.docs/introduction.md` que nous avons déjà écrit, mais il n'est pas identique.
Je te suggère de partir du document d'introduction de l'exercice et de le simplifier jusqu'à l'essentiel pour le fichier `introduction.md` du concept.
Et pour le document `about.md`, pars de l'introduction de l'exercice et complète-la afin que toutes les informations pertinentes concernant le concept soient présentes sur cette page.
`links.json` fournit des liens utiles vers des informations complémentaires sur un concept.
Il peut s'agir de la documentation officielle, d'un bon tutoriel, etc.
Ces liens ne remplacent pas les liens plus contextuels présents dans le fichier about.md d'un concept, mais offrent à l'apprenant un ensemble de références générales rapidement accessibles.
Les liens peuvent aussi comporter un champ facultatif icon_url, qui permet de personnaliser l'icône affichée lorsque le lien est présenté. S'il n'est pas précisé, l'icône est par défaut le favicon.
Tu trouveras les icônes disponibles sur [github.com/exercism/website-icons/tree/main/exercises][icons].

## 9. Complète les différents fichiers de configuration

Maintenant que le code et la documentation sont terminés, il ne reste plus que quelques fichiers de configuration pour que cette PR soit complète :

- [`concepts/<concept>/.meta/config.json`][concept-config-json] : mets-toi comme auteur, inscris les relecteurs potentiels comme contributeurs et ajoute une « blurb » (courte description).
- [`exercises/concept/<story-name>/.meta/config.json`][exercise-config-json] : contient les auteurs (toi), les contributeurs, la « blurb » et d'autres éléments. Reporte-toi à la spécification liée.
- `config.json` : ajoute une [entrée de concept][track-config-json-concept] et une [entrée d'exercice d'apprentissage][track-config-json-concept-exercise] dans le fichier `config.json` du parcours. Utilise « wip » ou « beta » pour la clé status de l'exercice d'apprentissage. Les UUID peuvent être générés grâce à l'[exécutable configlet][configlet] fourni par Exercism.
