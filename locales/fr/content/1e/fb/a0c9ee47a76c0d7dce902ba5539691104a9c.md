# Introduction

## Notation binaire

Un **entier** est une abstraction qui représente des nombres entiers, comme `4`, `-2`, `0` ou `64532`.

Pour représenter un entier sous la forme d'une séquence d'octets, on utilise la **notation binaire**.
Dans cette notation, chaque bit de la séquence représente une puissance de deux distincte, la valeur augmentant à mesure que l'indice du bit augmente de la droite vers la gauche.

## Nombres non signés

Si le nombre ne peut être que positif ou nul, on parle d'un nombre **non signé**.

Les nombres non signés sont représentés directement comme la somme des puissances de deux correspondant à tous les bits à 1 de leur séquence.

La plage d'entiers positifs ou nuls représentables dans un registre va de `0` (aucun bit à 1) à `2⁶⁴ - 1` (somme des 64 bits à 1).

Pour élargir un nombre non signé à une taille supérieure, on remplit tous les bits de poids fort avec des `0`, afin qu'aucun nouveau bit ne contribue à la valeur.
C'est ce qu'on appelle l'**extension de zéros**.

L'instruction `movzx` (`z` pour zero) étend par des zéros un opérande source de 8 ou 16 bits vers un opérande destination plus grand.
Un opérande source de 32 bits est toujours étendu par des zéros sur les 64 bits de l'opérande destination avec un simple `mov`.

## Nombres signés

Si un entier peut prendre des valeurs positives ou négatives, on parle d'un nombre **signé**.

Pour représenter les nombres négatifs, x86-64 utilise la représentation en **complément à deux**.

En complément à deux, les nombres signés sont eux aussi représentés comme la somme des puissances de deux correspondant aux bits à 1.
Toutefois, si le bit de poids fort est à 1, il est soustrait au lieu d'être ajouté aux autres.

Comme ce bit correspond à une valeur supérieure à la somme de tous les autres, cela signifie en pratique qu'un nombre dont ce bit est à 1 est toujours négatif.
Ce bit particulier s'appelle le **bit de signe**.

Élargir un nombre signé à une taille supérieure consiste à remplir chaque nouveau bit de poids fort par une copie du bit de signe, afin de préserver la valeur.
C'est ce qu'on appelle l'**extension de signe**.

L'instruction `movsx` (`s` pour sign) étend le signe d'un opérande source de 8 ou 16 bits vers un opérande destination plus grand.
Une variante de `movsx` appelée `movsxd` fait de même depuis un opérande source de 32 bits vers un opérande destination de 64 bits.

L'instruction `neg` permet de changer le signe d'un nombre.

~~~~exercism/caution
En assembleur, il n'existe aucun moyen de savoir si une séquence d'octets représente un nombre signé ou non signé.
C'est au programmeur de donner un sens à ces octets.

L'usage de commentaires peut grandement aider dans cette tâche.
~~~~

## Valeurs immédiates

Dans un concept précédent, il a été mentionné qu'un nombre constant, comme `4` ou `-15`, peut être utilisé comme opérande source pour de nombreuses instructions.
Ces nombres sont appelés des **valeurs immédiates**.

Une valeur immédiate n'est stockée ni dans un registre ni en mémoire : elle est encodée directement dans l'instruction elle-même.
Dans la plupart des instructions, l'espace qui lui est réservé ne fait que 32 bits de large, quelle que soit la taille de l'opérande destination.

Lorsque l'opérande destination fait 64 bits de large, ces 32 bits sont _étendus en signe_ pour le remplir.
La moitié supérieure de l'opérande est entièrement remplie de copies du bit de poids fort de la valeur immédiate, si bien que seule une valeur comprise dans la plage d'un _entier signé de 32 bits_ peut être écrite de cette façon :

```x86asm
add rax, -1          ; the immediate is sign-extended, so all 64 bits of rax are affected
add rax, 2147483647  ; the largest immediate an instruction like this accepts
```

Un nombre en dehors de cette plage ne peut pas être utilisé comme valeur immédiate.
L'exception à cette règle est `mov`, qui peut prendre une valeur immédiate complète de 64 bits lorsque l'opérande destination est un registre.
Si une valeur immédiate de 64 bits est nécessaire, utilise d'abord `mov` pour la charger dans un registre, puis utilise ce registre :

```x86asm
mov rax, 3435973837           ; this works, mov can take a 64-bit immediate
mov rdx, 18446744073709551615 ; the largest immediate mov accepts
sub rdx, rax
```

Note qu'une valeur immédiate négative et le nombre non signé ayant la même représentation binaire sont équivalents et s'assemblent exactement vers la même valeur :

```x86asm
mov rax, -1                   ; rax = 18446744073709551615
mov rax, 18446744073709551615 ; rax = -1
```

## Addition

L'addition de deux nombres peut être calculée à l'aide de l'instruction `add`.

Il existe aussi une instruction `inc` à un opérande, qui ajoute `1` à la valeur de son opérande :

```x86asm
inc rax ; rax = rax + 1
```

La somme de deux entiers fonctionne de la même manière pour les nombres non signés que pour les nombres signés.

## Soustraction

La soustraction de deux entiers s'effectue à l'aide de l'instruction `sub`.

Il existe aussi une instruction `dec` à un opérande, qui soustrait `1` à la valeur de son opérande :

```x86asm
dec rax ; rax = rax - 1
```

La soustraction de deux entiers fonctionne elle aussi de la même manière pour les nombres non signés que pour les nombres signés.

## Multiplication

Il existe deux instructions différentes pour effectuer la multiplication entre deux nombres en x86-64.
En règle générale, la multiplication non signée utilise l'instruction `mul`, tandis que la multiplication signée utilise `imul`.

L'instruction `mul` prend la forme à un opérande suivante, où `src` est l'opérande source :

```x86asm
mul src
```

L'instruction `imul` peut prendre une forme à un, deux ou trois opérandes :

```x86asm
imul src
imul dest, src
imul dest, src1, src2
```

### Multiplication à un opérande

Deux registres sont utilisés implicitement pour effectuer une multiplication sous la forme à un opérande : `rax` et `rdx`.
Si la multiplication porte sur deux nombres de 64 bits, les 64 bits de poids faible du résultat se trouveront dans `rax` et les 64 bits de poids fort dans `rdx`.

On note généralement cela `rdx:rax`, pour indiquer que les deux registres sont utilisés conjointement :

```x86asm
mul rcx ; rax = lower 64 bits of rax * rcx
        ; rdx = upper 64 bits of rax * rcx
```

Il en va de même pour les autres tailles d'opérande.
Ainsi, par exemple, si l'on multiplie deux nombres de 32 bits, ce sont `eax` et `edx` qui sont utilisés.

L'exception est la multiplication entre deux octets.

Dans ce cas, au lieu de `dl:al`, c'est `ax` qui est utilisé.
La partie basse de `ax` (`al`) reçoit les 8 bits de poids faible du produit, tandis que la partie haute (`ah`) reçoit les 8 bits de poids fort.

~~~~exercism/caution
Les registres utilisés implicitement dans une multiplication, comme `rax` et `rdx`, sont toujours écrasés.
Si les valeurs de ces registres sont nécessaires par la suite, il faut les sauvegarder avant l'opération.
~~~~

### Multiplication à deux opérandes

La forme à deux opérandes de `imul` possède un opérande destination explicite et suit la syntaxe habituelle.
`rdx` n'est pas utilisé.
Le résultat est plutôt tronqué pour tenir dans l'opérande destination.

```x86asm
imul r8, r9 ; r8 = lower 64 bits of r8 * r9
```

### Multiplication à trois opérandes

La forme à trois opérandes de `imul` possède deux opérandes source, dont le second est toujours une valeur immédiate (un nombre constant).
Les deux opérandes source sont multipliés, puis le résultat est tronqué et placé dans l'opérande destination :

```x86asm
imul r8, r9, 100 ; r8 = lower 64 bits of r9 * 100
```

Note que l'opérande destination n'est pas utilisé dans la multiplication.
Il ne fait que recevoir le résultat.

### Gérer le dépassement de capacité

Les multiplications à deux et à trois opérandes tronquent toutes deux le résultat pour le faire tenir dans la taille de l'opérande destination.
La multiplication à un opérande préserve toute la plage, mais le résultat est généralement réparti sur deux registres, `rdx` et `rax`.

Il est donc parfois utile d'élargir les opérandes avant la multiplication afin de faire tenir tout le produit dans un seul registre.
Un opérande non signé est étendu par des zéros, tandis qu'un opérande signé est étendu en signe :

```x86asm
movzx eax, di ; di and si hold unsigned 16-bit numbers
movzx ecx, si
mul ecx       ; the 32-bit product fits in eax, and edx is cleared
```

## Division

Comme pour la multiplication, il existe également deux instructions pour effectuer la division entre deux nombres.
La division non signée utilise l'instruction `div`, tandis que la division signée utilise `idiv`.

Les deux instructions ne fonctionnent qu'avec un seul opérande :

```x86asm
div src
idiv src
```

La division sur 16 bits, 32 bits et 64 bits utilise respectivement `dx:ax`, `edx:eax` et `rdx:rax` comme dividende.
Dans ces cas, les deux registres agissent conjointement pour former une valeur de 2N bits, où N est la taille de l'opération (16, 32 ou 64 bits).
Cette valeur est ensuite divisée par l'opérande source.
Le quotient est écrit dans `ax`, `eax` ou `rax` et le reste est écrit dans `dx`, `edx` ou `rdx`, selon la taille de l'opération.

La division entre octets est particulière : au lieu d'utiliser `dl:al`, c'est `ax` qui est utilisé.
Les 8 bits de poids faible de `ax` (`al`) reçoivent le quotient de l'opération et les 8 bits de poids fort (`ah`) reçoivent le reste.

Note que tous les bits du dividende doivent être correctement définis avant la division.
Tout bit à 1 dans `rdx` (ou dans `ah` pour une division sur 8 bits) contribue à la valeur qui est divisée.

En division non signée, lorsque la valeur à diviser tient dans la moitié basse, il faut mettre à zéro la moitié haute.
N'importe quelle instruction qui met ces bits à zéro fera l'affaire.
Par exemple, `mov edx, 0` met à zéro les bits de poids fort dans une division sur 32 bits.

En division signée, il faut au contraire étendre la valeur en signe.
Certaines instructions automatisent ce processus : `cbw`, `cwd`, `cdq` et `cqo`.
La première définit les bits de `ah` en fonction du signe de `al`.
Les autres effectuent l'extension de signe respectivement de `ax` vers `dx`, de `eax` vers `edx` et de `rax` vers `rdx`.

~~~~exercism/caution
Les registres utilisés implicitement dans une division, comme `rax` et `rdx`, sont toujours écrasés.
Si les valeurs de ces registres sont nécessaires par la suite, il faut les sauvegarder avant la division.
~~~~
