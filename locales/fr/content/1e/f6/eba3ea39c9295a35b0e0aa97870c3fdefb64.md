# Introduction

Jusqu'ici, le programme n'a pas beaucoup parlé des types, mais ils existent de toute évidence en Julia :

```julia-repl
julia> vals = (42, 4.3, π, "hello", 'Q')
(42, 4.3, π, "hello", 'Q')

julia> typeof(vals)
Tuple{Int64, Float64, Irrational{:π}, String, Char}
```

On n'a jamais précisé les types, mais Julia les a attribués quand même.

1. Julia possède des `types`, qui sont au cœur de sa conception.
2. Julia peut généralement « deviner » le type, grâce à `Type Inference`.

Le compilateur JIT parcourt (tout) le code, voit comment une variable est utilisée, et _infère_ un type par défaut approprié, compatible avec cet usage.

## Promotion de type

Les concepts précédents ont donné de nombreux exemples où des types numériques sont forcés à s'uniformiser, en commençant par l'arithmétique la plus simple.

```julia-repl
julia> 2 + 1.3
3.3
```

On a additionné un entier (Int64) et un nombre à virgule flottante (Float64) et on a obtenu un résultat Float64.
De même :

```julia-repl
julia> nums = (3, 4.1, 1//4)
(3, 4.1, 1//4)

julia> typeof(nums)
Tuple{Int64, Float64, Rational{Int64}}

julia> [nums...]
3-element Vector{Float64}:
 3.0
 4.1
 0.25
```

Dans le cas ci-dessus, un tuple a conservé le type de chaque élément, mais la conversion en vecteur les a tous ramenés à un Float64 uniforme.

Le compilateur Julia sait quelles conversions de type sont possibles : passer d'un entier à un nombre à virgule flottante ne pose aucun problème, tandis que passer d'un nombre à virgule flottante à un entier entraîne une perte de précision, et une `InexactError` est levée.
La promotion de type convertit toutes les valeurs de l'expression vers un type commun, suffisamment souple pour être compatible avec toutes les entrées.

## Affectation de type

Se fier à l'inférence de type suffit pour résoudre de simples exercices d'apprentissage, mais pour de plus gros programmes, tu auras probablement besoin d'un contrôle plus précis.

Sur la plupart des processeurs modernes, un entier est de type `Int64` par défaut.
On a vu dans le concept [`Numbers`][numbers] qu'une valeur peut être convertie vers un type particulier qui n'est pas celui par défaut.

```julia-repl
julia> x = Int16(42)
42

julia> typeof(x)
Int16
```

Cependant, la variable `x` peut toujours être réaffectée à un autre type :

```julia-repl
julia> x = "changed"
"changed"

julia> typeof(x)
String
```

C'est ce qu'on appelle la `type instability`, à savoir :

- Très pratique dans les petits scripts.
- Néfaste pour les performances et la fiabilité des programmes plus importants.

À la place, on peut fixer le type de `x` en utilisant l'opérateur `::` :

```julia-repl
julia> y::Int16 = 42
42

julia> typeof(y)
Int16

julia> y = "changed"
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Int16
The function `convert` exists, but no method is defined for this combination of argument types.
```

Désormais, `y` est de type `Int16`, et le restera toujours.
Ainsi, le compilateur sait combien d'octets réserver pour elle, et peut optimiser le reste du code en s'appuyant sur un type stable.
En cela, la variable est plus ou moins semblable à celles d'un langage à typage statique comme le C.

## Assertion de type

L'affectation de type, décrite plus haut, s'utilise du côté gauche d'une affectation de variable pour contraindre le type de cette variable.

Utiliser l'opérateur `::` avec une valeur, ou avec quelque chose qui s'évalue en une valeur, constitue généralement une _assertion_ : la valeur doit être de ce type, sinon une erreur doit être levée.

```julia-repl
julia> 42::Number
42

julia> "two"::Number
ERROR: TypeError: in typeassert, expected Number, got a value of type String
```

On l'utilise souvent avec la valeur de retour d'une fonction, comme une dernière vérification simple que la fonction s'est comportée comme prévu.

## La hiérarchie des types

`Int64`, `Int16`, `String`, `Char` : d'où viennent ces types ?

Dans de nombreux langages orientés objet (OO), chaque type est une classe, l'héritage les organise en une hiérarchie de classes, et les méthodes de classe définissent les comportements.

Java et Ruby en sont des exemples évidents, mais même Python fonctionne de façon similaire en interne.

***Julia n'a pas de classes.***

La raison documentée est que les fonctionnalités orientées objet interfèrent avec le compilateur JIT et nuisent aux performances à l'exécution.

Et pourtant, regarde ce code :

```julia-repl
julia> y::Int16 = 42
42

julia> typeof(y)
Int16

julia> supertype(Int16)
Signed

julia> supertypes(Int16)
(Int16, Signed, Integer, Real, Number, Any)
```

En complétant avec quelques détails :

- `Int16` est un type, et on peut créer des variables de ce type.
- `Int16` est un sous-type de `Signed`, et la fonction `supertype()` nous le montre.
- Il existe une hiérarchie de types qui remonte par `Integer`, `Real` et `Number` jusqu'à `Any` tout en haut, et `subtypes()` nous listera cette branche de la hiérarchie.

Toutes les branches aboutissent à `Any`, qui a la particularité d'être son propre supertype.

```julia-repl
julia> supertypes(String)
(String, AbstractString, Any)

julia> supertype(Any)
Any
```

Ainsi, Julia n'a pas de hiérarchie de `class`, mais elle a bel et bien une hiérarchie de `type`.

À terme, on essaiera de démêler tout ça, mais il y a bien d'autres choses à explorer avant.

## Teste les types

On peut utiliser `typeof()` pour tester l'égalité de la manière habituelle.

```julia-repl
julia> typeof(11)
Int64

julia> typeof(11) == Int64
true

julia> typeof(11) == Number
false
```

L'égalité de type doit être exacte, car cette forme de comparaison ne tient aucun compte de la hiérarchie des types.

De façon plus souple, `isa` nous dit si une valeur a le même type qu'un comparateur, ou un sous-type de celui-ci.
On peut l'utiliser sous forme de fonction ou sous forme infixe.

```julia-repl
julia> 12 isa Int64
true

julia> 12 isa Number
true

julia> isa(12, Number)
true

julia> 12 isa String
false
```

À noter que `isa` attend une `value` à gauche, et non un `type`.

Essayer de comparer deux _types_ de cette façon donnera des résultats inattendus.
Le bon opérateur est `<:`, que l'on reverra beaucoup dans les prochains concepts.

```julia-repl
julia> Int64 isa Number  ## Don't do this!
false

julia> Int64 <: Number
true
```

## Types abstraits et concrets

On a vu que la hiérarchie des types forme une structure arborescente (au sens de l'informatique, avec la racine en haut).

Chaque élément de l'arbre est un `node`, et on peut les répartir en catégories :

1. Les nœuds qui ont des sous-types sont dits `abstract`.
2. Les nœuds feuilles, sans sous-types, sont dits `concrete`.

```julia-repl
julia> subtypes(Integer)  # an abstract type
3-element Vector{Any}:
 Bool
 Signed
 Unsigned

julia> subtypes(Int64)  # a concrete type
Type[]
```

Cette distinction est importante, car seuls les types concrets peuvent être `instantiated` comme variables.


```julia-repl
julia> a::Int16 = 42
42

julia> typeof(a)
Int16

julia> b::Integer = 42
42

julia> typeof(b)
Int64
```

À noter qu'essayer d'utiliser un type abstrait ne donne aucun message d'erreur (dans ce cas), mais le compilateur crée un type concret approprié : `Int64` au lieu de `Integer`.
Au moins, cela empêche d'affecter à la variable une valeur qui n'est pas un entier :

```julia-repl
julia> f::Integer = "hello"
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Integer
The function `convert` exists, but no method is defined for this combination of argument types.
```

L'affectation de type avec un type abstrait est donc une _contrainte_ sur le type de la variable : elle impose un sous-type de `Integer` (dans le cas ci-dessus).
C'est une chose inhabituelle dans le monde des langages de programmation : plus faible qu'une affectation de type en C, plus forte qu'une indication de type dans les versions récentes de Python.

Les fonctions `isabstracttype()` et `isconcretetype()` permettent de faire ce test.
À noter que ces deux fonctions ne sont pas simplement la négation l'une de l'autre : on verra dans un concept ultérieur que certains types ne sont ni abstraits ni concrets.


```julia-repl
julia> isconcretetype(Integer), isabstracttype(Integer)
(false, true)

julia> isconcretetype(Int64), isabstracttype(Int64)
(true, false)

# Vector is neither
julia> isconcretetype(Vector), isabstracttype(Vector)
(false, false)
```
