# Introduction

De nombreux langages disposent d'un moyen comme `null` ou `none` pour indiquer une valeur inexistante. Comme Julia est conçu pour traiter de gros volumes de données (souvent désordonnées), ce langage dispose de plusieurs formes d'absence de valeur.

L'objectif général est de signaler les valeurs manquantes ou suspectes au fur et à mesure qu'on les rencontre, puis de poursuivre sans lever d'exception.

## `nothing`

Quand une valeur n'existe vraiment pas, elle est représentée par `nothing`. C'est probablement l'équivalent le plus proche de ce que peuvent faire le `NULL` de C ou le `None` de Python.

```julia-repl
julia> n = nothing

julia> isnothing(n)
true

julia> typeof(n)
Nothing
```

`nothing` est donc une valeur singleton de type `Nothing`, et on peut la tester.

Un usage courant de `nothing` est de servir de valeur de retour (ou plutôt d'absence de valeur de retour) pour les fonctions qu'on n'utilise que pour leurs effets de bord (affichage, configuration réseau, etc.).

## `missing`

Pour les situations où une valeur existe en théorie mais où l'on ne sait pas ce qu'elle vaut, on utilise `missing`. Par exemple, quand on compte les véhicules qui circulent sur une route, les observateurs humains ont parfois besoin d'une pause ou les capteurs automatiques tombent en panne, alors que le trafic continue de s'écouler.

`missing` est donc une valeur de remplacement, qui avertit les humains qu'ils doivent décider comment gérer cette lacune dans les données.

```julia-repl
julia> mv = [1, 2, missing]
3-element Vector{Union{Missing, Int64}}:
 1
 2
  missing

julia> typeof(mv)
Vector{Union{Missing, Int64}} (alias for Array{Union{Missing, Int64}, 1})

julia> ismissing.(mv)  # broadcast function, displays as 1 for true, 0 for false
3-element BitVector:
 0
 0
 1
```

Peu d'autres langages intègrent cette fonctionnalité nativement, mais `NA` en R ou `NULL` en SQL en sont des équivalents proches.

Les expressions renvoient généralement `missing` par défaut lorsqu'elles contiennent des valeurs `missing`. Si tu veux que ces valeurs soient ignorées, utilise la fonction `skipmissing()` pour le rendre explicite :

```julia-repl
julia> mv = [1, 2, missing]
3-element Vector{Union{Missing, Int64}}:
 1
 2
  missing

julia> sum(mv)  # missing in, missing out
missing

julia> skipmissing(mv)
skipmissing(Union{Missing, Int64}[1, 2, missing])

julia> collect(skipmissing(mv))
2-element Vector{Int64}:
 1
 2

julia> sum(skipmissing(mv))  # functions like sum() can work with iterators
3
```

Comme `skipmissing` crée un itérateur, il faut l'envelopper dans `collect()` si l'on a besoin d'un vecteur.

Il est parfois utile de remplacer les valeurs `missing` par une valeur par défaut. La macro `@coalesce()` est pratique pour cela : elle renvoie la première valeur qui n'est pas `missing` (ou `missing` s'il n'y a rien d'autre).

```julia-repl
julia> str = ["I", "exist", missing]
3-element Vector{Union{Missing, String}}:
 "I"
 "exist"
 missing

julia> [@coalesce(s, "-") for  s in str]
3-element Vector{String}:
 "I"
 "exist"
 "-"
```

## `NaN`

Abréviation de « Not a Number », NaN signale un problème de calcul dans les situations où l'on attendait un nombre.

```julia-repl
julia> v = [0, 1, -1]
3-element Vector{Int64}:
  0
  1
 -1

julia> v / 0
3-element Vector{Float64}:
 NaN
  Inf
 -Inf
 
julia> sum(v / 0)
NaN
```

Tout calcul portant sur des données qui contiennent un NaN donnera un résultat `NaN`.

Il n'existe actuellement aucune fonction spéciale pour supprimer les valeurs `NaN`, mais la fonction `filter()` de la bibliothèque standard s'en charge très simplement. Seules les valeurs pour lesquelles une condition donnée est `true` sont copiées dans le tableau de résultat :

```julia-repl
julia> filter(!isnan, [1, 2, NaN])
2-element Vector{Float64}:
 1.0
 2.0
```
