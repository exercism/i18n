# Introduction

## Structures

Les structures sont des types de données personnalisés qui permettent de nommer et de regrouper plusieurs valeurs liées entre elles.

Pour définir une structure, utilise le mot-clé `struct` suivi d'un nom et d'accolades contenant les champs avec leurs noms et leurs types :

```rust
#[derive(Drop)]
struct User {
    active: bool,
    username: ByteArray,
    email: ByteArray,
    sign_in_count: u64,
}
```

Pour créer une instance d'une structure, précise le nom de la structure et utilise des accolades avec des paires clé-valeur pour les champs.

```rust
let user = User {
   active: true, username: "someusername123", email: "someone@example.com", sign_in_count: 1
};
```

Utilise la notation pointée pour accéder aux champs d'une instance de structure mutable, ou pour les modifier.

```rust
let mut user = User {
    active: true, username: "someusername123", email: "someone@example.com", sign_in_count: 1
};
user.email = "anotheremail@example.com";
```

## Propriété

En Cairo, les valeurs sont immuables, et cette immuabilité garantit que même si de nombreuses variables font référence à la même valeur, la valeur elle-même reste constante et inchangée.
Le _propriétaire_ d'une variable est le code qui peut lire cette variable (et la modifier si elle est mutable).

Les règles de la propriété en Cairo :

1. Chaque variable en Cairo a un propriétaire.
2. Il ne peut y avoir qu'un seul propriétaire à la fois.
3. Quand le propriétaire sort de la portée, la variable est détruite.

Une portée est l'intervalle, dans un programme, dans lequel une variable est valide.

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Quand une variable sort de sa portée, elle est détruite, ce qui garantit que la ressource associée est correctement libérée.
Cela se fait en implémentant ou en dérivant le trait `Drop`, qui indique au compilateur que le type peut être détruit sans risque une fois qu'il n'est plus utile.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

Pour le moment, l'implémentation de `Drop` peut être dérivée pour tous les types, sauf pour les dictionnaires (`Felt252Dict`) et les types qui contiennent des dictionnaires.

Une valeur peut aussi être _déplacée_ : cela se produit quand une valeur est passée à une autre fonction, ce qui détruit la variable d'origine qui y faisait référence (la rendant inutilisable) et crée une nouvelle variable pour contenir la même valeur.

```rust
fn foo(num: u32) { 
    // do something with p
}

fn main() {
    let num: u32 = 10;
    foo(num);
    // ownership of `num` was moved into `foo` and is thus no longer valid in this scope
}
```

Renvoyer une valeur équivaut à la déplacer.

L'exemple ci-dessous montre une fonction qui renvoie une valeur :

```rust
#[derive(Drop)]
struct A {}

fn main() {
    // main now owns a1
    let a1 = gives_ownership();

    // a2 comes into scope
    let a2 = A {};

    // a2 is moved into takes_and_gives_back, which also moves its return value into a3
    let a3 = takes_and_gives_back(a2);
} // Here, a3 and a1 go out of scope and are dropped. a2 was moved, so nothing happens.

// Moves its return value into the function that calls it
fn gives_ownership() -> A {
    let some_a = A {};
    some_a
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A {
    some_a
}
```

Comme une variable est détruite après avoir été déplacée, le compilateur interdit de la réutiliser ensuite.

```rust
#[derive(Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(p: Point) { 
    // do something with p
}

fn main() {
    let p = Point { x: 5, y: 10 };
    foo(p);
    foo(p); // compiler error: Variable was previously moved.
}
```

Dans ce cas, on essaie de passer la même valeur (la structure `Point` contenue dans la variable `p`) aux deux appels de fonction.
Une fois que la variable a été passée à la fonction `foo` la première fois, elle n'est plus utilisable.

Une façon de régler le problème consiste à dériver le trait `Copy` sur notre structure : cela change ce qui se passe quand on passe une variable `Copy` à une fonction, car la valeur n'est plus déplacée, mais une nouvelle variable qui fait référence à la même valeur est créée.
C'est une opération sans coût, car les variables sont une abstraction de Cairo et les valeurs sont toujours immuables.

Pour implémenter le trait `Copy` sur ton type, ajoute l'annotation `#[derive(Copy)]` à la définition du type.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(p: Point) { 
    // do something with p
}

fn main() {
    let p = Point { x: 5, y: 10 };
    foo(p);
    foo(p); // this now works
}
```

## Références et snapshots

Cairo propose deux mécanismes pour passer une valeur sans la détruire ni la déplacer : les `references` et les `snapshots`.

Les _snapshots_ offrent une « vue » immuable d'une valeur à un instant donné, ce qui permet de conserver la propriété d'une variable tout en accédant à son état.
Toute modification de la variable crée une nouvelle cellule mémoire, sans changer la vue du _snapshot_.

Pour créer un _snapshot_, il suffit de faire précéder l'instance de la variable du symbole `@`.

```rust
// this function takes in a snapshot using `@` with the data-type
fn get_len(arr: @Array<u128>) -> u32 { // 
    arr.len()
}

fn foo(arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let mut new_arr: Array<u128> = array![1, 2, 3, 4, 5, 6, 7, 8];
    let snapshot = @new_arr; // using `@` to create a snapshot of a variable
    let len = get_len(snapshot); // pass the snapshot as argument, retaining ownership
    foo(new_arr); // `new_arr` is still valid up until here and no further
}
```

Pour reconvertir un _snapshot_ en variable ordinaire, tu peux utiliser l'opérateur _desnap_ `*`, qui est l'inverse de l'opérateur `@`.
Seuls les types qui implémentent le trait `Copy` peuvent subir un _desnap_.

```rust
fn square(n: @u32) -> u32 {
    let n = *n; // we desnap the value
    n * n
}

fn main() {
    let num: u32 = 10;
    let squared = square(@num); // we use `@` to create a snapshot
    println!("{} squared = {}", num, squared);
}
```

Les références permettent de passer des valeurs mutables à des fonctions et de se les faire renvoyer implicitement, tout en conservant la propriété dans le contexte appelant.
On y parvient en utilisant le modificateur `ref`, à condition que la variable soit déclarée mutable avec le mot-clé `mut`.

On peut adapter l'exemple précédent avec `Point` pour utiliser des références mutables plutôt que de compter sur le trait `Copy`, et cela fonctionnera quand même.

```rust
#[derive(Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(ref p: Point) { 
    // we can now update the passed values and the changes
    // will be visible in the calling context
    p.x += 1;
}

fn main() {
    let mut p = Point { x: 5, y: 10 };
    foo(ref p);
    foo(ref p); // this now works even without the Copy trait
    println!("p.x = {}", p.x); // p.x = 7 
}
```
