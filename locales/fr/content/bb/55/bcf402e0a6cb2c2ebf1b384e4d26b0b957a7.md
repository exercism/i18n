# Instructions

Cet exercice porte sur l'analyse de fichiers de log.

À la suite d'un récent audit de sécurité, on t'a demandé de nettoyer les fichiers de log archivés de l'organisation.

Toutes les _strings_ passées aux méthodes sont garanties non nulles et sans espace au début ni à la fin.

## 1. Identifie les lignes de log brouillées

Tu dois te faire une idée du nombre de lignes de log de ton archive qui ne respectent pas les normes actuelles. Tu penses qu'un simple test permet de déterminer si une ligne de log est valide. Pour être considérée comme valide, une ligne doit commencer par l'une des _strings_ suivantes :

- [TRC]
- [DBG]
- [INF]
- [WRN]
- [ERR]
- [FTL]

Implémente la méthode `LogParser.IsValidLine()` pour qu'elle renvoie `false` si une _string_ n'est pas valide, et `true` sinon.

```csharp
var lp = new LogParser();
lp.IsValidLine("[ERR] A good error here");
// => true
lp.IsValidLine("Any old [ERR] text");
// => false
lp.IsValidLine("[BOB] Any old text");
// => false
```

## 2. Découpe la ligne de log

Une nouvelle équipe a rejoint l'organisation, et tu découvres que ses fichiers de log utilisent un séparateur étrange pour les « champs ». Au lieu de quelque chose de sensé comme un deux-points « : », ils utilisent une _string_ telle que « <---> » ou « <=> » (parce que c'est plus joli), en fait n'importe quelle _string_ dont le premier caractère est « < » et le dernier « > », avec entre les deux n'importe quelle combinaison des caractères « ^ », « \* », « = » et « - ».

Implémente la méthode `LogParser.SplitLogLine()` qui prend une ligne et renvoie un tableau de _strings_ dont chacune contient un champ.

```csharp
var lp = new LogParser();
lp.SplitLogLine("Section 1<===>Section 2<^-^>Section 3");
// => {"Section 1", "Section 2", "Section 3"}
```

## 3. Compte le nombre de lignes contenant un mot de passe entre guillemets

L'équipe a besoin de savoir quels mots de passe apparaissent dans du texte entre guillemets, afin de pouvoir les examiner manuellement.

Implémente la méthode `LogParser.CountQuotedPasswords()` pour donner une idée de l'ampleur probable du travail manuel.

Identifie les lignes de log où la _string_ littérale « password », qui peut être en majuscules ou en minuscules dans n'importe quelle combinaison, est entourée de guillemets.
Tu dois tenir compte de la possibilité qu'il y ait du contenu supplémentaire entre les guillemets, avant et après « password ».

Les lignes passées à la routine peuvent être valides ou non, au sens de la tâche 1. On les traite de la même manière, qu'elles soient valides ou non.

```csharp
string lines =
    "[INF] passWord " + Environment.NewLine + // contains 'password' but not surrounded by quotation marks
    "\"passWord\"" + Environment.NewLine + // count this one
    "[INF] User saw error message \"Unexpected Error\" on page load." + Environment.NewLine + //does not contain 'password'
    "[INF] \"The secret password was added by the user\""; // count this one

var lp = new LogParser();
lp.CountQuotedPasswords(lines);
// => 2
```

## 4. Supprime les artefacts des logs

Tu as découvert qu'un traitement en amont des logs sème un peu partout le texte « end-of-line » suivi d'un numéro de ligne (sans espace intercalaire).

Implémente la méthode `LogParser.RemoveEndOfLineText()` qui prend une _string_, en retire le texte de fin de ligne et renvoie une _string_ « propre ».

Les lignes qui ne contiennent pas de texte de fin de ligne doivent être renvoyées sans modification.

Retire simplement le texte de fin de ligne. N'essaie pas de retoucher les espaces.

```csharp
var lp = new LogParser();
lp.RemoveEndOfLineText("[INF] end-of-line23033 Network Failure end-of-line27");
// => "[INF]  Network Failure "
```

## 5. Liste les lignes avec des mots de passe extrêmement faibles pour que les coupables soient punis

Avant d'effacer les mots de passe du fichier, on doit lister tous les cas où un mot de passe commence par le texte « password ».

Implémente la méthode `LogParser.ListLinesWithPasswords()` pour afficher le mot de passe fautif suivi de la ligne complète.

Les lignes contenant des mots de passe entre guillemets ont déjà été retirées, et tu traites les lignes qu'elles soient valides ou non (voir la tâche 1).

Les lignes contenant un mot de passe fautif doivent être renvoyées avec le préfixe « <password>: ».

Les lignes ne contenant pas de mot de passe fautif doivent être renvoyées avec le préfixe « --------: ».

```csharp
var lp = new LogParser();
lp.ListLinesWithPasswords(new string[] {"my passwordsecret is great"});
// => "passwordsecret: my passwordsecret is great"
lp.ListLinesWithPasswords(new string[] {"my password secret"});
// => {"--------: my password secret"}

```
