# Types de nombres

Crystal dispose de toutes sortes de types de nombres, adaptés à des usages variés.
Par exemple, certains types sont plus rapides, mais couvrent une plage de valeurs possibles plus restreinte que d'autres.
D'autres couvrent une plage de valeurs plus étendue, mais sont plus lents.

En Crystal, il existe à la fois des entiers signés et des entiers non signés.
Les entiers signés peuvent être positifs ou négatifs.
Les entiers non signés ne peuvent être que positifs.

## Types d'entiers signés

Voici les [types d'entiers signés][int] en Crystal :

| Type     | Taille (bits) | Plage                                                                                                       |
| -------- | ------------- | ----------------------------------------------------------------------------------------------------------- |
| `Int8`   | 8             | -128 à 127                                                                                                  |
| `Int16`  | 16            | -32_768 à 32_767                                                                                            |
| `Int32`  | 32            | -2_147_483_648 à 2_147_483_647                                                                              |
| `Int64`  | 64            | -9_223_372_036_854_775_808 à 9_223_372_036_854_775_807                                                      |
| `Int128` | 128           | -170_141_183_460_469_231_731_687_303_715_884_105_728 à 170_141_183_460_469_231_731_687_303_715_884_105_727 |

Les types les plus petits consomment moins de mémoire et sont plus rapides que les plus grands, mais leur plage de valeurs possibles est plus restreinte.

Quand on sait que les valeurs resteront dans une certaine plage, mieux vaut utiliser le plus petit type possible, afin d'économiser de la mémoire et d'améliorer les performances.

Le type d'entier par défaut est `Int32`.
Pour déclarer un entier d'un type précis, on peut ajouter le nom du type en suffixe en écrivant `<number>_I <bit>`.

```crystal
1_i8.class
# => Int8
```

On peut utiliser la méthode `to_i<bit>` pour convertir entre différents types d'entiers.
La méthode `to_i` convertit vers le type d'entier par défaut, `Int32`.

```crystal
1_i8.to_i16.class
# => Int16

2_i16.to_i.class
# => Int32
```

## Types d'entiers non signés

Voici les [entiers non signés][uint] en Crystal :

`UInt8`, `UInt16`, `UInt32`, `UInt64`, `UInt128`

La seule différence entre les entiers signés et les entiers non signés est que les entiers non signés ne peuvent être que positifs.
Pour déclarer un entier non signé d'un type précis, on peut ajouter le nom du type en suffixe en écrivant `<number>_u<bit>`.
On peut utiliser la méthode `to_u<bit>` pour convertir entre différents types d'entiers non signés.
La méthode `to_u` convertit vers le type d'entier non signé par défaut, `UInt32`.

```crystal
1_u8.to_u16.class
# => UInt16
```

## Types à virgule flottante

Voici les types à virgule flottante en Crystal :

| Type      | Taille (bits) | Plage                |
| --------- | ------------- | -------------------- |
| `Float32` | 32            | 1,2E-38 à 3,4E+38    |
| `Float64` | 64            | 2,3E-308 à 1,7E+308  |

Il existe deux [types à virgule flottante][float] différents, l'un étant plus précis que l'autre.

Le type à virgule flottante par défaut est `Float64`.

On peut utiliser la méthode `to_f<bit>` pour convertir entre différents types à virgule flottante.
La méthode `to_f` convertit vers le type à virgule flottante par défaut, `Float64`.

## Type après une opération

Lorsqu'on effectue une opération entre deux nombres, le résultat aura le type du nombre le plus précis.
Un nombre à virgule flottante est plus précis qu'un entier, et un entier est plus exact qu'un entier non signé.
Ensuite, `Float64` est plus précis que Float32, et ainsi de suite.

```crystal
(1_u8 + 2_u64).class
# => UInt64

(1_u8 + 2_i64).class
# => Int64

(1_u8 + 2.0_f64).class
# => Float64
```

## Creuse plus loin : entiers non signés vs entiers signés

~~~~exercism/advanced
Sous le capot, ce qui différencie les entiers non signés des entiers signés, c'est que les entiers signés utilisent le premier bit pour stocker le signe.
Le signe est soit positif, soit négatif.
Pour les entiers non signés, le premier bit sert à stocker la valeur.
Ainsi, pour un entier signé de 32 bits, la valeur maximale est 2^31 - 1.
Pour un entier non signé de 32 bits, la valeur maximale est 2^32 - 1.

Si tu veux en savoir plus sur la notion de signe, tu peux en lire davantage sur [Wikipédia](https://en.wikipedia.org/wiki/Signedness).
~~~~
