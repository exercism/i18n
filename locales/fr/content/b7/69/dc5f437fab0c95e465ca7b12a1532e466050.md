# Introduction

## Copies et références

Avec ce que l'on sait pour l'instant, mettre à jour une variable à l'aide d'une fonction est un peu laborieux.
Chaque argument de fonction est traité comme une copie et ne modifie pas la valeur d'origine.
Selon la taille du type, cela peut avoir de lourdes conséquences sur les performances du code.

```cpp
int adjust_salary(int base, int kids) {
    return base + kids * 500;
}
int now_a_mother_of_twins{2500};
adjust_salary(now_a_mother_of_twins, 2);

// now_a_mother_of_twins is still 2500
now_a_mother_of_twins = adjust_salary(now_a_mother_of_twins, 2);
// now_a_mother_of_twins is now 3500
```

On peut voir les `References` comme des alias : les modifier a un effet sur la variable d'origine.
Les `References` s'écrivent avec une **esperluette** (`&`) dans la déclaration du type.

```cpp
int balance{1000};
int& budget{balance};
int pro_computer_wheels{699};
budget -= pro_computer_wheels;
// budget is now 301;
// balance is also 301;
```
Réassigner une `reference` (c'est-à-dire changer ce à quoi elle est liée) n'est pas possible.
On ne peut pas avoir de `reference` non initialisée.
Une `reference` doit être initialisée avec une variable existante.

```cpp
int main_acc{1'000'000};
int side_acc{-20};
int& savings{main_acc};
// => main_acc and savings are 1'000'000

// try to reseat savings to use main account
savings = side_acc;
// savings and main_acc are now -20
// as this uses the **value** of side_acc
savings += 20;
// savings and main_acc are now 0, side_acc is stil -20

int& future_budget;
// => compiler error, reference must be bound!
```

## `void`

Avec la puissance des `references`, il se peut que tu n'aies pas besoin de renvoyer une valeur depuis une fonction.
Dans ce cas, `void` sert de type de retour.

```cpp
void increase_power(int& level) {
    level += 500;
}
int goku{8700};
increase_power(goku);
// goku's power level?
// It's over 9000!
```
