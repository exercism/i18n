# Générateurs de tests

Le parcours C# utilise un [générateur de tests](https://exercism.org/docs/building/tooling/test-generators) pour générer automatiquement les tests des exercices d'entraînement.
Il tire parti du fait que la plupart des exercices définis dans le [dépôt problem-specifications](https://github.com/exercism/problem-specifications/) possèdent aussi un fichier `canonical-data.json`, qui contient des entrées et des sorties de test normalisées pouvant servir à implémenter l'exercice.

## Étapes

Pour générer les tests d'un exercice d'entraînement, le générateur de tests :

1. Lit les cas de test de l'exercice dans son fichier `canonical-data.json`
2. Utilise le fichier `tests.toml` pour omettre les cas de test exclus
3. Effectue le rendu des cas de test à l'aide du gabarit de générateur de l'exercice
4. Formate le gabarit rendu avec Roslyn
5. Écrit le gabarit formaté dans le fichier de test de l'exercice

### Étape 1 : lis le fichier `canonical-data.json`

Le générateur de tests analyse les cas de test du fichier `canonical-data.json` de l'exercice à l'aide de l'[espace de noms System.Text.Json](https://learn.microsoft.com/en-us/dotnet/api/system.text.json).

Comme certaines données canoniques utilisent l'imbrication, le cas de test analysé comporte un champ `path` supplémentaire qui contient les propriétés `description` des éventuels éléments parents, ainsi que la propriété `description` du cas de test lui-même.

### Étape 2 : omets les tests exclus du fichier `tests.toml`

Chaque exercice possède un fichier `tests.toml`, dans lequel des tests individuels peuvent être exclus ou désactivés.
Le générateur de tests supprime tous les cas de test marqués comme exclus (`include = false`).

### Étape 3 : effectue le rendu des cas de test

Les cas de test (potentiellement transformés) sont ensuite transmis au fichier `.meta/Generator.tpl`, qui définit comment effectuer le rendu des tests à partir de ces cas de test.

### Étape 4 : formate le gabarit rendu avec Roslyn

Le gabarit rendu est ensuite formaté avec [Roslyn](https://github.com/dotnet/roslyn).
Cela présente les avantages suivants :

- Les exercices sont formatés de manière cohérente
- Tu n'as pas besoin de te soucier beaucoup des espaces et de l'alignement quand tu écris des gabarits

### Étape 5 : écris le gabarit rendu dans le fichier de test de l'exercice

Enfin, la sortie du gabarit rendu est écrite dans le fichier de test de l'exercice.

## Gabarits

Le rendu des gabarits est effectué à l'aide de la [bibliothèque Scriban](https://github.com/scriban/scriban/).

## Interface en ligne de commande

Le générateur de tests peut être exécuté de deux façons :

1. `bin/update-tests.ps1` : met à jour les tests de tous les exercices qui ont un gabarit de générateur
2. `bin/update-tests.ps1 -e <slug>` : met à jour les tests de l'exercice indiqué, s'il a un gabarit de générateur
