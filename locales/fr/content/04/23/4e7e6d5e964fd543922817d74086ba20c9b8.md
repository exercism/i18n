# Mutabilité

La mutabilité est une caractéristique d'une liaison particulière en Rust. Une liaison est soit immuable, soit mutable. La valeur d'une liaison immuable ne peut pas être modifiée ; celle d'une liaison mutable peut l'être. Toutes les liaisons sont immuables par défaut.

## Liaisons

Une liaison est l'association entre un nom de variable particulier tel qu'il apparaît dans le code source et une zone de mémoire particulière telle qu'elle apparaît pendant l'exécution. À proprement parler, les liaisons n'existent que pendant la compilation : avant la compilation, aucune mémoire n'est réellement allouée, et après la compilation, le code machine ne manipule plus que des adresses mémoire au lieu de variables nommées.

Les liaisons sont généralement créées avec le mot-clé `let`. Elles sont aussi créées à partir des paramètres de fonction et dans certaines autres situations.

Une liaison peut avoir diverses caractéristiques, dont la plus importante est la mutabilité. Une liaison mutable est une liaison pour laquelle il est légal de modifier la valeur de la mémoire liée. Rust suit et applique strictement la mutabilité de chaque liaison pour aider à garantir que les programmes sont corrects, en rejetant les programmes qui tentent à tort de modifier une liaison censée être immuable.

## Mutabilité

En pratique, la mutabilité est souvent simple : en utilisant le mot-clé `mut` dans la définition de la liaison, on obtient la possibilité de modifier la valeur.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### Rétrograde de mutable à immuable

Une liaison peut toujours être rétrogradée de mutable à immuable. Cette opération est transparente.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### Promeus d'immuable à mutable

En général, il est possible de promouvoir une valeur d'immuable à mutable à chaque fois que la propriété est transférée.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

En `(1)`, la propriété de la _string_ est transférée de `x` à `y`, ce qui permet de promouvoir la valeur en mutable.

### La mutabilité des paramètres de fonction

Il existe deux manières différentes pour qu'un paramètre de fonction soit mutable. La première, la plus courante, ressemble au passage par référence en C :

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

Dans cet exemple, la mutabilité est annotée explicitement à trois endroits. Les trois déclarations de mutabilité sont nécessaires pour que les références mutables fonctionnent.
En `(2)`, la liaison `x` est déclarée mutable. Cette liaison est le propriétaire de plus haut niveau de la valeur.
En `(3)`, cette valeur est empruntée de façon mutable, pour être passée à la fonction `increment`.
En `(1)`, une nouvelle liaison mutable `n` est créée vers la référence appropriée.

Il existe un autre style de mutabilité des paramètres, moins courant mais parfois encore utile. Dans ce style, la valeur est possédée, mais la liaison est mutable.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

Cet exemple demande moins d'annotations explicites, car il s'agit en fait d'un transfert de propriété avec une promotion de mutabilité intégrée. Il fonctionne parce que `i32` est un type `Copy`, qui copie les données de façon transparente.
En `(1)`, on déclare que `increment_internally` accepte comme paramètre un `i32` possédé et mutable nommé `n`.
En `(2)`, on déclare que `x` est une liaison immuable vers la valeur `1`.
En `(3)`, `x` est copié dans un nouvel emplacement mémoire. `x` reste immuable, tandis que `n` est mutable.

Il est bien sûr possible de combiner les formes, en donnant une liaison mutable à une référence mutable (`mut n: &mut i32`, etc.), mais c'est rarement ce que l'on souhaite réellement.

### La mutabilité sans `let`

Plusieurs constructions de Rust (`if let`, `match`, etc.) peuvent elles aussi créer des liaisons. Ces liaisons peuvent également être mutables.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

Cet exemple produit d'abord `v = Some(2)`, puis `v = None`.

## Le masquage

Il est possible, et souvent idiomatique, de réutiliser un nom de variable au fur et à mesure qu'une valeur est transformée, en le redéclarant avec plusieurs invocations de `let`. C'est ce qu'on appelle le masquage.

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

Cependant, il ne s'agit pas ici de mutabilité : les valeurs d'origine sont en principe toujours présentes. Face à des types qui n'implémentent pas `Drop`, le compilateur peut choisir de modifier un emplacement mémoire plutôt que d'en allouer un nouveau. Il ne le fera cependant jamais pour un type `Drop`, ni si l'ancienne liaison est réutilisée par la suite.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
