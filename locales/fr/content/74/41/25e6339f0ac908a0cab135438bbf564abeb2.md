# Instructions

Dans cet exercice, tu vas appliquer les [règles du jeu de Go](https://matmoore.github.io/learngo/). Les règles elles-mêmes sont déjà écrites ; il te suffit de les appliquer pour mettre à jour la partie et gérer les erreurs et les violations des règles.

Le jeu est représenté de la façon suivante :

```elm
type Player
    = Black
    | White


type alias Game =
    { whiteCapturedStones : Int
    , blackCapturedStones : Int
    , player : Player
    , error : String
    }
```

Le jeu comporte 4 règles :

- Chaque point ne peut porter qu'une seule pierre (`oneStonePerPointRule`)
- Les pierres adverses peuvent être capturées ! (`captureRule`)
- On ne peut pas placer une pierre là où elle se capturerait elle-même (`libertyRule`)
- On ne peut pas utiliser deux fois le même point (`koRule`)

## 1. Applique les règles

Écris le contenu de la fonction `applyRules`, qui prend un `Game` initial et un ensemble de règles, et qui renvoie le nouveau `Game` une fois les règles appliquées.

`oneStonePerPointRule`, `libertyRule` et `koRule` vérifient toutes les violations des règles et peuvent renvoyer une erreur ; elles ont donc pour type de retour `Result String Game`. Si l'une de ces règles échoue, c'est la partie d'origine qui doit être renvoyée, mais avec le champ `error` mis à jour avec l'erreur correspondante.

`captureRule` ne vérifie pas les violations et ne peut donc pas échouer (même si elle peut renvoyer un `Game` modifié) ; son type de retour est donc `Game`.

Si toutes les règles passent, les modifications apportées au `Game` par les règles doivent être conservées, et le joueur doit changer. La fonction `changePlayer` est fournie pour cela.

```elm
applyRules : Game -> Rule -> NonValidatingRule -> Rule -> Rule -> Game
applyRules game oneStonePerPointRule captureRule libertyRule koRule =
--> If all rules pass, return a `Game` with all changes from the rules applied, and changePlayer
--> If any rule fails, return the original Game, but with the error field set
```
