# À propos

L'analyse syntaxique est le processus qui consiste à transformer du texte en données exploitables. Les fonctions du paquet `String` sont vite limitées à cet égard et les expressions régulières sont difficiles à utiliser, c'est pourquoi la façon idiomatique d'analyser en Elm passe par le paquet `elm/parser`.

Prenons l'exemple de l'écriture d'un analyseur syntaxique pour (un sous-ensemble de) le langage de programmation [LOLCODE][lolcode].
Considérons le programme commenté suivant :

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

Commençons par écrire un type Elm pour représenter les commandes possibles :

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

On peut alors modéliser notre programme LOLCODE par une `List Command`.
Commençons par un analyseur pour la ligne `HAI 1` :

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP` se construit à l'aide d'un pipeline d'analyseurs.
L'opérateur `(|.)` signifie « analyser la _string_ mais jeter le résultat » et `(|=)` signifie « analyser la _string_ et garder le résultat ».
Dans cet exemple, `Parser.keyword "HAI"` consomme un « HAI », mais ce résultat est ignoré.
`Parser.spaces` consomme un nombre quelconque de caractères ' ', '\n' et '\r', mais ce résultat est lui aussi ignoré.
`Parser.int` analyse un entier, et la valeur de cet entier (par exemple 1) est passée au `Parser.succeed Version` situé en tête du pipeline, et l'analyseur réussit en renvoyant la valeur `Version 1`.

Si l'un des analyseurs du pipeline échoue, il renvoie un `Parser.DeadEnd` et l'analyseur tout entier échoue.
On peut exécuter un analyseur avec `Parser.run` :

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

Attaquons maintenant la ligne « CAN HAS STDIO? » avec

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP` est lui aussi un pipeline d'analyseurs, mais cette fois il se termine par `Parser.symbol`, qui convient pour analyser des symboles comme « ? ».
La valeur que l'on veut garder (le nom du paquet à importer) est analysée par

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

Comme on ne sait pas à l'avance quel sera le nom du paquet, on ne peut pas utiliser `Parser.keyword` ; on se sert donc de `Parser.chompWhile`, qui consomme les caractères un par un tant qu'ils satisfont une condition (ici, être un caractère alphanumérique).
Ces caractères ainsi « grignotés » sont ensuite rassemblés par `Parser.getChompedString`, qui renvoie un `Parser String`.
Ici, on veut normaliser le nom des paquets, donc on utilise `Parser.map` pour modifier la _string_ contenue dans l'analyseur et la mettre en minuscules.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

Ensuite, `VISIBLE "HAI WORLD!"` est analysé par

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

On dispose maintenant d'un analyseur pour chaque commande.
Bien sûr, dans un programme général, on ne peut pas prédire l'ordre de ces commandes, on construit donc un analyseur de commandes générique

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf` essaie les analyseurs un par un, dans l'ordre donné.
Si un analyseur échoue, on passe au suivant, mais s'il réussit, son résultat est renvoyé sans essayer les analyseurs restants.
Si tous les analyseurs échouent, `Parser.oneOf` échoue.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

On remarque que chaque tentative ratée produit un `Parser.DeadEnd`, que `Parser.oneOf` rassemble.

Pour analyser un programme complet, il faut analyser plusieurs commandes les unes à la suite des autres avec

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence` est un analyseur très personnalisable, doté d'un certain nombre d'options.
`start`, `separator` et `end` prennent des _strings_ qui séparent les éléments de la séquence ; pour analyser une liste Elm, on utiliserait « [ », « , » et « ] ».
`spaces` apporte de la souplesse en prenant un analyseur qui gère les espaces éventuels entre les éléments et les séparateurs ; pour analyser une liste Elm, on utiliserait `Parser.spaces`, mais ici on n'accepte aucun espace, donc on utilise `Parser.succeed ()`, qui réussit immédiatement sans rien consommer.
`item` prend l'analyseur des éléments et, pour finir, `trailing` permet de décider si les séparateurs en fin de séquence sont `Parser.Forbidden`, `Parser.Mandatory` ou `Parser.Optional`.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

Quand un analyseur réussit, il arrête de consommer la _string_.

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

Donc, si on veut s'assurer d'avoir analysé toute la _string_, on peut utiliser `Parser.end`

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

Enfin, il arrive qu'on doive décider de faire échouer un analyseur en fonction de ce qu'il a analysé.
Par exemple, si on voulait un analyseur qui fait échouer les programmes commençant par deux commandes « HAI » d'affilée, on pourrait utiliser

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen` peut inspecter le contenu d'un analyseur et renvoie un nouvel analyseur en fonction de sa valeur.
Ici, on fait échouer l'analyseur avec un message personnalisé via `Parser.problem` dans un cas, et on renvoie la valeur d'origine dans l'autre.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
