# À propos

En Rust, un itérateur est toute valeur qui implémente le _trait_ [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html).
On peut faire avancer manuellement les valeurs d'un itérateur en appelant la méthode `next` sur l'itérateur.

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Beaucoup de [`collections`](https://doc.rust-lang.org/std/collections/index.html) de Rust implémentent
[`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html),
ce qui permet de produire un `Iterator` à partir des valeurs d'une _collection_.

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

À noter : bien que `IntoIterator::into_iter` consomme son type `self`, ce type ne doit pas nécessairement être une valeur possédée.
Ainsi, il existe des implémentations d'`IntoIterator` pour [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2),
pour [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)
et pour [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1).
Ces implémentations, qui couvrent différents degrés de possession, offrent une souplesse appréciable.

Comprendre les `traits` n'est pas nécessaire pour ce concept, et tu auras tout un exercice pour les maîtriser.
Pour l'instant, retiens simplement que :

- Tout type qui implémente `IntoIterator` est appelé un itérable, car il peut être transformé en itérateur.
- Tout type qui implémente `Iterator` est un itérateur, qui _produit_ des valeurs et sur lequel on peut _itérer_.
- Tu peux obtenir un itérateur à partir de n'importe quel type qui implémente `IntoIterator` en appelant sa méthode `into_iter`.
- Tout itérateur [implémente `IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25) et se renvoie lui-même.
- Les boucles `for` opèrent toujours sur des itérateurs et appellent `IntoIterator` implicitement sur leur argument de plage.

## `into_iter` et les boucles for

Tu connais probablement déjà les boucles for sur un vecteur :

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

Fondamentalement, une boucle `for` n'est qu'une notation abrégée pour appeler la méthode `into_iter` de son argument,
puis pour appeler `next()` jusqu'à ce qu'il n'y ait plus d'éléments à produire. Autrement dit, la boucle précédente se décompose ainsi :

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## Les méthodes `iter` et `iter_mut`

La plupart des _collections_ de Rust fournissent les méthodes `iter` et `iter_mut`.
Pour une _collection_ de type `T`, ces deux méthodes font par convention ce qui suit :

- L'itérateur renvoyé par `iter` produit des références immuables `&T`.
- L'itérateur renvoyé par `iter_mut` produit des références mutables `&mut T`.

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## Différence entre `iter`, `iter_mut` et `into_iter`

Si `iter`, `iter_mut` et `into_iter` produisent tous des itérateurs, quelles sont les différences ?

- L'itérateur renvoyé par `iter` produit par convention des références immuables `&T`.
- L'itérateur renvoyé par `iter_mut` produit par convention des références mutables `&mut T`.
- L'itérateur renvoyé par `into_iter` peut produire `T`, `&T` ou `&mut T`, selon son contexte.

Quel est le contexte d'un appel à `into_iter` ?
Son type `self`.
Rappelle-toi qu'il existe des implémentations d'`IntoIterator` pour `Vec`, `&'a Vec` et `&'a mut Vec`.
Par conséquent :

- `(&v).into_iter()` équivaut à `v.iter()` => renvoie `&T`
- `(&mut v).into_iter()` équivaut à `v.iter_mut()` => renvoie `&mut T`
- `v.into_iter()` => renvoie `T` et déplace les valeurs

C'est encore plus clair dans les boucles for :

- `for num in &v {...}` => lie `&T`
- `for num in &mut v {...}` => lie `&mut T`
- `for num in v {...}` => lie `T` et déplace les valeurs

Il est souvent plus clair d'écrire `v.iter()` plutôt que `(&v).into_iter()`.
Il y a donc des raisons ergonomiques de préférer `iter` et `iter_mut` à `into_iter`.

## Utilise les méthodes intégrées des itérateurs

Les itérateurs fournissent de nombreuses méthodes intégrées, comme `map`, `filter` et `collect`.
Ces méthodes s'utilisent parfois avec des _closures_.

`map` utilise une _closure_ pour transformer les valeurs d'un itérateur.
`take` tronque un itérateur (potentiellement infini) en un itérateur qui se termine après au plus le nombre spécifié d'éléments.

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter` transforme l'itérateur en un itérateur qui ne renvoie que les valeurs pour lesquelles la _closure_ vaut `true`.
`count` consomme l'itérateur et renvoie le nombre d'éléments produits.

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map` transforme un itérateur en transformant chaque élément en un nouvel itérateur à l'aide de la _closure_ fournie,
puis en aplatissant tous les nouveaux itérateurs produits en les enchaînant les uns aux autres.
`collect` produit une nouvelle _collection_,
à condition que le type de _collection_ implémente [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html).

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

Le [_trait_ `Iterator`](https://doc.rust-lang.org/std/iter/trait.Iterator.html) fournit _beaucoup_ de transformations d'itérateurs de ce genre, tout aussi utiles ;
il vaut la peine de lire la documentation et de te familiariser avec elles.

## L'évaluation paresseuse

Il est important de savoir que les itérateurs de Rust sont paresseux :
ils ne produisent aucune valeur tant qu'on ne consomme pas l'itérateur.
Si tu écris et exécutes le code suivant :

```rust
(0..5).map(|x| x * x);
```

Tu obtiendras l'erreur de compilation suivante :

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

C'est parce que `map` est une méthode adaptatrice qui renvoie un autre itérateur.

Pour consommer un itérateur, utilise soit une boucle `for`, soit une méthode d'itérateur qui produit une valeur qui n'est pas elle-même un itérateur.

Par exemple, `collect` est une méthode consommatrice (sa signature ne renvoie pas un itérateur mais un type générique) :

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
