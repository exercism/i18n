# Exceptions

```sather
   raise "Unknown prop: " + prop;
```

```sather
   protect
      ...
   when $STR then
      #OUT + exception.str;
   end;
```

## raise

`raise` prend n'importe quel objet. Lever une `STR` est le cas simple, et c'est ce que cet exercice utilise. Une classe à toi transporte davantage d'informations (quelle prop, combien étaient attendues), au prix d'un endroit où la définir.

Une exception remonte vers l'extérieur à travers les appelants jusqu'à ce qu'un `protect` l'attrape. Si aucun ne l'attrape, le programme s'arrête et l'affiche.

Sather n'enregistre pas quelles exceptions une routine est susceptible de lever, et n'oblige pas les appelants à les gérer. Rien dans le type d'une routine n'indique qu'elle peut échouer.

## protect

```sather
   protect
      body
   when $STR then
      ...
   when SOME_CLASS then
      ...
   end;
```

Les branches sont essayées dans l'ordre, et c'est la première dont le type correspond à la valeur levée qui s'exécute. `exception` est cette valeur, et n'est dans la portée qu'à l'intérieur d'une branche.

Un `protect` sans branche correspondante n'attrape rien : l'exception continue vers l'extérieur comme si le `protect` n'était pas là.

## Où attraper

Attrape là où il est réellement possible de faire quelque chose. Un `protect` qui avale une exception et poursuit avec une valeur inventée transforme un échec bien visible en une réponse fausse et silencieuse, ce qui est pire.

```sather
   -- almost always wrong
   protect
      return risky;
   when $STR then
      return 0;
   end;
```

## Exceptions ou contrats ?

Les deux concernent les choses qui tournent mal, mais ils s'appliquent à des cas opposés.

Une **exception** concerne quelque chose qui peut réellement se produire, et que l'appelant pouvait raisonnablement ne pas pouvoir empêcher : une prop absente de la table, un fichier qui n'est pas là.

Un **contrat**, qui fait l'objet du prochain exercice, concerne ce qui ne doit jamais se produire (un appelant qui passe un poids négatif), et affirme que l'appelant a un bug. Les contrats ne sont vérifiés que lorsqu'on le demande, et un contrat violé arrête le programme au lieu de lever quelque chose d'attrapable.

En gros : si un appelant attentif peut encore tomber dessus, lève une exception. Si tomber dessus signifie que l'appelant a tort, mets-le dans un contrat.
