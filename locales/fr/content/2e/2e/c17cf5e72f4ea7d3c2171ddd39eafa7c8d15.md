# Introduction

L'utilisation du filtrage par motif est dominante dans le code Elixir idiomatique et assertif. Tu te souviens peut-être que `=/2` est décrit comme un opérateur de correspondance plutôt que comme un opérateur d'affectation. Lorsqu'on utilise l'opérateur de correspondance, si le motif à gauche correspond à la droite, les variables à gauche sont liées, et la valeur du côté droit est renvoyée. Une `MatchError` est levée s'il n'y a pas de correspondance.

```elixir
2 = 2
# => 2
# Literals can be matched if they are the same

2 = 3
# => ** (MatchError) no match of right hand side value: 3

{_, denominator} = Float.ratio(0.25)
# => {1, 4}
# the variable `denominator` is bound to the value 4
```

Rappelle-toi que les correspondances se font du côté droit vers le côté gauche.

Dans le dernier exemple, si on n'a pas besoin d'une variable dans un filtrage par motif, on peut l'ignorer en référençant `_`. Toute variable commençant par un `_` n'est pas suivie par l'environnement d'exécution.

## Filtrage par motif dans les fonctions nommées

Le filtrage par motif est aussi un outil utile lorsqu'on crée plusieurs clauses de fonction. Le filtrage par motif peut être utilisé sur les arguments des fonctions, ce qui détermine ensuite quelle clause de fonction invoquer, en partant du haut du fichier jusqu'à la première correspondance. Les variables peuvent être liées dans la tête de la fonction et utilisées dans le corps de la fonction.

```elixir
defmodule Example do
  def named_function(:a = variable_a) do
    {variable_a, 1}
  end

  def named_function(:b = variable_b) do
    {variable_b, 2}
  end
end

Example.named_function(:a)
# => {:a, 1}

Example.named_function(:b)
# => {:b, 2}

Example.named_function(:c)
# => ** (FunctionClauseError) no function clause matching in Example.named_function/1
```
