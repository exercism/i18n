# Introduction

Dans de nombreux langages orientés objet, il est courant d'étendre des comportements en créant une [sous-classe][wiki-subclass] d'une classe parente, en héritant des méthodes de la classe parente tout en en ajoutant de nouvelles.
On obtient ainsi une hiérarchie d'objets.

Julia _n'a pas de classes_, et donc, par extension, _n'a pas de sous-classes_.
Comment hériter et étendre des comportements existants ?

On a vu dans les concepts précédents comment créer une hiérarchie de types, et on a aussi appris comment Julia utilise le [dispatch multiple][concept-multiple-dispatch] pour choisir les méthodes en fonction des types des arguments.

Julia dispose aussi de plusieurs interfaces informelles, qui permettent à tes types personnalisés de se brancher sur des comportements déjà définis pour les types standards.

La façon la plus simple de l'illustrer est l'interface d'itération.

## Itérateurs

Plus tôt dans le programme, on a vu plusieurs façons dont Julia peut parcourir chaque élément d'une collection.

- [Boucles][concept-loops], comme `for item in items...`
- [Diffusion][concept-vector-operations] : `[1, 2, 3] .- 0.5`
- [Fonctions d'ordre supérieur][concept-hof] : `map(√, [1, 4, 9])`
- [Compréhensions][concept-comprehensions] : `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Générateurs][concept-comprehensions] : `(x^2 for x in 1:1e6)`, évalués de façon paresseuse.

De toute évidence, Julia sait parcourir les collections standards élément par élément : les vecteurs et les intervalles dans les exemples ci-dessus, mais aussi les Sets, les Dicts, etc.

Comment ajouter cette capacité à nos propres collections personnalisées, surtout si elles peuvent être parcourues de façon paresseuse comme un générateur ?

### Prérequis minimaux

Pour créer une séquence que l'on peut parcourir, il nous faut (au moins) deux choses :

1. Un moyen d'obtenir le _premier_ élément.
2. Un moyen d'obtenir l'élément _suivant_ à partir de l'état courant.

Julia réalise ces tâches grâce aux méthodes de la fonction `Base.iterate()`, selon les étapes suivantes :

1. `Base.iterate(iter)` est appelée automatiquement en premier.
    - S'il n'y a rien à parcourir, elle renvoie `nothing`.
    - Sinon, elle renvoie le `Tuple` du premier élément renvoyé et du premier état : `(firstitem, firststate)`.
2. `Base.iterate(iter, state)` est appelée automatiquement si un élément a été renvoyé à l'itération précédente, en prenant `firststate` comme argument `state`.
    - Si l'itération se termine, elle renvoie `nothing`.
    - Sinon, elle renvoie le `Tuple` de l'élément suivant et de l'état suivant : `(nextitem, nextstate)`.
3. Répète l'étape 2 jusqu'à la fin de l'itération.

Toutes ces étapes se déroulent « sous le capot », ce qui signifie que les appels de méthodes et l'état sont gérés en interne par le protocole d'itération (l'état restant opaque), et que seul l'élément est exposé aux constructions de haut niveau, comme les boucles.
Autrement dit, on ne voit jamais que l'`item`, tout le reste restant dans une boîte noire.

Le [dispatch multiple][concept-multiple-dispatch] est au cœur de ce mécanisme.
Le type de `iter` détermine quelles méthodes sont appelées, et le nombre d'arguments détermine si c'est le premier élément ou l'élément suivant qui est renvoyé.

Les méthodes pour les types standards sont déjà définies : `Vector`, `Range`, `Set`, etc. ([actuellement][ref-iterations-collections] 14 types au total).

Pour qu'un `MyType` personnalisé partage les mêmes comportements, il faut d'abord définir :
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Tout cela peut sembler abstrait et déroutant, mais ça peut être très simple.
Pour illustrer, imaginons que l'on veuille un type qui donne les puissances d'un entier `n` donné, jusqu'à un nombre maximum.

D'abord, définissons un type personnalisé :

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

On peut maintenant définir les méthodes `iterate` pour ce type, mais quel est le premier élément et quel est le premier état ?

Pour obtenir le premier élément, certains itérateurs ont besoin d'une mise en place compliquée, mais dans ce cas simple, on remarque que le premier élément renvoyé n'est autre que le nombre de base, il suffit donc de vérifier que la valeur de `count` est supérieure ou égale à un.

Intéressons-nous maintenant au premier état, qui transporte les informations utilisées pour l'itération suivante.
C'est à toi de décider quelles informations tu dois garder pour y parvenir, et ce peut être n'importe quel type.

Dans ce cas, on pourrait simplement garder l'« indice » auquel élever `n`, ou bien trouver une option plus performante en utilisant la puissance la plus récente de `n` (c'est-à-dire l'élément renvoyé) et l'« indice » suivant dans la séquence.
Ces deux nombres peuvent être regroupés dans un `Tuple` et renvoyés comme `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

Dans cet exemple, le premier élément (`p.n`) est renvoyé à la boucle et le premier état `(p.n, 2)` est passé à la méthode `iterate(P::Powers, state)`.
Là, on peut traiter l'état pour produire l'élément suivant en multipliant l'élément courant par le nombre de base, augmentant ainsi sa puissance de `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Si la valeur de l'indice reste dans les limites de `count`, le `Tuple` est renvoyé avec l'élément `next` et le `Tuple` d'état incrémenté.
Quand la valeur de l'`index` dépasse `count`, c'est `nothing` qui est renvoyé à la place, pour indiquer que l'itération est terminée.

Tu as peut-être remarqué que les méthodes `iterate(p::Powers)` et `iterate(p::Powers, state)` ont des corps de fonction assez similaires.
En fait, avec un peu d'astuce, cette similitude permet une implémentation plus épurée en n'utilisant que la version à deux arguments, avec un argument par défaut pour l'état : `Base.iterate(p::Powers, state=(1, 1))`
Avec ça, on n'aurait plus besoin de la méthode séparée à un seul argument `iterate(p::Powers)`.
C'est ce que l'on fait couramment en pratique quand c'est possible.

Jusqu'ici, on dispose déjà de fonctionnalités utiles : pour les 4 premières puissances de 3, on peut parcourir les résultats avec une boucle, vérifier si un nombre donné fait partie des résultats et appliquer des fonctions d'agrégation comme `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Méthodes supplémentaires

Malgré ce bon début, tout ne fonctionne pas encore.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Effectivement, `length(Powers(3, 4))` donne exactement le même message d'erreur.

C'est facile à corriger, car la longueur fait partie du constructeur de type : 4 dans ce cas.
Il suffit de définir `Base.length()` pour ce type, et on peut alors utiliser les compréhensions et `collect()` sur la séquence.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Pour des raisons d'efficacité, il vaut mieux définir aussi `Base.eltype()` : le type des éléments du résultat.
Cela permet à des fonctions comme `collect()` de pré-allouer de l'espace pour le `Vector{Int}` de sortie, au lieu de faire des `push!()` répétés dans un `Vector{Any}`.

Remarque la syntaxe, que tu n'as peut-être jamais vue : cette méthode est définie sur le _type_, et non sur une _instance_ de ce type.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Les itérateurs ne sont pas _tenus_ d'avoir une longueur finie.
L'usage des séquences « infinies » est plus limité, mais les parcourir en boucle peut être utile tant qu'il existe un moyen de sortir de la boucle avec l'instruction `break`.
Par exemple, on pourrait définir une variante de `Powers` qui génère des valeurs inférieures à une certaine limite (peut-être `typemax(Int)`, pour éviter un dépassement d'entier).

## Résumé

Les interfaces sont assez délicates à expliquer, car l'approche de Julia est très différente de celle de la plupart des autres langages.
En particulier, le nom de l'interface peut n'être jamais mentionné dans l'implémentation, contrairement à la [création de sous-classes][wiki-subclass] ou aux [mixins][wiki-mixins].

Cependant, elles sont étonnamment simples en pratique :

1. Définis un type adapté.
2. Détermine quelles méthodes sont nécessaires.
3. Implémente ces méthodes pour ton type personnalisé ; en général quelques méthodes seulement, assez courtes et simples.
4. Laisse le [dispatch multiple][concept-multiple-dispatch] s'occuper du reste, automatiquement.
