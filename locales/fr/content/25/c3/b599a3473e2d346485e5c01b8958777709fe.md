# Introduction à la mise entre guillemets

Un conseil que les nouveaux programmeurs bash entendent sans cesse :

> Mets tes variables entre guillemets !

Pourquoi donc ?

Quand tu effectues l'expansion d'une variable (comme `$name`), tu veux presque toujours utiliser la _valeur_ de la variable comme une seule _string_ (ou un nombre).
Tu ne veux pas que la valeur soit traitée de manière inattendue comme deux _strings_ ou plus.

## La mise entre guillemets

La mise entre guillemets est le principal mécanisme pour garantir qu'un morceau de texte soit traité comme un seul mot.
Il existe deux principaux types de guillemets.

### Guillemets doubles

Les guillemets doubles permettent l'expansion de paramètres, l'expansion arithmétique et la substitution de commandes à l'intérieur de ceux-ci.

```bash
echo "This is bash version $BASH_VERSION"
```

Tu peux inclure un guillemet double littéral à l'intérieur d'une _string_ entre guillemets doubles en le précédant d'un antislash.

```bash
echo "She said \"Let me teach you about bash.\""
```

### Guillemets simples

Les guillemets simples _n'autorisent pas_ d'expansion à l'intérieur.

```bash
echo 'This is bash version $BASH_VERSION'
# ...^..................................^
# prints exactly: This is bash version $BASH_VERSION
```

Il est _impossible_ d'intégrer un guillemet simple à l'intérieur d'une _string_ entre guillemets simples.

## Importance de la mise entre guillemets

Qu'est-ce qui ne va pas avec `echo $name`, exactement ?

Quand le shell analyse une ligne de code, il effectue [plusieurs types d'expansions][expansions], dans l'ordre.
Deux des dernières expansions sont le _découpage en mots_ et l'_expansion des noms de fichiers_.

### Découpage en mots

Tout résultat d'expansion de paramètre, de substitution de commande ou d'expansion arithmétique _qui ne s'est pas produit entre guillemets doubles_ est éligible au « découpage en mots ».
Le shell prend le résultat expansé et le découpe sur toute séquence de caractères présente dans la valeur de `$IFS`.
Par défaut, il s'agit de l'espace, de la tabulation et du saut de ligne.

On peut le voir en action avec une boucle shell :

```bash
sentence="The quick brown fox jumps."
i=0
for word in "$sentence"; do echo "$((++i)) $word"; done
# ..........^.........^
```
affiche
```none
1 The quick brown fox jumps.
```

Mais sans guillemets :

```bash
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
affiche
```none
1 The
2 quick
3 brown
4 fox
5 jumps.
```

Voyons cela avec une valeur différente de `$IFS` :

```bash
csv="first,second,third"
IFS=","
for word in $csv; do echo "$word"; done
```
affiche
```none
first
second
third
```

#### Désactiver le découpage en mots

Une technique pour désactiver le découpage en mots consiste à définir `$IFS` sur une _string_ vide

```bash
sentence="The quick brown fox jumps."
IFS=    # or explicitly, IFS=""
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
affiche
```none
1 The quick brown fox jumps.
```

Cependant, laisser les variables sans guillemets n'est pas recommandé, à moins de désactiver aussi l'expansion des noms de fichiers.
On verra comment faire cela plus bas.

### Expansion des noms de fichiers

Les motifs _glob_ sont utilisés pour exprimer un motif concis permettant de faire correspondre un ensemble de fichiers.
Par exemple, tu peux faire correspondre tous les fichiers Markdown d'un répertoire avec `*.md`.
Les [motifs glob][glob] existent depuis l'invention d'Unix.

Les caractères génériques _glob_ sont :

* `*` correspond à zéro ou plusieurs caractères quelconques,
* `?` correspond exactement à un caractère quelconque,
* `[...]` correspond exactement à un caractère parmi l'ensemble des caractères listés entre les crochets.

   ~~~~exercism/advanced
   <details><summary>
   Il y a plein de détails sur les jeux de caractères.
   Clique ici pour les afficher.
   </summary>

    * `[abc]` correspond exactement à un caractère qui est soit un `a`, soit un `b`, soit un `c`.
        * pour inclure un crochet fermant littéral dans l'expression, fais-en le premier caractère après le crochet ouvrant (après un `^` optionnel)
            * `[][]` est un ensemble de caractères qui correspond à un crochet fermant ou ouvrant.
            * ou échappe-le avec un antislash : `[[\]]`
    * `[x-y]` correspond exactement à un caractère qui est dans la _plage_ de `x` à `y`
        * pour inclure un trait d'union littéral dans un ensemble de caractères, il doit être soit le premier caractère après le crochet ouvrant (après un `^` optionnel), soit le dernier caractère avant le crochet fermant.
            * `[-xy]` ou `[xy-]` correspondent chacun exactement à un caractère qui est un `-`, un `x` ou un `y`
            * ou échappe-le avec un antislash : `[x\-y]`
        * plusieurs plages peuvent être spécifiées, par exemple `[0-9A-Fa-f]` correspond à un chiffre hexadécimal
    * `[^abc]` correspond exactement à un caractère qui n'est **PAS** un `a`, un `b` ou un `c`,
    * `[^x-y]` correspond exactement à un caractère qui n'est **PAS** dans la plage de `x` à `y`
    * `[[:character_class:]]` correspond à un caractère qui appartient à la « character_class » nommée
        * les classes de caractères disponibles sont : 
            * `lower` -- lettres minuscules
            * `upper` -- lettres majuscules
            * `alpha` -- lettres
            * `digit` -- chiffres
            * `alnum` -- lettres et chiffres
            * `space` -- espaces blancs
            * `blank` -- espaces blancs horizontaux (espace et tabulation)
            * `xdigit` -- chiffres hexadécimaux
            * `word` -- caractères autorisés dans un identifiant (lettres, chiffres, tiret bas)
            * `punct` -- ponctuation
            * `cntrl` -- caractères de contrôle
            * `graph` -- caractères « visibles »
            * `print` -- caractères visibles plus l'espace
        * ils peuvent être combinés :
            * la classe `[[:alpha:]]` est constituée de `[[:lower:][:upper:]]`
            * la classe `[[:alnum:]]` est constituée de `[[:alpha:][:digit:]]`
            * la classe `[[:word:]]` est constituée de `[[:alnum:]_]`
            * le tiret bas (octal 137) est à la fois `[[:word:]]` et `[[:punct:]]`
            * la classe `[[:graph:]]` est constituée de `[[:alnum:][:punct:]]`
            * la classe `[[:print:]]` est constituée de `[[:graph:] ]` -- juste l'espace (octal 040), pas d'autre espace blanc.
   </details>

#### Itérer sur une liste de fichiers

Tu peux itérer sur une liste de fichiers avec une boucle `for`

```bash
for file in *.csv; do
    do_something_with "$file"
done
```

Note que la variable `"$file"` est entre guillemets.
Le motif glob peut renvoyer des fichiers dont le nom contient des espaces.
On doit mettre la variable entre guillemets pour que la commande `do_something_with` reçoive exactement un argument, le nom du fichier.

#### Les motifs glob ne sont pas des expressions régulières

Les motifs glob **ne sont pas** des expressions régulières.

* correspondre exactement à un caractère
   * regex `.`
   * glob `?`
* correspondre à zéro ou plusieurs caractères
   * regex `.*`
   * glob `*`
        * le motif glob `.*` signifie « faire correspondre un nom de fichier dont le premier caractère est un point littéral suivi de zéro ou plusieurs caractères quelconques ».
* correspondre à un ou plusieurs caractères
   * regex `.+`
   * glob `?*`
* les ensembles de caractères regex et glob se comportent de la même façon.

#### Mise entre guillemets et expansion des noms de fichiers

Il y a des moments où tu veux supprimer l'expansion des noms de fichiers.
La gestion des entrées utilisateur est l'un de ces moments.
Considère cet extrait de code

```bash
read -p "Enter something: " user_input
echo $user_input
```

Si l'utilisateur saisit un astérisque (`*`), qu'est-ce qui sera affiché ? 
La liste des fichiers dans le répertoire courant.
Ce n'est probablement pas ce que tu veux faire.

Un autre exemple est de passer des motifs comme arguments à des programmes qui attendent des motifs.
Le programme `tr` est souvent utilisé pour la manipulation de texte. Pour mettre en minuscules la valeur d'une variable, tu peux faire ceci :

```bash
var="My Puppet"
echo "$var" | tr '[:upper:]' '[:lower:]'
```
affiche
```none
my puppet
```

Une erreur courante est d'oublier de mettre les arguments de `tr` entre guillemets : `tr [:upper:] [:lower:]`

~~~~exercism/caution
Pourquoi est-ce un problème ? 
Les motifs glob sans guillemets seront expansés en la liste des fichiers correspondants.
Supposons que la personne qui utilise ton script ait des fichiers nommés `p`, `u` et `w` dans le répertoire courant :

```bash
touch p u w
var="My Puppet"
echo "$var" | tr [:upper:] [:lower:]
```

Cela produit une erreur !

Le motif `[:upper:]` sans guillemets correspond à n'importe lequel de `:`, `u`, `p`, `e` ou `r`.
Le motif `[:lower:]` sans guillemets correspond à n'importe lequel de `:`, `l`, `o`, `w`, `e` ou `r`.
Bash fait correspondre les fichiers `p` et `u` au premier motif, et le fichier `w` au second motif, et `tr` est invoqué comme

```bash
echo "$var" | tr p u w
```

Et ce n'est pas le bon nombre d'arguments pour `tr`.
~~~~

#### Désactiver l'expansion des noms de fichiers

Tu peux utiliser la commande [`set`][set] pour désactiver l'expansion des noms de fichiers.

```bash
echo *      # prints a list of files
set -f      # disable filename expansion
echo *      # prints a literal asterisk
set +f      # enable filename expansion
```

#### Contrôler l'expansion des noms de fichiers

Il existe plusieurs paramètres pour la commande intégrée [`shopt`][shopt] qui contrôlent le fonctionnement de l'expansion des noms de fichiers.
Quelques-uns intéressants sont :

* `shopt -s nocaseglob` -- effectuer une correspondance insensible à la casse
* `shopt -s extglob` -- activer les motifs étendus
* `shopt -s nullglob` -- si aucun fichier ne correspond, remplacer le motif par rien.
   Le comportement par défaut est de laisser le motif en place comme une _string_ littérale.
