# Introduction

En Factor, les caractères sont des entiers, à savoir des points de code Unicode, donc les comparaisons numériques `<`, `>`, `=` donnent directement un ordre sensible à la casse. Le vocabulaire [`unicode`][unicode] apporte des prédicats qui tiennent compte d'Unicode et la conversion de casse d'un seul caractère.

## Prédicats sur les caractères

```
LETTER?  ( c -- ? )    ! uppercase letter
letter?  ( c -- ? )    ! lowercase letter
Letter?  ( c -- ? )    ! letter, either case
digit?   ( c -- ? )    ! decimal digit
digit>   ( c -- n )    ! the integer value of a digit char
blank?   ( c -- ? )    ! whitespace
```

```factor
USING: unicode ;

CHAR: A LETTER? .    ! => t
CHAR: a letter? .    ! => t
CHAR: 7 digit?  .    ! => t
CHAR: 7 digit>  .    ! => 7
```

## Conversion de casse

`ch>upper` et `ch>lower` changent la casse d'un seul caractère. Au niveau d'une _string_, `>upper` et `>lower` les appliquent à tous ses caractères.

```factor
CHAR: a ch>upper .   ! => 65   (which is CHAR: A)
"Hello" >upper .     ! => "HELLO"
```

`capitalize` met toute une _string_ en minuscules, puis passe son premier caractère en majuscule, ce qui donne la casse de titre d'un seul mot :

```factor
"hELLO" capitalize .   ! => "Hello"
```

## Littéraux de caractères

`CHAR: A` s'analyse en le point de code entier de `A`. Pour les caractères nommés, utilise les noms `space`, `tab`, `\n`, etc. :

```factor
CHAR: A .        ! => 65
CHAR: space .    ! => 32
CHAR: \n .       ! => 10
```

## Symboles

Quand un mot doit renvoyer une étiquette plutôt qu'une valeur, par exemple `yes`/`no`/`maybe` au lieu d'un booléen, déclare chaque étiquette comme un *symbole*. Un symbole est un mot qui se pousse lui-même lorsqu'on l'appelle, et deux symboles ne se comparent égaux que lorsqu'ils portent le même nom.

```factor
USING: kernel ;

SYMBOLS: yes no maybe ;

yes .    ! => yes
yes yes = .    ! => t
yes no = .     ! => f
```

`SYMBOL: name` en déclare un ; `SYMBOLS: a b c ;` en déclare plusieurs.
