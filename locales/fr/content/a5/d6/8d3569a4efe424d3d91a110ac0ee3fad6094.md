# Introduction

La plupart des mots de séquence que tu as vus renvoient de *nouvelles* séquences et laissent leurs entrées intactes : `suffix`, `reverse`, `map`, etc. Mais les tableaux et les vecteurs prennent aussi en charge la **mutation sur place**, et les deux apparaissent quand tu veux enregistrer un état qui change au fil du temps.

## Deux variétés de séquence mutable

- **Les tableaux** (`{ … }`) ont une longueur fixe. `<array> ( n elt -- array )` (dans [`arrays`][arrays]) construit un nouveau tableau de longueur `n` rempli de copies de `elt`.
- **Les vecteurs** (`V{ … }`) grandissent et rétrécissent. Utilise `V{ } clone` pour en obtenir un nouveau vide ; `<vector> ( n -- vector )` (dans [`vectors`][vectors]) préalloue la capacité pour `n` éléments.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## Modifier un emplacement

Ces deux mots fonctionnent sur l'un ou l'autre type de séquence : tous les deux attendent la séquence après l'indice :

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth` affecte une valeur ; `change-nth` applique une _quotation_ à l'élément à la position `n`. Ces deux mots de [`sequences`][sequences] ne renvoient rien sur la pile : la mutation est l'effet.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## Agrandir et rétrécir

Ces trois mots n'ont de sens que sur les vecteurs, car un tableau ne peut pas changer de longueur :

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## Du vecteur au tableau

Quand tu as construit un vecteur et que tu veux renvoyer un tableau de longueur fixe, `>array ( seq -- array )` (dans [`arrays`][arrays]) renvoie un nouveau tableau avec les mêmes éléments :

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone` : garder un instantané

La mutation modifie la séquence sur place. Si un appelant te passe une séquence et que tu t'apprêtes à la modifier, `clone` (dans [`kernel`][kernel]) te donne une copie indépendante toute neuve, pour que la vision de l'appelant ne se décale pas sous ses pieds :

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

La même précaution vaut pour `V{ }` et les autres littéraux vides. Dans certains langages, `[]` ou `vec![]` alloue un nouveau conteneur à chaque évaluation de l'expression. En Factor, le littéral `V{ }` écrit dans ton code source est *un seul* objet, partagé par tous les sites d'appel qui le mentionnent. Si tu fais un `push` directement sur `V{ }`, l'appel suivant voit les restes. `V{ } clone` crée la copie neuve que tu veux presque toujours.
