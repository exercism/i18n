# Introduction

## Comparaisons

Python prend en charge les opérateurs de comparaison de base suivants :

| Opérateur | Opération                      | Description                                                                             |
| --------- | ------------------------------ | --------------------------------------------------------------------------------------- |
| `>`       | « supérieur à »                | `a > b` est `True` si `a` est **strictement** supérieur en valeur à `b`                  |
| `<`       | « inférieur à »                | `a < b` est `True` si `a` est **strictement** inférieur en valeur à `b`                  |
| `==`      | « égal à »                     | `a == b` est `True` si `a` est **strictement** égal à `b` en valeur                      |
| `>=`      | « supérieur ou égal à »        | `a >= b` est `True` si `a > b` OU `a == b` en valeur                                     |
| `<=`      | « inférieur ou égal à »        | `a <= b` est `True` si `a < b` ou `a == b` en valeur                                     |
| `!=`      | « différent de »               | `a != b` est `True` si `a == b` est `False`                                              |
| `is`      | « identité »                   | `a is b` est `True` si **_et seulement si_** `a` et `b` sont le même _objet_              |
| `is not`  | « identité niée »              | `a is not b` est `True` si `a` et `b` ne sont **pas** le même _objet_                     |
| `in`      | « test d'appartenance »        | `a in b` est `True` si `a` est un membre, un sous-ensemble ou un élément de `b`          |
| `not in`  | « test de non-appartenance »   | `a not in b` est `True` si `a` n'est pas un membre, un sous-ensemble ou un élément de `b` |

Ils ont tous la même priorité (_plus élevée que celle des [opérations booléennes][boolean operations], mais plus faible que celle des opérations arithmétiques ou binaires_).

## Comparaison entre différents types de données

Des objets de types différents (_sauf les types numériques_) ne sont jamais considérés comme égaux par défaut.
Des instances non identiques d'une `class` ne seront _**pas**_ non plus considérées comme égales, à moins que la `class` ne définisse des méthodes spéciales de [comparaison enrichie][rich comparisons] qui personnalisent le comportement de comparaison par défaut de `object`.
La personnalisation via `rich comparisons` sera abordée dans un exercice ultérieur.
Pour (beaucoup) plus de détails sur ce sujet, consulte les [comparaisons de valeurs][value comparisons] dans la documentation Python.

Les types numériques constituent (en grande partie) une exception à cette règle d'appariement des types.
Un `integer` **peut** être considéré comme égal à un `float` (_ou un [`octal`][octal] égal à un [`hexadecimal`][hex]_), tant que les types peuvent être convertis implicitement pour la comparaison.

Pour les autres types numériques de la bibliothèque standard de Python ([complex][complex numbers], [decimal][decimal numbers], [fractions][rational numbers]), les opérateurs de comparaison sont définis là où ils « ont un sens » (_là où la conversion implicite ne change pas le résultat_), mais lèvent une `TypeError` si les objets sous-jacents ne peuvent pas être convertis précisément pour la comparaison.
Pour plus d'informations sur les règles que Python utilise pour la _conversion numérique_, consulte les [conversions arithmétiques][arithmetic conversions] dans la documentation Python.

```python
>>> import fractions

# A string cannot be converted to an int.
>>> 17 == '17'
False

# An int can be converted to float for comparison.
>>> 17 == 17.0
True

# The fraction 6/3 can be converted to the int 2
# The int 2 can be converted to 0b10 in binary.
>>> 6/3 == 0b10
True

# An int can be converted to a complex number with a 0 imaginary part.
>>> 17 == complex(17)
True

# The fraction 2/5 can be converted to the float 0.4
>>> 0.4 == 2/5
True

>>> complex(2/5, 1/2) == complex(0.4, 0.5)
True
```

Toute comparaison ordonnée entre un nombre et un type `NaN` (_not a number_, c'est-à-dire « pas un nombre ») est `False`.
Un effet de bord déroutant de la définition de `NaN` en Python est que `NaN` n'est jamais égal à `NaN`.

```python
>>> x = float('NaN')

>>> 3 < x
False

>>> x < 3
False

# NaN never compares equal to NaN
>>> x == x
False
```

## Comparer des _strings_

Contrairement aux nombres, les _strings_ (`str`) sont comparés selon l'[ordre lexicographique][lexographic order], en utilisant leurs points de code Unicode individuels (_le résultat du passage de chaque point de code du `str` à la fonction native [`ord()`][ord], qui renvoie un `int`_).
Si tous les points de code des deux _strings_ correspondent et sont _**dans le même ordre**_, les deux _strings_ sont considérés comme égaux.
Cette comparaison se fait par paires : le premier avec le premier, le deuxième avec le deuxième, etc.
En Python 3.x, `str` et `bytes` ne peuvent pas être convertis ni comparés directement.

```python
>>> 'Python' > 'Rust'
False

>>> 'Python' > 'JavaScript'
True

# Examples with Mandarin.
# hello < goodbye
>>> '你好' < '再见'
True

# ord() of first characters
>>> ord('你'), ord('再')
(20320, 20877)

# ord() of second characters
>>> ord('好'), ord('见')
(22909, 35265)

# And with Korean words.
# Pretty < beautiful.
>>> '예쁜' < '아름다운'
False

>>> ord('예'), ord('아')
(50696, 50500)
```

## Chaînage des comparaisons

Les opérateurs de comparaison peuvent être chaînés _arbitrairement_, c'est-à-dire qu'ils peuvent être utilisés dans n'importe quelle combinaison, de n'importe quelle longueur.
Note que l'évaluation d'une expression se fait de `left` à `right`.

Par exemple, `x < y <= z` équivaut à `x < y` `and` `y <= z`, sauf que `y` n'est évalué **qu'une seule fois**.
Dans les deux cas, `z` n'est **pas du tout** évalué lorsque `x < y` s'avère être `False`.
C'est ce qu'on appelle souvent `short-circuit evaluation` : l'évaluation s'arrête dès que la valeur de vérité de l'expression a déjà été déterminée.

Le `Short circuiting` est pris en charge par divers opérateurs booléens et fonctions, ainsi que par le chaînage de comparaisons en Python.
Contrairement à de nombreux autres langages de programmation, notamment `C`, `C++`, `C#` et `Java`, les expressions chaînées comme `a < b < c` en Python ont une [interprétation mathématique][three way boolean comparison] et une priorité conventionnelles.

```python
>>> x = 2
>>> y = 5
>>> z = 10

>>> x < y < z
True

>>> x < y > z
False

>>> x > y < z
False
```

## Comparer l'identité des objets

Les opérateurs `is` et `is not` testent l'[_identité_][object identity] d'un objet, par opposition à sa _valeur_.
L'identité d'un objet ne change jamais après sa création et peut être obtenue à l'aide de la fonction [`id()`][id function].

`<apple> is <orange>` est évalué à `True` si _**et seulement si**_ `id(<apple>)` == `id(<orange>)`.
`<apple> is not <orange>` donne le résultat inverse.

En raison de leur statut de singleton, `None` et `NotImplemented` doivent toujours être comparés à des éléments en utilisant `is` et `is not`.
Consulte la documentation de référence de Python sur les [comparaisons de valeurs][value comparisons none] et le [PEP8][pep8 programming recommendations] pour plus de détails sur cette convention.

```python
>>> my_fav_numbers = [1, 2, 3]

>>> your_fav_numbers = my_fav_numbers

>>> my_fav_numbers is your_fav_numbers
True

# The returned id will differ by system and python version.
>>> id(my_fav_numbers)
4517478208

# your_fav_numbers is only an alias pointing to the original my_fav_numbers object.
# Assigning a new name does not create a new object.
>>> id(your_fav_numbers)
4517478208


>>> my_fav_numbers is not your_fav_numbers
False

>>> my_fav_numbers is not None
True

>>> my_fav_numbers is NotImplemented
False
```

## Comparaisons d'appartenance

Les opérateurs `in` et `not in` testent l'_appartenance_.
`<fish> in <soup>` est évalué à `True` si `<fish>` est un membre de `<soup>` (_si `<fish>` est un sous-ensemble de `<soup>` ou est contenu dans `<soup>`_), et à `False` sinon.
`<fish> not in <soup>` renvoie la négation, c'est-à-dire l'_opposé de_ `<fish> in <soup>`.

Pour les types _string_ et _bytes_, `<name> in <fullname>` vaut `True` _**si et seulement si**_ `<name>` est une sous-chaîne de `<fullname>`.

```python
# A set of lucky numbers.
>>> lucky_numbers = {11, 22, 33}
>>> 22 in lucky_numbers
True

>>> 44 in lucky_numbers
False

# A dictionary of employee information.
>>> employee = {'name': 'John Doe', 
                'id': 67826, 'age': 33, 
                'title': 'ceo'}

# Checking for the membership of certain keys.
>>> 'age' in employee
True

>>> 33 in employee
False

>>> 'lastname' not in employee
True

# Checking for substring membership
>>> name = 'Super Batman'
>>> 'Bat' in name
True

>>> 'Batwoman' in name
False
```
