# À propos

Les ressources qui détiennent un état du système d'exploitation (descripteurs de fichiers, _sockets_, verrous) doivent être libérées de manière *garantie*, même lorsqu'une exception déroule la pile. Le vocabulaire [`destructors`][destructors] de Factor fournit un petit framework pour cela, et la plupart des ressources intégrées (`<file-reader>`, `<file-writer>`, les _sockets_, …) s'y branchent déjà.

## La classe et le générique

Une classe s'y intègre en étendant `disposable` et en implémentant `dispose*` :

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )` alloue le tuple *et* l'enregistre auprès de la portée de destructeurs courante, si bien qu'une exception entre l'allocation et le point sûr suivant ne peut pas provoquer de fuite de la ressource. Le framework garantit que `dispose*` s'exécute **au plus une fois** par objet : des appels répétés à `dispose` sont sans effet.

## Les appelants publics utilisent `dispose`

| mot              | effet                                        |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )` : libère la ressource ; sans danger même appelé deux fois    |
| `with-disposal`   | `( disposable quot -- )` : encadre une seule ressource |
| `with-destructors`| `( quot -- )` : ouvre une portée de registre         |
| `&dispose`        | `( obj -- obj )` : libère à la sortie normale *ou* en cas d'échec |
| `|dispose`        | `( obj -- obj )` : libère uniquement lorsque la portée se déroule |

`with-disposal` est la forme pour une seule ressource. Pour plusieurs ressources, ouvre une portée `with-destructors` et enregistre chaque acquisition avec `&dispose` (on veut toujours la libérer) ou `|dispose` (libération uniquement en cas d'échec : le chemin de réussite la conserve).

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup` est la primitive de base

Pour un try/finally ponctuel sans registre, [`cleanup`][cleanup] (du vocabulaire `continuations`) est le mot de plus bas niveau :

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` est strictement plus puissant (le registre peut grossir à l'exécution), mais `cleanup` est le choix naturel quand l'appariement acquisition/libération est fixe et local.
