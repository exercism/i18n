# À propos

Les _behaviours_ permettent de définir des interfaces (des ensembles de fonctions et de macros) dans un module de _behaviour_, que différents modules de _callback_ pourront ensuite implémenter. Grâce à cette interface commune, ces modules de _callback_ peuvent être utilisés indifféremment.

~~~~exercism/note
Remarque l'orthographe britannique de « behaviours ».
~~~~

## Définis des _behaviours_

Pour définir un _behaviour_, on crée un nouveau module et on y spécifie une liste de fonctions qui font partie de l'interface voulue. Chaque fonction doit être définie à l'aide de l'attribut de module `@callback`. La syntaxe est identique à celle d'une [spécification de type de fonction][concept-typespecs] (`@spec`). Il faut préciser un nom de fonction, une liste de types d'arguments et tous les types de retour possibles.

```elixir
defmodule Countable do
  @callback count(collection :: any) :: pos_integer
end
```

## Implémente des _behaviours_

Pour ajouter un _behaviour_ existant à notre module (créer un module de _callback_), on utilise l'attribut de module `@behaviour`. Sa valeur doit être le nom du module de _behaviour_ que l'on ajoute.

Ensuite, il faut définir toutes les fonctions (_callbacks_) requises par ce module de _behaviour_. Si l'on implémente le _behaviour_ de quelqu'un d'autre, comme les _behaviours_ `Access` ou `GenServer` intégrés à Elixir, on trouvera la liste de tous les _callbacks_ de ce _behaviour_ dans la documentation sur [hexdocs.pm][hexdocs].

Un module de _callback_ n'est pas limité à l'implémentation des seules fonctions qui font partie de son _behaviour_. Un même module peut aussi implémenter plusieurs _behaviours_.

Pour indiquer de quel _behaviour_ vient chaque fonction, on utilise l'attribut de module `@impl` devant chaque fonction. Sa valeur doit être le nom du module de _behaviour_ qui définit ce _callback_.

```elixir
defmodule BookCollection do
  @behaviour Countable

  defstruct [:list, :owner]

  @impl Countable
  def count(collection) do
    Enum.count(collection.list)
  end

  def mark_as_read(collection, book) do
    # other function unrelated to the Countable behaviour
  end
end
```

## Implémentations par défaut des _callbacks_

Lorsque l'on définit un _behaviour_, il est possible de fournir une implémentation par défaut d'un _callback_. Cette implémentation doit être définie dans l'expression _quoted_ de la macro `__using__/1`. Pour que les utilisateurs du module de _behaviour_ puissent redéfinir l'implémentation par défaut, on appelle la macro `defoverridable/1` après l'implémentation de la fonction. Elle accepte une liste de mots-clés dont les clés sont des noms de fonctions et les valeurs des arités de fonctions.

```elixir
defmodule Countable do
  @callback count(collection :: any) :: pos_integer

  defmacro __using__(_) do
    quote do
      @behaviour Countable
      def count(collection), do: Enum.count(collection)
      defoverridable count: 1
    end
  end
end
```

Note que définir des fonctions à l'intérieur de `__using__/1` est déconseillé pour toute autre raison que définir des implémentations de _callback_ par défaut, mais tu peux toujours définir des fonctions dans un autre module et les importer dans la macro `__using__/1`.
