# Vérification

L'usage principal de [configlet](/docs/building/configlet) est la vérification : s'assurer que les fichiers de configuration d'un parcours sont correctement structurés, tant sur le plan syntaxique que sémantique. Un parcours mal configuré risque de ne pas se synchroniser correctement, de s'afficher de façon erronée sur le site ou d'offrir une expérience utilisateur perfectible ; les garde-fous de configlet jouent donc un rôle important dans le maintien de l'intégrité d'Exercism.

## Utilisation

La commande `lint` permet de vérifier un parcours.

```
configlet [global-options] lint [command-options]

Global options:
  -h, --help                   Show this help message and exit
      --version                Show this tool's version information and exit
  -t, --track-dir <dir>        Specify a track directory to use instead of the current directory
  -v, --verbosity <verbosity>  The verbosity of output. Allowed values: q[uiet], n[ormal], d[etailed]
```

## Règles

Voici les règles de vérification appliquées.

### Règle : les fichiers requis sont présents

Le _linter_ doit vérifier que tous les fichiers requis sont présents. Les fichiers non spécifiques aux exercices qui doivent être présents sont :

- `config.json`
- `docs/ABOUT.md`
- `docs/INSTALLATION.md`
- `docs/LEARNING.md`
- `docs/RESOURCES.md`
- `docs/SNIPPET.txt`
- `docs/TESTS.md`
- `exercises/shared/.docs/help.md`
- `exercises/shared/.docs/tests.md`

Les fichiers spécifiques aux exercices d'apprentissage qui doivent être présents sont :

- `exercises/concept/<slug>/.docs/hints.md`
- `exercises/concept/<slug>/.docs/instructions.md`
- `exercises/concept/<slug>/.docs/introduction.md`
- `exercises/concept/<slug>/.meta/config.json`

Il y aura une liste similaire pour les exercices d'entraînement, mais les spécifications correspondantes n'ont pas encore été définies.

Chaque concept listé dans `config.json` doit posséder les fichiers suivants :

- `concepts/<slug>/about.md`
- `concepts/<slug>/introduction.md`
- `concepts/<slug>/links.json`

## Glossaire

1. **Chaîne non vide** : une chaîne qui contient au moins un caractère autre qu'un espace.
2. **Chaîne en `kebab-case`** : une chaîne qui ne contient que des caractères de l'intervalle `[a-z0-9]`, éventuellement séparés par des tirets (par ex. « two-fer »). Elle doit correspondre à l'expression régulière : `^[a-z0-9]+(-[a-z0-9]+)*$`
3. **Chaîne en `Title Case`** : une chaîne non vide qui suit les [règles du Chicago Manual of Style](https://en.wikipedia.org/wiki/Title_case#Chicago_Manual_of_Style) ci-dessous :
   - Mets une majuscule au premier et au dernier mot des titres et des sous-titres.
   - Mets une majuscule aux mots « majeurs » (noms, pronoms, verbes, adjectifs, adverbes et certaines conjonctions).
   - Laisse en minuscules les conjonctions _and_, _but_, _for_, _or_ et _nor_.
   - Laisse en minuscules les articles _the_, _a_ et _an_.
   - Laisse en minuscules les prépositions, quelle que soit leur longueur, sauf lorsqu'elles sont accentuées, employées comme adverbes ou adjectifs, ou utilisées comme conjonctions.
   - Laisse en minuscules les mots _to_ et _as_.
   - Laisse en minuscules la seconde partie des noms d'espèces latins.
4. **Chaîne en `Sentence Case`** : une chaîne non vide qui suit les [règles](https://en.wikipedia.org/wiki/Letter_case#Sentence_case) ci-dessous :
   - Mets une majuscule au premier mot de la phrase, ainsi qu'aux noms propres et aux autres mots lorsque qu'une règle plus spécifique l'exige.
5. **Motif `files` valide** : une chaîne non vide¹ qui désigne l'emplacement d'un fichier utilisé dans un exercice, relativement au répertoire de l'exercice. Un motif peut utiliser l'un des espaces réservés suivants :

   - `%{kebab_slug}` : le slug d'exercice en `kebab-case` (par ex. `bit-manipulation`)
   - `%{snake_slug}` : le slug d'exercice en `snake_case` (par ex. `bit_manipulation`)
   - `%{camel_slug}` : le slug d'exercice en `camelCase` (par ex. `bitManipulation`)
   - `%{pascal_slug}` : le slug d'exercice en `PascalCase` (par ex. `BitManipulation`)

6. **Chaîne UUID de version 4 unique** : une chaîne qui remplit toutes les conditions suivantes :

   - Elle n'existe qu'une seule fois dans le fichier `config.json` au niveau du parcours, pour un parcours Exercism donné
   - Elle n'existe pas dans le fichier `config.json` au niveau du parcours d'aucun autre parcours Exercism
   - Elle n'existe dans aucun fichier `canonical-data.json` de https://github.com/exercism/problem-specifications
   - Elle n'existe nulle part ailleurs sur Exercism
   - Elle correspond à l'expression régulière :

   ```
   ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
   ```

   Par exemple, l'UUID ci-dessous a la forme correcte :

   ```
   d334ffe3-657e-4725-a950-290b284b6d9f
   ```

   Tu peux exécuter `configlet uuid` pour générer un UUID approprié.

7. **`tag` d'analyseur valide** : une chaîne non vide¹ au format `<category>:<thing>`.
   La valeur de `<category>` doit être l'une des suivantes :

- `paradigm` (par ex. `paradigm:functional`)
- `technique` (par ex. `technique:recursion`)
- `construct` (par ex. `construct:bitwise-and`)
- `uses` (par ex. `uses:DateTime.add_seconds`)

La valeur de `<thing>` doit être une chaîne non vide¹.
