# À propos

Lorsqu'on fait du filtrage par motifs sur une valeur en Gleam, on doit s'assurer que les motifs couvrent toutes les valeurs possibles du type, sinon le code ne se compile pas.

Cette fonction doit être rejetée, car elle ne gère pas le cas où le tableau est vide :

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

La plupart du temps, dans un programme Gleam, on veut gérer tous les cas possibles, mais dans certains programmes, comme les prototypes ou les scripts rapides, on peut vouloir se concentrer uniquement sur le cas nominal sans écrire de code pour les autres cas. C'est là qu'intervient le `let assert` de Gleam.

Avec les assertions `let`, un motif peut ne correspondre qu'à une partie des valeurs possibles d'un type, et si le motif ne correspond pas à une valeur, le programme plante. Avec `let assert`, on peut écrire la fonction ci-dessus comme ceci :

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Les bibliothèques Gleam ne devraient jamais utiliser d'assertions `let`, car elles peuvent faire planter le programme ; elles devraient plutôt utiliser le type `Result` et laisser le développeur de l'application décider comment gérer les erreurs.
