# À propos

Pour comprendre [`Box`][box], il est utile de comprendre ce que sont [la pile et le tas][stack and heap].

La pile est une zone de mémoire qui fonctionne comme un tampon dernier entré, premier sorti (LIFO). Empiler des données sur la pile est très rapide, et les dépiler l'est tout autant.
Ces données peuvent être des variables ou des adresses de fonctions, mais leur taille doit être fixe et connue au moment de la compilation.

Si la taille des données est inconnue au moment de la compilation, ou si elle est susceptible de changer, il faut alors les allouer sur le tas. Le processus d'allocation doit trouver
dans le tas un espace assez grand pour stocker les données, écrire ces données dans le tas, puis empiler sur la pile l'adresse mémoire de ces données, ce qui prend
nettement plus de temps que de simplement placer des données sur la pile. Récupérer des données depuis le tas est un peu plus lent, car il faut passer par l'adresse sur la
pile et la suivre jusqu'à l'emplacement des données dans le tas.

`Box` est un pointeur intelligent qui alloue des données sur le tas. L'adresse se trouve sur la pile et pointe vers les données du tas. Une [raison][reasons] d'utiliser `Box`
est de placer des données sur le tas lorsque tu as un type dont la taille ne peut pas être connue à la compilation et que tu veux utiliser une valeur de ce type dans un contexte qui exige
une taille exacte. Un cas d'usage concret est lorsque tu as plusieurs structures que tu veux manipuler de la même manière via un trait qu'elles implémentent toutes, comme
dans l'exemple ci-dessous.

Imaginons que l'on ait deux structures. Chaque structure représente quelque chose de potentiellement agaçant. On peut faire implémenter à chaque structure un trait Annoyance, comme ceci

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

Maintenant, imaginons que l'on veuille une fonction qui nous renvoie une Annoyance en fonction du moment de la journée qu'on lui passe. On peut d'abord essayer ceci, et l'on découvre que ça ne compile pas

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

Le compilateur, dans toute sa bienveillance, nous dit exactement quoi faire : renvoyer un objet trait encapsulé dans une `Box`. Si tu ne sais pas ce qu'est un objet trait,
on peut le décrire simplement comme une manière de renvoyer un objet précis via un [_dispatch_ dynamique][dynamic dispatch] depuis une fonction qui pourrait renvoyer n'importe quel objet
implémentant un trait donné. Comme nous avons besoin de _dispatch_ dynamique, on peut essayer de simplement mettre un `dyn` devant le nom du trait et voir si ça passe.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

L'une des erreurs est que la taille de `dyn Annoyance` ne peut pas être connue à la compilation. C'est parce que `annoy_me` ne sait pas quel objet trait précis
elle va renvoyer avant d'être appelée. Les structures qui implémentent Annoyance peuvent avoir des champs différents et donc des tailles différentes. Et cela nous rappelle que
l'un des usages de `Box` concerne un type dont la taille ne peut pas être connue à la compilation. On essaie donc maintenant d'utiliser une valeur de retour encapsulée dans une `Box`, et on place les valeurs renvoyées
par l'expression `match` dans une `Box`, comme ceci

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

La signature de `Box` est `Box<T>`, où `T` représente le type précis à encapsuler, placé entre les chevrons, comme dans `Box<dyn Annoyance>` ci-dessus.

On peut consommer l'objet trait encapsulé comme ceci

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

ce qui affiche

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

Comme `my_annoyance` est de type `Box<dyn Annoyance>`, il faut la déréférencer depuis la `Box` à l'aide de l'opérateur de déréférencement `*`. Elle est ensuite référencée en tant que
`dyn Annoyance` pour que la fonction `be_annoying` puisse l'emprunter.

Une autre façon de l'implémenter serait de supprimer l'exigence selon laquelle le paramètre doit avoir une taille connue. Dans ce cas, la compilation créerait une fonction distincte
pour chaque variante d'Annoyance afin de permettre un _dispatch_ statique (un processus appelé [monomorphisation][monomorphization]), comme ceci

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

Encore une autre façon de l'implémenter serait que la fonction `be_annoying` accepte un `Box<dyn Annoyance>` et utilise une [conversion par déréférencement][deref coercion] pour éviter
d'avoir à déréférencer la `Box` manuellement. Cela transférerait la propriété de l'objet trait Annoyance à la fonction `be_annoying`. Il sortirait de la
portée à la fin de la fonction et ne serait plus disponible.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
