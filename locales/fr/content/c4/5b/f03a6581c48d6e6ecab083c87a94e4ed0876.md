# Tests

Exécute les tests avec :

```shell
corepack pnpm test
```

Assure-toi que ton code suit les bonnes pratiques et les conventions de style, comme le font les autres utilisateurs, avec ESLint, un outil qui effectue une analyse statique de ton code.
Parfois, ce genre d'outil te fait gagner du temps en détectant les fautes de frappe ou les erreurs bêtes dans ton code JavaScript :

```shell
corepack pnpm lint
```

Tu peux aussi lancer Jest en mode « watch », qui relancera automatiquement tes tests quand tu enregistres des modifications dans le code ou dans le module de test :

```shell
corepack pnpm watch
```

## Comprends les tests ignorés

La méthode `skip` indique à la suite de tests de ne pas exécuter un test ; cette fonction peut aussi être utilisée sous les alias : `it.skip(name, fn)`, `xit(name, fn)` ou `xtest(name, fn)`

- Pourquoi sont-ils ignorés ?

Pour permettre aux utilisateurs de se concentrer sur un test à la fois et de les activer un par un au fur et à mesure qu'ils font évoluer la solution.

- Comment les activer ?

Remplace `xtest` par `test`.

```javascript
test('title cased phrases', () => {
  expect(Acronyms.parse('Portable Network Graphics')).toEqual('PNG');
});
```

## Crée ton premier module JavaScript 2015

En général, les tests de ce parcours chargent ton implémentation en l'important comme un module JavaScript : `import { Bob } from './bob.js';`.
Tu as juste besoin d'exporter ton implémentation depuis le fichier référencé, `bob.js` :

```javascript
export function hey(message) {}
```

Tu trouveras plus d'informations sur les modules dans la [documentation de Babel](https://babeljs.io/docs/learn-es2015/#modules).
Pour faciliter le démarrage, il y a un fichier JavaScript _skeleton_ dans le répertoire.
