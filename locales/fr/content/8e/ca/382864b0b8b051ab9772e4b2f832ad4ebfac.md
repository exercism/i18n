# Tests

Chaque exercice fournit les tests unitaires et une recette de _build_ CMake. C'est à toi de fournir l'implémentation.
Chaque fichier de test est destiné à être lié à ton implémentation pour produire un exécutable en console qui lance les tests. L'exécution de l'exécutable de test affiche un message pour chaque test qui échoue et renvoie un statut de sortie non nul lorsque des tests échouent.

Le fichier de test porte le nom `<exercise>_test.f90` ; ainsi, pour l'exercice « Bob », le fichier contenant les tests est `bob_test.f90`. Chaque test comporte un commentaire qui le décrit, puis le test proprement dit, qui commence par `call assert_equal`, par exemple :

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Pour désactiver un test, il suffit de le mettre en commentaire avec un `'!'`, par exemple :

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Voici comment se déroule le travail sur chaque exercice :

* Créer le _build_ initial avec CMake
* Pour chaque test unitaire :
 * Corriger les erreurs de compilation pour que le test échoue.
 * Implémenter juste ce qu'il faut pour que le test passe.
 * Réécrire ton implémentation pour améliorer la lisibilité, réduire les duplications, etc.
 * Décommenter le test suivant


## Crée le _build_ initial avec CMake

Chaque exercice est accompagné d'un fichier `CMakeLists.txt` en plus des tests unitaires. Il contient la recette CMake toute prête qui se charge du _build_ à ta place. Tu ne devrais pas avoir besoin de modifier ce fichier. La recette fournie suppose que ton implémentation se trouve dans un fichier source portant le nom de l'exercice.

Par exemple, l'exercice « Bob » attend une implémentation dans le fichier `bob.f90`.

**Crée tes fichiers d'implémentation initiaux avant de lancer CMake.**
Si tu n'as pas le fichier `bob.f90` au moment de lancer CMake pour l'exercice « Bob », CMake générera une erreur indiquant que des fichiers sont introuvables.
**Ces fichiers peuvent être vides, mais ils doivent exister.**

Avec cette recette, CMake peut générer un projet adapté à ton environnement en exécutant `cmake -G` avec un générateur approprié et l'emplacement du répertoire de l'exercice. CMake générera un script de _build_ adapté à ton système d'exploitation. Pour garder ces fichiers générés séparés du code source de ton exercice, il est courant de créer un répertoire nommé `build` pour accueillir ces fichiers de _build_ générés, ainsi que le code compilé.

Cela permet de garder le dossier de ton exercice propre et bien rangé.

**Remarque : la première fois que `cmake` est appelé, [testlib](###-Testlib) sera téléchargé automatiquement. Le `testlib` est nécessaire au bon fonctionnement des tests unitaires.

Comme tu vas lancer CMake pour créer les instructions de _build_ de chaque exercice, tu voudras peut-être écrire un script bash (Linux/MacOS) ou un fichier batch (Windows) pour cette commande.

Une fois l'environnement de _build_ créé par CMake, tu peux compiler ton code avec la commande adaptée à ton environnement :

* Linux avec make : `make`
* Windows avec Visual Studio : sélectionne Build / Build Solution dans le menu.
* Windows avec MingW : `mingw32-make.exe`
* Windows avec nMake : `nmake.exe`
* MacOS avec Xcode : sélectionne Build dans la barre d'outils

Des exemples d'exécution de CMake pour différents environnements sont donnés ci-dessous.

### Linux\MacOS avec Make

Le nom du générateur pour CMake est `Unix Makefiles`.
En supposant que l'exercice courant soit `bob` et que l'on se trouve dans le dossier de l'exercice :

```
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

Cet exemple montre comment créer des fichiers vides pour l'implémentation avant de lancer CMake.

Tape simplement make dans le répertoire de _build_ pour compiler les tests. Cela devrait générer des erreurs de compilation. Une fois les erreurs corrigées, relance `make`. Quand toutes les erreurs de _build_ sont corrigées, lance les tests :

```
$ ctest -V
```
### Windows avec Visual Studio 2017

Le nom du générateur pour CMake est `Visual Studio 15`. Ce même générateur prend en charge toutes les éditions IDE de Visual Studio 2017 : Community, Professional et Enterprise. En supposant que l'exercice courant soit `bob` et que l'on se trouve dans le dossier de l'exercice :

```
> copy nul: bob.f90
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

Cet exemple montre comment créer des fichiers vides pour l'implémentation avant de lancer CMake.

### Testlib

Les tests dépendent d'une petite bibliothèque appelée `testlib`, téléchargée depuis github la première fois que le _build_ est configuré avec cmake.

Si le téléchargement échoue, il peut être effectué manuellement, par exemple :

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/TesterMain.f90
```
