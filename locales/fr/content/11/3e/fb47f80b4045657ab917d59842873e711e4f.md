# Introduction

Nous avons vu dans les concepts précédents que les types en Julia forment une hiérarchie, avec `Any` tout en haut.

Les types abstraits comme `Number` ont des sous-types, mais ne peuvent pas être instanciés eux-mêmes.
Donner à une variable un type abstrait _contraint_ ses valeurs à être n'importe quel sous-type de ce type abstrait.
Par exemple :

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Cela nous offre une première forme de souplesse pour contraindre les entrées acceptées.

Cependant, imaginons que l'on veuille qu'une variable accepte à la fois des entiers et des _strings_ ?
Ces types ne se trouvent pas dans la même branche de la hiérarchie.

On pourrait donner à la variable le type `Any`, ou le laisser par défaut, mais on perd alors tout contrôle sur les types autorisés.

Pour faire mieux, on dispose de la syntaxe `Union{ }`, avec deux types ou plus listés entre les accolades.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Un autre exemple utilise la même union de types dans la signature d'une fonction :

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

Ici, on a donné un nom au type, ce qui fournit un raccourci pratique, mais ce n'est pas strictement nécessaire.
La fonction `g(z::Union{Integer, String}) = z^3` se comporte de la même façon.

Nous aurons bien plus à dire sur les signatures de fonctions dans le concept de dispatch multiple.

## Les unions avec nothing

Plusieurs autres langages ont des types qui peuvent ou non contenir une valeur, avec des noms comme `Option`, `Nullable` ou `Maybe`.

Julia n'a pas de syntaxe spécifique pour cela, mais les unions de types généralisent la même idée.

Nous avons vu dans le concept `Nothingness` que Julia dispose de plusieurs façons de représenter l'absence de valeur, notamment `nothing` et `missing`.
L'une comme l'autre peut être incluse dans une union de types.

Par exemple, pour définir une sorte de liste chaînée, on a besoin d'un moyen de terminer la liste s'il n'y a plus de nœuds.
`Nothing` est le type dont l'unique valeur est `nothing`, et cette définition de Node permet de signaler la fin de la chaîne :

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

De même, `missing` peut servir de valeur de remplacement pour les valeurs absentes, en particulier dans les collections comme les vecteurs.
L'exemple ci-dessous est très artificiel, mais les valeurs manquantes sont courantes dans les jeux de données réels.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
