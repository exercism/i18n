# Instructions

Tu es l'officier de quart à bord d'un cotre qui traverse le détroit de Béring. Trois sources annoncent la position de chaque plaque de glace flottante et de chaque promontoire en vue :

- La **table à cartes** parle en directions de la boussole : `north`, `east`, `south`, `west`. Juste un cap, sans distance.
- Le **navigateur** parle en coordonnées *polaires* depuis le dernier point connu du cotre : une magnitude en milles marins, et un relèvement en degrés dans le sens horaire depuis le nord (donc `0` correspond au nord, `90` à l'est, `180` au sud et `270` à l'ouest).
- La **vigie en tête de mât** parle en coordonnées *relatives* : une distance vers l'avant, et l'un de `ahead`, `starboard`, `behind`, `port`. Les relèvements relatifs se mesurent par rapport au *cap actuel du navire* : le capitaine annonce ce cap sur la passerelle avant chaque quart.

Ton travail consiste à convertir ces trois formes dans un repère cartésien `(x, y)` commun afin que la carte puisse être tracée. Les relèvements sont en degrés ; `(0, 1)` correspond à un mille marin au nord, `(1, 0)` à un mille marin à l'est.

## 1. Le modèle de données, et la conversion en cartésien pour les points cardinaux

Commence par poser les éléments que tout l'exercice partage :

- Définis trois tuples : `cardinal` (un slot, `direction`), `polar` (les slots `magnitude` et `bearing`), et `relative` (les slots `distance` et `bearing`).
- Déclare les symboles de cap avec `SYMBOLS:` : `north`, `east`, `south`, `west`, `ahead`, `starboard`, `behind`, `port`.
- Déclare une variable dynamique `heading` avec `SYMBOL:` (la tâche 3 l'utilise).
- Déclare deux mots génériques : `GENERIC: >cartesian ( direction -- x y )` et `GENERIC: flip ( direction -- direction' )`. Tu ajoutes leurs méthodes dans les tâches suivantes.

Ensuite, ajoute la méthode `M: cardinal` de `>cartesian`, qui renvoie le vecteur unitaire de la direction nommée.

```factor
T{ cardinal { direction north } } >cartesian . .
! => 1
! => 0
! (top of stack is `y`, just below it is `x`)
```

## 2. La conversion en cartésien pour les coordonnées polaires

Ajoute une méthode `M: polar` à `>cartesian` qui convertit la forme polaire en `(x, y)` :

```
x = magnitude * sin(bearing-in-radians)
y = magnitude * cos(bearing-in-radians)
```

```factor
T{ polar { magnitude 10 } { bearing 90 } } >cartesian . .
! => 0   (close to zero — the cosine of π/2 isn't exactly 0 in floats)
! => 10
```

## 3. La conversion en cartésien pour les coordonnées relatives

Ajoute une méthode `M: relative` à `>cartesian`. La subtilité : un relèvement relatif se mesure par rapport au *cap actuel* du navire, qui ne fait pas partie du tuple. Lis la variable `heading` (déclarée à la tâche 1) avec `heading get`, ajoute le décalage de relèvement (`ahead = 0`, `starboard = 90`, `behind = 180`, `port = 270`), et produis le point cartésien. L'appelant définit `heading` dans un bloc `with-variable`.

```factor
0 heading [
    T{ relative { distance 5 } { bearing starboard } } >cartesian
] with-variable . .
! => 0   (heading 0 is north; starboard is east; (5, 0))
! => 5
```

## 4. Inverse

Ajoute les méthodes du générique `flip` (déclaré à la tâche 1) pour qu'il renvoie la direction opposée.

- Pour `cardinal` : north ↔ south, east ↔ west.
- Pour `polar` : ajoute 180° au relèvement (modulo 360).
- Pour `relative` : ahead ↔ behind, starboard ↔ port.

```factor
T{ cardinal { direction north } } flip .
! => T{ cardinal { direction south } }

T{ polar { magnitude 10 } { bearing 90 } } flip .
! => T{ polar { magnitude 10 } { bearing 270 } }

T{ relative { distance 5 } { bearing ahead } } flip .
! => T{ relative { distance 5 } { bearing behind } }
```

## 5. Ajoute des relèvements

Définis `add-bearings ( a b -- x y )` qui convertit les deux directions en cartésien et renvoie leur somme. Cela fonctionne pour n'importe quel mélange de `cardinal`, `polar` et `relative` : c'est là tout l'intérêt d'utiliser un générique pour `>cartesian`.

```factor
T{ cardinal { direction north } } T{ cardinal { direction east } } add-bearings . .
! => 1
! => 1
```
