# Introduction

Common Lisp possède un concept, _The Printer_, qui regroupe toutes les fonctions permettant d'écrire des représentations textuelles des données Lisp. L'une de ces fonctions est `format`, qui permet au programmeur de mettre en forme les données comme il le souhaite.

Les possibilités de `format`, et de _The Printer_ en général, constituent un vaste sujet ; on décrira ici les bases de son utilisation.

## La fonction FORMAT

La fonction `format` prend au moins deux arguments : un flux vers lequel imprimer et une chaîne de contrôle qui définit quoi imprimer et comment.

Les flux sont un concept à part entière, décrit ailleurs. Pour l'instant, tout ce qu'il faut savoir, c'est que l'impression se fait vers le flux et que deux valeurs particulières sont possibles pour cet argument : `t` et `nil`. `t` signifie d'imprimer sur la sortie standard (en réalité, le flux auquel la variable `*standard-output*` est liée), et `nil` signifie de créer une _string_ et de la renvoyer.

À noter que `format` s'évalue toujours à `nil`, sauf dans ce dernier cas, où `nil` est indiqué comme flux. C'est une façon courante de faire simplement de l'interpolation ou de la construction de _strings_.

```lisp
(format nil "hello world") ; => "hello world"
(format t "hello world")   ; => NIL (but "hello world" is printed to standard output)
```

## Les directives de format

La chaîne de contrôle peut contenir des « directives de format », qui donnent à `format` des instructions sur ce qu'il faut imprimer et sur la manière d'interpréter les autres paramètres qui lui sont passés. En un sens, la chaîne de contrôle est un programme que `format` va interpréter et exécuter. Toutes les directives commencent par `~` et sont suivies d'un caractère (_par exemple_ `~A`, `~D`, `~&`). La casse du caractère n'a pas d'importance.

La plupart des directives de format se contentent d'insérer dans la sortie un argument de `format`. On dit alors qu'elles le « consomment ». Certaines directives ne consomment aucun argument, ou en consomment plusieurs. Une directive permet même de sauter d'un endroit à l'autre dans la liste des arguments.

## La mise en forme de base

Une directive de format très générale est `~A`. Elle imprime une version « lisible par un humain » des données.

```lisp
(format nil "Value = ~a" 10)                ; => "10"
(format nil "hello ~a" "world")             ; => "hello world"
(format nil "The list is: ~A" (list 1 2 3)) ; => "The list is: (1 2 3)"
```

Une autre directive de format utile est `~S`. Elle imprime une version « lisible par une machine » des données. C'est très utile si tu veux pouvoir interpréter la sortie produite comme des données Lisp. Pour beaucoup de choses, elle donnera le même résultat que `~A`, mais note que pour les _strings_, par exemple, la sortie inclut les guillemets (échappés lorsqu'ils apparaissent dans une autre _string_), de sorte que la valeur puisse être relue comme un paramètre de type _string_.

```lisp
(format nil "~s" 10)            ; => "10"
(format nil "~s" "hello world") ; => "\"hello world\""
(format nil "~s" (list 1 2 3))  ; => "(1 2 3)"
```

Deux autres directives très utiles sont `~%` et `~&`. La première produit un caractère de nouvelle ligne, tandis que la seconde produit une « ligne fraîche ». La différence est que `~%` produit toujours un saut de ligne, alors que `~&` n'en produit un que si l'on n'est pas déjà en début de ligne. Ni l'une ni l'autre ne consomme d'argument.

```lisp
(format nil "~%new~%lines") ; => "
                                  new
                                  lines"

(format nil "~&new~&lines"  ; => "new
                                  lines"
```

Enfin, `~~` est une directive simple qui produit un `~` littéral.
