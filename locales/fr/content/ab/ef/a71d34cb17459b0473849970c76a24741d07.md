# À propos

`String` et `&str` sont deux façons fondamentales de manipuler des données textuelles en Rust.
Connaître leurs caractéristiques et la manière dont elles fonctionnent ensemble s'avère très utile.
Ce document explique comment elles se recoupent et propose quelques conseils de base.
`String` est un vecteur d'octets `u8` dont on est propriétaire.
`String` est mutable.
`&str` est une référence empruntée à une tranche de String.
`&str` est immuable.

La prononciation correcte de `&str` est « ref string ».
`String` est une représentation encodée en UTF-8, potentiellement mutable, d'une séquence de points de code Unicode.

`&str` est une vue en lecture seule d'une séquence UTF-8 bien formée.
Comme c'est une référence, elle est `Copy` et peut être partagée.

En Rust, on ne peut pas indexer `String` et `&str` comme on pourrait le faire dans d'autres langages.
Par exemple, ceci ne fonctionnera pas :

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

Cela découle des propriétés suivantes :

- Les _strings_ sont en UTF-8, dont l'unité élémentaire n'est pas l'octet, mais le point de code Unicode : `char`.
- Les points de code Unicode font jusqu'à 4 octets de large, mais s'encodent avec une largeur variable.
- Il est donc impossible de calculer la position du `n`-ième point de code sans parcourir les caractères réellement encodés, car au-delà du premier caractère, la position du caractère suivant dépend de la largeur des précédents.
- Les auteurs de la bibliothèque standard de Rust ont donc choisi de ne pas implémenter le trait `Index` pour les _strings_ : alors qu'indexer un tableau d'octets prend un temps constant, indexer une _string_ peut prendre beaucoup de temps. Cela viole le principe de moindre surprise.

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## Convertis une `String` en une `&str`

`String` implémente `Deref<Target=str>`.
Ce trait bénéficie d'un traitement particulier du compilateur : cela signifie que toute référence à une `String` peut être convertie automatiquement et de façon transparente en une `&str`.
Cela implique ce qui suit :

- Tout code qui attend, par exemple, un argument `&str` peut accepter un `&String` à la place.
- Toute méthode implémentée pour `&str` peut aussi être appelée sur une `String`.

(Si l'on voulait de façon générique pouvoir accepter n'importe quelle forme de référence à un `str`, on pourrait utiliser un argument de type `impl AsRef<str>`, mais il est courant de typer les arguments en `&str`.)

## Convertis une `&str` en une `String`

Il existe de nombreuses façons de créer une `String` à partir d'une `&str` :

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

Toutes les méthodes ci-dessus nécessitent d'allouer de la mémoire pour la `String` (sur le tas).
C'est pourquoi `&str` est disponible en no_std, mais pas `String`.

(La crate [heapless](https://crates.io/crates/heapless) est souvent utilisée pour manipuler des _strings_ en no_std.)

## Utilise `String` et `&str` dans les structures

Cette section explique quand utiliser `String` ou `&str` pour les champs d'une structure.
Tu verras souvent des structures définies avec `String` plutôt que `&str` pour la valeur de leurs champs.

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

En utilisant `String`, la structure est propriétaire des données.
Cela rend le code plus facile à lire et à enseigner pour les débutants.
Mais cela signifie aussi qu'une allocation sur le tas aura lieu pour chaque champ.
`&str` emprunte les données textuelles, ce qui offre de meilleures performances, au prix de la nécessité pour ta structure de définir des paramètres de durée de vie.
Le [tutoriel de la crate csv][csv-tutorial] démontre et explique ces idées de façon très concrète et très pédagogique.

## Notes sur les performances

Les `String` sont allouées sur le tas, ce qui peut les rendre plus coûteuses à utiliser.
Les `&str` sont des références partagées et ne nécessitent donc pas de réallocation fréquente.
