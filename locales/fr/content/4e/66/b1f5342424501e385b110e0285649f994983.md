# Instructions

Tu t'occupes de la boîte à outils de génération de code d'une station de signaux.
Chaque macro est un _stencil_ : un petit gabarit que le compilateur utilise pour
produire du code spécialisé à chaque site d'appel.

Tu n'écris que les quatre macros. Le fichier de tests définit de petits mots
enveloppes qui *appellent* tes macros (une macro ne s'observe qu'à travers le code
qu'elle génère), puis il vérifie ce que ces enveloppes renvoient à l'exécution.
Laisse ces enveloppes telles quelles.

Pour chaque tâche, le corps reçoit sur la pile les entrées littérales du site
d'appel et doit laisser **une seule _quotation_**. Les lignes « compiles to »
montrent le code linéaire que ta _quotation_ doit produire.

## 1. Deux fois de suite

`twice` prend une _quotation_ littérale et renvoie une _quotation_ qui exécute
l'originale deux fois de suite.

```factor
! : inc-twice ( x -- y ) [ 1 + ] twice ;
! body receives [ 1 + ]  ->  must build [ 1 + 1 + ]
5 inc-twice .   ! => 7
```

## 2. N répétitions

`repeat-quot` prend une _quotation_ littérale et un nombre littéral `n`, et
renvoie une _quotation_ qui exécute l'originale `n` fois de suite.
`n = 0` renvoie la _quotation_ vide `[ ]`.

```factor
! : inc-thrice ( x -- y ) [ 1 + ] 3 repeat-quot ;
! body receives [ 1 + ] 3  ->  must build [ 1 + 1 + 1 + ]
5 inc-thrice .   ! => 8
```

## 3. Compose plusieurs _quotations_

`compose-many` prend un tableau littéral de _quotations_ et renvoie une seule
_quotation_ qui exécute chacune d'elles à tour de rôle. Un tableau vide renvoie
la _quotation_ vide.

```factor
! : pipeline ( x -- y ) { [ 1 + ] [ 2 * ] [ 1 - ] } compose-many ;
! body receives { [ 1 + ] [ 2 * ] [ 1 - ] }  ->  must build [ 1 + 2 * 1 - ]
5 pipeline .   ! => 11
```

## 4. Itération déroulée

`each-literal` prend une séquence littérale et une _quotation_. Elle renvoie une
_quotation_ qui, pour chaque élément de la séquence, empile cet élément puis
exécute la _quotation_ : une itération qui a lieu à la compilation, ce qui donne
un code généré linéaire.

```factor
! : sum-three ( -- n ) 0 { 10 20 30 } [ + ] each-literal ;
! body receives { 10 20 30 } [ + ]  ->  must build [ 10 + 20 + 30 + ]
sum-three .   ! => 60
```

C'est la plus structurelle des quatre : la longueur de la séquence *et* la
valeur de ses éléments façonnent le code généré. Les indices te guident pas à
pas dans sa construction.
