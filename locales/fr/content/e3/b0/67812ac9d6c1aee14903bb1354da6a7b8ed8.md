# À propos

La seule convention de passage de données de Factor est la *pile de données* : les mots dépilent leurs entrées et empilent leurs sorties. Chaque définition de mot déclare un *effet de pile* qui documente ce contrat.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

Les noms à l'intérieur de `( … -- … )` servent au lecteur ; ce que le compilateur vérifie, c'est le *nombre* d'entrées et de sorties. Une incohérence est une erreur de compilation, ce qui permet d'attraper toute une catégorie de bugs qui seraient des erreurs d'exécution dans un langage à typage dynamique dépourvu de ce genre de déclaration.

Comme la pile est positionnelle, on doit sans cesse en réorganiser le sommet avant de pouvoir exécuter le mot suivant. Les **mots de réorganisation** du module `kernel` font exactement cela :

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

La famille complète des mots de réorganisation étend ces derniers avec `-rot` (rouler dans l'autre sens), les cousins suffixés d'un `d` qui agissent un cran plus profond (`dupd`, `swapd`), les cousins préfixés d'un `2` qui agissent sur des paires (`2dup`, `2drop`, `2nip`), et d'autres encore comme `pick` et `tuck`. Ils sont introduits au fur et à mesure que les exercices suivants en ont besoin ; recourir à trop de mots de réorganisation d'un coup est généralement le signe qu'une *variable locale* (une valeur nommée) se lirait mieux.

Par convention, les mots s'écrivent en `lowercase-kebab-case`, les prédicats se terminent par `?` et produisent un booléen (`even?`, `empty?`), les _setters_ s'écrivent `>>name` et les _getters_ `name>>`, et un mot et sa variante mutante partagent souvent un même nom, que seul le contexte permet de distinguer.
