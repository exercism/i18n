# Astuces

Un usage courant de `Either` consiste à indiquer un calcul qui peut éventuellement produire une erreur (si l'erreur elle-même ne t'intéresse pas, le type `Option`, plus simple, est peut-être un meilleur choix). En l'absence d'erreur, le résultat est généralement un `Right` (mnémonique : la valeur « right »), tandis qu'une erreur donne un `Left`, par exemple un `Left[String]` contenant un message d'erreur. Note qu'en Scala 2.12, `Either` est orienté à droite par défaut, si bien qu'il se comporte comme attendu pour des opérations comme `filter`, `map`, `flatMap` ou dans une _for-comprehension_. Si `Either` ne t'est pas familier, tu peux lire [ce tutoriel](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html). Mais sache que ce tutoriel porte sur des versions de Scala antérieures à la 2.12. Avec Scala 2.12, tu peux ignorer `RightProjection` sans crainte et omettre `.right`. `Either` est ce qu'on appelle une [monade](https://en.wikipedia.org/wiki/Monad_(functional_programming)), qui couvre un « aspect de calcul », ici la gestion des erreurs. Un bon usage des monades peut donner du code très concis, mais aussi élégant et lisible. Un usage inapproprié peut facilement produire le contraire. Regarde [cette vidéo](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) pour en savoir plus.

## Les pièges courants à éviter

Il existe quelques règles empiriques pour `Either` :

1. Si tu n'en as pas besoin, ne l'utilise pas. Plutôt que

```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```

mieux vaut écrire

```scala
def add1(x: Int): Int = x + 1
```

(il existe `Either.map` pour appliquer ce genre de fonctions simples, tu n'as donc pas besoin de les encombrer avec `Either`).

2. Ne fais pas d'« unwrap » si tu n'en as pas vraiment besoin. Il existe souvent des fonctions intégrées qui font le travail. Les signes d'un « unwrap » prématuré sont `isLeft/isRight` ou le _pattern matching_. Par exemple, plutôt que

```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```

mieux vaut écrire

```scala
x fold (identity, _ + 1)
```

3. Les monades s'utilisent très bien dans une _for-comprehension_ FTW.
C'est une bonne idée quand tu veux « composer » plusieurs instances d'`Either`. Plutôt que

```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```

mieux vaut écrire

```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
