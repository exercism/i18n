# À propos

## Application partielle

Toutes les fonctions en Elm sont [curryfiées][currying], ce qui signifie que si on appelle une fonction sans passer tous les arguments, elle renvoie une nouvelle fonction.

Le résultat de cette opération s'appelle l'[application partielle][partial-application] (on ne passe pas tous les arguments à la fonction, mais on en applique partiellement certains).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

L'application partielle applique toujours les arguments dans l'ordre.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## L'opérateur pipe (`|>`)

Écrire `x |> f` revient exactement à écrire `f x`. Un exemple concret : `"5" |> String.toInt` est identique à `String.toInt "5"`.

Au premier abord, ça ne semble pas très utile, mais on l'appelle l'[opérateur pipe][pipe-operator] parce qu'il permet d'écrire du code « en pipeline ».

Par exemple, imaginons une fonction _sanitize_ qui transforme les entrées de l'utilisateur en nombres entiers :

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

On peut la réécrire comme ceci :

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Cela évite d'utiliser des parenthèses et montre les fonctions dans l'ordre où elles sont appliquées (d'abord `String.trim`, puis `String.toInt`), ce qui améliore la lisibilité.

Il existe aussi un [opérateur pipe inversé `(<|)`][reverse-pipe-operator].
Écrire `x <| f` revient exactement à écrire `f x`.
Là non plus, ça ne semble pas très utile au premier abord, et c'est assurément beaucoup moins utilisé que l'opérateur pipe, mais ça aide à éviter les parenthèses dans certaines situations.

## Composition de fonctions / style point free

L'opérateur [`(>>)`][forward-composition] a le type `(a -> b) -> (b -> c) -> (a -> c)` et crée une fonction de type `a -> c` en composant deux fonctions compatibles de type `a -> b `et `b -> c`.
Pour cela, il prend la sortie (de type `b`) de la première fonction et l'utilise comme premier argument de la seconde fonction (qui doit être du même type `b`).
La fonction créée prend la même entrée (de type `a`) que la première fonction, et renvoie le `c` que renvoie la seconde fonction.

Un exemple concret est `String.trim >> String.toInt`.
`String.trim` prend une _string_ comme seul paramètre, c'est donc ce que prend la fonction créée.
`String.toInt` renvoie un `Maybe Int`, c'est donc ce que renvoie la fonction créée.
`String.trim` renvoie un `String`, que `String.toInt` accepte comme paramètre, donc l'exemple compile.

On peut maintenant réécrire notre fonction `sanitize` comme ceci :

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Remarque qu'on n'utilise plus le paramètre `input` visible dans l'exemple d'origine, même si le comportement reste identique.
Cette façon de créer des fonctions qui ne font aucune référence à leurs paramètres s'appelle le « style point free ».
L'avantage de ce style est que le code est plus concis ; l'inconvénient est qu'il peut être plus difficile à comprendre, surtout pour les débutants.

Il est bon de se rappeler que toutes les fonctions en Elm sont curryfiées, donc `String.length >> max` compile et donne ceci :

- Une fonction (1) qui prend une _string_ en paramètre (l'entrée de `String.length`)
- `max` est une fonction qui prend deux paramètres `Int`, mais la fonction 1 ne lui passe qu'un seul `Int` (la valeur renvoyée par `String.length`), donc `max` est partiellement appliquée.
- La valeur de retour de la fonction `max` partiellement appliquée est une autre fonction (2) qui prend un `Int` et renvoie le plus grand de cet `Int` et de l'`Int` partiellement appliqué issu de `String.length`
- La fonction 1 (`String -> Int`) renvoie donc la fonction 2 (`Int -> Int`)
- Donc `((String.length >> max) "123") 2` renvoie `3`, car `"123"` a une longueur de 3, qui est supérieure au 2 de l'argument `Int`.

## Conception de fonctions

Pour écrire facilement du code élégant en Elm, il est préférable de faire de la structure de données principale le dernier paramètre des fonctions.
Toutes les fonctions courantes de la bibliothèque standard font ça, comme `List.map` (signature de type ci-dessous).

```elm
map : (a -> b) -> List a -> List b
```

On voit ici que le dernier paramètre de la fonction `map` est `List a` et qu'elle renvoie `List b`, donc la structure de données principale (`List`) est bien le dernier paramètre.

Cela permet d'écrire du code élégant en pipeline, comme ci-dessous.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Cela rend aussi pratique l'utilisation de la composition de fonctions et du style point free, comme alternative au pipeline.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

La composition de fonctions permet aussi de réduire cet exemple à un seul appel à `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
