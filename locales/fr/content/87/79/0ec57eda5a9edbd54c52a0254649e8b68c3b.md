## Avantages et inconvénients de `from_quote`

Cet exercice définit une fonction `from_quote` dans le type `Time`. Cela permet d'écrire du code comme celui-ci :

```roc
time : Time
time = "00:01:23"
```

Ce code appelle implicitement `Time.from_quote("00:01:23")` à la compilation. Cela peut accélérer le programme, puisqu'il n'a pas besoin de gérer l'analyse à l'exécution, et cela garantit que les heures rejetées par `from_quote` sont détectées à la compilation plutôt qu'à l'exécution. En plus, cela rend le code propre et lisible. Par exemple, voici l'un des tests de cet exercice :

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

Cependant, quelqu'un qui lit ce code pourrait supposer que la fonction `advance_time` prend une `Str` alors qu'en réalité elle prend un `Time`. Cela peut prêter à confusion et provoquer des erreurs. Pour cette raison, tu peux préférer le format un peu plus long mais plus explicite : `"00:00:05".Time`, qui appelle lui aussi `from_quote` à la compilation.

Dans tes propres programmes, tu peux préférer utiliser `from_str` à la place :

```roc
Time := { ... }.{
    from_str : time_str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

Tu peux aussi appeler `from_str` (ou n'importe quelle autre fonction pure) à la compilation, comme ceci :

```roc
Ok(time) = Time.from_str("00:01:23")
```

Remarque : placer cette définition au niveau supérieur la fait s'exécuter à la compilation (puisque la fonction est pure et que son entrée est connue à la compilation). À l'intérieur d'une fonction, tu peux utiliser `from_str` à l'exécution.
