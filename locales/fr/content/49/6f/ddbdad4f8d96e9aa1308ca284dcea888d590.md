# À propos

Factor concentre l'aléatoire dans le vocabulaire [`random`][random] autour d'un seul _word_ générique :

```
random ( obj -- elt )
```

Il choisit son comportement en fonction de son argument :

- un **entier** `n` produit un entier aléatoire dans `[0, n)` ;
- une **séquence** produit un élément aléatoire ;
- les assocs, les hash-sets et les tuples `uniform-distribution` sont également pris en charge.

Deux fonctions auxiliaires pour les séquences s'appuient sur lui :

```factor
USING: random ;

{ 1 2 3 4 5 } randomize .   ! shuffle in place (Fisher–Yates)
{ 1 2 3 4 5 } 3 sample .    ! 3 distinct elements; error if too many
```

`randomize` modifie la séquence sur place et la renvoie, donc si tu veux conserver l'ordre d'origine, fais d'abord un `clone`.

## D'où vient l'aléatoire

`random` lit le générateur contenu dans la variable dynamique `random-generator`. Par défaut, il s'agit d'un Mersenne Twister initialisé à partir de l'horloge système, ce qui fait que chaque processus obtient un résultat différent. Tu peux installer un autre générateur le temps d'une _quotation_ :

```
<mersenne-twister> ( seed -- rnd )
with-random        ( rnd quot -- )
```

```factor
USING: random random.mersenne-twister ;

42 <mersenne-twister> [ { 1 2 3 } randomize ] with-random .
! => the same ordering on every run
```

Comme `with-random` se contente de lier `random-generator` pendant toute l'étendue dynamique de la _quotation_, un _word_ qui l'enveloppe doit être marqué `inline` afin que la _quotation_ puisse laisser son résultat sur la pile pour l'appelant.

En plus de ceux-ci, `random` propose `random-bits`, `random-unit`, `uniform-random` et `normal-random` pour d'autres distributions, ainsi que `system-random-generator` et `secure-random-generator` pour les besoins non reproductibles et cryptographiques.

[random]: https://docs.factorcode.org/content/vocab-random.html
