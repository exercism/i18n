# Introduction

Le code scalaire s'appuie sur des drapeaux positionnés par diverses instructions pour effectuer un branchement en réponse à une certaine condition.
Les valeurs compactées, elles, ne représentent pas une seule valeur mais de nombreuses valeurs en parallèle.
Une même condition peut ne pas être vérifiée pour une voie et l'être pour une autre.

C'est pourquoi le code SIMD est _sans branchement_ par défaut.

Au lieu de s'appuyer sur des drapeaux, les comparaisons compactées produisent généralement un **masque** dans l'opérande de destination.
Pour chaque voie, la comparaison remplit toute la voie de 1 lorsque la condition est vraie, et de 0 lorsqu'elle est fausse.
Lu comme un entier signé, une voie « vraie » vaut `-1` et une voie « fausse » vaut `0`.

Ce masque peut ensuite être combiné à des opérations bit à bit pour filtrer certaines voies.

## Comparaisons compactées

Une `cmp` scalaire est générique au sens où elle sert à positionner plusieurs drapeaux à la fois.
Une autre instruction peut ensuite consommer ces drapeaux, soit pour effectuer un branchement, soit pour effectuer des calculs.

Cependant, comme une comparaison compactée vérifie une condition et calcule un masque en même temps, elle n'est pas générique.
Il faut lui indiquer la condition exacte à tester.

Il y a deux façons de procéder :

- Pour les comparaisons d'entiers, la condition est indiquée par un suffixe : `eq` pour l'égalité et `gt` pour « supérieur à ».
  Les autres variantes se construisent en combinant le résultat de l'une de ces comparaisons.
- Pour les comparaisons en virgule flottante, la condition est encodée dans un immédiat.
  Les différentes valeurs de cet immédiat correspondent à différentes conditions testées.

Hormis l'utilisation d'un suffixe conditionnel spécifique pour les comparaisons d'entiers, la syntaxe suit la même structure que celle que l'on a déjà vue :

- Pour les entiers, `p` + `cmp` + condition + taille (`b`, `w`, `d` ou `q`).
- Pour les flottants, `cmp` + `p` + taille (`s` ou `d`).
  La condition est passée dans un immédiat en tant qu'opérande supplémentaire.

### Comparaisons d'entiers

Comme on l'a dit, il n'existe que des comparaisons d'entiers pour l'égalité et pour « supérieur à » :

| instruction                                | description                      |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | égalité voie par voie            |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | « supérieur à » **signé**, voie par voie |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

Pour créer une comparaison « inférieur à », utilise `gt` en échangeant les opérandes : `a < b` == `b > a`.

Note que la comparaison est **signée**.
Pour effectuer une comparaison non signée, inverse le bit de poids fort des deux opérandes.
On peut le faire avec un XOR avec un masque où seul le bit de poids fort est à 1.

~~~~exercism/note
Deux astuces pratiques :

1. Faire un XOR d'un registre avec lui-même pour obtenir une valeur tout à zéro.
2. Comparer un registre avec lui-même pour obtenir une valeur tout à un.

Par exemple :

```x86asm
pxor xmm4, xmm4    ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

Les masques tout à zéro et tout à un servent couramment à encoder respectivement « faux partout » et « vrai partout ».
Ils peuvent aussi représenter un `0` ou un `-1` compacté, qui sont des valeurs sentinelles courantes.
Par exemple, le NUL qui marque la fin d'une _string_ est un `0`.
~~~~

### Comparaisons en virgule flottante

Les voies en virgule flottante utilisent une forme différente : une seule instruction, `cmpps` (et `cmppd` pour les voies de 64 bits), avec la condition dans un immédiat :

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM propose aussi des pseudo-instructions qui correspondent au bon immédiat et sont plus faciles à retenir.
Dans tout ce qui suit, le `x` de `px` peut être `s` (flottants 32 bits) ou `d` (flottants 64 bits) :

| pseudo-instruction | immédiat | comparaison             |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a est NaN ou b est NaN |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | ni a ni b n'est NaN    |

## Sélectionner avec un masque

Un masque encode le résultat d'une condition.
Il peut ensuite servir à choisir, voie par voie, entre deux ensembles de valeurs selon cette condition.
On prend la voie d'une valeur là où le masque est vrai, et d'une autre là où il est faux :

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

Ce schéma est la forme compactée de la sélection sans branchement.
Chaque voie est calculée, et le masque seul décide quelle valeur est conservée, sans le moindre `jcc`.

## Mélanges dédiés

Il existe des instructions qui effectuent directement cette même sélection, en lisant un bit par élément dans un registre de masque.
On les appelle les instructions de **mélange** :

| instruction | élément     | source du masque |
|-------------|-------------|-----------------|
| `pblendvb`  | octet       | `xmm0` implicite |
| `blendvps`  | voie de 32 bits | `xmm0` implicite |
| `blendvpd`  | voie de 64 bits | `xmm0` implicite |

Note que la première instruction suit la syntaxe des entiers, tandis que les deux autres suivent la syntaxe des flottants.
Cependant, comme ces instructions se contentent de sélectionner des octets bruts, n'importe laquelle d'entre elles peut s'utiliser avec des entiers comme avec des flottants.

Pour chaque élément, le mélange conserve la destination lorsque le bit de poids fort de l'élément de masque correspondant vaut 0, et prend la source lorsqu'il vaut 1.
Seul ce **bit de poids fort** est consulté, ce qu'un masque de comparaison satisfait, puisque ses voies sont tout à un ou tout à zéro.
Le registre de masque est toujours `xmm0`, de façon implicite :

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

Il est aussi possible d'utiliser `pblendvb` pour sélectionner des voies à partir d'un masque de comparaison, quelle que soit la taille.
Comme tous les octets d'une voie vraie valent 1, `pblendvb` les sélectionne tous.

~~~~exercism/note
Ces instructions ajoutent toutes un `v` après l'opération effectuée (`blend`).
Ce `v` signifie _variable_, car la sélection n'est pas statique : elle dépend d'un registre.

Il existe aussi des variantes sans `v`, qui sélectionnent selon un immédiat.
Elles suivent le même schéma, en sélectionnant une voie `i` si le bit `i` de l'immédiat est à 1.
~~~~

## D'un masque vers le scalaire

Aussi puissant soit-il, le code SIMD est loin d'avoir la souplesse du code scalaire.
Dans de nombreuses situations, il faut repasser d'un registre compacté au monde des instructions scalaires.

La famille d'instructions `movmsk` fait le pont entre ces deux mondes.
Ces instructions extraient le **bit de poids fort** de chaque voie vers un registre à usage général :

| instruction | collecte                     | largeur du résultat |
|-------------|-----------------------------|--------------|
| `pmovmskb`  | le bit de poids fort de chacun des 16 octets | 16 bits      |
| `movmskps`  | le bit de poids fort de chacun des 4 dwords | 4 bits       |
| `movmskpd`  | le bit de poids fort de chacun des 2 qwords | 2 bits       |

Utilisé après une comparaison, chaque bit à 1 représente une voie « vraie » et chaque bit à 0, une voie « fausse ».
On peut ensuite manipuler ce résultat comme d'habitude avec des instructions scalaires.
Par exemple, un `popcnt` compte le nombre de correspondances, et un `tzcnt` trouve la première.

Le registre à usage général peut faire 32 ou 64 bits de large.

## Tester un vecteur entier

Il existe aussi une variante compactée de l'instruction scalaire `test` : `ptest`.

Elle est similaire à son homologue scalaire en ce qu'elle effectue une opération AND entre deux opérandes, sans les modifier.
Contrairement à `test`, `ptest` effectue aussi une opération ANDN, qui inverse le premier opérande.

Ainsi, on peut voir `ptest` comme une version non destructive de `pand` et `pandn` qui positionne des drapeaux selon le résultat.
Tout comme ces deux instructions, `ptest` traite l'ensemble du registre SIMD comme une seule voie et ne prend donc pas de préfixe de taille.

Si le résultat d'une opération AND vaut `0`, le `ZF` est positionné, et si l'opération ANDN donne `0`, c'est le `CF` qui est positionné.
Cela signifie que `ptest` permet de vérifier à la fois un masque tout à un et un masque tout à zéro :

1. Utiliser `ptest` sur un registre avec lui-même positionne `ZF` uniquement si le registre est tout à zéro.
   Cela imite l'astuce scalaire courante qui consiste à utiliser `test` sur un registre avec lui-même pour vérifier qu'il vaut `0`.
2. Utiliser `ptest` sur un registre avec un masque tout à un positionne `CF` uniquement si le registre est tout à un.
   De plus, cela positionne `ZF` uniquement si le registre est tout à zéro, ce qui permet de vérifier les deux masques d'un coup.

```x86asm
pxor    xmm0, xmm0   ; all zeros
pcmpeqb xmm1, xmm1   ; all ones
pcmpeqb xmm2, xmm2

ptest xmm0, xmm0     ; ZF set: a register against itself detects all zeros
ptest xmm0, xmm1     ; ZF set, CF clear: xmm0 is all zeros, not all ones
ptest xmm2, xmm1     ; CF is set only if xmm2 is all ones
```

Le résultat d'un `ptest` peut servir à effectuer un branchement ou à alimenter des instructions sans branchement comme `setcc` ou `cmovcc`, comme d'habitude.
