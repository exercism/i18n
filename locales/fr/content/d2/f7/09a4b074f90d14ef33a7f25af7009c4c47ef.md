# Indices

## Général

- Regarde l'[excellente conférence][phantom-builder-pattern] de Jeroen Engels sur le motif du constructeur fantôme

## 1. Fournis un espace réservé pour les coffres au trésor

- `Chest` peut être identique à `TreasureChest`, une seule variante avec un type fantôme ajouté
- L'espace réservé `Chest todo` ne prend pas assez d'arguments de type, il lui manque le type fantôme
- Le type fantôme doit être un enregistrement, afin de pouvoir être étendu
- Le type de départ est le `Chest treasure {}` non contraint et le type final est le `Chest treasure { conditions | securePassword : (), uniqueTreasure : () }` entièrement validé
- Pour passer du type de départ à l'autre, les conditions `securePassword : ()` et `uniqueTreasure : ()` seront ajoutées par `secureChest` et `uniqueTreasures` indépendamment

## 2. Sélectionne les coffres sécurisés

- Tu peux faire du filtrage par motif sur le `Chest` dans l'argument de la fonction
- Tu peux utiliser la fonction [`String.length`][string-length] pour valider le mot de passe
- La condition `securePassword : ()` est ajoutée depuis la signature de type, et non depuis le corps de la fonction
- Tu ne peux pas placer un `Chest` non contraint dans un `Just` en espérant que le type change. Tu dois créer une nouvelle valeur avec le constructeur `Chest`

## 3. Sélectionne les trésors uniques

- Il n'existe pas de fonction `List.unique` à utiliser, tu dois créer la tienne
- Une approche possible consiste à utiliser `List.filterMap` avec une fonction auxiliaire de type similaire à `secureChest`
- La condition `uniqueTreasure : ()` est ajoutée depuis la signature de type, et non depuis le corps de la fonction
- Tu ne peux pas placer un `Chest` non contraint dans un `Just` en espérant que le type change. Tu dois créer une nouvelle valeur avec le constructeur `Chest`

## 4. Profite du produit final

- `makeTreasureChest` devrait utiliser le constructeur de type `TreasureChest`
