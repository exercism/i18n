# À propos de la redirection

Dans le monde de l'interface en ligne de commande, les programmes interagissent souvent avec trois flux de données standard :

1. **Entrée standard** (`stdin`) : là où un programme reçoit son entrée (généralement depuis le clavier).
1. **Sortie standard** (`stdout`) : là où un programme envoie sa sortie normale (généralement vers l'écran du terminal).
1. **Erreur standard** (`stderr`) : là où un programme envoie ses messages d'erreur (généralement vers l'écran du terminal).

Souviens-toi qu'on les a présentés dans le chapitre [Pipelines et listes de commandes][pipelines].

~~~~exercism/note
On peut considérer les pipelines comme une forme de redirection : la sortie standard d'un programme est envoyée directement vers l'entrée standard d'un autre.
Nous avons déjà vu les pipelines.
Ce concept abordera la redirection depuis et vers des fichiers.
~~~~

La redirection du shell est un mécanisme puissant qui permet de changer la destination de ces flux.
Au lieu qu'un programme lise depuis le clavier ou écrive à l'écran, tu peux rediriger l'entrée depuis un fichier ou envoyer la sortie vers un fichier.
Cela offre une grande souplesse et un bon contrôle sur la façon dont les programmes interagissent avec les données.

## Les principaux opérateurs de redirection

Voici les opérateurs de redirection les plus courants et ce qu'ils font :

### `>` (redirection de la sortie)

* Rôle : rediriger la sortie standard (`stdout`) d'une commande vers un fichier.
* Comportement :
  * Si le fichier n'existe pas, il est créé.
  * Si le fichier existe, son contenu est écrasé.
* Exemple :

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
La redirection est effectuée **avant** l'exécution de la commande.
Cela signifie que tu ne peux pas rediriger vers le même fichier que celui dont tu as besoin en lecture.

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

Dans la seconde commande de l'exemple ci-dessus,

1. Bash tronque d'abord le fichier nommé dans la redirection.
   Cela détruit le contenu précédent et laisse un fichier vide.
2. Ensuite, bash lit le fichier désormais vide.
3. Puis bash réécrit le contenu (c'est-à-dire rien) dans le fichier.
~~~~

### `>>` (ajout à la sortie)

* Rôle : ajouter la sortie standard (`stdout`) d'une commande à la fin d'un fichier.
* Comportement :
  * Si le fichier n'existe pas, il est créé.
  * Si le fichier existe, la sortie est ajoutée à la fin du fichier.
* Exemple :

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<` (redirection de l'entrée)

* Rôle : rediriger l'entrée standard (`stdin`) d'une commande depuis un fichier.
* Comportement : la commande lit son entrée depuis le fichier indiqué au lieu du clavier.
* Exemple :

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>` (redirection des erreurs) :

* Rôle : rediriger l'erreur standard (`stderr`) d'une commande vers un fichier.
* Comportement : les messages d'erreur sont envoyés vers le fichier indiqué au lieu du terminal.
* Exemple :
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

Tu peux _ajouter_ l'erreur standard à la fin d'un fichier avec `2>>`.

### Autres redirections

Il existe aussi des redirections qui permettent de fusionner à la fois `stdin` et `stderr`.
Voir le [manuel][manual] pour plus de détails.

## `/dev/null`

`/dev/null` est un fichier spécial qui

* est un fichier vide quand on y lit, et
* rejette toutes les données qu'on y écrit.

On l'appelle parfois « le _bitbucket_ ».
Il est utile pour masquer la sortie ou les erreurs.

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## Combiner les redirections

On peut indiquer plusieurs redirections à la fois.

```bash
some_command < input.txt > output.txt 2> error.txt
```

Une redirection peut être copiée.

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

Quand tu vois `2>&1`, lis-le comme « redirige stderr vers _ce vers quoi stdout pointe **actuellement**_ ».
Bash traite les instructions de redirection strictement de gauche à droite, ce qui signifie que tu peux faire :

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## Les descripteurs de fichier

Dans le contexte de la programmation shell et des systèmes d'exploitation comme Linux/Unix, un descripteur de fichier (FD) est un entier positif ou nul qui sert d'identifiant ou de référence pour un fichier ouvert ou une ressource d'E/S (entrée/sortie).
Vois-le comme une étiquette ou un numéro de référence que le système d'exploitation utilise pour garder la trace des fichiers ouverts et des flux de données.

Les nombres que tu vois à gauche des redirections sont des descripteurs de fichier.

Les trois premiers descripteurs de fichier sont attribués aux flux d'E/S standard :

* l'entrée standard correspond au descripteur de fichier 0
* la sortie standard correspond au descripteur de fichier 1
* l'erreur standard correspond au descripteur de fichier 2

On peut définir ou créer de nouveaux descripteurs de fichier avec la commande `exec` et les opérateurs de redirection.

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

Cette technique paraît assez tortueuse, mais elle peut être très utile quand ton script est exécuté par un autre logiciel et que la sortie standard est récupérée automatiquement par ce logiciel.
La commande `bats`, utilisée pour exécuter les tests unitaires de ce parcours, fonctionne de cette manière : `bats` capture la sortie standard et la sortie d'erreur d'un test, mais les messages de débogage envoyés vers le descripteur 3 s'affichent dans le terminal.
~~~~

## En résumé

Pourquoi la redirection est-elle utile ?

* Conserver la sortie : garder les résultats d'une commande pour les examiner ou les traiter plus tard.
* Journalisation : capturer les messages d'erreur pour le débogage.
* Automatisation : enchaîner des commandes, en utilisant la sortie de l'une comme entrée d'une autre.
* Filtrage : se débarrasser de la sortie indésirable.
* Traitement par lots : traiter des données à partir de fichiers au lieu de les saisir à la main.
* Écriture de scripts : les redirections sont essentielles pour écrire des scripts shell robustes.

Les redirections du shell te donnent un contrôle fin sur la façon dont les programmes interagissent avec les données, ce qui te permet de construire des _workflows_ complexes et de gérer efficacement l'information.
