# À propos

`assocs` est un [protocole][assoc-protocol], et non un type de données à part entière. Les tables de hachage (`H{ }`), les listes d'associations (des séquences de paires `{ key value }`) et les tables arborescentes l'implémentent toutes, et la plupart des mots qui opèrent sur les assocs sont interchangeables d'une implémentation à l'autre.

```factor
USING: assocs ;

H{ } clone "coal" over inc-at
"coal" over inc-at
"wood" over inc-at      ! => H{ { "coal" 2 } { "wood" 1 } }
```

L'interface complète est vaste (itération triée, transformation, filtrage), mais l'essentiel du travail dans les exercices fait appel à un petit ensemble de mots :

| mot         | effet                                         |
|-------------|-----------------------------------------------|
| `at`        | `( key assoc -- value/f )`                    |
| `at*`       | `( key assoc -- value ? )`, distingue une valeur `f` d'une clé absente |
| `key?`      | `( key assoc -- ? )`                          |
| `set-at`    | `( value key assoc -- )`, modifie l'assoc     |
| `change-at` | `( key assoc quot -- )`, `quot` est `( old -- new )` |
| `inc-at`    | `( key assoc -- )`, fait `+1`, en insérant `1` si la clé est absente |
| `delete-at` | `( key assoc -- )`, modifie l'assoc           |
| `>alist`    | `( assoc -- pairs )`                          |

`sort-keys` et `sort-values` (dans `sorting`) trient un alist selon le champ choisi.

[assoc-protocol]: https://docs.factorcode.org/content/article-assocs-protocol.html
