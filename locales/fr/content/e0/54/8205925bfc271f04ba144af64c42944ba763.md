# Notes sur les délimiteurs

Tcl est un [langage très simple](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm), mais la façon dont l'interprète analyse le code comporte quelques cas limites particulièrement pénibles.

## Les accolades

Les accolades en Tcl sont simplement une façon de citer un bloc de texte : ce texte peut être interprété comme du code ou comme des données. À l'intérieur des accolades, des accolades imbriquées peuvent apparaître, mais elles doivent être équilibrées. La page de manuel de Tcl dit ceci :

> Les accolades s'imbriquent à l'intérieur du mot : pour chaque accolade ouvrante supplémentaire, il doit y avoir une accolade fermante supplémentaire (toutefois, si une accolade ouvrante ou fermante à l'intérieur du mot est _précédée d'un backslash_, elle n'est pas prise en compte pour localiser l'accolade fermante correspondante).

La formulation est très précise : si tu veux avoir un caractère d'accolade ouvrante ou fermante non apparié, il doit être précédé d'un backslash. Donc ne fais pas ceci :
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "{"}]
    # ......................^ will not work
}
```
Tu dois faire ceci
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "\{"}]
    # ......................^^ will work
}
```

Cela peut poser problème avec la façon dont Tcl analyse les commentaires, qui diffère de celle de la plupart des langages. On trouve une discussion plus poussée sur le [wiki de Tcl](https://wiki.tcl-lang.org/page/Why+can+I+not+place+unmatched+braces+in+Tcl+comments).

## Les crochets

De même, comme Tcl utilise les crochets pour la [substitution de commandes.](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M11), même à l'intérieur de chaînes entre guillemets doubles, tu dois faire attention à échapper les crochets ouvrants.

## Les parenthèses

À l'exception des [variables de tableau associatif](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M12), les parenthèses sont de simples caractères ordinaires.
