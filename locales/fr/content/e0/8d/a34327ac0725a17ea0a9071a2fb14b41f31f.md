# Générateurs de tests

Les générateurs de tests permettent aux parcours de générer automatiquement des tests, sans avoir à les écrire nous-mêmes. Chaque générateur de tests lit les `canonical data` de l'exercice, qui définissent le nom du test, ses entrées et ses sorties. Tu peux en savoir plus sur l'approche d'Exercism concernant les suites de tests [ici](https://github.com/exercism/problem-specifications#test-data-canonical-datajson).

Générer les tests automatiquement élimine toute forme d'erreur humaine lors de leur création. De plus, on veut que les tests soient fidèles à leurs _canonical data_. La génération de tests rend aussi beaucoup plus facile de garder les tests à jour. Quand les _canonical data_ changent, les tests sont automatiquement mis à jour dès que le générateur correspondant est exécuté.

Tu trouveras un exemple de fichier de _canonical data_ [ici](https://github.com/exercism/problem-specifications/blob/master/exercises/bob/canonical-data.json)

## Déploie le générateur

### Crée un projet

1. Ouvre IntelliJ Idea.
2. Clique sur « New Project ».
3. Définis le nom : « TestGeneratorTool ».
4. Définis l'emplacement souhaité du générateur de tests.
5. Définis le système de build : « Gradle ».
6. Sélectionne la dernière version du JDK et du SDK Groovy.
7. Définis le DSL Gradle : « Groovy ».
8. Clique sur « Create ».
9. Copie le dossier *TestGeneratorTool/src* dans le projet.
10. Copie le dossier *TestGeneratorTool/templates* dans le projet.
11. Copie le fichier *TestGeneratorTool/build.gradle* dans le projet.

### Ajoute les dépendances nécessaires

Toutes les dépendances nécessaires sont déjà ajoutées à *TestGeneratorTool/build.gradle*.

Si tu rencontres le moindre problème, cherche les instructions d'installation du framework de test Spock sur leur [site officiel][spock-framework-official].

Cherche les instructions d'installation du framework Picocli [ici][picocli].

### La structure du projet

- TestGeneratorTool/src : fichiers sources du générateur de tests
- TestGeneratorTool/templates : gabarits utilisés pour générer la classe de test et les méthodes de test
- TestGeneratorTool/build.gradle : dépendances du projet

## Utilisation du générateur de tests

1. Ouvre le projet dans IntelliJ Idea.
2. Va dans *TestGeneratorTool/src/main/groovy/Main.groovy*
3. Crée une nouvelle configuration d'exécution en cliquant sur la flèche verte à gauche de `static void main`.
4. Modifie la configuration :
   1. Trouve la configuration « Main » dans le panneau supérieur, à gauche de la flèche verte et du bug vert.
   2. Clique sur la configuration et choisis « Edit configurations... ».
   3. Dans la zone de texte « Program arguments », indique l'emplacement du répertoire du dépôt et l'emplacement du canonical-data.json à analyser.
      
      Voici un exemple, à modifier pour qu'il corresponde à ton système de fichiers :
      
      ```
      --repository-directory=C:\Users\Aksima\Exercism\building-exercism\groovy --canonical-data=C:\Users\Aksima\Exercism\building-exercism\canonical-data\groovy\largest-series-product\canonical-data.json
      ```
   4. Dans « Working directory », indique le chemin du projet que tu as créé pour l'outil de génération de tests. Par exemple, si tu as créé le projet dans
      
      ```
      C:\Users\Aksima\Exercism\building-exercism\tooling\groovy\generators\TestGeneratorTool
      ```
      
      ...alors tu dois mettre le même texte dans la zone de texte « Working directory ».
      
   5. Clique sur « OK »
5. Tout est prêt maintenant ! Tu peux générer les tests en cliquant simplement sur la flèche verte du menu supérieur.
6. N'oublie pas de modifier l'option de ligne de commande *--canonical-data* quand tu dois générer des tests à partir d'un autre fichier *canonical-data.json*.

### Étudie la structure du fichier canonical-data.json

La définition formelle du fichier canonical-data.json se trouve [ici][canonical-data-definition]. D'après cette définition, le fichier canonical-data.json se compose des parties suivantes :

- **exercise** : slug de l'exercice (kebab-case). Obligatoire.
- **comments** : facultatif.
- **cases** : un tableau d'éléments de test étiquetés. Obligatoire.
  - **labeledTestItem** : soit un **labeledTest**, soit un groupe composé d'une description et des **cases** définis plus haut.
  - **labeledTest** : un test unique avec les propriétés suivantes :
    - **uuid** : un UUID de version 4. Obligatoire.
    - **reimplements** : facultatif.
    - **description** : une description courte, claire, sur une seule ligne. Obligatoire.
    - **comments** : facultatif.
    - **scenarios** : scénarios pour inclure/exclure des cas de test. Facultatif.
    - **property** : nom de propriété en lowerCamelCase, composé uniquement de lettres. Obligatoire.
    - **input** : les entrées d'un cas de test. Obligatoire.
    - **expected** : la valeur de retour attendue d'un cas de test. Obligatoire.
