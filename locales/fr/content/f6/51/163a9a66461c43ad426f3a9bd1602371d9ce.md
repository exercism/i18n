# Les bases d'Unison

## Termes et fonctions

Les termes et les fonctions sont les unités de base pour écrire un programme Unison.

Un « terme » est ce que l'on appelle une valeur statique. Il se définit avec `name = expression`, éventuellement précédé d'une signature de type de la forme `name : MyType`. Unison prend en charge l'inférence de type, on verra donc peut-être la signature de type omise pour les définitions simples.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Les fonctions Unison s'écrivent `myFunctionName argument1 argument2 = myImplementation` : elles commencent par le nom de la fonction, suivi d'arguments séparés par des espaces.

```
getMax a b = Nat.max a b
```

Les fonctions peuvent, de façon facultative, inclure une signature de type. Le dernier type à droite est toujours le type de retour final de la fonction, et chaque argument est séparé par la flèche de fonction `->`.

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Pour appeler une fonction, utilise son nom suivi de ses arguments séparés uniquement par des espaces.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Lors de l'appel d'une fonction, Unison essaie de traiter ce qui se trouve immédiatement à droite comme son argument, ce qui ne produit pas toujours l'ordre d'évaluation des fonctions souhaité.

Supposons que l'on veuille obtenir la valeur `1` à partir de l'expression suivante

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Telle qu'elle est écrite, `shouldBe1` s'évalue à `0`, car l'ordre implicite d'application des fonctions est `getMax 1 10`, qui vaut `10`, puis `10 - 10`, qui vaut `0`.

Tu peux utiliser des parenthèses pour regrouper l'expression dans l'ordre d'opérations souhaité.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Les _watch expressions_

Unison propose un moyen d'évaluer rapidement du code, appelé _watch expression_. Une _watch expression_ commence par le symbole `>` et est suivie de l'expression à évaluer. Les _watch expressions_ peuvent être écrites dans n'importe quel fichier avec le suffixe `.u`. Une fois le fichier enregistré, tu devrais voir le résultat de l'évaluation de l'expression dans la console du Unison Codebase Manager (UCM). Dans cette documentation, on essaiera, autant que possible, de montrer une expression avec le résultat attendu après son évaluation dans une _watch expression_.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Fonctions multilignes

Les fonctions multilignes en Unison utilisent l'indentation ou des blocs `let` pour délimiter le code, c'est-à-dire la « portée lexicale ».

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Tout ce qui se trouve au même niveau d'indentation partage la même portée, c'est pourquoi on peut référencer la variable `newBeginning` dans la dernière ligne.

## Espaces de noms et instructions `use`

Les espaces de noms sont la façon dont on regroupe et organise les fonctions Unison. On peut les voir comme l'équivalent des « répertoires ». Ils apportent structure et regroupement logique.

Tu peux faire entrer les fonctions d'un espace de noms dans la portée avec une instruction `use`.

Supposons que tu écrives une fonction qui utilise des valeurs `List` d'Unison. Tu sais que tu auras besoin de fonctions comme `List.map` et `List.flatMap`, où `List` est l'espace de noms et `map` et `flatMap` sont des fonctions. Pour éviter les répétitions, tu peux choisir de faire entrer tout le contenu de l'espace de noms `List` dans la portée lexicale de ta fonction, comme ceci :

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

La ligne `use List` lève l'ambiguïté sur les références à `map` et `flatMap`. Tu peux en apprendre davantage sur [les instructions `use` ici][use-statements].

## La bibliothèque standard d'Unison

La bibliothèque standard d'Unison s'appelle `base`. Si tu as suivi le guide de démarrage rapide et que tu as une base de code créée en local, la bibliothèque standard a normalement été téléchargée automatiquement. Tu peux parcourir la documentation de la bibliothèque standard en ligne sur [Unison Share][unison-share-base].

## Commentaires et _documentation literals_

Les commentaires en Unison sont une fonctionnalité un peu inhabituelle. Lorsque tu écris du code Unison, tu peux créer, dans ton fichier avec le suffixe `.u`, du texte qui n'est pas interprété, avec la syntaxe suivante :

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Cependant_, comme le code Unison est enregistré sous la forme d'un hachage de son arbre de syntaxe abstraite, et non sous forme de fichiers texte sur le système de fichiers, les commentaires qui sont des « décorations » textuelles d'une fonction ou d'un terme Unison donné dans le fichier ne peuvent pas vraiment être enregistrés et rendus à nouveau pour être partagés. Si tu souhaites ajouter une information à ton terme Unison d'une manière qui sera conservée pour que d'autres puissent la lire et la comprendre, tu peux utiliser un _documentation literal_.

La documentation est une valeur de première classe dans le langage de programmation Unison. Cela signifie qu'un élément `Doc` peut être affecté à une valeur, passé en tant que valeur à une fonction, ou renvoyé comme valeur de retour d'une fonction. Les éléments _documentation literal_ s'ouvrent et se ferment avec des doubles accolades. Voici comment on pourrait utiliser l'élément `Doc` comme commentaire.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
