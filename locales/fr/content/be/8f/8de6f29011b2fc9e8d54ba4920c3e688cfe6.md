## Les avantages et les inconvénients de `from_quote`

Cet exercice définit une fonction `from_quote` dans le type `Card`. Cela permet d'écrire du code comme celui-ci :

```roc
card : Card
card = "Q"
```

Ce code appelle implicitement `Card.from_quote("Q")` à la compilation. Cela peut potentiellement accélérer le programme, puisqu'il n'a pas besoin de gérer l'analyse à l'exécution, et cela garantit que les cartes rejetées par `from_quote` sont détectées à la compilation plutôt qu'à l'exécution. De plus, cela rend le code agréable à lire. Par exemple, voici l'un des tests de cet exercice :

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

Cependant, une personne qui lit ce code pourrait supposer que la fonction `simulate_game` prend un enregistrement contenant deux `List(Str)`, alors qu'en réalité il s'agit d'un enregistrement contenant deux `List(Card)`. Cela peut prêter à confusion et provoquer des erreurs. Pour cette raison, tu préféreras peut-être la syntaxe un peu plus longue mais plus explicite : `"Q".Card`, qui appelle elle aussi `from_quote` à la compilation.

Dans tes propres programmes, tu préféreras peut-être utiliser `from_str` à la place :

```roc
Card := { ... }.{
    from_str : card_str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

Tu peux aussi appeler `from_str` (ou n'importe quelle autre fonction pure) à la compilation, comme ceci :

```roc
Ok(card) = Card.from_str("Q")
```

Remarque : placer cette définition au niveau supérieur fait qu'elle s'exécute à la compilation (puisque la fonction est pure et que son entrée est connue à la compilation). À l'intérieur d'une fonction, tu peux utiliser `from_str` à l'exécution.
