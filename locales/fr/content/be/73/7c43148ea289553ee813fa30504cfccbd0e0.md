# À propos

Comme beaucoup d'autres langages, Go dispose de pointeurs.
Si tu découvres les pointeurs, ils peuvent sembler un peu mystérieux, mais une fois que tu y es habitué, ils sont assez simples.
Ils constituent une partie cruciale de Go, alors prends le temps de bien les comprendre.

Avant d'entrer dans les détails, il vaut la peine de comprendre à quoi servent les pointeurs.
Les pointeurs sont un moyen de partager de la mémoire avec d'autres parties de notre programme, ce qui est utile pour deux raisons majeures :

1. Lorsque l'on manipule de grandes quantités de données, faire des copies pour les passer d'une fonction à l'autre est très inefficace.
   En passant plutôt l'emplacement mémoire où les données sont stockées, on peut réduire considérablement l'empreinte en ressources de nos programmes.
2. En passant des pointeurs entre les fonctions, on peut accéder directement à l'unique copie des données et la modifier, ce qui signifie que les changements effectués par une fonction sont immédiatement visibles par les autres parties du programme lorsque la fonction se termine.

## Variables et mémoire

Imaginons que l'on dispose d'une variable entière ordinaire `a` :

```go
var a int
```

Lorsque l'on déclare une variable, Go doit trouver un emplacement en mémoire pour y stocker sa valeur.
Cela reste en grande partie abstrait pour nous : quand on a besoin de récupérer la valeur stockée dans cet emplacement mémoire, on peut simplement y faire référence par le nom de la variable.

Par exemple, quand on écrit `a + 2`, on récupère en fait la valeur stockée dans la mémoire associée à la variable `a` et on y ajoute 2.

De même, lorsque l'on veut modifier la valeur présente dans l'emplacement mémoire de `a`, on peut utiliser le nom de la variable pour effectuer une affectation :

```go
a = 3
```

L'emplacement mémoire associé à `a` stocke désormais la valeur `3`.

## Pointeurs

Si les variables nous permettent de faire référence à des valeurs en mémoire, il est parfois utile de connaître l'**adresse mémoire** vers laquelle pointe la variable.
Les **pointeurs** contiennent les adresses mémoire de ces valeurs.
On déclare une variable de type pointeur en faisant précéder le type sous-jacent d'un astérisque :

```go
var p *int // 'p' contains the memory address of an integer
```

Ici, on déclare une variable `p` de type « pointeur vers un entier » (`*int`).
Cela signifie que `p` contiendra l'adresse mémoire d'un entier.
La valeur zéro d'un pointeur est `nil`, car un pointeur `nil` ne contient aucune adresse mémoire.

### Obtenir un pointeur vers une variable

Pour trouver l'adresse mémoire de la valeur d'une variable, on peut utiliser l'opérateur `&`.
Par exemple, si l'on veut trouver et stocker l'adresse mémoire de la variable `a` dans le pointeur `p`, on peut faire ceci :

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Accéder à la valeur via un pointeur (déréférencement)

Lorsque l'on dispose d'un pointeur, on peut vouloir connaître la valeur stockée à l'adresse mémoire qu'il représente.
On peut le faire avec l'opérateur `*` :

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

L'opération `*p` récupère la valeur stockée à l'adresse mémoire contenue dans `p`.
Cette opération est souvent appelée « déréférencement ».

On peut aussi utiliser l'opérateur de déréférencement pour affecter une nouvelle valeur à l'adresse mémoire référencée par le pointeur :

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

Affecter une valeur à `*pa` modifie la valeur stockée à l'adresse mémoire que contient `pa`.
Comme `pa` contient l'adresse mémoire de `a`, en affectant une valeur à `*pa`, on modifie en réalité la valeur de `a` !

Attention toutefois : vérifie toujours qu'un pointeur n'est pas `nil` avant de le déréférencer.
Déréférencer un pointeur `nil` fait planter le programme à l'exécution !

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Pointeurs vers des structures

Jusqu'ici, nous n'avons vu que des pointeurs vers des valeurs primitives.
On peut aussi créer des pointeurs vers des structures :

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

On aurait aussi pu créer une nouvelle `Person` et en stocker immédiatement un pointeur :

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Lorsque l'on a un pointeur vers une structure, on n'a pas besoin de déréférencer le pointeur avant d'accéder à l'un de ses champs :

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## Les _slices_ et les _maps_ sont déjà des pointeurs

Les _slices_ et les _maps_ sont des types particuliers, car leur implémentation repose déjà sur des pointeurs.
Cela signifie que, la plupart du temps, on n'a pas besoin de créer des pointeurs vers ces types pour partager l'adresse mémoire de leurs valeurs.
Imaginons une fonction qui incrémente la valeur associée à une clé dans une _map_ :

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Si l'on crée une _map_ et que l'on appelle cette fonction, les modifications apportées à la _map_ par la fonction persistent après la fin de celle-ci.
C'est un comportement similaire à celui que l'on obtient avec un pointeur, mais remarque que dans cet exemple, on n'utilise ni référence, ni déréférencement, ni aucune autre syntaxe liée aux pointeurs :

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

Il en va de même lorsque l'on modifie un élément existant dans une _slice_.

Cependant, les opérations qui renvoient une nouvelle _slice_, comme `append`, sont un cas particulier et **peuvent ne pas** modifier la _slice_ en dehors de la fonction.
Cela vient de la façon dont les _slices_ fonctionnent en interne, mais nous n'entrerons pas dans les détails, car le sujet est plus avancé.
Si tu es vraiment curieux, tu peux en lire davantage dans [Go Blog: Mechanics of 'append'][mechanics-of-append]

## Arithmétique des pointeurs

Contrairement à d'autres langages, Go ne prend pas en charge l'arithmétique des pointeurs.
Cela signifie que l'on ne peut pas passer de l'adresse mémoire d'une valeur à celle d'une autre en incrémentant la valeur du pointeur.
Des extraits comme le suivant sont donc invalides :

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
