# À propos

Le _cast_ et la conversion de type [sont deux façons différentes de faire passer une expression d'un type de données à un autre][wiki-casting].

La [documentation C#][type-testing-and-cast-operators] classe la conversion de type comme l'utilisation de l'[opérateur `as`][as-operator] ou de l'[opérateur `is`][is-operator]. Le _cast_ est défini comme l'utilisation de l'[opérateur de cast][cast-operator].

En C#, très souvent, en dehors du domaine des valeurs numériques et des hiérarchies de classes, il te faudra effectuer une conversion en appelant un membre du type cible, comme [`Int32.Parse()`][int32-parse] qui convertit une _string_ en entier, ou en appelant un membre du type source, par exemple `object.ToString()`. Les développeurs Javascript et d'autres langages dynamiques doivent en être conscients.

Note que des [opérateurs][operator-overloading] de cast implicite et explicite (abordés dans [concept:csharp/operator-overloading]()) sont disponibles, et qu'ils permettent d'apporter un _cast_ assez arbitraire à tes propres types.

## Le _cast_ des types primitifs : implicite

Le système de types de C# est un peu plus strict que celui de _C_ ou de Javascript, et par conséquent, les opérations de _cast_ sont plus limitées. Le [cast implicite][implicit-casts] a lieu entre deux types numériques tant que le type cible peut préserver l'ordre de grandeur et le signe de la valeur du type source. Remarque dans la documentation l'exception concernant la conversion vers des nombres réels, où la précision peut être perdue.

Un cast implicite n'est signalé par aucune syntaxe particulière. Par exemple :

```csharp
int myInt = 1729;
long myLong = myInt;
```

Il n'existe aucune conversion implicite d'une expression numérique (ou _string_) en `bool`. La Base Class Library (BCL) fournit `Convert.ToBoolean()` à cet effet.

Une expression de type `char` peut être convertie implicitement en `int`. Le _cast_ dans l'autre sens doit être explicite. Toutes les valeurs de `int` ne sont pas des caractères utf 16 valides.

## Le _cast_ des types primitifs : explicite

Lorsqu'un type numérique ne peut pas être converti implicitement, on peut généralement utiliser l'[opérateur][cast-operator] de cast explicite.

Lorsque la valeur convertie ne peut pas être représentée par le type cible, parce qu'il n'est pas assez large ou qu'il y a un conflit de signe, une exception de dépassement de capacité peut être levée dans le cas des entiers, ou la variable du type cible peut prendre la valeur `Infinity` dans le cas des `float` et des `double`.

Une expression de type `int` peut être convertie explicitement en `char`. Cela peut produire un `char` non valide.

## Le _cast_ des types primitifs : exemples

```csharp
int largeInt = Int32.MaxValue;
int largeNegInt = Int32.MinValue;
ushort shortUnsignedInt = ushort.MaxValue;
float largeFloat = float.MaxValue;
float smallFloat = 17.29f;

// implicit cast
int from_ushort = shortUnsignedInt;          // 65535
float from_int = largeInt;                   // -21474836E+09
int from_char = 'a';                         // 96

// explicit cast
uint from_largeInt = (uint)largeInt;         // 2147483647
uint from_neg = (uint) largeNegInt;          // 2147483648 or OverflowException is thrown (if checked)
int from_smallFloat = (int) smallFloat;      // 17
int from_largeFloat = (int) largeFloat;      // -2147483648 or OverflowException is thrown (if checked)
char from_intc = (char) 32;                  // ' '
char from_invalid_int = (char) 0xdcbf;       // invalid char - no exception thrown

// no cast available
int fromString = Int32.Parse("42");          // 42
string toString = largeInt.ToString();       // "2147483647"
int fromString_bad = Int32.Parse("forty two");     // FormatException is thrown
```

Voir cet [article][checked] pour le mot-clé _**checked**_.

## Conversion de type pour les types dans une hiérarchie

Tout type peut être converti implicitement en sa classe de base ou son interface.

```csharp
IList<int> ll = new List<int>();
```

On peut utiliser un opérateur de cast pour convertir une classe de base en classe dérivée.

```csharp
IList<int> ll = new List<int>();
List<int> l = (List<int>)ll;
```

Si le cast échoue parce que le type de l'expression convertie n'est pas lié au type vers lequel elle est convertie, une instance de `InvalidCastException` est levée.

Une approche plus courante pour ces conversions de type consiste à utiliser le mot-clé [`is`][is-operator] :

```csharp
interface IFoo { int Bar(); }
class Foo : IFoo { public int Bar() { return 42; }}
Object r = new Random();
IFoo ifoo = new Foo();
Object o = new Foo();

int result = 1729;

if (ifoo is Foo foo)
{
    result = foo.Bar();
}
// result == 42

result = 1729;
if (o is Foo foo2)
{
    result = foo2.Bar();
}
// result == 42

result = 1729;
if (r is Foo foo3)
{
    result = foo3.Bar();
}
// result == 1729
```

Le mot-clé [`as`][as-operator] remplit une fonction similaire à `is`, par exemple `var foo = ifoo as Foo;`. Dans cet exemple, `foo` vaudra `null` si `ifoo` n'est pas de type `Foo`, sinon `ifoo` lui sera affecté.

## Opérateur de cast personnalisé

Les types peuvent définir leurs propres [opérateurs de cast][custom-casts] explicites et implicites personnalisés.

Dans la BCL, les conversions entre la structure `BigInteger` et d'autres types numériques sont des exemples de casts [explicites][big-integer-explicit] et [implicites][big-integer-implicit].

## Utilise `typeof`

Si tu as besoin de déterminer le type précis d'un objet, `is` peut être un peu trop permissif, car il convertit un objet en une classe ou en l'une de ses classes de base. Dans ce cas, `typeof` et `Object.GetType()` sont la solution.

```csharp
object o = new List<int>();

o is ICollection<int> // true
o.GetType() == typeof(ICollection<int>) // false
o is List<int> // true
o.GetType() == typeof(List<int>) // true
```
