# Introduction

En Factor, on combine des mots simplement en les écrivant les uns à la suite des autres : l'ordre dans lequel on les écrit *est* la façon dont ils s'enchaînent. (Les programmeurs appellent cela la *composition de fonctions*.) Le corps d'un mot est lui-même une suite de mots : chacun consomme des valeurs de la pile et empile son résultat, et le mot suivant reprend là où le précédent s'est arrêté. Ainsi, définir

```factor
! DOCTEST: SKIP   (cleanupname is hypothetical here — the exercise's job)
: firstletter ( name -- letter ) cleanupname first 1string ;
```

*est* déjà la composition de `cleanupname`, `first` et `1string`.

Cet exercice introduit aussi les **quotations** : un morceau de code que l'on peut stocker comme une valeur et exécuter plus tard, au lieu de l'exécuter sur-le-champ.

## Quotations

Une quotation est un morceau de code entouré de crochets. Elle ne s'exécute pas quand on l'écrit ; elle reste sur la pile comme une valeur :

```factor
[ 2 * ] .       ! => [ 2 * ]
```

`call` exécute une quotation :

```factor
3 [ 2 * ] call .    ! => 6
```

On écrit une quotation quand on a besoin de passer du code comme donnée : pour l'exécuter plus tard, ou pour le passer à un *combinateur*, c'est-à-dire un mot qui prend une quotation en entrée.

## `compose`

`compose ( quot1 quot2 -- combined )` colle deux quotations en une seule, en les exécutant dans l'ordre où elles sont écrites :

```factor
[ 2 * ] [ 1 + ] compose .    ! => [ 2 * 1 + ]
```

On trouve en général que définir un petit mot avec `:` ... `;` se lit mieux que `compose`, mais `compose` est pratique quand on a besoin de construire des quotations à la volée. Quand les briques de base ne sont pas déjà des quotations, `>quotation ( seq -- quot )` (de [`quotations`][quotations]) transforme une séquence de valeurs et de références de mots en une quotation appelable :

```factor
USING: quotations sequences ;

{ [ 1 ] [ 2 + ] [ 3 * ] } concat >quotation call .   ! => 9
```

## Applique une quotation à deux entrées

`bi@ ( x y quot -- ... )` exécute la quotation sur `x` puis à nouveau sur `y`, en laissant les deux résultats sur la pile :

```factor
3 4 [ 2 * ] bi@ .s
! => 6
! => 8
```

La tâche `couple` de l'exercice prend deux noms ; `bi@` est la façon naturelle d'appliquer `initial` à chacun.

## Quelques mots pour manipuler les _strings_

L'exercice a besoin de quelques petits mots pour les _strings_, tirés de trois vocabulaires : [`sequences`][sequences], [`ascii`][ascii] et [`strings`][strings] :

- `replace ( seq old new -- new-seq )` (dans `splitting`) : remplace une sous-chaîne.
- `[ blank? ] trim` (`trim` dans `sequences`, `blank?` dans `ascii`) : supprime les espaces blancs en début et en fin.
- `1string ( char -- str )` (dans `strings`) : transforme un caractère unique en _string_.
- `>upper ( str -- upper )` (dans `ascii`) : met une _string_ en majuscules.
- `append ( s1 s2 -- s )` (dans `sequences`) : concatène deux _strings_.
- `prepend ( s1 s2 -- s )` (dans `sequences`) : concatène `s2` puis `s1` (`append` avec ses entrées dans l'autre ordre).
- `glue ( s1 s2 sep -- s )` (dans `sequences`) : concatène deux _strings_ avec un séparateur entre elles.
- `surround ( seq pre post -- new )` (dans `sequences`) : entoure une _string_ d'un préfixe et d'un suffixe.

Les caractères Unicode peuvent s'écrire `\u{XXXX}` à l'intérieur d'une _string_, où `XXXX` est le point de code en hexadécimal. Le cœur `\u{2764}` (❤) apparaît dans cet exercice.

## Sortie formatée

Quand `append`, `glue` et `surround` ne sont pas assez expressifs, [`formatting`][formatting] fournit le `sprintf` de style printf :

```
sprintf ( inputs... format-string -- str )
```

`%s` insère une _string_, `%d` un entier, `%f` un nombre décimal ; des modificateurs facultatifs de largeur, de précision et de remplissage se placent entre `%` et la lettre du type :

```factor
USING: formatting ;

"Alice" "Bob" "%s & %s" sprintf .   ! => "Alice & Bob"
3.14159 "%.2f" sprintf .             ! => "3.14"
42 "%05d" sprintf .                  ! => "00042"
```

Pour passer d'un nombre à une _string_ et inversement, [`math.parser`][math.parser] fournit `number>string` et `string>number` :

```factor
USING: math.parser ;

42 number>string .       ! => "42"
"3.14" string>number .   ! => 3.14
```
