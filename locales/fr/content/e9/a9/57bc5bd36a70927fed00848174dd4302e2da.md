# Introduction

Il est temps d'aborder l'un des paradigmes fondamentaux du C++ : la programmation orientée objet (POO).
La POO s'articule autour des `classes`, des types de données définis par l'utilisateur, avec leur propre ensemble de fonctions associées.
On commencera par les bases, puis on abordera des sujets plus avancés plus bas dans l'arborescence du programme.

## Membres

Les classes peuvent avoir des **variables membres** et des **fonctions membres**.
On y accède avec l'opérateur de **sélection de membre** `.`.
Comme pour les variables en dehors des `classes`, il est conseillé d'initialiser les variables membres avec une valeur dès leur déclaration.
Cette valeur devient alors la valeur par défaut des objets nouvellement créés à partir de cette classe.

## Encapsulation et masquage de l'information

Les classes offrent la possibilité de restreindre l'accès à leurs membres.
Les deux cas de base sont `private` et `public`.
Les membres `private` ne sont pas accessibles depuis l'extérieur de la classe.
Les membres `public` peuvent être appelés librement.
Par défaut, tous les membres sont `private` et doivent être explicitement marqués pour être utilisables en dehors de la classe.

## Exemple de base

La définition d'une nouvelle `class` est illustrée dans l'exemple suivant.
Remarque le `;` après la définition.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

Tu peux accéder à toutes les variables depuis l'intérieur de la classe.
Regarde `damage` à l'intérieur de la fonction `cast_spell`.
Tu ne peux pas lire ni modifier les membres `private` en dehors de la classe :

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## Constructeurs

Les constructeurs permettent d'affecter des valeurs aux variables membres lors de la création de l'objet.
Ils portent le même nom que la `class` et n'ont pas de type de retour.
Une classe peut avoir plusieurs constructeurs.
C'est utile si tu n'as pas toujours besoin de définir toutes les variables.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

Les constructeurs sont un vaste sujet et comportent de nombreuses nuances.
Si tu ne définis pas explicitement de `constructor` pour ta `class`, alors, et seulement alors, le compilateur s'en charge à ta place.
C'est ce qui s'est passé dans le premier exemple ci-dessus.
L'objet _silverhand_ est créé en appelant le constructeur par défaut, sans qu'aucun argument ne soit passé.
Toutes les variables prennent la valeur indiquée dans la définition de la classe.
Si tu n'avais donné aucune valeur dans cette définition, les variables pourraient être non initialisées, ce qui pourrait avoir des conséquences inattendues.

## Structures

Les structures viennent des racines C d'origine du langage et sont aussi anciennes que le C++ lui-même.
Elles sont en pratique la même chose que les `classes`, à une exception importante près.
Par défaut, tout ce qui se trouve dans une `class` est `private`.
Les structures, quant à elles, sont `public` tant qu'on ne définit pas le contraire.
Par convention, le mot-clé `struct` est souvent utilisé pour les **structures ne contenant que des données**.
Le mot-clé `class` est préféré pour les objets qui doivent garantir certaines propriétés.
Un tel invariant pourrait être que le `damage` de ta `class` `Wizzard` ne puisse pas devenir négatif.
La variable `damage` est privée, et toute fonction qui modifie `damage` garantirait que l'invariant est préservé.
