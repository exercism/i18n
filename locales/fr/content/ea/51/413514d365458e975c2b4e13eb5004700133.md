# Les types de données génériques

Les génériques en Cairo te permettent d'écrire du code réutilisable qui fonctionne avec différents types, ce qui évite la duplication et améliore la maintenabilité.

On peut utiliser les génériques avec les fonctions, les structs, les enums, les traits et les méthodes.

## Les fonctions génériques

Une fonction générique opère sur différents types sans qu'il soit nécessaire d'écrire des implémentations séparées.

Par exemple :

```rust
fn largest_list<T>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Ici, `T` est un espace réservé pour n'importe quel type.

Cependant, Cairo exige des bornes de traits pour s'assurer que le type générique satisfait à des exigences précises.

Si `T` doit pouvoir implémenter `Drop`, on peut modifier la signature :

```rust
fn largest_list<T, impl TDrop: Drop<T>>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Les bornes de traits, comme `Drop` ou `PartialOrd`, ajoutent des contraintes aux génériques pour des opérations précises.

## Les contraintes anonymes

Si une implémentation de trait n'est pas utilisée directement dans une fonction, on peut écrire des contraintes anonymes à l'aide de `+` :

```rust
fn smallest_element<T, +PartialOrd<T>, +Drop<T>, +Copy<T>>(list: @Array<T>) -> T {
    let mut smallest = *list[0];
    let mut index = 1;

    while index < list.len() {
        if *list[index] < smallest {
            smallest = *list[index];
        }
        index += 1;
    };

    smallest
}
```

Cela évite de nommer les traits comme `TPartialOrd`, ce qui réduit la verbosité.

## Les structs avec des génériques

Les génériques dans les structs permettent de rendre les champs flexibles.

Par exemple :

```rust
#[derive(Drop)]
struct Wallet<T> {
    balance: T,
}

let w = Wallet { balance: 42 };
```

Si une struct nécessite plusieurs types génériques, il suffit d'ajouter d'autres espaces réservés :

```rust
#[derive(Drop)]
struct Wallet<T, U> {
    balance: T,
    address: U,
}

let w = Wallet { balance: 42, address: '0xabc' };
```

## Les enums avec des génériques

Les enums peuvent aussi contenir des types de données génériques.

Par exemple :

```rust
enum Option<T> {
    Some: T,
    None,
}
```

L'enum `Option<T>` peut représenter une valeur optionnelle de n'importe quel type.

De même, `Result<T, E>` permet de définir les types de succès et d'échec :

```rust
enum Result<T, E> {
    Ok: T,
    Err: E,
}
```

## Les méthodes génériques

Les méthodes peuvent aussi utiliser des génériques.

Par exemple :

```rust
#[derive(Copy, Drop)]
struct Wallet<T> {
    balance: T,
}

trait WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T;
}

impl WalletImpl<T, +Copy<T>> of WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T {
        *self.balance
    }
}

let w = Wallet { balance: 50 };
assert!(w.balance() == 50);
```

On peut aussi définir des méthodes pour des types génériques précis, comme `Wallet<u128>` :

```rust
trait WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128);
}

impl WalletReceiveImpl of WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128) {
        self.balance += value;
    }
}

let mut w = Wallet { balance: 50 };
w.receive(100);
assert!(w.balance() == 150);
```

## Mélange les types génériques

Les génériques peuvent gérer des combinaisons complexes.

Prenons l'exemple de deux instances de `Wallet` de types différents :

```rust
trait WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2>;
}

impl WalletMixImpl<T1, +Drop<T1>, U1, +Drop<U1>> of WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2> {
        Wallet { balance: self.balance, address: other.address }
    }
}

let w1 = Wallet { balance: true, address: 10 };
let w2 = Wallet { balance: 32, address: 100 };
let w3 = w1.mixup(w2);

assert!(w3.balance);
assert!(w3.address == 100);
```

Grâce aux contraintes `+Drop`, le compilateur garantit une gestion correcte des ressources.

Les génériques sont puissants, mais ils demandent une gestion attentive des contraintes.

Utilise-les pour écrire du code réutilisable, indépendant du type et concis.
