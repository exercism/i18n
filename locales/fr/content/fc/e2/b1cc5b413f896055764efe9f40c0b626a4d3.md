# Tables associatives et ensembles

| Type | Contient | Recherche par |
| --- | --- | --- |
| `ARRAY{T}` | des valeurs dans l'ordre | position |
| `FMAP{K,T}` | des paires clé-cible | clé |
| `FSET{T}` | des valeurs, sans répétition | appartenance |

## FMAP

```sather
   m ::= #FMAP{STR,INT};
   m := m.insert("emu", 2);
   m.get("emu")          -- 2
   m.has_ind("emu")      -- true
   m.size                -- 1
   m := m.delete("emu");
```

`m["emu"]` n'est **pas** la bonne façon de lire une table associative : `FMAP` n'a pas de telle routine, et cette ligne ne compilera pas. C'est `get`.

### Clés absentes

`get` sur une clé absente renvoie la valeur vide du type plutôt que de se plaindre : `0`, `false` ou _void_. Un `STR` _void_ n'échouera pas là où il est produit ; il échoue plus tard, là où il finit par être utilisé. Appeler `has_ind` en premier est l'habitude à prendre.

## FSET

```sather
   s ::= #FSET{STR};
   s := s.insert("emu");
   s.has("emu")          -- true
   s.size                -- 1
   s := s.delete("emu");
```

Les ensembles se combinent :

```sather
   a.union(b)            -- in either
   a.intersect(b)        -- in both
   a.difference(b)       -- in a but not b
   a.is_subset(b)
```

## Réaffecter et copier

`insert` et `delete` renvoient le conteneur à utiliser désormais. Le plus souvent, c'est le même objet, modifié sur place ; quand il doit grandir, c'est un nouvel objet, plus grand. Donc :

```sather
   m := m.insert(k, v);     -- always
```

et le nom à gauche est le seul auquel se fier ensuite. Un autre nom pour la même table, pris avant le `insert`, peut être périmé.

Pour conserver une copie indépendante, on en prend d'abord une :

```sather
   n ::= m.copy.insert(k, v);      -- m is unchanged
```

avec un écueil : une table dans laquelle on n'a jamais rien inséré est **_void_**, et `copy` sur une table _void_ échoue. `insert`, `get`, `has_ind` et `size` se débrouillent tous avec une table _void_ (c'est `#FMAP{K,T}` qui est _void_, et c'est en y insérant quelque chose qu'une table commence à exister), mais `copy` n'y arrive pas.

`HMAP` et `HSET` sont les versions qui ne changent jamais que sur place. Elles sont plus rapides pour construire quelque chose de grand, et elles constituent un mauvais choix par défaut quand on apprend.

## Les parcourir

| Itérateur | Donne |
| --- | --- |
| `m.ind!` | chaque clé |
| `m.target!` | chaque cible |
| `m.pair!` | chaque paire clé-cible |
| `s.elt!` | chaque valeur d'un ensemble |

Ni une table ni un ensemble n'a d'ordre. Deux exécutions peuvent les parcourir dans un ordre différent, alors n'écris jamais quelque chose qui dépend de ce qui vient en premier.

```sather
   loop
      #OUT + guide.ind! + "\n";
   end;
```
