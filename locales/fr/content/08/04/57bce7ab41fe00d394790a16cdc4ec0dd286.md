## Messages d'exception

Il est parfois nécessaire de [lever une exception](https://docs.python.org/3/tutorial/errors.html#raising-exceptions). Dans ce cas, il faut toujours inclure un **message d'erreur explicite** qui indique l'origine de l'erreur. Cela rend le code plus lisible et facilite grandement le débogage. Lorsque tu sais que l'erreur vient d'un type précis, tu peux lever l'un des [types d'erreur intégrés](https://docs.python.org/3/library/exceptions.html#base-classes), mais tu dois tout de même inclure un message explicite.

Cet exercice demande en particulier d'utiliser l'[instruction `raise`](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement) pour lever une `ValueError` si l'entrée n'a pas les délimiteurs appropriés, n'est pas en majuscules, ne forme pas un arbre avec des nœuds, ou ne forme pas d'arbre du tout. Les tests ne passeront que si tu fais un `raise` de l'`exception` et que tu y joins un message.

Pour lever une `ValueError` avec un message, écris le message en argument du type `exception` :

```python
# if the tree properties as given do not have proper delimiters.
raise ValueError("properties without delimiter")

# if the tree properties as given are not all in uppercase.
raise ValueError("property must be in uppercase")

# if the input does not form a tree, or is empty.
raise ValueError("tree missing")

# if the input is a tree without any nodes.
raise ValueError("tree with no nodes")
```
