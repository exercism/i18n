# Les tests

Exécute les tests avec :

```bash
$ wrenc exercise-name.spec.wren
```

Par exemple pour `hello-world` :

```bash
$ wrenc hello-world.spec.wren
```


## Comprendre les tests ignorés

La méthode `skip` indique à la suite de tests de ne pas exécuter un test en particulier.

- Pourquoi sont-ils ignorés ?

Pour permettre aux utilisateurs de se concentrer sur un test à la fois et de les activer un par un au fur et à mesure qu'ils font évoluer la solution.

- Comment les activer ?

Un test ignoré :

```js
// this test will be skipped and not run
skip.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

Il suffit de remplacer `skip.test` par `do.test`.

```js
// now the test will be run normally
do.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

## Crée ton premier module Wren

Les tests de ce parcours chargent ton implémentation en l'important comme un module Wren :
`import "./bob" for Bob`. Il n'y a pas de syntaxe particulière pour exporter ton
implémentation. Nomme simplement ta classe `Bob` pour qu'elle corresponde aux instructions
d'import `for Bob`, et tout devrait fonctionner.

```javascript
class Bob {
  static hey(message) {
    // Your solution to the exercise goes here
  }
}
```

Tu trouveras plus d'informations sur les modules dans la
[documentation sur la modularité de Wren][modularity].
Pour faciliter le démarrage, il y a un fichier Wren _skeleton_ dans le
répertoire de chaque exercice.

[modularity]: https://wren.io/modularity.html
