# À propos

Un [opérateur de comparaison][comparisons] en Python (_aussi appelé opérateur relationnel_), examine les _valeurs_ de deux [opérandes][operand] et renvoie un booléen `True` ou `False` selon que la condition de comparaison est remplie ou non.

Le tableau ci-dessous présente les opérateurs de comparaison les plus courants en Python :

| Opérateur | Opération | Description |
| -------- | -------------------------- | ------------------------------------------------------------------------- |
| `>`      | « supérieur à »             | `a > b` vaut `True` si `a` est **strictement** supérieur en valeur à `b`        |
| `<`      | « inférieur à »             | `a < b` vaut `True` si `a` est **strictement** inférieur en valeur à `b`        |
| `==`     | « égal à »                  | `a == b` vaut `True` si `a` est **strictement** égal à `b` en valeur            |
| `>=`     | « supérieur ou égal à »     | `a >= b` vaut `True` si `a > b` OU `a == b` en valeur                           |
| `<=`     | « inférieur ou égal à »     | `a <= b` vaut `True` si `a < b` ou `a == b` en valeur                           |
| `!=`     | « différent de »            | `a != b` vaut `True` si `a == b` vaut `False`                                   |
| `is`     | « identité »                | `a is b` vaut `True` si **_et seulement si_** `a` et `b` sont le même _objet_   |
| `is not` | « identité niée »           | `a is not b` vaut `True` si  **_et seulement si_** `a` et `b` ne sont **pas** le même _objet_       |
| `in`     | « test d'appartenance »     | `a in b` vaut `True` si `a` est un membre, un sous-ensemble ou un élément de `b`            |
| `not in` | « test d'appartenance niée » | `a not in b` vaut `True` si `a` n'est pas un membre, un sous-ensemble ou un élément de `b`  |

Ils ont tous la même priorité (_plus élevée que celle des [opérations booléennes][boolean operations], mais plus faible que celle des opérations arithmétiques ou bit à bit_).

## Comparaison entre différents types de données

Des objets de types différents (_sauf les types numériques_) ne sont jamais égaux par défaut lors d'une comparaison.
De même, des instances non identiques d'une `class` ne seront _**pas**_ considérées comme égales, sauf si la `class` définit des méthodes spéciales de [comparaison enrichie][rich comparisons] qui personnalisent le comportement de comparaison par défaut des `object`.
Pour plus (beaucoup plus) de détails, consulte [Comparaisons de valeurs][value comparisons] dans la documentation Python.

Les types numériques font (en grande partie) exception à cette règle de correspondance des types.
Un `integer` **peut** être considéré comme égal à un `float` (_ou un [`octal`][octal] égal à un [`hexadecimal`][hex]_), tant que les types peuvent être convertis implicitement pour la comparaison.

Pour les autres types numériques ([complexes][complex numbers], [décimaux][decimal numbers], [fractions][rational numbers]), les opérateurs de comparaison sont définis là où ils « ont du sens » (_là où la conversion implicite ne change pas le résultat_), mais lèvent une `TypeError` si les objets sous-jacents ne peuvent pas être convertis avec précision pour la comparaison.
Pour plus d'informations sur les règles que Python applique à la conversion numérique, consulte [conversions arithmétiques][arithmetic conversions] dans la documentation Python.

```python
>>> import fractions

# A string cannot be converted to an int.
>>> 17 == '17'
False

# An int can be converted to float for comparison.
>>> 17 == 17.0
True

# The fraction 6/3 can be converted to the int 2
# The int 2 can be converted to 0b10 in binary.
>>> 6/3 == 0b10
True

# An int can be converted to a complex 
# number with a 0 imaginary part.
>>> 17 == complex(17)
True

# The fraction 2/5 can be converted to the float 0.4
>>> 0.4 == 2/5
True

>>> complex(2/5, 1/2) == complex(0.4, 0.5)
True
```

Toute comparaison ordonnée d'un nombre avec un `NaN` (_not a number_, autrement dit « pas un nombre ») vaut `False`.
Un effet secondaire déroutant de la définition de `NaN` en Python est que `NaN` n'est jamais égal à `NaN`.
Si tu es curieux de savoir pourquoi `NaN` a été défini ainsi en Python, ce [post Stack Overflow sur NaN][so nan post] consacré à l'établissement de la norme internationale est une lecture intéressante.

```python
>>> x = float('NaN')

>>> 3 < x
False

>>> x < 3
False

# NaN never compares equal to NaN
>>> x == x
False
```

## Comparer des _strings_

Les _strings_ (`str`) sont comparées [_lexicographiquement_][lexographic order], en utilisant leurs points de code Unicode individuels (_le résultat de passer chaque point de code du `str` à la fonction intégrée [`ord()`][ord], qui renvoie un `int`_).
Si tous les points de code des deux _strings_ correspondent et sont _**dans le même ordre**_, les deux _strings_ sont considérées comme égales.
Cette comparaison s'effectue par paires, la première avec la première, la deuxième avec la deuxième, etc.
En Python 3.x, `str` et `bytes` ne peuvent pas être convertis ou comparés directement.

```python
>>> 'Python' > 'Rust'
False

>>> 'Python' > 'JavaScript'
True

# Examples with Mandarin.
# hello < goodbye
>>> '你好' < '再见'
True

# ord() of first characters
>>> ord('你'), ord('再')
(20320, 20877)

# ord() of second characters
>>> ord('好'), ord('见')
(22909, 35265)

# And with Korean words.
# Pretty < beautiful.
>>> '예쁜' < '아름다운'
False

>>> ord('예'), ord('아')
(50696, 50500)
```

## Comparer des types de conteneurs

Les types de conteneurs (_`lists`, `tuples`, `sets`, `dicts`, etc._) se comparent eux aussi de manière [_lexicographique_][lexographic order] : ils sont égaux si les deux conteneurs contiennent les mêmes données **et** les mêmes types de données (_dans le cas des `lists` et des `tuples`, ils doivent également avoir le même **ordre**_), et inégaux sinon.

```python
>>> [1, 2] == [1, 2]
True

# But if the data is not in the same order, they are not equal.
>>> [2, 1] == [1, 2]
False

# The same holds true for tuples
>>> (3,4,5) == (5,4,3)
False

# Length is also compared
>>> [1, 2] < [1, 2, 3]
True

# Comparing dicts
>>> {'name': 'John', 'age': 19} == {'name': 'John', 'age': 18}
False

>>> {'name': 'John', 'age': 19} == {'name': 'John', 'age': 19}
True
```

## Chaînage de comparaisons

Les opérateurs de comparaison peuvent être chaînés _de manière arbitraire_.
Note que l'évaluation d'une expression se fait de `left` à `right`.
Par exemple, `x < y <= z` est équivalent à `x < y and y <= z`, sauf que `y` n'est évalué **qu'une seule fois**.
Dans les deux cas, `z` n'est _pas_ évalué **du tout** lorsque `x < y` s'avère valoir `False`.
C'est ce qu'on appelle souvent l'évaluation en `short-circuit evaluation` : elle s'arrête dès que la valeur de vérité de l'expression a déjà été déterminée.

`Short circuiting` est pris en charge par divers opérateurs booléens, par des fonctions, ainsi que par le chaînage de comparaisons en Python.
Contrairement à de nombreux autres langages de programmation, notamment `C`, `C++`, `C#` et `Java`, les expressions chaînées comme `a < b < c` en Python ont une [interprétation mathématique][three way boolean comparison] et une priorité conventionnelles.

```python
>>> x = 2
>>> y = 5
>>> z = 10

>>> x < y < z
True

>>> x < y > z
False

>>> x > y < z
False
```

## Comparaisons d'identité

Les opérateurs `is` et `is not` testent l'[_identité_][object identity] d'un objet, par opposition à sa _valeur_.
L'identité d'un objet ne change jamais après sa création et peut être obtenue à l'aide de la fonction [`id()`][id function].

`<apple> is <orange>` est évalué à `True` si _**et seulement si**_ `id(<apple>)` == `id(<orange>)`.
`<apple> is not <orange>` donne l'inverse.

En raison de leur statut de singleton, `None` et `NotImplemented` doivent toujours être comparés aux éléments à l'aide de `is` et `is not`.
Consulte la documentation de référence Python sur les [comparaisons de valeurs][value comparisons none] et [PEP8][PEP8 programming recommendations] pour plus de détails sur cette convention.

```python

# A list of favorite numbers.
>>> my_fav_numbers = [1, 2, 3]

>>> your_fav_numbers = my_fav_numbers

>>> my_fav_numbers is your_fav_numbers
True

# The returned id will differ by system and Python version.
>>> id(my_fav_numbers)
4517478208

# your_fav_numbers is only an alias pointing to the original my_fav_numbers object.
# Assigning a new name does not create a new object.
>>> id(your_fav_numbers)
4517478208


>>> my_fav_numbers is not your_fav_numbers
False

>>> my_fav_numbers is not None
True

>>> my_fav_numbers is NotImplemented
False
```

## Comparaisons d'appartenance

Les opérateurs `in` et `not in` testent l'_appartenance_.
`<fish> in <soup>` est évalué à `True` si `<fish>` est un membre de `<soup>` (_si `<fish>` est un sous-ensemble de `<soup>` ou est contenu dans `comparison`_), et à `False` sinon.
`<fish> not in <soup>` renvoie la négation, c'est-à-dire l'_inverse_ de `<fish> in <soup>`.

Pour les types _string_ et bytes, `<name> in <fullname>` vaut `True` _**si et seulement si**_ `<name>` est une sous-chaîne de `<fullname>`.

```python

# A set of lucky numbers.
>>> lucky_numbers = {11, 22, 33}
>>> 22 in lucky_numbers
True

>>> 44 in lucky_numbers
False

# A dictionary of employee information.
>>> employee = {'name': 'John Doe', 'id': 67826, 'age': 33, 'title': 'ceo'}

# Checking for the membership of certain keys.
>>> 'age' in employee
True

>>> 33 in employee
False

>>> 'lastname' not in employee
True

# Checking for substring membership
>>> name = 'Super Batman'
>>> 'Bat' in name
True

>>> 'Batwoman' in name
False
```
