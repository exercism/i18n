# Introduction

Les chiffres binaires correspondent en fin de compte directement aux transistors de ton processeur ou de ta mémoire RAM, et à leur état, « allumé » ou « éteint ».

La manipulation de bas niveau, appelée informellement « _bit-twiddling_ », est particulièrement importante dans les langages système.

Les langages de plus haut niveau comme Kotlin masquent généralement la plupart de ces détails.
Cependant, une gamme de base d'opérations sur les bits [est disponible][ref-bitwise].

## Opérations de décalage de bits

Les types `Int` ou `Long`, signés ou non signés, peuvent être représentés comme une suite de 1 et de 0, puis manipulés comme une séquence de bits.

Étonnamment, les types `Byte` ou `Short` ne sont pas compatibles avec la plupart des opérations bit à bit en Kotlin.
Tous les exemples ci-dessous utilisent des entiers 32 bits (`Int` ou `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Un décalage de bits déplace simplement tout vers la gauche ou vers la droite d'un nombre de positions donné.
Certains bits disparaissent d'un côté, et l'autre côté est complété par des zéros ou des uns.

- Décalage à gauche avec `shl` : complément par des zéros.
- Décalage à droite avec `shr` ou `ushr` : complément par des zéros pour les nombres positifs (voir plus loin le cas des nombres négatifs).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Chaque décalage à gauche double la valeur, et chaque décalage à droite la divise par deux (sous réserve de troncature).
C'est plus évident en représentation décimale :

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Ce type de décalage de bits est bien plus rapide que l'arithmétique « classique », ce qui rend la technique très populaire dans la programmation de bas niveau.

Avec les _entiers négatifs_, il faut être un peu plus prudent.

Les valeurs négatives sont stockées sous forme de [complément à deux][wiki-2complement], ce qui signifie que le bit le plus à gauche vaut 1.
Aucun problème pour un décalage à gauche, mais lors d'un décalage à droite, comment compléter les bits les plus à gauche ?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

L'opérateur `shr` effectue un [décalage arithmétique][wiki-arithmetic], qui préserve le bit de signe.

L'opérateur `ushr` effectue un [décalage logique][wiki-logical], en complétant par des zéros comme si le nombre était non signé.

## Logique bit à bit

On a vu dans le [concept Booléens][concept-booleans] que les opérateurs `&&` (et), `||` (ou) et `!` (non) s'utilisent avec des valeurs booléennes.

Il existe des opérateurs équivalents `and`, `or`, `xor` ([ou exclusif][wiki-xor]) pour comparer les bits de deux entiers, ainsi qu'une fonction `inv` (inversion) pour inverser tous les bits.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
