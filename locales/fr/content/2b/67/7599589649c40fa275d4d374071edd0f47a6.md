# Instructions

Elena, la nouvelle responsable qualité d’une usine de journaux, te demande d’écrire un petit logiciel pour surveiller la salle de production.

## 1. Définis une erreur personnalisée

Définis une classe de tuple d’erreur `machine-error` à l’aide du mot d’analyse `ERROR:`. Elle n’a pas besoin de _slots_.

```factor
machine-error   ! throws a fresh machine-error
```

## 2. Vérifie l’humidité

Définis `check-humidity`. Elle prend une mesure d’humidité sur la pile et `throw` la _string_ `"humidity too high"` lorsque la mesure est strictement supérieure à `70`. Sinon, elle ne renvoie rien.

```factor
50 check-humidity   ! returns nothing
80 check-humidity   ! throws "humidity too high"
```

## 3. Vérifie la température

Définis `check-temperature`. Elle prend une mesure de température et `throw` la _string_ `"temperature too high"` lorsque la mesure est strictement supérieure à `500`. Sinon, elle ne renvoie rien.

```factor
400 check-temperature   ! returns nothing
600 check-temperature   ! throws "temperature too high"
```

## 4. Surveille la machine

Définis `monitor` pour qu’elle prenne une mesure d’humidité et une mesure de température sur la pile, puis exécute les deux vérifications. Si l’une des vérifications lève une erreur, `monitor` doit lever une nouvelle `machine-error` à la place. Si les deux vérifications réussissent, `monitor` ne renvoie rien.

```factor
50 400 monitor   ! returns nothing
80 400 monitor   ! throws a machine-error
50 600 monitor   ! throws a machine-error
```

## 5. Surveille un lot de mesures

Définis `monitor-batch` pour qu’elle prenne un tableau de mesures `{ humidity temperature }` et renvoie combien d’entre elles échoueraient (c’est-à-dire combien feraient échouer `monitor`).

```factor
{ { 50 400 } { 80 400 } { 50 600 } { 60 200 } } monitor-batch .
! => 2
```
