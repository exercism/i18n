# À propos

Les _hash-sets_ implémentent le [protocole][set-protocol] [`sets`][sets] en s'appuyant en interne sur le hachage, ce qui donne en moyenne une insertion, une recherche et une suppression en O(1).
Ils sont mutables sur place, ce qui les rend idéaux pour le motif du _visited set_ quand on parcourt un graphe.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| mot           | effet                                     |
|---------------|-------------------------------------------|
| `HS{ }`       | littéral _hash-set_ vide (partagé : pense à le `clone`r !) |
| `>hash-set`   | `( seq -- set )` : construit un nouvel ensemble à partir d'une séquence (élimine les doublons) |
| `adjoin`      | `( elt set -- )` : insertion destructive  |
| `in?`         | `( elt set -- ? )` : appartenance         |
| `delete`      | `( elt set -- )` : suppression destructive |
| `cardinality` | `( set -- n )` : nombre d'éléments        |
| `null?`       | `( set -- ? )` : vrai quand l'ensemble est vide |
| `members`     | `( set -- seq )` : énumère sous forme de séquence |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )` : convertit `set` vers la classe de `exemplar` |

Pour construire un ensemble à partir de données que tu as déjà, `>hash-set` convertit
n'importe quelle séquence en une seule étape, en écartant les doublons : `{ 2 3 2 5 } >hash-set`
donne `HS{ 2 3 5 }`. C'est l'équivalent en bloc de la construction d'un ensemble par des
`adjoin` répétés.

Un point subtil concernant `in?` par rapport à `member?` (de
`sequences`) : les deux testent l'appartenance, mais `member?` parcourt
la séquence de façon linéaire, tandis que `in?` passe par la méthode de
protocole du type d'ensemble concerné. Pour `HS{ }`, il s'agit d'une
recherche par hachage. Utilise `in?` dès que ton conteneur
« _visited_ » contient plus de quelques éléments.

`null?` répond à la question « cet ensemble est-il vide ? » sans calculer
tout le `cardinality`. C'est le test naturel pour « reste-t-il quelque
chose à traiter ? ». Pour une liste de travail conservée sous forme
d'ensemble, `[ set null? ]
[ … ] until` la vide jusqu'à ce qu'il ne
reste rien.

## Se marie bien avec les tables de hachage

`HS{ }` pour répondre à « X a-t-il été visité ? » se marie naturellement
avec `H{ }` pour « quels sont les voisins de X ? ». Un DFS de manuel,
c'est simplement :

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

L'ensemble _visited set_ évite le travail en double ; la pile fait
circuler les nœuds de la frontière (LIFO via `push`/`pop`) ; la table des
voisins (une table de hachage) fournit le graphe. L'ordre de visite n'a
pas d'importance pour une question d'accessibilité, et c'est pourquoi un
vecteur utilisé comme pile suffit. Un vrai BFS sur la même structure
remplace le vecteur par une [`<dlist>`][dlist] et retire les éléments par
le début.
