# Introduction

Les littéraux sont des valeurs fixes utilisées directement dans le code.
Ils ne nécessitent aucun calcul à l'exécution.
Ils se présentent sous différentes formes afin de représenter efficacement différents types de données.
Les littéraux les plus fréquents sont de nature numérique, mais il existe aussi des opérateurs littéraux pour les types date, heure et _string_.
Un concept ultérieur montrera comment utiliser des opérateurs littéraux définis par l'utilisateur.

## Littéraux numériques

Les littéraux numériques incluent les représentations décimale, octale, hexadécimale et binaire.
Ces bases ont déjà été abordées dans le [concept sur les nombres][numbers-concept].

Toutes les représentations comme `23`, `0x50f7ba11` et `0xba5eba11` sont comprises comme des `int` par le compilateur.
Le type `int` général est signé et ([selon le compilateur et le système][in-depth-integers]) couvre souvent une plage de `-2'147'483'648` à `2'147'483'647`.
Cela suffit la plupart du temps et tu n'as pas besoin de te soucier du type précis.

Certains cas d'usage exigent des plages plus grandes ou une très faible empreinte mémoire des programmes.
Pour être explicite, on peut indiquer directement un type entier précis avec le littéral numérique.

Quand les nombres négatifs ne sont pas nécessaires, mais que la plage supplémentaire est souhaitée, on utilise le suffixe `u` ou `U` pour les entiers _non signés_.
Pour des plages plus grandes, `L` ou même `LL` peuvent être utilisés pour les types long et long long.

~~~~exercism/caution
L'usage d'un `l` minuscule est autorisé, mais il se confond facilement avec le chiffre `1` et est donc déconseillé.
~~~~

```cpp
auto net_worth_christian_grey{2'500'000'000U}; // out of range for 32-bit integers
auto net_worth_carlisle_cullen{46'000'000'000LL}; // int and uint are not enough
```

Les nombres à virgule flottante sont généralement résolus en `double` lors de la compilation.
C'est un bon choix par défaut, et les cas d'usage avec le type `float`, plus étroit, sont moins fréquents que l'exemple non signé ci-dessus.

~~~~exercism/advanced
La [norme C++23][cpp23-literals] introduit un contrôle plus fin avec des littéraux comme `f128` ou `F16`.
Certains compilateurs autorisent leurs propres littéraux.
GCC permet l'usage de `d` comme littéral, mais cela n'est pas prévu par la norme et peut nuire à la compatibilité multiplateforme.

[cpp23-literals]: https://en.cppreference.com/w/cpp/language/floating_literal

~~~~

```cpp
auto light_year_in_m{9.46073e+15f}; // well in the range of float
auto earth_to_edge_comoving_distance_in_nm{4.32355e+32}; // needs double type for magnitude
auto eulers_number{2.718281828459045}; // needs double type for precision
```

## Littéraux de caractères et de chaînes de caractères

D'autres concepts ont déjà utilisé des littéraux de caractères entre apostrophes, comme `'}'` ou `'@'`.

En C++, `char` est limité aux 128 premiers [codes ASCII][ascii-code].
Pour utiliser plusieurs caractères ASCII ou des caractères ASCII étendus comme `‰`, voire des caractères Unicode comme `麗` et `ẞ`, d'autres types sont nécessaires.
Dans un concept précédent, les littéraux de _string_ ont été introduits avec des _guillemets doubles_ : `"一体どういう意味ですか。C++です"`.
Le type réel de cette phrase japonaise est `const char (&)[46]`, une chaîne de style C.

L'usage des littéraux de _string_ n'est pas activé par défaut.
Pour utiliser le littéral _string_ `""s` ou le littéral _string-view_ `""sv`, il faut préciser leur usage en utilisant l'espace de noms correspondant :

```cpp
#include <string>
#include <string_view>

using namespace std::literals;

auto green_light{"무궁화 꽃 이 피었 습니다"};
// green_light type is const char (&)[36]
auto umbrella{"달고나"s};
// umbrella type is std::basic_string<char>, the same as std::string
auto il_nam{"보는 것이 하는 것보다 더 재미있을 수가 없지"sv};
// il_nam type is std::basic_string_view<char>
```

Une _string_view_ peut être considérée comme une référence vers une chaîne constante.
