# À propos

Les [closures][closures] en Swift sont des blocs de code autonomes auxquels on peut passer des paramètres pour déclencher leur calcul et qui renvoient des valeurs.
Les _closures_ capturent aussi des valeurs de leur environnement et les utilisent dans leurs calculs.
Comme elles sont autonomes, elles peuvent circuler dans un programme comme n'importe quelle autre valeur, ou être affectées à des constantes et à des variables.

Les _closures_ peuvent sembler très proches des fonctions Swift ; c'est le cas, et pour une bonne raison.
Les fonctions en Swift sont des cas particuliers de _closures_ : elles doivent avoir un nom et se définissent avec une syntaxe légèrement différente.

Bien que les fonctions en Swift soient techniquement des _closures_, quand on parle de « _closures_ » en Swift, on désigne les [expressions de _closure_][closure-expressions].
Une expression de _closure_ s'écrit sous la forme d'une liste de paramètres suivie d'un type de retour et du mot-clé `in`, puis du corps de la _closure_, le tout entre accolades :

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}
```

Ceci définit une expression de _closure_ de type `(Double, Double) -> Double`, que l'on peut exécuter de la même manière qu'une fonction de ce type, en l'appliquant à des paramètres du type approprié :

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}(10.0, 15.0)
// returns 12.5
```

Comme il n'est pas très pratique de réécrire l'expression de _closure_ complète chaque fois qu'on veut l'exécuter, on peut affecter des _closures_ à des noms, comme n'importe quelle autre valeur en Swift.
On peut ensuite les appeler en appliquant ce nom aux paramètres :

```swift
let mean = { (a: Double, b: Double) -> Double in
  (a + b) / 2.0
}

mean(13.0, 100.0)
// returns 56.5
```

Comme on le voit ci-dessus, les _closures_, tout comme les fonctions ordinaires, peuvent omettre le mot-clé `return` si le corps de la _closure_ tient en une seule expression.

Le plus souvent, les _closures_ s'utilisent avec des fonctions d'ordre supérieur, soit passées en paramètres, soit renvoyées comme résultats :

```swift
[11, 75, 3, 99, 53].contains(where: { (x: Int) -> Bool in x > 100 })
// returns false

["apple", "ball", "carrot"].sorted(by: { (s1: String, s2: String) -> Bool in s1.count < s2.count })
// returns ["ball", "apple", "carrot"]

func makeAdder(base: Int) -> (Int) -> Int {
  { (x: Int) -> Int in base + x }
}
```

## Inférence des types de _closure_

Quand le type de retour ou les types des paramètres peuvent être [inférés à partir du contexte][inferring-closure-types], on peut les omettre dans l'expression de _closure_.
De plus, si l'on peut omettre les types des paramètres, on peut aussi omettre les parenthèses autour de leurs noms :

```swift
let mean: (Double, Double) -> Double = { a, b in a + b / 2.0 }

func makeAdder(base: Int) -> (Int) -> Int {
  { x in base + x }
}

["apple", "ball", "carrot"].sorted(by: { s1, s2 in s1.count < s2.count })
```

- Dans le premier exemple, le type peut être inféré à partir de l'annotation sur la constante `mean`.
- Dans le deuxième, le compilateur sait, d'après la définition de `makeAdder`, que `base` est un entier et que la fonction renvoyée doit être de type `(Int) -> Int`. À partir de là, il peut vérifier que si `x` est un `Int`, alors la _closure_ aura le type `(Int) -> Int`, et l'on peut donc omettre la signature de type dans la _closure_, puisque `(Int) -> Int` est la seule signature valide qu'elle puisse avoir.
- Le troisième exemple est similaire, mais le compilateur doit tirer une partie des informations de type du tableau avec lequel la méthode est utilisée. Il sait que la méthode `sorted(by:)` prend en paramètre une _closure_ à deux paramètres, du même type que les éléments de la collection triée, et qui renvoie un `Bool`, si bien que le compilateur peut en déduire que le type de retour de la _closure_ doit être `Bool`. Et comme la méthode est utilisée avec un tableau de `String`, il peut déterminer que les types des paramètres `s1` et `s2` doivent tous deux être `String`.

## Limites des _closures_

Comme on l'a mentionné plus haut, les fonctions et les _closures_ se ressemblent beaucoup en Swift, mais il existe quelques différences importantes :

- Les _closures_ ne peuvent pas utiliser d'étiquettes d'argument externes. Il n'existe aucun moyen de les définir, et essayer d'utiliser le nom d'un paramètre lors de l'appel de la _closure_ provoque une erreur :

```swift
let add5 = { x in x + 5 }
add5(x: 10)
// Error: Extraneous argument label 'x:' in call
```

- Les paramètres d'une _closure_ ne peuvent pas avoir de valeur par défaut.
- Les paramètres d'une _closure_ peuvent être variadiques, mais ils doivent avoir un nom et une annotation de type.
