# À propos

## Caractères

Un [encodage de caractères][char-encoding] est une convention précise utilisée pour représenter les éléments d'un texte en langue naturelle sous forme de séquence d'octets.
Un « élément de texte » peut ici être n'importe quelle unité qui a un sens dans une langue naturelle : par exemple, des lettres, des espaces, de la ponctuation, des émojis, des idéogrammes, etc.

NASM (The Netwide Assembler, l'assembleur utilisé par ce parcours) prend en charge la définition de données à l'aide de l'[ASCII][ascii].

Les constantes de caractères en NASM peuvent faire jusqu'à 8 octets et peuvent être définies avec des guillemets simples (`'`), des guillemets doubles (`"`) ou des accents graves (`` ` ``) :

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Les caractères spéciaux doivent être définis entre accents graves et échappés avec `\` :

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASM prend aussi en charge les [caractères Unicode][unicode] en [UTF-8][utf8], spécifiés avec `\u` ou `\U` et entre accents graves :

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

Note qu'il n'existe pas de prise en charge native d'un quelconque encodage de caractères en x86-64 en tant que type distinct.
En assembleur, les données sont une séquence d'octets, et l'interprétation de ces octets comme un caractère, un nombre ou autre chose est laissée au programmeur.

Par exemple, le caractère ASCII '0' est un seul octet de valeur 48.
Ainsi, stocker 48 dans un octet revient exactement à stocker le caractère ASCII '0' :

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Pour cette même raison, on manipule les caractères en transformant directement les valeurs de ces octets :

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## *Strings*

Une [_string_][string] est une séquence de caractères.
En assembleur, elle est généralement implémentée sous forme de tableau.

Il est possible de déclarer une _string_ en NASM de la même manière qu'on déclarerait n'importe quel tableau :

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Une différence entre les _strings_ et les autres tableaux est que NASM prend aussi en charge la déclaration de _strings_ sans virgule (`,`) pour séparer les valeurs.
Il est aussi possible d'alterner les valeurs avec des virgules :

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Note que, comme déjà mentionné, les caractères ne sont que des octets (ou une séquence d'octets en encodage Unicode) :

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Comme chaque caractère ASCII occupe un seul octet, tout octet suivant dans une taille plus grande vaut `0`.
Par exemple, déclarer `'a'` comme un qword (8 octets) signifie que le premier octet est `'a'` (`97`) et que les sept autres octets valent tous `0`.

Pour cette raison, tous ces exemples sont équivalents :

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
En assembleur, les _strings_ ne se terminent pas automatiquement par un caractère NUL ASCII (valeur `0`).

Lorsqu'on interagit avec des langages de plus haut niveau, comme le C, il revient au programmeur de s'assurer que le bon terminateur, s'il y en a un, est ajouté à la fin d'une _string_.
~~~~

## Les instructions _string_

Comme les _strings_ sont des tableaux, on peut les manipuler de la même manière que n'importe quel tableau, en déréférençant explicitement la mémoire :

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

En plus de cela, il existe quelques instructions pour charger, déplacer et stocker des valeurs dans des séquences d'octets en mémoire.
Bien qu'on les appelle instructions _string_, on peut les utiliser avec n'importe quelle séquence d'octets en mémoire, c'est-à-dire avec n'importe quel tableau :

| instruction  | ce qu'elle fait                                                                                                   |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | charge dans `rax` une valeur depuis un emplacement mémoire indiqué par `rsi`                                      |
| [stos][stos] | stocke une valeur de `rax` dans un emplacement mémoire indiqué par `rdi`                                          |
| [movs][movs] | copie une valeur depuis un emplacement mémoire indiqué par `rsi` et la stocke dans un emplacement mémoire indiqué par `rdi` |
| [cmps][cmps] | compare la valeur d'un emplacement mémoire indiqué par `rsi` avec la valeur d'un emplacement mémoire indiqué par `rdi` |
| [scas][scas] | compare la valeur de `rax` avec la valeur d'un emplacement mémoire indiqué par `rdi`                              |

Note que ces instructions ne prennent _aucun_ opérande explicite.
Leurs opérandes sont implicites.

En règle générale :

1. Lorsque leur opérande source est un emplacement mémoire, son adresse doit être stockée dans `rsi` (`s` pour source).
2. Lorsque leur opérande destination est un emplacement mémoire, son adresse doit être stockée dans `rdi` (`d` pour destination).
3. Si l'un des opérandes n'est pas un emplacement mémoire, il s'agit du registre `rax`.

Note que ces instructions déréférencent automatiquement les adresses mémoire en fonction de l'opération précise qu'elles effectuent.

Toutes peuvent opérer sur différentes tailles.
Un suffixe est ajouté pour indiquer cette taille :

| suffixe | signification | taille   |
| :-----: | ------------- | :------- |
|  `b`    | byte          | 1 octet  |
|  `w`    | word          | 2 octets |
|  `d`    | dword         | 4 octets |
|  `q`    | qword         | 8 octets |

Par exemple :

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

Elles mettent aussi à jour toute adresse utilisée, de la taille de l'opération.
Cette mise à jour se fait en fonction de la valeur du **drapeau de direction (DF)** :

- Si le `DF` est à 0, les adresses sont _augmentées_ de la taille de l'opération.
- Si le `DF` est à 1, les adresses sont au contraire _diminuées_ de la même quantité.

L'ABI System V précise que le drapeau de direction doit être à 0 à l'entrée d'une fonction.
Ainsi, _par défaut, la mémoire est lue et écrite dans l'ordre croissant des adresses_.

L'instruction [cld][cld] permet de mettre le drapeau de direction à 0, tandis que l'instruction [std][std] permet de le mettre à 1 :

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
L'appelant s'attend à ce que le `DF` soit remis à 0 après le retour de toute fonction appelée, conformément à l'ABI System V.
Si tu positionnes un jour le `DF` à 1, veille bien à le remettre à 0 avant `ret`.
~~~~

### Lods

Cette instruction _lit_ un emplacement mémoire dont l'adresse se trouve dans `rsi` et copie la valeur dans `rax`.

La valeur de `rsi` est mise à jour du nombre d'octets lus :

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

Cette instruction copie la valeur de `rax` et l'_écrit_ dans un emplacement mémoire dont l'adresse se trouve dans `rdi`.

La valeur de `rdi` est mise à jour du nombre d'octets écrits :

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

Cette instruction _lit_ un emplacement mémoire dont l'adresse se trouve dans `rsi` et _écrit_ la valeur dans un emplacement mémoire dont l'adresse se trouve dans `rdi`.
La valeur de `rax` n'est pas affectée par cette instruction.

`rsi` et `rdi` sont tous deux mis à jour du nombre d'octets copiés d'un emplacement mémoire à l'autre :

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

Cette instruction _lit_ un emplacement mémoire dont l'adresse se trouve dans `rsi` et _lit_ aussi un emplacement mémoire dont l'adresse se trouve dans `rdi`.
Elle compare ensuite les valeurs et met à jour les drapeaux, comme `cmp`.

`rsi` et `rdi` sont tous deux mis à jour du nombre d'octets lus dans les deux emplacements :

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

Cette instruction compare la valeur de `rax` avec la valeur qu'elle _lit_ dans un emplacement mémoire dont l'adresse se trouve dans `rdi`.
Elle met ensuite à jour les drapeaux, comme `cmp`.

La valeur de `rdi` est mise à jour du nombre d'octets lus :

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

Outre celles-ci, l'instruction [rep][rep] n'interagit pas directement avec la mémoire.
Elle peut en revanche être ajoutée comme préfixe aux autres instructions mentionnées, _répétant_ ces instructions.

Lorsqu'elles sont préfixées par `rep`, les instructions _string_ sont répétées un nombre de fois égal à la valeur de `rcx`.
À chaque répétition, la valeur de `rcx` est diminuée de `1`.
Note que la valeur de `rcx` doit être définie avant d'utiliser l'instruction :

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

Outre l'utilisation de `rcx` comme compteur, `repe` (ou `repz`) et `repne` (ou `repnz`) arrêtent l'exécution si le `zero flag (ZF)` est à 0 ou à 1, respectivement :

| instruction      | où elle peut être ajoutée | peut s'arrêter plus tôt       |
| ---------------- | ------------------------- | ----------------------------- |
| `rep`            | `movs`, `lods`, `stos`    | non                           |
| `repe`,`repz`    | `cmps`, `scas`            | oui, s'arrête quand ZF vaut 0 |
| `repne`, `repnz` | `cmps`, `scas`            | oui, s'arrête quand ZF vaut 1 |

~~~~exercism/advanced
Sur les processeurs modernes, `rep movs` et `rep stos` sont généralement des options rapides pour déplacer des données par gros blocs.
Les autres instructions _string_, et même `movs` et `stos` lorsqu'elles opèrent sans `rep`, sont en revanche généralement plus lentes qu'une simple boucle.

Pour aller plus loin sur ce sujet, voir [le chapitre 16.9, « String instructions », de cet ouvrage de référence][agner-optimization-guide].
