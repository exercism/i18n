# Introduction

Les types personnalisés permettent de définir de nouveaux types de données en Gleam. Ils peuvent avoir plusieurs _variantes_, chacune avec son propre nom.

```gleam
pub type Season {
  Spring
  Summer
  Autumn
  Winter
}
```

Chaque variante d'un type personnalisé peut, de façon facultative, porter des données, et des variantes différentes peuvent porter des types de données différents. Lorsqu'une variante porte des données, on parle d'un _enregistrement_.

```gleam
pub type Number {
  SomeInt(Int)
  SomeFloat(Float)
  Invalid
}
```

Pour créer une valeur pour une variante donnée, on peut faire référence à son nom si elle ne porte pas de données supplémentaires (`Spring`), ou l'appeler comme une fonction si elle en porte (`SomeInt(2)`).

```gleam
let spring = Spring
let integer_two = SomeInt(2)
```

Les types personnalisés, comme tout le reste en Gleam, possèdent une _égalité structurelle_, ce qui signifie que deux valeurs de la même variante portant les mêmes données sont équivalentes.

```gleam
Spring == Spring // -> True
Spring == Autumn // -> False
SomeInt(2) == SomeInt(2) // -> True
SomeInt(2) == SomeFloat(2.0) // -> False
```

On peut faire du filtrage par motif sur les variantes d'un type personnalisé à l'aide d'expressions `case`.

```gleam
import gleam/int
import gleam/float

pub fn describe(flexible_number: Number) -> String {
  case flexible_number {
    SomeFloat(f) -> "Float: " <> float.to_string(f)
    SomeInt(i) -> "Int: " <> int.to_string(i)
    Invalid -> "Neither a float nor an int"
  }
}
```
