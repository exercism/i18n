# Conseils de _workflow_

## Écris et évalue du code Unison

Tu écris du code Unison dans des fichiers dont le suffixe est `.u`. On les appelle des fichiers _scratch_ parce que tu les utilises pour écrire du code Unison, mais c'est le Unison Codebase Manager (UCM) qui stocke et enregistre en fin de compte le contenu de ces fichiers. Tu continueras à soumettre ces fichiers via l'Exercism CLI, mais on peut considérer l'UCM comme la « source de vérité » du code Unison.

Bien qu'Unison n'ait pas de REPL (Read Evaluate Print Loop), tu peux évaluer rapidement des expressions Unison dans des _watch expressions_. Dans ton fichier avec le suffixe `.u`, commence une ligne par `>` et saisis une expression à droite.

```
> myFunction 42 "hi"
```

L'UCM affiche le résultat de l'évaluation de l'expression dès que tu enregistres le fichier. Ça peut servir à dépanner tes implémentations d'exercices.

Pour un _workflow_ Exercism plus approfondi, voici une [vidéo de démonstration][walk-through-vid] qui montre comment implémenter et tester un problème Exercism.

```exercism/caution
La vidéo de démonstration montre le _workflow_ de l'ancienne version d'Unison. Pour le nouveau _workflow_, consulte [cette page](https://exercism.org/docs/tracks/unison/tests), qui décrit le nouveau workflow de projet.
```

## Organisation de la base de code

Une base de code Unison s'organise en _namespaces_. Les _namespaces_ fonctionnent un peu comme des répertoires dans un système de fichiers, sauf qu'au lieu de contenir des fichiers, ils contiennent tes types et tes fonctions Unison. Les chemins de _namespaces_ sont séparés par des points, `.`. Par exemple, on peut désigner le _namespace_ `Text` du _namespace_ `base` par `base.Text`.

On te recommande de créer un _namespace_ pour chaque exercice que tu fais, ou d'y faire un `cd`.

## Imports

La syntaxe d'Unison pour gérer et spécifier les imports est la syntaxe `use`. Par exemple, `use base.data.List` fait entrer dans la portée toutes les fonctions du _namespace_ `base.data.List`. C'est utile quand tu utilises une fonction comme `map` sur une `List` et qu'il faut la distinguer d'autres fonctions `map` comme `Optional.map`. Tu peux aussi importer des fonctions précises en faisant suivre le _namespace_ d'une liste de fonctions séparées par des espaces, comme dans : `use base.data.List tails head flatMap`.

Tu peux utiliser la syntaxe `use` aussi bien au niveau supérieur d'un fichier qu'à l'intérieur de fonctions pour spécifier des imports. Les clauses `use` respectent les règles de portée lexicale, donc les imports les plus imbriqués sont prioritaires sur les moins imbriqués.

## Bibliothèque standard

La bibliothèque standard d'Unison s'appelle `base`. Par défaut, elle est téléchargée dans les nouvelles bases de code Unison. Tu peux parcourir les fonctions disponibles pour tes implémentations via le dépôt en ligne de code Unison, [Unison share][unison-share], ou via [l'interface locale de la base de code][local-codebase-ui], ou encore en effectuant une recherche dans le Unison Codebase Manager (UCM). On verra ça juste après.

## Navigue dans le Unison Codebase Manager (UCM)

Pour obtenir la liste complète des commandes de l'UCM, saisis `help` dans l'UCM. En voici quelques astuces et conventions.

Tu peux rechercher des termes par nom ou par préfixe de _namespace_ dans l'UCM avec la commande `find`, mais `find` prend aussi en charge la recherche _par type_ dans une base de code. Pour rechercher une fonction par sa signature de type, saisis `find` suivi d'un espace et d'un deux-points, par exemple `find : [a] -> [[a]]`.

Tu peux lister le contenu d'un _namespace_ avec la commande `ls`, par exemple `ls base.data.List` ou `ls .exercism.helloWorld`. Beaucoup de commandes de l'UCM acceptent aussi bien des chemins de _namespace_ relatifs que des chemins de _namespace_ complets. Les chemins complets commencent par un `.` qui représente la « racine » de ta base de code.

Déplace-toi dans l'UCM avec la commande `cd` dans la CLI. Si un _namespace_ n'existe pas, `cd` en _crée_ un quand tu y vas. Pour remonter d'un niveau dans les _namespaces_, tu peux utiliser `cd ..`.

## Dépannage

__Quand je charge les tests, l'UCM ne trouve pas mon implémentation de l'exercice.__

Vérifie que tu enregistres bien ton fichier _stub_ dans ton éditeur de texte et que tu fais `update` des termes de ta base de code avant de charger les tests.

__Je rencontre des conflits de noms. Je ne peux pas avoir deux termes appelés `tests`.__

Tu peux avoir deux termes du même nom dans des _namespaces_ différents. Si tu fais des exercices Exercism, il est recommandé de créer un _namespace_ distinct pour chaque exercice, afin que les tests et les _stubs_ soient séparés des autres.

__Mes tests passent en local, mais pas sur l'exécuteur de tests.__

Désolé ! Vérifie d'abord que tes imports ne font référence à rien d'autre qu'à la bibliothèque standard, `base`, et aux fonctions définies dans le fichier `scratch` testé. Si c'est le cas, n'hésite pas à nous le signaler sur le Slack Exercism, dans le canal `#track-unison`, ou en ouvrant une issue sur [le dépôt du parcours Unison][unison-track-repo].

__Si tu rencontres le moindre problème, n'hésite pas à nous le dire ! 🙂__
