# Introduction

Les [types personnalisés][custom-types] en Elm représentent un nombre fixe de cas nommés. Chaque valeur correspond à exactement un de ces cas nommés.

Un type personnalisé se définit à l'aide du mot-clé `type` et ne demande que très peu de syntaxe. C'est l'une des techniques les plus importantes de la programmation en Elm : on s'en sert pour que les valeurs possibles dans le code correspondent exactement aux valeurs valides dans la vie réelle, ce qui ne laisse aucune place aux données invalides et rend [impossible la représentation d'états impossibles dans le code][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Chaque cas d'un type personnalisé peut, de façon facultative, porter des données qui lui sont associées, et des cas différents peuvent porter des types de données différents. Si aucun des cas ne porte de données, cette union discriminée s'apparente à ce que d'autres langages appellent généralement une _énumération_ (ou _enum_).

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Pour créer une valeur d'un cas précis, on peut se référer à son nom (`Spring`) lorsqu'il est défini dans le même module ou importé avec la syntaxe `import SeasonModule exposing (Season(..))`, ou bien à son nom pleinement qualifié (`Season.Spring`) lorsqu'il est importé avec la syntaxe `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Les types personnalisés, comme tout le reste en Elm, ont une _égalité structurelle_, ce qui signifie que deux valeurs du même cas et portant les mêmes données (facultatives) sont équivalentes.

La façon privilégiée de manipuler les types personnalisés est le [filtrage par motif][pattern-matching] :

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
