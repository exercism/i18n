# Introduction

Une *deque* (file à double extrémité) prend en charge les opérations _push_ et _pop_ aux deux extrémités en O(1). L'implémentation standard de Factor est `<dlist>` (une liste doublement chaînée), dans [`dlists`][dlists] ; les opérations se trouvent dans [`deques`][deques].

## L'API de la deque

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` vide la deque sur place, ce qui est pratique pour la réutiliser sans réallouer.

Un _push_ et un _pop_ à la même extrémité donnent une pile LIFO. Un _push_ à une extrémité et un _pop_ à l'autre donnent une file FIFO :

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

Pour du LIFO, on se tourne vers un vecteur (`V{ }`) avec `push`/`pop`, qui présente moins de surcoût par opération. On se tourne vers `<dlist>` quand on a besoin de O(1) aux *deux* extrémités, presque toujours pour une file FIFO.

## La recherche en largeur

C'est l'usage FIFO qui fait des deques la bonne frontière pour le *BFS*. On part d'un seul nœud, on ajoute les voisins à l'arrière, on retire les candidats à l'avant et on dédoublonne avec un ensemble de hachage :

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

Les candidats plus anciens sont visités avant les plus récents, si bien que la recherche se déploie vers l'extérieur par couches depuis le point de départ. C'est ce qui donne au BFS sa propriété de plus court chemin : la première fois qu'on atteint un nœud objectif, c'est par un chemin comportant un minimum de sauts.

## La mise en cache automatique avec `MEMO:`

Parfois, la recherche par nœud que le BFS effectue est coûteuse. Le vocabulaire [`memoize`][memoize] de Factor fournit `MEMO:`, un remplacement direct de `:` qui met en cache le résultat du mot en l'indexant sur ses entrées :

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

Un mot `MEMO:` exécute son corps la première fois que chaque entrée est vue, puis renvoie le résultat mis en cache : même interface, aucun appel supplémentaire côté appelant, simplement plus rapide lors des répétitions.
