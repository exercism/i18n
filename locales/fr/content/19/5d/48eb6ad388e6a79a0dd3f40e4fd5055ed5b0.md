# Introduction

## Références nulles

Si tu as déjà utilisé un autre langage de programmation (C/C++, Python, Java, Ruby, Lisp, etc.), il est probable que tu aies déjà rencontré `null` ou `nil`.
L'utilisation de `null` ou de `nil` est la manière dont ces langages indiquent qu'une variable particulière n'a pas de valeur.
Cependant, cela fait de l'utilisation accidentelle d'une variable `null` une erreur facile (et fréquente) à commettre.
Comme tu peux l'imaginer, essayer d'appeler une fonction qui n'existe pas ou d'accéder à une valeur qui n'existe pas peut mener à toutes sortes de bugs et de plantages.
Le créateur de `null` est même allé jusqu'à l'appeler son [« erreur à un milliard de dollars »][billion-dollar-mistake].

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## Le type `Option`

Pour éviter ces problèmes, les variables Cairo peuvent utiliser l'énumération `Option` pour représenter l'absence de valeur en toute sécurité.
Cette énumération prend deux variantes : `None`, l'équivalent de null en Cairo, et `Some(T)`, où `T` est une valeur de n'importe quel type.

Elle ressemble à ceci :

```rust
enum Option<T> {
    None,
    Some(T),
}
```

Tu peux voir `Option` comme une couche de sécurité entre toi et les problèmes que peuvent causer les références nulles, tout en conservant leur utilité conceptuelle.

## Utilise `Option`

Définir une variable à `None` est assez simple :

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

Cependant, si tu veux que le type `Option` porte une valeur, tu ne peux pas affecter cette valeur directement.
Une variable de type `Option` et, disons, une variable de type `i32` ne sont pas équivalentes.
Tu dois utiliser `Some` :

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

Pour la même raison, ce qui suit ne fonctionnera pas :

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

Pour récupérer la valeur contenue dans `Some`, tu dois d'abord vérifier qu'elle existe :

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

Cairo dispose d'autres outils que `match` pour vérifier et accéder aux valeurs contenues dans `Option`, mais `match` devrait t'être familier maintenant.

Considère ceci comme une démonstration de la raison pour laquelle Cairo utilise `Option` plutôt qu'une référence nulle.
L'idée, c'est que **tu _dois_ vérifier** si la variable `Option` vaut `Some` (auquel cas tu peux extraire et utiliser la valeur qu'elle contient) ou `None`.
Sinon, ton programme ne compilera pas ; le compilateur te protège de `null`.
