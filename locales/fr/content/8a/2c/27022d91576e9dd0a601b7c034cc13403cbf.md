# Introduction

## Exceptions

Toutes les erreurs en Elixir implémentent le _Exception Behaviour_. Tout comme le _Access Behaviour_, le _Exception Behaviour_ définit des fonctions de rappel qu'un module doit implémenter pour remplir le contrat logiciel du _behaviour_. Une fois une erreur définie, elle possède les propriétés suivantes :

- Le nom du module définit le nom de l'erreur.
- Le module définit une _struct_ d'erreur.
- Cette _struct_ possède un champ `:message`.
- Le module peut être utilisé avec `raise/1` et `raise/2` pour lever l'erreur voulue

Le _Exception Behaviour_ définit aussi deux fonctions de rappel : `message/1` et `exception/1`. Si elles ne sont pas implémentées, des implémentations par défaut seront utilisées. `message/1` transforme la _struct_ d'erreur en un message lisible lorsqu'elle est appelée avec `raise`. `exception/1` permet d'ajouter du contexte supplémentaire au message lorsqu'elle est appelée avec `raise/2`

### Définis une exception

Pour définir une exception à partir d'un module d'erreur, on utilise la macro `defexception` :

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### Utilise les exceptions

Une erreur définie peut s'utiliser comme une erreur native, avec `raise/1` ou `raise/2`.

- `raise/1` lève une erreur précise par le nom de son module ou, si l'argument est une _string_, lève une `RuntimeError` avec cette _string_ comme message.
- `raise/2` lève une erreur précise par le nom de son module et accepte un argument d'attributs qui sert à obtenir l'erreur avec le message approprié.
