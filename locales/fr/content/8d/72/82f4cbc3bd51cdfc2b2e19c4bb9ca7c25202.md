# Instructions

Tu travailles sur un système qui vise à simplifier le processus de connexion au réseau de ton organisation. Les tâches portent sur la partie authentification. Le système utilise la reconnaissance faciale pour prouver l'identité.

Dans tous les cas, le paramètre de couleur des yeux est garanti non nul.

## 1. Vérifie que les traits du visage correspondent

Implémente `Authenticator.AreSameFace()` pour vérifier que deux visages correspondent.

Ajoute des routines d'égalité pour la classe `FacialFeatures`.

```csharp
Authenticator.AreSameFace(new FacialFeatures("green", 0.9m), new FacialFeatures("green", 0.9m);
// => true
Authenticator.AreSameFace(new FacialFeatures("blue", 0.9m), new FacialFeatures("green", 0.9m);
// => false
```

## 2. Authentifie l'administrateur système

Malgré tes protestations, l'administrateur système tient à disposer d'une identité intégrée pendant les tests d'acceptation, afin de pouvoir toujours être authentifié.

L'adresse e-mail de l'administrateur est admin@exerc.ism. Il a les yeux verts et un philtrum d'une largeur de 0,9.

Ajoute des routines d'égalité pour la classe `Identity`.

Implémente la méthode `Authenticator.IsAdmin()` pour vérifier que l'identité passée en argument correspond à celle de l'administrateur.

```csharp
var authenticator = new Authenticator();
authenticator.IsAdmin(new Identity("admin@exerc.ism", new FacialFeatures("green", 0.9m)));
// => true
authenticator.IsAdmin(new Identity("admin@thecompetition.com", new FacialFeatures("green", 0.9m)));
// => false
```

## 3. Enregistre de nouvelles identités

Implémente la méthode `Authenticator.Register()` qui stocke une identité sur l'authentificateur lui-même, de sorte que les appels à `IsRegistered()` renvoient `true` pour cette identité ; sinon, `IsRegistered()` renvoie `false`.

Pour détecter les tentatives d'enregistrement en double d'une identité, si l'identité a déjà été enregistrée, `Authenticator.Register()` renvoie `false`, sinon `true`.

```csharp
var authenticator = new Authenticator();
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.IsRegistered(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => false
```

## 4. Empêche l'authentification d'identités invalides

Implémente la méthode `Authenticator.IsRegistered()` et assure-toi qu'elle renvoie false lorsqu'aucune identité n'a été enregistrée.

```csharp
var authenticator = new Authenticator();
authenticator.IsRegistered(new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.8m)));
// => false
```

## 5. Ajoute des diagnostics pour détecter les tentatives d'authentification multiples

Un bug a été signalé : la méthode `Authenticator.IsRegistered()` est appelée plusieurs fois de suite pour la même identité. Tu penses qu'il s'agit d'une sorte de problème de « rebond », où le même enregistrement exact est soumis plusieurs fois. Ta tâche consiste à ajouter une routine de diagnostic `Authenticator.AreSameObject()` pour faciliter les éventuels tests qui seront entrepris. La routine compare deux objets et renvoie `true` s'il s'agit exactement de la même instance, sinon `false`.

```csharp
var identityA = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityB = identityA;
Authenticator.AreSameObject(identityA, identityB);
// => true

var identityC = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityD = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
Authenticator.AreSameObject(identityC, identityD);
// => false
```
