# Introduction

Toutes les erreurs en Elixir implémentent le _comportement Exception_. Tout comme le _comportement Access_, le _comportement Exception_ définit des fonctions de rappel qu'un module doit implémenter pour satisfaire le contrat logiciel du comportement. Une fois une erreur définie, elle a les propriétés suivantes :

- Le nom du module définit le nom de l'erreur.
- Le module définit une structure d'erreur.
- La structure aura un champ `:message`.
- Le module peut être utilisé avec `raise/1` et `raise/2` pour lever l'erreur souhaitée.

Le _comportement Exception_ spécifie aussi deux fonctions de rappel : `message/1` et `exception/1`. Si elles ne sont pas implémentées, les implémentations par défaut seront utilisées. `message/1` transforme la structure d'erreur en un message lisible lorsqu'elle est appelée avec `raise`. `exception/1` permet d'ajouter du contexte supplémentaire au message lorsqu'elle est appelée avec `raise/2`.

## Définis une exception

Pour définir une exception à partir d'un module d'erreur, on utilise la macro `defexception` :

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

## Utilise les exceptions

Les erreurs définies peuvent être utilisées comme une erreur intégrée avec `raise/1` ou `raise/2`.

- `raise/1` lève une erreur spécifique par son nom de module, ou, si l'argument est une _string_, une `RuntimeError` est levée avec la _string_ comme message.
- `raise/2` lève une erreur spécifique par son nom de module et accepte un argument d'attributs qui est utilisé pour obtenir l'erreur avec le message approprié.
