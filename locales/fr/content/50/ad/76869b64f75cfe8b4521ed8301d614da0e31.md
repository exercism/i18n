# Introduction

Comme on l'a vu dans le concept [`Nothingness`][concept-nothingness], R dispose de plusieurs façons de représenter des données absentes (`NULL`), inconnues (`NA`) ou mathématiquement invalides (`NaN`, `Inf`).
En général, R essaie de s'en servir pour signaler les problèmes sur place, et poursuit son exécution sans lever d'exception.

## `stop()`

Certains problèmes sont trop fondamentaux pour laisser le programme continuer.
Dans ce cas, utilise `stop(msg)` pour interrompre immédiatement le programme avec une `Error` et afficher `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Semblable à un `assert` dans d'autres langages, c'est une enveloppe pratique autour de `stop()`.
Ses paramètres sont un nombre arbitraire de conditions booléennes séparées par des virgules, et le programme ne continue que si elles valent toutes `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `warning()` et `message()`

Ce sont des réponses à des conditions non fatales, par exemple :

- Pour signaler un problème dont le programme peut au moins partiellement se remettre.
- Pour informer l'utilisateur de la progression d'un programme de longue durée.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

La fonction `suppressWarnings()` peut parfois être utile sur Exercism, pour éviter de perturber l'exécuteur de tests avec des sorties indésirables.
