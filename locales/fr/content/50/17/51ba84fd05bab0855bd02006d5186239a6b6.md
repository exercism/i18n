# À propos

Swift possède de nombreux types différents, mais chacun d'entre eux appartient à l'une des deux classifications suivantes : les _types valeur_ et les _types référence_. En Swift, [les structures sont des types valeur][structs-are-value-types], tandis que [les classes sont des types référence][classes-are-reference-types].

La principale différence entre les types valeur et les types référence tient au fait que, lorsqu'un type valeur est affecté à une variable ou à une constante, ou transmis à une fonction, c'est en réalité une copie de la valeur qui est affectée ou transmise, et non cette valeur précise. Modifier une copie d'une structure n'affecte pas les autres copies. Avec les types référence, c'est une référence vers cette valeur qui est affectée ou transmise, si bien que deux noms différents peuvent désigner la même instance d'une classe. Cela peut entraîner la modification de l'instance d'origine lorsqu'on y accède sous un autre nom.

Ainsi, étant donné la structure et la classe qui définissent un personnage dans un jeu, ainsi que leurs statistiques de jeu, on peut observer ce qui se passe lorsque ces éléments sont copiés et modifiés.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

Remarque comment la modification des propriétés de `charB` a affecté celles de `charA`, puisque les deux noms désignent la même instance. Remarque aussi que, avec les statistiques des deux personnages, les types valeur contenus dans un type référence changent eux aussi à l'intérieur de ce type référence. Cela ne constitue toutefois pas une violation du comportement des types valeur, car `charA.stats` est la même instance de `CharacterStats` que `charB.stats`, étant donné que `charA` et `charB` désignent la même instance de la classe `GameCharacter`. Comme on peut le voir, des copies de ces types valeur ne s'affectent pas mutuellement.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

C'est pourquoi les structures exigent le mot-clé `mutating` devant les méthodes qui modifient l'état des propriétés de la structure. Changer la propriété d'une structure crée en réalité une nouvelle copie de la structure, avec la nouvelle valeur définie pour cette propriété, et cette nouvelle copie remplace l'ancienne. C'est un indicateur visuel du fait que cette copie et ce remplacement peuvent avoir lieu pour les valeurs de ce type.

Cela a pour effet secondaire que toute instance de structure dont les propriétés variables changent, que ce soit en appelant des fonctions `mutating` ou par affectation directe, _doit_ être affectée à une variable, et non à une constante. Sinon, une erreur de compilation est générée :

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

Les valeurs initiales peuvent toujours être créées et consultées, mais elles n'ont pas le droit de changer. Cette restriction ne s'applique pas aux classes. Si une instance de classe est affectée à un nom à l'aide de `let`, c'est la référence vers l'instance que la constante contient, et donc qui ne peut pas changer, et non l'instance elle-même. Ainsi, l'instance elle-même peut changer, mais la référence ne peut pas être modifiée pour pointer vers une autre instance.

Voici un récapitulatif de ce qui peut être modifié avec des structures et des classes définies à l'aide de `let` ou `var` :

|         | **struct**                                                                                  | **class**                                                                                   |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **let** | _Impossible_ d'affecter une nouvelle structure au nom.</br>_Impossible_ de modifier les propriétés de la structure. | _Impossible_ d'affecter une nouvelle classe au nom.</br>_Possible_ de modifier les propriétés mutables de la classe. |
| **var** | _Possible_ d'affecter une nouvelle structure au nom.</br>_Possible_ de modifier les propriétés mutables de la structure.   | _Possible_ d'affecter une nouvelle classe au nom.</br>_Possible_ de modifier les propriétés mutables de la classe.    |

## Identité

Comme deux noms différents peuvent contenir une référence vers la même instance de classe, il est parfois utile de vérifier si c'est le cas. Swift utilise l'opérateur `===` _d'identité_ pour le tester (ainsi que sa négation, `!==`).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

Comme deux noms ne peuvent pas désigner la même instance de structure, ces opérateurs d'identité ne sont pas définis pour les structures.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

Remarque que l'identité n'est pas la même chose que l'égalité. Selon de nombreuses définitions, `char1` et `char3` seraient considérés comme égaux, car toutes leurs propriétés contiennent les mêmes valeurs, mais ils ne partagent pas la même identité. L'identité est disponible automatiquement pour toutes les classes en Swift, mais les développeurs doivent généralement écrire leurs propres opérateurs d'égalité pour déterminer si deux instances d'une structure ou d'une classe sont _égales_. Cela dépasse le cadre de cet exercice.
