# À propos

Les variables locales ne remplacent pas le code de la pile : elles cohabitent avec lui. Fais appel à elles quand :

- La même entrée est référencée plusieurs fois.
- L'ordre naturel des opérations ne correspond pas à l'ordre de la pile.
- Tu te trouves à l'intérieur d'un mot d'ordre supérieur qui passe plusieurs valeurs d'un coup à la lambda (`( key value -- newkey newvalue )` d'`assoc-map`).

```factor
USING: locals ;

! Two references to ratio: stack-shuffled vs. local.
: average  ( a b -- avg ) + 2 / ;
:: average ( a b -- avg ) a b + 2 / ;        ! same effect
```

Le `[let code :> name code :> name ... body ]` introduit des liaisons locales dans une _quotation_ ou au _listener_, là où `:>` n'aurait sinon aucune portée lexicale dans laquelle se lier :

```factor
[let 5 :> x 10 :> y x y + ] .   ! => 15
```

Le suffixe de mutation `:>` permet de relier une variable locale à une nouvelle valeur, ce qui est utile dans les boucles qui ont un air impératif :

```factor
:: collatz ( n -- count )
    n :> current!
    0 :> count!
    [ current 1 = ] [
        current odd?
        [ current 3 * 1 + current! ]
        [ current 2 / current! ] if
        count 1 + count!
    ] until
    count ;
```
