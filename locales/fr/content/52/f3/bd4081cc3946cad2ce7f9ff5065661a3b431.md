# À propos

Factor divise les entrées/sorties de flux en deux couches. La couche inférieure est l'API *explicit-stream* : chaque mot prend le flux en argument. La couche supérieure est l'API *ambient-stream* : des mots courts, tenant sur une ligne, qui agissent sur le flux actuellement lié. Les deux couches reposent sur le même [protocole][stream-protocol] ; les mots de la couche supérieure se contentent de chercher le flux ambiant et de transmettre l'appel.

## Les mots de l'API *explicit-stream*

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents` vide tout ; `stream-lines` vide le flux et le découpe aux limites de ligne ; `stream-readln` renvoie une ligne à la fois (ou `f` à la fin du flux).

## Les mots de l'API *ambient-stream*

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

Ce sont les mots d'entrées/sorties que l'on utilise tous les jours. Ils récupèrent le flux d'entrée ou de sortie courant dans les variables dynamiques `input-stream` / `output-stream`, puis transmettent l'appel. C'est pourquoi rediriger `print` vers une chaîne de caractères se résume à lier `output-stream` le temps d'une *quotation*.

## Les constructeurs de flux fournis

| mot               | vocabulaire          | ce qu'il construit              |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | lit une chaîne de caractères littérale |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | rassemble les écritures dans une chaîne de caractères |
| `<file-reader>`   | [`io.files`][io.files]           | lit un fichier avec un encodage |
| `<file-writer>`   | [`io.files`][io.files]           | écrit un fichier avec un encodage |

Les quatre produisent des flux jetables : ils étendent `disposable` de `destructors`, si bien que les combinateurs `with-…` ci-dessous les libèrent à la sortie.

## Liaison à portée limitée

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

Chacun ouvre un flux, le lie comme entrée ou sortie ambiante pour la *quotation* interne, et le libère à la sortie, même si la *quotation* lève une exception. Ce sont les combinateurs de destructeurs de `boatswains-bilge`, spécialisés pour les flux.

`with-string-writer` est une variante particulièrement nette : il construit automatiquement un nouveau `<string-writer>`, exécute la *quotation* avec ce writer comme sortie ambiante, et renvoie la chaîne de caractères accumulée. Tout le schéma « capturer la sortie d'une *quotation* » tient en un seul mot.

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## Pourquoi un flux ambiant ?

C'est la liaison à une variable dynamique qui permet à `print` de fonctionner dans un programme qui ne sait pas s'il est exécuté de façon interactive, vers un fichier journal, ou vers un tampon de test capturé. Il suffit de remplacer la liaison une fois pour que tous les mots qui appellent `print` fassent ce qu'il faut, sans rien recâbler. C'est cette inversion que la couche supérieure t'apporte.

Pour *implémenter* un flux, c'est-à-dire définir ta propre classe qui se branche sur le protocole, consulte le concept `streams` (enseigné dans `telegraphers-tape`).
