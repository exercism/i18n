# Instructions

Tu commences ton premier jour dans une entreprise australienne appelée « Doctor Data », spécialisée dans la récupération d'informations.
Tu as brillé à ton entretien d'embauche grâce à tes connaissances en C++ et sur les [sondes de von Neumann][van-neumann-probes].
Comme tu as déjà vu beaucoup de fichiers de tests, ton nouveau patron veut que tu recrées les fichiers source et d'en-tête correspondants à partir de code de test que l'entreprise a récemment récupéré.

Dans cet exercice, tu vas recréer des fichiers perdus.
Pour l'instant, le contenu de ces fichiers n'est que des données inutilisables.

~~~~exercism/note
Le workflow de cet exercice d'apprentissage ressemble beaucoup à la structure des exercices d'entraînement d'Exercism.
Le texte d'introduction de l'exercice ne constitue qu'une partie de la spécification.
Le fichier de tests est ton guide de référence pour résoudre un problème donné.
En raison du fonctionnement de la compilation en C++, les résultats des tests peuvent ne pas apparaître dans l'interface web tant que tu n'as pas implémenté une version minimale de chaque classe, fonction et énumération exigée par les tests.
Si tu obtiens des erreurs de compilation, elles peuvent disparaître une fois que tu as traité toutes les tâches et tous les tests.
~~~~

Tu dois accomplir quatre tâches, toutes liées à la récupération du code perdu dans les fichiers d'en-tête et source.

## 1. Essaie d'extraire quelques premiers indices

Tu regardes deux lignes récupérées des fichiers de tests :

```cpp
heaven::Vessel bob{"Robert Johansson", 1};
heaven::Vessel will{"Riker", 2, star_map::System::BetaHydri};
```

Ton œil exercé a immédiatement reconnu un espace de noms `heaven`.
Tu vois aussi qu'il doit y avoir une classe appelée `Vessel`.
Le constructeur peut apparemment être appelé avec deux ou trois arguments.
Le premier argument semble être de type `string`, le deuxième est un nombre.
Il est possible d'initialiser la classe `Vessel` avec un troisième argument.
Le troisième argument vient d'un espace de noms `star_map`.
C'est un énumérateur de type `System`.
Tu as même récupéré l'une des énumérations : `BetaHydri`.

Prépare les fichiers source et d'en-tête avec les informations que tu as découvertes.
Il te faut deux espaces de noms : `heaven` et `star_map`.
L'espace de noms `heaven` contient une classe `Vessel`, qui peut être appelée avec deux ou trois arguments.
L'énumération `System` doit être placée dans l'espace de noms `star_map` et comporte un énumérateur `BetaHydri`.
Garde l'œil ouvert pour repérer d'autres énumérateurs, afin de pouvoir mettre à jour l'énumération `System` au fur et à mesure.

## 2. Trouve plus de détails

Tu découvres d'autres lignes du test :

```cpp
heaven::Vessel bob{"Robert Johansson", 1};
REQUIRE(bob.current_system == star_map::System::Sol);
REQUIRE(bob.generation == 1);
heaven::Vessel bob5 = bob.replicate("Mario");
REQUIRE(bob5.current_system == star_map::System::Sol);
REQUIRE(bob5.generation == 2);
```

Les lignes de test que tu viens de trouver révèlent une autre fonction membre de la classe `Vessel` : `replicate`.
Cette fonction reçoit une _string_ et renvoie une autre instance de `Vessel`.
Tu commences à te faire une idée de la valeur par défaut du troisième argument du constructeur grâce à la tâche précédente.
Tu vois aussi deux variables membres publiques de la classe `Vessel` ainsi que la spécification de la fonction membre `replicate`.

Ajoute la fonction `replicate` et les variables membres publiques `current_system` et `generation` aux fichiers d'en-tête et source.

## 3. Examine le fonctionnement interne

Tu trouves d'autres lignes intéressantes dans les fichiers de tests récupérés :

```cpp
heaven::Vessel bob6{"Homer", 3, star_map::System::EpsilonEridani};
REQUIRE(bob6.busters == 0);
bob6.make_buster();
REQUIRE(bob6.busters == 1);
bool success = bob6.shoot_buster();
REQUIRE(success);
REQUIRE(bob6.busters == 0);
success = bob6.shoot_buster();
REQUIRE_FALSE(success);
```

Apparemment, la classe `Vessel` possède une variable membre `busters`, que l'on peut modifier avec les deux fonctions membres de la classe `make_buster` et `shoot_buster`.
En attendant d'avoir d'autres informations, tu supposes que la fonction `make_buster` renvoie `void`.
Comme il y a un test sur la valeur de retour de `shoot_buster`, tu supposes que cette fonction renvoie un `bool`.

Ajoute les deux fonctions et la variable membre à la classe `Vessel`.
Continue à chercher d'autres énumérateurs `System`.

## 4. Complète le tableau

En parcourant les fichiers de tests, tu ne trouves que deux sections de code encore inexplorées :

```cpp
heaven::Vessel bob1{"Bob", 1, star_map::System::AlphaCentauri};
heaven::Vessel marv{"Marvin", 2, star_map::System::DeltaEridani};
heaven::Vessel milo{"Milo", 3, star_map::System::DeltaEridani};
heaven::Vessel howie{"Howard", 4, star_map::System::Omicron2Eridani};

REQUIRE("Bob" == heaven::get_older_bob(bob1, marv));
REQUIRE(heaven::in_the_same_system(marv, milo));
REQUIRE_FALSE(heaven::in_the_same_system(marv, howie));
```

Tu vois deux fonctions qui ne sont pas des membres de la classe `Vessel`, puisqu'elles ne sont pas appelées sur une instance.
`get_older_bob` compare deux instances de `Vessel` et renvoie une _string_.
`in_the_same_system` compare deux instances de `Vessel` et renvoie un `bool`.

Implémente les dernières fonctions manquantes à partir des lignes récupérées ci-dessus.
