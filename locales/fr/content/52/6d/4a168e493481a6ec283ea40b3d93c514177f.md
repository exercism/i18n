# Instructions complémentaires

## Réécriture

L'implémentation dans `Markdown.roc` passe déjà les tests.
Réécris-la tout en conservant son comportement et l'interface `parse : Str -> Try(Str, _)`.
Renvoie `Ok(html)` en cas de succès et propage les éventuelles erreurs d'analyse avec `Err(...)`.
Cet exercice couvre un petit sous-ensemble de Markdown, pas la spécification Markdown complète.
Les tests définissent le comportement à préserver, notamment la façon dont les lignes vides et les marqueurs d'emphase non appariés sont traités.

<summary>Afficher les astuces</summary>

Cherche la logique répétée, les conditions profondément imbriquées, les noms obscurs et l'état mutable inutile.
Pense à séparer la classification des lignes, l'emphase en ligne et le rendu HTML.
Le paquet [`roc-parser`](https://github.com/lukewilliamboswell/roc-parser) est disponible sous le nom `parser` dans l'application de test si tu veux l'utiliser.
`Parser.one_of`, `Parser.many` et `Parser.between` peuvent t'aider à combiner de petits analyseurs.
Une solution qui utilise de simples fonctions sur les _string_ et les tableaux est tout aussi bienvenue.
