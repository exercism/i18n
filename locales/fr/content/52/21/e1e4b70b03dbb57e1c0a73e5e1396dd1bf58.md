# À propos

Le type `Option` est le mécanisme du langage F# pour gérer les valeurs qui peuvent exister ou non.
Il offre une alternative sûre du point de vue des types à l'usage de `null`, courant dans d'autres langages pour traiter ce genre de valeurs.
On le retrouve dans de nombreuses fonctions de la bibliothèque standard F#, il est donc essentiel de le comprendre pour bien utiliser cette bibliothèque.

## Les avantages du type `Option`

* __Sécurité à la compilation__ : en indiquant explicitement dans le système de types si une valeur est présente ou absente, le compilateur peut garantir que le cas « pas de valeur » est géré, ce qui évite tout un ensemble de bugs que l'on pourrait rencontrer avec `null`.

* __Sécurité à l'exécution__ : au lieu d'utiliser `null`, F# utilise `None` pour représenter l'absence de valeur, ce qui rend impossible toute `NullReferenceException`.

* __Gestion explicite obligatoire__ : le système de types impose de gérer explicitement les deux cas, `Some value` et `None`, ce qui rend le code plus robuste et plus prévisible.

* __Compatibilité avec le filtrage par motifs__ : les `Option` s'intègrent parfaitement à l'idiome de filtrage par motifs de F#, ce qui offre un moyen propre et sûr de déstructurer la valeur si elle existe, ou d'effectuer une autre action sinon.

## Utilisation

Le type `Option` est un type générique (il prend un type sous-jacent).  
Les valeurs `Option` sont soit `Some value`, qui représente une valeur précise, soit `None`, qui représente l'absence de valeur.

La fonction suivante montre comment créer une valeur `Option` :

```fsharp
let keepIfPositive (a: int) : int option = if a > 0 then Some a else None
```

~~~~exercism/note
`T option` est la syntaxe postfixée équivalente de `Option<T>` ; les deux formes s'utilisent de façon interchangeable.
Cependant, d'après le Guide de style F#, la notation postfixée est préférable pour les types Option (voir [la section du Guide de style F# consacrée à la mise en forme des types et des annotations de type](https://learn.microsoft.com/en-us/dotnet/fsharp/style-guide/formatting#for-types-prefer-prefix-syntax-for-generics-foot-with-some-specific-exceptions)). 
~~~~

Les fonctions de recherche constituent un cas d'usage typique du type `Option`. 
Par exemple, la fonction `List.tryFind` renvoie `Some index` lorsque l'élément se trouve dans la liste (`index` étant la position de la valeur recherchée dans la liste), ou `None` lorsqu'il ne s'y trouve pas.

## Lis le contenu d'une valeur `Option`

La façon idiomatique de lire une valeur `Option` passe par le filtrage par motifs, comme le montre l'exemple suivant :

```fsharp
// Returns "Hello, <name>!" if the name is provided; otherwise returns "Hello, you!"
let sayHello (optionalName: string option): string = 
    match optionalName with
    | Some name -> "Hello, " + name + "!"
    | None -> "Hello, you!"

sayHello (Some "Matthieu")
// --> "Hello, Matthieu!"

sayHello None
// --> "Hello, you!"
```

## Déballe les `Option` avec une valeur par défaut

Les `Option` peuvent être « déballées » (converties vers leur type contenu) en fournissant des valeurs par défaut avec la fonction `Option.defaultValue`. 
C'est particulièrement utile lorsqu'on veut s'assurer que la valeur n'est pas `None`.
Par exemple :

```fsharp
Option.defaultValue "" (Some "F#")
// --> "F#"

Option.defaultValue 0 None
// --> 0
```

## D'autres fonctions dans le module `Option`

Le module `Option` contient aussi des fonctions qui correspondent à celles disponibles pour les listes, les tableaux, les séquences et les autres types de collections, comme `Option.map`, `Option.iter`, `Option.forall` et `Option.count`. 
Ces fonctions permettent de traiter les `Option` comme une collection de zéro ou un élément.
