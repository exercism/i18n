# Indices

## Général

- Jette un œil au [guide Elm][elm-guide] : il contient un chouette exemple concret qui ressemble à ce que tu vas faire ici.

## 1. Définis les types Model et Msg de l'application et écris la fonction init

- Le `Model` contient l'état de l'application, c'est-à-dire toutes les données dont elle a besoin.
- Il doit s'agir d'un *record*.
- Cette application a juste besoin d'un `String` pour stocker le texte de la zone de texte (les tests exigent qu'il s'appelle `content`).

- Le type `Msg` définit les messages qui sont transmis à la fonction `update`, pour déclencher des changements précis dans le modèle.
- Il doit s'agir d'un [type personnalisé][custom-type].
- Cette application n'a besoin que d'un seul changement du modèle : mettre à jour le modèle quand le texte de la zone de texte change.

- La fonction `init` doit simplement renvoyer un `Model` avec une valeur par défaut raisonnable (les tests exigent une chaîne vide).

## 2. Écris la fonction update

- Dans toute application utile, la fonction `update` utilise une instruction `case` pour faire un filtrage par motif sur le paramètre `Msg`.
- Dans chaque branche de l'instruction `case`, elle extrait du paramètre `Msg` les informations dont elle a besoin, puis renvoie un `Model` mis à jour
- Le `Model` doit être un *record*, et on utilise normalement la [syntaxe de mise à jour des records][record-update-syntax].

## 3. Écris la fonction view

- La fonction `view` doit renvoyer une `div` pour l'élément racine
- Le premier enfant doit être un `input`, avec un attribut `value` pour le texte actuel et un attribut / événement `onInput` portant la variante correspondante de `Msg`.
- Le deuxième enfant doit être une autre `div` avec un enfant `text` qui indique si le texte est un palindrome ou non.

## 4. Écris la fonction main

- La fonction main doit simplement appeler [`Browser.sandbox`][browser-sandbox]
- `Browser.sandbox` prend en argument un [record][record] contenant les fonctions `init`, `update` et `view`.
