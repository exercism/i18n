# Introduction

## Application partielle et composition de fonctions

### Application partielle

En Elm, toutes les fonctions sont [curryfiées][currying], ce qui signifie que si on appelle une fonction sans lui passer tous les arguments, elle renvoie une nouvelle fonction.

Le résultat de cette opération s'appelle l'[application partielle][partial-application] (on ne passe pas tous les arguments à la fonction, mais on n'en applique qu'une partie).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

L'application partielle applique toujours les arguments dans l'ordre.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

### L'opérateur pipe (`|>`)

Dire `x |> f` est exactement la même chose que `f x`. Un exemple concret : `"5" |> String.toInt` est équivalent à `String.toInt "5"`.

Ça ne semble pas très utile au premier abord, mais on l'appelle l'[opérateur pipe][pipe-operator] parce qu'il permet d'écrire du code « en pipeline ».

Par exemple, imaginons une fonction sanitize qui transforme une entrée utilisateur en nombre entier :

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

On peut la réécrire comme ceci :

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

On évite ainsi d'utiliser des parenthèses, et on voit les fonctions dans l'ordre dans lequel elles sont appliquées (d'abord `String.trim`, puis `String.toInt`), ce qui améliore la lisibilité.

Il existe aussi un [opérateur pipe inversé `(<|)`][reverse-pipe-operator].
Dire `f <| x` est exactement la même chose que `f x`.
Ça ne semble pas très utile au premier coup d'œil non plus, et c'est clairement moins utilisé que l'opérateur pipe, mais ça permet d'éviter des parenthèses dans certaines situations.

### Composition de fonctions / style point free

L'opérateur [`(>>)`][forward-composition] a le type `(a -> b) -> (b -> c) -> (a -> c)` et crée une fonction de type `a -> c` en composant deux fonctions compatibles de type `a -> b `et `b -> c`.
Pour ce faire, il prend la sortie (de type `b`) de la première fonction et l'utilise comme premier argument de la seconde fonction (qui doit être du même type `b`).
La fonction ainsi créée prend la même entrée (de type `a`) que la première fonction, et renvoie le `c` que renvoie la seconde fonction.

Un exemple concret est `String.trim >> String.toInt`.
`String.trim` prend une _string_ comme seul paramètre, donc c'est ce que prend la fonction créée.
`String.toInt` renvoie un `Maybe Int`, donc c'est ce que renvoie la fonction créée.
`String.trim` renvoie une `String`, que `String.toInt` accepte comme paramètre, donc l'exemple compile.

On peut maintenant réécrire notre fonction `sanitize` de la façon suivante :

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Remarque qu'on n'utilise plus le paramètre `input` que l'on voit dans l'exemple d'origine, même si le comportement est identique.
Cette façon de créer des fonctions qui ne font aucune référence à leurs paramètres s'appelle le « point free style ».
L'avantage de ce style est que le code est plus concis, l'inconvénient est qu'il peut être plus difficile à comprendre, surtout pour les débutants.

Il faut garder à l'esprit qu'en Elm, toutes les fonctions sont curryfiées, donc `String.length >> max` compile.

- L'opérateur [`(>>)`][forward-composition] a le type `(a -> b) -> (b -> c) -> (a -> c)`.
- `String.length` a le type `String -> Int`, qui est la partie `(a -> b)`, donc `a` est `String` et `b` est `Int`.
- `max` a le type `Int -> Int -> Int`, qui est la partie `b -> c`.
- `b` est `Int`, donc on applique partiellement `max`, et `c` est le résultat de cette application partielle (`Int -> Int`).
- Donc le type de `String.length >> max` est `String -> (Int -> Int)`.
- Donc `((String.length >> max) "123") 2` renvoie `3`, parce que `"123"` a une longueur de 3, qui est supérieure au 2 de l'argument `Int`.

### Conception de fonctions

Pour écrire facilement du code élégant en Elm, il est conseillé de faire de la structure de données principale le dernier paramètre des fonctions.
Toutes les fonctions courantes de la bibliothèque standard font ça, comme `List.map` (dont voici la signature de type).

```elm
map : (a -> b) -> List a -> List b
```

On voit ici que le dernier paramètre de la fonction `map` est `List a` et qu'elle renvoie `List b`, donc la structure de données principale (`List`) est bien le dernier paramètre.

Cela permet d'écrire du code élégant sous forme de pipeline, comme ci-dessous.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Cela rend aussi pratique l'utilisation de la composition de fonctions et du style point free, comme alternative au pipeline.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

La composition de fonctions permet aussi de réduire cet exemple à un seul appel à `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
