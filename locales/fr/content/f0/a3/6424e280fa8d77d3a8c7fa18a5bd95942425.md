# À propos

## Les optionnels

Swift utilise des [_optionnels_][optionals] pour permettre aux programmeurs de représenter l'absence possible d'une valeur.
Un optionnel est un type qui peut soit contenir une valeur, soit être [`nil`][nil], ce qui représente l'absence de valeur.
Pour utiliser un optionnel, un programme doit d'abord vérifier qu'une valeur est bien présente, puis la déballer avant de s'en servir.

N'importe quel type peut devenir un optionnel en ajoutant un `?` à la fin du nom du type.
Ainsi, un entier optionnel aura le type `Int?` et une _string_ optionnelle aura le type `String?`.
Définir des constantes ou des variables de type optionnel et leur affecter des valeurs se fait de la même façon que pour des valeurs de types non optionnels.

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

On peut affecter l'absence de valeur à une variable de type optionnel en lui affectant la valeur spéciale `nil`.
On peut utiliser `nil` avec tous les types optionnels, mais les `nil` affectés à deux types optionnels différents n'ont pas le même type : ils ne peuvent pas être échangés ni même comparés.

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

Note aussi que, même si `nil` peut être affecté à n'importe quel type optionnel, il ne peut pas être affecté à un type non optionnel (même si celui-ci ne contient pas réellement `nil`).
De même, on ne peut pas passer un type optionnel à une méthode qui attend un type non optionnel sans l'avoir déballé au préalable.

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## Utilisation des optionnels

Comme un type optionnel n'est pas le même type que son type de base, les deux ne peuvent pas s'utiliser de la même manière.
Par exemple : `Int("123") + 1` produit une erreur de compilation « Value of optional type 'Int?' must be unwrapped to a value of type 'Int' ».
En effet, `Int("123")` renvoie un optionnel de type `Int?`, et non un `Int`, car si la _string_ ne peut pas être convertie en entier, le résultat vaut `nil`.
Pour récupérer la valeur de type `Int` issue de la conversion, il faut d'abord la « déballer ».

En Swift, on utilise le plus souvent pour cela les constructions `if-let` et `guard-let`, qui réalisent une [_liaison optionnelle_][optional-binding] : elles vérifient la présence de `nil`, puis empruntent un chemin de code si une valeur existe, en liant la valeur déballée au nom fourni, et un autre chemin si `nil` a été trouvé.

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

Il faut noter que la variable `safeNum` est de type `Int` et non `Int?`.
Dans l'exemple ci-dessous, `num` est de type `Int?` et `safeNum` est de type `Int`.

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

Cette _liaison optionnelle_ est importante, car elle déballe (ou « retire ») le type optionnel de la valeur, ce qui permet de l'utiliser comme une valeur non optionnelle.
Si on se contente de vérifier si la valeur vaut `nil`, celle-ci reste de type optionnel :

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

L'option `guard-let` peut aussi servir quand on souhaite un retour anticipé :

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## Comparaison des optionnels

À noter que, même si le type de base d'une paire d'optionnels peut se comparer avec les opérateurs de comparaison standard, les optionnels eux-mêmes ne peuvent pas être comparés.
On peut seulement tester leur égalité.
Deux optionnels sont égaux s'ils valent tous les deux `nil`, ou si les valeurs qu'ils contiennent sont égales au sein de leur type de base.

On peut toutefois écrire du code pour comparer deux valeurs optionnelles de façon personnalisée.
Voici un exemple d'instruction `switch` qui ne renvoie `true` que si les deux valeurs optionnelles ne valent pas `nil` et si la première est inférieure à la seconde.
Pour cela, elle utilise le _motif optionnel_ `varName?`, qui ne correspond qu'aux optionnels qui ne valent pas `nil` et lie la valeur contenue dans l'optionnel au nom `varName`.

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## Coalescence de nil

Il existe une autre façon de déballer un optionnel : utiliser une [valeur de repli][fallback] lorsque `nil` est présent.
On y parvient avec l'_opérateur de coalescence nil_, `??`. En supposant que `x` soit un `Int?`, si on écrit `let y = x ?? 0`, Swift vérifie si x vaut `nil`.
Si ce n'est pas le cas, il déballe `x` et affecte la valeur déballée à `y` ; et si `x` vaut _bel et bien_ `nil`, il affecte 0 à `y`.

Comme `x ?? y` n'est qu'une notation abrégée pour `x != nil ? x! : y`, si `x` ne vaut pas `nil`, l'expression `y` n'est pas évaluée du tout.

Enfin, notez que l'opérateur de coalescence nil est associatif à droite, ce qui peut réserver des surprises à qui ne le sait pas.

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

Pour en savoir plus sur l'opérateur de coalescence nil, consulte [A Tour of Swift: Nil-Coalescing Operator][nil-coalescing].
