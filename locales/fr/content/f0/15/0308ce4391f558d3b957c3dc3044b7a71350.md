# À propos

## Les nombres et les opérateurs numériques

Tous les **nombres**, qu'ils soient entiers ou non, sont des nombres à virgule flottante de précision double IEEE 754.
L'implémentation de `jq` utilise le type `double` du C.
Cela nous limite à 53 bits de précision.

Les opérateurs habituels sont disponibles pour les nombres :

- arithmétique : `+`, `-`, `*`, `/`, `%`
- comparaison : `==`, `!=`, `<`, `<=`, `>=`, `>`
- les [fonctions mathématiques][man-math] standard

  Pour les fonctions à une entrée, on envoie la valeur dans la fonction avec un pipe

  ```sh
  $ jq -n '(1 | atan) * 4'
  3.141592653589793
  ```

  Pour les fonctions à deux entrées, celles-ci ignorent l'entrée et attendent les entrées sous forme de paramètres

  ```sh
  $ jq -n 'pow(2; 10)'
  1024
  ```

  Le point-virgule est le séparateur des arguments d'une fonction, pas la virgule.

~~~~exercism/caution
Que signifie la phrase « Cela nous limite à 53 bits de précision » ?

Une démonstration :

```sh
$ jq -n 'pow(2;52) as $n | [$n, $n+1]'
[
  4503599627370496,
  4503599627370497
]
```

Ça a l'air correct. Et si on augmente l'exposant ?

```sh
$ jq -n 'pow(2;53) as $n | [$n, $n+1]'
[
  9007199254740992,
  9007199254740992
]
```

Ces nombres ne devraient pas être égaux.
Voilà à quoi ressemble une « perte de précision ».
Cela signifie que `jq` n'est pas capable de manipuler des nombres arbitrairement grands.

## Les expressions conditionnelles

`jq` utilise une [expression `if-then-else`][if-then-else] pour les **expressions conditionnelles**.
En tant qu'_expression_, elle se place dans un pipeline.

La syntaxe est la suivante : `if CONDTITION then TRUE_EXPR else FALSE_EXPR end`.

La clause `else` est facultative.

```jq
42 | if . < 33 then "small" else "larger" end
# => "larger"
```

Pour ajouter des conditions, on utilise `elif`

```jq
42 | if . < 33 then "small"
     elif . < 67 then "medium"
     else "large"
     end
# => "medium"
```
