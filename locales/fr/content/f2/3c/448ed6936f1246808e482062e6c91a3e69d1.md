## Options de ligne de commande supplémentaires pour jq

Tu remarqueras des options supplémentaires pour `jq` dans les tests.

```sh
run jq -s -R -c -f minesweeper.jq << 'END_INPUT'
```

À quoi servent-elles ?

- `-s`

  C'est le mode « slurp ».
  Au lieu de traiter l'entrée comme un flux d'objets JSON,
  l'intégralité de l'entrée est regroupée dans un tableau.

  ```sh
  $ seq 5 | jq -c '.'
  1
  2
  3
  4
  5
  $ seq 5 | jq -s -c '.'
  [1,2,3,4,5]
  ```

- `-R`

  Tu as peut-être déjà vu `-r`, qui affiche des chaînes « brutes » (sans guillemets).
  C'est l'inverse.
  Chaque ligne de l'entrée est considérée comme une _string_.

  Deux exemples :

  ```sh
  $ seq 5 | jq -R -c .
  "1"
  "2"
  "3"
  "4"
  "5"

  $ echo 42 | jq '. * 2'      # input is a JSON number
  84
  $ echo 42 | jq -R '. * 2'   # input is a JSON string
  "4242"
  ```

Quand tu combines ces deux options, tu n'obtiens _pas_ un tableau de _strings_ : tu obtiens l'intégralité de l'entrée sous la forme d'une seule _string_, y compris les retours à la ligne.

```sh
$ seq 5 | jq -s -R -c .
"1\n2\n3\n4\n5\n"
```

Gérer ce cas fait partie des difficultés de cet exercice.
