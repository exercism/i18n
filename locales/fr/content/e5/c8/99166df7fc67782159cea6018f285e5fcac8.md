# À propos

La liaison décrit depuis quel endroit du code un identifiant est accessible.
Les valeurs qui ont une portée de bloc, de fonction ou de prototype de fonction n'ont pas de liaison.
Cela signifie qu'on ne peut pas y accéder depuis l'extérieur de leur portée.
Pour en savoir plus sur la portée, consulte le [concept de portée](../scope/introduction.md#Introduction).

## Liaison externe

Les identifiants qui ont une portée de fichier ont une liaison externe par défaut.
Un identifiant qui a une liaison externe peut être appelé depuis n'importe quel fichier du programme.

## Liaison interne

On peut faire en sorte qu'un identifiant ayant une portée de fichier ait une liaison interne en utilisant le spécificateur `static`.
Un identifiant qui a une liaison interne ne peut être utilisé que dans son propre fichier.

Par exemple

```c
int public_count = 0; // file scope, external linkage by default
static int private_count = 0;  // file scope, internal linkage 

// file scope, internal linkage
static void some_function()
{
    // code snipped
}

// file scope, external linkage by default
int main()
{
    // code snipped
}
```

La liaison statique ne doit pas être confondue avec la durée de stockage statique.
Pour en savoir plus sur la durée de stockage statique, consulte le [concept de durée de stockage](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#static-the-storage-specifier-not-to-be-confused-with-the-static-linkage-type).

Si une valeur (par opposition à une fonction) est déclarée dans un en-tête mais est définie dans le fichier source comme un identifiant `static` à portée de fichier avec une valeur initialisée, sa valeur initialisée ne sera pas accessible depuis l'extérieur de son fichier source.
Elle peut se compiler, se lier et s'exécuter sans erreur, mais la valeur sera la valeur zéro de l'identifiant, même si la valeur est déclarée avec `extern`.
(Pour en savoir plus sur `extern`, consulte le [concept de `extern`](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#extern-how-to-access-a-variable-in-another-translation-unit).)
Un identifiant à portée de fichier marqué `static` dans un fichier source ne doit pas être déclaré dans son fichier d'en-tête.
