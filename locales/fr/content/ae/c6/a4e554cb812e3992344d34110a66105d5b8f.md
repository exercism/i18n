# Introduction aux boucles

Bash propose deux formes de boucles :

* Répéter des commandes _pour chaque élément d'une liste d'éléments_,
* Répéter des commandes _tant qu'_une condition est vraie (ou fausse).

## Les boucles `for`

Pour parcourir une liste d'éléments, on utilise la boucle `for`.

```bash
for varname in words; do COMMANDS; done
```

`words` est étendu par découpage en mots et expansion des noms de fichiers (ce que nous avons découvert dans le [concept de mise entre guillemets][quoting]).
Chaque mot est affecté tour à tour à `varname`, et les COMMANDS sont exécutés.

Voici quelques exemples qui montrent quand la boucle `for` peut être utile :

* Exécuter des commandes sur un groupe de fichiers.

    ```bash
    # source all the bash library files in the current directory
    for file in ./*.bash; do
        source "$file"
    done
    ```

* Exécuter une commande sur chacun des paramètres d'un script ou d'une fonction.

    ```bash
    for arg in "$@"; do
        echo "argument: ${arg}"
    done
    ```

* Exécuter une commande pour chaque mot séparé par des espaces dans la sortie d'une commande.

    ```bash
    for i in $(seq 10); do
        echo "${i} squared is $((i * i))"
    done
    ```

    On verra plus loin quelques avertissements à propos de ce style.

### La boucle `for` arithmétique

Bash possède bien une boucle arithmétique.
Cela te paraîtra familier si tu connais d'autres langages de programmation.

```bash
for ((INITIALIZATION; CONDITION; INCREMENT)); do COMMANDS; done
```

La double parenthèse en bash représente un contexte arithmétique (on verra plus en détail l'arithmétique de bash dans un concept ultérieur).
L'exemple ci-dessus qui utilise `seq` peut s'écrire ainsi :

```bash
for ((i = 1; i <= 10; i++)); do
    echo "${i} squared is $((i * i))"
done
```

### Quand ne pas utiliser la boucle `for`

[Ne lis pas les lignes avec `for`][bashfaq1].

C'est un anti-patron que l'on rencontre souvent : itérer sur la sortie de `cat`.

```bash
for line in $(cat some.file); do 
    do_something_with "$line"
done
```

C'est faux sur deux points.

1. La substitution de commande n'est pas entre guillemets, elle est donc soumise au découpage en mots.
   Par défaut, le découpage en mots se fait sur les _espaces blancs_, et pas seulement sur les retours à la ligne.
   Cette boucle `for` itère sur les **mots** du fichier, et non sur les lignes.
2. La substitution de commande n'est pas entre guillemets, elle est donc soumise à l'expansion des noms de fichiers.
   Chaque mot du fichier sera interprété comme un motif glob.

Comme on l'a vu dans le [concept de mise entre guillemets][quoting], le découpage en mots peut être contrôlé avec la variable `IFS`, et l'expansion des noms de fichiers peut être désactivée.
Mais c'est souvent une solution fragile.
La boucle `for` n'est pas la bonne méthode pour parcourir les lignes d'un fichier.
La façon idiomatique de lire un fichier est d'utiliser une boucle `while`.

## Les boucles `while`

Utilise `while` pour répéter une suite de commandes _tant qu'_une condition est vraie.

```bash
while CONDITION_COMMANDS; do COMMANDS; done
```

Comme pour `if` (comme on l'a vu dans le [concept des conditions][conditionals], il n'y a pas de syntaxe particulière pour les CONDITION_COMMANDS.
C'est le code de sortie de la liste de commandes qui détermine « vrai » ou « faux ».

## Contrôler les boucles

La commande `break` sort de la boucle.
L'exécution reprend à la commande qui suit le `done` qui termine la boucle.

La commande `continue` passe à l'itération suivante de la boucle.

## Lire les lignes d'un fichier

Comme on l'a dit, la boucle `while` est la façon idiomatique de lire un fichier.

```bash
while IFS= read -r line; do
    do_something_with "$line"
done < some.file
```

* Le contenu du fichier est fourni en entrée de la boucle grâce à la redirection `<`.
* La commande `read` renvoie « vrai » si elle parvient à lire une ligne complète de son entrée.
  Quand l'entrée est épuisée, ou si la dernière ligne ne se termine pas par un retour à la ligne, `read` renvoie « faux ».
  * La façon _vraiment_ idiomatique de lire les lignes d'un fichier, même si la dernière ligne ne se termine pas par un retour à la ligne, est

    ```bash
    while IFS= read -r line || [[ -n "$line" ]]; do ...
    ```

* L'option `-r` demande à `read` de ne pas interpréter les séquences d'échappement : un antislash n'est qu'un caractère ordinaire.
* `IFS=` affecte la chaîne vide à IFS uniquement pendant la durée de la commande `read`.
  Cela désactive temporairement le découpage en mots, de sorte que les espaces en début et en fin de la ligne entrante soient préservés.

## `until`

La construction `until` répète une suite de commandes tant qu'une condition est **fausse**.
La boucle se répète _jusqu'à ce que_ la condition devienne vraie.

```bash
until CONDITION_COMMANDS; do COMMANDS; done
```

Il est rare d'utiliser `until`.
Il est plus courant d'utiliser une boucle « while not ».

```bash
while ! CONDITION_COMANDS; do ...
```

## Les boucles infinies

Parfois, tu veux boucler indéfiniment.
Voici deux façons de faire.

1. une boucle `while` avec une condition dont le code de sortie est toujours un succès

    ```bash
    while true; do ...
    ```

2.  une boucle `for` arithmétique avec des expressions vides

    ```bash
    for ((;;)); do ...
    ```

## La boucle do-while

Il n'existe pas de construction do-while explicite, mais tu peux obtenir le même effet :

```bash
while true; do
    COMMANDS

    if END_CONDITION; then
        break
    fi
done
```
