# Itérateurs personnalisés

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | routine | itérateur |
| --- | --- | --- |
| nom | `foo` | `foo!` |
| rend une valeur | `return` | `yield` |
| se termine | `return`, ou la fin | `quit`, ou l'épuisement |
| peut être appelé | n'importe où | uniquement dans une `loop` |
| conserve sa position | non | oui |

## yield

`yield` transmet une valeur puis se suspend. Tout est restauré au tour suivant : les variables locales, la position dans les propres boucles de l'itérateur, et les positions de tous les itérateurs qu'il appelle lui-même.

Un `yield` à l'intérieur de boucles imbriquées reprend à la plus profonde, ce qui rend simple l'écriture d'un parcours sur une structure imbriquée :

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

Met fin à l'itérateur, et donc à la boucle qui l'appelle. Il ne porte aucune valeur : un `quit` n'est pas un dernier résultat, c'est l'annonce qu'il n'y en a aucun.

Un itérateur doté d'un type de retour doit livrer une valeur à chaque `yield` ; `quit` est ce qui lui permet de s'y dérober.

## once

```sather
   markers!(once count : INT) : INT is
```

Un argument `once` est évalué à l'entrée dans la boucle, puis conservé. Un argument ordinaire est réévalué à chaque tour, ce qui compte quand l'expression passée contient un autre appel d'itérateur :

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

Marque les arguments `once`, sauf si tu veux vraiment ce comportement-là. Toute la bibliothèque le fait.

## self et les itérateurs

Un itérateur peut être appelé sur un objet, et `self` est alors cet objet. Son état en pause appartient au site d'appel, pas à l'objet, de sorte que deux boucles qui parcourent le même objet ne se gênent pas.

## Quand en écrire un

Écris un itérateur quand la réponse est une séquence et que c'est à l'appelant de décider quelle part il en prend. S'arrêter tôt ne coûte rien, et rien n'est construit qui ne soit utilisé, alors qu'une routine qui renvoie un `ARRAY` doit d'abord tout construire.
