## Messages d'exception

Parfois, il est nécessaire de [lever une exception](https://docs.python.org/3/tutorial/errors.html#raising-exceptions). Dans ce cas, tu dois toujours inclure un **message d'erreur explicite** pour indiquer la source de l'erreur. Cela rend le code plus lisible et facilite grandement le débogage. Pour les situations où tu sais que la source de l'erreur sera d'un type précis, tu peux choisir de lever l'un des [types d'erreur intégrés](https://docs.python.org/3/library/exceptions.html#base-classes), mais tu dois quand même inclure un message explicite.

Cet exercice exige en particulier que tu utilises [l'instruction `raise`](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement) pour « lever » une `ValueError` quand la partie est terminée alors que le joueur essaie de continuer à jouer. Les tests ne réussiront que si tu lèves l'`exception` avec `raise` et que tu y joins un message.

Pour lever une `ValueError` avec un message, écris le message en argument du type de l'`exception` :

```python
# when player tries to play, but the game is already over.
raise ValueError("The game has already ended.")
```
