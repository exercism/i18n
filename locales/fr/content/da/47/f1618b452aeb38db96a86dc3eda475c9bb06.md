# Installation

## Préambule

Bien que Regina Rexx ait été porté sur de nombreuses plateformes, ces instructions d'installation se concentrent sur les plateformes de bureau 64 bits sous Windows, Linux ou MacOS.

## Étapes d'installation

Note que ce parcours suppose que la dernière version de [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) soit installée (la 3.9.5, au moment de la rédaction de ce document). Le lien fourni t'emmène directement dans la section Files, où tu choisis le fichier à télécharger.

### Windows

Une installation native sous Windows (via une fenêtre CMD ou Powershell) se fait facilement dans le navigateur grâce au bouton [`Download Latest Version`](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/Regina395w64.exe/download). Il suffit de cliquer, de télécharger et d'installer.

Si tu disposes déjà d'environnements d'émulation Linux, ou si tu souhaites en utiliser, comme :

* [Git for Windows](https://gitforwindows.org/)
* [Cygwin](https://cygwin.com/)
* [MinGW](http://mingw.org/)

les binaires Regina natifs Windows devraient être accessibles, tu peux donc simplement les exécuter dans ces environnements, et dans la plupart des cas, cela suffit.

Une réserve toutefois : l'instruction ADDRESS ne fonctionne pas correctement (car elle interagit avec le système d'exploitation hôte). Pour de meilleurs résultats dans ces environnements, récupère le paquet propre à l'environnement, puis installe-le. Le site de Regina héberge par exemple une compilation [spécifique à Cygwin](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-pc-cygwin.tgz/download) que tu peux installer.

Sinon, si tu disposes déjà, ou si tu souhaites utiliser, une _vraie_ distribution Linux sous Windows, comme [WSL](https://docs.microsoft.com/en-us/windows/wsl/about) ou [Virtual Box](https://www.virtualbox.org/), il te suffit de suivre les instructions de la section Linux correspondant à la distribution concernée.

### Linux

Sur Linux, l'installation est généralement assez simple lorsqu'on utilise le gestionnaire de paquets du système. Elle pose toutefois problème lorsque les paquets disponibles ne sont _pas_ les plus récents. C'est malheureusement le cas de Regina.

Une installation à partir de paquets reste possible en récupérant manuellement les paquets les plus récents. Le site de [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) héberge des paquets pour la famille Debian (qui inclut Ubuntu) et la famille RHEL (qui inclut Fedora, CentOS, Rocky et Alma), entre autres.

Pour la distribution choisie, tu devras télécharger deux paquets : un paquet de bibliothèque et un paquet de binaires. Par exemple, pour installer sur Debian ou Ubuntu, procède comme suit :

```plain
sudo apt update && sudo apt -y install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx_3.9.5-2_amd64-Debian-11.deb > regina-rexx_3.9.5-2_amd64-Debian-11.deb
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3_3.9.5-2_amd64-Debian-11.deb > libregina3_3.9.5-2_amd64-Debian-11.deb
sudo apt -y install libregina3_3.9.5-2_amd64-Debian-11.deb regina-rexx_3.9.5-2_amd64-Debian-11.deb
```

Et sur CentOS et RHEL 7, essaie :
```plain
sudo yum update && sudo yum install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
sudo yum localinstall libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
```

Et sur Fedora, Rocky et Alma, essaie :
```plain
sudo dnf update && sudo dnf install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
sudo dnf localinstall libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
```

Lorsqu'une installation à partir de paquets n'est pas possible, ou s'est révélée problématique, il est toujours possible de compiler depuis les sources, l'archive étant récupérable via :

```plain
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5.tar.gz > regina-rexx-3.9.5.tar.gz
```

En supposant que les outils de compilation standards (gcc, make) soient installés (sinon, suis les instructions ici : [Installer les outils de développement](https://ostechnix.com/install-development-tools-linux/)), effectue ensuite les étapes suivantes :

```plain
tar -xzvf regina-rexx-3.9.5.tar.gz && cd regina-rexx-3.9.5
./configure
sudo make
sudo make install
```

La bibliothèque (`libregina.so`) ainsi que deux ensembles de binaires (`rexx` et `regina`) sont installés (l'emplacement par défaut est `/usr/local/bin`).

Le binaire `rexx` est lié statiquement : il est donc autonome et prêt à l'emploi.

Le binaire `regina` est lié dynamiquement, il nécessite donc un peu de configuration pour pouvoir localiser la bibliothèque partagée `libregina.so` à l'exécution. Pour ce faire, suis ces étapes :

```plain
# Configure shared library location
sudo su
echo /usr/local/lib64/ > /etc/ld.so.conf.d/regina-rexx-3.9.5-x86_64.conf
echo /usr/local/lib64/regina-rexx/addons > /etc/ld.so.conf.d/regina-rexx-addons-x86_64.conf
cd /usr/local/lib64
rm -f libregina.so libregina.so.3
ln -s libregina.so.3.9 libregina.so
ln -s libregina.so.3.9 libregina.so.3
ldconfig
exit

# Check symbolic link creation
ls -l /usr/local/lib64/

# Output should be similar. Note symbolic links.
-rw-r--r--. 1 root root 3887554 Dec  1 18:22 libregina.a
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so -> libregina.so.3.9
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so.3 -> libregina.so.3.9
-rwxr-xr-x. 1 root root  574104 Dec  1 18:22 libregina.so.3.9
drwxr-xr-x. 2 root root      26 Dec  1 18:22 pkgconfig
drwxr-xr-x. 4 root root      33 Dec  1 18:22 regina-rexx

# Check library path, and executable using that path
ldconfig -p | grep regina
ldd /usr/local/bin/regina

# Alternate for local user
export LD_LIBRARY_PATH=${LD_LIBRARY_PATH}:/usr/local/lib64:/usr/local/lib64/regina-rexx/addons
```

Note que la compilation depuis les sources, et la configuration système qui l'accompagne, est une tâche que seuls des utilisateurs expérimentés devraient entreprendre.

### MacOS

L'installation se déroule en trois étapes :

* Installe le gestionnaire de paquets [Homebrew](https://brew.sh)
* Trouve et lance l'application `Terminal`
* Depuis la ligne de commande de `Terminal`, saisis ce qui suit :

   `brew install regina-rexx`

Cela _devrait_ installer la version la plus récente.

Si ce n'est pas le cas, tu peux télécharger le paquet [Regina for MacOS](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-apple-darwin21.6.0.tgz/download) et l'installer manuellement.

## Après l'installation

### Vérification de l'installation

Une fois l'installation terminée, tu peux vérifier que [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) a bien été installée en exécutant cette commande dans un terminal :

```plain
rexx --version=v
```

Sur Windows comme sur Linux, la sortie suivante apparaît dans le terminal :

```plain
3.9.5
```

qui correspond au numéro de version de l'interprète.

Un second binaire, `regina`, est également installé. Il est identique à `rexx` en tout point, à ceci près qu'il est lié à une bibliothèque partagée ; c'est l'interprète à utiliser si tu souhaites accéder à des fonctions utilitaires externes. Voir la section [Accède aux routines externes](###accessing-external-routines).

Aucun autre composant logiciel n'a besoin d'être installé pour commencer à utiliser le parcours (en supposant que tu aies installé l'Exercism CLI).

Les notes d'utilisation ci-dessous te donneront les bases pour utiliser l'interprète en ligne de commande.

### Utilisation

Un script Rexx a généralement une extension _`.rexx`_, bien que ce ne soit pas obligatoire : l'interprète tentera d'exécuter quel que soit le nom de fichier qui lui est passé en argument, et s'il contient du code Rexx valide, il s'exécutera correctement.

La commande suivante tentera d'exécuter un fichier nommé `hello.rexx` :

```plain
rexx hello.rexx
```

En supposant que le fichier contienne le code suivant :

```rexx
say "Hello, world!"
exit 0
```

la sortie du terminal serait alors :

```plain
Hello, world!
```

La même sortie apparaîtrait si le fichier était renommé en `hello.txt` et exécuté ainsi :

```plain
rexx hello.txt
```

Il est également bon de savoir que le code d'un script peut être envoyé à l'interprète via un tube, plutôt que de résider dans un fichier. Le code précédent peut être exécuté via un tube comme suit :

```plain
echo "say 'Hello, world' ; exit 0" | rexx
```

et cela fonctionne aussi bien depuis un terminal Linux que depuis un terminal Windows Powershell.

### Utilisation avancée

Les fichiers de script peuvent recevoir un ou plusieurs arguments de ligne de commande et peuvent renvoyer des codes de retour arbitraires, en nombres entiers. Toutefois, l'interprète doit savoir que plusieurs arguments seront transmis au script, ce qui se fait grâce à l'option `-a`.

Par exemple, supposons que le fichier `multiarg.rexx` contienne le code suivant :

```rexx
say "My name is" ARG(1) || ", your name is" ARG(2) || ", and the script return code will be" ARG(3) || "."
exit ABS(ARG(3))
```

Pour que les multiples arguments du script soient correctement interprétés, le script est exécuté comme suit :

```plain
rexx -a multiarg.rexx "John" "Jill" 5
```

ce qui produit la sortie suivante dans le terminal :

```plain
My name is John, your name is Jill, and the script return code will be 5.
```

et le code de retour du programme (accessible via `$?` sous Linux, ou `%errorlevel%` sous Windows) prend la valeur 5.

### Accède aux routines externes

Regina prend en charge l'utilisation de routines résidant dans des bibliothèques partagées externes. Plusieurs sont disponibles sur le site de Regina. L'installation de ces bibliothèques n'est toutefois pas abordée ici.

Regina est livré avec une de ces bibliothèques, _regutil_. Elle contient plusieurs routines polyvalentes, notamment pour les mathématiques, la manipulation de fichiers et de systèmes de fichiers, et les tâches d'accès au système.

Aucune étape d'installation supplémentaire n'est nécessaire. Toutefois, pour utiliser ces routines dans un script, il faut qu'elles soient enregistrées au chargement de l'interprète. Cela ne demande pas plus de deux appels de fonction, et le processus est illustré ici.

Un fichier `access-external.rexx` contient le code suivant :

```rexx
/* Register external library and functions */
call RxFuncAdd 'SysLoadFuncs', 'regutil', 'SysLoadFuncs'
call SysLoadFuncs

say "Value of pi is" SysPi()
say "Square root of 25 is" SysSqrt(25)
say "Square root of 2 is" SysSqrt(2)

/* Deregister */
call SysDropFuncs

exit 0
```

Pour charger et utiliser ces routines, c'est le binaire `regina` qu'il faut employer, le script serait donc exécuté ainsi :

```plain
regina access-external.rexx
```

et la sortie suivante apparaît dans le terminal :

```plain
Value of pi is 3.141592654
Square root of 25 is 5.000000000
Square root of 2 is 1.414213562
```

Si c'est le binaire `rexx` qui avait été utilisé, la sortie du terminal sous Windows serait :

```plain
'SYSLOADFUNCS' is not recognized as an internal or external command,
operable program or batch file.
'SYSPI' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSDROPFUNCS' is not recognized as an internal or external command,
operable program or batch file.
```

tandis que sous Linux, la sortie du terminal serait :

```plain
sh: SYSLOADFUNCS: command not found
sh: SYSPI: command not found
sh: SYSSQRT: command not found
sh: SYSSQRT: command not found
sh: SYSDROPFUNCS: command not found
```
