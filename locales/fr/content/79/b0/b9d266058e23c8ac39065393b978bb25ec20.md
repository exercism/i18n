# À propos

La mémoire dynamique est mise en œuvre par des fonctions de bibliothèque que le programmeur utilise pour allouer et libérer de la mémoire au moment de l'exécution.
Comme c'est le programmeur qui contrôle l'allocation et la libération de la mémoire, la mémoire dynamique est aussi sûre que le programmeur est à l'abri de l'erreur humaine.
Pour cette raison, la mémoire dynamique est l'une des principales sources de bugs et une cible de choix pour les attaques informatiques.

On utilise la mémoire dynamique pour les variables dont la taille n'est connue qu'au moment de l'exécution.
C'est particulièrement utile pour les tableaux dont le nombre d'éléments peut varier d'une exécution à l'autre.
Les tableaux de longueur variable (VLA) sont une autre façon de gérer les tableaux dont la taille des éléments n'est connue qu'au moment de l'exécution.
Un VLA utilise la durée de vie automatique, ce qui signifie que sa mémoire est libérée lorsqu'on quitte le bloc dans lequel il est défini.
(Pour en savoir plus sur la durée de vie, consulte le concept [spécificateurs de classe de stockage](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers).)
Les VLA ont été introduits dans le langage C par C99, mais depuis C11 ils sont facultatifs, si bien que les compilateurs qui prennent en charge C11 et au-delà ne sont pas obligés de prendre en charge les VLA.
Une analyse détaillée des tableaux de longueur variable dépasse le cadre de cet article.

## malloc

`malloc` est une fonction déclarée dans `stdlib.h` qui sert à allouer de la mémoire dynamique.
Si l'allocation réussit, un pointeur est renvoyé, qui pointe vers l'adresse du premier octet de la mémoire allouée.
Si l'allocation échoue, `NULL` est renvoyé.
Il est prudent de vérifier que le résultat de `malloc` n'est pas `NULL` et de gérer proprement l'échec éventuel.
Le pointeur renvoyé est de type `pointer-to-void`, que l'on peut en gros considérer comme un pointeur « générique » convertible vers le type spécifique utilisé par la mémoire.
`malloc` prend un paramètre : la taille, en octets, de la mémoire souhaitée.
La taille totale nécessaire pour allouer un tableau est la taille du type de données de chaque élément multipliée par le nombre d'éléments.
L'opérateur `sizeof` est couramment utilisé pour obtenir la taille du type de données de chaque élément.
L'exemple suivant le montre

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

Il est important de garder en tête que la mémoire fraîchement allouée par `malloc` n'est pas initialisée et peut contenir des valeurs résiduelles.
Note que le `sizeof` du pointeur `numbers` n'est ni le nombre d'éléments du tableau, ni la quantité totale de mémoire allouée.
La taille du pointeur renvoyé par `malloc` est la taille de n'importe quel pointeur sur ce système donné.
Le code d'exemple a été exécuté sur un système 64 bits, la taille du pointeur était donc de 8 octets (multiplié par 8 bits par octet = 64 bits).
Le type du pointeur a été implicitement converti de pointeur vers void en pointeur vers int.
Que le pointeur vers int pointe vers un seul `int` ou vers un tableau d'`ints`, c'est au programmeur de décider comment le traiter.
Par exemple

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

S'il est certain que la ou les valeurs seront écrites avant d'être lues, alors utiliser `malloc` peut être un moyen efficace d'allouer de la mémoire.
Mais s'il y a un risque que la ou les valeurs soient lues avant d'être initialisées, alors utiliser `malloc` est risqué.
Un moyen plus sûr d'allouer de la mémoire est d'utiliser `calloc`, qui initialise à zéro la mémoire fraîchement allouée.

Remarque dans les exemples ci-dessus que `free(numbers)` a été utilisé.

## free

`free` est une fonction déclarée dans `stdlib.h` qui sert à libérer de la mémoire allouée dynamiquement.
La mémoire allouée dynamiquement reste réservée jusqu'à ce qu'elle soit libérée par `free`.
Certains systèmes d'exploitation peuvent libérer automatiquement la mémoire allouée dynamiquement à la fin du programme, mais la bonne pratique est de ne pas compter là-dessus.
`free` prend un paramètre : un pointeur vers la mémoire qui a été allouée dynamiquement.
L'utilisation ou l'absence d'utilisation de `free` est associée à plusieurs problèmes de mémoire.

#### Fuite de mémoire

Ne pas libérer de la mémoire allouée dynamiquement alors que la référence vers cette mémoire a atteint la fin de sa durée de vie, ou a été détruite d'une manière ou d'une autre, s'appelle une fuite de mémoire.
La mémoire perdue est de la mémoire réservée par le système mais qui n'est plus accessible au programme.
Cela peut poser un problème particulier si de la mémoire est allouée dans une boucle, n'est pas libérée à la fin de la boucle, et est allouée à nouveau au début de la boucle.
Si l'on alloue suffisamment de mémoire sans la libérer, l'appel d'allocation échouera faute de mémoire disponible.
Il est important de garder en tête que, bien que la mémoire allouée dynamiquement reste réservée par le système jusqu'à sa libération, le pointeur auquel elle est affectée peut n'avoir qu'une portée de bloc.
Par exemple, dans les exemples sur `malloc`, la mémoire est allouée dans `my_function`.
Cette mémoire serait perdue si le pointeur vers celle-ci n'était pas renvoyé et utilisé pour définir le pointeur `numbers` dans `main`.
Ainsi, passer ce pointeur `numbers` à `free` libère la mémoire allouée dans `my_function`.

#### Utilisation après libération (**UAF**)

Si l'on accède à de la mémoire après l'avoir libérée, la ou les valeurs peuvent être n'importe quoi.
Dans l'exemple suivant, la mémoire pointée par `numbers` est libérée, puis lue dans `printf`.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

Le pointeur `numbers`, une fois libéré, est appelé un pointeur fantôme.
Un pointeur fantôme peut pointer vers une autre mémoire que celle à laquelle il était destiné.
Ainsi, un pointeur fantôme peut entraîner une corruption de données, ainsi que la substitution et l'exécution de code arbitraire.
Un pointeur vers de la mémoire allouée qui n'a pas été remis à `NULL` peut servir à pirater le programme.
Dans l'exemple ci-dessus, si `numbers` était remis à `NULL` ainsi : `numbers = NULL;` après sa libération, le `printf` suivant entraînerait l'arrêt du programme, en signalant peut-être une erreur de segmentation lors de la tentative de lecture de `numbers[0]`.

#### Double libération

Si `free` est appelé deux fois sur un pointeur vers de la mémoire allouée dynamiquement, cela provoque un comportement indéfini (**UB**).
Cela signifie que le compilateur peut le gérer de façon arbitraire, comme bon lui semble.
L'exemple suivant, compilé avec deux compilateurs différents, peut donner deux résultats différents

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

Le premier et le deuxième compilateur n'ont généré aucune erreur d'exécution lorsque `numbers` était remis à `NULL` entre chaque appel à `free`, mais rien ne garantit que cela fonctionnerait avec un troisième compilateur.
Une cause fréquente de double libération est d'avoir deux pointeurs qui pointent vers la même mémoire allouée dynamiquement.
Un pointeur peut pointer vers le début d'un tableau à un endroit du programme, et l'autre pointeur peut servir à parcourir le tableau à un autre endroit du programme.
À différents endroits du programme, chaque pointeur est libéré, ce qui provoque une double libération.

## calloc

`calloc` est une fonction déclarée dans `stdlib.h` qui sert à la fois à allouer de la mémoire dynamique et à initialiser à zéro la mémoire fraîchement allouée.
Si l'allocation réussit, un pointeur est renvoyé, qui pointe vers l'adresse du premier octet de la mémoire allouée.
Si l'allocation échoue, `NULL` est renvoyé.
Il est prudent de vérifier que le résultat de `calloc` n'est pas `NULL` et de gérer proprement l'échec éventuel.
Le pointeur renvoyé est de type `pointer-to-void`, que l'on peut en gros considérer comme un pointeur « générique » convertible vers le type spécifique utilisé par la mémoire.
`calloc` prend deux paramètres.
Le premier paramètre indique combien d'éléments du type de données spécifié doivent être alloués.
Le second paramètre indique la taille du type de données à allouer.

Dans l'exemple suivant, toutes les instructions `printf` doivent toujours afficher `0`, car `calloc` garantit la mise à zéro des valeurs fraîchement allouées.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` est une fonction déclarée dans `stdlib.h` qui sert soit à agrandir, soit à réduire une mémoire déjà allouée.
Si la réallocation réussit, un pointeur est renvoyé, qui pointe vers l'adresse du premier octet de la mémoire réallouée.
Si la réallocation échoue, `NULL` est renvoyé.
Il est prudent de vérifier que le résultat de `realloc` n'est pas `NULL` et de gérer proprement l'échec éventuel.
`realloc` prend deux paramètres.
Le premier paramètre est un pointeur vers la mémoire existante à réallouer.
Le second paramètre indique la taille, en octets, de la mémoire réallouée.
Les valeurs définies avant l'agrandissement de la mémoire sont conservées.
Il est important de garder en tête que la mémoire ajoutée lors de l'agrandissement n'est pas initialisée à zéro et que ses valeurs peuvent être n'importe quoi.
De plus, la mémoire retirée lors de la réduction n'est pas non plus initialisée et peut conserver ses valeurs.
L'exemple suivant illustre l'agrandissement et la réduction d'un tableau

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## Quand la taille passée vaut 0

Si la taille passée à `malloc`, `calloc` ou `relloac` vaut `0`, ce qui se passe dépend de la façon dont le compilateur l'implémente.
Un compilateur peut soit renvoyer un pointeur `NULL`, soit renvoyer un pointeur non nul.
Par exemple, lors de l'allocation de mémoire pour un pointeur vers `char`, le compilateur peut renvoyer soit `NULL`, soit un pointeur non nul vers une chaîne vide.
Pour éviter des résultats différents selon les compilateurs, mieux vaut ne pas allouer avec une taille de 0.
