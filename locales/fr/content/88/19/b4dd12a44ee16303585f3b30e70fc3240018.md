# Booléens

Swift dispose d'un type appelé [`Bool`][bools], qui sert à représenter les valeurs `true` et `false`.

## Opérateurs logiques

Swift dispose de 3 [opérateurs logiques (`!`, `||`, `&&`)][logical-operators] qui permettent de combiner des booléens et de construire des expressions qui produisent des valeurs différentes.

### Et (`&&`)

L'[opérateur _et_][and] en Swift est représenté par `&&` et renvoie `true` si les deux valeurs données sont `true`, sinon il renvoie `false`.
Quand on utilise l'opérateur _et_, on place un booléen à droite du `&&` et un autre à gauche.

```Swift
true && true  // true
true && false // false
```

### Ou (`||`)

L'[opérateur _ou_][or] en Swift est représenté par `||` et renvoie `true` si **au moins une** des valeurs données est `true`. Si les deux valeurs sont `false`, alors il renvoie `false`.
Quand on utilise l'opérateur _ou_, on place un booléen à droite du `||` et un autre à gauche.

```swift
true || true   // true
true || false  // true
false || false // false
```

### Non (`!`)

L'[opérateur _non_][not] en Swift est représenté par `!` et renvoie `true` si le booléen donné est `false`, et renvoie `false` si on lui donne `true`.
Quand on utilise l'opérateur _non_, on place un booléen après l'opérateur (`!`).

```swift
!true  // false
!false // true
```

## Utilise des parenthèses (`()`)

Quand on travaille avec des booléens, on peut utiliser des [parenthèses explicites][explicit-parentheses] pour décider quels booléens évaluer en premier.
Le résultat peut différer selon la façon dont on utilise les parenthèses.
En Swift, ce qui se trouve entre parenthèses est évalué en premier.

```swift
true && false && false || true   // true
true && false && (false || true) // false
```

Comme ce qui est entre parenthèses est évalué en premier, dans l'exemple suivant, l'opérateur _non_ s'applique à l'expression entre parenthèses.

```Swift
!true && false   // false
!(true && false) // true
```

~~~~exercism/note
Tu ne devrais utiliser des parenthèses que lorsqu'elles changent le résultat ; sinon, il vaut mieux les omettre.
~~~~
