# Instructions

À la suite d'un récent audit de sécurité, on t'a demandé de nettoyer les fichiers de log archivés de l'organisation.

## 1. Identifie les lignes de log brouillées

Tu dois te faire une idée du nombre de lignes de log de ton archive qui ne respectent pas les normes actuelles.
Tu penses qu'un test simple permet de savoir si une ligne de log est valide.
Pour être considérée comme valide, une ligne doit commencer par l'une des _strings_ suivantes :

- [DEBUG]
- [INFO]
- [WARNING]
- [ERROR]

Implémente la fonction `valid_line?/1` pour qu'elle renvoie `true` si la ligne de log est valide.

```elixir
LogParser.valid_line?("[ERROR] Network Failure")
# => true

LogParser.valid_line?("Network Failure")
# => false
```

## 2. Sépare la ligne de log

Peu après avoir commencé le projet d'analyse de logs, tu te rends compte que les logs d'une application ne sont pas découpés en lignes comme les autres. Dans ce projet, ce qui aurait dû former plusieurs lignes se retrouve sur une seule ligne, relié par d'étranges flèches comme `<--->` ou `<*~*~>`.

En fait, toute _string_ qui commence par `<`, se termine par `>` et contient entre les deux n'importe quelle combinaison des caractères `~`, `*`, `=` et `-` peut servir de séparateur dans les logs de ce projet.

Implémente la fonction `split_line/1` qui prend une ligne et renvoie un tableau de _strings_.

```elixir
LogParser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
# => ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. Supprime les artefacts du log

Tu as découvert qu'un traitement en amont des logs a parsemé les logs du texte « end-of-line » suivi d'un numéro de ligne (sans espace intermédiaire).

Implémente la fonction `remove_artifacts/1` qui prend une _string_ et supprime toutes les occurrences du texte « end-of-line » (sans tenir compte de la casse), puis renvoie une ligne de log propre.

Les lignes qui ne contiennent pas de texte « end-of-line » doivent être renvoyées sans modification.

Supprime simplement la _string_ « end-of-line », il n'est pas nécessaire d'ajuster les espaces.

```elixir
LogParser.remove_artifacts("[WARNING] end-of-line23033 Network Failure end-of-line27")
# => "[WARNING]  Network Failure "
```

## 4. Marque les lignes avec les noms d'utilisateur

Tu as remarqué que certaines lignes de log contiennent des phrases qui font référence à des utilisateurs.
Ces phrases contiennent toujours la _string_ `"User"`, suivie d'un ou plusieurs caractères d'espacement, puis d'un nom d'utilisateur.
Tu décides de marquer ces lignes.

Implémente une fonction `tag_with_user_name/1` qui traite les lignes de log :

- Les lignes qui ne contiennent pas la _string_ `"User"` restent inchangées.
- Pour les lignes qui contiennent la _string_ `"User"`, préfixe la ligne avec `[USER]` suivi du nom d'utilisateur.

```elixir
LogParser.tag_with_user_name("[INFO] User Alice created a new project")
# => "[USER] Alice [INFO] User Alice created a new project"
```

Tu peux supposer que :

- Chaque occurrence de la _string_ `"User"` est suivie d'un ou plusieurs caractères d'espacement et du nom d'utilisateur.
- Il y a au plus une occurrence de la _string_ `"User"` par ligne.
- Les noms d'utilisateur sont des _strings_ non vides qui ne contiennent pas d'espace.
