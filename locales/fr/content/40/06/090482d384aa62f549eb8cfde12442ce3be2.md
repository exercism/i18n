# Instructions

Ton travail consiste à développer et à maintenir une partie du système informatique d'un parc d'attractions.
Tu es notamment responsable du programme qui gère les visiteurs et les billets.

Tu vas d'abord créer un nouveau visiteur dans le système.
Ensuite, tu écriras une fonction pour révoquer un billet.
Dans les tâches 3 et 4, tu travailleras sur le système de suivi des billets qui aide à prévenir la falsification.
Enfin, tu participeras à l'adaptation du système à de nouvelles exigences légales.

## 1. Créer un nouveau visiteur

Lorsque les visiteurs viennent au parc d'attractions pour la première fois, ils doivent s'inscrire en saisissant leur nom et leur âge dans un terminal et en acceptant les conditions générales.
Bien sûr, ils doivent aussi acheter un billet.
Chaque billet possède un identifiant comme `H32AZ123`.

Écris une fonction `createVisitor` qui prend trois arguments.

- Le nom du visiteur.
- L'âge du visiteur.
- L'identifiant du billet que le visiteur a acheté.

La fonction doit renvoyer un objet contenant ces informations.
Les clés de l'objet doivent s'appeler `name`, `age` et `ticketId`.

```javascript
createVisitor('Verena Nardi', 45, 'H32AZ123');
// => { name: 'Verena Nardi', age: 45, ticketId: 'H32AZ123' }
```

## 2. Révoquer le billet

Quand les visiteurs quittent le parc d'attractions, leur billet est révoqué.
S'ils reviennent, ils doivent en acheter un nouveau.
Pour faire gagner du temps aux visiteurs réguliers, ceux-ci n'ont besoin de s'inscrire qu'une seule fois, et les informations du visiteur sont conservées pour les visites suivantes.

Cela signifie que lorsqu'un visiteur quitte le parc, seul son billet doit être invalidé, tandis que le reste de l'objet visiteur doit rester inchangé.
Implémente la fonction `revokeTicket` qui prend un objet visiteur, met l'identifiant du billet à `null` et renvoie ensuite l'objet.

```javascript
const visitor = {
  name: 'Verena Nardi',
  age: 45,
  ticketId: 'H32AZ123',
};

revokeTicket(visitor);
// => { name: 'Verena Nardi', age: 45, ticketId: null }
```

## 3. Déterminer l'état du billet

Pour éviter la falsification, les identifiants des billets sont uniques.
Une fois un billet imprimé, son identifiant est ajouté comme clé dans un objet du système afin de pouvoir le suivre.

Avant d'être vendu à un visiteur, le billet est enregistré avec la valeur `null` dans l'objet de suivi des billets.
Lorsqu'il est vendu à un visiteur, le nom du visiteur est affecté comme valeur.
Quand les employés doutent de la validité d'un billet, ils doivent vérifier l'état du billet dans le système.

Implémente une fonction `ticketStatus` qui prend l'objet de suivi et un identifiant de billet comme arguments.
Elle doit renvoyer l'un des résultats suivants.

- `'unknown ticket id'` si l'identifiant n'a pas été trouvé dans l'objet de suivi
- `'not sold'` si le billet a été imprimé mais pas vendu
- `'sold to {name}'` où `{name}` est le nom du visiteur si le billet a été vendu

```javascript
const tickets = {
  '0H2AZ123': null,
  '23LA9T41': 'Verena Nardi',
};

ticketStatus(tickets, 'RE90VAW7');
// => 'unknown ticket id'

ticketStatus(tickets, '0H2AZ123');
// => 'not sold'

ticketStatus(tickets, '23LA9T41');
// => 'sold to Verena Nardi'
```

## 4. Améliorer la réponse de l'état du billet

Au bout d'un moment, les employés te font remarquer qu'ils veulent que l'état du billet soit plus facile à comprendre au premier coup d'œil.
Ils veulent seulement voir soit le nom du visiteur, soit que le billet est invalide.

Écris une fonction `simpleTicketStatus` qui prend les mêmes arguments que `ticketStatus` dans la tâche 3.
Cette fonction ne renvoie que l'un de ces deux résultats.

- le nom du visiteur si le billet a été vendu
- `'invalid ticket !!!'` si le billet n'a pas encore été vendu ou si l'identifiant n'a pas été trouvé dans l'objet de suivi

```javascript
const tickets = {
  '0H2AZ123': null,
  '23LA9T41': 'Verena Nardi',
};

simpleTicketStatus(tickets, '23LA9T41');
// => 'Verena Nardi'

simpleTicketStatus(tickets, '0H2AZ123');
// => 'invalid ticket !!!'

simpleTicketStatus(tickets, 'RE90VAW7');
// => 'invalid ticket !!!'
```

## 5. Déterminer la version des conditions générales

En raison de nouvelles exigences légales, les objets visiteurs créés récemment contiennent désormais aussi des informations détaillées sur les « conditions générales » (CG) que l'utilisateur a acceptées.
Tu peux voir ci-dessous un exemple du nouvel objet visiteur.

Les caissiers du parc d'attractions doivent désormais vérifier si un visiteur doit signer une nouvelle version des CG.
Pour cela, implémente une fonction `gtcVersion` qui prend un objet visiteur comme argument et renvoie la version des CG si elle est disponible.
Si l'information de version n'est pas disponible, rien ne doit être renvoyé.

```javascript
const visitorNew = {
  name: 'Verena Nardi',
  age: 45,
  ticketId: 'H32AZ123',
  gtc: {
    signed: true,
    version: '2.1',
  },
};

gtcVersion(visitorNew);
// => '2.1'

const visitorOld = {
  name: 'Verena Nardi',
  age: 45,
  ticketId: 'H32AZ123',
};

gtcVersion(visitorOld);
// => undefined
```
