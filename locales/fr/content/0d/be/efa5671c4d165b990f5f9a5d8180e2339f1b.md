# À propos

Les [types personnalisés][custom-types] en Elm représentent un nombre fixe de cas nommés. Chaque valeur correspond à exactement un de ces cas nommés. Dans d'autres langages ou contextes, on les appelle _sum types_, _discriminated unions_, _tagged unions_ ou _algebraic data types_.

Chaque cas d'une union discriminée peut, éventuellement, avoir des données qui lui sont associées, et des cas différents peuvent avoir des types de données différents. Si aucun des cas n'a de données associées, l'union discriminée ressemble à ce que d'autres langages appellent en général une _enumeration_ (ou _enum_).

Un type personnalisé se définit avec le mot-clé `type` et demande très peu de syntaxe. Les types personnalisés comptent parmi les techniques les plus importantes de la programmation en Elm : on les utilise pour faire correspondre exactement les valeurs possibles dans le code aux valeurs valides dans la vie réelle, ce qui ne laisse aucune place aux données invalides et rend [impossible de représenter un état impossible dans le code][impossible-states].

```elm
-- Custom Type without associated data
type Season
    = Spring
    | Summer
    | Autumn
    | Winter

-- Custom Type with associated data
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Créer une valeur pour un cas particulier se fait en faisant référence à son nom (`Spring`), lorsque ce cas est défini dans le même module, ou importé avec la syntaxe `import SeasonModule exposing (Season(..))`, ou en faisant référence à son nom pleinement qualifié (`Season.Spring`), lorsqu'il est importé avec la syntaxe `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Les types personnalisés, comme tout ce qui existe en Elm, ont une _égalité structurelle_, ce qui signifie que deux valeurs du même cas portant les mêmes données (facultatives) sont équivalentes.

La façon recommandée de manipuler les types personnalisés est le [filtrage par motif][pattern-matching] :

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
