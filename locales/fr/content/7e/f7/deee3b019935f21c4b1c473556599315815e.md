# Les fonctions en `jq`

Tu peux définir tes propres **fonctions personnalisées** en `jq` pour encapsuler la logique dont tu as besoin. Les _fonctions_ se comportent exactement comme les fonctions natives : elles prennent une entrée et émettent zéro, une ou plusieurs sorties.

## Définir une fonction

Tu peux définir une _fonction_ `jq` avec la syntaxe suivante :

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- commence par le mot-clé `def`,
- un deux-points avant le corps de la fonction,
- le corps est constitué d'une seule expression,
- se termine par un point-virgule,
- comme pour le reste de la syntaxe `jq`, tu peux utiliser des espaces arbitraires pour la lisibilité.

## Où placer les fonctions

Les _fonctions_ doivent être définies avant d'être utilisées : ceci est une erreur :

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Cela implique que tu dois placer les _fonctions_ en haut de ton code `jq`, avant l'expression « principale ».

### Fonctions imbriquées

Les _fonctions_ peuvent être imbriquées :

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Ici, la _fonction_ `B` n'est visible que dans le corps de `A`.

## Portée

Une _fonction_ introduit une nouvelle **portée** pour les variables et les fonctions imbriquées.

## Arguments

Les **arguments** d'une _fonction_ sont séparés par des _points-virgules_ et non par des virgules.
Par exemple, une _fonction_ qui prend un nombre, puis ajoute un nombre et multiplie par un nombre :

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

### Les arguments sont des _expressions_

Les _arguments_ d'une fonction sont des filtres, pas des valeurs.
En ce sens, ils se comportent comme ce que d'autres langages appellent des _callbacks_ :

En prenant la fonction `add_mul` comme exemple :

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

Que se passe-t-il ici ?

- l'argument `adder` reçoit l'_expression_ `. + 5`
  - quand la fonction fait `. + adder`, cela devient `. + . + 5`
  - cela s'évalue à 25 puisque `. == 10`
- de même, l'argument `multiplier` est l'expression `. - 2`
  - cela s'évalue à 8
  - puis le résultat est `25 * 8 == 200`

### Les arguments en tant que valeurs

Parfois, tu voudras « matérialiser » un _argument_ dans une variable :

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Il existe une syntaxe abrégée pour cela :

```jq
def my_func($arg):
    other stuff ...
;
```

Note que ce n'est que du « sucre syntaxique » : le nom `arg` sans `$` est toujours dans la portée de la _fonction_.

## Arité

Les _fonctions_ ont une **arité** : le nombre d'_arguments_ qu'elles prennent.

Les _fonctions_ peuvent utiliser le même nom avec des _arités_ différentes.
La fonction native [`range`][man-range] le démontre : `range/1`, `range/2` et `range/3` coexistent toutes.

Cela peut être utile pour définir des fonctions récursives qui portent un état via des arguments.
Par exemple, `map` _pourrait_ être implémentée comme ceci :

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Récursion

`jq` effectue l'optimisation des appels terminaux, mais uniquement pour les fonctions d'arité 0.

## Modules

Un module `jq` est un fichier ne contenant que des fonctions.
Les modules sont inclus dans un programme jq avec les commandes [`include`][man-include] ou [`import`][man-import].
