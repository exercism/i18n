# À propos des conditions

## Opérateurs de comparaison

Les [opérateurs de comparaison][operators] sont semblables à ceux de nombreux autres langages, avec quelques extensions.

Pour l'égalité, les opérateurs sont `==` (égal) et `!=` (différent).

```Kotlin
val txt = "abc"
txt == "abc" // => true
txt != "abc" // => false
```

De plus, les opérateurs `===` et `!==` testent l'[« égalité référentielle »][referential-equality] : `a === b` si et seulement si `a` et `b` pointent vers le même objet. Cela devrait devenir plus clair plus tard dans le programme.

Les opérateurs supérieur/inférieur sont eux aussi classiques.

```Kotlin
1 < 3 // => true
3 > 3 // => false
3 <= 3 // => true
4 >= 3 // => true
```

## Branchements avec `if`

Voici la forme complète d'une [expression `if`][if-else] :

```Kotlin
if (conditional1) {
//    something...
} else if (conditional2) {
//    something...
} else {
//    something...
}
```

- Les parenthèses `()` autour de chaque condition sont obligatoires.
- Une condition doit s'évaluer en un booléen `true` ou `false`.
  Kotlin ne connaît pas les notions de « _truthy_ » et « _falsy_ » que l'on trouve dans certains langages.
- Les accolades `{}` sont facultatives s'il n'y a qu'une seule expression.
- `else if` et `else` sont tous deux facultatifs, et il peut y avoir plusieurs blocs `else if`.

L'expression `if` peut aussi servir à « choisir » une valeur :

```Kotlin
val number = 100000
val description = if (number > 100) "number is over 100" else "number is less than 100"
// => description = "number is over 100"
```

## Des alternatives ?

Par choix délibéré, Kotlin ne dispose _pas_ de l'opérateur ternaire `? :` présent en Java. On préfère une forme concise de `if ... else` :

```Kotlin
val result = if (isOk) goodValue else badValue

return if (isOK) goodValue else badValue
```

Contrairement à Ruby, la forme concise `if ... else` a *toujours* besoin d'un `else` et ne peut donc pas servir d'instruction de garde :

```kotlin
return 42 if (isOk)
// Syntax error: Unexpected tokens (use ';' to separate expressions on the same line).
// Syntax error: Expecting an expression.

return if (isOk) true
// 'if' must have both main and 'else' branches when used as an expression.
```

À noter qu'en Kotlin, `if` est une [_expression_][expression] qui renvoie une valeur. Ce n'est pas une [_instruction_][statement] comme en Java.

On verra dans un prochain concept que Kotlin possède une puissante construction [`when`][when], destinée à remplacer les longues chaînes de clauses `else if` par du filtrage par motif.
