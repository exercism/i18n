# À propos

En C#, un tuple est une structure de données qui organise des données et contient deux champs ou plus, de n'importe quel type.

On crée généralement un tuple en plaçant 2 expressions ou plus séparées par des virgules, entre parenthèses.

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

Comme toute autre expression, un tuple peut servir de bien des façons : dans des [affectations][tuple-assignment], pour initialiser un champ ou une variable, comme [valeur de retour][tuple-return-values] d'une méthode, ou passé en paramètre. On peut aussi tester leur [égalité][tuple-equality]. L'égalité des tuples est illustrée en détail dans l'exercice `pattern-matching-tuples`, mais un exemple est fourni dans le code ci-dessous pour être complet.

On extrait les champs avec la syntaxe point. Par défaut, le premier champ est `Item1`, le deuxième `Item2`, etc. Les noms non par défaut sont abordés plus bas, à la section _Nommage_.

Un tuple peut être utilisé comme paramètre générique, par exemple `IList<(bool, string)>`.

De plus, les tuples prennent en charge la « déconstruction », abordée plus bas, et peuvent être utilisés dans la correspondance de motifs, qui est traitée dans un exercice ultérieur.

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

Cette [introduction][tuples] montre comment définir et utiliser les tuples.

## Nommage

Les noms de champs `Item1`, etc. ne donnent pas un code très lisible. Il y a 3 façons de nommer les champs : a) dans la déclaration du type, b) dans l'expression qui le crée, c) au moyen d'[initialiseurs de projection de tuple][tuple-projection-initializers] (non illustrés ici).

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

N'essaie pas de faire trop de zèle avec le mécanisme de nommage. Ce n'est vraiment que du sucre syntaxique. Par exemple, on ne peut pas changer les noms d'un tuple quand on l'affecte depuis un autre tuple.

## Déconstruction

Parfois, il est pratique de prendre un tuple et d'affecter ses champs à plusieurs variables, en les initialisant si nécessaire. Ce mécanisme s'appelle la [déconstruction][tuple-deconstruction]. (Il peut aussi s'appliquer à tes propres objets. Voir [ici][udt-deconstruction].)

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## Affectation des champs

On peut affecter les champs d'un tuple individuellement. Cependant, compte tenu de la tendance du C# vers l'immuabilité, ce type d'usage reste peu répandu. On utilise souvent les tuples comme s'ils étaient immuables, ce qui n'est évidemment pas le cas.

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## Contexte

Les tuples dont nous parlons ici ne doivent pas être confondus avec [`System.Tuple`][system-tuple], que l'on ne trouvera probablement que dans des bases de code héritées.

La situation est un peu plus confuse quand on en vient à `System.ValueTuple`. La [documentation][system-value-tuple] de la dernière surcharge de [`System.ValueTuple`][system-value-tuple] indique que « les types valeur tuple fournissent l'implémentation d'exécution qui prend en charge les tuples en C#  ». Par « types valeur tuple », ils désignent ici les surcharges génériques de `System.ValueTuple`. Par « tuples », ils entendent ce qui nous a occupés dans cet exercice. En clair, ils disent que `System.ValueTuple` est un détail d'implémentation des tuples. Tout cela a peu de chances d'intéresser beaucoup de gens la plupart du temps. Malheureusement, une grande partie de la documentation sur les « tuples », y compris celle de Microsoft, est parsemée de références à `System.ValueTuple`. On peut sans doute survoler ces références.

## Autres usages et limites

La correspondance de motifs est un usage particulièrement productif des tuples. Elle est traitée dans un exercice ultérieur.

Les tuples permettent quelques autres petites fantaisies de style :

- L'affectation multiple (notamment dans les constructeurs), par exemple `(this.field1, this.field2) = (arg1, arg2);`
- L'échange ou le recyclage de valeurs, par exemple `(a, b) = (b, a);`
- L'utilisation à la place d'une `struct` dans une liste
- L'utilisation comme clé de dictionnaire ou comme contenu d'un ensemble.
- L'utilisation dans LINQ. (LINQ est traité dans des exercices ultérieurs.)

La documentation décrit les tuples comme un mécanisme léger, et c'est la clé de leur bon usage. Utiliser un tuple à la place d'une classe ou d'une structure peut entraîner une répétition fastidieuse des types de ses champs, et parfois de leurs noms. Cela vaut particulièrement pour son usage comme argument de méthode ou comme argument générique dans les collections.

Il vaut mieux recourir avec discernement à des astuces comme l'affectation multiple et l'échange de valeurs.

Les opérations relationnelles autres que l'égalité et l'inégalité ne sont pas prises en charge.

À noter que les tuples ont été introduits dans le langage assez récemment (C# 7), donc si tu veux les utiliser, assure-toi que ta base de code utilise la [version][language-version] 7 ou une version ultérieure du langage.
