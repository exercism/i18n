# À propos

En Rust, les méthodes sont des fonctions définies pour une _struct_ (ou un objet `enum` ou `trait`).
Cela change la façon de les appeler : au lieu d'écrire `frobnicate(foo)`, on appelle une méthode avec `foo.frobnicate()`.

Les méthodes sont similaires aux fonctions : elles sont déclarées avec le mot-clé `fn`, elles ont un nom, et elles peuvent prendre des paramètres et avoir des valeurs de retour.

Contrairement aux fonctions, le premier paramètre d'une méthode est toujours `self` (ou une variante), qui représente l'instance de la _struct_ sur laquelle la méthode est appelée (plus de détails ci-dessous).

Créons un `enum` pour les maisons de Hogwarts et une _struct_ qui décrit l'`age` et la `house` d'un sorcier :

```rust
#[derive(Debug)]
enum House {
    Gryffindor,
    Hufflepuff,
    Ravenclaw,
    Slytherin,
}

struct Wizard {
    age: u32,
    house: House,
}
```

## Définir des méthodes

Pour définir des méthodes pour la _struct_ `Wizard`, on commence un bloc `impl` (abréviation d'_implementation_) pour `Wizard`.

```rust
impl Wizard { }
```

Tout ce qui se trouve dans ce bloc `impl` sera associé au type `Wizard`.
À noter qu'une _struct_ peut avoir plusieurs blocs `impl`.

### Utiliser `self`

Une méthode doit avoir comme premier paramètre un paramètre nommé `self` de type `Self`.
Le type `Self` est un alias du type auquel le bloc `impl` s'applique.
Dans notre exemple, `Self` représente `Wizard`.

Par commodité, Rust permet d'abréger cela en n'écrivant que le nom `self` à la place du premier paramètre.
Les types de `self` courants pour les méthodes sont les suivants :

- `self` : abrège `self: Self`. La signature `self` seule consomme l'instance.
- `&self` : abrège `self: &Self`. Cela emprunte l'instance de façon immuable.
- `&mut self` : abrège `self: &mut Self`. Cela emprunte l'instance de façon mutable.

Dans du code plus avancé, tu verras peut-être aussi des signatures comme `self: Pin<&self>`, `self: Rc<Self>`, etc.
Cela dépasse toutefois le cadre de ce tutoriel.

### Définir une méthode avec `&self`

Si on souhaite implémenter une méthode `info` pour afficher les informations de base du sorcier, on peut définir cette méthode dans un bloc `impl` pour `Wizard` :

```rust
impl Wizard {
    fn info(&self) {
        println!(
            "A wizard of age {} who studies in House {:?} at Hogwarts",
            self.age,
            self.house,
        );
    }
}
```

Remarque que dans la signature de `info`, on emprunte l'instance de façon immuable avec `&self`.
Ainsi, on peut lire les champs `age` et `house` d'une instance de `Wizard` sans les modifier.
Si on avait utilisé un `self` consommant plutôt qu'un emprunt, l'instance serait inaccessible après l'appel de la méthode.

Une fois la méthode `info` implémentée, on peut afficher les informations de base d'un sorcier :

```rust
let harry = Wizard { age: 11, house: House::Gryffindor };
harry.info();
// => A wizard of age 11 who studies in House Gryffindor at Hogwarts
```

### Définir une méthode avec `&mut self`

Si on souhaite implémenter une méthode qui modifie les champs d'une instance de _struct_, on emprunte l'instance de façon mutable avec `&mut self` dans la signature de la méthode.

Imaginons qu'on veuille instaurer une nouvelle règle à Hogwarts pour permettre aux élèves de changer de maison.
On pourrait alors implémenter une méthode `switch_house` comme ceci :

```rust
impl Wizard {
    fn switch_house(&mut self, new_house: House) {
        self.house = new_house;
    }
}
```

On peut maintenant changer de maison pour un sorcier qui étudie à Hogwarts :

```rust
// Note that the variable must be mutable
let mut cedric = Wizard {age: 14, house: House::Hufflepuff};
cedric.info();
// => A wizard of age 14 who studies in House Hufflepuff at Hogwarts
cedric.switch_house(House::Slytherin);
cedric.info()
// => A wizard of age 14 who studies in House Slytherin at Hogwarts
```

## Plusieurs blocs `impl`

En Rust, chaque élément peut avoir plusieurs blocs `impl`.
On peut donc regrouper toutes les méthodes dans un même bloc `impl`, ou avoir plusieurs blocs `impl` pour différents groupes de méthodes.
Les deux approches sont syntaxiquement valides, mais l'organisation typique d'un projet utilise un seul bloc `impl` par ensemble unique de contraintes `where` au niveau du bloc `impl`.

## Fonctions associées

Il est possible de définir, dans un bloc `struct`, des fonctions qui ne contiennent pas de paramètre `self`.
Comme elles n'ont pas de paramètre `self`, ce ne sont pas des méthodes.
Elles restent toutefois associées au type implémenté, et on les appelle en nommant ce type.
C'est pourquoi on les appelle des fonctions associées (ou fonctions associées au type).

Tu as déjà vu certaines fonctions associées, comme `String::from()` :

```rust
let some_string = String::from("This is an associated function but not a method");
```

Les constructeurs sont souvent implémentés sous forme de fonctions associées.
Créons une fonction `new` associée au type `Wizard` :

```rust
impl Wizard {
    fn new(age: u32, house: House) -> Self {
        Self {
            age,
            house,
        }
    }
}
```

Remarque qu'on peut utiliser `Self` à la place de `Wizard` pour indiquer le type qui sera renvoyé par la fonction.
Utiliser l'alias de type `Self` de cette façon n'est pas obligatoire, mais cela peut simplifier l'implémentation pour des types aux noms compliqués ou verbeux.
On peut maintenant exécuter ceci :

```rust
let myrtle = Wizard::new(14, House::Ravenclaw);

myrtle.info();
// => A wizard of age 14 who studies in House Ravenclaw at Hogwarts
```
