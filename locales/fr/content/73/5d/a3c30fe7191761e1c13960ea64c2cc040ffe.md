# À propos

[Lua](https://lua.org) est un langage de script simple mais puissant, efficace, léger et intégrable. Il est conçu, implémenté et maintenu à la [PUC-RIO](https://www.puc-rio.br/) au Brésil depuis 1993 par l'équipe de Roberto Ierusalimschy, Waldemar Celes et Luiz Henrique de Figueiredo.

## Commentaires

Les commentaires sur une seule ligne en Lua commencent par `--` et les commentaires multilignes commencent par `--[[` et se terminent par `]]`.
```lua
-- This is a single line comment.

--[[This is
a multiline
comment
]]
```

## Variables

Il existe trois types de variables en Lua : les variables globales, les variables locales et les champs de table. Pour simplifier, seules les variables locales sont expliquées ici. Par défaut, toutes les variables sont globales, on doit donc déclarer les variables locales comme telles avec le mot-clé `local`.
```lua
local x
```

On peut affecter une valeur à une variable à l'aide de l'opérateur `=`.
```lua
local x = 1
```

La portée d'une variable `local` est limitée au bloc où elle est déclarée. Un bloc peut être le corps d'une structure de contrôle, le corps d'une fonction, ou encore un fichier ou une _string_ où la variable est déclarée.
```lua
local x = 1

if x == 1 then
  local x = 2
  print(x) -- prints 2
end

print(x) -- prints 1
```

## Fonctions

Une fonction est déclarée avec le mot-clé `function` et, comme les variables, est globale par défaut. Une définition de fonction comporte un nom, une liste de paramètres et un corps. La fonction se termine lorsque le mot-clé `return` est atteint et renvoie toutes les valeurs listées après lui. Sans `return` spécifié, la fonction renverra `nil`.

```lua
-- Defining a local function which returns "Hello " followed by 
-- the name which was given as parameter
local function say_hello(name)
  return 'Hello ' .. name
end
```

## Tables

Les tables sont le seul mécanisme de structuration de données en Lua et sont très puissantes. Elles servent à représenter des tableaux, des ensembles, des objets, des modules et bien d'autres choses. Essentiellement, une table en Lua est un tableau associatif.
```lua
-- create a table and assign its reference to tbl
local tbl = {}

-- new entry with key 'x' and value 1
tbl['x'] = 1

-- printing the value
print(tbl['x'])  --> 1

-- uninitialized table fields evaluate to nil
print(tbl['y'])  --> nil

-- there is also syntactic sugar - the following is the same as above
tbl.y = 1
print(tbl.y)    --> 1
```

Ce n'est qu'un petit aperçu nécessaire pour la section suivante. On reviendra plus en détail sur ce sujet plus tard.

## Modules

Un module est un ensemble de code stocké dans un fichier source `.lua`. Tout ce que le module exporte est stocké dans une table, et cette table est renvoyée à la fin du fichier. La table joue donc essentiellement le rôle d'une sorte d'espace de noms.
```lua
-- say-hello.lua

-- defining the table 'say' which is exported at the end
local say = {}

-- defining the function 'hello' as a table field
-- this is syntax sugar for: say.hello = function() print('Hello!') end
function say.hello()
  print('Hello!')
end

-- returning (exporting) the table 'say'
return say
```

Ce module peut ensuite être chargé dans un autre fichier via la fonction `require`, qui renvoie la table.
```lua
-- lets_say_hello.lua
local say = require('say-hello')
say.hello() -- prints "Hello!"
```

Quand on voit `say.hello`, on pense à « la fonction `hello` du module `say` ». Mais si l'on sait que notre `say-hello.lua` renvoie une table et que l'on revient à la section sur les tables, on remarque qu'en Lua cette expression signifie « indexer la table `say` en utilisant la _string_ `hello` comme clé ».

Bien qu'il soit de bonne pratique qu'un module renvoie une table, il est tout à fait possible de renvoyer n'importe quel autre type, comme une fonction.

```lua
--- say-bye.lua
local function bye()
  print('Bye!')
end

return bye
```
