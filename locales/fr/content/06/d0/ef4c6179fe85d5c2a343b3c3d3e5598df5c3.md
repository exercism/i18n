# Tests
Pour résoudre les exercices Exercism, tu peux te rendre sur le site et utiliser l'éditeur en ligne, qui te permet de modifier et de tester ta solution.

Tu peux aussi télécharger les exercices sur ton ordinateur, où tu utiliseras ton propre éditeur et une panoplie d'outils pour créer, tester, puis soumettre ta solution.

Cela implique d'utiliser l'Exercism CLI, c'est-à-dire l'interface en ligne de commande, une application qui s'exécute dans un terminal ou une fenêtre de ligne de commande. Les instructions d'installation se trouvent ici : [Documentation de l'Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally).

## Approche des tests
Exercism suppose une certaine expérience du développement piloté par les tests. Chaque exercice se compose d'un _`stub file`_, d'un _`test file`_ qui contient une série de tests déjà écrits, et d'un _`test script`_ qui sert à exécuter les tests.

Pour résoudre un exercice, il faut faire évoluer progressivement le _`stub file`_ jusqu'à ce qu'il contienne le code qui, au bout du compte, passera tous les tests.

Concrètement, cela signifie que tu vas modifier activement le _`stub file`_ comme le _`test file`_. À noter que l'on modifie le _`test file`_ non pas pour changer le code des tests, mais pour mettre en commentaire les tests qui échouent.

Au départ, tous les tests sauf un sont mis en commentaire. Puis, à mesure que le _`stub file`_ se rapproche d'une solution fonctionnelle, on décommente de plus en plus de tests jusqu'à ce qu'ils passent tous.

## L'infrastructure de test
Pas besoin d'installer le moindre logiciel supplémentaire : les composants du framework de test sont inclus dans le téléchargement de l'exercice.

Le framework de test se compose de trois fichiers Rexx qui, au moment du test, sont combinés à la solution de l'exercice pour former l'unité de code de test. C'est ensuite le _`test script`_ qui exécute cette unité et affiche les résultats des tests dans le terminal.

Merci de ne pas modifier ni supprimer le _`test script`_, ni aucun autre fichier du framework de test. Si des _gremlins_ s'en mêlent, il te suffit de retélécharger l'exercice via l'Exercism CLI, en prenant soin de sauvegarder ton code de solution.

## Exécuter les tests
Voici comment se déroule la résolution d'un exercice :

1. Ouvre un terminal
2. Télécharge l'exercice choisi
3. Place-toi dans le dossier de l'exercice
4. Charge le stub file et le test file dans ton éditeur
5. Puis, de façon itérative,

    1. Exécute le script de test
    2. Écris du code dans ton stub file (qui devient peu à peu un fichier de solution) et mets en commentaire ou décommente des tests dans ton test file

6. Une fois que tous les tests passent, soumets la solution à Exercism
7. Ferme le terminal
8. Célèbre ta réussite

Un exemple concret dans un terminal Linux avec l'exercice `acronym` (on suppose que l'espace de travail Exercism est `/home/exercism`).

Télécharger l'exercice :

`exercism download --track=rexx --exercise=acronym`

Se placer dans le dossier de l'exercice :

`cd /home/exercism/rexx/acronym`

Depuis une autre fenêtre, par exemple une interface graphique, charge `acronym.rexx` et `acronym-check.rexx`, respectivement le fichier stub et le fichier de test, dans ton éditeur.

Exécute le script de test : `./test-acronym`

et tous les tests devraient échouer :

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Mets en commentaire tous les tests sauf le premier dans le fichier `acronym-check.rexx`, puis relance le script de test ; tu devrais obtenir la sortie suivante :

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

Retravaille `acronym.rexx` jusqu'à ce qu'il contienne du code fonctionnel : la sortie du script de test finira par être la suivante :

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

Décommente ensuite les autres tests, relance le script de test, et tu finiras par obtenir :

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Tu peux maintenant soumettre ta solution :

`exercism submit acronym.rexx`

et gagner un point de réputation de plus. Ferme le terminal quand tu as terminé.

Pour un utilisateur de macOS, la procédure est assez similaire, puisque c'est un système d'exploitation dérivé d'UNIX.

Pour les utilisateurs de Windows, la procédure est globalement similaire, avec quelques différences mineures :

- La fenêtre _Command Prompt_ est le terminal
- Les barres obliques inverses remplacent les barres obliques dans les chemins, donc le dossier de travail pourrait être :

  `cd C:\Users\MyName\exercism\rexx\acronym`

- L'exécution du script de test se fait via :

  `test-acronym`  ou  `test-acronym.bat`

La sortie des tests sera identique.
