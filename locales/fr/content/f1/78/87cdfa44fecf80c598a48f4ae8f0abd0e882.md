# Les bases d’Unison

## Termes et fonctions

Les termes et les fonctions sont les unités de base pour écrire un programme Unison.

Un « terme » est ce qu’on appelle une valeur statique. Il est défini avec `name = expression`, éventuellement précédé d’une signature de type de la forme `name : MyType`. Unison prend en charge l’inférence de type, on peut donc voir la signature de type omise pour des définitions simples.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Les fonctions Unison ressemblent à `myFunctionName argument1 argument2 = myImplementation` ; elles commencent par le nom de la fonction suivi d’arguments séparés par des espaces.

```
getMax a b = Nat.max a b
```

Les fonctions peuvent éventuellement inclure une signature de type. Le dernier type à droite est toujours le type de retour final de la fonction, et chaque argument est séparé par la flèche de fonction `->`.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Pour appeler une fonction, utilise son nom suivi de ses arguments séparés uniquement par des espaces.

```
maximum = getMax 1 10
```

Lors de l’appel d’une fonction, Unison essaie de traiter ce qui vient immédiatement à droite comme son argument, ce qui ne crée pas toujours l’ordre d’évaluation de fonction souhaité.

Supposons qu’on veuille obtenir la valeur `1` à partir de l’expression suivante

```
shouldBe1 = getMax 1 10 - 10
```

Tel qu’écrit, `shouldBe1` s’évalue à `0` car l’ordre d’application implicite des fonctions est `getMax 1 10`, ce qui donne `10`, puis `10 - 10`, ce qui donne `0`.

Tu peux utiliser des parenthèses pour regrouper l’expression dans l’ordre d’opérations souhaité.

```
shouldBe1 = getMax 1 (10 - 10)
```

## Fonctions multilignes

Les fonctions multilignes d’Unison utilisent l’indentation ou des blocs `let` pour spécifier les limites du code, c’est-à-dire la « portée lexicale ».

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Tout ce qui est au même niveau d’indentation partage la même portée, c’est pourquoi on peut référencer la variable `newBeginning` dans la dernière ligne.

## Espaces de noms et instructions `use`

Les espaces de noms permettent de regrouper et d’organiser les fonctions Unison. On peut les voir comme analogues à des « répertoires ». Ils fournissent une structure et un regroupement logique.

Tu peux importer les fonctions d’un espace de noms dans la portée avec une instruction `use`.

Supposons que tu écrives une fonction qui utilise des valeurs `List` d’Unison. Tu sais que tu auras besoin de fonctions comme `List.map` et `List.flatMap`, où `List` est l’espace de noms et `map` et `flatMap` sont des fonctions. Pour éviter de te répéter, tu peux choisir d’importer tout ce qui vient de l’espace de noms `List` dans la portée lexicale de ta fonction, comme ceci :

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

La ligne `use List` lève l’ambiguïté sur les références à `map` et `flatMap`. Tu peux en savoir plus sur [les instructions `use` ici][use-statements].

## La bibliothèque standard d’Unison

La bibliothèque standard d’Unison s’appelle `base`. Si tu as suivi le guide de démarrage rapide et que tu as une base de code créée localement, la bibliothèque standard a dû être téléchargée automatiquement. Tu peux parcourir la documentation de la bibliothèque standard en ligne sur [Unison Share][unison-share-base].

## Commentaires et littéraux de documentation

Les commentaires en Unison sont une fonctionnalité assez inhabituelle. Quand tu écris du code Unison, tu peux créer du texte dans ton fichier avec l’extension `.u` qui n’est pas interprété avec la syntaxe suivante :

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Cependant_, comme le code Unison est enregistré sous forme de hash de son arbre syntaxique abstrait, et non sous forme de fichiers texte sur le système de fichiers, les commentaires qui sont des « décorations » textuelles d’une fonction ou d’un terme Unison donné dans le fichier ne peuvent pas vraiment être sauvegardés et réaffichés pour le partage. Si tu souhaites ajouter une information à ton terme Unison d’une manière qui sera stockée pour que d’autres puissent la lire et la comprendre, tu peux utiliser un littéral de documentation.

La documentation est une valeur de première classe dans le langage de programmation Unison. Cela signifie qu’un élément `Doc` peut être affecté à une valeur, passé comme valeur à une fonction, ou renvoyé comme valeur d’une fonction. Les éléments de littéral de documentation sont ouverts et fermés par des doubles accolades. Voici comment on pourrait utiliser l’élément `Doc` comme commentaire.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
