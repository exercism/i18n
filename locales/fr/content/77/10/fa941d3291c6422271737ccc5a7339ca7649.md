# Instructions supplémentaires

## Processus d'entrées-sorties

Contrairement aux autres exercices, `grep` doit interagir avec le « monde extérieur » : lire des fichiers, gérer des erreurs système et écrire sur `stdout`.

En Lean, l'interaction avec le système se fait généralement dans la monade [IO][io], ce qui permet aux effets de bord de se produire dans un environnement confiné sans affecter l'état pur de la plupart des autres fonctions.

## Lecture des arguments

Lean permet d'appeler un fichier comme un script, soit directement comme script autonome avec `lean --run`, soit avec `lake`.

Un projet Lean a un seul point d'entrée, une fonction appelée `main`, qui prend une `List String` contenant tous les arguments qui lui sont passés.
Pour simuler l'exécution de `Grep.lean` comme un exécutable, les arguments sont passés de la même façon dans cet exercice.

## Lecture des fichiers

Lean offre des [fonctions][files] pour manipuler des fichiers dans la monade `IO.FS`.
Par exemple, `IO.FS.readFile` permet de lire le contenu d'un fichier à un chemin donné, sous la forme d'une `String`.

## Écriture de la sortie

Plutôt que de renvoyer une valeur, cet exercice exige que les résultats soient écrits sur la sortie standard ou sur l'erreur standard.
Lean fournit des [fonctions][console] pour cela.

## Gestion des erreurs système

Contrairement aux erreurs dans `Except`, les exceptions `IO` sont de véritables exceptions à l'exécution.
Tu peux utiliser `try`/`catch` pour les gérer :

```
try
    /- 
        code that may possibly raise an exception 
    -/
catch msg =>
    /-
        code that is executed only if an exception was thrown
    -/
```
