Les blocs de code sont utilisés à profusion en Raku.
Ils sont fondamentaux pour les fonctions, mais on les retrouve aussi dans des outils comme `grep` et `map`, comme blocs d'instructions `if`, `for`, `while` et `given`, et même comme indices de tableaux.

## Routines

Les [`Subs`][type/Sub] et les [`Methods`][type/Method] sont des types de [`Routines`][type/Routine] en Raku.

Une routine peut être quittée à tout moment avec une valeur de retour grâce au mot-clé [`return`][control-return], un outil utile pour créer des fonctions.
Si aucun `return` n'est précisé, la dernière instruction de la routine sera sa valeur de retour implicite.

Une routine peut avoir une [`Signature`][language/signatures] entre parenthèses avant le bloc de code.

Une [`Routine`][type/Routine] est une sous-classe de [`Block`][type/Block].

```raku
sub add ($x, $y --> Int) { return $x + $y }
say add(1, 2); # 3
```

Les méthodes seront abordées dans un autre concept consacré aux classes et aux objets.

## Blocs

Un [`Block`][type/Block] est un objet de code réutilisable, généralement utilisé pour créer des lambdas.

La dernière instruction d'un bloc est sa valeur de retour implicite.

Un bloc peut avoir une [`Signature`][language/signatures] précédée de `->` avant le bloc de code.

Un [`Block`][type/Block] est une sous-classe de [`Code`][type/Code], qui est la classe de base ultime de tous les objets de code en Raku.

```raku
my $add = -> $x, $y { $x + $y };
say $add(1, 2); # 3
```

## Signatures

Une [`Signature`][language/signatures] est composée de zéro ou plusieurs [`Parameters`][type/Parameter], séparés par des virgules.

À la fin d'une signature, on peut préciser un type de retour à l'aide d'une [flèche de type de retour][signatures-return-type-arrow] `-->`.

Une signature permet de préciser les arguments qu'un `Block` acceptera.

Dans ce concept, on gardera les signatures simples, en n'utilisant que des paramètres positionnels avec des variables à sigil scalaire, et un type de retour.
Ces notions seront développées dans d'autres concepts.

## Multi-dispatch

Raku permet d'écrire plusieurs routines portant le même nom mais ayant des signatures différentes grâce au mot-clé `multi`.
Cette fonctionnalité est appelée [multi-dispatch][multi-dispatch].
Quand on appelle la routine par son nom, l'environnement d'exécution détermine le bon candidat et l'invoque.

Ce point sera traité plus en détail dans un concept sur les types.

```raku
multi foo () { say 'No arguments given'}

multi foo ($bar) { say "One argument given: $bar" }
```

## WhateverCode

Quand on utilise l'étoile `*` de [`Whatever`][type/Whatever] en combinaison avec la plupart des opérateurs, un objet [`WhateverCode`][type/WhateverCode] est créé.
Cela permet de créer des blocs avec une syntaxe plus simple.

```raku
# These will all give code blocks that increment a single argument by 1:
-> $x { $x  + 1 }; # Explicit signature
      { $^x + 1 }; # Signature via placeholder variable
      { $_  + 1 }; # Topic variable
          * + 1;   # WhateverCode
```
