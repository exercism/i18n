# Classes immuables

Un `SCOREBOARD` est une chose qui change. Deux noms pour un même tableau des
scores voient le même score, parce qu'il n'y a qu'un seul tableau et que les
deux noms désignent ce même tableau.

Un cap n'est pas comme ça. `350 degrees` ne devient pas autre chose : il *est*,
tout simplement. Les nombres se comportent ainsi, et les _strings_ aussi, et des
classes que tu écris toi-même peuvent faire de même.

## immutable

```sather
immutable class BEARING is

   readonly attr degrees : INT;

end; -- class BEARING
```

Deux mots changent tout. Un objet d'une classe immuable est une **valeur**, et
non une chose vers laquelle on pointe :

- il est copié quand on l'affecte ou qu'on le passe, donc personne d'autre ne
  peut modifier le tien ;
- il ne peut jamais être void ;
- et on ne peut pas affecter ses attributs.

## Modifie un objet en en créant un autre

Comme `degrees := 90` n'est pas autorisé, `attr` offre autre chose : une routine
qui prend la nouvelle valeur et renvoie **un nouvel objet** où elle a été
modifiée.

```sather
   b ::= b.degrees(90);      -- not b.degrees := 90
```

L'original reste intact. C'est tout l'idiome, et c'est ainsi qu'est écrit
`create` :

```sather
   create(d : INT) : SAME is
      b : SAME;                     -- starts with everything at nought
      return b.degrees(d);
   end;
```

Il n'y a pas de `new` ici. Un objet immuable existe toujours, donc `b : SAME`
en est déjà un, avec chaque attribut à sa valeur vide.

Une routine qui « change » un cap renvoie donc un nouveau cap :

```sather
   turned(by : INT) : SAME is
      return #BEARING(degrees + by);
   end;
```

## Compare

Les valeurs se comparent d'après ce qu'elles contiennent, et non d'après leur
identité d'objet, mais il faut dire comment. Écris `is_eq`, et `=` l'utilisera :

```sather
   is_eq(other : SAME) : BOOL is
      return degrees = other.degrees;
   end;
```

Sans lui, `=` sur deux caps ne compilera pas.

## Que choisir

Utilise une classe immuable quand la chose n'a pas d'identité et que rien en
elle ne peut raisonnablement changer : un cap, un point, une date, une longueur.
Utilise une classe ordinaire quand la chose est un objet particulier auquel il
arrive des choses : un tableau des scores, un harnais, un fichier.

Le critère, c'est de savoir si « le même » signifie « égal » ou bien
« exactement le même objet ».
