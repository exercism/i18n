# Tests

Les exercices Odin de ton répertoire de projet exercism s'exécutent en te plaçant dans le répertoire de l'exercice et en lançant `odin test .`.

```sh
cd "$(exercism workspace)"/odin/leap
odin test .
```

## Activer les vérifications du langage

Pendant que tu testes, Odin peut _vet_ ton code : il peut repérer des choses comme des imports et des variables inutilisés.

Lance tes tests avec

```sh
odin test . -vet
```

Pour encore plus de vérifications, ajoute l'option `-strict-style`.

## Le développement piloté par les tests (TDD)

`odin test` exécute chaque procédure qui possède l'attribut `@(test)`.

Dans la suite de tests, tu remarqueras que chaque procédure de test possède cet attribut. Cela signifie que lorsque tu lances les tests, chaque procédure de test va s'exécuter.

Exercism encourage généralement le [développement piloté par les tests][tdd], où :

- au départ, tous les tests sauf le premier sont configurés pour être ignorés ;
- tu écris juste assez de code pour faire passer le premier test ;
- puis tu actives le test suivant et tu écris juste assez de code pour le faire passer ;
- tu répètes jusqu'à ce que ton code passe tous les tests.

Nous (les mainteneurs) n'avons pas trouvé de façon élégante et programmatique d'exécuter un sous-ensemble des tests. Le fichier de test devenait tout simplement trop lourd à gérer. Pour développer en TDD, tu peux modifier le fichier de test pour mettre en commentaire les tests que tu n'es pas encore prêt à exécuter, puis les décommenter un par un au fur et à mesure que tu écris ta solution.
