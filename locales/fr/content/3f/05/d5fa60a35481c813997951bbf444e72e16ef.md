# Introduction

Comme beaucoup d'autres langages, Go dispose de pointeurs.
Si tu débutes avec les pointeurs, ils peuvent sembler un peu mystérieux, mais une fois que tu t'y es habitué, ils sont assez simples.
Ils sont une partie cruciale de Go, alors prends le temps de bien les comprendre.

Avant d'entrer dans les détails, il vaut la peine de comprendre l'utilité des pointeurs.
Les pointeurs sont un moyen de partager de la mémoire avec d'autres parties de notre programme, ce qui est utile pour deux raisons principales :

1. Quand on manipule de grandes quantités de données, en faire des copies pour les passer d'une fonction à l'autre est très inefficace.
   En passant plutôt l'emplacement mémoire où sont stockées les données, on peut réduire considérablement l'empreinte en ressources de nos programmes.
2. En passant des pointeurs entre les fonctions, on peut accéder à l'unique copie des données et la modifier directement, ce qui signifie que les modifications apportées par une fonction sont immédiatement visibles pour les autres parties du programme lorsque la fonction se termine.

## Variables et mémoire

Prenons une variable entière ordinaire `a` :

```go
var a int
```

Quand on déclare une variable, Go doit trouver un endroit en mémoire pour stocker sa valeur.
Tout cela est largement abstrait pour nous : quand on a besoin de récupérer la valeur stockée dans cette portion de mémoire, il suffit de s'y référer par le nom de la variable.

Par exemple, quand on écrit `a + 2`, on récupère en fait la valeur stockée dans la mémoire associée à la variable `a`, et on y ajoute 2.

De même, quand on veut modifier la valeur de l'emplacement mémoire de `a`, on peut utiliser le nom de la variable pour faire une affectation :

```go
a = 3
```

L'emplacement mémoire associé à `a` stocke maintenant la valeur `3`.

## Pointeurs

Alors que les variables nous permettent de désigner des valeurs en mémoire, il est parfois utile de connaître l'**adresse mémoire** vers laquelle pointe la variable.
Les **pointeurs** contiennent les adresses mémoire de ces valeurs.
On déclare une variable de type pointeur en faisant précéder le type sous-jacent d'un astérisque :

```go
var p *int // 'p' contains the memory address of an integer
```

Ici, on déclare une variable `p` de type « pointeur vers un entier » (`*int`).
Cela signifie que `p` contiendra l'adresse mémoire d'un entier.
La valeur zéro des pointeurs est `nil`, car un pointeur `nil` ne contient aucune adresse mémoire.

### Obtiens un pointeur vers une variable

Pour trouver l'adresse mémoire de la valeur d'une variable, on peut utiliser l'opérateur `&`.
Par exemple, si on veut trouver l'adresse mémoire de la variable `a` et la stocker dans le pointeur `p`, on peut faire ceci :

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Accède à la valeur via un pointeur (déréférencement)

Quand on a un pointeur, on peut vouloir connaître la valeur stockée à l'adresse mémoire qu'il représente.
On peut le faire avec l'opérateur `*` :

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

L'opération `*p` récupère la valeur stockée à l'adresse mémoire contenue dans `p`.
Cette opération est souvent appelée « déréférencement ».

On peut aussi utiliser l'opérateur de déréférencement pour affecter une nouvelle valeur à l'adresse mémoire référencée par le pointeur :

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

Affecter à `*pa` change la valeur stockée à l'adresse mémoire que contient `pa`.
Comme `pa` contient l'adresse mémoire de `a`, en affectant à `*pa`, on modifie en fait la valeur de `a` !

Attention toutefois : vérifie toujours qu'un pointeur n'est pas `nil` avant de le déréférencer.
Déréférencer un pointeur `nil` fait planter le programme à l'exécution !

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Pointeurs vers des structures

Jusqu'ici, on n'a vu que des pointeurs vers des valeurs primitives.
On peut aussi créer des pointeurs vers des structures :

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

On aurait aussi pu créer une nouvelle `Person` et y stocker immédiatement un pointeur :

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Quand on a un pointeur vers une structure, on n'a pas besoin de déréférencer le pointeur avant d'accéder à l'un des champs :

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## Les _slices_ et les _maps_ sont déjà des pointeurs

Les _slices_ et les _maps_ sont des types particuliers, car leur implémentation contient déjà des pointeurs.
Cela signifie que, la plupart du temps, on n'a pas besoin de créer des pointeurs pour ces types afin de partager l'adresse mémoire de leurs valeurs.
Imaginons une fonction qui incrémente la valeur d'une clé dans une _map_ :

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Si on crée une _map_ et qu'on appelle cette fonction, les modifications apportées par la fonction à la _map_ persistent après la fin de la fonction.
C'est un comportement semblable à celui qu'on obtiendrait avec un pointeur, mais remarque que dans cet exemple, on n'utilise aucune référence, aucun déréférencement, ni aucune syntaxe propre aux pointeurs :

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

Il en va de même quand on modifie un élément existant dans un _slice_.

Cependant, les actions qui renvoient un nouveau _slice_, comme `append`, sont un cas particulier et **peuvent ne pas** modifier le _slice_ en dehors de la fonction.
Cela vient de la façon dont les _slices_ fonctionnent en interne, mais on n'entrera pas dans les détails, car c'est un sujet plus avancé.
Si tu es vraiment curieux, tu peux en lire plus à ce sujet dans [Go Blog: Mechanics of 'append'][mechanics-of-append]
