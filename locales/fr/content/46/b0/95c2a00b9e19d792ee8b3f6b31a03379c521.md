# Instructions supplémentaires

## Notes supplémentaires pour l'implémentation en C++

Il y a plusieurs façons de mettre en œuvre du parallélisme en C++.
L'exécuteur en ligne d'Exercism prend en charge C++17, on peut donc utiliser les politiques d'exécution de la [bibliothèque d'algorithmes][algorithm].
Une autre option consiste à gérer les _threads_ manuellement.
Note cependant que créer un _thread_ coûte assez cher (utiliser un [pool de threads][pool] aiderait).

En local, tu peux bien sûr utiliser ce que tu veux.
Cependant, une solution qui utilise des bibliothèques non standard ne fonctionnera très probablement pas avec l'exécuteur en ligne d'Exercism.

### Benchmark

En local, tu peux éventuellement lancer un _benchmark_ pour te donner une idée de l'accélération qu'apportent les différentes implémentations.
Activer l'option CMake `EXERCISM_INCLUDE_BENCHMARK` active le _benchmark_ :
```
cmake -DEXERCISM_RUN_ALL_TESTS=1 -DEXERCISM_INCLUDE_BENCHMARK=1 .
```

### Prise en charge des algorithmes parallèles par les compilateurs

L'implémentation de la bibliothèque standard C++ par GCC (`libstdc++`) s'appuie sur [TBB][tbb].
Si TBB n'est pas disponible, une version séquentielle est utilisée en repli, même quand l'exécution parallèle est demandée.

Sous Ubuntu, tu dois installer le paquet `libtbb-dev` :
```
apt-get install libtbb-dev
```

Sous macOS, tu peux utiliser [Homebrew][homebrew] pour installer TBB :
```
brew install tbb
```

À partir de la version 17, la `libc++` de Clang prend en charge les algorithmes parallèles de manière expérimentale et partielle.
Pour l'activer, il faut passer l'option de compilation `-fexperimental-library`.

Apple Clang 15 et les versions antérieures _ne prennent pas_ en charge les algorithmes parallèles.

Sous Linux et macOS, on te recommande d'utiliser GCC (avec la `libstdc++` par défaut) pour cet exercice.

Le MSVC de Microsoft prend en charge les algorithmes parallèles depuis au moins VS 2017 15.7, sans qu'il soit nécessaire d'installer une bibliothèque supplémentaire.
