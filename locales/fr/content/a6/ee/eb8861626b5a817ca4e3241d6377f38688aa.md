# À propos

Ruby est un langage dynamique et fortement typé.
Dans les langages dynamiques, le type d'une variable ou d'un objet est résolu à l'exécution, ce qui signifie que sa valeur ou son type peut encore changer jusqu'au dernier moment (au moment où l'interprète l'analyse).
Et que veut-on dire par fortement typé ?
Une fois que l'on connaît le type d'une variable ou d'un objet, Ruby se montre strict sur ce que l'on peut en faire, par exemple :

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**Mais**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

Pour rappel, en Ruby tout est un objet.
Même les classes sont des instances de la classe `Class`.

Par exemple :

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

Cela signifie que l'on peut aussi définir des classes comme ceci :

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

Enfin, garde en tête que l'objet `Integer` contient des valeurs qui peuvent s'écrire sous la forme d'un ou plusieurs chiffres consécutifs, et que ses méthodes prennent en charge un grand nombre des [opérateurs mathématiques][integers-docs].

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
Dans la documentation, on trouve souvent les méthodes d'instance référencées avec une syntaxe comme `Class#method_name`, tandis que les méthodes de classe ou de module sont référencées par `Class::method_name`.
Le `::` s'appelle l'_opérateur de résolution de portée_ (Scope Resolution Operator), c'est-à-dire la constante ou la méthode au niveau de la classe ou du module qui est référencée.
Tu rencontreras cette notation dans la documentation Ruby, dans les listes de diffusion et dans les autres espaces d'entraide.
Tu verras qu'ici, nous référençons les méthodes de classe et de module sous la forme `ClassName.method_name` ou `ModuleName.method_name`.
~~~~
