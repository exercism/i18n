# Introduction

Les exceptions en Ruby, comme dans beaucoup de langages, permettent de gérer des événements inattendus. Bien gérer les exceptions est important pour éviter que ton programme ne plante.

Lorsqu'une exception est levée, que ce soit explicitement ou par l'interpréteur Ruby, le programme interrompt son fonctionnement normal et finit par s'arrêter avec un message d'erreur :

```ruby
raise ArgumentError.new("Something went wrong!")
=> Traceback (most recent call last):
.
.
ArgumentError (Something went wrong!)
```

```ruby
1/0
=> Traceback (most recent call last):
.
.
ZeroDivisionError (divided by 0)
```

Si on veut empêcher ce processus d'arrêt, il faut réagir à l'exception. C'est ce qu'on appelle «\u00A0intercepter\u00A0» une exception :

```ruby
begin
  # ...any code that raises an exception
rescue
  puts 'Got an exception'
end
```

Ce programme ne plantera pas et affichera «\u00A0Got an exception\u00A0». Au lieu de s'arrêter, Ruby exécute le code du bloc `rescue`, qui affiche un message.

Comme tout en Ruby, les exceptions sont aussi des objets et contiennent généralement des données sur l'exception. Voici comment on peut récupérer l'objet exception :

```ruby
begin
  # ...any code that raises an exception
rescue => e
  puts "Exception class: #{ e.class.name }"
  puts "Exception Message:#{e.message}"
end
```

Il est aussi possible de lever tes propres exceptions en Ruby. Par exemple :

```ruby
begin
  raise ArgumentError.new("Invalid argument")
rescue ArgumentError => e
  puts e.message
end
```

L'exception précédente est l'une des exceptions intégrées de Ruby, mais il est aussi possible de définir des exceptions personnalisées et de les lever :

```ruby
class CustomError < StandardError
end

raise CustomError.new("Something went wrong")
```
