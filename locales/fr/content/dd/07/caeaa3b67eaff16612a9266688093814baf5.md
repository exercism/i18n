# À propos

## Introduction

La généricité est une fonctionnalité du langage qui permet de réutiliser du code.
Par exemple, le type des éléments contenus dans un tableau ne devrait pas avoir d'importance pour en calculer la longueur.
C'est pourquoi la fonction `length` utilise un paramètre de type générique `a` dans sa signature de type.

```elm
length : List a -> Int
```

## Les paramètres dans les types

Quand un type est générique par rapport à un autre type, on utilise un nom en minuscules pour cet autre type, et on l'appelle un paramètre de type.
On en trouve des exemples courants avec les types personnalisés `List`, `Maybe` et `Result`.

```elm
-- Maybe is generic over the type a
type Maybe a
    = Nothing
    | Just a

someString : Maybe String
someString = Just "hello"

someInt : Maybe Int
someInt = Just 42
```

Une remarque importante à propos des noms des paramètres de type : ils peuvent comporter plusieurs caractères.
La seule contrainte est qu'il s'agit de noms en minuscules.
C'est pourquoi, quand c'est utile, on a tendance à leur donner des noms descriptifs.

Un type peut être générique par rapport à plusieurs autres types, et donc avoir plusieurs paramètres de type.
Dans ce cas, chaque type indépendant reçoit un nom en minuscules différent.
Le fait d'être indépendants ne les empêche pas de devenir le même type, cela leur permet simplement d'être différents.

```elm
-- Result is generic over the types error and value
type Result error value
    = Ok value
    | Err error
```

Les alias de type d'enregistrement peuvent aussi avoir des paramètres de type, même si c'est moins courant.

```elm
-- Event is generic over the type a
type alias Event a =
    { at : Time
    , data : a 
    }
```

> C'est pour cette raison que le paquet `Html` définit le type `Html msg`, avec un paramètre de type nommé `msg`.
> L'architecture Elm te guide vers la création d'un type personnalisé `Msg` décrivant tous les messages que ta page web peut déclencher.
> Par conséquent, ton code construira des vues de type `Html Msg`, où `Msg` est le type concret que tu as défini.
> Les débutants confondent parfois les erreurs qui mentionnent `Html msg` (en minuscules) et les erreurs avec `Html Msg`.
> Maintenant, tu sais !
> La différence est que la première est générique par rapport à n'importe quel type `msg`, tandis que la seconde est spécifique à ton type `Msg`.

## Les paramètres de type dans les fonctions

Puisque les types peuvent être génériques, les fonctions peuvent l'être aussi.
On peut écrire des fonctions qui manipulent des types génériques, comme `Maybe.withDefault`.

```elm
withDefault : a -> Maybe a -> a
withDefault default maybe =
    case maybe of
      Just value -> value
      Nothing -> default
```

Les fonctions qui prennent d'autres fonctions en paramètres sont appelées fonctions d'ordre supérieur, et celles-ci peuvent aussi être génériques.

```elm
map : (a -> b) -> Maybe a -> Maybe b
map function maybe =
  case maybe of
    Just value ->
      Just (function value)

    Nothing ->
      Nothing
```

Les paramètres de type peuvent apparaître à la fois dans les entrées et dans la sortie d'une fonction, et la généricité qu'ils permettent est généralement appelée **polymorphisme paramétrique**.
C'est à opposer au polymorphisme ad hoc, aussi appelé surcharge de fonctions, où le même nom de fonction peut être utilisé dans plusieurs implémentations dont les types diffèrent.
Cela contraste aussi avec le polymorphisme de sous-typage, où les types peuvent être définis dans une hiérarchie, et où les fonctions définies sur un type peuvent aussi être appelées avec des arguments de ses sous-types.
En Elm, le seul mécanisme de généricité disponible est le polymorphisme paramétrique.
