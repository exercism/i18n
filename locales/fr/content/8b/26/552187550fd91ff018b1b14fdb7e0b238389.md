# Instructions

Après un récent audit de sécurité, on t'a demandé de nettoyer les fichiers de log archivés de l'organisation.

## 1. Identifie les lignes de log corrompues

Tu as besoin de te faire une idée du nombre de lignes de log de ton archive qui ne respectent pas les normes actuelles.
Tu penses qu'un test simple suffit à déterminer si une ligne de log est valide.
Pour être considérée comme valide, une ligne doit commencer par l'une des _strings_ suivantes :

- `[DEBUG]`
- `[INFO]`
- `[WARNING]`
- `[ERROR]`

Implémente la fonction `is_valid_line` pour qu'elle renvoie `True` si la ligne de log est valide.

```gleam
log_parser.valid_line("[ERROR] Network Failure")
// -> True

log_parser.valid_line("Network Failure")
// -> False
```

## 2. Découpe la ligne de log

Peu après le début du projet d'analyse de logs, tu te rends compte que les logs d'une application ne sont pas découpés en lignes comme les autres.
Dans ce projet, ce qui aurait dû se trouver sur des lignes séparées est au contraire sur une seule ligne, relié par des flèches fantaisistes telles que `<--->` ou `<*~*~>`.

En fait, n'importe quelle _string_ dont le premier caractère est `<`, le dernier caractère `>`, et qui contient entre les deux zéro ou plusieurs des caractères suivants `~`, `*`, `=` et `-` peut servir de séparateur dans les logs de ce projet.

Implémente la fonction `split_line`, qui prend une ligne et renvoie un tableau de _strings_.

```gleam
log_parser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
// -> ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. Marque les lignes avec le nom d'utilisateur

Tu as remarqué que certaines lignes de log contiennent des phrases qui font référence à des utilisateurs.
Ces phrases contiennent toujours la _string_ `"User"`, suivie d'un ou plusieurs caractères d'espacement, puis d'un nom d'utilisateur.
Tu décides de marquer ces lignes.

Implémente une fonction `tag_with_user_name` qui traite les lignes de log :

- Les lignes qui ne contiennent pas la _string_ `"User"` restent inchangées.
- Pour les lignes qui contiennent la _string_ `"User"`, préfixe la ligne avec `[USER]` suivi du nom d'utilisateur.

```gleam
log_parser.tag_with_user_name("[INFO] User Alice created a new project")
// -> "[USER] Alice [INFO] User Alice created a new project"
```

Tu peux supposer que :

- Chaque occurrence de la _string_ `"User"` est suivie d'un ou plusieurs caractères d'espacement et du nom d'utilisateur.
- Il y a au plus une occurrence de la _string_ `"User"` par ligne.
- Les noms d'utilisateur sont des _strings_ non vides qui ne contiennent pas d'espace.
