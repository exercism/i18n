# Construis un exécuteur de tests

L'exécuteur de tests est un outil essentiel qui permet :

- au site web de vérifier automatiquement si une itération passe tous les tests ;
- aux apprenants de résoudre les exercices avec [l'éditeur en ligne](/docs/using/solving-exercises/using-the-online-editor) ([pas besoin de la CLI](/docs/using/solving-exercises/working-locally)).

Pour commencer à construire un exécuteur de tests, consulte le document [Créer un exécuteur de tests à partir de zéro](/docs/building/tooling/test-runners/creating-from-scratch).

## Implémentation

L'outillage d'un parcours est généralement (en grande partie) écrit dans le langage de ce parcours.

```exercism/caution
Tu es libre d'utiliser d'autres langages, mais chaque langage supplémentaire rendra plus difficile la maintenance du parcours et la contribution à celui-ci.
C'est pourquoi on te recommande d'utiliser le langage du parcours dans la mesure du possible, car cela facilite la maintenance et la contribution.
```

## Déploiement

L'exécuteur de tests est empaqueté et exécuté sous forme de [conteneur Docker](/docs/building/tooling/docker).
Les images Docker de l'exécuteur de tests sont déployées automatiquement grâce à un [workflow GitHub Actions](https://github.com/exercism/generic-test-runner/blob/main/.github/workflows/docker.yml).

## Tests

Une fois qu'un exécuteur de tests a été construit, tu peux utiliser son image Docker dans la configuration d'intégration continue de ton parcours pour vérifier les exercices de celui-ci.
Le principal avantage de cette approche est qu'elle imite mieux la configuration de production ; autrement dit, tu peux avoir davantage confiance dans le fait que tout fonctionne aussi en production.
Un inconvénient possible est qu'elle peut ralentir le workflow d'intégration continue.
C'est à toi, en tant que mainteneur, de décider quelle approche fonctionne le mieux pour ton parcours.
