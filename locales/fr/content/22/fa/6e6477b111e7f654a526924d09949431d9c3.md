# À propos

Un fichier est un flux auquel un nom est associé sur le disque. Le vocabulaire [`io.files`][io.files] propose deux façons de travailler avec un fichier : des mots pratiques qui lisent ou écrivent tout le fichier en un seul appel, et des ouvreurs de flux (les combinateurs `with-…`) pour lire ou écrire de façon incrémentale. Les deux s'appuient sur le même [protocole de flux][stream-protocol] que les flux en mémoire du concept `io-streams` : un `<file-reader>` et un `<string-reader>` répondent aux mêmes mots.

Chaque mot qui manipule un fichier prend un **encodage**, le schéma qui fait correspondre des octets à des caractères et inversement. Pour du texte, il s'agit presque toujours de [`utf8`][utf8], fourni par `io.encodings.utf8` ; le travail sur des données binaires utilise `latin1` ou un encodage `<byte-array>`.

## Lis tout le fichier

```
file-contents   ( path encoding -- str )
file-lines      ( path encoding -- seq )
```

`file-contents` renvoie tout le fichier sous forme d'une seule _string_. `file-lines` renvoie ses lignes dans un tableau, les caractères de fin de ligne en moins, ce qui est bien pratique quand chaque ligne correspond à un enregistrement.

```factor
USING: io.encodings.utf8 io.files ;

"forecast.txt" utf8 file-contents   ! => "sunny\ncloudy\n"
"forecast.txt" utf8 file-lines      ! => { "sunny" "cloudy" }
```

## Écris tout le fichier

```
set-file-contents   ( str path encoding -- )
set-file-lines      ( seq path encoding -- )
```

Les deux **remplacent** le fichier, en le créant s'il n'existe pas. `set-file-contents` écrit une _string_ telle quelle ; `set-file-lines` écrit chaque élément d'une séquence sur sa propre ligne, en fournissant les retours à la ligne.

```factor
{ "sunny" "cloudy" } "forecast.txt" utf8 set-file-lines
! forecast.txt now holds "sunny\ncloudy\n"
```

## Les flux à portée

Quand tu veux ajouter du contenu à un fichier, ou lire et écrire morceau par morceau, ouvre-le avec un combinateur `with-…` et utilise les mots de flux ambiants à l'intérieur de la _quotation_ :

```
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
with-file-appender   ( path encoding quot -- )
```

```factor
USING: io io.encodings.utf8 io.files ;

"log.txt" utf8 [ "another line" print ] with-file-appender
```

`with-file-writer` tronque d'abord le fichier ; `with-file-appender` conserve le contenu existant et écrit à la suite. Chacun constitue une portée de destruction : le descripteur de fichier est fermé quand la _quotation_ se termine, même si elle lève une exception, la même garantie qu'offrent les combinateurs de `boatswains-bilge`, ici spécialisée pour les fichiers.

## Tout le fichier ou les flux à portée ?

Utilise `file-contents` / `file-lines` / `set-file-contents` / `set-file-lines` quand le fichier est assez petit pour tenir en mémoire et que tu veux tout récupérer d'un coup. Utilise plutôt les ouvreurs `with-…` quand tu dois ajouter du contenu, lire un gros fichier ligne par ligne avec `readln`, ou entrelacer lectures et écritures : dans tous les cas où garder l'intégralité du fichier en mémoire serait du gaspillage ou une erreur.
