# Introduction

Le [filtrage par motif][pattern-matching] permet d'écrire du code avec des branchements expressifs et la [déstructuration][destructuring] offre une liaison élégante des valeurs aux variables. Maîtriser les deux est extrêmement utile quand on programme en Elm et, utilisés ensemble, ils améliorent grandement la lisibilité du code.

## Filtrage par motif simple

Le filtrage par motif désigne du code qui se branche selon la forme des données manipulées. Il s'accorde donc naturellement avec le concept de types personnalisés, qui expriment les multiples formes que peuvent prendre certaines données. Si l'on dispose par exemple d'un type personnalisé `Color`, défini comme étant soit `Blue`, soit `Red`, on peut écrire une fonction `toString` qui filtre par motif sur la couleur pour renvoyer la bonne _string_.

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

Le filtrage par motif fonctionne aussi pour les types personnalisés qui ne sont pas de simples énumérations. Prenons une fonction `hello` qui prend en paramètre un `Maybe String`, contenant soit le nom d'une personne, soit rien du tout. Lorsqu'on filtre par motif, on peut donner des noms en minuscules à des données pour les lier à cette variable, et pouvoir ainsi les utiliser dans la partie droite du cas.

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

Le filtrage par motif doit être exhaustif, sinon le compilateur refusera de compiler. Mais parfois, certaines données ou certaines branches d'une expression case ne nous intéressent pas. Dans ce cas, plutôt que d'avoir à trouver un nom de variable auquel lier les données et à écrire une branche pour chaque cas, on peut utiliser le joker de soulignement `_`.

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## Filtrage par motif avancé

En plus des types personnalisés, on peut aussi filtrer par motif sur des types qui possèdent des littéraux, comme `Char`, `String`, `Int` et `Floats`.

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

Pour filtrer sur plusieurs valeurs sans les imbriquer, une astuce courante en Elm consiste à combiner les valeurs à filtrer dans des [_tuples ad hoc_][ad-hoc-tuples], comme ceci :

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

Et comme les listes sont chères aux programmeurs fonctionnels, [on peut aussi les filtrer par motif][pattern-match-lists], avec la même syntaxe que celle utilisée pour les construire, à l'aide de l'opérateur `::`.

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

Enfin, le filtrage par motif fonctionne même de façon récursive, ce qui permet d'explorer en profondeur des types complexes et récursifs.

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## Déstructuration

La déstructuration est très proche du filtrage par motif, en ce sens qu'elle permet de lier des variables aux données contenues dans les types. La principale différence, c'est qu'on appelle ce mécanisme « déstructuration » quand une seule forme est possible, et qu'on parle de filtrage par motif quand il y en a plusieurs. On rencontre souvent la déstructuration dans les liaisons `let`, dans les arguments de fonction, et bien sûr dans les expressions case, mêlée au filtrage par motif.

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

La déstructuration peut s'employer pour les types personnalisés à une seule variante, pour les tuples, et aussi pour les enregistrements, où elle est très pratique. Pour [déstructurer un enregistrement][records-pattern-matching], on peut utiliser n'importe quel nombre de ses champs : un, deux, ..., ou bien tous les champs.

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

Malheureusement, la syntaxe d'Elm ne permet pas la déstructuration récursive des enregistrements. Dans l'exemple `Circle` précédent, impossible d'accéder aux positions `x`` and `y`center`center`x`x`y`y`.

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

Et voici une dernière astuce ! Parfois, on veut accéder facilement à la fois à une chose dans son ensemble et à une partie de celle-ci. C'est là que le [mot-clé `as`][as-keyword] peut être utile : il permet de donner un nom d'alias à une chose dans son ensemble, tout en pouvant déstructurer son contenu.

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
