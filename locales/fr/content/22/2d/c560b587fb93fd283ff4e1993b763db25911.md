# Complément aux instructions

Dans cet exercice Roc, les opérations sur le compte sont pures : chaque mise à jour renvoie une nouvelle valeur de compte. Les comptes sont fermés au départ, une réouverture réinitialise le solde, et les dépôts comme les retraits doivent être positifs. Les opérations invalides renvoient des erreurs. Cet exercice se concentre sur la logique du compte et ne teste pas la concurrence.

En Roc, on laisse généralement la concurrence à la plateforme ; il n'y a donc pas de tests de concurrence ici. Dans une application concurrente, ces opérations pures s'exécuteraient dans un mécanisme qui applique chaque mise à jour du compte de façon atomique. Par exemple, la plateforme peut traiter les commandes de compte de manière séquentielle, ou s'appuyer sur des transactions de base de données.

Tu peux aussi aller voir l'exercice `parallel-letter-frequency`, où la plateforme donne au code Roc accès aux primitives de calcul parallèle. Le parallélisme réel reste géré par la plateforme, mais le code Roc obtient davantage de contrôle dessus.
