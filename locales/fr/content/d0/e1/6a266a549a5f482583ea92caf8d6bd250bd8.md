# Introduction

Une **boucle** est une suite d'instructions qui est potentiellement exécutée plusieurs fois, jusqu'à ce qu'une condition d'arrêt soit remplie.

En x86-64, une boucle est généralement créée à l'aide d'un saut vers une étiquette précédente :

```x86asm
example_loop:
    ...
    jmp example_loop
```

Note qu'un saut inconditionnel vers une étiquette précédente transfère toujours l'exécution à cette étiquette.
Cela signifie que la boucle se répétera indéfiniment, à moins qu'un autre saut ne mène en dehors de la séquence répétée.

Par exemple, cette boucle ne s'arrête pas :

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Et cette boucle peut s'arrêter, selon que la condition est remplie ou non :

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Boucles de comptage

Une boucle de comptage se termine presque toujours de la même manière : une instruction qui met à jour un compteur ou compare deux valeurs, immédiatement suivie d'un saut conditionnel qui décide s'il faut refaire un tour.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0` n'est pas nécessaire dans le code ci-dessus, car `sub rsi, 1` positionne déjà le `zero flag (ZF)` lorsque le résultat vaut `0`.

Bien que `cmp` soit le principal moyen de tester des conditions en assembleur, de nombreuses instructions mettent à jour les indicateurs.
Par exemple, beaucoup d'instructions arithmétiques sur des entiers ou bit à bit mettent à jour `ZF` lorsque le résultat vaut `0`, et `SF` lorsqu'il est négatif (c'est-à-dire quand le bit de poids fort est à 1).

Tu peux consulter une [référence][reference] pour voir quels indicateurs sont affectés par chaque instruction.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Note que dans l'exemple ci-dessus, `rsi` est supposé supérieur à `0`.
S'il valait `0`, alors `sub rsi, 1` réduirait `rsi` à `-1`, qui est un très grand nombre non signé.
Il faudrait `18,446,744,073,709,551,615` itérations supplémentaires avant que la boucle ne se termine enfin.
De plus, comme la longueur du tableau vaut `0`, tout accès mémoire serait hors limites.

Si rien ne garantit la longueur d'un tableau, il existe deux approches courantes.

La première consiste à déplacer la condition d'arrêt au début de la boucle, puis à placer un saut inconditionnel à la fin :

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

La seconde consiste à tester une fois si le tableau est vide avant le début de la boucle :

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Cette seconde approche est généralement plus efficace que la première, car il y a moins de branchements dans le corps de la boucle.
Tu en apprendras davantage dans un prochain concept.

~~~~exercism/advanced
Dans certaines situations, les processeurs modernes parviennent à fusionner deux instructions différentes en une seule opération.
Cette optimisation s'appelle la **macrofusion**.

De nombreuses instructions arithmétiques telles que `sub` et `add`, ainsi que `cmp` et `test`, fusionnent couramment avec un saut conditionnel qui les suit immédiatement.
Cela signifie qu'une instruction telle que `cmp rax, rdx`, immédiatement suivie d'un saut conditionnel, peut généralement être traitée par le processeur comme une seule opération.

La macrofusion dépend du processeur, et le choix des instructions qui fusionnent avec tel ou tel saut conditionnel varie quelque peu.

Une référence utile est [La microarchitecture des processeurs Intel, AMD et VIA, par Agner Fog][agner-uarch].
La section 3.4.2.2 (Optimizing for Macrofusion) du [manuel de référence pour l'optimisation Intel][intel-opt] répertorie également les paires fusibles pour les processeurs Intel.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
