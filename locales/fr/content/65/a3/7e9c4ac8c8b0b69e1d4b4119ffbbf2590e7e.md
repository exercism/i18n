# Introduction

En Gleam, on peut utiliser une expression `case` pour exécuter du code de manière conditionnelle. Avec une expression `case`, on peut tester une valeur par rapport à un ou plusieurs _motifs_. Un exemple de tel motif est le _motif littéral_, qui correspond à une valeur littérale (par exemple `1` ou `"hello"`).

Les expressions `case` s'écrivent avec le mot-clé `case` :

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    1 -> "One"
  }
}
```

Même si cela peut ressembler aux instructions `switch` d'autres langages, le filtrage par motifs révèle tout son intérêt lorsqu'on utilise aussi d'autres motifs. L'un d'eux est le _motif de variable_, qui permet d'affecter une valeur à une variable. Dans cet exemple, la variable `i` se verra affecter la valeur de `number` si celui-ci n'est pas `0` :

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i -> "Non zero"
  }
}
```

Dans certains cas, tu peux vouloir ajouter une condition supplémentaire à un motif. C'est ce qu'on appelle une _garde_ (clause), que l'on peut ajouter avec le mot-clé `if` :

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
  }
}
```

Pour des raisons de performance, seuls les opérateurs mathématiques et booléens de base sont autorisés dans les gardes ; aucune autre fonction ne peut y être utilisée.

Dans l'exemple ci-dessus, certaines entrées possibles n'auront aucun motif correspondant. Le compilateur le détectera et affichera une erreur. C'est ce qu'on appelle la _vérification d'exhaustivité_. Pour résoudre l'avertissement, il faut traiter tous les cas. Pour cela, on peut utiliser le _motif joker_, qui correspond à n'importe quelle valeur :

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
    _ -> "Positive number"
  }
}

// No compiler error
```

Une expression `case` teste une valeur par rapport à chaque motif, de haut en bas, jusqu'à ce qu'elle trouve un motif correspondant et exécute la logique associée à ce motif. L'ordre des motifs est important !
