# Introduction

Tu sais déjà *construire* une _quotation_ à partir de morceaux et l'exécuter. Une _quotation_ n'est qu'une séquence de code, donc les mots de séquence que tu connais s'y appliquent :

```factor
USING: kernel math prettyprint quotations sequences ;

{ [ 1 ] [ 2 + ] [ 3 * ] } concat >quotation call .   ! => 9
[ 1 + ] dup append .                                 ! => [ 1 + 1 + ]
```

`append` réunit deux _quotations_, `concat` aplatit un tableau de celles-ci, `map` transforme des données en _quotations_, et `>quotation` rend le résultat appelable. `MACRO:` reprend exactement cette compétence pour la déplacer vers le **temps de compilation**.

## Qu'est-ce qu'une macro

Une définition `MACRO:` ressemble à un mot ordinaire, mais son corps s'exécute *au moment où ton programme est compilé*, et non au moment où il s'exécute. Le corps doit laisser **une seule _quotation_** sur la pile. Le compilateur **insère alors cette _quotation_ au site d'appel** : il remplace l'appel de macro par le code produit par le corps. Au moment de l'exécution, il ne reste aucune macro, seulement le code généré.

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- spliced )
    dup append ;
```

Partout où tu écris `[ 1 + ] twice`, le compilateur :

1. exécute le corps avec `[ 1 + ]` sur la pile,
2. `dup append` construit la _quotation_ `[ 1 + 1 + ]`,
3. insère son code, `1 + 1 +`, à cet endroit.

Ainsi, un mot qui appelle `twice` se compile comme si tu avais écrit `1 + 1 +` à la main :

```factor
: inc-twice ( x -- y ) [ 1 + ] twice ;

5 inc-twice .   ! => 7
```

Le contraste essentiel : un mot normal qui prend une _quotation_ la `call` au moment de l'exécution. Une macro n'appelle jamais rien : elle remet au compilateur du *nouveau code* à compiler à sa place.

## Les entrées doivent être des littéraux

Comme le corps s'exécute au moment de la compilation, les entrées d'une macro doivent être connues *à ce moment-là*. Elles doivent être des **littéraux** au site d'appel : une _quotation_ `[ … ]`, un nombre, un tableau, une _string_. Une valeur qui n'existe qu'au moment de l'exécution ne peut pas être transmise à une macro.

```factor
! DOCTEST: SKIP — illustrative call sites, not standalone code
[ 1 + ] twice          ! ok: the quotation is a literal
[ 1 + ] 3 repeat-quot  ! ok: the quotation and the number are literals
```

## La boîte à outils

Le corps d'une macro est du code ordinaire qui renvoie une _quotation_. Les mots que tu connais déjà font l'essentiel du travail :

| pour construire…                             | utilise              |
|----------------------------------------------|----------------------|
| `[ A B ]` à partir de `[ A ]` et de `[ B ]`  | `append`             |
| une _quotation_ à partir d'un tableau de celles-ci | `concat >quotation` |
| une _quotation_ par élément d'une séquence   | `map`, puis `concat >quotation` |

Deux mots supplémentaires, issus de `sequences` et `kernel`, complètent la panoplie.

**`<repetition>`** (dans `sequences`) crée une séquence de `n` copies d'un même élément. Son effet de pile est `( length elt -- repetition )`, le nombre venant en premier. Le résultat est une séquence *virtuelle*, qu'il faut donc aplatir de la façon habituelle :

```factor
3 [ 1 + ] <repetition> concat >quotation .   ! => [ 1 + 1 + 1 + ]
```

**`curry`** (dans `kernel`) ajoute une valeur au début d'une _quotation_, ce qui produit une nouvelle _quotation_ qui empile cette valeur en premier :

```factor
3 [ + ] curry .          ! => [ 3 + ]
{ 1 2 3 } [ . ] curry .  ! => [ { 1 2 3 } . ]
```

`curry` est le moyen d'incorporer un élément précis dans une _quotation_, exactement ce qui transforme `{ 10 20 30 }` et `[ + ]` en `[ 10 + ] [ 20 + ] [ 30 + ]`.

## Pourquoi c'est plus simple que ça en a l'air

Dans certains langages, les macros ont besoin d'une syntaxe spéciale de citation/décitation et d'une machinerie supplémentaire pour éviter les collisions de noms. Factor n'a besoin de rien de tout cela : une _quotation_ est déjà une séquence de mots *résolus*, car l'analyseur syntaxique a recherché chacun des `dup`, `+` et `append` au moment où il a lu le `[ … ]`. Le corps d'une macro n'est donc que la manipulation de séquences que tu pratiques déjà, qui se trouve renvoyer une _quotation_.

## Un proche cousin : `$[ … ]`

Une macro renvoie une _quotation_ destinée à être insérée dans un *appel*. Si tu veux plutôt une simple *valeur* calculée au moment de l'analyse, `$[ code ]` exécute `code` pendant que le fichier est lu et intègre le résultat dans la source sous forme de littéral :

```factor
! DOCTEST: SKIP — compile-time value, shown for contrast
USING: calendar literals ;

CONSTANT: build-time $[ now ]
```

`$[ … ]` vient du vocabulaire [`literals`][literals], qui rassemble les mots servant à interpoler dans des littéraux des résultats calculés au moment de l'analyse. Il est mentionné pour être complet. Les quatre pochoirs que tu vas écrire, `twice`, `repeat-quot`, `compose-many` et `each-literal`, sont tous des déclarations `MACRO:`.
