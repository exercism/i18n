# Introduction

Avec Go 1.18, Go a ajouté la prise en charge des **génériques**.
Les génériques permettent d'écrire des fonctions et des structures de données qui fonctionnent avec différents types sans dupliquer le code.

## Pourquoi les génériques ?

En Go, les fonctions et les types fonctionnent normalement avec des types précis, comme `int` ou `string`.
Avant les génériques, on avait deux options pour prendre en charge plusieurs types.
La première consistait à écrire plusieurs fonctions portant des noms différents, comme `SumInts` et `SumFloats`.
Cette approche produit du code dupliqué, difficile à maintenir.
La seconde consistait à utiliser l'interface vide `any` (`interface{}`).
Cependant, l'interface vide supprime les vérifications de type à la compilation et impose des assertions de type à l'exécution.
Les génériques résolvent ce problème en apportant la sûreté de typage tout en évitant la duplication de code.

## Les fonctions génériques

On définit une fonction générique en ajoutant des **paramètres de type** entre crochets `[...]` après le nom de la fonction.
Voici un exemple de fonction générique qui renvoie une _slice_ inversée :

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

Dans cet exemple, `T` est un paramètre de type.
On peut voir `T` comme un espace réservé pour un type réel.
Le mot-clé `any` entre les crochets est une **contrainte de type**.
La contrainte indique au compilateur quels types sont autorisés pour `T`.
Ici, `any` signifie que `T` peut être n'importe quel type.

### Appelle une fonction générique

On peut appeler une fonction générique en passant le type réel entre crochets.
Ce type réel s'appelle un **argument de type**.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

Dans la plupart des cas, le compilateur Go détecte automatiquement le type à partir des arguments de la fonction.
Cette fonctionnalité s'appelle l'**inférence de type**.
Avec l'inférence de type, inutile d'écrire l'argument de type entre crochets.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

Dans cet exemple, le compilateur voit que `words` est une _slice_ de _strings_, et en déduit que `T` est `string`.

## Les contraintes de type

Chaque paramètre de type doit avoir une contrainte.
Une contrainte précise quels types on peut utiliser comme arguments de type.
Elle détermine aussi les opérations qu'on est autorisé à effectuer sur les valeurs de ce type.

### La contrainte `any`

La contrainte `any` autorise n'importe quel type.
En Go, `any` est un alias de l'interface vide `interface{}`.
Comme `any` autorise tous les types, la fonction ne peut effectuer que des opérations qui fonctionnent sur l'ensemble des types Go.
Par exemple, si tu as deux valeurs de type `any` qui contiennent des _slices_, elles ne peuvent pas être comparées avec `==`, car les _slices_ ne se comparent pas avec `==`.

### La contrainte `comparable`

Go fournit une contrainte intégrée appelée `comparable`.
La contrainte `comparable` autorise tout type qui prend en charge les opérateurs `==` et `!=`.
Les types comparables comprennent les booléens, les nombres, les _strings_, les pointeurs, les canaux, ainsi que les structures et les tableaux composés de types comparables.

Voici un exemple de fonction qui vérifie si une _slice_ contient un élément donné :

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Comme `T` utilise la contrainte `comparable`, l'expression `elem == target` est valide.
Si on remplace `comparable` par `any`, le compilateur signale une erreur.

### Des contraintes personnalisées avec des ensembles de types

Depuis Go 1.18, les interfaces peuvent définir des ensembles de types en plus des méthodes.
On peut utiliser le caractère barre verticale `|` pour lister les types autorisés dans une interface.

```go
type Number interface {
    int | int64 | float64
}
```

On peut maintenant utiliser `Number` comme contrainte d'une fonction :

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Comme tous les types de `Number` prennent en charge l'opérateur `*`, Go autorise `value * 2` dans la fonction.

### L'approximation par le type sous-jacent `~`

Il arrive qu'on crée un type personnalisé à partir d'un type primitif :

```go
type MyInt int
```

La contrainte `Number` définie plus haut n'autorise que les types exacts `int`, `int64` et `float64`.
Si on passe une valeur de type `MyInt` à `Double`, le compilateur produit une erreur, car `MyInt` ne correspond pas à `int`.
Pour autoriser tout type dont le type sous-jacent est `int`, ajoute un tilde `~` devant le type :

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

On peut désormais utiliser `Double` avec des valeurs de type `MyInt`.

### La contrainte `cmp.Ordered`

La bibliothèque standard fournit la contrainte `cmp.Ordered` dans le [paquet `cmp`][doc-cmp].
La contrainte `cmp.Ordered` autorise tout type qui prend en charge les opérateurs de comparaison `<`, `<=`, `>` et `>=`.

## Les types génériques

On peut aussi utiliser des paramètres de type pour définir des types génériques, comme des structures.
Voici un exemple de structure de données générique `Stack` :

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Quand on déclare une variable d'un type générique, il faut fournir l'argument de type entre crochets :

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

L'inférence de type ne fonctionne que pour les fonctions génériques.
Il faut toujours préciser l'argument de type quand on crée une valeur d'un type générique.

## Quand utiliser les génériques

Les génériques sont une fonctionnalité puissante, mais il n'est pas nécessaire de les utiliser pour chaque problème.

Utilise les génériques dans les situations suivantes :
- Tu construis des structures de données, comme des arbres, des listes chaînées ou des caches, qui fonctionnent avec n'importe quel type d'élément.
- Tu écris des fonctions utilitaires qui agissent sur des _slices_ ou des _maps_ de n'importe quel type, comme filtrer, trier ou rechercher.
- Tu as besoin de la même implémentation exacte pour plusieurs types, et tu veux la sûreté de typage à la compilation.

Utilise plutôt des interfaces dans les situations suivantes :
- Ce qui t'intéresse, ce sont les comportements et les méthodes, pas le type de données sous-jacent.
  Par exemple, si tu veux lire et traiter des données provenant de sources de types variés (fichiers, réseau, TTY), utilise plutôt `func Process(src io.Reader)` que `func Process[T](src T)`.
- Des types différents ont besoin d'implémentations de méthodes différentes pour faire leur travail.
