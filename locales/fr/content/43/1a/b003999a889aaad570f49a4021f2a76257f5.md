# Tests

Si le binaire 8th se trouve dans ton PATH, saisis la commande :

```bash
8th -f test.8th
```

Si le binaire 8th n'est pas dans le PATH, sous Windows, saisis

```cmd
\path\to\8th -f test.8th
```

Sous Linux ou macOS :

```bash
/path/to/8th -f test.8th
```

## Tester dans la REPL

Lance 8th en chargeant test-words.8th :

```sh
8th -f test-words.8th
```

Cela démarre une session CLI dans laquelle, une fois que tu as écrit du code dans ton fichier de solution, tu peux le charger dans la REPL.
Par exemple, pour l'exercice « word-count », tu saisirais :

```8th
"word-count.8th" f:include
```

Et tu peux lancer les tests avec
```sh
"word-count-tests.8th" f:include
```

Ou tu peux copier-coller un seul test de ce fichier, ou saisir le tien.

## Tests ignorés

Résoudre un exercice signifie faire passer tous ses tests.
Par défaut, un seul test (le premier) est exécuté quand tu lances les tests.
C'est intentionnel : cela te permet de te concentrer uniquement sur la réussite de ce test.
Une fois qu'il passe, tu peux activer le test suivant en déplaçant le mot `SKIP-REST-OF-TESTS` après lui.

## Contourner les sauts

Pour lancer tous les tests, y compris ceux qui viennent après le mot `SKIP-REST-OF-TESTS`, tu peux définir la variable d'environnement `RUN_ALL_TESTS` avec la valeur `true`.
Une façon de la définir juste le temps de lancer les tests est la suivante (macOS et Linux) :

```bash
RUN_ALL_TESTS=true 8th -f test.8th
```
