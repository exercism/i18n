# Introduction

Les fonctions ont déjà été présentées dans le concept [Bases][concept-basics], avec des exemples comme celui-ci :

```R
squareit <- function(x) {
    x * x
}

squareit(3)
#> [1] 9

# shorter form
squareit_short <- function(x) x ^ 2
```

Si l'on examine de plus près la définition de `squareit`, on peut identifier plusieurs parties :

- La fonction prend un argument formel `x`.
- Il y a un corps de fonction, généralement entre accolades `{ }`.
- Une fois l'objet fonction créé, il est affecté à une variable `squareit`.

En R, une fonction est un objet de première classe, au même titre que les nombres et les _strings_.
Ainsi, `squareit <- function...` est une affectation dont la syntaxe est identique à celle de `x <- 42`.

## Arguments

Contrairement à d'autres langages de script comme Python et Julia, R ne fait pas de distinction claire entre les arguments positionnels et les arguments nommés.

Lors d'un appel de fonction, on peut passer les valeurs de façon positionnelle ou par leur nom.
Cette seconde possibilité est utile pour les fonctions complexes qui prennent beaucoup d'arguments, dont l'ordre est difficile à mémoriser.

```R
f <- function(x, y) x / y

# call positionally
f(4, 2)
#> [1] 2

# call by name
f(y = 2, x = 4)
#> [1] 2
```

### Arguments facultatifs

On peut spécifier des valeurs par défaut pour les arguments dans la définition de la fonction, mais elles doivent venir après tous les arguments qui n'en ont pas.

On peut ensuite choisir d'accepter la valeur par défaut ou de la remplacer.

```R
g <- function(x, y = 2) x / y

# default y value
g(6)
#> [1] 3

# explicit y value
g(6, 3)
#> [1] 2
```

### Arguments supplémentaires

Pour accepter un nombre quelconque d'arguments supplémentaires, utilise un `...` (ellipse) dans la définition.
Il est possible de convertir en vecteur les valeurs supplémentaires passées lors de l'appel de la fonction, mais lis la suite pour découvrir une autre façon d'utiliser ces « dot args » (*appelés « varargs » dans plusieurs autres langages*).

```R
var_f <- function(x, y, ...) {
  print(c(...))
}

var_f(2, 3, "opt1", "opt2")
#> [1] "opt1" "opt2"
```

## Environnement de la fonction

Plus haut, on a dit que les arguments formels et le corps sont tous deux des composants d'une fonction.

En réalité, il existe un troisième composant : l'*environnement* dans lequel la fonction est définie.

On peut l'illustrer avec le cas des fonctions imbriquées :

```R
outer_func <- function(x) {
  inner_func <- function(y) {
    x * y
  }
  
  inner_func(3)
}

outer_func(5)
#> [1] 15
```

L'appel de fonction passe `x = 5` à la fonction externe, et cette valeur est disponible dans le corps de cette fonction.

La fonction interne fait *partie* du corps de la fonction externe et a accès à la valeur de `x`.
Autrement dit, `x = 5` se trouve dans l'*environnement* de la fonction interne.

Techniquement, on parle de [_closure_][wiki-closure].

L'environnement est particulièrement important avec les « dot args », car les valeurs fournies de cette façon peuvent être transmises aux appels de fonction à l'intérieur du corps de la fonction.
La fonction externe n'a pas besoin de savoir, ni de se soucier, de ce que signifient les « dot args ».

```R
f_var <- function(x, ...) {
  sum(x, ...)
}

x <- c(1, 2, NA, 6)

# for sum(), na.rm defaults to FALSE
f_var(x)
#> [1] NA

# pass through the na.rm value
f_var(x, na.rm = TRUE)
#> [1] 9
```

Cette technique est beaucoup utilisée par les bibliothèques du Tidyverse, comme [`stringr`][ref-stringr].
Beaucoup de fonctions de `stringr` sont une surcouche conviviale autour de fonctions de bas niveau issues de `stringi` et de R de base.

Les arguments supplémentaires fournis aux fonctions `str_*()` sont simplement transmis à ces fonctions de bas niveau.

## Les fonctions comme valeurs de retour

Une fonction externe peut définir une fonction interne (nommée ou anonyme, comme décrit ci-dessous) et l'utiliser comme valeur de retour.

La fonction renvoyée inclura l'environnement dans lequel elle a été définie.

```R
times_y <- function(x) {
  # anonymous function - see next section
  \(y) x * y
}

f <- times_y(3)
class(f)
#> [1] "function"

f(4)
#> [1] 12
```

## Fonctions anonymes

Quand on définit une fonction, on lie généralement l'objet fonction obtenu à une variable :

```R
x <- 2

# function definition captures x from the environment
doubleit_short <- function(y) x * y
```

Cela facilite l'utilisation de la fonction plus loin dans le script, mais cette liaison n'est pas indispensable.
Une fonction courte, utilisée une seule fois, peut s'avérer utile dans le contexte immédiat.
Sans liaison de nom, on parle de *fonction anonyme*.

Les fonctions anonymes sont si courantes que (*depuis R v4.1.0*) il existe une syntaxe abrégée pour les définir : remplace le mot `function` par une barre oblique inverse `\`.

Un exemple a été utilisé dans la section précédente, à propos des valeurs de retour.

## Copie à la modification

R permet d'affecter des valeurs à des éléments individuels d'un vecteur.
Si on passe un vecteur comme argument d'une fonction et qu'on le modifie dans le corps de la fonction avant de le renvoyer, on obtient un vecteur modifié.

Mais qu'est-il arrivé au vecteur d'origine ?

```R
f <- function(vec) {
  vec[1] <- 42
  vec
}

vals <- c(1, 3, 4)

# f() returns a modified vector
f(vals)
#> [1] 42  3  4  

# the original vector is unchanged.
vals
#> [1] 1 3 4
```

R est un langage conçu pour la science des données.
La collecte de ces données peut coûter beaucoup de temps et d'efforts, et potentiellement une somme d'argent vertigineuse : *il est important de ne pas les corrompre !*

La règle générale (à quelques exceptions près) est la *copie à la modification*.
Si un objet (comme un vecteur) est modifié d'une manière qui pourrait causer des problèmes par la suite, R renvoie une *copie modifiée* et laisse l'original intact.

Copier de grandes structures de données peut être coûteux en calcul, mais c'est généralement le moindre mal quand l'alternative est la corruption des données.
