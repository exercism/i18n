# Introduction

Python est un [langage de programmation dynamique et fortement typé][dynamic typing in python].
Il utilise à la fois le [_duck typing_][duck typing] et le [typage progressif][gradual typing], via les [indications de type][type hints].
Python met fortement l'accent sur la lisibilité du code et, comme Haskell, utilise l'[indentation significative][significant indentation] pour désigner les définitions de fonctions, de méthodes et de classes.

Python a été créé par Guido van Rossum et publié pour la première fois en 1991.

Les _styles_ de programmation impératif, déclaratif (par exemple fonctionnel) et orienté objet sont tous pris en charge, mais en interne, **[tout, en Python, est un objet][everythings an object]**.

On creusera tout ce que cela signifie au fur et à mesure que l'on avancera dans les concepts du parcours Python.

Ce premier concept (`basics`) présente 4 grandes caractéristiques du langage Python :
1.  L'affectation de noms (_variables et constantes_),
2.  Les fonctions (_le mot-clé `def` et le mot-clé `return`_),
3.  Les commentaires, et
4.  Les docstrings.

<br>

## Affectation de noms (variables et constantes)

Les programmeurs peuvent lier des [_noms_][facts-and-myths-about-python-names] (aussi appelés _variables_) à n'importe quel type d'objet à l'aide de l'opérateur d'affectation `=` : `<name> = <value>`.
Un nom peut être réaffecté (ou relié à nouveau) à différentes valeurs (différents types d'objets) au cours de sa vie :


```python
>>> my_first_variable = 1  # <--my_first_variable bound to an integer object of value one.
>>> my_first_variable = 2  # <--my_first_variable re-assigned to integer value 2.

>>> print(type(my_first_variable))
<class 'int'>

>>> print(my_first_variable)
2

>>> my_first_variable = "Now, I'm a string." # <--You may re-bind a name to a different object type and value.
>>> print(type(my_first_variable))
<class 'str'>

>>> my_first_variable = 'You can call me "str".' # <--Strings can be declared using single or double quote marks.
>>> print(my_first_variable)
You can call me "str".
```


### Constantes

Les constantes sont des noms destinés à n'être affectés qu'une seule fois dans un programme, même si Python n'empêchera pas une réaffectation.
Utiliser `SCREAMING_SNAKE_CASE` signale à quiconque lit le code que ce nom ne doit **pas** être réaffecté, et que sa valeur ne doit pas être modifiée.
Les constantes doivent être définies au niveau d'un [module][module] (fichier), et sont généralement visibles par toutes les fonctions et toutes les classes d'un programme.



## Fonctions

Le mot-clé `def` commence une [définition de fonction][function definition].
Chaque fonction peut prendre zéro ou plusieurs [paramètres][parameters] formels entre parenthèses `()`, suivis de deux-points `:`.
Les instructions qui forment le _corps_ de la fonction commencent sur la ligne qui suit `def` et doivent être _indentées en bloc_.


```python
# The body of this function is indented by 2 spaces & prints the sum of the numbers.
def add_two_numbers(number_one, number_two):
  total = number_one + number_two
  print(total)  

>>> add_two_numbers(3, 4)
7


# Inconsistent indentation in your code blocks will raise an error.
>>> def add_three_numbers_misformatted(number_one, number_two, number_three):
...     result = number_one + number_two + number_three   # This was indented by 4 spaces.
...    print(result)     # <--This was only indented by 3 spaces.
...
...
  File "<stdin>", line 3
    print(result)
    ^
IndentationError: unindent does not match any outer indentation level
```


Les fonctions renvoient _explicitement_ une valeur ou un objet à l'aide du mot-clé [`return`][return] :


```python
# Function definition on first line, explicit return used on final line.
def add_two_numbers(number_one, number_two):
  return number_one + number_two   


# Calling the function in the Python shell returns the sum of the numbers.
>>> add_two_numbers(3, 4)
7

# Assigning the function call to a variable and printing 
# the variable will also return the value.
>>> sum_with_return = add_two_numbers(5, 6)
>>> print(sum_with_return)
11
```


Les fonctions qui n'ont pas d'expression _explicite_ après un `return` renvoient _implicitement_ l'objet [`None`][none].
Les détails de `None` seront couverts dans un concept ultérieur.
Pour les besoins de cet exercice et de cette explication, `None` est un espace réservé qui ne représente rien, ou null :


```python
# This function will return `None`
def square_a_number(number):
    square = number * number
    return # <-- note that this return is not followed by an expression

# Calling the function in the Python shell appears 
# to not return anything at all.
>>> square_a_number(2)
>>>


# Using print() with the function call shows that 
# the function is actually returning the **None** object.
>>> print(square_a_number(2))
None
```

Les fonctions qui omettent `return` renvoient elles aussi _implicitement_ l'objet [`None`][none].
Cela signifie que si tu n'utilises pas `return` dans une fonction, Python renverra l'objet `None` pour toi.

```python
# This function omits a return keyword altogether.
def add_two_numbers(number_one, number_two):
  result = number_one + number_two

>>> add_two_numbers(5, 7)
>>> print(add_two_numbers(5, 7))
None

# Assigning the function call to a variable and printing 
# the variable will also show None.
>>> sum_without_return = add_two_numbers(5, 6)
>>> print(sum_without_return)
None
```


## Commentaires

Les [commentaires][comments] en Python commencent par un `#` qui ne fait pas partie d'une _string_, et se terminent à la fin de la ligne.
Contrairement à beaucoup d'autres langages de programmation, Python **ne prend pas en charge** les marques de commentaire sur plusieurs lignes.
Chaque ligne d'un bloc de commentaire doit commencer par le caractère `#`.


## Docstrings

La première instruction du corps d'une fonction peut éventuellement être une [_docstring_][docstring], qui résume de façon concise le but de la fonction ou de l'objet.
Les docstrings sont lues par des outils de documentation automatisés comme [Sphinx][sphinx] et sont renvoyées en appelant l'attribut spécial `.__doc__` sur le nom de la fonction, de la méthode ou de la classe.
Les conventions générales sur les docstrings sont décrites dans la [PEP257][pep257], mais les formats exacts varient selon le projet et l'équipe.
Les docstrings se déclarent à l'aide de triples guillemets doubles (""") indentés au même niveau que le bloc de code :


