# Introduction

## JSON

### JSON

JSON (JavaScript Object Notation) est un format de données et de fichiers lisible par un humain, couramment utilisé pour échanger des données, en particulier dans les applications web.
Il n'est donc pas étonnant qu'il occupe une place à part dans le langage Elm.

Elm fournit les modules de base `Json.Decode` et `Json.Encode` pour analyser et écrire des données JSON.
Les décodeurs JSON permettent de _déclarer_ le type de données attendu et la structure de données vers laquelle ces données doivent être converties.

Importons quelques alias et types depuis les modules :

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Utiliser `Decode.decodeString : Decoder a -> String -> Result Error a` avec un décodeur et une _string_ JSON réussit si cette _string_ est conforme aux spécifications du décodeur, et échoue sinon.
Il n'y a aucun moyen d'inspecter les données JSON brutes au moment de définir le décodeur, ce qui peut paraître inhabituel quand on vient de langages impératifs.

### Décodeurs de types de base

JSON possède un petit nombre de types de données fondamentaux :

- _string_ : encodé entre guillemets doubles `"hello world"`
- booléen : soit `true`, soit `false`
- nombre : comme `34` ou `0.12`
- null : l'absence de données `null`

Chacun d'entre eux est associé à une fonction de `Decode` :

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Note que `Decode.null` permet de choisir comment modéliser un `null` dans ton programme, en exigeant une valeur arbitraire en argument (par exemple `()`, `Nothing`, ou toute valeur adaptée à ton programme).

### Combiner les décodeurs

JSON définit également deux structures de données pour regrouper les types de base :

- Tableau : une collection d'autres valeurs `[0, null, "none", []]`
- Objet : une collection de paires clé-valeur `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` propose aussi des fonctions pour les décoder :

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Ces fonctions `Decode.list : Decoder a -> Decoder (List a)` et `Decode.dict : Decoder a -> Decoder (Dict String a)` attendent chacune un décodeur en argument, censé décoder chaque élément de la structure de données.
Si le décodeur passé en argument ne parvient pas à décoder un seul élément d'un tableau ou d'un objet, c'est le décodeur entier qui échoue, ce qui est un schéma courant.

Combiner des décodeurs simples en décodeurs plus complexes est l'idée centrale de cette technique.
On va présenter, à travers un exemple, plusieurs autres fonctions qui permettent de construire des décodeurs de données réelles arbitrairement complexes.

### GeoJSON

Pour nous entraîner à combiner des décodeurs de base afin d'analyser des données JSON complexes, construisons des décodeurs pour analyser (un sous-ensemble de) données GeoJSON.
GeoJSON est un format de données spécialisé basé sur JSON, utilisé pour représenter des objets géographiques tels que des lieux, des tracés ou des régions, décrits par des coordonnées géographiques en 2D ou 3D, accompagnées d'autres propriétés.

#### Objet géométrique

Un objet géométrique GeoJSON est un objet qui contient un champ `type` dont la valeur est une _string_ (il y a 7 valeurs de type possibles) et un champ `coordinates` contenant des coordonnées géographiques (rassemblées dans une structure qui dépend du type).
Par exemple,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

ou

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Un objet géométrique pourrait être représenté en Elm par le type suivant :

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Pour examiner la valeur d'un champ donné, on peut utiliser `Decode.field : String -> Decoder a -> Decoder a`, qui décode la valeur d'une clé précise d'un objet.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Pour transformer la valeur correctement analysée par un décodeur, on peut utiliser `Decode.map : (a -> value) -> Decoder a -> Decoder value`, ou l'une de ses variantes, de `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` à `Decode.map8`.

Dans ce cas, on veut choisir le décodeur de coordonnées à utiliser en fonction de la valeur du champ `type` : c'est exactement le rôle de `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b`, accompagné de ses acolytes `Decode.succeed : a -> Decoder a` et `Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

Note à ce stade qu'on pourrait utiliser `Decode.andThen` pour valider les coordonnées (vérifier qu'elles vont par paires ou par triplets et que leurs valeurs ont un sens géographique).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

#### Objet Feature

Un objet Feature GeoJSON représente quelque chose de délimité dans l'espace : il possède un champ `type` valant `"Feature"`, un champ `geometry` contenant un objet géométrique ou `null`, un champ `properties` contenant un objet JSON arbitraire ou `null`, et un champ `id` facultatif dont la valeur est une _string_ ou un nombre JSON.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

ou

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Commençons par le champ `id`.
S'il est présent, il doit pouvoir contenir aussi bien des _strings_ que des nombres ; on peut donc soit introduire un type personnalisé pour cette valeur, soit toujours l'enregistrer sous forme de _string_.

Pour choisir entre deux décodeurs possibles, on peut utiliser `Decode.oneOf : List (Decoder a) -> Decoder a`.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Pour exprimer que le champ est facultatif, on pourrait utiliser la même technique :

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Mais on peut aussi utiliser `Decode.maybe : Decoder a -> Decoder (Maybe a)` :

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Note que `decodeMaybeFeatureId` (ou tout décodeur enveloppé avec `Decode.maybe`) réussit toujours, puisqu'il peut toujours se rabattre sur `Ok Nothing`, même si un décodeur qui l'utilise peut encore échouer :

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

Intéressons-nous maintenant au champ `geometry`, qui peut être soit un objet géométrique, soit `null`.
On pourrait de nouveau utiliser `Decode.oneOf`, mais il existe une meilleure option : `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` et `Decode.nullable` ont la même signature, mais leur comportement diffère : le résultat `OK Nothing` d'un `Decode.nullable` ne peut provenir que de la valeur JSON `null`.

Enfin, le champ `properties` peut contenir un objet JSON arbitraire ou `null`, ce qui est le rôle de `Decode.value : Decoder Value`.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Note que `Value` est un type opaque, ce qui veut dire qu'on ne peut pas facilement inspecter son contenu.
Pour l'utiliser, on peut soit écrire un décodeur et l'exécuter avec `Decode.decodeValue : Decoder a -> Value -> Result Error a`, soit l'envoyer directement à JavaScript via un port.

On est prêt à analyser des objets Feature :

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

### Encodeurs JSON

Les encodeurs permettent d'écrire du JSON valide à partir de valeurs Elm, grâce à la fonction `Encode.encode : Int -> Value -> String`.
Le premier argument indique la quantité d'indentation du résultat final, et le second est la valeur JSON à écrire.

Une `Value` peut être obtenue à partir de `Decode.value` ou produite par l'un des encodeurs :

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

ainsi qu'avec `Encode.object : List ( String, Value ) -> Value` :

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Définissons maintenant les encodeurs correspondant aux décodeurs GeoJSON définis plus haut :

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

En général, un bon moyen de tester un couple décodeur-encodeur consiste à vérifier que `elmValue |> encoder |> decoder == elmValue`.
