# Contrats

Les arguments et le type de retour d'une routine indiquent quel *genre* de chose entre et ressort. Ils ne peuvent pas dire qu'un poids doit être positif, ni qu'un harnais ne signale jamais plus de capacité disponible qu'il n'en possède.

Un **contrat** dit ces choses, dans l'en-tête même de la routine, là où quiconque la lit les verra.

## pre

`pre` énonce ce qui doit être vrai quand la routine est appelée. Il se place entre le type de retour et le `is`.

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

C'est une exigence vis-à-vis de l'**appelant** : il ne faut pas appeler cette routine avec une charge négative.

## post

`post` énonce ce qui sera vrai quand la routine répond. À l'intérieur, `result` est la valeur renvoyée.

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

C'est une promesse faite à l'appelant. Une routine qui réunit les deux est un marché : donne-moi ceci, et je te donnerai cela.

Plusieurs conditions se combinent avec `and`, comme n'importe quels booléens :

```sather
      pre load >= 0 and load <= limit
```

## Les contrats ne sont pas des exceptions

Une exception levée sert à signaler quelque chose qui peut arriver. Un contrat rompu signifie qu'il y a un **bug** : quelqu'un a appelé la routine de travers, ou la routine n'a pas fait ce qu'elle avait annoncé.

Un contrat rompu ne lève donc pas quelque chose que l'on peut intercepter. Quand la vérification des contrats est activée, le programme s'arrête et indique quelle routine et quelle condition sont en cause. Quand elle est désactivée, la condition n'est même pas testée, et le programme poursuit son exécution vers les absurdités qui s'ensuivent.

C'est pourquoi un contrat est une assertion sur la correction du programme plutôt qu'une façon de gérer une entrée incorrecte. Si l'on s'attend à une entrée incorrecte, vérifie-la et fais un `raise`. Si une entrée incorrecte signifie que l'appelant a fait une erreur, dis-le avec `pre`.

## Active la vérification des contrats

Ce Sather vérifie les contrats quand on passe `-chk` au compilateur :

```
sacomp -chk mine.sa -main MAIN -o mine
```

Sans cette option, `pre` et `post` ne sont qu'une documentation que le compilateur a lue et jugée bien formée, rien de plus. Les tests de cet exercice sont compilés sans `-chk`, ils ne peuvent donc pas détecter un contrat rompu à ta place ; ils vérifient que les routines font ce qu'il faut quand on les utilise correctement.
