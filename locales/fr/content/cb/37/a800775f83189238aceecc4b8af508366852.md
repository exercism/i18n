# À propos

Les types intégrés de Swift posent un certain nombre de problèmes lorsqu'on les utilise pour modéliser quelque chose qui peut prendre un nombre modéré d'états ou de valeurs possibles, comme les 63 codes de statut HTTP officiels ou les 8 boutons de la manette NES.

Par exemple, on peut essayer d'utiliser des types existants comme les _strings_ ou les entiers pour représenter ces valeurs, un peu comme on l'a fait pour les codes de statut HTTP, mais cela pose plusieurs problèmes. Le premier est que, même si un ordinateur traite sans difficulté des valeurs valides comme 103, 226 et 505, le programme lui-même doit sans cesse vérifier qu'il ne reçoit pas de valeurs invalides comme 213, 427, 512 ou 601. Dans le même temps, c'est au _programmeur_ qu'il incombe de s'assurer que chaque valeur valide est bien vérifiée lorsqu'on examine un code pour agir en conséquence, afin qu'aucun code valide ne soit oublié.

Un autre problème est la perte du sens sémantique. Une personne qui lit (ou écrit) un programme peut avoir du mal à se rappeler que les valeurs 103, 226 et 505 correspondent à « Early Hints », « IM Used » et « HTTP Version Not Supported ». De même, on pourrait modéliser un interrupteur avec un `Bool`, puisque les deux n'ont que deux états, mais que représente `true` pour l'interrupteur : cela signifie-t-il que l'interrupteur est ouvert ou qu'il est fermé ?

On pourrait atténuer ce problème en utilisant une _string_ pour représenter la version textuelle du code de statut ou de l'état de l'interrupteur, mais cela peut provoquer des erreurs lorsqu'on essaie de comparer un code de statut entrant à « HTTP Version not Supoorted » au lieu du « HTTP Version not Supported » attendu. Ces erreurs sont fréquentes et difficiles à localiser.

Pour résoudre ce problème, Swift, comme beaucoup de langages modernes, propose une fonctionnalité de langage qu'il appelle [_énumérations_][enumerations], ou _enums_ en abrégé.

Les énumérations en Swift sont un mécanisme qui permet de créer de nouveaux types, habités par un nombre fini de valeurs nommées, lesquelles peuvent porter des informations associées supplémentaires, et dont l'usage peut être vérifié à la compilation pour en garantir l'exhaustivité et l'exactitude. De plus, on peut attacher des propriétés et des méthodes aux énumérations, ce qui fournit des informations et des fonctionnalités supplémentaires en fonction de la valeur courante de l'énumération.

## Définir des énumérations

Les énumérations les plus simples se définissent en Swift avec le mot-clé `enum`, suivi du nom du type, puis du corps de l'énumération entre accolades, qui contient la liste des valeurs de l'énumération, introduites par le mot-clé `case`. Conformément au [guide de style Swift][api-design-guidelines], le nom du type doit être en UpperCamelCase et les valeurs en lowerCamelCase.

```swift
enum NESButton {
  case up
  case down
  case left
  case right
  case a
  case b
  case select
  case start
}
```

Pour aller plus vite, on peut aussi écrire plusieurs cas sur une seule ligne, séparés par des virgules, avec un seul mot-clé `case`.

```swift
enum NESButton {
  case up, down, left, right, a, b, select, start
}
```

Cela définit un nouveau type nommé `NESButton`, dont les valeurs possibles sont `up`, `down`, `left`, `right`, `a`, `b`, `select` et `start`. Pour désigner ces valeurs, on fait suivre le nom du type d'un point (`.`) et de la valeur. Lorsque le nom du type peut être déduit, seuls le point et la valeur sont nécessaires. Ces valeurs s'utilisent ensuite comme n'importe quelle autre valeur en Swift.

```swift
var lastPressed = NESButton.up

// Now that the type of lastPressed is set as NESButton
lastPressed = .down

let konamiCode = [NESButton.up, .up, .down, .down, .left, .right, .left, .right, .b, .a]
```

Remarque : comme tous les éléments d'un tableau doivent être du même type, il suffit de préciser le nom du type pour l'un des éléments ; pour les autres, les valeurs seules suffisent. Le nom du type ne serait nécessaire pour aucun d'entre eux si la constante était annotée avec le bon type, par exemple `let konamiCode: [NESButton] = …`.

## Énumérations et instructions `switch`

Les énumérations sont souvent utilisées [avec les instructions `switch`][enums-and-switches], qui servent à déterminer l'action à mener en fonction de la valeur de l'énumération.

```swift
lastPressed = .left
switch lastPressed {
case .up: print("You pressed the UP button")
case .down: print("You pressed the DOWN button")
case .left: print("You pressed the LEFT button")
case .right: print("You pressed the RIGHT button")
case .a: print("You pressed the A button")
case .b: print("You pressed the B button")
case .select: print("You pressed the SELECT button")
case .start: print("You pressed the START button")
}

// prints "You pressed the LEFT button"
```

Comme les instructions `switch` doivent être exhaustives, le compilateur t'avertit si tous les cas ne sont pas couverts.

```swift
switch lastPressed {
case .up, .down, .left, .right:
  print("You pressed a direction button.")
}
// Error: Switch must be exhaustive
```

C'est particulièrement utile lorsqu'on ajoute des cas à une énumération au fil de l'évolution d'un programme. Le compilateur peut alors signaler tous les endroits où une instruction `switch` non exhaustive doit être mise à jour pour inclure le nouveau cas.

Note qu'on peut corriger l'erreur ci-dessus en utilisant un cas `default` dans le `switch`.

```swift
lastPressed = .select
switch lastPressed {
case .up, .down, .left, .right:
  print("You pressed a direction button.")
default:
  print("You pressed a non-direction button.")
}
// prints: "You pressed a non-directional button."
```

Cependant, cela rend automatiquement n'importe quel `switch` exhaustif : si l'on ajoutait par exemple des cas de direction diagonale, comme `.upAndLeft`, à l'énumération, on ne saurait pas qu'il faut mettre à jour ce `switch` et on nous dirait à tort qu'un bouton non directionnel a été pressé. Pour éviter cela, il vaut mieux lister explicitement tous les cas quand c'est possible.

```swift
lastPressed = .select
switch lastPressed {
case .up, .down, .left, .right:
  print("You pressed a direction button.")
case .a, .b, .select, .start:
  print("You pressed a non-direction button.")
}
// prints: "You pressed a non-directional button."
```

Comme le compilateur connaît toutes les valeurs possibles d'une énumération, il peut aussi détecter des erreurs comme les fautes de frappe qui se glissent dans les programmes où l'on utilise des _strings_ pour représenter des valeurs.

```swift
lastPressed = .selcet
// Error: Type 'NESButton' has no member 'selcet'
```

## Méthodes

Comme les autres types en Swift, les énumérations peuvent contenir des méthodes, qui permettent à l'énumération d'offrir des fonctionnalités fondées sur sa valeur courante.

Les méthodes sont analogues aux fonctions, si ce n'est qu'elles sont définies à l'intérieur du corps de l'énumération et qu'elles sont liées à la valeur courante de l'énumération. On y accède par _notation pointée_ : on fait suivre le nom de la valeur de l'énumération d'un point (`.`), puis du nom de la méthode et de ses paramètres.

À l'intérieur de la méthode, la valeur de l'énumération peut être désignée par `self` et, dans la signature du type, on peut désigner le type par `Self` lorsqu'on accepte en paramètre ou qu'on renvoie une valeur de l'énumération.

### Initialiseurs

Les initialiseurs sont des méthodes spéciales qui servent à créer une valeur de l'énumération. Leur définition ressemble beaucoup à celle d'une méthode, à ceci près qu'il n'y a pas de mot-clé `func`, pas de type de retour, et que le nom doit être `init` et que l'initialiseur _doit_ affecter une valeur de l'énumération à `self`. On appelle un initialiseur soit par notation pointée, soit en passant les paramètres de l'initialiseur au nom de l'énumération.

Les énumérations peuvent aussi avoir des initialiseurs pouvant échouer, qui renvoient des valeurs optionnelles de l'énumération. On les utilise lorsqu'il peut ne pas y avoir de valeur valide vers laquelle initialiser, compte tenu de l'entrée de l'initialiseur, et que c'est `nil` qui peut être affecté à `self` à la place. Dans ce cas, le nom de l'initialiseur s'écrit `init?`, mais le point d'interrogation disparaît lorsqu'on appelle l'initialiseur.

```swift
enum Coin {
  case heads
  case tails

  init(_ i: Int) {
    if i.isMultiple(of: 2) {
      self = .heads
    } else {
      self = .tails
    }
  }

  func flip() -> Self {
    switch self {
    case .heads: return .tails
    case .tails: return .heads
    }
  }
}

let tails = Coin.init(13)
// .tails
let heads = Coin(0)
// .heads
let anotherTails = heads.flip()
// .tails
```

### Valeurs brutes

Les énumérations peuvent aussi porter une valeur interne appelée [_valeur brute_][raw-values]. Toutes les valeurs brutes doivent être du même type, lequel est déclaré dans la définition de l'énumération. On pourrait donc affecter, par exemple, des valeurs de type Character à notre énumération `NESButton` en modifiant sa définition :

```swift
enum NESButton: Character {
  case up = "⬆️"
  case down = "⬇️"
  case left = "⬅️"
  case right = "➡️"
  case a = "🅰️"
  case b = "🅱️"
  case select = "✅"
  case start = "🚦"
}
```

Ici, `: Character` indique au compilateur que les valeurs brutes seront de type `Character`, et l'affectation de la valeur brute suit chaque valeur.

On peut accéder aux valeurs brutes via la propriété `rawValue` générée automatiquement pour chaque valeur.

```swift
NESButton.left.rawValue
// => "⬅️"
NESButton.b.rawValue
// => "🅱️"
```

Les valeurs brutes peuvent aussi servir à initialiser des valeurs du type de l'énumération. Note que la valeur de retour est un optionnel, car une valeur brute invalide peut être fournie.

```swift
let upButton = NESButton.init(rawValue: "⬆️")
// => Optional(.up)
let invalid = NESButton.init(rawValue: "🙄")
// => nil
```

Swift peut affecter implicitement des valeurs brutes pour les valeurs brutes de type `String` et `Int`. Si l'on précise un type de valeur brute `String`, la valeur brute est implicitement affectée au nom du cas, sous forme de String, sauf si la valeur implicite est remplacée par une affectation explicite.

Si l'on précise un type de valeur brute `Int`, la valeur brute est implicitement affectée à un entier supérieur de 1 à la valeur brute du cas précédent, sauf si elle est remplacée par une affectation explicite. Par défaut, la valeur brute du premier cas est 0, sauf indication contraire.

```swift
enum Coin: String {
  case heads
  case tails = "eagle"
}

Coin.head.rawValue
// => "heads"
Coin.tails.rawValue
// => "eagle"

enum Dwarf: Int {
  case grumpy, sleepy, sneezy, happy = 8, bashful, dopey, doc
}

Dwarf.grumpy.rawValue
// => 0
Dwarf.sneezy.rawValue
// => 2
Dwarf.happy.rawValue
// => 8
Dwarf.bashful.rawValue
// => 9
```

### Valeurs associées

Les énumérations en Swift peuvent aussi porter un autre type d'information appelé [_valeurs associées_][associated-values]. Avec les valeurs associées, chaque cas de l'énumération peut transporter une valeur d'un type différent, rattachée à la valeur de l'énumération. Les types des valeurs associées sont précisés dans la déclaration de l'énumération. Ces valeurs peuvent ensuite être extraites et utilisées par filtrage par motif.

```swift
enum Suit: Character {
  case diamonds = "♦️", clubs = "♣️", hearts = "♥️", spades = "♠️"

  func print() {
    switch self {
    case .ace(let suit): print("A\(suit.rawValue)")
    case .king(let suit): print("K\(suit.rawValue)")
    case .queen(let suit): print("Q\(suit.rawValue)")
    case .jack(let suit): print("J\(suit.rawValue)")
    case let .number(suit, value): print("\(value)\(suit.rawValue)")
    }
  }
}

enum Card {
  case ace(Suit), king(Suit), queen(Suit), jack(Suit)
  case number(Suit, Int)
}

let aceOfSpades = Card.ace(.spades)
let twoOfHearts = Card.number(.hearts, 2)

aceOfSpades.print()
// prints "A♠️"

twoOfHearts.print()
// prints "2♥️"
```

Note qu'une énumération peut avoir des valeurs brutes, ou des valeurs associées, ou ni l'une ni l'autre, mais jamais les deux à la fois.

### Énumérations récursives

Comme on l'a vu dans l'exemple précédent, le type associé au cas d'une énumération peut être n'importe quel type, y compris celui d'une énumération. Dans certains cas, on peut vouloir que le type d'une valeur associée soit le type de l'énumération qui contient ce cas. En Swift, on peut le faire en écrivant le mot-clé `indirect` devant chaque cas qui utilise ces [types associés récursifs][recursive-enumerations], ou en plaçant `indirect` devant le mot-clé `enum` devant le mot-clé `enum` pour rendre tous les cas de l'énumération indirects.

```swift
enum BinaryTree {
  case leaf(value: Int)
  indirect case node(left: BinaryTree, value: Int, right: BinaryTree)
}

enum BinaryTree {
  case leaf(value: Int)
  indirect case node(left: BinaryTree, value: Int, right: BinaryTree)
}

let tree: BinaryTree = .node(left: .leaf(value: 1), value: 3, right: .node(left: .leaf(value: 5), value: 6, right: .leaf(value: 9)))
```
