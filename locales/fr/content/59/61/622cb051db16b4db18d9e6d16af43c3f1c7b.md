# À propos

On a vu dans les concepts précédents que les types en Julia forment une hiérarchie, avec `Any` au sommet.

Les types abstraits comme `Number` ont des sous-types, mais ne peuvent pas être instanciés eux-mêmes.
Affecter à une variable un type abstrait _contraint_ les valeurs de cette variable à être un sous-type quelconque du type abstrait.
Par exemple :

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Cela nous donne une forme de souplesse pour décider quelles entrées sont valides.

Mais imaginons que l'on veuille qu'une variable accepte à la fois des entiers et des _strings_ ?
Ces types ne se trouvent pas dans la même branche de la hiérarchie.

On pourrait donner le type [`Any`][any] à la variable, ou le laisser par défaut, mais on perdrait alors tout contrôle sur les types autorisés.

Pour une meilleure approche, on dispose de la syntaxe [`Union{ }`][union], qui liste deux types ou plus entre les accolades.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Un autre exemple utilise la même union de types dans la signature d'une fonction :

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

Ici, on a donné un nom au type, ce qui peut servir de raccourci pratique, mais ce n'est pas strictement nécessaire.
La fonction `g(z::Union{Integer, String}) = z^3` se comporte de la même manière.

On aura bien plus à dire sur les signatures de fonctions dans le concept de dispatch multiple.

## Les unions avec `nothing`

Plusieurs autres langages proposent des types qui peuvent contenir une valeur ou non, sous des noms comme `Option`, `Nullable` ou `Maybe`.

Julia n'a pas de syntaxe spécifique pour cela, mais les unions de types généralisent la même idée.

On a vu dans le concept [`Nothingness`][nothingness] que Julia dispose de plusieurs façons de représenter l'absence de valeur, notamment [`nothing`][nothing] et [`missing`][missing].
L'une ou l'autre peut être incluse dans une union de types.

Par exemple, pour définir une sorte de [liste chaînée][linked], on a besoin d'un moyen de terminer la liste quand il n'y a plus de nœuds.
`Nothing` est le type dont l'unique valeur est `nothing`, et cette définition de `Node` permet de signaler la fin de la chaîne :

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

De même, `missing` peut servir de valeur de remplacement pour des valeurs absentes, en particulier dans des collections comme les vecteurs.
L'exemple ci-dessous est très artificiel, mais les valeurs absentes sont courantes dans les jeux de données réels.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
