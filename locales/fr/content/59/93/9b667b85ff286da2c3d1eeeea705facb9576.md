# À propos

Les [_records_][records] sont des structures de données qui rassemblent des informations liées entre elles, accompagnées d'étiquettes. Ils sont semblables aux objets de JavaScript ou Java, ou aux structures du C ou du Rust, mais avec quelques différences importantes.

## Crée des _records_

Pour [créer][create] un _record_, on utilise des accolades, et ses éléments sont séparés par des virgules.

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Le type d'un _record_ se définit lui aussi avec une syntaxe similaire, sauf que les signes égal `=` sont remplacés par des deux-points `:`.

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Répéter ces définitions de type est fastidieux, c'est pourquoi il est courant d'utiliser un [alias de type][record-types] pour partager la définition.

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

L'alias de type fournit aussi automatiquement une fonction constructeur pour le _record_. Cela surprend parfois, étant donné qu'en Elm les fonctions doivent commencer par une minuscule, mais les constructeurs de type font exception.

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

## Accède aux champs d'un _record_

La principale façon d'[accéder à la valeur d'un champ d'une instance de _record_][access] est d'utiliser la notation pointée, comme `firefly.creator`. Le compilateur Elm prend aussi en charge des fonctions d'accès spéciales qui commencent par un point `.`, comme `.creator`, et qui fonctionnent sur tout _record_ possédant un champ de ce nom. C'est la deuxième exception à la règle selon laquelle les fonctions doivent commencer par une minuscule. En fait, les fonctions définies par l'utilisateur doivent commencer par une minuscule, mais les deux exemples que l'on vient de découvrir sont générés par le compilateur, pas par le programmeur.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

On peut aussi _déstructurer_ des _records_ dans des liaisons, en utilisant le [filtrage par motif sur les _records_][pattern-matching]. La déstructuration fonctionne avec tout _record_ qui possède des champs portant les noms voulus.

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

## Mets à jour des _records_

Les _records_ sont immuables, comme tout le reste en Elm, donc une fois qu'un _record_ est défini, les valeurs de ses champs ne peuvent plus jamais changer. Il existe une [syntaxe spéciale pour créer une copie d'un _record_ existant en modifiant un ou plusieurs de ses champs][update]. Cette syntaxe utilise le symbole barre verticale `|` pour distinguer le _record_ d'origine et les champs qui vont changer, comme dans `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

## Compare des _records_

Elm utilise l'[égalité structurelle][equality], ce qui signifie que deux instances du même _record_ avec des valeurs identiques sont égales.

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

## _Records_ extensibles

Elm prend aussi en charge le [typage structurel][structural-typing], ce qui signifie que si une fonction attend un _record_ avec un champ x et un champ y, elle fonctionnera avec n'importe quel _record_ possédant ces champs, comme des points 2D, des points 3D, des vaisseaux spatiaux, etc. Ces types de _records_ comportent une barre verticale `|` dans leur définition, comme `{ a | x : Float, y : Float }`, et sont appelés « _records_ extensibles » dans la terminologie d'Elm. Attention à la différence entre une barre verticale `|` dans une définition de type, qui est une définition de _record_ extensible (`{ a | x : Int }`), et une barre verticale `|` dans une instance de _record_ concrète, qui signifie que l'on met à jour certains champs de ce _record_.

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
