# Introduction

## Égalité

Les types simples (_strings_ et primitives) sont généralement testés pour l'égalité à l'aide de `==` et `!=`.

Les types référence (instances de classes) sont comparés à l'aide de la méthode `Equals()` héritée de `Object`. Si l'objectif du test d'égalité est de s'assurer que deux objets sont exactement la même instance, alors s'appuyer sur l'implémentation d'`Object` suffira. Sinon, il faut redéfinir `object.Equals()`.

Si on sait que toutes les instances de la classe sont créées au même endroit, par exemple des personnages dans un jeu ou une simulation, alors l'égalité de référence suffit. Cependant, il est probable que plusieurs instances de la même entité du monde réel soient créées (à partir d'une base de données, par saisie utilisateur, via une requête web). Dans ce cas, les valeurs qui identifient de manière unique l'entité doivent être testées pour l'égalité. Par conséquent, `Equals()` doit être redéfinie et les membres de données appropriés de la classe doivent être testés pour l'égalité.

Une méthode `Equals()` redéfinie contiendra des tests d'égalité sur les membres de types simples à l'aide de `==` et sur les types référence avec des appels récursifs à `Equals()`.

La classe `Object` fournit des méthodes appropriées pour comparer deux objets et détecter s'ils sont une seule et même instance.

### `Object.GetHashCode()`

La méthode `Object.GetHashCode()` renvoie un code de hachage sous la forme d'un entier 32 bits.

Le code de hachage est utilisé par les classes _dictionnaire_ et _ensemble_ telles que `Dictionary<T>` et `HashSet<T>` pour stocker et récupérer des objets de manière performante.

La relation entre le code de hachage et l'égalité est que si deux objets sont égaux (`Equal()` renvoie _true_) alors `GetHashCode()` pour les deux objets doit renvoyer la même valeur. Cela ne s'applique pas dans la direction inverse. Ce n'est pas symétrique. Ce n'est pas parce que deux objets ont le même code de hachage qu'ils doivent être égaux. Imagine une fonction de recherche qui se rend d'abord dans un «\u00A0compartiment\u00A0» en fonction du code de hachage, puis sélectionne l'élément particulier à l'aide du test d'égalité.

La documentation de l'API de la bibliothèque HashCode traite de la meilleure façon de générer un code de hachage.

Les valeurs utilisées dans le test d'égalité doivent être stables pendant que la collection hachée est utilisée. Si on ajoute un objet à la collection avec un ensemble de valeurs, puis qu'on modifie ces valeurs, le code de hachage ne pointera plus vers le bon «\u00A0compartiment\u00A0». En pratique, cela signifie que l'objet doit être immuable. D'autres approches risquent de créer des pièges pour les mainteneurs.

## Ensembles

Un ensemble est une collection de valeurs uniques. L'implémentation .NET par défaut d'un ensemble est la classe `HashSet<T>`, qui est une collection ne contenant que des valeurs uniques.
