# Pour les mainteneurs

## Génère les tests : `bin/generate_tests.py`

Les fichiers de test sont générés à partir des données canoniques de
[exercism/problem-specifications](https://github.com/exercism/problem-specifications)
à l'aide d'un _template_ Jinja stocké dans chaque exercice dans `.meta/template.j2`.

```bash
bin/generate_tests.py bob            # regenerate one exercise
bin/generate_tests.py                # regenerate every exercise that has a template
bin/generate_tests.py --no-pull bob  # skip `git pull` of problem-specifications
```

Le script lit problem-specifications depuis le cache de configlet
(`~/.cache/exercism/configlet/problem-specifications`, rempli par `bin/configlet sync`),
ou depuis un répertoire parent nommé `problem-specifications`.
Seuls les cas inclus dans `.meta/tests.toml` sont générés.

Les littéraux de chaîne Fortran ne peuvent pas contenir de séquences d'échappement comme `\n` et `\t`.
Le filtre de _template_ `escape_quote_whitespace` les réécrit sous la forme
`" // NEWLINE // "`, `" // TAB // "` et `" // CARRIAGE_RETURN // "`,
le _template_ doit donc déclarer ces constantes (voir `exercises/practice/bob/.meta/template.j2`).

### Prérequis

- CMake et un compilateur Fortran fonctionnels
- Python 3.12+ avec `jinja2`
- git

### Workflow pour ajouter un nouvel exercice

En prenant `bob` comme exemple :

- Crée une nouvelle branche, par ex. `git checkout -b exercise-bob`
- Lance `bin/add-exercise bob` (nécessite `jq` et `curl`). Ce script :
  - récupère configlet et lance `configlet create`, ce qui ajoute l'exercice à `config.json` et synchronise ses docs, ses métadonnées et son `tests.toml` depuis problem-specifications
  - trie `config.json` avec `bin/reorder-exercises`
  - copie `exercises/shared/CMakeLists.txt` dans le répertoire de l'exercice
  - écrit une solution squelette, un `.meta/example.f90` squelette et un `.meta/template.j2` de départ (à partir de `exercises/shared/template.j2`)

  Il te demande ton nom d'utilisateur GitHub sauf si tu passes `-a <username>`, et fixe la difficulté à 1 sauf si tu passes `-d <difficulty>`.

- Modifie `.meta/template.j2` pour que chaque cas appelle la bonne fonction avec les bonnes entrées, puis génère les tests :

  ```bash
  bin/generate_tests.py bob
  ```

- Écris une solution qui fonctionne dans `.meta/example.f90`. Remplace le fichier de l'apprenant (par ex. `bob.f90`) par un squelette des fonctions ou sous-routines appelées par les tests, pour aider l'apprenant à démarrer
- Vérifie que tous les tests passent, en lançant la compilation complète depuis la racine du dépôt :

  ```bash
  mkdir -p build && cd build
  cmake ..
  cmake --build .
  ctest -V -R bob
  ```

- Lance `bin/reorder-exercises` et `bin/configlet lint`
- Si tout passe, ouvre une pull request avec tes modifications

### Modifie `CMakeLists.txt`

Quand tu modifies le fichier cmake, mets à jour la copie principale dans `exercises/shared/` et utilise `bin/update-cmake-files` pour la copier dans tous les répertoires d'exercices.
