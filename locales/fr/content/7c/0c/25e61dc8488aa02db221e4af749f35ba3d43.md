# Introduction

## Ajoute du contexte aux erreurs

On a exploré la gestion de base des erreurs en Go dans le [concept des erreurs][concept-errors].
Comme tu l'as appris, par défaut, les erreurs ne transportent pas de traces de pile.
Il est donc crucial de s'assurer que l'erreur elle-même contient suffisamment d'informations pour identifier le problème.

Si on voulait ajouter des informations à une erreur existante avec les outils que l'on connaît déjà, on pourrait écrire quelque chose comme ceci pour créer une nouvelle erreur avec le texte combiné de l'erreur d'origine et des informations supplémentaires :

```go
err := errors.New(fmt.Sprintf("parsing age for user %d: %v", userID, originalError))
```

Heureusement, le paquet `fmt` de la bibliothèque standard contient une version raccourcie de cela sous la forme de la fonction `Errorf`.
Cela te permet, par exemple, d'ajouter facilement des informations sur le contexte dans lequel l'erreur s'est produite.

```go
originalError := errors.New("unexpected negative number")
userID := 123
err := fmt.Errorf("parsing age for user %d: %v", userID, originalError)
err.Error()
// => "parsing age for user 123: unexpected negative number"
```

Souvent, cette façon d'ajouter des informations à une erreur est suffisante, mais il y a des cas où tu veux permettre au consommateur de ton erreur de vérifier ou de récupérer l'erreur sous-jacente d'origine.
Ajouter du contexte d'une manière qui permet cela s'appelle « envelopper une erreur » en Go.

## Enveloppe les erreurs et vérifie les erreurs sentinelles

L'enveloppement d'erreurs peut se faire avec un changement très mineur dans le code que l'on a vu ci-dessus.
Pour envelopper une erreur, tu dois utiliser le verbe de formatage `%w` au lieu de `%v`.
En coulisses, cela fera en sorte que l'erreur résultante implémente une méthode `Unwrap` qui renvoie l'erreur d'origine.
C'est pourquoi on peut utiliser `errors.Is` pour vérifier si une erreur sentinelle spécifique apparaît quelque part dans la « chaîne d'erreurs ».
Elle le fait en appelant discrètement `Unwrap` à plusieurs reprises jusqu'à ce que l'erreur en question soit trouvée ou que la chaîne se termine.

```go
originalError := errors.New("unexpected negative number")
err := fmt.Errorf("parsing age: %w", originalError)
errors.Is(err, originalError)
// => true
```

C'est une bonne pratique d'utiliser `%v` par défaut et de n'utiliser `%w` que si tu veux explicitement permettre à ton consommateur d'accéder à une erreur sous-jacente ([Guide de style Go de Google][google-go-styleguide]).

Si tu te trouves dans une situation où tu veux vérifier une erreur sentinelle mais que tu ne veux explicitement pas la déballer, tu peux utiliser `==` au lieu de `errors.Is`.

```go
var originalError = errors.New("unexpected negative number")
func someFunc() error {
  return originalError
}

err := someFunc()
err == originalError 
// => true
```

Il est acceptable de travailler avec `errors.Is` par défaut, mais tu dois toujours être conscient que cela signifie que toute la chaîne d'erreurs sera parcourue.

## Vérifie les types d'erreurs (personnalisés)

Il existe un équivalent à `errors.Is` qui permet de vérifier et de récupérer une erreur d'un type spécifique dans la chaîne d'erreurs.
La fonction pour cela est `errors.As` et, tout comme `errors.Is`, elle recherchera le type d'erreur donné dans toute la chaîne.
`errors.As` n'extrait l'erreur correspondant au type que si elle la trouve dans la chaîne, ce qui te permet ensuite de travailler avec elle, par exemple pour récupérer des champs spécifiques.

```go
type MyCustomError struct {
  Message string
  Details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.Message, e.Details)
}

func someFunc() error {
  originalError := &MyCustomError{
    Message: "some message",
    Details: "some details",
  }

  return fmt.Errorf("doing something: %w", originalError)
}

err := someFunc()
var customError *MyCustomError
errors.As(err, &customError)
// => true

// customError now contains the error that was found in the error chain.
customError.Details
// => "some details"
```

~~~~exercism/caution
Fais attention à la syntaxe concernant les pointeurs ci-dessus.
Le code ne fonctionnera et ne se compilera correctement que si `customError` a exactement le type qui implémente l'interface d'erreur.
Dans notre cas, c'est `*MyCustomError` (un [pointeur][concept-pointers] vers `MyCustomError`), et non `MyCustomError` lui-même.

De plus, le deuxième argument doit être un pointeur vers la variable d'erreur.
Comme notre erreur est déjà un pointeur, ce que l'on passe à `errors.As` est un pointeur vers un pointeur (vers MyCustomError).
Ce n'est qu'avec cette configuration correcte que Go peut ensuite remplir la variable avec l'erreur qu'il a trouvée.
~~~~

Comme précédemment, `errors.As` n'aurait pas trouvé le type d'erreur si `%v` avait été utilisé lors de l'appel à `Errorf`.

Si tu ne veux pas déballer pour une raison quelconque, tu peux utiliser une assertion de type à la place (équivalent à `==` ci-dessus).

```go
// MyCustomError defined as above.

func someFunc() error {
  return &MyCustomError{
    Message: "some message",
    Details: "some details",
  }
}

err := someFunc()
customError, ok := err.(*CustomError)
// "ok" is now true
customError.Details
// => "some details"
```

L'assertion de type ne pourra pas identifier le type d'erreur si l'erreur a été enveloppée.

## Permets le déballage des erreurs de types personnalisés

Parfois, il ne suffit pas d'envelopper une erreur avec du texte supplémentaire.
Tu peux à la place créer un type d'erreur personnalisé qui contient l'erreur d'origine et les données structurées supplémentaires que tu veux ajouter.
Si tu veux permettre le déballage pour ton type d'erreur, la seule chose à faire est d'ajouter manuellement une méthode `Unwrap() error` pour que l'interface `Unwrap` soit satisfaite.

```go
type SpecialError struct {
  originalError error
  metadata string
}

func (e *SpecialError) Error() string {
  // The usual serialization code goes here.
}

func (e *SpecialError) Unwrap() error {
  return e.originalError
}
```
