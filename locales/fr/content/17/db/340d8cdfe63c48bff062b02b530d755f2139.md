# À propos

Common Lisp met à la disposition du programmeur plusieurs conditionnelles différentes, que l'on peut classer selon le nombre de « branches » qu'elles prennent en charge.

De plus, contrairement à beaucoup d'autres langages de programmation, toutes les conditionnelles de Common Lisp sont des _expressions_ et non des instructions.
Cela signifie que toutes les conditionnelles Lisp s'évaluent en une valeur et peuvent remplacer des paramètres concrets.

Par exemple :

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## Les conditionnelles à une seule branche

Les conditionnelles `when` et `unless` n'évaluent du code que lorsque le test fourni est respectivement vrai ou faux ; dans le cas contraire, elles s'évaluent en `nil`.

La section qui suit l'expression de test peut contenir plus d'une expression.

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## La conditionnelle à deux branches

La conditionnelle `if` évalue la première expression du corps lorsque le test est vrai, et la seconde dans le cas contraire.

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

À noter que la clause « alors » comme la clause « sinon » ne peuvent contenir qu'une seule expression.

## Les conditionnelles à branches multiples

La « super-conditionnelle » de Lisp est `cond`, qui peut avoir un nombre infini de branches.
Chaque branche comporte une condition de test et une expression de corps, que l'on entoure d'une paire de parenthèses supplémentaire.
Si tous les tests s'évaluent à faux, `nil` est renvoyé.

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

À noter qu'il n'y a pas de limite au nombre d'expressions qui suivent l'expression de test. 


Si tu veux simplement tester une valeur contre plusieurs branches, tu peux utiliser l'expression `case`, plus lisible.
Si aucune des clauses ne correspond, `nil` est renvoyé.
On peut utiliser aussi bien `t` que `otherwise` comme cas par défaut :

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

À noter que, comme pour `cond`, il n'y a pas de limite au nombre d'expressions qui suivent l'expression de test.

## Les conditionnelles déguisées

Les opérations booléennes `and` et `or` de Common Lisp sont des macros à court-circuit qui permettent de réduire la duplication de certaines expressions conditionnelles.

La macro `and` renvoie immédiatement `nil` dès qu'elle rencontre une seule valeur fausse ; sinon, elle renvoie la dernière valeur vraie :

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

La macro `or` renvoie la première valeur vraie qu'elle rencontre, ou `nil` s'il n'y a aucune valeur vraie :

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## Je suis épuisé...

Comme on l'a vu plus haut, lorsque aucune des branches d'une instruction `case` ne correspond, et qu'il n'y a pas de clause `otherwise`, `nil` est renvoyé.
Il arrive toutefois qu'une absence de correspondance avec n'importe quelle branche doive être traitée comme une erreur : c'est là qu'intervient `ecase` (pour une correspondance **exhaustive**).

Il s'utilise exactement de la même manière que `case`, mais signale une erreur au lieu de renvoyer `nil` lorsqu'il n'y a pas de correspondance.

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
