# Introduction

Quand on a plusieurs valeurs discrètes possibles sur lesquelles aiguiller, `case` (dans [`combinators`][combinators]) convient mieux qu'une chaîne de `if`.

## `case`

```
case ( obj assoc -- )
```

`case` prend la valeur au sommet de la pile et un *assoc* de clauses. Chaque clause s'écrit `{ value [ body ] }`. La première clause dont la valeur est égale à l'entrée (au sens de `=`) l'emporte ; son corps s'exécute alors que la valeur d'entrée est *déjà consommée*. Une entrée finale qui n'est qu'un `[ body ]` constitue le cas par défaut : l'entrée est *encore sur la pile* au moment où elle s'exécute.

```factor
USING: combinators ;

: name-of ( n -- s )
    {
        { 1 [ "one" ] }
        { 2 [ "two" ] }
        [ drop "many" ]
    } case ;
```

L'égalité se fait par `=`, donc tout ce qui se compare comme égal peut servir de clé : les nombres, les _strings_ et les symboles fonctionnent tous.

## `cond` pour les branches avec garde

Quand le choix dépend d'un *prédicat* plutôt que d'une égalité (par exemple `x > 11`), `cond` est l'outil adapté. Tu as rencontré `cond` dans [Voitures, rassemblez-vous !][cars-assemble].

## Symboles

Un `SYMBOL:` déclare un mot qui se pousse lui-même sur la pile : une valeur d'étiquette auto-évaluée. `SYMBOLS:` en déclare plusieurs d'un coup :

```factor
SYMBOLS: yes no maybe ;
```

Désormais, `yes` est une valeur, comparable avec `=`, que tu peux utiliser comme clé de `case` :

```factor
: invert ( ? -- ?' )
    { { yes [ no ] } { no [ yes ] } [ ] } case ;
```
