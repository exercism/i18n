# Introduction

Certaines boucles ne peuvent pas s'écrire comme « fais ceci pour chaque élément d'une séquence » : il faut continuer jusqu'à ce qu'une condition bascule. Le combinateur `while` de Factor est l'outil qu'il te faut pour ça : une _quotation_ prédicat qui demande « on continue ? », une _quotation_ corps qui effectue le travail d'une étape, et `while` répète jusqu'à ce que le prédicat renvoie `f`.

## `while` et `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` et `body` sont tous deux des _quotations_ qui opèrent sur la pile de données. `while` continue de boucler tant que `pred` laisse une valeur vraie ; `until` fait l'inverse : il continue de boucler *jusqu'à* ce que `pred` devienne vrai (autrement dit, tant que `pred` laisse `f`).

Une même valeur d'état peut circuler sur la pile entre le prédicat et le corps :

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

Déroulons le fil : le prédicat `dup 0 >` jette un œil au compteur en cours ; le corps `dup . 1 -` l'affiche puis le décrémente ; la boucle s'arrête dès que le compteur atteint `0`. Le `drop` final retire ce dernier `0` de la pile.

## `while*` — garder la valeur du prédicat

```
while* ( pred body -- )
```

`while` se contente de regarder si son prédicat a laissé une valeur vraie : il jette la valeur elle-même avant d'exécuter le corps. `while*`, lui, *transmet cette valeur au corps*. Utilise-le dès que le test et le corps veulent la même valeur fraîchement calculée : une recherche, une correspondance, un jeton analysé.

Ici, chaque nom pointe vers le suivant dans une chaîne. Le prédicat recherche le nom courant ; tant qu'il existe un nom suivant, `while*` le transmet au corps, qui l'affiche et repart de là :

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at` renvoie le nom suivant, ou `f` dès qu'un nom n'a pas d'entrée. Tant qu'il renvoie un nom, `while*` le donne à `dup .`, qui l'affiche et le laisse comme clé pour la recherche suivante. Le premier `f` arrête la boucle : `while*` le jette, donc il ne reste rien.

## Plusieurs valeurs d'état avec des variables locales

Quand la boucle transporte plus d'une valeur, par exemple une liste restante et un total cumulé, le jonglage avec la pile devient bruyant. Le motif le plus propre consiste à déclarer des *variables locales* avec `::` :

```
:: word ( inputs -- outputs ) ... ;
```

À l'intérieur du corps, `:> name!` ajoute une variable locale mutable ; les lectures utilisent `name`, les écritures utilisent `name!` (qui consomme la nouvelle valeur sur la pile et l'affecte).

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

Deux variables locales ici (`rest` et `running`) couvrent tout l'état de la boucle : le prédicat les inspecte, le corps les met à jour, et la valeur finale est renvoyée à la fin.

`unclip ( seq -- rest first )` détache le premier élément d'une séquence, ce qui est pratique quand la boucle veut consommer une liste élément par élément. La forme `[ rest! ] dip` met à jour `rest` avec la queue restante tout en laissant l'élément fraîchement dépilé sur la pile à la disposition du corps.
