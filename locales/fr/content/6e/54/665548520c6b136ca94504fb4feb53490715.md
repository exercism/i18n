# Introduction

Dans de nombreux langages orientés objet, il est courant d'étendre des comportements en [créant une sous-classe][wiki-subclass] d'une classe parente, en héritant des méthodes de la classe parente tout en en ajoutant de nouvelles.
On obtient ainsi une hiérarchie d'objets.

Julia _n'a pas de classes_, donc par extension, elle _n'a pas de sous-classes_.
Comment hériter de comportements existants et les étendre ?

On a vu dans les concepts précédents comment créer une hiérarchie de types, et on a aussi appris comment Julia utilise le [dispatch multiple][concept-multiple-dispatch] pour choisir des méthodes en fonction des types d'arguments.

Julia possède aussi plusieurs interfaces informelles, qui permettent à tes types personnalisés de s'intégrer à des comportements déjà définis pour les types standard.

Cela s'illustre le plus facilement avec l'interface Iterator.

## Itérateurs

Précédemment dans le programme, on a vu plusieurs façons pour Julia de traiter chaque élément d'une collection.

- [Boucles][concept-loops], comme `for item in items...`
- [Diffusion][concept-vector-operations] : `[1, 2, 3] .- 0.5`
- [Fonctions d'ordre supérieur][concept-hof] : `map(√, [1, 4, 9])`
- [Compréhensions][concept-comprehensions] : `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Générateurs][concept-comprehensions] : `(x^2 for x in 1:1e6)`, qui est évalué paresseusement.

De toute évidence, Julia sait parcourir les collections standard élément par élément : les vecteurs et les plages dans les exemples ci-dessus, ainsi que les Sets, les Dicts, etc.

Comment ajouter cette capacité à nos propres collections personnalisées, surtout si elles peuvent être parcourues paresseusement comme un générateur ?

### Exigences minimales

Pour créer une séquence à itérer, il faut (au moins) deux choses :

1. Un moyen d'obtenir le _premier_ élément.
2. Un moyen d'obtenir l'élément _suivant_ à partir de l'état courant.

Julia accomplit ces tâches avec des méthodes de la fonction `Base.iterate()`, selon les étapes suivantes :

1. `Base.iterate(iter)` est appelée automatiquement en premier.
    - S'il n'y a rien à itérer, renvoie `nothing`.
    - Sinon, renvoie le `Tuple` du premier élément renvoyé et du premier état : `(firstitem, firststate)`.
2. `Base.iterate(iter, state)` est appelée automatiquement si un élément a été renvoyé à l'itération précédente, en prenant `firststate` comme argument `state`.
    - Si l'itération se termine, renvoie `nothing`.
    - Sinon, renvoie le `Tuple` de l'élément suivant et de l'état suivant : `(nextitem, nextstate)`.
3. Répète l'étape 2 jusqu'à la terminaison.

Toutes ces étapes se font « sous le capot », ce qui signifie que les appels de méthodes et l'état sont gérés en interne par le protocole d'itération (l'état restant opaque), et seul l'élément est exposé aux constructions de haut niveau, comme les boucles.
Autrement dit, on ne voit jamais que `item`, tandis que tout le reste demeure dans une boîte noire.

Le [dispatch multiple][concept-multiple-dispatch] est au cœur de tout cela.
Le type de `iter` détermine quelles méthodes sont appelées, et le nombre d'arguments détermine si c'est le premier ou l'élément suivant qui est renvoyé.

Les méthodes pour les types standard sont déjà définies : `Vector`, `Range`, `Set`, etc. ([actuellement][ref-iterations-collections] 14 types au total).

Pour qu'un `MyType` personnalisé partage les mêmes comportements, il faut d'abord définir :
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Tout cela peut sembler confus dans l'abstrait, mais cela peut être très simple.
Pour illustrer, imaginons que l'on veuille un type qui donne les puissances d'un entier `n` donné, jusqu'à un nombre maximal de termes.

Tout d'abord, définis un type personnalisé :

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

On peut maintenant définir les méthodes `iterate` pour ce type, mais quels sont le premier élément et le premier état ?

Pour obtenir le premier élément, certains itérateurs ont besoin d'une mise en place compliquée, mais dans ce cas jouet, on peut remarquer que le premier élément renvoyé est simplement le nombre de base, donc il suffit de vérifier si la valeur de `count` est supérieure ou égale à un.

Maintenant, on peut considérer le premier état, qui transporte les informations utilisées pour l'itération suivante.
C'est à toi de décider de quelles informations tu dois garder une trace pour cela, et ce peut être n'importe quel type.

Dans ce cas, on pourrait simplement garder une trace de l'« indice » auquel élever `n`, ou trouver une option plus performante en utilisant la puissance la plus récente de `n` (c'est-à-dire l'élément renvoyé) et l'« indice » suivant dans la séquence.
Ces deux nombres peuvent être regroupés dans un `Tuple` et renvoyés comme `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

Dans cet exemple, le premier élément (`p.n`) est renvoyé à la boucle et le premier état `(p.n, 2)` est passé à la méthode `iterate(P::Powers, state)`.
Là, on peut traiter l'état pour produire l'élément suivant en multipliant l'élément courant par le nombre de base, augmentant ainsi sa puissance de `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Si la valeur de l'indice est toujours dans les limites de `count`, le `Tuple` est renvoyé avec l'élément `next` et le `Tuple` d'état incrémenté.
Lorsque la valeur de `index` dépasse `count`, c'est `nothing` qui est renvoyé à la place, pour indiquer que l'itération est terminée.

Tu as peut-être remarqué que les méthodes `iterate(p::Powers)` et `iterate(p::Powers, state)` ont des corps de fonction assez similaires.
En fait, si on est malin, cette similitude permet une implémentation simplifiée en n'utilisant que la version à deux arguments avec un argument par défaut pour l'état : `Base.iterate(p::Powers, state=(1, 1))`
Avec cela, on n'aurait pas besoin de la méthode séparée à un argument `iterate(p::Powers)`.
C'est ce qui se fait couramment en pratique lorsque c'est possible.

Jusqu'ici, on dispose déjà de fonctionnalités utiles : pour les 4 premières puissances de 3, on peut parcourir les résultats, vérifier si un nombre donné figure dans les résultats et appliquer des fonctions d'agrégation telles que `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Méthodes supplémentaires

Malgré ce bon début, tout ne fonctionne pas encore.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Comme prévu, `length(Powers(3, 4))` donne exactement le même message d'erreur.

C'est facile à corriger, car la longueur fait partie du constructeur du type : 4 dans ce cas.
Il suffit de définir `Base.length()` pour ce type, puis on peut utiliser des compréhensions et `collect()` sur la séquence.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Pour des raisons d'efficacité, il est préférable de définir aussi `Base.eltype()` : le type des éléments du résultat.
Cela permet à des fonctions telles que `collect()` de préallouer l'espace pour le `Vector{Int}` de sortie, au lieu de faire répétitivement un `push!()` dans un `Vector{Any}`.

Note la syntaxe, que tu n'as peut-être pas encore vue : cette méthode est définie sur le _type_, et non sur une _instance_ du type.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Les itérateurs ne sont pas _tenus_ d'avoir une longueur finie.
L'utilisation de séquences « infinies » est plus limitée, mais les parcourir en boucle peut être utile tant qu'il existe un moyen de `break` pour sortir de la boucle.
Par exemple, on pourrait définir une variante de `Powers` qui génère des valeurs inférieures à une certaine limite (peut-être `typemax(Int)`, pour éviter un débordement d'entier).

## Résumé

Les interfaces sont assez déroutantes à expliquer, car l'approche de Julia est très différente de celle de la plupart des autres langages.
En particulier, le nom de l'interface peut ne jamais être mentionné dans l'implémentation : contrairement à la [création de sous-classes][wiki-subclass] ou aux [mixins][wiki-mixins].

Cependant, elles sont étonnamment simples en pratique :

1. Définis un type approprié.
2. Découvre quelles méthodes sont nécessaires.
3. Implémente ces méthodes pour ton type personnalisé ; en général, seulement quelques méthodes, assez courtes et simples.
4. Laisse le [dispatch multiple][concept-multiple-dispatch] s'occuper du reste, automatiquement.
