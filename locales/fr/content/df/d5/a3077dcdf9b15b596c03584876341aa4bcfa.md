# Introduction

Presque tous les programmes Factor sont une suite de mots qui consomment et produisent des valeurs sur la *pile de données*. Quand les entrées et les sorties s'alignent bien, le code se lit de gauche à droite sans effort. Quand ce n'est pas le cas, on en vient aux *mots de réarrangement*, et le code devient vite bruyant.

Cet exercice te fait découvrir la solution standard de Factor : les combinateurs.

## Les mots de réarrangement

Les mots de réarrangement les plus courants se trouvent dans [`kernel`][kernel] :

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

Tu as déjà dû utiliser `dup` et `swap`. `over` fait une copie du *deuxième* élément depuis le haut, ce qui est pratique quand une même entrée doit alimenter deux calculs :

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

C'est très bien pour un seul usage. Mais enchaînées, les séquences de `dup`, `swap`, `over`, `rot` deviennent vite illisibles.

## `keep` : conserver l'entrée

`keep` (dans [`kernel`][kernel]) appelle une *quotation* sur le haut de la pile mais laisse la valeur d'origine au-dessus du résultat :

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

Ça remplace le schéma « `dup`, puis quelque chose, puis un réarrangement » : partout où tu écrirais `dup something swap`, tu peux simplement écrire `[ something ] keep`.

## `bi` : deux fonctions pour une seule entrée

`bi` (dans [`kernel`][kernel]) applique *deux* quotations à la même valeur et laisse les deux résultats sur la pile :

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

Sans `bi`, tu écrirais `dup sq swap neg`, ce qui reste lisible pour deux opérations mais devient corsé pour trois.

## `tri` et `cleave` : plusieurs fonctions pour une seule entrée

`tri` étend `bi` à trois quotations :

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

`cleave` (dans [`combinators`][combinators]) reprend la même idée pour un *tableau* contenant un nombre quelconque de quotations :

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

La quotation vide `[ ]` joue le rôle de l'identité, ce qui est utile lorsque l'une des cases du découpage doit être l'entrée elle-même.

## `dip` et `2dip` : opérer en dessous

`dip` (dans [`kernel`][kernel]) appelle une quotation sur les valeurs *sous* le haut de la pile, sans toucher au sommet. `2dip` fait la même chose mais protège les *deux* valeurs du haut :

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

Ici, `dip` a masqué `11`, exécuté `9 10 +`, puis remis `11` au sommet. `2dip` a masqué `11 12`, exécuté `9 10 +` en dessous, puis restauré `11 12`.

`dip` est l'outil adapté quand l'ordre naturel des arguments laisse au sommet de la pile la valeur qui doit simplement passer. Utilise-le plutôt que le sandwich `swap … swap`.

## `bi@` : la même opération sur deux valeurs

`bi@` (dans [`kernel`][kernel]) applique une seule quotation à deux valeurs de la pile :

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*` : des opérations différentes sur deux valeurs

`bi*` (dans [`kernel`][kernel]) applique des quotations *différentes* aux deux valeurs de la pile, la première à la valeur inférieure et la seconde à celle du sommet :

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

Utilise `bi@` quand les deux valeurs reçoivent le même traitement, et `bi*` quand chacune a besoin du sien.

## `tri*` : des opérations différentes sur trois valeurs

`tri*` (dans [`combinators`][combinators]) étend `bi*` à trois valeurs et trois quotations, en appliquant chaque quotation à une valeur dans l'ordre :

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
