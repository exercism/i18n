# Ajout aux instructions

## Notes spécifiques à WebAssembly

La signature de la fonction pour l'export WebAssembly `convert` est la suivante :

```wasm
(func (export "convert")
    (param $arrOffset i32)
    (param $arrLength i32)
    (param $inputBase i32)
    (param $outputBase i32)
    (result i32 i32 i32)
)
```

Les deux premiers paramètres `$arrOffset` et `$arrLength` expriment le décalage de base et la longueur d'un tableau d'entiers signés de 32 bits. Le paramètre de longueur est exprimé en nombre d'éléments du tableau, pas en octets. Avant d'appeler cette fonction, l'appelant écrit ce tableau dans la mémoire linéaire WebAssembly en commençant au décalage `$arrOffset`. La mémoire linéaire WebAssembly est toujours exprimée en _little-endian_.

L'appelant encoderait donc le tableau `[1,2]` sous la forme de la séquence de huit octets suivante.

```
| 64 | 65 | 66 | 67 | 68 | 69 | 70 | 71 |
| ---- arr[0] ----- | ---- arr[1] ----- |
,0x01,0x00,0x00,0x00,0x02,0x00,0x00,0x00,
```

Les paramètres `$inputBase` et `$outputBase` ne concernent pas la mémoire linéaire.

Le type de résultat est `(i32 i32 i32)`. Les deux premières valeurs sont les valeurs `offset` et `length` de ta sortie dans la mémoire linéaire. Si tu le souhaites, tu peux écraser les adresses de la mémoire linéaire utilisées pour l'entrée. La troisième valeur de retour est un code de statut i32 utilisé pour la gestion des erreurs.

Si la troisième valeur de retour exprime un état d'erreur, les tests unitaires ne lisent pas les deux premières valeurs de retour.
