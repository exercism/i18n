# Introduction

En programmation, il est essentiel de gérer les erreurs avec soin pour éviter que des situations inattendues ne fassent planter un programme ou ne le fassent se comporter de manière imprévisible.
Cairo propose deux mécanismes principaux pour gérer les erreurs :

1. **Les erreurs irrécupérables** avec `panic`, qui arrêtent immédiatement le programme.
2. **Les erreurs récupérables** avec `Result`, qui permettent au programme de gérer les erreurs et d'y réagir.

## Les erreurs irrécupérables avec `panic`

Il arrive qu'un programme rencontre une erreur si grave qu'il ne peut pas continuer.
Dans ce cas, Cairo utilise la fonction `panic` pour arrêter immédiatement l'exécution.
C'est utile lorsqu'une erreur, comme une tentative d'accès à un indice hors limites, empêche le programme de continuer de manière cohérente.
La fonction `panic` prend en argument un message de type `ByteArray` qui décrit la raison de l'erreur.

Par exemple, en Cairo :

```rust
fn main() {
    let data = array![1, 2];
    panic("An unrecoverable error has occurred!");
}
```

Cet exemple illustre un `panic` forcé, qui arrête immédiatement le programme avec un message.

### La macro `assert!`

La macro `assert!` est un outil pratique pour faire respecter certaines conditions dans le code.
Si la condition passée à `assert!` vaut `false`, le programme déclenche un `panic` avec un message d'erreur de type `ByteArray`.
On l'utilise souvent pour vérifier des hypothèses pendant le développement et s'assurer que les valeurs respectent certains critères.

Par exemple :

```rust
fn main() {
    let x = 5;
    assert!(x > 0, "x must be greater than zero");
}
```

Si `x` n'est pas supérieur à zéro, le programme déclenche un `panic` avec le message `"x must be greater than zero"`. `assert!` est utile pour vérifier des invariants et des préconditions sans écrire manuellement du code de gestion des erreurs.

## Les erreurs récupérables avec `Result`

Toutes les erreurs n'ont pas besoin d'arrêter le programme.
Certaines peuvent être gérées proprement pour que le programme continue.
L'énumération `Result` de Cairo représente ces erreurs récupérables, et elle comporte deux variantes :

- `Result::Ok` indique un succès.
- `Result::Err` représente une erreur.

Grâce à `Result`, une fonction peut renvoyer soit une valeur de succès, soit une erreur, ce qui permet à la fonction appelante de décider de la suite.

```rust
fn divide(a: u32, b: u32) -> Result<u32, ByteArray> {
    if b == 0 {
        Result::Err("Error: Division by zero")
    } else {
        Result::Ok(a / b)
    }
}
```

Dans cet exemple, si `b` vaut zéro, une erreur est renvoyée ; sinon, c'est le résultat de la division qui est renvoyé.
