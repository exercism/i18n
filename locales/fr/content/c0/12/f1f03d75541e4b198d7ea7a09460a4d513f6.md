# À propos

`<dlist>` (dans [`dlists`][dlists]) construit une nouvelle liste doublement
chaînée. Les opérations sont définies dans [`deques`][deques] et se répartissent
selon le [protocole deque][deque-protocol], ce qui permet à d'autres conteneurs,
principalement `<dlist>`, de les implémenter.

| mot            | effet                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )` : un nouveau deque vide  |
| `push-front`    | `( elt deque -- )` : ajouter en tête |
| `push-back`     | `( elt deque -- )` : ajouter en queue  |
| `pop-front`     | `( deque -- elt )` : retirer l'élément de tête |
| `pop-back`      | `( deque -- elt )` : retirer l'élément de queue  |
| `peek-front`    | `( deque -- elt )` : lire l'élément de tête sans le retirer |
| `peek-back`     | `( deque -- elt )` : lire l'élément de queue sans le retirer  |
| `deque-empty?`  | `( deque -- ? )` : le deque est-il vide ? |
| `dlist-length`  | `( dlist -- n )` : nombre d'éléments |

Toutes les opérations push/pop modifient le deque sur place. Passer un
deque à une routine puis le relire ensuite est le schéma habituel.

## Pile ou file

Deux schémas de répartition classiques :

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

Un vecteur doté de `push` et `pop` (de `mutation`) est le bon choix quand
l'ordre LIFO est tout ce qu'il te faut, car `<dlist>` traîne la surcharge
d'une liste chaînée. Pense à `<dlist>` quand il te faut du O(1) aux *deux*
extrémités, presque toujours pour une file FIFO.

## Le schéma BFS

Un parcours en largeur (BFS) est l'usage FIFO canonique :

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

Le deque porte la frontière de recherche ; l'ensemble de hachage assure la
déduplication. Remplace `pop-front` par `pop-back` et le même schéma
devient un parcours en profondeur.

## `MEMO:` pour la mise en cache automatique

Il arrive que la recherche que le BFS appelle pour chaque nœud soit
coûteuse. Factor fournit [`MEMO:`][memo-decl], un remplacement de `:` qui
met automatiquement en cache le résultat du mot en l'indexant sur ses
entrées :

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

Un mot `MEMO:` exécute son corps la première fois qu'il voit une entrée
donnée, puis renvoie le résultat mis en cache. Le cache persiste pendant
toute la durée de vie de l'image ; il n'y a aucune éviction fondée sur le
temps ou sur la taille. Utilise-le pour les fonctions pures dont les
entrées proviennent d'un ensemble fini et gérable.
