# Introduction

Comme nous l'avons vu dans le concept [`Nothingness`][concept-nothingness], R propose plusieurs façons de représenter des données absentes (`NULL`), inconnues (`NA`) ou mathématiquement invalides (`NaN`, `Inf`).
De manière générale, R essaie de les utiliser pour signaler les problèmes sur place, puis de continuer sans lever d'exception.

## `stop()`

Certains problèmes sont trop fondamentaux pour laisser le programme continuer.
Dans ce cas, utilise `stop(msg)` pour interrompre immédiatement le programme avec une `Error` et afficher `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Semblable à un `assert` dans d'autres langages, c'est un raccourci pratique pour `stop()`.
Les paramètres sont un nombre arbitraire de conditions booléennes séparées par des virgules, et le programme ne continue que si elles valent toutes `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R propose plusieurs façons de gérer les erreurs.
Elles s'appuient sur Common Lisp et diffèrent nettement de ce que font beaucoup de langages populaires.

La plus simple consiste à envelopper le code potentiellement problématique dans `try()`.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()` et `message()`

Ce sont des réponses à des conditions non fatales, par exemple :

- Pour avertir d'un problème dont le programme peut au moins se remettre en partie.
- Pour informer l'utilisateur de la progression d'un programme au long cours.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

La fonction `suppressWarnings()` peut parfois être utile dans Exercism, pour éviter de perturber l'exécuteur de tests avec des sorties indésirables.
