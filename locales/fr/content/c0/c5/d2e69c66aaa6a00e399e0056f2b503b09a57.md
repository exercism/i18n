# Introduction

## Références

### Copies et références

Avec nos connaissances actuelles, mettre à jour une variable à l'aide d'une fonction est un peu fastidieux.
Chaque argument de fonction est traité comme une copie et ne modifie pas la valeur d'origine.
Selon la taille du type, cela peut avoir de sérieuses conséquences sur les performances du code.

```cpp
int adjust_salary(int base, int kids) {
    return base + kids * 500;
}
int now_a_mother_of_twins{2500};
adjust_salary(now_a_mother_of_twins, 2);

// now_a_mother_of_twins is still 2500
now_a_mother_of_twins = adjust_salary(now_a_mother_of_twins, 2);
// now_a_mother_of_twins is now 3500
```

On peut voir les `References` comme des alias : les modifier a un effet sur la variable d'origine.
Les `References` utilisent une **esperluette** (`&`) dans la déclaration du type.

```cpp
int balance{1000};
int& budget{balance};
int pro_computer_wheels{699};
budget -= pro_computer_wheels;
// budget is now 301;
// balance is also 301;
```
Il n'est pas possible de réattribuer une `reference` (changer sa liaison).
On ne peut pas avoir une `reference` non initialisée.
Les `References` doivent être initialisées avec une variable existante.

```cpp
int main_acc{1'000'000};
int side_acc{-20};
int& savings{main_acc};
// => main_acc and savings are 1'000'000

// try to reseat savings to use main account
savings = side_acc;
// savings and main_acc are now -20
// as this uses the **value** of side_acc
savings += 20;
// savings and main_acc are now 0, side_acc is still -20

int& future_budget;
// => compiler error, reference must be bound!
```

### `void`

Avec la puissance des `references`, on n'a parfois pas besoin de renvoyer de valeur depuis une fonction.
Dans ce cas, `void` est utilisé comme type de retour.

```cpp
void increase_power(int& level) {
    level += 500;
}
int goku{8700};
increase_power(goku);
// goku's power level?
// It's over 9000!
```
