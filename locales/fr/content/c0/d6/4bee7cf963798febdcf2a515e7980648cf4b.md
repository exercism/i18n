# Introduction

L'assembleur écrit à la main regorge de répétitions.
La même petite suite d'instructions revient sans cesse, avec peu de variations, et il existe peu d'abstractions pour réduire le code qui se répète.
Qui plus est, programmer en assembleur oblige à gérer des valeurs sans sémantique évidente.
Il n'y a pas de paramètres nommés, et la plupart des détails de la machine sous-jacente doivent être gérés manuellement par le programmeur.

NASM, l'assembleur utilisé par le parcours, propose quelques outils qui peuvent aider le programmeur sur ces deux points.
Ces outils s'exécutent au _moment de l'assemblage_, avant qu'aucune instruction n'atteigne le processeur.
Ils indiquent à l'assembleur comment réécrire le texte source avant même qu'il soit traduit en code machine.

Le plus important de ces outils est la **macro**, que l'on peut voir comme une recette destinée à l'assembleur.
Elle est développée à l'endroit où elle est utilisée, comme si le code y avait été écrit à la main.

Une macro peut prendre un certain nombre de jetons littéraux en paramètres, ce qui la rend réutilisable dans des contextes différents.
Cependant, ce ne sont pas des fonctions : il n'y a pas de `call`, pas de `ret`, pas de transfert de contrôle vers un autre point du code.

## Les macros sur une seule ligne

La définition la plus simple donne un nom à une valeur ou à une courte expression avec `%define` :

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Chaque occurrence ultérieure de `WIDTH` est remplacée par `8` avant l'assemblage.
Le remplacement est textuel : le nom est substitué partout où il apparaît, que ce soit dans un opérande ou à l'intérieur d'une autre définition.

~~~~exercism/note
Pour les _constantes_ numériques, préfère `equ` à `%define`.

Une macro sur une seule ligne déclarée avec `%define` ne se développe que lorsqu'elle est utilisée, et peut être réaffectée ou supprimée.
Une constante `equ`, en revanche, est évaluée au moment de sa définition et n'est jamais modifiée.
~~~~

Un `%define` peut aussi prendre des paramètres _nommés_, se comportant comme une petite fonction en ligne :

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Entoure de parenthèses à la fois tout le corps et chaque paramètre.
Avec `%define square(x) x*x`, l'appel `square(1+1)` se développe en `1+1*1+1`, ce qui vaut `3`.
Écrit sous la forme `%define square(x) ((x)*(x))`, le même appel se développe en `((1+1)*(1+1))`, ce qui vaut `4`.
~~~~

Les noms définis avec `%define` sont sensibles à la casse.
La variante `%idefine` rend le nom insensible à la casse, si on le souhaite.

Les macros sur une seule ligne sont utiles pour donner du sens à différentes parties du code.
Utilisées avec soin, elles améliorent la lisibilité et réduisent le risque de fautes de frappe.
Par exemple, un registre auquel une fonction réserve un usage précis peut être défini par cet usage :

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Les macros sur plusieurs lignes

Toute une séquence de code, quel que soit son nombre de lignes, est capturée avec `%macro` et close par `%endmacro`.
Un nombre après le nom indique combien d'arguments la macro prend, ce qui peut être zéro.
Lorsque des arguments sont passés, ils sont séparés par une virgule (`,`) :

```x86asm
%macro example_macro 0
...
%endmacro
```

Les arguments des macros sur plusieurs lignes ne sont pas nommés.
On y fait référence par `%1`, `%2`, et ainsi de suite, dans l'ordre où ils sont passés :

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Note que les arguments doivent être une syntaxe valide pour les opérations effectuées dans le corps de la macro.
Ici, `mult_two eax, ecx` et `mult_two r8, r9` s'assemblent tous les deux, mais `mult_two eax, cl` non, car `imul eax, cl` n'est pas défini.

### Les étiquettes à l'intérieur d'une macro

Une macro qui définit une étiquette ordinaire casse dès qu'elle est utilisée deux fois, car l'étiquette serait alors définie deux fois elle aussi.
Pour utiliser des étiquettes dans une macro susceptible d'être appelée plusieurs fois, il faut faire précéder ces étiquettes de `%%`.
Cela demande à l'assembleur de donner à cette étiquette un nom différent et unique à chaque développement :

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Répéter au moment de l'assemblage

Il est possible de répéter un bloc de code d'une ligne avec `times`.
C'est particulièrement utile pour déclarer des valeurs répétées en mémoire :

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Pour répéter du code sur plusieurs lignes, on peut plutôt utiliser `%rep` :

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Note que le nombre de répétitions est indiqué juste après `%rep`, et qu'un `%endrep` clôt le bloc répété.

Il est courant d'utiliser un compteur d'assemblage à l'intérieur d'un bloc `%rep`, un peu comme une boucle à l'exécution utilise un compteur.
Si une constante entière d'assemblage peut être déclarée avec `equ`, pour des _variables_ entières d'assemblage on utilise plutôt `%assign`.
Contrairement à `%define`, `%assign` est évalué immédiatement en un nombre et peut être réaffecté :

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Une fois le préprocesseur passé, la boucle a disparu et il reste quatre instructions `add`, avec les valeurs immédiates `0`, `1`, `2` et `3` directement intégrées.
C'est un déroulage de boucle effectué par l'assembleur : pas de registre compteur, pas de branchement, juste du code linéaire.

## L'assemblage conditionnel

Le préprocesseur dispose de plusieurs conditionnelles.
Elles choisissent entre différents chemins, en développant leur corps sur place, mais seulement lorsque leur condition est vraie.

`%if` ... `%elif` ... `%else` ... `%endif` sélectionnent une branche à partir d'un test numérique :

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## Répartir dans plusieurs fichiers

Les macros sont souvent regroupées dans un fichier à part, puis incluses dans chaque source qui en a besoin avec `%include` :

```x86asm
%include "patterns.mac"
```

Le fichier nommé est inséré mot pour mot à cet endroit, avant l'assemblage, exactement comme si son contenu avait été saisi sur place.
Cela regroupe les définitions au même endroit et permet à plusieurs fichiers source de les partager.

Si le fichier de macros peut être assemblé seul, il doit avoir l'extension `.asm`.
Note que les macros n'ont aucune liaison.
Même si le fichier de macros est assemblé, ses macros ne sont visibles que pour un autre fichier qui l'inclut avec `%include`.

Sinon, un fichier uniquement destiné à `%include` peut avoir n'importe quelle extension.
Utiliser `.asm` ou `.mac` est une convention courante.
