# Instructions

Le travail se poursuit sur le projet de voiture télécommandée. La bande passante du système de télémétrie est limitée et on t'a demandé d'implémenter un protocole de messages pour transmettre les données de télémétrie.

Les données sont transmises dans un tampon (un tableau d'octets). Lorsque des entiers sont envoyés, la taille du tampon est réduite grâce au protocole décrit ci-dessous.

Chaque valeur doit être représentée dans le plus petit type entier possible (les types `byte` et `sbyte` ne sont pas inclus, car le gain serait négligeable) :

| De                         | À                         | Type     |
| -------------------------- | ------------------------- | -------- |
| 4_294_967_296              | 9_223_372_036_854_775_807 | `long`   |
| 2_147_483_648              | 4_294_967_295             | `uint`   |
| 65_536                     | 2_147_483_647             | `int`    |
| 0                          | 65_535                    | `ushort` |
| -32_768                    | -1                        | `short`  |
| -2_147_483_648             | -32_769                   | `int`    |
| -9_223_372_036_854_775_808 | -2_147_483_649            | `long`   |

La valeur doit être convertie dans le nombre d'octets approprié à son type. Le tampon complet comprend un octet indiquant le nombre d'octets supplémentaires qu'il contient (_octet de préfixe_), suivi des octets qui portent l'entier (_octets de charge utile_).

Certains types utilisent un nombre identique d'octets (par exemple les types `uint` et `int`). Normalement, ils auraient le même _octet de préfixe_, mais cela rendrait le décodage problématique. Pour y remédier, le protocole introduit une petite astuce : pour les types signés, la valeur de leur _octet de préfixe_ est `256` moins le nombre d'octets supplémentaires dans le tampon.

Seuls l'octet de préfixe et le nombre d'octets suivants indiqués par celui-ci sont envoyés lors de la communication. En interne, un tampon de 9 octets est utilisé (avec des zéros de remplissage si nécessaire), aussi bien par les routines d'envoi que de réception.

## 1. Encode une valeur entière prête à l'envoi

Implémente la méthode statique `TelemetryBuffer.ToBuffer()` pour encoder un tampon à partir du paramètre passé à la méthode.

```csharp
// Type: ushort, bytes: 2, signed: no, prefix byte: 2
TelemetryBuffer.ToBuffer(5)
// => {0x2, 0x5, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0 };

// Type: int, bytes: 4, signed: yes, prefix byte: 256 - 4
TelemetryBuffer.ToBuffer(Int32.MaxValue)
// => {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 };
```

## 2. Décode un tampon reçu

Implémente la méthode statique `TelemetryBuffer.FromBuffer()` pour décoder le tampon reçu et renvoyer la valeur sous la forme d'un `long`.

```csharp
TelemetryBuffer.FromBuffer(new byte[] {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 })
// => 2147483647
```

Si la valeur de l'octet de préfixe est inattendue, il faut renvoyer `0`.
