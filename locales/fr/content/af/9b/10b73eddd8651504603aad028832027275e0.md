# Tests

Pour exécuter les tests, on lance `cmake -G`, puis on utilise la commande de compilation qui correspond à sa plateforme.
Tu trouveras des instructions détaillées à ce sujet sur la page [Exécuter les tests][cpp-tests-instructions] pour le C++ sur exercism.org.

## Réussir les tests

Quand tu commences un nouvel exercice en local, les fichiers sont configurés pour qu'un seul test soit exécuté, le premier.
Fais en sorte que ce premier test compile, se lie et passe, en suivant les [trois règles du développement piloté par les tests][three-laws-of-tdd].
Crée juste assez de structure, en déclarant des espaces de noms, des fonctions, des classes, etc., pour faire disparaître les erreurs du compilateur et faire échouer le test.
Écris ensuite juste assez de code pour faire passer le test.
Une fois que c'est fait, décommente le test suivant en déplaçant la ligne `if defined(EXERCISM_RUN_ALL_TESTS)` après le test suivant.

Regarde l'exemple ci-dessous, tiré de l'exercice Bob (fichier `bob_test.cpp`, ligne 15) :

```diff
-#if defined(EXERCISM_RUN_ALL_TESTS)
TEST_CASE("shouting")
{
    REQUIRE("Whoa, chill out!" == bob::hey("WATCH OUT!"));
}
+#if defined(EXERCISM_RUN_ALL_TESTS)
```

Déplacer cette ligne après le test suivant peut entraîner des erreurs de compilation, car de nouvelles constructions peuvent être appelées alors que tu ne les as pas encore déclarées ni définies.
Là encore, corrige les erreurs de compilation de façon minimale pour obtenir un test qui échoue, puis modifie le code de façon minimale pour faire passer le test, réécris ton implémentation pour qu'elle soit plus lisible et plus expressive, puis passe au test suivant.

Essaie d'utiliser les fonctionnalités standard du C++17 plutôt que d'écrire toi-même tes propres algorithmes ou fonctionnalités de bas niveau.
