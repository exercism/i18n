# À propos

Il existe deux types principaux de propriétés :

1. les propriétés auto-implémentées, dont les accesseurs `get` et `set` n'ont pas de corps.
   Elles peuvent être initialisées explicitement ou non. Par exemple :
   ```csharp
   public int MyProperty {get; set;} = 42;
   ```
2. celles dont les accesseurs évaluent des expressions et exécutent des instructions. Le code peut
   être aussi simple que renvoyer ou affecter un champ de sauvegarde. Par exemple :
   ```csharp
   private int myField;
   public int MyProperty
   {
     get { return myField; }
     set { myField = value; }
   }
   ```

Il y a un chevauchement considérable, tant de comportement que de capacités, entre les
propriétés et les méthodes. Lorsqu'elles ne sont pas auto-implémentées, les propriétés peuvent
contenir toute instruction ou expression pouvant apparaître dans la portée de la classe. Dans un
cas courant, on les décrit souvent comme encapsulant un champ de sauvegarde.
Même si, la plupart du temps, il est évident de savoir s'il faut coder un comportement sous forme
de propriété ou de méthode dans un cas précis, c'est souvent une question de jugement pour le
développeur, en particulier pour décider combien de code doit être exécuté dans les accesseurs. On
rencontre couramment de la validation dans un accesseur `set`, et des calculs ou un formatage
simples dans un accesseur `get` :

```csharp
private float fraction;
public float Percentage
{
  get { return fraction * 100; }
  set
  {
    if (value < 0 || value > 100)
    {
      throw new ArgumentException("Percentage must be between 0 and 100");
    }
    fraction = value / 100;
  }
}
```

À l'instar des autres membres de classe, les propriétés peuvent avoir des niveaux d'accès.
Le plus souvent, les propriétés ont un niveau d'accès non privé, en accord avec leur objectif
essentiel. Il arrive que l'un des accesseurs ait un niveau d'accès différent de celui de la
propriété. Dans le cas de `TareWeight`, avec la contrainte de « sécurité » plutôt artificielle,
il était possible d'avoir une propriété publique dotée d'un accesseur `get` privé. Cela signifie
que du code externe à la classe peut définir la valeur de la propriété, mais qu'elle ne peut être
lue (`get`) que par du code à l'intérieur de la classe.

```csharp
public int ConfidentialValueUsedInternally {private get; set; }
```

Les accesseurs `set` non publics sont également pris en charge, mais le cas le plus courant est
celui où l'accesseur `set` peut être complètement omis. C'est peut-être parce que la valeur de la
propriété est définie dans le constructeur de la classe.

```csharp
class MyClass
{
  public MyClass( int importantValue)
  {
    ConstructedValue = importantValue;
  }
  public int ConstructedValue {get;}
}
```

Cet exercice a porté sur l'utilisation de base des propriétés. Tu trouveras des sujets plus
avancés dans d'autres exercices :

- les propriétés à corps d'expression, les accesseurs `get` et les accesseurs `set` (couvertes par les membres à corps d'expression)
- les propriétés sur les interfaces (couvertes par les interfaces)
- les propriétés et propriétés abstraites sur les classes abstraites (couvertes par l'héritage)
- l'utilisation du mot-clé `readonly` avec les propriétés (couverte par l'immuabilité)
- les propriétés statiques (couvertes par les membres statiques)
- les indexeurs (couverts par les indexeurs)
