# Générateurs

Un `generator` est une fonction ou une expression qui renvoie un type particulier d'[itérateur][iterator] appelé un [`generator iterator`][generator-iterator].
Les `Generator-iterator`s sont [paresseux][lazy iterator] : ils ne stockent pas leurs `values` en mémoire, mais _génèrent_ leurs valeurs au moment où on en a besoin.

Une fonction génératrice ressemble à n'importe quelle autre fonction, mais elle contient une ou plusieurs [expressions `yield`][yield expression].
Chaque `yield` suspend l'exécution du code et sauvegarde l'état d'exécution courant (_y compris toutes les variables locales et les instructions `try`_).
Quand le générateur reprend son exécution, il repart de l'état où il s'était interrompu, contrairement aux fonctions classiques qui sont réinitialisées à chaque appel.


## Construis un générateur

On construit les générateurs à peu près comme les autres fonctions itératives ou récursives, mais ils ont besoin d'une [expression `yield`](#the-yield-expression), que l'on verra plus en détail un peu plus loin.

Prenons l'exemple d'une fonction qui renvoie les _carrés_ d'une liste donnée de nombres.
Telle qu'elle est écrite actuellement, toutes les entrées doivent être traitées avant qu'une seule valeur puisse être renvoyée :

```python
>>> def squares(list_of_numbers):
...     squares = []
...     for number in list_of_numbers:
...         squares.append(number ** 2)
...     return squares
```

Tu peux transformer cette fonction en générateur comme ceci :

```python
>>> def squares_generator(list_of_numbers):
...     for number in list_of_numbers:
...         yield number ** 2
```

L'idée derrière tout ça, c'est qu'on utilise un générateur quand on n'a pas besoin de produire toutes les valeurs _d'un seul coup_.
Cela économise de la mémoire et de la puissance de calcul, puisque seule la valeur sur laquelle on travaille _à ce moment-là_ est calculée.


## Utilise un générateur

On peut utiliser les générateurs à la place de la plupart des `iterables` en Python.
Cela inclut les _fonctions_ ou les _objets_ qui attendent un `iterable`/`iterator` en argument.

Pour utiliser le générateur `squares_generator()` :

```python
>>> squared_numbers = squares_generator([1, 2, 3, 4])

>>> for square in squared_numbers:
...     print(square)
...
1
4
9
16
```

Les valeurs d'un `generator` peuvent aussi être produites ou récupérées via la fonction `next()`.
`next()` appelle la méthode `__next__()` d'un objet générateur-itérateur, ce qui « fait avancer » le code ou l'évalue jusqu'à son expression `yield`, laquelle « produit » ou renvoie alors une valeur :

```python
>>> squared_numbers = squares_generator([1, 2])

>>> next(squared_numbers)
1
>>> next(squared_numbers)
4
```

Quand un `generator-iterator` est entièrement consommé et n'a plus de valeurs à renvoyer, il lève une erreur `StopIteration`.

```python
>>> next(squared_numbers)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
StopIteration
```


~~~~exercism/note

Les générateurs-itérateurs sont un sous-ensemble particulier des [itérateurs][iterator].
Les `Iterators` sont le mécanisme (ou protocole) qui permet de parcourir des _iterables_.
Les générateurs-itérateurs et les itérateurs renvoyés par les [`iterables`][iterables] courants de Python se comportent de façon très similaire, mais il y a quelques différences importantes à connaître :

- Ils sont _[évalués paresseusement][lazy evaluation]_ ; l'itération est _à sens unique_ et il n'est pas possible de « revenir en arrière » vers une valeur précédente.
- Ils sont _consommés_ au fur et à mesure que l'on parcourt les valeurs renvoyées ; il n'y a ni réinitialisation ni sauvegarde en mémoire.
- Ils ne peuvent pas être triés et ne peuvent pas être parcourus à l'envers.
- Ce ne sont pas des séquences et ils _n'ont pas_ d'`indexes`.
  Tu ne peux pas référencer une valeur précédente ou suivante par addition ou soustraction, et tu ne peux pas utiliser la notation entre crochets (`[]`) ni le découpage.
- Ils ne peuvent pas être utilisés avec la fonction `len()`, car ils n'ont pas de longueur.
- Ils peuvent être _finis_ ou _infinis_ ; fais attention quand tu récupères toutes les valeurs d'un `generator-iterator` _infini_ !

## L'expression `yield`

L'[expression `yield`][yield expression] est très similaire à l'expression `return`.
_Contrairement à_ l'expression `return`, `yield` transmet des valeurs à l'appelant à un _moment précis_, en suspendant l'évaluation ou le renvoi de toute valeur supplémentaire jusqu'à ce qu'elle soit demandée.
Quand `yield` est évalué, il met en pause l'exécution de la fonction qui le contient et renvoie les valeurs de cette fonction _à cet instant précis_.
La fonction _reste alors dans la portée_, et quand `__next__()` est appelé, l'exécution reprend jusqu'à ce que `yield` soit rencontré à nouveau.


~~~~exercism/note
L'utilisation d'expressions `yield` est interdite en dehors des fonctions.
~~~~

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1

>>> lets_try = infinite_sequence()
>>> lets_try.__next__()
0
>>> lets_try.__next__()
1
```


## Pourquoi créer un générateur ?

Les générateurs sont utiles dans de nombreuses applications.

Quand on travaille avec une collection de valeurs potentiellement volumineuse, on n'a pas forcément envie de tout garder en mémoire.
Un générateur permet de traiter des données plus importantes morceau par morceau, ce qui économise de la mémoire et améliore les performances.

Les générateurs sont aussi très utiles quand un processus ou un calcul est _complexe_, _coûteux_ ou _infini_ :

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1
```

Maintenant, chaque fois que `__next__()` est appelé sur l'objet `infinite_sequence`, il renvoie le _nombre précédent_ + 1.
