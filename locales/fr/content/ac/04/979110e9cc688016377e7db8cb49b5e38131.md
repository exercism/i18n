# Propriété

En Cairo, le concept de propriété est rattaché aux _variables_ plutôt qu'aux _valeurs_ qu'elles contiennent.

Les valeurs en Cairo sont immuables, ce qui garantit que même si de nombreuses variables font référence à la même valeur, celle-ci reste constante et inchangée.
Le compilateur doit donc s'assurer que le programmeur en fait bon usage.
C'est là le sens de la _propriété_ d'une variable : le propriétaire est le code qui peut lire (et écrire si elle est _mutable_) la variable.

## Règles de propriété des variables

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## Portée des variables

Une portée est l'intervalle, au sein d'un programme, dans lequel une variable est valide.
Regardons l'exemple suivant, qui déclare une variable `x` de type entier non signé, avec des commentaires qui indiquent où la variable est valide :

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Notes :

- Quand `x` entre dans la portée, elle est valide.
- Elle reste valide jusqu'à ce qu'elle en sorte, ici jusqu'à la fin de la fonction `main()`.

## Déplacement de valeurs

Un déplacement se produit lorsqu'une valeur est passée à une autre fonction : la variable d'origine qui faisait référence à cette valeur est alors détruite (ce qui la rend inutilisable), et une nouvelle variable est créée pour contenir la même valeur.

Les tableaux sont un exemple de type complexe que l'on déplace quand on le passe à une autre fonction.
Voici un petit rappel de ce à quoi ressemble un tableau :

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

Comment le système de types garantit-il que le programme Cairo n'essaie jamais d'écrire deux fois dans la même cellule mémoire ?
Prenons le code suivant, dans lequel on essaie de retirer deux fois l'élément de tête du tableau :

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

Dans ce cas, on essaie de passer la même valeur (le tableau contenu dans la variable `arr`) aux deux appels de fonction.
Autrement dit, notre code essaie de retirer le premier élément deux fois, ce qui reviendrait à écrire deux fois dans la même cellule mémoire : c'est interdit par la VM Cairo, d'où une erreur d'exécution.
Heureusement, ce code ne compile pas.
Une fois que l'on a passé le tableau à la fonction `foo`, la variable `arr` n'est plus utilisable.
On obtient cette erreur de compilation, qui nous dit qu'il faudrait que `Array` implémente le _trait_ `Copy` :

## Le _trait_ `Copy`

Si un type implémente le _trait_ `Copy`, le fait de le passer à une fonction ne déplace pas la valeur, mais crée une nouvelle variable qui fait référence à la même valeur.
C'est une opération gratuite, car les variables sont une abstraction de Cairo et les valeurs sont toujours immuables.

Pour implémenter le _trait_ `Copy` sur ton type, ajoute l'annotation `#[derive(Copy)]` à la définition du type.
Cairo refusera cependant de le faire si le type, ou l'un de ses composants, n'implémente pas le _trait_ `Copy`.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## Destruction de valeurs

On peut également utiliser les types linéaires en les détruisant, ce qui garantit que la ressource associée est correctement libérée.
Pour cela, on implémente ou on dérive le _trait_ `Drop`, ce qui indique au compilateur que le type peut être détruit sans risque une fois qu'il n'est plus utile.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

Pour l'instant, l'implémentation de `Drop` peut être dérivée pour tous les types, sauf pour les dictionnaires (`Felt252Dict`) et les types qui contiennent des dictionnaires.
C'est parce que les dictionnaires doivent être « _squashed_ » au moment de leur destruction.
Pour cela, on dérive le _trait_ `Destruct` :

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## Valeurs de retour et portée

Renvoyer des valeurs revient à les déplacer.
L'exemple ci-dessous montre une fonction qui renvoie une valeur :

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
