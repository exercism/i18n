# À propos

Les fonctions récursives sont des fonctions qui s'appellent elles-mêmes.

Une fonction récursive doit avoir au moins un _cas de base_ et au moins un _cas récursif_.

Un _cas de base_ renvoie une valeur sans rappeler la fonction.
Un _cas récursif_ rappelle la fonction, en modifiant l'entrée pour qu'elle finisse par correspondre au cas de base.

En Elm, les fonctions récursives se définissent généralement à l'aide du _pattern matching_ et d'expressions `case`.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

Une fonction récursive peut avoir plusieurs cas de base et/ou plusieurs cas récursifs.
Par exemple, [la suite de Fibonacci][fibonacci] est une suite récursive avec deux cas de base :

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

À noter que cette implémentation en particulier est d'une lenteur exponentielle, car des nombres de Fibonacci apparentés sont recalculés à partir de zéro dans deux appels récursifs indépendants.

Compter le nombre d'occurrences d'une valeur donnée `x` dans un tableau comporte deux cas récursifs :

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## Les boucles par récursion

En raison de l'immutabilité, les boucles en Elm s'écrivent différemment de celles des langages impératifs.
Par exemple, une boucle ressemble souvent à ceci :

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

Dans un langage fonctionnel comme Elm, il n'est pas possible de modifier une variable.
Les boucles doivent donc être implémentées à l'aide de la récursion.

L'équivalent d'une boucle `for` en Elm ressemblerait à ceci :

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

En pratique, pour parcourir des listes et d'autres structures de données en Elm, on utilise le plus souvent des fonctions du module [`List`][module-list], comme `List.map`, `List.filter` et `List.foldl`.
Sous le capot, ces fonctions sont implémentées à l'aide de la récursion.

## Exécution infinie

Une fonction récursive, si elle est mal implémentée ou si le nombre d'appels récursifs est trop grand, peut ne jamais renvoyer son résultat.
Cela peut poser problème, car à chaque appel d'une fonction, une référence est stockée en mémoire à l'endroit où l'environnement d'exécution doit renvoyer le résultat (dans la [pile d'appels][wiki-call-stack]).
Si une fonction récursive s'appelle trop de fois, voire à l'infini, la mémoire peut être saturée, ce qui fait planter l'environnement d'exécution (une [erreur de dépassement de pile][wiki-stack-overflow]).
L'environnement d'exécution d'Elm est optimisé pour la récursion et la fiabilité, mais une récursion infinie peut tout de même poser problème.

Ce problème d'exécution infinie peut avoir plusieurs causes :

- Oublier d'implémenter un cas de base.
- Ne pas traiter tous les cas possibles dans le _pattern matching_.
- Ne pas modifier correctement l'argument lors de l'appel récursif, et donc ne jamais atteindre le cas de base.
