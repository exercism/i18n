- Lis la section sur les liens et les tâches dans le [guide de démarrage][getting-started-links] officiel.
- Jette un œil à la [documentation du module `Task`][task].
- Lis [« Demystifying processes in Elixir » sur blog.appsignal.com][appsignal-processes].

## 1. Démarre une vérification de fiabilité pour une seule entrée

- Tu n'as pas besoin d'une tâche pour cette étape, un processus lié classique suffit.
- Il existe une [fonction intégrée][spawn-link] qui exécute une fonction anonyme donnée dans un nouveau processus et la lie au processus courant.

## 2. Interprète les résultats d'une vérification de fiabilité

- Pour recevoir un seul message, appelle [`receive`][receive]. Il lira le premier message qui correspond à l'un des motifs donnés, en laissant les autres messages dans la boîte de réception du processus.
- On peut utiliser soit une garde, soit [l'opérateur de pin][pin-operator], pour s'assurer que seuls les messages provenant d'un processus dont le PID correspond au PID passé en argument à `await_reliability_check_result/2` seront reçus.
- [`receive`][receive] accepte une clause `after` pour gérer les délais d'attente.

## 3. Lance une vérification de fiabilité concurrente pour plusieurs entrées

- Le processus courant doit commencer à piéger les sorties avant que de nouveaux processus liés ne soient lancés.
- Pour piéger les sorties dans un processus, il faut définir un drapeau sur ce processus.
- Il existe une [fonction intégrée][process-flag] qui définit un drapeau sur un processus et renvoie l'ancienne valeur de ce drapeau.
- Le drapeau pour piéger les sorties s'appelle `:trap_exit` et accepte une valeur booléenne.
- Utilise les fonctions d'`Enum` pour d'abord démarrer un processus pour chaque entrée, puis attendre les messages de chaque processus. Utilise les fonctions implémentées dans les deux étapes précédentes. Note que la map renvoyée par `start_reliability_check/2` correspond à la map qu'`await_reliability_check_result/2` attend comme premier argument.

## 4. Lance une vérification de correction concurrente pour plusieurs entrées

- Utilise une tâche asynchrone pour cette étape.
- Il existe une [fonction intégrée][task-async] qui démarre une tâche asynchrone.
- Il existe une [fonction intégrée][task-await] qui attend qu'une tâche asynchrone ait fini de s'exécuter et renvoie son résultat. Elle accepte un délai d'attente en deuxième argument.
- Utilise les fonctions d'`Enum` pour d'abord démarrer une tâche pour chaque entrée, puis attendre chaque tâche.
