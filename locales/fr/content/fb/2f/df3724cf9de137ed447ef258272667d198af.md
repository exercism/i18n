L'interface publique d'une base de code mérite une attention particulière, car chaque fonction publique augmente les coûts de maintenance à long terme et rend la réécriture plus difficile.

Dans chaque exercice Exercism, l'interface publique est définie par la suite de tests.
Si une fonction est testée, elle doit être publique.
Toutes les autres fonctions doivent être privées, y compris les fonctions qui portent le même nom mais une arité différente.

```elixir
# you defined the following public function

%{actual}

# make it private like this

%{expected}
```
À noter que les arguments par défaut modifient l'arité d'une fonction.

Quand on écrit une bibliothèque, il est souvent nécessaire de rendre certaines fonctions publiques pour pouvoir les utiliser d'un module à l'autre.
Pour masquer ces fonctions dans la documentation, les auteurs de bibliothèques ajoutent `@doc false` avant la définition des fonctions, ou `@moduledoc false` pour masquer le module entier.
