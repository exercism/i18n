# Tests

## Fichiers de l'exercice

Un exercice téléchargé contient les fichiers suivants pour construire et tester ta solution :

```text
hello-world/
├── HelloWorld.vb       # Your solution
├── HelloWorldTests.vb  # The test suite
├── HelloWorld.vbproj   # Project and build configuration
└── packages.lock.json  # Resolved project dependencies
```

Les noms de fichiers varient d'un exercice à l'autre.
Écris ta solution dans le fichier `.vb` dont le nom ne se termine pas par `Tests`.
Le fichier qui se termine par `Tests.vb` est la suite de tests xUnit ; normalement, tu ne dois le modifier que pour supprimer les arguments `Skip`.
Normalement, tu n'as pas besoin de modifier le fichier de projet ni le fichier de verrouillage.

## Lance les tests

Ouvre un terminal dans le répertoire de l'exercice et lance :

```bash
dotnet test
```

La commande restaure les dépendances du projet, compile le projet et exécute ses tests.
Tu peux aussi utiliser `dotnet watch test` pour relancer les tests dès qu'un fichier source change.

## Tests ignorés

Au départ, les exercices n'activent que le premier test, ce qui te permet de résoudre les autres une étape à la fois.
Ouvre le fichier qui se termine par `Tests.vb` pour trouver les tests.
Chaque test est une sous-routine `Sub` marquée par un attribut `<Fact>` d'xUnit.
Un test sera ignoré tant que son attribut `<Fact>` possède un argument `Skip` :

```vb
<Fact(Skip:="Remove this Skip property to run this test")>
Public Sub Lowercase_words()
    Assert.Equal("ROR", Abbreviate("Ruby on Rails"))
End Sub
```

Pour activer le test, il te suffit de supprimer l'argument `Skip` :

```vb
<Fact>
Public Sub Lowercase_words()
    Assert.Equal("ROR", Abbreviate("Ruby on Rails"))
End Sub
```

Une fois que le test que tu viens d'activer passe, répète cette opération avec le test ignoré suivant.
Quand tous les tests sont activés et passent, c'est terminé.
