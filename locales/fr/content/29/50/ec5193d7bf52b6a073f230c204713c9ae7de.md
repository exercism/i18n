# Les routines liées

Jusqu'ici, tout ce qu'on a vu faisait circuler des *valeurs* : des nombres, des _strings_, des objets. Une **routine liée** permet de faire circuler une routine elle-même : quelque chose qui sera appelé plus tard, par du code qui ne sait pas ce que c'est.

Une doublure, c'est exactement l'idée : le régisseur détient une façon de jouer le rôle, sans savoir qui elle est ni ce qu'elle fera.

## Crées-en une

`bind` prend un appel comportant des trous, écrits `_` :

```sather
   shout(line : STR) : STR is return line.upper; end;

   ...

   part ::= bind(shout(_));
```

`part` est maintenant une valeur comme une autre. Son appel a lieu plus tard :

```sather
   part.call("who's there")      -- "WHO'S THERE"
```

## Le type

Le type d'une routine liée est `ROUT`, avec les types des arguments entre accolades et le type de retour après un deux-points :

```sather
   part : ROUT{STR}:STR := bind(shout(_));
```

On lit `ROUT{STR}:STR` comme « une routine qui prend un `STR` et qui renvoie un `STR` ».

| Écrit | Signification |
| --- | --- |
| `ROUT{STR}:STR` | prend un `STR`, renvoie un `STR` |
| `ROUT{INT,INT}:BOOL` | prend deux `INT`, renvoie un `BOOL` |
| `ROUT{STR}` | prend un `STR`, ne renvoie rien |
| `ROUT:INT` | ne prend rien, renvoie un `INT` |

Comme c'est un type, il peut être un argument :

```sather
   rehearse(line : STR, part : ROUT{STR}:STR) : STR is
      return part.call(line);
   end;
```

`rehearse` n'a aucune idée de ce que fait `part`. C'est justement l'intérêt : on peut lui passer `shout`, ou `whisper`, ou n'importe quoi d'autre de cette forme.

## Remplis certains arguments

Tous les arguments n'ont pas besoin d'être des trous. Tout ce qui est écrit est figé au moment de la liaison :

```sather
   repeat(times : INT, line : STR) : STR is ... end;

   twice ::= bind(repeat(2, _));      -- ROUT{STR}:STR
```

`twice` ne prend que la ligne, parce que le `2` est déjà fixé. La valeur est calculée au moment de la liaison et conservée, donc modifier ensuite la variable dont elle vient ne change rien.

C'est ainsi qu'une routine générale en devient beaucoup de spécifiques.

## Lie aussi l'objet

Pour une routine sur un objet, l'objet est le premier élément de l'appel et peut être fixé ou laissé comme trou :

```sather
   bind(board.home_goal)      -- this board's, always
   bind(_.home_goal)          -- whichever board is handed in later
```
