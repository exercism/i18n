# À propos

`TUPLE: child < parent extra-slots ;` déclare une classe dont les instances sont aussi des instances de `parent`. La recherche des _slots_ parcourt la hiérarchie : un `child` possède tous les _slots_ déclarés par le parent, plus les siens, dans cet ordre.

```factor
TUPLE: vessel name tonnage ;
TUPLE: cargo-vessel < vessel capacity ;
TUPLE: tanker < cargo-vessel fuel-type ;
```

## L'ordre des arguments de `boa`

Le constructeur `boa`, généré automatiquement, prend les _slots_ dans l'ordre de déclaration, *les parents d'abord*. Pour le `tanker` ci-dessus :

```
tanker boa ( name tonnage capacity fuel-type -- tanker )
```

L'ordre des _slots_ est fixé par la chaîne d'héritage : impossible d'entrelacer les _slots_ du parent et de l'enfant, et réordonner les _slots_ d'un parent constitue un changement incompatible pour le `boa` de chacun de ses descendants.

## Hiérarchie des prédicats

Chaque déclaration `TUPLE:` génère un prédicat de classe (`name?`). Avec l'héritage, les prédicats s'imbriquent :

```factor
"Esso" 50000 100000 "diesel" tanker boa .

! all three predicates fire
dup tanker?        .   ! => t
dup cargo-vessel?  .   ! => t
dup vessel?        .   ! => t
```

`instance?` (de [`classes`][classes]) pose la même question, mais avec la classe comme argument sur la pile plutôt que figée dans le nom d'un mot. Ainsi, `obj tanker instance?` équivaut à `obj tanker?` :

```factor
USING: classes ;

"Esso" 50000 100000 "diesel" tanker boa
dup vessel instance? .   ! => t
```

Comme la classe est maintenant une valeur, le même site d'appel peut tester la classe qu'on lui passe, ce qu'un prédicat `name?` figé ne permet pas.

La relation transitive `is-a` est aussi ce que parcourt la répartition des méthodes `M:` : une méthode définie sur `vessel` s'applique à chaque `cargo-vessel` et à chaque `tanker`, à moins qu'une méthode plus spécifique ne prenne le pas. Cet aspect est traité dans [`generics`][generics].

## Héritage des accesseurs

Les mots accesseurs (`slot>>`, `>>slot`, `change-slot`) viennent de [`accessors`][accessors] et ne sont pas liés à la classe pour laquelle ils ont été générés : n'importe quel _tuple_ qui *possède* le _slot_ peut les utiliser.

```factor
USING: accessors ;

"Esso" 50000 100000 "diesel" tanker boa
[ 1 + ] change-tonnage tonnage>> .   ! => 50001
```

`change-tonnage` a été généré pour `vessel`, mais il fonctionne sur un `tanker` parce que tout `tanker` est un `vessel`.

## Ce que ce n'est pas

- **Mixins** (`MIXIN:` / `INSTANCE:`) : une classe peut rejoindre de nombreux mixins ; la relation est plusieurs-à-plusieurs et sert principalement à la répartition générique sur un protocole partagé. Le concept des flux les présente en contexte.
- **Classes de prédicat** (`PREDICATE:`) : elles extraient une sous-classe d'une classe existante au moyen d'un prédicat évalué à l'exécution. C'est une fonctionnalité Factor distincte, non traitée ici.
