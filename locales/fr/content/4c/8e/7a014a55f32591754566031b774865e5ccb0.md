# Introduction

Jongler avec la pile convient pour les mots courts. Quand un mot prend plusieurs entrées et que tu dois y faire référence par leur nom, Factor propose les *locals*, des liaisons nommées introduites avec `::` (pour les définitions de mots) ou `[| | ]` (pour les lambdas en ligne).

## `:: ( inputs -- outputs )`

Remplace `:` par `::` et les noms des entrées deviennent des variables locales dans le corps :

```factor
USING: locals ;

:: hypotenuse ( a b -- c )
    a a *
    b b *
    + sqrt ;
```

Compare avec la version qui manipule la pile :

```factor
! DOCTEST: SKIP   (shown for comparison — would re-define hypotenuse)
: hypotenuse ( a b -- c )
    [ sq ] bi@ + sqrt ;
```

Les deux sont valides ; les *locals* brillent quand une entrée est utilisée à plusieurs endroits ou quand l'ordre des opérations ne suit pas naturellement l'ordre de la pile.

## Lie les valeurs intermédiaires avec `:>`

À l'intérieur d'un corps `::` (ou d'une lambda en ligne `[| ... |]`), `:>` dépile une valeur de la pile de données et la lie à une nouvelle variable locale :

```
value :> name      ! immutable binding
value :> name!     ! mutable binding (name! is its setter)
```

La forme immuable est la plus courante : utilise-la pour nommer une valeur intermédiaire afin que le corps se lise de haut en bas :

```factor
USING: locals math ;

:: average-3 ( x y z -- avg )
    x y + z + :> sum
    sum 3 / ;
```

La variante avec `!` déclare la variable locale comme mutable ; plus loin dans le corps, `value name!` (sans deux-points, sans `:>`) la réaffecte :

```factor
USING: kernel locals math math.order ;

:: clamped ( x lo hi -- y )
    x :> v!
    v lo < [ lo v! ] when
    v hi > [ hi v! ] when
    v ;
```

Les *locals* mutables brillent à l'intérieur des mots d'itération que tu rencontreras dans les exercices suivants (par exemple `while`).

## `[let` : une portée depuis n'importe où

`:>` ne fonctionne qu'à l'intérieur d'une portée lexicale, que `::` et `[| ... |]` créent automatiquement. Pour introduire des *locals* depuis un mot `:` ordinaire ou depuis le _listener_, enveloppe le code dans `[let ... ]` :

```
[let code :> name code :> name ... body ]
```

Chaque `:> name` lie la valeur au sommet de la pile de l'expression précédente ; les liaisons sont visibles depuis le reste de la forme.

```factor
USING: locals math ;

[let 3 :> x 4 :> y x x * y y * + ] .   ! => 25
```

`[let` fait le pont entre les définitions `:` à la pile et les liaisons nommées : c'est pratique quand seule une partie d'un mot profite des *locals*.

## Lambdas : `[| inputs | body ]`

À l'intérieur d'une _quotation_, `[| inputs | body ]` introduit des *locals* auxquels le corps peut faire référence par leur nom. C'est particulièrement utile avec les mots d'ordre supérieur comme `assoc-map`, dont la _quotation_ reçoit `key` *et* `value` :

```factor
USING: assocs locals ;

H{ { "a" 1 } { "b" 2 } }
[| key value | key value neg ] assoc-map .
! => H{ { "a" -1 } { "b" -2 } }
```

La même forme fonctionne pour `map-index` (dans [`sequences`][sequences]), dont la _quotation_ reçoit l'élément *et* son indice. Les noms indiquent clairement quel opérande joue quel rôle :

```factor
USING: locals sequences ;

! Divide each element by its 1-based position:
{ 10 80 270 } [| elt i | elt i 1 + / ] map-index .
! => { 10 40 90 }
```

L'effet sur la pile de la lambda est déterminé par la liste d'entrées et par ce que produit son corps.

## Quand utiliser les *locals*

Pense aux *locals* quand :

- La même entrée est utilisée à plusieurs endroits.
- L'ordre naturel des opérations ne correspond pas à l'ordre de la pile, et les `dup`/`swap`/`rot` nécessaires pour corriger ça sont difficiles à lire.
- Tu te trouves dans une lambda en ligne passée à un mot d'ordre supérieur qui te fournit plusieurs valeurs d'un coup (comme dans `assoc-map`).

Quand le corps est un flux linéaire clair, les définitions `:` ordinaires restent plus courtes et tout aussi lisibles.

## `assoc-map` : une entrée à la fois

`assoc-map` (dans [`assocs`][assocs]) applique une _quotation_ à chaque entrée d'une collection associative :

```
assoc-map ( assoc quot: ( key value -- newkey newvalue ) -- newassoc )
```

Une lambda avec *locals* est la façon la plus propre d'écrire la _quotation_.

## Retour sur `cond`

Quand tu dois aiguiller sur `f` *ou* sur une valeur numérique, `cond` est exactement la bonne forme : pas besoin de `case`, puisqu'il n'y a pas de valeur unique à laquelle comparer.
