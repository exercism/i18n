# Introduction

Savoir quel est le type d'une donnée est souvent très important pour que le code s'exécute correctement, sans erreur.

JavaScript propose plusieurs façons de vérifier le type d'une valeur ou d'un objet.

```exercism/note
Les mécanismes de vérification de type de JavaScript peuvent être assez peu fiables.

Pour une meilleure sûreté de type et des types plus stricts, tu devrais sans doute utiliser TypeScript, un langage construit sur JavaScript, mais qui reprend la syntaxe de typage d'un langage à typage statique.
```

## L'opérateur `typeof`

L'opérateur `typeof` renvoie le type de son opérande.
Le résultat est une _string_ correspondant au nom de l'un des [types de données primitifs][primitives], sauf pour `"null"`.
Il peut aussi valoir `"function"` ou `"object"`.

```javascript
typeof undefined;
// => "undefined"

typeof true;
// => "boolean"

typeof 42;
// => "number"

typeof 'Hello, World!';
// => "string"

typeof function () {
  return 'Hello, World';
};
// => "function"

typeof [1, 2, 3, 4];
// => "object"

typeof { city: 'Stockholm', country: 'Sweden' };
// => "object"
```

Pour des [raisons historiques][`typeof null` is `"object"`].

## L'opérateur `instanceof`

Pour vérifier le type d'un objet, tu peux utiliser l'opérateur `instanceof`.
Il s'évalue en un `boolean` selon que le second opérande figure ou non dans la [chaîne de prototypes][prototype chain] du premier opérande.
Pour préciser : `instanceof` renvoie si le premier opérande est une instance du second opérande ou de l'une de ses classes dérivées.
`instanceof` ne fonctionne que sur les objets.

```javascript
class Beverage {
  // ...
}

// The Coffee class is a child of the Beverage class.
class Coffee extends Beverage {
  // ...
}

const java = new Coffee();

java instanceof Coffee;
// => true

java instanceof Beverage;
// => true
```

````exercism/advanced
La classe `Array` possède une méthode appelée `Array.isArray()` qui vérifie si son argument est un tableau.

Alors que `instanceof Array` ne fonctionne pas avec un tableau créé dans un autre _realm_, comme une `iframe` dans une page web, `Array.isArray()` y parvient.

En effet, la classe `Array` a un constructeur différent dans chaque _realm_, et chaque `iframe` possède son propre _realm_, ce qui signifie que la fonction de la chaîne de prototypes diffère, et fait donc échouer `instanceof Array`.
`Array.isArray()` sait ignorer ce problème et devrait toujours être utilisée quand c'est possible.

Elle résiste aussi aux faux positifs, là où un objet n'est pas réellement un `Array` et possède simplement `Array` dans sa chaîne de prototypes.

```javascript
({ __proto__: Array.prototype }) instanceof Array
// => true

Array.isArray({ __proto__: Array.prototype })
// => false
```

````

## L'opérateur `in`

L'opérateur `in` renvoie si le premier opérande est une propriété du second opérande.
Il ne vérifie pas que la propriété possède une valeur définie.
Une propriété définie à `undefined` sera quand même détectée par `in`.

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
    this.isDarkMatter = undefined;
  }

  coolDown() {
    this.temperature = 'warm';
  }
}

const espresso = new Coffee();

'temperature' in espresso;
// => true

'color' in espresso;
// => false

'isDarkMatter' in espresso;
// => true
```

````exercism/note
`in` renvoie `true` pour les propriétés et méthodes héritées.

```javascript
"coolDown" in espresso
// => true

"constructor" in espresso
// => true
```

Pour éviter cela, utilise plutôt `Object.hasOwn()`
````

## La fonction `Object.hasOwn()`

La méthode `Object.hasOwn()` renvoie si l'objet spécifié _possède la propriété donnée_ (elle n'est pas héritée et ce n'est pas une méthode).

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
  }

  coolDown() {
    this.temperature = 'warm';
  }
}
const cappuccino = new Coffee();

Object.hasOwn(cappucino, 'temperature');
// => true

Object.hasOwn(cappucino, 'constructor');
// => false

Object.hasOwn(cappucino, 'coolDown');
// => false
```
