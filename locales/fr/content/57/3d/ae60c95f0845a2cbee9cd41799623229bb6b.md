# Introduction

Une déclaration `GENERIC:` crée un mot dont le comportement dépend de la *classe* de l'un de ses arguments. Le comportement concret vient des *méthodes*, définies avec `M:`.

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

Lorsqu'on appelle `area`, Factor inspecte le sommet de la pile, cherche la méthode la plus spécifique dont la classe correspond, puis l'exécute. Avec les locales, tu peux utiliser `M::` :

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

Les génériques permettent d'ajouter de nouvelles représentations plus tard sans modifier le code appelant : `area` fonctionnait déjà pour `square` et `circle`, et la méthode `rectangle` est prise en compte automatiquement partout où `area` est appelé.

## Quand un générique est le bon choix

Pense à `GENERIC:` quand :

- Une même opération a des implémentations *vraiment différentes* selon les entrées.
- Tu t'attends à ce que du code futur ajoute de nouveaux types.
- Tu veux que le système de types impose des définitions par classe.

Si la variation se limite à une petite énumération d'étiquettes, un `case` est plus simple.

## Rejoindre un mixin avec `INSTANCE:`

Un *mixin* est une classe générique qui est *ouverte* : n'importe qui peut enregistrer une nouvelle classe comme membre. Beaucoup de protocoles intégrés de Factor (séquences, ensembles, flux, …) sont exposés sous forme de mixins, si bien qu'un tuple personnalisé peut adopter les méthodes par défaut du protocole en se déclarant instance :

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

Après `INSTANCE:`, chaque méthode par défaut `M: shape …` s'applique automatiquement à `my-shape`, et tout code qui demande un `shape` accepte un `my-shape`. `M:` sert à ajouter des méthodes à un générique ; `INSTANCE:` sert à rattacher une classe à un mixin.

## `TYPED::`, des entrées vérifiées pour un mot ordinaire

`GENERIC:`/`M:` choisissent une méthode selon la classe d'un argument. Parfois, tu ne veux pas de dispatch, mais juste *un* mot qui exige que ses entrées soient d'une classe donnée. `TYPED::` (dans le vocabulaire `typed`) est `::` avec une classe écrite après chaque nom d'entrée :

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

`n: integer` se lit comme les locales que tu utilises déjà, avec la classe écrite après les deux-points. Il n'y a pas de dispatch, une seule définition, un seul comportement, mais chaque argument est désormais vérifié par rapport à sa classe : une incompatibilité comme `"x" triple` est rejetée (*expected input value of type integer but got string*) au lieu de passer silencieusement.

La sortie peut être annotée de la même façon. `yes?` type à la fois son entrée et son résultat :

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## Fonctions et constantes mathématiques

Cet exercice s'appuie aussi sur quelques mots de `math.constants` et de `math.functions` que tu rencontres ici pour la première fois :

- `pi`, la constante π, issue de `math.constants`.
- `sin ( x -- y )`, `cos ( x -- y )`, le sinus et le cosinus d'un angle en radians.
- `e^ ( x -- y )`, `e` élevé à la puissance `x`. (Pour une base quelconque, utilise `^`.)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
