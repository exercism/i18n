# Indices

## Général

- `movapd` et `movaps` ne doivent être utilisés que lorsqu'on sait qu'un opérande mémoire est aligné.
  Leur emploi ne pose aucun problème lorsque les deux opérandes sont des registres `xmm`.
- Les adresses mémoire sont passées sous forme de valeurs entières.
  Les six premiers arguments entiers d'une fonction sont passés dans `rdi`, `rsi`, `rdx`, `rcx`, `r8` et `r9`, respectivement.

## 1. Combiner les rendements de deux lignes

- L'addition _packed_ pour les flottants 32 bits est `addps`.
- Les trois arguments pointeur sont garantis alignés sur 16 octets, donc la variante de déplacement alignée, `movaps`, est appropriée.

## 2. Calculer l'écart mis à l'échelle

- La soustraction _packed_ pour les flottants 64 bits est `subpd`.
- La multiplication _packed_ pour les flottants 64 bits est `mulpd`.
- `measured` est aligné et `target` ne l'est pas, ce qui impose des variantes de chargement différentes.

## 3. Calibrer un lot

- `reference` et `offset` sont alignés, contrairement à `raw`, ce qui impose des variantes de chargement différentes.
- `reference` comme `offset` sont nécessaires pour les deux lignes.
- Les instructions à deux opérandes écrasent généralement leur opérande de destination.
- Pour convertir les 2 flottants supérieurs de `raw` en doubles, utilise `cvtps2pd` avec un opérande mémoire décalé de 8 octets à partir du pointeur raw.
- Le facteur de conversion doit être stocké en mémoire sous forme de 2 nombres à virgule flottante de 64 bits (tous les deux égaux à `0.5`).
- Le résultat occupe 32 octets (4 nombres à virgule flottante de 64 bits) : les 16 premiers octets à `[result]`, les 16 suivants à `[result + 16]`.

## 4. Normaliser les scores le long d'une ligne

- Les instructions à deux opérandes écrasent généralement leur opérande de destination.
- La mémoire ne peut pas être l'opérande de destination des instructions arithmétiques _packed_.
- À chaque `score` de type nombre à virgule flottante de 64 bits du tableau `scores` (premier argument) correspond un `gain` équivalent dans le tableau `gains` (deuxième argument).
  Chaque `score` sera utilisé avec le `gain` situé à la même position.
- Le troisième argument est un `scale` fixe contenant 2 nombres à virgule flottante de 64 bits _packed_.
- Pour chaque paire `score` et `gain`, la fonction calcule `score * gain / scale_lane`.
  La première voie de `scale` met à l'échelle le premier élément de chaque paire (les voies aux positions paires), la seconde met à l'échelle le second (les voies aux positions impaires).
- Le score normalisé est stocké sur place dans le tableau `scores`, à la même position que son `score` d'entrée.
- Le nombre d'éléments de `scores` et de `gains` est identique et vaut la valeur de `n` (le quatrième argument).
- Utilise une boucle pour traiter toutes les paires d'éléments, en avançant de 16 octets (2 éléments) à chaque itération.
