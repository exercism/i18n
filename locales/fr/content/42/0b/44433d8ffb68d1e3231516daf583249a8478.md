# À propos

Les littéraux sont des valeurs fixes utilisées directement dans le code.
Ils ne nécessitent aucun calcul au moment de l'exécution.
Ils se présentent sous différentes formes afin de représenter efficacement différents types de données.
Les littéraux les plus fréquents sont de nature numérique, mais il existe aussi des opérateurs littéraux pour les dates, les heures et les _strings_.
Un concept abordé plus tard montrera comment utiliser des opérateurs littéraux définis par l'utilisateur.

## Littéraux numériques

Les littéraux numériques comprennent les représentations décimales, octales, hexadécimales et binaires.
Ces bases ont déjà été abordées dans le [concept des nombres][numbers-concept].

Toutes les représentations comme `23`, `0x50f7ba11` et `0xba5eba11` sont interprétées comme des `int` par le compilateur.
Le type `int` général est signé et couvre souvent une plage allant de `-2'147'483'648` à `2'147'483'647` (cela dépend du compilateur et du système, voir [cet article][in-depth-integers]).
C'est suffisant la plupart du temps et tu n'as pas besoin de te soucier du type précis.

Certains cas d'usage exigent des plages plus grandes ou une très faible empreinte mémoire des programmes.
Pour être explicite, on peut indiquer directement un type entier précis à l'aide du littéral numérique.

Quand les nombres négatifs ne sont pas nécessaires, mais que l'on veut la plage supplémentaire, on utilise le suffixe `u` ou `U` pour les entiers _non signés_.
Pour des plages plus grandes, on peut utiliser `L` ou même `LL` pour les types long et long long.

~~~~exercism/caution
L'usage d'un `l` minuscule est permis, mais il se confond facilement avec le chiffre `1` et est donc déconseillé.
~~~~

```cpp
auto net_worth_christian_grey{2'500'000'000U}; // out of range for 32-bit integers
auto net_worth_carlisle_cullen{46'000'000'000LL}; // int and uint are not enough
```

Lors de la compilation, les nombres à virgule flottante sont généralement résolus en `double`.
C'est un bon choix par défaut, et les cas d'usage nécessitant le type `float`, plus étroit, sont moins fréquents que l'exemple non signé ci-dessus.

```cpp
auto light_year_in_m{9.46073e+15f}; // well in the range of float
auto earth_to_edge_comoving_distance_in_nm{4.32355e+32}; // needs double type for magnitude
auto eulers_number{2.718281828459045}; // needs double type for precision
```

## Littéraux de caractères et de chaînes de caractères

D'autres concepts ont déjà utilisé des littéraux de caractères entre apostrophes, comme `'}'` ou `'@'`.

En C++, `char` est limité aux 128 premiers [codes de caractères ASCII][ascii-code].
Pour utiliser plusieurs caractères ASCII, ou des caractères ASCII étendus comme `‰`, voire des caractères unicode comme `麗` et `ẞ`, d'autres types sont nécessaires.
Dans un concept précédent, les littéraux de chaînes ont été introduits avec des _guillemets doubles_ : `"一体どういう意味ですか。C++です"`.
Le type réel de cette phrase japonaise est `const char (&)[46]`, une chaîne de caractères de style C.

L'utilisation des littéraux de chaînes n'est pas activée par défaut.
Pour utiliser le littéral _string_ `""s` ou le littéral _string-view_ `""sv`, l'utilisateur doit préciser leur utilisation en passant par l'espace de noms correspondant :

```cpp
#include <string>
#include <string_view>

using namespace std::literals;

auto green_light{"무궁화 꽃 이 피었 습니다"};
// green_light type is const char (&)[36]
auto umbrella{"달고나"s};
// umbrella type is std::basic_string<char>, the same as std::string
auto il_nam{"보는 것이 하는 것보다 더 재미있을 수가 없지"sv};
// il_nam type is std::basic_string_view<char>
```

Une _string_view_ peut être vue comme une référence vers une _string_ constante.
