# Debug

YS dispose d'une fonction `DBG` intégrée qui peut s'avérer utile pour déboguer le code de ta solution.
Elle prend un nombre quelconque d'arguments et les affiche sur stderr, dans la console.
Elle renvoie le dernier argument, ce qui te permet de l'utiliser directement dans le code.


Tu peux utiliser l'opérateur _inline_ `.>`, qui est un raccourci pour `.DBG()`.

Voici un exemple de fichier de code :

```yaml
# file: program.ys

!YS-v0

defn do-it(nums):
  x =: 5

  DBG: -'my vars' x nums

  nums: .map(\(_ * x)).>
        .reverse().>
        .map(str).>
        .join(' - ')

say: do-it(3 .. 5)
```

Lorsque tu exécutes ce code avec `ys`, tu obtiens la sortie suivante :

```txt
>>>
"my vars"
5
(3 4 5)
<<<
>>>(15 20 25)<<<
>>>(25 20 15)<<<
>>>("25" "20" "15")<<<
25 - 20 - 15
```


## Compilation

Une autre façon courante de cerner un problème consiste à regarder le code Clojure vers lequel ton code YS est compilé.

Pour cela, tu peux lancer l'interprète en ligne de commande `ys` avec l'option `-c`.

Voici à quoi ressemble le fichier `program.ys` ci-dessus une fois compilé :

```clojure
$ ys -c program.ys
(defn do-it [nums]
 (let [x 5]
  (DBG "my vars" x nums)
  (join
   (DBG
    (+map
     (DBG (reverse (DBG (+map nums (fn [& [_1]] (mul+ _1 x))))))
     str))
   " - ")))
(say (do-it (rng 3 5)))
```

Tu vois clairement comment l'opérateur `.>` se compile en un appel à la fonction `DBG`.
