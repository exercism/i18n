# Introduction

## Les _maps_

Les _maps_ en Elixir sont la structure de données qui permet de stocker des informations sous forme de paires clé-valeur. Dans d'autres langages, on les connaît aussi sous le nom de tableaux associatifs (PHP), de tables de hachage (Perl 5, Raku) ou de dictionnaires (Python).

Les clés et les valeurs peuvent être de n'importe quel type, mais si la clé est un atome, on peut utiliser une syntaxe abrégée. L'ordre des entrées d'une _map_ n'est pas garanti, qu'on y accède ou qu'on la renvoie.

### Les formes littérales

Une _map_ vide se déclare simplement avec `%{}`. Si on veut ajouter des éléments à une _map_ littérale, on peut utiliser deux formes :

```elixir
# If the key is an atom:
%{atom_key: 1}

# If the key is a different type:
%{1 => :atom_value}

# You can even mix these if the atom form comes second:
%{"first_form" => :a, atom_form: :b}
```

Il n'existe pas de format canonique, alors choisis une façon cohérente de représenter les paires clé-valeur.

### Les fonctions du module _Map_

Elixir fournit de nombreuses fonctions pour manipuler les _maps_ dans le _module Map_. Certaines fonctions du _module Map_ demandent qu'on leur passe une fonction anonyme pour faciliter la transformation de la _map_.

## Les attributs de module comme constantes

En Elixir, on peut définir des attributs de module qui peuvent servir de constantes dans nos fonctions.

```elixir
defmodule Example do
  # Defines the attribute as the value 1
  @constant_number 1

  def example_value() do
    # Returns the value 1
    @constant_number
  end
end
```

Lorsqu'on les utilise pour définir des constantes de module, les attributs peuvent être n'importe quelle expression évaluable au moment de la compilation. Après la compilation, les attributs de module ne sont plus accessibles, car ils sont développés pendant la compilation, un peu comme les macros définies dans des langages tels que le C.
