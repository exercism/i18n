# À propos

Les entrées/sorties de Factor reposent sur un seul [protocole][stream-protocol] que toute source ou destination de données peut implémenter. Les flux fournis avec Factor (`<file-reader>`, `<file-writer>`, `<string-reader>`, `<string-writer>`, les sockets réseau, les tableaux d'octets, les ttys) sont tous des classes qui implémentent le même petit ensemble de génériques de [`io`][io] et qui étendent `disposable` de [`destructors`][destructors].

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe` est la lecture par lots de bas niveau : elle remplit un tampon fourni par l'appelant, puis renvoie le nombre d'éléments qui ont été écrits. Les mots publics `stream-read` et `stream-read-partial` s'appuient dessus et gèrent l'allocation. La plupart des flux définis par l'utilisateur implémentent soit `stream-read1` (quand les lectures se font un élément à la fois), soit `stream-read-unsafe` (quand les lectures peuvent se faire par lots).

`stream-element-type` renvoie l'un de deux jetons singletons : `+byte+` pour les flux d'octets (lecteurs de fichiers, sockets) et `+character+` pour les flux de caractères (lecteurs de chaînes, ttys). Un flux enveloppe se contente en général de déléguer au flux sous-jacent.

## Rejoins les mixins

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

Une classe peut être l'un, l'autre, ou les deux. Rejoindre le mixin fait que les méthodes par défaut de `input-stream` / `output-stream` sont dispatchées vers ta classe, selon le même schéma de mixin ouvert que `set` du vocabulaire `sets`.

## Le framework des disposables

`new-disposable ( class -- disposable )` enregistre une nouvelle instance auprès de la portée de destructeur courante, afin qu'une exception au milieu de la mise en place des ressources soit gérée proprement :

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose` est le mot public ; `dispose*` est le générique que la classe implémente. Une redéfinition de `dispose*` dans une sous-classe doit nettoyer son propre état, puis libérer les ressources qu'elle détient :

```factor
M: my-stream dispose* underlying>> dispose ;
```

Le framework garantit que `dispose*` s'exécute au plus une fois par objet : des appels répétés à `dispose` n'ont aucun effet.

## Les accesseurs à portée

Trois combinateurs mettent en place le « flux d'entrée/sortie courant » global utilisé par `print`, `read1`, etc. :

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

Chacun libère la ressource à la sortie, même si la _quotation_ lève une exception. C'est ainsi que la plupart du code utilise un flux personnalisé, plutôt que de le transmettre à chaque appel.
