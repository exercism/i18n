# Astuces
`Option` sert à indiquer un calcul qui peut éventuellement ne pas avoir de résultat utile
(par exemple à cause d'une erreur ou d'une entrée invalide).
Si tu ne connais pas `Option`, tu peux lire [ce tutoriel](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html).
`Option` est ce qu'on appelle une [monade](https://en.wikipedia.org/wiki/Monad_(functional_programming)) qui recouvre un « aspect calculatoire », en l'occurrence l'absence éventuelle d'une valeur.
Un usage correct des monades peut donner du code très concis, tout en restant élégant
et lisible. Un usage incorrect peut facilement donner l'inverse.
Regarde [cette vidéo](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) pour en savoir plus.
## Les pièges courants à éviter
Il existe quelques règles empiriques pour `Option` :
1. Si tu n'en as pas besoin, ne l'utilise pas. Au lieu de
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
il vaut mieux écrire
```scala
def add1(x: Int): Int = x + 1
```
(il y a `Option.map` pour appliquer ce genre de fonctions simples,
tu n'as donc pas besoin de les encombrer avec `Option`).
2. Ne « unwrap » pas si tu n'en as pas vraiment besoin.
Il existe souvent des fonctions intégrées pour ce que tu veux faire. Les signes d'un
« unwrap » prématuré sont `isDefined/isEmpty` ou le filtrage par motif. Au lieu de
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
il vaut mieux écrire
```scala
x map (_ + 1) getOrElse 0
```
3. On peut utiliser les monades dans une _for-comprehension_, FTW.
C'est conseillé quand tu veux « composer » plusieurs instances de `Option`. Au lieu de
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
il vaut mieux écrire
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
