# Introduction

Un signaleur à bord d'un navire de patrouille côtière tient le journal des messages. Les drapeaux de signalisation bruts arrivent encadrés par des caractères marqueurs ; les relevés doivent être rendus pour la transmission ; les paires et les triplets d'observations sont résumés à la volée. Quelques idiomes de la bibliothèque standard de Factor font l'essentiel du travail.

## `unparse` : de la valeur au code source

[`unparse`][unparse] (dans `prettyprint`) renvoie le texte sous forme source de n'importe quelle valeur :

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` est l'inverse de l'analyseur syntaxique : l'aller-retour `dup unparse parse` reconstruit la valeur. C'est le bon outil pour sérialiser vers un format de transmission que le destinataire analysera à son tour, et le mauvais pour produire une sortie lisible par un humain (les _strings_ gardent leurs guillemets, les vecteurs gardent leur `V{ ... }`, etc.).

## Les variantes _slice_ : des vues, pas des copies

`head` et `tail`, dans `sequences`, *copient* la partie que l'on garde dans une nouvelle séquence. Leurs équivalents `-slice` renvoient un objet `slice`, un tuple contenant l'indice de début, l'indice de fin et la séquence sous-jacente, qui implémente le [protocole des séquences][sequence-protocol] sans rien copier :

| mot           | effet                                            |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )` : copie les n premiers     |
| `head-slice`  | `( seq n -- slice )` : vue sur les n premiers    |
| `tail`        | `( seq n -- newseq )` : copie à partir de l'indice n |
| `tail-slice`  | `( seq n -- slice )` : vue à partir de l'indice n |
| `head*`       | `( seq n -- newseq )` : copie tout sauf les n derniers |
| `head-slice*` | `( seq n -- slice )` : vue sur tout sauf les n derniers |
| `tail*`       | `( seq n -- newseq )` : copie les n derniers     |
| `tail-slice*` | `( seq n -- slice )` : vue sur les n derniers    |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

Un `slice` *est* une séquence, donc tout ce qui accepte une séquence accepte un `slice` : `length`, `first`, `each` et compagnie fonctionnent tous sans copier. Les tests qui doivent comparer avec une _string_ littérale peuvent convertir avec `>string`.

## `?head` et `?tail` : retirer un marqueur s'il est présent

Les relevés encadrés portent un texte marqueur qui peut être présent ou non. `?head` et `?tail` (dans `splitting`) essaient de retirer un préfixe ou un suffixe, et renvoient la séquence (éventuellement raccourcie) *et* un booléen indiquant si le marqueur a été trouvé :

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

Le booléen placé en fin de pile en fait un choix naturel pour une garde : associe `?head` à `if` pour brancher selon que le cadre était présent, ou à `unless` pour rejeter une entrée à laquelle manque le marqueur attendu.

## `<repetition>` : N copies virtuelles

[`<repetition>`][repetition] (dans `sequences`) est une autre séquence virtuelle sans copie : `( len elt -- repetition )` construit une séquence de `len` éléments tous égaux à `elt`, sans allouer autant d'emplacements :

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

L'`elt` peut lui-même être une séquence : chaque copie est cette même séquence. `concat` joint ensuite les copies bout à bout :

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

Comme un `slice`, le résultat *est* une séquence : `length`, `each` et compagnie fonctionnent directement dessus. Utilise-la pour compléter un code de signal à une largeur fixe ou pour poser une suite de marqueurs répétés ; ne convertis avec `>string` (ou `>array`) que lorsqu'une séquence concrète est réellement nécessaire.

## `<clumps>` : des fenêtres chevauchantes, sans copie

[`<clumps>`][clumps] (dans `grouping`) est une troisième séquence virtuelle sans copie : `( seq n -- clumps )` considère `seq` comme la série de fenêtres de longueur `n` qui se *chevauchent*, chaque fenêtre étant un `slice` :

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

Une séquence de `length` n produit `length - n + 1` fenêtres. Comme chaque fenêtre est un `slice`, apparier des relevés successifs ne coûte aucune copie : `[ first2 ]` appliqué à chaque `2`-clump fournit toutes les paires consécutives sur lesquelles projeter. (Son cousin sans chevauchement, `<groups>`, découpe quant à lui la séquence en blocs disjoints.)

## Le _cleave_ à plusieurs entrées : `2bi`, `3bi`, `2tri`, `3tri`

Les mots de _cleave_ ordinaires `bi` et `tri` appliquent deux ou trois quotations à *une* entrée. Les variantes préfixées par `2` et par `3` appliquent chaque quotation à *deux* ou *trois* entrées :

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

Chaque quotation reçoit *toutes* les entrées. Utilise-les lorsque plusieurs projections dépendent de la même paire (ou du même triplet) de valeurs, et non lorsque tu veux appliquer la *même* opération à chaque entrée séparément (c'est à cela que servent `bi@` et `tri@`).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
