# Introduction

Le concept des conditionnels présente `jcc`, la famille d'instructions qui effectue des branchements en fonction d'une condition.
Un `jcc` transfère l'exécution vers un autre point du programme uniquement si sa condition est remplie.

Cependant, les processeurs modernes sont rapides et capables d'exécuter de nombreuses instructions en parallèle.
Il serait trop coûteux de suspendre tout le travail pendant que le processeur attend une vérification de condition à l'exécution.

C'est pourquoi, en interne, le processeur n'attend pas.
Il utilise un **prédicteur de branchement** pour deviner le résultat d'une condition et commence à exécuter _spéculativement_ le chemin prédit.

Si la prédiction est correcte, l'exécution se poursuit comme s'il n'y avait pas de branchement.
En revanche, si la prédiction est fausse, le processeur doit _jeter le travail effectué_ sur le chemin prédit et reprendre l'exécution sur le chemin correct.

C'est ce qu'on appelle une **mauvaise prédiction de branchement**, et c'est coûteux, car cela entraîne un délai.

Quand un branchement est difficile à prédire, ces mauvaises prédictions s'accumulent.
Dans ces cas, il est parfois préférable d'éviter complètement le branchement, afin que les mêmes instructions s'exécutent quelle que soit la condition.
Le code qui choisit entre des valeurs sans `jcc` est dit **sans branchement**.

Il existe plusieurs façons de structurer le code pour qu'il effectue moins souvent des branchements, ou pour que les branchements qu'il contient soient plus faciles à prédire.
En particulier, x86-64 fournit deux familles d'instructions couramment utilisées pour écrire du code sans branchement.

## Déplacements conditionnels

La famille d'instructions `cmovcc` copie l'opérande source dans la destination uniquement si une condition précise est remplie.
Sinon, la destination reste inchangée.

Le suffixe `cc` suit la même nomenclature que dans `jcc`, avec la même signification :

| instruction | déplace si                          |
|-------------|--------------------------------------|
| `cmove`     | A == B après `cmp A, B`              |
| `cmovne`    | A != B après `cmp A, B`              |
| `cmovl`     | A < B (signé) après `cmp A, B`       |
| `cmovb`     | A < B (non signé) après `cmp A, B`   |
| `cmovg`     | A > B (signé) après `cmp A, B`       |
| `cmova`     | A > B (non signé) après `cmp A, B`   |

Les règles sont similaires à celles de `jcc` :

1. `l` et `g` servent aux comparaisons signées, et `b` et `a` aux comparaisons non signées.
2. Ajouter `e` à un suffixe inclut l'égalité.
3. Ajouter `n` inverse la condition.
4. Il existe aussi des variantes qui font référence à un drapeau positionné.
   Par exemple, `cmovz` et `cmovc`.

Prenons la valeur absolue d'un entier signé placé dans `rdi`, renvoyée dans `rax`.
Écrite avec `jcc`, la fonction sélectionne l'un de deux chemins :

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Écrite avec `cmovcc`, les deux valeurs candidates sont calculées inconditionnellement, et le déplacement conditionnel en choisit une :

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

La version sans branchement exécute toujours les mêmes instructions.
Il n'y a aucun `jcc` que le prédicteur puisse deviner.

La destination d'un `cmovcc` doit être un registre.
La source peut être un registre ou un emplacement mémoire, mais pas une valeur immédiate.

~~~~exercism/note
Dans le code ci-dessus, l'instruction `neg` positionne plusieurs drapeaux en fonction du résultat, notamment le drapeau de signe (SF).
Cela signifie que le `cmp rdi, 0` peut être supprimé complètement :

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Pour un `rdi` positif, `neg` produit un résultat négatif et SF == 1, donc `cmovs` restaure `rdi`.
Pour un `rdi` nul ou négatif, `neg` produit un résultat non négatif et SF == 0, donc `rax` conserve la valeur négative (qui est bien la valeur absolue correcte).

Bien que `cmp` soit le principal moyen de comparer des valeurs en assembleur, beaucoup d'instructions positionnent aussi des drapeaux en fonction de leur résultat.
La liste complète des drapeaux que modifie une instruction figure généralement dans sa [référence][reference].
Pour `neg` en particulier, ce sont SF, ZF, CF, OF et PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

## Affectation conditionnelle

La famille d'instructions `setcc` met l'opérande de destination à `1` si une condition précise est remplie, et à `0` sinon.
La destination est toujours un _opérande de 8 bits_.

Le suffixe `cc` suit la même nomenclature que dans `jcc` et `cmovcc`.
Par exemple, `setz` met la destination à `1` si `ZF == 1`, et à `0` sinon.

Comme la destination fait 8 bits, il est courant de faire suivre `setcc` d'un `movzx` lorsqu'une valeur plus large est nécessaire :

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

C'est un idiome courant pour transformer le résultat d'une comparaison en un entier valant `0` ou `1`.
