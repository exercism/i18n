# Ignore

## Options supplémentaires de ligne de commande pour jq

Tu remarqueras des options supplémentaires pour `jq` dans les tests.

```sh
run jq -s -R -c -f flower-field.jq << 'END_INPUT'
```

Que sont-elles ?

- `-s`

  C'est le mode « _slurp_ ».
  Au lieu de traiter l'entrée comme un flux d'objets JSON,
  toute l'entrée sera aspirée dans un tableau.

  ```sh
  $ seq 5 | jq -c '.'
  1
  2
  3
  4
  5
  $ seq 5 | jq -s -c '.'
  [1,2,3,4,5]
  ```

- `-R`

  Tu as peut-être déjà vu `-r`, pour afficher des _strings_ brutes (sans guillemets).
  C'est l'opposé.
  Chaque ligne d'entrée est considérée comme une _string_.

  Deux exemples :

  ```sh
  $ seq 5 | jq -R -c .
  "1"
  "2"
  "3"
  "4"
  "5"

  $ echo 42 | jq '. * 2'      # input is a JSON number
  84
  $ echo 42 | jq -R '. * 2'   # input is a JSON string
  "4242"
  ```

Lorsque tu combines ces deux options, tu n'obtiens _pas_ un tableau de _strings_ :
tu obtiens toute l'entrée sous forme d'une seule _string_, y compris les sauts de ligne.

```sh
$ seq 5 | jq -s -R -c .
"1\n2\n3\n4\n5\n"
```

Gérer cela fait partie du défi de cet exercice.
