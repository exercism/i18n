## `Print` n'ajoute pas de guillemets autour des _strings_

Cet exercice t'amène à manipuler des scores numériques.
#[a: 1]` and `#[a: "1"]` ne sont pas identiques :

```arturo
inspect #[a: 1]
; [ :dictionary
;        a  :        1 :integer
; ]

inspect #[a: "1"]
; [ :dictionary
;        a  :        1 :string
; ]
equal? #[a: "1"] #[a: 1]
; false
```

Une pratique courante de débogage consiste à `print` des valeurs.
Cependant, la sortie n'ajoute pas de guillemets autour des _strings_.
Ainsi, une _string_ numérique comme `"1"`, une fois affichée, semble identique à l'entier `1`.

```arturo
print #[a: 1]
; [a:1]
print #[a: "1"]
; [a:1]
```
Dans la sortie des tests de cet exercice, tu peux voir un résultat comme `:x: equal? [a:1 e:1 i:1 o:1 u:1] [a:1 e:1 i:1 o:1 u:1]`.
Les deux dictionnaires comparés semblent identiques à l'affichage.
Cependant, le premier dictionnaire contient des _strings_ numériques et le second des entiers, ils ne sont donc pas identiques. 
Pour déboguer, tu peux utiliser `inspect` pour vérifier le contenu de ton dictionnaire.

## `Express` entoure les _strings_ de guillemets

`express` convertit une valeur en code Arturo et renvoie une _string_ qui représente ce code.
Dans ce résultat, les valeurs de type _string_ sont entourées de guillemets.
Par conséquent, `express "1"` renvoie `"1"`, et non `1`.

```arturo
express #[name: "Octavius" age: 22]
; #[name: "Octavius" age: 22 ]
```
```arturo
express #[name: "Octavius" age: "22"]
; #[name: "Octavius" age: "22" ]
```
