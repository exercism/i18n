# Tests

Les tests d'un projet Elm se trouvent dans le sous-répertoire `tests/` de ce projet.
La suite de tests de chaque exercice peut être lancée depuis le répertoire racine de cet exercice.

```bash
$ cd ~/exercism/elm/hello-world
$ elm-test
```

## Surveille les modifications

Relance automatiquement les tests lorsque tu enregistres des modifications :

```bash
$ elm-test --watch
```

## Flux de développement piloté par les tests

Dans la plupart des exercices, les tests sont déjà écrits dans le fichier `tests/Tests.elm`.
Ton objectif est de les faire passer en écrivant le code nécessaire
dans le fichier `src/<exercise>.elm`.
Concentre-toi sur le premier test qui échoue, corrige-le,
puis supprime ou commente le prochain extrait `skip <|` dans le fichier de tests et répète
jusqu'à ce que tous les tests passent.

## Tu es bloqué ?

Ton premier objectif est de faire compiler ton code, même avec `Debug.todo` dedans.
Si tu as l'impression de ne pas savoir comment faire quelque chose,
il est souvent utile d'extraire cette partie dans sa propre fonction non implémentée.

```elm
complexOperationOnMultipleStrings : List String -> List String
complexOperationOnMultipleStrings allStrings =
    List.map complexOperation allStrings


complexOperation : String -> String
complexOperation input =
    Debug.todo "Extracted operation into its own function"
```

Ajouter une annotation de type sur cette fonction extraite
t'aidera à réfléchir et aidera aussi le compilateur à te donner de meilleurs messages d'erreur.

## Nettoie ton code

Pense à exécuter [`elm-format`](https://github.com/avh4/elm-format) sur ton code avant de le soumettre
et même à le configurer dans ton éditeur de texte pour un formatage automatique à l'enregistrement.
