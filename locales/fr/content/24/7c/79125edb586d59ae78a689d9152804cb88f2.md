# À propos

Un **nombre à virgule flottante** est un nombre qui peut comporter une partie fractionnaire, comme `-1.23` ou `3.1415`.

Pour représenter un tel nombre sous la forme d'une séquence d'octets, x86-64 utilise la norme [IEEE-754][ieee].
Les deux formats les plus courants de cette norme sont les nombres à virgule flottante en simple précision et en double précision.
x86-64 prend en charge les deux.

Un nombre à virgule flottante en simple précision est codé sur 32 bits, tandis qu'un nombre en double précision est codé sur 64 bits.

## Les registres XMM

En x86-64, il existe 16 registres dédiés à l'arithmétique à virgule flottante, nommés `xmm0` à `xmm15`.

Ces registres font au moins 128 bits de large, mais les processeurs récents portent cette taille à 256 ou 512 bits.
En pratique, cependant, la plupart des nombres à virgule flottante n'utilisent que les 32 ou 64 bits de poids faible, selon la précision souhaitée.

## Conversion entre nombres

Il existe une famille d'instructions pour convertir entre les formats de nombres : `cvtxx2yy`.

`xx` et `yy` ne sont pas des littéraux, mais des espaces réservés :

- `xx` est un espace réservé pour le type de l'opérande source.
- `yy` est un espace réservé pour le type de l'opérande destination.

Cet espace réservé peut prendre de nombreuses formes, parmi lesquelles :

| espace réservé | signification         |
| ----------- | --------------------- |
| `si`        | entier signé          |
| `ss`        | flottant 32 bits      |
| `sd`        | flottant 64 bits      |

Par exemple :

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

Note qu'il est possible de convertir un entier 32 bits en un flottant 64 bits, ou un entier 64 bits en un flottant 32 bits.
De même, il est aussi possible de convertir un flottant 32 bits en un entier 64 bits, ou un flottant 64 bits en un entier 32 bits.
Autrement dit, la taille des deux opérandes d'une instruction `cvtxx2yy` _n'a pas besoin d'être la même_ :

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

Lorsque le nombre à virgule flottante ne peut pas être exprimé exactement sous la forme d'un entier, `cvtxx2si` arrondit le nombre selon le contrôle d'arrondi d'un registre spécial appelé `mxcsr`.
Il peut s'agir d'un arrondi au plus proche, d'un arrondi vers le bas, d'un arrondi vers le haut ou d'une troncature.
Aucune valeur par défaut n'est garantie à l'entrée d'une fonction.

Note qu'un résultat exact n'est pas arrondi et n'est donc pas affecté par le contrôle d'arrondi.
Par exemple, `42.0` sera _toujours_ converti en `42`.

Il existe une famille d'instructions similaire, de la forme `cvttxx2si` (avec un `t` supplémentaire), qui tronque toujours le résultat.

## Arrondi

La famille d'instructions `roundxx` convertit le flottant de l'opérande source en un flottant arrondi, stocké dans l'opérande destination.

Ici, `xx` est un espace réservé pour le type des opérandes, comme d'habitude : `ss` pour la simple précision et `sd` pour la double précision.

Ces instructions prennent un nombre constant comme troisième opérande.
Ce nombre indique le mode d'arrondi :

| Nombre | Mode         |
| :----- | :----------- |
| 0      | Au plus proche |
| 1      | Plancher (vers le bas) |
| 2      | Plafond (vers le haut) |
| 3      | Troncature   |

Par exemple :

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

Comme ces instructions produisent un résultat exact, elles peuvent servir à préparer un `cvtxx2si`.

## Instructions arithmétiques

De nombreuses opérations sur les nombres à virgule flottante disposent d'instructions dont le nom est similaire à celui de leur équivalent pour les entiers, auquel on ajoute l'espace réservé nécessaire (`ss` ou `sd`) à la fin.
Ces instructions sont à deux opérandes, avec la sémantique habituelle, y compris celles qui effectuent une multiplication ou une division :

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## Déplacement

Les instructions pour déplacer une valeur d'un registre XMM vers un autre sont `movss` et `movsd` :

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

Il n'est **pas** possible de déplacer directement une valeur immédiate (un entier signé constant) vers un registre xmm.
Ce nombre doit d'abord être placé dans un registre à usage général, puis converti à l'aide de `cvtsi2xx` :

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## Comparaisons

Il existe deux groupes d'instructions pour comparer deux nombres à virgule flottante.
Elles se présentent sous la forme `comixx` et `ucomixx`, où `xx` vaut `ss` ou `sd`.
Toutes deux positionnent des drapeaux dans `rflags` comme d'habitude, en suivant la même sémantique que `cmp`.

La différence entre elles est que `ucomixx` positionne le `parity flag (PF)` si l'un des deux nombres à virgule flottante a une valeur `NaN`, tandis que `comixx` lève une exception dans ce cas.

La comparaison entre valeurs à virgule flottante est _non signée_ :

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## Autres instructions

Il existe beaucoup d'autres instructions pour manipuler les nombres à virgule flottante, mettant en œuvre des opérations courantes.
En voici quelques-unes :

| Instruction | Description                                      |
| :---------- | :----------------------------------------------- |
| `sqrtxx`    | Calcule la racine carrée (`sqrt(x)`)             |
| `rcpss`     | Calcule l'inverse (`1/x`)                        |
| `rsqrtss`   | Calcule l'inverse de la racine carrée (`1/sqrt(x)`) |
| `minxx`     | Calcule le minimum (`min(x, y)`)                 |
| `maxxx`     | Calcule le maximum (`max(x, y)`)                 |

Là où un espace réservé `xx` est utilisé, il peut prendre la forme `ss` ou `sd`, comme d'habitude.
Cependant, `rcpss` et `rsqrtss` ne fonctionnent qu'avec des nombres à virgule flottante en simple précision.

Ces instructions sont toutes à deux opérandes.

## Convention d'appel

Dans l'ABI System V, les huit premiers arguments à virgule flottante sont passés aux fonctions dans l'ordre, de `xmm0` à `xmm7`.
Les valeurs à virgule flottante sont renvoyées par les fonctions dans `xmm0` et, si nécessaire, dans `xmm1`.

Tous les registres `xmm` sont librement utilisables ; aucun d'entre eux n'est réservé à l'appelant.

## Mémoire

Les valeurs à virgule flottante peuvent être définies en mémoire en suivant la même sémantique que les entiers de même taille.
NASM (The Netwide Assembler, l'assembleur utilisé par ce parcours) permet aussi de déclarer des valeurs à virgule flottante en notation scientifique.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```

## AVX/AVX2

Les extensions AVX/AVX2 de l'architecture x86-64 introduisent de nouvelles formes à trois opérandes pour les instructions à virgule flottante, qui séparent la destination des sources.
Elles prennent un préfixe `v` (pour _vector_) qui les distingue de la forme SSE historique vue plus haut :

```x86asm
vaddss xmm0, xmm1, xmm2 ; xmm0 = xmm1 + xmm2 (32-bit floating-point)
vmulsd xmm2, xmm3, xmm4 ; xmm2 = xmm3 * xmm4 (64-bit floating-point)
```

Dans ce parcours, nous nous sommes limités aux instructions et aux registres des extensions SSE précédentes.
Cela suffit pour enseigner les bases et garantit la compatibilité avec un large éventail de processeurs.

Cependant, l'exécuteur de tests prend entièrement en charge AVX et AVX2.
Tu es libre de les utiliser.
