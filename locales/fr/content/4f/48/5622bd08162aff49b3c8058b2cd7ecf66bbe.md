# Introduction

## Résultats

Gleam n'utilise pas d'exceptions pour gérer les erreurs : à la place, les fonctions qui peuvent réussir ou échouer renvoient le type générique `Result`.

Le type `Result` est intégré au langage, tu n'as donc pas besoin de le définir ni de l'importer, mais si tu devais le définir toi-même, il ressemblerait à ceci :

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

La variante `Ok` est renvoyée quand une fonction réussit, et la variante `Error` est renvoyée quand une fonction échoue.

Les résultats sont très courants en Gleam, et les développeurs Gleam utilisent souvent le [module `gleam/result`](https://hexdocs.pm/gleam_stdlib/gleam/result.html) pour faciliter leur utilisation.

La fonction `result.map` permet d'appeler une fonction sur la valeur contenue dans un résultat si celui-ci est un `Ok`, ou de laisser passer un `Error` tel quel.

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

La fonction `result.try` est similaire, mais la fonction de rappel doit renvoyer un résultat. C'est utile pour enchaîner plusieurs fonctions qui renvoient des résultats.

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
