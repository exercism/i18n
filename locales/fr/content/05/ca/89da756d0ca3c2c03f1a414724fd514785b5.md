# Tests

Chaque exercice est fourni avec un ensemble de tests unitaires et tout ce qu'il faut pour les compiler et les lancer.
C'est à toi de fournir l'implémentation.

## Lance les tests

Ouvre un terminal dans le dossier de l'exercice, puis lance :

```
make
```

Cette commande compile ta solution et les tests, puis lance les tests.
Relance-la à chaque fois que tu modifies ta solution.

Si tu disposes de l'[Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally), tu peux utiliser cette commande à la place, qui lance aussi `make` :

```
exercism test
```

Pour supprimer les fichiers créés par la compilation, lance `make clean`.

### Sans make

Si tu n'as pas `make` (sous Windows, par exemple), tu peux compiler et lancer les tests directement.
Pour l'exercice « Bob » :

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

Lance ensuite les tests sous Linux ou macOS :

```
./run_tests
```

Ou sous Windows :

```
.\run_tests
```

## Travaille un exercice

Les fichiers de chaque exercice portent son nom.
Pour l'exercice « Bob » :

| Fichier          | Contenu                                                           |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90`        | un squelette de la solution, prêt à être complété                 |
| `bob_test.f90`   | les tests                                                         |
| `TesterMain.f90` | la bibliothèque de tests                                          |
| `Makefile`       | les instructions pour `make`                                      |
| `CMakeLists.txt` | les instructions pour [CMake](#using-cmake-instead), qui est facultatif |

Tu n'as besoin de modifier que le fichier de solution.

Chaque exercice se travaille en répétant ces étapes jusqu'à ce que tous les tests passent :

- Corrige les erreurs de compilation, puis lance les tests pour voir lesquels échouent.
- Implémente juste ce qu'il faut pour que le prochain test qui échoue passe.
- Réécris ton implémentation pour améliorer la lisibilité, réduire les duplications, etc.
- Relance les tests et passe au prochain test qui échoue.

Un message est affiché pour chaque test qui échoue, suivi d'un résumé.
Si des tests échouent, `make` se termine sur une erreur.

Chaque test comporte un commentaire qui le décrit, suivi du test proprement dit, qui commence par `call assert_equal`, par exemple :

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Pour désactiver un test, il suffit de le mettre en commentaire avec un `'!'`, par exemple :

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## Utilise CMake à la place

Tu n'as pas besoin de CMake, mais il peut être utile si tu travailles dans un IDE comme Visual Studio ou Xcode, ou si tu utilises un compilateur autre que GFortran.

Le dossier de l'exercice doit conserver son nom d'origine, car CMake s'en sert pour retrouver les fichiers source.
Place-toi dans le dossier de l'exercice :

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

Après avoir modifié ta solution, seules les deux dernières commandes sont nécessaires.

**Remarque :** lance toujours `cmake` depuis un dossier séparé, comme `build`.
Lancer `cmake .` dans le dossier de l'exercice remplace le `Makefile` fourni avec l'exercice.

CMake choisit un générateur adapté à ton système.
Pour en choisir un autre, utilise l'option `-G`, par exemple `cmake -G Xcode ..`.
Lance `cmake --help` pour lister les générateurs que tu peux utiliser.
Avec Visual Studio ou Xcode, lance les tests avec `ctest -V -C Debug`.

Si ton dossier d'exercice ne contient pas de `Makefile`, c'est qu'il a été téléchargé avant l'ajout de ces fichiers aux exercices.
Tu peux quand même utiliser CMake.
