# Tests

Chaque exercice fournit les tests unitaires.
C'est à toi de fournir l'implémentation.
Chaque fichier produit un exécutable console qui lance les tests.
Lancer l'exécutable de test affiche un message pour chaque test qui échoue et renvoie un code de sortie non nul lorsque des tests échouent.

*Note* : ton code est testé par la suite de tests à chaque fois que tu compiles ton projet.
Si ton code ne passe pas un ou plusieurs tests mais reste du code D valide, il sera quand même compilé.

Pour chaque exercice, la démarche est la suivante :

* Lancer les tests avec `dub test`
  * Si tu as choisi de ne pas installer DUB, tu peux à la place utiliser `dmd source/*.d -de -w -main -unittest`, puis exécuter le binaire obtenu.
* Pour chaque test unitaire :
  * Corrige les erreurs de compilation pour que le test échoue.
  * Implémente juste ce qu'il faut pour que le test passe.
  * Réécris ton implémentation pour améliorer la lisibilité, réduire les duplications, etc.
  * Active le test suivant.

*Note :* D prend en charge les tests unitaires directement dans le langage, c'est pourquoi les tests unitaires se trouvent généralement dans le même fichier que l'implémentation.
Les tests unitaires sont exécutés avant le corps de main et sont activés dans l'exécutable final grâce à l'option de compilation **-unittest**.

## Interprète la sortie des tests unitaires

Si tous les tests réussissent, la sortie des tests peut ressembler à ceci :

```none
$ dub test
             Generating test runner configuration 'dnd-character-test-library' for 'library' (library).
    Starting Performing "unittest" build using dmd for x86_64.
    Building dnd-character ~master: building configuration [dnd-character-test-library]
     Linking dnd-character-test-library
     Running dnd-character-test-library
1 modules passed unittests
```
