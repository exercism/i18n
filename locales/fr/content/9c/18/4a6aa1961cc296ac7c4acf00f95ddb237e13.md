# Inclusion de code

`circus-acts` utilisait `<` pour dire qu'une classe *peut faire* ce qu'une classe abstraite décrit. Il ne disait rien sur la façon de le faire.

`include` est l'autre moitié : il prend le code lui-même d'une autre classe et en met une copie dans celle-ci.

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

`JAZZ_ROUTINE::count` vaut 8, sans que `JAZZ_ROUTINE` ait besoin de le mentionner.

## Ce sont deux décisions distinctes

La plupart des langages les réunissent : un seul `extends` transmet le code et rend la sous-classe utilisable partout où la superclasse l'est. Sather les garde séparées.

| Ce qu'on écrit | Ce que ça dit |
| --- | --- |
| `class A < $B` | un `A` peut être utilisé partout où un `$B` est attendu |
| `class A is include B` | `A` commence avec une copie du code de `B` |

L'un sans l'autre, ou les deux. Inclure une classe **n'en fait pas** un sous-type : après `include WARM_UP`, un `JAZZ_ROUTINE` ne peut toujours pas être utilisé là où un `WARM_UP` est attendu, et rien ne prétend le contraire.

## Renommage

On peut inclure une routine sous un autre nom :

```sather
   include WARM_UP count -> warm_up_count;
```

Plusieurs se séparent par des virgules :

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## Laisse-en une de côté

Le renommage vers *rien* l'omet, ce qui permet de la remplacer :

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

`count` est inclus comme d'habitude ; `describe` ne l'est pas, donc en écrire une ici ne crée pas de conflit. Sans le `describe -> ;`, le compilateur refuserait : deux routines de même nom et de mêmes arguments dans une même classe constituent une erreur, et Sather ne devinera pas laquelle tu voulais.

C'est là toute la différence avec une redéfinition dans la plupart des langages : le remplacement est annoncé plutôt que sous-entendu.
