# À propos

Une [boucle][control] est une suite d'instructions qui peut être exécutée plusieurs fois, jusqu'à ce qu'une condition d'arrêt soit remplie.

En x86-64, une boucle est généralement créée à l'aide d'un saut vers une étiquette précédente :

```x86asm
example_loop:
    ...
    jmp example_loop
```

Note qu'un saut inconditionnel vers une étiquette précédente transfère toujours l'exécution à cette étiquette.
Cela signifie que la boucle va se répéter indéfiniment, à moins qu'un autre saut ne mène en dehors de la séquence répétée.

Par exemple, cette boucle ne se termine jamais :

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Et cette boucle peut se terminer, selon que la condition est remplie ou non :

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Boucles de comptage

Une boucle de comptage se termine presque toujours de la même façon : une instruction qui met à jour un compteur ou compare deux valeurs, immédiatement suivie d'un saut conditionnel qui décide s'il faut repartir pour un tour.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0` n'est pas nécessaire dans le code ci-dessus, car `sub rsi, 1` positionne déjà le `zero flag (ZF)` lorsque le résultat vaut `0`.

Bien que `cmp` soit le principal moyen de tester des conditions en assembleur, de nombreuses instructions mettent à jour les drapeaux.
Par exemple, beaucoup d'instructions arithmétiques entières ou bit à bit mettent à jour `ZF` lorsque le résultat vaut `0`, et `SF` lorsqu'il est négatif (c'est-à-dire que le bit de poids fort vaut 1).

Tu peux consulter une [référence][reference] pour voir quels drapeaux sont modifiés par chaque instruction.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Note que dans l'exemple ci-dessus, on suppose que `rsi` est supérieur à `0`.
S'il valait `0`, alors `sub rsi, 1` ramènerait `rsi` à `-1`, ce qui correspond à un très grand nombre non signé.
Il faudrait encore `18,446,744,073,709,551,615` itérations avant que la boucle ne se termine enfin.
De plus, comme la longueur du tableau vaut `0`, tout accès à la mémoire se ferait hors limites.

Si rien ne garantit la longueur d'un tableau, deux approches sont courantes.

La première consiste à déplacer la condition d'arrêt au début de la boucle, puis à placer un saut inconditionnel à la fin :

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

La seconde consiste à tester une fois le cas d'un tableau de longueur nulle avant le début de la boucle :

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Cette seconde approche est généralement plus efficace que la première, car le corps de la boucle contient moins de branchements.
Tu en apprendras davantage dans un prochain concept.

## Micro-opérations

Un processeur n'exécute pas directement une instruction telle que `add` ou `jnz`.
Le front-end du processeur commence par _décoder_ chaque instruction en une ou plusieurs étapes internes plus petites, appelées **micro-opérations** (ou **micro-ops**).
Le processeur planifie ensuite ces micro-opérations et les exécute, souvent plusieurs par cycle et dans un ordre différent de leur ordre d'origine.

La plupart des instructions simples se décodent en une seule micro-opération, tandis qu'une instruction plus complexe peut se décoder en plusieurs.
Comme la charge de travail réelle du processeur est le flux de micro-opérations, en produire moins pour une même tâche est un moyen de rendre le code plus rapide.

## Macrofusion

Comme on l'a mentionné plus haut, une boucle se termine généralement par une sorte de saut conditionnel.
C'est si courant que les processeurs modernes sont optimisés pour ce schéma au moment du décodage.

Une instruction qui positionne des drapeaux, immédiatement suivie d'un saut conditionnel qui lit ces drapeaux, peut être décodée en **une seule** micro-opération, au lieu d'une pour chacune.
C'est ce qu'on appelle la **macrofusion**.

La paire fusionnée se comporte comme une seule opération : la mise à jour du compteur et la décision de branchement ont lieu ensemble, au sein d'une même micro-opération.
Le flux de contrôle de la boucle ne coûte alors presque rien en plus du travail que la boucle effectue réellement.

En règle générale, deux types de paires fusionnent habituellement de cette façon :

- Les instructions arithmétiques telles que `add` ou `sub`, immédiatement suivies d'un saut conditionnel.
- Un `cmp`, `test` ou `and`, immédiatement suivi d'un saut conditionnel.

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

La fusion ne se produit que lorsque le saut conditionnel vient **immédiatement** après l'instruction qui positionne les drapeaux, sans rien entre les deux.

~~~~exercism/note
La macrofusion dépend du processeur et il existe des variations selon les instructions qui fusionnent avec tel ou tel saut conditionnel.

Une référence utile est [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
La section 3.4.2.2 (Optimizing for Macrofusion) du [Intel optimization reference manual][intel-opt] liste également les paires fusionnables pour les processeurs Intel.

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## L'instruction `loop`

Certaines instructions permettent de créer un comportement de type boucle.
L'une d'elles est [loop][loop].

Son unique opérande est une étiquette qui contient l'adresse du début de la boucle.

L'instruction `loop` utilise la valeur de `rcx` comme compteur, en la décrémentant de 1 à chaque fois.
Une fois que la valeur de `rcx` atteint zéro, la boucle se termine et l'exécution se poursuit séquentiellement :

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

Il existe deux variantes de l'instruction `loop` qui vérifient le drapeau zéro (`ZF`) à chaque itération.
Outre l'arrêt de la boucle dès que `rcx` atteint zéro, elles s'arrêtent aussi lorsque la condition n'est _pas_ remplie.

| instruction       | condition |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

Le `ZF` **n'est pas positionné** par ces instructions.
Il doit y avoir un `cmp`, un `test` ou une autre instruction qui modifie `ZF` avant celles-ci :

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
Malgré leur commodité, `loop`, `loope` et `loopne` sont généralement beaucoup plus lentes sur les processeurs modernes que la séquence équivalente `sub`/`jnz` ou `cmp`/`jnz`.

Une bonne référence sur les performances des instructions sur de nombreux processeurs différents est [Agner's tables][agner-tables].

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
