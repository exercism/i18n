# Instructions

Dans cet exercice, on va traiter des lignes de journal.

Chaque ligne de journal est une _string_ au format suivant : `"[<LVL>]: <MESSAGE>"`.

Voici les différents niveaux de journalisation :

- `TRC` (trace)
- `DBG` (débogage)
- `INF` (info)
- `WRN` (avertissement)
- `ERR` (erreur)
- `FTL` (fatal)

Tu as trois tâches.

## 1. Analyse le niveau de journalisation

Définis une énumération `LogLevel` comportant six éléments correspondant aux niveaux de journalisation ci-dessus.

- `Trace`
- `Debug`
- `Info`
- `Warning`
- `Error`
- `Fatal`

Ensuite, implémente la méthode (_statique_) `LogLine.ParseLogLevel()` pour analyser le niveau de journalisation d'une ligne de journal :

```csharp
LogLine.ParseLogLevel("[INF]: File deleted")
// => LogLevel.Info
```

## 2. Prends en charge un niveau de journalisation inconnu

Malheureusement, il arrive parfois que certaines lignes de journal aient un niveau de journalisation inconnu. Pour gérer ces lignes de journal avec élégance, ajoute un élément `Unknown` à l'énumération `LogLevel`, qui doit être renvoyé lors de l'analyse d'un niveau de journalisation inconnu :

```csharp
LogLine.ParseLogLevel("[XYZ]: Overly specific, out of context message")
// => LogLevel.Unknown
```

## 3. Convertis une ligne de journal au format court

Le niveau de journalisation d'une ligne de journal est assez verbeux. Pour réduire l'espace disque nécessaire au stockage des lignes de journal, un format court a été développé : `"[<ENCODED_LEVEL>]:<MESSAGE>"`.

Le niveau de journalisation encodé est une simple correspondance entre un niveau de journalisation et un nombre :

- `Unknown` - `0`
- `Trace` - `1`
- `Debug` - `2`
- `Info` - `4`
- `Warning` - `5`
- `Error` - `6`
- `Fatal` - `42`

Implémente la méthode (_statique_) `LogLine.OutputForShortLog()` qui peut produire le format de ligne de journal raccourci :

```csharp
LogLine.OutputForShortLog(LogLevel.Error, "Stack overflow")
// => "6:Stack overflow"
```
