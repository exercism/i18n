# utilisation des spécifications

[comment]: # (Cet avertissement est émis lorsque la solution ne comporte pas de spécification de type)

Inclus des [spécifications de type](https://elixir-lang.org/getting-started/typespecs-and-behaviours.html#types-and-specs) (`@spec`) pour communiquer le contrat entre les entrées et la sortie d'une fonction.

- Elixir est un langage à typage dynamique, ce qui signifie que les vérifications de type n'ont lieu qu'à l'exécution. L'utilisation de spécifications de type permet aux _linters_ et aux outils d'analyse statique comme [`Dialyxir`](https://hexdocs.pm/dialyxir/readme.html) (basé sur [`Dialyzer`](http://erlang.org/doc/man/dialyzer.html) d'Erlang) d'évaluer le code à la recherche de comportements inattendus.
- Tu peux trouver une [liste complète](https://hexdocs.pm/elixir/typespecs.html#basic-types) de tous les types intégrés dans la [documentation du langage](https://hexdocs.pm/elixir/typespecs.html#content)
- les types peuvent être spécifiés avec ou sans parenthèses : `atom()` ou `atom`
  - le style d'Exercism pour Elixir consiste à spécifier sans parenthèses.

```elixir
# Example 1
@spec add_one(int) :: int
def add_one(n) when is_integer(n) do
  n + 1
end

# Example 2
@spec hello(String.t) :: String.t
def hello(what \\ "world") when is_binary(what) do
  "Hello, #{what}"
end
```
