# Classes abstraites

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## Le $ fait partie du nom

Toute classe abstraite porte un nom qui commence par un `$`, et seules les classes abstraites en ont un. Ainsi, un type qui commence par `$` est un type dont on ne peut pas créer d'objet, et c'est visible partout où ce nom apparaît.

## Ce qu'on peut y mettre

Des signatures de routines et d'itérateurs, qui s'arrêtent au point-virgule. Pas de corps, pas d'attributs, pas de `create`. Une classe abstraite décrit ce qu'on peut *demander* à un objet, jamais ce qu'il contient.

## Conformité

```sather
class TRAPEZE < $ACT is
```

La classe doit définir chaque routine listée, avec des types d'arguments et un type de retour qui correspondent. Cette vérification a lieu à la compilation.

Une classe peut être conforme à plusieurs :

```sather
class TRAPEZE < $ACT, $RISKY is
```

et les classes abstraites peuvent hériter les unes des autres :

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## Où se produit le _dispatch_

Une variable de type abstrait contient une référence vers un objet conforme. Quand on appelle une routine sur cette variable, c'est la version qui appartient à la classe réelle de l'objet qui est choisie, au moment de l'exécution.

C'est le seul endroit où Sather décide quelque chose au moment de l'exécution. Un appel sur une variable de type concret est fixé à la compilation.

## typecase

Parfois, le genre compte vraiment. `typecase` pose la question :

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

À l'intérieur d'une branche, la variable prend le type plus étroit. N'y recours que rarement : un `typecase` sur chaque genre d'acte est généralement une routine qui aurait dû se trouver dans la classe abstraite depuis le début.

## $OB

`$OB` est la classe abstraite à laquelle tout objet est conforme. Elle est parfois utile, mais c'est le plus souvent le signe qu'un type a été perdu en chemin.

## Pourquoi pas l'héritage ?

Sather sépare deux choses que la plupart des langages réunissent. `<` dit seulement ce qu'une classe peut *faire*. Obtenir une implémentation depuis ailleurs se fait avec `include`, qui arrive deux exercices plus loin, et qui est une décision à part.
