# Introduction

L'égalité des types simples (les _strings_ et les primitives) se teste généralement avec `==` et `!=`.

Les types référence (les instances de classes) se comparent à l'aide de la méthode `Equals()` héritée de `Object`. Si ton objectif, avec le test d'égalité, est de vérifier que deux objets sont exactement la même instance, alors il te suffit de t'appuyer sur l'implémentation de `Object`. Sinon, tu dois redéfinir `object.Equals()`.

Si tu sais que toutes les instances de ta classe sont créées au même endroit, par exemple les personnages d'un jeu ou d'une simulation, alors l'égalité de référence suffit. Cependant, il est probable que plusieurs instances d'une même entité du monde réel soient créées (depuis une base de données, à partir d'une saisie de l'utilisateur, via une requête web). Dans ce cas, les valeurs qui identifient l'entité de manière unique doivent être testées par égalité. Par conséquent, `Equals()` doit être redéfinie et les membres de données appropriés de ta classe doivent être testés par égalité.

Une méthode `Equals()` redéfinie contiendra des tests d'égalité sur les membres de types simples à l'aide de `==`, et sur les types référence avec des appels récursifs à `Equals()`.

La classe `Object` fournit les méthodes appropriées pour comparer deux objets et détecter s'il s'agit d'une seule et même instance.

## `Object.GetHashCode()`

La méthode `Object.GetHashCode()` renvoie un code de hachage sous la forme d'un entier de 32 bits. Le code de hachage est utilisé par les classes _dictionnaire_ et _ensemble_ telles que `Dictionary<T>` et `HashSet<T>`pour stocker et récupérer des objets de manière performante.

La relation entre le code de hachage et l'égalité est la suivante : si deux objets sont égaux (la méthode `Equal()` renvoie vrai), alors `GetHashCode()` doit renvoyer la même valeur pour les deux objets. Cela ne s'applique pas dans l'autre sens. La relation n'est pas symétrique. Ce n'est pas parce que deux objets ont le même code de hachage qu'ils sont forcément égaux. Imagine une fonction de recherche qui se rend d'abord dans un « compartiment » en fonction du code de hachage, puis sélectionne l'élément précis à l'aide du test d'égalité.

La documentation de l'API de la bibliothèque HashCode décrit la meilleure façon de générer un code de hachage.

Les valeurs utilisées dans le test d'égalité doivent rester stables pendant toute la durée d'utilisation de la collection hachée. Si tu ajoutes un objet à la collection avec un jeu de valeurs, puis que tu modifies ces valeurs, le code de hachage ne pointera plus vers le bon « compartiment ». En pratique, cela signifie que l'objet doit être immuable. D'autres approches risquent de créer des pièges pour les mainteneurs.
