# Introduction aux pipelines et aux listes de commandes

On a vu comment écrire des commandes simples, où une commande est suivie de ses arguments.
On va maintenant voir comment construire des commandes plus complexes en composant des commandes simples.

## Entrées et sorties

Avant de commencer, une brève introduction aux entrées/sorties.

Les processus disposent de « canaux d'entrée/sortie standard ».

* Un processus peut consommer une _entrée_ sur « stdin ».
* Un processus peut émettre une _sortie_ sur « stdout ».
* Un processus peut émettre une _sortie d'erreur_ sur « stderr ».

La commande `tr` en est un exemple très pur.
Elle se contente de lire du texte depuis son entrée, d'effectuer des translittérations de caractères, puis d'afficher le texte obtenu sur sa sortie.

On verra plus en détail la manipulation des canaux « stdio » plus loin dans le programme.

## Pipelines

C'est l'une des « fonctionnalités phares » de la programmation shell.
Les pipelines permettent de créer des transformations élaborées sur un flux de texte.

Pour produire une liste d'utilisateurs triée :

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

Le symbole pipe (`|`) relie la sortie d'une commande à l'entrée d'une autre.
`cut` lit la sortie de `cat`, et `sort` lit la sortie de `cut`.

~~~~exercism/advanced
* Par défaut, chaque commande d'un pipeline s'exécute dans un sous-shell distinct.
  (Un sous-shell est un processus enfant qui est une copie du shell en cours d'exécution.)

* L'utilisation de pipelines a un coût en performance.
  Si tu te retrouves avec de longs pipelines composés de commandes similaires, envisage de les regrouper en une seule commande.
  Par exemple, les pipelines qui utilisent plusieurs instances de `grep`, `cut`, `sed`, `awk` et `tr` peuvent généralement être combinés en une seule commande `awk` pour gagner en efficacité.

* Le code de sortie d'un pipeline est le code de sortie de la dernière commande du pipeline.
  Cela signifie que si une commande précédente a échoué mais que la dernière a réussi, le code de sortie du pipeline entier vaut zéro.

  Il existe un paramètre du shell qui peut changer cela ;
  si l'option « pipefail » est activée (avec `set -o pipefail`), alors le code de sortie du pipeline sera :
  * zéro si toutes les commandes réussissent, sinon
  * le _**dernier** code de sortie non nul_ des commandes du pipeline.
~~~~

## Listes de commandes

Une liste de commandes est une suite de pipelines séparés par `;` (ou un saut de ligne), `&&` ou `||`.

* `A; B` est une liste de commandes où `B` s'exécute après la fin de `A`.
* `A && B`, où `B` ne s'exécute que si `A` réussit (se termine avec un code de sortie zéro).
* `A || B`, où `B` ne s'exécute que si `A` échoue (se termine avec un code de sortie non nul).

Le code de sortie d'une liste de commandes est le code de sortie de la dernière commande exécutée.

Les opérateurs `&&` et `||` peuvent être enchaînés pour que la commande suivante s'exécute de façon conditionnelle selon le code de sortie des commandes précédentes.
Par exemple

```bash
A && B && C && D || E
```

* B s'exécute si A réussit,
* C s'exécute si A et B réussissent,
* D s'exécute si A, B et C réussissent,
* E s'exécute si **l'une** des commandes A, B, C ou D échoue.

~~~~exercism/caution
Utilise ces opérateurs logiques avec parcimonie.
Ils peuvent vite rendre le code illisible, ou la logique difficile à comprendre.

Par exemple, tu peux penser que ces deux extraits sont identiques :

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

La différence est la suivante : quand C s'exécute-t-il ?

* Dans le premier extrait (l'instruction `if`), C ne s'exécute que si A échoue.
* Dans le second extrait, C s'exécutera si A échoue _ou si A réussit mais que B échoue_ !
~~~~

### Utilisations des listes de commandes

Voici quelques exemples où les listes de commandes permettent de simplifier le code.

#### Lis des blocs de lignes dans un fichier

Supposons que tu disposes d'un fichier de données contenant des informations sur des triangles,
et qu'un triangle soit représenté par trois lignes distinctes portant les longueurs de ses côtés.

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

Tu peux utiliser une boucle _while_ dont la condition est constituée de trois commandes read distinctes :

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

En supposant que `is_pythagorean` soit une commande qui détermine si les trois côtés satisfont l'équation de Pythagore, la sortie serait :

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### Assertions

De nombreux langages de programmation proposent une forme d'assertion où une exception est levée si une condition n'est pas remplie

```
assert(user == "Administrator", "wrong user");
```

On peut utiliser un opérateur OU en Bash pour simuler cette fonction :

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## Considérations de style

Les longues listes de commandes deviennent vite difficiles à lire.
Un usage généreux des sauts de ligne peut beaucoup aider.

Prenons l'exemple suivant, où un mot est ajouté à un tableau lorsque deux conditions sont remplies.

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

Bash permet d'ajouter un saut de ligne après un pipe ou un opérateur logique.

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

Cependant, l'opérateur peut facilement passer inaperçu en fin de ligne.
Utiliser une _continuation de ligne_ permet de placer l'opérateur en début de ligne, ce qui rend plus évident le fait que la liste se poursuit :

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
Une _continuation de ligne_ est la séquence de deux caractères « barre oblique inversée » et « saut de ligne » (`\` + `\n`).
Quand Bash rencontre cette séquence, elle est simplement retirée du code, ce qui _prolonge_ la ligne courante avec la ligne suivante.
Veille à ne laisser aucun espace entre la barre oblique inversée et le saut de ligne.
~~~~

Voici un autre exemple

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

ou

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
