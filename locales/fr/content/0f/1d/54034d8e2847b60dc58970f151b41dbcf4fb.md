# Instructions complémentaires

## Remarques sur l'implémentation de `smallest` et `largest` :

Les deux fonctions doivent prendre deux arguments nommés :
- `max_factor` : int
- `min_factor` : int, 0 par défaut

Leur valeur de retour doit être un `tuple -- (value, factors)` où `value` est le palindrome lui-même, et `factors` est un `iterable` contenant les deux facteurs du palindrome, dans un ordre arbitraire.


## Messages d'exception

Il est parfois nécessaire de [lever une exception](https://docs.python.org/3/tutorial/errors.html#raising-exceptions). Quand tu le fais, tu dois toujours inclure un **message d'erreur explicite** pour indiquer l'origine de l'erreur. Cela rend le code plus lisible et facilite grandement le débogage. Dans les cas où tu sais que l'origine de l'erreur sera d'un certain type, tu peux choisir de lever l'un des [types d'erreur intégrés](https://docs.python.org/3/library/exceptions.html#base-classes), mais tu dois tout de même inclure un message explicite.

Cet exercice demande en particulier d'utiliser l'[instruction `raise`](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement) pour « lever » une `ValueError` quand la fonction `largest()` ou `smallest()` reçoit une paire de facteurs qui ne sont pas dans la bonne plage. Les tests ne réussiront que si tu lèves l'`exception` et que tu y ajoutes un message.

Pour lever une `ValueError` avec un message, écris ce message comme argument du type `exception` :

```python
# if the max_factor is less than the min_factor
raise ValueError("min must be <= max")
```
