# Tags d'analyseur

Les tags d'analyseur servent à identifier _comment_ une solution a été résolue.

Ces tags peuvent ensuite servir à :

- Lier une solution à des approches
- Lier une solution à des concepts
- Rechercher des solutions portant certains tags

## Format

Un tag est une _string_ au format suivant : `<category>:<thing>`.

Nous prenons en charge quatre catégories, du niveau le plus élevé au plus bas :

| Catégorie   | Description                                     | Spécificité                                  | Exemples                              |
| ----------- | ----------------------------------------------- | -------------------------------------------- | ------------------------------------- |
| `paradigm`  | Un [paradigme de programmation][programming-paradigms] | Très haut niveau, pas spécifique à un parcours | `imperative`, `functional`      |
| `technique` | Une technique utilisée                          | Haut niveau, la plupart ne sont pas spécifiques à un parcours | `recursion`, `immutability` |
| `construct` | Une construction du langage                     | Beaucoup ne sont pas spécifiques à un parcours | `bitwise-and`, `for-loop`           |
| `uses`      | Un usage propre à un langage, comme les types ou les méthodes | Bas niveau, spécifique à un parcours | `DateTime.add_seconds`, `IEnumerable` |

Quelques exemples de tags :

- `paradigm:functional`
- `technique:recursion`
- `construct:bitwise-and`
- `uses:DateTime.add_seconds`

## Tags couramment utilisés

Bien que chaque parcours soit libre d'associer les tags qu'il veut aux solutions, nous recommandons d'utiliser autant que possible la liste de tags couramment utilisés ci-dessous.
Un ensemble de tags commun nous permet de faire des choses sympathiques, comme relier des solutions entre parcours.

### Paradigme

| Tag                        | Description                                                      |
| -------------------------- | ---------------------------------------------------------------- |
| `paradigm:array`           | utilise la [programmation par tableaux][array-programming].      |
| `paradigm:declarative`     | utilise la [programmation déclarative][declarative-programming]. |
| `paradigm:functional`      | utilise la [programmation fonctionnelle][functional-programming]. |
| `paradigm:generic`         | utilise la [programmation générique][generic-programming].       |
| `paradigm:imperative`      | utilise la [programmation impérative][imperative-programming].   |
| `paradigm:logic`           | utilise la [programmation logique][logic-programming].           |
| `paradigm:meta`            | utilise la [métaprogrammation][metaprogramming].                 |
| `paradigm:object-oriented` | utilise la [programmation orientée objet][object-oriented-programming]. |
| `paradigm:procedural`      | utilise la [programmation procédurale][procedural-programming].  |
| `paradigm:reflective`      | utilise la [programmation réflective][reflective-programming].   |
| `paradigm:stack-oriented`  | utilise la [programmation orientée pile][stack-oriented-programming]. |
