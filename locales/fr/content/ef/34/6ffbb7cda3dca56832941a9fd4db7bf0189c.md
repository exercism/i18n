# Introduction

## `Base.@kwdef`

La macro `Base.@kwdef` peut être utilisée pour définir automatiquement des constructeurs qui prennent des arguments nommés pour la définition d'une [struct][struct].
Elle permet aussi de définir des valeurs par défaut pour les champs.

Par exemple, la définition suivante

```julia
Base.@kwdef struct HumanStats
    birthyear::Int
    height::Int
    mass::Int
    bmi::Float64 = mass / (0.01 * height)^2
end
```

définit trois constructeurs à la fois

```julia-repl
julia> methods(HumanStats)
# 3 methods for type constructor:
[1] HumanStats(; birthyear, height, mass, bmi) [...]
[2] HumanStats(birthyear::Int64, height::Int64, mass::Int64, bmi::Float64) [...]
[3] HumanStats(birthyear, height, mass, bmi) [...]
```

y compris un constructeur basé sur des arguments nommés

```julia-repl
julia> HumanStats(
           birthyear = 2002,
           height = 193,
           mass = 83
       )
HumanStats(2002, 193, 83, 22.28247738194314)
```

tandis que la définition standard

```julia
struct HumanStats
    birthyear::Int
    height::Int
    mass::Int
    bmi::Float64
end
```

ne définit que les deux suivants

```julia-repl
julia> methods(HumanStats)
# 2 methods for type constructor:
[1] HumanStats(birthyear::Int64, height::Int64, mass::Int64, bmi::Float64) [...]
[2] HumanStats(birthyear, height, mass, bmi) [...]
```

et nécessiterait de définir manuellement un constructeur basé sur des mots-clés.

### Quand utiliser `Base.@kwdef` ?

Les constructeurs basés sur des mots-clés sont particulièrement utiles pour construire des structs qui prennent un grand nombre d'arguments, en particulier lorsque le type ou la valeur des arguments n'a pas de lien direct avec la signification des arguments.

Prenons la définition suivante :

```julia
dirk = BasketballPlayer(1978, 1994, 2019, 213, 111, 42, 1998, [2011], 31560, 11489, 3651)
```

On ne voit pas clairement ce que chaque valeur signifie sans connaître la définition du type.
Et même si on connaît la définition, on devrait probablement consulter l'ordre encore et encore.

Cependant, lorsqu'on utilise un constructeur basé sur des mots-clés, leur signification est immédiatement évidente :

```julia
dirk = BasketballPlayer(
    birthyear = 1978,
    career_start = 1994,
    career_end = 2019,
    height = 213,
    weight = 111,
    number = 42,
    drafted = 1998,
    championships = [2011],
    points = 31560,
    rebounds = 11489,
    assists = 3651
)
```

~~~~exercism/caution
`Base.@kwdef` n'est pas exportée et n'est pas documentée dans le manuel, et ne fait donc pas partie de [l'API publique de Julia][public-api].
Cela signifie que son interface n'est techniquement pas garantie comme stable et peut changer entre les versions mineures de Julia.

Cependant, la macro est largement utilisée dans l'écosystème, et il est peu probable qu'elle soit modifiée d'une manière incompatible.

Pour plus d'informations, voir :

- [« Que fait `@kwdef` ? »][discourse-kwdef]
- [Julia Issue #32659 pour ajouter `@kwdef` au manuel][add-kwdef-to-manual]
- [Julia Issue #33192 pour exporter `@kwdef`][export-kwdef]
