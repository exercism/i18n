# À propos

En JavaScript, les valeurs peuvent être de différents types. On peut changer le type d'une variable à l'aide d'une _conversion de type_ explicite.
En plus de cela, JavaScript effectue aussi une _coercition de type_ (conversion de type implicite) lorsque le contexte l'exige.

## Conversion de type

JavaScript ne dispose pas d'une construction permettant de convertir une valeur vers un (autre) type, contrairement à beaucoup d'autres langages, mais on peut utiliser à la place certains utilitaires intégrés.
En particulier, les objets globaux `Boolean`, `Number` et `String` peuvent être utilisés comme des fonctions pour convertir une valeur vers le type correspondant.

### Convertir en booléen (valeurs _truthy_ et _falsy_)

Avec `Boolean(value)`, on peut convertir n'importe quelle valeur en booléen.
Comment ça marche ?

Il existe un ensemble fixe de valeurs, dites _falsy_, qui sont converties en `false`.
Surtout, `false`, `0`, la _string_ vide, `null`, `undefined` et `NaN` sont _falsy_.
L'[article MDN sur « Falsy »][mdn-falsy] donne la liste complète.

Pour toutes les autres valeurs, `Boolean` renvoie `true`.
Ces valeurs sont appelées _truthy_.

```javascript
Boolean(-1);
// => true

Boolean(0);
// => false

Boolean(' ');
// => true

Boolean('');
// => false
```

Note que, d'après les règles décrites, `'0'`, `'false'`, `[]` et `{}` sont **_truthy_** en JavaScript.

### Convertir en nombre

On peut utiliser `Number(value)` pour convertir une valeur en nombre.
Les espaces au début et à la fin d'une _string_ sont ignorés, et une _string_ vide est convertie en `0`.
Si on essaie de convertir une valeur non primitive ou une _string_ qui ne représente pas un nombre, **aucune** erreur ne sera levée.
Le résultat est alors `NaN` ([Not-A-Number][mdn-nan]).

```javascript
Number('  -12.34  ');
// => -12.34

Number('1,2');
// => NaN

Number('1 2');
// => NaN

Number('');
// => 0

Number('10e3');
// => 10000

Number({ key: '123' });
// => NaN
```

Ci-dessous, on peut voir ce que `Number` renvoie pour d'autres valeurs primitives.

```javascript
Number(true);
// => 1

Number(false);
// => 0

Number(null);
// => 0

Number(undefined);
// => NaN
```

Note que, contrairement au dernier exemple, `Number()` appelé sans aucun argument est défini comme renvoyant `0`.

JavaScript fournit aussi les fonctions `parseInt` et `parseFloat`.
Elles appliquent des règles plus souples sur les _strings_ qui peuvent être converties en nombre.
Pour cette raison, il vaut mieux privilégier `Number` comme fonction de conversion, afin d'éviter des résultats inattendus.

```javascript
parseInt('123a45');
// => 123

Number('123a45');
// => NaN
```

### Convertir en _string_

Avec `String(value)`, tu peux convertir une valeur en _string_.
Le résultat est celui que l'on attend pour des valeurs primitives.

```javascript
String(12.34);
// => '12.34'

String(false);
// => 'false'

String(null);
// => 'null'

String(undefined);
// => 'undefined'
```

Pour les tableaux, la fonction `String` applique la conversion en _string_ à chaque élément, puis joint les résultats avec une virgule.
Tu peux aussi appliquer toi-même la [méthode `join`][mdn-join], par exemple pour personnaliser le séparateur.
Dans ces cas-là, cependant, `null` et `undefined` sont convertis en une _string_ vide.

```javascript
String([42, null, true, 'abc']);
// => '42,,true,abc'
```

Pour les objets, `String` renvoie par défaut un texte peu utile.

```javascript
String({ key: 'value' });
// => '[object Object]'
```

Tu peux personnaliser le comportement de conversion, par exemple en fournissant une méthode `toString`.
La section « [Conversion d'un objet en valeur primitive][custom-conversion] » sur javascript.info explique les détails.

Une autre façon courante d'obtenir une meilleure représentation sous forme de _string_ pour les objets et les tableaux est d'utiliser l'[encodage JSON][json].
Tu peux convertir en _string_ avec `JSON.stringify`, puis revenir à un objet ou un tableau avec `JSON.parse`.

```javascript
const obj = {
  name: 'Gilda Guerra',
  address: {
    city: 'Goiânia',
  },
};

JSON.stringify(obj);
// => '{"name":"Gilda Guerra","address":{"city":"Goiânia"}}'
```

## Coercition de type

Dans certains contextes, JavaScript convertit automatiquement une valeur vers un autre type de données avant d'évaluer une instruction.
Cette conversion implicite s'appelle la _coercition de type_.

### Contexte booléen

Quand une valeur est utilisée dans un contexte booléen, JavaScript applique les mêmes règles que la fonction `Boolean` pour la convertir implicitement.

- Quand la condition d'une [instruction `if`][concept-conditionals] n'est pas un booléen, une coercition est appliquée pour déterminer si la condition est remplie ou non.
  Il en va de même pour le premier opérande de l'[opérateur ternaire][mdn-ternary] `?`.

  ```javascript
  const num = 0;
  if (num) {
    // this block is NOT executed because 0 is falsy
  }

  const name = 'Jin';
  name ? 'name was provided' : 'no name provided';
  // => 'name was provided'
  ```

- L'opérande de l'opérateur logique NON `!` est lui aussi converti en booléen avant l'application de l'opération NON.

  ```javascript
  const name = '';
  !name;
  // => true
  ```

  Une conséquence du comportement décrit est que `!!value` a le même effet que `Boolean(value)`.
  Il vaut néanmoins mieux utiliser `Boolean` pour la lisibilité.

- JavaScript applique aussi une coercition aux opérandes des opérateurs ET logique (`&&`) et OU logique (`||`).
  Mais garde en tête que le résultat de l'expression n'est **pas** forcément un booléen.
  Elle renvoie l'un des opérandes d'origine (voir [MDN sur les opérateurs logiques][mdn-logical-operators]).

  ```javascript
  null || 'hello';
  // => 'hello'
  ```

### Contexte _string_

Si l'opérateur d'addition `+` est utilisé avec des valeurs primitives et qu'un opérande est une _string_, l'autre est lui aussi converti en _string_.
La logique de conversion est la même que celle de la fonction `String`.
Ensuite, les deux _strings_ sont concaténées.

```javascript
let name;
'hello ' + name;
// => 'hello undefined'
```

La même conversion implicite se produit pour les valeurs qui ne sont pas des _strings_ et qui sont intégrées dans des [_template strings_][mdn-template-strings].

```javascript
const degrees = 23;
`It is ${degrees} °C`;
// => 'Is is 23 °C.';
```

### Contexte numérique

De nombreux opérateurs convertissent les opérandes en nombres (si nécessaire) selon la logique de la fonction `Number` expliquée plus haut.

- Opérateurs arithmétiques : `+` (si aucune _string_ n'est impliquée), `-`, `*`, `/`, `%`, `**`
- Opérateurs plus unaire et négation unaire : `+`, `-`
- Opérateurs relationnels (pour des opérandes qui ne sont pas des _strings_) : `>`, `>=`, `<`, `<=`
- Opérateurs binaires : `|`, `&`, `^`, `~`

Consulte la [liste des opérateurs MDN][mdn-operators] pour plus de détails sur chacun de ces opérateurs.

Quand un opérande peut potentiellement être une _string_, il vaut mieux toujours convertir explicitement avec la fonction `Number` pour éviter les erreurs.

```javascript
'1' + '2';
// => '12'
// addition operator in string context as explained above

Number('1') + Number('2');
// => 3
```

Tu verras parfois l'opérateur plus unaire utilisé pour convertir une _string_ en nombre.
Ce n'est pas recommandé, car c'est bien plus difficile à lire qu'un appel explicite à `Number`.

```javascript
const value = '42';
+value;
// => 42

Number(value);
// => 42
```

Utiliser les opérateurs d'égalité et d'inégalité faibles `==`/`!=` implique aussi souvent une conversion implicite en nombre.
Cependant, la logique exacte de ces opérateurs est assez compliquée (voir [MDN sur l'égalité faible][mdn-loose-equality]).
Les résultats sont difficiles à prévoir et parfois différents de ce à quoi on s'attend.
Utilise plutôt les opérateurs d'égalité et d'inégalité strictes `===`/`!==` pour éviter ces conversions implicites.
