# Introduction

## Types personnalisés

Les [types personnalisés][custom-types] en Elm représentent un nombre fixe de cas nommés. Chaque valeur correspond à exactement l'un de ces cas nommés.

Un type personnalisé se définit à l'aide du mot-clé `type` et demande très peu de syntaxe. C'est l'une des techniques les plus importantes de la programmation en Elm, et elle sert à faire correspondre exactement les valeurs possibles dans le code aux valeurs valides de la vie réelle, ce qui ne laisse aucune place aux données invalides et rend [impossible la représentation dans le code d'états impossibles][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Chaque cas d'un type personnalisé peut éventuellement porter des données qui lui sont associées, et différents cas peuvent porter des données de types différents. Si aucun des cas ne porte de données, l'union discriminée ressemble à ce que d'autres langages appellent généralement une _énumération_ (ou _enum_).

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

On peut créer une valeur pour un cas précis en faisant référence à son nom (`Spring`) lorsqu'il est défini dans le même module, ou importé avec la syntaxe `import SeasonModule exposing (Season(..))`, ou bien en utilisant son nom pleinement qualifié (`Season.Spring`) lorsqu'il est importé avec la syntaxe `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Les types personnalisés, comme tout le reste en Elm, possèdent une _égalité structurelle_, ce qui signifie que deux valeurs du même cas, avec les mêmes données (facultatives), sont équivalentes.

La façon privilégiée de manipuler les types personnalisés est le [filtrage par motif][pattern-matching] :

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
