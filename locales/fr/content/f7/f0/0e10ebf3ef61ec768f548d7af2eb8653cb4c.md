# À propos

[Elixir](https://elixir-lang.org/), publié pour la première fois en 2012, s'appuie sur les fonctionnalités déjà solides d'Erlang tout en restant plus accessible, plus facile à lire, à tester et à écrire pour les débutants.

José Valim, le créateur d'Elixir, explique [dans sa conférence de 2012](https://vimeo.com/53221562) comment il a conçu le langage pour que les applications soient :

  1. Distribuées
  2. Tolérantes aux pannes
  3. En temps réel souple
  4. Rechargées à chaud (on peut introduire du nouveau code sans arrêter le serveur)

Elixir est en fait compilé en [bytecode](https://en.wikipedia.org/wiki/Bytecode), puis exécuté sur la [machine virtuelle Erlang BEAM](https://codesync.global/media/robert-virding-co-creator-of-erlang-explains-the-beam/).

Appeler du code Erlang n'a aucun « coût de conversion » : on peut donc exécuter du code Erlang juste à côté de code Elixir.

Elixir étant un langage fonctionnel, tout y est une expression.

Elixir propose une « documentation de première classe » : les commentaires peuvent être attachés à une fonction, ce qui facilite leur consultation.

Les expressions régulières bénéficient elles aussi d'un traitement de première classe, ce qui évite les échappements pénibles dans les _strings_.

L'implémentation de la communication asynchrone d'Elixir permet d'écrire du code léger tout en gérant une concurrence très élevée.

Les programmeurs utilisent Elixir pour traiter des milliers de requêtes et de réponses *en parallèle* sur un seul nœud de serveur.

Il a été utilisé avec succès pour des microservices qui doivent consommer et servir rapidement une multitude d'API.

Le [framework Phoenix](https://www.phoenixframework.org/) aide à structurer les applications Elixir pour le web.
