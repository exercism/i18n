# Workflows

GitHub Actions utilise le concept de _workflows_, qui sont des scripts exécutés automatiquement dès qu'un événement spécifique se produit (par exemple, pousser un commit).

Chaque workflow GitHub Actions est défini dans un fichier `.yml` du répertoire `.github/workflows`.
Pour plus d'informations sur les workflows, consulte la documentation suivante :

- [Syntaxe des workflows](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions)
- [Choisir quand ton workflow s'exécute](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow)
- [Choisir où ton workflow s'exécute](https://docs.github.com/en/actions/writing-workflows/choosing-where-your-workflow-runs)
- [Choisir ce que fait ton workflow](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does)
- [Écrire des workflows](https://docs.github.com/en/actions/writing-workflows)
- [Bonnes pratiques](/docs/building/github/gha-best-practices)

## Workflows partagés

Certains workflows sont partagés entre plusieurs dépôts.

```exercism/caution
Les workflows partagés sont synchronisés automatiquement (depuis le [dépôt org-wide-files](https://github.com/exercism/org-wide-files/)).
Tu ne dois donc pas modifier leur contenu manuellement.
```

### Workflows généraux

- [Sync labels](/docs/building/tracks/ci/workflows/sync-labels) : synchronise les libellés du dépôt à partir d'un fichier

### Workflows spécifiques au parcours

- [configlet](/docs/building/tracks/ci/workflows/configlet) : vérifie que les fichiers (de configuration) du parcours sont correctement structurés, tant sur le plan syntaxique que sémantique
- [No important files changed](/docs/building/tracks/ci/workflows/no-important-files-changed) : commente les pull requests qui entraîneraient un nouveau test des solutions existantes
- [Test](/docs/building/tracks/new/setup-continuous-integration#h-test-workflow) : vérifie les exercices du parcours

### Workflows spécifiques à l'outillage

- [Deploy](/docs/building/tracks/ci/workflows/deploy) : déploie l'image Docker de l'outillage du parcours vers Docker Hub et ECR

### Workflows facultatifs

Il existe aussi des workflows que les parcours peuvent choisir d'activer :

- [Pause community contributions](/docs/building/tracks/ci/workflows/pause-community-contributions) : commente automatiquement les nouvelles issues et les nouvelles PR créées par des utilisateurs qui ne sont pas membres de l'organisation GitHub Exercism
