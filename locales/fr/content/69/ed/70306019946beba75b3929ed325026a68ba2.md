# Instructions

Tu écris du code pour le système de données d'un atelier de production de pièces automobiles.
Les composants de moteur et de châssis défilent à travers une série de stations d'usinage.
Chaque station produit des mesures qui doivent être combinées, comparées, calibrées ou normalisées avant que l'étape suivante ne démarre.
Les fonctions que tu implémentes ici correspondent chacune à une station.

~~~~exercism/note
Les calculs de cet exercice doivent être effectués à l'aide d'instructions SIMD, et non d'opérations scalaires.
~~~~

## 1. Combine les rendements de deux lignes

L'atelier fait fonctionner deux chaînes de montage parallèles.
À la fin de chaque poste, les deux lignes déclarent leurs rendements pour 4 bacs de pièces sous forme de nombres en simple précision.
Le tableau de bord du superviseur affiche le rendement combiné par bac, donc les deux rapports sont additionnés bac par bac.
Les trois tampons sont gérés par le système de déclaration et sont toujours alignés sur 16 octets.

Définis une fonction `sum_yields` qui, à partir des rendements par bac de `line_a` et `line_b`, écrit la somme bac par bac dans `result`.
Les arguments, dans l'ordre, sont :

1. `line_a` : adresse mémoire alignée sur 16 octets contenant 4 nombres à virgule flottante 32 bits
2. `line_b` : adresse mémoire alignée sur 16 octets contenant 4 nombres à virgule flottante 32 bits
3. `result` : adresse mémoire alignée sur 16 octets où la fonction écrira 4 nombres à virgule flottante 32 bits

Cette fonction n'a pas de valeur de retour ; le résultat est stocké dans le tampon passé (`result`) :

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. Calcule l'écart mis à l'échelle

Entre deux opérations, une station d'échantillonnage mesure des pièces usinées et les compare à des dimensions cibles.
Les valeurs mesurées arrivent d'une jauge de précision dans un tampon toujours aligné sur 16 octets.
Les valeurs cibles proviennent du dossier de fabrication, qui n'offre aucune garantie d'alignement.
L'écart est multiplié par un facteur de sensibilité par axe avant d'être transmis au contrôleur de tolérance en aval.
À cette étape, le contrôleur en aval lit l'écart directement depuis un registre SIMD plutôt que depuis la mémoire.

Définis une fonction `scaled_deviation` qui, à partir de `measured`, de `target` et de `sensitivity`, écrit l'écart mis à l'échelle dans `result`.
Les arguments, dans l'ordre, sont :

1. `measured` : adresse mémoire alignée sur 16 octets contenant 2 nombres à virgule flottante 64 bits
2. `target` : adresse mémoire contenant 2 nombres à virgule flottante 64 bits (alignement non garanti)
3. `sensitivity` : adresse mémoire contenant 2 nombres à virgule flottante 64 bits (alignement non garanti)
4. `result` : adresse mémoire d'un tampon où la fonction écrira 2 nombres à virgule flottante 64 bits (alignement non garanti)

L'écart mis à l'échelle est `(measured - target) * sensitivity`, voie par voie.

Cette fonction n'a pas de valeur de retour ; le résultat est stocké dans le tampon passé (`result`) sous forme de paire de nombres à virgule flottante 64 bits.

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. Calibre un lot

Avant que les pièces n'entrent dans le poste de contrôle final, les relevés dimensionnels d'un lot de 4 pièces sont remis à l'échelle en double précision et corrigés d'une dérive de température connue.

Les 4 relevés bruts arrivent sous forme de nombres en simple précision.
Pour chaque ligne de 2 relevés, le calibrage calcule `reference / (raw - offset)`, puis multiplie ce résultat par un facteur de conversion constant de `0.5`.

Note que la référence et le décalage sont identiques pour les deux lignes du lot.
Le facteur de conversion est le même à chaque calibrage ; plutôt que de le recevoir en argument, tu dois le déclarer comme une constante compactée de 16 octets en mémoire.

Définis une fonction `calibrate_batch` qui, à partir du lot `raw`, de `reference`, de `offset` et du tampon `result`, écrit les valeurs calibrées dans `result`.
Les arguments, dans l'ordre, sont :

1. `raw` : adresse mémoire contenant 4 nombres à virgule flottante 32 bits (alignement non garanti)
2. `reference` : adresse mémoire alignée sur 16 octets contenant 2 nombres à virgule flottante 64 bits
3. `offset` : adresse mémoire alignée sur 16 octets contenant 2 nombres à virgule flottante 64 bits
4. `result` : adresse mémoire alignée sur 16 octets où la fonction écrira 4 nombres à virgule flottante 64 bits (32 octets au total)

Pour chacune des deux lignes du lot, la fonction doit :

1. Convertir les 2 valeurs brutes en simple précision de la ligne en double précision.
2. Soustraire `offset` de la paire convertie.
3. Diviser `reference` par le résultat.
4. Multiplier, voie par voie, chaque nombre à virgule flottante 64 bits par le facteur de conversion fixe de `0.5`.
5. Stocker les 2 nombres à virgule flottante 64 bits dans les 16 octets correspondants de `result`.

Cette fonction n'a pas de valeur de retour ; le résultat est stocké dans le tampon passé (`result`) :

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. Normalise les scores le long d'une ligne

Au bout de la ligne, chaque pièce possède un score de qualité qui doit être normalisé avant d'être communiqué.
Chaque score est multiplié par son propre gain par pièce, puis divisé par une échelle de production par axe.
Le tampon des gains contient un gain par pièce.

L'échelle de production est la même pour toute la série et est passée dans une adresse mémoire contenant deux nombres à virgule flottante 64 bits.
Les scores sont mis à jour **en place** : le même tampon qui contenait les scores bruts contient désormais les scores normalisés.

Définis une fonction `normalize_scores` qui, à partir d'un tableau `scores`, d'un tableau `gains`, de `scale` et d'un nombre `n`, normalise les scores en place.
Les arguments, dans l'ordre, sont :

1. `scores` : adresse mémoire alignée sur 16 octets contenant `n` nombres à virgule flottante 64 bits (modifiée en place)
2. `gains` : adresse mémoire alignée sur 16 octets contenant `n` nombres à virgule flottante 64 bits
3. `scale` : adresse mémoire alignée sur 16 octets contenant 2 nombres à virgule flottante 64 bits
4. `n` : un entier 64 bits positif et pair (minimum `2`), le nombre de scores à normaliser

Les deux voies de l'échelle s'appliquent aux deux éléments de chaque paire.
La première voie met à l'échelle le premier élément de chaque paire (voies aux positions paires), la seconde met à l'échelle le second (voies aux positions impaires).
Chaque score est multiplié par le gain correspondant, puis divisé par la voie d'échelle appropriée : `score * gain / scale_lane`.

Cette fonction n'a pas de valeur de retour ; le résultat est stocké dans le tampon d'entrée (`scores`), à la même position que le `score` correspondant qui a été normalisé :

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
