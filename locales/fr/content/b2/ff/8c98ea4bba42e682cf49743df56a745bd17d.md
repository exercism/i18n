# Introduction

Dans d'autres parties du programme, on a vu différents types de données aux caractéristiques variées.

- Les vecteurs atomiques sont unidimensionnels et de type homogène.
- Les listes sont unidimensionnelles et leurs éléments peuvent être de types hétérogènes.
- Les matrices et les tableaux sont multidimensionnels et homogènes.

Ce concept s'intéresse aux façons de stocker des données multidimensionnelles et hétérogènes.
En pratique, _la plupart_ des données du monde réel sont de ce type, et on arrive donc au cœur de l'usage que l'on fait de R en pratique.

## Variantes de dataframe

Au fil des décennies, R a ajouté de nombreux types de données pour gérer les données tabulaires.

Ce programme portera principalement sur les tibbles, mais il est utile de connaître les alternatives.

### Le `data.frame`

Dans le R de base, un `data.frame` est une `list` de `vectors` de même longueur.
On peut le voir comme un tableau rectangulaire de données, dans lequel chaque colonne est homogène, mais où chaque ligne peut contenir (et contient généralement) des types de données différents.

Un exemple pour illustrer cela :

```R
# create the column vectors
languages <- c("Fortran", "R", "Python", "Julia")
created <- c(1957, 1993, 1991, 2012)
has.syllabus <- c(FALSE, TRUE, TRUE, TRUE)

# join columns to create the dataframe
df <- data.frame(languages, created, has.syllabus)
df
#>   languages created has.syllabus
#> 1   Fortran    1957        FALSE
#> 2         R    1993         TRUE
#> 3    Python    1991         TRUE
#> 4     Julia    2012         TRUE
 ```

On a une colonne de chaînes de caractères, une colonne de nombres et une colonne de booléens.
À plus grande échelle, c'est une façon intuitive de représenter de nombreux ensembles de données du monde réel.

### Le `tibble`

La conception du `data.frame` est _ancienne_.

Des décennies d'expérience, ainsi que l'évolution de la façon dont R est utilisé, ont conduit à une refonte, donnant naissance dans le Tidyverse à une alternative modernisée : les tibbles.

Par rapport au R de base, les tibbles ont :

- Des valeurs par défaut différentes, pour réduire les problèmes courants.
- Une propension moindre à convertir les types de données à la saisie.
- Des messages d'erreur plus nombreux et plus clairs.
- Des formats d'affichage différents, généralement meilleurs.

En bref, un `tibble` cherche à « _faire moins et se plaindre plus_ », ce que l'on décrit aussi comme « _paresseux et grincheux_ ».

Ces types sont généralement interchangeables : toute fonction qui accepte un `data.frame` acceptera aussi un `tibble`, et _vice versa_.

La conversion entre les types est facile, avec `as_tibble(df)` et `as.data.frame(tbl)`.

Pour les nouveaux projets, utiliser des tibbles t'aidera sans doute à écrire du code plus robuste.
Cependant, le code et les données hérités sont très abondants dans le monde de R, donc le `data.frame` devrait rester courant encore longtemps.

```R
# column vectors are same as for data.frame
library(tibble)
tbl <- tibble(languages, created, has.syllabus)
tbl
  # A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 R            1993 TRUE        
#> 3 Python       1991 TRUE        
#> 4 Julia        2012 TRUE      
```

Remarque le format d'affichage par défaut : la ligne de commentaire avec les dimensions est imprimée automatiquement, et les types des colonnes sont eux aussi affichés.

## Travaille avec les tibbles

Les tibbles font partie intégrante du Tidyverse, alors charge-les avec `library(tibble)` ou `library(tidyverse)`.

### Crée un tibble

Le plus simple est d'utiliser la fonction `tibble()` pour assembler des vecteurs colonnes, comme pour `data.frame()`.
On en a vu un exemple dans une section précédente.

S'il est plus pratique de saisir les valeurs ligne par ligne, la fonction correspondante est `tribble()`.

En pratique, il existe des dizaines de façons de créer des tibbles, car c'est le format de sortie par défaut d'un large éventail de fonctions du Tidyverse.

## Manipule un tibble

Le concept de programmation fonctionnelle a présenté la bibliothèque `purrr` pour manipuler des vecteurs et des listes (des structures de données à une dimension).

Pour les dataframes (traditionnels ou sous forme de tibbles), la bibliothèque à utiliser est `dplyr`.

### Sous-ensembles

Les dataframes, y compris les tibbles, peuvent être traités comme des listes de vecteurs colonnes, si bien qu'on récupère une colonne donnée comme on le ferait avec une liste.

```R
tbl
# A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 R            1993 TRUE        
#> 3 Python       1991 TRUE        
#> 4 Julia        2012 TRUE    

tbl$created
#> [1] 1957 1993 1991 2012
```

On peut aussi accéder à un dataframe avec la syntaxe des matrices.

```R
tbl[c(2, 4), 1:2]
  # A tibble: 2 × 2
#>   languages created
#>   <chr>       <dbl>
#> 1 R            1993
#> 2 Julia        2012
```

Dans le R moderne et son écosystème Tidyverse, les fonctions de `dplyr` sont généralement plus souples et plus pratiques, et c'est sur elles que se concentrera la suite de ce concept.

### Opérations par colonne

Récupère une seule colonne avec `pull()`, en donnant son nom ou son numéro d'ordre (les nombres négatifs comptent de droite à gauche).

```R
tbl |> pull(created)
#> [1] 1957 1993 1991 2012
```

C'est le même résultat que `tbl$created`, mais avec une fonction adaptée aux pipelines.

Pour récupérer plusieurs colonnes, la fonction appropriée est `select()`, qui est très polyvalente.
Récupère (ou supprime) des colonnes selon les propriétés de leur nom ou de leur type.

```R
# Range with position and/or name
tbl |> select(1:created)
  # A tibble: 4 × 2
#>   languages created
#>   <chr>       <dbl>
#> 1 Fortran      1957
#> 2 R            1993
#> 3 Python       1991
#> 4 Julia        2012      

# Use type of column
tbl |> select(where(is.numeric))
  # A tibble: 4 × 1
#>   created
#>     <dbl>
#> 1    1957
#> 2    1993
#> 3    1991
#> 4    2012
```

On peut combiner plusieurs critères avec les opérateurs booléens `&`, `|` et `!` (et, ou, non).

Une telle puissance semble assez ridicule avec notre petit dataframe jouet sur les langages.
Heureusement, le tibble `starwars` est fourni avec `dplyr`, ce qui nous donne un ensemble plus gros pour nous entraîner.

```R
# pick a subset of columns
starwars |> 
  select(name | ends_with("color")) |> 
  head(5)
  # A tibble: 5 × 4
#>   name           hair_color skin_color  eye_color
#>   <chr>          <chr>      <chr>       <chr>    
#> 1 Luke Skywalker blond      fair        blue     
#> 2 C-3PO          NA         gold        yellow   
#> 3 R2-D2          NA         white, blue red      
#> 4 Darth Vader    none       white       yellow   
#> 5 Leia Organa    brown      light       brown    
```

### Opérations par ligne

Récupère les lignes qui correspondent à un critère avec `filter()`, ou exclus-les avec `filter_out()`.

```R
starwars |> 
  select(name:mass) |> 
  filter(between(height, 150, 165) & !is.na(mass))
  # A tibble: 4 × 3
#>   name               height  mass
#>   <chr>               <int> <dbl>
#> 1 Leia Organa           150    49
#> 2 Beru Whitesun Lars    165    75
#> 3 Nien Nunb             160    68
#> 4 Ben Quadinaros        163    65
```

Les critères de filtrage peuvent être arbitrairement complexes, mais reposent toujours sur le _contenu_ des lignes.

Si l'on connaît le _numéro_ des lignes, on peut utiliser divers membres de la famille de fonctions `slice()`.

```R
starwars |> 
  select(name | homeworld) |> 
  slice(20:25)
  # A tibble: 6 × 2
#>   name             homeworld
#>   <chr>            <chr>    
#> 1 Palpatine        Naboo    
#> 2 Boba Fett        Kamino   
#> 3 IG-88            NA       
#> 4 Bossk            Trandosha
#> 5 Lando Calrissian Socorro  
#> 6 Lobot            Bespin   
```

## Modifie un tibble

Première mise en garde : le comportement par défaut _copy-on-modify_ fait que le tibble d'origine reste généralement inchangé.

La plupart des modifications s'appliquent colonne par colonne.

On peut changer les noms de colonnes avec `rename(newname = oldname)`, ou `rename_with()` pour appliquer une fonction.
Remarque la syntaxe à l'intérieur de `rename()`.
Le _contenu_ de la colonne `oldname` est _lié_ au nom `newname`, d'où l'ordre.

L'ordre des colonnes peut être modifié avec `relocate()`.
Par défaut, la ou les colonnes indiquées sont déplacées vers la ou les positions les plus à gauche, mais on peut utiliser un argument `.before` ou `.after` pour un positionnement plus fin.

```R
sw <- starwars |> select(name:species) |> slice(1:4)
sw
  # A tibble: 4 × 11
#>   name           height  mass hair_color skin_color  eye_color birth_year sex   gender    homeworld species
#>   <chr>           <int> <dbl> <chr>      <chr>       <chr>          <dbl> <chr> <chr>     <chr>     <chr>  
#> 1 Luke Skywalker    172    77 blond      fair        blue            19   male  masculine Tatooine  Human  
#> 2 C-3PO             167    75 NA         gold        yellow         112   none  masculine Tatooine  Droid  
#> 3 R2-D2              96    32 NA         white, blue red             33   none  masculine Naboo     Droid  
#> 4 Darth Vader       202   136 none       white       yellow          41.9 male  masculine Tatooine  Human  

sw |> relocate(c(species, homeworld), .after = name)
  # A tibble: 4 × 11
#>   name           species homeworld height  mass hair_color skin_color  eye_color birth_year sex   gender   
#>   <chr>          <chr>   <chr>      <int> <dbl> <chr>      <chr>       <chr>          <dbl> <chr> <chr>    
#> 1 Luke Skywalker Human   Tatooine     172    77 blond      fair        blue            19   male  masculine
#> 2 C-3PO          Droid   Tatooine     167    75 NA         gold        yellow         112   none  masculine
#> 3 R2-D2          Droid   Naboo         96    32 NA         white, blue red             33   none  masculine
#> 4 Darth Vader    Human   Tatooine     202   136 none       white       yellow          41.9 male  masculine
```

Pour des modifications plus importantes, `mutate()` propose plusieurs opérations :

- Créer de nouvelles colonnes qui sont des fonctions de colonnes existantes.
- Remplacer une colonne existante, en créant une nouvelle colonne portant le même nom.
- Supprimer une colonne, en lui affectant la valeur `NULL`.

De toute évidence, `mutate()` est puissant, potentiellement déroutant, et une bonne raison d'être très reconnaissant envers _copy-on-modify_.

Il n'y a aucune raison évidente de s'intéresser à l'indice de masse corporelle des personnages de Star Wars, mais au cas où :

```R
starwars |> 
  select(c(name, species, height, mass)) |> 
  mutate(BMI = mass / (height / 100)^2) |> 
  head(4)
  # A tibble: 4 × 5
#>   name           species height  mass   BMI
#>   <chr>          <chr>    <int> <dbl> <dbl>
#> 1 Luke Skywalker Human      172    77  26.0
#> 2 C-3PO          Droid      167    75  26.9
#> 3 R2-D2          Droid       96    32  34.7
#> 4 Darth Vader    Human      202   136  33.3
```

Les **opérations par ligne** sont moins courantes pour modifier un seul tibble (la fusion de plusieurs tibbles sera abordée dans un autre concept).

Une exception : `arrange()` trie les lignes selon les valeurs d'une ou plusieurs colonnes.

```R
tbl
#>       A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 R            1993 TRUE        
#> 3 Python       1991 TRUE        
#> 4 Julia        2012 TRUE  

tbl |> arrange(languages)
#>       A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 Julia        2012 TRUE        
#> 3 Python       1991 TRUE        
#> 4 R            1993 TRUE     
```
