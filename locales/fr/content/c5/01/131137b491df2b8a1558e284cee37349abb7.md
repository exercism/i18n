# Introduction

Le langage de programmation Java utilise des _exceptions_ pour gérer les erreurs et autres événements exceptionnels.

## Qu'est-ce qu'une exception ?

Une exception est un événement qui se produit pendant l'exécution d'un programme et qui perturbe le flux normal des instructions.
En Java, les exceptions sont déclenchées explicitement, et l'action de déclencher une exception s'appelle _lever une exception_.
L'action de traiter une exception s'appelle _intercepter une exception_.

En Java, toutes les exceptions sont des sous-classes de la classe `Exception`, elle-même sous-classe de `Throwable`.

Java distingue deux types d'exceptions :

1. Les exceptions vérifiées
2. Les exceptions non vérifiées

### Les exceptions vérifiées

Les _exceptions vérifiées_ sont des conditions exceptionnelles qu'une application doit anticiper et dont elle doit pouvoir se remettre.
Un exemple d'exception vérifiée est `FileNotFoundException`, qui se produit quand une méthode tente de lire un fichier qui n'existe pas.

Ce type d'exception est vérifié à la compilation : les méthodes qui lèvent des exceptions vérifiées doivent l'indiquer dans leur signature, et le code qui appelle une méthode susceptible de lever une exception vérifiée doit la gérer, sinon il ne compile pas.

Toutes les exceptions vérifiées sont des sous-classes de `Exception` qui n'étendent pas `RuntimeException`.

### Les exceptions non vérifiées

Les _exceptions non vérifiées_ sont des conditions exceptionnelles qu'une application ne peut généralement ni anticiper ni surmonter.
Un exemple d'exception non vérifiée est `NullPointerException`, qui se produit quand une méthode attend une valeur non nulle mais reçoit `null`.

Ce type d'exception n'est pas vérifié à la compilation : les méthodes qui lèvent des exceptions non vérifiées ne sont pas tenues de l'indiquer dans leur signature, et le code qui appelle une méthode susceptible de lever une exception non vérifiée n'est pas tenu de la gérer.

Toutes les exceptions non vérifiées héritent de `RuntimeException`, qui est elle-même une extension de `Exception`.

## Lever des exceptions

En Java, une méthode peut lever une exception à l'aide de l'instruction `throw`.

### Lever une exception vérifiée

Quand une méthode lève une exception vérifiée, elle doit l'indiquer dans sa signature à l'aide du mot-clé `throws`, comme le montre l'exemple ci-dessous.
Le code appelant est ainsi obligé d'anticiper qu'une exception peut être levée et de la gérer en conséquence.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### Lever une exception non vérifiée

Quand une méthode lève une exception non vérifiée, elle n'est pas tenue de l'indiquer dans sa signature, même si c'est possible.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## Gérer les exceptions

En Java, la gestion des exceptions repose sur les mots-clés `try`, `catch` et `finally`.

- Les instructions susceptibles de lever une exception doivent être placées dans un bloc `try`.
- Le bloc `try` est suivi d'un ou plusieurs blocs `catch` qui interceptent les exceptions levées dans le bloc `try`.
- Les blocs `catch` peuvent être suivis d'un bloc `finally` qui s'exécute toujours après le bloc `try`, qu'une exception ait été levée ou non.

L'exemple suivant montre comment ces mots-clés fonctionnent :

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

Dans cet exemple, quand aucune exception n'est levée, le texte suivant est affiché :

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

En revanche, si l'instruction `bankAccount.withdraw(amount)` lève une `InsufficientBalanceException`, c'est le texte suivant qui est affiché :

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

Ou, si une exception non vérifiée est levée par `bankAccount.withdraw(amount)`, c'est le texte suivant qui est affiché :

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## Les erreurs

Java possède aussi une catégorie distincte appelée _erreurs_, qui regroupe des problèmes graves externes à l'application.
Un exemple d'erreur est `OutOfMemoryError`, qui se produit quand une application tente d'utiliser plus de mémoire que le système n'en propose.

Comme les exceptions non vérifiées, les erreurs ne sont pas vérifiées à la compilation.
La différence, c'est qu'elles représentent des problèmes au niveau du système et sont généralement levées par la machine virtuelle Java ou par l'environnement plutôt que par l'application.
Une application ne doit généralement pas chercher à les intercepter ni à les gérer.

En Java, toutes les erreurs héritent de la classe `Error`.
