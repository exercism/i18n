# À propos de la nullabilité

Dans un monde idéal, on pourrait compter sur le fait que tout est bien défini, avec des valeurs concrètes et sans lacunes.

Cela contredit notre expérience quotidienne, et c'est pourquoi de nombreux langages de programmation disposent d'un moyen de représenter l'absence de valeur : null ou NULL, nil, None, nothing...

Cela a été facile à introduire (dès 1965), mais n'a pas tardé à susciter des regrets.
Son inventeur l'a ensuite qualifiée de [« erreur à un milliard de dollars »][web-mistake].

Ces dernières décennies, les concepteurs de langages ont exploré de nombreuses façons de rendre les valeurs nulles disponibles mais (le plus souvent) sûres.

Kotlin a quelques [principes généraux][ref-null-safety], qui [diffèrent sensiblement de ceux de Java][ref-java2kotlin].
_Ces différences impliquent que Kotlin dispose de fonctionnalités spécifiques pour gérer l'interopérabilité avec Java, mais les détails dépassent le cadre de ce concept._

- Kotlin a une valeur `null` spéciale.
- Par défaut, tous les types sont _non-nullables_ (c'est-à-dire qu'ils ne peuvent pas être `null`).
- Tous les types peuvent être _nullables_, mais cela doit être fait explicitement.
- Les fonctions susceptibles d'échouer avec une exception ont souvent une variante dont la valeur de retour est _nullable_.
- Une syntaxe spéciale, très concise, s'efforce de rendre aussi simple que possible le test des valeurs nulles et la réaction à celles-ci.

## Créer des variables nullables

On peut rendre un type [nullable][ref-nullable-type] en ajoutant le suffixe `?` (par exemple `String?` au lieu de `String`).

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## Opérateurs et fonctions utiles

### L'[opérateur d'appel sécurisé][ref-safe-call] `?.`

Pour une `String` non-nullable, on peut accéder à la propriété `.length`.

Avec une `String?` _nullable_, la même syntaxe échoue, mais utiliser `?.length` tient compte de la possibilité d'un `null`.
Le type de retour est `Int?`.

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

Comme on l'a vu à la dernière ligne ci-dessus, `?.` fonctionne aussi avec les types non-nullables.

### L'[opérateur Elvis][ref-elvis] `?:`

Prolongeant l'idée de l'opérateur d'appel sécurisé, l'[opérateur Elvis][wiki-elvis] permet de fournir une valeur par défaut pour remplacer `null`.

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### L'[opérateur d'assertion non-null][ref-not-null] `!!`

Avec cet opérateur, un type _nullable_ est de force traité comme non-nullable, lorsque le programmeur en est convaincu.
Peut-être qu'on comprend parfois mieux la logique du programme qu'un compilateur trop prudent ?

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

La responsabilité nous incombe désormais : si `b` vaut toujours `null`, on obtient une `NullPointerException`.

### La [fonction let][ref-let] `?.let`

Si l'on transmet un élément _nullable_ à un bloc de code, on pourrait effectuer des vérifications de nullité explicites : `if (item != null) { do something }`.

Il est plus simple et plus idiomatique d'utiliser `item?.let { do something }`.
Le `do something` ne s'exécute que lorsque `item` n'est pas null.

### Les fonctions de type `somethingOrNone()`

Certaines fonctions peuvent échouer, par exemple lorsqu'on demande un indice invalide dans une _string_ ou un tableau.

Plutôt que de lever une exception, on peut utiliser la [variante `...OrNull`][ref-elem-at-or-null] de la fonction, pour obtenir (dans ce cas) une valeur de retour `Int?`.

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
