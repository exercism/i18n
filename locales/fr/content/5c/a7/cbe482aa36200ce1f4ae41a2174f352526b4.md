# Nil

Crystal possède un type appelé [`Nil`][nil], qui ne peut avoir qu'une seule valeur : `nil`.
Il sert à représenter l'absence de valeur, et est semblable à `null` ou `None` dans d'autres langages.

Des valeurs Nil peuvent être renvoyées par diverses méthodes, par exemple [`String#[]?`][string-index], qui renvoie `nil` si l'indice est en dehors des limites.

```crystal
"foo"[10]? # => nil
```

Crystal met en œuvre ce qu'on appelle les **VÉRIFICATIONS DES RÉFÉRENCES NULLES**, ce qui signifie qu'aucun type n'accepte `nil` par défaut.
Cela signifie qu'on ne peut pas affecter `nil` à une variable à moins de la déclarer explicitement de type `Nil`.
Le compilateur vérifiera donc automatiquement les références nulles.

## Valeur _falsey_

On peut adopter différentes approches pour gérer les valeurs `nil`.
`nil` est une valeur [falsey][truthy-falsey], tout comme `false`.
Cela signifie que dans les instructions et les autres endroits où l'on attend une valeur _falsey_ ou _truthy_, `nil` sera traité de la même manière que `false`.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Cela signifie que la branche _truthy_ ne sera pas empruntée si une variable pouvant valoir `nil` a pour valeur `nil`.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Vérifie si une valeur est nil

Crystal dispose d'une méthode qui permet de vérifier si une valeur est `nil`.
Elle s'appelle [`nil?`][nil?] et elle est disponible sur tous les objets.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Le comportement est un peu différent quand on se contente d'utiliser la valeur dans une instruction `if`, car dans les exemples précédents, `false` comme nil auraient été traités comme faux.
Ici, seul `nil` est traité comme _falsey_, car si la valeur avait été false, elle n'aurait pas été nil et aurait donc été _truthy_.

## L'opérateur ou

La façon la plus simple de gérer les valeurs `nil` est de faire en sorte qu'elles ne deviennent jamais `nil` dès le départ.
L'opérateur ou ([`||`][or]) est souvent utilisé pour manipuler des `Bools`, mais si on le comprend bien, il peut aussi servir à gérer les valeurs `nil`.
L'opérateur ou vérifie si la première valeur est _truthy_ ; dans le cas contraire, la deuxième valeur est utilisée.
Cela permet de faire en sorte que, si la valeur est `nil`, elle soit _falsey_ et que la deuxième valeur soit donc utilisée.

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
Cette approche doit être considérée comme un dernier recours, et ne doit être utilisée que si tu es **sûr** que la valeur n'est pas nil.
Si possible, utilise plutôt les autres approches.
~~~~

[`not_nil!`][not_nil] est une méthode qui permet de dire au compilateur qu'une valeur n'est pas nil, ce qui fait que le type qu'elle porte ne peut pas être nil.
Elle y parvient en levant une exception si la valeur est nil.

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
