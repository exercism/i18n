# À propos des bases

Kotlin est un langage à typage statique, conçu pour être entièrement interopérable avec Java.

Par rapport à Java, Kotlin :

- possède une syntaxe plus propre et plus concise ;
- intègre de nombreuses fonctionnalités des langages fonctionnels ;
- offre une prise en charge étendue des valeurs nullables.

## Variables

Comme Kotlin est un langage à typage statique, il est nécessaire de _connaître_ le type de chaque valeur au moment de la compilation.

Cependant, l'[inférence de type][inference] de Kotlin est très puissante, si bien que _préciser_ le type est souvent facultatif.

Il y a deux façons de déclarer une variable.

1. `val` crée une variable immuable, et essayer de la modifier provoque une erreur de compilation.

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. `var` crée une variable mutable.

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

Comme les variables immuables éliminent une catégorie courante de bugs, on encourage l'usage de `val` dès que possible.

De plus, même une variable déclarée avec `var` ne peut pas changer de type :

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

Pour limiter les distractions visuelles, les types explicites seront le plus souvent omis dans ce programme.
Néanmoins, il est recommandé de préciser les types au moins pour :

- les API publiques
- les signatures de fonctions
- les endroits qui nécessitent une documentation

Certaines entreprises et organisations exigent une sûreté de typage stricte et interdisent l'inférence de type, tandis que d'autres la réservent aux types « simples », ou l'acceptent pleinement.

```kotlin
val x: Int = 42  // => 42
```

En général, les noms de variables et de fonctions doivent s'écrire en `camelCase`, et non en `snake_case`.

## Fonctions

On déclare une fonction avec le mot-clé `fun`.
Contrairement à Java, une fonction n'a pas besoin de faire partie d'une classe.

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

Quelques points à noter :

- Les parenthèses `()` sont nécessaires après le nom de la fonction, même si elle ne prend aucun argument.
- Les arguments d'une fonction doivent préciser leur type : il n'y a pas d'inférence de type (contrairement aux variables).
- Le corps de la fonction est délimité par des accolades `{ }` (voir plus bas).
- Le mot-clé `return` est obligatoire lorsqu'on renvoie une valeur.
- Les points-virgules `;` en fin de ligne sont facultatifs, et généralement omis.
- Les opérateurs arithmétiques `+`, `-`, `*`, `/` sont semblables à ceux de la plupart des langages courants.

Cependant, pour ces fonctions très simples, dites « à expression unique », il existe une syntaxe abrégée :

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
Les fonctions peuvent avoir des paramètres avec des valeurs par défaut.
Ces valeurs seront utilisées si elles sont omises là où la fonction est appelée :

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

Dans Exercism, les fonctions renvoient généralement une valeur (en raison de la façon dont l'exécuteur de tests est structuré).
Pour utiliser Kotlin plus largement, il peut être utile de savoir qu'une fonction qui ne renvoie aucune valeur peut omettre le type de retour et le mot-clé `return`.

On dit alors qu'elle a un type de retour `Unit` : l'équivalent de `void` en Java et dans plusieurs autres langages.

## Commentaires

Les commentaires sur une seule ligne commencent par `//`, et le reste de la ligne est alors ignoré.

Les commentaires sur plusieurs lignes commencent par `/*` et se terminent par `*/`.

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

C'est la même chose qu'en Java.
