# À propos

Des classes comme `LocalDate` et `LocalDateTime` décrivent un _point_ dans le temps.
Le paquet `java.time` contient aussi deux classes qui décrivent une _quantité_ de temps :

- [`Period`][period-docs] est une quantité de temps calendaire, exprimée en années, mois et jours, par exemple « 2 mois et 5 jours ».
- [`Duration`][duration-docs] est une quantité de temps chronométrée, exprimée en heures, minutes, secondes, millisecondes et nanosecondes, par exemple « 1 heure et 30 minutes ».

La différence compte, car les unités du calendrier n'ont pas de longueur fixe.
Un mois peut compter 28, 29, 30 ou 31 jours, donc « un mois » ne correspond pas à un nombre fixe de secondes.
Un `Period` suit le calendrier, tandis qu'un `Duration` mesure un temps exact.

| | `Period` | `Duration` |
| --- | --- | --- |
| Stocke | années, mois et jours | secondes et nanosecondes |
| S'utilise avec | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

Les deux classes sont immuables.
Des méthodes comme `plusDays()` ou `multipliedBy()` renvoient une _nouvelle_ instance et laissent l'originale inchangée.

## `Period`

### Création d'une période

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

Le résultat de `toString()` utilise le [format de durée ISO-8601][iso-8601-durations] : un `P` suivi du nombre d'années (`Y`), de mois (`M`) et de jours (`D`).
Il n'y a pas de semaines dans un `Period` : `Period.ofWeeks(2)` est stocké sous la forme de 14 jours.
La même notation peut être relue avec `Period.parse()` :

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### Ajout d'une période à une date

On ajoute ou on soustrait une période à une date avec `plus()` et `minus()` :

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

On peut ajouter une période à un `LocalDateTime` de la même façon, et l'heure de la journée reste identique :

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

Un `Instant` n'a pas de calendrier, donc on ne peut lui ajouter qu'une période en jours.
Une période comportant des années ou des mois lève une exception :

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

Les années sont ajoutées en premier, puis les mois, puis les jours.
Quand l'ajout d'années ou de mois tombe sur un jour qui n'existe pas, le résultat est ramené au dernier jour valide de ce mois :

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

Cela implique aussi que si l'on ajoute une période puis qu'on la soustrait, on ne retrouve pas toujours la date de départ :

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### La période entre deux dates

`Period.between()` renvoie la période qui va d'une date (incluse) à une autre (exclue).
Le même résultat est disponible avec `LocalDate.until()` :

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

On accède aux composantes d'une période avec `getYears()`, `getMonths()` et `getDays()`.
Ces composantes sont indépendantes les unes des autres : `getDays()` ne renvoie que la partie jours, pas le nombre total de jours.
`toTotalMonths()` renvoie les années et les mois combinés en un nombre de mois, mais il n'existe aucune méthode pour le nombre total de jours, car cela dépend des mois concernés.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### Normaliser une période

Une période créée avec une méthode de fabrique conserve ses unités exactement telles qu'elles ont été fournies, et `equals()` compare les unités une à une.
`normalized()` reporte les mois en années au-delà de douze, mais laisse les jours tels quels :

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## Compter les unités avec `ChronoUnit`

Pour obtenir le nombre total d'une même unité entre deux points dans le temps, utilise la méthode `between()` sur l'une des constantes de [`ChronoUnit`][chronounit-docs] :

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

Seules les unités complètes sont comptées, et le résultat est négatif quand le second argument précède le premier :

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit` fonctionne aussi avec les unités horaires et les dates-heures :

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### Création d'une `Duration`

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

Dans la notation ISO-8601, le `T` sépare la partie date de la partie heure.
Un `Duration` n'a pas de partie date, donc son `toString()` commence toujours par `PT`.
`Duration.ofDays()` considère qu'un jour fait exactement 24 heures.

Une durée peut elle aussi être obtenue à partir d'une chaîne avec `Duration.parse()` :

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### Ajout d'une durée à une heure

On ajoute ou on soustrait une durée à un `LocalTime`, un `LocalDateTime` ou un `Instant` avec `plus()` et `minus()` :

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

Comme le montre le dernier exemple, un `LocalTime` repart de zéro après minuit.

Un `LocalDate` n'a pas d'heure, donc on ne peut pas le combiner avec un `Duration` :

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### La durée entre deux instants

`Duration.between()` renvoie la quantité exacte de temps entre deux heures ou deux dates-heures :

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()` n'accepte pas deux `LocalDate`, car une date n'a pas de secondes à mesurer :

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

Utilise plutôt `Period.between()` ou `ChronoUnit.DAYS.between()` pour les dates.

### Convertir une durée

Les méthodes `toXxx()` convertissent une durée en une quantité _totale_ d'une seule unité, arrondie à l'inférieur :

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

Les méthodes `toXxxPart()` découpent une durée en ses composantes, comme sur une horloge :

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()` s'arrête à 23, car au-delà, les heures sont comptées par `toDaysPart()`.

### Comparer et calculer avec des durées

Les durées se comparent avec `compareTo()` et se testent avec `isZero()` et `isNegative()` :

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

Elles prennent aussi en charge les opérations arithmétiques, comme `plus()`, `minus()`, `multipliedBy()` et `dividedBy()` :

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` ou `Duration` ?

Pour un `LocalDate` ou un `LocalTime`, le choix est fait pour toi : une date n'a pas d'heure à mesurer, et une heure n'a pas de calendrier.
Un `LocalDateTime` a les deux, mais pas de fuseau horaire, donc lui ajouter `Period.ofDays(1)` ou `Duration.ofDays(1)` donne le même résultat.
La différence devient visible avec les fuseaux horaires.
Quand les horloges avancent d'une heure pour le passage à l'heure d'été, une journée calendaire ne dure que 23 heures :

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

Ajouter un `Period` d'un jour conserve l'heure de la journée, tandis qu'ajouter un `Duration` d'un jour ajoute exactement 24 heures.
Utilise un `Period` pour les quantités que l'on pense en termes de calendrier (« la même heure le mois prochain ») et un `Duration` pour le temps écoulé (« le ticket de parking est valable 2 heures »).
