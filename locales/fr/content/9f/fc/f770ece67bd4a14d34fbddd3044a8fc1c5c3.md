# À propos des caractères

C'est un sujet potentiellement _vaste_ ! On pourrait écrire un long livre là-dessus, et plusieurs personnes l'ont d'ailleurs fait (cherche « unicode book » sur Amazon pour en voir quelques exemples).

## Un très bref historique

La gestion des caractères dans les ordinateurs était bien plus simple dans les décennies précédentes, quand les programmeurs partaient du principe que l'anglais était la seule langue importante.
Donc : 26 lettres, majuscules et minuscules, 10 chiffres, quelques signes de ponctuation, plus un code (0x07) pour faire sonner une cloche, et tout cela tenait sur 7 bits : le jeu de caractères [ASCII][wiki-ascii].

Naturellement, les gens ont commencé à demander ce qu'il en était de à, ä et Ł, puis d'autres ont demandé pour ऄ, ஹ et ญ, et les jeunes voulaient des emojis 😱.
Que faire ?

Pour faire court, de nombreuses personnes intelligentes et patientes ont dû siéger des années dans des comités afin de régler les détails du jeu de caractères [Unicode][web-unicode] et des encodages comme [UTF-8][wiki-utf-8], et beaucoup de logiciels ont eu besoin d'une réécriture _très_ compliquée.
Sans compter tous les nouveaux bugs que cela a introduits.

Pour éviter que _tout_ ne casse, la conception d'Unicode/UTF-8 garantit que les 127 premiers codes sont identiques à l'ASCII _(même la cloche)_.

## Les caractères en Kotlin

Les langages conçus après 2005 environ ont l'immense avantage qu'une norme Unicode raisonnablement stable existait déjà.

Kotlin (dont la première version date de 2011) a pu partir du principe que ses utilisateurs emploieraient diverses langues (humaines) et auraient besoin d'Unicode pour les exprimer.

~~~~exercism/advanced
Les [caractères][ref-char] en Kotlin sont des [`codepoints`][wiki-codepoint] de 16 bits (UTF-16), comme le `char` d'une JVM.
Cela suffit à exprimer la plupart des alphabets écrits, mais pas toute la gamme des emojis.

La norme Unicode complète utilise jusqu'à six octets (48 bits) par caractère (ce qu'on appelle un [`grapheme`][wiki-grapheme]).

Les `Strings` de Kotlin prennent en charge cette norme complète en utilisant plusieurs codepoints par caractère lorsque c'est nécessaire.
Par exemple, 😱 correspondrait à `\uD83D` et `\uDE31`.

Malheureusement, Java n'a pas de prise en charge intégrée des graphemes, et pour des raisons de compatibilité, Kotlin non plus.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


Les littéraux de caractère s'écrivent entre apostrophes, et se distinguent des _strings_ écrites entre guillemets doubles.
Cela paraît probablement évident à qui vient du monde C/C++, mais peut dérouter les programmeurs Python et JavaScript.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

La conversion entre `Char` et `Int` est simple :

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

Le compilateur autorise _certaines_ formes d'arithmétique entière sur les `Char` :

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## Quelques fonctions pour `Char`

Comme toujours, il y a bien trop de [fonctions][ref-char-lib] pour les aborder toutes ici, voici donc seulement une sélection.

- Pour les alphabets qui s'y prêtent, change la casse avec [`uppercase()`][ref-uppercase] et [`lowercase()`][ref-lowercase].
- Teste la casse avec [`isUpperCase()`][ref-isuppercase] et [`isLowerCase()`][ref-islowercase].
- Teste le type d'un caractère avec :
  - [`isLetter()`][ref-isletter], couvre de nombreux alphabets (les catégories Lu, Ll, Lt, Lm et Lo d'Unicode)
  - [`isDigit()`][ref-isdigit], dans la plage 0..9 (la catégorie Nd d'Unicode)
  - `isLetterOrDigit()`, combine les deux précédentes
  - [`isWhitespace()`][ref-iswhitespace], n'importe quel caractère d'espacement (les catégories Cc, Zp, Zl et Zs d'Unicode)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

Par ailleurs, les [expressions régulières][ref-regex] (qui feront l'objet d'un prochain concept) permettent des recherches et des manipulations puissantes.

## Conversions entre `Char`, listes et _strings_

Pour convertir une `String` en `List` de `Char`, on peut utiliser `toList()`.

Pour convertir une `List` de `Char` en `String`, il y a la fonction [`joinToString()`][ref-jointostring], qui prend un séparateur (souvent la chaîne vide) comme argument.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

Note que `joinToString()` s'applique à une List ou un Array.
Pour _caster_ un seul `Char` en une chaîne d'un seul caractère, utilise `toString()`.

```kotlin
'a'.toString() // => "a"
```

Pour vérifier qu'un caractère est présent dans une `String`, ou dans une liste ou un tableau de `Char`, on dispose de `in`, qui correspond à la fonction [`contains()`][ref-contains].

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
