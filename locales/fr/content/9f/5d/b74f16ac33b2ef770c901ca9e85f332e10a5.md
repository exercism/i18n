# Constructeurs de _string_

`STR` est immuable ; `FSTR` ne l'est pas. Utilise `STR` pour un texte terminé et `FSTR` pour un texte encore en cours d'assemblage.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## Réaffecte toujours le résultat

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR` grandit par **doublement amorti** : quand il n'y a plus de place, il prend un nouveau tableau, plus grand, deux fois la taille, et y recopie son contenu. Le résultat est donc le plus souvent le même objet, et parfois un objet différent. Écrire `b := b + x` à chaque fois est correct dans les deux cas, et c'est la seule forme qui vaille la peine d'être apprise.

C'est ce doublement qui rend le travail total proportionnel à la longueur plutôt qu'à son carré : les copies se raréfient aussi vite qu'elles deviennent plus coûteuses.

## Pourquoi ne pas simplement utiliser `+` sur STR ?

Assembler un petit nombre fixe de morceaux avec `+` est clair et tout à fait adapté :

```sather
   return piece + " by " + composer;
```

Le problème ne se pose que dans une boucle, où le nombre d'assemblages n'est pas connu au moment où l'on écrit le code. Règle approximative : si le `+` est à l'intérieur d'une `loop`, alors utilise `FSTR`.

## Routines utiles

| Appel | Effet |
| --- | --- |
| `b + x` | ajoute ; `x` peut être `STR`, `CHAR`, `INT`, `BOOL` … |
| `b.size` | combien de caractères jusqu'ici |
| `b.str` | un `STR` terminé |
| `b.clear` | le vide, en conservant l'espace |

## Séquences d'échappement

| Écriture | Signification |
| --- | --- |
| `"\n"` | un saut de ligne |
| `"\t"` | une tabulation |
| `"\""` | un guillemet double |
| `"\\"` | une barre oblique inversée |
