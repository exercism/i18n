# Nil

Crystal possède un type appelé [`Nil`][nil], qui ne peut avoir qu'une seule valeur : `nil`.
Il sert à représenter l'absence de valeur et s'apparente à `null` ou `None` dans d'autres langages.

Des valeurs Nil peuvent être renvoyées par diverses méthodes, par exemple [`String#[]?`][string-index], qui renvoie `nil` si l'indice est hors limites.

```crystal
"foo"[10]? # => nil
```

Crystal dispose de ce que l'on appelle des **VÉRIFICATIONS DE RÉFÉRENCE NULLE**, ce qui signifie que par défaut, aucun type ne peut prendre la valeur `nil`.
Autrement dit, tu ne peux pas affecter `nil` à une variable, sauf si tu la déclares explicitement comme étant de type `Nil`.
Par conséquent, le compilateur vérifie automatiquement les références nulles.

## Valeur fausse

On peut adopter différentes approches pour gérer les valeurs `nil`.
`nil` est une [valeur fausse][truthy-falsey], tout comme `false`.
Cela signifie que dans les instructions et les autres endroits où une valeur fausse ou vraie est attendue, elle est traitée de la même façon que `false`.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Autrement dit, la branche vraie ne sera pas empruntée si une variable pouvant valoir `nil` a pour valeur `nil`.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Vérifie si une valeur est `nil`

Crystal dispose d'une méthode qui permet de vérifier si une valeur est `nil`.
Elle s'appelle [`nil?`][nil?] et elle est disponible sur tous les objets.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Le comportement est un peu différent quand on utilise simplement la valeur dans une instruction `if`, car dans les exemples précédents, `false` comme `nil` seraient traités comme faux.
Ici, seul `nil` est traité comme une valeur fausse, car si c'était `false`, ce ne serait pas `nil`, et ce serait donc vrai.

## L'opérateur OU

La façon la plus simple de gérer les valeurs `nil` est de faire en sorte qu'elles ne deviennent jamais `nil` dès le départ.
L'opérateur ou ([`||`][or]) est souvent utilisé avec les `Bools`, mais si on le comprend bien, il peut aussi servir à gérer les valeurs `nil`.
L'opérateur ou vérifie si la première valeur est vraie ; si ce n'est pas le cas, c'est la deuxième valeur qui est utilisée.
Cela permet de faire en sorte que si la valeur est `nil`, elle soit considérée comme fausse et que la deuxième valeur soit utilisée à la place.

```crystal
"foo"[10]? || "bar" # => "bar"
```
