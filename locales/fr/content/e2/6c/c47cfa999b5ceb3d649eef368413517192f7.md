# À propos des bits

Les chiffres binaires correspondent en définitive directement aux transistors de ton processeur ou de ta RAM, et à leur état « allumé » ou « éteint ».

La manipulation de bas niveau, que l'on appelle familièrement le _bit-twiddling_, est particulièrement importante dans les langages système.

Les langages de plus haut niveau comme Kotlin masquent généralement la plupart de ces détails. Cependant, un ensemble de base d'opérations au niveau des bits [est disponible][ref-bitwise].

~~~~exercism/note
Pour obtenir une sortie binaire lisible par un humain, presque tous les exemples ci-dessous doivent être enveloppés dans une fonction [`Integer.toBinaryString()`][web-binstring], ou convertis avec `toString(radix = 2)`.
 
Cela nuit à la lisibilité, c'est pourquoi la plupart des occurrences de cette fonction ont été retirées et les résultats sont représentés avec la notation `0b`.

## Les opérations de décalage de bits

Les types `Int` ou `Long`, signés comme non signés, peuvent être représentés sous la forme d'une `String` de 1 et de 0, et manipulés comme une séquence de bits.

Aussi surprenant que cela puisse paraître, les types `Byte` ou `Short` ne sont pas compatibles avec la plupart des opérations bit à bit de Kotlin. Tous les exemples ci-dessous utilisent des entiers 32 bits (`Int` ou `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Les décalages de bits déplacent tout vers la gauche ou vers la droite d'un nombre donné de positions. Certains bits sortent d'un côté, et l'autre côté est complété par des zéros ou des uns.

- Décalage à gauche avec `shl` : remplissage par des zéros.
- Décalage à droite avec `shr` ou `ushr` : remplissage par des zéros pour les nombres positifs (voir la section suivante pour les nombres négatifs).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Chaque décalage à gauche double la valeur, et chaque décalage à droite la divise par deux (avec troncature). C'est plus évident en représentation décimale :

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Ces décalages de bits sont bien plus rapides que l'arithmétique « classique », ce qui rend la technique très populaire dans le code de bas niveau.

### Le décalage de bits des entiers négatifs

Avec les entiers négatifs, il faut redoubler de prudence.

Les valeurs négatives sont stockées sous la forme du [complément à deux][wiki-2complement], ce qui signifie que le bit le plus à gauche vaut 1. Aucun problème pour un décalage à gauche, mais lors d'un décalage à droite, comment compléter les bits les plus à gauche ?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

L'opérateur [`shr`][ref-shr] effectue un [décalage arithmétique][wiki-arithmetic], qui préserve le bit de signe.

L'opérateur [`ushr`][ref-ushr] effectue un [décalage logique][wiki-logical], en complétant avec des zéros comme si le nombre n'était pas signé.

## La logique bit à bit

Nous avons vu dans le [concept des booléens][concept-booleans] que les opérateurs `&&` (et), `||` (ou) et `!` (pas) s'utilisent avec des valeurs booléennes.

Il existe des opérateurs équivalents `and`, `or` et `xor` ([ou exclusif][wiki-xor]) pour comparer les bits de deux entiers, ainsi qu'une fonction `inv` (inversion) pour inverser tous les bits.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
