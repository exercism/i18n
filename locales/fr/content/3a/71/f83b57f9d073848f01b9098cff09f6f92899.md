# Introduction

Pompes, vannes, tuyaux : tout ce qui détient une ressource du système d'exploitation (un fichier ouvert, une connexion réseau) doit être *libéré* quand on a fini de s'en servir. Le vocabulaire [`destructors`][destructors] de Factor enveloppe ces ressources dans un _framework_ qui garantit le nettoyage, même quand une erreur vient interrompre ton code à mi-parcours.

## La classe et le générique

Une classe rejoint le _framework_ en étendant `disposable` et en implémentant le générique `dispose*` :

```factor
USING: accessors destructors kernel ;

TUPLE: pump < disposable opened ;

: <pump> ( -- pump )
    pump new-disposable t >>opened ;

M: pump dispose* f >>opened drop ;
```

`new-disposable ( class -- obj )` alloue le tuple *et* l'enregistre auprès du _framework_ : une exception entre l'allocation et le prochain point sûr ne peut pas provoquer de fuite de la ressource. Le _framework_ garantit que `dispose*` s'exécute **au plus une fois** par objet ; des appels répétés à `dispose` ne font rien.

## Les appelants publics utilisent `dispose`

```
dispose          ( obj -- )                ! release; safe to call twice
with-disposal    ( disposable quot -- )    ! scope one resource
with-destructors ( quot -- )               ! open a registry scope
&dispose         ( obj -- obj )            ! dispose on normal *or* failure exit
|dispose         ( obj -- obj )            ! dispose only if the scope unwinds
```

`with-disposal` est la forme pour une seule ressource : elle empile le _disposable_ pour la _quotation_ interne et le libère en sortant.

```factor
USING: destructors io ;

<pump> [
    "pumping" print
] with-disposal
! pump released on the way out — even if `print` had thrown
```

Pour plusieurs ressources, ouvre une portée `with-destructors` et enregistre chaque acquisition. `&dispose` (esperluette) signifie « toujours libérer en sortant, en cas de succès comme d'échec ». `|dispose` (barre verticale) signifie « libérer **uniquement** en cas d'échec », ce qui est utile quand le chemin de succès transmet la ressource à un appelant qui en prend possession.

```factor
[
    <pump> &dispose
    <pump> &dispose
    ! ... use the pumps ...
] with-destructors
! both pumps released
```

Pour un simple try/finally sans registre, [`cleanup`][cleanup] (dans `continuations`) est la primitive de plus bas niveau, mais `with-destructors` est la forme idiomatique du Factor moderne.
