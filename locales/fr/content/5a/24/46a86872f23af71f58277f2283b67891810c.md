# Introduction aux _here documents_

En Bash, un _here document_ (ou _heredoc_) redirige plusieurs lignes d'entrée vers une commande ou un programme, comme si tu les saisissais directement dans le terminal.
C'est un outil puissant pour intégrer du texte sur plusieurs lignes dans tes scripts, sans avoir besoin de fichiers externes ni de manipulations complexes de _strings_.

## Caractéristiques principales et syntaxe

1. Délimiteur : un heredoc commence par l'opérateur `<<` suivi d'un mot délimiteur (souvent appelé « marqueur » ou « mot de terminaison »).
   Ce délimiteur peut être n'importe quel mot de ton choix, mais on utilise souvent quelque chose comme `EOF`, `END` ou `TEXT` pour plus de clarté.
   Pour un code plus lisible, tu peux utiliser un mot descriptif comme délimiteur, par exemple `END_INSTALLATION_INSTRUCTIONS`.

1. Contenu : après le `<< DELIMITER` initial, tu écris le contenu que tu veux rediriger.
   Cela peut être plusieurs lignes de texte, du code, ou n'importe quoi d'autre.

1. Fin : le heredoc se termine lorsque le mot délimiteur réapparaît seul sur une ligne, sans espace au début ni à la fin.

## Syntaxe de base

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## Comment ça marche

* Bash lit toutes les lignes entre le `<< DELIMITER` de départ et le `DELIMITER` de fin.
* Bash connecte ce contenu à l'entrée standard de la commande.
* La commande traite cette entrée comme si elle venait du clavier.

### Exemple 1 : Sortie de texte simple

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

Sortie :

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

Dans cet exemple :

* `cat` est la commande.
* `<< EOF` démarre le heredoc avec `EOF` comme délimiteur.
* Les trois lignes de texte constituent le contenu.
* `EOF` seul sur sa ligne termine le heredoc.
* `cat` affiche ensuite le contenu qu'il a reçu.

### Exemple 2 : Utilisation avec wc (comptage de mots)

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

Sortie :

```plaintext
3
```

Ici, `wc -l` compte le nombre de lignes.
Le heredoc fournit les trois lignes en entrée.

### Exemple 3 : Transmission de données à un script

Le script :

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

Appelle le script depuis une invite Bash interactive avec un heredoc :

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

Sortie :

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## Variantes et fonctionnalités avancées

### Contenu littéral

Bash effectue l'expansion des variables, la substitution de commandes et l'expansion arithmétique à l'intérieur d'un heredoc.
En ce sens, les heredocs se comportent comme des _strings_ entre guillemets doubles.

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

Sortie :

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

Lorsqu'on met le délimiteur entre guillemets (simples ou doubles), ces expansions n'ont plus lieu.
Le contenu est pris littéralement.
C'est comme avec des _strings_ entre guillemets simples.

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

Sortie :

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### Supprime les tabulations de début de ligne

Si tu utilises `<<-` (avec un tiret final) au lieu de `<<`, Bash supprime les _caractères de tabulation_ en début de chaque ligne du heredoc.
C'est utile pour indenter le contenu du heredoc dans ton script sans modifier la sortie.

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

La sortie est affichée avec toutes les tabulations de début supprimées :

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
L'auteur ne recommande pas cette utilisation.
Même si cela peut améliorer la lisibilité du script,

1. il est facile de remplacer accidentellement les tabulations par des espaces (ton éditeur peut le faire automatiquement), et 
1. il est difficile de repérer la différence entre les espaces et les tabulations.
~~~~

## Quand utiliser les _here documents_

* Entrée sur plusieurs lignes : quand tu dois fournir plusieurs lignes de texte à une commande.
* Fichiers de configuration : intégrer de petits extraits de configuration dans un script.
* Génération de code : créer du code à la volée dans un script.
* Interactions scriptées : simuler la saisie de l'utilisateur pour des programmes interactifs.
* Éviter les fichiers externes : quand tu veux éviter de créer des fichiers temporaires.

Un cas d'usage typique consiste à fournir un texte d'aide :

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## Inconvénients possibles

* De gros documents intégrés peuvent rendre ton code plus difficile à lire.
  Il peut être préférable de déployer ton script avec la documentation dans des fichiers séparés.
* Les _here documents_ peuvent perturber le flux du code.
  Tu peux te trouver dans une section de code profondément imbriquée au moment où tu veux transmettre du texte à un programme.
  L'indentation du heredoc peut paraître déroutante par rapport au code qui l'entoure.

## Les _here strings_

Comme les _here documents_, les _here strings_ (ou _herestrings_) fournissent une entrée à une commande.
Toutefois, alors que les heredocs sont donnés sous forme de bloc de texte, les herestrings sont donnés sous forme d'une seule _string_ de texte.
Les here strings utilisent la syntaxe `<<< "text"`.

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

Sortie :

```plaintext
UPPER CASE THIS STRING
```

Contrairement aux heredocs, aucun délimiteur de fin n'est nécessaire.

### Pourquoi utiliser les _here strings_ ?

On peut utiliser un pipeline à la place d'une here string :

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

Alors, pourquoi utiliser une here string ?

Prenons le cas où tu obtiens la _string_ en sortie d'un calcul long, et où tu veux transmettre le résultat à deux commandes distinctes.
Avec des pipelines, tu dois exécuter le calcul deux fois :

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

Une approche plus efficace consiste à capturer la sortie du calcul (avec une substitution de commande) et à utiliser des here strings pour fournir l'entrée aux deux commandes suivantes :

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

Voici une application concrète de cet exemple :

* capturer la réponse JSON à une requête d'API REST (paginée),
* fournir les données JSON à un programme jq pour analyser les résultats et les écrire dans un fichier, puis
* fournir les données JSON à un autre programme jq pour déterminer l'URL de la requête suivante.

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

Remarque la position de la redirection de sortie.
Toute la sortie de la boucle `while` sera ajoutée au fichier `data.csv`.

## Les heredocs et les herestrings comme redirections

Comme ce ne sont que des formes de redirection, on peut les combiner avec d'autres opérations de redirection :

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## En résumé

Les _here documents_ (ou _heredocs_) sont un moyen souple et pratique de gérer des entrées sur plusieurs lignes dans les scripts Bash.
Ils simplifient l'intégration de texte et de données directement dans tes scripts, ce qui les rend plus autonomes et plus faciles à lire.

Les _here strings_ (ou _herestrings_) sont semblables aux _here documents_, mais offrent une syntaxe plus simple et plus dynamique.
