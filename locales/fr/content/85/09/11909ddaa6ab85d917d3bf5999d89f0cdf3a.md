# À propos

Les charlists sont créées à l'aide du sigil `~c`.

```elixir
~c"hello"
```

~~~~exercism/note
Dans les anciennes versions d'Elixir, les charlists étaient représentées par `'hello'` entre guillemets simples.
~~~~

Une charlist est un tableau d'entiers. Les entiers représentent les valeurs Unicode d'un caractère donné, aussi appelées points de code.

```elixir
[65, 66, 67]
# => ~c"ABC"
```

## Les charlists _sont_ des tableaux

```elixir
~c"" === []
# => true

is_list(~c"hello")
# => true
```

Comme les charlists sont des tableaux, on peut les manipuler exactement comme n'importe quel autre tableau, en utilisant la récursion et le pattern matching, ou le module [`List`][list].

```elixir
[first_letter | _] = ~c"cat"
first_letter
# => 99

List.first(~c"hello")
# => 104
List.pop_at(~c"hello", 0)
# => {104, ~c"ello"}

```

On peut concaténer deux tableaux avec [`++`][kernel-concat-list].

```elixir
~c"hi" ++ ~c"!"
# => ~c"hi!"
```

Plus le premier tableau est long, plus la concaténation est lente, donc évite d'ajouter des éléments de façon répétée à des tableaux de longueur arbitraire.

## Imprimabilité

Si un tableau d'entiers ne contient que des entiers qui sont des points de code de caractères imprimables, il sera affiché comme une charlist. Même s'il a été défini avec la syntaxe `[]`.

```elixir
~c"ABC"
# => ~c"ABC"

[65, 66, 67]
# => ~c"ABC"
```

Si un tableau d'entiers contient ne serait-ce qu'un point de code d'un caractère non imprimable (par exemple `0-6`, `14-26`, `28-31`), il sera affiché comme un tableau. Même s'il a été défini avec la syntaxe `~c""`.

```elixir
~c"ABC\0"
# => [65, 66, 67, 0]

[65, 66, 67, 0]
# => [65, 66, 67, 0]
```

On peut vérifier l'imprimabilité avec [`List.ascii_printable?`][list-ascii-printable].

```elixir
List.ascii_printable?([65, 66, 67])
# => true
List.ascii_printable?([65, 66, 67, 0])
# => false
```

Garde à l'esprit que ce sont deux façons différentes d'_afficher_ les mêmes données. Les valeurs sont strictement égales.

```elixir
~c"ABC" === [65, 66, 67]
# => true
```

Quand on affiche un tableau avec [`IO.inspect`][io-inspect], on peut utiliser l'option [`:charlists`][inspect-opts] pour contrôler la façon dont les tableaux sont affichés.

```elixir
IO.inspect(~c"ABC", charlists: :as_charlists)
# => prints ~c"ABC"

IO.inspect(~c"ABC", charlists: :as_lists)
# => prints [65, 66, 67]
```

## Points de code

On peut faire précéder un caractère de `?` pour obtenir son point de code.

```elixir
?A
# => 65

[?:, ?)]
# => ~c":)"
```

## Charlists vs _strings_

Une charlist et un _string_ composés des mêmes caractères ne sont pas considérés comme égaux.

```elixir
~c"hello" == "hello"
false
```

Chaque valeur d'une charlist est le [point de code Unicode d'un caractère][unicode-table], tandis que dans un _string_, les points de code sont encodés en [UTF-8][utf8].

```elixir
IO.inspect(~c"tschüss", charlists: :as_lists)
# => prints [116, 115, 99, 104, 252, 115, 115]

IO.inspect("tschüss", binaries: :as_binaries)
# => prints <<116, 115, 99, 104, 195, 188, 115, 115>>
```

Remarque comment `ü`, de point de code `252`, est encodé en UTF-8 sous la forme `195` et `188`.

**En pratique, les charlists sont rarement utilisées**. Leur principal cas d'usage est l'interfaçage avec Erlang, en particulier lorsqu'on utilise des bibliothèques plus anciennes qui n'acceptent pas les binaires en argument.

Quand on travaille avec Elixir, **utilise des _strings_ pour stocker du texte**. Le module `String` offre un large choix de fonctions pour traiter du texte, des fonctions qui ne sont pas disponibles pour les charlists.

On peut convertir des charlists en _strings_ avec [`to_string`][kernel-to-string].

```elixir
to_string(~c"hello")
# => "hello"
```
