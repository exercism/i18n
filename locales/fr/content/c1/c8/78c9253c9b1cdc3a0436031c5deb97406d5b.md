# Introduction

La liaison décrit depuis quel endroit du code un identifiant est accessible.
Les valeurs qui ont une portée de bloc, de fonction ou de prototype de fonction n'ont aucune liaison.
Cela signifie qu'on ne peut pas y accéder depuis l'extérieur de leur portée.
Pour en savoir plus sur la portée, consulte le [concept de portée](../scope/introduction.md#Introduction).

## Liaison externe

Les identifiants qui ont une portée de fichier ont une liaison externe par défaut.
Un identifiant à liaison externe peut être appelé depuis n'importe quel fichier du programme.

## Liaison interne

On peut donner à un identifiant qui a une portée de fichier une liaison interne en utilisant le spécificateur `static`.
Un identifiant à liaison interne ne peut être utilisé que dans son fichier.

Par exemple

```c
int public_count = 0; // file scope, external linkage by default
static int private_count = 0;  // file scope, internal linkage 

// file scope, internal linkage
static void some_function()
{
    // code snipped
}

// file scope, external linkage by default
int main()
{
    // code snipped
}
```

Il ne faut pas confondre la liaison statique avec la durée de stockage statique.
Pour en savoir plus sur la durée de stockage statique, consulte le [concept de durée de stockage](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#static-the-storage-specifier-not-to-be-confused-with-the-static-linkage-type).
