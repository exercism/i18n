# Instructions supplémentaires

## Responsabilités de Roc et de l'hôte

Dans le code Roc, on se concentre généralement sur la logique métier, tandis que la plateforme gère la concurrence et l'état partagé.
Par conséquent, dans cet exercice, il te suffit d'implémenter les opérations sur les comptes dans `BankAccount.roc`, sans avoir à te soucier de la concurrence.
Les comptes sont fermés au départ, une réouverture réinitialise le solde, et les montants des dépôts et des retraits doivent être positifs.

## Démo facultative du serveur

Le fichier `bank-account-demo.roc` fourni montre comment ton implémentation peut être utilisée dans un petit service web.
Tu peux le lire dans l'éditeur, mais il est indépendant des tests et ne fait pas partie de ta solution.

Pour lancer la démo, tu dois [installer Roc](https://www.roc-lang.org/install/) sur ta machine, installer [l'Exercism CLI](https://exercism.org/cli-walkthrough), puis exécuter cette commande dans un terminal :

```sh
exercism download --exercise=bank-account --track=roc
```

Ensuite, implémente `BankAccount.roc` et teste-le avec la commande suivante (modifie l'emplacement de téléchargement affiché par la CLI s'il diffère du chemin ci-dessous) :

```sh
cd ~/Exercism/roc/bank-account
roc test bank-account-test.roc
```

Une fois que tous les tests passent, tu peux démarrer le serveur de démo avec la commande suivante :

```sh
roc bank-account-demo.roc
```

Le serveur utilise la [plateforme basic-webserver](https://github.com/roc-lang/basic-webserver) et sa prise en charge intégrée de SQLite (Roc télécharge la plateforme au premier lancement).
Aucun serveur de base de données séparé n'est nécessaire.
Le serveur écoute sur `http://127.0.0.1:8000` et crée `bank-account-demo.db` dans ton répertoire courant (définis `DB_PATH` pour utiliser un autre fichier de base de données).
Arrête le serveur avec Ctrl-C.
Les données sont conservées d'un redémarrage à l'autre.

Dans un autre terminal, tu peux appeler le service web avec `curl` (sous Windows, utilise `curl.exe` partout pour éviter l'alias `curl` de PowerShell).
Par exemple, voici comment ouvrir le compte n° 123, déposer 50, retirer 10 et vérifier son solde :

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/open
curl -X POST http://127.0.0.1:8000/accounts/123/deposit/50
curl -X POST http://127.0.0.1:8000/accounts/123/withdraw/10
curl http://127.0.0.1:8000/accounts/123/balance
```

Le solde est de `40`.
Les identifiants de compte et les montants doivent être des entiers non signés.
Les mises à jour renvoient `OK` en cas de succès ou une erreur de ton implémentation de compte en cas d'échec.
Pour fermer le compte n° 123 :

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/close
```

Pour essayer des requêtes concurrentes sous Linux ou macOS, utilise un nouvel identifiant de compte et envoie 100 dépôts depuis huit clients :

```sh
curl -X POST http://127.0.0.1:8000/accounts/456/open
seq 100 | xargs -P 8 -I '{}' curl --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1
curl http://127.0.0.1:8000/accounts/456/balance
```

Sous Windows, utilise [PowerShell 7+](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows) pour l'exemple de parallélisme :

```powershell
curl.exe -X POST http://127.0.0.1:8000/accounts/456/open
1..100 | ForEach-Object -Parallel { curl.exe --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1 } -ThrottleLimit 8
curl.exe http://127.0.0.1:8000/accounts/456/balance
```

Tous les dépôts devraient réussir et le solde devrait être de `100`.

## Comment la démo gère la concurrence

Chaque requête lit le compte, appelle tes fonctions Roc et enregistre le résultat dans une transaction SQLite `Immediate`.
Les opérations qui échouent sont annulées sans modifier le compte.
SQLite n'autorise qu'un seul écrivain à la fois, ce qui empêche les requêtes concurrentes d'écraser mutuellement leurs mises à jour (même entre comptes différents).

Remarque : l'exercice utilise `U64`, mais la démo stocke les soldes sous forme d'entiers SQLite et rejette les mises à jour dépassant la valeur maximale de `I64` (`9223372036854775807`).

Pour un exemple de calculs indépendants exécutés en parallèle, essaie l'exercice [Fréquence des lettres en parallèle](https://exercism.org/tracks/roc/exercises/parallel-letter-frequency).
