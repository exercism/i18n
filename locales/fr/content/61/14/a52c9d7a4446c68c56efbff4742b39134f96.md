# Introduction

Les expressions régulières sont un moyen très polyvalent de _rechercher des motifs_ dans des _strings_, grâce à un langage dédié (DSL) conçu pour cette tâche.

De nombreuses fonctionnalités des expressions régulières sont intégrées à Base R, et on en trouve des exemples dans du code plus ancien.

Pour du code nouveau, il est _vivement_ recommandé d'utiliser la bibliothèque [`stringr`][web-stringr].

Comme indiqué dans le [concept Strings][concept-strings], `stringr` dispose d'une bonne documentation, généralement écrite par le ou les auteurs du paquet.

- Un [site de référence][web-stringr]
- Un [aide-mémoire][cheat-stringr].
- Un [chapitre sur les _strings_][book-strings] et un [chapitre sur les expressions régulières][book-regex] dans « R for Data Science ».

Beaucoup des fonctions déjà présentées dans le concept [`Strings`][concept-strings] sont conçues nativement pour les recherches par expression régulière.

On a gardé le concept Strings relativement simple, en se limitant à la recherche de chaînes littérales, mais n'importe quel motif d'expression régulière peut être utilisé à la place.

À proprement parler, une expression régulière est créée en R en appelant [`regex()`][ref-regex].
Par commodité, les fonctions de `stringr` traitent tout motif fourni sous forme de chaîne comme une expression régulière.
Dans l'exemple ci-dessous, le premier `str_replace_all()` est du sucre syntaxique pour la seconde version :

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

L'[aide-mémoire][cheat-stringr] est un guide utile : toutes les fonctions qui prennent un argument `pattern` (imprimé en rouge) acceptent une expression régulière, et la page 2 résume la syntaxe des expressions régulières.

Note que la fonction [`regex()`][ref-regex] peut malgré tout être importante si tu as besoin de modifier les valeurs par défaut, par exemple la sensibilité à la casse ou la locale.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

De nombreux codes d'expressions régulières comportent une barre oblique inversée, comme le `\s` utilisé ci-dessus.
Dans des chaînes R ordinaires, il faut doubler le `\` pour l'échapper, d'où `"\\s"`.

Les barres obliques inversées peuvent se multiplier et devenir sources de confusion, il peut donc être utile d'utiliser des [chaînes brutes][book-raw] dans les cas complexes.

Par défaut, la syntaxe pour définir une chaîne brute est `r"( )"`, mais d'autres délimiteurs sont autorisés.
Comme les parenthèses `( )` et les crochets `[ ]` sont tous les deux courants dans la syntaxe des expressions régulières (pour les groupes de capture et les groupes d'options), les accolades `{ }` peuvent être un bon choix.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## Détecte les correspondances

Voici quelques questions, et les fonctions qui peuvent aider à y répondre.

Certains exemples utilisent `fruit`, un vecteur de 80 noms de fruits fourni avec `stringr` pour s'entraîner.

_Est-ce qu'une chaîne de caractères contient une correspondance ?_
`str_detect()`, ou bien `str_starts()` et `str_ends()` pour éviter d'utiliser les ancres `^` ou `$`.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_Ne renvoyer que les chaînes qui contiennent une correspondance ?_
Utilise `str_subset()` pour obtenir les chaînes, `str_which()` pour obtenir les indices.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_Combien de correspondances dans chaque chaîne ?_
Utilise `str_count()`.

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_Où se trouve la correspondance ?_
`str_view()` pour un usage interactif, `str_locate()` ou `str_locate_all()` de façon plus générale.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## Captures

Souvent, on veut savoir _ce qui_ correspond. 
Pour cela, on inclut des groupes de capture entre parenthèses dans l'expression régulière.

Il est possible de faire référence à une capture au sein d'une même expression régulière, avec `\1`, `\2`, etc.
Par exemple, pour trouver des paires de lettres répétées :

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

Avec une syntaxe similaire, les captures peuvent être utilisées dans les chaînes de remplacement :

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

Récupère les correspondances pour les traiter ensuite, avec la fonction `str_match()` pour la première correspondance uniquement, ou `str_match_all()` pour toutes les correspondances.

Les groupes de capture ont tendance à produire une sortie compliquée, quel que soit le langage.
L'approche de R (_qui est en plus vectorisée, pour corser le tout_) consiste à générer une matrice à partir de `str_match()`, avec une ligne par chaîne d'entrée, la colonne 1 contenant la correspondance complète, et les colonnes suivantes les différents groupes de capture.

Utiliser des groupes nommés peut être un avantage, puisqu'ils deviennent les noms des colonnes de la matrice de résultats.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

On n'a pas beaucoup parlé des matrices dans ce programme, mais tu peux consulter un [document de concept][concept-matrices-arrays].
Les matrices s'intègrent mal à l'écosystème Tidyverse, même si elles font partie de Base R depuis longtemps.

En résumé rapide : considère les matrices comme des vecteurs à 2 indices, dans l'ordre `[rows, cols]`.
Laisse l'un ou l'autre des indices vide pour obtenir la ligne ou la colonne entière.

Quand on récupère une seule ligne `r` avec `m[r,]` ou une seule colonne `c` avec `m[,c]`, la valeur renvoyée est aplatie en un vecteur par défaut.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

Forcément, `str_match_all()` produit une sortie encore plus structurée :

- Le résultat est une liste, avec un élément par chaîne d'entrée.
- S'il n'y a qu'une seule chaîne d'entrée, aplatis la sortie avec l'indexation `[[1]]`, comme décrit dans le [concept Lists][concept-lists].
- Chaque élément est une matrice, avec les mêmes colonnes que pour `match()`.
- Chaque ligne de la matrice correspond à une capture réussie.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

Bien sûr, une correspondance peut échouer.
Le résultat est alors la valeur spéciale `NA`.
Sois prêt à tester ce cas, comme décrit dans le [concept Nothingness][concept-nothingness].

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
