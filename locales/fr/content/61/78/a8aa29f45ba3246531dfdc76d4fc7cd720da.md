# Booléens

`BOOL` contient l'une de deux valeurs, `true` et `false`.

```sather
   ready : BOOL is
      return true;
   end;
```

## Comparaison

| Opérateur | Demande | Exemple |
| --- | --- | --- |
| `=` | identique ? | `age = 13` |
| `/=` | différent ? | `age /= 13` |
| `<` | inférieur à | `age < 13` |
| `<=` | inférieur ou égal à | `age <= 13` |
| `>` | supérieur à | `age > 13` |
| `>=` | supérieur ou égal à | `age >= 13` |

Ils fonctionnent sur les nombres, et `=` et `/=` fonctionnent aussi sur les _strings_.

## Les trois opérateurs

| Opérateur | Écriture | Vrai quand |
| --- | --- | --- |
| and | `a and b` | les deux sont vrais |
| or | `a or b` | au moins l'un est vrai |
| not | `~a` | `a` est faux |

`and` et `or` sont **évalués en court-circuit** : `a and b` ne prend pas la peine de regarder `b` dès que `a` s'avère faux, car la réponse est déjà fixée. De même, `a or b` s'arrête si `a` est vrai. Cela compte quand le membre de droite est coûteux, ou qu'il poserait problème s'il était exécuté.

## Renvoie directement une comparaison

Une routine dont le seul travail est de poser une question doit renvoyer la question, et non choisir une réponse à l'aide d'un test conditionnel :

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

Écrire `if age >= 13 then return true else return false end` prend trois lignes pour dire ce que la comparaison disait déjà, et tout lecteur expérimenté le remarquera.

## Priorité

`~` a la priorité la plus forte, puis `and`, puis `or`. Ainsi,

```sather
~a and b or c
```

signifie `((~a) and b) or c`. Les parenthèses ne coûtent rien à écrire, et elles valent la peine chaque fois qu'un lecteur devrait sinon se rappeler cet ordre pour suivre la ligne.
