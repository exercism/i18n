# Les bases du `match`

L'expression `match` permet de comparer facilement une valeur à une série de motifs, puis d'exécuter le code correspondant au motif trouvé.
Un motif peut être constitué de valeurs littérales, de noms de variables, de jokers et de bien d'autres choses.

```rust
#[derive(Drop)]
enum Color {
    Red,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red => println!("The color is Red"),
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Yellow;
    print_color_type(color); // prints "The color is Yellow"
}
```

Pour gérer plusieurs lignes de code, la branche du `match` doit être entourée d'accolades `{}` :

```rust
fn specified_color(color: Color) -> felt252 {
    let mut response: felt252 = '';

    match color {
        Color::Red => {
            response = 'You passed in Red';
        },
        Color::Yellow => {
            response = 'You passed in Yellow';
        },
        Color::Green => {
            response = 'You passed in Green';
        },
    }

    response
}
```

L'expression `match` a aussi la particularité de lier des valeurs qui correspondent au motif.
Cela permet d'extraire la valeur associée à une variante d'énumération.

```rust
#[derive(Drop, Debug)]
enum ColorType {
    Light,
    Dark,
}

#[derive(Drop)]
enum Color {
    Red: ColorType,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red(state) => {
            println!("The color is Red");
            println!("The Color Type is {:?}", state);
        },
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Red(ColorType::Dark);
    print_color_type(color);
}
```

Ici, la variante `Red` de l'énumération `Color` est étendue pour porter une énumération associée.
Grâce à l'expression `match`, on peut extraire la valeur associée, `state`.
Il s'agit simplement d'un nom de variable qui peut ensuite être utilisé dans la branche de code.

## Fais correspondre le type d'énumération `Option`

L'énumération native `Option` peut elle aussi être traitée avec l'expression `match`.

Concevons une fonction qui prend un paramètre `Option<u8>`.
Si le paramètre fourni contient une valeur, on y ajoute 1 ; sinon, la fonction renvoie la valeur `None` sans rien faire.

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
        Option::None => Option::None,
    }
}

fn main() {
    let three: Option<u8> = Option::Some(3);
    let four: Option<u8> = add_one(three);
    let none = add_one(Option::None);

    println!("{three:?}"); // prints "Option::Some(3)"
    println!("{four:?}"); // prints "Option::Some(4)"
    println!("{none:?}"); // prints "Option::None(())"
}
```

> Remarque : `{:?}` est une syntaxe de formatage spéciale qui permet d'afficher une forme de débogage du paramètre passé à la macro `println!`.
> Tu trouveras plus d'informations à ce sujet dans [The Cairo Book][debugging].

L'un des avantages de la structure de contrôle `match` est son caractère exhaustif : les motifs des branches doivent couvrir _toutes_ les possibilités.
Prenons la version de l'exemple précédent qui ne gère pas le cas `None` :

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
    }
     // this code does not compile, as we forgot to handle the `None` case
}
```

## Le motif attrape-tout avec le joker `_`

Avec les énumérations, on peut aussi exécuter des actions spécifiques pour quelques valeurs particulières, et une action par défaut pour toutes les autres, en ajoutant une branche avec `_` comme motif pour la dernière branche de l'expression `match`.
Le motif `_` est un motif spécial qui correspond à n'importe quelle valeur sans la lier.

La fonction `is_red` reçoit un paramètre et renvoie `true` si la couleur est `Red`, et `false` pour toute autre couleur :

```rust
fn is_red(color: Color) -> bool {
    match color {
        Color::Red => true,
        _ => false,
    }
}
```

## La correspondance de motifs avec l'opérateur `|`

La structure de contrôle `match` de Cairo permet de faire correspondre une valeur à plusieurs motifs à l'aide de l'opérateur `|` (_ou_).
Cela permet de simplifier le code.

Par exemple, avec l'énumération `Color`, on veut écrire une fonction qui renvoie `true` pour les couleurs `Red` ou `Green`, et `false` pour les autres couleurs :

```rust
fn is_red_or_green(color: Color) -> bool {
    match color {
        Color::Red | Color::Green => true,
        _ => false,
    }
}
```

## La correspondance de motifs avec `felt252` et les variables entières

Il est possible de faire correspondre des variables `felt252` et entières à un ensemble de valeurs.
Cependant, il y a quelques contraintes :

- Seuls les entiers qui tiennent dans un seul `felt252` sont pris en charge (autrement dit, `u256` n'est pas pris en charge).
- 0 doit être la première branche.
- Chaque branche doit suivre un segment séquentiel, de façon contiguë avec les autres branches.

Implémentons un jeu de lancer de dé à six faces.
Quand on lance ce dé, on obtient un nombre entre 0 et 5.
Si le lancer donne 0, 1 ou 2, tu gagnes.
Tu relances le dé si tu obtiens 3.
Tu perds pour les autres valeurs :

```rust
fn toss(value: u8) {
    match value {
        0 | 1 | 2 => println!("you won!"),
        3 => println!("you can roll again!"),
        _ => println!("you lost...")
    }
}

fn main() {
    toss(2); // prints "you won!".
    toss(3); // prints "you can roll again!".
    toss(5); // prints "you lost...".
}
```

## Fais correspondre les tuples

On peut aussi faire correspondre des tuples à un ensemble de motifs.
Ces motifs se construisent de la même façon qu'un tuple.

```rust
#[derive(Drop)]
enum DayType {
    Week,
    Weekend,
    Holiday
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn vending_machine_accept(c: (DayType, Coin)) -> bool {
    match c {
        (DayType::Week, _) => true, // accepts all coins during week day
        (_, Coin::Dime) | (_, Coin::Quarter) => true, // accepts only Dime or Quarter coin for all specified days
        (_, _) => false, // returns false for other instances
    }
}
```

Dans la dernière branche du `match`, peu importe qu'on utilise `(_, _)` ou simplement le joker `_` pour correspondre à n'importe quelle combinaison de jour et de couleur, car les deux sont fonctionnellement équivalents.
