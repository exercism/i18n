# Instructions

Dans cet exercice, on va traiter des messages de _log_ répartis sur six niveaux de gravité.

Chaque ligne de _log_ est une _string_ au format suivant : `"[<LVL>]: <MESSAGE>"`.

Voici les différents niveaux de _log_ :

| NIVEAU    | ABRÉVIATION |
| --------- | ----------- |
| `Trace`   | `TRC`       |
| `Debug`   | `DBG`       |
| `Info`    | `INF`       |
| `Warning` | `WRN`       |
| `Error`   | `ERR`       |
| `Fatal`   | `FTL`       |

## 1. Analyse le niveau de _log_

Définis une énumération `LogLevel` qui possède six éléments correspondant aux niveaux de _log_ définis ci-dessus.
Ensuite, définis la fonction `parse_log_level` qui prend le message de _log_ en paramètre et renvoie le membre de l'énumération correspondant à son niveau.

```python
parse_log_level("[INF]: File deleted")
#=> LogLevel.Info
```

## 2. Gère un niveau de _log_ inconnu

Malheureusement, certains messages de _log_ arrivent parfois avec une gravité _inconnue_. Pour gérer sans problème ces messages de _log_ « mystérieux » dans la fonction `parse_log_level`, ajoute un membre `Unknown` à l'énumération `LogLevel`, qui est renvoyé lorsqu'on analyse un niveau de _log_ inconnu :

```python
parse_log_level("[XYZ]: Overly specific, out of context message")
#=> LogLevel.Unknown
```

## 3. Convertis un message de _log_ au format court

Le niveau de _log_ d'une ligne de _log_ est assez verbeux. Pour réduire l'espace disque nécessaire au stockage des messages de _log_, un format court est défini : `"[<CODE_LEVEL>]:<MESSAGE>"`.

Les codes des niveaux de _log_ suivent une correspondance simple :

| NIVEAU    | CODE |
| --------- | ---- |
| `Trace`   | `0`  |
| `Debug`   | `1`  |
| `Info`    | `4`  |
| `Warning` | `5`  |
| `Error`   | `6`  |
| `Fatal`   | `7`  |
| `Unknown` | `42` |

Définis la fonction `convert_to_short_log()`, qui prend deux paramètres :

1. Niveau de _log_ : le niveau de _log_ du message envoyé, par ex. `LogLevel.Error`.
2. Message de _log_ : le message, de type `str`.

```python
convert_to_short_log(LogLevel.Error, "Stack overflow")
# => "6:Stack overflow"
```

## 4. Crée un alias

Il semble que l'utilisateur ait créé des _logs_ pour `LogLevel.Warn` au lieu de `LogLevel.Warning`. Crée un `alias` pour `LogLevel.Warning` et renvoie le nouveau membre alias depuis la fonction `get_warn_alias`.

Cela peut se faire dans la même classe d'énumération `LogLevel` déjà définie en haut du fichier. Les deux niveaux de _log_ doivent pointer vers la même valeur : `"WRN"`.

```python
get_warn_alias()
#=> LogLevel.Warn

get_warn_alias() == LogLevel.Warning
#=> True
```

## 5. Tous les noms et valeurs des membres

Définis la fonction `get_members()`.

Cette fonction doit renvoyer une liste de tuples `(name, value)` contenant tous les membres de l'énumération `LogLevel`.

```python
get_members()
#=> [('Trace', 'TRC'), ('Debug', 'DBG'), ('Info', 'INF'), ('Warning', 'WRN'),
# ('Error', 'ERR'), ('Fatal', 'FTL'), ('Unknown', 'UKN')]
```
