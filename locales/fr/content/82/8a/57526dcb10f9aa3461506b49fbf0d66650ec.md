# À propos

L'assembleur écrit à la main est plein de répétitions.
La même courte suite d'instructions revient sans cesse, avec peu de variations, et il existe peu d'abstractions pour réduire le code qui se répète.
Et ce n'est pas tout : écrire en assembleur demande de gérer des valeurs sans sémantique évidente.
Il n'y a pas de paramètres nommés, et la plupart des détails de la machine sous-jacente doivent être gérés manuellement par le programmeur.

NASM, l'assembleur utilisé par le parcours, offre quelques outils qui peuvent aider le programmeur sur ces deux points.
Ces outils s'exécutent au _moment de l'assemblage_, avant qu'aucune instruction n'atteigne le processeur.
Ils indiquent à l'assembleur comment réécrire le texte source avant même qu'il ne soit traduit en code machine.

Le plus important de ces outils, ce sont les **macros**, que l'on peut voir comme une recette destinée à l'assembleur.
Elles sont insérées à l'endroit où on les utilise, comme si le code y avait été écrit à la main.

Les [macros][macro] peuvent prendre un certain nombre de jetons littéraux en paramètres, ce qui les rend réutilisables dans différents contextes.
Cependant, ce ne sont pas des fonctions : il n'y a pas de `call`, pas de `ret`, ni de transfert de contrôle vers un autre point du code.

## Macros d'une seule ligne

La définition la plus simple donne un nom à une valeur ou à une courte expression avec `%define` :

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Chaque occurrence ultérieure de `WIDTH` est remplacée par `8` avant l'assemblage.
Le remplacement est textuel : le nom est donc substitué partout où il apparaît, que ce soit dans un opérande ou à l'intérieur d'une autre définition.

~~~~exercism/note
Pour les _constantes_ numériques, préfère `equ` à `%define`.

Une macro d'une seule ligne déclarée avec `%define` n'est remplacée par son contenu que lorsqu'on l'utilise, et elle peut être réaffectée ou indéfinie.
Une constante `equ`, en revanche, est évaluée au moment de sa définition et n'est jamais modifiée.
~~~~

Un `%define` peut aussi prendre des paramètres _nommés_, qui se comporte comme une petite fonction en ligne :

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Mets entre parenthèses à la fois le corps entier et chaque paramètre.
Avec `%define square(x) x*x`, l'appel `square(1+1)` est remplacé par `1+1*1+1`, ce qui donne `3`.
Écrit sous la forme `%define square(x) ((x)*(x))`, le même appel est remplacé par `((1+1)*(1+1))`, ce qui donne `4`.
~~~~

Les noms définis avec `%define` sont sensibles à la casse.
La variante `%idefine` rend le nom insensible à la casse, si on le souhaite.

Les macros d'une seule ligne sont utiles pour donner du sens à diverses parties du code.
Si on les utilise avec soin, cela améliore la lisibilité et réduit le risque de fautes de frappe.
Par exemple, un registre qui joue un rôle bien précis à l'intérieur d'une fonction peut être défini par ce rôle :

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Macros sur plusieurs lignes

Toute une séquence de code, quel que soit le nombre de lignes, est capturée avec `%macro`, et se termine par `%endmacro`.
Un nombre après le nom indique combien d'arguments la macro prend, ce qui peut être zéro.
Lorsqu'on lui passe des arguments, ceux-ci sont séparés par une virgule (`,`) :

```x86asm
%macro example_macro 0
...
%endmacro
```

Les arguments des macros multilignes ne sont pas nommés.
On y fait référence par `%1`, `%2`, etc., dans l'ordre où ils sont passés :

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Note que les arguments doivent être une syntaxe valide pour les opérations effectuées dans le corps de la macro.
Ici, `mult_two eax, ecx` et `mult_two r8, r9` s'assemblent tous les deux, mais `mult_two eax, cl` ne le ferait pas, car `imul eax, cl` n'est pas défini.

Les macros peuvent aussi prendre un nombre arbitraire d'arguments.
Cela se fait avec la notation `n-*`, où `n` est le nombre minimum d'arguments :

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

Dans une macro multiligne, `%0` désigne le _nombre_ d'arguments de la macro.
C'est particulièrement utile dans les macros qui peuvent prendre un nombre arbitraire d'arguments.

### Étiquettes à l'intérieur d'une macro

Une macro qui définit une étiquette ordinaire casse dès qu'on l'utilise deux fois, car l'étiquette serait alors définie deux fois elle aussi.
Pour utiliser des étiquettes à l'intérieur d'une macro susceptible d'être appelée plusieurs fois, il faut faire précéder ces étiquettes de `%%`.
Cela indique à l'assembleur de donner à cette étiquette un nom différent et unique à chaque fois que la macro est utilisée :

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Répéter au moment de l'assemblage

Il est possible de répéter un bloc de code d'une seule ligne avec [`times`][times].
C'est particulièrement utile lorsqu'on déclare des valeurs répétées en mémoire :

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Pour répéter du code sur plusieurs lignes, on peut plutôt utiliser `%rep` :

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Note que le nombre de répétitions se précise juste après `%rep` et qu'un `%endrep` vient fermer le bloc répété.

Il est courant d'utiliser un compteur au moment de l'assemblage à l'intérieur d'un bloc `%rep`, un peu comme une boucle à l'exécution utilise un compteur.
Alors qu'une constante entière évaluée au moment de l'assemblage peut être déclarée avec `equ`, comme on l'a déjà vu, pour des _variables_ entières évaluées au moment de l'assemblage on utilise plutôt `%assign`.
Contrairement à `%define`, `%assign` est immédiatement évalué en un nombre et peut être réaffecté :

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Une fois le préprocesseur passé, la boucle a disparu et il reste quatre instructions `add`, avec les valeurs immédiates `0`, `1`, `2` et `3` directement intégrées.
C'est du déroulage de boucle effectué par l'assembleur : aucun registre compteur, aucune instruction de branchement, juste du code linéaire.

Un autre usage courant de `%rep` est de traiter les arguments d'une macro qui peut en prendre un nombre quelconque.
Dans ce cas, `%rep` est généralement associé à `%rotate`, qui fait tourner les arguments d'une macro, de sorte que le deuxième argument devienne le premier.
Des applications répétées de `%rotate` font du troisième argument le premier, puis du quatrième, et ainsi de suite, ce qui garantit que chaque argument peut être traité à son tour :

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## Assemblage conditionnel

Diverses instructions conditionnelles sont à la disposition du [préprocesseur][preprocessor].
Elles choisissent entre plusieurs chemins différents, en insérant leur corps à cet endroit, mais seulement lorsque leur condition est vraie.

`%if` ... `%elif` ... `%else` ... `%endif` sélectionnent une branche à partir d'un test numérique :

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef` et `%ifndef` sont similaires, mais testent si un nom a été défini.
Par exemple, on peut les utiliser pour s'assurer que le contenu d'un fichier n'est inclus qu'une seule fois, même quand le fichier est appelé par plusieurs sources :

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

Tu as peut-être remarqué qu'à la fin de chaque fichier `.asm` de ce parcours se trouve ce morceau de code :

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn` compare deux morceaux de texte pour vérifier qu'ils sont identiques.
La macro prédéfinie `__OUTPUT_FORMAT__` est remplacée par le format de sortie courant, de sorte que ce code vérifie si le format de sortie est `elf64`, le format utilisé par les systèmes Linux.
Si c'est le cas, une note est ajoutée au fichier objet pour déclarer les permissions que la pile doit avoir, une mesure de sécurité courante.
Sinon, rien ne change.

## Structures

Pour atteindre un champ d'un enregistrement en mémoire, il faut ajouter le décalage en octets du champ à une adresse de base.
Écrire ces décalages sous forme de nombres bruts est source d'erreurs et masque leur signification.
[`struc`][struc] et `endstruc` nomment plutôt une disposition, en transformant chaque champ en un décalage symbolique calculé au moment de l'assemblage.

À l'intérieur du bloc, les directives de réservation `resb`, `resw`, `resd` et `resq` réservent un ou plusieurs octets, mots, doubles mots ou quadruples mots.
Donner à chaque champ un `.` initial limite la portée de son nom à la structure :

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

Chaque nom de champ représente désormais son décalage : `thread.color` vaut `0`, `thread.tension` vaut `4` et `thread.name` vaut `12`.
NASM définit aussi `<struc>_size` comme le total, où `<struc>` est le nom du `struc`.
Par exemple, ici `thread_size` vaudrait `4 + 8 + 16 = 28`.

On atteint un champ en ajoutant son décalage à un registre de base, et `thread_size` est le pas d'un enregistrement au suivant :

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

Un `struc` ne décrit qu'une forme, il n'alloue pas de mémoire à lui seul.
Pour créer une instance initialisée, tu peux utiliser `istruc ... iend` après une étiquette.
À l'intérieur d'une instance, `at` place une valeur dans un champ nommé :

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

Note que `thread.name` est initialisé avec `"warp", 0`, ce qui n'occupe que 5 octets.
Les 11 autres octets qui lui sont réservés dans le `struc` sont automatiquement remplis de zéros par `iend`, qui complète l'instance jusqu'à `thread_size` avec des `0`.

Un `struc` n'est que du sucre syntaxique pour une mémoire que l'on peut aussi déclarer manuellement.
Par exemple, le code ci-dessus est équivalent au suivant, où `times 11 db 0` garantit que 16 octets sont alloués à la fin :

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## Répartir dans plusieurs fichiers

Les macros sont souvent regroupées dans un fichier à part, puis incluses dans chaque source qui en a besoin avec `%include` :

```x86asm
%include "patterns.mac"
```

Le fichier nommé est inséré tel quel à cet endroit, avant l'assemblage, exactement comme si son contenu avait été saisi sur place.
Cela garde les définitions au même endroit et permet à plusieurs fichiers source de les partager.

Si le fichier de macros peut être assemblé seul, il doit avoir l'extension `.asm`.
Note que les macros n'ont aucune liaison.
Même si le fichier de macros est assemblé, ses macros ne sont visibles que pour un autre fichier qui l'inclut avec `%include`.

Sinon, un fichier destiné uniquement à être inclus peut avoir n'importe quelle extension.
L'usage de `.asm` ou de `.mac` est une convention courante.
