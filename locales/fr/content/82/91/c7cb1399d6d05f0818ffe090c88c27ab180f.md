# À propos

Les [compréhensions][for] offrent un moyen de transformer facilement et de manière déclarative des _Enumerables_. C'est du _sucre syntaxique_ pour parcourir des enumerables en Elixir.

[//]: # (elixir-formatter-disable-next-block)

```elixir
for s <- ["a", "b", "hello", "c"], # 1. generator
  String.length(s) == 1,           # 2. filter
  into: "",                        # 3. collectable
  do: String.upcase(s)

# => "ABC"
```

Une compréhension comporte trois parties :

1. _générateurs_ :
   - des valeurs énumérées à partir de structures qui implémentent le protocole [_Enumerable_][enumerable].
   - des expressions de filtrage par motif pour déstructurer les valeurs énumérées.
2. _Filtres_ : des conditions booléennes qui servent à sélectionner les valeurs énumérées à utiliser pour créer les nouvelles valeurs.
3. _Collectables_ : une structure qui implémente le protocole [_Collectable_][collectable] et sert à collecter les nouvelles valeurs.

Il existe des compréhensions sur une seule ligne et des compréhensions sur plusieurs lignes. Quand on utilise plus d'un générateur, le [produit cartésien][cartesian-product] des valeurs générées est énuméré. Cela signifie que chaque valeur générée par le premier générateur sera associée une fois à chaque valeur générée par le second.

```elixir
for n <- [0, 1, 2, 3], do: n + 1
# => [1, 2, 3, 4]

for x <- [0, 1],
    y <- [0, 1] do
  {x, y}
end

# => [{0, 0}, {0, 1}, {1, 0}, {1, 1}]
```

La valeur du bloc do est insérée dans le _collectable_ **pour chaque valeur générée** à partir de l'_enumerable_.

```elixir
for _ <- [1, 2, 3], do: :a
# => [:a, :a, :a]
```

Le filtrage par motif peut intervenir dans la compréhension, soit à gauche du `<-`, soit sur sa propre ligne.

```elixir
for {atom, str} <- [a: "string"], do: str
# => ["string"]

for pair <- [a: "string"],
    {atom, str} = pair do
  str
end

# => ["string"]
```
