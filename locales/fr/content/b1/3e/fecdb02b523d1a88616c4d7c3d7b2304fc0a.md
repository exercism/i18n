# Introduction

Travailler avec des données binaires est un concept important dans tout langage, et Elixir offre une syntaxe élégante pour écrire des données binaires, faire du pattern matching dessus et en construire.

En Elixir, on désigne les données binaires par le terme de type _bitstring_. Le _type_ de données binaires (à ne pas confondre avec les données binaires en général) est une forme particulière de _bitstring_, dont on parlera dans un exercice ultérieur.

Les littéraux _bitstring_ se définissent à l'aide de la forme spéciale `<<>>`. Un littéral se compose de segments. Chaque segment a une valeur et un type, séparés par l'opérateur `::`. Le type indique combien de bits seront utilisés pour encoder la valeur. On peut omettre complètement le type, auquel cas la valeur par défaut est un entier de 8 bits.

```elixir
# This defines a bitstring with three segments of a single bit each
<<0::1, 1::1, 0::1>>
```

Indiquer le type sous la forme `::1` est un raccourci pour `::size(1)`. Il faut utiliser la syntaxe plus longue si la taille en bits provient d'une variable.

## Binaire

Quand on écrit des littéraux d'entiers binaires, on peut les écrire directement en base 2 en préfixant le littéral par `0b`. À noter qu'ils seront de toute façon affichés sous forme de nombres décimaux dans les résultats des tests ou dans iex.

```elixir
<<0b1011::4>> == <<11::4>>
# => true
```

## Troncature

Si la valeur du segment dépasse la capacité du type de ce segment, elle est tronquée par la gauche.

```elixir
<<0b1011::3>> == <<0b0011::3>>
# => true
```

## Ajout en début et en fin

On peut à la fois ajouter au début et à la fin d'un _bitstring_ existant grâce à la forme spéciale. Le type `::bitstring` doit être utilisé sur le _bitstring_ existant s'il est de taille inconnue.

```elixir
value = <<0b110::3, 0b001::3>>
new_value = <<0b011::3, value::bitstring, 0b000::3>>
# => <<120, 8::size(4)>>
```

## Concaténation

On peut concaténer des _bitstrings_ stockés dans des variables grâce à la forme spéciale. Le type `::bitstring` doit être utilisé lorsqu'on concatène deux _bitstrings_ de tailles inconnues.

```elixir
first = <<0b110::3>>
second = <<0b001::3>>
concatenated = <<first::bitstring, second::bitstring>>
# => <<49::size(6)>>
```

## Pattern matching

On peut aussi faire du pattern matching pour récupérer des valeurs à partir de la forme spéciale. Il faut connaître le nombre de bits de chaque fragment que l'on souhaite capturer, à une exception près : le type `::bitstring` permet de faire du pattern matching sur un _bitstring_ de taille inconnue, mais uniquement pour le dernier fragment.

```elixir
<<value::4, rest::bitstring>> = <<0b01101001::8>>
value == 0b0110
# => true
```

## Inspection des _bitstrings_

~~~~exercism/note
Les _bitstrings_ peuvent être affichés (par l'exécuteur de tests ou dans iex) dans un format différent de celui qui a été utilisé pour les créer. Cela prête souvent à confusion quand on apprend les _bitstrings_.
~~~~

Par défaut, les _bitstrings_ sont affichés par fragments de 8 bits (un octet), même si on les a créés avec des fragments d'une taille différente.

```elixir
<<2011::11>>
# => <<251, 3::size(3)>>
```

Si on crée un _bitstring_ qui représente une chaîne imprimable encodée en UTF-8, il est affiché comme une _string_.

```elixir
<<>>
# => ""

<<65, 66, 67>>
# => "ABC"
```
