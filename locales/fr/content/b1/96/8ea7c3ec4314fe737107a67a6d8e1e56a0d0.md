# Introduction

Cet exercice s'appuie sur ce que tu as vu dans [Observateur d'oiseaux de jardin][backyard-birdwatcher] en introduisant les mots d'ordre supérieur qui prennent une *quotation*, un morceau de code entre crochets `[ ]`, pour piloter l'opération.

## Les *quotations* comme valeurs

Une *quotation* est simplement un morceau de code littéral. Tu peux en passer une comme donnée à un autre mot :

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

Ici, `[ 2 > ]` est une *quotation* qui prend un nombre et laisse un booléen. `count` l'exécute sur chaque élément et compte les résultats vrais.

## Filtre et rejette

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

`without` traite son deuxième argument comme un ensemble : tout élément de `seq` qui est `=` à *n'importe quel* élément de `exclude` est supprimé. `sift` est le cas particulier de `reject` sans *quotation* : il garde tous les éléments sauf `f`, ce qui est pratique pour éliminer les trous laissés par un `map` précédent.

### Conserve le résultat du test

`find` renvoie l'*élément* correspondant. Quand le test *calcule* déjà la valeur que tu veux réellement, `map-find` t'évite une seconde passe : il exécute la *quotation* sur chaque élément et renvoie le premier résultat différent de `f` **et** l'élément qui l'a produit.

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

La *quotation* renvoie `f` pour les éléments qui ne conviennent pas et le résultat à conserver pour celui qui convient. Si aucun ne convient, `map-find` laisse `f f`, exactement comme `find`.

### Filtre des enregistrements par un *slot*

Quand les éléments sont des *tuples*, le prédicat projette en général un *slot* via son accesseur généré automatiquement `slot>>` et teste sur celui-ci :

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## Fais circuler une valeur fixe avec `with`

Parfois, le prédicat a besoin d'une valeur qui reste la même à chaque appel : un seuil, un diviseur, une *string* cible. `with` (dans [`kernel`][kernel]) intègre cette valeur fixe à la *quotation*, transformant une *quotation* à deux arguments `( value elt -- ? )` en la *quotation* à un argument que `filter`, `count`, `map` et `each` attendent :

```
with ( value seq quot -- seq curry )
```

Chaque appel par élément voit `( value elt )` sur la pile, la valeur fixe en premier, l'élément courant en second :

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## Transforme et parcours

`map` (dans [`sequences`][sequences]) applique une *quotation* à chaque élément et renvoie le tableau des résultats. `each` fait le même parcours mais jette les résultats, ce qui est utile quand la *quotation* ne sert qu'à produire des effets de bord. `2map` parcourt *deux* séquences de front et combine les éléments correspondants ; `2each` et `2reduce` en sont les cousins, l'un limité aux effets de bord, l'autre au repliement ; `zip` est le raccourci pour « les apparier sans les combiner » :

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

`2reduce` fait circuler un accumulateur à travers les deux séquences à la fois : sa *quotation* prend `( accumulator elt1 elt2 -- accumulator' )`. Ici, il accumule un produit scalaire : chaque paire est multipliée, et les produits sont additionnés (`1*10 + 2*20 + 3*30`) :

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

`map-as` est le cousin de `map` qui force le type de la séquence de sortie : passe un `{ }` ou un `V{ }` vide comme exemplaire pour remplacer le type par défaut déduit de l'entrée (sinon, transformer une *string* en éléments qui ne sont pas des caractères provoque une erreur quand Factor essaie de reconditionner les résultats dans une *string*).

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

Les deux formes à deux séquences s'arrêtent à la longueur de l'entrée la plus courte. `zip` équivaut à `[ 2array ] 2map` : il conserve les paires au lieu de les fusionner.

## Trie

`sort` renvoie une copie triée dans l'ordre naturel ; `sort-by` (dans [`sorting`][sorting]) trie selon une clé extraite de chaque élément :

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## Agrège

`map-sum` (dans [`sequences`][sequences]) applique une *quotation* sur la séquence et additionne les résultats en une seule passe :

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## Minimum et maximum

`minimum` et `maximum` renvoient directement le plus petit ou le plus grand élément d'une séquence. `minimum-by` et `maximum-by` (tous dans [`sequences`][sequences]) renvoient l'élément dont la clé extraite est la plus petite ou la plus grande :

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## Écris ton propre mot d'ordre supérieur

Quand *ton* mot prend une *quotation* comme argument à l'exécution et la transmet à `map`, `filter`, `each`, etc., déclare ton mot avec `; inline`. Cela demande au compilateur d'incorporer ton mot à chaque site d'appel, là où la *quotation* est un littéral connu ; sans cela, le compilateur n'a aucun moyen de connaître l'effet de pile de la *quotation*.

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

Les mots construits uniquement à partir de *quotations* littérales n'ont pas besoin de `inline` ; seuls ceux qui transmettent une *quotation* entrante en ont besoin.

Si un tel mot déclaré `inline` s'appelle *lui-même*, un combinateur récursif, déclare-le `; inline recursive` à la place. Sans ce mot supplémentaire, le compilateur s'arrête sur *« The inline recursive word ... must be declared recursive »*, ce qui t'indique exactement ce qu'il faut ajouter.

## Récupère le second élément

Pour un tableau à 2 éléments, `second` renvoie son second élément. `first` renvoie le premier. Les deux se trouvent dans [`sequences`][sequences].

## Des nombres vers des *strings*

`number>string ( n -- str )` (dans [`math.parser`][math.parser]) transforme un nombre en sa forme de *string* décimale :

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
