# Complément d'instructions

## Messages d'exception

Parfois, il est nécessaire de [lever une exception][raising-exceptions].
Quand tu fais cela, tu dois toujours inclure un **message d'erreur explicite** qui indique l'origine de l'erreur.
Cela rend ton code plus lisible et facilite grandement le débogage.
Pour les situations où tu sais que l'origine de l'erreur sera d'un type précis, tu peux choisir de lever l'un des [types d'erreurs intégrés][error-base-classes], mais tu dois quand même inclure un message explicite.


Une partie de `Tic Tac Toe` valide se termine quand un joueur gagne.
Si les deux joueurs sont en position gagnante, cet exercice attend que tu utilises l'[instruction `raise`][raise] pour « lever » une `ValueError` dans ta solution.
Ton code doit aussi lever une `ValueError` si un joueur est considéré comme ayant joué deux tours d'affilée, ou comme ayant joué le premier coup alors qu'il devait jouer le second.


Pour lever une `ValueError` avec un message, écris le message comme argument du type `exception` :

```python
# Example when player O goes before player X.
raise ValueError("Wrong turn order: O started")

# Example when player X goes twice.
raise ValueError("Wrong turn order: X went twice")

# Example when player X wins AND player O wins.
raise ValueError("Impossible board: game should have ended after the game was won")
```

Les tests vérifient que le message d'erreur correspond exactement, alors lis attentivement les résultats attendus.
