# À propos

Elm est un langage agréable pour construire des applications web fiables.
Il propose des messages d'erreur conviviaux, d'excellentes performances, des ressources légères et aucune exception à l'exécution.

La partie la plus célèbre et la plus largement copiée d'Elm est sans doute The Elm Architecture, un schéma simple pour structurer les applications web, et c'est ainsi que toutes les applications web en Elm sont écrites.

L'idée centrale est que le code s'articule autour d'un `Model` représentant l'état de l'application, d'une façon de `update` ce modèle et d'une façon de `view` ce modèle.

Le `Model` contient l'état de l'application : toutes les données dont elle a besoin.
Il peut être de n'importe quel type, mais dans toute application utile il s'agit généralement d'un [enregistrement][record].
Si on imagine une application simple avec un champ de texte et un texte affichant l'inverse de ce texte, le modèle ressemblerait à ceci.
Tu peux aussi voir cet exemple dans le [guide Elm][elm-guide-text-fields].

```elm
type alias Model =
  { text : String
  }
```

`update` est une fonction qui est appelée avec un `Msg` quand quelque chose change (par exemple quand l'utilisateur clique sur un bouton).
Elle prend le `Msg` et le `Model` courant, et renvoie un nouveau `Model`.
Le `Msg` peut être de n'importe quel type, mais il s'agit généralement d'un [type personnalisé][custom-type].

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

Comme pour tous les types personnalisés, les variantes du `Msg` peuvent contenir autant d'informations arbitraires que nécessaire.
Dans l'exemple ci-dessus, la variante `TextChanged` contient une `String`.

`view` est une fonction qui renvoie du HTML à afficher à l'utilisateur dans le navigateur.
Elle prend le `Model` courant et renvoie un `Html Msg` (le type qu'Elm utilise pour représenter le HTML).
Chaque élément HTML (par exemple `<div>`) a une fonction Elm correspondante (`Html.div`), dans le paquet `Html`.
Chacune de ces fonctions prend deux paramètres : le premier est une liste d'attributs (issus des paquets `Html.Attributes` et `Html.Events`), et le second est une liste d'éléments enfants (des fonctions du paquet `Html`).
Il existe aussi une fonction `text` qui représente un contenu HTML de type _string_ et qui prend simplement un paramètre _string_, mais qui s'utilise sinon de la même manière que toutes les autres fonctions et tous les autres éléments du paquet `Html`.

La fonction `view` peut indiquer que certains événements, comme un clic sur un bouton ou la modification d'un texte dans un champ de texte, entraînent la création d'un `Msg`, que le runtime d'Elm utilisera pour appeler la fonction `update`, modifier le `Model` et générer le HTML mis à jour.
Dans le code ci-dessous, cela se produit avec `Html.Events.onInput TextChanged`.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

`Html.Events.onInput` s'attend à recevoir une fonction (`String -> Msg`) qu'il utilisera pour créer le `Msg`.
Chaque événement attend une fonction différente selon les informations qu'il peut fournir ; par exemple `Html.Events.onCheck` (pour les cases à cocher) attend `Bool -> Msg` et `Html.Events.onClick` attend simplement un `Msg`.

Le langage Elm est pur et fonctionnel et aucune mutation n'est possible, c'est donc le runtime d'Elm qui gère tout ce qui change.
Tu peux consulter tous les différents [éléments HTML][html-elements], [attributs d'éléments][element-attributes] et [événements HTML][html-events] dans le registre des paquets Elm.

Il existe 4 « niveaux » d'applications web que l'on peut écrire en Elm, de plus en plus puissants et de plus en plus complexes (même si Elm reste un langage et un écosystème d'une simplicité réjouissante).
Tous sont définis dans le [paquet Browser][browser-package] :

- [sandbox][browser-sandbox] : réagir aux entrées de l'utilisateur, comme les boutons et les cases à cocher
- [element][browser-element] : communiquer avec le monde extérieur, via HTTP et l'interopérabilité JavaScript
- [document][browser-document] : contrôler le `<title>` et le `<body>` d'une page web
- [application][browser-application] : créer de véritables applications monopages qui gèrent le routage et les changements d'URL

Ce concept utilise le [sandbox][browser-sandbox], car c'est le plus simple (et, parce qu'il s'agit d'un sandbox, il est relativement facile de travailler avec l'éditeur en ligne d'Exercism).
Le module d'entrée d'un programme Elm doit s'appeler `Main`, et la fonction qui crée l'application doit s'appeler `main`, comme ci-dessous.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

On a déjà vu les fonctions `update` et `view`, et le [sandbox][browser-sandbox] exige en plus une fonction `init`, qui renvoie l'état initial du `Model`.
