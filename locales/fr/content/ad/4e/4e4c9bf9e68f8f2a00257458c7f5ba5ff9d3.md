# Introduction

## Énumérations

Jusqu'ici, on a surtout manipulé des nombres et des _strings_.
Pour modéliser le monde réel, on peut vouloir qu'une variable ne puisse prendre qu'un nombre limité de valeurs.
On peut vouloir un type dédié avec quelques valeurs distinctes aux noms distincts.
Par exemple, dans une usine de skateboards, le matériau du plateau se limiterait à un choix entre érable, bambou ou plastique.

On pourrait encoder ces valeurs avec des entiers, mais il faudrait du code supplémentaire pour vérifier qu'aucune valeur invalide ne vienne du système pour le matériau.
Le sens de ces [nombres magiques][magic numbers] est difficile à suivre dans le code source, et ils sont faciles à confondre.
On peut utiliser les `enumerations` pour encourager un code expressif et limiter les erreurs de comparaison involontaires.

## Exemple d'utilisation

Le terme précis pour ce type d'énumération est `scoped enumeration`.
L'extrait ci-dessous montre comment écrire une `enumeration` `DeckMaterial`.
Remarque le mot-clé `enum class` et le `;` à la fin de la définition :

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
Maintenant, regarde une fonction de tarification dans le magasin de skate et prête attention à l'opérateur de résolution de portée (`::`), qui précise un `enumerator` de l'`enumeration` :

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## Portée

Imagine une deuxième `enumeration` pour le matériau des roues :

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
Bien que les roues et le plateau puissent tous les deux être en _plastic_, on ne peut pas les confondre.
Ce sont des _types_ différents : `DeckMaterial` plastic et `WheelMaterial` plastic.
Chaque `enumeration` a ses `enumerators` dans sa propre portée, son propre `namespace`.
C'est pour cela qu'on les appelle des `scoped enumerations`.

## Énumérations non délimitées
Tu penses peut-être qu'avec le nom `scoped`, il existe aussi des énumérations `unscoped`, et tu as raison.
Les `Unscoped enumerations` sont de moins en moins populaires, parce qu'elles partagent toutes le même `namespace` global.
À cause de ce partage, on ne peut pas avoir deux `unscoped enumerations` avec les mêmes `enumerators`, comme _plastic_ dans l'exemple ci-dessus.

De plus, les `unscoped enumerations` se convertissent implicitement en entiers.
Regarde l'exemple ci-dessous pour voir un résultat surprenant :

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

Si tu veux convertir des `scoped enumerations` en entiers, tu peux utiliser `static_cast<int>`.
