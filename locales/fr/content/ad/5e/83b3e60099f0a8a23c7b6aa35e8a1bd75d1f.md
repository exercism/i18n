# Introduction

## Types personnalisés

En Gleam, les types personnalisés permettent de définir de nouveaux types de données. Ils peuvent avoir plusieurs _variantes_, chacune avec son propre nom.

```gleam
pub type Season {
  Spring
  Summer
  Autumn
  Winter
}
```

Chaque cas d'un type personnalisé peut, éventuellement, contenir des données, et différents cas peuvent contenir des types de données différents. Quand une variante contient des données, on parle d'un _enregistrement_.

```gleam
pub type Number {
  SomeInt(Int)
  SomeFloat(Float)
  Invalid
}
```

Pour créer une valeur pour un cas précis, on peut faire référence à son nom s'il ne contient aucune donnée supplémentaire (`Spring`), ou l'appeler comme une fonction s'il en contient (`SomeInt(2)`).

```gleam
let spring = Spring
let integerTwo = SomeInt(2)
```

Les types personnalisés, comme tout ce qui existe en Gleam, possèdent une _égalité structurelle_, ce qui signifie que deux valeurs de la même variante et portant les mêmes données sont équivalentes.

```gleam
Spring == Spring // -> True
Spring == Autumn // -> False
SomeInt(2) == SomeInt(2) // -> True
SomeInt(2) == SomeFloat(2.0) // -> False
```

On peut filtrer par motif les variantes d'un type personnalisé à l'aide d'expressions `case`.

```gleam
import gleam/int
import gleam/float

pub fn describe(flexible_number: Number) -> String {
  case flexible_number {
    SomeFloat(f) -> "Float: " <> float.to_string(f)
    SomeInt(i) -> "Int: " <> int.to_string(i)
    Invalid -> "Neither a float nor an int"
  }
}
```
