# Introduction

Le système d'erreurs de Factor se compose de trois éléments : `throw` pour signaler une erreur, `recover` pour en gérer une, et `ERROR:` pour définir ton propre type d'erreur.

## `throw`

`throw` (dans [`kernel`][kernel]) lève une erreur. L'argument peut être *n'importe quelle* valeur, une _string_, un nombre ou un _tuple_, et c'est cette valeur qui devient l'erreur que tu pourras examiner ensuite :

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw` ne rend pas la main ; le reste du mot en cours est ignoré.

## `recover`

`recover` (dans [`continuations`][continuations]) est le _try/catch_ de Factor. Il prend une _quotation_ *try* et une _quotation_ *recovery* :

```
recover ( try recovery -- )
```

Si `try` se termine sans lever d'erreur, `recovery` est ignoré. Si `try` lève une erreur, celle-ci est empilée et `recovery` est exécuté :

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

`when`, dans [`kernel`][kernel], est le compagnon naturel : il n'exécute une _quotation_ que lorsque le sommet de la pile est vrai :

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:` définit une classe de _tuple_ *et* un mot qui construit une nouvelle instance et la lève :

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

Une erreur sans _slot_ s'écrit simplement `ERROR: name ;`. Appeler `name` lève une instance vide. Les _tuples_ définis avec `ERROR:` portent un prédicat de classe, `name?`, que tu peux utiliser pour tester si une erreur interceptée était de ce type.

## Relis les _slots_

Une erreur interceptée n'est qu'un _tuple_ : chaque _slot_ défini avec `ERROR:` dispose donc du même lecteur `slot>>` généré automatiquement que n'importe quel autre _tuple_.

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
