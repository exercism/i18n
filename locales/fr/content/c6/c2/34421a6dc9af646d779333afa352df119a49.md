# Types de _strings_

Cairo ne dispose pas d'un type de données natif pour les _strings_.
Il existe cependant deux façons de représenter une _string_ : les _strings_ courtes avec un seul `felt252`, et les _strings_ de longueur arbitraire avec `ByteArray`.

## Les _strings_ courtes

Une _string_ courte se forme avec des guillemets simples, où chaque caractère qui la compose est encodé sur un octet selon la [norme ASCII][ascii-table].

En tant que _string_ ASCII, par exemple, `'abc'` correspond à :

- `'a'` correspond à `0x61`
- `'b'` correspond à `0x62`
- `'c'` correspond à `0x63`
- `'abc'` correspond à `0x616263`

C'est le type de données `felt252` qui stocke les _strings_ courtes en Cairo.
Comme `felt252` contient 251 bits, une _string_ courte est limitée à 31 caractères (31 \* 8 = 248 bits, soit le plus grand multiple de 8 qui tient dans 251 bits).

Exemples de déclarations de _strings_ courtes :

```rust
    let my_first_char = 'D';
    let my_first_char_in_hex = 0x44;

    let my_first_string = 'Hello world';
    let my_first_string_in_hex = 0x48656C6C6F20776F726C64;
```

### ByteArray

La structure ByteArray a été introduite dans Cairo 2.4.0.
Les _strings_ ByteArray s'écrivent entre guillemets doubles, comme ceci :

```rust
    let long_string: ByteArray = "this is a string which has more than 31 characters";
```

Techniquement, cette mise à jour a aussi introduit le type `bytes31`, qui contient 31 octets et qui tient dans un felt.
La structure `ByteArray` représente essentiellement une _string_ longue à l'aide d'un tableau de `bytes31` qui contient les « mots complets » (c'est-à-dire les mots qui remplissent tout le felt) et d'un unique champ felt qui contient un « mot incomplet » (le nombre d'octets qu'il contient est précisé dans un champ de longueur séparé).

```rust
#[derive(Drop, Clone, PartialEq, Serde, Default)]
struct ByteArray {
    data: Array<bytes31>,
    pending_word: felt252,
    pending_word_len: usize,
}
```
