# 简介

解析是将文本转换为有意义数据的过程。`String`包中的函数在这方面有局限，而且正则表达式也很难用，所以在 Elm 中解析的惯用方式是使用 `elm/parser` 包。

我们来看一个为编程语言 [LOLCODE][lolcode]（的一个子集）编写解析器的例子。来看看下面这个带注释的程序：

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

首先，我们编写一个 Elm 类型来表示可能的命令：

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

我们的 LOLCODE 程序随后可以建模为`List Command`。我们从`HAI 1`这一行的解析器开始：

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP`是用一个_解析器管道_构建的。`(|.)`运算符的意思是“解析字符串但丢弃结果”，`(|=)`的意思是“解析字符串并保留结果”。在这个例子中，`Parser.keyword "HAI"`会消耗一个“HAI”，但那个结果会被忽略。`Parser.spaces`会消耗任意数量的 ' '、'\n' 和 '\r' 字符，但这些也会被忽略。`Parser.int`会解析一个整数，这个整数的值（比如 1）会被传给最上层的`Parser.succeed Version`，解析器会成功返回`Version 1`。

如果管道中任何一个解析器失败，它会返回`Parser.DeadEnd`，整个解析器也会失败。解析器可以用`Parser.run`运行：

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

我们来处理“CAN HAS STDIO?”这一行：

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP`也是一个解析器管道，但这次以`Parser.symbol`结尾，它适合解析像“?”这样的符号。我们想要保留的值（要导入的包名）由下面的代码解析：

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

因为我们不知道包名会是什么，所以不能使用`Parser.keyword`，而是使用`Parser.chompWhile`，它会逐个消耗字符，只要这些字符满足条件（这里是指字母数字字符）。这些被消耗的字符随后由`Parser.getChompedString`收集，它返回一个`Parser String`。在这种情况下，我们想规范化包名，所以使用`Parser.map`修改解析器中包含的字符串，并把它变成小写。

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

接下来，`VISIBLE "HAI WORLD!"`由下面的代码解析：

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

现在我们有了每个命令的解析器。当然，在一般程序中，这些命令的顺序无法预测，所以我们构建一个通用的命令解析器：

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf`会按给定顺序尝试一个解析器。如果一个解析器失败，就尝试下一个；如果成功，就返回它的结果，不再尝试剩下的解析器。如果所有解析器都失败，`Parser.oneOf`也会失败。

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

注意每次失败的尝试都会产生一个`Parser.DeadEnd`，由`Parser.oneOf`收集。

要解析完整程序，我们需要用下面的代码依次解析多个命令：

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence`是一个非常可定制的解析器，有很多选项。`start`、`separator`和`end`接收分隔序列各项的字符串。如果要解析 Elm 列表，我们会用“[”、“,”和“]”。`spaces`通过接收一个解析器来提供灵活性，这个解析器会处理各项和分隔符之间可能出现的空格。如果要解析 Elm 列表，我们会用`Parser.spaces`，但在这个例子中我们不接受任何空格，所以我们使用`Parser.succeed ()`，它会立即成功，实际不消耗任何内容。`item`接收项解析器，最后，`trailing`让我们决定尾随分隔符是`Parser.Forbidden`、`Parser.Mandatory`还是`Parser.Optional`。

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

当解析器成功时，它们会停止消耗字符串：

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

所以如果我们需要确保字符串中的所有内容都被解析，可以使用`Parser.end`：

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

最后，有时我们需要根据解析出的内容决定让解析器失败。例如，如果我们需要一个解析器，让以连续两个“HAI”命令开头的程序失败，可以使用：

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen`可以检查解析器的内容，并根据其值返回新的解析器。这里，我们在一种情况下用`Parser.problem`以自定义消息让解析器失败，在另一种情况下返回原值。

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
