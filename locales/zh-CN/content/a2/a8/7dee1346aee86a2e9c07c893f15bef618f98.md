# 关于

## const

[`const`][constants]修饰符可以（而且通常也应该）用在任何这样的字段上：它的值在编译时已知，并且在程序的生命周期内不会改变。

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

编译器会告诉你哪些表达式可以在编译时求值。简单的算术运算可以，字符串拼接也可以。这排除了任何需要用到堆或栈的求值，因此所有方法调用以及对非基元类型的引用都用不了。

网上有一些讨论，聊的是`const`相比变量在性能上的优势。如果比的是实例的非`const`字段，内存上也许能省下可观的一块，但和静态变量相比，这点节省就微不足道了。任何对 CPU 性能的考量，在同事眼里很可能都属于[过早优化][premature-optimization]。

使用`const`更有说服力的理由，是它能帮助维护者更好地理解代码。一眼看到某个字段被标成`const`或`readonly`，或者某个属性没有 setter，维护者就能在分析时基本把它放一边。它不太可能是 bug 的源头，也不太会在重构时带来麻烦。[Stack Overflow 上的这条评论][so-consts]谈到了这一点。

`const`修饰符也可以用在方法内部的值上：

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

用这种方式把某个值标成`const`，如果它在方法里会被用到多次，或者你想提示它的含义，那就很有用。相比直接把字面量内联写在用到的地方，它并不会带来任何性能上的好处。

## readonly

[`readonly`][readonly-fields]修饰符可以（而且通常也应该）用在任何无法设为`const`的字段上：它的值在程序的生命周期内不会改变，并且要么由内联初始化器设置，要么在实例化时设置（由构造函数，或由构造函数调用的方法）。

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

鼓励使用`readonly`修饰符，理由和`const`一样。用这种方式约束字段，有助于维护者理解代码。

注意，给字段加上`readonly`修饰符，只能阻止字段的值被改变。对于聚合类型，它并不能保护该类型的字段或属性。尤其不能保护数组的内容。

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

要确保引用类型的所有成员都受到保护，可以把字段设为`readonly`，并定义不带`set`访问器的自动属性。

你应该看看基类库里的[只读集合][readonly-collections]。

对于数组，最接近只读版本的做法是使用[`Array.AsReadOnly<T>()`][as-read-only]方法。
