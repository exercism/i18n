# 简介

如果一个函数_最后_执行的操作是调用它自己，那么这个函数就是[尾递归][recursion-tc]的。

每次调用函数时，一个包含局部变量和实参的_栈帧_都会被放到[函数调用栈][call-stack]的顶部。函数返回时，这个栈帧会从栈中移除。

尾递归函数支持[尾调用优化][tail-call-optimization]（也称尾调用消除）。这种优化让下一个函数调用可以复用上一个栈帧，前提是能确定上一个函数不再需要它。这样可以缓解函数调用栈溢出的问题：当函数调用栈上的栈帧太多，以至于没有内存再创建新的栈帧时，就会发生这种溢出。

## Elm 中的尾调用优化

在某些条件下，Elm 编译器在编译为 JavaScript 时能够自动执行尾调用优化。

当某个分支中_最后_执行的操作是以简单的函数应用形式调用函数自身时，递归函数就能得到这种优化。来看几个例子：

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

上面的实现不是尾递归的，因为 `else`分支中最后的操作是乘法`n *`。

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

上面的实现是尾递归的，会被优化，因为 `else`分支中最后的操作是`factorialHelper`调用自身。对于类型签名为`Int -> Int`的函数来说这是做不到的，因此实践中尾调用优化往往通过定义辅助函数来实现。
