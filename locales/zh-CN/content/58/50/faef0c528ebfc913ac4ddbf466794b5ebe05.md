# 简介

Go 中的切片类似于其他语言中的数组。
它们保存着若干属于某一特定类型（或接口）的元素。

Go 中的切片基于数组。
数组的大小是固定的。
而切片则是数组元素的一个大小动态、灵活的视图。

切片的写法是`[]T`，其中`T`是切片中元素的类型：

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

你可以用方括号语法读取或修改指定下标处的元素，下标从 0 开始：

```go
withData[1] = 5
x := withData[1] // x is now 5
```

你可以从已有的切片中取出一段元素，创建一个新切片。
这里同样使用方括号语法，但要同时指定起始下标（包含）和结束下标（不包含）。
如果不指定起始下标，默认为 0。
如果不指定结束下标，默认为切片的长度。

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

你可以使用`append`函数向切片中添加元素。
下面我们把`4`和`2`追加到切片`a`中。

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append`总是返回一个新切片。如果我们只是想向已有切片追加元素，常见的做法是把返回值重新赋值给作为第一个实参传进去的那个切片变量，就像上面那样。

`append`也可以用来合并两个切片：

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## 切片中的下标

使用切片的下标时，始终应该以某种方式加以保护，通过检查确保该下标确实存在。
否则整个程序都会崩溃。

## 空切片

`nil`切片是默认的空切片。
与不含任何值的切片相比，它们没有任何缺点。
`len`函数可以作用于`nil`切片，无需初始化就能往里添加元素，诸如此类。
如果要创建新切片，优先使用`var s []int`（`nil`切片），而不是`s := []int{}`（空的、非`nil`切片）。

## 性能

如果切片的最终大小已知，那么在创建需要逐步填充的切片时，有一个很容易到手的性能优化点。
关键在于尽量减少内存分配的次数。分配内存开销相当大，一旦切片增长超出已分配的内存空间，就会发生分配。
最稳妥的做法是用`s := make([]int, 0, cap)`为切片指定容量`cap`，然后照常向切片追加元素。
这样，虽然切片长度为零，但能容纳`cap`个元素的空间会立即分配好。
实践中，`cap`常常是另一个切片的长度：`s := make([]int, 0, len(otherSlice))`。

## `append`不是纯函数

Go 的`append`函数针对性能做了优化，因此不会复制输入的切片。
这意味着原始切片（`append`的第一个形参）有时会被修改。
