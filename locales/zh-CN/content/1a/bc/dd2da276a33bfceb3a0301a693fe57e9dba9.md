# 关于

[`switch`语句][switch_statement]会先对一个表达式求值，然后运行第一个与该值匹配的`case`。相比冗长的`if ... else if`链，它往往是更简洁的选择。

## 基本用法

```go
operatingSystem := "windows"

switch operatingSystem {
case "windows":
    // do something if the operating system is windows
case "linux":
    // do something if the operating system is linux
case "macos":
    // do something if the operating system is macos
default:
    // do something if the operating system is none of the above
}
```

可以用逗号把多个值合并到同一个`case`里。只要表达式的值等于其中任意一个，这个`case`就匹配：

```go
switch operatingSystem {
case "windows", "linux":
    // do something if the operating system is windows or linux
case "macos":
    // do something if the operating system is macos
default:
    // do something if the operating system is none of the above
}
```

## 不带表达式的 switch

`switch`后面的表达式也可以完全省略。此时每个`case`里都是一个布尔表达式，第一个求值为`true`的`case`会被执行。

```go
age := 21

switch {
case age > 20 && age < 30:
    // do something if age is between 20 and 30
case age == 10:
    // do something if age is equal to 10
default:
    // do something else for every other case
}
```

## 初始化语句

和`if`一样，`switch`也可以在表达式前面加上一条简短的初始化语句。在那里声明的变量，作用域只限于这个`switch`代码块：

```go
switch v := getValue(); {
case v < 0:
    // do something if v is less than 0
case v == 0:
    // do something if v is 0
default:
    // do something else for every other case
}
// v will not be accessible here
```

## fallthrough

`fallthrough`会让下一个`case`的主体执行，不管它的表达式是否匹配。它必须是该`case`主体里的最后一条语句，而且后面必须还有一个`case`可以执行。

在地道的 Go 代码里，`fallthrough`并不常见，因为它会让相邻的`case`互相依赖。这样一来，也就更难单独理解每个`case`，整个 switch 也更难读。如果几个`case`应该有相同的行为，用逗号把它们分组会更清楚。如果各个`case`因为其他原因共享逻辑，可以考虑把共享的逻辑提取成一个辅助函数。

```go
s := "hello"

switch s {
case "hello":
    fmt.Println("hello")
    fallthrough
case "world":
    fmt.Println("world") // also runs, even though s != "world"
}
// Output:
// hello
// world
```
