# 测试

  ## 快速概览

  1. 在`<myFileName>.u`文件中进行修改
  2. 保存`<myFileName>.u`文件
  3. 如果文件通过类型检查，运行 UCM 的`add`或`update`命令
    * 如果文件没有通过类型检查，就修改`<myFileName>.u`文件中的代码，直到它能编译。修改之后记得`update`你的函数！
  4. 在 UCM CLI 中运行`load <myFileName>.test.u`命令，把测试引入作用域并运行它们

  ## 逐步讲解

  如果你在命令行上做 Exercism 的题目，那么你多半会在以该练习命名的目录里实现解答。例如，如果练习是`hello-world`，你应该先`cd`到`~/exercism/unison/hello-world`，再从命令行打开`ucm`。在`hello.u`文件中修改你的实现，满意之后，在 Unison 代码库管理器 CLI（UCM）中输入`add`或`update`命令，把文件里的工作添加到代码库中。

  每个练习的测试文件都以`.test.u`为后缀。你需要用 UCM 中的`load`命令把测试引入作用域并运行它们。`load`命令接受一个文件路径作为参数。对 hello world 练习来说，大致是这样的：

  ```
  .> load hello.test.u
  ```

  你会看到 UCM 发来的一条消息，说明哪些项被引入了作用域，更重要的是，还有运行测试的结果：

  ```

    ⍟ These new definitions are ok to `add`:

      hello.test : Test.Test
      tests      : [Result]

  Now evaluating any watch expressions (lines starting with
  `>`)... Ctrl+C cancels.


    6 | test> tests = runAll [hello.test]

    🚫 FAILED
  ```

  假设你的测试第一次没有通过。回到`myExercise.u`文件继续编辑，保存之后就可以`update`了。

  ```
  I found and typechecked these definitions in ~/Exercism/unison/hello-world/hello.u. If you do an
  `add` or `update`, here's how your codebase would change:

    ⍟ These names already exist. You can `update` them to your new definition:

      hello : Text

  .> update

  ⍟ I've updated these names to your new definition:

    hello : Text
  ```

  接下来我们可以重新加载测试，看看有没有变化！

  ```
  .> load hello.test.u
    Now evaluating any watch expressions (lines starting with `>`)... Ctrl+C cancels.


    6 | test> tests = runAll [hello.test]

    ✅ Passed : Passed 1 tests.
  ```
