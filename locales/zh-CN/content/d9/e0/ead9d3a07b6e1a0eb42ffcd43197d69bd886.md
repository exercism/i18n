# 关于

你不太可能遇到很多不使用命名空间的生产代码。

语法示例如下：

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

命名空间是一种将相关代码分组并避免名称冲突的方式。

根据[官方文档][namespaces]，命名空间有两个主要作用：

- 首先，.NET 使用命名空间来组织其众多的类
- 其次，声明自己的命名空间有助于在大型编程项目中控制类名和方法名的作用域。

基类库（BCL）广泛使用命名空间来组织其功能。

## 引用命名空间中的类型

在命名空间外部引用其中包含的类型时，需要在类型名前加上点语法作为前缀。另一种更常见的做法是，在文件顶部（或命名空间内）放置`using`指令，这样导入的命名空间中的任何类型都可以不加前缀直接使用。在同一命名空间内，则不需要限定类型名。

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

这篇[文章][using]清楚地解释了`using`指令的几种用法：

- `using`：避免用命名空间限定类型
- `using static`：避免用类型限定成员（一个很好的例子是`Math.Max()`）。
- `using MyAlias = YourNamespace;`：用更易读的名称替代命名空间名称。

## 命名空间冲突

.NET 解决了不同程序集中两个同名命名空间的问题：这会导致完全限定标识符名称冲突（例如，某个程序集加载了多个版本的情况）。这个问题通过[命名空间别名限定符][namespace-alias-qualifier]和 [extern alias][extern-alias] 来解决。

提及这个相当小众的话题，一个原因是它会用到 [`::`运算符][dot-dot-operator]。你经常会看到限定符`global::`作为命名空间的前缀，尤其是在生成的代码中。这样做的目的是避免与某个嵌套命名空间或类名发生潜在冲突。通过在命名空间前加上`global::`，你可以确保选中的是顶级命名空间。

## 给 Java 开发者的说明

与 Java `packages`的`import`相比时，需要注意一些异同：

- C# 没有导入特定类型的等价功能。
- `using static`和`import static`是等价的。
- 在 Java 中，包名会影响不同 jar 之间的可访问性。而在 C# 中，程序集才是关键，属于同一命名空间并不影响访问级别。
- 在 Java 中，文件系统路径与完全限定类名之间的关系，在 C# 命名空间中并没有对应体现；不过，尽可能让文件与其包含的主要类同名仍是一种好做法。
