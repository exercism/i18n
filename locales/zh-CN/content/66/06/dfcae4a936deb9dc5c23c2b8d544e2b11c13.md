# 元组

[元组][tuple] 是一个由元素组成的有限有序列表，并且不可变。
元组要求每个位置都有固定的类型。
这也就意味着，编译器知道每个位置上是什么类型。
元组中每个位置使用的类型可以不同，但这些类型必须在编译时已知。

## 创建元组

根据元组中值的类型能否在编译时确定，可以用不同的方式创建元组。
如果这些值在编译时已知，就可以用元组字面量语法创建元组；否则需要显式声明类型。
同样重要的是，值的类型要与元组中指定的类型一致，值的数量也要与指定的类型数量一致。
下面是通过元组字面量语法定义的例子：

```crystal
tuple = {1, "foo", 'c'} # Tuple(Int32, String, Char)
```

也可以用 `Tuple` 类来创建元组。

```crystal
tuple = Tuple(Int32, String, Char).new(1, "foo", 'c')
```

或者，你也可以显式指定被赋值为元组的变量类型。

```crystal
tuple : Tuple(Int32, String, Char) = {1, "foo", 'c'}
```

显式指定元组的类型会很有用，因为这样可以定义某个位置应持有联合类型。
这意味着一个位置可以持有多种类型。

```crystal
tuple : Tuple(Int32 | String, String, Char) = {1, "foo", 'c'}
```

## 转换

### 从数组创建元组

你可以使用 `Tuple` 类的 `from` 方法从数组创建元组。
这要求指定元组的类型。

```crystal
array = [1, "foo", 'c']
tuple = Tuple(Int32, String, Char).from(array)
```

### 转换为数组

你可以使用 `to_a` 方法把元组转换为数组。
生成的数组，其元素类型是元组中各个字段类型的联合。

```crystal
tuple = {1, "foo", 'c'}
array = tuple.to_a
array # => [1, "foo", 'c']
```

### 元组定义的简写

定义显式元组类型有一种简写方式。
就是把类型写在元组字面量里面。

```crystal
tuple : {Int32, String, Char} = {1, "foo", 'c'}
```

## 访问元素

和数组一样，元组的下标从 0 开始，也就是说第一个元素的下标是 0。
不过，和数组不同的是，每个元素的类型都是固定的，并且在编译时就已知，因此给元组取下标时，元素类型取决于所在的位置。
要访问元组中的元素，可以使用 `[]` 运算符。

```crystal
array = [1, "foo", 'c']
array[0]         # => 1
typeof(array[0]) # => Int32 | String | Char

tuple = {1, "foo", 'c'}
tuple[0]         # => 1
typeof(tuple[0]) # => Int32
```

访问元素时，与数组的另一点不同在于：如果下标是直接指定的，编译器会检查它是否在元组的边界之内。
也就是说，你会得到编译时错误，而不是运行时错误。

```crystal
tuple = {1, "foo", 'c'}
tuple[3]
# => Error: index out of bounds for Tuple(Int32, String, Char) (3 not in -3..2)
```

但如果下标存放在变量里，编译器就无法在编译时检查它是否在元组边界内，这时会给出运行时错误。

## 子元组

使用带范围的 `[]` 运算符，可以取得元组的子元组。
返回的是一个新元组，包含指定范围内的元素。
范围必须在编译时给出，否则编译器无法知道子元组中元素的类型。
这意味着范围必须是范围字面量，不能赋值给变量。

```crystal
tuple = {1, "foo", 'c'}
subtuple = tuple[0..1] # Tuple(Int32, String)

i = 0..1
tuple[i]
# Error: Tuple#[](Range) can only be called with range literals known at compile-time
```

## 何时使用元组

当你想把固定数量的值组合在一起，并且这些值的类型在编译时已知时，元组很有用。
这是因为元组不可变，所以比数组占用更少的内存，速度也更快。
另一个用例是从方法中返回多个值。
如果这些值的类型不同，这一点尤其有用，因为元组中每个位置都可以有不同的类型。

如果需要的数据结构能够增大或缩小，或者经常需要修改，就不应该使用元组。
