# 关于

## 简介

不透明类型是 Elm 中的一种封装技术。
也有人把它叫做信息隐藏，或者隐藏实现细节。
它还常被用来强制执行验证，采用的是[解析，不要验证][parse-dont-validate]模式。
例如，你可以有一个`EmailAddress`不透明类型，它只能包含合法的电子邮件地址（与之相对，`String`可以包含任何内容）。

## 创建不透明类型

[自定义类型][custom-types]有一个或多个*变体*，编译器会自动为每个*变体*生成一个创建函数，用的就是*变体*的名字。
这是创建自定义类型的唯一方式。
编译器也允许对这些变体进行解构。

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

默认情况下，这些内容都是文件或模块内部的，我们通过`exposing`关键字来选择要导出什么。
要创建不透明类型，你只需要选择不导出这些*变体*。

这样做之后，你几乎总是需要另外提供一种创建和获取*变体*的方式，也就是导出自定义函数。
这些自定义函数让你在创建和获取*变体*时可以应用一些逻辑。
这样就隐藏了模块内部的实现细节，意味着只要导出的函数保持不变，你可以随意修改实现细节。

## 解析，不要验证

不透明类型最常见的用途，大概就是强制执行验证，采用的是[解析，不要验证][parse-dont-validate]模式。
在这种模式下，你导出一个函数，它接收一个结构化程度或类型安全性比你期望更低的输入，比如`String`，然后把它解析成结构化程度更高的类型，比如`EmailAddress`，最后要么返回该类型，要么返回一个错误（通常是`Maybe`或`Result`）。

例如，在下面的代码中，外部模块只能通过`parseEmailAddress`函数来创建`EmailAddress`类型，所以当你处理`EmailAddress`类型时，就能确定它是合法的。

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
