# 简介

每次调用函数时，都会在内存中创建一个新的栈帧，用来存储这个函数的实参和局部变量；函数返回时，这个栈帧就会被释放。由于 Gleam 使用递归函数调用而不是循环语法，这些栈帧可能会占用大量内存。

为了避免这个问题，Gleam 支持尾调用优化：如果函数做的最后一件事是发起一次函数调用，编译器就可以复用当前函数的栈帧。这意味着函数可以无限次调用自身，而不会占用任何额外的内存。

未优化的递归函数常常可以通过使用_累加器_改写成尾调用优化的函数。

累加器是一个随着数据一起传递的变量。它用来传递函数执行的当前状态，直到抵达基本情况。

累加器应该由函数的作者初始化，而不是由函数的用户初始化。为此，需要声明两个函数：一个公开函数，只接收必要的数据作为实参，并初始化累加器；另一个私有函数，除了数据还接收累加器。

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
