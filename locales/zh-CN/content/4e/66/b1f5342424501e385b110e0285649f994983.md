# 说明

你在维护一套信号站的代码生成工具。
每个宏都是一块*模板*，也就是编译器在每个调用点用来生成特化代码的小模板。

你只需要写这四个宏。测试文件定义了几个小的包装词，这些包装词会*调用*你的宏（宏只能通过它生成的代码来观察），然后检查它们运行时的结果。包装词保持原样即可。

在每个任务里，宏体都会在栈上收到调用点传入的字面量输入，最后必须留下**一个引用**。注释里标着“编译为”的那几行，展示的就是你的引用应当生成的直线代码。

## 1. 运行两次

`twice`接收一个字面量引用，返回一个把原引用连续运行两次的引用。

```factor
! : inc-twice ( x -- y ) [ 1 + ] twice ;
! body receives [ 1 + ]  ->  must build [ 1 + 1 + ]
5 inc-twice .   ! => 7
```

## 2. 重复 N 次

`repeat-quot`接收一个字面量引用和一个字面量计数`n`，返回一个把原引用连续运行`n`次的引用。`n = 0`时返回空引用`[ ]`。

```factor
! : inc-thrice ( x -- y ) [ 1 + ] 3 repeat-quot ;
! body receives [ 1 + ] 3  ->  must build [ 1 + 1 + 1 + ]
5 inc-thrice .   ! => 8
```

## 3. 组合多个

`compose-many`接收一个由引用组成的字面量数组，返回一个单独的引用，依次运行其中的每一个引用。传入空数组时返回空引用。

```factor
! : pipeline ( x -- y ) { [ 1 + ] [ 2 * ] [ 1 - ] } compose-many ;
! body receives { [ 1 + ] [ 2 * ] [ 1 - ] }  ->  must build [ 1 + 2 * 1 - ]
5 pipeline .   ! => 11
```

## 4. 展开迭代

`each-literal`接收一个字面量序列和一个引用。它返回的引用会对序列中的每个元素做两件事：先把该元素压入栈，再运行那个引用。这样迭代就发生在编译期，生成的代码也是直线代码。

```factor
! : sum-three ( -- n ) 0 { 10 20 30 } [ + ] each-literal ;
! body receives { 10 20 30 } [ + ]  ->  must build [ 10 + 20 + 30 + ]
sum-three .   ! => 60
```

这是四个任务里最讲究结构的一个：序列的长度*和*它的元素值都会影响生成的代码。提示会带你一步一步把它做出来。
