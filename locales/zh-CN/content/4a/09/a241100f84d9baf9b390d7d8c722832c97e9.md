# 从 Travis 迁移

下面是一个`.travis.yml`示例（取自`elm`赛道）：

```yml
sudo: false
language: node_js
node_js:
  - lts/*
script:
  - bin/fetch-configlet
  - bin/configlet lint
  - bin/build.sh
```

要想快速把它改造成 GitHub Actions，请按以下步骤操作：

## 确定模板变量

| 变量                        | 值                                   |
| --------------------------- | ------------------------------------ |
| `<track>`                   | `elm`                                |
| `<image-name>`              | `ubuntu-latest`                      |
| `<action to setup tooling>` | `actions/setup-node@v1`              |
| `<install dependencies>`    | `npm ci`（发生在 `build.sh` 内）     |
| `<code-extensions>`         | `.elm`                               |

> 通过[这个搜索](https://github.com/actions/?q=setup+node&type=&language=)找到了 setup action。镜像名称则是查看[Travis 的默认发行版](https://blog.travis-ci.com/2019-04-15-xenial-default-build-environment)后确定的。

## 确定步骤

- `bin/fetch-configlet`：改用[`configlet.yml`][workflow-template-configlet-yml]工作流后，这一步就不再需要了
- `bin/configlet lint`：改用[`configlet.yml`][workflow-template-configlet-yml]工作流后，这一步就不再需要了
- `bin/build.sh`：一个脚本搞定所有事情

## 准备“脚本”

这条赛道使用`bin`文件夹，所以请在`bin`文件夹中创建以下文件：

```bash
# bin/pr
bin/build.sh
```

```bash
# bin/pr-check
echo "No checks yet"
```

```bash
# bin/ci
bin/build.sh
```

```bash
# bin/ci-check
echo "No checks yet"
```

把它们创建为*相互独立*的二进制文件，方便以后优化。现在不需要把任何东西内联进来。

[`workflows/pr.yml`][workflow-template-pr-ci-yml]的改动相同，只有一处明显的例外：那段把每个改动的文件作为参数传给`pr-check`和`pr`脚本的 bash-fu：

```diff
# # .github/workflows/pr.yml

# # ...

-       - name: Run exercism/<track> ci pre-check (stub files, config integrity) for changed exercises
+       - name: Run exercism/elm ci pre-check (stub files, config integrity) for changed exercises
          run: |
            PULL_REQUEST_URL=$(jq -r ".pull_request.url" "$GITHUB_EVENT_PATH")
            curl --url $"${PULL_REQUEST_URL}/files" --header 'authorization: Bearer ${{ secrets.GITHUB_TOKEN }}' | \

+             jq -c '.[] | select(.status == "added" or .status == "modified") | select(.filename | match("\\.(elm|md|json)$")) | .filename' | \
-             xargs -r scripts/pr-check
+             xargs -r bin/pr-check

  # ...
```

## 现在应该可以了

做到这里就足以迁移到 GitHub Actions 了，之后还可以继续优化你的脚本。

1. 从`build.sh`中移除只应运行一次的步骤，把它们提取到`ci-check.sh`和`pre-check.sh`文件里（提示：你可以创建`lint.sh`，然后在两个“脚本”里都调用它）
2. 为`pr.sh`和`pr-check.sh`添加优化，利用传入的参数来判断该检查哪些文件或练习。
3. 添加更多检查
4. 补充文档，说明如何在本地运行检查，以及每项检查想达到什么目的。
