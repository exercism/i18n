# 简介

## 相等性

简单类型（字符串和基元类型）通常用 `==` 和 `!=` 来测试是否相等。

引用类型（类的实例）则使用从 `Object` 继承来的 `Equals()` 方法进行比较。如果你做相等性测试的目的是确保两个对象是同一个实例，那么直接使用 `Object` 的实现就够了。如果不是，就需要重写 `object.Equals()`。

如果你知道类的所有实例都创建于同一个地方，比如某个游戏或模拟程序里的角色，那么引用相等就足够了。但更常见的情况是，同一个现实实体会有多个实例（来自数据库、用户输入、Web 请求等）。这时就必须对能唯一标识该实体的值做相等性测试。因此必须重写 `Equals()`，并对类中相应的数据成员进行相等性测试。

重写后的 `Equals()` 方法中，会包含对简单类型成员的相等性测试（使用 `==`），以及对引用类型递归调用 `Equals()` 进行的比较。

`Object` 类提供了合适的方法来比较两个对象，判断它们是否是同一个实例。

### `Object.GetHashCode()`

`Object.GetHashCode()` 方法会返回一个 32 位整数形式的哈希码。哈希码被_字典_和_集合_类（例如 `Dictionary<T>` 和 `HashSet<T>`）用来以高效的方式存取对象。

哈希码与相等性的关系是：如果两个对象相等（`Equal()` 返回 true），那么这两个对象的 `GetHashCode()` 必须返回相同的值。反过来则不一定成立，两者并不对称。两个对象哈希码相同，并不代表它们一定相等。可以想象一个查找函数：它先根据哈希码找到对应的“桶”，再用相等性测试挑出具体的那一项。

HashCode 库的 API 文档讨论了生成哈希码的最佳方式。

用在相等性测试中的值，在哈希集合使用期间必须保持稳定。如果你以一个值集把对象加入集合，随后又修改了这些值，哈希码就不再指向正确的“桶”了。实际使用中，这意味着对象应当是不可变的。其他做法则有可能给维护者留下各种坑。

## 集合

集合由唯一值构成。.NET 中集合的默认实现是 `HashSet<T>` 类，它只包含唯一值。
