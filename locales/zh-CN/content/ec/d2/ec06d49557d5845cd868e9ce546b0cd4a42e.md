# 关于

Factor 的 I/O 建立在一个单一的[协议][stream-protocol]之上，任何数据源或数据接收方都可以实现它。内置的流，包括`<file-reader>`、`<file-writer>`、`<string-reader>`、`<string-writer>`、网络套接字、字节数组和 tty，都是实现了[`io`][io]中同一组泛型的类，并且扩展了[`destructors`][destructors]中的`disposable`。

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe`是底层的批量读取：填入调用方提供的缓冲区，并返回写入了多少个元素。对外的`stream-read`和`stream-read-partial`建立在它之上，并负责内存分配。大多数用户自定义的流要么实现`stream-read1`（每次读取一个元素时），要么实现`stream-read-unsafe`（读取可以批量进行时）。

`stream-element-type`返回两个单例标记之一：字节流（文件读取器、套接字）用`+byte+`，字符流（字符串读取器、tty）用`+character+`。包装流通常只是把操作委托给它底层的流。

## 加入混入

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

一个类可以是其中一种，也可以是另一种，或者两者都是。加入混入后，`input-stream` / `output-stream`上的默认方法就会分派到你的类，这和`sets`词汇中的`set`是同一种开放混入模式。

## disposable 框架

`new-disposable ( class -- disposable )`把新创建的实例注册到当前的析构作用域中，这样在资源初始化中途抛出异常时也能干净地回退：

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose`是对外的词，`dispose*`是类需要实现的泛型。子类重写`dispose*`时，应当先清理自己的状态，再释放自己持有的资源：

```factor
M: my-stream dispose* underlying>> dispose ;
```

框架保证每个对象最多只运行一次`dispose*`，重复调用`dispose`都是空操作。

## 带作用域的访问器

有三个组合子用来设置全局的“当前输入/输出流”，供`print`、`read1`等使用：

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

它们都会在退出时释放资源，即使引用抛出了异常也一样。大多数代码正是用它们来使用自定义流，而不是把流层层传递给每一次调用。
