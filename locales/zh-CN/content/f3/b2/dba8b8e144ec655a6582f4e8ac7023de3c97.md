# 说明

你正在为一台复古掌机的计分系统编写固件。
这台机器的处理器性能一般，计分板显示屏的刷新频率是固定的。
为了让画面保持流畅，无论玩家在做什么，计分例程都必须在可预测的周期数内运行。

你有 4 个任务。

~~~~exercism/note
这些任务的代码应当是无分支的。
请使用`cmovcc`、`setcc`和算术运算，而不是条件跳转。
~~~~

## 1. 添加奖励分而不让显示溢出

掌机液晶屏的得分区域只能容纳 6 位十进制数字。
它无法显示任何大于`999999`的数字。
当奖励分会让当前总分超过这个上限时，显示的总分会被固定在上限，而不是回绕。

定义一个函数`add_bonus`：给定当前总分和要添加的奖励分，返回限制在`999999`的新总分。
实参按顺序如下：

1. `total`：当前的得分总分（始终在`0`到`999999`之间）
2. `bonus`：要添加的奖励分（始终非负）

如果`total + bonus`的和小于或等于`999999`，返回值就是该和，否则返回`999999`：

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

实参和返回值都是 64 位有符号整数。

~~~~exercism/note
你可以假设`total + bonus`不会溢出 64 位有符号整数。
~~~~

## 2. 比较两个得分

这台掌机在存档中保存着一份小型排行榜，记录玩家最近取得的最高得分。
每次游戏结束后，新的得分会被插入排行榜中正确的位置。
排序例程会询问两个得分中哪一个更靠前，并期望得到一个小的整数作为回答。

定义一个函数`compare_scores`：给定两个得分，返回：

- 如果第一个得分_更高_，返回`+1`
- 如果第一个得分_更低_，返回`-1`
- 如果两个得分_相等_，返回`0`

示例：

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

实参和返回值都是 64 位有符号整数。

## 3. 校验原始得分

多人对战结束后，掌机可以通过连接线连接到另一台掌机来分享得分。
这条连接线存在电气噪声，传入的字节偶尔会损坏，产生远低于合法下限或远高于合法上限的值。
校验函数会先把每个传入的得分限制到合法范围内，再交给系统的其他部分处理。

定义一个函数`validate_score`：给定一个原始得分和合法边界，返回限制在`[min, max]`范围内的得分。
实参按顺序如下：

1. `score`：通过连接线收到的原始得分
2. `min`：允许的最小得分
3. `max`：允许的最大得分

如果`score < min`，返回值为`min`；如果`score > max`，返回值为`max`；否则返回值为`score`。
你可以假设`min <= max`。

示例：

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

所有实参和返回值都是 64 位有符号整数。

## 4. 记录最高的 2 个得分

每次游玩结束时，掌机都会扫描存档里的最近游玩记录，找出其中记录过的最高的 2 个得分。
这份记录就是内存中一个普通的 64 位有符号整数数组。
扫描过程只遍历数组一次，并维护 2 个当前最大值：目前遇到的最高值，以及第二高值。

注意，这 2 个值都应当至少为`0`。
任何负数都会被忽略。

这个函数的第一个版本使用了层层嵌套的条件跳转。
对每个候选值，代码都会判断它应该放在哪里（高于第一、介于第一和第二之间，或者哪里都不放），并相应地调整当前的 2 个最大值，同时丢弃任何为负的结果。

这样做是可行的。
不过，由于输入值是随机的，每次条件跳转都会导致大量分支预测错误。
因此，你决定把主循环重构成无分支的形式。

下面是这个函数，其中有分支的部分已被注释掉：

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

请把注释掉的部分替换为无分支的实现。
新代码中唯一允许的跳转，是回到循环开头、检查数组中下一个元素的那一次跳转。

这个函数没有返回值，接受的实参与有分支的版本相同：

1. `out`：输出缓冲区，函数会把最高的 2 个非负得分按降序写入其中，形式为 64 位有符号整数
2. `array`：输入的 64 位有符号整数数组
3. `length`：数组中的元素个数，形式为 64 位无符号整数

~~~~exercism/note
如果数组中存在重复的值，而它们正好是最高的 2 个得分，那么这 2 个重复值可能会同时出现在 2 个输出位置中。
~~~~
