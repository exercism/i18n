# 关于

递归函数就是会调用自身的函数。

一个递归函数至少需要一个_基本情况_和一个_递归情况_。

_基本情况_会返回一个值，不再调用函数本身。
_递归情况_会再次调用函数，同时修改输入，使其最终能匹配基本情况。

在 Elm 中，递归函数通常使用模式匹配和`case`表达式来定义。

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

一个递归函数可以有多个基本情况，也可以有多个递归情况。
例如，[斐波那契数列][fibonacci]就是一个带有两个基本情况的递归数列：

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

注意，这个实现会随着输入增大而呈指数级变慢，因为相关的斐波那契数是在两次独立的递归调用中从头算起的。

统计某个给定值`x`在数组中出现的次数，用到了两个递归情况：

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## 通过递归实现循环

由于不可变性，Elm 中的循环写法与命令式语言不同。
例如，循环通常长这样：

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

在 Elm 这样的函数式语言中，无法修改变量。
因此，循环只能用递归来实现。

在 Elm 中，与`for`循环等价的写法是这样的：

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

在实践中，在 Elm 中迭代数组和其他数据结构，最常用的方式是使用[`List`][module-list]模块中的函数，比如`List.map`、`List.filter`和`List.foldl`。
在底层，这些函数都是用递归实现的。

## 无限执行

如果递归函数实现有误，或者递归调用的次数过多，它可能永远无法返回结果。
这会带来问题，因为每次调用函数时，都会在内存中保存一个引用，指明运行时应该把结果返回到哪里（就在[调用栈][wiki-call-stack]上）。
如果递归函数调用自身的次数太多，甚至无限调用，就可能耗尽内存，导致运行时崩溃（即[栈溢出错误][wiki-stack-overflow]）。
Elm 的运行时针对递归和可靠性做了优化，但无限递归依然可能引发问题。

导致无限执行问题的原因有：

- 忘记实现基本情况。
- 模式匹配时没有处理所有可能出现的情况。
- 进行递归调用时没有正确修改实参，因而永远无法到达基本情况。
