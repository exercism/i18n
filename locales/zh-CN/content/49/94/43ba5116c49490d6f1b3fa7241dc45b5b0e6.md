# 简介

标量代码依赖各种指令设置的标志位，以便根据特定条件进行分支。
而打包值表示的不是一个值，而是许多并行排列的值。
同一个条件可能对某个通道不成立，却对另一个通道成立。

这就是为什么 SIMD 代码默认就是_无分支_的。

打包比较通常不依赖标志位，而是向目标操作数中写入一个**掩码**。
对于每个通道，当比较结果为 true 时，它会用 1 填满整个通道，为 false 时则用 0 填充。
按有符号整数来读，为 true 的通道是 `-1`，为 false 的通道是 `0`。

然后就可以把这个掩码与按位运算组合起来，筛选出特定的通道。

## 打包比较

标量 `cmp` 是通用的，因为它一次可以设置多个标志位。
之后，另一条指令可以读取这些标志位，据此进行分支或执行计算。

然而，打包比较既要检查条件，又要计算出掩码，所以它并不通用。
比较必须明确指定所要测试的条件。

有两种做法：

- 整数比较通过后缀来指定条件：`eq` 表示相等，`gt` 表示大于。
  其他变体则通过组合上述某一种的结果来构造。
- 浮点数比较的条件则编码在立即数中。
  该立即数的不同取值对应不同的测试条件。

除了整数比较要使用特定的条件后缀之外，语法结构与我们之前见过的相同：

- 整数：`p` + `cmp` + 条件 + 尺寸（`b`、`w`、`d` 或 `q`）。
- 浮点数：`cmp` + `p` + 尺寸（`s` 或 `d`）。
  条件作为一个额外操作数，通过立即数传入。

### 整数比较

如前所述，整数比较只有相等和大于两种：

| 指令                                        | 说明                             |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`、`pcmpeqw`、`pcmpeqd`、`pcmpeqq` | 逐通道相等                       |
| `pcmpgtb`、`pcmpgtw`、`pcmpgtd`、`pcmpgtq` | 逐通道**有符号**大于             |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

要构造小于比较，可以把操作数交换后使用 `gt`：`a < b` 等价于 `b > a`。

注意，这种比较是**有符号**的。
要进行无符号比较，需要翻转两个操作数的最高位。
这可以通过与一个只有最高位置位的掩码做异或来实现。

~~~~exercism/note
有两个好用的惯用写法：

1. 把寄存器与自身做异或，得到全 0。
2. 把寄存器与自身做比较，得到全 1。

例如：

```x86asm
pxor xmm4, xmm4    ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

全 0 和全 1 是常见的掩码，分别用来表示“处处为 false”和“处处为 true”。
它们还可以用来表示打包的 `0` 或打包的 `-1`，这些是常见的哨兵值。
例如，标记字符串结尾的 NUL 就是一个 `0`。
~~~~

### 浮点数比较

浮点数通道采用不同的形式：只用一条指令 `cmpps`（64 位通道则用 `cmppd`），条件以立即数的形式给出：

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM 还提供了一些伪指令，它们会映射到正确的立即数，而且更好记忆。
在下面所有写法中，`px` 里的 `x` 可以是 `s`（32 位浮点数）或 `d`（64 位浮点数）：

| 伪指令       | 立即数    | 比较                   |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a 为 NaN 或 b 为 NaN   |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | a 和 b 都不是 NaN      |

## 用掩码进行选择

掩码编码了某个条件的结果。
然后就可以根据这个条件，逐个通道地在两组值之间做选择。
掩码为 true 的通道取自其中一个值，为 false 的通道取自另一个值：

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

这种模式是无分支选择的打包形式。
每个通道都会被计算出来，仅由掩码决定哪个值最终保留，全程没有任何 `jcc`。

## 专用的混合指令

有些指令可以直接完成同样的选择，它们从掩码寄存器中为每个元素读取一个位。
它们被称为**混合**指令：

| 指令        | 元素        | 掩码来源        |
|-------------|-------------|-----------------|
| `pblendvb`  | 字节        | 隐式 `xmm0`     |
| `blendvps`  | 32 位通道   | 隐式 `xmm0`     |
| `blendvpd`  | 64 位通道   | 隐式 `xmm0`     |

注意，第一条指令遵循整数语法，另外两条则遵循浮点数语法。
不过，由于这些指令只是选择原始字节，所以它们中的任何一条都能同时用于整数和浮点数。

对于每个元素，当对应掩码元素的最高位为 0 时，混合指令保留目标值；为 1 时则取源值。
只会查看那个**最高位**，比较掩码正好满足这一点，因为它的每个通道要么全是 1，要么全是 0。
掩码寄存器始终是 `xmm0`，它是隐式的：

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

也可以用 `pblendvb` 从比较掩码中选取任意其他尺寸的通道。
由于为 true 的通道中所有字节都是全 1，`pblendvb` 会把它们全部选中。

~~~~exercism/note
这些指令都在所执行的操作名（`blend`）后面加了一个 `v`。
这个 `v` 代表 _variable_，因为选择不是静态的：它取决于某个寄存器。

还有不带 `v` 的变体，它们根据立即数进行选择。
它们的模式相同：如果立即数的第 `i` 位为 1，就选择通道 `i`。
~~~~

## 从掩码回到标量

SIMD 代码虽然强大，却缺少标量代码的许多灵活性。
在很多情况下，都需要从打包寄存器回到标量指令的世界。

`movmsk` 系列指令就是连接这两个世界的桥梁。
这些指令会把每个通道的**最高位**提取到一个通用寄存器中：

| 指令        | 收集内容                     | 结果宽度    |
|-------------|------------------------------|-------------|
| `pmovmskb`  | 16 个字节各自的最高位        | 16 位       |
| `movmskps`  | 4 个双字各自的最高位         | 4 位        |
| `movmskpd`  | 2 个四字各自的最高位         | 2 位        |

如果用在比较之后，每个置位的位表示一个“true”通道，每个清零的位则表示一个“false”通道。
然后就可以像往常一样用标量指令来处理这个结果。
例如，`popcnt` 可以数出匹配的个数，`tzcnt` 则可以找到第一个匹配。

通用寄存器可以是 32 位或 64 位宽。

## 测试整个向量

`test` 标量指令还有一个打包版本：`ptest`。

它与对应的标量指令类似，会在两个操作数之间执行与运算，但不会修改它们。
与 `test` 不同的是，`ptest` 还会执行与非运算，对第一个操作数取反。

因此，可以把 `ptest` 看作 `pand` 和 `pandn` 的非破坏性版本，它根据结果设置标志位。
大致和这两条指令一样，`ptest` 把整个 SIMD 寄存器当作单个通道，所以不带尺寸前缀。

如果与运算的结果是 `0`，就会设置 `ZF`；如果与非运算的结果是 `0`，设置的则是 `CF`。
这意味着可以用 `ptest` 同时检查全 1 掩码和全 0 掩码：

1. 对一个寄存器自身使用 `ptest`，只有当该寄存器全为 0 时才会设置 `ZF`。
   这模仿了常见的标量惯用写法：对寄存器自身使用 `test` 来检查是否为 `0`。
2. 对一个寄存器与全 1 掩码使用 `ptest`，只有当该寄存器全为 1 时才会设置 `CF`。
   此外，只有当该寄存器全为 0 时它才会设置 `ZF`，因此可以一次检查两种掩码。

```x86asm
pxor    xmm0, xmm0   ; all zeros
pcmpeqb xmm1, xmm1   ; all ones
pcmpeqb xmm2, xmm2

ptest xmm0, xmm0     ; ZF set: a register against itself detects all zeros
ptest xmm0, xmm1     ; ZF set, CF clear: xmm0 is all zeros, not all ones
ptest xmm2, xmm1     ; CF is set only if xmm2 is all ones
```

`ptest` 的结果可以像往常一样用于分支，或者用于 `setcc`、`cmovcc` 等无分支指令。
