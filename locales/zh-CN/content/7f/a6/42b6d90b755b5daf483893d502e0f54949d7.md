# Shell 基础入门

## Shell

_shell_ 是一个程序，让你可以输入命令来与操作系统交互。
shell 可以是图形化的：你用鼠标或触控板操作的桌面环境就是一个 shell。
我们将重点关注命令行界面：你在其中输入命令，结果（通常）会打印到终端里。

命令行 shell 有很多种。
Windows 提供了 **cmd** 和 **powershell**。
Mac 和 Linux 提供“Unix shell”，种类繁多。
Mac 的默认 shell 是 **zsh**。
**csh** 是一种语法类似 C 的老式 shell。
**bash** 是最流行的 shell 之一，在 Linux 上尤其如此。

最早的 shell 之一是 Bourne shell，即 **sh**。
随着时间的推移，这个 shell 被[标准化][posix]，成为每个类 Unix 系统都必须提供的东西。
许多 shell 都以 Bourne shell 为基础，通常还提供了额外的交互或编程功能。

**Bash** 基于 Bourne shell。
这就是它被称为“**B**ourne-**a**gain **sh**ell”的原因。
它是许多 Linux 系统的默认 shell。
Bash 提供了许多功能，让它成为一个用起来很愉快的交互式 shell，其中包括：

* 可完全自定义的提示符，
* 能够调出并修改历史记录中的命令，
* 能够操作正在运行的进程，
* 可以减少输入的别名，
* 以及更多。

本 track 讲的不是如何把 bash 当作交互式 shell 来用。
它讲的是学习如何用 bash 编写程序。
重点是_只_用 bash 来解决问题，不过调用外部工具并没有任何限制。

## Bash 基础：命令与实参

Bash 从它的输入（通常要么是终端，要么是文件）中读取命令。
它读取的每一行输入都会被当作一条_命令_，也就是一条要执行的指令。
（有一些高级情况，比如跨多行的命令，稍后再讨论。）

Bash 把每一行拆分成由空白字符（空格和制表符）分隔的**单词**。
这一行的第一个单词就是要执行的_命令_的名字。
其余所有单词都成为该命令的_实参_（选项、文件名等）。

~~~~exercism/note
下面的示例中，我们会展示一些你可以运行的交互式命令。

* `#`字符开始一条_注释_。
  注释后面的任何内容都会被 shell 忽略；注释只是让人阅读的。
* `$`字符表示 shell 提示符。
  如果你要复制命令，不要带上提示符。
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm`是一个应用，用来删除传给它的文件。
`*`是一个 [glob][glob] 字符，一种“通配符”模式，能匹配当前目录下的所有文件。
稍后我们会更详细地讲 glob。

你注意到`a`和`b`之间有好几个空格，而`b`和`c`之间只有一个了吗？
实参之间空白多少并不重要！
例如：

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo`是一个命令，会把它的实参打印到标准输出（在我们这里就是终端）。
Bash 把这条命令拆成五个单词，然后用四个实参调用`echo`命令。
第二个示例里多出来的空格没有任何影响。
`echo`并不知道单词之间原本有多少空格。

如果我们想保留多余的空白，就需要把整句话作为单个实参传进去。
我们可以用[引号][Quotes]来做到这一点：

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

引号会把其中的所有内容归为一个_单个实参_。
这个实参是`This    is    a    test.`，包含那些具体的空格字符。
注意，引号并不属于实参的一部分，bash 会在把这个实参交给`echo`之前把它们去掉。

实参之间，以及实参与命令名之间，都用空白分隔。
这一点很重要，要记住。
例如，下面这种写法是错的：

```bash
$ [-f file]
bash: [-f: command not found
```

这段代码本意是测试名为`file`的文件是否存在。
人们很容易以为`[`和`]`周围的空白无关紧要，但`[`其实是一个命令，它要求最后一个实参是`]`。
（稍后我们会更详细地讲`[`命令。）
因此，我们必须把`[`与`-f`分开，把`]`与`file`分开。
否则 bash 会以为我们在执行一个名为`[-f`的命令，并带着单个实参`file]`。
正确的命令是用空白把所有实参分开：

```bash
$ [ -f file ]
```

（我们看到很多人被这种行为弄糊涂；他们以为`[...]`“只是语法”，可以省略空格；但`[`是一个命令，那些空白是必需的。）

如果文件名里含有空白或其他特殊字符，也应该用引号括起来：

```bash
$ [ -f "my file" ]
```

## 命令的类型

Bash 能识别几种不同类型的命令：别名、函数、内置命令、关键字和可执行文件。
它们都是_命令_，行为方式也非常相似。

默认情况下，别名只在交互式 shell 中启用，而不会在 shell 脚本中启用。
这里我们不展开讲。

### 函数

函数里包含 shell 命令，用起来很像一个小脚本；它们甚至可以接收实参、创建局部变量。
调用函数时，里面的命令会被执行。
函数会在后面详细介绍。

### 内置命令

Bash 内置了一些基本命令，比如：`cd`（切换目录）、`echo`（输出内容）等等。
可以把它们看作已经预先提供的函数。

### 关键字

关键字和内置命令类似，主要区别在于：关键字其实是 bash 语法的一部分，可能会按特殊规则来解析。
例如，`[`是 bash 的内置命令，而`[[`是 bash 的关键字；两者都用来测试各种条件。
但`[[`关键字有额外的功能。
例如，它提供了`=~`运算符，用来做正则表达式测试。

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

字符串比较运算符`<`和`>`是另一个例子，说明关键字会以不同方式解析代码。
在`[[...]]`里，这些运算符不需要特别处理。

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

但在`[...]`里，必须给它们加引号或转义，防止 shell 把它们解析成重定向运算符。

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### 可执行文件

bash 能执行的最后一类命令是_可执行文件_。
它们是你电脑文件系统上可以运行的可执行文件（程序）。
（可执行文件有时也叫_外部命令_或_应用程序_。）
通常只要输入名字就能调用可执行文件，一般不需要文件的完整路径。
之所以能做到这一点，是因为 bash 使用了一个预定义的变量，帮助它找到常见可执行文件的位置。
这个变量叫`PATH`。
它是一组用冒号分隔的目录名（例如`/usr/bin:/bin`）。
当指定一个命令（例如`myprogram`或`ls`）却没有给出文件路径时（而且它不是别名、函数、内置命令或关键字），bash 会在`PATH`里的各个目录中查找。
这些目录会按从左到右的顺序被搜索，看其中是否含有名字匹配的可执行文件。

如果可执行文件不在已知路径里，就需要指定它的文件路径。
对于当前目录里的`myprogram`，使用`./myprogram`；如果它在目录`/opt/somedirectory`里，就使用`/opt/somedirectory/myprogram`。

提示：`type`命令可以用来获取命令的详细信息：

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## 脚本

_脚本_是存放在文件里的一串命令。
Bash 读取文件，并按顺序处理其中的命令。
只有当前命令结束后，它才会继续处理下一条命令。
例外情况是命令被指定为异步运行（在后台运行）。
现在还不用太担心这种情况；我们后面会学习它是如何工作的。

本指南里的任何命令行示例也都可以用在脚本中。

编写脚本很简单。
先新建一个文件，在第一行写上：

```bash
#!/bin/bash
```

这一行叫作_解释器指令_（也叫 _hashbang_ 或 **_shebang_**）。
它指定当这个文件被当作命令中的可执行文件使用时，要用`/bin/bash`作为解释器。
当操作系统的内核执行一个_非二进制文件_时，它会读取文件的第一行。
如果这一行以`#!`开头，内核就会根据这一行来确定把文件交给哪个解释器。
（还有其他可行的做法，见下文。）
`#!`必须位于文件的最开头，前面不能有空格或空行。
我们脚本里的命令会分别出现在这一行下方的各行中。

提示：除了`#!/bin/bash`，你也可以用

```bash
#!/usr/bin/env bash
```

`env`会在`$PATH`中搜索由它的第一个实参指定的可执行文件（这里是“bash”）。
想更详细了解这种做法，以及它与普通的`#!/bin/bash`有什么不同，请参见 [StackOverflow 上的这个问题][env bash]。

请不要被网上把`/bin/sh`当作解释器的脚本或示例骗了。
**`sh` 不是 `bash`！**
Bash 本身是一个“与 sh 兼容”的 shell，也就是说它能运行大多数`sh`脚本，并沿用了许多相同的语法。
但反过来并不成立；bash 的一些功能在`sh`里会出错或产生意外的行为。
事实上，并不存在单一的`sh` shell。
有许多支持 POSIX-sh 语法的 shell 实现。
取决于你的操作系统，当你运行`sh`时，实际执行的可能是 bash、ash、dash 或其他某个 shell。

脚本文件创建好之后，就可以这样执行：

```bash
$ bash myscript
```

在这个例子里，我们执行_命令_`bash`，并让它读取我们作为_实参_传入的脚本。
这样执行时，`#!`那一行只是一条_注释_。

另一种做法是给脚本加上可执行权限。
用这种方法，我们可以像执行任何其他可执行文件一样执行这个脚本，而不必手动调用 bash：

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

当我们用这种方式运行命令时，操作系统（OS）会根据`#!`那一行来决定用哪个解释器来运行你的脚本。
