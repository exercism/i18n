# 简介

程序的内存通常由操作系统（OS）映射为一种通用布局：

| 地址 | 内存区域 |
| :--: | :------- |
| 高地址 | 栈 |
|  | …… |
|  | 堆 |
|  | 可读写段 |
|  | 代码/只读段 |
| 低地址 | 保留 |

内存划分成不同的段，段内又按节进行组织，各节拥有不同的权限。

我们目前定义的函数都位于**section .text**中。
该节存放只读的可执行数据。
其他节用于声明数据变量，这些变量可以是只读的，也可以是可读写的，但不可执行。

## Section .data

已初始化的数据在**section .data**中声明。

在 NASM（The Netwide Assembler，即本学习路径所使用的汇编器）中，一个初始化变量包含一个名称、一个指明数据大小的伪指令，以及一个用逗号分隔的值列表。
这些部分之间用空格分隔，标签后面还可以选择性地加上一个`:`。

主要的伪指令及其对应的数据大小如下：

| 伪指令 | 大小 |
| :----: | :--- |
|    db     | 1 字节  |
|    dw     | 2 字节 |
|    dd     | 4 字节 |
|    dq     | 8 字节 |

例如，下面声明了一个名为`space`、值为`10`的字节变量：

```x86asm
section .data
    space db 10
```

在`section .data`中声明的变量是可变的，也就是说，它们是可读写的。
它们还具有_静态_存储期，也就是在程序的整个运行期间一直存在。

## Section .rodata

**section .rodata**与`section .data`类似。
两个节都包含已初始化的数据，声明方式相同，存储期也相同。

两者的主要区别在于，`section .rodata`中的数据是不可变的，也就是只读的。

~~~~exercism/note
用`equ`定义的常量与在`section .rodata`中定义的常量不同。

用`equ`定义的常量不占用内存空间，汇编器会直接用它的值进行替换。
实际上，它就是这个值的一个占位符。

另一方面，在`section .rodata`中定义的常量确实存储在内存中，拥有一个地址。
~~~~

## 访问数据

### 标签与间接寻址

声明的数据必须有一个与之关联的名称。
这个名称叫做**标签**。

标签是一个符号，它表示数据在内存中的具体地址。
**x86-64 中的地址是 64 位的值**。

在 NASM 中，直接用标签访问数据，得到的并不是所分配的内存，而是它的地址：

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

要访问某个内存地址中的内容，需要对其进行_解引用_。
这叫做**间接寻址**。

在 NASM 中，用`[]`完成这一操作：

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

不过，有些情况下，被解引用的内存大小可能存在歧义。
在这些情况下，必须使用一个指明该大小的前缀。

以下是典型的 x86-64 程序中最重要的前缀及其大小：

| 前缀 | 大小 |
| :--- | :--- |
| byte   | 1 字节  |
| word   | 2 字节 |
| dword  | 4 字节 |
| qword  | 8 字节 |

同一次加载也可以显式写出大小：

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

解引用内存时始终使用前缀，是一种好习惯。

### 写入内存

向内存写入的方式相同，也是通过解引用一个地址：

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

注意，在大多数指令中，无需先把内容加载到寄存器，就可以直接使用内存操作数。
不过，通常不能同时在源操作数和目标操作数中使用它们，只能用在其中一个：

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### LEA 指令

虽然可以用`mov`把变量的地址存入寄存器，但有一条专门用于此目的的指令：**lea**。

这条指令使用内存形式的操作数，但它_不会_读取内存。
相反，它计算有效地址表达式，并把结果写入目标操作数：

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

用`lea`来计算内存地址并存入寄存器，是更符合习惯的做法。

### 相对寻址

在访问内存位置时，NASM 的默认行为是生成**绝对地址**，也就是固定的内存地址。

出于安全原因，可执行文件通常构建为 **PIE（位置无关可执行文件）**，其中的内存区域被放在随机化的位置。
在`PIE`中，变量的最终地址在链接时是未知的。
因此，代码改为根据一个名为`rip`的特殊寄存器中的值，以偏移量的形式计算地址，该寄存器指向下一条将要执行的指令。

这通常叫做 **RIP 相对寻址**。

在 NASM 中，可以用`rel`运算符请求 RIP 相对访问：

```x86asm
mov rax, qword [rel variable]
```

也可以在源文件顶部用`default rel`，把相对寻址设为默认方式。

本学习路径中的所有练习都以`PIE`方式编译和链接，因此应使用`rel`生成相对地址。

### 可见性

在任何节（例如`.text`、`.data`、`.rodata`）中定义的标签（函数和数据），在同一个源文件内都是可见的。
如果声明为`global`，它们对其他源文件也是可见的。

反过来，在其他源文件中定义的标签，如果声明为`extern`，则对当前源文件可见。
在这种情况下，汇编里不会指明数据大小，必须事先知道它。

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
