# 关于

## Julia 中的布尔值

真值和假值由`Bool`类型表示。
它只有两个取值：`true`和`false`。

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

与许多其他语言不同，Julia 有意没有“truthiness”这个概念，只有求值为`true`或`false`的表达式才会被当作`Bool`。

具体来说，空数组或空字符串*不会*被解释为`false`。
如果你想对空值做特殊处理，就必须使用合适的判断，比如`isempty()`。

## 布尔运算符

Julia 中有三个[布尔运算符][boolean-operators]。

`&&`是布尔“与”。
当`&&`*两侧*的表达式都为`true`时，它的求值结果是`true`。

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||`是布尔“或”。
当`||`*任意一侧*的表达式为`true`时，它的求值结果是`true`。

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!`是布尔“非”。
它会把`true`和`false`互换（取反）。

```julia-repl
julia> !true
false

julia> !false
true
```

许多其他语言的使用者对这些运算符的概念会很熟悉，不过具体语法可能因语言而异。

## 运算符优先级

在更复杂的表达式里，知道`&&`的[优先级][operator-precedence]比`||`稍高会很有用*（就像算术表达式里`*`先于`+`运算一样）*。

依赖它容易让人困惑，也容易出错。
为了清晰起见，请用括号把你的意图表达清楚。

## 短路求值

表达式`true || x`是否依赖`x`的值，还是说编译器可以忽略`x`？

Julia 从左到右对布尔表达式求值，一旦结果已经确定就停下来。

例如，无论`x`是什么，`true || x`必定为`true`，所以不会对`x`求值。
同样，`false && y`一定是`false`，不需要对`y`求值。

反过来，只有*在*`x`为`true`时，`true && x`才为`true`，所以必须对`x`求值。

同样，如果串联多个运算符：

```julia-repl
julia> true && false && something_else
false
```

因为`true && false`必定为`false`，所以`something_else`无关紧要，编译器会忽略它。

在这个例子里，`something_else`并不是一个存在的变量，但把它写在这个上下文里并没有报错*（如果你不信，可以在 REPL 里试试）*。

Julia 程序员经常利用这种短路求值，作为一种捕获运行时问题和边界情况的捷径：

```julia
all_ok || do_something()

is_problem && do_something_else()
```

例如，当`all_ok`为`false`时，`do_something`可能是函数的一次提前`return`，也可能是先给变量赋一个默认值再继续。

这算是对布尔语法的一点滥用，但有时非常方便。

## 布尔值的内部机制

如果布尔值出现在*算术*表达式里，`true`会被当成`1`，`false`会被当成`0`，这也反映了它们在底层的存储方式。

如果你习惯使用底层语言（比如 C 以及类似的语言），*请*尽量避免频繁这样做。
这会降低代码的可读性，也让调试更困难。

有时你可能会看到有人用这些数值来快速统计有多少项为`true`。

```julia-repl
julia> true + false + true
2
```
