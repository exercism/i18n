# 说明补充

## 实现

在开始之前，先确认你了解如何编写能通过测试用例的代码。
想了解更多背景信息，可以看看这篇[教程][tutorial]。

大多数 Java 练习都包含多个测试用例。
这些用例的结构支持一种很有用的流程，叫做[测试驱动开发（TDD）][tdd]。
TDD 会重复一个有结构的循环，帮助程序员一步步地构建复杂功能，而不是一次性全部写完。
这个循环可以这样描述：

1. 添加一个测试，用来描述你的代码目前还缺少的某一项功能。
2. 运行测试，确认这个新添加的测试失败。
3. 修改你现有的代码，直到：
   - 原来所有的测试仍然通过；
   - 新的测试也能通过。
4. [整理][refactoring]你的代码，确保所有测试仍然通过。
   这通常包括重命名变量、删除重复的逻辑片段、删除残留的日志输出等。
5. 回到第 1 步，直到所有想要的功能都实现为止！

这个 track 里的测试文件包含你的解答必须通过、才能被判定为有效的_全部_测试。
这乍看之下和上面描述的循环并不兼容，因为上面是一步一步地写测试的。
不过，我们用来编写测试的工具 [JUnit][junit] 提供了一个 [@Disabled][junit-disabled] [注解][java-annotation]，可以用来临时跳过已经写好的测试。
借助这个注解，我们可以确保交付给你的测试文件满足以下规则：

- 任何测试文件中的第一个测试默认_不会_被跳过。
- 任何测试文件中除第一个以外的测试默认_都会_被跳过。

这样你就可以按照下面这些稍作调整的步骤，来模拟 TDD 循环：

1. 运行测试，确认当前_最多只有一个_测试失败。
2. 修改你现有的代码，直到所有未被跳过的测试都通过。
3. 整理你的代码，确保所有未被跳过的测试仍然通过。
4. 删除测试文件中最上面那个 `@Disabled` 注解。
5. 回到第 1 步，直到没有测试被跳过，并且所有测试都通过！

[junit]: https://junit.org/junit5/
