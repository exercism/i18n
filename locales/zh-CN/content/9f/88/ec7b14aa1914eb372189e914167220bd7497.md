# 自定义迭代器

从 `bird-survey` 开始，你就一直在用迭代器。现在轮到你来写一个。

## yield

迭代器看起来像例程，但有两处不同：它的名字以 `!` 结尾，而且它用 `yield` 而不是 `return` 交出值。

```sather
   markers!(count : INT) : INT is
      loop
         yield 100 * 1.upto!(count);
      end;
   end;
```

`yield` 把一个值交给调用这个迭代器的循环，然后**等待**。当那个循环再次轮到它时，迭代器从 `yield` 之后接着往下走，一切保持原样：它的变量、它自己的循环、它所在的位置。

这就是迭代器：一个能在中途暂停、之后再继续的例程。

```sather
   loop
      #OUT + TRAIL::markers!(3) + " ";      -- 100 200 300
   end;
```

## 结束

迭代器有两种结束方式。

**耗尽。** 当迭代器自己的循环跑完，或者例程走到末尾时，它就结束了，而调用它的那个循环也立刻结束。

**quit。** `quit` 就在当下把它结束掉，不经过 `yield`。

```sather
   named!(names : ARRAY{STR}) : STR is
      loop
         name ::= names.elt!;
         if name = "" then quit; end;
         yield name;
      end;
   end;
```

它会一直交出名字，直到遇到空字符串，然后停下。`quit` 之于迭代器，就像 `return` 之于例程，区别在于它不带值：已经没有东西可以交出去了。

## once

标了 `once` 的实参只会在循环开始时计算一次，而不是每一轮都算：

```sather
   markers!(once count : INT) : INT is
```

凡是每一轮之间都不会变的东西，都用它标注，大多数实参都是这样。库自己的迭代器也是这么做的：`upto!(once i : SAME)`。

## 没有值的迭代器

迭代器不必交出任何值。`times!` 就是一个：

```sather
   steps!(once count : INT) is
      loop
         ignored ::= 1.upto!(count);
         yield;
      end;
   end;
```

单独的 `yield` 不交出任何东西，只是让循环进入下一轮。

## 位置在哪里

程序中每个调用迭代器的*位置*都保有自己的进度，这就是为什么在同一个循环体里两次调用同一个迭代器，就会把它走两遍。现在你就能明白原因了：这两次调用是两个各自暂停的例程。
