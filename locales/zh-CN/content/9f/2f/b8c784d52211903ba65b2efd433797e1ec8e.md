# 引言

Factor 的 I/O 建立在*流*之上：你可以从中读取字节或字符，也可以向其中写入。[`io`][io] 词汇表为你提供了同一个[协议][stream-protocol]的两种视角。

## 两种视角

**显式流**词以流作为参数。它们都以 `stream-` 开头：

```
stream-read       ( n stream -- seq/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

**环境流**词从*当前绑定*的那个流读取，或向它写入，也就是程序范围内生效的动态变量 `input-stream` 或 `output-stream`。它们的名字都很短：

```
read1 read readln write write1 print flush
```

日常代码大多使用环境流形式。当你手头有一个具体的流，又不想替换掉环境流时，才会用到显式流形式。

## 内存中的流

本练习中，你将使用来自 [`io.streams.string`][io.streams.string] 的、以字符串为后端的流：

```
<string-reader>   ( str -- reader )
<string-writer>   ( -- writer )
```

`<string-reader>` 会像读取文件一样读取一个字面量字符串；`<string-writer>` 则收集写入其中的所有内容，方便你之后读回来。两者实现的协议与文件流相同，因此这些经验可以直接套用到 `<file-reader>` / `<file-writer>` 上。

## 用 `with-…` 限定作用域

若要把一个显式流绑定为某个引用的环境流，并在之后释放它，可以使用 `with-…` 组合子：

```
with-input-stream    ( stream quot -- )
with-output-stream   ( stream quot -- )
with-string-writer   ( quot -- str )
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
```

[`with-string-writer`][with-string-writer] 是“收集这个引用所打印的内容”的便捷形式：它构建好 writer，以该 writer 作为环境输出来运行引用，并返回捕获到的字符串：

```factor
USING: io io.streams.string ;

[ "captured" print ] with-string-writer .
! => "captured\n"
```

所有 `with-…` 组合子都是析构组合子（与 [`boatswains-bilge`][boatswains-bilge] 中的 `with-disposal` 和 `with-destructors` 属于同一家族）：即使引用抛出异常，流也会在退出时被释放。
