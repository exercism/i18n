# 字符串构建器

`STR`是不可变的，`FSTR`不是。已经定稿的文本用`STR`，还在组装中的文本用`FSTR`。

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## 一定要把结果赋回去

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR`通过**均摊倍增**来扩容：空间不够时，它会换一个新的、更大的数组，大小是原来的两倍，再把内容复制进去。所以得到的结果通常是同一个对象，偶尔才会是另一个。每次都写`b := b + x`在两种情况下都正确，也是唯一值得记住的写法。

翻倍正是让总工作量与长度成正比、而不是与长度的平方成正比的原因：复制得越少，每次复制就越贵。

## 为什么不直接对 STR 用 `+`？

用`+`拼接固定的、少量的片段，既清晰又没问题：

```sather
   return piece + " by " + composer;
```

问题只出在循环里：写代码的时候，还不知道要拼接多少次。一个粗略的准则：如果`+`出现在`loop`里面，就用`FSTR`。

## 常用例程

| 调用 | 作用 |
| --- | --- |
| `b + x` | 追加；`x`可以是`STR`、`CHAR`、`INT`、`BOOL`等 |
| `b.size` | 目前有多少个字符 |
| `b.str` | 一个定稿的`STR` |
| `b.clear` | 清空内容，但保留已经分配的空间 |

## 转义序列

| 写法 | 含义 |
| --- | --- |
| `"\n"` | 换行 |
| `"\t"` | 制表符 |
| `"\""` | 双引号 |
| `"\\"` | 反斜杠 |
