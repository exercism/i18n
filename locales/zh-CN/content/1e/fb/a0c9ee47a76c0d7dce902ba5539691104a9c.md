# 简介

## 二进制表示法

**整数**是一种抽象，用来表示不带小数部分的数，例如 `4`、`-2`、`0` 或 `64532`。

要把一个整数表示成字节序列，就要用到**二进制表示法**。在这种表示法中，序列里的每一位代表一个不同的 2 的幂；位的索引从右向左递增，所表示的值也随之增大。

## 无符号数

如果一个数只能是非负数，就称它为**无符号**数。

无符号数直接表示为其序列中所有置 1 的位所对应的 2 的幂之和。

一个寄存器里可表示的非负整数范围，从 `0`（没有任何位被置 1）到 `2⁶⁴ - 1`（全部 64 位都置 1 时的和）。

把一个无符号数加宽到更大的位宽，做法是把所有高位都填上 `0`，这样新增的位都不会对数值有贡献。这叫做**零扩展**。

指令`movzx`（`z` 代表 zero）会把 8 位或 16 位的源操作数零扩展到更大的目标操作数。32 位的源操作数则总是用一条简单的`mov`就零扩展到目标操作数的全部 64 位。

## 有符号数

如果一个整数可以取正值或负值，就称它为**有符号**数。

为了表示负数，x86-64 采用**补码**表示法。

在补码中，有符号数同样表示为置 1 的位所对应的 2 的幂之和。不过，如果最高位被置 1，它就不是加到其他位上，而是被减去。

由于这一位对应的值比其他所有位的和还要大，所以在实际中，只要这一位被置 1，这个数就一定是负数。这个特殊的位叫做**符号位**。

把一个有符号数加宽到更大的位宽，意味着每个新增的高位都填入符号位的副本，从而保持数值不变。这叫做**符号扩展**。

指令`movsx`（`s` 代表 sign）会把 8 位或 16 位的源操作数符号扩展到更大的目标操作数。`movsx`有一个变体叫`movsxd`，它把 32 位的源操作数符号扩展到 64 位的目标操作数。

可以用`neg`指令改变一个数的符号。

~~~~exercism/caution
在汇编中，无法判断一个字节序列表示的是有符号数还是无符号数。这些字节的含义，得由程序员自己来赋予。

使用注释能在这方面帮上很大的忙。
~~~~

## 立即数

在之前的一个概念里提到过，像 `4` 或 `-15` 这样的常数可以作为许多指令的源操作数。这类数字叫做**立即数**。

立即数不存放在寄存器或内存中：它被编码在指令本身里面。在大多数指令中，为它预留的空间只有 32 位宽，无论目标操作数有多大。

当目标操作数有 64 位宽时，这 32 位会进行_符号扩展_来填满它。操作数的高半部分会完全用立即数最高位的副本填充，所以用这种方式只能写出_32 位有符号整数_范围内的数字：

```x86asm
add rax, -1          ; the immediate is sign-extended, so all 64 bits of rax are affected
add rax, 2147483647  ; the largest immediate an instruction like this accepts
```

超出这个范围的数字不能用作立即数。这条规则有一个例外，就是`mov`：当目标操作数是寄存器时，它可以接受完整的 64 位立即数。如果需要 64 位立即数，就先用`mov`把它加载到寄存器里，再用这个寄存器：

```x86asm
mov rax, 3435973837           ; this works, mov can take a 64-bit immediate
mov rdx, 18446744073709551615 ; the largest immediate mov accepts
sub rdx, rax
```

注意，负的立即数和具有相同位表示的无符号数是等价的，汇编后得到的值完全相同：

```x86asm
mov rax, -1                   ; rax = 18446744073709551615
mov rax, 18446744073709551615 ; rax = -1
```

## 加法

两个数相加可以用`add`指令来计算。

还有一个单操作数指令`inc`，它把操作数里的值加 `1`：

```x86asm
inc rax ; rax = rax + 1
```

两个整数的加法，对于无符号数和有符号数的运算方式完全相同。

## 减法

两个整数相减用`sub`指令来完成。

还有一个单操作数指令`dec`，它把操作数里的值减去 `1`：

```x86asm
dec rax ; rax = rax - 1
```

两个整数的减法，对于无符号数和有符号数的运算方式也完全相同。

## 乘法

在 x86-64 中，有两个不同的指令可以用来做两个数之间的乘法。一般来说，无符号乘法使用`mul`指令，有符号乘法则使用`imul`。

`mul`指令采用下面这种单操作数形式，其中`src`是源操作数：

```x86asm
mul src
```

`imul`指令可以有单操作数、双操作数或三操作数形式：

```x86asm
imul src
imul dest, src
imul dest, src1, src2
```

### 单操作数乘法

单操作数形式的乘法会隐式地用到两个寄存器：`rax`和`rdx`。如果相乘的是两个 64 位数，那么结果的低 64 位会放在`rax`里，高 64 位会放在`rdx`里。

这通常写作`rdx:rax`，表示两个寄存器是配合使用的：

```x86asm
mul rcx ; rax = lower 64 bits of rax * rcx
        ; rdx = upper 64 bits of rax * rcx
```

其他操作数大小也是同样的道理。比如，如果相乘的是两个 32 位数，就会用到`eax`和`edx`。

例外情况是两个字节之间的乘法。

这种情况下，使用的不是`dl:al`，而是`ax`。`ax`的低半部分（`al`）会得到乘积的低 8 位，高半部分（`ah`）会得到高 8 位。

~~~~exercism/caution
乘法中隐式使用的寄存器，比如`rax`和`rdx`，总是会被覆盖。如果之后还要用到这些寄存器里的值，应该在运算前先保存好。
~~~~

### 双操作数乘法

`imul`的双操作数形式有一个显式的目标操作数，遵循通常的语法。它不会用到`rdx`。结果会被截断，以放进目标操作数。

```x86asm
imul r8, r9 ; r8 = lower 64 bits of r8 * r9
```

### 三操作数乘法

`imul`的三操作数形式有两个源操作数，其中第二个总是立即数（一个常数）。两个源操作数相乘，结果被截断后放进目标操作数：

```x86asm
imul r8, r9, 100 ; r8 = lower 64 bits of r9 * 100
```

注意，目标操作数并不参与乘法，它只是接收结果。

### 处理溢出

双操作数乘法和三操作数乘法都会把结果截断，以符合目标操作数的大小。单操作数乘法会保留完整的范围，但它通常被拆分到两个寄存器`rdx`和`rax`中。

所以，有时在乘法之前先把操作数加宽是很有用的，这样可以给完整的乘积在一个寄存器里留出空间。无符号操作数做零扩展，有符号操作数则做符号扩展：

```x86asm
movzx eax, di ; di and si hold unsigned 16-bit numbers
movzx ecx, si
mul ecx       ; the 32-bit product fits in eax, and edx is cleared
```

## 除法

和乘法一样，也有两个指令可以用来做两个数之间的除法。无符号除法使用`div`指令，有符号除法使用`idiv`。

这两个指令都只使用一个操作数：

```x86asm
div src
idiv src
```

16 位、32 位和 64 位除法分别使用`dx:ax`、`edx:eax`和`rdx:rax`作为被除数。在这些情况下，两个寄存器配合起来构成一个 2N 位的值，其中 N 是运算的位宽（16 位、32 位或 64 位）。然后用这个值除以源操作数。根据运算位宽的不同，商会写入`ax`、`eax`或`rax`，余数会写入`dx`、`edx`或`rdx`。

字节之间的除法比较特殊：使用的不是`dl:al`，而是`ax`。`ax`的低 8 位（`al`）会得到运算的商，高 8 位（`ah`）会得到余数。

注意，做除法之前，被除数中的所有位都应设置妥当。`rdx`中任何被置 1 的位（8 位除法中是`ah`），都会计入被除数这个值。

在无符号除法中，当要被除的值能放进低半部分时，高半部分应该清零。任何能把这些位清零的指令都可以。例如，在 32 位除法中，`mov edx, 0`会把高半部分清零。

在有符号除法中，则应该对值做符号扩展。有一些指令可以自动完成这个过程：`cbw`、`cwd`、`cdq`和`cqo`。第一个指令根据`al`的符号来设置`ah`中的位。其余的指令分别执行从`ax`到`dx`、从`eax`到`edx`，以及从`rax`到`rdx`的符号扩展。

~~~~exercism/caution
除法中隐式使用的寄存器，比如`rax`和`rdx`，总是会被覆盖。如果之后还要用到这些寄存器里的值，应该在除法前先保存好。
~~~~
