# 简介

到目前为止，教学大纲还没有怎么谈到类型，但类型在 Julia 中显然是存在的：

```julia-repl
julia> vals = (42, 4.3, π, "hello", 'Q')
(42, 4.3, π, "hello", 'Q')

julia> typeof(vals)
Tuple{Int64, Float64, Irrational{:π}, String, Char}
```

我们从未指定过类型，但 Julia 还是照样给它们分配了类型。

1. Julia 有`types`，这是它设计的核心。
2. Julia 通常能借助`Type Inference`“猜出”类型。

JIT 编译器会通读（所有）代码，查看变量是如何使用的，然后_推断_出一个与这种用法兼容的合适默认类型。

## 类型提升

之前的许多概念里都有把数值类型强制统一化的例子，从最简单的算术开始。

```julia-repl
julia> 2 + 1.3
3.3
```

我们让一个整数（Int64）和一个浮点数（Float64）相加，得到的是 Float64 结果。
类似地：

```julia-repl
julia> nums = (3, 4.1, 1//4)
(3, 4.1, 1//4)

julia> typeof(nums)
Tuple{Int64, Float64, Rational{Int64}}

julia> [nums...]
3-element Vector{Float64}:
 3.0
 4.1
 0.25
```

在上面的例子里，元组保留了每个元素的类型，但转换成向量后，所有元素都变成了统一的 Float64。

Julia 编译器知道哪些类型转换是可行的：整数转浮点数没问题，浮点数转整数会丢失精度，所以会抛出`InexactError`。
类型提升会把表达式中的所有值转换成一个共同的类型，这个类型足够通用，能兼容所有输入。

## 类型赋值

依靠类型推断来解决简单的教程练习没什么问题，但对于更大的程序，你很可能需要更精确的控制。

在大多数现代处理器上，整数默认是`Int64`。
我们在[`Numbers`][numbers]概念中看到，可以把一个值转换成某个非默认的类型。

```julia-repl
julia> x = Int16(42)
42

julia> typeof(x)
Int16
```

不过，变量`x`仍然可以被重新赋值为另一种类型：

```julia-repl
julia> x = "changed"
"changed"

julia> typeof(x)
String
```

这就是`type instability`，它：

- 在小型脚本里非常方便。
- 在较大的程序里则不利于性能和可靠性。

相反，我们可以用`::`运算符来设定`x`的类型：

```julia-repl
julia> y::Int16 = 42
42

julia> typeof(y)
Int16

julia> y = "changed"
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Int16
The function `convert` exists, but no method is defined for this combination of argument types.
```

现在`y`的类型是`Int16`，而且永远都会是。
这样，编译器就知道要为它预留多少字节，也能优化其余的代码，让它们依赖于一个稳定的类型。
在这一点上，这个变量和 C 这类静态类型语言中的变量大体相似。

## 类型断言

上文讲述的类型赋值，用在变量赋值的左侧，用来约束该变量的类型。

对一个值、或者任何能求值出某个值的东西使用`::`运算符，通常是一种_断言_：该值必须属于这个类型，否则就应该抛出错误。

```julia-repl
julia> 42::Number
42

julia> "two"::Number
ERROR: TypeError: in typeassert, expected Number, got a value of type String
```

常见用法是把它用在函数的返回值上，作为一种简单的最后检查，确认函数的表现符合预期。

## 类型层级

`Int64`、`Int16`、`String`、`Char`：这些类型究竟_从哪里来_。

在许多面向对象（OO）语言中，每个类型都是一个类，子类化把它们组织成类层级，而类方法定义了各种行为。

Java 和 Ruby 是这种模式的明显例子，但连 Python 在内部也类似。

***Julia 没有类。***

官方文档给出的原因是，面向对象的特性会干扰 JIT 编译器，影响运行时性能。

可是，看看这段代码：

```julia-repl
julia> y::Int16 = 42
42

julia> typeof(y)
Int16

julia> supertype(Int16)
Signed

julia> supertypes(Int16)
(Int16, Signed, Integer, Real, Number, Any)
```

补充一些细节：

- `Int16`是一个类型，我们可以创建这种类型的变量。
- `Int16`是`Signed`的子类型，`supertype()`函数向我们展示了这一点。
- 类型存在一个层级，向上依次经过`Integer`、`Real`、`Number`，到达最顶端的`Any`，而`subtypes()`会为我们列出层级的这一分支。

所有分支的终点都是`Any`，它的独特之处在于，它是自己的超类型。

```julia-repl
julia> supertypes(String)
(String, AbstractString, Any)

julia> supertype(Any)
Any
```

所以，Julia 没有`class`层级，但它_确实_有`type`层级。

最终我们会试着拆解它到底是怎么运作的，但在此之前还有很多东西值得先探索。

## 类型测试

我们可以用`typeof()`按常规方式测试相等性。

```julia-repl
julia> typeof(11)
Int64

julia> typeof(11) == Int64
true

julia> typeof(11) == Number
false
```

类型相等必须是精确的，因为这种比较方式完全不理解类型层级。

更灵活的是，`isa`会告诉我们一个值是否与比较对象类型相同、或者是它的子类型。
它既可以按函数形式使用，也可以按中缀形式使用。

```julia-repl
julia> 12 isa Int64
true

julia> 12 isa Number
true

julia> isa(12, Number)
true

julia> 12 isa String
false
```

注意，`isa`左侧接受的是`value`，而不是`type`。

用这种方式去比较两个_类型_会得到出乎意料的结果。
正确的运算符是`<:`，在之后的概念里我们还会经常见到它。

```julia-repl
julia> Int64 isa Number  ## Don't do this!
false

julia> Int64 <: Number
true
```

## 抽象类型与具体类型

我们看到，类型层级构成了一个树状结构（按照计算机科学的说法，根在顶部）。

树中的每一项都是一个`node`，它们可以分为几类：

1. 有子类型的节点称为`abstract`。
2. 没有子类型的叶子节点称为`concrete`。

```julia-repl
julia> subtypes(Integer)  # an abstract type
3-element Vector{Any}:
 Bool
 Signed
 Unsigned

julia> subtypes(Int64)  # a concrete type
Type[]
```

这是一个重要的区别，因为只有具体类型才能作为变量被`instantiated`。

```julia-repl
julia> a::Int16 = 42
42

julia> typeof(a)
Int16

julia> b::Integer = 42
42

julia> typeof(b)
Int64
```

注意，在这个例子里，使用抽象类型并不会产生错误信息，但编译器会创建一个合适的具体类型：`Int64`，而不是`Integer`。
至少它阻止了变量被赋值为非整数：

```julia-repl
julia> f::Integer = "hello"
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Integer
The function `convert` exists, but no method is defined for this combination of argument types.
```

因此，用抽象类型做类型赋值，是对变量类型的一种_约束_：它可以是（在上面的例子里）`Integer`的任意子类型。
这在编程语言的世界里颇为少见：它比 C 里的类型赋值更弱，又比近年 Python 版本里的类型提示更强。

函数`isabstracttype()`和`isconcretetype()`可以用来测试。
注意，它们并不只是彼此的否定：在后面的某个概念中我们会看到，有些类型既不是抽象的，也不是具体的。

```julia-repl
julia> isconcretetype(Integer), isabstracttype(Integer)
(false, true)

julia> isconcretetype(Int64), isabstracttype(Int64)
(true, false)

# Vector is neither
julia> isconcretetype(Vector), isabstracttype(Vector)
(false, false)
```
