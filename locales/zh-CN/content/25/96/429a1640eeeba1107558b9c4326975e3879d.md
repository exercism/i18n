# 关于

当一个函数把另一个函数（或闭包）作为形参接收时，传入的这个闭包默认是*非逃逸*的。
当闭包在函数本身已经返回之后才被调用时，就说这个闭包从函数中*逃逸*了。

这种情况通常出现在：

- 闭包被存入外部变量或属性。
- 闭包在某个操作完成后异步执行。
- 闭包从函数中返回，以便稍后调用。

来看下面这个例子：

```swift
func emptyKitchen(_ order: String) -> String {
    "Sorry, we're all out of \(order)."
}

func prepare(order: String, kitchen: (String) -> String) -> (String) -> String {
    func newKitchen(_ newOrder: String) -> String {
        if newOrder == order {
            return "One \(order) coming up!"
        } else {
            return kitchen(newOrder)
        }
    }
    return newKitchen
}
```

在这段代码中，`prepare`接收一个名为 `kitchen` 的函数，构造出一个调用 `kitchen` 的新函数 `newKitchen`，然后返回 `newKitchen`。
试着编译这段代码会报错：`Escaping local function captures non-escaping parameter 'kitchen'`。

因为 `newKitchen` 的生命周期比 `prepare` 长，所以 `kitchen` 闭包逃逸了。
要允许这种情况，给形参的类型加上 `@escaping` 特性。

```swift
func prepare(order: String, kitchen: @escaping (String) -> String) -> (String) -> String {
    func newKitchen(_ newOrder: String) -> String {
        if newOrder == order {
            return "One \(order) coming up!"
        } else {
            return kitchen(newOrder)
        }
    }
    return newKitchen
}

let restaurant = prepare(
    order: "sandwich",
    kitchen: prepare(
        order: "chicken",
        kitchen: prepare(order: "steak", kitchen: emptyKitchen)
    )
)

print(restaurant("pork chop"))
// Prints "Sorry, we're all out of pork chop."

print(restaurant("chicken"))
// Prints "One chicken coming up!"
```

`@escaping` 特性会告诉 Swift 编译器，这个闭包的生命周期会超过当前的函数调用，这样 Swift 才能正确管理内存和被捕获的引用。
