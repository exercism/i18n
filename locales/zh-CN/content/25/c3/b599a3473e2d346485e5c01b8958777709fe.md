# 引号入门

新学 bash 的程序员会反复听到这样一条建议：

> 给变量加上引号！

这是为什么呢？

当你展开一个变量（比如`$name`）时，几乎总是希望把变量的_值_当作一个单独的字符串（或数字）来使用。
你不会希望这个值被意外地当成两个或多个独立的字符串来处理。

## 引号

加引号是确保一段文本被当作单个单词处理的主要机制。
引号主要有两种类型。

### 双引号

双引号内部允许进行参数扩展、算术扩展和命令替换。

```bash
echo "This is bash version $BASH_VERSION"
```

在双引号包围的字符串里，可以通过在前面加反斜杠来嵌入一个字面意义的双引号。

```bash
echo "She said \"Let me teach you about bash.\""
```

### 单引号

单引号内部_不允许_任何扩展。

```bash
echo 'This is bash version $BASH_VERSION'
# ...^..................................^
# prints exactly: This is bash version $BASH_VERSION
```

在单引号包围的字符串里_无法_嵌入单引号。

## 引号的重要性

`echo $name`到底哪里不对呢？

当 shell 解析一行代码时，它会依次执行[好几种扩展][expansions]。
其中最后进行的两种扩展是_单词拆分_和_文件名扩展_。

### 单词拆分

参数扩展、命令替换或算术扩展的结果，_只要不是发生在双引号内部_，都可能被“单词拆分”。
shell 会取扩展后的结果，并按`$IFS`值中出现的任意字符序列来拆分它。
默认情况下，这个值是空格、制表符和换行符。

我们可以用一个 shell 循环看看它的实际效果：

```bash
sentence="The quick brown fox jumps."
i=0
for word in "$sentence"; do echo "$((++i)) $word"; done
# ..........^.........^
```
输出
```none
1 The quick brown fox jumps.
```

但不加引号时：

```bash
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
输出
```none
1 The
2 quick
3 brown
4 fox
5 jumps.
```

再看一个`$IFS`取不同值的例子：

```bash
csv="first,second,third"
IFS=","
for word in $csv; do echo "$word"; done
```
输出
```none
first
second
third
```

#### 关闭单词拆分

关闭单词拆分的一个技巧是把`$IFS`设为空字符串

```bash
sentence="The quick brown fox jumps."
IFS=    # or explicitly, IFS=""
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
输出
```none
1 The quick brown fox jumps.
```

不过，除非你也关闭文件名扩展，否则不建议让变量不加引号。
下面我们会看到怎么做。

### 文件名扩展

“Glob”模式用来简洁地表达匹配一组文件的模式。
比如，你可以用`*.md`匹配某个目录里所有的 Markdown 文件。
[Glob 模式][glob]自 Unix 诞生以来就存在了。

glob 通配符包括：

* `*` 匹配任意字符的零个或多个，
* `?` 匹配任意字符的恰好一个，
* `[...]` 匹配方括号内所列字符集合中的恰好一个字符。

   ~~~~exercism/advanced
   <details><summary>
   关于字符集有很多细节。
   点击这里查看。
   </summary>

    * `[abc]` 匹配 `a`、`b` 或 `c` 中的恰好一个字符。
        * 若要在表达式中包含一个字面意义的右方括号，把它放在左方括号之后的第一个位置（在可选的 `^` 之后）
            * `[][]` 是一个字符集，它能匹配右方括号或左方括号。
            * 或者用反斜杠转义：`[[\]]`
    * `[x-y]` 匹配从 `x` 到 `y` 这个_范围_内的恰好一个字符
        * 若要在字符集中包含一个字面意义的连字符，它必须是左方括号之后的第一个字符（在可选的 `^` 之后），或者是右方括号之前的最后一个字符。
            * `[-xy]` 或 `[xy-]` 都匹配 `-`、`x` 或 `y` 中的恰好一个字符
            * 或者用反斜杠转义：`[x\-y]`
        * 可以指定多个范围，例如 `[0-9A-Fa-f]` 匹配一个十六进制数字
    * `[^abc]` 匹配**不是** `a`、`b` 或 `c` 的恰好一个字符，
    * `[^x-y]` 匹配**不在**从 `x` 到 `y` 范围内的恰好一个字符
    * `[[:character_class:]]` 匹配属于名为“character_class”的字符类的一个字符
        * 可用的字符类有：
            * `lower`：小写字母
            * `upper`：大写字母
            * `alpha`：字母
            * `digit`：数字
            * `alnum`：字母和数字
            * `space`：空白字符
            * `blank`：水平空白（空格和制表符）
            * `xdigit`：十六进制数字
            * `word`：标识符中允许的字符（字母、数字、下划线）
            * `punct`：标点符号
            * `cntrl`：控制字符
            * `graph`：“可见”字符
            * `print`：可见字符加上空格
        * 它们可以组合：
            * `[[:alpha:]]` 类由 `[[:lower:][:upper:]]` 组成
            * `[[:alnum:]]` 类由 `[[:alpha:][:digit:]]` 组成
            * `[[:word:]]` 类由 `[[:alnum:]_]` 组成
            * 下划线（八进制 137）既是 `[[:word:]]` 也是 `[[:punct:]]`
            * `[[:graph:]]` 类由 `[[:alnum:][:punct:]]` 组成
            * `[[:print:]]` 类由 `[[:graph:] ]` 组成：只有空格（八进制 040），不含其他任何空白。

#### 遍历文件列表

你可以用 `for` 循环遍历文件列表

```bash
for file in *.csv; do
    do_something_with "$file"
done
```

注意变量`"$file"`加了引号。
glob 模式可能返回文件名里含空格的文件。
我们需要给变量加引号，好让`do_something_with`命令正好收到一个实参，也就是文件名。

#### Glob 模式不是正则表达式

Glob 模式**不是**正则表达式。

* 匹配恰好一个字符
   * 正则`.`
   * glob `?`
* 匹配零个或多个字符
   * 正则`.*`
   * glob `*`
        * glob 模式`.*`的意思是“匹配这样一个文件名：第一个字符是字面意义的点，后面跟着零个或多个任意字符”。
* 匹配一个或多个字符
   * 正则`.+`
   * glob `?*`
* 正则的字符集和 glob 的字符集表现方式相同。

#### 引号与文件名扩展

有时你会想抑制文件名扩展。
处理用户输入就是其中一种情况。
看看这段代码

```bash
read -p "Enter something: " user_input
echo $user_input
```

如果用户输入一个星号（`*`），会输出什么？
当前目录下的文件列表。
这多半不是你想要的。

另一个例子是把模式作为实参传给那些期望模式的程序。
`tr`程序常用于文本处理。要把一个变量的值转成小写，可以这样做

```bash
var="My Puppet"
echo "$var" | tr '[:upper:]' '[:lower:]'
```
输出
```none
my puppet
```

一个常见的错误是忘了给`tr`的实参加引号：`tr [:upper:] [:lower:]`

~~~~exercism/caution
为什么这是个问题？
不加引号的 glob 模式会展开成匹配到的文件列表。
假设使用你脚本的人在当前目录里有名为 `p`、`u` 和 `w` 的文件：

```bash
touch p u w
var="My Puppet"
echo "$var" | tr [:upper:] [:lower:]
```

这会导致一个错误！

不加引号的 `[:upper:]` 模式匹配 `:`、`u`、`p`、`e` 或 `r` 中的任意一个字符。
不加引号的 `[:lower:]` 模式匹配 `:`、`l`、`o`、`w`、`e` 或 `r` 中的任意一个字符。
Bash 为第一个模式匹配到文件 `p` 和 `u`，为第二个模式匹配到文件 `w`，于是 `tr` 被这样调用

```bash
echo "$var" | tr p u w
```

而这对 `tr` 来说实参个数不对。
~~~~

#### 关闭文件名扩展

你可以用[`set`][set]命令来关闭文件名扩展。

```bash
echo *      # prints a list of files
set -f      # disable filename expansion
echo *      # prints a literal asterisk
set +f      # enable filename expansion
```

#### 控制文件名扩展

内置命令[`shopt`][shopt]有几个设置可以控制文件名扩展的行为。
其中几个比较有意思：

* `shopt -s nocaseglob`：执行不区分大小写的匹配
* `shopt -s extglob`：启用扩展模式
* `shopt -s nullglob`：如果没有文件匹配，用空字符串替换模式。
   默认行为是把模式当作字面字符串留在原地。
