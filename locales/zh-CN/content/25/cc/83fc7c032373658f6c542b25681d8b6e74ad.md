# 说明补充

## 用`from_quote`写出生日期字面量

`DateOfBirth.from_quote`函数会把格式为`"YYYY-MM-DD"`的字符串解析成一个`DateOfBirth`。
这样就可以写出下面这样的代码：

```roc
birthdate : DateOfBirth
birthdate = "2019-01-20"
```

这段代码会在编译期隐式调用`DateOfBirth.from_quote("2019-01-20")`。
用这种方式（或者下面介绍的其他方式）在编译期运行代码，有可能加快程序的速度，因为运行时不再需要处理解析和数据校验。
此外，它还确保无效数据（比如格式不正确的日期）在编译期就被拒绝，而不是拖到运行时，让你的应用更健壮。
最后，它还让代码更美观易读。
例如，下面是本练习中的一个测试：

```roc
# multiple birthdates with one shared birthday
expect {
	shared_birthday(["1966-07-29", "1977-02-12", "2001-07-29", "1980-11-10"])
}
```

不过，读到这段代码的人可能会以为`shared_birthday`函数接收的是`List(Str)`，而实际上它接收的是`List(DateOfBirth)`。
这可能造成困惑和错误。
因此，你可能更偏爱下面这种稍长但更明确的写法：`"2019-01-20".DateOfBirth`，它同样会在编译期调用`from_quote`。

在你自己的程序里，你也许更愿意提供一个方便的构造函数，比如这个：

```roc
DateOfBirth := { year : I64, month : U8, day : U8 }.{
    from_ymd : I64, U8, U8 -> Try(DateOfBirth, [InvalidMonth, InvalidDay])
    from_ymd = |year, month, day| ...
}
```

你也可以在编译期调用这个构造函数，像这样：

```roc
Ok(birthdate) = DateOfBirth.from_ymd(2019, 1, 20)
```

注意：把这个定义放在顶层，会让它在编译期运行（因为这个函数是纯函数，输入在编译期就已知）。
在函数内部，你可以在运行时使用同一个构造函数。
