## 脚本用法

生成测试需要本地有一份 [problem-specifications][problem-specifications] 仓库的副本。脚本应当从`python`根目录运行，这样才能正确访问各个练习。

运行`bin/generate_tests.py --help`查看用法信息。


## 测试模板

测试模板支持 [Jinja2] 语法，并且可以从规范数据中获得以下上下文变量：
- `exercise`：练习的名称，用连字符连接（例如`two-fer`）
- `version`：规范数据的版本（例如`1.2.0`）
- `cases`：用例对象的列表，或者 `cases` 列表的列表。想了解你正在处理的练习的确切结构，请查阅`canonical-data.json`
- `has_error_case`：表示是否有任何测试用例期望抛出错误（例如`False`）
- `additional_cases`：结构与 `cases` 类似，但如果练习有`.meta/additional_tests.json`文件，则从中填充（示例见`exercises/word-count/.meta/additional_tests.json`）

此外，为了方便，还添加了以下模板过滤器：
- `to_snake`：把字符串转换成 snake_case（例如`{{ "CamelCaseString" | to_snake }}` -> `camel_case_string`）
- `camel_case`：把字符串转换成 CamelCase（例如`{{ "snake_case_string" | camel_case }}` -> `SnakeCaseString` ）
- `error_case`：检查某个测试用例是否期望抛出错误（例如`{% for case in cases%}{% if case is error_case}`）
- `regex_replace`：正则表达式字符串替换（例如`{{ "abc123" | regex_replace("\\d", "D") }}` -> `abcDDD`）


### 约定

- 高度重复的模板结构所用的通用宏定义在`config/generator_macros.j2`中。
  - 可以用下面这行导入它们：
  `{%- import "generator_macros.j2" as macros with context -%}`
- 所有测试模板都应以`{{ macros.footer() }}`结尾。
- 所有 Python 类名都应使用 CamelCase（例如`TwoFer`）。
  - 用`{{ "two-fer" | camel_case }}`转换
- 所有 Python 模块名和函数名都应使用 snake_case（例如`high_scores`、`personal_best`）。
  - 用`{{ "personalBest" | to_snake }}`转换
- 轨道专属测试定义在选项文件`.meta/additional_tests.json`中。该文件中定义的 JSON 对象应当只有一个键`cases`，其结构与`canonical-data.json`中的`cases`相同。
- 轨道专属测试在测试文件中应放在规范测试之后。
- 轨道专属测试在测试文件中应使用以下注释标记：
```
# Additional tests for this track
```


### 布局

大多数模板看起来都像这样：

```Jinja2
{%- import "generator_macros.j2" as macros with context -%}
{{ macros.header() }}

class {{ exercise | camel_case }}Test(unittest.TestCase):
    {% for case in cases -%}
    def test_{{ case["description"] | to_snake }}(self):
        value = {{ case["input"]["value"] }}
        expected = {{ case["expected"] }}
        self.assertEqual({{ case["property"] }}(value), expected)

    {% endfor %}

{{ macros.footer() }}
```


### 覆盖导入

在`macros.header()`中导入的名称，可以通过添加一个要导入的备用名称列表来覆盖（例如`clock`）：

```Jinja2
{{ macros.header(["Clock"])}}
```


### 忽略属性

偶尔可能需要过滤掉本轨道中不测试的属性。`header`宏还接受一个`ignore`参数（例如`high-scores`）：

```Jinja2
{{ macros.header(ignore=["scores"]) }}
```

## 创建模板

1. 为你要实现的练习创建`.meta/template.j2`，并在编辑器中打开它。
2. 把[示例布局](#Layout)复制粘贴到模板文件中，然后保存。
3. 对模板文件做相应的修改，直到它能生成有效的测试代码；输入名称和用例结构请参考该练习的`canonical-data.json`。
    - 使用[可用的宏](../config/generator_macros.j2)来避免重复编写标准化的部分。
    - 如果你是在为已有的练习实现模板，并不要求与现有测试文件的结构完全一致，但尽量减少差异会让 PR 审查对所有人来说顺利得多。
