# Here Document 简介

在 Bash 脚本中，“here document”（也叫 “heredoc”）可以把多行输入重定向到某个命令或程序，就好像你在终端里直接输入这些内容一样。
它是一种强大的工具，让你无需借助外部文件或复杂的字符串操作，就能在脚本中嵌入多行文本。

## 主要特性与语法

1. 分隔符：heredoc 以 `<<` 运算符开头，后面跟一个分隔词（通常也叫“标记”或“终止符”）。
   这个分隔符可以是你选定的任意单词，不过为了清晰，通常会用 `EOF`、`END` 或 `TEXT` 这类写法。
   想让代码更易读，也可以用带描述性的词作分隔符，比如 `END_INSTALLATION_INSTRUCTIONS`。

1. 内容：在开头的 `<< DELIMITER` 之后，写下你想重定向的内容。
   它可以有多行，可以是文本、代码或其他任何内容。

1. 终止：当分隔词再次出现，且独占一行、前后都没有空白字符时，heredoc 就结束了。

## 基本语法

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## 工作原理

* Bash 会读取从起始 `<< DELIMITER` 到结尾 `DELIMITER` 之间的所有行。
* Bash 把这些内容连接到命令的标准输入。
* 命令处理这些输入，就像它们是来自键盘的一样。

### 示例 1：简单的文本输出

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

输出：

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

在这个例子中：

* `cat` 是命令。
* `<< EOF` 启动 heredoc，并以 `EOF` 作为分隔符。
* 这三行文本就是内容。
* 单独一行的 `EOF` 结束了 heredoc。
* 随后 `cat` 输出它接收到的内容。

### 示例 2：配合 wc 使用（词数统计）

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

输出：

```plaintext
3
```

这里 `wc -l` 统计行数。
heredoc 把这三行作为输入提供给命令。

### 示例 3：把数据传递给脚本

脚本：

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

在交互式 bash 提示符下，用 heredoc 调用这个脚本：

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

输出：

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## 变体与高级特性

### 原样内容

Bash 会在 heredoc 内部进行变量展开、命令替换和算术展开。
从这个意义上说，heredoc 的行为就像双引号字符串。

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

输出：

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

如果分隔符被引号括起来（用单引号或双引号），这些展开就不会发生。
内容会按字面原样处理。
这就像单引号字符串一样。

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

输出：

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### 去掉开头的制表符

如果你用 `<<-`（末尾多一个连字符）代替 `<<`，Bash 会去掉 heredoc 每一行开头的_制表符_。
当你想在脚本里缩进 heredoc 内容，又不影响输出时，这很有用。

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

输出时，所有开头的制表符都被去掉了：

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
作者并不推荐这种用法。
虽然它能提高脚本的可读性，但是：

1. 很容易不小心把制表符换成空格（你的编辑器可能会自动这么做），而且
1. 空格和制表符之间的区别很难看出来。
~~~~

## 什么时候使用 Here Document

* 多行输入：需要向命令提供多行文本时。
* 配置文件：在脚本中嵌入一小段配置时。
* 生成代码：在脚本中即时生成代码时。
* 脚本化交互：为交互式程序模拟用户输入时。
* 避免使用外部文件：不想创建临时文件时。

一个典型的用法是提供帮助文本：

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## 可能的缺点

* 嵌入的文档太大会让代码更难读。
  把脚本和文档分开放在不同的文件里部署，可能会更好。
* Here Document 会打断代码的流畅性。
  你可能正处于一段嵌套很深的代码中，这时却想向程序传递一些文本。
  与周围的代码相比，heredoc 的缩进看起来会很突兀。

## Here String

和 here document 一样，_here string_（也叫 “herestring”）也能向命令提供输入。
不过，heredoc 提供的是一整块文本，而 herestring 提供的是单个字符串。
Here String 使用 `<<< "text"` 语法。

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

输出：

```plaintext
UPPER CASE THIS STRING
```

与 heredoc 不同，here string 不需要结束分隔符。

### 为什么要用 Here String？

可以用管道来代替 here string：

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

那为什么还要用 here string 呢？

设想一种情况：某个耗时很长的计算会输出一个字符串，而你想把这个结果分别提供给两个不同的命令。
如果用管道，就得把这个计算执行两遍：

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

更高效的做法是先把计算的输出保存下来（用命令替换），再用 here string 把输入分别提供给后面这两个命令：

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

这个例子在现实中有一个应用场景：

* 捕获 REST API 查询返回的 JSON 响应（该查询是分页的），
* 把 JSON 数据交给一个 jq 程序解析结果并输出到文件，然后
* 再把 JSON 数据交给另一个 jq 程序，用来确定下一次查询的 URL。

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

注意输出重定向的位置。
while 循环的所有输出都会被追加到 `data.csv` 文件中。

## 作为重定向的 Heredoc 与 Herestring

因为它们本质上只是重定向的几种形式，所以可以和其他重定向操作组合使用：

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## 小结

Here Document（也叫 “heredoc”）是管理 Bash 脚本中多行输入的一种灵活、方便的方式。
它们简化了在脚本中直接嵌入文本和数据的过程，让脚本更加自包含、更易读。

Here String（也叫 “herestring”）和 Here Document 类似，但语法更简单，也更动态。
