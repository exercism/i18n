# 测试

每个练习都会提供单元测试。
你来提供实现。
每个文件都会生成一个控制台可执行文件，用来运行这些测试。
运行测试可执行文件时，每个失败的测试都会打印一条消息，测试失败时还会报告非零退出状态码。

*注意*：每次构建项目时，你的代码都会接受测试套件的检验。
如果你的代码没有通过一个或多个测试，但本身是合法的 D 代码，它仍然会被编译。

完成每个练习的过程如下：

* 用`dub test`运行测试
  * 如果你选择不安装 DUB，可以改用`dmd source/*.d -de -w -main -unittest`，然后运行生成的可执行文件。
* 对每个单元测试：
  * 解决编译错误，让测试先真正地失败。
  * 只写刚好能让测试通过的实现。
  * 重构你的实现，提升可读性、减少重复，等等。
  * 启用下一个测试

*注意：* D 语言本身就支持单元测试，所以单元测试通常和实现放在同一个文件里。
单元测试在 main 的函数体之前运行，并在最终的可执行文件中通过**-unittest**编译选项启用。

## 解读单元测试的输出

如果所有测试都通过，测试输出大概是这样：

```none
$ dub test
             Generating test runner configuration 'dnd-character-test-library' for 'library' (library).
    Starting Performing "unittest" build using dmd for x86_64.
    Building dnd-character ~master: building configuration [dnd-character-test-library]
     Linking dnd-character-test-library
     Running dnd-character-test-library
1 modules passed unittests
```
