# 介绍

## 空引用

如果你用过其他编程语言（C/C++、Python、Java、Ruby、Lisp 等），那么你很可能遇到过`null`或`nil`。
这些语言用`null`或`nil`来表示某个变量没有值。
但这会让“不小心使用了指向`null`的变量”成为一个很容易犯（而且很常见）的错误。
可以想见，试图调用一个并不存在的函数，或者访问一个并不存在的值，都会引发各种各样的 bug 和崩溃。
`null`的创造者甚至把它称作自己的[“十亿美元错误”](https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/)。

## `Option`类型

为了避免这些问题，Rust 没有使用空引用。
不过，它仍然需要一种安全的方式来表示某个变量没有值。
这正是`Option`的用武之地。
与其让变量缺少值，Rust 变量可以使用`Option`枚举。
这个枚举有两个变体：`None`，相当于 Rust 里的 null；以及`Some(T)`，其中 T 是任意类型的值。

它看起来是这样的：

```rust
enum Option<T> {
    None,
    Some(T),
}
```

你可以把`Option`看作一层安全屏障，隔在你和空引用可能引发的问题之间，同时保留了它们在概念上的用处。

## 使用`Option`

把变量设为`None`相当直接：

```rust
let nothing: Option<u32> = None;  // Variable nothing is set to None
```

不过，如果你想让`Option`类型携带一个值，就不能直接把这个值赋给它。
`Option`类型的变量和（比方说）`i32`类型的变量并不等价。
你需要使用`Some`：

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Some(-4); // This will work
let another_right_way = Some(-4); // Compiler infers that this is Option<i32>
```

也正是出于这个原因，下面这段代码也不行：

```rust
let number = 47;
let option_number = Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

如果你想取出`Some`中包含的值，首先需要确认它确实存在：

```rust
let mut some_words = Some("choose something to say"); // some_words set to something

match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "Here, we will choose something to say"

some_words = None; // some_words now set to None

// exactly the same match block as above
match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "I've got nothing to say"
```

除了`match`，Rust 还提供了其他工具来检查和访问`Option`中包含的值，不过你现在应该已经很熟悉`match`了。

另外，你也可以把这看作一个示范，说明 Rust 为什么用`Option`而不是空引用。
重点在于，**你_必须_检查**`Option`变量究竟是`Some`（如果是，你就可以继续取出并使用其中包含的值），还是`None`。
除此之外的任何情况，你的程序都无法通过编译；编译器会保护你免受`null`的影响。
