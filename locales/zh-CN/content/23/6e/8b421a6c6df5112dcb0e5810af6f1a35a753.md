# 关于

[`Rational numbers`][rational] 是分数，分子和分母都是整数。

例如，我们可以把`2//3`存成精确的分数，而不是`Float64`的近似值`0.6666...`

这样做的好处是，有理数始终是精确的（只有[整数溢出][integer-overflow]这种极端情况除外），可以避免浮点数往往难以避免的舍入误差。

更多细节见 Julia 的[手册页面][julia-rational]。

有理数是一种相当简单的数值类型，行为基本符合你的预期。由于从早期版本起它就已经是 Julia 的标准类型，大多数函数都能像接受整数和浮点数那样接受有理数作为输入。

## 创建有理数

创建方式很简单，在两个整数之间使用`//`即可。

```julia-repl
julia> 3//4
3//4

julia> a = 3; b = 4;

julia> a//b
3//4
```

公因数会被自动约去，把分数化成[“最简形式”][lowest-terms]：能准确表示该分数的最小整数，且分母非负。

```julia-repl
julia> 5//15
1//3

julia> 5//-15
-1//3
```

无穷大的结果是被接受的，但不接受[`NaN`][NaN]。

```julia-repl
julia> 1//0
1//0

julia> float(1//0)
Inf

julia> 0//0
ERROR: ArgumentError: invalid rational: zero(Int64)//zero(Int64)
```

## 有理数的运算

通常的[`arithmetic operators`][operators] `+ - * / ^ %` 对有理数同样适用，基本和其他数值类型一样。

整数和其他`Rational`可以参与运算，结果仍是`Rational`。
表达式中只要含有`float`，结果就会是`float`，精度可能因此损失。

如果确实需要`float`，用`float()`函数把有理数转换过去即可。为了在漫长的计算中保持精度，先用有理数、最后再转成浮点数，是很常见的做法。

```julia-repl
julia> 3//4 + 1//3  # addition
13//12

julia> 3//4 * 1//3  # multiplication
1//4

julia> 3//4 / 1//3  # division
9//4

julia> 3//4 ^ 2  # exponentiation
3//16

julia> 3//4 + 5  # rational and int => rational
23//4

julia> 3//4 + 5.3  # rational and float => float
6.05

julia> float(3//4)  # casting
0.75
```

有理数和[复数][complex]也可以组合使用。复数会在[另一个概念][complex-concept]中讨论。

## 其他运算

在 Julia 中，有理数就是普通的数字。编译器通常会在需要时自动转换类型。

不过要注意，只有当分数具有有限小数表示时，直接比较才按预期工作：

```julia-repl
julia> 3//4 == 0.75
true

julia> 3//4 < 0.74
false
```

但除此之外，`Rational`要先转成`Float`再比较：

```julia-repl
julia> 1//3 == 1/3
false

julia> float(1//3) == 1/3
true
```

数学函数接受有理数作为输入，但结果可能是浮点数：

```julia-repl
julia> sqrt(9//16)
0.75
```
