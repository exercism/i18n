# 关于

[`interfaces`][interfaces] 是把类的使用与其实现[解耦][wiki-loose-coupling]的主要手段。解耦之后，实现更容易维护，也有助于支持类型安全的泛型行为。

接口的语法与类或结构体类似，不同之处在于方法和属性只写出签名，不提供方法体。

```csharp
public interface ILanguage
{
    string Speak();
}

public interface IItalianLanguage : ILanguage
{
    string Speak();
    string SpeakItalian();
}

public interface IScriptConverter
{
    string Version { get; set; }
    string ConvertCyrillicToLatin(string cyrillic);
}
```

实现该接口的类或结构体必须实现接口定义的所有操作。

接口通常用于完成下面的一项或多项任务：

- 让使用代码可以把多个不同的类当作同一种类型来统一处理。这时接口扮演的角色和基类相同
- 为某个特定目的公开一部分功能（例如 `IComparable<T>`），或者
- 公开一个类的公共 API，让多个实现可以共存。其中一个例子就是[测试替身][wiki-test-double]

```csharp
public class ItalianTraveller : IItalianLanguage
{
    public string Speak()
    {
        return "Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class ItalianTravellerV2 : IItalianLanguage
{
    public string Speak()
    {
        return "migliorata - Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class FrenchTraveller : ILanguage
{
    public string Speak()
    {
        return "Ça va?";
    }
}

public class RussianTraveller : ILanguage, IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Speak()
    {
        return "Привет мир";
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}

public class DocumentTranslator : IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Translate(string russian)
    {
        throw new NotImplementedException();
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}
```

使用上述接口和类的代码可以：

- 以相同的方式对待所有说话者，不管他们说的是哪种语言。
- 让负责文字转写的某个子系统在运行时不必关心自己处理的究竟是什么具体类型。
- 对意大利语说话者的改动毫不知情；如果类代码和使用者代码由不同团队维护，这会很方便。

接口被广泛用于支持测试，因为它们便于进行[模拟][so-mocking-interfaces]。

想了解接口中可以包含哪些类型的成员，请参阅这篇[文章][dt-interfaces]。

接口可以继承其他接口。

接口的成员默认是 public。

接口可以包含嵌套类型，例如 `const` 字面量、`enums`、`delegates`、`classes` 和 `structs`。这时接口的作用和类、结构体一样，充当[命名空间][wiki-namespaces]，行为与语法完全相同。

C# 在设计上不支持多继承，但借助接口可以实现某种形式的多继承。

此外，[多态可以通过接口实现][interface-polymorphism]这一理念，正是整个接口机制的基础。

## 显式接口实现

有时两个不同的接口会共用相同的方法名和签名。为了给这些方法分别提供不同的实现，C# 提供了[接口的显式实现][explicit-implementation]。注意，要使用接口的某个特定实现，需要把引用该对象的表达式转换成那个接口的类型。赋值、强制类型转换或作为实参传入都可以做到这一点。

```csharp
public interface IFoo
{
    void X();
}

public interface IBar
{
    void X();
}

public class Census : IFoo, IBar
{
    void IFoo.X()
    {
        Console.Write("This is from Foo");
    }

    void IBar.X()
    {
        Console.Write("This is from Bar");
    }
}

public class User
{
    public void Use()
    {
        IFoo foo = new Census();
        IBar bar = new Census();
        foo.X();
        // => "This is from Foo"
        bar.X();
        // => "This is from Bar"
    }
}
```

有若干种适用场景：

- 不同领域发生冲突（如上例所示），方法签名完全相同。
- 方法名相同但返回类型不同：如果你实现自己的集合类，可能会发现需要为旧版的 `IEnumerable.GetEnumerator()` 提供一个显式接口，并与 `IEnumerable<T>.GetEnuerator()` 并列。你可能永远用不到这样的接口，但编译器可能会坚持要求。
- 接口之间没有名称冲突，但实现类希望把这个名称用于某个相关用途：`IFormattable` 有一个 `ToString()` 方法，它除了接收 `IFormatProvider` 类型的参数外，还接收一个*格式类型*参数。基类库（BCL）中的 `FormattableString` 这类类实现了该接口，以确保能被接收 `IFormattable` 的例程使用；但它的主要版本 `ToString(IFormatProvider)` 省略*格式类型*参数会更有表达力，因为该参数在实现中并不使用，反而会让 API 使用者困惑。

## 默认实现

C# 8 解决了一个长期困扰 API 的烦人问题。如果为了给新的实现增强功能而向接口添加方法，那么就必须修改该接口所有已有的实现，让它们符合 API 约定，即使这些实现本身并没有任何特定的行为。现在 C# 允许把*默认方法*作为接口的一部分提供（Java 开发者对此会很熟悉）。而在以前，发生这类改动时，会有一个接口的*第 2 版*与原始版本并存。

这篇[文章][dt-interfaces]是很好的接口入门读物，重点介绍了*默认实现*以及其他配套的新特性，例如 `static`、`private` 和 `virtual` 成员。
