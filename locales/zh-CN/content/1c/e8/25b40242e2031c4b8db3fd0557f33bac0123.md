# 关于

_“日期和时间是我们教小孩子的东西。能有多难？”_

很多程序员都犯过这个错误，随之而来的经历往往会对他们的健康和幸福造成不良影响。

任何用日期和时间做正经编程的人，至少都应该做好理解并缓解潜在问题的准备。

本文会尝试概述 Julia 如何处理日期和时间，不过要了解更深入的内容，还是得查阅[手册][Dates]。还有一本 [Wikibook][Wikibook]，有些读者可能觉得它的解释更清楚，其中还配有一张很有用的类型层级[图][type-hierarchy]。

## `Dates`模块

大部分基础功能都在`Dates`里，这个模块会随默认安装一起提供，但不属于标准库。

使用这个模块有两种方式：

1. 添加`import Dates`，然后在所有函数调用前都加上`Dates.`
2. 添加`using Dates`，它会把整个模块引入当前命名空间（_少数有问题的名字除外_）。

```julia-repl
# option 1
julia> import Dates

julia> Dates.now()
2025-06-21T16:02:39.080

julia> now()  # wrong: need to include `Dates.` after an import
ERROR: UndefVarError: `now` not defined in `Main`


# option 2
julia> using Dates

julia> now()  # functions are now in the namespace
2025-06-21T16:03:04.161
```

`Dates`模块庞大而复杂，但它提供四类主要功能：

- `Dates.Date`，包含日、月、年，但不含一天中的时间。
- `Dates.Time`，包含一天中的时间，精确到纳秒，但不含日期。
- `Dates.DateTime`，把日期和时间组合起来，精确到毫秒。
- `Dates.Period`，处理时间或日期的间隔。

请注意，`DateTime`通常_不_包含时区信息（Python 会把它称为“naive”的 datetime）。一个例外是`now()`，它从你的系统时钟获取本地时间，必要时可以把它转换成 UTC。

其他时区计算需要`TimeZones.jl`包，它不属于默认安装。截至 2025 年 6 月，Exercism 上还无法使用它，但将来可能会加入。

最常见的需求大概是：

- 解析某种合适的输入格式，构造出一个`Dates`类型。
- 从`Dates`类型中取出需要的数字格式或字符串格式。
- 给`Date`、`Time`或`DateTime`值加上一个偏移量。
- 计算两个这样的值之间的间隔。
- 获取当前日期（用`today()`）和/或时间（用`now()`）。

~~~~exercism/note
为了减少视觉干扰，本文剩下的大部分示例代码都假定已经在使用`using Dates`，并且在函数调用中省略了模块名`Dates.`。
~~~~

### 日期和时间格式

写日期和时间的方式有很多，而且往往因文化而异。像“7/6/23”这样全是数字的日期有歧义、让人困惑，还在跨国公司里造成过许多代价高昂的错误（_作者说这是他惨痛的亲身经历_）。

国际标准定义在 [`ISO 8601`][ISO8601] 中，它有两个主要优点：

- 解析又快又没有歧义。
- 排序很容易，因为日期时间可以当作普通文本按字母顺序排序。

前面的例子中我们看到`Date.now()`返回了`2025-06-21T16:03:04.161`。

它由几个部分组成：

- `YYYY-MM-DD` 是日期部分。
- `hh:mm:ss` 是时间部分。
- 小数点后可选地跟毫秒（或更小的单位）。

其他字符串格式会在后面的小节讨论。

## 日期

`Dates.Date`是一个相对简单的、只表示日期的类型，它不理解时间，也不理解时区。

```julia-repl
# constructor with year, month, day arguments
julia> date1 = Date(2025, 06, 23)
2025-06-23

# constructor with ISO 8601 string
julia> date2 = Date("2025-06-23")
2025-06-23

julia> date1 == date2
true

julia> typeof(date1)
Date
```

有一些访问函数可以获取日期的各个组成部分，它们成对出现，靠大小写区分。

```julia-repl
# lowercase returns an integer
julia> month(date1)
6

julia> typeof(month(date1))
Int64

# Propercase returns a Period type
julia> Month(date1)
6 months

julia> typeof(Month(date1))
Month

# various compound methods are also available, returning a tuple
julia> monthday(date1)
(6, 23)
```

### 查询函数

有各种各样的[查询函数][query-func]，它们对日历有一定理解。下面这个例子只展示了其中几个。

```julia-repl
julia> date1
2025-06-23

julia> dayofweek(date1) # 1 = Monday, 7 = Sunday
1

julia> dayname(date1)
"Monday"

julia> daysinmonth(date1)
30

julia> isleapyear(date1)
false

julia> lastdayofmonth(date1)
2025-06-30
```

## 时间

`Dates.Time`是只表示时间的基础类型。它不理解日期：到了午夜，时间会自动回绕到`Time(0, 0, 0)`。

完整的构造函数格式是`Time(hour, min, sec, millisec, microsec)`，或者等价的 ISO 8601 写法。

所有参数都是可选的，默认值为`0`。

```julia-repl
julia> Time(14, 57, 25, 142)
14:57:25.142

julia> Time(14, 57, 25, 142, 32)`
14:57:25.142032

julia> Time("14:57:25.142")
14:57:25.142
```

和`Date`一样，各个部分都可以用访问函数获取：

```julia-repl
julia> minute(t) # => integer
57

julia> Minute(t) # => Period
57 minutes
```

## 日期时间

`Dates.DateTime`结合了`Date`和`Time`类型的大部分特性。

在这三个类中，它是最灵活的，不过时间精度只到毫秒（`Time`可以精确到纳秒）。

```julia-repl
julia> dt1 = DateTime(2025, 6, 23, 14, 57, 25, 142)
2025-06-23T14:57:25.142

# date1 and t were defined in previous examples
julia> dt2 = DateTime(date1, t)
2025-06-23T14:57:25.142
```

年、月、日参数默认值为`1`，时间参数默认值都是`0`。

要记住所有这些参数的位置可能有点难，所以 ISO 格式可能更好用。

或者，也可以像上面的例子那样，用`Date`和`Time`构造出一个`DateTime`。

## 周期

每个日期/时间组成部分都有自己的 [`Period`][period] 类型，从`Year`一直到`Nanosecond`，表示一段时间隔。它们在算术运算中特别有用。

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Year(21)
21 years

julia> Second(61)
61 seconds

julia> dt1 + Year(21) - Second(61)
2046-06-23T14:56:24.142

julia> Date(2025, 07, 03) - Date(2025, 04, 25)
69 days
```

还有一个 [`CompoundPeriod`][compound-period] 类型，可以组合多个`Period`类型。奇怪的是，目前它需要写出模块名才能避免命名空间错误（_感觉像是个 bug_）。

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> offset = Dates.CompoundPeriod(Year(21), Second(-61))
21 years, -61 seconds

julia> dt1 + offset
2046-06-23T14:56:24.142
```

相减日期/时间时，得到的周期会以天（对日期而言）或纳秒（对时间而言）给出。把它们[`canonicalize`][canonicalize]成`CompoundPeriod`可能会更方便。

```julia-repl
julia> diff = Time(23, 14, 00) - Time(1, 23, 52)
78608000000000 nanoseconds

julia> canonicalize(diff)
21 hours, 50 minutes, 8 seconds

julia> typeof(canonicalize(diff))
Dates.CompoundPeriod
```

处理`Period`类型时，Julia 会尽量聪明地应对月份长度之类的日历不规则情况，必要时进行舍入。

```julia-repl
# February has fewer days than January
julia> Date(2025, 1, 31) + Month(1) 
2025-02-28
```

## [舍入][rounding]

`floor`、`ceil`和`round`这几个函数在处理整数/浮点数时应该很熟悉了，它们对日期和时间也同样适用。把要舍入到的`Period`指定为第二个参数。

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> floor(dt1, Minute(15))
2025-06-23T14:45:00

julia> ceil(dt1, Minute(30))
2025-06-23T15:00:00

julia> ceil(dt1, Month(1))
2025-07-01T00:00:00
```

## 字符串表示

前面提到过 ISO 8601 标准，它是 Julia 在格式化或解析字符串时默认的日期/时间表示方式。

显然，还有很多其他格式被频繁使用，而且常常带有文化特色。为了处理这些格式，Julia 提供了`DateFormat`类型，可以用任意复杂的格式字符串来构造。

```julia-repl
# dateformat"" string syntax
julia> dtfmt = dateformat"d/m/y"
dateformat"d/m/y"

julia> typeof(dtfmt)
DateFormat{Symbol("d/m/y"), Tuple{Dates.DatePart{'d'}, Dates.Delim{Char, 1}, Dates.DatePart{'m'}, Dates.Delim{Char, 1}, Dates.DatePart{'y'}}}

# DateFormat constructor
julia> DateFormat("d/m/y")
dateformat"d/m/y"
```

上面的例子非常简单，只是一个欧洲常见的日/月/年格式的日期。这里展示了两种语法变体，但结果完全相同。

然后就可以用`DateFormat`来解析任何合适的字符串：

```julia-repl
julia> DateTime("14/7/2023", dtfmt)
2023-07-14T00:00:00
```

创建`DateFormat`有不小的开销，所以只做一次这一步（就像这里用`dtfmt`那样），在遍历大量日期/时间字符串时对性能很有帮助。

格式可以比这复杂得多，详情请查阅[手册][dateformat]。

熟悉其他语言的人可能会注意到，它和有几十年历史的`strptime`和`strftime`函数有相似之处。Julia 版本借鉴了这份历史遗产，但力求更简洁、更灵活。

同一个`DateFormat`也可以用来把日期/时间输出成任何想要的字符串格式，只需使用[`Dates.format()`][format]函数。

遗憾的是，`format`似乎存在命名空间冲突（至少在 Julia 1.11.5 中是这样），所以即使在`using Dates`之后，最好也还是加上`Dates.`前缀。

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Dates.format(dt1, dateformat"e, u d")
"Mon, Jun 23"
```

如[文档][wiki-format]所述，`"e, u d"`给出星期几和月份的缩写文本表示。

文本表示默认使用英语。也可以添加其他语言，不过目前的支持还不算理想。
