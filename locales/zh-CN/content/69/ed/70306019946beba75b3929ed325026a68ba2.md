# 说明

你在为汽车零件工厂车间里的数据系统编写代码。
发动机和底盘部件会经过一系列加工工位。
每个工位都会产生测量数据，这些数据必须在下一阶段开始前进行合并、比较、校准或归一化。
你在这里实现的函数，每个工位对应一个。

~~~~exercism/note
本练习中的计算应使用 SIMD 指令完成，而不是标量运算。
~~~~

## 1. 合并两条产线的产量

工厂车间里运行着两条并行的装配线。
每个班次结束时，两条产线都会报告 4 个零件箱的产量，数值为单精度浮点数。
主管的仪表盘会显示每个零件箱的合计产量，因此要把两份报告按零件箱逐一相加。
这三个缓冲区都由报表系统管理，并且始终按 16 字节对齐。

定义一个函数`sum_yields`，它接收`line_a`和`line_b`中每个零件箱的产量，把按箱求和的结果写入`result`。
形参按顺序如下：

1. `line_a`：16 字节对齐的内存地址，存放 4 个 32 位浮点数
2. `line_b`：16 字节对齐的内存地址，存放 4 个 32 位浮点数
3. `result`：16 字节对齐的内存地址，函数会把 4 个 32 位浮点数写入这里

这个函数没有返回值，结果存放在传入的缓冲区（`result`）中：

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. 计算缩放后的偏差

在工序之间，一个采样工位会测量已加工的零件，并把它们与目标尺寸进行比较。
测量值会从精密量具流入一个始终 16 字节对齐的缓冲区。
目标值来自工单包，它不保证对齐。
偏差在传给下游的公差检查器之前，会先乘以每个轴的灵敏度系数。
在这个阶段，下游检查器直接从 SIMD 寄存器读取偏差，而不是从内存中读取。

定义一个函数`scaled_deviation`，它接收`measured`、`target`和`sensitivity`，把缩放后的偏差写入`result`。
形参按顺序如下：

1. `measured`：16 字节对齐的内存地址，存放 2 个 64 位浮点数
2. `target`：内存地址，存放 2 个 64 位浮点数（不保证对齐）
3. `sensitivity`：内存地址，存放 2 个 64 位浮点数（不保证对齐）
4. `result`：缓冲区的内存地址，函数会把 2 个 64 位浮点数写入其中（不保证对齐）

缩放后的偏差为`(measured - target) * sensitivity`，逐通道计算。

这个函数没有返回值，结果以一对 64 位浮点数的形式存放在传入的缓冲区（`result`）中。

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. 校准一批零件

在零件进入最终检验区之前，一批 4 个零件的尺寸读数会被重新缩放到双精度，并针对已知的温度漂移进行修正。

这 4 个原始读数以单精度浮点数的形式传入。
对于每一行 2 个读数，校准过程会计算`reference / (raw - offset)`，然后把结果乘以固定的换算系数`0.5`。

注意，对于这一批中的两行，reference 和 offset 都相同。
换算系数在每次校准时都相同，所以不用把它作为形参接收，而应该在内存中把它声明为一个打包的 16 字节常量。

定义一个函数`calibrate_batch`，它接收一批`raw`、`reference`、`offset`和一个`result`缓冲区，把校准后的值写入`result`。
形参按顺序如下：

1. `raw`：内存地址，存放 4 个 32 位浮点数（不保证对齐）
2. `reference`：16 字节对齐的内存地址，存放 2 个 64 位浮点数
3. `offset`：16 字节对齐的内存地址，存放 2 个 64 位浮点数
4. `result`：16 字节对齐的内存地址，函数会把 4 个 64 位浮点数写入这里（共 32 字节）

对于这一批中的两行，函数应该分别执行以下操作：

1. 把该行中 2 个单精度原始值转换为双精度。
2. 从转换后的这对值中减去`offset`。
3. 用`reference`除以得到的结果。
4. 把每个 64 位浮点数逐通道乘以固定的换算系数`0.5`。
5. 把这 2 个 64 位浮点数存入`result`对应的 16 字节中。

这个函数没有返回值，结果存放在传入的缓冲区（`result`）中：

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. 沿产线归一化分数

在产线的末端，每个零件都有一个质量分数，在上报之前需要进行归一化。
每个分数先乘以它自己对应的每个零件的增益，再除以每个轴的生产缩放系数。
增益缓冲区为每个零件保存一个增益。

生产缩放系数对于整轮运行都是相同的，通过一个存放 2 个 64 位浮点数的内存地址传入。
分数是**原地**更新的：原来存放原始分数的同一个缓冲区，现在存放归一化后的分数。

定义一个函数`normalize_scores`，它接收`scores`数组、`gains`数组、`scale`和计数`n`，原地归一化这些分数。
形参按顺序如下：

1. `scores`：16 字节对齐的内存地址，存放`n`个 64 位浮点数（原地修改）
2. `gains`：16 字节对齐的内存地址，存放`n`个 64 位浮点数
3. `scale`：16 字节对齐的内存地址，存放 2 个 64 位浮点数
4. `n`：一个 64 位正偶数（最小为`2`），需要归一化的分数个数

缩放系数的两个通道分别作用于每一对中的两个元素。
第一个通道缩放每一对中的第一个元素（偶数位置上的通道），第二个通道缩放第二个元素（奇数位置上的通道）。
每个分数先乘以对应的增益，再除以相应的缩放通道：`score * gain / scale_lane`。

这个函数没有返回值，结果存放在输入缓冲区（`scores`）中，位置与被归一化的那个`score`相同：

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
