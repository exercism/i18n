# 简介

**单指令多数据（SIMD）** 是一种硬件层面的并行方式。CPU 会同时对多个元素执行相同的计算。

举个例子，考虑把两个包含四个 32 位浮点数的数组按元素相加。标量实现会发出四条独立的 `addss` 指令，每个元素一条。SIMD 实现则用一条 `addps` 并行完成全部四次加法。也就是说，每条指令完成的工作量变成了四倍。

在 x86-64 汇编中，SIMD 指令通常通过 `xmm` 寄存器来执行。其中一些指令处理整数，另一些处理浮点数。

这些整数或浮点数被称为**打包**数据。每一个都占据同一个寄存器中的一块空间，称为**通道**。SIMD 指令通常会并行地操作两个源操作数中处于同一通道位置的值。每次运算的结果会存入目标操作数中同一位置的通道。

通道并不是硬性限制，而是每条指令对一串字节的解读方式。一个 128 位的操作数包含 16 个字节。根据指令的不同，这些字节可以被解读为 16 个 _1 字节_ 通道、8 个 _2 字节_ 通道、4 个 _4 字节_ 通道、2 个 _8 字节_ 通道，甚至单个 _16 字节_ 通道。

例如，指令 `addps` 会把打包的单精度（4 字节）浮点数相加。对于这条指令来说，操作数中每个 4 字节的数据块都是一个不同的通道。在一个 128 位宽（16 字节）的操作数中：

| 操作数     | 第 4 个通道 | 第 3 个通道 | 第 2 个通道 | 第 1 个通道 |
|:-----------:|:--------:|:--------:|:--------:|:--------:|
| 源 1    |  1.5     |  2.1     | 6.2      | 3.4      |
|    +        |  +       |  +       | +        | +        |
| 源 2    |  0.5     |  8.26    | -13.4    | 22.9     |
|    =        |  =       |  =       | =        | =        |
| 结果      |  2.0     |  10.36   | -7.2     | 26.3     |

另一方面，对于 `mulpd` 来说，一个 128 位操作数会被解读为只有 2 个通道。这是因为该指令对双精度（8 字节）数值执行打包乘法：

| 操作数     | 第 2 个通道 | 第 1 个通道 |
|:-----------:|:--------:|:--------:|
| 源 1    |  4.2     |  2.1     |
|    *        |  *       |  *       |
| 源 2    |  1.0     |  92.4    |
|    =        |  =       |  =       |
| 结果      |  4.2     |  194.04  |

在本概念中，我们会重点介绍一小部分 SIMD 指令。它们使用 `xmm` 寄存器来操作打包的浮点数。

## 浮点 SIMD 指令

一般来说，操作浮点数的 SIMD 指令采用双操作数形式。它们的名字遵循一定的结构：

1. 所执行的操作，与其非 SIMD（也称为_标量_）版本同名（例如 `add`、`mul` 等）。
2. 一个后缀 `p`，表示该指令操作的是_打包_数据，位置与原先的 `s`（表示_标量_数据）相同。
3. 一个表示每个通道大小的后缀，语义与其非 SIMD 版本相同（`s` 表示单精度，`d` 表示双精度）。

因此，打包版本的名字就是把标量版本助记符中间的 `s`（标量）替换成 `p`（打包）得到的。操作名和大小后缀保持不变：

| 标量  | 打包  | 含义                                |
|---------|---------|----------------------------------------|
| `addss` | `addps` | 加法，单精度（32 位通道）   |
| `addsd` | `addpd` | 加法，双精度（64 位通道）   |
| `mulss` | `mulps` | 乘法，单精度             |
| `mulsd` | `mulpd` | 乘法，双精度             |

### 算术运算

算术 SIMD 指令遵循上面的规则。来看几个例子：

```x86asm
addps xmm0, xmm1 ; xmm0 = xmm0 + xmm1 (each 32-bit float at the same position)
subpd xmm2, xmm3 ; xmm2 = xmm2 - xmm3 (each 64-bit float at the same position)
mulps xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (each 32-bit float at the same position)
divpd xmm6, xmm7 ; xmm6 = xmm6 / xmm7 (each 64-bit float at the same position)
```

### 精度之间的转换

还有一些 SIMD 指令用于在打包的单精度浮点数和打包的双精度浮点数之间转换。它们遵循相同的命名规则，把表示_标量_的 `s` 换成表示_打包_的 `p`：

| 标量     | 打包     | 含义                                      |
|------------|------------|----------------------------------------------|
| `cvtss2sd` | `cvtps2pd` | 把单精度转换为双精度 |
| `cvtsd2ss` | `cvtpd2ps` | 把双精度转换为单精度 |

这些指令正好说明了前面提到的一点：通道是一种解读方式，而不是硬性限制。源操作数和目标操作数的通道大小不同，因此通道数量也不同。

对于 `cvtps2pd`，源（`ps`）有 4 个单精度通道，目标（`pd`）有 2 个双精度通道。只会读取源的低 2 个通道，高 2 个通道被忽略：

| 操作数              | 第 4 个通道 | 第 3 个通道 | 第 2 个通道 | 第 1 个通道 |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| 作为 `ps` 的源       | 忽略  | 忽略  | 2.5      | 1.5      |
| 作为 `pd` 的目标  |          |          | 2.5      | 1.5      |

对于 `cvtpd2ps`，源（`pd`）有 2 个双精度通道，目标（`ps`）有 4 个单精度通道。源的两个通道都会被转换，并写入目标的低 2 个通道。目标的高 2 个通道会被置零：

| 操作数              | 第 4 个通道 | 第 3 个通道 | 第 2 个通道 | 第 1 个通道 |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| 作为 `pd` 的源       |          |          | 4.0      | 3.0      |
| 作为 `ps` 的目标  | 0        | 0        | 4.0      | 3.0      |

一些例子：

```x86asm
cvtps2pd xmm0, xmm1 ; xmm0 = xmm1 as 2 doubles (low 2 lanes of xmm1 are read)
cvtpd2ps xmm0, xmm1 ; xmm0 = xmm1 as 2 floats (in low 2 lanes; upper 2 zeroed)
```

### 内存操作数

上面这些 SIMD 指令展示的都是寄存器到寄存器的操作数。它们也可以把内存操作数作为源（但**不能**作为目标）。

从内存读取多少字节由指令决定。例如，`addps` 读取 16 字节（4 个单精度浮点数）。相比之下，`cvtps2pd` 只读取 8 字节（2 个单精度浮点数），因为它需要的输入就只有这么多。

```x86asm
addps    xmm0, [rsi]      ; xmm0 = xmm0 + 4 floats at [rsi]
mulpd    xmm1, [rsi + 16] ; xmm1 = xmm1 * 2 doubles at [rsi + 16]
cvtps2pd xmm2, [rsi + 8]  ; xmm2 = (2 floats at [rsi + 8]) converted to 2 doubles
```

当内存操作数为 16 字节宽时，它必须是_16 字节对齐_的。对齐的内存位置，其地址是操作大小（这里是 16 字节）的整数倍。

要声明对齐的内存，可以在 .data 和 .rodata 段使用 `align` 指示符，或者在 .bss 段使用 `alignb`：

```x86asm
section .rodata
align 16
mem1: dd 4.0, 3.5, 2.0, -1.0

section .data
align 16
mem2: dq 6.0, 2.1

section .bss
alignb 16
mem3: resb 16

section .text
fn:
    movaps xmm0, oword [rel mem1] ; loads 4 packed 32-bit floats in xmm0
    movapd xmm1, oword [rel mem2] ; loads 2 packed 64-bit floats in xmm1
    movaps oword [rel mem3], xmm0 ; stores 4 packed 32-bit floats in mem3
    ret
```

小于 16 字节的内存操作数没有对齐要求，比如 `cvtps2pd` 的 8 字节源操作数。

### 加载与存储数值

有四条指令用于复制 128 位的打包浮点数。它们在两个 `xmm` 寄存器之间，或者在一个 `xmm` 寄存器和一个内存位置之间操作：

| 指令 | 说明                                                                       |
|-------------|-----------------------------------------------------------------------------------|
| `movaps`    | 在_对齐_的内存位置与寄存器之间复制打包的单精度数据     |
| `movups`    | 在_未对齐_的内存位置与寄存器之间复制打包的单精度数据   |
| `movapd`    | 在_对齐_的内存位置与寄存器之间复制打包的双精度数据    |
| `movupd`    | 在_未对齐_的内存位置与寄存器之间复制打包的双精度数据   |

这些指令都可以用来在两个 `xmm` 寄存器之间复制数值。

如果操作涉及内存位置，`movaps` 和 `movapd` 就要求它必须_对齐_。如果给出未对齐的地址，`movaps` 和 `movapd` 会触发错误。它们同时也是一种安全检查，确认你的数据布局就是你以为的样子。

另一方面，`movups` 和 `movupd` 可以用于任何内存位置，无论对齐与否。

在 NASM 中，16 字节数值的大小前缀是 `oword`。

## SIMD 扩展

几十年来，SIMD 一直是 x86-64 生态中活跃发展的方向。架构的每一次扩展都会带来新指令，或者让旧指令有新的用法。

尤其是 AVX 和 AVX2 这两个扩展，带来了一些相关的变化。

第一，支持名为 `ymm` 的 256 位 SIMD 寄存器。它们扩展了对应的 `xmm` 寄存器，就像 `rax` 包含 `eax` 那样。

第二，它们为大多数操作 `xmm`（和 `ymm`）寄存器的指令增加了三操作数变体。这不仅包括 SIMD 指令，也包括操作标量浮点数的指令。这些变体沿用其 SSE 版本的写法，只是在前面加了一个 `v`：

```x86asm
vaddsd xmm0, xmm1, xmm2   ; xmm0 = xmm1 + xmm2 (scalar sum of 64-bit floats)
vmulps xmm1, xmm3, xmm4   ; xmm1 = xmm3 * xmm4 (packed multiplication of 32-bit floats)
vmovupd ymm5, yword [mem] ; this copies 32 bytes from the location at mem to ymm5
```

第三，SIMD 内存操作数所需的对齐被放宽了。只有像 `vmovaps` 这样显式要求对齐的移动指令才需要这种对齐。

在本学习路径中，我们把范围限定在之前的 SSE 扩展及其之前的指令和寄存器。这足以讲解基础知识，也能兼容种类广泛的 CPU。

不过，测试运行器完全支持 AVX 和 AVX2，甚至支持属于 AVX-512 的更新扩展。你可以随意使用它们。

~~~~exercism/note
在使用 SIMD 变体时保持一致是个好习惯。尽量不要对同一条指令混用 SSE 和 AVX 变体。

如果你的代码库混用了这些变体，那么在用完 AVX 之后、使用 SSE 之前，最好调用 `vzeroupper`。这样可以打断依赖链，避免 CPU 在 AVX 和 SSE 状态之间切换时出现代价高昂的停顿。
~~~~
