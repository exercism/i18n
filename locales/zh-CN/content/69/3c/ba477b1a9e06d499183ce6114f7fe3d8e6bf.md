# 关于

`String` 中的单个字符，可以通过与数组相同的下标访问方式来获取。不过，字符串所用的[下标][string-indices]_不是_整数，无法直接使用。你需要根据某个已知的下标把它们算出来，比如 `startIndex`，它指向非空字符串中第一个字符的位置。计算时要用到 [`String`][string-docs] 和 [`NSString`][nsstring-docs] 库提供的方法（导入 `Foundation` 模块后，Swift 中的字符串就可以使用 NSString 的全部属性和方法）。

例如，给定下面这个字符串：

```swift
let csv = "apple,pear,peach,orange,cherry,lime,goosberry"
```

你无法用 `csv[21]` 取到 “orange” 里的 “g”，而必须先算出一个 `String.Index` 类型的值，再用它作为下标。注意，这些下标本身并不是给人直接阅读的。它们被称为_不透明下标_，因为人类不需要知道它们里面装的是什么。

```swift
let index = csv.index(csv.startIndex, offsetBy: 21)
csv[index]
// "g"
print(index)
// prints Index(_rawBits: 1376513)
```

但要注意，如果偏移量并不对应一个有效的下标，也就是说算出的下标落在 `startIndex` 之前或 `endIndex` 之后，这个操作就会报错，导致程序崩溃。要避免这个问题，可以指定一个限制下标。这样返回的会是可选下标，对于本来无效的下标，它会返回 nil。

```swift
let tooFar = csv.index(csv.startIndex, offsetBy: 200)
// error: Execution was interrupted, reason: EXC_BAD_INSTRUCTION (code=EXC_I386_INVOP, subcode=0x0).
let tooFarButSafe = csv.index(csv.startIndex, offsetBy: 200, limitedBy: csv.endIndex)
// nil
```

另外，下标不能在字符串之间共用。例如，用上面算出的 “orange” 中 “g” 的 `index` 去索引字符串 `fam = "This is my family: 👨‍👩‍👦‍👦, this is our dog: 🐶, this is our cat: 🐱!"`，也就是 `fam[index]`，会让程序崩溃。

造成这一切的原因有很多，但归根结底就是一句话：“Unicode 很棘手。”

一般来说，如果你需要随机访问单个字符，那最好改用别的数据结构，比如 `Array<Character>`。

## 一些有用的方法

Swift 提供了 `first` 和 `last` 方法，用来获取字符串的第一个和最后一个字符。这两个方法返回的是可选值，所以如果字符串为空，就会返回 nil。

```swift
let str = "Hello, world!"
print(str.first) // Prints Optional("H")
print(str.last)  // Prints Optional("!")
```

你还可以用 `prefix` 和 `suffix` 方法获取字符串的子串。这两个方法接收一个整数作为实参，返回包含字符串前 n 个字符或后 n 个字符的子串。

```swift
let str = "Hello, world!"
print(str.prefix(5)) // Prints "Hello"
print(str.suffix(6)) // Prints "world!"
```

## 深入探讨：Unicode 下标

~~~~exercism/advanced

[Unicode][unicode] 是一种文本编码标准，它收录了来自许多不同语言和文字的大量字符。它是 ASCII 的超集，也就是说所有 ASCII 字符同时也是 Unicode 字符。Unicode 是一种变长编码，意思是有些字符占用的字节比其他字符多。至于这为什么重要，下一节会解释。

所以要看清楚这个问题，我们得去看英语之外的语言。以德语中的字符 “ü” 为例（注意这里用的是 2 字节的写法，它还有一个 1 字节的版本）。它乍看可能像一个字符，但实际上是两个字符：“u”和“¨”。所以在 Python 这类语言里，如果你去打印字符串 “ü” 的长度，得到的结果会是 2。然而，无论是作为用户还是程序员，我们都会说它是一个字符，而 Swift 也认同我们的看法。可为什么 Swift 这样做，Python 却不这样？答案是，Swift 采用的字符串表示方式和 Python 不同。在 Python 中，字符串表示为字节序列，也就是说字符串的长度就是它在内存中占用的字节数。而在 Swift 中，字符串表示为字符序列，也就是说字符串的长度就是它包含的字符数。这是一个非常重要的区别，因为它意味着在 Swift 中，字符串的长度不一定等于它在内存中占用的字节数。正因如此，我们才不能用整数来作为字符串的下标。
