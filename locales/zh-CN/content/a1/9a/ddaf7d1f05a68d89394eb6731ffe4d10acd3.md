# 简介

*双端队列*（deque）支持在两端以 O(1) 的时间复杂度进行压入和弹出。Factor 的标准实现是[`dlists`][dlists]中的`<dlist>`（一个双向链表），相关操作则位于[`deques`][deques]中。

## 双端队列 API

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` 会就地清空双端队列，这样可以在不重新分配的情况下复用它。

在同一端压入和弹出，得到的就是一个后进先出（LIFO）的栈。在一端压入、在另一端弹出，得到的就是一个先进先出（FIFO）的队列：

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

要后进先出，你会选用带 `push`/`pop` 的向量（`V{ }`），它每次操作的开销更小。当你需要在*两端*都达到 O(1) 时，才该用`<dlist>`，而这几乎总是为了先进先出队列。

## 广度优先搜索

正是先进先出的用法，让双端队列成为*广度优先搜索*（BFS）合适的前沿结构。你从一个节点开始，把邻居压入尾部，从头部弹出候选节点，再用哈希集合去重：

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

较早加入的候选节点会先于较晚的节点被访问，因此搜索会从起点开始逐层向外铺开。这正是广度优先搜索具备最短路径性质的原因：第一次到达目标节点时，走的必定是一条跳数最少的路径。

## `MEMO:`：自动缓存

有时广度优先搜索对每个节点所做的那次查找开销很大。Factor 的[`memoize`][memoize]词汇表提供了 `MEMO:`，它能直接替换 `:`，并以输入为键缓存该词的结果：

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

用 `MEMO:` 定义的词在第一次见到某个输入时会执行它的函数体，之后便返回缓存的结果。接口不变，调用处不需要额外的调用，只是在重复调用时更快。
