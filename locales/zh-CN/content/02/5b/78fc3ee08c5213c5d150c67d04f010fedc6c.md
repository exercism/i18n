# 提示
`Option` 用来表示一个可能没有有用结果的计算
（例如因为错误或无效输入）。
如果你不熟悉`Option`，可以阅读[这篇教程](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html)。
`Option` 是所谓的[单子](https://en.wikipedia.org/wiki/Monad_(functional_programming))，它涵盖了一个“计算层面”的特性，在这里就是值可能不存在。
恰当使用单子可以写出非常简洁、优雅
且易读的代码。使用不当则很容易适得其反。
观看[这个视频](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA)了解更多。
## 应该避免的常见坑
对于`Option`有几条经验法则：
1. 不需要就别用。与其写成
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
不如写成
```scala
def add1(x: Int): Int = x + 1
```
（有`Option.map`可以对这类简单函数做映射，
所以不必用`Option`把它们弄得累赘）。
2. 如果并不真的需要，就不要“解包”。
通常有内置函数能实现你的目的。过早解包的迹象
是`isDefined/isEmpty`或模式匹配。与其写成
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
不如写成
```scala
x map (_ + 1) getOrElse 0
```
3. 单子可以用在 for 推导式里，效果拔群。
当你想“组合”多个`Option`实例时，建议这样做。与其写成
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
不如写成
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
