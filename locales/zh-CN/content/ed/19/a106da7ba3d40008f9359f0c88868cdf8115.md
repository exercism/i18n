# 关于

在 Gleam 中，对值进行模式匹配时，我们必须确保所有模式都覆盖该类型所有可能的值，否则代码无法通过编译。

下面这个函数应该被拒绝，因为它没有处理数组为空的情况：

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

在大多数 Gleam 程序里，我们都想处理所有可能的情况，但在原型、临时脚本这类程序里，我们可能只关心正常路径，不为其他情况写代码。这正是 Gleam 的`let assert`的用武之地。

借助`let assert`，模式可以只匹配某个类型的部分可能值；如果模式没有匹配到值，程序就会崩溃。用`let assert`，上面的函数可以这样写：

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam 的库永远不应该使用`let assert`，因为它可能导致程序崩溃；库应该改用`Result`类型，由应用开发者决定如何处理错误。
