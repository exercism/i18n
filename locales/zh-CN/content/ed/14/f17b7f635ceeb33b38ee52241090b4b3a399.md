# 简介

要理解 [`Box`][box]，先了解[栈和堆][stack and heap]是什么会很有帮助。

栈是一块内存区域，工作方式类似后进先出（LIFO）缓冲区。把数据压入栈非常快，从栈中弹出数据也很快。栈上的数据可以是变量或函数地址，但数据的大小必须在编译时就是已知且固定的。

如果数据的大小在编译时未知，或者大小可能会变化，就必须在堆上分配。分配的过程要先找到堆里足够大的空间来存放数据，把数据写入堆，再把该数据的内存地址压入栈。这一整套流程比直接把数据放到栈上要慢得多。从堆中取回数据也会稍慢一些，因为需要先经过栈上的地址，再顺着这个地址找到数据在堆中的位置。

`Box`是一种智能指针，它把数据分配在堆上。地址在栈上，指向堆中的数据。使用`Box`的一个[原因][reasons]是：当某个类型的大小在编译时无法确定，而你又需要在要求确切大小的上下文中使用该类型的值时，可以把数据放到堆上。一个实际的用法是，你有多个结构体，想通过它们都实现的某个 trait 以相同的方式处理它们，如下面的例子所示。

假设我们有两个结构体。每个结构体都代表某种会惹人烦的东西。我们可以让每个结构体实现一个 Annoyance trait，像这样

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

现在假设我们想要一个函数，根据传入的一天中的时间返回一个 Annoyance。我们可以先试试下面这样，结果发现它无法编译

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

编译器非常热心，明确告诉了我们该怎么做：返回一个装箱的 trait 对象。如果你不知道什么是 trait 对象，简单来说，它是一种从可能返回任何实现了指定 trait 的对象的函数中，通过[动态分发][dynamic dispatch]返回某个具体对象的方式。既然需要动态分发，我们可以试着直接在 trait 名字前面加上`dyn`，看看能不能行得通。

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

其中一个错误是`dyn Annoyance`的大小无法在编译时确定。这是因为`annoy_me`在被调用之前并不知道它会返回哪个具体的 trait 对象。实现 Annoyance 的结构体可能有不同的字段，大小也可能不同。这也提醒我们，`Box`的用途之一正是处理大小在编译时无法确定的类型。那么现在我们试着用`Box`作为返回值，把 match 表达式返回的值`Box`起来，像这样

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

`Box`的签名是`Box<T>`，其中`T`代表要被装箱的具体类型，放在尖括号里，就像上面的`Box<dyn Annoyance>`一样。

我们可以像这样使用这个装箱的 trait 对象

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

它会打印

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

由于`my_annoyance`的类型是`Box<dyn Annoyance>`，必须用解引用运算符`*`把它从`Box`中解引用出来。然后它作为`dyn Annoyance`传给`be_annoying`函数借用。

另一种实现方式是去掉参数必须有大小的要求。这样，编译时会为 Annoyance 的每个变体分别生成一个函数，以便进行静态分发（这个过程称为[单态化][monomorphization]），像这样

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

还有一种方式，是让`be_annoying`函数接受一个`Box<dyn Annoyance>`，并使用[解引用强制转换][deref coercion]来避免手动解引用`Box`。这样会把 Annoyance trait 对象的所有权转移给`be_annoying`函数。它会在函数结束时离开作用域，不再可用。

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
