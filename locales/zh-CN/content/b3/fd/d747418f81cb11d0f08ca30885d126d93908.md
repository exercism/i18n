## 自定义异常与抛出异常

有时，你的代码需要同时[自定义](https://docs.python.org/3/tutorial/errors.html#user-defined-exceptions)和[`raise`](https://docs.python.org/3/tutorial/errors.html#raising-exceptions)异常。这时，你始终应该提供一条**有意义的错误信息**，说明错误的来源。这能让你的代码更易读，对调试也有很大帮助。

自定义异常可以通过新建异常类来创建（详见[`classes`](https://docs.python.org/3/tutorial/classes.html#tut-classes)），这些类通常是[`Exception`](https://docs.python.org/3/library/exceptions.html#Exception)的子类。

如果你知道错误来源会是某种异常类型的衍生物，可以选择继承 _Exception_ 类下面的某个[`built in error types`](https://docs.python.org/3/library/exceptions.html#base-classes)。抛出该错误时，你仍然应该附上一条有意义的错误信息。

这个练习要求你创建一个_自定义异常_，当传给`meetup()`函数的星期名称和数字组合无效时，将其[抛出](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement)（也就是“抛”）。只有当你自定义了合适的异常、`raise` 了这些异常，并附上合适的错误信息，测试才会通过。

要自定义一个`built-in exception`，就创建一个继承自该异常的`class`。在带消息抛出这个自定义异常时，把消息作为参数传给`exception`类型：

```python
# subclassing the built-in ValueError to create MeetupDayException
class MeetupDayException(ValueError):
    """Exception raised when the Meetup weekday and count do not result in a valid date.

    message: explanation of the error.

    """
    def __init__(self, message):
        self.message = message

        
# raising a MeetupDayException
raise MeetupDayException("That day does not exist.")
```
