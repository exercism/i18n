# 提示

## 通用

- 只有当已知某个内存操作数是对齐的时候，才应该使用`movapd`和`movaps`。当两个操作数都是`xmm`寄存器时，可以放心使用它们。
- 内存地址以整数值的形式传递。
  前六个整数实参分别通过`rdi`、`rsi`、`rdx`、`rcx`、`r8`和`r9`传给函数。

## 1. 合并两条产线的产出

- 32 位浮点数的打包加法是`addps`。
- 三个指针实参都保证按 16 字节对齐，所以适合使用对齐的移动变体`movaps`。

## 2. 计算按比例缩放的偏差

- 64 位浮点数的打包减法是`subpd`。
- 64 位浮点数的打包乘法是`mulpd`。
- `measured`是对齐的，`target`不是，所以它们需要不同的加载变体。

## 3. 校准一批数据

- `reference`和`offset`都是对齐的，`raw`不是，所以它们需要不同的加载变体。
- 两行都需要用到`reference`和`offset`。
- 双操作数指令通常会覆盖它的目标操作数。
- 要把`raw`的高 2 个浮点数转换成双精度浮点数，请使用`cvtps2pd`，并传入一个从 raw 指针偏移 8 字节的内存操作数。
- 转换系数应该以 2 个 64 位浮点数的形式存储在内存中（两者都等于`0.5`）。
- 结果占 32 字节（4 个 64 位浮点数）：前 16 字节位于`[result]`，接下来的 16 字节位于`[result + 16]`。

## 4. 对一条产线上的分数做归一化

- 双操作数指令通常会覆盖它的目标操作数。
- 对于打包算术指令，内存不能作为目标操作数。
- 对于`scores`数组（第一个实参）中的每个 64 位浮点`score`，`gains`数组（第二个实参）中都有一个对应的`gain`。
  每个`score`都会与同一位置上的`gain`进行运算。
- 第三个实参是一个固定的`scale`，包含 2 个打包的 64 位浮点数。
- 对于每一对`score`和`gain`，函数都会计算`score * gain / scale_lane`。
  `scale`中的第一个通道用于缩放每一对中的第一个元素（偶数位置上的通道），第二个通道用于缩放第二个元素（奇数位置上的通道）。
- 归一化后的分数就地存储在`scores`数组中，位置与它输入的`score`相同。
- `scores`和`gains`中的元素数量相同，且等于`n`的值（第四个实参）。
- 你应该使用循环来处理所有元素对，每次迭代前进 16 字节（2 个元素）。
