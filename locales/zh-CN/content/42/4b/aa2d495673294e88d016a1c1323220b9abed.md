# 关于

在之前的概念中，我们提到过，`global`指令可以让在一个源文件中定义的函数或变量对其他文件可见。
类似地，`extern`指令告诉汇编器，当前源文件中使用的某个函数或变量是在另一个文件中定义的。

这两个指令是汇编代码与其他源文件交互、实现模块化的主要方式。

就这两个指令而言，外部代码是用汇编还是用高级语言定义或使用，并没有区别。
因此，举例来说，即使一个用高级语言定义的函数，只要声明为`extern`，也可以在 x86-64 代码中使用。

同样，调用约定在这些函数之间是共通的，无论它们是用汇编还是高级语言定义的，甚至与操作系统（OS）之间也是如此。

不过，由于在汇编中，数据只是一串字节，所以有必要了解与之交互的高级语言是如何管理内存的。

## C 类型

C 语言是与汇编代码交互时常见的高级语言选择。
它让与操作系统交互的任务变得更容易，为许多重要任务提供了高层封装，比如向屏幕打印输出、从键盘读取输入，或者分配动态内存。

在这个 track 中，测试是用 C 编写的，因此有必要对该语言做一个总体概览。

~~~~exercism/note
下面列出的任何类型都可以用`const`修饰。
这会让它们变成只读。
~~~~

### 基本类型

C 中的基本类型有很多，它们的大小（以字节为单位）可能各不相同。
下表总结了其中一部分，以及它们在 x86-64 系统上的典型大小：

| 类型      | 字节数           | 整数/浮点数             |
|-----------|-----------------|------------------------|
| _Bool     | 1               | 整数                   |
| char      | 1               | 整数                   |
| short     | 2               | 整数                   |
| int       | 4               | 整数                   |
| long      | 4 或 8          | 整数                   |
| long long | 8               | 整数                   |
| float     | 4               | 浮点数                 |
| double    | 8               | 浮点数                 |

这些整数类型中的每一个都可以是有符号的（默认）或无符号的。
如果它们是无符号的，则必须显式指定，例如：`unsigned int`。

这些整数类型还有一些别名，用来精确控制它们的大小：

| 别名    | 字节数          |
|---------|-----------------|
| int8_t  | 1               |
| int16_t | 2               |
| int32_t | 4               |
| int64_t | 8               |

这些别名可以加上`u`前缀来表示无符号类型，例如：`uint64_t`。

其他值得注意的别名有：

| 别名   | 类型                                          |
|--------|-----------------------------------------------|
| bool   | _Bool                                         |
| size_t | 通常是一个无符号的 8 字节整数                  |

`_Bool`（或其别名`bool`）的独特之处在于，它虽然占用整整 1 个字节，却只能取两个值之一：`true`（`1`）和`false`（`0`）。

这些基本类型的值，会按照整数和浮点数的常规规则传入和传出函数。

### 枚举

[枚举][enum]是一种类型，它可以取若干显式列出的元素之一：

```c
enum example {
    example_1,
    example_2,
    example_3,
    example_4
};
```

在 C 中，枚举会被隐式转换为整数类型，通常是`int`，也就是 4 字节整数。

默认情况下，枚举中第一个可能的元素会被转换为`0`，之后每个元素依次转换为下一个整数。
所以，在上面定义的`enum example`中，`example_1`的值是`0`，`example_2`的值是`1`，依此类推。

可以为枚举中的任意元素指定值，之后默认情况下，下一个元素会取下一个整数作为值：

```c
enum example_2 {
    example_1 = 4,
    example_2 = 8,
    example_3
}; // example_3 is equal to 9
```

### 内存地址

在 C 中，内存地址通过指向某个类型的[指针][pointer]来引用，并用`*`运算符表示。
所以，举例来说，`int64_t *`指向存放一个或多个`int64_t`的内存位置。

地址和往常一样，被当作 8 字节整数处理。

### 数组

数组传入和传出函数时，是以指向其第一个元素的指针的形式。

```c
int64_t example_arr[] = {1, 2, 3}; // this is an array of 3 signed 8-byte integers
fn(example_arr); // this is a function that passes a pointer (int64_t *) to the beginning of the array as argument
```

数组中的每个元素都占用数组元素类型的大小。
比如上面定义的`example_arr`有 3 个元素，每个 8 字节，总共 24 字节。

由于数组不存储自己的长度，通常需要另外用一个值来指明元素个数，除非用哨兵值标记结尾。

### 字符串

C 中的字符串是`char`数组，而`char`是 1 字节类型。
大多数字符串由 ASCII 字符组成，并以 NUL 结尾，所以当遇到值为`0`的字节时，字符串就结束了。
这意味着字符串的长度通常不需要作为单独的实参传递。

## 调用 C 库函数

`extern`指令只是声明某个符号定义在另一个文件中。
对它的调用实际上如何发生，取决于那段外部代码是如何链接的。

对于与你的代码一起链接的普通函数，链接器能够直接找到外部函数，所以一条普通的`call`就够了。

不过，像`malloc`、`free`和`printf`这样的标准 C 库函数，通常是在运行时从共享库中解析的，而在你的代码被汇编时，这个库的地址还未知。
因此，调用会经过[过程链接表（PLT）][plt]中的一个桩，它位于已知的偏移量处。
从汇编中调用外部库函数时，NASM 需要你指明该调用应从 PLT 中解析。

在`elf64`（Linux 程序使用的输出格式）中，这种指明是通过在调用后加上`wrt ..plt`（即“引用 plt”）来完成的。
例如，`call printf wrt ..plt`。

而在`macho64`程序（macOS 程序使用的输出格式）中，只需要在函数名前加一个下划线就够了。
例如，`extern _printf`，然后`call _printf`。
不过，由于这个 track 在汇编`macho64`代码时使用了`--prefix _`标志，所以在两种情况下，这个下划线都会由汇编器自动添加。例如，`extern printf`，然后`call printf`。

注意，Exercism 的 test-runner 运行在 Linux 镜像中，所以任何调用了 C 库函数的提交解答都必须使用`wrt ..plt`。
可以用一个汇编期守卫，在两种输出格式之间正确分派：

```x86asm
extern malloc

%ifidn __OUTPUT_FORMAT__,elf64
    call malloc wrt ..plt       ; elf64: reach the function through the PLT
%else
    call malloc                 ; macho64: the linker generates the call stub
                                ; the underscore is added automatically by an assembler flag
%endif
```

## 系统调用

有很多操作是用户级程序（比如这个 track 中运行的程序）无法直接执行的。
从`stdin`读取、向`stdout`写入、申请动态内存、与外围设备交互等等，这些都由操作系统（OS）处理。

用户级程序在需要时，必须显式请求操作系统来执行这些操作。
这是通过[`syscall`][syscall]指令完成的。
从概念上讲，这条指令可以看作是对某个预定义的操作系统过程的调用（即一次“系统”调用）。

系统调用的任何实参都应通过 GPR 传给操作系统：`rdi`、`rsi`、`rdx`、`r10`、`r8` 和 `r9`。

注意，这个顺序与函数调用中使用的顺序几乎相同，只是`rcx`被换成了`r10`。
这是因为`syscall`会用`rcx`和`r11`来保存返回地址和标志位（在把控制权交还给调用函数之前，这些值会被恢复）。
在每次`syscall`中，这两个寄存器都必须视为被破坏。

与`call`不同的是，这里没有标明系统“函数”的标签。
相反，它们是通过在调用前放入`rax`的特定编号来访问的。
任何返回值（如果有的话）也放在`rax`中。

上述约定在 [System V ABI 的一个附录][linux-convention]中有描述，该附录专门针对 Linux，并且被标注为仅供参考。
在实践中，可用的系统调用有哪些、它们的编号是多少，以及错误如何报告，这些都是操作系统层面的细节，在不同操作系统之间差别很大，甚至同一个操作系统的不同版本之间也会不同。

许多 C 库函数，以及操作系统定义的其他真正的函数，都是对某个系统调用的高层封装。
ABI 建议应优先使用这些封装，而不是直接使用普通的`syscall`，而 Apple [并不保证内核系统调用接口的兼容性][mac-qa1118]。
