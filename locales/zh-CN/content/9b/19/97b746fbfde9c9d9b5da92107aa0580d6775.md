# 关于

内存通常由操作系统（OS）为程序映射成一种通用的布局：

| 地址 | 内存区域          |
| :-----: | :--------------------- |
|  高   | 栈                  |
|         | ...                    |
|         | 堆                   |
|         | 读写段 |
|         | 代码/只读段 |
|   低   | 保留               |

内存按段划分，段内再组织成若干节，各节具有不同的权限。

到目前为止我们定义的函数都位于**section .text**中。
这个节存放只读的可执行数据。
其他节用来声明数据变量，这些变量可以是只读的，也可以是可读写的，但不能执行。

## .data 节

已初始化的数据在 **[section .data][data]** 中声明。

在 NASM（The Netwide Assembler，本轨道使用的汇编器）中，一个已初始化的变量有一个名字、一个指明数据大小的伪指令，以及一串用逗号分隔的值。
这几部分之间用空格分隔，标签后面也可以选择性地跟一个`:`。

主要的伪指令及其对应的数据大小如下：

| 伪指令 | 大小    |
| :-------: | :------ |
|    db     | 1 字节  |
|    dw     | 2 字节 |
|    dd     | 4 字节 |
|    dq     | 8 字节 |

例如，下面声明了一个名为`space`、值为`10`的字节变量：

```x86asm
section .data
    space db 10
```

在`section .data`中声明的变量是可变的，也就是说，它们是可读写的。
它们还具有_静态_存储期，这意味着它们在整个程序运行期间一直存在。

## .rodata 节

**section .rodata**与`section .data`类似。
这两个节都包含已初始化的数据，声明方式相同，存储期也相同。

它们的主要区别在于，`section .rodata`中的数据是不可变的，也就是只读的。

~~~~exercism/note
用`equ`定义的常量与在`section .rodata`中定义的常量不同。

用`equ`定义的常量不占用内存空间，汇编器会直接把它替换成对应的值。
实际上，它就是那个值的一个占位符。

而在`section .rodata`中定义的常量则真正存储在内存中，拥有一个地址。
~~~~

## 访问数据

### 标签与间接寻址

已声明的数据必须有一个与之关联的名字。
这个名字叫做**标签**。

标签是一个符号，它编码了数据在内存中的具体地址。
**x86-64 中的地址是 64 位的值**。
保存这样一个地址的值，无论是在寄存器中还是在内存中，就是高级语言所说的**[指针][pointer]**。

在 NASM 中，直接用标签访问数据，得到的并不是所分配的内存，而是它的地址：

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

要访问某个内存地址中的内容，必须先对它进行_解引用_。
这叫做**间接寻址**。

在 NASM 中，用`[]`来完成：

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

不过，有些情况下被解引用的内存大小会存在歧义。
这时必须使用一个指定该大小的前缀。

在典型的 x86-64 程序中，最重要的几种前缀及其大小如下：

| 前缀 | 大小    |
| :----- | :------ |
| byte   | 1 字节  |
| word   | 2 字节 |
| dword  | 4 字节 |
| qword  | 8 字节 |

同一个加载也可以显式写出大小：

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

解引用内存时始终加上前缀是个好习惯。

### 写入内存

写入内存的方式相同，也是通过解引用一个地址：

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

注意，在大多数指令中，你可以直接使用内存操作数，而不必先把内容加载到寄存器中。
不过，通常不能在源操作数和目标操作数中同时使用内存操作数，二者只能用其一：

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### LEA 指令

虽然可以用`mov`把变量的地址存入寄存器，但有一条专门做这件事的指令：**[lea][lea]**。

这条指令使用内存形式的操作数，但它并_不_读取内存。
它会计算有效地址表达式，并把结果写入目标操作数：

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

用`lea`来计算内存地址并存入寄存器，是更地道的做法。

### 相对寻址

访问内存位置时，NASM 的默认行为是生成**绝对地址**，也就是固定的内存地址。

出于安全考虑，可执行文件通常被构建为**PIE（位置无关可执行文件）**，其中各内存区域会被放在随机化的位置。
在`PIE`中，变量的最终地址在链接时是未知的。
因此，代码会改为把地址计算为相对于一个名为`rip`的特殊寄存器中值的偏移，这个寄存器指向下一条将要执行的指令。

这通常叫做**RIP 相对寻址**。

在 NASM 中，可以用**[rel 运算符][rel]**来请求 RIP 相对访问：

```x86asm
mov rax, qword [rel variable]
```

也可以通过在源文件顶部加上`default rel`，把相对寻址设为默认方式。

本轨道的所有练习都以`PIE`方式编译和链接，所以应该使用`rel`来生成相对地址。

上面提到的这种随机化布局，是一种叫做地址空间布局随机化的缓解措施。
它让每个内存区域的基址变得不可预测，从而使攻击者无法得到许多利用技术所依赖的那些固定地址，而正是`PIE`让加载器能够把这些区域放在任意位置。

因此，本轨道不但不鼓励使用绝对寻址，而且根本无法使用它。
像`[abs variable]`这样的绝对引用，会要求汇编器把一个固定的 32 位地址嵌入指令中。
在 Linux 上，`PIE`链接器会拒绝这种做法产生的重定位；而在 macOS 上，`macho64`格式根本不支持 32 位绝对地址，所以文件无法汇编。

RIP 相对寻址能同时避免这两个问题，因为指令只编码相对于`rip`的偏移，而不会编码固定地址。
因此，在`PIE`下把地址放入寄存器的地道做法，就是使用带`rel`操作数的`lea`：

```x86asm
default rel

section .data
    variable dq 7

section .text
fn:
    lea rax, [rel variable]       ; materialize the address (PIE-safe)
    mov rcx, qword [rel variable] ; load the value through a RIP-relative access
    ...
```

### 可见性

在任何节（例如`.text`、`.data`、`.rodata`）中定义的标签（函数和数据），在同一个源文件内都是可见的。
如果声明为`global`，它们对其他源文件也是可见的。

反过来，在其他源文件中定义的标签如果声明为`extern`，则对当前源文件可见。
这种情况下，汇编中不会标明数据的大小，必须事先知道它。

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
