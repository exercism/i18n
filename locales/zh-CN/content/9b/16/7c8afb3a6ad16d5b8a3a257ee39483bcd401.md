# 关于

`TUPLE: child < parent extra-slots ;` 声明一个类，它的实例同时也是 `parent` 的实例。槽位查找沿着继承层级进行：`child` 拥有父类声明的每一个槽位，再加上自己的槽位，顺序就是如此。

```factor
TUPLE: vessel name tonnage ;
TUPLE: cargo-vessel < vessel capacity ;
TUPLE: tanker < cargo-vessel fuel-type ;
```

## `boa` 的实参顺序

自动生成的 `boa` 构造函数按声明顺序接收槽位，*父类的槽位在前*。对于上面的 `tanker`：

```
tanker boa ( name tonnage capacity fuel-type -- tanker )
```

槽位的顺序由继承链固定下来。父类槽位和子类槽位无法交错排列，而重新排列父类的槽位，对每一个后代的 `boa` 来说都是破坏性变更。

## 谓词层级

每个 `TUPLE:` 声明都会生成一个类谓词（`name?`）。有了继承，这些谓词会层层嵌套：

```factor
"Esso" 50000 100000 "diesel" tanker boa .

! all three predicates fire
dup tanker?        .   ! => t
dup cargo-vessel?  .   ! => t
dup vessel?        .   ! => t
```

`instance?`（来自 [`classes`][classes]）问的是同一个问题，只不过类是通过栈上的实参给出的，而不是写死在一个词的名字里：`obj tanker instance?` 等同于 `obj tanker?`：

```factor
USING: classes ;

"Esso" 50000 100000 "diesel" tanker boa
dup vessel instance? .   ! => t
```

因为类现在是一个值，所以同一个调用点可以针对传给它的任意类来测试，而固定的 `name?` 谓词做不到这一点。

`M:` 方法分派所走的，也是这种具有传递性的 `is-a` 关系：定义在 `vessel` 上的方法会作用于每一个 `cargo-vessel` 和每一个 `tanker`，除非更具体的覆盖先被触发。这部分内容见 [`generics`][generics]。

## 访问器继承

访问器词（`slot>>`、`>>slot`、`change-slot`）来自 [`accessors`][accessors]，并不绑定到生成它们时所用的那个类：任何*拥有*该槽位的元组都能使用它们。

```factor
USING: accessors ;

"Esso" 50000 100000 "diesel" tanker boa
[ 1 + ] change-tonnage tonnage>> .   ! => 50001
```

`change-tonnage` 是为 `vessel` 生成的，但它能作用于 `tanker`，因为每个 `tanker` 都是一个 `vessel`。

## 这里不涉及的内容

- **混入**（`MIXIN:` / `INSTANCE:`）：一个类可以加入多个混入；这种关系是多对多的，主要用于在一套共享协议之上进行泛型分派。流这个概念会在相应的上下文里介绍它们。
- **谓词类**（`PREDICATE:`）：通过运行时谓词从已有的类中划出一个子类。这是 Factor 的另一项特性，这里不涉及。
