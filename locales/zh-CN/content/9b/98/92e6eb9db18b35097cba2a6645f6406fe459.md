# 关于

正如[`Nothingness`][concept-nothingness]概念中探讨的那样，R 有多种方式表示缺失（[`NULL`][ref-null]）、未知（[`NA`][ref-na]）或数学上无效（[`NaN`][ref-finite]、[`Inf`][ref-finite]）的数据。一般来说，R 会尝试用这些值就地标记问题，并继续运行，而不抛出异常。

## `stop()`

有些问题过于根本，无法让程序继续运行。这种情况下，可以用[`stop(msg)`][ref-stop]立即以 `Error` 中止程序，并打印 `msg`。

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

与其他语言中的[`assert`][wiki-assert]类似，[`stopifnot()`][ref-stopifnot]是 `stop()` 的便捷包装。它的参数是任意数量的布尔条件，用逗号分隔，只有当所有条件都为 `TRUE` 时，程序才会继续。

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R 有多种处理错误的方式。它们基于 Common Lisp，与许多流行语言的做法差异很大。

最简单的方式，是把可能有问题的代码包在[`try()`][ref-try]里。

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning]和[`message()`][ref-message]

它们用于响应非致命的情况，例如：

- 对程序至少能部分恢复的问题发出警告。
- 告知用户长时间运行的程序目前的进展。

两者的一个区别是：警告会被缓存，并（默认）在函数返回时输出，而消息则会立即输出。改变默认行为的方法有很多，这里不展开讨论。

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

在 Exercism 里，[`suppressWarnings()`][ref-warning]函数偶尔也很有用，可以避免不需要的输出干扰测试运行器。
