# 关于可空性

在理想世界中，我们大可以指望一切都定义得妥妥当当，有具体的值，没有空缺。

这与我们的日常经验相矛盾，因此许多编程语言都提供了表示“值不存在”的方式：null 或 NULL、nil、None、nothing……

引入它很容易（早在 1965 年），但很快就带来了遗憾。它的发明者后来把它称为自己的[“十亿美元的错误”][web-mistake]。

近几十年来，语言设计者探索了许多方法，让 null 既能使用，（在大多数情况下）又安全。

Kotlin 有几条[通用原则][ref-null-safety]，它们[与 Java 有显著差异][ref-java2kotlin]。_这些差异意味着 Kotlin 有专门的功能来处理与 Java 的互操作，不过细节超出了本概念的范围。_

- Kotlin 有一个特殊的`null`值。
- 所有类型都_默认_不可空（也就是说，不能为`null`）。
- 所有类型都可以设为_可空_，但必须显式地这样做。
- 可能因异常而失败的函数，通常还会有一个带可空返回值的变体。
- 一些特殊而极其简洁的语法，力求让检测和应对 null 变得尽可能简单。

## 创建可空变量

只要加上`?`后缀，就能把类型变成[可空类型][ref-nullable-type]（例如用`String?`代替`String`）。

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## 有用的运算符和函数

### [安全调用运算符][ref-safe-call]`?.`

对于非空的`String`，我们可以获取它的`.length`属性。

可空的`String?`用同样的语法会失败，但改用`?.length`就能应对出现`null`的可能。返回类型是`Int?`。

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

正如上面最后一行所示，`?.`对非空类型同样适用。

### [Elvis 运算符][ref-elvis]`?:`

延续安全调用运算符的思路，[Elvis 运算符][wiki-elvis]让我们可以提供一个默认值来替代`null`。

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### [非空断言运算符][ref-not-null]`!!`

有了这个运算符，只要程序员有把握，就可以把可空类型强制当作非空类型处理。也许有时候，我们对程序逻辑的理解比过分谨慎的编译器更到位？

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

责任就落到我们自己身上了：如果`b`仍然是`null`，就会抛出`NullPointerException`。

### [let 函数][ref-let]`?.let`

如果要把一个可空的项传给一段代码，我们可以专门做 null 检查：`if (item != null) { do something }`。

更简单也更符合习惯的做法是用`item?.let { do something }`。只有当`item`不为 null 时，`do something`才会执行。

### 类型为`somethingOrNone()`的函数

有些函数可能会失败，比如在字符串或数组中请求一个无效的下标时。

与其抛出异常，我们可以改用函数的[`...OrNull`变体][ref-elem-at-or-null]，来得到（在这里）一个`Int?`返回值。

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
