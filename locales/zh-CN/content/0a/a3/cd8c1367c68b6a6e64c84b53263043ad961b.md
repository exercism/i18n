# 简介

## `jq`中的错误

`jq`报告的报错大致分为两类：

1. **编译期错误**：程序本身无效，比如语法错误、引用了未定义的函数或变量等等。
   `jq`会直接拒绝运行整个程序。

   ```sh
   $ jq -n '1 + $foo + 2'
   jq: error: $foo is not defined at <top-level>, line 1, column 5:
       1 + $foo + 2
           ^^^^
   jq: 1 compile error
   ```

2. **运行时错误**：程序本身是有效的，但在处理某个值的过程中出了问题，比如用字符串给数字做索引、用`fromjson`解析无效的 JSON 文本、用类型不正确的实参调用函数等等。

   ```sh
   $ echo '42' | jq '.foo'
   jq: error (at <stdin>:1): Cannot index number with "foo"
   ```

本概念讲的是**运行时错误**：如何抛出它们、如何捕获它们，以及如何终止它们。

未被捕获的运行时错误会让`jq`向_标准错误_打印一条消息，并以状态码`5`退出。

## 抛出错误：`error`和`error(message)`

[`error`][man-error]过滤器会抛出一个错误。

- `error`抛出的错误，其值就是**输入**值。
- `error(message)`抛出的错误，其值是`message`的结果。

```jq
"bad input" | try error catch .
# => "bad input"

42 | try error("invalid value: \(.)") catch .
# => "invalid value: 42"
```

~~~~exercism/note
错误值可以是_任意_ JSON 值，而不只是字符串。
抛出结构化的错误，可以让`catch`处理程序根据错误的内容做出判断。

```jq
try error({kind: "range", msg: "age must be non-negative"})
catch (if type == "object" then "\(.kind) error: \(.msg)" else "unexpected: \(.)" end)
# => "range error: age must be non-negative"
```
~~~~

如果非字符串的错误值没有被捕获，`jq`会把它按 JSON 打印出来，并标注`(not a string)`。

```sh
$ jq -n 'error({code: 42, msg: "boom"})'
jq: error (at <unknown>) (not a string): {"code":42,"msg":"boom"}
```

## 捕获错误：`try`和`catch`

可以用[`try EXP catch HANDLER`][man-try-catch]捕获错误。
第一个表达式会被执行；如果它抛出了错误，就执行`HANDLER`表达式，**并把错误值作为它的输入**。
处理程序的输出会照常输出，就好像它是被`try`的那个表达式产生的一样。

```jq
true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]

true | try error("some exception") catch .
# => "some exception"
```

简短形式`try EXP`等价于`try EXP catch empty`：错误被丢弃，不产生任何输出。

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

~~~~exercism/note
在`try`内部，错误会**中止流中剩余的部分**。
已经产生的值会保留下来，但错误之后的内容不会再被求值。

```jq
jq -n 'try (1, error("x"), 3) catch "caught: \(.)"'
# outputs:
# 1
# "caught: x"
# (3 is never produced)
```
~~~~

处理程序可以抛出新的错误，也可以用不带参数的`error`重新抛出原来的错误。因为错误值就是处理程序的输入，所以这样会把它原封不动地继续抛出去。

```jq
try repeat(f) catch
  if . == "break" then empty else error end
```

## 抑制错误：`?`运算符

[`?`运算符][man-question-mark]写成`EXP?`时，是`try EXP`的简写。
它把一个会失败的表达式变成一个什么都不输出的表达式。

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]

true | [.a?]
# => []
```

它经常出现在索引运算符上：

- `.foo?`就是`.["foo"]?`
- `.[]?`只在输入是数组或对象时才迭代，否则什么都不输出

~~~~exercism/caution
`?`会抑制**所有**错误，包括你没想到的那些。
当`user`不是对象时，`user.name?`会悄悄不输出任何东西，这可能掩盖数据问题或程序里的拼写错误。
如果你需要知道某件事_确实_失败了，或者想显式校验输入，优先使用`try ... catch`。
~~~~

## 替代运算符`//`

程序员有时会以为，当`a`失败时`a // b`会产生`b`。
在旧版本的`jq`中确实如此，但从`jq` 1.6 起就不是了。
`//`运算符并不会抑制错误。
它只在`a`不产生任何值、产生`false`或`null`时用`b`替代；`a`中的错误仍会继续向外传播。

```sh
$ jq -n '(error("x")) // 42'
jq: error (at <unknown>): x
```

如果希望为错误准备一个备用值，请使用`try a catch b`。

## 解构替代运算符`?//`

[`?//`运算符][man-question-mark-slash-slash]把解构和错误处理结合在一起。
它会依次尝试各个绑定模式，直到有一个成功为止；失败的替代分支所绑定的变量会被设为`null`。

```jq
# input:
#   [
#     {"a": 1, "b": 2, "c": {"d": 3, "e": 4}},
#     {"a": 5, "b": 6, "c": [{"d": 7, "e": 8}]}
#   ]

.[] as {$a, $b, c: {$d, $e}} ?// {$a, $b, c: [{$d, $e}]}
| {$a, $b, $d, $e}

# outputs:
# {"a": 1, "b": 2, "d": 3, "e": 4}    # first element: c is an object, first pattern matched
# {"a": 5, "b": 6, "d": 7, "e": 8}    # second element: c is an array, second pattern matched
```

这里第一个模式要求`c`是一个带有`d`和`e`两个键的_对象_，而第二个模式要求`c`是一个包含这种对象的_数组_。
第一个输入元素与第一个模式绑定成功；第二个元素无法匹配该模式，于是改用第二个模式。

这样，同一个程序就能解构形状各不相同的输入，而不必写一长串显式的`if type == ...`判断。

## 终止程序：`halt`和`halt_error`

有时候，面对错误最合适的做法就是彻底停止处理。

- [`halt`][man-halt]立即停止`jq`程序，不再产生任何输出；退出状态码为`0`。
- [`halt_error`][man-halt-error]停止程序，把它的**输入**以原始文本的形式打印到_标准错误_（不加任何修饰，连换行都没有），并以指定的状态码退出，默认为`5`。

```sh
$ echo '"Error: something went wrong"' | jq 'halt_error(1)'
Error: something went wrong    # printed on stderr, exit status 1
```

注意，这些过滤器会立即终止程序，即使还有输入没读完。

### 退出状态码

供参考，`jq`使用以下退出状态码：

| 状态码 | 含义                                             |
| :----: | ------------------------------------------------ |
| `0`    | 成功                                             |
| `2`    | 用法错误（命令行选项不正确）                     |
| `3`    | 编译错误                                         |
| `5`    | 运行时错误（或`halt_error`不带参数）             |

使用`--exit-status` / `-e`选项时，状态码反映的则是最后一个输出值：`true`或数字为`0`，`false`或`null`为`1`，没有任何输出为`4`。

## 调试辅助工具

在追查错误来源时，下面这些过滤器会很有帮助：

- [`debug`][man-debug]把输入原样传递出去，但会向标准错误打印`["DEBUG:", <input>]`。
  `debug(msgs)`也会把`msgs`作为调试信息打印出来。
- [`stderr`][man-stderr]把输入以原始、紧凑的形式打印到标准错误。
- [`input_line_number`][man-input-line-number]输出当前正在处理的输入所在的行号，当文件里包含许多 JSON 文本而其中有一个出错时，这非常有价值。
- [`$__loc__`][man-loc]输出一个带有`file`和`line`两个键的对象，描述它在程序中出现的位置，可以把它嵌进错误消息里。

```jq
def checked_div($d):
  if $d == 0
  then error("\($__loc__): division by zero")
  else . / $d end;

try (10 | checked_div(0)) catch .
# => "{\"file\":\"<top-level>\",\"line\":3}: division by zero"
```
