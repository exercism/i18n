# 补充说明

## 实现

开始之前，请确保你了解如何编写能通过测试用例的代码。
想了解更多背景，可以看看这篇[教程][tutorial]。

大多数 Java 练习都包含多个测试用例。
这些用例的结构支持一种非常有用的流程，叫做[测试驱动开发（TDD）][tdd]。
TDD 会重复一个结构化的循环，帮助程序员一点一点地构建复杂功能，而不是一次性写完。
这个循环可以这样描述：

1. 添加一个测试，用它描述你当前代码还缺少的某一项期望功能。
2. 运行测试，确认这个新添加的测试失败。
3. 修改现有代码，直到：
    - 所有旧测试仍然通过；
    - 新测试也能通过。
4. [清理][refactoring]你的代码，确保所有测试仍然通过。
   这通常包括重命名变量、删除重复的逻辑片段、删除遗留的日志输出等。
5. 回到第 1 步，直到实现所有期望的功能！

本 track 的测试文件包含你的解答要被判定为有效而需要通过的_全部_测试。
这似乎与上面描述的循环（一次只写一个测试）并不完全兼容。
不过，我们用来编写测试的工具 [JUnit][junit] 提供了一个 [@Disabled][junit-disabled] [注解][java-annotation]，可以用它临时跳过已经写好的测试。
借助这个注解，我们确保交付给你的测试文件满足以下规则：

- 任何测试文件中的第一个测试默认_不会_被跳过。
- 任何测试文件中除第一个测试外的所有测试默认_都会_被跳过。

这样，你只要按照下面这些稍作修改的步骤，就能模拟 TDD 循环：

1. 运行测试，确认当前_至多只有一个_测试失败。
2. 修改现有代码，直到所有未被跳过的测试都通过。
3. 清理你的代码，确保所有未被跳过的测试仍然通过。
4. 删除测试文件中最上面的 `@Disabled` 注解。
5. 回到第 1 步，直到没有测试被跳过，并且所有测试都通过！

[junit]: https://junit.org/junit5/
[junit-disabled]: https://junit.org/junit5/docs/current/api/org.junit.jupiter.api/org/junit/jupiter/api/Disabled.html
[refactoring]: https://en.wikipedia.org/wiki/Code_refactoring
[tdd]: https://en.wikipedia.org/wiki/Test-driven_development
