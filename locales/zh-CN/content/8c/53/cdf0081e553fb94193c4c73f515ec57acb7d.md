# 贡献概念和概念练习

一个[概念练习][product-concept]旨在教授某一门编程语言中的单个概念。它应当有明确的学习目标，并提供足够的样板代码，让学生不必去学无关的代码。相关的概念有自己独立的文档，不受概念练习的约束。概念可以把其他概念作为前置概念，并在这些前置概念对应的概念练习完成之前保持锁定。概念练习的难度不应随着学习路径的推进而增加。熟悉前置概念的开发者，都应该能在 5 到 10 分钟内完成一个概念练习。

既然我们已经了解了什么是概念练习，下面就来详细说明如何实现一个概念练习，以及它对应的概念。作为参考，[概念练习的详细规范][concept-exercise-spec]和[概念的详细规范][concept-spec]都在 exercism 的[文档仓库][docs-repo]里。本文汇总了许多资料中的信息，作为一份方便的逐步指南，告诉你如何贡献一个概念练习。

## 2. 确定学习目标

重要的是知道一个概念练习打算教什么、什么不在范围内，所以我们来创建第一个文件：`exercises/concept/<story-name>/.meta/design.md`。概念练习是按它们所用的故事命名的，而我们还不知道故事是什么，所以先保留 `story-name`，之后再替换。[`design.md` 规范][design-spec]要求这份文档定义练习的总体目标、多个学习目标、不在范围内的事项、它解锁的相关概念，以及完成该练习所需的前置概念。你可以用[布尔概念练习的 `design.md`][design-bool]作为起点的模板。

## 3. 为练习撰写概念介绍

学习目标明确之后，就该写一篇介绍，把概念讲得足够清楚，让学生能够解出练习。创建文件 `exercises/concept/<story-name>/.docs/introduction.md`。该文件的详细内容在[它的规范][exercise-intro-spec]中有说明。你可以用[布尔概念练习的 `introduction.md`][intro-bool]作为起点的模板。

提供的信息应当刚好够介绍这个概念，让学生自己找出练习的解法。使用恰当的技术术语，方便学生在线搜索。尽量少用链接，改为在正文里简洁地解释。用代码块来介绍代码语法。

## 4. 为练习找一个故事

每个概念练习都必须基于一个故事或一个主题。我们知道 Exercism 的用户遍布全球，所以会尽量让故事具有包容性。第一种选择是复用[文档中记录的故事列表][stories]里已有的故事。如果你想创建新故事，尽管在 PR 里 @exercism/leadership。现在你可以把 `exercises/concept/<story-name>/` 目录重命名，与你的故事对应。

## 5. 编写练习说明

故事找到后，就要写出精确的说明，逐一列出学生需要完成的任务。故事和说明都写在 `exercises/concept/<story-name>/.docs/instructions.md` 文档里。正如[该文档的规范][instructions-spec]所说明的，每个任务都有自己的二级 Markdown 标题（`## 1. Do X`），后面跟着描述和示例代码用法。你可以用[布尔概念练习的 `instructions.md`][instructions-bool]作为起点的模板。

除了 `instructions.md`，我们还需要一个 `hints.md` 文件。它应当包含与说明文件相同的二级标题（`## 1. Do X`），这样才能根据学生当前正在做的任务给出相应的提示。还可以有一个 `## General` 小节，放适用于所有任务的提示。提示不应直接写出解法。另外要注意，点击提示的人可能已经被练习搞得困惑、不知所措或沮丧了。关于这个文档的更多信息在[它的规范][hints-spec]里，你可以用[布尔概念练习的 `hints.md`][hints-bool]作为起点的模板。

## 6. 打开一个草稿 PR 来验证设计

现在正是为你的概念练习打开一个草稿 PR 的好时机！我们已经有足够的材料来评估这个练习，并在把它固定成现在这样、继续写其余必需文件之前重新调整它。不用担心 CI 里的自动检查因为缺少文档而失败，那些文档我们稍后会创建！

## 7. 编写代码

我们会像在解这道练习一样写代码，之后再调整文件位置，使其符合规范。先把 [`template/`][template] 目录的内容复制到 `exercises/concept/<story-name>/` 目录里。这样我们就有了下面这些文件：

```txt
elm.json           # elm project configuration file
src/Exercise.elm   # code for the exercise
tests/Tests.elm    # tests for the exercise
```

然后把 `Exercise.elm` 重命名为故事名的大驼峰形式。例如 `annalyns-infiltration` 变成 `AnnalynsInfiltration.elm`。在这个源文件里，你现在可以写下刚才写的 `instructions.md` 中描述的所有函数。

练习实现完成后，更新 `tests/Tests.elm` 文件的内容，加入相关的测试，让它们自然地按照 `instructions.md` 中任务的顺序排列。**请不要在概念练习的测试中使用 `Fuzz`**，因为它与用 `Debug.log` 调试代码的能力配合得不好。请改为加入几个边界情况和一般情况的单元测试。**请不要在概念练习的测试中把 `let` 表达式直接放在 `test` 或 `describe` 函数调用下面**，因为 [elm 测试运行器目前还不支持这样写](https://github.com/exercism/elm-test-runner/issues/30)。

练习和测试都完成、运行良好后，做下面这几件事：

- 把 `src/<ExerciseSlug>.elm` 复制到 `.meta/Exemplar.elm`。你的实现作为参考，也就是这道练习的“示例”实现，运行学习路径测试时会用到它。
- 清空 `src/<ExerciseSlug>.elm` 里所有的实现，只留下一个起始文件，让学生可以开始做练习。

## 8. 编写概念文档

为 `exercises/concept/<story-name>` 练习对应的概念创建 `concepts/<concept>/` 目录。在这个新文件夹里，我们创建两个 Markdown 文档 [`introduction.md`][concept-intro-spec] 和 [`about.md`][concept-about-spec]，以及一个 [`links.json`][concept-links-spec] 文件（链接指向各自的规范）。

`introduction.md` 概念文件包含学生在完成对应概念练习之前，会在概念页面上看到的介绍。它应当让学生对开始该练习后将学到什么有个大致了解。相比之下，`about.md` 概念文件包含学生只在完成对应概念练习之后，才会在概念页面上看到的概念总结。因此，这两个文件的内容与我们已写好的 `exercises/concept/<story-name>/.docs/introduction.md` 文件相似，但并不相同。我建议从练习的介绍文档出发，把它精简到最核心的部分，作为概念的 `introduction.md`。至于 `about.md` 文档，以练习介绍为起点，把它补全，使该页面上包含关于这个概念的所有相关信息。`links.json` 提供关于某个概念的有用链接和补充信息。这些可能是官方文档、很棒的教程等等。这些链接不会取代概念 about.md 文件里更贴近上下文的链接，而是为学生提供一组便捷的总体参考。链接还可以可选地带一个 icon_url 字段，用来在显示链接时自定义图标。如果没有指定，图标默认为 favicon。可用的图标可以在 [github.com/exercism/website-icons/tree/main/exercises][icons] 找到。

## 9. 补全各个配置文件

代码和文档都完成后，就只剩几个配置文件，这个 PR 就完整了：

- [`concepts/<concept>/.meta/config.json`][concept-config-json]：把自己设为作者，把可能的评审者添加为贡献者，并加上“blurb”（简短描述）。
- [`exercises/concept/<story-name>/.meta/config.json`][exercise-config-json]：包含作者（你）、贡献者、blurb 等内容。参考链接到的规范。
- `config.json`：在学习路径的 `config.json` 文件里添加一个[概念条目][track-config-json-concept]和一个[概念练习条目][track-config-json-concept-exercise]。概念练习的 status 键用“wip”或“beta”。UUID 可以用 exercism 提供的 [configlet 可执行文件][configlet]生成。
