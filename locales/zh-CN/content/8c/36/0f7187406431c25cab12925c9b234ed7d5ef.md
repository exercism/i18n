## 协变与逆变

使用联合类型时，你必须了解协变和逆变这两个概念。它们在[文档](https://www.php.net/manual/en/language.oop5.variance.php)中有解释，不过下面的例子可能会有所帮助。

假设我们有一个 Calculator 类，它使用一个类似上面示例的函数：

```php
class Calculator
{
    public function add(int|float $x, int|float $y): int|float
    {
        return $x + $y;
    }
}
```

如果要继承该类，你可以更改形参类型和返回类型，但必须遵循以下规则。

首先，形参类型可以“更宽”，也就是能接受比基类更多的类型。例如，下面这样是允许的：

```php
class StringCalc extends Foo
{
    public function add(float|int|string $x, float|int|string $y): int|float
    {
        if (!is_numeric($x) || !is_numeric($y)) {
            throw new \InvalidArgumentException('$x and $y must be numeric');
        }
        return $x + $y;
    }
}
```

我们可以用`StringCalc`替换原来的`Calculator`，一切仍然能正常工作。调用方仍然可以传入它原本就能传入的`float`或`int`，返回类型也仍然是预期的`int`或`float`。

同样，你也可以缩小返回类型，也就是从联合类型中去掉一些类型，让它更具体。下面这个例子就利用了这条规则：

```php
class IntCalc extends Calculator
{
    public function add(float|int $x, float|int $y) : int
    {
        return (int)($x + $y);
    }
}
```

由于`IntCalc`仍然接受`int`和`float`，它依然可以毫无问题地替换原来的`Calculator`。

想进一步了解哪些允许、哪些不允许，可以参考[里氏替换原则（LSP）](https://en.wikipedia.org/wiki/Liskov_substitution_principle)。

至于不允许的例子，可以看看下面的`InvalidCalc`：

```php
class InvalidCalc extends Calculator
{
    public function add(int $x, int $y) : int|float|string
    {
        // Declaration must be compatible with Calculator->add(x: float|int, y: float|int)

        // Return type declaration must be compatible with Calculator->add(x: float|int, y: float|int) : float|int
    }
}
```

`InvalidCalc`类将无法编译，并且存在两个问题。由于缩小了形参允许的类型，`InvalidCalc`无法替代原来的`Calculator`，因为它不再接受`float`。此外，它现在可能返回`string`，而这也不在原来类允许的返回类型范围内。
