# 异常

有些例程无法作答。被要求给出一个不在表中的属性时，`count_of`没有数字可给，而零又会骗人，因为零的意思是“我们一个都没有”，而不是“根本没有这种东西”。

**异常**就是例程表示自己无法作答的方式。

## 抛出

`raise`会放弃例程，并把一个值交给调用它的那方。

```sather
   count_of(props : FMAP{STR,INT}, prop : STR) : INT is
      if ~props.has_ind(prop) then
         raise "Unknown prop: " + prop;
      end;
      return props.get(prop);
   end;
```

`raise`之后的任何东西都不会运行。例程不会返回，因此没有答案可供检查，调用方也无法当作有答案一样继续下去。

抛出的值通常是一个说明出了什么问题的字符串。

## 捕获

`protect`会运行一段代码，并准备好它可能抛出异常。

```sather
   protect
      taken ::= count_of(props, prop);
      #OUT + "There are " + taken;
   when $STR then
      #OUT + "Cannot: " + exception.str;
   end;
```

如果没有任何东西抛出异常，`protect`之后的部分会运行，`when`分支则被跳过。如果有东西抛出异常，`protect`部分剩下的内容会被放弃，转而运行与之匹配的`when`。

`when $STR then`捕获抛出的字符串。`exception`就是被抛出的那个值，在分支内部可以使用。

## 向外传递

没有捕获异常的例程不必对它做任何处理。它会向外传播，经过每一个调用者，直到有东西把它捕获：

```sather
   take_one(props : FMAP{STR,INT}, prop : STR) : INT is
      -- If this raises, take_one raises too. Nothing here says so.
      have ::= count_of(props, prop);
      ...
   end;
```

这正是异常的意义所在。发现问题的例程和知道该如何处理它的例程通常不是同一个，而中间的所有例程都可以对它不管不顾。
