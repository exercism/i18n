# Unison 基础

## 项和函数

项和函数是编写 Unison 程序的基本单位。

“项”就是我们对静态值的称呼。它的定义形式是`name = expression`，前面可以选择性地加一个形如`name : MyType`的类型签名。Unison 支持类型推断，所以在简单的定义中，类型签名常常被省略。

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison 函数的形式是`myFunctionName argument1 argument2 = myImplementation`：先写函数名，后面跟上以空格分隔的形参。

```
getMax a b = Nat.max a b
```

函数可以可选地带上类型签名。右边最后一个类型始终是函数的最终返回类型，各个形参之间用函数箭头`->`分隔。

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

调用函数时，先写函数名，后面跟上实参，实参之间只用空格分隔。

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

调用函数时，Unison 会尝试把紧跟在右边的内容当作它的实参，而这不一定总能得到你想要的函数求值顺序。

假设我们想从下面这个表达式得到值`1`。

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

按现在的写法，`shouldBe1`的求值结果是`0`，因为隐含的函数应用顺序是`getMax 1 10`，得到`10`，然后计算`10 - 10`，得到`0`。

你可以用括号重新组合表达式，得到想要的运算顺序。

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## 监视表达式

Unison 提供了一种快速给代码求值的方式，叫做“监视表达式”。监视表达式以`>`符号开头，后面跟上要求值的表达式。监视表达式可以写在后缀为`.u`的任何文件里。保存文件后，你应该能在 Unison Codebase Manager（UCM）控制台中看到表达式的求值结果。在这些文档中，只要条件允许，我们都会尽量给出表达式及其在监视表达式中求值后的预期输出。

```
> helloThere
  ⧩
  "Hello, World!"
```

## 多行函数

Unison 的多行函数用缩进或`let`块来划定代码边界，也就是“词法作用域”。

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

处于同一缩进层级的所有内容共享同一个作用域，所以我们才能最后一行引用变量`newBeginning`。

## 命名空间和`use`语句

命名空间是我们对 Unison 函数进行分组和组织的方式。你可以把它类比成“目录”。它们提供了结构和逻辑分组。

你可以用`use`语句把某个命名空间里的函数引入作用域。

假设你正在写一个使用 Unison `List`值的函数。你知道自己会用到`List.map`和`List.flatMap`这样的函数，其中`List`是命名空间，`map`和`flatMap`是函数。为了避免重复书写，你可以像下面这样，把`List`命名空间里的所有内容都引入函数的词法作用域：

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List`这一行消除了对`map`和`flatMap`引用的歧义。你可以阅读更多关于 [`use`语句][use-statements]的内容。

## Unison 的标准库

Unison 的标准库叫做`base`。如果你跟着快速入门指南做，并在本地创建了代码库，那么标准库应该已经自动下载好了。你可以在 [Unison Share][unison-share-base] 上在线浏览标准库文档。

## 注释和文档字面量

Unison 里的注释算是一个有点特别的功能。写 Unison 代码时，你可以在后缀为`.u`的文件里用下面的语法创建不会被解释执行的文本：

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_不过_，由于 Unison 代码是以其抽象语法树的哈希形式保存的，而不是文件系统上的文本文件，因此那些作为文件里某个 Unison 函数或项的文本“装饰”的注释，实际上无法被保存下来，也无法在分享时重新呈现。如果你想以某种能被保存下来、供他人阅读和理解的方式，为你的 Unison 项添加信息，可以使用文档字面量。

在 Unison 编程语言中，文档是一等值。这意味着`Doc`元素可以被赋值给某个值、作为值传给函数，或者作为函数的值返回。文档字面量元素用双大括号开始和结束。下面是我们可能用`Doc`元素来充当注释的写法。

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
