# 简介

在 Gleam 中，可以用 `case`表达式来按条件执行代码。借助 case 表达式，可以拿一个值去和一个或多个_模式_进行匹配。这类模式的一个例子是_字面量模式_，它把值与一个字面量（例如 `1` 或 `"hello"`）进行匹配。

case 表达式用 `case`关键字书写：

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    1 -> "One"
  }
}
```

虽然这看起来像其他语言里的 `switch`语句，但当你同时使用其他模式时，模式匹配才真正开始大放异彩。其中一种模式是_变量模式_，它可以把一个值赋值给一个变量。在下面这个例子里，如果 `number`不是 `0`，变量 `i`就会被赋值为 `number`的值：

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i -> "Non zero"
  }
}
```

有时你可能想给模式附加一个条件。这就是所谓的_守卫_（子句），可以用 `if`关键字来添加：

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
  }
}
```

出于性能方面的考虑，守卫中只允许使用基本的数学运算符和布尔运算符，其他函数不能用在守卫里。

在上面的例子里，并非所有可能的输入都能匹配到模式。编译器会检测到这一点，并输出一个错误。这就是所谓的_穷尽性检查_。要解决这个警告，就必须处理所有情况。为此可以使用_丢弃模式_，它能匹配任何值：

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
    _ -> "Positive number"
  }
}

// No compiler error
```

case 表达式会自上而下地把值拿去和每一个模式逐一匹配，直到找到匹配的模式，并执行与该模式关联的逻辑。模式的顺序很重要！
