# 不可变类

`SCOREBOARD`是会变的东西。同一个记分板的两个名字看到的是同一个分数，因为只有一块板，两个名字都指向它。

方位角不是这样。`350 degrees`不会变成别的什么，它*就是*它本身。数字如此，字符串也是如此，你自己写的类也可以如此。

## immutable

```sather
immutable class BEARING is

   readonly attr degrees : INT;

end; -- class BEARING
```

两个词改变了一切。不可变类的对象是一个**值**，而不是被指向的一个东西：

- 赋值或传递时它会被复制，所以别人改不了你的那份；
- 它永远不会是 void；
- 而且不能给它的属性赋值。

## 再造一个来改变

既然不允许写 `degrees := 90`，`attr`提供的就是别的东西：一个例程，接收新值，并返回一个把该值改好的**新对象**。

```sather
   b ::= b.degrees(90);      -- not b.degrees := 90
```

原来的对象丝毫未动。这就是整个惯用法，`create`也是这样写的：

```sather
   create(d : INT) : SAME is
      b : SAME;                     -- starts with everything at nought
      return b.degrees(d);
   end;
```

这里没有 `new`。不可变对象总是存在的，所以 `b : SAME`本身就已经是一个对象，每个属性都处在它的空值上。

因此，一个"改变"方位角的例程返回的是一个新的方位角：

```sather
   turned(by : INT) : SAME is
      return #BEARING(degrees + by);
   end;
```

## 比较

比较值看的是它装的内容，而不是它是哪个对象，但你必须说明按什么比。写下 `is_eq`，`=`就会用它：

```sather
   is_eq(other : SAME) : BOOL is
      return degrees = other.degrees;
   end;
```

没有它，两个方位角上的 `=`无法编译。

## 该选哪一种

当某个东西没有身份、它的一切都不该合理地改变时，就用不可变类：方位角、点、日期、长度。当某个东西是某个特定的事物、会有事情发生在它身上时，就用普通类：记分板、挽具、文件。

判断标准在于，"相同"指的是"相等"，还是"就是同一个"。
