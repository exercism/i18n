# 提示

## 通用

- 你的解答文件会被包含在另一个文件里，那个文件会调用你的宏。
  每个宏的名称和参数顺序都要与任务给出的完全一致，否则文件无法汇编。
- 宏的参数是记号，在宏体中每处出现的地方都会以 `%1`、`%2`、`%3` 的形式被替换。
  它们可以是寄存器、地址表达式或字面量，只要每次展开都是一条合法的指令即可。
- 每个宏都会被检查它保留了哪些寄存器不变，而不只是看它写入了什么。
  阅读每个任务中的破坏说明，只修改它允许修改的寄存器。

## 1. 命名格式常量

- 单行的 `%define` 可以给一个值取个名字，这样代码的其余部分就能通过这个名字来读取，而不用直接写一个裸数字。
  对于固定的数字，`equ` 也能做到同样的事，而且是常量的常用选择。
- 字节常量既可以写成十六进制（`0x20`），也可以写成字符字面量（`' '`）。
  两者汇编后得到相同的值。

## 2. 编写`fill_run`宏

- 你应该为`rcx`取一个易读的名字`COUNTER`。
- `fill_run`是一个多行宏，接受 3 个参数。
  多行宏用`%macro ... %endmacro`定义。
- `fill_run`的第一个参数是 64 位通用寄存器中的内存地址。
  第二个是计数值，可以通过 64 位通用寄存器传入，也可以作为立即数传入。
  第三个是要写入的一个字节，作为立即数。
  你应该根据这些规定来规划宏中的代码。
- `fill_run`允许修改的寄存器只有`COUNTER`。
- 宏内部的循环通常需要一个以`%%`为前缀的标签。
  没有这个前缀，每次调用宏时都会创建同一个标签，如果宏被调用不止一次，就可能导致错误。

## 3. 编写`lay_columns`宏

- `lay_columns`是一个多行宏，接受 2 个参数。
  多行宏用`%macro ... %endmacro`定义。
- `lay_columns`的两个参数都通过 64 位通用寄存器传入。
  第一个是内存地址，第二个是整数。
  你应该根据这些规定来规划宏中的代码。
- `lay_columns`允许修改的寄存器只有作为参数传入的那两个。
- 宏必须写入的偏移量数量在汇编时就已固定。
  你可以用`%rep ... %endrep`来重复代码。
- 偏移量的计算用`offset[i] = margin + i * COLUMN_STRIDE`完成。
  `margin`是宏的第二个参数。
  `i`是循环计数器，可以定义为一个`%assign`变量。

## 4. 编写`set_header`宏

- `set_header`是一个多行宏，接受 2 个参数。
  多行宏用`%macro ... %endmacro`定义。
- `set_header`的第一个参数是一个有效内存地址的表达式。
  它接受一个基址寄存器，该寄存器可以与按`1`、`2`、`4`或`8`缩放的索引寄存器相加，还要接受一个立即数。
  这意味着单独的`rdi`是合法的，`rdi+rax*4+2`也是。
- `set_header`的第二个参数是一个立即数，取值可以是`0`、`1`或`2`。
- `set_header`完全不能修改任何寄存器。
- 你应该在汇编时根据第二个参数，有条件地把一个字节复制到目标地址。
  值为`0`时应复制`PLAIN`，值为`1`时应复制`RULED`，值为`2`时应复制`BOXED`。
