# 关于

[SIMD][SIMD] 概念引入了打包浮点值：多个数字存放在一个`xmm`寄存器中，按通道并行地进行运算。同样的`xmm`寄存器也可以存放打包的_整数_。

## 语法

SIMD 浮点模型的大部分内容原封不动地适用于打包整数：

- 128 位寄存器被划分为若干通道
- 指令并行作用于处于同一位置的各通道
- 内存操作数遵循相同的 16 字节对齐规则

不过，语法略有不同：

1. 一个_前缀_`p`，表示该指令操作的是_打包_数据。
2. 所执行的操作，其名称与非 SIMD（也称_标量_）版本相同（例如`add`、`mul`等）。
3. 一个后缀，表示每个通道的大小。

打包整数有四种通道大小，每种都有自己的后缀：

| 通道宽度 | 字节 | 128 位中的通道数 | 后缀 |
|------------|-------|-------------------|--------|
| 字节       | 1     | 16                | b      |
| 字       | 2     | 8                 | w      |
| 双字       | 4     | 4                 | d      |
| 四字       | 8     | 2                 | q      |

例如：

| 指令 | 含义 |
|-------------|--------------------------------------|
| `paddb`     | 打包`add`，8 位通道（16 个通道） |
| `paddw`     | 打包`add`，16 位通道（8 个通道） |
| `paddd`     | 打包`add`，32 位通道（4 个通道） |
| `paddq`     | 打包`add`，64 位通道（2 个通道） |

有些指令以某种大小的通道作为输入，却以另一种大小的通道作为输出。它们遵循同样的一般约定，只是带有_两个_大小后缀。第一个表示输入通道的大小，第二个表示输出通道的大小：

| 指令 | 含义 |
|--------------|---------------------------------------------------|
| `pmovsxwd`   | 打包`movsx`，从 16 位通道到 32 位通道 |
| `pmuldq`     | 打包`mul`，从 32 位通道到 64 位通道 |

## 内存移动

有两条以整数命名的指令，用于在`xmm`寄存器与内存之间复制 128 位：

| 指令 | 描述 |
|-------------|---------------------------------------------------------|
| `movdqa`    | 将打包整数复制到_已对齐_的位置，或从该位置复制出来 |
| `movdqu`    | 将打包整数复制到_未对齐_的位置，或从该位置复制出来 |

它们的行为与`movaps`和`movups`一样：`movdqa`在地址未对齐时会报错，而`movdqu`接受任意地址。这四条指令都复制 128 位，不对内容作任何解释。以整数命名的那一对按惯例用于整数数据，这只是约定，而非硬性要求。

~~~~exercism/note
这里的`dq`代表`double-qword`，即 128 位（16 字节）。
~~~~

## 加法/减法

加法和减法遵循命名规则：

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

没有单独的带符号和无符号形式。在补码中，无论把通道读作带符号还是无符号，加法和减法产生的位都相同，所以一条指令就能兼顾两者。如何解读由你决定，与标量的`add`和`sub`完全一样。

这些指令在溢出时会**回绕**，与它们的标量版本一样。8 位通道以 256 为模保存值，所以`paddb`的`200 + 100`会得到`300 - 256 = 44`，多出来的位数被丢弃。

注意，这些多出来的位不会进位到下一个通道。每个通道都与其它通道分开运算，即使它们共用同一个寄存器。

## 饱和加法/减法

整数 SIMD 增加了一种浮点 SIMD 没有的运算：[饱和][saturation]加法和减法，它_钳制_而不是回绕。结果高于通道范围时，会变成该通道能容纳的最大值；结果低于范围时，会变成最小值。

饱和形式在大小后缀前插入`s`（带符号）或`us`（无符号）：

| 指令 | 含义 |
|-------------|--------------------------------------------|
| `paddsb`    | `add`，饱和，带符号 8 位通道      |
| `paddusb`   | `add`，饱和，无符号 8 位通道    |
| `psubsw`    | `sub`，饱和，带符号 16 位通道     |
| `psubusw`   | `sub`，饱和，无符号 16 位通道   |

钳制范围是相应大小和符号性的整数所能表示的完整范围。对于字节：

- 无符号字节钳制到`[0, 255]`：`paddusb`的`200 + 100`得到`255`，`psubusb`的`5 - 10`得到`0`。
- 带符号字节钳制到`[-128, 127]`：`paddsb`的`100 + 50`得到`127`。

当通道保存的是有界量（例如像素通道或音频采样）时，饱和就很重要。回绕会把一个过亮的像素变暗，而钳制会把它保持在最大亮度，这才是你想要的结果。

~~~~exercism/note
饱和加法和减法只对字节和字通道存在，不适用于双字或四字。
~~~~

## 乘法

两个 N 位值相乘可能得到 2N 位的乘积，但目标通道只有 N 位宽。SIMD 运算通过指定保留乘积的哪一半来解决这个问题：要么是低 N 位，要么是高 N 位。

对于 16 位通道，会用到三条指令：

| 指令 | 含义 |
|-------------|---------------------------------------------------------------|
| `pmullw`    | `mul`，16 位通道，保留每个乘积的低 16 位     |
| `pmulhw`    | `mul`，16 位通道，保留高 16 位，带符号操作数   |
| `pmulhuw`   | `mul`，16 位通道，保留高 16 位，无符号操作数 |

乘积的低 16 位无论操作数读作带符号还是无符号都相同，所以只有一条`pmullw`。

然而，高 16 位会随结果的符号性而变化。这就是为什么取高半部分的乘法为带符号和无符号乘法准备了不同的形式：

1. `pmulhw`，用于带符号乘法。
2. `pmulhuw`，多一个`u`，用于无符号乘法。

注意其语法：

1. 一个`p`，表示打包整数。
2. 所执行的操作`mul`。
3. 一个`h`，表示选取结果的高位（“high”）。
4. 一个可选的`u`，表示结果应被解读为无符号（即不进行符号扩展）。
5. 最后是大小后缀`w`，表示这是字（16 位）运算。

字的打包乘法完全遵循上述规则。双字（32 位）乘法也遵循该规则，但只有选取低半部分的变体：`pmulld`。

双字乘法没有选取高位的变体。不过，有些变体会_加宽_乘法，把_偶数下标_通道（即位置 0 和 2 处的通道）的完整 64 位乘积保存下来：

| 指令 | 含义 |
|-------------|----------------------------------------------------------------------------------|
| `pmuludq`   | 将偶数下标的 32 位元素按无符号相乘，得到 2 个完整的 64 位乘积 |
| `pmuldq`    | 将偶数下标的 32 位元素按带符号相乘，得到 2 个完整的 64 位乘积   |

注意，语法中使用了`dq`，在无符号乘法时它前面可能还有一个`u`。这是因为这些指令接受`dword`通道并输出`qword`通道。

## 除法

没有打包整数除法。需要它的代码会把值转换成浮点数，相除，再转换回来。

## 整数加宽

`movsx`和`movzx`有对应的打包版本。它们遵循我们前面提到的、用于输入通道大小与输出不同的指令的同一语法：

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

注意，通道数由较大（输出）的宽度决定。指令会从源的低位部分读取相应数量的通道。这与我们在单精度和双精度浮点数之间的打包`cvt`指令中已经看到的语义相同。

## 整数与浮点数之间的转换

有些指令可以在 32 位带符号整数与浮点通道之间转换。它们遵循`cvt`和`cvtt`指令的常见语法，但用`dq`而不是`si`来表示打包整数：

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
使用`pi`表示打包整数的指令会写入旧式的`mmx`寄存器，在 x86-64 上实际上已被弃用。请优先使用`dq`形式，它们使用`xmm`寄存器。
~~~~

前面关于浮点数与整数之间标量转换的说明，在这里同样适用。浮点数会根据一个名为 MXCSR 的特殊寄存器进行舍入，而在进入函数时你不能假设它的模式。有一个`cvtt`变体（多一个`t`），它总是截断结果。

也可以先用`round`把打包浮点值置于已知状态，然后再转换。舍入控制值与标量`round`相同，打包浮点值的语法也相同：

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
