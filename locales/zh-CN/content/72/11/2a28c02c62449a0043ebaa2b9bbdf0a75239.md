# 简介

## RFLAGs

有一个特殊的寄存器叫`rflags`。
它的各个位就像标志位一样，用来表示各种条件。

下面列出了其中一部分：

| name     | symbol | bit |
| :------- | :----: | :-: |
| carry    |   CF   |  0  |
| zero     |   ZF   |  6  |
| sign     |   SF   |  7  |
| overflow |   OF   | 11  |

## 比较指令

`rflags`中的标志位_并不是_直接被修改的。
相反，它们是由许多不同的指令设置的。

例如，当结果为 0 时，很多算术运算或按位运算都会设置 `ZF`。

最常用来判断条件的指令之一是 `cmp`。
它接收两个操作数并更新标志位，但**不会修改它的操作数**。

### CMP 指令

`cmp`指令用第一个操作数减去第二个操作数，并根据结果设置标志位。

如果 A 是第一个操作数，B 是第二个操作数：

| flag | set when                       |
| :--: | :----------------------------- |
|  CF  | A < B（无符号）                 |
|  ZF  | A == B                         |
|  SF  | A < B（有符号，无溢出）          |
|  OF  | 有符号减法发生溢出               |

## 分支

默认情况下，x86-64 中的代码从上到下顺序执行。

但很多时候需要改变这种行为。
例如，根据某个条件执行另一组不同的指令。

在高级语言中，这通常用 `if...else` 之类的抽象来实现。
但 x86-64 中并不存在这些。

取而代之的是，x86-64 提供了能把执行转移到代码另一处的指令。
这称为`branching`。

~~~~exercism/note
我们已经见过两条这样的指令：`call` 和 `ret`。

调用一个函数时，执行会从调用方转移到被调用的函数。
而在返回时，执行又会转移回调用方。

如果找不到 `ret`，执行就会从当前函数直接顺序进入下一个函数。
有时可以利用这一点来优化代码的执行流程。
~~~~

### 无条件跳转

**jmp** 指令会无条件地把程序的执行转移到代码的另一点。
它只有一个操作数，即一个标签，这个标签给出了执行将继续的位置的地址。

例如，看看下面这个函数：

```x86asm
fn:
    mov rax, 5
    jmp end

    add rax, 10
end:
    ret
```

调用 `fn` 时，执行从 `mov rax, 5` 开始。
此时`rax`的值被设为 5。

下一条指令是 `jmp end`，它把执行转移到标签 `end`。

`end` 之后的下一条指令是 `ret`，它把执行转移回调用方函数。

注意，由于 `add rax, 10` 位于 `jmp end` 之后、`end` 之前，它永远不会被执行。
`fn` 返回时，`rax` 的值是 5。

### 条件跳转

**jcc** 这一系列指令只在满足特定条件时，才把程序的执行转移到另一点。
否则，执行会顺序继续下去。

每个条件都对应 `rflags` 中的一个或多个标志位。
有些 `jcc` 变体检测某个标志位是否置位，另一些则检测它是否清零。

`jcc`中的`cc`并不是字面的，而是指与被检测的标志位相关联的那个具体后缀。

后缀有很多，其中许多检测的条件和另一个后缀相同。
其中一些直接对应某个标志位，因此如果该标志位置位，指令就会跳转到某个标签：

| suffix | jumps if |
| :----: | :------: |
|   z    | ZF == 1  |
|   c    | CF == 1  |
|   s    | SF == 1  |
|   o    | OF == 1  |

还有很多后缀是为了表示它们在 `cmp` 指令中的含义而选择的。
例如：

| instruction | suffix | jumps if         |
| ----------- | :----: | :--------------- |
| cmp A, B    |   e    | A == B           |
| cmp A, B    |   l    | A < B（有符号）   |
| cmp A, B    |   b    | A < B（无符号）   |
| cmp A, B    |   g    | A > B（有符号）   |
| cmp A, B    |   a    | A > B（无符号）   |

可以在 `l`、`b`、`g` 或 `a` 后面加上 `e`，把相等的情况也包括进条件里：

```x86asm
cmp rcx, r8
jge two      ; this jumps to 'two' if rcx is greater than, or equal to, r8 in a signed comparison
jbe two      ; this jumps to 'two' if rcx is lesser than, or equal to, r8 in an unsigned comparison
```

对于所有后缀，都有检测相反情况的变体。
它们的语法相同，只是在后缀前多一个 `n`。

例如，当 `ZF` **没有**置位时，`jnz` 会跳转。
同样，当 A 与 B 不满足 >= 关系时（这里把 A 和 B 当作无符号整数），`jnae` 会跳转。

~~~~exercism/note
有些后缀是相同条件的别名。
例如，`jz`（后缀 `z`，对应 `ZF`）和 `je`（后缀 `e`，表示相等）在 `ZF` 置位时都会跳转。
这是因为在用 `cmp` 时，减法结果为零就会设置 `ZF`，而这正对应两个操作数相等的情况。

不过，另一些后缀检测的是多个标志位的组合，不能直接用某个单一标志位的后缀代替。

优先选择更能表达你的比较语义的后缀。
~~~~

## 局部标签

标签在整个源文件中都可见，它们并不是函数局部的。
因此无法重复使用同一个标签名。

为了模拟局部标签的行为，NASM 为在名字前面加一个句点（`.`）声明的标签提供了一种特殊写法。
这种写法定义的标签会隐式地包含上一个不带句点的标签名：

```x86asm
section .text
fn1:
    ...
.example: ; this is fn1.example
    ...
    ret

fn2:
    ...
.example: ; this is fn2.example
    ...
    ret
```

仍然可以在代码的任何位置，使用完整的标签名跳转到这个标签，例如 `jmp fn1.example`。

不过，如果跳转时只用到从句点开始的那部分标签名，那么跳转的目标会是上层函数_内部_的那个标签。
例如，`.example` 的行为就像它是该函数的局部标签一样：

```x86asm
section .text
fn1:
    ...
.example:
    ...
    jmp .example ; this jumps to fn1.example

fn2:
    ...
.example:
    ...
    jmp .example ; this jumps to fn2.example
```
