# 契约

例程的实参和返回类型说明了进去和出来的是*哪一类*东西。它们无法说明重量必须为正，也无法说明一个测试框架报告的空闲容量永远不会超过它实际拥有的数量。

**契约**就在例程自己的头部说明这些事，任何读到它的人都能看到。

## pre

`pre`说明调用例程时必须成立的条件。它写在返回类型和`is`之间。

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

这是对**调用方**的要求：不要用负的 load 调用它。

## post

`post`说明例程返回结果时必须成立的条件。在它里面，`result`就是被返回的值。

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

这是对调用方的承诺。同时具备两者的例程就是一笔交易：你给我这个，我就给你那个。

多个条件用`and`连接，就像任何布尔值一样：

```sather
      pre load >= 0 and load <= limit
```

## 契约不是异常

抛出的异常针对的是可能发生的事。契约被违反就意味着一个**bug**：有人错误地调用了例程，或者例程没有做到它说过的事。

所以，契约被违反并不会抛出可捕获的东西。打开契约检查时，程序会停下来，并打印出是哪个例程、哪个条件。关闭契约检查时，条件根本不会被检验，程序会继续跑下去，进入随之而来的任何混乱之中。

这就是为什么契约是对正确性的判定，而不是处理错误输入的方式。如果错误输入是预料之中的，就检查它并`raise`。如果错误输入意味着调用方出了问题，就用`pre`说明。

## 打开检查

这个 Sather 在编译器收到`-chk`时会检查契约：

```
sacomp -chk mine.sa -main MAIN -o mine
```

没有它，`pre`和`post`就只是编译器读过、并认定格式正确的文档，仅此而已。这个练习的测试是在没有`-chk`的情况下构建的，所以它们没法替你抓到被违反的契约；它们检查的是例程在被正确使用时是否做了该做的事。
