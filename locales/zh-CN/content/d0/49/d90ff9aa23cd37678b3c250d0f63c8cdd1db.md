# 关于

程序员通常都想写出完美的软件，但通常都做不到。

事情总会在意料之外出错，我们得有能力应对这些情况。

有些语言的设计者认为，首要任务是尽快检测出错误，然后带着一条有助于调试的提示信息终止运行。

数据科学类的语言往往采取更细腻的做法。有些错误严重到必须立即终止，但很多时候，更好的做法是把问题标记下来留待以后处理，然后继续运行。

我们在 [空无][nothingness] 概念中看到，Julia 为有问题的值提供了各种占位符：[`missing`][nothing]、[`NaN`][NaN] 和`Inf`。在具体情况下，这些做法是否比终止程序更合适，得由程序员自己判断。

在深入细节之前，先说明一下术语：Julia 的文档基本上把“错误”和“异常”这两个词当作可以互换的说法。下面的内容可能也同样前后不一致。

## 标准错误类型

学到这里，你一定已经见过 Julia 的许多错误信息了。例如：

```julia-repl
julia> Int(3.14)
ERROR: InexactError: Int64(3.14)
```

把浮点数转换成整数会损失精度，所以会得到`InexactError`。

`InexactError`是一种类型，是 Julia 内置的几种标准类型之一（[目前有 25 种][errors]）。它们全都是`Exception`的子类型：

```julia-repl
julia> supertype(InexactError)
Exception
```

## `throw()`

有些标准错误类型，在你自己的代码里生成可能很有用。

和所有具体类型一样，这些错误也有构造函数。它们接受的实参各不相同，所以想用哪个，先查一下对应的[文档][errors]。

```julia-repl
julia> DomainError(42, "out of range")
DomainError(42, "out of range")
```

要使用这个错误，把构造函数包在 [`throw()`][throw] 函数里：

```julia-repl
julia> throw(DomainError(42, "out of range"))
ERROR: DomainError with 42:
out of range
```

## `error()`

如果想图省事，[`error()`][error] 函数会很方便。它接受一个字符串（或者字符串的各个组成部分）作为实参：

```julia-repl
julia> happy = false;
julia> happy || error("😞 something went wrong")
ERROR: 😞 something went wrong
```

## 自定义错误

创建新的错误类型原则上非常简单。只要再加一个`Exception`的子类型就行：

```julia-repl
julia> struct MyError <: Exception end

julia> throw(MyError)
ERROR: MyError
```

不过，上面的例子没有任何字段，构造函数也不接受实参，所以我们无法控制错误信息。我们可以加一个消息字段：

```julia-repl
julia> struct AnotherError <: Exception
           msg::String
       end

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError("Wrong!")
```

只是把构造函数打印出来还不太对。对比一下前面抛出`DomainError`的那个例子。

要让自定义错误像内置错误那样被处理，我们需要添加一个 [`showerror()`][showerror] 方法：

```julia-repl
julia> Base.showerror(io::IO, e::AnotherError) =
           print(io, "AnotherError: ", e.msg)

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError: Wrong!
```

这个文档写得相当简略的功能，本质上就是把我们的自定义错误类型接入 Julia 的标准错误处理系统。

## 断言

断言的基本想法是：“这个判定应该为真，所以如果它为假，就大声报错。”它的价值主要体现在调试阶段，因为生产代码绝不应该断言失败。

我们在[类型][types]概念中看到，可以添加类型断言，比如用来检查函数的返回类型。

```julia-repl
julia> 42::Number
42

julia> "two"::Number
ERROR: TypeError: in typeassert, expected Number, got a value of type String
```

更一般地说，[`@assert`][assert] 宏让我们可以检验任何求值为布尔值的表达式：

```julia-repl
julia> n = 22;
julia> @assert isodd(n) "n must be odd"
ERROR: AssertionError: n must be odd
```

## `try`...`catch`

有些错误必然是致命的，但很多时候我们期望程序能从容地恢复过来。

默认情况下，错误会立即终止当前函数，然后这个错误（连同提示信息）被传给调用它的那个函数。这样一路上溯调用栈，直到顶层代码带着错误信息终止。

在任何阶段，都可以用 [`try...catch`][try-catch] 块拦截这个错误，尝试处理它。

```julia-repl
julia> n = -1;
julia> try
           log_n = log(n)
       catch problem
           if problem isa DomainError # number out of range
               # See next section for more on @warn and @info
               @warn "you may have supplied a negative real number: $n"
               @info "trying with complex argument"
               log_n = log(Complex(n))  # fallback calculation

           elseif problem isa MethodError # no idea what n is
               @error "please supply a valid argument"
 
           else
              rethrow() # the error could be anything else
           end
      end
┌ Warning: you may have supplied a negative real number: -1
└ @ Main REPL[3]:5
[ Info: trying with complex argument
0.0 + 3.141592653589793im  # success
```

在上面的例子里，`log(n)`要求`n`要么是正实数值，要么是任意复数值。`try ... catch`会捕获负实数值引起的问题，并以数学记号返回正确的复数答案`iπ`。

比如你传入一个字符串实参，那就没有别的办法恢复，只能请用户改正。

作为最后的兜底，我们为既不是`DomainError`也不是`MethodError`的情况加上了 [`rethrow()`][rethrow]。

还有几个可选的子句：

- [`else`][else]，在`try`子句成功时运行；
- [`finally`][finally]，无论`try`成功还是失败，都可以用它清理外部资源：关闭文件、断开数据库连接……

***注意：***有时候`try...catch`确实正是你需要的，但请避免过度使用它。如果能改用`if...else`块，性能会比捕获异常好得多。

## 日志

注意，前面讨论的`error()`函数不要和 [`@error`][error_macro] 宏搞混。

这个函数会生成一个异常，如果没被捕获，它就会沿调用栈向上传递。

`@error`宏，以及与之对应的 [`@debug`][debug_macro]、[`@info`][info_macro] 和 [`@warn`][warn_macro]，都属于 [`Logging`][logging] 模块，用来在不改变程序流程的前提下生成提示信息。

输出默认发往终端（按严重程度用颜色区分），不过在真实的应用里还有很多别的可能。

```julia-repl
julia> @warn "Something looks not quite right"
┌ Warning: Something looks not quite right
└ @ Main REPL[55]:1

julia> @error "Panic!"
┌ Error: Panic!
└ @ Main REPL[56]:1
```
