# 提示

## 概述

这个练习有很多种可能的解法，你也可以沿着许多不同的路径前进。没有哪条路明显比另一条“更好”，不过某条路可能更有意思，或者更适合你当下想学、想探索的东西。有些路径会用速度换取清晰，有些则会占用更多内存，却更具扩展性或更易维护。我们鼓励你多尝试几种策略，看看会发生什么。

_______
-  Python 有一套很强大的字符串处理工具。[`str.split`][str.split]、[`str.replace`][str.replace]、[`str.lower`][str.lower]和[`str.strip`][str.strip]在这个挑战中可能特别有用。
-  字符串方法可以链式调用（_只要该方法返回的是`str`_）。
-  虽然 `str.split()` 非常_有针对性_，但 `str.strip()` 的行为不同，它允许多种组合。
-  [`string`][string]模块（与`str`不同）包含一些常量，在处理字符串时对过滤和比较很有用。
________

-  [字典][dict]在字符串中某个条目（键）多次出现时，很方便用来做统计。
-  当字典中可能缺少某个键时，[`dict.setdefault()`][dict.setdefault]可以在处理时帮上忙。
-  [Collections][collections] 模块为核心`dict`（字典）实现了一些非常有用的子类型，专门用于[计数][collections.counter]这类操作。
________
-  探索[`re`][re]模块和正则表达式可能很有趣，但解决这个挑战并不一定需要它们。
-  [Regex101][regex101] 对试验正则表达式的逻辑非常有帮助。
-  [`re.sub`][re.sub]和[`re.findall`][re.findall]都是值得一试的有趣策略。
________
-  [推导式][comprehensions]常常可以“压平”那些把条目追加到列表或插入字典的循环。
-  [生成器表达式][generator expressions]在需要可迭代对象时，常常可以“替代”列表推导式。生成器表达式采用“惰性”求值，占用的内存比对应的列表推导式更少。
