# 测试生成器

测试生成器让 track 可以自动生成测试，无需我们自己动手编写。每个测试生成器都会读取练习的 `canonical data`，其中定义了测试的名称、输入和输出。想进一步了解 Exercism 处理测试套件的方式，可以看[这里](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md)。

自动生成测试可以避免创建测试时出现的各种人为错误。我们希望测试与其规范数据保持准确一致。测试生成还让测试的更新变得轻松许多。当规范数据发生变化时，只要运行该测试对应的生成器，测试就会自动更新。

规范数据文件的示例可以在[这里](https://github.com/exercism/problem-specifications/blob/master/exercises/bob/canonical-data.json)找到

## 常见术语

在查看规范数据和生成器代码库时，我们会用到很多常见术语。下面这份清单希望能说明它们各自代表什么。

* 规范数据：表示整个测试套件。
* 规范数据用例：单个测试用例的表示。
* 描述：测试的名称。
* 属性：运行测试时要调用的方法。
* 输入：测试用例的输入。
* 期望值：运行测试用例时的期望值。

## 添加一个简单的生成器

添加测试生成器很简单。只要在 `generators` 文件夹的 `Generators.fs` 文件里添加一个以练习名（PascalCase）命名的类，并继承 `GeneratorExercise` 抽象类即可。

一个简单的生成器示例就是 Bob 练习。源代码见下方，你也可以在代码仓库中查看，见[这里](https://github.com/exercism/fsharp/blob/master/generators/Generators.fs#L174)。

```fsharp
type Bob() =
    inherit GeneratorExercise()
```

这就是一个完整可用的生成器，不需要再写任何其他代码。不过，它之所以这么简单，是因为这个测试套件和程序本身都比较简单。

## 添加一个复杂的生成器

对许多生成器来说，`GeneratorExercise` 类的默认行为已经足够。不过，对于更_复杂_的生成器，可以重写它的一个或多个虚方法：

### 方法：RenderInput

渲染测试方法的输入。

#### 示例

`Gigasecond` 生成器会把输入值渲染成一个（带括号的）`DateTime` 值：

```fsharp
override __.RenderInput (_, _, value) =
    DateTime.Parse(string value, CultureInfo.InvariantCulture)
    |> DateTime.renderParenthesized
```

注意，你可以利用 `key` 字段，只为特定的输入字段自定义输出。`Yacht` 生成器就是这么做的：

```fsharp
override __.RenderInput (canonicalDataCase, key, value) =
    match key with
    | "category" -> Obj.renderEnum "Category" value
    | _ -> base.RenderInput (canonicalDataCase, key, value)
```

### 方法：RenderExpected

渲染测试方法的期望值。

#### 示例

`Connect` 生成器会把期望值渲染成 `Option<T>` 值：

```fsharp
override __.RenderExpected (canonicalDataCase, key, value) =
    match string value with
    | "O" -> "(Some White)"
    | "X" -> "(Some Black)"
    | _   -> "None"
```

### 方法：RenderSut

渲染被测系统（SUT）。它就是要与期望值进行验证的实际值。

#### 示例

`RunLengthEncoding` 生成器有一个测试用例，用来验证先对输入编码、再解码后会得到相同的值。这里重写了 `RenderSut` 方法，把原本对并不存在的 `consistency` 函数的一次调用，转换成一条 `encode |> decode` 的调用链：

```fsharp
override this.RenderSut canonicalDataCase =
    match canonicalDataCase.Property with
    | "consistency" ->
        let parameters = this.RenderSutParameters canonicalDataCase |> String.concat " "
        sprintf "%s |> encode |> decode" parameters
    | _ ->
        base.RenderSut canonicalDataCase
```

### 方法：RenderArrange

渲染测试方法的准备部分。在这一部分中，会创建 SUT。

默认行为通常就是你想要的。只有在非常特殊的情况下，你才需要修改它。

注意：这个方法返回一个 `string list`，其中每个 `string` 对应测试文件中渲染出来的一行。

### 方法：RenderAssert

渲染测试方法的断言部分。在这一部分中，会进行断言，用期望值来验证 SUT。

默认行为通常就是你想要的。只有在非常特殊的情况下，你才需要修改它。

注意：这个方法返回一个 `string list`，其中每个 `string` 对应测试文件中渲染出来的一行。

### 方法：RenderSetup

渲染任何额外的工具/设置方法。可以用它来定义可在测试方法中使用的辅助方法。

设置代码会添加在测试方法_之前_，这样测试方法就能使用这些设置方法。

注意：这个方法返回一个 `string list`，其中每个 `string` 对应测试文件中渲染出来的一行。

#### 示例

`Zipper` 生成器添加了两个辅助方法，供测试方法使用，以去掉一些繁琐的样板代码：

```fsharp
override __.RenderSetup _ =
    [ "let subTree value left right = Some (tree value left right)"
      "let leaf value = subTree value None None" ]
    |> String.concat "\n"
```

### 方法：RenderValue

渲染单个值（用于渲染输入形参、期望值和 SUT）。

### 示例

`ComplexNumbers` 生成器会根据值的类型渲染不同的值：

```fsharp
override __.PropertiesWithIdentifier canonicalDataCase =
    match canonicalDataCase.Expected.Type with
    | JTokenType.Array -> ["sut"]
    | _ -> base.PropertiesWithIdentifier canonicalDataCase
```

### 方法：MapCanonicalDataCase

映射规范数据用例。如果你想添加或删除属性，这会很有用。

默认行为通常就是你想要的。只有在非常特殊的情况下，你才需要修改它。

#### 示例

`ScaleGenerator` 生成器利用规范数据用例映射，把缺失的属性以 `null` 值补上（这样后续处理会更方便）：

```fsharp
override __.MapCanonicalDataCase canonicalDataCase =
    let input = canonicalDataCase.Input
    match Map.tryFind "intervals" input with
    | Some _ -> canonicalDataCase
    | None   -> { canonicalDataCase with Input = Map.add "intervals" null input }
```

### 方法：PropertiesUsedAsSutParameter

指定哪些属性应作为 SUT 的形参。

默认行为通常就是你想要的。只有在非常特殊的情况下，你才需要修改它。

#### 示例

`RailFenceCipher` 显式定义了用作 SUT 形参的属性，以改变它们传入的顺序：

```fsharp
override __.PropertiesUsedAsSutParameter _ = ["rails"; "msg"]
```

### 方法：PropertiesWithIdentifier

指定哪些属性应该被赋予标识符。如果某个属性在这个列表中，它的值会在单独的一行上赋给它自己的标识符。

#### 示例

`Transpose` 生成器选择为所有属性都使用标识符：

```fsharp
override this.PropertiesWithIdentifier canonicalDataCase = this.Properties canonicalDataCase
```

### 方法：IdentifierTypeAnnotation

某些情况下，你会希望标识符带有显式类型。一个常见的用例是值为空列表时。在这种情况下，FsUnit 需要类型标注才能成功执行断言。

#### 示例

`Minesweeper` 生成器会为空值添加 `string list` 类型标注：

```fsharp
override __.IdentifierTypeAnnotation (_, _, value) =
    match Seq.isEmpty value with
    | true  -> Some "string list"
    | false -> None
```

### 方法：AdditionalNamespaces

返回一个列表，列出要在测试文件中打开的其他命名空间。

#### 示例

`Gigasecond` 生成器要处理 `DateTime` 实例，因此把它的命名空间加入其他命名空间列表：

```fsharp
override __.AdditionalNamespaces = [typeof<DateTime>.Namespace]
```

### 方法：AssertTemplate

要使用的断言模板。完整的断言模板列表可以在 `generators/Templates/_Assert*.liquid` 中找到

#### 示例

`RationalNumbers` 生成器使用 `"AssertEqualWithin"` 模板，以便在特定容差范围内比较双精度浮点数是否相等：

```fsharp
override __.AssertTemplate canonicalDataCase =
    match canonicalDataCase.Expected.Type with
    | JTokenType.Float -> "AssertEqualWithin"
    | _ -> base.AssertTemplate(canonicalDataCase)
```

### 方法：TestFileFormat

测试文件的格式：模块或类。

默认行为几乎总是你想要的。只有在极其罕见的情况下，你才需要修改它。

#### 示例

`Grep` 生成器把自己定义为测试类，以便使用设置与清理方法：

```fsharp
override __.TestFileFormat = TestFileFormat.Class
```

### 方法：TestMethodName

指定测试方法的名称。

默认行为通常就是你想要的。只有在非常特殊的情况下，你才需要修改它。

#### 示例

`Zipper` 生成器会对测试方法名做一些清理：

```fsharp
override __.RenderTestMethodName canonicalDataCase =
    let testMethodName = base.RenderTestMethodName canonicalDataCase
    testMethodName.Replace("Set_", "Set ")
```

### 方法：UseFullMethodName

指示所使用的测试方法名是否应使用完整路径，也就是说，对于嵌套的测试用例，会在测试方法名前加上父级描述。

默认行为通常就是你想要的。只有在否则会出现多个同名测试方法的情况下，你才需要修改它。

#### 方法：Signature

`KindergartenGarden` 生成器使用完整方法名来防止测试方法名冲突：

```fsharp
override __.UseFullMethodName _ = true
```

### 方法：SkipTestMethod

指示是否应给测试方法标记 `Skip = true` 属性。

默认行为几乎总是你想要的。只有在极其罕见的情况下，你才需要修改它。

#### 方法：Signature

`Markdown` 练习是一个重构练习，因此它的所有测试本就应当处于有效状态。所以，它不会为任何测试方法添加 `Skip` 属性：

```fsharp
override __.SkipTestMethod (_, _) = false
```

## 更新现有文件

现有的练习有可能与规范数据不一致。为了让练习符合规范数据，更新练习存根和/或练习示例是完全可以的！

另外，如果你发现某个现有生成器或测试套件有问题，只要打开你想更新的生成器，做出修改，然后运行生成器即可。

## 运行生成器

这个代码仓库基于[.NET Core 2.x](https://www.microsoft.com/net/core)编写。要运行生成器，你只需在 generators 目录中运行以下命令：

`dotnet run`

这条命令会取用所有已定义的练习生成器，并为每个练习生成全部测试用例。我们使用反射来获取所有练习，所以如果你要添加一个新测试，运行生成器时它会自动被包含进来。

如果你只需要运行单个生成器，可以运行以下命令：

`dotnet run -e <exercise>`

运行完生成器后，你可以打开该练习的测试文件，查看生成结果。举例来说，Bob 练习的测试套件位于：

`exercises/bob/BobTests.fs`

## 提交生成器

如果你对自己生成器的输出感到满意，我们非常希望你能提交一个 pull request！请附上你的生成器、更新后的测试套件，以及你可能改动过的其他相关文件。
