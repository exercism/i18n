# 提示
`Either`的一个常见用途是表示一个可能出错的计算
（如果实际错误无关紧要，那么更简单的`Option`类型可能是更好的选择）。
没有错误时，结果通常是一个`Right`（助记：即“正确”的那个值），
而错误则是一个`Left`，例如一个包含错误信息的`Left[String]`。
注意，在 Scala 2.12 中，`Either`默认是右偏的，因此对于`filter`、`map`、`flatMap`这类操作，或者在 for 推导式中，它的行为都符合预期。
如果你不熟悉`Either`，可以阅读[这篇教程](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html)。但要注意，这篇教程讲的是 2.12 之前的 Scala 版本。如果你用的是 Scala 2.12，可以放心忽略`RightProjection`，并省略`.right`。
`Either`是一种所谓的 [Monad](https://en.wikipedia.org/wiki/Monad_(functional_programming))，它涵盖了一个“计算层面”，在这里就是错误处理。
正确使用 Monad 可以写出非常简洁、优雅且易读的代码。用得不恰当则很容易适得其反。
想了解更多，可以看看[这个视频](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA)。
## 你应该避免的常见坑
对于`Either`，有几条经验法则：
1. 不需要就不要用。与其写成
```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```
不如写成
```scala
def add1(x: Int): Int = x + 1
```
（有`Either.map`可以应用这类简单的函数，
所以不必用`Either`把它们弄得乱糟糟的）。
2. 不是真的需要，就不要“拆包”。
通常已经有现成的内置函数能满足你的目的。过早拆包的标志是`isLeft/isRight`或模式匹配。例如，与其写成
```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```
不如写成
```scala
x fold (identity, _ + 1)
```
3. Monad 可以放进 for 推导式里用，这才是王道。
当你想“组合”多个`Either`实例时，推荐这样做。与其写成
```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```
不如写成
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
