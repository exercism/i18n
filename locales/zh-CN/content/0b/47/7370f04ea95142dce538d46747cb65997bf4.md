# 引言

条件语句这个概念介绍了 `jcc`，即根据条件进行分支的一族指令。`jcc` 只有在满足自身条件时，才会把执行权转移到程序中的另一个位置。

不过，现代 CPU 速度很快，能够并行执行许多指令。如果让所有工作都停下来，等 CPU 检查完运行时的条件再继续，代价就太高了。

正因如此，CPU 在内部并不会等待。它用**分支预测器**来猜测条件的结果，并开始_推测性地_执行预测的那条路径。

如果预测正确，执行就照常进行，仿佛根本没有分支。但如果预测错误，CPU 就必须_丢弃在预测路径上已完成的工作_，改从正确的路径重新开始。

这被称为**分支预测错误**，代价很高，会带来延迟。

当分支难以预测时，这些预测错误就会不断累积。这时，有时宁可完全避开分支，让同一组指令无论条件如何都执行。像这样不用 `jcc` 在多个值之间做选择的代码，称为**无分支**代码。

有多种办法可以把代码组织得分支更少，或者让它仅有的那些分支更容易预测。其中，x86-64 提供了两族指令，常被用来编写无分支代码。

## 条件移动

`cmovcc` 这一族指令，只在满足特定条件时，才把源操作数复制到目标操作数。否则，目标操作数保持不变。

`cc` 后缀的命名方式与 `jcc` 相同，含义也相同：

| 指令 | 满足以下条件时移动 |
|-------------|--------------------------------------|
| `cmove`     | `cmp A, B`之后 A == B |
| `cmovne`    | `cmp A, B`之后 A != B |
| `cmovl`     | `cmp A, B`之后 A < B（有符号） |
| `cmovb`     | `cmp A, B`之后 A < B（无符号） |
| `cmovg`     | `cmp A, B`之后 A > B（有符号） |
| `cmova`     | `cmp A, B`之后 A > B（无符号） |

这些规则与 `jcc` 类似：

1. `l` 和 `g` 用于有符号比较，`b` 和 `a` 则用于无符号比较。
2. 在后缀中加上 `e`，表示把相等的情况也算进去。
3. 加上 `n` 则对条件取反。
4. 还有一些变体指的是标志位被置位的情况。
   例如 `cmovz` 和 `cmovc`。

来看一个例子：求 `rdi` 中有符号整数的绝对值，结果通过 `rax` 返回。
用 `jcc` 编写时，这个函数会在两条路径中选择一条：

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

用 `cmovcc` 编写时，两个候选值都会无条件地计算出来，再由条件移动指令挑出其中一个：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

无分支版本始终执行同样的指令，没有 `jcc` 可供预测器去猜测。

`cmovcc` 的目标操作数必须是寄存器。源操作数可以是寄存器或内存位置，但不能是立即数。

~~~~exercism/note
在上面的代码中，`neg` 指令会根据结果设置多个标志位，其中包括符号标志（SF）。这意味着 `cmp rdi, 0` 完全可以省略：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

对于正的 `rdi`，`neg` 会得到负的结果，SF == 1，因此 `cmovs` 会把 `rdi` 恢复回来。
对于零或负的 `rdi`，`neg` 得到的是非负结果，SF == 0，因此 `rax` 保留取负后的值（这正是正确的绝对值）。

虽然 `cmp` 是比较汇编代码中数值的主要方式，但许多指令也会根据自身的结果设置标志位。
一条指令会影响哪些标志位，通常会在它的[参考文档][reference]中完整列出。
具体到 `neg`，这些标志位是 SF、ZF、CF、OF 和 PF。

[reference]: https://www.felixcloutier.com/x86/
~~~~

## 条件设置

`setcc` 这一族指令，在满足特定条件时把目标操作数设为 `1`，否则设为 `0`。
目标操作数始终是一个_8 位操作数_。

`cc` 后缀的命名方式与 `jcc` 和 `cmovcc` 相同。
例如，`setz` 在 `ZF == 1` 时把目标操作数设为 `1`，否则设为 `0`。

由于目标操作数是 8 位的，所以当需要更宽的值时，通常会在 `setcc` 后面跟一条 `movzx`：

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

这是把比较结果变成一个整数 `0` 或 `1` 的常见写法。
