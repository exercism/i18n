# 简介

海岸巡逻艇上的*信号员*负责维护消息日志。原始信号旗送来时，两侧框着标记字符；读数需要渲染成适合线路传输的形式；成对、成三的观测结果则要随手汇总。大部分工作都由 Factor 标准库里的几个惯用法完成。

## `unparse`：从值到源码

[`unparse`][unparse]（位于`prettyprint`）返回任意值的源码形式文本：

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse`是解析器的逆操作：往返一次`dup unparse parse`就能重建原来的值。要把数据序列化成接收方能解析回来的线路格式，它是合适的工具；但要生成人类可读的输出，它就不合适了（字符串会带着引号，向量也保留`V{ ... }`，等等）。

## 切片变体：视图，而非副本

`head`和`tail`（来自`sequences`）会把要保留的部分*复制*到一个新的序列里。带`-slice`后缀的对应版本则返回一个`slice`对象：它是一个元组，里面装着起始下标、结束下标和底层序列，能在不复制的情况下实现[序列协议][sequence-protocol]：

| 词            | 效果                                             |
|---------------|--------------------------------------------------|
| `head`        | `( seq n -- newseq )`，复制前 n 个                |
| `head-slice`  | `( seq n -- slice )`，前 n 个的视图               |
| `tail`        | `( seq n -- newseq )`，从下标 n 起复制            |
| `tail-slice`  | `( seq n -- slice )`，从下标 n 起的视图           |
| `head*`       | `( seq n -- newseq )`，复制除最后 n 个以外的所有元素 |
| `head-slice*` | `( seq n -- slice )`，除最后 n 个以外所有元素的视图 |
| `tail*`       | `( seq n -- newseq )`，复制最后 n 个              |
| `tail-slice*` | `( seq n -- slice )`，最后 n 个的视图             |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

`slice`*本身就是*一种序列，所以凡是接受序列的地方都接受切片：`length`、`first`、`each`等等都能在不复制的情况下直接工作。需要和字面字符串比较的测试，可以用`>string`强制转换。

## `?head` 和 `?tail`：有标记就剥掉

带框的读数会附带标记文本，而这些文本不一定存在。`?head`和`?tail`（位于`splitting`）会尝试剥掉前缀或后缀，返回（可能变短的）序列，*以及*一个布尔值，说明是否找到了标记：

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

末尾的布尔值让它们很适合当作守卫：把`?head`和`if`搭配，就能根据帧是否存在来分支；搭配`unless`，则可以拒绝缺少预期标记的输入。

## `<repetition>`：N 个副本，虚拟生成

[`<repetition>`][repetition]（位于`sequences`）是另一个不复制元素的虚拟序列：`( len elt -- repetition )`会构造一个由`len`个元素组成的序列，这些元素全都是`elt`，而不必真的分配那么多槽位：

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

`elt`本身也可以是一个序列，此时每个副本都是同一个序列。再用`concat`把这些副本首尾相接：

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

和`slice`一样，结果*本身就是*序列，`length`、`each`之类的词都能直接对它操作。当你要把信号码补齐到固定宽度，或者铺出一串重复的标记时，就可以用它；只有确实需要一个具体的序列时，才用`>string`（或`>array`）强制转换。

## `<clumps>`：重叠的窗口，虚拟生成

[`<clumps>`][clumps]（位于`grouping`）是第三个不复制元素的虚拟序列：`( seq n -- clumps )`把`seq`看作一系列覆盖它的、*相互重叠*且长度为`n`的窗口，每个窗口都是一个切片：

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

一个长度为 n 的序列会产生`length - n + 1`个窗口。因为每个窗口都是切片，把相邻的读数配对不需要任何复制：对每个`2`-clump应用`[ first2 ]`，就能得到每一对相邻元素，供你投影。（它那位不重叠的表亲`<groups>`则把序列切成互不相交的块。）

## 多输入的 cleave：`2bi`、`3bi`、`2tri`、`3tri`

普通的 cleave 词`bi`和`tri`把两三个引述应用到*一个*输入上。带`2`前缀和`3`前缀的变体则把每个引述应用到*两*个或*三*个输入上：

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

每个引述都会收到*全部*输入。当有多个投影依赖同一对（或同一组三个）值时，就用这些词；如果你想对每个输入分别应用*同一个*操作，那就不该用它们（那是`bi@`或`tri@`的活儿）。

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
