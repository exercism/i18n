# 测试

解决 Exercism 练习的一种方法是访问网站，使用浏览器内的编辑器来编辑和测试你的解答。

另一种做法是把练习下载到自己的电脑上，用自己的编辑器和一套工具来编写、测试，最后提交你的解答。

这需要使用 Exercism 的命令行接口，也就是 CLI（命令行）。CLI 是一个在终端或命令行窗口中运行的程序。安装说明见：[Exercism CLI 文档](https://exercism.org/docs/using/solving-exercises/working-locally)。

## 测试方法

Exercism 假设你已经有一些测试驱动开发的经验。每个练习都由一个 _`stub file`_、一个包含一系列预写测试的 _`test file`_，以及一个用于运行测试的 _`test script`_ 组成。

解决一个练习，需要逐步完善 _`stub file`_，让它最终包含能通过所有测试的代码。

实际来说，这意味着 _`stub file`_ 和 _`test file`_ 都会被反复修改。注意，修改 _`test file`_ 不是为了改动测试代码，而是为了把失败的测试注释掉。

一开始，除一个测试外，其他测试都会被注释掉；随着 _`stub file`_ 逐步完善成一个可用的解答，再逐个取消注释，直到所有测试都成功运行。

## 测试基础设施

不需要安装任何额外的软件，因为测试框架的各个组件已经包含在下载的练习里。

测试框架由三个 Rexx 文件组成。运行时，它们会与练习解答组合成测试代码单元，再由 _`test script`_ 运行，并把测试结果打印到终端上。

请不要编辑或删除 _`test script`_ 或任何其他测试框架文件。如果一不小心弄坏了，只要通过 Exercism CLI 重新下载练习即可，注意先保存好解答代码。

## 运行测试

解决一个练习的流程如下：

1. 打开终端
2. 下载选定的练习
3. 进入练习目录
4. 在编辑器中打开桩文件和测试文件
5. 反复执行以下步骤：

    1. 运行测试脚本
    2. 在桩文件中编写代码（逐步把它变成解答文件），并在测试文件中注释或取消注释测试

6. 所有测试通过后，把解答提交到 Exercism
7. 关闭终端
8. 庆祝你的成功

下面是在 Linux 终端里使用`acronym`练习的一个具体示例（假设 Exercism 工作区为：`/home/exercism`）

下载练习：

`exercism download --track=rexx --exercise=acronym`

进入练习目录：

`cd /home/exercism/rexx/acronym`

在另一个窗口（可能是图形界面窗口）中，把`acronym.rexx`和`acronym-check.rexx`分别作为桩文件和测试文件加载到编辑器里。

运行测试脚本：`./test-acronym`

这时所有测试都应该失败：

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

在`acronym-check.rexx`文件中把除第一个测试以外的所有测试都注释掉，然后重新运行测试脚本，应该会得到如下输出：

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

反复修改`acronym.rexx`，直到里面的代码能正常工作，最终运行测试脚本得到的输出应该是：

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

接着取消注释其他测试，重新运行测试脚本，最终输出应该是：

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

现在你就可以提交练习解答了：

`exercism submit acronym.rexx`

并再获得一个声望点。完成后关闭终端。

MacOS 用户的过程会非常相似，因为它是基于 UNIX 的操作系统。

Windows 用户的过程大体上相似，但有一些细微的差别：

- _Command Prompt_ 窗口就是终端
- 路径中的正斜杠要换成反斜杠，所以工作目录可能是：

  `cd C:\Users\MyName\exercism\rexx\acronym`

- 运行测试脚本的方式是：

  `test-acronym`或`test-acronym.bat`

测试输出是一样的。
