# 重定向简介

在命令行界面的世界里，程序通常会和三个标准数据流打交道：

1. **标准输入**（`stdin`）：程序接收输入的地方（通常来自键盘）。
1. **标准输出**（`stdout`）：程序发送正常输出的地方（通常是终端屏幕）。
1. **标准错误**（`stderr`）：程序发送错误消息的地方（通常是终端屏幕）。

回想一下，我们曾在[管道和命令列表][pipelines]一章里介绍过这些内容。

~~~~exercism/note
管道可以看作是重定向的一种形式：一个程序的标准输出被直接送到另一个程序的标准输入。
我们已经讲过管道了。
这个概念会讲与文件之间的重定向。
~~~~

Shell 重定向是一种强大的机制，让你可以改变这些数据流的目的地。
程序不必再从键盘读取、向屏幕写入，你可以把输入从文件重定向进来，也可以把输出重定向到文件。
这让你能非常灵活地控制程序与数据交互的方式。

## 常见的重定向运算符

以下是最常见的重定向运算符及其作用：

### `>`（输出重定向）

* 作用：把命令的标准输出（`stdout`）重定向到一个文件。
* 行为：
  * 如果文件不存在，就会创建它。
  * 如果文件已存在，它的内容会被覆盖。
* 示例：

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
重定向是在命令执行**之前**完成的。
这意味着你不能把输出重定向到同一个你还需要读取的文件。

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

在上面例子的第二条命令中，

1. Bash 先清空重定向中指定的文件。
   这会销毁之前的内容，留下一个空文件。
2. 然后 bash 读取这个刚变空的文件。
3. 然后 bash 再把内容（也就是什么都没有）写回文件。
~~~~

### `>>`（追加输出重定向）

* 作用：把命令的标准输出（`stdout`）追加到一个文件里。
* 行为：
  * 如果文件不存在，就会创建它。
  * 如果文件已存在，输出会加到文件的末尾。
* 示例：

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<`（输入重定向）

* 作用：从文件重定向命令的标准输入（`stdin`）。
* 行为：命令从指定的文件读取输入，而不是从键盘。
* 示例：

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>`（错误重定向）：

* 作用：把命令的标准错误（`stderr`）重定向到一个文件。
* 行为：错误消息会发送到指定的文件，而不是终端。
* 示例：
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

你可以用 `2>>` 把标准错误_追加_到文件。

### 其他重定向

还有一些重定向可以同时合并 `stdin` 和 `stderr`。
详见[手册][manual]。

## `/dev/null`

`/dev/null` 是一个特殊的文件，它

* 读取时是一个空文件，而且
* 会丢弃写入其中的所有数据。

它有时也被称为“比特桶”。
它适合用来屏蔽输出或错误。

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## 组合重定向

可以一次给出多个重定向。

```bash
some_command < input.txt > output.txt 2> error.txt
```

重定向也可以被复制。

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

当你看到 `2>&1` 时，可以这样理解：“把 stderr 重定向到 stdout **当前**指向的地方”。
Bash 严格按照从左到右的顺序处理重定向指令，这意味着你可以这样写：

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## 文件描述符

在 shell 编程以及 Linux/Unix 这类操作系统的语境里，文件描述符（FD）是一个非负整数，用来标识或引用一个打开的文件或 I/O（输入/输出）资源。
可以把它想象成操作系统用来追踪打开的文件和数据流的一个标签或引用编号。

你在重定向左侧看到的那些数字就是文件描述符。

标准的 I/O 流被分配了前 3 个文件描述符：

* 标准输入是 FD 0
* 标准输出是 FD 1
* 标准错误是 FD 2

新的文件描述符可以用 `exec` 命令和重定向运算符来设置或创建。

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

这种技巧看起来相当绕，但当你的脚本被其他软件包运行时，它能派上大用场，因为此时标准输出会被那段软件自动捕获。
本课程用来运行单元测试的`bats`命令就是这样工作的：`bats`会捕获测试的 stdout 和 stderr，但发送到 FD 3 的调试消息会显示在终端上。
~~~~

## 小结

重定向有什么用？

* 保存输出：把命令的结果存下来，方便以后查看或处理。
* 记录日志：捕获错误消息，便于调试。
* 自动化：把命令串起来，用一个命令的输出作为另一个命令的输入。
* 过滤：丢弃不需要的输出。
* 批处理：处理来自文件的数据，不必手动输入。
* 编写脚本：重定向是写出健壮的 shell 脚本所必需的。

Shell 重定向让你能细致地控制程序与数据交互的方式，帮助你构建复杂的工作流并高效地管理信息。
