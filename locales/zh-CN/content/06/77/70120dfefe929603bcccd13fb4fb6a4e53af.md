# 简介

正则表达式是一种用途极为广泛的字符串_模式匹配_方式，它使用的是一种为此专门设计的领域特定语言（DSL）。

Base R 内置了许多正则表达式功能，你在较旧的代码里可能见过相关示例。

对于新代码，_强烈_建议使用[`stringr`][web-stringr]库。

如[字符串概念][concept-strings]中所述，`stringr`拥有良好的文档，通常由包的作者撰写。

- 一个[参考网站][web-stringr]
- 一份[速查表][cheat-stringr]。
- “R for Data Science”一书中的[字符串章节][book-strings]和[正则表达式章节][book-regex]。

[`Strings`][concept-strings]概念中已经讨论过的许多函数，本身就支持正则表达式搜索。

我们让字符串概念保持得相对简单，只匹配字符串字面量，但你完全可以改用任何正则表达式模式。

严格来说，在 R 中创建正则表达式要调用[`regex()`][ref-regex]。
为方便起见，`stringr`函数会把任何模式字符串都当成正则表达式。
下面的示例中，第一个`str_replace_all()`就是第二种写法的语法糖：

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[速查表][cheat-stringr]是一份很有用的指南：所有带`pattern`实参的函数（在速查表中印成红色）都接受正则表达式，第 2 页还总结了正则表达式语法。

请注意，如果你需要覆盖默认设置，比如大小写敏感性或区域设置，[`regex()`][ref-regex]函数仍然可能很重要。

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

很多正则表达式代码都包含反斜杠，比如上面用到的`\s`。
在普通的 R 字符串里，`\`需要通过重复一次来转义，因此要写成`"\\s"`。

反斜杠会越堆越多，让人眼花缭乱，所以在复杂的情况下，使用[原始字符串][book-raw]可能会有帮助。

默认情况下，定义原始字符串的语法是`r"( )"`，但也允许使用其他分隔符。
由于圆括号`( )`和方括号`[ ]`在正则表达式语法中都很常见（分别用于捕获组和选项组），所以大括号`{ }`也许是个不错的选择。

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## 检测匹配

下面是一些问题，以及可以帮助你回答它们的函数。

有些示例会用到`fruit`，它是`stringr`自带的一个包含 80 个水果名称的向量，供练习用。

_字符串中是否包含匹配项？_
`str_detect()`，或者用`str_starts()`、`str_ends()`来避免使用`^`或`$`锚点。

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_只返回包含匹配项的字符串？_
用`str_subset()`获取字符串，用`str_which()`获取下标。

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_每个字符串中有多少个匹配项？_
用`str_count()`。

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_匹配项在什么位置？_
交互式查看用`str_view()`，更一般的情况用`str_locate()`或`str_locate_all()`。

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## 捕获

通常，我们想知道_到底什么_被匹配了。
这可以通过在正则表达式中用圆括号加入捕获组来实现。

可以在同一个正则表达式内部用`\1`、`\2`等反向引用捕获组。
例如，找出重复出现的字母对：

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

用类似的语法，捕获组也可以用在替换字符串里：

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

如果只想要第一个匹配项，可以用`str_match()`函数把它收集起来留待后续处理；如果想要所有匹配项，就用`str_match_all()`。

无论用哪种语言，捕获组产生的输出往往都很复杂。
R 的做法（_它还是向量化的，算是个额外的挑战_）是用`str_match()`生成一个矩阵：每个输入字符串对应一行，第 1 列是完整匹配到的字符串，其余各列则是各个捕获组。

使用命名分组会更有优势，因为它们会成为结果矩阵的列名。

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

~~~~exercism/note
本教学大纲没有过多介绍矩阵，不过你可以查阅一份[概念文档][concept-matrices-arrays]。
尽管矩阵作为 Base R 的一部分由来已久，但它和 Tidyverse 生态配合得并不好。

简单来说：把矩阵看作带 2 个下标的向量，顺序是`[rows, cols]`。
把其中一个下标留空，就能取到整行或整列。

用`m[r,]`取第`r`行或用`m[,c]`取第`c`列时，返回的值默认会被展平成一个向量。

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```
~~~~

`str_match_all()`产生的输出结构不可避免地会更加复杂：

- 结果是一个列表，每个输入字符串对应一个元素。
- 如果只有一个输入字符串，可以按照[列表概念][concept-lists]中所述，用`[[1]]`下标取出其中的内容。
- 每个元素都是一个矩阵，各列的含义和`match()`一样。
- 矩阵中的每一行对应一次成功的捕获。

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

当然，匹配也可能失败。
这时结果会是特殊值`NA`。
要做好检测这种情况的准备，具体做法见[虚无概念][concept-nothingness]。

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
