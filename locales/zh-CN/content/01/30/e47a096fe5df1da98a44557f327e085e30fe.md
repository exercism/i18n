# 关于

虽然这道练习探究的是 `time` 这一概念，但在实践中，你很少单独处理时间。时间几乎总是与日期一起处理。并不存在一个单独的 _时间_ 类型，只有 [`DateTime`][date-time]。

一天中的时间可以用 [`TimeSpan`][time-span] 表示（事实上，它正是 `DateTime.TimeOfDay` 的返回类型）。它并非[专门为此设计][skeet-time-of-day]，所以代码的表达力有时会显得有点笨拙。比如，对于一个 UTC 形式的 `DateTime` 实例，你期望它的一天中的时间是什么呢？不过，它确实能完成任务。

围绕 _时间_ 的讨论涉及多个方面：

- 本地时间与协调世界时（UTC）
- `DateTime` 的运算
- 时区（包括夏令时）
- 日期时间字符串的解析与格式化
- 分辨率（计时器选择等）

这道练习涵盖了本地时间与 UTC 的对比、日期时间运算、时区以及日期时间解析。

[格式化][date-string-formatting]在 `string-formatting` 练习中讨论。

分辨率与计时器在网上[讨论得很多][so-timers]。`DateTime` API 有专门处理文件时间戳的例程。

长期存储日期时间时，通常最好采用 UTC 形式。如果涉及不止一个时区，这样可以保证一致性，也能避免夏令时带来的潜在问题。

UTC 时间的缺点是，如果一天中的时间是重要因素，就需要把它们转换成当地时间。

大多数情况下，只要处理是以你电脑的时区为基础，`DateTime.ToUniversalTime()` 和 `DateTime.ToLocalTime()` 都能很好地工作。如果涉及多个时区，或者涉及一个与你电脑不同的时区，你就需要 [`TimeZoneInfo`][time-zone-info] 类来处理转换，而不是那个已过时的 ~~TimeZone~~ 对象。

你应该还记得，在编程练习中，那些至关重要的时区标识符在 Windows 和其他平台上是不一样的。这篇[文章][cross-platform-time-zones]很好地介绍了这个跨平台问题。注意，`TimeZoneInfo.GetSystemTimeZones()` 会列出你所在平台的时区。

这篇[文章][time-overview]对时间和时区做了很好的概述。

在编程练习中做日期时间运算时，你可能已经用过 `TimeSpan` 结构。当你需要涉及整月或整年的运算时，`DateTime` 结构提供了许多方法，比如 `AddHours()` 和 `AddMonths()`。

如果日期和时间在你的项目中无处不在，或者至关重要，那么你应该研究一下 [Noda Time][noda-time]。

如果你好奇的话，根据这篇[维基百科文章][wiki-utc]，世界时 UTC 这个缩写源于英语使用者（UCT）和法语使用者（CUT）之间的妥协，这样一来，两种语言都不会显得更优先。
