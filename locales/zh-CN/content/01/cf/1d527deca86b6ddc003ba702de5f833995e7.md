# 关于

大多数标量按位运算都有对应的打包变体。它们遵循与 [SIMD 整数运算][simd-integers] 相同的基本语法，但没有大小后缀：

| instruction | description                       |
|-------------|-----------------------------------|
| `pand`      | 两个 128 位值的按位与 |
| `por`       | 两个 128 位值的按位或  |
| `pxor`      | 两个 128 位值的按位异或 |

注意，没有打包形式的`NOT`。
不过有一个 ANDN 运算，它先对**目的操作数**取反（翻转其中的所有位），再计算两个操作数的与。
可以把它看作把 NOT 和与结合在了一起：

| instruction | description                                                     |
|-------------|-----------------------------------------------------------------|
| `pandn`     | **取反后的**目的操作数与源操作数的按位与 |

注意，按位运算组合的是两个不同操作数中相同位置上的位，所以通道边界不会改变结果。
这就是这些指令没有大小后缀的原因：寄存器就像一个 128 位通道那样工作：

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
本概念中的所有指令都计算位，但不会设置任何标志位。
后面的概念会讲到如何用打包的值处理条件判断。
~~~~

## 逐通道移位

与纯粹的按位运算不同，移位确实会把位移动到别的位置上，因此需要一个通道大小来划出边界。
在每个通道内部，它们的行为与标量版本一样，位也绝不会从一个通道跨越到相邻通道：

| instruction               | description                         |
|---------------------------|-------------------------------------|
| `psllw`, `pslld`, `psllq` | 逐通道逻辑左移        |
| `psrlw`, `psrld`, `psrlq` | 逐通道逻辑右移       |
| `psraw`, `psrad`          | 逐通道算术右移    |

注意，这些指令遵循打包整数运算的语法，包括大小后缀。
没有字节通道的移位，只有字、双字和四字，不过算术右移是个例外，它没有四字形式。

打包移位与对应的标量版本有一个区别在于运算名称：

- 不是`shl`和`shr`，而是`sll`和`srl`，代表 **s**hift **l**eft（**r**ight）**l**ogical。
- 不是`sar`，而是`sra`，代表 **s**hift **r**ight **a**rithmetic。

名称虽然不同，运算本身是一样的：

- 逻辑右移用零填充最高位。
  它等价于无符号数除以 2 的幂。
- 算术右移用符号位的值填充最高位。
  它等价于有符号数除以 2 的幂，并向负无穷方向取整。
- 左移始终用零填充（这就是不需要算术左移的原因）。

移位位数对每个通道都是相同的。
它可以是一个立即数，也可以是`xmm`寄存器的低 64 位：

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
大于通道宽度的移位位数不会像标量`shl`/`shr`那样回绕。
它只会产生零（对于算术右移，则产生全符号位）。
~~~~

## 浮点按位运算

每条按位指令还有一个以浮点数命名的孪生版本，它们遵循我们在打包浮点运算中见过的那套语法：

| integer name | float names          |
|--------------|----------------------|
| `pand`       | `andps`, `andpd`     |
| `pandn`      | `andnps`, `andnpd`   |
| `por`        | `orps`, `orpd`       |
| `pxor`       | `xorps`, `xorpd`     |

由于按位运算作用于位，实际上整数运算和浮点运算计算出的结果完全相同。
名称不同有两个原因：

1. 表达意图，就像我们会根据所复制字节的性质，更倾向于选择`movdqa`、`movaps`或`movapd`。
2. 整数运算和浮点运算通常属于不同的执行域。
   同一执行域内的运算通常能以更快的速度串行执行。

浮点值没有移位运算。

## 浮点数的位表示

一个 [IEEE 754][ieee-754] 浮点数的位表示与整数差别很大。

在无符号整数中，每一位的含义都是统一的：它表示与位下标对应的 2 的幂。
整数的值就是所有置位对应的 2 的幂之和。
这就是为什么移位可以让数字乘以或除以 2 的幂：我们只是改变了每个置位的下标。

在有符号整数中，大多数位的解释方式与无符号整数相同。
但最高位很特殊。
如果它被置位，它就不是加到其他位上，而是要减去对应的 2 的幂，从而得到负数。
在实践中，要改变一个数的符号，概念上需要两步：翻转所有位（`not`），再把结果加 1（`inc`）。

浮点数的各位含义并不统一，需要根据它们所在的位置以非常不同的方式解释：

| field    | indexes (32-bit) | indexes (64-bit) |
|----------|------------------|------------------|
| sign     | 31               | 63               |
| exponent | 30-23            | 62-52            |
| fraction | 22-0             | 51-0             |

最终得到的数由 `(-1)^sign * 1.fraction * 2^(exponent - bias)` 计算得出。
偏置值取决于精度：

| size   | bias |
|--------|------|
| 32-bit | 127  |
| 64-bit | 1023 |

在这两种格式中，数的符号都完全由符号位决定。
改变浮点数的符号，只需翻转这一位（一次异或运算）。
求绝对值，只需把它清零（一次将该位清零的与运算）：

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

注意，在这种位表示中，移位不会有可预测且统一的结果。
尾数可能“溢出”到指数中，指数也可能“溢出”到符号中。

不过，有时把表示的不同部分单独取出来再对它们进行运算会很方便。

例如，指数部分的位应先按无符号数解释，再从中减去偏置值。
这意味着我们可以得到一个 32 位或 64 位整数，其底层的位表示对应相应浮点格式中的某个 2 的幂。
然后就可以用这个原始位表示去乘或除另一个浮点数。

例如：

```x86asm
mov eax, 210       ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23        ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax     ; we move the raw bits to xmm0
mulss xmm1, xmm0   ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

反过来，我们也可以用一个掩码对打包浮点数做与运算来提取指数，该掩码中指数位被置位、其余位被清零。
再结合一次移位和一次减法，就能把每个通道的无偏指数表示为有符号整数：

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
直接操作浮点数的原始位虽然在某些情况下很有用，但应谨慎进行。
上面的公式只描述了**规格化**数：指数字段全为零表示零和非规格化数，全为一时表示无穷大和 NaN。
只有在不发生上溢或下溢、且输入的数是规格化数时，才能安全地对指数字段做加减。
另外，给`0.0`的指数字段加上一个有效的`x`，得到的是`2^(x - bias)`，而不是`0.0 * 2^x`。
~~~~

## AVX 及更高版本

AVX 为这里的每条指令都提供了加`v`前缀、使用更宽寄存器的三操作数形式，行为保持不变：

```x86asm
vpand  ymm0, ymm1, ymm2 ; ymm0 = ymm1 AND ymm2, 256 bits
vxorps ymm3, ymm4, ymm5 ; ymm3 = ymm4 XOR ymm5, 256 bits
vpsrad ymm6, ymm7, 2    ; eight 32-bit lanes shifted right arithmetically
```

AVX2 还引入了可变移位，在大小后缀前加一个`v`。
它们接受一个移位位数向量，按对应通道中的位数进行移位：

```x86asm
vpsllvd ymm0, ymm1, ymm2  ; each 32-bit lane shifted left by its own count
vpsravd ymm3, ymm4, ymm5  ; each 32-bit lane shifted right arithmetically by its own count
```

AVX-512 补上了 SSE 留下的两个空缺：

- `vpsraq`终于提供了 64 位算术右移。
- `vpternlogd`和`vpternlogq`能用一条指令计算出**任意**三输入按位函数。
  8 位立即数本身就是真值表：立即数的第`i`位就是输入组合`i`对应的输出。
  任何由`pand`/`pandn`/`por`/`pxor`构成的三操作数运算链，都能合并成一条`vpternlog`。

提到这些扩展只是为了完整。
这里的练习使用的是 SSE 形式。
