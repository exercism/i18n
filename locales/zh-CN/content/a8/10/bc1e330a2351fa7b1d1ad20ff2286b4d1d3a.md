# 简介

前面某个概念介绍了打包浮点值：多个数字存放在同一个`xmm`寄存器中，按通道并行地进行运算。同一个`xmm`寄存器也可以存放打包_整数_。

## 语法

SIMD 浮点模型的大部分内容都可以原封不动地沿用到打包整数上：

- 一个 128 位寄存器被划分为若干通道
- 指令并行地作用于处于相同位置的各个通道
- 内存操作数遵循相同的 16 字节对齐规则

不过，语法略有不同：

1. 用一个_前缀_`p`表明这条指令处理的是_打包_数据。
2. 所执行的操作，名称与非 SIMD（也叫_标量_）版本相同（例如`add`、`mul`等）。
3. 用一个后缀表明每条通道的大小。

打包整数有四种通道大小，每一种都有自己的后缀：

| 通道宽度 | 字节数 | 128 位中的通道数 | 后缀 |
|------------|-------|-------------------|--------|
| 字节       | 1     | 16                | b      |
| 字         | 2     | 8                 | w      |
| 双字       | 4     | 4                 | d      |
| 四字       | 8     | 2                 | q      |

例如：

| 指令 | 含义                              |
|-------------|--------------------------------------|
| `paddb`     | 打包`add`，8 位通道（16 条通道） |
| `paddw`     | 打包`add`，16 位通道（8 条通道） |
| `paddd`     | 打包`add`，32 位通道（4 条通道） |
| `paddq`     | 打包`add`，64 位通道（2 条通道） |

有些指令输入的通道是一种大小，输出的通道却是另一种大小。
它们遵循同样的一般约定，但带有_两个_大小后缀。
第一个表示输入通道的大小，第二个表示输出通道的大小：

| 指令  | 含义                                           |
|--------------|---------------------------------------------------|
| `pmovsxwd`   | 打包`movsx`，从 16 位通道到 32 位通道 |
| `pmuldq`     | 打包`mul`，从 32 位通道到 64 位通道   |

## 内存移动

有两条以整数命名的指令可以在`xmm`寄存器与内存之间复制 128 位：

| 指令 | 说明                                             |
|-------------|---------------------------------------------------------|
| `movdqa`    | 在_对齐_的位置之间复制打包整数   |
| `movdqu`    | 在_未对齐_的位置之间复制打包整数 |

它们的行为和`movaps`、`movups`一样：`movdqa`在地址未对齐时会报错，而`movdqu`则接受任意地址。
这四条指令都只是复制 128 位，并不解释其中的内容。
以整数命名的那一对只是按惯例用于整数数据，而不是硬性要求。

~~~~exercism/note
这里的`dq`表示`double-qword`，即 128 位（16 字节）。
~~~~

## 加法与减法

加法和减法遵循上面的命名规则：

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

没有单独的带符号形式和无符号形式。
在补码表示下，无论通道被当作有符号数还是无符号数来读，加法和减法产生的位都相同，所以一条指令就能兼顾两者。
如何解读这些位由你决定，和标量`add`、`sub`完全一样。

这些指令在溢出时会**回绕**，和它们的标量版本一样。
一条 8 位通道保存的是对 256 取模后的值，所以对`200 + 100`执行`paddb`会得到`300 - 256 = 44`，装不下的位被丢弃。

注意，这些多出来的位不会进位到下一条通道。
每条通道都独立于其他通道单独运算，尽管它们共用同一个寄存器。

## 饱和加法与减法

整数 SIMD 增加了一种浮点 SIMD 没有的运算：**饱和**加法与减法，它们做的是_钳位_而不是回绕。
超出通道范围的结果会变成该通道能容纳的最大值；低于范围的结果则变成最小值。

饱和形式会在大小后缀之前插入`s`（有符号）或`us`（无符号）：

| 指令 | 含义                                    |
|-------------|--------------------------------------------|
| `paddsb`    | `add`，饱和，有符号 8 位通道      |
| `paddusb`   | `add`，饱和，无符号 8 位通道    |
| `psubsw`    | `sub`，饱和，有符号 16 位通道     |
| `psubusw`   | `sub`，饱和，无符号 16 位通道   |

钳位的范围是对应大小和符号性的整数能够表示的完整范围。
以字节为例：

- 无符号字节钳位到`[0, 255]`：对`200 + 100`执行`paddusb`得到`255`，对`5 - 10`执行`psubusb`得到`0`。
- 有符号字节钳位到`[-128, 127]`：对`100 + 50`执行`paddsb`得到`127`。

当一条通道保存的是有界的量（比如像素通道或音频采样）时，饱和就很重要。
回绕会把过亮的像素变暗，而钳位会让它保持在最大亮度，这才是你想要的结果。

~~~~exercism/note
饱和加法和减法只存在于字节通道和字通道，没有双字或四字通道的版本。
~~~~

## 乘法

两个 N 位值相乘可能得到 2N 位的乘积，但目标通道只有 N 位宽。
SIMD 运算的解决办法是指定保留乘积的哪一半，要么是低 N 位，要么是高 N 位。

对于 16 位通道，会用到三条指令：

| 指令 | 含义                                                       |
|-------------|---------------------------------------------------------------|
| `pmullw`    | `mul`，16 位通道，保留每个乘积的低 16 位     |
| `pmulhw`    | `mul`，16 位通道，保留高 16 位，有符号操作数   |
| `pmulhuw`   | `mul`，16 位通道，保留高 16 位，无符号操作数 |

无论操作数被当作有符号数还是无符号数，乘积的低 16 位都相同，所以只有一条`pmullw`。

但高 16 位会随结果的符号性而不同。
这就是为什么取高半部分的乘法会有分别用于有符号和无符号乘法的两种形式：

1. `pmulhw`，用于有符号乘法。
2. `pmulhuw`，多了一个`u`，用于无符号乘法。

注意它的语法：

1. 一个`p`，表示打包整数。
2. 所执行的操作`mul`。
3. 一个`h`，表示选取结果的高（“high”）位。
4. 一个可选的`u`，表示结果应当按无符号解释（也就是说，不做符号扩展）。
5. 最后是大小后缀`w`，表示这是字（16 位）运算。

字的打包乘法完全遵循上面的规则。
双字（32 位）乘法也遵循这条规则，但只有选取低半部分的版本：`pmulld`。

双字乘法没有选取高位的版本。
不过，有些版本会_加宽_乘法，把_偶数下标_通道（也就是位置 0 和 2 的通道）的完整 64 位乘积存下来：

| 指令 | 含义                                                                          |
|-------------|----------------------------------------------------------------------------------|
| `pmuludq`   | 把偶数下标的 32 位元素按无符号相乘，得到 2 个完整的 64 位乘积 |
| `pmuldq`    | 把偶数下标的 32 位元素按有符号相乘，得到 2 个完整的 64 位乘积   |

注意这里的语法用的是`dq`，如果是无符号乘法，前面可能还会有一个`u`。
这是因为这些指令输入的是`dword`通道，输出的是`qword`通道。

## 除法

没有打包整数除法。
需要它的代码会先把值转换成浮点数，做完除法再转换回来。

## 整数加宽

`movsx`和`movzx`都有对应的打包版本。
它们遵循我们前面提到的、输入通道大小与输出通道大小不同的指令所用的语法：

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

注意，通道的数量由较大的（输出）宽度决定。
指令会从源操作数的低位部分读取这么多条通道。
这与我们前面在单精度和双精度浮点数之间用打包`cvt`指令时看到的语义相同。

## 在整数与浮点数之间转换

有些指令可以在 32 位有符号整数与浮点通道之间转换。
它们遵循`cvt`和`cvtt`指令的常见语法，但打包整数不用`si`表示，而是用`dq`：

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
用`pi`表示打包整数的指令会写入传统的`mmx`寄存器，在 x86-64 上实际上已经弃用。
请优先使用`dq`形式，也就是使用`xmm`寄存器的那些。
~~~~

关于浮点数与整数之间的标量转换所做的那些说明，在这里同样适用。
浮点数会按照一个名为 MXCSR 的特殊寄存器来舍入，进入函数时不能假定这个寄存器的模式。
还有一个`cvtt`变体（多了一个`t`），它总是截断结果。

也可以在转换之前用`round`把打包浮点值调整到已知状态。
舍入控制值和标量`round`相同，打包浮点值的语法也相同：

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
