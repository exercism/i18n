# 代码检查

[configlet](/docs/building/configlet)的主要用途是代码检查：检查某个 track 的配置文件结构是否正确，既要语法正确，也要语义正确。配置有误的 track 可能无法正确同步，可能在网站上显示异常，也可能给用户带来欠佳的体验，因此 configlet 的这些把关检查对维护 Exercism 的完整性起着重要作用。

## 用法

可以用 `lint` 命令对某个 track 进行代码检查。

```
configlet [global-options] lint [command-options]

Global options:
  -h, --help                   Show this help message and exit
      --version                Show this tool's version information and exit
  -t, --track-dir <dir>        Specify a track directory to use instead of the current directory
  -v, --verbosity <verbosity>  The verbosity of output. Allowed values: q[uiet], n[ormal], d[etailed]
```

## 规则

以下就是 configlet 会检查的各项规则。

### 规则：必需文件均已存在

代码检查器应检查所有必需文件是否都已存在。必须存在的非练习专属文件有：

- `config.json`
- `docs/ABOUT.md`
- `docs/INSTALLATION.md`
- `docs/LEARNING.md`
- `docs/RESOURCES.md`
- `docs/SNIPPET.txt`
- `docs/TESTS.md`
- `exercises/shared/.docs/help.md`
- `exercises/shared/.docs/tests.md`

必须存在的概念练习专属文件有：

- `exercises/concept/<slug>/.docs/hints.md`
- `exercises/concept/<slug>/.docs/instructions.md`
- `exercises/concept/<slug>/.docs/introduction.md`
- `exercises/concept/<slug>/.meta/config.json`

实践练习也会有类似的清单，但我们还没有定义相应的规范。

`config.json` 中列出的每个概念都应有以下文件：

- `concepts/<slug>/about.md`
- `concepts/<slug>/introduction.md`
- `concepts/<slug>/links.json`

## 术语表

1. **非空白字符串**：至少包含一个非空白字符的字符串。
2. **kebab-case 字符串**：只包含 `[a-z0-9]` 范围内的字符、可选地用短横线分隔的字符串（例如 “two-fer”）。它必须匹配正则表达式：`^[a-z0-9]+(-[a-z0-9]+)*$`
3. **标题式大写字符串**：遵循下面这些[《芝加哥手册》中的指南](https://en.wikipedia.org/wiki/Title_case#Chicago_Manual_of_Style)的非空白字符串：
   - 标题和副标题的第一个和最后一个单词首字母大写。
   - 把“主要”单词（名词、代词、动词、形容词、副词以及部分连词）首字母大写。
   - 连词 _and_、_but_、_for_、_or_ 和 _nor_ 小写。
   - 冠词 _the_、_a_ 和 _an_ 小写。
   - 介词一律小写，不论长短，但介词受到强调、用作副词或形容词，或者用作连词时除外。
   - 单词 _to_ 和 _as_ 小写。
   - 拉丁学名中的第二部分小写。
4. **句首大写字符串**：遵循下面这些[指南](https://en.wikipedia.org/wiki/Letter_case#Sentence_case)的非空白字符串：
   - 句子第一个单词首字母大写，专有名词以及更具体的规则要求大写的其他单词也同样首字母大写。
5. **有效的 `files` 模式**：一个非空白字符串¹，用来指定练习中某个文件相对于练习目录的位置。模式可以使用以下占位符之一：

   - `%{kebab_slug}`：`kebab-case` 形式的练习 slug（例如 `bit-manipulation`）
   - `%{snake_slug}`：`snake_case` 形式的练习 slug（例如 `bit_manipulation`）
   - `%{camel_slug}`：`camelCase` 形式的练习 slug（例如 `bitManipulation`）
   - `%{pascal_slug}`：`PascalCase` 形式的练习 slug（例如 `BitManipulation`）

6. **唯一的版本 4 UUID 字符串**：满足以下所有条件的字符串：

   - 在某个 Exercism track 的 track 级 `config.json` 文件中只出现一次
   - 不出现在其他任何 Exercism track 的 track 级 `config.json` 文件中
   - 不出现在 https://github.com/exercism/problem-specifications 里的任何 `canonical-data.json` 文件中
   - 不出现在 Exercism 的其他任何地方
   - 匹配以下正则表达式：

   ```
   ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
   ```

   例如，下面这个 UUID 格式正确：

   ```
   d334ffe3-657e-4725-a950-290b284b6d9f
   ```

   你可以运行 `configlet uuid` 生成一个合适的 UUID。

7. **有效的分析器 `tag`**：格式为 `<category>:<thing>` 的非空白字符串¹。
   `<category>`的值必须是以下之一：

- `paradigm`（例如 `paradigm:functional`）
- `technique`（例如 `technique:recursion`）
- `construct`（例如 `construct:bitwise-and`）
- `uses`（例如 `uses:DateTime.add_seconds`）

`<thing>`的值必须是非空白字符串¹。
