# 简介

我们在前面几个概念中已经看到，Julia 中的类型构成一个层级，`Any`位于最顶端。

像`Number`这样的抽象类型有子类型，但自身不能被实例化。
把变量的类型设为抽象类型，会_限制_该变量的值只能是这个抽象类型的某个子类型。
例如：

```julia-repl
julia> x::Number = 3
3
julia> typeof(x)  # one subtype of Number
Int64
julia> x = 4.2
4.2
julia> typeof(x) # another subtype of Number
Float64
julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

这样我们就多了一种灵活性，可以限制哪些输入是合法的。

不过，假如我们希望一个变量既能接受整数值，也能接受字符串值呢？
这两类类型并不在类型层级的同一个分支上。

我们可以把类型设为`Any`，或者让它默认就是`Any`，但这样一来，我们就完全失去了对可用类型的控制。

更好的做法是使用`Union{ }`语法，在花括号里列出两个或更多类型。

```julia-repl
julia> y::Union{Integer, String} = 4
4
julia> typeof(y)
Int64
julia> y = "works"
"works"
julia> typeof(y)
String
julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

另一个例子在函数签名中使用了同一个类型联合：

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}
julia> f(z::IntOrString) = z^3
f (generic function with 1 method)
julia> f(2) # integers are cubed
8
julia> f("ab") # strings are repeated 3 times
"ababab"
```

这里我们给这个类型起了个名字，这样可以提供方便的简写，但并非严格必需。
函数`g(z::Union{Integer, String}) = z^3`的行为完全相同。

关于函数签名，后面的多重派发概念中还有更多内容要讲。

## 与 nothing 的联合

其他几种语言也有这样的类型：它可能包含一个值，也可能不包含，名字类似`Option`、`Nullable`或`Maybe`。

Julia 没有专门为此设计的语法，但类型联合正是同一思路的推广。

我们在概念`Nothingness`中已经看到，Julia 有多种表示“没有值”的方式，包括`nothing`和`missing`。
这两者都可以包含在类型联合中。

例如，在定义某种链表时，我们需要一种方式，在没有了后续节点时结束链表。
`Nothing`是单例值为`nothing`的类型，下面这个 Node 定义让我们可以标示出链表的结尾：

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

同样，`missing`可以用作缺失值的占位符，尤其是在向量这类集合中。
下面的例子非常牵强，但缺失值在真实数据集里很常见。

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)
julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
