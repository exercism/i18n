# 介绍

在理想的世界里，我们可以假定一切都被清晰地定义好，有具体的值，没有空缺。

这与我们的日常经验相矛盾，因此许多编程语言都有表示“值不存在”的方式：null 或 NULL、nil、None、nothing……

引入它很容易（那还是 1965 年），但很快就带来了遗憾。
发明者后来称它为他的“十亿美元错误”。

近几十年来，语言设计者探索了许多方法，让 null 可用，但（在大多数情况下）是安全的。

Kotlin 有一些[通用原则][ref-null-safety]，与 Java 有显著不同。


- Kotlin 有一个特殊的 `null` 值。
- 所有类型*默认*都是非空的。
- 大多数类型*可以*变为可空，但必须由程序员显式指定。
- 可能因异常而失败函数，往往会有返回可空值的变体。
- 有一些特殊而极为简洁的语法，力求让 null 的检测与应对尽可能简单。

## 创建可空变量

标准类型通常都有对应的可空版本，就是在类型后加 `?` 后缀：例如用 `String?` 代替 `String`。

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## 常用的运算符和函数

### 安全调用运算符 `?.`

对于一个非空的 `String`，我们可以取得它的 `.length` 属性。

可空的 `String?` 用同样的语法会出错，但改用 `?.length` 就能容许 `null` 的存在。
返回类型是 `Int?`。

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

正如上面最后一行所示，`?.` 对非空类型同样适用。

### Elvis 运算符 `?:`

在安全调用运算符的基础上进一步延伸，[Elvis 运算符][wiki-elvis]让我们可以提供一个默认值来替代 `null`。

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### 非空断言运算符 `!!`

用这个运算符，可以在程序员有把握时，强制把可空类型当作非空类型处理。
也许有时我们对程序逻辑的理解，会胜过过分谨慎的编译器？

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

责任现在落到我们身上：如果 `b` 仍然是 `null`，就会得到 `NullPointerException`。

### let 函数 `?.let`

如果要把一个可空的值传给某个代码块，我们可以专门做 null 检查，例如 `if (item != null) { do something }`。

更简单、也更符合习惯的做法是使用 `item?.let { do something }`。
只有当 `item` 不为 null 时，`do something` 才会执行。

### 类型为 `somethingOrNone()` 的函数

有些函数可能会失败，比如在字符串或数组中请求一个无效的下标时。

与其抛出异常，我们可以使用函数的 `...OrNull` 变体，来得到（在这里是）一个 `Int?` 返回值。

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
