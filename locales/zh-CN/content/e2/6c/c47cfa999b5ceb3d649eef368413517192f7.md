# 关于位

二进制位最终直接对应着你 CPU 或 RAM 中的晶体管，以及每个晶体管是“开”还是“关”。

底层操作，俗称“bit-twiddling”，在系统级语言中尤为重要。

像 Kotlin 这样的高级语言通常会把这类细节大部分抽象掉。
不过，一系列基本的位运算仍然[可以使用][ref-bitwise]。

~~~~exercism/note
要想看到人类可读的二进制输出，下面几乎所有示例都需要用[`Integer.toBinaryString()`][web-binstring]函数包起来，或者用`toString(radix = 2)`转换。
 
这会让代码看起来很乱，所以这个函数的大多数出现都被删掉了，结果改用`0b`记法表示。

## 位移运算

`Int`或`Long`类型，无论是有符号还是无符号，都可以表示成由 1 和 0 组成的字符串，并作为一串位来操作。

也许出乎意料的是，`Byte`或`Short`类型与 Kotlin 中的大多数位运算并不兼容。
下面所有示例都使用 32 位整数（`Int`或`UInt`）。

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

位移会把所有位向左或向右移动指定的位数。
有些位会从一端掉出去，另一端则用零或一来补齐。

- 用`shl`左移：补零。
- 用`shr`或`ushr`右移：对正数补零（负数见后面的小节）。

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

每一次左移都会让值翻倍，每一次右移都会让它减半（可能会有截断）。
用十进制表示时，这一点更明显：

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

这种位移比“正规”的算术运算快得多，因此这种技巧在底层编程中非常流行。

### 负整数的位移

处理_负整数_时，我们需要更小心一点。

负值以[补码][wiki-2complement]形式存储，这意味着最左边的位是 1。
左移没问题，但右移时，最左边的位该怎么补呢？

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

[`shr`][ref-shr]运算符执行[算术移位][wiki-arithmetic]，会保留符号位。

[`ushr`][ref-ushr]运算符执行[逻辑移位][wiki-logical]，像处理无符号数一样用零补齐。

## 位逻辑

我们在[布尔值概念][concept-booleans]中看到，运算符`&&`（与）、`||`（或）和`!`（非）用于布尔值。

也有对应的运算符`and`、`or`、`xor`（[异或][wiki-xor]）用来比较两个整数中的位，还有一个`inv`（取反）函数用来翻转所有位。

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
