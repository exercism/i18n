# 简介

在程序中，我们常常需要自定义类型。

创建新的原始类型是可行的，但很少这么做。内置的原始类型并非随意挑选：它们与 Julia 用于 JIT 编译的 LLVM 编译器中的标准类型高度吻合。

更有用的，是能够定义带具名字段的复合类型。

其他语言也有类似的东西，称之为 `structs` 或 `records`。Julia 的文档把它们称为 `composite types`，不过（稍有不一致的是）语言语法用 `struct` 关键字来定义它们。

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

上面的例子中有几点值得注意：

- `id`没有指定类型，因此编译器会把它解释为`id::Any`。
- 类型名被用作构造函数，例如`Person(id, name, age)`，用来生成一个类型为`Person`的实例。
- 各个字段可以用点号访问，与具名元组一样。

`Person`类型的项是不可变的，因此不允许更新。

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

如果需要可变性，在定义中加上`mutable`。

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

默认情况下，构造函数要求字段的顺序与定义中相同，对于更复杂的类型来说这会造成不便。

使用`@kwdef`宏可以带来两项新能力：

- 构造函数使用关键字，而不是位置。
- 字段可以有默认值，并且可以有选择地从构造函数中省略。

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## 复合类型层次结构

到目前为止，我们只创建了具体的复合类型。如果你去检查，它们全都是`Any`的子类型。

在创建多个相关类型时，为它们定义一个层次结构可能更合理。这很容易做到。

首先，创建一个抽象类型：

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

接下来，在类型定义中加入`<:`运算符来表示这种关系。

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

根据需要重复，记住不允许对具体类型进行子类型化。

对于更复杂的层次结构，按需创建抽象子类型。

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

当我们学到`Multiple Dispatch`这个概念，看到函数如何处理实参类型时，这种层次结构的价值就会更清楚。
