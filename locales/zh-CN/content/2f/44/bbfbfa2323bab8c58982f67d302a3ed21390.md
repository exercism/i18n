# golint 未通过

有一个很棒的工具叫[`golint`](https://github.com/golang/lint)，它会检查代码中常见的问题和代码风格问题。
对提交的解答运行 `golint`，例如：`golint two_fer.go`，它会给出一些有用的建议。

建议始终用 `golint` 检查代码。
在编写用于生产环境的 Go 软件时，如果代码没有通过 `golint`，许多构建流水线会自动失败。

如果你想从代码检查工具那里得到更多反馈，可以看看 [golangci-lint](https://github.com/golangci/golangci-lint) 项目，它让你用一条命令运行大量检查工具。
项目配置文件可以根据项目需求调整它的行为。

```
> golint
%{golint}
```
