# 贡献指南

如果你想参与 Pharo 学习轨道的开发，请遵循下面的说明，它们会帮你上手。

我们非常希望能改进这个学习轨道，向开发者展示一种不同的编程思维方式！:tada:

请阅读如何[参与 Exercism 学习轨道](https://github.com/exercism/docs/tree/master/contributing-to-language-tracks)，也请务必阅读 [Exercism 行为准则](https://exercism.io/code-of-conduct)。

我们欢迎各种形式的 pull request。任何贡献都不嫌小，尤其是那些修复和改进现有练习的贡献。请注意，本学习轨道的练习必须符合 [Exercism 全局标准](https://github.com/exercism/docs/tree/master/language-tracks/exercises)，但如果你不确定该如何做出改动，那就开一个 GitHub issue，我们来讨论。

>__注意__：Exercism 组织已决定[暂停 Exercism 更广泛的社区贡献](https://exercism.org/blog/freeing-our-maintainers)。Pharo 学习轨道选择不适用这一政策，因为我们的社区规模较小（换句话说：任何 Pharo 学习轨道的贡献者仍然可以创建 issue 并提交 PR）。

## 知识前提

我们默认你已经[熟悉](./docs/RESOURCES.md) Pharo 开发，以及它对 [Iceberg Git](https://github.com/pharo-vcs/iceberg) 的使用。

## 开发环境搭建

开始之前，你需要确保自己拥有完整的 Exercism 开发环境，并已安装以下组件：

### __Pharo 映像和 IDE__

你需要一个 Pharo 开发环境（运行中的 Pharo 映像，即 IDE）来创建实际的编程示例。

1. 用 [PharoLauncher](https://pharo.org/download) 从 `Official distributions` 分类创建一个全新的稳定开发映像（截至 05/24，稳定映像是：Pharo 12.0 - 64bit (stable)），然后启动它（如果你熟悉 [zerconf](https://get.pharo.org/)，也可以用它）。
2. 启动你的映像，测试一切是否正常运行。

> __注意__：如果遇到任何 TIMEOUT 问题，请参考[用户安装说明](./docs/INSTALLATION.md)。

### __设置 git 代码仓库__

1. 如果之前没有做过，先在 GitHub 上 fork`https://exercism/pharo-smalltalk`。
2. 要克隆你的 fork，在运行中的 Pharo 映像的 Playground 中执行以下命令：
```
Metacello new
 baseline: 'Exercism';
 repository: 'github://exercism/pharo-smalltalk:main/releases/latest';
 load: 'dev'
```
这会实际克隆 Pharo 学习轨道的 git 代码仓库，并把 Pharo 学习轨道的源代码加载到 Pharo 映像中，也就是它的开发基线。克隆得到的代码仓库所在的本地文件夹位于（取决于你的 Iceberg 偏好设置）：`<path-to-Pharo-image>/pharo-local/iceberg/<your-id/pharo-smalltalk`。
> __注意__：Pharo 映像的源代码会同步并序列化到 `*.st` 文件中，这些文件位于上述目录的 `src` 子文件夹里。

2. 另一种做法是通过 CLI 克隆你的 fork：把`git clone https://github.com/<your id>/pharo-smalltalk`作为 GitHub 项目克隆，并把`<your id>`指定为 owner 名称，`pharo-smalltalk`指定为项目名称。
然后在运行中的 Pharo 映像里，用 Metacello 上下文菜单在 Iceberg 中安装 Metacello 基线 `dev`（不是默认那个）。（例如，右键点击你刚克隆的“pharo-smalltalk”项目，选择 Metacello 菜单里的第二项，输入 `dev`）

3. 把项目加载到 Pharo 映像后，别忘了 __保存映像__（菜单项 Pharo -> Save）。

__可选代码仓库__
1. 或者，你可以把`git clone https://github.com/exercism/pharo-smalltalk`克隆成一个暂存代码仓库，用来生成要提交的练习和资源文件（与在 Pharo 里写代码分开）。注意，Configlet 工具在这个代码仓库里生成的改动，需要复制到你本地的 fork 代码仓库中。建议使用类似`~/development/exercism/pharo-staging`的路径，以免混淆（注意：它放在哪里都可以）。这个代码仓库并非必需，如果你清楚要把哪些改动包含进提交，仍然可以直接在 fork 的代码仓库（它与你的 Pharo 映像同步）里生成 configlet 改动。
2. 如果你想从零开始做实践练习，也可以克隆 Exercism 的[问题规范](https://github.com/exercism/problem-specifications)。也把它放到下面配置的 exercism 工作区的子目录里（这个代码仓库用于生成练习的 readme.md 文件，也是建议测试用例的参考）。

### __关于所用代码仓库分支的说明__

`main` 分支是主要开发分支，所有内容都合并到它上面。如果你要改动代码，请从 main 创建一个功能分支，把改动提交到那里。完成后，在 GitHub 上发起 PR，合并到基础代码仓库（Exercism/pharo-smalltalk）的 `main` 分支。这个分支以前叫 `master`，__现已废弃__。

### __设置 Exercism CLI 工具__

与 Exercism 项目交互需要这些工具：
1. [exercism 命令行界面](https://exercism.io/cli-walkthrough)，并把它配置到用于开发 Exercism 练习的目录，也就是工作区（例如 `exercism configure -w ~/development/exercism`）。这个路径可以指向你本地的 fork 代码仓库，也可以（可选）指向暂存代码仓库。
2. Exercism 的 [configlet](https://github.com/exercism/configlet#usage) 检查器/生成器，用于生成练习元数据并运行校验。要安装 Configlet，请按照[在你的学习轨道中使用](https://github.com/exercism/configlet#use-in-your-track)一节的说明操作（参见 bin/fetch-configlet）。

## 开发 Exercism 练习

Exercism 组织把概念练习（讲解编程语言理论）和实践练习区分开来。下面几段目前只讨论实践练习的贡献。

### __概览__

完成练习的步骤：
1a. 从零创建实践练习（基于问题规范）。
1b. 处理现有实践练习的解答。
2a. 把练习解答的序列化源文件生成到目录中，并生成练习元数据。
2b. 调整项目基线，把新完成的练习纳入项目。
3. 把改动提交到你的 fork 代码仓库，并提交 PR 来发布改动。

#### TLDR：生成并导出实践练习的快速指南
简而言之，你只需要在 Pharo 中生成并导出练习，在 Playground 中执行：
```Smalltalk
"Obtain exercise from problem specification"
ExercismExerciseGenerator new generateExerciseFrom: 'path-to-problem-specifications/exercises/slug-name' asFileReference.

"Update exercise version within Pharo image  (with updated test cases) to output exercise directory (once you have solution class defined)"
ExercismGenerator new 
	exercisesDirReference: 'path-to-local-repository/exercises/practice' asFileReference;
	generateForExercise: 'slug-name'.
```
  > __注意__：更多细节见下面的步骤。

![完成实践练习的工作流](/docs/images/overview-exercism-pharo-contribution.svg)

### __1. 创建新的实践练习__
*TLDR：与练习生成相关的所有细节和 API 说明，都可以在 `ExercismExerciseGenerator` 类的类注释里找到。*

__从问题规范代码仓库创建新练习__
- 如果你想完全从零开始做新实践练习（步骤 1a.），可以使用问题规范代码仓库，通过运行以下命令为指定练习生成测试类：
`ExercismExerciseGenerator generateFrom: <path-to-problem-specifications/exercises>`，这会在 `ExerciseWIP` 包中为问题规范代码仓库里的所有练习生成测试类。

  > __注意__：你也可以用 Pharo 映像里的菜单项完成同样的操作（World menu -> Exercism -> Generate test cases）。
- 更具体地说，你可以用下面的代码为特定练习生成测试类：`ExercismExerciseGenerator generateExerciseFrom: '<path-to-problem-specifications/exercises/slug-name>' asFileReference`。

上面语句的结果是一个新的 `<SlugNameTest>`（ExercismTest 的子类）测试类，其中包含生成在 `ExerciseWIP` 包中的测试方法。

__从问题规范代码仓库重新生成现有练习__
如果你想重新生成现有练习（已经定义在解答包中，例如 `Exercise@TwoFer`）的测试方法，可以使用下面的代码。注意其他方法不会被改动（例如 uuid、version 等）。

 `ExercismExerciseGenerator new regenerateExerciseFrom: 'path-to-problem-specifications/exercises/exercise-slug' asFileReference`

__从零开始__
如果你有好点子，请参考关于添加新练习的文档。

项目中有一个用户自定义练习的示例，见 `DieTest`。通过重写 customData 方法，生成器会为你创建相关文件。

注意：
- 每个练习必须自成一体。不要引用练习目录之外的文件。用户获取练习时，这些文件不会被包含在内。
- 练习必须符合 [Exercism 全局标准](https://exercism.org/docs/building/tracks/practice-exercises)。
- 练习只应使用 Pharo 核心库。
- 每个练习应当：
  - 存储在名为 `Exercism@<ExerciseName>` 的顶层项目中
  - 有一个名为 `<ExerciseName>Test`（采用 CamelCase）的 TestCase，以及一个名为 `<ExerciseName>` 的示例解答
  - TestCase 应当有一个 markdown 格式的类注释，描述这个练习。这段文字也用于生成 README.md 文件。
- 不要在练习内部提交任何配置文件或目录（未来可能会重新审视这一点，如果这成为问题请告诉我们）。
- 务必用 `UUIDGenerator next` 为练习生成新的 UUID，并把该值放进测试的 `uuid` 方法中。

> __注意__：遗憾的是，当前的 Pharo UUID 生成器不符合 RFC 4122 第 4 版。因此应当通过执行 `/bin/configlet uuid` 来使用由 configlet 生成的 UUID。

### __2. 处理现有练习__

虽然有很多帮忙的方式，但到目前为止最简单也最有用的贡献，就是为当前任何“开放”的练习完成一个解答。

  * 确保你的映像已更新到 exercism/pharo-smalltalk 的 main（并把任何改动推回你的 fork）

  * 这些练习都是从上述 problem-specifications 代码仓库自动生成的 TestCase。你会在 ExercismWIP 包中找到它们，作为 ExercismTest 的子类。注意，如果解答已经就位，重新生成的 ExercismTest 可能已经在对应的练习包里。ExercismWIP 包用于还没有连同解答类一起发布的新练习或进行中的练习。

  * 一旦选定了要处理的练习，就在 GitHub 上创建一个 Issue，写明“Convert Exercise <name>”。这样别人就知道你正在做这个练习，也会成为你之后 pull request 的基础。

  * 每个进行中的练习的类注释里已经有问题描述，你可以运行它的测试，用 TDD 写一个解答（如果单独运行第一个测试，会在调试器里进行）。

  * 如果测试不符合 Smalltalk 的习惯写法，你可能需要__调整测试__（我们的生成器相当基础，话虽如此，有些修正或许适合作为 PR 回馈给上游的[问题规范](https://github.com/exercism/problem-specifications)文本）。

  * 通过重写 #exercise 方法并填写难度、主题等，更新练习类侧的练习元数据。你还应当在 Test comment 标签页（在底部，把 TBD 文字替换掉）里填写一些提示文字。

  * 把所选示例的包改为 `Exercise@<ExerciseName>`（也就是把它移出 WIP 包），即步骤 1b。
  * 在 Iceberg 中用你选定的练习名创建一个新分支（你可以用 Iceberg 工具来做，并填入上面提到的 issue 编号）。
  * 提交 pull request 之前，运行 Pharo 所有练习的测试，并确保它们__全部通过__。


### 测试

在最基本的层面上，Exercism 的核心就是测试，以及用[测试套件](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md)来测试。

Pharo 的 exercism 练习组织成若干子包，每个子包里有一个必须与 [SUnit](https://en.wikipedia.org/wiki/SUnit) 兼容的 TestCase。SUnit 是最早的 xUnit 库，练习不需要任何额外的第三方框架。

要测试某个练习，点击 test orb，从内置的测试运行器中运行它。如果测试成功，orb 会变绿；如果有失败或错误，它会分别变成橙色或红色。或者你也可以在 playground 中手动运行测试，执行下面的代码：

```smalltalk
<ExerciseName>Test suite run. "single exercise"

AllExercismTests suite run. "all exercises"
```
> __注意：__如果你想定义自己的（非生成的）测试用例，可以把它放到测试类的 `extra` 协议里。
为保持一致，我们在测试方法中使用这样的测试参数顺序：`self assert: actual equals: expected`。


要在非开发映像中测试，你应当遵循[用户安装步骤](./docs/INSTALLATION.md)。如果你
用那个映像来测试后续的开发基线，可能需要删除下面的开发目录，以确保拿到最新的代码：
`./pharo/pharo-local/iceberg, ./pharo/pharo-local/package-cache`


### __3. 发布已完成的练习__

当你完成了解答并把改动提交到本地功能分支后，应当完成以下步骤：
#### 生成练习源代码
这指的是步骤 2a：为解答和测试类__生成源代码__文件。

__为所有练习生成输出源代码__
- `ExercismGenerator generate` -> 这会生成所有练习的全部源代码文件。它会运行 configlet 的 `generate` 命令，并重新生成列出所有有效练习的 `config.json`。（或者在 World menu 中选择：“Exercism” -> “Regenerate meta data”）

#### 为特定练习生成输出源代码
- 使用默认目录（`repository-root/exercises/practice`）时
```
ExercismGenerator new generateForExercise: 'slug-name'
```

需要导出到指定的练习目录时：
```
ExercismGenerator new 
	exercisesDirReference: 'path-to-exercises/practice' asFileReference;
	generateForExercise: 'slug-name'
```

> __注意__：
  - ExercismGenerator 会自动更新主 config.json（如果不存在则新建）。
  - 会使用 configlet 命令为指定的练习同步所有文档、元数据和文件路径。详情见：[添加新练习时使用 sync](https://github.com/exercism/configlet#using-sync-when-adding-a-new-exercise-to-a-track)

#### 更新 Pharo-smalltalk 项目基线
步骤 2b：在 `BaselineOfExercism>>exercisePackageNames` 方法的列表中加入练习名，从而更新 Pharo-smalltalk 项目基线。这样当通过 Metacello 命令加载包含新练习的项目时，你的练习就会被加载。
  
#### 提交 Pull Request
步骤 3：创建 PR 之前，你应当运行 CLI 命令检查 Exercism 制品是否正确：
`bin/configlet lint`（提交 PR 时，CI 自动化本来也会运行 lint 检查）。
如果一切正常，就可以创建 PR 了：
- 把你的分支推送到你的 fork，然后在 `exercism/pharo-Smalltalk` 上创建 pull request

> __最后几点__：

- 重要的一点是[允许维护者编辑](https://help.github.com/en/articles/allowing-changes-to-a-pull-request-branch-created-from-a-fork)，这样我们才能在你的分支上与你协作。
-  Pull request 应当聚焦于一个练习、一个 issue，或一个概念上内聚的改动。更多细节请参考 Exercism 的 [pull request 指南](https://github.com/exercism/docs/tree/main/building/github#guides)。
- 关注你的 PR，回答后续出现的任何问题。
- 最后提交任何调整，维护者会合并你的 Pull request，让最终解答出现在网站上。

## 给维护者的补充信息

### 编码风格

本代码仓库中的代码应尽可能遵循 [Pharo with style](https://github.com/SquareBracketAssociates/Booklet-PharoWithStyle) 的规范。你也可以参考更通用的 [Smalltalk with style](http://sdmeta.gforge.inria.fr/FreeBooks/WithStyle/SmalltalkWithStyle.pdf)。

创建练习时，你还应当利用内置的代码格式化工具（编辑器中的 meta-t FO），以及代码评审。

### 破坏性改动

如果你打算做重大或破坏性改动，请先创建一个 issue，以便我们在合并前讨论。如果这个讨论不只与 Pharo 学习轨道相关，也请在 [exercism/discussions](https://github.com/exercism/discussions/issues) 中创建一个 issue。
