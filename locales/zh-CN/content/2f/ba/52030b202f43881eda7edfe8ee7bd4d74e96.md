# 简介

## 字符串

### 字符

**字符编码**是一种特定的约定，用于把自然语言中的文本元素表示成字节序列。
这里的“文本元素”可以是任何在自然语言中有意义的单位，例如字母、空格、标点符号、emoji、表意文字等。

NASM（The Netwide Assembler，本 track 使用的汇编器）支持使用 **ASCII** 定义数据。

NASM 中的字符常量最长可达 8 字节，可以用单引号（`'`）、双引号（`"`）或反引号（`` ` ``）定义：

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

特殊字符必须用反引号定义，并用`\`转义：

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

注意，在 x86-64 中，字符编码并不是一种有内置支持的独立类型。
汇编中的数据就是字节序列，把这些字节解释成字符、数字还是别的什么，由程序员自己决定。

例如，ASCII 字符 '0' 是值为 48 的单个字节。
因此，把一个字节设为 48，与存入 ASCII 字符 '0' 完全是同一回事：

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

同理，操作字符就是直接变换这些字节中的值：

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### 字符串

**字符串**就是字符序列。
在汇编中，通常用数组来实现。

在 NASM 中，可以像声明任何数组那样声明字符串：

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

字符串与其他数组的一个区别是，NASM 还支持在声明字符串时不使用逗号（`,`）分隔各个值。
也可以把两种写法混用，有的值之间用逗号分隔：

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

注意，如前所述，字符就是字节（在 Unicode 编码中则是一段字节序列）：

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

由于每个 ASCII 字符只占一个字节，在更大的宽度中，后续的字节都是`0`。
例如，把`'a'`声明为 qword（8 字节）意味着第一个字节是`'a'`（`97`），其余七个字节都是`0`。

因此，下面几种写法完全等价：

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
在汇编中，字符串不会自动以 ASCII NUL 字符（值为`0`）结尾。

与 C 等更高级的语言交互时，由程序员负责确保在字符串末尾加上正确的终止符（如果有的话）。
~~~~

### 字符串指令

由于字符串就是数组，你可以像处理任何数组那样，通过显式解引用内存来操作它们：

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

除此之外，还有一些指令用于在内存的字节序列中加载、移动和存储值。
虽然它们被称为_字符串指令_，但其实可以用于内存中的任何字节序列，也就是任何数组。

最重要的三条字符串指令是`lods`、`stos`和`movs`：

| 指令 | 作用                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | 从`rsi`指向的内存位置加载一个值到`rax`                                                |
| `stos`      | 把`rax`中的值存储到`rdi`指向的内存位置                                               |
| `movs`      | 从`rsi`指向的内存位置复制一个值，并把它存储到`rdi`指向的内存位置    |

注意，这些指令_不_接受任何显式操作数。
它们的操作数是隐式的。

一个经验法则是：

1. 当源操作数是内存位置时，它的地址应存放在`rsi`中（`s`表示 source）。
2. 当目标操作数是内存位置时，它的地址则应存放在`rdi`中（`d`表示 destination）。
3. 如果其中一个操作数不是内存位置，那它就是`rax`寄存器。

注意，这些指令会根据它们执行的具体操作自动解引用内存地址。

它们都可以按不同的大小进行操作。
通过在指令后附加后缀来指明这个大小：

| 后缀 | 含义 | 大小    |
| :----: | ------- | :------ |
|  `b`   | 字节    | 1 字节  |
|  `w`   | 字    | 2 字节 |
|  `d`   | 双字   | 4 字节 |
|  `q`   | 四字   | 8 字节 |

例如：

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

它们还会按操作的大小更新所用到的地址。
更新的方式取决于**方向标志（DF）**的值：

- 如果`DF`被清零，地址会按操作的大小_增加_。
- 如果`DF`被置位，地址则会按同样的大小_减少_。

System V ABI 规定，方向标志必须在函数入口处清零。
所以，_默认行为是按地址递增的顺序读写内存_。

指令`cld`可以用来清零方向标志，而指令`std`则用来置位：

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
按照 System V ABI，调用方期望被调用的函数返回后`DF`是清零的。
只要你设置了`DF`，就要确保在`ret`之前把它清零。
~~~~

#### Rep

除此之外，**rep**指令并不直接与内存交互。
相反，它可以作为前缀加在上述其他指令前，_重复_执行那些指令。

加上`rep`前缀后，字符串指令会重复执行，次数等于`rcx`中的值。
每次重复时，`rcx`中的值都会减`1`。
注意，必须在使用这些指令之前设置好`rcx`的值：

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
在现代 CPU 上，搬运大块数据时，`rep movs`和`rep stos`通常是很快的选择。
但其他字符串指令，甚至不带`rep`的`movs`和`stos`，通常都比普通的循环慢。

关于这个主题更深入的讨论，可以参见[这本参考书第 16.9 章“字符串指令”][agner-optimization-guide]。
