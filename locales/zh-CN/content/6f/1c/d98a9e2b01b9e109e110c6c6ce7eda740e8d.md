# 浮点数

`FLTD`存的是一个可能有小数部分的数字。字面量需要一个小数点和一个`d`：

```sather
   440.0d
   0.5d
   -2.25d
```

`FLT`是同样的思路，但精度只有一半。本课程全程使用`FLTD`；除非内存紧张，否则没有理由去用`FLT`。

## 算术运算

| 运算符 | 含义 |
| --- | --- |
| `+` `-` `*` | 与`INT`相同 |
| `/` | 除法，保留小数部分 |

`FLTD`没有`%`。

两个操作数都必须是`FLTD`。混入一个`INT`是编译错误，而不是静默转换，这其实是一种优点：唯一会让人栽跟头的地方，恰恰就是人们容易搞错的地方。

## 转换

```sather
   7.fltd            -- 7.0, an INT made into an FLTD
   7.5d.int          -- 7, the fraction thrown away
   7.5d.round        -- 8, to the nearest whole number
   7.5d.floor        -- 7.0, down to a whole number
   7.5d.ceiling      -- 8.0, up to a whole number
```

要先转换再相除，绝不能反过来：`n.fltd / 2.0d`会保留那半个，而`(n / 2).fltd`已经把它丢掉了。

## 常用例程

```sather
   (-2.5d).abs       -- 2.5
   2.0d.sqrt         -- 1.41421
   (2.0d).max(3.0d)  -- 3.0
```

## 浮点数只是近似值

`FLTD`保存的是一个非常接近的近似值，而不是精确值。大多数十进制小数都无法精确存储，就像三分之一无法用十进制精确写出来一样。所以：

```sather
0.1d + 0.2d          -- very nearly 0.3, but not exactly
```

有 2 个后果值得记住：

**不要用`=`比较。** 两次本应得出相同答案的计算，结果常常在最后几位上不同。应该改为判断它们是否足够接近：

```sather
   (a - b).abs < 0.0001d
```

**累加许多小数值会损失精度。** 每次相加都会有一点舍入，误差会逐渐累积。

当数值必须精确时，尤其是涉及钱的时候，改用`INT`以整数单位来计数（用分而不是元）。

## 打印

`.str`显示大约 6 位有效数字，少于它实际保存的精度：

```sather
   #OUT + (1.0d / 3.0d).str;      -- 0.333333
```
