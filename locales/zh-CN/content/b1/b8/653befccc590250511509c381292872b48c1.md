# 简介

函数在调用自身时就是**递归**的。

函数调用和循环的一个关键区别在于，调用函数会把要返回的地址压入栈中。
这意味着递归函数通常比等价的循环需要更多的栈空间。

因此，一个不断调用自身的函数最终可能会耗尽所有栈空间。
这种情况称为**栈溢出**。

这就是为什么每个递归函数都必须至少有一个基本情况，也就是函数不再调用自身而直接返回的情形。
任何递归调用最终都必须到达某个基本情况。

例如，阶乘函数 `n! = n * (n - 1) * ... * 1` 可以用 `1` 作为基本情况递归地定义：

```x86asm
factorial:
    ; the argument `n` is passed on `rdi`
    ; the factorial will be returned on `rax`

    cmp rdi, 1
    jle .base_case     ; base case -> if rdi <= 1, return 1

    push rdi           ; save n
    dec rdi            ; rdi = n - 1
    call factorial     ; recursive call, rax = (n - 1)!
    pop rdi            ; restore n
    imul rax, rdi      ; rax = n * (n - 1)! = n!
    ret
.base_case:
    mov rax, 1
    ret
```

注意，`factorial`必须在递归之前`push rdi`，在递归之后`pop rdi`。
这是因为递归调用返回后，它仍然需要`n`来计算`n * (n-1)!`。

还要注意，使用被调用者保存寄存器并不能解决这个问题。

尽管递归函数可能是自身的调用者，但它本身也是某个其他函数的被调用者。
这意味着函数在使用被调用者保存寄存器之前也必须保存它们，并在使用之后恢复它们的值。
这通常通过`push`/`pop`序列来完成，就像我们在之前的概念中看到的那样。

由于递归函数的每个栈帧（基本情况除外）同时也是需要保存自身局部变量的调用者，因此这个`push`/`pop`序列必须在每个栈帧中重复。
即使不使用寄存器，而是直接把变量存到栈上，每个栈帧仍然要占用同样的`8`个字节。

这意味着每次递归调用都会因为`call`压入的返回地址而给栈增加`8`个字节，另外每保存一个局部变量还要再加`8`个字节。
函数会在每个栈帧中不断把这些字节加到栈上，直到到达基本情况。
只有到那时，它才开始按相反的顺序回退，每次递归调用按需使用相应数量的`pop`，然后执行一次`ret`。

例如，如果以实参`10`调用`factorial`，它会在到达基本情况`1`之前调用自身九次。
此时，用于存储每个之前栈帧的`n`（`8`个字节）和返回地址（`8`个字节）的字节数已经达到了`144`。

## 尾调用

在某些情况下，函数在调用另一个函数之后、返回之前不再做任何工作。

例如，考虑下面这段代码：

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    call times_three
    ret
```

函数`triple_of_square`：

- 把传入的实参（在`rdi`中）与自身相乘，得到它的平方；
- 然后调用`times_three`，它返回传入实参的三倍。

因此，`triple_of_square`返回`3*x²`，其中`x`是它的实参，通过`rdi`传入。

注意，`triple_of_square`在调用`times_three`之后没有做任何工作，函数直接返回。
在这种情况下，函数可以不使用`call`，而是用`jmp`把执行权转移给被调用的函数：

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    jmp times_three
```

这称为**尾调用**。

尾调用的主要优势在于省去了`call`的额外开销。
`call`会把一个返回地址压入栈，而要让控制权回到那个位置，就必须有一个与之配对的`ret`。

尾调用把两者都省掉了：没有要压入的返回地址，也没有需要配对的额外`ret`，只有被调用函数自己的`ret`。

## 尾递归

对于在返回之前可能多次调用自身的递归函数来说，尾调用特别有用。

不过，并不是每次递归调用都能直接转换为尾调用。
由于`jmp`会把控制权转移给被调用的函数，所以调用者在尾调用之后无法再做任何工作。

例如，前面的`factorial`函数**不是**尾递归的。
在递归调用之后，它仍然需要用`imul rax, rdi`把结果与当前的`n`相乘。

在这类情况下，有时可以使用一个累加器来收集部分计算结果，并在最后返回。
例如，我们可以定义一个承担大部分工作的`factorial_helper`，然后让`factorial`设置一个累加器并把控制权转移给`factorial_helper`：

```x86asm
factorial_helper:
    ; the argument `n` is passed on `rdi`
    ; `rax` is used as an accumulator and will be returned at the end

    cmp rdi, 1
    jle .base_case

    imul rax, rdi        ; we accumulate the partial result on `rax`
    dec rdi              ; rdi = n - 1
    jmp factorial_helper ; tail call to accumulate (n - 1)!
.base_case:
    ret                  ; returns the factorial already accumulated on `rax`

factorial:
    mov rax, 1           ; initial value for the accumulator
    jmp factorial_helper ; tail call
```

由于递归调用之后不再做任何工作，我们也不再需要保存`rdi`。
没有`call`，也没有`push rdi`，所以每次递归迭代给栈增加`0`个字节：不会占用额外的栈空间。
这个版本可以处理任意大的`n`，而不会让栈溢出。
它既更高效，也更安全。

在某些情况下，通过调整函数的顺序，甚至可以省去跳转到辅助函数的那个`jmp`。
例如，`factorial`和`triple_of_square`可以这样改写：

```x86asm
factorial:
    mov rax, 1
factorial_helper:
    cmp rdi, 1
    jle .base_case

    imul rax, rdi
    dec rdi
    jmp factorial_helper
.base_case:
    ret

triple_of_square:
    imul rdi, rdi
times_three:
    imul rax, rdi, 3
    ret
```

在上面的代码片段中，`factorial`的执行会直接落入`factorial_helper`。
`triple_of_square`和`times_three`也是如此。
在两种情况下，执行都是顺序继续的，尾函数看起来就像是“主”函数内部的一个局部标签。

实际上，任何局部标签和函数之间都没有本质区别。
x86-64 汇编不会对它们中的任何一个给予特殊对待，它们只是某个存放可执行代码的段（例如`section .text`）中的地址。

这样一来，尾递归函数基本上可以看作与循环相同：递归调用跳回到顶部，而基本情况就是结束循环的条件。
