# 关于

Swift 有很多不同的类型，但每个类型都归属于两种分类之一：_值类型_和_引用类型_。在 Swift 中，[结构体是值类型][structs-are-value-types]，而[类是引用类型][classes-are-reference-types]。

值类型和引用类型的主要区别在于：当值类型被赋给一个变量或常量，或者被传入一个函数时，实际被赋值或传入的是该值的一个副本，而不是那个值本身。修改结构体的一个副本不会影响其他副本。而对于引用类型，被赋值或传入的是指向该值的引用，所以两个不同的名字可以指向同一个类的实例。这可能导致通过另一个名字访问时修改了原来的实例。

那么，给定一个定义游戏中角色的结构体和一个类，以及它们的游戏统计数据，我们来看看这些东西被复制和修改时会发生什么。

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

注意，修改`charB`的属性也影响了`charA`的属性，因为这两个名字指向同一个实例。还要注意，就这两个角色的统计数据而言，引用类型内部的值类型会随着引用类型一起改变。不过，这并不违背值类型的行为，因为`charA.stats`和`charB.stats`是`CharacterStats`的同一个实例，`charA`和`charB`指向的是`GameCharacter`类的同一个实例。例如，可以看到，这些值类型的副本之间不会互相影响。

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

这就是为什么结构体要求在会改变其属性状态的方法前面加上`mutating`关键字。修改结构体的属性实际上会创建该结构体的一个新副本，把这个属性的新值设置进去，再用新副本替换原来的副本。它是一个直观的提示，表明该类型的值可能会发生这种复制和替换。

由此带来一个副作用：任何可变属性会发生变化的结构体实例，无论是通过调用可变方法还是直接赋值，这个实例都_必须_赋给变量，而不能赋给常量。否则编译器会报错：

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

初始值仍然可以创建和访问，但不允许改变。这一限制不适用于类。如果用`let`把一个类的实例赋给一个名字，那么常量持有的是指向该实例的引用，不能改变的是这个引用，而不是实例本身。所以实例本身可以改变，但引用不能改为指向另一个实例。

用`let`或`var`定义的结构体和类分别允许哪些改动，总结如下：

|         | **struct**                                                                                  | **class**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _无法_给该名字赋一个新的结构体。</br>_无法_修改该结构体的任何属性。 | _无法_给该名字赋一个新的类。</br>_可以_修改该类中可变的属性。 |
| **var** | _可以_给该名字赋一个新的结构体。</br>_可以_修改该结构体中可变的属性。   | _可以_给该名字赋一个新的类。</br>_可以_修改该类中可变的属性。    |

## 同一性

因为两个不同的名字可能持有同一个类实例的引用，有时需要判断情况是否如此。Swift 用`===`这个_恒等_运算符来做这种判断（以及它的取反形式`!==`）。

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

因为两个名字不可能指向同一个结构体实例，所以这些恒等运算符没有为结构体定义。

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

注意，同一性不等同于相等。按照很多定义，`char1`和`char3`会被认为是相等的，因为它们的所有属性值都相同，但它们的同一性并不相同。在 Swift 中，所有类都自动支持同一性判断，但开发者通常需要自己编写相等运算符，来判断一个结构体或类的两个实例是否_相等_。这超出了本练习的范围。
