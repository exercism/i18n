# 简介

正则表达式是一种非常通用的字符串_模式匹配_方式，它使用为此专门设计的领域特定语言（DSL）。

许多正则表达式功能都内置于 Base R 中，你可能在旧代码里看到相关示例。

对于新代码，_强烈_建议使用[`stringr`][web-stringr]库。

正如[字符串概念][concept-strings]中提到的，`stringr`有完善的文档，通常由包的作者编写。

- 一个[参考网站][web-stringr]
- 一份[速查表][cheat-stringr]。
- “R for Data Science” 中的[字符串章节][book-strings]和[正则表达式章节][book-regex]。

在[`Strings`][concept-strings]概念中已经讨论过的许多函数，本来就支持正则表达式搜索。

我们把字符串概念讲得相对简单，只针对字符串字面量进行匹配，但其实完全可以使用任意正则表达式模式。

严格来说，在 R 中通过调用[`regex()`][ref-regex]来创建正则表达式。
为方便起见，`stringr`函数会把任何模式字符串都当作正则表达式来处理。
在下面的例子中，第一个`str_replace_all()`是第二种写法的语法糖：

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[速查表][cheat-stringr]是一份很有用的指南：所有带`pattern`参数的函数（以红色标出）都接受正则表达式，第 2 页还总结了正则表达式语法。

注意，如果你需要覆盖默认行为，比如大小写敏感性或区域设置，[`regex()`][ref-regex]函数仍然很重要。

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

很多正则表达式的写法都包含反斜杠，比如上面用到的`\s`。
在普通的 R 字符串中，`\`需要用双写来转义，因此写成`"\\s"`。

反斜杠容易越写越多，让人看得眼花，所以在复杂的情况下，使用[原始字符串][book-raw]可能会有所帮助。

默认情况下，定义原始字符串的语法是`r"( )"`，但也可以使用其他定界符。
由于圆括号`( )`和方括号`[ ]`在正则表达式语法中都很常见（用于捕获组和选项组），大括号`{ }`也许是个不错的选择。

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## 检测匹配

下面列出了一些问题，以及能帮你解答它们的函数。

有些例子用到了`fruit`，它是`stringr`附带的、包含 80 个水果名称的向量，方便用来练习。

_字符串中是否包含匹配？_
用`str_detect()`，或者用`str_starts()`、`str_ends()`来避免使用`^`或`$`锚点。

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_只返回包含匹配的字符串？_
用`str_subset()`取出这些字符串，用`str_which()`取出它们的下标。

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_每个字符串里有多少个匹配？_
用`str_count()`。

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_匹配在哪里？_
交互式查看用`str_view()`，更通用的场合用`str_locate()`或`str_locate_all()`。

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## 捕获

通常，我们想知道_到底什么_被匹配到了。
要做到这一点，可以在正则表达式里用括号加入捕获组。

在同一个正则表达式内部，可以用`\1`、`\2`等反向引用捕获的内容。
例如，找出重复出现的字母对：

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

用类似的语法，捕获也可以用在替换字符串中：

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

如果只需要第一个匹配，用`str_match()`函数收集匹配以便后续处理；如果需要所有匹配，就用`str_match_all()`。

无论用哪种语言，捕获组往往都会产生复杂的输出。
R 的做法（_它同样是向量化的，这也算是一项额外的挑战_）是用`str_match()`生成一个矩阵：每个输入字符串占一行，第 1 列是完整的匹配字符串，其余各列是各个捕获组。

使用具名组会带来好处，因为它们会成为结果矩阵的列名。

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

本教学大纲里还没怎么讲过矩阵，不过有一份[概念文档][concept-matrices-arrays]可供查阅。
尽管矩阵长期以来都是 Base R 的一部分，但它与 Tidyverse 生态并不太契合。

简单总结一下：把矩阵看作带 2 个下标的向量，顺序是`[rows, cols]`。
把任一位置留空，就能取到整行或整列。

用`m[r,]`取单行`r`，或用`m[,c]`取单列`c`时，返回的值默认会被展平成一个向量。

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

`str_match_all()`不可避免地会产生结构更复杂的输出：

- 结果是一个列表，每个输入字符串对应一个元素。
- 如果只有一个输入字符串，可以按照[列表概念][concept-lists]中描述的方法，用`[[1]]`索引把输出展开。
- 每个元素都是一个矩阵，各列的含义与`match()`相同。
- 矩阵中的每一行都对应一次成功的捕获。

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

当然，匹配也可能失败。
这时结果会是特殊值`NA`。
要做好检测它的准备，具体见[空无概念][concept-nothingness]。

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
