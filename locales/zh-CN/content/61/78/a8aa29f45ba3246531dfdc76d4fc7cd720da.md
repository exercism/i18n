# 布尔值

`BOOL` 只保存两个值中的一个：`true` 和 `false`。

```sather
   ready : BOOL is
      return true;
   end;
```

## 比较

| 运算符 | 询问 | 示例 |
| --- | --- | --- |
| `=` | 相同吗？ | `age = 13` |
| `/=` | 不同吗？ | `age /= 13` |
| `<` | 小于 | `age < 13` |
| `<=` | 小于或等于 | `age <= 13` |
| `>` | 大于 | `age > 13` |
| `>=` | 大于或等于 | `age >= 13` |

这些运算符可用于数字，`=` 和 `/=` 也可以用于字符串。

## 三个运算符

| 运算符 | 写法 | 为真的条件 |
| --- | --- | --- |
| and | `a and b` | 两者都为真 |
| or | `a or b` | 至少有一个为真 |
| not | `~a` | `a` 为假 |

`and` 和 `or` 都是**短路**的：`a and b` 一旦发现 `a` 为假，就不会再去看 `b`，因为答案已经确定了。同样，`a or b` 在 `a` 为真时就会停下。当右侧的表达式开销很大，或者运行起来会出错时，这一点就很重要。

## 直接返回比较结果

如果一个例程的全部工作就是提出一个问题，那么它应该返回这个问题，而不是用条件判断挑出一个答案：

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

写成 `if age >= 13 then return true else return false end`，要用三行才能表达出比较运算本身已经说清楚的东西，而且每个有经验的读者都会注意到。

## 优先级

`~` 的结合最紧，其次是 `and`，最后是 `or`。所以

```sather
~a and b or c
```

的含义是 `((~a) and b) or c`。写括号不费什么力气，只要不写读者就得回忆起这个优先级顺序才能读懂这一行，那么括号就值得写。
