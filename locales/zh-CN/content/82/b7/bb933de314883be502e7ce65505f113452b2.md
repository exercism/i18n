# 说明

在这个练习中，你将处理包含六种严重级别的日志消息。

每一行日志都是一个字符串，格式如下：`"[<LVL>]: <MESSAGE>"`。

以下是不同的日志级别：

| 级别      | 缩写  |
| --------- | ----- |
| `Trace`   | `TRC` |
| `Debug`   | `DBG` |
| `Info`    | `INF` |
| `Warning` | `WRN` |
| `Error`   | `ERR` |
| `Fatal`   | `FTL` |

## 1. 解析日志级别

定义一个`LogLevel`枚举，它包含六个元素，分别对应上面定义的日志级别。
接下来，定义`parse_log_level`函数，它接收日志消息作为形参，并返回其级别对应的枚举成员。

```python
parse_log_level("[INF]: File deleted")
#=> LogLevel.Info
```

## 2. 支持未知日志级别

遗憾的是，有些日志消息偶尔会带有_未知_的严重级别。为了在`parse_log_level`函数中优雅地处理这些“神秘”的日志消息，请给`LogLevel`枚举添加一个`Unknown`成员，在解析未知日志级别时返回该成员：

```python
parse_log_level("[XYZ]: Overly specific, out of context message")
#=> LogLevel.Unknown
```

## 3. 将日志消息转换为短格式

日志行的级别名称相当冗长。为了减少存储日志消息所需的磁盘空间，我们定义了短格式：`"[<CODE_LEVEL>]:<MESSAGE>"`。

日志级别代码的映射关系很直接：

| 级别      | 代码 |
| --------- | ---- |
| `Trace`   | `0`  |
| `Debug`   | `1`  |
| `Info`    | `4`  |
| `Warning` | `5`  |
| `Error`   | `6`  |
| `Fatal`   | `7`  |
| `Unknown` | `42` |

定义`convert_to_short_log()`函数，它接收两个形参：

1. 日志级别 - 所发送日志的级别。例如：`LogLevel.Error`。
2. 日志消息 - 类型为`str`的消息。

```python
convert_to_short_log(LogLevel.Error, "Stack overflow")
# => "6:Stack overflow"
```

## 4. 创建别名

看起来用户创建的日志使用的是`LogLevel.Warn`，而不是`LogLevel.Warning`。请为`LogLevel.Warning`创建一个`alias`，并在`get_warn_alias`函数中返回这个新的别名成员。

这可以在文件顶部已经定义的同一个枚举类`LogLevel`上完成。这两个 LogLevel 应指向同一个值：`"WRN"`。

```python
get_warn_alias()
#=> LogLevel.Warn

get_warn_alias() == LogLevel.Warning
#=> True
```

## 5. 所有成员的名称和值

定义`get_members()`函数。

这个函数应返回一个由元组`(name, value)`组成的数组，其中包含枚举`LogLevel`的所有成员。

```python
get_members()
#=> [('Trace', 'TRC'), ('Debug', 'DBG'), ('Info', 'INF'), ('Warning', 'WRN'),
# ('Error', 'ERR'), ('Fatal', 'FTL'), ('Unknown', 'UKN')]
```
