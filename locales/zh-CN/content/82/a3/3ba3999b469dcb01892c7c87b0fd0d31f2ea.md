# 不可变类

```sather
immutable class BEARING is
   readonly attr degrees : INT;
   create(d : INT) : SAME is
      b : SAME;
      return b.degrees(d);
   end;
end;
```

## 有什么变化

| | 普通类 | 不可变类 |
| --- | --- | --- |
| 赋值 | 共享对象 | 复制值 |
| 可以是 void | 可以 | 不可以 |
| `attr` 写入器 | `x.a := v` | `x := x.a(v)` |
| `new` | 可以 | 不可以；`x : SAME` 已经存在 |

不可变对象不可能为 void，所以`void(b)`永远是假，也不会因为缺少对象而让它的任何例程出错。这样就消除了一整类错误，代价是永远无法表示“还没有方位”。

## 值存放在哪里

值就存放在变量所在的地方，也就是另一个对象内部，或者栈上，而不是通过引用去访问。所以`ARRAY{BEARING}`存放的是方位本身，而不是指向它们的指针，这样占用更小，遍历也更快。

代价是复制：传递一个大的不可变对象时，每次都会复制它。所以它们最好保持小巧。

## 属性例程

`readonly attr degrees : INT`会给出两个例程：

```sather
   b.degrees          -- read: INT
   b.degrees(90)      -- answer a new BEARING with degrees changed
```

第二个例程即使在`readonly`下也存在，因为它不改变任何东西，而是构造出一个新值。在普通的`attr`下它是公有的；在`private attr`下则不是。

## is_eq 与 str

这两个都没有提供。为`=`编写`is_eq`，再编写`str`，让对象可以被打印并拼接字符串：

```sather
   is_eq(other : SAME) : BOOL is return degrees = other.degrees; end;
   str : STR is return degrees.str + " degrees"; end;
```

编写`str`会让该类符合`$STR`，这正是`+`和`#OUT`能接受它的原因。

## 内置的那些

`INT`、`BOOL`、`CHAR`、`FLTD`和`TUP`都是不可变类。它们没有任何特别之处：它们同样是用 Sather 写在库里的，其行为也是出于上面这些原因。
