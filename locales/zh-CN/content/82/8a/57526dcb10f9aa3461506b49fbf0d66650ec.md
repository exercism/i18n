# 关于

手写汇编充满了重复。
同一小段指令反复出现，几乎没有变化，而能够减少样板代码的抽象也寥寥无几。
不仅如此，用汇编编程时，管理值的过程也没有任何显而易见的语义。
这里没有具名形参，底层机制的多数细节都得由程序员手动处理。

本 track 使用的汇编器 NASM 提供了一些工具，能帮程序员解决这两个问题。
这些工具在_汇编期_运行，此时还没有任何指令到达处理器。
它们指导汇编器在源代码被翻译成机器码之前就重写源文本。

其中最重要的工具是**宏**，可以把宏看作写给汇编器的一份配方。
宏在使用的位置展开，就好像那段代码本来就是手写在那里的一样。

[宏][macro]可以接受若干字面量记号作为形参，从而能在不同场景中复用。
不过，宏不是函数：没有 `call`，没有 `ret`，也不会把控制权转移到代码中的另一处。

## 单行宏

最简单的定义方式是用 `%define` 给一个值或一段短表达式起名：

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

在汇编之前，后续每次出现的 `WIDTH` 都会被替换成 `8`。
这种替换是文本层面的，所以只要名字出现就会被替换，无论是在操作数里还是在另一个定义内部。

~~~~exercism/note
对于数值_常量_，优先使用 `equ`，而不是 `%define`。

用 `%define` 声明的单行宏只在被使用时才展开，而且可以被重新赋值或取消定义。
而 `equ` 常量在定义处就完成求值，之后永远不会被修改。
~~~~

`%define` 也可以接受_具名_形参，行为就像一个小型的内联函数：

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
整个宏体和每个形参都要用括号括起来。
如果写成 `%define square(x) x*x`，调用 `square(1+1)` 会展开成 `1+1*1+1`，结果是 `3`。
改写成 `%define square(x) ((x)*(x))` 后，同一个调用会展开成 `((1+1)*(1+1))`，结果是 `4`。
~~~~

用 `%define` 定义的名字区分大小写。
如果需要，可以用变体 `%idefine` 让名字不区分大小写。

单行宏很适合用来给代码的各个部分赋予含义。
只要用心使用，就能提升可读性，减少打错字的可能。
例如，某个在函数内承担专门用途的寄存器，可以用它的用途来定义：

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## 多行宏

一整段代码，无论有多少行，都可以用 `%macro` 捕获，并以 `%endmacro` 结束。
名字后面的数字表示宏接受多少个实参，可以是 0。
传实参时，用逗号（`,`）分隔：

```x86asm
%macro example_macro 0
...
%endmacro
```

多行宏的实参没有名字。
它们按传入顺序被称为 `%1`、`%2`，依此类推：

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

注意，实参必须使宏体内所执行的操作语法合法。
这里 `mult_two eax, ecx` 和 `mult_two r8, r9` 都能汇编通过，但 `mult_two eax, cl` 不行，因为 `imul eax, cl` 没有定义。

宏也可以接受任意数量的实参。
这是用 `n-*` 这种写法实现的，其中 `n` 是实参的最小数量：

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

在多行宏中，`%0` 表示宏的实参_数量_。
这在可能接受任意数量实参的宏中特别有用。

### 宏内部的标签

定义了普通标签的宏一旦被使用两次就会出问题，因为那样标签也会被定义两次。
要在可能被多次调用的宏里使用标签，就需要给这样的标签加上前缀 `%%`。
这会指示汇编器在每次展开时给这个标签一个不同的、唯一的名字：

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## 在汇编期重复

可以用 [`times`][times] 重复单行代码块。
在内存中声明重复的值时，这特别有用：

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

要重复多行代码，可以改用 `%rep`：

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

注意，重复次数紧跟在 `%rep` 后面指定，并用 `%endrep` 结束重复的代码块。

在 `%rep` 块里使用汇编期计数器很常见，就像运行时的循环使用计数器一样。
汇编期的整数常量可以用 `equ` 声明，前面已经见过；而汇编期的整数_变量_则改用 `%assign`。
与 `%define` 不同，`%assign` 会立即求值成一个数字，并且可以被重新赋值：

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

预处理器运行之后，循环消失了，只剩下四条 `add` 指令，立即数 `0`、`1`、`2`、`3` 已经被写死在其中。
这就是由汇编器完成的循环展开：没有计数寄存器，也没有分支，只有直线执行的代码。

`%rep` 的另一个常见用途，是处理可能接受任意数量实参的宏中的实参。
这种情况下，`%rep` 通常与 `%rotate` 搭配使用，后者会轮换宏中的实参，让第二个实参变成第一个。
反复应用 `%rotate`，会让第三个、第四个乃至更靠后的实参依次成为第一个，从而保证每个实参都能被轮流处理：

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## 条件汇编

[预处理器][preprocessor]提供了多种条件指令。
它们在不同的分支之间做选择，就地展开自身的内容，但只有在条件成立时才会展开。

`%if` ... `%elif` ... `%else` ... `%endif` 根据数值判断来选择一个分支：

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef` 和 `%ifndef` 类似，但判断的是某个名字是否已被定义。
例如，可以用它们确保一个文件的内容只被包含一次，即使该文件被多个源文件引入：

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

你可能已经注意到，这个 track 里每个 `.asm` 文件的末尾都有这样一段代码：

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn` 会比较两段文本是否完全一致。
内置的 `__OUTPUT_FORMAT__` 会展开成当前的输出格式，所以那段代码是在检查输出格式是否为 `elf64`，也就是 Linux 系统使用的格式。
如果是，就会往目标文件里添加一条注释，声明栈应当拥有的权限，这是一种常见的安全措施。
如果不是，则一切不变。

## 结构体

要访问内存中某条记录的字段，就是把该字段的字节偏移量加到基地址上。
把那些偏移量写成原始数字既容易出错，也掩盖了它们的含义。
[`struc`][struc] 和 `endstruc` 则为一个布局起了名字，把每个字段变成在汇编期计算出的符号化偏移量。

在块内部，预留指令 `resb`、`resw`、`resd`、`resq` 会分别预留一个或多个字节、字、双字或四字。
给每个字段加上前导的 `.`，可以让它的名字只在结构体内部有效：

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

现在每个字段名都代表它的偏移量，因此 `thread.color` 是 `0`，`thread.tension` 是 `4`，`thread.name` 是 `12`。
NASM 还会定义 `<struc>_size` 表示总大小，其中 `<struc>` 是 `struc` 的名字。
例如这里 `thread_size` 就是 `4 + 8 + 16 = 28`。

访问字段的方法是把它在偏移量加到基址寄存器上，而 `thread_size` 是从一条记录跨到下一条的步长：

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

`struc` 只描述一种布局，它本身并不分配内存。
要创建一个已初始化的实例，可以在某个标签之后使用 `istruc ... iend`。
在实例内部，`at` 会把一个值放到指定的字段上：

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

注意 `thread.name` 是用 `"warp", 0` 初始化的，只占 5 个字节。
`struc` 中为它预留的另外 11 个字节会由 `iend` 自动填零，`iend` 会把实例用 `0` 补齐到 `thread_size`。

`struc` 不过是语法糖，所描述的内存我们也可以手动声明。
例如，上面的代码等价于下面这段，其中 `times 11 db 0` 确保末尾分配了 16 个字节：

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## 拆分成文件

宏通常单独放在一个文件里，需要用它们的每个源文件都用 `%include` 把它引进来：

```x86asm
%include "patterns.mac"
```

被指定的文件会在汇编之前原样插入到该位置，就好像其内容本来就在那里打出来一样。
这样定义就集中在一处，多个源文件可以共享它们。

如果宏文件可能会被单独汇编，它就应该带 `.asm` 扩展名。
注意，宏没有链接关系。
即使宏文件被汇编，它的宏也只会对用 `%include` 引入它的另一个文件可见。

否则，仅用于 `%include` 的文件可以带任何扩展名。
使用 `.asm` 或 `.mac` 都是一种常见的约定。
