# 简介

## 不透明类型

### 简介

不透明类型是 Elm 中的一种封装技术。
有些人也称之为信息隐藏，或隐藏实现细节。
它们也常用于强制进行验证，使用[解析，而非验证][parse-dont-validate]模式。
例如，你可以有一个`EmailAddress`不透明类型，它只能包含有效的电子邮件地址（而不是`String`，后者可以包含任何内容）。

### 创建不透明类型

[自定义类型][custom-types]有一个或多个*变体*，编译器会自动生成一个函数来创建每个*变体*，使用*变体*名称。
这些函数是创建自定义类型的唯一方式。
编译器也允许对这些变体进行解构。

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

默认情况下，所有这些都只存在于文件/模块内部，我们使用`exposing`关键字来选择导出哪些内容。
要创建不透明类型，只需选择不导出*变体*。

这样做时，你几乎总是需要通过公开自定义函数，来提供另一种创建和获取*变体*的方式。
这些自定义函数允许你在创建和获取*变体*时应用一些逻辑。
这会隐藏模块的内部实现细节，也意味着只要公开的函数保持不变，你可以随意更改实现细节。

### 解析，而非验证

不透明类型最常见的用途可能就是强制进行验证，使用[解析，而非验证][parse-dont-validate]模式。
在这种模式中，你公开一个函数，它接收一个输入，而该输入的结构或类型安全性比你想要的更少，例如`String`，然后把它解析成结构更丰富的类型，例如`EmailAddress`，要么返回该类型，要么返回一个错误（通常是`Maybe`或`Result`）。

例如，在下面的代码中，外部模块只能使用`parseEmailAddress`函数创建`EmailAddress`类型，所以当你处理`EmailAddress`类型时，可以确定它是有效的。

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
