# 关于

持有操作系统状态的资源（文件句柄、套接字、锁）需要*有保证的*清理，即使在异常展开调用栈时也不例外。Factor 的[`destructors`][destructors]词库为此提供了一个小框架，大多数内置资源（`<file-reader>`、`<file-writer>`、套接字等）也已经接入其中。

## 类与泛型词

一个类通过继承 `disposable` 并实现 `dispose*` 来加入这个框架：

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )`会分配元组，*并且*把它注册到当前的析构器作用域中，所以在分配和下一个安全点之间发生异常也不会泄漏资源。这个框架保证每个对象的 `dispose*` **至多运行一次**，重复调用 `dispose` 不会有任何效果。

## 外部调用者使用 `dispose`

| 词                | 作用                                          |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )`，释放资源；重复调用也安全        |
| `with-disposal`   | `( disposable quot -- )`，为一个资源限定作用域 |
| `with-destructors`| `( quot -- )`，打开一个注册表作用域           |
| `&dispose`        | `( obj -- obj )`，正常退出*或*失败退出时销毁  |
| `|dispose`        | `( obj -- obj )`，只在作用域展开时销毁        |

`with-disposal` 是单资源形式。如果要管理不止一个资源，就打开一个 `with-destructors` 作用域，并用 `&dispose`（你总是想释放它）或 `|dispose`（只在失败时释放，成功路径会保留它）来注册每一次获取。

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup` 是最基础的原语

如果只是想一次性做 try/finally 而不需要注册表，那么来自 `continuations` 的[`cleanup`][cleanup]就是更底层的词：

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` 严格来说功能更强（注册表可以在运行时增长），但当获取与释放的配对固定且就在本地时，`cleanup` 才最合适。
