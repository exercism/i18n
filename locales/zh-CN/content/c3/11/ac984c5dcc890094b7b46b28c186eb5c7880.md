# 说明

你的朋友 Leticia 在地铁站的失物招领处工作。

每找到一件物品，都会在当天的物品列表中新增一条记录。
到了月底，凡是无人认领的物品都会被移到一个保管箱里，箱子上贴着它被找到的日期标签。
这些事全都靠纸笔完成，所以有时会变得很麻烦！

Leticia 想请你帮忙把这些工作中的一部分自动化。

~~~~exercism/note
这就是本概念中提到的指令：

| 指令          | 说明                                                      |
|---------------|-----------------------------------------------------------|
| push a        | 将 a 压入栈，使 `rsp` 减少 a 的大小                       |
| pop a         | 将 a 从栈中弹出，使 `rsp` 增加 a 的大小                   |
~~~~

## 1. 为每件物品创建一条记录

你首先要做的是整理所有物品，以便能更轻松地查找它们。
在存储中，每件物品由它的 ID、一段描述、被找到的日期以及数量不定的类别来标识。

定义一个函数 `create_item_entry`，它没有返回值，会在某个内存位置插入一条物品记录。
这个函数可以接收任意数量的参数，其中前六个始终是：

1. 存放该记录的内存位置的地址。
2. 物品的 ID，为 64 位无符号整数。
3. 保存物品描述字符串的地址。
4. 物品被找到的日，为 64 位无符号整数。
5. 物品被找到的月，为 64 位无符号整数。
6. 物品的类别数量，为 64 位无符号整数。

之后的每个参数都是保存其中一个类别字符串的地址。

这些值应按照与参数相同的顺序存入提供的内存位置：ID、描述、日、月、类别数量，以及按顺序排列的每一个类别。

## 2. 为每月的物品列表预留空间

在这么多不同的列表里查找物品实在太麻烦了。
于是你决定每个月用一份单独的列表来整理所有物品。
这份列表用数组实现。

定义 `create_monthly_list` 函数，它在内存中为数组分配空间，并返回该内存位置的地址。
它接收以下参数：

1. 数组的容量（以字节为单位），为 64 位无符号整数。
2. 一个分配函数。

该分配函数接收一个 64 位无符号整数作为参数，表示要分配的内存大小（以字节为单位），并返回所分配空间的地址。

注意，分配到的空间的值是_未定义的_，因此应清空该空间中的所有字节，也就是把它们的值设为 `0`。

## 3. 把物品插入月度列表

每天，每件找到的物品都应插入月度列表。

定义 `insert_found_item` 函数，它没有返回值，接收以下参数：

1. 月度列表所在内存空间的地址。
2. 列表中已存储的当前记录数量，为 64 位无符号整数。
3. 要添加到列表中的新记录。

你可以认为新记录总能放进列表，并且列表中的每条记录都占用 120 字节的空间。

## 4. 打印一件物品

如果 Leticia 能在屏幕上看到打印出来的内容，查找某条特定的记录就会容易得多。

定义 `print_item` 函数，它接收以下参数：

1. 缓冲区的地址，其中可能存放一段以 ASCII NUL 结尾的引导字符串。
2. 月度列表所在内存空间的地址。
3. 要打印的物品在数组中的记录下标，为 64 位无符号整数。
4. 一个打印函数。

该函数没有返回值，并应以以下参数调用打印函数：

1. 存放引导字符串的内存位置的地址；如果没有传入字符串，则为 `0`（64 位整数）。
2. 要打印的物品在数组中的记录下标，为 64 位无符号整数。
3. 物品的 ID，为 64 位无符号整数。
4. 保存物品描述字符串的地址。
5. 物品被找到的日，为 64 位无符号整数。
6. 物品被找到的月，为 64 位无符号整数。
7. 物品的类别数量，为 64 位无符号整数。
8. 第一个类别字符串的地址。

引导字符串是可选的。
如果在打印函数中使用它，该字符串必须以 NUL 结尾（以 `0` 结束），并且最多包含 50 个字符，这已经算上了 NUL 终止符。
否则，应向打印函数传入值 `0`。

你可以认为列表中的每件物品都占用 120 字节的空间。
