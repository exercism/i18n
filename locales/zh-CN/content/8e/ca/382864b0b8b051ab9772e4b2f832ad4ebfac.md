# 测试

每个练习都会提供单元测试和一个 CMake 构建脚本。你需要自己提供实现。
每个测试文件都会与你的实现链接，生成一个运行测试的控制台可执行文件。运行该测试可执行文件时，每个失败的测试都会打印一条消息；当测试失败时，它会返回非零的退出状态。

测试文件的命名格式为`<exercise>_test.f90`，因此练习“Bob”的测试文件名是`bob_test.f90`。每个测试都会先有一段描述该测试的注释，然后是以`call assert_equal`开头的实际测试代码，例如：

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

要禁用某个测试，只需用`'!'`把它注释掉，例如：

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

完成每个练习的过程如下：

* 用 CMake 创建初始构建
* 对每个单元测试：
 * 先解决编译错误，让测试失败。
 * 只实现刚好能让测试通过的部分。
 * 重构你的实现，提高可读性、减少重复，等等。
 * 取消下一个测试的注释


## 用 CMake 创建初始构建

每个练习除了单元测试外，还会附带一个`CMakeLists.txt`文件。其中包含现成的 CMake 脚本，帮你处理构建。你通常不需要修改这个文件。这个现成的脚本假设你的实现位于以练习命名的源文件中。

例如，练习“Bob”期望实现位于`bob.f90`文件中。

**在运行 CMake 之前，先创建你的初始实现文件。**
如果在为练习“Bob”运行 CMake 时没有`bob.f90`文件，CMake 会报错说找不到文件。
**这些文件可以是空的，但必须存在。**

使用这个脚本，你可以运行`cmake -G`，并指定合适的生成器和练习所在目录，让 CMake 为你的环境生成合适的项目。CMake 会生成适合你操作系统的构建脚本。为了让这些生成的文件与练习源代码分开，常见的做法是创建一个名为`build`的目录，用来存放生成的构建文件和编译后的代码。

这样能让你的练习文件夹保持整洁。

**注意：第一次调用`cmake`时，会自动下载 [testlib](###-Testlib)。单元测试需要`testlib`才能运行。

由于你会为每个任务运行 CMake 来生成构建指令，不妨为这条命令创建一个 bash 脚本（Linux/MacOS）或批处理文件（Windows）。

CMake 创建好构建环境后，你就可以用适合自己环境的命令来构建代码：

* Linux 使用 make：`make`
* Windows 配合 Visual Studio：从菜单中选择 Build / Build Solution。
* Windows 配合 MingW：`mingw32-make.exe`
* Windows 配合 nMake：`nmake.exe`
* MacOS 配合 Xcode：从工具栏中选择 Build

下面展示了在不同环境中运行 CMake 的示例。

### Linux\MacOS 使用 Make

CMake 的生成器名称是`Unix Makefiles`。
假设当前练习是`bob`，并且我们位于该练习的文件夹中：

```
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

这个示例展示了在运行 CMake 之前先创建空的实现文件。

在 build 目录中直接输入 make 就能编译测试。这应该会产生编译时错误。修复错误后再次运行`make`。当所有构建错误都修复后，运行测试：

```
$ ctest -V
```
### Windows 配合 Visual Studio 2017

CMake 的生成器名称是`Visual Studio 15`。同一个生成器支持 Visual Studio 2017 的所有 IDE 版本：Community、Professional 和 Enterprise。假设当前练习是`bob`，并且我们位于该练习的文件夹中：

```
> copy nul: bob.f90
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

这个示例展示了在运行 CMake 之前先创建空的实现文件。

### Testlib

测试依赖一个名为`testlib`的小型库，它会在第一次用 cmake 配置构建时从 github 下载。

如果下载失败，也可以手动下载，例如：

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/TesterMain.f90
```
