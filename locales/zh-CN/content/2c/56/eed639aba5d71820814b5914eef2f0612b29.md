# 简介

## SIMD：整数

之前的概念介绍过打包浮点值：多个数字存放在同一个 `xmm` 寄存器中，按通道并行运算。
同样的 `xmm` 寄存器也可以存放打包的_整数_。

### 语法

SIMD 浮点模型的大部分内容原封不动地适用于打包整数：

- 128 位寄存器被划分为若干通道
- 指令会并行地作用于处于相同位置的各个通道
- 内存操作数遵循相同的 16 字节对齐规则

不过，语法稍有不同：

1. 一个_前缀_ `p`，用来表示该指令操作的是_打包_数据。
2. 所执行的操作，名称与其非 SIMD（也叫_标量_）版本相同（例如 `add`、`mul` 等）。
3. 一个后缀，用来表示每个通道的大小。

打包整数有四种通道宽度，每种都有自己的后缀：

| 通道宽度 | 字节数 | 128 位中的通道数 | 后缀 |
|------------|-------|-------------------|--------|
| 字节       | 1     | 16                | b      |
| 字         | 2     | 8                 | w      |
| 双字       | 4     | 4                 | d      |
| 四字       | 8     | 2                 | q      |

例如：

| 指令 | 含义                              |
|-------------|--------------------------------------|
| `paddb`     | 打包 `add`，8 位通道（16 个通道） |
| `paddw`     | 打包 `add`，16 位通道（8 个通道） |
| `paddd`     | 打包 `add`，32 位通道（4 个通道） |
| `paddq`     | 打包 `add`，64 位通道（2 个通道） |

有些指令输入的通道是一种大小，输出的却是另一种大小。
它们遵循同样的总体约定，但带有_两个_大小后缀。
第一个表示输入通道的大小，第二个表示输出通道的大小：

| 指令  | 含义                                           |
|--------------|---------------------------------------------------|
| `pmovsxwd`   | 打包 `movsx`，从 16 位通道到 32 位通道 |
| `pmuldq`     | 打包 `mul`，从 32 位通道到 64 位通道   |

### 内存移动

有两条以整数命名的指令在 `xmm` 寄存器与内存之间复制 128 位数据：

| 指令 | 说明                                             |
|-------------|---------------------------------------------------------|
| `movdqa`    | 将打包整数复制到_已对齐_的位置，或从该位置复制   |
| `movdqu`    | 将打包整数复制到_未对齐_的位置，或从该位置复制 |

它们的行为与 `movaps` 和 `movups` 类似：`movdqa` 在地址未对齐时会触发错误，而 `movdqu` 则接受任意地址。
这四条指令都原样复制 128 位，不对数据作任何解释。
以整数命名的那一对按惯例用于整数数据，但这并不是硬性要求。

~~~~exercism/note
这里的 `dq` 代表 `double-qword`，也就是 128 位（16 字节）。
~~~~

### 加法与减法

加法和减法遵循上述命名规则：

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

没有单独的有符号和无符号版本。
在补码表示中，无论通道按有符号还是无符号读取，加法和减法产生的位都相同，所以一条指令就能同时满足两种用途。
如何解释由你决定，和标量的 `add` 与 `sub` 完全一样。

这些指令在溢出时会**回绕**，和它们的标量版本一样。
8 位通道存放的值以 256 取模，所以 `paddb` 计算 `200 + 100` 会得到 `300 - 256 = 44`，放不下的位会被丢弃。

注意，这些多出来的位不会进位到下一个通道。
每个通道都与其他通道分开运算，尽管它们共用同一个寄存器。

### 饱和加法与减法

整数 SIMD 增加了一种浮点 SIMD 没有的运算：**饱和**加法与减法，它们会_钳制_结果而不是回绕。
结果高于通道范围时取该通道能存放的最大值；低于范围时取最小值。

饱和形式会在大小后缀之前插入 `s`（有符号）或 `us`（无符号）：

| 指令 | 含义                                    |
|-------------|--------------------------------------------|
| `paddsb`    | `add`，饱和，有符号 8 位通道      |
| `paddusb`   | `add`，饱和，无符号 8 位通道    |
| `psubsw`    | `sub`，饱和，有符号 16 位通道     |
| `psubusw`   | `sub`，饱和，无符号 16 位通道   |

钳制范围是相应大小和有符号性的整数所能表示的全部范围。
对于字节：

- 无符号字节钳制到 `[0, 255]`：`paddusb` 计算 `200 + 100` 得到 `255`，`psubusb` 计算 `5 - 10` 得到 `0`。
- 有符号字节钳制到 `[-128, 127]`：`paddsb` 计算 `100 + 50` 得到 `127`。

当通道存放的是有界量时，饱和就很重要，例如像素通道或音频采样。
回绕会把过亮的像素变成暗色，而钳制会让它保持在最大亮度，这才是你想要的结果。

~~~~exercism/note
饱和加法与减法只针对字节和字通道提供，双字和四字通道没有。
~~~~

### 乘法

两个 N 位值相乘可能得到 2N 位的积，但目标通道只有 N 位宽。
SIMD 运算通过指定保留积的哪一半来解决这个问题：要么保留低 N 位，要么保留高 N 位。

对于 16 位通道，会用到三条指令：

| 指令 | 含义                                                       |
|-------------|---------------------------------------------------------------|
| `pmullw`    | `mul`，16 位通道，保留每个积的低 16 位     |
| `pmulhw`    | `mul`，16 位通道，保留高 16 位，操作数为有符号   |
| `pmulhuw`   | `mul`，16 位通道，保留高 16 位，操作数为无符号 |

无论操作数按有符号还是无符号读取，积的低 16 位都相同，所以只有一条 `pmullw`。

但高 16 位会随结果的有符号性而变化。
因此高半部分乘法分别提供了有符号和无符号两种形式：

1. `pmulhw`，用于有符号乘法。
2. `pmulhuw`，多了一个 `u`，用于无符号乘法。

注意语法：

1. 一个 `p`，表示打包整数。
2. 所执行的操作 `mul`。
3. 一个 `h`，表示选取结果中“较高”的那部分位。
4. 一个可选的 `u`，表示结果应按无符号解释（也就是说，没有进行符号扩展）。
5. 最后是大小后缀 `w`，表示这是一次字（16 位）运算。

字的打包乘法完全遵循上面的规则。
双字（32 位）乘法也遵循该规则，但只有选取低半部分的变体：`pmulld`。

双字乘法没有选取高位的变体。
不过，有一些变体会_拓宽_乘法，存放_偶数索引_通道（也就是位置 0 和 2 的通道）完整的 64 位积：

| 指令 | 含义                                                                          |
|-------------|----------------------------------------------------------------------------------|
| `pmuludq`   | 将偶数索引的 32 位元素按无符号相乘，得到 2 个完整的 64 位积 |
| `pmuldq`    | 将偶数索引的 32 位元素按有符号相乘，得到 2 个完整的 64 位积   |

注意语法中使用了 `dq`，无符号乘法时它前面可能还有一个 `u`。
这是因为这些指令接收 `dword` 通道，输出 `qword` 通道。

### 除法

没有打包整数除法。
需要它的代码会先把值转换成浮点数，相除，再转换回来。

### 整数扩展

`movsx` 和 `movzx` 都有对应的打包版本。
它们遵循我们前面提到的语法，适用于输入通道大小与输出不同的指令：

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

注意，通道数量由较大的一方（输出）宽度决定。
指令会从源数据的低位部分读取这么多个通道。
这与我们前面见过的单精度和双精度浮点数之间的打包 `cvt` 指令语义相同。

### 在整数与浮点数之间转换

有一些指令可以在 32 位有符号整数与浮点通道之间转换。
它们遵循 `cvt` 和 `cvtt` 指令的常见语法，只是用 `dq` 而不是 `si` 来表示打包整数：

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
用 `pi` 表示打包整数的指令会写入旧式的 `mmx` 寄存器，在 x86-64 上实际上已被弃用。
请优先使用 `dq` 形式，它们使用 `xmm` 寄存器。
~~~~

前面关于浮点数与整数之间标量转换的说明在这里同样适用。
浮点数会按照一个名为 MXCSR 的特殊寄存器进行舍入，函数入口处不能假定它的模式。
还有一个 `cvtt` 变体（多了一个 `t`），它总是截断结果。

也可以在转换之前用 `round` 让打包浮点值处于已知状态。
舍入控制值与标量 `round` 相同，打包浮点值的语法也一样：

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
