# 任务

任务是我们希望大家来帮忙处理的 GitHub issue，从校对文本到构建概念练习，不一而足。
这些任务会展示在网站上，并链接到 GitHub 上对应的 issue。
每个任务都会带上一到多个属性，这些属性取自该 issue 的 label。
之后用户就能根据这些属性来筛选任务。

## 标签

一个 issue 要想被当作任务，必须带有一个或多个任务专用的 label。
因此维护者可以选择只让一部分 issue 以任务的形式出现。

每个任务 label 的格式都是`x:<type>/<value>`，目前支持五种任务类型：

- `action`
- `knowledge`
- `module`
- `size`
- `type`

### 操作标签

`x:action/<value>`这类 label 描述贡献者在处理该 issue 时会做哪一类工作。

| 标签 | 说明 |
| --- | --- |
| `x:action/create` | 从头开始做一件事 |
| `x:action/fix` | 修复一个 issue |
| `x:action/improve` | 改进现有的功能或内容 |
| `x:action/proofread` | 校对文本 |
| `x:action/sync` | 把内容同步到最新版本 |

### 知识标签

`x:knowledge/<value>`这类 label 描述贡献者需要具备多少 Exercism 知识。

| 标签 | 说明 |
| --- | --- |
| `x:knowledge/none` | 不需要任何 Exercism 知识 |
| `x:knowledge/elementary` | 需要少量 Exercism 知识 |
| `x:knowledge/intermediate` | 需要相当多的 Exercism 知识 |
| `x:knowledge/advanced` | 需要全面的 Exercism 知识 |

### 模块标签

`x:module/<value>`这类 label 表示贡献者将参与 Exercism 的哪一部分工作。

| 标签 | 说明 |
| --- | --- |
| `x:module/analyzer` | 处理分析器相关的工作 |
| `x:module/concept` | 处理概念相关的工作 |
| `x:module/concept-exercise` | 处理概念练习相关的工作 |
| `x:module/generator` | 处理练习生成器相关的工作 |
| `x:module/practice-exercise` | 处理实践练习相关的工作 |
| `x:module/representer` | 处理表示器相关的工作 |
| `x:module/test-runner` | 处理测试运行器相关的工作 |

### 规模标签

`x:size/<value>`这类 label 描述预计的工作量。

| 标签 | 说明 |
| --- | --- |
| `x:size/tiny` | 工作量极小 |
| `x:size/small` | 工作量小 |
| `x:size/medium` | 工作量中等 |
| `x:size/large` | 工作量大 |
| `x:size/massive` | 工作量超大 |

### 类型标签

`x:type/<value>`这类 label 描述贡献者将从事的工作类型。

| 标签 | 说明 |
| --- | --- |
| `x:type/ci` | 处理持续集成相关的工作（例如 GitHub Actions 工作流） |
| `x:type/coding` | 编写不属于面向学生内容的代码。这类工作通常与生产工具（例如测试运行器）、内部工具（生成器），或 Exercism 维护的库有关。 |
| `x:type/content` | 处理内容相关的工作（例如练习、概念） |
| `x:type/docker` | 处理 Dockerfile 相关的工作 |
| `x:type/docs` | 处理文档相关的工作 |

## 已认领与未认领的标签

如果某个任务已经有人在处理，想让它隐藏起来，可以给对应的 issue 加上`x:status/claimed` label。
