# 简介

**调用栈**，或者简称为**栈**，是一种特殊的数据结构，它从内存的最高处开始，向下增长。

## push 和 pop

栈至少支持两种操作，它们有同名的指令：

| 指令 | 执行的操作                                 |
| ----------- | --------------------------------------------------- |
| `push`      | 向栈中添加一个元素                        |
| `pop`       | 移除并返回最近添加的元素 |

这意味着栈是一种**后进先出（LIFO）**的数据结构。

为了跟踪栈的当前位置，也就是最近元素所在的位置，需要使用寄存器`rsp`。

因此，`push`指令接受一个操作数，并将该操作数的内容存入栈中。
由于栈向下增长，`rsp`中的值会减去所存储值的大小。

类似地，`pop`指令接受一个操作数，并将栈中最近的值（即`rsp`指向的那个值）存入该操作数。
然后，`rsp`中的值会增加所取出值的大小。

## 局部变量

也可以直接操作`rsp`的值。
这通常用于为函数创建局部变量。

```x86asm
sub rsp, 24 ; this reserves 24 bytes of space in the stack
add rsp, 24 ; this restores the previous value of rsp, "reducing" the stack by 24 bytes
```

注意，在栈中保留空间时，该空间中存储的值是_未定义_的。

~~~~exercism/note
`pop`和直接操作`rsp`都不会真正移除内存中存储的内容。
栈的“移除”是从`rsp`中的新地址抽象出来的。

在某些情况下，这可能会因为将内部值暴露给外部来源而引发安全问题。
一种处理方法是将函数使用的任何栈空间内容清零。
~~~~

## call 和 ret

栈的主要用途是跟踪被调用函数的返回地址。

正如之前的概念中提到的，有一个名为`rip`的特殊寄存器，它指向下一条要执行的指令。
该寄存器用于控制程序的流程，会被`jmp`和`call`等指令修改。

每当使用`call`指令时，`rip`中的当前值会被隐式压入栈中。
随后，该指令的操作数会被移入`rip`，这样执行就会在被调用的函数中继续。

`ret`指令执行相反的操作。
它从栈中弹出一个值到`rip`，于是执行返回到调用函数。

在入口点，`rsp`指向要返回的地址。
这正是`ret`必须从栈中弹出的地址。

因此，函数内部对`rsp`值的任何改动，无论是直接改动还是通过`push`，都必须在函数返回前还原。

## 被调用者保存寄存器和调用者保存寄存器

除了`rsp`，还有其他一些寄存器必须在函数调用之间保持不变：`rbp`、`rbx`、`r12`、`r13`、`r14`和`r15`。
一般来说，调用函数期望在使用这些寄存器时，被调用的函数不会改动它们。

这意味着_被调用_函数在使用这些寄存器之前必须保存其中的值，并在返回前将它们恢复为原值。
这就是它们被称为**被调用者保存寄存器**的原因。

其他通用寄存器可直接供被调用函数使用。

这意味着_调用者_函数在调用任何函数之前必须保存这些寄存器中的值，以防被调用函数修改它们。
这就是它们被称为**调用者保存寄存器**的原因。

_保存寄存器内容最常见的方式是将其存入栈中。_

## 序言与尾声

在某些情况下，栈可能会被大量使用，在函数返回前会有许多改动。
因此，跟踪所有这些改动以便还原它们可能会很复杂。

在这些情况下，一种常见策略是将`rsp`的地址保存到另一个在函数内保持不变的寄存器中。
然后，在函数返回之前，可以在末尾用一条简单的`mov`指令恢复`rsp`的值。

尽管任何寄存器都可以用于此目的，但通常使用`rbp`作为基址指针。
由于`rbp`本身是被调用者保存寄存器，这通常会先执行`push rbp`。
这个序列通常称为**序言**。

在末尾，通过`mov rsp, rbp`恢复`rsp`，然后也用`pop`从栈中恢复`rbp`。
这个序列通常称为**尾声**。

```x86asm
section .text
fn:
    ; prologue
    push rbp
    mov rbp, rsp
    ...
    ; epilogue
    mov rsp, rbp
    pop rbp
    ret
```

## 使用栈传递参数

在 System V ABI 调用约定中，参数通常通过寄存器传递给函数。
然而，当参数太多，或者它们需要超过一个寄存器大小的空间时，可以使用栈。

在这些情况下，值会以相反的顺序添加到栈中，这样第一个参数就更靠近`rsp`。
由于在入口点，`rsp`指向返回地址，而在 x86-64 中返回地址是一个 8 字节的值，所以栈上的第一个参数（如果有）可以通过`rsp + 8`访问。

## 栈对齐

System V ABI 规定，栈需要在`call`指令执行_之前_立即按 16 字节对齐。
由于`call`会将`rip`压入栈中，因此在入口点，被调用函数的栈**不是** 16 字节对齐的。

这意味着，调用另一个函数（特别是外部函数）的函数在使用`call`之前需要对齐栈。

这可以通过从`rsp`中减去一个合适的值来实现。
在入口点，这个值必须比 16 的倍数多 8：8、24、40 等。
由于`push`指令会减少`rsp`，因此也可以用奇数个`push`来达到同样的效果：

```x86asm
fn_a:
    sub rsp, 24 ; subtracting 8 more than a multiple of 16: this aligns the stack
    call fn_b
    add rsp, 24
    ret

fn_b:
    push rbx    ; odd number of pushes: this aligns the stack
    call fn_c
    pop rbx
    ret
```
