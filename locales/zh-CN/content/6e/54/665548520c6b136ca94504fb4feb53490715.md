# 简介

在许多面向对象的语言中，常见的做法是通过[子类化][wiki-subclass]父类来扩展行为，在继承父类方法的同时添加新的方法。
这样就得到了一个对象层级结构。

Julia _没有类_，因此也就_没有子类_。
那么我们该如何继承并扩展现有的行为呢？

在之前的章节中，我们了解了如何创建类型层级，也学习了 Julia 如何使用[多重分派][concept-multiple-dispatch]根据实参类型来选择方法。

Julia 还有若干非正式接口，它们能让你的自定义类型接入为标准类型已定义好的行为。

用迭代器接口来说明这一点最为容易。

## 迭代器

在之前的课程中，我们已经见过 Julia 对集合中每个元素进行操作的几种方式。

- [循环][concept-loops]，例如 `for item in items...`
- [广播][concept-vector-operations]：`[1, 2, 3] .- 0.5`
- [高阶函数][concept-hof]：`map(√, [1, 4, 9])`
- [推导式][concept-comprehensions]：`[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [生成器][concept-comprehensions]：`(x^2 for x in 1:1e6)`，它是惰性求值的。

显然，Julia 知道如何逐项遍历标准集合：上面例子中的向量和范围，还有 Sets、Dicts 等。

我们该如何把这种能力添加到自己的自定义集合上呢，尤其是当它们能够像生成器一样被惰性迭代时？

### 最低要求

要创建一个可供迭代的序列，我们（至少）需要两样东西：

1. 一种获取_第一个_元素的方法。
2. 一种从当前状态获取_下一个_元素的方法。

Julia 通过 `Base.iterate()` 函数的方法来完成这些任务，步骤如下：

1. 首先会自动调用 `Base.iterate(iter)`。
    - 如果没有可迭代的内容，就返回 `nothing`。
    - 否则，返回第一个元素与第一个状态组成的 `Tuple`：`(firstitem, firststate)`。
2. 如果上一次迭代返回了一个元素，就会自动调用 `Base.iterate(iter, state)`，并以 `firststate` 作为它的 `state` 实参。
    - 如果迭代终止，就返回 `nothing`。
    - 否则，返回下一个元素与下一个状态组成的 `Tuple`：`(nextitem, nextstate)`。
3. 重复第 2 步，直到终止。

这些步骤都在“幕后”完成，也就是说，方法调用和状态由迭代协议在内部管理（状态始终是不透明的），只有元素会暴露给循环等高层结构。
换句话说，我们始终只能看到 `item`，而其他一切都在黑箱之中。

[多重分派][concept-multiple-dispatch]是其中的核心。
`iter` 的类型决定了调用哪些方法，而实参的数量决定了返回的是第一个元素还是下一个元素。

标准类型的方法已经定义好了：`Vector`、`Range`、`Set` 等（[目前][ref-iterations-collections]共有 14 种类型）。

要让自定义的 `MyType` 拥有相同的行为，我们首先需要定义：
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

这些内容在抽象层面听起来可能让人困惑，但实际上可以非常简单。
为了说明，假设我们想要一个类型，它能给出给定整数 `n` 的各次幂，直到某个最大个数。

首先，定义一个自定义类型：

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

现在我们可以为这个类型定义 `iterate` 方法，但是第一个元素和第一个状态是什么呢？

为了得到第一个元素，有些迭代器需要复杂的准备工作，但在这个小例子里，我们可以注意到，返回的第一个元素就是底数，所以我们只需要检查 `count` 的值是否大于或等于 1。

现在我们来看第一个状态，它携带了供下一次迭代使用的信息。
由你来决定为此需要记录哪些信息，它可以是任意类型。

在这个例子中，我们可以只记录要把 `n` 提升到的“指数”，或者，我们也可以用 `n` 最近一次的幂（也就是返回的元素）和序列中的下一个“指数”来找到性能更好的方案。
这两个数字可以装进一个 `Tuple` 并作为 `state` 返回。

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

在这个例子中，第一个元素（`p.n`）被返回给循环，第一个状态 `(p.n, 2)` 则被传给 `iterate(P::Powers, state)` 方法。
在那里，我们可以处理状态，通过把当前元素乘以底数来生成下一个元素，从而把它的幂增加 `1`。

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

如果指数值仍在 `count` 之内，就返回包含 `next` 元素和自增后状态 `Tuple` 的 `Tuple`。
当 `index` 的值超过 `count` 的时候，就改为返回 `nothing`，表示迭代已经终止。

你也许已经注意到，`iterate(p::Powers)` 和 `iterate(p::Powers, state)` 这两个方法的函数体相当相似。
事实上，只要巧妙一点，这种相似性就能让我们用更简洁的方式实现：只使用带两个参数的版本，并为状态设置默认实参：`Base.iterate(p::Powers, state=(1, 1))`
这样一来，我们就不需要单独的单参数版本 `iterate(p::Powers)` 了。
在实际中，只要有可能，人们常常这么做。

到目前为止，我们已经有了些实用的功能：对于 3 的前 4 次幂，我们可以循环遍历结果、检查某个给定数字是否在结果中，以及应用 `sum()` 这样的聚合函数。

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 额外的方法

尽管有了这个好的开始，但并不是所有东西都能用了。

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

果然，`length(Powers(3, 4))` 给出了完全相同的错误信息。

这很容易修复，因为长度是类型构造器的一部分：在这个例子中是 4。
我们只需要为这个类型定义 `Base.length()`，然后就可以对这个序列使用推导式和 `collect()` 了。

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

为了效率，最好再定义 `Base.eltype()`：结果的元素类型。
这让 `collect()` 等函数可以为输出 `Vector{Int}` 预先分配空间，而不是反复对 `Vector{Any}` 执行 `push!()`。

注意这个语法，你可能以前没见过：这个方法定义在_类型_上，而不是类型的_实例_上。

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

迭代器并不_要求_具有有限长度。
“无限”序列的用途比较有限，但只要某种方式能 `break` 跳出循环，对它们进行循环可能就很有用。
例如，我们可以定义 `Powers` 的一个变体，让它生成小于某个限制的值（也许是 `typemax(Int)`，以避免整数溢出）。

## 小结

接口解释起来相当令人困惑，因为 Julia 的做法与大多数其他语言差别太大。
尤其是，接口的名字在实现中可能根本不会被提到：这与[子类化][wiki-subclass]或[混入][wiki-mixins]大不相同。

然而，它们在实践中出奇地简单：

1. 定义一个合适的类型。
2. 弄清楚需要哪些方法。
3. 为你的自定义类型实现这些方法；通常只有少数几个方法，而且相当简短简单。
4. 让[多重分派][concept-multiple-dispatch]自动处理剩下的事情。
