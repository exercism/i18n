# 关于

在 C# 中，可以使用_继承_来定义_类_的层次结构，让派生类（`Car`）继承其父类（`Vehicle`）的行为和数据。如果没有指定父类，该类会继承`object`类。

父类可以通过三种方式向派生类提供功能：

- 定义一个普通方法。
- 定义一个[`virtual`方法][virtual-keyword]，它和普通方法类似，但派生类_可以_修改它。
- 定义一个[`abstract`方法][abstract-keyword]，它没有实现，派生类_必须_实现它。含有`abstract`方法的类也必须标记为[`abstract`][abstract-classes]。抽象类不能被实例化。

[`protected`访问修饰符][protected-keyword]允许在派生类中访问父类的成员，但会阻止其他类访问。因此，派生类可以访问父类的`public`和`protected`成员，但不能访问`private`成员。

派生类可以通过[`base`关键字][base-keyword]访问父类的成员。

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

派生类的构造函数会在执行自身构造函数逻辑_之前_，[自动调用父类的构造函数][constructors]。可以使用[`base`关键字][base-keyword-constructor]把实参传给父类的构造函数。由于抽象类不能被实例化，它们的构造函数可以设为`protected`。

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

当一个基类派生出多个类时，这两个（或更多）子类往往会以不同的方式实现基类的同一个方法。这是一个非常重要的原则，叫做[多态][polymorphism]。例如，在上面的例子的一个变体中，我们展示了使用`Vehicle`的代码如何根据实际实例化的类型改变自身的行为。

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

要阻止一个类被继承，可以加上[`sealed`修饰符][sealed-classes]。有些开发者会尽量避免继承具体类（参见[这个 Stack Overflow 问题][pro-sealed]），而 _sealed_ 修饰符支持这种做法。另一方面，许多 C# 开发者认为它们会妨碍维护，正如[这个问题][anti-sealed]下的一些评论所讨论的那样。建议谨慎使用 sealed 修饰符，直到你对它在自己的需求中的用法有了把握。

下面这篇[文章][new-vs-override]介绍了如何用`new`替代`override`修饰符。它偶尔会派上用场，比如在类层次结构错综复杂，或者库之间出现某种冲突的时候。
