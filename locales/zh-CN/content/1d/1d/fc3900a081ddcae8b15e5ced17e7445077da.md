# 关于

为一个值的传输做好准备，意味着同时要办三件事：把它序列化，从中挑出正确的部分，以及在不需要复制的时候不去复制。Factor 里有三个惯用法正好覆盖这些内容。

## `unparse`：从值到源码

[`unparse`][unparse]（位于 `prettyprint` 中）会返回任意值的源码形式文本。它是解析器的逆操作：把`dup unparse parse`来回跑一趟，就能重建原来的值。

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

对比一下 `>string`（只适用于字符序列）和 `number>string`（只适用于数字）。`unparse` 则是通用的那一个，代价是它生成的是 Factor 语法（带引号的字符串会保留引号）。所以当接收方要把文本解析回去时，它是对的工具；而要做人类可读的输出时，它就不合适了。

## 切片：视图，而非副本

| 单词          | 效果                                            |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`：复制前 n 个                |
| `head-slice`  | `( seq n -- slice )`：前 n 个的视图               |
| `tail`        | `( seq n -- newseq )`：从下标 n 起复制            |
| `tail-slice`  | `( seq n -- slice )`：从下标 n 起的视图           |
| `head*`       | `( seq n -- newseq )`：复制除最后 n 个以外的全部    |
| `head-slice*` | `( seq n -- slice )`：除最后 n 个以外的视图         |
| `tail*`       | `( seq n -- newseq )`：复制最后 n 个               |
| `tail-slice*` | `( seq n -- slice )`：最后 n 个的视图              |

`slice` 是一个元组，里面存着起始下标、结束下标和底层序列。它实现了[序列协议][sequence-protocol]，因此任何序列操作都能用在它上面。当你只是为了读取、不想白白分配内存时，就用带 slice 的那些变体；当你需要在底层序列可能发生变化之后仍然保留数据时，就用会复制的那些。

## 多输入 cleave：`2bi`、`3bi`、`2tri`、`3tri`

普通的 cleave 单词 `bi` 和 `tri` 会把两个或三个 quotation 应用到栈上的*一个*输入上。带 `2` 前缀和带 `3` 前缀的变体，则是把每个 quotation 分别应用到*两个*或*三个*输入上：

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

每个 quotation 都会收到*全部*输入。所以当两个投影都依赖这一对值时，用 `2bi`；如果你想让同一个投影分别作用于每个输入（那是 `bi@`），就不要用它。

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

如果想让*一个* quotation 分别作用于每个输入，就该改用 `bi@`（两个输入）或 `tri@`（三个输入）。同属一个家族，只是形态不同。
