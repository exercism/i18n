# 简介

## 尾调用优化

每次调用函数时，都会在内存中创建一个新的栈帧，用于存储该函数的实参和局部变量；当函数返回时，这个栈帧会被释放。由于 Gleam 使用递归函数调用而不是循环语法，这可能会导致这些栈帧占用大量内存。

为了避免这个问题，Gleam 支持尾调用优化。如果函数执行的最后一个操作是调用函数，编译器就可以复用当前函数的栈帧。这意味着一个函数可以无限次调用自身，而不会使用任何额外内存。

未优化的递归函数通常可以通过使用_累加器_改写成尾调用优化后的函数。

累加器是一个在数据之外额外传递的变量。它用于传递函数执行的当前状态，直到达到基本情况。

累加器应由函数的作者初始化，而不是由函数的用户初始化。为此，声明两个函数：一个公开函数，它只接收必要的数据作为实参，并初始化累加器；以及一个私有函数，它也接收一个累加器。

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
