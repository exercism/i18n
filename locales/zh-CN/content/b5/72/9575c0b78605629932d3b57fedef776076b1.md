# 说明

在这个练习中，你要为一位朋友正在开发的电子游戏编写一些逻辑。
游戏的主角是 Annalyn，一个勇敢的女孩，养着一只凶猛又忠诚的宠物狗。
不幸的是，灾难降临了：她最好的朋友在森林里采摘浆果时被绑架了。
Annalyn 会想办法找到并救出她的朋友，这次冒险她可以选择带上她的狗。

Annalyn 最终找到了关押她朋友的营地，结果发现那里有两个绑匪：一个强大的骑士和一个狡猾的弓箭手。

玩家会看到接下来可以采取的几个选项。
对于四种可能的选项，你需要各编写一个单词，告诉游戏是否应该显示该选项。

## 1. 检查是否应该显示“快速攻击”选项

如果骑士正在睡觉，Annalyn 就能在他完全醒来、穿好盔甲之前，对营地发动一次快速攻击。

实现一个名为`can-do-fast-attack`的单词，它接收一个布尔值，表示骑士是否醒着。
如果“快速攻击”动作可用，它返回`t`，否则返回`f`：

```factor
t can-do-fast-attack .
! => f
```

## 2. 检查是否应该显示“侦察”选项

只要这群人里至少有一个人醒着，就可以对他们进行侦察。否则，侦察就是浪费时间。

实现一个名为`can-spy`的单词，它接收三个布尔值，分别表示骑士、弓箭手和囚犯是否醒着。
如果“侦察”动作可用，它返回`t`，否则返回`f`：

```factor
f t f can-spy .
! => t
```

## 3. 检查是否应该显示“向囚犯发信号”选项

如果囚犯醒着，而弓箭手正在睡觉，就可以用鸟叫声向她发出信号。
如果弓箭手醒着，就没法安全地给她发信号，因为弓箭手也受过用鸟叫声传递信号的专业训练。

实现一个名为`can-signal-prisoner`的单词，它接收两个布尔值，分别表示弓箭手和囚犯是否醒着。
如果“向囚犯发信号”动作可用，它返回`t`，否则返回`f`：

```factor
f t can-signal-prisoner .
! => t
```

## 4. 检查是否应该显示“解救囚犯”选项

Annalyn 可以试着潜入营地救出她的朋友。这件事风险很大，只有以下两条路之一能成功：

- 如果 Annalyn 带着宠物狗，那么在弓箭手睡着时，她就能救出囚犯。
  骑士怕狗，而弓箭手来不及做好准备，Annalyn 和她的朋友就能逃走。

- 如果 Annalyn 没带狗，那她和囚犯就必须非常小心才行！
  如果囚犯醒着，而骑士和弓箭手都在睡觉，Annalyn 就能救出囚犯。
  如果囚犯正在睡觉，就没法救她：她会被突然出现的 Annalyn 吓到，从而惊醒骑士和弓箭手。

实现一个名为`can-free-prisoner`的单词，它接收四个布尔值。
这些形参按顺序分别表示：弓箭手是否醒着、狗是否在场、囚犯是否醒着，以及骑士是否醒着。
如果“解救囚犯”动作可用，它返回`t`，否则返回`f`：

```factor
f t t f can-free-prisoner .
! => t      (archer asleep, dog present, prisoner awake, knight asleep)

t t f f can-free-prisoner .
! => f      (archer is awake, so no rescue possible)
```
