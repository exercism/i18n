# 说明

首映之夜到了，Grand Marquee 的全体员工都在同时忙碌。
人群从每一扇门涌进来，好几个售票窗口卖着同一卷票，首映场快要售罄，而楼上的放映室里，胶片盘必须一刻不停地转下去。

员工共享的每一样东西都存放在一个内存地址上，而测试会从多个线程同时调用你的函数。
在那种负载下，一个值如果读取、修改、写回分成了几步，就会丢失更新，所以每个函数都必须让自己的更新是原子的。

本练习中所有共享的值都是 64 位有符号整数。

你有五个任务。

~~~~exercism/note
本练习中的更新应当用_原子_指令完成。
测试会并发运行你的函数，并检查没有更新丢失，所以非原子的读-改-写很可能会让测试失败。
~~~~

## 1. 统计入场人数

门开了，每一扇门前都有一个引座员在撕票。
每一批被放进来的人都计进同一个入场总人数，而所有门都在同时计数，最终的全场人数仍必须准确无误。

实现`admit_group`函数，它原子地把一个团体的人数加到总人数上。

这个函数按顺序接收以下实参：

- `admissions`：共享入场总人数的内存地址，一个 64 位有符号整数。
- `group_size`：团体中的人数，一个 64 位有符号整数，总是大于`0`。

```c
admissions = 120, group_size = 4
// admissions is now 124
```

测试会同时从好几扇门放人进来。
最终的总人数必须等于所有被放进来的人数之和。

这个函数没有返回值。
总人数应当原地更新。

## 2. 更换胶片盘

放映机上只装一个胶片盘。
装上下一个胶片盘和取下当前这个，必须是一气呵成的动作：如果两位放映员同时操作机器，分成两步就可能把同一个胶片盘交给两个人，或者把其中一个掉在地上。

实现`change_reel`函数，它原子地装上下一个胶片盘，并返回原先装着的那个。

这个函数按顺序接收以下实参：

- `mounted`：已装胶片盘标识符的内存地址，一个 64 位有符号整数。
- `next_reel`：要装上的胶片盘的标识符，一个 64 位有符号整数。

```c
mounted = 7, next_reel = 9
// => 7, and mounted is now 9
```

这个函数返回先前装着的胶片盘的标识符，是一个 64 位有符号整数。
测试会让多个线程同时通过同一个安装点更换胶片盘，并检查每一个交进去的胶片盘都恰好出来一次。

## 3. 卖出一张票

每个窗口卖的票都来自同一个已售票数。
像门那样往一个计数上累加，在这里还不够：每一次售卖还必须知道分给自己的号码。
任何两次售卖都不得共用同一个号码，而且在抢票高峰过后，这个计数必须恰好等于卖出的票数。

实现`sell_ticket`函数，它原子地把计数加一，并返回刚刚卖出的票号。
票号是这次售卖_之后_的计数：当计数是`41`时，这次售卖的就是`42`号票。

这个函数接收一个实参：

- `tickets_sold`：共享已售票数的内存地址，一个 64 位有符号整数。

```c
tickets_sold = 0
// => 1, and tickets_sold is now 1

tickets_sold = 41
// => 42, and tickets_sold is now 42
```

这个函数返回票号，是一个 64 位有符号整数。
测试会同时从好几个窗口售票：每一个返回的号码都必须互不相同，最终计数必须等于售卖的次数。

## 4. 坐满首映场

首映场有固定数量的座位，每个窗口都在卖。
只有当还有座位时才允许售票，而且放映绝不能超卖，即使在所有窗口都同时抢最后一个座位的瞬间也不行。
把检查计数和往计数上加当成两步，中间就会留出空隙，所以检查和更新必须一起成功或一起失败。

实现`claim_seat`函数，它原子地在还有空位时占下一个座位。
占到一个座位时，函数返回座位号，也就是这次占座之后已占座位的计数。
放映已经售罄时，它返回`0`，并且计数保持不变。

这个函数按顺序接收以下实参：

- `seats_taken`：已占座位计数的内存地址，一个 64 位有符号整数，永远不会超过`capacity`。
- `capacity`：放映的座位数，一个 64 位有符号整数，总是大于`0`。

```c
seats_taken = 0, capacity = 150
// => 1, and seats_taken is now 1

seats_taken = 82, capacity = 150
// => 83, and seats_taken is now 83

seats_taken = 149, capacity = 150
// => 150, and seats_taken is now 150

seats_taken = 150, capacity = 150
// => 0, and seats_taken stays 150
```

这个函数返回座位号，或在放映售罄时返回`0`，都是 64 位有符号整数。

## 5. 看守放映室

放映室里只容得下一个人。
内存里有一个字表示它是否有人占用：`0`表示空闲，`1`表示占用。
整晚都有员工过来，每个人都在里面有一项要做的事：在日志本上签名、给放映机穿胶片、归档一个胶片盘。
不管是什么任务，放映室的规矩都一样，而执行这条规矩就是你的职责：同一时间只能有一个人在里面，从他任务开始到任务结束。

实现`visit_booth`函数，它会：

1. 等到放映室空闲；
2. 占用放映室；
3. 运行来访者的任务；
4. 在任务之后、返回之前重新开放放映室。

当放映室被别人占着时，它应当用`pause`礼貌地等待。

这个函数按顺序接收以下实参：

- `booth`：占用标志字的内存地址，一个 64 位有符号整数，取值为`0`或`1`。
- `task`：来访者的任务，一个不接收形参、没有返回值的函数。

注意，测试运行的任务会查看放映室，也会查看一个共享的日志本。
这意味着放映室在整个任务期间必须一直处于被占用状态，每次来访都必须恰好运行一次它的任务，而且在多个来访者同时进行时，日志本必须准确无误。

~~~~exercism/caution
来访者的任务是一个遵循调用约定的普通函数：

- 它可以覆盖任何调用者保存的寄存器，所以任务结束之后你仍然需要的东西，应当放在调用碰不到的地方；
- 它还要求调用发生的那一刻栈是 16 字节对齐的。

违反其中任何一条，都可能表现为崩溃，而不是一次失败的检查。
~~~~
