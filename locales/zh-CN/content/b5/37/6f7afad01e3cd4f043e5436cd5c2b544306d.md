# 关于

Julia 和大多数编程语言一样，提供了丰富多样的集合类型。

有些集合本身就是有序的（包括 `Vectors` 和高维 `Arrays`），因此我们可以按位置访问元素。另一些集合则是无序的（`Sets`、`Dicts`），必须按键或值来访问元素。

最简单的情况是，假设我们有一个由 `Ints` 组成的 `Vector`，想把它按升序[排序][ref-sorting]。

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

很简单！
[`sort()`][ref-sort] 函数的命名一目了然，看上去返回的就是排序后的 `Vector`。

_开个玩笑！_
学到教学大纲的这个阶段，你也许已经（正确地）猜到，有些细节需要我们讨论一下。

## 修改与不修改输入的函数

运行 `sort(v)` 之后，`v` 是什么？

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

原来的向量没有变化。
`sort()` 是一个***不修改输入***的函数，它返回输入的_副本_。

在很多场合，这是很好的设计：我们得到一个[纯函数][wiki-pure-func]，它的行为很容易推断，即使在并行、分布式的代码中也是如此。

另一方面，假设我们有一个包含 10 亿个字符串的数组，想要对它排序。

排序本身可能就很慢（后面会详细讲）。
此外，我们还要复制全部内容（_很慢！_），并分配足够的内存（_好几 GB！_）来存放这份副本。

对比一下这段很相似的代码：

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

现在输入 `Vector` 被就地排序，没有复制，原来的顺序也永久丢失了。

这样做可能很高效，也可能引入 bug，导致意想不到的[副作用][wiki-side-effect]，还可能会让使用你代码的人感到困惑。
_请谨慎选择！_

[`sort!()`][ref-sort!] 是一个[会修改输入的函数][ref-mutating-func]，按照（_非常强烈的_）约定，任何会修改输入的函数都会在名字末尾加上 `!`，用来提醒程序员。

## 按什么排序？

给 `Int64` 值排序相对简单：连小孩都明白 2 比 1 大、比 3 小。

其他类型可能更复杂，但一般来说，如果 `isless(x, y) == true`，就有 `x < y`。
Julia 为大多数标准类型提供了 `isless()` 的实现，你也可以定义对应的[方法][concept-multiple-dispatch]，用来比较你的[自定义类型][concept-composite-types]。

例如，Unicode 字符（对欧洲字母来说，大写字母排在小写字母前面）：

```julia-repl
julia> j = collect("Julia")
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)

julia> sort(j)
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0false069 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
```

我们还可以在排序前对元素应用任意函数，比如用 [`abs`][ref-abs] 忽略正负号，或者用 [`uppercase`][ref-uppercase] 做不区分大小写的排序：

```julia-repl
julia> nums = [3, -2, -4, 1]
4-element Vector{Int64}:
  3
 -2
 -4
  1

julia> sort(nums)
4-element Vector{Int64}:
 -4
 -2
  1
  3

julia> sort(nums, by=abs)
4-element Vector{Int64}:
  1
 -2
  3
 -4

# j is from "Julia", as previously

julia> sort(j, by=uppercase)
5-element Vector{Char}:
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)

julia> vecs = [[1, 3], [4, 2], [3, 4], [2, 1]];

julia> sort(vecs)  # by default sorts by the first element of the (2-element) vectors
4-element Vector{Vector{Int64}}:
 [1, 3]
 [2, 1]
 [3, 4]
 [4, 2]

julia> sort(vecs, by=last)
4-element Vector{Vector{Int64}}:
 [2, 1]
 [4, 2]
 [1, 3]
 [3, 4]
```

对于[多维数组][concept-mda]，我们可以指定 `dims` 关键字来控制排序的方向。

```julia-repl
# create a matrix of integers in random order
julia> A = reshape(Random.shuffle(1:9), (3, 3))
3×3 Matrix{Int64}:
 8  4  9
 6  7  5
 2  1  3

julia> sort(A, dims=1)  # sort rows
3×3 Matrix{Int64}:
 2  1  3
 6  4  5
 8  7  9

julia> sort(A, dims=2)  # sort columns
3×3 Matrix{Int64}:
 4  8  9
 5  6  7
 1  2  3
```

## 排序下标数组

如果要排序的元素是很大的对象，直接处理它们的位置下标可能更方便。

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

因为 `langs` 是一个 Vector，所以每个下标都是[范围][concept-range] `1:length(langs)` 内的一个整数。
对 Vector 调用 [sortperm()][ref-sortperm] 得到的输出，是这些整数的一个[排列][wiki-permutation]，它对应着对输入 Vector 的一次排序。

## 部分排序

你的程序需要把整个输入都排好序吗？
如果只有前几个或后几个条目才是你关心的，做一次[部分排序][wiki-partial-sort]会明显快得多。

Julia 提供了 [`partialsort()`][ref-partialsort] 和 [`partialsort!()`][ref-partialsort!] 函数，它们保证指定的那个条目或那段条目范围是正确的，但对输入的其余部分不作任何保证。

第二个实参可以是一个整数，也可以是一个范围，表示排序后输入中的下标：

```julia-repl
julia> vsq = [9, 4, 16, 1];  # would be [1, 4, 9, 16] after a full sort

julia> partialsort(vsq, 4)
16

julia> partialsort(vsq, 2:3)
2-element view(::Vector{Int64}, 2:3) with eltype Int64:
 4
 9
```

## 排序算法

给 `[3, 2, 4, 1]` 排序，无论对人还是对计算机来说都不难。

如果输入_大得多_，最好的排序方式又是什么呢？

这就逼着我们去定义什么叫“最好”！

- 平均耗时最短？
- 最好情况还是最坏情况的耗时最短？还是一个折中的界限，比如第 90 百分位的耗时？
- 内存占用最少？
- 做一个近似排序或部分排序，对当前应用来说“足够好”就行？

另外，输入是什么样的？
它可能基本是随机的，但也有一些特殊情况，比如数组已经排好序、按逆序排列，或者含有大量重复的条目。
在这些情况下，不同算法的表现会相差很大。

设计更新、更好的排序算法，既在智力上令人着迷（_对某类性格的人来说_），又有商业价值：_这是强有力的组合！_

因此，这个主题上有大量文献，而且仍在稳步增长。

大多数情况下，Julia 会尝试选择一个合理的默认算法，不过程序员在必要时可以[指定自己的偏好][ref-algorithms]。

下面这个玩具示例有点离谱，但能说明语法：

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v, alg=InsertionSort)
4-element Vector{Int64}:
 1
 2
 3
 4
```
