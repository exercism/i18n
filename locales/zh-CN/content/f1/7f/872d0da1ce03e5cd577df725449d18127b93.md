# 补充说明

JavaScript 天生就是单线程的，因此缺少其他语言为处理并行代码执行而具备的许多语言特性。
事实上，想要实现“真正的”并行代码执行，唯一的途径就是使用 `Worker threads`（也叫 `Web Workers`）。

大多数时候，看起来像是在并行执行的代码，比如`async functions`或`Promises`，实际上都是并发执行的。
这通常更好，因为现代 JavaScript 正是为这种用法做了优化。你也经常会看到一些代码借助`Promise.all()`以及其他并发执行的方法来“模拟”（或者说“取巧”实现）并行执行。

## 并发与并行

下面用简短的定义来说明两者的区别：

- 并发：两个或多个任务可以在相互重叠的时间段内启动、运行和完成，由同一个处理单元执行。
- 并行：两个或多个任务可以同时启动和运行，由不同的处理单元各自独立执行。

为了完整起见，这里再给出同步执行的定义：

- 同步执行：一个任务必须等待另一个正在运行的任务完成后，才能开始运行。

## JavaScript 中的并行

虽然 JavaScript 默认是单线程的，但仍然有办法以并行的方式执行代码。

如果你是在浏览器中运行 JavaScript（例如在 Web 应用里），那么实现并行的方式就是使用 [Web Worker API][mdn-demo]。
正如 MDN 所说：

> Web Workers 让脚本操作可以在后台线程中运行，与应用程序的主执行线程分离。

另一方面，如果你的 JavaScript 运行在 Node.js 中（Node.js 也是 Exercism 的目标运行时），同一个概念叫做 [Worker threads][node]。

下面是一个 `Web Worker API` 的简单示例（摘自 [Medium][medium-demo]）

```js
// main.js
const myWorker = new Worker('worker.js');

myWorker.postMessage(5);

myWorker.onmessage = function (event) {
  console.log('Received result from worker:', event.data);
};
```

```js
// worker.js
onmessage = function (event) {
  console.log('Received number from main thread:', event.data);

  // Perform computation
  const result = event.data * 2;

  // Send result back to the main thread
  postMessage(result);
};
```

下面是 `Worker threads API` 的示例（摘自[文档][node]）

```js
const {
  Worker,
  isMainThread,
  parentPort,
  workerData,
} = require('node:worker_threads');

if (isMainThread) {
  module.exports = function parseJSAsync(script) {
    return new Promise((resolve, reject) => {
      const worker = new Worker(__filename, {
        workerData: script,
      });
      worker.on('message', resolve);
      worker.on('error', reject);
      worker.on('exit', (code) => {
        if (code !== 0)
          reject(new Error(`Worker stopped with exit code ${code}`));
      });
    });
  };
} else {
  const { parse } = require('some-js-parsing-library');
  const script = workerData;
  parentPort.postMessage(parse(script));
}
```
