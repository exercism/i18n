```exercism/note
抛开这个搞笑的故事不谈，本练习的需求直接取自 GitHub REST API 中关于拉取请求评审评论的端点。
```

## 1. 请给我 ID！

你的火眼金睛已经发现，评论和用户都有一个`id`字段，这正是绝佳的起点。

定义`decodeId`，让它能解码一个带有整数`id`的 JSON 对象。

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. 我叫什么名字来着？

你注意到，在上面的示例里，并不是所有用户都有名字。

定义`decodeName`，让它能在`name`字段存在时解码其中的字符串。
没有名字？没关系，直接返回`Nothing`。
这个解码器永远不应该失败。

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. 用户？我跟他不熟！

解码用户这件事我们已经完成一大半了，把它做完吧。

定义`decodeUser`，让它能解码一个 JSON 用户对象。
记得在`decodeUser`里用上`decodeId`和`decodeName`。

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. 我是一条坚强独立的评论

拉取请求评审中的有些评论是独立存在的，因此没有`pull_request_review_id`。
不过，规范里提到，这种情况下仍然应该有`pull_request_review_id`字段，只是值应该为`null`，也就是穷人版的`Nothing`。

定义`decodePullRequestReviewId`，让它能在`pull_request_review_id`字段里有整数时解码这个整数。
如果没有整数，就应该有`null`；如果连`null`都没有，解码器就应该失败。

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. 副业

接下来是这个看起来很有意思的`side`字段。
在拉取请求评审里，你可以对删掉的代码（屏幕的`Left`侧）发表评论，也可以对新增的代码（屏幕的`Right`侧）发表评论。

定义`decodeSide`，让它能解码`side`字段中的`"LEFT"`或`"RIGHT"`，并把它对应到相应的类型变体上。

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. 链接的觉醒

每条评论都有一组链接，而且这些链接在不同评论之间似乎并不一致。

定义`decodeLinks`，让它能解码`_links`字段中的一组 URL。
链接的名字和数量都可能变化，要确保你能把它们都考虑进去。
链接本身是 JSON 对象，并且始终应该有`href`字段。

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. 应声评论

就快到了，把它做完吧。

定义`decodeComment`和`decodeComments`，让它们分别能解码单个 JSON 评论对象或一组评论。
记得在`decodeComment`里用上前面定义的所有函数，`decodeName`除外。
当然，`decodeComments`也应该用上`decodeComment`。

## 8. 全部串联起来

这一切里还差一个功能：能把新评论发送到服务器。
为此，你需要做出解码器的反面，也就是能把 Elm 的`Comment`转换成 JSON 的`Value`。

定义`encodeComment`，让它能编码任何合法的`Comment`。
字段的顺序无所谓，只要编码器生成的值能被`decodeComment`解码就行。
