# 简介

## SIMD：按位运算

大多数标量按位运算都有对应的打包变体。它们遵循与 SIMD 整数运算相同的一般语法，但没有大小后缀：

| 指令    | 说明                   |
|---------|------------------------|
| `pand`  | 两个 128 位值的按位与  |
| `por`   | 两个 128 位值的按位或  |
| `pxor`  | 两个 128 位值的按位异或 |

注意，并不存在打包的 `NOT`。
不过，有一个 ANDN 运算，它对**目标**操作数取反（翻转其所有位），然后计算两个操作数之间的与。
可以把它看作按位非运算和按位与运算的组合：

| 指令    | 说明                                           |
|---------|------------------------------------------------|
| `pandn` | 将**取反后**的目标操作数与源操作数做按位与      |

注意，按位运算组合的是两个不同操作数中同一位置上的位，所以通道边界不会改变结果。
这就是这些指令没有大小后缀的原因：寄存器在这里表现为一个 128 位的通道：

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
本概念中的所有指令都只计算位，不设置任何标志位。
后面的概念会介绍如何处理打包值上的条件判断。
~~~~

### 按通道移位

与纯粹的按位运算不同，移位确实会让位跨越位置移动，因此需要通道大小来设定边界。
在每个通道内部，它们的行为与对应的标量指令相同，位也绝不会从一个通道越到相邻通道：

| 指令                      | 说明             |
|---------------------------|------------------|
| `psllw`、`pslld`、`psllq` | 按通道逻辑左移   |
| `psrlw`、`psrld`、`psrlq` | 按通道逻辑右移   |
| `psraw`、`psrad`          | 按通道算术右移   |

注意，这些指令遵循打包整数运算的语法，包括大小后缀。
没有以字节为通道的移位，只有 word、dword，以及 qword（算术右移除外）。

打包移位与对应的标量指令有一个区别在于运算的名称：

- 不再是 `shl` 和 `shr`，而是 `sll` 和 `srl`，分别对应 **s**hift **l**eft **l**ogical 和 **s**hift **r**ight **l**ogical。
- 不再是 `sar`，而是 `sra`，即 **s**hift **r**ight **a**rithmetic。

名称虽然不同，运算本身却是一样的：

- 逻辑右移用 0 填充最高位。
  它等价于对 2 的幂做无符号除法。
- 算术右移用符号位的值填充最高位。
  它等价于对 2 的幂做有符号除法，并向负无穷方向取整。
- 左移始终用 0 填充（这就是不需要算术左移的原因）。

移位次数对每个通道都相同。
它可以是一个立即数，也可以是 `xmm` 寄存器的低 64 位：

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
移位次数大于通道宽度时，不会像标量 `shl`/`shr` 那样回绕。
它只会产生 0（对算术右移而言则是全为符号位）。
~~~~

### 浮点数按位运算

每个按位指令还都有一个浮点版本的孪生指令，遵循我们在打包浮点运算中已经见过的相同语法：

| 整数名称 | 浮点数名称           |
|--------------|----------------------|
| `pand`       | `andps`, `andpd`     |
| `pandn`      | `andnps`, `andnpd`   |
| `por`        | `orps`, `orpd`       |
| `pxor`       | `xorps`, `xorpd`     |

由于按位运算作用于位，实际上整数运算和浮点运算会算出相同的结果。
名称不同有两个原因：

1. 记录意图，就像我们会根据所复制字节的性质，更倾向于选用 `movdqa`、`movaps` 或 `movapd` 一样。
2. 整数运算和浮点运算往往有不同的执行域。
   同一个执行域内的运算通常能更快地依次执行。

浮点数没有对应的移位运算。

### 浮点数的位表示

IEEE 浮点数与整数的位表示截然不同。

在无符号整数中，每一位的含义都统一：它表示与位下标对应的一个 2 的幂。
这个整数就是所有被置位的位所对应的 2 的幂之和。
这也是为什么移位可以把数字乘以或除以 2 的幂：我们只是在改变每个被置位的位的下标。

在有符号整数中，大多数位的解释方式与无符号整数相同。
但最高位很特殊。
如果它被置位，我们不是把它加到其他位上，而是要减去对应的 2 的幂，结果就是一个负数。
实际上，要改变一个数的符号，从概念上需要两步：翻转所有位（一个 `not`），然后给结果加 1（一个 `inc`）。

浮点数中的位没有统一的含义，需要根据它们的位置用截然不同的方式来解释：

| 字段   | 下标（32 位） | 下标（64 位） |
|--------|---------------|---------------|
| 符号位 | 31            | 63            |
| 指数   | 30-23         | 62-52         |
| 尾数   | 22-0          | 51-0          |

最终得到的数按 `(-1)^sign * 1.fraction * 2^(exponent - bias)` 计算。
偏置值取决于精度：

| 大小   | 偏置 |
|--------|------|
| 32 位  | 127  |
| 64 位  | 1023 |

在这两种格式中，数的符号完全由符号位决定。
改变浮点数的符号只需翻转这一位（一次异或运算）。
取绝对值只需清除这一位（一次把该位清零的与运算）：

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

注意，在这种位表示中，移位并不会产生可预测且统一的结果。
尾数可能会“溢出”到指数中，指数也可能会“溢出”到符号位中。

不过，有时把表示中的不同部分单独取出来进行操作会很方便。

例如，指数中的位应当先按无符号数来解释，然后再减去偏置。
这意味着我们可以构造一个 32 位或 64 位整数，其底层的位表示正好对应某个 2 的幂在相应浮点格式下的样子。
之后就可以用这个原始的位表示来乘以或除以另一个浮点数。

例如：

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

反过来，我们可以通过与一个掩码做与运算，来提取打包浮点数的指数：该掩码把指数字段的位置位，其余位清零。
再配合一次移位和一次减法，就能得到每个通道未经偏置的指数，并以有符号整数表示：

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
对浮点数的原始位进行操作，虽然在某些情况下很有用，但应当谨慎。
只有在不发生上溢或下溢、且输入数为规格化数时，对指数字段做加法或减法才是安全的。
另外，把合法的 `x` 加到 `0.0` 的指数字段上，得到的是 `2^(x - bias)`，而不是 `0.0 * 2^x`。
~~~~
