# 简介

你已经在`channel-chatter`里*用过*流，也在`boatswains-bilge`里把它们释放掉了。这个练习是你第一次自己写自定义流：一个实现了[协议][stream-protocol]的类，这样，原本在`<string-reader>`上能用的`with-input-stream` / `read1` / `stream-read1`代码，也能用在你的类上。

## 混入：类层次结构的另一半

你已经在`dragons-descendants`里认识了`TUPLE: child < parent …`，那是一种单父级层次结构，槽位自上而下流动。Factor 还有*第二种*扩展类图的方式：**开放式混入**。`MIXIN: m`声明了一个没有槽位的类，其他类可以在事后通过`INSTANCE: c m`加入它。这种成员关系是多对多的：一个类可以同时是任意多个混入的实例。

流协议用两个混入来标记一个类实现的是接口的哪一半：

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

一个流可以是其中一种、另一种，或者两者都是。于是，`input-stream`（或`output-stream`）上的泛型方法会分派给任何加入了该混入的类，环境中的`read1`、`stream-contents`、`with-input-stream`等，就是这样找到你的类的。

混入是*开放的*：即使混入已经声明，你仍然可以添加新成员，甚至可以来自不同的词汇。这与`TUPLE: < parent`形成对比：在后者中，关系在声明子类时就已经固定。

## 协议泛型

协议泛型都放在`io`里：

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

`stream-read1`返回下一个字节（或流末尾的`f`）；`stream-write1`写入一个字节。`stream-read-unsafe`是大多数输入流提供的更底层的批量读取；`stream-read`构建在它之上，负责内存分配。`stream-element-type`用来表明这个流处理的是字节（`+byte+`）还是字符（`+character+`）；当你包装另一个流时，最简单的实现就是直接委托给底层的流。

## 清理来自`destructors`

流是可释放对象：自定义的流继承`disposable`并实现`dispose*`。这就是`boatswains-bilge`里的那套框架，只不过应用到了流类上：

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

一旦写好这些，`channel-chatter`里所有的`with-…`组合子就能自动作用于你的流。
