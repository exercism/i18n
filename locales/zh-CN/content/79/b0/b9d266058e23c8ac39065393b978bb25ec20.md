# 关于

动态内存由库函数实现，程序员用这些函数在运行时分配和释放内存。
由于内存的分配和释放都由程序员控制，动态内存的安全与否，完全取决于程序员能否避免人为失误。
正因如此，动态内存是编程 bug 的主要来源之一，也是黑客攻击的主要目标。

动态内存用于大小只有在运行时才能确定的变量。
当数组的元素个数在每次运行时都可能不同时，动态内存尤其有用。
变长数组（VLA）是另一种处理元素大小只在运行时才确定的数组的方式。
VLA 使用自动存储，也就是说离开定义它的代码块时，它的内存就会被销毁。
（关于存储的更多内容，请参见[存储类说明符](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers)概念。）
变长数组由 C99 引入 C 语言，但从 C11 起变长数组成了可选项，因此支持 C11 及之后标准的编译器不必支持变长数组。
对变长数组的详细分析超出了本文的范围。

## malloc

`malloc`是声明在`stdlib.h`中的函数，用于分配动态内存。
如果分配成功，会返回一个指针，指向所分配内存第一个字节的地址。
如果分配失败，则返回`NULL`。
稳妥的做法是检查`malloc`的返回值是否为`NULL`，并在失败时妥善处理。
返回的指针类型是`pointer-to-void`，大致可以把它看作一个“通用”指针，可以转换成该内存实际使用的具体类型。
`malloc`只有一个形参，即所需内存的字节大小。
为数组分配内存时，总大小等于每个元素的数据类型大小乘以元素个数。
通常用`sizeof`运算符来获取每个元素数据类型的大小。
下面的例子演示了这一点

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

要记住，`malloc`新分配的内存不会被初始化，其中可能残留垃圾值。
注意，`numbers`指针的`sizeof`既不是数组的元素个数，也不是所分配内存的总量。
`malloc`返回的指针的大小，就是该系统中任意指针的大小。
示例代码运行在 64 位系统上，因此指针的大小是 8 字节（每字节 8 位，8 × 8 = 64 位）。
指针类型从 pointer-to-void 隐式转换成了 pointer-to-int。
pointer-to-int 指向的是单个`int`还是一个`ints`数组，由程序员根据需要自行处理。
例如

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

如果这些值在被读取之前一定会先被写入，那么用`malloc`分配内存是一种高效的方式。
但如果这些值有可能在被初始化之前就被读取，那么用`malloc`就有风险。
更安全的做法是用`calloc`分配内存，它会把新分配的内存初始化为零。

注意上面的例子中使用了`free(numbers)`。

## free

`free`是声明在`stdlib.h`中的函数，用于释放已动态分配的内存。
动态分配的内存在被`free`释放之前，会一直被系统占用。
有些操作系统会在程序结束时自动释放动态分配的内存，但最好的做法是不要依赖这一点。
`free`只有一个形参，即指向动态分配内存的指针。
是否使用`free`，与好几类内存问题有关。

#### 内存泄漏

当指向动态分配内存的引用到达其生命周期的终点，或者以其他方式被销毁之后，却没有释放这块内存，这就称为内存泄漏。
泄漏的内存是被系统占用、但程序再也无法访问的内存。
如果在循环中分配内存，循环结束时没有释放，下一次循环开始时又再次分配，问题就会特别严重。
如果分配的内存足够多却始终不释放，那么再次调用分配内存时会因为剩余内存不足而失败。
要记住，虽然动态分配的内存在被释放之前一直由系统占用，但保存它的指针可能只有块作用域。
例如，在`malloc`的示例中，内存是在`my_function`里分配的。
如果指向它的指针没有被返回并用来给`main`中的`numbers`指针赋值，那块内存就会泄漏。
因此，把这个`numbers`指针传给`free`，就能释放`my_function`中分配的内存。

#### 释放后使用（**UAF**）

如果内存被释放后又被访问，里面的值可能是任何东西。
在下面的例子中，`numbers`所指向的内存先被释放，随后又在`printf`中被读取。

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

`numbers`指针在释放之后被称为悬空指针。
悬空指针可能指向原本并不打算指向的其他内存。
因此，悬空指针可能导致数据损坏，以及任意代码替换和执行。
如果指向已分配内存的指针没有通过设为`NULL`来清除，就可能被用来入侵程序。
在上面的例子中，如果在释放之后像这样把`numbers`设为`NULL`：`numbers = NULL;`，那么接下来的`printf`会导致程序终止，在尝试读取`numbers[0]`时可能会报段错误。

#### 重复释放

对指向动态分配内存的指针调用两次`free`，会导致未定义行为（**UB**）。
也就是说，编译器可以随意以任何方式处理它。
下面的例子用两个不同的编译器编译，可能得到两种不同的结果

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

如果在每次调用`free`之间把`numbers`设为`NULL`，第一个和第二个编译器都没有产生运行时错误，但对第三个编译器来说，这并不保证可行。
重复释放的一个常见来源，是有两个指针指向同一块动态分配的内存。
一个指针可能在程序的某处指向数组的开头，另一个指针可能在程序的另一处被用来遍历这个数组。
在程序的不同位置，两个指针分别被释放，于是就造成了重复释放。

## calloc

`calloc`是声明在`stdlib.h`中的函数，既用于分配动态内存，也用于把新分配的内存初始化为零。
如果分配成功，会返回一个指针，指向所分配内存第一个字节的地址。
如果分配失败，则返回`NULL`。
稳妥的做法是检查`calloc`的返回值是否为`NULL`，并在失败时妥善处理。
返回的指针类型是`pointer-to-void`，大致可以看作一个“通用”指针，可以转换成该内存实际使用的具体类型。
`calloc`有两个形参。
第一个形参是要分配多少个指定数据类型的元素。
第二个形参是要分配的指定数据类型的大小。

在下面的例子中，所有`printf`语句都应该始终输出`0`，因为`calloc`保证会把新分配的值清零。

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc`是声明在`stdlib.h`中的函数，用于扩大或缩小已分配的内存。
如果重新分配成功，会返回一个指针，指向重新分配后内存第一个字节的地址。
如果重新分配失败，则返回`NULL`。
稳妥的做法是检查`realloc`的返回值是否为`NULL`，并在失败时妥善处理。
`realloc`有两个形参。
第一个形参是指向要重新分配的现有内存的指针。
第二个形参是重新分配后内存的字节大小。
在内存扩大之前已经设置的值会保留下来。
要记住，扩大内存时新增的内存不会初始化为零，其中的值可能是任何东西。
另外，缩小内存时被移除的内存同样不会被初始化，可能保留原来的值。
下面的例子演示了数组的扩大和缩小

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## 传入的大小为 0 时

如果传给`malloc`、`calloc`或`relloac`的大小是`0`，那么会发生什么取决于编译器如何实现。
编译器可能返回一个`NULL`指针，也可能返回一个非空指针。
例如，在为指向`char`的指针分配内存时，编译器可能返回`NULL`，也可能返回一个指向空字符串的非空指针。
为了避免不同编译器给出不同结果，最好不要用 0 作为大小去分配内存。
