# 简介

在程序中定义自定义类型通常很有用。

可以创建新的基本类型，但很少这么做。
内置基本类型并非随意选择：它们与 Julia 用于 JIT 编译的 LLVM 编译器中的标准类型紧密对应。

更有用的是，可以定义带命名字段的复合类型。

其他语言也有类似的东西，称之为`structs`或`records`。
Julia 文档称它们为`composite types`，不过（略有出入）语言语法通过`struct`关键字来定义它们。

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

上面的例子有几点值得注意：

- 没有为`id`指定类型，因此编译器将其解释为`id::Any`。
  - 实践中，最好通过为字段指定具体类型来帮助编译器
- 类型名被用作构造函数，例如`Person(id, name, age)`，用于创建类型为`Person`的实例。
- 各个字段可以用点表示法访问，与命名元组相同。

类型为`Person`的项是不可变的，因此不允许更新。

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

如果需要可变性，在定义中添加`mutable`。

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

默认情况下，构造函数要求字段按定义中的顺序出现，这对更复杂的类型来说会变得不方便。

使用`@kwdef`宏可以实现两个新功能：

- 构造函数使用关键字，而不是位置。
- 字段可以有默认值，并且可以选择从构造函数中省略。

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## 复合类型层级

到目前为止，我们只创建了具体的复合类型。
如果检查一下，它们都是`Any`的子类型。

当创建多个相关类型时，为它们定义层级可能更合理。
这很容易做到。

首先，创建一个抽象类型：

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

接下来，在类型定义中包含一个`<:`运算符，以表示这种关系。

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

按需重复，记住不允许对具体类型进行子类型化。

对于更复杂的层级，根据需要创建抽象子类型。

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

当我们学到`Multiple Dispatch`概念，并看到函数如何处理实参类型时，这种层级的价值会更加清晰。
