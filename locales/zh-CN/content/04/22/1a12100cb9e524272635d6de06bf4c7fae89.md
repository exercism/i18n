# 说明

你是一艘近海货轮上的水手长。舱底是船体最底层的隔舱，用来收集废水，每个班次都要把舱底设备打开、运行，再收好。无论抽水过程中发生什么，设备*必须*回到收好的状态。

测试会提供`<test-pump>`，用来获取新的泵。每个泵都有一个`opened>>`槽，打开时读出`t`，被释放后读出`f`。

## 1. 排空舱底

定义`drain-bilge`，释放单个泵。对同一个泵调用两次`drain-bilge`也不会有问题，框架会替你处理。

```factor
<test-pump> dup drain-bilge opened>> .   ! => f
```

## 2. 抽水流程

定义`pump-out`：接受一个泵和一个 quotation，把泵压入栈供 quotation 使用，然后在之后释放这个泵，*即使 quotation 抛出异常也不例外*。

```factor
<test-pump> [ drop ] pump-out   ! pump released
```

## 3. 整个班次的流程

定义`shift-routine`：接受两个泵和一个 quotation。打开一个析构作用域，把*两个*泵都注册为无条件释放，然后调用 quotation。无论 quotation 正常结束还是抛出异常，两个泵最终都会被释放。

quotation 会从栈上接收这两个泵作为输入。

```factor
<test-pump> <test-pump> [ 2drop ] shift-routine
! both pumps released
```

## 4. 有风险的抽水

有时泵是借来的，只有在出问题时才想丢弃它，否则下一班的人还需要它保持打开。定义`risky-pump-out`：接受一个泵和一个 quotation，把泵注册为**仅在失败时**释放，然后在栈上有这个泵的情况下调用 quotation。

如果 quotation 正常执行完成，泵会保持打开。如果 quotation 抛出异常，泵会被释放，异常也会继续向外传播。

```factor
<test-pump> [ drop ] risky-pump-out                ! stays open
<test-pump> [ drop "boom" throw ] risky-pump-out   ! pump released, throws
```

## 5. 自定义的 disposable：阀门

最后用一个全新的 disposable 把工具箱补齐：一个`valve`。这个元组已经为你声明好了：

```factor
TUPLE: valve < disposable is-open ;
```

- 定义`<valve> ( -- valve )`，通过`new-disposable`构造一个新的阀门，并把`is-open`设为`t`。
- 实现`M: valve dispose*`，把`is-open`翻转为`f`。

```factor
<valve> is-open>> .                ! => t
<valve> dup dispose is-open>> .    ! => f
```
