# 简介

## 错误接口

在 Go 中，错误处理**不是**通过异常来完成的。
相反，错误是普通_值_，它们的类型实现了内置的`error`接口。
`error`接口非常精简。
它只包含一个方法`Error()`，该方法以字符串的形式返回错误信息。

```go
type error interface {
  Error() string
}
```

每当你定义的函数在执行过程中可能发生需要传递给调用方的错误时，都需要把`error`列为返回类型之一。
如果函数有多个返回值，按照惯例，`error`总是最后一个。

```go
func DoSomething() (int, error) {
  // ...
}
```

## 创建并返回一个简单的错误

你不必总是自己去实现错误接口。
要创建一个简单的错误，可以使用标准库包`errors`中的`errors.New()`函数。
你唯一需要传入的是字符串形式的错误信息，`errors.New()`会负责创建一个包含你的信息并实现`error`接口的值。

如果函数返回错误，最好为所有其他返回值都返回零值：

```go
func DoSomething() (SomeStruct, int, error) {
  // ...
  return SomeStruct{}, 0, errors.New("failed to calculate result")
}
```

~~~~exercism/caution
你不应假设所有函数在出现错误时都会把其他返回值设为零值。
最佳做法是假设一旦发生错误，使用任何其他返回值都是不安全的。
唯一的例外是文档明确指出在出错时其他返回值仍然有意义的情况。
~~~~

如果你想在多个地方使用这样一个简单的错误，应该为这个错误声明一个变量，而不是内联使用`errors.New`。
按照惯例，变量名应以`Err`或`err`开头（取决于它是否被导出）。
这些错误变量通常被称为_哨兵错误_。

```go
import "errors"

var ErrNotFound = errors.New("resource was not found")

func DoSomething() error {
  // ...
  return ErrNotFound
}
```

让函数返回`nil`作为错误，以表示函数执行期间没有发生错误：

```go
func Foo() (int, error) {
  return 10, nil
}
```

## 错误检查

如果你调用一个返回错误的函数，通常会把错误值存入一个名为`err`的变量。
在使用函数的实际结果之前，你需要先检查没有错误。

为了避免嵌套代码的“正常路径”，应该先处理错误情况。
我们可以用`==`和`!=`把错误与`nil`进行比较，当`err`不为`nil`时，就知道发生了错误。

```go
func processUserFile() error {
	file, err := os.Open("./users.csv")
	if err != nil {
		return err
	}

	// do something with file
}
```

大多数情况下，错误会根据上面的示例沿着函数调用栈向上返回。
处理错误的另一种方式是把错误记录下来，然后继续执行其他操作。
好的做法是要么返回错误，要么记录错误，绝不要两者都做。

由于 Go 中大多数函数都把错误作为返回值之一，你会在 Go 代码里到处看到/用到`if err != nil`这种模式。

## 自定义错误类型

如果你希望错误包含的信息不止错误信息字符串，可以创建一个自定义错误类型。
如前所述，任何实现了`error`接口的东西（即拥有`Error() string`方法）都可以在 Go 中充当错误。

通常会用结构体来创建自定义错误类型。
按照惯例，自定义错误类型的名称应以`Error`结尾。
另外，最好用指针接收者来实现`Error() string`方法，想了解其中的理由，可以看这条 [Stackoverflow 评论][stackoverflow-errors]。
注意，这意味着你需要返回指向自定义错误的指针，否则它不会被算作`error`，因为非指针值没有提供`Error() string`方法。

```go
type MyCustomError struct {
  message string
  details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.message, e.details)
}

func someFunction() error {
  // ...
  return &MyCustomError{
    message: "...",
    details: "...",
  }
}
```
