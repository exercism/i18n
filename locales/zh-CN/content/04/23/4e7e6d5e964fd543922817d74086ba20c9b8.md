# 可变性

可变性是 Rust 中某个特定绑定的属性。绑定要么是不可变的，要么是可变的。不可变绑定的值不能改变；可变绑定的值可以改变。所有绑定默认都是不可变的。

## 绑定

绑定是源代码中出现的某个变量名与执行期间出现的某块内存区域之间的关联。严格来说，绑定只存在于编译期间：编译之前，还没有真正分配内存；编译之后，机器码只处理内存地址，不再处理有名字的变量。

绑定通常使用`let`关键字创建。此外，函数形参以及在某些其他情况下也会创建绑定。

绑定可以具有多种属性，其中最重要的是可变性。可变绑定是指可以合法改变其所绑定的内存值的绑定。Rust 会严格跟踪并强制约束每个绑定的可变性，拒绝那些错误地试图修改本应不可变的绑定的程序，从而帮助确保程序正确。

## 可变性

实践中，可变性往往很简单。在绑定的定义中使用`mut`关键字，你就能改变它的值。

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### 从可变降级为不可变

绑定总是可以从可变降级为不可变。这一操作是透明的。

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### 从不可变提升为可变

一般来说，只要所有权发生转移，任何时候都可以把值从不可变提升为可变。

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

在`(1)`处，字符串的所有权从`x`转移到了`y`，这让我们可以把该值提升为可变。

### 函数形参中的可变性

函数形参可变有两种不同的方式。第一种，也是更常见的一种，类似于 C 语言中的按引用传递：

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

在这个例子中，可变性在三处被显式标注。要让可变引用正常工作，这三处可变性声明都是必需的。
在`(2)`中，绑定`x`被声明为可变的。这个绑定是该值的顶层所有者。
在`(3)`中，该值被可变地借用，传入`increment`函数。
在`(1)`中，为相应的引用创建了一个新的可变绑定`n`。

还有另一种形参可变性的风格，它不太常见，但有时仍然很有用。在这种风格中，值是被拥有的，但绑定是可变的。

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

这个例子需要的显式标注更少，因为它实际上是带内置可变性提升的所有权转移。它能成立，是因为`i32`是一种`Copy`类型，会透明地复制数据。
在`(1)`中，我们声明`increment_internally`接受一个名为`n`的、被拥有的可变`i32`作为形参。
在`(2)`中，我们声明`x`是指向值`1`的不可变绑定。
在`(3)`中，`x`被复制到内存中的新位置。`x`仍然是不可变的。`n`是可变的。

当然也可以把这些形式组合起来，给可变引用加上可变绑定（`mut n: &mut i32`等），但这很少是真正想要的做法。

### 没有`let`的可变性

Rust 中有几种结构（`if let`、`match`等）也能创建绑定。这些绑定同样可以是可变的。

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

这个例子会先产生`v = Some(2)`，然后产生`v = None`。

## 遮蔽

随着某个值被转换，通过多次`let`调用重新声明，复用同一个变量名是可行的，而且往往很惯用。这被称为遮蔽。

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

不过，这并不是可变性的情况；原来的值原则上仍然存在。对于非`Drop`类型，编译器可能选择修改某个内存位置，而不是分配一个新的。但只要涉及`Drop`类型，或者旧的绑定之后还会被使用，它就不会这么做。

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
