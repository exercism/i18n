# 关于

`String`和`&str`是在 Rust 中处理文本数据的两种基本方式。了解它们各自的特点以及它们如何配合使用，会非常实用。本文讨论它们之间的重叠之处，并给出一些基本建议。

`String`是一个拥有所有权的`u8`字节向量。`String`是可变的。`&str`是对 String 切片的借用引用。`&str`是不可变的。

`&str`的正确读法是“ref string”。

`String`是对一串 Unicode 码点的表示，采用 UTF-8 编码，并且可能可变。

`&str`是对格式良好的 UTF-8 序列的只读视图。由于它是引用，因此它实现了`Copy`，可以被共享。

Rust 中的`String`和`&str`不能像其他语言里那样用下标访问。例如，下面这样是不行的：

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

这源于以下几个特性：

- 字符串采用 UTF-8 编码，它的基本单位不是字节，而是 Unicode 码点：`char`。
- Unicode 码点最多占 4 个字节，但编码后的宽度是可变的。
- 因此，如果不逐个迭代实际编码后的字符，就无法算出第`n`个码点的位置，因为过了第一个字符之后，下一个字符的位置取决于前面那些字符有多宽。
- 因此，Rust 标准库的作者选择不为字符串实现`Index` trait：对字节数组做下标访问只需要常数时间，而对字符串做下标访问则可能要花很久。这违背了最小惊讶原则。

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## 把`String`转换成`&str`

`String`实现了`Deref<Target=str>`。编译器对这个 trait 做了一些特殊处理：这意味着任何指向`String`的引用都可以自动、透明地强制转换成`&str`。这带来以下结果：

- 比如，任何期望接收`&str`实参的代码，都可以改为接受`&String`。
- 为`&str`实现的任何方法，也可以在`String`上调用。

（如果想以泛型的方式接受任何形式的`str`引用，可以把实参类型写成`impl AsRef<str>`，不过通常把实参类型写成`&str`更常见。）

## 把`&str`转换成`String`

从`&str`创建`String`有很多种方式：

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

上面这些方式都需要为`String`分配内存（在堆上）。这也是为什么`&str`在 no_std 中可用，而`String`不可用。

（在 no_std 中处理字符串时，经常会用到 [heapless](https://crates.io/crates/heapless) crate。）

## 在结构体中使用 String 和`&str`

本节讨论结构体字段什么时候该用`String`，什么时候该用`&str`。你经常能看到结构体用`String`而不是`&str`来定义字段值。

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

使用`String`时，结构体拥有数据。这让代码更容易阅读，也更便于向初学者讲解。但这也意味着每个字段都会发生堆分配。`&str`借用文本数据，因此性能更好，代价是你的结构体需要定义生命周期参数。[csv crate 教程][csv-tutorial]很好地实际演示并解释了这些思路。

## 性能说明

`String`在堆上分配，所以使用起来可能代价更高。`&str`是共享引用，因此不需要频繁重新分配。
