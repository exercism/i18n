# 说明

赫尔码头正赶上夜班。货轮 *Olwen* 停靠在旁边，一群码头工人正并行地处理货物清单。每个货箱在上船之前都必须称重，而港务长维护着一份唯一的、持续更新的**吨位计数**，每一次吊装都会更新它。问题在于：码头只有一台起重机，所以不能让两个码头工人同时更新它，把计数撕裂。

每个货箱是一个数组，装着各个物品的重量。货箱的重量就是这些物品重量之和。

## 1. 称一箱货

定义`weigh-crate`，接收一个货箱，返回它的总重量。这是普通的顺序工作，一个货箱进，一个数字出。

```factor
{ 12 8 15 } weigh-crate .
! => 35
```

## 2. 并行称量整份清单

定义`weigh-all`，接收一个货箱数组，返回它们重量的数组，顺序保持一致。使用`parallel-map`，让每个货箱的工作并发进行。

```factor
{ { 5 5 } { 10 } { 3 4 5 } } weigh-all .
! => { 10 10 12 }
```

## 3. 造一台新起重机

定义`<crane>`来构造一台新的起重机：一个元组，含一把全新的`<lock>`，吨位为`0`。起重机是共享资源，后续任务会保护它。

```factor
<crane> tonnage>> .
! => 0
```

## 4. 把一个货箱吊装到运行中的计数上

定义`hoist-crate`，接收一个`weight`和一台`crane`，在**起重机的锁之下**把这个重量加到起重机的吨位上，这样相对于其他同时吊装的码头工人，读-加-写这一系列操作就是原子的。

```factor
<crane>
35 over hoist-crate
17 over hoist-crate
tonnage>> .
! => 52
```

## 5. 读取运行中的吨位

定义`crane-tonnage`，返回起重机当前的吨位，同样要在锁之下进行，这样读取时就不会看到吊装中途被撕裂的值。

```factor
<crane>
35 over hoist-crate
crane-tonnage .
! => 35
```

## 6. 装货

定义`load-cargo`，接收一个货箱数组和一台起重机，并且**为每个货箱启动一个码头工人线程**，由它称量货箱，再把重量吊装到起重机上。只有当所有码头工人都完成后，这个词才会返回。使用`<promise>`和`?promise`来协调汇合。

```factor
<crane> :> crane
{ { 5 5 } { 10 } { 3 4 5 } } crane load-cargo
crane crane-tonnage .
! => 32
```
