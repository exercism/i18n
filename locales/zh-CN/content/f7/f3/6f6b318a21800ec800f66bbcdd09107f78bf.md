# 关于

如果函数执行的_最后_一件事是调用它自己，那么它就是[尾递归][recursion-tc]。

每次调用函数时，都会把一个包含局部变量和实参的_栈帧_放到[函数调用栈][call-stack]的栈顶。
函数返回时，这个栈帧就会从栈中移除。

尾递归函数可以使用[尾调用优化][tail-call-optimization]（也叫尾调用消除）。
这种优化让下一次函数调用可以复用上一个栈帧，前提是前一个函数确定不再需要它了。
这样可以缓解函数调用栈溢出的问题，也就是函数调用栈上的栈帧太多，已经没有内存再创建新栈帧的情况。

## Elm 中的尾调用优化

在某些情况下，Elm 编译器在编译到 JavaScript 时能够自动进行尾调用优化。

对于递归函数来说，当某个分支中的_最后_一个操作是以简单的函数调用形式调用函数自身时，就可以进行这种优化。
来看几个例子：

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

上面的实现不是尾递归的，因为`else`分支中的最后一个操作是乘法`n *`。

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

上面的实现是尾递归的，会被优化，因为`else`分支中的最后一个操作是`factorialHelper`调用它自己。
对于类型签名为`Int -> Int`的函数，这是做不到的，而在实践中，尾调用优化通常通过定义辅助函数来实现。

## 边界情况

有些情况下，编译器无法优化递归函数。来看几个例子。

虽然`f x = f (x - 1)`是尾递归的，但`f x = (x - 1) |> f`不是，因为函数应用`|>`是最后一个操作，会被视为独立于`f`。
同样，以布尔条件`f x = x > 0 || f (x - 1)`结尾的函数也不是尾递归的。

函数`f x = if f (x - 1) then 1 else 0`不是尾递归的，因为`if`中的表达式不被视为分支。
同样，`case`语句中的递归调用也不会被优化。

函数`f x = let y = f (x - 1) in y`不是尾递归的，因为它在`let`语句中调用自身，而`let`语句不被视为分支。
不过，在`f x = let g x = g (x - 1) in g x`中，函数`g`是尾递归的，即使在`let`语句中定义，也会被优化。

函数`f x = if x > 0 then f (x + 1) else 1 + f x`会被_部分_优化：`then`分支可以优化，但`else`分支不行。
在某些情况下，比如遍历树状结构或定义互递归函数时，部分优化已经是能做到的最好结果。
