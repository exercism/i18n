# 工作流

GitHub Actions 使用了_工作流_这一概念。工作流是在特定事件发生时（例如推送一次提交）自动运行的脚本。

每个 GitHub Actions 工作流都定义在 `.github/workflows` 目录中的一个 `.yml` 文件里。
有关工作流的更多信息，请查看以下文档：

- [工作流语法](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions)
- [选择工作流的运行时机](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow)
- [选择工作流的运行位置](https://docs.github.com/en/actions/writing-workflows/choosing-where-your-workflow-runs)
- [选择工作流要执行的操作](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does)
- [编写工作流](https://docs.github.com/en/actions/writing-workflows)
- [最佳实践](/docs/building/github/gha-best-practices)

## 共享工作流

有些工作流会在多个代码仓库之间共享。

```exercism/caution
共享工作流会自动同步（来源为 [org-wide-files 仓库](https://github.com/exercism/org-wide-files/)）。
因此，你不应手动修改它们的内容。
```

### 通用工作流

- [同步标签](/docs/building/tracks/ci/workflows/sync-labels)：从文件同步代码仓库的标签

### 轨道专用工作流

- [configlet](/docs/building/tracks/ci/workflows/configlet)：检查轨道的（配置）文件结构是否正确，包括语法和语义两方面
- [没有重要文件发生变更](/docs/building/tracks/ci/workflows/no-important-files-changed)：对会导致现有解答被重新测试的拉取请求发表评论
- [测试](/docs/building/tracks/new/setup-continuous-integration#h-test-workflow)：验证轨道中的练习

### 工具专用工作流

- [部署](/docs/building/tracks/ci/workflows/deploy)：将轨道工具的 Docker 镜像部署到 Docker Hub 和 ECR

### 可选工作流

还有一些工作流，轨道可以选择启用：

- [暂停社区贡献](/docs/building/tracks/ci/workflows/pause-community-contributions)：对由非 Exercism GitHub 组织成员创建的新议题和拉取请求自动发表评论

## 自定义工作流

维护者可以自由地往自己的代码仓库里添加自定义工作流。
这类工作流可能是：

- [对 shell 脚本进行 lint 检查](https://github.com/exercism/configlet/blob/3baa09608c8ac327315c887608c13a68ae8ac359/.github/workflows/shellcheck.yml)
- [自动评论拉取请求](https://github.com/exercism/elixir/blob/b737f80cc93fcfdec6c53acb7361819834782470/.github/workflows/pr-comment.yml)
- 等等。
