# 契约

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| 子句 | 说明 | 违反时是谁的责任 |
| --- | --- | --- |
| `pre` | 进入时必须满足的条件 | 调用者的责任 |
| `post` | 返回时会满足的条件 | 例程的责任 |

两者都接受一个`BOOL`，也都可以使用例程的实参和对象的属性。`post`还可以使用`result`，也就是即将返回的值。

## assert

在例程体内，`assert`声明某个在该位置必须为真的判定：

```sather
      assert load <= limit;
```

它和其他几种一样，在同一个开关下接受检查。

## 类不变式

类可以声明一件在两次调用之间对它的每个对象都成立的事情：

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

当检查开启时，在每个公开例程进入和退出时都会检查。

## 开启检查

| 标志 | 检查的内容 |
| --- | --- |
| `-chk` | 全部内容：pre、post、assert、不变式、边界检查、算术检查 |
| `-chk_no` | 什么都不检查 |

注意，单独使用`-chk_pre`在这个编译器里*并不*会开启前置条件检查；真正管用的是`-chk`。违反契约时，程序会打印出例程和源代码行，然后停止运行。它不是异常，`protect`也捕获不到。

通常的做法是，开发和测试时开启`-chk`，发布时不带检查，这样检查在发布的程序里就不产生任何开销。只有测试真正覆盖到那些路径时，这样做才划算。

## 什么是好的契约

说明例程需要什么，而不是它如何工作：

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

把例程体又复述一遍的`post`，对谁都没有帮助：

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## 继承

子类型可以弱化`pre`、强化`post`，也就是接受得更多、承诺得更多，但绝不能反过来，否则针对超类型编写的代码就会被破坏。这正是契约存在的意义：让这条规则可以被检查。
