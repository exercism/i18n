# 列表

`LIST{T}`是一种可增长的、有序的集合，底层用一个数组来支撑，数组装满时会被替换成一个更大的。

```sather
   notes ::= #LIST{STR};
   notes.append("muddy boots");
   notes[0]                     -- "muddy boots"
   notes[0] := "clean boots";
   notes.size
   notes.is_empty
   notes.has("clean boots")
   notes.remove_index(0);
```

## 数组还是列表？

| | `ARRAY{T}` | `LIST{T}` |
| --- | --- | --- |
| 大小 | 创建时固定 | 会变化 |
| 追加 | 不支持 | 支持 |
| 删除 | 不支持 | 支持 |
| 下标 | `a[i]` | `l[i]` |
| 额外开销 | 无 | 一个大小记录，以及预留空间 |

当大小已知且固定时，就用`ARRAY`，比如一排舞者、一周的计数。当元素会来会走时，就用`LIST`。

## 原地修改，而非函数式

`append`、`remove_index`和`[i] :=`都会改动列表本身。不需要把结果赋回原处，而且把一个列表交给某个例程后，也不能保证它不会改动这个列表。

这与`FMAP`和`FSET`正好相反，所以值得弄清楚你手上拿的到底是哪一种。经验法则是：名字开头的`F`表示函数式，其他所有操作都原地修改。

要交出一个谁也无法改坏的列表，就交出一份副本：

```sather
   return notes.copy;
```

## 追加的代价

追加平均来说很便宜。底层数组装满时，会取一个两倍大小的新数组，把所有元素都复制过去。所以大多数追加几乎不花什么代价，偶尔一次则要付出一整份复制的代价。在大量追加之后，平均下来每次的代价是常数，这正是采用翻倍、而不是每次只增一个的原因。

`remove_index`并不便宜：被删除位置之后的所有元素都要前移一位。反复从长列表的头部删除元素会很慢，而这种慢很容易被忽略。

## 常用例程

| 调用 | 作用 |
| --- | --- |
| `l.append(x)` | 追加到末尾 |
| `l.insert_before(i, x)` | 在指定位置插入 |
| `l.remove_index(i)` | 移除某个位置 |
| `l.has(x)` | 是否包含它？ |
| `l.copy` | 一份独立的副本 |
| `l.str` | 内容，放在大括号中 |
| `l.elt!`, `l.ind!` | 遍历各个值，或各个位置 |
