# 简介

智能指针是现代 C++ 的一项特性，旨在提供自动内存管理，帮助避免内存泄漏和悬空指针，这些通常是原始指针会带来的问题。
它们是对原始指针的封装，增加了额外的功能，比如在不再需要该指针时自动释放内存。

## 通用语法

智能指针在 C++ 标准库中通常以类模板的形式实现。
最常用的两种智能指针是`std::unique_ptr`和`std::shared_ptr`。

## 独占指针

`std::unique_ptr`是一种智能指针，它独占对象的所有权。
它确保在任何时刻，都只有一个`std::unique_ptr`对象拥有该资源。
当拥有资源的`std::unique_ptr`被销毁或被重置时，它会自动销毁对象并释放其内存。

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## `std::make_unique()`的优点

创建`std::unique_ptr`时，最好用`std::make_unique()`，而不是直接用`new`分配内存。
`std::make_unique()`有以下几个优点：
1. **异常安全**：`std::make_unique()`保证异常安全。
  如果在对象的构造过程中抛出异常，内存会被自动释放，从而避免内存泄漏。
2. **清晰**：使用`std::make_unique()`让代码更清晰、更简洁。
  它省去了显式指定所分配类型的需要，因为模板实参会被自动推导。
3. **优化机会**：相比用`new`手动分配内存，编译器有机会更有效地优化`std::make_unique()`，从而可能提升性能。
4. **避免误用**：手动构造`std::unique_ptr`时，就有可能删除底层资源。
  这样当`std::unique_ptr`在其作用域结束时试图删除它，就会导致未定义行为。

## 共享指针

`std::shared_ptr`是一种智能指针，它允许多个`std::shared_ptr`对象共享同一资源的所有权。
它会记录有多少个共享指针引用该资源，并且只有当拥有该资源的最后一个共享指针离开作用域或被重置时，才会释放内存。

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
在 C++17 及更早的版本中，并不直接支持通过`std::make_shared<T[]>`把`std::shared_ptr`用于数组。
虽然可以用`std::make_shared<T[]>`分配数组，但直接用它创建共享指针可能会导致未定义行为，因为单个对象和数组在内存管理上存在差异。
相反，可以考虑使用`std::vector`或自定义的删除函数，以便用共享指针有效地管理数组。
在 C++17 中处理数组分配和共享指针时，一定要确保与你的编译器和标准库实现兼容。
~~~~

## `std::make_shared()`的优点

与`std::make_unique()`类似，`std::make_shared()`也带来了更好的内存效率、异常安全性和可读性等好处。
它把控制块和被管理对象的内存分配合并为一次操作，提高了效率，也降低了内存泄漏的风险。
此外，自动推导模板实参让代码更简单，也提升了可读性。
在 C++ 中处理`std::shared_ptr`对象时，使用`std::make_shared()`有助于写出更清晰、更安全、更高效的代码。

## 弱指针

`std::weak_ptr`是`std::shared_ptr`的配套类，它对由共享指针管理的对象提供一种不拥有所有权的“弱”引用。

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

在需要打破循环引用以避免内存泄漏的场景中，弱指针很有用。
`std::weak_ptr`的设计目的，就是解决使用`std::shared_ptr`时可能出现的循环所有权问题，也叫循环引用。
在循环所有权的情况下，两个或更多`std::shared_ptr`对象互相引用，形成一个环，其中没有任何对象能被删除，因为它们彼此持有强引用，最终导致内存泄漏。
`std::weak_ptr`为这个问题提供了解决方案：它允许对共享对象建立弱引用，而不增加其引用计数。
这意味着它可以观察和访问共享对象，但不会阻止该对象被删除。
~~~~

## 使用建议

默认情况下使用智能指针：独占所有权用`std::unique_ptr`，共享所有权用`std::shared_ptr`。
原始指针只留给不拥有所有权的引用，或者与旧代码交互的场合。
大多数情况下，`std::unique_ptr`足以应付独占所有权，因为它提供轻量的内存管理，没有引用计数的开销。
`std::shared_ptr`应谨慎使用，因为除非确实需要共享所有权，否则它会带来开销和复杂性。
`std::weak_ptr`专门用于打破循环依赖或观察共享对象，但并不常用。
