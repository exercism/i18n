# 关于

要理解`collect`函数，重要的是知道它用于求出迭代器的结果。回想一下，迭代器是一系列项，可以和其他迭代器链接起来。迭代器是_惰性_的，这意味着在你调用消费迭代器的代码之前，它们不会执行。这类代码包括`for`循环和[消费型适配器][consuming adaptor]。消费型适配器会处理迭代器中的所有项，产生某种输出。

[`collect`][collect]就是这样一种消费型适配器，可以用来生成任何实现了 [`FromIterator`特征][from iterator] 的类型的实例。标准库中的所有集合都实现了这个特征。因为许多类型都实现了`FromIterator`，所以你需要让 Rust 知道你想要哪种集合。例如，如果我们想从一个字符串切片得到一个`Vec<char>`，可以在调用`collect`时把类型写进去，就像这样

```rust
    let my_chars = "Hello, World!".chars().collect::<Vec<char>>();
// since the item type of the `String::chars()` iterator can be inferred to be `char`, we can omit that information
// let my_chars = "Hello, World!".chars().collect::<Vec<_>>();
```

双冒号和外侧的尖括号（即`::<_>`）被称为`turbofish`。在这种情况下，turbofish 的语法比我们需要的更啰嗦。通过在绑定本身指定类型，`collect`就能在语法上更简洁地推断出应该创建哪种集合。

```rust
    let my_chars: Vec<char> = "Hello, World!".chars().collect();
// or
// let my_chars: Vec<_> = "Hello, World!".chars().collect();
```

如果我们想要一个字符顺序反转的`String`，可以这样做

```rust
    let rev_chars: String = "Hello, World!".chars().rev().collect();
```

Rust 的类型推断足够强大，有时候我们并不需要显式地写上类型标注：

```rust
fn get_reversed_chars(phrase: &str) -> Vec<char> {
    phrase.chars().rev().collect()
}
```

`get_reversed_chars`函数的返回类型让`collect`函数能够推断出应该返回哪种集合。不过在这里，我们必须指定`Vec<char>`而不是`Vec<_>`，因为 Rust 不会对函数签名进行类型推断。这样做是为了确保阅读代码的人能快速知道一个函数接收和返回什么类型。
