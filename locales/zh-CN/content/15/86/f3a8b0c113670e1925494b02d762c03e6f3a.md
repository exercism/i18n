# 关于

这道练习展示了各种数字类型在溢出时的行为，也就是当它们的容量不足以容纳算术运算或类型转换等计算所产生的结果时会发生什么。

- 无符号[整数][integral-numeric-types]（`byte`、`ushort`、`uint`、`ulong`）会回绕到零（该类型的最大值 + 1 会起到模数的作用），除非[大致来说][checked-compiler-setting]它们出现在[`checked`][checked-and-unchecked]块中，这时会抛出`OverflowException`的实例。`int`和`long`的行为类似，只是它们分别回绕到`int.MinValue`和`long.minValue`。

```csharp
int one = 1;
checked
{
    int expr = int.MaxValue + one;  // overflow exception is thrown
}

// or

int expr2 = checked(int.MaxValue + one);  // overflow exception is thrown
```

- 如果一个字面量表达式会导致它被赋值到的变量溢出，那么就会出现编译时错误。
- `checked`状态只适用于直接位于该块中的表达式。被调用的函数中的溢出状态不会被捕获。
- [`float`和`double`][floating-point-numeric-types]类型会进入 _无穷大_ 状态，可以用`float.IsInfinity()`等方法检测。

```csharp
double d = double.MaxValue;
d *= 2d;
Double.IsFinite(d)
// => false
```

- 类型为[`decimal`][floating-point-numeric-types]的数字会抛出`OverflowException`的实例。
- 还有一个对应的`unchecked`关键字，用于你想在`checked`块内撤销`unchecked`效果的场合，或用于已经启用编译器设置的情形。

没有抛出异常就发生的溢出可能会带来问题，因为一般来说，错误情况报告得越早越好。

`int`和`float`的溢出问题可以通过把结果赋值给`long`、`decimal`或`double`类型的变量来缓解。

如果大整数对你的代码来说必不可少，那么使用[`BigInteger`][big-integer]类型也是一种选择。

当然，有些情况下允许整数回绕是合理的，尤其是无符号值。一个经典的例子是哈希码，它把整数的位宽当作一种求模运算。

你通常会发现，代码库里把`uint`或`ulong`用作标识符的地方往往没有检查，因为人们觉得这么做得不偿失。如果从领域就能明显看出不会涉及非常大的值，这也同样适用。不过，看看[这个][computerphile-gangnam-style]，它是一则警示。
