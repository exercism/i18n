# 简介

在 Elixir 中，所有代码都运行在进程里。

默认情况下，函数会在调用它的那个进程中执行。如果需要让某个函数显式地在新进程中运行，可以使用`spawn/1`：

```elixir
spawn(fn -> 2 + 2 end)
# => #PID<0.125.0>
```

`spawn/1`会创建一个新进程，执行传入的零元函数，并返回一个_进程标识符_（PID）。新进程会在函数执行期间一直存活，函数执行完毕后便悄然退出。

不要把 Elixir 的进程与操作系统进程混为一谈。Elixir 的进程占用的内存和 CPU 要少得多。一个 Elixir 应用同时运行几百个 Elixir 进程，也完全没有问题。

## 消息

进程之间不会直接共享信息。进程通过_发送和接收消息_来共享数据。

可以用`send/2`向任意进程发送消息。`send/2`的第一个实参是接收者的 PID，第二个实参是消息。

消息可以是任意类型，通常由原子和元组组成。如果想收到回复，就应该在消息的某个位置带上发送者的 PID。可以用`self()`获取当前进程的 PID。

`send/2`不会检查消息是否被接收者收到，也不会检查接收者是否还活着。消息会进入接收者的_邮箱_，只有当接收者显式地要求_接收消息_时，消息才会被读取。

可以用`receive/1`宏从邮箱中读取消息。它接受一个`do`块，可以对消息进行[模式匹配][exercism-pattern-matching]。

```elixir
receive do
  {:ping, sender_pid} -> send(sender_pid, :pong)
  :do_nothing -> nil
end
```

`receive/1`会从邮箱中取出_一条消息_，这条消息与给定的某个模式匹配，然后执行该模式对应的表达式。如果邮箱里没有消息，或者没有消息能匹配任何模式，`receive/1`就会一直等待，直到等到一条。

## 接收循环

如果想接收不止一条消息，就需要递归地调用`receive/1`。一种常见做法是实现一个递归函数，比如命名为`loop`，它调用`receive/1`，对消息做一些处理，然后再调用自己，等待更多消息。如果需要在两次`receive/1`调用之间传递状态，可以把状态作为实参传给那个`loop`函数。
