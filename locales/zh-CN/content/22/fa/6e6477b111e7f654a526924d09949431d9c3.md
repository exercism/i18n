# 关于

文件是磁盘上一个有名字的流。[`io.files`][io.files]词汇表提供两种处理文件的方式：一种是整文件便捷单词，一次调用就能读完或写完整个文件；另一种是流打开器（`with-…`组合子），可以增量地读写。两者都建立在同一个[流协议][stream-protocol]之上，这个协议也支撑着`io-streams`概念里的内存流：`<file-reader>`和`<string-reader>`响应的单词完全相同。

每个文件单词都要指定一个**编码**，也就是把字节映射成字符、再把字符映射回字节的方案。处理文本时，用的几乎总是`io.encodings.utf8`里的[`utf8`][utf8]；处理二进制数据时则用`latin1`或`<byte-array>`编码。

## 整文件读取

```
file-contents   ( path encoding -- str )
file-lines      ( path encoding -- seq )
```

`file-contents`把整个文件作为一个字符串返回。`file-lines`以数组形式返回文件中的各行，并去掉行终止符，当每一行就是一条记录时，这一点尤其方便。

```factor
USING: io.encodings.utf8 io.files ;

"forecast.txt" utf8 file-contents   ! => "sunny\ncloudy\n"
"forecast.txt" utf8 file-lines      ! => { "sunny" "cloudy" }
```

## 整文件写入

```
set-file-contents   ( str path encoding -- )
set-file-lines      ( seq path encoding -- )
```

两者都会**替换**文件，文件不存在时会先把它创建出来。`set-file-contents`原样写入一个字符串；`set-file-lines`把序列里的每个元素各写成一行，并自动补上换行符。

```factor
{ "sunny" "cloudy" } "forecast.txt" utf8 set-file-lines
! forecast.txt now holds "sunny\ncloudy\n"
```

## 带作用域的流

如果你想往文件里追加内容，或者想一段一段地读写，就用`with-…`组合子把它打开，然后在引用内部使用当前环境中的流单词：

```
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
with-file-appender   ( path encoding quot -- )
```

```factor
USING: io io.encodings.utf8 io.files ;

"log.txt" utf8 [ "another line" print ] with-file-appender
```

`with-file-writer`会先清空文件；`with-file-appender`保留原有内容，并在其后写入。每一个都是一个析构作用域：引用结束时文件句柄就会关闭，即使其中抛出异常也一样，这与`boatswains-bilge`组合子提供的保证相同，只不过这里专门针对文件。

## 整文件还是带作用域？

当文件小到可以完整放进内存，而你又想一次性拿到全部内容时，就用`file-contents` / `file-lines` / `set-file-contents` / `set-file-lines`。当你需要追加内容，需要用`readln`逐行读取一个大文件，或者需要交替进行读写时，就用`with-…`打开器，总之凡是把整个文件放进内存会造成浪费或根本行不通的地方，都该用它。
