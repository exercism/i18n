# 简介

[模式匹配][pattern-matching]让分支代码更具表现力，[解构][destructuring]则能优雅地把值绑定到变量上。作为 Elm 程序员，这两者都非常值得掌握；把它们搭配使用，还能大幅提升代码的可读性。

## 简单的模式匹配

模式匹配是指根据所处理数据的形态来编写分支代码。因此它天然契合自定义类型的概念，因为自定义类型表达的正是同一份数据可能呈现的多种形态。例如，给定一个 `Color` 自定义类型，它被定义为 `Blue` 或 `Red`，我们就可以编写一个 `toString` 函数，对颜色进行模式匹配，返回对应的字符串。

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

模式匹配同样适用于并非简单枚举的自定义类型。来看一个 `hello` 函数，它接收一个 `Maybe String` 作为形参，里面要么是一个人的名字，要么什么都没有。进行模式匹配时，我们可以给数据起一个小写名字，把这份数据绑定到该变量上，从而能在匹配的右侧使用它。

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

模式匹配必须是穷尽的，否则编译器会拒绝编译。但有时，我们并不关心某些数据，也不关心 case 表达式中的某些分支。这时，与其费劲找一个变量名来绑定、为所有情况都写分支，不如使用下划线通配符 `_`。

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## 进阶模式匹配

除了自定义类型，我们还可以对具有字面量的类型进行模式匹配，例如 `Char`、`String`、`Int` 和 `Floats`。

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

要在不嵌套的情况下匹配多个值，Elm 中一个常见的技巧是把要匹配的值组合成[_临时元组_][ad-hoc-tuples]，就像这样：

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

既然函数式程序员钟爱列表，[我们也可以对它们进行模式匹配][pattern-match-lists]，所用的语法与构建它们时相同，借助运算符 `::`。

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

最后，模式匹配甚至可以递归使用，让我们能深入复杂的递归类型内部。

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## 解构

解构与模式匹配非常相似，它同样能把变量绑定到类型内部的数据上。主要区别在于：当只有一种可能的形态时，我们把这个机制称为“解构”；而有多种形态时，则称为模式匹配。解构常出现在 `let` 绑定、函数实参中，当然也常与模式匹配一起出现在 case 表达式中。

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

解构可以用于只有一个变体的自定义类型、元组，也可以用于记录，用在记录上时格外方便。要[解构记录][records-pattern-matching]，可以使用它的任意数量字段：一个、两个、……或者全部字段。

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

遗憾的是，Elm 语法不支持对记录进行递归解构。在上面的 `Circle` 示例中，无法一次性访问圆心的 `x`` and `y`center`center`x`x`y`y` 位置。

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

最后再分享一个小技巧！有时，我们既想方便地访问某个整体，又想访问它的一部分。这时 [`as` 关键字][as-keyword]就派上用场了。它允许给整体起一个别名，同时仍然能解构其中的内容。

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
