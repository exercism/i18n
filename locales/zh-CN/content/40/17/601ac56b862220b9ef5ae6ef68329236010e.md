# 关于

`Option`类型是标准库提供的一种枚举。它适合用来表示一个可能不存在的值。虽然听起来像 `null` 或 `nil`，但它其实很不一样，也很特别。

`Option<T>`持有其他类型，并且有两个变体：`Some(T)`和`None`。

例如，`Option<u32>`持有`u32`类型。

## 用法

### 在`Option<T>`中使用`T`

要使用`Option`中可能存在的值，有几种常见的惯用法：

- `if let Some(t) = optional { ... }`。

    `if let`惯用法会从`Option<T>`中取出值，并把它绑定到变量`t`上。这样你就能在那个块作用域中直接使用它。

- `match optional { Some(t) => {...}, None => {...}}`

    `match`运算符也能让你在一条语句或一个表达式中解包并处理`None`的情况。它是 if 和 else 语句链的一种替代写法。使用`match`可以提高代码中某些部分的可读性。
- `optional.map(|t| ...)`
   `Option::map`会用你提供的函数就地更新一个 Option，并可能把它的类型换成新的类型。

   **注意**：只在其中含有值时才对该值进行操作。绑定后的结果是一个`Option<U>`，其中给定的闭包是`FnOnce(T) -> U`。
- `optional.unwrap()`。
   对`Option<T>`进行解包会取出`T`，但如果`T`并不存在，就会 panic。有些情况下这样写很方便。

   **重要**：解包短期内或写测试代码时能带来方便，但它有可能引发运行时 panic。所以应尽量避免使用。

- `optional.expect("Unexpected None found! Aborting program.)`。
   `Option<T>`上的`expect`方法与`unwrap()`很相似，但如果它是`None`，就会用你提供的消息触发 panic。

## 示例

当`Option<u32>`中存在值时：

```rust
let has_something: Option<u32> = Some(100);
assert_eq!(has_something.unwrap(), 100);
```

当`Option<u32>`中*不*存在值时：

```rust
let has_nothing: Option<u32> = None;
assert_eq!(has_nothing, None);
```
