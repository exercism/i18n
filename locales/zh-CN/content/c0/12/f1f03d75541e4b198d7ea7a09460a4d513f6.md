# 关于

`<dlist>`（位于 [`dlists`][dlists] 中）会构造一个全新的双向链表。相关操作位于 [`deques`][deques] 中，并通过 [deque 协议][deque-protocol]进行分派，因此其他容器（主要是 `<dlist>`）也可以实现这些操作。

| 单词 | 效果 |
|------|------|
| `<dlist>` | `( -- dlist )`，新建的空 deque |
| `push-front` | `( elt deque -- )`，在队首添加 |
| `push-back` | `( elt deque -- )`，在队尾添加 |
| `pop-front` | `( deque -- elt )`，从队首移除 |
| `pop-back` | `( deque -- elt )`，从队尾移除 |
| `peek-front` | `( deque -- elt )`，读取队首但不移除 |
| `peek-back` | `( deque -- elt )`，读取队尾但不移除 |
| `deque-empty?` | `( deque -- ? )`，deque 是否为空？ |
| `dlist-length` | `( dlist -- n )`，元素个数 |

所有 push/pop 操作都会原地修改 deque。把一个 deque 传给某个例程后再从它读取，是完全正常的用法。

## 栈与队列

有两种常见的分派模式：

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

当你只需要 LIFO 顺序时，带有 `push` 和 `pop`（来自 `mutation`）的向量才是合适的选择，因为 `<dlist>` 会带来链表的额外开销。当你需要在*两端*都达到 O(1) 时，才该用 `<dlist>`，而这几乎总是为了 FIFO 队列。

## BFS 模式

广度优先搜索是 FIFO 的典型用法：

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

deque 承载着搜索边界，哈希集合则负责去重。把 `pop-front` 换成 `pop-back`，同样的结构就变成了深度优先。

## `MEMO:`：自动缓存

有时，BFS 调用的逐节点查找开销很大。Factor 提供了 [`MEMO:`][memo-decl]，它可以替代 `:`，并根据单词的输入自动缓存其结果：

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

`MEMO:` 单词会在第一次遇到某个输入时运行它的函数体，此后便返回缓存的结果。缓存的生存期与映像相同，没有基于时间或大小的淘汰机制。它适合用在输入来自一个有限且规模可控的集合的纯函数上。
