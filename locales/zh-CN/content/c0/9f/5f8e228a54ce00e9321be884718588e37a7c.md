# 说明

遥控车项目的工作还在继续。遥测系统的带宽十分紧张，你被要求实现一套用于传输遥测数据的消息协议。

数据通过缓冲区（字节数组）传输。发送整数时，会采用下面描述的协议来减小缓冲区的大小。

每个值都应使用尽可能小的整数类型来表示（不包含 `byte` 和 `sbyte` 类型，因为那样节省的空间微乎其微）：

| 起始值                     | 结束值                    | 类型     |
| -------------------------- | ------------------------- | -------- |
| 4_294_967_296              | 9_223_372_036_854_775_807 | `long`   |
| 2_147_483_648              | 4_294_967_295             | `uint`   |
| 65_536                     | 2_147_483_647             | `int`    |
| 0                          | 65_535                    | `ushort` |
| -32_768                    | -1                        | `short`  |
| -2_147_483_648             | -32_769                   | `int`    |
| -9_223_372_036_854_775_808 | -2_147_483_649            | `long`   |

值应转换为与其分配到的类型相对应的字节数。完整的缓冲区由一个表示缓冲区中额外字节数的字节（_前缀字节_）以及随后存放该整数的字节（_载荷字节_）组成。

有些类型使用的字节数相同（例如 `uint` 和 `int` 类型）。通常它们会拥有相同的_前缀字节_，但这会让解码变得困难。为此，协议引入了一个小技巧：对于有符号类型，其_前缀字节_的值等于 `256` 减去缓冲区中额外的字节数。

通信中只会发送前缀字节以及由该前缀指明数量的后续字节。在内部，发送和接收例程都会使用一个 9 字节的缓冲区（必要时补上末尾的零）。

## 1. 将整数值编码以便发送

请实现静态方法 `TelemetryBuffer.ToBuffer()`，把传入该方法的参数编码进缓冲区。

```csharp
// Type: ushort, bytes: 2, signed: no, prefix byte: 2
TelemetryBuffer.ToBuffer(5)
// => {0x2, 0x5, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0 };

// Type: int, bytes: 4, signed: yes, prefix byte: 256 - 4
TelemetryBuffer.ToBuffer(Int32.MaxValue)
// => {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 };
```

## 2. 解码接收到的缓冲区

请实现静态方法 `TelemetryBuffer.FromBuffer()`，解码接收到的缓冲区，并以 `long` 的形式返回该值。

```csharp
TelemetryBuffer.FromBuffer(new byte[] {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 })
// => 2147483647
```

如果前缀字节的值不符合预期，则应返回 `0`。
