# 简介

手写汇编充满了重复。
同一段简短的指令反复出现，几乎没有什么变化，而能减少样板代码的抽象又少之又少。
不仅如此，用汇编编写代码时，还得管理那些没有明显语义的值。
这里没有具名参数，底层机制的大部分细节都必须由程序员手动处理。

本课程使用的汇编器 NASM 提供了一些工具，可以帮程序员解决这两个问题。
这些工具在_汇编期_运行，此时任何指令都还没有到达处理器。
它们指导汇编器，如何在源文本被转换成机器码之前重写源文本。

这些工具中最重要的是**宏**，可以把它看成给汇编器的一份配方。
宏在使用的位置展开，就好像这段代码本来就是在那里手写的一样。

宏可以接受若干个字面量记号作为形参，从而能在不同场景中复用。
不过，宏不是函数：没有`call`，没有`ret`，也不会把控制权转移到代码中的另一处。

## 单行宏

最简单的定义方式，是用`%define`给一个值或一小段表达式起个名字：

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

此后每次出现`WIDTH`，都会在汇编之前被替换成`8`。
这种替换是文本层面的，所以这个名字无论出现在哪里都会被替换，不管是在操作数中，还是在另一个定义内部。

~~~~exercism/note
对于数字_常量_，优先使用`equ`，而不是`%define`。

用`%define`声明的单行宏只在使用时展开，而且可以重新赋值或取消定义。
而`equ`常量则在定义处求值，之后永远不会被修改。
~~~~

`%define`也可以接受_具名_形参，表现得像一个小型的内联函数：

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
把整个宏体以及每个形参都用括号括起来。
对于`%define square(x) x*x`，调用`square(1+1)`会展开成`1+1*1+1`，也就是`3`。
如果写成`%define square(x) ((x)*(x))`，同样的调用会展开成`((1+1)*(1+1))`，也就是`4`。
~~~~

用`%define`定义的名字区分大小写。
如果需要，可以用`%idefine`这个变体让名字不区分大小写。

单行宏很适合用来给代码中的各个部分赋予含义。
用得恰当的话，它能提高可读性，减少拼写错误的可能。
例如，某个在函数内有专门用途的寄存器，可以按它的用途来定义：

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## 多行宏

用`%macro`可以捕获整段代码，行数不限，并以`%endmacro`结束。
名字后面的数字表示这个宏接受多少个实参，可以是零。
传递实参时，用逗号（`,`）分隔：

```x86asm
%macro example_macro 0
...
%endmacro
```

多行宏中的实参没有名字。
它们按传递的顺序被称为`%1`、`%2`，以此类推：

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

注意，这些实参必须符合宏体中各项操作所要求的语法。
在这里，`mult_two eax, ecx`和`mult_two r8, r9`都能汇编通过，但`mult_two eax, cl`不行，因为`imul eax, cl`没有定义。

### 宏内部的标签

如果宏定义了一个普通标签，那么它一旦被使用两次就会出问题，因为那个标签也会被定义两次。
要在可能被调用多次的宏里使用标签，就必须给这样的标签加上`%%`前缀。
这会让汇编器在每次展开时给这个标签一个不同的、唯一的名字：

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## 在汇编期重复

用`times`可以重复一行代码。
在内存中声明重复的值时，这尤其有用：

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

要重复多行代码，可以改用`%rep`：

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

注意，重复次数紧跟在`%rep`之后指定，并且要有`%endrep`来结束重复的代码块。

在`%rep`块里使用汇编期计数器很常见，就像运行时循环使用计数器一样。
汇编期的整数常量可以用`equ`声明，而汇编期的整数_变量_则要用`%assign`。
与`%define`不同，`%assign`会立即求值成一个数字，并且可以重新赋值：

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

预处理器运行之后，循环就消失了，只剩下四条`add`指令，其中已经嵌入了立即数`0`、`1`、`2`和`3`。
这就是由汇编器完成的循环展开：没有计数器寄存器，也没有分支，只有顺序执行的代码。

## 条件汇编

预处理器提供了多种条件判断。
它们在若干不同的分支之间做出选择，在原处展开自己的主体，但只有在条件成立时才展开。

`%if` ... `%elif` ... `%else` ... `%endif`根据数值判断来选择一个分支：

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## 拆分到多个文件

宏常常放在单独的文件里，需要它们的每个源文件都用`%include`把它们引入：

```x86asm
%include "patterns.mac"
```

指定的文件会在该处、在汇编之前被原样插入，就好像它的内容本来就是在那里敲进去的一样。
这样可以把定义集中在一个地方，并让多个源文件共享它们。

如果这个宏文件可能被当作独立文件汇编，它就应该使用`.asm`扩展名。
注意，宏没有链接性。
即使这个宏文件被汇编了，它的宏也只对用`%include`引入它的另一个文件可见。

否则，只用于`%include`的文件可以使用任意扩展名。
使用`.asm`或`.mac`都是常见的约定。
