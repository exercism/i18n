# 简介

什么是函数式编程？

对我们来说，它有几个关键特征：

- 纯函数：把输入稳定地映射为输出，并且没有副作用。
- 不可变数据。
- 一等函数：可以像其他任何类型一样被当作值来处理。
- 高阶函数：接收其他函数作为实参，或者返回其他函数作为返回值。

不过，R 并不是纯函数式语言（例如，与 Haskell 相反）。

把 R 看作一门务实的语言：只要函数式能力是干净、轻松完成任务的方式，它就（越来越多地）提供这些能力。通常，数据分析才是目标，编程只是达成目标的手段。

## 管道

用管道 `|>` 连接函数，是多种语言中越来越常见的技术。

简单来说：

- 管道左侧的结果会成为右侧函数的第一个实参（这里的“右侧”忽略可选的换行）。
- 其余实参可以照常写在这次函数调用里。
- 在 R 中，管道必须指向一次函数_调用_，而不只是一个_名字_，所以括号总是必需的（_这一点与其他一些语言不同_）。

有些程序员在阅读代码时习惯把管道读作“then”：先做第 1 步，THEN 再做第 2 步……

下面的例子演示了这种语法。

```R
library(stringr)

"Monday-25-February" |> 
  str_split("-") |>     
  unlist() |>               # [1] "Monday"   "25"       "February"
  str_sub(1, 3) |>          # [1] "Mon" "25"  "Feb"
  str_to_upper() |>         # [1] "MON" "25"  "FEB"
  str_flatten(collapse = ", ")
#> [1] "MON, 25, FEB"
```

这种管道是在 v4.1.0 中加入 Base R 的，你可能会看到它被称为“原生管道”。

RStudio 编辑器（以及其他一些编辑器）用 `Ctrl-Shift-M` 作为快捷键，插入一个带合适空格的管道。

## apply 函数

前面我们看到，R 中的许多函数都是“向量化”的：它们会作用于整个向量，不需要写显式的循环。

只使用向量化函数的函数，本身很可能也会自动向量化。举个简单的例子：

```R
triple <- function(x) return(3 * x)
triple(1:10)
 [1]  3  6  9 12 15 18 21 24 27 30
 ```

不过，更复杂的函数可能不接受向量输入，例如函数中包含循环或 if-else 代码块时。

我们需要一种更通用的方式，把函数应用到向量上（类似于其他一些语言中的 `map()`）。

由于 R 的基础语言中有丰富多样的数据结构，它也有一整套 `*apply()` 函数来操作这些结构。更专业地说，程序员常把这类函数称为“高阶函数”，数学家则称之为“泛函”，因为它们接收函数作为实参。

现在，先来看看 `lapply()` 和 `sapply()`。

### `lapply()`

“List-apply”设计用于处理列表输入，但必要时向量会被静默地强制转换为列表。

输出是一个列表，所以可能需要拆解才能得到向量：

```R
h <- function(size) {
    switch(size,
           "small" = 6,
           "medium" = 8,
           "large" = 10
    )
}

v <- c("small", "large", "medium")

h(v) # bad use of an unvectorized function
#> Error in switch(size, small = 6, medium = 8, large = 10) : 
#>   EXPR must be a length 1 vector

lapply(v, h)  # output is a list
#> [[1]]
#> [1] 6

#> [[2]]
#> [1] 10

#> [[3]]
#> [1] 8

lapply(v, h) |> unlist() # output is a vector
#> [1]  6 10  8
```

熟悉[Switch 概念][concept-switch]的同学可能会注意到，我们也可以把标量 `switch` 换成 [`dplyr`][ref-dplyr]库中向量化的 [`recode_values()`][ref-recode_values]。向量化是好事，现代 R 提供了多种实现它的方式。

```R
library(dplyr)

h <- function(size) {
  recode_values(size,
         "small" ~ 6,
         "medium" ~ 8,
         "large" ~ 10
  )
}

v <- c("small", "large", "medium")
h(v)
#> [1]  6 10  8
```

### [`sapply()`][ref-lapply]

“Simplified-apply”做的事情和 `lapply` 类似，但还会尝试简化返回值：例如，返回带名字的向量而不是列表。视情况而定，可能需要用 [`unname()`][ref-unname]：

```R
sapply(v, h)
 small  large medium 
     6     10      8 

sapply(v, h) |> unname()
#> [1]  6 10  8
```

## `purrr`库

`lapply` 和 `sapply` 很简单，为大多数 R 用户所熟悉，在处理向量和简单列表时仍然相当流行。

Base R 还有_许多_其他的 apply 函数。为这类混乱提供更简单、更一致的替代方案，是 Tidyverse 的一个关键目标。

现在有了 `purrr` 包，它提供了若干额外选项，比如 `map()`，同时在设计上更加一致，错误信息也更加清晰。

与 Base R 相比，这个包受向下兼容的约束更少，它让 R 明显更接近其他语言中的现代函数式编程。

`purrr` 中的函数又多又杂，很难简单概括。有助于了解这个库的资源包括：

- 一个[网站][web-purrr]，其中包括[入门指南][web-starting]。
- 所有函数的[参考页][ref-purrr-funcs]。
- PDF 格式的[速查表][cheat-purrr]。
- 从 [Base R][web-from-R] 迁移的指南。

### 众多 map 函数

[map()][ref-map] 函数把函数应用到输入中的每个元素，并且总是返回一个[列表][concept-lists]。

到目前为止，听起来它就像 [`lapply()`][ref-lapply]换了个名字，可能还带了更好的错误信息。

不过，`map()` 只是一个_庞大_家族中的一员。

挑选函数时，可以考虑这些问题：

- 你想要返回什么？[`map()`][ref-map]总是返回列表，但如果你想要某种特定类型的原子向量，可以用 [`map_chr()`][ref-map_chr]返回字符串，用 [`map_int()`][ref-map_int]返回整数，等等。
- 你需要输入中每个位置的下标吗？在函数名前面加上 `i`，比如 [`imap()`][ref-imap]。
- 你想并行处理多个输入吗？
  - 把名字里的 `map` 换成 `map2`，比如用 [`map2_dbl()`][ref-map2_dbl]处理两个输入（例如值和权重，用来计算加权平均值）
  - 换成 `pmap` 来处理一组并行的输入，比如 [`pmap_chr()`][ref-pmap_chr]。没错，硬件层面的并行也是可以做到的。
- 你想处理输入中的所有元素吗？如果不是，可以考虑用 [`map_if()`][ref-map_if]应用谓词（布尔）过滤，用 [`map_at()`][ref-map_at]指定位置下标条件，用 [`head_while()`][ref-head_while]一直处理输入，直到某个元素不满足谓词为止。
- 输入数据是否嵌套得很深？针对这种情况有相应的[函数][ref-plucks]。
- 你想让返回值始终与输入类型相同吗？可以用 [`modify()`][ref-modify]系列函数代替 `map`，递归处理则用 [`modify_tree()`][ref-modify_tree]。

这些函数尽可能把输入数据作为第一个实参，以保证它们能和管道良好配合。

另外，`purrr`（有意）比 Base R 更吹毛求疵。如果你要求返回某种特定的东西，这些函数要么_恰好_返回它，要么直接报错停止。虽然严格，但对减少难以发现的 bug 非常有效。

### reduce 函数

map 函数返回值的长度通常与输入相同。

另一些函数则会_降低_数据的维度，例如 `sum()`。

```R
sum(1:100)
#> [1] 5050
```

在上面的例子中，我们把一个长度为 100 的向量转换成了一个长度为 1 的整数。在之后关于矩阵和数组的概念中我们会看到，降维这个概念其实更为普遍。

`sum()` 函数是内置的（许多其他统计函数也是）。不过，我们需要一种方式，用一个类似于 `map()` 的高阶函数，把任意的降维函数应用到整个数据结构上。

在其他一些语言中，这类函数叫 `fold`、`foldl`、`foldr` 之类的名字。在 R 中，相应的函数是 [`reduce()`][ref-reduce]，它对应着（算法爱好者熟知的）MapReduce 框架。

第一个实参照例是输入数据。第二个实参是一个接收两个实参的函数：通常是匿名函数，也可能简单到只是一个像 `+` 这样的算术运算符。

```R
# surround an infix operator with backticks, to use as a function
reduce(1:100, `+`)
#> [1] 5050  # same as sum(1:100)

# anonymous function, alternately add and subtract
reduce(1:10, \(accum, nextval) ifelse(nextval %% 2 == 0, accum + nextval, accum - nextval))
#> [1] 7
```

从输入的开头还是结尾开始应用这个函数，结果会有区别吗？

对于 `+` 或 `*` 这类[可结合][wiki-associative]的运算符来说没有区别。显然，`(1 + 2) + 3 == 1 + (2 + 3)`。

相比之下，`-` 和 `/` 不满足结合律：

```R
(1 - 2) - 3
#> [1] -4
1 - (2 - 3)
#> [1] 2
```

对于方向有影响的函数，有一个可选的 `.dir` 实参。

```R
# default is .dir = "forward"
reduce(1:10, `-`)
#> [1] -53
reduce(1:10, `-`, .dir = "backward")
#> [1] -5
```

和 `map()`、`map2()` 一样，也有一个 [`reduce2()`][ref-reduce]函数，可以并行处理两个输入向量。

在 R 中，我们喜欢使用向量。假设你不想只看最终的一个值，而是想看到所有的中间步骤。

为此，对应的函数是 [`accumulate()`][ref-accumulate]和 `accumulate2()`。语法和 `reduce()` 类似，但多了一些可选实参来指定输出类型。

```R
accumulate(1:10, `+`)
#> [1]  1  3  6 10 15 21 28 36 45 55
 ```

一些常见的累加类型有各自专用的函数。[向量函数][concept-vector-functions]概念中讨论了 Base R 里的 [`cumsum()`][ref-cumsum]和 `cumprod()`，而 `dplyr` 库则有用于数值平均的 [`cummean()`][ref-dplyr-cum]，以及用于逻辑向量的 `cumall()` 和 `cumany()`。

### 过滤函数

我们常常想保留（或排除）输入中符合某个谓词的元素。

在[向量过滤][concept-vector-filtering]概念中，我们看到了一种惯用的做法。

```R
v <- 1:3
v[v >= 2]
#> [1] 2 3
```

这在传统 R 中用得很多，但它和现代函数式管道配合得并不好。

因此，`purrr` 提供了一组[谓词函数][ref-predicates]，它们遵循 `f(input, func, ...)` 这样常见的实参约定，以便和管道配合使用。

这些名字和大多数其他语言略有不同（`filter`、`drop` 这样的名字在 R 里已经有完全不同的含义）。

对应的 `purrr` 函数包括 [`keep()`][ref-keep]和 [`discard()`][ref-keep]，以及其他几个函数。

此外，还有 [`every()`][ref-every]、[`some()`][ref-every]和 [`none()`][ref-every]，用来替代 `all()` 和 `any()`，返回单个逻辑值。
