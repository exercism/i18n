# 关于

在许多面向对象语言中，常见的做法是通过[子类化][wiki-subclass]父类来扩展行为：从父类继承方法，同时添加新的方法。
这样我们就得到了对象层次结构。

Julia _没有类_，因此顺理成章地也_没有子类_。
那么我们该如何继承和扩展现有的行为呢？

在前面的概念中，我们了解了如何创建类型层次结构，也学习了 Julia 如何使用[多重分派][concept-multiple-dispatch]根据实参类型来选择方法。

Julia 还有若干非正式的[接口][ref-interfaces]，它们能让你的自定义类型接入已为标准类型定义好的行为。

用迭代器接口来说明这一点最为容易。

## [迭代器][ref-iterators]

在教学大纲的前面部分，我们已经见过 Julia 对集合中每个元素进行操作的几种方式。

- [循环][concept-loops]，例如`for item in items...`
- [广播][concept-vector-operations]：`[1, 2, 3] .- 0.5`
- [高阶函数][concept-hof]：`map(√, [1, 4, 9])`
- [推导式][concept-comprehensions]：`[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [生成器][concept-comprehensions]：`(x^2 for x in 1:1e6)`，它会惰性求值。

显然，Julia 知道如何逐项遍历标准集合：上面例子中的向量和范围，还有 Set、Dict 等等。

那么，如何为我们自己的自定义集合添加这一能力呢？尤其是当它们像生成器一样可以惰性迭代时。

### 最低要求

要创建一个可迭代的序列，我们至少需要两样东西：

1. 一种获取_第一个_元素的方法。
2. 一种从当前状态获取_下一个_元素的方法。

Julia 通过`Base.iterate()`函数的方法来完成这些任务，步骤如下：

1. 首先会自动调用`Base.iterate(iter)`。
    - 如果没有可迭代的内容，返回`nothing`。
    - 否则，返回第一个元素和第一个状态组成的`Tuple`：`(firstitem, firststate)`。
2. 如果上一次迭代返回了一个元素，就会自动调用`Base.iterate(iter, state)`，并把`firststate`作为它的`state`实参。
    - 如果迭代结束，返回`nothing`。
    - 否则，返回下一个元素和下一个状态组成的`Tuple`：`(nextitem, nextstate)`。
3. 重复第 2 步，直到迭代结束。

这些步骤都在“后台”完成，也就是说，方法调用和状态由迭代协议在内部管理（状态始终保持不透明），只有元素会暴露给循环之类的上层结构。
换句话说，我们只能看到`item`，其余一切都留在黑箱里。

[多重分派][concept-multiple-dispatch]在这里是核心。
`iter`的类型决定调用哪些方法，实参的个数决定返回的是第一个元素还是下一个元素。

标准类型的方法已经定义好了：`Vector`、`Range`、`Set`等（[目前][ref-iterations-collections]共 14 种类型）。

要让自定义的`MyType`拥有同样的行为，我们首先需要定义：
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

这些内容在抽象层面听起来可能令人困惑，但实际上可以非常简单。
举个例子，假设我们想要一个类型，它能给出某个整数`n`的各次幂，直到达到最大个数。

首先，定义一个自定义类型：

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

现在我们可以为这个类型定义`iterate`方法了，但第一个元素和第一个状态分别是什么呢？

要得到第一个元素，有些迭代器需要复杂的准备工作，但在这个玩具示例中，我们可以看到返回的第一个元素就是底数本身，所以只需要检查`count`的值是否大于等于 1。

接下来考虑第一个状态，它携带供下一次迭代使用的信息。
具体需要记录哪些信息由你决定，而且它可以是任何类型。

在这个例子中，我们可以只记录`n`要乘方的“下标”，也可以利用`n`最近的一次幂（也就是返回的元素）和序列中的下一个“下标”，找到性能更好的做法。
把这两个数字包进一个`Tuple`，作为`state`返回即可。

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

在这个例子中，第一个元素（`p.n`）被返回给循环，第一个状态`(p.n, 2)`被传给`iterate(P::Powers, state)`方法。
在那里我们可以处理这个状态来生成下一个元素：把当前元素乘以底数，从而把它的幂增加`1`。

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

如果下标值仍在`count`范围内，就返回由`next`元素和自增后的状态`(next, index + 1)`组成的`Tuple`。
当`index`值超过`count`时，则返回`nothing`，表示迭代已经结束。

也许你已经注意到，`iterate(p::Powers)`和`iterate(p::Powers, state)`这两个方法的函数体相当相似。
事实上，只要足够巧妙，这种相似性就允许我们用更精简的方式实现：只保留带两个实参的版本，并为状态设置默认值：`Base.iterate(p::Powers, state=(1, 1))`。
这样一来，就不再需要单独的单实参版本`iterate(p::Powers)`。
在实践中，只要可行，人们常常这样做。

~~~~exercism/advanced
我们在[函数][concept-functions]概念中介绍可选实参时，并没有提到实现层面的细节。

后来我们学习了多重分派，所以现在更容易理解：Julia 会自动把_带_可选实参的函数转换成_不带_可选实参的多个方法。

定义`Base.iterate(P::Powers, state=(1, 1))`，与分别定义`Base.iterate(P::Powers, state)`和`Base.iterate(P::Powers)`完全等价。

[concept-functions]: https://exercism.org/tracks/julia/concepts/functions
~~~~

到目前为止，我们已经有了一些实用的功能：对于 3 的前 4 次幂，我们可以循环遍历结果、检查某个数字是否在结果中，以及应用`sum()`之类的聚合函数。

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 其他方法

尽管开局不错，但并非一切都能正常工作。

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

果然，`length(Powers(3, 4))`给出了完全相同的错误信息。

这很容易解决，因为长度本来就是类型构造器的一部分：在这个例子里是 4。
我们只需为这个类型定义`Base.length()`，然后就能对这个序列使用推导式和`collect()`了。

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

为了效率，最好同时定义`Base.eltype()`：即结果的元素类型。
这样，`collect()`之类的函数就能为输出的`Vector{Int}`预先分配空间，而不必反复向`Vector{Any}`执行`push!()`。

注意这个语法，你可能之前没见过：这个方法定义在_类型_上，而不是类型的_实例_上。

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

迭代器并不_要求_具有有限长度。
“无限”序列的用途比较有限，但只要能有办法`break`跳出循环，对它们进行循环就可能很有用。
例如，我们可以定义`Powers`的一个变体，让它生成小于某个上限的值（比如`typemax(Int)`，以避免整数溢出）。

## 其他接口

### [索引][ref-indexing]

迭代器接口让我们可以拿任意自定义类型，只需定义几个简单的方法，就能让它像序列一样工作。

假设我们还希望能在序列中使用索引：

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

我们可以添加这种行为，[手册][ref-indexing]中说明了具体做法。

最低限度上，我们需要定义`getindex()`。

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

我们还需要定义：

- `firstindex()`和`lastindex()`，以支持`P[begin]`和`P[end]`。
- `getindex()`的若干变体，以支持用向量和范围进行索引。
- 理论上还有`setindex!()`，不过很难看出在这个例子里它究竟意味着什么。

然而到了这一步，我们做了大量工作，只是为了让自己的迭代器看起来更像 Vector。

### [AbstractArray][ref-abstractarray]

也许值得考虑一些能提供更好起点的其他接口。

在这个例子中，我们可以考虑让`Powers`成为[`AbstractArray`][ref-abstractarray]的子类型，这样就能免费获得大量类似数组的行为。

对于`Powers`序列来说，对应的数组由整数构成，只有 1 个维度。
你有时会看到它写成`AbstractArray{Int, 1}`，但在较新的 Julia 代码中，更常见的是别名：一维用`AbstractVector{Int}`，二维用`AbstractMatrix{Int}`。

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

现在我们需要定义的不是`length()`，而是`size()`，它接收一个由各维度长度组成的元组：在这个例子里只有一个维度。

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

我们希望如何为各个条目建立索引呢？
在[多维数组概念][concept-multi-dimensional-arrays]中，我们介绍了两种主要方式：

- 每个维度一个索引，例如矩阵`M`写作`M[row, col]`。
- 单个索引，对应条目在内存中的排布方式

它们分别称为`Cartesian`和`Linear`。

我们的例子只有一个维度，所以线性索引是合适的。

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

注意，在这个例子里我们没有定义`iterate()`。
Julia 会根据我们定义的`getindex()`自动提供一个默认实现。

仍然可以自己定义`iterate()`的版本，在某些情况下可能效率更高。

如果我们想要更高维度的迭代，使用`AbstractArray`接口就特别有价值。
冒着把这个玩具示例拉伸到极限的风险，这可能是指`1:n`中各个数字的前`m`次幂，它会迭代地生成一个大小为`(m, n)`的数组。

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [舍入][ref-rounding]

前面的概念提到过针对数字类型的各种舍入方式。

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

[`round()`][ref-round]函数比这更灵活，它允许你指定[`RoundingMode`][ref-roundingmode]（目前支持 7 种）、输出的小数位数以及进制。

我们可能希望让同样的函数也能处理自定义类型。
常见的例子是坐标这样的复合类型。

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

不出所料，这里有一个`Rounding`接口，最低限度要求我们为自己的类型定义`round()`。

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

因为我们在定义中包含了`RoundingMode`，所以`floor()`和`ceil()`会自动生效。

当然，我们也可以自由地定义更复杂的舍入方式。

- 我们可能希望把`Point3D`沿同一方向舍入到距原点为整数距离的位置。
- 对于角度，我们可能希望舍入到气象预报员使用的 16 个方向（_“西南偏南风，15 节”_），也就是 π/8 弧度的整数倍。
- 我们可能希望增加指定`digits`、`sigdigits`或`base`的能力。
- 时间段有[特殊的选项][ref-round-periods]

## 总结

接口这个概念解释起来相当令人困惑，因为 Julia 的做法与大多数其他语言差别很大。
尤其是，接口的名字在实现中可能根本不会出现：这与[子类化][wiki-subclass]或[混入][wiki-mixins]非常不同。

不过，在实践中它们出奇地简单：

1. 定义一个合适的类型，并判断使用子类型是否有用。
2. （从[文档][ref-interfaces]中）找出需要哪些方法。
3. 为你的自定义类型实现这些方法；通常只有几个方法，而且相当简短。
4. 剩下的交给[多重分派][concept-multiple-dispatch]自动处理。
