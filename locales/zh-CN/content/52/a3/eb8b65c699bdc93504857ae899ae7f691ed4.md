# 关于

_“日期和时间不过是我们教给小孩子的东西。这能有多难？”_

许多程序员都犯过这个错误，而随后的经历往往对他们的健康与幸福没什么好处。

任何要用日期和时间做点稍复杂编程的人，至少都该做好准备，去理解并化解潜在的问题。

本文会尝试概览 R 处理日期和时间的方式，但想了解更多细节，还得去查阅完整的文档。

作为一门数据科学语言，日期和时间在 R 中有着特别重要的地位。
很多数据都以时间序列的形式出现：疾病暴发期间每天的患者人数、政府报告的月度就业数据、某个筑巢群落里的鸟类数量、主要经济体的年度 GDP，还有数不清的例子。

_这是否意味着 R 把日期和时间的处理变得很简单？_

可惜，并不是！

Base R 里的日期和时间功能名声不佳，如今大部分都很少有人用了。

[`lubridate`][web-lubridate] 包是一大改进，但你要做好心理准备：它是一个庞大而复杂的库，为的是处理一大类复杂的问题。

`lubridate` 最初是独立的，现在已经并入 `tidyverse` 合集。
用 `library(lubridate)` 或 `library(tidyverse)` 都能加载它。

下面这些资源可以帮你更好地使用 `lubridate`：

- 一个[参考页面][ref-lubridate]。
- 一份 PDF 格式的[速查表][cheat-lubridate]。
- 《R for Data Science》里的[一章][book-dates-times]。

## 日期与日期时间

`date` 就是一个日期，不含任何时间信息。

在内部，日期存储为自 `1970-01-01` 以来的天数（带符号）。

```R
today()
#> [1] "2026-04-22"
typeof(today())  # just a number
#> [1] "double"
class(today())  # the class understands how to interpret the raw number
#> [1] "Date"
```

`datetime` 把日期、时间和时区信息组合在一起。

在内部，它存储为自 1970 年初（UTC 时区）以来的秒数。

```R
now()
#> [1] "2026-04-22 15:37:11 MST"  # mid-afternoon in Arizona
typeof(now())
#> [1] "double"  # again, just a number
# POSIX datetimes are built into most operating systems as standard
class(now())
#> [1] "POSIXct" "POSIXt"
```

也许出乎意料的是，R 并没有针对仅时间值的内部表示。
需要这一功能的人（Exercism 之外）可以安装 [`hms`][ref-hms] 包。

## 处理 `date` 和 `datetime` 值

最常见的日期/时间需求大概是：

- 解析合适格式的输入，构造出日期或日期时间。
- 从日期或日期时间中取出所需的数字或字符串格式。
- 给日期或日期时间值加上一个偏移量。
- 计算两个这样的值之间的时间跨度。
- 获取当前日期（用 `today()`）和/或日期时间（用 `now()`）。

### 从字符串解析

日期和时间的写法五花八门，而且往往因文化而异。
像 “7/6/23” 这样全用数字的日期有歧义、容易让人困惑，还曾在跨国公司里造成过许多代价高昂的错误（_作者对此有痛苦的亲身经历_）。

国际标准（y-m-d）由 [`ISO 8601`][wiki-ISO8601] 定义，有两大优点：

- 解析起来又快又无歧义。
- 排序也很容易，因为日期时间可以当作普通文本，按字母顺序排序。

不过，数据科学就是要处理你能找到的任何数据，抱怨别人怎么格式化数据往往毫无意义。

Base R 有一些转换函数，接受一个格式字符串（默认是 ISO 8601）。

```R
as.Date("2026-04-22")
#> [1] "2026-04-22"
as.Date("4/22/26", format = "%m/%d/%y")
#> [1] "2026-04-22"
as.POSIXct("2026-04-22 15:30:09 MST")
#> [1] "2026-04-22 15:30:09 MST"
```

这些格式字符串与已有几十年历史的 `strptime()` 函数很像，后者被 _许多_ 语言所采用。
熟悉这套语法的程序员可以选择使用 lubridate 中的 [`fast_strptime()`][ref-parse_dt] 函数。

更有用的是，`lubridate` 提供了各种各样的[辅助函数][ref-parsing]，它们的名称表示各字段的顺序。
只要这些函数知道了要查找哪些值、按什么顺序，解析就灵活得令人惊讶。

```R
mdy("4/22/26")
#> [1] "2026-04-22"
mdy("April 22nd 26")
#> [1] "2026-04-22"
mdy("Wednesday, April 22nd 2026")
#> [1] "2026-04-22"
mdy_hm("Wednesday, April 22nd 2026, 4:14 pm")
#> [1] "2026-04-22 16:14:00 UTC"  # defaults to your OS timezone
```

这些辅助函数是 [`parse_date_time()`][ref-parse_dt] 函数的特例，后者把像 `"mdy_hm"` 这样的格式字符串作为它的第二个参数。

### 从数值构造

如果你的程序把日期/日期时间的各个组成部分存成了单独的数字，可以用 [`make_date()` 或 `make_datetime()`][ref-make_datetime] 把它们组装起来。

下面是可以提供的各个组成部分，同时展示了它们的顺序和默认值：

```R
make_datetime(
  year = 1970L,
  month = 1L,
  day = 1L,
  hour = 0L,
  min = 0L,
  sec = 0,
  tz = "UTC"
)
#> [1] "1970-01-01 UTC"

make_datetime(2026, 4, 22, 17)
#> [1] "2026-04-22 17:00:00 UTC"
```

当然，`make_date()` 只接受年、月和日这几个参数。

### 以人类可读的形式输出

R 控制台会自动把日期/日期时间显示成字符串形式。
这通常很方便，但有时会误导人。

在内部，日期和日期时间都是数字（外加几个属性），而不是字符串。
在本该返回字符串的地方返回了日期（时间），就会出问题，所以我们得知道怎么做这个转换。

一个简单的办法是使用 Base R 的 [`as.character()`][ref-ascharacter]，它会输出 ISO 8601 格式的字符串。

还有一个用于日期时间的 [`format_ISO8601()`][ref-iso8601] 函数，它有把结果舍入到指定精度的选项。

```R
today() |> as.character()  # a date
#> [1] "2026-04-23"
now() |> as.character()  # a datetime
#> [1] "2026-04-23 09:07:09.779319"
now() |> format_ISO8601() # defaults to nearest second
#> [1] "2026-04-23T09:07:38"
```

没几个非程序员愿意看到 ISO 8601 格式的输出，所以处理因文化而异的日期/时间格式就很有必要。

Base R 提供了 [`format()`][ref-format] 函数，它使用的格式字符串与许多其他语言中久经考验的 `strftime()` 函数类似。

```R
format(today(), "%A, %d %B %Y")
#> [1] "Thursday, 23 April 2026"
```

Base R 的这种做法虽然难看，但很可靠。
下面是几个比较常用的代码：

代码 | 结果
-- | --
%d | 一个月中的第几天（5、17、28 等）
%a | 星期几的缩写（Mon、Tue、Wed 等）
%A | 完整的星期几（Monday、Tuesday 等）
%w | 星期几的数字（0-6，周日为 0）
%u | 星期几的数字（1-7，周一为 1）
%b | 月份的缩写（Jan、Feb 等）
%B | 完整的月份（January、February 等）
%y | 两位数年份（如 89）
%Y | 四位数年份（如 1989）
%h | 小时（24 小时制）
%m | 分钟
%s | 秒
%z | 与 UTC 的偏移量
%Z | 时区（字符串）

Lubridate 想提供一种更人性化的替代方案，即 [`stamp()`][ref-stamp] 函数，以及范围更窄的 `stamp_date()` 和 `stamp_time()`。

它们接受一个模板字符串，作为期望输出的示例，然后生成一个自定义函数来产生那种格式。

Lubridate 会尝试猜测格式，但常常遇到歧义，给出错误的结果。
要准备好提供格式字符串（比如 “dmy”）来消除歧义。

在 Exercism 上，指定 `locale = "C"` 也很有用，这样可以绕过系统的区域设置，直接以英语工作（测试就是这么期望的）。
区域设置这东西很复杂！

```R
sf <- stamp("Saturday, June 27, 2026 at 14:45", locale = "C")
#> Multiple formats matched: "%A, %B %d, %Y at %H:%M"(1), "Saturday, %Om %d, %Y at %H:%M"(1), "Saturday, %B %d, %Y at %H:%M"(1), "%A, %Om %d, %Y at %H:%M"(0)
#> Using: "%A, %B %d, %Y at %H:%M"

sf(make_datetime(2023, 3, 29, 15, 0, 0))
#> [1] "Wednesday, March 29, 2023 at 15:00"
```

### 设置或提取组成部分

Lubridate 提供了[许多函数][ref-set-get]来获取或设置日期或日期时间的元素：既有 `year()` 和 `second()` 这样显而易见的，也有 `quarter()` 和 `epiweek()` 这样更专门的。

所有这些函数都能用来获取值，其中大多数还能用来设置值。

```R
dt <- now()
dt
#> [1] "2026-04-23 15:47:11 MST"

# get
month(dt)
#> [1] 4

# set
month(dt) <- 11
dt
#> [1] "2026-11-23 15:47:11 MST"
```

对于 `wday()`（星期几）和 `month()`，默认输出的是整数，不过：

- 设置 `labels = TRUE` 会返回一个对应当前区域设置的缩写字符串。
- 再设置 `abbr = FALSE` 则会返回完整的名称。

```R
d <- today()
d
#> [1] "2026-04-23"
wday(d)
#> [1] 5
wday(d, label = TRUE)
#> [1] Thu
#> Levels: Sun < Mon < Tue < Wed < Thu < Fri < Sat
wday(d, label = TRUE, abbr = FALSE)
#> [1] Thursday
#> Levels: Sunday < Monday < Tuesday < Wednesday < Thursday < Friday < Saturday
```

这些标签是 `categorical variables`，它们会是另一个概念的主题。
值的范围限定在列出的 `Levels` 之内，`"dmy"` 同时也体现了排序顺序。

一周默认从周日开始，但可以用 `week_start` 参数改变（周一用 `1`）。

```R
dt <- make_datetime(2026, 4, 23)

# default behavior
wday(dt)
#> [1] 5
wday(dt, label = T)
#> [1] Thu

# set week_start to Monday
wday(dt, week_start = 1)
#> [1] 4
```

还有几个工具函数会返回 `TRUE`/`FALSE` 值，比如 `leap_year()` 和 `dst()`（夏令时是否生效？）。

每个月的天数不一样，`days_in_month()` 会给出对应的整数值。

### 舍入

数字可以用 `round()`、`floor()` 和 `ceiling()` 这样的[函数][ref-round]来舍入。

推而广之，日期和日期时间也有[函数][ref-round_date] `round_date()`、`floor_date()` 和 `ceiling_date()`。

默认是按秒舍入，但用 `unit` 参数还有更多别的选项。
详情和大量示例请见[文档][ref-round_date]。

## 时间跨度

`date` 和 `datetime` 值都表示时间轴上的一个瞬间。

那么像 “昨天的这个时候” 或 “一周之后” 这样的概念该怎么处理呢？

熟悉其他面向科学计算的语言的读者，可能知道 Python 里的 `datetime.timedelta` 或 Julia 里的 `Period` 类型。

相比之下，R 表示时间跨度的方法不少于三种，各有各的长处和局限。
和往常一样，选最适合你场景的那一种。

各种跨度之间可以很方便地互相转换，用 `as.period()`、`as_duration()` 和 `as.interval()` 即可。

可以用 `is.period()` 之类的函数来查询跨度的类型。

### 周期

一个 `period`，比如 `hours(3)`，可以把时钟时间增加 3 小时。

夏令时（DST）之类的不规则情况基本会被忽略。

所有周期都是单位名称的复数形式：`years`、`weeks` 等。

```R
d <- today()
d
#> [1] "2026-04-25"

d + weeks(2)
#> [1] "2026-05-09"

# dates are coerced to datetimes at midnight if necessary
d - hours(20)
#> [1] "2026-04-24 04:00:00 UTC"

hours(3)
#> [1] "3H 0M 0S"
```

### 时长

一个 `duration`，比如 `dhours(3)`，会增加 3 小时的真实时间，并且会顾及 DST 这类让时钟时间偏离真实时间的不规则情况。

所有时长都是在对应周期前面加 `d` 前缀：`dyears`、`dweeks` 等。

```R
dhours(3)
#> [1] "10800s (~3 hours)"
```

### 区间

一个 `interval` 由起始时间和结束时间组合而成，可以用 [`interval()`][ref-interval] 函数创建，也可以用 `%--%` 中缀运算符创建。

```R
# the next 2 lines were run about 33s apart, so now() is different
dt1 <- now()
dt2 <- now() + hours(1)

# interval(0 function)
ivl <- interval(dt1, dt2)
ivl
#> [1] 2026-04-24 16:24:54 MST--2026-04-24 17:25:27 MST
class(ivl)
#> [1] "Interval"
attr(,"package")
#> [1] "lubridate"

# infix operator
iv2 <- dt1 %--% dt2
iv2 == iv1
#> [1] TRUE

# conversions
as.period(ivl)
#> [1] "1H 0M 32.738214969635S"
as.duration(ivl)
#> [1] "3632.73821496964s (~1.01 hours)"

# components
int_start(ivl)
#> [1] "2026-04-24 16:24:54 MST"

# is datetime within the interval?
(now() - minutes(20)) %within% ivl
#> [1] TRUE
```

## 时区

处理时区可能相当棘手。
下面这句话出自 Python 文档，但对 R 同样适用：

> “世界各地调整时间的规则，与其说是理性的，不如说是政治性的，而且经常变化；除了 UTC 之外，没有任何标准适合所有应用。”

关于时区，有几点需要注意：

- 一个 `datetime` 总是包含时区（`tz`）；而 `date` 不感知时区。
- 日期时间构造函数一般默认使用 [UTC][wiki-UTC]。
- [`now()`][ref-now] 函数是个例外：它从系统时钟获取你的本地时间，包括 `tz`。
  默认使用本地 `tz`，但也可以指定其他时区，比如 `now("UTC")`。

```R
# timezone defaults to UTC
local <- ymd_hm("2026-04-25 10:32")
local
#> [1] "2026-04-25 10:32:00 UTC"

# timezone can be specified
AZ <- ymd_hm("2026-04-25 10:32", tz = "America/Phoenix")
AZ
#> [1] "2026-04-25 10:32:00 MST"

# same clocktime, different tz
local - AZ
#> Time difference of -7 hours
```

在与时区相关的运算中，用时长比用周期更可靠。

```R
dt <- make_datetime(2020, 10, 31, 12, tz = "Europe/Helsinki")

# EET is 2h ahead of UTC
dt
#> [1] "2020-10-31 12:00:00 EET"

# A week earler, EEST (summer time) is 3h ahead of UTC

# a 7-day period => midday
dt - days(7)
#> [1] "2020-10-24 12:00:00 EEST"

# a 7-day duration => 1 pm
dt - ddays(7)
#> [1] "2020-10-24 13:00:00 EEST"
```

无论是周期计算还是时长计算，lubridate 都能识别从东欧时间到东欧夏令时的切换，但只有时长会针对这 1 小时的时间变化做出调整。

处理日期和日期时间，用 lubridate 通常比用 Base R 轻松得多。

这个概念已经尽力给出一个概览，但不可避免地会漏掉很多细节。
