# 关于

Factor 把流的输入输出分成两层。下层是*显式流* API：每个词都把流当作实参传入。上层是*环境流* API：简短的一行词，作用于当前绑定的那个流。两层都建立在同一个[协议][stream-protocol]之上，上层的词只是查出环境流，然后把调用转发过去。

## 显式流的词

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents`会把流里的内容全部读完；`stream-lines`也会读完，并按行边界拆分；`stream-readln`每次返回一行（到达流末尾时返回`f`）。

## 环境流的词

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

这些是日常使用的 I/O 词。它们会从动态变量`input-stream` / `output-stream`中查出当前的输入流或输出流，然后转发调用。正因如此，要把`print`重定向到字符串，只需在某个代码块执行期间绑定`output-stream`即可。

## 自带的流构造函数

| 词              | 词汇表                | 构建出的内容                  |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | 读取字符串字面量          |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | 把写入的内容收集成一个字符串   |
| `<file-reader>`   | [`io.files`][io.files]           | 按指定编码读取文件   |
| `<file-writer>`   | [`io.files`][io.files]           | 按指定编码写入文件  |

这四个词都会创建可释放对象：它们扩展了来自`destructors`的`disposable`，因此下面的`with-…`组合子会在退出时释放它们。

## 作用域绑定

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

每个词都会打开一个流，把它绑定为内层代码块的环境输入流或输出流，并在退出时释放它，即使代码块抛出异常也不例外。它们是`boatswains-bilge`的析构组合子，专门用于流。

`with-string-writer`是一个特别干净的变体：它会自动创建一个新的`<string-writer>`，以这个 writer 作为环境输出流来运行代码块，最后返回累积得到的字符串。“捕获代码块输出”这整套模式，用一个词就够了。

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## 为什么需要环境流？

动态变量绑定正是`print`能在一个不知道自己是以交互方式运行、是写入日志文件、还是写入被捕获的测试缓冲区中的程序里也正常工作的原因。只要把绑定替换一次，所有调用`print`的词都会做正确的事，不需要重新接线。这就是上层为你带来的反转。

如果要*实现*一个流，也就是定义自己的类来接入这个协议，请看`streams`概念（在`telegraphers-tape`中讲解）。
