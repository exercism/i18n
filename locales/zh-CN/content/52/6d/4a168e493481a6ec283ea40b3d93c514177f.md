# 说明补充

## 重构

`Markdown.roc` 里的实现已经能通过测试了。
在保持其行为和 `parse : Str -> Try(Str, _)` 接口不变的前提下重构它。
成功时返回 `Ok(html)`，出现解析错误时用 `Err(...)` 向上传递。
本练习只涉及 Markdown 的一个小子集，而不是完整的 Markdown 规范。
需要保持的行为由测试来定义，包括空行和未配对的强调标记该如何处理。

留意重复的逻辑、嵌套过深的条件、含义不明的命名，以及不必要的可变状态。
可以考虑把行的分类、行内强调和 HTML 渲染拆分开来。
如果你想用，[`roc-parser` 包](https://github.com/lukewilliamboswell/roc-parser)在测试应用里已经以 `parser` 的名字提供好了。
`Parser.one_of`、`Parser.many` 和 `Parser.between` 可以帮助你把小的解析器组合起来。
用普通的字符串和列表函数写出的解答也同样欢迎。
