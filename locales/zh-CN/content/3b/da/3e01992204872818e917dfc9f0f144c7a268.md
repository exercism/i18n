# 代码包含

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

`include`会把另一个类的代码复制到当前类中。它是编译期操作，没有运行时开销，也不产生运行时关系：之后两个类之间没有任何联系。

## 子句

```
   include CLASS  old_name -> new_name , old_name -> ;
```

每一项重命名一个特性。`-> ;`后面不写新名字，就是把它排除在外。没有提到的内容都原样引入。

重命名影响的是*外部*看到的名字。被包含的例程之间互相调用仍然正常：如果 `describe`调用了 `count`，而 `count`被重命名为 `beats`，那么 `describe`调用的就是 `beats`。

## 一次包含多个

```sather
   include WARM_UP;
   include COOL_DOWN;
```

这是允许的，也是 Sather 实现其他语言所说的多重继承的方式，而且没有常见的麻烦，因为冲突是编译错误，解决办法就是重命名或者排除其中一个。没有什么靠你需要记住的优先级顺序来化解。

## private include

```sather
   private include WARM_UP;
```

把代码引入供本类自己使用，而不对外暴露。当你想要的是实现而不是接口时，这很有用。

## 两者结合

一族类常用的形态：

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

`< $ACT`说明它能做什么；`include ACT_BASICS`提供了一部分怎么做。改主意换了做法，`<`也不会动。

## 为什么这样设计

抽象类没有代码，所以不会被意外继承，也不会存在那种行为会在你脚下悄悄改变的父类。复用是编译期进行的复制，来自你明确指定的类，每一次重命名都白纸黑字写下来。

代价是，每个类都必须显式地请求复用。这就是取舍：多打点字，但没有任何隐式的东西。
