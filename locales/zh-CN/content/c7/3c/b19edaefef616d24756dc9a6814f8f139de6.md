## 元组

[元组][tuple]常用来把信息组合在一起。它和数组不同，大小是固定的，而且可以存放不同的数据类型。
元组使用花括号`()`创建，常用来从一个函数返回多个值。

```haskell
tuple = (1, "abc", False)
```

当你需要存储二维空间中的坐标时，这就很有用：你知道这个元组永远有两个元素，也就是 x 坐标和 y 坐标。

```haskell
coordinate = (3, 4)
```

### 访问元素

你经常会处理简短的元组，这时可以用`fst`和`snd`函数来访问其中的元素。

```haskell
x = fst coordinate
-- x = 3
y = snd coordinate
-- y = 4
```

## 模式匹配

编写 Haskell 函数时，我们可以借助[模式匹配][pattern-match-doc]，采用一种[断言式风格][assertive-style]：
模式匹配是 Haskell 一个非常强大的特性，它让你可以匹配数据构造器，并把变量绑定到其中的值。
顾名思义，我们做的就是拿值去和模式匹配；如果值匹配上了模式，就可以把变量绑定到模式内部的值。
模式匹配主要建立在这些概念之上：识别值、绑定变量，以及拆解值。

以这个函数为例：

```haskell
lucky :: Int -> String
lucky 7 = "Lucky number seven!"
lucky x = "Sorry, you're out of luck, pal!"
```

这里有一个函数`lucky`，它接收一个`Int`，返回一个`String`。
我们为这个函数定义了两个模式：一个匹配数字`7`，另一个匹配其他任何数字。这个名字可以是任何内容（只要符合 Haskell 的命名规范），不过我们在这里用了`x`。
如果数字是`7`，函数会返回`"Lucky number seven!"`；否则会返回`"Sorry, you're out of luck, pal!"`。
这里要注意的是，模式是从上到下依次检查的，所以如果我们把两个模式的顺序调换一下，函数就会总是返回`"Lucky number seven!"`。

### 数组模式

一种非常常见的模式是匹配数组，也就是取出数组的头部和尾部。
这是因为数组本质上是一个链表。
下面是一个返回数组头部和尾部的函数示例：

```haskell
headAndTail :: [Int] -> (Int, [Int])
headAndTail [] = error "Can't call head on an empty list"
headAndTail (x:xs) = (x, xs)
```

这里有两个模式：一个匹配空数组，另一个匹配至少有一个元素的数组。
因为如果数组是空的，我们必须为这种情况留一个分支，否则就会遇到运行时错误。
如果数组不为空，我们可以把数组的头部匹配到`x`，把尾部匹配到`xs`。
这是通过`:`（cons）运算符实现的，它用来把一个元素添加到数组的最前面。
但在模式匹配中，它让我们能把一个数组拆解成头部和尾部，某种程度上算是反着来。

`xs`是数组尾部常见的命名，它强调这是一个数组。如果你处理的是嵌套数组，可以用`xss`来强调这是一个“数组的数组”。

### 元组模式

和数组一样，我们也可以匹配元组。
下面是一个接收元组、返回第一个和第二个元素的函数示例：

```haskell
sumTuple :: (Int, Int) -> Int
sumTuple (x, y) = x + y
```

这里的模式匹配一个有两个元素的元组，第一个元素绑定到`x`，第二个元素绑定到`y`。

### 通配符模式

有时我们并不关心某个变量的值，只想匹配模式。
这时就要用到通配符模式，它用下划线`_`表示。

下面是一个返回数组第一个元素的函数示例：

```haskell
head' :: [Int] -> Int
head' [] = error "Can't call head on an empty list"
head' (x:_) = x
```

这里我们表示不需要数组的尾部，于是用通配符模式把它忽略掉。

### 类型模式

我们也可以匹配类型，方法是使用该类型的构造器。
我们同样可以从类型中提取值，就像处理元组时那样。

```haskell
data AccountType = Guest | User String 

greet :: AccountType -> String
greet Guest = "Welcome, guest!"
greet (User name) = "Welcome, " ++ name ++ "!"
```

在第一个模式中，我们匹配`Guest`构造器；在第二个模式中，我们匹配`User`构造器，并把其中的值绑定到`name`。
