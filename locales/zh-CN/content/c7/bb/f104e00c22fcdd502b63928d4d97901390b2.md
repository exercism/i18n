# 简介

和大多数编程语言一样，Julia 提供了丰富多样的集合类型。

有些集合天然就是有序的（包括 `Vectors` 和更高维的 `Arrays`），我们可以按位置访问其中的元素。另一些集合是无序的（`Sets`、`Dicts`），元素必须通过键或值来访问。

最简单的情况：假设有一个由 `Ints` 组成的 `Vector`，我们想按升序对它排序。

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

很简单！
`sort()` 函数名字一目了然，看起来会返回排好序的 `Vector`。

_开个玩笑！_
学到教学大纲的这个阶段，你也许已经（正确地）猜到，其中还有一些细微之处需要我们讨论。

## 会修改输入的函数与不修改输入的函数

运行 `sort(v)` 之后，`v` 是什么？

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

原来的数组没有变。
`sort()` 是一个***不修改输入***的函数，它返回输入的一个_副本_。

在很多场景下，这是很好的设计：我们得到一个纯函数，它的行为很容易推断，即使在并行、分布式的代码中也是如此。

另一方面，假设有一个包含 10 亿个字符串的数组，我们想对它排序。

排序很可能很慢。
此外，我们还需要复制全部内容（_很慢！_），并分配足够的内存（_好几 GB！_）来存放这份副本。

比较一下这段非常相似的代码：

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

现在，输入的 `Vector` 会在原地排序，不需要复制，但原来的顺序也会永久丢失。

这样做可能很高效，也可能埋下 bug、带来意料之外的副作用，还可能让阅读你代码的人感到困惑。
_请谨慎选择！_

`sort!()` 是一个“修改输入的函数”。按照（_非常强_）的约定，任何会修改输入的函数都要在名字后面加上 `!`，用来提醒程序员。

## 排序索引数组

如果要排序的元素是很大的对象，那么用它们的位置下标来处理可能更方便。

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

因为 `langs` 是一个 Vector，所以每个下标都是 `1:length(langs)` 范围内的一个整数。
`sortperm()` 的输出就是这些整数的一个排列，对应着对输入数组排序的结果。
