# 说明补充

## `from_quote`的优缺点
本练习在`Time`类型中定义了一个`from_quote`函数。这样就可以写出这样的代码：

```roc
time : Time
time = "00:01:23"
```

这段代码会在编译时隐式调用`Time.from_quote("00:01:23")`。这样有可能加快程序的速度，因为它不需要在运行时处理解析；同时，它还能确保被`from_quote`拒绝的时间值在编译时就被捕获，而不是等到运行时。而且，它让代码既美观又易读。例如，下面是本练习中的一个测试：

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

不过，读这段代码的人可能会以为`advance_time`函数接受的是`Str`，而实际上它接受的是`Time`。这可能会导致困惑和错误。因此，你可能更倾向于稍长但更明确的写法：`"00:00:05".Time`，它同样会在编译时调用`from_quote`。

在你自己的程序里，也许更愿意改用`from_str`：

```roc
Time := { ... }.{
    from_str : time_str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

你也可以在编译时调用`from_str`（或其他任何纯函数），像这样：

```roc
Ok(time) = Time.from_str("00:01:23")
```

注意：把这个定义放在顶层会让它在编译时运行（因为该函数是纯函数，且它的输入在编译时就是已知的）。在函数内部，你可以在运行时使用`from_str`。
