# Nil

Crystal 有一个叫做[`Nil`][nil]的类型，它只能有一个值：`nil`。
它用于表示值的缺失，也类似于其他语言中的`null`或`None`。

方法可能返回 Nil 值，例如[`String#[]?`][string-index]，当索引越界时它会返回`nil`。

```crystal
"foo"[10]? # => nil
```

Crystal 有所谓的**空引用检查**，也就是说，所有类型默认都不可为`nil`。
这意味着，除非你显式地把变量声明为`Nil`类型，否则就不能给它赋值`nil`。
反过来，这也意味着编译器会自动检查空引用。

## 假值

处理`nil`值有几种办法。
`nil`和`false`一样，都是[假值][truthy-falsey]。
这意味着，在语句以及其他需要假值或真值的地方，`nil`都会被当作`false`来处理。

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

这意味着，如果一个可为 nil 的变量的值是`nil`，就不会进入真值分支。

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## 检查是否为 nil

Crystal 有一个方法可以用来检查某个值是否为`nil`。
它叫做[`nil?`][nil?]，所有对象都可以使用它。

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

直接在`if`语句中使用这个值时，情况会稍有不同：在前面的例子里，`false`和`nil`都会被当作假值。
而这里只有`nil`会被当作假值，因为如果它的值是`false`，那它就不是 nil，从而会是真值。

## 或运算符

处理`nil`值最简单的办法，就是一开始就保证它不会变成`nil`。
或运算符（[`||`][or]）常用于处理`Bools`，但只要理解正确，它也可以用来处理`nil`值。
或运算符会检查第一个值是否为真值，如果不是，就使用第二个值。
利用这一点，如果值是`nil`，它就会被当作假值，从而使用第二个值。

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
这种做法应该被视为最后的手段，只有在你**确信**该值不是 nil 时才使用。
如果可能，请改用其他方法。
~~~~

[`not_nil!`][not_nil]这个方法可以让你告诉编译器某个值不是 nil，从而让它所持有的类型不可能是 nil。
它的做法是：如果值是 nil，就抛出异常。

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
