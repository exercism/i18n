# 构建测试运行器

测试运行器是一种至关重要的工具，它可以让：

- 网站自动验证一次迭代是否通过了所有测试。
- 学生使用[浏览器内编辑器](/docs/using/solving-exercises/using-the-online-editor)来做练习（[不需要 CLI](/docs/using/solving-exercises/working-locally)）。

要开始构建测试运行器，请查看[从零开始创建测试运行器](/docs/building/tooling/test-runners/creating-from-scratch)文档。

## 实现

赛道的工具通常（基本上）都是用赛道自己的语言编写的。

```exercism/caution
虽然你可以自由使用其他语言，但每增加一种语言，都会让赛道的维护和贡献变得更困难。
因此，我们建议尽可能使用赛道自己的语言，因为这样维护和贡献起来都会更容易。
```

## 部署

测试运行器会打包为 [Docker 容器](/docs/building/tooling/docker) 并运行。
测试运行器的 Docker 镜像会通过 [GitHub Actions 工作流](https://github.com/exercism/generic-test-runner/blob/main/.github/workflows/docker.yml) 自动部署。

## 测试

测试运行器构建好之后，你可以在赛道的 CI 配置中使用它的 Docker 镜像，来验证赛道里的练习。
这种做法的主要好处是，它能更好地模拟生产环境的配置；换句话说，你可以更确信这些内容在生产环境中也能正常工作。
一个可能的缺点是，它可能会拖慢 CI 工作流。
作为维护者，由你来决定哪种做法最适合你的赛道。
