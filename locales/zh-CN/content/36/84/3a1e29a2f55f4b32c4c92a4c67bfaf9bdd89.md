# 关于

## 部分应用

Elm 中的所有函数都是[柯里化的][currying]，也就是说，如果你调用函数时没有传入全部实参，它会返回一个新函数。

这样做的结果叫做[部分应用][partial-application]（你没有把全部实参都传给函数，而是只应用了其中一部分）。

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

部分应用总是按顺序应用实参。

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## 管道运算符（`|>`）

`x |> f`和`f x`完全一样。一个具体的例子是，`"5" |> String.toInt`和`String.toInt "5"`相同。

乍一听这似乎没什么用，但它被称为[管道运算符][pipe-operator]，因为它能让你写出“管道式”的代码。

举个例子，假设我们有一个 sanitize 函数，用来把用户输入转换成整数：

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

我们可以把它改写成这样：

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

这样就避免了使用括号，并且按函数被应用的顺序来展示它们（先是 `String.trim`，然后是 `String.toInt`），有助于提升可读性。

还有一个[反向管道运算符`(<|)`][reverse-pipe-operator]。
`x <| f`和`f x`完全一样。
乍一看它似乎也没什么用，而且使用频率肯定远不如管道运算符，但在某些情况下能帮你避免使用括号。

## 函数组合 / 无参风格

[`(>>)`][forward-composition]运算符的类型是`(a -> b) -> (b -> c) -> (a -> c)`，它通过组合两个类型兼容的函数（`a -> b `和`b -> c`），创建一个类型为`a -> c`的函数。
它的做法是：取第一个函数的输出（类型为`b`），把它用作第二个函数的第一个实参（后者必须具有相同的类型`b`）。
创建出来的函数会接收与第一个函数相同的输入（类型为`a`），并返回第二个函数返回的那个`c`。

一个具体的例子是`String.trim >> String.toInt`。
`String.trim`只接收一个字符串作为形参，所以创建出来的函数接收的也是它。
`String.toInt`返回一个`Maybe Int`，所以创建出来的函数返回的也是它。
`String.trim`返回一个`String`，而`String.toInt`把它作为形参接收，所以这个例子能通过编译。

现在我们可以把`sanitize`函数改写成下面这样：

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

注意，虽然功能完全相同，我们不再使用最初那个例子里的`input`形参。
这种不引用自身形参来创建函数的方式叫做“无参风格”。
这种风格的优点是代码更简洁，缺点是可能更难理解，对初学者尤其如此。

值得一提的是，Elm 中所有函数都是柯里化的，所以`String.length >> max`能通过编译，结果是：

- 一个函数（1），它有一个字符串形参（`String.length`的输入）
- `max`是一个有两个`Int`形参的函数，但函数 1 只向它传入一个`Int`（`String.length`的返回值），所以`max`被部分应用了。
- 部分应用后的`max`函数的返回值是另一个函数（2），它接收一个`Int`，并返回这个`Int`与`String.length`提供的那个`Int`中的较大值
- 因此，函数 1（`String -> Int`）返回函数 2（`Int -> Int`）
- 所以`((String.length >> max) "123") 2`返回`3`，因为`"123"`的长度是 3，比`Int`实参中的 2 大。

## 函数设计

为了在 Elm 中轻松写出优雅的代码，你应该把主要数据结构作为函数的最后一个形参。
标准库中所有常用函数都这么做，比如`List.map`（类型签名如下）。

```elm
map : (a -> b) -> List a -> List b
```

可以看到，`map`函数的最后一个形参是`List a`，它返回`List b`，所以主要数据结构（`List`）就是最后一个形参。

这样就可以写出优雅的管道式代码，如下所示。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

这也让使用函数组合和无参风格变得很方便，作为管道写法之外的另一种选择。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

函数组合还能让你把这个例子简化为对`List.map`的一次调用。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
