# 简介

## 无分支代码

条件语句这个概念介绍了 `jcc`，即根据条件进行分支的一族指令。
只有满足自身条件时，`jcc` 才会把执行转移到程序中的另一个位置。

不过，现代 CPU 速度很快，能够并行执行许多指令。
如果为了让 CPU 在运行时检查某个条件而让所有工作都停下来，代价就太高了。

所以，CPU 在内部并不会等待。
它使用**分支预测器**来猜测某个条件的结果，并开始_推测性地_执行预测的那条路径。

如果预测正确，执行就会像没有分支一样继续下去。
但如果预测错了，CPU 就必须_丢弃预测路径上已完成的工作_，改从正确的路径重新开始。

这叫做**分支预测错误**，代价很高，会带来延迟。

当一条分支难以预测时，这些预测错误就会不断累积。
在这种情况下，有时最好完全避开分支，让同一批指令无论条件如何都执行。
不借助 `jcc` 就在多个值之间做出选择的代码，称为**无分支**代码。

有多种组织代码的方式，可以让分支出现得更少，或者让已有的分支更容易预测。
其中，x86-64 提供的两族指令常用于编写无分支代码。

### 条件传送

指令族 `cmovcc` 只有在满足特定条件时，才会把源操作数复制到目标操作数。
否则，目标操作数保持不变。

`cc` 后缀的命名与 `jcc` 相同，含义也相同：

| 指令        | 满足以下条件时传送                   |
|-------------|--------------------------------------|
| `cmove`     | 执行 `cmp A, B` 后 A == B            |
| `cmovne`    | 执行 `cmp A, B` 后 A != B            |
| `cmovl`     | 执行 `cmp A, B` 后 A < B（有符号）   |
| `cmovb`     | 执行 `cmp A, B` 后 A < B（无符号）   |
| `cmovg`     | 执行 `cmp A, B` 后 A > B（有符号）   |
| `cmova`     | 执行 `cmp A, B` 后 A > B（无符号）   |

规则与 `jcc` 类似：

1. `l` 和 `g` 用于有符号比较，`b` 和 `a` 用于无符号比较。
2. 在后缀中加上 `e`，表示包含相等的情况。
3. 加上 `n` 则对条件取反。
4. 还有一些变体是根据标志位是否置位来判断的。
   例如 `cmovz` 和 `cmovc`。

考虑对一个放在 `rdi` 中的有符号整数取绝对值，结果返回在 `rax` 中。
用 `jcc` 来写，函数会在两条路径中选择一条：

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

用 `cmovcc` 来写，两个候选值都会无条件算出来，再由条件传送挑出其中一个：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

无分支版本始终执行同一批指令。
没有 `jcc` 需要预测器去猜。

`cmovcc` 的目标操作数必须是寄存器。
源操作数可以是寄存器或内存位置，但不能是立即数。

~~~~exercism/note
在上面的代码中，`neg` 指令会根据结果设置多个标志位，其中包括符号标志（SF）。
这意味着 `cmp rdi, 0` 可以完全删掉：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

当 `rdi` 为正数时，`neg` 产生负数结果，SF == 1，于是 `cmovs` 把 `rdi` 恢复回来。
当 `rdi` 为零或负数时，`neg` 产生非负结果，SF == 0，于是 `rax` 保留取负后的值（这正是正确的绝对值）。

虽然在汇编代码中 `cmp` 是比较值的主要方式，但许多指令也会根据自身的结果设置标志位。
一条指令会影响哪些标志位，完整列表通常列在它的[参考手册][reference]中。
具体到 `neg`，这些标志位是 SF、ZF、CF、OF 和 PF。

[reference]: https://www.felixcloutier.com/x86/
~~~~

### 条件设置

指令族 `setcc` 在满足特定条件时把目标操作数设为 `1`，否则设为 `0`。
目标操作数始终是_8 位操作数_。

`cc` 后缀的命名与 `jcc` 和 `cmovcc` 相同。
例如，如果 `ZF == 1`，`setz` 会把目标操作数设为 `1`，否则设为 `0`。

由于目标操作数是 8 位的，当需要更宽的值时，通常会在 `setcc` 后面接一条 `movzx`：

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

这是把比较结果转成整数 `0` 或 `1` 的常见写法。
