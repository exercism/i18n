# 关于

## 复合类型

在我们的程序里，定义自定义类型往往很有用。

创建新的原始类型是可行的，但很少这么做。内置的[原始类型][primitive]并不是随意选定的：它们与 Julia 用于 JIT 编译的 LLVM 编译器中的标准类型高度一致。

而更有用的，是能够定义带有命名字段的[复合类型][composite-types]。

其他语言也有类似的东西，把它们叫做`structs`或`records`。Julia 文档把它们称为`composite types`，不过（略有出入的是）这门语言的语法用`struct`关键字来定义它们。

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

上面的例子中有几点值得注意：

- 没有为`id`指定类型，因此编译器将其解释为`id::Any`。
  - **注意：**在实践中，最好为字段指定具体类型，以帮助编译器。
  - 我们会在[后面的概念][parametric]中看到，使用参数是另一种选择。
- 类型名被用作构造函数，如`Person(id, name, age)`，用来得到一个`Person`类型的实例。
- 可以用点号访问各个字段，和[具名元组][named-tuple]一样。

`Person`类型的项是不可变的，因此不允许更新。

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

如果需要可变性，就在定义中加上`mutable`。

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

默认情况下，构造函数要求字段按定义中的顺序出现，对于更复杂的类型来说这就不太方便了。

使用`@kwdef`宏带来了两项新能力：

- 构造函数使用关键字，而不是位置。
- 字段可以有默认值，并且可以选择在构造函数中省略。

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## 复合类型层级

到目前为止，我们只创建了具体的复合类型。检查一下就会发现，它们都是`Any`的子类型。

创建多个相关类型时，为它们定义一个层级结构通常更合理。这做起来非常简单。

首先，创建一个抽象类型：

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

接下来，在类型定义中加入`<:`运算符，来表示这种关系。

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

按需要重复，记住不允许对具体类型进行子类型化。

对于更复杂的层级，按需创建抽象子类型。

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

当我们讲到`Multiple Dispatch`概念，并看到函数如何处理实参类型时，这种层级结构的价值就会更清楚。


## 内部构造函数

在本概念开头我们看到，类型名被用作构造函数，用来创建该类型的项：

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)
```

这里，`Person()`被称为`outer constructor`。字段类型会被检查是否与类型定义兼容，必要时会报错。

假如我们想对传入的_值_施加约束，而不只是对_类型_，该怎么办？

那么可以在类型定义内部加入`inner constructor`，来执行相应的检查。

例如，我们有一个抽象类型`AbstractPoint`，打算用来表示`(x, y)`坐标，但希望有一个带`y > x`约束的子类型。

```julia-repl
julia> abstract type AbstractPoint end;

julia> struct Point <: AbstractPoint
           x::Integer
           y::Integer
       end;

julia> struct ConstrainedPoint <: AbstractPoint
           x::Integer
           y::Integer
           
           ConstrainedPoint(x, y) =
               y > x ? new(x, y) : @error("require y > x")
       end;
       
julia> Point(3, 2)
Point(3, 2)

julia> ConstrainedPoint(3, 2)
Error: require y > x

julia> ConstrainedPoint(3, 5)
ConstrainedPoint(3, 5)
```

`new()`函数_只能_用在内部构造函数中，如果输入被判定为有效，它就会返回所要的项。

对于无效输入，我们可以像例子中那样，以一条错误信息终止。或者，你可能更愿意使用`nothing`或`missing`这样的占位符。关于这些内容的更多信息，请参阅[`Nothingness`][nothingness]概念。
