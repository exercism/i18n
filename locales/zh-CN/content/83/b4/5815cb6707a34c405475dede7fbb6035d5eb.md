# 关于

标量代码依赖各种指令设置的标志位，根据特定条件进行分支。但打包值表示的不是一个值，而是并行的多个值。同一个条件可能在某个通道上不成立，在另一个通道上却成立。

这就是 SIMD 代码默认[无分支][branchless-code]的原因。

打包比较通常不依赖标志位，而是生成一个**掩码**写入目标操作数。对于每个通道，条件成立时比较会用 1 填满整个通道，不成立时则用 0 填满。按有符号整数读取时，条件成立的通道值为`-1`，不成立的通道值为`0`。

然后就可以用[按位运算][simd-bitwise]组合这个掩码，筛选出特定的通道。

## 打包比较

标量`cmp`是通用的，因为它一次会设置多个标志位。随后另一条指令可以读取这些标志位，用来分支或执行计算。

但打包比较既检查条件又计算掩码，所以它不是通用的。必须把要测试的确切条件交给比较指令。

有两种做法：

- 整数比较把条件作为后缀：`eq`表示相等，`gt`表示大于。其他变体则通过组合其中一种的结果来构造。
- 浮点比较把条件编码在立即数中。这个立即数的不同取值，对应不同的测试条件。

除了整数比较要使用特定的条件后缀之外，语法结构与我们已经见过的一样：

- 整数：`p` + `cmp` + 条件 + 大小（`b`、`w`、`d`或`q`）。
- 浮点数：`cmp` + `p` + 大小（`s`或`d`）。条件作为额外的操作数通过立即数传入。

### 整数比较

如前所述，整数比较只有相等和大于两种：

| 指令                                | 说明                      |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | 逐通道相等                |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | 逐通道**有符号**大于 |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

要构造小于比较，把操作数交换后使用`gt`：`a < b` == `b > a`。

注意，比较是**有符号**的。要进行无符号比较，把两个操作数的最高位取反。这可以用一个只有最高位为 1 的掩码做异或来实现。

~~~~exercism/note
有两个好用的惯用法：

1. 把寄存器与自身异或，得到全零。
2. 把寄存器与自身比较，得到全一。

例如：

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

全零和全一是常见的掩码，分别用来表示“处处为假”和“处处为真”。它们也可以用来表示打包的`0`或打包的`-1`，这是常见的哨兵值。例如，标记字符串结尾的 NUL 就是一个`0`。
~~~~

### 浮点比较

浮点通道采用另一种形式：只使用一条指令`cmpps`（64 位通道则为`cmppd`），把条件作为立即数传入：

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM 还提供了一些伪指令，它们会映射到正确的立即数，也更容易记住。在下面所有用法中，`px`中的`x`可以是`s`（32 位浮点数）或`d`（64 位浮点数）：

| 伪指令    | 立即数 | 比较             |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a is NaN or b is NaN   |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | neither a nor b is NaN |

~~~~exercism/caution
NaN 的比较是无序的：它既不小于、不等于也不大于任何值，包括它自己。有序谓词（如`cmpltps`）在任一操作数为 NaN 时结果为假，而无序谓词的结果为真。这正是`cmpordps`和`cmpunordps`存在的原因：用来显式测试 NaN。
~~~~

## 用掩码进行选择

掩码编码了一个条件的结果。然后就可以按照这个条件，逐通道地在两组值之间做选择：掩码成立时从一组值里取该通道，不成立时从另一组值里取：

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

这个模式是无分支选择的打包形式。每个通道都会被计算，由掩码单独决定哪个值留下来，全程没有`jcc`。

## 专用的混合指令

有些指令可以直接完成同样的选择，它们从掩码寄存器中为每个元素读取一位。这类指令称为**混合**指令：

| 指令 | 元素     | 掩码来源     |
|-------------|-------------|-----------------|
| `pblendvb`  | 字节        | 隐式`xmm0` |
| `blendvps`  | 32 位通道 | 隐式`xmm0` |
| `blendvpd`  | 64 位通道 | 隐式`xmm0` |

注意，第一条指令遵循整数语法，而另外两条遵循浮点语法。不过，由于这些指令只是选择原始字节，它们中的任何一条都可以同时用于整数和浮点数。

对于每个元素，当对应掩码元素的最高位为 0 时，混合指令保留目标操作数；该位为 1 时则取源操作数。只查看那个**最高位**，而比较掩码正好满足这一点，因为它的通道要么全一，要么全零。掩码寄存器始终是`xmm0`，它是隐式的：

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

也可以用`pblendvb`为任意其他大小从比较掩码中选择通道。由于条件成立的通道中所有字节都是全一，`pblendvb`会把它们全部选中。

~~~~exercism/note
这些指令都在所执行的操作（`blend`）后面加上`v`。这个`v`代表 _variable_（可变），因为这种选择不是静态的：它取决于某个寄存器。

也有不带`v`的变体，它们根据立即数进行选择。它们遵循同样的模式：如果立即数的第`i`位为 1，就选中通道`i`。
~~~~

## 从掩码回到标量

SIMD 代码虽然强大，却缺少标量代码的许多灵活性。在很多情况下，需要从打包寄存器回到标量指令的世界。

`movmsk`系列指令充当两个世界之间的桥梁。这些指令把每个通道的**最高位**提取到一个通用寄存器中：

| 指令 | 收集内容                     | 结果宽度 |
|-------------|-----------------------------|--------------|
| `pmovmskb`  | 16 个字节各自的最高位 | 16 位      |
| `movmskps`  | 4 个双字各自的最高位 | 4 位       |
| `movmskpd`  | 2 个四字各自的最高位 | 2 位       |

如果在比较之后使用，每个置位的比特代表一个条件成立的通道，每个清零的比特则代表一个条件不成立的通道。然后就可以像平常一样用标量指令处理这个结果。例如，`popcnt`可以统计匹配的个数，`tzcnt`可以找出第一个匹配的位置。

通用寄存器可以是 32 位或 64 位宽。

## 测试整个向量

标量指令`test`也有一个打包变体：`ptest`。

它与对应的标量指令类似，会对两个操作数执行 AND 运算，但不修改它们。与`test`不同，`ptest`还会执行 ANDN 运算，对第一个操作数取反。

因此，可以把`ptest`看作`pand`和`pandn`的非破坏性版本，它会根据结果设置标志位。与这两条指令很像，`ptest`把整个 SIMD 寄存器当作一个通道，因此不接受大小前缀。

如果 AND 运算的结果为`0`，就会置位`ZF`；如果 ANDN 运算的结果为`0`，置位的则是`CF`。这意味着可以用`ptest`同时检查全一掩码和全零掩码：

1. 对寄存器自身使用`ptest`，只有当该寄存器全零时才会置位`ZF`。这与常见的标量惯用法相同：对寄存器自身使用`test`来检查是否为`0`。
2. 把寄存器与全一掩码一起使用`ptest`，只有当该寄存器全一时才会置位`CF`。另外，只有当该寄存器全零时它才会置位`ZF`，因此可以一次检查两种掩码。

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

`ptest`的结果可以像往常一样用来分支，也可以用在`setcc`或`cmovcc`这类无分支指令中。

## AVX 及之后

AVX 为比较、混合和`ptest`提供了带`v`前缀的形式，作用在更宽的寄存器上。

可变混合指令的形式发生了变化。掩码不再是隐式的`xmm0`，而是显式的第四个操作数：

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

AVX-512 扩展对模型做了更深层的改变。

首先，它新增了一类 64 字节的 SIMD 寄存器，称为`zmm`。它们扩展了对应的`ymm`寄存器，就像`ymm`寄存器扩展`xmm`寄存器那样。

其次，这些扩展还创建了一类全新的**掩码寄存器**，从`k0`到`k7`，它们的主要用途就是作为 SIMD 指令的掩码。比较不再写入向量，而是写入这些新寄存器之一。在许多指令上，它们还能作为谓词配合`{k}`写掩码使用，_直接_选择通道：

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

最后，还有一些新指令用于操作这些新寄存器，包括把它们复制到通用寄存器中。这使得`movmsk`指令不再必要，而且`zmm`寄存器也不支持`movmsk`指令。

这里提到这些扩展只是为了完整起见。本轨道中的练习使用的是 SSE 形式。
