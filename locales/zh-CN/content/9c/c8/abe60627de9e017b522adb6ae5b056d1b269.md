# 关于

[循环][control]是一串指令，这些指令可能会被执行多次，直到满足某个结束条件。

在 x86-64 中，循环通常通过跳转到一个靠前的标签来创建：

```x86asm
example_loop:
    ...
    jmp example_loop
```

注意，无条件跳转到一个靠前的标签，总会把执行转移到该标签。这意味着循环会一直重复下去，除非还有另一个跳转能跳到这段重复序列之外。

例如，下面这个循环不会结束：

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

而这个循环可能会结束，取决于条件是否满足：

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## 计数循环

计数循环的结尾几乎总是同一个样子：一条更新计数器或比较两个值的指令，紧接着是一条条件跳转，由它决定是否再绕一圈。

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
在上面的代码中，`cmp rsi, 0`并非必需，因为当结果为`0`时，`sub rsi, 1`已经设置了`zero flag (ZF)`。

尽管`cmp`是汇编中检测条件的主要方式，但许多指令都会更新标志位。
例如，许多整数运算或位运算指令会在结果为`0`时更新`ZF`，在结果为负数（即最高位被置位）时更新`SF`。

你可以查阅[参考资料][reference]，看看每条指令会影响哪些标志位。

[reference]: https://www.felixcloutier.com/x86/
~~~~

注意，在上面的示例中，假定`rsi`大于`0`。
如果它是`0`，那么`sub rsi, 1`会把`rsi`减成`-1`，这是一个非常大的无符号数。
循环还需要再经过`18,446,744,073,709,551,615`次迭代才会最终结束。
而且，由于数组的长度是`0`，任何内存访问都会越界。

如果无法保证数组的长度，有两种常见的做法。

第一种是把结束条件移到循环的开头，然后在末尾放一个无条件跳转：

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

第二种是在循环开始之前，先检查一次数组是否为空：

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

第二种做法通常比第一种更高效，因为循环体中的分支更少。
你会在后续的概念中学到更多相关内容。

## 微操作

处理器并不会直接运行`add`或`jnz`这样的指令。
CPU 的前端会先把每条指令*解码*成一个或多个更小的内部步骤，这些步骤称为**微操作**（micro-operation，简称 **micro-op**）。
随后，处理器会调度并执行这些微操作，常常一个周期执行好几个，而且不按它们原来的顺序。

大多数简单指令会解码成一个微操作，而较复杂的指令可能会解码成好几个。
由于处理器真正处理的是这一串微操作，所以完成同样的任务时产生更少的微操作，就是让代码变快的一种方法。

## 宏融合

如前所述，循环通常以某种条件跳转结束。
这种情况太常见了，因此现代处理器在解码时会专门针对这种模式进行优化。

一条设置标志位的指令，如果紧接着是一条读取这些标志位的条件跳转，那么这两条指令可以一起解码成**一个**微操作，而不是各自解码成一个。
这称为**宏融合**。

融合后的这一对指令表现为一个操作：计数器的更新和分支的判断在同一个微操作里一起完成。
这样一来，循环的控制流程在循环实际要做的工作之外，几乎不带来任何额外开销。

根据经验，通常有两类指令对会这样融合：

- 诸如`add`或`sub`这样的算术指令，紧接着一条条件跳转。
- `cmp`、`test`或`and`，紧接着一条条件跳转。

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

只有当条件跳转**紧接**在设置标志位的指令之后、中间没有任何其他指令时，融合才会发生。

~~~~exercism/note
宏融合取决于具体的 CPU，而且哪些指令会与哪种条件跳转融合，也存在一些差异。

一个有用的参考资料是 [Agner Fog 的《Intel、AMD 和 VIA CPU 的微架构》][agner-uarch]。
[Intel 优化参考手册][intel-opt]的第 3.4.2.2 节（针对宏融合的优化）也列出了 Intel CPU 上可以融合的指令对。

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## `loop` 指令

有些指令可以用来实现类似循环的行为。
其中之一就是 [loop][loop]。

它唯一的操作数是一个标签，指向循环开头的地址。

`loop`指令把`rcx`中的值当作计数器，每次把它减 1。
一旦`rcx`中的值变成零，循环就结束，执行会接着顺序进行：

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

`loop`指令有两个变体，它们在每次迭代时都会检查零标志位（`ZF`）。
除了在`rcx`变为零时结束循环之外，当条件*不*满足时，它们也会结束循环。

| 指令       | 条件 |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

这些指令**不会设置**`ZF`。
在它们之前，必须有一条`cmp`、`test`或其他能改变`ZF`的指令：

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
尽管用起来很方便，但在现代处理器上，`loop`、`loope`和`loopne`通常比等价的`sub`/`jnz`或`cmp`/`jnz`序列慢得多。

关于各种不同 CPU 上指令性能的一个很好的参考资料是 [Agner 的指令表][agner-tables]。

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
