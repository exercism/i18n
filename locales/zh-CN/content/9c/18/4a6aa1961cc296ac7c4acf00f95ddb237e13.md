# 代码包含

`circus-acts`用`<`表示一个类*能够做*某个抽象类所描述的事情，却没有说明具体怎么做。

`include`是另一半：它把另一个类里的实际代码拿来，复制一份放进这个类。

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

`JAZZ_ROUTINE::count`的值是 8，而`JAZZ_ROUTINE`里根本没提过它。

## 这是两个独立的决定

多数语言把这两件事合在一起：一个`extends`既把代码传下去，又让子类能在需要父类的地方使用。Sather 则把它们分开。

| 写法 | 表示 |
| --- | --- |
| `class A < $B` | 凡是需要`$B`的地方，都可以用`A` |
| `class A is include B` | `A`一开始就复制了一份`B`的代码 |

可以只用其中一个，也可以两个都用。包含一个类并**不**会让它成为子类型：`include WARM_UP`之后，需要`WARM_UP`的地方仍然不能用`JAZZ_ROUTINE`，也不会假装它可以用。

## 重命名

包含进来的例程可以换个名字引入：

```sather
   include WARM_UP count -> warm_up_count;
```

多个之间用逗号分隔：

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## 略去其中一个

重命名成*空*就把它略去了，这正是替换它的方法：

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

`count`照常引入；`describe`则没有，所以在这里写一个并不会冲突。如果没有`describe -> ;`，编译器会拒绝：同一个类里出现两个名字和实参都相同的例程属于错误，而且 Sather 不会去猜你指的是哪一个。

这就是它和多数语言里重写的区别：替换是明说出来的，而不是隐含的。
