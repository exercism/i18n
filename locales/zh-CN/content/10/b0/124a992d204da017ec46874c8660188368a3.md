# 简介

在 Go 中，字符串是不可变的。
在循环中使用`+`拼接字符串会导致频繁分配内存，并多次复制数据。
[`strings`包](https://pkg.go.dev/strings)提供了[`Builder`](https://pkg.go.dev/strings#Builder)，通过高效地拼接字符串来最大限度减少内存开销。

## 构建字符串

`strings.Builder`的零值无需任何显式初始化或分配，就可以直接使用。
你可以使用特定的写入方法向构建器中写入新数据。
每个写入方法都会返回一个错误值，以满足 Go 的标准接口；但该值保证始终为`nil`，在日常代码中通常会被忽略。

最常用的方法有：

- `WriteString(s string) (int, error)`：向缓冲区追加一个字符串。
- `WriteRune(r rune) (int, error)`：追加一个 rune 的 UTF-8 编码。
- `WriteByte(c byte) error`：追加单个字节。

```go
var sb strings.Builder

sb.WriteString("Hello")
var r rune = ' '
sb.WriteRune(r)
var b byte = '.'
sb.WriteByte(b)
```

## 获取与重置

文本拼接完成后，你可以调用`String()`方法，将累积的内容提取为标准的 Go 字符串。
调用`String()`的开销非常小，因为它会直接将底层字节切片作为字符串返回，而不会复制累积的数据。

如果需要复用同一个构建器实例来拼接新的字符串（例如在循环中），可以调用`Reset()`方法。
这会清空内部缓冲区，让你可以从头开始构建下一个字符串，同时在底层保留已经分配的内存容量。

```go
var sb strings.Builder

sb.WriteString("Task One")
fmt.Println(sb.String()) // Output: Task One

// Clear the buffer for resource reuse
sb.Reset()

sb.WriteString("Task Two")
fmt.Println(sb.String()) // Output: Task Two
```
