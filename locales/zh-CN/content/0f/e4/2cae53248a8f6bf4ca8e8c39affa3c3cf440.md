# 简介

简单类型（字符串和基元类型）通常用`==`和`!=`来测试相等性。

引用类型（类的实例）用继承自`Object`的`Equals()`方法进行比较。如果你的相等性测试是要确保两个对象就是同一个实例，那么依靠`Object`的实现就足够了。如果不是，就需要重写`object.Equals()`。

如果你知道类的所有实例都在同一个地方创建，比如某个游戏或模拟程序里的角色，那么引用相等就足够了。然而，同一个现实世界实体很可能会被创建出多个实例（来自数据库、来自用户输入、通过 Web 请求）。这种情况下，就必须用能够唯一标识该实体的值来做相等性测试。因此必须重写`Equals()`，并用类中相应的数据成员来做相等性测试。

重写后的`Equals()`方法中，对简单类型的成员用`==`做相等性测试，对引用类型的成员则递归调用`Equals()`。

`Object`类提供了合适的方法来比较两个对象，判断它们是不是同一个实例。

## `Object.GetHashCode()`

`Object.GetHashCode()`方法返回一个 32 位整数形式的哈希码。哈希码被_字典_和_集合_类（例如`Dictionary<T>`和`HashSet<T>`）用来高效地存储和检索对象。

哈希码和相等性之间的关系是：如果两个对象相等（`Equal()`返回 true），那么这两个对象的`GetHashCode()`必须返回相同的值。反过来并不成立。它并不是对称的。两个对象的哈希码相同，并不意味着它们就相等。想象一下这样一个查找函数：它先根据哈希码找到对应的“桶”，再用相等性测试挑出具体的项。

HashCode 库的 API 文档讨论了生成哈希码的最佳方式。

在哈希集合使用期间，用于相等性测试的值必须保持稳定。如果你用一组值把对象加入集合，然后修改这些值，哈希码就不再指向正确的“桶”。实际上，这意味着对象应该是不可变的。其他做法则有可能给维护者留下容易踩的坑。
