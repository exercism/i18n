# 关于

异常是一种错误处理方式。它们之所以叫异常，是因为通常在处理某些意外事件时才会出现。

在代码的任何位置，我们都可以“抛出”异常。我们通过`raise`方法来实现，传入一个对象，通常是一个 Exception 对象，不过也可以传入普通的字符串。例如，在练习的存根代码里你会看到，我们用内置的`RuntimeError`来告诉 Ruby 某个方法还没有实现。你也可以使用`raise(ExceptionObject, params)`这种简写语法。如果省略了异常类，默认会使用`RuntimeError`。

例如：

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

当 Ruby 看到这种情况时，会把错误逐层向上抛出到程序顶层，然后退出程序。

例如，如果你尝试用某个数除以零，会看到类似这样的内容：

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

需要注意，异常应该用在真正发生了异常情况的地方，也就是某个需要特殊处理的错误。异常不应用来控制程序的流程，这被认为是糟糕的设计，常常会导致性能和可维护性变差。

## 类的层级结构

在 Ruby 中，异常遵循类的层级结构，其中`Exception`是基类。以下是 Ruby 最常见的内置异常：

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

捕获某个特定类的错误时，也会一并捕获其子类的错误。这就是为什么从`Exception`进行捕获可能很危险。Ruby 也用异常来处理操作系统“Signals”传来的消息，例如`ctrl-c`。这意味着，从`Exception`捕获也会把这些系统“Signals”一起捕获。因此，为了避免出现意外行为，要捕获“所有错误”的常见做法是改为捕获`StandardError`。

## rescue 语法

Ruby 还为需要特殊处理的情况提供了扩展的 rescue 子句：

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

这在处理网络 I/O 时很有用，例如我们总是需要记得关闭连接。

Ruby 的 rescue 块还可以使用`retry`关键字，它会重新运行 begin 和 rescue 之间的所有内容：

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
