# 指令

本题以实时操作系统的非抢占式静态调度为模型，但也类似于只有一种资源的作业车间调度问题（JSP）。本题假设所有任务都是静态已知的，也就是说，题中所有任务的释放时间在程序开始时就已知。而在实际中，任务的释放时间在程序开始时并不已知，可能在任意时刻通过 I/O、中断等方式产生。

给定一个带有各项参数的任务数组，请确定一个调度方案，使这些任务能够顺序执行、互不重叠。由于本题以实时操作系统的进程调度为模型，我们假设任务之间需要一段非零的时间，也就是上下文切换开销。任务分为两种类型：周期任务和动态任务。两种任务都有一个任务 ID 参数，它是一个字符串，用于区分任务数组中的不同任务。

**周期任务**是指周期性地执行的任务。换句话说，该任务每隔 T 秒执行一次，其中 T 定义为周期。周期任务由以下参数定义：

* 开始时间：任务第一次重复（也就是第一个实例）开始的时间
* 周期：任务各次重复开始之间的时间
* 执行时间：每次重复运行所持续的时间
* 结束时间：整个任务不再被调度的时间

**动态任务**是指只执行一次的任务。动态任务由以下参数定义：

* 释放时间：任务最早可以被调度的时刻（与开始时间不同）
* 执行时间：任务运行所持续的时间
* 截止时间：任务必须在此之前完成执行的时限

要实现的函数有两个输入。第一个输入是一个数组，其中包含若干`RealTimeTask`实例。`RealTimeTask`实例会以`PeriodicRealTimeTask`或`DynamicRealTimeTask`实例的形式输入，所有任务参数都是整数。可以用 Python 内置的`isinstance()`函数来区分数组中的这两种任务。数组的顺序无关紧要，只需看任务的各项参数。第二个输入是一个整数，指定上下文切换开销。上下文切换开销始终是非负整数。

输出应为一个字典，其键是各个`RealTimeTask`实例的任务 ID，值则是一个由二元组组成的数组。二元组的格式为（开始时间，结束时间）。动态任务对应的数组中只应包含一个二元组，而周期任务的数组可能包含多个。数组中二元组的顺序无关紧要。如果无法在给定的上下文切换开销下为这些任务生成有效的调度方案，就抛出`NoRtosStaticScheduleProducible`异常。注意，输出前需要把 Z3 模型对变量求出的结果转换为整数。如果 Z3 模型结果的类型是`IntNumRef`，可以使用`as_long()`类方法将其转换为整数。

另外还提供了一个函数，让用户直观地看到任务的先后顺序。在`check()`函数中把`plot`关键字参数设为`True`，就可以针对单个测试用例启用这个函数。每个任务都会用断开的水平条形图来绘制并标注。要使用这个函数，必须先安装 Python 库 *matplotlib*。*matplotlib* 的安装详情见[这里](https://matplotlib.org/stable/users/installing.html)。
