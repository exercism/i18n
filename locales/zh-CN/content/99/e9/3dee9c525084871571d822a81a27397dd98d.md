# 说明

一个海盗正在一张隐藏海湾的海图上规划路线。这张海图是一个哈希表，以海湾名称为键；每个值都是一个数组，里面是能从该海湾直接到达的那些海湾。

## 1. 排空潮汐队列

定义 `tide-queue`，让它接收一个元素数组，把每个元素按顺序压入一个新的双端队列，再把它们全部弹出到一个数组中，并保持原来的顺序。这就是先进先出（FIFO）：从尾部压入，从头部弹出。

```factor
{ "alpha" "bravo" "charlie" } tide-queue .
! => { "alpha" "bravo" "charlie" }
```

## 2. 可达的海湾

定义 `coves-reachable`，接收一个起始海湾和一张海图，返回一个哈希集合，里面是从 `start` 出发能到达的每一个海湾，`start` 自身也包括在内。

```factor
"Skull Bay" H{
    { "Skull Bay"   { "Hidden Cove" } }
    { "Hidden Cove" { "Reef Point"  } }
    { "Reef Point"  { } }
} coves-reachable .
! => HS{ "Skull Bay" "Hidden Cove" "Reef Point" }
```

用 `<dlist>` 作为广度优先搜索（BFS）的边界，用 `HS{ }` 作为已访问集合。

## 3. 跳跃次数

定义 `hop-count`，接收起始海湾、目标海湾和一张海图，返回它们之间的最少跳跃次数；如果目标无法到达，则返回 `f`。

```factor
"Skull Bay" "Hidden Cove"
H{
    { "Skull Bay"   { "Hidden Cove" } }
    { "Hidden Cove" { } }
} hop-count .
! => 1
```

在双端队列中，把每个海湾和它到起点的距离一起携带（用包含 2 个元素的数组即可）。

## 4. 黄金数量

桩代码用 `:` 声明了 `gold-count`。把它改成 `MEMO:`（而不是 `:`），这样每个海湾的结果只计算一次并缓存起来。在练习提供的 `gold-distribution` 常量里查找该海湾的黄金。不在这个分布里的海湾，黄金数量为零。

```factor
"Smuggler's Hollow" gold-count .   ! => 200
"Davy Jones' Locker" gold-count .  ! => 0
```

## 5. 寻宝路线

定义 `treasure-route`，接收一个起始海湾和一张海图，返回可达海湾中黄金最多的那一个。使用任务 2 的 `coves-reachable` 和任务 4 的 `gold-count`。

```factor
"Skull Bay" some-chart treasure-route .
! => "Smuggler's Hollow"   (the richest reachable cove)
```

经过记忆化的 `gold-count` 让重复查找不再有开销，这在算法的多个部分都要查询同一个海湾时很有用。
