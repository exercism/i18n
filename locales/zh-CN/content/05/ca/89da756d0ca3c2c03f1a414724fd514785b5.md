# 测试

每个练习都附带一套单元测试，以及构建和运行它们所需的一切。
你需要自己提供实现。

## 运行测试

在练习文件夹中打开终端，然后运行：

```
make
```

这会编译你提交的解答和测试，然后运行测试。
每次修改解答后，都重新运行一次。

如果你有 [Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally)，可以改用下面这条命令，它也会运行`make`：

```
exercism test
```

要删除构建生成的文件，运行`make clean`。

### 没有 make

如果你没有`make`（例如在 Windows 上），可以直接编译并运行测试。
以练习“Bob”为例：

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

然后在 Linux 或 macOS 上运行测试：

```
./run_tests
```

在 Windows 上则运行：

```
.\run_tests
```

## 完成一个练习

每个练习的文件都以该练习的名字命名。
以练习“Bob”为例：

| 文件             | 内容                                                              |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90`        | 解答的存根，等你来补全                                            |
| `bob_test.f90`   | 测试                                                              |
| `TesterMain.f90` | 测试库                                                            |
| `Makefile`       | 给`make`的指令                                                    |
| `CMakeLists.txt` | 给 [CMake](#using-cmake-instead) 的指令，这一项是可选的            |

你只需要编辑解答文件。

完成每个练习，就是重复以下步骤，直到所有测试都通过：

  - 修复编译错误，然后运行测试，看看哪些测试失败。
  - 只实现刚好足以让下一个失败的测试通过的部分。
  - 重构你的实现，以提高可读性、减少重复等。
  - 再次运行测试，然后继续处理下一个失败的测试。

每个失败的测试都会打印一条消息，最后再给出汇总。
如果有测试失败，`make`会以错误结束。

每个测试都有一段注释来描述该测试，然后是实际的测试，以`call assert_equal`开头，例如：

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

要禁用某个测试，只需用`'!'`把它注释掉，例如：

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## 改用 CMake

你并不需要 CMake，但如果你使用 Visual Studio 或 Xcode 这类 IDE，或者使用 GFortran 以外的编译器，它可能很有用。

练习文件夹必须保留原来的名字，因为 CMake 靠它来查找源文件。
在练习文件夹中执行：

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

修改解答之后，只需要再运行最后两条命令。

**注意：**一定要在单独的文件夹（例如`build`）里运行`cmake`。
在练习文件夹里运行`cmake .`会覆盖练习自带的`Makefile`。

CMake 会为你的系统选择合适的生成器。
要选别的生成器，可以用`-G`选项，例如`cmake -G Xcode ..`。
运行`cmake --help`可以列出可用的生成器。
用 Visual Studio 或 Xcode 时，请用`ctest -V -C Debug`运行测试。

如果你的练习文件夹里没有`Makefile`，说明它是在这些文件加入练习之前下载的。
你仍然可以使用 CMake。
