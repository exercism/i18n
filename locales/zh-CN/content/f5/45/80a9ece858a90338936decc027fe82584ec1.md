# 泛型类

```sather
class LOST_BOX{T} is
   attr item : T;
   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;
end;
```

## 类型参数是什么

`T` 代表在使用处提供的类型。程序编译时，Sather 会为每一个实际用到的组合构建一个独立的类。所以：

- `LOST_BOX{STR}` 和 `LOST_BOX{INT}` 是不相关的类型；
- 没有运行时检查，没有装箱，也没有转换；
- 类里的错误会在它用到的每个类型上分别暴露出来。

这与 C++ 模板或 Rust 泛型采用的方法相同，而不同于 Java 泛型：后者会擦除类型，所有东西实际上都是对象。

## 带约束的类型参数

一个不加约束的 `T` 可以被赋值、传递和返回，别的什么都不行，因为对它别无了解。要在它上面调用例程，就得声明它必须符合什么：

```sather
class LOST_BOX{T < $STR} is
   describe : STR is return "a box holding " + item.str; end;
end;
```

`T < $STR` 要求 `T` 符合 `$STR`，作为回报，就允许调用 `item.str` 了。不加约束的 `T` 做不到的事，约束就是允许它们的办法。

没有这个约束，`item.str` 就无法编译，而且报错信息会指向泛型类里的那行，而不是使用它的那行。

## 泛型例程？

没有。只有类才带参数。需要在多种类型上工作的例程，要么放进泛型类里，要么接受像 `$STR` 这样的抽象类型。

## 如何在两者间选择

|  | 泛型类 | 抽象类 |
| --- | --- | --- |
| 确定时机 | 编译时 | 运行时 |
| 容纳 | 每次实例化一种类型 | 任何符合的类型 |
| 代价 | 无 | 一次派发 |

`ARRAY{$ACT}` 两者都用到了：在元素类型上是泛型，在元素可以是什么上则是抽象。

当类型自始至终都相同，而且类的使用者对此心知肚明时，就用泛型类。当多种类型必须共存于同一个集合中时，就用抽象类。
