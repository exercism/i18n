# 简介

学到教学大纲的这个阶段，你应该已经注意到，R 经常被当作命令式语言使用，而且越来越多地被当作函数式语言使用（尤其是配合`purrr`和`dplyr`这两个库的时候）。

现在如果说 R 主要是一门面向对象语言，可能会引来不少质疑！

奇怪的是，这句话确实成立。
在内部，R 的实现用到了类、继承、多态，以及面向对象程序员特有的那种态度。

不过，熟悉 Java 或 Ruby（明确的面向对象语言），甚至熟悉 Python（在某些方面算是半隐蔽地面向对象）的人，都会觉得 R 的做法……_很陌生_。

首先，R 有多种类设计方案：常用的可能有三种（S3、S4、R6），此外还有一些主要只有理论意义的方案。

深入的讨论可以见 [Advanced R（第 2 版）][book-advanced-r] 的第 12 章到第 16 章。
这本 2019 年出版的书主要面向想理解并维护 R 内部机制的人，因此面向对象是必不可少的。

而更面向最终用户的教材则各不相同。

- 《The Art of R Programming》（2011 年，仅有纸质版）有一章讲面向对象，涵盖 S3 和（更简略地）S4，这两者在当时都很重要。
  书中那句_“S3 类有着相当拼凑起来的结构”_至今依然惊人地成立。
- 《R in Action》（第 3 版，2022 年）把面向对象压缩到末尾“高级编程”一章里的 3 页。
- [R for Data Science（第 2 版）][book-r-data-sci]（2023 年，纸质版共 548 页）完全没提到面向对象。

本概念将重点介绍 S3 类，它最简单、最常用，也最贴合 Exercism 这类题目。
R 赛道上有些练习要求你创建 S3 类，另一些则把它作为可选项，但会温和地鼓励你这么做。

## S3 类

它们的历史很悠久：S3 这个名字只说明它们是在 S 语言（R 的商业前身）的第 3 版中引入的。

S3 类本身也非常简单：通常就是一个[数组][concept-lists]，外加至少一个额外的属性。

引用 [Advanced R][book-s3] 中的话：_“S3 是非正式的、临时的，但它的极简主义自有一种优雅：你拿掉其中任何一部分，都无法再拥有一个可用的面向对象系统。”_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

所以，对[`class(obj)`][ref-class]赋值，只是给`obj`增加一个属性；在这个例子里，它把 pt2d 标识为 point2d 类的一个实例。

创建步骤也可以合并，改用[`structure()`][ref-structure]：

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

尽管这两个实例在概念上完全相同，我们还没有实现让 R 确认这一点的方法。

### 泛型方法

熟悉其他语言中面向对象的人可能会想：_“类不是应该能做点什么吗？”_

我们可以查看`point2d`实例可用的方法，结果会发现（与底层的`list`相比）目前一个也没有。

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

在大多数面向对象语言里，方法都定义在类的定义内部。
少数语言（尤其是 Ruby）允许你之后再去添加和修改类的方法。

S3 类则完全不同。
我们不是把方法加到类上，而是把类加到一个泛型方法上。

在 R 控制台里交互操作的人一直在使用泛型方法，通常不会去想它们是怎么实现的。

一个很常见的例子就是`print()`，尽管你很少亲手打出这个函数名。
在控制台提示符下单独输入一个值`x`，不过是`print(x)`的语法糖。

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

我们已经可以打印`pt2d`。
虽然`print()`对`point2d`类一无所知，但它有合理的默认行为，足以处理各种各样的对象。

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

这样的输出相当啰嗦，我们可能想要一种简洁地美化打印这个点的方式。

很简单：加一个名为`print.point2d()`的函数就行。
名字必须写成`methodname.classname`这种形式，这样分发器才知道该找什么。

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

现在假设我们想创建一个新的泛型方法，比如用`flipvert()`来把`y`坐标的符号取反。

同样很简单：

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

这样就创建了一个分发器：`x`是带有 S3 类的对象，`...`负责处理方法定义可能需要的任何额外实参（也就是“点参数”，见[函数概念][concept-functions]）。

然后我们就能为`point2d`定义这个方法并使用了。

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

现在 R 既知道怎么翻转这个点，也知道怎么显示结果。

我们可以据此扩展，为三维、极坐标等创建类，再分别为每个类定义方法。

从最终用户的角度看，只有`flipvert(x, ...)`这一个入口，我们可以交给 R 去判断输入属于哪个类，并选用合适的底层实现。

~~~~exercism/caution
`verb.class`这种格式的函数名，无论对用户还是对 R 的解析器来说，看起来都像是 S3 方法。
请在其他场合避免使用类似的命名。

诚然，base R 有时会违反这条规则。
我们应当把它看作一次不幸的历史遗留（对那些比 S3 还要古老的函数而言），出于向下兼容，必须保留。
~~~~

### 继承

面向对象的爱好者可以就继承、子类化、混入以及其他种种话题写上好几章教科书。

R 只是允许你给`class`属性提供多个名字：一个更长的字符串向量，而不是单个字符串。

冒着把这个例子用坏的风险，假设我们做了一个通用的`point`类，想把它细分为`point2d`、`point3d`等子类。

那么`point2d`的定义只需写成`class = c("point2d", "point")`：具体类和父类（可能不止一个）。

这时像`print()`这样的泛型方法会依次查找`print.point2d()`、`print.point()`，以及（很可能还有）`print.default()`，并使用分发器找到的第一个实现。

### 安全性

许多面向对象语言（Java、C# 等）利用类内部的数据封装，来执行细致的编译期检查并强制保证类型安全。

请注意，S3 允许你几乎想做什么就做什么，哪怕毫无道理（就算有错误信息，也会在之后才出现）。

引用[“Advanced R”][book-s3]（第 2 版，13.3 节）：

> _如果你用过其他面向对象语言，这可能会让你感到不安，但实际上这种灵活性很少带来问题。R 不会阻止你朝自己的脚开枪，但只要你不把枪口对准脚趾扣动扳机，就不会有问题。_

R 在探索性数据科学和统计方面非常出色，尤其是在交互式使用的时候。
没人建议你用它来编写高度安全的企业财务系统！
