# 关于

很多程序需要（看起来）随机的值来模拟现实世界中的事件。

常见且熟悉的例子包括：

- 抛硬币：一个取值为 `"H"` 或 `"T"` 的随机值。
- 掷骰子：一个 1 到 6 之间的随机整数。
- 洗一副牌：一个牌列表的随机顺序。

用计算机生成真正随机的值是一项[出奇困难的技术挑战][web-truly-random]，所以你可能会看到这类结果被称为“伪随机”。

***重要***：本概念*不*涵盖密码学安全的随机数，那是一个困难得多的挑战。

不过，R 源自一个统计软件包，常被用于模拟，因此它提供了丰富多样的随机值生成方式。这些结果对于建模、模拟和游戏中的大多数应用来说已经足够好了。

## [有放回与无放回抽样][yt-sampling-with-replacement]

想象我们有一个袋子，里面有 3 个红球和 4 个绿球，我们随机从袋子里摸出一个球。要再摸一个球，有两种可能：

1. 把第一个球放回袋子，摇匀后再摸出一个。此时球的数量和之前一样（7 个），*红球与绿球的比例也保持不变*。
2. 把第一个球放在桌上，再摸出第二个。此时袋子里只剩 6 个球，*红绿比例取决于第一个球的颜色*。

情形 1 是有放回，情形 2 是无放回，*两者会得到不同的结果*。

## 使用`sample`获取离散值

要从有限个离散值中挑选，可以带放回或不带放回地使用[`sample()`][ref-sample]。这对整数、字符串等都很有用。

```R
sample(1:10, 5) # no repeats by default
#> [1] 8 3 4 2 6

sample(1:10, 5, replace = TRUE) # repeats are OK
#> [1] 10 10  7 10  9

languages <- c("Fortran", "R", "Python", "Julia")
sample(languages, 1)
#> [1] "Python"

sample(c("H", "T"), 5, replace = TRUE) # coin flips
#> [1] "T" "T" "H" "H" "H"

sample(c(TRUE, FALSE), 5, replace = TRUE) # alternative coin flips
#> [1] FALSE  TRUE FALSE  TRUE  TRUE
```

抽样很适合放进数据管道。例如，生成随机的字母数字字符串：

```R
library(stringr)

c(letters, LETTERS, 0:9) |> sample(50) |> str_flatten()
#> [1] "5tX71jhbM9zUmKrpENBQyGYaZdJPVAx06leSF2s8gcfw3OviIH"
```

另外，抽样并不局限于向量和区间。在其他概念中我们会看到，[列表][concept-lists]、[矩阵][concept-matrices-arrays]和[数据框][concept-dataframes]都是合法的输入。*这完全符合你对 R 的期待*。

## 洗牌

其他几种语言都有专门的函数来打乱序列：Python 的 `random.shuffle()`、Julia 的 `shuffle()`、Matlab 的 `randperm()` 等等。

R 没有洗牌函数。*为什么？*

要理解这一点，请再看一眼[`sample`][ref-sample]函数。

完整形式是 `sample(x, size, replace = FALSE, prob = NULL)`，其中`x`（通常）是要抽样的序列，`size` 是要选取的元素个数。

我们已经讨论过 `replace`，其默认值是无放回抽样。现在先忽略 `prob`，它允许你给`x`中的各个元素赋予不相等的权重。

如果我们省略 `size`，只提供`x`，会发生什么？

```R
x <- letters[1:6]
x
#> [1] "a" "b" "c" "d" "e" "f"
sample(x)
#> [1] "e" "a" "f" "b" "c" "d"
```

以典型的 R 风格，这个模式是输入向量、输出向量，而 `size` 默认为 `length(x)`。

R 在很大程度上是由统计学家编写、也为统计学家服务的，他们明白“无放回地对`x`的所有元素进行抽样”不过是“打乱`x`”的更技术化的说法。

*因此*，没有 `shuffle` 函数，因为 `sample` 已经恰好完成了我们需要的操作！

## 处理概率分布

上面的例子描述的是所有结果等可能的情形。例如，`sample(1:100)` 给出 1 到 100 之间任意整数的可能性都相同。

这叫做[`uniform`][web-uniform]分布。

许多现实世界的情形远没有这么简单。因此，统计学家创造了各种各样的[`distributions`][wiki-probability-distribution]，用数学方式描述“现实世界”的结果。

基础 R 支持的分布比你听说过的还要多，还有一些分布可以在开源包中找到。

本文档的其余部分只介绍最常见的几种分布。

## 浮点数

### 均匀分布

要获得浮点数的[等权重分布][wiki-uniform]，请使用[`runif()`][ref-runif]（注意它是“**r**andom-**unif**orm”的组合，要克制住那种自然但*错误*地把它读成“run if”的倾向）。`min`和`max`都可以指定，但默认分别为 0 和 1。

```R
runif(5)  # generate 5 values
#> [1] 0.3038506 0.3527959 0.3319309 0.4846354 0.4386279

# generate 5 non-negative values <= 100.0
runif(5, max = 100)
#> [1] 79.70762 51.62232 52.85281 71.08571 63.94380
```

### 正态（高斯）分布

它也被称为“钟形”曲线，是描述测量值不精确性的一种非常常见的方式。

例如，假设你工作的工厂刚买进 10,000 个本应完全相同的螺栓。你想设置工厂机器人来处理它们，于是称量了 100 个样本，发现它们的平均（即[`mean`][ref-mean]）重量是 4.731g。这几乎不可能意味着它们每个都恰好重 4.731g。也许你会发现数值分布在 4.627 到 4.794g 之间，但集中在 4.731g 附近。

这就是[`normal distribution`][wiki-normal-distribution]（或“高斯分布”，以数学家 Card Friedrich Gauss 命名），它的概率在均值处达到峰值，并向两侧对称地逐渐减小（因此是“钟形”）。

要在软件中模拟它，我们需要某种方式来指定曲线的宽度（*通常，昂贵的螺栓会比便宜的螺栓更紧密地聚集在均值附近！*）。按照惯例，这通过[`standard deviation`][wiki-standard-deviation]来完成：数值小则曲线尖锐狭窄，数值大则曲线低矮宽阔。

数学家喜欢希腊字母，所以你会经常看到用 `μ`（'mu'）表示均值，用 `σ`（'sigma'）表示标准差（或 `sd`）。因此，如果你读到“95% 的值都在 μ 的 2σ 范围内”或“希格斯玻色子以 5-sigma 置信度被探测到”，这类说法都与标准差有关。

<!-- 关于这一点，[`Statistics`][statistics]概念中还会有更多内容。 -->

要用这种分布生成随机值，R 提供了[`rnorm()`][ref-rnorm]函数。

它是“random normal”的缩写，默认 `mean` 为 0，`sd` 为 1。

```R
rnorm(5)
#> [1]  0.36965357  0.07489948 -0.83827224 -0.83126506 -0.59895825

# Simulating our bolts example
rnorm(5, mean = 4.731, sd = 0.2)
#> [1] 4.564521 4.613237 4.419512 4.772196 4.839102
```

单看这些数字，很难看出原始输出比均匀分布更集中在均值附近。如果你有疑问，可以生成 1000 个或更多，并绘制出来，这样会更明显。本地没有安装 RStudio（或类似工具）的学生可以使用在线 R 运行器，例如 [rdrr.io][web-rdrr] 或 [WebR ggplot2 Playground][web-ggplot]。

代码 `hist(rnorm(10000), breaks = 40)` 会展示出基本模式，尽管呈现方式不算最优雅。随机数被分到各个区间，纵轴是每个区间内结果的数量。

~~~~exercism/advanced

## 离散分布

### 二项分布

如果你抛一枚硬币（*不作弊*），得到正面或反面的机会相同：两者的概率都是 `p = 0.5`。

如果你把这枚硬币抛 20 次，会有多少次得到正面？可能是 0 次，也可能是 20 次，但即使没有受过统计训练的人也可能猜到“*大约 10 次*”。

单次抛掷中得到 0 次或 1 次正面的概率之比是 `1:1`。

抛两次时，0、1、2 次正面的比例是 `1:2:1`；抛三次时是 `1:3:3:1`。

这些比例被称为[“二项式系数”][wiki-binom-coeff]。它们构成了[帕斯卡三角][wiki-pascal-triangle]，包括 R 在内的许多 Exercism 学习路径都有一个基于它的[练习题][practice-pascal]。

如果我们想要的是某个特定结果的概率，R 提供了[`dbinom()`][ref-rbinom]函数（它计算[概率密度][wiki-pdf]）。从 20 次抛掷中得到 10 次正面的概率接近 18%。

```R
# Probability of exactly 10 heads in 20 flips, fair coin
dbinom(10, size = 20, prob = 0.5)
#> [1] 0.1761971
```

作弊是可能的，所以把正面的概率提高到 `p = 0.6` 反而会*降低*得到 10 次正面的概率：

```R
# Probability of exactly 10 heads in 20 flips, biased coin
dbinom(10, size = 20, prob = 0.6)
#> [1] 0.1171416
```

现在，20 次抛掷中出现超过 10 次正面的可能性更大了。显然，我们需要关注所有可能的结果：[二项分布][wiki-binomial]。

R 提供了[`rbinom()`][ref-rbinom]函数，用于按二项分布生成随机值。告诉它要返回多少个值 `n`、进行多少次试验 `size`（比如抛硬币的次数），以及单个事件发生的概率 `prob`（比如一次抛掷得到正面的概率）。

要模拟我们的抛硬币，请把这段代码运行在能够显示图形输出的地方，就像处理正态分布时那样：

```R
# fair coin
hist(rbinom(n = 10000, size = 20, prob = 0.5))

# biased coin
hist(rbinom(n = 10000, size = 20, prob = 0.6))
```

生成的图显示，最可能的正面次数分别是“大约 10 次”和“大约 12 次”。

对于 20 次抛掷，结果是明显离散的，直方图上有很大的台阶，但已经有点接近“钟形”。如果我们模拟数百万次抛掷，并使用公平硬币以保证结果对称，二项分布就会越来越接近（*连续的*）正态分布。

### 泊松分布

每年有多少颗直径大于 1m 的陨石撞击地球？

地球上每个地方都有一定（低）水平的天然本底放射性。如果你打开一个[盖革计数器][wiki-geiger]，每秒会听到多少次探测到辐射粒子的咔哒声？

这些例子的共同特点包括：

- 事件彼此*独立*。
- 某个区间内事件发生的概率保持不变。
- 我们在对离散事件计数。
- 计数值没有*理论上的*上限（尽管测量上可能存在实际限制）。

某个区间内发生 0、1、2……个事件的概率构成一个[泊松分布][wiki-poisson]。

泊松分布的关键参数是所选区间内事件的[`mean`][ref-mean]（平均值），通常用希腊字母 λ（'lambda'）表示。

文献中把直径至少 1 米的撞击地球的陨石频率描述为“每隔几个月一次”。

举个例子，取 `lambda = 4`，看看用[`rpois()`][ref-rpois]得到的分布是什么样子：

```R
hist(rpois(n = 10000, lambda = 4))
```

现在直方图高度不对称，峰值在 2 次撞击处，还有一条长尾，显示 10 次或更多的计数不为零。

## 随机种子

上面描述的所有随机函数都力求每次运行时给出不同的结果。毕竟，它们是*随机的*！

这种行为依赖于每次都生成一个不同的[随机种子][wiki-seed]。

为了调试，使用[`set.seed(n)`][ref-set-seed]函数可能会有帮助，其中 `n` 是你选择的整数。每次都设置相同的种子，我们的代码在每次运行时就会返回同一组随机值。

```R
sample(1:5) #> [1] 5 1 2 4 3
sample(1:5) #> [1] 2 5 4 1 3
sample(1:5) #> [1] 4 2 5 1 3

set.seed(100); sample(1:5) #> [1] 2 3 5 4 1
set.seed(100); sample(1:5) #> [1] 2 3 5 4 1
set.seed(100); sample(1:5) #> [1] 2 3 5 4 1
```

对于进阶用户，`set.seed()` 还允许你指定要使用的 RNG（*Random Number Generator*，即随机数生成器）类型。

据说默认值是 `"Mersenne-Twister"`，所以在尝试更改它之前，请确保你明白这意味着什么。本概念的作者对 RNG 没有更多建议可以提供。
