# 关于

## 枚举

到目前为止，我们处理的主要是数字和字符串。
为了给现实世界建模，我们可能希望某个变量只能取有限的几个值。
你可能想要一个专门的数据类型，它只包含几个名字各不相同的值。
例如，在滑板工厂里，板面材料只能是枫木、竹子或塑料中的一种。

你可以用整数来编码这些值，但那样就得写额外的代码，去检查系统传来的材料值是不是无效的。
这些[_魔法数字_][magic numbers]的含义很难在源码中追查，而且很容易弄混。
用`enumerations`可以鼓励你写出富有表现力的代码，并减少无意的比较错误。

## 示例用法

这种枚举的专门术语叫`scoped enumeration`。
下面的代码片段展示了如何编写一个`DeckMaterial` `enumeration`。
注意`enum class`关键字，以及定义末尾的`;`：

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
现在来看滑板店里的定价函数，注意作用域解析运算符（`::`），它指定了来自`enumeration`的`enumerator`：

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## 作用域

假设你还有第二个`enumeration`，用来表示轮子材料：

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
尽管轮子和板面都可以用_塑料_制成，但两者不会混淆。
它们是不同的_类型_：`DeckMaterial`的塑料和`WheelMaterial`的塑料。
每个`enumeration`的`enumerators`都在自己的作用域里，也就是自己的`namespace`。
这就是它们被称为`scoped enumerations`的原因。

## 无作用域枚举
你可能会想，既然名字里带`scoped`，那应该也有 _`unscoped`_ 枚举吧，没错。
`Unscoped enumerations`越来越不受欢迎，因为它们共享同一个全局命名空间。
正因为共享，你不能有两个`unscoped enumerations`，它们的`enumerators`同名，比如上面的例子里的 _塑料_。

另外，`unscoped enumerations`会隐式转换为整数。
看看下面这个例子，结果会让你意外：

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

如果你想把`scoped enumerations`转换为整数，可以用`static_cast<int>`。
