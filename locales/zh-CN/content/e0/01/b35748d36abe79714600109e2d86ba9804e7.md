# 关于

`Result`类型让函数可以返回单个值，同时表明以下几件事：
- 操作是成功还是失败
- 成功时，操作的结果值
- 失败时，失败的原因

在不支持`Result`类型这类机制的其他编程语言中，通常会用下面这些模式来实现上述目标：
- 函数返回一个数字代码，用来表示成功或失败的原因，同时需要一个输出参数在成功时接收结果值。
- 函数在成功时返回值、出错时返回 NULL，然后再用另一个函数取得错误代码，以指出失败的原因。

另一种常见的错误处理机制是异常：一旦发生失败，它会突然跳出当前函数，把控制权交给调用栈中的第一个处理程序。如果没有任何处理程序“捕获”这个异常，程序就会终止。

## 使用`Result`类型的好处

* __编译期安全__：把一次函数调用的成功或失败显式地写进类型系统中，编译器就能确保调用方代码处理所有失败情况，从而避免一大类可能由 null 引发的 bug。

* __运行时安全__：`Result`类型不使用`null`，而是用`Error`表示失败，因此不可能出现`NullReferenceException`。

* __显式的错误处理__：调用返回`Result`的函数的代码必须承认这次调用可能失败，必须有意识地处理这类失败。既没有静默失败，也没有意外的异常。

* __可预测的控制流__：`Result`和其他值一样被返回，不会像异常那样跳出调用栈。你始终清楚错误从哪里产生，又是如何传播的。

* __更好的可读性与可维护性__：通过返回`Result`，函数的签名清楚地表明它在成功和失败时的预期行为。

## 用法

`Result`类型是一种泛型类型，包含两个底层类型：
- 操作成功时结果值的类型
- 失败时表示失败原因的类型

`Result`类型也是一种[可区分联合][discriminated-union]，有以下几种可能的情况：
* `Ok <value>`表示成功的结果
* `Error <reason>`表示失败

下面这个函数演示了如何创建一个`Result`值：

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

在这个例子中，`Ok`的值是一个字符串（即给定的名字），`Error`的值也是一个字符串（即错误原因的人类可读形式）。

## 读取`Result`值的内容

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

调用`openFile`函数的代码可以用模式匹配来处理成功和失败的情况，如下例所示：

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
