# 简介

## 部分应用

Elm 中所有函数都是[柯里化的][currying]，这意味着如果你调用一个函数时没有传入全部实参，它会返回一个新函数。

这样做的结果叫做[部分应用][partial-application]（你没有把全部实参都传给函数，而是只应用了其中一部分）。

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

部分应用总是按顺序应用实参。

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## 管道运算符（`|>`）

写`x |> f`和写`f x`完全一样。举个具体的例子，`"5" |> String.toInt`和`String.toInt "5"`是一样的。

乍一听这似乎没什么用，但它被称为[管道运算符][pipe-operator]，因为它让你能写出“管道式”的代码。

例如，假设我们有一个 sanitize 函数，用来把用户输入转换成整数：

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

我们可以把它改写成这样：

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

这样避免了使用括号，并且按照函数被应用的顺序来展示它们（先是`String.trim`，然后是`String.toInt`），有助于提高可读性。

还有一个[反向管道运算符 `(<|)`][reverse-pipe-operator]。
写`f <| x`和写`f x`完全一样。
乍看之下这似乎也没什么用，而且它的使用频率肯定远不如管道运算符，但在某些情况下它能帮你省去括号。

## 函数组合 / 无参风格

[`(>>)`][forward-composition]运算符的类型是`(a -> b) -> (b -> c) -> (a -> c)`，它通过组合两个类型兼容的函数（类型分别为`a -> b `和`b -> c`）来创建一个类型为`a -> c`的函数。
它的做法是：取第一个函数的输出（类型为`b`），把它作为第二个函数的第一个实参（第二个函数的类型必须是同一个`b`）。
新创建的函数会接收和第一个函数相同的输入（类型为`a`），并返回第二个函数返回的那个`c`。

举个具体的例子：`String.trim >> String.toInt`。
`String.trim`接收一个字符串作为它唯一的形参，所以新创建的函数接收的也是它。
`String.toInt`返回一个`Maybe Int`，所以新创建的函数返回的也是它。
`String.trim`返回一个`String`，而`String.toInt`接受`String`作为形参，所以这个例子能通过编译。

现在我们可以把`sanitize`函数改写成下面这样：

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

注意，尽管功能完全相同，我们不再使用原始例子中那个`input`形参。
这种创建函数、不引用其形参的方式叫做“无参风格”。
这种风格的优点是代码更简洁，缺点是可能更难理解，尤其是对初学者来说。

值得记住的是，Elm 中所有函数都是柯里化的，所以`String.length >> max`能通过编译。

- [`(>>)`][forward-composition]运算符的类型是`(a -> b) -> (b -> c) -> (a -> c)`。
- `String.length`的类型是`String -> Int`，也就是`(a -> b)`那部分，所以`a`是`String`，而`b`是 - `Int`。
- `max`的类型是`Int -> Int -> Int`，也就是`b -> c`那部分。
- `b`是`Int`，所以`max`被部分应用，因此`c`是这次部分应用的结果（`Int -> Int`）。
- 所以`String.length >> max`的类型是`String -> (Int -> Int)`。
- 所以`((String.length >> max) "123") 2`返回`3`，因为`"123"`的长度是 3，大于`Int`实参里的 2。

## 函数设计

为了在 Elm 中轻松写出优雅的代码，你应该把主要数据结构放在函数的最后一个形参位置。
标准库中所有常用函数都这样做，比如`List.map`（类型签名见下）。

```elm
map : (a -> b) -> List a -> List b
```

这里我们可以看到，`map`函数的最后一个形参是`List a`，返回的是`List b`，所以主要数据结构（`List`）是最后一个形参。

这样就可以写出优雅的管道式代码，比如下面这样。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

它也让你能方便地使用函数组合和无参风格，作为管道写法以外的另一种选择。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

函数组合还能让你把这个例子简化为对`List.map`的单次调用。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
