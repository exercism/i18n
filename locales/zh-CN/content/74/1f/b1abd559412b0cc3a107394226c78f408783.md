# 关于

解析（parsing）就是把文本转换成有意义的数据的过程。`String`包里的函数在这方面有很大局限，而正则表达式又难以使用，所以在 Elm 中，解析的惯用做法是使用`elm/parser`包。

我们来看一个例子：为编程语言 [LOLCODE][lolcode]（的一个子集）编写解析器。先看下面这个带注释的程序：

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

首先，我们用 Elm 写一个类型来表示可能出现的命令：

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

这样，LOLCODE 程序就可以表示为一个`List Command`。先从`HAI 1`这一行的解析器开始：

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP`是用_解析器管线_构建出来的。`(|.)`运算符的意思是“解析字符串，但丢弃结果”，`(|=)`的意思是“解析字符串并保留结果”。在这个例子里，`Parser.keyword "HAI"`会消耗掉一个“HAI”，但这个结果会被忽略。`Parser.spaces`会消耗任意数量的 ' ', '\n' 和 '\r' 字符，不过这些同样会被忽略。`Parser.int`会解析出一个整数，这个整数的值（比如 1）会被传给最上层的`Parser.succeed Version`，解析器就会成功返回`Version 1`。

管线中只要有一个解析器失败，就会返回一个`Parser.DeadEnd`，整个解析器也随之失败。可以用`Parser.run`来运行解析器：

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

下面来处理“CAN HAS STDIO?”这一行：

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP`同样是一条解析器管线，只不过这次以`Parser.symbol`结尾，它适合解析“?”这类符号。我们想保留的值（也就是要导入的包名）由下面这段代码解析：

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

因为不知道包名会是什么，所以不能用`Parser.keyword`，而要用`Parser.chompWhile`：只要字符满足某个条件（这里是必须是字母或数字），它就会逐个消耗字符。这些被消耗的字符随后由`Parser.getChompedString`收集起来，它返回一个`Parser String`。这里我们希望把包名规范化，所以用`Parser.map`修改解析器中的字符串，把它转成小写。

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

接下来，`VISIBLE "HAI WORLD!"`由下面这段代码解析：

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

现在每条命令都有了自己的解析器。当然，在一般的程序里，这些命令的顺序无法预测，所以我们再来构建一个通用的命令解析器：

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf`会按给定的顺序依次尝试各个解析器。如果某个解析器失败，就尝试下一个；但如果它成功了，就直接返回它的结果，不再尝试剩下的解析器。如果所有解析器都失败，`Parser.oneOf`也就失败了。

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

注意，每一次失败的尝试都会产生一个`Parser.DeadEnd`，这些都会被`Parser.oneOf`收集起来。

要解析完整的程序，我们需要用下面这段代码依次解析多条命令：

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence`是一个可定制性很强的解析器，有很多选项。`start`、`separator`和`end`接收用来分隔序列中各项的字符串：解析 Elm 列表时会用 "[", "," 和 "]"；`spaces`接收一个解析器，用来处理各项与分隔符之间可能出现的空格，从而提供灵活性：解析 Elm 列表时我们会用`Parser.spaces`，但这里我们不接受任何空格，所以用`Parser.succeed ()`，它会立刻成功，不消耗任何内容。`item`接收解析每一项的解析器；最后，`trailing`让我们决定末尾的分隔符是`Parser.Forbidden`、`Parser.Mandatory`还是`Parser.Optional`。

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

解析器成功之后就会停止消耗字符串：

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

所以如果需要确保字符串里的内容全部都被解析完，可以使用`Parser.end`：

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

最后，有时我们需要根据解析到的内容来决定让解析器失败。比如，如果需要一个解析器，让以连续两条“HAI”命令开头的程序失败，就可以这样写：

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen`可以检查解析器的内容，并根据它的值返回一个新的解析器。这里，我们在一种情况下用`Parser.problem`让解析器带着自定义信息失败，在另一种情况下则返回原来的值。

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
