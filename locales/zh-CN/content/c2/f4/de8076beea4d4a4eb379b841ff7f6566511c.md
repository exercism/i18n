# 声望

声望是 Exercism 生态中让人们获得“信任”的系统。

声望衡量的是一个人为 Exercism 做了多少贡献，既包括对平台的贡献（例如开发软件、编写练习和文档），也包括对社区的贡献（例如担任导师指导他人）。

声望不能被“花掉”，也不能被“使用”。不过，达到一定的声望阈值后，就能获得新的权限和新的贡献途径。简单来说，一个人的声望越高，我们就越觉得可以信任他，他得到的权限也就越大。声望同时也是一份公开可见的记录，展示你为 Exercism 付出了多少。

## 目的

声望系统的目的是：

1. 最大化以成长为核心的学员与导师之间的互动
2. 最大化导师参与贡献的意愿

## 如何获得声望

获得声望的方式有很多种：

| 操作                              | 声望 |
| --------------------------------- | ---------- |
| 成功指导一份提交的解答            | 5          |
| 发布提交的解答                    | 1-3        |
| 编写练习                          | 20         |
| 更新练习                          | 10         |
| 编写概念                          | 10         |
| 更新概念                          | 5          |
| 创建拉取请求                      | 3-100      |
| 审查拉取请求                      | 1-20       |
| 合并拉取请求                      | 1-5        |

### 成功指导一份提交的解答

每成功指导一份提交的解答（讨论已结束），即可获得`5`点声望。

### 发布提交的解答

每发布一份提交的解答，获得的声望取决于该练习的难度：

| 标签     | 声望 |
| -------- | ---------- |
| `easy`   | 1          |
| `medium` | 2          |
| `hard`   | 3          |

### 编写练习

对于每个将该用户列为作者的练习，可获得`20`点声望。

### 更新练习

对于每个将该用户列为贡献者的练习，可获得`10`点声望。

### 编写概念

对于每个将该用户列为作者的概念，可获得`10`点声望。

### 更新概念

对于每个将该用户列为贡献者的概念，可获得`5`点声望。

### 创建拉取请求

默认情况下，用户发起的拉取请求被合并时，可获得`12`点声望。

根据拉取请求的内容，维护者可以通过给拉取请求添加以下标签之一，来授予更多（或更少）的声望：

| 标签            | 声望 | 示例                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x:rep/tiny`    | 3          | <ul><li>修复一个错别字或链接</li><li>删除一个空行或添加一个换行</li><li>修改或添加一条代码注释</li></ul>                                                                                                                                                                                                                   |
| `x:rep/small`   | 5          | <ul><li>修复单个测试用例、任务或示例</li><li>修复单个文件中的多处错别字或链接</li><li>通过给文件添加几行内容来澄清说明</li></ul>                                                                                                                                                                                     |
| `x:rep/medium`  | 12         | <ul><li>将练习与 problem-specifications 同步（包括相关改动）</li><li>从零开始添加一个或多个测试用例</li><li>改进练习中的多个文件</li><li>从零开始为练习添加导师笔记</li><li>修复测试运行器、分析器或表示器中的小 bug</li><li>为单个练习添加分析器注释</li></ul> |
| `x:rep/large`   | 30         | <ul><li>添加一个新的概念练习或实践练习</li><li>添加新的概念文档</li><li>大幅改写现有的概念或练习</li><li>添加新的 CI 脚本或其他自动化流程</li></ul>                                                                                                                                            |
| `x:rep/massive` | 100        | <ul><li>从零开始创建测试运行器、分析器、表示器或生成器</li><li>对这些工具进行大规模重构</li><li>从零开始编写重要文档（例如贡献指南或测试指南）</li></ul>                                                                                                                                            |

上面的示例可以作为判断该用哪个标签的大致参考，但维护者可以自行决定。

- 估计的耗时，应理解为一名_维护者_完成该拉取请求平均需要花费的时间。
- 如果指定了多个标签，则以声望值最高的标签决定授予的声望。
- 如果拉取请求仍处于打开状态，则（暂时）不会授予声望。
- 如果拉取请求是在_未合并_的情况下被关闭的，则不会授予声望。

_出于向下兼容的考虑，我们也支持用`x:size`标签来决定授予的声望。_

### 审查拉取请求

对于用户审查过的每个已合并或已关闭的拉取请求，可获得`5`点声望。

- 如果拉取请求仍处于打开状态，则（暂时）不会授予声望。
- 每个用户对每个拉取请求只能获得一次审查声望。
- 发起拉取请求的用户审查自己的拉取请求，_不会_获得声望。

- 如果给拉取请求添加了以下标签之一，审查该拉取请求所获得的声望会随之改变：

  | 标签            | 声望 |
  | --------------- | ---------- |
  | `x:rep/tiny`    | 1          |
  | `x:rep/small`   | 2          |
  | `x:rep/medium`  | 5          |
  | `x:rep/large`   | 10         |
  | `x:rep/massive` | 20         |

  _无法_为拉取请求的作者和审查者使用不同的声望“等级”。
  两者都基于同一个`x:rep`标签。

  如果指定了多个标签，则以声望值最高的标签决定授予的声望。

  _出于向下兼容的考虑，我们也支持用`x:size`标签来决定授予的声望。_

### 合并拉取请求

对于用户合并的每个拉取请求，可获得`1`点声望。

- 如果拉取请求仍处于打开状态，则（暂时）不会授予声望。
- 如果拉取请求是在_未合并_的情况下被关闭的，则不会授予声望。
- 发起拉取请求的用户合并自己的拉取请求，_不会_获得声望。
- 如果该拉取请求没有任何审查记录，则改为授予`5`点声望。

### 创建议题

和拉取请求一样，默认情况下，创建议题**不会授予任何声望**。
和拉取请求不同的是，只有 large 或 massive 级别的议题才会授予声望。

根据议题的内容，维护者可以选择通过给议题添加以下标签之一来授予声望：

| 标签            | 声望 | 示例                                             |
| --------------- | ---------- | ---------------------------------------------------- |
| `x:rep/large`   | 30         | <ul><li>内容完整的概念练习</li></ul> |
| `x:rep/massive` | 100        | <ul><li>设计一条学习路径的课程体系</li></ul>       |

上面的示例可以作为判断该用哪个标签的大致参考，但维护者可以自行决定。

- 声望应当反映一名_维护者_创建该议题需要付出的工作量。

- 如果指定了多个标签，则以声望值最高的标签决定授予的声望。
