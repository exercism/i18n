# 说明附录

## `from_quote`的优缺点

`Card.from_quote`函数会把字符串解析成`Card`。
这样就可以写出下面这样的代码：

```roc
card : Card
card = "Q"
```

这段代码会在编译时隐式调用`Card.from_quote("Q")`。用这种方式（或下文介绍的其他方式）在编译时运行代码，有可能加快程序的运行速度，因为程序无需在运行时处理解析和数据校验。此外，它还能确保无效数据（比如错误的日期格式）在编译时就被拒绝，而不是拖到运行时，让你的应用更加健壮。最后，它也让代码更加简洁易读。例如，下面是本练习中的一个测试：

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

不过，阅读这段代码的人可能会以为`simulate_game`函数接收的是一个包含两个`List(Str)`的记录，而实际上它接收的是包含两个`List(Card)`的记录。这可能会导致困惑和错误。因此，你可能更偏好下面这种稍长但更明确的写法：`"Q".Card`，它同样会在编译时调用`from_quote`。

在你自己的程序中，你也许更愿意改用`from_str`：

```roc
Card := { ... }.{
    from_str : Str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

你也可以在编译时调用`from_str`（或其他任何纯函数），就像这样：

```roc
Ok(card) = Card.from_str("Q")
```

注意：把这个定义放在顶层会让它在编译时运行（因为该函数是纯函数，且它的输入在编译时已知）。而在函数内部，你可以在运行时使用`from_str`。
