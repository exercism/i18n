# 映射与集合

| 类型 | 保存的内容 | 查找方式 |
| --- | --- | --- |
| `ARRAY{T}` | 按顺序排列的值 | 位置 |
| `FMAP{K,T}` | 键和目标对 | 键 |
| `FSET{T}` | 值，不重复 | 是否属于集合 |

## FMAP

```sather
   m ::= #FMAP{STR,INT};
   m := m.insert("emu", 2);
   m.get("emu")          -- 2
   m.has_ind("emu")      -- true
   m.size                -- 1
   m := m.delete("emu");
```

`m["emu"]`**不是**读取映射的方式，`FMAP`没有这样的例程，这一行也无法编译。要用`get`。

### 缺失的键

对不存在的键调用`get`，返回的是该类型的空值，而不是报错：`0`、`false` 或 void。void 的`STR`不会在产生它的地方出错，而是会在真正使用它的时候才出错。先调用`has_ind`是值得养成的习惯。

## FSET

```sather
   s ::= #FSET{STR};
   s := s.insert("emu");
   s.has("emu")          -- true
   s.size                -- 1
   s := s.delete("emu");
```

集合可以合并：

```sather
   a.union(b)            -- in either
   a.intersect(b)        -- in both
   a.difference(b)       -- in a but not b
   a.is_subset(b)
```

## 赋值回去与复制

`insert`和`delete`返回的是从现在起要使用的容器。通常就是同一个对象，在原地被修改；需要扩容时，则是一个新的、更大的对象。所以：

```sather
   m := m.insert(k, v);     -- always
```

之后只有等号左边这个名字可以信任。在`insert`之前取得的、指向同一个映射的另一个名字，可能已经过时了。

要保留一份独立的副本，就先复制一份：

```sather
   n ::= m.copy.insert(k, v);      -- m is unchanged
```

不过有个坑：从未插入过任何东西的映射是 **void**，而对 void 映射调用`copy`会失败。`insert`、`get`、`has_ind`和`size`都能处理 void 映射（`#FMAP{K,T}`就是 void，往里面插入正是映射诞生的方式），但`copy`不行。

`HMAP`和`HSET`是只会在原地修改的版本。构建大型结构时它们更快，但在学习阶段，它们不是合适的默认选择。

## 遍历

| 迭代器 | 给出 |
| --- | --- |
| `m.ind!` | 每个键 |
| `m.target!` | 每个目标 |
| `m.pair!` | 每个键连同对应的目标 |
| `s.elt!` | 集合中的每个值 |

映射和集合都没有顺序。两次运行遍历它们的顺序可能不同，所以千万不要写任何依赖谁先谁后的代码。

```sather
   loop
      #OUT + guide.ind! + "\n";
   end;
```
