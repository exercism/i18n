# 关于

链接性描述的是：在代码中，一个标识符可以从哪里被访问。
具有块作用域、函数作用域或函数原型作用域的值没有链接性。
这意味着它们无法从自己的作用域之外访问。
想进一步了解作用域，请参阅[作用域概念](../scope/introduction.md#Introduction)。

## 外部链接

具有文件作用域的标识符默认具有外部链接。
具有外部链接的标识符可以从程序中的任何文件调用。

## 内部链接

通过使用`static`说明符，可以让具有文件作用域的标识符具有内部链接。
具有内部链接的标识符只能在其文件内使用。

例如

```c
int public_count = 0; // file scope, external linkage by default
static int private_count = 0;  // file scope, internal linkage 

// file scope, internal linkage
static void some_function()
{
    // code snipped
}

// file scope, external linkage by default
int main()
{
    // code snipped
}
```

不要把静态链接与静态存储期混为一谈。
想进一步了解静态存储期，请参阅[存储期概念](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#static-the-storage-specifier-not-to-be-confused-with-the-static-linkage-type)。

如果一个值（而非函数）在头文件中声明，但在源文件中被定义为一个带有初始值的`static`文件作用域标识符，那么它的初始值将无法从该源文件之外访问。
它可能可以顺利编译、链接并运行而不报错，但该标识符的值会是零值，即使这个值是用`extern`声明的。
（想进一步了解`extern`，请参阅 [extern 概念](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#extern-how-to-access-a-variable-in-another-translation-unit)。）
在源文件中被标记为`static`的文件作用域标识符，不应在其头文件中声明。
