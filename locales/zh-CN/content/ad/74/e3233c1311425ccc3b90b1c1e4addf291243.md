# 介绍

## 循环

一个**循环**是一系列指令，它可能会被执行多次，直到满足某个结束条件为止。

在 x86-64 中，循环通常通过跳转回之前的标签来创建：

```x86asm
example_loop:
    ...
    jmp example_loop
```

注意，跳转回之前标签的无条件跳转总是会把执行权交给这个标签。这意味着循环会一直重复下去，除非还有另一个跳到重复序列之外的跳转。

例如，下面这个循环不会结束：

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

而下面这个循环可能会结束，取决于是否满足条件：

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### 计数循环

计数循环的结束方式几乎总是一样的：一条更新计数器或比较两个值的指令，紧接着是一个条件跳转，用来决定是否再绕一圈。

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
上面的代码中不需要`cmp rsi, 0`，因为当结果为`0`时，`sub rsi, 1`已经设置了`zero flag (ZF)`。

尽管在汇编中`cmp`是检验条件的主要方式，但很多指令都会更新标志位。
例如，许多整数算术或位运算指令在结果为`0`时会更新`ZF`，在结果为负数（即最高位被置位）时会更新`SF`。

你可以查阅[参考手册][reference]，看看每条指令会影响哪些标志位。

[reference]: https://www.felixcloutier.com/x86/
~~~~

注意，在上面的例子中，假定`rsi`大于`0`。
如果它是`0`，那么`sub rsi, 1`会把`rsi`减到`-1`，这是一个非常大的无符号数。
循环要再迭代`18,446,744,073,709,551,615`次才会最终结束。
而且，由于数组的长度是`0`，任何内存访问都会越界。

如果数组的长度没有保证，有两种常见做法。

第一种是把结束条件移到循环的开头，然后在末尾用一个无条件跳转：

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

第二种是在循环开始之前先检查一次数组是否为空：

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

第二种做法通常比第一种更高效，因为循环体里的分支更少。
你会在以后的概念中学到更多相关内容。

~~~~exercism/advanced
在某些情况下，现代 CPU 能够把两条不同的指令合并成一次操作。
这种优化叫做 **macrofusion**。

许多算术指令，比如`sub`和`add`，以及`cmp`和`test`，通常会与紧随其后的条件跳转融合。
这意味着，像`cmp rax, rdx`这样紧接着一个条件跳转的指令，通常会被 CPU 当作一次操作来处理。

Macrofusion 取决于具体的 CPU，哪些指令与哪种条件跳转融合也存在一些差异。

一份有用的参考资料是 [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]。
[Intel optimization reference manual][intel-opt]的 3.4.2.2 节（Optimizing for Macrofusion）也列出了 Intel CPU 上可融合的指令对。

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
