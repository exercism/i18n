# 简介

## 枚举

到目前为止，我们主要处理的是数字和字符串。
为了对现实世界建模，我们可能想限定一个变量只能取有限的几个值。
你可能会想要一个专门的类型，它只有几个不同的值，每个值都有各自的名字。
例如，在滑板工厂里，板面材料只能从枫木、竹子或塑料中选择。

你可以用整数来编码这些值，但必须写额外的代码来检查系统传入的材料值是否无效。
这些[_魔法数字_][magic numbers]的含义很难在源代码中追踪，而且很容易弄混。
用`enumerations`可以写出更有表现力的代码，并避免无意的比较错误。

## 用法示例

这类枚举的具体术语是`scoped enumeration`。
下面的代码片段展示了如何编写一个 `DeckMaterial` `enumeration`。
注意`enum class`关键字和定义末尾的`;`：

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
现在，看看滑板店里的一个定价函数，注意作用域解析运算符（`::`），它指明了某个`enumeration`中的`enumerator`：

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## 作用域

假设你为轮子材料又定义了一个`enumeration`：

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
虽然轮子和板面都可以用_塑料_制成，但两者不会混淆。
它们是不同的_类型_：`DeckMaterial` 的塑料和 `WheelMaterial` 的塑料。
每个`enumeration`的`enumerators`都有各自的作用域，也就是各自的`namespace`。
这就是它们被称为`scoped enumerations`的原因。

## 不限定作用域枚举
你可能会想，既然有`scoped`这个名字，那也应该有`unscoped`枚举吧，你说得没错。
`Unscoped enumerations`越来越不受欢迎，因为它们都共享同一个全局命名空间。
正因为共享，你无法像上面的例子那样，让两个`unscoped enumerations`拥有相同的`enumerators`（比如_塑料_）。

此外，`unscoped enumerations`会隐式转换为整数。
看看下面这个例子，结果出人意料：

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

如果想把`scoped enumerations`转换成整数，可以使用`static_cast<int>`。
