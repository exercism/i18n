# 简介

汇编中的任何数据都是字节序列。
这意味着任何数据都可以看作由这些底层字节构成的**数组**。

## 访问数组中的元素

要访问内存中的任意一个值，都必须先算出它的**有效地址**。
有效地址是一个表达式，它可以由以下几部分组成：

- 一个_基地址_，例如变量的标签所指示的地址。
- 一个_索引寄存器_，可以按`1`、`2`、`4`或`8`缩放。
- 一个有符号的 32 位_位移量_，即一个要加到基地址上（或从基地址中减去）的数。

注意，这种地址是_从 0 开始索引的_，因此不带任何偏移量的基地址指向变量的第一个字节。
这就是为什么像前面几个概念里那样，只用一个标签、不带任何偏移量去解引用内存，得到的是从第一个字节开始的值：

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 采用[小端序][endianness]。
这意味着多字节值的最低有效字节存储在最小的内存地址处。

因此，要访问多字节值的各个字节时，必须在基地址上加一个正偏移量，才能到达更高位的字节。

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

用一串值声明的已初始化变量，就是由这些值构成的数组，每个元素的大小就是所指定的大小。
不过，偏移量始终以**_字节_**为单位，即使数组中每个元素的大小更大也是如此：

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

注意，由于地址以字节为单位，所以可以直接访问数组中任意一个元素的某个单独字节：

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

出于同样的原因，一条指令也可以访问超过一个元素大小的数据：

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
汇编不会对数组访问做边界检查。
越过数组末尾的下标会读写数组之外的内存。
这可能导致悄无声息的错误结果、破坏其他数据，甚至在访问的内存未被映射时引发运行时故障。
程序员有责任让每个有效地址都落在数组范围内。
~~~~

## 计算已初始化数组的大小

NASM（The Netwide Assembler，即本 track 使用的汇编器）有一个特殊符号（`$`），用来表示当前在内存中的位置。
这个符号提供了一种简便的方法，用来计算数组在内存中占用的总大小：

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

紧跟在`example`之后使用时，`$`的值就是数组末尾在内存中的地址。
也就是说，`$ - example`就是那个地址与标签`example`所指向的地址之差。
这正是`example`所指向的数组占用的总大小（以字节计）。

所以，用这个值来定义`example_length`，我们就创建了一个 8 字节的变量，用来以字节为单位存储数组的大小（也就是长度）。

## .bss 段

未初始化的数据在**section .bss**中声明。
在大多数平台上，程序启动时操作系统会把这块数据填充为零。

在 NASM 中，一个未初始化的变量包括名字、指示数据大小的指令，以及要保留的元素个数。
这几部分之间用空格分隔。

主要的指令及其对应的数据大小如下：

| directive | size    |
| :-------: | :------ |
|   resb    | 1 字节  |
|   resw    | 2 字节 |
|   resd    | 4 字节 |
|   resq    | 8 字节 |

例如，下面为名为`example`的变量保留了`3`字节的未初始化空间：

```x86asm
section .bss
    example resb 3
```

而下面为名为`arr`的变量保留了`10`乘`8`字节（也就是`80`字节）的未初始化空间：

```x86asm
section .bss
    arr resq 10
```

`section .bss`中的变量是可变的，也就是说，它们可读可写。

未初始化的数据可以用与已初始化数据相同的方式访问，即通过它的有效地址。
同样，它们也具有静态存储期，并且可以从同一个源文件中的任何函数访问（如果声明为`global`，也可以从其他源文件访问）。

## 使用 lea 指令访问数组地址

正如前面某个概念所介绍的，`lea`指令会计算出一个有效的内存地址。
它可以用相同的语义来计算数组中任意元素的地址。

注意，在相对寻址中，往往需要先把变量的地址加载到某个寄存器，然后再构成更复杂的地址：

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea`的优点之一是，它用地址运算的方式算出一个值，而不会真正访问该地址处的内存。
因此，即使没有任何寄存器保存着内存地址，它也能用来做算术运算：

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
