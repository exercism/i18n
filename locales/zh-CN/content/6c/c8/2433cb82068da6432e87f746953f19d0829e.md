# Docker

我们的 Analyzer 以 Docker 镜像的形式部署。

请先阅读[通用的工具 Docker 说明](/docs/building/tooling/docker)，了解它们的工作方式。

## 集成

当我们运行 Analyzer 来分析一份解答时，执行的 Docker 命令如下：

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-analyzer" \
        "${exercise_slug}" "/solution" "/output"
```

可以看到，我们向该 Docker 镜像传入了三个实参：

1. 练习的 slug
2. 解答目录的路径
3. 输出目录的路径

## 约定

我们所有 Analyzer 在实现时都遵循以下约定：

- `Dockerfile` 位于代码仓库的根目录。
- 工作目录应为 `/opt/analyzer`。
- 入口点是 `/opt/analyzer/bin/run.sh`
- `/opt/analyzer/bin/run.sh` 脚本接收 3 个实参：
  1. 练习的 slug
  2. 解答目录的路径
  3. 输出目录的路径

更多信息请参见[接口](/docs/building/tooling/analyzer/interface)。

```exercism/note
新的 analyzer 代码仓库默认会采用这些约定。
```
