# 绑定例程

```sather
   part : ROUT{STR}:STR := bind(shout(_));
   part.call("who's there");
```

## bind

`bind`接收一个调用，其中任何部分都可以用`_`代替。不是`_`的部分会**立即**求值并保存下来；每个`_`都会按书写的顺序成为绑定例程的一个实参。

```sather
   bind(repeat(2, _))         -- ROUT{STR}:STR
   bind(repeat(_, "Ha"))      -- ROUT{INT}:STR
   bind(repeat(_, _))         -- ROUT{INT,STR}:STR
```

## 类型

| 类型 | 接收 | 返回 |
| --- | --- | --- |
| `ROUT:INT` | 无 | `INT` |
| `ROUT{STR}` | 一个`STR` | 无 |
| `ROUT{STR}:STR` | 一个`STR` | 一个`STR` |
| `ROUT{INT,INT}:BOOL` | 两个`INT` | `BOOL` |

`ITER{...}`是同一套思路用在迭代器上。

## call

`call`补齐剩下的实参。不返回任何值的绑定例程也用同样的方式调用，也就是作为一条语句。

## bind 要写在赋值的右侧

可以把`bind`声明到变量里，也可以把它作为实参传进去：

```sather
   part ::= bind(shout(_));                -- yes
   part : ROUT{STR}:STR := bind(shout(_)); -- yes
   rehearse("line", bind(shout(_)));       -- yes
```

但不能直接把它写进`return`：

```sather
   return bind(shout(_));                  -- does not parse
```

先把它放进变量，再返回那个变量。错误信息会指向`bind`并提到下划线，光看这一行本身是看不出来的。

## 哪些地方会用到它们

凡是需要提供行为的地方，标准库都会接收它们：

```sather
   names.sort_by(bind(shorter(_, _)));
   scores.count_if(bind(over(10, _)));
   scores.find_if(bind(is_even(_)));
```

排序是最清楚的例子：`sort_by`知道怎么排序，却完全不了解你心目中的顺序，而绑定例程正是让二者接上的方式。

## 这个编译器的一处限制

Sather 1.2 没有实现**分派**绑定例程，也就是在抽象类型的变量上绑定例程。编译器会把这一点说得很明白：

```
Dispatched bound routines are not implemented yet
```

在具体类型或类上绑定就没有问题。这也是为什么这个 track 自带的测试框架宁可手写异常检查，也不用绑定例程。

## 绑定例程还是抽象类？

两者都能让调用方提供行为。

绑定例程就是一个例程，不需要类，而且就写在用到它的地方。抽象类则携带多个例程和一些状态；当要提供的东西不止一个部分时，它值得这点麻烦。

要交出的是一个例程：绑定它。要交出的协作者有多个例程：写一个类。
