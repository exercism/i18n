# 简介

二进制位最终直接对应到你 CPU 或内存中的晶体管，以及每个晶体管是“开”还是“关”。

底层操作，俗称“摆弄二进制位”，在系统级语言中尤为重要。

像 Kotlin 这样的高级语言通常会把这类细节抽象掉。不过，Kotlin 也提供了一组基本的位级运算[ref-bitwise]。

## 位移运算

`Int`或`Long`类型，无论是有符号还是无符号，都可以表示为一串 1 和 0，并按比特序列进行操作。

可能出乎意料的是，在 Kotlin 中，`Byte`或`Short`类型与大多数按位运算并不兼容。
下面所有示例都使用 32 位整数（`Int`或`UInt`）。

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

位移就是把所有位向左或向右移动指定的位数。
一些位从一端掉出，另一端则用 0 或 1 补齐。

- 用`shl`左移：补 0。
- 用`shr`或`ushr`右移：对正数补 0（负数的情况稍后介绍）。

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

每次左移都会让值翻倍，每次右移都会让值减半（结果会被截断）。
用十进制表示会更明显：

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

这种位移比“正规”的算术运算快得多，因此这项技巧在底层编码中非常流行。

处理_负整数_时，我们需要更小心一些。

负值以[二进制补码][wiki-2complement]形式存储，也就是说最左边的位是 1。
左移没有问题，但右移时，最左边的那些位该怎么补呢？

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

`shr`运算符执行[算术移位][wiki-arithmetic]，会保留符号位。

`ushr`运算符执行[逻辑移位][wiki-logical]，补 0，就好像这个数是无符号的一样。

## 按位逻辑

我们在[布尔概念][concept-booleans]中看到，运算符`&&`（与）、`||`（或）和`!`（非）用于布尔值。

还有一些对应的运算符`and`、`or`、`xor`（[异或][wiki-xor]），用来比较两个整数中的各个位，以及一个`inv`（取反）函数，用来翻转所有位。

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
