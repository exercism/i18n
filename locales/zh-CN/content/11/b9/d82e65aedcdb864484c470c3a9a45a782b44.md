# 说明

Andrew 是公司里的一名开发者，最近为一个数据库迁移工具写了一个轻量的 SQL 查询生成器。他最初那个简单的实现，处理小规模数据时完全没问题。但在大规模的生产迁移中，应用开始占用过多内存，在重负载下也撑不住了。对应用做了性能分析之后，Andrew 意识到，在循环里使用普通的字符串拼接，会迫使 Go 不断地重新分配内存。现在他需要你帮忙，用 Go 的 `strings.Builder` 重构这个工具，让它能够良好地扩展，处理大量文本时不会把内存堆压垮。

## 1. 生成 SELECT 查询

实现 `BuildSelectQuery` 函数。它接收一个表名（`string`）和一个列名切片（`[]string`），返回一条完整成形的 SQL `SELECT` 语句，以分号结尾。如果列切片为空或是 `nil`，查询就回退到用 `*` 通配符来选择所有列。

```go
columns := []string{"id", "name", "email"}
BuildSelectQuery("users", columns)
// Function return: "SELECT id, name, email FROM users;"

BuildSelectQuery("orders", nil)
// Function return: "SELECT * FROM orders;"
```

## 2. 生成批量 INSERT 语句

实现 `BuildBatchInserts` 函数。它接收一个表名（`string`）和一个表示数据库各行的二维切片（`[][]ColumnValue`）。一行中的每个元素都把某个具体的列名和它的字符串值关联起来。函数必须返回一个切片，里面是一条条单独的 `INSERT` SQL 字符串。这种结构化的切片格式保证了查询输出顺序可预测且稳定。如果输入的行切片为空，就返回一个空的字符串切片。如果其中某一行本身为空，就跳过它。`VALUES` 子句里的字符串值必须用单引号 `'` 括起来。

```go
rows := [][]ColumnValue{
    {
        {Column: "title", Value: "Book"},
        {Column: "price", Value: "100"},
    },
    {
        {Column: "title", Value: "Magazine"},
        {Column: "price", Value: "15"},
    },
}

BuildBatchInserts("products", rows)
// Function returns string slice: [
//   "INSERT INTO products (title, price) VALUES ('Book', '100');",
//   "INSERT INTO products (title, price) VALUES ('Magazine', '15');"
// ]
```
