# 简介

我们在之前的“概念”中看到，Julia 里的类型构成一个层级结构，最顶层是`Any`。

像`Number`这样的抽象类型有子类型，但自身不能被实例化。把变量设置为某个抽象类型，会_约束_该变量的值必须是这个抽象类型的某个子类型。例如：

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

这为约束哪些输入有效提供了一种灵活性。

可是，假设我们希望一个变量既能接受整数值，也能接受字符串值呢？这两种类型不在层级结构的同一个分支上。

我们可以把类型设为`Any`，或者让它默认就是`Any`，但这样一来就完全失去了对允许类型的控制。

有更好的办法：`Union{ }`语法，在大括号里列出两个或更多类型。

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

另一个例子在函数签名里使用了同样的类型联合：

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

这里我们给这个类型起了个名字，这样可以提供方便的简写，但并非必需。函数`g(z::Union{Integer, String}) = z^3`的行为是一样的。

关于函数签名，在“多重分派”概念里还会讲很多。

## 与 nothing 的联合

其他几种语言也有“可能包含值、也可能不包含值”的类型，名字像`Option`、`Nullable`或`Maybe`。

Julia 没有专门的语法来处理这件事，但类型联合是同一个想法的推广。

我们在`Nothingness`概念中看到，Julia 有多种表示“非值”的方式，包括`nothing`和`missing`。这两个都可以放进类型联合里。

例如，在定义某种链表时，我们需要一种方式，在没有更多节点时结束链表。`Nothing`是单例值为`nothing`的类型，而下面这个 Node 定义可以标示链的结束：

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

类似地，`missing`可以用作缺失值的占位符，尤其是在向量这类集合里。下面这个例子非常牵强，但缺失值在真实世界的数据集中很常见。

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
