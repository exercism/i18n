## <a name="virtual-environments"></a>虚拟环境

Python 虚拟环境提供了轻量级的运行时和包隔离。
它可以帮助你整理项目，把你安装的 Python 包集中放在某个特定的环境目录里。
不同的环境可以保存不同版本的 Python 运行时，以及各自的项目或库依赖。
这样可以避免因为给某个项目升级某个库、却“破坏”了另一个项目的依赖而引发的 bug 和不兼容问题。

如今在用的*虚拟环境*和*类虚拟环境*工具非常多，而且用[内联脚本元数据][PEP723]、[dev containers][dev containers] 或 [docker][docker] 来替代虚拟环境的做法也越来越流行。
重要的是多尝试不同的策略，找到适合你开发风格和项目需求的那一种。
不要以为这里的策略是放之四海而皆准的，也别以为它们是你唯一的选择。
如果想了解这里没有提到的更多工具，可以看看 [Bas Nijholt 的这篇博客文章][bas nihholt]，并保持好奇心。


这里我们要介绍三种主要的*虚拟环境*工具：Python 标准库中的 [`venv`][venv]、第三方的 [`conda env`][condaenv]（使用 [`conda`][conda] 包管理器以及（_通常_）Anaconda Python 发行版），还有第三方用来替代 `pip` + `venv` 的 [`uv`][uv]。
这三种工具使用和/或安装起来都相当简单。

此外，[`PyEnv`][pyenv]、[`Poetry`][poetry] 和 [virtualenvwrapper][virtualenvwrapper] 也能帮你在一台机器上管理多个 Python 版本和多个 Python 环境。

### <a name="creating-a-virtual-environment-with-venv"></a>用 `venv` 创建虚拟环境

要用 `venv` 创建虚拟环境，先 `cd` 到你想存放环境的目录。
这个目录应当**与项目代码分开**，而且**不要**把它提交到版本控制。
接下来，运行 `venv` 命令，并给出你想存放这个特定**环境**的文件夹名称。
常见的约定是把这个文件夹命名为 `<project-name-here>_venv`：

**Windows**

```powershell
PS C:\Users\foobar> py -m venv {name_of_virtualenv}
```
要激活虚拟环境，请运行以下命令：

```powershell
PS> .\{name_of_virtual_env}\Scripts\activate.bat
(venv) PS> _
```

<br>

**Linux/MacOS**

```bash
$ python3 -m venv {name_of_virtualenv}
created virtual environment ... in 8568ms
```

要激活虚拟环境，请运行以下命令：

```bash
$ source {name_of_virtual_env}/bin/activate
(venv) $ _
```

`venv` 激活后，你就可以在环境“内部”运行 `pip` 命令来安装包。
安装的包会与这个 `venv` 的 Python 版本关联，并存放在 `{name_of_virtual_env}/Lib` 里面。

要*停用*虚拟环境，可以调用 `deactivate` 脚本，它和 `activate` 位于同一个目录。

### <a name="creating-a-virtual-environment-using-conda"></a>用 `conda` 创建虚拟环境

*最新版本的 `conda` 可以通过 [miniconda][miniconda] 安装。*
这份 [`conda` 速查表][conda-cheatsheet]非常有用，[`conda` 文档][conda-docs]也一样。

`conda` 最初是作为“科学 Python”的流行发行版 [`Anaconda distribution`][anaconda] 的 Python 包管理器而创建的，后来被通用化并不断扩展。
conda 环境与 `venv` 类似，关键区别在于 conda 除了 Python 之外，还能为许多其他编程语言创建虚拟环境并安装包。

conda 支持的语言包括 `R`、`JavaScript`、`Ruby`、`Fortran`、`C/C++`、`Scala`、`Java` 等。
想比较 conda 和 venv 的命令，可以查看 conda 的[命令参考][conda command ref]。

### <a name="uv">UV

用 uv 处理项目：[uv][uv-docs]

`uv` 是 [Astral][astral] 用 [Rust][rust programming language] 编写的 Python 包与项目管理工具。
它的设计目标是取代 `pip`、`venv`、`poetry` 以及其他 Python 打包和依赖管理工具。
与 `Conda` 或 `Mamba` 不同，uv 只专注于 Python。
不过，uv 确实支持构建用 Fortran 等其他语言编写的 Python 扩展模块。
Astral 也是流行的 [Ruff][ruff] linter 和 [TY][ty]（一个用于 Python 类型提示的静态类型检查器）的开发者，两者都用 Rust 编写。


这里就不展开细讲了，[UV 文档][uv documentation]是你了解安装和配置的最佳来源。

### <a name="virtual-environment-wrapper">虚拟环境包装工具

文档和背景资料：[virtualenvwrapper][virtualenvwrapper]。

`virtualenvwrapper` 包在 `venv` 之上工作，让你能在一个地方管理所有虚拟环境。
你可以用 `lsvirtualenv`（_列出所有环境_）和 `mkvirtualenv`（_创建一个环境_）这类类 Unix 命令来创建、复制、删除和切换环境。
它还允许你通过扩展添加额外的管理工具。
你甚至可以通过[这个教程][venv wrapper tutorial]为它编写自己的扩展。

<br>

### <a name="pyenv"></a>PyEnv

`pyenv` 是流行的 `rbenv`/`ruby-build` 工具为 Python 修改而来的分支。
它本质上是一组脚本和 shim，让你可以在全局和用户级别设置 Python 版本。
它力求遵循 Unix 的传统：一个单一用途、不张扬的工具，把一件事做好。

`pyenv` 以及 `pyenv` 文档可以在 [GitHub][pyenv on github] 上找到。

### <a name="visual-studio-code"></a>Visual Studio Code

[Visual studio code (VS Code)][vscode] 是 Microsoft 推出的免费代码编辑器。
它对[虚拟环境/conda 环境][virtual environments in vscode]以及 [`docker`][docker in vscode]（_通过 [docker 插件][vs code docker plugin]_）都提供了出色的支持，还能通过许多不同的插件扩展出[测试][python testing in vscode]、[代码检查][linting python in vscode]、[格式化][formatting python in vscode]和 [Web 开发][python web dev in vscode]等功能。

#### <a name="python-for-vs-code"></a>VS Code 的 Python

_扩展 ID：ms-python.python_

![VS Code 上的 Python 扩展标题](https://raw.githubusercontent.com/exercism/python/main/docs/img/VSCode-EXT-Python-Header.png)

付费版还支持 [Django 开发][pycharm django dev]、[Docker 开发][pycharm docker] 和[数据库集成][pycharm database tools]。

### <a name="spyder-ide">Spyder IDE

[Spyder][spyder-ide] 是一款面向科学社区的跨平台、免费开源 Python 集成开发环境。
它通常随 Anaconda 的 Python 发行版一起提供，但也可以[单独安装][spyder standalone installers]，并与任意版本的 Python 搭配使用。
我们推荐单独安装，以确保最大的灵活性，并避免包冲突。

Spyder 完全支持 `venv` 和 `conda` 环境。
它内置 [IPython][ipython] 交互式终端和交互式调试器，并强大地支持在编辑器内绘图和数据探索。
额外的代码补全和检查由 [kite][kite] 提供。
与 [Jupyter Notebooks][spyder notebook plugin] 和[测试工具][spyder unittest plugin]的集成由社区开发的插件提供。
你也可以使用 Spyder API 编写[自己的插件][writing spyder plugins]。

### <a name="vim"></a>Vim

[Vim][vimdotorg] 是 Unix 标准 `vi` 文本编辑器的免费“改进”版本。
它可用于各种各样的操作系统和 Linux/Unix 发行版。
Real Python 上有一份很棒的[安装和设置指南][vim setup at real python]，[vimsheet][vim cheat sheet]、[glump][glump vim cheatsheet] 和 [rtorr][rtorr vim cheat sheet] 上也有便捷的速查表。


即使你决定不用 `vim` 编辑 Python 代码，也建议你熟悉一组基本命令。
在 Linux 和 Unix 发行版中，`vim` 或 `vi` 常常是“基础”或“默认”文本编辑器，在这些系统上它还是 `git` 提交信息（_以及其他东西_）的默认编辑器。
你很可能遇到这种情况：在一台 *nix 系统上，手头只有 `vi` 可用，却需要编辑一个配置文件。所以，懂得如何[退出 vim][how do I quit vim]（_至少_）是一项不错的防身技能。
