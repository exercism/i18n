# 关于

## 表示、字符与整数

和其他简单类型（`int`s、`bool`s 等）一样，`char`也有一个伴随类型或别名类型，在这里就是 `System.Char`。

实际上，它是一个带有 16 位字段的 `struct`，并且默认不可变。

`char`有一些实例方法，例如 `Equals`、`ToString` 和 [`CompareTo`][compare-to]。

`char`和[`ushort`][uint16]的位宽相同，但二者通常不像在某些语言中那样可以互换使用。`ushort`必须显式强制转换为 `char`。

值得一提的是，`char`可以进行算术运算，运算的结果是整数。

显然，8 位的 `byte` 和 16 位的 `char` 之间并不等价。

## 用法

`char`通常很容易使用。

可以用单引号把它定义为字面量：

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

可以用（从 0 开始的）下标从字符串中取出单个 `char`：

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

遍历字符串时，每一步都会返回一个 `char`：

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

如上所示，`char`可以强制转换成它的 `int` 值。对其他文字的字符来说，这样做也（*至少在部分情况下*）可行：

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

比较字符时，使用的是底层的 Int16：

```fsharp
'A' < 'D'
// => val it: bool = true
```

另外，`int` 也可以强制转换成 `char`：

```fsharp
char 77
// => val it: char = 'M'
```

`System.Char` 库包含 .NET 语言所期望的整套[方法][Char-methods]，例如大小写转换（但请留意下一节提到的注意事项）：

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

.NET 库可以帮助从字符串中提取 `char`，这里用到的是 `Seq` 方法：

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

把字符数组转换成字符串有多种方式，下面列举几种：

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

关于 `char` 的通用信息可以在这里找到：

- [字符文档][chars-docs]：`char` 的参考文档。

不过，`char` 有不少粗糙之处，下面会详细说明。这些粗糙之处主要源于两方面的对立：一方面是完整的 Unicode 标准，另一方面是历史上对文本的表示方式，以及性能和内存占用。

## Unicode 相关问题

处理字符串时，如果[`System.String`][System-string]库方法可用，就应当寻找并使用它们，而不是把字符串拆成一个个字符。

有些文本“字符”由不止一个 `char` 组成，因为 Unicode 标准有超过 65536 个码点。例如，某些测试中出现的表情符号包含 2 个 `char`，因为它们由[代理项][surrogates]字符组成。

此外，还有组合序列：在某些情况下，一个带重音的字符可能由一个 `char` 表示基础字符、另一个 `char` 表示重音符号。

如果必须处理单个字符，应当尽量使用库方法，例如 [`System.Char.IsControl`][is-control]、[`System.Char.IsDigit`][is-digit]，而不是做那种天真的比较，比如检查某个字符是否在 '0' 和 '9' 之间。

例如，注意 '٢' 是阿拉伯数字 2。`IsDigit` 对阿拉伯数字会返回 true，所以在做验证时，需要清楚说明可接受的输入范围。

即使使用 `System.Char` 库方法，在处理相对冷门的语言时，它们的行为也可能和你的预期不符。

要把字符串安全地拆成显示用的“字符”，一种方法是使用 [`StringInfo`][string-info] 和 [`GetNexttextElement`][get-next-text-element] 之类的方法。在处理全球化/本地化时，这可能是必要的。

当 Unicode 字符的标量值很重要时（比如你在自己实现一套编码系统），另一种做法是使用 [Rune][runes]。不过，如果你知道自己处理的字符范围不包含代理项或组合字符序列（例如拉丁字母 ASCII），并且输入经过充分验证，就可以避免这样做。

同样，最理想的情况是能够使用 `String` 的库方法。

如果你真的落到不得不处理 Unicode 各种细枝末节的地步，那么[这篇文章][char-encoding-net]是一个不错的起点。

## 全球化

如果你的工作环境需要处理多种区域性，或者区域性在代码的某些部分很重要、在其他部分却不重要，那么就要注意 [`ToUpper`][to-upper] 和 [`ToLower`][to-lower] 接受区域性参数的重载，以及 [`ToUpperInvariant`][to-upper-invariant] 和 [`ToLowerInvariant`][to-lower-invariant]，它们会给出不受当前[区域性][culture-info]影响的一致结果。
