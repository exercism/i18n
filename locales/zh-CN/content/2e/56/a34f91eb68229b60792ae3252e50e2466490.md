# 异常

```sather
   raise "Unknown prop: " + prop;
```

```sather
   protect
      ...
   when $STR then
      #OUT + exception.str;
   end;
```

## raise

`raise`接受任何对象。抛出`STR`是最简单的情况，也是这个练习采用的做法。自定义的类能携带更多信息（是哪个 prop、原本想要多少个），代价是需要找个地方来定义它。

异常会向外穿过每个调用者，直到某个`protect`把它捕获。如果没有捕获，程序就会停止并打印它。

Sather 不会记录一个例程可能抛出哪些异常，也不会强制调用者处理它们。例程的类型中没有任何东西表明它可能失败。

## protect

```sather
   protect
      body
   when $STR then
      ...
   when SOME_CLASS then
      ...
   end;
```

各个分支按顺序依次尝试，第一个类型与所抛出值匹配的分支会执行。`exception`就是那个值，并且只在分支内部的作用域中有效。

没有匹配分支的`protect`不会捕获异常，异常会继续向外传播，就好像那个`protect`根本不存在一样。

## 在哪里捕获

要在确实能做些事情的地方捕获。一个吞掉异常、然后拿一个瞎编的值继续往下走的`protect`，会把一次响亮的失败变成一次悄无声息的错误答案，而后者更糟。

```sather
   -- almost always wrong
   protect
      return risky;
   when $STR then
      return 0;
   end;
```

## 异常还是契约？

两者都关乎出错的情况，但适用的场景正好相反。

**异常**用于那些确实可能发生、并且调用者合理地无法阻止的情况，比如表中缺少某个 prop，或者某个文件不存在。

**契约**（也就是下一个练习）用于那些绝不应该发生的情况，比如调用者传入了负的重量，它是一条判定：调用者存在 bug。契约只在被要求时才检查，而一旦被违反，程序会直接停止，而不是抛出一个可以捕获的东西。

大致来说：如果谨慎的调用者仍然可能碰到它，就抛出异常。如果碰到它意味着调用者写错了，就把它放进契约里。
