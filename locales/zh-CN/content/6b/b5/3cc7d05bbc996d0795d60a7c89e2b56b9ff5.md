# 关于

Go 中的切片类似于其他语言中的数组。
它们存放同一具体类型（或接口）的若干元素。

Go 中的切片以数组为基础。
数组的大小是固定的。
而切片则不同，它是对数组元素的一种灵活视图，大小可以动态变化。

切片的写法是`[]T`，其中`T`是切片中元素的类型：

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

你可以用方括号写法获取或设置指定从零开始的下标处的元素：

```go
withData[1] = 5
x := withData[1] // x is now 5
```

你可以通过取一段元素，从已有切片创建一个新切片。
同样使用方括号写法，但要同时指定起始下标（包含）和结束下标（不包含）。
如果不指定起始下标，它默认为 0。
如果不指定结束下标，它默认为切片的长度。

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

你可以使用`append`函数向切片中添加元素。
下面我们把`4`和`2`追加到`a`切片中。

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append`始终返回一个新的切片；当我们只是想向已有切片追加元素时，通常会把返回值重新赋给那个作为第一个参数传入的切片变量，就像上面那样。

`append`也可以用来合并两个切片：

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## 切片中的下标

操作切片的下标时，始终应该通过某种检查来确保该下标确实存在。
否则会导致整个程序崩溃。

## 空切片

`nil`切片就是默认的空切片。
与不含任何值的切片相比，它没有任何缺点。
`len`函数可以作用于`nil`切片，无需初始化就能往里添加元素，等等。
如果要新建切片，优先使用`var s []int`（`nil`切片），而不是`s := []int{}`（空的、非`nil`切片）。

## 性能

如果要迭代地填充切片，并且事先知道切片的最终大小，那么就有一个现成的提升性能的办法。
关键在于尽量减少内存分配的次数：内存分配开销相当大，当切片增长超出已分配的内存空间时就会发生。
最稳妥的做法是用`s := make([]int, 0, cap)`为切片指定容量`cap`，然后照常向切片`append`。
这样，容量为`cap`的元素空间会立即分配好，而切片的长度仍然为零。
实践中，`cap`常常是另一个切片的长度：`s := make([]int, 0, len(otherSlice))`。

## `append`不是纯函数

Go 的`append`函数为性能做了优化，因此不会复制传入的切片。
这意味着原切片（`append`的第一个形参）有时会被改变。
