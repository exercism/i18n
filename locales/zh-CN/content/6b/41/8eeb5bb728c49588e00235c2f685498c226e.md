# 关于

严格来说，[`Higher Order Function`][HOFunc]就是一个至少满足以下条件之一的函数：

- 接受一个函数作为它的实参之一。
- 返回一个函数作为它的结果。

在函数式编程的世界里，这个术语的用法往往更窄。
它通常指`filter`、`map`和`reduce`这类函数，它们会把传入的函数应用到集合的各个元素上。

## 对集合进行操作

学到这里，我们已经见过好几种方法，可以把某个操作应用到可迭代集合（比如 Vector）的所有元素上：

- 使用[循环][loops]（就像自数字计算诞生以来大多数编程语言所做的那样）。
- 使用[推导式][comprehensions]（Python 风格）。
- 使用[广播][broadcasting]（Julia 特有的语法，不过深受 R、Matlab 和 NumPy 的影响）。

本概念将重点介绍高阶函数（任何函数式语言里都有，比如 Haskell 或 F#）。

其他可行的方法还有：

- 递归（ML 系语言就是如此）。
  - Julia 支持这种做法，但如果没有尾调用优化，就有栈溢出的风险。
- 用宏进行元编程（传统上是 Lisp 的特性）。
  - 在高级 Julia 编程中它被广泛使用，但大多数情况下_要谨慎使用_。
  - 其他方案通常更容易编写，调试起来也容易得多。

## 过滤

[`filter()`][filter]函数接受一个返回布尔值的传入函数，并把它应用到集合上。
只有返回`true`的元素才会被包含在返回值中，返回值的类型与输入属于同一种_基本_类型（见下文）。

```julia-repl
julia> filter(iseven, 1:6)
3-element Vector{Int64}:
 2
 4
 6

# String is a collection of Chars, so String in -> String out
julia> filter(!isascii, "Hrōðgār")
"ōðā"

# tuple input -> tuple output
julia> filter(iseven, (1, 2, 3, 4, 5))
(2, 4)
```

对于多维数组，`filter`会把输入的维度展平，并返回一个 Vector：_这是“输出类型与输入类型一致”这条规则的主要例外_。

```julia-repl
julia> m
2×3 Matrix{Int64}:
 1  2  3
 4  5  6

julia> filter(isodd, m)
3-element Vector{Int64}:
 1
 5
 3
```

上面的例子用的是内置函数，但在这种场景下，使用[匿名函数][anonymous]也非常常见。

```julia-repl
julia> filter(x -> x % 3 == 0, 1:20)
6-element Vector{Int64}:
  3
  6
  9
 12
 15
 18
```

也有对应的原地版本 [`filter!()`][filter-bang]，本概念中的许多函数都是如此。

## 映射

[`map()`][map]函数通过把某个函数应用到每个元素上来转换一个集合。
在简单的情况下，它和[广播][broadcasting]很像，输出的形状与输入一致。

```julia-repl
julia> map(√, [1, 4, 9])
3-element Vector{Float64}:
 1.0
 2.0
 3.0

julia> map(x -> x^2 + 1, 1:4)
4-element Vector{Int64}:
  2
  5
 10
 17

julia> m
2×3 Matrix{Int64}:
 1  2  3
 4  5  6

julia> map(√, m)
2×3 Matrix{Float64}:
 1.0  1.41421  1.73205
 2.0  2.23607  2.44949
```

`map()`也能对多个集合逐元素地操作。

```julia-repl
julia> map(*, [1, 2], [3, 4])
2-element Vector{Int64}:
 3
 8
```

从概念上讲，我们可以把它看作先在多个输入集合上运行[`zip()`][zip]，再对中间结果的每个元素运行`map()`。
_这只是一个粗略的类比，不代表实际实现！_

和`zip()`一样，形状不匹配的集合会被截断到最小集合的维度。

有时我们只需要传入函数的副作用，比如写数据库，或者对数组执行`push!`。
这时可以用高阶函数 [`foreach()`][foreach]，它总是返回[`nothing`][nothingness]。

对于大型集合，`map()`的开销可能很大。
并行计算超出了本概念的范围，但了解一下 [`Distributed.pmap()`][pmap] 的存在也许有用：它能把计算分摊到一个工作进程池上。
在 Exercism 的测试运行器里，`Distributed`包_是_可用的。

## 归约

[`reduce()`][reduce]函数接受一个接收两个实参的函数，并把它应用到集合上，从而降低维度。

抽象地看可能有点绕，但想想`sum()`或`prod()`这类函数：它们接收一个集合，返回单个值。

```julia-repl
julia> sum(1:4) # add
10

julia> prod(1:4) # multiply
24
```

_这些专用函数经过高度优化，只要能用就应该用它们。_
其他例子还有`maximum()`和`minimum()`、逻辑函数`all()`和`any()`，以及许多统计函数。

_这里只是为了演示_，来看看用更通用的`reduce()`实现同样的功能（回想一下，中缀运算符`+`和`*`在内部其实就是函数）。

```julia-repl
julia> reduce(+, 1:4) # add
10

julia> reduce(*, 1:4) # multiply
24
```

和`sum()`以及其他聚合函数一样，`reduce()`可以接受一个可选的关键字参数`dims`，用来指定要归约的[维度][multidim]。

```julia-repl
julia> m
2×3 Matrix{Int64}:
 1  2  3
 4  5  6

julia> reduce(+, m; dims=1)
1×3 Matrix{Int64}:
 5  7  9
```

这些例子都很简单，因为加法和乘法既满足交换律（`1+2 == 2+1`），又满足结合律（`(1+2)+3 == 1+(2+3)`）。

但这远不是普遍规律！
就连减法和除法这样常见的运算都不满足结合律。

还有一个问题：在大型集合上，浮点数误差会不断累积，所以从左到右归约得到的结果，可能和从右到左略有不同。

Julia 的`reduce`函数采用哪个方向取决于具体实现，并不作保证。

如果想明确控制方向，还有 [`foldl()`][foldl] 和 [`foldr()`][foldr] 函数，名义上分别从“左”和“右”开始（对 Vector 来说，实际上是自上而下和自下而上）。

```julia-repl
julia> foldl(-, 1:3) # (1 - 2) - 3
-4

julia> foldr(-, 1:3) # 1 - (2 - 3)
2
```

注意，它们面向的是可以当作一维处理的集合，返回一个标量结果。
`foldl`和`foldr`不支持`dims`实参，只有`reduce`支持。

在并行计算中，归约函数的用法会变得更微妙，那时计算乱序是常态（不过这超出了本概念的范围）。

## MapReduce

把`map`操作和`reduce`结合起来，在各种编程领域都非常常见。

我们可以先依次运行`map`，再对中间集合运行`reduce`。
但这样做充其量只是效率不高，而且随着集合变大，扩展性会变得非常糟。

因此_强烈_建议改用二者合一的 [`mapreduce()`][mapreduce] 函数。
它可以实现一种性能好得多的算法，把 map 和 reduce 操作交织在一起执行。

第一个实参是用来做映射的函数，第二个实参是归约运算符。

```julia-repl
julia> mapreduce(x -> x^2 + 1, +, 1:3)
17

# equivalent to (2 + 5 + 10)
julia> sum(map(x -> x^2 + 1, 1:3))
17
```

MapReduce 操作在大数据系统（Hadoop、Spark 等）中尤其流行，因为它们能实时处理长度任意、未知的数据流，而不会让内存占用爆炸。

不出所料，Julia 也有 [`mapfoldl()`][mapfoldl] 和 [`mapfoldr()`][mapfoldr] 函数，用于方向很重要的场合。
