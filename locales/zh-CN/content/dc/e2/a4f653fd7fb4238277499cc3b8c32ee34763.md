# 说明补充

## 任务

实现两个过程。

- `custom_error_message message`抛出一个错误，`message`就是错误信息。
- `handle_error script`运行给定的脚本，并返回一个描述所发生情况的字符串：

  | 脚本……                            | 返回值                  |
  | --------------------------------- | ----------------------- |
  | 除以零                            | `"division by zero"`    |
  | 打开一个不存在的文件              | `"file does not exist"` |
  | 调用一个不存在的 proc             | `"proc does not exist"` |
  | 抛出任何其他错误                  | `"unknown error"`       |
  | 成功                              | `"success"`             |

## 抛出错误

Tcl 有两个用于抛出错误的命令。

```tcl
error "something went wrong"
throw {MYAPP BADTHING} "something went wrong"
```

`throw`要求第一个参数是一个_错误码_。
错误码是一个列表，用来告诉处理程序发生了什么类型的错误，这样处理程序不用解析消息文本就能作出响应。
它的内容由你决定：`{MYAPP BADTHING}`只是一个例子，任何非空列表都可以。
按惯例，它从一般排到具体。
处理程序用匹配的`try ... trap`模式（下面会讲到）来捕获它，例如`trap {MYAPP BADTHING}`，或者用`trap {MYAPP}`捕获所有`MYAPP`错误。
`error`把可选的错误码作为第三个参数：`error message ?info? ?code?`。

## 用`catch`处理错误

[`catch`][catch]运行一个脚本，返回一个整数_完成码_，而不是抛出错误：

| 完成码 | 含义       |
| ---- | ---------- |
| 0    | `ok`       |
| 1    | `error`    |
| 2    | `return`   |
| 3    | `break`    |
| 4    | `continue` |

```tcl
if {[catch {expr {1 / 0}} result options] == 1} {
    puts "error message: $result"
    puts "error code:    [dict get $options -errorcode]"
}
```
```none
error message: divide by zero
error code:    ARITH DIVZERO {divide by zero}
```

可选的第二个参数接收结果（或错误消息）。
可选的第三个参数接收一个_选项字典_，其中包含`-errorcode`和`-errorinfo`（堆栈跟踪）。

优点：

- 它小巧而灵活。
- 对简单情况很简短，例如`if {[catch {open $f} fh]} {...}`。

缺点：

- 完成码得自己检查。
  粗心地写成`if {[catch ...] != 0} { handle error }`，`return`、`break`和`continue`也会被当成错误。
- 你没有处理的错误会被悄悄吞掉，除非你自己重新抛出。
- 没有内置的办法，不管脚本成功还是失败都运行清理代码。

## 用`try`处理错误

[`try`][try]运行一个脚本，并把结果交给第一个匹配的处理程序。
可选的`finally`子句总会执行，所以很适合用来释放文件通道之类的资源。

```tcl
set fh [open $filename r]
try {
    set data [read $fh]
} on error {msg options} {
    puts "could not read $filename: $msg"
} finally {
    close $fh
}
```

优点：

- 结构清晰：每种结果对应一个处理程序。
- `finally`总会执行。
- 没有处理程序匹配的结果会原样交给调用者。

缺点：

- 对简单情况来说，比`catch`稍微啰嗦一点。

### `try ... on`与`try ... trap`的对比

处理程序有两类。

`on code {msgVar optionsVar}`匹配_完成码_：`ok`、`error`、`return`、`break`或`continue`。
每个错误的完成码都是`error`，所以`on error`分不清是除以零还是文件不存在。
你只能去看消息文本，而这很不可靠：消息是给人看的，在 Tcl 不同版本之间可能变化。

```tcl
try {
    expr {$a / $b}
} on error {msg} {
    if {[string match "*divide by zero*" $msg]} { ... }
}
```

`trap pattern {msgVar optionsVar}`匹配_错误码_。
当模式是`-errorcode`列表的前缀时，处理程序就匹配。
这样能可靠地挑出错误的类型。

```tcl
try {
    expr {$a / $b}
} trap {ARITH DIVZERO} {} {
    puts "division by zero"
} trap {} {msg} {
    puts "some other error: $msg"
}
```

空模式`trap {}`匹配任何错误。
处理程序按顺序检查，所以把兜底的那个放在最后。

## 找到错误码

`ARITH DIVZERO`的文档在哪里？
大多只在源代码里，不过 Tcl 会把它显示给你。
出错之后，全局变量`errorCode`保存着最近一次错误的错误码：

```none
$ tclsh
% set a 1; set b 0
% expr {$a / $b}
divide by zero
% set errorInfo     ;# this is the stack trace
divide by zero
    while executing
"expr {$a / $b}"
% set errorCode     ;# this is what we're after
ARITH DIVZERO {divide by zero}
```

在程序内部，可以从选项字典中取出：

```tcl
try {
    expr {$a / $b}
} on error {msg options} {
    puts [dict get $options -errorcode]
}
```

错误码的最后一个元素通常是一条人类可读的消息，或者引发错误的东西的名字。
把它从`trap`模式里去掉：用`{ARITH DIVZERO}`，不要用`{ARITH DIVZERO {divide by zero}}`。

### 一些常见的错误码

这张表并不完整。
用上面的方法就能找到其他任何错误的错误码。

| 情况             | 示例                  | 错误码                        |
| --------------------- | ------------------------ | ----------------------------- |
| 除以零                | `expr {1 / 0}`           | `ARITH DIVZERO ...`           |
| 数学域错误            | `expr {sqrt(-1)}`        | `ARITH DOMAIN ...`            |
| 找不到文件            | `open nosuchfile r`      | `POSIX ENOENT ...`            |
| 权限不足              | `open /root/x w`         | `POSIX EACCES ...`            |
| 未知命令              | `no::such::proc`         | `TCL LOOKUP COMMAND name`     |
| 未知变量              | `set nosuchvar`          | `TCL LOOKUP VARNAME name`     |
| 参数个数不对          | `string length a b`      | `TCL WRONGARGS`               |
| 无效的字典            | `dict size {1 2 3}`      | `TCL VALUE DICTIONARY`        |
| 无效的列表            | `llength "a \{b"`        | `TCL VALUE LIST ...`          |

`POSIX`错误码使用操作系统的`errno`名字，例如`ENOENT`、`EACCES`和`EEXIST`。

## 提示：脚本在哪里运行

`handle_error`从调用者那里收到一个脚本。
如果你用`try $script`运行它，它会在`handle_error`的作用域里求值，而不是调用者的作用域。
要在它写就的位置求值，请用[`uplevel`][uplevel]：`try {uplevel 1 $script} ...`。
