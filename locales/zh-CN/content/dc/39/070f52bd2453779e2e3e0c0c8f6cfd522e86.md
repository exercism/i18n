# 简介

在 Go 1.18 中，Go 加入了对**泛型**的支持。
泛型让你能编写适用于多种类型的函数和数据结构，而无需重复代码。

## 为什么需要泛型？

在 Go 中，函数和类型通常只针对特定的类型，比如`int`或`string`。
在泛型出现之前，要支持多种类型有两种选择。
第一种是编写多个名字不同的函数，比如`SumInts`和`SumFloats`。
这种做法会产生重复的代码，而且很难维护。
第二种是使用空接口`any`（`interface{}`）。
但空接口去掉了编译期的类型检查，还需要在运行时做类型断言。
泛型既提供了类型安全，又避免了重复代码，从而解决了这个问题。

## 泛型函数

在函数名后面用方括号`[...]`加上**类型形参**，就定义了一个泛型函数。
下面是一个返回反转后切片的泛型函数示例：

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

在这个例子中，`T`是一个类型形参。
你可以把`T`看作真正类型的占位符。
方括号里的`any`关键字是一个**类型约束**。
约束告诉编译器`T`允许使用哪些类型。
这里的`any`表示`T`可以是任意类型。

### 调用泛型函数

调用泛型函数时，可以在方括号里传入实际的类型。
这个实际的类型叫做**类型实参**。

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

大多数情况下，Go 编译器能从函数实参自动推断出类型。
这个特性叫做**类型推断**。
有了类型推断，你就不必在方括号里写类型实参了。

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

在这个例子中，编译器看出`words`是字符串切片，因此推断出`T`是`string`。

## 类型约束

每个类型形参都必须有约束。
约束规定了哪些类型可以作为类型实参使用。
约束还决定了你能对该类型的值执行哪些操作。

### `any`约束

`any`约束允许任意类型。
在 Go 中，`any`是空接口`interface{}`的别名。
因为`any`允许所有类型，所以函数只能执行对所有 Go 类型都成立的操作。
例如，如果有两个持有切片的`any`值，它们不能用`==`比较，因为切片不能用`==`比较。

### `comparable`约束

Go 提供了一个叫做`comparable`的内置约束。
`comparable`约束允许任何支持`==`和`!=`运算符的类型。
可比较的类型包括布尔值、数字、字符串、指针、通道，以及由可比较类型构成的结构体或数组。

下面是一个检查切片中是否包含某个特定元素的函数示例：

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

因为`T`使用了`comparable`约束，所以`elem == target`是合法的。
如果把`comparable`换成`any`，编译器就会报错。

### 用接口类型集自定义约束

从 Go 1.18 开始，接口除了可以定义方法，还可以定义类型集合。
你可以用竖线字符`|`在接口中列出允许的类型。

```go
type Number interface {
    int | int64 | float64
}
```

现在就可以把`Number`用作函数的约束：

```go
func Double[T Number](value T) T {
    return value * 2
}
```

因为`Number`中的所有类型都支持`*`运算符，所以 Go 允许在函数里写`value * 2`。

### 底层类型近似`~`

有时你会基于基本类型创建一个自定义类型：

```go
type MyInt int
```

上面定义的`Number`约束只允许`int`、`int64`和`float64`这几个确切的类型。
如果把`MyInt`值传给`Double`，编译器会报错，因为`MyInt`与`int`并不匹配。
要允许底层类型是`int`的所有类型，在类型前加一个波浪号`~`：

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

现在就可以把`Double`用在`MyInt`类型的值上了。

### `cmp.Ordered`约束

标准库在[`cmp`包][doc-cmp]中提供了`cmp.Ordered`约束。
`cmp.Ordered`约束允许任何支持比较运算符`<`、`<=`、`>`和`>=`的类型。

## 泛型类型

你还可以用类型形参定义泛型类型，比如结构体。
下面是一个泛型`Stack`数据结构的示例：

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

声明泛型类型的变量时，必须在方括号里给出类型实参：

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

类型推断只对泛型函数有效。
创建泛型类型的值时，必须始终指定类型实参。

## 何时使用泛型

泛型是一个强大的功能，但并不是每个问题都需要用它。

以下情况适合使用泛型：
- 你在构建适用于任意元素类型的数据结构，比如树、链表或缓存。
- 你在编写对任意类型的切片或映射进行操作的实用函数，比如过滤、排序或查找。
- 几种类型需要完全相同的实现，而你又想要编译期的类型安全。

以下情况则更适合使用接口：
- 你关心的是行为和方法，而不是底层的数据类型。
  例如，如果要从各种来源（文件、网络、TTY）读取并处理数据，应该用`func Process(src io.Reader)`而不是`func Process[T](src T)`。
- 不同类型需要不同的方法实现来完成各自的工作。
