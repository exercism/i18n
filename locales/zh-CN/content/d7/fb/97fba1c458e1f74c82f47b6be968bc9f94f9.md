# 简介

大多数标量按位运算都有对应的打包版本。
它们的语法与 SIMD 整数运算大体相同，只是没有大小后缀：

| 指令 | 说明 |
|------|------|
| `pand` | 两个 128 位值的按位 AND |
| `por` | 两个 128 位值的按位 OR |
| `pxor` | 两个 128 位值的按位 XOR |

注意，并没有打包版的 `NOT`。
不过有一个 ANDN 运算，它会先对**目标**操作数取反（翻转其中所有位），再计算两个操作数之间的 AND。
可以把它理解为 NOT 与 AND 的结合：

| 指令 | 说明 |
|------|------|
| `pandn` | **取反后的**目标与源的按位 AND |

注意，按位运算组合的是两个不同操作数中同一位置上的位，因此通道边界不会改变结果。
这就是这些指令没有大小后缀的原因：寄存器表现为单个 128 位通道：

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
本概念中的所有指令都只计算位，不设置任何标志位。
后面的概念会讲到如何用打包值处理条件。
~~~~

## 逐通道移位

移位与纯按位运算不同，它确实会让位跨位置移动，因此需要一个通道大小来设定边界。
在每个通道内，它们的行为与标量版本相同，位绝不会从一个通道越到相邻通道：

| 指令 | 说明 |
|---------------------------|-------------------------------------|
| `psllw`, `pslld`, `psllq` | 逐通道逻辑左移 |
| `psrlw`, `psrld`, `psrlq` | 逐通道逻辑右移 |
| `psraw`, `psrad`          | 逐通道算术右移 |

注意，这些指令遵循打包整数运算的语法，包括大小后缀。
没有字节通道的移位，只有字、双字，以及四字（算术右移除外）。

打包移位与标量移位的一个区别在于运算名称：

- 不是 `shl` 和 `shr`，而是 `sll` 和 `srl`，即 **s**hift **l**eft（**r**ight）**l**ogical，逻辑左移（逻辑右移）。
- 不是 `sar`，而是 `sra`，即 **s**hift **r**ight **a**rithmetic，算术右移。

名称虽然不同，运算本身却是一样的：

- 逻辑右移在高位填入零。
  它等价于除以 2 的幂的无符号除法。
- 算术右移在高位填入符号位的值。
  它等价于除以 2 的幂的有符号除法，向负无穷方向舍入。
- 左移总是填入零（这就是不需要算术左移的原因）。

移位计数对每个通道都相同。
它可以是一个立即数，也可以是 `xmm` 寄存器的低 64 位：

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
当移位计数大于通道宽度时，它不会像标量 `shl`/`shr` 家族那样回绕，而只会产生零（对算术右移来说则是全符号位）。
~~~~

## 浮点按位运算

每个按位指令也都有一对以浮点命名的孪生指令，语法与我们已经见过的打包浮点运算相同：

| 整数名称 | 浮点名称 |
|--------------|----------------------|
| `pand`       | `andps`, `andpd`     |
| `pandn`      | `andnps`, `andnpd`   |
| `por`        | `orps`, `orpd`       |
| `pxor`       | `xorps`, `xorpd`     |

由于按位运算作用于位，实际上整数运算和浮点运算会算出相同的结果。
名称不同有两个原因：

1. 记录意图，就像我们会根据被复制的字节的性质，更倾向于选择 `movdqa`、`movaps` 或 `movapd` 一样。
2. 整数运算和浮点运算往往属于不同的执行域。
   同一执行域内的运算通常可以更快地串接执行。

浮点值没有移位运算。

## 浮点数的位表示

IEEE 浮点数的位表示与整数相差很大。

在无符号整数中，每一位的含义都是统一的：它表示与位下标对应的 2 的幂。
整数就是所有置位所对应的 2 的幂之和。
这就是为什么移位可以把数乘以或除以 2 的幂：我们只是在改变每个置位的下标。

在有符号整数中，大多数位的解释方式与无符号整数相同。
不过最高位是特殊的。
如果它被置位，我们不是把它加到其他位上，而是要减去对应的 2 的幂，结果就是一个负数。
实际上，要改变一个数的符号，概念上需要两步：翻转所有位（一次 `not`），再给结果加 1（一次 `inc`）。

浮点数中的位含义并不统一，需要根据位置以非常不同的方式解释：

| 字段    | 下标（32 位） | 下标（64 位） |
|----------|------------------|------------------|
| 符号     | 31               | 63               |
| 指数 | 30-23            | 62-52            |
| 尾数 | 22-0             | 51-0             |

得到的数由 `(-1)^sign * 1.fraction * 2^(exponent - bias)` 计算得出。
偏置取决于精度：

| 大小   | 偏置 |
|--------|------|
| 32 位 | 127  |
| 64 位 | 1023 |

在两种格式中，数的符号都完全由符号位决定。
改变浮点数的符号只需翻转这一位（一次 XOR 运算）。
取绝对值只需把它清零（一次将该位清零的 AND）：

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

注意，在这种位表示中，移位不会产生可预测且统一的结果。
尾数可能渗入指数，指数也可能渗入符号位。

不过，有时把表示的不同部分隔离开来分别处理会很方便。

例如，指数中的位应先被解释为无符号数，然后再从中减去偏置。
这意味着我们可以生成一个 32 位或 64 位整数，其底层的位表示对应着相应浮点格式中某个 2 的幂。
然后就可以用这个原始位表示去乘或除另一个浮点数。

例如：

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

反过来，我们也可以通过一个掩码执行 AND 来提取打包浮点数的指数，该掩码中只有指数位被置位，其余位都被清零。
再结合一次移位和一次减法，就能把每个通道的无偏指数算成一个有符号整数：

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
直接操作浮点数的原始位虽然在某些情况下很有用，但应谨慎进行。
只有当不存在上溢或下溢、且输入数为规范数时，对指数字段做加法或减法才是安全的。
另外，把有效的 `x` 加到 `0.0` 的指数字段上，得到的是 `2^(x - bias)`，而不是 `0.0 * 2^x`。
~~~~
