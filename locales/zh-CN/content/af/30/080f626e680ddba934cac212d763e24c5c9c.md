# 关于

除了字符类和量词之外，正则表达式还能描述文本的*结构*和*上下文*。这些特性位于同一个[`regexp`][regexp]词汇表中，并用`R/ /`字面量编写。

## 分组与选择

圆括号`( )`将模式的一部分分组，这样量词或`|`（“这个或那个”）就会作用于整个分组。分组后面的`?`使其变为可选：

```factor
USING: regexp ;

"abab"    R/ (ab)+/ matches? .             ! => t
"cat"     R/ cat|dog/ matches? .           ! => t
"$100.50" R/ \$\d+(\.\d{2})?/ matches? .   ! => t
"$100"    R/ \$\d+(\.\d{2})?/ matches? .   ! => t   (group optional)
```

## 锚点

```
^    ! start of the string
$    ! end of the string
\b   ! a word boundary
```

*单词边界*（`\b`）是单词字符（字母、数字或下划线）与非单词字符相遇的位置，包括字符串的两端。因此，`\bcat\b`只在`cat`独立出现时才匹配：

```factor
USING: regexp ;

"cat nap" R/ \bcat\b/ re-contains? .   ! => t
"scatter" R/ \bcat\b/ re-contains? .   ! => f
```

## 环视

*环视*测试某个位置之前或之后的内容，但不让这些字符成为匹配的一部分，它是零宽的：

```
(?=...)    ! lookahead
(?!...)    ! negative lookahead
(?<=...)   ! lookbehind
```

```factor
USING: regexp ;

"spent $100 and $25" R/ (?<=\$)\d+/ all-matching-subseqs .
! => { "100" "25" }

"up 5% then 12%" R/ \d+(?=%)/ all-matching-subseqs .
! => { "5" "12" }
```

## 选项

结束的`/`后面的选项字母会改变整个模式。`i`表示不区分大小写：

```factor
USING: regexp ;

"REFUND" R/ refund/i matches? .   ! => t
```

## 转换每个匹配项

`map-matches`对每个匹配项运行一个 quotation 并收集结果；`each-match`只为了副作用做同样的事。两者都把匹配项的`start`索引、`end`索引和整个字符串传给 quotation，因此`subseq`可以取出匹配到的文本：

```
map-matches ( string regexp quot: ( start end string -- obj ) -- seq )
each-match  ( string regexp quot: ( start end string --     ) --     )
```

```factor
USING: math regexp sequences ;

"a1 b22 c333" R/ \d+/ [ subseq length ] map-matches .
! => { 1 2 3 }
```

## Factor 不支持的功能

Factor 的正则表达式引擎没有**捕获组提取**（`( )`分组可以组织模式，但你无法读回它匹配到的文本），没有**反向引用**（`\1`），也没有**惰性/非贪婪**量词（`*?`、`+?`）。环视是捕获组的惯用替代方案：匹配你想要的部分，并通过它周围的上下文来识别。
