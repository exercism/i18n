# 关于

在 C# 应用程序中，随机性通常通过`System.Random`类来实现。

这篇[文章][system-random]是该主题的绝佳入门。

熟悉一个库类时，值得研究它的[文档][system-random]，了解其中的属性、方法及其重载。

这次编程练习凸显了几个要点：

- 随机数生成器不需要[种子][random-seedless]。
- `Random.Next()`可以生成一个范围内的整数。
- `Random.Double()`可以生成 0 到 1 之间的 double。
- `Next...()`、`Double()`和`Sample()`中的上界都是**不包含**的，所以`Random.Next(1,19)`会返回 1 到 18 的值，但不包括 19。
- 拿到随机数之后，你想怎么用它都行。

实现最后一点有 3 种模式：

- 你可以获取随机数，然后随意处理它。就这次编程练习而言，就是调用`Random.NextDouble()`再乘以 100。这篇[文章][random-use-case-array]讨论了如何从数组中随机选取元素。
- 你可以继承`System.Random`并重写`Sample()`方法。
- 你可以把`System.Random`的实例封装成自己类的一个成员，例如[用来生成布尔值][random-use-cases]。

`Random`生成的数字并不保证唯一。

[建议][random-thread-safety]将`System.Random`实例化为静态成员。但要注意，它并不是线程安全的。

你可能会看到一些文档不鼓励使用不带种子的构造函数。这主要针对的是 .NET Framework，而不是 .NET Core（_Exercism_用的就是它）。想了解完整的来龙去脉，可以看[这篇][random-multiple-instantiations]。

建议不要将`System.Random`用于加密或安全用途。参见这个[提供程序][crypto-provider]和这个[随机数生成器][crypto-rng]。

## 线程安全

在库 API 的语境下，“不是线程安全的”只是一种简略说法，意思是：如果你可能会通过多个并发的[线程][threading]访问该类的实例，就应该自己提供线程同步机制；如果是集合，则可以考虑使用该类的并发版本。缺少这些防范措施，就很可能会出现[竞态条件][so-race-conditions]。如果你的代码库没有使用多线程，将来也不太可能用到，那么这个警告就不必太在意。
