# 简介

泵、阀门、软管，任何持有操作系统资源（比如打开的文件、网络连接）的东西，用完之后都必须*释放*。Factor 的[`destructors`][destructors]词汇表把这些东西包进一个框架，保证清理一定会完成，即使错误在代码执行到一半时打断也不例外。

## 类和泛型词

一个类通过扩展`disposable`并实现`dispose*`泛型词来加入这个框架：

```factor
USING: accessors destructors kernel ;

TUPLE: pump < disposable opened ;

: <pump> ( -- pump )
    pump new-disposable t >>opened ;

M: pump dispose* f >>opened drop ;
```

`new-disposable ( class -- obj )`会分配元组，*并且*把它注册到框架里，这样在分配和下一个安全点之间发生的异常就不会泄漏资源。框架保证`dispose*`对每个对象**至多只运行一次**，重复调用`dispose`是空操作。

## 公开调用者使用`dispose`

```
dispose          ( obj -- )                ! release; safe to call twice
with-disposal    ( disposable quot -- )    ! scope one resource
with-destructors ( quot -- )               ! open a registry scope
&dispose         ( obj -- obj )            ! dispose on normal *or* failure exit
|dispose         ( obj -- obj )            ! dispose only if the scope unwinds
```

`with-disposal`是单资源形式：它把可释放对象压入，供内部引用使用，并在退出时释放。

```factor
USING: destructors io ;

<pump> [
    "pumping" print
] with-disposal
! pump released on the way out — even if `print` had thrown
```

需要管理多个资源时，打开一个`with-destructors`作用域，并逐一注册每次获取的资源。`&dispose`（和号）表示“退出时总是释放，无论成功还是失败”。`|dispose`（竖线）表示“**只在**失败时释放”，当成功路径会把资源交给接手的调用者时，这很有用。

```factor
[
    <pump> &dispose
    <pump> &dispose
    ! ... use the pumps ...
] with-destructors
! both pumps released
```

如果只想要一个不带注册表的 try/finally，[`cleanup`][cleanup]（位于`continuations`中）是更底层的原语，不过`with-destructors`才是现代 Factor 的惯用做法。
