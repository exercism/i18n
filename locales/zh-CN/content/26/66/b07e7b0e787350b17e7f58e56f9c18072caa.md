# 关于

## 字符

[字符编码][char-encoding]是一种特定的约定，用来把自然语言中的文本元素表示为字节序列。
这里的“文本元素”可以是自然语言中有意义的任何单位，例如字母、空格、标点、表情符号、表意文字等。

NASM（The Netwide Assembler，本课程使用的汇编器）支持使用 [ASCII][ascii] 定义数据。

NASM 中的字符常量最长可达 8 字节，可以用单引号（`'`）、双引号（`"`）或反引号（`` ` ``）来定义：

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

特殊字符必须用反引号定义，并用`\`转义：

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASM 还支持 [UTF-8][utf8] 中的 [Unicode 字符][unicode]，用`\u`或`\U`指定，并放在反引号中：

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

注意，x86-64 并没有把任何字符编码作为一个独立类型来内置支持。
汇编中的数据就是一串字节，把这些字节解释为字符、数字还是其他别的什么，完全由程序员来决定。

例如，ASCII 字符 '0' 是值为 48 的单个字节。
因此，把 48 存入一个字节，与存入 ASCII 字符 '0' 完全一样：

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

出于同样的原因，操作字符就是直接变换这些字节中的值：

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## 字符串

[字符串][string]是字符的序列。
在汇编中，它通常用数组来实现。

在 NASM 中，可以像声明任何数组那样声明字符串：

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

字符串与其他数组的一个区别在于，NASM 还支持声明字符串时不使用逗号（`,`）分隔各个值。
也可以让各个值与逗号交错混用：

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

注意，正如前面提到的，字符就是字节（在 Unicode 编码中则是字节序列）：

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

由于每个 ASCII 字符只占一个字节，在更宽的尺寸中后续的字节都是`0`。
例如，把`'a'`声明为 qword（8 字节），意味着第一个字节是`'a'`（`97`），其余七个字节全是`0`。

因此，下面这些写法完全等价：

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
在汇编中，字符串不会自动以 ASCII NUL 字符（值`0`）结尾。

与 C 之类的更高层语言交互时，程序员有责任确保在字符串末尾附加正确的终止符（如果有的话）。
~~~~

## 字符串指令

既然字符串就是数组，你就可以像操作任何数组一样操作它们，即显式地对内存解引用：

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

除此之外，还有一些指令用于在内存中的字节序列里加载、移动和存储值。
尽管被称为*字符串指令*，它们可以用于内存中的任何字节序列，也就是任何数组：

| 指令  | 作用                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | 把由`rsi`指向的内存位置中的值加载到`rax`                                                |
| [stos][stos] | 把`rax`中的值存储到由`rdi`指向的内存位置                                               |
| [movs][movs] | 把由`rsi`指向的内存位置中的值复制到由`rdi`指向的内存位置    |
| [cmps][cmps] | 把由`rsi`指向的内存位置中的值与由`rdi`指向的内存位置中的值进行比较 |
| [scas][scas] | 把`rax`中的值与由`rdi`指向的内存位置中的值进行比较                                |

注意，这些指令*不*接受任何显式操作数。
它们的操作数是隐式的。

一条经验法则是：

1. 当源操作数是内存位置时，其地址应存放在`rsi`中（`s`代表 source）。
2. 当目标操作数是内存位置时，其地址则应存放在`rdi`中（`d`代表 destination）。
3. 如果其中一个操作数不是内存位置，那它就是`rax`寄存器。

注意，这些指令会依据各自执行的特定操作，自动地对内存地址解引用。

它们都可以按不同尺寸操作。
用一个后缀来表明这个尺寸：

| 后缀 | 含义 | 尺寸    |
| :----: | ------- | :------ |
|  `b`   | 字节    | 1 字节  |
|  `w`   | 字    | 2 字节 |
|  `d`   | 双字   | 4 字节 |
|  `q`   | 四字   | 8 字节 |

例如：

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

它们还会按操作的尺寸更新所用到的地址。
这个更新依据**方向标志（DF）**的值进行：

- 如果`DF`被清零，地址会按操作的尺寸*增加*。
- 如果`DF`被置位，地址则会*减少*相同的量。

System V ABI 规定，方向标志必须在函数入口处清零。
所以，*默认行为是按地址递增的顺序读/写内存*。

指令 [cld][cld] 可以用来清零方向标志，而指令 [std][std] 则用来置位它：

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
按照 System V ABI，调用方期望任何被调用的函数返回后`DF`都是清零的。
如果你设置过`DF`，请务必在`ret`之前把它清零。
~~~~

### Lods

这条指令从地址存放在`rsi`中的内存位置*读取*，并把值复制到`rax`。

`rsi`中的值会按读取的字节数更新：

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

这条指令复制`rax`中的值，并把它*写入*地址存放在`rdi`中的内存位置。

`rdi`中的值会按写入的字节数更新：

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

这条指令从地址存放在`rsi`中的内存位置*读取*，并把值*写入*地址存放在`rdi`中的内存位置。
`rax`中的值不受这条指令影响。

`rsi`和`rdi`都会按从一个内存位置复制到另一个内存位置的字节数更新：

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

这条指令从地址存放在`rsi`中的内存位置*读取*，同时也从地址存放在`rdi`中的内存位置*读取*。
然后它比较这两个值，并按照`cmp`的方式更新标志。

`rsi`和`rdi`都会按从两个位置读取的字节数更新：

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

这条指令把`rax`中的值，与它从地址存放在`rdi`中的内存位置*读取*到的值进行比较。
然后它按照`cmp`的方式更新标志。

`rdi`中的值会按读取的字节数更新：

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

除了这些之外，[rep][rep] 指令并不直接与内存交互。
相反，它可以作为前缀加到前面提到的其他指令上，*重复*执行这些指令。

加上`rep`前缀后，字符串指令会重复执行，重复次数等于`rcx`中的值。
每重复一次，`rcx`中的值就减少`1`。
注意，必须在使用该指令之前设置好`rcx`的值：

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

除了把`rcx`用作计数器之外，如果`zero flag (ZF)`分别为清零或置位，`repe`（或`repz`）和`repne`（或`repnz`）会提前停止执行：

| 指令      | 可添加的位置     | 是否可能提前停止        |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`、`lods`、`stos` | 否                      |
| `repe`、`repz`    | `cmps`、`scas`         | 是，ZF 为 0 时停止 |
| `repne`、`repnz` | `cmps`、`scas`         | 是，ZF 为 1 时停止 |

~~~~exercism/advanced
在现代 CPU 上，移动大块数据时，`rep movs`和`rep stos`通常是很快的选择。
不过，其他字符串指令，甚至不带`rep`操作的`movs`和`stos`，通常都比一个普通循环慢。

关于这个主题更深入的讲解，可以在[这本参考书的第 16.9 章“字符串指令”][agner-optimization-guide]中找到。
