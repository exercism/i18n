# 关于

在 C# 中，元组是一种数据结构，用于组织数据，可以容纳任意类型的两个或多个字段。

元组通常的创建方式，是把两个或多个用逗号分隔的表达式放在一对括号里。

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

和任何其他表达式一样，元组有多种用法：用在[赋值][tuple-assignment]中，用于初始化字段或变量，作为方法的[返回值][tuple-return-values]，或者作为参数传递。还可以对它们进行[相等性][tuple-equality]测试。元组的相等性在`pattern-matching-tuples`练习中有完整说明，不过为了完整起见，下面的代码也提供了一个示例。

字段通过点语法提取。默认情况下，第一个字段是`Item1`，第二个是`Item2`，依此类推。非默认名称会在下面的*命名*一节中讨论。

元组可以用作泛型参数，例如`IList<(bool, string)>`。

此外，元组还支持“解构”（下文会讨论），并且可以用于模式匹配，这会在后面的练习中介绍。

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

这篇[介绍][tuples]展示了如何定义和使用元组。

## 命名

字段名`Item1`等并不利于代码的可读性。有三种方式可以为字段提供名称：a) 在类型声明中，b) 在创建它的表达式中，c) 通过[元组投影初始值设定项][tuple-projection-initializers]（这里不做演示）。

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

不要在命名机制上试图耍小聪明，它其实只是语法糖。例如，当你从另一个元组赋值时，无法改变元组的字段名。

## 解构

有时，把一个元组的各个字段分别赋给多个变量，并在合适时初始化它们，会很方便。这种机制叫做[解构][tuple-deconstruction]。（它也可以用于你自己的对象。参见[这里][udt-deconstruction]。）

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## 字段赋值

元组的各个字段可以单独赋值。不过，考虑到 C# 中趋向不可变的潮流，这种用法并不普遍。元组经常被当作不可变来使用，当然它们并非如此。

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## 背景

我们讨论的元组不应与[`System.Tuple`][system-tuple]混淆，后者大概只会出现在遗留代码库中。

谈到`System.ValueTuple`时，情况会稍微更令人困惑一些。[`System.ValueTuple`][system-value-tuple]最后一个重载的[文档][system-value-tuple]中写道：“值元组类型提供了在 C# 中支持元组的运行时实现。”这里说的“值元组类型”指的是`System.ValueTuple`的泛型重载，说的“元组”则是指本练习中一直讨论的东西。实际上，他们是在说`System.ValueTuple`是元组的实现细节。对大多数人来说，大多数时候，这大概都没什么意义。遗憾的是，很多关于“元组”的文档，包括微软自己的文档，都随意地夹杂着对`System.ValueTuple`的引用。遇到这类引用，直接略过即可。

## 其他用途与限制

模式匹配是元组特别有成效的一种用途。这会在后面的练习中介绍。

元组还支持一些其他小的风格化技巧：

- 多重赋值（尤其是在构造函数中），例如`(this.field1, this.field2) = (arg1, arg2);`
- 交换或循环利用值，例如`(a, b) = (b, a);`
- 在列表中代替`struct`使用
- 用作字典的键，或作为集合的内容
- 用于 LINQ。（LINQ 会在后面的练习中介绍）

文档把元组描述为一种轻量级机制，而这正是成功使用它的关键。用元组代替类或结构体会导致其字段类型（可能还有名称）被乏味地重复。这在把元组用作方法参数或集合中的泛型参数时尤其明显。

最好明智地使用多重赋值和交换这类技巧。

除相等和不相等之外的关系运算不受支持。

注意，元组是相对较近才引入这门语言的（C# 7），所以如果你想使用它们，就应该确保你的代码库使用的语言[版本][language-version]不低于 7。
