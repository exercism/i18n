# 关于

汇编中的数据都是一串字节。
这意味着，任何数据都可以看作由这些底层字节组成的**[数组][array]**。

## 访问数组中的元素

要访问内存中的任何值，都必须先计算它的**有效地址**。
有效地址是一个表达式，可以由以下几部分组成：

- 一个_基址_，例如某个变量的标签所指示的地址。
- 一个_索引寄存器_，可以按`1`、`2`、`4`或`8`缩放。
- 一个带符号的 32 位_位移量_，这个数字会加到基址上（或从基址中减去）。

注意，这种地址是_从 0 开始编号_的，因此不带任何偏移量的基址，指向的就是变量的第一个字节。
这也是为什么只用一个标签、不带任何偏移量去解引用内存（就像前面几个概念里做的那样），得到的是从第一个字节开始的值：

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 是[小端序][endianness]。
这意味着，多字节值的最低有效字节存放在最小的内存地址上。

因此，在访问多字节值的各个字节时，必须给基址加上一个正的偏移量，才能到达更高有效位所在的字节。

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

用一组值声明的已初始化变量，就是由这些值组成的数组，每个元素的大小由声明时指定。
不过，偏移量始终以_字节_为单位，即使数组中每个元素的大小更大也是如此：

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

注意，由于地址以字节为单位，我们可以直接访问数组中任意元素的单个字节：

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

同理，也可以在一条指令中访问超过一个元素大小的数据：

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
汇编不会对数组访问做边界检查。
超出数组末尾的下标会读到或写到数组之外的内存。
这可能导致悄无声息的错误结果，破坏其他数据，而且如果被访问的内存没有被映射，还会引发运行时故障。
程序员有责任保证每个有效地址都落在数组范围内。
~~~~

## 计算已初始化数组的大小

NASM（Netwide Assembler，即本课程使用的汇编器）有一个特殊符号（`$`），用来表示内存中的当前位置。
这个符号提供了一种便捷的方法，用来计算数组在内存中占用的总大小：

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

紧跟在`example`之后使用时，`$`的值就是数组末尾在内存中的地址。
这意味着`$ - example`就是那个地址与`example`标签所指地址之间的差值。
这正是`example`所指数组占用的总字节数。

因此，用这个值定义`example_length`，我们就创建了一个 8 字节的变量，用来存放数组的大小，也就是长度，单位是字节。

## .bss 段

未初始化的数据声明在 **[.bss 段][bss]** 中。
在大多数平台上，程序启动时操作系统会把这段数据全部填充为零。

在 NASM 中，未初始化的变量由一个名称、一个指明数据大小的伪指令以及要保留的元素个数组成。
它们之间用空格分隔。

主要伪指令及其对应的数据大小如下：

| 伪指令 | 大小    |
| :-------: | :------ |
|   resb    | 1 字节  |
|   resw    | 2 字节 |
|   resd    | 4 字节 |
|   resq    | 8 字节 |

例如，下面这段代码为一个名为`example`的变量保留了`3`字节的未初始化空间：

```x86asm
section .bss
    example resb 3
```

而下面这段代码为一个名为`arr`的变量保留了`10`个`8`字节（也就是`80`字节）的未初始化空间：

```x86asm
section .bss
    arr resq 10
```

`section .bss`中的变量是可变的，也就是说，它们可读可写。

未初始化的数据可以像已初始化数据一样，通过有效地址来访问。
同样，它们也具有静态存储期，可以从同一源文件中的任何函数访问（如果声明为`global`，也可以从其他源文件访问）。

## 使用 lea 指令访问数组地址

正如前面某个概念中讲过的，`lea`指令会计算出一个有效的内存地址。
按照相同的语义，它也可以用来计算数组中任意元素的地址。

注意，在使用相对寻址时，往往需要先把变量的地址加载到寄存器中，然后才能构造更复杂的地址：

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea`的一个优点是，它利用地址运算来计算一个值，而不会真正访问该地址处的内存。
因此，即使没有任何寄存器保存着内存地址，它也能用来做算术运算：

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
