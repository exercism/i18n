# 说明

在最近的一次安全审查之后，你接到任务，要清理组织归档的日志文件。

## 1. 找出乱码日志行

你需要大致了解归档中有多少日志行不符合当前标准。
你相信一个简单的测试就能判断某行日志是否有效。
一行日志要被判定为有效，就必须以下列字符串之一开头：

- `[DEBUG]`
- `[INFO]`
- `[WARNING]`
- `[ERROR]`

实现`is_valid_line`函数，如果日志行有效就返回`True`。

```gleam
log_parser.valid_line("[ERROR] Network Failure")
// -> True

log_parser.valid_line("Network Failure")
// -> False
```

## 2. 拆分日志行

开始这个日志解析项目后不久，你发现有一个应用的日志不像其他应用那样分行。在这个项目里，本应分成多行的内容却挤在一行里，由`<--->`或`<*~*~>`这类花哨的箭头连接。

事实上，只要一个字符串以`<`开头、以`>`结尾，中间包含零个或多个`~`、`*`、`=`、`-`，就可以作为这个项目日志中的分隔符。

实现`split_line`函数，它接收一行日志，返回一个字符串数组。

```gleam
log_parser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
// -> ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. 给日志行打上用户名标签

你注意到有些日志行里包含提到用户的句子。
这些句子总是包含字符串`"User"`，后面跟着一个或多个空白字符，然后是一个用户名。
你决定给这些行打上标签。

实现`tag_with_user_name`函数来处理日志行：

- 不包含字符串`"User"`的行保持不变。
- 对于包含字符串`"User"`的行，在行首加上`[USER]`，后面跟用户名。

```gleam
log_parser.tag_with_user_name("[INFO] User Alice created a new project")
// -> "[USER] Alice [INFO] User Alice created a new project"
```

你可以假设：

- 字符串`"User"`每次出现之后都跟着一个或多个空白字符以及用户名。
- 每一行最多出现一次字符串`"User"`。
- 用户名是非空字符串，且不包含空白字符。
