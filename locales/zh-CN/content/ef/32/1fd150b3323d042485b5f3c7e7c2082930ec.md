# 简介

Factor 的线程是*协作式协程*：它们共用一个操作系统线程，在 I/O 以及显式的让出点互相交出控制权，从不会真正同时运行。你*在两次让出之间*做的任何事，都会作为一个不被打断的步骤发生。但如果一个复合操作（读取-修改-写入）在中途让出，另一个线程就可能趁机插进来，在你完成之前改变世界，这就是竞态。

本练习会涉及 4 个反复出现的原语：

## `parallel-map`：对序列做 fork/join

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

位于[`concurrency.combinators`][combinators]中。它为每个元素启动一个线程，运行引用，再把结果按原来的顺序收集到一个新序列里：

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`：启动一个线程

```
spawn ( quot name -- thread )
```

位于[`threads`][threads]中。引用会并发运行；`name`是用于调试的标签。返回的线程句柄在这个层面基本没什么用，`drop`掉就行。

## 承诺：一次性的值传递

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

位于[`concurrency.promises`][promises]中。一个承诺就是一次性的信箱：一个线程兑现它，其他线程读取它。`?promise`会一直阻塞，直到这个承诺被兑现，然后返回该值。

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

`parallel-map`正是用`spawn`和`<promise>`构建出来的；当每个任务要做的不是“计算一个元素”时，自己动手实现它们会很有用。

对一个序列做 fan-out/join 的典型形态是：为每个输入新建一个承诺，启动一个线程来完成工作并`fulfill`该承诺，把所有承诺收集到一个序列里，再对每个承诺调用`?promise`来等待完成。局部变量能让这段代码更好读：在`[| | ]` lambda 中用`:>`把承诺绑定到一个名字上，这样启动出来的引用就能捕获它：

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## 锁：互斥

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

位于[`concurrency.locks`][locks]中。同一时刻只有一个线程能持有某个锁。`with-lock`会获取锁、运行引用、再释放锁，即使引用抛出了异常也一样。

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

只要一个值会被*多个线程读写*，而针对它的操作又不是天然原子的，就该用锁。读取和写入都需要这把锁：一次在中途让出的读取，可能看到撕裂的状态。
