# 简介

## `Base.@kwdef`

宏`Base.@kwdef`可以用来自动定义接受关键字参数的构造函数，用于定义[结构体][struct]。
它还可以为字段设置默认值。

例如，下面这个定义

```julia
Base.@kwdef struct HumanStats
    birthyear::Int
    height::Int
    mass::Int
    bmi::Float64 = mass / (0.01 * height)^2
end
```

一次性定义了三个构造函数

```julia-repl
julia> methods(HumanStats)
# 3 methods for type constructor:
[1] HumanStats(; birthyear, height, mass, bmi) [...]
[2] HumanStats(birthyear::Int64, height::Int64, mass::Int64, bmi::Float64) [...]
[3] HumanStats(birthyear, height, mass, bmi) [...]
```

其中就包括一个基于关键字参数的构造函数

```julia-repl
julia> HumanStats(
           birthyear = 2002,
           height = 193,
           mass = 83
       )
HumanStats(2002, 193, 83, 22.28247738194314)
```

而标准定义

```julia
struct HumanStats
    birthyear::Int
    height::Int
    mass::Int
    bmi::Float64
end
```

只定义了下面这两个

```julia-repl
julia> methods(HumanStats)
# 2 methods for type constructor:
[1] HumanStats(birthyear::Int64, height::Int64, mass::Int64, bmi::Float64) [...]
[2] HumanStats(birthyear, height, mass, bmi) [...]
```

而且需要手动定义一个基于关键字的构造函数。

### 什么时候该用`Base.@kwdef`？

当结构体的参数数量很多时，基于关键字的构造函数特别有用，尤其是当参数的类型或取值与参数的含义没有直接关系时。

看看下面这个定义：

```julia
dirk = BasketballPlayer(1978, 1994, 2019, 213, 111, 42, 1998, [2011], 31560, 11489, 3651)
```

如果不知道这个类型的定义，就看不出每个值是什么意思。
就算知道定义，也很可能得反复去查参数的顺序。

但如果使用基于关键字的构造函数，它们的含义就一目了然了：

```julia
dirk = BasketballPlayer(
    birthyear = 1978,
    career_start = 1994,
    career_end = 2019,
    height = 213,
    weight = 111,
    number = 42,
    drafted = 1998,
    championships = [2011],
    points = 31560,
    rebounds = 11489,
    assists = 3651
)
```

~~~~exercism/caution
`Base.@kwdef`没有被导出，手册里也没有相关文档，因此它不属于[Julia 的公共 API][public-api]。
这意味着从技术上讲，它的接口不保证稳定，可能会在 Julia 的小版本更新中发生变化。

不过，这个宏在整个生态系统中被广泛使用，不太可能以破坏性的方式被改动。

更多信息请见：

- [Julia Issue #33192：导出`@kwdef`][export-kwdef]
