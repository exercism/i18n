# 迭代器组合

几个迭代器可以共用一个循环。每一轮每个迭代器各前进一次。

```sather
   loop
      a ::= xs.elt!;
      b ::= ys.elt!;
      ...
   end;
```

## 终止

只要**任意一个**迭代器没有元素了，循环就结束。其余的迭代器不再前进，循环体剩下的部分也不会执行。

这意味着同时遍历两个数组只会走`min(xs.size, ys.size)`轮。要覆盖更长的那个，就改为遍历位置并用下标访问，自己为较短的那个数组做保护。

## 每个调用点各自遍历

迭代器的位置属于它在程序里写下的*位置*，而不属于对象本身。所以：

```sather
   loop
      #OUT + xs.elt! + xs.elt!;      -- two walks, each advancing separately
   end;
```

每一轮会从两条互相独立的遍历中取出两个不同的元素。所以只取一次，把值留下。

## 无尽的迭代器

| 迭代器 | 给出 |
| --- | --- |
| `n.up!` | `n`、`n+1`、`n+2`、……，永不结束 |
| `n.upto!(m)` | `n` … `m`，然后结束 |

无尽的迭代器必须与某个会结束的东西配对，或者配合`break!`或`until!`使用。单独使用的话，它会一直循环下去。

把`1.up!`和遍历一个集合配对，是给元素编号的惯用写法，值得一眼就认出来。

## 为什么这是一个独立的概念，而不是别的概念的一部分

当*第一个*迭代器耗尽时循环就结束，这条规则最容易写出那种悄悄出错、而不是明显坏掉的程序：它不会崩溃，只是提前停下来。如果把它塞进介绍迭代器的那个练习里，或者塞进自己写迭代器的那个练习里，就会让人在还有别的新东西要学的时候碰到它。
