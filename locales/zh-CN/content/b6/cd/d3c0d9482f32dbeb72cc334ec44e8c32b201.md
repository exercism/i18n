# 安装 Factor

Factor 轨道使用 **Factor 0.101**。不支持更早的版本。

你可以安装[稳定版](#stable)或[每日构建版](#nightly)，也可以[从源代码构建](#build-from-source)。

运行`factor -e='vm-version print'`来验证安装，它应该输出`0.101`或更高版本。

---
### 稳定版

<https://factorcode.org#stable-release> 在“Stable release”一栏下提供了稳定版二进制文件。

---
### 每日构建版

<https://factorcode.org#development-release> 在“Development release”一栏下提供每日构建版二进制文件。这些二进制文件由 git 构建，但只展示构建通过的版本。

---
### 从源代码构建

如果你想尝鲜，甚至觉得每日构建版都太旧，那么你需要一个现代的 C++ 编译器（GCC >=4.8 或 Clang >=3.5）、`make` 和 `curl`。

满足这些简单的要求后，你可以：

1. 下载 `build` shell 脚本：[**这里**，适用于 Unix-like / POSIX shell](https://raw.githubusercontent.com/factor/factor/master/build.sh)，或[**这里**，适用于 Windows](https://raw.githubusercontent.com/factor/factor/master/build.cmd)。把它放到 Factor 应该安装到的目录下。程序会创建一个名为 `factor` 的目录，用来存放代码库。

2. 运行它，例如 `./build.sh install`，在 Windows 上则是 `.\build.cmd install`。<sub>这会克隆 Factor 的 `git` 代码仓库、构建它，并从 <https://factorcode.org> 下载一个 Factor VM 镜像。这个过程可能需要 2 到 20 分钟，具体取决于你的网速和 CPU 频率。</sub>

3. 现在你可以运行在 `factor` 子目录中生成的 `factor` 或 `factor.exe` 二进制文件。试试 `factor --help` 来获取帮助。你也可以从命令行访问文档，或在 GUI Listener 中按 <kbd>F1</kbd> 打开帮助浏览器。

4. 以后使用 `factor` 子目录里的 `build.sh`（Windows 上是 `build.cmd`）从 git 拉取更新并就地重新构建，如有需要还会下载新的 VM 镜像。

现在文件结构可能类似于：

```
.
├── build.sh                   <- delete if you like
└── factor
    ├── basis
    ├── boot.unix-x86.64.image
    ├── build.cmd              <- use these from now on
    ├── build.sh               <-
    ├── core
    ├── extra
    ├── factor
    ├── Factor.app
    ├── factor.image
    ├── GNUmakefile
    ├── libfactor.a
    ├── libfactor-ffi-test.so
    ├── LICENSE.txt
    ├── misc
    ├── Nmakefile
    ├── README.md
    ├── unmaintained
    ├── vm
    └── work
```

你不再需要顶层 `build` 脚本，因为以后应该使用下载下来的那个。

---

### 手动从源代码构建（不推荐）

克隆[代码仓库](https://github.com/factor/factor)，并在该文件夹中运行 `make`。

如果 `make` 因为目标不存在而报错，试试 `make factor`；如果你看得懂 Makefile，也可以在 `GNUmakefile` 里找到适用于你平台的 make 目标。

如果*那样*还是失败，就到 [factor/factor](https://github.com/factor/factor) 提一个 issue，附上报错信息。友好的开发者们会很乐意帮忙。
