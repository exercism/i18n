# 关于

按照教学大纲的进度，到这里你已经看到 R 经常被当作命令式语言使用，也越来越常被当作函数式语言使用（尤其是在[`purrr`][ref-purrr]和[`dplyr`][ref-dplyr]这两个库的帮助下）。

现在如果说 R 主要是一门面向对象的语言，可能会引来一些质疑！

说来奇怪，这确实是事实。
在内部，R 的实现用到了类、继承、多态，以及面向对象程序员特有的那种态度。

然而，任何熟悉 Java 或 Ruby（明确地面向对象）甚至 Python（在某些方面半隐蔽地面向对象）的人，都会觉得 R 的做法……很陌生。

首先，类的设计不止一种：常用的可能就有三种（S3、S4、R6），另外还有一些主要只有理论意义的。

完整的讨论见 [Advanced R, 2e][book-advanced-r] 第 12 到 16 章。这本 2019 年出版的书主要面向想理解并维护 R 内部实现的人，因此面向对象编程是必不可少的。

更面向最终用户的教科书则各不相同。

- The Art of R Programming（2011 年，仅纸质版）有一章讲面向对象编程，涵盖 S3 以及（更简略的）S4，这两者在当时都很重要。那句“S3 类有着相当拼凑而成的结构”的评论，至今依然惊人地准确。
- R in Action（第 3 版，2022 年）把面向对象编程压缩到接近末尾“高级编程”一章里的 3 页。
- [R for Data Science, 2e][book-r-data-sci]（2023 年，纸质版共 548 页）完全没有提到面向对象编程。

本概念将聚焦 S3 类，它最简单、最常见，也和 Exercism 这类平台的练习最相关。
R 轨道上的一些练习要求你创建一个 S3 类，另一些则把它设为可选，但会温和地鼓励你这么做。

## S3 类

S3 类很古老：S3 这个名字只是表示它们是在 S 语言（R 的商业前身）的第 3 版中引入的。

S3 类本身也非常简单：通常就是一个[列表][concept-lists]，外加至少一个属性。

引用 [Advanced R][book-s3]：“S3 是非正式的、临时的，但它的极简主义自有一种优雅：你拿掉其中任何一部分，它都不再是一个有用的面向对象系统。”

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

所以给[`class(obj)`][ref-class]赋值，只是给 `obj` 增加了一个属性，这里就是把 pt2d 标识为 point2d 类的一个实例。

创建步骤还可以用[`structure()`][ref-structure]合并起来：

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

虽然得到的两个实例在概念上是相同的，但我们还没有实现让 R 确认这一点的方法。

### 泛型方法

熟悉其他语言面向对象的人可能会想：“类不是应该能做点什么吗？”

我们可以看看`point2d`实例有哪些可用的方法，会发现（和底层的`list`不同）目前一个都没有。

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

在大多数面向对象语言里，方法都定义在类的定义内部。
少数语言（尤其是 Ruby）允许你在之后添加和修改类方法。

S3 类则完全不同。
我们不是把方法加到类上，而是把类加到泛型方法上。

经常在 R 控制台交互式工作的人，一直都在使用泛型方法，通常不会去想它们是怎么实现的。

一个非常常见的例子是`print()`，尽管你很少直接敲出这个函数名。
在控制台提示符下单独输入值`x`，不过是`print(x)`的语法糖。

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

我们已经可以打印`pt2d`了。
虽然`print()`对`point2d`类一无所知，但它有一批合理的默认行为，能处理各种各样的对象。

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

这样输出相当啰嗦，我们可能希望有种办法，能把点简洁地打印得漂亮些。

很简单：只要加一个名为`print.point2d()`的函数就行。
名字必须采用`methodname.classname`的形式，这样分派器才知道该找什么。

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

现在假设我们想创建一个新的泛型方法，比如用`flipvert()`把`y`坐标的符号取反。

同样很简单：

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

这就创建了一个分派器，其中`x`是带有 S3 类的对象，而`...`负责处理方法定义可能需要的额外参数（即“点参数”，见[函数概念][concept-functions]）。

然后我们就可以为`point2d`定义这个方法并使用它。

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

现在 R 知道怎么翻转我们的点，也知道怎么显示结果。

我们可以进一步扩展，为 3D、极坐标等创建类，再为每个类定义方法。

从最终用户的角度看，只有`flipvert(x, ...)`这一个函数，我们可以依靠 R 来判断输入对象的类，并使用相应的底层实现。

~~~~exercism/caution
`verb.class`这种格式的函数名，无论对用户还是对 R 解析器来说，看起来都像 S3 方法。
请避免在其他场景中使用类似的命名。

诚然，base R 有时会违反这条规则。
我们应当把它看作一次不幸的历史遗留（那些函数甚至比 S3 还要古老），为了向下兼容必须保留。
~~~~

### 继承

面向对象爱好者可以就继承、子类化、混入以及其他种种，写上好几章厚厚的教科书。

R 则允许你给`class`属性提供多个名字：一个更长的字符串向量，而不是单个字符串。

冒着把这个例子用坏的风险，假设我们做了一个通用的`point`类，想派生出`point2d`、`point3d`等子类。

那么`point2d`的定义只需写成`class = c("point2d", "point")`：具体类和父类（可能不止一个）。

像`print()`这样的泛型方法会依次查找`print.point2d()`、`print.point()`以及（很可能是）`print.default()`，并使用分派器找到的第一个实现。

### 安全性

许多面向对象语言（Java、C# 等）利用类内部的数据封装，来进行细致的编译期检查并强制类型安全。

请注意，S3 几乎允许你为所欲为，哪怕这么做毫无道理（错误信息要到之后才出现，甚至根本不出现）。

引用 [Advanced R][book-s3]（第 2 版，13.3 节）：

> 如果你用过其他面向对象语言，这可能会让你感到不安，但实践中这种灵活性很少带来麻烦。R 不会阻止你朝自己的脚开枪，但只要你不把枪口对准自己的脚趾并扣动扳机，就不会有问题。
