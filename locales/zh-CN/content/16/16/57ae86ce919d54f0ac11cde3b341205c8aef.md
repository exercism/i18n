# 附加说明

## Node 进程

与其他练习不同，`grep.js`并_不_是在测试文件`grep.spec.js`中导入的。相反，它会被当作可执行文件来使用。为了方便这一点，`grep.js`文件已经设置好了 shebang，并附有一段注释来说明它的作用：

```javascript
#!/usr/bin/env node

// The above line is a shebang. On Unix-like operating systems, or environments,
// this will allow the script to be run by node, and thus turn this JavaScript
// file into an executable. In other words, to execute this file, you may run
// the following from your terminal:
//
// ./grep.js args
//
// If you do not have a Unix-like operating system or environment, for example
// Windows without WSL, you can use the following inside a window terminal,
// such as cmd.exe:
//
// node grep.js args
//
// Read more about shebangs here: https://en.wikipedia.org/wiki/Shebang_(Unix)
```

测试会启动一个新的 node _进程_，并执行`grep.js`。

## 读取参数

要获取启动 _进程_ 时传入的参数，请使用`process.argv`。

## 读取文件

我们已经提供了`readLines`函数。使用它时不需要转换文件路径。`readlines`函数会从当前工作目录 _解析_ 路径；对于`grep.js`进程来说，这个目录被设为练习目录。

## 写入输出

要写入输出，请使用：

- `console.log`写入标准输出流，
- `console.error`写入标准错误流。

如果没有向标准错误流写入任何内容，测试就认为执行成功（resolved）；如果向标准错误流写入了内容，则认为执行不成功（rejected）。
