# 关于

到教学大纲的这一部分，你已经见过很多函数定义。这些定义出现时，通常并没有对 REPL 中的输出作太多说明：

```julia-repl
julia> f(x) = x^2
f (generic function with 1 method)
```

为什么是 _"generic function with 1 method"_ ？

假设我们想更具体地指定实参的类型。

```julia-repl
julia> f(x::Integer) = x^2
f (generic function with 2 methods)

julia> f(x::Real) = x^2
f (generic function with 3 methods)
```

或者我们也可以改变实参的数量：

```julia-repl
julia> f(x, y) = x * y
f (generic function with 4 methods)
```

看来，同一个函数的新定义被称为“方法”。方法会被加进一个列表，而不是覆盖原来的定义。

我们可以轻松列出这些方法：

```julia-repl
julia> methods(f)  # output edited for brevity
# 4 methods for generic function "f" from Main:
 [1] f(x, y)
 [2] f(x::Integer)
 [3] f(x::Real)
 [4] f(x)
 ```

如果我们调用函数 `f`，Julia 会以某种方式知道该用哪个方法：

```julia-repl
julia> f(2.5)  # Float64
6.25

julia> f(2)  # Int64
4

julia> f(2, 3)  # Int64, Int64
6
```

## 什么是函数？

根据[手册][function]，函数是一种对象，它把实参组成的元组映射到一个返回值。这与数学家的定义很接近。

我们通常把 `f(2, 3)` 中的函数实参看作两个独立的项，但编译器把它们看作一个[元组][tuple]。即使只有一个实参也是如此（不过需要加一个逗号才能更清楚地体现这一点）：

```julia-repl
julia> typeof( (2, 3) )
Tuple{Int64, Int64}

julia> typeof( (2,) )
Tuple{Int64}
```

把函数看作一个黑盒，我们可以说，一个元组进去，一个返回值出来。更正式地说，元组被_映射_到一个返回值。

## 函数如何处理不同数量和类型的实参？

这通常被称为[“多态”][polymorphism]。

几十年来，这一直是计算机科学中的一个重要话题，也出现了各种不同的处理方式。

Julia 的做法很不寻常，但并非独一无二。

- 函数是[“泛型”][generic]的，也就是说一个函数可以挂载多个方法。
- 在挂上方法之前，函数只是一个名字。
- 方法可以按需添加，数量可能很大（`+` 运算符目前就是一个拥有 161 个方法的函数）。
- 调用函数时，Julia 会检查调用签名：实参的数量以及每个实参当前的类型。
- 它会选出与调用签名最匹配的方法。
  - 一般来说，实参数量必须完全一致（不过 [splat/slurp][splat] 运算符 `...` 可以部分绕过这一限制）。
  - 类型与调用签名完全一致的方法会被优先选用。
  - 如有必要，Julia 会查看调用签名中每个实参的父类型，以找到最匹配、最具体的方法。
- 选中的方法会以给定的实参被[`dispatched`][dispatch]，并返回一个结果。
- 如果没有找到合适的方法，就会抛出 [`MethodError`][methoderror]。

注意，Julia 是动态类型的，因此方法分派发生在_运行期_。

## 多重分派：一个示例

上一节写了很多文字，现在我们把这些想法写成代码。为了简单起见，下面这些函数都只有一个实参，但拥有几十个实参的函数也并不少见（比如绘图包或机器学习中的函数）。

先定义一些自定义类型，用来表示几何图形。

```julia-repl
julia> abstract type Shape end

julia> struct Circle <: Shape
           radius::Float64
       end

julia> struct Square <: Shape
           side::Float64
       end

julia> struct Rectangle <: Shape
           length::Float64
           width::Float64
       end
```

接下来，我们可以定义方法来计算每个图形的面积。每个方法都接收一个实参，而且各自接收的都是不同的具体自定义类型。

```julia-repl
julia> area(c::Circle) = π * c.radius^2
area (generic function with 1 method)

julia> area(s::Square) = s.side^2
area (generic function with 2 methods)

julia> area(r::Rectangle) = r.length * r.width
area (generic function with 3 methods)
```

现在我们可以创建一些图形并计算面积，依靠 Julia 的分派机制为每个图形选用正确的公式。

```julia-repl
julia> circle = Circle(2.3)
Circle(2.3)

julia> area(circle)  # call signature Tuple{Circle}
16.619025137490002

julia> square = Square(1.6)
Square(1.6)

julia> area(square)  # call signature Tuple{Square}
2.5600000000000005

julia> rectangle = Rectangle(1.4, 2.1)
Rectangle(1.4, 2.1)

julia> area(rectangle)  # call signature Tuple{Rectangle}
2.94
```

## [参数化方法][parametric]

方法签名可以接收占位类型值，方式与参数化类型大致相同。

语法很独特，需要一个 `where` 子句：

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T} = true
same_type (generic function with 1 method)

julia> same_type([1, 2], 3)
true

julia> same_type([1, 2], "three")
ERROR: MethodError: no method matching same_type(::Vector{Int64}, ::String)
```

上面的例子要求两个实参使用同一个类型 `T`，无论 `T` 是什么。

我们可以给 `T` 加上约束，从而更具体：

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T<:Number} = true
same_type (generic function with 2 methods)
```

使用这个方法，只有数值类型完全相同时才会返回 `true`。

也可以使用多个占位变量，在 `where` 子句里用逗号分隔。下面两个方法看起来很相似：

```julia-repl
julia> func(v::Vector{Number}, x::Number) = true
func (generic function with 1 method)

julia> func(v::Vector{S}, x::T) where {S<:Number, T<:Number} = true
func (generic function with 2 methods)
```

一个区别是，在第二个方法的函数体里可以使用类型值 `S` 和 `T`。这类技巧你可能不常使用，但在某些情况下能省去很多麻烦。

例如，在下面的参数化类型定义中，各个字段必须是同一个类型 `T`，而 `T` 被约束为 `Real` 的子类型：
```julia
struct Point{T<:Real}
    x::T
    y::T
end
```
这个 `Point` 定义可以接受类型相同的 `x` 和 `y`，也可以接受类型不同的 `x` 和 `y`，但此时必须提供一个显式的转换类型。
```julia-repl
julia> Point(4, 5)
 Point{Int64}(4, 5)

julia> Point(3.5, 2)
 MethodError: no method matching Point(::Float64, ::Int64)    # Output truncated for brevity

julia> Point{Float32}(3.5, 2)
 Point{Float32}(3.5f0, 2.0f0)

julia> Point{Int64}(3.5, 2) 
 InexactError: Int64(3.5)      # Output truncated for brevity
```
虽然这种对类型的控制程度可能是我们想要的，但有一点抽象也可能很有用。
```julia
Point(x::T, y::S) where {T<:Real, S<:Real} = Point{promote_type(T,  S)}(x, y)
```
这个外部构造函数就实现了这一点：它允许 `Point` 接受类型不同的 `x` 和 `y`，而不必显式指定转换类型。类型值 `T` 和 `S` 在函数体中被用于 `promote_type(T, S)`，为原本的定义提供显式的转换类型。
```julia-repl
julia> Point(3.5, 2)
 Point{Float64}(3.5, 2.0)
```

## 与其他语言比较

因为 Julia 在选择方法时会检查所有实参，所以这被称为 [`multiple dispatch`][multiple-dispatch]。

还有少数其他语言也允许多重分派，比如 Common Lisp，但它很少像在 Julia 中那样成为语言设计的核心。

相比之下，在面向对象（OO）语言中（例如 Ruby），方法通常是在一个[实例][instance]上调用。这时的定义会偏重第一个实参（在定义中名字类似 `self` 或 `this`），调用时把方法名用点号接在实例上：

```ruby
irb(main):004:0> "abc".sub("b", "*")
=> "a*c"
```

这被称为 [`single dispatch`][single-dispatch]，因为选择方法时只用到了实例所属的类（在上例中就是字符串 "abc" 的类）。

一些静态类型的面向对象语言支持方法多态，看起来与多重分派有些相似。最大的区别在于，方法的选择只发生在_编译期_。

函数式语言往往只有一个函数定义，再通过某种 Select/Case/Match 表达式来处理各种情况。你需要自己编写逻辑，通常还会借助一套简洁的模式匹配语法，而这在 Julia 中是没有的。当然，Julia 也做某种形式的模式匹配，但发生在分派阶段，而不是在函数体内部。

## 小结

多重分派在 Julia 中非常灵活，性能也很高，因此被广泛使用。

正如 `+` 拥有 161 个方法的例子所示，Julia 程序员会尽量把方法的类型定义得很窄。在字节码层面，两个整数相加和两个浮点数相加差别很大，而整数与浮点数相加还额外带来类型提升的复杂性。

类型越具体，编译器能做的优化就越多：这在 Exercism 的一个小练习里无关紧要，但对 Julia 所面向的大型数值模拟来说，性能上至关重要。

_如果你知道一个方法会收到什么输入，请告诉编译器！_
