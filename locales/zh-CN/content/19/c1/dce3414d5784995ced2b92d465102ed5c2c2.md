**Franziska:** 对，对，确实。一开始你总是高估技术的部分。你会想，哦，这份工作的技术正好是我想做的，那肯定没问题。但实际上，团队这一块几乎比你具体在做什么技术更重要。

但你得学 Go。当然。我说，只要你不介意我一开始花点时间学，我就愿意。我看了一下这门语言，感觉挺酷的。对，我换了公司。新地方的团队真的很棒。
在那里，就算你和 CEO 讨论，只要你的论点更好，就会被注意到，大家也会回应你。跟他们共事很舒服，大家也很有意思。我在那儿待了五年。
搭建了很多 Go 服务，也写了很多文档、概念说明，帮其他开发者上手 Go，还做了一些前端的东西，等等。对，但五年之后，人也会想找点新挑战。另外促使我找新工作的，还有疫情。
我注意到，反正我本来就在家办公，对吧？可能一周才去一次办公室。所以我想，外面有很多完全远程的工作。也许我能在更大的公司找到一份很酷的工作。
反正我都是在家办公，那也可以给更大更酷的公司干活，对吧？对，就是那时候我还在工作，然后找到了 Atlassian 这份工作。

**Jonathan:** 我想我的问题是，疫情是不是让你开始觉得，哦，也许不只是法兰克福和法兰克福的创业圈。因为我本来想问，法兰克福的创业圈作为一个圈子是什么样的？

**Franziska:** 对，先说疫情这点。疫情首先让我接受了完全远程办公这个想法。因为以前我一直习惯去办公室。我喜欢当面见人，也喜欢那样的日常节奏。但主要远程了两年之后，我意识到这也没什么问题。我能应付。我有女儿，反正总得出门。所以现在我的日常已经有足够的节奏了。
这是疫情让我看到的一件事，也让我愿意考虑去别的地方看看。至于法兰克福，这里科技和创业的事确实不少，但你也猜得到，很多都集中在银行业，有很多金融科技公司之类的。我以前也做过金融科技，但这个领域并不是我特别热衷的。
对，所以这一直有点……另外附近也没有多少 Go 开发者。对，没有什么特别的原因把我留在法兰克福，或者留在法兰克福这个圈子里。

**Jonathan:** 不，当然。那有没有哪些语言是法兰克福特别侧重的？比如说金融科技，支撑这些的语言大概是哪些，是不是更集中？作为一个在法兰克福的 Go 开发者，你会觉得自己有点稀有吗？还是说越来越多了？在你看来是什么样？

**Franziska:** 对，现在很难说是不是在变多，因为疫情的关系，线下聚会之类的活动也不多，对吧？所以现在很难判断来参加聚会的人是不是在变多。
我觉得像 Java 领域的事情要多得多，比如。对，所以有点难说具体情况到底怎样。但比如说，JavaScript 通常不太难把社区组织起来，因为大家多少都会碰到一些前端的东西，对吧？所以前端圈子的活动通常比后端多。

**Jonathan:** 那你当初开始写代码、去训练营的时候，应该也接触过前端吧。稍微学过一点，而现在你更偏后端。你为什么更喜欢后端而不是前端？还是这只是我的假设？

**Franziska:** 不，确实是这样，这是我训练营期间发现的：我更喜欢后端这块。这里有几个原因。首先，我不是那种有设计感的人。做前端的话，你通常也要自己做一些判断，比如这东西应该长什么样？
这里能怎么改？写点 CSS 之类的。对我来说，做这些判断太难了。当然在真实工作里你也会拿到设计稿。但说实话，我就是不太有这方面的眼光。
我看到那些有这种眼光、做得到的前端开发者，干起活来效率更高。所以这是我想到“这不太适合我”的一点。另一点是，现在前端这个领域真的超级复杂。
那边关于框架，常用的那些大多都很难。所以某种程度上，现在的后端还稍微简单一点。它难在不容易可视化，对吧？不像前端，你看着屏幕就能看到最终结果，就是这个样子。
但就所涉及技术的复杂度来说，我觉得现在后端反而比前端那边容易一些。所以对我来说，职业生涯某个阶段，我肯定还是想回去做前端。但我在等一个更好的框架出现。
等到现在这一团乱麻平息下来，有了更好的东西，我就会回去做前端。

**Jonathan:** 那我可能就等你判断那个框架什么时候出现，然后跟你一起回去。因为看看那些建立在 JavaScript 之上的框架……我还是个新手，方方面面都是。我现在正在学 Go，学得挺开心。但光是那些概念和你要建立的思维模型，就已经是一个全新的世界了。
我还想问，你最开始学编程时先学的 JavaScript，后来再学 Go，这中间你是怎么跨过去的？因为听你说起来，从 JavaScript 转到 Go 好像挺顺理成章的。但实际是什么样？你是怎么过渡的？

**Franziska:** 对，好问题。这里有一点很重要：JavaScript 并不是我唯一学过的语言，对吧？上大学时我没有把很多语言学得很深，但我学过 C，学过 Java，学过 C++，还学过像 Mala 这样的冷门语言。
所以对我来说，JavaScript 已经是我第五门语言了，Go 是第六门。所以对我来说，比如 Go 里那些你听说过的指针之类的概念，如果我只学过 JavaScript，那会是全新的东西，我就得去搞明白这到底是什么。
但因为有这些其他语言打底，我从 C 和 C++ 里就已经知道这些了。对，我可以靠很多大学时学过的东西，所以上手很容易。另外，Go 有帮助的一点是它是一门相当精简的语言。
它没有那么多的关键字，也没有那么多你能构建的结构。你能很快读完，我通常说，去官网做一遍官方导览，或者别的什么资源，两三周就能过完。
然后你就能有扎实的理解。而 JavaScript 的话，这不可能。光是把基础理解扎实，你就得花长得多的时间，而且后面要学的东西还多得很。对，目标语言本身也帮了很大的忙，让过渡变得容易。

**Franziska:** 对，我感兴趣的方向或主题有好几种，不只是我现在工作的地方。比如我很喜欢消费级产品里的一些东西。像 Hello Fresh 这样的公司就做了很多很酷的事。
跟技术相关的很酷的东西，或者教育领域里也有很多，比如 Exercism 等等。另一个方向是开发者工具，或者更广义的团队工具。
所以有好几个领域，而现在这个是我觉得能说得通、值得去帮人们解决的方向。说到产品管理，我可以讲个关于 Jeremy 的趣事。我上一家公司的 CEO，我告诉他这份新工作和我要做的事时，他说的和 Jeremy，也就是 Exercism 的创始人，一模一样。他对我说了完全相同的话：你是不是因为受不了我的产品管理能力才选了这份工作？
这整件事说明，产品管理以及把它做好，一直是我热衷的东西。因为问题在于，作为开发者，你也许能写出有史以来最好的代码。但如果你写的东西本身就不对，如果你造的东西就是错的，那一切都是白费，对吧？
如果你的产品经理没能找出你真正该做的东西，那你做出来的东西也许根本没人用，因为他们没有好好分析市场，也没有排好优先级，等等。我在以前的工作里经历过这些。我做过很多东西，最后都没能见天日，因为没有好的优先级流程，对吧？
所以我认为，把产品管理这个领域整体做好，也能让全世界开发者的日子好过很多，因为他们就能做对的东西，真正创造价值，而不是做出一件最终被扔进垃圾桶、或者用户根本看不到的东西。

**Jonathan:** 对，这真的很有意思，因为你似乎注意到的是心理层面的东西。我觉得我们常有一种思维定式：如果你擅长技术，你就躲在幕后埋头做，作为一个人你永远见不到天日，因为你在搞技术，可以说这就是那种刻板印象。但过去几年确实感觉，技术和业务之间的交叉越来越多。对我来说，我一直把敏捷当成一个概念来看。而敏捷这个概念，我觉得本质上是把一种商业思维、一种看待事情的方式强加在技术团队身上。说实话，在我心里，感觉就是这样：它有用，但我从没见过哪个敏捷环境按时结出果实，如果这话说得通的话。也许是因为我过去见到的都是管理得很糟的情况。但确实感觉交叉越来越多了，开发者开始想更多地参与业务，我觉得这非常有意思，而且其实是件好事，因为这样整体的决策会更好。

**Franziska:** 对，有些开发者想更多地参与，但也有人不想，可他们还是得参与。问题是，那种做法根本行不通：产品管理坐下来把一切拆好，然后隔着墙丢过来，开发者照着做，就完事了。就算在过去那是标准模式的时候，这种做法也从没真正奏效过。
现在大家是更关注这一点了，但开发者与设计者、开发者与产品经理之间有更多对话，本来就是对的。另外，当你下游还有别的角色，比如有支持团队，或者有人负责维护之类的，他们配合得越紧密、越能一起找出最好的方案，你们能一起创造的价值就越多。这一直都是对的。

对，他们没法判断。所以我们能为第一次迭代找到好的打包方式，唯一办法就是互相沟通，说这个加进去容易，那个加进去难，等等。然后我们一起找出合适的范围。而我在 Atlassian 这份工作的好处是，我们的产品经理也是这么想的。
他总说，范围是双向的。我有一些想法，但你也得告诉我什么最合理。然后我们一起商量出结果。我还注意到，我走招聘流程的时候，与别人、与其他团队沟通这个话题，现在非常受重视。
很多人会问，你是怎么和其他团队合作的？他们真的会通过和你聊天来判断你表达能力如何，因为你在不在乎其他团队在做什么、有没有参与其中，这非常重要。只有这样，你才能真正把你有的时间用到极致。

**Jonathan:** 从这个意义上说，这感觉是一种更整合的方式。这也让我想到另一点，经常……

**Jonathan:** 这很有意思，因为感觉是这样：如果你在 LinkedIn 上找工作，比如产品负责人或产品经理，满眼都是 Scrum、敏捷，到处都是，你会觉得太惊人了。但有趣的是，我见过的最……怎么说呢，最有办法的开发团队用的其实是看板，没有必须在某个时间期限内产出的压力，但产出的质量很好，等于是把责任交回给个人，让他自己负责。这段经历挺有意思的，因为年轻的团队一上来就卡在“敏捷不管用”上，很受挫，最后落到看板，靠长期稳定地一点点推进，事情就成了。不过我觉得，把产品作为一门生意，和给别人做产品，也是很有意思的对比。我不知道你以前的工作是做什么的，是不是内部产品。我知道在 Atlassian，你们本质上是在做自己的产品。

**Jonathan:** 对，外包那些事简直是噩梦，因为每个人都会盯着你每一小时的开发时间之类的，然后说：我不明白，为什么这个按钮要花我 400 美元？而实际上是你想把它从这里挪到那里，这等于把整个后端重做了一遍。所以我想问你一个问题，这个问题我们在各种播客和直播里问过很多人。

**Franziska:** 好，我没有多少特别大的“愿为之而死”的观点。有一点我挺在意：很多人建议你去优化自己的开发环境。我觉得这大多被高估了。
