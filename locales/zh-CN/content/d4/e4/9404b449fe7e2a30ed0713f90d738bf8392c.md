# 简介

JavaScript 内置了一个`Date`对象，用来存储日期和时间，并提供管理它们的方法。

<!-- prettier-ignore -->
~~~exercism/caution
它基于 Java 的`java.util.Date`类，这个类在 2010 年代初就被取代了，但出于向下兼容，JavaScript 的`Date`一直保留至今。

由于处理日期本身就十分困难，加上时区处理要么很糟糕、要么根本不存在，于是涌现出许多库，例如`moment.js`、`day.js`、`date-fns`和`luxon`。
这些库在 Exercism 上都不可用。

在你自己的项目里，不要使用`moment.js`这类已废弃、无人维护的包，而应依靠更现代的替代方案，比如`luxon`，或者尚未被广泛采用的 [Temporal][mdn-temporal]。
本练习聚焦于`Date`，它会一直重要到 JavaScript 的尽头。

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal
~~~

## 创建

`Date`对象是`Date`类的一个实例。
创建时可以不向构造函数传入任何实参。
这样得到的`Date`对象表示当前的日期和时间：

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### **Unix 时间戳（数字）**

如果传入一个数字，它会被解释为`timestamp`。
时间戳是一个整数，表示自**1970 年 1 月 1 日 [UTC][defn-utc]+0**以来经过的**毫秒**数。

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

你可能会以为`new Date(0)`会生成“最早”的日期对象，但 JavaScript 会把日期转换到你所在的时区，这意味着只有在 [GMT / UTC+0][defn-gmt] 时区附近的人，才能真正得到 [Unix 纪元][defn-unix-epoch]的值。

### **ISO 8601 时间戳（字符串）**

你可以向`Date`构造函数传入一个表示日期的字符串值。
在各种实现之间**唯一**一致的格式，是国际公认并标准化的所谓 [ISO 8601 时间戳字符串][defn-iso8601]的[简化版本][mdn-date-string-format]。

一个处于 [UTC][defn-gmt] 的时刻看起来是这样的：

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

其中的替换如下：

| 键   | 说明                          | 默认值 |
| ---- | ----------------------------- | ------ |
| YYYY | 日历年，用 4 位数字表示       |        |
| MM   | 日历月，用 2 位数字表示       | 01     |
| DD   | 日历日，用 2 位数字表示       | 01     |
| T    | 字面字母 T，用来分隔日期和时间 |        |
| HH   | 24 小时制的小时，2 位数字     | 00     |
| mm   | 分钟，2 位数字                | 00     |
| ss   | 秒，2 位数字                  | 00     |
| mss  | 毫秒，3 位数字                | 000    |
| Z    | 字面字母 Z，或偏移量`+/-HH:mm` |        |

字面字母`Z`表示 UTC（无时区，无夏令时）。

由于大多数组成部分都有默认值，省略末尾的部分是合法的：

```text
YYYY-MM-DD
```

时间默认为 00:00:00.000

如果时间戳不以`Z`结尾，也不以`+HH:mm`或`-HH:mm`（表示时区偏移量）结尾，那么出于历史原因，适用以下规则：

> 当缺少时区偏移量时，只有日期的形式会被解释为 UTC 时间，而日期加时间的形式会被解释为本地时间。
> 之所以解释为 UTC 时间，源于一个历史性的规范错误，它与 ISO 8601 不一致，但出于 Web 兼容性又无法更改。
> 参见 [Broken Parser：一个 Web 现实问题][ref-broken-parser]。

### **Date 对象**

也可以把一个已有的日期对象作为构造函数的实参。
这会复制已有的`Date`对象，得到日期和时间都相同的一份副本。

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### **分别提供日期和时间的各个组成部分**

传入三个数字，可以创建一个表示日期的日期。
传入 6 个数字，可以创建一个表示日期和时间的日期。

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

第二个值是`month`，一月从`0`开始，一直到十二月的`11`。

## `Date.parse()`

你可能会看到有人提到或引用一个日期解析函数`Date.parse`。
由于这个函数只有很少几条不变式（也就是真理），而其余实现都没有规定（因此也不是标准），所以不应该使用它。

## 访问`Date`的各个组成部分

日期对象上有很多方法可以返回日期的各个组成部分：

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

这些方法每一个都有一个对应的`set`变体（例如`setFullYear`），用来更新值。
任何溢出的值都会进位到下一个组成部分：

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

所有这些方法都有忽略本地时区的 UTC 变体。

## 从日期转换

日期对象有一个方法`getTime()`，返回以毫秒为单位的 UNIX 时间戳，也就是从 1970 年 1 月 1 日 UTC 午夜开始经过的毫秒数。
此外，还有一个方法`toISOString()`，可以把日期对象转换成 ISO 8601 时间戳字符串。

## 比较日期

大于（`>`）、大于或等于（`>=`）、小于（`<`）以及小于或等于（`<=`），都可以直接用在两个日期之间，或用在一个日期和一个数字之间。
这样之所以可行，是因为 JavaScript 会尝试把日期强制转换为原始值。

<!-- prettier-ignore -->
~~~exercism/advanced
当在两个日期之间、或在一个日期和一个数字之间做比较时，JavaScript 会调用 [`[Symbol.toPrimitive]("number")`][mdn-to-primitive]，它内部又会调用 [`date.valueOf()`][mdn-date-value-of]。
后者等同于调用 [`date.getTime()`][mdn-date-get-time]。

如果你不想依赖这种行为，请先用`getTime()`转换成数字。

[mdn-to-primitive]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/Symbol.toPrimitive
[mdn-date-value-of]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/valueOf
[mdn-date-get-time]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/getTime
~~~

日期不能用相等比较（`==`和`===`），但`.getTime()`的结果可以。
