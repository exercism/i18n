# 说明

你正在构建一个小型的逆波兰表示法（RPN）计算器。
计算器的状态是一个*存放值的栈*（用 Factor 数组表示），而*操作*则是一个 quotation，它接受这样的栈并返回一个新的栈。

```factor
{ 3 4 }   ! the calculator's stack: 3 is below 4
[ ... ]   ! an operation that consumes some values and pushes a result
```

## 1. 实现加法

定义`add-op`，从栈中弹出栈顶的两个值，压入它们的和，然后返回新的栈。

```factor
{ 3 4 } add-op .
! => { 7 }

{ 1 2 3 4 } add-op .
! => { 1 2 7 }
```

## 2. 实现乘法

按照同样的方式定义`multiply-op`，不过做的是乘法。

```factor
{ 3 4 } multiply-op .
! => { 12 }
```

## 3. 应用单个操作

定义`apply-op`，从数据栈中取出一个栈和一个操作（quotation），并返回新的计算器栈。

```factor
{ 3 4 } [ add-op ] apply-op .
! => { 7 }
```

## 4. 对程序求值

定义`evaluate`，接受一个起始栈和一个操作数组，依次应用每个操作，并返回最终的栈。

```factor
{ 3 4 5 } { [ add-op ] [ multiply-op ] } evaluate .
! => { 27 }
```

## 5. 按名称求值

现在，程序是一个由*运算符名称*（字符串）组成的数组，计算器会在一个把名称映射到操作的 assoc 中查找每个名称。

定义`evaluate-named`，接受一个起始栈、一个命名操作的 assoc 和一个名称数组，并返回最终的栈。

```factor
{ 3 4 5 } H{ { "+" [ add-op ] } { "*" [ multiply-op ] } } { "+" "*" }
evaluate-named .
! => { 27 }
```

## 6. 安全除法

真正的计算器在被要求除以零时，不能悄悄产生垃圾结果。错误类`zero-divisor-error`已经为你定义好了。实现`divide-op`，与`add-op`和`multiply-op`类似，区别在于当栈顶的除数是`0`时，它会`throw`一个新的`zero-divisor-error`。

```factor
{ 12 4 } divide-op .
! => { 3 }

{ 1 5 6 2 } divide-op .
! => { 1 5 3 }

{ 5 0 } divide-op
! throws zero-divisor-error
```
