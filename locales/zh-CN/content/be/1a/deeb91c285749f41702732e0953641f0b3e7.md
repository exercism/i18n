# 补充说明

## 实现

如果你刚开始接触 Go 的错误或 panic，建议先阅读[关于这些主题的文档](https://blog.golang.org/defer-panic-and-recover)来了解背景。

在这个练习中，你需要定义一个函数`Use(opener ResourceOpener, input string) error`，它会打开一个资源，对返回的资源调用`Frob(input)`，然后无论发生什么都关闭该资源。你的函数应当妥善处理错误和 panic。

`ResourceOpener opener`是一个函数，你可以直接调用`opener()`来尝试“打开”该资源。它会以 [Go 的惯用方式](https://blog.golang.org/error-handling-and-go) 返回一个`Resource`和一个错误值：

有关`Resource`、`ResourceOpener`、`FrobError`和`TransientError`的定义，请参阅 [common.go](./common.go) 文件。你的解答需要与 [common.go](./common.go) 和 [error_handling_test.go](./error_handling_test.go) 位于同一个包中：“erratum”。这样这些类型才能在你的解答中使用。

在`Use`函数中有几个地方可能会发生错误：

- 调用作为第一个参数传入 Use 的`ResourceOpener`函数时，它可能会失败并返回`TransientError`类型的错误，这种情况下要继续尝试打开资源。
  如果遇到的是其他类型的错误，就把它从`Use`函数中返回。

- 对`ResourceOpener`函数返回的`Resource`调用`Frob`函数时，它可能会**panic**并抛出`FrobError`（或其他类型的错误）。
  如果确实是`FrobError`，你就必须调用该 Resource 的`Defrob`函数，_并把 panic 抛出的`FrobError`的`.defrobTag`变量作为`Defrob`函数的输入_。
  无论哪种情况，`Use`都应返回这个错误。

- _另外注意_：如果`Resource`成功打开了，请务必无论发生什么都恰好调用一次它的`Close`函数（即使已经发生了错误）。

测试特定的错误类型可以用[类型断言](https://golang.org/ref/spec#Type_assertions)。
你可能还需要看看[具名返回值](https://blog.golang.org/defer-panic-and-recover)，它是从 panic 恢复中返回错误信息的一种有用方式。
