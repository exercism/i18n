# Eigene Iteratoren

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | Routine | Iterator |
| --- | --- | --- |
| Name | `foo` | `foo!` |
| gibt einen Wert zurück | `return` | `yield` |
| endet | mit `return` oder am Ende | mit `quit` oder wenn nichts mehr kommt |
| darf aufgerufen werden | überall | nur innerhalb einer `loop` |
| behält seinen Platz | nein | ja |

## yield

`yield` übergibt einen Wert und hält an. Beim nächsten Durchlauf ist alles
wiederhergestellt: die lokalen Variablen, die Position in den eigenen Schleifen
des Iterators und die Positionen aller Iteratoren, die er selbst aufruft.

Ein `yield` in verschachtelten Schleifen setzt bei der innersten wieder an.
Genau das macht es einfach, etwas Verschachteltes zu durchlaufen:

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

Beendet den Iterator und damit die Schleife, die ihn aufruft. Er trägt keinen
Wert: Ein `quit` ist kein letztes Ergebnis, sondern die Ansage, dass es keines
gibt.

Ein Iterator mit einem Rückgabetyp muss bei jedem `yield` einen Wert liefern;
`quit` ist die Art, wie er sich weigert.

## once

```sather
   markers!(once count : INT) : INT is
```

Ein `once`-Argument wird beim Eintritt in die Schleife ausgewertet und behalten.
Ein gewöhnliches Argument wird bei jedem Durchlauf neu ausgewertet. Das ist
wichtig, wenn der übergebene Ausdruck einen weiteren Iteratoraufruf enthält:

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

Markiere Argumente als `once`, außer du willst genau das. Die gesamte
Bibliothek macht das.

## self und Iteratoren

Ein Iterator kann auf einem Objekt aufgerufen werden; dann ist `self` dieses
Objekt. Sein pausierter Zustand gehört zur Aufrufstelle, nicht zum Objekt.
Deshalb stören sich zwei Schleifen, die dasselbe Objekt durchlaufen, nicht
gegenseitig.

## Wann du einen Iterator schreibst

Schreibe einen Iterator, wenn die Antwort eine Folge ist und der Aufrufer
entscheiden soll, wie viel davon er nimmt. Vorzeitig aufzuhören kostet nichts,
und es wird nichts aufgebaut, was nicht gebraucht wird. Eine Routine, die ein
`ARRAY` zurückgibt, muss dagegen erst das Ganze aufbauen.
