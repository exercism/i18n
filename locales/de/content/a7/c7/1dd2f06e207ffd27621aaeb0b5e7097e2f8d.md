# Ergänzende Anweisungen

## Bankkonten in Roc

Im Roc-Code konzentrieren wir uns normalerweise auf die Geschäftslogik, während die Plattform Nebenläufigkeit und gemeinsamen Zustand übernimmt.
In dieser Übung musst du deshalb nur die Kontooperationen in `BankAccount.roc` implementieren und dich nicht um Nebenläufigkeit kümmern.
Konten starten geschlossen, ein erneutes Öffnen setzt den Kontostand zurück, und Einzahlungen und Auszahlungen müssen positiv sein.

## Optionale Server-Demo

Die mitgelieferte Datei `bank-account-demo.roc` zeigt, wie deine Implementierung in einem kleinen Webdienst verwendet werden kann.
Du kannst sie im Editor lesen, aber sie ist unabhängig von den Tests und nicht Teil deiner Lösung.

Um die Demo auszuführen, musst du [Roc installieren](https://www.roc-lang.org/install/), die [Exercism CLI](https://exercism.org/cli-walkthrough) installieren und dann diesen Befehl in einem Terminal ausführen:

```sh
exercism download --exercise=bank-account --track=roc
```

Als Nächstes implementierst du `BankAccount.roc` und testest es mit dem folgenden Befehl (ändere den Download-Pfad, den die CLI ausgibt, falls er von dem Pfad unten abweicht):

```sh
cd ~/Exercism/roc/bank-account
roc test bank-account-test.roc
```

Sobald alle Tests durchlaufen, kannst du den Demo-Server mit dem folgenden Befehl starten:

```sh
roc bank-account-demo.roc
```

Der Server nutzt die [basic-webserver-Plattform](https://github.com/roc-lang/basic-webserver) und ihre eingebaute SQLite-Unterstützung (Roc lädt die Plattform beim ersten Start herunter).
Ein separater Datenbankserver ist nicht nötig.
Der Server lauscht auf `http://127.0.0.1:8000` und legt `bank-account-demo.db` in deinem aktuellen Verzeichnis an (setze `DB_PATH`, um eine andere Datenbankdatei zu verwenden).
Beende den Server mit Strg-C.
Die Daten bleiben über Neustarts hinweg erhalten.

In einem anderen Terminal kannst du den Webdienst mit `curl` aufrufen (unter Windows verwendest du durchgängig `curl.exe`, um den `curl`-Alias von PowerShell zu vermeiden).
So öffnest du zum Beispiel Konto Nr. 123, zahlst 50 ein, hebst 10 ab und prüfst den Kontostand:

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/open
curl -X POST http://127.0.0.1:8000/accounts/123/deposit/50
curl -X POST http://127.0.0.1:8000/accounts/123/withdraw/10
curl http://127.0.0.1:8000/accounts/123/balance
```

Der Kontostand ist `40`.
Konto-IDs und Beträge müssen vorzeichenlose Ganzzahlen sein.
Updates geben bei Erfolg `OK` zurück, bei einem Fehler den Fehler aus deiner Kontoimplementierung.
So schließt du Konto Nr. 123:

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/close
```

Um nebenläufige Anfragen unter Linux/macOS auszuprobieren, verwendest du eine neue Konto-ID und schickst 100 Einzahlungen von acht Clients:

```sh
curl -X POST http://127.0.0.1:8000/accounts/456/open
seq 100 | xargs -P 8 -I '{}' curl --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1
curl http://127.0.0.1:8000/accounts/456/balance
```

Unter Windows verwendest du für das parallele Beispiel [PowerShell 7+](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows):

```powershell
curl.exe -X POST http://127.0.0.1:8000/accounts/456/open
1..100 | ForEach-Object -Parallel { curl.exe --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1 } -ThrottleLimit 8
curl.exe http://127.0.0.1:8000/accounts/456/balance
```

Alle Einzahlungen sollten erfolgreich sein und der Kontostand sollte `100` betragen.

## Wie die Demo mit Nebenläufigkeit umgeht

Jede Anfrage liest das Konto, ruft deine Roc-Funktionen auf und speichert das Ergebnis innerhalb einer SQLite-Transaktion mit `Immediate`.
Fehlgeschlagene Operationen werden zurückgerollt, ohne das Konto zu verändern.
SQLite erlaubt nur einen Schreiber gleichzeitig, wodurch nebenläufige Anfragen die Updates der jeweils anderen nicht überschreiben können (auch nicht über verschiedene Konten hinweg).

Hinweis: Die Übung verwendet `U64`, die Demo speichert Kontostände aber als SQLite-Ganzzahlen und lehnt Updates ab, die den maximalen `I64`-Wert (`9223372036854775807`) überschreiten.

Ein Beispiel dafür, wie du unabhängige Berechnungen parallel ausführst, findest du in der [Übung parallel-letter-frequency](https://exercism.org/tracks/roc/exercises/parallel-letter-frequency).
