# Überblick

Die Programmierübung veranschaulicht eine Reihe von Eigenschaften von Parametern:

- Parameter ohne einen Modifizierer (wie `out` oder `ref`) [werden als Wert übergeben][passing-parameters]. Das heißt, der Parameter kann in der aufgerufenen Methode verwendet und ihm kann ein Wert zugewiesen werden, aber Änderungen haben keine Auswirkung auf den Aufrufer.
- Wenn eine Referenz auf ein Array oder eine Instanz einer Klasse ein Parameter ist, kann die aufgerufene Methode die Elemente/Felder dieser Instanz ändern, und der Aufrufer sieht die Änderungen. Das gilt unabhängig davon, ob der `ref`-Modifizierer vorhanden ist.
- Ein Parameter mit dem [`out`][out-parameter]-Modifizierer gibt einen Wert von der aufgerufenen Methode an den Aufrufer zurück. Der Parameter kann an die aufgerufene Methode übergeben werden, ohne initialisiert zu werden, und in jedem Fall wird er innerhalb der aufgerufenen Methode so behandelt, als wäre er beim Eintritt nicht initialisiert gewesen. Ein Verständnis des Verhaltens und der Regeln zu Parameter-Modifizierern lässt sich am leichtesten anhand von Beispielen (siehe unten) und Compiler-Meldungen gewinnen.

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- `out`-Parametern muss innerhalb einer aufgerufenen Methode ein Wert zugewiesen werden.

- Ein Parameter mit dem [`ref`][ref-parameter]-Modifizierer übergibt einen Wert an eine aufgerufene Methode. Wenn die Methode zurückkehrt, findet der Aufrufer in diesem Parameter alle Aktualisierungen wieder, die die aufgerufene Methode vorgenommen hat.

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

-`ref`-Parameter müssen Variablen sein, denn die aufgerufene Methode arbeitet direkt auf dem Parameter, so wie der Aufrufer ihn sieht.

- Die Modifizierer `out` und `ref` sind sowohl in der Signatur der aufgerufenen Methode als auch an der Aufrufstelle erforderlich.
- `out`-Parameter können an der Aufrufstelle inline deklariert werden, und zwar so: `Foo(out int importantValue);`
- Wenn du eine Methode aufrufst, die `out`-Parameter hat, dich aber der Wert, der einem oder mehreren davon zugewiesen wird, nicht interessiert, kannst du die [Verwerfen][discard]-Dummy-Variable `_` verwenden, etwa so: `Foo(out int _);`

Alle Regeln zu `ref`- und `out`-Parametern werden vom Compiler durchgesetzt.

[`in`][in-parameter]-Parameter gibt es ebenfalls, sie sind aber in erster Linie eine Performance-Optimierung und werden in der `structs`-Übung besprochen, wo sie am relevantesten sind.

Die oben verlinkte Dokumentation ist unten zusammengefasst:

- [passing-parameters][passing-parameters]: erklärt, wie Werte als Argumente übergeben werden können. Beachte, dass das Thema Structs und Parameter in der `structs`-Übung behandelt wird.
- [ref-parameter][ref-parameter]: beschreibt, wie `ref`-Parameter funktionieren.
- [out-parameter][out-parameter]: beschreibt, wie `out`-Parameter funktionieren.

Wenn du die Dokumentation durcharbeitest, beachte, dass sie die folgenden Begriffe verwendet:

- Parameter / formeller Parameter: bezeichnet den Parameter so, wie die aufgerufene Methode ihn sieht.
- Argument: bezeichnet den Parameter so, wie der Aufrufer ihn sieht.

[Man kann argumentieren][so-tuples-vs-out], dass ein Großteil des Nutzens von `out`-Parametern durch die Einführung von `tuples` in C# 7 weggefallen ist. Die `tuples`-Übung zeigt, wie `tuples` verwendet werden, um mehrere Werte zurückzugeben.

`ref` ist zwar einfach zu verwenden und hat keine Performance-Einbußen, es lohnt sich aber, sich anzusehen, wie die Probleme, die es löst, in einer bestimmten Codebasis behandelt werden, bevor du es breit einsetzt. Es gibt Alternativen, etwa die Übergabe als Wert und die Verwendung des Werts aus der Rückgabeanweisung der aufgerufenen Methode. Auch hier können `tuples` eine Rolle spielen.

Du wirst in der [Dokumentation][ref-parameter] sehen, dass `out` und `ref` in bestimmten Situationen nicht verwendet werden können, aber die kannst du vorerst ignorieren. Der Compiler wird dich darauf hinweisen, wenn solche Situationen auftreten.

Beachte, dass `optional parameters` und `named arguments` in der `method-overloading`-Übung behandelt werden.

Die verwandten Themen [`ref local`][ref-local] und [`ref return`][ref-return] werden an anderer Stelle behandelt.

## Stack-Allokationen

Die Regeln zu Parametern und ihren Modifizierern sind so einfach, dass du sie so hinnehmen und auf ihrer Abstraktionsebene verstehen kannst. Wenn dich jedoch die zugrunde liegenden Mechanismen interessieren und warum diese Schlüsselwörter einen Performance-Unterschied machen können, zumindest im Fall von `struct`s, dann kannst du mit diesem [_Wikipedia-Artikel_][calling-conventions] beginnen; beachte, dass C# auf x86/64 `stdcall` verwendet.

Der Kern der Sache ist: Bei unveränderten Parametern wird der **Wert** einer Variablen auf den Stack des Programms kopiert, damit sie einer aufgerufenen Routine zur Verfügung steht. Bei `ref`-, `out`- und `in`-Parametern dagegen wird ein Zeiger (**Referenz**) auf den Speicher, der den Wert enthält, auf den Stack des Programms gelegt, und Werte werden dem Speicher zugewiesen, auf den die Referenz zeigt.
