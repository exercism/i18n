# Über

[Guards][guards] werden als Ergänzung zum [Pattern Matching][exercism-pattern-matching] verwendet. Sie ermöglichen komplexere Prüfungen. Sie können in [einigen, aber nicht allen Situationen][where-guards-can-be-used] verwendet werden, in denen Pattern Matching verwendet werden kann, zum Beispiel in Funktionsklauseln oder Case-Klauseln.

```elixir
def empty?(list) when is_list(list) and length(list) == 0 do
  true
end
```

- Guards beginnen mit dem `when`-Schlüsselwort, gefolgt von einem booleschen Ausdruck.
- Guard-Ausdrücke sind spezielle Funktionen, für die gilt:
  - Sie müssen [rein][pure-function] sein und dürfen keine globalen Zustände verändern.
  - Sie müssen strikte `true`- oder `false`-Werte zurückgeben.
- Eine Liste häufiger Guards findest du in der [Elixir-Dokumentation][kernel-guards]. Dazu gehören:
  - Typprüfungen: [`is_integer/1`][guard-is-integer], [`is_list/1`][guard-is-list], [`is_nil/1`][guard-is-nil] usw.
  - Arithmetische Operatoren: [`+/2`][guard-plus], [`-/2`][guard-minus] usw.
  - Vergleiche: [`==/2`][guard-equals], [`>/2`][guard-greater], [`</2`][guard-less] usw.
  - Boolesche Operatoren: [`and/2`][guard-and], [`or/2`][guard-or], [`not/1`][guard-not]
  - Mitgliedschaftsoperator: [`in/2`][guard-in]
- Du kannst deinen eigenen Guard mit [`defguard`][defguard] definieren.

  - Laut Elixirs [Namenskonvention][naming] sollten Guard-Namen mit `is_` beginnen.

    ```elixir
    defmodule HTTP do
      defguard is_success(code) when code >= 200 and code < 300

      def handle_response(code) when is_success(code) do
        :ok
      end
    end
    ```
