# Aufgaben

Aufgaben sind GitHub-Issues, bei denen wir uns über Hilfe freuen: vom Korrekturlesen von Texten bis zum Bauen von Konzeptübungen.
Sie werden auf der Website angezeigt und verlinken auf die entsprechenden Issues auf GitHub.
Jede Aufgabe ist mit einer oder mehreren Eigenschaften versehen, die aus den Labels des Issues gefüllt werden.
Anschließend lassen sich Aufgaben nach ihren Eigenschaften filtern.

## Tags

Damit ein Issue als Aufgabe gilt, muss es mit einem oder mehreren aufgabenspezifischen Labels versehen sein.
Maintainer können so festlegen, dass nur bestimmte Issues als Aufgaben erscheinen.

Jedes Aufgaben-Label ist definiert als `x:<type>/<value>`, und fünf Aufgabentypen werden unterstützt:

- `action`
- `knowledge`
- `module`
- `size`
- `type`

### Action-Tag

Die Labels `x:action/<value>` beschreiben, welche Art von Arbeit auf dich zukommt, wenn du an diesem Issue arbeitest.

| Tag                  | Beschreibung                            |
| -------------------- | -------------------------------------- |
| `x:action/create`    | Etwas von Grund auf neu erstellen       |
| `x:action/fix`       | Ein Issue beheben                       |
| `x:action/improve`   | Bestehende Funktionalität/Inhalte verbessern |
| `x:action/proofread` | Text korrekturlesen                     |
| `x:action/sync`      | Inhalte mit ihrer neuesten Version abgleichen |

### Knowledge-Tag

Die Labels `x:knowledge/<value>` beschreiben, wie viel Wissen über Exercism du für die Mitarbeit brauchst.

| Tag                        | Beschreibung                                |
| -------------------------- | ------------------------------------------ |
| `x:knowledge/none`         | Kein vorhandenes Wissen über Exercism nötig |
| `x:knowledge/elementary`   | Wenig Wissen über Exercism nötig            |
| `x:knowledge/intermediate` | Recht viel Wissen über Exercism nötig       |
| `x:knowledge/advanced`     | Umfassendes Wissen über Exercism nötig      |

### Module-Tag

Die Labels `x:module/<value>` geben an, an welchem Teil von Exercism du arbeitest.

| Tag                          | Beschreibung                 |
| ---------------------------- | --------------------------- |
| `x:module/analyzer`          | Arbeit an Analyzern           |
| `x:module/concept`           | Arbeit an Konzepten           |
| `x:module/concept-exercise`  | Arbeit an Konzeptübungen      |
| `x:module/generator`         | Arbeit an Übungsgeneratoren   |
| `x:module/practice-exercise` | Arbeit an Praxisübungen       |
| `x:module/representer`       | Arbeit an Representern        |
| `x:module/test-runner`       | Arbeit an Test-Runnern        |

### Size-Tag

Die Labels `x:size/<value>` beschreiben den erwarteten Arbeitsaufwand für dich.

| Tag              | Beschreibung            |
| ---------------- | ---------------------- |
| `x:size/tiny`    | Winziger Arbeitsaufwand |
| `x:size/small`   | Kleiner Arbeitsaufwand  |
| `x:size/medium`  | Mittlerer Arbeitsaufwand |
| `x:size/large`   | Großer Arbeitsaufwand   |
| `x:size/massive` | Riesiger Arbeitsaufwand |

### Type-Tag

Die Labels `x:type/<value>` beschreiben die Art der Arbeit, die dich erwartet.

| Tag              | Beschreibung                                                                                                                                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x:type/ci`      | Arbeit an Continuous Integration (z. B. GitHub Actions Workflows)                                                                                                                                                 |
| `x:type/coding`  | Schreibe Code, der nicht Teil der Inhalte für Lernende ist. Das sind normalerweise Aufgaben rund um Produktions-Tooling (z. B. Test-Runner), internes Tooling (Generatoren) oder Bibliotheken, die Exercism pflegt. |
| `x:type/content` | Arbeit an Inhalten (z. B. Übungen, Konzepten)                                                                                                                                                                     |
| `x:type/docker`  | Arbeit an Dockerfiles                                                                                                                                                                                            |
| `x:type/docs`    | Arbeit an der Dokumentation                                                                                                                                                                                      |

## Beanspruchte und nicht beanspruchte Tags

Damit eine Aufgabe ausgeblendet wird, weil bereits jemand daran arbeitet, kann ein Issue das Label `x:status/claimed` hinzufügen.
