# Abstrakte Klassen

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## Das $ gehört zum Namen

Jede abstrakte Klasse trägt ein führendes `$` im Namen, und nur abstrakte Klassen tun das. Ein Typ, der mit `$` beginnt, ist also einer, von dem du kein Objekt erzeugen kannst, und das sieht man überall, wo der Name auftaucht.

## Was hinein darf

Routinen- und Iteratorsignaturen, endend mit dem Semikolon. Keine Rümpfe, keine Attribute, kein `create`. Eine abstrakte Klasse beschreibt, was man von etwas *verlangen* kann, nie, was es enthält.

## Konformität

```sather
class TRAPEZE < $ACT is
```

Die Klasse muss jede aufgelistete Routine definieren, mit passenden Argumenttypen und passendem Rückgabetyp. Das wird beim Kompilieren geprüft.

Eine Klasse kann zu mehreren konform sein:

```sather
class TRAPEZE < $ACT, $RISKY is
```

und abstrakte Klassen können einander erweitern:

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## Wo die dynamische Bindung stattfindet

Eine Variable eines abstrakten Typs enthält eine Referenz auf irgendein konformes Objekt. Wenn du eine Routine darauf aufrufst, wird zur Laufzeit die Version gewählt, die zur echten Klasse des Objekts gehört.

Das ist die einzige Stelle, an der Sather zur Laufzeit etwas entscheidet. Ein Aufruf auf einer Variable eines konkreten Typs steht schon beim Kompilieren fest.

## typecase

Manchmal spielt die Art wirklich eine Rolle. `typecase` fragt:

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

Innerhalb eines Zweigs hat die Variable den engeren Typ. Greif nur selten darauf zurück: Ein `typecase` über jede Art von Act ist meistens eine Routine, die von Anfang an in die abstrakte Klasse gehört hätte.

## $OB

`$OB` ist die abstrakte Klasse, zu der jedes Objekt konform ist. Sie ist gelegentlich nützlich und meistens ein Zeichen dafür, dass unterwegs ein Typ verloren gegangen ist.

## Warum nicht Vererbung?

Sather trennt zwei Dinge, die die meisten Sprachen zusammenwerfen. `<` sagt nur, was eine Klasse *kann*. Eine Implementierung von woanders zu bekommen ist `include`, das ist die übernächste Übung, und das ist eine eigene Entscheidung.
