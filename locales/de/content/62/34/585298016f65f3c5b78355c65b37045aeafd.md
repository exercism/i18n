# Tests

## Übungsdateien

Eine heruntergeladene Übung enthält die folgenden Dateien, mit denen du deine Lösung baust und testest:

```text
hello-world/
├── HelloWorld.vb       # Your solution
├── HelloWorldTests.vb  # The test suite
├── HelloWorld.vbproj   # Project and build configuration
└── packages.lock.json  # Resolved project dependencies
```

Die Dateinamen unterscheiden sich je nach Übung.
Schreibe deine Lösung in die `.vb`-Datei, deren Name nicht auf `Tests` endet.
Die Datei, deren Name auf `Tests.vb` endet, ist die xUnit-Testsuite; normalerweise solltest du sie nur bearbeiten, um `Skip`-Argumente zu entfernen.
Die Projekt- oder die Lock-Datei musst du normalerweise nicht bearbeiten.

## Tests ausführen

Öffne ein Terminal im Verzeichnis der Übung und führe Folgendes aus:

```bash
dotnet test
```

Der Befehl stellt die Abhängigkeiten des Projekts wieder her, baut das Projekt und führt seine Tests aus.
Du kannst auch `dotnet watch test` verwenden, um die Tests erneut auszuführen, sobald sich eine Quelldatei ändert.

## Übersprungene Tests

Übungen aktivieren zunächst nur den ersten Test, damit du den Rest Schritt für Schritt lösen kannst.
Öffne die Datei, deren Name auf `Tests.vb` endet, um die Tests zu finden.
Jeder Test ist eine `Sub`-Subroutine, die mit dem xUnit-Attribut `<Fact>` markiert ist.
Ein Test wird übersprungen, solange sein `<Fact>`-Attribut ein `Skip`-Argument hat:

```vb
<Fact(Skip:="Remove this Skip property to run this test")>
Public Sub Lowercase_words()
    Assert.Equal("ROR", Abbreviate("Ruby on Rails"))
End Sub
```

Um den Test zu aktivieren, entferne einfach das `Skip`-Argument:

```vb
<Fact>
Public Sub Lowercase_words()
    Assert.Equal("ROR", Abbreviate("Ruby on Rails"))
End Sub
```

Nachdem der neu aktivierte Test bestanden ist, wiederhole diesen Vorgang mit dem nächsten übersprungenen Test.
Wenn alle Tests aktiviert sind und bestanden werden, bist du fertig.
