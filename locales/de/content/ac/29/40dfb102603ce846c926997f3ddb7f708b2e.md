# Einführung

Der **Call-Stack**, oder einfach **Stack**, ist eine spezielle Datenstruktur, die am höchsten Punkt im Speicher beginnt und nach unten wächst.

## Push und Pop

Der Stack unterstützt mindestens zwei Operationen, mit Befehlen desselben Namens:

| Befehl | Ausgeführte Operation                                      |
| ------ | ---------------------------------------------------------- |
| `push` | fügt ein Element zum Stack hinzu                           |
| `pop`  | entfernt das zuletzt hinzugefügte Element und gibt es zurück |

Das bedeutet, dass der Stack eine **Last-In-First-Out (LIFO)**-Datenstruktur ist.

Um den aktuellen Punkt des Stacks im Blick zu behalten, an dem sich das zuletzt hinzugefügte Element befindet, wird das Register `rsp` verwendet.

Ein `push`-Befehl nimmt also einen Operanden und legt dessen Inhalt auf den Stack.
Da der Stack nach unten wächst, wird der Wert in `rsp` um die Größe des gespeicherten Werts verringert.

Ein `pop`-Befehl nimmt ebenso einen Operanden und schreibt den zuletzt hinzugefügten Wert im Stack (den, auf den `rsp` zeigt) in diesen Operanden.
Danach wird der Wert in `rsp` um die Größe des entnommenen Werts erhöht.

## Lokale Variablen

Es ist auch möglich, den Wert von `rsp` direkt zu verändern.
Das wird oft genutzt, um lokale Variablen für eine Funktion anzulegen.

```x86asm
sub rsp, 24 ; this reserves 24 bytes of space in the stack
add rsp, 24 ; this restores the previous value of rsp, "reducing" the stack by 24 bytes
```

Beachte, dass der in diesem Bereich gespeicherte Wert in dem Moment, in dem Speicher im Stack reserviert wird, _undefiniert_ ist.

~~~~exercism/note
Weder `pop` noch die direkte Manipulation von `rsp` entfernen tatsächlich die im Speicher abgelegten Inhalte.
Das „Entfernen“ aus dem Stack ist nur eine Abstraktion der neuen Adresse in `rsp`.

In manchen Kontexten kann das Sicherheitsbedenken verursachen, weil interne Werte nach außen sichtbar werden.
Eine Möglichkeit, damit umzugehen, ist, den Inhalt jedes von der Funktion genutzten Stack-Bereichs auf null zu setzen.
~~~~

## Call und Ret

Der Hauptzweck des Stacks ist es, die Rücksprungadresse für aufgerufene Funktionen im Blick zu behalten.

Wie in einem früheren Konzept erwähnt, gibt es ein spezielles Register namens `rip`, das auf den nächsten auszuführenden Befehl zeigt.
Dieses Register steuert den Ablauf eines Programms und wird von Befehlen wie `jmp` und `call` verändert.

Immer wenn ein `call`-Befehl verwendet wird, wird der aktuelle Wert in `rip` implizit auf den Stack gelegt.
Anschließend wird der Operand des Befehls nach `rip` verschoben, sodass die Ausführung in der aufgerufenen Funktion fortgesetzt wird.

Ein `ret`-Befehl macht das Gegenteil.
Er holt einen Wert vom Stack nach `rip`, sodass die Ausführung zur aufrufenden Funktion zurückkehrt.

Beim Eintritt zeigt `rsp` auf die Adresse, an die zurückgesprungen werden soll.
Das ist die Adresse, die `ret` vom Stack holen muss.

Jede Änderung des Werts von `rsp` innerhalb einer Funktion, ob direkt oder durch `push`, muss also vor der Rückkehr aus der Funktion rückgängig gemacht werden.

## Callee-Saved- und Caller-Saved-Register

Neben `rsp` gibt es weitere Register, die über Funktionsaufrufe hinweg erhalten bleiben müssen: `rbp`, `rbx`, `r12`, `r13`, `r14` und `r15`.
Im Allgemeinen erwartet die aufrufende Funktion, diese Register nutzen zu können, ohne dass eine aufgerufene Funktion sie verändert.

Das bedeutet, dass die _aufgerufene_ Funktion die Werte in diesen Registern sichern muss, bevor sie sie verwendet, und sie vor der Rückkehr auf ihre ursprünglichen Werte zurücksetzen muss.
Deshalb heißen sie **Callee-Saved-Register**.

Andere Allzweckregister stehen der aufgerufenen Funktion direkt zur Verfügung.

Das bedeutet, dass die _aufrufende_ Funktion die Werte in diesen Registern sichern muss, bevor sie eine Funktion aufruft, falls die aufgerufene Funktion sie verändert.
Deshalb heißen sie **Caller-Saved-Register**.

_Registerinhalte werden am häufigsten gesichert, indem man sie auf den Stack legt._

## Prolog und Epilog

In manchen Fällen wird der Stack stark genutzt, mit vielen Änderungen, bevor die Funktion zurückkehrt.
Dann kann es aufwendig sein, all diese Änderungen im Blick zu behalten, um sie rückgängig zu machen.

In solchen Fällen besteht eine gängige Strategie darin, die Adresse von `rsp` in einem anderen Register zu sichern, das innerhalb der Funktion ansonsten unverändert bleibt.
Der Wert von `rsp` lässt sich dann am Ende, vor der Rückkehr aus der Funktion, mit einem einfachen `mov`-Befehl wiederherstellen.

Obwohl jedes Register für diesen Zweck verwendet werden kann, ist es üblich, `rbp` als Basiszeiger zu nutzen.
Da `rbp` selbst ein Callee-Saved-Register ist, geht dem oft ein `push rbp` voraus.
Diese Abfolge nennt man üblicherweise **Prolog**.

Am Ende wird `rsp` mit einem `mov rsp, rbp` wiederhergestellt, und danach wird auch `rbp` mit einem `pop` vom Stack wiederhergestellt.
Diese Abfolge nennt man üblicherweise **Epilog**.

```x86asm
section .text
fn:
    ; prologue
    push rbp
    mov rbp, rsp
    ...
    ; epilogue
    mov rsp, rbp
    pop rbp
    ret
```

## Argumente über den Stack übergeben

In der Aufrufkonvention der System V ABI werden Argumente normalerweise in Registern an Funktionen übergeben.
Wenn es jedoch zu viele Argumente gibt oder sie mehr als die Größe eines Registers benötigen, kann der Stack verwendet werden.

In diesen Fällen werden die Werte in umgekehrter Reihenfolge auf den Stack gelegt, sodass das erste Argument näher an `rsp` liegt.
Da `rsp` beim Eintritt auf die Rücksprungadresse zeigt, die in x86-64 ein 8-Byte-Wert ist, ist auf das erste Argument auf dem Stack, falls vorhanden, über `rsp + 8` zuzugreifen.

## Stack-Ausrichtung

Die System V ABI legt fest, dass der Stack unmittelbar _bevor_ der `call`-Befehl ausgeführt wird, 16-Byte-ausgerichtet sein muss.
Da `call` `rip` auf den Stack legt, ist der Stack der aufgerufenen Funktion beim Eintritt **nicht** 16-Byte-ausgerichtet.

Das bedeutet, dass eine Funktion, die eine andere aufruft (insbesondere externe Funktionen), den Stack ausrichten muss, bevor sie `call` verwendet.

Das lässt sich erreichen, indem man einen passenden Wert von `rsp` abzieht.
Beim Eintritt muss dieser Wert um 8 größer als ein Vielfaches von 16 sein: 8, 24, 40 usw.
Da ein `push`-Befehl von `rsp` abzieht, kann eine ungerade Anzahl von `push`-Befehlen denselben Effekt erzielen:

```x86asm
fn_a:
    sub rsp, 24 ; subtracting 8 more than a multiple of 16: this aligns the stack
    call fn_b
    add rsp, 24
    ret

fn_b:
    push rbx    ; odd number of pushes: this aligns the stack
    call fn_c
    pop rbx
    ret
```
