# Ownership

In Cairo ist das Konzept Ownership an _Variablen_ gebunden, nicht an die _Werte_, die sie enthalten.

Werte in Cairo sind unveränderlich. Diese Unveränderlichkeit sorgt dafür, dass der Wert selbst konstant und unverändert bleibt, selbst wenn viele Variablen auf denselben Wert verweisen.
Deshalb muss der Compiler sicherstellen, dass sie vom Programmierer korrekt verwendet werden.
Das ist die Bedeutung von _Ownership_ bei Variablen: Der Eigentümer ist der Code, der die Variable lesen (und schreiben, wenn sie veränderlich ist) kann.

## Regeln für das Ownership von Variablen

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## Gültigkeitsbereich von Variablen

Ein Gültigkeitsbereich ist der Bereich innerhalb eines Programms, in dem eine Variable gültig ist.
Schauen wir uns das folgende Beispiel an. Es deklariert eine Variable `x` vom Typ vorzeichenlose Ganzzahl, und Kommentare geben an, wo die Variable gültig ist:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Hinweise:

- Wenn `x` in den Gültigkeitsbereich eintritt, ist sie gültig.
- Sie bleibt gültig, bis sie den Gültigkeitsbereich verlässt, in diesem Fall bis zum Ende der Funktion `main()`.

## Werte verschieben

Ein Move findet statt, wenn ein Wert an eine andere Funktion übergeben wird. Dabei wird die ursprüngliche Variable, die auf den Wert verwiesen hat, zerstört (und damit unbrauchbar), und es wird eine neue Variable angelegt, die denselben Wert enthält.

Arrays sind ein Beispiel für einen komplexen Typ, der verschoben wird, wenn er an eine andere Funktion übergeben wird.
Zur Erinnerung: So sieht ein Array aus:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

Wie stellt das Typsystem sicher, dass das Cairo-Programm nie versucht, zweimal in dieselbe Speicherzelle zu schreiben?
Betrachte den folgenden Code. Hier versuchen wir, das erste Element des Arrays zweimal zu entfernen:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

In diesem Fall versuchen wir, denselben Wert (das Array in der Variablen `arr`) an beide Funktionsaufrufe zu übergeben.
Das bedeutet, unser Code versucht, das erste Element zweimal zu entfernen. Dabei würde zweimal in dieselbe Speicherzelle geschrieben, was die Cairo VM verbietet und zu einem Laufzeitfehler führt.
Glücklicherweise lässt sich dieser Code nicht kompilieren.
Sobald wir das Array an die Funktion `foo` übergeben haben, ist die Variable `arr` nicht mehr verwendbar.
Wir erhalten diesen Fehler zur Compile-Zeit: Er besagt, dass `Array` das `Copy`-Trait implementieren müsste:

## Das Copy-Trait

Wenn ein Typ das `Copy`-Trait implementiert, wird beim Übergeben an eine Funktion der Wert nicht verschoben, sondern es wird eine neue Variable erstellt, die auf denselben Wert verweist.
Das ist eine kostenlose Operation, denn Variablen sind eine Abstraktion von Cairo und Werte sind immer unveränderlich.

Um das `Copy`-Trait für deinen Typ zu implementieren, fügst du der Typdefinition die Annotation `#[derive(Copy)]` hinzu.
Allerdings erlaubt Cairo das nicht, wenn der Typ oder eine seiner Komponenten das `Copy`-Trait nicht implementiert.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## Werte zerstören

Lineare Typen können auch genutzt werden, indem sie zerstört werden. Dadurch wird sichergestellt, dass die zugehörige Ressource korrekt freigegeben wird.
Das erreicht man, indem man das `Drop`-Trait implementiert oder ableitet. Es signalisiert dem Compiler, dass der Typ sicher zerstört werden kann, sobald er nicht mehr nützlich ist.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

Momentan kann die `Drop`-Implementierung für alle Typen abgeleitet werden, außer für Wörterbücher (`Felt252Dict`) und Typen, die Wörterbücher enthalten.
Das liegt daran, dass Wörterbücher beim Zerstören „gequetscht“ werden müssen.
Dafür leiten wir das `Destruct`-Trait ab:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## Rückgabewerte und Gültigkeitsbereich

Werte zurückzugeben ist gleichbedeutend mit dem Verschieben dieser Werte.
Das folgende Beispiel zeigt eine Funktion, die einen Wert zurückgibt:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
