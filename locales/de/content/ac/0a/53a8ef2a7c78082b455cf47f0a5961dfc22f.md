# Generatoren

Ein `generator` ist eine Funktion oder ein Ausdruck, der einen speziellen Typ von [Iterator][iterator] zurückgibt, den sogenannten [`generator iterator`][generator-iterator].
`Generator-iterator`s sind [lazy][lazy iterator]: Sie speichern ihre `values` nicht im Speicher, sondern _erzeugen_ ihre Werte erst, wenn sie gebraucht werden.

Eine Generatorfunktion sieht aus wie jede andere Funktion, enthält aber einen oder mehrere [yield-Ausdrücke][yield expression].
Jedes `yield` unterbricht die Ausführung des Codes und speichert den aktuellen Ausführungszustand (_einschließlich aller lokalen Variablen und try-Anweisungen_).
Wenn der Generator fortgesetzt wird, nimmt er den Zustand von der Unterbrechung wieder auf, anders als reguläre Funktionen, die mit jedem Aufruf zurückgesetzt werden.


## Einen Generator erstellen

Generatoren werden ähnlich konstruiert wie andere Schleifen- oder rekursive Funktionen, benötigen aber einen [`yield`-Ausdruck](#the-yield-expression), den wir uns später noch genauer ansehen.

Ein Beispiel ist eine Funktion, die die _Quadrate_ aus einer gegebenen Liste von Zahlen zurückgibt.
So wie sie derzeit geschrieben ist, muss die gesamte Eingabe verarbeitet werden, bevor Werte zurückgegeben werden können:

```python
>>> def squares(list_of_numbers):
...     squares = []
...     for number in list_of_numbers:
...         squares.append(number ** 2)
...     return squares
```

Du kannst diese Funktion so in einen Generator umwandeln:

```python
>>> def squares_generator(list_of_numbers):
...     for number in list_of_numbers:
...         yield number ** 2
```

Der Grundgedanke dahinter ist, dass du einen Generator verwendest, wenn du nicht alle Werte _auf einmal_ erzeugen musst.
Das spart Speicher und Rechenleistung, da nur der Wert berechnet wird, an dem du _gerade arbeitest_.


## Einen Generator verwenden

Generatoren können in Python die meisten `iterables` ersetzen.
Das schließt _Funktionen_ oder _Objekte_ ein, die ein `iterable`/`iterator` als Argument erwarten.

So verwendest du den Generator `squares_generator()`:

```python
>>> squared_numbers = squares_generator([1, 2, 3, 4])

>>> for square in squared_numbers:
...     print(square)
...
1
4
9
16
```

Werte innerhalb eines `generator` können auch über die Funktion `next()` erzeugt oder abgerufen werden.
`next()` ruft die Methode `__next__()` eines Generator-Iterator-Objekts auf, „bringt“ den Code also voran und wertet ihn bis zu seinem `yield`-Ausdruck aus, der dann einen Wert „liefert“ oder zurückgibt:

```python
>>> squared_numbers = squares_generator([1, 2])

>>> next(squared_numbers)
1
>>> next(squared_numbers)
4
```

Wenn ein `generator-iterator` vollständig verbraucht ist und keine Werte mehr zurückzugeben hat, wirft er einen `StopIteration`-Fehler.

```python
>>> next(squared_numbers)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
StopIteration
```


~~~~exercism/note

Generator-Iteratoren sind eine spezielle Teilmenge der [Iteratoren][iterator].
`Iterators` sind der Mechanismus bzw. das Protokoll, das das Durchlaufen von _iterables_ ermöglicht.
Generator-Iteratoren und die Iteratoren, die von gängigen Python-[`iterables`][iterables] zurückgegeben werden, verhalten sich sehr ähnlich, aber es gibt einige wichtige Unterschiede:

- Sie werden _[verzögert ausgewertet][lazy evaluation]_; die Iteration ist _einbahnig_ und es gibt kein „Zurückspringen“ zu einem vorherigen Wert.
- Sie werden _verbraucht_, indem man über die zurückgegebenen Werte iteriert; es gibt kein Zurücksetzen oder Speichern im Speicher.
- Sie lassen sich nicht sortieren und nicht umkehren.
- Sie sind keine Sequenztypen und haben _keine_ `indexes`. 
  Du kannst nicht per Addition oder Subtraktion auf einen vorherigen oder zukünftigen Wert verweisen und kannst weder die eckige Klammer-Notation (`[]`) noch Slicing verwenden.
- Sie können nicht mit der Funktion `len()` verwendet werden, da sie keine Länge haben.
- Sie können _endlich_ oder _unendlich_ sein. Sei vorsichtig, wenn du alle Werte aus einem _unendlichen_ `generator-iterator` sammelst!

## Der yield-Ausdruck

Der [yield-Ausdruck][yield expression] ist dem `return`-Ausdruck sehr ähnlich.
_Anders als_ beim `return`-Ausdruck gibt `yield` Werte an den Aufrufer an einem _bestimmten Punkt_ ab und unterbricht die Auswertung/Rückgabe weiterer Werte, bis diese angefordert werden.
Wenn `yield` ausgewertet wird, pausiert es die Ausführung der umgebenden Funktion und gibt alle Werte der Funktion _zu diesem Zeitpunkt_ zurück.
Die Funktion bleibt dann _im Gültigkeitsbereich_, und wenn `__next__()` aufgerufen wird, wird die Ausführung fortgesetzt, bis `yield` erneut angetroffen wird.


~~~~exercism/note
Die Verwendung von `yield`-Ausdrücken ist außerhalb von Funktionen nicht erlaubt.
~~~~

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1

>>> lets_try = infinite_sequence()
>>> lets_try.__next__()
0
>>> lets_try.__next__()
1
```


## Warum einen Generator erstellen?

Generatoren sind in vielen Anwendungen nützlich.

Wenn du mit einer potenziell großen Sammlung von Werten arbeitest, möchtest du vielleicht nicht alle davon in den Speicher laden.
Ein Generator kann verwendet werden, um größere Daten Stück für Stück zu verarbeiten, was Speicher spart und die Leistung verbessert.

Generatoren sind auch sehr hilfreich, wenn ein Prozess oder eine Berechnung _komplex_, _teuer_ oder _unendlich_ ist:

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1
```

Wenn nun `__next__()` für das Objekt `infinite_sequence` aufgerufen wird, gibt es die _vorherige Zahl_ + 1 zurück.
