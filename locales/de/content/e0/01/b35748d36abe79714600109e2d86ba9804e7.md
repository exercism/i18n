# Überblick

Der Typ `Result` ermöglicht es einer Funktion, einen einzelnen Wert zurückzugeben, der alle folgenden Dinge angibt:
- Ob die Operation erfolgreich war oder fehlgeschlagen ist
- Bei Erfolg den resultierenden Wert der Operation
- Bei einem Fehler den Grund für den Fehler

In anderen Programmiersprachen, die so etwas wie einen `Result`-Typ nicht unterstützen, sind die folgenden Muster üblich, um die genannten Ziele zu erreichen:
- Eine Funktion, die einen numerischen Code zurückgibt, der Erfolg oder den Grund für den Fehler angibt, und die einen Ausgabeparameter benötigt, der bei Erfolg den Wert aufnimmt.
- Eine Funktion, die bei Erfolg den Wert oder bei einem Fehler NULL zurückgibt, und dann eine andere Funktion, um den Fehlercode abzurufen, der den Grund für den Fehler angibt.

Ein weiterer verbreiteter Mechanismus zur Fehlerbehandlung ist die Ausnahme. Sie bricht abrupt aus der aktuellen Funktion aus und übergibt die Kontrolle an den ersten Handler im Aufrufstapel, wenn ein Fehler auftritt.  
Wenn kein Handler die Ausnahme „fängt“, bricht das Programm ab.

## Vorteile der Verwendung des `Result`-Typs

* __Sicherheit zur Kompilierzeit__: Indem Erfolg oder Misserfolg eines Funktionsaufrufs im Typsystem explizit gemacht werden, kann der Compiler sicherstellen, dass der aufrufende Code alle Fehlerfälle behandelt. Das verhindert eine große Kategorie von Fehlern, die bei Nullwerten auftreten könnten.

* __Sicherheit zur Laufzeit__: Anstatt `null` zu verwenden, nutzt der `Result`-Typ `Error`, um einen Fehler darzustellen. Dadurch kann keine `NullReferenceException` auftreten.

* __Explizite Fehlerbehandlung__: Code, der eine Funktion aufruft, die ein `Result` zurückgibt, muss anerkennen, dass der Aufruf fehlschlagen kann; der aufrufende Code muss solche Fehler bewusst behandeln.  Es gibt keine stillen Fehler und keine überraschenden Ausnahmen.

* __Vorhersehbarer Kontrollfluss__: Ein `Result` wird wie jeder andere Wert zurückgegeben; es springt nicht wie eine Ausnahme aus dem Aufrufstapel.  Du weißt immer, wo Fehler entstehen und wie sie sich ausbreiten.

* __Verbesserte Lesbarkeit und Wartbarkeit__: Durch die Rückgabe eines `Result` zeigt die Signatur einer Funktion klar das erwartete Verhalten bei Erfolg und bei einem Fehler an.

## Verwendung

Der Typ `Result` ist ein generischer Typ, der zwei zugrunde liegende Typen enthält:
- Den Typ des resultierenden Werts bei einer erfolgreichen Operation
- Den Typ, der bei einem Fehler den Grund für den Fehler darstellt

Der Typ `Result` ist außerdem eine [diskriminierte Union][discriminated-union] mit den folgenden möglichen Fällen:
* `Ok <value>` steht für ein erfolgreiches Ergebnis
* `Error <reason>` steht für einen Fehler

Die folgende Funktion zeigt, wie du einen `Result`-Wert erstellst:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

In diesem Beispiel ist der `Ok`-Wert ein String (der angegebene Name), und der `Error`-Wert ist ebenfalls ein String (die Ursache des Fehlers in für Menschen lesbarer Form).

## Den Inhalt eines `Result`-Werts auslesen

Betrachte die folgende Typdefinition und Funktionssignatur:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

Code, der die Funktion `openFile` aufruft, kann Pattern Matching verwenden, um die Erfolgs- und Fehlerfälle zu behandeln, wie im folgenden Beispiel:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
