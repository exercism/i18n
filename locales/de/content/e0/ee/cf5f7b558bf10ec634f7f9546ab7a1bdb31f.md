# Einführung

## Interface als Menge von Methoden

In seiner einfachsten Form ist ein **Interface-Typ** eine Menge von Methodensignaturen.
Hier ist ein Beispiel für eine Interface-Definition, die zwei Methoden `Add` und `Value` enthält:

```go
type Counter interface {
    Add(increment int)
    Value() int
}
```

Parameternamen wie `increment` können in der Interface-Definition weggelassen werden, aber sie erhöhen oft die Lesbarkeit.

Interface-Namen in Go enthalten nicht das Wort `Interface` oder `I`.
Stattdessen enden sie oft auf `er`, z. B. `Reader`, `Stringer`.

## Ein Interface implementieren

Jeder Typ, der die Methoden des Interfaces definiert, „implementiert" das Interface automatisch implizit.
In Go gibt es kein `implements`-Schlüsselwort.

Der folgende Typ implementiert das `Counter`-Interface, das wir oben gesehen haben.

```go
type Stats struct {
    value int
    // ...
}

func (s Stats) Add(v int) {
    s.value += v
}

func (s Stats) Value() int {
    return s.value
}

func (s Stats) SomeOtherMethod() {
    // The type can have additional methods not mentioned in the interface.
}
```

Für die Implementierung des Interfaces spielt es keine Rolle, ob die Methode einen Wert- oder einen Pointer-Empfänger hat.
(Schau dir die [Methoden-Konzepte][concept-methods] noch einmal an, wenn du dir dabei unsicher bist.)

> Ein Wert vom Interface-Typ kann jeden Wert halten, der diese Methoden implementiert. [^1]

Das bedeutet, dass `Stats` jetzt überall dort verwendet werden kann, wo das `Counter`-Interface erwartet wird.

```go
func SetUpAnalytics(counter Counter) {
    // ...
}

stats := Stats{}
SetUpAnalytics(stats)
// works because Stats implements Counter
```

Da Interfaces implizit implementiert werden, kann ein Typ leicht mehrere Interfaces implementieren.
Er muss nur alle notwendigen Methoden definiert haben.

## Das leere Interface

In Go gibt es einen ganz besonderen Interface-Typ, den **leeren Interface-Typ**, der null Methoden enthält.
Das leere Interface wird so geschrieben: `interface{}`.
`any` ist ein Alias für `interface{}` und wird häufiger verwendet.

Da das leere Interface keine Methoden hat, implementiert es jeder Typ implizit.
Das ist hilfreich, um eine Funktion zu definieren, die generisch jeden Wert annehmen kann.
In diesem Fall verwendet der Funktionsparameter den leeren Interface-Typ.
