# Einführung

In vielen objektorientierten Sprachen ist es üblich, Verhalten zu erweitern, indem man eine Unterklasse einer Elternklasse bildet, Methoden von der Elternklasse erbt und gleichzeitig neue hinzufügt.
So entsteht eine Objekthierarchie.

Julia _hat keine Klassen_, und folglich auch _keine Unterklassen_.
Wie erben und erweitern wir also bestehendes Verhalten?

In früheren Konzepten haben wir gesehen, wie man eine Typhierarchie erstellt, und außerdem gelernt, wie Julia [Multiple Dispatch][concept-multiple-dispatch] nutzt, um Methoden anhand der Argumenttypen auszuwählen.

Außerdem hat Julia mehrere informelle Interfaces, mit denen du deine eigenen Typen an Verhalten anbinden kannst, das bereits für Standardtypen definiert ist.

Am einfachsten lässt sich das am Iterator-Interface zeigen.

## Iteratoren

Im Lehrplan haben wir bereits mehrere Möglichkeiten gesehen, wie Julia mit jedem Element einer Sammlung umgehen kann.

- [Schleifen][concept-loops], wie etwa `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Höhere Funktionen][concept-hof]: `map(√, [1, 4, 9])`
- [Comprehensions][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Generatoren][concept-comprehensions]: `(x^2 for x in 1:1e6)`, die erst bei Bedarf ausgewertet werden.

Julia weiß also offensichtlich, wie es Standard-Sammlungen Element für Element durchläuft: Vektoren und Ranges in den obigen Beispielen, aber auch Sets, Dicts usw.

Wie fügen wir diese Fähigkeit unseren eigenen, selbst definierten Sammlungen hinzu, besonders wenn sie sich wie ein Generator erst bei Bedarf durchlaufen lassen?

### Minimale Anforderungen

Um eine Sequenz zum Iterieren zu erstellen, brauchen wir (mindestens) zwei Dinge:

1. Eine Möglichkeit, das _erste_ Element zu erhalten.
2. Eine Möglichkeit, aus dem aktuellen Zustand das _nächste_ Element zu erhalten.

Julia löst diese Aufgaben mit Methoden der Funktion `Base.iterate()` in den folgenden Schritten:

1. Zuerst wird automatisch `Base.iterate(iter)` aufgerufen.
    - Gibt es nichts zu iterieren, wird `nothing` zurückgegeben.
    - Andernfalls wird das `Tuple` aus dem ersten zurückgegebenen Element und dem ersten Zustand zurückgegeben: `(firstitem, firststate)`.
2. Wurde in der vorherigen Iteration ein Element zurückgegeben, wird automatisch `Base.iterate(iter, state)` aufgerufen, wobei `firststate` als `state`-Argument übergeben wird.
    - Endet die Iteration, wird `nothing` zurückgegeben.
    - Andernfalls wird das `Tuple` aus dem nächsten Element und dem nächsten Zustand zurückgegeben: `(nextitem, nextstate)`.
3. Schritt 2 wird bis zur Beendigung wiederholt.

Diese Schritte laufen alle „unter der Haube“ ab. Das heißt, die Methodenaufrufe und der Zustand werden intern vom Iterationsprotokoll verwaltet (wobei der Zustand undurchsichtig bleibt), und nur das Element ist für übergeordnete Konstrukte wie Schleifen sichtbar.
Anders gesagt, wir sehen immer nur das `item`, während alles andere in einer Blackbox bleibt.

[Multiple Dispatch][concept-multiple-dispatch] ist dabei zentral.
Der Typ von `iter` bestimmt, welche Methoden aufgerufen werden, und die Anzahl der Argumente bestimmt, ob das erste oder das nächste Element zurückgegeben wird.

Für Standardtypen sind die Methoden bereits definiert: `Vector`, `Range`, `Set` usw. ([derzeit][ref-iterations-collections] insgesamt 14 Typen).

Damit ein eigener Typ `MyType` dasselbe Verhalten teilt, müssen wir zuerst definieren:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

All das klingt in der Theorie wahrscheinlich verwirrend, kann aber ganz einfach sein.
Zur Veranschaulichung stell dir vor, wir wollen einen Typ, der Potenzen einer gegebenen Ganzzahl `n` liefert, bis zu einer maximalen Anzahl.

Definiere zuerst einen eigenen Typ:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Jetzt können wir die `iterate`-Methoden für diesen Typ definieren, aber was sind das erste Element und der erste Zustand?

Um das erste Element zu erhalten, brauchen manche Iteratoren einen komplizierten Aufbau. In diesem einfachen Beispiel fällt aber auf, dass das erste zurückgegebene Element einfach die Basiszahl ist. Wir müssen also nur prüfen, ob der Wert von `count` größer oder gleich eins ist.

Jetzt können wir den ersten Zustand betrachten, der Informationen trägt, die für die nächste Iteration verwendet werden.
Du entscheidest, welche Informationen du dafür im Auge behalten musst, und es kann jeder beliebige Typ sein.

In diesem Fall könnten wir einfach den „Index“ verfolgen, mit dem `n` potenziert wird, oder wir finden eine performantere Variante, indem wir die letzte Potenz von `n` (also das zurückgegebene Element) und den nächsten „Index“ in der Sequenz verwenden.
Diese beiden Zahlen können in ein `Tuple` gepackt und als `state` zurückgegeben werden.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

In diesem Beispiel wird das erste Element (`p.n`) an die Schleife zurückgegeben und der erste Zustand `(p.n, 2)` an die Methode `iterate(P::Powers, state)` übergeben.
Dort können wir den Zustand verarbeiten, um das nächste Element zu erzeugen, indem wir das aktuelle Element mit der Basiszahl multiplizieren und so seine Potenz um `1` erhöhen.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Wenn der Indexwert noch innerhalb von `count` liegt, wird das `Tuple` mit dem `next`-Element und dem erhöhten Zustands-`Tuple` zurückgegeben.
Wenn der Wert von `index` `count` überschreitet, wird stattdessen `nothing` zurückgegeben, um anzuzeigen, dass die Iteration beendet ist.

Vielleicht ist dir aufgefallen, dass die Methoden `iterate(p::Powers)` und `iterate(p::Powers, state)` recht ähnliche Funktionskörper haben.
Wenn wir geschickt sind, erlaubt uns diese Ähnlichkeit tatsächlich eine schlankere Implementierung, indem wir nur die Version mit zwei Argumenten und einem Standardwert für den Zustand verwenden: `Base.iterate(p::Powers, state=(1, 1))`
Damit bräuchten wir die separate Methode `iterate(p::Powers)` mit nur einem Argument nicht.
Das wird in der Praxis häufig so gemacht, wenn es möglich ist.

Bisher haben wir schon einige nützliche Funktionalität: Für die ersten 4 Potenzen von 3 können wir die Ergebnisse durchlaufen, prüfen, ob eine gegebene Zahl in den Ergebnissen enthalten ist, und Aggregatfunktionen wie `sum()` anwenden.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Weitere Methoden

Trotz dieses guten Anfangs funktioniert noch nicht alles.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Tatsächlich liefert `length(Powers(3, 4))` genau dieselbe Fehlermeldung.

Das lässt sich leicht beheben, denn die Länge ist Teil des Typkonstruktors: in diesem Fall 4.
Wir müssen nur `Base.length()` für diesen Typ definieren, dann können wir Comprehensions und `collect()` auf die Sequenz anwenden.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Aus Effizienzgründen ist es am besten, auch `Base.eltype()` zu definieren: den Elementtyp des Ergebnisses.
Das ermöglicht Funktionen wie `collect()`, im Voraus Speicher für den Ausgabe-`Vector{Int}` zu reservieren, statt wiederholt ein `push!()` auf einen `Vector{Any}` auszuführen.

Beachte die Syntax, die du vielleicht noch nicht gesehen hast: Diese Methode wird für den _Typ_ definiert, nicht für eine _Instanz_ des Typs.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Iteratoren müssen _nicht_ zwingend eine endliche Länge haben.
Der Einsatz von „unendlichen“ Sequenzen ist eingeschränkter, aber das Durchlaufen kann nützlich sein, solange es eine Möglichkeit gibt, mit `break` aus der Schleife auszubrechen.
Zum Beispiel könnten wir eine Variante von `Powers` definieren, die Werte kleiner als eine bestimmte Grenze erzeugt (vielleicht `typemax(Int)`, um einen Ganzzahlüberlauf zu vermeiden).

## Zusammenfassung

Interfaces sind recht verwirrend zu erklären, weil der Julia-Ansatz sich so sehr von den meisten anderen Sprachen unterscheidet.
Insbesondere wird der Name des Interfaces in der Implementierung vielleicht gar nicht erwähnt: ganz anders als bei [Unterklassen][wiki-subclass] oder [Mixins][wiki-mixins].

Doch in der Praxis sind sie überraschend einfach:

1. Definiere einen passenden Typ.
2. Finde heraus, welche Methoden erforderlich sind.
3. Implementiere diese Methoden für deinen eigenen Typ; meist sind es nur wenige Methoden, und sie sind recht kurz und einfach.
4. Überlasse den Rest einfach [Multiple Dispatch][concept-multiple-dispatch], automatisch.
