# Einführung in das Quoting

Einen Ratschlag, den neue Bash-Programmierer immer wieder hören werden:

> Setze deine Variablen in Anführungszeichen!

Warum ist das so?

Wenn du eine Variable expandierst (wie `$name`), willst du fast immer den _Wert_ der Variable als einen einzelnen String (oder eine Zahl) verwenden. Du willst nicht, dass der Wert unerwartet als zwei oder mehr getrennte Strings behandelt wird.

## Quoting

Quoting ist der wichtigste Mechanismus, um sicherzustellen, dass ein Stück Text als ein einzelnes Wort behandelt wird. Es gibt zwei Hauptarten von Anführungszeichen.

### Doppelte Anführungszeichen

Innerhalb von doppelten Anführungszeichen sind Parameterexpansion, arithmetische Expansion und Befehlssubstitution erlaubt.

```bash
echo "This is bash version $BASH_VERSION"
```

Du kannst ein wörtliches doppeltes Anführungszeichen in einen String in doppelten Anführungszeichen einfügen, indem du ihm einen Backslash voranstellst.

```bash
echo "She said \"Let me teach you about bash.\""
```

### Einfache Anführungszeichen

Innerhalb von einfachen Anführungszeichen ist _keine_ Expansion erlaubt.

```bash
echo 'This is bash version $BASH_VERSION'
# ...^..................................^
# prints exactly: This is bash version $BASH_VERSION
```

Es ist _nicht möglich_, ein einfaches Anführungszeichen in einen String in einfachen Anführungszeichen einzubetten.

## Warum Quoting wichtig ist

Was genau ist falsch an `echo $name`?

Wenn die Shell eine Codezeile parst, führt sie [mehrere Arten von Expansionen][expansions] in der Reihenfolge aus. Zwei der letzten Expansionen sind _Wortaufteilung_ und _Dateinamen-Erweiterung_.

### Wortaufteilung

Alle Ergebnisse von Parameterexpansion, Befehlssubstitution oder arithmetischer Expansion, _die nicht innerhalb von doppelten Anführungszeichen entstanden sind_, kommen für die „Wortaufteilung“ infrage. Die Shell nimmt das expandierte Ergebnis und teilt es an jeder Zeichenfolge auf, die im Wert von `$IFS` vorkommt. Standardmäßig sind das Leerzeichen, Tabulator und Zeilenumbruch.

Mit einer Shell-Schleife können wir das in Aktion sehen:

```bash
sentence="The quick brown fox jumps."
i=0
for word in "$sentence"; do echo "$((++i)) $word"; done
# ..........^.........^
```
gibt aus
```none
1 The quick brown fox jumps.
```

Aber ohne Anführungszeichen:

```bash
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
gibt aus
```none
1 The
2 quick
3 brown
4 fox
5 jumps.
```

Schauen wir uns das mit einem anderen Wert von `$IFS` an:

```bash
csv="first,second,third"
IFS=","
for word in $csv; do echo "$word"; done
```
gibt aus
```none
first
second
third
```

#### Wortaufteilung deaktivieren

Eine Technik, um die Wortaufteilung zu deaktivieren, besteht darin, `$IFS` auf einen leeren String zu setzen

```bash
sentence="The quick brown fox jumps."
IFS=    # or explicitly, IFS=""
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
gibt aus
```none
1 The quick brown fox jumps.
```

Es ist jedoch nicht empfehlenswert, Variablen ohne Anführungszeichen zu lassen, es sei denn, du deaktivierst auch die Dateinamen-Erweiterung. Wie das geht, sehen wir weiter unten.

### Dateinamen-Erweiterung

Mit „Glob“-Mustern lässt sich ein knappes Muster ausdrücken, das auf eine Menge von Dateien passt. Zum Beispiel kannst du mit `*.md` alle Markdown-Dateien in einem Verzeichnis finden. [Glob-Muster][glob] gibt es seit der Erfindung von Unix.

Die Glob-Platzhalterzeichen sind:

* `*` passt auf null oder mehr beliebige Zeichen,
* `?` passt auf genau ein beliebiges Zeichen,
* `[...]` passt auf genau ein Zeichen aus der Menge der in den eckigen Klammern aufgeführten Zeichen.

   ~~~~exercism/advanced
   <details><summary>
   Es gibt viele Details zu Zeichenmengen.
   Klicke hier, um sie anzuzeigen.
   </summary>

    * `[abc]` passt auf genau ein Zeichen, das entweder ein `a`, ein `b` oder ein `c` ist.
        * um eine wörtliche schließende Klammer in den Ausdruck aufzunehmen, mache sie zum ersten Zeichen nach der öffnenden Klammer (nach einem optionalen `^`)
            * `[][]` ist eine Zeichenmenge, die entweder auf eine schließende oder eine öffnende Klammer passt.
            * oder maskiere sie mit einem Backslash: `[[\]]`
    * `[x-y]` passt auf genau ein Zeichen, das im _Bereich_ von `x` bis `y` liegt
        * um einen wörtlichen Bindestrich in eine Zeichenmenge aufzunehmen, muss er entweder das erste Zeichen nach der öffnenden Klammer (nach einem optionalen `^`) oder das letzte Zeichen vor der schließenden Klammer sein.
            * `[-xy]` oder `[xy-]` passen jeweils auf genau ein Zeichen, das ein `-`, ein `x` oder ein `y` ist
            * oder maskiere ihn mit einem Backslash: `[x\-y]`
        * es können mehrere Bereiche angegeben werden, zum Beispiel passt `[0-9A-Fa-f]` auf eine hexadezimale Ziffer
    * `[^abc]` passt auf genau ein Zeichen, das **NICHT** ein `a`, ein `b` oder ein `c` ist,
    * `[^x-y]` passt auf genau ein Zeichen, das **NICHT** im Bereich von `x` bis `y` liegt
    * `[[:character_class:]]` passt auf ein Zeichen, das in der namensgebenden „character_class“ liegt
        * die verfügbaren Zeichenklassen sind: 
            * `lower` -- Kleinbuchstaben
            * `upper` -- Großbuchstaben
            * `alpha` -- Buchstaben
            * `digit` -- Ziffern
            * `alnum` -- Buchstaben und Ziffern
            * `space` -- Leerraum
            * `blank` -- horizontaler Leerraum (Leerzeichen und Tabulator)
            * `xdigit` -- hexadezimale Ziffern
            * `word` -- Zeichen, die in einem Identifier erlaubt sind (Buchstaben, Zahlen, Unterstrich)
            * `punct` -- Satzzeichen
            * `cntrl` -- Steuerzeichen
            * `graph` -- „sichtbare“ Zeichen
            * `print` -- sichtbare Zeichen plus Leerzeichen
        * sie können kombiniert werden:
            * die Klasse `[[:alpha:]]` besteht aus `[[:lower:][:upper:]]`
            * die Klasse `[[:alnum:]]` besteht aus `[[:alpha:][:digit:]]`
            * die Klasse `[[:word:]]` besteht aus `[[:alnum:]_]`
            * der Unterstrich (oktal 137) ist sowohl `[[:word:]]` als auch `[[:punct:]]`
            * die Klasse `[[:graph:]]` besteht aus `[[:alnum:][:punct:]]`
            * die Klasse `[[:print:]]` besteht aus `[[:graph:] ]` -- nur Leerzeichen (oktal 040), kein anderer Leerraum.
   </details>   
   ~~~~

#### Über eine Liste von Dateien iterieren

Mit einer `for`-Schleife kannst du über eine Liste von Dateien iterieren

```bash
for file in *.csv; do
    do_something_with "$file"
done
```

Beachte, dass die Variable `"$file"` in Anführungszeichen steht. Das Glob-Muster kann Dateien zurückgeben, deren Namen Leerzeichen enthalten. Wir müssen die Variable in Anführungszeichen setzen, damit der Befehl `do_something_with` genau ein Argument erhält, nämlich den Dateinamen.

#### Glob-Muster sind keine regulären Ausdrücke

Glob-Muster **sind keine** regulären Ausdrücke.

* auf genau ein Zeichen passen
   * Regex `.`
   * Glob `?`
* auf null oder mehr Zeichen passen
   * Regex `.*`
   * Glob `*`
        * das Glob-Muster `.*` bedeutet „auf einen Dateinamen passen, dessen erstes Zeichen ein wörtlicher Punkt ist, gefolgt von null oder mehr beliebigen Zeichen“.
* auf ein oder mehr Zeichen passen
   * Regex `.+`
   * Glob `?*`
* Regex-Zeichenmengen und Glob-Zeichenmengen verhalten sich gleich.

#### Quoting und Dateinamen-Erweiterung

Es gibt Situationen, in denen du die Dateinamen-Erweiterung unterdrücken möchtest. Der Umgang mit Benutzereingaben ist so eine Situation. Betrachte dieses Code-Schnipsel

```bash
read -p "Enter something: " user_input
echo $user_input
```

Wenn der Benutzer ein Sternchen (`*`) eingibt, was wird dann ausgegeben? 
Die Liste der Dateien im aktuellen Verzeichnis.
Das ist wahrscheinlich nicht, was du willst.

Ein weiteres Beispiel ist, Muster als Argumente an Programme zu übergeben, die Muster erwarten.
Das Programm `tr` wird oft zur Textbearbeitung verwendet. Um den Wert einer Variable in Kleinbuchstaben umzuwandeln, kannst du das hier machen

```bash
var="My Puppet"
echo "$var" | tr '[:upper:]' '[:lower:]'
```
gibt aus
```none
my puppet
```

Ein häufiger Fehler ist, die Argumente von `tr` nicht in Anführungszeichen zu setzen: `tr [:upper:] [:lower:]`

~~~~exercism/caution
Warum ist das ein Problem? 
Glob-Muster ohne Anführungszeichen werden zur Liste der passenden Dateien expandiert.
Angenommen, die Person, die dein Skript verwendet, hat Dateien mit den Namen `p`, `u` und `w` im aktuellen Verzeichnis:

```bash
touch p u w
var="My Puppet"
echo "$var" | tr [:upper:] [:lower:]
```

Das führt zu einem Fehler!

Das Muster `[:upper:]` ohne Anführungszeichen passt auf jedes von `:`, `u`, `p`, `e` oder `r`.
Das Muster `[:lower:]` ohne Anführungszeichen passt auf jedes von `:`, `l`, `o`, `w`, `e` oder `r`.
Bash findet für das erste Muster die Dateien `p` und `u` und für das zweite Muster die Datei `w`, und `tr` wird so aufgerufen

```bash
echo "$var" | tr p u w
```

Und das ist die falsche Anzahl von Argumenten für `tr`.
~~~~

#### Dateinamen-Erweiterung deaktivieren

Mit dem Befehl [`set`][set] kannst du die Dateinamen-Erweiterung deaktivieren.

```bash
echo *      # prints a list of files
set -f      # disable filename expansion
echo *      # prints a literal asterisk
set +f      # enable filename expansion
```

#### Dateinamen-Erweiterung steuern

Es gibt mehrere Einstellungen für den eingebauten Befehl [`shopt`][shopt], die steuern, wie die Dateinamen-Erweiterung funktioniert.
Ein paar interessante sind:

* `shopt -s nocaseglob` -- Groß- und Kleinschreibung beim Abgleich ignorieren
* `shopt -s extglob` -- erweiterte Muster aktivieren
* `shopt -s nullglob` -- wenn keine Dateien passen, ersetze das Muster durch nichts.
   Standardmäßig bleibt das Muster als wörtlicher String stehen.
