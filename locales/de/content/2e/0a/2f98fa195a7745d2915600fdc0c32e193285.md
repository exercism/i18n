# Überblick

In Rust ist ein Iterator jeder Wert, der das Trait [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html) implementiert.
Du kannst die Werte eines Iterators manuell weiterschalten, indem du die Methode `next` auf dem Iterator aufrufst.

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Viele der [`collections`](https://doc.rust-lang.org/std/collections/index.html) von Rust implementieren
[`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html),
womit sich aus den Werten einer Collection ein `Iterator` erzeugen lässt.

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

Beachte, dass `IntoIterator::into_iter` zwar seinen `self`-Typ konsumiert, dieser Typ aber nicht unbedingt ein Wert mit Ownership sein muss.
Deshalb gibt es `IntoIterator`-Implementierungen für [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2),
für [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)
und für [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1).
Diese Implementierungen für unterschiedliche Grade an Ownership sorgen für nützliche Flexibilität.

Für dieses Konzept ist ein Verständnis von `traits` nicht nötig, und wir haben eine ganze Übung für dich, in der du `traits` meistern kannst.
Merk dir für den Moment nur Folgendes:

- Jeder Typ, der `IntoIterator` implementiert, wird _iterierbar_ genannt, weil er in einen Iterator umgewandelt werden kann.
- Jeder Typ, der `Iterator` implementiert, ist ein Iterator, der Werte _erzeugt_ und über den _iteriert_ werden kann.
- Von jedem Typ, der `IntoIterator` implementiert, bekommst du einen Iterator, indem du seine Methode `into_iter` aufrufst.
- Jeder Iterator [implementiert `IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25) und erzeugt sich selbst.
- `for`-Schleifen arbeiten immer mit Iteratoren und rufen `IntoIterator` implizit für ihr Bereichsargument auf.

## `into_iter` und for-Schleifen

for-Schleifen über einen Vektor kennst du wahrscheinlich schon:

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

Im Grunde ist eine `for`-Schleife nur eine Kurzform dafür, die Methode `into_iter` ihres Arguments aufzurufen und dann `next()` so lange aufzurufen, bis keine Elemente mehr erzeugt werden. Anders gesagt lässt sich die vorherige Schleife so ausschreiben:

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## Die Methoden `iter` und `iter_mut`

Die meisten Collection-Typen von Rust bieten die Methoden `iter` und `iter_mut`.
Bei einer Collection vom Typ `T` machen diese beiden Methoden konventionsgemäß Folgendes:

- Der von `iter` zurückgegebene Iterator liefert unveränderlich geliehene `&T`.
- Der von `iter_mut` zurückgegebene Iterator liefert veränderlich geliehene `&mut T`.

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## Der Unterschied zwischen `iter`, `iter_mut` und `into_iter`

Wenn `iter`, `iter_mut` und `into_iter` alle Iteratoren erzeugen, worin liegen dann die Unterschiede?

- Der von `iter` zurückgegebene Iterator liefert konventionsgemäß unveränderlich geliehene `&T`.
- Der von `iter_mut` zurückgegebene Iterator liefert konventionsgemäß veränderlich geliehene `&mut T`.
- Der von `into_iter` zurückgegebene Iterator kann `T`, `&T` oder `&mut T` liefern, je nach Kontext.

Was ist der Kontext für einen Aufruf von `into_iter`?
Sein `self`-Typ.
Erinnere dich daran, dass es `IntoIterator`-Implementierungen für `Vec`, `&'a Vec` und `&'a mut Vec` gibt.
Daraus folgt:

- `(&v).into_iter()` ist gleichwertig zu `v.iter()` => liefert `&T`
- `(&mut v).into_iter()` ist gleichwertig zu `v.iter_mut()` => liefert `&mut T`
- `v.into_iter()` => liefert `T` und verschiebt die Werte

Am deutlichsten zeigt sich das in for-Schleifen:

- `for num in &v {...}` => bindet `&T`
- `for num in &mut v {...}` => bindet `&mut T`
- `for num in v {...}` => bindet `T` und verschiebt die Werte

Oft ist es klarer, `v.iter()` statt `(&v).into_iter()` zu schreiben.
Deshalb gibt es ergonomische Gründe, `iter` und `iter_mut` gegenüber `into_iter` zu bevorzugen.

## Eingebaute Methoden für Iteratoren verwenden

Iteratoren bieten zahlreiche eingebaute Methoden wie `map`, `filter` und `collect`.
Diese Methoden werden manchmal zusammen mit Closures verwendet.

`map` verwendet eine Closure, um die Werte eines Iterators umzuwandeln.
`take` kürzt einen (möglicherweise unendlichen) Iterator auf einen, der nach höchstens der angegebenen Anzahl von Elementen endet.

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter` wandelt den Iterator in einen um, der nur die Werte zurückgibt, für die die Closure `true` ergibt.
`count` konsumiert den Iterator und gibt die Anzahl der erzeugten Elemente zurück.

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map` wandelt einen Iterator um, indem es jedes Element mit der übergebenen Closure in einen neuen Iterator umwandelt und dann alle neu entstandenen Iteratoren durch Verkettung flach zusammenführt.
`collect` erzeugt eine neue Collection, sofern der Collection-Typ [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html) implementiert.

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

Das [`Iterator`-Trait](https://doc.rust-lang.org/std/iter/trait.Iterator.html) bietet _viele_ solcher nützlichen Iterator-Transformationen.
Es lohnt sich, die Dokumentation zu lesen und sich damit vertraut zu machen.

## Faulheit

Wichtig zu wissen: Rust-Iteratoren sind faul.
Sie erzeugen keine Werte, solange wir den Iterator nicht konsumieren.
Wenn du den folgenden Code schreibst und ausführst:

```rust
(0..5).map(|x| x * x);
```

bekommst du folgenden Compilerfehler:

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

Das liegt daran, dass `map` eine Adaptermethode ist, die einen weiteren Iterator zurückgibt.

Um einen Iterator zu konsumieren, verwendest du entweder eine `for`-Schleife oder eine Iterator-Methode, die einen Wert erzeugt, der selbst kein Iterator ist.

Zum Beispiel ist `collect` eine Consumer-Methode (ihre Signatur gibt keinen Iterator zurück, sondern einen generischen Typ):

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
