# Einführung

Der Einsatz von Pattern Matching ist in ausdrucksstarkem, idiomatischem Elixir-Code vorherrschend. Du erinnerst dich vielleicht, dass `=/2` als Match-Operator und nicht als Zuweisungsoperator beschrieben wird. Wenn du den Match-Operator verwendest und das Muster auf der linken Seite zur rechten Seite passt, werden alle Variablen auf der linken Seite gebunden. Zurückgegeben wird der Wert der rechten Seite. Gibt es keine Übereinstimmung, wird ein `MatchError` ausgelöst.

```elixir
2 = 2
# => 2
# Literals can be matched if they are the same

2 = 3
# => ** (MatchError) no match of right hand side value: 3

{_, denominator} = Float.ratio(0.25)
# => {1, 4}
# the variable `denominator` is bound to the value 4
```

Denk daran: Der Abgleich erfolgt von der rechten zur linken Seite.

Im letzten Beispiel können wir eine Variable, die wir im Pattern Matching nicht brauchen, verwerfen, indem wir `_` verwenden. Jede Variable, die mit einem `_` beginnt, wird von der Laufzeitumgebung nicht verfolgt.

## Pattern Matching in benannten Funktionen

Pattern Matching ist auch ein nützliches Werkzeug, wenn du mehrere Funktionsklauseln erstellst. Du kannst Pattern Matching auch auf die Argumente von Funktionen anwenden. Das bestimmt dann, welche Funktionsklausel aufgerufen wird, und zwar von oben in der Datei nach unten, bis der erste Treffer gefunden ist. Variablen können im Funktionskopf gebunden und im Funktionskörper verwendet werden.

```elixir
defmodule Example do
  def named_function(:a = variable_a) do
    {variable_a, 1}
  end

  def named_function(:b = variable_b) do
    {variable_b, 2}
  end
end

Example.named_function(:a)
# => {:a, 1}

Example.named_function(:b)
# => {:b, 2}

Example.named_function(:c)
# => ** (FunctionClauseError) no function clause matching in Example.named_function/1
```
