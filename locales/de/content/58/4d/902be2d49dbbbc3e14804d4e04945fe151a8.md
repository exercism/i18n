# Einführung

_„Datums- und Zeitangaben bringen wir schon kleinen Kindern bei. Wie schwer kann das sein?“_

Viele Programmierer haben diesen Fehler gemacht, und die anschließende Erfahrung wirkt sich meist negativ auf ihre Gesundheit und ihr Glück aus. 

Wer nichttriviale Programmierung mit Datums- und Zeitangaben betreibt, sollte zumindest bereit sein, mögliche Probleme zu verstehen und abzumildern.

Dieses Dokument versucht einen Überblick darüber zu geben, wie Julia mit Datums- und Zeitangaben umgeht, für weitere Details ist jedoch ein Blick in das [Handbuch][Dates] erforderlich.
Außerdem gibt es ein [Wikibook][Wikibook], dessen Erklärungen manche Leser vielleicht klarer finden; es enthält ein hilfreiches [Diagramm][type-hierarchy] der Typhierarchie.

## Das Modul `Dates`

Der Großteil der grundlegenden Funktionalität steckt in `Dates`, einem Modul, das in einer Standardinstallation enthalten ist, aber nicht zur Standardbibliothek gehört.

Um das Modul zu verwenden, gibt es zwei Möglichkeiten:

1. Füge `import Dates` hinzu und stelle dann allen Funktionsaufrufen `Dates.` voran.
2. Füge `using Dates` hinzu, wodurch das gesamte Modul in den aktuellen Namensraum gelangt (_mit Ausnahme einiger problematischer Namen_).

```julia-repl
# option 1
julia> import Dates

julia> Dates.now()
2025-06-21T16:02:39.080

julia> now()  # wrong: need to include `Dates.` after an import
ERROR: UndefVarError: `now` not defined in `Main`


# option 2
julia> using Dates

julia> now()  # functions are now in the namespace
2025-06-21T16:03:04.161
```

Das Modul `Dates` ist groß und kompliziert, bietet aber vier Hauptarten von Funktionalität:

- `Dates.Date`, das Tag, Monat und Jahr enthält, aber keine Uhrzeit.
- `Dates.Time`, das die Uhrzeit enthält, aber kein Datum.
- `Dates.DateTime`, das Datum und Uhrzeit kombiniert.
- `Dates.Period`, das Zeit- und Datumsintervalle behandelt.

Beachte, dass ein `DateTime` im Allgemeinen _keine_ Zeitzoneninformationen enthält (Python würde dies als „naive“ Datetime bezeichnen).
Eine Ausnahme ist `now()`, das die lokale Zeit von der Systemuhr abruft und bei Bedarf in UTC umrechnen kann.

Die vielleicht häufigsten Anliegen sind:

- Ein geeignetes Eingabeformat parsen, um einen `Dates`-Typ zu erzeugen.
- Das gewünschte numerische oder String-Format aus einem `Dates`-Typ gewinnen.
- Einen Offset auf einen `Date`-, `Time`- oder `DateTime`-Wert anwenden.
- Das Intervall zwischen zwei solchen Werten berechnen.
- Das aktuelle Datum (mit `today()`) und/oder die aktuelle Uhrzeit (mit `now()`) abrufen.

### Datums- und Zeitformate

Es gibt viele Arten, Datums- und Zeitangaben zu schreiben, die oft kulturspezifisch sind.
Datumsangaben mit nur Zahlen wie „7/6/23“ sind mehrdeutig, verwirrend und haben in multinationalen Organisationen zu vielen teuren Fehlern geführt (_der Autor spricht aus bitterer persönlicher Erfahrung_).

Der internationale Standard ist in `ISO 8601` definiert und hat zwei Hauptvorteile:

- Das Parsen ist schnell und eindeutig.
- Das Sortieren ist einfach, da der Datetime-Wert wie normaler Text behandelt und alphabetisch sortiert werden kann.

Wir haben in einem vorherigen Beispiel gesehen, dass `Date.now()` `2025-06-21T16:03:04.161` zurückgegeben hat.

Dies setzt sich aus verschiedenen Teilen zusammen:

- `YYYY-MM-DD` für den Datumsteil.
- `hh:mm:ss` für den Zeitteil.
- Optional Millisekunden (oder eine noch kleinere Einheit) nach dem Dezimalpunkt.

Andere String-Formate werden in einem späteren Abschnitt besprochen.

## Datumsangaben

`Dates.Date` ist ein relativ einfacher reiner Datumstyp, der weder Zeiten noch Zeitzonen kennt.

```julia-repl
# constructor with year, month, day arguments
julia> date1 = Date(2025, 06, 23)
2025-06-23

# constructor with ISO 8601 string
julia> date2 = Date("2025-06-23")
2025-06-23

julia> date1 == date2
true

julia> typeof(date1)
Date
```

Es gibt Zugriffsfunktionen für einzelne Teile des Datums, und diese treten in Paaren auf, die sich durch die Groß- und Kleinschreibung unterscheiden.

```julia-repl
# lowercase returns an integer
julia> month(date1)
6

julia> typeof(month(date1))
Int64

# Propercase returns a Period type
julia> Month(date1)
6 months

julia> typeof(Month(date1))
Month
```

### Abfragefunktionen

Es gibt eine Vielzahl von Funktionen mit einem gewissen Verständnis für den Kalender.
Das nächste Beispiel zeigt nur einige davon.

```julia-repl
julia> date1
2025-06-23

julia> dayofweek(date1) # 1 = Monday, 7 = Sunday
1

julia> dayname(date1)
"Monday"

julia> daysinmonth(date1)
30

julia> isleapyear(date1)
false

julia> lastdayofmonth(date1)
2025-06-30
```

## Uhrzeiten

`Dates.Time` ist der grundlegende Nur-Uhrzeit-Typ.
Er kennt keine Datumsangaben: Uhrzeiten laufen um Mitternacht automatisch auf `Time(0, 0, 0)` über.

Das vollständige Konstruktorformat ist `Time(hour, min, sec, millisec, microsec)` oder die entsprechende ISO-8601-Form.

Alle Parameter sind optional und werden standardmäßig auf `0` gesetzt.

```julia-repl
julia> Time(14, 57, 25, 142)
14:57:25.142

julia> Time("14:57:25.142")
14:57:25.142

julia> Time(14, 57, 25, 142, 32)
14:57:25.142032
```

Wie bei `Date` sind einzelne Teile über Zugriffsfunktionen verfügbar:

```julia-repl
julia> minute(t) # => integer
57

julia> Minute(t) # => Period
57 minutes
```

## DateTime-Werte

`Dates.DateTime` kombiniert die meisten Merkmale der Typen `Date` und `Time`.

```julia-repl
julia> dt1 = DateTime(2025, 6, 23, 14, 57, 25, 142)
2025-06-23T14:57:25.142

# date1 and t were defined in previous examples
julia> dt2 = DateTime(date1, t)
2025-06-23T14:57:25.142
```

Die Parameter für Jahr, Monat und Tag haben den Standardwert `1`, alle Zeitparameter den Standardwert `0`.

Es kann schwierig sein, all diese Parameter auseinanderzuhalten, daher ist das ISO-Format für die Eingabe möglicherweise vorzuziehen.

Alternativ kann ein `DateTime` aus einem `Date` und einem `Time` konstruiert werden, wie im obigen Beispiel.

## Perioden

Jede der Datums-/Zeitkomponenten hat ihren eigenen `Period`-Typ, von `Year` bis hinunter zu `Nanosecond`, der ein Zeitintervall darstellt.
Diese sind besonders nützlich für Arithmetik.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Year(21)
21 years

julia> Second(61)
61 seconds

julia> dt1 + Year(21) - Second(61)
2046-06-23T14:56:24.142

julia> Date(2025, 07, 03) - Date(2025, 04, 25)
69 days
```

Bei der Arbeit mit `Period`-Typen versucht Julia, clever mit Kalenderunregelmäßigkeiten wie der Monatslänge umzugehen, und rundet bei Bedarf.

```julia-repl
# February has fewer days than January
julia> Date(2025, 1, 31) + Month(1) 
2025-02-28
```

## String-Darstellungen

Wir haben bereits den ISO-8601-Standard erwähnt, der in Julia die Standarddarstellung für Datums-/Zeitangaben beim Formatieren oder Parsen von Strings ist.

Natürlich sind viele andere Formate häufig im Einsatz, oft auf kulturspezifische Weise.
Um damit umzugehen, gibt es in Julia den Typ `DateFormat`, der aus einem Format-String beliebiger Komplexität konstruiert werden kann.

```julia-repl
# dateformat"" string syntax
julia> dtfmt = dateformat"d/m/y"
dateformat"d/m/y"

julia> typeof(dtfmt)
DateFormat{Symbol("d/m/y"), Tuple{Dates.DatePart{'d'}, Dates.Delim{Char, 1}, Dates.DatePart{'m'}, Dates.Delim{Char, 1}, Dates.DatePart{'y'}}}

# DateFormat constructor
julia> DateFormat("d/m/y")
dateformat"d/m/y"
```

Das obige Beispiel ist sehr einfach, nur ein Datum im in Europa üblichen Format Tag/Monat/Jahr.
Es werden zwei Varianten der Syntax gezeigt, aber das Ergebnis ist identisch.

Ein `DateFormat` kann dann zum Parsen eines beliebigen geeigneten Strings verwendet werden:

```julia-repl
julia> DateTime("14/7/2023", dtfmt)
2023-07-14T00:00:00
```

Das Erstellen eines `DateFormat` verursacht erheblichen Overhead. Daher ist es hilfreich, diesen Schritt nur einmal auszuführen (wie hier mit `dtfmt`), wenn du viele Datums-/Zeit-Strings in einer Schleife verarbeitest.

Formate können viel komplexer sein, weitere Details findest du im [Handbuch][dateformat].

Dasselbe `DateFormat` kann auch verwendet werden, um ein Datum/eine Uhrzeit in einem beliebigen gewünschten String-Format auszugeben, mit der Funktion [`Dates.format()`][format].

Leider scheint es einen Namensraumkonflikt mit `format` zu geben (zumindest in Julia 1.11.5), daher ist es am besten, auch nach `using Dates` das Präfix `Dates.` anzugeben.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Dates.format(dt1, dateformat"e, u d")
"Mon, Jun 23"
```

Wie [dokumentiert][wiki-format], liefert `"e, u d"` die abgekürzte Textdarstellung für Wochentag und Monat.

Die Textdarstellung ist standardmäßig Englisch.
Andere Sprachen können hinzugefügt werden, allerdings ist die Unterstützung dafür derzeit nicht optimal.
