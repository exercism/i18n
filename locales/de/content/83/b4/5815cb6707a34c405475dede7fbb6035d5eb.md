# Über

Skalarer Code verlässt sich auf Flags, die verschiedene Instruktionen setzen, um abhängig von einer bestimmten Bedingung zu verzweigen.
Gepackte Werte hingegen repräsentieren nicht einen, sondern viele Werte parallel.
Eine einzelne Bedingung kann für eine Lane fehlschlagen und für eine andere zutreffen.

Deshalb ist SIMD-Code standardmäßig [branchless][branchless-code].

Statt sich auf Flags zu verlassen, erzeugen gepackte Vergleiche normalerweise eine **Maske** im Zieloperanden.
Für jede Lane füllt der Vergleich die ganze Lane mit Einsen, wenn die Bedingung zutrifft, und mit Nullen, wenn sie nicht zutrifft.
Als vorzeichenbehaftete Ganzzahl gelesen ist eine zutreffende Lane `-1` und eine nicht zutreffende Lane `0`.

Diese Maske lässt sich dann mit [bitweisen Operationen][simd-bitwise] kombinieren, um bestimmte Lanes herauszufiltern.

## Gepackte Vergleiche

Ein skalares `cmp` ist insofern generisch, als es verwendet wird, um verschiedene Flags gleichzeitig zu setzen.
Eine andere Instruktion kann diese Flags dann konsumieren, um entweder zu verzweigen oder Berechnungen durchzuführen.

Da ein gepackter Vergleich jedoch sowohl eine Bedingung prüft als auch eine Maske berechnet, ist er nicht generisch.
Dem Vergleich muss die genaue Bedingung mitgegeben werden, die getestet wird.

Dafür gibt es zwei Möglichkeiten:

- Ganzzahlvergleichen wird die Bedingung als Suffix mitgegeben: `eq` für Gleichheit und `gt` für Größer-als.
  Andere Varianten entstehen, indem man das Ergebnis eines dieser Vergleiche kombiniert.
- Gleitkommavergleichen wird die Bedingung in einem Immediate kodiert mitgegeben.
  Verschiedene Werte dieses Immediates entsprechen unterschiedlichen Bedingungen, die getestet werden.

Abgesehen von der Verwendung eines bestimmten bedingten Suffixes bei Ganzzahlvergleichen folgt die Syntax derselben Struktur, die wir bereits gesehen haben:

- Für Ganzzahlen: `p` + `cmp` + Bedingung + Größe (`b`, `w`, `d` oder `q`).
- Für Gleitkommazahlen: `cmp` + `p` + Größe (`s` oder `d`).
  Die Bedingung wird in einem Immediate als zusätzlicher Operand übergeben.

### Ganzzahlvergleiche

Wie erwähnt gibt es Ganzzahlvergleiche nur für Gleichheit und Größer-als:

| Instruktion                                | Beschreibung                      |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | Gleichheit pro Lane                |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | **vorzeichenbehaftetes** Größer-als pro Lane |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

Um einen Kleiner-als-Vergleich zu erzeugen, verwendet man `gt` mit vertauschten Operanden: `a < b` == `b > a`.

Beachte, dass der Vergleich **vorzeichenbehaftet** ist.
Um einen vorzeichenlosen Vergleich durchzuführen, invertiert man das oberste Bit beider Operanden.
Das geht mit einem XOR mit einer Maske, bei der nur das oberste Bit gesetzt ist.

~~~~exercism/note
Zwei praktische Idiome sind:

1. Ein Register mit sich selbst XOR-verknüpfen, um lauter Nullen zu erzeugen.
2. Ein Register mit sich selbst vergleichen, um lauter Einsen zu erzeugen.

Zum Beispiel:

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

Lauter Nullen und lauter Einsen sind gängige Masken, um „überall falsch“ bzw. „überall wahr“ zu kodieren.
Sie können auch verwendet werden, um gepackte `0` oder gepackte `-1` darzustellen, was gängige Sentinel-Werte sind.
Zum Beispiel ist das NUL, das das Ende eines Strings markiert, eine `0`.
~~~~

### Gleitkommavergleiche

Gleitkomma-Lanes haben eine andere Form: eine einzelne Instruktion, `cmpps` (und `cmppd` für 64-Bit-Lanes), mit der Bedingung als Immediate:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM hat außerdem Pseudo-Ops, die auf das richtige Immediate abbilden und leichter zu merken sind.
In allem Folgenden kann `x` in `px` `s` (32-Bit-Gleitkommazahlen) oder `d` (64-Bit-Gleitkommazahlen) sein:

| Pseudo-Op    | Immediate | Vergleich             |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a ist NaN oder b ist NaN   |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | weder a noch b ist NaN |

~~~~exercism/caution
NaN vergleicht sich als ungeordnet: es ist weder kleiner als noch gleich noch größer als irgendetwas, auch nicht als es selbst.
Die geordneten Prädikate wie `cmpltps` ergeben falsch, wenn einer der Operanden NaN ist, während die ungeordneten Prädikate wahr ergeben.
Deshalb gibt es `cmpordps` und `cmpunordps`, um explizit auf NaN zu testen.
~~~~

## Auswählen mit einer Maske

Eine Maske kodiert das Ergebnis einer Bedingung.
Sie kann dann verwendet werden, um gemäß dieser Bedingung Lane für Lane zwischen zwei Wertemengen zu wählen.
Wir nehmen die Lane von einem Wert, wo die Maske wahr ist, und von einem anderen, wo sie falsch ist:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

Dieses Muster ist die gepackte Form der branchless Auswahl.
Jede Lane wird berechnet, und allein die Maske entscheidet, welcher Wert überlebt, ganz ohne `jcc`.

## Dedizierte Blends

Es gibt Instruktionen, die genau diese Auswahl direkt durchführen und dabei ein Bit pro Element aus einem Maskenregister lesen.
Sie heißen **Blend**-Instruktionen:

| Instruktion | Element     | Maskenquelle   |
|-------------|-------------|-----------------|
| `pblendvb`  | Byte        | implizit `xmm0` |
| `blendvps`  | 32-Bit-Lane | implizit `xmm0` |
| `blendvpd`  | 64-Bit-Lane | implizit `xmm0` |

Beachte, dass die erste Instruktion der Ganzzahlsyntax folgt, während die anderen beiden der Gleitkommasyntax folgen.
Da diese Instruktionen jedoch einfach rohe Bytes auswählen, kann jede von ihnen sowohl mit Ganzzahlen als auch mit Gleitkommazahlen verwendet werden.

Für jedes Element behält der Blend das Ziel, wenn das oberste Bit des zugehörigen Maskenelements nicht gesetzt ist, und übernimmt die Quelle, wenn es gesetzt ist.
Nur dieses **oberste Bit** wird herangezogen, was eine Vergleichsmaske erfüllt, da ihre Lanes alle Einsen oder alle Nullen sind.
Das Maskenregister ist immer `xmm0`, was implizit ist:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

Es ist auch möglich, `pblendvb` zu verwenden, um Lanes aus einer Vergleichsmaske für jede andere Größe auszuwählen.
Da alle Bytes in einer zutreffenden Lane alle Einsen sind, wählt `pblendvb` sie alle aus.

~~~~exercism/note
Diese Instruktionen hängen alle ein `v` an die ausgeführte Operation (`blend`) an.
Dieses `v` steht für _variable_, denn die Auswahl ist nicht statisch: sie hängt von einem Register ab.

Es gibt auch Varianten ohne `v`, die gemäß einem Immediate auswählen.
Sie folgen demselben Muster und wählen eine Lane `i` aus, wenn Bit `i` des Immediates gesetzt ist.
~~~~

## Von einer Maske zurück zum Skalar

So leistungsfähig SIMD-Code auch ist, ihm fehlt ein Großteil der Flexibilität von skalarem Code.
In vielen Situationen ist es notwendig, von einem gepackten Register zurück in die Welt der skalaren Instruktionen zu wechseln.

Die Instruktionsfamilie `movmsk` dient als Brücke zwischen den beiden Welten.
Diese Instruktionen extrahieren das **oberste Bit** jeder Lane in ein Allzweckregister:

| Instruktion | sammelt                     | Ergebnisbreite |
|-------------|-----------------------------|--------------|
| `pmovmskb`  | oberstes Bit jedes der 16 Bytes | 16 Bit      |
| `movmskps`  | oberstes Bit jedes der 4 Dwords | 4 Bit      |
| `movmskpd`  | oberstes Bit jedes der 2 Qwords | 2 Bit      |

Nach einem Vergleich repräsentiert jedes gesetzte Bit eine „wahre“ Lane und jedes gelöschte Bit eine „falsche“ Lane.
Dieses Ergebnis kann dann wie gewohnt mit skalaren Instruktionen weiterverarbeitet werden.
Zum Beispiel zählt ein `popcnt` die Anzahl der Übereinstimmungen, und `tzcnt` findet die erste.

Das Allzweckregister kann 32 oder 64 Bit breit sein.

## Einen ganzen Vektor testen

Es gibt auch eine gepackte Variante der skalaren `test`-Instruktion: `ptest`.

Sie ähnelt ihrem skalaren Gegenstück darin, dass sie eine AND-Operation zwischen zwei Operanden ausführt, ohne diese zu verändern.
Anders als `test` führt `ptest` auch eine ANDN-Operation aus, die den ersten Operanden negiert.

Somit kann man `ptest` als nicht-destruktive Version von `pand` und `pandn` betrachten, die Flags entsprechend dem Ergebnis setzt.
Ganz ähnlich wie diese beiden Instruktionen behandelt `ptest` das gesamte SIMD-Register als eine einzige Lane und nimmt daher kein Größenpräfix.

Wenn das Ergebnis einer AND-Operation `0` ist, wird das `ZF` gesetzt, und wenn die ANDN-Operation `0` ergibt, wird das `CF` gesetzt.
Damit lässt sich mit `ptest` sowohl auf eine Maske aus lauter Einsen als auch auf eine aus lauter Nullen prüfen:

1. Verwendet man `ptest` auf einem Register mit sich selbst, wird `ZF` nur gesetzt, wenn das Register lauter Nullen enthält.
   Das ahmt das gängige skalare Idiom nach, `test` auf einem Register mit sich selbst zu verwenden, um auf `0` zu prüfen.
2. Verwendet man `ptest` auf einem Register mit einer Maske aus lauter Einsen, wird `CF` nur gesetzt, wenn das Register lauter Einsen enthält.
   Außerdem wird `ZF` nur gesetzt, wenn das Register lauter Nullen enthält, sodass sich beide Masken auf einmal prüfen lassen.

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

Das Ergebnis eines `ptest` kann wie gewohnt zum Verzweigen oder in branchless Instruktionen wie `setcc` oder `cmovcc` verwendet werden.

## AVX und darüber hinaus

AVX gibt den Vergleichen, Blends und `ptest` eine `v`-präfigierte Form auf breiteren Registern.

Der variable Blend ändert seine Form.
Die Maske ist nicht mehr das implizite `xmm0`, sondern ein expliziter vierter Operand:

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

Die AVX-512-Erweiterungen verändern das Modell grundlegender.

Erstens fügen sie eine neue Klasse von 64-Byte-SIMD-Registern hinzu, die `zmm` heißen.
Sie erweitern die entsprechenden `ymm`-Register, genauso wie `ymm`-Register die `xmm`-Register erweitern.

Zweitens schaffen diese Erweiterungen auch eine ganz neue Klasse von **Opmask-Registern**, `k0` bis `k7`, deren Hauptzweck es ist, als Masken für SIMD-Instruktionen zu dienen.
Vergleiche schreiben nicht mehr in Vektoren, sondern in eines dieser neuen Register.
Sie können auch direkt bei vielen Instruktionen als Prädikate mit einer `{k}`-Schreibmaske verwendet werden, die Lanes _direkt_ auswählen:

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

Schließlich gibt es neue Instruktionen, die auf diesen neuen Registern arbeiten, darunter das Kopieren in Allzweckregister.
Dadurch werden `movmsk`-Instruktionen überflüssig, und es gibt keine Unterstützung für `movmsk`-Instruktionen auf `zmm`-Registern.

Diese Erweiterungen werden nur der Vollständigkeit halber erwähnt.
Die Übungen in diesem Track verwenden die SSE-Formen.
