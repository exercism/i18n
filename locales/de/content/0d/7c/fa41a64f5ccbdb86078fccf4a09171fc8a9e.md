# Über

Jeder Wert kann ein Fehler sein. `throw` (in `kernel`) signalisiert; der Stackeffekt des aktuellen Worts wird verworfen, und die Kontrolle wird bis zum nächstgelegenen umschließenden `recover` abgewickelt.

```factor
[ 0 1 / ] [ "div by zero" prepend ] recover
```

`ERROR:` ist ein Parsing-Wort, das in einem Zug eine Fehler-Tupelklasse *und* ein Konstruktor-Wort definiert:

```factor
ERROR: not-found path ;
! defines:
!   TUPLE: not-found path ;
!   : not-found ( path -- * ) \ not-found boa throw ;
!   : not-found? ( object -- ? ) … class predicate
```

Damit bekommt jeder eigene Fehler eine eindeutige Klasse, ein freundliches Konstruktor-Wort, das wirft, und ein Klassenprädikat (`name?`), mit dem du abgefangene Fehler prüfen kannst:

```factor
[ "/missing" not-found ]
[ dup not-found? [ path>> "missing: " prepend ] [ drop "other" ] if ]
recover
```

Für Aufräumarbeiten im finally-Stil siehe `cleanup` in `continuations`. Für wiederaufsetzbare Bedingungen siehe `condition`.
