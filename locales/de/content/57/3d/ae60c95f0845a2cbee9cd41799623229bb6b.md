# Einführung

Eine `GENERIC:`-Deklaration erzeugt ein Wort, dessen Verhalten von der *Klasse* eines seiner Argumente abhängt. Konkretes Verhalten kommt von *Methoden*, die mit `M:` definiert werden.

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

Wenn `area` aufgerufen wird, untersucht Factor die Spitze des Stacks, sucht die spezifischste Methode heraus, deren Klasse passt, und führt sie aus. Mit Locals kannst du `M::` verwenden:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

Generics erlauben dir, später neue Repräsentationen hinzuzufügen, ohne den aufrufenden Code zu ändern: `area` funktionierte bereits für `square` und `circle`, und die `rectangle`-Methode wird überall dort automatisch aufgegriffen, wo `area` aufgerufen wird.

## Wann ein Generic die richtige Wahl ist

Greif zu `GENERIC:`, wenn:

- Eine einzelne Operation *wirklich unterschiedliche* Implementierungen für verschiedene Eingaben hat.
- Du erwartest, dass zukünftiger Code neue Typen hinzufügt.
- Du möchtest, dass das Typsystem Definitionen pro Klasse erzwingt.

Wenn die Variation nur eine kleine Aufzählung von Bezeichnern ist, ist ein `case` einfacher.

## Einem Mixin mit `INSTANCE:` beitreten

Ein *Mixin* ist eine generische Klasse, die *offen* ist: Jeder kann eine neue Klasse als Mitglied registrieren. Viele der eingebauten Protokolle von Factor (Sequenzen, Mengen, Streams, …) sind als Mixins verfügbar, sodass ein eigenes Tuple sich für die Standardmethoden des Protokolls entscheiden kann, indem es sich selbst als Instanz deklariert:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

Nach `INSTANCE:` wird jede Standardmethode `M: shape …` automatisch auf `my-shape` angewendet, und jeder Code, der ein `shape` verlangt, akzeptiert auch ein `my-shape`. `M:` dient dazu, einem Generic Methoden hinzuzufügen; `INSTANCE:` dient dazu, eine Klasse einem Mixin hinzuzufügen.

## `TYPED::` – geprüfte Eingaben für ein einfaches Wort

`GENERIC:`/`M:` wählen eine Methode anhand der Klasse eines Arguments aus. Manchmal möchtest du keinen Dispatch, sondern nur *ein* Wort, das darauf besteht, dass seine Eingaben von einer bestimmten Klasse sind. `TYPED::` (im `typed`-Vokabular) ist `::` mit einer Klasse, die hinter jeden Eingabenamen geschrieben wird:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

`n: integer` liest sich wie die Locals, die du bereits verwendest, nur mit der Klasse nach dem Doppelpunkt. Es gibt keinen Dispatch (eine Definition, ein Verhalten), aber jedes Argument wird jetzt gegen seine Klasse geprüft: Eine Nichtübereinstimmung wie `"x" triple` wird abgelehnt (*expected input value of type integer but got string*), statt still durchgereicht zu werden.

Die Ausgabe kann auf die gleiche Weise annotiert werden. `yes?` typisiert sowohl seine Eingabe als auch sein Ergebnis:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## Mathematische Funktionen und Konstanten

Diese Übung stützt sich außerdem auf ein paar Wörter aus `math.constants` und `math.functions`, denen du hier zum ersten Mal begegnest:

- `pi` – die Konstante π aus `math.constants`.
- `sin ( x -- y )`, `cos ( x -- y )` – Sinus und Kosinus eines Winkels im Bogenmaß.
- `e^ ( x -- y )` – `e` hoch `x`. (Für eine beliebige Basis verwende `^`.)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
