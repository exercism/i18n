# String-Typen

Cairo hat keinen nativen Datentyp für Strings.
Es gibt aber zwei Möglichkeiten, einen String-Typ darzustellen: kurze Strings mit einem einzelnen `felt252` und Strings beliebiger Länge mit `ByteArray`.

## Kurze Strings

Ein kurzer String wird mit einfachen Anführungszeichen gebildet, wobei jedes Zeichen, aus dem der String besteht, nach dem [ASCII-Standard][ascii-table] in einem Byte kodiert wird.

Als ASCII-String ist `'abc'` zum Beispiel:

- `'a'` entspricht `0x61`
- `'b'` entspricht `0x62`
- `'c'` entspricht `0x63`
- `'abc'` entspricht `0x616263`

In Cairo ist `felt252` der Datentyp, der kurze Strings aufnimmt.
Da `felt252` 251 Bits enthält, ist ein kurzer String auf 31 Zeichen begrenzt (31 \* 8 = 248 Bits, also das größte Vielfache von 8, das in 251 Bits passt).

Beispiele für Deklarationen kurzer Strings:

```rust
    let my_first_char = 'D';
    let my_first_char_in_hex = 0x44;

    let my_first_string = 'Hello world';
    let my_first_string_in_hex = 0x48656C6C6F20776F726C64;
```

### ByteArray

Das `ByteArray`-Struct wurde in Cairo 2.4.0 eingeführt.
`ByteArray`-Strings stehen in doppelten Anführungszeichen, wie hier:

```rust
    let long_string: ByteArray = "this is a string which has more than 31 characters";
```

Technisch gesehen hat das Update außerdem den Typ `bytes31` eingeführt, der 31 Bytes aufnimmt und in ein felt passt.
Das `ByteArray`-Struct stellt einen langen String im Wesentlichen mit einem Array von `bytes31` dar, die die „ganzen Wörter“ enthalten (also Wörter, die das ganze felt ausfüllen), und mit einem einzelnen felt-Feld, das ein „unvollständiges Wort“ enthält (die Anzahl der darin enthaltenen Bytes steht in einem separaten Längenfeld).

```rust
#[derive(Drop, Clone, PartialEq, Serde, Default)]
struct ByteArray {
    data: Array<bytes31>,
    pending_word: felt252,
    pending_word_len: usize,
}
```

[ascii-table]: https://www.asciitable.com/
