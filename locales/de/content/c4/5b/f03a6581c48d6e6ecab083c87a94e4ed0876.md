# Tests

Führe die Tests aus mit:

```shell
corepack pnpm test
```

Achte darauf, dass dein Code bewährten Verfahren und Coding-Stilen folgt, so wie es andere Nutzer tun, mit ESLint, einem Tool zur statischen Analyse deines Codes.
Manchmal sparen dir solche Tools etwas Zeit beim Aufspüren von Tippfehlern oder dummen Fehlern in deinem JavaScript-Code:

```shell
corepack pnpm lint
```

Du kannst Jest auch im „Watch“-Modus ausführen. Dann werden deine Tests automatisch erneut ausgeführt, wenn du Änderungen am Code oder am Testmodul speicherst:

```shell
corepack pnpm watch
```

## Skip-Tests verstehen

Die skip-Methode weist die Testsuite an, einen Test nicht auszuführen. Diese Funktion kann auch unter folgenden Aliasnamen verwendet werden: `it.skip(name, fn)` oder `xit(name, fn)` oder `xtest(name, fn)`

- Warum werden sie übersprungen?

Damit sich Nutzer jeweils auf einen Test konzentrieren können und sie nach und nach aktivieren, während sie die Lösung weiterentwickeln.

- Wie aktiviert man sie?

Ändere `xtest` zu `test`.

```javascript
test('title cased phrases', () => {
  expect(Acronyms.parse('Portable Network Graphics')).toEqual('PNG');
});
```

## Dein erstes JavaScript-2015-Modul

Üblicherweise laden die Tests in diesem Track deine Implementierung, indem sie sie als JavaScript-Modul importieren: `import { Bob } from './bob.js';`.
Du musst deine Implementierung nur aus der referenzierten Datei `bob.js` exportieren:

```javascript
export function hey(message) {}
```

Weitere Informationen über Module findest du in der [Babel-Dokumentation](https://babeljs.io/docs/learn-es2015/#modules).
Um dir den Einstieg zu erleichtern, gibt es eine _Skelett_-JavaScript-Datei im Verzeichnis.
