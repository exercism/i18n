# Einführung

## Stack

Der **Aufrufstack**, oder einfach der **Stack**, ist eine besondere Datenstruktur, die am höchsten Punkt im Speicher beginnt und nach unten wächst.

### Push und Pop

Der Stack unterstützt mindestens zwei Operationen, für die es Instruktionen mit demselben Namen gibt:

| Instruktion | Ausgeführte Operation                               |
| ----------- | --------------------------------------------------- |
| `push`      | fügt ein Element zum Stack hinzu                    |
| `pop`       | entfernt das zuletzt hinzugefügte Element und gibt es zurück |

Das bedeutet, dass der Stack nach dem **Last In, First Out (LIFO)**-Prinzip arbeitet.

Um den aktuellen Punkt des Stacks zu verfolgen, also die Stelle, an der sich das zuletzt hinzugefügte Element befindet, wird das Register `rsp` verwendet.

Eine `push`-Instruktion nimmt also einen Operanden und speichert dessen Inhalt im Stack.
Da der Stack nach unten wächst, wird der Wert in `rsp` um die Größe des gespeicherten Werts verringert.

Ebenso nimmt eine `pop`-Instruktion einen Operanden und schreibt den zuletzt abgelegten Wert des Stacks (den, auf den `rsp` zeigt) hinein.
Der Wert in `rsp` wird dann um die Größe des entnommenen Werts erhöht.

### Lokale Variablen

Es ist auch möglich, den Wert von `rsp` direkt zu verändern.
Das wird oft genutzt, um lokale Variablen für eine Funktion anzulegen.

```x86asm
sub rsp, 24 ; this reserves 24 bytes of space in the stack
add rsp, 24 ; this restores the previous value of rsp, "reducing" the stack by 24 bytes
```

Beachte, dass der Wert, der an dieser Stelle gespeichert wird, _undefiniert_ ist, sobald Speicherplatz im Stack reserviert wird.

~~~~exercism/note
Weder `pop` noch das direkte Verändern von `rsp` entfernt tatsächlich die im Speicher abgelegten Inhalte.
Das „Entfernen“ vom Stack ist eine Abstraktion, die sich aus der neuen Adresse in `rsp` ergibt.

In manchen Kontexten kann das Sicherheitsbedenken auslösen, weil dadurch interne Werte für externe Quellen offengelegt werden.
Eine Möglichkeit, damit umzugehen, ist, den Inhalt jedes von der Funktion genutzten Stack-Bereichs mit Nullen zu überschreiben.
~~~~

### Call und Ret

Der Hauptzweck des Stacks ist es, die Rücksprungadresse für aufgerufene Funktionen zu speichern.

Wie in einem früheren Konzept erwähnt, gibt es ein spezielles Register namens `rip`, das auf die nächste auszuführende Instruktion zeigt.
Dieses Register steuert den Ablauf eines Programms und wird von Instruktionen wie `jmp` und `call` verändert.

Immer wenn eine `call`-Instruktion ausgeführt wird, wird der aktuelle Wert in `rip` implizit auf den Stack gelegt.
Anschließend wird der Operand der Instruktion nach `rip` geschrieben, sodass die Ausführung in der aufgerufenen Funktion fortgesetzt wird.

Eine `ret`-Instruktion macht das Gegenteil.
Sie holt einen Wert vom Stack nach `rip`, sodass die Ausführung zur aufrufenden Funktion zurückkehrt.

Beim Eintritt in die Funktion zeigt `rsp` auf die Adresse, zu der zurückgesprungen werden soll.
Das ist die Adresse, die `ret` vom Stack holen muss.

Jede Änderung des Werts von `rsp` innerhalb einer Funktion, ob direkt oder durch `push`, muss also vor der Rückkehr aus der Funktion rückgängig gemacht werden.

### Callee-Saved- und Caller-Saved-Register

Neben `rsp` gibt es weitere Register, die über Funktionsaufrufe hinweg erhalten bleiben müssen: `rbp`, `rbx`, `r12`, `r13`, `r14` und `r15`.
Im Allgemeinen erwartet die aufrufende Funktion, diese Register weiterhin nutzen zu können, ohne dass eine aufgerufene Funktion sie verändert.

Das bedeutet, dass die _aufgerufene_ Funktion die Werte dieser Register sichern muss, bevor sie sie verwendet, und sie vor der Rückkehr auf ihre ursprünglichen Werte zurücksetzen muss.
Deshalb heißen sie **Callee-Saved-Register**.

Andere Allzweckregister stehen der aufgerufenen Funktion direkt zur Verfügung.

Das bedeutet, dass die _aufrufende_ Funktion die Werte dieser Register sichern muss, bevor sie eine Funktion aufruft, falls die aufgerufene Funktion sie verändert.
Deshalb heißen sie **Caller-Saved-Register**.

_Am häufigsten sichert man den Inhalt eines Registers, indem man ihn auf den Stack legt._

### Prolog und Epilog

In manchen Fällen wird der Stack stark genutzt und bis zur Rückkehr der Funktion vielfach verändert.
Dann kann es aufwendig sein, all diese Änderungen zu verfolgen und wieder rückgängig zu machen.

In solchen Fällen ist es üblich, die Adresse von `rsp` in einem anderen Register zu sichern, das innerhalb der Funktion ansonsten unverändert bleibt.
Zum Schluss, vor der Rückkehr aus der Funktion, lässt sich der Wert von `rsp` dann mit einer einfachen `mov`-Instruktion wiederherstellen.

Obwohl jedes Register dafür verwendet werden kann, ist es üblich, `rbp` als Basiszeiger zu nutzen.
Da `rbp` selbst ein Callee-Saved-Register ist, steht davor oft ein `push rbp`.
Diese Sequenz nennt man üblicherweise **Prolog**.

Am Ende wird `rsp` mit `mov rsp, rbp` wiederhergestellt, und dann wird auch `rbp` mit einem `pop` vom Stack zurückgeholt.
Diese Sequenz nennt man üblicherweise **Epilog**.

```x86asm
section .text
fn:
    ; prologue
    push rbp
    mov rbp, rsp
    ...
    ; epilogue
    mov rsp, rbp
    pop rbp
    ret
```

### Argumente über den Stack übergeben

In der Aufrufkonvention der System V ABI werden Argumente normalerweise in Registern an Funktionen übergeben.
Wenn es jedoch zu viele Argumente gibt oder sie mehr Platz brauchen, als ein Register bietet, kann der Stack genutzt werden.

In diesen Fällen werden die Werte in umgekehrter Reihenfolge auf den Stack gelegt, damit das erste Argument näher an `rsp` liegt.
Da `rsp` beim Eintritt auf die Rücksprungadresse zeigt, die in x86-64 8 Byte groß ist, lässt sich das erste Argument auf dem Stack, falls vorhanden, über `rsp + 8` erreichen.

### Stack-Ausrichtung

Die System V ABI legt fest, dass der Stack unmittelbar _vor_ der Ausführung der call-Instruktion an einer 16-Byte-Grenze ausgerichtet sein muss.
Da `call` `rip` auf den Stack legt, ist der Stack der aufgerufenen Funktion beim Eintritt **nicht** 16-Byte-ausgerichtet.

Das bedeutet, dass eine Funktion, die eine andere aufruft (insbesondere externe Funktionen), den Stack vor der Verwendung von `call` ausrichten muss.

Das lässt sich erreichen, indem man einen passenden Wert von `rsp` subtrahiert.
Beim Eintritt muss dieser Wert um 8 größer sein als ein Vielfaches von 16: 8, 24, 40 usw.
Da eine `push`-Instruktion von `rsp` subtrahiert, kann eine ungerade Anzahl an `push`-Instruktionen denselben Effekt erzielen:

```x86asm
fn_a:
    sub rsp, 24 ; subtracting 8 more than a multiple of 16: this aligns the stack
    call fn_b
    add rsp, 24
    ret

fn_b:
    push rbx    ; odd number of pushes: this aligns the stack
    call fn_c
    pop rbx
    ret
```
