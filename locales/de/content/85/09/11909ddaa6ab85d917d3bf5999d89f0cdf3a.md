# Über

Charlists werden mit dem `~c`-Sigil erstellt.

```elixir
~c"hello"
```

~~~~exercism/note
Beachte, dass in älteren Versionen von Elixir Charlists als `'hello'` mit einfachen Anführungszeichen dargestellt werden.
~~~~

Ein Charlist ist eine Liste von Ganzzahlen. Die Ganzzahlen repräsentieren die Unicode-Werte eines Zeichens, auch bekannt als Codepunkte.

```elixir
[65, 66, 67]
# => ~c"ABC"
```

## Charlists _sind_ Listen

```elixir
~c"" === []
# => true

is_list(~c"hello")
# => true
```

Weil Charlists Listen sind, kannst du mit ihnen genauso arbeiten wie mit jeder anderen Liste: mit Rekursion und Musterabgleich oder mit dem [`List`][list]-Modul.

```elixir
[first_letter | _] = ~c"cat"
first_letter
# => 99

List.first(~c"hello")
# => 104
List.pop_at(~c"hello", 0)
# => {104, ~c"ello"}

```

Du kannst zwei Listen mit [`++`][kernel-concat-list] verketten.

```elixir
~c"hi" ++ ~c"!"
# => ~c"hi!"
```

Je länger die erste Liste ist, desto langsamer ist das Verketten. Vermeide es daher, wiederholt an Listen beliebiger Länge anzuhängen.

## Druckbarkeit

Wenn eine Liste von Ganzzahlen nur Ganzzahlen enthält, die Codepunkte druckbarer Zeichen sind, wird sie als Charlist angezeigt. Selbst wenn sie mit der `[]`-Syntax definiert wurde.

```elixir
~c"ABC"
# => ~c"ABC"

[65, 66, 67]
# => ~c"ABC"
```

Wenn eine Liste von Ganzzahlen auch nur einen Codepunkt eines nicht druckbaren Zeichens enthält (z. B. `0-6`, `14-26`, `28-31`), wird sie als Liste angezeigt. Selbst wenn sie mit der `~c""`-Syntax definiert wurde.

```elixir
~c"ABC\0"
# => [65, 66, 67, 0]

[65, 66, 67, 0]
# => [65, 66, 67, 0]
```

Die Druckbarkeit kann mit [`List.ascii_printable?`][list-ascii-printable] überprüft werden.

```elixir
List.ascii_printable?([65, 66, 67])
# => true
List.ascii_printable?([65, 66, 67, 0])
# => false
```

Beachte, dass dies zwei verschiedene Arten sind, dieselben Daten _anzuzeigen_. Die Werte sind strikt gleich.

```elixir
~c"ABC" === [65, 66, 67]
# => true
```

Wenn du eine Liste mit [`IO.inspect`][io-inspect] ausgibst, kannst du die Option [`:charlists`][inspect-opts] verwenden, um zu steuern, wie Listen ausgegeben werden.

```elixir
IO.inspect(~c"ABC", charlists: :as_charlists)
# => prints ~c"ABC"

IO.inspect(~c"ABC", charlists: :as_lists)
# => prints [65, 66, 67]
```

## Codepunkte

Du kannst einem Zeichen ein `?` voranstellen, um seinen Codepunkt zu erhalten.

```elixir
?A
# => 65

[?:, ?)]
# => ~c":)"
```

## Charlists vs. Strings

Charlists und Strings, die aus denselben Zeichen bestehen, gelten nicht als gleich.

```elixir
~c"hello" == "hello"
false
```

Jeder Wert in einem Charlist ist der [Unicode-Codepunkt eines Zeichens][unicode-table], während in einem String die Codepunkte als [UTF-8][utf8] kodiert sind.

```elixir
IO.inspect(~c"tschüss", charlists: :as_lists)
# => prints [116, 115, 99, 104, 252, 115, 115]

IO.inspect("tschüss", binaries: :as_binaries)
# => prints <<116, 115, 99, 104, 195, 188, 115, 115>>
```

Beachte, wie `ü`, Codepunkt `252`, in UTF-8 als `195` und `188` kodiert wird.

**In der Praxis werden Charlists selten verwendet**. Ihr Hauptanwendungsfall ist die Anbindung an Erlang, insbesondere wenn du ältere Bibliotheken verwendest, die keine Binaries als Argumente akzeptieren.

Wenn du mit Elixir arbeitest, **verwende Strings, um Text zu speichern**. Das `String`-Modul bietet eine große Auswahl an Funktionen zur Textverarbeitung, Funktionen, die für Charlists nicht verfügbar sind.

Charlists können mit [`to_string`][kernel-to-string] in Strings umgewandelt werden.

```elixir
to_string(~c"hello")
# => "hello"
```
