# Einführung

## Verzweigungsfreier Code

Das Konzept der Bedingungen führt `jcc` ein, die Familie der Instruktionen, mit denen man abhängig von einer Bedingung verzweigt.
Ein `jcc` überträgt die Ausführung nur dann an eine andere Stelle im Programm, wenn seine Bedingung erfüllt ist.

Moderne CPUs sind jedoch schnell und können viele Instruktionen parallel ausführen.
Es wäre zu kostspielig, alle Arbeit anzuhalten, während die CPU auf eine Laufzeitprüfung einer Bedingung wartet.

Deshalb wartet die CPU intern nicht.
Sie nutzt eine **Verzweigungsvorhersage**, um das Ergebnis einer Bedingung zu erraten, und beginnt, den vorhergesagten Pfad _spekulativ_ auszuführen.

Ist die Vorhersage richtig, läuft die Ausführung weiter, als gäbe es keine Verzweigung.
Ist die Vorhersage jedoch falsch, muss die CPU die auf dem vorhergesagten Pfad _geleistete Arbeit verwerfen_ und auf dem richtigen Pfad neu starten.

Das nennt man eine **Verzweigungsfehlvorhersage**, und sie ist teuer, denn sie verursacht eine Verzögerung.

Ist eine Verzweigung schwer vorherzusagen, summieren sich diese Fehlvorhersagen.
In solchen Fällen ist es manchmal besser, die Verzweigung ganz zu vermeiden, sodass dieselben Instruktionen unabhängig von der Bedingung ausgeführt werden.
Code, der ohne `jcc` zwischen Werten auswählt, heißt **verzweigungsfrei**.

Es gibt mehrere Möglichkeiten, Code so zu strukturieren, dass er seltener verzweigt oder dass die Verzweigungen, die er hat, besser vorhersagbar sind.
Insbesondere stellt x86-64 zwei Instruktionsfamilien bereit, die häufig für verzweigungsfreien Code verwendet werden.

### Bedingte Moves

Die Familie der Instruktionen `cmovcc` kopiert den Quelloperanden nur dann in das Ziel, wenn eine bestimmte Bedingung erfüllt ist.
Andernfalls bleibt das Ziel unverändert.

Das Suffix `cc` folgt derselben Namensgebung wie bei `jcc` und hat dieselbe Bedeutung:

| Instruktion | Move, falls                          |
|-------------|--------------------------------------|
| `cmove`     | A == B nach `cmp A, B`               |
| `cmovne`    | A != B nach `cmp A, B`               |
| `cmovl`     | A < B (mit Vorzeichen) nach `cmp A, B` |
| `cmovb`     | A < B (ohne Vorzeichen) nach `cmp A, B` |
| `cmovg`     | A > B (mit Vorzeichen) nach `cmp A, B` |
| `cmova`     | A > B (ohne Vorzeichen) nach `cmp A, B` |

Die Regeln ähneln denen von `jcc`:

1. `l` und `g` werden für Vergleiche mit Vorzeichen verwendet, `b` und `a` für Vergleiche ohne Vorzeichen.
2. Ein angehängtes `e` schließt Gleichheit ein.
3. Ein `n` negiert die Bedingung.
4. Es gibt außerdem Varianten, die sich auf ein gesetztes Flag beziehen.
   Zum Beispiel `cmovz` und `cmovc`.

Betrachte den Absolutbetrag einer Ganzzahl mit Vorzeichen in `rdi`, der in `rax` zurückgegeben wird.
Mit `jcc` geschrieben wählt die Funktion einen von zwei Pfaden:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Mit `cmovcc` geschrieben werden beide Kandidatenwerte bedingungslos berechnet, und der bedingte Move wählt einen davon aus:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

Die verzweigungsfreie Version führt immer dieselben Instruktionen aus.
Es gibt kein `jcc`, das die Verzweigungsvorhersage erraten könnte.

Das Ziel eines `cmovcc` muss ein Register sein.
Die Quelle kann ein Register oder eine Speicherstelle sein, aber kein unmittelbarer Operand.

~~~~exercism/note
Im obigen Code setzt die Instruktion `neg` abhängig vom Ergebnis mehrere Flags, darunter das Vorzeichen-Flag (SF).
Das bedeutet, dass `cmp rdi, 0` ganz entfallen kann:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Für positives `rdi` erzeugt `neg` ein negatives Ergebnis und SF == 1, also stellt `cmovs` `rdi` wieder her.
Für null oder negatives `rdi` erzeugt `neg` ein nicht-negatives Ergebnis und SF == 0, also behält `rax` den negierten Wert (der dem korrekten Absolutbetrag entspricht).

Obwohl `cmp` die wichtigste Möglichkeit ist, in Assembler-Code Werte zu vergleichen, setzen viele Instruktionen auch abhängig von ihrem Ergebnis Flags.
Die vollständige Liste der Flags, die eine Instruktion beeinflusst, steht normalerweise in ihrer [Referenz][reference].
Bei `neg` sind das konkret SF, ZF, CF, OF und PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

### Bedingtes Setzen

Die Familie der Instruktionen `setcc` setzt den Zieloperanden auf `1`, wenn eine bestimmte Bedingung erfüllt ist, und andernfalls auf `0`.
Das Ziel ist immer ein _8-Bit-Operand_.

Das Suffix `cc` folgt derselben Namensgebung wie bei `jcc` und `cmovcc`.
Zum Beispiel setzt `setz` das Ziel auf `1`, wenn `ZF == 1`, und andernfalls auf `0`.

Da das Ziel 8 Bit breit ist, folgt auf `setcc` häufig ein `movzx`, wenn ein breiterer Wert benötigt wird:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Das ist ein gängiges Idiom, um ein Vergleichsergebnis in die Ganzzahl `0` oder `1` umzuwandeln.
