# Anweisungen

Nach einer kürzlich durchgeführten Sicherheitsüberprüfung wurdest du gebeten, die archivierten Logdateien der Organisation aufzuräumen.

## 1. Fehlerhafte Logzeilen erkennen

Du brauchst einen ungefähren Überblick darüber, wie viele Logzeilen in deinem Archiv nicht den aktuellen Standards entsprechen.
Du bist der Meinung, dass ein einfacher Test zeigt, ob eine Logzeile gültig ist.
Um als gültig zu gelten, muss eine Zeile mit einem der folgenden Strings beginnen:

- [DEBUG]
- [INFO]
- [WARNING]
- [ERROR]

Implementiere die Funktion `valid_line?/1`, die `true` zurückgibt, wenn die Logzeile gültig ist.

```elixir
LogParser.valid_line?("[ERROR] Network Failure")
# => true

LogParser.valid_line?("Network Failure")
# => false
```

## 2. Die Logzeile aufteilen

Kurz nach dem Start des Projekts zur Log-Analyse stellst du fest, dass die Logs einer Anwendung nicht wie die anderen in Zeilen aufgeteilt werden. In diesem Projekt steht das, was eigentlich einzelne Zeilen sein sollten, stattdessen in einer einzigen Zeile, verbunden durch ausgefallene Pfeile wie `<--->` oder `<*~*~>`.

Tatsächlich kann jeder String, dessen erstes Zeichen `<` und dessen letztes Zeichen `>` ist und der dazwischen eine beliebige Kombination der Zeichen `~`, `*`, `=` und `-` enthält, als Trennzeichen in den Logs dieses Projekts verwendet werden.

Implementiere die Funktion `split_line/1`, die eine Zeile entgegennimmt und eine Liste von Strings zurückgibt.

```elixir
LogParser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
# => ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. Artefakte aus dem Log entfernen

Du hast festgestellt, dass eine vorgelagerte Verarbeitung der Logs den Text „end-of-line“, gefolgt von einer Zeilennummer (ohne Leerzeichen dazwischen), über die gesamten Logs verteilt hat.

Implementiere die Funktion `remove_artifacts/1`, die einen String entgegennimmt, alle Vorkommen des end-of-line-Textes entfernt (ohne Beachtung der Groß-/Kleinschreibung) und eine saubere Logzeile zurückgibt.

Zeilen, die keinen end-of-line-Text enthalten, sollten unverändert zurückgegeben werden.

Entferne einfach den end-of-line-String, du musst die Leerzeichen nicht anpassen.

```elixir
LogParser.remove_artifacts("[WARNING] end-of-line23033 Network Failure end-of-line27")
# => "[WARNING]  Network Failure "
```

## 4. Zeilen mit Benutzernamen markieren

Dir ist aufgefallen, dass einige Logzeilen Sätze enthalten, die sich auf Benutzer beziehen.
Diese Sätze enthalten immer den String `"User"`, gefolgt von einem oder mehreren Leerzeichen und dann einem Benutzernamen.
Du beschließt, solche Zeilen zu markieren.

Implementiere eine Funktion `tag_with_user_name/1`, die Logzeilen verarbeitet:

- Zeilen, die den String `"User"` nicht enthalten, bleiben unverändert.
- Bei Zeilen, die den String `"User"` enthalten, stellst du der Zeile `[USER]` gefolgt vom Benutzernamen voran.

```elixir
LogParser.tag_with_user_name("[INFO] User Alice created a new project")
# => "[USER] Alice [INFO] User Alice created a new project"
```

Du kannst davon ausgehen, dass:

- auf jedes Vorkommen des Strings `"User"` ein oder mehrere Leerzeichen und der Benutzername folgen.
- der String `"User"` auf jeder Zeile höchstens einmal vorkommt.
- Benutzernamen nicht leere Strings sind, die keine Leerzeichen enthalten.
