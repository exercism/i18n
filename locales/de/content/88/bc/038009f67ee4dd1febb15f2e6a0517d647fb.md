# Sortieren

Dinge in eine Reihenfolge zu bringen, kommt so häufig vor, dass die Bibliothek es für dich erledigt.

```sather
   scores : ARRAY{INT} := |3, 1, 2|;
   scores.sort;              -- 1, 2, 3
```

`sort` funktioniert mit allem, was sich bereits selbst vergleichen kann. Zahlen und Strings können das, weil sie ein `is_lt` haben.

## Nach deiner eigenen Regel sortieren

Die meisten Reihenfolgen sind nicht die eingebaute. Eine Netball-Tabelle ist weder alphabetisch noch nach der Länge der Namen geordnet: Sie richtet sich nach den Punkten und dann nach der Tordifferenz für Teams mit gleich vielen Punkten. `ARRAY` kann das unmöglich erraten.

Also gibst du die Reihenfolge selbst an, und zwar als gebundene Routine:

```sather
   before(a, b : STR) : BOOL is
      return a.size < b.size;
   end;

   ...

   words.insertion_sort_by(bind(before(_, _)));
```

`insertion_sort_by` nimmt einen `ROUT{T,T}:BOOL` entgegen, also eine Routine, die zwei der zu sortierenden Dinge entgegennimmt und beantwortet, ob das erste vor dem zweiten hingehört. Sie ruft diese Routine so oft auf, wie sie muss, und bringt das Array in die Reihenfolge, die sich aus den Antworten ergibt.

Dafür war `understudy` gedacht. Die Bibliothek weiß, wie man sortiert, aber nichts über deine Vorstellung von Reihenfolge; in der gebundenen Routine treffen beide aufeinander.

## Den Vergleich schreiben

Die Routine gibt **wahr zurück, wenn das erste Argument zuerst kommt**.

```sather
   -- shortest first
   return a.size < b.size;

   -- longest first: turn it round
   return a.size > b.size;
```

Bei einer Regel mit mehr als einem Teil behandelst du die Teile in der Reihenfolge ihrer Wichtigkeit:

```sather
   higher(a, b : TEAM) : BOOL is
      if a.points /= b.points then
         return a.points > b.points;      -- more points comes first
      end;
      return a.difference > b.difference; -- level: better difference wins
   end;
```

Das erste `if` entscheidet die Sache, sobald die Punkte sich unterscheiden. Nur wenn sie gleich sind, kommt die zweite Zeile zum Zug. Würdest du die Entscheidung bei Gleichstand zuerst schreiben, hätten die Punkte nie eine Rolle gespielt.

## Sortieren verändert das Array

`insertion_sort_by` bringt das Array selbst in die richtige Reihenfolge und gibt nichts zurück:

```sather
   teams.insertion_sort_by(bind(higher(_, _)));   -- teams is now sorted
```

Wenn die ursprüngliche Reihenfolge wichtig ist, sortiere eine Kopie:

```sather
   ranked ::= teams.copy;
   ranked.insertion_sort_by(bind(higher(_, _)));
   return ranked;
```
