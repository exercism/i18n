# Ergänzung der Anweisungen

## Ausnahmemeldungen

Manchmal ist es notwendig, [eine Ausnahme auszulösen][raising-exceptions].
Wenn du das tust, solltest du immer eine **aussagekräftige Fehlermeldung** angeben, die zeigt, woher der Fehler stammt.
Das macht deinen Code lesbarer und hilft beim Debuggen erheblich.
Wenn du weißt, dass die Fehlerquelle von einem bestimmten Typ ist, kannst du einen der [eingebauten Fehlertypen][error-base-classes] auslösen, solltest aber trotzdem eine aussagekräftige Meldung angeben.


Ein gültiges Spiel `Tic Tac Toe` endet, wenn ein Spieler gewinnt.
Wenn sich beide Spieler in einem gewinnenden Zustand befinden, erwartet diese Übung, dass du die [raise-Anweisung][raise] verwendest und in deiner Lösung einen `ValueError` „wirfst“.
Dein Code soll außerdem einen `ValueError` werfen, wenn bei einem Spieler festgestellt wird, dass er zwei Züge hintereinander gespielt hat, oder dass er den ersten Zug gespielt hat, obwohl ihm der zweite Zug zugewiesen war.


Um einen `ValueError` mit einer Meldung zu werfen, schreibst du die Meldung als Argument an den Typ `exception`:

```python
# Example when player O goes before player X.
raise ValueError("Wrong turn order: O started")

# Example when player X goes twice.
raise ValueError("Wrong turn order: X went twice")

# Example when player X wins AND player O wins.
raise ValueError("Impossible board: game should have ended after the game was won")
```

Die Tests prüfen auf eine exakte Übereinstimmung der Fehlermeldung. Lies dir die erwarteten Ergebnisse deshalb sorgfältig durch.

[error-base-classes]: https://docs.python.org/3/library/exceptions.html#base-classes
