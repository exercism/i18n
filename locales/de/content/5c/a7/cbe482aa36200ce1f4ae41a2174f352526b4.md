# Nil

Crystal hat einen Typ namens [`Nil`][nil], der nur einen Wert haben kann: `nil`.
Er wird verwendet, um die Abwesenheit eines Werts darzustellen, und ähnelt `null` oder `None` in anderen Sprachen.

`Nil`-Werte können von verschiedenen Methoden zurückgegeben werden, zum Beispiel von [`String#[]?`][string-index], die `nil` zurückgibt, wenn der Index außerhalb des gültigen Bereichs liegt.

```crystal
"foo"[10]? # => nil
```

Crystal hat das, was man **Nullreferenzprüfungen** nennt. Das bedeutet, dass alle Typen standardmäßig nicht nil sein können.
Das bedeutet, du kannst einer Variable kein `nil` zuweisen, es sei denn, du deklarierst sie explizit als Typ `Nil`.
Das wiederum bedeutet, dass der Compiler automatisch auf Nullreferenzen prüft.

## Falsey-Wert

Es gibt verschiedene Ansätze, um mit `nil`-Werten umzugehen.
`nil` ist ein [falsey][truthy-falsey]-Wert, ebenso wie `false`.
Das bedeutet, dass er in Anweisungen und an anderen Stellen, an denen ein falsey- oder truthy-Wert erwartet wird, genauso wie `false` behandelt wird.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Das bedeutet, dass der truthy-Zweig nicht ausgeführt wird, wenn eine nil-fähige Variable den Wert `nil` hat.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Auf `nil` prüfen

Crystal hat eine Methode, mit der du prüfen kannst, ob ein Wert `nil` ist.
Sie heißt [`nil?`][nil?] und ist für alle Objekte verfügbar.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Das ist etwas anders, wenn du den Wert direkt in einer if-Anweisung verwendest, denn in den vorherigen Beispielen würden sowohl false als auch nil als false behandelt.
Hier wird nur `nil` als falsey behandelt, denn wenn es false wäre, wäre es nicht nil gewesen und wäre damit truthy.

## Oder-Operator

Der einfachste Weg, mit `nil`-Werten umzugehen, ist sicherzustellen, dass sie gar nicht erst `nil` werden.
Der Oder-Operator ([`||`][or]) wird oft im Umgang mit `Bools` verwendet, aber richtig verstanden, kannst du ihn auch für `nil`-Werte nutzen.
Der Oder-Operator prüft, ob der erste Wert truthy ist. Wenn nicht, wird der zweite Wert verwendet.
Damit kannst du erreichen, dass, wenn der Wert `nil` ist, er falsey ist und deshalb der zweite Wert verwendet wird.

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
Dieser Ansatz sollte als letztes Mittel gesehen werden und nur verwendet werden, wenn du **sicher** bist, dass der Wert nicht nil ist.
Verwende nach Möglichkeit stattdessen die anderen Ansätze.
~~~~

[`not_nil!`][not_nil] ist eine Methode, mit der du dem Compiler sagen kannst, dass ein Wert nicht nil ist, wodurch der Typ, den er enthält, nicht nil sein kann.
Sie tut das, indem sie eine Ausnahme auslöst, wenn der Wert nil ist.

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
