# Überblick

In der Sprache C ist ein [struct][struct] ein zusammengesetzter Typ, der aus verschiedenen Feldern besteht.
Jedes Feld hat seinen eigenen Typ und seine eigene Größe.

Zum Beispiel definiert dies einen Typ aus drei Ganzzahlen, zwei mit 4 Bytes und eine mit 8 Bytes:

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

Ein struct kann auch andere structs enthalten:

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

Wenn eines der Felder des structs ein Array ist, sind alle für das Array reservierten Bytes Teil des structs.
Wenn das Feld jedoch nur ein Zeiger auf das Array ist, muss das Array woanders gespeichert werden:

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## Ausrichtung

Die [Ausrichtung][alignment] eines Typs ist eine nicht negative Zweierpotenz (1, 2, 4, 8, ...), die eine Anforderung an seine Adresse darstellt.
Jedes Objekt dieses Typs muss an einer Adresse liegen, die ein Vielfaches seiner Ausrichtung ist.

Bei einem primitiven Typ ist die Ausrichtung normalerweise gleich seiner Größe.
So hat ein `int32_t` zum Beispiel üblicherweise eine 4-Byte-Ausrichtung.
Das bedeutet, dass `int32_t` an 4-Byte-Grenzen ausgerichtet sein muss.

Die Ausrichtung eines structs ist jedoch die maximale Ausrichtung seiner Felder.
So hätte das oben definierte `struct example` zum Beispiel eine Ausrichtung von 8 Bytes, da dies die Ausrichtung von `uint64_t` ist.

Wenn die Ausrichtung eines Feldes im struct kleiner ist als die des structs, können nach diesem Feld Füllbytes eingefügt werden.
Dadurch wird sichergestellt, dass die folgenden Felder und das struct als Ganzes die Ausrichtungsanforderungen erfüllen.
In der Praxis bedeutet das: Obwohl diese Füllbytes zur Größe des structs beitragen, werden sie nicht im Wert des structs verwendet:

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

Beachte, dass im oben definierten struct das Feld 'one_byte' eine Ausrichtung von 1 hat und an jeder Adresse liegen kann.
Da das Feld 'four_byte' eine Ausrichtung von 4 hat, müssen die Felder im struct auch 4-Byte-Grenzen einhalten.
Das bedeutet, dass zwischen zwei beliebigen Feldern im struct eine Anzahl von Bytes liegen muss, die ein Vielfaches von 4 ist.
Da 'one_byte' nur 1 Byte belegt, werden danach 3 Füllbytes eingefügt, um diese Grenze einzuhalten.

Benachbarte Felder werden nach Möglichkeit gruppiert, um die Anzahl der notwendigen Füllbytes zu minimieren:

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

Diese Gruppierung muss auch die Ausrichtung jedes Feldes berücksichtigen:

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

Das bedeutet, dass eine Änderung der Reihenfolge der Felder in einem struct manchmal zu einer unterschiedlichen Größe führen kann:

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

Beachte, dass die Ausrichtung eines Arrays dieselbe ist wie die Ausrichtung seines zugrunde liegenden Typs:

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

Elemente eines Arrays können genauso gruppiert werden, als wären sie nicht Teil eines Arrays:

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

Es ist wichtig, alle möglichen Füllbytes zu berücksichtigen, wenn du in Assembler auf ein struct zugreifst.

## Aufrufkonvention

Im Allgemeinen werden Werte so an Funktionen übergeben und von ihnen zurückgegeben, wie man es erwarten würde:

- Ganzzahlige Werte, einschließlich Speicheradressen und Enums, werden in General-Purpose-Registern (GPR) übergeben.
- Gleitkommazahlen werden in `xmm`-Registern übergeben.

structs sind jedoch ein Sonderfall.
Als Faustregel gilt: Alle Felder in einem struct belegen benachbarten Speicherplatz und sollten nach Möglichkeit in einem einzigen Register untergebracht werden:

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

Wenn ein struct Felder mit ganzzahligen Werten und auch Felder mit Gleitkommazahlen enthält, sollte jeder aufeinanderfolgende 8-Byte-Block im struct separat klassifiziert werden:

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

Wenn Ganzzahlen und Gleitkommazahlen im selben 8-Byte-Block liegen, ist der Typ ganzzahlig, und der gesamte 8-Byte-Block (einschließlich der Gleitkommazahl) wird in einem GPR untergebracht:

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
Wenn du eine Gleitkommazahl mit `cvtss2si` oder `cvtsd2si` in eine Ganzzahl umwandelst, ändert sich die Anordnung der zugrunde liegenden Bytes.

Mit [movd][mov] (für 32-Bit-Werte) oder [movq][mov] (für 64-Bit-Werte) kannst du rohe Bytes von einem `xmm`-Register in ein GPR verschieben, ohne die Bitdarstellung zu ändern.

[mov]: https://www.felixcloutier.com/x86/movd:movq
~~~~

structs mit mehr als 16 Bytes Größe werden jedoch normalerweise im Speicher abgelegt, unabhängig vom Typ jedes 8-Byte-Blocks:

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

Wenn ein struct als Argument an eine Funktion übergeben wird, verwendet es so viele Register wie nötig.
Wenn es im Speicher abgelegt wird, wird stattdessen der Stack verwendet.

Ähnliche Regeln gelten für structs, die von einer Funktion zurückgegeben werden.
Sie werden normalerweise zuerst in `rax` und `rdx` zurückgegeben (wenn sie ganzzahlig sind) oder in `xmm0` und `xmm1` (wenn sie Gleitkommazahlen sind).
Wenn sie jedoch im Speicher abgelegt werden, muss der Aufrufer Speicherplatz dafür reservieren und die Adresse dieser Speicherstelle als implizites erstes Argument an die Funktion übergeben (in `rdi`).
Die Funktion speichert das struct dann in diesem Speicher und gibt seine Adresse in `rax` zurück.
