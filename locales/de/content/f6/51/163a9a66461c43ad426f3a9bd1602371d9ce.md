# Unison-Grundlagen

## Terme und Funktionen

Terme und Funktionen sind die grundlegenden Bausteine, wenn du ein Unison-Programm schreibst.

Ein „Term“ ist das, was wir einen statischen Wert nennen. Er wird mit `name = expression` definiert, optional mit einer vorangestellten Typsignatur der Form `name : MyType`. Unison unterstützt Typinferenz, daher kann die Typsignatur bei einfachen Definitionen auch weggelassen werden.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison-Funktionen sehen so aus: `myFunctionName argument1 argument2 = myImplementation`. Sie beginnen mit dem Namen der Funktion, gefolgt von durch Leerzeichen getrennten Argumenten.

```
getMax a b = Nat.max a b
```

Funktionen können optional eine Typsignatur enthalten. Der letzte Typ auf der rechten Seite ist immer der endgültige Rückgabetyp der Funktion, und die einzelnen Argumente werden durch den Funktionspfeil `->` getrennt.

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Um eine Funktion aufzurufen, verwendest du ihren Namen, gefolgt von ihren Argumenten, die nur durch Leerzeichen getrennt sind.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Wenn du eine Funktion aufrufst, versucht Unison, alles, was direkt rechts davon steht, als ihr Argument zu behandeln. Das führt nicht immer zu der Reihenfolge, in der die Funktionen ausgewertet werden sollen.

Angenommen, wir wollen aus dem folgenden Ausdruck den Wert `1` erhalten:

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

So wie es geschrieben steht, wird `shouldBe1` zu `0` ausgewertet, weil die implizite Reihenfolge der Funktionsanwendung `getMax 1 10` lautet, also `10`, und danach `10 - 10`, also `0`.

Mit runden Klammern kannst du den Ausdruck neu gruppieren, sodass die gewünschte Reihenfolge der Operationen entsteht.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Watch Expressions

Unison bietet eine Möglichkeit, Code schnell auszuwerten: die „Watch Expression“. Eine Watch Expression beginnt mit dem Symbol `>` und danach folgt der Ausdruck, der ausgewertet werden soll. Watch Expressions kannst du in jeder Datei mit der Endung `.u` schreiben. Sobald du die Datei speicherst, siehst du in der Konsole des Unison Codebase Manager (UCM), zu welchem Wert der Ausdruck ausgewertet wird. Wo es in dieser Dokumentation möglich ist, zeigen wir einen Ausdruck zusammen mit der erwarteten Ausgabe, nachdem er in einer Watch Expression ausgewertet wurde.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Mehrzeilige Funktionen

Mehrzeilige Funktionen in Unison verwenden Einrückung oder `let`-Blöcke, um Codegrenzen festzulegen, auch bekannt als lexikalischer Gültigkeitsbereich.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Alles auf derselben Einrückungsebene teilt sich denselben Gültigkeitsbereich. Deshalb können wir in der letzten Zeile auf die Variable `newBeginning` verweisen.

## Namensräume und `use`-Anweisungen

Namensräume sind das Mittel, mit dem wir Unison-Funktionen gruppieren und organisieren. Du kannst sie dir wie „Verzeichnisse“ vorstellen. Sie sorgen für Struktur und logische Gruppierung.

Mit einer `use`-Anweisung kannst du die Funktionen eines Namensraums in den Gültigkeitsbereich holen.

Angenommen, du schreibst eine Funktion, die Unison-`List`-Werte verwendet. Du weißt, dass du Funktionen wie `List.map` und `List.flatMap` brauchst, wobei `List` der Namensraum und `map` und `flatMap` die Funktionen sind. Um Wiederholungen zu vermeiden, kannst du alles aus dem Namensraum `List` in deiner Funktion in den lexikalischen Gültigkeitsbereich holen, etwa so:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

Die Zeile `use List` macht die Verweise auf `map` und `flatMap` eindeutig. Mehr über [`use`-Anweisungen findest du hier][use-statements].

## Unisons Standardbibliothek

Unisons Standardbibliothek heißt `base`. Wenn du der Schnellstartanleitung gefolgt bist und eine Codebasis lokal angelegt hast, sollte die Standardbibliothek automatisch heruntergeladen worden sein. Die Dokumentation der Standardbibliothek kannst du online auf [Unison Share][unison-share-base] durchstöbern.

## Kommentare und Dokumentationsliterale

Kommentare sind in Unison eine etwas ungewöhnliche Sache. Wenn du Unison-Code schreibst, kannst du in deiner Datei mit der Endung `.u` Text anlegen, der nicht ausgewertet wird, und zwar mit der folgenden Syntax:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Allerdings_ wird Unison-Code als Hash seines abstrakten Syntaxbaums gespeichert und nicht als textbasierte Dateien im Dateisystem. Deshalb lassen sich textbasierte Kommentare, die eine Unison-Funktion oder einen Term in der Datei sozusagen „verzieren“, nicht wirklich speichern und zum Teilen erneut anzeigen. Wenn du einem Unison-Term Informationen hinzufügen möchtest, die für andere gespeichert werden, damit sie sie lesen und verstehen können, kannst du ein Dokumentationsliteral verwenden.

Dokumentation ist in der Programmiersprache Unison ein Wert erster Klasse. Das bedeutet, ein `Doc`-Element kann einem Wert zugewiesen, als Wert an eine Funktion übergeben oder als Wert einer Funktion zurückgegeben werden. Dokumentationsliterale werden mit doppelten geschweiften Klammern geöffnet und geschlossen. So könnten wir das `Doc`-Element als Kommentar verwenden.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
