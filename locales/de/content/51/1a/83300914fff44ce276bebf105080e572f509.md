# Match-Grundlagen

Der `match`-Ausdruck ermöglicht den einfachen Vergleich eines Werts mit einer Reihe von Mustern und führt anschließend den Code basierend auf dem übereinstimmenden Muster aus.
Ein Muster besteht aus Literalwerten, Variablennamen, Wildcards und vielen anderen Dingen.

```rust
#[derive(Drop)]
enum Color {
    Red,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red => println!("The color is Red"),
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Yellow;
    print_color_type(color); // prints "The color is Yellow"
}
```

Um mehrere Codezeilen zu behandeln, sollte der `match`-Zweig in geschweifte Klammern `{}` gesetzt werden:

```rust
fn specified_color(color: Color) -> felt252 {
    let mut response: felt252 = '';

    match color {
        Color::Red => {
            response = 'You passed in Red';
        },
        Color::Yellow => {
            response = 'You passed in Yellow';
        },
        Color::Green => {
            response = 'You passed in Green';
        },
    }

    response
}
```

Der `match`-Ausdruck besitzt außerdem die Fähigkeit, an Werte zu binden, die dem Muster entsprechen.
Dadurch ist es möglich, den zugehörigen Wert einer Enum-Variante zu extrahieren.

```rust
#[derive(Drop, Debug)]
enum ColorType {
    Light,
    Dark,
}

#[derive(Drop)]
enum Color {
    Red: ColorType,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red(state) => {
            println!("The color is Red");
            println!("The Color Type is {:?}", state);
        },
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Red(ColorType::Dark);
    print_color_type(color);
}
```

Wir erweitern die `Red`-Variante des `Color`-Enums um ein zugehöriges Enum.
Mithilfe des `match`-Ausdrucks können wir den zugehörigen Wert extrahieren; `state`.
Dies ist einfach ein Variablenname, der später im Code-Zweig verwendet werden kann.

## Abgleich mit dem `Option`-Enum-Typ

Das eingebaute `Option`-Enum kann ebenfalls mit dem `match`-Ausdruck behandelt werden.

Entwerfen wir eine Funktion, die einen Parameter vom Typ `Option<u8>` entgegennimmt.
Wenn der übergebene Parameter einen Wert enthält, addiere eins zu diesem Wert, andernfalls soll die Funktion den `None`-Wert ohne Operation zurückgeben.

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
        Option::None => Option::None,
    }
}

fn main() {
    let three: Option<u8> = Option::Some(3);
    let four: Option<u8> = add_one(three);
    let none = add_one(Option::None);

    println!("{three:?}"); // prints "Option::Some(3)"
    println!("{four:?}"); // prints "Option::Some(4)"
    println!("{none:?}"); // prints "Option::None(())"
}
```

> Hinweis: `{:?}` ist eine spezielle Formatierungssyntax, mit der eine Debug-Form des an das `println!`-Makro übergebenen Parameters ausgegeben werden kann.
> Weitere Informationen dazu findest du im [Cairo-Buch][debugging].

Ein Vorteil der Verwendung des `match`-Kontrollflusses ist seine Vollständigkeit: Die Muster der Zweige müssen _alle_ Möglichkeiten abdecken.
Betrachte die Version des vorherigen Beispiels, die den `None`-Fall nicht behandelt:

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
    }
     // this code does not compile, as we forgot to handle the `None` case
}
```

## Catch-all-Muster mit `_`-Wildcard

Mit Enums können wir auch spezielle Aktionen für einige bestimmte Werte ausführen, aber für alle anderen Werte eine Standardaktion ausführen, indem wir einen neuen Zweig mit `_` als Muster für den letzten Zweig des `match`-Ausdrucks hinzufügen.
Das `_`-Muster ist ein spezielles Muster, das auf jeden Wert passt und nicht an diesen Wert bindet.

Die Funktion `is_red` empfängt einen Parameter und gibt `true` zurück, wenn die Farbe `Red` ist, und `false` für jede andere Farbe:

```rust
fn is_red(color: Color) -> bool {
    match color {
        Color::Red => true,
        _ => false,
    }
}
```

## Musterabgleich mit dem `|`-Operator

Das `match`-Kontrollflusskonstrukt von Cairo ermöglicht es, einen Wert mit mehreren Mustern mithilfe des `|`-Operators (_oder_) abzugleichen.
Das hilft, den Code zu vereinfachen.

Zum Beispiel möchten wir unter Verwendung des `Color`-Enums eine Funktion schreiben, die `true` für die Farben `Red` oder `Green` zurückgibt und `false` für andere Farben:

```rust
fn is_red_or_green(color: Color) -> bool {
    match color {
        Color::Red | Color::Green => true,
        _ => false,
    }
}
```

## Musterabgleich mit `felt252` und Ganzzahlvariablen

Es ist möglich, `felt252`- und Ganzzahlvariablen mit einer Reihe von Werten abzugleichen.
Es gibt jedoch einige Einschränkungen;

- Es werden nur Ganzzahlen unterstützt, die in ein einzelnes `felt252` passen (d. h. `u256` wird nicht unterstützt).
- 0 muss der erste Zweig sein.
- Jeder Zweig muss einem sequenziellen Segment folgen, zusammenhängend mit anderen Zweigen.

Implementieren wir ein Spiel, bei dem ein sechsseitiger Würfel geworfen wird.
Wenn dieser Würfel geworfen wird, erhalten wir eine Zahl zwischen 0 und 5.
Bei einem Wurf, der 0, 1 oder 2 ergibt, gewinnst du.
Du würfelst erneut, wenn du 3 hast.
Bei anderen Werten verlierst du:

```rust
fn toss(value: u8) {
    match value {
        0 | 1 | 2 => println!("you won!"),
        3 => println!("you can roll again!"),
        _ => println!("you lost...")
    }
}

fn main() {
    toss(2); // prints "you won!".
    toss(3); // prints "you can roll again!".
    toss(5); // prints "you lost...".
}
```

## Tupel abgleichen

Tupel können ebenfalls mit einer Reihe von Mustern abgeglichen werden.
Diese Muster sind ähnlich wie ein Tupel aufgebaut.

```rust
#[derive(Drop)]
enum DayType {
    Week,
    Weekend,
    Holiday
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn vending_machine_accept(c: (DayType, Coin)) -> bool {
    match c {
        (DayType::Week, _) => true, // accepts all coins during week day
        (_, Coin::Dime) | (_, Coin::Quarter) => true, // accepts only Dime or Quarter coin for all specified days
        (_, _) => false, // returns false for other instances
    }
}
```

Im letzten `match`-Zweig spielt es keine Rolle, ob wir `(_, _)` oder nur die `_`-Wildcard verwenden, um eine beliebige Tages- und Farbkombination abzugleichen, da sie funktional identisch sind.
