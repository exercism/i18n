# Überblick

Klassen wie `LocalDate` und `LocalDateTime` beschreiben einen _Zeitpunkt_.
Das Paket `java.time` enthält außerdem zwei Klassen, die eine _Zeitspanne_ beschreiben:

- [`Period`][period-docs] ist eine datumsbasierte Zeitspanne in Jahren, Monaten und Tagen, etwa „2 Monate und 5 Tage“.
- [`Duration`][duration-docs] ist eine zeitbasierte Zeitspanne in Stunden, Minuten, Sekunden, Millisekunden und Nanosekunden, etwa „1 Stunde und 30 Minuten“.

Der Unterschied ist wichtig, weil Kalendereinheiten keine feste Länge haben.
Ein Monat kann 28, 29, 30 oder 31 Tage haben, „ein Monat“ ist also keine feste Anzahl von Sekunden.
Eine `Period` folgt dem Kalender, während eine `Duration` exakte Zeit misst.

| | `Period` | `Duration` |
| --- | --- | --- |
| Speichert | Jahre, Monate und Tage | Sekunden und Nanosekunden |
| Verwendet mit | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

Beide Klassen sind unveränderlich.
Methoden wie `plusDays()` oder `multipliedBy()` geben eine _neue_ Instanz zurück und lassen das Original unverändert.

## `Period`

### Eine `Period` erstellen

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

Das Ergebnis von `toString()` verwendet das [ISO-8601-Dauerformat][iso-8601-durations]: `P` gefolgt von der Anzahl der Jahre (`Y`), Monate (`M`) und Tage (`D`).
In einer `Period` gibt es keine Wochen: `Period.ofWeeks(2)` wird als 14 Tage gespeichert.
Mit `Period.parse()` lässt sich dieselbe Notation wieder parsen:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### Eine `Period` zu einem Datum addieren

Mit `plus()` und `minus()` addierst du eine `Period` zu einem Datum oder ziehst sie davon ab:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

Genauso kannst du eine `Period` zu einem `LocalDateTime` addieren, und die Uhrzeit bleibt dabei gleich:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

Ein `Instant` hat keinen Kalender, deshalb kannst du nur eine `Period` aus Tagen dazu addieren.
Eine `Period` mit Jahren oder Monaten wirft eine Exception:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

Zuerst werden die Jahre addiert, dann die Monate und dann die Tage.
Wenn du Jahre oder Monate addierst und dabei auf einen Tag stößt, den es nicht gibt, wird das Ergebnis auf den letzten gültigen Tag dieses Monats zurückgesetzt:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

Das heißt auch: Wenn du eine `Period` addierst und danach wieder abziehst, kommt nicht immer das ursprüngliche Datum heraus:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### Die `Period` zwischen zwei Daten

`Period.between()` liefert die `Period` von einem Datum (einschließlich) bis zu einem anderen (ausschließlich).
Dasselbe Ergebnis bekommst du mit `LocalDate.until()`:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

Die Bestandteile einer `Period` bekommst du über `getYears()`, `getMonths()` und `getDays()`.
Diese Bestandteile sind unabhängig voneinander: `getDays()` liefert nur den Tagesanteil, nicht die Gesamtzahl der Tage.
`toTotalMonths()` fasst Jahre und Monate zu einer Anzahl von Monaten zusammen, aber es gibt keine Methode für die Gesamtzahl der Tage, denn die hängt davon ab, um welche Monate es geht.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### Eine `Period` normalisieren

Eine mit einer Factory-Methode erzeugte `Period` behält ihre Einheiten genau so, wie du sie angegeben hast, und `equals()` vergleicht die Einheiten einzeln.
`normalized()` rechnet volle Monate in Jahre um, lässt die Tage aber unangetastet:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## Einheiten mit `ChronoUnit` zählen

Um die Gesamtzahl einer einzelnen Einheit zwischen zwei Zeitpunkten zu bekommen, verwendest du die Methode `between()` auf einer der Konstanten von [`ChronoUnit`][chronounit-docs]:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

Es werden nur vollständige Einheiten gezählt, und das Ergebnis ist negativ, wenn das zweite Argument vor dem ersten liegt:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit` funktioniert auch mit zeitbasierten Einheiten und mit Datum-Uhrzeit-Werten:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### Eine `Duration` erstellen

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

In der ISO-8601-Notation trennt das `T` den Datumsteil vom Zeitteil.
Eine `Duration` hat keinen Datumsteil, deshalb beginnt ihr `toString()` immer mit `PT`.
`Duration.ofDays()` behandelt einen Tag als genau 24 Stunden.

Eine `Duration` lässt sich auch mit `Duration.parse()` parsen:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### Eine `Duration` zu einer Uhrzeit addieren

Mit `plus()` und `minus()` kannst du eine `Duration` zu `LocalTime`-, `LocalDateTime`- oder `Instant`-Werten addieren oder von ihnen abziehen:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

Eine `LocalTime` läuft über Mitternacht hinaus, wie das letzte Beispiel zeigt.

Ein `LocalDate` hat keine Uhrzeit, deshalb lässt es sich nicht mit einer `Duration` kombinieren:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### Die `Duration` zwischen zwei Uhrzeiten

`Duration.between()` liefert die exakte Zeitspanne zwischen zwei Uhrzeiten oder Datum-Uhrzeit-Werten:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()` akzeptiert keine zwei `LocalDate`-Werte, weil ein Datum keine Sekunden hat, die man messen könnte:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

Verwende für Daten stattdessen `Period.between()` oder `ChronoUnit.DAYS.between()`.

### Eine `Duration` umrechnen

Die Methoden `toXxx()` rechnen eine `Duration` in eine _Gesamtmenge_ einer einzelnen Einheit um und runden dabei ab:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

Die Methoden `toXxxPart()` zerlegen eine `Duration` in ihre Bestandteile, wie auf einer Uhr:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()` hört bei 23 auf, denn die Stunden darüber zählt `toDaysPart()`.

### `Duration`-Werte vergleichen und mit ihnen rechnen

`Duration`-Werte lassen sich mit `compareTo()` vergleichen und mit `isZero()` und `isNegative()` prüfen:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

Sie unterstützen auch Arithmetik, etwa `plus()`, `minus()`, `multipliedBy()` und `dividedBy()`:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` oder `Duration`?

Bei einem `LocalDate` oder einer `LocalTime` ist die Wahl schon getroffen: Ein Datum hat keine Uhrzeit zum Messen, und eine Uhrzeit hat keinen Kalender.
Ein `LocalDateTime` hat beides, aber keine Zeitzone, deshalb kommt beim Addieren von `Period.ofDays(1)` oder `Duration.ofDays(1)` dasselbe heraus.
Mit Zeitzonen wird der Unterschied sichtbar.
Wenn die Uhren wegen der Sommerzeit vorgestellt werden, ist ein Kalendertag nur 23 Stunden lang:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

Addierst du eine `Period` von einem Tag, bleibt die Uhrzeit gleich; addierst du eine `Duration` von einem Tag, kommen genau 24 Stunden dazu.
Nimm eine `Period` für Zeiträume, die Menschen in Kalenderbegriffen denken („zur gleichen Zeit nächsten Monat“), und eine `Duration` für verstrichene Zeit („der Parkschein gilt 2 Stunden“).
