# Überblick

Factor teilt die Stream-Ein- und -Ausgabe in zwei Schichten auf. Die untere Schicht ist die *Explicit-Stream*-API: Jedes Wort nimmt den Stream als Argument entgegen. Die obere Schicht ist die *Ambient-Stream*-API: kurze, einzeilige Wörter, die auf den gerade gebundenen Stream wirken. Beide Schichten bauen auf demselben [Protokoll][stream-protocol] auf: Die Wörter der oberen Schicht schlagen nur den ambienten Stream nach und leiten den Aufruf weiter.

## Wörter der Explicit-Stream-API

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents` liest alles aus; `stream-lines` liest alles aus und teilt an den Zeilengrenzen auf; `stream-readln` liefert jeweils eine Zeile (oder `f` am Stream-Ende).

## Wörter der Ambient-Stream-API

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

Das sind die alltäglichen Ein- und Ausgabewörter. Sie schlagen den aktuellen Eingabe- oder Ausgabestream in den dynamischen Variablen `input-stream` / `output-stream` nach und leiten den Aufruf weiter. Deshalb genügt es, `output-stream` für die Dauer einer Quotation zu binden, um `print` auf einen String umzuleiten.

## Mitgelieferte Stream-Konstruktoren

| Wort              | Vokabular            | was es erzeugt                  |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | liest ein String-Literal        |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | sammelt Schreibvorgänge in einem String |
| `<file-reader>`   | [`io.files`][io.files]           | liest eine Datei mit einer Kodierung |
| `<file-writer>`   | [`io.files`][io.files]           | schreibt eine Datei mit einer Kodierung |

Alle vier erzeugen Disposables: Sie erweitern `disposable` aus `destructors`, sodass die `with-…`-Kombinatoren weiter unten sie beim Verlassen wieder freigeben.

## Bindung im Gültigkeitsbereich

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

Jedes dieser Wörter öffnet einen Stream, bindet ihn für die innere Quotation als ambienten Eingabe- bzw. Ausgabestream und gibt ihn beim Verlassen wieder frei, selbst wenn die Quotation eine Ausnahme auslöst. Es sind die Destruktor-Kombinatoren aus `boatswains-bilge`, spezialisiert auf Streams.

`with-string-writer` ist eine besonders saubere Variante: Es erzeugt automatisch einen frischen `<string-writer>`, führt die Quotation mit diesem Writer als ambienter Ausgabe aus und gibt den gesammelten String zurück. Das ganze Muster „die Ausgabe einer Quotation einfangen" ist ein einziges Wort.

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## Warum überhaupt Ambient-Streams?

Die Bindung über dynamische Variablen ist der Grund, warum `print` in einem Programm funktioniert, das nicht weiß, ob es interaktiv läuft, ob seine Ausgabe in eine Logdatei oder in einen eingefangenen Testpuffer geht. Ersetze die Bindung einmal, und jedes Wort, das `print` aufruft, macht das Richtige, ganz ohne Umverdrahtung. Das ist die Umkehrung, die dir die obere Schicht liefert.

Wie du einen Stream selbst *implementierst*, also eine eigene Klasse definierst, die sich in das Protokoll einklinkt, siehst du im Konzept `streams` (vermittelt in `telegraphers-tape`).
