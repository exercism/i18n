# Überblick

Der Typ `Option` ist der Mechanismus der Sprache F#, um mit Werten umzugehen, die es geben kann oder auch nicht.
Er bietet eine typsichere Alternative zur Verwendung von `null`, die in anderen Sprachen für solche Werte üblich ist.
Er wird in vielen Funktionen der F#-Standardbibliothek verwendet, deshalb ist es unerlässlich, ihn zu verstehen, wenn du die F#-Standardbibliothek effektiv nutzen willst.

## Vorteile des Typs `Option`

* __Sicherheit zur Kompilierzeit__: Indem das Vorhandensein oder Fehlen eines Werts im Typsystem explizit gemacht wird, kann der Compiler sicherstellen, dass du den Fall „kein Wert“ behandelst. So verhinderst du eine große Klasse von Fehlern, die bei null auftreten könnten.

* __Sicherheit zur Laufzeit__: Statt `null` zu verwenden, nutzt F# `None`, um das Fehlen eines Werts darzustellen. Dadurch kann eine `NullReferenceException` gar nicht erst auftreten.

* __Erzwingt explizite Behandlung__: Das Typsystem verlangt, dass der Code sowohl den Fall `Some value` als auch den Fall `None` explizit behandelt. Das macht deinen Code robuster und vorhersagbarer.

* __Funktioniert mit Pattern Matching__: `Option`s lassen sich nahtlos mit dem Pattern-Matching-Idiom von F# kombinieren. Sie bieten eine saubere und sichere Möglichkeit, den Wert zu zerlegen und zu behandeln, wenn er existiert, oder eine andere Aktion auszuführen, wenn nicht.

## Verwendung

Der Typ `Option` ist ein generischer Typ (er hat einen zugrunde liegenden Typ).
`Option`-Werte sind entweder `Some value`, was einen konkreten Wert darstellt, oder `None`, was keinen Wert darstellt.

Die folgende Funktion zeigt, wie du einen `Option`-Wert erstellst:

```fsharp
let keepIfPositive (a: int) : int option = if a > 0 then Some a else None
```

~~~~exercism/note
`T option` ist die Postfix-Syntax, die `Option<T>` entspricht; die beiden Syntaxformen kannst du austauschen.
Laut dem F# Style Guide ist für Option-Typen jedoch die Postfix-Notation vorzuziehen (siehe [Abschnitt zur Formatierung von Typen und Typannotationen im F# Style Guide](https://learn.microsoft.com/en-us/dotnet/fsharp/style-guide/formatting#for-types-prefer-prefix-syntax-for-generics-foot-with-some-specific-exceptions)).
~~~~

Ein typischer Anwendungsfall für einen `Option`-Wert sind Suchfunktionen.
Zum Beispiel gibt die Funktion `List.tryFind` `Some index` zurück, wenn das Element in der Liste enthalten ist (`index` ist dann die Position des gesuchten Werts in der Liste), oder `None`, wenn das Element nicht in der Liste ist.

## Den Inhalt eines Option-Werts lesen

Der idiomatische Weg, einen `Option`-Wert zu lesen, ist das Pattern Matching, wie das folgende Beispiel zeigt:

```fsharp
// Returns "Hello, <name>!" if the name is provided; otherwise returns "Hello, you!"
let sayHello (optionalName: string option): string = 
    match optionalName with
    | Some name -> "Hello, " + name + "!"
    | None -> "Hello, you!"

sayHello (Some "Matthieu")
// --> "Hello, Matthieu!"

sayHello None
// --> "Hello, you!"
```

## Options mit Standardwerten entpacken

`Option`s lassen sich mit der Funktion `Option.defaultValue` „entpacken“ (in den enthaltenen Typ umwandeln), indem du Standardwerte angibst.
Das ist besonders nützlich, wenn du sicherstellen willst, dass der Wert nicht `None` ist.
Zum Beispiel:

```fsharp
Option.defaultValue "" (Some "F#")
// --> "F#"

Option.defaultValue 0 None
// --> 0
```

## Weitere Funktionen im Modul `Option`

Das Modul `Option` enthält auch Funktionen, die den Funktionen für Listen, Arrays, Sequenzen und andere Sammlungstypen entsprechen, zum Beispiel `Option.map`, `Option.iter`, `Option.forall` und `Option.count`.
Mit diesen Funktionen lassen sich `Option`s wie eine Sammlung mit null oder einem Element behandeln.
