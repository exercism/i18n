# Tests

Odin-Übungen in deinem Exercism-Projektverzeichnis kannst du ausführen, indem du in das Übungsverzeichnis wechselst und `odin test .` ausführst.

```sh
cd "$(exercism workspace)"/odin/leap
odin test .
```

## Sprachprüfungen aktivieren

Während du testest, kann Odin deinen Code „vetten“: Es kann nach Dingen wie ungenutzten Imports und Variablen suchen.

Führe deine Tests aus mit

```sh
odin test . -vet
```

Für noch mehr Prüfungen füge die Option `-strict-style` hinzu.

## Testgetriebene Entwicklung (TDD)

`odin test` führt jede Prozedur aus, die das Attribut `@(test)` hat.

In der Testsuite wirst du feststellen, dass jede Testprozedur dieses Attribut hat. Das bedeutet: Wenn du die Tests startest, wird jede Testprozedur ausgeführt.

Exercism setzt im Allgemeinen auf [testgetriebene Entwicklung][tdd], bei der:

- zunächst alle Tests außer dem ersten so konfiguriert sind, dass sie übersprungen werden;
- du gerade genug Code schreibst, um den ersten Test zu bestehen;
- du dann den nächsten Test aktivierst und gerade genug Code schreibst, um ihn zu bestehen;
- und das so lange wiederholst, bis dein Code alle Tests besteht.

Wir (die Maintainer) haben keinen eleganten programmatischen Weg gefunden, eine Teilmenge der Tests auszuführen. Die Testdatei wurde einfach zu unhandlich. Um mit TDD zu entwickeln, kannst du die Testdatei bearbeiten, die Tests, die du noch nicht ausführen möchtest, auskommentieren und sie dann nach und nach einkommentieren, während du deine Lösung schreibst.
