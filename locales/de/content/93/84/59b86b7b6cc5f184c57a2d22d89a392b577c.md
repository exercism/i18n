# Einführung in Typ-Assertionen

Interfaces in Go können zu Unklarheiten über den zugrunde liegenden Typ führen.
Mit einer Typ-Assertion können wir den konkreten Wert hinter einem Interface-Wert herausziehen, und zwar mit dieser Syntax: `interfaceVariable.(concreteType)`.

Zum Beispiel:

```go
var input interface{} = 12
number := input.(int)
```

HINWEIS: Das löst eine Panik aus, wenn die Interface-Variable keinen Wert des konkreten Typs enthält.

Wir können prüfen, ob ein Interface-Wert einen bestimmten konkreten Typ enthält, indem wir beide Rückgabewerte der Typ-Assertion nutzen: den zugrunde liegenden Wert und einen booleschen Wert, der angibt, ob die Assertion erfolgreich war.
Zum Beispiel:

```go
str, ok := input.(string) // no panic if input is not a string
```

Enthält `input` einen `string`, dann ist `str` der zugrunde liegende Wert und `ok` ist wahr.
Enthält `input` keinen `string`, dann ist `str` der Nullwert vom Typ `string` (also `""`, der leere String) und `ok` ist falsch.
In keinem Fall tritt eine Panik auf.

## Typ-Switches

Ein **Typ-Switch** kann mehrere Typ-Assertions nacheinander ausführen.
Er hat dieselbe Syntax wie eine Typ-Assertion (`interfaceVariable.(concreteType)`), aber `concreteType` wird durch das Schlüsselwort `type` ersetzt.
Hier ist ein Beispiel:

```go
var i interface{} = 12 // try: 12.3, true, int64(12), []int{}, map[string]int{}

switch v := i.(type) {
case int:
    fmt.Printf("the integer %d\n", v)
case string:
    fmt.Printf("the string %q\n", v)
default:
    fmt.Printf("type, %T, not handled explicitly: %#v\n", v, v)
}
```
