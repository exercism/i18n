# Unveränderliche Klassen

Ein `SCOREBOARD` ist ein Ding, das sich verändert. Zwei Namen für ein Scoreboard sehen denselben Punktestand, denn es gibt nur ein Scoreboard und beide Namen zeigen darauf.

Eine Peilung ist nicht so. `350 degrees` wird nicht zu etwas anderem; sie *ist* einfach. Zahlen verhalten sich so, Strings ebenso, und auch deine eigenen Klassen können das.

## immutable

```sather
immutable class BEARING is

   readonly attr degrees : INT;

end; -- class BEARING
```

Zwei Wörter ändern alles. Ein Objekt einer unveränderlichen Klasse ist ein **Wert**, kein Ding, auf das gezeigt wird:

- es wird kopiert, wenn es zugewiesen oder übergeben wird, also kann niemand sonst deines ändern;
- es kann niemals void sein;
- und seine Attribute lassen sich nicht zuweisen.

## Eine ändern, indem man eine neue erzeugt

Da `degrees := 90` nicht erlaubt ist, liefert `attr` etwas anderes: eine Routine, die den neuen Wert entgegennimmt und **ein neues Objekt** mit dem geänderten Wert zurückgibt.

```sather
   b ::= b.degrees(90);      -- not b.degrees := 90
```

Das Original bleibt unangetastet. Das ist das ganze Idiom, und genau so ist `create` geschrieben:

```sather
   create(d : INT) : SAME is
      b : SAME;                     -- starts with everything at nought
      return b.degrees(d);
   end;
```

Hier gibt es kein `new`. Ein unveränderliches Objekt existiert immer, also *ist* `b : SAME` bereits eines, mit jedem Attribut auf seinem leeren Wert.

Eine Routine, die eine Peilung „ändert“, gibt daher eine neue zurück:

```sather
   turned(by : INT) : SAME is
      return #BEARING(degrees + by);
   end;
```

## Vergleichen

Werte werden danach verglichen, was sie enthalten, nicht danach, welches Objekt sie sind. Aber du musst sagen, wie. Schreibe `is_eq`, und `=` verwendet es:

```sather
   is_eq(other : SAME) : BOOL is
      return degrees = other.degrees;
   end;
```

Ohne das lässt sich `=` auf zwei Peilungen nicht kompilieren.

## Was du wählen solltest

Nimm eine unveränderliche Klasse, wenn das Ding keine Identität hat und sich sinnvollerweise nichts an ihm ändern kann: eine Peilung, ein Punkt, ein Datum, eine Länge. Nimm eine gewöhnliche Klasse, wenn das Ding ein bestimmtes Etwas ist, dem etwas widerfährt: ein Scoreboard, ein Harness, eine Datei.

Der Prüfstein ist, ob „dasselbe“ „gleich“ bedeutet oder „ein und dasselbe“.
