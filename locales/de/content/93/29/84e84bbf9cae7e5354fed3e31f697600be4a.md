# Einführung

## Listen

Eine `list` in F# ist eine unveränderliche Sammlung von null oder mehr Werten. Alle Werte in einer Liste müssen denselben Typ haben. Da Listen unveränderlich sind, kann sich der Wert einer Liste nie mehr ändern, sobald sie erstellt wurde. Alle Funktionen und Operatoren, die eine Liste zu verändern scheinen (etwa das Hinzufügen eines Elements), geben in Wirklichkeit eine neue Liste zurück.

So kannst du Listen definieren:

```fsharp
let empty = []
let singleValue = [5]
let threeValues = ["a"; "b"; "c"]
```

Am häufigsten fügst du ein Element über den `::`-Operator (cons) zu einer Liste hinzu:

```fsharp
let twoToFour = [2; 3; 4]
let oneToFour = 1 :: twoToFour
// => [1; 2; 3; 4]
```

Eine F#-Liste hat einen _Kopf_ (das erste Element) und einen _Rest_ (alles nach dem ersten Element). Der Rest einer Liste ist selbst eine Liste.

Listen werden entweder mit Funktionen und Operatoren aus dem `List`-Modul bearbeitet oder manuell mit Pattern Matching unter Verwendung des _list_- und des _cons_-Musters:

```fsharp
let describe list =
    match list with
    | [] -> "Empty list"
    | head::tail -> sprintf "Non-empty list with head: %d" head

describe []        // => "Empty list"
describe [1]       // => "Non-empty with head: 1"
describe [5; 7; 9] // => "Non-empty with head: 5"
```

Du kannst einen Wert beim Pattern Matching auch _verwerfen_. Wenn du dich in einem bestimmten Fall nicht für einen Wert interessierst (das heißt, du wirst einen Wert nicht _benutzen_), kannst du einen Unterstrich (`'_'`) verwenden, um das zu kennzeichnen:

```fsharp
let describe list =
    match list with
    | [] -> "Empty list"
    | [x] -> "List with one item"
    | [_; y] -> "List with two items (first item ignored)"
    | _ -> "List with many items (all items ignored)"

describe []        // => "Empty list"
describe [1]       // => "List with one item"
describe [5; 7]     // => "List with two items (first item ignored)"
describe [5; 7; 9] // => "List with many items (all items ignored)"
```

Der einzelne `'_'` sollte beim Pattern Matching immer _zuletzt_ kommen. Jeder Wert, der auf keinen der anderen Fälle passt, wird von diesem Fall behandelt.
