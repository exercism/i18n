# Iteratoren kombinieren

Mehrere Iteratoren können sich eine Schleife teilen. Jeder wird pro Durchlauf einmal weitergerückt.

```sather
   loop
      a ::= xs.elt!;
      b ::= ys.elt!;
      ...
   end;
```

## Beendigung

Die Schleife endet in dem Moment, in dem **irgendeiner** der Iteratoren nichts mehr liefert. Die übrigen Iteratoren werden nicht weitergerückt, und der Rest des Schleifenblocks wird nicht ausgeführt.

Das bedeutet: Wenn du zwei Arrays gemeinsam durchläufst, deckst du `min(xs.size, ys.size)` Durchläufe ab. Willst du das längere Array abdecken, durchläufst du stattdessen Positionen und indizierst, wobei du das kürzere Array selbst absicherst.

## Jede Aufrufstelle ist ein eigener Lauf

Die Position eines Iterators gehört zu der *Stelle im Programm*, an der er geschrieben steht, nicht zum Objekt. Also:

```sather
   loop
      #OUT + xs.elt! + xs.elt!;      -- two walks, each advancing separately
   end;
```

Der Code nimmt pro Durchlauf zwei verschiedene Elemente aus zwei unabhängigen Läufen. Frag einmal ab und behalte den Wert.

## Endlose Iteratoren

| Iterator | Liefert |
| --- | --- |
| `n.up!` | `n`, `n+1`, `n+2`, … für immer |
| `n.upto!(m)` | `n` … `m`, dann endet er |

Ein endloser Iterator muss mit etwas kombiniert werden, das endet, oder mit `break!` oder `until!`. Allein läuft er endlos.

`1.up!` mit einem Lauf über eine Sammlung zu kombinieren, ist die idiomatische Art, Elemente zu nummerieren, und es lohnt sich, das auf Anhieb zu erkennen.

## Warum das ein eigenes Konzept ist und nicht Teil eines anderen

Eine Schleife, die endet, sobald ihr *erster* Iterator nichts mehr liefert, ist die Regel, die am ehesten zu einem Programm führt, das unauffällig falsch statt offensichtlich kaputt ist: Es stürzt nicht ab, es hört einfach zu früh auf. Es in die Übung einzubauen, die Iteratoren einführt, oder in die, die sie schreiben lässt, würde bedeuten, ihm zu begegnen, während auch etwas anderes neu ist.
