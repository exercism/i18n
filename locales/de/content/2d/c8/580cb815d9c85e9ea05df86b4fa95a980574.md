# Über die Grundlagen

Kotlin ist eine statisch typisierte Sprache, die so entworfen wurde, dass sie vollständig mit Java interoperabel ist.

Was Kotlin von Java unterscheidet:

- hat eine sauberere, prägnantere Syntax;
- übernimmt viele Merkmale funktionaler Sprachen;
- bietet umfangreiche Unterstützung für Werte, die null sein können.

## Variablen

Weil Kotlin statisch typisiert ist, musst du den Typ jedes Werts zur Kompilierzeit _kennen_.

Allerdings ist Ktlins [Typinferenz][inference] sehr mächtig, sodass das _Angeben_ des Typs oft optional ist.

Es gibt zwei Möglichkeiten, eine Variable zu deklarieren.

1. `val` erstellt eine unveränderliche Variable, und der Versuch, sie zu ändern, führt zu einem Fehler zur Kompilierzeit.

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. `var` erstellt eine veränderliche Variable.

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

Weil unveränderliche Variablen eine ganze Klasse häufiger Fehler ausschließen, wird `val` nach Möglichkeit empfohlen.

Außerdem kann selbst ein `var` seinen Typ nicht ändern:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

Um visuelle Ablenkung zu verringern, werden explizite Typen in diesem Lehrplan meist weggelassen.
Dennoch ist es empfehlenswert, Typen zumindest für Folgendes anzugeben:

- öffentliche APIs
- Funktionssignaturen
- Stellen, die dokumentiert werden müssen

Manche Unternehmen und Organisationen verlangen strikte Typsicherheit und verbieten Typinferenz, während andere sie auf „einfache“ Typen beschränken oder voll auf Typinferenz setzen.

```kotlin
val x: Int = 42  // => 42
```

Im Allgemeinen sollten die Namen von Variablen und Funktionen in `camelCase` geschrieben werden, nicht in `snake_case`

## Funktionen

Eine Funktion deklarierst du mit dem Schlüsselwort `fun`.
Anders als in Java müssen Funktionen nicht Teil einer Klasse sein.

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

Ein paar Punkte, die du beachten solltest:

- Nach dem Funktionsnamen sind runde Klammern `()` nötig, auch wenn die Funktion keine Argumente entgegennimmt.
- Bei Funktionsargumenten muss der Typ angegeben werden: Es gibt keine Typinferenz (anders als bei Variablen).
- Der Funktionskörper wird in geschweifte Klammern `{ }` gesetzt (siehe aber unten).
- Das Schlüsselwort `return` ist erforderlich, wenn ein Wert zurückgegeben wird.
- Semikolons `;` am Zeilenende sind optional und werden meist weggelassen.
- Die Rechenoperatoren `+`, `-`, `*`, `/` ähneln denen der meisten gängigen Sprachen.

Für diese sehr einfachen Funktionen mit nur einem einzigen Ausdruck gibt es jedoch eine Kurzform:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
Funktionen können Parameter mit Standardwerten haben.
Diese Werte werden verwendet, wenn sie beim Aufruf der Funktion weggelassen werden:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

Funktionen bei Exercism geben normalerweise einen Wert zurück (weil der Test-Runner so aufgebaut ist).
Wenn du Kotlin auch außerhalb von Exercism nutzen willst, ist es nützlich zu wissen, dass eine Funktion ohne Rückgabewert den Rückgabetyp und das Schlüsselwort `return` weglassen kann.

Dann hat sie den Rückgabetyp `Unit`, was `void` in Java und einigen anderen Sprachen entspricht.

## Kommentare

Einzeilige Kommentare beginnen mit `//`, und der Rest der Zeile wird dann ignoriert.

Mehrzeilige Kommentare beginnen mit `/*` und enden mit `*/`

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

Das ist wie in Java.
