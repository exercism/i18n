# Einführung

## Null-Referenzen

Wenn du schon einmal eine andere Programmiersprache benutzt hast (C/C++, Python, Java, Ruby, Lisp usw.), ist dir wahrscheinlich schon einmal `null` oder `nil` begegnet.
Mit `null` oder `nil` zeigen diese Sprachen an, dass eine bestimmte Variable keinen Wert hat.
Dadurch passiert es allerdings leicht (und häufig), dass man versehentlich eine `null`-Variable verwendet.
Wie du dir vorstellen kannst, kann der Versuch, eine Funktion aufzurufen, die es gar nicht gibt, oder auf einen Wert zuzugreifen, den es nicht gibt, zu allerlei Bugs und Abstürzen führen.
Der Erfinder von `null` nannte es sogar seinen [„Milliarden-Dollar-Fehler“][billion-dollar-mistake].

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## Der Typ `Option`

Um diese Probleme zu vermeiden, können Cairo-Variablen das Enum `Option` verwenden, um das Fehlen eines Werts sicher darzustellen.
Dieses Enum hat zwei Varianten: `None`, das Äquivalent zu `null` in Cairo, und `Some(T)`, wobei `T` ein Wert eines beliebigen Typs ist.

Das sieht so aus:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

Du kannst dir `Option` als eine Sicherheitsschicht zwischen dir und den Problemen vorstellen, die Null-Referenzen verursachen können, während ihr konzeptioneller Nutzen erhalten bleibt.

## `Option` verwenden

Eine Variable auf `None` zu setzen, ist recht einfach:

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

Wenn du aber möchtest, dass der Typ `Option` einen Wert trägt, kannst du diesen Wert nicht direkt zuweisen.
Eine Variable vom Typ `Option` und zum Beispiel eine Variable vom Typ `i32` sind nicht gleichwertig.
Du musst `Some` verwenden:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

Aus demselben Grund funktioniert Folgendes nicht:

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

Um den Wert zu erhalten, den `Some` enthält, musst du zuerst prüfen, ob er vorhanden ist:

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

Cairo hat außer `match` noch andere Werkzeuge, um Werte in `Option` zu prüfen und auf sie zuzugreifen, aber `match` sollte dir inzwischen vertraut sein.

Betrachte das als Demonstration, warum Cairo `Option` anstelle einer Null-Referenz verwendet.
Der Punkt ist, dass du **_prüfen musst_**, ob die `Option`-Variable `Some` ist (in diesem Fall kannst du den enthaltenen Wert extrahieren und verwenden) oder `None`.
Sonst wird dein Programm nicht kompiliert; der Compiler schützt dich vor `null`.
