# Einführung

## RFLAGs

Es gibt ein spezielles Register namens `rflags`.
Seine Bits wirken wie Flags für verschiedene Bedingungen.

Einige davon sind unten aufgeführt:

| Name     | Symbol | Bit |
| :------- | :----: | :-: |
| Carry    |   CF   |  0  |
| Zero     |   ZF   |  6  |
| Sign     |   SF   |  7  |
| Overflow |   OF   | 11  |

## Vergleichsanweisungen

Die Flags in `rflags` werden _nicht_ direkt verändert.
Stattdessen werden sie von vielen verschiedenen Anweisungen gesetzt.

Zum Beispiel wird `ZF` von vielen arithmetischen oder bitweisen Operationen gesetzt, wenn das Ergebnis null ist.

Eine der häufigsten Anweisungen zum Testen von Bedingungen ist `cmp`.
Sie nimmt zwei Operanden und aktualisiert die Flags, **verändert ihre Operanden aber nicht**.

### Die CMP-Anweisung

Die `cmp`-Anweisung subtrahiert den zweiten Operanden vom ersten und setzt die Flags entsprechend dem Ergebnis.

Wenn A der erste Operand und B der zweite ist:

| Flag | gesetzt, wenn                       |
| :--: | :---------------------------------- |
|  CF  | A < B (vorzeichenlos)               |
|  ZF  | A == B                              |
|  SF  | A < B (mit Vorzeichen, kein Überlauf) |
|  OF  | Überlauf bei Subtraktion mit Vorzeichen |

## Verzweigungen

Standardmäßig wird Code in x86-64 sequenziell von oben nach unten ausgeführt.

Aber es gibt viele Situationen, in denen dieses Verhalten geändert werden muss.
Zum Beispiel, um als Reaktion auf eine Bedingung eine andere Gruppe von Anweisungen auszuführen.

In höheren Programmiersprachen geschieht das normalerweise mit Abstraktionen wie `if...else`-Konstrukten.
In x86-64 gibt es sie jedoch nicht.

Stattdessen bietet x86-64 Anweisungen, die die Ausführung effektiv an eine andere Stelle im Code übertragen.
Das nennt man `branching`.

~~~~exercism/note
Wir haben bereits zwei solche Anweisungen gesehen: `call` und `ret`.

Wenn eine Funktion aufgerufen wird, wird die Ausführung vom Aufrufer auf die aufgerufene Funktion übertragen.
Und bei der Rückkehr wird die Ausführung wieder auf den Aufrufer übertragen.

Wenn kein `ret` gefunden wird, fällt die Ausführung von einer Funktion in die nächste durch.
Das kann manchmal genutzt werden, um den Codefluss zu optimieren.
~~~~

### Unbedingter Sprung

Die Anweisung **jmp** überträgt die Ausführung des Programms bedingungslos an eine andere Stelle im Code.
Ihr einziger Operand ist ein Label, das die Adresse der Stelle enthält, an der die Ausführung fortgesetzt wird.

Betrachte zum Beispiel die folgende Funktion:

```x86asm
fn:
    mov rax, 5
    jmp end

    add rax, 10
end:
    ret
```

Wenn `fn` aufgerufen wird, beginnt die Ausführung bei `mov rax, 5`.
Damit wird der Wert in `rax` an dieser Stelle auf 5 gesetzt.

Die nächste Anweisung ist `jmp end`, die die Ausführung zum Label `end` überträgt.

Nach `end` ist die nächste Anweisung `ret`, die die Ausführung zurück zur aufrufenden Funktion überträgt.

Beachte, dass `add rax, 10` nie ausgeführt wird, weil es nach `jmp end` und vor `end` steht.
Der Wert von `rax` ist 5, wenn `fn` zurückkehrt.

### Bedingter Sprung

Die Anweisungsfamilie **jcc** überträgt die Ausführung des Programms nur dann an eine andere Stelle, wenn eine bestimmte Bedingung erfüllt ist.
Andernfalls läuft die Ausführung sequenziell weiter.

Jede Bedingung entspricht einem oder mehreren Flags in `rflags`.
Einige `jcc`-Varianten prüfen, ob ein Flag gesetzt ist, andere prüfen, ob es gelöscht ist.

Das `cc` in `jcc` ist nicht wörtlich gemeint, sondern verweist auf das jeweilige Suffix, das zu dem getesteten Flag gehört.

Es gibt viele Suffixe, und viele von ihnen prüfen dieselbe Bedingung wie ein anderes.
Einige davon verweisen direkt auf ein Flag, sodass die Anweisung zu einem Label springt, wenn das jeweilige Flag gesetzt ist:

| Suffix | springt, wenn |
| :----: | :-----------: |
|   z    |   ZF == 1     |
|   c    |   CF == 1     |
|   s    |   SF == 1     |
|   o    |   OF == 1     |

Viele andere sind so gewählt, dass sie sich auf ihre Bedeutung in einer `cmp`-Anweisung beziehen.
Zum Beispiel:

| Anweisung | Suffix | springt, wenn    |
| --------- | :----: | :--------------- |
| cmp A, B  |   e    | A == B           |
| cmp A, B  |   l    | A < B (mit Vorzeichen) |
| cmp A, B  |   b    | A < B (vorzeichenlos) |
| cmp A, B  |   g    | A > B (mit Vorzeichen) |
| cmp A, B  |   a    | A > B (vorzeichenlos) |

Man kann `e` nach `l`, `b`, `g` oder `a` hinzufügen, um die Gleichheit in die Bedingung einzubeziehen:

```x86asm
cmp rcx, r8
jge two      ; this jumps to 'two' if rcx is greater than, or equal to, r8 in a signed comparison
jbe two      ; this jumps to 'two' if rcx is lesser than, or equal to, r8 in an unsigned comparison
```

Für alle Suffixe gibt es Varianten, die das entgegengesetzte Verhalten prüfen.
Sie haben dieselbe Syntax, aber mit einem `n` vor dem Suffix.

Zum Beispiel springt `jnz`, wenn `ZF` **nicht** gesetzt ist.
Ähnlich springt `jnae`, wenn A **nicht** >= B ist (A und B als vorzeichenlose Ganzzahlen interpretiert).

~~~~exercism/note
Einige Suffixe sind Aliase für dieselben Bedingungen.
Zum Beispiel springen `jz` (Suffix `z`, für `ZF`) und `je` (Suffix `e`, für gleich) beide, wenn `ZF` gesetzt ist.
Das liegt daran, dass bei `cmp` `ZF` gesetzt wird, wenn die Subtraktion null ergibt, was bedeutet, dass die beiden Operanden gleich sind.

Andere Suffixe prüfen jedoch eine Kombination von Flags und können nicht direkt durch ein einzelnes Flag-Suffix ersetzt werden.

Bevorzuge das Suffix, das die Semantik deines Vergleichs besser beschreibt.
~~~~

## Lokale Labels

Labels sind in der gesamten Quelldatei sichtbar, sie sind nicht auf eine Funktion beschränkt.
Es ist also unmöglich, einen Labelnamen wiederzuverwenden.

Um das Verhalten eines lokalen Labels nachzuahmen, hat NASM eine spezielle Notation für ein Label, dem ein Punkt (`.`) vorangestellt ist.
Diese Notation definiert ein Label, das implizit den Namen des vorherigen Labels ohne Punkt enthält:

```x86asm
section .text
fn1:
    ...
.example: ; this is fn1.example
    ...
    ret

fn2:
    ...
.example: ; this is fn2.example
    ...
    ret
```

Es ist weiterhin möglich, von überall im Code zu diesem Label zu springen, indem man den vollständigen Labelnamen verwendet, zum Beispiel `jmp fn1.example`.

Ein Sprung, der nur den ab dem Punkt beginnenden Teil des Labels verwendet, führt jedoch zu dem Label _innerhalb_ der umgebenden Funktion.
Zum Beispiel verhält sich `.example`, als wäre es lokal für die Funktion:

```x86asm
section .text
fn1:
    ...
.example:
    ...
    jmp .example ; this jumps to fn1.example

fn2:
    ...
.example:
    ...
    jmp .example ; this jumps to fn2.example
```
