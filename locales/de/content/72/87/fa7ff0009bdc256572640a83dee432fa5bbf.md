# Einführung

## Endrekursion

Wenn du [rekursiv][exercism-recursion] durch Enumerables (Listen, Bitstrings, Strings) gehst, gibt es oft zwei Dinge zu bedenken:

- wie viel Speicher benötigt wird, um die Spur der rekursiven Funktionsaufrufe zu speichern
- wie du die Lösung effizient aufbaust

Um diese Punkte in den Griff zu bekommen, kannst du einen _Akkumulator_ verwenden.

Ein Akkumulator ist eine Variable, die zusätzlich zu den Daten übergeben wird. Damit gibst du den aktuellen Zustand der Ausführung der Funktion von einem Funktionsaufruf zum nächsten weiter, bis der _Basisfall_ erreicht ist. Im Basisfall wird mit dem Akkumulator der endgültige Wert des rekursiven Funktionsaufrufs zurückgegeben.

Den Akkumulator sollte der Autor der Funktion initialisieren, nicht ihr Nutzer. Dazu deklarierst du zwei Funktionen: eine öffentliche Funktion, die nur die nötigen Daten als Argumente entgegennimmt und den Akkumulator initialisiert, und eine private Funktion, die zusätzlich einen Akkumulator entgegennimmt. In Elixir ist es ein verbreitetes Muster, dem Namen der privaten Funktion `do_` voranzustellen.

```elixir
# Count the length of a list without an accumulator
def count([]), do: 0
def count([_head | tail]), do: 1 + count(tail)

# Count the length of a list with an accumulator
def count(list), do: do_count(list, 0)

defp do_count([], count), do: count
defp do_count([_head | tail], count), do: do_count(tail, count + 1)
```

Mit einem Akkumulator kannst du rekursive Funktionen in _endrekursive_ Funktionen umwandeln. Eine Funktion ist endrekursiv, wenn das _Letzte_, was die Funktion ausführt, ein Aufruf ihrer selbst ist.
