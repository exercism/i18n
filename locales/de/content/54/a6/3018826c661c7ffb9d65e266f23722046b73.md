# Einführung in die Arithmetik in der Bash-Shell

Bash kann rechnen, aber _nur mit Ganzzahlen_.
Wenn du Gleitkommazahlen brauchst, musst du ein externes Programm aufrufen (etwa [awk][awk] oder [bc][bc]).

Die arithmetischen Operatoren sind im Handbuch aufgelistet (nach Rangfolge): [Shell-Arithmetik][arithmetic].

Außerdem rechnet Bash nur an bestimmten Stellen, den sogenannten arithmetischen „Kontexten“.

## Arithmetische Expansion

Eine arithmetische Expansion sieht aus wie eine [Kommandosubstitution][cmd-sub], nur mit doppelten runden Klammern.

```bash
$(( expression ))
```

Diese Syntax expandiert zum Ergebnis der Auswertung des Ausdrucks.
Häufig wird sie verwendet, um das Ergebnis in einer Variable aufzufangen:

```bash
x=$(( 3 + 4 ))
```

~~~~exercism/note
Wie viel Leerraum du innerhalb der Klammern verwendest, bleibt dir überlassen.
Das ist eine Frage des Stils und der Lesbarkeit.

```bash
x=$(( 3 + 4 ))
y=$((5+6))
```

Dein freundlicher Autor setzt gern Leerzeichen, damit der arithmetische Ausdruck innerhalb der Klammern besser zu erkennen ist.
~~~~

## Arithmetische Bedingung

Die arithmetische Bedingung wird in doppelten runden Klammern _ohne_ das führende `$` ausgeführt:

```bash
(( expression ))
```

Sie expandiert nicht zum Ergebnis.
Sie erzeugt aber einen _Exit-Status_.

* Der Exit-Status ist 0 (Erfolg), wenn das Ergebnis des Ausdrucks **nicht null** ist.
* Der Exit-Status ist 1 (Fehler), wenn das Ergebnis des Ausdrucks **null** ist.

~~~~exercism/note
Innerhalb von `((` verwendet Bash dasselbe Verständnis von wahr/falsch wie die Sprache C: null ist falsch, nicht null ist wahr.
**Das ist genau umgekehrt zu der Art, wie Bash Exit-Status auswertet!**
~~~~

Diese Syntax wird typischerweise an zwei Stellen verwendet:

1. als COMMAND-Teil einer [`if`-Anweisung][conditional-if] oder einer [`while`-Schleife][looping-while].

   ```bash
   if (( x == y - 1 )); then ...
   while (( y > 0 )); do ...
   ```

1. als eigenständigen Befehl, um den Wert einer Variable zu ändern.

   ```bash
   (( x = x + 1 ))
   echo "new value for x is $x"
   ```

   ~~~~exercism/caution
   Sei vorsichtig, wenn du Arithmetik auf diese Weise mit `set -e` kombinierst.
   Wenn der Ausdruck zu null auswertet, ist der Exit-Status ungleich null und Bash beendet sich.

   ```bash
   x=0
   (( x++ ))
   echo "you will see this"

   set -e
   x=0
   (( x++ ))
   echo "shell exits on the previous line; you won't see this"
   ```

   Eine ausführlichere Diskussion über den `++`-Operator findest du in diesem Artikel zu [Postincrement vs Preincrement][incr]

   [incr]: https://thisvsthat.io/postincrement-vs-preincrement
   ~~~~


## Weitere Stellen mit arithmetischem Kontext

Es gibt noch einige weitere Stellen, die arithmetische Kontexte sind:

* Die [arithmetische for-Schleife][looping-for].

  ```bash
  for (( i = 0; i < 10; i++ )); do
      echo "$i"
  done
  ```

* Der Index-Teil eines numerisch indizierten Arrays.

  ```bash
  echo "The next element is ${array[x + 1]}"
  # ................................^^^^^
  ```

  Mehr über Arrays erfährst du im Konzeptdokument [Arrays][arrays].

* Die Offset- und Längen-Teile der Expansion `${var:offset:length}`.
* Den eingebauten Befehl [`let`][let].
  * Beachte, dass `(( expression ))` gegenüber `let "expresson"` bevorzugt wird.
    Anders als bei der arithmetischen Bedingung unterliegt der Ausdruck bei `let` der Dateinamenexpansion und der Worttrennung und muss in Anführungszeichen gesetzt werden.
* Die Variablenzuweisung, wenn die Variable das „Ganzzahl-Attribut“ hat.

  ```bash
  # variable x does not have the integer attribute
  x="3 + 4"
  declare -p x      # => declare -- x="3 + 4"

  # variable y has the integer attribute
  declare -i y
  y="4 + 5"
  declare -p y      # => declare -i y="9"
  ```

  ~~~~exercism/note
  Der Autor ist der Meinung, dass `declare -i` nur begrenzt nützlich ist.
  Sein Hauptvorteil ist, dass es „nackte“ Arithmetik erlaubt (ohne die Syntax der arithmetischen Ausdrücke).
  Das kann bei allen, die deinen Code lesen, für Verwirrung sorgen, weil arithmetische Ausdrücke dann an unerwarteten Stellen ausgewertet werden.
  ~~~~

## Variablen in arithmetischen Ausdrücken verwenden

Hier ist ein Aspekt arithmetischer Kontexte, der die Lesbarkeit verbessert.

```bash
height=10
width=20
area=$(( height * width ))
```

Ist dir aufgefallen, dass die `$`-Zeichen bei den Variablen im arithmetischen Ausdruck fehlen?
Bash erlaubt dir das.
Das macht Ausdrücke deutlich leichter lesbar.

Im Handbuch steht:

> Innerhalb eines Ausdrucks können Shell-Variablen auch mit ihrem Namen referenziert werden, ohne die Syntax der Parameterexpansion zu verwenden.

Das funktioniert sogar für Array-Elemente:

```bash
point1=(10 15)  # these are (x, y) coordinates
point2=(20 7)
distance_squared=$(( (point1[0] - point2[0])**2 + (point1[1] - point2[1])**2 ))
```

Andere Parameterausdrücke brauchen aber ihre spezielle Syntax.
Zum Beispiel die Verdopplung der Länge eines Strings:

```bash
s="hello world"
len=$(( ${#s} * 2 ))
```

Und Positionsparameter müssen das ebenfalls.
Wenn die ersten beiden Positionsparameter Breite und Höhe darstellen:

```bash
area=$(( $1 * $2 ))
```
