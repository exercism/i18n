# Einführung

Pumpen, Ventile, Schläuche: Alles, was eine Ressource des Betriebssystems hält (eine geöffnete Datei, eine Netzwerkverbindung), muss *freigegeben* werden, wenn du damit fertig bist. Das [`destructors`][destructors]-Vokabular von Factor verpackt sie in ein Framework, das das Aufräumen garantiert, selbst wenn ein Fehler deinen Code mittendrin unterbricht.

## Die Klasse und das generische Wort

Eine Klasse tritt dem Framework bei, indem sie `disposable` erweitert und das generische Wort `dispose*` implementiert:

```factor
USING: accessors destructors kernel ;

TUPLE: pump < disposable opened ;

: <pump> ( -- pump )
    pump new-disposable t >>opened ;

M: pump dispose* f >>opened drop ;
```

`new-disposable ( class -- obj )` legt das Tupel an *und* registriert es beim Framework. Auch eine Ausnahme zwischen der Allokation und dem nächsten sicheren Punkt führt nicht dazu, dass die Ressource verloren geht. Das Framework garantiert, dass `dispose*` **höchstens einmal** pro Objekt ausgeführt wird. Wiederholte Aufrufe von `dispose` sind No-Ops.

## Öffentliche Aufrufer verwenden `dispose`

```
dispose          ( obj -- )                ! release; safe to call twice
with-disposal    ( disposable quot -- )    ! scope one resource
with-destructors ( quot -- )               ! open a registry scope
&dispose         ( obj -- obj )            ! dispose on normal *or* failure exit
|dispose         ( obj -- obj )            ! dispose only if the scope unwinds
```

`with-disposal` ist die Form für eine einzelne Ressource: Es legt das Disposable für die innere Quotation auf den Stack und gibt es beim Verlassen wieder frei.

```factor
USING: destructors io ;

<pump> [
    "pumping" print
] with-disposal
! pump released on the way out — even if `print` had thrown
```

Bei mehr als einer Ressource öffnest du einen `with-destructors`-Gültigkeitsbereich und registrierst jede Beschaffung. `&dispose` (Ampersand) bedeutet „beim Verlassen immer freigeben, bei Erfolg wie bei Fehlschlag“. `|dispose` (Pipe) bedeutet „**nur** bei Fehlschlag freigeben“, nützlich, wenn der Erfolgspfad die Ressource an einen Aufrufer übergibt, der die Verantwortung übernimmt.

```factor
[
    <pump> &dispose
    <pump> &dispose
    ! ... use the pumps ...
] with-destructors
! both pumps released
```

Für ein nacktes try/finally ohne Registry ist [`cleanup`][cleanup] (in `continuations`) die tiefer liegende Primitive, aber `with-destructors` ist das idiomatische moderne Factor.
