# Gebundene Routinen

Bisher haben wir überall *Werte* weitergegeben: Zahlen, Strings, Objekte. Eine **gebundene Routine** lässt dich eine Routine selbst weitergeben: etwas, das später aufgerufen wird, von Code, der nicht weiß, was sie ist.

Eine Zweitbesetzung ist genau diese Idee: Der Inspizient hält eine Möglichkeit in der Hand, die Rolle zu spielen, ohne zu wissen, wer es ist oder was er tun wird.

## So erstellst du eine

`bind` nimmt einen Aufruf mit Lücken entgegen, die mit `_` geschrieben werden:

```sather
   shout(line : STR) : STR is return line.upper; end;

   ...

   part ::= bind(shout(_));
```

`part` ist jetzt ein Wert wie jeder andere. Aufgerufen wird es später:

```sather
   part.call("who's there")      -- "WHO'S THERE"
```

## Der Typ

Der Typ einer gebundenen Routine ist `ROUT`, mit den Argumenttypen in geschweiften Klammern und dem Rückgabetyp nach einem Doppelpunkt:

```sather
   part : ROUT{STR}:STR := bind(shout(_));
```

Lies `ROUT{STR}:STR` als „eine Routine, die einen `STR` entgegennimmt und einen `STR` zurückgibt“.

| Geschrieben | Bedeutung |
| --- | --- |
| `ROUT{STR}:STR` | nimmt einen `STR`, gibt einen `STR` zurück |
| `ROUT{INT,INT}:BOOL` | nimmt zwei `INT`s, gibt einen `BOOL` zurück |
| `ROUT{STR}` | nimmt einen `STR`, gibt nichts zurück |
| `ROUT:INT` | nimmt nichts, gibt einen `INT` zurück |

Da es ein Typ ist, kann es ein Argument sein:

```sather
   rehearse(line : STR, part : ROUT{STR}:STR) : STR is
      return part.call(line);
   end;
```

`rehearse` hat keine Ahnung, was `part` tut. Genau darum geht es: Man kann ihm `shout` übergeben, oder `whisper`, oder irgendetwas anderes von dieser Form.

## Einige der Argumente vorbelegen

Nicht jedes Argument muss eine Lücke sein. Was ausgeschrieben ist, wird beim Binden festgelegt:

```sather
   repeat(times : INT, line : STR) : STR is ... end;

   twice ::= bind(repeat(2, _));      -- ROUT{STR}:STR
```

`twice` nimmt nur die Zeile entgegen, weil die `2` schon feststeht. Der Wert wird im Moment des Bindens ermittelt und behalten, es macht also keinen Unterschied, die Variable, aus der er stammt, danach zu ändern.

So wird aus einer allgemeinen Routine viele spezielle.

## Auch das Objekt binden

Bei einer Routine auf einem Objekt ist das Objekt das Erste im Aufruf und kann festgelegt oder als Lücke gelassen werden:

```sather
   bind(board.home_goal)      -- this board's, always
   bind(_.home_goal)          -- whichever board is handed in later
```
