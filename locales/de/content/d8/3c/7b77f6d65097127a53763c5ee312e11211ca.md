# Einführung

## Kommentare

In Common Lisp kannst du „Kommentare“ schreiben, die vom Computer ignoriert werden. Einzeilige Kommentare beginnen mit einem oder mehreren Semikolons (`;`), und gelegentlich siehst du Folgendes:

```lisp
(code...) ; => value
```

Dabei wird der Kommentar verwendet, um anzugeben, welchen Wert Common Lisp nach der Ausführung des Codes in dieser Zeile zurückgibt.

Es ist idiomatisch, ein einzelnes Semikolon für einen kurzen Kommentar am Ende einer Zeile zu verwenden, zwei für einen längeren Kommentar über einem Codeabschnitt, drei für einen langen Kommentar, der etwas wie eine Funktion beschreibt, und vier für einen Kommentar wie einen Header am Anfang einer Quelldatei.

## Cons

Alle Objekte in Common Lisp sind entweder „Atome“ (einzelne, unteilbare Werte) oder „Conses“ (die von der Konstruktorfunktion „cons“ erzeugt werden).
Ein Cons besteht aus zwei Teilen: dem ersten Element und dem Rest der Elemente.
Aus historischen Gründen heißen diese beiden Teile `car` und `cdr`.
Wenn diese Conses als Code ausgewertet werden, repräsentiert das erste Element (`car`) die aufgerufene Funktion, während der Rest der Elemente
(`cdr`) die Argumente für diese Funktion darstellen:

```lisp
(<function> <arg1> <arg2> ... <argN>)
; ^ car ^  |        ^ cdr ^
```

## Ausdrücke

Der gesamte Common-Lisp-Code besteht aus S-Ausdrücken (symbolischen Ausdrücken). Kurz nennt man sie Sexprs. Jeder Sexpr ist entweder ein Atom oder ein Cons. Wenn S-Ausdrücke ausgewertet werden, geben sie automatisch einen Wert zurück, der den Platz des Ausdrucks einnimmt. Wenn du deine eigenen Funktionen schreibst (mit `defun`), wird der letzte Wert innerhalb des Rumpfes der `defun` automatisch zurückgegeben:

```lisp
;; Defining a new function
(defun gimme-foo () 'foo)
;; Calling the function as an S-Expression
(gimme-foo) ; => FOO
```

## Symbole

Symbole in Common Lisp sind besondere Werte, die auf andere Werte zeigen können oder, im Fall von _Keywords_, auf sich selbst.
Wenn Symbole von Lisp ausgewertet werden, werden sie durch die Werte ersetzt, auf die sie zeigen:

```lisp
foo  ; => <whatever-foo-points-to>
:foo ; => :FOO
```

Beachte, dass Keywords durch einen führenden Doppelpunkt (`:`) gekennzeichnet werden.

Quoting, also das Setzen eines `'` vor einen S-Ausdruck, weist Lisp an, diesen Ausdruck nicht auszuwerten.
Indem wir `'foo` in unserem `defun`-Beispiel quotiert haben, haben wir verhindert, dass Lisp versucht, den Wert nachzuschlagen, auf den `FOO` zeigen sollte (und ihn nicht findet). Stattdessen wurde der Wert `FOO` selbst zurückgegeben.
Wenn `FOO` nirgendwo in unserem Programm definiert wurde:

```lisp
foo  ; => <ERROR! Lisp doesn't know what foo points to!>
'foo ; => FOO
```

Vorerst kannst du das einfach als eine Möglichkeit betrachten, Symbole aus einer Funktion zurückzugeben, aber wir werden auf Quoting zurückkommen und seine Auswirkungen in zukünftigen Konzeptübungen weiter erkunden.
