# Über

Elm ist eine wunderbare Sprache, um zuverlässige Webanwendungen zu bauen.
Sie hat freundliche Fehlermeldungen, eine großartige Performance, kleine Assets und keine Laufzeitausnahmen.

Der wohl bekannteste und meistkopierte Teil von Elm ist The Elm Architecture: ein einfaches Muster, um Webanwendungen zu strukturieren. Alle Elm-Webanwendungen sind so aufgebaut.

Die Kernidee ist, dass sich dein Code um ein `Model` deines Anwendungszustands dreht, um eine `update`-Funktion für dein Modell und um eine `view`-Funktion, die dein Modell anzeigt.

Das `Model` enthält den Zustand der Anwendung: alle Daten, die die Anwendung braucht.
Stell dir eine einfache Anwendung mit einem Textfeld vor, in der ein Text das Umgekehrte dieses Textes anzeigt. Dann sieht das Modell so aus:
Dieses Beispiel findest du auch im [Elm Guide][elm-guide-text-fields].

```elm
type alias Model =
  { text : String
  }
```

`update` ist eine Funktion, die bei jeder Änderung eine `Msg` erhält (zum Beispiel, wenn der Nutzer auf einen Button klickt).
Sie nimmt die `Msg` und das aktuelle `Model` entgegen und gibt ein neues `Model` zurück.

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

`view` ist eine Funktion, die HTML zurückgibt, um es dem Nutzer im Browser anzuzeigen.
Sie nimmt das aktuelle `Model` und gibt ein `Html Msg` zurück (der Typ, mit dem Elm HTML darstellt).

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```
