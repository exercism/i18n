# Einführung

Eine *Deque* (double-ended queue) unterstützt Push und Pop an beiden
Enden in O(1). Die Standardimplementierung in Factor ist `<dlist>` (eine
doppelt verkettete Liste) in [`dlists`][dlists]; die Operationen liegen
in [`deques`][deques].

## Die Deque-API

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` leert die Deque an Ort und Stelle, praktisch für die
Wiederverwendung ohne Neuallokation.

Push und Pop am selben Ende ergeben einen LIFO-Stack. Push am einen
Ende und Pop am anderen ergeben eine FIFO-Warteschlange:

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

Für LIFO greifst du zu einem Vektor (`V{ }`) mit `push`/`pop`,
der weniger Overhead pro Operation hat. Zu `<dlist>` greifst du, wenn
du O(1) an *beiden* Enden brauchst, fast immer also für eine
FIFO-Warteschlange.

## Breitensuche

Die FIFO-Nutzung macht Deques zur richtigen Frontier für die *BFS*.
Du startest mit einem einzelnen Knoten, schiebst Nachbarn nach hinten,
holst Kandidaten von vorne und entfernst Duplikate mit einem `hash-set`:

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

Ältere Kandidaten werden vor neueren besucht. So schreitet die Suche
in Schichten vom Startpunkt nach außen voran. Das verleiht der BFS
ihre Kurzeste-Wege-Eigenschaft: Wenn du einen Zielknoten zum ersten
Mal erreichst, dann über einen Pfad mit der minimalen Anzahl an
Schritten.

## `MEMO:`: automatisches Zwischenspeichern

Manchmal ist der Lookup pro Knoten, den die BFS aufruft, teuer. Das
[`memoize`][memoize]-Vokabular in Factor liefert dir `MEMO:`, einen
direkten Ersatz für `:`, der das Ergebnis des Wortes mit seinen
Eingaben als Schlüssel zwischenspeichert:

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

Ein `MEMO:`-Wort führt seinen Rumpf beim ersten Auftreten jeder
Eingabe aus und liefert danach das zwischengespeicherte Ergebnis
zurück: gleiche Schnittstelle, keine zusätzlichen Aufrufe an der
Aufrufstelle, nur schneller bei Wiederholungen.
