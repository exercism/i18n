# Einführung

Reguläre Ausdrücke sind eine äußerst vielseitige Möglichkeit, Strings per _Musterabgleich_ abzugleichen, und nutzen dafür eine eigens entwickelte domänenspezifische Sprache (DSL).

Viele Regex-Funktionen sind bereits in Base R enthalten, und in älterem Code findest du vielleicht Beispiele dafür.

Für neuen Code wird _dringend_ empfohlen, die Bibliothek [`stringr`][web-stringr] zu verwenden.

Wie im [Strings-Konzept][concept-strings] erwähnt, hat `stringr` eine gute Dokumentation, die meist von den Autorinnen und Autoren des Pakets selbst geschrieben wurde.

- Eine [Referenz-Website][web-stringr]
- Ein [Spickzettel][cheat-stringr].
- Ein [Strings-Kapitel][book-strings] und ein [Regex-Kapitel][book-regex] in „R for Data Science“.

Viele der Funktionen, die wir im [`Strings`][concept-strings]-Konzept bereits besprochen haben, sind standardmäßig für Regex-Suchen ausgelegt.

Wir haben das Strings-Konzept bewusst einfach gehalten und nur auf String-Literale abgeglichen, aber du kannst stattdessen jedes beliebige Regex-Muster verwenden.

Formal wird ein Regex in R durch den Aufruf von [`regex()`][ref-regex] erzeugt.
Der Einfachheit halber behandeln die Funktionen von `stringr` jeden String, der als Muster übergeben wird, als Regex.
Im folgenden Beispiel ist der erste Aufruf von `str_replace_all()` nur syntaktischer Zucker für die zweite Variante:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

Der [Spickzettel][cheat-stringr] ist ein nützlicher Leitfaden: Alle Funktionen mit einem `pattern`-Argument (rot gedruckt) akzeptieren einen Regex, und auf Seite 2 ist die Regex-Syntax zusammengefasst.

Beachte, dass die Funktion [`regex()`][ref-regex] trotzdem wichtig sein kann, wenn du die Standardeinstellungen überschreiben musst, etwa die Beachtung der Groß- und Kleinschreibung oder das Locale.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

Viele Regex-Codes enthalten einen Backslash, wie das oben verwendete `\s`.
In normalen R-Strings muss `\` durch Verdoppeln escaped werden, daher `"\\s"`.

Backslashes können sich häufen und unübersichtlich werden, deshalb kann es helfen, in komplexen Fällen [Raw Strings][book-raw] zu verwenden.

Standardmäßig lautet die Syntax zum Definieren eines Raw Strings `r"( )"`, aber andere Begrenzungszeichen sind erlaubt.
Da runde Klammern `( )` und eckige Klammern `[ ]` in der Regex-Syntax beide häufig vorkommen (für Capture-Gruppen und Optionsgruppen), sind geschweifte Klammern `{ }` vielleicht eine gute Wahl.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## Übereinstimmungen erkennen

Hier sind ein paar Fragen und die Funktionen, die dir helfen können, sie zu beantworten.

Einige Beispiele verwenden `fruit`, einen Vektor mit 80 Fruchtnamen, der in `stringr` zum Üben enthalten ist.

_Enthält ein String eine Übereinstimmung?_
`str_detect()`, oder `str_starts()` und `str_ends()`, um die Anker `^` oder `$` zu vermeiden.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_Nur Strings zurückgeben, die eine Übereinstimmung enthalten?_
Verwende `str_subset()`, um die Strings zu erhalten, und `str_which()`, um die Indizes zu erhalten.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_Wie viele Übereinstimmungen gibt es in jedem String?_
Verwende `str_count()`.

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_Wo ist die Übereinstimmung?_
`str_view()` für die interaktive Verwendung, `str_locate()` oder `str_locate_all()` für den allgemeinen Gebrauch.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## Capture-Gruppen

Häufig wollen wir wissen, _was_ übereinstimmt.
Das erreichen wir, indem wir Capture-Gruppen in runde Klammern im Regex aufnehmen.

Es ist möglich, innerhalb desselben Regex mit `\1`, `\2` usw. auf Captures zurückzuverweisen.
Zum Beispiel das Finden wiederholter Buchstabenpaare:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

Mit ähnlicher Syntax lassen sich Captures in Ersatz-Strings verwenden:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

Sammle Übereinstimmungen für die spätere Verarbeitung mit der Funktion `str_match()` für nur die erste Übereinstimmung oder `str_match_all()` für alle Übereinstimmungen.

Capture-Gruppen erzeugen in jeder Sprache tendenziell komplizierte Ausgaben.
Der R-Ansatz (_der als zusätzliche Herausforderung auch vektorisiert ist_) besteht darin, aus `str_match()` eine Matrix zu erzeugen, mit einer Zeile pro Eingabe-String, wobei Spalte 1 den vollständig übereinstimmenden String enthält und die übrigen Spalten die verschiedenen Capture-Gruppen.

Benannte Gruppen können von Vorteil sein, da sie zu Spaltennamen in der Ergebnismatrix werden.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

In diesem Lehrplan haben wir nicht viel über Matrizen gesagt, obwohl es ein [Konzeptdokument][concept-matrices-arrays] gibt, das du dir ansehen kannst.
Matrizen passen nicht gut zum Tidyverse-Ökosystem, obwohl sie seit Langem Teil von Base R sind.

Kurz zusammengefasst: Behandle Matrizen wie Vektoren mit 2 Indizes, in der Reihenfolge `[rows, cols]`.
Lass einen der beiden Indizes leer, um die ganze Zeile bzw. Spalte zu erhalten.

Wenn du mit `m[r,]` eine einzelne Zeile `r` oder mit `m[,c]` eine einzelne Spalte `c` abrufst, wird der zurückgegebene Wert standardmäßig zu einem Vektor abgeflacht.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

Unweigerlich erzeugt `str_match_all()` eine Ausgabe mit noch mehr Struktur:

- Das Ergebnis ist eine Liste mit einem Element pro Eingabe-String.
- Wenn es nur einen Eingabe-String gibt, hole die Ausgabe mit der Indizierung `[[1]]` aus der Liste, wie im [Listen-Konzept][concept-lists] beschrieben.
- Jedes Element ist eine Matrix, mit Spalten wie bei `match()`.
- Jede Zeile in der Matrix ist eine erfolgreiche Übereinstimmung.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

Natürlich können Übereinstimmungen fehlschlagen.
Das Ergebnis ist dann der spezielle Wert `NA`.
Sei darauf vorbereitet, das zu testen, wie im [Nichts-Konzept][concept-nothingness] beschrieben.

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
