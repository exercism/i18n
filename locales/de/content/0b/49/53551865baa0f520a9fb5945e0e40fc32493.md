# Einführung

Ein *Signalgeber* an Bord eines Küstenpatrouillenboots führt das Nachrichtenprotokoll. Rohsignalfahnen kommen mit Markierungszeichen umrahmt an; Messwerte müssen für die Übertragung aufbereitet werden; Paare und Tripel von Beobachtungen werden spontan zusammengefasst. Ein paar Idiome aus Factors Standardbibliothek erledigen den Großteil der Arbeit.

## `unparse` – Wert zu Quelltext

[`unparse`][unparse] (in `prettyprint`) gibt den Quelltext eines beliebigen Werts zurück:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` ist die Umkehrung des Parsers; der Roundtrip `dup unparse parse` rekonstruiert den Wert. Er ist das richtige Werkzeug, um in ein Übertragungsformat zu serialisieren, das der Empfänger wieder parst, und das falsche Werkzeug für menschenlesbare Ausgabe (Strings behalten ihre Anführungszeichen, Vektoren behalten ihr `V{ ... }` usw.).

## Slice-Varianten – Ansichten, keine Kopien

`head` und `tail` aus `sequences` *kopieren* den Teil, den du behältst, in eine neue Sequenz. Ihre `-slice`-Gegenstücke geben ein `slice`-Objekt zurück: ein Tupel aus Von-Index, Bis-Index und der zugrunde liegenden Sequenz, das das [Sequenzprotokoll][sequence-protocol] ohne Kopieren implementiert:

| Wort          | Wirkung                                          |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )` – kopiert die ersten n           |
| `head-slice`  | `( seq n -- slice )` – Ansicht der ersten n           |
| `tail`        | `( seq n -- newseq )` – kopiert ab Index n             |
| `tail-slice`  | `( seq n -- slice )` – Ansicht ab Index n              |
| `head*`       | `( seq n -- newseq )` – kopiert alle bis auf die letzten n |
| `head-slice*` | `( seq n -- slice )` – Ansicht aller bis auf die letzten n |
| `tail*`       | `( seq n -- newseq )` – kopiert die letzten n          |
| `tail-slice*` | `( seq n -- slice )` – Ansicht der letzten n           |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

Ein `slice` *ist* eine Sequenz, also nimmt alles, was eine Sequenz nimmt, auch einen Slice – `length`, `first`, `each` und so weiter funktionieren alle ohne Kopieren. Tests, die gegen einen Literal-String vergleichen müssen, können mit `>string` umwandeln.

## `?head` und `?tail` – Markierung entfernen, falls vorhanden

Eingerahmte Messwerte tragen Markierungstext, der vorhanden sein kann oder nicht. `?head` und `?tail` (in `splitting`) versuchen, ein Präfix oder Suffix zu entfernen, und geben die (möglicherweise verkürzte) Sequenz *und* einen booleschen Wert zurück, der meldet, ob die Markierung gefunden wurde:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

Der nachgestellte boolesche Wert macht sie zu einem natürlichen Kandidaten für eine Wächterbedingung: Kombiniere `?head` mit `if`, um danach zu verzweigen, ob der Rahmen vorhanden war, oder mit `unless`, um Eingaben abzulehnen, denen die erwartete Markierung fehlt.

## `<repetition>` – N Kopien, virtuell

[`<repetition>`][repetition] (in `sequences`) ist eine weitere nicht kopierende virtuelle Sequenz – `( len elt -- repetition )` erzeugt eine Sequenz aus `len` Elementen, die alle `elt` sind, ohne so viele Slots zuzuweisen:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

Das `elt` kann selbst eine Sequenz sein – jede Kopie ist dieselbe Sequenz. `concat` fügt dann die Kopien aneinander:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

Wie ein `slice` *ist* das Ergebnis eine Sequenz – `length`, `each` und Freunde arbeiten direkt darauf. Greif darauf zurück, um einen Signalcode auf eine feste Breite aufzufüllen oder eine Folge wiederholter Markierungen anzulegen; wandle nur dann mit `>string` (oder `>array`) um, wenn tatsächlich eine konkrete Sequenz benötigt wird.

## `<clumps>` – überlappende Fenster, virtuell

[`<clumps>`][clumps] (in `grouping`) ist eine dritte nicht kopierende virtuelle Sequenz – `( seq n -- clumps )` betrachtet `seq` als die Reihe *überlappender* Fenster der Länge `n` darüber, wobei jedes Fenster ein Slice ist:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

Eine Sequenz der Länge n ergibt `length - n + 1` Fenster. Weil jedes Fenster ein Slice ist, erfordert das Paaren aufeinanderfolgender Messwerte kein Kopieren – `[ first2 ]` auf jedem 2-Clump gibt dir jedes aufeinanderfolgende Paar, aus dem du projizieren kannst. (Der nicht überlappende Vetter, `<groups>`, zerhackt die Sequenz stattdessen in disjunkte Blöcke.)

## Multi-Input-Cleave – `2bi`, `3bi`, `2tri`, `3tri`

Die einfachen Cleave-Wörter `bi` und `tri` wenden zwei oder drei Quotations auf *einen* Eingabewert an. Die Varianten mit Präfix `2` und `3` wenden jede Quotation auf *zwei* oder *drei* Eingabewerte an:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

Jede Quotation erhält *alle* Eingabewerte. Verwende diese, wenn mehr als eine Projektion von demselben Paar (oder Tripel) von Werten abhängt – nicht, wenn du die *gleiche* Operation auf jeden Eingabewert separat anwenden möchtest (das ist `bi@` oder `tri@`).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
