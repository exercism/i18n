# Einführung

Das Konzept der Bedingungen stellt `jcc` vor, die Familie der Befehle zum Verzweigen anhand einer Bedingung.
Ein `jcc` überträgt die Ausführung nur dann an eine andere Stelle im Programm, wenn seine Bedingung erfüllt ist.

Moderne CPUs sind jedoch schnell und können viele Befehle parallel ausführen.
Es wäre zu teuer, alle Arbeit anzuhalten, während die CPU auf eine Laufzeitprüfung einer Bedingung wartet.

Deshalb wartet die CPU intern nicht.
Sie nutzt eine **Sprungvorhersage**, um das Ergebnis einer Bedingung zu erraten, und beginnt, den vorhergesagten Pfad _spekulativ_ auszuführen.

Ist die Vorhersage korrekt, läuft die Ausführung weiter, als gäbe es keine Verzweigung.
Ist die Vorhersage jedoch falsch, muss die CPU die auf dem vorhergesagten Pfad _geleistete Arbeit verwerfen_ und auf dem korrekten Pfad neu starten.

Das nennt man eine **Fehlvorhersage**, und sie ist teuer, denn sie verursacht eine Verzögerung.

Wenn eine Verzweigung schwer vorherzusagen ist, summieren sich diese Fehlvorhersagen.
In solchen Fällen ist es manchmal besser, die Verzweigung ganz zu vermeiden, sodass unabhängig von der Bedingung dieselben Befehle ausgeführt werden.
Code, der ohne `jcc` zwischen Werten auswählt, nennt man **zweigfrei**.

Es gibt mehrere Möglichkeiten, Code so zu strukturieren, dass er seltener verzweigt oder dass die vorhandenen Verzweigungen besser vorhersagbar sind.
Insbesondere stellt x86-64 zwei Befehlsfamilien bereit, die häufig zum Schreiben zweigfreien Codes verwendet werden.

## Bedingte Moves

Die Befehlsfamilie `cmovcc` kopiert den Quelloperanden nur dann in das Ziel, wenn eine bestimmte Bedingung erfüllt ist.
Andernfalls bleibt das Ziel unverändert.

Das `cc`-Suffix folgt derselben Namensgebung wie bei `jcc`, mit derselben Bedeutung:

| Befehl  | Move, wenn                                  |
|-------------|--------------------------------------|
| `cmove`     | A == B nach `cmp A, B`              |
| `cmovne`    | A != B nach `cmp A, B`              |
| `cmovl`     | A < B (vorzeichenbehaftet) nach `cmp A, B`      |
| `cmovb`     | A < B (vorzeichenlos) nach `cmp A, B`    |
| `cmovg`     | A > B (vorzeichenbehaftet) nach `cmp A, B`    |
| `cmova`     | A > B (vorzeichenlos) nach `cmp A, B`    |

Die Regeln ähneln denen von `jcc`:

1. `l` und `g` werden für vorzeichenbehaftete Vergleiche verwendet, `b` und `a` für vorzeichenlose.
2. Das Anhängen von `e` an ein Suffix schließt Gleichheit ein.
3. Das Anhängen von `n` negiert die Bedingung.
4. Es gibt auch Varianten, die sich auf ein gesetztes Flag beziehen.
   Zum Beispiel `cmovz` und `cmovc`.

Betrachte den Absolutwert einer vorzeichenbehafteten Ganzzahl in `rdi`, der in `rax` zurückgegeben wird.
Mit `jcc` geschrieben, wählt die Funktion einen von zwei Pfaden:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Mit `cmovcc` geschrieben, werden beide Kandidatenwerte bedingungslos berechnet, und der bedingte Move wählt einen davon aus:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

Die zweigfreie Version führt immer dieselben Befehle aus.
Es gibt kein `jcc`, das die Sprungvorhersage erraten könnte.

Das Ziel eines `cmovcc` muss ein Register sein.
Die Quelle kann ein Register oder eine Speicherstelle sein, aber kein Immediate.

~~~~exercism/note
Im obigen Code setzt der `neg`-Befehl mehrere Flags entsprechend dem Ergebnis, darunter das Vorzeichen-Flag (SF).
Das bedeutet, dass `cmp rdi, 0` vollständig weggelassen werden kann:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Für positives `rdi` erzeugt `neg` ein negatives Ergebnis und SF == 1, sodass `cmovs` `rdi` wiederherstellt.
Für null oder negatives `rdi` erzeugt `neg` ein nicht-negatives Ergebnis und SF == 0, sodass `rax` den negierten Wert behält (der den korrekten Absolutwert darstellt).

Obwohl `cmp` der wichtigste Weg ist, Werte in Assembler-Code zu vergleichen, setzen viele Befehle auch Flags entsprechend ihrem Ergebnis.
Die vollständige Liste der Flags, die ein Befehl beeinflusst, ist normalerweise in seiner [Referenz][reference] aufgeführt.
Für `neg` sind das konkret SF, ZF, CF, OF und PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

## Bedingtes Setzen

Die Befehlsfamilie `setcc` setzt den Zieloperanden auf `1`, wenn eine bestimmte Bedingung erfüllt ist, andernfalls auf `0`.
Das Ziel ist immer ein _8-Bit-Operand_.

Das `cc`-Suffix folgt derselben Namensgebung wie bei `jcc` und `cmovcc`.
Zum Beispiel setzt `setz` das Ziel auf `1`, wenn `ZF == 1`, andernfalls auf `0`.

Da das Ziel 8 Bit breit ist, folgt auf `setcc` häufig ein `movzx`, wenn ein breiterer Wert benötigt wird:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Dies ist ein gängiges Idiom, um ein Vergleichsergebnis in die Ganzzahl `0` oder `1` umzuwandeln.
