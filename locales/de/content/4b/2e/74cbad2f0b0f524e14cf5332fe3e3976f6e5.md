# Überblick

Ein `generator` ist eine Funktion oder ein Ausdruck, der eine spezielle Art von [Iterator][iterator] zurückgibt, die [Generator-Iterator][generator-iterator] genannt wird.
`Generator-iterators` sind [lazy][lazy iterator]: Sie speichern ihre `values` nicht im Arbeitsspeicher, sondern _erzeugen_ ihre Werte, wenn sie gebraucht werden.

Eine Generator-Funktion sieht aus wie jede andere Funktion, enthält aber einen oder mehrere [yield-Ausdrücke][yield expression].
Jedes `yield` unterbricht die Codeausführung und speichert den aktuellen Ausführungszustand (_einschließlich aller lokalen Variablen und try-Anweisungen_).
Wenn der Generator fortgesetzt wird, nimmt er den Zustand von der Unterbrechung wieder auf, anders als reguläre Funktionen, die bei jedem Aufruf zurückgesetzt werden.


## Einen Generator erstellen

Generatoren werden ähnlich aufgebaut wie andere Schleifen- oder rekursive Funktionen, benötigen aber einen [`yield`-Ausdruck](#the-yield-expression), den wir uns später noch genauer ansehen.

Ein Beispiel ist eine Funktion, die die _Quadrate_ aus einer gegebenen Liste von Zahlen zurückgibt.  
So wie sie jetzt geschrieben ist, muss die gesamte Eingabe verarbeitet werden, bevor Werte zurückgegeben werden können:

```python
>>> def squares(list_of_numbers):
...     squares = []
...     for number in list_of_numbers:
...         squares.append(number ** 2)
...     return squares
```

Du kannst diese Funktion so in einen Generator umwandeln:

```python
>>> def squares_generator(list_of_numbers):
...     for number in list_of_numbers:
...         yield number ** 2
```

Der Grund dafür ist, dass du einen Generator verwendest, wenn du nicht alle Werte _auf einmal_ brauchst.

Das spart Arbeitsspeicher und Rechenleistung, da nur der Wert berechnet wird, an dem du _gerade arbeitest_.


## Einen Generator verwenden

Generatoren (_technisch gesehen [`generator-iterator`s][generator-iterator], siehe den Hinweis unten_) sind ein Typ von `iterator` und können überall in Python verwendet werden, wo ein `iterator` oder `iterable` erwartet wird.
Dazu gehören _Funktionen_ oder _Objekte_, die ein `iterable`/`iterator` als Argument benötigen.
Für einen tieferen Einblick siehe [How to Make an Iterator in Python][how-to-iterator].


~~~~exercism/note

Generator-iteratoren sind eine spezielle Teilmenge von [Iteratoren][iterator].
`Iterators` sind der Mechanismus bzw. das Protokoll, das das Durchlaufen von _Iterables_ ermöglicht.
Generator-iteratoren und die Iteratoren, die gängige Python-[`iterables`][iterables] zurückgeben, verhalten sich sehr ähnlich, aber es gibt einige wichtige Unterschiede, die du beachten solltest:

- Sie werden _[lazy ausgewertet][lazy evaluation]_; die Iteration ist _einseitig_ und es gibt kein „Zurückspringen“ zu einem vorherigen Wert.
- Sie werden _verbraucht_, wenn man über die zurückgegebenen Werte iteriert; es gibt kein Zurücksetzen und kein Speichern im Arbeitsspeicher.
- Sie sind nicht sortierbar und können nicht umgekehrt werden.
- Sie sind keine Sequenztypen und haben _keine_ `indexes`. 
  Du kannst nicht per Addition oder Subtraktion auf einen vorherigen oder zukünftigen Wert verweisen, und du kannst weder die Klammernotation (`[]`) noch Slicing verwenden.
- Sie können nicht mit der Funktion `len()` verwendet werden, da sie keine Länge haben.
- Sie können _endlich_ oder _unendlich_ sein. Sei vorsichtig, wenn du alle Werte aus einem _unendlichen_ `generator-iterator` sammelst!

[iterator]: https://docs.python.org/3.11/glossary.html#term-iterator
[iterables]: https://wiki.python.org/moin/Iterator
[lazy evaluation]: https://en.wikipedia.org/wiki/Lazy_evaluation
~~~~


So verwendest du den Generator `squares_generator()`:

```python
>>> squared_numbers = squares_generator([1, 2, 3, 4])

>>> for square in squared_numbers:
...     print(square)
...
1
4
9
16
```

Werte innerhalb eines Generators können auch über die Funktion `next()` erzeugt bzw. abgerufen werden.
`next()` ruft die Methode `__next__()` eines Generatorobjekts auf, „rückt“ den Generatorcode bis zu seinem `yield`-Ausdruck vor bzw. wertet ihn bis dahin aus, der dann den Wert „liefert“ bzw. zurückgibt.

```python
>>> squared_numbers = squares_generator([1, 2])

>>> next(squared_numbers)
1
>>> next(squared_numbers)
4
```

Wenn ein `generator` vollständig verbraucht ist und keine weiteren Werte mehr zurückgibt, wirft er einen `StopIteration`-Fehler.

```python
>>> next(squared_numbers)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
StopIteration
```

### Unterschied zwischen Iterables und Generatoren

Generatoren sind eine spezielle Teilmenge von _Iteratoren_.
`Iterators` sind der Mechanismus bzw. das Protokoll, das das Durchlaufen von _Iterables_ ermöglicht.
Generatoren und die Iteratoren, die gängige Python-[`iterables`][iterables] zurückgeben, verhalten sich sehr ähnlich, aber es gibt einige wichtige Unterschiede, die du beachten solltest:

- Generatoren sind _einseitig_; es gibt kein „Zurückspringen“ zu einem vorherigen Wert.

- Das Iterieren über Generatoren verbraucht die zurückgegebenen Werte; kein Zurücksetzen.

- Generatoren (_da sie lazy ausgewertet werden_) sind nicht sortierbar und können nicht umgekehrt werden.

- Generatoren haben _keine_ `indexes`, du kannst also nicht per Addition oder Subtraktion auf einen früheren oder späteren Wert verweisen.

- Generatoren können nicht mit der Funktion `len()` verwendet werden.

- Generatoren können _endlich_ oder _unendlich_ sein. Sei vorsichtig, wenn du alle Werte aus einem _unendlichen_ Generator sammelst.

## Der yield-Ausdruck

Der [yield-Ausdruck][yield expression] ist dem `return`-Ausdruck sehr ähnlich.

Im _Unterschied_ zum `return`-Ausdruck gibt `yield` Werte an den Aufrufer an einem _bestimmten Punkt_ ab und unterbricht die Auswertung bzw. Rückgabe weiterer Werte, bis diese angefordert werden.

Wenn `yield` ausgewertet wird, pausiert es die Ausführung der umgebenden Funktion und gibt die Werte der Funktion _zu diesem Zeitpunkt_ zurück.

Die Funktion bleibt dann _im Gültigkeitsbereich_, und wenn `__next__()` aufgerufen wird, wird die Ausführung fortgesetzt, bis `yield` erneut auftritt.

~~~~exercism/note
Die Verwendung von `yield`-Ausdrücken ist außerhalb von Funktionen nicht erlaubt.
~~~~

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1

>>> lets_try = infinite_sequence()
>>> lets_try.__next__()
0
>>> lets_try.__next__()
1
```

## Warum Generatoren?

Generatoren sind in vielen Anwendungen nützlich.

Wenn du mit einer großen Sammlung arbeitest, möchtest du vielleicht nicht alle ihre Werte in `memory` ablegen.
Ein Generator kann verwendet werden, um größere Daten Stück für Stück zu verarbeiten, was Arbeitsspeicher spart und die Leistung verbessert.

Generatoren sind auch sehr hilfreich, wenn ein Prozess oder eine Berechnung _komplex_, _teuer_ oder _unendlich_ ist:

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1
```

Jetzt gibt das Objekt `infinite_sequence` jedes Mal, wenn `__next__()` dafür aufgerufen wird, die _vorherige Zahl_ + 1 zurück.
