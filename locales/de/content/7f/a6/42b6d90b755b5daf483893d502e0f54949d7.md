# Einführung in die Grundlagen der Shell

## Shells

Eine _Shell_ ist ein Programm, mit dem du Befehle eingeben kannst, um mit dem Betriebssystem zu interagieren.
Shells können grafisch sein; deine Desktopumgebung, die du mit Maus oder Trackpad bedienst, ist eine Shell.
Wir konzentrieren uns auf Kommandozeilenschnittstellen, bei denen du Befehle eintippst und die Ergebnisse (normalerweise) in deinem Terminal ausgegeben werden.

Es gibt viele verschiedene Kommandozeilen-Shells.
Windows bietet **cmd** und **powershell**.
Mac und Linux bieten „Unix-Shells", von denen es viele gibt.
Die Standard-Shell unter Mac ist **zsh**.
**csh** ist eine alte Shell mit C-ähnlicher Syntax.
**bash** ist eine der beliebtesten Shells, besonders unter Linux.

Eine der allerersten Shells ist die Bourne-Shell, **sh**.
Mit der Zeit wurde diese Shell [standardisiert][posix] und ist auf jedem Unix-ähnlichen System verfügbar.
Viele Shells basieren auf der Bourne-Shell und bieten oft zusätzliche interaktive oder Programmierfunktionen.

**Bash** basiert auf der Bourne-Shell.
Deshalb heißt sie „**B**ourne-**a**gain **sh**ell".
Sie ist die Standard-Shell auf vielen Linux-Systemen.
Bash bietet viele Funktionen, die sie zu einer angenehmen interaktiven Shell machen, darunter:

* einen vollständig anpassbaren Prompt,
* die Möglichkeit, Befehle aus dem Verlauf abzurufen und zu ändern,
* die Möglichkeit, laufende Prozesse zu steuern,
* Aliase, die Tipparbeit sparen,
* und mehr.

In diesem Track geht es nicht darum, wie du bash als interaktive Shell verwendest.
Es geht darum, zu lernen, Programme mit bash zu schreiben.
Der Schwerpunkt liegt darauf, Probleme mit _nur_ bash zu lösen, auch wenn es keine Einschränkungen gibt, externe Tools aufzurufen.

## Bash-Grundlagen: Befehle und Argumente

Bash liest Befehle aus ihrer Eingabe (meistens entweder ein Terminal oder eine Datei).
Jede Eingabezeile, die sie liest, wird als _Befehl_ behandelt, also als eine Anweisung, die ausgeführt werden soll.
(Es gibt ein paar fortgeschrittene Fälle, etwa Befehle, die sich über mehrere Zeilen erstrecken, die später besprochen werden.)

Bash teilt jede Zeile in **Wörter** auf, die durch ein Whitespace-Zeichen (Leerzeichen und Tabs) getrennt werden.
Das erste Wort der Zeile ist der Name des _Befehls_, der ausgeführt werden soll.
Alle übrigen Wörter werden zu _Argumenten_ für diesen Befehl (Optionen, Dateinamen usw.).

~~~~exercism/note
In den folgenden Beispielen zeigen wir dir ein paar interaktive Befehle, die du ausführen kannst.

* Das Zeichen `#` beginnt einen _Kommentar_.
  Alle Wörter, die auf den Kommentar folgen, werden von der Shell ignoriert; der Kommentar ist nur zum Lesen gedacht.
* Das Zeichen `$` kennzeichnet den Shell-Prompt. 
  Wenn du den Befehl kopierst, gib den Prompt nicht mit ein.
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm` ist eine Anwendung, die die ihr übergebenen Dateien entfernt.
`*` ist ein [Glob][glob]-Zeichen, ein „Wildcard"-Muster, das auf alle Dateien im aktuellen Verzeichnis passt.
Wir sprechen später noch mehr über Globs.

Ist dir aufgefallen, dass zwischen `a` und `b` mehrere Leerzeichen stehen und zwischen `b` und `c` nur eines?
Die Menge an Whitespace zwischen Argumenten spielt keine Rolle!
Zum Beispiel:

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo` ist ein Befehl, der seine Argumente auf die Standardausgabe schreibt (in unserem Fall das Terminal).
Bash teilt den Befehl in fünf Wörter auf und ruft den Befehl `echo` mit vier Argumenten auf.
Die zusätzlichen Leerzeichen im zweiten Beispiel machen keinen Unterschied.
`echo` weiß nicht, wie die Leerzeichen ursprünglich zwischen den Wörtern verteilt waren.

Wenn wir die zusätzlichen Leerzeichen behalten wollen, müssen wir den Satz als ein einziges Argument übergeben.
Das geht mit [Anführungszeichen][Quotes]:

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

Anführungszeichen fassen alles zwischen sich zu einem _einzigen Argument_ zusammen.
Das Argument ist `This    is    a    test.` samt diesen konkreten Leerzeichen.
Beachte, dass die Anführungszeichen nicht Teil des Arguments sind: Bash entfernt sie, bevor sie das eine Argument an `echo` übergibt.

Argumente werden vom Befehlsnamen und voneinander durch Whitespace getrennt.
Das ist wichtig zu merken.
Zum Beispiel ist das Folgende falsch:

```bash
$ [-f file]
bash: [-f: command not found
```

Das soll prüfen, ob eine Datei namens `file` existiert.
Es ist naheliegend anzunehmen, dass Whitespace um `[` und `]` keine Rolle spielt, aber `[` ist tatsächlich ein Befehl und verlangt, dass sein letztes Argument `]` ist.
(Auf den Befehl `[` gehen wir später genauer ein.) 
Deshalb müssen wir `[` von `-f` und `]` von `file` trennen.
Sonst denkt bash, wir wollten einen Befehl namens `[-f` mit dem einen Argument `file]` ausführen.
Der korrekte Befehl trennt alle Argumente durch Whitespace:

```bash
$ [ -f file ]
```

(Wir erleben viele Leute, die von diesem Verhalten verwirrt sind; sie denken, `[...]` sei „nur Syntax" und sie könnten die Leerzeichen weglassen; `[` ist ein Befehl und die Leerzeichen sind erforderlich.)

Wenn unser Dateiname Whitespace oder andere Sonderzeichen enthält, sollte er ebenfalls in Anführungszeichen gesetzt werden:

```bash
$ [ -f "my file" ]
```

## Arten von Befehlen

Bash kennt mehrere verschiedene Arten von Befehlen: Aliase, Funktionen, Builtins, Schlüsselwörter und ausführbare Dateien.
Sie alle sind _Befehle_ und verhalten sich sehr ähnlich.

Standardmäßig sind Aliase nur in interaktiven Shells aktiviert, nicht in Shell-Skripten.
Wir behandeln sie hier nicht.

### Funktionen

Eine Funktion enthält Shell-Befehle und verhält sich ähnlich wie ein kleines Skript; sie kann sogar Argumente entgegennehmen und lokale Variablen anlegen.
Wenn eine Funktion aufgerufen wird, werden die Befehle darin ausgeführt.
Funktionen behandeln wir später ausführlich.

### Builtins

Bash hat einige grundlegende Befehle fest eingebaut, etwa: `cd` (Verzeichnis wechseln), `echo` (Ausgabe schreiben) und so weiter.
Man kann sie sich als Funktionen vorstellen, die schon mitgeliefert werden.

### Schlüsselwörter

Schlüsselwörter sind wie Builtins, mit dem Hauptunterschied, dass Schlüsselwörter tatsächlich bash-Syntax sind und nach speziellen Regeln geparst werden können.
Zum Beispiel ist `[` ein bash-Builtin, während `[[` ein bash-Schlüsselwort ist; beide werden verwendet, um verschiedene Bedingungen zu prüfen.
Das Schlüsselwort `[[` hat aber einige zusätzliche Funktionen.
Zum Beispiel stellt es den Operator `=~` bereit, der reguläre Ausdrücke prüft.

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

Die String-Vergleichsoperatoren `<` und `>` sind ein weiteres Beispiel dafür, wie Schlüsselwörter den Code anders parsen.
Innerhalb von `[[...]]` brauchen diese Operatoren keine besondere Behandlung.

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

Innerhalb von `[...]` musst du sie aber in Anführungszeichen setzen oder escapen, damit die Shell sie nicht als Umleitungsoperatoren parst.

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### Ausführbare Dateien

Die letzte Art von Befehl, die bash ausführen kann, ist eine _ausführbare Datei_.
Das sind ausführbare Dateien (Programme) im Dateisystem deines Computers, die du starten kannst.
(Ausführbare Dateien werden manchmal auch _externe Befehle_ oder _Anwendungen_ genannt.)
Ausführbare Dateien ruft man üblicherweise auf, indem man nur ihren Namen eintippt; der vollständige Pfad zur Datei ist normalerweise nicht nötig.
Das funktioniert, weil bash eine vordefinierte Variable verwendet, die ihr hilft, den Speicherort gängiger ausführbarer Dateien zu finden.
Diese Variable heißt `PATH`.
Sie ist eine Menge von Verzeichnisnamen, die durch Doppelpunkte getrennt sind (z. B. `/usr/bin:/bin`). 
Wenn ein Befehl (z. B. `myprogram` oder `ls`) ohne Dateipfad angegeben wird (und es sich nicht um einen Alias, eine Funktion, ein Builtin oder ein Schlüsselwort handelt), durchsucht bash die Verzeichnisse in `PATH`.
Die Verzeichnisse werden der Reihe nach von links nach rechts durchsucht, um zu sehen, ob sie eine ausführbare Datei mit dem angegebenen Namen enthalten.

Wenn die ausführbare Datei außerhalb eines bekannten Pfads liegt, musst du den Dateipfad der ausführbaren Datei angeben.
Für die ausführbare Datei `myprogram` im aktuellen Verzeichnis verwende `./myprogram`; wenn sie im Verzeichnis `/opt/somedirectory` liegt, verwende `/opt/somedirectory/myprogram`.

Tipp: Mit dem Befehl `type` bekommst du Details über den Befehl:

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## Skripte

Ein _Skript_ ist eine Folge von Befehlen, die in einer Datei gespeichert sind.
Bash liest die Datei und verarbeitet die Befehle der Reihe nach.
Sie geht erst dann zum nächsten Befehl über, wenn der aktuelle beendet ist.
Die Ausnahme ist, wenn ein Befehl so angegeben wurde, dass er asynchron (im Hintergrund) läuft.
Mach dir über diesen Fall noch keine allzu großen Gedanken; wir lernen später, wie das funktioniert.

Jedes Kommandozeilen-Beispiel in dieser Anleitung kannst du auch in einem Skript verwenden.

Ein Skript zu schreiben ist einfach.
Lege zuerst eine neue Datei an und schreibe Folgendes in die erste Zeile:

```bash
#!/bin/bash
```

Diese Zeile heißt _Interpreter-Direktive_ (man nennt sie auch _Hashbang_ oder **_Shebang_**).
Sie legt fest, dass `/bin/bash` als Interpreter verwendet werden soll, wenn die Datei in einem Befehl als ausführbare Datei dient.
Wenn der Kernel des Betriebssystems eine _nicht-binäre Datei_ ausführt, liest er die erste Zeile der Datei.
Beginnt die Zeile mit `#!`, verwendet der Kernel sie, um den Interpreter zu bestimmen, an den er die Datei weiterreicht.
(Es gibt auch andere gültige Möglichkeiten, siehe unten.)
Das `#!` muss ganz am Anfang der Datei stehen, ohne Leerzeichen oder leere Zeilen davor.
Die Befehle unseres Skripts stehen in den folgenden Zeilen darunter.

Tipp: Statt `#!/bin/bash` kannst du auch Folgendes verwenden

```bash
#!/usr/bin/env bash
```

`env` durchsucht `$PATH` nach der ausführbaren Datei, die durch sein erstes Argument benannt wird (in diesem Fall „bash").
Eine ausführlichere Erklärung dieser Technik und wie sie sich von einem gewöhnlichen `#!/bin/bash` unterscheidet, findest du in [dieser Frage auf StackOverflow][env bash].

Lass dich nicht von Skripten oder Beispielen im Internet täuschen, die `/bin/sh` als Interpreter verwenden.
**`sh` ist nicht `bash`!**
Bash selbst ist eine „sh-kompatible" Shell, das heißt, sie kann die meisten `sh`-Skripte ausführen und übernimmt einen großen Teil derselben Syntax.
Das Gegenteil gilt aber nicht; einige Funktionen von bash brechen in `sh` oder verursachen unerwartetes Verhalten.
Tatsächlich gibt es nicht die eine `sh`-Shell.
Es gibt viele Shell-Implementierungen, die die POSIX-sh-Syntax unterstützen.
Je nach Betriebssystem führst du bei `sh` möglicherweise tatsächlich bash, ash, dash oder eine andere Shell aus.

Sobald die Skriptdatei erstellt ist, kannst du sie so ausführen:

```bash
$ bash myscript
```

In diesem Beispiel führen wir den _Befehl_ `bash` aus und sagen ihm, dass er das Skript lesen soll, das wir als _Argument_ übergeben haben.
Wenn wir es so machen, ist die `#!`-Zeile nur ein _Kommentar_.

Alternativ können wir unseren Skripten Ausführungsrechte geben.
So können wir das Skript wie jede andere ausführbare Datei ausführen, statt bash manuell aufzurufen:

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

Wenn wir den Befehl so ausführen, verwendet das Betriebssystem (OS) die `#!`-Zeile, um zu bestimmen, welcher Interpreter zum Ausführen deines Skripts verwendet wird.
