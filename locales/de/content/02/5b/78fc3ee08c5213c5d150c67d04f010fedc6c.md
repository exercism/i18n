# Hinweise

`Option` wird verwendet, um eine Berechnung auszudrücken, die möglicherweise kein brauchbares Ergebnis hat (zum Beispiel aufgrund eines Fehlers oder einer ungültigen Eingabe).
Wenn du mit `Option` nicht vertraut bist, kannst du [dieses Tutorial](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html) lesen.
`Option` ist eine sogenannte [Monade](https://en.wikipedia.org/wiki/Monad_(functional_programming)), die einen „rechnerischen Aspekt“ abdeckt, in diesem Fall das mögliche Fehlen eines Werts.
Der richtige Umgang mit Monaden kann zu sehr prägnantem und dennoch elegantem und lesbarem Code führen. Falscher Umgang kann leicht das Gegenteil bewirken.
Schau dir [dieses Video](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) an, um mehr zu erfahren.

## Häufige Fallstricke, die du vermeiden solltest

Es gibt ein paar Faustregeln für `Option`:

1. Wenn du sie nicht brauchst, verwende sie nicht. Statt

```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```

besser so

```scala
def add1(x: Int): Int = x + 1
```

(es gibt `Option.map`, um solche einfachen Funktionen anzuwenden, damit du sie nicht mit `Option` überladen musst).

2. Packe nichts aus, wenn du es nicht wirklich musst.
Oft gibt es eingebaute Funktionen für deinen Zweck. Anzeichen für vorzeitiges Auspacken sind `isDefined/isEmpty` oder Pattern Matching. Statt

```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```

besser so

```scala
x map (_ + 1) getOrElse 0
```

3. Monaden kannst du in einer for-Comprehension verwenden. Das ist ein echter Gewinn.
Das ist ratsam, wenn du mehrere `Option`-Instanzen „zusammensetzen“ willst. Statt

```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```

besser so

```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
