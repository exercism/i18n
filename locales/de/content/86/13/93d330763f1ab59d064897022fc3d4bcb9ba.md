# Einführung

Die meisten Daten in Factor liegen in *Sequenzen*. Arrays, Vektoren und Strings sind alle Sequenzen und teilen sich eine gemeinsame Menge von Wörtern aus dem Vokabular [`sequences`][sequences].

## Array-Literale

Ein Array-Literal verwendet `{ }` mit Leerzeichen zwischen den Elementen:

```factor
{ 1 2 3 } .          ! => { 1 2 3 }
{ "a" "b" "c" } .    ! => { "a" "b" "c" }
```

Arrays haben eine feste Länge. Wörter wie `suffix` und `remove-nth`, die die Anzahl der Elemente ändern, geben deshalb eine *neue* Sequenz zurück, statt die ursprüngliche zu vergrößern.

## Länge und Indizierung

```
length   ( seq -- n   )
first    ( seq -- elt )
rest     ( seq -- tailseq )    ! everything but the first element
last     ( seq -- elt )
but-last ( seq -- headseq )    ! everything but the last element
nth      ( n seq -- elt )      ! 0-based
?nth     ( n seq -- elt/f )    ! 0-based; f when out of bounds
```

```factor
{ 10 20 30 } length .       ! => 3
{ 10 20 30 } first .        ! => 10
{ 10 20 30 } rest .         ! => { 20 30 }
{ 10 20 30 } last .         ! => 30
{ 10 20 30 } but-last .     ! => { 10 20 }
1 { 10 20 30 } nth .        ! => 20
```

`?nth` ist die grenzsichere Variante: Du kannst eine Position abfragen, ohne vorher die Länge zu prüfen.

```factor
1 { 10 20 30 } ?nth .       ! => 20
9 { 10 20 30 } ?nth .       ! => f  (out of bounds, no error)
```

## Ausschnitte

```
head ( seq n -- headseq )    ! first n elements
tail ( seq n -- tailseq )    ! drop first n
```

```factor
{ 1 2 3 4 5 } 3 head .   ! => { 1 2 3 }
{ 1 2 3 4 5 } 3 tail .   ! => { 4 5 }
```

Beide lösen einen Fehler aus, wenn `n` größer ist als die Sequenz. Ist `n` zu groß, kürzt `index-or-length` es auf die Länge der Sequenz, damit der anschließende Ausschnitt nicht über das Ende hinausläuft:

```
index-or-length ( seq n -- seq n' )
```

```factor
{ 10 20 30 40 50 } 3 index-or-length head .   ! => { 10 20 30 }
{ 10 20 } 3 index-or-length head .            ! => { 10 20 }
```

Die Varianten mit Stern, `head*` und `tail*`, zählen vom Ende: `head*` lässt die letzten `n` weg, `tail*` behält die letzten `n`:

```
head* ( seq n -- headseq )   ! everything except the last n
tail* ( seq n -- tailseq )   ! the last n elements
```

```factor
{ 1 2 3 4 5 } 2 head* .   ! => { 1 2 3 }
{ 1 2 3 4 5 } 2 tail* .   ! => { 4 5 }
```

Für einen beliebigen Ausschnitt zwischen zwei Indizes nimmt `subseq` den *Anfang* (einschließlich) und das *Ende* (ausschließlich):

```
subseq ( from to seq -- subseq )
```

```factor
1 4 { 10 20 30 40 50 } subseq .   ! => { 20 30 40 }
1 4 "hello" subseq .              ! => "ell"
```

Wenn du einen *Anfang und eine Länge* hast, addierst du beide, um das Ende zu erhalten:

```factor
2 dup 3 + "hello world" subseq .  ! => "llo"
```

(Das ist der Indexbereich `[2, 5)`, also drei Zeichen ab Position 2.)

Die umgekehrte Frage, nämlich *wo* eine Teilsequenz vorkommt, beantwortet `subseq-index`: Es gibt den Startindex des ersten Treffers zurück, oder `f`, wenn es keinen gibt:

```
subseq-index ( seq subseq -- i/f )
```

```factor
"hello world" "o w" subseq-index .   ! => 4
"hello world" "xyz" subseq-index .   ! => f
```

## Auffüllen

```
pad-head ( seq n elt -- padded )    ! prepend copies of elt
pad-tail ( seq n elt -- padded )    ! append copies of elt
```

Beide verlängern `seq`, bis seine Länge mindestens `n` beträgt. Ist `seq` schon so lang, wird es unverändert zurückgegeben.

```factor
{ 2 5 0 } 6 0 pad-tail .   ! => { 2 5 0 0 0 0 }
{ 4 1 } 5 9 pad-head .     ! => { 9 9 9 4 1 }
```

## Dieselben Wörter funktionieren auch bei Strings

Ein String ist eine Sequenz von Zeichen, deshalb funktioniert alles oben auch mit Strings. Das Ergebnis ist dann nur ein anderer String statt eines Arrays:

```factor
"hello" length .            ! => 5
"hello" 3 head .             ! => "hel"
"abc" 6 CHAR: . pad-tail .   ! => "abc..."
```

## Aggregieren

`sum` und `product` (in [`sequences`][sequences]) addieren oder multiplizieren die Elemente einer numerischen Sequenz:

```factor
{ 2 5 0 7 } sum .        ! => 14
{ 2 5 3 7 } product .    ! => 210
```

`count` wendet ein Prädikat auf die Sequenz an und gibt zurück, für wie viele Elemente es wahr ist:

```
count ( seq quot -- n )
```

```factor
{ 2 5 0 7 4 1 } [ even? ] count .    ! => 3
```

## Prädikate über die gesamte Sequenz

```
any?   ( seq quot -- ? )
all?   ( seq quot -- ? )
empty? ( seq -- ? )
```

```factor
{ 2 5 0 7 } [ 4 > ] any? .      ! => t
{ 2 5 0 7 } [ 0 > ] all? .      ! => f
```

## Eine neue Sequenz aufbauen

`suffix` hängt ein Element an das Ende einer Sequenz an, `prefix` fügt eines am Anfang ein. `unclip` nimmt das erste Element heraus und `unclip-last` das letzte:

```
prefix      ( seq elt -- newseq )
suffix      ( seq elt -- newseq )
unclip      ( seq -- rest first )
unclip-last ( seq -- butlast last )
```

```factor
{ 7 9 } 3 prefix .             ! => { 3 7 9 }
{ 7 9 } 3 suffix .             ! => { 7 9 3 }
{ 4 0 9 } unclip .s
! => { 0 9 }
! => 4
```

Die Kombination von `unclip-last` und `suffix` ergibt eine nicht-destruktive Aktualisierung des letzten Elements (und `unclip` + `prefix` macht dasselbe für das erste):

```factor
{ 10 20 30 } unclip-last 2 * suffix .
! => { 10 20 60 }
```

## Umwandeln zwischen Sequenztypen

`>array`, `>vector` und `>string` (in [`arrays`][arrays] und den entsprechenden Vokabularen) zwingen eine Sequenz in einen bestimmten konkreten Typ. Das ist nützlich, wenn eine Operation einen Ausschnitt oder eine generische Sequenz zurückgegeben hat und du wieder ein Array (oder einen String) brauchst.

```factor
{ 1 2 3 } 1 tail >array .   ! => { 2 3 }
"hello" >array .            ! => { 104 101 108 108 111 }
{ 65 66 67 } >string .      ! => "ABC"
```
