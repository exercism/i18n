# Über

Dynamischer Speicher wird durch Bibliotheksfunktionen implementiert, die der Programmierer verwendet, um Speicher zur Laufzeit zu reservieren und freizugeben.
Da der Programmierer die Reservierung und Freigabe von Speicher steuert, ist dynamischer Speicher genau so sicher, wie der Programmierer frei von menschlichen Fehlern ist.
Aus diesem Grund ist dynamischer Speicher eine der größten Quellen für Programmierfehler und ein beliebtes Ziel für Hackerangriffe.

Dynamischer Speicher wird für Variablen verwendet, deren Größe erst zur Laufzeit bekannt ist.
Das ist häufig nützlich für Arrays, deren Elementanzahl sich von einem Programmlauf zum nächsten unterscheiden kann.
Arrays variabler Länge (VLA) sind eine weitere Möglichkeit, mit Arrays umzugehen, deren Elementgröße erst zur Laufzeit bekannt ist.
Ein VLA verwendet automatischen Speicher, das heißt, sein Speicher wird beim Verlassen des definierenden Blocks zerstört.
(Mehr zum Thema Speicher findest du im Konzept [storage class specifiers](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers).)
VLAs wurden mit C99 in die Sprache C eingeführt, aber seit C11 sind VLAs optional, sodass Compiler, die C11 oder neuer unterstützen, VLAs nicht unterstützen müssen.
Eine ausführliche Analyse von Arrays variabler Länge würde den Rahmen dieses Artikels sprengen.

## malloc

`malloc` ist eine Funktion, die in `stdlib.h` deklariert ist und zum Reservieren von dynamischem Speicher verwendet wird.
Wenn die Reservierung erfolgreich ist, wird ein Zeiger zurückgegeben, der auf die Adresse des ersten Bytes des reservierten Speichers zeigt.
Wenn die Reservierung nicht erfolgreich ist, wird `NULL` zurückgegeben.
Es ist ratsam, das Ergebnis von `malloc` auf `NULL` zu prüfen und den Fehlerfall sauber zu behandeln.
Der zurückgegebene Zeiger hat den Typ `pointer-to-void`, den man grob als „generischen“ Zeiger betrachten kann, der in den konkreten Typ umgewandelt werden kann, der für den Speicher verwendet wird.
`malloc` hat einen Parameter, nämlich die Größe des gewünschten Speichers in Bytes.
Die Gesamtgröße zum Reservieren eines Arrays ist die Größe des Datentyps jedes Elements multipliziert mit der Anzahl der Elemente.
Der Operator `sizeof` wird üblicherweise verwendet, um die Größe des Datentyps jedes Elements zu ermitteln.
Das folgende Beispiel zeigt das

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

Es ist wichtig, sich daran zu erinnern, dass der von `malloc` neu reservierte Speicher nicht initialisiert wird, sondern Müllwerte enthalten kann.
Beachte, dass `sizeof` des Zeigers `numbers` weder die Anzahl der Elemente des Arrays noch die insgesamt reservierte Speichermenge ist.
Die Größe des von `malloc` zurückgegebenen Zeigers ist die Größe eines beliebigen Zeigers auf diesem System.
Der Beispielcode wurde auf einem 64-Bit-System ausgeführt, daher betrug die Größe des Zeigers 8 Bytes (mal 8 Bits pro Byte = 64 Bits).
Der Zeigertyp wurde implizit von pointer-to-void in pointer-to-int umgewandelt.
Ob der pointer-to-int auf einen einzelnen `int` oder auf ein Array von `ints` zeigt, kann der Programmierer nach eigenem Ermessen handhaben.
Zum Beispiel

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

Wenn die Werte mit Sicherheit geschrieben werden, bevor sie gelesen werden, kann `malloc` eine effiziente Möglichkeit sein, Speicher zu reservieren.
Wenn jedoch die Möglichkeit besteht, dass die Werte gelesen werden, bevor sie initialisiert wurden, ist die Verwendung von `malloc` riskant.
Eine sicherere Möglichkeit, Speicher zu reservieren, ist `calloc`, das den neu reservierten Speicher auf null initialisiert.

Beachte, dass in den obigen Beispielen `free(numbers)` verwendet wurde.

## free

`free` ist eine Funktion, die in `stdlib.h` deklariert ist und zum Freigeben von dynamisch reserviertem Speicher verwendet wird.
Dynamisch reservierter Speicher bleibt im Speicher belegt, bis er von `free` freigegeben wird.
Manche Betriebssysteme geben dynamisch reservierten Speicher möglicherweise automatisch frei, wenn das Programm endet, aber es ist gute Praxis, sich nicht darauf zu verlassen.
`free` hat einen Parameter, nämlich einen Zeiger auf den Speicher, der dynamisch reserviert wurde.
Die Verwendung oder Nichtverwendung von `free` ist mit mehreren Speicherproblemen verbunden.

#### Speicherleck

Wenn dynamisch reservierter Speicher nicht freigegeben wird, nachdem die Referenz auf diesen Speicher das Ende seiner Lebensdauer erreicht hat oder anderweitig zerstört wurde, spricht man von einem Speicherleck.
Ein Speicherleck ist Speicher, der vom System belegt ist, aber vom Programm nicht mehr erreicht werden kann.
Das kann besonders problematisch sein, wenn Speicher in einer Schleife reserviert, am Ende der Schleife nicht freigegeben und am Anfang der Schleife erneut reserviert wird.
Wenn genug Speicher reserviert wird, ohne freigegeben zu werden, schlägt der Aufruf zur Speicherreservierung fehl, weil nicht mehr genügend Speicher zum Reservieren übrig ist.
Es ist wichtig, sich daran zu erinnern, dass der dynamisch reservierte Speicher zwar vom System belegt bleibt, bis er freigegeben wird, der Zeiger, dem er zugewiesen wird, aber nur Blockgültigkeitsbereich haben kann.
In den `malloc`-Beispielen wird der Speicher zum Beispiel in `my_function` reserviert.
Dieser Speicher würde verloren gehen, wenn der Zeiger darauf nicht zurückgegeben und verwendet würde, um den Zeiger `numbers` in `main` zu setzen.
Wenn man also den Zeiger `numbers` an `free` übergibt, wird der in `my_function` reservierte Speicher freigegeben.

#### Verwendung nach der Freigabe (**UAF**)

Wenn auf Speicher zugegriffen wird, nachdem er freigegeben wurde, kann der Wert beliebig sein.
Im folgenden Beispiel wird der Speicher, auf den `numbers` zeigt, freigegeben und anschließend in `printf` gelesen.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

Der Zeiger `numbers` wird nach seiner Freigabe als hängender Zeiger bezeichnet.
Ein hängender Zeiger kann auf anderen Speicher verweisen als den, für den er gedacht war.
Daher kann ein hängender Zeiger zu Datenkorruption sowie zum Austausch und zur Ausführung beliebigen Codes führen.
Ein Zeiger auf reservierten Speicher, der nicht durch Setzen auf `NULL` geleert wurde, kann genutzt werden, um das Programm zu hacken.
Im obigen Beispiel würde, wenn `numbers` nach der Freigabe so auf `NULL` gesetzt würde: `numbers = NULL;`, das folgende `printf` zum Abbruch des Programms führen, möglicherweise mit einem Speicherzugriffsfehler beim Versuch, `numbers[0]` zu lesen.

#### doppelte Freigabe

Wenn `free` zweimal mit einem Zeiger auf dynamisch reservierten Speicher aufgerufen wird, führt das zu undefiniertem Verhalten (**UB**).
Das bedeutet, dass der Compiler damit nach Belieben umgehen kann.
Das folgende Beispiel kann, mit zwei verschiedenen Compilern kompiliert, zwei verschiedene Ergebnisse haben

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

Der erste und der zweite Compiler erzeugten keinen Laufzeitfehler, als `numbers` zwischen den beiden Aufrufen von `free` auf `NULL` gesetzt wurde, aber das würde mit einem dritten Compiler nicht garantiert funktionieren.
Eine häufige Ursache für eine doppelte Freigabe ist, zwei Zeiger zu haben, die auf denselben dynamisch reservierten Speicher zeigen.
Ein Zeiger kann an einer Stelle im Programm auf den Anfang eines Arrays zeigen, und der andere Zeiger kann an einer anderen Stelle im Programm verwendet werden, um durch das Array zu laufen.
An verschiedenen Stellen im Programm wird jeder Zeiger freigegeben, was zu einer doppelten Freigabe führt.

## calloc

`calloc` ist eine Funktion, die in `stdlib.h` deklariert ist und sowohl zum Reservieren von dynamischem Speicher als auch zum Initialisieren des neu reservierten Speichers auf null verwendet wird.
Wenn die Reservierung erfolgreich ist, wird ein Zeiger zurückgegeben, der auf die Adresse des ersten Bytes des reservierten Speichers zeigt.
Wenn die Reservierung nicht erfolgreich ist, wird `NULL` zurückgegeben.
Es ist ratsam, das Ergebnis von `calloc` auf `NULL` zu prüfen und den Fehlerfall sauber zu behandeln.
Der zurückgegebene Zeiger hat den Typ `pointer-to-void`, den man grob als „generischen“ Zeiger betrachten kann, der in den konkreten Typ umgewandelt werden kann, der für den Speicher verwendet wird.
`calloc` hat zwei Parameter.
Der erste Parameter gibt an, wie viele Elemente des angegebenen Datentyps reserviert werden sollen.
Der zweite Parameter gibt die Größe des angegebenen Datentyps an, der reserviert werden soll.

Im folgenden Beispiel sollten alle `printf`-Anweisungen immer `0` anzeigen, da `calloc` garantiert die neu reservierten Werte auf null setzt.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` ist eine Funktion, die in `stdlib.h` deklariert ist und verwendet wird, um bereits reservierten Speicher entweder zu vergrößern oder zu verkleinern.
Wenn die Neureservierung erfolgreich ist, wird ein Zeiger zurückgegeben, der auf die Adresse des ersten Bytes des neu reservierten Speichers zeigt.
Wenn die Neureservierung nicht erfolgreich ist, wird `NULL` zurückgegeben.
Es ist ratsam, das Ergebnis von `realloc` auf `NULL` zu prüfen und den Fehlerfall sauber zu behandeln.
`realloc` hat zwei Parameter.
Der erste Parameter ist ein Zeiger auf den vorhandenen Speicher, der neu reserviert werden soll.
Der zweite Parameter gibt die Größe des neu reservierten Speichers in Bytes an.
Werte, die gesetzt wurden, bevor der Speicher vergrößert wird, bleiben erhalten.
Es ist wichtig, sich daran zu erinnern, dass der beim Vergrößern hinzugefügte Speicher nicht auf null initialisiert wird und seine Werte beliebig sein können.
Auch der beim Verkleinern entfernte Speicher wird nicht initialisiert und kann die Werte noch enthalten.
Das folgende Beispiel zeigt das Vergrößern und Verkleinern eines Arrays

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## Wenn die übergebene Größe 0 ist

Wenn die an `malloc`, `calloc` oder `relloac` übergebene Größe `0` ist, hängt das Ergebnis davon ab, wie der Compiler dies implementiert.
Ein Compiler kann entweder einen `NULL`-Zeiger oder einen Nicht-NULL-Zeiger zurückgeben.
Wenn du zum Beispiel Speicher für einen Zeiger auf `char` reservierst, kann der Compiler entweder `NULL` oder einen Nicht-NULL-Zeiger auf eine leere Zeichenkette zurückgeben.
Um unterschiedliche Ergebnisse bei unterschiedlichen Compilern zu vermeiden, solltest du am besten nicht mit einer Größe von 0 reservieren.
