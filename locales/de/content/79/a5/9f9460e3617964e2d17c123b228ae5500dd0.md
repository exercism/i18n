# Einleitung

Du hast Streams bereits in `channel-chatter` *verwendet* und sie in `boatswains-bilge` wieder freigegeben. Diese Übung ist dein erster eigener Stream: eine Klasse, die das [Protokoll][stream-protocol] implementiert, sodass derselbe Code mit `with-input-stream` / `read1` / `stream-read1`, der mit einem `<string-reader>` funktioniert hat, auch mit deinem funktioniert.

## Mixins: die andere Hälfte der Klassenhierarchie

Du kennst `TUPLE: child < parent …` bereits aus `dragons-descendants`: eine Hierarchie mit einem einzigen Elternteil, in der Slots nach unten weitergegeben werden. Factor hat einen *zweiten* Weg, den Klassen-Graphen zu erweitern: **offene Mixins**. Ein `MIXIN: m` deklariert eine Klasse ohne Slots, der andere Klassen nachträglich mit `INSTANCE: c m` beitreten können. Die Zugehörigkeit ist m:n: Eine Klasse kann Instanz beliebig vieler Mixins sein.

Das Stream-Protokoll verwendet zwei Mixins, um zu markieren, welche Hälfte der Schnittstelle eine Klasse implementiert:

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

Ein Stream kann das eine, das andere oder beides sein. Generische Methoden auf `input-stream` (oder `output-stream`) leiten dann an jede Klasse weiter, die dem Mixin beigetreten ist. So finden die allgemein verfügbaren `read1`, `stream-contents`, `with-input-stream` usw. ihren Weg zu deiner Klasse.

Mixins sind *offen*: Du kannst noch nach der Deklaration des Mixins ein neues Mitglied hinzufügen, sogar in einem anderen Vokabular. Das ist der Unterschied zu `TUPLE: < parent`, wo die Beziehung feststeht, sobald die Kindklasse deklariert wird.

## Die generischen Methoden des Protokolls

Die generischen Methoden des Protokolls liegen in `io`:

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

`stream-read1` gibt das nächste Byte zurück (oder `f` am Ende des Streams); `stream-write1` schreibt eines. `stream-read-unsafe` ist das gebündelte Lesen auf niedrigerer Ebene, das die meisten Eingabe-Streams anbieten; `stream-read` baut darauf auf und kümmert sich um die Speicherzuweisung. `stream-element-type` gibt an, ob der Stream mit Bytes (`+byte+`) oder Zeichen (`+character+`) arbeitet. Wenn du einen anderen Stream umhüllst, delegiert die einfachste Implementierung einfach an den darunterliegenden.

## Das Aufräumen kommt aus `destructors`

Streams sind Disposables: Ein eigener Stream erweitert `disposable` und implementiert `dispose*`. Das ist das Framework aus `boatswains-bilge`, angewendet auf eine Stream-Klasse:

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

Sobald das steht, funktionieren alle Kombinatoren `with-…` aus `channel-chatter` automatisch mit deinem Stream.
