# Installation

## Einleitung

Obwohl Regina Rexx weit verbreitet portiert wurde, konzentrieren sich die Installationsanweisungen auf 64-Bit-Desktop-Plattformen unter Windows, Linux oder MacOS.

## Installationsschritte

Beachte, dass dieser Track die Installation der neuesten Version von [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) erwartet (3.9.5, zum Zeitpunkt der Erstellung dieses Textes). Der angegebene Hyperlink führt dich direkt zum Bereich „Files“, in dem du eine Datei zum Herunterladen auswählst.

### Windows

Eine Installation für den nativen Betrieb unter Windows (über ein CMD- oder PowerShell-Fenster) lässt sich bequem im Browser über die Schaltfläche [`Download Latest Version`](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/Regina395w64.exe/download) durchführen. Du musst nicht mehr tun als klicken, herunterladen und installieren.

Wenn du Linux-Emulationsumgebungen wie die folgenden hast oder nutzen möchtest:

* [Git for Windows](https://gitforwindows.org/)
* [Cygwin](https://cygwin.com/)
* [MinGW](http://mingw.org/)

sollten die Windows-nativen Regina-Binärdateien zugänglich sein. Du kannst sie also einfach in diesen Umgebungen ausführen, und für die meisten Zwecke ist das in Ordnung.

Eine Einschränkung gibt es jedoch: Die `ADDRESS`-Anweisung funktioniert nicht korrekt (weil sie mit dem Host-Betriebssystem interagiert). Für die besten Ergebnisse in diesen Umgebungen solltest du das umgebungsspezifische Paket beziehen und installieren. Die Regina-Website hostet zum Beispiel einen [Cygwin-spezifischen](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-pc-cygwin.tgz/download) Build, den du installieren könntest.

Wenn du alternativ eine _echte_ Linux-Distribution unter Windows wie [WSL](https://docs.microsoft.com/en-us/windows/wsl/about) oder [Virtual Box](https://www.virtualbox.org/) hast oder nutzen möchtest, folge einfach den Anweisungen im Abschnitt zu Linux für die entsprechende Distribution.

### Linux

Linux-Installationen sind mit dem Paketmanager des Systems in der Regel recht unkompliziert. Problematisch wird es jedoch, wenn die verfügbaren Pakete _nicht_ die neuesten sind. Das ist bedauerlicherweise bei Regina der Fall.

Eine paketbasierte Installation ist trotzdem möglich, indem du das neueste Paket manuell beziehst. Die [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/)-Website hostet unter anderem Pakete für Distributionen der Debian-Familie (einschließlich Ubuntu) und der RHEL-Familie (einschließlich Fedora, CentOS, Rocky und Alma).

Für die gewählte Distribution musst du zwei Pakete herunterladen: ein Bibliothekspaket und ein Binärpaket. Um beispielsweise auf Debian oder Ubuntu zu installieren, gehst du so vor:

```plain
sudo apt update && sudo apt -y install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx_3.9.5-2_amd64-Debian-11.deb > regina-rexx_3.9.5-2_amd64-Debian-11.deb
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3_3.9.5-2_amd64-Debian-11.deb > libregina3_3.9.5-2_amd64-Debian-11.deb
sudo apt -y install libregina3_3.9.5-2_amd64-Debian-11.deb regina-rexx_3.9.5-2_amd64-Debian-11.deb
```

Und auf CentOS und RHEL 7 versuche:
```plain
sudo yum update && sudo yum install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
sudo yum localinstall libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
```

Und auf Fedora, Rocky und Alma versuche:
```plain
sudo dnf update && sudo dnf install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
sudo dnf localinstall libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
```

Wo eine paketbasierte Installation nicht möglich ist oder sich anderweitig als problematisch erwiesen hat, kannst du immer aus dem Quellcode bauen. Das Archiv erhältst du so:

```plain
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5.tar.gz > regina-rexx-3.9.5.tar.gz
```

Angenommen, die üblichen Build-Werkzeuge (gcc, make) sind installiert (wenn nicht, folge den Anweisungen hier: [Install Development Tools](https://ostechnix.com/install-development-tools-linux/)), dann führe die folgenden Schritte aus:

```plain
tar -xzvf regina-rexx-3.9.5.tar.gz && cd regina-rexx-3.9.5
./configure
sudo make
sudo make install
```

Die Bibliothek (`libregina.so`) und zwei Sätze von Binärdateien (`rexx` und `regina`) werden installiert (der Standardort ist `/usr/local/bin`).

Die Binärdatei `rexx` ist statisch gelinkt, also eigenständig und sofort einsatzbereit.

Die Binärdatei `regina` ist dynamisch gelinkt und benötigt daher eine Konfiguration, damit sie die Shared Library `libregina.so` zur Laufzeit findet. Gehe dazu so vor:

```plain
# Configure shared library location
sudo su
echo /usr/local/lib64/ > /etc/ld.so.conf.d/regina-rexx-3.9.5-x86_64.conf
echo /usr/local/lib64/regina-rexx/addons > /etc/ld.so.conf.d/regina-rexx-addons-x86_64.conf
cd /usr/local/lib64
rm -f libregina.so libregina.so.3
ln -s libregina.so.3.9 libregina.so
ln -s libregina.so.3.9 libregina.so.3
ldconfig
exit

# Check symbolic link creation
ls -l /usr/local/lib64/

# Output should be similar. Note symbolic links.
-rw-r--r--. 1 root root 3887554 Dec  1 18:22 libregina.a
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so -> libregina.so.3.9
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so.3 -> libregina.so.3.9
-rwxr-xr-x. 1 root root  574104 Dec  1 18:22 libregina.so.3.9
drwxr-xr-x. 2 root root      26 Dec  1 18:22 pkgconfig
drwxr-xr-x. 4 root root      33 Dec  1 18:22 regina-rexx

# Check library path, and executable using that path
ldconfig -p | grep regina
ldd /usr/local/bin/regina

# Alternate for local user
export LD_LIBRARY_PATH=${LD_LIBRARY_PATH}:/usr/local/lib64:/usr/local/lib64/regina-rexx/addons
```

Beachte, dass das Bauen aus dem Quellcode und die damit verbundene Systemkonfiguration eine Aufgabe sind, die am besten erfahrene Nutzer übernehmen.

### MacOS

Die Installation ist ein dreistufiger Prozess:

* Installiere den Paketmanager [Homebrew](https://brew.sh)
* Suche die Anwendung `Terminal` und starte sie
* Gib in der Kommandozeile des `Terminal` Folgendes ein:

   `brew install regina-rexx`

Dies _sollte_ die neueste Version installieren.

Wenn das nicht der Fall ist, kannst du das Paket [Regina for MacOS](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-apple-darwin21.6.0.tgz/download) herunterladen und manuell installieren.

## Nach der Installation

### Installationsprüfung

Nachdem du die Installation abgeschlossen hast, kannst du überprüfen, ob [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) erfolgreich installiert wurde, indem du diesen Befehl in einem Terminal ausführst:

```plain
rexx --version=v
```

Sowohl unter Windows als auch unter Linux erscheint die folgende Terminal-Ausgabe:

```plain
3.9.5
```

Das ist die Versionsnummer des Interpreters.

Eine zweite Binärdatei, `regina`, wird ebenfalls installiert. Sie ist in jeder Hinsicht mit `rexx` identisch, außer dass sie gegen eine Shared Library gelinkt ist, und ist der Interpreter, den du stattdessen verwenden solltest, wenn du auf externe Utility-Funktionen zugreifen möchtest. Siehe Abschnitt [Zugriff auf externe Routinen](#zugriff-auf-externe-routinen).

Es müssen keine weiteren Softwarekomponenten installiert werden, um mit dem Track zu beginnen (vorausgesetzt, die Exercism CLI ist installiert).

Die folgenden Nutzungshinweise vermitteln dir die Grundlagen für die Verwendung des Interpreters über die Kommandozeile.

### Verwendung

Ein Rexx-Skript hat typischerweise die Dateiendung _`.rexx`_, obwohl das nicht zwingend erforderlich ist: Der Interpreter versucht, jeden als Argument übergebenen Dateinamen auszuführen, und wenn die Datei gültigen Rexx-Code enthält, läuft sie erfolgreich.

Der folgende Befehl versucht, eine Datei namens `hello.rexx` auszuführen:

```plain
rexx hello.rexx
```

Angenommen, die Datei enthält den folgenden Code:

```rexx
say "Hello, world!"
exit 0
```

dann wäre die Terminal-Ausgabe:

```plain
Hello, world!
```

Dieselbe Terminal-Ausgabe würde erscheinen, wenn die Datei in `hello.txt` umbenannt und so ausgeführt würde:

```plain
rexx hello.txt
```

Es ist außerdem gut zu wissen, dass Skriptcode über eine Pipe an den Interpreter übergeben werden kann, statt in einer Datei zu liegen. Der obige Code lässt sich zum Beispiel so per Pipe ausführen:

```plain
echo "say 'Hello, world' ; exit 0" | rexx
```

und funktioniert sowohl in einem Linux- als auch in einem Windows-PowerShell-Terminal gleichermaßen.

### Erweiterte Verwendung

An Skriptdateien können ein oder mehrere Kommandozeilenargumente übergeben werden, und sie können beliebige ganzzahlige Rückgabecodes zurückgeben. Der Interpreter muss jedoch wissen, dass mehrere Argumente an das Skript übergeben werden, was über die Option `-a` erreicht wird.

Angenommen, die Datei `multiarg.rexx` enthält den folgenden Code:

```rexx
say "My name is" ARG(1) || ", your name is" ARG(2) || ", and the script return code will be" ARG(3) || "."
exit ABS(ARG(3))
```

Damit die mehreren Skriptargumente korrekt interpretiert werden, wird das Skript so ausgeführt:

```plain
rexx -a multiarg.rexx "John" "Jill" 5
```

Das ergibt die folgende Terminal-Ausgabe:

```plain
My name is John, your name is Jill, and the script return code will be 5.
```

und der Programm-Rückgabecode (über `$?` unter Linux oder `%errorlevel%` unter Windows abrufbar) wird auf den Wert 5 gesetzt.

### Zugriff auf externe Routinen

Regina unterstützt die Verwendung von Routinen, die in externen Shared Libraries liegen. Einige davon sind auf der Regina-Website verfügbar. Die Installation solcher Bibliotheken wird hier jedoch nicht behandelt.

Regina wird jedoch mit einer solchen Bibliothek ausgeliefert, _regutil_. Sie enthält mehrere Allzweckroutinen, unter anderem für Mathematik, Datei- und Dateisystemmanipulation sowie Systemzugriffsaufgaben.

Es sind keine zusätzlichen Installationsschritte erforderlich. Um diese Routinen in einem Skript zu verwenden, müssen sie jedoch beim Laden des Interpreters registriert werden. Dafür sind nicht mehr als zwei Funktionsaufrufe nötig, und der Ablauf wird hier veranschaulicht.

Eine Datei `access-external.rexx` enthält den folgenden Code:

```rexx
/* Register external library and functions */
call RxFuncAdd 'SysLoadFuncs', 'regutil', 'SysLoadFuncs'
call SysLoadFuncs

say "Value of pi is" SysPi()
say "Square root of 25 is" SysSqrt(25)
say "Square root of 2 is" SysSqrt(2)

/* Deregister */
call SysDropFuncs

exit 0
```

Um diese Routinen zu laden und zu verwenden, muss die Binärdatei `regina` verwendet werden, das Skript würde also so ausgeführt:

```plain
regina access-external.rexx
```

und die folgende Terminal-Ausgabe erscheint:

```plain
Value of pi is 3.141592654
Square root of 25 is 5.000000000
Square root of 2 is 1.414213562
```

Wenn stattdessen die Binärdatei `rexx` verwendet worden wäre, wäre die Terminal-Ausgabe auf einer Windows-Plattform:

```plain
'SYSLOADFUNCS' is not recognized as an internal or external command,
operable program or batch file.
'SYSPI' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSDROPFUNCS' is not recognized as an internal or external command,
operable program or batch file.
```

während auf einer Linux-Plattform die Terminal-Ausgabe wäre:

```plain
sh: SYSLOADFUNCS: command not found
sh: SYSPI: command not found
sh: SYSSQRT: command not found
sh: SYSSQRT: command not found
sh: SYSDROPFUNCS: command not found
```
