# Überblick

`TUPLE: child < parent extra-slots ;` deklariert eine Klasse, deren
Instanzen auch Instanzen von `parent` sind. Die Slot-Suche durchläuft die
Hierarchie: Eine Instanz von `child` hat jeden Slot, den die Elternklasse
deklariert hat, plus ihre eigenen, in dieser Reihenfolge.

```factor
TUPLE: vessel name tonnage ;
TUPLE: cargo-vessel < vessel capacity ;
TUPLE: tanker < cargo-vessel fuel-type ;
```

## Argumentreihenfolge von `boa`

Der automatisch generierte Konstruktor `boa` nimmt Slots in der Reihenfolge
ihrer Deklaration entgegen, *zuerst die Elternklassen*. Für `tanker` oben:

```
tanker boa ( name tonnage capacity fuel-type -- tanker )
```

Die Slot-Reihenfolge ist durch die Vererbungskette festgelegt: Es gibt keine
Möglichkeit, die Slots von Eltern- und Kindklasse zu vermischen, und das
Umsortieren der Slots einer Elternklasse ist eine inkompatible Änderung für
das `boa` jeder Nachkommenklasse.

## Prädikatshierarchie

Jede `TUPLE:`-Deklaration erzeugt ein Klassenprädikat
(`name?`). Mit Vererbung verschachteln sich die Prädikate:

```factor
"Esso" 50000 100000 "diesel" tanker boa .

! all three predicates fire
dup tanker?        .   ! => t
dup cargo-vessel?  .   ! => t
dup vessel?        .   ! => t
```

`instance?` (aus [`classes`][classes]) stellt dieselbe Frage,
jedoch mit der Klasse als Argument auf dem Stack, statt sie fest
in einen Wortnamen einzubauen: `obj tanker instance?` entspricht
`obj tanker?`:

```factor
USING: classes ;

"Esso" 50000 100000 "diesel" tanker boa
dup vessel instance? .   ! => t
```

Weil die Klasse jetzt ein Wert ist, kann dieselbe Aufrufstelle gegen
jede Klasse testen, die ihr übergeben wird, was ein festes `name?`-Prädikat
nicht kann.

Die transitive `is-a`-Beziehung ist auch das, was der Methoden-Dispatch
von `M:` durchläuft: Eine Methode, die für `vessel` definiert ist, gilt
für jedes `cargo-vessel` und jeden `tanker`, es sei denn, eine
spezifischere Überschreibung greift zuerst. Diese Seite wird in
[`generics`][generics] behandelt.

## Accessor-Vererbung

Accessor-Wörter (`slot>>`, `>>slot`, `change-slot`) stammen aus
[`accessors`][accessors] und sind nicht an die Klasse gebunden, für
die sie erzeugt wurden: Jedes Tupel, das den Slot *hat*, kann sie
verwenden.

```factor
USING: accessors ;

"Esso" 50000 100000 "diesel" tanker boa
[ 1 + ] change-tonnage tonnage>> .   ! => 50001
```

`change-tonnage` wurde für `vessel` erzeugt, funktioniert aber auf einem
`tanker`, weil jeder `tanker` ein `vessel` ist.

## Was das hier nicht ist

- **Mixins** (`MIXIN:` / `INSTANCE:`): Eine Klasse kann vielen
  Mixins beitreten; die Beziehung ist n:m und wird hauptsächlich für
  generischen Dispatch über ein gemeinsames Protokoll verwendet. Das
  Streams-Konzept führt sie im Kontext ein.
- **Prädikatsklassen** (`PREDICATE:`): gliedern eine Unterklasse aus
  einer bestehenden Klasse mithilfe eines Laufzeitprädikats aus. Ein
  eigenständiges Factor-Feature; wird hier nicht behandelt.
