# Über

Ein [Vergleichsoperator][comparisons] in Python (_auch als relationaler Operator in Python bezeichnet_) betrachtet die _Werte_ zweier [Operanden][operand] und gibt den booleschen Wert `True` oder `False` zurück, je nachdem, ob die `comparison`-Bedingung erfüllt ist oder nicht.

Die folgende Tabelle zeigt die gebräuchlichsten Vergleichsoperatoren in Python:

| Operator | Operation                  | Beschreibung                                                               |
| -------- | -------------------------- | ------------------------------------------------------------------------- |
| `>`      | „größer als“               | `a > b` ist `True`, wenn `a` **strikt** größer im Wert als `b` ist        |
| `<`      | „kleiner als“              | `a < b` ist `True`, wenn `a` **strikt** kleiner im Wert als `b` ist       |
| `==`     | „gleich“                   | `a == b` ist `True`, wenn `a` **strikt** gleich `b` im Wert ist           |
| `>=`     | „größer oder gleich“       | `a >= b` ist `True`, wenn `a > b` ODER `a == b` im Wert gilt              |
| `<=`     | „kleiner oder gleich“      | `a <= b` ist `True`, wenn `a < b` oder `a == b` im Wert gilt              |
| `!=`     | „ungleich“                 | `a != b` ist `True`, wenn `a == b` `False` ist                            |
| `is`     | „Identität“                | `a is b` ist `True` **_und nur dann_**, wenn `a` und `b` dasselbe _Objekt_ sind |
| `is not` | „negierte Identität“       | `a is not b` ist `True` **_und nur dann_**, wenn `a` und `b` **nicht** dasselbe _Objekt_ sind |
| `in`     | „Enthaltensein-Test“       | `a in b` ist `True`, wenn `a` Mitglied, Teilmenge oder Element von `b` ist |
| `not in` | „negierter Enthaltensein-Test“ | `a not in b` ist `True`, wenn `a` kein Mitglied, keine Teilmenge oder kein Element von `b` ist |

Sie haben alle dieselbe Priorität (_die höher ist als die von [booleschen Operationen][boolean operations], aber niedriger als die von arithmetischen oder bitweisen Operationen_).

## Vergleich zwischen verschiedenen Datentypen

Objekte unterschiedlichen Typs (_außer numerischen Typen_) sind standardmäßig niemals gleich.
Instanzen, die nicht identisch sind, sind ebenfalls _**nicht**_ gleich, es sei denn, die `class` definiert spezielle [Rich-Comparison-Methoden][rich comparisons], die das standardmäßige Vergleichsverhalten von `object` anpassen.
Für (wesentlich) mehr Details siehe [Wertvergleiche][value comparisons] in der Python-Dokumentation.

Numerische Typen sind (größtenteils) eine Ausnahme von dieser Typübereinstimmungsregel.
Ein Wert vom Typ `integer` **kann** als gleich einem Wert vom Typ `float` betrachtet werden (_oder eine [`octal`][octal] gleich einer [`hexadecimal`][hex]_), solange die Typen für den Vergleich implizit umgewandelt werden können.

Für die anderen numerischen Typen ([komplexe Zahlen][complex numbers], [Dezimalzahlen][decimal numbers], [Brüche][rational numbers]) sind Vergleichsoperatoren dort definiert, wo sie „Sinn ergeben“ (_wo eine implizite Konvertierung das Ergebnis nicht ändert_), lösen aber einen `TypeError` aus, wenn die zugrunde liegenden Objekte für den Vergleich nicht genau umgewandelt werden können.
Weitere Informationen zu den Regeln, die Python für numerische Konvertierungen verwendet, findest du unter [arithmetische Konvertierungen][arithmetic conversions] in der Python-Dokumentation.

```python
>>> import fractions

# A string cannot be converted to an int.
>>> 17 == '17'
False

# An int can be converted to float for comparison.
>>> 17 == 17.0
True

# The fraction 6/3 can be converted to the int 2
# The int 2 can be converted to 0b10 in binary.
>>> 6/3 == 0b10
True

# An int can be converted to a complex 
# number with a 0 imaginary part.
>>> 17 == complex(17)
True

# The fraction 2/5 can be converted to the float 0.4
>>> 0.4 == 2/5
True

>>> complex(2/5, 1/2) == complex(0.4, 0.5)
True
```

Jeder geordnete Vergleich einer Zahl mit einem `NaN`-Typ (_keine Zahl_) ist `False`.
Ein verwirrender Nebeneffekt von Pythons `NaN`-Definition ist, dass `NaN` nie gleich `NaN` ist.
Wenn du neugierig bist, warum `NaN` in Python so definiert wurde, ist dieser [Stack-Overflow-Beitrag zu NaN][so nan post] rund um die Festlegung des internationalen Standards eine interessante Lektüre.

```python
>>> x = float('NaN')

>>> 3 < x
False

>>> x < 3
False

# NaN never compares equal to NaN
>>> x == x
False
```

## Strings vergleichen

Strings (`str`) werden [_lexikografisch_][lexographic order] verglichen, anhand ihrer einzelnen Unicode-Codepunkte (_das Ergebnis der Übergabe jedes Codepunkts im `str` an die eingebaute Funktion [`ord()`][ord], die einen `int` zurückgibt_).
Wenn alle Codepunkte in beiden Strings übereinstimmen und _**in derselben Reihenfolge**_ stehen, gelten die beiden Strings als gleich.
Dieser Vergleich erfolgt „paarweise“: erstes mit erstem, zweites mit zweitem usw.
In Python 3.x können `str` und `bytes` nicht direkt umgewandelt/verglichen werden.

```python
>>> 'Python' > 'Rust'
False

>>> 'Python' > 'JavaScript'
True

# Examples with Mandarin.
# hello < goodbye
>>> '你好' < '再见'
True

# ord() of first characters
>>> ord('你'), ord('再')
(20320, 20877)

# ord() of second characters
>>> ord('好'), ord('见')
(22909, 35265)

# And with Korean words.
# Pretty < beautiful.
>>> '예쁜' < '아름다운'
False

>>> ord('예'), ord('아')
(50696, 50500)
```

## Vergleich von Container-Datentypen

Container-Datentypen (_`lists`, `tuples`, `sets`, `dicts` usw._) werden ebenfalls [_lexikografisch_][lexographic order] verglichen: Sie sind gleich, wenn beide Container dieselben Daten **und** dieselben Datentypen haben (_im Fall von `lists` und `tuples` müssen sie auch dieselbe **Reihenfolge** haben_), andernfalls sind sie ungleich.

```python
>>> [1, 2] == [1, 2]
True

# But if the data is not in the same order, they are not equal.
>>> [2, 1] == [1, 2]
False

# The same holds true for tuples
>>> (3,4,5) == (5,4,3)
False

# Length is also compared
>>> [1, 2] < [1, 2, 3]
True

# Comparing dicts
>>> {'name': 'John', 'age': 19} == {'name': 'John', 'age': 18}
False

>>> {'name': 'John', 'age': 19} == {'name': 'John', 'age': 19}
True
```

## Verkettete Vergleiche

Vergleichsoperatoren können _beliebig_ verkettet werden.
Beachte, dass die Auswertung eines Ausdrucks von `left` nach `right` erfolgt.
Zum Beispiel ist `x < y <= z` äquivalent zu `x < y and y <= z`, mit der Ausnahme, dass `y` **nur einmal** ausgewertet wird.
In beiden Fällen wird `z` **überhaupt nicht** ausgewertet, wenn `x < y` als `False` erkannt wird.
Das nennt man oft `short-circuit evaluation`: Die Auswertung stoppt, wenn der Wahrheitswert des Ausdrucks bereits bestimmt wurde.

`Short circuiting` wird von verschiedenen booleschen Operatoren, Funktionen und auch von der Vergleichsverkettung in Python unterstützt.
Anders als in vielen anderen Programmiersprachen, darunter `C`, `C++`, `C#` und `Java`, haben verkettete Ausdrücke wie `a < b < c` in Python eine konventionelle [mathematische Interpretation][three way boolean comparison] und Priorität.

```python
>>> x = 2
>>> y = 5
>>> z = 10

>>> x < y < z
True

>>> x < y > z
False

>>> x > y < z
False
```

## Identitätsvergleiche

Die Operatoren `is` und `is not` prüfen die [_Identität_][object identity] eines Objekts, im Gegensatz zum _Wert_ eines Objekts.
Die Identität eines Objekts ändert sich nach der Erstellung nie und kann mit der Funktion [`id()`][id function] ermittelt werden.

`<apple> is <orange>` ergibt `True` **_und nur dann_**, wenn `id(<apple>)` == `id(<orange>)` ist.
`<apple> is not <orange>` liefert das Gegenteil.

Aufgrund ihres Singleton-Status sollten `None` und `NotImplemented` immer unter Verwendung von `is` und `is not` mit Elementen verglichen werden.
Siehe die Python-Referenzdokumentation zu [Wertvergleichen][value comparisons none] und [PEP8][PEP8 programming recommendations] für weitere Details zu dieser Konvention.

```python

# A list of favorite numbers.
>>> my_fav_numbers = [1, 2, 3]

>>> your_fav_numbers = my_fav_numbers

>>> my_fav_numbers is your_fav_numbers
True

# The returned id will differ by system and Python version.
>>> id(my_fav_numbers)
4517478208

# your_fav_numbers is only an alias pointing to the original my_fav_numbers object.
# Assigning a new name does not create a new object.
>>> id(your_fav_numbers)
4517478208


>>> my_fav_numbers is not your_fav_numbers
False

>>> my_fav_numbers is not None
True

>>> my_fav_numbers is NotImplemented
False
```

## Mitgliedschaftsvergleiche

Die Operatoren `in` und `not in` prüfen die _Mitgliedschaft_.
`<fish> in <soup>` ergibt `True`, wenn `<fish>` ein Mitglied von `<soup>` ist (_wenn `<fish>` eine Teilmenge von `<soup>` ist oder in `<soup>` enthalten ist_), andernfalls ergibt es `False`.
`<fish> not in <soup>` liefert die Negation, also das _Gegenteil von_ `<fish> in <soup>`.

Bei den Typen String und `bytes` ist `<name> in <fullname>` `True` **_und nur dann_**, wenn `<name>` ein Teilstring von `<fullname>` ist.

```python

# A set of lucky numbers.
>>> lucky_numbers = {11, 22, 33}
>>> 22 in lucky_numbers
True

>>> 44 in lucky_numbers
False

# A dictionary of employee information.
>>> employee = {'name': 'John Doe', 'id': 67826, 'age': 33, 'title': 'ceo'}

# Checking for the membership of certain keys.
>>> 'age' in employee
True

>>> 33 in employee
False

>>> 'lastname' not in employee
True

# Checking for substring membership
>>> name = 'Super Batman'
>>> 'Bat' in name
True

>>> 'Batwoman' in name
False
```
