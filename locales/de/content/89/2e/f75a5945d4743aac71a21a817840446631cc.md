# Über

In C# ist ein Tupel eine Datenstruktur, die Daten organisiert und zwei oder mehr Felder beliebigen Typs enthält.

Ein Tupel wird typischerweise erstellt, indem du zwei oder mehr durch Kommas getrennte Ausdrücke in runde Klammern setzt.

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

Wie jeder andere Ausdruck kann ein Tupel auf vielfältige Weise verwendet werden: in [Zuweisungen][tuple-assignment], zum Initialisieren eines Felds oder einer Variable, als [Rückgabewert][tuple-return-values] einer Methode oder als übergebener Parameter. Sie können auf [Gleichheit][tuple-equality] geprüft werden. Die Gleichheit von Tupeln wird in der Übung `pattern-matching-tuples` vollständig veranschaulicht, aber der Vollständigkeit halber ist unten ein Beispiel im Code angegeben.

Felder werden über die Punktsyntax extrahiert. Standardmäßig heißt das erste Feld `Item1`, das zweite `Item2` und so weiter. Von der Standardbenennung abweichende Namen werden weiter unten unter _Namensgebung_ besprochen.

Ein Tupel kann als generischer Parameter verwendet werden, z. B. `IList<(bool, string)>`

Außerdem unterstützen Tupel die „Dekonstruktion“, die weiter unten besprochen wird, und können im Musterabgleich verwendet werden, der in einer späteren Übung behandelt wird.

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

Diese [Einführung][tuples] zeigt, wie du Tupel definierst und verwendest.

## Namensgebung

Feldnamen wie `Item1` machen den Code nicht gerade lesbar. Es gibt drei Möglichkeiten, den Feldern Namen zu geben: a) in der Typdeklaration, b) im Ausdruck, der das Tupel erstellt, oder c) mithilfe von [Tupelprojektionsinitialisierern][tuple-projection-initializers] (hier nicht gezeigt).

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

Versuch nicht, beim Benennungsmechanismus zu clever zu sein. Er ist wirklich nur syntaktischer Zucker. Du kannst die Namen eines Tupels beispielsweise nicht ändern, indem du ihm ein anderes Tupel zuweist.

## Dekonstruktion

Manchmal ist es praktisch, ein Tupel zu nehmen und seine Felder mehreren Variablen zuzuweisen und sie dabei gegebenenfalls zu initialisieren. Dieser Mechanismus heißt [Dekonstruktion][tuple-deconstruction]. (Er lässt sich auch auf deine eigenen Objekte anwenden. Siehe [hier][udt-deconstruction].)

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## Zuweisung an Felder

Die Felder von Tupeln können einzeln zugewiesen werden. Angesichts des Trends in C# hin zur Unveränderlichkeit ist diese Art der Verwendung jedoch nicht weit verbreitet. Tupel werden oft so verwendet, als wären sie unveränderlich, was sie natürlich nicht sind.

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## Hintergrund

Die Tupel, um die es hier geht, solltest du nicht mit [`System.Tuple`][system-tuple] verwechseln, das wahrscheinlich nur in Legacy-Codebasen zu finden ist.

Etwas verwirrender wird es bei `System.ValueTuple`. Die [Dokumentation][system-value-tuple] für die letzte Überladung von [`System.ValueTuple`][system-value-tuple] besagt: „Die Werttupeltypen bieten die Laufzeitimplementierung, die Tupel in C# unterstützt.“ Mit „Werttupeltypen“ meinen sie hier die generischen Überladungen von `System.ValueTuple`. Mit „Tupel“ meinen sie die Dinge, mit denen wir uns in dieser Übung beschäftigt haben. Im Grunde sagen sie damit, dass `System.ValueTuple` ein Implementierungsdetail von Tupeln ist. Das dürfte die meisten Leute die meiste Zeit kaum interessieren. Leider ist ein Großteil der Dokumentation über „Tupel“, auch die von Microsoft selbst, reichlich mit Verweisen auf `System.ValueTuple` gespickt. Wahrscheinlich kannst du solche Verweise getrost überfliegen.

## Weitere Verwendungen und Einschränkungen

Musterabgleich ist eine besonders ergiebige Verwendung für Tupel. Das wird in einer späteren Übung behandelt.

Tupel erlauben noch einige kleinere stilistische Spielereien:

- Mehrfachzuweisung (besonders in Konstruktoren), z. B. `(this.field1, this.field2) = (arg1, arg2);`
- Werte tauschen oder wiederverwenden, z. B. `(a, b) = (b, a);`
- Verwendung anstelle eines `struct` in einer Liste
- Verwendung als Wörterbuchschlüssel oder als Inhalt einer Menge.
- Verwendung in LINQ. (LINQ wird in späteren Übungen behandelt.)

Die Dokumentation beschreibt Tupel als einen leichtgewichtigen Mechanismus, und darin liegt der Schlüssel zu ihrer erfolgreichen Verwendung. Ein Tupel statt einer Klasse oder eines structs zu verwenden, kann zu mühsamen Wiederholungen seiner Feldtypen und möglicherweise seiner Namen führen. Das gilt besonders für die Verwendung als Methodenargument oder als generisches Argument in Sammlungen.

Am besten setzt du Tricks wie Mehrfachzuweisung und Vertauschen mit Bedacht ein.

Andere relationale Operationen als Gleichheit und Ungleichheit werden nicht unterstützt.

Beachte, dass Tupel erst vor relativ kurzer Zeit in die Sprache eingeführt wurden (C# 7). Wenn du sie verwenden möchtest, solltest du sicherstellen, dass deine Codebasis [Version][language-version] 7 oder höher der Sprache verwendet.
