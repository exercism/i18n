# Über Bedingungen

## Vergleichsoperatoren

[Vergleichsoperatoren][operators] ähneln denen vieler anderer Sprachen, mit ein paar Erweiterungen.

Für Gleichheit gibt es die Operatoren `==` (gleich) und `!=` (ungleich).

```Kotlin
val txt = "abc"
txt == "abc" // => true
txt != "abc" // => false
```

Zusätzlich prüfen die Operatoren `===` und `!==` auf [„referenzielle Gleichheit“][referential-equality]: `a === b` genau dann, wenn `a` und `b` auf dasselbe Objekt zeigen. Das wird später im Syllabus klarer werden.

Auch die Operatoren für größer und kleiner sind wie gewohnt.

```Kotlin
1 < 3 // => true
3 > 3 // => false
3 <= 3 // => true
4 >= 3 // => true
```

## Verzweigungen mit `if`

Das ist die vollständige Form eines [`if`-Ausdrucks][if-else]:

```Kotlin
if (conditional1) {
//    something...
} else if (conditional2) {
//    something...
} else {
//    something...
}
```

- Runde Klammern `()` um jede Bedingung sind erforderlich.
- Eine Bedingung muss zu einem booleschen Wert `true` oder `false` ausgewertet werden.
  Kotlin kennt kein Konzept von „truthy“ und „falsy“, wie es in manchen Sprachen zu finden ist.
- Geschweifte Klammern `{}` sind optional, wenn es nur einen einzigen Ausdruck gibt.
- Sowohl `else if` als auch `else` sind optional, und es kann mehrere `else if`-Blöcke geben.

Der `if`-Ausdruck kann auch verwendet werden, um einen Wert „auszuwählen“:

```Kotlin
val number = 100000
val description = if (number > 100) "number is over 100" else "number is less than 100"
// => description = "number is over 100"
```

## Alternativen?

Kotlin hat den ternären Operator `? :` aus Java bewusst _nicht_.
Bevorzugt wird eine kompakte Form von `if ... else`:

```Kotlin
val result = if (isOk) goodValue else badValue

return if (isOK) goodValue else badValue
```

Anders als in Ruby braucht die kompakte `if ... else`-Form *immer* ein `else` und kann deshalb nicht als Guard-Anweisung verwendet werden:

```kotlin
return 42 if (isOk)
// Syntax error: Unexpected tokens (use ';' to separate expressions on the same line).
// Syntax error: Expecting an expression.

return if (isOk) true
// 'if' must have both main and 'else' branches when used as an expression.
```

Beachte, dass `if` in Kotlin ein [_Ausdruck_][expression] ist, der einen Wert zurückgibt.
Es ist keine [_Anweisung_][statement] wie in Java.

In einem späteren Konzept werden wir sehen, dass Kotlin ein mächtiges [`when`][when]-Konstrukt hat, das lange Ketten von `else if`-Klauseln durch Pattern Matching ersetzen soll.
