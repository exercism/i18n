# Einführung

Gleam verwendet keine Ausnahmen zur Fehlerbehandlung. Stattdessen geben Funktionen, die entweder erfolgreich sein oder fehlschlagen können, den generischen Typ `Result` zurück.

Der Typ `Result` ist in die Sprache eingebaut, du musst ihn also nicht definieren oder importieren. Wenn du ihn aber selbst definieren würdest, sähe das so aus:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

Die Variante `Ok` wird zurückgegeben, wenn eine Funktion erfolgreich ist, und die Variante `Error`, wenn eine Funktion fehlschlägt.

Results sind in Gleam sehr verbreitet, und Gleam-Programmierer nutzen häufig das [`gleam/result`-Modul](https://hexdocs.pm/gleam_stdlib/gleam/result.html), um die Arbeit mit ihnen zu erleichtern.

Mit der Funktion `result.map` kannst du eine Funktion auf den Wert in einem Result anwenden, wenn es ein `Ok` ist, oder ein `Error` unverändert durchreichen.

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

Die Funktion `result.try` ist ähnlich, aber die Callback-Funktion soll ein Result zurückgeben. Das ist nützlich, um mehrere Funktionen zu verketten, die Results zurückgeben.

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
