# Anweisungen

Je mehr du über das Programmieren lernst, desto mehr denkst du, dass das mehr als nur eine Modeerscheinung sein könnte.
Vielleicht steckt sogar ein Geschäft dahinter: Menschen schreiben Code, sie wollen ihn speichern, teilen, zusammenarbeiten, vielleicht sogar Feedback bekommen.

Also los, bauen wir einen Dienst, der Menschen zum Programmieren ermutigt: hup, hup, Leute, benutzt git!
Nennen wir ihn... GitHup.

Du machst dich daran, eine REST-JSON-API zu bauen: Benutzer, Pull Requests, Kommentare, das Backend ist schnell fertig.
Hier ist ein Beispiel für die Nutzlast, die ausgeliefert wird, wenn du den Server nach der Liste der Kommentare zu einem Pull Request fragst:

Natürlich wird das Frontend in Elm geschrieben, aber zuerst musst du herausfinden, was es mit diesen berüchtigten Decodern und Encodern auf sich hat.

```exercism/note
Spaß beiseite, die Anforderungen dieser Übung stammen direkt aus GitHubs REST-API-Endpunkten für Pull-Request-Review-Kommentare.
Einige Felder wurden der Einfachheit halber aus den JSON-Schemas entfernt, aber näher an echte Anwendungen kommt man kaum heran.
```

## 1. ID, bitte!

Deinem Adlerauge ist aufgefallen, dass sowohl Kommentare als auch Benutzer ein Feld `id` haben, ein perfekter Ausgangspunkt.

Definiere `decodeId`, sodass es ein JSON-Objekt mit einer ganzzahligen `id` dekodieren kann.

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. Wie heiße ich noch gleich?

Du bemerkst im obigen Beispiel, dass nicht alle Benutzer einen Namen haben.

Definiere `decodeName`, sodass es einen String im Feld `name` dekodieren kann, falls einer vorhanden ist.
Kein Name? Kein Problem, gib einfach `Nothing` zurück.
Dieser Decoder darf niemals fehlschlagen.

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. Benutzer? Den kenne ich kaum!

Beim Dekodieren von Benutzern sind wir schon fast auf halbem Weg, bringen wir es zu Ende.

Definiere `decodeUser`, sodass es ein JSON-Benutzerobjekt dekodieren kann.
Achte darauf, `decodeId` und `decodeName` in `decodeUser` zu verwenden.

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. Ich bin ein starker, unabhängiger Kommentar

Manche Kommentare in einer Pull-Request-Review sind eigenständig und haben daher keine `pull_request_review_id`.
Die Spezifikation erwähnt jedoch, dass es in einem solchen Fall trotzdem ein Feld `pull_request_review_id` geben sollte, aber der Wert sollte `null` sein, das `Nothing` des kleinen Mannes.

Definiere `decodePullRequestReviewId`, sodass es eine Ganzzahl im Feld `pull_request_review_id` dekodieren kann, falls eine vorhanden ist.
Wenn es keine Ganzzahl gibt, sollte dort `null` stehen, und wenn es kein `null` gibt, sollte der Decoder fehlschlagen.

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. Nebenjob

Als Nächstes kommt dieses interessant aussehende Feld `side`.
In einer Pull-Request-Review kannst du Code kommentieren, der entfernt wurde (auf der `Left`-Seite des Bildschirms), oder Code, der hinzugefügt wurde (auf der `Right`-Seite des Bildschirms).

Definiere `decodeSide`, sodass es entweder `"LEFT"` oder `"RIGHT"` im Feld `side` dekodieren und der entsprechenden Typvariante zuordnen kann.

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. Das Erwachen der Links

Jeder Kommentar hat eine Reihe von Links, die über die Kommentare hinweg nicht einheitlich zu sein scheint.

Definiere `decodeLinks`, sodass es eine Sammlung von URLs im Feld `_links` dekodieren kann.
Die Namen und die Anzahl der Links können variieren, stelle sicher, dass du das berücksichtigst.
Die Links selbst sind JSON-Objekte, die immer ein Feld `href` haben sollten.

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. Ja, Kommentare

Fast geschafft, bringen wir es zu Ende.

Definiere `decodeComment` und `decodeComments`, sodass sie ein einzelnes JSON-Kommentarobjekt bzw. eine Liste von Kommentaren dekodieren können.
Achte darauf, alle bisher definierten Funktionen in `decodeComment` zu verwenden, mit Ausnahme von `decodeName`.
Natürlich sollte `decodeComments` ebenfalls `decodeComment` verwenden.

## 8. Alles fügt sich zusammen

Eine Funktion fehlt noch in all dem: einen neuen Kommentar an den Server senden zu können.
Dafür brauchst du das Gegenteil eines Decoders, du musst in der Lage sein, ein Elm-`Comment` in einen JSON-`Value` umzuwandeln.

Definiere `encodeComment`, sodass es jeden gültigen `Comment` kodieren kann.
Die Reihenfolge der Felder spielt keine Rolle, solange der Encoder einen Wert erzeugen kann, den `decodeComment` dekodieren kann.
