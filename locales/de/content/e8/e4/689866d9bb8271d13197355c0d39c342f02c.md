# Einführung

Manchmal muss ein Zustand zwischen mehreren Wörtern geteilt werden, ohne ihn jedes Mal durch ihre Stack-Effekte zu schleusen. Factors *dynamische Variablen*, die mit `SYMBOL:` deklariert werden, geben jedem Wort Zugriff auf einen Wert, der in einem Namensraum gespeichert ist.

## `SYMBOL:` und `SYMBOLS:`

`SYMBOL: name` deklariert eine Variable. `SYMBOLS: a b c ;` deklariert mehrere auf einmal:

```factor
USING: namespaces ;

SYMBOLS: counter total ;
```

## Setzen und Abrufen

`set-global` und `get-global` (in [`namespaces`][namespaces]) arbeiten auf dem globalen Namensraum:

```
set-global    ( value variable -- )
get-global    ( variable -- value )
change-global ( variable quot: ( old -- new ) -- )
```

```factor
0 counter set-global
counter get-global .         ! => 0
counter [ 10 + ] change-global
counter get-global .         ! => 10
```

Für Zustand auf Modulebene sind die `-global`-Varianten genau das Richtige.

## Bereichsgebundene Bindungen mit `with-variable`

Eine dynamische Variable unterstützt außerdem eine zweite, *bereichsgebundene* Variante. `set` / `get` / `change` (ohne das Suffix `-global`) lesen und schreiben den *aktuellen* dynamischen Gültigkeitsbereich, und `with-variable` (in [`namespaces`][namespaces]) erzeugt einen frischen Gültigkeitsbereich für die Dauer einer Quotation:

```
with-variable ( value variable quot -- )
set           ( value variable -- )
get           ( variable -- value )
change        ( variable quot: ( old -- new ) -- )
```

Die Variable ist an `value` gebunden, während `quot` läuft; sobald es zurückkehrt, verschwindet die Bindung. So kann ein äußerer Aufrufer einen Wert „injizieren“, den innerer Code lesen kann, ohne ihn durch jede Stack-Signatur zu schleusen.

```factor
SYMBOL: greeting

"Hello" greeting [
    greeting get .                ! => "Hello"
    "Howdy" greeting set
    greeting get .                ! => "Howdy"
    greeting [ "!" append ] change
    greeting get .                ! => "Howdy!"
] with-variable

greeting get-global .    ! => f   (the scoped binding is gone)
```

Diese Übung verwendet durchgehend die globale Variante. Es lohnt sich aber, die parallele Familie `set`/`get`/`change` zu erkennen, wenn du Code von anderen liest.

## Veränderliche Vektoren

Weil dynamische Variablen eine Referenz halten, kannst du darin eine *veränderliche* Sammlung speichern und sie an Ort und Stelle aktualisieren:

```factor
SYMBOL: history

V{ } clone history set-global
"first event" history get-global push
"second event" history get-global push
history get-global .
! => V{ "first event" "second event" }
```

`V{ … }` ist ein Vektor-Literal. `clone` ein `V{ }`-Literal immer, bevor du es speicherst: Literale werden zwischen Aufrufen geteilt.

## `find`: der erste Treffer

`find` (in [`sequences`][sequences]) gibt das erste Element zurück, für das ein Prädikat wahr ist, zusammen mit seinem Index:

```
find ( seq quot -- index elt/f )
```

Wenn nichts übereinstimmt, sind beide Werte `f`. Den Index mit `nip` wegzulassen und `unless*` zu verwenden ist die übliche Kombination für „Standardwert, falls nichts gefunden wird“.

## `reject`: die Treffer verwerfen

`reject` (ebenfalls in [`sequences`][sequences]) ist das Gegenteil von `filter`: Es gibt die Elemente zurück, die das Prädikat *nicht erfüllen*.
