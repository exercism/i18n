# Tests

Eine Möglichkeit, Exercism-Übungen zu lösen, ist, die Website aufzurufen und den Editor im Browser zu nutzen, in dem du deine Lösung bearbeiten und testen kannst.

Alternativ kannst du die Übungen auf deinen eigenen Computer herunterladen und dort mit deinem eigenen Editor und einer Reihe von Tools deine Lösung erstellen, testen und schließlich einreichen.

Dabei nutzt du die Exercism-Kommandozeile, auch CLI genannt, eine Anwendung, die in einem Terminal- oder Kommandozeilenfenster läuft. Die Installationsanleitung findest du hier: [Dokumentation zur Exercism-Kommandozeile](https://exercism.org/docs/using/solving-exercises/working-locally).

## Vorgehen beim Testen

Exercism geht davon aus, dass du schon etwas Erfahrung mit testgetriebener Entwicklung hast. Jede Übung besteht aus einer _`stub file`_, einer _`test file`_ mit einer Reihe vorab geschriebener Tests und einem _`test script`_, mit dem die Tests ausgeführt werden.

Um eine Übung zu lösen, musst du die _`stub file`_ Schritt für Schritt so weiterentwickeln, dass sie schließlich Code enthält, der alle Tests besteht.

Praktisch bedeutet das, dass du sowohl die _`stub file`_ als auch die _`test file`_ aktiv bearbeitest. Beachte, dass du die _`test file`_ nicht bearbeitest, um den Testcode zu ändern, sondern um fehlschlagende Tests auszukommentieren.

Anfangs sind alle Tests bis auf einen auskommentiert. Während du die _`stub file`_ dann zu einer funktionierenden Lösung ausbaust, kommentierst du immer mehr Tests ein, bis schließlich alle Tests erfolgreich durchlaufen.

## Testinfrastruktur

Du musst keine zusätzliche Software installieren, denn die Bestandteile des Testframeworks sind im Download der Übung enthalten.

Das Testframework besteht aus drei Rexx-Dateien, die beim Testen mit der Übungslösung zu einer Testcode-Einheit zusammengesetzt werden. Diese führt dann das _`test script`_ aus, und die Testergebnisse werden im Terminal ausgegeben.

Bitte bearbeite oder lösche das _`test script`_ nicht, und auch keine andere Datei des Testframeworks. Falls doch einmal etwas schiefgeht, lade die Übung einfach über die Exercism-Kommandozeile erneut herunter und achte darauf, deinen Lösungscode zu sichern.

## Tests ausführen

Beim Lösen einer Übung gehst du so vor:

1. Öffne ein Terminal
2. Lade die ausgewählte Übung herunter
3. Wechsle in das Übungsverzeichnis
4. Lade Stub-Datei und Testdatei in deinen Editor
5. Und dann immer wieder:

    1. Führe das Testskript aus
    2. Schreibe Code in deine Stub-Datei (die damit langsam zu einer Lösungsdatei wird) und kommentiere Tests in deiner Testdatei aus oder wieder ein

6. Wenn alle Tests bestehen, reiche die Lösung bei Exercism ein
7. Schließe das Terminal
8. Feiere deinen Erfolg

Ein konkretes Beispiel in einem Linux-Terminal mit der Übung `acronym` (angenommen, der Exercism-Arbeitsbereich ist:`/home/exercism`)

Übung herunterladen:

`exercism download --track=rexx --exercise=acronym`

In das Übungsverzeichnis wechseln:

`cd /home/exercism/rexx/acronym`

Lade aus einem anderen Fenster, vielleicht mit grafischer Oberfläche, `acronym.rexx` und `acronym-check.rexx` in deinen Editor, also die Stub- bzw. die Testdatei.

Führe das Testskript aus: `./test-acronym`

und alle Tests sollten fehlschlagen:

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Kommentiere alle Tests bis auf den ersten in der Datei `acronym-check.rexx` aus und führe das Testskript erneut aus; dann sollte die folgende Ausgabe erscheinen:

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

Überarbeite `acronym.rexx` so lange, bis funktionierender Code darin steht, und irgendwann sollte die Ausgabe des Testskripts so aussehen:

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

Kommentiere nun die übrigen Tests ein, führe das Testskript erneut aus, und schließlich sollte die Ausgabe so aussehen:

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Jetzt kannst du deine Übungslösung einreichen:

`exercism submit acronym.rexx`

und kassierst einen weiteren Reputationspunkt. Schließe das Terminal, wenn du fertig bist.

Für dich als macOS-Nutzer verläuft der Ablauf ganz ähnlich, denn macOS ist ein von UNIX abgeleitetes Betriebssystem.

Für Windows-Nutzer ist der Ablauf im Großen und Ganzen ähnlich, es gibt aber ein paar kleine Unterschiede:

- Das Fenster _Command Prompt_ ist das Terminal
- In Pfaden ersetzen Backslashes die Schrägstriche, das Arbeitsverzeichnis könnte also so aussehen:

  `cd C:\Users\MyName\exercism\rexx\acronym`

- Das Testskript führst du so aus:

  `test-acronym`  oder  `test-acronym.bat`

Die Testausgabe ist dieselbe.
