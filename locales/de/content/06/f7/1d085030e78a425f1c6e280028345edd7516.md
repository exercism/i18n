# Einführung in die Umleitung

In der Welt der Kommandozeile arbeiten Programme oft mit drei Standard-Datenströmen:

1. **Standardeingabe** (`stdin`): Woher ein Programm seine Eingabe bekommt (normalerweise von der Tastatur).
1. **Standardausgabe** (`stdout`): Wohin ein Programm seine normale Ausgabe sendet (normalerweise auf den Terminalbildschirm).
1. **Standardfehlerausgabe** (`stderr`): Wohin ein Programm Fehlermeldungen sendet (normalerweise auf den Terminalbildschirm).

Erinnere dich, dass wir sie im Kapitel [Pipelines und Befehlslisten][pipelines] eingeführt haben.

~~~~exercism/note
Pipelines kann man als eine Form der Umleitung betrachten: Die Standardausgabe eines Programms wird direkt an die Standardeingabe eines anderen gesendet.
Pipelines haben wir bereits behandelt.
In diesem Konzept geht es um die Umleitung von und zu Dateien.
~~~~

Die Umleitung in der Shell ist ein mächtiges Werkzeug, mit dem du das Ziel dieser Ströme änderst.
Statt dass ein Programm von der Tastatur liest oder auf den Bildschirm schreibt, kannst du die Eingabe aus einer Datei umleiten oder die Ausgabe in eine Datei schreiben.
Das gibt dir viel Flexibilität und Kontrolle darüber, wie Programme mit Daten umgehen.

## Die wichtigsten Umleitungsoperatoren

Hier sind die gebräuchlichsten Umleitungsoperatoren und was sie tun:

### `>` (Ausgabeumleitung)

* Zweck: Die Standardausgabe (`stdout`) eines Befehls in eine Datei umleiten.
* Verhalten:
  * Wenn die Datei nicht existiert, wird sie erstellt.
  * Wenn die Datei existiert, wird ihr Inhalt überschrieben.
* Beispiel:

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
Die Umleitung erfolgt **bevor** der Befehl ausgeführt wird.
Das heißt, du kannst nicht in dieselbe Datei umleiten, aus der du lesen musst.

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

Im zweiten Befehl des obigen Beispiels

1. kürzt Bash zuerst die in der Umleitung genannte Datei.
   Das zerstört den bisherigen Inhalt und lässt eine leere Datei zurück.
2. Dann liest Bash die nun leere Datei.
3. Dann schreibt Bash den Inhalt (also nichts) zurück in die Datei.
~~~~

### `>>` (Anhängen der Ausgabe)

* Zweck: Die Standardausgabe (`stdout`) eines Befehls an eine Datei anhängen.
* Verhalten:
  * Wenn die Datei nicht existiert, wird sie erstellt.
  * Wenn die Datei existiert, wird die Ausgabe am Ende der Datei angehängt.
* Beispiel:

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<` (Eingabeumleitung)

* Zweck: Die Standardeingabe (`stdin`) eines Befehls aus einer Datei umleiten.
* Verhalten: Der Befehl liest seine Eingabe aus der angegebenen Datei statt von der Tastatur.
* Beispiel:

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>` (Fehlerumleitung):

* Zweck: Die Standardfehlerausgabe (`stderr`) eines Befehls in eine Datei umleiten.
* Verhalten: Fehlermeldungen werden in die angegebene Datei geschrieben statt aufs Terminal.
* Beispiel:
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

Mit `2>>` kannst du die Standardfehlerausgabe an eine Datei _anhängen_.

### Weitere Umleitungen

Es gibt auch Umleitungen, die sowohl `stdin` als auch `stderr` zusammenführen können.
Weitere Details findest du im [Handbuch][manual].

## `/dev/null`

`/dev/null` ist eine spezielle Datei, die

* eine leere Datei ist, wenn du aus ihr liest, und
* alle Daten verwirft, die in sie geschrieben werden.

Manchmal wird sie auch als „Bitbucket“ bezeichnet.
Sie ist nützlich, um Ausgaben oder Fehler zu unterdrücken.

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## Umleitungen kombinieren

Du kannst mehrere Umleitungen auf einmal angeben.

```bash
some_command < input.txt > output.txt 2> error.txt
```

Eine Umleitung lässt sich kopieren.

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

Wenn du `2>&1` siehst, dann lies das als „leite stderr dorthin um, _wohin stdout **gerade** zeigt_“.
Bash verarbeitet Umleitungsanweisungen streng von links nach rechts. Das heißt, du kannst Folgendes machen:

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## Dateideskriptoren

Im Zusammenhang mit Shell-Programmierung und Betriebssystemen wie Linux/Unix ist ein Dateideskriptor (FD) eine nicht-negative Ganzzahl, die als Kennung oder Handle für eine geöffnete Datei oder eine I/O-Ressource (Eingabe/Ausgabe) dient.
Stell es dir wie ein Etikett oder eine Referenznummer vor, mit der das Betriebssystem geöffnete Dateien und Datenströme im Blick behält.

Die Zahlen, die du auf der linken Seite von Umleitungen siehst, sind Dateideskriptoren.

Die Standard-I/O-Ströme bekommen die ersten drei Dateideskriptoren:

* Standardeingabe ist FD 0
* Standardausgabe ist FD 1
* Standardfehlerausgabe ist FD 2

Neue Dateideskriptoren kannst du mit dem Befehl `exec` und Umleitungsoperatoren setzen oder anlegen.

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

Diese Technik wirkt ziemlich verschachtelt, aber sie kann sehr nützlich sein, wenn dein Skript von einer anderen Software ausgeführt wird und die Standardausgabe automatisch von dieser Software abgefangen wird.
Der Befehl `bats`, mit dem in diesem Track die Unit-Tests ausgeführt werden, funktioniert so: `bats` fängt die Standardausgabe und die Standardfehlerausgabe eines Tests ab, aber Debug-Nachrichten, die an FD 3 gesendet werden, werden auf dem Terminal angezeigt.
~~~~

## Zusammenfassung

Warum ist die Umleitung nützlich?

* Ausgabe speichern: Die Ergebnisse eines Befehls für späteres Nachschauen oder Weiterverarbeiten aufbewahren.
* Protokollieren: Fehlermeldungen zum Debuggen auffangen.
* Automatisieren: Verkette Befehle miteinander und nutze die Ausgabe des einen als Eingabe des anderen.
* Filtern: Unerwünschte Ausgabe verwerfen.
* Stapelverarbeitung: Daten aus Dateien verarbeiten, statt sie manuell einzugeben.
* Skripte schreiben: Umleitungen sind unverzichtbar, um robuste Shell-Skripte zu schreiben.

Mit Shell-Umleitungen hast du eine fein abgestufte Kontrolle darüber, wie Programme mit Daten umgehen. So baust du komplexe Workflows auf und verwaltest Informationen effektiv.
