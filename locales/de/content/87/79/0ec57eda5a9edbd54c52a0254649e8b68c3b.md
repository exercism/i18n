# Ergänzung zu den Anweisungen

## Vor- und Nachteile von `from_quote`
Diese Übung definiert im Typ `Time` eine Funktion `from_quote`. Damit kannst du Code wie diesen schreiben:

```roc
time : Time
time = "00:01:23"
```

Dieser Code ruft zur Kompilierzeit implizit `Time.from_quote("00:01:23")` auf. Das kann das Programm potenziell beschleunigen, weil es das Parsen nicht zur Laufzeit erledigen muss, und es stellt sicher, dass Zeiten, die `from_quote` ablehnt, schon zur Kompilierzeit auffallen und nicht erst zur Laufzeit. Außerdem wird der Code dadurch schön lesbar. Hier ist zum Beispiel einer der Tests aus dieser Übung:

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

Wer diesen Code liest, könnte allerdings annehmen, dass die Funktion `advance_time` einen `Str` entgegennimmt, obwohl sie tatsächlich einen `Time` nimmt. Das kann zu Verwirrung und Fehlern führen. Deshalb ist dir vielleicht das etwas längere, aber eindeutigere Format lieber: `"00:00:05".Time`, das `from_quote` ebenfalls zur Kompilierzeit aufruft.

In deinen eigenen Programmen ist dir vielleicht `from_str` lieber:

```roc
Time := { ... }.{
    from_str : time_str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

Du kannst `from_str` (oder jede andere reine Funktion) auch zur Kompilierzeit aufrufen, und zwar so:

```roc
Ok(time) = Time.from_str("00:01:23")
```

Hinweis: Wenn du diese Definition auf der obersten Ebene platzierst, läuft sie zur Kompilierzeit (da die Funktion rein ist und ihre Eingabe zur Kompilierzeit bekannt ist). Innerhalb einer Funktion kannst du `from_str` zur Laufzeit verwenden.
