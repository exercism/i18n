# Funktionen in `jq`

Du kannst in `jq` deine eigenen **benutzerdefinierten Funktionen** definieren, um beliebige Logik zu kapseln. _Funktionen_ verhalten sich wie eingebaute Funktionen: Sie nehmen eine Eingabe entgegen und geben null, eine oder mehrere Ausgaben aus.

## Eine Funktion definieren

Du kannst eine `jq`-_Funktion_ mit der folgenden Syntax definieren:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- beginnt mit dem `def`-Schlüsselwort,
- einem Doppelpunkt vor dem Funktionskörper,
- der Körper besteht aus einem einzigen Ausdruck,
- endet mit einem Semikolon,
- wie im Rest der `jq`-Syntax kannst du zur besseren Lesbarkeit beliebigen Leerraum verwenden.

## Wohin die Funktionen gehören

_Funktionen_ müssen definiert werden, bevor sie verwendet werden: Das hier ist ein Fehler:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Das bedeutet, dass du _Funktionen_ an den Anfang deines `jq`-Codes setzen musst, vor den „Haupt"-Ausdruck.

### Verschachtelte Funktionen

_Funktionen_ können verschachtelt werden:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Hier ist die `B`-_Funktion_ nur im Körper von `A` sichtbar.

## Gültigkeitsbereich

Eine _Funktion_ führt einen neuen **Gültigkeitsbereich** für Variablen und verschachtelte Funktionen ein.

## Argumente

Die **Argumente** einer _Funktion_ werden durch _Semikolons_ getrennt, nicht durch Kommas.
Zum Beispiel eine _Funktion_, die eine Zahl entgegennimmt und dann eine Zahl addiert und mit einer Zahl multipliziert:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
Semikolons sind nötig, weil das Komma in `jq` bereits eine Aufgabe hat: Es ist ein Operator, der Streams verbindet.

Wenn du ein Komma statt eines Semikolons verwendest, versucht `jq` zwei Aufrufe der `add_mul`-Funktion mit _einem Argument_; diese Funktion gibt es nicht, also schlägt schon der erste Aufrufversuch fehl:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

Das Komma in `5, 4` verkettet die Zahlen 5 und 4 zu einem Stream.
Wenn wir eine Funktion mit einem Stream als Argument aufrufen, ruft `jq` diese Funktion mehrfach auf, einmal für jeden Wert im Stream.
Das ist ein Beispiel für die „implizite Iteration", die `jq`-Streams innewohnt.
`10 | add_mul(5, 4)` ist äquivalent zu Folgendem.

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
Jetzt sehen wir, wie der Fehler `add_mul/1 is not defined` auftaucht.
~~~~

<!-- prettier-ignore-end -->

### Argumente sind _Ausdrücke_

Die _Argumente_ einer Funktion sind Filter, keine Werte.
In diesem Sinn verhalten sie sich wie das, was andere Sprachen als Callbacks bezeichnen:

Nehmen wir die `add_mul`-Funktion als Beispiel:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

Was passiert hier?

- Das `adder`-Argument bekommt den _Ausdruck_ `. + 5`
  - Wenn die Funktion `. + adder` ausführt, wird daraus `. + . + 5`
  - Das ergibt 25, da `. == 10`
- Ebenso ist das `multiplier`-Argument der Ausdruck `. - 2`
  - Das ergibt 8
  - Dann ist das Ergebnis `25 * 8 == 200`

### Argumente als Werte

Manchmal möchtest du ein _Argument_ in einer Variablen „materialisieren":

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Dafür gibt es eine Kurzform:

```jq
def my_func($arg):
    other stuff ...
;
```

Beachte, dass das nur „syntaktischer Zucker" ist: Der Name `arg` ohne `$` ist weiterhin im Gültigkeitsbereich der _Funktion_.

<!-- prettier-ignore -->
~~~~exercism/caution
Zum Beispiel habe ich so etwas geschrieben, um eine Übung zu lösen:

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

und ich war überrascht, dass jeder Wert des Arrays gleich dem Schlüssel war.

Das passierte, weil jq die `equals`-Funktion so sah:

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

Das **Argument** `code` _überschrieb_ die zuvor definierte **Funktion** `code`.
Das bedeutete, dass `(. | code)` einfach das **Argument** ausgibt, anstatt einen neuen Code auf Basis des Eingabewerts zu berechnen.
Somit waren `$this_code` und `$code` immer gleich.
~~~~

## Stelligkeit

_Funktionen_ haben eine **Stelligkeit**: die Anzahl der _Argumente_, die sie entgegennehmen.

_Funktionen_ können denselben Namen mit unterschiedlicher _Stelligkeit_ verwenden.
Die eingebaute Funktion [`range`][man-range] zeigt das: `range/1`, `range/2` und `range/3` existieren alle nebeneinander.

Das kann nützlich sein, um rekursive Funktionen zu definieren, die ihren Zustand über Argumente mitführen.
Zum Beispiel _könnte_ `map` so implementiert werden:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Rekursion

`jq` führt Tailcall-Optimierung durch, aber nur bei 0-stelligen Funktionen.

## Module

Ein `jq`-Modul ist eine Datei, die nur Funktionen enthält.
Module werden mit den Befehlen [`include`][man-include] oder [`import`][man-import] in ein jq-Programm eingebunden.
