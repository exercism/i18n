# Einführung

Manche Schleifen lassen sich nicht als „mach das für jedes Element einer Sequenz“ schreiben. Du musst so lange weitermachen, bis eine Bedingung kippt. Factors `while`-Kombinator ist genau dafür da: Eine Prädikat-Quotation sagt „weitermachen?“, eine Rumpf-Quotation erledigt die Arbeit eines Schritts, und `while` wiederholt das so lange, bis das Prädikat `f` liefert.

## `while` und `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` und `body` sind beides Quotationen, die auf dem Datenstapel arbeiten. `while` wiederholt die Schleife, solange `pred` einen wahren Wert hinterlässt; `until` ist das Gegenteil: Es wiederholt sie so lange, *bis* `pred` wahr wird (also solange `pred` `f` hinterlässt).

Ein einzelner Zustandswert kann auf dem Stapel zwischen Prädikat und Rumpf fließen:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

Ablauf: Das Prädikat `dup 0 >` schaut auf den laufenden Zähler; der Rumpf `dup . 1 -` gibt ihn aus und verringert ihn; die Schleife stoppt, sobald der Zähler `0` erreicht. Das abschließende `drop` verwirft diese letzte `0` vom Stapel.

## `while*`: den Wert des Prädikats behalten

```
while* ( pred body -- )
```

`while` kümmert sich nur darum, ob sein Prädikat einen wahren Wert hinterlassen hat. Den Wert selbst wirft es weg, bevor es den Rumpf ausführt. `while*` dagegen *reicht diesen Wert an den Rumpf weiter*. Nimm es immer dann, wenn Test und Rumpf dasselbe frisch berechnete Ergebnis brauchen: eine Suche, einen Treffer, ein eingelesenes Token.

Hier zeigt jeder Name auf den nächsten in einer Kette. Das Prädikat schlägt den aktuellen Namen nach; solange es einen nächsten Namen gibt, reicht `while*` ihn an den Rumpf weiter, der ihn ausgibt und von dort aus weitermacht:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at` gibt den nächsten Namen zurück oder `f`, sobald ein Name keinen Eintrag hat. Solange es einen Namen zurückgibt, übergibt `while*` diesen Namen an `dup .`, das ihn ausgibt und als Schlüssel für die nächste Suche liegen lässt. Das erste `f` stoppt die Schleife; `while*` verwirft es, sodass nichts übrig bleibt.

## Mehrere Zustandswerte mit Locals

Wenn die Schleife mehr als einen Wert mitführt, etwa eine verbleibende Liste und eine laufende Summe, wird das Jonglieren mit dem Stapel unübersichtlich. Das sauberste Muster ist, *Locals* mit `::` zu deklarieren:

```
:: word ( inputs -- outputs ) ... ;
```

Im Rumpf fügt `:> name!` einen veränderlichen Local hinzu; gelesen wird mit `name`, geschrieben mit `name!` (was den neuen Wert vom Stapel nimmt und ihn zuweist).

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

Zwei Locals hier (`rest` und `running`) decken den gesamten Zustand der Schleife ab: Das Prädikat prüft sie, der Rumpf aktualisiert sie, und am Ende wird der finale Wert zurückgegeben.

`unclip ( seq -- rest first )` schält das erste Element einer Sequenz ab. Das ist praktisch, wenn die Schleife in jeder Iteration ein Element einer Liste verbrauchen soll. Die Form `[ rest! ] dip` aktualisiert `rest` auf den verbleibenden Rest und lässt das gerade entnommene Element auf dem Stapel, damit der Rumpf es verwenden kann.
