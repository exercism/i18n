## Smalltalk und Strings

Was Strings angeht, gibt es einige offensichtliche kleine Details wie doppelte Anführungszeichen für Kommentare, einfache Anführungszeichen für Strings und eine spezielle Syntax für Zeichen (z. B. $x für das Zeichen „x“), die dich beim ersten Lesen verwirren können, weil die Konventionen anders sind als in anderen Sprachen.

Außerdem gibt es das Konzept des Symbols: ein String, der im gesamten Speicher einmalig ist. Wenn es erzeugt wird (typischerweise zur Compile-Zeit), wird der Speicher durchsucht, um festzustellen, ob ein gleiches Symbol bereits existiert, und nur das Original wird verwendet. Der Grund dafür ist nicht nur Speichereinsparung, sondern auch eine deutlich höhere Geschwindigkeit beim Vergleichen von Symbolen.

```smalltalk
"this is a comment"
'this is a string'
#'this is a symbol'
#thisIsASymbolToo
```

In Smalltalk-Programmen gibt es außerdem nur sehr wenige Kommas, weil sie keine syntaktische Rolle spielen.
Deshalb kommen Array-Literale zum Beispiel ohne Kommas aus, z. B.
`#(1 2 3 4 5)`
Das Komma ist aber ein eigenständiger Operator, und du wirst es beim Verketten zweier Strings bemerken, z. B.
`'string1', 'string2'`

Schließlich solltest du wissen, dass Strings und Characters unterschiedliche Klassen sind. Ein String ist eine Sammlung von Characters. Das kann dich beim Iterieren über Strings überraschen, weil du am Ende Zeichen an eine Methode übergibst, die Strings erwartet. Schau dir das an ...
```smalltalk
(('hello' at: 2) = $e) inspect.
(('hello' at: 2) = 'e') inspect.
```

## Smalltalk und Streams
Streams sind nützlich für das sequenzielle Lesen und Schreiben.  Sie machen den Code sauberer, weil du keinen Index erhöhen musst.
Streams arbeiten mit jeder Collection.
```smalltalk
stream := WriteStream on: String new.
stream nextPut: $h ; nextPutAll: 'ell' ; nextPut: $o.
stream contents inspect
```
