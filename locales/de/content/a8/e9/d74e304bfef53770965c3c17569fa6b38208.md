# Einführung

Julia ermutigt Programmierer, so viel Code wie möglich in Funktionen unterzubringen, die JIT-kompiliert werden können. Viele kleine Funktionen zu erstellen ist bewusst performant.

Das führt oft dazu, dass viele kleine, einfache Funktionen übrig bleiben, die kombiniert werden müssen, um nicht triviale Aufgaben zu erledigen.

Ein naheliegender Ansatz ist es, Funktionsaufrufe zu verschachteln.
Das folgende Beispiel ist sehr konstruiert, veranschaulicht aber den Punkt.

```julia-repl
julia> first.(titlecase.(reverse.(["my", "test", "strings"])))
3-element Vector{Char}:
 'Y': ASCII/Unicode U+0059 (category Lu: Letter, uppercase)
 'T': ASCII/Unicode U+0054 (category Lu: Letter, uppercase)
 'S': ASCII/Unicode U+0053 (category Lu: Letter, uppercase)
```

Der Nachteil dieses Ansatzes ist, dass die Lesbarkeit schnell sinkt, je tiefer die Verschachtelung wird.

Wir brauchen einen einfacheren und flexibleren Ansatz.

## Komposition

Dies ist die bei Mathematikern beliebte Technik, und Julia übernimmt die mathematische Syntax.

Eine beliebige Anzahl von Funktionen kann mit `∘`-Operatoren [`composed`][comp] werden (eingegeben als `\circ`, dann Tab).
Das Ergebnis kann als eine einzelne Funktion verwendet werden.

```julia-repl
julia> compfunc = first ∘ titlecase ∘ reverse
first ∘ titlecase ∘ reverse
julia> compfunc.(["my", "test", "strings"])
3-element Vector{Char}:
 'Y': ASCII/Unicode U+0059 (category Lu: Letter, uppercase)
 'T': ASCII/Unicode U+0054 (category Lu: Letter, uppercase)
 'S': ASCII/Unicode U+0053 (category Lu: Letter, uppercase)
# alternative syntax, giving the same result
julia> (first ∘ titlecase ∘ reverse).(["my", "test", "strings"])
```

Ein paar Punkte, die zu beachten sind:

- Die Ausgangsfunktionen erscheinen in derselben Reihenfolge wie beim Verschachteln und werden von rechts nach links ausgeführt.
- Broadcasting ist bei der Komposition nicht einfach zu verwenden, kann aber beim Aufruf der komponierten Funktion angewendet werden.

## Pipelining

Eine Alternative könnte man als den Ansatz der _Programmierer_ betrachten, nicht als den der _Mathematiker_.

[`Pipelines`][comp] werden seit Langem in Unix-Shell-Skripten verwendet und wurden in jüngerer Zeit in gängigen Programmiersprachen populär (F# wird manchmal zugeschrieben, ihre Einführung vorangetrieben zu haben).

Das Grundkonzept ist, mit einigen Daten zu beginnen und sie dann durch eine Abfolge von Funktionen zu leiten, um das Ergebnis zu erhalten.

Der Pipe-Operator ist `|>` (wie in F# und neueren Versionen von R), allerdings hat Julia auch eine Broadcast-Version `.|>`.

```julia-repl
julia> ["my", "test", "strings"] .|> reverse .|> titlecase .|> first
3-element Vector{Char}:
 'Y': ASCII/Unicode U+0059 (category Lu: Letter, uppercase)
 'T': ASCII/Unicode U+0054 (category Lu: Letter, uppercase)
 'S': ASCII/Unicode U+0053 (category Lu: Letter, uppercase)
```

Die Ausführung erfolgt jetzt streng von links nach rechts, wobei die Ausgabe jeder Funktion in Richtung des Pfeils fließt und zum Eingabewert für die nächste Funktion wird.

## Einschränkungen, Workarounds und andere Optionen

Es ist kein Zufall, dass die Funktionen, die zur Veranschaulichung von Komposition und Pipelining verwendet werden, alle ein _einziges_ Argument entgegennehmen.

Einige rein funktionale Sprachen leiten das _erste_ Argument in eine Funktion, erlauben aber, dass weitere einbezogen werden.

Im Gegensatz dazu erwartet Julia in einer Pipeline nur Funktions-_Namen_ (oder etwas Gleichwertiges), ohne zusätzliche Argumente.

Dafür gibt es wichtige technische Gründe (damit zusammenhängend, dass [`currying`][currying] kein Standardteil des Sprachdesigns ist).
Die _vielen_ Menschen, die kein Verständnis von Currying haben, sollten einfach akzeptieren, dass diese Einschränkung kein Versehen aus Nachlässigkeit ist und sich in zukünftigen Julia-Versionen wahrscheinlich nicht ändern wird.

### Workarounds

Wir brauchen Funktionen mit einem einzigen Argument, die tun, was nötig ist.
Glücklicherweise ist es einfach, neue Funktionen in Julia zu definieren.

Am einfachsten könnten wir eine [`anonymous function`][anonymous-function] verwenden.
Wenn wir beispielsweise einen einzelnen Eingabe-String haben und an Unterstrichen aufteilen möchten:

```julia-repl
julia> "my_test_strings" |> (s -> split(s, '_'))
3-element Vector{SubString{String}}:
 "my"
 "test"
 "strings"
```

Dieser Vektor könnte dann wie zuvor an andere Funktionen weitergeleitet werden.

Die anonyme Funktion in Klammern zu setzen, ist in diesem Fall optional, aber allgemein eine nützliche Methode, um Mehrdeutigkeit zu verringern.

Ebenso könnten wir eine benannte Funktion früher im Programm erstellen und sie nach Bedarf wiederverwenden.
