# Einführung

## Interface als Menge von Methoden

In ihrer einfachsten Form ist ein **Interface-Typ** eine Menge von Methodensignaturen.
Hier ist ein Beispiel für eine Interface-Definition mit den zwei Methoden `Add` und `Value`:

```go
type Counter interface {
    Add(increment int)
    Value() int
}
```

Die Parameternamen wie `increment` können in der Interface-Definition weggelassen werden, aber sie erhöhen oft die Lesbarkeit.

Interface-Namen in Go enthalten nicht das Wort `Interface` oder `I`.
Stattdessen enden sie oft mit `er`, z. B. `Reader`, `Stringer`.

## Ein Interface implementieren

Jeder Typ, der die Methoden des Interfaces definiert, „implementiert“ das Interface automatisch implizit.
In Go gibt es kein `implements`-Schlüsselwort.

Der folgende Typ implementiert das `Counter`-Interface, das wir oben gesehen haben.

```go
type Stats struct {
    value int
    // ...
}

func (s Stats) Add(v int) {
    s.value += v
}

func (s Stats) Value() int {
    return s.value
}

func (s Stats) SomeOtherMethod() {
    // The type can have additional methods not mentioned in the interface.
}
```

Für die Implementierung des Interfaces spielt es keine Rolle, ob die Methode einen Wert- oder Pointer-Receiver hat.
(Schau dir die [Methoden-Konzepte][concept-methods] noch einmal an, wenn du dir dabei unsicher bist.)

> Ein Wert vom Interface-Typ kann jeden Wert enthalten, der diese Methoden implementiert. ((Go Tour: Interfaces)[go-tour-interfaces])

Das bedeutet, dass `Stats` jetzt überall verwendet werden kann, wo das `Counter`-Interface erwartet wird.

```go
func SetUpAnalytics(counter Counter) {
    // ...
}

stats := Stats{}
SetUpAnalytics(stats)
// works because Stats implements Counter
```

Weil Interfaces implizit implementiert werden, kann ein Typ leicht mehrere Interfaces implementieren.
Er muss nur alle notwendigen Methoden definiert haben.

## Das leere Interface

In Go gibt es einen ganz besonderen Interface-Typ: den **leeren Interface**-Typ, der keine einzige Methode enthält.
Das leere Interface wird so geschrieben: `interface{}`.
Ab Go 1.18 kann auch `any` verwendet werden.
Es wurde als Alias definiert.

Da das leere Interface keine Methoden hat, implementiert es jeder Typ implizit.
Das ist hilfreich, um eine Funktion zu definieren, die generisch jeden Wert akzeptieren kann.
In diesem Fall verwendet der Funktionsparameter den leeren Interface-Typ.
