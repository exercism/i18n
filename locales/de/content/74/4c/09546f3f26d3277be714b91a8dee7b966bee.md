# Einführung

## Partielle Applikation

In Elm sind alle Funktionen [curryfiziert][currying]. Das heißt: Wenn du eine Funktion aufrufst, ohne alle Argumente zu übergeben, gibt sie eine neue Funktion zurück.

Das Ergebnis davon nennt man [partielle Applikation][partial-application] (du übergibst nicht alle Argumente an die Funktion, sondern wendest nur einige davon teilweise an).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

Die partielle Applikation wendet die Argumente immer der Reihe nach an.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## Pipe-Operator (`|>`)

`x |> f` ist genau dasselbe wie `f x`. Ein konkretes Beispiel: `"5" |> String.toInt` ist dasselbe wie `String.toInt "5"`.

Das klingt zunächst nicht besonders nützlich, aber es heißt [Pipe-Operator][pipe-operator], weil du damit Code in „Pipelines“ schreiben kannst.

Angenommen, wir haben eine `sanitize`-Funktion, die Nutzereingaben in Ganzzahlen umwandelt:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Wir können sie so umschreiben:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Das vermeidet Klammern und zeigt die Funktionen in der Reihenfolge, in der sie angewendet werden (zuerst `String.trim`, dann `String.toInt`), was die Lesbarkeit verbessert.

Es gibt auch einen [umgekehrten Pipe-Operator `(<|)`][reverse-pipe-operator].
`f <| x` ist genau dasselbe wie `f x`.
Auch das sieht auf den ersten Blick nicht besonders nützlich aus und wird definitiv nicht so oft verwendet wie der Pipe-Operator, aber in manchen Situationen hilft es, Klammern zu vermeiden.

## Funktionskomposition / punktfreier Stil

Der Operator [`(>>)`][forward-composition] hat den Typ `(a -> b) -> (b -> c) -> (a -> c)` und erzeugt eine Funktion vom Typ `a -> c`, indem er zwei kompatible Funktionen der Typen `a -> b ` und `b -> c` miteinander kombiniert.
Er nimmt dazu die Ausgabe (vom Typ `b`) der ersten Funktion und verwendet sie als erstes Argument der zweiten Funktion (die denselben Typ `b` haben muss).
Die erzeugte Funktion nimmt dieselbe Eingabe (vom Typ `a`) wie die erste Funktion und gibt das zurück, was die zweite Funktion als `c` zurückgibt.

Ein konkretes Beispiel ist `String.trim >> String.toInt`.
`String.trim` nimmt einen String als einzigen Parameter, also nimmt die erzeugte Funktion das auch.
`String.toInt` gibt ein `Maybe Int` zurück, also gibt die erzeugte Funktion das auch zurück.
`String.trim` gibt einen `String` zurück, den `String.toInt` als Parameter akzeptiert, also kompiliert das Beispiel.

Jetzt können wir unsere Funktion `sanitize` so umschreiben:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Beachte, dass wir den Parameter `input` aus dem ursprünglichen Beispiel nicht mehr verwenden, obwohl die Funktionalität identisch ist.
Diese Art, Funktionen zu schreiben, die ihre Parameter nicht erwähnen, heißt „punktfreier Stil“.
Der Vorteil dieses Stils ist, dass der Code knapper ist; der Nachteil ist, dass er schwerer zu verstehen sein kann, besonders für Anfänger.

Denk daran, dass in Elm alle Funktionen curryfiziert sind, deshalb kompiliert `String.length >> max`.

- Der Operator [`(>>)`][forward-composition] hat den Typ `(a -> b) -> (b -> c) -> (a -> c)`.
- `String.length` hat den Typ `String -> Int`, das ist der Teil `(a -> b)`, also ist `a` gleich `String` und `b` gleich `Int`.
- `max` hat den Typ `Int -> Int -> Int`, das ist der Teil `b -> c`.
- `b` ist `Int`, also wird `max` partiell angewendet, und `c` ist das Ergebnis dieser partiellen Anwendung (`Int -> Int`).
- Der Typ von `String.length >> max` ist also `String -> (Int -> Int)`.
- Also gibt `((String.length >> max) "123") 2` den Wert `3` zurück, weil `"123"` die Länge 3 hat und die größer ist als die 2 aus dem `Int`-Argument.

## Funktionsdesign

Damit du in Elm einfach eleganten Code schreiben kannst, solltest du die Hauptdatenstruktur zum letzten Parameter von Funktionen machen.
Alle gängigen Funktionen in der Standardbibliothek machen das, zum Beispiel `List.map` (Typsignatur siehe unten).

```elm
map : (a -> b) -> List a -> List b
```

Hier sehen wir, dass der letzte Parameter der Funktion `map` `List a` ist und sie `List b` zurückgibt, die Hauptdatenstruktur (`List`) also der letzte Parameter ist.

Damit kannst du eleganten Code in Pipelines schreiben, wie hier:

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Außerdem ist es so bequem, Funktionskomposition und den punktfreien Stil als Alternative zur Pipeline-Schreibweise zu nutzen.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

Mit Funktionskomposition kannst du dieses Beispiel auch auf einen einzigen Aufruf von `List.map` reduzieren.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
