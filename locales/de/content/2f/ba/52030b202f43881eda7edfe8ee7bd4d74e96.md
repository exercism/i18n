# Einführung

## Strings

### Zeichen

Eine **Zeichenkodierung** ist eine bestimmte Konvention, mit der Textelemente einer natürlichen Sprache als Folge von Bytes dargestellt werden.
Ein „Textelement“ kann hier jede Einheit sein, die in einer natürlichen Sprache eine Bedeutung hat, zum Beispiel Buchstaben, Leerzeichen, Satzzeichen, Emojis, Ideogramme usw.

NASM (The Netwide Assembler, der Assembler, der in diesem Track verwendet wird) unterstützt die Definition von Daten mit **ASCII**.

Zeichenkonstanten in NASM dürfen bis zu 8 Bytes lang sein und können mit einfachen Anführungszeichen (`'`), doppelten Anführungszeichen (`"`) oder Backticks (`` ` ``) definiert werden:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Sonderzeichen müssen in Backticks definiert und mit `\` maskiert werden:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Beachte, dass es in x86-64 keine eingebaute Unterstützung für eine Zeichenkodierung als eigenständigen Typ gibt.
Daten sind in Assembly eine Folge von Bytes, und wie diese Bytes interpretiert werden, als Zeichen, Zahl oder etwas anderes, bleibt dem Programmierer überlassen.

Zum Beispiel ist das ASCII-Zeichen '0' ein einzelnes Byte mit dem Wert 48.
Eine 48 in ein Byte zu speichern ist also genau dasselbe, wie das ASCII-Zeichen '0' zu speichern:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Aus demselben Grund werden Zeichen manipuliert, indem die Werte in diesen Bytes direkt umgewandelt werden:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### Strings

Ein **String** (Zeichenkette) ist eine Folge von Zeichen.
In Assembly wird er üblicherweise als Array umgesetzt.

In NASM kannst du einen String genauso deklarieren wie jedes andere Array:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Ein Unterschied zwischen Strings und anderen Arrays besteht darin, dass NASM Strings auch ohne ein Komma (`,`) zwischen den Werten deklarieren kann.
Es ist auch möglich, Werte und Kommas gemischt zu verwenden:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Beachte, dass Zeichen, wie bereits erwähnt, nur Bytes sind (oder eine Folge von Bytes bei Unicode-Kodierung):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Da jedes ASCII-Zeichen ein einzelnes Byte belegt, ist jedes darauffolgende Byte bei einer größeren Größe `0`.
Wenn du zum Beispiel `'a'` als Qword (8 Bytes) deklarierst, ist das erste Byte `'a'` (`97`) und die anderen sieben Bytes sind alle `0`.

Aus diesem Grund sind alle folgenden Deklarationen gleichwertig:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
In Assembly werden Strings nicht automatisch durch ein ASCII-NUL-Zeichen (Wert `0`) beendet.

Wenn du mit höheren Programmiersprachen wie C arbeitest, liegt es in deiner Verantwortung, dafür zu sorgen, dass am Ende eines Strings das richtige Abschlusszeichen (falls vorhanden) angehängt wird.
~~~~

### String-Befehle

Da Strings Arrays sind, kannst du genauso mit ihnen arbeiten wie mit jedem Array, indem du den Speicher explizit dereferenzierst:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Darüber hinaus gibt es einige Befehle zum Laden, Verschieben und Speichern von Werten in Bytefolgen im Speicher.
Obwohl sie _String-Befehle_ heißen, kannst du sie mit jeder Bytefolge im Speicher verwenden, also mit jedem Array.

Die drei wichtigsten String-Befehle sind `lods`, `stos` und `movs`:

| Befehl | was er bewirkt                                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | lädt einen Wert aus einer Speicherstelle, die durch `rsi` angegeben wird, in `rax`                                |
| `stos`      | speichert einen Wert aus `rax` in eine Speicherstelle, die durch `rdi` angegeben wird                             |
| `movs`      | kopiert einen Wert aus einer Speicherstelle, die durch `rsi` angegeben wird, und speichert ihn in einer Speicherstelle, die durch `rdi` angegeben wird |

Beachte, dass diese Befehle _keinen_ expliziten Operanden annehmen.
Ihre Operanden sind implizit.

Als Faustregel gilt:

1. Wenn ihr Quelloperand eine Speicherstelle ist, sollte deren Adresse in `rsi` gespeichert werden (`s` für source).
2. Wenn ihr Zieloperand eine Speicherstelle ist, sollte deren Adresse stattdessen in `rdi` gespeichert werden (`d` für destination).
3. Wenn einer der Operanden keine Speicherstelle ist, handelt es sich um das Register `rax`.

Beachte, dass diese Befehle Speicheradressen automatisch dereferenzieren, je nachdem, welche Operation sie ausführen.

Sie alle können in verschiedenen Größen arbeiten.
Ein Suffix wird angehängt, um diese Größe anzugeben:

| Suffix | Bedeutung | Größe   |
| :----: | ------- | :------ |
|  `b`   | Byte    | 1 Byte  |
|  `w`   | Wort    | 2 Bytes |
|  `d`   | Dword   | 4 Bytes |
|  `q`   | Qword   | 8 Bytes |

Zum Beispiel:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

Sie aktualisieren außerdem jede verwendete Adresse um die Größe der Operation.
Diese Aktualisierung erfolgt entsprechend dem Wert des **Richtungsflags (DF)**:

- Wenn das `DF` gelöscht ist, werden die Adressen um die Größe der Operation _erhöht_.
- Wenn das `DF` gesetzt ist, werden die Adressen stattdessen um denselben Betrag _verringert_.

Die System V ABI schreibt vor, dass das Richtungsflag beim Eintritt in eine Funktion gelöscht sein muss.
Das Standardverhalten besteht also darin, _den Speicher in aufsteigender Adressreihenfolge zu lesen und zu schreiben_.

Der Befehl `cld` kann verwendet werden, um das Richtungsflag zu löschen, während der Befehl `std` es setzt:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Der Aufrufer erwartet, dass das `DF` nach der Rückkehr einer aufgerufenen Funktion gelöscht ist, gemäß der System V ABI.
Wenn du das `DF` jemals setzt, achte darauf, es vor `ret` zu löschen.
~~~~

#### Rep

Abgesehen davon interagiert der **rep**-Befehl nicht direkt mit dem Speicher.
Stattdessen kann er als Präfix zu den anderen genannten Befehlen hinzugefügt werden und _wiederholt_ diese Befehle.

Mit dem Präfix `rep` werden String-Befehle so oft wiederholt, wie es dem Wert in `rcx` entspricht.
Jedes Mal wird der Wert in `rcx` um `1` verringert.
Beachte, dass der Wert in `rcx` gesetzt sein muss, bevor der Befehl verwendet wird:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
Auf modernen CPUs sind `rep movs` und `rep stos` beim Verschieben von Daten in großen Blöcken normalerweise schnelle Optionen.
Andere String-Befehle, und selbst `movs` und `stos`, wenn sie ohne `rep` arbeiten, sind jedoch normalerweise langsamer als eine einfache Schleife.

Eine ausführlichere Betrachtung dieses Themas findest du in [Kapitel 16.9, „String instructions“, dieses Referenzbuchs][agner-optimization-guide].
