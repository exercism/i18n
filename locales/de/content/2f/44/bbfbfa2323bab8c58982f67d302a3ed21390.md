# golint nicht erfüllt

Es gibt ein großartiges Tool namens [`golint`](https://github.com/golang/lint), das den Code auf häufige Probleme und Stilfragen untersucht.
Führe `golint` für deine Lösung aus, z. B.: `golint two_fer.go`. Damit bekommst du einige nützliche Hinweise.

Es ist sinnvoll, den Code immer mit `golint` zu prüfen.
Wenn du Go-Software für den Produktionseinsatz schreibst, lassen viele Build-Pipelines den Build automatisch fehlschlagen, wenn der Code `golint` nicht besteht.

Wenn du deutlich mehr Feedback von Code-Lintern bekommen möchtest, gibt es das Projekt [golangci-lint](https://github.com/golangci/golangci-lint),
mit dem du viele Linter mit einem einzigen Befehl ausführen kannst.
Eine Projekt-Konfigurationsdatei kann das Verhalten an die Anforderungen eines Projekts anpassen.

```
> golint
%{golint}
```
