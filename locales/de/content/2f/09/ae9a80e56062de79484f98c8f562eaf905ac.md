# Über

Das primäre objektorientierte Konstrukt in C# ist die _Klasse_, eine Kombination aus Daten ([_Felder_][fields]) und Verhalten ([_Methoden_][methods]). Die Felder und Methoden einer Klasse werden als ihre _Member_ bezeichnet.

Der Zugriff auf Member kann durch Zugriffsmodifizierer eingeschränkt werden, wobei die beiden häufigsten sind:

- [`public`][public]: Auf das Member kann jeder Code zugreifen (keine Einschränkungen).
- [`private`][private]: Auf das Member kann nur Code in derselben Klasse zugreifen.

Es ist üblich, für alle Member einen Zugriffsmodifizierer anzugeben. Wenn kein Zugriffsmodifizierer angegeben wird, ist `private` die Standardeinstellung.

Die oben erwähnte Gruppierung zusammengehöriger Daten und Verhalten sowie die Einschränkung des Zugriffs auf Member wird als [Kapselung][encapsulation] bezeichnet, eines der Kernkonzepte der objektorientierten Programmierung.

Die Kombination der Feldwerte eines Objekts zu einem bestimmten Zeitpunkt wird als [Zustand][object-state] des Objekts bezeichnet.

Du kannst dir eine Klasse als Vorlage für das Erstellen von Instanzen dieser Klasse vorstellen. Um [eine Instanz einer Klasse zu erzeugen][creating-objects] (auch als _Objekt_ bezeichnet), wird das [`new`-Schlüsselwort][new] verwendet:

```csharp
class Car
{
}

// Create two car instances
var myCar = new Car();
var yourCar = new Car();
```

[_Felder_][fields] haben einen Typ und können überall in einer Klasse definiert werden.
Öffentliche Felder werden in [PascalCase][pascal-case] definiert und private Felder in [camelCase][camel-case] und mit einem Unterstrich `_` versehen:

```csharp
class Car
{
    // Accessible by anyone
    public int Weight;

    // Only accessible by code in this class
    private string _color;
}
```

Du kannst einem Feld optional einen Anfangswert zuweisen. Wenn ein Feld _keinen_ Anfangswert angibt, wird es auf den [Standardwert][default-values] seines Typs gesetzt. Du kannst auf die Feldwerte einer Instanz mit der Punktnotation zugreifen und sie aktualisieren.

```csharp
class Car
{
    // Will be set to specified value
    public int Weight = 2500;

    // Will be set to default value (0)
    public int Year;
}

var newCar = new Car();
newCar.Weight; // => 2500
newCar.Year;   // => 0

// Update value of the field
newCar.Year = 2018;
```

Private Felder werden normalerweise als Nebeneffekt eines Methodenaufrufs aktualisiert. Solche Methoden geben normalerweise keinen Wert zurück; in diesem Fall sollte der Rückgabetyp [`void`][void] sein:

```csharp
class CarImporter
{
    private int _carsImported;

    public void ImportCars(int numberOfCars)
    {
        // Update private field
        _carsImported = _carsImported + numberOfCars;
    }
}
```

Beachte, dass es in C#-Klassen nicht üblich ist, öffentliche Felder zu verwenden. Stattdessen werden entweder private Felder verwendet oder andere Arten von Membern, die in späteren Übungen besprochen werden.

Innerhalb einer Klasse bezieht sich das [`this`-Schlüsselwort][this] auf die aktuelle Klasse. Das ist besonders nützlich, wenn ein Parameter denselben Namen wie ein Feld hat:

```csharp
class CarImporter
{
    private int carsImported;

    public void SetImportedCars(int carsImported)
    {
        // Update private field from public method
        this.carsImported = carsImported;
    }
}
```

Die Struktur von Klassen und Methoden bietet eine natürliche Möglichkeit, die Sichtbarkeit von Programmelementen wie Feldern und Methoden einzuschränken und das bekannte [Problem des globalen Zustands][so-global-state-problem] zu vermeiden. Öffentliche Felder, Methoden und andere Member müssen mit dem Objektnamen qualifiziert werden, also `object.field` oder `object.method()` (bei statischen Membern der Klassenname), damit Code außerhalb der Klasse sie sehen kann. Variablen und Parameter, die innerhalb einer Methode deklariert werden, sind nur innerhalb dieser Methode sichtbar.

Worauf du bei diesem Ansatz achten solltest: Wenn ein Feldname und der Name einer Variablen oder eines Parameters in einer Methode gleich sind, wird der Feldname vom Code innerhalb der Methode ignoriert, was möglicherweise nicht das ist, was du möchtest. Im Allgemeinen solltest du das nach Möglichkeit vermeiden, obwohl es in Konstruktoren ein gängiges Muster ist. Wenn es sinnvoll ist, dass Feldname und Variablenname gleich sind, qualifiziere den Feldnamen innerhalb der Methode mit dem `this`-Schlüsselwort.

Mit diesen [Zugriffsmodifizierern][access-modifiers] lässt sich die Sichtbarkeit weiter einschränken.
