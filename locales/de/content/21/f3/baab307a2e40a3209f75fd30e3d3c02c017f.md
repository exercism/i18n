# Einführung

Gleam kann auf der Erlang-Virtual-Machine (BEAM) laufen oder in JavaScript-Laufzeitumgebungen. Es gibt viele andere Sprachen, die diese Laufzeitumgebungen nutzen, und oft ist es nützlich, Code, der in diesen Sprachen geschrieben ist, aus Gleam heraus aufzurufen.

Mit Gleams Feature der _externen Funktionen_ lassen sich Funktionen aus anderen Sprachen nach Gleam importieren und ohne Laufzeit-Overhead aufrufen.

Wenn dein Gleam-Projekt auf der Erlang-Virtual-Machine läuft und du die Funktion `reverse` aus dem Erlang-Modul `lists` aufrufen möchtest, kannst du dazu das Attribut `@external` an den Kopf einer Gleam-Funktion anhängen, und zwar so:

```gleam
@external(erlang, "lists", "reverse")
pub fn reverse_list(x: List(a)) -> List(a)
```

Danach lässt sie sich wie eine normale Gleam-Funktion aufrufen:

```gleam
let reversed = reverse_list([1, 2, 3])
// -> [3, 2, 1]
```

Wenn du versuchst, diesen Code für JavaScript-Laufzeitumgebungen zu kompilieren, schlägt das mit einer Fehlermeldung fehl, weil es keine Implementierung für JavaScript gibt. Für JavaScript-Laufzeitumgebungen kannst du eine andere Implementierung angeben, und zwar so:

```gleam
@external(erlang, "lists", "reverse")
@external(javascript, "./my_module.mjs", "reverse")
pub fn reverse_list(x: List(a)) -> List(a)
```

Du kannst auch eine Gleam-Implementierung schreiben, die verwendet wird, wenn es keine externe Implementierung für das aktuelle Kompilierungsziel gibt:

```gleam
@external(erlang, "lists", "reverse")
pub fn reverse_list(x: List(a)) -> List(a) {
  tail_recursive_reverse(x, [])
}

fn tail_recursive_reverse(list, reversed) {
  case list {
    [] -> reversed
    [x, ..xs] -> tail_recursive_reverse(xs, [x, ..reversed])
  }
}
```
