# Tests

Jede Übung liefert die Unit-Tests.
Du lieferst die Implementierung.
Jede Datei erzeugt ein ausführbares Konsolenprogramm, das die Tests ausführt.
Wenn du das Testprogramm ausführst, werden für jeden fehlgeschlagenen Test Meldungen ausgegeben, und wenn Tests fehlschlagen, wird ein Exit-Code ungleich null gemeldet.

*Hinweis*: Dein Code wird jedes Mal gegen die Testsuite getestet, wenn du dein Projekt baust.
Wenn dein Code einen oder mehrere Tests nicht besteht, aber gültiger D-Code ist, wird er trotzdem kompiliert.

Bei jeder Übung gehst du so vor:

* Die Tests mit `dub test` ausführen
  * Wenn du dich entschieden hast, DUB nicht zu installieren, verwendest du stattdessen `dmd source/*.d -de -w -main -unittest` und führst anschließend die erzeugte Binärdatei aus.
* Für jeden Unit-Test:
  * Behebe die Kompilierfehler, damit der Test fehlschlägt.
  * Implementiere gerade so viel, dass der Test besteht.
  * Refaktoriere deine Implementierung, um die Lesbarkeit zu verbessern, Duplikate zu reduzieren usw.
  * Aktiviere den nächsten Test

*Hinweis:* D unterstützt Unit-Tests direkt in der Sprache, deshalb stehen die Unit-Tests normalerweise in derselben Datei wie die Implementierung.
Die Unit-Tests werden vor dem Rumpf von main ausgeführt und im fertigen ausführbaren Programm über den Compiler-Schalter **-unittest** aktiviert.

```none
$ dub test
             Generating test runner configuration 'dnd-character-test-library' for 'library' (library).

    Building dnd-character ~master: building configuration [dnd-character-test-library]
     Linking dnd-character-test-library
     Running dnd-character-test-library

```
