# Einführung

`Complex numbers` sind nicht kompliziert.
Sie brauchen nur einen weniger erschreckenden Namen.

Sie sind so nützlich, besonders in Technik und Wissenschaft, dass R komplexe Zahlen als atomare Standardtypen neben integer, double, logical, character und raw enthält.

## Grundlagen

Eine Zahl vom Typ `complex` ist in R ein einzelner Wert.
Bei der Verwendung kann man sie sich jedoch als ein Paar von Zahlen vorstellen.
Aus unglücklichen historischen Gründen werden diese als „Realteil" und „Imaginärteil" bezeichnet.
Auch hier ist es am besten, sich auf die zugrunde liegende Einfachheit zu konzentrieren und nicht auf die seltsamen Namen.

Um komplexe Zahlen aus zwei reellen Zahlen zu erzeugen, hängst du einfach das Suffix `i` an den Imaginärteil an.

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

Um eine komplexe Zahl aus reellen Variablen zu erzeugen, funktioniert die obige Syntax nicht.
`r + imi` verwirrt den Parser, sodass er `imi` für einen (nicht existierenden) Variablennamen hält.

Multipliziere den Imaginärteil entweder mit `1i` oder verwende die Funktion [`complex()`][ref-complex]:

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

Du fragst dich vielleicht, warum `i` und nicht `j`?

Die meisten Ingenieure bevorzugen `j`.
Die meisten Naturwissenschaftler und Mathematiker bevorzugen die mathematische Schreibweise `i` für _imaginär_, aber diese Schreibweise steht im Konflikt mit der Verwendung von `i` für _Strom_ in der Elektrotechnik.

R hat sich für `i` entschieden, Python für `j`, und Julia ist der Kontroverse ausgewichen, indem es `im` gewählt hat.
Sei vorsichtig, wenn du zwischen [MINT][wiki-STEM]-Programmiersprachen wechselst.

Um einzeln auf die Teile einer komplexen Zahl zuzugreifen:

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

Jeder der beiden Teile kann null sein, und Mathematiker sprechen dann vielleicht davon, dass die Zahl „rein reell" oder „rein imaginär" ist.
In R ist sie jedoch weiterhin eine komplexe Zahl.

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

Du hast vielleicht schon gehört, dass „`i` (oder `j`) die Quadratwurzel von -1 ist".

Vorerst bedeutet das nur, dass der Imaginärteil _per Definition_ die folgende Gleichheit erfüllt:

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

Das ist eine einfache Idee, aber sie führt zu interessanten Konsequenzen.

## Arithmetik

Die meisten Operatoren, die mit Gleitkommazahlen und Ganzzahlen verwendet werden, funktionieren auch mit komplexen Zahlen:

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

## Funktionen

Die meisten mathematischen Funktionen funktionieren mit komplexen Eingabewerten.

Neben `Re()` und `Im()` gibt es einige Funktionen, die für komplexe Zahlen besonders relevant sind.

- `Conj()` kehrt einfach das Vorzeichen des Imaginärteils einer komplexen Zahl um (_von + nach - oder umgekehrt_).
  - Aufgrund der Funktionsweise der komplexen Multiplikation ist das nützlicher, als du vielleicht denkst.
- `abs(<complex number>)` gibt garantiert eine reelle Zahl ohne Imaginärteil zurück (ihren „Betrag"), und `Mod(<complex number>)` ist ein Synonym.
- `Arg(<complex number>)` gibt den Phasenwinkel im Bogenmaß zurück.

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
