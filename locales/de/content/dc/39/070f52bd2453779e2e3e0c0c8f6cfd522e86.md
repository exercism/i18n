# Einführung

In Go 1.18 hat Go Unterstützung für **Generics** hinzugefügt.
Mit Generics kannst du Funktionen und Datenstrukturen schreiben, die mit verschiedenen Typen arbeiten, ohne Code zu duplizieren.

## Warum Generics?

In Go arbeiten Funktionen und Typen normalerweise mit bestimmten Typen, etwa `int` oder `string`.
Vor Generics hattest du zwei Möglichkeiten, mehrere Typen zu unterstützen.
Erstens konntest du mehrere Funktionen mit unterschiedlichen Namen schreiben, etwa `SumInts` und `SumFloats`.
Dieser Ansatz erzeugt doppelten Code, der schwer zu pflegen ist.
Zweitens konntest du das leere Interface `any` (`interface{}`) verwenden.
Das leere Interface entfernt aber die Typprüfungen zur Kompilierzeit und erfordert zur Laufzeit Type Assertions.
Generics lösen dieses Problem, indem sie Typsicherheit bieten und trotzdem doppelten Code vermeiden.

## Generische Funktionen

Du definierst eine generische Funktion, indem du **Typparameter** in eckigen Klammern `[...]` hinter den Funktionsnamen setzt.
Hier ist ein Beispiel für eine generische Funktion, die einen umgekehrten Slice zurückgibt:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

In diesem Beispiel ist `T` ein Typparameter.
Du kannst dir `T` als Platzhalter für einen echten Typ vorstellen.
Das Schlüsselwort `any` in den eckigen Klammern ist eine **Typbeschränkung**.
Die Beschränkung sagt dem Compiler, welche Typen für `T` erlaubt sind.
Hier bedeutet `any`, dass `T` jeder Typ sein kann.

### Generische Funktionen aufrufen

Du kannst eine generische Funktion aufrufen, indem du den tatsächlichen Typ in eckigen Klammern übergibst.
Dieser tatsächliche Typ heißt **Typargument**.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

In den meisten Fällen erkennt der Go-Compiler den Typ automatisch an den Funktionsargumenten.
Diese Eigenschaft heißt **Typinferenz**.
Mit Typinferenz musst du das Typargument nicht in eckigen Klammern schreiben.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

In diesem Beispiel sieht der Compiler, dass `words` ein Slice von Strings ist, also leitet er ab, dass `T` gleich `string` ist.

## Typbeschränkungen

Jeder Typparameter braucht eine Beschränkung.
Eine Beschränkung legt fest, welche Typen du als Typargumente verwenden kannst.
Eine Beschränkung bestimmt außerdem, welche Operationen du auf Werten dieses Typs ausführen darfst.

### Die Beschränkung `any`

Die Beschränkung `any` erlaubt jeden Typ.
In Go ist `any` ein Alias für das leere Interface `interface{}`.
Weil `any` jeden Typ erlaubt, kann die Funktion nur Operationen ausführen, die für alle Go-Typen funktionieren.
Wenn du zum Beispiel zwei `any`-Werte hast, die Slices enthalten, kannst du sie nicht mit `==` vergleichen, weil sich Slices nicht mit `==` vergleichen lassen.

### Die Beschränkung `comparable`

Go bietet eine eingebaute Beschränkung namens `comparable`.
Die Beschränkung `comparable` erlaubt jeden Typ, der die Operatoren `==` und `!=` unterstützt.
Zu den vergleichbaren Typen gehören boolesche Werte, Zahlen, Strings, Pointer und Channels sowie Structs oder Arrays aus vergleichbaren Typen.

Hier ist ein Beispiel für eine Funktion, die prüft, ob ein Slice ein bestimmtes Element enthält:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Weil `T` die Beschränkung `comparable` verwendet, ist `elem == target` gültig.
Wenn du `comparable` durch `any` ersetzt, meldet der Compiler einen Fehler.

### Eigene Beschränkungen mit Typmengen in Interfaces

Seit Go 1.18 können Interfaces neben Methoden auch Mengen von Typen definieren.
Mit dem Pipe-Zeichen `|` kannst du die erlaubten Typen in einem Interface auflisten.

```go
type Number interface {
    int | int64 | float64
}
```

Jetzt kannst du `Number` als Beschränkung für eine Funktion verwenden:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Weil alle Typen in `Number` den Operator `*` unterstützen, erlaubt Go `value * 2` innerhalb der Funktion.

### Die Näherung des zugrunde liegenden Typs `~`

Manchmal legst du eine eigene Typdefinition auf Basis eines primitiven Typs an:

```go
type MyInt int
```

Die oben definierte Beschränkung `Number` erlaubt nur die exakten Typen `int`, `int64` und `float64`.
Wenn du einen `MyInt`-Wert an `Double` übergibst, meldet der Compiler einen Fehler, weil `MyInt` nicht zu `int` passt.
Um jeden Typ zu erlauben, dessen zugrunde liegender Typ `int` ist, setzt du eine Tilde `~` vor den Typ:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

Jetzt kannst du `Double` mit Werten vom Typ `MyInt` verwenden.

### Die Beschränkung `cmp.Ordered`

Die Standardbibliothek stellt die Beschränkung `cmp.Ordered` im [`cmp`-Paket][doc-cmp] bereit.
Die Beschränkung `cmp.Ordered` erlaubt jeden Typ, der die Vergleichsoperatoren `<`, `<=`, `>` und `>=` unterstützt.

## Generische Typen

Du kannst Typparameter auch verwenden, um generische Typen zu definieren, etwa Structs.
Hier ist ein Beispiel für eine generische Datenstruktur `Stack`:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Wenn du eine Variable eines generischen Typs deklarierst, musst du das Typargument in eckigen Klammern angeben:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

Typinferenz funktioniert nur bei generischen Funktionen.
Beim Erzeugen von Werten eines generischen Typs musst du das Typargument immer angeben.

## Wann du Generics einsetzen solltest

Generics sind eine mächtige Funktion, aber du musst sie nicht für jedes Problem einsetzen.

Setze Generics in diesen Situationen ein:
- Du baust Datenstrukturen wie Bäume, verkettete Listen oder Caches, die mit jedem Elementtyp funktionieren.
- Du schreibst Hilfsfunktionen, die auf Slices oder Maps beliebiger Typen arbeiten, etwa zum Filtern, Sortieren oder Suchen.
- Du brauchst für mehrere Typen exakt dieselbe Implementierung und möchtest Typsicherheit zur Kompilierzeit.

Verwende stattdessen Interfaces in diesen Situationen:
- Dir geht es um Verhalten und Methoden, nicht um den zugrunde liegenden Datentyp.
  Wenn du zum Beispiel Daten aus Quellen verschiedener Typen (Dateien, Netzwerk, TTY) lesen und verarbeiten willst, würdest du `func Process(src io.Reader)` statt `func Process[T](src T)` verwenden.
- Verschiedene Typen brauchen unterschiedliche Methodenimplementierungen, um ihre Arbeit zu erledigen.
