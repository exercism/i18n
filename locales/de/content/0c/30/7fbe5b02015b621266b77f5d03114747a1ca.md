# Einführung

JavaScript hat ein eingebautes Objekt `Date`, das Datum und Uhrzeit speichert und Methoden für deren Verwaltung bereitstellt.

<!-- prettier-ignore -->
~~~exercism/caution
Es basierte auf Javas Klasse `java.util.Date`, die Anfang der 2010er Jahre ersetzt wurde, aber aus Gründen der Abwärtskompatibilität bleibt JavaScripts `Date` erhalten.

Weil die Arbeit mit Datumsangaben im Allgemeinen schwierig ist und weil die Behandlung von Zeitzonen schlecht oder gar nicht vorhanden ist, gibt es viele Bibliotheken wie `moment.js`, `day.js`, `date-fns` und `luxon`.
Keine davon ist auf Exercism verfügbar.

Verwende in deinen eigenen Projekten kein veraltetes oder nicht mehr gepflegtes Paket wie `moment.js`, sondern setz auf modernere Alternativen wie `luxon` oder das noch nicht weit verbreitete [Temporal][mdn-temporal].
Diese Übung konzentriert sich auf `Date`, das bis zum Ende von JavaScript relevant bleiben wird.

## Erstellung

Ein `Date`-Objekt ist eine Instanz der `Date`-Klasse.
Du kannst es erzeugen, ohne Argumente an die Konstruktorfunktion zu übergeben.
Das ergibt ein `Date`-Objekt, das das aktuelle Datum und die aktuelle Uhrzeit darstellt:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### Unix-Zeitstempel (Zahl)

Wenn du eine Zahl übergibst, wird sie als `timestamp` interpretiert.
Ein Zeitstempel ist eine Ganzzahl, die die Anzahl der **Millisekunden** angibt, die seit dem **1. Januar 1970 [UTC][defn-utc]+0** vergangen sind.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

Man könnte erwarten, dass `new Date(0)` das „früheste“ Datumsobjekt erzeugt, aber JavaScript rechnet das Datum in deine lokale Zeitzone um. Das bedeutet, dass nur diejenigen in einer Zeitzone um [GMT bzw. mit UTC+0][defn-gmt] tatsächlich den Wert der [Unix-Epoche][defn-unix-epoch] erhalten.

### ISO-8601-Zeitstempel (String)

Du kannst dem `Date`-Konstruktor einen String übergeben, der ein Datum darstellt.
Das **einzige** Format, das über alle Implementierungen hinweg konsistent ist, ist die [vereinfachte Version][mdn-date-string-format] der international anerkannten und standardisierten sogenannten [ISO-8601-Zeitstempel-Strings][defn-iso8601].

Ein Zeitpunkt in [UTC][defn-gmt] sieht so aus:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

Dabei gelten folgende Ersetzungen:

| Schlüssel | Beschreibung                                 | Standard |
| ---- | ------------------------------------------- | ------- |
| YYYY | Das Kalenderjahr, in 4 Ziffern angegeben    |         |
| MM   | Der Kalendermonat, in 2 Ziffern angegeben   | 01      |
| DD   | Der Kalendertag, in 2 Ziffern angegeben     | 01      |
| T    | Ein wörtliches T, das Datum und Uhrzeit trennt | T    |
| HH   | Die Stunden in einer 24-Stunden-Anzeige, 2 Ziffern | 00 |
| mm   | Die Minuten, 2 Ziffern                      | 00      |
| ss   | Die Sekunden, 2 Ziffern                     | 00      |
| mss  | Die Millisekunden, 3 Ziffern                | 000     |
| Z    | Ein wörtliches Z oder ein Offset `+/-HH:mm` |         |

Der wörtliche Buchstabe `Z` steht für UTC (keine Zeitzone, keine Sommerzeit).

Da es für die meisten Komponenten Standardwerte gibt, ist es gültig, Teile am Ende wegzulassen:

```text
YYYY-MM-DD
```

Standardmäßig gilt die Uhrzeit 00:00:00.000

Wenn der Zeitstempel nicht auf `Z` endet und auch nicht mit `+HH:mm` oder `-HH:mm` endet (was einen Zeitzonen-Offset angibt), gilt aus historischen Gründen Folgendes:

> Wenn der Zeitzonen-Offset fehlt, werden reine Datumsformen als UTC-Zeit interpretiert und Datum-Uhrzeit-Formen als lokale Zeit.
> Die Interpretation als UTC-Zeit geht auf einen historischen Fehler in der Spezifikation zurück, der nicht mit ISO 8601 übereinstimmte, aber aus Gründen der Web-Kompatibilität nicht geändert werden konnte.
> Siehe [Broken Parser – A Web Reality Issue][ref-broken-parser].

### Date-Objekt

Ein vorhandenes Datumsobjekt kann auch als Argument für den Konstruktor verwendet werden.
Dadurch wird eine Kopie des vorhandenen `Date`-Objekts mit demselben Datum und derselben Uhrzeit erstellt.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### Einzelne Werte für Datums- und Uhrzeitkomponenten übergeben

Ein Datumsobjekt für ein Datum kannst du erzeugen, indem du drei Zahlen übergibst.
Ein Datumsobjekt für Datum und Uhrzeit erzeugst du, indem du sechs Zahlen übergibst.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

Der zweite Wert ist der `month`, der bei `0` für Januar beginnt und bis `11` für Dezember geht.

## `Date.parse()`

Vielleicht stößt du auf Erwähnungen oder Verweise auf eine Funktion zum Parsen von Datumsangaben namens `Date.parse`.
Da es für diese Funktion nur wenige Invarianten (also gesicherte Aussagen) gibt und der Rest der Implementierung nicht spezifiziert (und damit nicht standardisiert) ist, solltest du sie nicht verwenden.

## Zugriff auf `Date`-Komponenten

Es gibt verschiedene Methoden auf Datumsobjekten, die die Bestandteile des Datums zurückgeben:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

Jede dieser Methoden hat eine passende `set`-Variante (z. B. `setFullYear`), um den Wert zu aktualisieren.
Ein überlaufender Wert geht auf die nächste Komponente über:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

Für alle Methoden gibt es UTC-Varianten, die die lokale Zeitzone ignorieren.

## Von einem Datum umwandeln

Datumsobjekte haben eine Methode `getTime()`, die den UNIX-Zeitstempel in Millisekunden zurückgibt, also die Anzahl der Millisekunden seit Mitternacht am Anfang des 1. Januar 1970 UTC.
Außerdem gibt es die Methode `toISOString()`, mit der du ein Datumsobjekt in einen ISO-8601-Zeitstempel-String umwandeln kannst.

## Datumsangaben vergleichen

Größer als (`>`), größer oder gleich (`>=`), kleiner als (`<`) und kleiner oder gleich (`<=`) kannst du direkt zwischen zwei Datumsangaben oder zwischen einem Datum und einer Zahl verwenden.
Das funktioniert, weil JavaScript versucht, das Datum in einen primitiven Wert umzuwandeln.

Letzteres ist dasselbe wie ein Aufruf von [`date.getTime()`][mdn-date-get-time].

Wenn du dich nicht auf dieses Verhalten verlassen willst, wandle den Wert zuerst mit `getTime()` in eine Zahl um.
