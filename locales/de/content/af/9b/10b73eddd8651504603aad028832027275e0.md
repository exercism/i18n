# Tests

Zum Ausführen der Tests musst du zuerst `cmake -G` ausführen und dann den Build-Befehl verwenden, der zu deiner Plattform passt.
Eine ausführliche Anleitung dazu findest du auf der Seite [Tests ausführen][cpp-tests-instructions] für C++ auf exercism.org.

## Die Tests bestehen

Wenn du eine neue Übung lokal startest, sind die Dateien so konfiguriert, dass nur der erste Test ausgeführt wird.
Bring diesen ersten Test zum Kompilieren, Linken und Bestehen, indem du die [drei Regeln der testgetriebenen Entwicklung][three-laws-of-tdd] befolgst.
Erstelle gerade so viel Struktur, indem du Namespaces, Funktionen, Klassen usw. deklarierst, dass die Compilerfehler verschwinden und der Test fehlschlägt.
Dann schreib gerade so viel Code, dass der Test besteht.
Wenn du das geschafft hast, kommentiere den nächsten Test aus, indem du die Zeile `if defined(EXERCISM_RUN_ALL_TESTS)` hinter den nächsten Test verschiebst.

Sieh dir das folgende Beispiel aus der Übung Bob an (Datei `bob_test.cpp`, Zeile 15):

```diff
-#if defined(EXERCISM_RUN_ALL_TESTS)
TEST_CASE("shouting")
{
    REQUIRE("Whoa, chill out!" == bob::hey("WATCH OUT!"));
}
+#if defined(EXERCISM_RUN_ALL_TESTS)
```

Wenn du diese Zeile hinter den nächsten Test verschiebst, kann es zu Compilerfehlern kommen, weil neue Konstrukte verwendet werden, die du noch nicht deklariert oder definiert hast.
Behebe die Compilerfehler wieder nur so weit, dass du einen fehlschlagenden Test bekommst, ändere dann den Code gerade so weit, dass der Test besteht, mach deine Implementierung lesbarer und ausdrucksstärker und wende dich dann dem nächsten Test zu.

Versuche, die Standardmittel von C++17 zu nutzen, statt eigene Low-Level-Algorithmen oder -Konstrukte von Hand zu schreiben.
