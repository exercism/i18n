# Über

Die zwei wichtigsten Arten von Eigenschaften sind

1. automatisch implementierte Eigenschaften, bei denen die `get`- und `set`-Accessoren keinen Rumpf haben.
   Sie können explizit initialisiert werden oder auch nicht. Zum Beispiel:
   ```csharp
   public int MyProperty {get; set;} = 42;
   ```
2. solche, bei denen die Accessoren Ausdrücke auswerten und Anweisungen ausführen. Der Code kann
   so einfach sein wie das Zurückgeben oder Zuweisen eines Backing Fields. Zum Beispiel:
   ```csharp
   private int myField;
   public int MyProperty
   {
     get { return myField; }
     set { myField = value; }
   }
   ```

Es gibt erhebliche Überschneidungen bei Verhalten und Möglichkeiten zwischen Eigenschaften und Methoden.
Wenn sie nicht automatisch implementiert sind, können Eigenschaften jede Anweisung oder jeden Ausdruck
enthalten, der innerhalb des Gültigkeitsbereichs der Klasse vorkommen kann. Häufig werden sie
als Umhüllung eines Backing Fields beschrieben.
Auch wenn meistens klar ist, ob ein Verhalten in einem bestimmten Fall als Eigenschaft oder als Methode
umgesetzt werden sollte, ist es oft eine Ermessensfrage für den Entwickler, und insbesondere, wie viel Code
in den Accessoren ausgeführt werden soll. Validierung in einem set-Accessor und einfache Berechnungen oder
Formatierungen in einem get-Accessor findet man häufig:

```csharp
private float fraction;
public float Percentage
{
  get { return fraction * 100; }
  set
  {
    if (value < 0 || value > 100)
    {
      throw new ArgumentException("Percentage must be between 0 and 100");
    }
    fraction = value / 100;
  }
}
```

Ähnlich wie andere Member einer Klasse können Eigenschaften Zugriffsebenen haben.
Meistens haben Eigenschaften eine nicht private Zugriffsebene, passend zu
ihrem eigentlichen Zweck. Manchmal hat einer der Accessoren
eine andere Zugriffsebene als die Eigenschaft. Im Fall von `TareWeight`
gab es unter der eher künstlichen Vorgabe der „Sicherheit“ die Möglichkeit,
eine öffentliche Eigenschaft mit einem privaten Getter zu haben. Das bedeutet, dass Code außerhalb
der Klasse den Wert der Eigenschaft setzen kann, aber nur Code innerhalb
der Klasse kann ihn lesen (get).

```csharp
public int ConfidentialValueUsedInternally {private get; set; }
```

Nicht öffentliche set-Accessoren werden ebenfalls unterstützt, aber häufiger ist der Fall,
dass der set-Accessor ganz weggelassen wird. Das liegt vielleicht daran,
dass der Wert der Eigenschaft im Konstruktor der Klasse gesetzt wird.

```csharp
class MyClass
{
  public MyClass( int importantValue)
  {
    ConstructedValue = importantValue;
  }
  public int ConstructedValue {get;}
}
```
