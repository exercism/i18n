# Anleitung

Nach einer kürzlich durchgeführten Sicherheitsüberprüfung wurdest du darum gebeten, die archivierten Logdateien der Organisation aufzuräumen.

## 1. Verstümmelte Logzeilen erkennen

Du brauchst einen Überblick darüber, wie viele Logzeilen in deinem Archiv nicht den aktuellen Standards entsprechen.
Du bist der Meinung, dass ein einfacher Test zeigt, ob eine Logzeile gültig ist.
Um als gültig zu gelten, muss eine Zeile mit einem der folgenden Strings beginnen:

- `[DEBUG]`
- `[INFO]`
- `[WARNING]`
- `[ERROR]`

Implementiere die Funktion `is_valid_line`, die `True` zurückgibt, wenn die Logzeile gültig ist.

```gleam
log_parser.valid_line("[ERROR] Network Failure")
// -> True

log_parser.valid_line("Network Failure")
// -> False
```

## 2. Die Logzeile aufteilen

Kurz nachdem du mit dem Projekt zur Loganalyse begonnen hast, stellst du fest, dass die Logs einer Anwendung nicht wie bei den anderen in Zeilen aufgeteilt sind. In diesem Projekt steht das, was eigentlich separate Zeilen sein sollten, auf einer einzigen Zeile, verbunden durch ausgefallene Pfeile wie `<--->` oder `<*~*~>`.

Tatsächlich kann jeder String, dessen erstes Zeichen `<`, dessen letztes Zeichen `>` ist und der dazwischen null oder mehr der folgenden Zeichen `~`, `*`, `=` und `-` enthält, in den Logs dieses Projekts als Trennzeichen verwendet werden.

Implementiere die Funktion `split_line`, die eine Zeile entgegennimmt und eine Liste von Strings zurückgibt.

```gleam
log_parser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
// -> ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. Zeilen mit Benutzernamen markieren

Du hast bemerkt, dass einige der Logzeilen Sätze enthalten, die sich auf Benutzer beziehen.
Diese Sätze enthalten immer den String `"User"`, gefolgt von einem oder mehreren Leerzeichen und dann einem Benutzernamen.
Du beschließt, solche Zeilen zu markieren.

Implementiere eine Funktion `tag_with_user_name`, die Logzeilen verarbeitet:

- Zeilen, die den String `"User"` nicht enthalten, bleiben unverändert.
- Bei Zeilen, die den String `"User"` enthalten, stelle der Zeile `[USER]` gefolgt vom Benutzernamen voran.

```gleam
log_parser.tag_with_user_name("[INFO] User Alice created a new project")
// -> "[USER] Alice [INFO] User Alice created a new project"
```

Du kannst davon ausgehen, dass:

- auf jedes Vorkommen des Strings `"User"` ein oder mehrere Leerzeichen und der Benutzername folgen.
- der String `"User"` höchstens einmal pro Zeile vorkommt.
- Benutzernamen nicht leere Strings sind, die keine Leerzeichen enthalten.
