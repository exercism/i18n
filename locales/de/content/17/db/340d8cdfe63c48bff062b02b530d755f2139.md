# Über

Common Lisp bietet Programmierenden mehrere verschiedene Bedingungsausdrücke, die sich nach der Anzahl der „Zweige“ kategorisieren lassen, die sie unterstützen.

Anders als in vielen anderen Programmiersprachen sind außerdem alle Bedingungsausdrücke in Common Lisp _Ausdrücke_ und keine Anweisungen.
Das bedeutet, dass alle Lisp-Bedingungsausdrücke zu einem Wert ausgewertet werden und für konkrete Parameter eingesetzt werden können.

Ein Beispiel:

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## Einzweigige Bedingungsausdrücke

Die Bedingungsausdrücke `when` und `unless` werten nur dann Code aus, wenn der angegebene Test wahr bzw. falsch ist; andernfalls ergeben sie `nil`.

Der Teil nach dem Testausdruck kann aus mehr als einem Ausdruck bestehen.

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## Der Bedingungsausdruck mit zwei Zweigen

Der `if`-Bedingungsausdruck wertet den ersten Ausdruck des Rumpfs aus, wenn der Test wahr ist, andernfalls den zweiten.

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

Beachte, dass die Dann- und die Sonst-Klausel jeweils nur aus einem einzigen Ausdruck bestehen dürfen.

## Bedingungsausdrücke mit vielen Zweigen

Der Lisp-„Super-Bedingungsausdruck“ ist `cond`, der unendlich viele Zweige haben kann.
Jeder Zweig hat eine Testbedingung und einen Rumpfausdruck, die von einem zusätzlichen Paar runder Klammern umschlossen werden.
Wenn alle Tests falsch ergeben, wird `nil` zurückgegeben.

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

Beachte, dass die Anzahl der Ausdrücke nach dem Testausdruck unbegrenzt ist.

Wenn du nur einen Wert gegen eine Reihe von Zweigen testen möchtest, kannst du den übersichtlicheren `case`-Ausdruck verwenden.
Wenn keiner der Fälle passt, wird `nil` zurückgegeben.
Sowohl `t` als auch `otherwise` können als Auffangfälle verwendet werden:

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

Beachte, dass wie bei `cond` die Anzahl der Ausdrücke nach dem Testausdruck unbegrenzt ist.

## Die getarnten Bedingungsausdrücke

Die booleschen Operationen `and` und `or` in Common Lisp sind Makros mit Kurzschlussauswertung, mit denen sich die Duplizierung bestimmter Bedingungsausdrücke reduzieren lässt.

Das `and`-Makro gibt sofort `nil` zurück, wenn ein einziger falscher Wert auftritt, andernfalls aber den letzten wahren Wert des `and`:

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

Das `or`-Makro gibt den ersten wahren Wert zurück, der ihm begegnet, oder `nil`, wenn es keine wahren Werte gab:

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## Ich bin erschöpft...

Wie bereits erwähnt: Wenn keiner der Zweige in einer `case`-Anweisung passt und es keine `otherwise`-Klausel gibt, wird `nil` zurückgegeben.
Gelegentlich sollte ein fehlender Treffer in allen Zweigen jedoch als Fehler behandelt werden; hier kommt `ecase` (für **erschöpfende** Übereinstimmung) ins Spiel.

Es wird genauso wie `case` verwendet, signalisiert aber einen Fehler, anstatt `nil` zurückzugeben, wenn es keine Übereinstimmung gibt.

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
