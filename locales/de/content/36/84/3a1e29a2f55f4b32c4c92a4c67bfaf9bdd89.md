# Überblick

## Partielle Applikation

In Elm sind alle Funktionen [curryed][currying], das heißt: Wenn du eine Funktion aufrufst, ohne alle Argumente zu übergeben, gibt sie eine neue Funktion zurück.

Das Ergebnis davon nennt man [partielle Applikation][partial-application] (du übergibst nicht alle Argumente an die Funktion, sondern wendest sie nur teilweise an).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

Bei der partiellen Applikation werden die Argumente immer in der Reihenfolge angewendet.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## Pipe-Operator (`|>`)

`x |> f` zu schreiben ist genau dasselbe wie `f x`. Ein konkretes Beispiel: `"5" |> String.toInt` ist dasselbe wie `String.toInt "5"`.

Das klingt zunächst nicht besonders nützlich, aber er heißt [Pipe-Operator][pipe-operator], weil du damit Code in Form einer Pipeline schreiben kannst.

Angenommen, wir haben zum Beispiel eine sanitize-Funktion, die Benutzereingaben in Ganzzahlen umwandelt:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Wir können sie so umschreiben:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Das vermeidet Klammern und zeigt die Funktionen in der Reihenfolge, in der sie angewendet werden (zuerst `String.trim`, dann `String.toInt`), was die Lesbarkeit verbessert.

Es gibt auch einen [umgekehrten Pipe-Operator `(<|)`][reverse-pipe-operator].
`x <| f` zu schreiben ist genau dasselbe wie `f x`.
Auch das sieht auf den ersten Blick nicht besonders nützlich aus und wird definitiv nicht so oft verwendet wie der Pipe-Operator, aber in manchen Situationen hilft es, Klammern zu vermeiden.

## Funktionskomposition / Point-Free-Stil

Der Operator [`(>>)`][forward-composition] hat den Typ `(a -> b) -> (b -> c) -> (a -> c)` und erzeugt eine Funktion vom Typ `a -> c`, indem er zwei zueinander passende Funktionen vom Typ `a -> b `und `b -> c` komponiert.
Dazu nimmt er den Rückgabewert (vom Typ `b`) der ersten Funktion und verwendet ihn als erstes Argument der zweiten Funktion (die denselben Typ `b` haben muss).
Die erzeugte Funktion nimmt denselben Eingabewert (vom Typ `a`) wie die erste Funktion entgegen und gibt das zurück, was die zweite Funktion als `c` zurückgibt.

Ein konkretes Beispiel ist `String.trim >> String.toInt`.
`String.trim` nimmt einen String als einzigen Parameter, also nimmt die erzeugte Funktion denselben.
`String.toInt` gibt ein `Maybe Int` zurück, also gibt die erzeugte Funktion dasselbe zurück.
`String.trim` gibt einen `String` zurück, den `String.toInt` als Parameter akzeptiert, also lässt sich das Beispiel kompilieren.

Jetzt können wir unsere `sanitize`-Funktion so umschreiben:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Beachte, dass wir den Parameter `input` aus dem ursprünglichen Beispiel nicht mehr verwenden, obwohl die Funktionalität identisch ist.
Diese Art, Funktionen zu erstellen, die ihre Parameter nicht erwähnen, heißt „Point-Free-Stil".
Der Vorteil dieses Stils ist, dass der Code kürzer ist, der Nachteil, dass er schwerer zu verstehen sein kann, besonders für Anfänger.

Denk daran, dass in Elm alle Funktionen curryed sind, deshalb lässt sich `String.length >> max` kompilieren, und das ergibt Folgendes:

- Eine Funktion (1), die einen String-Parameter hat (die Eingabe für `String.length`)
- `max` ist eine Funktion mit zwei `Int`-Parametern, aber Funktion 1 übergibt ihr eine einzelne `Int` (den Rückgabewert von `String.length`), also wird `max` partiell angewendet.
- Der Rückgabewert der partiell angewendeten `max`-Funktion ist eine weitere Funktion (2), die eine `Int` entgegennimmt und die größere dieser `Int` und der partiell angewendeten `Int` aus `String.length` zurückgibt
- Somit gibt Funktion 1 (`String -> Int`) Funktion 2 (`Int -> Int`) zurück
- Also gibt `((String.length >> max) "123") 2` den Wert `3` zurück, weil `"123"` die Länge 3 hat, was größer ist als die 2 aus dem `Int`-Argument.

## Funktionsdesign

Damit du in Elm leicht eleganten Code schreiben kannst, solltest du die Haupt-Datenstruktur zum letzten Parameter von Funktionen machen.
Alle gängigen Funktionen der Standardbibliothek machen das, zum Beispiel `List.map` (Typsignatur unten).

```elm
map : (a -> b) -> List a -> List b
```

Hier sehen wir, dass der letzte Parameter der Funktion `map` `List a` ist und sie `List b` zurückgibt, die Haupt-Datenstruktur (`List`) also der letzte Parameter ist.

So kannst du eleganten Code in Pipeline-Form schreiben, wie im folgenden Beispiel.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Außerdem ist es so bequem möglich, Funktionskomposition und Point-Free-Stil als Alternative zur Pipeline zu verwenden.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

Mit Funktionskomposition kannst du dieses Beispiel auch auf einen einzigen Aufruf von `List.map` reduzieren.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
