# Über

Um [`Box`][box] zu verstehen, ist es hilfreich zu wissen, was [Stack und Heap][stack and heap] sind.

Der Stack ist ein Speicherbereich, der wie ein Last-In-First-Out-Puffer (LIFO) arbeitet. Daten auf den Stack zu pushen geht sehr schnell, und sie wieder herunterzunehmen ebenfalls.
Bei den Daten kann es sich um Variablen oder Funktionsadressen handeln, aber ihre Größe muss zur Kompilierzeit bekannt und fest sein.

Wenn die Größe der Daten zur Kompilierzeit unbekannt ist oder sich ändern kann, müssen sie auf dem Heap allokiert werden. Beim Allokieren muss genug Platz auf dem Heap gefunden werden, um die Daten zu speichern, die Daten müssen auf den Heap geschrieben und die Speicheradresse dieser Daten auf den Stack gelegt werden. All das dauert deutlich länger, als Daten einfach auf den Stack zu legen. Das Abrufen von Daten vom Heap ist etwas langsamer, weil wir über die Adresse auf dem Stack gehen und ihr zum Speicherort der Daten auf dem Heap folgen müssen.

`Box` ist ein Smart Pointer, der Daten auf dem Heap allokiert. Die Adresse liegt auf dem Stack und zeigt auf die Daten auf dem Heap. Ein [Grund][reasons], `Box` zu verwenden, ist, Daten auf dem Heap abzulegen, wenn du einen Typ hast, dessen Größe zur Kompilierzeit nicht bekannt sein kann, und du einen Wert dieses Typs in einem Kontext verwenden möchtest, der eine genaue Größe erfordert. Ein praktischer Anwendungsfall dafür ist, wenn du mehrere Structs hast, die du über ein Trait, das sie alle implementieren, auf dieselbe Weise behandeln möchtest, wie im folgenden Beispiel.

Sagen wir, wir haben zwei Structs. Jedes Struct steht für etwas, das nerven kann. Wir können jedes Struct ein Annoyance-Trait implementieren lassen, und zwar so

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

Nehmen wir nun an, wir wollen eine Funktion, die uns abhängig von der übergebenen Tageszeit ein Annoyance-Objekt liefert. Wir können zuerst Folgendes versuchen und stellen fest, dass es nicht kompiliert

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

Der Compiler sagt uns in seiner ganzen Hilfsbereitschaft genau, was zu tun ist: nämlich ein geboxtes Trait-Objekt zurückzugeben. Falls du nicht weißt, was ein Trait-Objekt ist: Einfach gesagt ist es eine Möglichkeit, über [dynamisches Dispatch][dynamic dispatch] aus einer Funktion ein konkretes Objekt zurückzugeben, die jedes Objekt zurückgeben könnte, das ein bestimmtes Trait implementiert. Da wir dynamisches Dispatch brauchen, können wir einfach ein `dyn` vor den Namen des Traits setzen und sehen, ob wir damit durchkommen.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

Einer der Fehler besagt, dass die Größe von `dyn Annoyance` zur Kompilierzeit nicht bekannt sein kann. Das liegt daran, dass `annoy_me` nicht im Voraus weiß, welches konkrete Trait-Objekt es zurückgeben wird, wenn es aufgerufen wird. Structs, die Annoyance implementieren, könnten unterschiedliche Felder und unterschiedliche Größen haben. Und wir werden daran erinnert, dass `Box` unter anderem für einen Typ verwendet wird, dessen Größe zur Kompilierzeit nicht bekannt sein kann. Also versuchen wir nun einen `Box`-Rückgabewert und boxen die Werte, die der `match`-Ausdruck zurückgibt, so

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

Die Signatur von `Box` ist `Box<T>`, wobei `T` für den konkreten Typ steht, der geboxt werden soll und der in den spitzen Klammern steht, wie oben in `Box<dyn Annoyance>`.

Wir können das geboxte Trait-Objekt so verwenden

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

was Folgendes ausgibt

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

Da `my_annoyance` vom Typ `Box<dyn Annoyance>` ist, muss es mit dem Deref-Operator `*` aus der `Box` dereferenziert werden. Danach wird es als `dyn Annoyance` referenziert, damit die Funktion `be_annoying` es ausleihen kann.

Eine andere Möglichkeit wäre, die Anforderung fallen zu lassen, dass der Parameter eine feste Größe hat. In diesem Fall würde der Compiler für jede Variante von Annoyance eine eigene Funktion erzeugen, damit statisches Dispatch möglich ist (ein Vorgang, den man [Monomorphisierung][monomorphization] nennt), und zwar so

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

Noch eine andere Möglichkeit wäre, dass die Funktion `be_annoying` ein `Box<dyn Annoyance>` annimmt und [Deref-Koersion][deref coercion] nutzt, um die `Box` nicht manuell dereferenzieren zu müssen. Damit würde die Ownership des Annoyance-Trait-Objekts an die Funktion `be_annoying` übergehen. Sie würde am Ende der Funktion ihren Gültigkeitsbereich verlassen und nicht mehr zur Verfügung stehen.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
