# Über

Wenn wir in Gleam ein Pattern Matching auf einen Wert anwenden, müssen wir sicherstellen, dass die Muster jeden möglichen Wert des Typs abdecken, sonst lässt sich der Code nicht kompilieren.

Diese Funktion sollte abgelehnt werden, weil sie den Fall nicht behandelt, in dem die Liste leer ist:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Meistens wollen wir in Gleam-Programmen jeden möglichen Fall behandeln, aber in manchen Programmen, etwa Prototypen und kleinen Skripten, wollen wir uns vielleicht nur auf den Happy Path konzentrieren und keinen Code für die anderen Fälle schreiben. Genau hier kommt `let assert` von Gleam ins Spiel.

Mit let assertions kann ein Muster nur einen Teil der möglichen Werte eines Typs abdecken, und wenn das Muster nicht zu einem Wert passt, stürzt das Programm ab. Mit `let assert` können wir die obige Funktion so schreiben:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam-Bibliotheken sollten niemals let assertions verwenden, da sie das Programm zum Absturz bringen können. Stattdessen sollten sie den Typ `Result` verwenden und die Entwicklerin oder den Entwickler der Anwendung entscheiden lassen, wie mit Fehlern umgegangen wird.
