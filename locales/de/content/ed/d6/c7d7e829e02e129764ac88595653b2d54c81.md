# Anhang zu den Anweisungen

## Odin-spezifische Anweisungen

### Zipper auf Binärbäumen

In den Anweisungen oben wird der Zipper anhand eines Rose Tree (mehrere Kinder pro Knoten) erklärt, aber das Zipper-Konzept lässt sich auf jede Art von Baum anwenden und sogar auf Listen.
In dieser Übung verwenden wir einen Binärbaum (jeder Knoten hat zwei Kinder), damit wir uns auf die Zipper-Operationen konzentrieren können statt auf die Verwaltung einer dynamischen Anzahl von Kindern.

Die in den Anweisungen aufgeführten Operationen wurden an Binärbäume angepasst:

| Operation       | Beschreibung                                                                |
| --------------- | -------------------------------------------------------------------------- |
|`zip_from_tree`  | Erzeugt einen Zipper aus einem Baum, der Fokus liegt auf dem Wurzelknoten.  |
|`zip_to_tree`    | Holt den Baum aus dem Zipper.                                               |
| `zip_value`     | Ermittelt den Wert des Fokusknotens.                                        |
| `zip_left`      | Verschiebt den Fokus auf das linke Kind des Fokusknotens, gibt einen neuen Zipper zurück.  |
| `zip_right`     | Verschiebt den Fokus auf das rechte Kind des Fokusknotens, gibt einen neuen Zipper zurück. |
| `zip_up`        | Verschiebt den Fokus auf den Elternknoten des Fokusknotens, gibt einen neuen Zipper zurück. |
| `zip_set_value` | Setzt den Wert des Fokusknotens, gibt einen neuen Zipper zurück.             |
| `zip_set_left`  | Setzt den linken Teilbaum des Fokusknotens, gibt einen neuen Zipper zurück.  |
| `zip_set_right` | Setzt den rechten Teilbaum des Fokusknotens, gibt einen neuen Zipper zurück. |

### Speicherverwaltung

In Odin musst du den Speicher selbst verwalten.
Um die Übung zu vereinfachen und den Fokus auf die Zipper-Operationen zu legen, wird der Speicher für die Baumknoten und die Pfade über einen Arena-Allocator automatisch für dich verwaltet.
Du musst nur bei Bedarf mit `new(Node)` und `new(Step)` Speicher allokieren; wenn wir mit der Arbeit am Baum fertig sind, ruft der Test automatisch `free_all()` auf der Arena auf.
Das ist der idiomatische Weg, in Odin mit Speicherallokationen für jeden wiederkehrenden Prozess umzugehen (wie eine Game Loop oder eine Reihe von Anfragen und Antworten).

Wenn du mehr über Allocatoren in Odin erfahren möchtest, speziell über Arena-Allocatoren, könnten die folgenden Dokumente interessant für dich sein: [Das Kapitel über Allocatoren in der Odin-Übersicht][allocators-overview], [Understand the Temporary Allocator; Understand arenas von Karl Zylinski][allocators-zylinksi] und [Linear/Arena Allocators von gingerBill][allocators-gingerbill].
