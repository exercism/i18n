# Über

Eine `MACRO:`-Deklaration ist ein Wort, dessen *Rumpf* zur Kompilierzeit ausgeführt wird. Der Rumpf entnimmt dem Stack zur Kompilierzeit literale Argumente und muss eine Quotation darauf hinterlassen. Der Compiler ersetzt dann den Makroaufruf durch diese Quotation, sodass das Laufzeitprogramm das Makro nie zu sehen bekommt, sondern nur den Code, den es erzeugt hat.

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- compound )
    dup append ;
```

Wenn ein Aufrufer `[ 1 + ] twice` schreibt, führt der Compiler den Rumpf mit `[ 1 + ]` auf dem Stack aus, bekommt `[ 1 + 1 + ]` zurück und fügt das dort ein. Es gibt keinen Laufzeit-Overhead: Die Schleife oder der Kombinator, den das Makro ersetzt hat, ist verschwunden.

## Eingaben müssen Literale sein

Da der Rumpf zur Kompilierzeit läuft, muss jede Eingabe an der Aufrufstelle ein *Literal* sein: eine `[ … ]`-Quotation, eine Zahl, ein Array oder ein String. Einen Nicht-Literal-Wert zu übergeben (also einen, der erst zur Laufzeit bekannt ist) ist ein Kompilierzeitfehler.

```factor
! works: [ 1 + ] is a literal quotation
: inc-twice ( x -- y ) [ 1 + ] twice ;

! refused: f is a literal, but the macro can't run with a non-quotation
! input where the body expects to call `append` on it
```

## Strukturelle Eingaben erzeugen strukturelle Ausgabe

Die interessanten Makros nehmen eine *Struktur* (ein Array, eine literale Folge von Paaren) und erzeugen Code, dessen Form von dieser Struktur abhängt. `each-literal` aus dieser Übung nimmt eine literale Folge und eine Quotation und erzeugt für jedes Element eine curryisierte und inline eingefügte Kopie der Quotation. Das Laufzeitprogramm ist geradliniger Code, kein `each`, kein Dispatch pro Element, und die Iteration über die Folge fand vollständig zur Kompilierzeit statt.

## Warum es kein Hygiene-Problem gibt

Lisp-Makros ringen mit der *Hygiene*: Ein Makro, das einen lokalen Namen einführt, kann mit Namen an der Aufrufstelle kollidieren, was `gensym` oder ein Hygiene-System erfordert. Factor hat dieses Problem nicht, weil Quotations Folgen von *aufgelösten Wortreferenzen* sind: Jedes Wort wird zur Parsezeit nachgeschlagen, nicht symbolisch zur Expansionszeit. Ein `dup` in einer makroerzeugten Quotation ist immer `kernel:dup`, egal, welche Namen an der Aufrufstelle existieren.

Der Preis: Factor-Makros können keine neuen Bindungen einführen, wie `defmacro` es kann. Sie bauen Code aus Wörtern, die der Parser bereits gesehen hat. Für die meisten Metaprogrammierungsaufgaben reicht das.

## Verwandte Formen (hier nicht behandelt)

- `MACRO::`: die Locals-Form von `MACRO:`, so wie `::` die Locals-Form von `:` ist. Nützlich, wenn der Rumpf seine Eingaben mehr als einmal referenziert.
- `<< … >>`: ein Auswertungsblock zur Parsezeit. Führt gewöhnliches Factor zur Kompilierzeit aus, ohne den Vertrag, eine Quotation zurückzugeben. Nützlich, um einen Wert zu berechnen, der schon zur Parsezeit existieren muss (zum Beispiel eine `CONSTANT:`, die aus einem Umgebungs-Lookup abgeleitet wird).
- `SYNTAX:`: *Parsing-Words*. Ein anderes Kaliber: Sie arbeiten auf dem Token-Stream des Parsers, nicht auf Werten, und laufen in einer noch früheren Phase. Damit werden neue literale Syntaxen definiert (`T{ }`, `H{ }`). Gehört nicht zum Umfang dieses Konzepts.
- `functor:`: deklarative Vorlagen, die aus einer einzigen Spezifikation Gruppen verwandter Wörter erzeugen. Baut auf der Makro-Maschinerie auf; das Terrain von Bibliotheksautoren.
