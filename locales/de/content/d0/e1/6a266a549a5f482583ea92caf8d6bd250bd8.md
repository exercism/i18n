# Einführung

Eine **Schleife** ist eine Folge von Befehlen, die möglicherweise mehr als einmal ausgeführt wird, bis eine Abbruchbedingung erfüllt ist.

In x86-64 wird eine Schleife normalerweise mit einem Sprung zu einer vorherigen Sprungmarke erzeugt:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Beachte, dass ein unbedingter Sprung zu einer vorherigen Sprungmarke immer dazu führt, dass die Ausführung bei dieser Sprungmarke landet.
Das bedeutet, dass die Schleife endlos weiterläuft, es sei denn, es gibt einen weiteren Sprung aus der wiederholten Sequenz heraus.

Zum Beispiel endet diese Schleife nicht:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Und diese Schleife kann enden, je nachdem, ob die Bedingung erfüllt wird:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Zählschleifen

Eine Zählschleife endet fast immer auf dieselbe Weise: ein Befehl, der einen Zähler aktualisiert oder zwei Werte vergleicht, unmittelbar gefolgt von einem bedingten Sprung, der entscheidet, ob die Schleife noch einmal durchlaufen wird.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0` ist im obigen Code nicht nötig, weil `sub rsi, 1` das `zero flag (ZF)` bereits setzt, wenn das Ergebnis `0` ist.

Obwohl `cmp` in Assemblersprache die übliche Art ist, Bedingungen zu prüfen, aktualisieren viele Befehle die Flags.
Zum Beispiel aktualisieren viele arithmetische oder bitweise Befehle für Ganzzahlen `ZF`, wenn das Ergebnis `0` ist, und `SF`, wenn es negativ ist (d. h. das höchste Bit ist gesetzt).

Du kannst in einer [Referenz][reference] nachsehen, welche Flags von welchem Befehl beeinflusst werden.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Beachte, dass im obigen Beispiel angenommen wird, dass `rsi` größer als `0` ist.
Wenn `rsi` `0` wäre, würde `sub rsi, 1` `rsi` auf `-1` reduzieren, was eine sehr große vorzeichenlose Zahl ist.
Es würde `18,446,744,073,709,551,615` weitere Iterationen dauern, bevor die Schleife schließlich endet.
Außerdem läge jeder Speicherzugriff außerhalb der Grenzen, weil die Länge des Arrays `0` ist.

Wenn es keine Garantien für die Länge eines Arrays gibt, gibt es zwei übliche Vorgehensweisen.

Bei der ersten wird die Abbruchbedingung an den Anfang der Schleife verschoben und am Ende ein unbedingter Sprung eingefügt:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

Bei der zweiten wird vor Beginn der Schleife einmal geprüft, ob das Array die Länge 0 hat:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Diese zweite Vorgehensweise ist normalerweise effizienter als die erste, weil es weniger Verzweigungen im Schleifenblock gibt.
Mehr darüber erfährst du in einem zukünftigen Konzept.

~~~~exercism/advanced
In manchen Situationen können moderne CPUs zwei verschiedene Befehle zu einer einzigen Operation zusammenfassen.
Diese Optimierung heißt **Makrofusion**.

Viele arithmetische Befehle wie `sub` und `add` sowie `cmp` und `test` verschmelzen häufig mit einem bedingten Sprung, der unmittelbar darauf folgt.
Das bedeutet, dass ein Befehl wie `cmp rax, rdx`, auf den unmittelbar ein bedingter Sprung folgt, von der CPU normalerweise als eine einzige Operation behandelt werden kann.

Die Makrofusion hängt von der CPU ab, und es gibt Unterschiede darin, welche Befehle mit welchem bedingten Sprung verschmelzen.

Eine nützliche Referenz ist [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
Abschnitt 3.4.2.2 (Optimizing for Macrofusion) des [Intel optimization reference manual][intel-opt] listet ebenfalls fusionierbare Paare für Intel-CPUs auf.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
