# Gleitkommazahlen

`FLTD` speichert eine Zahl, die einen Bruchteil haben kann. Ein Literal braucht einen Dezimalpunkt und ein `d`:

```sather
   440.0d
   0.5d
   -2.25d
```

`FLT` ist dasselbe Konzept mit halber Genauigkeit. In diesem Track wird durchgehend `FLTD` verwendet; es gibt keinen Grund, zu `FLT` zu greifen, es sei denn, der Speicher ist knapp.

## Arithmetik

| Operator | Bedeutung |
| --- | --- |
| `+` `-` `*` | wie bei `INT` |
| `/` | Division, behält den Bruchteil |

Für `FLTD` gibt es kein `%`.

Beide Operanden müssen `FLTD` sein. Eine `INT` dazwischenzumischen ist ein Compilerfehler und keine stille Umwandlung. Das ist gut so: Die einzige Stelle, an der das wehtut, ist genau die Stelle, an der es die Leute falsch machen.

## Umwandeln

```sather
   7.fltd            -- 7.0, an INT made into an FLTD
   7.5d.int          -- 7, the fraction thrown away
   7.5d.round        -- 8, to the nearest whole number
   7.5d.floor        -- 7.0, down to a whole number
   7.5d.ceiling      -- 8.0, up to a whole number
```

Wandle vor dem Dividieren um, niemals danach: `n.fltd / 2.0d` behält die Hälfte, `(n / 2).fltd` hat sie bereits verloren.

## Nützliche Routinen

```sather
   (-2.5d).abs       -- 2.5
   2.0d.sqrt         -- 1.41421
   (2.0d).max(3.0d)  -- 3.0
```

## Gleitkommazahlen sind Näherungswerte

Ein `FLTD` speichert eine sehr gute Näherung, nicht den exakten Wert. Die meisten Dezimalbrüche lassen sich nicht exakt speichern, genauso wie sich ein Drittel nicht exakt als Dezimalzahl schreiben lässt. Also:

```sather
0.1d + 0.2d          -- very nearly 0.3, but not exactly
```

Zwei Konsequenzen, die man sich merken sollte:

**Vergleiche nicht mit `=`.** Zwei Berechnungen, die dasselbe Ergebnis liefern sollten, unterscheiden sich oft in den letzten paar Stellen. Frag stattdessen, ob sie nah beieinander liegen:

```sather
   (a - b).abs < 0.0001d
```

**Das Addieren vieler kleiner Werte kostet Genauigkeit.** Jede Addition rundet ein wenig, und die Fehler summieren sich.

Wenn Werte exakt sein müssen, besonders bei Geld, zähle stattdessen in ganzen Einheiten mit `INT` (Cent statt Dollar).

## Ausgabe

`.str` zeigt etwa sechs signifikante Stellen, das ist weniger als die tatsächlich gespeicherte Genauigkeit:

```sather
   #OUT + (1.0d / 3.0d).str;      -- 0.333333
```
