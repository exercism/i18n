# Einführung

[concept:csharp/resource-cleanup]() verwendet die `IDispose`-Schnittstelle, um zu signalisieren, dass die Ressource eines Objekts oder ein anderer Programmzustand freigegeben oder zurückgesetzt werden musste, wenn das Objekt nicht mehr benötigt wurde (und dass man sich dabei nicht auf den Garbage Collector verlassen konnte, weil dieser das nicht erreichen würde und auch nicht die nötige Kontrolle bietet), und dass die Methode `IDisposable.Dispose()` der natürliche Ort für solche Aufräumarbeiten war.

Es gibt ein weiteres Konstrukt, den `using`-Block. Aus Sicht des Aufrufers lassen sich damit alle Aufgaben rund um die Lebensdauer von Ressourcen in einer einzigen Anweisung bündeln.

```csharp
using (var file = new File("my_secrets"))
{
    file.WriteSecret("xxxxxxx");
}
```

Im obigen Beispiel werden die mit `file` verbundenen Dateisystemressourcen an das Betriebssystem zurückgegeben, sobald der `using`-Block verlassen wird.

Damit das Muster funktioniert, muss die Variable in der using-Anweisung ein Referenztyp sein, der die `IDisposable`-Schnittstelle implementiert, und in seiner `Dispose()`-Methode Ressourcen freigeben bzw. den Programmzustand zurücksetzen.

C# 8 führt eine Verfeinerung dieses Musters ein. Eine using-Anweisung kann am Anfang eines Blocks stehen.

```csharp
using var drawingResource = some_provided_or_new_object;
try
{
    drawingResource.DrawSomething();
}
catch (Exception)
{
    throw;
}
```

Wer in Java entwickelt, erkennt darin vielleicht ein Analogon zum Mechanismus der _automatischen Ressourcenverwaltung_, der in Java 7 eingeführt wurde.
