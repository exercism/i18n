# Über


Jetzt geht es an eines der Kernparadigmen von C++: die objektorientierte Programmierung (OOP).
Bei der OOP dreht sich alles um `classes`, also benutzerdefinierte Datentypen mit ihren eigenen zugehörigen Funktionen.
Wir beginnen mit den Grundlagen und behandeln weiter unten im Lehrplan fortgeschrittenere Themen.

## Member

Klassen können **Membervariablen** und **Memberfunktionen** haben.
Der Zugriff erfolgt über den **Memberzugriff**-Operator `.`.
Wie bei Variablen außerhalb von `classes` ist es ratsam, Membervariablen schon bei der Deklaration mit einem Wert zu initialisieren.
Dieser Wert ist dann der Standardwert für neu erzeugte Objekte dieser Klasse.

## Kapselung und Informationsverbergung

Klassen bieten die Möglichkeit, den Zugriff auf ihre Member einzuschränken.
Die beiden grundlegenden Fälle sind `private` und `public`.
Auf `private` Member kann von außerhalb der Klasse nicht zugegriffen werden.
`public` Member kannst du frei aufrufen.
Alle Member sind standardmäßig `private` und müssen explizit gekennzeichnet werden, damit sie außerhalb der Klasse verwendet werden können.

## Einfaches Beispiel

Die Definition einer neuen `class` siehst du im folgenden Beispiel.
Beachte das `;` nach der Definition.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

Auf alle Variablen kannst du innerhalb der Klasse zugreifen.
Schau dir `damage` in der `cast_spell`-Funktion an.
`private` Member kannst du von außerhalb der Klasse weder lesen noch ändern:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## Konstruktoren

Konstruktoren bieten die Möglichkeit, Membervariablen schon beim Erzeugen eines Objekts einen Wert zuzuweisen.
Sie haben denselben Namen wie die `class` und keinen Rückgabetyp.
Eine Klasse kann mehrere Konstruktoren haben.
Das ist nützlich, wenn du nicht immer alle Variablen setzen musst.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

Konstruktoren sind ein großes Thema mit vielen Feinheiten.
Wenn du keinen `constructor` für deine `class` explizit definierst, dann erledigt der Compiler diese Aufgabe für dich, aber auch nur dann.
Genau das ist im ersten Beispiel oben passiert.
Das Objekt _silverhand_ wird durch den Aufruf des Standardkonstruktors erzeugt, es wurden keine Argumente übergeben.
Alle Variablen werden auf den Wert gesetzt, der in der Definition der Klasse angegeben wurde.
Wenn du in dieser Definition keine Werte angegeben hättest, wären die Variablen möglicherweise nicht initialisiert, was unerwünschte Folgen haben kann.

## Structs

Structs stammen aus den ursprünglichen C-Wurzeln der Sprache und sind so alt wie C++ selbst.
Sie sind im Grunde dasselbe wie `classes`, mit einer wichtigen Ausnahme.
Standardmäßig ist in einer `class` alles `private`.
Bei Structs hingegen ist alles `public`, solange nichts anderes definiert wird.
Üblicherweise wird das Schlüsselwort `struct` oft für **reine Datenstrukturen** verwendet.
Das Schlüsselwort `class` bevorzugt man für Objekte, die bestimmte Eigenschaften sicherstellen müssen.
Eine solche Invariante könnte sein, dass `damage` in deiner `Wizzard` `class` nicht negativ werden kann.
Die Variable `damage` ist als private deklariert, und jede Funktion, die `damage` ändert, würde dafür sorgen, dass die Invariante erhalten bleibt.
