# Anleitung

In dieser Übung geht es um das Parsen von Logdateien.

Nach einer kürzlichen Sicherheitsüberprüfung wurdest du gebeten, die archivierten Logdateien der Organisation aufzuräumen.

Alle Strings, die an die Methoden übergeben werden, sind garantiert nicht null und haben keine führenden oder abschließenden Leerzeichen.

## 1. Fehlerhafte Logzeilen erkennen

Du brauchst einen ungefähren Überblick darüber, wie viele Logzeilen in deinem Archiv nicht den aktuellen Standards entsprechen. Du bist der Meinung, dass ein einfacher Test zeigt, ob eine Logzeile gültig ist. Um als gültig zu gelten, muss eine Zeile mit einem der folgenden Strings beginnen:

- [TRC]
- [DBG]
- [INF]
- [WRN]
- [ERR]
- [FTL]

Implementiere die Methode `LogParser.IsValidLine()`, die `false` zurückgibt, wenn ein String nicht gültig ist, andernfalls `true`.

```csharp
var lp = new LogParser();
lp.IsValidLine("[ERR] A good error here");
// => true
lp.IsValidLine("Any old [ERR] text");
// => false
lp.IsValidLine("[BOB] Any old text");
// => false
```

## 2. Die Logzeile aufteilen

Ein neues Team ist zur Organisation gestoßen, und du stellst fest, dass ihre Logdateien ein seltsames Trennzeichen für „Felder“ verwenden. Statt etwas Sinnvollem wie einem Doppelpunkt „:“ benutzen sie einen String wie „<--->“ oder „<=>“ (weil das hübscher ist). Genauer gesagt verwenden sie jeden String, dessen erstes Zeichen „<“ und dessen letztes Zeichen „>“ ist und der dazwischen eine beliebige Kombination der Zeichen „^“, „\*“, „=“ und „-“ enthält.

Implementiere die Methode `LogParser.SplitLogLine()`, die eine Zeile entgegennimmt und ein Array von Strings zurückgibt, von denen jeder ein Feld enthält.

```csharp
var lp = new LogParser();
lp.SplitLogLine("Section 1<===>Section 2<^-^>Section 3");
// => {"Section 1", "Section 2", "Section 3"}
```

## 3. Die Anzahl der Zeilen mit einem in Anführungszeichen gesetzten Passwort zählen

Das Team muss über Passwörter Bescheid wissen, die in zitiertem Text vorkommen, damit sie manuell untersucht werden können.

Implementiere die Methode `LogParser.CountQuotedPasswords()`, um einen Hinweis auf den wahrscheinlichen Umfang der manuellen Arbeit zu geben.

Finde Logzeilen, in denen der Literal-String „password“, der in beliebiger Groß- und Kleinschreibung vorkommen kann, von Anführungszeichen umgeben ist.
Du solltest berücksichtigen, dass zwischen den Anführungszeichen vor und nach „password“ zusätzlicher Inhalt stehen kann.

Die an die Routine übergebenen Zeilen können gültig sein oder nicht, wie in Aufgabe 1 definiert. Wir verarbeiten sie unabhängig davon auf die gleiche Weise.

```csharp
string lines =
    "[INF] passWord " + Environment.NewLine + // contains 'password' but not surrounded by quotation marks
    "\"passWord\"" + Environment.NewLine + // count this one
    "[INF] User saw error message \"Unexpected Error\" on page load." + Environment.NewLine + //does not contain 'password'
    "[INF] \"The secret password was added by the user\""; // count this one

var lp = new LogParser();
lp.CountQuotedPasswords(lines);
// => 2
```

## 4. Artefakte aus dem Log entfernen

Du hast festgestellt, dass eine vorgelagerte Verarbeitung der Logs den Text „end-of-line“, gefolgt von einer Zeilennummer (ohne dazwischenliegendes Leerzeichen), über die gesamten Logs verteilt hat.

Implementiere die Methode `LogParser.RemoveEndOfLineText()`, die einen String entgegennimmt, den Text „end-of-line“ entfernt und einen „sauberen“ String zurückgibt.

Zeilen, die keinen Text „end-of-line“ enthalten, sollten unverändert zurückgegeben werden.

Entferne einfach den String „end-of-line“. Versuche nicht, die Leerzeichen anzupassen.

```csharp
var lp = new LogParser();
lp.RemoveEndOfLineText("[INF] end-of-line23033 Network Failure end-of-line27");
// => "[INF]  Network Failure "
```

## 5. Zeilen mit extrem schwachen Passwörtern auflisten, damit die Schuldigen bestraft werden können

Bevor wir die Passwörter aus der Datei entfernen, müssen wir alle Fälle auflisten, in denen Passwörter mit dem Text „password“ beginnen.

Implementiere die Methode `LogParser.ListLinesWithPasswords()`, die das betreffende Passwort gefolgt von der vollständigen Zeile ausgibt.

Zeilen mit Passwörtern in Anführungszeichen wurden bereits entfernt, und du verarbeitest die Zeilen unabhängig davon, ob sie gültig sind (wie in Aufgabe 1).

Zeilen, die ein betreffendes Passwort enthalten, sollten mit dem Präfix „<password>: “ zurückgegeben werden.

Zeilen, die kein betreffendes Passwort enthalten, sollten mit dem Präfix „--------: “ zurückgegeben werden.

```csharp
var lp = new LogParser();
lp.ListLinesWithPasswords(new string[] {"my passwordsecret is great"});
// => "passwordsecret: my passwordsecret is great"
lp.ListLinesWithPasswords(new string[] {"my password secret"});
// => {"--------: my password secret"}

```
