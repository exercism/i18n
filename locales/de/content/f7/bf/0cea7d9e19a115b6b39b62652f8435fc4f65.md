# Einführung

## Benutzerdefinierte Typen

[Benutzerdefinierte Typen][custom-types] in Elm stellen eine feste Anzahl benannter Fälle dar. Jeder Wert entspricht genau einem der benannten Fälle.

Ein benutzerdefinierter Typ wird mit dem Schlüsselwort `type` definiert und benötigt nur sehr wenig Syntax. Sie sind eine der wichtigsten Techniken in der Elm-Programmierung und werden eingesetzt, damit die möglichen Werte im Code genau den gültigen Werten in der realen Welt entsprechen. Das lässt keinen Raum für ungültige Daten und macht [unmögliche Zustände im Code nicht darstellbar][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Jeder Fall eines benutzerdefinierten Typs kann optional zugeordnete Daten haben, und verschiedene Fälle können unterschiedliche Datentypen haben. Wenn keinem der Fälle Daten zugeordnet sind, ähnelt die diskriminierte Union dem, was andere Sprachen üblicherweise als _Aufzählung_ (oder _Enum_) bezeichnen.

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Einen Wert für einen bestimmten Fall erstellst du, indem du auf seinen Namen (`Spring`) verweist, wenn er im selben Modul definiert oder mit der Importsyntax `import SeasonModule exposing (Season(..))` importiert wurde, oder indem du auf seinen voll qualifizierten Namen (`Season.Spring`) verweist, wenn er mit der Importsyntax `import SeasonModule exposing (Season)` importiert wurde.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Benutzerdefinierte Typen haben, wie alles in Elm, _strukturelle Gleichheit_. Das bedeutet, dass zwei Werte für denselben Fall und mit denselben (optionalen) Daten äquivalent sind.

Die bevorzugte Art, mit benutzerdefinierten Typen zu arbeiten, ist [Musterabgleich][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
