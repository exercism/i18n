# Über

[Elixir](https://elixir-lang.org/) wurde erstmals 2012 veröffentlicht und baut auf den bereits robusten Eigenschaften von Erlang auf, ist aber für Anfänger leichter zugänglich, zu lesen, zu testen und zu schreiben.

José Valim, der Erfinder von Elixir, erklärt [in seinem Konferenzvortrag von 2012](https://vimeo.com/53221562), wie er die Sprache gebaut hat, damit Anwendungen:

  1. Verteilt
  2. Fehlertolerant
  3. Soft-Real-Time
  4. Hot-Code-Swapped sind (neuer Code lässt sich einspielen, ohne den Server anzuhalten)

Elixir wird tatsächlich zu [Bytecode](https://en.wikipedia.org/wiki/Bytecode) kompiliert und läuft dann auf der [BEAM Erlang Virtual Machine](https://codesync.global/media/robert-virding-co-creator-of-erlang-explains-the-beam/).

Für den Aufruf von Erlang fallen keine „Umstellungskosten“ an, du kannst Erlang-Code also direkt neben Elixir-Code laufen lassen.

Da Elixir eine funktionale Sprache ist, ist in Elixir alles ein Ausdruck.

Elixir bietet „First-Class-Dokumentation“: Kommentare können an eine Funktion angehängt werden, wodurch sie sich leichter abrufen lassen.

Auch reguläre Ausdrücke werden erstklassig behandelt, wodurch umständliches Escaping in Strings entfällt.

Die asynchrone Kommunikation in Elixir macht den Code leichtgewichtig und ermöglicht dennoch Nebenläufigkeit in großem Umfang.

Programmierer nutzen Elixir, um tausende Anfragen und Antworten *nebenläufig* auf einem einzigen Server-Knoten zu verarbeiten.

Es wird erfolgreich für Microservices eingesetzt, die eine Vielzahl von APIs schnell konsumieren und bedienen müssen.

Das Phoenix-Framework hilft dabei, Elixir-Anwendungen für das Web zu strukturieren.
