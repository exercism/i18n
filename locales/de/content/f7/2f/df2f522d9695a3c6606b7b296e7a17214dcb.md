# Einführung

## JSON

JSON (JavaScript Object Notation) ist ein für Menschen lesbares Daten- und Dateiformat, das häufig zum Austausch von Daten verwendet wird, insbesondere für Webanwendungen.
Daher überrascht es nicht, dass es in der Sprache Elm einen besonderen Platz einnimmt.

Elm stellt die Kernmodule `Json.Decode` und `Json.Encode` bereit, um JSON-Daten zu parsen und zu schreiben.
JSON-Decoder sind eine Möglichkeit, zu _deklarieren_, welcher Datentyp erwartet wird und auf welche Datenstruktur die Daten abgebildet werden sollen.

Importieren wir einige Aliase und Typen aus den Modulen:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Wenn du `Decode.decodeString : Decoder a -> String -> Result Error a` mit einem Decoder und einem JSON-String verwendest, ist das Ergebnis entweder erfolgreich, wenn der String den Decoder-Spezifikationen entspricht, oder es schlägt andernfalls fehl.
Wenn du den Decoder definierst, kannst du die rohen JSON-Daten nicht inspizieren, was aus imperativen Sprachen kommend ungewöhnlich wirken kann.

## Decoder für grundlegende Datentypen

JSON hat eine kleine Anzahl grundlegender Datentypen:

- String: mit doppelten Anführungszeichen kodiert `"hello world"`
- Boolescher Wert: entweder `true` oder `false`
- Zahl: zum Beispiel `34` oder `0.12`
- Null: das Fehlen von Daten `null`

Jeder davon ist einer `Decode`-Funktion zugeordnet:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Beachte, dass `Decode.null` dich entscheiden lässt, wie du ein `null` in deinem Programm modellierst, indem es einen beliebigen Wert als Argument verlangt (vielleicht `()`, `Nothing` oder etwas, das zu deinem Programm passt).

## Decoder kombinieren

JSON definiert außerdem zwei Datenstrukturen, um grundlegende Datentypen zu sammeln:

- Array: eine Sammlung anderer Datentypen `[0, null, "none", []]`
- Objekt: eine Sammlung von Schlüssel-Wert-Paaren `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` bietet auch Funktionen, um diese zu decodieren:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Diese Funktionen `Decode.list : Decoder a -> Decoder (List a)` und `Decode.dict : Decoder a -> Decoder (Dict String a)` erwarten jeweils einen Decoder als Argument, der jedes einzelne Element der Datenstruktur decodieren soll.
Wenn der Argument-Decoder ein Element eines Array- oder Objektwerts nicht decodieren kann, schlägt der gesamte Decoder fehl, was ein häufiges Muster ist.

Einfache Decoder zu komplexeren zu kombinieren, ist die Kernidee der Technik.
Anhand eines Beispiels stellen wir mehrere weitere Funktionen vor, mit denen du beliebig komplexe Decoder für echte Daten bauen kannst.

## GeoJSON

Um das Kombinieren grundlegender Decoder zum Parsen komplexer JSON-Daten zu üben, bauen wir Decoder zum Parsen (einer Teilmenge) von GeoJSON-Daten.
GeoJSON ist ein spezialisiertes JSON-basiertes Datenformat, mit dem geografische Objekte wie Orte, Pfade oder Regionen dargestellt werden, angegeben mit 2D- oder 3D-Koordinaten sowie weiteren Eigenschaften.

### Geometrie-Objekt

Ein GeoJSON-Geometrie-Objekt ist ein Objekt, das ein Feld `type` mit einem String-Wert enthält (es gibt 7 mögliche Typwerte) und ein Feld `coordinates` mit geografischen Koordinaten (gesammelt in einer Struktur, die vom Typ abhängt).
Zum Beispiel,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

oder

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Ein Geometrie-Objekt könnte in Elm mit dem folgenden Typ dargestellt werden

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Um den Wert eines bestimmten Feldes auszulesen, können wir `Decode.field : String -> Decoder a -> Decoder a` verwenden, wodurch der Wert eines bestimmten Schlüssels eines Objekts decodiert wird.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Um den von einem Decoder erfolgreich geparsten Wert umzuwandeln, können wir `Decode.map : (a -> value) -> Decoder a -> Decoder value` oder einen seiner Verwandten verwenden, von `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` bis `Decode.map8`.

In diesem Fall möchten wir anhand des Werts im Feld `type` entscheiden, welchen Koordinaten-Decoder wir verwenden. Das ist die perfekte Aufgabe für `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` und seine Freunde `Decode.succeed : a -> Decoder a` und `Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

An dieser Stelle sei angemerkt, dass wir `Decode.andThen` verwenden könnten, um die Koordinaten zu validieren (zu prüfen, ob die Koordinaten paarweise oder in Tripeln vorliegen und ob die Koordinatenwerte geografisch sinnvoll sind).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### Feature-Objekt

Ein GeoJSON-Feature-Objekt repräsentiert etwas räumlich Begrenztes: Es hat ein Feld `type` mit dem Wert `"Feature"`, ein Feld `geometry` mit einem Geometrie-Objekt oder `null`, ein Feld `properties` mit einem beliebigen JSON-Objekt oder `null` und ein optionales Feld `id` mit einem JSON-String- oder Zahlenwert.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

oder

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Kümmern wir uns zuerst um das Feld `id`.
Falls es existiert, muss es Strings oder Zahlen aufnehmen können. Wir könnten also entweder einen benutzerdefinierten Typ für den Wert einführen oder ihn immer als String speichern.

Um zwischen zwei möglichen Decodern zu wählen, können wir `Decode.oneOf : List (Decoder a) -> Decoder a` verwenden.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Um auszudrücken, dass das Feld optional ist, könnten wir dieselbe Technik verwenden

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Wir könnten aber stattdessen `Decode.maybe : Decoder a -> Decoder (Maybe a)` verwenden

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Beachte, dass `decodeMaybeFeatureId` (oder jeder mit `Decode.maybe` umhüllte Decoder) immer erfolgreich ist, da er immer auf `Ok Nothing` zurückfallen kann, obwohl ein Decoder, der ihn verwendet, trotzdem fehlschlagen kann

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

Als Nächstes konzentrieren wir uns auf das Feld `geometry`, das entweder ein Geometrie-Objekt oder `null` sein kann.
Wir könnten erneut `Decode.oneOf` verwenden, aber es gibt eine bessere Option: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` und `Decode.nullable` haben dieselbe Signatur, aber ihr Verhalten unterscheidet sich, da das Ergebnis `OK Nothing` eines `Decode.nullable` nur vom spezifischen JSON-Wert `null` stammt.

Schließlich kann das Feld `properties` ein beliebiges JSON-Objekt oder `null` enthalten, wofür `Decode.value : Decoder Value` zuständig ist.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Beachte, dass `Value` ein opaker Typ ist, was bedeutet, dass du seinen Inhalt nicht einfach auslesen kannst.
Um ihn zu verwenden, kannst du entweder einen Decoder dafür schreiben und ihn mit `Decode.decodeValue : Decoder a -> Value -> Result Error a` ausführen oder ihn direkt über einen Port an JavaScript senden.

Wir sind bereit, Feature-Objekte zu parsen:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## JSON-Encoder

Mit Encodern kannst du gültiges JSON aus Elm-Werten schreiben, indem du die Funktion `Encode.encode : Int -> Value -> String` verwendest.
Das erste Argument gibt die Anzahl der Einrückungsstufen im Endergebnis an, das zweite Argument ist der zu schreibende JSON-Wert.

Ein `Value` kann entweder von `Decode.value` stammen oder mit einem der Encoder erzeugt werden:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

sowie mit `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Definieren wir Encoder für die zuvor definierten GeoJSON-Decoder

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

Im Allgemeinen ist ein guter Test für deine Decoder-Encoder-Paare, zu prüfen, dass `elmValue |> encoder |> decoder == elmValue` gilt.
