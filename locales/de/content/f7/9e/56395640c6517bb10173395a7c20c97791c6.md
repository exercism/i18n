# Workflows

GitHub Actions verwendet das Konzept der _Workflows_. Das sind Skripte, die automatisch ausgeführt werden, sobald ein bestimmtes Ereignis eintritt (z. B. wenn du einen Commit pushst).

Jeder Workflow von GitHub Actions ist in einer `.yml`-Datei im Verzeichnis `.github/workflows` definiert.
Informationen zu Workflows findest du in den folgenden Dokumenten:

- [Workflow-Syntax](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions)
- [Auswählen, wann dein Workflow ausgeführt wird](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow)
- [Auswählen, wo dein Workflow ausgeführt wird](https://docs.github.com/en/actions/writing-workflows/choosing-where-your-workflow-runs)
- [Auswählen, was dein Workflow tut](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does)
- [Workflows schreiben](https://docs.github.com/en/actions/writing-workflows)
- [Best Practices](/docs/building/github/gha-best-practices)

## Gemeinsam genutzte Workflows

Einige Workflows werden von mehreren Repositories gemeinsam genutzt.

```exercism/caution
Die gemeinsam genutzten Workflows werden automatisch synchronisiert (aus dem [org-wide-files-Repo](https://github.com/exercism/org-wide-files/)).
Du solltest ihre Inhalte deshalb nicht manuell ändern.
```

### Allgemeine Workflows

- [Labels synchronisieren](/docs/building/tracks/ci/workflows/sync-labels): synchronisiert die Labels des Repositorys aus einer Datei

### Track-spezifische Workflows

- [configlet](/docs/building/tracks/ci/workflows/configlet): prüft, ob die (Konfigurations-)Dateien des Tracks korrekt strukturiert sind, sowohl syntaktisch als auch semantisch
- [Keine wichtigen Dateien geändert](/docs/building/tracks/ci/workflows/no-important-files-changed): kommentiert Pull Requests, die ein erneutes Testen bestehender Lösungen auslösen würden
- [Test](/docs/building/tracks/new/setup-continuous-integration#h-test-workflow): überprüft die Übungen des Tracks

### Tool-spezifische Workflows

- [Deployment](/docs/building/tracks/ci/workflows/deploy): rollt das Docker-Image für das Tooling des Tracks auf Docker Hub und ECR aus

### Optionale Workflows

Es gibt außerdem einige Workflows, für die sich Tracks entscheiden können:

- [Community-Beiträge pausieren](/docs/building/tracks/ci/workflows/pause-community-contributions): kommentiert neue Issues und PRs automatisch, die von Nutzern erstellt wurden, die nicht Mitglied der GitHub-Organisation von Exercism sind
