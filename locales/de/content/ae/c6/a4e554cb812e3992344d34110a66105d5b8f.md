# Einführung in Schleifen

Bash kennt zwei Formen von Schleifen:

* Wiederhole einige Befehle _für jedes Element in einer Liste von Elementen_,
* Wiederhole einige Befehle, _solange eine Bedingung wahr (oder falsch) ist_.

## for-Schleifen

Um über eine Liste von Elementen zu iterieren, verwenden wir die `for`-Schleife.

```bash
for varname in words; do COMMANDS; done
```

`words` wird durch Wortaufteilung und Dateinamen-Erweiterung expandiert (das haben wir im [Quoting-Konzept][quoting] kennengelernt).
Jedes Wort wird der Reihe nach der Variable `varname` zugewiesen, und dann werden die Befehle ausgeführt.

Hier sind ein paar Beispiele, die zeigen, wann die `for`-Schleife nützlich sein kann:

* Einige Befehle auf eine Gruppe von Dateien anwenden.

    ```bash
    # source all the bash library files in the current directory
    for file in ./*.bash; do
        source "$file"
    done
    ```

* Für jeden Parameter eines Skripts oder einer Funktion einen Befehl ausführen.

    ```bash
    for arg in "$@"; do
        echo "argument: ${arg}"
    done
    ```

* Für jedes durch Leerzeichen getrennte Wort in der Ausgabe eines Befehls einen Befehl ausführen.

    ```bash
    for i in $(seq 10); do
        echo "${i} squared is $((i * i))"
    done
    ```

    Zu diesem Stil sehen wir später noch einige Warnungen.

### Arithmetische for-Schleife

Bash hat tatsächlich eine arithmetische Schleife.
Sie kommt dir aus anderen Programmiersprachen bekannt vor.

```bash
for ((INITIALIZATION; CONDITION; INCREMENT)); do COMMANDS; done
```

Die doppelten runden Klammern in Bash stehen für einen arithmetischen Kontext (mehr über Arithmetik in Bash sehen wir in einem späteren Konzept).
Das obige Beispiel mit `seq` kannst du auch so schreiben:

```bash
for ((i = 1; i <= 10; i++)); do
    echo "${i} squared is $((i * i))"
done
```

### Wann du `for` nicht verwenden solltest

[Lies keine Zeilen mit `for`][bashfaq1].

Das ist ein Anti-Pattern, das du oft siehst: über die Ausgabe von `cat` iterieren.

```bash
for line in $(cat some.file); do 
    do_something_with "$line"
done
```

Das ist aus zwei Gründen falsch.

1. Die Befehlssubstitution steht nicht in Anführungszeichen und unterliegt daher der Wortaufteilung.
   Die Wortaufteilung trennt standardmäßig an _Leerzeichen_, nicht nur an Zeilenumbrüchen.
   Diese `for`-Schleife iteriert über die **Wörter** in der Datei, nicht über die Zeilen.
2. Die Befehlssubstitution steht nicht in Anführungszeichen und unterliegt daher der Dateinamen-Erweiterung.
   Jedes Wort in der Datei wird als Glob-Muster abgeglichen.

Wie wir im [Quoting-Konzept][quoting] gelernt haben, kannst du die Wortaufteilung mit der Variable `IFS` steuern und die Dateinamen-Erweiterung abschalten.
Aber das ist meist eine fragile Lösung.
`for` ist die falsche Methode, um über die Zeilen einer Datei zu iterieren.
Die idiomatische Art, eine Datei zu lesen, ist eine `while`-Schleife.

## while-Schleifen

Verwende `while`, um eine Befehlsfolge zu wiederholen, _solange_ eine Bedingung wahr ist.

```bash
while CONDITION_COMMANDS; do COMMANDS; done
```

Wie bei `if` (wie wir im [Konzept Bedingungen][conditionals] gelernt haben) gibt es keine spezielle Syntax für CONDITION_COMMANDS.
Der Exit-Status der Befehlsliste entscheidet über „wahr“ oder „falsch“.

## Schleifen steuern

Der Befehl `break` springt aus der Schleife heraus.
Die Ausführung geht mit dem Befehl weiter, der auf das `done` der Schleife folgt.

Der Befehl `continue` springt zur nächsten Iteration der Schleife.

## Die Zeilen einer Datei lesen

Wie erwähnt ist eine `while`-Schleife die idiomatische Art, eine Datei zu lesen.

```bash
while IFS= read -r line; do
    do_something_with "$line"
done < some.file
```

* Der Inhalt der Datei wird der Schleife mit der Umleitung `<` als Eingabe übergeben.
* Der Befehl `read` gibt „wahr“ zurück, wenn er eine vollständige Zeile aus seiner Eingabe lesen kann.
  Wenn die Eingabe aufgebraucht ist oder die letzte Zeile ohne abschließenden Zeilenumbruch endet, gibt `read` „falsch“ zurück.
  * Die _wirklich_ idiomatische Art, die Zeilen einer Datei zu lesen, auch wenn die letzte Zeile nicht mit einem Zeilenumbruch endet, ist

    ```bash
    while IFS= read -r line || [[ -n "$line" ]]; do ...
    ```

* Die Option `-r` weist `read` an, Backslash-Sequenzen nicht zu ersetzen: Ein Backslash ist einfach ein normales Zeichen.
* `IFS=` weist IFS nur für die Dauer des `read`-Befehls die leere Zeichenkette zu.
  Das schaltet die Wortaufteilung vorübergehend ab, sodass führende oder abschließende Leerzeichen in der eingelesenen Zeile erhalten bleiben.

## until

Das Konstrukt `until` wiederholt eine Befehlsfolge, solange eine Bedingung **falsch** ist.
Die Schleife wiederholt sich, _bis_ die Bedingung wahr wird.

```bash
until CONDITION_COMMANDS; do COMMANDS; done
```

`until` wird selten verwendet.
Häufiger verwendest du eine „while not“-Schleife.

```bash
while ! CONDITION_COMANDS; do ...
```

## Endlosschleifen

Manchmal möchtest du endlos wiederholen.
Hier sind zwei Möglichkeiten.

1. eine `while`-Schleife mit einer Bedingung, die immer einen erfolgreichen Exit-Status hat

    ```bash
    while true; do ...
    ```

2.  eine arithmetische `for`-Schleife mit leeren Ausdrücken

    ```bash
    for ((;;)); do ...
    ```

## Do-while

Ein explizites do-while-Konstrukt gibt es nicht, aber du kannst denselben Effekt erzielen:

```bash
while true; do
    COMMANDS

    if END_CONDITION; then
        break
    fi
done
```
