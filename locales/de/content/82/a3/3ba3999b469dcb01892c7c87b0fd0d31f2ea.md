# Unveränderliche Klassen

```sather
immutable class BEARING is
   readonly attr degrees : INT;
   create(d : INT) : SAME is
      b : SAME;
      return b.degrees(d);
   end;
end;
```

## Was sich ändert

| | gewöhnliche Klasse | unveränderliche Klasse |
| --- | --- | --- |
| Zuweisung | teilt das Objekt | kopiert den Wert |
| kann void sein | ja | nein |
| `attr`-Schreibzugriff | `x.a := v` | `x := x.a(v)` |
| `new` | ja | nein; `x : SAME` existiert bereits |

Ein unveränderliches Objekt kann nicht void sein, deshalb ist `void(b)` immer falsch, und keine Routine darauf kann fehlschlagen, weil das Objekt fehlt. Das beseitigt eine ganze Klasse von Fehlern, um den Preis, dass man nie sagen kann „noch kein Bearing“.

## Wo der Wert liegt

Der Wert wird dort gespeichert, wo die Variable ist (in einem anderen Objekt oder auf dem Stack), statt über eine Referenz erreicht zu werden. Ein `ARRAY{BEARING}` enthält also die Bearings selbst und keine Zeiger darauf. Das braucht weniger Speicher und lässt sich schneller durchlaufen.

Der Preis ist das Kopieren: Ein großes unveränderliches Objekt wird bei jeder Übergabe kopiert. Deshalb hält man sie am besten klein.

## Die Attributroutinen

`readonly attr degrees : INT` liefert zwei Routinen:

```sather
   b.degrees          -- read: INT
   b.degrees(90)      -- answer a new BEARING with degrees changed
```

Die zweite gibt es auch unter `readonly`, weil sie nichts ändert: Sie baut einen neuen Wert auf. Unter einem einfachen `attr` ist sie öffentlich, unter `private attr` nicht.

## is_eq und str

Keine von beiden wird mitgeliefert. Schreib `is_eq` für `=`, und `str`, damit sich das Objekt ausgeben und an Strings anhängen lässt:

```sather
   is_eq(other : SAME) : BOOL is return degrees = other.degrees; end;
   str : STR is return degrees.str + " degrees"; end;
```

Wenn du `str` schreibst, entspricht die Klasse `$STR`, und genau das bringt `+` und `#OUT` dazu, sie zu akzeptieren.

## Die eingebauten

`INT`, `BOOL`, `CHAR`, `FLTD` und `TUP` sind alle unveränderliche Klassen. Nichts an ihnen ist besonders: Sie sind in der Bibliothek genauso in Sather geschrieben und verhalten sich aus den oben genannten Gründen so, wie sie es tun.
