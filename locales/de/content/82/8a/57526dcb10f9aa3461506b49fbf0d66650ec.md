# Überblick

Handgeschriebener Assembler ist voller Wiederholungen.
Dieselbe kurze Folge von Anweisungen taucht immer wieder auf, kaum variiert, und es gibt nur wenige Abstraktionen, die den Boilerplate-Aufwand verringern.
Darüber hinaus verlangt das Programmieren in Assembler, Werte zu verwalten, deren Bedeutung nicht offensichtlich ist.
Es gibt keine benannten Parameter, und die meisten Details der darunterliegenden Maschinerie muss der Programmierer von Hand regeln.

NASM, der Assembler, den dieser Track verwendet, bietet einige Werkzeuge, die dem Programmierer bei beiden Problemen helfen können.
Diese Werkzeuge laufen zur _Assemblierzeit_, bevor eine Anweisung den Prozessor erreicht.
Sie weisen den Assembler an, wie er den Quelltext umschreiben soll, noch bevor dieser in Maschinencode übersetzt wird.

Das wichtigste dieser Werkzeuge sind **Makros**, die man sich als Rezept für den Assembler vorstellen kann.
Sie werden an der Stelle, an der sie verwendet werden, entfaltet, als wäre der Code dort von Hand geschrieben worden.

[Makros][macro] können eine Reihe wörtlicher Tokens als Parameter annehmen, wodurch sie in verschiedenen Kontexten wiederverwendbar sind.
Sie sind jedoch keine Funktionen: Es gibt kein `call`, kein `ret` und keine Kontrollübergabe an eine andere Stelle im Code.

## Einzeilige Makros

Die einfachste Definition gibt einem Wert oder einem kurzen Ausdruck mit `%define` einen Namen:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Jedes spätere Vorkommen von `WIDTH` wird vor der Assemblierung durch `8` ersetzt.
Die Ersetzung ist textuell, der Name wird also überall dort eingesetzt, wo er auftaucht, sei es in einem Operanden oder innerhalb einer anderen Definition.

~~~~exercism/note
Für numerische _Konstanten_ verwende lieber `equ` statt `%define`.

Ein einzeiliges Makro, das mit `%define` deklariert wird, wird erst bei der Verwendung entfaltet und kann neu zugewiesen oder aufgehoben werden.
Eine `equ`-Konstante hingegen wird an der Stelle der Definition ausgewertet und nie verändert.
~~~~

Ein `%define` kann auch _benannte_ Parameter annehmen und verhält sich dann wie eine kleine Inline-Funktion:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Setze sowohl den gesamten Rumpf als auch jeden Parameter in runde Klammern.
Mit `%define square(x) x*x` entfaltet der Aufruf `square(1+1)` zu `1+1*1+1`, was `3` ergibt.
Als `%define square(x) ((x)*(x))` geschrieben, entfaltet derselbe Aufruf zu `((1+1)*(1+1))`, was `4` ergibt.
~~~~

Namen, die mit `%define` definiert werden, beachten Groß- und Kleinschreibung.
Die Variante `%idefine` macht den Namen unabhängig von Groß- und Kleinschreibung, falls das gewünscht ist.

Einzeilige Makros sind nützlich, um verschiedenen Teilen des Codes eine Bedeutung zu geben.
Mit Bedacht eingesetzt verbessern sie die Lesbarkeit und verringern die Gefahr von Tippfehlern.
Ein Register zum Beispiel, das innerhalb einer Funktion einen festen Zweck hat, lässt sich nach seinem Zweck benennen:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Mehrzeilige Makros

Eine ganze Codefolge mit beliebig vielen Zeilen wird mit `%macro` erfasst und mit `%endmacro` abgeschlossen.
Eine Zahl nach dem Namen gibt an, wie viele Argumente das Makro annimmt; das können auch null sein.
Wenn Argumente übergeben werden, trennt man sie durch ein Komma (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Argumente in mehrzeiligen Makros haben keine Namen.
Sie werden als `%1`, `%2` und so weiter bezeichnet, und zwar in der Reihenfolge, in der sie übergeben werden:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Beachte, dass die Argumente gültige Syntax für die Operationen sein müssen, die im Rumpf des Makros ausgeführt werden.
Hier lassen sich `mult_two eax, ecx` und `mult_two r8, r9` beide assemblieren, `mult_two eax, cl` hingegen nicht, da `imul eax, cl` nicht definiert ist.

Makros können auch eine beliebige Anzahl von Argumenten annehmen.
Das geschieht mit der Notation `n-*`, wobei `n` die minimale Anzahl von Argumenten ist:

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

In einem mehrzeiligen Makro bezeichnet `%0` die _Anzahl_ der Argumente im Makro.
Das ist besonders nützlich in Makros, die eine beliebige Anzahl von Argumenten annehmen können.

### Labels innerhalb eines Makros

Ein Makro, das ein gewöhnliches Label definiert, geht kaputt, sobald es zweimal verwendet wird, denn dann würde auch das Label zweimal definiert.
Um Labels in einem Makro zu verwenden, das mehr als einmal aufgerufen werden kann, muss man einem solchen Label `%%` voranstellen.
Das weist den Assembler an, diesem Label bei jeder Entfaltung einen anderen, eindeutigen Namen zu geben:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Wiederholen zur Assemblierzeit

Mit [`times`][times] lässt sich ein Block Code wiederholen, der nur aus einer Zeile besteht.
Das ist besonders nützlich, wenn man wiederholte Werte im Speicher deklariert:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Für das Wiederholen mehrzeiligen Codes können wir stattdessen `%rep` verwenden:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Beachte, dass die Anzahl der Wiederholungen direkt nach `%rep` angegeben wird und dass ein `%endrep` den wiederholten Block abschließt.

Häufig verwendet man einen Zähler zur Assemblierzeit in einem `%rep`-Block, ganz ähnlich wie eine Schleife zur Laufzeit einen Zähler verwendet.
Während eine ganzzahlige Konstante zur Assemblierzeit mit `equ` deklariert werden kann, wie wir bereits gesehen haben, verwenden wir für ganzzahlige _Variablen_ zur Assemblierzeit stattdessen `%assign`.
Anders als `%define` wird `%assign` sofort zu einer Zahl ausgewertet und kann neu zugewiesen werden:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Nachdem der Präprozessor gelaufen ist, ist die Schleife verschwunden, und es bleiben vier `add`-Anweisungen übrig, in die die Immediate-Werte `0`, `1`, `2` und `3` fest eingebaut sind.
Das ist Schleifenabrollung, wie sie der Assembler vornimmt: kein Zählerregister und kein Sprung, nur geradliniger Code.

Ein weiterer häufiger Einsatz von `%rep` ist der Umgang mit Argumenten in einem Makro, das beliebig viele davon annehmen kann.
In diesem Fall wird `%rep` üblicherweise mit `%rotate` kombiniert, das die Argumente in einem Makro rotiert, sodass das zweite Argument zum ersten wird.
Wiederholte Anwendungen von `%rotate` machen das dritte, dann das vierte und so weiter zum ersten Argument, sodass jedes Argument der Reihe nach behandelt werden kann:

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## Bedingte Assemblierung

Dem [Präprozessor][preprocessor] stehen verschiedene Bedingungen zur Verfügung.
Sie wählen zwischen mehreren verschiedenen Pfaden und entfalten ihren Rumpf an Ort und Stelle, aber nur, wenn ihre Bedingung zutrifft.

`%if` ... `%elif` ... `%else` ... `%endif` wählen einen Zweig anhand eines numerischen Tests aus:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef` und `%ifndef` sind ähnlich, prüfen aber, ob ein Name definiert wurde.
Sie können zum Beispiel sicherstellen, dass der Inhalt einer Datei nur einmal eingebunden wird, selbst wenn die Datei von mehr als einer Quelle hereingezogen wird:

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

Vielleicht ist dir aufgefallen, dass am Ende jeder `.asm`-Datei in diesem Track dieses Stück Code steht:

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn` vergleicht zwei Textstücke auf exakte Übereinstimmung.
Das eingebaute `__OUTPUT_FORMAT__` entfaltet sich zum aktuellen Ausgabeformat, dieser Code prüft also, ob das Ausgabeformat `elf64` ist, das Format, das Linux-Systeme verwenden.
Wenn ja, wird eine Notiz an die Objektdatei angehängt, die die Berechtigungen deklariert, die der Stack haben soll, eine übliche Sicherheitsmaßnahme.
Wenn nicht, ändert sich nichts.

## Strukturen

Um an ein Feld eines Datensatzes im Speicher zu gelangen, addiert man den Byte-Offset des Feldes zu einer Basisadresse.
Diese Offsets als rohe Zahlen zu schreiben ist fehleranfällig und verschleiert ihre Bedeutung.
[`struc`][struc] und `endstruc` benennen stattdessen ein Layout und machen jedes Feld zu einem symbolischen Offset, der zur Assemblierzeit berechnet wird.

Innerhalb des Blocks reservieren die Reservierungsdirektiven `resb`, `resw`, `resd` und `resq` ein oder mehrere Bytes, Wörter, Doppelwörter oder Vierfachwörter.
Wenn jedes Feld mit einem führenden `.` beginnt, bleibt sein Name auf die Struktur beschränkt:

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

Jeder Feldname steht nun für seinen Offset, `thread.color` ist also `0`, `thread.tension` ist `4` und `thread.name` ist `12`.
NASM definiert außerdem `<struc>_size` als Gesamtgröße, wobei `<struc>` der Name des `struc` ist.
Hier wäre `thread_size` zum Beispiel `4 + 8 + 16 = 28`.

Auf ein Feld greift man zu, indem man seinen Offset zu einem Basisregister addiert, und `thread_size` ist der Schritt von einem Datensatz zum nächsten:

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

Ein `struc` beschreibt nur eine Form, es reserviert nicht selbst Speicher.
Um eine initialisierte Instanz zu erzeugen, kannst du `istruc ... iend` nach einem beliebigen Label verwenden.
Innerhalb einer Instanz platziert `at` einen Wert an einem benannten Feld:

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

Beachte, dass `thread.name` mit `"warp", 0` initialisiert wird, was nur 5 Bytes belegt.
Die anderen 11 Bytes, die im `struc` dafür reserviert sind, werden von `iend` automatisch mit Nullen gefüllt, das die Instanz mit `0` auf `thread_size` auffüllt.

Ein `struc` ist nur syntaktischer Zucker für Speicher, den wir auch von Hand deklarieren können.
Der obige Code ist zum Beispiel äquivalent zu folgendem, wobei `times 11 db 0` dafür sorgt, dass am Ende 16 Bytes reserviert werden:

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## Aufteilen auf Dateien

Makros werden oft in einer eigenen Datei gehalten und mit `%include` in jede Quelle eingebunden, die sie braucht:

```x86asm
%include "patterns.mac"
```

Die genannte Datei wird an dieser Stelle vor der Assemblierung wortwörtlich eingefügt, genau so, als wäre ihr Inhalt an Ort und Stelle getippt worden.
So bleiben die Definitionen an einem Ort und mehrere Quelldateien können sie gemeinsam nutzen.

Wenn die Makrodatei auch eigenständig assembliert werden kann, sollte sie die Dateiendung `.asm` haben.
Beachte, dass Makros keine Bindung haben.
Selbst wenn die Makrodatei assembliert wird, sind ihre Makros nur für eine andere Datei sichtbar, die sie mit `%include` einbindet.

Andernfalls darf eine Datei, die nur per `%include` eingebunden wird, jede Dateiendung haben.
Die Verwendung von entweder `.asm` oder `.mac` ist eine übliche Konvention.
