# Über

[Comprehensions][for] bieten eine Möglichkeit, _Enumerables_ einfach und deklarativ zu transformieren. Sie sind _syntaktischer Zucker_, um in Elixir durch Enumerables zu iterieren.

[//]: # (elixir-formatter-disable-next-block)

```elixir
for s <- ["a", "b", "hello", "c"], # 1. generator
  String.length(s) == 1,           # 2. filter
  into: "",                        # 3. collectable
  do: String.upcase(s)

# => "ABC"
```

Eine Comprehension besteht aus drei Teilen:

1. _Generatoren_:
   - Werte, die aus Strukturen aufgezählt werden, die das [_Enumerable_][enumerable]-Protokoll implementieren.
   - Pattern-Matching-Ausdrücke, um die aufgezählten Werte zu destrukturieren.
2. _Filter_: Boolesche Bedingungen, mit denen ausgewählt wird, welche aufgezählten Werte beim Erzeugen der neuen Werte verwendet werden.
3. _Collectables_: Eine Struktur, die das [_Collectable_][collectable]-Protokoll implementiert und mit der die neuen Werte gesammelt werden.

Es gibt ein- und mehrzeilige Comprehensions. Wenn mehr als ein Generator verwendet wird, wird ein [kartesisches Produkt][cartesian-product] der erzeugten Werte aufgezählt. Das bedeutet, dass jeder vom ersten Generator erzeugte Wert einmal mit jedem vom zweiten Generator erzeugten Wert gepaart wird.

```elixir
for n <- [0, 1, 2, 3], do: n + 1
# => [1, 2, 3, 4]

for x <- [0, 1],
    y <- [0, 1] do
  {x, y}
end

# => [{0, 0}, {0, 1}, {1, 0}, {1, 1}]
```

Der Wert im do-Block wird **für jeden Wert, der aus dem _Enumerable_ erzeugt wird**, in das _Collectable_ eingefügt.

```elixir
for _ <- [1, 2, 3], do: :a
# => [:a, :a, :a]
```

Pattern Matching kann in der Comprehension vorkommen, entweder auf der linken Seite von `<-` oder in einer eigenen Zeile.

```elixir
for {atom, str} <- [a: "string"], do: str
# => ["string"]

for pair <- [a: "string"],
    {atom, str} = pair do
  str
end

# => ["string"]
```
