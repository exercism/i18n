# Einführung

## Zeichen

Eine **Zeichenkodierung** ist eine bestimmte Konvention, mit der Elemente eines Textes in einer natürlichen Sprache als Bytefolge dargestellt werden.
Ein „Element eines Textes“ kann hier jede Einheit sein, die in einer natürlichen Sprache Bedeutung hat, zum Beispiel Buchstaben, Leerzeichen, Satzzeichen, Emojis, Ideogramme usw.

NASM (The Netwide Assembler, der in diesem Track verwendete Assembler) unterstützt die Definition von Daten mit **ASCII**.

Zeichenkonstanten in NASM dürfen bis zu 8 Byte lang sein und können mit einfachen Anführungszeichen (`'`), doppelten Anführungszeichen (`"`) oder Backticks (`` ` ``) definiert werden:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Sonderzeichen müssen in Backticks definiert und mit `\` maskiert werden:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Beachte, dass x86-64 keine eingebaute Unterstützung für eine Zeichenkodierung als eigenen Typ bietet.
Daten sind in Assembler eine Bytefolge, und wie diese Bytes interpretiert werden, ob als Zeichen, als Zahl oder als etwas anderes, bleibt dem Programmierer überlassen.

So ist das ASCII-Zeichen '0' ein einzelnes Byte mit dem Wert 48.
Eine 48 in ein Byte zu schreiben ist also genau dasselbe, wie das ASCII-Zeichen '0' zu speichern:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Aus demselben Grund bearbeitet man Zeichen, indem man die Werte in diesen Bytes direkt umformt:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Strings

Ein **String** ist eine Folge von Zeichen.
In Assembler wird er üblicherweise als Array umgesetzt.

In NASM kannst du einen String genauso deklarieren wie jedes andere Array:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Ein Unterschied zwischen Strings und anderen Arrays ist, dass NASM Strings auch ohne ein Komma (`,`) zwischen den Werten deklarieren kann.
Werte dürfen auch mit Kommas gemischt werden:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Beachte, dass Zeichen, wie bereits erwähnt, einfach Bytes sind (oder eine Bytefolge bei Unicode-Kodierung):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Da jedes ASCII-Zeichen ein einzelnes Byte belegt, ist jedes weitere Byte in einer größeren Größe `0`.
Wenn du `'a'` zum Beispiel als qword (8 Byte) deklarierst, ist das erste Byte `'a'` (`97`) und die übrigen sieben Bytes sind alle `0`.

Aus diesem Grund sind alle folgenden Varianten äquivalent:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
In Assembler werden Strings nicht automatisch durch ein ASCII-NUL-Zeichen (Wert `0`) beendet.

Bei der Anbindung an höhere Sprachen wie C liegt es in der Verantwortung des Programmierers, dafür zu sorgen, dass am Ende eines Strings das richtige Abschlusszeichen angehängt wird, falls eines nötig ist.
~~~~

## String-Befehle

Da Strings Arrays sind, kannst du genauso mit ihnen arbeiten wie mit jedem anderen Array, indem du den Speicher explizit dereferenzierst:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Darüber hinaus gibt es einige Befehle, um Werte in Bytefolgen im Speicher zu laden, zu verschieben und zu speichern.
Obwohl sie _String-Befehle_ heißen, kannst du sie mit jeder Bytefolge im Speicher verwenden, also mit jedem Array.

Die drei wichtigsten String-Befehle sind `lods`, `stos` und `movs`:

| Befehl | was er macht                                                                                                      |
| ------ | ----------------------------------------------------------------------------------------------------------------- |
| `lods` | lädt einen Wert von einer Speicherstelle, auf die `rsi` zeigt, nach `rax`                                         |
| `stos` | schreibt einen Wert aus `rax` an eine Speicherstelle, auf die `rdi` zeigt                                         |
| `movs` | kopiert einen Wert von einer Speicherstelle, auf die `rsi` zeigt, und schreibt ihn an eine Speicherstelle, auf die `rdi` zeigt |

Beachte, dass diese Befehle _keine_ expliziten Operanden haben.
Ihre Operanden sind implizit.

Als Faustregel gilt:

1. Wenn ihr Quelloperand eine Speicherstelle ist, sollte ihre Adresse in `rsi` stehen (`s` steht für source).
2. Wenn ihr Zieloperand eine Speicherstelle ist, sollte ihre Adresse stattdessen in `rdi` stehen (`d` steht für destination).
3. Wenn einer der Operanden keine Speicherstelle ist, ist er das Register `rax`.

Beachte, dass diese Befehle Speicheradressen je nach der jeweiligen Operation automatisch dereferenzieren.

Alle von ihnen können mit verschiedenen Größen arbeiten.
Um diese Größe anzugeben, wird ein Suffix angehängt:

| Suffix | Bedeutung  | Größe   |
| :----: | ---------- | :------ |
|  `b`   | Byte       | 1 Byte  |
|  `w`   | Wort       | 2 Byte  |
|  `d`   | Doppelwort | 4 Byte  |
|  `q`   | Quadword   | 8 Byte  |

Zum Beispiel:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

Außerdem aktualisieren sie jede verwendete Adresse um die Größe der Operation.
Diese Aktualisierung richtet sich nach dem Wert des **Richtungsflag (DF)**:

- Wenn `DF` gelöscht ist, werden die Adressen um die Größe der Operation _erhöht_.
- Wenn `DF` gesetzt ist, werden die Adressen stattdessen um denselben Betrag _verringert_.

Die System V ABI legt fest, dass das Richtungsflag beim Eintritt in eine Funktion gelöscht sein muss.
_Das Standardverhalten ist also, dass der Speicher in aufsteigender Adressreihenfolge gelesen und geschrieben wird_.

Mit dem Befehl `cld` kannst du das Richtungsflag löschen, mit dem Befehl `std` setzen:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Der Aufrufer erwartet laut System V ABI, dass `DF` nach der Rückkehr einer aufgerufenen Funktion gelöscht ist.
Wenn du `DF` setzt, achte darauf, es vor `ret` wieder zu löschen.
~~~~

### Rep

Abgesehen davon greift der **rep**-Befehl nicht direkt auf den Speicher zu.
Stattdessen kannst du ihn als Präfix vor die anderen genannten Befehle setzen, wodurch diese Befehle _wiederholt_ werden.

Mit dem Präfix `rep` werden String-Befehle so oft wiederholt, wie der Wert in `rcx` angibt.
Bei jedem Durchlauf wird der Wert in `rcx` um `1` verringert.
Beachte, dass der Wert in `rcx` festgelegt sein muss, bevor der Befehl verwendet wird:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
Auf modernen CPUs sind `rep movs` und `rep stos` meist schnelle Optionen, wenn du Daten in großen Blöcken verschiebst.
Andere String-Befehle und sogar `movs` und `stos` ohne `rep` sind dagegen meist langsamer als eine einfache Schleife.

Eine ausführlichere Betrachtung dieses Themas findest du in [Kapitel 16.9, „String instructions“, dieses Referenzbuchs][agner-optimization-guide].
