# Überblick

## Optionals

Swift verwendet [_Optionals_][optionals], damit Programmierer das mögliche Fehlen eines Werts darstellen können.
Ein Optional ist ein Typ, der entweder einen Wert enthalten oder [`nil`][nil] sein kann, was das Fehlen eines Werts darstellt.
Die Verwendung eines Optionals erfordert, dass ein Programm prüft, ob tatsächlich ein Wert vorhanden ist, bevor es ihn nach dem Auspacken verwendet.

Jeder Typ lässt sich zu einem Optional machen, indem du ein `?` an das Ende des Typnamens anhängst.
Eine optionale Ganzzahl hat also den Typ `Int?` und ein optionaler String den Typ `String?`.
Konstanten oder Variablen eines optionalen Typs zu definieren und ihnen Werte zuzuweisen, funktioniert genauso wie bei Werten nicht-optionaler Typen.

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

Du kannst einer Variable eines optionalen Typs das Fehlen eines Werts zuweisen, indem du ihr den speziellen Wert `nil` zuweist.
`nil` kann bei allen optionalen Typen verwendet werden, aber `nil`-Werte, die zwei verschiedenen optionalen Typen zugewiesen werden, haben nicht denselben Typ und lassen sich weder austauschen noch vergleichen.

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

Beachte außerdem: `nil` lässt sich zwar jedem optionalen Typ zuweisen, aber keinem nicht-optionalen Typ (auch dann nicht, wenn dieser tatsächlich niemals `nil` enthält).
Und einer Methode, die einen nicht-optionalen Typ erwartet, kannst du keinen optionalen Typ übergeben, ohne ihn vorher auszupacken.

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## Optionals verwenden

Da optionale Typen nicht dieselben Typen wie ihre Basistypen sind, lassen sich beide nicht auf dieselbe Weise verwenden.
Zum Beispiel: `Int("123") + 1` führt zu einem Compilerfehler „Value of optional type 'Int?' must be unwrapped to a value of type 'Int'“.
Das liegt daran, dass `Int("123")` einen optionalen Typ `Int?` zurückgibt und nicht den Typ `Int`: Wenn sich der String nicht in eine Ganzzahl umwandeln lässt, ist das Ergebnis `nil`.
Um aus der Umwandlung an den `Int` zu gelangen, musst du ihn zuerst „auspacken“.

In Swift geschieht das meist mit den Konstrukten `if-let` und `guard-let` für das [_optional binding_][optional-binding]. Sie prüfen auf `nil`: Ist ein Wert vorhanden, nimmt das Programm einen Codepfad, in dem der ausgepackte Wert an einen angegebenen Namen gebunden wird; wurde `nil` gefunden, nimmt es einen anderen Codepfad.

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

Beachte, dass die Variable `safeNum` den Typ `Int` hat und nicht `Int?`.
Im folgenden Beispiel hat `num` den Typ `Int?` und `safeNum` den Typ `Int`.

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

Dieses _optional binding_ ist wichtig, weil es den optionalen Typ aus dem Wert auspackt (oder „entfernt“) und er dadurch als nicht-optionaler Wert verwendet werden kann.
Wenn du nur bedingt prüfst, ob der Wert `nil` ist, behält er weiterhin seinen optionalen Typ:

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

Die Variante mit `guard-let` kannst du auch verwenden, wenn du früh zurückkehren möchtest:

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## Optionals vergleichen

Beachte: Auch wenn sich der Basistyp eines Paars von Optionals mit den üblichen Vergleichsoperatoren vergleichen lässt, lassen sich die Optionals selbst nicht vergleichen.
Du kannst sie nur auf Gleichheit prüfen.
Zwei Optionals sind gleich, wenn beide `nil` sind oder wenn die Werte, die sie umschließen, in ihren Basistypen gleich sind.

Du kannst aber Code schreiben, der zwei optionale Werte benutzerdefiniert vergleicht.
Unten siehst du ein Beispiel für eine `switch`-Anweisung, die nur dann `true` zurückgibt, wenn beide optionalen Werte nicht `nil` sind und der erste Wert kleiner als der zweite ist.
Dazu verwendet sie das _optional pattern_ `varName?`, das nur Optionals ohne `nil` trifft und den Wert im Optional an den Namen `varName` bindet.

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## Nil-Coalescing

Eine weitere Möglichkeit zum Auspacken ist die Verwendung eines [Ersatzwerts][fallback], wenn `nil` vorliegt.
Das geht mit dem _nil coalescing operator_ `??`. Angenommen, `x` ist ein `Int?`. Wenn du `let y = x ?? 0` schreibst, prüft Swift, ob x `nil` ist.
Ist er es nicht, packt Swift `x` aus und weist den ausgepackten Wert `y` zu. Ist `x` dagegen _doch_ `nil`, weist Swift `y` den Wert 0 zu.

Da `x ?? y` nur eine Kurzform für `x != nil ? x! : y` ist, wird der Ausdruck `y` gar nicht ausgewertet, wenn `x` nicht `nil` ist.

Zum Schluss sei angemerkt, dass der nil coalescing operator rechtsassoziativ ist, was zu überraschenden Ergebnissen führen kann, wenn man das nicht weiß.

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

Mehr über den nil coalescing operator erfährst du in [A Tour of Swift: Nil-Coalescing Operator][nil-coalescing].
