# Über

Hash-Sets implementieren das [Protokoll][set-protocol] [`sets`][sets] mit Hashing unter der Haube und ergeben damit im Durchschnitt O(1) für Einfügen, Suchen und Löschen. Sie lassen sich direkt verändern, was sie ideal für das *Visited-Set*-Muster bei Graphdurchläufen macht.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| Wort          | Wirkung                                    |
|---------------|-------------------------------------------|
| `HS{ }`       | leeres Hash-Set-Literal (wird geteilt, deshalb `clone` aufrufen!) |
| `>hash-set`   | `( seq -- set )` – baut aus einer Sequenz ein frisches Set und entfernt Duplikate |
| `adjoin`      | `( elt set -- )` – destruktives Einfügen     |
| `in?`         | `( elt set -- ? )` – Zugehörigkeitstest           |
| `delete`      | `( elt set -- )` – destruktives Entfernen     |
| `cardinality` | `( set -- n )` – Anzahl der Elemente       |
| `null?`       | `( set -- ? )` – wahr, wenn das Set leer ist |
| `members`     | `( set -- seq )` – als Sequenz auflisten  |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )` – wandelt `set` in die Klasse von `exemplar` um |

Wenn du aus Daten, die du schon hast, ein Set bauen willst, wandelt `>hash-set`
jede Sequenz in einem Schritt um und verwirft dabei Duplikate: `{ 2 3 2 5 } >hash-set`
ergibt `HS{ 2 3 5 }`. Das ist das Gegenstück zum schrittweisen Aufbau eines
Sets durch wiederholtes `adjoin`.

Ein feiner Unterschied zwischen `in?` und `member?` (aus
`sequences`): Beide prüfen die Zugehörigkeit, aber `member?` durchsucht
eine Sequenz linear, während `in?` an die Protokollmethode des
jeweiligen Set-Typs weiterleitet, bei `HS{ }` ist das ein
Hash-Lookup. Nutze `in?`, sobald dein „visited“-Container mehr
als eine Handvoll Einträge enthält.

`null?` beantwortet die Frage „Ist dieses Set leer?“, ohne die volle
`cardinality` zu berechnen. Es ist die natürliche Wächterabfrage für
„Haben wir noch etwas zu verarbeiten?“. Bei einer Arbeitsliste, die als
Set gehalten wird, leert `[ set null? ] [ … ] until` sie, bis nichts
mehr übrig ist.

## Passt gut zu Hashtabellen

`HS{ }` für „Ist X schon besucht?“ lässt sich natürlich mit `H{ }` für
„Wer sind die Nachbarn von X?“ kombinieren. Eine DFS aus dem Lehrbuch
ist dann einfach:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

Das Visited-Set verhindert doppelte Arbeit; der Stack fädelt die
Frontier-Knoten auf (LIFO über `push`/`pop`); die Nachbarn-Tabelle
(eine Hashtabelle) liefert den Graphen. Für eine Erreichbarkeitsfrage
spielt die Reihenfolge des Besuchs keine Rolle, deshalb reicht ein
Vektor als Stack. Eine echte BFS über dieselbe Struktur ersetzt den
Vektor durch eine [`<dlist>`][dlist] und entnimmt die Elemente
stattdessen von vorne.
