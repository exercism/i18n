# Über

Einen Wert für die Übertragung vorzubereiten bedeutet drei Dinge auf einmal: ihn zu serialisieren, das richtige Stück davon herauszupicken und nicht zu kopieren, wenn du es nicht musst. Drei Factor-Idiome decken das ab.

## `unparse`: vom Wert zum Quelltext

[`unparse`][unparse] (in `prettyprint`) gibt den Quelltext eines beliebigen Werts in seiner Quellform zurück. Es ist die Umkehrung des Parsers: Der Roundtrip `dup unparse parse` rekonstruiert den Wert.

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

Im Gegensatz zu `>string` (funktioniert nur auf Zeichenfolgen) und `number>string` (nur Zahlen). `unparse` ist der universelle Weg, allerdings zum Preis davon, dass Factor-Syntax entsteht (Strings in Anführungszeichen behalten ihre Anführungszeichen). Es ist also das richtige Werkzeug, wenn die Gegenseite den Text wieder parst, und das falsche für menschenlesbare Ausgabe.

## Slices: Ansichten, keine Kopien

| Wort          | Wirkung                                        |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`: kopiert die ersten n     |
| `head-slice`  | `( seq n -- slice )`: Ansicht der ersten n      |
| `tail`        | `( seq n -- newseq )`: kopiert ab Index n       |
| `tail-slice`  | `( seq n -- slice )`: Ansicht ab Index n        |
| `head*`       | `( seq n -- newseq )`: kopiert alles außer den letzten n |
| `head-slice*` | `( seq n -- slice )`: Ansicht von allem außer den letzten n |
| `tail*`       | `( seq n -- newseq )`: kopiert die letzten n    |
| `tail-slice*` | `( seq n -- slice )`: Ansicht der letzten n     |

Ein `slice` ist ein Tupel, das einen Von-Index, einen Bis-Index und die zugrundeliegende Sequenz enthält. Er implementiert das [Sequenzprotokoll][sequence-protocol], sodass jede Sequenzoperation darauf funktioniert. Greif zu den Slice-Varianten, wenn du sonst nur zum Lesen Speicher belegen würdest; greif zu den kopierenden Varianten, wenn du die Daten behalten musst, nachdem sich die zugrundeliegende Sequenz ändern könnte.

## Cleave mit mehreren Eingaben: `2bi`, `3bi`, `2tri`, `3tri`

Die einfachen Cleave-Wörter `bi` und `tri` wenden zwei oder drei Quotations auf *einen* Eingabewert auf dem Stack an. Die Varianten mit der Vorsilbe `2` bzw. `3` wenden jede Quotation auf *zwei* oder *drei* Eingabewerte an:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

Jede Quotation erhält *alle* Eingabewerte. Benutze `2bi` also, wenn beide Projektionen von dem Paar abhängen, und nicht, wenn du dieselbe Projektion auf jeden Eingabewert einzeln anwenden willst (das ist `bi@`).

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

Für *eine* Quotation, die auf jeden Eingabewert einzeln angewendet wird, nimm stattdessen `bi@` (zwei Eingabewerte) oder `tri@` (drei Eingabewerte). Dieselbe Familie, andere Form.
