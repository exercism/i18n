# Kombination von Iteratoren

Eine Schleife kann mehr als einen Iterator aufrufen. Jeder wird pro Durchlauf einmal nach seinem nächsten Wert gefragt, und sie bewegen sich gemeinsam vorwärts.

```sather
   loop
      first ::= violin_one.elt!;
      second ::= violin_two.elt!;
      #OUT + first + " against " + second + "\n";
   end;
```

Das durchläuft beide Arrays Seite an Seite: erstes Element mit erstem Element, zweites mit zweitem.

## Die Regel, die alle überrascht

**Die Schleife endet, sobald der *erste* ihrer Iteratoren nichts mehr liefert.**

Nicht, wenn der letzte das tut. Nicht, wenn alle das tun. Der erste.

Wenn `violin_one` also vier Takte enthält und `violin_two` zwei, dann läuft die Schleife oben **zweimal**. Der dritte und vierte Takt der ersten Stimme werden nie angeschaut, denn dann hat die zweite Stimme nichts mehr anzubieten.

Das ist meistens genau das, was man will: Dinge zu Paaren zusammenzufassen ergibt nur Sinn, solange es Paare gibt. Aber man muss es wissen, statt es selbst herauszufinden.

## Zählen nebenbei

Ein Iterator, der nie endet, ist genau wegen dieser Regel nützlich. `up!` zählt für immer:

```sather
1.up!        -- 1, 2, 3, 4, ... and never ends
```

Allein würde er für immer weiterlaufen. Mit einem gepaart, der endet, nummeriert er die Werte, ohne je entscheiden zu müssen, wie weit gezählt wird:

```sather
   loop
      number ::= 1.up!;
      bar ::= part.elt!;
      #OUT + "Bar " + number + ": " + bar + "\n";
   end;
```

`part.elt!` beendet die Schleife; `1.up!` liefert die Nummerierung. Keiner von beiden muss wissen, wie lang die Stimme ist.

## Die Reihenfolge spielt keine Rolle

Die Iteratoren werden alle einmal pro Durchlauf gefragt, deshalb macht es keinen Unterschied, welcher zuerst geschrieben wird. Wichtig ist, dass jeder genau einmal gefragt wird: `part.elt!` zweimal in einem Durchlauf zu schreiben, nimmt zwei Werte statt einem.
