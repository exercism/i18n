# Über

## Bedingte Anweisungen

Bedingte Anweisungen sind Anweisungen, die Entscheidungen treffen: Sie können entweder Seiteneffekte ausführen oder den Ablauf der Ausführung durch ein Programm steuern.
Zu den bedingten Anweisungen gehören `if`-, `if/else`-, `switch`- und `ternary`-Anweisungen.

Mit bedingten Anweisungen stellst du Fragen zu einem Wert oder zu einer Beziehung zwischen Werten.
Die Frage ergibt eine boolesche Antwort, aber die `if`-Anweisung selbst kann jeden beliebigen Wert zurückgeben oder einfach einen Seiteneffekt ausführen.

## if-Anweisungen

Die einfachste `if`-Anweisung wertet einen Ausdruck aus und führt eine Zeile aus.
Der getestete Ausdruck steht immer in runden Klammern.

Sie kann einen Seiteneffekt ausführen

```c
if (count > 10)
    printf("count is greater than 10");
```

oder sie kann den Ablauf der Ausführung ändern


```c
if (count > 10)
    return sum;
```

Wenn eine `if`-Anweisung mehr als eine Zeile ausführt, muss sie die Zeilen in geschweifte Klammern setzen

```c
if (count > 10) {
    printf("count is greater than 10");
    return sum;
}
```

Manche Teams legen als Standard fest, dass `if`-Anweisungen immer geschweifte Klammern verwenden sollen, auch bei nur einer Zeile.


## if-else

Eine `if`-Anweisung kannst du mit einem `else` kombinieren

```c
if (number % 2 == 0)
    return "even";
else
    return "odd";
```

## if-else-if


`else` kannst du mit einem weiteren `if` kombinieren, um das zu bilden, was man eine `if-else-if ladder` nennt.

```c
if (number == 0)
    return "zero";
else if (number < 0)
    return "negative";
else if (number < 10)
    return "single digit";   
else if (number % 2 == 0)
    return "even";
else
    return "odd";
```

## switch


Manchmal lässt sich eine `if-else-if ladder` besser durch ein `switch` darstellen.
Wie bei `if` steht der getestete Ausdruck immer in runden Klammern.

```c
switch (number) {
    case -1:
        return "negative one";
    case 0:
        return "zero";
    case 1:
        return "positive one";
    case 10:
        return "positive ten";
    case -10:
        return "negative ten";
    default:
        return "don't care";
}
```

Der `default`-Fall wird ausgeführt, wenn der getestete Wert zu keinem der vorherigen Fälle passt.

Wenn ein `switch`-Fall nichts zurückgibt, fügst du üblicherweise ein `break` ein, um den Fall zu beenden. Andernfalls fällt die Logik in den nächsten Fall durch.
Manchmal wird das Durchfallen absichtlich verwendet

```c
switch (number) {
    case 0:
        msg = "zero"; break;
    case 1:
        msg = "one"; break;
    case 2: case 3: case 4:
        msg = "more than one and less than five"; break;
    default:
        msg = "don't care";
}
```

Wenn das Durchfallen unbeabsichtigt passiert, ist es ein Bug.

```c
switch (number) {
    case 0:
        msg = "zero"; // bug! fallthrough of 0 will set msg to "one"
    case 1:
        msg = "one"; break; 
    case 2: case 3: case 4:
        msg = "more than one and less than five"; break;
    default:
        msg = "don't care";
}
```

Ein switch kann von Vorteil sein, wenn du gegen bestimmte Werte statt gegen einen Wertebereich testest.
Er kann schneller sein als eine `if-else-if ladder`, weil der Compiler die `switch`-Anweisung möglicherweise auf Arten optimieren kann, die mit einer Leiter nicht möglich sind.
Ein switch kann manchmal lesbarer wirken als eine Leiter.

## Ternärer (auch bedingter) Operator

Der ternäre Operator ist eine bedingte Anweisung aus drei Teilen, die oft verwendet wird, um einen Wert festzulegen.
Der zu testende Ausdruck steht vor dem Fragezeichen und muss nicht in runden Klammern stehen.
Der Wert, der bei wahr zurückgegeben wird, steht vor dem Doppelpunkt, der Wert, der bei falsch zurückgegeben wird, danach.
Zurückgegeben werden kann entweder ein Literal oder eine Variable.

```c
int i = j > 5 ? 5: j;
```

Ternäre Operatoren lassen sich verschachteln, um syntaktischen Ballast zu verringern.

```c
// the below could also be 
i = j > 5 ? j :k > 5 ? k: 10;
// but that may not be quite as readable

i = j > 5 ? j
    :k > 5 ? k
    :10;

// which is the same as
if (j > 5) i = j;
else if (k > 5) i = k;
else i = 10;
```

## Bedingte Vergleiche von Gleitkommazahlen

Weil Gleitkommazahlen auf eine bestimmte Weise implementiert sind, kann eine einfache Rechenoperation zu einem Rundungsfehler führen. Dadurch liefert ein Gleichheitstest möglicherweise nicht das erwartete Ergebnis.

```c
    a = 1.345f;
    b = 1.123f;
    c = a + b;
    // c may equal something like 2.4679999352
    if (c == 2.468)
        return "I won the lottery!";
```

Mit einem Toleranzwert, der als `epsilon` bezeichnet wird, kannst du einen Bereich festlegen, in dem ein Wert beim Vergleich mit einem anderen Wert noch als gleich gilt.
Manche Plattformen haben eingebaute Konstanten für die Epsilons von float und double.
Weitere Informationen findest du in der Dokumentation deines Compilers.
Die Berechnung des Epsilons kann anspruchsvoll sein und sich von Plattform zu Plattform unterscheiden, sogar von Rechner zu Rechner.
Hier ist ein Beispielprogramm mit einem einfachen Vergleich.

```c
#include <stdio.h>
#include <math.h>
#include <stdbool.h>

const double MY_EPSILON = .002;

bool same(double x, double y)
{
    return fabs(x - y) < MY_EPSILON;
}

int main()
{
    // Same should return true if the difference is less than MY_EPSILON
    printf("%s\n", same(1.1, 1.099) ? "true" : "false"); // prints true
    printf("%s\n", same(1.1, 1.098) ? "true" : "false"); // prints false
    return 0;
}
```

Sei vorsichtig, wenn du `float`s oder `double`s auf Gleichheit vergleichst!
