# Einführung

Smart Pointer sind ein modernes C++-Feature, das automatische Speicherverwaltung bietet und dabei hilft, Speicherlecks und Dangling Pointer zu vermeiden, wie sie bei rohen Zeigern häufig auftreten.
Sie fungieren als Wrapper um rohe Zeiger und fügen zusätzliche Funktionalität hinzu, etwa die automatische Speicherfreigabe, wenn der Zeiger nicht mehr benötigt wird.

## Allgemeine Syntax

Smart Pointer sind in der C++-Standardbibliothek typischerweise als Klassentemplates implementiert.
Die beiden am häufigsten verwendeten Smart Pointer sind `std::unique_ptr` und `std::shared_ptr`.

## Unique Pointer

`std::unique_ptr` ist ein Smart Pointer, der das Objekt exklusiv besitzt.
Er stellt sicher, dass zu jedem Zeitpunkt nur ein `std::unique_ptr`-Objekt die Ressource besitzt.
Wenn der besitzende `std::unique_ptr` zerstört oder zurückgesetzt wird, zerstört er automatisch die Objekte und gibt ihren Speicher frei.

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## Vorteile von `std::make_unique()`

Wenn du einen `std::unique_ptr` erzeugst, ist es besser, `std::make_unique()` zu verwenden, statt den Speicher mit `new` direkt zu allokieren.
`std::make_unique()` bietet mehrere Vorteile:
1. **Ausnahmesicherheit**: `std::make_unique()` garantiert Ausnahmesicherheit.
  Wird während der Konstruktion des Objekts eine Ausnahme ausgelöst, wird der Speicher automatisch freigegeben, sodass keine Speicherlecks entstehen.
2. **Klarheit**: Die Verwendung von `std::make_unique()` macht den Code klarer und prägnanter.
  Du musst den Typ, der allokiert wird, nicht mehr explizit angeben, weil die Template-Argumente automatisch abgeleitet werden.
3. **Optimierungsmöglichkeiten**: Compiler können `std::make_unique()` besser optimieren als eine manuelle Speicherallokation mit `new`, was zu besserer Performance führen kann.
4. **Vermeidung von Fehlgebrauch**: Wird der `std::unique_ptr` manuell konstruiert, ist es möglich, die zugrunde liegende Ressource zu löschen.
  Das würde zu undefiniertem Verhalten führen, wenn der `std::unique_ptr` sie am Ende seines Gültigkeitsbereichs zu löschen versucht.

## Shared Pointer

`std::shared_ptr` ist ein Smart Pointer, der es mehreren `std::shared_ptr`-Objekten ermöglicht, sich das Ownership an derselben Ressource zu teilen.
Er verfolgt, wie viele Shared Pointer auf die Ressource verweisen, und gibt den Speicher erst frei, wenn der letzte Shared Pointer, der die Ressource besitzt, seinen Gültigkeitsbereich verlässt oder zurückgesetzt wird.

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
In C++17 und darunter wird die Verwendung von `std::shared_ptr` mit Arrays über `std::make_shared<T[]>` nicht direkt unterstützt.
Zwar lassen sich Arrays mit `std::make_shared<T[]>` allokieren, aber daraus direkt Shared Pointer zu erzeugen, kann zu undefiniertem Verhalten führen, weil sich die Speicherverwaltung einzelner Objekte von der von Arrays unterscheidet.
Verwende stattdessen `std::vector` oder eigene Löschfunktionen, um Arrays mit Shared Pointern effektiv zu verwalten.
Achte bei Array-Allokationen und Shared Pointern in C++17 immer auf die Kompatibilität mit deinem Compiler und deiner Standardbibliothek.
~~~~

## Vorteile von `std::make_shared()`

Ähnlich wie `std::make_unique()` bietet `std::make_shared()` Vorteile wie eine bessere Speichereffizienz, Ausnahmesicherheit und Lesbarkeit.
Es fasst die Speicherallokation für den Kontrollblock und das verwaltete Objekt in einer einzigen Operation zusammen, was die Effizienz erhöht und das Risiko von Speicherlecks verringert.
Außerdem vereinfacht die automatische Ableitung der Template-Argumente den Code und verbessert die Lesbarkeit.
Bei der Arbeit mit `std::shared_ptr`-Objekten in C++ sorgt `std::make_shared()` für saubereren, sichereren und effizienteren Code.

## Weak Pointer

`std::weak_ptr` ist eine Begleitklasse zu `std::shared_ptr`, die eine nicht-besitzende „schwache“ Referenz auf ein Objekt bereitstellt, das von einem Shared Pointer verwaltet wird.

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

Weak Pointer sind in Szenarien nützlich, in denen zyklische Referenzen aufgebrochen werden müssen, um Speicherlecks zu verhindern.
`std::weak_ptr` wurde entwickelt, um das Problem des zyklischen Ownerships zu lösen, auch bekannt als zirkuläre Referenzen, die bei der Verwendung von `std::shared_ptr` auftreten können.
In einem zyklischen Ownership-Szenario verweisen zwei oder mehr `std::shared_ptr`-Objekte aufeinander und bilden einen Zyklus, in dem keines der Objekte gelöscht werden kann, weil sie starke Referenzen aufeinander halten, was zu Speicherlecks führt.
`std::weak_ptr` bietet eine Lösung für dieses Problem, indem es schwache Referenzen auf gemeinsame Objekte erlaubt, ohne zu deren Referenzzähler beizutragen.
Das bedeutet, dass es das gemeinsame Objekt beobachten und darauf zugreifen kann, aber nicht verhindert, dass es gelöscht wird.
~~~~

## Empfehlungen zur Verwendung

Verwende Smart Pointer standardmäßig: `std::unique_ptr` für exklusives Ownership und `std::shared_ptr` für gemeinsames Ownership.
Rohe Zeiger sind für nicht-besitzende Referenzen oder die Anbindung an Legacy-Code reserviert.
In den meisten Fällen reicht `std::unique_ptr` für exklusives Ownership aus, weil es eine schlanke Speicherverwaltung ohne den Overhead der Referenzzählung bietet.
`std::shared_ptr` solltest du sparsam einsetzen, denn es bringt Overhead und Komplexität mit sich, sofern nicht wirklich gemeinsames Ownership nötig ist.
`std::weak_ptr` ist darauf spezialisiert, zyklische Abhängigkeiten aufzubrechen oder gemeinsame Objekte zu beobachten, wird aber nicht oft verwendet.
