# Überblick

## Einführung

Generics sind ein Sprachmerkmal, das die Wiederverwendung von Code ermöglicht.
Zum Beispiel sollte es keine Rolle spielen, welchen Typ eine Liste enthält, um ihre Länge zu berechnen.
Deshalb verwendet die Funktion `length` einen generischen Typparameter `a` in ihrer Typsignatur.

```elm
length : List a -> Int
```

## Parameter in Typen

Wenn ein Typ generisch über einen anderen Typ ist, verwenden wir für diesen anderen Typ einen kleingeschriebenen Namen und nennen ihn Typparameter.
Häufige Beispiele sind die benutzerdefinierten Typen `List`, `Maybe` und `Result`.

```elm
-- Maybe is generic over the type a
type Maybe a
    = Nothing
    | Just a

someString : Maybe String
someString = Just "hello"

someInt : Maybe Int
someInt = Just 42
```

Ein wichtiger Hinweis zu Namen von Typparametern ist, dass sie aus mehreren Zeichen bestehen können.
Die einzige Einschränkung ist, dass ihre Namen kleingeschrieben sein müssen.
Wenn es nützlich ist, geben wir ihnen daher aussagekräftige Namen.

Ein Typ kann generisch über mehrere andere Typen sein und dadurch mehrere Typparameter haben.
In diesem Fall erhält jeder unabhängige Typ einen anderen kleingeschriebenen Namen.
Ihre Unabhängigkeit hindert sie nicht daran, derselbe Typ zu werden; sie ermöglicht ihnen lediglich, verschieden zu sein.

```elm
-- Result is generic over the types error and value
type Result error value
    = Ok value
    | Err error
```

Record-Typ-Aliase können ebenfalls Typparameter haben, obwohl das seltener vorkommt.

```elm
-- Event is generic over the type a
type alias Event a =
    { at : Time
    , data : a 
    }
```

> Deshalb definiert das Paket `Html` den Typ `Html msg` mit einem Typparameter namens `msg`.
> Die Elm-Architektur leitet dich dazu an, einen benutzerdefinierten Typ `Msg` zu erstellen, der alle Nachrichten beschreibt, die deine Webseite auslösen kann.
> Infolgedessen baust du Ansichten vom Typ `Html Msg`, wobei `Msg` der konkrete Typ ist, den du definiert hast.
> Anfänger sind manchmal verwirrt bei Fehlermeldungen, die `Html msg` (kleingeschrieben) erwähnen, und bei Fehlern mit `Html Msg`.
> Jetzt weißt du es!
> Der Unterschied ist, dass der erste generisch über jeden `msg`-Typ ist, während der zweite spezifisch für deinen `Msg`-Typ ist.

## Typparameter in Funktionen

Da Typen generisch sein können, können auch Funktionen generisch sein.
Funktionen, die generische Typen verarbeiten, können geschrieben werden, wie zum Beispiel `Maybe.withDefault`.

```elm
withDefault : a -> Maybe a -> a
withDefault default maybe =
    case maybe of
      Just value -> value
      Nothing -> default
```

Funktionen, die andere Funktionen als Parameter entgegennehmen, heißen Funktionen höherer Ordnung, und auch diese können generisch sein.

```elm
map : (a -> b) -> Maybe a -> Maybe b
map function maybe =
  case maybe of
    Just value ->
      Just (function value)

    Nothing ->
      Nothing
```

Typparameter können sowohl in den Eingabewerten als auch in der Ausgabe einer Funktion vorkommen. Die durch Typparameter ermöglichte Generizität wird üblicherweise **parametrische Polymorphie** genannt.
Dies steht im Gegensatz zur Ad-hoc-Polymorphie, auch bekannt als Funktionsüberladung, bei der derselbe Funktionsname für mehrere Implementierungen mit unterschiedlichen Typen verwendet werden kann.
Ebenso steht es im Gegensatz zur Subtyppolymorphie, bei der Typen in einer Hierarchie definiert werden können und Funktionen, die für einen Typ definiert sind, auch mit Argumenten seiner Subtypen aufgerufen werden können.
In Elm ist der einzige verfügbare Mechanismus für Generizität die parametrische Polymorphie.
