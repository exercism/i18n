# Überblick

Auch wenn Elixir-Programmierer oft „let it crash“ sagen und für den „Happy Path“ programmieren, gibt es doch häufig Situationen, in denen wir den Funktionsaufruf absichern müssen, um einen bestimmten Wert oder eine bestimmte Meldung zurückzugeben oder Systemressourcen freizugeben.

- Funktionen, die unter normalen Umständen Fehler auslösen, sollten ein `!` am Ende ihres Namens haben.
- Alternativ können Funktionen Atome und Tupel zurückgeben, um Erfolg und Fehlschlag anzuzeigen:

  ```elixir
  Map.fetch(%{a: 1}, :a)
  # => {:ok, 1}
  Map.fetch(%{a: 1}, :b)
  # => :error

  Map.fetch!(%{a: 1}, :b)
  # => raises KeyError
  ```

## Vermeide Anti-Patterns

Vermeide Programmiermuster, die Fehler zur Steuerung des logischen Ablaufs verwenden. In Elixir ist das ein Anti-Pattern.

```elixir
# Avoid using errors for control-flow.
try do
  {:ok, value} = MyModule.janky_function()
  "All good! #{value}."
rescue
  e in RuntimeError ->
    reason = e.message
    "Uh oh! #{reason}."
end

# Rather, use control-flow structures for control-flow.
case MyModule.janky_function() do
  {:ok, value} -> "All good! #{value}."
  {:error, reason} -> "Uh oh! #{reason}."
end
```
