# Einführung

Wenn wir bei einem Wert in Gleam Musterabgleich betreiben, müssen wir sicherstellen, dass die Muster jeden möglichen Wert des Typs abdecken, sonst lässt sich der Code nicht kompilieren.

Diese Funktion sollte abgelehnt werden, weil sie den Fall nicht behandelt, in dem die Liste leer ist:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

In Gleam-Programmen wollen wir meistens jeden möglichen Fall behandeln, aber in manchen Programmen wie Prototypen und schnellen Skripten wollen wir uns vielleicht nur auf den Happy Path konzentrieren und keinen Code für andere Fälle schreiben. Hier kommt Gleams `let assert` ins Spiel.

Mit let-assert-Ausdrücken kann ein Muster nur auf einige der möglichen Werte eines Typs passen, und wenn das Muster nicht auf einen Wert passt, stürzt das Programm ab. Mit `let assert` können wir die obige Funktion so schreiben:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam-Bibliotheken sollten niemals let-assert-Ausdrücke verwenden, da diese das Programm zum Absturz bringen können. Stattdessen sollten sie den `Result`-Typ verwenden und den Anwendungsentwickler entscheiden lassen, wie mit Fehlern umgegangen wird.
