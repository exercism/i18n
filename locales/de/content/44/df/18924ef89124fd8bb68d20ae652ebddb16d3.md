# Gebundene Routinen

```sather
   part : ROUT{STR}:STR := bind(shout(_));
   part.call("who's there");
```

## bind

`bind` nimmt einen Aufruf entgegen, in dem jeder Teil durch `_` ersetzt werden kann. Alles, was kein `_` ist, wird **jetzt** ausgewertet und behalten; jedes `_` wird zu einem Argument der gebundenen Routine, in der Reihenfolge, in der es geschrieben steht.

```sather
   bind(repeat(2, _))         -- ROUT{STR}:STR
   bind(repeat(_, "Ha"))      -- ROUT{INT}:STR
   bind(repeat(_, _))         -- ROUT{INT,STR}:STR
```

## Die Typen

| Typ | Nimmt | Liefert |
| --- | --- | --- |
| `ROUT:INT` | nichts | `INT` |
| `ROUT{STR}` | ein `STR` | nichts |
| `ROUT{STR}:STR` | ein `STR` | ein `STR` |
| `ROUT{INT,INT}:BOOL` | zwei `INT`-Werte | `BOOL` |

`ITER{...}` ist dieselbe Idee für einen Iterator.

## call

`call` liefert die restlichen Argumente. Eine gebundene Routine, die nichts zurückgibt, wird genauso aufgerufen, als Anweisung.

## bind steht auf der rechten Seite einer Zuweisung

Ein `bind` kann in einer Variablen deklariert oder als Argument übergeben werden:

```sather
   part ::= bind(shout(_));                -- yes
   part : ROUT{STR}:STR := bind(shout(_)); -- yes
   rehearse("line", bind(shout(_)));       -- yes
```

aber es darf nicht direkt in ein `return` gesetzt werden:

```sather
   return bind(shout(_));                  -- does not parse
```

Pack es in eine Variable und gib diese zurück. Die Fehlermeldung zeigt auf das `bind` und erwähnt Unterstriche, was aus der Zeile selbst nicht ersichtlich ist.

## Wo sie verwendet werden

Die Bibliothek nimmt sie überall dort entgegen, wo Verhalten bereitgestellt werden muss:

```sather
   names.sort_by(bind(shorter(_, _)));
   scores.count_if(bind(over(10, _)));
   scores.find_if(bind(is_even(_)));
```

Sortieren ist der klarste Fall: `sort_by` weiß, wie sortiert wird, und nichts über deine Vorstellung von Reihenfolge, und über die gebundene Routine treffen sich die beiden.

## Eine Einschränkung in diesem Compiler

Sather 1.2 implementiert keine **dispatched** gebundenen Routinen, also das Binden einer Routine an eine Variable eines abstrakten Typs. Der Compiler sagt das unmissverständlich:

```
Dispatched bound routines are not implemented yet
```

Binde an einen konkreten Typ oder an eine Klasse, und alles ist in Ordnung. Deshalb schreibt das Test-Harness des Tracks seine Prüfungen auf Ausnahmen von Hand aus, statt eine gebundene Routine zu nehmen.

## Gebundene Routinen oder abstrakte Klassen?

Beide lassen den Aufrufer Verhalten bereitstellen.

Eine gebundene Routine ist eine einzige Routine, braucht keine Klasse und wird dort geschrieben, wo sie verwendet wird. Eine abstrakte Klasse trägt mehrere Routinen und etwas Zustand und ist den Aufwand wert, wenn das Bereitgestellte aus mehr als einem Teil besteht.

Eine Routine zum Weitergeben: binde sie. Ein Mitspieler mit mehreren: schreibe eine Klasse.
