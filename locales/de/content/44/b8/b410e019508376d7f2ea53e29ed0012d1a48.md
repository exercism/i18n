# Über

Eine `GENERIC:`-Deklaration führt ein Wort ein, dessen Verhalten von der Klasse eines seiner Argumente abhängt. Konkretes Verhalten liefern *Methoden* (`M:`), die auf bestimmte Klassen abzielen.

```factor
GENERIC: stringify ( obj -- str )
M: integer stringify number>string ;
M: string  stringify ;
M: f       stringify drop "(none)" ;
```

Wenn `stringify` aufgerufen wird, untersucht Factor die Spitze des Stacks, sucht die spezifischste Methode, deren Klasse passt, und führt sie aus. Wenn keine Methode passt, wird ein Fehler ausgelöst.

## Dispatch-Klasse

Standardmäßig erfolgt der Dispatch auf dem obersten Argument (dem ersten Eingabewert, der im Stack-Effekt deklariert ist). Für Multi-Argument-Dispatch siehe `HOOK:` und `MATH:`, deren Dispatch auf dem zweiten Argument bzw. auf numerischer Promotion basiert.

## Methoden zu einem generischen Wort hinzufügen

Du kannst ein generisches Wort jederzeit erweitern, sogar aus einem anderen Vokabular, solange du sowohl das generische Wort als auch die Klasse mit `USE:` einbinden kannst:

```factor
USING: math ;
M: ratio  area drop 0 ;     ! adds an `area` method for ratios
```

## Methoden für eingebaute Klassen

Generische Wörter funktionieren genauso gut mit eingebauten Klassen (`integer`, `string`, `array`, `f`, `t`) wie mit benutzerdefinierten Tupeln. Methoden für `f` und `t` sind besonders nützlich für Prädikate im Stil von „is-set?“, die natürliche Standardwerte haben.

## Wann ein generisches Wort die richtige Wahl ist

Greif zu `GENERIC:`, wenn:

- Eine einzelne Operation *wirklich unterschiedliche* Implementierungen für verschiedene Eingabewerte hat (nicht nur ein `case` über Labels).
- Du erwartest, dass später neue Typen durch anderen Code hinzugefügt werden.
- Du möchtest, dass das Typsystem erzwingt, dass die Operation für jede relevante Klasse definiert ist. Factor kann dir die fehlenden Methoden auflisten.

Wenn die Variation eine kleine, feste Aufzählung von Labels ist, ist ein `case` einfacher.
