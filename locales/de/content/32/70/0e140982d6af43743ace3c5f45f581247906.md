# Über

Wenn wir Haskell-Funktionen schreiben, können wir [Pattern Matching][pattern-matching] verwenden. Pattern Matching ist ein sehr mächtiges Feature von Haskell, mit dem du auf Datenkonstruktoren matchen und Variablen an die Werte darin binden kannst. Wie der Name schon sagt, gleichen wir dabei Werte mit Patterns ab, und wenn ein Wert zu einem Pattern passt, können wir Variablen an die Werte im Pattern binden. Pattern Matching baut vor allem auf diesen Konzepten auf: Werte erkennen, Variablen binden und Werte zerlegen.

~~~~exercism/note
Pattern Matching in Sprachen wie Elixir unterscheidet sich ein wenig von Pattern Matching in Haskell. Elixir erlaubt zum Beispiel mehrere gleiche Bindungsnamen in einem Pattern, Haskell nicht.
~~~~


Nimm zum Beispiel diese Funktion:

```haskell
lucky :: Int -> String
lucky 7 = "Lucky number seven!"
lucky x = "Sorry, you're out of luck, pal!"
```

Hier haben wir eine Funktion `lucky`, die einen `Int` entgegennimmt und einen `String` zurückgibt.
Wir haben zwei Patterns für die Funktion definiert: eines, das auf die Zahl `7` passt, und eines, das auf jede andere Zahl passt. Der Name kann beliebig sein (solange er der Namenskonvention von Haskell folgt), aber wir verwenden hier `x`.
Wenn die Zahl `7` ist, gibt die Funktion `"Lucky number seven!"` zurück, andernfalls gibt sie `"Sorry, you're out of luck, pal!"` zurück.
Wichtig ist hier, dass die Patterns von oben nach unten geprüft werden. Hätten wir die Reihenfolge der Patterns vertauscht, würde die Funktion immer `"Lucky number seven!"` zurückgeben.

## Patterns für Listen

Ein sehr häufiges Pattern ist das Matchen auf Listen, wobei man den Kopf und den Rest der Liste nimmt.
Das liegt daran, dass Listen in Haskell verkettete Listen sind.
Hier ein Beispiel für eine Funktion, die den Kopf und den Rest einer Liste zurückgibt:

```haskell
headAndTail :: [Int] -> (Int, [Int])
headAndTail [] = error "Can't call head on an empty list"
headAndTail (x:xs) = (x, xs)
```

Wir haben hier zwei Patterns: eines, das auf eine leere Liste passt, und eines, das auf eine Liste mit mindestens einem Element passt.
Der Grund dafür ist, dass wir für den Fall einer leeren Liste einen eigenen Fall brauchen, sonst bekämen wir einen Laufzeitfehler.
Ist die Liste nicht leer, können wir den Kopf der Liste an `x` und den Rest der Liste an `xs` binden.
Das machen wir mit dem `:`-Operator (cons), mit dem man ein Element an den Anfang einer Liste setzt.
Beim Pattern Matching zerlegt er dagegen eine Liste in ihren Kopf und ihren Rest, macht also gewissermaßen das Gegenteil.

`xs` ist ein gebräuchlicher Name für den Rest einer Liste; er macht deutlich, dass es sich um eine Liste handelt. Arbeitest du mit einer verschachtelten Liste, kannst du `xss` verwenden, um zu zeigen, dass es eine Liste von Listen ist.

## Patterns für Tupel

Wie bei Listen können wir auch auf Tupel matchen.
Hier ein Beispiel für eine Funktion, die ein Tupel entgegennimmt und das erste und zweite Element zurückgibt:

```haskell
sumTuple :: (Int, Int) -> Int
sumTuple (x, y) = x + y
```

Hier haben wir ein Pattern, das auf ein Tupel mit zwei Elementen passt: Das erste Element wird an `x` gebunden, das zweite an `y`.

## Wildcard-Patterns

Manchmal interessiert uns der Wert einer Variable nicht, wir wollen nur auf das Pattern matchen.
Genau dafür gibt es das Wildcard-Pattern, das durch einen Unterstrich `_` dargestellt wird.

Hier ein Beispiel für eine Funktion, die das erste Element einer Liste zurückgibt:

```haskell
head' :: [Int] -> Int
head' [] = error "Can't call head on an empty list"
head' (x:_) = x
```

Hier sagen wir, dass wir den Rest der Liste nicht brauchen, und ignorieren ihn mit dem Wildcard-Pattern.

## Patterns für Typen

Wir können auch auf Typen matchen, indem wir den Konstruktor des jeweiligen Typs verwenden.
Außerdem können wir Werte aus dem Typ herausziehen, wie wir es bei Tupeln gemacht haben.

```haskell
data AccountType = Guest | User String 

greet :: AccountType -> String
greet Guest = "Welcome, guest!"
greet (User name) = "Welcome, " ++ name ++ "!"
```

Im ersten Pattern matchen wir auf den Konstruktor `Guest`, im zweiten auf den Konstruktor `User` und binden den Wert darin an `name`.
