# Tests

Jede Übung enthält eine Testdatei.
Führe die Tests mit dem Programm `bats` aus.
```bash
bats test-hello-world.bats
```

`bats` muss installiert werden.
Wie du `bats` für dein System installierst, erfährst du auf der Seite [Tests auf dem Bash-Track][bash].

### bats ist in Bash implementiert

Die bats-Datei ist ein Bash-Skript mit einigen speziellen Funktionen, die der Befehl `bats` erkennt.
Du wirst einige Tests sehen, die so aussehen:
```sh
gawk -f some-exercise.awk <<< "some,input,here"
```
Diese `<<<`-Syntax ist ein Bash-[Here String][here-string].
Sie schickt den String auf der rechten Seite in die Standardeingabe des Programms auf der linken Seite.
Das ist ([ungefähr][so]) dasselbe wie
```sh
echo "some,input,here" | gawk -f some-exercise.awk
```

## Hilfe zu den assert-Funktionen

Die Tests verwenden Funktionen aus der Bibliothek [bats-assert][bats-assert].
Dort findest du Hilfe zu den verschiedenen `assert*`-Funktionen.

## Übersprungene Tests

Eine Übung ist gelöst, wenn alle ihre Tests bestehen.
Standardmäßig wird nur ein Test (der erste) ausgeführt, wenn du die Tests startest.
Das ist Absicht, denn so kannst du dich ganz darauf konzentrieren, diesen einen Test bestehen zu lassen.
Sobald er besteht, kannst du den nächsten Test aktivieren, indem du die folgende Anmerkung auskommentierst oder entfernst:

    [[ $BATS_RUN_SKIPPED == true ]] || skip

Diese Anmerkung steht vor den weiteren Tests.

## Skips außer Kraft setzen

Um alle Tests auszuführen, auch die mit `skip`-Anmerkungen, kannst du Folgendes ausführen:
```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Es kann praktisch sein, eine Wrapper-Funktion zu verwenden, um Tipparbeit zu sparen. In `bash` kannst du das so machen:
```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```
Danach startest du die Tests einfach mit:
```bash
bats
```

## Debug-Ausgaben

```exercism/caution
Das funktioniert lokal mit `bats`, aber **nicht** im Online-Editor von Exercism.
```

Beim Ausführen der Tests fängt `bats` sowohl stdout als auch stderr ab, um sie mit der erwarteten Ausgabe zu vergleichen.
Wenn du Debug-Meldungen nach stdout oder stderr schreibst, werden sie in die abgefangene Ausgabe aufgenommen und können dazu führen, dass der Test fehlschlägt.

Um Debug-Informationen auszugeben, ohne die Testergebnisse zu beeinflussen, stellt `bats` dafür den Dateideskriptor **3** bereit.
Alles, was in die Datei `/dev/fd/3` geschrieben wird, wird während des Testlaufs angezeigt, fließt aber nicht in die abgefangene Ausgabe ein, die für die Assertions verwendet wird.

Beispiel:

```awk
BEGIN {
    # This debug message will not interfere with test output comparison
    print "a debug message" > "/dev/fd/3"

    # Normal program output (this is what your tests will see and compare)
    print "Hello, World!"
}
```

Beispiellauf:

```none
$ bats test-hello-world.bats
test-hello-world.bats
 ✓ Say Hi!
a debug message

1 test, 0 failures
```

So siehst du hilfreiche Debug-Ausgaben, ohne die Tests zu beeinflussen.

Wenn du die Details in einer Funktion versteckst, kann das die Lesbarkeit verbessern, falls du sie an mehreren Stellen in deinem Code verwendest:

```awk
BEGIN {
    debug("starting ...")
}

# do stuff here ...

END {
    debug("... finished")
}

function debug(msg) {print msg > "/dev/fd/3"}
```
