# Überblick

## const

Der [`const`][constants]-Modifizierer kann (und sollte in der Regel) auf jedes Feld angewendet werden, dessen Wert zur Kompilierzeit bekannt ist und sich während der Laufzeit des Programms nicht ändert.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

Der Compiler zeigt dir, welche Ausdrücke zur Kompilierzeit ausgewertet werden können. Einfache arithmetische Operationen sind erlaubt, ebenso die Verkettung von Strings. Das schließt jede Auswertung aus, die den Heap oder Stack benötigen würde, daher sind alle Methodenaufrufe und Referenzen auf nicht-primitive Typen nicht möglich.

Im Netz gibt es einige Diskussionen über die Performance-Vorteile von `const` gegenüber Variablen. Beim Vergleich mit nicht-konstanten Instanzfeldern könnte es eine spürbare Speichereinsparung geben, aber im Vergleich zu statischen Variablen ist das eindeutig trivial. Jede Betrachtung der CPU-Leistung wird von deinen Kollegen wahrscheinlich als [vorzeitige Optimierung][premature-optimization] angesehen.

Ein überzeugenderer Grund, `const` zu verwenden, ist, dass es Maintainern hilft, den Code besser zu verstehen. Wenn du auf einen Blick siehst, dass ein Feld als `const` oder `readonly` markiert ist oder dass eine Eigenschaft keinen Setter hat, kannst du es weitgehend aus deiner Analyse ausklammern. Es ist unwahrscheinlich, dass es die Quelle von Bugs ist. Es wird bei einem Refactoring wahrscheinlich keine Schwierigkeiten bereiten. Dieser [Stack-Overflow-Kommentar][so-consts] geht darauf ein.

Der `const`-Modifizierer kann auch auf Werte innerhalb von Methoden angewendet werden:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

Einen Wert auf diese Weise mit `const` zu kennzeichnen, kann nützlich sein, wenn er in der Methode mehrfach verwendet wird oder du seine Bedeutung hervorheben möchtest. Einen Performance-Gewinn gegenüber der direkten Verwendung von Literalen gibt es nicht.

## readonly

Der [`readonly`][readonly-fields]-Modifizierer kann (und sollte in der Regel) auf jedes Feld angewendet werden, das nicht `const` gemacht werden kann, dessen Wert sich während der Laufzeit des Programms nicht ändert und das entweder durch einen Inline-Initialisierer oder während der Instanziierung festgelegt wird (durch den Konstruktor oder eine vom Konstruktor aufgerufene Methode).

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

Die Verwendung des `readonly`-Modifizierers wird aus denselben Gründen empfohlen, die für `const` gelten. Felder auf diese Weise einzuschränken, hilft Maintainern, den Code besser zu verstehen.

Beachte, dass der `readonly`-Modifizierer bei einem Feld nur verhindert, dass der Wert des Feldes geändert wird. Bei zusammengesetzten Typen schützt er nicht die Felder oder Eigenschaften dieses Typs. Insbesondere schützt er nicht den Inhalt von Arrays.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

Um sicherzustellen, dass alle Member eines Referenztyps geschützt sind, können die Felder `readonly` gemacht und automatische Eigenschaften ohne `set`-Accessor definiert werden.

Du solltest dir die [schreibgeschützten Sammlungen][readonly-collections] in der Base Class Library ansehen.

Für Arrays ist die [`Array.AsReadOnly<T>()`][as-read-only]-Methode das, was einer schreibgeschützten Version am nächsten kommt.
