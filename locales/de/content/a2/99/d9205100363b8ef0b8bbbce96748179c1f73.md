# Tests

Du kannst die Tests ausführen, indem du den folgenden Befehl im Verzeichnis der Übung ausführst:

```bash
dub test
```

## Die Tests bestehen

Bring den ersten Test zum Kompilieren, Linken und Bestehen, indem du den [drei Regeln der testgetriebenen Entwicklung](http://butunclebob.com/ArticleS.UncleBob.TheThreeRulesOfTdd) folgst. Erstelle gerade genug Struktur, indem du Namespaces, Funktionen, Klassen usw. deklarierst, um die Compilerfehler zu beheben und den Test fehlschlagen zu lassen. Dann schreib gerade so viel Code, dass der Test besteht. Wenn du das geschafft hast, kommentierst du den nächsten Test aus, indem du die folgende Zeile hinter den nächsten Test verschiebst.

```D
static if (all_tests_enabled)
```

Das kann zu Compilerfehlern führen, weil neue Konstrukte verwendet werden, die du noch nicht deklariert oder definiert hast. Behebe die Compilerfehler wieder minimal, damit der Test fehlschlägt, ändere dann den Code minimal, damit der Test besteht, refaktoriere deine Implementierung für Lesbarkeit und Ausdruckskraft und geh dann zum nächsten Test über.

Versuche, Standardmittel von D zu verwenden, statt eigene Low-Level-Algorithmen oder -Mittel von Hand zu schreiben.
