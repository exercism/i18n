# Über

Rekursive Funktionen sind Funktionen, die sich selbst aufrufen.

Eine rekursive Funktion braucht mindestens einen _Basisfall_ und mindestens einen _Rekursionsfall_.

Ein _Basisfall_ gibt einen Wert zurück, ohne die Funktion erneut aufzurufen.
Ein _Rekursionsfall_ ruft die Funktion erneut auf und verändert die Eingabe so, dass sie irgendwann zum Basisfall passt.

In Elm definierst du rekursive Funktionen normalerweise mit Pattern Matching und `case`-Ausdrücken.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

Eine rekursive Funktion kann viele Basisfälle und/oder viele Rekursionsfälle haben.
Zum Beispiel ist [die Fibonacci-Folge][fibonacci] eine rekursive Folge mit zwei Basisfällen:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

Beachte, dass diese konkrete Implementierung exponentiell langsam ist, weil zusammenhängende Fibonacci-Zahlen in zwei unabhängigen rekursiven Aufrufen von Grund auf neu berechnet werden.

Das Zählen, wie oft ein gegebener Wert `x` in einer Liste vorkommt, hat zwei Rekursionsfälle:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## Schleifen durch Rekursion

Wegen der Unveränderlichkeit schreibst du Schleifen in Elm anders als in imperativen Sprachen.
Zum Beispiel sehen Schleifen oft so aus:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

In einer funktionalen Sprache wie Elm kannst du Variablen nicht verändern.
Deshalb musst du Schleifen mit Rekursion umsetzen.

Das Äquivalent einer `for`-Schleife in Elm sieht so aus:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

In der Praxis iterierst du in Elm über Listen und andere Datenstrukturen meistens mit Funktionen aus dem [`List`][module-list]-Modul, etwa `List.map`, `List.filter` und `List.foldl`.
Intern sind diese Funktionen mit Rekursion umgesetzt.

## Endlose Ausführung

Rekursive Funktionen geben ihr Ergebnis möglicherweise nie zurück, wenn sie falsch umgesetzt sind oder wenn die Zahl der rekursiven Aufrufe zu groß ist.
Das kann problematisch sein, weil bei jedem Funktionsaufruf im Speicher eine Referenz abgelegt wird, an die die Laufzeitumgebung das Ergebnis zurückgeben soll (auf dem [Aufrufstapel][wiki-call-stack]).
Wenn sich eine rekursive Funktion zu oft oder sogar endlos selbst aufruft, kann der Speicher ausgehen und die Laufzeitumgebung abstürzen (ein [Stack-Overflow-Fehler][wiki-stack-overflow]).
Die Laufzeitumgebung von Elm ist auf Rekursion und Zuverlässigkeit optimiert, aber endlose Rekursion kann trotzdem Probleme verursachen.

Dieses Problem der endlosen Ausführung kann folgende Ursachen haben:

- Du vergisst, einen Basisfall umzusetzen.
- Du behandelst beim Pattern Matching nicht alle möglichen Fälle.
- Du veränderst das Argument beim rekursiven Aufruf nicht richtig und erreichst dadurch nie den Basisfall.
