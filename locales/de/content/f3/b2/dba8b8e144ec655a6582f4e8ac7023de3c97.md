# Anleitung

Du schreibst Firmware für das Punktesystem in einer Retro-Handheld-Konsole.
Die CPU des Geräts ist bescheiden, und die Anzeige des Punktestands aktualisiert sich mit einer festen Rate.
Damit das Bild flüssig bleibt, müssen die Routinen zur Punkteberechnung in einer vorhersagbaren Anzahl von Zyklen laufen, egal was der Spieler gerade tut.

Du hast vier Aufgaben.

~~~~exercism/note
Der Code für die Aufgaben sollte verzweigungsfrei sein.
Verwende `cmovcc`, `setcc` und Arithmetik statt bedingter Sprünge.
~~~~

## 1. Addiere einen Bonus, ohne dass das Display überläuft

Der Punktebereich des LCDs der Konsole hat Platz für sechs Dezimalstellen.
Er kann keine Zahl über `999999` anzeigen.
Wenn ein Bonus die laufende Gesamtpunktzahl über dieses Limit hinaus treiben würde, wird die angezeigte Gesamtpunktzahl auf dem Maximum gehalten, statt umzulaufen.

Definiere eine Funktion `add_bonus`, die, gegeben eine aktuelle Gesamtpunktzahl und einen zu addierenden Bonus, die neue Gesamtpunktzahl auf `999999` begrenzt zurückgibt.
Die Argumente sind in dieser Reihenfolge:

1. `total`: die aktuelle Gesamtpunktzahl (immer zwischen `0` und `999999`)
2. `bonus`: der zu addierende Bonus (immer nicht-negativ)

Der Rückgabewert ist `total + bonus`, wenn diese Summe kleiner oder gleich `999999` ist, andernfalls `999999`:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

Sowohl die Argumente als auch der Rückgabewert sind 64-Bit-Ganzzahlen mit Vorzeichen.

~~~~exercism/note
Du kannst davon ausgehen, dass `total + bonus` eine 64-Bit-Ganzzahl mit Vorzeichen nicht überläuft.
~~~~

## 2. Vergleiche zwei Punktzahlen

Die Konsole führt in ihrer Speicherdatei eine kleine Bestenliste der besten letzten Punktzahlen des Spielers.
Nach jeder Partie wird die neue Punktzahl an der richtigen Position in die Bestenliste eingefügt.
Die Sortierroutine fragt, welche von zwei Punktzahlen weiter vorn liegt, und erwartet die Antwort als kleine Ganzzahl.

Definiere eine Funktion `compare_scores`, die, gegeben zwei Punktzahlen, zurückgibt:

- `+1`, wenn die erste Punktzahl _höher_ ist
- `-1`, wenn die erste Punktzahl _niedriger_ ist
- `0`, wenn die beiden Punktzahlen _gleich_ sind

Beispiel:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

Sowohl die Argumente als auch der Rückgabewert sind 64-Bit-Ganzzahlen mit Vorzeichen.

## 3. Einen Rohwert validieren

Die Konsole kann sich über ihr Link-Kabel mit einem anderen Gerät verbinden, um nach einer Mehrspieler-Partie Punktzahlen auszutauschen.
Das Kabel ist elektrisch verrauscht und ankommende Bytes werden gelegentlich verfälscht, wodurch Werte weit unter dem zulässigen Minimum oder weit über dem zulässigen Maximum entstehen.
Der Validator begrenzt jede ankommende Punktzahl auf den zulässigen Bereich, bevor der Rest des Systems sie sieht.

Definiere eine Funktion `validate_score`, die, gegeben einen Rohwert und die zulässigen Grenzen, die Punktzahl auf `[min, max]` begrenzt zurückgibt.
Die Argumente sind in dieser Reihenfolge:

1. `score`: der über das Link-Kabel empfangene Rohwert
2. `min`: die kleinste erlaubte Punktzahl
3. `max`: die größte erlaubte Punktzahl

Der Rückgabewert ist `min`, wenn `score < min`, `max`, wenn `score > max`, und andernfalls `score`.
Du kannst davon ausgehen, dass `min <= max` gilt.

Beispiel:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

Alle Argumente und der Rückgabewert sind 64-Bit-Ganzzahlen mit Vorzeichen.

## 4. Die zwei höchsten Punktzahlen im Blick behalten

Am Ende jeder Spielsitzung durchsucht die Konsole das Protokoll der letzten Spiele in ihrer Speicherdatei, um die zwei höchsten jemals aufgezeichneten Punktzahlen zu finden.
Das Protokoll ist ein einfaches Array aus 64-Bit-Ganzzahlen mit Vorzeichen im Speicher.
Der Durchlauf geht einmal durch das Array und führt zwei laufende Maxima mit: den bisher höchsten Wert und den zweithöchsten.

Beachte, dass beide Zahlen mindestens `0` sein sollten.
Jede negative Zahl wird ignoriert.

Eine erste Version der Funktion wurde mit kaskadierenden bedingten Sprüngen geschrieben.
Für jeden Kandidaten fragt der Code, wo er hingehört (über dem ersten, zwischen erstem und zweitem, oder nirgends), und verschiebt die laufenden Maxima entsprechend, wobei jedes negative Ergebnis verworfen wird.

Das funktioniert.
Da die Eingabewerte aber zufällig sind, führt jeder bedingte Sprung zu vielen Fehlvorhersagen der Sprungvorhersage.
Deshalb hast du beschlossen, die Hauptschleife verzweigungsfrei umzuschreiben.

Unten siehst du die Funktion, bei der der verzweigte Abschnitt auskommentiert ist:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

Ersetze den auskommentierten Abschnitt durch eine verzweigungsfreie Implementierung.
Der einzige erlaubte Sprung im neuen Code ist der, der zum Anfang der Schleife zurückspringt, um ein neues Element im Array zu prüfen.

Die Funktion hat keinen Rückgabewert und nimmt dieselben Argumente wie die verzweigte Version:

1. `out`: Ausgabepuffer, in den die Funktion die zwei höchsten nicht-negativen Punktzahlen in absteigender Reihenfolge als 64-Bit-Ganzzahlen mit Vorzeichen schreibt
2. `array`: Eingabe-Array aus 64-Bit-Ganzzahlen mit Vorzeichen
3. `length`: die Anzahl der Elemente im Array als 64-Bit-Ganzzahl ohne Vorzeichen

~~~~exercism/note
Wenn das Array doppelte Werte enthält, können die Duplikate in beiden Ausgabefeldern auftauchen, wenn sie die zwei höchsten Punktzahlen sind.
~~~~
