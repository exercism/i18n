# Über Zeichen

Das ist ein potenziell _großes_ Thema!
Man kann ein langes Buch darüber schreiben, und mehrere Leute haben das getan (suche bei Amazon nach „unicode book“, um einige Beispiele zu sehen).

## Eine sehr kurze Geschichte

Der Umgang mit Zeichen in Computern war in früheren Jahrzehnten viel einfacher, als Programmierer annahmen, dass Englisch die einzige wichtige Sprache sei.
Also: 26 Buchstaben, Groß- und Kleinschreibung, 10 Ziffern, mehrere Satzzeichen, plus ein Code (0x07) zum Klingeln, und alles passte in 7 Bits: der [ASCII][wiki-ascii]-Zeichensatz.

Natürlich fingen die Leute an zu fragen, was es mit à, ä und Ł auf sich hat, dann fragten andere nach ऄ, ஹ und ญ, und junge Leute wollten Emojis 😱.
Was tun?

Um es kurz zu machen: Viele kluge und geduldige Leute mussten jahrelang in Ausschüssen sitzen und die Details des [Unicode][web-unicode]-Zeichensatzes und von Kodierungen wie [UTF-8][wiki-utf-8] ausarbeiten, und viele Softwareprogramme mussten _sehr_ kompliziert neu geschrieben werden.
Außerdem kamen viele neue Bugs hinzu.

Um zu verhindern, dass _alles_ kaputtgeht, stellt das Unicode/UTF-8-Design sicher, dass die ersten 127 Codes identisch mit ASCII sind _(sogar die Glocke)_.

## Zeichen in Kotlin

Sprachen, die nach etwa 2005 entworfen wurden, haben den großen Vorteil, dass bereits ein einigermaßen stabiler Unicode-Standard existierte.

Kotlin (erstmals 2011 veröffentlicht) konnte davon ausgehen, dass Benutzer eine Vielzahl von (menschlichen) Sprachen verwenden und Unicode benötigen würden, um sie auszudrücken.

~~~~exercism/advanced
[Zeichen][ref-char] in Kotlin sind 16-Bit (UTF-16) [`codepoints`][wiki-codepoint], genau wie ein JVM `char`.
Das reicht aus, um die meisten Schriftsysteme auszudrücken, aber nicht die gesamte Bandbreite an Emojis.

Der vollständige Unicode-Standard verwendet bis zu sechs Bytes (48 Bits) pro Zeichen (genannt [`grapheme`][wiki-grapheme]).

Kotlin `Strings` unterstützen diesen vollständigen Standard, indem sie bei Bedarf mehrere Codepoints pro Zeichen verwenden.
Zum Beispiel wäre 😱 `\uD83D` und `\uDE31`.

Leider hat Java keine eingebaute Graphem-Unterstützung, und aus Kompatibilitätsgründen Kotlin auch nicht.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


Zeichenliterale werden in einfache Anführungszeichen geschrieben und unterscheiden sich von Strings, die in doppelte Anführungszeichen gesetzt werden.
Das ist wahrscheinlich offensichtlich für Leute aus der C/C++-Welt, aber potenziell verwirrend für Python- und JavaScript-Programmierer.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

Die Konvertierung zwischen `Char` und `Int` ist unkompliziert:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

Der Compiler erlaubt _einige_ Formen der Ganzzahlarithmetik mit `Char`s:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## Einige Funktionen für `Char`

Wie immer gibt es viel zu [viele Funktionen][ref-char-lib], um sie hier zu besprechen, daher ist dies nur eine Auswahl.

- Für passende Alphabete ändere die Groß-/Kleinschreibung mit [`uppercase()`][ref-uppercase] und [`lowercase()`][ref-lowercase].
- Teste die Groß-/Kleinschreibung mit [`isUpperCase()`][ref-isuppercase] und [`isLowerCase()`][ref-islowercase].
- Teste den Zeichentyp mit:
  - [`isLetter()`][ref-isletter], deckt viele Alphabete ab (die Kategorien Lu, Ll, Lt, Lm und Lo in Unicode)
  - [`isDigit()`][ref-isdigit], im Bereich 0..9 (die Kategorie Nd in Unicode)
  - `isLetterOrDigit()`, kombiniert die beiden vorherigen
  - [`isWhitespace()`][ref-iswhitespace], jedes Leerzeichen (die Kategorien Cc, Zp, Zl und Zs in Unicode)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

Außerdem ermöglichen [reguläre Ausdrücke][ref-regex] (die später in einem anderen Konzept behandelt werden) eine leistungsstarke Suche und Bearbeitung.

## Konvertierungen zwischen Char-Liste und String

Um einen `String` in eine `List` von `Char`s umzuwandeln, können wir `toList()` verwenden.

Um eine `List` von `Char`s in einen `String` umzuwandeln, gibt es die Funktion [`joinToString()`][ref-jointostring], die ein Trennzeichen (oft den leeren String) als Argument nimmt.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

Beachte, dass `joinToString()` auf einer List oder einem Array arbeitet.
Um einen einzelnen `Char` in einen String mit einem Zeichen _umzuwandeln_, verwende `toString()`.

```kotlin
'a'.toString() // => "a"
```

Um zu prüfen, ob ein Zeichen in einem `String` oder einer `Char`-Liste oder einem Array vorhanden ist, haben wir `in`, was auf die Funktion [`contains()`][ref-contains] verweist.

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
