# String-Builder

`STR` ist unveränderlich, `FSTR` nicht. Verwende `STR` für fertigen Text und `FSTR` für Text, der noch zusammengesetzt wird.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## Weise das Ergebnis immer wieder zu

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR` wächst durch **amortisiertes Verdoppeln**: Wenn ihm der Platz ausgeht, nimmt es ein neues, größeres Array, doppelt so groß, und kopiert dorthin. Das Ergebnis ist also meistens dasselbe Objekt und gelegentlich ein anderes. Wenn du jedes Mal `b := b + x` schreibst, ist das in beiden Fällen korrekt und die einzige Schreibweise, die es zu lernen lohnt.

Die Verdopplung sorgt dafür, dass der Gesamtaufwand proportional zur Länge ist und nicht zu deren Quadrat: Die Kopien werden genauso schnell seltener, wie sie teurer werden.

## Warum nicht einfach `+` für STR verwenden?

Eine feste, kleine Anzahl von Teilen mit `+` zusammenzufügen, ist klar und völlig in Ordnung:

```sather
   return piece + " by " + composer;
```

Das Problem entsteht nur in einer Schleife, in der beim Schreiben des Codes nicht bekannt ist, wie viele Verknüpfungen es werden. Eine grobe Faustregel: Wenn das `+` innerhalb einer `loop` steht, greif zu `FSTR`.

## Nützliche Routinen

| Aufruf | Bewirkt |
| --- | --- |
| `b + x` | hängt an; `x` kann `STR`, `CHAR`, `INT`, `BOOL` … sein |
| `b.size` | wie viele Zeichen bisher |
| `b.str` | ein fertiger `STR` |
| `b.clear` | leert es, der Platz bleibt erhalten |

## Escape-Sequenzen

| Geschrieben | Ist |
| --- | --- |
| `"\n"` | eine neue Zeile |
| `"\t"` | ein Tabulator |
| `"\""` | ein doppeltes Anführungszeichen |
| `"\\"` | ein Backslash |
