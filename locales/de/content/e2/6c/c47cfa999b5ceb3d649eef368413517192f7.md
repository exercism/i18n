# Über Bits

Binärziffern entsprechen letztlich direkt den Transistoren in deiner CPU oder deinem RAM und ob jeder von ihnen „an“ oder „aus“ ist.

Die Low-Level-Manipulation, informell auch „Bit-Twiddling“ genannt, ist besonders in Systemsprachen wichtig.

Höhere Programmiersprachen wie Kotlin blenden die meisten dieser Details normalerweise aus.
Allerdings steht eine grundlegende Auswahl an Bit-Operationen [zur Verfügung][ref-bitwise].

~~~~exercism/note
Um eine für Menschen lesbare Binärausgabe zu sehen, müssen fast alle Beispiele unten in eine Funktion [`Integer.toBinaryString()`][web-binstring] eingepackt oder mit `toString(radix = 2)` umgewandelt werden.
 
Das lenkt optisch ab, deshalb wurden die meisten Vorkommen dieser Funktion entfernt und die Ergebnisse mit der `0b`-Notation dargestellt.

## Bit-Shift-Operationen

Die Typen `Int` oder `Long`, sowohl vorzeichenbehaftet als auch vorzeichenlos, lassen sich als String aus Einsen und Nullen darstellen und als Folge von Bits manipulieren.

Vielleicht überraschend: Die Typen `Byte` und `Short` sind mit den meisten Bit-Operationen in Kotlin nicht kompatibel.
Alle Beispiele unten verwenden 32-Bit-Ganzzahlen (`Int` oder `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Bit-Verschiebungen bewegen alles um eine bestimmte Anzahl von Positionen nach links oder rechts.
Einige Bits fallen an einem Ende heraus, und das andere Ende wird mit Nullen oder Einsen aufgefüllt.

- Verschiebung nach links mit `shl`: Auffüllen mit Nullen.
- Verschiebung nach rechts mit `shr` oder `ushr`: Auffüllen mit Nullen bei positiven Zahlen (negative Zahlen siehe späteren Abschnitt).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Jede Verschiebung nach links verdoppelt den Wert, jede Verschiebung nach rechts halbiert ihn (mit Abschneidung).
In der Dezimaldarstellung ist das deutlicher:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Solche Bit-Verschiebungen sind viel schneller als „richtige“ Arithmetik, weshalb diese Technik beim Low-Level-Coding sehr beliebt ist.

### Bit-Verschiebung negativer Ganzzahlen

Bei _negativen Ganzzahlen_ müssen wir etwas vorsichtiger sein.

Negative Werte werden im [Zweierkomplement][wiki-2complement] gespeichert, das heißt, das am weitesten links stehende Bit ist 1.
Bei einer Verschiebung nach links ist das kein Problem, aber wie füllen wir bei einer Verschiebung nach rechts die am weitesten links stehenden Bits auf?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

Der Operator [`shr`][ref-shr] führt eine [arithmetische Verschiebung][wiki-arithmetic] durch und behält dabei das Vorzeichenbit bei.

Der Operator [`ushr`][ref-ushr] führt eine [logische Verschiebung][wiki-logical] durch und füllt mit Nullen auf, als wäre die Zahl vorzeichenlos.

## Bitweise Logik

Im [Konzept Boolesche Werte][concept-booleans] haben wir gesehen, dass die Operatoren `&&` (und), `||` (oder) und `!` (nicht) mit booleschen Werten verwendet werden.

Es gibt entsprechende Operatoren `and`, `or` und `xor` ([exklusives Oder][wiki-xor]), um die Bits zweier Ganzzahlen zu vergleichen, sowie eine Funktion `inv` (Inversion), um alle Bits umzukehren.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
