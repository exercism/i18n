# Nil

Crystal hat einen Typ namens [`Nil`][nil], der nur einen einzigen Wert haben kann: `nil`.
Er steht für das Fehlen eines Werts und ähnelt `null` oder `None` in anderen Sprachen.

Methoden können `nil` zurückgeben, zum Beispiel [`String#[]?`][string-index]. Diese Methode liefert `nil`, wenn der Index außerhalb des gültigen Bereichs liegt.

```crystal
"foo"[10]? # => nil
```

Crystal hat, was man **NULL-REFERENZPRÜFUNGEN** nennt. Das bedeutet, dass alle Typen standardmäßig nicht nil-fähig sind.
Du kannst einer Variable also kein `nil` zuweisen, es sei denn, du deklarierst sie ausdrücklich als Typ `Nil`.
Das wiederum bedeutet, dass der Compiler automatisch auf Null-Referenzen prüft.

## Falsey-Wert

Es gibt verschiedene Ansätze, um mit `nil`-Werten umzugehen.
`nil` ist ein [falsey][truthy-falsey]-Wert, genau wie `false`.
In Bedingungen und an anderen Stellen, an denen ein falsey- oder truthy-Wert erwartet wird, wird er also genauso behandelt wie `false`.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Das bedeutet, dass der truthy-Zweig nicht ausgeführt wird, wenn eine nil-fähige Variable den Wert `nil` hat.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Auf `nil` prüfen

Crystal hat eine Methode, mit der du prüfen kannst, ob ein Wert `nil` ist.
Sie heißt [`nil?`][nil?] und ist auf allen Objekten verfügbar.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Etwas anders ist es, wenn du den Wert direkt in einer if-Anweisung verwendest. In den letzten Beispielen würden sowohl `false` als auch `nil` als falsch gelten.
Hier wird nur `nil` als falsey behandelt. Wäre der Wert `false`, dann wäre er nicht `nil` gewesen und somit truthy.

## Der or-Operator

Der einfachste Weg, mit `nil`-Werten umzugehen, ist sicherzustellen, dass sie gar nicht erst `nil` werden.
Der or-Operator ([`||`][or]) wird oft im Umgang mit `Bools` verwendet, aber richtig verstanden hilft er auch bei `nil`-Werten.
Der or-Operator prüft, ob der erste Wert truthy ist. Wenn nicht, wird der zweite Wert verwendet.
Damit kannst du erreichen, dass der zweite Wert verwendet wird, wenn der erste `nil` und damit falsey ist.

```crystal
"foo"[10]? || "bar" # => "bar"
```
