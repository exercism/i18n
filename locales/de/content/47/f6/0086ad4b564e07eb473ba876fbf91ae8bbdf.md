# Einführung

Funktionen haben wir schon im Konzept [Grundlagen][concept-basics] kennengelernt, mit Beispielen wie diesem:

```R
squareit <- function(x) {
    x * x
}

squareit(3)
#> [1] 9

# shorter form
squareit_short <- function(x) x ^ 2
```

Wenn wir uns die Definition von `squareit` genauer ansehen, erkennen wir verschiedene Bestandteile:

- Die Funktion nimmt einen formalen Parameter `x` entgegen.
- Es gibt einen Funktionskörper, meist in geschweiften Klammern `{ }`.
- Sobald das Funktionsobjekt erstellt ist, wird es einer Variablen `squareit` zugewiesen.

In R ist eine Funktion ein erstklassiges Objekt, ganz ähnlich wie Zahlen und Strings.
Somit ist `squareit <- function...` eine Zuweisung, die syntaktisch genauso aussieht wie `x <- 42`.

## Argumente

R unterscheidet nicht klar zwischen Positionsargumenten und benannten Argumenten, anders als andere Skriptsprachen wie Python und Julia.

Bei einem Funktionsaufruf kannst du Werte entweder über die Position oder über den Namen übergeben.
Letzteres ist bei komplexen Funktionen mit vielen Argumenten nützlich, bei denen man sich die Reihenfolge nur schwer merken kann.

```R
f <- function(x, y) x / y

# call positionally
f(4, 2)
#> [1] 2

# call by name
f(y = 2, x = 4)
#> [1] 2
```

### Optionale Argumente

Standardwerte für Argumente lassen sich in der Funktionsdefinition angeben, sie müssen aber nach allen Argumenten ohne Standardwert stehen.

Wir können dann entscheiden, ob wir den Standardwert übernehmen oder überschreiben.

```R
g <- function(x, y = 2) x / y

# default y value
g(6)
#> [1] 3

# explicit y value
g(6, 3)
#> [1] 2
```

### Zusätzliche Argumente

Um eine beliebige Anzahl zusätzlicher Argumente entgegenzunehmen, verwendest du ein `...` (Ellipse) in der Definition.
Es ist möglich, alle zusätzlichen Werte im Funktionsaufruf in einen Vektor umzuwandeln, aber lies weiter, um eine andere Möglichkeit kennenzulernen, diese „dot args“ zu verwenden (*in einigen anderen Sprachen „varargs“ genannt*).

```R
var_f <- function(x, y, ...) {
  print(c(...))
}

var_f(2, 3, "opt1", "opt2")
#> [1] "opt1" "opt2"
```

## Funktionsumgebung

Vorhin haben wir gesagt, dass die formalen Parameter und der Funktionskörper beide Bestandteile einer Funktion sind.

Tatsächlich gibt es noch eine dritte Komponente: die *Umgebung*, in der die Funktion definiert wird.

Das lässt sich am Beispiel verschachtelter Funktionen zeigen:

```R
outer_func <- function(x) {
  inner_func <- function(y) {
    x * y
  }
  
  inner_func(3)
}

outer_func(5)
#> [1] 15
```

Der Funktionsaufruf übergibt `x = 5` an die äußere Funktion, und dieser Wert ist im Funktionskörper verfügbar.

Die innere Funktion ist *Teil* des Funktionskörpers der äußeren Funktion und hat Zugriff auf den Wert von `x`.
Anders ausgedrückt: `x = 5` liegt in der *Umgebung* der inneren Funktion.

Fachlich spricht man hier von einer [Closure][wiki-closure].

Die Umgebung ist bei dot args besonders wichtig, denn alle so übergebenen Werte lassen sich an Funktionsaufrufe im Funktionskörper weiterreichen.
Die äußere Funktion muss nicht wissen und sich nicht darum kümmern, was die dot args bedeuten.

```R
f_var <- function(x, ...) {
  sum(x, ...)
}

x <- c(1, 2, NA, 6)

# for sum(), na.rm defaults to FALSE
f_var(x)
#> [1] NA

# pass through the na.rm value
f_var(x, na.rm = TRUE)
#> [1] 9
```

Diese Technik nutzen Tidyverse-Bibliotheken wie [`stringr`][ref-stringr] ausgiebig.
Viele der `stringr`-Funktionen sind ein benutzerfreundlicher Wrapper um Low-Level-Funktionen aus `stringi` und Base R.

Zusätzliche Argumente, die an die `str_*()`-Funktionen übergeben werden, werden einfach an diese untergeordneten Funktionen weitergegeben.

## Funktionen als Rückgabewerte

Eine äußere Funktion kann eine innere Funktion definieren (entweder benannt oder anonym, wie weiter unten beschrieben) und sie als Rückgabewert verwenden.

Die zurückgegebene Funktion enthält die Umgebung, in der sie definiert wurde.

```R
times_y <- function(x) {
  # anonymous function - see next section
  \(y) x * y
}

f <- times_y(3)
class(f)
#> [1] "function"

f(4)
#> [1] 12
```

## Anonyme Funktionen

Wenn wir eine Funktion definieren, binden wir das entstehende Funktionsobjekt normalerweise an eine Variable:

```R
x <- 2

# function definition captures x from the environment
doubleit_short <- function(y) x * y
```

So lässt sich die Funktion später im Skript leicht verwenden, aber diese Bindung ist nicht nötig.
Eine kurze Funktion, die nur einmal verwendet wird, kann im unmittelbaren Zusammenhang nützlich sein.
Ohne Namensbindung nennt man sie eine *anonyme Funktion*.

Anonyme Funktionen werden so häufig verwendet, dass es (*seit R v4.1.0*) eine Kurzschreibweise gibt, um sie zu definieren: Ersetze das Wort `function` durch einen Backslash `\`.

Ein Beispiel dafür gab es im vorigen Abschnitt über Rückgabewerte.

## Kopieren beim Ändern

In R kannst du einzelnen Elementen eines Vektors Werte zuweisen.
Wenn wir einen Vektor als Argument an eine Funktion übergeben und ihn im Funktionskörper ändern, bevor wir ihn zurückgeben, erhalten wir einen geänderten Vektor.

Doch was ist mit dem ursprünglichen Vektor passiert?

```R
f <- function(vec) {
  vec[1] <- 42
  vec
}

vals <- c(1, 3, 4)

# f() returns a modified vector
f(vals)
#> [1] 42  3  4  

# the original vector is unchanged.
vals
#> [1] 1 3 4
```

R ist eine Sprache, die für Data Science entwickelt wurde.
Das Sammeln dieser Daten kann viel Zeit, Mühe und unter Umständen schwindelerregend viel Geld kosten: *Es ist wichtig, die Daten nicht zu verfälschen!*

Die allgemeine Regel (mit wenigen Ausnahmen) lautet *Kopieren beim Ändern*.
Wenn ein Objekt (etwa ein Vektor) so geändert wird, dass das später Probleme verursachen könnte, gibt R eine *geänderte Kopie* zurück und lässt das Original unangetastet.

Große Datenstrukturen zu kopieren kann rechenintensiv sein, aber das ist meist das kleinere Übel, wenn die Alternative eine Datenverfälschung ist.
