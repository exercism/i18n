# Einführung

Ein `Iterator` in Gleam ähnelt insofern einer Liste, als er eine geordnete Sammlung von Werten ist, bei der alle Werte denselben Typ haben. Er unterscheidet sich von einer Liste dadurch, dass er lazy ist: Er speichert nicht alle seine Werte auf einmal im Speicher, sondern berechnet sie erst, wenn sie gebraucht werden.

Das ist nützlich, wenn du mit Sequenzen arbeitest, die sehr groß oder sogar unendlich sind. So kannst du mit ihnen arbeiten, auch wenn der freie Speicher nicht ausreicht, um sie alle auf einmal zu speichern.

Das Modul `gleam/iterator` definiert den Typ `Iterator` sowie Funktionen für die Arbeit mit Iteratoren.

Viele der Funktionen für Listen gibt es auch für Iteratoren, zum Beispiel `map`, `filter` und `take`. Diese Funktionen geben Iteratoren zurück, das heißt, sie erledigen noch keine Arbeit, bis der Iterator konsumiert wird.

```gleam
let iter = 
  [1, 2, 3, 4, 5, 6]
  |> iterator.from_list
  |> iterator.filter(fn(x) { x > 2 })
  |> iterator.take(2)

// No work has been done yet as the iterator has not been consumed

// Consume the iterator and collect the values into a list
iterator.to_list(iter)
// -> [3, 4]
```

Die Funktion `unfold` kannst du verwenden, um Iteratoren aus einer Funktion zu erzeugen, die wiederholt aufgerufen wird, um den nächsten Wert der Sequenz zu liefern.

Hier wird die Funktion `unfold` verwendet, um einen Iterator zu erzeugen, der die Fibonacci-Folge produziert:

```gleam 
iterator.unfold(#(0, 1), fn(pair) {
  let x = pair.0 + pair.1
  iterator.Next(element: x, accumulator: #(pair.1, x))
})
|> iterator.take(6)
|> iterator.to_list
// -> [1, 2, 3, 5, 8, 13]
```

Die Sequenz ist hier unendlich, deshalb wird die Funktion `take` verwendet, um sie endlich zu machen, bevor die Werte in einer Liste gesammelt werden. Wenn `to_list` auf einen unendlichen Iterator angewendet wird, läuft das Programm so lange, bis ihm der Speicher ausgeht und es abstürzt.
