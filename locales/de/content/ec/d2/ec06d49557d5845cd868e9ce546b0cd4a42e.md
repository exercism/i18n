# Überblick

Factors I/O basiert auf einem einzigen [Protokoll][stream-protocol], das jede Datenquelle und jede Datensenke implementieren kann. Die mitgelieferten Streams (`<file-reader>`, `<file-writer>`, `<string-reader>`, `<string-writer>`, Netzwerk-Sockets, Byte-Arrays, TTYs) sind alle Klassen, die dieselbe Handvoll generischer Wörter aus [`io`][io] implementieren und `disposable` aus [`destructors`][destructors] erweitern.

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe` ist das Lesen in Stapeln auf niedriger Ebene: Es füllt einen vom Aufrufer bereitgestellten Puffer und gibt zurück, wie viele Elemente geschrieben wurden. Die öffentlichen `stream-read` und `stream-read-partial` bauen darauf auf und kümmern sich um die Speicherzuweisung. Die meisten selbst definierten Streams implementieren entweder `stream-read1` (wenn jeweils ein Element gelesen wird) oder `stream-read-unsafe` (wenn sich Lesevorgänge bündeln lassen).

`stream-element-type` gibt eines von zwei Singleton-Tokens zurück: `+byte+` für Byte-Streams (Dateileser, Sockets) und `+character+` für Zeichen-Streams (String-Reader, TTYs). Ein Wrapper-Stream delegiert meist einfach an den Stream, den er umschließt.

## Mixins einbinden

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

Eine Klasse kann das eine, das andere oder beides sein. Wenn du dem Mixin beitrittst, leiten die Standardmethoden von `input-stream` / `output-stream` an deine Klasse weiter, nach demselben Open-Mixin-Muster wie `set` aus dem Vokabular `sets`.

## Das Disposable-Framework

`new-disposable ( class -- disposable )` registriert eine neue Instanz im aktuellen Gültigkeitsbereich der Destructors, damit eine Ausnahme mitten im Aufbau von Ressourcen sauber abgewickelt wird:

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose` ist das öffentliche Wort; `dispose*` ist das generische Wort, das die Klasse implementiert. Eine Überschreibung von `dispose*` in einer Unterklasse sollte den eigenen Zustand aufräumen und danach alle Ressourcen freigeben, die sie besitzt:

```factor
M: my-stream dispose* underlying>> dispose ;
```

Das Framework garantiert, dass `dispose*` höchstens einmal pro Objekt ausgeführt wird. Wiederholte `dispose`-Aufrufe bewirken nichts.

## Zugriffswörter mit Gültigkeitsbereich

Drei Kombinatoren richten den globalen „aktuellen Eingabe- und Ausgabestream“ ein, den `print`, `read1` usw. verwenden:

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

Jeder von ihnen gibt die Ressource beim Verlassen wieder frei, selbst wenn die Quotation eine Ausnahme auslöst. So verwendet der meiste Code einen eigenen Stream, statt ihn durch jeden Aufruf hindurchzureichen.
