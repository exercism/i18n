# Anleitung

In dieser Übung definierst du die Syntax und das Ausführungsmodell für eine kleine Sprache, die von der `x86-64`-Assemblersprache inspiriert ist.

Das Ziel ist, zu formalisieren, wie Code in einer eingeschränkten Umgebung geschrieben, geparst und ausgeführt wird.

## Ausführungsmodell

Dein Assembler-Code wird in ein spezielles Konstrukt geschrieben:

```lean
let program := assemble!(
    -- assembly code here
)
```

Dieses Konstrukt muss ein **Programm** erzeugen, das eine Funktion simuliert, die den Assembler-Code ausführt und einen Wert zurückgibt.
Dieses Programm wird dann mit der folgenden Syntax aufgerufen, wobei `a`, `b`, `c` usw. Argumente sind:

```lean
let result := program(a, b, c, ...)
```

Alle Argumente und der Rückgabewert sind _vorzeichenbehaftete 64-Bit-Ganzzahlen_.
Es sind maximal _6 Argumente_ erlaubt.

## Register

Der Rückgabewert und alle Argumente werden in **Registern** übergeben.
Deine Sprache muss die folgenden Register unterstützen:

| Register | Rolle         |
|----------|---------------|
| `rdi`    | 1. Argument   |
| `rsi`    | 2. Argument   |
| `rdx`    | 3. Argument   |
| `rcx`    | 4. Argument   |
| `r8`     | 5. Argument   |
| `r9`     | 6. Argument   |
| `rax`    | Rückgabewert  |

Register starten mit dem Standardwert `0`, es sei denn, sie werden verwendet, um Argumente an die Funktion zu übergeben.

In dem folgenden Programm haben zum Beispiel alle Register den Wert `0`, mit Ausnahme von `rdi`, das mit `10` initialisiert wird, und `rsi`, das mit `-20` initialisiert wird:

```lean
program(10, -20)
```

Der Rückgabewert des Programms wird immer in `rax` gespeichert.

~~~~exercism/note
Bei Registernamen wird _nicht zwischen Groß- und Kleinschreibung unterschieden_.
Das bedeutet, dass `rax`, `RAX` und `rAx` alle dasselbe Register bezeichnen.
~~~~

## Assembler-Code

Jede Zeile im Assembler-Code kann eine von zwei Formen haben:

- **Labels** markieren bestimmte Stellen des Programms, die von einigen Anweisungen verwendet werden.
- **Anweisungen** stellen Operationen dar, die vom Programm ausgeführt werden.

Sofern keine Anweisung etwas anderes bewirkt, läuft der Ausführungsfluss des Programms linear ab.
Das bedeutet, dass eine vorherige Zeile vollständig ausgeführt wird, bevor die darauf folgende Zeile ausgeführt wird.

### Labels

Labels haben die folgende Syntax:

```lean
<label>:
```

Sie ändern den Wert keines Registers und haben keine andere Wirkung auf das Programm, als bestimmte Stellen des Codes zu markieren, damit sie von Anweisungen verwendet werden können.

~~~~exercism/note
Bei Labels wird _nicht zwischen Groß- und Kleinschreibung unterschieden_.
Das bedeutet, dass `Start`, `start` und `sTart` alle unterschiedliche Labels sind.
~~~~

### Anweisungen mit zwei Operanden

Die meisten Anweisungen haben die folgende Syntax:

```lean
<opcode> <destination>, <source>
```

Der `opcode` gibt die auszuführende Operation an und verwendet dabei die Werte der Operanden `destination` und `source`.
Das Ergebnis der Operation wird im Operanden `destination` gespeichert.

Die Anweisung `add` zum Beispiel addiert die Werte in den Operanden `destination` und `source` und speichert dieses Ergebnis im Operanden `destination`.

Der Operand `destination` ist _immer_ ein Register, während der Operand `source` ein Register oder eine Literalzahl sein kann.

Dies ist eine Liste der Anweisungen, die dein Programm unterstützen muss:

| Opcode | ausgeführte Operation                     |
|--------|-------------------------------------------|
| `mov`  | destination := source                 |
| `add`  | destination := destination + source   |
| `sub`  | destination := destination - source   |
| `mul`  | destination := destination * source   |
| `div`  | destination := destination / source   |
| `xor`  | destination := destination ^^^ source |
| `and`  | destination := destination &&& source |
| `or`   | destination := destination \|\|\| source |
| `shl`  | destination := destination <<< source |
| `shr`  | destination := destination >>> source |

Darüber hinaus muss dein Programm die `cmp`-Anweisung mit zwei Operanden unterstützen.

Diese Anweisung ändert kein Register, sondern vergleicht die Operanden `destination` und `source` und setzt einen internen Zustand des Programms auf eine von drei Möglichkeiten:

- _größer als_, wenn `destination` > `source`
- _gleich_, wenn `destination` == `source`
- _kleiner als_, wenn `destination` < `source`

Wie du diesen Zustand intern verfolgst, bleibt dir überlassen.

### Anweisungen mit einem Operanden

Es gibt einige Anweisungen, die den Ablauf des Programms ändern und die Ausführung an eine andere Stelle des Codes übertragen.
Sie werden _Sprunganweisungen_ genannt.

Sie alle nehmen nur einen Operanden, nämlich ein Label, das das Ziel des Sprungs angibt, also die Stelle im Code, an der die Ausführung fortgesetzt wird:

```lean
<opcode> <label>
```

Die `jmp`-Anweisung führt _immer_ den Sprung zum Ziel-Label aus.

Andere Sprunganweisungen führen den Sprung nur aus, wenn der interne Zustand des Programms auf einen bestimmten Wert gesetzt ist.
Das bedeutet, dass ihnen normalerweise eine `cmp`-Anweisung vorausgeht.

Dies sind die Sprunganweisungen, die dein Programm unterstützen muss:

| Anweisung | ausgeführte Operation                                |
|-------------|----------------------------------------------------|
| `jmp`       | unbedingter Sprung. Der Sprung wird immer ausgeführt |
| `je`        | springt, wenn der interne Zustand _gleich_ ist             |
| `jl`        | springt, wenn der interne Zustand _kleiner als_ ist         |
| `jg`        | springt, wenn der interne Zustand _größer als_ ist      |

~~~~exercism/note
Bei den Opcodes von Anweisungen, ob mit zwei Operanden oder mit einem, wird _nicht zwischen Groß- und Kleinschreibung unterschieden_.
Das bedeutet, dass `add`, `ADD` und `aDd` alle dieselbe Anweisung bezeichnen.
~~~~
