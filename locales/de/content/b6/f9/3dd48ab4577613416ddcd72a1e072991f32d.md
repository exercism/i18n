# Über

Zu diesem Zeitpunkt im Lehrplan hast du R schon oft als imperative Sprache erlebt und zunehmend als funktionale Sprache (besonders mit den Bibliotheken [`purrr`][ref-purrr] und [`dplyr`][ref-dplyr]).

Wenn ich nun behaupte, R sei in erster Linie objektorientiert, mag das auf Skepsis stoßen!

Seltsamerweise stimmt das.
Intern ist R mit Klassen, Vererbung, Polymorphismus und der für OOP-Programmierer typischen Einstellung umgesetzt.

Wer jedoch Java oder Ruby (ausdrücklich OOP) oder auch nur Python (in mancher Hinsicht halb verdeckt OOP) kennt, wird den Ansatz von R ... _ungewöhnlich_ finden.

Zunächst einmal gibt es mehrere Klassendesigns: etwa drei, die häufig verwendet werden (S3, S4, R6), dazu verschiedene andere von überwiegend theoretischem Interesse.

Eine ausführliche Diskussion findest du in [Advanced R, 2e][book-advanced-r], Kapitel 12-16.
Dieses Buch von 2019 richtet sich vor allem an Menschen, die das Innenleben von R verstehen und warten wollen, deshalb ist OOP dort unverzichtbar.

Lehrbücher, die sich stärker an Endnutzer richten, gehen damit unterschiedlich um.

- The Art of R Programming (2011, nur gedruckt) enthält ein OOP-Kapitel, das S3 und (kürzer) S4 behandelt, die damals wichtig waren.
  Der Kommentar, dass _"S3-Klassen eine eher zusammengeschusterte Struktur haben"_, ist immer noch verblüffend wahr.
- R in Action (3e, 2022) verbannt OOP auf 3 Seiten in einem Kapitel über fortgeschrittene Programmierung gegen Ende.
- [R for Data Science, 2e][book-r-data-sci] (2023, in der gedruckten Ausgabe 548 Seiten) erwähnt OOP überhaupt nicht.

Dieses Konzept konzentriert sich auf S3-Klassen, die einfachsten, gebräuchlichsten und für Exercism-Aufgaben am relevantesten.
Einige der Practice-Übungen im R-Track verlangen von dir, eine S3-Klasse zu erstellen; bei anderen ist das optional, aber durchaus nahegelegt.

## S3-Klassen

Sie sind alt: Der Name S3 bedeutet nur, dass sie in Version 3 der Sprache S eingeführt wurden (ein kommerzieller Vorläufer von R).

Eine S3-Klasse ist außerdem sehr einfach: typischerweise eine [Liste][concept-lists] mit mindestens einem zusätzlichen Attribut.

Aus [Advanced R][book-s3]: _"S3 ist informell und ad hoc, aber sein Minimalismus hat eine gewisse Eleganz: Man kann keinen Teil davon wegnehmen und hätte immer noch ein nützliches OO-System."_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

Eine Zuweisung an [`class(obj)`][ref-class] fügt `obj` also einfach ein Attribut hinzu, hier das, das pt2d als Instanz der Klasse point2d kennzeichnet.

Die Erstellungsschritte lassen sich mit [`structure()`][ref-structure] kombinieren:

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

Obwohl die so entstandenen Instanzen theoretisch identisch sind, haben wir noch keine Möglichkeit implementiert, mit der R das bestätigen könnte.

### Generische Methoden

Wer OOP aus anderen Sprachen kennt, fragt sich vielleicht: _"Sollen Klassen nicht in der Lage sein, Dinge zu TUN?"_

Wir können die Methoden prüfen, die für `point2d`-Instanzen verfügbar sind, und stellen fest, dass es (im Gegensatz zur zugrunde liegenden `list`) derzeit keine gibt.

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

In den meisten OOP-Sprachen werden Methoden innerhalb der Klassendefinition definiert.
Einige wenige Sprachen (vor allem Ruby) erlauben dir, Klassenmethoden später hinzuzufügen und zu ändern.

S3-Klassen sind ganz anders.
Statt Methoden zu einer Klasse hinzuzufügen, fügen wir die Klasse zu einer generischen Methode hinzu.

Wer interaktiv an der R-Konsole arbeitet, nutzt ständig generische Methoden, meist ohne darüber nachzudenken, wie sie umgesetzt sind.

Ein sehr häufiges Beispiel ist `print()`, auch wenn du den Funktionsnamen selten eintippst.
Wenn du einen Wert `x` allein an der Konsolenaufforderung eingibst, ist das nur syntaktischer Zucker für `print(x)`.

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

Wir können `pt2d` bereits ausgeben.
Obwohl `print()` nichts über die Klasse `point2d` weiß, hat sie sinnvolle Voreinstellungen, um eine Vielzahl von Objekten zu behandeln.

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

Das ist ziemlich umständlich, und wir hätten gern eine Möglichkeit, den Punkt knapp und übersichtlich auszugeben.

Ganz einfach: Füge einfach eine Funktion namens `print.point2d()` hinzu.
Der Name muss die Form `methodname.classname` haben, damit der Dispatcher weiß, wonach er suchen muss.

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

Nehmen wir nun an, wir wollen eine neue generische Methode erstellen, zum Beispiel `flipvert()`, um das Vorzeichen der `y`-Koordinate umzukehren.

Wieder ganz einfach:

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

Das erstellt einen Dispatcher, wobei `x` unser Objekt mit einer S3-Klasse ist und `...` alle zusätzlichen Argumente verarbeitet, die Methodendefinitionen brauchen könnten („dot args“, wie im [Funktionen-Konzept][concept-functions] beschrieben).

Wir können dann die Methode für `point2d` definieren und sie verwenden.

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

R weiß jetzt, wie es unseren Punkt umkehrt und wie es das Ergebnis anzeigt.

Wir könnten das erweitern, indem wir Klassen für 3D, für Polarkoordinaten usw. erstellen und dann für jede Methoden definieren.

Aus Sicht der Endnutzer gibt es nur `flipvert(x, ...)`, und wir können uns darauf verlassen, dass R die Eingabeklasse bestimmt und die passende zugrunde liegende Implementierung verwendet.

~~~~exercism/caution
Funktionsnamen im Format `verb.class` sehen sowohl für Nutzer als auch für den R-Parser wie S3-Methoden aus.
Bitte vermeide eine ähnliche Namensgebung in anderen Zusammenhängen.

Zugegeben, das Basis-R verstößt manchmal gegen diese Regel.
Wir sollten das als einen unglücklichen historischen Unfall betrachten (für Funktionen, die noch älter sind als S3), der aus Gründen der Abwärtskompatibilität erhalten bleiben muss.
~~~~

### Vererbung

OOP-Begeisterte können mehrere lange Lehrbuchkapitel über Vererbung, Unterklassenbildung, Mixins und alles Weitere schreiben.

R lässt dich einfach mehrere Namen für das `class`-Attribut angeben: einen längeren Vektor von Strings statt eines einzelnen Strings.

Auf die Gefahr hin, das Beispiel bis zum Zerreißen zu strapazieren: Angenommen, wir hätten eine generische Klasse `point` erstellt und wollten davon `point2d`, `point3d` usw. ableiten.

Dann verwendet die Definition von `point2d` einfach `class = c("point2d", "point")`: die spezifische Klasse und die übergeordnete Klasse (oder Klassen).

Generische Methoden wie `print()` suchen dann der Reihe nach nach `print.point2d()`, `print.point()` und (wahrscheinlich) `print.default()` und verwenden die erste Implementierung, die der Dispatcher findet.

### Sicherheit

Viele OOP-Sprachen (Java, C# usw.) nutzen die Datenkapselung innerhalb von Klassen, um sorgfältige Prüfungen zur Kompilierzeit durchzuführen und die Typsicherheit durchzusetzen.

Sei dir bewusst, dass S3 dir so ziemlich alles erlaubt, selbst wenn es keinen Sinn ergibt (eine Fehlermeldung kommt erst später, wenn überhaupt).

Aus [„Advanced R“][book-s3] (2e, Abschnitt 13.3):

> _Wenn du andere OO-Sprachen verwendet hast, mag dir das mulmig werden, aber in der Praxis verursacht diese Flexibilität nur wenige Probleme. R hindert dich nicht daran, dir selbst in den Fuß zu schießen, aber solange du die Waffe nicht auf deine Zehen richtest und abdrückst, hast du kein Problem._

Nun ja, _okay?_
R ist hervorragend für explorative Datenwissenschaft und Statistik geeignet, oft bei interaktiver Arbeit.
Niemand behauptet, du solltest damit hochsichere Unternehmensfinanzsysteme schreiben!
