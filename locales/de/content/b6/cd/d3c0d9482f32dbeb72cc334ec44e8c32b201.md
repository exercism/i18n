# Factor installieren

Der Factor-Track verwendet **Factor 0.101**. Ältere Versionen werden nicht unterstützt.

Du kannst eine [stabile Version](#stable) oder eine [Nightly-Version](#nightly) installieren, oder Factor [aus dem Quellcode bauen](#build-from-source).

Überprüfe deine Installation mit `factor -e='vm-version print'`. Die Ausgabe sollte `0.101` oder höher sein.

---
### Stabile Version

<https://factorcode.org#stable-release> stellt im Abschnitt „Stable release“ stabile Binärdateien bereit.

---
### Nightly-Version

<https://factorcode.org#development-release> stellt im Abschnitt „Development release“ Nightly-Binärdateien bereit. Diese Binärdateien werden aus git gebaut, aber es werden nur erfolgreiche Builds angezeigt.

---
### Aus dem Quellcode bauen

Wenn du ganz vorne mit dabei sein willst und dir selbst Nightly zu alt ist, brauchst du einen modernen C++-Compiler (GCC >=4.8 oder Clang >=3.5), `make` und `curl`.

Wenn diese einfachen Voraussetzungen erfüllt sind, kannst du loslegen:

1. Lade das `build`-Shellskript herunter: [**hier** für Unix-artige Systeme / POSIX-Shells](https://raw.githubusercontent.com/factor/factor/master/build.sh) oder [**hier** für Windows](https://raw.githubusercontent.com/factor/factor/master/build.cmd). Lege es in das Verzeichnis, unter dem Factor installiert werden soll. Es wird ein Verzeichnis namens `factor` mit dem Quellcode angelegt.

2. Führe es mit `./build.sh install` aus, unter Windows mit `.\build.cmd install`. <sub>Dabei wird Factors `git`-Repository geklont, es wird gebaut und ein Factor-VM-Image von <https://factorcode.org> heruntergeladen. Dieser Vorgang kann zwischen 2 und 20 Minuten dauern, je nach deiner Verbindungs- und Prozessorgeschwindigkeit.</sub>

3. Jetzt kannst du die Binärdatei `factor` bzw. `factor.exe` ausführen, die im Unterverzeichnis `factor` erzeugt wurde. Probiere `factor --help` für Hilfe aus. Du kannst die Dokumentation auch von der Kommandozeile aus aufrufen oder <kbd>F1</kbd> im GUI Listener drücken, wodurch der Hilfe-Browser geöffnet wird.

4. Verwende künftig `build.sh` (unter Windows `build.cmd`) im Unterverzeichnis `factor`, um von git zu pullen und direkt vor Ort neu zu bauen und bei Bedarf ein neues VM-Image herunterzuladen.

Die Dateistruktur kann jetzt so aussehen:

```
.
├── build.sh                   <- delete if you like
└── factor
    ├── basis
    ├── boot.unix-x86.64.image
    ├── build.cmd              <- use these from now on
    ├── build.sh               <-
    ├── core
    ├── extra
    ├── factor
    ├── Factor.app
    ├── factor.image
    ├── GNUmakefile
    ├── libfactor.a
    ├── libfactor-ffi-test.so
    ├── LICENSE.txt
    ├── misc
    ├── Nmakefile
    ├── README.md
    ├── unmaintained
    ├── vm
    └── work
```

Das `build`-Skript auf oberster Ebene brauchst du nicht mehr, denn künftig soll das heruntergeladene verwendet werden.

---

### Manuell aus dem Quellcode bauen (nicht empfohlen)

Klone das [Repository](https://github.com/factor/factor) und verwende `make` in diesem Ordner.

Wenn `make` mit einem Fehler über ein nicht vorhandenes Ziel fehlschlägt, versuche `make factor`, oder suche, wenn du ein Makefile lesen kannst, das Make-Ziel für deine Plattform in `GNUmakefile`.

Wenn *das* fehlschlägt, eröffne ein Issue auf [factor/factor](https://github.com/factor/factor) mit der Fehlermeldung. Die freundlichen Entwickler helfen dir gerne.
