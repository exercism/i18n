# Über

## Zeichen

Eine [Zeichenkodierung][char-encoding] ist eine bestimmte Konvention, mit der Elemente eines Textes in einer natürlichen Sprache als Folge von Bytes dargestellt werden.
Ein „Element eines Textes“ kann hier jede Einheit sein, die in einer natürlichen Sprache eine Bedeutung hat, zum Beispiel Buchstaben, Leerzeichen, Satzzeichen, Emojis, Ideogramme usw.

NASM (The Netwide Assembler, der Assembler, den dieser Track verwendet) unterstützt die Definition von Daten mit [ASCII][ascii].

Zeichenkonstanten in NASM dürfen bis zu 8 Bytes lang sein und können mit einfachen Anführungszeichen (`'`), doppelten Anführungszeichen (`"`) oder Backticks (`` ` ``) definiert werden:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Sonderzeichen müssen in Backticks definiert und mit `\` escaped werden:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASM unterstützt außerdem [Unicode-Zeichen][unicode] in [UTF-8][utf8], die mit `\u` oder `\U` und in Backticks angegeben werden:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

Beachte, dass x86-64 keine eingebaute Unterstützung für eine Zeichenkodierung als eigenständigen Typ bietet.
Daten sind in Assembler eine Folge von Bytes, und wie diese Bytes interpretiert werden, als Zeichen, als Zahl oder als etwas anderes, bleibt dem Programmierer überlassen.

Das ASCII-Zeichen '0' ist zum Beispiel ein einzelnes Byte mit dem Wert 48.
Eine 48 in ein Byte zu speichern ist also genau dasselbe, wie das ASCII-Zeichen '0' zu speichern:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Aus demselben Grund bearbeitest du Zeichen, indem du die Werte in diesen Bytes direkt veränderst:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Zeichenketten

Eine [Zeichenkette][string] ist eine Folge von Zeichen.
In Assembler wird sie üblicherweise als Array umgesetzt.

In NASM kannst du eine Zeichenkette genauso deklarieren wie ein beliebiges Array:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Ein Unterschied zwischen Zeichenketten und anderen Arrays ist, dass NASM Zeichenketten auch ohne Komma (`,`) zwischen den Werten deklarieren kann.
Es ist auch möglich, Werte mit Kommas zu mischen:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Beachte, dass Zeichen, wie bereits erwähnt, einfach Bytes sind (oder eine Folge von Bytes in einer Unicode-Kodierung):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Da jedes ASCII-Zeichen ein einzelnes Byte belegt, ist jedes folgende Byte in einer größeren Breite `0`.
Wenn du `'a'` zum Beispiel als qword (8 Bytes) deklarierst, ist das erste Byte `'a'` (`97`) und die übrigen sieben Bytes sind alle `0`.

Aus diesem Grund sind alle folgenden Varianten gleichwertig:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
In Assembler werden Zeichenketten nicht automatisch durch ein ASCII-NUL-Zeichen (Wert `0`) beendet.

Bei der Zusammenarbeit mit höheren Programmiersprachen wie C liegt es in der Verantwortung des Programmierers, dafür zu sorgen, dass am Ende einer Zeichenkette das richtige Abschlusszeichen steht, falls eines nötig ist.
~~~~

## Zeichenketten-Anweisungen

Da Zeichenketten Arrays sind, kannst du mit ihnen genauso arbeiten wie mit jedem anderen Array, indem du den Speicher explizit dereferenzierst:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Darüber hinaus gibt es einige Anweisungen zum Laden, Verschieben und Speichern von Werten in Bytefolgen im Speicher.
Obwohl sie _Zeichenketten-Anweisungen_ heißen, kannst du sie mit jeder Bytefolge im Speicher verwenden, also mit jedem Array:

| Anweisung    | was sie macht                                                                                                                 |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | lädt einen Wert von der Speicherstelle, auf die `rsi` zeigt, nach `rax`                                                       |
| [stos][stos] | speichert einen Wert aus `rax` in der Speicherstelle, auf die `rdi` zeigt                                                     |
| [movs][movs] | kopiert einen Wert von der Speicherstelle, auf die `rsi` zeigt, und speichert ihn in der Speicherstelle, auf die `rdi` zeigt  |
| [cmps][cmps] | vergleicht den Wert in der Speicherstelle, auf die `rsi` zeigt, mit dem Wert in der Speicherstelle, auf die `rdi` zeigt       |
| [scas][scas] | vergleicht den Wert in `rax` mit dem Wert in der Speicherstelle, auf die `rdi` zeigt                                          |

Beachte, dass diese Anweisungen _keinen_ expliziten Operanden haben.
Ihre Operanden sind implizit.

Als Faustregel gilt:

1. Wenn ihr Quelloperand eine Speicherstelle ist, sollte deren Adresse in `rsi` stehen (`s` wie in source).
2. Wenn ihr Zieloperand eine Speicherstelle ist, sollte deren Adresse stattdessen in `rdi` stehen (`d` wie in destination).
3. Wenn einer der Operanden keine Speicherstelle ist, handelt es sich um das Register `rax`.

Beachte, dass diese Anweisungen Speicheradressen je nach der jeweiligen Operation automatisch dereferenzieren.

Alle von ihnen können mit unterschiedlichen Größen arbeiten.
Ein Suffix gibt diese Größe an:

| Suffix | Bedeutung | Größe   |
| :----: | --------- | :------ |
|  `b`   | Byte      | 1 Byte  |
|  `w`   | Wort      | 2 Bytes |
|  `d`   | Dword     | 4 Bytes |
|  `q`   | Qword     | 8 Bytes |

Zum Beispiel:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

Sie aktualisieren außerdem jede verwendete Adresse um die Größe der Operation.
Diese Aktualisierung richtet sich nach dem Wert des **Direction Flag (DF)**:

- Wenn das `DF` gelöscht ist, werden Adressen um die Größe der Operation _erhöht_.
- Wenn das `DF` gesetzt ist, werden Adressen stattdessen um denselben Betrag _verringert_.

Die System-V-ABI schreibt vor, dass das Direction Flag beim Eintritt in eine Funktion gelöscht sein muss.
_Standardmäßig wird der Speicher also in aufsteigender Adressreihenfolge gelesen und beschrieben._

Mit der Anweisung [cld][cld] kannst du das Direction Flag löschen, mit der Anweisung [std][std] setzen:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Der Aufrufer erwartet laut System V ABI, dass das `DF` nach der Rückkehr einer aufgerufenen Funktion gelöscht ist.
Wenn du das `DF` jemals setzt, stelle sicher, dass du es vor `ret` wieder löschst.
~~~~

### Lods

Diese Anweisung _liest_ von einer Speicherstelle, deren Adresse in `rsi` steht, und kopiert den Wert nach `rax`.

Der Wert in `rsi` wird um die Anzahl der gelesenen Bytes aktualisiert:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

Diese Anweisung kopiert den Wert in `rax` und _schreibt_ ihn in eine Speicherstelle, deren Adresse in `rdi` steht.

Der Wert in `rdi` wird um die Anzahl der geschriebenen Bytes aktualisiert:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

Diese Anweisung _liest_ von einer Speicherstelle, deren Adresse in `rsi` steht, und _schreibt_ den Wert in eine Speicherstelle, deren Adresse in `rdi` steht.
Der Wert in `rax` wird von dieser Anweisung nicht verändert.

Sowohl `rsi` als auch `rdi` werden um die Anzahl der von einer Speicherstelle zur anderen kopierten Bytes aktualisiert:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

Diese Anweisung _liest_ von einer Speicherstelle, deren Adresse in `rsi` steht, und _liest_ außerdem von einer Speicherstelle, deren Adresse in `rdi` steht.
Danach vergleicht sie die Werte und aktualisiert die Flags, wie bei `cmp`.

Sowohl `rsi` als auch `rdi` werden um die Anzahl der von beiden Speicherstellen gelesenen Bytes aktualisiert:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

Diese Anweisung vergleicht den Wert in `rax` mit dem Wert, den sie von einer Speicherstelle _liest_, deren Adresse in `rdi` steht.
Danach aktualisiert sie die Flags, wie bei `cmp`.

Der Wert in `rdi` wird um die Anzahl der gelesenen Bytes aktualisiert:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

Abgesehen davon greift die Anweisung [rep][rep] nicht direkt auf den Speicher zu.
Stattdessen kannst du sie als Präfix vor die anderen genannten Anweisungen setzen und _wiederholst_ damit diese Anweisungen.

Mit dem Präfix `rep` werden Zeichenketten-Anweisungen so oft wiederholt, wie der Wert in `rcx` angibt.
Dabei wird der Wert in `rcx` jedes Mal um `1` verringert.
Beachte, dass du den Wert in `rcx` setzen musst, bevor du die Anweisung verwendest:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

Neben der Verwendung von `rcx` als Zähler brechen `repe` (oder `repz`) und `repne` (oder `repnz`) die Ausführung ab, wenn das `zero flag (ZF)` gelöscht bzw. gesetzt ist:

| Anweisung        | wo kann sie stehen     | kann früher abbrechen   |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`, `lods`, `stos` | nein                    |
| `repe`,`repz`    | `cmps`, `scas`         | ja, bricht ab, wenn ZF 0 ist |
| `repne`, `repnz` | `cmps`, `scas`         | ja, bricht ab, wenn ZF 1 ist |

~~~~exercism/advanced
Auf modernen CPUs sind `rep movs` und `rep stos` meist schnelle Optionen, wenn du Daten in großen Blöcken verschiebst.
Andere Zeichenketten-Anweisungen und selbst `movs` und `stos` ohne `rep` sind dagegen meist langsamer als eine einfache Schleife.
