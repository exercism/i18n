# Überblick

Seit Go 1.18 unterstützt Go **Generics**.
Mit Generics kannst du Funktionen und Datenstrukturen schreiben, die mit verschiedenen Typen arbeiten, ohne Code zu duplizieren.

## Warum Generics?

In Go arbeiten Funktionen und Typen normalerweise mit ganz bestimmten Typen wie `int` oder `string`.
Bevor es Generics gab, hattest du zwei Möglichkeiten, mehrere Typen zu unterstützen.
Erstens konntest du mehrere Funktionen mit unterschiedlichen Namen schreiben, etwa `SumInts` und `SumFloats`.
Dieser Ansatz erzeugt doppelten Code, der schwer zu pflegen ist.
Zweitens konntest du das leere Interface `any` (`interface{}`) verwenden.
Das leere Interface schaltet jedoch die Typprüfung zur Kompilierzeit ab und erfordert zur Laufzeit Typzusicherungen.
Generics lösen dieses Problem: Sie geben dir Typsicherheit und vermeiden gleichzeitig doppelten Code.

## Generische Funktionen

Du definierst eine generische Funktion, indem du **Typparameter** in eckigen Klammern `[...]` hinter den Funktionsnamen setzt.
Hier ist ein Beispiel für eine generische Funktion, die einen umgekehrten Slice zurückgibt:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

In diesem Beispiel ist `T` ein Typparameter.
Du kannst dir `T` als Platzhalter für einen echten Typ vorstellen.
Das Schlüsselwort `any` in den eckigen Klammern ist eine **Typbeschränkung**.
Die Beschränkung sagt dem Compiler, welche Typen für `T` erlaubt sind.
Hier bedeutet `any`, dass `T` jeder Typ sein kann.

### Generische Funktionen aufrufen

Du rufst eine generische Funktion auf, indem du den konkreten Typ in eckigen Klammern übergibst.
Dieser konkrete Typ heißt **Typargument**.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

In den meisten Fällen erkennt der Go-Compiler den Typ automatisch an den Funktionsargumenten.
Dieses Verfahren heißt **Typinferenz**.
Mit Typinferenz musst du das Typargument nicht in eckigen Klammern angeben.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

In diesem Beispiel sieht der Compiler, dass `words` ein Slice von Strings ist, und schließt daraus, dass `T` gleich `string` ist.

## Typbeschränkungen

Jeder Typparameter muss eine Typbeschränkung haben.
Eine Typbeschränkung legt fest, welche Typen du als Typargumente verwenden kannst.
Sie bestimmt außerdem, welche Operationen du auf Werten dieses Typs ausführen darfst.

### Die Typbeschränkung `any`

Die Typbeschränkung `any` erlaubt jeden Typ.
In Go ist `any` ein Alias für das leere Interface `interface{}`.
Da `any` jeden Typ erlaubt, kann die Funktion nur Operationen ausführen, die für alle Go-Typen funktionieren.
Wenn du zum Beispiel zwei `any`-Werte hast, die Slices enthalten, lassen sie sich nicht mit `==` vergleichen, denn Slices können nicht mit `==` verglichen werden.

### Die Typbeschränkung `comparable`

Go bringt eine eingebaute Typbeschränkung namens `comparable` mit.
Die Typbeschränkung `comparable` erlaubt jeden Typ, der die Operatoren `==` und `!=` unterstützt.
Vergleichbare Typen sind unter anderem boolesche Werte, Zahlen, Strings, Pointer, Channels sowie Structs oder Arrays, die aus vergleichbaren Typen bestehen.

Hier ist ein Beispiel für eine Funktion, die prüft, ob ein Slice ein bestimmtes Element enthält:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Weil `T` die Typbeschränkung `comparable` verwendet, ist `elem == target` gültig.
Ersetzt du `comparable` durch `any`, meldet der Compiler einen Fehler.

### Eigene Typbeschränkungen mit Typmengen in Interfaces

Seit Go 1.18 können Interfaces neben Methoden auch Typmengen definieren.
Mit dem Pipe-Zeichen `|` listest du die erlaubten Typen in einem Interface auf.

```go
type Number interface {
    int | int64 | float64
}
```

Jetzt kannst du `Number` als Typbeschränkung für eine Funktion verwenden:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Da alle Typen in `Number` den Operator `*` unterstützen, erlaubt Go `value * 2` innerhalb der Funktion.

### Die Näherung des zugrunde liegenden Typs `~`

Manchmal legst du einen eigenen Typ auf Basis eines primitiven Typs an:

```go
type MyInt int
```

Die oben definierte Typbeschränkung `Number` erlaubt nur die exakten Typen `int`, `int64` und `float64`.
Wenn du einen `MyInt`-Wert an `Double` übergibst, erzeugt der Compiler einen Fehler, weil `MyInt` nicht zu `int` passt.
Um jeden Typ zuzulassen, dessen zugrunde liegender Typ `int` ist, setzt du eine Tilde `~` vor den Typ:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

Jetzt kannst du `Double` mit Werten vom Typ `MyInt` verwenden.

### Die Typbeschränkung `cmp.Ordered`

Die Standardbibliothek stellt im [`cmp`-Paket][doc-cmp] die Typbeschränkung `cmp.Ordered` bereit.
Die Typbeschränkung `cmp.Ordered` erlaubt jeden Typ, der die Vergleichsoperatoren `<`, `<=`, `>` und `>=` unterstützt.

## Generische Typen

Du kannst Typparameter auch verwenden, um generische Typen zu definieren, zum Beispiel Structs.
Hier ist ein Beispiel für eine generische Datenstruktur `Stack`:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Wenn du eine Variable eines generischen Typs deklarierst, musst du das Typargument in eckigen Klammern angeben:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

Typinferenz funktioniert nur bei generischen Funktionen.
Beim Erzeugen von Werten eines generischen Typs musst du das Typargument immer angeben.

## Wann du Generics einsetzen solltest

Generics sind mächtig, aber du musst sie nicht für jedes Problem einsetzen.

Setz Generics in diesen Situationen ein:
- Du baust Datenstrukturen wie Bäume, verkettete Listen oder Caches, die mit jedem Elementtyp funktionieren.
- Du schreibst Hilfsfunktionen, die auf Slices oder Maps beliebiger Typen arbeiten, etwa Filtern, Sortieren oder Suchen.
- Du brauchst für mehrere Typen exakt dieselbe Implementierung und möchtest Typsicherheit zur Kompilierzeit.

Verwende stattdessen Interfaces in diesen Situationen:
- Dir geht es um Verhalten und Methoden, nicht um den zugrunde liegenden Datentyp.
  Wenn du zum Beispiel Daten aus Quellen verschiedener Typen (Dateien, Netzwerk, TTY) lesen und verarbeiten willst, nimmst du `func Process(src io.Reader)` statt `func Process[T](src T)`.
- Verschiedene Typen brauchen unterschiedliche Methodenimplementierungen, um ihre Arbeit zu erledigen.
