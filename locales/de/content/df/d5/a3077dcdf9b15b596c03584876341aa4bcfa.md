# Einführung

Fast jedes Factor-Programm ist eine Abfolge von Wörtern, die Werte auf dem *Datenstack* verbrauchen und erzeugen. Wenn Eingaben und Ausgaben sauber zusammenpassen, liest sich der Code ohne Umstände von links nach rechts. Wenn nicht, greifst du zu *Shuffle-Wörtern*, und der Code wird schnell unübersichtlich.

Diese Übung führt dich durch die Standardlösung von Factor: Kombinatoren.

## Shuffle-Wörter

Die gebräuchlichsten Shuffle-Wörter findest du in [`kernel`][kernel]:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

`dup` und `swap` hast du sicher schon benutzt. `over` erzeugt eine Kopie des *zweiten* Elements von oben. Das ist praktisch, wenn dieselbe Eingabe zwei Berechnungen speisen soll:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

Für einen einzelnen Einsatz ist das in Ordnung. Doch aneinandergereiht werden Folgen aus `dup`, `swap`, `over` und `rot` schnell unlesbar.

## `keep` – den Eingabewert erhalten

`keep` (aus [`kernel`][kernel]) ruft eine Quotation für das oberste Stack-Element auf, lässt aber den ursprünglichen Wert über dem Ergebnis liegen:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

Das ersetzt das Muster aus `dup`, irgendetwas und anschließendem Shuffle: Überall, wo du `dup something swap` schreiben würdest, kannst du einfach `[ something ] keep` sagen.

## `bi` – zwei Funktionen für eine Eingabe

`bi` (aus [`kernel`][kernel]) wendet *zwei* Quotations auf denselben Wert an und lässt beide Ergebnisse auf dem Stack:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

Ohne `bi` würdest du `dup sq swap neg` schreiben. Für zwei Operationen noch gut lesbar, für drei wird es übel.

## `tri` und `cleave` – viele Funktionen für eine Eingabe

`tri` erweitert `bi` auf drei Quotations:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

`cleave` (aus [`combinators`][combinators]) ist dieselbe Idee für ein *Array* beliebig vieler Quotations:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

Die leere Quotation `[ ]` wirkt als Identität. Das ist nützlich, wenn einer der Plätze in der Kartenauslage die Eingabe selbst sein soll.

## `dip` und `2dip` – darunter arbeiten

`dip` (aus [`kernel`][kernel]) ruft eine Quotation für die Werte *unter* dem obersten Stack-Element auf und lässt das oberste unangetastet. `2dip` macht dasselbe, schützt aber die obersten *zwei* Werte:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

Hier hat `dip` die `11` verdeckt, `9 10 +` ausgeführt und die `11` wieder nach oben gelegt. `2dip` hat `11 12` verdeckt, darunter `9 10 +` ausgeführt und dann `11 12` wiederhergestellt.

`dip` ist das richtige Werkzeug, wenn die natürliche Argumentreihenfolge den „durchgereichten“ Wert oben auf dem Stack lässt. Greif dazu statt zum `swap … swap`-Sandwich.

## `bi@` – dieselbe Operation für zwei Werte

`bi@` (aus [`kernel`][kernel]) wendet eine Quotation auf zwei Stack-Werte an:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*` – verschiedene Operationen für zwei Werte

`bi*` (aus [`kernel`][kernel]) wendet *verschiedene* Quotations auf die zwei Stack-Werte an. Die erste Quotation bekommt den unteren Wert, die zweite den oberen:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

Nimm `bi@`, wenn beide Werte gleich behandelt werden, und `bi*`, wenn jeder seine eigene Behandlung braucht.

## `tri*` – verschiedene Operationen für drei Werte

`tri*` (aus [`combinators`][combinators]) erweitert `bi*` auf drei Werte und drei Quotations und wendet jede Quotation der Reihe nach auf einen Wert an:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
