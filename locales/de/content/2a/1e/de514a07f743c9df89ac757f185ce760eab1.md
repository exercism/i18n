# Über

Ressourcen, die OS-Status halten (Datei-Handles, Sockets, Locks), brauchen ein *garantiertes* Aufräumen, auch wenn eine Ausnahme den Stack abwickelt. Das [`destructors`][destructors]-Vokabular von Factor bietet dafür ein kleines Framework, und die meisten eingebauten Ressourcen (`<file-reader>`, `<file-writer>`, Sockets, …) sind bereits damit kompatibel.

## Die Klasse und das generische Wort

Eine Klasse macht mit, indem sie `disposable` erweitert und `dispose*` implementiert:

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )` allokiert das Tupel *und* registriert es beim aktuellen Destruktor-Gültigkeitsbereich, sodass eine Ausnahme zwischen der Allokation und dem nächsten sicheren Punkt nicht dazu führt, dass die Ressource verloren geht. Das Framework garantiert, dass `dispose*` **höchstens einmal** pro Objekt ausgeführt wird, wiederholte `dispose`-Aufrufe sind wirkungslos.

## Öffentliche Aufrufer verwenden `dispose`

| word              | effect                                        |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )`: gibt frei; kann gefahrlos zweimal aufgerufen werden    |
| `with-disposal`   | `( disposable quot -- )`: umschließt eine Ressource |
| `with-destructors`| `( quot -- )`: öffnet einen Registry-Gültigkeitsbereich |
| `&dispose`        | `( obj -- obj )`: gibt frei bei normalem *oder* fehlerhaftem Verlassen |
| `|dispose`        | `( obj -- obj )`: gibt nur frei, wenn der Gültigkeitsbereich abgewickelt wird |

`with-disposal` ist die Einzelressourcen-Form. Für mehr als eine Ressource öffnest du einen `with-destructors`-Gültigkeitsbereich und registrierst jeden Erwerb mit `&dispose` (du willst ihn immer freigeben) oder `|dispose` (nur bei Fehler freigeben, der Erfolgspfad behält ihn).

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup` ist die bloße Primitive

Für ein einmaliges try/finally ohne Registry ist [`cleanup`][cleanup] (aus `continuations`) das Wort auf niedrigerer Ebene:

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` ist strikt mächtiger (die Registry kann zur Laufzeit wachsen), aber `cleanup` ist die natürliche Wahl, wenn die Paarung von Erwerb und Freigabe fest und lokal ist.
