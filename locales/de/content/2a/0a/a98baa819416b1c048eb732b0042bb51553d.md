# Einführung

## Vergleiche

Python unterstützt die folgenden grundlegenden Vergleichsoperatoren:

| Operator | Operation                  | Beschreibung                                                              |
| -------- | -------------------------- | ------------------------------------------------------------------------- |
| `>`      | „größer als"               | `a > b` ist `True`, wenn `a` **strikt** größer als `b` ist                |
| `<`      | „kleiner als"              | `a < b` ist `True`, wenn `a` **strikt** kleiner als `b` ist               |
| `==`     | „gleich"                   | `a == b` ist `True`, wenn `a` **strikt** gleich `b` ist                   |
| `>=`     | „größer oder gleich"       | `a >= b` ist `True`, wenn `a > b` ODER `a == b` gilt                      |
| `<=`     | „kleiner oder gleich"      | `a <= b` ist `True`, wenn `a < b` oder `a == b` gilt                      |
| `!=`     | „ungleich"                 | `a != b` ist `True`, wenn `a == b` `False` ist                            |
| `is`     | „Identität"                | `a is b` ist `True`, wenn **_und nur wenn_** `a` und `b` dasselbe _Objekt_ sind |
| `is not` | „negierte Identität"       | `a is not b` ist `True`, wenn `a` und `b` **nicht** dasselbe _Objekt_ sind |
| `in`     | „Mitgliedschaftstest"      | `a in b` ist `True`, wenn `a` Mitglied, Teilmenge oder Element von `b` ist |
| `not in` | „negierter Mitgliedschaftstest" | `a not in b` ist `True`, wenn `a` kein Mitglied, keine Teilmenge und kein Element von `b` ist |

Sie alle haben dieselbe Priorität (_die höher ist als die von [booleschen Operationen][boolean operations], aber niedriger als die von arithmetischen oder bitweisen Operationen_).

## Vergleich zwischen verschiedenen Datentypen

Objekte unterschiedlichen Typs (_außer numerischen Typen_) sind standardmäßig nie gleich.
Auch nicht identische Instanzen einer `class` gelten _**nicht**_ als gleich, es sei denn, die `class` definiert spezielle [Rich-Comparison-Methoden][rich comparisons], die das Standardvergleichsverhalten von `object` anpassen.
Das Anpassen über `rich comparisons` wird in einer Folgeübung behandelt.
Weitere (viel) mehr Details zu diesem Thema findest du unter [Wertvergleiche][value comparisons] in der Python-Dokumentation.

Numerische Typen bilden (größtenteils) eine Ausnahme von dieser Regel zur Typübereinstimmung.
Ein `integer` **kann** als gleich einem `float` angesehen werden (_oder ein [`octal`][octal] als gleich einem [`hexadecimal`][hex]_), solange die Typen für den Vergleich implizit konvertiert werden können.

Für die anderen numerischen Typen in der Python-Standardbibliothek ([complex][complex numbers], [decimal][decimal numbers], [fractions][rational numbers]) sind Vergleichsoperatoren dort definiert, wo sie „Sinn ergeben" (_wo eine implizite Konvertierung das Ergebnis nicht verändert_), lösen aber einen `TypeError` aus, wenn die zugrunde liegenden Objekte nicht genau genug für einen Vergleich konvertiert werden können.
Weitere Informationen zu den Regeln, die Python für die _numerische Konvertierung_ verwendet, findest du unter [arithmetische Konvertierungen][arithmetic conversions] in der Python-Dokumentation.

```python
>>> import fractions

# A string cannot be converted to an int.
>>> 17 == '17'
False

# An int can be converted to float for comparison.
>>> 17 == 17.0
True

# The fraction 6/3 can be converted to the int 2
# The int 2 can be converted to 0b10 in binary.
>>> 6/3 == 0b10
True

# An int can be converted to a complex number with a 0 imaginary part.
>>> 17 == complex(17)
True

# The fraction 2/5 can be converted to the float 0.4
>>> 0.4 == 2/5
True

>>> complex(2/5, 1/2) == complex(0.4, 0.5)
True
```

Jeder geordnete Vergleich einer Zahl mit einem `NaN`-Typ (_keine Zahl_) ist `False`.
Ein verwirrender Nebeneffekt von Pythons `NaN`-Definition ist, dass `NaN` niemals gleich `NaN` ist.

```python
>>> x = float('NaN')

>>> 3 < x
False

>>> x < 3
False

# NaN never compares equal to NaN
>>> x == x
False
```

## Strings vergleichen

Anders als Zahlen werden Strings (`str`) [_lexikografisch_][lexographic order] verglichen, anhand ihrer einzelnen Unicode-Codepunkte (_das Ergebnis davon, jeden Codepunkt im `str` an die eingebaute Funktion [`ord()`][ord] zu übergeben, die ein `int` zurückgibt_).
Wenn alle Codepunkte in beiden Strings übereinstimmen und _**in derselben Reihenfolge**_ sind, gelten die beiden Strings als gleich.
Dieser Vergleich erfolgt „paarweise": erstes mit erstem, zweites mit zweitem usw.
In Python 3.x können `str` und `bytes` nicht direkt konvertiert oder verglichen werden.

```python
>>> 'Python' > 'Rust'
False

>>> 'Python' > 'JavaScript'
True

# Examples with Mandarin.
# hello < goodbye
>>> '你好' < '再见'
True

# ord() of first characters
>>> ord('你'), ord('再')
(20320, 20877)

# ord() of second characters
>>> ord('好'), ord('见')
(22909, 35265)

# And with Korean words.
# Pretty < beautiful.
>>> '예쁜' < '아름다운'
False

>>> ord('예'), ord('아')
(50696, 50500)
```

## Verkettung von Vergleichen

Vergleichsoperatoren können _beliebig_ verkettet werden, das heißt, sie lassen sich in jeder Kombination und beliebiger Länge verwenden.
Beachte, dass die Auswertung eines Ausdrucks von `left` nach `right` erfolgt.

Zum Beispiel ist `x < y <= z` äquivalent zu `x < y` `and` `y <= z`, außer dass `y` **nur einmal** ausgewertet wird.
In beiden Fällen wird `z` **überhaupt nicht** ausgewertet, wenn sich `x < y` als `False` erweist.
Das nennt man oft `short-circuit evaluation`: Die Auswertung stoppt, sobald der Wahrheitswert des Ausdrucks bereits feststeht.

`Short circuiting` wird von verschiedenen booleschen Operatoren, Funktionen und auch von der Vergleichsverkettung in Python unterstützt.
Anders als in vielen anderen Programmiersprachen, darunter `C`, `C++`, `C#` und `Java`, haben verkettete Ausdrücke wie `a < b < c` in Python eine herkömmliche [mathematische Interpretation][three way boolean comparison] und Vorrang.

```python
>>> x = 2
>>> y = 5
>>> z = 10

>>> x < y < z
True

>>> x < y > z
False

>>> x > y < z
False
```

## Objektidentität vergleichen

Die Operatoren `is` und `is not` prüfen die [_Identität_][object identity] eines Objekts, im Gegensatz zum _Wert_ eines Objekts.
Die Identität eines Objekts ändert sich nach seiner Erzeugung nie und lässt sich mit der Funktion [`id()`][id function] ermitteln.

`<apple> is <orange>` ergibt `True`, wenn _**und nur wenn**_ `id(<apple>)` == `id(<orange>)` gilt.
`<apple> is not <orange>` liefert das Gegenteil.

Aufgrund ihres Singleton-Status sollten `None` und `NotImplemented` immer mit `is` und `is not` mit anderen Objekten verglichen werden.
Weitere Details zu dieser Konvention findest du in der Python-Referenz zu [Wertvergleichen][value comparisons none] und in [PEP8][pep8 programming recommendations].

```python
>>> my_fav_numbers = [1, 2, 3]

>>> your_fav_numbers = my_fav_numbers

>>> my_fav_numbers is your_fav_numbers
True

# The returned id will differ by system and python version.
>>> id(my_fav_numbers)
4517478208

# your_fav_numbers is only an alias pointing to the original my_fav_numbers object.
# Assigning a new name does not create a new object.
>>> id(your_fav_numbers)
4517478208


>>> my_fav_numbers is not your_fav_numbers
False

>>> my_fav_numbers is not None
True

>>> my_fav_numbers is NotImplemented
False
```

## Mitgliedschaftsvergleiche

Die Operatoren `in` und `not in` prüfen die _Mitgliedschaft_.
`<fish> in <soup>` ergibt `True`, wenn `<fish>` ein Mitglied von `<soup>` ist (_wenn `<fish>` eine Teilmenge von `<soup>` ist oder darin enthalten ist_), andernfalls ergibt es `False`.
`<fish> not in <soup>` liefert die Negation, also das _Gegenteil von_ `<fish> in <soup>`.

Bei den Typen String und Byte ist `<name> in <fullname>` _**dann und nur dann**_ `True`, wenn `<name>` ein Teilstring von `<fullname>` ist.

```python
# A set of lucky numbers.
>>> lucky_numbers = {11, 22, 33}
>>> 22 in lucky_numbers
True

>>> 44 in lucky_numbers
False

# A dictionary of employee information.
>>> employee = {'name': 'John Doe', 
                'id': 67826, 'age': 33, 
                'title': 'ceo'}

# Checking for the membership of certain keys.
>>> 'age' in employee
True

>>> 33 in employee
False

>>> 'lastname' not in employee
True

# Checking for substring membership
>>> name = 'Super Batman'
>>> 'Bat' in name
True

>>> 'Batwoman' in name
False
```
