# Über

`String` und `&str` sind zwei grundlegende Arten, in Rust mit Textdaten zu arbeiten.
Es ist sehr nützlich, ihre Eigenschaften und ihr Zusammenspiel zu kennen.
Dieses Dokument beschreibt, wie sie sich überschneiden, und gibt einige grundlegende Ratschläge.
`String` ist ein Vektor aus `u8`-Bytes, der Speicher besitzt.
`String` ist veränderbar.
`&str` ist eine ausgeliehene Referenz auf einen String-Slice.
`&str` ist unveränderlich.

Die korrekte Aussprache von `&str` lautet „ref string“.
`String` ist eine potenziell veränderbare UTF-8-kodierte Darstellung einer Folge von Unicode-Codepunkten.

`&str` ist eine schreibgeschützte Sicht auf eine wohlgeformte UTF-8-Sequenz.
Weil es eine Referenz ist, ist es `Copy` und kann geteilt werden.

`String` und `&str` können in Rust nicht so indexiert werden, wie du es aus anderen Sprachen kennst.
Beispielsweise funktioniert Folgendes nicht:

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

Das liegt an den folgenden Eigenschaften:

- Zeichenketten sind UTF-8, deren Grundeinheit kein Byte ist, sondern ein Unicode-Codepunkt: `char`.
- Unicode-Codepunkte sind bis zu 4 Bytes breit, werden aber mit variabler Breite kodiert.
- Es ist daher unmöglich, die Position des `n`-ten Codepunkts zu berechnen, ohne über die tatsächlich kodierten Zeichen zu iterieren, denn ab dem ersten Zeichen hängt die Position des nächsten Zeichens davon ab, wie breit die vorherigen waren.
- Die Autoren der Rust-Standardbibliothek haben sich daher entschieden, das `Index`-Trait nicht für Zeichenketten zu implementieren: Während das Indexieren in ein Byte-Array konstante Zeit kostet, kann das Indexieren in eine Zeichenkette ziemlich lange dauern. Das verletzt das Prinzip der geringsten Überraschung.

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## `String` in `&str` umwandeln

`String` implementiert `Deref<Target=str>`.
Dieses Trait hat einige Sonderbehandlungen im Compiler: Es bedeutet, dass jede Referenz auf einen `String` automatisch und transparent in einen `&str` umgewandelt werden kann.
Das hat Folgendes zur Folge:

- Jeder Code, der zum Beispiel ein `&str`-Argument erwartet, kann stattdessen ein `&String` akzeptieren.
- Jede für `&str` implementierte Methode kann auch auf einem `String` aufgerufen werden.

(Wenn man generisch jede Art von Referenz auf einen `str` akzeptieren möchte, könnte man ein Argument vom Typ `impl AsRef<str>` nehmen, aber normalerweise werden Argumente als `&str` typisiert.)

## `&str` in `String` umwandeln

Es gibt viele Möglichkeiten, aus einem `&str` einen `String` zu erstellen:

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

Alle oben genannten Möglichkeiten erfordern das Zuweisen von Speicher für den `String` (auf dem Heap).
Deshalb ist `&str` in no_std verfügbar, `String` aber nicht.

(Das [heapless](https://crates.io/crates/heapless)-Crate wird oft verwendet, wenn man in no_std Zeichenketten manipuliert.)

## String und `&str` in Structs verwenden

In diesem Abschnitt geht es darum, wann du `String` oder `&str` für Struct-Felder verwenden solltest.
Du wirst oft sehen, dass Structs mit `String` statt `&str` für Feldwerte definiert werden.

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

Durch die Verwendung von `String` besitzt das Struct die Daten.
Das macht den Code für Anfänger leichter zu lesen und zu vermitteln.
Aber es bedeutet auch, dass für jedes Feld Heap-Allokationen anfallen.
`&str` leiht sich Textdaten, ist also performanter, allerdings muss dein Struct dann Lifetime-Parameter definieren.
Das [csv-Crate-Tutorial][csv-tutorial] demonstriert und erklärt diese Ideen recht anschaulich.

## Hinweise zur Performance

`String`-Werte werden auf dem Heap allokiert und können daher teurer in der Nutzung sein.
`&str`-Werte sind eine geteilte Referenz und erfordern daher keine häufige Neuzuweisung.
