# Debug

YS hat eine eingebaute `DBG`-Funktion, die beim Debuggen deines Lösungscodes nützlich sein kann.
Sie nimmt eine beliebige Anzahl von Argumenten entgegen und gibt sie auf stderr an der Konsole aus.
Sie gibt das letzte Argument zurück, sodass du sie direkt in deinem Code verwenden kannst.


Du kannst den Inline-Operator `.>` verwenden, der eine Kurzform für `.DBG()` ist.

Hier ist ein Beispiel für eine Codedatei:

```yaml
# file: program.ys

!YS-v0

defn do-it(nums):
  x =: 5

  DBG: -'my vars' x nums

  nums: .map(\(_ * x)).>
        .reverse().>
        .map(str).>
        .join(' - ')

say: do-it(3 .. 5)
```

Wenn du diesen Code mit `ys` ausführst, siehst du die folgende Ausgabe:

```txt
>>>
"my vars"
5
(3 4 5)
<<<
>>>(15 20 25)<<<
>>>(25 20 15)<<<
>>>("25" "20" "15")<<<
25 - 20 - 15
```


## Kompilierung

Eine andere übliche Methode, ein Problem zu finden, ist, sich den Clojure-Code anzusehen, in den dein YS-Code kompiliert wird.

Du kannst das tun, indem du den `ys`-Kommandozeilen-Interpreter mit dem `-c`-Flag ausführst.

So sieht die obige Datei `program.ys` aus, wenn sie kompiliert wird:

```clojure
$ ys -c program.ys
(defn do-it [nums]
 (let [x 5]
  (DBG "my vars" x nums)
  (join
   (DBG
    (+map
     (DBG (reverse (DBG (+map nums (fn [& [_1]] (mul+ _1 x))))))
     str))
   " - ")))
(say (do-it (rng 3 5)))
```

Du siehst deutlich, wie der Operator `.>` in einen Aufruf der `DBG`-Funktion kompiliert wurde.
