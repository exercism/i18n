# Einführung

Ein Block ist eine Menge von Anweisungen und Deklarationen, die zu einer syntaktischen Einheit zusammengefasst sind.
Blöcke werden oft, aber nicht immer, in geschweiften Klammern definiert.
Blöcke können innerhalb von Funktionen und innerhalb anderer Blöcke verschachtelt werden.

Eine Funktion verhält sich in gewisser Weise wie ein Block.
Ein Bezeichner für eine in einer Funktion definierte Variable ist außerhalb der Funktion nicht sichtbar, genauso wie ein Bezeichner für eine in einem Block definierte Variable außerhalb des Blocks nicht sichtbar ist.
Zwei Variablen in zwei Funktionen können denselben Namen haben, da die beiden Funktionen nicht ineinander hineinsehen, genauso wie zwei Variablen in zwei Blöcken denselben Namen haben können, da die beiden Blöcke nicht ineinander hineinsehen.
Aber Funktionen und Blöcke sind nicht identisch.
Eine Funktion kann nicht in eine andere Funktion verschachtelt werden, ein Block hingegen kann in einen anderen Block verschachtelt werden.

Im folgenden Beispiel wird `number` innerhalb der `main`-Funktion definiert.
`flag` wird innerhalb des `if`-Blocks definiert, der in die `main`-Funktion verschachtelt ist.
Variablen, die innerhalb eines Blocks definiert werden, sind nur innerhalb dieses Blocks gültig.
Wenn du versuchst, den Code zu kompilieren, führt das daher zu einem Kompilierungsfehler.

```c
#include <stdio.h>

int main() {

  int number = 1;

  if (number == 1) {
      int flag = 1;
      printf("%d", flag);
  }

  // this line generates a compilation error
  // error: 'flag' undeclared (first use in this function)
  printf("%d", flag);
    
}
```

Die Fehlermeldung kann verwirrend sein, da `flag` weiter oben in der Funktion ja _verwendet_ wird.
Allerdings wird `flag` in einem Block innerhalb der Funktion definiert.
Der innere Block kann die Variable `number` in der umgebenden Funktion „sehen“, aber die äußere Funktion kann die im inneren Block definierte Variable `flag` nicht „sehen“.
Sobald die Ausführung den Block verlässt, wird die Variable `flag` automatisch zerstört und steht dem Programm nicht mehr zur Verfügung.
Die `main`-Funktion selbst sieht den Bezeichner `flag` zum ersten Mal in der letzten `printf`-Anweisung.
Wenn die letzte `printf`-Anweisung entfernt wird, lässt sich das Programm kompilieren und gibt bei der Ausführung `1` aus.
Das liegt daran, dass die Variable `flag` in dem Block gültig ist, der die erste `printf`-Anweisung enthält.

Seit `C99` gelten einzeilige `if`-, `for`-, `while`- und `do`-Anweisungen ebenfalls als Blöcke.
Im folgenden Beispiel ist `i` zwar nicht in geschweiften Klammern definiert, es existiert aber nur in dem Block, der durch die `for`-Anweisung definiert wird, und ist für die äußere `main`-Funktion nicht sichtbar.

```c
#include <stdio.h>

int main() {

    for (int i = 0, j = 11; i < j; i+=2)
        printf("%d", i);

    // this line generates a compilation error
    // error: 'i' undeclared (first use in this function)
    printf("%d", i);
    
}
```

Wenn die letzte `printf`-Anweisung entfernt wird, lässt sich das Programm kompilieren und gibt bei der Ausführung `0 2 4 6 8 10 ` aus.
Manche Sprachen wie Go und Rust schreiben ausdrücklich vor, dass einzeilige bedingte Anweisungen und Schleifenanweisungen einen Block bilden.
Sie verlangen, dass solche einzeiligen Anweisungen trotzdem in geschweifte Klammern gesetzt werden.
