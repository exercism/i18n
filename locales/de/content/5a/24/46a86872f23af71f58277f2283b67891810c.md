# Einführung in Here-Dokumente

Beim Schreiben von Bash-Skripten leitet ein „Here-Dokument“ (oder „Heredoc“) mehrere Eingabezeilen an einen Befehl oder ein Programm um, so als würdest du sie direkt im Terminal eintippen.
Es ist ein mächtiges Werkzeug, um mehrzeiligen Text in deine Skripte einzubetten, ohne dass du externe Dateien oder komplizierte String-Manipulation brauchst.

## Wichtige Merkmale und Syntax

1. Trennzeichen: Ein Heredoc beginnt mit dem Operator `<<`, gefolgt von einem Trennwort (oft „Marker“ oder „Terminator“ genannt).
   Dieses Trennzeichen kann ein beliebiges Wort sein, aber üblich sind Dinge wie `EOF`, `END` oder `TEXT`, weil sie klar erkennbar sind.
   Für besser lesbaren Code kannst du auch etwas Beschreibendes als Trennzeichen nehmen, zum Beispiel `END_INSTALLATION_INSTRUCTIONS`.

1. Inhalt: Nach dem einleitenden `<< DELIMITER` schreibst du den Inhalt, den du umleiten willst.
   Das können mehrere Zeilen Text, Code oder irgendetwas anderes sein.

1. Ende: Das Heredoc endet, wenn das Trennwort wieder allein in einer Zeile steht, ohne Leerzeichen davor oder danach.

## Grundlegende Syntax

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## So funktioniert es

* Bash liest alle Zeilen zwischen dem beginnenden `<< DELIMITER` und dem abschließenden `DELIMITER`.
* Bash verbindet diesen Inhalt mit der Standardeingabe des Befehls.
* Der Befehl verarbeitet diese Eingabe, als käme sie von der Tastatur.

### Beispiel 1: Einfache Textausgabe

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

Ausgabe:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

In diesem Beispiel:

* `cat` ist der Befehl.
* `<< EOF` startet das Heredoc mit `EOF` als Trennzeichen.
* Die drei Textzeilen sind der Inhalt.
* `EOF` allein in einer Zeile beendet das Heredoc.
* Anschließend gibt `cat` den Inhalt aus, den es erhalten hat.

### Beispiel 2: Verwendung mit wc (Wortzählung)

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

Ausgabe:

```plaintext
3
```

Hier zählt `wc -l` die Anzahl der Zeilen.
Das Heredoc liefert die drei Zeilen als Eingabe.

### Beispiel 3: Daten an ein Skript übergeben

Das Skript:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

Rufe das Skript mit einem Heredoc von einer interaktiven Bash-Eingabeaufforderung aus auf:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

Ausgabe:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## Varianten und fortgeschrittene Funktionen

### Wörtlicher Inhalt

Bash führt innerhalb eines Heredocs Variablenexpansion, Befehlssubstitution und arithmetische Expansion durch.
In diesem Sinn verhalten sich Heredocs wie Strings in doppelten Anführungszeichen.

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

Ausgabe:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

Wenn das Trennzeichen in Anführungszeichen steht (einfache oder doppelte), werden diese Expansionen verhindert.
Der Inhalt wird wörtlich genommen.
Das ist wie bei Strings in einfachen Anführungszeichen.

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

Ausgabe:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### Führende Tabs entfernen

Wenn du `<<-` (mit einem Bindestrich am Ende) statt `<<` verwendest, entfernt Bash alle führenden _Tabulatorzeichen_ aus jeder Zeile des Heredocs.
Das ist nützlich, um den Heredoc-Inhalt in deinem Skript einzurücken, ohne die Ausgabe zu verändern.

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

Die Ausgabe wird ohne alle führenden Tabs ausgegeben:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
Der Autor empfiehlt diese Verwendung nicht.
Sie kann zwar die Lesbarkeit des Skripts verbessern, aber:

1. es ist leicht, die Tabulatorzeichen versehentlich durch Leerzeichen zu ersetzen (dein Editor macht das vielleicht automatisch), und 
1. es ist schwer, den Unterschied zwischen Leerzeichen und Tabs zu erkennen.
~~~~

## Wann du Here-Dokumente verwendest

* Mehrzeilige Eingabe: wenn du einem Befehl mehrere Textzeilen übergeben willst.
* Konfigurationsdateien: kleine Konfigurationsausschnitte in ein Skript einbetten.
* Code erzeugen: Code direkt in einem Skript erstellen.
* Interaktionen skripten: Benutzereingaben für interaktive Programme simulieren.
* Externe Dateien vermeiden: wenn du keine temporären Dateien anlegen willst.

Ein typischer Anwendungsfall ist ein Hilfetext:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## Mögliche Nachteile

* Große eingebettete Dokumente können deinen Code schwerer lesbar machen.
  Oft ist es besser, das Skript mit der Dokumentation in getrennten Dateien auszurollen.
* Here-Dokumente können den Fluss des Codes unterbrechen.
  Vielleicht bist du gerade tief in verschachteltem Code, wenn du einem Programm etwas Text übergeben willst.
  Die Einrückung des Heredocs kann im Vergleich zum umgebenden Code störend wirken.

## Here-Strings

Wie Here-Dokumente liefern _Here-Strings_ (oder „Herestrings“) Eingaben an einen Befehl.
Während Heredocs jedoch als Textblock übergeben werden, wird ein Herestring als einzelner String übergeben.
Here-Strings verwenden die Syntax `<<< "text"`.

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

Ausgabe:

```plaintext
UPPER CASE THIS STRING
```

Anders als bei Heredocs ist kein abschließendes Trennzeichen nötig.

### Warum Here-Strings verwenden?

Statt eines Here-Strings kannst du auch eine Pipeline verwenden:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

Warum also einen Here-String verwenden?

Stell dir vor, du bekommst einen String als Ergebnis einer lang laufenden Berechnung und willst das Ergebnis an zwei verschiedene Befehle weitergeben.
Mit Pipelines musst du die Berechnung zweimal ausführen:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

Effizienter ist es, die Ausgabe der Berechnung mit Befehlssubstitution abzufangen und Here-Strings zu verwenden, um die beiden folgenden Befehle mit Eingaben zu versorgen:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

Hier ist eine Anwendung dieses Beispiels aus der Praxis:

* die JSON-Antwort auf eine (paginierte) REST-API-Abfrage abfangen,
* die JSON-Daten an ein jq-Programm übergeben, das die Ergebnisse auswertet und in eine Datei schreibt, und dann
* die JSON-Daten an ein weiteres jq-Programm übergeben, um die URL der nächsten Abfrage zu ermitteln.

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

Achte auf die Position der Ausgabeumleitung.
Die gesamte Ausgabe der while-Schleife wird an die Datei `data.csv` angehängt.

## Heredocs und Herestrings als Umleitung

Weil es sich nur um Formen der Umleitung handelt, lassen sie sich mit anderen Umleitungsoperationen kombinieren:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## Zusammenfassung

Here-Dokumente (oder „Heredocs“) sind eine flexible und praktische Möglichkeit, mehrzeilige Eingaben in Bash-Skripten zu verwalten.
Sie vereinfachen es, Text und Daten direkt in deine Skripte einzubetten, wodurch diese eigenständiger und leichter lesbar werden.

Here-Strings (oder „Herestrings“) ähneln Here-Dokumenten, bieten aber eine einfachere und dynamischere Syntax.
