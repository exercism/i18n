# Einführung

## Let Assertions

Wenn wir in Gleam Pattern Matching auf einen Wert anwenden, müssen wir sicherstellen, dass die Muster jeden möglichen Wert des Typs abdecken, andernfalls kompiliert der Code nicht.

Diese Funktion sollte abgelehnt werden, weil sie den Fall, dass die Liste leer ist, nicht behandelt:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Meistens wollen wir in Gleam-Programmen jeden möglichen Fall behandeln, aber in manchen Programmen, etwa Prototypen oder kurzen Skripten, wollen wir uns vielleicht nur auf den Happy Path konzentrieren und keinen Code für andere Fälle schreiben. Hier kommt Gleams `let assert` ins Spiel.

Mit let assertions kann ein Muster nur auf einen Teil der möglichen Werte eines Typs passen, und wenn das Muster nicht auf einen Wert passt, stürzt das Programm ab. Mit `let assert` können wir die obige Funktion so schreiben:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam-Bibliotheken sollten niemals let assertions verwenden, weil sie das Programm zum Absturz bringen können. Stattdessen sollten sie den Typ `Result` verwenden und es den Entwicklerinnen und Entwicklern der Anwendung überlassen, wie sie mit Fehlern umgehen.
