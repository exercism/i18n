# Einführung

Ausnahmen in Ruby bieten, wie in vielen Sprachen, eine Möglichkeit, mit unerwarteten Ereignissen umzugehen. Ein guter Umgang mit Ausnahmen ist wichtig, wenn du verhindern willst, dass dein Programm abstürzt.

Wenn eine Ausnahme ausgelöst wird, egal ob du sie explizit auslöst oder ob der Ruby-Interpreter sie auslöst, unterbricht das Programm seinen normalen Ablauf und beendet sich schließlich mit einer Fehlermeldung:

```ruby
raise ArgumentError.new("Something went wrong!")
=> Traceback (most recent call last):
.
.
ArgumentError (Something went wrong!)
```

```ruby
1/0
=> Traceback (most recent call last):
.
.
ZeroDivisionError (divided by 0)
```

Wenn wir diesen Abbruch verhindern wollen, müssen wir auf die Ausnahme reagieren. Das nennt man eine Ausnahme „abfangen“:

```ruby
begin
  # ...any code that raises an exception
rescue
  puts 'Got an exception'
end
```

Dieses Programm stürzt nicht ab und gibt „Got an exception“ aus. Statt sich zu beenden, führt Ruby den Code im rescue-Block aus, der eine Nachricht ausgibt.

Wie alles in Ruby sind auch Ausnahmen Objekte, und sie enthalten meist Daten über die Ausnahme. So bekommen wir das Ausnahmeobjekt:

```ruby
begin
  # ...any code that raises an exception
rescue => e
  puts "Exception class: #{ e.class.name }"
  puts "Exception Message:#{e.message}"
end
```

In Ruby kannst du auch eigene Ausnahmen auslösen. Zum Beispiel:

```ruby
begin
  raise ArgumentError.new("Invalid argument")
rescue ArgumentError => e
  puts e.message
end
```

Bei der vorigen Ausnahme handelt es sich um eine von Rubys eingebauten Ausnahmen, aber du kannst auch eigene Ausnahmen definieren und auslösen:

```ruby
class CustomError < StandardError
end

raise CustomError.new("Something went wrong")
```
