# Über

## Boolesche Werte in Julia

Die Werte wahr und falsch werden durch den Typ `Bool` dargestellt.
Er enthält nur zwei Werte: `true` und `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

Anders als in vielen anderen Sprachen gibt es in Julia bewusst kein Konzept von „truthiness“, und nur Ausdrücke, die zu `true` oder `false` ausgewertet werden, werden als `Bool` behandelt.

Leere Arrays oder Strings werden ausdrücklich *nicht* als `false` interpretiert.
Wenn du leere Werte gesondert behandeln willst, brauchst du einen passenden Test wie `isempty()`.

## Boolesche Operatoren

In Julia gibt es drei [boolesche Operatoren][boolean-operators].

`&&` ist das boolesche „und“.
Der Ausdruck ergibt `true`, wenn die Ausdrücke auf *beiden* Seiten von `&&` `true` sind.

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||` ist das boolesche „oder“.
Der Ausdruck ergibt `true`, wenn ein Ausdruck auf *einer* der beiden Seiten von `||` `true` ist.

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!` ist das boolesche „nicht“.
Er vertauscht (invertiert) die Werte `true` und `false`.

```julia-repl
julia> !true
false

julia> !false
true
```

Wer viele andere Sprachen kennt, wird ähnliche Operatoren konzeptionell wiedererkennen, auch wenn die genaue Syntax sich von Sprache zu Sprache unterscheiden kann.

## Operatorrangfolge

In komplexeren Ausdrücken ist es nützlich zu wissen, dass `&&` eine etwas höhere [Rangfolge][operator-precedence] hat als `||` *(so wie in der Arithmetik `*` vor `+` ausgeführt wird)*.

Sich darauf zu verlassen, kann verwirrend und fehleranfällig sein.
Setze zur Klarheit runde Klammern, damit deine Absicht deutlich wird.

## Kurzschlussauswertung

Hängt der Ausdruck `true || x` vom Wert von `x` ab, oder kann der Compiler `x` ignorieren?

Julia wertet boolesche Ausdrücke von links nach rechts aus und hört auf, sobald das Ergebnis eindeutig ist.

Zum Beispiel muss `true || x` unabhängig von `x` immer `true` sein, also wird `x` nicht ausgewertet.
Ebenso ist `false && y` immer `false`, ohne dass `y` ausgewertet werden muss.

Umgekehrt ist `true && x` nur dann `true`, *wenn* `x` ebenfalls `true` ist, also muss `x` ausgewertet werden.

Ähnlich verhält es sich, wenn wir mehrere Operatoren verketten:

```julia-repl
julia> true && false && something_else
false
```

Weil `true && false` immer `false` ergibt, spielt `something_else` keine Rolle und wird vom Compiler ignoriert.

In diesem Fall gab es die Variable `something_else` gar nicht, trotzdem führte sie in diesem Zusammenhang zu keinem Fehler *(teste das in der REPL, wenn du es nicht glaubst)*.

Diese Kurzschlussauswertung nutzen Julia-Programmierer recht häufig als Abkürzung, um Laufzeitprobleme und Randfälle abzufangen:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

Zum Beispiel könnte `do_something` ein frühes `return` aus der Funktion sein, wenn `all_ok` `false` ist, oder das Zuweisen eines Standardwerts an eine Variable, bevor es weitergeht.

Das ist ein kleiner Missbrauch der booleschen Syntax, kann aber sehr praktisch sein.

## Wie Bools intern funktionieren

Wird ein Bool in einen *arithmetischen* Ausdruck eingebaut, wird `true` als `1` und `false` als `0` interpretiert, was ihrer Speicherung entspricht.

Wenn du an maschinennahe Sprachen wie C gewöhnt bist, verzichte *bitte* darauf, das häufig zu nutzen.
Es mindert die Lesbarkeit des Codes und erschwert das Debuggen.

Manchmal siehst du die numerischen Werte als schnelle Möglichkeit, zu zählen, wie viele Dinge `true` sind.

```julia-repl
julia> true + false + true
2
```
