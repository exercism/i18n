# Ergänzung zu den Anweisungen

## Implementierung

Bevor du anfängst, stelle sicher, dass du weißt, wie du Code schreibst, der die Testfälle besteht.
Für mehr Hintergrund schau dir dieses [tutorial] an.

Die meisten Java-Übungen enthalten mehrere Testfälle.
Diese Fälle sind so aufgebaut, dass sie einen nützlichen Prozess unterstützen, der als [testgetriebene Entwicklung (TDD)][tdd] bekannt ist.
Bei TDD wiederholst du einen strukturierten Zyklus, der Programmierenden hilft, komplexe Funktionalität Stück für Stück statt auf einmal aufzubauen.
Dieser Zyklus lässt sich so beschreiben:

1. Füge einen Test hinzu, der einen Teil der gewünschten Funktionalität beschreibt, der in deinem Code gerade noch fehlt.
2. Führe die Tests aus, um zu prüfen, dass dieser neu hinzugefügte Test fehlschlägt.
3. Aktualisiere deinen vorhandenen Code, bis:
   - alle alten Tests weiterhin bestehen;
   - auch der neue Test besteht.
4. [Räume deinen Code auf][refactoring] und stelle sicher, dass alle Tests weiterhin bestehen.
   Das bedeutet typischerweise, Variablen umzubenennen, doppelte Logikblöcke zu entfernen, übrig gebliebenes Logging zu entfernen usw.
5. Kehre zu Schritt 1 zurück, bis die gesamte gewünschte Funktionalität umgesetzt ist!

Die Testdateien in diesem Track enthalten _alle_ Tests, die deine Lösung bestehen muss, um als gültig zu gelten.
Das scheint zunächst nicht zu dem oben beschriebenen Zyklus zu passen, in dem die Tests einzeln geschrieben werden.
Allerdings bietet das Tool, mit dem wir unsere Tests schreiben, [JUnit][junit],
eine [@Disabled][junit-disabled]-[Annotation][java-annotation], mit der sich ein bereits geschriebener Test vorübergehend überspringen lässt.
Mit dieser Annotation sorgen wir dafür, dass die Testdateien, die wir dir liefern, die folgenden Regeln erfüllen:

- Der erste Test in einer Testdatei wird standardmäßig _nicht_ übersprungen.
- Alle Tests außer dem ersten in jeder Testdatei werden standardmäßig _übersprungen_.

So kannst du den TDD-Zyklus simulieren, indem du diese leicht abgewandelten Schritte befolgst:

1. Führe die Tests aus, um zu prüfen, dass derzeit _höchstens ein_ Test fehlschlägt.
2. Aktualisiere deinen vorhandenen Code, bis alle nicht übersprungenen Tests bestehen.
3. Räume deinen Code auf und stelle sicher, dass alle nicht übersprungenen Tests weiterhin bestehen.
4. Entferne die oberste `@Disabled`-Annotation in der Testdatei.
5. Kehre zu Schritt 1 zurück, bis keine Tests mehr übersprungen werden und alle Tests bestehen!
