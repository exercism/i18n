# Code-Einbindung

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

Ein `include` kopiert den Code einer anderen Klasse in diese hier. Es ist eine
Operation zur Compilezeit, ohne Laufzeitkosten und ohne Laufzeitbeziehung:
Die beiden Klassen sind danach nicht mehr verbunden.

## Die Klausel

```
   include CLASS  old_name -> new_name , old_name -> ;
```

Jeder Eintrag benennt ein Feature um. `-> ;` ohne neuen Namen lässt es weg.
Alles, was nicht erwähnt wird, kommt unverändert herein.

Die Umbenennung betrifft das, was von außen sichtbar ist. Aufrufe zwischen den
eingebundenen Routinen funktionieren weiterhin: Wenn `describe` `count` aufruft
und `count` in `beats` umbenannt wird, ruft `describe` `beats` auf.

## Mehrere einbinden

```sather
   include WARM_UP;
   include COOL_DOWN;
```

ist erlaubt, und so bekommt Sather, was andere Sprachen Mehrfachvererbung
nennen, ohne die üblichen Probleme: Ein Konflikt ist ein Compilefehler, und die
Lösung ist, umzubenennen oder eines wegzulassen. Nichts wird durch eine
Rangfolge entschieden, die du dir merken musst.

## private include

```sather
   private include WARM_UP;
```

bringt den Code für den eigenen Gebrauch dieser Klasse herein, ohne ihn nach
außen sichtbar zu machen. Nützlich, wenn du die Implementierung willst und
nicht die Schnittstelle.

## Beides zusammen

Die übliche Form für eine Familie von Klassen:

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

`< $ACT` sagt, was es kann; `include ACT_BASICS` liefert einen Teil davon, wie.
Änderst du deine Meinung zum Wie, bewegt sich das `<` nicht.

## Warum das so gemacht wird

Eine abstrakte Klasse hat keinen Code, also kann man nicht versehentlich von ihr
erben, und es gibt keine Oberklasse, deren Verhalten sich unter dir ändert.
Wiederverwendung ist eine Kopie, die zur Compilezeit aus einer Klasse gezogen
wird, die du benannt hast, und bei der jede Umbenennung aufgeschrieben ist.

Der Preis dafür ist, dass Wiederverwendung in jeder Klasse ausdrücklich
angefordert werden muss. Das ist der Tausch: mehr Tipparbeit, nichts implizit.
