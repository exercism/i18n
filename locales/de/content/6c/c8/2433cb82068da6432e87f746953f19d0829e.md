# Docker

Unsere Analyzer werden als Docker-Images ausgerollt.

Bitte lies die [allgemeinen Docker-Informationen zum Tooling](/docs/building/tooling/docker), um dich damit vertraut zu machen, wie diese funktionieren.

## Integration

Wenn wir einen Analyzer ausführen, um eine Lösung zu analysieren, führen wir einen Docker-Befehl aus, der so aussieht:

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-analyzer" \
        "${exercise_slug}" "/solution" "/output"
```

Du kannst sehen, dass wir drei Argumente an das Docker-Image übergeben:

1. Den Übungs-Slug
2. Den Pfad zum Verzeichnis der Lösung
3. Den Pfad zum Ausgabeverzeichnis

## Konventionen

Alle unsere Analyzer verwenden in ihrer Implementierung die folgenden Konventionen:

- Die `Dockerfile` befindet sich im Wurzelverzeichnis des Repos.
- Das Arbeitsverzeichnis sollte `/opt/analyzer` sein.
- Der Entrypoint ist `/opt/analyzer/bin/run.sh`
- Das Skript `/opt/analyzer/bin/run.sh` erwartet 3 Argumente:
  1. Den Übungs-Slug
  2. Den Pfad zum Verzeichnis der Lösung
  3. Den Pfad zum Ausgabeverzeichnis

Weitere Informationen findest du unter [Die Schnittstelle](/docs/building/tooling/analyzer/interface).

```exercism/note
Neue Analyzer-Repos verwenden diese Konventionen standardmäßig.
```
