# Über

Elm ist eine wunderbare Sprache, um zuverlässige Webanwendungen zu bauen.
Sie hat freundliche Fehlermeldungen, eine großartige Performance, kleine Assets und keine Laufzeitausnahmen.

Der wohl berühmteste und am häufigsten kopierte Teil von Elm ist The Elm Architecture, ein einfaches Muster, um Webanwendungen zu strukturieren. Alle Elm-Webanwendungen sind so aufgebaut.

Die Kernidee ist, dass dein Code um ein `Model` deines Anwendungszustands herum aufgebaut ist, zusammen mit einer Möglichkeit, dein Modell mit `update` zu ändern, und einer, es mit `view` anzuzeigen.

Das `Model` enthält den Zustand der Anwendung, also alle Daten, die die Anwendung braucht.
Es kann von jedem Typ sein, aber in jeder nützlichen Anwendung ist es normalerweise ein [record][record].
Stell dir eine einfache Anwendung mit einem Textfeld und einem Text vor, der diesen Text rückwärts anzeigt. Dann sieht das Modell aus wie unten.
Du findest dieses Beispiel auch im [Elm Guide][elm-guide-text-fields].

```elm
type alias Model =
  { text : String
  }
```

`update` ist eine Funktion, die mit einer `Msg` aufgerufen wird, wenn sich etwas ändert (zum Beispiel, wenn der Nutzer auf einen Button klickt).
Sie nimmt die `Msg` und das aktuelle `Model` und gibt ein neues `Model` zurück.
Die `Msg` kann von jedem Typ sein, ist aber normalerweise ein [custom type][custom-type].

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

Wie bei allen Custom Types können die Varianten der `Msg` so viele beliebige Informationen enthalten, wie sie brauchen.
Im obigen Beispiel enthält die Variante `TextChanged` einen `String`.

`view` ist eine Funktion, die HTML zurückgibt, um es dem Nutzer im Browser anzuzeigen.
Sie nimmt das aktuelle `Model` und gibt eine `Html Msg` zurück (der Typ, mit dem Elm HTML darstellt).
Jedes HTML-Element (zum Beispiel `<div>`) hat eine entsprechende Elm-Funktion (`Html.div`) im `Html`-Paket.
Jede dieser Funktionen nimmt zwei Parameter: Der erste ist eine Liste von Attributen (aus den Paketen `Html.Attributes` und `Html.Events`), der zweite eine Liste von Kindelementen (Funktionen aus dem `Html`-Paket).
Es gibt außerdem eine `text`-Funktion, die HTML-Textinhalt darstellt. Sie nimmt nur einen String-Parameter, wird ansonsten aber genauso verwendet wie alle anderen Funktionen und Elemente im `Html`-Paket.

Die `view`-Funktion kann festlegen, dass bestimmte Ereignisse, etwa das Klicken auf einen Button oder das Bearbeiten von Text in einem Textfeld, dazu führen, dass eine `Msg` erzeugt wird. Die Elm-Runtime nutzt sie dann, um die `update`-Funktion aufzurufen, das `Model` zu ändern und aktualisiertes HTML zu erzeugen.
Im folgenden Code geschieht das mit `Html.Events.onInput TextChanged`.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

`Html.Events.onInput` erwartet eine Funktion (`String -> Msg`), mit der sie die `Msg` erzeugt.
Verschiedene Ereignisse erwarten unterschiedliche Funktionen, je nachdem, welche Informationen sie liefern können. So erwartet `Html.Events.onCheck` (für Checkboxen) `Bool -> Msg` und `Html.Events.onClick` einfach eine `Msg`.

Die Sprache Elm ist rein und funktional, und Mutation ist nicht möglich. Deshalb kümmert sich die Elm-Runtime um alles, was sich ändert.
Alle verschiedenen [HTML Elements][html-elements], [Element Attributes][element-attributes] und [HTML Events][html-events] findest du im Elm-Paketregister.

Es gibt 4 „Stufen“ von Webanwendungen, die du in Elm schreiben kannst, und sie werden mit jeder Stufe mächtiger und komplizierter (obwohl Elm eine wunderbar einfache Sprache und ein ebenso einfaches Ökosystem bleibt).
Alle sind im [Browser-Paket][browser-package] definiert:

- [sandbox][browser-sandbox]: reagiere auf Nutzereingaben wie Buttons und Checkboxen
- [element][browser-element]: kommuniziere mit der Außenwelt über HTTP und JavaScript-Interop
- [document][browser-document]: steuere `<title>` und `<body>` einer Webseite
- [application][browser-application]: erstelle vollständige Single-Page-Anwendungen, die Routing und URL-Änderungen verarbeiten

Dieses Konzept verwendet die [sandbox][browser-sandbox], weil sie die einfachste ist (und weil es eine Sandbox ist, lässt sie sich relativ leicht mit dem Online-Editor von Exercism verwenden).
Das Einstiegsmodul eines Elm-Programms muss `Main` heißen, und die Funktion, die die Anwendung erstellt, muss `main` heißen, wie unten.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

Die Funktionen `update` und `view` haben wir schon gesehen. Die [sandbox][browser-sandbox] braucht zusätzlich eine `init`-Funktion, die den Anfangszustand des `Model` zurückgibt.
