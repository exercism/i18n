# Generische Klassen

Du verwendest `ARRAY{STR}`, `FMAP{STR,INT}` und `FSET{STR}` schon seit dem Anfang.
In den geschweiften Klammern stand schon immer ein Typ. Jetzt schreibst du eine
Klasse mit eigenen geschweiften Klammern.

## Das Problem

Das Fundbüro braucht eine Kiste, die eine Sache aufbewahrt und sich merkt, wer
sie abgegeben hat. Eine Kiste für einen Pullover:

```sather
class JUMPER_BOX is
   attr item : JUMPER;
   ...
end;
```

und dann dieselbe Klasse noch einmal für eine Wasserflasche und noch einmal für
ein Handy. Drei Kopien, die sich in einem Wort unterscheiden.

## Der Typparameter

```sather
class LOST_BOX{T} is

   attr item : T;

   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;

end; -- class LOST_BOX{T}
```

`{T}` nach dem Klassennamen ist ein **Typparameter**. `T` ist kein Typ, sondern
steht für den Typ, der beim Verwenden der Klasse eingesetzt wird. Innerhalb der
Klasse wird `T` genau so verwendet wie jeder andere Typname.

## Verwenden

Gib den Typ in geschweiften Klammern an:

```sather
   jumper ::= #LOST_BOX{STR}("blue jumper");
   count ::= #LOST_BOX{INT}(3);

   jumper.item      -- "blue jumper", a STR
   count.item       -- 3, an INT
```

`LOST_BOX{STR}` und `LOST_BOX{INT}` sind zwei verschiedene Typen. Den einen dort
einzusetzen, wo der andere erwartet wird, ist ein Fehler, den der Compiler
findet, genau als hättest du die beiden Klassen von Hand ausgeschrieben. Und
genau das passiert auch: Sather baut für jeden tatsächlich verwendeten Typ eine
eigene Klasse aus dem Muster.

Zur Laufzeit kostet das also nichts, und es geht keine Typinformation verloren:
`jumper.item` ist wirklich ein `STR` und nicht etwas, das geprüft oder
umgewandelt werden muss.

## Mehr als einer

Eine Klasse kann mehrere Parameter annehmen, getrennt durch Kommas.
`FMAP{K,T}` ist das Beispiel, das du schon kennst.

```sather
class LABELLED{L,T} is
   attr label : L;
   attr item : T;
   ...
end;
```

## Namensgebung

Einzelne Großbuchstaben sind die Konvention: `T` für eine Sache, `K` für einen
Schlüssel, `E` für ein Element. Die Bibliothek verwendet sie durchgängig.
