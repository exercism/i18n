# Einführung

## Ausnahmen

Alle Fehler in Elixir implementieren das _Exception Behaviour_. Genau wie das _Access Behaviour_ definiert das _Exception Behaviour_ Callback-Funktionen, die ein Modul implementieren muss, um den Software-Vertrag des Behaviours zu erfüllen. Sobald ein Fehler definiert ist, hat er die folgenden Eigenschaften:

- Der Name des Moduls legt den Namen des Fehlers fest.
- Das Modul definiert ein Fehler-Struct.
- Das Struct hat ein `:message`-Feld.
- Das Modul kann mit `raise/1` und `raise/2` verwendet werden, um den beabsichtigten Fehler auszulösen.

Das _Exception Behaviour_ legt außerdem zwei Callbacks fest: `message/1` und `exception/1`. Wenn sie nicht implementiert sind, werden Standardimplementierungen verwendet. `message/1` wandelt das Fehler-Struct in eine lesbare Nachricht um, wenn es mit `raise` aufgerufen wird. `exception/1` ermöglicht es, der Nachricht zusätzlichen Kontext hinzuzufügen, wenn es mit `raise/2` aufgerufen wird.

### Eine Ausnahme definieren

Um eine Ausnahme als Fehlermodul zu definieren, verwenden wir das `defexception`-Makro:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### Ausnahmen verwenden

Definierte Fehler können wie ein eingebauter Fehler verwendet werden, und zwar mit `raise/1` oder `raise/2`.

- `raise/1` löst einen bestimmten Fehler über seinen Modulnamen aus. Ist das Argument ein String, wird ein `RuntimeError` mit dem String als Nachricht ausgelöst.
- `raise/2` löst einen bestimmten Fehler über seinen Modulnamen aus und akzeptiert ein Attributargument, mit dem der Fehler mit der passenden Nachricht ermittelt wird.
