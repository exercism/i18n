# Über

Reguläre Ausdrücke sind eine äußerst vielseitige Möglichkeit, bei Strings einen _Musterabgleich_ durchzuführen. Dazu verwendet man eine domänenspezifische Sprache (DSL), die genau für diesen Zweck entworfen wurde.

ICU ähnelt der beliebten Bibliothek [PCRE2][web-PCRE], die von den meisten neueren Sprachen verwendet wird, allerdings werden einige Randfälle anders behandelt.

Viele der Funktionen, die bereits im [`Strings`][concept-strings]-Konzept besprochen wurden, sind standardmäßig für Regex-Suchen ausgelegt.

Wir haben das Strings-Konzept bewusst einfach gehalten und nur mit String-Literalen abgeglichen, aber stattdessen kann jedes beliebige Regex-Muster verwendet werden.

Formell wird ein Regex in R durch den Aufruf von [`regex()`][ref-regex] erzeugt.
Der Einfachheit halber behandeln `stringr`-Funktionen jeden Muster-String als Regex.
Im folgenden Beispiel ist der erste `str_replace_all()`-Aufruf nur syntaktischer Zucker für die zweite Variante:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

Das [Cheatsheet][cheat-stringr] ist ein nützlicher Leitfaden: Alle Funktionen mit einem `pattern`-Argument (rot gedruckt) akzeptieren ein Regex, und Seite 2 fasst die Regex-Syntax zusammen.

Beachte, dass die Funktion [`regex()`][ref-regex] weiterhin wichtig sein kann, wenn du die Standardeinstellungen überschreiben musst, etwa die Groß- und Kleinschreibung oder das Locale.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

Viele Regex-Muster enthalten einen Backslash, wie das oben verwendete `\s`.
In normalen R-Strings muss `\` durch Verdopplung escaped werden, daher `"\\s"`.

Backslashes können sich häufen und unübersichtlich werden, deshalb kann es helfen, in komplexen Fällen [Raw-Strings][book-raw] zu verwenden.

Standardmäßig lautet die Syntax zum Definieren eines Raw-Strings `r"( )"`, aber auch andere Begrenzungszeichen sind erlaubt.
Da runde Klammern `( )` und eckige Klammern `[ ]` in der Regex-Syntax beide häufig vorkommen (für Erfassungs- und Optionsgruppen), sind geschweifte Klammern `{ }` vielleicht eine gute Wahl.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## Übereinstimmungen erkennen

Hier sind einige Fragen und Funktionen, die bei der Beantwortung helfen können.

Einige Beispiele verwenden [`fruit`][ref-fruit], einen Vektor mit 80 Fruchtnamen, der zum Üben in `stringr` enthalten ist.

_Enthält ein String eine Übereinstimmung?_
[`str_detect()`][ref-str_detect] oder [`str_starts()`][ref-str_starts], `str_ends()`, um die Anker `^` oder `$` zu vermeiden.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_Nur Strings zurückgeben, die eine Übereinstimmung enthalten?_
Verwende [`str_subset()`][ref-str_subset], um die Strings zu erhalten, und `str_which()`, um die Indizes zu erhalten.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_Wie viele Übereinstimmungen gibt es in jedem String?_
[`str_count()`][ref-str_count]

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_Wo befindet sich die Übereinstimmung?_
[`str_view()`][ref-str_view] für die interaktive Nutzung, [`str_locate()`][ref-str_locate] oder allgemeiner `str_locate_all()`.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## Erfassungsgruppen

Häufig möchten wir wissen, _was_ übereinstimmt. 
Das erreicht man, indem man Erfassungsgruppen in runden Klammern in das Regex aufnimmt.

Es ist möglich, innerhalb desselben Regex auf Erfassungsgruppen zurückzuverweisen, mit `\1`, `\2` usw.
Zum Beispiel das Finden wiederholter Buchstabenpaare:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

Mit ähnlicher Syntax können Erfassungsgruppen in Ersetzungs-Strings verwendet werden:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

Sammle Übereinstimmungen für die spätere Verarbeitung mit der Funktion [`str_match()`][ref-str_match] für nur die erste Übereinstimmung oder `str_match_all()` für alle Übereinstimmungen.

Erfassungsgruppen erzeugen in jeder Sprache tendenziell komplizierte Ausgaben.
Der R-Ansatz (_der als zusätzliche Herausforderung auch vektorisiert ist_) besteht darin, aus `str_match()` eine Matrix zu erzeugen, mit einer Zeile pro Eingabe-String, wobei Spalte 1 den vollständigen übereinstimmenden String enthält und die übrigen Spalten die verschiedenen Erfassungsgruppen.

Die Verwendung benannter Gruppen kann von Vorteil sein, da sie zu Spaltennamen in der Ergebnis-Matrix werden.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

Wir haben in diesem Lehrplan nicht viel über Matrizen gesagt, aber es gibt ein [Konzeptdokument][concept-matrices-arrays], auf das du zugreifen kannst.
Matrizen passen nicht gut zum Tidyverse-Ökosystem, obwohl sie seit langem Teil von Base R sind.

Kurz zusammengefasst: Behandle Matrizen wie Vektoren mit zwei Indizes, in der Reihenfolge `[rows, cols]`.
Lass einen der beiden Indizes leer, um die gesamte Zeile bzw. Spalte zu erhalten.

Wenn du mit `m[r,]` eine einzelne Zeile `r` oder mit `m[, c]` eine einzelne Spalte `c` abrufst, wird der zurückgegebene Wert standardmäßig zu einem Vektor abgeflacht.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

Unweigerlich erzeugt [`str_match_all()`][ref-str_match] eine Ausgabe mit noch mehr Struktur:

- Das Ergebnis ist eine Liste mit einem Element pro Eingabe-String.
- Wenn es nur einen Eingabe-String gibt, entpackst du die Ausgabe mit der Indizierung `[[1]]`, wie im [Listen-Konzept][concept-lists] beschrieben.
- Jedes Element ist eine Matrix, mit Spalten wie bei `match()`.
- Jede Zeile in der Matrix ist eine erfolgreiche Erfassung.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

Natürlich können Übereinstimmungen fehlschlagen.
Das Ergebnis ist dann der spezielle Wert `NA`.
Sei darauf vorbereitet, dies zu testen, wie im [Nichts-Konzept][concept-nothingness] beschrieben.

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
