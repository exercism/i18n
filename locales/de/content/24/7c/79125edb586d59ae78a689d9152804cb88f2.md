# Über

Eine **Gleitkommazahl** ist eine Zahl, die einen Bruchteil haben kann, wie `-1.23` oder `3.1415`.

Um eine solche Zahl als Bytefolge darzustellen, verwendet x86-64 den [IEEE-754][ieee]-Standard.
Die zwei häufigsten Formate in diesem Standard sind Gleitkommazahlen mit einfacher Genauigkeit und Gleitkommazahlen mit doppelter Genauigkeit.
x86-64 unterstützt beide.

Eine Gleitkommazahl mit einfacher Genauigkeit ist 32 Bit breit, eine mit doppelter Genauigkeit 64 Bit.

## XMM-Register

In x86-64 gibt es 16 dedizierte Register für Gleitkommaarithmetik, benannt `xmm0` bis `xmm15`.

Diese Register sind mindestens 128 Bit breit, aber neuere Prozessoren erhöhen dies auf 256 Bit oder 512 Bit.
In der Praxis nutzen die meisten Gleitkommazahlen jedoch nur die niedrigsten 32 Bit oder 64 Bit, je nach gewünschter Genauigkeit.

## Umwandlung zwischen Zahlen

Es gibt eine Familie von Instruktionen zur Umwandlung zwischen Zahlenformaten: `cvtxx2yy`.

Sowohl `xx` als auch `yy` sind keine Literale, sondern Platzhalter:

- `xx` ist ein Platzhalter für den Typ des Quelloperanden.
- `yy` ist ein Platzhalter für den Typ des Zieloperanden.

Dieser Platzhalter kann viele Formen annehmen, darunter:

| Platzhalter | Bedeutung             |
| ----------- | --------------------- |
| `si`        | vorzeichenbehaftete Ganzzahl |
| `ss`        | 32-Bit-Gleitkommazahl |
| `sd`        | 64-Bit-Gleitkommazahl |

Zum Beispiel:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

Beachte, dass es möglich ist, eine 32-Bit-Ganzzahl in eine 64-Bit-Gleitkommazahl oder eine 64-Bit-Ganzzahl in eine 32-Bit-Gleitkommazahl umzuwandeln.
Ebenso ist es möglich, eine 32-Bit-Gleitkommazahl in eine 64-Bit-Ganzzahl oder eine 64-Bit-Gleitkommazahl in eine 32-Bit-Ganzzahl umzuwandeln.
Mit anderen Worten: Die Größe beider Operanden in einem `cvtxx2yy` _muss nicht gleich sein_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

Wenn die Gleitkommazahl nicht exakt als Ganzzahl ausgedrückt werden kann, rundet `cvtxx2si` die Zahl gemäß der Rundungssteuerung in einem speziellen Register namens `mxcsr`.
Dies kann ein Runden zur nächsten Zahl, ein Abrunden, ein Aufrunden oder ein Abschneiden sein.
Beim Funktionseintritt gibt es keinen garantierten Standardwert.

Beachte, dass ein exaktes Ergebnis nicht gerundet wird und daher nicht von der Rundungssteuerung betroffen ist.
Zum Beispiel würde `42.0` _immer_ in `42` umgewandelt werden.

Es gibt eine ähnliche Familie von Instruktionen mit dem Format `cvttxx2si` (mit einem zusätzlichen `t`), die das Ergebnis immer abschneidet.

## Runden

Die Instruktionsfamilie `roundxx` wandelt eine Gleitkommazahl im Quelloperanden in eine gerundete Gleitkommazahl um, die im Zieloperanden gespeichert wird.

Hier ist `xx` wie üblich ein Platzhalter für den Typ der Operanden: `ss` für Gleitkommazahlen mit einfacher Genauigkeit und `sd` für Gleitkommazahlen mit doppelter Genauigkeit.

Diese Instruktionen nehmen eine konstante Zahl als dritten Operanden.
Diese Zahl gibt den Rundungsmodus an:

| Zahl | Modus                |
| :--- | :------------------- |
| 0    | Nächste Zahl         |
| 1    | Abrunden (nach unten) |
| 2    | Aufrunden (nach oben) |
| 3    | Abschneiden          |

Zum Beispiel:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

Da diese Instruktionen ein exaktes Ergebnis liefern, können sie zur Vorbereitung auf ein `cvtxx2si` verwendet werden.

## Arithmetische Instruktionen

Viele Operationen mit Gleitkommazahlen verwenden Instruktionen mit einem ähnlichen Namen wie ihr Gegenstück für Ganzzahlen, ergänzen aber den nötigen Platzhalter (`ss` oder `sd`) am Ende.
Diese Instruktionen haben zwei Operanden und die übliche Semantik, auch diejenigen, die Multiplikation oder Division ausführen:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## Verschieben

Die Instruktionen zum Verschieben von einem XMM-Register in ein anderes sind `movss` oder `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

Es ist **nicht** möglich, einen Immediate-Wert (eine konstante vorzeichenbehaftete Ganzzahl) direkt in ein xmm-Register zu verschieben.
Diese Zahl muss zuerst in ein Allzweckregister verschoben und dann mit `cvtsi2xx` umgewandelt werden:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## Vergleiche

Es gibt zwei Gruppen von Instruktionen, um zwei Gleitkommazahlen zu vergleichen.
Sie haben die Form `comixx` und `ucomixx`, wobei `xx` entweder `ss` oder `sd` ist.
Beide setzen wie üblich Flags in `rflags`, mit derselben Semantik wie `cmp`.

Der Unterschied zwischen ihnen ist, dass `ucomixx` das `parity flag (PF)` setzt, wenn eine der beiden Gleitkommazahlen einen `NaN`-Wert hat, während `comixx` in diesem Fall eine Ausnahme auslöst.

Der Vergleich zwischen Gleitkommawerten ist _vorzeichenlos_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## Weitere Instruktionen

Es gibt noch viele weitere Instruktionen für die Arbeit mit Gleitkommazahlen, die gängige Operationen implementieren.
Einige davon sind:

| Instruktion | Beschreibung                                      |
| :---------- | :----------------------------------------------- |
| `sqrtxx`    | Berechnet die Quadratwurzel (`sqrt(x)`)          |
| `rcpss`     | Berechnet den Kehrwert (`1/x`)                   |
| `rsqrtss`   | Berechnet den Kehrwert der Quadratwurzel (`1/sqrt(x)`) |
| `minxx`     | Berechnet das Minimum (`min(x, y)`)              |
| `maxxx`     | Berechnet das Maximum (`max(x, y)`)              |

Wo ein `xx`-Platzhalter verwendet wird, kann er wie üblich die Form `ss` oder `sd` annehmen.
Allerdings funktionieren `rcpss` und `rsqrtss` nur mit Gleitkommazahlen einfacher Genauigkeit.

Diese Instruktionen haben alle zwei Operanden.

## Aufrufkonvention

In der System V ABI werden die ersten acht Gleitkommaargumente in der Reihenfolge von `xmm0` bis `xmm7` an Funktionen übergeben.
Gleitkommawerte werden von Funktionen in `xmm0` und, falls nötig, in `xmm1` zurückgegeben.

Alle `xmm`-Register stehen frei zur Verfügung, keines davon ist für den Aufrufer reserviert.

## Speicher

Gleitkommawerte können im Speicher mit derselben Semantik wie Ganzzahlen gleicher Größe definiert werden.
NASM (The Netwide Assembler, der von diesem Track verwendete Assembler) ermöglicht außerdem die Deklaration von Gleitkommawerten in wissenschaftlicher Notation.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```

## AVX/AVX2

Die AVX/AVX2-Erweiterungen der x86-64-Architektur führen neue Drei-Operanden-Formen für die Gleitkomma-Instruktionen ein, die Ziel und Quellen trennen.
Sie tragen das Präfix `v` (für _Vektor_), um sie von der oben gesehenen alten SSE-Form zu unterscheiden:

```x86asm
vaddss xmm0, xmm1, xmm2 ; xmm0 = xmm1 + xmm2 (32-bit floating-point)
vmulsd xmm2, xmm3, xmm4 ; xmm2 = xmm3 * xmm4 (64-bit floating-point)
```

In diesem Track haben wir uns auf Instruktionen und Register bis zu den vorherigen SSE-Erweiterungen beschränkt.
Das reicht aus, um die Grundlagen zu vermitteln, und gewährleistet Kompatibilität mit einer breiten Palette von CPUs.

Der Test-Runner unterstützt jedoch AVX und AVX2 vollständig.
