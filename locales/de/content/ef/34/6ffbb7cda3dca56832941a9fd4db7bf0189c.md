# Einführung

## `Base.@kwdef`

Mit dem Makro `Base.@kwdef` kannst du beim Definieren eines [Structs][struct] automatisch Konstruktoren definieren, die Schlüsselwortargumente entgegennehmen.
Außerdem kannst du damit Standardwerte für Felder festlegen.

Zum Beispiel definiert die folgende Definition

```julia
Base.@kwdef struct HumanStats
    birthyear::Int
    height::Int
    mass::Int
    bmi::Float64 = mass / (0.01 * height)^2
end
```

auf einmal drei Konstruktoren

```julia-repl
julia> methods(HumanStats)
# 3 methods for type constructor:
[1] HumanStats(; birthyear, height, mass, bmi) [...]
[2] HumanStats(birthyear::Int64, height::Int64, mass::Int64, bmi::Float64) [...]
[3] HumanStats(birthyear, height, mass, bmi) [...]
```

darunter einen Konstruktor, der auf Schlüsselwortargumenten basiert

```julia-repl
julia> HumanStats(
           birthyear = 2002,
           height = 193,
           mass = 83
       )
HumanStats(2002, 193, 83, 22.28247738194314)
```

wohingegen die Standarddefinition

```julia
struct HumanStats
    birthyear::Int
    height::Int
    mass::Int
    bmi::Float64
end
```

nur die folgenden zwei definiert

```julia-repl
julia> methods(HumanStats)
# 2 methods for type constructor:
[1] HumanStats(birthyear::Int64, height::Int64, mass::Int64, bmi::Float64) [...]
[2] HumanStats(birthyear, height, mass, bmi) [...]
```

und einen schlüsselwortbasierten Konstruktor manuell definieren müsste.

### Wann solltest du `Base.@kwdef` verwenden?

Schlüsselwortbasierte Konstruktoren sind besonders nützlich, um Structs zu erzeugen, die eine große Zahl von Argumenten entgegennehmen, vor allem wenn Typ oder Wert der Argumente nicht direkt erkennen lassen, was sie bedeuten.

Betrachte die folgende Definition:

```julia
dirk = BasketballPlayer(1978, 1994, 2019, 213, 111, 42, 1998, [2011], 31560, 11489, 3651)
```

Ohne die Definition des Typs zu kennen, ist nicht klar, was die einzelnen Werte bedeuten.
Und selbst wenn du die Definition kennst, müsstest du die Reihenfolge vermutlich immer wieder nachschauen.

Wenn du dagegen einen schlüsselwortbasierten Konstruktor verwendest, ist ihre Bedeutung sofort ersichtlich:

```julia
dirk = BasketballPlayer(
    birthyear = 1978,
    career_start = 1994,
    career_end = 2019,
    height = 213,
    weight = 111,
    number = 42,
    drafted = 1998,
    championships = [2011],
    points = 31560,
    rebounds = 11489,
    assists = 3651
)
```

~~~~exercism/caution
`Base.@kwdef` ist nicht exportiert und nicht im Handbuch dokumentiert und daher nicht Teil der [öffentlichen API von Julia][public-api].
Das bedeutet, dass seine Schnittstelle technisch nicht als stabil garantiert ist und sich zwischen kleineren Julia-Versionen ändern kann.

Das Makro wird jedoch im gesamten Ökosystem vielfach verwendet, und es ist unwahrscheinlich, dass es auf eine inkompatible Weise geändert wird.
