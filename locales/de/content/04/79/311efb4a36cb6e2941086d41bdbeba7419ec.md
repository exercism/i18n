# Einführung

## Das `error`-Interface

Fehlerbehandlung erfolgt in Go **nicht** über Exceptions.
Stattdessen sind Fehler normale _Werte_ von Typen, die das eingebaute `error`-Interface implementieren.
Das `error`-Interface ist sehr minimalistisch.
Es enthält nur eine Methode `Error()`, die die Fehlermeldung als String zurückgibt.

```go
type error interface {
  Error() string
}
```

Jedes Mal, wenn du eine Funktion definierst, in der während der Ausführung ein Fehler auftreten kann, der den Aufrufer erreichen muss, musst du `error` als einen der Rückgabetypen angeben.
Wenn die Funktion mehrere Rückgabewerte hat, ist `error` per Konvention immer der letzte.

```go
func DoSomething() (int, error) {
  // ...
}
```

## Einen einfachen Fehler erzeugen und zurückgeben

Du musst das `error`-Interface nicht immer selbst implementieren.
Um einen einfachen Fehler zu erzeugen, kannst du die Funktion `errors.New()` verwenden, die Teil des Pakets `errors` der Standardbibliothek ist.
Das Einzige, was du übergeben musst, ist die Fehlermeldung als String, und `errors.New()` kümmert sich darum, einen Wert zu erzeugen, der deine Nachricht enthält und das `error`-Interface implementiert.

Wenn die Funktion einen Fehler zurückgibt, ist es gute Praxis, für alle anderen Rückgabeparameter den Nullwert zurückzugeben:

```go
func DoSomething() (SomeStruct, int, error) {
  // ...
  return SomeStruct{}, 0, errors.New("failed to calculate result")
}
```

~~~~exercism/caution
Du solltest nicht davon ausgehen, dass alle Funktionen Nullwerte für die anderen Rückgabewerte liefern, wenn ein Fehler vorliegt.
Es ist gute Praxis, davon auszugehen, dass keiner der anderen Rückgabewerte sicher verwendet werden kann, wenn ein Fehler aufgetreten ist.
Die einzigen Ausnahmen sind Fälle, in denen die Dokumentation eindeutig angibt, dass andere Rückgabewerte im Fehlerfall aussagekräftig sind.
~~~~

Wenn du einen solchen einfachen Fehler an mehreren Stellen verwenden möchtest, solltest du eine Variable für den Fehler deklarieren, anstatt `errors.New` inline zu verwenden.
Per Konvention sollte der Name der Variable mit `Err` oder `err` beginnen (je nachdem, ob sie exportiert ist oder nicht).
Diese Fehlervariablen werden oft _Sentinel-Fehler_ genannt.

```go
import "errors"

var ErrNotFound = errors.New("resource was not found")

func DoSomething() error {
  // ...
  return ErrNotFound
}
```

Gib `nil` für den Fehler zurück, um zu signalisieren, dass während der Funktionsausführung keine Fehler aufgetreten sind:

```go
func Foo() (int, error) {
  return 10, nil
}
```

## Fehlerprüfung

Wenn du eine Funktion aufrufst, die einen Fehler zurückgibt, ist es üblich, den Fehlerwert in einer Variable namens `err` zu speichern.
Bevor du das tatsächliche Ergebnis der Funktion verwendest, musst du prüfen, dass kein Fehler aufgetreten ist.

Um zu vermeiden, dass du den „Happy Path“ deines Codes verschachtelst, sollten Fehlerfälle zuerst behandelt werden.
Wir können `==` und `!=` verwenden, um den Fehler mit `nil` zu vergleichen, und wir wissen, dass ein Fehler aufgetreten ist, wenn `err` nicht `nil` ist.

```go
func processUserFile() error {
	file, err := os.Open("./users.csv")
	if err != nil {
		return err
	}

	// do something with file
}
```

Meistens wird der Fehler, wie im obigen Beispiel gezeigt, im Funktionsstapel nach oben zurückgegeben.
Eine andere Möglichkeit, mit dem Fehler umzugehen, wäre, ihn zu loggen und mit einer anderen Operation fortzufahren.
Es ist gute Praxis, den Fehler entweder zurückzugeben oder zu loggen, niemals beides.

Da die meisten Funktionen in Go einen Fehler als einen der Rückgabewerte enthalten, wirst du das Muster `if err != nil` überall im Go-Code sehen und verwenden.

## Eigene Fehlertypen

Wenn du möchtest, dass dein Fehler mehr Informationen als nur den Fehlermeldungs-String enthält, kannst du einen eigenen Fehlertyp erstellen.
Wie bereits erwähnt, kann alles, was das `error`-Interface implementiert (d. h. eine Methode `Error() string` hat), in Go als Fehler dienen.

Üblicherweise wird ein Struct verwendet, um einen eigenen Fehlertyp zu erstellen.
Per Konvention sollten die Namen eigener Fehlertypen mit `Error` enden.
Außerdem ist es am besten, die Methode `Error() string` mit einem Pointer-Receiver einzurichten; sieh dir diesen [Stackoverflow-Kommentar][stackoverflow-errors] an, um die Begründung zu erfahren.
Beachte, dass das bedeutet, dass du einen Pointer auf deinen eigenen Fehler zurückgeben musst; andernfalls zählt er nicht als `error`, weil der Nicht-Pointer-Wert die Methode `Error() string` nicht bereitstellt.

```go
type MyCustomError struct {
  message string
  details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.message, e.details)
}

func someFunction() error {
  // ...
  return &MyCustomError{
    message: "...",
    details: "...",
  }
}
```
