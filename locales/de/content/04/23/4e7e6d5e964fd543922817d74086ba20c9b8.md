# Veränderbarkeit

Veränderbarkeit ist eine Eigenschaft eines bestimmten Bindings in Rust. Ein Binding ist entweder unveränderlich oder veränderlich. Der Wert eines unveränderlichen Bindings darf nicht geändert werden; der Wert eines veränderlichen Bindings kann geändert werden. Alle Bindings sind standardmäßig unveränderlich.

## Bindings

Ein Binding ist die Verknüpfung zwischen einem bestimmten Variablennamen, wie er im Quellcode steht, und einem bestimmten Speicherbereich, wie er zur Ausführungszeit vorliegt. Streng genommen existieren Bindings nur während der Kompilierung: Vor der Kompilierung ist noch kein Speicher tatsächlich belegt, und nach der Kompilierung arbeitet der Maschinencode ausschließlich mit Speicheradressen statt mit benannten Variablen.

Bindings werden typischerweise mit dem Schlüsselwort `let` erzeugt. Außerdem entstehen Bindings aus Funktionsparametern und unter bestimmten anderen Umständen.

Bindings können verschiedene Eigenschaften haben, von denen die wichtigste die Veränderbarkeit ist. Ein veränderliches Binding ist eines, bei dem es erlaubt ist, den Wert des gebundenen Speichers zu ändern. Rust verfolgt und erzwingt die Veränderbarkeit jedes Bindings streng, um sicherzustellen, dass Programme korrekt sind. Dazu lehnt es Programme ab, die fälschlicherweise versuchen, ein Binding zu ändern, das unveränderlich sein sollte.

## Veränderbarkeit

In der Praxis ist Veränderbarkeit oft einfach. Indem du das Schlüsselwort `mut` in der Definition des Bindings verwendest, erhältst du die Möglichkeit, den Wert zu ändern.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### Herabstufen von veränderlich zu unveränderlich

Ein Binding kann jederzeit von veränderlich zu unveränderlich herabgestuft werden. Dieser Vorgang ist transparent.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### Hochstufen von unveränderlich zu veränderlich

Im Allgemeinen ist es möglich, einen Wert jederzeit von unveränderlich zu veränderlich hochzustufen, wenn das Ownership übertragen wird.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

An `(1)` wird das Ownership des Strings von `x` auf `y` übertragen, was es uns ermöglicht, den Wert auf veränderlich hochzustufen.

### Veränderbarkeit in Funktionsparametern

Es gibt zwei verschiedene Möglichkeiten, wie Funktionsparameter veränderlich sein können. Die erste und üblichere Methode ähnelt der Übergabe per Referenz in C:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

In diesem Beispiel wurde die Veränderbarkeit an drei Stellen explizit annotiert. Alle drei Veränderbarkeits-Deklarationen sind erforderlich, damit veränderliche Referenzen funktionieren.
An `(2)` wird das Binding `x` als veränderlich deklariert. Dieses Binding ist der oberste Eigentümer des Werts.
An `(3)` wird dieser Wert veränderlich ausgeliehen, um ihn an die Funktion `increment` zu übergeben.
An `(1)` wird ein neues, veränderliches Binding `n` auf die entsprechende Referenz erzeugt.

Es gibt einen weiteren Stil der Parameter-Veränderbarkeit, der seltener ist, aber manchmal trotzdem nützlich. Bei diesem Stil ist der Wert im Besitz, aber das Binding ist veränderlich.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

Dieses Beispiel erfordert weniger explizite Annotationen, weil es tatsächlich eine Ownership-Übertragung mit eingebauter Veränderbarkeits-Hochstufung ist. Es funktioniert, weil `i32` ein `Copy`-Typ ist, der Daten transparent kopiert.
An `(1)` deklarieren wir, dass `increment_internally` einen veränderlichen, besessenen `i32` namens `n` als Parameter akzeptiert.
An `(2)` deklarieren wir `x` als unveränderliches Binding auf den Wert `1`.
An `(3)` wird `x` an eine neue Stelle im Speicher kopiert. `x` bleibt unveränderlich. `n` ist veränderlich.

Es ist natürlich möglich, die Formen zu kombinieren und ein veränderliches Binding auf eine veränderliche Referenz zu legen (`mut n: &mut i32` usw.), aber das ist selten das, was man wirklich will.

### Veränderbarkeit ohne `let`

Mehrere Konstrukte in Rust (`if let`, `match` usw.) können ebenfalls Bindings erzeugen. Diese Bindings können auch veränderlich sein.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

Dieses Beispiel erzeugt zuerst `v = Some(2)`, dann `v = None`.

## Shadowing

Es ist möglich und oft idiomatisch, einen Variablennamen wiederzuverwenden, während ein bestimmter Wert umgewandelt wird, indem er mit mehreren `let`-Aufrufen neu deklariert wird. Das nennt man Shadowing.

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

Dies ist jedoch kein Fall von Veränderbarkeit; die ursprünglichen Werte sind im Prinzip noch vorhanden. Bei Nicht-`Drop`-Typen kann der Compiler sich dafür entscheiden, eine Speicherstelle zu verändern, statt eine neue zu reservieren. Bei einem `Drop`-Typ oder wenn das alte Binding erneut verwendet wird, wird er das jedoch nie tun.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
