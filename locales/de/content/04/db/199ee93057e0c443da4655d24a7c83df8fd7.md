# Über

## Gleichheit

Elm-Typen können mit dem [Gleichheitsoperator][equality-operator] `(==)` darauf geprüft werden, ob sie „gleich“ sind.
Der Ungleichheitsoperator ist `(/=)` (*nicht* `!=` wie in vielen Sprachen).

```elm
1 == 2
    --> False

1 /= 2
    --> True
```

Beide verglichenen Werte müssen denselben Typ haben.
Der Gleichheitsoperator funktioniert mit Literalen, Tupeln, Records und eigenen Typen.
Der Operator prüft auf strukturelle Gleichheit. Das bedeutet, dass gleiche Werte den gleichen Inhalt und die gleiche tiefe Struktur haben, unabhängig von Typannotation oder Position im Speicher.

```elm
(1, 2) == (2, 1)
    --> False

type alias MyRecord = { myInt : Int, myStrings : List String }
a : MyRecord
a = MyRecord (1 + 1) ["hello world"]

type alias MyOtherRecord = { myInt : Int, myStrings : List String }
myStrings =  (String.join " " ["hello", "world"]) :: []
b : MyOtherRecord
b = { myInt = 2, myStrings = myStrings}

a == b
    --> True
```

Beachte, dass du *niemals* Funktionen vergleichen solltest, da das Programm sonst zur Laufzeit abstürzt.
Mehr Informationen zu dieser Einschränkung findest du [hier][equality-operator].

## Vergleiche

Die [Vergleichsoperatoren][comparison-operators] `(<)`, `(<=)`, `(>)`, `(>=)` und die Funktionen `min`, `max`, `compare` funktionieren mit `comparable`-Typen.
Der `comparable`-Typ ist ein spezieller Typ, der alle eingebauten Typen zusammenfasst, die verglichen werden können: Zahlen, Zeichen, Strings, Listen vergleichbarer Dinge und Tupel vergleichbarer Dinge.
Zeichen werden anhand ihrer [Unicode-Codepunkte][unicode-codepoint] verglichen.

```elm
1 < 1 + 1
    --> True

'x' < 'X'
    --> False

'互' < '🙏'
    --> True
```

Sequenzartige Typen (Strings, Listen und Tupel) werden in [lexikografischer Reihenfolge][lexicographic-order] verglichen.
Kurz gesagt: Sequenzelemente werden paarweise der Reihe nach verglichen, bis ein Element kleiner ist oder eine Sequenz endet.

```elm
"abc" < "abz"
    --> True

"abc" < "abcd"
    --> True

"abc" < "b"
    --> True

min [1 , 2, 9000] [10]
    --> [1 , 2, 9000]

min (1, "hello") (3, "bye")
    --> (1, "hello")

min (1, ['a', 'b']) (1, ['A', 'B'])
    --> (1, ['A', 'B'])
```

Werte anderer Typen wie Records oder eigene Typen können nicht direkt verglichen werden.

Einige eingebaute Typen erfordern, dass ihr Inhalt `comparable` ist, etwa die Schlüssel von `Set` oder `Dict`, da ihre Struktur auf einer internen Ordnung beruht.
Das bedeutet, dass eigene Typen nicht in einem `Set` gespeichert werden dürfen, obwohl es Alternativen aus der Community gibt: [`AnySet`][any-set], [`AnyDict`][any-dict], [`Sort`][sort] und andere.

Listen von `comparable`-Werten können mit `List.sort` sortiert werden, und Listen von Werten, die auf vergleichbare Werte abgebildet werden können, können mit `List.sortBy` sortiert werden.
Wenn du eine hierarchische Sortierung brauchst (nach einer Eigenschaft sortieren und Gleichstände mit einer anderen auflösen), können Tupel oder Listen mit `List.sortBy` verwendet werden (unter anderem mit [Alternativen][sort-by]), da Tupel und Listen in lexikografischer Reihenfolge sortiert werden.


```elm
List.sort ["hi", "hello", "bye", "goodbye"]
    --> ["bye", "goodbye", "hello", "hi"]

List.sortBy String.length ["hi", "hello", "bye", "goodbye"]
    --> ["hi", "bye", "hello", "goodbye"]

-- sort by length, then alphabetically
List.sortBy (\str -> (String.length str, str)) ["hi", "mum", "hello", "sis", "bye", "dad"]
    --> ["hi", "bye", "dad", "mum", "sis", "hello"]
```

Die Funktion `compare` nimmt zwei `comparable`-Werte und gibt eine `Order` zurück.
Eine `Order` ist ein Typ, der in einer einzigen Operation prüft, ob ein Wert größer (`GT`), gleich (`EQ`) oder kleiner (`LT`) als ein anderer ist.

```elm
compare 1 2
    --> LT

compare "" ""
    --> EQ

compare [12] []
    --> GT
```

Vergleichsfunktionen können für beliebige Typen erstellt und zum Beispiel mit `List.sortWith` zum Sortieren verwendet werden:

```elm
type Color = Red | Green | Blue

compareColors : Color -> Color -> Order
compareColors a b =
  case (a, b) of
    (Red, Red) -> EQ
    (Red, _) -> LT
    (_, Red) -> GT
    (Green, Green) -> EQ
    (Green, _) -> LT
    (_, Green) -> GT
    (Blue, Blue) -> EQ

List.sortWith compareColors [Blue, Red, Green, Green, Blue]
    --> [Red, Green, Green, Blue, Blue]
```
