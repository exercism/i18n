# Einführung

An diesem Punkt im Lehrplan hast du R schon oft als imperative Sprache erlebt und zunehmend als funktionale Sprache (besonders mit den Bibliotheken [`purrr`][ref-purrr] und [`dplyr`][ref-dplyr]).

Wenn ich jetzt behaupte, dass R in erster Linie objektorientiert ist, stößt das vielleicht auf Skepsis!

Seltsamerweise stimmt dieser Satz.
Intern ist R mit Klassen, Vererbung, Polymorphismus und der Einstellung umgesetzt, die für OOP-Programmierer typisch ist.

Wer jedoch Java oder Ruby (ausdrücklich OOP) oder auch Python (in mancher Hinsicht halb versteckt OOP) kennt, wird den Ansatz von R ... _ungewohnt_ finden.

Zum einen gibt es mehrere Klassendesigns: vielleicht drei, die häufig verwendet werden (S3, S4, R6), dazu diverse andere, die vor allem von theoretischem Interesse sind.

Eine ausführliche Diskussion findest du in [Advanced R, 2e][book-advanced-r], Kapitel 12-16.
Dieses Buch von 2019 richtet sich vor allem an Menschen, die das Innenleben von R verstehen und pflegen wollen, deshalb ist OOP dort unverzichtbar.

Stärker an Endnutzer ausgerichtete Lehrbücher gehen unterschiedlich damit um.

- The Art of R Programming (2011, nur gedruckt) hat ein OOP-Kapitel über S3 und (kürzer) S4, die damals wichtig waren.
  Der Kommentar, dass _„S3-Klassen eine ziemlich zusammengeschusterte Struktur haben“_, trifft immer noch verblüffend zu.
- R in Action (3. Aufl., 2022) verbannt OOP auf 3 Seiten in einem Kapitel über fortgeschrittene Programmierung gegen Ende.
- [R for Data Science, 2e][book-r-data-sci] (2023, 548 Seiten in der Druckausgabe) erwähnt OOP überhaupt nicht.

Dieses Konzept konzentriert sich auf S3-Klassen, die einfachsten, gebräuchlichsten und für Aufgaben vom Exercism-Typ relevantesten.
Einige der Praxisübungen im R-Track verlangen, dass du eine S3-Klasse erstellst; bei anderen ist das optional, aber durchaus erwünscht.

## S3-Klassen

Sie sind alt: Der Name S3 bedeutet nur, dass sie in Version 3 der Sprache S eingeführt wurden (ein kommerzieller Vorläufer von R).

Eine S3-Klasse ist zudem sehr einfach: typischerweise eine [Liste][concept-lists] mit mindestens einem zusätzlichen Attribut.

Aus [Advanced R][book-s3]: _„S3 ist informell und ad hoc, aber sein Minimalismus hat eine gewisse Eleganz: Man kann keinen Teil davon wegnehmen und hat immer noch ein nützliches OO-System.“_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

Eine Zuweisung an [`class(obj)`][ref-class] fügt also einfach ein Attribut zu `obj` hinzu, das hier pt2d als Instanz der Klasse point2d kennzeichnet.

Die Erstellungsschritte lassen sich mit [`structure()`][ref-structure] kombinieren:

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

Obwohl die resultierenden Instanzen begrifflich identisch sind, haben wir noch keinen Weg umgesetzt, wie R das bestätigen kann.

### Generische Methoden

Wer OOP aus anderen Sprachen kennt, fragt sich vielleicht: _„Sollen Klassen nicht in der Lage sein, etwas zu TUN?“_

Wir können nachsehen, welche Methoden für `point2d`-Instanzen verfügbar sind, und stellen fest, dass es derzeit keine gibt (anders als bei der zugrunde liegenden `list`).

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

In den meisten OOP-Sprachen werden Methoden innerhalb der Klassendefinition definiert.
Einige wenige Sprachen (vor allem Ruby) erlauben es, Klassenmethoden später hinzuzufügen und zu ändern.

S3-Klassen funktionieren ganz anders.
Statt Methoden zu einer Klasse hinzuzufügen, fügen wir die Klasse zu einer generischen Methode hinzu.

Wer interaktiv in der R-Konsole arbeitet, verwendet ständig generische Methoden, meist ohne darüber nachzudenken, wie sie umgesetzt sind.

Ein sehr häufiges Beispiel ist `print()`, auch wenn du den Funktionsnamen selten eintippst.
Einen Wert `x` allein an der Konsoleneingabe einzugeben, ist nur syntaktischer Zucker für `print(x)`.

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

Wir können `pt2d` bereits ausgeben.
`print()` weiß zwar nichts über die Klasse `point2d`, hat aber sinnvolle Standardwerte, um eine Vielzahl von Objekten zu behandeln.

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

Das ist ziemlich ausführlich, und wir hätten gern eine Möglichkeit, den Punkt knapp und schön auszugeben.

Ganz einfach: Füge eine Funktion namens `print.point2d()` hinzu.
Der Name muss die Form `methodname.classname` haben, damit der Dispatcher weiß, wonach er suchen muss.

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

Nehmen wir nun an, wir wollen eine neue generische Methode erstellen, zum Beispiel `flipvert()`, um das Vorzeichen der `y`-Koordinate umzukehren.

Wieder ganz einfach:

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

Damit wird ein Dispatcher erstellt, wobei `x` unser Objekt mit einer S3-Klasse ist und `...` alle zusätzlichen Argumente verarbeitet, die Methodendefinitionen brauchen könnten („dot args“, wie im [Konzept Funktionen][concept-functions] beschrieben).

Anschließend können wir die Methode für `point2d` definieren und verwenden.

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

R weiß jetzt, wie es unseren Punkt umkehrt und wie es das Ergebnis anzeigt.

Wir könnten das erweitern, indem wir Klassen für 3D, für Polarkoordinaten usw. erstellen und dann für jede Methoden definieren.

Aus Sicht der Endnutzer gibt es nur `flipvert(x, ...)`, und wir können uns darauf verlassen, dass R die Eingabeklasse bestimmt und die passende zugrunde liegende Umsetzung verwendet.

~~~~exercism/caution
Funktionsnamen im Format `verb.class` sehen sowohl für Nutzer als auch für den R-Parser wie S3-Methoden aus.
Bitte vermeide ähnliche Namen in anderen Zusammenhängen.

Zugegeben, base R verstößt manchmal gegen diese Regel.
Wir sollten das als unglücklichen historischen Zufall betrachten (für Funktionen, die sogar älter als S3 sind), der aus Gründen der Abwärtskompatibilität erhalten bleiben muss.
~~~~

### Vererbung

OOP-Begeisterte können mehrere lange Lehrbuchkapitel über Vererbung, Unterklassen, Mixins und alles Weitere schreiben.

R erlaubt es einfach, dem Attribut `class` mehrere Namen zu geben: einen längeren Vektor aus Strings statt eines einzelnen Strings.

Auf die Gefahr hin, das Beispiel bis zum Zerreißen zu dehnen: Angenommen, wir hätten eine generische Klasse `point` erstellt und wollten davon `point2d`, `point3d` usw. ableiten.

Dann verwendet die Definition von `point2d` einfach `class = c("point2d", "point")`: die spezifische Klasse und die Elternklasse (oder Elternklassen).

Generische Methoden wie `print()` suchen dann der Reihe nach nach `print.point2d()`, `print.point()` und (wahrscheinlich) `print.default()` und verwenden die erste Umsetzung, die der Dispatcher findet.

### Sicherheit

Viele OOP-Sprachen (Java, C# usw.) nutzen die Datenkapselung innerhalb von Klassen, um sorgfältige Prüfungen zur Kompilierzeit durchzuführen und Typsicherheit zu erzwingen.

Sei dir bewusst, dass S3 dich so ziemlich alles tun lässt, was du willst, selbst wenn es keinen Sinn ergibt (eine Fehlermeldung kommt später, wenn überhaupt).

Aus [„Advanced R“][book-s3] (2. Aufl., Abschnitt 13.3):

> _Wenn du andere OO-Sprachen verwendet hast, kann dir das mulmig werden, aber in der Praxis verursacht diese Flexibilität nur wenige Probleme. R hindert dich nicht daran, dir selbst in den Fuß zu schießen, aber solange du die Waffe nicht auf deine Zehen richtest und abdrückst, wirst du kein Problem haben._

Na ja, _okay?_
R ist hervorragend für explorative Datenwissenschaft und Statistik, oft bei interaktiver Arbeit.
Niemand behauptet, du solltest damit hochsichere Finanzsysteme für Unternehmen schreiben!
