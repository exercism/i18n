# Einführung

[Custom Types][custom-types] in Elm stehen für eine feste Anzahl benannter Fälle. Jeder Wert entspricht genau einem dieser benannten Fälle.

Ein Custom Type wird mit dem Schlüsselwort `type` definiert und kommt mit sehr wenig Syntax aus. Custom Types gehören zu den wichtigsten Techniken der Elm-Programmierung: Mit ihnen sorgst du dafür, dass die möglichen Werte im Code genau den gültigen Werten im echten Leben entsprechen. So bleibt kein Raum für ungültige Daten, und [unmögliche Zustände lassen sich gar nicht erst im Code darstellen][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Jeder Fall eines Custom Type kann optional Daten enthalten, und verschiedene Fälle können verschiedene Datentypen haben. Wenn kein Fall Daten enthält, ähnelt die diskriminierte Union dem, was andere Sprachen üblicherweise als _Enumeration_ (oder _Enum_) bezeichnen.

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Einen Wert für einen bestimmten Fall erzeugst du, indem du seinen Namen angibst (`Spring`). Das geht, wenn der Fall im selben Modul definiert ist oder mit der Syntax `import SeasonModule exposing (Season(..))` importiert wurde. Alternativ gibst du seinen vollqualifizierten Namen an (`Season.Spring`), wenn du ihn mit der Syntax `import SeasonModule exposing (Season)` importiert hast.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Wie alles in Elm besitzen Custom Types _strukturelle Gleichheit_. Das heißt: Zwei Werte, die zum selben Fall gehören und dieselben (optionalen) Daten tragen, sind gleichwertig.

Am besten arbeitest du mit Custom Types über [Pattern Matching][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
