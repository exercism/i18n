# Einführung

Sobald ein Wert dein Programm verlässt, sei es auf eine Leitung, in eine Logdatei oder über einen Socket, muss er *Text* sein. Drei Factor-Idiome begegnen dir immer wieder, wenn du Werte für die Übertragung packst: der Serializer `unparse`, die Slice-Varianten, die eine Sequenz ansehen, ohne sie zu kopieren, und die Cleave-Kombinatoren mit mehreren Eingaben, mit denen du mehrere Felder in einer einzigen Phrase vom Stack projizieren kannst.

```factor
USING: combinators kernel prettyprint sequences strings ;

123 unparse .                          ! => "123"
"NS-1024" 2 head-slice >string .       ! => "NS"
1 2 [ + ] [ - ] 2bi . .
! => -1
! => 3
```

`unparse` ist die Umkehrung von Factors Parser: `dup unparse parse` liefert wieder den Ausgangswert. `head-slice` gibt eine *Sicht* (ein `slice`-Objekt) zurück, statt wie `head` eine neue Sequenz anzulegen. Das ist nützlich, wenn du nur einen Bereich ansehen willst. `2bi`, `3bi`, `2tri` und `3tri` erweitern die Cleave-Familie auf zwei oder drei Stack-Eingaben.
