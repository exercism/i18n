# Einführung

Meistens erledigt Factor die Iteration über Kombinatoren wie
`each`, `map` und `count`. Manchmal ist aber **Rekursion** der
sauberste Weg, eine Berechnung auszudrücken: ein Wort, das sich
selbst aufruft.

## Ein rekursives Wort definieren

Eine `:`-Definition kann sich selbst direkt aufrufen:

```factor
: count-down ( n -- )
    dup 0 = [ drop ] [ dup . 1 - count-down ] if ;

5 count-down
! prints 5 4 3 2 1
```

## Verzweigung nach leer oder nicht leer

`if-empty` (in [`sequences`][sequences]) ist der natürliche
Basisfall der Rekursion:

```
if-empty ( seq emptyquot nonemptyquot -- )
```

```factor
{ 4 0 9 } [ "empty" ] [ "got data" ] if-empty .
! => "got data"
```

`emptyquot` läuft, nachdem die (leere) Sequenz bereits vom Stack
genommen wurde; `nonemptyquot` läuft, während die Sequenz noch auf
dem Stack liegt.

## `cond`: eine Kette von bedingten Zweigen

Wenn deine Rekursion mehr als zwei Fälle hat, hält `cond` (in
[`combinators`][combinators]) den Code lesbar:

```factor
: classify ( n -- label )
    {
        { [ dup 0 < ] [ drop "negative" ] }
        { [ dup 0 = ] [ drop "zero"     ] }
        [ drop "positive" ]
    } cond ;
```

## Vorwärtsreferenzen mit `DEFER:`

Eine `:`-Definition kann sich selbst direkt aufrufen, aber wenn
zwei Wörter sich *gegenseitig* aufrufen, sieht der Parser das erste
schon, bevor das zweite existiert. `DEFER:` reserviert einen Namen,
damit sich die erste Definition kompilieren lässt:

```factor
DEFER: even?

: odd? ( n -- ? ) dup 0 = [ drop f ] [ 1 - even? ] if ;
: even? ( n -- ? ) dup 0 = [ drop t ] [ 1 - odd? ] if ;
```

`DEFER:` ist auch praktisch, wenn ein Hilfswort natürlicher
* nach* dem Wort gelesen wird, das es verwendet.
