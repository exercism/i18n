# Installation

Dieser Track setzt durchgehend auf [Node.js][web-nodejs], um eine Laufzeitumgebung für JavaScript bereitzustellen.
Das bedeutet, wir gehen davon aus, dass die gesamte Ausführung von JavaScript auf deinem Computer mit [Node.js][web-nodejs] erfolgt.

## Voraussetzungen für den Track

Viele Rechner haben [Node.js][web-nodejs] bereits vorinstalliert, oder es wurde schon früher oder als Abhängigkeit installiert.
Bevor wir also irgendetwas tun, sollten wir prüfen, ob es bereits installiert ist:

1. Öffne ein _Terminal_ (`Terminal`, `cmd`, `Powershell`, `bash`, ...)
1. `node -v`

Wenn [Node.js][web-nodejs] installiert ist, wird eine Version angezeigt.
Notiere diese Version.
Wenn [Node.js][web-nodejs] _nicht_ installiert ist, wird ein Fehler ausgegeben.
Meistens so etwas wie `'node' is not recognised`.

## Node.js

### Wenn Node.js vorinstalliert ist

Rufe [die Node.js-Website][web-nodejs] auf.
Sie zeigt dir _zwei_ Versionen an (wenn sie dein Betriebssystem erkennt; andernfalls wähle zuerst dein Betriebssystem aus).
Wenn die Version von `node -v` mit einer davon übereinstimmt, passt alles.
Wenn nicht, empfehlen wir dir, Node.js LTS zu verwenden.
Wenn du befürchtest, dass ein Upgrade etwas auf deinem System kaputt macht, kannst du einfach weitermachen, als wäre alles in Ordnung;
wenn dann etwas Unerwartetes passiert, können wir möglicherweise keinen Support bieten.

### Wenn Node.js nicht installiert ist

Es gibt mehrere Wege, [Node.js][web-nodejs] zu installieren:

- über einen [Installer oder ein Binary][web-nodejs-download]
- über einen [Paketmanager][web-nodejs-package]

Beide Optionen funktionieren unter Windows, macOS und Linux. Wenn du nicht weißt, was du tun sollst, ist ein Installer der einfachste Weg.

- Wir empfehlen die **LTS**-Version. Sie ist auf der [Node.js][web-nodejs]-Website auch als _empfohlen_ „für die meisten Nutzer“ gekennzeichnet.
- Folge den Anweisungen auf der Webseite und/oder während der Installation und installiere [Node.js][web-nodejs].

## Die Installation testen

Wenn der Installer fertig ist, der Paketmanager durchgelaufen ist oder das Binary kopiert und die Anweisungen befolgt wurden, solltest du testen, ob alles in Ordnung ist.

1. Öffne ein _Terminal_ (`Terminal`, `cmd`, `Powershell`, `bash`, ...)
1. `node -v`

Die Version sollte mit der auf der Website übereinstimmen.

> [!NOTE]
> Es ist wichtig, ein _neues_ Terminalfenster zu öffnen.
> Bereits geöffnete Terminalfenster wurden nach Abschluss der Installation möglicherweise nicht aktualisiert.
> Das bedeutet, dass die offenen Terminals nicht wissen, dass ein neues Programm installiert wurde.

> [!IMPORTANT] > _**Hilfe**_: `'node' is not recognised`
>
> Wenn du den offiziellen Installer verwendet hast, sollte dein `PATH` automatisch konfiguriert worden sein. Falls deine Shell aber Probleme hat, global installierte Module zu finden, oder falls du Node.js aus dem Quellcode baust, aktualisiere deinen `PATH` so, dass er die `npm`-Binaries enthält.
>
> Unter macOS und Linux kannst du das erreichen, indem du Folgendes entweder zu `~/.bash_profile` oder zu `~/.zshrc` hinzufügst:
>
> ```shell
> export PATH=/usr/local/share/npm/bin:$PATH
> ```
>
> Öffne unter Windows das Startmenü und suche nach „environment variables“.
> Dort musst du den `PATH`-Eintrag bearbeiten und den Pfad zu den `npm`-Binaries _hinzufügen_.
> Normalerweise findest du sie unter `C:\Program Files\nodejs`.
> Wenn du mit deinem `File Explorer` dorthin navigierst, solltest du `node.exe`, `npm.bat` und `npx.bat` finden.
>
> Schließe alle geöffneten Terminals und öffne ein neues.

## Corepack aktivieren

Um einen versionierten Paketmanager zu verwenden, der mit diesem Track kompatibel ist, muss `corepack` einmal aktiviert werden:

```shell
corepack enable pnpm
```

## Voraussetzungen für die Übungen

Folge [dieser Anleitung][cli-walkthrough], um die Exercism CLI für dein Betriebssystem herunterzuladen.

Sobald die Exercism CLI eingerichtet und konfiguriert ist, lade die erste Übung herunter, `hello-world`:

```shell
exercism download --exercise=hello-world --track=javascript
```

Für jede Übung brauchst du dann einige Tools, um die Tests auszuführen.
Du kannst sie installieren, indem du diesen Befehl im Verzeichnis der jeweiligen Übung ausführst:

```shell
corepack pnpm install
```

Da dieser Track auf pnpm umgestiegen ist, musst du dir keine Gedanken über den Speicherplatz machen.
Wirf einen Blick auf [pnpm](https://pnpm.io/), das dafür sorgt, dass jede Paketversion nur ein einziges Mal auf der Festplatte installiert wird.

> **Doch was ist corepack, und warum funktioniert das?**
>
> Diese Information brauchst du nicht, um den JavaScript-Track abzuschließen, aber wenn du unbedingt verstehen möchtest, was gerade passiert ist, sind die folgenden Absätze für dich gedacht:
>
> Das funktioniert, weil `corepack` ein Tool ist, das mit Node.js mitgeliefert wird, das du nach den obigen Schritten installiert hast.
> Es kann den Paketmanager `pnpm` installieren. Es konfiguriert das System.
> Der Befehl `corepack` sucht nach einer `package.json`-Datei, die in _jedem_ Übungsordner vorhanden ist.
> Dann prüft er `packageManager`, was zu `pnpm` passt, sodass er fortfahren kann. Falls nötig, aktualisiert er zuerst `pnpm`.
> Diese Datei listet außerdem die oben genannten `"dependencies"` auf, die anschließend von `pnpm` heruntergeladen und in einem lokalen Cache abgelegt werden.
>
> Die Skripte in der `package.json` verwenden die Binaries aus dem lokalen Cache, und genau diese Skripte werden verwendet, um die Tests auszuführen, wie in der Beschreibung von `exercise` aufgeführt.
