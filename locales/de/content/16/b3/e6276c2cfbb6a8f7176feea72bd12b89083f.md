# Über

Der Typ `Result` ist in Elm die Lösung für Fehlerberichterstattung und Fehlerbehandlung. Er ähnelt dem Typ `Maybe` ein wenig, aber während das `Nothing` von `Maybe` eine Art von Fehlschlag kodiert, sagt es dir nichts darüber, _warum_ etwas fehlgeschlagen ist. `Result` enthält einen Kontext darüber, warum etwas fehlgeschlagen ist.

## Definition und Typvariable

Der Typ `Result` ist so definiert:

```elm
type Result error value
  = Ok value
  | Err error
```

Kurz gesagt kodiert dieser Typ das Ergebnis einer Operation, die entweder erfolgreich sein und einen `value` zurückgeben kann oder fehlschlagen und eine Erklärung für den Fehlschlag zurückgeben kann (`error`).

In der Elm-Terminologie heißt das „custom type“. Custom Types werden in einem anderen Konzept dieses Tracks ausführlich vorgestellt, aber wir brauchen sie nicht, um speziell `Result` zu verstehen.
Das `error` und `value` in `OK value` und `Error error` stehen für eine Typvariable, das heißt, sie kann jeder Typ sein, etwa `Int`, `Bool` oder `String`.
Ein `Result String Int` ist also ein Wert, von dem erwartet wird, dass er einen `Int` enthält, und wenn ein Fehler auftritt, wird dieser als `String` dargestellt.

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## Den Inhalt eines Result-Werts lesen

Den Inhalt eines `Result`-Werts liest du über den „Musterabgleich“ aus.
Der Musterabgleich wird ebenfalls in einem anderen Konzept ausführlicher vorgestellt, deshalb konzentrieren wir uns hier nur darauf, wie der Musterabgleich bei einem `Result` funktioniert.

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

Jedes Mal, wenn du einen `Result`-Wert verwendest, prüft der Elm-Compiler, dass dein Code alle Möglichkeiten abdeckt. Du kannst also nie einen `Result` mit Musterabgleich behandeln und dabei nur den Fall abdecken, in dem ein `Ok value` vorliegt.
Das mag am Anfang lästig wirken, aber es ist eine der größten Stärken der Sprache Elm.
So werden Hunderte von Bugs verhindert, und Refactoring mit Unterstützung des Compilers wird zu einer furchtlosen und lohnenden Erfahrung.

## Den Inhalt eines Result-Werts verändern

Es gibt verschiedene Funktionen für die Arbeit mit `Result`-Typen, die meist dem Musterabgleich vorzuziehen sind. Mit `Result.map` kannst du den Wert abbilden, und mit `Result.andThen` kannst du Funktionen verketten, die fehlschlagen können.

Result.map wird verwendet, um den Ok-Wert zu ändern, und ist nützlich, um Funktionen zu verketten, ohne dir Gedanken darüber machen zu müssen, ob das Result einen Fehler enthält. Wenn der Wert Ok ist, ruft Result.map die verkettete Funktion auf (`formatAge` unten), aber wenn ein Fehler vorliegt, tut Result.map nichts und gibt einfach den Fehler zurück.

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

Result.andThen wird verwendet, um den Ok-Wert zu ändern, und ist nützlich, um Funktionen zu verketten, ohne dir Gedanken darüber machen zu müssen, ob das Result einen Fehler enthält. Es ähnelt Result.map, aber Result.andThen arbeitet mit einer verketteten Funktion (`formatSpecialBirthday` unten), die ebenfalls ein Result zurückgibt. `Result.map` kann das auch, aber am Ende entsteht eine zusätzliche Verschachtelungsebene, die `andThen` geschickt vermeidet.

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
