# Ergänzung zu den Anweisungen

## Node-Prozess

Anders als bei anderen Übungen wird `grep.js` _nicht_ in die Testdatei `grep.spec.js` importiert. Stattdessen wird es verwendet, als wäre es eine ausführbare Datei. Damit das funktioniert, wurde die Datei `grep.js` mit einem Shebang und einem Kommentar eingerichtet, der erklärt, was dieser bewirkt:

```javascript
#!/usr/bin/env node

// The above line is a shebang. On Unix-like operating systems, or environments,
// this will allow the script to be run by node, and thus turn this JavaScript
// file into an executable. In other words, to execute this file, you may run
// the following from your terminal:
//
// ./grep.js args
//
// If you do not have a Unix-like operating system or environment, for example
// Windows without WSL, you can use the following inside a window terminal,
// such as cmd.exe:
//
// node grep.js args
//
// Read more about shebangs here: https://en.wikipedia.org/wiki/Shebang_(Unix)
```

Die Tests starten einen neuen Node-_Prozess_, der `grep.js` ausführt.

## Argumente lesen

Um die Argumente abzurufen, mit denen der _Prozess_ gestartet wurde, verwendest du `process.argv`.

## Dateien lesen

Die Funktion `readLines` ist bereits vorhanden. Du musst den Dateipfad nicht umwandeln, um sie zu verwenden. Die Funktion `readlines` _löst_ den Pfad ausgehend vom aktuellen Arbeitsverzeichnis auf, das für die `grep.js`-Prozesse auf das Übungsverzeichnis gesetzt ist.

## Ausgabe schreiben

Um Ausgaben zu schreiben, verwendest du

- `console.log`, um in die Standardausgabe zu schreiben,
- `console.error`, um in die Standardfehlerausgabe zu schreiben.

Die Tests betrachten die Ausführung als erfolgreich (resolved), wenn nichts in die Standardfehlerausgabe geschrieben wird, und als nicht erfolgreich (rejected), wenn etwas in die Standardfehlerausgabe geschrieben wird.
