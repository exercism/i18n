# Einführung

Das Konzept [`Basics`][basics] hat zwei Möglichkeiten vorgestellt, eine Funktion zu definieren.

Am allgemeinsten ist die mehrzeilige Form:

```julia
function muladd(x, y, z)
    x * y + z
end
```

Die „Zuweisungs“- oder „einzeilige“ Form für kurze Definitionen:
```julia
muladd(x, y, z) = x * y + z
```

In einer dritten, noch kürzeren Form lässt sich eine kurze, nur einmal verwendete Funktion ohne Namen erstellen:

```julia-repl
julia> map(x -> 2x, 1:3)
4-element Vector{Int64}:
 2
 4
 6

julia> map((x, y) -> x * y, 1:3, 4:6)
3-element Vector{Int64}:
  4
 10
 18
```

In diesem Fall ist `x -> 2x` eine „anonyme Funktion“.
Das entspricht dem, was andere Sprachen eine „Lambda-Funktion“ nennen.

Beachte, dass mehrere Argumente runde Klammern brauchen, wie in `(x, y) -> x * y`.

Anonyme Funktionen sind im Julia-Code weit verbreitet, besonders in Kombination mit Funktionen höherer Ordnung wie `map()` und `filter()`.

## Funktionsargumente

Bisher haben wir im Lehrplan nur Funktionen betrachtet, die eine genaue Anzahl von Argumenten haben und bei denen der Funktionsaufruf alle Argumente in der richtigen Reihenfolge übergeben muss.
Das wäre einschränkend und unpraktisch, deshalb gibt es noch mehrere andere Möglichkeiten.

### Optionale Argumente

Wie viele andere Sprachen erlaubt es Julia, in der Funktionsdefinition Standardwerte für einzelne Argumente anzugeben.

Ein Funktionsaufruf kann dann entweder einen Wert für dieses Argument übergeben oder es weglassen und sich auf den Standardwert verlassen.

```julia-repl
julia> f(x, y=10) = x * y
f (generic function with 2 methods)

julia> f(2, 3)
6

julia> f(2)
20
```

Alle Argumente _ohne_ Standardwert müssen vor allen Argumenten _mit_ Standardwert stehen, das heißt, `f(x=2, y)` wäre ungültig.

### Schlüsselwortargumente

Alle Beispiele bisher verwenden `positional arguments`, bei denen die im Funktionsaufruf übergebenen Werte in der Reihenfolge der entsprechenden Argumente in der Funktionsdefinition stehen müssen.

Wie viele andere Sprachen erlaubt Julia auch `keyword arguments`.
Im Funktionsaufruf muss der Name des Arguments angegeben werden, aber mehrere Schlüsselwortargumente können dann in beliebiger Reihenfolge angegeben werden.

Ein besonderes Merkmal von Julia ist, dass die Schlüsselwortargumente (falls vorhanden) in der Funktionsdefinition durch ein Semikolon `;` abgetrennt werden müssen, um sie von den Positionsargumenten zu trennen.
Ein Funktionsaufruf kann entweder `;` oder `,` zwischen dem letzten Positionsargument und dem ersten Schlüsselwortargument verwenden.

```julia-repl
julia> b(x; y) = x + y
b (generic function with 1 method)

julia> b(2, y=3)
5

# keyword is required when calling
julia> b(2, 3)
ERROR: MethodError: no method matching b(::Int64, ::Int64)
The function `b` exists, but no method is defined for this combination of argument types.
```

Standardwerte können optional angegeben werden, genau wie bei Positionsargumenten.

Häufig entsteht innerhalb eines Funktionsaufrufs Syntax wie `myarg=myarg`, wenn eine Variable mit demselben Namen wie der Parameter vorher berechnet wurde.
In dieser Situation ist eine Kurzschreibweise erlaubt:

```julia-repl
julia> width = 4.0
4.0

julia> height = √ width
2.0

julia> area(; width, height) = width * height
area (generic function with 1 method)

# repetition
julia> area(; width=width, height=height)
8.0

# shorthand form
julia> area(; width, height)
8.0
```

### Splat und Slurp

Das sind die üblichen Namen für einen nützlichen Aspekt der Julia-Syntax, falls du dich das gefragt hast.
Beide beziehen sich auf den `...`-Operator.

#### Splat

Splatting wird in Funktions_aufrufen_ verwendet, um eine Sammlung in die einzelnen Werte zu entpacken, die die Funktion benötigt.

Das lässt sich leichter zeigen als erklären:

```julia-repl
julia> fxyz(x, y, z) = x * y * z
fxyz (generic function with 1 method)

julia> xyz = [2, 3, 4]
3-element Vector{Int64}:
 2
 3
 4

# Using the vector directly in a function call is invalid
julia> fxyz(xyz)
ERROR: MethodError: no method matching fxyz(::Vector{Int64})
The function `fxyz` exists, but no method is defined for this combination of argument types.

# splatting converts the vector to 3 numbers, used as positional arguments
julia> fxyz(xyz...)
24
```

Manche „Funktionsaufrufe“ sind hinter syntaktischem Zucker verborgen, deshalb kann Splatting auch auf weniger offensichtliche Weise verwendet werden.

Zum Beispiel verwendet die Mehrfachzuweisung intern eine Tupel-Konstruktorfunktion:

```julia-repl
julia> first, rest... = [1, 2, 3, 4]
4-element Vector{Int64}:
 1
 2
 3
 4

julia> first
1

julia> rest
3-element Vector{Int64}:
 2
 3
 4
```

Schlüsselwortargumente können ebenfalls per Splatting übergeben werden, typischerweise mit einem `named tuple`. 
Ein `Dict` funktioniert ebenfalls, aber die Schlüssel müssen Symbole sein (Strings funktionieren nicht).

```julia-repl
# function with 3 keyword arguments
julia> fabc(; a, b, c) = a + b + c
fabc (generic function with 1 method)

# named tuple
julia> abc_nt = (a=2, b=3, c=4)
(a = 2, b = 3, c = 4)

# there are no positional arguments, so need to use ; before kw argument
julia> fabc(;abc_nt...)
9

# Dict
julia> abc_dict = Dict(:a=>2, :b=>3, :c=>4)
Dict{Symbol, Int64} with 3 entries:
  :a => 2
  :b => 3
  :c => 4

julia> fabc(;abc_dict...)
9
```

#### Slurp

Slurping wird in der Funktions_definition_ verwendet, um eine beliebige Anzahl einzelner Werte in einer Sammlung zusammenzufassen.

```julia-repl
julia> f_more(i, j, more...) = i + j + sum(more)
f_more (generic function with 1 method)

julia> f_more(1, 3, 5, 7, 9, 11)
36
```

Der Name des geslurpten Arguments (in diesem Fall `more`) spielt keine Rolle.
Der Typ dieser Variable wird vom Compiler gewählt, ist aber bei Positionsargumenten wahrscheinlich `tuple` oder etwas Ähnliches.

Schlüsselwortargumente können ebenfalls geslurpt werden, was ein `Dict` (oder Ähnliches) ergibt.

```julia-repl
julia> f_kwslurp(x, y; switches...) = :mult in keys(switches) ? x * y : x + y
f_kwslurp (generic function with 1 method)

julia> f_kwslurp(5, 6; mult=true)
30

julia> f_kwslurp(5, 6)
11
```

Im Aufruf können beliebige Schlüsselwortargumente verwendet werden.
Die Funktionsdefinition entscheidet, auf welche Schlüsselwörter sie reagiert und welche sie ignoriert.
