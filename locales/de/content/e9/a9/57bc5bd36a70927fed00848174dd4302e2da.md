# Einführung

Es ist Zeit für eines der Kernparadigmen von C++: die objektorientierte Programmierung (OOP).
Im Mittelpunkt der OOP stehen `classes`: benutzerdefinierte Datentypen mit einer eigenen Sammlung zugehöriger Funktionen.
Wir beginnen mit den Grundlagen und behandeln weiter unten im Lehrplan fortgeschrittenere Themen.

## Member

Klassen können **Membervariablen** und **Memberfunktionen** haben.
Der Zugriff erfolgt über den **Member-Zugriffsoperator** `.`.
Wie bei Variablen außerhalb von `classes` solltest du Membervariablen am besten schon bei der Deklaration mit einem Wert initialisieren.
Dieser Wert wird dann zum Standard für neu erzeugte Objekte dieser Klasse.

## Kapselung und Informationsverbergung

Klassen bieten die Möglichkeit, den Zugriff auf ihre Member einzuschränken.
Die beiden Grundfälle sind `private` und `public`.
Auf `private` Member kann von außerhalb der Klasse nicht zugegriffen werden.
`public` Member können frei aufgerufen werden.
Alle Member sind standardmäßig `private` und müssen explizit als von außerhalb der Klasse nutzbar gekennzeichnet werden.

## Ein grundlegendes Beispiel

Die Definition einer neuen `class` siehst du im folgenden Beispiel.
Achte auf das `;` nach der Definition.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

Innerhalb der Klasse kannst du auf alle Variablen zugreifen.
Schau dir `damage` in der Funktion `cast_spell` an.
Von außerhalb der Klasse kannst du `private` Member weder lesen noch ändern:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## Konstruktoren

Konstruktoren bieten die Möglichkeit, Membervariablen bei der Objekterzeugung einen Wert zuzuweisen.
Sie haben denselben Namen wie die `class` und keinen Rückgabetyp.
Eine Klasse kann mehrere Konstruktoren haben.
Das ist nützlich, wenn du nicht immer alle Variablen setzen musst.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

Konstruktoren sind ein großes Thema mit vielen Nuancen.
Wenn du für deine `class` keinen `constructor` explizit definierst, dann erledigt der Compiler die Arbeit für dich, und nur dann.
Genau das ist im ersten Beispiel oben passiert.
Das Objekt _silverhand_ wird durch den Aufruf des Standardkonstruktors erzeugt, es wurden keine Argumente übergeben.
Alle Variablen werden auf den Wert gesetzt, der in der Definition der Klasse angegeben wurde.
Wenn du in dieser Definition keine Werte angegeben hättest, wären die Variablen möglicherweise uninitialisiert, was unerwünschte Folgen haben kann.

## Structs

Structs stammen aus den ursprünglichen C-Wurzeln der Sprache und sind so alt wie C++ selbst.
Sie sind im Grunde dasselbe wie `classes`, mit einer wichtigen Ausnahme.
Standardmäßig ist in einer `class` alles `private`.
Structs hingegen sind `public`, solange nichts anderes festgelegt ist.
Konventionell wird das Schlüsselwort `struct` oft für **reine Datenstrukturen** verwendet.
Das Schlüsselwort `class` ist für Objekte zu bevorzugen, die bestimmte Eigenschaften sicherstellen müssen.
Eine solche Invariante könnte sein, dass der `damage` deiner `Wizzard`-`class` nicht negativ werden kann.
Die Variable `damage` ist privat, und jede Funktion, die `damage` ändert, würde sicherstellen, dass die Invariante erhalten bleibt.
