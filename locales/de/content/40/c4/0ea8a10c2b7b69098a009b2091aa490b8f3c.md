# Einführung

Ein [Vergleichsoperator][comparisons] in Python (_auch relationaler Operator genannt_) betrachtet die _Werte_ zweier [Operanden][operand] und gibt einen booleschen Wert `True` oder `False` zurück, je nachdem, ob die Bedingung `comparison` erfüllt ist oder nicht.

Die folgende Tabelle zeigt die gebräuchlichsten Vergleichsoperatoren in Python:

| Operator | Operation                  | Beschreibung                                                               |
| -------- | -------------------------- | ------------------------------------------------------------------------- |
| `>`      | "größer als"               | `a > b` ist `True`, wenn `a` **echt** größer als `b` ist                  |
| `<`      | "kleiner als"              | `a < b` ist `True`, wenn `a` **echt** kleiner als `b` ist                 |
| `==`     | "gleich"                   | `a == b` ist `True`, wenn `a` **exakt** gleich `b` ist                    |
| `>=`     | "größer oder gleich"       | `a >= b` ist `True`, wenn `a > b` ODER `a == b` gilt                      |
| `<=`     | "kleiner oder gleich"      | `a <= b` ist `True`, wenn `a < b` oder `a == b` gilt                      |
| `!=`     | "ungleich"                 | `a != b` ist `True`, wenn `a == b` `False` ergibt                         |
| `is`     | "Identität"                | `a is b` ist `True`, wenn **_und nur wenn_** `a` und `b` dasselbe _Objekt_ sind |
| `is not` | "negierte Identität"       | `a is not b` ist `True`, wenn **_und nur wenn_** `a` und `b` **nicht** dasselbe _Objekt_ sind |
| `in`     | "Test auf Enthaltensein"   | `a in b` ist `True`, wenn `a` ein Mitglied, eine Teilmenge oder ein Element von `b` ist |
| `not in` | "negierter Test auf Enthaltensein" | `a not in b` ist `True`, wenn `a` kein Mitglied, keine Teilmenge und kein Element von `b` ist |

Sie haben alle dieselbe Priorität (_die höher ist als die von [booleschen Operationen][boolean operations], aber niedriger als die von arithmetischen oder bitweisen Operationen_).

## Vergleich zwischen verschiedenen Datentypen

Objekte unterschiedlichen Typs (_außer numerische Typen_) sind standardmäßig niemals gleich.
Auch nicht identische Instanzen einer `class` sind _**nicht**_ gleich, es sei denn, die `class` definiert spezielle Methoden, die das standardmäßige Vergleichsverhalten von `object` anpassen.

Numerische Typen sind (meist) eine Ausnahme von dieser Regel zur Typübereinstimmung.
Ein `integer` **kann** als gleich einer `float` betrachtet werden (_oder ein [`octal`][octal] als gleich einem [`hexadecimal`][hex]_), solange die Typen für den Vergleich implizit konvertiert werden können.

Für die anderen numerischen Typen ([komplexe Zahlen][complex numbers], [Dezimalzahlen][decimal numbers], [Brüche][rational numbers]) sind Vergleichsoperatoren dort definiert, wo sie „Sinn ergeben" (_wo eine implizite Konvertierung das Ergebnis nicht verändert_), lösen aber einen `TypeError` aus, wenn die zugrunde liegenden Objekte nicht genau genug für einen Vergleich konvertiert werden können.

## Vergleich der Objektidentität

Die Operatoren `is` und `is not` prüfen die _[Identität][object identity]_ eines Objekts, im Gegensatz zum _Wert_ eines Objekts.
Die Identität eines Objekts ändert sich nach seiner Erstellung nie und lässt sich mit der Funktion [`id()`][id function] ermitteln.

`<apple> is <orange>` ergibt `True`, wenn **_und nur wenn_** `id(<apple>)` == `id(<orange>)`.
`<apple> is not <orange>` liefert das Gegenteil.

## Zugehörigkeitsvergleiche

Die Operatoren `in` und `not in` prüfen die _Zugehörigkeit_.
`<fish> in <soup>` ergibt `True`, wenn `<fish>` ein Mitglied von `<soup>` ist (_wenn `<fish>` eine Teilmenge von `<soup>` ist oder darin enthalten ist_), und ergibt andernfalls `False`.
`<fish> not in <soup>` liefert die Negation, also das _Gegenteil von_ `<fish> in <soup>`.

Bei String- und Bytes-Typen ist `<name> in <fullname>` genau dann `True`, _**wenn**_ `<name>` ein Teilstring von `<fullname>` ist.
