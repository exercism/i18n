# Anweisungen

Es ist deine Aufgabe, Teile des IT-Systems eines Freizeitparks bereitzustellen und zu warten.
Insbesondere bist du für das Programm verantwortlich, das Besucher und Tickets verwaltet.

Zuerst erstellst du einen neuen Besucher im System.
Danach stellst du eine Funktion zum Entwerten eines Tickets bereit.
In den Aufgaben 3 und 4 arbeitest du am Ticketverfolgungssystem, das dabei hilft, Fälschungen zu verhindern.
Zum Schluss hilfst du dabei, das System an neue gesetzliche Anforderungen anzupassen.

## 1. Erstelle einen neuen Besucher

Wenn Besucher zum ersten Mal in den Freizeitpark kommen, müssen sie sich registrieren, indem sie ihren Namen und ihr Alter in ein Terminal eingeben und den Allgemeinen Geschäftsbedingungen zustimmen.
Natürlich müssen sie auch ein Ticket kaufen.
Jedes Ticket hat eine Kennung wie `H32AZ123`.

Schreibe eine Funktion `createVisitor`, die drei Argumente akzeptiert.

- Den Namen des Besuchers.
- Das Alter des Besuchers.
- Die Kennung des Tickets, das der Besucher gekauft hat.

Die Funktion sollte ein Objekt zurückgeben, das diese Informationen enthält.
Die Schlüssel in dem Objekt sollten `name`, `age` und `ticketId` heißen.

```javascript
createVisitor('Verena Nardi', 45, 'H32AZ123');
// => { name: 'Verena Nardi', age: 45, ticketId: 'H32AZ123' }
```

## 2. Entwerte das Ticket

Wenn Besucher den Freizeitpark verlassen, wird ihr Ticket entwertet.
Wenn sie zurückkommen, müssen sie ein neues kaufen.
Um Stammgästen etwas Zeit zu sparen, müssen sie sich nur einmal registrieren, und die Besucherinformationen werden für spätere Besuche aufbewahrt.

Das bedeutet: Wenn ein Besucher den Park verlässt, sollte nur sein Ticket ungültig werden, der Rest des Besucher-Objekts bleibt unverändert.
Implementiere die Funktion `revokeTicket`, die ein Besucher-Objekt akzeptiert, die Ticketkennung auf `null` setzt und das Objekt danach zurückgibt.

```javascript
const visitor = {
  name: 'Verena Nardi',
  age: 45,
  ticketId: 'H32AZ123',
};

revokeTicket(visitor);
// => { name: 'Verena Nardi', age: 45, ticketId: null }
```

## 3. Ermittle den Ticketstatus

Um Fälschungen zu verhindern, sind die Ticketkennungen eindeutig.
Sobald ein Ticket gedruckt wird, wird seine Kennung als Schlüssel in einem Objekt im System hinterlegt, damit es verfolgt werden kann.

Bevor das Ticket an einen Besucher verkauft wird, wird es mit dem Wert `null` im Ticketverfolgungsobjekt gespeichert.
Wenn es an einen Besucher verkauft wird, wird der Name des Besuchers als Wert zugewiesen.
Wenn Mitarbeiter Zweifel an der Gültigkeit eines Tickets haben, müssen sie den Status des Tickets im System prüfen.

Implementiere eine Funktion `ticketStatus`, die das Verfolgungsobjekt und eine Ticketkennung als Argumente akzeptiert.
Sie sollte eines der folgenden Ergebnisse zurückgeben.

- `'unknown ticket id'`, wenn die Kennung nicht im Verfolgungsobjekt gefunden wurde
- `'not sold'`, falls das Ticket gedruckt, aber nicht verkauft wurde
- `'sold to {name}'`, wobei `{name}` der Name des Besuchers ist, wenn das Ticket verkauft wurde

```javascript
const tickets = {
  '0H2AZ123': null,
  '23LA9T41': 'Verena Nardi',
};

ticketStatus(tickets, 'RE90VAW7');
// => 'unknown ticket id'

ticketStatus(tickets, '0H2AZ123');
// => 'not sold'

ticketStatus(tickets, '23LA9T41');
// => 'sold to Verena Nardi'
```

## 4. Verbessere die Antwort des Ticketstatus

Nach einer Weile bekommst du Feedback von den Mitarbeitern, dass sie den Ticketstatus auf den ersten Blick leichter verstehen wollen.
Sie wollen nur entweder den Namen des Besuchers sehen oder dass das Ticket ungültig ist.

Schreibe eine Funktion `simpleTicketStatus`, die dieselben Argumente wie `ticketStatus` aus Aufgabe 3 akzeptiert.
Diese Funktion gibt nur eines von zwei verschiedenen Ergebnissen zurück.

- den Namen des Besuchers, wenn das Ticket verkauft wurde
- `'invalid ticket !!!'`, wenn das Ticket noch nicht verkauft wurde oder die Kennung nicht im Verfolgungsobjekt gefunden wurde

```javascript
const tickets = {
  '0H2AZ123': null,
  '23LA9T41': 'Verena Nardi',
};

simpleTicketStatus(tickets, '23LA9T41');
// => 'Verena Nardi'

simpleTicketStatus(tickets, '0H2AZ123');
// => 'invalid ticket !!!'

simpleTicketStatus(tickets, 'RE90VAW7');
// => 'invalid ticket !!!'
```

## 5. Ermittle die Version der Allgemeinen Geschäftsbedingungen

Aufgrund neuer gesetzlicher Anforderungen enthalten neu erstellte Besucher-Objekte jetzt auch detaillierte Informationen zu den „Allgemeinen Geschäftsbedingungen“ (AGB), denen der Nutzer zugestimmt hat.
Unten siehst du ein Beispiel für das neue Besucher-Objekt.

Die Kassierer des Freizeitparks müssen nun prüfen, ob ein Besucher eine neue Version der AGB unterschreiben muss.
Implementiere dazu eine Funktion `gtcVersion`, die ein Besucher-Objekt als Argument akzeptiert und die AGB-Version zurückgibt, falls sie verfügbar ist.
Wenn die Versionsinformationen nicht verfügbar sind, sollte nichts zurückgegeben werden.

```javascript
const visitorNew = {
  name: 'Verena Nardi',
  age: 45,
  ticketId: 'H32AZ123',
  gtc: {
    signed: true,
    version: '2.1',
  },
};

gtcVersion(visitorNew);
// => '2.1'

const visitorOld = {
  name: 'Verena Nardi',
  age: 45,
  ticketId: 'H32AZ123',
};

gtcVersion(visitorOld);
// => undefined
```
