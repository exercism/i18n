# Über

`reduce` ist Factors allgemeine Fold-Operation: Sie durchläuft eine Sequenz und fädelt einen Akkumulator durch eine binäre Quotation, die den laufenden Akkumulator und das nächste Element entgegennimmt und den neuen Akkumulator erzeugt.

```
reduce ( seq init quot: ( prev elt -- next ) -- result )
```

```factor
USING: math sequences ;

{ 1 2 3 4 } 0 [ + ] reduce .         ! => 10
{ 1 2 3 4 } 1 [ * ] reduce .         ! => 24
```

Mit einem eigenen Startwert lassen sich mit `reduce` Folds ausdrücken, die `sum` oder `product` nicht hinbekommen. Zum Beispiel der größte Wert einer Sequenz mit einem Standardwert, falls jedes Element den Vergleich verliert:

```factor
USING: math.order ;

{ 3 1 -4 5 -2 } 0 [ max ] reduce .   ! => 5
{ -3 -1 -4 }    0 [ max ] reduce .   ! => 0
```

Der Startwert `0` nimmt am Vergleich teil, deshalb liefert eine durchweg negative Sequenz trotzdem `0` und nicht ihren kleinsten Wert.

## `produce`: das Unfold

Das Gegenstück zu `reduce` ist `produce` (in [`sequences`][sequences]): Wo `reduce` eine Sequenz *verbraucht*, *erzeugt* `produce` eine. Eine Prädikat-Quotation prüft den laufenden Zustand; solange sie truthy zurückgibt, erzeugt eine Rumpf-Quotation das nächste Element.

```
produce ( pred quot -- seq )
```

Zusammen bilden `reduce` und `produce` Factors Fold/Unfold-Paar.

## Kumulative Reduktionen

Die kumulative Familie in [`math.statistics`][math.statistics] liefert eine Sequenz mit derselben Länge wie die Eingabe, wobei jedes Element die Reduktion über das Präfix bis einschließlich dieser Position ist:

| Wort          | laufende Operation |
|---------------|--------------------|
| `cum-sum`     | laufende Summe     |
| `cum-product` | laufendes Produkt  |
| `cum-min`     | laufendes Minimum  |
| `cum-max`     | laufendes Maximum  |

```factor
USING: math.statistics ;

{ 3 1 4 1 5 9 2 6 } cum-sum .         ! => { 3 4 8 9 14 23 25 31 }
{ 3 1 4 1 5 9 2 6 } cum-min .         ! => { 3 1 1 1 1 1 1 1 }
{ 3 1 4 1 5 9 2 6 } cum-max .         ! => { 3 3 4 4 5 9 9 9 }
```

Kumulative Reduktionen sind nützlich, wenn du untersuchen willst, *wie* sich eine Größe über die Sequenz hinweg entwickelt hat, und nicht nur ihren Endwert. Auch das Verketten ist nützlich: Die Ausgabe einer kumulativen Reduktion ist selbst eine Sequenz und bereit, in die nächste eingespeist zu werden.
