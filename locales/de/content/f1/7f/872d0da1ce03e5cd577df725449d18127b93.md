# Ergänzung zur Anleitung

JavaScript ist von Natur aus single-threaded, daher fehlen ihm viele Sprachmerkmale, die andere Sprachen besitzen, um parallele Codeausführung zu ermöglichen.
Tatsächlich gibt es nur einen Weg, eine „echte“ parallele Codeausführung zu erreichen: über `Worker threads` (auch `Web Workers` genannt).

Fast immer läuft Code, der parallel ausgeführt zu werden scheint, wie `async functions` oder `Promises`, in Wahrheit nebenläufig ab.
Das ist oft sogar besser, denn modernes JavaScript ist genau dafür optimiert, und du siehst häufig Code, der parallele Ausführung mit `Promise.all()` und anderen nebenläufigen Ausführungsmethoden „nachahmt“ (oder „vortäuscht“).

## Nebenläufigkeit vs. Parallelität

Hier eine kurze Definition für beide, die die Unterschiede zwischen ihnen verdeutlicht:

- Nebenläufigkeit bedeutet, dass zwei oder mehr Aufgaben starten, laufen und abgeschlossen werden können, wobei sich ihre Zeiträume überschneiden und sie von derselben Verarbeitungseinheit ausgeführt werden.
- Parallelität bedeutet, dass zwei oder mehr Aufgaben gleichzeitig starten und laufen können, unabhängig voneinander von getrennten Verarbeitungseinheiten ausgeführt.

Der Vollständigkeit halber noch eine Definition für synchrone Ausführung:

- Bei synchroner Ausführung muss eine Aufgabe warten, bis eine andere laufende Aufgabe abgeschlossen ist, bevor sie selbst laufen kann.

## Parallelität in JavaScript

Auch wenn JavaScript standardmäßig single-threaded ist, gibt es eine Möglichkeit, Code parallel auszuführen.

Wenn du JavaScript im Browser ausführst (z. B. in einer Web-App),
dann erreichst du Parallelität über die [Web Worker API][mdn-demo].
Wie MDN es beschreibt:

> Web Workers ermöglichen es, eine Skriptoperation in einem Hintergrund-Thread auszuführen, getrennt vom Hauptausführungs-Thread einer Anwendung.

Wenn dein JavaScript dagegen in Node.js läuft, der Ziel-Laufzeitumgebung von Exercism,
heißt dasselbe Konzept [Worker threads][node].

Hier ist eine einfache Demo der `Web Worker API` (entnommen aus [Medium][medium-demo])

```js
// main.js
const myWorker = new Worker('worker.js');

myWorker.postMessage(5);

myWorker.onmessage = function (event) {
  console.log('Received result from worker:', event.data);
};
```

```js
// worker.js
onmessage = function (event) {
  console.log('Received number from main thread:', event.data);

  // Perform computation
  const result = event.data * 2;

  // Send result back to the main thread
  postMessage(result);
};
```

Und hier eine Demo der `Worker threads API` (entnommen aus der [Dokumentation][node])

```js
const {
  Worker,
  isMainThread,
  parentPort,
  workerData,
} = require('node:worker_threads');

if (isMainThread) {
  module.exports = function parseJSAsync(script) {
    return new Promise((resolve, reject) => {
      const worker = new Worker(__filename, {
        workerData: script,
      });
      worker.on('message', resolve);
      worker.on('error', reject);
      worker.on('exit', (code) => {
        if (code !== 0)
          reject(new Error(`Worker stopped with exit code ${code}`));
      });
    });
  };
} else {
  const { parse } = require('some-js-parsing-library');
  const script = workerData;
  parentPort.postMessage(parse(script));
}
```
