# Unison-Grundlagen

## Terme und Funktionen

Terme und Funktionen sind die grundlegenden Bausteine, wenn du ein Unison-Programm schreibst.

Ein „Term" ist das, was wir einen statischen Wert nennen. Er wird mit `name = expression` definiert, optional davor eine Typsignatur der Form `name : MyType`. Unison unterstützt Typinferenz, deshalb kann bei einfachen Definitionen die Typsignatur auch mal weggelassen werden.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison-Funktionen sehen so aus: `myFunctionName argument1 argument2 = myImplementation`. Sie beginnen mit dem Namen der Funktion, gefolgt von Argumenten, die durch Leerzeichen getrennt sind.

```
getMax a b = Nat.max a b
```

Funktionen können optional eine Typsignatur haben. Der letzte Typ rechts ist immer der Rückgabetyp der Funktion, und die Argumente werden durch den Funktionspfeil `->` getrennt.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Um eine Funktion aufzurufen, schreibst du ihren Namen gefolgt von ihren Argumenten, die nur durch Leerzeichen getrennt sind.

```
maximum = getMax 1 10
```

Beim Aufruf einer Funktion versucht Unison, alles, was direkt rechts steht, als Argument zu behandeln. Das führt nicht immer zur gewünschten Reihenfolge der Funktionsauswertung.

Angenommen, wir wollen aus dem folgenden Ausdruck den Wert `1` erhalten:

```
shouldBe1 = getMax 1 10 - 10
```

So wie es dasteht, ergibt `shouldBe1` den Wert `0`, denn die implizite Reihenfolge der Funktionsanwendung ist `getMax 1 10`, also `10`, und dann `10 - 10`, also `0`.

Mit runden Klammern kannst du den Ausdruck so umgruppieren, dass die gewünschte Reihenfolge der Operationen entsteht.

```
shouldBe1 = getMax 1 (10 - 10)
```

## Mehrzeilige Funktionen

Mehrzeilige Unison-Funktionen nutzen Einrückung oder `let`-Blöcke, um Codegrenzen festzulegen, auch bekannt als „lexikalischer Gültigkeitsbereich".

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Alles auf derselben Einrückungsebene teilt denselben Gültigkeitsbereich. Deshalb können wir in der letzten Zeile auf die Variable `newBeginning` verweisen.

## Namensräume und `use`-Anweisungen

Mit Namensräumen gruppieren und organisieren wir Unison-Funktionen. Du kannst sie dir wie „Verzeichnisse" vorstellen. Sie geben Struktur und eine logische Gruppierung.

Mit einer `use`-Anweisung holst du die Funktionen eines Namensraums in den Gültigkeitsbereich.

Angenommen, du schreibst eine Funktion, die mit Unison-`List`-Werten arbeitet. Du weißt, dass du Funktionen wie `List.map` und `List.flatMap` brauchst, wobei `List` der Namensraum ist und `map` und `flatMap` Funktionen sind. Um dich nicht zu wiederholen, kannst du alles aus dem Namensraum `List` in den lexikalischen Gültigkeitsbereich deiner Funktion holen:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

Die Zeile `use List` macht die Verweise auf `map` und `flatMap` eindeutig. Mehr über [`use`-Anweisungen findest du hier][use-statements].

## Unisons Standardbibliothek

Unisons Standardbibliothek heißt `base`. Wenn du der Schnellstartanleitung gefolgt bist und eine Codebasis lokal angelegt hast, sollte die Standardbibliothek automatisch heruntergeladen worden sein. Die Dokumentation der Standardbibliothek kannst du online auf [Unison Share][unison-share-base] durchstöbern.

## Kommentare und Dokumentations-Literale

Kommentare sind in Unison eine etwas ungewöhnliche Sache. Wenn du Unison-Code schreibst, kannst du in deiner Datei mit der Endung `.u` Text anlegen, der nicht interpretiert wird, und zwar mit dieser Syntax:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Allerdings_ wird Unison-Code als Hash seines abstrakten Syntaxbaums gespeichert und nicht als textbasierte Dateien im Dateisystem. Kommentare, die eine bestimmte Unison-Funktion oder einen Term in der Datei textbasiert „verzieren", lassen sich deshalb kaum speichern und zum Teilen erneut anzeigen. Wenn du einem Unison-Term Informationen hinzufügen möchtest, die gespeichert werden und die andere lesen und verstehen können, kannst du ein Dokumentations-Literal verwenden.

Dokumentation ist in der Programmiersprache Unison ein Wert erster Klasse. Das heißt, ein `Doc`-Element kann einem Wert zugewiesen, als Wert an eine Funktion übergeben oder als Rückgabewert einer Funktion zurückgegeben werden. Dokumentations-Literale werden mit doppelten geschweiften Klammern geöffnet und geschlossen. So könnten wir das `Doc`-Element als Kommentar verwenden.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
