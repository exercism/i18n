# Docker

Unsere Test-Runner werden als Docker-Images ausgerollt.

Lies dir bitte die [allgemeinen Informationen zu Docker im Tooling](/docs/building/tooling/docker) durch, damit du weißt, wie sie funktionieren.

## Integration

Wenn wir einen Test-Runner ausführen, um eine Lösung zu testen, führen wir einen Docker-Befehl aus, der so aussieht:

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-test-runner" \
        "${exercise_slug}" "/solution" "/output"
```

Du siehst, dass wir drei Argumente an das Docker-Image übergeben:

1. Den Übungs-Slug
2. Den Pfad zum Verzeichnis der Lösung
3. Den Pfad zum Ausgabeverzeichnis

## Konventionen

Alle unsere Test-Runner folgen in ihrer Umsetzung diesen Konventionen:

- Das `Dockerfile` liegt im Wurzelverzeichnis des Repos.
- Das Arbeitsverzeichnis sollte `/opt/test-runner` sein.
- Der Entrypoint ist `/opt/test-runner/bin/run.sh`
- Das Skript `/opt/test-runner/bin/run.sh` nimmt 3 Argumente entgegen:
  1. Den Übungs-Slug
  2. Den Pfad zum Verzeichnis der Lösung
  3. Den Pfad zum Ausgabeverzeichnis

Weitere Informationen findest du unter [Die Schnittstelle](/docs/building/tooling/test-runners/interface).

```exercism/note
Neue Test-Runner-Repos verwenden diese Konventionen standardmäßig.
```
