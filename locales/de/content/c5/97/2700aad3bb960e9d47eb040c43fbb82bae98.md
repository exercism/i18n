# Ergänzung zur Anleitung

## Ausnahmemeldungen

Manchmal ist es notwendig, [eine Ausnahme auszulösen][raise-an-exception]. Wenn du das tust, solltest du immer eine **aussagekräftige Fehlermeldung** angeben, um anzugeben, worin die Fehlerquelle liegt. Das macht deinen Code lesbarer und hilft beim Debugging erheblich. Wenn du weißt, dass die Fehlerquelle von einem bestimmten Typ ist, kannst du eine der [eingebauten Fehlertypen][built-in-errors] auslösen, solltest aber trotzdem eine aussagekräftige Meldung angeben.

Diese Übung verlangt von dir, dass du die [raise-Anweisung][raise-statement] verwendest, um einen `ValueError` zu „werfen", wenn die an `answer()` übergebene Frage fehlerhaft/ungültig ist oder eine unbekannte Operation enthält. Die Tests bestehen nur, wenn du die `exception` mit `raise` auslöst und eine Meldung dazu angibst.
**Beachte**: Die benötigte Meldung ist für jedes Szenario eine andere, obwohl derselbe _Fehlertyp_ ausgelöst wird.
Schau dir die Tests genau an.

Um einen [`ValueError`][value-error] mit einer Meldung auszulösen, übergibst du die Meldung als Argument an den `exception`-Typ:


```python
# if the question contains an unknown operation.
raise ValueError("unknown operation")

# if the question is malformed or invalid.
raise ValueError("syntax error")
```

Um einen ausgelösten Fehler innerhalb eines bestimmten Blocks zu _behandeln_, kannst du ein [try-except][handling-exceptions] verwenden.
`try-except`-Blöcke „umhüllen" den Code, der potenziell einen Fehler verursachen könnte, und bilden alle Ausnahmen auf einen Fehler, mehrere Fehler oder andere Codestücke ab, die das Problem behandeln:


```python
while len(equation) > 1:
        try:
           # The questionable/error-prone code goes here,in an indented block
           # It can contain statements, loops, if-else blocks, or other executable code.
           x_value, operation, y_value, *rest = equation
           ...
           ...

        except:
            # Code for what to do when an error gets thrown in the code above.
            # This could be one error, or more complicated logging, error checking and messaging.
            raise ValueError("syntax error")
```
