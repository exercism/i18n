# Einleitung

Die Programmiersprache Java verwendet _Ausnahmen_, um Fehler und andere außergewöhnliche Ereignisse zu behandeln.

## Was ist eine Ausnahme

Eine Ausnahme ist ein Ereignis, das während der Ausführung eines Programms auftritt und den normalen Ablauf der Anweisungen unterbricht.
Ausnahmen werden in Java explizit ausgelöst, und das Auslösen einer Ausnahme nennt man _Werfen einer Ausnahme_.
Das Behandeln einer Ausnahme nennt man _Abfangen einer Ausnahme_.

In Java sind alle Ausnahmen Unterklassen der Klasse `Exception`, die selbst eine Unterklasse von `Throwable` ist.

Java unterscheidet zwei Arten von Ausnahmen:

1. Geprüfte Ausnahmen
2. Ungeprüfte Ausnahmen

### Geprüfte Ausnahmen

_Geprüfte Ausnahmen_ sind außergewöhnliche Bedingungen, auf die eine Anwendung vorbereitet sein sollte und von denen sie sich erholen können sollte.
Ein Beispiel für eine geprüfte Ausnahme ist die `FileNotFoundException`, die auftritt, wenn eine Methode versucht, eine Datei zu lesen, die nicht existiert.

Diese Art von Ausnahme wird zur Kompilierzeit geprüft: Methoden, die geprüfte Ausnahmen werfen, sollten das in ihrer Methodensignatur angeben, und Code, der eine Methode aufruft, die eine geprüfte Ausnahme werfen könnte, muss diese behandeln, sonst lässt sich der Code nicht kompilieren.

Alle geprüften Ausnahmen sind Unterklassen von `Exception`, die `RuntimeException` nicht erweitern.

### Ungeprüfte Ausnahmen

_Ungeprüfte Ausnahmen_ sind außergewöhnliche Bedingungen, die eine Anwendung normalerweise nicht vorhersehen kann und von denen sie sich nicht erholen kann.
Ein Beispiel für eine ungeprüfte Ausnahme ist die `NullPointerException`, die auftritt, wenn eine Methode einen Nicht-null-Wert erwartet, aber `null` erhält.

Diese Art von Ausnahme wird zur Kompilierzeit nicht geprüft: Methoden, die ungeprüfte Ausnahmen werfen, müssen das nicht in ihrer Methodensignatur angeben, und Code, der eine Methode aufruft, die eine ungeprüfte Ausnahme werfen könnte, muss diese nicht behandeln.

Alle ungeprüften Ausnahmen erben von `RuntimeException`, die selbst eine Erweiterung von `Exception` ist.

## Ausnahmen werfen

Eine Methode kann in Java mit der `throw`-Anweisung eine Ausnahme werfen.

### Eine geprüfte Ausnahme werfen

Wenn du aus einer Methode eine geprüfte Ausnahme wirfst, musst du sie mit dem Schlüsselwort `throws` in der Methodensignatur angeben, wie das folgende Beispiel zeigt.
Dadurch muss der aufrufende Code damit rechnen, dass eine Ausnahme geworfen werden könnte, und sie entsprechend behandeln.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### Eine ungeprüfte Ausnahme werfen

Wenn du aus einer Methode eine ungeprüfte Ausnahme wirfst, musst du das nicht in der Methodensignatur angeben, obwohl es möglich ist.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## Ausnahmen behandeln

Zum Behandeln von Ausnahmen verwendet Java die Schlüsselwörter `try`, `catch` und `finally`.

- Code-Anweisungen, die eine Ausnahme werfen könnten, sollten in einen `try`-Block eingeschlossen werden.
- Auf den `try`-Block folgen ein oder mehrere `catch`-Blöcke, die die im `try`-Block geworfenen Ausnahmen abfangen.
- Optional folgen auf die `catch`-Blöcke ein `finally`-Block, der immer nach dem `try`-Block ausgeführt wird, egal ob eine Ausnahme geworfen wurde oder nicht.

Das folgende Beispiel zeigt, wie diese Schlüsselwörter zusammenwirken:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

Wenn in diesem Beispiel keine Ausnahme geworfen wird, wird Folgendes ausgegeben:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

Wenn jedoch die Anweisung `bankAccount.withdraw(amount)` eine `InsufficientBalanceException` wirft, wird Folgendes ausgegeben:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

Oder, falls `bankAccount.withdraw(amount)` eine ungeprüfte Ausnahme wirft, wird Folgendes ausgegeben:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## Fehler

Java kennt außerdem eine separate Kategorie namens _Fehler_: ernste Probleme, die außerhalb einer Anwendung liegen.
Ein Beispiel für einen Fehler ist der `OutOfMemoryError`, der auftritt, wenn eine Anwendung mehr Speicher verwenden will, als auf dem System verfügbar ist.

Wie ungeprüfte Ausnahmen werden Fehler nicht zur Kompilierzeit geprüft.
Der Unterschied ist, dass sie Probleme auf Systemebene darstellen und im Allgemeinen von der Java Virtual Machine oder der Umgebung geworfen werden, nicht von der Anwendung.
Anwendungen sollten im Allgemeinen nicht versuchen, sie abzufangen oder zu behandeln.

Alle Fehler in Java erben von der Klasse `Error`.
