# Traits

Ein Trait legt eine Reihe von Methoden fest, die ein Typ implementieren kann.
Traits sind nützlich, um Methoden zu definieren, die zwischen Typen geteilt werden sollen.
Wenn Traits mit generischen Typen verwendet werden, lassen sich die definierten Methoden nicht nur auf einen bestimmten Typ aufrufen, sondern auch auf andere Datentypen.
Auf abstrakte Weise können wir mit _Trait-Bounds_ festlegen, dass der generische Typ ein bestimmtes Verhalten teilen muss.

> **Hinweis:** Traits ähneln dem, was in anderen Programmiersprachen als Interfaces bekannt ist, allerdings mit einigen Unterschieden.

## Trait-Definition

Ein Trait zu definieren hilft dabei, die Funktionssignaturen festzulegen, aus denen die Verhaltensweisen bestehen, die ein Typ implementieren kann, um ein Ergebnis zu erreichen.
Diese Methoden bilden das Verhalten eines Typs.
Wenn wir dieselben Methoden auf verschiedenen Typen aufrufen können, bedeutet das, dass die beteiligten Typen dasselbe Verhalten haben.

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

Nach der obigen Definition des `Summary`-Traits ist die `summarize`-Methode ein Verhalten, das nur vom Struct-Typ `NewsArticle` aufgerufen werden kann.
Wird sie auf Instanzen anderer Typen aufgerufen, führt das zu einem Kompilierfehler.
Wenn du das Trait mit dem Schlüsselwort `pub` deklarierst, wird es in diesem Crate für andere Crates sichtbar, die das Trait ebenfalls nutzen möchten.
Beachte außerdem, dass wir nach der Deklaration von Methodensignaturen in Traits ein Semikolon setzen.

Ein Trait kann mit einem generischen Argument definiert werden, wodurch eine Funktion Argumente jedes Datentyps annehmen kann.
Das verleiht der Funktionssignatur Flexibilität, sodass sie verschiedene Datentypen verarbeiten kann.
Beim untenstehenden `Summary`-Trait wurde es so umgestaltet, dass es für jeden Datentyp funktioniert, sodass die Methode `summarize`, wenn sie darauf aufgerufen wird, ein ByteArray zurückgibt.

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

Ein Trait kann mehr als eine Methode in seinem Body haben; jede deklarierte Methodensignatur ist ein Einzeiler, der mit einem Semikolon endet.

## Trait-Implementierung für einen Typ

Nachdem du die Funktionssignaturen definiert hast, aus denen ein Trait besteht, achtet der Compiler darauf, dass auch eine Implementierung für Typen definiert ist, die das Trait übernehmen.
Unten haben wir einen `aggregator`-Bibliotheks-Crate für Medien geschrieben, der einige Daten aus Instanzen von `NewsArticle` und `Tweet` zusammenfasst.
Für das Struct `NewsArticle` würden wir die Felder headline, author und location verwenden, um den Wert für die Methode `summarize` aus dem `Summary`-Trait zurückzugeben, während wir für das Struct `Tweet` den Benutzernamen und den Inhalt verwenden würden, wobei wir davon ausgehen, dass der Tweet-Inhalt auf 280 Zeichen begrenzt ist.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## Standardimplementierungen

Manchmal kann ein Trait mit einer Standardimplementierung für einige oder alle Methoden definiert werden, aus denen das Trait besteht.
Das vermeidet es, für jeden Typ eine Implementierung aller Methoden zu verlangen, und verbessert die Lesbarkeit des Codes.
Wenn ein bestimmter Typ eine spezielle Implementierung einer Trait-Methode benötigt, kann er die Standardimplementierung überschreiben.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## Externe Traits verwenden und verwalten

Traits und Implementierungen können in einem externen Modul definiert und in anderen Modulen verwendet werden, solange sie ordnungsgemäß importiert werden.
Nehmen wir an, wir haben ein `ShapeGeometry`-Trait mit der Methode `boundary`, das sowohl für das Struct `Circle` als auch für das Struct `Rectangle` implementiert werden muss.
Unten siehst du ein Beispiel dafür, wie das Trait und die Implementierung über Module hinweg importiert, verwaltet und verwendet werden.

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

Die Sichtbarkeit der Implementierungen `CircleGeometry` und `RectangleGeometry` muss nicht öffentlich sein, da das `ShapeGeometry`-Trait öffentlich gemacht wird und der Compiler es leicht finden können sollte.

## Impl-Aliase

Implementierungen können beim Import mit dem Schlüsselwort `impl` mit einem Alias versehen werden.
Das hilft beim Instanziieren einer generischen Implementierung für konkrete Typen.
Definieren wir eine triviale Implementierung des Traits `Two` für alle Typen, die das Trait `One` implementieren, indem wir einfach den doppelten Wert von `One` addieren und die Summe zurückgeben.
Danach können wir die `Two`-Implementierung bereitstellen, die nur für die Typen `u8` und `u128` funktioniert.

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

Die generische Implementierung kann in einem privaten Modul geschrieben werden, und mit einem Impl-Alias können wir die generische Implementierung dieser beiden konkreten Typen instanziieren.
Der Vorteil einer privaten, nicht exponierten generischen Implementierung ist, dass sie Codeduplizierung über Dateien hinweg vermeidet.
Außerdem bleibt die öffentliche API dadurch einfach und sauber.
