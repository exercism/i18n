# Einführung

JavaScript hat ein eingebautes Objekt `Date`, das Datum und Uhrzeit speichert und Methoden für deren Verwaltung bereitstellt.

<!-- prettier-ignore -->
~~~exercism/caution
Es basierte auf Javas Klasse `java.util.Date`, die Anfang der 2010er Jahre ersetzt wurde, aber aus Gründen der Abwärtskompatibilität bleibt JavaScripts `Date` erhalten.

Weil die Arbeit mit Datumsangaben allgemein schwierig ist und weil die Zeitzonenbehandlung schlecht oder gar nicht vorhanden ist, gibt es viele Bibliotheken wie `moment.js`, `day.js`, `date-fns` und `luxon`.
Keine davon ist auf Exercism verfügbar.

In deinen eigenen Projekten solltest du kein veraltetes / nicht mehr gepflegtes Paket wie `moment.js` verwenden, sondern dich auf modernere Alternativen wie `luxon` verlassen oder auf das noch nicht weit verbreitete [Temporal][mdn-temporal].
Diese Übung konzentriert sich auf `Date`, das bis zum Ende von JavaScript relevant bleiben wird.

## Erstellung

Ein `Date`-Objekt ist eine Instanz der Klasse `Date`.
Es kann erstellt werden, ohne Argumente an die Konstruktorfunktion zu übergeben.
Das ergibt ein `Date`-Objekt, das das aktuelle Datum und die aktuelle Uhrzeit repräsentiert:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### Unix-Zeitstempel (Zahl)

Wenn eine Zahl übergeben wird, wird sie als `timestamp` interpretiert.
Ein Zeitstempel ist eine ganze Zahl, die die Anzahl der **Millisekunden** darstellt, die seit **1. Januar 1970 [UTC][defn-utc]+0** vergangen sind.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

Man könnte erwarten, dass `new Date(0)` das „früheste“ Datumsobjekt erzeugt, aber JavaScript konvertiert das Datum in deine lokale Zeitzone. Das bedeutet, dass nur diejenigen rund um [GMT bzw. mit einer UTC+0-Zeitzone][defn-gmt] tatsächlich den Wert der [Unix-Epoche][defn-unix-epoch] erhalten.

### ISO-8601-Zeitstempel (String)

Du kannst einen String-Wert, der ein Datum repräsentiert, an den `Date`-Konstruktor übergeben.
Das **einzige** Format, das über alle Implementierungen hinweg konsistent ist, ist die [vereinfachte Version][mdn-date-string-format] der international anerkannten und standardisierten sogenannten [ISO-8601-Zeitstempel-Strings][defn-iso8601].

Ein Zeitpunkt in [UTC][defn-gmt] sieht so aus:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

Dabei gelten die folgenden Ersetzungen:

| Zeichen | Beschreibung                                   | Standardwert |
| ------- | ---------------------------------------------- | ------------ |
| YYYY    | Das Kalenderjahr, in 4 Ziffern dargestellt     |              |
| MM      | Der Kalendermonat, in 2 Ziffern dargestellt    | 01           |
| DD      | Der Kalendertag, in 2 Ziffern dargestellt      | 01           |
| T       | Ein wörtliches T, das Datum und Uhrzeit trennt |              |
| HH      | Die Stunden in einer 24-Stunden-Anzeige, 2 Ziffern | 00       |
| mm      | Die Minuten, 2 Ziffern                         | 00           |
| ss      | Die Sekunden, 2 Ziffern                        | 00           |
| mss     | Die Millisekunden, 3 Ziffern                   | 000          |
| Z       | Ein wörtliches Z oder ein Offset `+/-HH:mm`    |              |

Der wörtliche Buchstabe `Z` steht für UTC (keine Zeitzone, keine Sommerzeit).

Da die meisten Komponenten Standardwerte haben, ist es gültig, Teile am Ende wegzulassen:

```text
YYYY-MM-DD
```

Standardwert ist die Uhrzeit 00:00:00.000.

Wenn der Zeitstempel nicht auf `Z` endet und auch nicht mit `+HH:mm` oder `-HH:mm` endet (was einen Zeitzonen-Offset anzeigen würde), gilt aus historischen Gründen Folgendes:

> Fehlt der Zeitzonen-Offset, werden reine Datumsformen als UTC-Zeit und Datum-Uhrzeit-Formen als lokale Zeit interpretiert.
> Die Interpretation als UTC-Zeit geht auf einen historischen Fehler in der Spezifikation zurück, der nicht mit ISO 8601 übereinstimmte, aber wegen der Web-Kompatibilität nicht geändert werden konnte.
> Siehe [Broken Parser – A Web Reality Issue][ref-broken-parser].

### Date-Objekt

Ein vorhandenes Datumsobjekt kann ebenfalls als Argument an den Konstruktor übergeben werden.
Dadurch wird eine Kopie des vorhandenen `Date`-Objekts mit demselben Datum und derselben Uhrzeit erstellt.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### Einzelne Werte für Datum und Uhrzeit übergeben

Ein Datum ohne Uhrzeit lässt sich erzeugen, indem du drei Zahlen übergibst.
Ein Datum mit Uhrzeit lässt sich erzeugen, indem du 6 Zahlen übergibst.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

Der zweite Wert ist der `month`, der bei `0` für Januar beginnt und bis `11` für Dezember geht.

## `Date.parse()`

Vielleicht stößt du auf Erwähnungen oder Verweise auf die Funktion zum Parsen von Datumsangaben `Date.parse`.
Da es für diese Funktion nur wenige Invarianten (Tatsachen) gibt und der Rest der Implementierung nicht spezifiziert (und damit nicht standardisiert) ist, solltest du sie nicht verwenden.

## Zugriff auf `Date`-Komponenten

Es gibt verschiedene Methoden auf Datumsobjekten, die die Komponenten des Datums zurückgeben:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

Jede davon hat eine passende `set`-Variante (z. B. `setFullYear`), um den Wert zu aktualisieren.
Jeder überlaufende Wert wird auf die nächste Komponente übertragen:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

Für alle Methoden gibt es UTC-Varianten, die die lokale Zeitzone ignorieren.

## Von einem Datum konvertieren

`Date`-Objekte haben eine Methode `getTime()`, die den UNIX-Zeitstempel in Millisekunden zurückgibt, d. h. die Anzahl der Millisekunden seit Mitternacht zu Beginn des 1. Januar 1970 UTC.
Außerdem gibt es die Methode `toISOString()`, um ein Datumsobjekt in einen ISO-8601-Zeitstempel-String umzuwandeln.

## Datumsangaben vergleichen

Größer als (`>`), größer oder gleich (`>=`) sowie kleiner als (`<`) und kleiner oder gleich (`<=`) kannst du direkt zwischen zwei Datumsangaben oder zwischen einem Datum und einer Zahl verwenden.
Das funktioniert, weil JavaScript versucht, das Datum in einen primitiven Wert umzuwandeln.
