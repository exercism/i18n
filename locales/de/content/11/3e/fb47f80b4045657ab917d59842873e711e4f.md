# Einführung

In früheren Konzepten haben wir gesehen, dass Typen in Julia eine Hierarchie bilden, mit `Any` an der Spitze.

Abstrakte Typen wie `Number` haben Untertypen, können aber selbst nicht instanziiert werden.
Wenn du eine Variable auf einen abstrakten Typ festlegst, _beschränkst_ du ihre Werte auf beliebige Untertypen dieses abstrakten Typs.
Zum Beispiel:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Das gibt uns eine Form von Flexibilität dabei, einzuschränken, welche Eingabewerte gültig sind.

Angenommen, wir möchten aber, dass eine Variable sowohl Ganzzahl- als auch String-Werte akzeptiert?
Diese Typen liegen nicht im selben Zweig der Hierarchie.

Wir könnten den Typ auf `Any` setzen oder ihn einfach bei diesem Standard belassen, doch dann verlieren wir jede Kontrolle über die erlaubten Typen.

Für einen besseren Ansatz gibt es die Syntax `Union{ }`, bei der zwei oder mehr Typen in den geschweiften Klammern aufgelistet werden.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Ein weiteres Beispiel verwendet dieselbe Typ-Union in einer Funktionssignatur:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

Hier haben wir dem Typ einen Namen gegeben, was eine praktische Kurzschreibweise ermöglicht, aber nicht unbedingt nötig ist.
Die Funktion `g(z::Union{Integer, String}) = z^3` verhält sich genauso.

Über Funktionssignaturen gibt es im Konzept „Multiple Dispatch“ noch viel mehr zu sagen.

## Unions mit nichts

Einige andere Sprachen haben Typen, die einen Wert enthalten können oder auch nicht, mit Namen wie `Option`, `Nullable` oder `Maybe`.

Julia hat dafür keine eigene Syntax, aber Typ-Unions sind eine Verallgemeinerung derselben Idee.

Im Konzept `Nothingness` haben wir gesehen, dass Julia verschiedene Möglichkeiten hat, Nicht-Werte darzustellen, darunter `nothing` und `missing`.
Beide können in eine Typ-Union aufgenommen werden.

Wenn wir zum Beispiel eine Art verkettete Liste definieren, brauchen wir eine Möglichkeit, die Liste zu beenden, wenn es keine weiteren Knoten gibt.
`Nothing` ist der Typ mit dem Singleton-Wert `nothing`, und diese Node-Definition macht es möglich, das Ende der Kette zu signalisieren:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

Ebenso kann `missing` als Platzhalter für fehlende Werte dienen, besonders in Sammlungen wie Vektoren.
Das folgende Beispiel ist sehr konstruiert, aber fehlende Werte sind in echten Datensätzen häufig.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
