# Anleitung

Du schreibst Code für das Datensystem in der Fertigungshalle eines Werks, das Automobilteile herstellt.
Motor- und Fahrgestellkomponenten durchlaufen eine Reihe von Bearbeitungsstationen.
Jede Station erzeugt Messwerte, die kombiniert, verglichen, kalibriert oder normalisiert werden müssen, bevor der nächste Arbeitsschritt läuft.
Du implementierst hier für jede Station eine Funktion.

~~~~exercism/note
Die Berechnungen in dieser Übung sollten mit SIMD-Befehlen durchgeführt werden, nicht mit skalaren Operationen.
~~~~

## 1. Kombiniere die Ausbeuten zweier Linien

In der Fertigungshalle laufen zwei parallele Fließbänder.
Am Ende jeder Schicht melden beide Linien ihre Ausbeute für 4 Behälter als Gleitkommazahlen einfacher Genauigkeit.
Das Dashboard des Vorarbeiters zeigt die kombinierte Ausbeute pro Behälter, also werden die beiden Meldungen Behälter für Behälter addiert.
Alle drei Buffer werden vom Meldesystem verwaltet und sind immer auf 16 Byte ausgerichtet.

Definiere eine Funktion `sum_yields`, die aus den Ausbeuten pro Behälter von `line_a` und `line_b` die behälterweise Summe nach `result` schreibt.
Die Argumente sind, in dieser Reihenfolge:

1. `line_a`: eine auf 16 Byte ausgerichtete Speicheradresse mit 4 32-Bit-Gleitkommazahlen
2. `line_b`: eine auf 16 Byte ausgerichtete Speicheradresse mit 4 32-Bit-Gleitkommazahlen
3. `result`: eine auf 16 Byte ausgerichtete Speicheradresse, an die die Funktion 4 32-Bit-Gleitkommazahlen schreibt

Diese Funktion hat keinen Rückgabewert. Stattdessen wird das Ergebnis im übergebenen Buffer (`result`) gespeichert:

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. Berechne die skalierte Abweichung

Zwischen den Arbeitsgängen vermisst eine Messstation bearbeitete Teile und vergleicht sie mit den Sollmaßen.
Die Messwerte fließen von einem Präzisionsmessgerät in einen Buffer, der immer auf 16 Byte ausgerichtet ist.
Die Sollwerte stammen aus dem Arbeitsauftrag, der keine garantierte Ausrichtung hat.
Die Abweichung wird mit einem Empfindlichkeitsfaktor pro Achse multipliziert, bevor sie an den nachgelagerten Toleranzprüfer weitergegeben wird.
In diesem Schritt liest der nachgelagerte Prüfer die Abweichung direkt aus einem SIMD-Register statt aus dem Speicher.

Definiere eine Funktion `scaled_deviation`, die anhand von `measured`, `target` und `sensitivity` die skalierte Abweichung nach `result` schreibt.
Die Argumente sind, in dieser Reihenfolge:

1. `measured`: eine auf 16 Byte ausgerichtete Speicheradresse mit 2 64-Bit-Gleitkommazahlen
2. `target`: eine Speicheradresse mit 2 64-Bit-Gleitkommazahlen (Ausrichtung nicht garantiert)
3. `sensitivity`: eine Speicheradresse mit 2 64-Bit-Gleitkommazahlen (Ausrichtung nicht garantiert)
4. `result`: eine Speicheradresse für einen Buffer, in den die Funktion 2 64-Bit-Gleitkommazahlen schreibt (Ausrichtung nicht garantiert)

Die skalierte Abweichung ist `(measured - target) * sensitivity`, Lane für Lane.

Diese Funktion hat keinen Rückgabewert. Stattdessen wird das Ergebnis im übergebenen Buffer (`result`) als Paar von 64-Bit-Gleitkommazahlen gespeichert.

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. Kalibriere eine Charge

Bevor Teile in den Endprüfbereich gelangen, werden die Maßwerte einer Charge aus 4 Teilen in doppelte Genauigkeit umskaliert und um eine bekannte Temperaturdrift korrigiert.

Die 4 Rohwerte kommen als Gleitkommazahlen einfacher Genauigkeit an.
Für jede Zeile aus 2 Messwerten berechnet die Kalibrierung `reference / (raw - offset)` und multipliziert dieses Ergebnis anschließend mit einem konstanten Umrechnungsfaktor von `0.5`.

Beachte, dass der Referenzwert und der Offset für beide Zeilen der Charge gleich sind.
Der Umrechnungsfaktor ist bei jeder Kalibrierung gleich. Statt ihn als Argument zu übergeben, solltest du ihn als gepackte 16-Byte-Konstante im Speicher deklarieren.

Definiere eine Funktion `calibrate_batch`, die aus einer `raw`-Charge, einem `reference`, einem `offset` und einem `result`-Buffer die kalibrierten Werte nach `result` schreibt.
Die Argumente sind, in dieser Reihenfolge:

1. `raw`: eine Speicheradresse mit 4 32-Bit-Gleitkommazahlen (Ausrichtung nicht garantiert)
2. `reference`: eine auf 16 Byte ausgerichtete Speicheradresse mit 2 64-Bit-Gleitkommazahlen
3. `offset`: eine auf 16 Byte ausgerichtete Speicheradresse mit 2 64-Bit-Gleitkommazahlen
4. `result`: eine auf 16 Byte ausgerichtete Speicheradresse, an die die Funktion 4 64-Bit-Gleitkommazahlen schreibt (insgesamt 32 Byte)

Für jede der beiden Zeilen der Charge soll die Funktion:

1. Die 2 Rohwerte der Zeile einfacher Genauigkeit in doppelte Genauigkeit umwandeln.
2. `offset` vom umgewandelten Paar subtrahieren.
3. `reference` durch das Ergebnis dividieren.
4. Jede 64-Bit-Gleitkommazahl Lane für Lane mit dem festen Umrechnungsfaktor `0.5` multiplizieren.
5. Die 2 64-Bit-Gleitkommazahlen in die entsprechenden 16 Byte von `result` schreiben.

Diese Funktion hat keinen Rückgabewert. Stattdessen wird das Ergebnis im übergebenen Buffer (`result`) gespeichert:

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. Normalisiere die Qualitätswerte entlang einer Linie

Am Ende der Linie hat jedes Teil einen Qualitätswert, der normalisiert werden muss, bevor er gemeldet wird.
Jeder Qualitätswert wird mit seinem eigenen Verstärkungsfaktor pro Teil multipliziert und dann durch eine Produktionsskalierung pro Achse dividiert.
Der `gains`-Buffer enthält einen Verstärkungsfaktor pro Teil.

Die Produktionsskalierung ist für den gesamten Durchlauf gleich und wird als Speicheradresse mit zwei 64-Bit-Gleitkommazahlen übergeben.
Die Qualitätswerte werden **in-place** aktualisiert: Derselbe Buffer, der die Rohwerte enthielt, enthält nun die normalisierten Qualitätswerte.

Definiere eine Funktion `normalize_scores`, die anhand eines `scores`-Arrays, eines `gains`-Arrays, einer `scale` und einer Anzahl `n` die Qualitätswerte in-place normalisiert.
Die Argumente sind, in dieser Reihenfolge:

1. `scores`: eine auf 16 Byte ausgerichtete Speicheradresse mit `n` 64-Bit-Gleitkommazahlen (wird in-place verändert)
2. `gains`: eine auf 16 Byte ausgerichtete Speicheradresse mit `n` 64-Bit-Gleitkommazahlen
3. `scale`: eine auf 16 Byte ausgerichtete Speicheradresse mit 2 64-Bit-Gleitkommazahlen
4. `n`: eine positive gerade 64-Bit-Ganzzahl (mindestens `2`), die Anzahl der zu normalisierenden Qualitätswerte

Die beiden Lanes der Skalierung gelten für die beiden Elemente jedes Paares.
Die erste Lane skaliert das erste Element jedes Paares (Lanes an geraden Positionen), die zweite Lane skaliert das zweite (Lanes an ungeraden Positionen).
Jeder Qualitätswert wird mit seinem zugehörigen Verstärkungsfaktor multipliziert und dann durch die passende Skalierungs-Lane dividiert: `score * gain / scale_lane`.

Diese Funktion hat keinen Rückgabewert. Stattdessen wird das Ergebnis im Eingabe-Buffer (`scores`) gespeichert, an derselben Position wie der entsprechende `score`, der normalisiert wurde:

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
