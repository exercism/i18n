# Code schreiben

Schreib deinen Code in `src/lib.rs`.
Die Übungen enthalten eine Stub-Datei in `src/lib.rs`, die dir die Signaturen des Codes zeigt, den du schreiben musst.

Für die meisten Übungen ist es am besten, deinen gesamten Code in der Datei `src/lib.rs` zu schreiben.
Wenn du deine Lösung auf mehrere Dateien aufteilen möchtest, wirf einen Blick in das [Kapitel über Module][chapter-modules] im Rust-Buch.

[chapter-modules]: https://doc.rust-lang.org/book/ch07-02-defining-modules-to-control-scope-and-privacy.html

## Tests ausführen

Um die Tests auszuführen, musst du nur den folgenden Befehl ausführen:

```bash
$ cargo test
```

Standardmäßig ist nur der erste Test aktiviert.
Wenn du bereit bist, den nächsten Test zu bestehen, entferne das Ignorieren-Flag vom nächsten Test (`#[ignore]`).
Du kannst das Flag auch auf einmal von allen Tests entfernen, wenn du möchtest.

Schreib ruhig so wenig Code wie möglich, damit die Tests bestehen.
Die Testfehler zeigen dir, was als Nächstes geschrieben werden sollte.

Da Rust den gesamten Code zur Kompilierzeit prüft, kann es sein, dass deine Tests erst kompilieren, wenn du den erforderlichen Code geschrieben hast.
Auch Tests, die mit `ignore` markiert sind, werden zur Kompilierzeit geprüft.
Du kannst Tests, die nicht kompilieren, [auskommentieren][comments], indem du jede Zeile mit `//` beginnst.
Wenn du dann bereit bist, an diesem Test zu arbeiten, kannst du ihn wieder einkommentieren.
Rust hat außerdem ein spezielles Makro namens `todo!()`, das du an unfertigen Codepfaden verwenden kannst, damit dein Programm kompiliert.

[comments]: https://doc.rust-lang.org/book/ch03-04-comments.html

## Bibliotheken verwenden

Die meisten Übungen solltest du ohne externe Bibliotheken lösen können.
Trotzdem kannst du Bibliotheken hinzufügen (die Rust-Community nennt sie **Crates**), indem du `cargo add crate-name` im Verzeichnis einer Übung ausführst.

Die automatischen Tests auf der Website unterstützen nur eine festgelegte Auswahl an Crates, die du [hier][local-registry] im Abschnitt `[dependencies]` findest.
Du kannst gerne ein Issue oder einen Pull Request öffnen, wenn du dir Unterstützung für ein bestimmtes Crate wünschst.

[local-registry]: https://github.com/exercism/rust-test-runner/blob/main/local-registry/Cargo.toml
