# Über

## Einführung

Opaque Types sind eine Kapselungstechnik in Elm.
Manche nennen das auch Information Hiding oder das Verbergen von Implementierungsdetails.
Häufig werden sie außerdem eingesetzt, um die Validierung mit dem Muster [Parse, dont validate][parse-dont-validate] zu erzwingen.
Zum Beispiel könntest du einen Opaque Type `EmailAddress` haben, der nur gültige E-Mail-Adressen enthalten kann (im Gegensatz zu einem `String`, der alles Mögliche enthalten kann).

## Einen Opaque Type erstellen

[Custom types][custom-types] haben eine oder mehrere *Varianten*, und der Compiler erzeugt automatisch eine Funktion, um jede *Variante* zu erstellen, wobei er den Namen der *Variante* verwendet.
Nur so können Custom Types erstellt werden.
Der Compiler erlaubt außerdem die Destrukturierung dieser Varianten.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

Standardmäßig ist all das datei- bzw. modulintern, und mit dem Schlüsselwort `exposing` wählst du aus, was exportiert wird.
Um einen Opaque Type zu erstellen, exportierst du die *Varianten* einfach nicht.

Wenn du das tust, brauchst du fast immer einen anderen Weg, um die *Varianten* zu erstellen und auszulesen, nämlich eigene Funktionen, die du exportierst.
Diese eigenen Funktionen erlauben es dir, beim Erstellen und Auslesen der *Varianten* eine Logik anzuwenden.
Das verbirgt die internen Implementierungsdetails des Moduls und bedeutet, dass du die Implementierungsdetails beliebig ändern kannst, solange die exportierten Funktionen gleich bleiben.

## Parse, don't validate

Der wohl häufigste Einsatz von Opaque Types ist es, die Validierung mit dem Muster [Parse, dont validate][parse-dont-validate] zu erzwingen.
Bei diesem Muster exportierst du eine Funktion, die eine Eingabe mit weniger Struktur bzw. Typsicherheit entgegennimmt, als du möchtest, zum Beispiel einen `String`, und parst diese dann in einen stärker strukturierten Typ wie `EmailAddress`. Dabei gibst du entweder den Typ zurück oder einen Fehler (meist `Maybe` oder `Result`).

Im folgenden Code zum Beispiel können externe Module einen `EmailAddress`-Typ nur mit der Funktion `parseEmailAddress` erstellen. Wenn du also mit dem Typ `EmailAddress` arbeitest, kannst du sicher sein, dass er gültig ist.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
