# Einführung

Jedes Mal, wenn eine Funktion aufgerufen wird, wird im Speicher ein neuer Stackframe angelegt, um die Argumente und lokalen Variablen der Funktion zu speichern. Dieser Stackframe wird wieder freigegeben, wenn die Funktion zurückkehrt. Da Gleam rekursive Funktionsaufrufe statt einer Schleifensyntax verwendet, können diese Stackframes eine große Menge Speicher belegen.

Um dieses Problem zu vermeiden, unterstützt Gleam die Tail-Call-Optimierung. Damit kann der Compiler den Stackframe der aktuellen Funktion wiederverwenden, wenn ein Funktionsaufruf das Letzte ist, was die Funktion tut. So kann sich eine Funktion unendlich oft selbst aufrufen, ohne zusätzlichen Speicher zu verbrauchen.

Nicht optimierte rekursive Funktionen lassen sich oft in tail-call-optimierte Funktionen umschreiben, indem du einen _Akkumulator_ verwendest.

Ein Akkumulator ist eine Variable, die zusätzlich zu den Daten übergeben wird. Mit ihm reichst du den aktuellen Zustand der Funktionsausführung weiter, bis der Basisfall erreicht ist.

Akkumulatoren sollten vom Autor der Funktion initialisiert werden, nicht von ihrem Nutzer. Dazu deklarierst du zwei Funktionen: eine öffentliche Funktion, die nur die nötigen Daten als Argumente entgegennimmt und den Akkumulator initialisiert, und eine private Funktion, die zusätzlich einen Akkumulator entgegennimmt.

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
