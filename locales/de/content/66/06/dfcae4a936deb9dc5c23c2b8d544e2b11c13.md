# Tupel

Ein [Tupel][tuple] ist eine endliche geordnete Liste von Elementen, die unveränderlich ist.
Tupel erfordern, dass alle Positionen einen festen Typ haben.
Das wiederum bedeutet, dass der Compiler weiß, welcher Typ an welcher Position steht.
Die Typen in einem Tupel können an jeder Position unterschiedlich sein, aber die Typen müssen zur Kompilierzeit bekannt sein.

## Ein Tupel erstellen

Je nachdem, ob die Typen der Tupelwerte bei der Kompilierung bestimmt werden können, lässt sich das Tupel auf verschiedene Arten erstellen.
Wenn die Werte zur Kompilierzeit bekannt sind, kannst du das Tupel mit der Tupel-Literal-Syntax erstellen, andernfalls musst du es explizit deklarieren.
Wichtig ist auch, dass die Typen der Werte mit den im Tupel angegebenen Typen übereinstimmen und dass die Anzahl der Werte mit der Anzahl der angegebenen Typen übereinstimmt.
Hier ist ein Beispiel für die Definition über die Tupel-Literal-Syntax:

```crystal
tuple = {1, "foo", 'c'} # Tuple(Int32, String, Char)
```

Es gibt auch die Möglichkeit, ein Tupel mit der Klasse `Tuple` zu erstellen.

```crystal
tuple = Tuple(Int32, String, Char).new(1, "foo", 'c')
```

Alternativ kannst du den Typ der Variable explizit angeben, der das Tupel zugewiesen wird.

```crystal
tuple : Tuple(Int32, String, Char) = {1, "foo", 'c'}
```

Den Typ des Tupels explizit anzugeben, kann nützlich sein, denn so kannst du festlegen, dass eine Position einen Union-Typ haben soll.
Das bedeutet, dass eine Position mehrere Typen enthalten kann.

```crystal
tuple : Tuple(Int32 | String, String, Char) = {1, "foo", 'c'}
```

## Konvertierung

### Ein Tupel aus einem Array erstellen

Du kannst mit der Methode `from` der Klasse `Tuple` ein Tupel aus einem Array erstellen.
Dazu muss der Typ des Tupels angegeben werden.

```crystal
array = [1, "foo", 'c']
tuple = Tuple(Int32, String, Char).from(array)
```

### Konvertierung in ein Array

Du kannst ein Tupel mit der Methode `to_a` in ein Array umwandeln.
Der Elementtyp des resultierenden Arrays ist die Vereinigung der Typen der einzelnen Felder im Tupel.

```crystal
tuple = {1, "foo", 'c'}
array = tuple.to_a
array # => [1, "foo", 'c']
```

### Kurzschreibweise für Tupeldefinitionen

Es gibt eine Kurzschreibweise für die explizite Definition von Tupeltypen.
Dazu schreibst du die Typen direkt in das Tupel-Literal.

```crystal
tuple : {Int32, String, Char} = {1, "foo", 'c'}
```

## Zugriff auf Elemente

Wie bei Arrays sind Tupel nullbasiert, das heißt, das erste Element steht an Index 0.
Anders als bei Arrays ist der Typ jedes Elements jedoch fest und zur Kompilierzeit bekannt, deshalb ist beim Indizieren eines Tupels der Typ des Elements von der Position abhängig.
Um auf ein Element in einem Tupel zuzugreifen, kannst du den Operator `[]` verwenden.

```crystal
array = [1, "foo", 'c']
array[0]         # => 1
typeof(array[0]) # => Int32 | String | Char

tuple = {1, "foo", 'c'}
tuple[0]         # => 1
typeof(tuple[0]) # => Int32
```

Ein weiterer Unterschied beim Zugriff auf Elemente von Arrays ist, dass der Compiler prüft, ob der Index innerhalb der Grenzen des Tupels liegt, wenn er angegeben wird.
Das heißt, du bekommst einen Fehler zur Kompilierzeit statt einen Laufzeitfehler.

```crystal
tuple = {1, "foo", 'c'}
tuple[3]
# => Error: index out of bounds for Tuple(Int32, String, Char) (3 not in -3..2)
```

Wenn der Index jedoch in einer Variable gespeichert ist, kann der Compiler zur Kompilierzeit nicht prüfen, ob der Index innerhalb der Grenzen des Tupels liegt, und gibt stattdessen einen Laufzeitfehler aus.

## Teiltupel

Du kannst mit dem Operator `[]` und einem Bereich ein Teiltupel eines Tupels erhalten.
Zurückgegeben wird ein neues Tupel mit den Elementen aus dem angegebenen Bereich.
Der Bereich muss zur Kompilierzeit angegeben werden, sonst kann der Compiler die Typen der Elemente im Teiltupel nicht kennen.
Das bedeutet, dass der Bereich ein Bereichsliteral sein muss und nicht einer Variable zugewiesen werden darf.

```crystal
tuple = {1, "foo", 'c'}
subtuple = tuple[0..1] # Tuple(Int32, String)

i = 0..1
tuple[i]
# Error: Tuple#[](Range) can only be called with range literals known at compile-time
```

## Wann du ein Tupel verwenden solltest

Tupel sind nützlich, wenn du eine feste Anzahl von Werten zusammenfassen möchtest, deren Typen zur Kompilierzeit bekannt sind.
Das liegt daran, dass Tupel weniger Speicher benötigen und schneller sind als Arrays, weil sie unveränderlich sind.
Ein weiterer Anwendungsfall ist die Rückgabe mehrerer Werte aus einer Methode.
Das ist besonders hilfreich, wenn die Werte unterschiedliche Typen haben, da jede Position im Tupel einen anderen Typ haben kann.

Tupel solltest du nicht verwenden, wenn du eine Datenstruktur brauchst, die wachsen oder schrumpfen kann oder oft geändert werden muss.
