# Reputation

Reputation ist das System, mit dem Menschen „Vertrauen" innerhalb des Exercism-Ökosystems aufbauen können.

Reputation ist ein Maß dafür, wie viel eine Person zu Exercism beigetragen hat, sowohl durch Beiträge zur Plattform (z. B. durch die Entwicklung von Software, Übungen und Dokumentation) als auch durch Beiträge zur Community (z. B. durch Mentoring).

Reputation kann man nicht „ausgeben" oder „verwenden". Wenn du jedoch bestimmte Reputationsgrenzen erreichst, erhältst du Zugang zu neuen Privilegien und Möglichkeiten, beizutragen. Einfach gesagt: Je mehr Reputation eine Person hat, desto mehr glauben wir, ihr vertrauen zu können, und desto mehr Befugnisse bekommt sie. Reputation ist außerdem ein öffentlich einsehbares Maß dafür, wie viel du zu Exercism beigetragen hast.

## Zweck

Das Reputationssystem hat folgende Ziele:

1. Wachstumsorientierte Interaktionen zwischen Lernenden und Mentoren maximieren
2. Die Motivation von Mentoren, beizutragen, maximieren

## Reputation erwerben

Reputation lässt sich auf verschiedene Arten erwerben:

| Aktion                            | Reputation |
| --------------------------------- | ---------- |
| Erfolgreiches Mentoring einer Lösung | 5          |
| Eine Lösung veröffentlichen             | 1-3        |
| Eine Übung schreiben               | 20         |
| Eine Übung aktualisieren              | 10         |
| Ein Konzept schreiben                 | 10         |
| Ein Konzept aktualisieren                | 5          |
| Einen Pull Request erstellen           | 3-100      |
| Einen Pull Request reviewen              | 1-20       |
| Einen Pull Request mergen                | 1-5        |

### Erfolgreiches Mentoring einer Lösung

Für jede Lösung, deren Mentoring erfolgreich abgeschlossen wurde (die Diskussion wurde beendet), werden `5` Reputation vergeben.

### Eine Lösung veröffentlichen

Für jede veröffentlichte Lösung wird Reputation vergeben, abhängig vom Schwierigkeitsgrad der Übung:

| Label    | Reputation |
| -------- | ---------- |
| `easy`   | 1          |
| `medium` | 2          |
| `hard`   | 3          |

### Eine Übung schreiben

Für jede Übung, bei der der Nutzer als Autor aufgeführt ist, werden `20` Reputation vergeben.

### Eine Übung aktualisieren

Für jede Übung, bei der der Nutzer als Mitwirkender aufgeführt ist, werden `10` Reputation vergeben.

### Ein Konzept schreiben

Für jedes Konzept, bei dem der Nutzer als Autor aufgeführt ist, werden `10` Reputation vergeben.

### Ein Konzept aktualisieren

Für jedes Konzept, bei dem der Nutzer als Mitwirkender aufgeführt ist, werden `5` Reputation vergeben.

### Einen Pull Request erstellen

Standardmäßig werden `12` Reputation vergeben, wenn ein Pull Request gemergt wird, den der Nutzer geöffnet hat.

Je nach Inhalt des Pull Requests kann ein Maintainer mehr (oder weniger) Reputation vergeben, indem er eines der folgenden Labels zum Pull Request hinzufügt:

| Label           | Reputation | Beispiele                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x:rep/tiny`    | 3          | <ul><li>Einen einzelnen Tippfehler oder Link korrigieren</li><li>Eine Leerzeile entfernen oder einen Zeilenumbruch hinzufügen</li><li>Einen einzelnen Code-Kommentar ändern oder hinzufügen</li></ul>                                                                                                                                                                                                                   |
| `x:rep/small`   | 5          | <ul><li>Einen einzelnen Testfall, eine einzelne Aufgabe oder ein einzelnes Beispiel korrigieren</li><li>Mehrere Tippfehler oder Links in einer einzelnen Datei korrigieren</li><li>Inhalt klarer machen, indem du einer Datei ein paar Zeilen hinzufügst</li></ul>                                                                                                                                                                                     |
| `x:rep/medium`  | 12         | <ul><li>Eine Übung mit problem-specifications synchronisieren (inkl. Änderungen)</li><li>Einen oder mehrere Testfälle von Grund auf hinzufügen</li><li>Mehrere Dateien in einer Übung verbessern</li><li>Mentor-Notizen für eine Übung von Grund auf hinzufügen</li><li>Einen kleinen Bug in einem Test-Runner/Analyzer/Representer beheben</li><li>Analyzer-Kommentare für eine einzelne Übung hinzufügen</li></ul> |
| `x:rep/large`   | 30         | <ul><li>Eine neue Konzept- oder Praxisübung hinzufügen</li><li>Neue Konzeptdokumentation hinzufügen</li><li>Umfangreiches Umschreiben eines bestehenden Konzepts oder einer bestehenden Übung</li><li>Neue CI-Skripte oder andere Automatisierung hinzufügen</li></ul>                                                                                                                                            |
| `x:rep/massive` | 100        | <ul><li>Einen Test-Runner, Analyzer, Representer oder Generator von Grund auf erstellen</li><li>Größere Refactorings dieser Tools</li><li>Umfangreiche Dokumentation von Grund auf erstellen (z. B. Leitfäden für Beiträge oder Tests)</li></ul>                                                                                                                                            |

Die Beispiele oben können als grobe Orientierung dafür dienen, wann welches Label angewendet werden sollte, aber Maintainer können nach eigenem Ermessen entscheiden.

- Die geschätzte Zeitangabe sollte als die durchschnittliche Zeit verstanden werden, die ein _Maintainer_ für die Arbeit am PR aufwenden würde.
- Wenn mehr als ein Label angegeben ist, bestimmt das Label mit dem höchsten Reputationswert die vergebene Reputation.
- Wenn ein Pull Request noch offen ist, wird (noch) keine Reputation vergeben.
- Wenn ein Pull Request geschlossen wird, _ohne_ gemergt zu werden, wird keine Reputation vergeben.

_Aus Gründen der Abwärtskompatibilität unterstützen wir auch die Verwendung der `x:size`-Labels, um die vergebene Reputation zu bestimmen._

### Einen Pull Request reviewen

Für jeden gemergten oder geschlossenen Pull Request, den der Nutzer reviewt hat, werden `5` Reputation vergeben.

- Wenn ein Pull Request noch offen ist, wird (noch) keine Reputation vergeben.
- Review-Reputation wird pro Nutzer und Pull Request nur einmal vergeben.
- Der Nutzer, der den Pull Request geöffnet hat, bekommt _keine_ Reputation dafür, seinen eigenen Pull Request zu reviewen.

- Die für ein Pull-Request-Review vergebene Reputation ändert sich, wenn eines der folgenden Labels zum Pull Request hinzugefügt wird:

  | Label           | Reputation |
  | --------------- | ---------- |
  | `x:rep/tiny`    | 1          |
  | `x:rep/small`   | 2          |
  | `x:rep/medium`  | 5          |
  | `x:rep/large`   | 10         |
  | `x:rep/massive` | 20         |

  Es ist _nicht_ möglich, unterschiedliche Reputations-„Größen" für den Autor und den Reviewer eines Pull Requests zu verwenden.
  Beide basieren auf demselben `x:rep`-Label.

  Wenn mehr als ein Label angegeben ist, bestimmt das Label mit dem höchsten Reputationswert die vergebene Reputation.

  _Aus Gründen der Abwärtskompatibilität unterstützen wir auch die Verwendung der `x:size`-Labels, um die vergebene Reputation zu bestimmen._

### Einen Pull Request mergen

Für jeden Pull Request, der vom Nutzer gemergt wurde, wird `1` Reputation vergeben.

- Wenn ein Pull Request noch offen ist, wird (noch) keine Reputation vergeben.
- Wenn ein Pull Request geschlossen wird, _ohne_ gemergt zu werden, wird keine Reputation vergeben.
- Der Nutzer, der den Pull Request geöffnet hat, bekommt _keine_ Reputation dafür, seinen eigenen Pull Request zu mergen.
- Wenn der Pull Request keine Reviews hat, werden stattdessen `5` Reputation vergeben.

### Ein Issue öffnen

Wie bei Pull Requests wird standardmäßig **keine Reputation vergeben**, wenn ein Issue geöffnet wird.
Anders als bei Pull Requests wird Reputation nur für große oder massive Issues vergeben.

Je nach Inhalt des Issues kann ein Maintainer Reputation vergeben, indem er eines der folgenden Labels zum Issue hinzufügt:

| Label           | Reputation | Beispiele                                             |
| --------------- | ---------- | ---------------------------------------------------- |
| `x:rep/large`   | 30         | <ul><li>Eine vollständig ausgearbeitete Konzeptübung</li></ul> |
| `x:rep/massive` | 100        | <ul><li>Einen Lehrplan für einen Track entwerfen</li></ul>       |

Die Beispiele oben können als grobe Orientierung dafür dienen, wann welches Label angewendet werden sollte, aber Maintainer können nach eigenem Ermessen entscheiden.

- Die Reputation sollte den Aufwand widerspiegeln, den ein _Maintainer_ für das Erstellen des Issues aufwenden würde.

- Wenn mehr als ein Label angegeben ist, bestimmt das Label mit dem höchsten Reputationswert die vergebene Reputation.
