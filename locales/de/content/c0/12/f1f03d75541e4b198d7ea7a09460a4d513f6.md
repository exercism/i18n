# Über

`<dlist>` (in [`dlists`][dlists]) erzeugt eine neue doppelt verkettete Liste. Die Operationen befinden sich in [`deques`][deques] und dispatchen auf das [Deque-Protokoll][deque-protocol], sodass andere Container, vor allem `<dlist>`, sie implementieren können.

| Wort            | Wirkung                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`: neue leere Deque  |
| `push-front`    | `( elt deque -- )`: vorne einfügen |
| `push-back`     | `( elt deque -- )`: hinten einfügen  |
| `pop-front`     | `( deque -- elt )`: vorne entfernen |
| `pop-back`      | `( deque -- elt )`: hinten entfernen  |
| `peek-front`    | `( deque -- elt )`: vorne lesen, ohne zu entfernen |
| `peek-back`     | `( deque -- elt )`: hinten lesen, ohne zu entfernen  |
| `deque-empty?`  | `( deque -- ? )`: Ist die Deque leer? |
| `dlist-length`  | `( dlist -- n )`: Anzahl der Elemente |

Alle Push-/Pop-Operationen verändern die Deque an Ort und Stelle. Eine Deque an eine Routine zu übergeben und danach wieder aus ihr zu lesen, ist das normale Muster.

## Stack vs. Warteschlange

Zwei übliche Dispatch-Muster:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

Ein Vektor mit `push` und `pop` (aus `mutation`) ist die richtige Wahl, wenn dir LIFO-Reihenfolge genügt; `<dlist>` trägt den Overhead einer verketteten Liste. Greife zu `<dlist>`, wenn du O(1) an *beiden* Enden brauchst, fast immer für eine FIFO-Warteschlange.

## BFS-Muster

Eine Breitensuche (BFS) ist der klassische FIFO-Anwendungsfall:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

Die Deque trägt die Suchfront; das Hash-Set trägt die Deduplizierung. Tausche `pop-front` gegen `pop-back`, und dieselbe Form wird zu einer Tiefensuche.

## `MEMO:`: automatisches Zwischenspeichern

Manchmal ist der Lookup pro Knoten, den die BFS aufruft, teuer. Factor stellt [`MEMO:`][memo-decl] bereit, einen Ersatz für `:`, der das Ergebnis des Wortes automatisch zwischenspeichert, mit seinen Eingaben als Schlüssel:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

Ein `MEMO:`-Wort führt seinen Rumpf beim ersten Auftreten jeder Eingabe aus und gibt danach das zwischengespeicherte Ergebnis zurück. Der Cache lebt für die Lebensdauer des Image; es gibt keine zeit- oder größenbasierte Verdrängung. Verwende es für reine Funktionen, deren Eingaben aus einer endlichen, überschaubaren Menge stammen.
