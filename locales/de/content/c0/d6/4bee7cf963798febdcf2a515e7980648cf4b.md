# Einführung

Handgeschriebener Assembly-Code steckt voller Wiederholungen.
Dieselbe kurze Folge von Anweisungen taucht immer wieder auf, mit kaum Variation, und es gibt nur wenige Abstraktionen, um Boilerplate-Code zu reduzieren.
Hinzu kommt, dass man beim Programmieren in Assembly Werte verwalten muss, deren Bedeutung nicht offensichtlich ist.
Es gibt keine benannten Parameter, und die meisten Details der darunterliegenden Maschinerie muss man selbst von Hand behandeln.

NASM, der in diesem Track verwendete Assembler, bietet einige Werkzeuge, die bei beiden Problemen helfen können.
Diese Werkzeuge laufen zur _Assemble-Zeit_, bevor eine Anweisung den Prozessor erreicht.
Sie weisen den Assembler an, wie er den Quelltext umschreiben soll, noch bevor dieser überhaupt in Maschinencode übersetzt wird.

Das wichtigste dieser Werkzeuge sind **Makros**, die man sich als ein Rezept für den Assembler vorstellen kann.
Sie werden an der Stelle, an der sie verwendet werden, entfaltet, als wäre der Code dort von Hand geschrieben worden.

Makros können eine Reihe von literalen Tokens als Parameter annehmen, wodurch sie in verschiedenen Kontexten wiederverwendbar sind.
Sie sind jedoch keine Funktionen: Es gibt kein `call`, kein `ret`, keine Übertragung der Kontrolle an eine andere Stelle im Code.

## Einzeilige Makros

Die einfachste Definition gibt einem Wert oder einem kurzen Ausdruck mit `%define` einen Namen:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Jedes spätere Vorkommen von `WIDTH` wird vor der Assemblierung durch `8` ersetzt.
Die Ersetzung ist textuell, der Name wird also überall dort eingesetzt, wo er auftaucht, ob in einem Operanden oder innerhalb einer anderen Definition.

~~~~exercism/note
Für numerische _Konstanten_ verwende lieber `equ` statt `%define`.

Ein einzeiliges Makro, das mit `%define` deklariert wird, wird erst beim Verwenden entfaltet und kann neu zugewiesen oder gelöscht werden.
Eine `equ`-Konstante hingegen wird an der Stelle ihrer Definition ausgewertet und niemals geändert.
~~~~

Ein `%define` kann auch _benannte_ Parameter annehmen und verhält sich dann wie eine kleine Inline-Funktion:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Setze sowohl den gesamten Rumpf als auch jeden Parameter in Klammern.
Mit `%define square(x) x*x` wird der Aufruf `square(1+1)` zu `1+1*1+1`, was `3` ergibt.
Als `%define square(x) ((x)*(x))` geschrieben, wird derselbe Aufruf zu `((1+1)*(1+1))`, was `4` ergibt.
~~~~

Namen, die mit `%define` definiert werden, unterscheiden zwischen Groß- und Kleinschreibung.
Die Variante `%idefine` macht den Namen unabhängig von Groß- und Kleinschreibung, falls das gewünscht ist.

Einzeilige Makros sind nützlich, um verschiedenen Teilen des Codes eine Bedeutung zu geben.
Mit Bedacht eingesetzt verbessern sie die Lesbarkeit und verringern die Gefahr von Tippfehlern.
Ein Register, das innerhalb einer Funktion einen festen Zweck erfüllt, kann zum Beispiel nach diesem Zweck benannt werden:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Mehrzeilige Makros

Eine ganze Codefolge mit beliebig vielen Zeilen wird mit `%macro` erfasst und mit `%endmacro` abgeschlossen.
Eine Zahl nach dem Namen gibt an, wie viele Argumente das Makro annimmt; das können auch null sein.
Beim Übergeben von Argumenten werden diese durch ein Komma (`,`) getrennt:

```x86asm
%macro example_macro 0
...
%endmacro
```

Argumente in mehrzeiligen Makros haben keine Namen.
Sie werden als `%1`, `%2` und so weiter bezeichnet, und zwar in der Reihenfolge, in der sie übergeben werden:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Beachte, dass die Argumente gültige Syntax für die Operationen sein müssen, die im Rumpf des Makros ausgeführt werden.
Hier lassen sich `mult_two eax, ecx` und `mult_two r8, r9` beide assemblieren, `mult_two eax, cl` jedoch nicht, da `imul eax, cl` nicht definiert ist.

### Labels innerhalb eines Makros

Ein Makro, das ein gewöhnliches Label definiert, funktioniert nicht mehr, sobald es ein zweites Mal verwendet wird, denn dann würde das Label ebenfalls zweimal definiert.
Um Labels in einem Makro zu verwenden, das mehr als einmal aufgerufen werden kann, muss man einem solchen Label `%%` voranstellen.
Das weist den Assembler an, diesem Label bei jeder Entfaltung einen anderen, eindeutigen Namen zu geben:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Wiederholen zur Assemble-Zeit

Mit `times` kann man einen einzeiligen Codeblock wiederholen.
Das ist besonders nützlich, wenn man wiederholte Werte im Speicher deklariert:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Für die Wiederholung mehrzeiligen Codes können wir stattdessen `%rep` verwenden:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Beachte, dass die Anzahl der Wiederholungen direkt nach `%rep` angegeben wird und ein `%endrep` den wiederholten Block abschließt.

Es ist üblich, innerhalb eines `%rep`-Blocks einen Zähler zur Assemble-Zeit zu verwenden, ähnlich wie eine Schleife zur Laufzeit einen Zähler nutzt.
Während eine ganzzahlige Konstante zur Assemble-Zeit mit `equ` deklariert werden kann, verwenden wir für ganzzahlige _Variablen_ zur Assemble-Zeit stattdessen `%assign`.
Anders als `%define` wird `%assign` sofort zu einer Zahl ausgewertet und kann neu zugewiesen werden:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Nachdem der Präprozessor gelaufen ist, ist die Schleife verschwunden, und es bleiben vier `add`-Anweisungen übrig, in die die Immediate-Werte `0`, `1`, `2` und `3` fest eingebaut sind.
Das ist Loop-Unrolling, das der Assembler übernimmt: kein Zählerregister und kein Sprung, nur geradliniger Code.

## Bedingte Assemblierung

Dem Präprozessor stehen verschiedene Bedingungen zur Verfügung.
Sie wählen zwischen mehreren verschiedenen Pfaden und entfalten ihren Rumpf an Ort und Stelle, aber nur, wenn ihre Bedingung zutrifft.

`%if` ... `%elif` ... `%else` ... `%endif` wählen anhand eines numerischen Tests einen Zweig aus:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## Aufteilen auf Dateien

Makros werden oft in einer eigenen Datei gehalten und mit `%include` in jede Quelldatei eingebunden, die sie braucht:

```x86asm
%include "patterns.mac"
```

Die genannte Datei wird an dieser Stelle vor der Assemblierung wörtlich eingefügt, genau als hätte man ihren Inhalt dort eingetippt.
So bleiben die Definitionen an einem Ort, und mehrere Quelldateien können sie gemeinsam nutzen.

Wenn die Makrodatei auch für sich allein assembliert werden können soll, sollte sie die Dateiendung `.asm` haben.
Beachte, dass Makros keine Linkage haben.
Selbst wenn die Makrodatei assembliert wird, sind ihre Makros nur für eine andere Datei sichtbar, die sie mit `%include` einbindet.

Ansonsten kann eine Datei, die nur per `%include` eingebunden wird, jede beliebige Dateiendung haben.
Üblicherweise verwendet man entweder `.asm` oder `.mac`.
