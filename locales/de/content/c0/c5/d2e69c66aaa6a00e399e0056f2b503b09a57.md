# Einführung

## Referenzen

### Kopien und Referenzen

Mit unserem aktuellen Wissen ist es etwas umständlich, eine Variable mit Hilfe einer Funktion zu aktualisieren.
Jedes Argument einer Funktion wird wie eine Kopie behandelt und verändert den ursprünglichen Wert nicht.
Je nach Größe deines Typs kann das ernste Folgen für die Performance deines Codes haben.

```cpp
int adjust_salary(int base, int kids) {
    return base + kids * 500;
}
int now_a_mother_of_twins{2500};
adjust_salary(now_a_mother_of_twins, 2);

// now_a_mother_of_twins is still 2500
now_a_mother_of_twins = adjust_salary(now_a_mother_of_twins, 2);
// now_a_mother_of_twins is now 3500
```

`References` kann man als Aliase betrachten: Änderungen daran wirken sich auf die ursprüngliche Variable aus.
`References` verwenden ein **Ampersand** (`&`) in der Typdeklaration.

```cpp
int balance{1000};
int& budget{balance};
int pro_computer_wheels{699};
budget -= pro_computer_wheels;
// budget is now 301;
// balance is also 301;
```
Ein Neusetzen (das Ändern der Bindung einer `reference`) ist nicht möglich.
Du kannst keine nicht initialisierte `reference` haben.
`References` müssen mit einer existierenden Variable initialisiert werden.

```cpp
int main_acc{1'000'000};
int side_acc{-20};
int& savings{main_acc};
// => main_acc and savings are 1'000'000

// try to reseat savings to use main account
savings = side_acc;
// savings and main_acc are now -20
// as this uses the **value** of side_acc
savings += 20;
// savings and main_acc are now 0, side_acc is still -20

int& future_budget;
// => compiler error, reference must be bound!
```

### `void`

Mit der Macht der `references` musst du vielleicht gar keinen Wert aus einer Funktion zurückgeben.
In diesem Szenario wird `void` als Rückgabetyp verwendet.

```cpp
void increase_power(int& level) {
    level += 500;
}
int goku{8700};
increase_power(goku);
// goku's power level?
// It's over 9000!
```
