# Einführung

Wie im Konzept [`Nothingness`][concept-nothingness] beschrieben, hat R verschiedene Möglichkeiten, Daten darzustellen, die fehlen (`NULL`), unbekannt (`NA`) oder mathematisch ungültig (`NaN`, `Inf`) sind.
Im Allgemeinen versucht R, damit Probleme an Ort und Stelle zu markieren und weiterzulaufen, ohne eine Ausnahme auszulösen.

## `stop()`

Manche Probleme sind so grundlegend, dass das Programm nicht weiterlaufen kann.
In diesem Fall verwendest du `stop(msg)`, um das Programm sofort mit einem `Error` anzuhalten und `msg` auszugeben.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Ähnlich wie ein `assert` in anderen Sprachen ist dies ein praktischer Wrapper für `stop()`.
Die Parameter sind eine beliebige Anzahl durch Kommas getrennter boolescher Bedingungen, und das Programm läuft nur weiter, wenn alle `TRUE` sind.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R hat eine Vielzahl von Möglichkeiten, mit Fehlern umzugehen.
Sie basieren auf Common Lisp und unterscheiden sich deutlich von vielen populären Sprachen.

Am einfachsten packst du potenziell problematischen Code in `try()` ein.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()` und `message()`

Dies sind Reaktionen auf nicht fatale Bedingungen, zum Beispiel:

- um vor einem Problem zu warnen, von dem sich das Programm zumindest teilweise erholen könnte.
- um bei einem lang laufenden Programm über den Fortschritt zu informieren.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

Die Funktion `suppressWarnings()` kann bei Exercism gelegentlich nützlich sein, um den Test-Runner nicht mit unerwünschter Ausgabe zu verwirren.
