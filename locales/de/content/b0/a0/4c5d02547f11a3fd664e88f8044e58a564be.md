# Über

## JSON

[JSON][json] (JavaScript Object Notation) ist ein für Menschen lesbares Daten- und Dateiformat, das häufig zum Austausch von Daten verwendet wird, insbesondere für Webanwendungen.
Es überrascht daher nicht, dass es in der Sprache Elm einen besonderen Platz einnimmt.

Elm stellt die Kernmodule [`Json.Decode`][decode] und [`Json.Encode`][encode] bereit, um JSON-Daten zu parsen und zu schreiben.
JSON-Decoder sind eine Möglichkeit, zu _deklarieren_, welcher Datentyp erwartet wird und auf welche Datenstruktur die Daten abgebildet werden sollen.

Wenn du aus dynamisch typisierten Sprachen kommst, wirken Decoder oft umständlich oder auf den ersten Blick zu starr.
Sie sind zwar sicherlich wortreich, zumindest in Elm, aber sie sind ein wertvolles Werkzeug, um die Erwartungen eines Programms an eingehende Daten explizit zu beschreiben, und sie sind [nicht weniger ausdrucksstark als dynamische Typen][dynamic-types-not-more-open].

Importieren wir zunächst einige Aliase und Typen aus den Modulen:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Wenn du `Decode.decodeString : Decoder a -> String -> Result Error a` mit einem Decoder und einem JSON-String verwendest, gelingt es entweder, wenn der String den Vorgaben des Decoders entspricht, oder es schlägt fehl.
Beim Definieren des Decoders gibt es keine Möglichkeit, die rohen JSON-Daten zu untersuchen, was aus imperativen Sprachen kommend ungewöhnlich wirken kann.

## Decoder für grundlegende Datentypen

JSON kennt eine kleine Anzahl grundlegender Datentypen:

- String: wird mit doppelten Anführungszeichen kodiert, `"hello world"`
- Boolescher Wert: entweder `true` oder `false`
- Zahl: etwa `34` oder `0.12`
- Null: die Abwesenheit von Daten, `null`

Jeder dieser Typen ist mit einer `Decode`-Funktion verknüpft:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Beachte, dass du mit `Decode.null` selbst entscheiden kannst, wie du ein `null` in deinem Programm modellierst, indem du einen beliebigen Wert als Argument übergibst (vielleicht `()`, `Nothing` oder etwas, das zu deinem Programm passt).

## Decoder kombinieren

JSON definiert außerdem zwei Datenstrukturen, um grundlegende Datentypen zu sammeln:

- Array: eine Sammlung anderer Datentypen, `[0, null, "none", []]`
- Objekt: eine Sammlung von Schlüssel-Wert-Paaren, `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` bietet auch Funktionen, um diese zu dekodieren:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Diese Funktionen `Decode.list : Decoder a -> Decoder (List a)` und `Decode.dict : Decoder a -> Decoder (Dict String a)` erwarten jeweils einen Decoder als Argument, der jedes einzelne Element der Datenstruktur dekodieren soll.
Wenn der übergebene Decoder ein Element eines Array- oder Objektwerts nicht dekodieren kann, schlägt der gesamte Decoder fehl, was ein häufiges Muster ist.

Einfache Decoder zu komplexeren zu kombinieren ist die Kernidee dieser Technik.
Anhand eines Beispiels stellen wir noch einige Funktionen vor, mit denen du beliebig komplexe Decoder für echte Daten bauen kannst.

## GeoJSON

Um das Kombinieren einfacher Decoder zum Parsen komplexer JSON-Daten zu üben, bauen wir Decoder zum Parsen (einer Teilmenge) von GeoJSON-Daten.
[GeoJSON][geojson] ist ein spezialisiertes, auf JSON basierendes Datenformat zur Darstellung geografischer Objekte wie Orte, Pfade oder Regionen, die durch 2D- oder 3D-Koordinaten zusammen mit weiteren Eigenschaften beschrieben werden.

### Geometrie-Objekt

Ein GeoJSON-Geometrie-Objekt ist ein Objekt, das ein Feld `type` mit einem String-Wert enthält (es gibt 7 mögliche Typwerte) und ein Feld `coordinates` mit geografischen Koordinaten (in einer Struktur gesammelt, die vom Typ abhängt).
Zum Beispiel:

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

oder

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Ein Geometrie-Objekt könnte in Elm mit folgendem Typ dargestellt werden

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Um den Wert eines bestimmten Feldes abzufragen, kannst du `Decode.field : String -> Decoder a -> Decoder a` verwenden, das den Wert eines bestimmten Schlüssels eines Objekts dekodiert.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Um den von einem Decoder erfolgreich geparsten Wert umzuwandeln, kannst du `Decode.map : (a -> value) -> Decoder a -> Decoder value` verwenden oder eines seiner Geschwister, von `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` bis `Decode.map8`.

In diesem Fall wollen wir abhängig vom Wert im Feld `type` entscheiden, welchen Koordinaten-Decoder wir verwenden, und dafür sind `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` und seine Freunde `Decode.succeed : a -> Decoder a` und `Decode.fail : String -> Decoder a` wie geschaffen.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

An dieser Stelle sei angemerkt, dass wir `Decode.andThen` auch verwenden könnten, um die Koordinaten zu validieren (wir könnten prüfen, ob die Koordinaten paar- oder drillingsweise auftreten und ob die Koordinatenwerte geografisch sinnvoll sind).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### Feature-Objekt

Ein GeoJSON-Feature-Objekt stellt etwas räumlich Begrenztes dar: Es hat ein Feld `type` mit dem Wert `"Feature"`, ein Feld `geometry` mit einem Geometrie-Objekt oder einem `null`, ein Feld `properties` mit einem beliebigen JSON-Objekt oder einem `null` und ein optionales Feld `id` mit einem JSON-String- oder Zahlenwert.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

oder

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Kümmern wir uns zunächst um das Feld `id`.
Wenn es existiert, muss es Strings oder Zahlen aufnehmen können, also könnten wir entweder einen eigenen Typ für den Wert einführen oder ihn immer als String speichern.

Um zwischen zwei möglichen Decodern zu wählen, kannst du `Decode.oneOf : List (Decoder a) -> Decoder a` verwenden.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Um auszudrücken, dass das Feld optional ist, könnten wir dieselbe Technik verwenden

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Wir könnten aber stattdessen `Decode.maybe : Decoder a -> Decoder (Maybe a)` verwenden

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Beachte, dass `decodeMaybeFeatureId` (oder jeder mit `Decode.maybe` umhüllte Decoder) immer erfolgreich ist, da er immer auf `Ok Nothing` zurückfallen kann, auch wenn ein Decoder, der ihn verwendet, trotzdem fehlschlagen kann

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

Als Nächstes schauen wir uns das Feld `geometry` an, das entweder ein Geometrie-Objekt oder `null` sein kann.
Wir könnten wieder `Decode.oneOf` verwenden, aber es gibt eine bessere Option: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` und `Decode.nullable` haben dieselbe Signatur, verhalten sich aber unterschiedlich: Das Ergebnis `OK Nothing` eines `Decode.nullable` stammt nur vom konkreten JSON-Wert `null`.

Schließlich kann das Feld `properties` ein beliebiges JSON-Objekt oder `null` enthalten, und dafür ist `Decode.value : Decoder Value` zuständig.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Beachte, dass `Value` ein opaker Typ ist, du kannst seinen Inhalt also nicht ohne Weiteres untersuchen.
Um ihn zu nutzen, kannst du entweder einen Decoder dafür schreiben und ihn mit `Decode.decodeValue : Decoder a -> Value -> Result Error a` ausführen oder ihn direkt über einen Port an JavaScript senden.

Jetzt sind wir bereit, Feature-Objekte zu parsen:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## JSON-Encoder

Mit Encodern kannst du gültiges JSON aus Elm-Werten schreiben, und zwar mit der Funktion `Encode.encode : Int -> Value -> String`.
Das erste Argument legt die Anzahl der Einrückungen im Endergebnis fest, das zweite Argument ist der zu schreibende JSON-Wert.

Einen `Value` erhältst du entweder über `Decode.value`, oder du erzeugst ihn mit einem der Encoder:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

sowie mit `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Definieren wir nun Encoder für die zuvor definierten GeoJSON-Decoder

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

Im Allgemeinen ist ein guter Test für deine Decoder-Encoder-Paare die Prüfung, ob `elmValue |> encoder |> decoder == elmValue` gilt.

## Was noch?

Wir haben nicht jede einzelne Funktion in den `Json`-Modulen behandelt.
Zu den nicht erwähnten Dingen gehören: Decoder, die Arrays in `Array` oder Objekte in `List (String, a)` umwandeln, Decoder für Arrays mit einem oder mehreren Elementen, Decoder für bestimmte Felder in verschachtelten JSON-Objekten oder bestimmte Elemente in Arrays, das Dekodieren rekursiver Strukturen sowie die verschiedenen Varianten von `Error` und ihre Darstellung.

Andere häufig verwendete Pakete sind [`Json.Decode.Pipeline`][pipeline], das einen komfortablen Ablauf für komplexe JSON-Strukturen bietet, und [`Json.Decode.Extra`][extra], das weitere Decoder, Encoder und Hilfsfunktionen bereitstellt.
