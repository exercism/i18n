# Über

[Records][records] sind Datenstrukturen, die zusammengehörige Informationen unter Bezeichnungen bündeln.
Sie ähneln Objekten in JavaScript oder Java oder Structs in C oder Rust, unterscheiden sich aber in einigen wichtigen Punkten.

## Records erstellen

Records werden mit geschweiften Klammern [erstellt][create] und ihre Elemente werden durch Kommas getrennt.

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Der Typ eines Records wird ebenfalls mit einer ähnlichen Syntax definiert, nur dass Gleichheitszeichen `=` durch Doppelpunkte `:` ersetzt werden.

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Diese Typdefinitionen immer zu wiederholen ist mühsam, deshalb ist es ein gängiges Idiom, einen [Typalias][record-types] zu verwenden, um die Definition zu teilen.

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Der Typalias liefert außerdem automatisch eine Konstruktorfunktion für den Record.
Das ist manchmal überraschend, da Funktionen in Elm mit einem Kleinbuchstaben beginnen müssen, aber Typkonstruktoren sind eine Ausnahme.

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

## Auf Record-Felder zugreifen

Der wichtigste Weg, [auf den Wert eines Feldes einer Record-Instanz zuzugreifen][access], ist die Punktnotation wie `firefly.creator`.
Der Elm-Compiler unterstützt außerdem spezielle Zugriffsfunktionen, die mit einem Punkt `.` beginnen, wie `.creator`, und die bei jedem Record funktionieren, der ein Feld mit diesem Namen hat.
Das ist die zweite Ausnahme von der Regel, dass Funktionen mit einem Kleinbuchstaben beginnen müssen.
Tatsächlich müssen selbst definierte Funktionen mit einem Kleinbuchstaben beginnen, aber die beiden Beispiele, die wir gerade entdeckt haben, werden vom Compiler erzeugt, nicht vom Programmierer.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

Records können in Bindungen auch _destrukturiert_ werden, indem man den [Musterabgleich für Records][pattern-matching] verwendet.
Das Destrukturieren funktioniert mit jedem Record, der Felder mit den entsprechenden Namen hat.

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

## Records aktualisieren

Records sind unveränderlich, wie alles in Elm. Sobald ein Record definiert ist, können sich seine Feldwerte nie mehr ändern.
Es gibt eine [spezielle Syntax, um eine Kopie eines bestehenden Records zu erstellen und dabei ein oder mehrere Felder zu ändern][update].
Diese Syntax verwendet das Pipe-Symbol `|`, um den ursprünglichen Record und die Felder, die sich ändern, zu unterscheiden, wie in `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

## Records vergleichen

Elm verwendet [strukturelle Gleichheit][equality]. Das heißt, zwei Instanzen desselben Records mit identischen Werten sind gleich.

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

## Erweiterbare Records

Elm unterstützt außerdem [strukturelle Typisierung][structural-typing]. Das bedeutet: Wenn eine Funktion einen Record mit einem Feld x und einem Feld y erwartet, funktioniert sie mit jedem Record, der diese Felder hat, etwa 2D-Punkten, 3D-Punkten, Raumschiffen usw.
Diese Record-Typen haben ein Pipe `|` in ihrer Definition, wie `{ a | x : Float, y : Float }`, und heißen in der Elm-Terminologie „erweiterbare Records“.
Achte auf den Unterschied zwischen einem Pipe `|` in einer Typdefinition, also der Definition eines erweiterbaren Records (`{ a | x : Int }`), und einem Pipe `|` in einer tatsächlichen Record-Instanz, was bedeutet, dass wir einige Felder dieses Records aktualisieren.

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
