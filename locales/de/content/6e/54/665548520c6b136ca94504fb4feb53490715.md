# Einführung

In vielen objektorientierten Sprachen ist es üblich, Verhalten zu erweitern, indem man von einer Elternklasse [eine Unterklasse ableitet][wiki-subclass], Methoden von der Elternklasse erbt und gleichzeitig neue hinzufügt.
So entsteht eine Objekthierarchie.

Julia _hat keine Klassen_ und folglich auch _keine Unterklassen_.
Wie erben und erweitern wir also bestehendes Verhalten?

In früheren Konzepten haben wir gesehen, wie man eine Typhierarchie erstellt, und dabei auch gelernt, wie Julia [Multiple Dispatch][concept-multiple-dispatch] nutzt, um Methoden anhand der Argumenttypen auszuwählen.

Julia hat außerdem mehrere informelle Schnittstellen, mit denen deine eigenen Typen an Verhalten anknüpfen können, das bereits für Standardtypen definiert ist.

Am einfachsten lässt sich das an der Iterator-Schnittstelle zeigen.

## Iteratoren

Im Lehrplan haben wir bereits mehrere Möglichkeiten gesehen, wie Julia mit jedem Element einer Sammlung arbeiten kann.

- [Schleifen][concept-loops], wie `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Funktionen höherer Ordnung][concept-hof]: `map(√, [1, 4, 9])`
- [Comprehensions][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Generatoren][concept-comprehensions]: `(x^2 for x in 1:1e6)`, das erst bei Bedarf ausgewertet wird.

Julia kann also offenbar Standard-Sammlungen Element für Element durchlaufen: Vektoren und Ranges in den obigen Beispielen, aber auch Sets, Dicts usw.

Wie fügen wir diese Fähigkeit unseren eigenen Sammlungen hinzu, besonders wenn sie sich wie ein Generator erst bei Bedarf durchlaufen lassen?

### Minimale Anforderungen

Um eine Sequenz zum Iterieren zu erstellen, brauchen wir (mindestens) zwei Dinge:

1. Eine Möglichkeit, das _erste_ Element zu bekommen.
2. Eine Möglichkeit, das _nächste_ Element aus dem aktuellen Zustand zu bekommen.

Julia erledigt diese Aufgaben mit Methoden der Funktion `Base.iterate()` in den folgenden Schritten:

1. `Base.iterate(iter)` wird automatisch zuerst aufgerufen.
    - Wenn es nichts zu iterieren gibt, wird `nothing` zurückgegeben.
    - Andernfalls wird das `Tuple` aus dem ersten zurückgegebenen Element und dem ersten Zustand zurückgegeben: `(firstitem, firststate)`.
2. `Base.iterate(iter, state)` wird automatisch aufgerufen, wenn in der vorherigen Iteration ein Element zurückgegeben wurde, und nimmt `firststate` als sein `state`-Argument.
    - Wenn die Iteration endet, wird `nothing` zurückgegeben.
    - Andernfalls wird das `Tuple` aus dem nächsten Element und dem nächsten Zustand zurückgegeben: `(nextitem, nextstate)`.
3. Wiederholt Schritt 2 bis zum Abbruch.

Diese Schritte laufen alle „unter der Haube“ ab. Das heißt, die Methodenaufrufe und der Zustand werden intern vom Iterationsprotokoll verwaltet (der Zustand bleibt undurchsichtig), und nur das Element wird für High-Level-Konstrukte wie Schleifen sichtbar.
Anders gesagt: Wir sehen immer nur das `item`, während alles andere in einer Blackbox bleibt.

[Multiple Dispatch][concept-multiple-dispatch] ist hierbei zentral.
Der Typ von `iter` bestimmt, welche Methoden aufgerufen werden, und die Anzahl der Argumente bestimmt, ob das erste oder das nächste Element zurückgegeben wird.

Methoden für Standardtypen sind bereits definiert: `Vector`, `Range`, `Set` usw. ([derzeit][ref-iterations-collections] insgesamt 14 Typen).

Damit ein eigener `MyType` dasselbe Verhalten teilt, müssen wir zuerst definieren:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Das klingt in der Theorie wahrscheinlich verwirrend, kann aber ganz einfach sein.
Stell dir zur Veranschaulichung vor, wir wollen einen Typ, der Potenzen einer gegebenen Ganzzahl `n` liefert, bis zu einer maximalen Anzahl.

Definiere zuerst einen eigenen Typ:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Jetzt können wir die `iterate`-Methoden für diesen Typ definieren, aber was sind das erste Element und der erste Zustand?

Um das erste Element zu bekommen, brauchen manche Iteratoren einen komplizierten Aufbau, aber in diesem Spielzeugfall sehen wir, dass das erste zurückgegebene Element einfach die Basiszahl ist. Wir müssen also nur prüfen, ob der Wert von `count` größer oder gleich eins ist.

Nun betrachten wir den ersten Zustand, der Informationen trägt, die für die nächste Iteration verwendet werden.
Du entscheidest, welche Informationen du dafür im Blick behalten musst, und es kann ein beliebiger Typ sein.

In diesem Fall könnten wir einfach den „Index“ verfolgen, mit dem `n` potenziert wird, oder wir finden eine performantere Variante, indem wir die zuletzt berechnete Potenz von `n` (also das zurückgegebene Element) und den nächsten „Index“ in der Sequenz nutzen.
Diese beiden Zahlen können in ein `Tuple` gepackt und als `state` zurückgegeben werden.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

In diesem Beispiel wird das erste Element (`p.n`) an die Schleife zurückgegeben und der erste Zustand `(p.n, 2)` an die Methode `iterate(P::Powers, state)` übergeben.
Dort können wir den Zustand verarbeiten, um das nächste Element zu erzeugen, indem wir das aktuelle Element mit der Basiszahl multiplizieren und so seine Potenz um `1` erhöhen.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Wenn der Indexwert noch innerhalb von `count` liegt, wird das `Tuple` mit dem `next`-Element und dem erhöhten Zustands-`Tuple` zurückgegeben.
Wenn der Wert von `index` `count` überschreitet, wird stattdessen `nothing` zurückgegeben, um anzuzeigen, dass die Iteration beendet ist.

Vielleicht ist dir aufgefallen, dass die Methoden `iterate(p::Powers)` und `iterate(p::Powers, state)` recht ähnliche Funktionskörper haben.
Tatsächlich erlaubt diese Ähnlichkeit, wenn wir geschickt sind, eine schlankere Implementierung, indem wir nur die Version mit zwei Argumenten und einem Standardargument für den Zustand verwenden: `Base.iterate(p::Powers, state=(1, 1))`
Damit bräuchten wir die separate Version mit nur einem Argument `iterate(p::Powers)` nicht.
Das macht man in der Praxis häufig, wenn es möglich ist.

Bisher haben wir schon einige nützliche Funktionen: Für die ersten 4 Potenzen von 3 können wir die Ergebnisse durchlaufen, prüfen, ob eine gegebene Zahl in den Ergebnissen vorkommt, und Aggregatfunktionen wie `sum()` anwenden.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Weitere Methoden

Trotz dieses guten Starts funktioniert noch nicht alles.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Und tatsächlich liefert `length(Powers(3, 4))` genau dieselbe Fehlermeldung.

Das lässt sich leicht beheben, denn die Länge ist Teil des Typkonstruktors: in diesem Fall 4.
Wir müssen nur `Base.length()` für diesen Typ definieren, dann können wir Comprehensions und `collect()` auf die Sequenz anwenden.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Aus Effizienzgründen ist es am besten, auch `Base.eltype()` zu definieren: den Elementtyp des Ergebnisses.
Dadurch können Funktionen wie `collect()` den Speicher für den Ausgabe-`Vector{Int}` im Voraus reservieren, statt wiederholt ein `push!()` auf einen `Vector{Any}` auszuführen.

Beachte die Syntax, die du vielleicht noch nicht gesehen hast: Diese Methode wird für den _Typ_ definiert, nicht für eine _Instanz_ des Typs.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Iteratoren müssen keine endliche Länge haben.
Die Verwendung „unendlicher“ Sequenzen ist eingeschränkter, aber das Durchlaufen kann nützlich sein, solange es einen Weg gibt, die Schleife mit `break` zu verlassen.
Zum Beispiel könnten wir eine Variante von `Powers` definieren, die Werte kleiner als eine bestimmte Grenze erzeugt (vielleicht `typemax(Int)`, um einen Ganzzahl-Überlauf zu vermeiden).

## Zusammenfassung

Schnittstellen sind recht verwirrend zu erklären, weil der Julia-Ansatz sich so stark von den meisten anderen Sprachen unterscheidet.
Insbesondere wird der Name der Schnittstelle in der Implementierung vielleicht nie erwähnt: ganz anders als beim [Erben von Unterklassen][wiki-subclass] oder bei [Mixins][wiki-mixins].

In der Praxis sind sie jedoch überraschend einfach:

1. Definiere einen passenden Typ.
2. Finde heraus, welche Methoden erforderlich sind.
3. Implementiere diese Methoden für deinen eigenen Typ; typischerweise sind es nur wenige Methoden, und sie sind recht kurz und einfach.
4. Überlass den Rest [Multiple Dispatch][concept-multiple-dispatch], der das automatisch erledigt.
