# Tests

Jede Übung enthält eine Reihe von Unit-Tests und alles, was du zum Bauen und Ausführen brauchst.
Die Implementierung schreibst du selbst.

## Tests ausführen

Öffne ein Terminal im Übungsordner und führe Folgendes aus:

```
make
```

Das kompiliert deine Lösung und die Tests und führt dann die Tests aus.
Führe den Befehl jedes Mal erneut aus, wenn du deine Lösung änderst.

Wenn du die [Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally) hast, kannst du stattdessen diesen Befehl verwenden, der auch `make` ausführt:

```
exercism test
```

Um die vom Build erzeugten Dateien zu entfernen, führe `make clean` aus.

### Ohne make

Wenn du `make` nicht hast (zum Beispiel unter Windows), kannst du die Tests direkt kompilieren und ausführen.
Für die Übung „Bob“:

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

Führe die Tests dann unter Linux oder macOS aus:

```
./run_tests
```

Oder unter Windows:

```
.\run_tests
```

## Eine Übung durcharbeiten

Die Dateien jeder Übung sind nach ihr benannt.
Für die Übung „Bob“:

| Datei            | Inhalt                                                            |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90`        | eine Vorlage der Lösung, die du vervollständigen kannst           |
| `bob_test.f90`   | die Tests                                                         |
| `TesterMain.f90` | die Testbibliothek                                                |
| `Makefile`       | Anweisungen für `make`                                            |
| `CMakeLists.txt` | Anweisungen für [CMake](#using-cmake-instead), das optional ist   |

Du musst nur die Lösungsdatei bearbeiten.

Eine Übung durchzuarbeiten heißt, diese Schritte zu wiederholen, bis alle Tests bestehen:

- Alle Kompilierfehler beheben und dann die Tests ausführen, um zu sehen, welche fehlschlagen.
- Genau so viel implementieren, dass der nächste fehlschlagende Test besteht.
- Deine Implementierung refaktorieren, um die Lesbarkeit zu verbessern, Duplikate zu reduzieren usw.
- Die Tests erneut ausführen und mit dem nächsten fehlschlagenden Test weitermachen.

Für jeden fehlschlagenden Test wird eine Meldung ausgegeben, gefolgt von einer Zusammenfassung.
Wenn Tests fehlschlagen, endet `make` mit einem Fehler.

Jeder Test hat einen Kommentar, der den Test beschreibt, und danach den eigentlichen Test, der mit `call assert_equal` beginnt, z. B.

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Um einen Test zu deaktivieren, kommentierst du ihn einfach mit einem `'!'` aus, z. B.

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## Stattdessen CMake verwenden

Du brauchst CMake nicht, aber es kann nützlich sein, wenn du in einer IDE wie Visual Studio oder Xcode arbeitest oder einen anderen Compiler als GFortran verwendest.

Der Übungsordner muss seinen ursprünglichen Namen behalten, weil CMake ihn verwendet, um die Quelldateien zu finden.
Starte im Übungsordner:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

Nachdem du deine Lösung geändert hast, brauchst du nur die letzten beiden Befehle.

**Hinweis:** Führe `cmake` immer aus einem separaten Ordner wie `build` aus.
Wenn du `cmake .` im Übungsordner ausführst, wird das `Makefile` ersetzt, das mit der Übung geliefert wird.

CMake wählt einen passenden Generator für dein System.
Um einen anderen zu wählen, verwende die Option `-G`, z. B. `cmake -G Xcode ..`.
Führe `cmake --help` aus, um die Generatoren aufzulisten, die du verwenden kannst.
Mit Visual Studio oder Xcode führst du die Tests mit `ctest -V -C Debug` aus.

Wenn dein Übungsordner kein `Makefile` enthält, wurde er heruntergeladen, bevor diese Dateien zu den Übungen hinzugefügt wurden.
CMake kannst du trotzdem verwenden.
