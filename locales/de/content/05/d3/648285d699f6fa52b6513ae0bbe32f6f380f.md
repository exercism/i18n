# Zusätzliches

## GNU awk und Arithmetik mit beliebiger Genauigkeit

Standardmäßig werden Zahlen in `awk` als Gleitkommazahlen mit doppelter Genauigkeit dargestellt. Das liefert 53 Bit Genauigkeit (siehe [Tabelle 16.3][table-16.3] im Handbuch). Leider reicht das nicht aus, um diese Übung zu lösen (Spoiler: Ein Test benötigt 63 Bit Genauigkeit).

„not enough precision“ sieht so aus:
```sh
$ gawk 'BEGIN {
  n = 2 ^ 54
  if (n == n + 1)
    print "not enough precision"
  else
    print "OK"
}'
```
```none
not enough precision
```

GNU `awk` kann mit Zahlen beliebiger Genauigkeit rechnen, wenn die entsprechenden Bibliotheken in die ausführbare Datei von `awk` einkompiliert wurden. Prüfe die Version deines awk und achte auf „GNU MPFR“:
```sh
$ gawk --version
GNU Awk 5.0.1, API: 2.0 (GNU MPFR 4.0.2, GNU MP 6.2.0)
...
```

Wenn sie vorhanden ist, aktivierst du diese Fähigkeit mit der Option `-M`:
```sh
$ gawk -M 'BEGIN {
  n = 2 ^ 54
  if (n == n + 1)
    print "not enough precision"
  else
    print "OK"
}'
```
```none
OK
```

Was aber, wenn mein `awk` kein `-M` hat? Dann musst du ein externes Programm aufrufen, das mit beliebiger Genauigkeit rechnen kann, zum Beispiel `bc`. Ein Beispiel dafür findest du im Abschnitt [Eine Variable mit getline aus einer Pipe lesen][getline-pipe].
