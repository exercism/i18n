# Einführung

## Partielle Anwendung und Funktionskomposition

### Partielle Anwendung

Alle Funktionen in Elm sind [curried][currying]. Das heißt: Wenn du eine Funktion aufrufst, ohne alle Argumente zu übergeben, gibt sie eine neue Funktion zurück.

Das Ergebnis davon nennt man [partielle Anwendung][partial-application] (du übergibst nicht alle Argumente an die Funktion, sondern wendest nur einen Teil davon an).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

Die partielle Anwendung wendet die Argumente immer in der Reihenfolge an.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

### Pipe-Operator (`|>`)

`x |> f` zu schreiben ist genau dasselbe wie `f x`. Ein konkretes Beispiel: `"5" |> String.toInt` ist dasselbe wie `String.toInt "5"`.

Das klingt zunächst nicht besonders nützlich, aber man nennt es [Pipe-Operator][pipe-operator], weil du damit „pipelineartigen“ Code schreiben kannst.

Angenommen, wir haben eine Funktion `sanitize`, die Benutzereingaben in Ganzzahlen umwandelt:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Wir können sie so umschreiben:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Das vermeidet Klammern und zeigt die Funktionen in der Reihenfolge, in der sie angewendet werden (zuerst `String.trim`, dann `String.toInt`). Das verbessert die Lesbarkeit.

Es gibt auch einen [umgekehrten Pipe-Operator `(<|)`][reverse-pipe-operator].
`f <| x` zu schreiben ist genau dasselbe wie `f x`.
Auch das sieht auf den ersten Blick nicht besonders nützlich aus und wird eindeutig nicht so oft verwendet wie der Pipe-Operator, aber in manchen Situationen hilft es, Klammern zu vermeiden.

### Funktionskomposition / Point Free Style

Der Operator [`(>>)`][forward-composition] hat den Typ `(a -> b) -> (b -> c) -> (a -> c)` und erzeugt eine Funktion vom Typ `a -> c`, indem er zwei kompatible Funktionen vom Typ `a -> b ` und `b -> c` komponiert.
Das macht er, indem er die Ausgabe (vom Typ `b`) der ersten Funktion nimmt und sie als erstes Argument an die zweite Funktion übergibt (die vom selben Typ `b` sein muss).
Die erzeugte Funktion nimmt dieselbe Eingabe (vom Typ `a`) wie die erste Funktion und gibt das `c` zurück, das die zweite Funktion zurückgibt.

Ein konkretes Beispiel ist `String.trim >> String.toInt`.
`String.trim` nimmt einen String als einzigen Parameter, also nimmt die erzeugte Funktion dasselbe.
`String.toInt` gibt ein `Maybe Int` zurück, also gibt die erzeugte Funktion das zurück.
`String.trim` gibt einen `String` zurück, den `String.toInt` als Parameter akzeptiert, also kompiliert das Beispiel.

Jetzt können wir unsere Funktion `sanitize` so umschreiben:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Beachte, dass wir den Parameter `input` aus dem ursprünglichen Beispiel nicht mehr verwenden, obwohl die Funktionalität identisch ist.
Diese Art, Funktionen zu erstellen, die ihre Parameter nicht erwähnen, nennt man „Point Free Style“.
Der Vorteil dieses Stils ist, dass der Code knapper ist; der Nachteil ist, dass er schwerer zu verstehen sein kann, besonders für Anfängerinnen und Anfänger.

Es lohnt sich zu merken, dass alle Funktionen in Elm curried sind, also kompiliert `String.length >> max`.

- Der Operator [`(>>)`][forward-composition] hat den Typ `(a -> b) -> (b -> c) -> (a -> c)`.
- `String.length` hat den Typ `String -> Int`, das ist der Teil `(a -> b)`, also ist `a` gleich `String` und `b` ist - `Int`.
- `max` hat den Typ `Int -> Int -> Int`, das ist der Teil `b -> c`.
- `b` ist `Int`, also wird `max` partiell angewendet, also ist `c` das Ergebnis dieser partiellen Anwendung (`Int -> Int`).
- Also ist der Typ von `String.length >> max` gleich `String -> (Int -> Int)`.
- Also gibt `((String.length >> max) "123") 2` den Wert `3` zurück, weil `"123"` die Länge 3 hat und das größer ist als die 2 aus dem `Int`-Argument.

### Funktionsdesign

Um in Elm mühelos eleganten Code zu schreiben, solltest du die Hauptdatenstruktur zum letzten Parameter von Funktionen machen.
Alle gängigen Funktionen in der Standardbibliothek machen das so, zum Beispiel `List.map` (Typsignatur siehe unten).

```elm
map : (a -> b) -> List a -> List b
```

Hier sehen wir, dass der letzte Parameter der Funktion `map` vom Typ `List a` ist und sie `List b` zurückgibt. Die Hauptdatenstruktur (`List`) ist also der letzte Parameter.

Damit kannst du eleganten pipelineartigen Code schreiben, wie im folgenden Beispiel.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Außerdem ist es so bequem möglich, Funktionskomposition und Point Free Style als Alternative zum Pipelining zu verwenden.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

Mit Funktionskomposition kannst du dieses Beispiel außerdem auf einen einzigen Aufruf von `List.map` reduzieren.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
