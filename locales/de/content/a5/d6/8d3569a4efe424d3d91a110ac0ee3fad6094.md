# Einführung

Die meisten Wörter für Sequenzen, die du bisher gesehen hast, geben *neue* Sequenzen zurück und lassen ihre Eingaben unverändert – `suffix`, `reverse`, `map` und so weiter. Aber Arrays und Vektoren unterstützen auch **Mutation an Ort und Stelle**, und beide sind gefragt, wenn du einen Zustand festhalten willst, der sich mit der Zeit ändert.

## Zwei Spielarten veränderbarer Sequenzen

- **Arrays** (`{ … }`) haben eine feste Länge. `<array> ( n elt --
  array )` (in [`arrays`][arrays]) erzeugt ein neues Array der Länge
  `n`, das mit Kopien von `elt` gefüllt ist.
- **Vektoren** (`V{ … }`) wachsen und schrumpfen. Nimm `V{ } clone` für
  einen neuen leeren Vektor; `<vector> ( n -- vector )` (in
  [`vectors`][vectors]) reserviert vorab Kapazität für `n` Elemente.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## Eine Position ändern

Diese beiden funktionieren mit beiden Arten von Sequenzen – beide
erwarten die Sequenz nach dem Index:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth` weist zu, `change-nth` wendet eine Quotation auf das Element an Position `n` an.
Beide dieser [`sequences`][sequences]-Wörter geben nichts auf dem Stack zurück – die Mutation ist der Effekt.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## Wachsen und Schrumpfen

Diese drei sind nur bei Vektoren sinnvoll, denn Arrays können ihre
Länge nicht ändern:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## Vektor → Array

Wenn du einen Vektor aufgebaut hast und ein Array fester Länge
zurückgeben willst, gibt `>array ( seq -- array )` (in [`arrays`][arrays])
ein neues Array mit denselben Elementen zurück:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone` – einen Schnappschuss behalten

Eine Mutation verändert die Sequenz an Ort und Stelle. Wenn dir ein
Aufrufer eine Sequenz übergibt und du sie gleich ändern willst, gibt dir
`clone` (in [`kernel`][kernel]) eine frische, unabhängige Kopie, damit
sich die Sicht des Aufrufers nicht unter ihm verschiebt:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

Dieselbe Vorsicht gilt für `V{ }` und andere leere
Literale. In manchen Sprachen legt `[]` oder `vec![]` bei jeder
Auswertung des Ausdrucks einen neuen Container an. In Factor ist das
Literal `V{ }` in deinem Quelltext *ein* Objekt, das jede
Aufrufstelle, die es nennt, gemeinsam nutzt. Wenn du direkt auf `V{ }`
ein `push` machst, sieht der nächste Aufruf die Reste. `V{ } clone`
erzeugt die frische Kopie, die du fast immer willst.
