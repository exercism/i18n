# Tests

Die Tests für ein Elm-Projekt liegen im Unterverzeichnis `tests/` des Projekts.
Die Test-Suite jeder Übung kannst du aus dem Stammverzeichnis der Übung heraus ausführen.

```bash
$ cd ~/exercism/elm/hello-world
$ elm-test
```

## Auf Änderungen achten

Lass die Tests automatisch erneut laufen, wenn du Änderungen speicherst:

```bash
$ elm-test --watch
```

## Ablauf der testgetriebenen Entwicklung

In den meisten Übungen sind die Tests bereits in der Datei `tests/Tests.elm` geschrieben.
Dein Ziel ist es, sie zum Laufen zu bringen, indem du den erforderlichen Code in der Datei `src/<exercise>.elm` schreibst.
Konzentriere dich auf den ersten fehlschlagenden Test, behebe ihn,
entferne oder kommentiere dann das nächste `skip <|`-Snippet in der Testdatei aus und wiederhole das,
bis alle Tests bestehen.

## Du kommst nicht weiter?

Dein erstes Ziel ist es, dass dein Code kompiliert, auch wenn `Debug.todo` darin vorkommt.
Wenn du nicht weißt, wie du etwas umsetzen sollst,
ist es oft hilfreich, diesen Teil in eine eigene, noch nicht implementierte Funktion auszulagern.

```elm
complexOperationOnMultipleStrings : List String -> List String
complexOperationOnMultipleStrings allStrings =
    List.map complexOperation allStrings


complexOperation : String -> String
complexOperation input =
    Debug.todo "Extracted operation into its own function"
```

Eine Typannotation an dieser ausgelagerten Funktion
hilft dir beim Denken und dem Compiler dabei, dir bessere Fehlermeldungen zu geben.

## Deinen Code aufräumen

Vielleicht möchtest du [`elm-format`](https://github.com/avh4/elm-format) vor dem Einreichen auf deinen Code anwenden
und es sogar in deinem Texteditor einrichten, damit dein Code beim Speichern automatisch formatiert wird.
