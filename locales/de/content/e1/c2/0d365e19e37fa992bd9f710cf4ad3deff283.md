# Einführung

TypeScript ist JavaScript mit einer Syntax für Typen. Damit ist es eine stark typisierte Programmiersprache, die objektorientierte, imperative und deklarative Stile (z. B. funktionale Programmierung) unterstützt und dir in jedem Umfang ein besseres Tooling bietet.

Weil [du TypeScript nicht lernen kannst, ohne JavaScript zu lernen][handbook-js-or-ts], konzentriert sich ein Teil des Inhalts in diesem Track darauf, JavaScript-Konzepte zu vermitteln, während andere Konzepte nur auf TypeScript-spezifische Features eingehen.

## (Neu-)Zuweisung

In TypeScript gibt es einige grundlegende Wege, Namen Werte zuzuweisen: über Variablen oder Konstanten.
Auf Exercism werden Variablen immer in [camelCase][wiki-camel-case] geschrieben, Konstanten in [SCREAMING_SNAKE_CASE][wiki-snake-case].
Es gibt keine offizielle Richtlinie, an der man sich orientieren könnte, und verschiedene Firmen und Organisationen haben unterschiedliche Style Guides.
_Schreib Variablen ruhig so, wie du möchtest._
Der Vorteil, sie so zu schreiben, wie die Übungen vorbereitet sind: Sie werden in der Web-Oberfläche und in den meisten IDEs anders hervorgehoben.

Variablen in TypeScript kannst du mit dem Schlüsselwort [`const`][mdn-const], [`let`][mdn-let] oder [`var`][mdn-var] definieren.

Wenn du `let` oder `var` verwendest, kann eine Variable im Laufe ihres Lebens auf verschiedene Werte verweisen.
Zum Beispiel kannst du `myFirstVariable` mit dem Zuweisungsoperator `=` beliebig oft definieren und neu zuweisen:

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

Im Gegensatz zu `let` und `var` kannst du Variablen, die mit `const` definiert werden, nur einmal zuweisen.
So definiert man in TypeScript Konstanten.

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

Weil TypeScript das statisch erkennen kann, gibt auch der TypeScript-Compiler einen Fehler aus:

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

Das heißt, du musst den Code nicht ausführen, um den `TypeError` zu erkennen.

## Typinferenz

Ohne zu tief in das Thema [Typinferenz][handbook-type-inference] einzusteigen: Du solltest wissen, dass eine zugewiesene Variable meist einen abgeleiteten Typ hat, auch ohne Typannotation.

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

Dieser Typ wird dann im gesamten Code durchgesetzt.
Das bedeutet auch, dass der folgende Code gültiges JavaScript ist:

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

In TypeScript gibt es dagegen einen Fehler:

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

Diese Eigenschaft sorgt für Typsicherheit, auch wenn keine Typannotationen verwendet werden.

## Funktionsdeklarationen

In TypeScript werden Funktionseinheiten in _Funktionen_ gekapselt. Funktionen, die zusammengehören, stehen meist in derselben Datei.
Diese Funktionen können Parameter (Argumente) entgegennehmen und mit dem Schlüsselwort `return` einen Wert _zurückgeben_.
Funktionen werden mit der Syntax `()` aufgerufen.

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

Funktionsparameter solltest du in der Regel mit einem Typ annotieren, indem du einen Doppelpunkt (`:`) und danach den Typ schreibst.
Rückgabewerte von Funktionen kannst du nach der schließenden Klammer der Parameterliste annotieren, ebenfalls mit einem Doppelpunkt (`:`) gefolgt vom Typ.

<!--prettier-ignore -->
~~~~exercism/note
💡 In TypeScript gibt es _viele_ verschiedene Arten, eine Funktion zu deklarieren.
Diese anderen Arten sehen anders aus als die Verwendung des Schlüsselworts `function`.
Der Track versucht, sie nach und nach einzuführen. Wenn du sie aber schon kennst, kannst du jede davon verwenden.
In den meisten Fällen ist die eine nicht besser oder schlechter als die andere.
~~~~

## Typannotationen

Wie in der Funktionsdeklaration für `add` zu sehen, haben die Parameter eine explizite Typannotation `: number`.
Variablendeklarationen, Klasseneigenschaften, Funktionsdeklarationen und mehr unterstützen Typannotationen.

Sowohl explizite Typannotationen als auch abgeleitete Typen werden vom Type-Checker durchgesetzt.

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## Für andere Dateien verfügbar machen

Damit eine `function`, eine Konstante oder eine Variable in _anderen Dateien_ verfügbar ist, müssen sie mit dem Schlüsselwort `export` [exportiert][mdn-export] werden.
Eine andere Datei kann sie dann mit dem Schlüsselwort `import` [importieren][mdn-import].
Das nennt man auch das Modulsystem.
Ein gutes Beispiel ist, wie alle Tests funktionieren.
Jede Übung hat mindestens eine Datei, zum Beispiel `lasagna.ts`, die die _Implementierung_ enthält.
Dazu gibt es mindestens eine weitere Datei, zum Beispiel `lasagna.test.ts`, die die _Tests_ enthält.
Diese Datei _importiert_ die öffentlichen (also exportierten) Entitäten, um die Implementierung zu testen:

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
