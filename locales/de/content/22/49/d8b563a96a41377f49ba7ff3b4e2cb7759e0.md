# Anleitung

Deine Freundin Helma hat ein kleines Online-Spiel entwickelt, das schnell beliebt wurde.
Es heißt _HellMath_.
Die kleine Community zog einige Trolle an, die das Spiel und die Foren ziemlich unangenehm machen.
Helma hat dich gebeten, an einem neuen Berechtigungssystem zu arbeiten, um Störenfriede von den anderen zu trennen.

Das Forum unterstützt drei verschiedene Aktionen:

- Lesen
- Schreiben
- Entfernen

Es gibt vier Arten von Konten, jede mit anderen Standardberechtigungen:

- Gäste: können Beiträge lesen.
- Benutzer und Trolle: können Beiträge lesen und schreiben.
- Moderatoren: können Beiträge lesen, schreiben und entfernen, sie haben alle Berechtigungen.

Helma hat bemerkt, dass es nichts bringt, Troll-Konten zu sperren.
Ihre Strategie ist, ihnen die Illusion zu geben, ihre Zeit sei „gut investiert“, aber ihre Beiträge werden nur anderen Trollen angezeigt.
Überall, wo eine Prioritätsreihenfolge nötig ist, stehen Trolle in jeder Reihenfolge ganz hinten.
Wenn sie ein Spiel betreten, ist der Pool der verfügbaren Spieler ebenfalls auf andere Trolle beschränkt.

Diese Praxis nennt man [Shadowbanning][shadow-ban].

## 1. Richte Benutzertypen und Berechtigungen ein.

Definiere zuerst eine `AccountStatus`-Enumeration, die die vier Kontotypen darstellt: `troll`, `guest`, `user` und `mod`.

Definiere als Nächstes eine `Action`-Enumeration, die die drei Berechtigungstypen darstellt: `read`, `write` und `remove`.


## 2. Mache Trolle nur für andere Trolle sichtbar.

Jeder Beitrag in den Foren speichert den `AccountStatus` des Verfassers in seinen Metadaten.
Stelle sicher, dass Beiträge von Trollen nur anderen Trollen angezeigt werden.

Helma braucht eine Funktion `display_post`, die zwei Argumente vom Typ `AccountStatus` erhält und ein `bool` zurückgibt.
Das erste Argument ist der Status des Verfassers, das zweite ist der Status des Betrachters.

```cpp
using namespace hellmath;
display_post(AccountStatus::troll, AccountStatus::user);
// => false
display_post(AccountStatus::mod, AccountStatus::guest);
// => true
```

## 3. Prüfe die Berechtigungen verschiedener Benutzer.

Helma braucht eine Möglichkeit zu prüfen, ob eine bestimmte Aktion für einen Benutzer erlaubt ist.

Implementiere bitte eine Funktion `permission_check`, die eine `Action` als erstes Argument und einen `AccountStatus` zum Prüfen entgegennimmt.
Sie soll ein `bool` zurückgeben, entsprechend den Berechtigungen aus der Einleitung.

```cpp
permission_check(Action::remove, AccountStatus::guest);
// => false
permission_check(Action::write, AccountStatus::mod);
// => true
```

## 4. Gewähre Spielzugang und bilde Spielerpaare.

Damit die eigentlichen Spieler im Spiel für ihre Handlungen zur Verantwortung gezogen werden können, verweigert _Hellmath_ Gästen den Zugang.
Wie oben erwähnt, möchte Helma, dass Trolle andere Trolle trollen.
Spielverbindungen zwischen anderen Benutzern sind nicht eingeschränkt.

Implementiere die Funktion `valid_player_combination`, die prüft, ob zwei Spieler demselben Spiel beitreten können.
Die Funktion hat zwei Parameter vom Typ `AccountStatus` und gibt ein `bool` zurück.

```cpp
valid_player_combination(AccountStatus::guest, AccountStatus::mod);
// => false
valid_player_combination(AccountStatus::troll, AccountStatus::troll);
// => true
```

## 5. Erstelle eine Prioritätswarteschlange.

Durch das enorme Wachstum des Spiels und der Foren muss Helma jetzt Rechenleistung und Bandbreite unter den Benutzern verteilen.
Um Notfälle zu bewältigen, bekommen Moderatoren die höchste Priorität.
Gäste stehen in der Warteschlange hinter normalen Benutzern, und Trolle werden hinter allen anderen einsortiert.

Implementiere die Funktion `has_priority`, die zwei `AccountStatus`-Argumente entgegennimmt und genau dann `true` zurückgibt, wenn das erste Konto eine strikt höhere Priorität hat als das zweite.

```cpp
has_priority(AccountStatus::guest, AccountStatus::mod);
// => false
has_priority(AccountStatus::user, AccountStatus::troll);
// => true
```
