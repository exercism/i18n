# Einführung

In Elixir läuft der gesamte Code in Prozessen.

Standardmäßig wird eine Funktion in demselben Prozess ausgeführt, aus dem sie aufgerufen wurde. Wenn du eine bestimmte Funktion explizit in einem neuen Prozess ausführen möchtest, verwende `spawn/1`:

```elixir
spawn(fn -> 2 + 2 end)
# => #PID<0.125.0>
```

`spawn/1` erzeugt einen neuen Prozess, der die angegebene Funktion ohne Argumente ausführt und einen _Prozessbezeichner_ (PID) zurückgibt. Der neue Prozess bleibt am Leben, solange die Funktion ausgeführt wird, und beendet sich danach still.

Elixirs Prozesse sollte man nicht mit Prozessen des Betriebssystems verwechseln. Elixirs Prozesse verbrauchen viel weniger Speicher und CPU. Es ist völlig in Ordnung, wenn eine Elixir-Anwendung Hunderte von Elixir-Prozessen ausführt.

## Nachrichten

Prozesse teilen Informationen nicht direkt miteinander. Prozesse _senden und empfangen Nachrichten_, um Daten auszutauschen.

Du kannst mit `send/2` eine Nachricht an jeden beliebigen Prozess senden. Das erste Argument von `send/2` ist die PID des Empfängers, das zweite Argument ist die Nachricht.

Eine Nachricht kann von beliebigem Typ sein. Oft besteht sie aus Atomen und Tupeln. Wenn du eine Antwort erhalten möchtest, solltest du die PID des Absenders irgendwo in die Nachricht aufnehmen. Die PID des aktuellen Prozesses erhältst du mit `self()`.

`send/2` prüft nicht, ob die Nachricht vom Empfänger empfangen wurde, noch ob der Empfänger noch am Leben ist. Die Nachricht landet in der _Mailbox_ des Empfängers und wird nur dann gelesen, wenn der Empfänger ausdrücklich darum bittet, _Nachrichten zu empfangen_.

Eine Nachricht kann mit dem Makro `receive/1` aus einer Mailbox gelesen werden. Es akzeptiert einen `do`-Block, der [Pattern Matching][exercism-pattern-matching] auf den Nachrichten anwenden kann.

```elixir
receive do
  {:ping, sender_pid} -> send(sender_pid, :pong)
  :do_nothing -> nil
end
```

`receive/1` entnimmt der Mailbox _eine Nachricht_, die auf eines der angegebenen Muster passt, und führt den für dieses Muster angegebenen Ausdruck aus. Wenn sich keine Nachrichten in der Mailbox befinden oder keine der Nachrichten in der Mailbox auf eines der Muster passt, wartet `receive/1` auf eine Nachricht.

## receive-Schleife

Wenn du mehr als eine Nachricht empfangen möchtest, musst du `receive/1` rekursiv aufrufen. Es ist ein übliches Vorgehen, eine rekursive Funktion zu implementieren, zum Beispiel mit dem Namen `loop`, die `receive/1` aufruft, etwas mit der Nachricht macht und sich dann selbst aufruft, um auf weitere Nachrichten zu warten. Wenn du einen Zustand von einem `receive/1`-Aufruf zum nächsten mitnehmen musst, kannst du das tun, indem du ein Argument an diese `loop`-Funktion übergibst.
