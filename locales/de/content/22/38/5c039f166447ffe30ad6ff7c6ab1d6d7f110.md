# Einführung

[Pattern Matching][pattern-matching] ermöglicht ausdrucksstarken verzweigenden Code und [Destrukturierung][destructuring] bringt elegantes Binden von Werten an Variablen.
Beide sind für Elm-Programmierer äußerst nützlich zu beherrschen, und wenn man sie zusammen verwendet, verbessern sie die Lesbarkeit des Codes erheblich.

## Einfaches Pattern Matching

Pattern Matching bezeichnet verzweigenden Code, der von der Form der verarbeiteten Daten abhängt.
Es passt daher natürlich zum Konzept der benutzerdefinierten Typen, die die verschiedenen Formen ausdrücken, die Daten annehmen können.
Wenn wir zum Beispiel einen benutzerdefinierten Typ `Color` haben, der entweder `Blue` oder `Red` ist, dann können wir eine `toString`-Funktion schreiben, die per Pattern Matching auf die Farbe den passenden String zurückgibt.

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

Pattern Matching funktioniert auch für benutzerdefinierte Typen, die keine einfache Aufzählung sind.
Betrachten wir eine `hello`-Funktion, die als Parameter ein `Maybe String` nimmt, das entweder einen Personennamen oder gar nichts enthält.
Beim Pattern Matching können wir den Daten kleingeschriebene Namen geben, um diese Daten an die Variable zu binden, und sie dann auf der rechten Seite des Match-Ausdrucks zu verwenden.

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

Pattern Matching muss vollständig sein, sonst weigert sich der Compiler zu kompilieren.
Aber manchmal interessieren uns bestimmte Daten oder bestimmte Zweige eines case-Ausdrucks nicht.
In diesen Fällen können wir den Unterstrich-Wildcard `_` verwenden, statt einen Variablennamen zum Binden zu finden und Zweige für alle Fälle zu schreiben.

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## Fortgeschrittenes Pattern Matching

Zusätzlich zu benutzerdefinierten Typen können wir auch Pattern Matching für Typen anwenden, die Literale haben, wie `Char`, `String`, `Int` und `Floats`.

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

Um mehr als einen Wert ohne Verschachtelung zu matchen, kombiniert man die zu matchenden Werte in Elm üblicherweise in [_Ad-hoc-Tupeln_][ad-hoc-tuples], und zwar so:

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

Und da Listen funktionalen Programmierern am Herzen liegen, [kann man auch auf sie Pattern Matching anwenden][pattern-match-lists], mit derselben Syntax, mit der man sie aufbaut, nämlich mit dem Operator `::`.

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

Schließlich funktioniert Pattern Matching sogar rekursiv, was tiefe Einblicke in komplexe und rekursive Typen ermöglicht.

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## Destrukturierung

Destrukturierung ist dem Pattern Matching sehr ähnlich, insofern sie das Binden von Variablen an Daten innerhalb von Typen ermöglicht.
Der Hauptunterschied ist, dass wir diesen Mechanismus „Destrukturierung“ nennen, wenn nur eine Form möglich ist, und „Pattern Matching“ für mehrere Formen.
Destrukturierung findet man oft in `let`-Bindungen, in Funktionsargumenten und natürlich in case-Ausdrücken, gemischt mit Pattern Matching.

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

Destrukturierung kann für benutzerdefinierte Typen mit einer einzigen Variante, für Tupel und auch für Records verwendet werden, wo sie sehr praktisch ist.
Um [einen Record zu destrukturieren][records-pattern-matching], kann man eine beliebige Anzahl seiner Felder verwenden, ein Feld, zwei, ..., oder alle Felder.

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

Leider ermöglicht die Elm-Syntax keine rekursive Destrukturierung von Records.
Im vorherigen `Circle`-Beispiel gibt es keine Möglichkeit, im selben Schritt auf die `x`` and `y`center`center`x`x`y`y`-Positionen destrukturieren.

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

Und wir haben noch einen letzten Tipp!
Manchmal möchten wir einfachen Zugriff sowohl auf ein Ding als Ganzes als auch auf einen Teil davon.
Hier kann das [`as`-Schlüsselwort][as-keyword] nützlich sein.
Es ermöglicht, einem Ding als Ganzes einen Aliasnamen zu geben und trotzdem seinen Inhalt zu destrukturieren.

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
