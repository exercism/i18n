# Über

Eine Datei ist ein Stream mit einem Namen auf der Festplatte. Das Vokabular [`io.files`][io.files] bietet zwei Wege, mit einer Datei zu arbeiten: Komfortwörter für die ganze Datei, die alles in einem einzigen Aufruf lesen oder schreiben, und Stream-Öffner (die `with-…`-Kombinatoren), mit denen du schrittweise lesen oder schreiben kannst. Beide bauen auf demselben [Stream-Protokoll][stream-protocol] auf wie die Streams im Arbeitsspeicher aus dem Konzept `io-streams`: Ein `<file-reader>` und ein `<string-reader>` verstehen dieselben Wörter.

Jedes Datei-Wort nimmt eine **Kodierung** entgegen, also das Schema, das Bytes auf Zeichen und zurück abbildet. Für Text ist das fast immer [`utf8`][utf8] aus `io.encodings.utf8`; bei Binärdaten verwendest du `latin1` oder eine `<byte-array>`-Kodierung.

## Ganze Dateien lesen

```
file-contents   ( path encoding -- str )
file-lines      ( path encoding -- seq )
```

`file-contents` gibt die ganze Datei als einen String zurück. `file-lines` gibt ihre Zeilen als Array zurück, ohne die Zeilenende-Zeichen. Das ist praktisch, wenn jede Zeile ein Datensatz ist.

```factor
USING: io.encodings.utf8 io.files ;

"forecast.txt" utf8 file-contents   ! => "sunny\ncloudy\n"
"forecast.txt" utf8 file-lines      ! => { "sunny" "cloudy" }
```

## Ganze Dateien schreiben

```
set-file-contents   ( str path encoding -- )
set-file-lines      ( seq path encoding -- )
```

Beide **ersetzen** die Datei und legen sie an, wenn es sie noch nicht gibt.
`set-file-contents` schreibt einen String unverändert; `set-file-lines` schreibt jedes Element einer Sequenz in eine eigene Zeile und fügt die Zeilenumbrüche selbst ein.

```factor
{ "sunny" "cloudy" } "forecast.txt" utf8 set-file-lines
! forecast.txt now holds "sunny\ncloudy\n"
```

## Streams mit Gültigkeitsbereich

Wenn du etwas an eine Datei anhängen oder Stück für Stück lesen und schreiben willst, öffne sie mit einem `with-…`-Kombinator und verwende innerhalb der Quotation die Stream-Wörter für den aktuellen Stream:

```
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
with-file-appender   ( path encoding quot -- )
```

```factor
USING: io io.encodings.utf8 io.files ;

"log.txt" utf8 [ "another line" print ] with-file-appender
```

`with-file-writer` kürzt die Datei zuerst; `with-file-appender` behält den vorhandenen Inhalt und schreibt dahinter. Jeder davon ist ein Gültigkeitsbereich mit Destruktor: Das Dateihandle wird geschlossen, wenn die Quotation endet, auch wenn sie eine Ausnahme wirft. Das ist dieselbe Garantie, die die Kombinatoren aus `boatswains-bilge` bieten, hier auf Dateien spezialisiert.

## Ganze Datei oder Gültigkeitsbereich?

Greif zu `file-contents` / `file-lines` / `set-file-contents` / `set-file-lines`, wenn die Datei klein genug ist, um sie im Arbeitsspeicher zu halten, und du alles auf einmal willst. Greif zu den `with-…`-Öffnern, wenn du anhängen, eine große Datei mit `readln` Zeile für Zeile streamen oder Lesen und Schreiben verschachteln willst. Überall dort, wo es Verschwendung oder schlicht falsch wäre, die ganze Datei im Arbeitsspeicher zu halten.
