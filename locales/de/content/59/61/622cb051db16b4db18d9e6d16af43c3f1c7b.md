# Überblick

In den vorherigen Konzepten haben wir gesehen, dass Typen in Julia eine Hierarchie bilden, mit `Any` an der Spitze.

Abstrakte Typen wie `Number` haben Untertypen, können aber selbst nicht instanziiert werden.
Wenn du eine Variable auf einen abstrakten Typ setzt, _schränkst_ du die Werte der Variablen auf beliebige Untertypen des abstrakten Typs ein.
Zum Beispiel:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Das gibt uns eine Form der Flexibilität, um einzuschränken, welche Eingabewerte gültig sind.

Angenommen, wir möchten, dass eine Variable sowohl Ganzzahl- als auch String-Werte akzeptiert?
Diese Typen gehören nicht zum selben Zweig der Hierarchie.

Wir könnten den Typ auf [`Any`][any] setzen oder ihn standardmäßig darauf belassen, aber dann verlieren wir jede Kontrolle über die erlaubten Typen.

Für einen besseren Ansatz gibt es die [`Union{ }`][union]-Syntax, bei der zwei oder mehr Typen innerhalb der geschweiften Klammern aufgelistet werden.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Ein weiteres Beispiel verwendet denselben Union-Typ in einer Funktionssignatur:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

Hier haben wir dem Typ einen Namen gegeben, was eine praktische Kurzschreibweise sein kann, aber nicht unbedingt nötig ist.
Die Funktion `g(z::Union{Integer, String}) = z^3` verhält sich genauso.

Zum Thema Funktionssignaturen gibt es im Multiple-Dispatch-Konzept noch viel mehr zu sagen.

## Unions mit nothing

Einige andere Sprachen haben Typen, die einen Wert enthalten können oder nicht, mit Namen wie `Option`, `Nullable` oder `Maybe`.

Julia hat dafür keine spezielle Syntax, aber Union-Typen sind eine Verallgemeinerung derselben Idee.

Im [`Nothingness`][nothingness]-Konzept haben wir gesehen, dass Julia verschiedene Möglichkeiten hat, Nichtwerte darzustellen, darunter [`nothing`][nothing] und [`missing`][missing].
Beide können in einen Union-Typ aufgenommen werden.

Wenn wir beispielsweise eine Art [verkettete Liste][linked] definieren, brauchen wir eine Möglichkeit, die Liste zu beenden, wenn es keine weiteren Knoten gibt.
`Nothing` ist der Typ mit dem Singleton-Wert `nothing`, und diese Node-Definition macht es möglich, das Ende der Kette zu signalisieren:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

Ähnlich kann `missing` als Platzhalter für fehlende Werte verwendet werden, insbesondere in Sammlungen wie Vektoren.
Das folgende Beispiel ist sehr konstruiert, aber fehlende Werte sind in realen Datensätzen üblich.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
