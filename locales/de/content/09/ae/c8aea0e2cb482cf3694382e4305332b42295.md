# Überblick

In Elixir läuft der gesamte Code innerhalb von Prozessen. Elixir-Prozesse:

- sind nicht mit Systemprozessen zu verwechseln.
- sind leichtgewichtig.
- haben bestimmte Anwendungsfälle. Sie können:
  - [globalen Zustand halten][getting-started-processes-state].
  - [Fehler eindämmen][getting-started-processes-links].
  - nebenläufigen und asynchronen Code ermöglichen.
- Es ist normal, dass eine Elixir-App _hunderte_ Prozesse ausführt, aber auch eine, die gar keine neuen Prozesse ausdrücklich erzeugt, besonders wenn es eine Bibliothek ist.

## Prozesse erzeugen

Standardmäßig wird eine Funktion in demselben Prozess ausgeführt, aus dem sie aufgerufen wurde. Wenn du eine bestimmte Funktion ausdrücklich in einem neuen Prozess ausführen möchtest, verwende `spawn`:

- [`spawn/1`][kernel-spawn-1] akzeptiert eine Funktion, die es direkt ausführt.

  ```elixir
  spawn(fn -> 2 + 2 end)
  # => #PID<0.125.0>
  ```

- [`spawn/3`][kernel-spawn-3] akzeptiert eine Funktion, die es anhand des Modulnamens, des Funktionsnamens (als Atom) und einer Liste von Argumenten ausführt, die an diese Funktion übergeben werden.

  ```elixir
  spawn(String, :split, ["hello there", " "])
  # => #PID<0.113.0>
  ```

  - Dieses Datentripel wird oft _MFA_ genannt: _Module, Function, Arguments_.

- Ein Prozess wird beendet, sobald seine Funktion fertig ausgeführt wurde.

- Du kannst mit [`Process.alive?/1`][process-alive] prüfen, ob ein Prozess noch _lebt_ (also ausgeführt wird):

  ```elixir
  pid = spawn(fn -> 2 + 2 end)
  Process.alive?(pid)
  # => false
  ```

## Nachrichten

Prozesse teilen Informationen nicht direkt miteinander. Prozesse _senden Nachrichten_, um Daten auszutauschen. Dieses Nebenläufigkeitsmuster heißt [Aktormodell][wiki-actor-model].

- Sende mit [`send/2`][kernel-send] Nachrichten an einen Prozess.

  ```elixir
  send(pid, :hello)
  ```

  - Die Nachricht landet in der Reihenfolge des Versendens in der _Mailbox_ des Empfängers.
  - `send` prüft weder, ob die Nachricht empfangen wurde, noch, ob der Empfänger noch lebt.

- Eine Nachricht kann von beliebigem Typ sein.
- Mit [`receive/1`][kernel-receive] kannst du eine Nachricht empfangen, die an den aktuellen Prozess gesendet wurde.

  - Du musst die Nachrichten per Pattern Matching prüfen.
  - `receive` wartet, bis eine Nachricht, die auf eines der angegebenen Muster passt, in der Mailbox des Prozesses liegt.
    - Standardmäßig wartet es unbegrenzt, aber du kannst ihm mit einem `after`-Block ein Timeout geben.
  - Gelesene Nachrichten werden aus der Mailbox des Prozesses entfernt. Ungelesene Nachrichten bleiben dort unbegrenzt liegen.
    - Schreibe in `receive/1` immer eine `_`-Klausel, die alles abfängt, damit dir durch aufgestaute ungelesene Nachrichten nicht der Speicher ausgeht.

  ```elixir
  receive do
    {:ping, sender_pid} -> send(sender_pid, :pong)
    _ -> nil
  after
    5000 ->
      {:error, "No message in 5 seconds"}
  end
  ```

## Empfangsschleife

Wenn du mehr als eine Nachricht empfangen möchtest, musst du `receive/1` rekursiv aufrufen. Ein gängiges Muster ist eine rekursive Funktion, zum Beispiel mit dem Namen `loop`, die `receive/1` aufruft, etwas mit der Nachricht macht und sich dann selbst aufruft, um auf weitere Nachrichten zu warten. Wenn du einen Zustand von einem `receive/1`-Aufruf zum nächsten mitnehmen musst, kannst du ihn als Argument an diese Funktion `loop` übergeben.

```elixir
def loop(state) do
  receive do
    :increment_by_one ->
      loop(state + 1)

    {:report_state, sender_pid} ->
      send(sender_pid, state)
      loop(state)

    :stop ->
      nil

    _ ->
      loop(state)
  end
end
```

In der Praxis wird dieser Ansatz nur selten direkt verwendet. Elixir bietet Abstraktionen für Nebenläufigkeit, etwa das [`Agent`-Modul][agent] oder ein [`GenServer`-Behaviour][genserver], die beide auf der Empfangsschleife aufbauen. Um diese Abstraktionen effizient nutzen zu können, ist es aber entscheidend, diese Grundlagen zu verstehen.
