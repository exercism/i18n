# Einführung

Custom Types sind der Weg, wie in Gleam neue Datentypen definiert werden. Sie können mehrere _Varianten_ haben, jede mit einem eigenen Namen.

```gleam
pub type Season {
  Spring
  Summer
  Autumn
  Winter
}
```

Jeder Fall eines Custom Types kann optional Daten enthalten, und verschiedene Fälle können verschiedene Arten von Daten enthalten. Wenn eine Variante Daten enthält, spricht man von einem _Record_.

```gleam
pub type Number {
  SomeInt(Int)
  SomeFloat(Float)
  Invalid
}
```

Einen Wert für einen bestimmten Fall erzeugst du, indem du seinen Namen angibst, wenn er keine zusätzlichen Daten enthält (`Spring`), oder indem du ihn wie eine Funktion aufrufst, wenn er welche enthält (`SomeInt(2)`).

```gleam
let spring = Spring
let integer_two = SomeInt(2)
```

Custom Types haben, wie alles in Gleam, _strukturelle Gleichheit_. Das bedeutet, dass zwei Werte derselben Variante mit denselben Daten gleichwertig sind.

```gleam
Spring == Spring // -> True
Spring == Autumn // -> False
SomeInt(2) == SomeInt(2) // -> True
SomeInt(2) == SomeFloat(2.0) // -> False
```

Varianten von Custom Types lassen sich mit case-Ausdrücken per Musterabgleich vergleichen.

```gleam
import gleam/int
import gleam/float

pub fn describe(flexible_number: Number) -> String {
  case flexible_number {
    SomeFloat(f) -> "Float: " <> float.to_string(f)
    SomeInt(i) -> "Int: " <> int.to_string(i)
    Invalid -> "Neither a float nor an int"
  }
}
```
