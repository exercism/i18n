# Anleitung

Deine Aufgabe ist es, einen Rate Limiter mit festen Zeitfenstern zu bauen.

Stell dir einen einzelnen Server vor, der mit einem oder mehreren Clients verbunden ist.
Ein Client sendet eine Anfrage, der Server erledigt etwas Arbeit und gibt eine Antwort zurück.
Doch die Verarbeitung kostet Zeit.
Wenn ein Client zu viele Anfragen zu schnell sendet, kann der Server überlastet werden: Alles wird langsamer oder schlägt fehl.

Ein Rate Limiter ist eine kleine Komponente, die entscheidet, ob eine Anfrage erlaubt oder abgelehnt wird, je nachdem, wie häufig dieser Client Anfragen gestellt hat.
Es gibt verschiedene Strategien; in dieser Übung implementierst du einen Rate Limiter mit festen Zeitfenstern.

Beim Rate Limiting mit festen Zeitfenstern wird die Zeit in gleich lange Zeitfenster aufgeteilt (zum Beispiel alle 10 Sekunden), und pro Client ist innerhalb jedes Zeitfensters bis zu einer bestimmten Anzahl von Anfragen erlaubt.
Sobald das Zeitfenster zurückgesetzt wird, wird das Kontingent für das nächste Zeitfenster erneuert.
Jeder Client wird separat erfasst, sodass ein anderer Client im selben Zeitraum Anfragen senden kann.

Betrachte zum Beispiel einen Rate Limiter, der auf 2 Anfragen pro 10 Sekunden pro Client begrenzt ist.
Sagen wir, ein Client sendet eine Anfrage:

- Da es die erste Anfrage ist, wird sie erlaubt.
- Eine zweite Anfrage innerhalb von 10 Sekunden nach der ersten wird ebenfalls erlaubt.
- Weitere Anfragen danach werden jedoch abgelehnt, _bis_ mindestens 10 Sekunden seit der ersten Anfrage vergangen sind.
- Wenn ein zweiter Client seine erste Anfrage innerhalb von 10 Sekunden nach der ersten Anfrage des ersten Clients sendet, wird sie ebenfalls erlaubt, _unabhängig_ davon, ob der erste Client eine zweite Anfrage gesendet hat.
