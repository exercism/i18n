# Einführung

## Binärschreibweise

Eine **Ganzzahl** ist eine Abstraktion, die ganze Zahlen darstellt, wie zum Beispiel `4`, `-2`, `0` oder `64532`.

Um eine Ganzzahl als eine Folge von Bytes darzustellen, wird die **Binärschreibweise** verwendet.
In dieser Schreibweise repräsentiert jedes Bit in der Folge eine eigene Zweierpotenz, wobei der Wert zunimmt, wenn der Index des Bits von rechts nach links steigt.

## Vorzeichenlose Zahlen

Wenn die Zahl nur nicht-negativ sein kann, nennt man sie eine **vorzeichenlose** Zahl.

Vorzeichenlose Zahlen werden direkt als Summe der Zweierpotenzen dargestellt, die allen gesetzten Bits in ihrer Folge entsprechen.

Der Bereich der darstellbaren nicht-negativen Ganzzahlen in einem Register reicht von `0` (kein Bit gesetzt) bis `2⁶⁴ - 1` (Summe aller 64 gesetzten Bits).

Das Erweitern einer vorzeichenlosen Zahl auf eine größere Größe erfolgt, indem alle oberen Bits mit `0` gefüllt werden, sodass kein neues Bit zum Wert beiträgt.
Dies nennt man **Nullerweiterung**.

Der Befehl `movzx` (`z` für Null) nullerweitert einen 8-Bit- oder 16-Bit-Quelloperanden auf einen größeren Zieloperanden.
Ein 32-Bit-Quelloperand wird mit einem einfachen `mov` immer auf alle 64 Bits des Zieloperanden nullerweitert.

## Vorzeichenbehaftete Zahlen

Wenn eine Ganzzahl positive oder negative Werte annehmen kann, nennt man sie eine **vorzeichenbehaftete** Zahl.

Um negative Zahlen darzustellen, verwendet x86-64 die **Zweierkomplement**-Darstellung.

Im Zweierkomplement werden vorzeichenbehaftete Zahlen ebenfalls als Summe der Zweierpotenzen dargestellt, die den gesetzten Bits entsprechen.
Wenn jedoch das oberste Bit gesetzt ist, wird es subtrahiert, anstatt zu den anderen addiert zu werden.

Da dieses Bit einem höheren Wert entspricht als die Summe aller anderen, bedeutet das in der Praxis, dass eine Zahl mit diesem gesetzten Bit immer negativ ist.
Dieses spezielle Bit nennt man das **Vorzeichenbit**.

Das Erweitern einer vorzeichenbehafteten Zahl auf eine größere Größe bedeutet, jedes neue obere Bit mit einer Kopie des Vorzeichenbits zu füllen, sodass der Wert erhalten bleibt.
Dies nennt man **Vorzeichenerweiterung**.

Der Befehl `movsx` (`s` für Vorzeichen) vorzeichenerweitert einen 8-Bit- oder 16-Bit-Quelloperanden auf einen größeren Zieloperanden.
Eine Variante von `movsx` namens `movsxd` macht dasselbe von einem 32-Bit-Quelloperanden zu einem 64-Bit-Zieloperanden.

Der Befehl `neg` kann verwendet werden, um das Vorzeichen einer Zahl zu ändern.

~~~~exercism/caution
In Assembly gibt es keine Möglichkeit festzustellen, ob eine Folge von Bytes eine vorzeichenbehaftete oder eine vorzeichenlose Zahl darstellt.
Der Programmierer ist dafür verantwortlich, diesen Bytes eine Bedeutung zu geben.

Die Verwendung von Kommentaren kann bei dieser Aufgabe eine große Hilfe sein.
~~~~

## Immediates

In einem vorherigen Konzept wurde erwähnt, dass eine konstante Zahl wie `4` oder `-15` als Quelloperand für viele Befehle verwendet werden kann.
Diese Zahlen nennt man **Immediates**.

Ein Immediate wird nicht in einem Register oder im Speicher gehalten: es ist im Befehl selbst codiert.
In den meisten Befehlen ist der dafür reservierte Platz nur 32 Bit breit, unabhängig davon, wie groß der Zieloperand ist.

Wenn der Zieloperand 64 Bit breit ist, werden diese 32 Bits _vorzeichenerweitert_, um ihn zu füllen.
Die obere Hälfte des Operanden wird vollständig mit Kopien des obersten Bits des Immediates gefüllt, sodass auf diese Weise nur eine Zahl im Bereich einer _vorzeichenbehafteten 32-Bit-Ganzzahl_ geschrieben werden kann:

```x86asm
add rax, -1          ; the immediate is sign-extended, so all 64 bits of rax are affected
add rax, 2147483647  ; the largest immediate an instruction like this accepts
```

Eine Zahl außerhalb dieses Bereichs kann nicht als Immediate verwendet werden.
Die Ausnahme von dieser Regel ist `mov`, der ein volles 64-Bit-Immediate aufnehmen kann, wenn der Zieloperand ein Register ist.
Wenn ein 64-Bit-Immediate benötigt wird, lade es zuerst mit `mov` in ein Register und verwende dann dieses Register:

```x86asm
mov rax, 3435973837           ; this works, mov can take a 64-bit immediate
mov rdx, 18446744073709551615 ; the largest immediate mov accepts
sub rdx, rax
```

Beachte, dass ein negatives Immediate und die vorzeichenlose Zahl mit derselben Bitdarstellung äquivalent sind und zu exakt demselben Wert assemblieren:

```x86asm
mov rax, -1                   ; rax = 18446744073709551615
mov rax, 18446744073709551615 ; rax = -1
```

## Summe

Die Addition zweier Zahlen kann mit dem Befehl `add` berechnet werden.

Es gibt auch einen Ein-Operanden-Befehl `inc`, der `1` zum Wert in seinem Operanden addiert:

```x86asm
inc rax ; rax = rax + 1
```

Die Summe zweier Ganzzahlen verhält sich für vorzeichenlose und vorzeichenbehaftete Zahlen gleich.

## Subtraktion

Die Subtraktion zweier Ganzzahlen erfolgt mit dem Befehl `sub`.

Es gibt auch einen Ein-Operanden-Befehl `dec`, der `1` vom Wert in seinem Operanden subtrahiert:

```x86asm
dec rax ; rax = rax - 1
```

Die Subtraktion zweier Ganzzahlen verhält sich ebenfalls für vorzeichenlose und vorzeichenbehaftete Zahlen gleich.

## Multiplikation

Es gibt zwei verschiedene Befehle, um in x86-64 eine Multiplikation zwischen zwei Zahlen durchzuführen.
In der Regel verwendet die vorzeichenlose Multiplikation den Befehl `mul`, während die vorzeichenbehaftete Multiplikation `imul` verwendet.

Der Befehl `mul` hat die folgende Ein-Operanden-Form, wobei `src` der Quelloperand ist:

```x86asm
mul src
```

Der Befehl `imul` kann eine Ein-Operanden-, Zwei-Operanden- oder Drei-Operanden-Form haben:

```x86asm
imul src
imul dest, src
imul dest, src1, src2
```

### Ein-Operanden-Multiplikation

Zwei Register werden implizit verwendet, um eine Multiplikation in der Ein-Operanden-Form durchzuführen: `rax` und `rdx`.
Wenn die Multiplikation zwei 64-Bit-Zahlen umfasst, dann befinden sich die unteren 64 Bits des Ergebnisses in `rax` und die oberen 64 Bits in `rdx`.

Dies wird üblicherweise `rdx:rax` genannt, um anzugeben, dass beide Register gemeinsam verwendet werden:

```x86asm
mul rcx ; rax = lower 64 bits of rax * rcx
        ; rdx = upper 64 bits of rax * rcx
```

Dasselbe geschieht bei anderen Operandengrößen.
Wenn beispielsweise zwei 32-Bit-Zahlen multipliziert werden, werden `eax` und `edx` verwendet.

Die Ausnahme ist die Multiplikation zwischen zwei Bytes.

In diesem Fall wird anstelle von `dl:al` `ax` verwendet.
Der untere Teil von `ax` (`al`) erhält die unteren 8 Bits des Produkts, während der obere Teil (`ah`) die oberen 8 Bits erhält.

~~~~exercism/caution
Register, die implizit in einer Multiplikation verwendet werden, wie `rax` und `rdx`, werden immer überschrieben.
Die Werte in diesen Registern sollten vor der Operation gespeichert werden, wenn sie später benötigt werden.
~~~~

### Zwei-Operanden-Multiplikation

Die Zwei-Operanden-Form von `imul` hat einen expliziten Zieloperanden und folgt der üblichen Syntax.
`rdx` wird nicht verwendet.
Stattdessen wird das Ergebnis abgeschnitten, um in den Zieloperanden zu passen.

```x86asm
imul r8, r9 ; r8 = lower 64 bits of r8 * r9
```

### Drei-Operanden-Multiplikation

Die Drei-Operanden-Form von `imul` hat zwei Quelloperanden, von denen der zweite immer ein Immediate (eine konstante Zahl) ist.
Beide Quelloperanden werden multipliziert und das Ergebnis wird abgeschnitten und in den Zieloperanden geschrieben:

```x86asm
imul r8, r9, 100 ; r8 = lower 64 bits of r9 * 100
```

Beachte, dass der Zieloperand bei der Multiplikation nicht verwendet wird.
Er empfängt nur das Ergebnis.

### Umgang mit Überlauf

Sowohl die Zwei-Operanden- als auch die Drei-Operanden-Multiplikation schneiden das Ergebnis ab, damit es in die Größe des Zieloperanden passt.
Eine Ein-Operanden-Multiplikation bewahrt den vollen Bereich, aber sie wird normalerweise auf zwei Register aufgeteilt, `rdx` und `rax`.

Daher ist es manchmal nützlich, die Operanden vor der Multiplikation zu erweitern, um Platz für das gesamte Produkt in einem einzigen Register zu schaffen.
Ein vorzeichenloser Operand wird nullerweitert, während ein vorzeichenbehafteter vorzeichenerweitert wird:

```x86asm
movzx eax, di ; di and si hold unsigned 16-bit numbers
movzx ecx, si
mul ecx       ; the 32-bit product fits in eax, and edx is cleared
```

## Division

Wie bei der Multiplikation gibt es auch zwei Befehle, um eine Division zwischen zwei Zahlen durchzuführen.
Die vorzeichenlose Division verwendet den Befehl `div`, während die vorzeichenbehaftete Division `idiv` verwendet.

Beide Befehle arbeiten mit nur einem Operanden:

```x86asm
div src
idiv src
```

Die 16-Bit-, 32-Bit- und 64-Bit-Division verwenden `dx:ax`, `edx:eax` bzw. `rdx:rax` als Dividenden.
In diesen Fällen wirken beide Register zusammen, um einen 2N-Bit-Wert zu bilden, wobei N die Größe der Operation ist (16 Bit, 32 Bit oder 64 Bit).
Dieser Wert wird dann durch den Quelloperanden dividiert.
Der Quotient wird in `ax`, `eax` oder `rax` geschrieben und der Rest in `dx`, `edx` oder `rdx`, entsprechend der Größe der Operation.

Die Division zwischen Bytes ist speziell: Anstelle von `dl:al` wird `ax` verwendet.
Die unteren 8 Bits von `ax` (`al`) erhalten den Quotienten der Operation und die oberen 8 Bits (`ah`) erhalten den Rest.

Beachte, dass alle Bits im Dividenden vor der Division entsprechend gesetzt sein sollten.
Jedes in `rdx` (oder in `ah` bei 8-Bit-Division) gesetzte Bit trägt zum Wert bei, der dividiert wird.

Bei der vorzeichenlosen Division sollte die obere Hälfte gelöscht werden, wenn der zu dividierende Wert in die untere Hälfte passt.
Jeder Befehl, der diese Bits löscht, ist geeignet.
Zum Beispiel löscht `mov edx, 0` die oberen Bits bei der 32-Bit-Division.

Bei der vorzeichenbehafteten Division sollte der Wert stattdessen vorzeichenerweitert werden.
Es gibt Befehle, die diesen Prozess automatisieren: `cbw`, `cwd`, `cdq` und `cqo`.
Der erste setzt die Bits in `ah` entsprechend dem Vorzeichen von `al`.
Die anderen führen eine Vorzeichenerweiterung von `ax` nach `dx`, von `eax` nach `edx` bzw. von `rax` nach `rdx` durch.

~~~~exercism/caution
Register, die implizit in einer Division verwendet werden, wie `rax` und `rdx`, werden immer überschrieben.
Die Werte in diesen Registern sollten vor der Division gespeichert werden, wenn sie später benötigt werden.
~~~~
