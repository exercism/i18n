# Anleitung

Du betreust das Toolkit zur Codegenerierung einer Signalstation.
Jedes Makro ist eine *Schablone*: eine kleine Vorlage, mit der der Compiler
an jeder Aufrufstelle spezialisierten Code ausstanzt.

Du schreibst nur die vier Makros. Die Testdatei definiert kleine
Wrapper-Wörter, die deine Makros *aufrufen* (ein Makro lässt sich nur
anhand des Codes beobachten, den es erzeugt), und prüft dann die
Laufzeitergebnisse der Wrapper. Lass die Wrapper so, wie sie sind.

Für jede Aufgabe bekommt der Body die literalen Eingaben der Aufrufstelle
auf dem Stack und muss **eine Quotation** hinterlassen. Die Zeilen mit
„compiles to" zeigen den geradlinigen Code, den deine Quotation erzeugen
soll.

## 1. Zweimal

`twice` nimmt eine literale Quotation und gibt eine Quotation zurück, die
die ursprüngliche zweimal hintereinander ausführt.

```factor
! : inc-twice ( x -- y ) [ 1 + ] twice ;
! body receives [ 1 + ]  ->  must build [ 1 + 1 + ]
5 inc-twice .   ! => 7
```

## 2. N Wiederholungen

`repeat-quot` nimmt eine literale Quotation und eine literale Anzahl `n`
und gibt eine Quotation zurück, die die ursprüngliche `n`-mal hintereinander
ausführt. `n = 0` gibt die leere Quotation `[ ]` zurück.

```factor
! : inc-thrice ( x -- y ) [ 1 + ] 3 repeat-quot ;
! body receives [ 1 + ] 3  ->  must build [ 1 + 1 + 1 + ]
5 inc-thrice .   ! => 8
```

## 3. Viele kombinieren

`compose-many` nimmt ein literales Array von Quotationen und gibt eine
einzelne Quotation zurück, die jede der Reihe nach ausführt. Ein leeres
Array gibt die leere Quotation zurück.

```factor
! : pipeline ( x -- y ) { [ 1 + ] [ 2 * ] [ 1 - ] } compose-many ;
! body receives { [ 1 + ] [ 2 * ] [ 1 - ] }  ->  must build [ 1 + 2 * 1 - ]
5 pipeline .   ! => 11
```

## 4. Entrollte Iteration

`each-literal` nimmt eine literale Sequenz und eine Quotation. Sie gibt
eine Quotation zurück, die für jedes Element der Sequenz dieses Element
auf den Stack legt und dann die Quotation ausführt. Die Iteration findet
schon zur Compilezeit statt, sodass der erzeugte Code geradlinig ist.

```factor
! : sum-three ( -- n ) 0 { 10 20 30 } [ + ] each-literal ;
! body receives { 10 20 30 } [ + ]  ->  must build [ 10 + 20 + 30 + ]
sum-three .   ! => 60
```

Das ist die strukturellste der vier: Sowohl die Länge der Sequenz *als
auch* ihre Elementwerte bestimmen den erzeugten Code. Die Hinweise führen
dich Schritt für Schritt durch den Aufbau.
