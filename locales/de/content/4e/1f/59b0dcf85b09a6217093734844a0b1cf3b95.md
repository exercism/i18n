# Anweisungen

Deine Aufgabe ist es, einen String im Smart Game Format (SGF) zu parsen und eine Baumdatenstruktur zurückzugeben, die das Spiel darstellt.

Ein SGF-String stellt einen Baum aus Knoten dar. Der gesamte Baum steht in runden Klammern `()`.
Jeder Knoten im Baum wird durch ein Semikolon `;` gekennzeichnet, gefolgt von einer Folge von Eigenschaften.
Eine Eigenschaft besteht aus einer Kennung in Großbuchstaben (z. B. `AB`), gefolgt von einem oder mehreren Werten in eckigen Klammern `[]`.

Zum Beispiel stellt der String `(;FF[4]C[root])` einen Baum mit einem einzigen Wurzelknoten dar. Dieser Knoten hat zwei Eigenschaften:
- Eigenschaft `FF` mit dem Wert `4`
- Eigenschaft `C` mit dem Wert `root`

**Variationen (Bäume und Zweige)**
SGF unterstützt Spielvariationen durch verschachtelte Bäume. Ein Baum kann mehrere untergeordnete Bäume haben, die ebenfalls in runden Klammern stehen.
Zum Beispiel stellt `(;A[B](;C[D])(;E[F]))` einen Wurzelknoten mit der Eigenschaft `A` dar, der zwei untergeordnete Zweige hat:
1. einen Knoten mit der Eigenschaft `C` und dem Wert `D`
2. einen Knoten mit der Eigenschaft `E` und dem Wert `F`

**Formatierung und Escaping**
Werte in Klammern können maskierte Zeichen enthalten. Ein Backslash `\`, gefolgt von einem beliebigen Zeichen, steht für genau dieses Zeichen (z. B. sollte `\]` als wörtliches `]` geparst werden). Wenn vor einem Zeilenumbruch ein Backslash steht, dient das als Zeilenfortsetzung und sollte aus dem Wert entfernt werden. Alle anderen Zeilenumbrüche innerhalb eines Werts sollten erhalten bleiben.

**Fehlerbehandlung**
Bei ungültigen SGF-Strings musst du einen Fehler werfen. Die folgenden Beispiele zeigen ungültige SGF-Strings:
- Ein Baum, der nicht mit runden Klammern `()` beginnt.
- Ein Knoten, der nicht mit einem Semikolon `;` beginnt.
- Eigenschaftskennungen, die nicht vollständig aus Großbuchstaben bestehen.
- Fehlende eckige Klammern oder nicht zusammenpassende runde Klammern.

### Datenstruktur

Deine Parse-Funktion sollte eine Darstellung des Baums zurückgeben. Ein üblicher Ansatz ist, jeden Baum als Objekt mit zwei Feldern darzustellen:
- `properties`: Ein Objekt (oder eine Map), bei dem die Schlüssel die Eigenschaftskennungen (Strings) sind und die Werte Arrays von Strings (da eine Eigenschaft mehrere Werte haben kann).
- `children`: Ein Array mit den untergeordneten Bäumen.


Beispiel:

Eingabe: `(;FF[4]C[root])`
Ausgabe: `{
  properties: {
    FF: ['4'],
    C: ['root']
  },
  children: []
}`

Eingabe: `(;A[B](;C[D])(;E[F]))`
Ausgabe: `{
  properties: {
    A: ['B']
  },
  children: [
    {
      properties: {
        C: ['D']
      },
      children: []
    },
    {
      properties: {
        E: ['F']
      },
      children: []
    }
  ]
}`
