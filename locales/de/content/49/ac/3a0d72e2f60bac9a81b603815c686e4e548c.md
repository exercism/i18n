# Einführung

## Funktionen

Du kannst in `jq` deine eigenen **benutzerdefinierten Funktionen** definieren, um die Logik zu kapseln, die du brauchst.
_Funktionen_ verhalten sich wie eingebaute Funktionen: Sie nehmen einen Eingabewert und geben null, eine oder mehrere Ausgaben aus.

### Eine Funktion definieren

Du kannst eine `jq`-Funktion mit der folgenden Syntax definieren:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- beginnt mit dem Schlüsselwort `def`,
- ein Doppelpunkt vor dem Funktionskörper,
- der Körper besteht aus einem einzigen Ausdruck,
- endet mit einem Semikolon,
- wie im restlichen `jq`-Syntax kannst du beliebige Leerzeichen zur besseren Lesbarkeit verwenden.

### Wohin Funktionen gehören

_Funktionen_ müssen definiert werden, bevor sie verwendet werden. Das hier ist ein Fehler:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Das bedeutet, du musst _Funktionen_ oben in deinem `jq`-Code platzieren, vor dem „Haupt“-Ausdruck.

#### Verschachtelte Funktionen

_Funktionen_ können verschachtelt werden:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Hier ist die `B`-Funktion nur im Körper von `A` sichtbar.

### Gültigkeitsbereich

Eine _Funktion_ führt einen neuen **Gültigkeitsbereich** für Variablen und verschachtelte Funktionen ein.

### Argumente

Funktionsargumente werden durch _Semikolons_ getrennt, nicht durch Kommas.
Zum Beispiel eine _Funktion_, die eine Zahl entgegennimmt und dann eine Zahl addiert und mit einer Zahl multipliziert:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

10 | add_mul(5, 4)

#### Argumente sind _Ausdrücke_

Funktionsargumente sind Filter, keine Werte.
In diesem Sinn verhalten sie sich wie das, was andere Sprachen als Callbacks bezeichnen:

Am Beispiel der `add_mul`-Funktion:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

Was passiert hier?

- das `adder`-Argument erhält den _Ausdruck_ `. + 5`
  - wenn die Funktion `. + adder` ausführt, wird daraus `. + . + 5`
  - das ergibt 25, da `. == 10`
- ähnlich ist das `multiplier`-Argument der Ausdruck `. - 2`
  - das ergibt 8
  - dann ist das Ergebnis `25 * 8 == 200`

#### Argumente als Werte

Manchmal möchtest du ein _Argument_ in eine Variable „materialisieren“:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Dafür gibt es eine Kurzschreibweise:

```jq
def my_func($arg):
    other stuff ...
;
```

Beachte, dass das nur „syntaktischer Zucker“ ist: Der Name `arg` ohne `$` ist weiterhin im Gültigkeitsbereich der _Funktion_.

### Stelligkeit

_Funktionen_ haben eine **Stelligkeit**: die Anzahl der _Argumente_, die sie entgegennehmen.

_Funktionen_ können denselben Namen mit unterschiedlichen _Stelligkeiten_ verwenden.
Die eingebaute Funktion [`range`][man-range] zeigt das: `range/1`, `range/2` und `range/3` existieren alle nebeneinander.

Das kann nützlich sein, um rekursive Funktionen zu definieren, die ihren Zustand über Argumente tragen.
Zum Beispiel _könnte_ `map` so implementiert werden:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

### Rekursion

`jq` führt Tail-Call-Optimierung durch, aber nur für Funktionen mit Stelligkeit 0.

### Module

Ein `jq`-Modul ist eine Datei, die nur Funktionen enthält.
Module werden mit den Befehlen [`include`][man-include] oder [`import`][man-import] in ein jq-Programm eingebunden.
