# Über

Factor bündelt die Zufälligkeit im Vokabular [`random`][random] um ein einziges generisches Wort:

```
random ( obj -- elt )
```

Es entscheidet anhand seines Arguments:

- eine **Ganzzahl** `n` liefert eine zufällige Ganzzahl in `[0, n)`;
- eine **Sequenz** liefert ein zufälliges Element;
- Assocs, Hash-Sets und Tupel vom Typ `uniform-distribution` werden ebenfalls unterstützt.

Zwei Sequenz-Helfer bauen darauf auf:

```factor
USING: random ;

{ 1 2 3 4 5 } randomize .   ! shuffle in place (Fisher–Yates)
{ 1 2 3 4 5 } 3 sample .    ! 3 distinct elements; error if too many
```

`randomize` verändert die Sequenz und gibt sie zurück; rufe also zuerst `clone` auf, wenn du die ursprüngliche Reihenfolge behalten willst.

## Woher die Zufälligkeit kommt

`random` liest den Generator, der in der dynamischen Variable `random-generator` hinterlegt ist. Standardmäßig ist das ein Mersenne-Twister, der mit der Systemuhr initialisiert wird, sodass sich jeder Prozess unterscheidet. Du kannst für die Dauer einer Quotation einen anderen Generator installieren:

```
<mersenne-twister> ( seed -- rnd )
with-random        ( rnd quot -- )
```

```factor
USING: random random.mersenne-twister ;

42 <mersenne-twister> [ { 1 2 3 } randomize ] with-random .
! => the same ordering on every run
```

Weil `with-random` die Variable `random-generator` einfach für die dynamische Ausdehnung der Quotation bindet, sollte ein Wort, das es umschließt, mit `inline` markiert werden, damit die Quotation ihr Ergebnis für den Aufrufer auf dem Stack lassen kann.

Darüber hinaus bietet `random` `random-bits`, `random-unit`, `uniform-random` und `normal-random` für andere Verteilungen sowie `system-random-generator` und `secure-random-generator` für nicht reproduzierbare und kryptografische Zwecke.

[random]: https://docs.factorcode.org/content/vocab-random.html
