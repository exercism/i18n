# Einführung

Skalarer Code verlässt sich auf Flags, die von verschiedenen Befehlen gesetzt werden, um als Reaktion auf eine bestimmte Bedingung zu verzweigen.
Gepackte Werte hingegen repräsentieren nicht einen, sondern viele Werte parallel.
Eine einzelne Bedingung kann für eine Lane fehlschlagen und für eine andere zutreffen.

Deshalb ist SIMD-Code standardmäßig _verzweigungsfrei_.

Anstatt sich auf Flags zu verlassen, erzeugen gepackte Vergleiche normalerweise eine **Maske** im Zieloperanden.
Für jede Lane füllt der Vergleich die gesamte Lane mit Einsen, wenn er wahr ist, und mit Nullen, wenn er falsch ist.
Als vorzeichenbehaftete Ganzzahl gelesen ist eine wahre Lane `-1` und eine falsche Lane `0`.

Diese Maske kann dann mit bitweisen Operationen kombiniert werden, um bestimmte Lanes herauszufiltern.

## Gepackte Vergleiche

Ein skalares `cmp` ist insofern generisch, als dass es verwendet wird, um verschiedene Flags gleichzeitig zu setzen.
Ein anderer Befehl kann diese Flags dann konsumieren, um entweder zu verzweigen oder Berechnungen durchzuführen.

Da ein gepackter Vergleich jedoch sowohl eine Bedingung prüft als auch eine Maske berechnet, ist er nicht generisch.
Dem Vergleich muss die genaue Bedingung mitgegeben werden, die getestet wird.

Dafür gibt es zwei Möglichkeiten:

- Bei Ganzzahlvergleichen wird die Bedingung als Suffix angegeben: `eq` für Gleichheit und `gt` für Größer-als.
  Andere Varianten entstehen durch Kombination der Ergebnisse dieser Vergleiche.
- Bei Gleitkommavergleichen ist die Bedingung in einem Immediate kodiert.
  Verschiedene Werte dieses Immediates entsprechen unterschiedlichen Bedingungen, die getestet werden.

Abgesehen von der Verwendung eines bestimmten Bedingungs-Suffixes bei Ganzzahlvergleichen folgt die Syntax derselben Struktur, die wir bereits gesehen haben:

- Bei Ganzzahlen: `p` + `cmp` + Bedingung + Größe (`b`, `w`, `d` oder `q`).
- Bei Gleitkommazahlen: `cmp` + `p` + Größe (`s` oder `d`).
  Die Bedingung wird in einem Immediate als zusätzlicher Operand übergeben.

### Ganzzahlvergleiche

Wie erwähnt gibt es nur Ganzzahlvergleiche für Gleichheit und Größer-als:

| Befehl                                     | Beschreibung                              |
|--------------------------------------------|-------------------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | Gleichheit pro Lane                       |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | **vorzeichenbehaftetes** Größer-als pro Lane |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

Um einen Kleiner-als-Vergleich zu erzeugen, verwendest du `gt` mit vertauschten Operanden: `a < b` == `b > a`.

Beachte, dass der Vergleich **vorzeichenbehaftet** ist.
Um einen vorzeichenlosen Vergleich durchzuführen, kippst du das oberste Bit beider Operanden.
Das kannst du mit einem XOR mit einer Maske erreichen, in der nur das oberste Bit gesetzt ist.

~~~~exercism/note
Zwei praktische Idiome sind:

1. Ein Register mit sich selbst zu XORen, um lauter Nullen zu erhalten.
2. Ein Register mit sich selbst zu vergleichen, um lauter Einsen zu erhalten.

Zum Beispiel:

```x86asm
pxor xmm4, xmm4    ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

Lauter Nullen und lauter Einsen sind gängige Masken, um „überall falsch“ bzw. „überall wahr“ zu kodieren.
Sie können auch verwendet werden, um gepackte `0` oder gepackte `-1` darzustellen, was gängige Sentinelwerte sind.
Der NUL zum Beispiel, der das Ende eines Strings markiert, ist eine `0`.
~~~~

### Gleitkommavergleiche

Gleitkomma-Lanes haben eine andere Form: ein einzelner Befehl, `cmpps` (und `cmppd` für 64-Bit-Lanes), mit der Bedingung als Immediate:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM hat außerdem Pseudo-Ops, die auf das richtige Immediate abbilden und leichter zu merken sind.
Im Folgenden kann `x` in `px` für `s` (32-Bit-Gleitkommazahlen) oder `d` (64-Bit-Gleitkommazahlen) stehen:

| Pseudo-Op    | Immediate | Vergleich             |
|--------------|-----------|-----------------------|
| `cmpeqpx`    | 0         | a == b                |
| `cmpltpx`    | 1         | a <  b                |
| `cmplepx`    | 2         | a <= b                |
| `cmpunordpx` | 3         | a ist NaN oder b ist NaN |
| `cmpneqpx`   | 4         | a != b                |
| `cmpnltpx`   | 5         | a >= b                |
| `cmpnlepx`   | 6         | a >  b                |
| `cmpordpx`   | 7         | weder a noch b ist NaN |

## Auswählen mit einer Maske

Eine Maske kodiert das Ergebnis einer Bedingung.
Sie kann dann verwendet werden, um gemäß dieser Bedingung Lane für Lane zwischen zwei Wertemengen zu wählen.
Wir nehmen die Lane von einem Wert, wo die Maske wahr ist, und von einem anderen, wo sie falsch ist:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

Dieses Muster ist die gepackte Form der verzweigungsfreien Auswahl.
Jede Lane wird berechnet, und allein die Maske entscheidet, welcher Wert überlebt, ganz ohne `jcc`.

## Dedizierte Blends

Es gibt Befehle, die dieselbe Auswahl direkt durchführen und dabei ein Bit pro Element aus einem Maskenregister lesen.
Sie heißen **Blend**-Befehle:

| Befehl     | Element     | Maskenquelle    |
|------------|-------------|-----------------|
| `pblendvb` | Byte        | implizites `xmm0` |
| `blendvps` | 32-Bit-Lane | implizites `xmm0` |
| `blendvpd` | 64-Bit-Lane | implizites `xmm0` |

Beachte, dass der erste Befehl der Ganzzahl-Syntax folgt, während die anderen beiden der Gleitkomma-Syntax folgen.
Da diese Befehle jedoch einfach rohe Bytes auswählen, kann jeder von ihnen sowohl mit Ganzzahlen als auch mit Gleitkommazahlen verwendet werden.

Für jedes Element behält der Blend das Ziel, wenn das oberste Bit des zugehörigen Maskenelements nicht gesetzt ist, und übernimmt die Quelle, wenn es gesetzt ist.
Nur dieses **oberste Bit** wird herangezogen, was eine Vergleichsmaske erfüllt, da ihre Lanes entweder lauter Einsen oder lauter Nullen sind.
Das Maskenregister ist immer `xmm0`, was implizit ist:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

Es ist auch möglich, `pblendvb` zu verwenden, um Lanes aus einer Vergleichsmaske für jede andere Größe auszuwählen.
Da alle Bytes in einer wahren Lane lauter Einsen sind, wählt `pblendvb` sie alle aus.

~~~~exercism/note
Diese Befehle hängen alle ein `v` an die ausgeführte Operation (`blend`) an.
Dieses `v` steht für _variable_, weil die Auswahl nicht statisch ist: Sie hängt von einem Register ab.

Es gibt auch Varianten ohne `v`, die gemäß einem Immediate auswählen.
Sie folgen demselben Muster und wählen eine Lane `i` aus, wenn Bit `i` des Immediates gesetzt ist.
~~~~

## Von einer Maske zurück zum Skalar

SIMD-Code ist zwar mächtig, aber ihm fehlt ein Großteil der Flexibilität von skalarem Code.
In vielen Situationen ist es nötig, von einem gepackten Register zurück in die Welt der skalaren Befehle zu wechseln.

Die Befehlsfamilie `movmsk` dient als Brücke zwischen den beiden Welten.
Diese Befehle extrahieren das **oberste Bit** jeder Lane in ein Allzweckregister:

| Befehl     | sammelt                          | Ergebnisbreite |
|------------|----------------------------------|----------------|
| `pmovmskb` | das oberste Bit von jeweils 16 Bytes | 16 Bit     |
| `movmskps` | das oberste Bit von jeweils 4 Dwords | 4 Bit      |
| `movmskpd` | das oberste Bit von jeweils 2 Qwords | 2 Bit      |

Nach einem Vergleich stellt jedes gesetzte Bit eine „wahre“ Lane dar und jedes gelöschte Bit eine „falsche“ Lane.
Dieses Ergebnis kann dann wie gewohnt mit skalaren Befehlen weiterverarbeitet werden.
Zum Beispiel zählt ein `popcnt` die Anzahl der Treffer, und `tzcnt` findet den ersten.

Das Allzweckregister kann 32 oder 64 Bit breit sein.

## Einen ganzen Vektor testen

Es gibt auch eine gepackte Variante des skalaren Befehls `test`: `ptest`.

Er ähnelt seinem skalaren Gegenstück darin, dass er eine AND-Operation zwischen zwei Operanden durchführt, ohne sie zu verändern.
Anders als `test` führt `ptest` zusätzlich eine ANDN-Operation durch, die den ersten Operanden negiert.

Somit kann `ptest` als nicht-destruktive Version von `pand` und `pandn` betrachtet werden, die Flags entsprechend dem Ergebnis setzt.
Ähnlich wie diese beiden Befehle behandelt `ptest` das gesamte SIMD-Register als eine einzige Lane und nimmt daher kein Größenpräfix entgegen.

Wenn das Ergebnis einer AND-Operation `0` ist, wird das `ZF` gesetzt, und wenn die ANDN-Operation `0` ergibt, wird `CF` gesetzt.
Das bedeutet, dass `ptest` verwendet werden kann, um sowohl auf eine Maske aus lauter Einsen als auch aus lauter Nullen zu prüfen:

1. Verwendet man `ptest` mit einem Register gegen sich selbst, wird `ZF` nur gesetzt, wenn das Register lauter Nullen enthält.
   Das ahmt das übliche skalare Idiom nach, `test` mit einem Register gegen sich selbst zu verwenden, um auf `0` zu prüfen.
2. Verwendet man `ptest` mit einem Register und einer Maske aus lauter Einsen, wird `CF` nur gesetzt, wenn das Register lauter Einsen enthält.
   Außerdem wird `ZF` nur gesetzt, wenn das Register lauter Nullen enthält, sodass sich beide Masken auf einmal prüfen lassen.

```x86asm
pxor    xmm0, xmm0   ; all zeros
pcmpeqb xmm1, xmm1   ; all ones
pcmpeqb xmm2, xmm2

ptest xmm0, xmm0     ; ZF set: a register against itself detects all zeros
ptest xmm0, xmm1     ; ZF set, CF clear: xmm0 is all zeros, not all ones
ptest xmm2, xmm1     ; CF is set only if xmm2 is all ones
```

Das Ergebnis eines `ptest` kann wie gewohnt zum Verzweigen oder in verzweigungsfreien Befehlen wie `setcc` oder `cmovcc` verwendet werden.
