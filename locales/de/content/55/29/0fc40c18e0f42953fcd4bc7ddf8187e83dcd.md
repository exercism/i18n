# Über

## Darstellung, Zeichen und Ganzzahlen

Wie andere einfache Typen (`int`s, `bool`s usw.) hat der `char` einen Begleit- oder Alias-Typ, in diesem Fall `System.Char`.

Dies ist tatsächlich ein `struct` mit einem 16-Bit-Feld und standardmäßig unveränderlich.

`char` hat einige Instanzmethoden wie `Equals`, `ToString` und [`CompareTo`][compare-to].

`char` hat die gleiche Breite wie ein [`ushort`][uint16], aber sie werden im Allgemeinen nicht austauschbar verwendet wie in einigen Sprachen. `ushort` muss explizit in einen `char` umgewandelt werden.

Übrigens können `char`s arithmetischen Operationen unterzogen werden. Das Ergebnis dieser Operationen ist eine Ganzzahl.

Offensichtlich gibt es keine Äquivalenz zwischen einem `byte` mit 8 Bit und dem 16-Bit-`char`.

## Verwendung

`char`s sind im Allgemeinen einfach zu verwenden.

Sie können als Literale mit einfachen Anführungszeichen definiert werden:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

Ein einzelner `char` kann mit (nullbasierter) Indexierung aus einem String abgerufen werden:

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

Das Iterieren über einen String liefert bei jedem Schritt einen `char`:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

Wie oben gezeigt, kann ein `char` in seinen `int`-Wert umgewandelt werden.
Dies funktioniert auch (*zumindest manchmal*) für andere Schriftsysteme:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

Der zugrunde liegende Int16 wird beim Vergleich von Zeichen verwendet:

```fsharp
'A' < 'D'
// => val it: bool = true
```

Außerdem kann ein `int` in `char` umgewandelt werden:

```fsharp
char 77
// => val it: char = 'M'
```

Die `System.Char`-Bibliothek enthält den vollständigen Satz von [Methoden][Char-methods], die für eine .NET-Sprache erwartet werden, wie Groß-/Kleinschreibung (aber beachte die Einschränkungen im nächsten Abschnitt):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

Die .NET-Bibliotheken helfen beim Extrahieren von `char`s aus Strings, in diesem Fall `Seq`-Methoden:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

Es gibt verschiedene Möglichkeiten, eine Zeichenliste (oder ein Array) in einen String umzuwandeln, darunter diese:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

Allgemeine Informationen zu `char`s findest du hier:

- [Chars-Dokumentation][chars-docs]: Referenzdokumentation für `char`.

Allerdings haben `char`s einige Schwachstellen, wie unten beschrieben. Diese Schwachstellen beziehen sich hauptsächlich auf den Gegensatz zwischen dem vollständigen Unicode-Standard einerseits und historischen Textdarstellungen sowie Leistung und Speicherverbrauch andererseits.

## Unicode-Probleme

Wenn du mit Strings arbeitest und [`System.String`][System-string]-Bibliotheksmethoden verfügbar sind, solltest du diese suchen und verwenden, anstatt den String in Zeichen aufzuteilen.

Einige textliche „Zeichen“ bestehen aus mehr als einem `char`, weil der Unicode-Standard mehr als 65536 Codepunkte hat. Zum Beispiel bestehen die Emojis, die in einigen Tests auftauchen, aus 2 `char`s, da sie [Surrogat][surrogates]-Zeichen umfassen.

Darüber hinaus gibt es kombinierende Sequenzen, bei denen beispielsweise ein akzentuiertes Zeichen aus einem `char` für das Grundzeichen und einem weiteren `char` für den Akzent bestehen kann.

Wenn du mit einzelnen Zeichen umgehen musst, solltest du versuchen, Bibliotheksmethoden wie [`System.Char.IsControl`][is-control], [`System.Char.IsDigit`][is-digit] zu verwenden, anstatt naive Vergleiche anzustellen, wie zu prüfen, ob ein Zeichen zwischen '0' und '9' liegt.

Beachte zum Beispiel, dass '٢' die arabische Ziffer 2 ist. `IsDigit` gibt für die arabische Version wahr zurück, also musst du beim Validieren klarstellen, welcher Eingabebereich akzeptabel ist.

Selbst die `System.Char`-Bibliotheksmethoden verhalten sich möglicherweise nicht wie erwartet, wenn du mit obskureren Sprachen zu tun hast.

Eine Möglichkeit, einen String sicher in Anzeige-„Zeichen“ aufzuteilen, ist die Verwendung von [`StringInfo`][string-info] und Methoden wie [`GetNexttextElement`][get-next-text-element].
Dies kann notwendig sein, wenn du mit Globalisierung/Lokalisierung zu tun hast.

Eine weitere Möglichkeit, bei der die Skalarwerte von Unicode-Zeichen wichtig sind (sagen wir, du entwickelst dein eigenes Kodierungssystem), ist die Verwendung von [Runes][runes]. Wenn du jedoch weißt, dass der Bereich der Zeichen, mit denen du umgehst, keine Surrogate oder kombinierenden Zeichensequenzen enthält (z. B. Latin ASCII) und deine Eingabe gut validiert ist, kannst du dies vermeiden.

Wiederum, die beste Position ist die, in der du die Bibliotheksmethoden von `String` verwenden kannst.

Wenn du dich in der unangenehmen Lage befindest, dich mit den Details von Unicode befassen zu müssen, dann ist [dies][char-encoding-net] ein guter Ausgangspunkt.

## Globalisierung

Wenn du in einer Umgebung arbeitest, in der du mit mehreren Kulturen zu tun hast oder die Kultur in einigen Teilen des Codes wichtig ist, in anderen aber nicht, dann achte auf die Überladungen von [`ToUpper`][to-upper] und [`ToLower`][to-lower], die eine Kultur annehmen, sowie [`ToUpperInvariant`][to-upper-invariant] und [`ToLowerInvariant`][to-lower-invariant], die ein konsistentes Ergebnis unabhängig von der aktuellen [Kultur][culture-info] liefern.
