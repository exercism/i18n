# Verträge

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| Klausel | Sagt | Wessen Schuld, wenn verletzt |
| --- | --- | --- |
| `pre` | was beim Eintritt gelten muss | die des Aufrufers |
| `post` | was bei der Rückkehr gilt | die der Routine |

Beide nehmen einen `BOOL`, und beide dürfen die Argumente der Routine und die
Attribute des Objekts verwenden. `post` darf außerdem `result` verwenden, den
zurückgegebenen Wert.

## assert

Innerhalb des Rumpfs einer Routine stellt `assert` etwas fest, das an dieser
Stelle wahr sein muss:

```sather
      assert load <= limit;
```

Es wird mit demselben Flag geprüft wie die anderen.

## Klasseninvarianten

Eine Klasse kann etwas feststellen, das zwischen Aufrufen für jedes ihrer
Objekte wahr ist:

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

Wird beim Eintritt in jede öffentliche Routine und beim Austritt daraus
geprüft, wenn die Prüfung eingeschaltet ist.

## So schaltest du es ein

| Flag | Prüft |
| --- | --- |
| `-chk` | alles: pre, post, assert, Invariante, Grenzen, Arithmetik |
| `-chk_no` | nichts |

Beachte, dass `-chk_pre` allein in diesem Compiler die Prüfung der
Vorbedingungen *nicht* einschaltet; `-chk` ist es, was funktioniert. Eine
Verletzung gibt die Routine und die Quellzeile aus und stoppt das Programm. Sie
ist keine Ausnahme, und `protect` fängt sie nicht ab.

Üblich ist, mit `-chk` zu entwickeln und zu testen und ohne auszuliefern, damit
die Prüfungen im ausgelieferten Programm nichts kosten. Das zahlt sich nur aus,
wenn die Tests die Pfade tatsächlich durchlaufen.

## Was einen guten Vertrag ausmacht

Sag, was die Routine braucht, nicht wie sie funktioniert:

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

Ein `post`, der den Rumpf nur wiederholt, bringt niemandem etwas:

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## Vererbung

Ein Untertyp darf ein `pre` abschwächen und ein `post` verstärken (mehr
akzeptieren, mehr zusagen), aber niemals umgekehrt, sonst würde Code brechen,
der gegen den Obertyp geschrieben wurde. Genau diese Regel machen Verträge
überprüfbar.
