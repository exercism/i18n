# Abschnitt über Kommentare

Go hat [großartige Richtlinien](https://golang.org/doc/effective_go.html) dazu, wie du Kommentare schreibst. Es gibt ein Standardformat, das du für Dokumentationskommentare verwenden kannst und das dann vom `godoc`-Tool automatisch in schöne Dokumentation umgewandelt werden kann.

Der Paketkommentar sollte mit dem Wort `Package` beginnen, gefolgt vom Paketnamen, so:

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

Bei exportierten Funktionen, Methoden, Konstanten und Paketvariablen sollte der Kommentar mit dem Namen beginnen und mit einer Verbphrase fortfahren:

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

Das [CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences)-Wiki legt außerdem fest, dass Dokumentationskommentare vollständige Sätze sein sollten, die mit einem Punkt enden.

Wenn du die Empfehlungen befolgst, verbesserst du nicht nur die Lesbarkeit, sondern auch, wie dein Code in [Go-Dokumentationswerkzeugen](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/) wie [godoc.org](http://godoc.org), `godoc` und `go doc` aussieht.

Nimm dir einen Moment Zeit und lies den Abschnitt über Dokumentationskommentare im offiziellen Styleguide, [Effective Go](https://golang.org/doc/effective_go.html), um die Gründe für diese Entscheidungen zu verstehen.
