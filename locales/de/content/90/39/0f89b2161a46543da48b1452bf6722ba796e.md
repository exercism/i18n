# Unison-Grundlagen

## Terme und Funktionen

Terme und Funktionen sind die grundlegenden Bausteine, aus denen du ein Unison-Programm schreibst.

Ein „Term“ ist das, was wir einen statischen Wert nennen. Er wird mit `name = expression` definiert, optional mit einer Typsignatur der Form `name : MyType` davor. Unison unterstützt Typinferenz, daher kann die Typsignatur bei einfachen Definitionen auch weggelassen werden.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison-Funktionen sehen so aus: `myFunctionName argument1 argument2 = myImplementation`. Sie beginnen mit dem Namen der Funktion, gefolgt von den durch Leerzeichen getrennten Argumenten.

```
getMax a b = Nat.max a b
```

Funktionen können optional eine Typsignatur enthalten. Der letzte Typ rechts ist immer der endgültige Rückgabetyp der Funktion, und jedes Argument wird durch den Funktionspfeil `->` getrennt.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Um eine Funktion aufzurufen, verwendest du ihren Namen, gefolgt von ihren Argumenten, die nur durch Leerzeichen getrennt werden.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Beim Aufruf einer Funktion versucht Unison, alles, was direkt rechts steht, als ihr Argument zu behandeln. Das ergibt nicht immer die gewünschte Reihenfolge der Funktionsauswertung.

Sagen wir, wir wollen den Wert `1` aus dem folgenden Ausdruck erhalten:

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

So wie es dasteht, wird `shouldBe1` zu `0` ausgewertet, weil die implizite Reihenfolge der Funktionsanwendung `getMax 1 10` ist, was `10` ergibt, und danach `10 - 10`, was `0` ergibt.

Du kannst runde Klammern verwenden, um den Ausdruck in die gewünschte Reihenfolge der Operationen umzugruppieren.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Watch-Ausdrücke

Unison bietet eine Möglichkeit, Code schnell auszuwerten, die als „Watch-Ausdruck“ bezeichnet wird. Ein Watch-Ausdruck beginnt mit einem `>`-Symbol, gefolgt von dem Ausdruck, der ausgewertet werden soll. Watch-Ausdrücke kannst du in jeder Datei mit der Endung `.u` schreiben. Nach dem Speichern der Datei solltest du in der Konsole des Unison Codebase Manager (UCM) sehen, zu was der Ausdruck ausgewertet wird. Wo möglich, versuchen wir in dieser Dokumentation, einen Ausdruck zusammen mit seiner erwarteten Ausgabe zu zeigen, nachdem er in einem Watch-Ausdruck ausgewertet wurde.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Mehrzeilige Funktionen

Mehrzeilige Funktionen in Unison verwenden Einrückung oder `let`-Blöcke, um Codegrenzen festzulegen, auch bekannt als „lexikalischer Gültigkeitsbereich“.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Alles auf derselben Einrückungsebene teilt denselben Gültigkeitsbereich. Deshalb können wir die Variable `newBeginning` in der letzten Zeile referenzieren.

## Namensräume und `use`-Anweisungen

Namensräume sind, wie wir Unison-Funktionen gruppieren und organisieren. Du kannst sie dir als analog zu „Verzeichnissen“ vorstellen. Sie bieten Struktur und logische Gruppierung.

Du kannst die Funktionen in einem Namensraum mit einer `use`-Anweisung in den Gültigkeitsbereich bringen.

Angenommen, du schreibst eine Funktion, die Unison-`List`-Werte verwendet. Du weißt, dass du Funktionen wie `List.map` und `List.flatMap` brauchst, wobei `List` der Namensraum und `map` und `flatMap` Funktionen sind. Um Wiederholungen zu vermeiden, könntest du alles aus dem `List`-Namensraum so in den lexikalischen Gültigkeitsbereich deiner Funktion bringen:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

Die Zeile `use List` macht die Referenzen auf `map` und `flatMap` eindeutig. Mehr über [`use`-Anweisungen findest du hier][use-statements].

Unisons Standardbibliothek heißt `base`. Wenn du dem Quickstart-Leitfaden gefolgt bist und eine Codebasis lokal erstellt hast, sollte die Standardbibliothek automatisch heruntergeladen worden sein. ## Kommentare und Dokumentationsliterale

Kommentare sind in Unison eine etwas ungewöhnliche Funktion. Wenn du Unison-Code schreibst, kannst du in deiner Datei mit der Endung `.u` Text erstellen, der nicht interpretiert wird, mit der folgenden Syntax:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Allerdings_ wird Unison-Code als Hash seines abstrakten Syntaxbaums gespeichert, nicht als textbasierte Dateien im Dateisystem. Kommentare, die textbasierte „Dekorationen“ einer bestimmten Unison-Funktion oder eines Terms in der Datei sind, können daher nicht wirklich gespeichert und zum Teilen erneut gerendert werden. Wenn du deinem Unison-Term Informationen auf eine Weise hinzufügen möchtest, die gespeichert wird, damit andere sie lesen und verstehen können, kannst du ein Dokumentationsliteral verwenden.

Dokumentation ist in der Programmiersprache Unison ein Wert erster Klasse. Das bedeutet, dass ein `Doc`-Element einem Wert zugewiesen, als Wert an eine Funktion übergeben oder als Rückgabewert einer Funktion zurückgegeben werden kann. Elemente von Dokumentationsliteralen werden mit doppelten geschweiften Klammern geöffnet und geschlossen. So könnten wir das `Doc`-Element als Kommentar verwenden:

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
