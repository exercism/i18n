# Über

Gleam kann auf der virtuellen Maschine von Erlang (BEAM) oder in JavaScript-Laufzeitumgebungen laufen. Es gibt viele weitere Sprachen, die diese Laufzeitumgebungen nutzen, und oft ist es nützlich, Code, der in diesen Sprachen geschrieben wurde, aus Gleam heraus aufrufen zu können.

Gleams Feature der _externen Funktionen_ erlaubt es, Funktionen aus anderen Sprachen nach Gleam zu importieren und ohne Laufzeit-Overhead aufzurufen.

Wenn dein Gleam-Projekt auf der virtuellen Maschine von Erlang läuft und du die Funktion `reverse` aus dem Erlang-Modul `lists` aufrufen möchtest, kannst du das tun, indem du dem Funktionskopf einer Gleam-Funktion das Attribut `@external` hinzufügst, und zwar so:

```gleam
@external(erlang, "lists", "reverse")
pub fn reverse_list(x: List(a)) -> List(a)
```

Danach kannst du sie wie eine normale Gleam-Funktion aufrufen:

```gleam
let reversed = reverse_list([1, 2, 3])
// -> [3, 2, 1]
```

Wenn du versuchst, diesen Code für JavaScript-Laufzeitumgebungen zu kompilieren, schlägt das mit einer Fehlermeldung fehl, weil es keine Implementierung für JavaScript gibt. Für JavaScript-Laufzeitumgebungen kannst du eine andere Implementierung angeben, und zwar so:

```gleam
@external(erlang, "lists", "reverse")
@external(javascript, "./my_module.mjs", "reverse")
pub fn reverse_list(x: List(a)) -> List(a)
```

Du kannst auch eine Gleam-Implementierung schreiben, die verwendet wird, wenn es keine externe Implementierung für das aktuelle Kompilierungsziel gibt:

```gleam
@external(erlang, "lists", "reverse")
pub fn reverse_list(x: List(a)) -> List(a) {
  tail_recursive_reverse(x, [])
}

fn tail_recursive_reverse(list, reversed) {
  case list {
    [] -> reversed
    [x, ..xs] -> tail_recursive_reverse(xs, [x, ..reversed])
  }
}
```
