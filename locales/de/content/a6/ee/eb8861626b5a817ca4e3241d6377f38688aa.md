# Über

Ruby ist eine dynamische und stark typisierte Sprache.
In dynamischen Sprachen wird der Typ einer Variable oder eines Objekts zur Laufzeit aufgelöst. Das bedeutet, dass sich Wert oder Typ bis zum allerletzten Moment ändern können, nämlich bis der Interpreter den Code parst.
Und was meinen wir mit stark typisiert?
Sobald wir den Typ einer Variable oder eines Objekts kennen, ist Ruby streng dabei, was man damit machen kann, zum Beispiel:

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**Aber**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

Denk daran: In Ruby ist alles ein Objekt.
Sogar Klassen sind Instanzen der Klasse `Class`.

Zum Beispiel:

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

Das heißt, wir können Klassen auch so definieren:

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

Und schließlich: Denk daran, dass das `Integer`-Objekt Werte enthält, die als eine oder mehrere (aufeinanderfolgende) Ziffern definiert sein können, und dass seine Methoden viele der [mathematischen Operatoren][integers-docs] unterstützen.

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
In der Dokumentation werden Instanzmethoden oft mit einer Syntax wie `Class#method_name` angegeben, während Methoden auf Klassen- oder Modulebene als `Class::method_name` referenziert werden.
Der `::` heißt _Scope Resolution Operator_ und verweist auf die Konstante oder Methode auf Klassen- oder Modulebene.
Das wirst du in der Ruby-Dokumentation, in Mailinglisten und in anderen Support-Bereichen antreffen.
Stattdessen wirst du feststellen, dass wir Klassen- und Modulmethoden in unseren Texten als `ClassName.method_name` oder `ModuleName.method_name` schreiben.
~~~~
