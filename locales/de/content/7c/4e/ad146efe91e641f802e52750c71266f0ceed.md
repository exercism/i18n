# Für Maintainer

## Tests generieren: `bin/generate_tests.py`

Testdateien werden aus den kanonischen Daten in
[exercism/problem-specifications](https://github.com/exercism/problem-specifications)
mit einem Jinja-Template generiert, das in jeder Übung unter `.meta/template.j2` liegt.

```bash
bin/generate_tests.py bob            # regenerate one exercise
bin/generate_tests.py                # regenerate every exercise that has a template
bin/generate_tests.py --no-pull bob  # skip `git pull` of problem-specifications
```

Das Skript liest problem-specifications aus dem Cache von configlet
(`~/.cache/exercism/configlet/problem-specifications`, gefüllt durch `bin/configlet sync`)
oder aus einem übergeordneten Verzeichnis namens `problem-specifications`.
Nur Fälle, die in `.meta/tests.toml` aufgeführt sind, werden generiert.

String-Literale in Fortran dürfen keine Escapes wie `\n` und `\t` enthalten.
Der Template-Filter `escape_quote_whitespace` schreibt sie in
`" // NEWLINE // "`, `" // TAB // "` und `" // CARRIAGE_RETURN // "` um,
deshalb muss das Template diese Konstanten deklarieren (siehe `exercises/practice/bob/.meta/template.j2`).

### Voraussetzungen

- Funktionierendes CMake und einen funktionierenden Fortran-Compiler
- Python 3.12+ mit `jinja2`
- git

### Workflow zum Hinzufügen einer neuen Übung

Am Beispiel von `bob`:

- Erstelle einen neuen Branch, z. B. `git checkout -b exercise-bob`
- Führe `bin/add-exercise bob` aus (benötigt `jq` und `curl`). Das Skript:
  - lädt configlet herunter und führt `configlet create` aus, was die Übung zu `config.json` hinzufügt und ihre Dokumentation, Metadaten und `tests.toml` aus problem-specifications synchronisiert
  - sortiert `config.json` mit `bin/reorder-exercises`
  - kopiert `exercises/shared/CMakeLists.txt` in das Übungsverzeichnis
  - schreibt eine Stub-Lösung, eine Stub-Datei `.meta/example.f90` und ein Start-Template `.meta/template.j2` (aus `exercises/shared/template.j2`)

  Es fragt nach deinem GitHub-Benutzernamen, wenn du nicht `-a <username>` übergibst, und setzt die Schwierigkeit auf 1, wenn du nicht `-d <difficulty>` übergibst.

- Bearbeite `.meta/template.j2` so, dass jeder Fall die richtige Funktion mit den richtigen Eingabewerten aufruft, und generiere dann die Tests:

  ```bash
  bin/generate_tests.py bob
  ```

- Schreibe eine funktionierende Lösung in `.meta/example.f90`. Ersetze die Datei mit dem Übungsnamen (z. B. `bob.f90`) durch ein Skelett der Funktionen oder Subroutinen, die die Tests aufrufen, damit die Lernenden leichter anfangen können
- Stelle sicher, dass alle Tests durchlaufen, und starte dafür den vollständigen Build aus dem Wurzelverzeichnis des Repositories:

  ```bash
  mkdir -p build && cd build
  cmake ..
  cmake --build .
  ctest -V -R bob
  ```

- Führe `bin/reorder-exercises` und `bin/configlet lint` aus
- Wenn alles durchläuft, öffne einen Pull Request mit deinen Änderungen

### `CMakeLists.txt` ändern

Wenn du die CMake-Datei änderst, aktualisiere die Master-Kopie in `exercises/shared/` und kopiere sie mit `bin/update-cmake-files` in alle Übungsverzeichnisse.
