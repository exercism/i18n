# Überblick

In vielen objektorientierten Sprachen ist es üblich, Verhalten durch [Unterklassenbildung][wiki-subclass] einer Elternklasse zu erweitern, wobei Methoden von der Elternklasse geerbt und gleichzeitig neue hinzugefügt werden.
So entsteht eine Objekthierarchie.

Julia _hat keine Klassen_, also folglich auch _keine Unterklassen_.
Wie erben und erweitern wir vorhandenes Verhalten?

In vorherigen Konzepten haben wir gesehen, wie man eine Typhierarchie erstellt, und außerdem gelernt, wie Julia [Multiple Dispatch][concept-multiple-dispatch] verwendet, um Methoden anhand von Argumenttypen auszuwählen.

Julia hat außerdem mehrere informelle [Schnittstellen][ref-interfaces], mit denen du eigene Typen in bereits für Standardtypen definiertes Verhalten einhängen kannst.

Am einfachsten lässt sich das mit der Iterator-Schnittstelle veranschaulichen.

## [Iteratoren][ref-iterators]

Früher im Lehrplan haben wir mehrere Möglichkeiten gesehen, wie Julia auf jedes Element einer Sammlung einwirken kann.

- [Schleifen][concept-loops], etwa `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Funktionen höherer Ordnung][concept-hof]: `map(√, [1, 4, 9])`
- [Comprehensions][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Generatoren][concept-comprehensions]: `(x^2 for x in 1:1e6)`, die verzögert ausgewertet werden.

Offensichtlich weiß Julia, wie man Standard-Sammlungen Element für Element durchgeht: Vektoren und Ranges in den obigen Beispielen, außerdem Sets, Dicts usw.

Wie fügen wir diese Fähigkeit unseren eigenen Sammlungen hinzu, besonders wenn sie wie ein Generator verzögert iteriert werden können?

### Minimale Anforderungen

Um eine Sequenz zur Iteration zu erstellen, brauchen wir (mindestens) zwei Dinge:

1. Eine Möglichkeit, das _erste_ Element zu erhalten.
2. Eine Möglichkeit, das _nächste_ Element aus dem aktuellen Zustand zu erhalten.

Julia erledigt diese Aufgaben mit Methoden der Funktion `Base.iterate()` in den folgenden Schritten:

1. `Base.iterate(iter)` wird zuerst automatisch aufgerufen.
    - Wenn es nichts zu iterieren gibt, gibt sie `nothing` zurück.
    - Andernfalls gibt sie das `Tuple` aus dem ersten zurückgegebenen Element und dem ersten Zustand zurück: `(firstitem, firststate)`.
2. `Base.iterate(iter, state)` wird automatisch aufgerufen, wenn in der vorherigen Iteration ein Element zurückgegeben wurde, wobei `firststate` als ihr `state`-Argument verwendet wird.
    - Wenn die Iteration endet, gibt sie `nothing` zurück.
    - Andernfalls gibt sie das `Tuple` aus dem nächsten Element und dem nächsten Zustand zurück: `(nextitem, nextstate)`.
3. Wiederholt Schritt 2 bis zum Ende.

Diese Schritte laufen alle „unter der Haube“ ab, das heißt, die Methodenaufrufe und der Zustand werden intern vom Iterationsprotokoll verwaltet (wobei der Zustand opak bleibt), und nur das Element wird übergeordneten Konstrukten wie Schleifen zugänglich gemacht.
Mit anderen Worten: Wir sehen immer nur das `item`, während alles andere in einer Blackbox bleibt.

[Multiple Dispatch][concept-multiple-dispatch] ist hier zentral.
Der Typ von `iter` bestimmt, welche Methoden aufgerufen werden, und die Anzahl der Argumente bestimmt, ob das erste oder das nächste Element zurückgegeben wird.

Methoden für Standardtypen sind bereits definiert: `Vector`, `Range`, `Set` usw. ([derzeit][ref-iterations-collections] insgesamt 14 Typen).

Damit ein eigener `MyType` dieselben Verhaltensweisen teilt, müssen wir zuerst definieren:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Das alles klingt in der Theorie wahrscheinlich verwirrend, kann aber ganz einfach sein.
Stell dir zur Veranschaulichung vor, wir wollen einen Typ, der Potenzen einer gegebenen Ganzzahl `n` bis zu einer maximalen Anzahl liefert.

Definiere zuerst einen eigenen Typ:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Jetzt können wir die `iterate`-Methoden für diesen Typ definieren, aber was sind das erste Element und der erste Zustand?

Um das erste Element zu erhalten, brauchen manche Iteratoren einen komplizierten Aufbau, aber in diesem Beispiel können wir feststellen, dass das erste zurückgegebene Element einfach die Basiszahl ist. Wir müssen also nur prüfen, ob der Wert von `count` größer oder gleich eins ist.

Jetzt können wir den ersten Zustand betrachten, der Informationen trägt, die für die nächste Iteration verwendet werden.
Es liegt an dir zu entscheiden, welche Informationen du dafür verfolgen musst, und es kann jeder Typ sein.

In diesem Fall könnten wir einfach den „Index“ verfolgen, mit dem `n` potenziert wird, oder wir finden eine performantere Option, indem wir die letzte Potenz von `n` (also das zurückgegebene Element) und den nächsten „Index“ in der Sequenz verwenden.
Diese beiden Zahlen können in ein `Tuple` gepackt und als `state` zurückgegeben werden.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

In diesem Beispiel wird das erste Element (`p.n`) an die Schleife zurückgegeben und der erste Zustand `(p.n, 2)` an die Methode `iterate(P::Powers, state)` übergeben.
Dort können wir den Zustand verarbeiten, um das nächste Element zu erzeugen, indem wir das aktuelle Element mit der Basiszahl multiplizieren und dadurch seine Potenz um `1` erhöhen.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Wenn der Indexwert noch innerhalb von `count` liegt, wird das `Tuple` mit dem `next`-Element und dem erhöhten Zustand `(next, index + 1)` zurückgegeben.
Wenn der `index`-Wert `count` überschreitet, wird stattdessen `nothing` zurückgegeben, um anzuzeigen, dass die Iteration beendet ist.

Vielleicht ist dir aufgefallen, dass die Methoden `iterate(p::Powers)` und `iterate(p::Powers, state)` recht ähnliche Funktionskörper haben.
Tatsächlich erlaubt uns diese Ähnlichkeit, wenn wir geschickt sind, eine schlankere Implementierung, indem wir nur die Zwei-Argument-Version mit einem Standardargument für den Zustand verwenden: `Base.iterate(p::Powers, state=(1, 1))`
Damit bräuchten wir die separate Ein-Argument-Version `iterate(p::Powers)` nicht.
Das wird in der Praxis häufig gemacht, wenn es möglich ist.

~~~~exercism/advanced
Als wir optionale Argumente im Konzept [Funktionen][concept-functions] eingeführt haben, wurde nichts über die Implementierung gesagt.

Seitdem haben wir etwas über Multiple Dispatch gelernt, daher ist es jetzt sinnvoller zu wissen, dass Julia eine Funktion _mit_ optionalen Argumenten automatisch in mehrere Methoden _ohne_ optionale Argumente umwandelt.

`Base.iterate(P::Powers, state=(1, 1))` zu definieren ist genau äquivalent dazu, sowohl `Base.iterate(P::Powers, state)` als auch `Base.iterate(P::Powers)` getrennt zu definieren.

[concept-functions]: https://exercism.org/tracks/julia/concepts/functions
~~~~

Bisher haben wir schon einige nützliche Funktionalität: Für die ersten 4 Potenzen von 3 können wir die Ergebnisse durchlaufen, prüfen, ob eine gegebene Zahl in den Ergebnissen enthalten ist, und Aggregatfunktionen wie `sum()` anwenden.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Weitere Methoden

Trotz dieses guten Anfangs funktioniert noch nicht alles.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Tatsächlich liefert `length(Powers(3, 4))` genau dieselbe Fehlermeldung.

Das lässt sich leicht beheben, denn die Länge ist Teil des Typkonstruktors: in diesem Fall 4.
Wir müssen nur `Base.length()` für diesen Typ definieren, dann können wir Comprehensions und `collect()` auf die Sequenz anwenden.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Aus Effizienzgründen ist es am besten, auch `Base.eltype()` zu definieren: den Elementtyp des Ergebnisses.
Dadurch können Funktionen wie `collect()` Speicher für den Ausgabe-`Vector{Int}` vorab reservieren, anstatt wiederholt ein `push!()` auf einen `Vector{Any}` auszuführen.

Beachte die Syntax, die dir vielleicht noch nicht begegnet ist: Diese Methode wird auf dem _Typ_ definiert, nicht auf einer _Instanz_ des Typs.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Iteratoren _müssen_ keine endliche Länge haben.
Die Verwendung „unendlicher“ Sequenzen ist eingeschränkter, aber das Durchlaufen kann nützlich sein, solange es eine Möglichkeit gibt, mit `break` aus der Schleife auszubrechen.
Zum Beispiel könnten wir eine Variante von `Powers` definieren, die Werte erzeugt, die kleiner als eine bestimmte Grenze sind (vielleicht `typemax(Int)`, um Ganzzahlüberlauf zu vermeiden).

## Weitere Schnittstellen

### Indexierung

Die Iterator-Schnittstelle erlaubt es uns, einen beliebigen eigenen Typ zu nehmen und ihn wie eine Sequenz zu behandeln, indem wir nur ein paar einfache Methoden definieren.

Angenommen, wir wollten außerdem auf die Sequenz mit Index zugreifen können:

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

Wir können dieses Verhalten hinzufügen, und das [Handbuch][ref-indexing] erklärt, wie.

Minimal müssen wir `getindex()` definieren.

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

Wir müssen außerdem definieren:

- `firstindex()` und `lastindex()`, um `P[begin]` und `P[end]` zu unterstützen.
- Varianten von `getindex()`, um Indexierung mit Vektoren und Ranges zu unterstützen.
- Theoretisch `setindex!()`, obwohl schwer zu erkennen ist, was das in diesem Beispiel überhaupt bedeuten würde.

Allerdings leisten wir zu diesem Zeitpunkt viel Arbeit, nur damit unser Iterator eher wie ein Vector aussieht.

### [AbstractArray][ref-abstractarray]

Es kann sich lohnen, über alternative Schnittstellen nachzudenken, die einen besseren Ausgangspunkt bieten.

In diesem Fall könnten wir erwägen, `Powers` zu einem Untertyp von [`AbstractArray`][ref-abstractarray] zu machen, was uns viel Array-ähnliches Verhalten kostenlos liefert.

Für die Sequenz `Powers` besteht das entsprechende Array aus Ganzzahlen und hat 1 Dimension.
Manchmal siehst du das als `AbstractArray{Int, 1}` geschrieben, aber die Aliase `AbstractVector{Int}` für 1-D und `AbstractMatrix{Int}` für 2-D sind in neuerem Julia-Code üblicher.

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

Statt `length()` müssen wir jetzt `size()` mit einem Tupel von Längen entlang jeder Dimension definieren: in diesem Fall nur eine Dimension.

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

Wie wollen wir auf die Einträge zugreifen?
Im [Konzept für mehrdimensionale Arrays][concept-multi-dimensional-arrays] haben wir die beiden wichtigsten Ansätze vorgestellt:

- Ein Index pro Dimension, also `M[row, col]` für eine Matrix `M`.
- Ein einzelner Index, der dem Layout der Einträge im Speicher entspricht

Diese heißen jeweils `Cartesian` und `Linear`.

Im Beispiel haben wir nur eine Dimension, daher ist lineare Indexierung angebracht.

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

Beachte, dass wir in diesem Fall `iterate()` nicht definiert haben.
Julia stellt automatisch eine Standardimplementierung bereit, basierend auf unserer Definition von `getindex()`.

Es ist weiterhin möglich, unsere eigene Version von `iterate()` zu definieren, und in manchen Fällen kann sie effizienter sein.

Die Verwendung der `AbstractArray`-Schnittstelle ist besonders wertvoll, wenn wir höherdimensionale Iteration wollen.
Auf die Gefahr hin, das Beispiel über seine Grenzen hinaus zu strapazieren: Das könnte die ersten `m` Potenzen von Zahlen in `1:n` bedeuten, wodurch iterativ ein Array der Größe `(m, n)` definiert wird.

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [Rundung][ref-rounding]

In vorherigen Konzepten wurden verschiedene Arten der Rundung für numerische Typen erwähnt.

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

Die Funktion [`round()`][ref-round] ist flexibler als das: Du kannst den [`RoundingMode`][ref-roundingmode] (von den derzeit 7 unterstützten), die Anzahl der Nachkommastellen in der Ausgabe und die Zahlenbasis angeben.

Vielleicht möchten wir, dass dieselben Funktionen unsere eigenen Typen verarbeiten.
Häufig sind das zusammengesetzte Typen wie Koordinaten.

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

Wie zu erwarten gibt es eine `Rounding`-Schnittstelle, für die wir minimal `round()` für unseren Typ definieren müssen.

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

Weil wir `RoundingMode` in die Definition aufnehmen, funktionieren `floor()` und `ceil()` automatisch.

Natürlich steht es uns frei, kompliziertere Formen der Rundung zu definieren.

- Wir könnten `Point3D` auf eine ganzzahlige Entfernung vom Ursprung in derselben Richtung runden wollen.
- Für Winkel könnten wir auf die 16 Richtungen runden wollen, die Wettervorhersager verwenden (_„Wind SSW mit 15 Knoten“_), also Vielfache von π/8 Radiant.
- Wir könnten die Möglichkeit hinzufügen wollen, `digits`, `sigdigits` oder `base` anzugeben.
- Für Zeiträume gibt es [spezielle Optionen][ref-round-periods]

## Zusammenfassung

Schnittstellen sind ziemlich verwirrend zu erklären, weil der Julia-Ansatz sich so sehr von den meisten anderen Sprachen unterscheidet.
Insbesondere wird der Name der Schnittstelle in der Implementierung möglicherweise nie erwähnt: ganz anders als bei [Unterklassenbildung][wiki-subclass] oder [Mixins][wiki-mixins].

In der Praxis sind sie jedoch überraschend einfach:

1. Definiere einen geeigneten Typ und entscheide, ob Untertypisierung nützlich ist oder nicht.
2. Finde heraus, welche Methoden erforderlich sind (in der [Dokumentation][ref-interfaces]).
3. Implementiere diese Methoden für deinen eigenen Typ; normalerweise nur ein paar Methoden, und ziemlich kurz und einfach.
4. Lass [Multiple Dispatch][concept-multiple-dispatch] den Rest automatisch erledigen.
