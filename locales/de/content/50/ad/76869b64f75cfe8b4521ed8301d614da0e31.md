# Einführung

Wie im Konzept [`Nothingness`][concept-nothingness] beschrieben, hat R verschiedene Möglichkeiten, Daten darzustellen, die fehlen (`NULL`), unbekannt (`NA`) oder mathematisch ungültig (`NaN`, `Inf`) sind.
Im Allgemeinen versucht R, damit Probleme direkt an der Stelle zu kennzeichnen und weiterzumachen, ohne eine Ausnahme auszulösen.

## `stop()`

Manche Probleme sind so grundlegend, dass das Programm nicht weiterlaufen kann.
In diesem Fall beendest du das Programm mit `stop(msg)` sofort mit einem `Error` und gibst `msg` aus.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Ähnlich wie ein `assert` in anderen Sprachen ist dies ein praktischer Wrapper für `stop()`.
Die Parameter sind eine beliebige Anzahl durch Kommas getrennter boolescher Bedingungen, und das Programm läuft nur weiter, wenn alle `TRUE` sind.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `warning()` und `message()`

Sie sind Reaktionen auf nicht schwerwiegende Bedingungen, zum Beispiel:

- Um vor einem Problem zu warnen, von dem sich das Programm zumindest teilweise erholen kann.
- Um den Nutzer über den Fortschritt eines lang laufenden Programms zu informieren.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

Die Funktion `suppressWarnings()` kann innerhalb von Exercism gelegentlich nützlich sein, um den Test-Runner nicht mit unerwünschter Ausgabe zu verwirren.
