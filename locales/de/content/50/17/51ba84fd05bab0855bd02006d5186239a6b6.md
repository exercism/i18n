# Über

Swift hat viele verschiedene Typen, doch jeder dieser Typen gehört zu einer von zwei Klassifizierungen: _Werttypen_ und _Referenztypen_. In Swift sind [Strukturen Werttypen][structs-are-value-types], während [Klassen Referenztypen sind][classes-are-reference-types].

Der Hauptunterschied zwischen Werttypen und Referenztypen besteht darin, dass bei Werttypen, wenn sie einer Variablen oder Konstante zugewiesen oder an eine Funktion übergeben werden, tatsächlich eine Kopie des Werts zugewiesen oder übergeben wird, nicht der Wert selbst. Das Ändern einer Kopie einer Struktur wirkt sich nicht auf andere Kopien aus. Bei Referenztypen wird eine Referenz auf diesen Wert zugewiesen oder übergeben, sodass zwei verschiedene Namen auf dieselbe Instanz einer Klasse verweisen können. Das kann dazu führen, dass die ursprüngliche Instanz geändert wird, wenn unter einem anderen Namen auf sie zugegriffen wird.

Angenommen, wir haben die Struktur und die Klasse, die einen Charakter in einem Spiel und seine Spielstatistiken definieren. Dann können wir uns ansehen, was passiert, wenn diese Elemente kopiert und geändert werden.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

Beachte, wie sich das Ändern der Eigenschaften von `charB` auf die von `charA` ausgewirkt hat, da beide Namen auf dieselbe Instanz verweisen. Beachte außerdem, dass sich bei den Statistiken der beiden Charaktere Werttypen innerhalb eines Referenztyps in den Referenztypen ändern. Das ist jedoch kein Verstoß gegen das Verhalten von Werttypen, denn `charA.stats` ist dieselbe Instanz von `CharacterStats` wie `charB.stats`, da `charA` und `charB` auf dieselbe Instanz der Klasse `GameCharacter` verweisen. Wie wir sehen, beeinflussen sich Kopien dieser Werttypen beispielsweise nicht gegenseitig.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

Deshalb benötigen Strukturen das `mutating`-Schlüsselwort vor Methoden, die den Zustand der Eigenschaften der Struktur ändern. Das Ändern einer Eigenschaft einer Struktur erzeugt tatsächlich eine neue Kopie der Struktur mit dem neuen Wert für diese Eigenschaft, und die neue Kopie ersetzt die alte. Es ist ein visueller Hinweis darauf, dass dieses Kopieren und Ersetzen bei Werten dieses Typs stattfinden kann.

Das hat die Nebenwirkung, dass alle Instanzen von Strukturen, bei denen sich veränderliche Eigenschaften ändern, sei es durch den Aufruf mutierender Funktionen oder durch direkte Zuweisung, Variablen zugewiesen werden _müssen_, nicht Konstanten. Andernfalls erzeugt der Compiler einen Fehler:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

Die Anfangswerte können weiterhin erzeugt und abgerufen werden, aber sie dürfen sich nicht ändern. Diese Einschränkung gilt nicht für Klassen. Wenn eine Instanz einer Klasse mit `let` einem Namen zugewiesen wird, dann ist es die Referenz auf die Instanz, die die Konstante hält und die sich daher nicht ändern kann, nicht die Instanz selbst. Die Instanz selbst kann sich also ändern, aber die Referenz kann nicht geändert werden, sodass sie auf eine andere Instanz zeigt.

Eine Übersicht darüber, was sich bei Strukturen und Klassen ändern lässt, die mit `let` oder `var` definiert wurden, sieht so aus:

|         | **Struktur**                                                                                  | **Klasse**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _Kann nicht_ dem Namen eine neue Struktur zuweisen.</br>_Kann keine_ Eigenschaften der Struktur ändern. | _Kann nicht_ dem Namen eine neue Klasse zuweisen.</br>_Kann_ veränderliche Eigenschaften der Klasse ändern. |
| **var** | _Kann_ dem Namen eine neue Struktur zuweisen.</br>_Kann_ veränderliche Eigenschaften der Struktur ändern.   | _Kann_ dem Namen eine neue Klasse zuweisen.</br>_Kann_ veränderliche Eigenschaften der Klasse ändern.    |

## Identität

Da zwei verschiedene Namen eine Referenz auf dieselbe Instanz einer Klasse halten können, ist es manchmal nützlich zu prüfen, ob dies der Fall ist. Swift verwendet den _Identitätsoperator_ `===`, um dies zu prüfen (zusammen mit seiner Negation `!==`).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

Da keine zwei Namen auf dieselbe Instanz einer Struktur verweisen können, sind diese Identitätsoperatoren für Strukturen nicht definiert.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

Beachte, dass Identität nicht dasselbe ist wie Gleichheit. Nach vielen Definitionen würden `char1` und `char3` als gleich betrachtet, da alle ihre Eigenschaften dieselben Werte haben, aber sie haben nicht dieselbe Identität. Identität ist in Swift für alle Klassen automatisch verfügbar, aber Entwickler müssen normalerweise eigene Gleichheitsoperatoren schreiben, um festzustellen, ob zwei Instanzen einer Struktur oder Klasse _gleich_ sind. Dies zu tun, geht über den Rahmen dieser Übung hinaus.
