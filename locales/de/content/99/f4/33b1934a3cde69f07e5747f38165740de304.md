# Einführung

Literale sind feste Werte, die direkt im Code verwendet werden.
Sie benötigen zur Laufzeit keine Berechnung.
Sie kommen in verschiedenen Formen vor, um unterschiedliche Datentypen effizient darzustellen.
Die häufigsten Literale sind numerischer Natur, aber es gibt auch literale Operatoren für Datums-, Zeit- und String-Typen.
Ein späteres Konzept zeigt, wie benutzerdefinierte literale Operatoren verwendet werden können.

## Numerische Literale

Numerische Literale umfassen dezimale, oktale, hexadezimale und binäre Darstellungen.
Diese Grundlagen wurden bereits im [Konzept Zahlen][numbers-concept] behandelt.

Alle Darstellungen wie `23`, `0x50f7ba11` und `0xba5eba11` werden vom Compiler als `int` verstanden.
Der allgemeine Typ `int` ist vorzeichenbehaftet und hat ([je nach Compiler und System][in-depth-integers]) oft einen Wertebereich von `-2'147'483'648` bis `2'147'483'647`.
Das reicht meistens aus, und du musst dir keine Gedanken über den konkreten Typ machen.

Manche Anwendungsfälle verlangen größere Wertebereiche oder einen sehr geringen Speicherbedarf von Programmen.
Um es explizit zu machen, kann man mit dem numerischen Literal direkt bestimmte Ganzzahltypen angeben.

Wenn keine negativen Zahlen benötigt werden, aber der zusätzliche Wertebereich erwünscht ist, verwendet man das Suffix `u` oder `U` für _vorzeichenlose_ Ganzzahlen.
Für größere Wertebereiche kann `L` oder sogar `LL` für die Typen long und long long verwendet werden.

~~~~exercism/caution
Die Verwendung von kleingeschriebenem `l` ist erlaubt, aber es wird leicht mit der Zahl `1` verwechselt und ist deshalb nicht zu empfehlen.
~~~~

```cpp
auto net_worth_christian_grey{2'500'000'000U}; // out of range for 32-bit integers
auto net_worth_carlisle_cullen{46'000'000'000LL}; // int and uint are not enough
```

Gleitkommazahlen ergeben bei der Kompilierung normalerweise `double`.
Das ist ein guter Standardfall, und Anwendungsfälle mit dem schmaleren Typ `float` sind seltener als das vorzeichenlose Beispiel oben.

~~~~exercism/advanced
Der [C++23-Standard][cpp23-literals] führt eine feinere Steuerung mit Literalen wie `f128` oder `F16` ein.
Manche Compiler erlauben eigene Literale.
GCC erlaubt die Verwendung von `d` als Literal, aber das ist im Standard nicht vorgesehen und kann die plattformübergreifende Kompatibilität beeinträchtigen.

[cpp23-literals]: https://en.cppreference.com/w/cpp/language/floating_literal

~~~~

```cpp
auto light_year_in_m{9.46073e+15f}; // well in the range of float
auto earth_to_edge_comoving_distance_in_nm{4.32355e+32}; // needs double type for magnitude
auto eulers_number{2.718281828459045}; // needs double type for precision
```

## Zeichen- und String-Literale

Andere Konzepte haben bereits Zeichenliterale mit einfachen Anführungszeichen wie `'}'` oder `'@'` verwendet.

In C++ ist `char` auf die ersten 128 [ASCII-Zeichencodes][ascii-code] beschränkt.
Um mehrere ASCII-Zeichen oder erweiterte ASCII-Zeichen wie `‰` oder sogar Unicode-Zeichen wie `麗` und `ẞ` zu verwenden, werden andere Typen benötigt.
In einem früheren Konzept wurden String-Literale mit _doppelten Anführungszeichen_ eingeführt: `"一体どういう意味ですか。C++です"`.
Der tatsächliche Typ dieses japanischen Satzes ist `const char (&)[46]`, ein C-String.

Die Verwendung von String-Literalen ist nicht standardmäßig aktiviert.
Um das _String_-Literal `""s` oder das _String-View_-Literal `""sv` zu verwenden, muss man ihre Verwendung über den zugehörigen Namensraum angeben:

```cpp
#include <string>
#include <string_view>

using namespace std::literals;

auto green_light{"무궁화 꽃 이 피었 습니다"};
// green_light type is const char (&)[36]
auto umbrella{"달고나"s};
// umbrella type is std::basic_string<char>, the same as std::string
auto il_nam{"보는 것이 하는 것보다 더 재미있을 수가 없지"sv};
// il_nam type is std::basic_string_view<char>
```

Ein _String-View_ kann als Referenz auf einen konstanten String gesehen werden.
