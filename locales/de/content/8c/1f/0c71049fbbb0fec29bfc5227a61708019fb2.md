# Ergänzung der Anweisungen

## Implementierung

Bevor du loslegst, stelle sicher, dass du weißt, wie du Code schreibst, der die Testfälle besteht.
Mehr Hintergrund findest du in diesem [Tutorial].

Die meisten Java-Übungen enthalten mehrere Testfälle.
Diese Fälle sind so aufgebaut, dass sie einen nützlichen Prozess unterstützen, der als [testgetriebene Entwicklung (TDD)][tdd] bekannt ist.
TDD bedeutet, einen strukturierten Zyklus zu wiederholen, der Programmierenden hilft, komplexe Funktionalität Stück für Stück aufzubauen statt auf einmal.
Dieser Zyklus lässt sich wie folgt beschreiben:

1. Füge einen Test hinzu, der einen Teil der gewünschten Funktionalität beschreibt, der in deinem Code gerade noch fehlt.
2. Führe die Tests aus, um zu prüfen, dass dieser neu hinzugefügte Test fehlschlägt.
3. Aktualisiere deinen vorhandenen Code, bis:
    - alle alten Tests weiterhin bestehen;
    - auch der neue Test besteht.
4. [Räum deinen Code auf][refactoring] und stelle dabei sicher, dass alle Tests weiterhin bestehen.
   Dazu gehört typischerweise das Umbenennen von Variablen, das Entfernen doppelter Logikblöcke, das Entfernen übrig gebliebener Logging-Ausgaben usw.
5. Kehre zu Schritt 1 zurück, bis die gesamte gewünschte Funktionalität aufgebaut ist!

Die Testdateien in diesem Track enthalten _alle_ Tests, die deine Lösung bestehen muss, um als gültig zu gelten.
Das scheint zunächst nicht mit dem oben beschriebenen Zyklus vereinbar zu sein, in dem Tests einzeln geschrieben werden.
Das Tool, mit dem wir unsere Tests schreiben, [JUnit][junit], bietet jedoch eine [@Disabled][junit-disabled]-[Annotation][java-annotation], mit der du einen bereits geschriebenen Test vorübergehend überspringen kannst.
Mit dieser Annotation stellen wir sicher, dass die Testdateien, die wir dir liefern, die folgenden Regeln erfüllen:

- Der erste Test in einer Testdatei wird standardmäßig _nicht_ übersprungen.
- Alle Tests außer dem ersten in einer Testdatei _werden_ standardmäßig übersprungen.

So kannst du den TDD-Zyklus simulieren, indem du diese leicht abgewandelten Schritte befolgst:

1. Führe die Tests aus, um zu prüfen, dass derzeit _höchstens ein_ Test fehlschlägt.
2. Aktualisiere deinen vorhandenen Code, bis alle nicht übersprungenen Tests bestehen.
3. Räume deinen Code auf und stelle sicher, dass alle nicht übersprungenen Tests weiterhin bestehen.
4. Entferne die oberste `@Disabled`-Annotation in der Testdatei.
5. Kehre zu Schritt 1 zurück, bis keine Tests mehr übersprungen werden und alle Tests bestehen!
