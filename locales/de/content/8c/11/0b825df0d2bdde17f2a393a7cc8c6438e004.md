# Einführung in Befehle und Argumente

In diesem Track geht es nicht darum, wie du bash als interaktive Shell verwendest.
Es geht darum, zu lernen, Programme mit bash zu schreiben, der Programmiersprache.

Ein bash-Programm, oder _Skript_, ist eine Folge von Befehlen, die in einer Datei gespeichert sind.
bash (die ausführbare Datei) liest die Datei und führt die Befehle der Reihe nach aus.

## Der Shebang

Die erste Zeile eines Skripts ist normalerweise eine _Interpreter-Direktive_, auch bekannt als _Hashbang_ oder _Shebang_:

```bash
#!/usr/bin/env bash
```

Wenn das Betriebssystem eine nicht-binäre Datei ausführt, liest es die erste Zeile.
Beginnt die Zeile mit `#!`, verwendet der Kernel sie, um zu bestimmen, welcher Interpreter die Datei ausführen soll.
Das `#!` muss ganz am Anfang der Datei stehen, ohne Leerzeichen oder leere Zeilen davor.

Hier durchsucht `env` die Variable `PATH` nach der ausführbaren Datei `bash`.
Du siehst vielleicht auch die einfachere Form `#!/bin/bash`, die den Speicherort des Interpreters fest vorgibt; die `env`-Form ist portabler.

~~~~exercism/note
Lass dich nicht von Skripten oder Beispielen im Internet täuschen, die `/bin/sh` als Interpreter verwenden.
**`sh` ist nicht `bash`!**
Bash ist „sh-kompatibel“ und kann die meisten `sh`-Skripte ausführen, aber einige bash-Funktionen brechen in `sh` oder verhalten sich unerwartet.
~~~~

## Kommentare

Eine Zeile, die mit `#` beginnt, ist ein _Kommentar_, und bash ignoriert sie.
Ein Kommentar kann auch in derselben Zeile hinter einem Befehl stehen: alles vom `#` bis zum Zeilenende wird ignoriert.
Kommentare sind für die Menschen gedacht, die das Skript lesen.

## Wörter und Argumente

Bash liest Befehle aus ihrer Eingabe (meistens entweder ein Terminal oder eine Datei).
Jede Eingabezeile, die sie liest, wird als _Befehl_ behandelt, also als eine Anweisung, die ausgeführt werden soll.
(Es gibt ein paar fortgeschrittene Fälle, etwa Befehle, die sich über mehrere Zeilen erstrecken, die später besprochen werden.)

Bash teilt jeden Befehl in **Wörter** auf, die durch Whitespace-Zeichen (Leerzeichen und Tabs) abgegrenzt werden.
Das erste Wort ist der Name des _Befehls_, der ausgeführt werden soll.
Alle übrigen Wörter werden zu _Argumenten_ für diesen Befehl (Optionen, Dateinamen usw.).

Ein Befehl kann ein bash-_Builtin_ sein, etwa `echo`, oder ein _ausführbares_ Programm wie `head`, `awk` oder `sed`.

## Der Befehl `echo`

`echo` gibt seine Argumente aus, getrennt durch ein einzelnes Leerzeichen, und beendet die Ausgabe mit einem Zeilenumbruch:

```bash
echo flour sugar eggs
```

gibt aus:

```text
flour sugar eggs
```

Die Menge an Whitespace zwischen den Argumenten spielt keine Rolle:

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

Rufst du `echo` ohne Argumente auf, wird eine leere Zeile ausgegeben.

## Optionen sind einfach Argumente

Viele Befehle akzeptieren _Optionen_, die ihr Verhalten ändern.
Für bash ist eine Option nichts Besonderes: Sie ist ein Wort wie jedes andere, durch Whitespace von seinen Nachbarn getrennt.
Der Befehl selbst entscheidet, wie er seine Argumente interpretiert.
Üblicherweise beginnen Optionen mit einem `-`.

Der Befehl `head` gibt die ersten Zeilen einer Datei aus.
Gegeben sei eine Datei `list.txt`:

```bash
head -n 2 list.txt
```

Bash teilt diese Zeile in vier Wörter auf:

| Wort       | Rolle                                               |
| ---------- | --------------------------------------------------- |
| `head`     | der auszuführende Befehl                            |
| `-n`       | eine Option, die `head` anweist, _Zeilen_ zu zählen |
| `2`        | der Wert für die Option `-n`                        |
| `list.txt` | die zu lesende Datei                                |

Bash übergibt die letzten drei Wörter unverändert an `head`.
`head` ist es, das versteht, dass auf `-n` eine Zahl folgt und dass das verbleibende Wort eine Datei ist.

Weil der Whitespace die Wörter trennt, kommt es darauf an, wo du ihn setzt.
`head -n 2` gibt `head` zwei Argumente (`-n` und `2`), während `head -n2` ihm nur eins gibt (`-n2`).
Viele Befehle akzeptieren beide Formen, aber das entscheidet der jeweilige Befehl.
Bash ist das egal; sie teilt die Zeile nur in Wörter auf.

## Argumente in Anführungszeichen setzen

[Anführungszeichen][Quotes] fassen Wörter zu einem _einzigen Argument_ zusammen.
Whitespace innerhalb der Anführungszeichen bleibt erhalten, und die Anführungszeichen selbst sind nicht Teil des Arguments:

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

Wenn ein Argument wie ein Dateiname Whitespace enthält, setze es in Anführungszeichen:

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## Ein Skript ausführen

Um ein Skript auszuführen, übergib es als Argument an den Befehl `bash`:

```bash
bash myscript
```

So verwendet, ist die `#!`-Zeile nur ein Kommentar.
Du sagst damit dem Betriebssystem, wie es die Datei ausführen soll.

Alternativ kannst du die Skriptdatei als ausführbar markieren und sie wie jedes andere Programm starten:

```bash
chmod +x myscript
./myscript
```

Jetzt verwendet das Betriebssystem die `#!`-Zeile, um zu bestimmen, welcher Interpreter verwendet werden soll.
