# Anleitung

Du arbeitest an einem System, das den Anmeldeprozess für das Netzwerk deiner Organisation vereinfachen soll. Die Aufgaben betreffen den Authentifizierungsteil. Das System nutzt Gesichtserkennung, um die Identität nachzuweisen.

In allen Fällen ist garantiert, dass der Parameter für die Augenfarbe nicht null ist.

## 1. Stelle sicher, dass die Gesichtsmerkmale übereinstimmen

Implementiere `Authenticator.AreSameFace()`, um zu prüfen, ob zwei Gesichter übereinstimmen.

Füge Gleichheitsroutinen für die Klasse `FacialFeatures` hinzu.

```csharp
Authenticator.AreSameFace(new FacialFeatures("green", 0.9m), new FacialFeatures("green", 0.9m);
// => true
Authenticator.AreSameFace(new FacialFeatures("blue", 0.9m), new FacialFeatures("green", 0.9m);
// => false
```

## 2. Authentifiziere den Systemadministrator

Trotz deiner Einwände besteht der Systemadministrator darauf, während der Abnahmetests eine fest eingebaute Identität zu haben, damit er immer authentifiziert werden kann.

Die E-Mail-Adresse des Admins ist admin@exerc.ism. Er hat grüne Augen und ein Philtrum mit einer Breite von 0,9.

Füge Gleichheitsroutinen für die Klasse `Identity` hinzu.

Implementiere die Methode `Authenticator.IsAdmin()`, um zu prüfen, ob die übergebene Identität mit der des Administrators übereinstimmt.

```csharp
var authenticator = new Authenticator();
authenticator.IsAdmin(new Identity("admin@exerc.ism", new FacialFeatures("green", 0.9m)));
// => true
authenticator.IsAdmin(new Identity("admin@thecompetition.com", new FacialFeatures("green", 0.9m)));
// => false
```

## 3. Registriere neue Identitäten

Implementiere die Methode `Authenticator.Register()`, die eine Identität im Authenticator selbst speichert, sodass Aufrufe von `IsRegistered()` für diese Identität `true` zurückgeben: andernfalls gibt `IsRegistered()` `false` zurück.

Um doppelte Versuche zu erkennen, eine Identität zu registrieren, gilt: Wenn die Identität bereits registriert wurde, gibt `Authenticator.Register()` `false` zurück, andernfalls `true`.

```csharp
var authenticator = new Authenticator();
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.IsRegistered(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => false
```

## 4. Verhindere, dass ungültige Identitäten authentifiziert werden

Implementiere die Methode `Authenticator.IsRegistered()` und stelle sicher, dass sie false zurückgibt, wenn keine Identitäten registriert wurden.

```csharp
var authenticator = new Authenticator();
authenticator.IsRegistered(new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.8m)));
// => false
```

## 5. Füge Diagnosen hinzu, um mehrere Authentifizierungsversuche zu erkennen

Es wurde ein Bug gemeldet, bei dem die Methode `Authenticator.IsRegistered()` für dieselbe Identität mehrmals kurz hintereinander aufgerufen wird. Du vermutest, dass es irgendein „Bounce“-Problem gibt, bei dem genau derselbe Datensatz mehrfach übermittelt wird. Deine Aufgabe ist es, eine Diagnoseroutine `Authenticator.AreSameObject()` hinzuzufügen, um alle Tests zu unterstützen, die durchgeführt werden. Die Routine vergleicht zwei Objekte und gibt `true` zurück, wenn es sich um dieselbe Instanz handelt, andernfalls `false`.

```csharp
var identityA = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityB = identityA;
Authenticator.AreSameObject(identityA, identityB);
// => true

var identityC = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityD = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
Authenticator.AreSameObject(identityC, identityD);
// => false
```
