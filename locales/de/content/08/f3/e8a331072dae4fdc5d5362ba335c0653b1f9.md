# Tests

So führst du die Tests aus:

```bash
$ wrenc exercise-name.spec.wren
```

Zum Beispiel für `hello-world`:

```bash
$ wrenc hello-world.spec.wren
```


## Skip-Tests verstehen

Die Methode `skip` weist die Testsuite an, einen bestimmten Test nicht auszuführen.

- Warum werden sie übersprungen?

Damit sich die Nutzer auf einen Test nach dem anderen konzentrieren können und sie einen nach dem anderen aktivieren, während sie ihre Lösung weiterentwickeln.

- Wie aktiviert man sie?

Ein übersprungener Test:

```js
// this test will be skipped and not run
skip.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

Ändere einfach `skip.test` in `do.test`.

```js
// now the test will be run normally
do.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

## Dein erstes Wren-Modul erstellen

Die Tests in diesem Track laden deine Implementierung, indem sie sie als Wren-Modul importieren: `import "./bob" for Bob`. Es gibt keine besondere Syntax, um deine Implementierung zu exportieren. Nenne deine Klasse einfach `Bob`, damit sie zu den Import-Anweisungen `for Bob` passt, und alles sollte einfach funktionieren.

```javascript
class Bob {
  static hey(message) {
    // Your solution to the exercise goes here
  }
}
```

Mehr Informationen über Module findest du in der [Wren-Dokumentation zur Modularität][modularity].
Damit du leichter loslegen kannst, gibt es im Verzeichnis jeder Übung eine _Skeleton_-Wren-Datei.

[modularity]: https://wren.io/modularity.html
