# Einführung

Python ist eine [dynamisch und stark typisierte][dynamic typing in python] Programmiersprache.
Sie nutzt sowohl [Duck-Typing][duck typing] als auch [graduelle Typisierung][gradual typing], und zwar über [Type Hints][type hints].
Python legt großen Wert auf die Lesbarkeit des Codes und verwendet (_ähnlich wie Haskell_) [signifikante Einrückung][significant indentation], um Funktions-, Methoden- und Klassendefinitionen zu kennzeichnen.

Python wurde von Guido van Rossum entwickelt und 1991 erstmals veröffentlicht.

Imperative, deklarative (z. B. funktionale) und objektorientierte Programmier_stile_ werden alle unterstützt, aber intern ist **[in Python alles ein Objekt][everythings an object]**.

Wir gehen später genauer darauf ein, was das alles bedeutet, wenn wir im weiteren Verlauf die Konzepte des Python-Tracks durchgehen.

Dieses erste Konzept (`basics`) stellt 4 wichtige Sprachmerkmale von Python vor:
1.  Zuweisung von Namen (_Variablen und Konstanten_),
2.  Funktionen (_das Schlüsselwort `def` und das Schlüsselwort `return`_),
3.  Kommentare und
4.  Docstrings.

<br>

## Zuweisung von Namen (Variablen und Konstanten)

Programmierer können [_Namen_][facts-and-myths-about-python-names] (auch _Variablen_ genannt) mit dem Zuweisungsoperator `=` an jeden beliebigen Objekttyp binden: `<name> = <value>`.
Ein Name kann während seiner Lebensdauer neu zugewiesen (oder neu gebunden) werden, an verschiedene Werte (verschiedene Objekttypen):


```python
>>> my_first_variable = 1  # <--my_first_variable bound to an integer object of value one.
>>> my_first_variable = 2  # <--my_first_variable re-assigned to integer value 2.

>>> print(type(my_first_variable))
<class 'int'>

>>> print(my_first_variable)
2

>>> my_first_variable = "Now, I'm a string." # <--You may re-bind a name to a different object type and value.
>>> print(type(my_first_variable))
<class 'str'>

>>> my_first_variable = 'You can call me "str".' # <--Strings can be declared using single or double quote marks.
>>> print(my_first_variable)
You can call me "str".
```


### Konstanten

Konstanten sind Namen, die in einem Programm nur einmal zugewiesen werden sollen, obwohl Python eine erneute Zuweisung nicht verhindert.
Die Verwendung von `SCREAMING_SNAKE_CASE` signalisiert jedem, der den Code liest, dass der Name **nicht** neu zugewiesen oder sein Wert verändert werden sollte.
Konstanten sollten auf der Ebene eines [Moduls][module] (einer Datei) definiert werden und sind typischerweise für alle Funktionen und Klassen in einem Programm sichtbar.



## Funktionen

Das Schlüsselwort `def` leitet eine [Funktionsdefinition][function definition] ein.
Jede Funktion kann null oder mehr formale [Parameter][parameters] in `()` runden Klammern haben, gefolgt von einem `:` Doppelpunkt.
Die Anweisungen für den _Rumpf_ der Funktion beginnen in der Zeile nach `def` und müssen _in einem Block eingerückt_ sein.


```python
# The body of this function is indented by 2 spaces & prints the sum of the numbers.
def add_two_numbers(number_one, number_two):
  total = number_one + number_two
  print(total)  

>>> add_two_numbers(3, 4)
7


# Inconsistent indentation in your code blocks will raise an error.
>>> def add_three_numbers_misformatted(number_one, number_two, number_three):
...     result = number_one + number_two + number_three   # This was indented by 4 spaces.
...    print(result)     # <--This was only indented by 3 spaces.
...
...
  File "<stdin>", line 3
    print(result)
    ^
IndentationError: unindent does not match any outer indentation level
```


Funktionen geben einen Wert oder ein Objekt _explizit_ über das Schlüsselwort [`return`][return] zurück:


```python
# Function definition on first line, explicit return used on final line.
def add_two_numbers(number_one, number_two):
  return number_one + number_two   


# Calling the function in the Python shell returns the sum of the numbers.
>>> add_two_numbers(3, 4)
7

# Assigning the function call to a variable and printing 
# the variable will also return the value.
>>> sum_with_return = add_two_numbers(5, 6)
>>> print(sum_with_return)
11
```


Funktionen, auf deren `return` kein _expliziter_ Ausdruck folgt, geben _implizit_ das [`None`][none]-Objekt zurück.
Die Details von `None` werden in einem späteren Konzept behandelt.
Für diese Übung und Erklärung ist `None` ein Platzhalter, der nichts oder null darstellt:


```python
# This function will return `None`
def square_a_number(number):
    square = number * number
    return # <-- note that this return is not followed by an expression

# Calling the function in the Python shell appears 
# to not return anything at all.
>>> square_a_number(2)
>>>


# Using print() with the function call shows that 
# the function is actually returning the **None** object.
>>> print(square_a_number(2))
None
```

Funktionen, die `return` weglassen, geben ebenfalls _implizit_ das [`None`][none]-Objekt zurück.
Das heißt, wenn du `return` in einer Funktion nicht verwendest, gibt Python für dich das `None`-Objekt zurück.

```python
# This function omits a return keyword altogether.
def add_two_numbers(number_one, number_two):
  result = number_one + number_two

>>> add_two_numbers(5, 7)
>>> print(add_two_numbers(5, 7))
None

# Assigning the function call to a variable and printing 
# the variable will also show None.
>>> sum_without_return = add_two_numbers(5, 6)
>>> print(sum_without_return)
None
```


## Kommentare

[Kommentare][comments] in Python beginnen mit einem `#`, das nicht Teil eines Strings ist, und enden am Zeilenende.
Anders als viele andere Programmiersprachen **unterstützt** Python **keine** mehrzeiligen Kommentarzeichen.
Jede Zeile eines Kommentarblocks muss mit dem Zeichen `#` beginnen.


## Docstrings

Die erste Anweisung eines Funktionsrumpfs kann optional ein [_Docstring_][docstring] sein, der den Zweck der Funktion oder des Objekts kurz zusammenfasst.
Docstrings werden von automatisierten Dokumentationswerkzeugen wie [Sphinx][sphinx] gelesen und durch Aufrufen des speziellen Attributs `.__doc__` auf dem Funktions-, Methoden- oder Klassennamen zurückgegeben.
Allgemeine Konventionen für Docstrings sind in [PEP257][pep257] festgehalten, aber die genauen Formate unterscheiden sich je nach Projekt und Team.
Docstrings werden mit dreifachen doppelten Anführungszeichen (""") deklariert, eingerückt auf derselben Ebene wie der Block:


```python
# An example from PEP257 of a multi-line docstring

# https://www.sphinx-doc.org/en/master/usage/extensions/napoleon.html#getting-started

    """Form a complex number.

    Keyword Arguments:
        real (float): The real part of the number (default 0.0)
        imag (float): The imaginary part of the number (default 0.0)
```
