# Verträge

Die Argumente und der Rückgabetyp einer Routine sagen, von welcher *Art* das ist, was hineingeht und herauskommt. Sie können nicht sagen, dass ein Gewicht positiv sein muss oder dass ein Test-Harness nie mehr freie Kapazität meldet, als es hat.

Ein **Vertrag** sagt genau das, direkt im Kopf der Routine, wo sie jeder sehen kann, der sie liest.

## pre

`pre` legt fest, was wahr sein muss, wenn die Routine aufgerufen wird. Es steht zwischen dem Rückgabetyp und dem `is`.

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

Das ist eine Forderung an den **Aufrufer**: Rufe sie nicht mit einem negativen load auf.

## post

`post` legt fest, was wahr sein wird, wenn die Routine antwortet. Darin ist `result` der Wert, der zurückgegeben wird.

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

Das ist ein Versprechen an den Aufrufer. Eine Routine mit beidem ist ein Handel: Gib mir das, und ich gebe dir das.

Mehrere Bedingungen werden mit `and` verknüpft, wie es bei beliebigen booleschen Werten üblich ist:

```sather
      pre load >= 0 and load <= limit
```

## Verträge sind keine Ausnahmen

Eine ausgelöste Ausnahme steht für etwas, das passieren kann. Ein gebrochener Vertrag bedeutet einen **Bug**: Jemand hat die Routine falsch aufgerufen, oder die Routine hat nicht getan, was sie versprochen hat.

Ein gebrochener Vertrag löst also nichts aus, was sich abfangen lässt. Wenn die Vertragsprüfung eingeschaltet ist, hält das Programm an und gibt aus, welche Routine und welche Bedingung betroffen ist. Ist sie ausgeschaltet, wird die Bedingung nicht einmal geprüft, und das Programm läuft weiter, hinein in was auch immer für einen Unsinn folgt.

Deshalb ist ein Vertrag eine Aussage über Korrektheit und nicht ein Weg, mit schlechten Eingaben umzugehen. Wenn schlechte Eingaben erwartet werden, prüfe sie und löse `raise` aus. Wenn schlechte Eingaben bedeuten, dass der Aufrufer fehlerhaft ist, sag es mit `pre`.

## Die Prüfung einschalten

Dieses Sather prüft Verträge, wenn dem Compiler `-chk` übergeben wird:

```
sacomp -chk mine.sa -main MAIN -o mine
```

Ohne das sind `pre` und `post` Dokumentation, die der Compiler gelesen und als wohlgeformt akzeptiert hat, und nichts weiter. Die Tests für diese Übung werden ohne `-chk` gebaut, sie können einen gebrochenen Vertrag also nicht für dich abfangen; sie prüfen, dass die Routinen das Richtige tun, wenn man sie richtig verwendet.
