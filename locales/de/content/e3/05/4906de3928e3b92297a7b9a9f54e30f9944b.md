# Hinweise

Eine häufige Verwendung von `Either` ist es, eine Berechnung anzugeben, die möglicherweise zu einem Fehler führt (wenn der tatsächliche Fehler nicht von Interesse ist, ist der einfachere Typ `Option` vielleicht die bessere Wahl). Wenn kein Fehler vorliegt, ist das Ergebnis normalerweise ein `Right` (Eselsbrücke: der „richtige“ Wert), während ein Fehler ein `Left` ist, zum Beispiel ein `Left[String]`, das eine Fehlermeldung enthält.

Beachte, dass `Either` in Scala 2.12 standardmäßig nach rechts ausgerichtet ist, sodass es für Operationen wie `filter`, `map`, `flatMap` oder in einer For-Comprehension wie erwartet funktioniert.

Wenn dir `Either` nicht vertraut ist, kannst du [dieses Tutorial](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html) lesen. Beachte aber, dass dieses Tutorial Scala-Versionen vor 2.12 behandelt. In Scala 2.12 kannst du `RightProjection` getrost ignorieren und `.right` weglassen.

`Either` ist eine sogenannte [Monade](https://en.wikipedia.org/wiki/Monad_(functional_programming)), die einen „Berechnungsaspekt“ abdeckt, in diesem Fall die Fehlerbehandlung.
Der richtige Einsatz von Monaden kann zu sehr prägnantem, aber elegantem
und lesbarem Code führen. Falscher Einsatz kann leicht das Gegenteil bewirken.
Sieh dir [dieses Video](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) an, um mehr zu erfahren.

## Häufige Fallstricke, die du vermeiden solltest

Für `Either` gibt es ein paar Faustregeln:

1. Wenn du es nicht brauchst, verwende es nicht. Statt

```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```

besser

```scala
def add1(x: Int): Int = x + 1
```

(es gibt `Either.map`, um solche einfachen Funktionen anzuwenden,
damit du sie nicht mit `Either` überladen musst).

2. Packe nichts aus, wenn du es wirklich nicht musst.
Oft gibt es eingebaute Funktionen für deinen Zweck. Hinweise auf vorzeitiges
Auspacken sind `isLeft/isRight` oder Pattern Matching. Zum Beispiel statt

```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```

besser

```scala
x fold (identity, _ + 1)
```

3. Monaden lassen sich großartig in einer For-Comprehension verwenden.
Das ist ratsam, wenn du mehrere `Either`-Instanzen „zusammensetzen“ möchtest. Statt

```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```

besser

```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
