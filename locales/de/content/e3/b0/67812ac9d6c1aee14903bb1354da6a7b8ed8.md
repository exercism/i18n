# Über

Factors einzige Konvention für die Datenübergabe ist der *Daten-Stack*: Wörter nehmen ihre Eingabewerte vom Stack und legen ihre Ausgabewerte dort wieder ab. Jede Wortdefinition deklariert einen *Stack-Effekt*, der diesen Vertrag dokumentiert.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

Die Namen in `( … -- … )` dienen nur der Lesbarkeit; der Compiler prüft allein die *Anzahl* von Ein- und Ausgabewerten. Ein Missverhältnis ist ein Fehler zur Kompilierzeit. Das fängt eine Klasse von Fehlern ab, die in einer dynamisch typisierten Sprache ohne solche Angaben erst zur Laufzeit auffallen würde.

Weil der Stack positionsabhängig ist, musst du ständig seine obersten Werte umsortieren, bevor das nächste Wort ausgeführt werden kann. Genau das machen die **Shuffle-Wörter** aus `kernel`:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

Die vollständige Shuffle-Familie erweitert sie um `-rot` (rollt in die andere Richtung), die Cousins mit `d`-Suffix, die ein Element tiefer wirken (`dupd`, `swapd`), die Cousins mit der Vorsilbe `2`, die auf Paaren arbeiten (`2dup`, `2drop`, `2nip`), und weitere wie `pick` und `tuck`. Sie kommen erst ins Spiel, wenn spätere Übungen sie brauchen; zu viele Shuffle-Wörter auf einmal sind meist ein Zeichen dafür, dass ein *Local* (ein benannter Wert) besser lesbar wäre.

Nach Konvention schreibt man Wörter in `lowercase-kebab-case`, Prädikate enden auf `?` und liefern einen booleschen Wert (`even?`, `empty?`), Setter schreibt man `>>name` und Getter `name>>`, und ein Wort und seine mutierende Variante teilen sich oft denselben Namen und unterscheiden sich nur durch den Kontext.
