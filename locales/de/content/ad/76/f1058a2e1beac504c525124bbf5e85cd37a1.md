# Einführung

Alle Daten in Assembly sind eine Folge von Bytes.
Das bedeutet, dass jede Datenmenge als **Array** dieser zugrunde liegenden Bytes betrachtet werden kann.

## Zugriff auf Elemente in einem Array

Um einen beliebigen Wert im Speicher zu erreichen, muss seine **effektive Adresse** berechnet werden.
Eine effektive Adresse ist ein Ausdruck, der aus Folgendem bestehen kann:

- einer _Basisadresse_, zum Beispiel der, die durch das Label einer Variable angegeben wird.
- einem _Indexregister_, eventuell skaliert mit `1`, `2`, `4` oder `8`.
- einem vorzeichenbehafteten 32-Bit-_Displacement_, also einer Zahl, die zur Basisadresse addiert (oder von ihr subtrahiert) wird.

Beachte, dass diese Adresse _0-indiziert_ ist, sodass eine Basisadresse ohne Offset auf das erste Byte einer Variable zeigt.
Deshalb liefert das Dereferenzieren von Speicher allein über ein Label ohne Offset, wie wir es in früheren Konzepten getan haben, einen Wert, der bei seinem ersten Byte beginnt:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 ist [Little Endian][endianness].
Das bedeutet, dass das niederwertigste Byte eines Multibyte-Werts an der kleinsten Speicheradresse gespeichert wird.

Wenn du also auf die einzelnen Bytes eines Multibyte-Werts zugreifst, musst du einen positiven Offset zur Basisadresse addieren, um höherwertige Bytes zu erreichen.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

Eine initialisierte Variable, die mit einer Liste von Werten deklariert wird, ist ein Array dieser Werte, wobei jedes Element die angegebene Größe hat.
Offsets beziehen sich jedoch immer auf **_Bytes_**, auch wenn jedes Element im Array eine größere Größe hat:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

Beachte, dass du, da sich Adressen auf Bytes beziehen, direkt auf ein einzelnes Byte eines beliebigen Elements in einem Array zugreifen kannst:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

Aus demselben Grund kannst du mit einer einzigen Anweisung auf mehr zugreifen, als die Größe eines Elements beträgt:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
Assembly führt keine Grenzprüfung bei Array-Zugriffen durch.
Ein Index hinter dem Ende eines Arrays liest oder schreibt Speicher außerhalb des Arrays.
Das kann zu stillschweigend falschen Ergebnissen, zur Beschädigung anderer Daten und, wenn der zugegriffene Speicher nicht gemappt ist, zu einem Laufzeitfehler führen.
Du bist dafür verantwortlich, dass jede effektive Adresse innerhalb des Arrays bleibt.
~~~~

## Die Größe eines initialisierten Arrays berechnen

NASM (The Netwide Assembler, der von diesem Track verwendete Assembler) hat ein spezielles Symbol (`$`), das die aktuelle Position im Speicher angibt.
Dieses Symbol bietet eine bequeme Möglichkeit, die Gesamtgröße zu berechnen, die ein Array im Speicher einnimmt:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

Direkt nach `example` verwendet, hat `$` die Speicheradresse für das Ende des Arrays.
Das bedeutet, dass `$ - example` die Differenz zwischen dieser Adresse und derjenigen ist, auf die das Label `example` zeigt.
Das ist genau die Gesamtgröße in Bytes, die das Array einnimmt, auf das `example` zeigt.

Indem wir `example_length` mit diesem Wert definieren, haben wir also eine 8-Byte-Variable erstellt, die die Größe bzw. Länge des Arrays in Bytes speichert.

## Section .bss

Nicht initialisierte Daten werden in der **section .bss** deklariert.
Auf den meisten Plattformen werden diese Daten vom Betriebssystem beim Start des Programms mit Null gefüllt.

In NASM hat eine nicht initialisierte Variable einen Namen, eine Direktive, die die Datengröße angibt, und die Anzahl der zu reservierenden Elemente.
Jedes davon wird durch ein Leerzeichen von den anderen getrennt.

Die wichtigsten Direktiven und ihre zugehörigen Datengrößen sind:

| Direktive | Größe   |
| :-------: | :------ |
|   resb    | 1 Byte  |
|   resw    | 2 Bytes |
|   resd    | 4 Bytes |
|   resq    | 8 Bytes |

Das folgende Beispiel reserviert beispielsweise nicht initialisierten Speicher für `3` Bytes in einer Variable namens `example`:

```x86asm
section .bss
    example resb 3
```

Und dies reserviert nicht initialisierten Speicher für `10` mal `8` Bytes (also `80` Bytes) in einer Variable namens `arr`:

```x86asm
section .bss
    arr resq 10
```

Variablen in `section .bss` sind veränderbar, d. h. sie sind les- und schreibbar.

Auf nicht initialisierte Daten kann auf dieselbe Weise zugegriffen werden wie auf initialisierte Daten, nämlich über ihre effektive Adresse.
Ebenso haben sie eine statische Speicherdauer und sind aus jeder Funktion in derselben Quelldatei zugänglich (und, wenn sie als `global` deklariert sind, auch in anderen Quelldateien).

## Array-Adressen mit der Lea-Anweisung ermitteln

Wie in einem früheren Konzept behandelt, berechnet die `lea`-Anweisung eine effektive Speicheradresse.
Sie kann verwendet werden, um die Adresse eines beliebigen Elements in einem Array zu berechnen, wobei dieselbe Semantik gilt.

Beachte, dass es bei relativer Adressierung oft nötig ist, die Adresse der Variable in ein Register zu laden, bevor eine komplexere Adresse gebildet wird:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
Einer der Vorteile von `lea` ist, dass es Adressberechnungsarithmetik verwendet, um einen Wert zu berechnen, ohne tatsächlich auf den Speicher an dieser Adresse zuzugreifen.
Dadurch ist es nützlich, um arithmetische Berechnungen durchzuführen, selbst wenn keines der Register eine Speicheradresse enthält:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
