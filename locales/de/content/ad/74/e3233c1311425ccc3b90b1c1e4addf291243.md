# Einführung

## Schleifen

Eine **Schleife** ist eine Abfolge von Anweisungen, die möglicherweise mehr als einmal ausgeführt wird, bis eine Abbruchbedingung erfüllt ist.

In x86-64 wird eine Schleife normalerweise mit einem Sprung zu einem vorherigen Label erzeugt:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Beachte, dass ein unbedingter Sprung zu einem vorherigen Label die Ausführung immer zu diesem Label überträgt.
Das heißt, die Schleife wiederholt sich endlos, solange es keinen weiteren Sprung aus der wiederholten Sequenz heraus gibt.

Diese Schleife endet zum Beispiel nie:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Und diese Schleife endet möglicherweise, je nachdem, ob die Bedingung erfüllt ist:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### Zählschleifen

Eine Zählschleife endet fast immer auf dieselbe Weise: eine Anweisung, die einen Zähler aktualisiert oder zwei Werte vergleicht, unmittelbar gefolgt von einem bedingten Sprung, der entscheidet, ob es noch einmal rundgeht.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0` ist im obigen Code nicht nötig, weil `sub rsi, 1` bereits das `zero flag (ZF)` setzt, wenn das Ergebnis `0` ist.

Obwohl `cmp` in Assembler die wichtigste Art ist, Bedingungen zu prüfen, aktualisieren viele Anweisungen die Flags.
Zum Beispiel aktualisieren viele ganzzahlige Arithmetik- oder Bitoperationen `ZF`, wenn das Ergebnis `0` ist, und `SF`, wenn das Ergebnis negativ ist (d. h. das höchste Bit ist gesetzt).

In einer [Referenz][reference] kannst du nachschauen, welche Flags von den einzelnen Anweisungen beeinflusst werden.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Beachte, dass im obigen Beispiel davon ausgegangen wird, dass `rsi` größer als `0` ist.
Wäre es `0`, dann würde `sub rsi, 1` den Wert von `rsi` auf `-1` reduzieren, was als vorzeichenlose Zahl sehr groß ist.
Es würde `18,446,744,073,709,551,615` weitere Iterationen dauern, bis die Schleife endlich endet.
Außerdem läge jeder Speicherzugriff außerhalb der Grenzen, weil die Länge des Arrays `0` ist.

Wenn es keine Garantien für die Länge eines Arrays gibt, sind zwei Vorgehensweisen üblich.

Bei der ersten verschiebst du die Abbruchbedingung an den Anfang der Schleife und setzt ans Ende einen unbedingten Sprung:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

Bei der zweiten prüfst du vor dem Beginn der Schleife einmal, ob das Array die Länge null hat:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Diese zweite Vorgehensweise ist normalerweise effizienter als die erste, weil es weniger Verzweigungen im Schleifenblock gibt.
Mehr darüber lernst du in einem späteren Konzept.

~~~~exercism/advanced
In manchen Situationen können moderne CPUs zwei verschiedene Anweisungen zu einer einzigen Operation zusammenfassen.
Diese Optimierung heißt **Macrofusion**.

Viele Arithmetik-Anweisungen wie `sub` und `add` sowie `cmp` und `test` verschmelzen häufig mit einem bedingten Sprung, der direkt danach folgt.
Das heißt, eine Anweisung wie `cmp rax, rdx`, auf die unmittelbar ein bedingter Sprung folgt, kann die CPU in der Regel als eine einzige Operation behandeln.

Macrofusion hängt von der CPU ab, und es gibt Unterschiede darin, welche Anweisungen mit welchem bedingten Sprung verschmelzen.

Eine nützliche Referenz ist [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
Abschnitt 3.4.2.2 (Optimizing for Macrofusion) des [Intel optimization reference manual][intel-opt] listet ebenfalls verschmelzbare Paare für Intel-CPUs auf.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
