# Einführung

## Aufzählungen

Bisher haben wir uns überwiegend mit Zahlen und Strings beschäftigt.
Um die reale Welt zu modellieren, wollen wir vielleicht eine begrenzte Anzahl von Werten festlegen, die eine Variable annehmen kann.
Du möchtest vielleicht einen eigenen Typ mit ein paar verschiedenen Werten und jeweils eigenen Namen.
In einer Skateboard-Fabrik soll das Material des Decks zum Beispiel nur Ahorn, Bambus oder Kunststoff sein können.

Du könntest diese Werte mit Ganzzahlen kodieren, müsstest dann aber zusätzlichen Code schreiben, um zu prüfen, ob das System einen ungültigen Wert für das Material liefert.
Die Bedeutung dieser [_magischen Zahlen_][magic numbers] lässt sich im Quellcode kaum nachvollziehen, und sie werden leicht verwechselt.
Mit `enumerations` kannst du ausdrucksstarken Code fördern und unbeabsichtigte Vergleichsfehler vermeiden.

## Anwendungsbeispiel

Der genaue Fachbegriff für diese Art von Aufzählung ist `scoped enumeration`.
Das folgende Beispiel zeigt, wie du eine `enumeration` namens `DeckMaterial` schreibst.
Achte auf das Schlüsselwort `enum class` und das `;` am Ende der Definition:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
Schau dir nun eine Funktion zur Preisberechnung im Skate-Shop an und achte auf den Bereichsauflösungsoperator (`::`), der einen `enumerator` aus der `enumeration` auswählt:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## Gültigkeitsbereich

Stell dir vor, du hast eine zweite `enumeration` für das Material der Rollen:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
Obwohl die Rollen und das Deck beide aus _Kunststoff_ bestehen können, lassen sich die beiden nicht verwechseln.
Sie sind verschiedene _Typen_: `DeckMaterial` Kunststoff und `WheelMaterial` Kunststoff.
Jede `enumeration` hat ihre `enumerators` in ihrem eigenen Gültigkeitsbereich, ihrem eigenen `namespace`.
Deshalb heißen sie `scoped enumerations`.

## Aufzählungen ohne Gültigkeitsbereich
Du denkst vielleicht, dass es mit dem Namen `scoped` auch `unscoped`-Aufzählungen geben müsste, und damit hast du recht.
`Unscoped enumerations` werden immer unbeliebter, weil sie sich alle denselben globalen Namensraum teilen.
Wegen dieses gemeinsamen Namensraums könntest du nicht zwei `unscoped enumerations` mit denselben `enumerators` wie _Kunststoff_ im obigen Beispiel haben.

Außerdem werden `unscoped enumerations` implizit in Ganzzahlen umgewandelt.
Schau dir das folgende Beispiel an, das ein überraschendes Ergebnis liefert:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

Wenn du `scoped enumerations` in Ganzzahlen umwandeln möchtest, kannst du `static_cast<int>` verwenden.
