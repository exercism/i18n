# Ergänzung zu den Anweisungen

## Vor- und Nachteile von `from_quote`
Diese Übung definiert eine Funktion `from_quote` im Typ `Card`. Damit kannst du Code wie diesen schreiben:

```roc
card : Card
card = "Q"
```

Dieser Code ruft `Card.from_quote("Q")` zur Kompilierzeit implizit auf. Das kann das Programm potenziell beschleunigen, weil es das Parsen nicht zur Laufzeit erledigen muss, und es stellt sicher, dass Karten, die `from_quote` ablehnt, schon zur Kompilierzeit auffallen und nicht erst zur Laufzeit. Außerdem wird der Code dadurch schön lesbar. Hier ist zum Beispiel einer der Tests in dieser Übung:

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

Wer diesen Code liest, könnte allerdings annehmen, dass die Funktion `simulate_game` ein Record mit zwei `List(Str)` entgegennimmt, obwohl es in Wirklichkeit ein Record mit zwei `List(Card)` ist. Das kann zu Verwirrung und Fehlern führen. Aus diesem Grund bevorzugst du vielleicht die etwas längere, aber explizitere Schreibweise: `"Q".Card`, die ebenfalls `from_quote` zur Kompilierzeit aufruft.

In deinen eigenen Programmen bevorzugst du vielleicht stattdessen `from_str`:

```roc
Card := { ... }.{
    from_str : card_str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

Du kannst `from_str` (oder jede andere reine Funktion) auch zur Kompilierzeit aufrufen, und zwar so:

```roc
Ok(card) = Card.from_str("Q")
```

Hinweis: Wenn du diese Definition auf die oberste Ebene setzt, wird sie zur Kompilierzeit ausgeführt (weil die Funktion rein ist und ihre Eingabe zur Kompilierzeit bekannt ist). Innerhalb einer Funktion kannst du `from_str` zur Laufzeit verwenden.
