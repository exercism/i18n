# Im Detail

Wie viele andere Sprachen hat auch Go Pointer.
Wenn du noch nie mit Pointern zu tun hattest, wirken sie vielleicht ein wenig rätselhaft, aber sobald du dich an sie gewöhnt hast, sind sie ganz unkompliziert.
Sie sind ein wesentlicher Teil von Go, also nimm dir etwas Zeit, sie wirklich zu verstehen.

Bevor wir ins Detail gehen, lohnt es sich zu verstehen, wozu Pointer überhaupt gut sind.
Mit Pointern können wir Speicher mit anderen Teilen unseres Programms teilen, was aus zwei wichtigen Gründen nützlich ist:

1. Wenn wir große Datenmengen haben, ist es sehr ineffizient, Kopien anzulegen, um sie zwischen Funktionen zu übergeben.
   Wenn wir stattdessen die Speicheradresse übergeben, an der die Daten liegen, können wir den Ressourcenverbrauch unserer Programme drastisch senken.
2. Wenn wir Pointer zwischen Funktionen übergeben, können wir direkt auf die einzige Kopie der Daten zugreifen und sie ändern.
   Das bedeutet: Änderungen, die eine Funktion vornimmt, sind für andere Teile des Programms sofort sichtbar, sobald die Funktion endet.

## Variablen und Speicher

Sagen wir, wir haben eine gewöhnliche Variable `a` vom Typ Ganzzahl:

```go
var a int
```

Wenn wir eine Variable deklarieren, muss Go einen Platz im Speicher finden, um ihren Wert abzulegen.
Das ist für uns weitgehend abstrahiert: Wenn wir den Wert abrufen wollen, der in diesem Speicherbereich liegt, können wir ihn einfach über den Variablennamen ansprechen.

Wenn wir zum Beispiel `a + 2` schreiben, holen wir den Wert, der in dem zu `a` gehörenden Speicherbereich liegt, und addieren 2 dazu.

Genauso können wir den Variablennamen verwenden, um den Wert im Speicherbereich von `a` zu ändern:

```go
a = 3
```

Der Speicherbereich, der zu `a` gehört, enthält jetzt den Wert `3`.

## Pointer

Variablen erlauben uns, auf Werte im Speicher zu verweisen.
Manchmal ist es aber nützlich, die **Speicheradresse** zu kennen, auf die eine Variable zeigt.
**Pointer** enthalten die Speicheradressen dieser Werte.
Du deklarierst eine Variable mit einem Pointer-Typ, indem du dem zugrunde liegenden Typ einen Stern voranstellst:

```go
var p *int // 'p' contains the memory address of an integer
```

Hier deklarieren wir eine Variable `p` vom Typ „Pointer auf int“ (`*int`).
Das bedeutet, dass `p` die Speicheradresse einer Ganzzahl enthält.
Der Nullwert von Pointern ist `nil`, weil ein `nil`-Pointer keine Speicheradresse enthält.

### Einen Pointer auf eine Variable erhalten

Um die Speicheradresse des Wertes einer Variablen herauszufinden, können wir den Operator `&` verwenden.
Wenn wir zum Beispiel die Speicheradresse der Variablen `a` ermitteln und im Pointer `p` speichern wollen, geht das so:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Über einen Pointer auf den Wert zugreifen (Dereferenzierung)

Wenn wir einen Pointer haben, wollen wir vielleicht wissen, welcher Wert unter der Speicheradresse liegt, die der Pointer enthält.
Dazu können wir den Operator `*` verwenden:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

Die Operation `*p` holt den Wert, der unter der in `p` gespeicherten Speicheradresse liegt.
Diese Operation wird oft „Dereferenzierung“ genannt.

Mit dem Dereferenzierungsoperator können wir auch einen neuen Wert an die Speicheradresse schreiben, auf die der Pointer verweist:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

Eine Zuweisung an `*pa` ändert den Wert, der unter der Speicheradresse liegt, die `pa` enthält.
Da `pa` die Speicheradresse von `a` enthält, ändern wir mit einer Zuweisung an `*pa` letztlich den Wert von `a`!

Ein Wort der Warnung: Prüfe immer, ob ein Pointer nicht `nil` ist, bevor du ihn dereferenzierst.
Wenn du einen `nil`-Pointer dereferenzierst, stürzt das Programm zur Laufzeit ab!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Pointer auf Structs

Bisher haben wir nur Pointer auf primitive Werte gesehen.
Wir können auch Pointer auf Structs erstellen:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

Wir hätten auch direkt eine neue `Person` erstellen und einen Pointer darauf speichern können:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Wenn wir einen Pointer auf ein Struct haben, müssen wir den Pointer nicht dereferenzieren, bevor wir auf eines der Felder zugreifen:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## Slices und Maps sind bereits Pointer

Slices und Maps sind besondere Typen, weil in ihrer Implementierung bereits Pointer stecken.
Deshalb müssen wir für diese Typen meistens keine Pointer erstellen, um die Speicheradresse ihrer Werte zu teilen.
Stell dir vor, wir haben eine Funktion, die den Wert eines Schlüssels in einer Map erhöht:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Wenn wir eine Map erstellen und diese Funktion aufrufen, bleiben die Änderungen, die die Funktion an der Map vorgenommen hat, auch nach dem Ende der Funktion erhalten.
Das ist ein ähnliches Verhalten wie bei einem Pointer. Beachte aber, dass wir in diesem Beispiel keinerlei Referenzierung/Dereferenzierung und keine Pointer-Syntax verwenden:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

Dasselbe gilt, wenn du ein vorhandenes Element in einem Slice änderst.

Operationen, die ein neues Slice zurückgeben, wie `append`, sind jedoch ein Sonderfall: Sie verändern das Slice außerhalb der Funktion **möglicherweise nicht**.
Das liegt daran, wie Slices intern funktionieren, aber darauf gehen wir hier nicht näher ein, denn das ist ein fortgeschritteneres Thema.
Wenn du neugierig bist, kannst du mehr dazu im [Go Blog: Mechanics of 'append'][mechanics-of-append] lesen.

## Pointer-Arithmetik

Im Gegensatz zu anderen Sprachen unterstützt Go keine Pointer-Arithmetik.
Das heißt, du kannst nicht von der Speicheradresse eines Wertes zur Adresse eines anderen gelangen, indem du den Pointer-Wert erhöhst.
Snippets wie das folgende sind also ungültig:

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
