# Überblick

In Rust sind Methoden Funktionen, die für ein Struct (oder ein `enum`- oder `trait`-Objekt) definiert werden.
Das ändert das Aufrufmuster: Statt `frobnicate(foo)` wird eine Methode als `foo.frobnicate()` aufgerufen.

Methoden sind Funktionen ähnlich: Sie werden mit dem Schlüsselwort `fn` deklariert, sie haben einen Namen und sie können Parameter und Rückgabewerte haben.

Anders als bei Funktionen ist der erste Parameter einer Methode immer `self` (oder eine Variante davon), das die Instanz des Structs repräsentiert, für die die Methode aufgerufen wird (mehr dazu weiter unten).

Erstellen wir ein `enum` für die Häuser von Hogwarts und ein `struct`, das `age` und `house` eines Zauberers beschreibt:

```rust
#[derive(Debug)]
enum House {
    Gryffindor,
    Hufflepuff,
    Ravenclaw,
    Slytherin,
}

struct Wizard {
    age: u32,
    house: House,
}
```

## Methoden definieren

Um Methoden für das Struct `Wizard` zu definieren, beginnen wir einen `impl`-Block für `Wizard` (`impl` ist kurz für implementation, also Implementierung).

```rust
impl Wizard { }
```

Alles innerhalb dieses `impl`-Blocks wird dem Typ `Wizard` zugeordnet.
Beachte, dass ein Struct mehrere `impl`-Blöcke haben darf.

### `self` verwenden

Eine Methode muss als ersten Parameter einen Parameter namens `self` vom Typ `Self` haben.
Der Typ `Self` ist ein Alias für den Typ, für den der `impl`-Block steht.
In unserem Beispiel repräsentiert `Self` den Typ `Wizard`.

Rust erlaubt es uns, das der Einfachheit halber abzukürzen und an der Stelle des ersten Parameters nur den Namen `self` zu schreiben.
Häufige `self`-Typen für Methoden sind:

- `self`: Kurz für `self: Self`. Die Signatur mit bloßem `self` konsumiert die Instanz.
- `&self`: Kurz für `self: &Self`. Das leiht die Instanz unveränderlich aus.
- `&mut self`: Kurz für `self: &mut Self`. Das leiht die Instanz veränderlich aus.

In fortgeschrittenerem Code siehst du vielleicht auch Signaturen wie `self: Pin<&self>`, `self: Rc<Self>` usw.
Das geht jedoch über den Rahmen dieses Tutorials hinaus.

### Eine Methode mit `&self` definieren

Wenn wir eine `info`-Methode implementieren möchten, die die grundlegenden Informationen des Zauberers anzeigt, könnten wir diese Methode in einem `impl`-Block für `Wizard` definieren:

```rust
impl Wizard {
    fn info(&self) {
        println!(
            "A wizard of age {} who studies in House {:?} at Hogwarts",
            self.age,
            self.house,
        );
    }
}
```

Beachte, dass wir in der Signatur von `info` die Instanz mit `&self` unveränderlich ausleihen.
So können wir die Felder `age` und `house` einer `Wizard`-Instanz lesen, ohne sie zu verändern.
Hätten wir statt des Ausleihens ein konsumierendes `self` verwendet, wäre die Instanz nach dem Aufruf der Methode nicht mehr zugänglich.

Mit der implementierten `info`-Methode könnten wir die grundlegenden Informationen eines Zauberers ausgeben:

```rust
let harry = Wizard { age: 11, house: House::Gryffindor };
harry.info();
// => A wizard of age 11 who studies in House Gryffindor at Hogwarts
```

### Eine Methode mit `&mut self` definieren

Wenn wir eine Methode implementieren möchten, die die Felder einer Struct-Instanz verändert, leihen wir die Instanz in der Signatur der Methode mit `&mut self` veränderlich aus.

Nehmen wir an, wir möchten in Hogwarts eine neue Regel aufstellen, die es Schülern erlaubt, das Haus zu wechseln.
Dann könnten wir eine Methode `switch_house` so implementieren:

```rust
impl Wizard {
    fn switch_house(&mut self, new_house: House) {
        self.house = new_house;
    }
}
```

Jetzt können wir das Haus für einen Zauberer wechseln, der in Hogwarts studiert:

```rust
// Note that the variable must be mutable
let mut cedric = Wizard {age: 14, house: House::Hufflepuff};
cedric.info();
// => A wizard of age 14 who studies in House Hufflepuff at Hogwarts
cedric.switch_house(House::Slytherin);
cedric.info()
// => A wizard of age 14 who studies in House Slytherin at Hogwarts
```

## Mehrere „impl“-Blöcke

In Rust darf jedes Element mehrere `impl`-Blöcke haben.
Wir können also alle Methoden in denselben `impl`-Block gruppieren oder mehrere `impl`-Blöcke für verschiedene Gruppen von Methoden haben.
Beide Vorgehensweisen sind syntaktisch gültig, aber in typischen Projekten verwendet man einen einzigen `impl`-Block pro eindeutiger Menge von `where`-Bounds auf `impl`-Ebene.

## Assoziierte Funktionen

Es ist möglich, innerhalb eines `impl`-Blocks Funktionen zu definieren, die keinen `self`-Parameter enthalten.
Weil ihnen der `self`-Parameter fehlt, sind sie keine Methoden.
Sie sind aber trotzdem dem implementierten Typ zugeordnet und werden aufgerufen, indem man diesen Typ benennt.
Deshalb heißen sie assoziierte Funktionen (oder typassoziierte Funktionen).

Du hast schon einige assoziierte Funktionen gesehen, zum Beispiel `String::from()`:

```rust
let some_string = String::from("This is an associated function but not a method");
```

Konstruktoren werden oft als assoziierte Funktionen implementiert.
Erstellen wir eine `new`-Funktion, die dem Typ `Wizard` zugeordnet ist:

```rust
impl Wizard {
    fn new(age: u32, house: House) -> Self {
        Self {
            age,
            house,
        }
    }
}
```

Beachte, dass wir `Self` statt `Wizard` verwenden können, um den Typ anzugeben, der von der Funktion zurückgegeben wird.
Es ist nicht Pflicht, den Typ-Alias `Self` so zu verwenden, aber er kann die Implementierung für Typen mit komplizierten oder langen Namen vereinfachen.
Jetzt können wir Folgendes ausführen:

```rust
let myrtle = Wizard::new(14, House::Ravenclaw);

myrtle.info();
// => A wizard of age 14 who studies in House Ravenclaw at Hogwarts
```
