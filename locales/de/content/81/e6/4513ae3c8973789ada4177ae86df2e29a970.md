# Ergänzung zur Anleitung

## Vor- und Nachteile von `from_quote`
Diese Übung definiert eine Funktion `from_quote` im Typ `DateOfBirth`. Dadurch kannst du Code wie diesen schreiben:

```roc
birthdate : DateOfBirth
birthdate = "2019-01-20"
```

Dieser Code ruft `DateOfBirth.from_quote("2019-01-20")` implizit zur Kompilierzeit auf. Das kann das Programm potenziell beschleunigen, weil es das Parsen nicht zur Laufzeit erledigen muss. Außerdem sorgt es dafür, dass Datumsangaben, die `from_quote` ablehnt, bereits zur Kompilierzeit auffallen und nicht erst zur Laufzeit. Zudem ist der Code schön und gut lesbar. Hier ist zum Beispiel einer der Tests in dieser Übung:

```roc
# multiple birthdates with one shared birthday
expect {
	shared_birthday(["1966-07-29", "1977-02-12", "2001-07-29", "1980-11-10"])
}
```

Wer diesen Code liest, könnte allerdings annehmen, dass die Funktion `shared_birthday` einen `List(Str)` entgegennimmt, obwohl sie tatsächlich einen `List(DateOfBirth)` entgegennimmt. Das kann zu Verwirrung und Fehlern führen. Deshalb bevorzugst du vielleicht das etwas längere, aber eindeutigere Format `"2019-01-20".DateOfBirth`, das `from_quote` ebenfalls zur Kompilierzeit aufruft.

In deinen eigenen Programmen gibst du vielleicht lieber einen praktischen Konstruktor an, etwa diesen hier:

```roc
DateOfBirth := { year : I64, month : U8, day : U8 }.{
    from_ymd : I64, U8, U8 -> Try(DateOfBirth, [InvalidMonth, InvalidDay])
    from_ymd = |year, month, day| ...
}
```

Diesen Konstruktor kannst du auch zur Kompilierzeit aufrufen, und zwar so:

```roc
Ok(birthdate) = DateOfBirth.from_ymd(2019, 1, 20)
```

Hinweis: Wenn du diese Definition auf der obersten Ebene platzierst, wird sie zur Kompilierzeit ausgeführt (denn die Funktion ist rein und die Eingabewerte sind zur Kompilierzeit bekannt). Innerhalb einer Funktion kannst du denselben Konstruktor zur Laufzeit verwenden.
