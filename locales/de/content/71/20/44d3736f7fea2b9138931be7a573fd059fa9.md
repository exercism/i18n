# Einführung

Eine `list` in F# ist eine unveränderliche Sammlung von null oder mehr Werten. Alle Werte in einer Liste müssen denselben Typ haben. Da Listen unveränderlich sind, kann sich der Wert einer Liste nach ihrer Erstellung nie ändern. Alle Funktionen und Operatoren, die eine Liste zu verändern scheinen (zum Beispiel das Hinzufügen eines Elements), geben tatsächlich eine neue Liste zurück.

Listen kannst du so definieren:

```fsharp
let empty = []
let singleValue = [5]
let threeValues = ["a"; "b"; "c"]
```

Am häufigsten fügst du ein Element mit dem Operator `::` (cons) zu einer Liste hinzu:

```fsharp
let twoToFour = [2; 3; 4]
let oneToFour = 1 :: twoToFour
// => [1; 2; 3; 4]
```

Eine F#-Liste hat einen _Kopf_ (das erste Element) und einen _Rest_ (alles nach dem ersten Element). Der Rest einer Liste ist selbst eine Liste.

Listen bearbeitest du entweder mit Funktionen und Operatoren aus dem Modul `List` oder manuell mit Pattern Matching über die Muster _list_ und _cons_:

```fsharp
let describe list =
    match list with
    | [] -> "Empty list"
    | head::tail -> sprintf "Non-empty list with head: %d" head

describe []        // => "Empty list"
describe [1]       // => "Non-empty with head: 1"
describe [5; 7; 9] // => "Non-empty with head: 5"
```

Beim Pattern Matching kannst du einen Wert auch _verwerfen_. Wenn dir ein Wert in einem bestimmten Fall _nicht_ wichtig ist (du ihn also nicht _verwenden_ willst), kannst du das mit einem Unterstrich (`'_'`) kennzeichnen:

```fsharp
let describe list =
    match list with
    | [] -> "Empty list"
    | [x] -> "List with one item"
    | [_; y] -> "List with two items (first item ignored)"
    | _ -> "List with many items (all items ignored)"

describe []        // => "Empty list"
describe [1]       // => "List with one item"
describe [5; 7]     // => "List with two items (first item ignored)"
describe [5; 7; 9] // => "List with many items (all items ignored)"
```

Der einzelne Unterstrich `'_'` sollte beim Pattern Matching immer _zuletzt_ kommen. Jeder Wert, der auf _keinen_ der anderen Fälle passt, wird von diesem Fall behandelt.
