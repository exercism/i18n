# Einführung

_„Datum und Uhrzeit bringen wir schon kleinen Kindern bei. Wie schwer kann das schon sein?"_

Viele Programmierer haben diesen Fehler gemacht, und die anschließende Erfahrung wirkt sich meist schlecht auf ihre Gesundheit und ihr Wohlbefinden aus.

Wer nicht ganz trivial mit Datum und Uhrzeit programmiert, sollte zumindest bereit sein, mögliche Probleme zu verstehen und ihnen vorzubeugen.

Dieses Dokument versucht, einen Überblick darüber zu geben, wie Julia mit Datum und Uhrzeit umgeht, aber für weitere Details ist ein Blick in das [Handbuch][Dates] notwendig.
Es gibt außerdem ein [Wikibook][Wikibook], dessen Erklärungen manche Leser klarer finden, und das ein hilfreiches [Diagramm][type-hierarchy] der Typhierarchie enthält.

## Das Modul `Dates`

Der Großteil der grundlegenden Funktionalität steckt in `Dates`, einem Modul, das in einer Standardinstallation enthalten ist, aber nicht Teil der Standardbibliothek ist.

Um das Modul zu nutzen, gibt es zwei Möglichkeiten:

1. Füge `import Dates` hinzu und stelle allen Funktionsaufrufen `Dates.` voran.
2. Füge `using Dates` hinzu, wodurch das gesamte Modul in den aktuellen Namensraum gelangt (_bis auf ein paar problematische Namen_).

```julia-repl
# option 1
julia> import Dates

julia> Dates.now()
2025-06-21T16:02:39.080

julia> now()  # wrong: need to include `Dates.` after an import
ERROR: UndefVarError: `now` not defined in `Main`


# option 2
julia> using Dates

julia> now()  # functions are now in the namespace
2025-06-21T16:03:04.161
```

Das Modul `Dates` ist groß und kompliziert, aber es bietet vier Hauptarten von Funktionalität:

- `Dates.Date`, was Tag, Monat und Jahr enthält, aber keine Uhrzeit.
- `Dates.Time`, was die Uhrzeit enthält, aber kein Datum.
- `Dates.DateTime`, was Datum und Uhrzeit kombiniert.
- `Dates.Period`, was Zeit- und Datumsintervalle behandelt.

Bitte beachte, dass ein `DateTime` im Allgemeinen _keine_ Zeitzoneninformationen enthält (Python würde das einen „naiven" Datetime nennen).
Eine Ausnahme ist `now()`, das die lokale Zeit von deiner Systemuhr bezieht und bei Bedarf in UTC umrechnen kann.

Die vielleicht häufigsten Anforderungen sind:

- Ein passendes Eingabeformat parsen, um einen `Dates`-Typ zu konstruieren.
- Das gewünschte numerische oder String-Format aus einem `Dates`-Typ gewinnen.
- Einen Offset auf einen `Date`-, `Time`- oder `DateTime`-Wert anwenden.
- Das Intervall zwischen zwei solchen Werten berechnen.
- Das aktuelle Datum (mit `today()`) und/oder die aktuelle Uhrzeit (mit `now()`) abrufen.

### Datums- und Zeitformate

Es gibt viele Arten, Datum und Uhrzeit zu schreiben, die oft kulturspezifisch sind.
Rein numerische Datumsangaben wie „7/6/23" sind mehrdeutig, verwirrend und haben in multinationalen Organisationen zu vielen teuren Fehlern geführt (_der Autor spricht hier aus bitterer eigener Erfahrung_).

Der internationale Standard ist in `ISO 8601` definiert und hat zwei Hauptvorteile:

- Das Parsen ist schnell und eindeutig.
- Das Sortieren ist einfach, da das Datetime wie normaler Text behandelt und alphabetisch sortiert werden kann.

In einem vorherigen Beispiel haben wir gesehen, dass `Date.now()` `2025-06-21T16:03:04.161` zurückgegeben hat.

Das setzt sich aus verschiedenen Teilen zusammen:

- `YYYY-MM-DD` für den Datumsteil.
- `hh:mm:ss` für den Zeitteil.
- Optional Millisekunden (oder eine noch kleinere Einheit) nach dem Dezimalpunkt.

Andere String-Formate werden in einem späteren Abschnitt behandelt.

## Datumsangaben

`Dates.Date` ist ein relativ einfacher, reiner Datumstyp, der nichts über Uhrzeiten oder Zeitzonen weiß.

```julia-repl
# constructor with year, month, day arguments
julia> date1 = Date(2025, 06, 23)
2025-06-23

# constructor with ISO 8601 string
julia> date2 = Date("2025-06-23")
2025-06-23

julia> date1 == date2
true

julia> typeof(date1)
Date
```

Für einzelne Teile des Datums gibt es Zugriffsfunktionen, und diese treten paarweise auf, unterschieden durch die Groß- und Kleinschreibung.

```julia-repl
# lowercase returns an integer
julia> month(date1)
6

julia> typeof(month(date1))
Int64

# Propercase returns a Period type
julia> Month(date1)
6 months

julia> typeof(Month(date1))
Month
```

### Abfragefunktionen

Es gibt eine Vielzahl von Funktionen, die ein gewisses Verständnis des Kalenders mitbringen.
Das nächste Beispiel zeigt nur ein paar davon.

```julia-repl
julia> date1
2025-06-23

julia> dayofweek(date1) # 1 = Monday, 7 = Sunday
1

julia> dayname(date1)
"Monday"

julia> daysinmonth(date1)
30

julia> isleapyear(date1)
false

julia> lastdayofmonth(date1)
2025-06-30
```

## Uhrzeiten

`Dates.Time` ist der grundlegende reine Uhrzeittyp.
Er kennt keine Datumsangaben: Uhrzeiten gehen um Mitternacht automatisch auf `Time(0, 0, 0)` über.

Das vollständige Konstruktorformat ist `Time(hour, min, sec, millisec, microsec)` oder das ISO-8601-Äquivalent.

Alle Parameter sind optional und haben den Standardwert `0`.

```julia-repl
julia> Time(14, 57, 25, 142)
14:57:25.142

julia> Time("14:57:25.142")
14:57:25.142

julia> Time(14, 57, 25, 142, 32)
14:57:25.142032
```

Wie bei `Date` sind einzelne Teile über Zugriffsfunktionen verfügbar:

```julia-repl
julia> minute(t) # => integer
57

julia> Minute(t) # => Period
57 minutes
```

## Datums- und Uhrzeitangaben

`Dates.DateTime` kombiniert die meisten Eigenschaften der Typen `Date` und `Time`.

```julia-repl
julia> dt1 = DateTime(2025, 6, 23, 14, 57, 25, 142)
2025-06-23T14:57:25.142

# date1 and t were defined in previous examples
julia> dt2 = DateTime(date1, t)
2025-06-23T14:57:25.142
```

Die Parameter für Jahr, Monat und Tag haben den Standardwert `1`, die Zeitparameter alle den Standardwert `0`.

All diese Parameter in der richtigen Reihenfolge zu behalten, kann eine Herausforderung sein, deshalb ist das ISO-Format für die Eingabe möglicherweise vorzuziehen.

Alternativ kann ein `DateTime` aus einem `Date` und einem `Time` konstruiert werden, wie im obigen Beispiel.

## Perioden

Jede der Datums- und Zeitkomponenten hat ihren eigenen `Period`-Typ, von `Year` bis hinunter zu `Nanosecond`, der ein Zeitintervall darstellt.
Diese sind besonders nützlich für die Arithmetik.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Year(21)
21 years

julia> Second(61)
61 seconds

julia> dt1 + Year(21) - Second(61)
2046-06-23T14:56:24.142

julia> Date(2025, 07, 03) - Date(2025, 04, 25)
69 days
```

Beim Arbeiten mit `Period`-Typen versucht Julia, clever mit Kalenderunregelmäßigkeiten wie der Monatslänge umzugehen, und rundet nach Bedarf.

```julia-repl
# February has fewer days than January
julia> Date(2025, 1, 31) + Month(1) 
2025-02-28
```

## String-Darstellungen

Wir haben bereits den ISO-8601-Standard erwähnt, der Julias Standarddarstellung für Datum und Uhrzeit beim Formatieren oder Parsen von Strings ist.

Natürlich sind viele andere Formate häufig in Gebrauch, oft auf kulturspezifische Weise.
Um diese zu behandeln, hat Julia den `DateFormat`-Typ, der aus einem Formatstring beliebiger Komplexität konstruiert werden kann.

```julia-repl
# dateformat"" string syntax
julia> dtfmt = dateformat"d/m/y"
dateformat"d/m/y"

julia> typeof(dtfmt)
DateFormat{Symbol("d/m/y"), Tuple{Dates.DatePart{'d'}, Dates.Delim{Char, 1}, Dates.DatePart{'m'}, Dates.Delim{Char, 1}, Dates.DatePart{'y'}}}

# DateFormat constructor
julia> DateFormat("d/m/y")
dateformat"d/m/y"
```

Das obige Beispiel ist sehr einfach, nur ein Datum im in Europa üblichen Format Tag/Monat/Jahr.
Es werden zwei Varianten der Syntax gezeigt, aber das Ergebnis ist identisch.

Ein `DateFormat` kann dann verwendet werden, um jeden geeigneten String zu parsen:

```julia-repl
julia> DateTime("14/7/2023", dtfmt)
2023-07-14T00:00:00
```

Das Erstellen eines `DateFormat` ist mit erheblichem Aufwand verbunden, deshalb ist es hilfreich, diesen Schritt nur einmal auszuführen (wie hier mit `dtfmt`), wenn du über viele Datums- und Zeitstrings schleifst.

Formate können viel komplexer sein als dieses, daher sieh im [Handbuch][dateformat] nach Einzelheiten.

Dasselbe `DateFormat` kann auch verwendet werden, um ein Datum oder eine Uhrzeit in einem beliebigen gewünschten String-Format auszugeben, und zwar mit der Funktion [`Dates.format()`][format].

Leider scheint es einen Namensraumkonflikt mit `format` zu geben (zumindest in Julia 1.11.5), deshalb ist es am besten, das Präfix `Dates.` auch nach `using Dates` anzugeben.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Dates.format(dt1, dateformat"e, u d")
"Mon, Jun 23"
```

Wie in der [Dokumentation][wiki-format] beschrieben, liefert `"e, u d"` die abgekürzte Textdarstellung für Wochentag und Monat.

Die Textdarstellung ist standardmäßig Englisch.
Andere Sprachen können hinzugefügt werden, obwohl die Unterstützung dafür derzeit nicht optimal ist.
