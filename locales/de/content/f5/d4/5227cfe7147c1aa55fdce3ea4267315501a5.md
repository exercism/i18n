# Tests

Jede Übung enthält eine Testdatei.
Führe die Tests mit dem Programm `bats` aus.

```bash
bats test-hello-world.bats
```

`bats` muss dafür installiert sein.
Auf der Seite [Tests im Bash-Track][bash] findest du Anweisungen, wie du `bats` für dein System installierst.

### bats ist in Bash implementiert

Die bats-Datei ist ein Bash-Skript mit einigen speziellen Funktionen, die der Befehl `bats` erkennt.
Du wirst Tests sehen, die so aussehen:

```sh
jq -f some-exercise.jq <<< "{some,json,here}"
```

Diese `<<<`-Syntax ist ein [Here String][here-string] in Bash.
Dabei wird der String auf der rechten Seite in die Standardeingabe des Programms auf der linken Seite geleitet.
Das ist ([ungefähr][so]) dasselbe wie

```sh
echo "{some,json,here}" | jq -f some-exercise.jq
```

## Hilfe zu assert-Funktionen

Die Tests verwenden Funktionen aus der Bibliothek [bats-assert][bats-assert].
Hilfe zu den verschiedenen `assert*`-Funktionen findest du dort.

## Übersprungene Tests

Eine Übung ist gelöst, wenn alle ihre Tests bestehen.
Standardmäßig wird nur ein Test (der erste) ausgeführt, wenn du die Tests laufen lässt.
Das ist Absicht, denn so kannst du dich darauf konzentrieren, nur diesen einen Test bestehen zu lassen.
Sobald er besteht, kannst du den nächsten Test aktivieren, indem du die

    [[ $BATS_RUN_SKIPPED == true ]] || skip

Annotationen auskommentierst oder entfernst, die den anderen Tests vorangestellt sind.

## Skips überschreiben

Um alle Tests auszuführen, auch die mit `skip`-Annotationen, kannst du Folgendes ausführen:

```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Es kann praktisch sein, eine Wrapper-Funktion zu verwenden, um Tipparbeit zu sparen: In `bash` kannst du das so machen:

```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```

Dann führst du die Tests einfach so aus:

```bash
bats
```

## Debugging in `jq`

`jq` bringt einen praktischen [`debug`][debug]-Filter mit.
Verwende ihn, während du deine Lösungen für die Übungen entwickelst, um die Daten zu untersuchen, die gerade durch die jq-Pipeline laufen.
Weitere Details findest du im [Debugging-Dokument][debugging].
