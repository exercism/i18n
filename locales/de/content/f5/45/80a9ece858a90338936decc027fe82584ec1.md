# Generische Klassen

```sather
class LOST_BOX{T} is
   attr item : T;
   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;
end;
```

## Was der Parameter ist

`T` steht für einen Typ, der an der Stelle der Verwendung angegeben wird. Sather erzeugt beim Kompilieren des Programms für jede tatsächlich vorkommende Kombination eine eigene Klasse. Also:

- `LOST_BOX{STR}` und `LOST_BOX{INT}` sind nicht miteinander verwandte Typen;
- es gibt keine Laufzeitprüfung, kein Boxing und keine Konvertierung;
- ein Fehler in der Klasse zeigt sich für jeden Typ, mit dem sie verwendet wird.

Das ist derselbe Ansatz wie bei C++-Templates oder Rust-Generics und anders als bei Java-Generics, bei denen der Typ gelöscht wird und alles in Wahrheit ein Objekt ist.

## Eingeschränkte Parameter

Ein nacktes `T` lässt sich zuweisen, übergeben und zurückgeben, mehr nicht, weil weiter nichts darüber bekannt ist. Um Routinen darauf aufzurufen, gib an, mit welchem Typ es konform sein muss:

```sather
class LOST_BOX{T < $STR} is
   describe : STR is return "a box holding " + item.str; end;
end;
```

`T < $STR` verlangt, dass `T` mit `$STR` konform ist, und erlaubt dafür, dass `item.str` aufgerufen wird. Was ein nacktes `T` nicht kann, lässt sich mit einer Einschränkung ermöglichen.

Ohne die Einschränkung lässt sich `item.str` nicht kompilieren, und die Fehlermeldung nennt die Zeile innerhalb der generischen Klasse, nicht die Zeile, die die generische Klasse verwendet hat.

## Generische Routinen?

Es gibt keine. Nur Klassen nehmen Parameter. Eine Routine, die mit mehreren Typen arbeiten muss, steckt entweder in einer generischen Klasse oder nimmt einen abstrakten Typ wie `$STR`.

## Die Wahl zwischen ihnen

| | generische Klasse | abstrakte Klasse |
| --- | --- | --- |
| entschieden | zur Kompilierzeit | zur Laufzeit |
| enthält | einen Typ pro Instanziierung | jeden konformen Typ |
| Kosten | keine | ein Dispatch |

`ARRAY{$ACT}` nutzt beides: generisch beim Elementtyp, abstrakt darin, was dieses Element sein kann.

Greif zu einer generischen Klasse, wenn der Typ durchgehend derselbe ist und der Nutzer der Klasse ihn kennt. Greif zu einer abstrakten Klasse, wenn mehrere Typen in einer Sammlung koexistieren müssen.
