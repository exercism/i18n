# Tests

Jede Übung liefert die Unit-Tests und ein CMake-Build-Rezept.  Die
Implementierung schreibst du selbst.
Jede Testdatei ist dafür gedacht, gegen deine Implementierung gelinkt zu
werden, um ein Konsolenprogramm bereitzustellen, das die Tests ausführt.  Wenn du das Testprogramm ausführst, werden für jeden fehlgeschlagenen Test Meldungen ausgegeben, und wenn Tests fehlschlagen, wird ein Exit-Status ungleich null gemeldet.

Die Testdatei heißt `<exercise>_test.f90`, für die Übung „Bob“ heißt die Datei mit den Tests also `bob_test.f90`. Jeder Test hat einen Kommentar, der den Test beschreibt, und danach den eigentlichen Test, der mit `call assert_equal` beginnt, z. B.

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Um einen Test zu deaktivieren, kommentierst du ihn einfach mit einem `'!'` aus, z. B.

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Eine Übung durchzuarbeiten läuft so ab:

* Den ersten Build mit CMake erstellen
* Für jeden Unit-Test:
 * Die Kompilierfehler beheben, damit der Test fehlschlägt.
 * Gerade genug implementieren, damit der Test besteht.
 * Deine Implementierung refaktorieren, um die Lesbarkeit zu verbessern, Redundanz zu reduzieren usw.
 * Den nächsten Test einkommentieren


## Den ersten Build mit CMake erstellen

Jede Übung bringt zusammen mit den Unit-Tests eine Datei `CMakeLists.txt` mit.  Sie enthält das fertige CMake-Rezept, das den Build für dich übernimmt.  Diese Datei solltest du nicht bearbeiten müssen.  Das mitgelieferte Rezept geht davon aus, dass deine Implementierung in einer Quelldatei liegt, die nach der Übung benannt ist.

Die Übung „Bob“ erwartet zum Beispiel eine Implementierung in der Datei `bob.f90`.

**Erstelle deine ersten Implementierungsdateien, bevor du CMake ausführst.**
Wenn du beim Ausführen von CMake für die Übung „Bob“ die Datei `bob.f90` nicht hast, erzeugt CMake einen Fehler, dass Dateien nicht gefunden wurden.
**Diese Dateien dürfen leer sein, aber sie müssen existieren.**

Mit diesem Rezept kann CMake ein passendes Projekt für deine Umgebung erzeugen, indem du `cmake -G` mit einem passenden Generator und dem Pfad zum Verzeichnis der Übung ausführst.  CMake erzeugt ein Build-Skript, das zu deinem Betriebssystem passt.  Damit diese generierten Dateien von deinem Übungsquellcode getrennt bleiben, ist es üblich, ein Verzeichnis namens `build` anzulegen, das diese generierten Build-Dateien sowie den kompilierten Code enthält.

So bleibt dein Übungsordner aufgeräumt und übersichtlich.

**Hinweis: Beim ersten Aufruf von `cmake` wird die [testlib](###-Testlib) automatisch heruntergeladen. Die `testlib` wird benötigt, damit die Unit-Tests funktionieren.

Da du CMake für jede Übung ausführst, um die Build-Anweisungen zu erstellen, möchtest du dafür vielleicht ein Bash-Skript (Linux/MacOS) oder eine Batchdatei (Windows) anlegen.

Sobald CMake die Build-Umgebung erstellt hat, kannst du deinen Code mit dem passenden Befehl für deine Umgebung bauen:

* Linux mit make: `make`
* Windows mit Visual Studio: Wähle im Menü Build / Build Solution aus.
* Windows mit MingW: `mingw32-make.exe`
* Windows mit nMake: `nmake.exe`
* MacOS mit Xcode: Wähle in der Symbolleiste Build aus

Im Folgenden findest du Beispiele, wie du CMake in verschiedenen Umgebungen ausführst.

### Linux\MacOS mit Make

Der Generatorname für CMake ist `Unix Makefiles`.
Angenommen, die aktuelle Übung ist `bob` und wir befinden uns im Übungsordner:

```
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

Dieses Beispiel zeigt, wie du leere Dateien für die Implementierung erstellst, bevor du CMake ausführst.

Tippe im Build-Verzeichnis einfach make ein, um die Tests zu kompilieren. Das sollte Kompilierfehler erzeugen. Sobald die Fehler behoben sind, führe `make` erneut aus.
Wenn alle Build-Fehler behoben sind, führe die Tests aus:

```
$ ctest -V
```
### Windows mit Visual Studio 2017

Der Generatorname für CMake ist `Visual Studio 15`.  Derselbe Generator unterstützt alle IDE-Editionen von Visual Studio 2017: Community, Professional und Enterprise. Angenommen, die aktuelle Übung ist `bob` und wir befinden uns im Übungsordner:

```
> copy nul: bob.f90
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

Dieses Beispiel zeigt, wie du leere Dateien für die Implementierung erstellst, bevor du CMake ausführst.

### Testlib

Die Tests hängen von einer kleinen Bibliothek namens `testlib` ab, die von GitHub heruntergeladen wird, wenn der Build zum ersten Mal mit cmake konfiguriert wird.

Falls der Download fehlschlägt, kannst du ihn manuell durchführen, z. B.

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/TesterMain.f90
```
