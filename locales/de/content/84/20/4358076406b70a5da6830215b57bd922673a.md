# Über

Ein wichtiger Aspekt bei der Arbeit mit Zahlen in Java ist der Unterschied zwischen Ganzzahlen (Zahlen ohne Nachkommastellen) und Gleitkommazahlen (Zahlen mit null oder mehr Nachkommastellen).

Java kennt noch andere [Datentypen][numeric-datatypes] außer `int` und `double`:

```java
// 8-Bit Integer
byte   a = 127;

// 16-Bit Integer
short  b = 262143;

// 64-Bit Integer
long   d = 18446744073709551999L;

// 32-bit Single-Precision Floating-Point
float  e = 5409.29f;
```

Sowohl Ganzzahlen als auch Gleitkommazahlen können das Zeichen `_` als _Zifferntrennzeichen_ verwenden, was beim Definieren großer Zahlen helfen kann:

```java
int largeInt = 1_000_000;
// => 1000000

double largeDouble = 9_876_543.21;
// => 9876543.21
```

Gerechnet wird mit den üblichen [arithmetischen Operatoren][arithmetic-operators] (`+`, `-`, `*` usw.).
Zahlen lassen sich mit den üblichen [Vergleichsoperatoren][comparison-operators] (`<`, `>=` usw.) sowie dem Gleichheitsoperator (`==`) und dem Ungleichheitsoperator (`!=`) vergleichen.

```java
5 * 6
// => 30

1.2 > 0.8
// => true

120 == 100
// => false

2 != 4
// => true
```

Beim Umwandeln zwischen numerischen Typen gibt es zwei Arten von Umwandlungen:

1. Implizite Umwandlungen: Es gehen keine Daten verloren, und es ist keine zusätzliche Syntax nötig.
2. Explizite Umwandlungen: Daten könnten verloren gehen, und es ist zusätzliche Syntax in Form eines _Casts_ nötig.

Da ein `int` weniger genau als ein `double` ist, ist die Umwandlung von einem `int` in einen `double` sicher und damit eine [implizite Umwandlung][type-casting].
Die Umwandlung von einem `double` in einen `int` kann jedoch bedeuten, dass Daten verloren gehen, deshalb ist dafür eine [explizite Umwandlung][type-casting] nötig.

```java
int i = 9;
double d = 2.72;

// Safe conversion, thus implicit conversion
double fromInt = i;

// Potentially unsafe conversion, thus explicit conversion
int fromDouble = (int)d;
```
