# Überblick

Exceptions sind eine Form der Fehlerbehandlung.
Sie heißen Exceptions, weil sie normalerweise auftreten, wenn etwas Unerwartetes passiert.

An jeder Stelle in unserem Code können wir eine Exception auslösen.
Dazu verwenden wir die `raise`-Methode und übergeben ihr ein Objekt, normalerweise ein Exception-Objekt, obwohl wir auch einfache Strings verwenden können.
In den Stubs der Übungen siehst du zum Beispiel, dass wir das eingebaute `RuntimeError` verwenden, um Ruby mitzuteilen, dass eine Methode noch nicht implementiert wurde.
Du kannst auch die Kurzschreibweise `raise(ExceptionObject, params)` verwenden.
Wenn die Exception-Klasse weggelassen wird, wird standardmäßig `RuntimeError` verwendet.

Zum Beispiel:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

Wenn Ruby das sieht, reicht es den Fehler bis an die Spitze des Programms weiter und beendet dann das Programm.

Wenn du zum Beispiel versuchst, etwas durch null zu teilen, siehst du ungefähr Folgendes:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

Wichtig ist, dass Exceptions nur dann verwendet werden sollten, wenn etwas Außergewöhnliches passiert, also ein Fehler, der eine besondere Behandlung braucht.
Exceptions sollten nicht für den Kontrollfluss eines Programms verwendet werden, denn das gilt als schlechtes Design und führt oft zu schlechter Leistung und Wartbarkeit.

## Klassenhierarchie

In Ruby folgen Exceptions einer Klassenhierarchie, an deren Spitze `Exception` als Basisklasse steht.
Das sind die gebräuchlichsten eingebauten Exceptions von Ruby:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

Wenn du Fehler einer bestimmten Klasse abfängst, fängst du auch die Fehler ihrer Unterklassen ab.
Deshalb kann es gefährlich sein, von `Exception` aus abzufangen.
Ruby verwendet Exceptions auch, um Nachrichten von den Signalen des Betriebssystems zu behandeln, zum Beispiel `ctrl-c`.
Das bedeutet, dass du mit `Exception` auch diese System-Signale abfängst.
Um unerwartetes Verhalten zu vermeiden, fängst du daher üblicherweise alle Fehler über `StandardError` ab.

## Rescue-Syntax

Ruby bietet außerdem erweiterte `rescue`-Klauseln für Situationen, die eine besondere Behandlung erfordern:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

Das ist zum Beispiel bei Netzwerk-I/O nützlich, wo wir immer daran denken müssen, die Verbindung zu schließen.

Ruby-`rescue`-Blöcke können auch das Schlüsselwort `retry` verwenden, das alles zwischen `begin` und `rescue` erneut ausführt:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
