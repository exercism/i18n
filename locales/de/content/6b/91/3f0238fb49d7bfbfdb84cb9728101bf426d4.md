# Über

Ein `Iterator` in Gleam ist einer Liste insofern ähnlich, als dass er eine geordnete Sammlung von Werten ist, bei der alle Werte vom selben Typ sind. Er unterscheidet sich von einer Liste dadurch, dass er lazy ist: Er speichert nicht alle seine Werte auf einmal im Speicher, sondern berechnet sie erst, wenn sie gebraucht werden.

Das ist nützlich, wenn du mit Sequenzen arbeitest, die sehr groß oder sogar unendlich sind, denn so kannst du mit ihnen arbeiten, auch wenn nicht genug freier Speicher vorhanden ist, um sie alle auf einmal zu speichern.

Das Modul `gleam/iterator` definiert den Typ `Iterator` sowie Funktionen für die Arbeit mit Iteratoren.

Viele der Funktionen für Listen gibt es auch für Iteratoren, zum Beispiel `map`, `filter` und `take`. Diese Funktionen geben Iteratoren zurück, das heißt, sie erledigen erst dann tatsächlich Arbeit, wenn der Iterator konsumiert wird.

```gleam
let iter = 
  [1, 2, 3, 4, 5, 6]
  |> iterator.from_list
  |> iterator.filter(fn(x) { x > 2 })
  |> iterator.take(2)

// No work has been done yet as the iterator has not been consumed

// Consume the iterator and collect the values into a list
iterator.to_list(iter)
// -> [3, 4]
```

Mit der Funktion `unfold` kannst du Iteratoren aus einer Funktion erstellen, die wiederholt aufgerufen wird, um den nächsten Wert in der Sequenz zu erzeugen.

Hier wird die Funktion `unfold` verwendet, um einen Iterator zu erstellen, der die Fibonacci-Folge erzeugt:

```gleam 
iterator.unfold(#(0, 1), fn(pair) {
  let x = pair.0 + pair.1
  iterator.Next(element: x, accumulator: #(pair.1, x))
})
|> iterator.take(6)
|> iterator.to_list
// -> [1, 2, 3, 5, 8, 13]
```

Die Sequenz ist hier unendlich, deshalb wird die Funktion `take` verwendet, um sie endlich zu machen, bevor die Werte in einer Liste gesammelt werden. Wenn `to_list` auf einen unendlichen Iterator aufgerufen wird, läuft das Programm so lange, bis ihm der Speicher ausgeht und es abstürzt.
