# Einführung

Speicherklassen-Spezifizierer bestimmen, wie Variablen im Speicher abgelegt werden.
Sie hängen eng mit der Speicherdauer (auch Lebensdauer genannt) eines Werts zusammen.

## auto: die Standard-Speicherklasse für Variablen mit Funktions- oder Blockgültigkeitsbereich

Da Variablen, die in einem Block oder einer Funktion definiert werden, standardmäßig `auto` sind, ist es unüblich, den Spezifizierer ausdrücklich zu verwenden.
Die Lebensdauer einer `auto`-Variablen beginnt, wenn ihr Block betreten wird, und endet, wenn er wieder verlassen wird.
Beim Betreten des Blocks wird für eine `auto`-Variable Speicher reserviert, _aber kein Standardwert festgelegt_.

## static: der Speicherklassen-Spezifizierer, den man nicht mit dem static-Bindungstyp verwechseln sollte

Wird eine Variable außerhalb eines Blocks oder einer Funktion definiert und mit `static` gekennzeichnet, bezieht sich `static` auf ihre Bindung: Sie ist dann nur innerhalb der Datei zugänglich.
Wird eine Variable innerhalb einer Funktion oder in einem Block innerhalb einer Funktion definiert und mit `static` gekennzeichnet, hat sie die Speicherdauer `static`.
Der Wert einer `static`-Variablen bleibt zwischen Aufrufen der Funktion bzw. des Blocks erhalten.

## extern: wie du auf eine Variable in einer anderen Übersetzungseinheit zugreifst

Eine Übersetzungseinheit besteht aus einer Quelldatei und allen weiteren Dateien, die sie mit `#include` einbindet.
Obwohl eine Variable mit Dateigültigkeitsbereich als `extern` deklariert und initialisiert werden kann, dient das Schlüsselwort `extern` normalerweise dazu, auf eine vorhandene Variable zu verweisen, und nicht dazu, eine neue zu definieren.
Die Variable, auf die `extern` verweist, muss Dateigültigkeitsbereich haben.
Eine Variable mit Dateigültigkeitsbereich hat immer `static`-Speicherdauer.
Eine Variable in einer eingebundenen Datei muss externe Bindung haben, damit die einbindende Datei auf sie zugreifen kann.

## register: wie du den Zugriff auf eine Variable möglicherweise beschleunigst

Eine als `register` gekennzeichnete Variable drückt den Wunsch des Programmierers aus, den Wert für einen schnellen Zugriff in einem Register abzulegen.
Eine `register`-Variable ist wie eine `auto`-Variable: Sie muss Funktions- oder Blockgültigkeitsbereich haben.
Da der Wert im Register statt im Speicher liegen soll, sollte der Compiler den Zugriff auf die Adresse der Variable verweigern, denn die Adresse eines Registers lässt sich nicht bilden.
Eine Speicheradresse selbst kann jedoch durchaus in einem Register liegen.
`register` ist im Grunde nur ein Hinweis, denn der Wert landet möglicherweise nicht tatsächlich in einem Register.

## typedef: der Speicherklassen-Spezifizierer, der keiner ist

`typedef` wird nur aus syntaktischen Gründen als Speicherklassen-Spezifizierer bezeichnet.
Denn ein Speicherklassen-Spezifizierer kann nicht zusammen mit einem anderen Speicherklassen-Spezifizierer verwendet werden.
Also ist `typedef auto int i = 42;` genauso unzulässig wie `static auto int i = 42;`.
