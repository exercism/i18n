# Über

Slices in Go ähneln Listen oder Arrays in anderen Sprachen.
Sie enthalten mehrere Elemente eines bestimmten Typs (oder eines Interfaces).

Slices in Go basieren auf Arrays.
Arrays haben eine feste Größe.
Ein Slice ist dagegen eine dynamisch große, flexible Sicht auf die Elemente eines Arrays.

Ein Slice wird als `[]T` geschrieben, wobei `T` der Typ der Elemente im Slice ist:

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

Mit eckigen Klammern kannst du ein Element an einem bestimmten nullbasierten Index lesen oder setzen:

```go
withData[1] = 5
x := withData[1] // x is now 5
```

Du kannst aus einem vorhandenen Slice einen neuen Slice erstellen, indem du einen Bereich von Elementen auswählst.
Wieder mit eckigen Klammern, aber diesmal gibst du sowohl einen Startindex (inklusive) als auch einen Endindex (exklusiv) an.
Wenn du keinen Startindex angibst, ist er standardmäßig 0.
Wenn du keinen Endindex angibst, ist er standardmäßig die Länge des Slices.

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

Mit der Funktion `append` kannst du Elemente zu einem Slice hinzufügen.
Im Folgenden hängen wir `4` und `2` an den Slice `a` an.

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append` gibt immer einen neuen Slice zurück. Wenn wir nur Elemente an einen vorhandenen Slice anhängen wollen, ist es üblich, das Ergebnis wieder der Slice-Variablen zuzuweisen, die wir als erstes Argument übergeben, so wie oben.

Mit `append` kannst du auch zwei Slices zusammenführen:

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## Indizes in Slices

Wenn du mit Indizes von Slices arbeitest, solltest du das immer mit einer Prüfung absichern, die sicherstellt, dass der Index tatsächlich existiert.
Wenn du das nicht tust, stürzt die gesamte Anwendung ab.

## Leere Slices

`nil`-Slices sind der Standard für leere Slices.
Sie haben keine Nachteile gegenüber einem Slice, der keine Werte enthält.
Die Funktion `len` funktioniert mit `nil`-Slices, du kannst Elemente hinzufügen, ohne den Slice zu initialisieren, und so weiter.
Wenn du einen neuen Slice erstellst, bevorzuge `var s []int` (`nil`-Slice) gegenüber `s := []int{}` (leerer Slice, nicht `nil`).

## Performance

Wenn du Slices erstellst, die anschließend nach und nach gefüllt werden, gibt es eine einfache Möglichkeit, die Performance zu verbessern, sofern die endgültige Größe des Slices bekannt ist.
Der Schlüssel ist, die Anzahl der Speicherallokationen zu minimieren. Allokationen sind ziemlich teuer und passieren, wenn der Slice über seinen zugewiesenen Speicherplatz hinauswächst.
Am sichersten gibst du dem Slice mit `s := make([]int, 0, cap)` eine Kapazität `cap` und hängst dann wie gewohnt mit `append` Elemente an.
Auf diese Weise wird der Platz für `cap` Elemente sofort reserviert, während die Länge des Slices null ist.
In der Praxis ist `cap` oft die Länge eines anderen Slices: `s := make([]int, 0, len(otherSlice))`.

## Append ist keine reine Funktion

Die Funktion `append` von Go ist auf Performance optimiert und kopiert daher den Eingabe-Slice nicht.
Das bedeutet, dass der ursprüngliche Slice (der erste Parameter von `append`) manchmal verändert wird.
