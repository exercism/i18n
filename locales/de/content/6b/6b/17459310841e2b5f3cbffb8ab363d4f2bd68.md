# Anweisungen

Die Arbeit am RPN-Rechner bei _Instruments of Texas_ läuft gut. Dein Team möchte jetzt eine String-Version der Gleichung in eine _IO_-Ressource schreiben können.

## 1. Eine Datei öffnen

Dein Team hat noch nicht entschieden, auf welchen Gerätetyp die Gleichung geschrieben werden soll, also schlägst du einen Ansatz mit _dynamischem Dispatch_ vor, damit du die Ressource in die Funktion injizieren kannst, statt sie hart zu kodieren. Implementiere die Funktion `write/3`, um mit der Ressource und dem Dateinamen ein _IO-Gerät_ zu öffnen.

Du kannst davon ausgehen, dass `resource` immer ein Atom ist, das ein Modul repräsentiert, welches eine Funktion `open/1` hat, die `{:ok, io_device}` zurückgibt.

Wenn die Funktion erfolgreich ist, gib ein Ok-Tupel mit der Gleichung zurück.

```elixir
RPNCalculator.Output.write(resource, "file_to_be_written", "1 4 +")
# {:ok, "1 4 +"}
```

## 2. Versuch, in das IO-Gerät zu schreiben

Jetzt, wo du das IO-Gerät geöffnet hast, versuche mit `IO.write/2` hineinzuschreiben.

Erweitere die Funktion `write/3`, damit sie diese Aktion ausführt. Der Schreibversuch kann einen Fehler auslösen; fange den Fehler ab und gib dabei ein Fehler-Tupel zurück:

```elixir
RPNCalculator.Output.write(resource, "bad_file", "1 4 +")
# {:error, "Unable to write to resource"}
```

## 3. Das IO-Gerät schließen

Es ist gute Praxis, immer zu versuchen, Ressourcen freizugeben, die du geöffnet hast, selbst wenn die Funktion, die die Ressource nutzt, einen Fehler auslöst. Erweitere die Funktion `write/3`, damit sie die Close-Funktion der Ressource aufruft, um das _IO-Gerät_ zu schließen.

Du kannst davon ausgehen, dass `resource` immer ein Atom ist, das ein Modul repräsentiert, welches eine Funktion `close/1` hat, die ein _IO-Gerät_ entgegennimmt.
