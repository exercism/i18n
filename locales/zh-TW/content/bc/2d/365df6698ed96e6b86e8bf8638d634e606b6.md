# 關於

`MACRO:`宣告是一種詞，它的*主體*會在編譯時期執行。主體會從編譯時期的堆疊取出字面值引數，而且必須在堆疊上留下一個 quotation。接著編譯器會用那個 quotation 取代巨集呼叫，所以執行時期的程式永遠看不到巨集，只看得到它產生的程式碼。

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- compound )
    dup append ;
```

如果呼叫端寫下`[ 1 + ] twice`，編譯器就會在堆疊上帶著`[ 1 + ]`執行主體，取回`[ 1 + 1 + ]`，再把它拼接進去。這沒有任何執行時期的額外負擔，因為巨集取代掉的迴圈或組合子已經消失了。

## 輸入必須是字面值

因為主體是在編譯時期執行，所以每個輸入在呼叫端都必須是*字面值*，例如`[ … ]` quotation、數字、陣列或字串。傳入非字面值的值（只有在執行時期才知道的值）會是編譯時期錯誤。

```factor
! works: [ 1 + ] is a literal quotation
: inc-twice ( x -- y ) [ 1 + ] twice ;

! refused: f is a literal, but the macro can't run with a non-quotation
! input where the body expects to call `append` on it
```

## 結構化輸入產生結構化輸出

有趣的巨集會接受一個*結構*（陣列、字面值配對序列），並產生形狀取決於該結構的程式碼。這個練習的`each-literal`會接受一個字面值序列和一個 quotation，並為每個元素產生一份柯里化並內嵌的 quotation 副本。執行時期的程式是直線程式碼，沒有`each`，也沒有逐元素分派。序列的疊代完全發生在編譯時期。

## 為什麼沒有衛生的問題

Lisp 巨集得和*衛生*問題搏鬥：引入區域名稱的巨集可能會和呼叫端的名稱衝突，因而需要`gensym`或一套衛生系統。Factor 沒有這個問題，因為 quotation 是*已解析的詞參照*序列，每個詞都是在剖析時期查找，而不是在展開時期以符號方式查找。巨集建構出的 quotation 裡的`dup`，永遠都是`kernel:dup`，無論呼叫端存在哪些名稱。

代價是：Factor 巨集無法像`defmacro`那樣引入新的綁定。它們只能用剖析器已經看過的詞來建構程式碼。對大多數的元程式設計來說，這樣就夠了。

## 相關形式（本練習未涵蓋）

- `MACRO::`：`MACRO:`的區域變數形式變體，就像`::`是`:`的區域變數形式一樣。當主體需要多次參照它的輸入時很方便。
- `<< … >>`：剖析時期求值區塊。在編譯時期執行一般的 Factor 程式，但不受「必須回傳 quotation」的契約約束。適合用來計算必須在剖析時期就存在的值（例如由環境查詢推導出的`CONSTANT:`）。
- `SYNTAX:`：*剖析詞*。這是完全不同的東西，它們操作的是剖析器的權杖串流，而不是值，而且執行的階段更早。用來定義新的字面值語法（`T{ }`、`H{ }`）。不屬於這個概念的範疇。
- `functor:`：宣告式範本，能從單一規格產生一組相關的詞。它建構在巨集機制之上，屬於函式庫作者的領域。
