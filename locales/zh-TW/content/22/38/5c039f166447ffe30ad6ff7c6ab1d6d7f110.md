# 簡介

[模式比對][pattern-matching]能讓你寫出表達力豐富的分支程式碼，而[解構][destructuring]則能把值優雅地綁定到變數上。
對 Elm 程式設計師來說，精通這兩者極為實用，而且兩者搭配使用時，更能大幅提升程式碼的可讀性。

## 簡單的模式比對

模式比對是指依照所處理資料的形狀，決定程式碼要走哪個分支。
因此它很自然地契合自訂型別的概念，因為自訂型別正是在表達某份資料可能呈現的多種形狀。
舉例來說，假設有一個`Color`自訂型別，定義成`Blue`或`Red`，我們就能寫一個`toString`函式，對顏色做模式比對，回傳正確的字串。

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

模式比對也能用在並非單純列舉的自訂型別上。
來看看一個`hello`函式，它的參數是`Maybe String`，裡面可能是一個人的名字，也可能什麼都沒有。
做模式比對時，我們可以用小寫名稱把資料綁定到該變數，並在配對式的右側使用它。

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

模式比對必須窮盡所有情況，否則編譯器會拒絕編譯。
但有時候，我們並不在意某些資料，或某個 case 運算式的某些分支。
這時候，我們不必特地找一個變數名稱來綁定、也不必為所有情況都寫出分支，只要使用底線萬用字元`_`就好。

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## 進階模式比對

除了自訂型別之外，我們也可以對帶有字面值的型別做模式比對，例如`Char`、`String`、`Int`和`Floats`。

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

若要在不使用巢狀結構的情況下比對多個值，Elm 常見的技巧是把要比對的值組成[臨時元組][ad-hoc-tuples]，像這樣：

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

既然陣列對函式程式設計師來說如此親切，[我們當然也能對它做模式比對][pattern-match-lists]，用的正是建立陣列時的同一套語法，也就是`::`運算子。

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

最後，模式比對甚至能遞迴進行，讓你深入探索複雜又遞迴的型別。

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## 解構

解構和模式比對非常相似，兩者都能把變數綁定到型別內部的資料。
主要差別在於：當可能的形狀只有一種時，我們把這個機制稱為「解構」；形狀有多種時，則稱為模式比對。
解構經常出現在`let`綁定、函式引數，當然還有 case 運算式裡，與模式比對混用。

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

解構可以用在只有單一變體的自訂型別、元組，也能用在紀錄上，而且相當方便。
要[解構紀錄][records-pattern-matching]，可以使用任意數量的欄位，一個、兩個、……或全部欄位。

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

可惜的是，Elm 語法並不支援對紀錄做遞迴解構。
在前面的`Circle`範例中，沒有辦法一次就取得圓心的`x`` and `y位置。
我們必須先取得`center`，再把它解構成`x`和`y`位置。

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

最後再送你一個小技巧！
有時候，我們希望既能輕鬆取用某個東西的整體，也能取用它的某一部分。
這時候[`as`關鍵字][as-keyword]就很好用了。
它能讓你為整體取一個別名，同時又能解構它的內容。

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
