# 簡介

_「日期和時間這種東西，我們連小孩子都在教。能有多難？」_

許多程式設計師都犯過這個錯誤，而隨之而來的經歷，往往對他們的健康和幸福造成不良影響。

任何要用日期和時間進行稍微複雜的程式設計的人，至少都應該有心理準備，去理解並減輕潛在的問題。

本文件會試著概述 R 如何處理日期和時間，但若需要更多細節，還是得查閱完整的文件。

身為一門資料科學語言，日期和時間在 R 裡格外重要。
許多資料都是以時間序列的形式出現：疾病爆發期間的每日病患人數、政府回報的每月就業數據、築巢聚落裡的鳥類數量、主要經濟體的年度 GDP，還有數不完的例子。

_這是不是代表 R 讓日期和時間的處理變得很簡單？_

很遺憾，並不是！

Base R 的日期和時間功能評價不佳，而且大部分現在已經很少人用了。

[`lubridate`][web-lubridate] 套件是一大進步，但要有些心理準備：這是一套龐大又複雜的程式庫，是為了處理各式各樣龐大又複雜的問題而設計的。

`lubridate` 原本是獨立的，現在則收錄在 `tidyverse` 系列中。
可以用 `library(lubridate)` 或 `library(tidyverse)` 載入它。

以下是一些能幫助你使用 `lubridate` 的資源：

- 一份[參考頁面][ref-lubridate]。
- 一份 PDF 格式的[速查表][cheat-lubridate]。
- 《R for Data Science》裡的[一個章節][book-dates-times]。

## 日期與日期時間

`date` 就只是一天，不帶任何時間資訊。

在內部，日期是以自 `1970-01-01` 起算的（帶正負號的）天數來儲存。

```R
today()
#> [1] "2026-04-22"
```

`datetime` 則結合了日期、時間和時區資訊。

在內部，它是以自 1970 年初起算、以 UTC 時區計的秒數來儲存。

```R
now()
#> [1] "2026-04-22 15:37:11 MST"  # mid-afternoon in Arizona
```

或許令人意外的是，R 對「只有時間」的值並沒有內部的表示方式。

## 處理 `date` 與 `datetime` 值

日期和時間最常見的需求大概是：

- 解析某種合適的輸入格式，來建構出日期或日期時間。
- 從日期或日期時間取得所需的數字或字串格式。
- 對日期或日期時間的值套用偏移量。
- 計算兩個這類值之間的時間跨度。
- 取得目前的日期（用 `today()`）和／或日期時間（用 `now()`）。

### 從字串解析

日期和時間的寫法有很多種，而且往往因文化而異。
像「7/6/23」這種全數字的日期既模稜兩可又容易混淆，還曾在跨國組織裡造成許多代價高昂的錯誤（_作者是從慘痛的親身經驗說這句話的_）。

國際標準（年-月-日）定義在 [`ISO 8601`][wiki-ISO8601] 中，有兩大優點：

- 解析起來快速又明確。
- 排序很容易，因為可以把日期時間當成一般文字，依字母順序排序。

不過，資料科學的重點就是運用你能找到的任何資料，而且抱怨別人怎麼格式化資料，通常沒什麼意義。

Base R 有一些轉換函式，會接收一個格式字串（預設為 ISO 8601）。

```R
as.Date("2026-04-22")
#> [1] "2026-04-22"
as.Date("4/22/26", format = "%m/%d/%y")
#> [1] "2026-04-22"
as.POSIXct("2026-04-22 15:30:09 MST")
#> [1] "2026-04-22 15:30:09 MST"
```

這些格式字串類似於問世數十年的 `strptime()` 函式，_許多_語言都有提供。
熟悉這種語法的程式設計師，也可以選擇使用 lubridate 裡的 [`fast_strptime()`][ref-parse_dt] 函式。

更有用的是，`lubridate` 提供了各式各樣的[輔助函式][ref-parsing]，其名稱代表了欄位的順序。
一旦這些函式知道要找哪些值、以及用什麼順序，解析就靈活得令人印象深刻。

```R
mdy("4/22/26")
#> [1] "2026-04-22"
mdy("April 22nd 26")
#> [1] "2026-04-22"
mdy("Wednesday, April 22nd 2026")
#> [1] "2026-04-22"
mdy_hm("Wednesday, April 22nd 2026, 4:14 pm")
#> [1] "2026-04-22 16:14:00 UTC"  # defaults to your OS timezone
```

### 從數值建構

當你的程式把日期／日期時間的各個組成部分當成獨立的數字時，可以用 [`make_date()` 或 `make_datetime()`][ref-make_datetime] 把它們組起來。

以下是可以提供的組成部分，並顯示它們的順序與預設值：

```R
make_datetime(
  year = 1970L,
  month = 1L,
  day = 1L,
  hour = 0L,
  min = 0L,
  sec = 0,
  tz = "UTC"
)
#> [1] "1970-01-01 UTC"


make_datetime(2026, 4, 22, 17)
#> [1] "2026-04-22 17:00:00 UTC"
```

當然，`make_date()` 只接受年、月、日三個引數。

### 以人類可讀的形式輸出

R 主控台會自動把日期／日期時間顯示成字串表示。
這通常很方便，但有時也會誤導人。

在內部，日期和日期時間是數字（外加一些屬性），不是字串。
在預期會拿到字串的地方回傳日期（時間），會造成問題，所以我們得知道怎麼做轉換。

簡單的做法是用 Base R 的 [`as.character()`][ref-ascharacter]，它會輸出 ISO 8601 格式的字串。

針對日期時間，還有一個 [`format_ISO8601()`][ref-iso8601] 函式，可以選擇四捨五入到想要的精度。

```R
today() |> as.character()  # a date
#> [1] "2026-04-23"
now() |> as.character()  # a datetime
#> [1] "2026-04-23 09:07:09.779319"
now() |> format_ISO8601() # defaults to nearest second
#> [1] "2026-04-23T09:07:38"
```

沒幾個非程式設計師想看到 ISO 8601 的輸出，所以處理因文化而異的日期／時間格式就變得不可或缺。

Base R 提供了 [`format()`][ref-format] 函式，它使用的格式字串，類似於許多其他語言都有的、歷史悠久的 `strftime()` 函式。

```R
format(today(), "%A, %d %B %Y")
#> [1] "Thursday, 23 April 2026"
```

Base R 的做法雖然醜，但很可靠。
以下是一些比較常見的代碼：

代碼 | 結果
-- | --
%d | 月中的日（5、17、28 等）
%a | 縮寫的星期（Mon、Tue、Wed 等）
%A | 完整的星期（Monday、Tuesday 等）
%w | 星期編號（0-6，星期日是 0）
%u | 星期編號（1-7，星期一是 1）
%b | 縮寫的月份（Jan、Feb 等）
%B | 完整的月份（January、February 等）
%y | 兩位數年份（例如 89）
%Y | 四位數年份（例如 1989）
%h | 小時（24 小時制）
%m | 分鐘
%s | 秒
%z | 與 UTC 的偏移
%Z | 時區（字元）

Lubridate 想用 [`stamp()`][ref-stamp] 函式提供更貼近人類習慣的替代方案，還有範圍更窄的 `stamp_date()` 和 `stamp_time()`。

這些函式會接收一個範本字串，作為想要輸出的範例，並建立一個自訂函式來產生那種格式。

Lubridate 會試著猜測格式，但常常碰到模稜兩可的情況，而產生錯誤的結果。
要有心理準備，得提供格式字串（例如 `"dmy"`）來消除歧義。

在 Exercism 上，指定 `locale = "C"` 也很有用，可以繞過你的系統地區設定，改用英文運作（這也是測試所預期的）。
_地區設定很複雜！_

```R
sf <- stamp("Saturday, June 27, 2026 at 14:45", locale = "C")
#> Multiple formats matched: "%A, %B %d, %Y at %H:%M"(1), "Saturday, %Om %d, %Y at %H:%M"(1), "Saturday, %B %d, %Y at %H:%M"(1), "%A, %Om %d, %Y at %H:%M"(0)
#> Using: "%A, %B %d, %Y at %H:%M"

sf(make_datetime(2023, 3, 29, 15, 0, 0))
#> [1] "Wednesday, March 29, 2023 at 15:00"
```

### 設定或擷取組成部分

Lubridate 提供了[許多函式][ref-set-get]來取得或設定日期或日期時間的元素：像 `year()` 和 `second()` 這種顯而易見的，也有像 `quarter()` 和 `epiweek()` 這種更專門的。

這些函式全都能用來取得值，而大多數也能用來設定值。

```R
dt <- now()
dt
#> [1] "2026-04-23 15:47:11 MST"

# get
month(dt)
#> [1] 4

# set
month(dt) <- 11
dt
#> [1] "2026-11-23 15:47:11 MST"
```

對 `wday()`（一週中的第幾天）和 `month()` 來說，預設輸出是整數，但：

- 設定 `labels = TRUE` 會回傳對應目前地區設定的縮寫字元字串。
- 同時設定 `abbr = FALSE` 則會回傳完整名稱。

```R
d <- today()
d
#> [1] "2026-04-23"
wday(d)
#> [1] 5
wday(d, label = TRUE)
#> [1] Thu
#> Levels: Sun < Mon < Tue < Wed < Thu < Fri < Sat
wday(d, label = TRUE, abbr = FALSE)
#> [1] Thursday
#> Levels: Sunday < Monday < Tuesday < Wednesday < Thursday < Friday < Saturday
```

這些標籤是 `categorical variables`，會是另一個概念的主題。
值會限制在列出的 `Levels` 裡，這也顯示了排序順序。

一週預設從星期日開始，但可以用 `week_start` 引數改變（星期一想用 `1`）。

```R
dt <- make_datetime(2026, 4, 23)

# default behavior
wday(dt)
#> [1] 5
wday(dt, label = T)
#> [1] Thu

# set week_start to Monday
wday(dt, week_start = 1)
#> [1] 4
```

有幾個工具函式會回傳 `TRUE`/`FALSE` 值，例如 `leap_year()` 和 `dst()`（日光節約時間是否生效？）。

每個月的長度不一，所以 `days_in_month()` 會給出整數值。

## 時間跨度

`date` 和 `datetime` 值都代表時間軸上的某個瞬間。

我們要怎麼處理像「昨天的這個時候」或「從現在算起一週後」這樣的概念？

熟悉其他科學導向語言的學生，可能知道 Python 的 `datetime.timedelta` 或 Julia 的 `Period` 型別。

相對地，R 用來表示時間跨度的方法不下三種，各有不同的長處與限制。
一如往常，請挑選最適合你情境的那一種。

各種跨度之間可以輕鬆互相轉換，用 `as.period()`、`as_duration()` 和 `as.interval()`。

跨度的型別可以用 `is.period()` 之類的函式來查詢。

### 期間

`period`，例如 `hours(3)`，可以用來把時鐘時間增加 3 小時。

像日光節約時間（DST）這類的不規則情況，大致上會被忽略。

所有 period 都是單位名稱的複數形：`years`、`weeks` 等。

```R
d <- today()
d
#> [1] "2026-04-25"

d + weeks(2)
#> [1] "2026-05-09"

# dates are coerced to datetimes at midnight if necessary
d - hours(20)
#> [1] "2026-04-24 04:00:00 UTC"

hours(3)
#> [1] "3H 0M 0S"
```

### 持續時間

`duration`，例如 `dhours(3)`，會把物理時間增加 3 小時，並顧及像 DST 這類讓時鐘時間偏離物理時間的不規則情況。

所有 duration 都是在對應的 period 名稱前面加上 `d` 前綴：`dyears`、`dweeks` 等。

```R
dhours(3)
#> [1] "10800s (~3 hours)"
```

### 區間

`interval` 是起始時間和結束時間的組合，可以用 [`interval()`][ref-interval] 函式或 `%--%` 中綴運算子來建立。

```R
# the next 2 lines were run about 33s apart, so now() is different
dt1 <- now()
dt2 <- now() + hours(1)

# interval(0 function)
ivl <- interval(dt1, dt2)
ivl
#> [1] 2026-04-24 16:24:54 MST--2026-04-24 17:25:27 MST

# infix operator
iv2 <- dt1 %--% dt2
iv2 == iv1
#> [1] TRUE
```

## 時區

處理時區可能很棘手。
下面這段引文出自 Python 文件，但對 R 也同樣適用：

> 「世界各地調整時間的規則，政治成分多於理性成分，而且經常改變；除了 UTC 之外，沒有哪一套標準適合所有應用。」

關於時區，有幾個一般的重點：

- `datetime` 一律包含時區（`tz`）；`date` 則不具備時區感知。
- 日期時間的建構子通常預設為 [UTC][wiki-UTC]。
- [`now()`][ref-now] 函式是個例外：它會從系統時鐘取得你的當地時間，包括 `tz`。
  預設會使用當地的 `tz`，但也可以指定其他的，例如 `now("UTC")`。

```R
# timezone defaults to UTC
local <- ymd_hm("2026-04-25 10:32")
local
#> [1] "2026-04-25 10:32:00 UTC"

# timezone can be specified
AZ <- ymd_hm("2026-04-25 10:32", tz = "America/Phoenix")
AZ
#> [1] "2026-04-25 10:32:00 MST"

# same clocktime, different tz
local - AZ
#> Time difference of -7 hours
```

跟時區相關的運算，用 duration 做比用 period 做更可靠。
