# 關於

雜湊集合以雜湊為底層機制，實作了[`sets`][sets] [協定][set-protocol]，提供平均 O(1) 的插入、查詢與刪除。它們可以原地修改，因此非常適合圖形走訪中的*已造訪集合*模式。

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| 詞            | 效果                                       |
|---------------|-------------------------------------------|
| `HS{ }`       | 空的雜湊集合字面值（共用，記得先`clone`！） |
| `>hash-set`   | `( seq -- set )`，從序列建立一個全新的集合（會去除重複） |
| `adjoin`      | `( elt set -- )`，破壞性插入               |
| `in?`         | `( elt set -- ? )`，成員測試               |
| `delete`      | `( elt set -- )`，破壞性移除               |
| `cardinality` | `( set -- n )`，元素的數量                 |
| `null?`       | `( set -- ? )`，集合為空時為 true          |
| `members`     | `( set -- seq )`，列舉為序列               |
| `union`       | `( set1 set2 -- set )`                     |
| `intersect`   | `( set1 set2 -- set )`                     |
| `diff`        | `( set1 set2 -- set )`                     |
| `set-like`    | `( set exemplar -- set' )`，將`set`強制轉換成`exemplar`所屬的類別 |

想用現有的資料建立集合時，`>hash-set`能一步轉換任何序列，並捨棄重複的項目，例如`{ 2 3 2 5 } >hash-set`會得到`HS{ 2 3 5 }`。它對應的是「批次」的做法，而反覆使用`adjoin`則是一筆一筆地擴充集合。

關於`in?`與`member?`（來自`sequences`），有個微妙的重點：兩者都在做成員測試，但`member?`會對序列做線性掃描，而`in?`則會分派到該集合型別的協定方法；對`HS{ }`來說，就是一次雜湊查詢。一旦「已造訪」容器裡的項目超過幾筆，就改用`in?`吧。

`null?`能回答「這個集合是空的嗎？」，而不必計算完整的`cardinality`，它也是「還有東西要處理嗎？」最自然的守衛條件。當待處理清單以集合的形式保存時，`[ set null? ] [ … ] until`會把它一路清空。

## 和雜湊表搭配使用

用`HS{ }`回答「X 造訪過了嗎？」，正好能與用`H{ }`回答「X 的鄰居是誰？」互相搭配。教科書上的 DFS 不過就是這樣：

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

已造訪集合負責去除重複的工作；堆疊串起邊界節點（透過`push`/`pop`達成 LIFO）；鄰居映射（一個雜湊表）則提供圖形。對於可達性問題來說，造訪順序並不重要，這也是為什麼用向量當堆疊就夠了；同樣的結構下，真正的 BFS 會把向量換成[`<dlist>`][dlist]，改為從前端取出。
