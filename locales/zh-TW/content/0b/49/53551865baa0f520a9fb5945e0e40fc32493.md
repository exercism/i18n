# 簡介

海岸巡邏艦上的*訊號員*負責維護訊息記錄。原始的訊號旗送來時，外頭會用標記字元框住；讀數必須轉換成能透過線路傳送的格式；成對或三筆一組的觀測值則要即時彙總。Factor 標準函式庫裡的幾個慣用寫法，就能搞定大部分的工作。

## `unparse`：把值轉成原始碼

[`unparse`][unparse]（位於 `prettyprint`）會回傳任何值的原始碼形式文字：

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` 是解析器的反向操作：來回一趟 `dup unparse parse` 就能重建原本的值。要把資料序列化成接收端會再解析回來的傳輸格式，它正是合適的工具；但用來產生人類可讀的輸出就不對了（字串會保留引號，向量會保留 `V{ ... }`，諸如此類）。

## slice 變體：是檢視，不是複本

`sequences` 裡的 `head` 和 `tail` 會把你要保留的部分*複製*成一個全新的序列。加上 `-slice` 的對應版本則會回傳一個 `slice` 物件，也就是一個裝著起始索引、結束索引和底層序列的元組，它實作了[序列協定][sequence-protocol]，而且不會複製：

| 詞            | 效果                                             |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )`：複製前 n 個                |
| `head-slice`  | `( seq n -- slice )`：前 n 個的檢視               |
| `tail`        | `( seq n -- newseq )`：從索引 n 開始複製到最後     |
| `tail-slice`  | `( seq n -- slice )`：從索引 n 開始的檢視          |
| `head*`       | `( seq n -- newseq )`：複製除了最後 n 個以外的全部 |
| `head-slice*` | `( seq n -- slice )`：除了最後 n 個以外的檢視      |
| `tail*`       | `( seq n -- newseq )`：複製最後 n 個              |
| `tail-slice*` | `( seq n -- slice )`：最後 n 個的檢視             |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

`slice` *本身*就是一種序列，所以任何接受序列的地方也能接受 slice：`length`、`first`、`each` 等等全都能直接運作，不需要複製。如果測試需要和字串字面值比較，可以用 `>string` 轉型。

## `?head` 和 `?tail`：有標記就移除

被框住的讀數會帶著標記文字，而這些標記不一定存在。`?head` 和 `?tail`（位於 `splitting`）會試著移除前綴或後綴，回傳（可能已經縮短的）序列*以及*一個指出是否找到標記的布林值：

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

結尾的那個布林值讓它們很適合當作防護條件：把 `?head` 搭配 `if`，就能依框架是否存在來分支；搭配 `unless`，則可以擋掉缺少預期標記的輸入。

## `<repetition>`：N 個複本，虛擬產生

[`<repetition>`][repetition]（位於 `sequences`）是另一種不會複製的虛擬序列：`( len elt -- repetition )` 會建立一個由 `len` 個元素組成的序列，每個元素都是 `elt`，而且不會實際配置那麼多個位置：

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

`elt` 本身也可以是一個序列，此時每個複本都是同一個序列。接著再用 `concat` 把這些複本首尾相接：

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

和 `slice` 一樣，結果*本身*就是一種序列：`length`、`each` 等都能直接套用。想把手上的訊號碼補到固定寬度，或鋪出一連串重複的標記時，就可以派它上場；只有在真的需要具體序列時，才用 `>string`（或 `>array`）轉型。

## `<clumps>`：重疊視窗，虛擬產生

[`<clumps>`][clumps]（位於 `grouping`）是第三種不會複製的虛擬序列：`( seq n -- clumps )` 把 `seq` 看成一系列*彼此重疊*、長度為 `n` 的視窗，每個視窗都是一個 slice：

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

長度為 `length`、視窗大小為 n 的序列會產生 `length - n + 1` 個視窗。因為每個視窗都是 slice，把相鄰的讀數兩兩配對時完全不需要複製：對每個大小為 `2` 的 clump 套用 `[ first2 ]`，就能取得每一組連續的配對來做投影。（它不重疊的近親 `<groups>` 則是改成把序列切成互不重疊的區塊。）

## 多輸入的 cleave：`2bi`、`3bi`、`2tri`、`3tri`

一般的 cleave 詞 `bi` 和 `tri` 會把兩或三個 quotation 套用到*一個*輸入上。加上 `2` 或 `3` 前綴的變體，則會把每個 quotation 分別套用到*兩個*或*三個*輸入上：

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

每個 quotation 都會收到*全部*的輸入。當一個以上的投影都依賴同一對（或同一組三個）值時，就用這些詞；如果你要的是把*同一個*運算分別套用到每個輸入上，那就不適合（那種情況要用 `bi@` 或 `tri@`）。

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
