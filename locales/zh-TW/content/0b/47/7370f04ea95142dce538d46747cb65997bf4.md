# 簡介

「條件判斷」概念會介紹`jcc`，也就是根據條件進行分支的指令家族。只有在條件成立時，`jcc`才會把執行流程轉移到程式中的另一個位置。

不過，現代 CPU 速度很快，而且能平行執行許多指令。若要讓所有工作停下來，等 CPU 在執行期間檢查某個條件，代價實在太高。

這就是為什麼在內部，CPU 並不會等待。它會用**分支預測器**猜測條件的結果，並開始_推測性地_執行預測出來的路徑。

如果預測正確，執行流程就會像沒有分支一樣繼續進行。但如果預測錯誤，CPU 就必須_捨棄在預測路徑上完成的工作_，並從正確的路徑重新開始。

這叫做**分支預測錯誤**，代價很高，會造成延遲。

當分支很難預測時，這些預測錯誤就會累積起來。在這種情況下，有時最好完全避開分支，讓同一組指令不論條件為何都照樣執行。不使用`jcc`就能在幾個值之間做出選擇的程式碼，叫做**無分支**。

有幾種安排程式碼結構的方式，可以讓分支出現的次數更少，或讓保留下來的分支更容易預測。特別是 x86-64 提供了兩個指令家族，常被用來撰寫無分支程式碼。

## 條件搬移

`cmovcc`指令家族只有在特定條件成立時，才會把來源運算元複製到目的運算元。否則目的運算元維持不變。

`cc`後綴的命名方式和`jcc`相同，意義也一樣：

| 指令 | 符合以下情況時搬移 |
|-------------|--------------------------------------|
| `cmove`     | 執行`cmp A, B`後 A == B              |
| `cmovne`    | 執行`cmp A, B`後 A != B              |
| `cmovl`     | 執行`cmp A, B`後 A < B（有號）      |
| `cmovb`     | 執行`cmp A, B`後 A < B（無號）    |
| `cmovg`     | 執行`cmp A, B`後 A > B（有號）      |
| `cmova`     | 執行`cmp A, B`後 A > B（無號）    |

規則和`jcc`類似：

1. `l`和`g`用於有號比較，而`b`和`a`則用於無號比較。
2. 在後綴加上`e`會把相等的情況包含進來。
3. 在後綴加上`n`會把條件取反。
4. 另外還有一些變體是指涉某個旗標被設定。
   例如`cmovz`和`cmovc`。

來看看要如何計算放在`rdi`中的有號整數絕對值，並把結果回傳到`rax`。用`jcc`撰寫的話，函式會在兩條路徑中選一條：

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

用`cmovcc`撰寫的話，兩個候選值都會無條件算出來，再由條件搬移挑選其中一個：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

無分支的版本永遠執行同一組指令。沒有`jcc`可以讓預測器去猜。

`cmovcc`的目的運算元必須是暫存器。來源運算元可以是暫存器或記憶體位置，但不能是立即值。

~~~~exercism/note
在上面的程式碼中，`neg`指令會根據結果設定好幾個旗標，其中包括符號旗標（SF）。這表示`cmp rdi, 0`可以整個省略：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

當`rdi`是正數時，`neg`會產生負的結果，而且 SF == 1，所以`cmovs`會把`rdi`還原回去。當`rdi`是零或負數時，`neg`會產生非負的結果，而且 SF == 0，所以`rax`會保留取負之後的值（也就是正確的絕對值）。

雖然`cmp`是組合語言中比較值的主要方式，但許多指令也會根據自己的結果設定旗標。某個指令會影響哪些旗標，完整清單通常會列在它的[參考資料][reference]中。就`neg`來說，那些旗標是 SF、ZF、CF、OF 和 PF。

[reference]: https://www.felixcloutier.com/x86/
~~~~

## 條件設定

`setcc`指令家族會在特定條件成立時，把目的運算元設為`1`，否則設為`0`。目的運算元一律是_8 位元運算元_。

`cc`後綴的命名方式和`jcc`、`cmovcc`相同。例如`setz`會在`ZF == 1`時把目的運算元設為`1`，否則設為`0`。

由於目的運算元是 8 位元，當需要更寬的值時，常見的做法是在`setcc`後面接一個`movzx`：

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

這是把比較結果轉成整數`0`或`1`的常見慣用寫法。
