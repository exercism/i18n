# 關於

## 字元

[字元編碼][char-encoding]是一種特定的慣例，用來將自然語言中的文字元素表示為一連串的位元組。
這裡的「文字元素」可以是自然語言中有意義的任何單位，例如字母、空格、標點符號、表情符號、表意文字等。

NASM（The Netwide Assembler，本 track 使用的組譯器）支援使用 [ASCII][ascii] 來定義資料。

NASM 中的字元常數最多可以有 8 個位元組長，可以使用單引號（`'`）、雙引號（`"`）或反引號（`` ` ``）來定義：

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

特殊字元必須以反引號定義，並使用 `\` 跳脫：

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASM 也支援以 [UTF-8][utf8] 表示的 [Unicode 字元][unicode]，使用 `\u` 或 `\U` 指定，並置於反引號中：

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

請注意，x86-64 中並沒有將任何字元編碼當作獨立型別的內建支援。
組譯中的資料就是一連串的位元組，將這些位元組解讀為字元、數字或其他任何東西，都取決於程式設計者。

例如，ASCII 字元 '0' 是值為 48 的單一位元組。
因此，將 48 存入一個位元組，與存入 ASCII 字元 '0' 完全是同一回事：

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

基於同樣的理由，操作字元的方式就是直接轉換這些位元組中的值：

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## 字串

[字串][string]是一連串的字元。
在組譯中，它通常以陣列的形式實作。

在 NASM 中，可以用宣告任何陣列的相同方式來宣告字串：

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

字串與其他陣列的一個差別，在於 NASM 也支援不以逗號（`,`）分隔值的字串宣告方式。
也可以混用逗號來分隔值：

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

請注意，如前面所述，字元就只是位元組（在 Unicode 編碼中則是位元組序列）：

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

由於每個 ASCII 字元只佔用單一位元組，因此在較大的尺寸中，後續的位元組都是 `0`。
例如，將 `'a'` 宣告為 qword（8 位元組）時，第一個位元組是 `'a'`（`97`），其餘七個位元組全都是 `0`。

基於這個理由，以下這些寫法全都等價：

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
在組譯中，字串不會自動以 ASCII NUL 字元（值 `0`）作為結尾。

與 C 這類高階語言介接時，程式設計者必須自行負責確保在字串結尾附加正確的結束字元（若有的話）。
~~~~

## 字串指令

由於字串就是陣列，你可以像操作任何陣列一樣操作它們，也就是明確地對記憶體取值：

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

除此之外，還有一些指令可以在記憶體中的位元組序列裡載入、搬移和儲存值。
雖然它們被稱為_字串指令_，但其實可以用於記憶體中的任何位元組序列，也就是任何陣列：

| instruction  | what it does                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | 從 `rsi` 所指的記憶體位置載入一個值到 `rax`                                                                       |
| [stos][stos] | 將 `rax` 中的值存入 `rdi` 所指的記憶體位置                                                                        |
| [movs][movs] | 從 `rsi` 所指的記憶體位置複製一個值，並存入 `rdi` 所指的記憶體位置                                                |
| [cmps][cmps] | 比較 `rsi` 所指的記憶體位置中的值與 `rdi` 所指的記憶體位置中的值                                                  |
| [scas][scas] | 比較 `rax` 中的值與 `rdi` 所指的記憶體位置中的值                                                                  |

請注意，這些指令並_不_接收任何明確的運算元。
它們的運算元都是隱含的。

大致上有一個通則：

1. 當它們的來源運算元是記憶體位置時，該位址應存放在 `rsi`（`s` 代表 source）。
2. 當它們的目的地運算元是記憶體位置時，該位址則應存放在 `rdi`（`d` 代表 destination）。
3. 如果其中一個運算元不是記憶體位置，那就是 `rax` 暫存器。

請注意，這些指令會根據它們所執行的特定操作，自動對記憶體位址取值。

它們全都可以用不同的尺寸運作。
會附加一個後綴來表示這個尺寸：

| suffix | meaning | size    |
| :----: | ------- | :------ |
|  `b`   | 位元組  | 1 位元組  |
|  `w`   | 字      | 2 位元組 |
|  `d`   | 雙字    | 4 位元組 |
|  `q`   | 四字    | 8 位元組 |

例如：

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

它們也會依操作的尺寸，更新所用到的任何位址。
這個更新是依據**方向旗標（DF）**的值來進行：

- 如果 `DF` 被清除，位址會依操作的尺寸_增加_。
- 如果 `DF` 被設定，位址則會依相同數量_減少_。

System V ABI 規定，在函式進入點時方向旗標必須被清除。
因此，_預設行為是以位址遞增的順序讀寫記憶體_。

可以使用 [cld][cld] 指令來清除方向旗標，而 [std][std] 指令則用來設定它：

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
依據 System V ABI，呼叫端會預期任何被呼叫的函式在返回後，`DF` 都已被清除。
如果你曾設定 `DF`，請務必在 `ret` 之前清除它。
~~~~

### Lods

這個指令會從 `rsi` 所指位址的記憶體位置_讀取_，並將值複製到 `rax`。

`rsi` 中的值會依讀取的位元組數更新：

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

這個指令會複製 `rax` 中的值，並將它_寫入_ `rdi` 所指位址的記憶體位置。

`rdi` 中的值會依寫入的位元組數更新：

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

這個指令會從 `rsi` 所指位址的記憶體位置_讀取_，並將值_寫入_ `rdi` 所指位址的記憶體位置。
`rax` 中的值不會受這個指令影響。

`rsi` 和 `rdi` 都會依兩個記憶體位置之間複製的位元組數更新：

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

這個指令會從 `rsi` 所指位址的記憶體位置_讀取_，同時也會從 `rdi` 所指位址的記憶體位置_讀取_。
接著它會比較這兩個值，並依據 `cmp` 更新旗標。

`rsi` 和 `rdi` 都會依從兩個位置讀取的位元組數更新：

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

這個指令會比較 `rax` 中的值與它從 `rdi` 所指位址的記憶體位置_讀取_到的值。
接著它會依據 `cmp` 更新旗標。

`rdi` 中的值會依讀取的位元組數更新：

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

除了上述指令之外，[rep][rep] 指令並不直接與記憶體互動。
相反地，它可以作為前綴加到其他提到的指令前面，_重複_執行那些指令。

加上 `rep` 前綴時，字串指令會重複執行等同於 `rcx` 中值的次數。
每一次，`rcx` 中的值都會減 `1`。
請注意，`rcx` 中的值必須在指令使用之前設定好：

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

除了使用 `rcx` 作為計數器之外，`repe`（或 `repz`）與 `repne`（或 `repnz`）會分別在 `zero flag (ZF)` 被清除或設定時停止執行：

| instruction      | where can be added     | may stop earlier        |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`、`lods`、`stos` | 否                      |
| `repe`、`repz`    | `cmps`、`scas`         | 是，ZF 為 0 時停止      |
| `repne`、`repnz` | `cmps`、`scas`         | 是，ZF 為 1 時停止      |

~~~~exercism/advanced
在現代 CPU 上，搬移大型資料區塊時，`rep movs` 和 `rep stos` 通常是快速的選擇。
然而，其他字串指令，甚至是不搭配 `rep` 的 `movs` 和 `stos`，通常都比單純的迴圈慢。

關於這個主題更深入的探討，可以在[這本參考書的第 16.9 章「String instructions」][agner-optimization-guide]中找到。
