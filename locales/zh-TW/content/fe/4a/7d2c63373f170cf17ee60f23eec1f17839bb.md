# 簡介

## 部分應用與函式組合

### 部分應用

Elm 中所有的函式都是[柯里化][currying]的，意思是如果你呼叫函式時沒有傳入全部的引數，它會回傳一個新的函式。

這樣做的結果稱為[部分應用][partial-application]（你沒有把全部引數都傳給函式，而是只套用了其中一部分）。

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

部分應用一律會依照順序套用引數。

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

### 管線運算子（`|>`）

`x |> f` 和 `f x` 完全一模一樣。具體的例子是：`"5" |> String.toInt` 等同於 `String.toInt "5"`。

乍聽之下這似乎沒什麼用，但它被稱為[管線運算子][pipe-operator]，因為它讓你可以寫出「管線化」的程式碼。

舉例來說，假設我們有一個 `sanitize` 函式，用來把使用者的輸入轉成整數：

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

我們可以把它改寫成這樣：

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

這樣可以避免使用括號，並且依照函式套用的順序來呈現（先是 `String.trim`，然後是 `String.toInt`），有助於閱讀。

另外還有[反向管線運算子 `(<|)`][reverse-pipe-operator]。
`f <| x` 和 `f x` 完全一模一樣。
乍看之下這也似乎沒什麼用，而且使用頻率肯定不如管線運算子，但在某些情況下可以幫你避開括號。

### 函式組合／無點風格

[`(>>)`][forward-composition] 運算子的型別是 `(a -> b) -> (b -> c) -> (a -> c)`，它會組合兩個相容的函式（型別分別為 `a -> b `和 `b -> c`），建立出一個型別為 `a -> c` 的函式。
做法是取出第一個函式的輸出（型別為 `b`），並把它當成第二個函式的第一個引數（後者的型別必須同樣是 `b`）。
建立出來的函式會接收與第一個函式相同的輸入（型別為 `a`），並回傳第二個函式所回傳的 `c`。

具體的例子是 `String.trim >> String.toInt`。
`String.trim` 只接受一個字串作為參數，所以建立出來的函式也是接收這個。
`String.toInt` 回傳 `Maybe Int`，所以建立出來的函式也是回傳這個。
`String.trim` 回傳 `String`，而 `String.toInt` 接受它作為參數，所以這個例子可以編譯。

現在我們可以把 `sanitize` 函式改寫成下面這樣：

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

注意，雖然功能完全相同，我們已經不再使用原本範例中看得到的 `input` 參數。
這種建立函式、完全不提及參數的方式稱為「無點風格」（英文：_Point Free Style_）。
這種風格的優點是程式碼更簡潔，缺點是可能比較難理解，對初學者尤其如此。

值得記住的是，Elm 中所有的函式都是柯里化的，所以 `String.length >> max` 可以編譯。

- [`(>>)`][forward-composition] 運算子的型別是 `(a -> b) -> (b -> c) -> (a -> c)`。
- `String.length` 的型別是 `String -> Int`，也就是 `(a -> b)` 的部分，所以 `a` 是 `String`，而 `b` 是 `Int`。
- `max` 的型別是 `Int -> Int -> Int`，也就是 `b -> c` 的部分。
- `b` 是 `Int`，所以 `max` 會被部分套用，因此 `c` 就是這個部分套用的結果（`Int -> Int`）。
- 所以 `String.length >> max` 的型別是 `String -> (Int -> Int)`。
- 所以 `((String.length >> max) "123") 2` 會回傳 `3`，因為 `"123"` 的長度是 3，比來自 `Int` 引數的 2 還大。

### 函式設計

為了讓你在 Elm 中輕鬆寫出優雅的程式碼，你應該把主要的資料結構放在函式的最後一個參數。
標準函式庫中所有常見的函式都這麼做，例如 `List.map`（型別簽章如下）。

```elm
map : (a -> b) -> List a -> List b
```

在這裡可以看到，`map` 函式的最後一個參數是 `List a`，而它回傳 `List b`，所以主要的資料結構（`List`）就是最後一個參數。

這讓你能寫出優雅的管線化程式碼，如下所示。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

這也讓使用函式組合和無點風格變得很方便，可以作為管線化的替代方案。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

函式組合也讓你能把這個例子縮減成單一次呼叫 `List.map`。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
