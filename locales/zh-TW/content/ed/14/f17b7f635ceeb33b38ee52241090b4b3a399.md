# 關於

要理解 [`Box`][box]，先了解[堆疊與堆積][stack and heap]是什麼會有幫助。

堆疊是一塊記憶體區域，運作方式類似後進先出（LIFO）的緩衝區。把資料推入堆疊非常快，取出也很快。
這些資料可以是變數或函式位址，但資料在編譯時期必須是已知的固定大小。

如果資料在編譯時期大小未知，或大小可能改變，就必須配置到堆積上。配置的過程必須在堆積中找到足夠大的空間來存放資料、把資料寫入堆積，再把該資料的記憶體位址推入堆疊；這些步驟花的時間，遠比單純把資料放上堆疊多。從堆積取回資料則稍微慢一點，因為我們必須先經過堆疊上的位址，再沿著它找到資料在堆積中的位置。

`Box`是一種智慧指標，會把資料配置在堆積上。位址放在堆疊上，指向堆積上的資料。使用 `Box` 的其中一個[理由][reasons]，是當你有一個在編譯時期無法得知大小的型別，而你想在需要確切大小的情境中使用該型別的值時，把資料放到堆積上。其中一個實際的用法，是當你有多個結構體，想透過它們全都實作的同一個特徵以相同方式處理時，如下面的範例所示。

假設我們有兩個結構體。每個結構體都代表某種會惹人煩的東西。我們可以讓每個結構體像這樣實作一個 Annoyance 特徵

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

現在假設我們想要一個函式，能根據傳入的一天時段，回傳一個 Annoyance。我們可以先試試下面這種寫法，然後會發現它無法編譯

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

編譯器非常熱心地直接告訴我們該怎麼做，也就是回傳一個裝箱的特徵物件。如果你不知道什麼是特徵物件，簡單的說，它是一種從可能回傳任何實作某個特定特徵之物件的函式中，透過[動態分派][dynamic dispatch]回傳特定物件的方式。既然我們需要動態分派，可以直接在特徵名稱前面加上 `dyn`，看看這樣能不能過關。

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

其中一個錯誤是 `dyn Annoyance` 的大小無法在編譯時期得知。這是因為 `annoy_me` 在被呼叫之前，並不知道自己會回傳哪一個特定的特徵物件。實作 Annoyance 的結構體可能有不同的欄位，大小也可能不同。這也提醒了我們，`Box` 的用途之一，就是用在編譯時期無法得知大小的型別上。所以現在我們試著使用以 `Box` 裝箱的回傳值，並把 match 運算式回傳的值也用 `Box` 裝箱，像這樣

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

`Box` 的簽章是 `Box<T>`，其中 `T` 代表要裝箱的特定型別，放在尖括號內，就像上面的 `Box<dyn Annoyance>` 一樣。

我們可以像這樣使用裝箱後的特徵物件

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

它會印出

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

由於 `my_annoyance` 的型別是 `Box<dyn Annoyance>`，必須用解參考運算子 `*` 對 `Box` 解參考。接著它會以 `dyn Annoyance` 的形式被引用，讓 `be_annoying` 函式借用它。

另一種實作方式，是移除「參數必須有已知大小」這項要求。這樣一來，編譯時會為 Annoyance 的每個變體建立一個獨立的函式，以便進行靜態分派（這個過程稱為[單態化][monomorphization]），像這樣

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

還有一種實作方式，是讓 `be_annoying` 函式接受 `Box<dyn Annoyance>`，並使用[解參考強制轉型][deref coercion]，這樣就不必手動對 `Box` 解參考。這會把 Annoyance 特徵物件的所有權轉移給 `be_annoying` 函式。它會在函式結束時離開作用域，之後就不再可用。

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
