# 指令補充

## Odin 專屬指令

### 二元樹上的 Zipper

上面的指令是用玫瑰樹（每個節點可以有多個子節點）來討論 Zipper，但 Zipper 的概念可以套用到任何種類的樹，甚至應用到陣列上。
在這個練習裡，我們會使用二元樹（每個節點有兩個子節點），這樣就能專注在 Zipper 的操作上，而不是忙著處理數量會變動的子節點。

指令中列出的操作已更新，以配合二元樹：

| 操作            | 說明                                                                       |
| --------------- | -------------------------------------------------------------------------- |
|`zip_from_tree`  | 從樹取出一個 Zipper，焦點位於根節點。                                      |
|`zip_to_tree`    | 從 Zipper 取出樹。                                                         |
| `zip_value`     | 取得焦點節點的值。                                                         |
| `zip_left`      | 把焦點移到焦點節點的左子節點，回傳一個新的 Zipper。                        |
| `zip_right`     | 把焦點移到焦點節點的右子節點，回傳一個新的 Zipper。                        |
| `zip_up`        | 把焦點移到焦點節點的父節點，回傳一個新的 Zipper。                          |
| `zip_set_value` | 設定焦點節點的值，回傳一個新的 Zipper。                                    |
| `zip_set_left`  | 設定焦點節點的左子樹，回傳一個新的 Zipper。                                |
| `zip_set_right` | 設定焦點節點的右子樹，回傳一個新的 Zipper。                                |

### 記憶體管理

在 Odin 裡，你必須手動管理記憶體。
為了簡化這個練習、專注在 Zipper 的操作上，分配給樹節點與軌跡的記憶體會透過 arena 配置器自動替你管理。
你只需要視需要以`new(Node)`和`new(Step)`配置記憶體；當我們對樹的操作結束後，測試會自動對 arena 呼叫`free_all()`。
在 Odin 裡，對於任何週期性流程（例如遊戲迴圈，或一連串請求和回應），這就是處理記憶體配置的慣用做法。

如果你想更深入了解 Odin 的配置器，特別是 arena 配置器，下列文件或許會讓你感興趣：[Odin 總覽中的 Allocator 章節][allocators-overview]、[Karl Zylinski 的 Understand the Temporary Allocator; Understand arenas][allocators-zylinksi]，以及 [gingerBill 的 Linear/Arena Allocators][allocators-gingerbill]。
