# 關於

在 Gleam 中對值做模式配對時，我們必須確保模式涵蓋該型別所有可能的值，否則程式碼就無法編譯。

下面這個函式應該被拒絕，因為它沒有處理陣列為空的情況：

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

在 Gleam 程式裡，大多數時候我們會想處理所有可能的情況，但在某些程式（例如原型和快速指令碼）中，我們可能只想專注在正常路徑上，而不為其他情況寫程式碼。這就是 Gleam 的`let assert`派上用場的地方。

有了 let 斷言，模式可以只配對某個型別中部分可能的值，而如果模式沒有配對到某個值，程式就會崩潰。使用`let assert`，我們可以把上面的函式改寫成這樣：

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam 的函式庫絕對不該使用 let 斷言，因為它們可能讓程式崩潰；函式庫應該改用`Result`型別，讓應用程式開發者自行決定如何處理錯誤。
