# 關於

例外是錯誤處理的一種形式。
之所以稱為例外，是因為它們通常出現在處理某些非預期事件的時候。

在程式碼中的任何地方，我們都可以「引發」例外。
我們使用`raise`方法來做到這件事，並傳入一個物件，通常是 Exception 物件，不過也可以使用基本的字串。
舉例來說，你會在練習的程式骨架中看到我們使用內建的`RuntimeError`，告訴 Ruby 某個方法尚未被實作。
你也可以使用`raise(ExceptionObject, params)`這種簡寫語法。
如果省略了例外類別，預設會使用`RuntimeError`。

例如：

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

當 Ruby 看到這個情況，會把錯誤往上傳遞到程式的最上層，然後結束執行。

舉例來說，如果你試著把某個數除以零，會看到類似這樣的內容：

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

要注意的是，例外應該用於發生異常情況的時候，也就是出現需要特別處理的錯誤時。
例外不應該用來控制程式的流程，因為那被認為是不良的設計，往往會導致效能與可維護性變差。

## 類別階層

在 Ruby 中，例外遵循一套類別階層，其中`Exception`是基底類別。
以下是 Ruby 最常見的內建例外：

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

救援某個特定類別的錯誤時，也會一併救援其子類別的錯誤。
這就是從`Exception`救援可能很危險的原因。
Ruby 也會使用例外來處理作業系統的「訊號」，例如`ctrl-c`。
這表示從`Exception`救援也會一併捕捉到這些系統「訊號」。
因此，為了避免非預期的行為，捕捉「所有錯誤」的常見做法是從`StandardError`救援。

## rescue 語法

Ruby 也為需要特別處理的情況提供了擴充的 rescue 子句：

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

舉例來說，在處理網路 IO 時這就很有用，因為我們永遠需要記得關閉連線。

Ruby 的 rescue 區塊也可以使用`retry`關鍵字，重新執行 begin 和 rescue 之間的所有內容：

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
