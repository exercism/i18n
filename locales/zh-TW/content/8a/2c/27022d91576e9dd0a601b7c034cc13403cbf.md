# 簡介

## 例外

Elixir 中的所有錯誤都實作了_例外行為_。就像_存取行為_一樣，_例外行為_定義了模組必須實作的幾個回呼函式，以滿足這個行為的軟體契約。一旦定義了錯誤，它就具備下列特性：

- 模組的名稱定義了錯誤的名稱。
- 模組定義了一個錯誤結構。
- 這個結構會有一個`:message`欄位。
- 這個模組可以和`raise/1`與`raise/2`搭配使用，來拋出預期的錯誤

_例外行為_也指定了兩個回呼函式：`message/1` 和 `exception/1`。如果沒有實作，就會使用預設的實作。當搭配`raise`呼叫時，`message/1`會把錯誤結構轉換成可讀的訊息。當搭配`raise/2`呼叫時，`exception/1`允許在訊息中加入額外的脈絡資訊。

### 定義例外

若要從錯誤模組定義例外，我們會使用`defexception`巨集：

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### 使用例外

定義好的錯誤可以像內建錯誤一樣，透過`raise/1`或`raise/2`來使用。

- `raise/1`會依照模組名稱拋出特定的錯誤；或者，如果引數是字串，就會拋出一個`RuntimeError`，並以該字串做為訊息。
- `raise/2`會依照模組名稱拋出特定的錯誤，並接受一個屬性引數，用來取得帶有適當訊息的錯誤。
