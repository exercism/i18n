# 簡介

純量程式碼依賴各種指令所設定的旗標，以便針對某個條件進行分支。
然而，打包值代表的不只是 1 個值，而是許多個平行並存的值。
同一個條件可能在某個通道不成立，卻在另一個通道成立。

這就是為什麼 SIMD 程式碼預設是_無分支_的。

打包比較通常不依賴旗標，而是產生一個寫入目的運算元的**遮罩**。
對每個通道而言，比較結果為真時會把整個通道填滿 1，為假時則填滿 0。
若解讀為帶號整數，為真的通道是`-1`，為假的通道是`0`。

接著就能把這個遮罩與位元運算組合起來，篩選出特定的通道。

## 打包比較

純量的`cmp`之所以通用，是因為它能同時設定多個旗標。
接著另一道指令可以取用這些旗標，據以分支或進行運算。

不過，打包比較既檢查條件又計算遮罩，因此並不通用。
這種比較必須明確指定要測試的條件。

做法有 2 種：

- 整數比較以條件作為後綴：`eq` 表示相等，`gt` 表示大於。
  其他變體則由其中一種的結果組合而成。
- 浮點比較則把條件編碼在立即值中。
  立即值不同，代表測試的條件也不同。

除了整數比較會使用特定的條件後綴之外，語法結構和我們先前看過的相同：

- 整數是`p` + `cmp` + 條件 + 大小（`b`、`w`、`d` 或 `q`）。
- 浮點數則是`cmp` + `p` + 大小（`s` 或 `d`）。
  條件以立即值的形式，作為額外的運算元傳入。

### 整數比較

如前所述，整數比較只有相等和大於兩種：

| 指令                                       | 說明                             |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | 逐通道相等                       |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | 逐通道**帶號**大於               |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

若要建立小於比較，把運算元對調後使用`gt`：`a < b` == `b > a`。

注意，這種比較是**帶號**的。
若要進行無號比較，請把兩個運算元的最高位元翻轉。
做法是與一個只有最高位元被設定的遮罩進行 XOR。

~~~~exercism/note
有 2 個實用的慣用技巧：

1. 將一個暫存器與自身 XOR，產生全零。
2. 將一個暫存器與自身比較，產生全一。

例如：

```x86asm
pxor xmm4, xmm4    ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

全零和全一是常見的遮罩，分別用來表示「全部為假」和「全部為真」。
它們也可以用來表示打包的`0`或打包的`-1`，這是常見的哨兵值。
例如，標記字串結尾的 NUL 就是一個`0`。
~~~~

### 浮點比較

浮點通道的型式不同：只有 1 道指令`cmpps`（64 位元通道則用`cmppd`），並以立即值指定條件：

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM 也有對應到正確立即值的虛擬指令，比較容易記。
以下所有指令中，`px`裡的`x`可以是`s`（32 位元浮點數）或`d`（64 位元浮點數）：

| 虛擬指令     | 立即值    | 比較                   |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a 是 NaN 或 b 是 NaN   |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | a 和 b 都不是 NaN      |

## 用遮罩進行選擇

遮罩會把某個條件的結果編碼起來。
接著就能依據這個條件，逐一通道在兩組值之間做選擇。
遮罩為真的通道取自其中一個值，為假的通道則取自另一個值：

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

這個模式就是無分支選擇的打包版本。
每個通道都會被計算，最後只由遮罩決定哪個值留下來，完全不需要任何`jcc`。

## 專用的混合指令

有些指令可以直接進行同樣的選擇，從遮罩暫存器為每個元素讀取 1 個位元。
這些指令稱為**混合**指令：

| 指令        | 元素        | 遮罩來源        |
|-------------|-------------|-----------------|
| `pblendvb`  | 位元組      | 隱含的`xmm0`    |
| `blendvps`  | 32 位元通道 | 隱含的`xmm0`    |
| `blendvpd`  | 64 位元通道 | 隱含的`xmm0`    |

注意，第 1 道指令遵循整數語法，另外 2 道則遵循浮點語法。
不過，由於這些指令只是單純選取原始位元組，因此三者在整數和浮點上都能使用。

對每個元素而言，當對應遮罩元素的最高位元為 0 時，混合會保留目的運算元；為 1 時則取用來源運算元。
只會參考那個**最高位元**；比較產生的遮罩正好符合這點，因為它的通道不是全一就是全零。
遮罩暫存器一律是`xmm0`，而且是隱含的：

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

也可以用`pblendvb`，為任何其他元素大小從比較遮罩中選取通道。
由於為真的通道中所有位元組都是全一，`pblendvb`會把它們全部選取起來。

~~~~exercism/note
這些指令都會在執行的運算（`blend`）後面加上`v`。
這個`v`代表可變（英文：_variable_），因為選擇並非固定不變，而是取決於某個暫存器。

另外也有不含`v`的變體，它們依據立即值進行選擇。
這些變體遵循相同的模式：若立即值的第`i`個位元被設定，就選取通道`i`。
~~~~

## 從遮罩回到純量

SIMD 程式碼雖然強大，卻少了純量程式碼大部分的彈性。
在許多情況下，必須從打包暫存器回到純量指令的世界。

`movmsk`系列指令是這 2 個世界之間的橋樑。
這些指令會把每個通道的**最高位元**抽取到通用暫存器中：

| 指令        | 收集的內容                   | 結果寬度 |
|-------------|------------------------------|----------|
| `pmovmskb`  | 16 個位元組各自的最高位元    | 16 位元  |
| `movmskps`  | 4 個雙字組各自的最高位元     | 4 位元   |
| `movmskpd`  | 2 個四字組各自的最高位元     | 2 位元   |

若在比較之後使用，每個被設定的位元代表一個「為真」的通道，每個被清除的位元則代表一個「為假」的通道。
接著就能像平常一樣用純量指令操作這個結果。
例如，`popcnt`可以數出相符的數量，`tzcnt`則能找出第一個。

通用暫存器可以是 32 位元或 64 位元寬。

## 測試整個向量

純量指令`test`也有一個打包版本：`ptest`。

它和純量版本相似，會在 2 個運算元之間執行 AND 運算，但不會修改它們。
和`test`不同的是，`ptest`還會執行 ANDN 運算，把第一個運算元取反。

因此，`ptest`可以視為`pand`和`pandn`的非破壞性版本，會依結果設定旗標。
和這兩道指令很類似，`ptest`把整個 SIMD 暫存器視為單一通道，因此不帶大小前綴。

若 AND 運算的結果是`0`，會設定`ZF`；若 ANDN 運算的結果是`0`，設定的則是`CF`。
這表示`ptest`可以用來檢查全一和全零兩種遮罩：

1. 把`ptest`用在暫存器與自身時，只有在暫存器為全零才會設定`ZF`。
   這模仿了純量中常見的技巧：對暫存器與自身使用`test`來檢查是否為`0`。
2. 把`ptest`用在暫存器與全一遮罩上時，只有在暫存器為全一才會設定`CF`。
   此外，只有在暫存器為全零時才會設定`ZF`，因此可以一次檢查這兩種遮罩。

```x86asm
pxor    xmm0, xmm0   ; all zeros
pcmpeqb xmm1, xmm1   ; all ones
pcmpeqb xmm2, xmm2

ptest xmm0, xmm0     ; ZF set: a register against itself detects all zeros
ptest xmm0, xmm1     ; ZF set, CF clear: xmm0 is all zeros, not all ones
ptest xmm2, xmm1     ; CF is set only if xmm2 is all ones
```

和往常一樣，`ptest`的結果可以用來進行分支，也可以用在`setcc`、`cmovcc`這類無分支指令中。
