# 說明

你的朋友 Li Mei 經營一間果汁吧，店裡賣的是美味的綜合果汁。
你是她店裡的常客，發現自己可以讓朋友的生活輕鬆一些。
你決定運用你的程式設計能力，來幫 Li Mei 分擔工作。

## 1. 判斷製作一杯果汁需要多久

Li Mei 喜歡事先告訴客人，他們從菜單上點的果汁要等多久。
她很難記住確切的數字，因為調製各種果汁所需的時間都不一樣：

| ID  | 飲品 | 時間 |
| --- | ------------------- | ---- |
| 1   | 純草莓樂 | 1    |
| 2   | 活力飲 | 3    |
| 3   | 綠色花園 | 3    |
| 4   | 熱帶島嶼 | 4    |
| 5   | 全有或全無 | 5    |
| 6   | 感覺良好 | 4    |
| 7   | 今日特調 | 7    |
| 8   | 顧客首選 | 10   |

撰寫一個函式`time_to_make_juice`，它接受一個果汁的 ID（32 位元數字），並回傳製作該果汁所需的時間，同樣以 32 位元數字表示。

```c
time_to_make_juice(2);
// => 3
```

## 2. 判斷製作所有已點果汁需要多久

Li Mei 需要定期補充材料，所以她得事先知道準備目前所有可製作的訂單會花上多少時間。

為了幫助你的朋友，請撰寫一個函式`time_to_prepare`，它接受一個包含每杯已點果汁 ID 的陣列，以及陣列中果汁的數量。
這個函式應該回傳準備陣列中所有飲品所需的總時間。

你可以假定每個 ID、陣列中 ID 的數量，以及回傳值都是 32 位元數字。
結果一定在 32 位元數字的範圍內。

```c
time_to_prepare({2, 3, 8}, 3);
// => 16
```

## 3. 補充萊姆角的庫存

Li Mei 的許多創作都會用到萊姆角，無論是當作原料，還是用來裝飾。
所以每天早上開始上班時，她都得確認裝萊姆角的箱子是滿的，足以應付接下來的一天。

請實作函式`limes_to_cut`，它接受 Li Mei 需要切出的萊姆角數量、一個代表她手邊整顆萊姆庫存的陣列，以及陣列中萊姆的數量。

陣列中的每顆萊姆都以一個字元表示它的大小。
不同大小的萊姆能讓 Li Mei 切出不同數量的萊姆角：

| 大小 | 萊姆角數量 |
| ---- | ------ |
| 'S'  | 6      |
| 'M'  | 8      |
| 'L'  | 10     |

~~~~exercism/note
字元是 8 位元數字，可以像任何 8 位元數字一樣使用：

| 字元 | 值 |
|-----------|-------|
| 'S'       | 83    |
| 'M'       | 77    |
| 'L'       | 76    |

它也可以直接用在指令中，等同於它的值：

```x86asm
mov dl, 'S'
cmp cl, 'M'
```
~~~~

Li Mei 總是按照萊姆在陣列中出現的順序來切，從第一項開始。
她會一直切到切出所需的萊姆角數量，或是萊姆用完為止。

Li Mei 希望事先知道她需要切幾顆萊姆。

你可以假定所需的萊姆角數量、陣列中萊姆的數量，以及回傳值都是 32 位元數字。
結果一定在 32 位元數字的範圍內。

```c
limes_to_cut(25, {'S', 'S', 'L', 'M', 'S'}, 5);
// => 4
```

## 4. 完成這班工作

Li Mei 總是工作到下午 3 點，之後由她的員工 Dmitry 接班。
Li Mei 的班結束時，經常還有已經點好但還沒做好的飲品，這時就由 Dmitry 來準備剩下的果汁。

為了讓交接更順利，請實作一個函式`remaining_orders`，它接受：

- Li Mei 這班還剩下多少分鐘。
- 一個陣列，內含每杯已點但尚未準備的果汁 ID。

這個函式應該回傳 Li Mei 在下班前準備了幾筆訂單。

這班剩下的時間一定大於 0。
待準備的果汁陣列永遠不會是空的，而且這一班一定會在處理完整個陣列之前結束。
此外，訂單會按照它們在陣列中出現的順序來準備。
如果 Li Mei 開始調製某杯果汁，她一定會把它做完，即使得多工作一點時間。

你可以假定剩下的分鐘數、陣列中的每個 ID，以及回傳值都是 32 位元數字。
結果一定在 32 位元數字的範圍內。

```c
remaining_orders(5, {5, 5, 3});
// => 1
```
