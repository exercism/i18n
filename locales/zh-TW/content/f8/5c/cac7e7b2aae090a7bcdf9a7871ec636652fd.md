# 指令補充

## 實作

開始之前，請先確認你了解如何撰寫能通過測試案例的程式碼。如果想了解更多背景，可以參考這篇[教學][tutorial]。

大多數 Java 練習都包含多個測試案例。這些案例的結構是為了支援一個很實用的流程，也就是[測試驅動開發（TDD）][tdd]。TDD 會反覆進行一個有結構的循環，幫助程式設計師把複雜的功能一塊一塊建構起來，而不是一次全部完成。這個循環可以描述如下：

1. 新增一個測試，描述你的程式碼目前還缺少的某項功能。
2. 執行測試，確認這個剛新增的測試會失敗。
3. 修改現有的程式碼，直到：
   - 所有舊的測試都仍然通過；
   - 新的測試也通過。
4. [清理][refactoring]你的程式碼，並確認所有測試都仍然通過。這通常包括重新命名變數、移除重複的邏輯片段、移除殘留的日誌等。
5. 回到步驟 1，直到所有想要的功能都建構完成！

這個 track 的測試檔包含了你的解法必須通過的_所有_測試，這樣才算有效。這乍看之下似乎和前面描述的循環不相容，因為那個循環是一次只寫一個測試。不過，我們用來撰寫測試的工具 [JUnit][junit]，提供了 [@Disabled][junit-disabled] [註解][java-annotation]，可以用來暫時略過已經寫好的測試。透過這個註解，我們可以確保交付給你的測試檔符合以下規則：

- 任何測試檔中的第一個測試，預設_不會_被略過。
- 任何測試檔中除了第一個測試以外的所有測試，預設_都會_被略過。

這樣一來，你就可以依照以下稍作修改的步驟，模擬 TDD 的循環：

1. 執行測試，確認目前_最多只有一個_測試失敗。
2. 修改現有的程式碼，直到所有未被略過的測試都通過。
3. 清理你的程式碼，並確認所有未被略過的測試都仍然通過。
4. 移除測試檔中最上方的 `@Disabled` 註解。
5. 回到步驟 1，直到沒有測試被略過，而且所有測試都通過！
