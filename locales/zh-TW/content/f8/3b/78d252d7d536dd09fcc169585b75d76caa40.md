# 簡介

作業系統（OS）通常會以一個通用配置來為程式對應記憶體：

| 位址 | 記憶體區域 |
| :-----: | :--------------------- |
|  高   | 堆疊                  |
|         | ...                    |
|         | 堆積                   |
|         | 可讀寫段 |
|         | 程式碼／唯讀段 |
|   低   | 保留區               |

記憶體以段為單位，再組織成具有不同權限的區段。

我們到目前為止定義的函式，全都位於 **.text 區段**。
這個區段存放的是唯讀的可執行資料。
其他區段則用來宣告資料變數，這些變數可以是唯讀或可讀寫的，但不可執行。

## .data 區段

已初始化的資料會宣告在 **.data 區段**中。

在 NASM（The Netwide Assembler，也就是這個 track 使用的組譯器）中，一個已初始化的變數包含名稱、指出資料大小的指示詞，以及以逗號分隔的一串值。
這些部分彼此以空格分隔，標籤後面則可以選擇性加上`:`。

主要的指示詞及其對應的資料大小如下：

| 指示詞 | 大小    |
| :-------: | :------ |
|    db     | 1 位元組  |
|    dw     | 2 位元組 |
|    dd     | 4 位元組 |
|    dq     | 8 位元組 |

舉例來說，下面這行宣告了一個名為`space`、值為`10`的位元組變數：

```x86asm
section .data
    space db 10
```

宣告在`section .data`中的變數是可變的，也就是可讀寫。
它們也具有_靜態_儲存期，這表示在整個程式執行期間它們都存在。

## .rodata 區段

**.rodata 區段**與`section .data`類似。
這兩個區段都包含已初始化的資料，宣告方式相同，儲存期也一樣。

兩者最主要的差別在於，`section .rodata`中的資料不可變，也就是唯讀。

~~~~exercism/note
用`equ`定義的常數，與定義在`section .rodata`中的常數不同。

以`equ`定義的常數不會佔用記憶體空間，組譯器會直接以它的值來取代。
它實際上只是那個值的佔位符。

另一方面，定義在`section .rodata`中的常數則實際儲存在記憶體中，並擁有位址。
~~~~

## 存取資料

### 標籤與間接定址

宣告的資料必須有一個與之關聯的名稱。
這個名稱稱為**標籤**。

標籤是一個符號，用來編碼資料在記憶體中的確切位址。
**x86-64 中的位址是 64 位元的值**。

在 NASM 中，直接以標籤存取資料並不會取得配置到的記憶體內容，而是取得它的位址：

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

若要存取某個記憶體位址的內容，必須先對它_解參考_。
這就叫做**間接定址**。

在 NASM 中，這是用`[]`來完成的：

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

不過，有些情況下，被解參考的記憶體大小可能不明確。
這時就必須使用一個指明大小的前綴。

以下是在典型的 x86-64 程式中最常用的前綴及其大小：

| 前綴 | 大小    |
| :----- | :------ |
| byte   | 1 位元組  |
| word   | 2 位元組 |
| dword  | 4 位元組 |
| qword  | 8 位元組 |

同樣的載入動作也可以明確寫出大小：

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

解參考記憶體時，最好總是加上前綴。

### 寫入記憶體

寫入記憶體也是用同樣的方式，也就是對位址進行解參考：

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

請注意，在多數指令中，你可以直接使用記憶體運算元，而不必先把內容載入暫存器。
不過，通常無法在來源運算元和目的運算元同時使用記憶體運算元，只能用在其中一個：

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### LEA 指令

雖然可以用`mov`把變數的位址存入暫存器，但有一個專門為此目的而設計的指令：**lea**。

這個指令使用記憶體形式的運算元，但它_不會_讀取記憶體。
相反地，它會計算有效位址運算式，並把結果寫入目的運算元：

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

用`lea`來計算並把記憶體位址存入暫存器，是比較道地的做法。

### 相對定址

在存取記憶體位置時，NASM 的預設行為是產生**絕對位址**，也就是固定的記憶體位址。

基於安全考量，執行檔通常會建置成 **PIE（Position Independent Executable，位置無關執行檔）**，此時記憶體區域會被放在隨機化的位置。
在`PIE`中，變數的最終位址在連結時並未知曉。
因此，程式碼改為以某個特殊暫存器`rip`中的值加上偏移量來計算位址，`rip`會指向下一條要執行的指令。

這通常稱為 **RIP 相對定址**。

在 NASM 中，你可以用`rel`運算子來要求 RIP 相對存取：

```x86asm
mov rax, qword [rel variable]
```

也可以在原始檔開頭加上`default rel`，把相對定址設為預設。

這個 track 中的所有練習都會編譯並連結成`PIE`，因此應該使用`rel`來產生相對位址。

### 可見性

在任何區段（例如`.text`、`.data`、`.rodata`）中定義的標籤（函式與資料），在同一個原始檔內是可見的。
若宣告為`global`，它們對其他原始檔也可見。

反之，定義在其他原始檔中的標籤，若宣告為`extern`，則對目前的原始檔可見。
在這種情況下，組譯碼中不會標示資料大小，必須事先知道。

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
