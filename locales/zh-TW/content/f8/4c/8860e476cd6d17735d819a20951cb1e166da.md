# 關於

## Julia 中的布林值

真或假的值由`Bool`型別表示。
它只包含 2 個值：`true`和`false`。

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

與其他幾種語言不同，Julia 刻意不採用「真值性」的概念，只有求值結果為`true`或`false`的運算式，才會被視為`Bool`。

具體來說，空的陣列或字串*不會*被解讀為`false`。
如果你想特別處理空值，就必須有像是`isempty()`這樣恰當的測試。

## 布林運算子

Julia 中有 3 種[布林運算子][boolean-operators]。

`&&`是布林的「且」。
當`&&`*兩側*的運算式都是`true`時，它的求值結果為`true`。

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||`是布林的「或」。
當`||`*任一側*的運算式是`true`時，它的求值結果為`true`。

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!`是布林的「非」。
它會交換（反轉）`true`與`false`值。

```julia-repl
julia> !true
false

julia> !false
true
```

許多其他語言的使用者對這類運算子在概念上應該很熟悉，不過確切的語法可能因語言而異。

## 運算子優先順序

在較複雜的運算式中，知道`&&`的[優先順序][operator-precedence]比`||`稍高會很有幫助*（就像在算術運算式中，`*`會先於`+`套用一樣）*。

依賴這一點可能會令人困惑，而且容易出錯。
為了清楚起見，請使用括號來明確表達你的意圖。

## 短路求值

運算式`true || x`是否取決於`x`的值，還是編譯器可以忽略`x`？

Julia 會由左至右對布林運算式求值，並在得到明確的結果時停止。

例如，無論`x`是什麼，`true || x`必定是`true`，因此不會對`x`求值。
同樣地，`false && y`是`false`，不需要對`y`求值。

反之，`true && x`*只有在*`x`是`true`時才是`true`，因此必須對`x`求值。

同樣地，如果我們串接多個運算子：

```julia-repl
julia> true && false && something_else
false
```

由於`true && false`必定是`false`，`something_else`並不重要，會被編譯器忽略。

在這個例子中，`something_else`並不是存在的變數，但把它放在這個情境中卻沒有產生錯誤*（如果你不信，可以在 REPL 裡試試看）*。

Julia 程式設計師經常利用這種短路求值，做為捕捉執行階段問題與邊界情況的捷徑：

```julia
all_ok || do_something()

is_problem && do_something_else()
```

例如，`do_something`可能是在`all_ok`為`false`時提早從函式`return`，或是在繼續之前為變數指定預設值。

這算是稍微濫用了布林語法，但用起來可能非常方便。

## 布林值的內部運作方式

如果把一個 Bool 放進*算術*運算式，`true`會被解讀為`1`，`false`則解讀為`0`，這反映了它們的儲存方式。

如果你習慣使用較低階的語言（例如 C 及類似語言），*請*盡量避免經常這樣做。
這會降低程式碼的可讀性，也讓除錯變得更困難。

你有時可能會看到有人用這些數值，做為快速計算有多少項目為`true`的方法。

```julia-repl
julia> true + false + true
2
```
