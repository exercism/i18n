# 提示

## 一般

- 請特別留意指標的語法。你會用到`*`（解參考運算子）和`->`（透過指標存取成員）。
- 請務必在必要時檢查空指標（`nullptr`），避免存取無效的記憶體。
- 即使程式碼還沒寫完，也可以先執行測試喔；只要有粗略的結構，就能看到測試結果。
- 測試會用到的所有函式，都必須在標頭檔中宣告。
- 如果你的程式當掉或行為不如預期，通常都是空指標解參考造成的。請再次確認你有正確處理`nullptr`。
- 使用指標運算時，請確保沒有超出感測器陣列的範圍。超出陣列容量可能會導致記憶體問題。

## 1. 檢查感測器連線（`connection_check`）

- 這個任務主要是要驗證指標是否為空。
- 使用比較運算子`!=`來檢查指標是否有效。
- 如果你不確定自己的指標檢查方式是否正確，想想`nullptr`代表什麼（沒有有效的記憶體位址）。


## 2. 計算感測器的活動量（`activity_counter`）

- 你需要逐一疊代感測器陣列。在 C++ 中，陣列可以視為指向第一個元素的指標。
- 使用指標運算（`sensor_array + i`）來存取索引`i`的感測器。
- `->`運算子用來透過指標存取結構的成員。

### 範例

```cpp
int sum = (sensor_array + i)->activity; // Access activity using pointer arithmetic
```

## 3. 警報控制（`alarm_control`）

- 首先，在存取感測器之前，先檢查指標是否為空。
- 使用`->`運算子來存取`pillar_men_sensor`結構的`activity`成員。
- 仔細想想，如果感測器的活動量是`0`，應該發生什麼事。警報該觸發嗎？

## 4. 使用`uv_alarm`函式檢查資料是否有異常

- 使用`&`運算子，把指向感測器資料陣列的指標傳入`uv_light_heuristic`函式。
- 請確保在存取感測器資料之前，正確檢查空指標。
- 比較`uv_light_heuristic`的結果和感測器的`activity`值，判斷警報是否該觸發。
