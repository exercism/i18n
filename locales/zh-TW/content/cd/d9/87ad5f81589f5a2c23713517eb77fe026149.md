# 疊代器組合

多個疊代器可以共用同一個迴圈。每一輪各前進一次。

```sather
   loop
      a ::= xs.elt!;
      b ::= ys.elt!;
      ...
   end;
```

## 終止

只要**任何**一個疊代器沒有東西可取，迴圈就立刻結束。其餘的疊代器不會前進，迴圈主體剩下的部分也不會執行。

也就是說，同時走訪兩個陣列只會跑`min(xs.size, ys.size)`輪。如果想走完比較長的那個，就改成走訪索引位置，並自己為較短的陣列把關。

## 每個呼叫位置都是獨立的一趟走訪

疊代器的位置屬於它在程式中*被寫下的地方*，而不是那個物件本身。所以：

```sather
   loop
      #OUT + xs.elt! + xs.elt!;      -- two walks, each advancing separately
   end;
```

每一輪會從兩趟獨立的走訪中各取一個不同的元素。只取一次，然後把值保存起來。

## 無限疊代器

| 疊代器 | 產生 |
| --- | --- |
| `n.up!` | `n`、`n+1`、`n+2`、……永遠持續下去 |
| `n.upto!(m)` | `n`到`m`，然後結束 |

無限疊代器一定要搭配會結束的東西，或是搭配`break!`或`until!`。單獨使用時會永遠迴圈下去。

把`1.up!`搭配走訪集合，是為項目編號的慣用做法，值得一看就認出來。

## 為什麼這是一個獨立的概念，而不是附屬於其他概念

當迴圈在*第一個*疊代器用完時就結束，這條規則最容易寫出那種悄悄出錯、而不是明顯壞掉的程式：它不會當掉，只是提早停下來。如果把它併進介紹疊代器的練習，或併進要自己寫疊代器的練習，就表示學生會在還有其他新東西要學的同時遇上它。
