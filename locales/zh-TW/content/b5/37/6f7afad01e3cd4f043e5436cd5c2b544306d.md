# 關於

Julia 和大多數程式語言一樣，提供了豐富多樣的集合型態。

有些本質上就是有序的（包括`Vectors`和更高維度的`Arrays`），因此我們可以依位置存取元素。
其他集合則是無序的（`Sets`、`Dicts`），元素必須透過鍵或值來存取。

最簡單的情況是，假設我們有一個由`Ints`組成的`Vector`，想將它依遞增順序[排序][ref-sorting]。

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

很簡單！
[`sort()`][ref-sort]這個函式的名字一看就懂，而且似乎會回傳排序後的`Vector`。

_只是開玩笑的！_
進到課程大綱的這個階段，你或許已經猜到（而且猜對了），還有一些細節值得我們討論。

## 會修改與不會修改的函式

執行`sort(v)`之後，`v`會變成什麼？

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

原本的向量並沒有改變。
`sort()`是一個***不會修改輸入***的函式，它會回傳輸入的_副本_。

在許多情境下，這是很好的設計：我們有一個[純函式][wiki-pure-func]，它的行為很容易推理，即使在平行、分散式的程式碼中也是如此。

另一方面，假設我們有一個包含 10 億個字串的陣列，想對它排序。

排序大概會很慢（後面會再詳細說明）。
此外，我們還得複製所有內容（_很慢！_），並配置足夠的記憶體（_好幾 GB！_）來存放副本。

比較一下這段相當類似的程式碼：

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

現在輸入的`Vector`會原地排序，不需要複製，原本的順序則會永久遺失。

這樣做可能很有效率，也可能藏有 bug，導致意想不到的[副作用][wiki-side-effect]，還可能讓其他使用你程式碼的人一頭霧水。
_請謹慎選擇！_

[`sort!()`][ref-sort!]是一個[會修改輸入的函式][ref-mutating-func]，依照（_非常強烈的_）慣例，任何會修改自己輸入的函式，名稱後面都會加上`!`，用來提醒程式設計師。

## 依什麼排序？

排序`Int64`的值相對簡單：連年幼的孩子都懂 2 比 1 大、比 3 小。

其他型別可能更複雜，不過一般來說，只要`isless(x, y) == true`，就表示`x < y`。
Julia 為大多數標準型別提供了`isless()`的實作，你也可以定義對應的[方法][concept-multiple-dispatch]，來比較自己的[自訂型別][concept-composite-types]。

例如，Unicode 字元（就歐洲字母而言，大寫會排在小寫前面）：

```julia-repl
julia> j = collect("Julia")
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)

julia> sort(j)
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0false069 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
```

我們也可以在排序前，先對每個項目套用任意函式，例如用[`abs`][ref-abs]忽略正負號，或用[`uppercase`][ref-uppercase]做忽略大小寫的排序：

```julia-repl
julia> nums = [3, -2, -4, 1]
4-element Vector{Int64}:
  3
 -2
 -4
  1

julia> sort(nums)
4-element Vector{Int64}:
 -4
 -2
  1
  3

julia> sort(nums, by=abs)
4-element Vector{Int64}:
  1
 -2
  3
 -4

# j is from "Julia", as previously

julia> sort(j, by=uppercase)
5-element Vector{Char}:
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)

julia> vecs = [[1, 3], [4, 2], [3, 4], [2, 1]];

julia> sort(vecs)  # by default sorts by the first element of the (2-element) vectors
4-element Vector{Vector{Int64}}:
 [1, 3]
 [2, 1]
 [3, 4]
 [4, 2]

julia> sort(vecs, by=last)
4-element Vector{Vector{Int64}}:
 [2, 1]
 [4, 2]
 [1, 3]
 [3, 4]
```

對於[多維陣列][concept-mda]，我們可以指定`dims`關鍵字來控制排序的方向。

```julia-repl
# create a matrix of integers in random order
julia> A = reshape(Random.shuffle(1:9), (3, 3))
3×3 Matrix{Int64}:
 8  4  9
 6  7  5
 2  1  3

julia> sort(A, dims=1)  # sort rows
3×3 Matrix{Int64}:
 2  1  3
 6  4  5
 8  7  9

julia> sort(A, dims=2)  # sort columns
3×3 Matrix{Int64}:
 4  8  9
 5  6  7
 1  2  3
```

## 排序索引陣列

如果要排序的元素是大型物件，改用它們的位置索引來操作可能會更容易。

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

因為`langs`是 Vector，每個索引都是落在[範圍][concept-range]`1:length(langs)`內的整數。
對 Vector 呼叫[sortperm()][ref-sortperm]的輸出，就是這些整數的一個[排列][wiki-permutation]，對應到輸入 Vector 排序後的結果。

## 部分排序

你的程式需要把整個輸入都排序好嗎？
如果只有最前面或最後面幾個項目才重要，做[部分排序][wiki-partial-sort]可能會快得多。

Julia 提供了[`partialsort()`][ref-partialsort]和[`partialsort!()`][ref-partialsort!]這兩個函式，它們保證指定的項目或項目範圍會是正確的，但不保證輸入的其餘部分。

第二個引數可以是整數或範圍，代表排序後輸入的索引：

```julia-repl
julia> vsq = [9, 4, 16, 1];  # would be [1, 4, 9, 16] after a full sort

julia> partialsort(vsq, 4)
16

julia> partialsort(vsq, 2:3)
2-element view(::Vector{Int64}, 2:3) with eltype Int64:
 4
 9
```

## 排序演算法

把`[3, 2, 4, 1]`排序，無論對人還是對電腦來說，都是個簡單的挑戰。

如果輸入_大得多_，最好的排序方式是什麼？

這就逼著我們要先定義什麼是「最好」！

- 平均時間最快？
- 最佳情況還是最壞情況的時間？或者取個中間值，例如第 90 百分位的時間？
- 記憶體用量最少？
- 做近似或部分排序，對目前應用來說「夠好」就行？

另外，輸入是什麼？
它可能基本上是隨機的，但特殊情況包括已經排序好的陣列、以相反順序排序的陣列，或是含有大量重複項目的陣列。
不同的演算法在這些情況下，表現會天差地遠。

設計更新、更好的排序演算法，既在智識上令人著迷（_對某種性格的人來說_），也具有商業價值：_這是個強效的組合！_

因此，這個主題有大量的文獻，而且還在穩定成長。

Julia 在大多數情況下會試著選擇合理的預設演算法，不過程式設計師有需要的話，也可以[指定偏好][ref-algorithms]。

下面這個玩具範例很荒謬，但能示範語法：

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v, alg=InsertionSort)
4-element Vector{Int64}:
 1
 2
 3
 4
```
