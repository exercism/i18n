# 指令

Grand Marquee 的開幕之夜到了，全體工作人員正同時忙碌著。
觀眾從每一道門湧入，好幾個售票窗口共用同一卷票券販售，首映場即將售罄，而放映室裡的膠卷還得持續轉動。

工作人員共享的每一樣東西都存在某個記憶體位址，而測試會從多個執行緒同時呼叫你的函式。
如果一個值是在分開的步驟中讀取、修改再寫回，在這樣的負載下就會遺失更新，所以每個函式都必須以原子操作來完成更新。

這個練習中所有共享的值都是 64 位元有號整數。

你有五個任務。

~~~~exercism/note
這個練習中的更新應該以_原子_指令來執行。
測試會並行執行你的函式，並檢查沒有任何更新遺失，所以非原子的讀取-修改-寫回很可能無法通過測試。
~~~~

## 1. 計算入場人數

大門敞開，每一道門前都有帶位員在撕票。
每一個放行的團體都會計入同一份共享的入場人數統計，而即使每道門同時在計數，總人數仍必須正確無誤。

實作 `admit_group` 函式，以原子操作將一個團體的人數加到統計數字上。

這個函式會依序接受以下引數：

- `admissions`：共享入場人數統計的記憶體位址，一個 64 位元有號整數。
- `group_size`：團體中的人數，一個 64 位元有號整數，永遠大於 `0`。

```c
admissions = 120, group_size = 4
// admissions is now 124
```

測試會同時從好幾道門放行團體入場。
最終的統計數字必須等於所有放行團體人數的總和。

這個函式沒有回傳值。
統計數字應該就地更新。

## 2. 更換膠卷

放映機一次只裝得一卷膠卷。
裝上下一卷膠卷與取下目前這卷必須是一個一氣呵成的動作：如果有兩個放映師同時在機器旁，分成兩個步驟可能會把同一卷膠卷交給兩個人，或是讓其中一卷掉到地上。

實作 `change_reel` 函式，以原子操作裝上下一卷膠卷，並回傳原本裝著的那一卷。

這個函式會依序接受以下引數：

- `mounted`：目前裝著之膠卷識別碼的記憶體位址，一個 64 位元有號整數。
- `next_reel`：要裝上的膠卷識別碼，一個 64 位元有號整數。

```c
mounted = 7, next_reel = 9
// => 7, and mounted is now 9
```

這個函式會回傳先前裝著之膠卷的識別碼，型別為 64 位元有號整數。
測試會讓多個執行緒同時透過同一個裝載處交換膠卷，並檢查每一卷交進去的膠卷都恰好被換出來一次。

## 3. 賣出一張票

每個窗口都從同一份共享的售票數來賣票。
像各道門那樣只是把計數加一，在這裡並不夠：每一次售票還必須得知它拿到的號碼。
任兩筆售票不得共用同一個號碼，而在人潮過後，計數必須恰好等於售出的票數。

實作 `sell_ticket` 函式，以原子操作將計數加一，並回傳剛剛售出那張票的號碼。
票號是這次售票_之後_的計數：當計數是 `41` 時，這次售票就是第 `42` 號票。

這個函式會接受一個引數：

- `tickets_sold`：共享售票數的記憶體位址，一個 64 位元有號整數。

```c
tickets_sold = 0
// => 1, and tickets_sold is now 1

tickets_sold = 41
// => 42, and tickets_sold is now 42
```

這個函式會回傳票號，型別為 64 位元有號整數。
測試會同時從好幾個窗口售票：每一個回傳的號碼都必須不重複，而最終的計數必須等於售票筆數。

## 4. 坐滿首映場

首映場有固定數量的座位，每個窗口都在賣它的票。
只有在還有座位時，售票才能成交，而且這場放映絕不能超賣，即使每個窗口在同一瞬間都去搶最後一個座位也一樣。
先檢查計數、再把它加一，這兩個分開的步驟之間會留下空窗，所以檢查與更新必須一起成功或一起失敗。

實作 `claim_seat` 函式，在還有空位時以原子操作劃下一個座位。
當一個座位被劃下時，函式會回傳該座位的號碼，也就是這次劃位之後已佔用座位的計數。
當這場放映售罄時，它會回傳 `0`，並讓計數維持不變。

這個函式會依序接受以下引數：

- `seats_taken`：已佔用座位計數的記憶體位址，一個 64 位元有號整數，絕不會超過 `capacity`。
- `capacity`：這場放映的座位數，一個 64 位元有號整數，永遠大於 `0`。

```c
seats_taken = 0, capacity = 150
// => 1, and seats_taken is now 1

seats_taken = 82, capacity = 150
// => 83, and seats_taken is now 83

seats_taken = 149, capacity = 150
// => 150, and seats_taken is now 150

seats_taken = 150, capacity = 150
// => 0, and seats_taken stays 150
```

這個函式會回傳座位號碼，或在這場放映售罄時回傳 `0`，型別為 64 位元有號整數。

## 5. 看好放映室

放映室只能容納一個人。
記憶體中的一個字組表示它是否有人在使用：`0` 代表空閒，`1` 代表使用中。
工作人員整晚來來去去，每個人都有一項要在裡面完成的任務：在紀錄簿上簽名、把膠卷穿進放映機、歸檔一卷膠卷。
無論任務是什麼，放映室的規矩都一樣，而確保大家遵守就是你的工作：一次只能有一個人在裡面，從任務開始到任務結束為止。

實作 `visit_booth` 函式，它會：

1. 等到放映室空出來；
2. 佔用放映室；
3. 執行訪客的任務；
4. 在任務結束後、回傳之前重新開放放映室。

當放映室被別人佔用時，它應該用 `pause` 禮貌地等待。

這個函式會依序接受以下引數：

- `booth`：使用狀態字組的記憶體位址，一個 64 位元有號整數，值會是 `0` 或 `1`。
- `task`：訪客的任務，一個不接受參數也沒有回傳值的函式。

請注意，測試所執行的任務會查看放映室，也會查看一本共享的紀錄簿。
這代表放映室在整個任務期間都必須被佔用、每次造訪都必須恰好執行一次它的任務，而且同時有多位訪客時，紀錄簿的結果必須完全正確。

~~~~exercism/caution
訪客的任務是一個遵循呼叫慣例的普通函式：

- 它可能會覆寫任何由呼叫者負責儲存的暫存器，所以你應該把任務結束後還需要的東西，收在呼叫碰不到的地方；
- 它還預期在呼叫的當下，堆疊是 16 位元組對齊的。

違反其中任何一條規則，都可能以當機的形式浮現，而不是以檢查失敗的形式。
~~~~
