# 關於

如果一個函式_最後_執行的事情是呼叫自己，它就是[尾遞迴][recursion-tc]。

每次呼叫任何函式時，帶著區域變數與引數的_堆疊框架_都會被放上[函式呼叫堆疊][call-stack]的頂端。當函式回傳時，這個堆疊框架就會從堆疊中移除。

尾遞迴函式可以進行[尾呼叫最佳化][tail-call-optimization]（或稱尾呼叫消除）。這是一種最佳化，當能保證前一個函式不再需要最後一個堆疊框架時，就讓下一次函式呼叫重複使用它。這能減輕函式呼叫堆疊溢位的問題。堆疊溢位是指函式呼叫堆疊上的框架多到沒有記憶體可以再建立新的框架。

## Elm 中的尾呼叫最佳化

在某些情況下，Elm 編譯器在編譯成 JavaScript 時，會自動執行尾呼叫最佳化。

當分支中_最後_一個運算是以單純的函式套用呼叫函式本身時，遞迴函式就能進行這項最佳化。我們來看幾個例子：

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

上面的實作不是尾遞迴，因為`else`分支中的最後一個運算是乘法`n *`。

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

上面的實作是尾遞迴，而且會被最佳化，因為`else`分支中的最後一個運算是`factorialHelper`呼叫自己。對於型別簽章為`Int -> Int`的函式來說，這是不可能的，因此在實務上，尾呼叫最佳化通常得靠定義輔助函式來達成。

## 邊界情況

在某些情況下，編譯器無法最佳化遞迴函式，我們來看幾個例子。

雖然`f x = f (x - 1)`是尾遞迴，但`f x = (x - 1) |> f`不是，因為最後一個運算是函式套用`|>`，而且它被視為與`f`分開。同樣地，以布林條件`f x = x > 0 || f (x - 1)`結尾的函式也不是尾遞迴。

函式`f x = if f (x - 1) then 1 else 0`不是尾遞迴，因為`if`裡的運算式不被視為分支。同樣地，`case`敘述中的遞迴呼叫也不會被最佳化。

函式`f x = let y = f (x - 1) in y`不是尾遞迴，因為它在`let`敘述中呼叫自己，而這不被視為分支。不過，在`f x = let g x = g (x - 1) in g x`中，函式`g`是尾遞迴，即使它定義在`let`敘述裡，還是會被最佳化。

函式`f x = if x > 0 then f (x + 1) else 1 + f x`會被_部分_最佳化：`then`分支可以最佳化，但`else`分支不行。在某些情況下，部分最佳化已經是最好的結果，例如走訪樹狀結構或定義互遞迴函式。
