# 工作流

GitHub Actions 使用了_工作流_的概念：工作流是在特定事件發生時（例如推送提交）自動執行的指令碼。

每個 GitHub Actions 工作流都定義在 `.github/workflows` 目錄中的 `.yml` 檔裡。想進一步了解工作流，可以參考下列文件：

- [工作流語法](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions)
- [選擇工作流的執行時機](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow)
- [選擇工作流的執行位置](https://docs.github.com/en/actions/writing-workflows/choosing-where-your-workflow-runs)
- [選擇工作流要執行什麼](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does)
- [撰寫工作流](https://docs.github.com/en/actions/writing-workflows)
- [最佳實務](/docs/building/github/gha-best-practices)

## 共用工作流

有些工作流會在儲存庫之間共用。

```exercism/caution
共用工作流會自動同步（來源是 [org-wide-files 儲存庫](https://github.com/exercism/org-wide-files/)）。
因此，請不要手動變更它們的內容。
```

### 一般工作流

- [同步標籤](/docs/building/tracks/ci/workflows/sync-labels)：從檔案同步儲存庫的標籤

### 軌道專屬工作流

- [configlet](/docs/building/tracks/ci/workflows/configlet)：檢查軌道的（設定）檔案結構是否正確，包括語法與語意兩方面
- [沒有重要檔案變更](/docs/building/tracks/ci/workflows/no-important-files-changed)：針對會導致現有解法重新測試的 pull request 留言
- [測試](/docs/building/tracks/new/setup-continuous-integration#h-test-workflow)：驗證軌道的練習

### 工具專屬工作流

- [部署](/docs/building/tracks/ci/workflows/deploy)：將軌道工具的 Docker 映像檔部署到 Docker Hub 和 ECR

### 選用工作流

此外，還有一些軌道可以選擇啟用的工作流：

- [暫停社群貢獻](/docs/building/tracks/ci/workflows/pause-community-contributions)：對非 Exercism GitHub 組織成員的使用者新建立的 issue 和 PR 自動留言

## 自訂工作流

維護者可以自由地在他們的儲存庫中新增自訂工作流。
這類工作流的例子包括：

- [shell 指令碼的 lint 檢查](https://github.com/exercism/configlet/blob/3baa09608c8ac327315c887608c13a68ae8ac359/.github/workflows/shellcheck.yml)
- [在 pull request 上自動留言](https://github.com/exercism/elixir/blob/b737f80cc93fcfdec6c53acb7361819834782470/.github/workflows/pr-comment.yml)
- 等等。
