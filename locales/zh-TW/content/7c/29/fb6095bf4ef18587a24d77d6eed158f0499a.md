# 關於

在許多物件導向語言中，常見的做法是透過[子類別化][wiki-subclass]來擴充行為：繼承父類別的方法，同時加入新的方法。如此一來，就形成了物件階層。

Julia _沒有類別_，因此也就_沒有子類別_。那麼，我們要如何繼承並擴充既有的行為呢？

在先前的概念中，我們看過如何建立型別階層，也認識了 Julia 如何運用[多重分派][concept-multiple-dispatch]，依據引數的型別來選擇方法。

Julia 也有幾種非正式的[介面][ref-interfaces]，讓你的自訂型別能夠接上已為標準型別定義好的行為。

用疊代器介面來說明最清楚。

## [疊代器][ref-iterators]

在課程大綱中，我們先前已經看過 Julia 對容器中每個元素進行操作的幾種方式。

- [迴圈][concept-loops]，例如`for item in items...`
- [廣播][concept-vector-operations]：`[1, 2, 3] .- 0.5`
- [高階函式][concept-hof]：`map(√, [1, 4, 9])`
- [推導式][concept-comprehensions]：`[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [生成器][concept-comprehensions]：`(x^2 for x in 1:1e6)`，採用惰性求值。

顯然，Julia 知道如何逐項走訪標準容器：上面例子中的向量與範圍，還有`Set`、`Dict`等等。

我們要如何把這項能力加到自己的自訂容器上呢？尤其當它們能像生成器一樣惰性疊代時。

### 最小需求

要建立可供疊代的序列，我們至少需要兩樣東西：

1. 取得_第一個_項目的方法。
2. 從目前狀態取得_下一個_項目的方法。

Julia 透過`Base.iterate()`函式的方法，以下列步驟完成這些任務：

1. 首先會自動呼叫`Base.iterate(iter)`。
    - 如果沒有東西可以疊代，就回傳`nothing`。
    - 否則，回傳第一個項目與第一個狀態組成的`Tuple`：`(firstitem, firststate)`。
2. 如果上一次疊代有回傳項目，就會自動呼叫`Base.iterate(iter, state)`，並以`firststate`作為它的`state`引數。
    - 如果疊代結束，就回傳`nothing`。
    - 否則，回傳下一個項目與下一個狀態組成的`Tuple`：`(nextitem, nextstate)`。
3. 重複步驟 2，直到疊代結束。

這些步驟全都在「底層」完成，意思是方法呼叫與狀態都由疊代協定在內部管理（狀態維持不透明），只有項目會暴露給高階的結構，例如迴圈。
換句話說，我們看到的永遠只有`item`，其餘的一切都留在黑盒子裡。

[多重分派][concept-multiple-dispatch]是這一切的核心。
`iter`的型別決定要呼叫哪些方法，而引數的數量則決定回傳的是第一個項目還是下一個項目。

標準型別的方法已經定義好了：`Vector`、`Range`、`Set`等等（[目前][ref-iterations-collections]共有 14 種型別）。

若要讓自訂的`MyType`擁有相同的行為，我們首先需要定義：
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

抽離來看，這些聽起來可能很令人困惑，但其實可以相當簡單。
為了說明，想像我們想要一個型別，能產生某個整數`n`的次方，最多到指定的次數。

首先，定義一個自訂型別：

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

現在我們可以為這個型別定義`iterate`方法，但什麼是第一個項目與第一個狀態呢？

有些疊代器需要複雜的設定才能取得第一個項目，但在這個小例子裡，我們可以注意到，回傳的第一個項目就是基底數，因此只要檢查`count`的值是否大於或等於 1 即可。

接著來看第一個狀態，它帶著供下一次疊代使用的資訊。
你需要自己決定為此要追蹤哪些資訊，而且它可以是任何型別。

在這個情況下，我們可以只追蹤要對`n`取次方的「索引」，或者找出效能更好的做法，改用`n`最近的次方（也就是回傳的項目）以及序列中的下一個「索引」。
這兩個數字可以包成一個`Tuple`，並作為`state`回傳。

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

在這個例子中，第一個項目（`p.n`）會回傳給迴圈，而第一個狀態`(p.n, 2)`會傳遞給`iterate(P::Powers, state)`方法。
在那裡，我們可以處理狀態來產生下一個項目，方法是把目前的項目乘上基底數，讓它的次方增加`1`。

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

如果索引值仍在`count`範圍內，就會回傳包含`next`項目與遞增後狀態`(next, index + 1)`的`Tuple`。
當`index`值超過`count`時，則改為回傳`nothing`，表示疊代已經結束。

你也許已經注意到，`iterate(p::Powers)`與`iterate(p::Powers, state)`這兩個方法的內容相當相似。
事實上，只要動點腦筋，這樣的相似性讓我們能用精簡的實作，只保留雙引數的版本，並為狀態加上預設引數：`Base.iterate(p::Powers, state=(1, 1))`
如此一來，就不需要另外那個單引數的`iterate(p::Powers)`。
實務上只要可行，通常都會這麼做。

~~~~exercism/advanced
當我們在[函式][concept-functions]概念中介紹選擇性引數時，並沒有提到實作的部分。

在那之後，我們學到了多重分派，所以現在更容易理解：Julia 會自動把_帶有_選擇性引數的函式，轉換成多個_不帶_選擇性引數的方法。

定義`Base.iterate(P::Powers, state=(1, 1))`，與分別定義`Base.iterate(P::Powers, state)`和`Base.iterate(P::Powers)`完全等價。

到目前為止，我們已經有一些實用的功能了：對於 3 的前 4 個次方，我們可以逐一走訪結果、檢查某個數字是否在結果中，並套用像是`sum()`的彙總函式。

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 其他方法

儘管有了不錯的開始，但並非所有功能都能運作。

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

果然，`length(Powers(3, 4))`給出了完全相同的錯誤訊息。

這很容易修正，因為長度本來就是型別建構子的一部分：在這個例子中是 4。
我們只要為這個型別定義`Base.length()`，就能對這個序列使用推導式與`collect()`。

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

為了效率，最好也定義`Base.eltype()`：結果的元素型別。
這能讓`collect()`之類的函式預先為輸出的`Vector{Int}`配置空間，而不必反覆對`Vector{Any}`執行`push!()`。

注意這個語法，你可能沒見過：這個方法是定義在_型別_上，而不是型別的_實例_上。

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

疊代器_不一定要_有有限的長度。
使用「無限」序列的場合比較有限，但只要能用某種方式`break`跳出迴圈，走訪它們可能還是很有用。
舉例來說，我們可以定義一個`Powers`的變體，產生小於某個上限的值（也許是`typemax(Int)`，以避免整數溢位）。

## 其他介面

### [索引][ref-indexing]

疊代器介面讓我們能拿任意的自訂型別，只要定義幾個簡單的方法，就能讓它像序列一樣運作。

假設我們也希望能夠對序列進行索引：

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

我們可以加上這個行為，[手冊][ref-indexing]裡說明了做法。

最基本來說，我們需要定義`getindex()`。

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

我們還需要定義：

- `firstindex()`與`lastindex()`，用來支援`P[begin]`和`P[end]`。
- `getindex()`的各種變體，以支援用向量與範圍進行索引。
- 理論上還有`setindex!()`，不過很難想像在這個例子裡那到底是什麼意思。

然而，到了這個地步，我們做了這麼多工作，只是為了讓疊代器看起來更像向量。

### [AbstractArray][ref-abstractarray]

也許值得想想其他能提供更好起點的介面。

在這個情況下，我們可以考慮讓`Powers`成為[`AbstractArray`][ref-abstractarray]的子型別，這樣就能免費獲得許多類似陣列的行為。

對`Powers`這個序列來說，對應的陣列是整數陣列，維度為 1。
你有時會看到它寫成`AbstractArray{Int, 1}`，但在較新的 Julia 程式碼中，1 維的別名`AbstractVector{Int}`與 2 維的`AbstractMatrix{Int}`更為常見。

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

現在我們需要的不是`length()`，而是要定義`size()`，帶入各維度長度組成的元組：在這個例子中只有一個維度。

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

我們想用什麼方式為這些項目建立索引呢？
在[多維陣列概念][concept-multi-dimensional-arrays]中，我們介紹了兩種主要做法：

- 每個維度一個索引，因此對矩陣`M`使用`M[row, col]`。
- 單一索引，對應項目在記憶體中的排列方式

這兩者分別稱為`Cartesian`和`Linear`。

這個例子只有一個維度，所以適合用線性索引。

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

注意，在這個情況下我們並沒有定義`iterate()`。
Julia 會根據我們對`getindex()`的定義，自動提供預設的實作。

我們仍然可以自行定義`iterate()`，而且在某些情況下可能更有效率。

如果我們想要更高維度的疊代，使用`AbstractArray`介面特別有價值。
冒著把這個小例子拗到極限的風險，這可能是指`1:n`中每個數字的前`m`個次方，這樣就會逐一產生一個大小為`(m, n)`的陣列。

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [捨入][ref-rounding]

先前的概念曾提過數值型別的各種捨入方式。

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

[`round()`][ref-round]函式比這更有彈性，可以指定[`RoundingMode`][ref-roundingmode]（目前支援 7 種）、輸出的小數位數，以及數字基底。

我們可能希望這些函式也能處理我們的自訂型別。
通常這指的是像座標這樣的複合型別。

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

毫不意外地，有一個`Rounding`介面，最基本的要求是為我們的型別定義`round()`。

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

因為我們在定義中包含了`RoundingMode`，`floor()`與`ceil()`就會自動運作。

當然，我們也可以自由定義更複雜的捨入方式。

- 我們可能想把`Point3D`捨入成距離原點為整數、且方向相同的點。
- 對於角度，我們可能想捨入到氣象預報使用的 16 個方位（_「風向 SSW，風速 15 節」_），也就是 π/8 弧度的倍數。
- 我們可能想加入指定`digits`、`sigdigits`或`base`的能力。
- 針對時間週期，還有[特殊選項][ref-round-periods]

## 總結

介面之所以很難解釋，是因為 Julia 的做法跟大多數其他語言差很多。
特別是，介面的名稱在實作中可能從未被提及：這跟[子類別化][wiki-subclass]或[混入][wiki-mixins]非常不同。

不過，實際上它們簡單得出奇：

1. 定義一個合適的型別，並判斷子型別化是否有用。
2. 從[文件][ref-interfaces]找出需要哪些方法。
3. 為你的自訂型別實作這些方法；通常只有幾個方法，而且相當簡短。
4. 剩下的就交給[多重分派][concept-multiple-dispatch]自動處理。
