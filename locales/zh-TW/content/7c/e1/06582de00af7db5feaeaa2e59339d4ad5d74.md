# 簡介

雖然 `if/else` 運算式可以用來執行條件邏輯，但 Haskell 還有一個更強大的方式來執行條件邏輯：[模式匹配][pattern-matching]。
有了模式匹配，就能用一或多個_模式_來測試一個值。
其中一個例子是_常數模式_，它會拿一個值去比對常數（例如 `1` 或 `"hello"`）。

定義函式時，你可以為不同的模式定義不同的函式主體。
這會讓程式碼簡潔、簡單又好讀。
你可以對任何資料型態做模式匹配，數字、字元、陣列、元組等等都可以。

舉例來說，一個接收整數（`Int`）並讓它更接近 _0_ 的簡單函式，可以寫成這樣：

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero 1 = 0
```

模式匹配要和其他模式搭配使用時，才會開始展現它的威力，例如_變數模式_：

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero n = n - 1
```

上面的例子把 _0_ 以外的所有輸入都一視同仁，對負數會產生錯誤的結果。
這可以用條件模式來解決，也就是所謂的_守衛_，以 `|` 符號表示：

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
```

在上面的例子中，並非所有可能的輸入都有對應的模式。
編譯器會偵測到這點並發出警告。
這是 Haskell 一個非常有用的特色，能幫助確保涵蓋所有可能的路徑，避免執行階段錯誤。
這稱為_窮盡性檢查_。
要解決這個警告，你必須處理所有情況。
在_守衛_裡，你可以使用運算式 `otherwise` 作為 `True` 的語法糖，來接住所有剩下的模式。

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
    | otherwise = 0
```

模式匹配會由上而下依序用每個模式測試值，直到找到相符的模式，並執行該模式對應的邏輯。
**模式的順序很重要！**
