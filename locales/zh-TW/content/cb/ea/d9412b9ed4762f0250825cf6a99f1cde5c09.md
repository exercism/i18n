# 契約

常式的引數和回傳型別，說明了進去和出來的東西是*哪一種*。它們沒辦法說明重量一定要是正數，也沒辦法說明吊具回報的剩餘容量永遠不會超過它實際擁有的量。

**契約**會在常式自己的標頭裡說明這些事，任何讀到它的人都看得見。

## pre

`pre`說明呼叫常式時必須成立的事。它放在回傳型別和`is`之間。

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

這是對**呼叫者**的要求：不要用負的 load 來呼叫它。

## post

`post`說明常式回應時會成立的事。在它裡面，`result`就是要回傳的值。

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

這是對呼叫者的承諾。同時具備兩者的常式就是一場交易：給我這個，我就給你那個。

多個條件可以用`and`連接起來，就像任何布林值一樣：

```sather
      pre load >= 0 and load <= limit
```

## 契約不是例外

拋出的例外是為了處理可能發生的事。被破壞的契約則代表一個**bug**：可能是有人用錯的方式呼叫了常式，或是常式沒做到它說過的事。

所以契約被破壞時，並不會拋出可以捕捉的東西。當契約檢查開啟時，程式會停下來，並印出是哪個常式、哪個條件。當它關閉時，條件甚至不會被檢查，程式就這麼繼續跑進接下來的一團混亂裡。

這就是為什麼契約談的是正確性，而不是處理錯誤輸入的方法。如果錯誤輸入是可以預期的，就檢查它，然後`raise`。如果錯誤輸入代表呼叫者本身有問題，就用`pre`說出來。

## 開啟契約檢查

這裡的 Sather 會在編譯器收到`-chk`時檢查契約：

```
sacomp -chk mine.sa -main MAIN -o mine
```

沒有它的話，`pre`和`post`就只是編譯器讀過、也同意格式正確的文件，僅此而已。這個練習的測試是在沒有`-chk`的情況下建置的，所以它們沒辦法替你抓到被破壞的契約；它們檢查的是常式在被正確使用時，有沒有做出對的事。
