# 測試

Elm 專案的測試都放在該專案的`tests/`子目錄裡。每個練習的測試套件都可以在該練習的根目錄中執行。

```bash
$ cd ~/exercism/elm/hello-world
$ elm-test
```

## 監看變更

儲存變更後自動重新執行測試：

```bash
$ elm-test --watch
```

## 測試驅動開發流程

大多數練習的測試都已經寫在`tests/Tests.elm`檔案中。
你的目標，是撰寫`src/<exercise>.elm`檔案裡所需的程式碼，讓這些測試通過。
先專注在第一個失敗的測試上，修正它，
然後移除或註解掉測試檔案中下一個`skip <|`片段，再重複這個過程，
直到所有測試都通過。

## 卡住了嗎？

你的第一個目標，是讓程式碼能夠編譯，即使裡面還有`Debug.todo`也一樣。
如果你覺得不知道某件事該怎麼做，
把它抽成一個獨立、還沒實作的函式，往往很有用喔。

```elm
complexOperationOnMultipleStrings : List String -> List String
complexOperationOnMultipleStrings allStrings =
    List.map complexOperation allStrings


complexOperation : String -> String
complexOperation input =
    Debug.todo "Extracted operation into its own function"
```

為這個抽出來的函式加上型別標註，
既能幫助你思考，也能讓編譯器給你更好的錯誤訊息。

## 整理你的程式碼

提交之前，不妨用 [`elm-format`](https://github.com/avh4/elm-format) 整理一下程式碼，
甚至把它設定在你的文字編輯器裡，在儲存時自動格式化。
