# 關於

Factor 把串流 I/O 拆成兩層。下層是*明確串流* API：每個詞都把串流當成引數傳進去。上層是*環境串流* API：短、單行的詞，作用在目前綁定的那個串流上。兩層都建立在同一個[協定][stream-protocol]上，上層的詞只是查出當下的環境串流，再把呼叫轉送過去。

## 明確串流的詞

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents`會把整個串流讀完；`stream-lines`會讀完並依行邊界切開；`stream-readln`一次回傳一行（串流結束時回傳`f`）。

## 環境串流的詞

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

這些是日常使用的 I/O 詞。它們會從動態變數`input-stream` / `output-stream`查出目前的輸入或輸出串流，然後把呼叫轉送過去。也因為這樣，要把`print`重導向到字串，只要在 quotation 執行的期間把`output-stream`綁定起來就行。

## 內建的串流建構子

| 詞              | 詞彙庫                | 建構出的東西                  |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | 讀取字串常值          |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | 把寫入的內容收集成字串   |
| `<file-reader>`   | [`io.files`][io.files]           | 以指定編碼讀取檔案   |
| `<file-writer>`   | [`io.files`][io.files]           | 以指定編碼寫入檔案  |

這四個產生的都是可處置的物件：它們擴充了`destructors`裡的`disposable`，所以下面這些`with-…`組合子會在離開時釋放它們。

## 限定範圍的綁定

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

每一個都會開啟一個串流，把它綁定成內層 quotation 的環境輸入或輸出，並在離開時處置它，就算 quotation 拋出例外也一樣。它們是`boatswains-bilge`的解構子組合子，特化為串流版本。

`with-string-writer`是特別簡潔的一種：它會自動建構一個全新的`<string-writer>`，用那個 writer 當作環境輸出來執行 quotation，然後回傳累積起來的字串。整個「捕捉 quotation 輸出」的模式，就是一個詞。

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## 為什麼要有環境串流？

動態變數的綁定，就是`print`能在一個不知道自己是被互動執行、寫進日誌檔，還是寫進被捕捉的測試緩衝區的程式裡照常運作的原因。只要換掉綁定一次，每個呼叫`print`的詞就會做出正確的事，完全不用重新接線。這就是上層替你換來的反轉。

要*實作*串流，也就是定義自己的類別來接上這個協定，請看`streams`概念（在`telegraphers-tape`裡教到）。
