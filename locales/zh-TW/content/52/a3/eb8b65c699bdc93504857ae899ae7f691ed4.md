# 關於

_「日期和時間這種東西，我們連小孩子都在教。能有多難？」_

許多程式設計師都犯過這個錯，隨之而來的經驗往往對他們的健康和幸福沒什麼好處。

任何用日期和時間從事非簡單程式設計的人，起碼都該準備好去理解並減輕潛在的問題。

本文會試著概略說明 R 如何處理日期和時間，但更進一步的細節仍有賴查閱完整文件。

身為一門資料科學語言，日期和時間在 R 裡格外重要。
許多資料都是以時間序列的形式到來：疫情爆發期間的每日病患數、政府通報的每月就業數字、築巢聚落中的鳥類族群數量、主要經濟體的年度 GDP，還有數不清的其他例子。

_這代表 R 讓日期和時間的處理變簡單了嗎？_

很遺憾，並沒有！

Base R 裡的日期和時間功能評價不佳，如今大多已很少使用。

[`lubridate`][web-lubridate]套件是一大改良，但要準備好面對一個龐大又複雜的函式庫，它是為了處理各式各樣龐大又複雜的問題而設計的。

`lubridate`原本是獨立發展的，現在已併入`tidyverse`集合中。
用`library(lubridate)`或`library(tidyverse)`都能載入它。

協助你使用`lubridate`的資源包括：

- 一份[參考頁面][ref-lubridate]。
- 一份 PDF 格式的[速查表][cheat-lubridate]。
- R for Data Science 裡的[一個章節][book-dates-times]。

## 日期與日期時間

`date`就只是一天，不帶任何時間資訊。

在內部，日期儲存為自`1970-01-01`起算的（有號）天數。

```R
today()
#> [1] "2026-04-22"
typeof(today())  # just a number
#> [1] "double"
class(today())  # the class understands how to interpret the raw number
#> [1] "Date"
```

`datetime`結合了日期、時間與時區資訊。

在內部，它儲存為 UTC 時區中自 1970 年初起算的秒數。

```R
now()
#> [1] "2026-04-22 15:37:11 MST"  # mid-afternoon in Arizona
typeof(now())
#> [1] "double"  # again, just a number
# POSIX datetimes are built into most operating systems as standard
class(now())
#> [1] "POSIXct" "POSIXt"
```

或許出乎意料，R 對純時間值並沒有內部的表示法。
需要這項功能的人（Exercism 之外）可以安裝[`hms`][ref-hms]套件。

## 處理`date`與`datetime`值

最常見的日期與時間需求大概是：

- 解析某種合適的輸入格式，藉此建構出日期或日期時間。
- 從日期或日期時間取得所需的數字或字串格式。
- 對日期或日期時間值套用一個偏移量。
- 計算兩個這類值之間的時間跨度。
- 取得目前的日期（用`today()`）和/或日期時間（用`now()`）。

### 從字串解析

日期和時間有許多種寫法，而且往往因文化而異。
像「7/6/23」這種全數字的日期既含糊又令人困惑，還曾在跨國組織裡造成許多代價高昂的錯誤（_作者說這句話是出於慘痛的親身經驗_）。

國際標準（y-m-d）定義於 [`ISO 8601`][wiki-ISO8601]，有兩大優點：

- 解析又快又沒有歧義。
- 排序很簡單，因為日期時間可以當成一般文字，依字母順序排序。

然而，資料科學就是得用手上找得到的資料來做事，抱怨別人怎麼格式化資料通常毫無意義。

Base R 有轉換函式，接受一個格式字串（預設為 ISO 8601）。

```R
as.Date("2026-04-22")
#> [1] "2026-04-22"
as.Date("4/22/26", format = "%m/%d/%y")
#> [1] "2026-04-22"
as.POSIXct("2026-04-22 15:30:09 MST")
#> [1] "2026-04-22 15:30:09 MST"
```

這些格式字串類似已有數十年歷史的`strptime()`函式，_許多_語言都內建了它。
熟悉這套語法的程式設計師，也可以選擇使用 lubridate 裡的[`fast_strptime()`][ref-parse_dt]函式。

更有用的是，`lubridate`提供了一系列[輔助函式][ref-parsing]，名稱本身就代表了欄位的順序。
只要這些函式知道要找哪些值、順序為何，解析起來就靈活得令人印象深刻。

```R
mdy("4/22/26")
#> [1] "2026-04-22"
mdy("April 22nd 26")
#> [1] "2026-04-22"
mdy("Wednesday, April 22nd 2026")
#> [1] "2026-04-22"
mdy_hm("Wednesday, April 22nd 2026, 4:14 pm")
#> [1] "2026-04-22 16:14:00 UTC"  # defaults to your OS timezone
```

這些輔助函式都是[`parse_date_time()`][ref-parse_dt]函式的特例，後者接受像`"mdy_hm"`這樣的格式字串作為第二個引數。

### 從數值建構

當你的程式把日期或日期時間的各個組成部分拆成獨立數字時，可以用[`make_date()`或`make_datetime()`][ref-make_datetime]把它們組裝起來。

以下是可提供的組成部分，顯示它們的順序與預設值：

```R
make_datetime(
  year = 1970L,
  month = 1L,
  day = 1L,
  hour = 0L,
  min = 0L,
  sec = 0,
  tz = "UTC"
)
#> [1] "1970-01-01 UTC"

make_datetime(2026, 4, 22, 17)
#> [1] "2026-04-22 17:00:00 UTC"
```

`make_date()`當然只接受年、月、日三個引數。

### 以人類可讀的形式輸出

R 主控台會自動把日期或日期時間顯示為字串表示。
這通常很方便，但有時會造成誤導。

在內部，日期和日期時間是數字（加上幾個屬性），不是字串。
在預期會拿到字串的地方回傳日期（時間），會導致問題，所以我們得知道該怎麼做轉換。

簡單的做法是使用 Base R 的[`as.character()`][ref-ascharacter]，它會以 ISO 8601 格式輸出字串。

日期時間另外還有[`format_ISO8601()`][ref-iso8601]函式，可選擇四捨五入到想要的精確度。

```R
today() |> as.character()  # a date
#> [1] "2026-04-23"
now() |> as.character()  # a datetime
#> [1] "2026-04-23 09:07:09.779319"
now() |> format_ISO8601() # defaults to nearest second
#> [1] "2026-04-23T09:07:38"
```

沒幾個非程式設計師想看 ISO 8601 的輸出，所以處理因文化而異的日期和時間格式是不可或缺的。

Base R 提供了[`format()`][ref-format]函式，它使用的格式字串類似許多其他語言內建、歷史悠久的`strftime()`函式。

```R
format(today(), "%A, %d %B %Y")
#> [1] "Thursday, 23 April 2026"
```

這種 Base R 的做法很醜但可靠。
以下是幾個較常見的代碼：

代碼 | 結果
-- | --
%d | 月內第幾天（5、17、28 等）
%a | 星期幾的縮寫（Mon、Tue、Wed 等）
%A | 完整的星期幾名稱（Monday、Tuesday 等）
%w | 星期幾的數字（0-6，星期日為 0）
%u | 星期幾的數字（1-7，星期一為 1）
%b | 月份的縮寫（Jan、Feb 等）
%B | 完整的月份名稱（January、February 等）
%y | 兩位數年份（例如 89）
%Y | 四位數年份（例如 1989）
%h | 小時（24 小時制）
%m | 分鐘
%s | 秒
%z | 與 UTC 的時差
%Z | 時區（字元）

Lubridate 則想用[`stamp()`][ref-stamp]函式，以及範圍更窄的`stamp_date()`和`stamp_time()`，提供更符合人類習慣的替代方案。

它們接受一個範本字串（也就是想要輸出的一例），並建立一個自訂函式來產生該格式。

Lubridate 會嘗試猜測格式，但經常碰上歧義而產生錯誤的結果。
要有心理準備提供格式字串（例如`"dmy"`）來消除歧義。

在 Exercism 上，指定`locale = "C"`也很有用，可以繞過你系統的地區設定，改用英文運作（測試就是這麼預期的）。
地區設定很複雜！

```R
sf <- stamp("Saturday, June 27, 2026 at 14:45", locale = "C")
#> Multiple formats matched: "%A, %B %d, %Y at %H:%M"(1), "Saturday, %Om %d, %Y at %H:%M"(1), "Saturday, %B %d, %Y at %H:%M"(1), "%A, %Om %d, %Y at %H:%M"(0)
#> Using: "%A, %B %d, %Y at %H:%M"

sf(make_datetime(2023, 3, 29, 15, 0, 0))
#> [1] "Wednesday, March 29, 2023 at 15:00"
```

### 設定或擷取組成部分

Lubridate 提供了[許多函式][ref-set-get]來取得或設定日期或日期時間的元素：像是`year()`和`second()`這類顯而易見的，也有`quarter()`和`epiweek()`這類更專門的。

這類函式全都可以用來取得值，其中大多數也能用來設定值。

```R
dt <- now()
dt
#> [1] "2026-04-23 15:47:11 MST"

# get
month(dt)
#> [1] 4

# set
month(dt) <- 11
dt
#> [1] "2026-11-23 15:47:11 MST"
```

對`wday()`（一週中的第幾天）和`month()`而言，預設輸出是整數，不過：

- 設定`labels = TRUE`會回傳對應目前地區設定的縮寫字元字串。
- 再設定`abbr = FALSE`則會回傳完整名稱。

```R
d <- today()
d
#> [1] "2026-04-23"
wday(d)
#> [1] 5
wday(d, label = TRUE)
#> [1] Thu
#> Levels: Sun < Mon < Tue < Wed < Thu < Fri < Sat
wday(d, label = TRUE, abbr = FALSE)
#> [1] Thursday
#> Levels: Sunday < Monday < Tuesday < Wednesday < Thursday < Friday < Saturday
```

這些標籤是`categorical variables`，會是另一個概念的主題。
值被限制在列出的`Levels`之內，這些同時也顯示了排序順序。

一週預設從星期日開始，但可以用`week_start`引數改變（用`1`代表星期一）。

```R
dt <- make_datetime(2026, 4, 23)

# default behavior
wday(dt)
#> [1] 5
wday(dt, label = T)
#> [1] Thu

# set week_start to Monday
wday(dt, week_start = 1)
#> [1] 4
```

有幾個工具函式會回傳`TRUE`/`FALSE`值，例如`leap_year()`和`dst()`（現在是否為日光節約時間？）。

每個月的長度不一，所以`days_in_month()`會給出整數值。

### 進位與取整

數字可以用`round()`、`floor()`和`ceiling()`這類[函式][ref-round]來進位。

依此類推，日期和日期時間也有[函式][ref-round_date]：`round_date()`、`floor_date()`和`ceiling_date()`。

預設會進位到秒，但`unit`引數還有許多其他選項。
詳情和大量範例請見[文件][ref-round_date]。

## 時間跨度

`date`和`datetime`值都代表時間軸上的某個瞬間。

我們該怎麼處理像「昨天的這個時候」或「一週之後」這樣的概念？

熟悉其他科學導向語言的學生，可能知道 Python 的`datetime.timedelta`或 Julia 的`Period`型別。

相較之下，R 有足足三種表示時間跨度的方式，各有不同的長處與限制。
一如往常，挑最適合你當下情境的那一種。

各種跨度可以輕鬆互相轉換，用`as.period()`、`as_duration()`和`as.interval()`即可。

可以用`is.period()`之類的函式來查詢跨度的型別。

### 期間

一個`period`，例如`hours(3)`，可以用來把時鐘時間增加 3 小時。

日光節約時間（DST）這類不規則之處大致會被忽略。

所有的期間都是單位的複數名稱：`years`、`weeks`等。

```R
d <- today()
d
#> [1] "2026-04-25"

d + weeks(2)
#> [1] "2026-05-09"

# dates are coerced to datetimes at midnight if necessary
d - hours(20)
#> [1] "2026-04-24 04:00:00 UTC"

hours(3)
#> [1] "3H 0M 0S"
```

### 持續時間

一個`duration`，例如`dhours(3)`，會增加 3 小時的物理時間，並顧及 DST 這類讓時鐘時間偏離物理時間的不規則之處。

所有的持續時間都是在對應的期間前面加上`d`：`dyears`、`dweeks`等。

```R
dhours(3)
#> [1] "10800s (~3 hours)"
```

### 區間

一個`interval`是一段起始與結束時間的組合，可以用[`interval()`][ref-interval]函式或`%--%`中綴運算子建立。

```R
# the next 2 lines were run about 33s apart, so now() is different
dt1 <- now()
dt2 <- now() + hours(1)

# interval(0 function)
ivl <- interval(dt1, dt2)
ivl
#> [1] 2026-04-24 16:24:54 MST--2026-04-24 17:25:27 MST
class(ivl)
#> [1] "Interval"
attr(,"package")
#> [1] "lubridate"

# infix operator
iv2 <- dt1 %--% dt2
iv2 == iv1
#> [1] TRUE

# conversions
as.period(ivl)
#> [1] "1H 0M 32.738214969635S"
as.duration(ivl)
#> [1] "3632.73821496964s (~1.01 hours)"

# components
int_start(ivl)
#> [1] "2026-04-24 16:24:54 MST"

# is datetime within the interval?
(now() - minutes(20)) %within% ivl
#> [1] TRUE
```

## 時區

處理時區可能頗有挑戰。
下面這段引文出自 Python 文件，但對 R 同樣適用：

> 「世界各地調整時間的規則，政治考量多過理性，而且經常變動，除了 UTC 之外，沒有哪一套標準適用於所有用途。」

關於時區的幾個通則：

- `datetime`一定包含時區（`tz`）；`date`則不具時區概念。
- 日期時間的建構函式一般都預設為 [UTC][wiki-UTC]。
- [`now()`][ref-now]函式是例外：它會從系統時鐘取得你的本地時間，並包含`tz`。
  預設會使用本地的`tz`，但也可以指定其他的，例如`now("UTC")`。

```R
# timezone defaults to UTC
local <- ymd_hm("2026-04-25 10:32")
local
#> [1] "2026-04-25 10:32:00 UTC"

# timezone can be specified
AZ <- ymd_hm("2026-04-25 10:32", tz = "America/Phoenix")
AZ
#> [1] "2026-04-25 10:32:00 MST"

# same clocktime, different tz
local - AZ
#> Time difference of -7 hours
```

用持續時間做與時區相關的運算，會比用期間更可靠。

```R
dt <- make_datetime(2020, 10, 31, 12, tz = "Europe/Helsinki")

# EET is 2h ahead of UTC
dt
#> [1] "2020-10-31 12:00:00 EET"

# A week earler, EEST (summer time) is 3h ahead of UTC

# a 7-day period => midday
dt - days(7)
#> [1] "2020-10-24 12:00:00 EEST"

# a 7-day duration => 1 pm
dt - ddays(7)
#> [1] "2020-10-24 13:00:00 EEST"
```

無論用期間計算或用持續時間計算，lubridate 都會辨識出從東歐時間切換到東歐夏令時間，但只有用持續時間的算法會針對那 1 小時的時差做調整。
