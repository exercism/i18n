# 自訂疊代器

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | 常式 | 疊代器 |
| --- | --- | --- |
| 名稱 | `foo` | `foo!` |
| 交回值 | `return` | `yield` |
| 結束方式 | `return`，或執行到結尾 | `quit`，或耗盡 |
| 可呼叫的位置 | 任何地方 | 只能在`loop`內 |
| 保留自己的位置 | 否 | 是 |

## yield

`yield`會交出一個值並暫停。下次輪到它時，一切都會復原：區域變數、它在自己迴圈裡的位置，以及它本身所呼叫的其他疊代器的位置。

巢狀迴圈裡的`yield`會從最內層的那一個繼續，這正是讓走訪巢狀結構寫起來如此直覺的原因：

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

結束這個疊代器，連帶結束呼叫它的迴圈。它不帶任何值：`quit`不是最後一個結果，而是宣告已經沒有結果了。

帶有回傳型別的疊代器，每次 yield 時都必須`yield`一個值；`quit`就是它拒絕交出的方式。

## once

```sather
   markers!(once count : INT) : INT is
```

`once`引數會在進入迴圈時求值一次並保留下來。一般引數則每一輪都會重新求值，當傳入的運算式裡含有另一個疊代器呼叫時，這點就很重要：

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

除非你確實想要這種行為，否則就把引數標成`once`。整個函式庫都是這麼做的。

## self 與疊代器

疊代器可以在某個物件上被呼叫，此時`self`就是那個物件。它暫停的狀態屬於呼叫處，不屬於物件，所以兩個迴圈走訪同一個物件時不會互相干擾。

## 何時該寫一個

當答案是一個序列，而該由呼叫者決定要取用多少時，就寫一個疊代器。提早停下來不花任何成本，也不會建構用不到的東西；相較之下，回傳`ARRAY`的常式就必須先把整個東西建構出來。
