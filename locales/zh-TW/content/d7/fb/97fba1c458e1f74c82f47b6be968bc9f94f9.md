# 簡介

大多數純量位元運算都有 packed 版本。它們遵循和 SIMD 整數運算相同的一般語法，但沒有大小後綴：

| 指令   | 說明                              |
|-------------|-----------------------------------|
| `pand`      | 兩個 128 位元值的位元 AND |
| `por`       | 兩個 128 位元值的位元 OR  |
| `pxor`      | 兩個 128 位元值的位元 XOR |

請注意，並沒有 packed 的 `NOT`。
不過，有一個 ANDN 運算，它會先對**目的**運算元取補數（翻轉所有位元），再計算兩個運算元之間的 AND。
可以把它想成是 NOT 加上 AND 的組合：

| 指令   | 說明                                                     |
|-------------|-----------------------------------------------------------------|
| `pandn`     | **取補數後**的目的運算元與來源的位元 AND |

請注意，位元運算會結合兩個不同運算元中相同位置的位元，因此 lane 的邊界不會改變結果。
這就是為什麼這些指令沒有大小後綴：暫存器的行為就像單一 128 位元的 lane：

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
這個概念中的所有指令都會計算位元，但不會設定任何旗標。
之後的概念會談到如何用 packed 值處理條件判斷。
~~~~

## 逐 lane 位移

位移和純粹的位元運算不同，它確實會讓位元跨越位置移動，因此需要有 lane 大小來設定邊界。
在每個 lane 之內，它們的行為就像對應的純量版本，位元也永遠不會從一個 lane 跨越到相鄰的 lane：

| 指令               | 說明                         |
|---------------------------|-------------------------------------|
| `psllw`、`pslld`、`psllq` | 每個 lane 的邏輯左移        |
| `psrlw`、`psrld`、`psrlq` | 每個 lane 的邏輯右移       |
| `psraw`、`psrad`          | 每個 lane 的算術右移    |

請注意，這些指令遵循 packed 整數運算的語法，其中包含大小後綴。
沒有以 byte 為 lane 的位移，只有 word、dword，以及 qword（算術右移除外）。

packed 位移和純量版本的一項差異，在於運算的名稱：

- 純量用 `shl` 和 `shr`，這裡則用 `sll` 和 `srl`，代表 **s**hift **l**eft（**r**ight）**l**ogical。
- 純量用 `sar`，這裡則用 `sra`，代表 **s**hift **r**ight **a**rithmetic。

名稱雖然不同，運算本身卻是一樣的：

- 邏輯右移會把最高的位元補 0。
  它等同於對 2 的次方做無號除法。
- 算術右移會把最高的位元補上符號位元的值。
  它等同於對 2 的次方做有號除法，並朝負無限大捨入。
- 左移一律補 0（這就是為什麼不需要算術左移）。

位移次數對每個 lane 都相同。
它可以是立即值，或是 `xmm` 暫存器的低 64 位元：

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
位移次數大於 lane 寬度時，不會像純量的 `shl`/`shr` 系列那樣繞回。
它只會產生 0（若是算術右移，則產生全為符號位元的值）。
~~~~

## 浮點數位元運算

每個位元運算指令也都有一組以 float 命名的對應版本，語法和我們在 packed 浮點數運算看過的一樣：

| 整數名稱 | 浮點數名稱          |
|--------------|----------------------|
| `pand`       | `andps`、`andpd`     |
| `pandn`      | `andnps`、`andnpd`   |
| `por`        | `orps`、`orpd`       |
| `pxor`       | `xorps`、`xorpd`     |

由於位元運算作用在位元上，實際上整數運算和浮點數運算算出的結果相同。
名稱之所以不同，有兩個原因：

1. 記錄意圖，就像我們會依被複製的位元組性質，偏好選用 `movdqa`、`movaps` 或 `movapd` 一樣。
2. 整數運算和浮點數運算通常屬於不同的執行領域。
   同一個執行領域內的運算，通常能更快地接續執行。

浮點數值沒有位移運算。

## 浮點數的位元表示法

IEEE 浮點數的位元表示法和整數非常不同。

在無號整數中，每個位元的意義都一致：它代表對應該位元索引的 2 的次方。
整數的值就是所有值為 1 的位元所對應之 2 的次方之和。
這就是為什麼位移可以讓數字乘或除以 2 的次方：我們只是在改變每個值為 1 的位元索引。

在有號整數中，大多數位元的解讀方式和無號整數相同。
不過，最高位元很特別。
如果它被設為 1，我們不是把它加到其他位元上，而是要減去對應的 2 的次方，結果就會是負數。
實際上，要改變一個數字正負號，概念上需要兩個步驟：翻轉所有位元（`not`），然後把結果加 1（`inc`）。

浮點數的位元沒有統一的意義，必須依它們的位置以截然不同的方式解讀：

| 欄位    | 索引（32 位元） | 索引（64 位元） |
|----------|------------------|------------------|
| 符號     | 31               | 63               |
| 指數 | 30-23            | 62-52            |
| 小數 | 22-0             | 51-0             |

算出來的數字是 `(-1)^sign * 1.fraction * 2^(exponent - bias)`。
偏差值取決於精度：

| 大小   | 偏差值 |
|--------|------|
| 32 位元 | 127  |
| 64 位元 | 1023 |

在兩種格式中，數字的正負號完全由符號位元決定。
要改變浮點數的正負號，只要翻轉這個位元（一個 XOR 運算）就好。
要取得絕對值，只要把它清除（一個將該位元清零的 AND）就好：

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

請注意，在這種位元表示法下，位移的結果並不具有可預測且一致的行為。
小數部分可能會「溢」進指數，指數則可能溢進符號。

不過，有時把表示法的不同部分獨立出來操作會很方便。

舉例來說，指數中的位元應該先解讀為無號數，再從中減去偏差值。
這表示我們可以產生一個 32 位元或 64 位元的整數，其底層的位元表示法對應到該浮點格式中的某個 2 的次方。
接著就能用這個原始位元表示法，去乘或除另一個浮點數。

例如：

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

反過來說，我們也可以用遮罩做 AND 來取出 packed 浮點數的指數，這個遮罩只設定了指數位元，其餘都清零。
再搭配位移和減法，就能得到每個 lane 未加偏差的有號整數指數：

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
直接操作浮點數的原始位元雖然在某些情況下很有用，但應該謹慎為之。
只有在沒有溢位或下溢，而且輸入數字是正規數時，對指數欄位做加減才是安全的。
另外，把一個有效的 `x` 加到 `0.0` 的指數欄位上，結果會是 `2^(x - bias)`，而不是 `0.0 * 2^x`。
~~~~
