# 關於

在 C# 應用程式中，隨機性通常是使用 `System.Random` 類別來實作。

這篇[文章][system-random]是這個主題很棒的入門介紹。

在熟悉某個程式庫類別時，永遠值得研究它的[文件][system-random]，了解其中的屬性、方法以及它們的多載。

這個程式練習凸顯了幾個重點：

- 隨機數字產生器不需要[種子][random-seedless]。
- `Random.Next()` 可以產生一個範圍的整數
- `Random.Double()` 可以產生 0 到 1 之間的浮點數
- `Next...()`、`Double()` 和 `Sample()` 中的上界都是**不包含**的，所以 `Random.Next(1,19)` 會產生 1 到 18 的值，但不包括 19。
- 取得隨機數字之後，你想怎麼用它都可以

針對最後一點，有三種實作模式：

- 你可以取得隨機數字並加以運用。以這個程式練習來說，就是呼叫 `Random.NextDouble()` 再乘以 100。這篇[文章][random-use-case-array]討論了如何從陣列中隨機選取元素。
- 你可以繼承 `System.Random` 並覆寫 `Sample()` 方法。
- 你可以把 `System.Random` 的執行個體封裝成自己類別的成員，例如[用來產生布林值][random-use-cases]。

`Random` 產生的數字不保證是唯一的。

[建議][random-thread-safety]把 `System.Random` 具現化為靜態成員。不過要注意，它不是執行緒安全的。

你可能會看到某些文件不建議使用無種子建構函式。這主要適用於 .NET Framework，而不是 .NET Core（也就是 _Exercism_ 使用的）。完整的來龍去脈請看[這篇][random-multiple-instantiations]。

建議你不要把 `System.Random` 用於加密或安全性用途。請參考這個[提供者][crypto-provider]和這個[數字產生器][crypto-rng]。

## 執行緒安全

在程式庫 API 的脈絡下，「不是執行緒安全」只是個簡略的說法，意思是：如果你可能會透過多個並行[執行緒][threading]存取這個類別的執行個體，就應該自己提供執行緒同步機制；如果是集合，則可以考慮使用該類別的並行版本。少了這些防護，就很可能發生[競爭條件][so-race-conditions]。如果你的程式碼基底不會用到多個執行緒，而且未來也不太可能用到，那這個警告就沒什麼好擔心的。
