# 簡介

幫浦、閥門、軟管，任何佔用作業系統資源（開啟的檔案、網路連線）的東西，用完之後都必須被*釋放*。Factor 的[`destructors`][destructors]詞彙把這些資源包進一個框架裡，保證一定會清理乾淨，即使程式執行到一半被錯誤打斷也一樣。

## 類別與泛型詞

類別只要擴充`disposable`並實作`dispose*`泛型詞，就能加入這個框架：

```factor
USING: accessors destructors kernel ;

TUPLE: pump < disposable opened ;

: <pump> ( -- pump )
    pump new-disposable t >>opened ;

M: pump dispose* f >>opened drop ;
```

`new-disposable ( class -- obj )`會配置元組，*同時*把它註冊到框架裡。就算在配置完成之後、下一個安全點之前發生例外，資源也不會外洩。框架保證每個物件的`dispose*`**最多執行一次**，重複呼叫`dispose`不會有任何作用。

## 公開的呼叫者使用`dispose`

```
dispose          ( obj -- )                ! release; safe to call twice
with-disposal    ( disposable quot -- )    ! scope one resource
with-destructors ( quot -- )               ! open a registry scope
&dispose         ( obj -- obj )            ! dispose on normal *or* failure exit
|dispose         ( obj -- obj )            ! dispose only if the scope unwinds
```

`with-disposal`是單一資源的形式：它會把 disposable 推給內部的引述，並在離開時釋放它。

```factor
USING: destructors io ;

<pump> [
    "pumping" print
] with-disposal
! pump released on the way out — even if `print` had thrown
```

需要處理多個資源時，就開一個`with-destructors`作用域，把每一次取得的資源都註冊進去。`&dispose`（& 符號）表示「離開時一律釋放，不論成功或失敗」；`|dispose`（| 符號）表示「**只在**失敗時釋放」，適合成功路徑要把資源交給願意接手的呼叫者時使用。

```factor
[
    <pump> &dispose
    <pump> &dispose
    ! ... use the pumps ...
] with-destructors
! both pumps released
```

如果只想要單純的 try/finally 而不需要註冊表，[`cleanup`][cleanup]（位於`continuations`）是更底層的基本工具，但`with-destructors`才是現代 Factor 的慣用寫法。

[destructors]: https://docs.factorcode.org/content/vocab-destructors.html
[cleanup]: https://docs.factorcode.org/content/word-cleanup%2Ccontinuations.html
