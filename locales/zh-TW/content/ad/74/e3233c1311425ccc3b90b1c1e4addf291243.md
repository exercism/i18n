# 簡介

## 迴圈

**迴圈**是一連串的指令，可能會執行不只一次，直到符合結束條件為止。

在 x86-64 中，迴圈通常會用跳躍至先前的標籤來建立：

```x86asm
example_loop:
    ...
    jmp example_loop
```

請注意，無條件跳躍至先前的標籤，一定會將執行流程轉移到這個標籤。
這表示迴圈會永遠重複下去，除非有另一個跳躍可以跳到重複序列之外。

例如，這個迴圈不會結束：

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

而這個迴圈可能會結束，取決於是否符合條件：

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### 計數迴圈

計數迴圈幾乎總是以相同的方式結束：更新計數器或比較兩個值的指令，緊接著是決定是否要再繞一圈的條件跳躍。

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0`在上面的程式碼中不是必要的，因為當結果為`0`時，`sub rsi, 1`已經設定了`zero flag (ZF)`。

雖然`cmp`是在組合語言中測試條件的主要方式，但許多指令都會更新旗標。
例如，許多整數運算或位元運算指令會在結果為`0`時更新`ZF`，並在結果為負（也就是最高位元被設定）時更新`SF`。

你可以查看[參考資料][reference]，了解每個指令會影響哪些旗標。

[reference]: https://www.felixcloutier.com/x86/
~~~~

請注意，在上面的例子中，假設`rsi`大於`0`。
如果它是`0`，那麼`sub rsi, 1`會將`rsi`減少到`-1`，這是一個非常大的無號數。
迴圈最後結束前，還要再進行`18,446,744,073,709,551,615`次疊代。
此外，因為陣列的長度是`0`，任何記憶體存取都會超出範圍。

如果無法保證陣列的長度，有兩種常見的做法。

第一種是將結束條件移到迴圈的開頭，然後在結尾使用無條件跳躍：

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

第二種是在迴圈開始前，先測試陣列長度是否為零：

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

第二種做法通常比第一種更有效率，因為迴圈主體中的分支比較少。
你之後會在某個概念中學到更多相關內容。

~~~~exercism/advanced
在某些情況下，現代 CPU 能夠將兩個不同的指令合併成單一操作。
這種最佳化稱為**macrofusion**。

許多算術指令，例如`sub`和`add`，以及`cmp`和`test`，通常會與緊接在後的條件跳躍融合。
這表示，像是`cmp rax, rdx`這樣緊接著條件跳躍的指令，通常可以被 CPU 視為單一操作。

Macrofusion 取決於 CPU，而且哪些指令會與哪種條件跳躍融合，會有一些差異。

有用的參考資料是 [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]。
[Intel optimization reference manual][intel-opt] 的第 3.4.2.2 節（Optimizing for Macrofusion）也列出了 Intel CPU 可融合的配對。

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
