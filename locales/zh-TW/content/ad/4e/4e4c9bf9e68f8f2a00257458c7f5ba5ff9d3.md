# 簡介

## 列舉

到目前為止，我們處理的大多是數字和字串。
若要模擬真實世界，我們可能會希望變數只能取幾個特定的值。
你可能會想要一個專屬的型別，裡面有幾個名稱各不相同、彼此相異的值。
例如，在滑板工廠裡，板身材質只能從楓木、竹子或塑膠中挑選。

你當然可以用整數來編碼這些值，但這樣就得額外寫程式碼，檢查系統傳來的材質值是不是無效的。
那些[_魔術數字_][magic numbers]的意義很難在原始碼中追蹤，而且很容易搞混。
`enumerations`可以用來鼓勵寫出更有表達力的程式碼，並避免不小心發生的比較錯誤。

## 使用範例

這類列舉的專門術語是`scoped enumeration`。
下面的程式片段示範如何撰寫一個`DeckMaterial` `enumeration`。
請注意`enum class`關鍵字，以及定義結尾的`;`：

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
現在看看滑板店的定價函式，並留意作用域解析運算子（`::`），它指出某個`enumerator`來自哪個`enumeration`：

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## 作用域

想像你有第二個`enumeration`，代表輪子材質：

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
雖然輪子和板身都可以用 _plastic_ 做成，但兩者不會混淆。
它們是不同的_型別_：`DeckMaterial`的 plastic 和`WheelMaterial`的 plastic。
每個`enumeration`的`enumerators`都位在自己的作用域中，也就是自己的`namespace`。
這就是它們被稱為`scoped enumerations`的原因。

## 不具作用域的列舉
你可能會想，既然名稱裡有`scoped`，那應該也有`unscoped`列舉吧，沒錯。
`Unscoped enumerations`越來越不受歡迎，因為它們全都共用同一個全域命名空間。
因為共用的關係，你無法同時有兩個`unscoped enumerations`，讓它們擁有相同的`enumerators`，就像上面例子裡的 _plastic_ 那樣。

此外，`unscoped enumerations`會隱式轉換成整數。
看看下面這個令人意外的例子：

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

如果你想將`scoped enumerations`轉換成整數，可以使用`static_cast<int>`。
