# 簡介

在許多物件導向語言中，常見的做法是透過[子類別化][wiki-subclass]父類別來擴充行為，在繼承父類別方法的同時也加入新的方法。
如此一來，我們就得到了物件階層。

Julia _沒有類別_，所以延伸來說，它_也沒有子類別_。
那麼，我們要如何繼承並擴充既有的行為呢？

我們在先前幾個概念中看過如何建立型別階層，也了解 Julia 如何運用[多重分派][concept-multiple-dispatch]根據引數型別來選擇方法。

Julia 也提供幾種非正式的介面，讓你的自訂型別能夠掛接到已為標準型別定義好的行為上。

用疊代器介面來說明最清楚。

## 疊代器

先前在課程大綱中，我們看過幾種 Julia 處理集合中各個元素的方式。

- [迴圈][concept-loops]，例如`for item in items...`
- [廣播][concept-vector-operations]：`[1, 2, 3] .- 0.5`
- [高階函式][concept-hof]：`map(√, [1, 4, 9])`
- [推導式][concept-comprehensions]：`[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [產生器][concept-comprehensions]：`(x^2 for x in 1:1e6)`，採惰性求值。

顯然，Julia 知道如何逐項走訪標準集合：上述例子中的向量與範圍，還有 Set、Dict 等等。

那麼，我們要如何把這項能力加到自己自訂的集合上呢？特別是當它們能像產生器一樣惰性疊代時。

### 最低需求

要建立一個可供疊代的序列，我們至少需要兩樣東西：

1. 取得_第一個_項目的方法。
2. 從目前狀態取得_下一個_項目的方法。

Julia 透過`Base.iterate()`函式的各種方法，以下列步驟完成這些任務：

1. 首先會自動呼叫`Base.iterate(iter)`。
    - 如果沒有東西可以疊代，就回傳`nothing`。
    - 否則回傳第一個項目與第一個狀態組成的`Tuple`：`(firstitem, firststate)`。
2. 如果前一次疊代有回傳項目，就會自動呼叫`Base.iterate(iter, state)`，並以`firststate`作為它的`state`引數。
    - 如果疊代結束，就回傳`nothing`。
    - 否則回傳下一個項目與下一個狀態組成的`Tuple`：`(nextitem, nextstate)`。
3. 重複步驟 2，直到結束。

這些步驟全都在「幕後」進行，也就是說，方法呼叫與狀態都由疊代協定在內部管理（狀態保持不透明），只有項目會暴露給迴圈這類高階結構。
換句話說，我們永遠只會看到`item`，其他一切都留在黑箱裡。

[多重分派][concept-multiple-dispatch]是其中的核心。
`iter`的型別決定要呼叫哪些方法，而引數的數量則決定要回傳第一個項目還是下一個項目。

標準型別的方法都已經定義好了：`Vector`, `Range`, `Set` 等等（[目前][ref-iterations-collections]共 14 種型別）。

想讓自訂的`MyType`擁有相同的行為，我們首先需要定義：
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

這些抽象的描述聽起來可能很令人困惑，但其實可以相當簡單。
為了說明，想像我們想要一個型別，能產生某個整數`n`的次方，最多到指定的次數上限。

首先，定義一個自訂型別：

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

現在我們可以為這個型別定義`iterate`方法，但第一個項目和第一個狀態是什麼？

要取得第一個項目，有些疊代器需要複雜的設定，但在這個簡單的例子裡，我們可以發現第一個回傳的項目就是底數，所以我們只需要檢查`count`的值是否大於或等於 1。

接著來考慮第一個狀態，它帶有供下一次疊代使用的資訊。
要追蹤哪些資訊才能做到這件事，由你自行決定，而且它可以是任何型別。

在這個例子中，我們可以直接追蹤要將`n`取次方的「索引」，或者採用效能更好的做法，使用`n`最近一次的次方（也就是回傳的項目）以及序列中的下一個「索引」。
這兩個數字可以包成一個`Tuple`，並以`state`的形式回傳。

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

在這個例子中，第一個項目（`p.n`）會回傳給迴圈，而第一個狀態`(p.n, 2)`則會傳給`iterate(P::Powers, state)`方法。
在那裡，我們可以處理狀態來產生下一個項目，做法是把目前的項目乘以底數，藉此把它的次方增加`1`。

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

如果索引值仍在`count`範圍內，就會回傳包含`next`項目與遞增後狀態的`Tuple`。
當`index`值超過`count`時，則改為回傳`nothing`，表示疊代已經結束。

你可能已經注意到，`iterate(p::Powers)`和`iterate(p::Powers, state)`這兩個方法的函式主體相當類似。
事實上，如果夠聰明，這樣的相似性讓我們可以用更精簡的方式實作：只保留兩個引數的版本，並為狀態提供預設引數：`Base.iterate(p::Powers, state=(1, 1))`
這樣一來，我們就不需要另一個只有單一引數的`iterate(p::Powers)`。
實際應用上，只要情況允許，這是很常見的做法。

到目前為止，我們已經有了一些實用的功能：對於 3 的前 4 個次方，我們可以逐一迴圈走訪結果、檢查某個數字是否在結果中，以及套用`sum()`這類彙總函式。

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 其他方法

儘管有了好的開始，但並不是所有功能都能運作。

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

果然，`length(Powers(3, 4))`給出完全相同的錯誤訊息。

這很容易修正，因為長度是型別建構子的一部分：在這裡是 4。
我們只需要為這個型別定義`Base.length()`，接著就能對這個序列使用推導式與`collect()`。

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

為了效率，最好也定義`Base.eltype()`：也就是結果的元素型別。
這能讓`collect()`這類函式預先為輸出的`Vector{Int}`配置空間，而不必反覆對`Vector{Any}`執行`push!()`。

注意這個語法，你可能沒見過：這個方法是定義在_型別_上，而不是型別的_實例_上。

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

疊代器並不_一定_要有有限長度。
使用「無限」序列的場合比較有限，但只要能用某種方式從迴圈中`break`出來，逐一迴圈走訪它們仍可能很實用。
舉例來說，我們可以定義一個`Powers`的變體，只產生小於某個上限的值（也許是`typemax(Int)`，以避免整數溢位）。

## 總結

介面之所以相當難以解釋，是因為 Julia 的做法和大多數其他語言截然不同。
尤其，介面的名稱在實作中可能根本不會被提到，這和[子類別化][wiki-subclass]或[混入][wiki-mixins]非常不同。

不過，實際用起來卻出奇地簡單：

1. 定義一個合適的型別。
2. 找出需要哪些方法。
3. 為你的自訂型別實作這些方法；通常只有少數幾個方法，而且相當短、相當簡單。
4. 剩下的就交給[多重分派][concept-multiple-dispatch]自動處理。
