# 說明

這道練習的主題是情人節，你和你的伴侶打算一起做點開心的事。你的伴侶有很多想法，現在請你為這些想法評分，好找出你們要一起從事的活動。

你的伴侶提出了以下想法：

- 玩桌遊
- 放鬆一下
- 看電影
- 上餐廳
- 散步

你有 6 個任務，幫助你選出情人節活動。

## 1. 定義同意程度

對於伴侶提出的每個想法，你的回應會是以下 3 種選項之一：同意、不同意或也許。

定義 `Approval` 自訂型別，用以下 3 種情況來表示這些選項：`Yes`、`No` 和 `Maybe`。

## 2. 定義料理類型

你的伴侶選了 2 間可能的餐廳：一間是韓式料理，另一間是土耳其料理。

定義 `Cuisine` 自訂型別，用以下 2 種情況來表示這些料理類型：`Korean` 和 `Turkish`。

## 3. 定義電影類型

電影多到數不清，所以為了縮小範圍，你的伴侶也列出了電影的類型。

定義 `Genre` 自訂型別，用以下情況來表示這些類型：`Crime`、`Horror`、`Romance` 和 `Thriller`。

## 4. 定義活動

如前所述，你的伴侶想出了 5 種不同的活動：玩桌遊、放鬆一下、看電影、上餐廳和散步。

定義 `Activity` 自訂型別來表示這些活動類型：

- `BoardGame`：沒有附帶資料。
- `Chill`：沒有附帶資料。
- `Movie`：帶有 `Genre` 作為附帶資料。
- `Restaurant`：帶有 `Cuisine` 作為附帶資料。
- `Walk`：帶有一個 `Int` 作為附帶資料，代表要步行的公里數。

## 5. 為活動評分

最後，你終於可以為伴侶的想法評分了。以下是你對這些想法的感覺：

- 玩桌遊：不同意。
- 放鬆一下：不同意。
- 看電影：浪漫電影就同意，其他電影就不同意。
- 上餐廳：韓式料理就同意，土耳其料理就也許。
- 散步：超過 11 公里就同意；超過 6 公里就也許；其他情況就不同意。

實作一個名為 `rate_activity` 的函式，它接收一個 `Activity` 值，並根據上述感受回傳 `Approval`：

```gleam
rate_activity(Restaurant(Turkish))
// -> Maybe
```
