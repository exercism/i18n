# 簡介

單一指令看起來可能像是一個不可分割的動作，實際上卻完全不是這麼回事。以把記憶體中的某個值加上五為例：

```x86asm
add qword [rel counter], 5
```

在底層，處理器沒辦法直接把值加到記憶體上。它會把這道指令拆成三個更小的步驟，稱為**微操作**：

1. 從記憶體**讀取**目前的值；
2. 在暫存器中**修改**這個值，把它加上五；
3. 把結果**寫回去**。

```x86asm
mov rax, qword [rel counter] ; 1. load the current value
add rax, 5                   ; 2. add five
mov qword [rel counter], rax ; 3. store the result back
```

這是一種常見的模式，稱為**讀取-修改-寫入（RMW）**。

請注意，讀取（或載入）與寫入（或儲存）是兩個獨立的事件，因此它們之間存在一段時間的空窗。我們平常不會注意到這件事，因為在單一核心上，每道指令都保證會在下一道指令開始前完整產生效果。因此那段空窗是看不見的，`add`的行為就像一個不可分割的單位。

然而，現代 CPU 很少是單核心的，而且應用程式經常同時在許多核心上執行，彼此之間沒有任何順序關係。當好幾個核心在同一個瞬間執行時，另一個核心可能就在那段空窗內、在這個核心載入之後、寫入之前，讀取或寫入`counter`。兩個執行緒各自載入同一個舊值，各自加上五，再各自寫回自己的結果。明明發生了兩次加法，值卻只增加了五。有一次更新就這樣悄悄消失了。

這叫做**資料競爭**，是多執行緒程式碼中很常見的問題。

不是每個值都會這樣曝露在風險中。每個執行緒都有自己的暫存器與自己的堆疊，所以放在暫存器裡的值，或執行緒堆疊上的區域變數，都專屬於該執行緒，不可能發生競爭。只有像上面`counter`那樣由執行緒共用的記憶體才需要保護。

x86-64 提供了一組指令來解決這個問題：讓指令變得不可分割。它不僅對處理它的那個核心而言是一個單位，對其他每個核心也是如此。這種能保持完整、沒有其他核心能從中切開的操作，就稱為**原子**操作。

~~~~exercism/note
我們常把在許多核心上執行的應用程式稱為多執行緒。然而，**執行緒**和核心並不是同一回事。兩個執行緒可能同時在同一顆核心上執行、彼此交錯，也可能在不同的核心上平行執行。

交錯執行的執行緒，如果一個讀取-修改-寫入被拆成多道指令，就已經可能在它中間發生競爭，因為作業系統可以在任意兩道指令之間切換執行緒。然而，_單一_一道指令內部的空窗，只有真正平行執行的程式碼才會曝露出來。由於作業系統只會在指令之間切換執行緒，絕不會在指令內部切換，所以單一指令在單一核心上本質上是安全的。

下面這些指令所提供的，正是在_多個_核心之間的真正原子性。
~~~~

## 原子交換

`xchg`指令會交換兩個運算元。目的運算元會變成來源運算元原本的值，而來源運算元則會變成目的運算元原本的值。從概念上來說，可以把它想成兩道`mov`指令同時發生。

一如往常，它可以搭配兩個暫存器運算元，或是一個記憶體運算元配一個暫存器運算元：

```x86asm
mov  eax, 1
xchg dword [rdi], eax ; [rdi] = 1, eax = the old value of [rdi]
mov ecx, 2
mov edx, 3
xchg edx, ecx         ; edx = 2, ecx = 3
```

搭配記憶體運算元使用時，`xchg`_永遠_是原子性的。

~~~~exercism/caution
當其中一個運算元是記憶體位置時，`xchg`會自動具有原子性。這也代表在那種情況下，這個操作會慢得多。

如果你不需要原子性，改用一般的`mov`指令，透過一個備用的暫存器來完成交換就好。
~~~~

## `lock`前綴

在 x86-64 中，讓一道指令具有原子性最常見的方法，就是加上`lock`前綴。它會把讀取、修改與寫入融為一個不可分割的步驟。這表示在整個過程中，該核心會獨佔這塊記憶體，所以其他核心無法在中途讀取或寫入那個位置。

```x86asm
lock add qword [rel counter], 5 ; the read, the modify, and the write are one step
```

`lock`只在目的運算元是記憶體時有效，而且只適用於會對該記憶體進行讀取-修改-寫入的指令：

1. 算術運算，例如`add`、`sub`、`inc`、`dec`、`neg`；
2. 位元運算，例如`and`、`or`、`xor`、`not`；
3. 位元操作`bts`、`btr`、`btc`；
4. 其他一些專門的指令，例如下面會介紹的`xadd`與`cmpxchg`。

~~~~exercism/caution
獨佔一個位置、把其他每個核心都擋在外面，並不是沒有代價的。加了`lock`前綴的操作，會比它的一般形式明顯慢上許多；當好幾個核心競爭同一個位置時，還會更慢。

這個前綴應該保留給預期會被多個執行緒修改的記憶體。如果記憶體不是共用的，或只會被讀取，就避免使用它。
~~~~

## 交換並相加

單純的`lock add`會更新記憶體，卻把舊值丟掉。很多時候，我們要的正是那個舊值，例如要發給每個執行緒一個不同的號碼牌。

`xadd`指令（`x`代表 exchange）會在相加的同時回傳先前的值。它把相加的結果寫入目的運算元，並把目的運算元原本的值留在來源暫存器中。

```x86asm
mov  rax, 1
lock xadd qword [rdi], rax ; [rdi] = [rdi] + rax = [rdi] + 1
                           ; rax = the old value of [rdi]
```

加上`lock`前綴之後，這就是一個具原子性的**擷取並相加**。當許多執行緒對同一個計數器執行它時，每次呼叫都會回傳不同的舊值。

和`lock add`一樣，計數器最後會等於呼叫的確切次數。不過，和`lock add`不同的是，每一個中間值也都被回傳了，各自交給一位呼叫者。

## 比較並交換

`xadd`會相加，`xchg`會覆寫，但兩者都無法讓新值取決於目前的值，並且只在底下的內容沒有改變時才套用它。這種有條件的更新，正是`cmpxchg`（比較並交換）所提供的能力，也是這幾個基本操作中最通用的一個。

`cmpxchg dest, src`會用`rax`作為隱含的累加器，並拿它跟`dest`比較：

- 如果`dest == rax`，則`dest = src`，且`ZF = 1`。
- 如果`dest != rax`，則`rax = dest`，且`ZF = 0`。

請注意，`dest`只有在等於事先載入`rax`的預期值時才會更新。這個相等條件確保`dest`仍然持有新值所根據的那個值，因此絕不會套用基於過期讀取所算出的更新。這讓`cmpxchg`成為原子更新的基礎，也就是所謂的**比較並交換（CAS）**：

```x86asm
    mov rax, qword [rdi]          ; rax = the value we expect to find
.retry:
    lea rcx, [rax + 10]           ; rcx = the new value we want to install
    lock cmpxchg qword [rdi], rcx ; if [rdi] still equals rax, store rcx and set ZF
                                  ; otherwise reload rax with the current value, clear ZF
    jnz  .retry                   ; ZF is cleared, so another thread won the race. Recompute and retry
```

這個**重試迴圈**是無鎖更新的核心。讀取與比較並交換之間的空窗，正是另一個執行緒可能介入的時機，而`cmpxchg`會拒絕寫入根據過期讀取所算出的值，藉此攔住這種情況。

## 記憶體排序

到目前為止，每個操作都只碰觸單一位置。當執行緒透過多個位置互相協調時，就會出現一個新問題：某個執行緒的寫入，會以什麼順序被另一個執行緒看見。回答這個問題的規則，就是處理器的**記憶體排序**。

無分支程式碼的概念介紹過這樣的想法：現代核心不會一次只慢慢地處理一道指令。它會同時讓許多指令在途，並在能力所及之處提前執行。這表示某個寫入被其他核心看見的時間，可能比程式所暗示的還要晚，而它後面的指令卻早已先行。

x86-64 在一般的載入與儲存之間維持著**強記憶體排序**，因此在每個核心上：

1. 載入永遠不會被重排到較晚的載入之後；
2. 儲存永遠不會被重排到較晚的儲存之後；
3. 載入永遠不會被重排到較晚的儲存之後。

唯一可能的重排，是一個儲存看起來在對_不同_位址的較晚載入之後才完成。

加了`lock`前綴的指令，或是搭配記憶體運算元的`xchg`，都是完整的屏障：沒有任何東西看起來能跨越它往任何方向移動。這就是為什麼在多數情況下，它們就足以確保完整的排序。

## 自旋與`pause`

能在設定旗標的同時回傳其先前狀態的指令，稱為**測試並設定**。它們可以作為**自旋鎖**的基礎，確保某個核心能獨佔存取程式碼的某一部分。

以下是整體的演算法，使用`xchg`指令搭配一個二元旗標：

1. 旗標一開始是`0`。
2. 要取得鎖，某個核心會把旗標裡的值跟`1`交換。
3. 如果回傳的值是`1`，表示鎖正被另一個核心_持有_。目前這個核心就會等待，然後再次嘗試取得鎖。
4. 如果回傳的值是`0`，表示鎖是空閒的。`xchg`這時已經把它設成`1`，其他核心會等到這個核心釋放鎖為止。
5. 一旦目前這個核心完成工作，把旗標更新為`0`就能釋放鎖。

```x86asm
acquire:
    mov  eax, 1
    xchg dword [rdi], eax ; try to take the lock; eax = its old value
    test eax, eax
    jnz  .held            ; old value was 1: someone else holds it
    ret                   ; old value was 0: the lock is ours
.held:
    pause                 ; wait before trying again
    jmp  acquire
```

等待迴圈中的`pause`指令並不會改變程式碼算出的結果。它是在向處理器暗示這是一段自旋等待。CPU 接著就能降低等待中執行緒的耗電，並讓出資源給共用同一顆核心的兄弟執行緒。沒有`pause`的自旋迴圈依然是正確的，只是浪費而已。

一旦執行緒完成工作，它可以用`mov`做一次單純的`0`儲存來釋放鎖。需要的就只是這麼一個`mov`，因為在 x86-64 上，載入與儲存永遠不會被重排到較晚的儲存之後。一個永遠不會超越它前面存取的儲存，被稱為具有**釋放排序**，而在 x86 上，每個單純的儲存都帶有這種性質。

~~~~exercism/note
任何能以原子方式測試並設定某個記憶體位置的指令，都可以用於自旋鎖。舉例來說，可以用`lock bts`取代`xchg`，在設定某個特定位元的同時檢查它是否已經被設定。

請注意，像`bts`所修改的`CF`這類旗標，都是`rflags`這個暫存器的一部分。這表示它們專屬於各個執行緒。
~~~~
