# 關於

## JSON

[JSON][json]（JavaScript Object Notation）是一種人類可讀的資料與檔案格式，常用來交換資料，尤其是網頁應用程式。
因此，它在 Elm 語言中佔有特殊的地位，一點也不令人意外。

Elm 提供了核心模組`Json.Decode`和`Json.Encode`來解析和寫入 JSON 資料。
JSON 解碼器讓你_宣告_預期的是哪種資料型態，以及資料應該對應到哪種資料結構。

如果你來自動態型別語言，解碼器乍看之下常顯得笨重或太過僵硬。
雖然它們確實很囉嗦（至少在 Elm 裡是如此），卻是能明確描述程式對傳入資料有何期待的好工具，表達能力也不比動態型別差。

我們從這些模組匯入一些別名和型別：

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

使用`Decode.decodeString : Decoder a -> String -> Result Error a`搭配一個解碼器和一個 JSON 字串，如果字串符合解碼器的規格就會成功，否則就會失敗。
定義解碼器時，沒有辦法檢視原始的 JSON 資料，這對來自命令式語言的人來說可能會覺得不太尋常。

## 基本的資料型態解碼器

JSON 只有少數幾種核心資料型態：

- 字串：以雙引號編碼，例如`"hello world"`
- 布林值：`true`或`false`
- 數字：例如`34`或`0.12`
- Null：資料的缺席，也就是`null`

以上每一種都對應到一個`Decode`函式：

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

注意，`Decode.null`讓你決定要在程式中如何建模一個`null`，做法是要求你傳入一個任意的值作為引數（也許是`()`、`Nothing`，或任何適合你程式的東西）。

## 組合解碼器

JSON 也定義了兩種資料結構來收集核心資料型態：

- 陣列：其他資料型態的集合`[0, null, "none", []]`
- 物件：鍵值對的集合`{"id": 1, "is_admin": false, "more_info": {}}`

`Decode`也提供了函式來解碼這些資料結構：

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

這些函式`Decode.list : Decoder a -> Decoder (List a)`和`Decode.dict : Decoder a -> Decoder (Dict String a)`都預期接收一個解碼器作為引數，由它負責解碼該資料結構中的每一個元素。
如果傳入的解碼器無法解碼陣列或物件中的任何一個元素，整個解碼器就會失敗，這是很常見的模式。

把簡單的解碼器組合成更複雜的解碼器，就是這個技巧的核心概念。
接下來我們會透過一個範例，介紹幾個能用來打造任意複雜的真實世界資料解碼器的函式。

## GeoJSON

為了練習組合基本解碼器來解析複雜的 JSON 資料，我們來打造能解析（一部分）GeoJSON 資料的解碼器吧。
[GeoJSON][geojson]是一種以 JSON 為基礎的專門資料格式，用來表示地理特徵，例如位置、路徑或區域，這些特徵以 2D 或 3D 地理座標以及其他屬性來描述。

### 幾何物件

GeoJSON 的幾何物件是一種物件，其中包含一個`type`欄位，值為字串（有 7 種可能的型別值），以及一個`coordinates`欄位，存放地理座標（收集成什麼樣的結構取決於型別）。
例如，

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

或

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

幾何物件在 Elm 中可以用以下型別來表示

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

要探查某個欄位的值，我們可以使用`Decode.field : String -> Decoder a -> Decoder a`，它會解碼物件中某個特定鍵的值。

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

要轉換解碼器成功解析出來的值，我們可以使用`Decode.map : (a -> value) -> Decoder a -> Decoder value`，或它的任何兄弟函式，從`Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value`到`Decode.map8`。

在這個例子中，我們想根據`type`欄位中的值來決定要用哪個座標解碼器，這正是`Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b`以及它的好夥伴`Decode.succeed : a -> Decoder a`和`Decode.fail : String -> Decoder a`的拿手好戲。

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

附帶一提，我們也可以用`Decode.andThen`來驗證座標（檢查座標是否成對或成三出現，以及檢查座標值在地理上是否合理）。

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### 特徵物件

GeoJSON 的特徵物件代表某個在空間上有界的事物：它有一個`type`欄位，值為`"Feature"`；一個`geometry`欄位，值為幾何物件或`null`；一個`properties`欄位，值為任意的 JSON 物件或`null`；以及一個選用的`id`欄位，值為 JSON 字串或數字。

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

或

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

我們先來處理`id`欄位。
如果它存在，就必須能容納字串或數字，所以我們可以為這個值自訂一個型別，或是永遠把它存成字串。

要在兩個可能的解碼器之間做選擇，我們可以使用`Decode.oneOf : List (Decoder a) -> Decoder a`。

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

要表達這個欄位是選用的，我們也可以用同樣的技巧

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

但我們也可以改用`Decode.maybe : Decoder a -> Decoder (Maybe a)`

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

注意，`decodeMaybeFeatureId`（或任何用`Decode.maybe`包起來的解碼器）永遠都會成功，因為它總是可以退回到`Ok Nothing`，不過使用它的解碼器仍然有可能失敗

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

接下來，我們把焦點放在`geometry`欄位上，它的值可以是幾何物件，也可以是`null`。
我們可以再次使用`Decode.oneOf`，但有個更好的選擇：`Decode.nullable : Decoder a -> Decoder (Maybe a)`。

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe`和`Decode.nullable`的簽章相同，但行為不同，因為`Decode.nullable`的`OK Nothing`結果只會來自特定的 JSON 值`null`。

最後，`properties`欄位可以包含任意的 JSON 物件或`null`，這就交給`Decode.value : Decoder Value`了。

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

注意，`Value`是不透明型別，也就是說你無法輕易探查它的內容。
要使用它，你可以為它寫一個解碼器，再用`Decode.decodeValue : Decoder a -> Value -> Result Error a`執行；或者透過 port 直接把它送給 JavaScript。

我們準備好解析特徵物件了：

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## JSON 編碼器

編碼器讓你用`Encode.encode : Int -> Value -> String`函式，把 Elm 的值寫成合法的 JSON。
第一個引數指定最終結果的縮排量，第二個引數則是要寫入的 JSON 值。

`Value`可以從`Decode.value`取得，也可以由其中一個編碼器產生：

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

也可以搭配`Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

我們來為前面定義的 GeoJSON 解碼器寫對應的編碼器吧

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

一般來說，檢查解碼器與編碼器是否搭配得好的一個好方法，就是確認`elmValue |> encoder |> decoder == elmValue`。

## 還有什麼？

我們沒有涵蓋`Json`模組中的每一個函式。
沒有提到的東西包括：把陣列轉成`Array`、或把物件轉成`List (String, a)`的解碼器；處理含有一個以上元素的陣列的解碼器；解碼巢狀 JSON 物件中特定欄位或陣列中特定元素的解碼器；如何解碼遞迴結構；以及`Error`的各種變體和如何顯示它們。

其他常用的套件還包括[`Json.Decode.Pipeline`][pipeline]，它為複雜的 JSON 結構帶來方便的流程，以及[`Json.Decode.Extra`][extra]，它提供了更多解碼器、編碼器和輔助工具。
