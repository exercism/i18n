# 簡介

**浮點數**是一種可以帶有小數部分的數字，例如 `-1.23` 或 `3.1415`。

為了將這樣的數字表示成一連串的位元組，x86-64 採用 **IEEE-754** 標準。
這個標準中最常見的兩種格式是單精度浮點數與雙精度浮點數。
x86-64 兩者都支援。

單精度浮點數的寬度是 32 位元，而雙精度浮點數則是 64 位元。

## XMM 暫存器

在 x86-64 中，有 16 個專門用來進行浮點運算的暫存器，名稱從`xmm0`到`xmm15`。

這些暫存器至少有 128 位元寬，但近期的處理器會將其增加到 256 位元或 512 位元。
不過實際上，大多數浮點數只會用到最低的 32 位元或 64 位元，取決於所需的精度。

## 數字之間的轉換

有一系列指令可以在各種數字格式之間進行轉換：`cvtxx2yy`。

`xx`和`yy`都不是字面值，而是佔位符：

- `xx`是來源運算元型別的佔位符。
- `yy`是目的運算元型別的佔位符。

這些佔位符有許多種形式，其中包括：

| 佔位符 | 意義               |
| ----------- | --------------------- |
| `si`        | 有號整數        |
| `ss`        | 32 位元浮點數 |
| `sd`        | 64 位元浮點數 |

例如：

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

請注意，可以將 32 位元整數轉換成 64 位元浮點數，或是將 64 位元整數轉換成 32 位元浮點數。
同樣地，也可以將 32 位元浮點數轉換成 64 位元整數，或是將 64 位元浮點數轉換成 32 位元整數。
換句話說，`cvtxx2yy`中兩個運算元的大小_不必相同_：

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

當浮點數無法精確表示為整數時，`cvtxx2si`會根據一個名為`mxcsr`的特殊暫存器中的捨入控制，對數字進行捨入。
這可能是捨入到最接近值、向下捨入、向上捨入，或截斷。
進入函式時，並不保證有任何預設值。

請注意，精確的結果不會被捨入，因此也不受捨入控制影響。
例如，`42.0`_永遠_會被轉換成`42`。

另有一系列格式為`cvttxx2si`的類似指令（多了一個`t`），它們一律會截斷結果。

## 捨入

`roundxx`系列指令會將來源運算元中的浮點數轉換成捨入後的浮點數，並儲存在目的運算元中。

這裡的`xx`一如往常是運算元型別的佔位符：`ss`代表單精度，`sd`代表雙精度浮點數。

這些指令會以一個常數作為第三個運算元。
這個數字代表捨入模式：

| 數字 | 模式         |
| :----- | :----------- |
| 0      | 最接近      |
| 1      | 向下取整（向下） |
| 2      | 向上取整（向上）    |
| 3      | 截斷     |

例如：

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

由於這些指令會產生精確的結果，因此可以用來為`cvtxx2si`做準備。

## 算術指令

許多浮點數運算所用的指令，名稱和對應的整數指令相似，只是在結尾加上必要的佔位符（`ss`或`sd`）。
這些指令都是雙運算元，語意一如往常，即使是執行乘法或除法的指令也不例外：

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## 搬移

要在 XMM 暫存器之間搬移的指令是`movss`或`movsd`：

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

**無法**直接將立即值（一個常數有號整數）搬移到 xmm 暫存器。
這個數字必須先搬移到通用暫存器中，再使用`cvtsi2xx`進行轉換：

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## 比較

有兩組指令可以用來比較兩個浮點數。
它們的形式為`comixx`與`ucomixx`，其中`xx`是`ss`或`sd`。
兩者都會一如往常地在`rflags`中設定旗標，語意和`cmp`相同。

兩者的差別在於，如果兩個浮點數中有一個是`NaN`值，`ucomixx`會設定`parity flag (PF)`；而`comixx`在這種情況下會引發例外。

浮點數值之間的比較是_無號_的：

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## 呼叫慣例

在 System V ABI 中，前八個浮點引數會依序從`xmm0`到`xmm7`傳入函式。
浮點數值會透過`xmm0`從函式回傳，必要時則使用`xmm1`。

所有`xmm`暫存器都可以自由使用，沒有任何一個是保留給呼叫者的。

## 記憶體

浮點數值可以依照與相同大小的整數相同的語意定義在記憶體中。
NASM（The Netwide Assembler，也就是本軌道所使用的組譯器）也允許以科學記號宣告浮點數值。

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```
