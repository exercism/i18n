# 關於

我們在前面的概念中看過，Julia 的型別會構成一種階層，最頂端是`Any`。

像`Number`這樣的抽象型別有子型別，但本身無法被實例化。
把變數的型別設為抽象型別，會_限制_該變數的值必須是該抽象型別的子型別。
例如：

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

這給了我們一種彈性，可以限制哪些輸入是有效的。

不過，假設我們希望同一個變數能同時接受整數和字串的值呢？
這兩個型別並不在階層的同一條分支上。

我們可以把型別設成[`Any`][any]，或讓它預設就是這個型別，但這麼一來就完全無法控制允許的型別了。

更好的做法是使用[`Union{ }`][union]語法，在大括號內列出兩個以上的型別。

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

另一個例子則是在函式簽章中使用同樣的聯合型別：

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

這裡我們替這個型別取了名字，這樣寫起來比較方便，但並非必要。
函式`g(z::Union{Integer, String}) = z^3`的行為完全相同。

關於函式簽章，之後在多重分派概念中還會有更多討論。

## 包含 nothing 的聯合型別

其他一些語言有那種可能含有值、也可能不含值的型別，名稱像是`Option`、`Nullable`或`Maybe`。

Julia 沒有針對這種情況的特定語法，但聯合型別是這個想法的推廣。

我們在[`Nothingness`][nothingness]概念中看過，Julia 有各種方式來表示「非值」，包括[`nothing`][nothing]和[`missing`][missing]。
這兩者都可以放進聯合型別裡。

舉例來說，在定義某種[鏈結串列][linked]時，我們需要一種方式，在沒有後續節點時結束這個串列。
`Nothing`是只有單一值`nothing`的型別，而這樣的 Node 定義讓我們能標示出這條鏈的結尾：

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

同樣地，`missing`可以當作缺少值的佔位符，特別是在向量這類集合中。
下面這個例子非常牽強，但缺少值在真實世界的資料集裡很常見。

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
