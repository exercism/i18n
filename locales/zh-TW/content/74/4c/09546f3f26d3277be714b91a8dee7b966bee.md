# 簡介

## 部分應用

Elm 裡所有的函式都是[柯里化][currying]的，這表示如果你呼叫函式時沒有傳入全部的引數，它就會回傳一個新的函式。

這樣做的結果稱為[部分應用][partial-application]（你並沒有把全部引數都傳給函式，而是只套用了其中一部分）。

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

部分應用一律會依序套用引數。

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## 管線運算子（`|>`）

寫成`x |> f`就完全等同於`f x`。具體的例子是，`"5" |> String.toInt`等同於`String.toInt "5"`。

乍聽之下這好像沒什麼用，但它之所以叫做[管線運算子][pipe-operator]，是因為它能讓你寫出「管線式」的程式碼。

舉例來說，假設我們有一個 sanitize 函式，可以把使用者的輸入轉換成整數：

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

我們可以把它改寫成這樣：

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

這樣可以避免使用括號，並且依照函式套用的順序來呈現（先`String.trim`，再`String.toInt`），有助於提升可讀性。

另外還有[反向管線運算子`(<|)`][reverse-pipe-operator]。
寫成`f <| x`就完全等同於`f x`。
乍看之下這好像也不太有用，而且使用頻率絕對比不上管線運算子，但在某些情況下它能幫你省去括號。

## 函式合成／無點風格

[`(>>)`][forward-composition]運算子的型別是`(a -> b) -> (b -> c) -> (a -> c)`，它會把兩個型別相容的函式`a -> b `和`b -> c`合成為一個型別是`a -> c`的函式。
它的做法是取出第一個函式的輸出（型別為`b`），並把它當作第二個函式的第一個引數（第二個函式的型別也必須是`b`）。
建立出來的函式會接收與第一個函式相同的輸入（型別為`a`），並回傳第二個函式所回傳的`c`。

具體的例子是`String.trim >> String.toInt`。
`String.trim`只接受一個字串作為它唯一的參數，所以建立出來的函式也接受同樣的輸入。
`String.toInt`回傳`Maybe Int`，所以建立出來的函式也回傳同樣的東西。
`String.trim`回傳一個`String`，而`String.toInt`接受它作為參數，所以這個例子可以編譯。

現在我們可以把`sanitize`函式改寫成下面這樣：

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

注意，我們已經不再使用你在原始範例中看到的`input`參數，儘管功能完全相同。
這種建立函式、完全不提及自身參數的風格稱為「無點風格」。
這種風格的優點是程式碼更簡潔，缺點是比較難理解，對初學者來說尤其如此。

值得一提的是，Elm 裡所有函式都是柯里化的，所以`String.length >> max`可以編譯。

- [`(>>)`][forward-composition]運算子的型別是`(a -> b) -> (b -> c) -> (a -> c)`。
- `String.length`的型別是`String -> Int`，也就是`(a -> b)`這個部分，所以`a`是`String`，而`b`是`Int`。
- `max`的型別是`Int -> Int -> Int`，也就是`b -> c`這個部分。
- `b`是`Int`，所以`max`會被部分套用，因此`c`是這個部分套用的結果（`Int -> Int`）。
- 所以`String.length >> max`的型別是`String -> (Int -> Int)`。
- 所以`((String.length >> max) "123") 2`會回傳`3`，因為`"123"`的長度是 3，比來自`Int`引數的 2 還大。

## 函式設計

為了讓你在 Elm 中能輕鬆寫出優雅的程式碼，你應該把主要的資料結構放在函式的最後一個參數。
標準函式庫裡所有常見的函式都是這麼做的，例如`List.map`（型別簽章如下）。

```elm
map : (a -> b) -> List a -> List b
```

這裡可以看到，`map`函式的最後一個參數是`List a`，而它回傳`List b`，所以主要的資料結構（`List`）就是最後一個參數。

這樣就能寫出優雅的管線式程式碼，例如下面這樣。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

它也能讓你方便地改用函式合成與無點風格，作為管線寫法的替代方案。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

函式合成還能讓你把這個例子縮減成只呼叫一次`List.map`。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
