# 關於

解析是把文字轉換成有意義資料的過程。`String`套件裡的函式在這方面有所限制，而正規表達式又不容易使用，所以在 Elm 中，慣用的解析方式是使用`elm/parser`套件。

我們來看一個範例，寫一個解析器來處理程式語言 [LOLCODE][lolcode]（的一部分）。
看看下面這個帶有註解的程式：

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

首先，我們寫一個 Elm 型別來表示各種可能的指令：

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

我們的 LOLCODE 程式就可以建模成`List Command`。
先從`HAI 1`這行的解析器開始：

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP`是用_解析器管線_建立的。
`(|.)`運算子的意思是「解析字串但捨棄結果」，而`(|=)`的意思則是「解析字串並保留結果」。
在這個範例中，`Parser.keyword "HAI"`會消耗掉一個「HAI」，但那項結果會被忽略。
`Parser.spaces`會消耗任意數量的 ' '、'\n' 和 '\r' 字元，而這同樣會被忽略。
`Parser.int`會解析出一個整數，這個整數的值（例如 1）會被傳給最上層的`Parser.succeed Version`，解析器最後會成功回傳值`Version 1`。

管線中只要有任何一個解析器失敗，就會回傳`Parser.DeadEnd`，整個解析器也會跟著失敗。
解析器可以用`Parser.run`來執行：

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

接著來處理「CAN HAS STDIO?」這一行：

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP`同樣是一個解析器管線，但這次結尾用的是`Parser.symbol`，適合解析像「?」這樣的符號。
我們想保留的值（要匯入的套件名稱）則由以下解析：

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

由於我們不知道套件名稱會是什麼，所以不能用`Parser.keyword`，改用`Parser.chompWhile`，只要字元符合某個條件（這裡是英數字元），它就會逐字消耗。
這些被消耗掉的字元接著由`Parser.getChompedString`收集起來，它會回傳一個`Parser String`。
在這裡，我們想把套件名稱正規化，所以用`Parser.map`修改解析器內含的字串，把它變成小寫。

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

接下來，`VISIBLE "HAI WORLD!"`由以下解析：

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

現在我們已經有了每個指令的解析器。
當然，在一般的程式裡，這些指令的順序無法預測，所以我們建立一個通用的指令解析器

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf`會依照給定的順序逐一嘗試解析器。
如果某個解析器失敗，就換下一個試；但如果成功，就會直接回傳它的結果，不再嘗試其餘的解析器。
如果所有解析器都失敗，`Parser.oneOf`就會失敗。

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

注意每次失敗的嘗試都會產生一個`Parser.DeadEnd`，並由`Parser.oneOf`收集起來。

要解析一個完整的程式，我們需要用以下方式依序解析多個指令：

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence`是非常有彈性的解析器，提供了許多選項。
`start`、`separator`和`end`接收用來分隔序列中各項目的字串，如果要解析 Elm 的陣列，我們會用「[」、「,」和「]」。
`spaces`則提供彈性，它接收一個解析器來處理項目與分隔符之間可能的空白；解析 Elm 的陣列時我們會用`Parser.spaces`，但在這個例子裡我們不接受任何空白，所以改用`Parser.succeed ()`，它會立刻成功，實際上不消耗任何東西。
`item`接收項目的解析器，最後，`trailing`讓我們決定結尾的分隔符是`Parser.Forbidden`、`Parser.Mandatory`還是`Parser.Optional`。

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

解析器成功之後就會停止消耗字串

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

所以如果我們需要確保字串裡所有內容都被解析過，可以使用`Parser.end`

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

最後，有時我們需要根據解析出來的內容，決定讓解析器失敗。
舉例來說，如果我們需要一個解析器，讓以連續兩個「HAI」指令開頭的程式失敗，可以這樣寫：

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen`可以檢視解析器的內容，並依據它的值回傳一個新的解析器。
在這裡，其中一種情況我們用`Parser.problem`讓解析器帶著自訂訊息失敗，另一種情況則回傳原本的值。

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
