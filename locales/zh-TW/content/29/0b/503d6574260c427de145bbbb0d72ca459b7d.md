# 簡介

還記得高中時，你第一次學代數的情景嗎？

通常，老師會給我們一組聯立方程式，然後要我們解出 `x` 和 `y`。

```
4x - 3y = -2
2x + 7y = 16
```

兩個方程式、兩個未知數：稍微做點代入，很快就能看出 `x = 1, y = 2`。

再看看上一個例子的左邊。
它看起來像是一個矩陣`[4 -3; 2 7]`乘上一個未知向量`[x, y]`，得到向量`[-2, 16]`。

以線性代數的記法：**A** **x** = **b**，遵循一般慣例：矩陣用大寫字母，向量用小寫字母。

## **A x = 0**與零空間

一個重要的特例是，當所有方程式的等號右邊都是零的時候。

```
4x - 3y = 0
2x + 7y = 0
```

在上面的例子中，唯一的解是 `x = y = 0`，這通常沒什麼意思。

**A x = 0**要有非平凡解，只有在**A**的[行列式][wiki-determinant]為零時才可能。

```julia-repl
julia> using LinearAlgebra

julia> A = [4 -3; 2 7]
2×2 Matrix{Int64}:
 4  -3
 2   7

julia> det(A)  # not zero!
34.0
```

換個角度，看看這組方程式：

```
4x - 3y = 0
8x + 6y = 0
```

第二個方程式只是第一個方程式的兩倍，並沒有帶來任何新資訊。
只要符合 `x = 0.75y` 的任何數值都會是解。

這些 `(x, y)` 數值落在二維空間中的一條直線上。
解有無窮多個，它們構成了這個矩陣的[零空間][wiki-nullspace]。

在這種情況下，矩陣中的各列並不是[線性獨立][indep]，而且矩陣的[秩][rank]小於列數或行數。

```julia-repl
julia> A = [4 -3; 8 -6]
2×2 Matrix{Int64}:
 4  -3
 8  -6

julia> det(A)
0.0

julia> size(A)  # total number of rows and columns
(2, 2)

julia> rank(A)  # number of linearly-independent rows (or columns)
1

julia> nullspace(A)
2×1 Matrix{Float64}:
 -0.6
 -0.8

julia> nullspace(A) |> norm  # Julia returns unit vectors when possible
1.0
```

[`nullspace()`][ref-nullspace] 函式會回傳單一個點，並選擇將它[正規化][wiki-unit-vec]成單位向量，但這個向量的任何純量倍數也都落在零空間中。

## 解**A x = b**

現在假設你有 1000 條方程式、1000 個未知數，會怎樣？
如果這聽起來很荒謬，別忘了現在無線數位換能器既便宜又多用途（可以量測應變、風速、三軸加速度，什麼都行……）。
用 1000 個這種換能器來監測一座像吊橋這樣的現代結構，完全合情合理。
還需要一套控制系統來解讀資料流，並在情況變得令人擔憂時發出警報。

同樣地，**A** **x** = **b**，其中我們已經有**A**（來自工程設計）和**b**（換能器量測到的值），但需要求出**x**。

對不熟悉的人來說，第一個念頭可能是想辦法「兩邊同除以**A**」，把它移到等號右邊。

事實上，**A**確實有反矩陣（大多數但並非所有方陣都有：其[行列式][wiki-determinant]必須不為零），而這樣算確實可行（_但很慢！_）。

```julia-repl
julia> A = [4 -3; 2 7]
2×2 Matrix{Int64}:
 4  -3
 2   7

julia> b = [-2, 16]
2-element Vector{Int64}:
 -2
 16

# the inverse matrix
julia> inv(A)
2×2 Matrix{Float64}:
  0.205882   0.0882353
 -0.0588235  0.117647

julia> inv(A) * b
2-element Vector{Float64}:
 0.9999999999999999
 2.0
```

可惜的是，計算反矩陣對小矩陣來說很慢，對大矩陣更是慢如冰河。
如果你的橋在計算途中就塌了，那可不太理想！

幸運的是，其他演算法快得多了（在這個情況下是[高斯消去法][gaussian-elim]）。

Julia（仿效 Matlab）直接用反斜線來求解（嚴格來說是「左除」）。

```julia-repl
julia> x = A \ b
2-element Vector{Float64}:
 1.0
 2.0
```

這是個簡單的例子，但有幾個細節要留意。

- 係數必須按行對齊，缺少的項則依需要補上 0。
- 方程式（因此矩陣的各列）必須[線性獨立][indep]。如果第 3 列只是第 1 列和第 2 列的和，它就沒有帶來新資訊，這個問題就是欠定的。

[`rank()`][rank] 指令會給出線性獨立的列數或行數，所以要設法讓它等於未知變數的數目。

```julia-repl
julia> rank(A)
2
```

### 長方矩陣

在你還不到青春期時，可能就學過：要有 `N` 條方程式才能解出 `N` 個未知數。

就像數學裡的大多數事情一樣，實際情況要再微妙一些（不只是上一節提到的線性獨立這個細節）。

#### 列太少

只有 `N-1` 條方程式（矩陣 `A` 的列）時，這個問題就是欠定的。
我們要絕望地放棄嗎？

看情況！

`N-1` 條方程式仍然含有大量資訊。
從幾何上來說，我們需要 `N` 才能把解定位成 N 維空間中的一個_點_，但 `N-1` 會告訴我們，解一定落在某條_直線_上的某處。

這麼一來，我們會有無窮多個解，但同時在參數空間中也有無窮大的區域是_完全沒有_解的。

你解所在的那條直線，會不會穿過某個讓有信譽的工程師該擔心的參數空間區域？
或者該區域嚴重到足以構成封閉這座結構、禁止公眾進入的理由（_吊橋在強側風下可是會晃得很厲害的_）？
也許值得多做些計算來確認一下！

```julia-repl
julia> A3 = [4 -3 1; 2 2 2; 3 -4 -3]
3×3 Matrix{Int64}:
 4  -3   1
 2   2   2
 3  -4  -3

julia> b3 = [1, 12, -14]
3-element Vector{Int64}:
   1
  12
 -14

# fully-determined solution
julia> A3 \ b3
3-element Vector{Float64}:
 1.0
 2.0
 3.0

# remove row 3 from A3 and B3
julia> A2 = A3[1:2, :]
2×3 Matrix{Int64}:
 4  -3  1
 2   2  2

julia> b2 = b3[1:2]
2-element Vector{Int64}:
  1
 12

# an under-determined solution
julia> z1 = A2 \ b2
3-element Vector{Float64}:
 1.594594594594594
 2.445945945945947
 1.9594594594594592
```

反斜線求解器給了我們一個解！
[非官方說法][underdet]指出，這似乎就是範數最小的解（從幾何上來說，最靠近原點）。

要取得其他解，我們需要 `A2` 的 [`nullspace`][ref-nullspace]。

把零空間的任何純量倍數加到原本的解上，都會得到另一個有效的解。

```julia-repl
# get the nummspace of A2
julia> N = nullspace(A2)
3×1 Matrix{Float64}:
 -0.46499055497527725
 -0.3487429162314578
  0.813733471206735

# add a random multiple of the nullspace to the earlier solution
julia> z = z1 + rand() * N
3×1 Matrix{Float64}:
 1.274331860650258
 2.205748895487695
 2.5199192438620472

# our random z is a valid solution, recovering b2 = [1, 12]
julia> A2 * z
2×1 Matrix{Float64}:
  0.9999999999999947
 12.0
```

同樣地，`N-2` 條方程式會把（無窮多個）解限制在一個平面上，同樣的原則也適用。

#### 列太多

相反的情況是方程式比未知數_更多_，但不知怎麼的它們仍然是線性獨立的。

_在現實世界的工程裡，這完全是正常的，甚至被視為一件好事！_

換能器的精度有限，**b**向量精度也有限，而且計算中還有雜訊。
現在的解就變成對這些帶雜訊資料的[最小平方][least-squares]擬合。

最簡單的技巧是用矩陣的[`pseudoinverse`][pseudoinv]，Julia 將它實作成 [`pinv()`][pinv] 函式。

它的用法很像（非奇異）方陣的反矩陣，會給出變數的最小平方估計值，而不是精確解。

```julia-repl
# create 5-row A and b for 2 variables
julia> A5 = [4 -3; 2 7; -1 2; 1 -1; 3 1]
5×2 Matrix{Int64}:
  4  -3
  2   7
 -1   2
  1  -1
  3   1

julia> rank(A5)
2

# add some random-normal noise to b5
julia> b5n = [-2, 16, 3, -1, 5] + randn(5) * 0.1
5-element Vector{Float64}:
 -1.9337349223581917
 16.024913008059457
  3.0087646177373992
 -0.8675748721176717
  4.914568047308805

# solve to get x ≈ 1, y ≈ 2, using the pseudoinverse
julia> pinv(A5) * b5n
2-element Vector{Float64}:
 1.006117942769543
 1.9962973764508272
```

## 特徵值與特徵向量

上一節談的是 **A** **x** = **b** 的解，這相當於我們熟悉的代數。

本節則要談 **A** **x** = λ **x** 的解，其中 λ 是一個純量。

這是線性代數特有的概念，但我們可以從幾何上來理解它：

_對適當的 **x** 與 λ 值而言，方陣 **A** 會把非零向量 **x** 的長度伸縮 λ 倍，但不改變它的方向（除非 λ 為負，會把它反向）_。

這聽起來很冷門，但結果卻_好用得離譜_！

***術語：*** λ 的有效值稱為 **A** 的_特徵值_，對應的 **x** 值則是 **A** 的_特徵向量_。
_很不幸地，我們只能接受這種講到一半就換語言的詞。_

學生通常會學到手算 2×2 矩陣的特徵值與特徵向量，但用電腦來算實在容易太多了（雖然還是頗慢，而且在一般情況下，`n×n` 矩陣的計算量會以 `O(n^3)` 增長）。

```julia-repl
julia> A = rand(-9:9, 2, 2)
2×2 Matrix{Int64}:
 9  5
 3  2

julia> F = eigen(A)
Eigen{Float64, Float64, Matrix{Float64}, Vector{Float64}}
values:
2-element Vector{Float64}:
  0.27984674554472466
 10.720153254455274
vectors:
2×2 Matrix{Float64}:
 -0.497417  0.945605
  0.867511  0.325317

# eigenvalues
julia> F.values
2-element Vector{Float64}:
  0.27984674554472466
 10.720153254455274

# each column is an eigenvector, normalized to a unit vector
julia> F.vectors
2×2 Matrix{Float64}:
 -0.497417  0.945605
  0.867511  0.325317
```

一般而言，一個 `n×n` 矩陣會有 `n` 個特徵值，但這些值不一定_互異_。
你可以把它們想成一個 `n` 次多項式（稱為[特徵多項式][wiki-char-poly]）的根，這些根可以重複，而且即使矩陣是實數值，根也常常是複數。

每個特徵向量代表一個方向，它的任何純量倍數也都是有效的特徵向量。
為了方便後續計算，Julia 會回傳[範數][wiki-norm]為 1 的單位向量。

### 應用

要說明特徵向量為什麼重要，理想上得靠一本 500 頁的教科書，而不是短短幾段話。
這個主題滲透到現代應用數學中_非常多_的領域。

從最上層來看，特徵向量代表資料集中「最重要」的軸（方向）。
特徵值則指出每個軸的「相對重要性」（_前提是對輸入的正規化方式有一些假設_）。

這實際上_代表_什麼，取決於應用情境。

#### 主成分分析

在典型的資料科學問題中，我們可能有 100 個以上的「特徵」，以資料行的形式儲存。
幾乎無可避免地，會有雜訊、冗餘，以及不想要的相關性。

我們需要做降維，而 [PCA][wiki-PCA] 是讓混沌回歸秩序的一種方法：

- 計算資料的[共變異數矩陣][wiki-cov-matrix]。
- 現在我們有了一個方陣，接著計算它的特徵值與特徵向量。
- 依特徵值由大到小排序這些特徵向量（更精確地說，是依絕對值 `|λ|` 排序）。
- 前 `k` 個特徵向量就是你的 `principal components`，其中 `k` 明顯小於原本的特徵數。
- 把整個資料集投影到這 `k` 個軸上，然後開始尋找有趣的模式。

以這種形式，PCA 曾被各式各樣的團體使用：從試圖在藥物設計中改善分子特性的醫學科學家，到想從民調資料中了解選民偏好的政治競選團隊。
搞不好連想賣你東西的行銷團隊也在用，但任何技術都能被用在好的或壞的地方。

PCA 並不屬於最小安裝的 Julia，但（在 Exercism 之外）[MultivariateStats][ref-multistats] 套件裡有你需要的一切。

#### 影像處理

把 PCA 的概念再推進一步，數位影像不過就是像素值的矩陣，我們可以為它們計算主成分。

幾十年來，這個方法一直被用在影像壓縮上，PCA 會指引你在縮減檔案大小時，哪些部分最該保留下來。

越來越多的影像分類器（例如人臉辨識）把 PCA 當成關鍵的一環。
下次你走過機場時，[老大哥][wiki-big-brother]可不只是在看著你，他還用線性代數來理解他看到的一切！

#### 機械工程

比較沒有爭議的是，機械元件的主軸就是它[慣性張量][wiki-I-tensor] ***I*** 的特徵向量（換個名字的矩陣罷了）。

你車上的每個輪子大概都有一塊或好幾塊配重，用來把這個張量 ***I*** 的非對角元素歸零。
修車廠的技師想必不會去做這些數學（跟飛機設計師和火箭工程師很不一樣），但「抖動」只是用來描述張量中交叉項的日常說法，而在這裡，這些交叉項會讓你的旅程不那麼舒適，並增加軸承的機械磨損。
