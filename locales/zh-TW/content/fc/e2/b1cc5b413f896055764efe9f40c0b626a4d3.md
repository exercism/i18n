# 映射與集合

| 型別 | 存放內容 | 查找方式 |
| --- | --- | --- |
| `ARRAY{T}` | 依序排列的值 | 位置 |
| `FMAP{K,T}` | 鍵與目標的配對 | 鍵 |
| `FSET{T}` | 值，不重複 | 是否為成員 |

## FMAP

```sather
   m ::= #FMAP{STR,INT};
   m := m.insert("emu", 2);
   m.get("emu")          -- 2
   m.has_ind("emu")      -- true
   m.size                -- 1
   m := m.delete("emu");
```

`m["emu"]`**不是**讀取映射的方法，`FMAP`沒有這樣的常式，那一行也無法編譯。要用的是`get`。

### 缺少的鍵

對不存在的鍵呼叫`get`，它不會報錯，而是回傳該型別的空值：`0`、`false`或 void。void 的`STR`不會在產生它的地方出錯，而是在之後、真正被用到的地方才出錯。養成先用`has_ind`檢查的習慣吧。

## FSET

```sather
   s ::= #FSET{STR};
   s := s.insert("emu");
   s.has("emu")          -- true
   s.size                -- 1
   s := s.delete("emu");
```

集合可以這樣組合：

```sather
   a.union(b)            -- in either
   a.intersect(b)        -- in both
   a.difference(b)       -- in a but not b
   a.is_subset(b)
```

## 重新指定與複製

`insert`和`delete`會回傳接下來要使用的容器。通常就是同一個物件，就地改變；需要擴充時，則是一個新的、更大的物件。所以：

```sather
   m := m.insert(k, v);     -- always
```

之後唯一能信任的，就是等號左邊的那個名稱。在`insert`之前取得的、指向同一個映射的另一個名稱，可能已經過時了。

想保留一份獨立的複本，得先做一次複製：

```sather
   n ::= m.copy.insert(k, v);      -- m is unchanged
```

但有個陷阱：從未插入過任何東西的映射是**void**，而對 void 的映射呼叫`copy`會失敗。`insert`、`get`、`has_ind`和`size`都能處理 void 的映射（`#FMAP{K,T}`就是 void，而映射正是靠插入才誕生的），但`copy`不行。

`HMAP`和`HSET`是只會就地改變的版本。建構大型結構時它們比較快，但在學習階段，把它們當成預設選擇是錯的。

## 走訪

| 疊代器 | 產出 |
| --- | --- |
| `m.ind!` | 每個鍵 |
| `m.target!` | 每個目標 |
| `m.pair!` | 每個鍵與目標的配對 |
| `s.elt!` | 集合中的每個值 |

映射和集合都沒有順序。兩次執行走訪的順序可能不同，所以千萬不要寫出任何取決於誰先誰後的程式。

```sather
   loop
      #OUT + guide.ind! + "\n";
   end;
```
