# 說明

Mecha Munch™ 是一家生鮮雜貨購物自動化公司，他們剛雇用你來開發他們的訂購應用程式。
你的團隊負責打造一個 MVP（_[最小可行產品][mvp]_），用來管理所有基本的購物車操作，讓使用者可以新增、移除及排序他們的雜貨訂單。
幸運的是，金流和結帳功能由另一個團隊負責！

## 1. 將項目加入使用者的購物車

MVP 應該讓使用者能將項目加入購物車。
這可以是單一項目，也可以同時是多個項目。
由於這是 MVP，項目數量以_重複出現_來表示。
如果使用者想加入 2 個 Orange，'Oranges' 會在輸入的可迭代物件中出現兩次。
如果購物車裡已經有這個項目，購物車中的數量應該增加 1。
如果這個項目對購物車來說是_新的_，就應該以數量 1 加入。

建立函式 `add_item(<current_cart>, <items_to_add>)`，它接受一個購物車字典，以及任何類似陣列、要加入的項目可迭代物件作為引數。
它應該為使用者回傳一個新的或更新後的購物車字典。

```python
>>> add_item({'Banana': 3, 'Apple': 2, 'Orange': 1},
              ('Apple', 'Apple', 'Orange', 'Apple', 'Banana'))
{'Banana': 4, 'Apple': 5, 'Orange': 2}

>>> add_item({'Banana': 3, 'Apple': 2, 'Orange': 1},
              ['Banana', 'Orange', 'Blueberries', 'Banana'])
{'Banana': 5, 'Apple': 2, 'Orange': 2, 'Blueberries': 1}
```

## 2. 讀取使用者記事應用程式中列出的項目

哎呀。
看來產品團隊開始陷入[功能蔓延][feature creep]了。
他們想為 MVP 加入額外的功能。
應用程式現在必須藉由讀取使用者記事應用程式中的項目來建立購物車。
對使用者來說很方便，但對團隊來說稍微多了一些工作。

建立函式 `read_notes(<notes>)`，它可以接受任何類似陣列的可迭代物件作為引數。
這個函式應該解析這些項目，並建立使用者的購物車字典。
每個項目都應該以數量 1 加入。
然後回傳新的使用者購物車。

```python
>>> read_notes(('Banana','Apple', 'Orange'))
{'Banana': 1, 'Apple': 1, 'Orange': 1}

>>> read_notes(['Blueberries', 'Pear', 'Orange', 'Banana', 'Apple'])
{'Blueberries' : 1, 'Pear' : 1, 'Orange' : 1, 'Banana' : 1, 'Apple' : 1}
```

## 3. 更新食譜「ideas」區段

應用程式有一個「ideas」區段，裡面充滿了來自各國料理的現成食譜。
使用者可以選擇其中任何一份食譜，並自動將其所有食材加入購物車。
專案經理請你建立一種方法來編輯這些「ideas」食譜，因為內容團隊不斷更動食材和數量。

建立函式 `update_recipes(<ideas>, <recipe_updates>)`，它接受一個「ideas」字典和一個食譜更新的可迭代物件作為引數。

## 4. 排序使用者購物車中的項目

使用者開始一個購物車之後，應用程式允許他們依字母順序排序項目。
這讓項目更容易找到，也能在出現資料輸入錯誤時有所幫助，例如資料庫裡同時有 'potatoes' 和 'Potato'。

建立函式 `sort_entries(<cart>)`，它接受一個購物車字典作為引數，並回傳一個新的、依字母順序排序的購物車。

```python
>>> sort_entries({'Banana': 3, 'Apple': 2, 'Orange': 1})
{'Apple': 2, 'Banana':3, 'Orange': 1}
```

## 5. 將使用者購物車送往商店備貨

應用程式需要將指定使用者的購物車送往商店備貨。
不過，商店裡的揀貨人員需要知道該項目位於哪個走道，以及該項目是否需要冷藏。
所以（_相當任意地_），「備貨購物車」需要依反向字母順序排序，並將項目數量與位置和冷藏資訊結合在一起。

建立函式 `send_to_store(<cart>, <aisle_mapping>)`，它接受一個使用者購物車，以及一個包含各項目商店走道編號和是否需要冷藏的 `True`/`False` 的字典。
這個函式應該 `return` 一個合併後的「備貨購物車」，其中包含顧客所訂購每個項目的（數量、走道和冷藏）。
項目應該以_反向_字母順序出現。

```python
>>> send_to_store({'Banana': 3, 'Apple': 2, 'Orange': 1, 'Milk': 2},
                  {'Banana': ['Aisle 5', False], 'Apple': ['Aisle 4', False], 'Orange': ['Aisle 4', False], 'Milk': ['Aisle 2', True]})
{'Orange': [1, 'Aisle 4', False], 'Milk': [2, 'Aisle 2', True], 'Banana': [3, 'Aisle 5', False], 'Apple': [2, 'Aisle 4', False]}
```

## 6. 更新商店庫存以反映使用者的訂購內容。

應用程式不能只是無止境地接受顧客的訂單。
總有一天，商店的各種商品會用完。
所以你的 MVP 應用程式需要在使用者每次將訂單送往商店時更新商店庫存。
否則，顧客會訂購實際上沒有庫存的商品。

建立函式 `update_store_inventory(<fulfillment_cart>, <store_inventory>)`，它接受一個「備貨購物車」和一個商店庫存。
這個函式應該依照「備貨購物車」中「訂購」的數量來扣減商店庫存，然後回傳更新後的商店庫存。
當某個商店項目的數量降為 0 時，該數量應該被替換為訊息 'Out of Stock'。

```python
>>> update_store_inventory({'Orange': [1, 'Aisle 4', False], 'Milk': [2, 'Aisle 2', True], 'Banana': [3, 'Aisle 5', False], 'Apple': [2, 'Aisle 4', False]},
{'Banana': [15, 'Aisle 5', False], 'Apple': [12, 'Aisle 4', False], 'Orange': [1, 'Aisle 4', False], 'Milk': [4, 'Aisle 2', True]})

{'Banana': [12, 'Aisle 5', False], 'Apple': [10, 'Aisle 4', False], 'Orange': ['Out of Stock', 'Aisle 4', False], 'Milk': [2, 'Aisle 2', True]}
```
