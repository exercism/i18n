# 測試

解決 Exercism 練習的方法之一，是連上網站並使用瀏覽器內的編輯器，在那裡編輯和測試你的解答。

或者，你也可以把練習下載到自己的電腦，使用自己的編輯器和一組工具來撰寫、測試，最後提交你的解答。

這會用到 Exercism 命令列介面（CLI），這是一套在終端機或命令列視窗中執行的應用程式。安裝說明請見：[Exercism CLI 文件](https://exercism.org/docs/using/solving-exercises/working-locally)。

## 測試方式
Exercism 假設你對測試驅動開發有些經驗。每個練習都包含一個 _`stub file`_、一個內含一系列預先寫好測試的 _`test file`_，以及一個用來執行測試的 _`test script`_。

解決一個練習，需要逐步發展 _`stub file`_，讓它最後包含能通過所有測試的程式碼。

實際來說，這代表 _`stub file`_ 和 _`test file`_ 都會被你頻繁修改。請注意，修改 _`test file`_ 並不是要改動測試程式碼，而是要把失敗的測試註解掉。

一開始，除了其中一個測試之外，其餘都會被註解掉；接著，隨著 _`stub file`_ 逐漸發展成可運作的解答，你會取消註解更多測試，直到所有測試都能成功執行。

## 測試基礎架構
你不需要安裝任何額外的軟體，因為測試框架的元件已經包含在下載的練習裡。

測試框架由三個 Rexx 檔案組成，測試時會和練習的解答結合成測試程式碼單元，再由 _`test script`_ 執行，並將測試結果列印到終端機。

請不要編輯或刪除 _`test script`_，或任何其他測試框架檔案。如果真有這種情況發生，只要用 Exercism CLI 重新下載練習就好，但請小心保留你的解答程式碼。

## 執行測試
解決練習的步驟如下：

1. 開啟終端機
2. 下載你要做的練習
3. 切換到練習目錄
4. 將 stub file 和 test file 載入你的編輯器
5. 反覆進行以下步驟：

    1. 執行 test script
    2. 在 stub file 裡寫程式碼（慢慢把它變成解答檔），並在 test file 裡把測試註解掉或取消註解

6. 當所有測試都通過，把解答提交到 Exercism
7. 關閉終端機
8. 慶祝你的成功吧！

以下是在 Linux 終端機中使用`acronym`練習的具體範例（假設 exercism 工作區是：`/home/exercism`）

下載練習：

`exercism download --track=rexx --exercise=acronym`

切換到練習目錄：

`cd /home/exercism/rexx/acronym`

從另一個視窗（也許是圖形介面），把 `acronym.rexx` 和 `acronym-check.rexx` 分別載入你的編輯器，它們分別是 stub 檔和 test 檔。

執行 test script：`./test-acronym`

所有測試應該都會失敗：

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

把 `acronym-check.rexx` 檔案裡除了第一個以外的測試都註解掉，再重新執行 test script，應該會得到以下輸出：

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

修改 `acronym.rexx`，直到它包含能運作的程式碼，最後執行 test script 的輸出應該會是：

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

接著依序取消註解其他測試，重新執行 test script，最後輸出應該會是：

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

現在你可以提交練習解答了：

`exercism submit acronym.rexx`

再累積一個聲譽點數。完成後關閉終端機。

對 MacOS 使用者來說，流程會相當類似，因為 MacOS 是從 UNIX 衍生而來的作業系統。

Windows 使用者的流程大致類似，但有幾個小差異：

- _Command Prompt_ 視窗就是終端機
- 路徑中的斜線會換成反斜線，所以工作目錄可能長這樣：

  `cd C:\Users\MyName\exercism\rexx\acronym`

- 執行 test script 的方式是：

  `test-acronym`  或  `test-acronym.bat`

測試輸出會完全相同。
