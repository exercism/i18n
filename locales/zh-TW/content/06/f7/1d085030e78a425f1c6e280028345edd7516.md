# 重新導向簡介

在命令列介面的世界裡，程式常常會和三個標準資料流打交道：

1. **標準輸入**（`stdin`）：程式接收輸入的地方（通常來自鍵盤）。
1. **標準輸出**（`stdout`）：程式送出正常輸出的地方（通常送到終端機畫面）。
1. **標準錯誤**（`stderr`）：程式送出錯誤訊息的地方（通常送到終端機畫面）。

還記得我們在[管線與命令清單][pipelines]那一章介紹過這些嗎？

~~~~exercism/note
管線可以算是一種重新導向：某個程式的標準輸出會直接送到另一個程式的標準輸入。
我們已經談過管線了。
這個概念要談的是把輸出重新導向到檔案，以及從檔案重新導向輸入。
~~~~

Shell 的重新導向是很強大的機制，讓你能改變這些資料流的去向。程式原本從鍵盤讀取、把結果寫到畫面，現在你可以改成從檔案讀取輸入，或把輸出送到檔案。這讓程式與資料互動的方式更有彈性，也更好掌控。

## 主要的重新導向運算子

以下是幾個最常見的重新導向運算子，以及它們的功能：

### `>`（輸出重新導向）

* 用途：把命令的標準輸出（`stdout`）重新導向到檔案。
* 行為：
  * 如果檔案不存在，會建立檔案。
  * 如果檔案已存在，內容會被覆蓋。
* 範例：

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
重新導向會在命令執行**之前**就完成。
也就是說，你沒辦法重新導向到一個同時還需要讀取的檔案。

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

在上面範例的第二個命令裡，

1. Bash 會先截斷重新導向裡指定的檔案。
   這會破壞原本的內容，留下一個空檔案。
2. 接著 Bash 讀取這個剛變空的檔案。
3. 然後 Bash 再把內容（也就是空的）寫回檔案。
~~~~

### `>>`（附加輸出重新導向）

* 用途：把命令的標準輸出（`stdout`）附加到檔案後面。
* 行為：
  * 如果檔案不存在，會建立檔案。
  * 如果檔案已存在，輸出會附加到檔案的末端。
* 範例：

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<`（輸入重新導向）

* 用途：把命令的標準輸入（`stdin`）改成從檔案讀取。
* 行為：命令會從指定的檔案讀取輸入，而不是從鍵盤。
* 範例：

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>`（錯誤重新導向）：

* 用途：把命令的標準錯誤（`stderr`）重新導向到檔案。
* 行為：錯誤訊息會送到指定的檔案，而不是終端機。
* 範例：
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

你也可以用`2>>`把標準錯誤_附加_到檔案。

### 其他重新導向

還有一些重新導向可以把`stdin`和`stderr`合併起來。
詳情請參考[使用手冊][manual]。

## `/dev/null`

`/dev/null`是一個特殊的檔案，它

* 讀取時是一個空檔案，而且
* 會丟棄所有寫入其中的資料。

它有時被稱為「the bitbucket」。
它很適合用來抑制輸出或錯誤。

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## 合併重新導向

你可以在同一個命令裡同時使用多個重新導向。

```bash
some_command < input.txt > output.txt 2> error.txt
```

重新導向也可以複製。

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

看到`2>&1`時，把它讀成「把 stderr 重新導向到 _stdout **目前**指向的地方_」。
Bash 會嚴格依照從左到右的順序處理重新導向指令，所以你可以這樣做：

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## 檔案描述符

在 Shell 程式設計以及 Linux/Unix 這類作業系統的脈絡下，檔案描述符（FD）是一個非負整數，用來當作已開啟檔案或 I/O（輸入／輸出）資源的識別碼或控制代碼。
你可以把它想成一個標籤或參照編號，作業系統靠它來追蹤開啟中的檔案與資料流。

你在重新導向左邊看到的那些數字，就是檔案描述符。

標準 I/O 資料流會拿到前 3 個檔案描述符：

* 標準輸入是 FD 0
* 標準輸出是 FD 1
* 標準錯誤是 FD 2

你可以用`exec`命令和重新導向運算子來設定或建立新的檔案描述符。

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

這個技巧看起來有點複雜，但當你的指令碼是由其他軟體套件執行、而標準輸出會被該軟體自動接收時，它會非常有用。
這個 track 用來執行單元測試的`bats`命令就是這樣運作的：`bats`會接收測試的 stdout 和 stderr，但送到 FD 3 的除錯訊息會顯示在終端機上。
~~~~

## 總結

重新導向有什麼用呢？

* 儲存輸出：把命令的結果存下來，之後再查看或處理。
* 記錄：把錯誤訊息保留下來，方便除錯。
* 自動化：把多個命令串起來，用一個命令的輸出當作另一個命令的輸入。
* 過濾：丟掉不需要的輸出。
* 批次處理：直接處理檔案裡的資料，不用手動輸入。
* 撰寫指令碼：重新導向是寫出穩定 Shell 指令碼的必要工具。

Shell 的重新導向讓你更精細地控制程式與資料互動的方式，幫助你建立複雜的工作流，有效管理資訊。
