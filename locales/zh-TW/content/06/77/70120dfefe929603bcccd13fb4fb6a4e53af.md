# 簡介

正規表達式是用途非常廣泛的方式，可以用來對字串進行_模式比對_，它使用的是一種專門為此設計的領域特定語言（DSL）。

許多正規表達式的功能都已內建於 Base R，你可能會在較舊的程式碼中看到相關範例。

對於新的程式碼，_強烈_建議使用 [`stringr`][web-stringr] 套件。

如[字串概念][concept-strings]所述，`stringr`有良好的文件，通常由套件作者親自撰寫。

- 一個[參考網站][web-stringr]
- 一份[速查表][cheat-stringr]。
- 「R for Data Science」中的[字串章節][book-strings]和[正規表達式章節][book-regex]。

我們在 [`Strings`][concept-strings]概念中討論過的許多函式，本身就支援以正規表達式進行搜尋。

我們在字串概念中刻意保持相對簡單，只比對字串常值，不過你也可以改用任何正規表達式模式。

正式來說，在 R 中建立正規表達式的方式是呼叫 [`regex()`][ref-regex]。
為了方便起見，`stringr`的函式會把任何模式字串都視為正規表達式。
在下面的範例中，第一個 `str_replace_all()` 是第二種寫法的語法糖：

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[速查表][cheat-stringr]是相當實用的指南：所有帶有 `pattern` 引數的函式（以紅色標示）都接受正規表達式，第 2 頁則整理了正規表達式的語法。

請注意，如果你需要覆寫預設值（例如大小寫敏感度或地區設定），[`regex()`][ref-regex]函式仍然很重要。

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

許多正規表達式碼都包含反斜線，例如上面用到的 `\s`。
在一般的 R 字串中，`\` 需要以雙寫的方式跳脫，因此要寫成 `"\\s"`。

反斜線可能愈來愈多、變得令人混淆，所以在複雜的情況下，改用[原始字串][book-raw]可能會有所幫助。

預設用來定義原始字串的語法是 `r"( )"`，不過也允許使用其他分隔符號。
由於括號 `( )` 和方括號 `[ ]` 在正規表達式語法中都很常見（用於擷取群組和選項群組），大括號 `{ }` 或許是不錯的選擇。

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## 偵測符合項

以下是一些問題，以及能幫助你回答這些問題的函式。

有些範例使用 `fruit`，這是一個包含 80 個水果名稱的向量，內含在 `stringr` 中供練習使用。

_字串中是否包含符合的內容？_
使用 `str_detect()`，或使用 `str_starts()`、`str_ends()` 來避免用到 `^` 或 `$` 錨點。

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_只回傳包含符合內容的字串？_
使用 `str_subset()` 取得字串，使用 `str_which()` 取得索引。

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_每個字串中有多少個符合項？_
使用 `str_count()`。

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_符合的內容在哪裡？_
`str_view()` 用於互動式檢視，一般情況則使用 `str_locate()` 或 `str_locate_all()`。

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## 擷取

通常我們想知道的是_什麼_符合了。
這可以透過在正規表達式中用括號加入擷取群組來達成。

你可以在同一個正規表達式中，使用 `\1`、`\2` 等反向參照先前擷取到的內容。
例如，找出重複的字母組合：

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

用類似的語法，擷取到的內容也能用在取代字串中：

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

使用 `str_match()` 函式收集符合的內容以供後續處理（僅取第一個符合項），或使用 `str_match_all()` 取得所有符合項。

擷取群組在任何語言中都傾向產生複雜的輸出。
R 的做法（_同時也經過向量化，算是額外的挑戰_）是從 `str_match()` 產生一個矩陣，每個輸入字串對應一列，第 1 欄包含完整符合的字串，其餘欄位則包含各個擷取群組。

使用具名群組可能有好處，因為它們會成為結果矩陣的欄位名稱。

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

~~~~exercism/note
我們在這份課程大綱中沒有多談矩陣，不過你可以存取一份[概念文件][concept-matrices-arrays]。
雖然矩陣長久以來都是 Base R 的一部分，但它和 Tidyverse 生態系並不太契合。

簡單來說：把矩陣當成帶有 2 個索引的向量，順序是`[rows, cols]`。
把任一索引留空，就能取得整列或整欄。

當你用 `m[r,]` 取得單一列 `r`，或用 `m[,c]` 取得單一欄 `c` 時，回傳的值預設會被攤平成向量。

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```
~~~~

不可避免地，`str_match_all()` 產生的輸出結構又更加複雜：

- 結果是一個陣列，每個輸入字串對應一個元素。
- 如果只有一個輸入字串，就用 `[[1]]` 索引把輸出攤平，如[陣列概念][concept-lists]所述。
- 每個元素都是一個矩陣，欄位與 `match()` 相同。
- 矩陣中的每一列都是一次成功的擷取。

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

當然，比對也可能失敗。
此時結果會是特殊值 `NA`。
請準備好測試這種情況，如[空無概念][concept-nothingness]所述。

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
