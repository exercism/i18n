# 提示
`Either`常見的用途是表示一個可能會產生錯誤的運算（如果其實不在意錯誤本身，那麼更單純的 `Option` 型別可能是更好的選擇）。
沒有發生錯誤時，結果通常是 `Right`（記憶法：代表正確的那個值），而發生錯誤時則是 `Left`，例如帶有錯誤訊息的 `Left[String]`。
請注意，在 Scala 2.12 中，`Either`預設是偏右的，所以像是`filter`、`map`、`flatMap`這類操作，或是在 for-comprehension 裡，它都能如預期般運作。
如果你不熟悉 `Either`，可以閱讀[這篇教學](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html)。但請注意，這篇教學談的是 2.12 之前的 Scala 版本。使用 Scala 2.12 時，你可以放心忽略 `RightProjection`，並省略 `.right`。
`Either`是一種所謂的[Monad](https://en.wikipedia.org/wiki/Monad_(functional_programming))，涵蓋了某種「運算面向」，在這裡指的就是錯誤處理。
妥善運用 Monad 可以寫出非常簡潔，卻又優雅且易讀的程式碼。運用不當則很容易得到相反的結果。
想進一步了解，請觀看[這段影片](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA)。
## 你應該避免的常見陷阱
`Either`有幾個經驗法則：
1. 用不到就不要用。與其寫
```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```
不如寫
```scala
def add1(x: Int): Int = x + 1
```
（有`Either.map`可以套用這類簡單的函式，所以不必用`Either`把它們包起來）。
2. 不是真的需要，就不要「取出」裡面的值。
通常都有現成的函式可以達到你的目的。過早取值的跡象包括`isLeft/isRight`或模式比對。例如，與其寫
```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```
不如寫
```scala
x fold (identity, _ + 1)
```
3. Monad 也可以用在 for-comprehension 裡，超讚。
當你想「組合」好幾個 `Either` 實例時，建議這麼做。與其寫
```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```
不如寫
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
