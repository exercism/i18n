# 簡介

到了課程大綱的這個階段，你應該已經看過 R 經常被當成命令式語言使用，也越來越常被當成函式式語言使用（尤其是搭配 [`purrr`][ref-purrr] 和 [`dplyr`][ref-dplyr] 這兩個套件的時候）。

現在如果主張 R 主要是物件導向的語言，可能會引來一些質疑！

說也奇怪，這是個真確的說法。
在內部，R 是用類別、繼承、多型，以及物件導向程式設計師典型的那種心態實作出來的。

不過，任何熟悉 Java 或 Ruby（兩者都是明確的物件導向），或甚至 Python（在某些方面算是半隱藏地物件導向）的人，都會覺得 R 的做法……_很陌生_。

首先，R 有好幾種類別設計：常用的可能有三種（S3、S4、R6），另外還有一些主要出於理論興趣的其他設計。

完整的討論可以參考 [Advanced R, 2e][book-advanced-r] 第 12 到 16 章。
這本 2019 年出版的書，主要寫給想理解並維護 R 內部運作的人，因此物件導向是不可或缺的。

比較以一般使用者為導向的教科書，做法就各不相同。

- The Art of R Programming（2011 年，僅有紙本）有一章談物件導向，涵蓋 S3 以及（較簡略地）S4，這兩者在當時都很重要。
  書中那句_「S3 類別有著相當拼湊而成的結構」_至今依然驚人地貼切。
- R in Action（第 3 版，2022 年）把物件導向擠到接近書末、談進階程式設計那一章裡的 3 頁。
- [R for Data Science, 2e][book-r-data-sci]（2023 年，紙本版共 548 頁）完全沒有提到物件導向。

本概念會聚焦在 S3 類別，因為它最簡單、最常見，也最貼近 Exercism 這類題目。
R track 上有些練習要求你建立 S3 類別，其他練習則把它列為選用，但也會溫和地鼓勵你這麼做。

## S3 類別

這些類別很老了：S3 這個名字只是表示它們是在 S 語言（R 的商業前身）第 3 版中引進的。

S3 類別本身也非常簡單：通常就是一個帶有至少一個額外屬性的[陣列][concept-lists]。

引用 [Advanced R][book-s3]：_「S3 很不正式、很臨時，但它的極簡主義帶著某種優雅：你沒辦法從其中拿掉任何一部分，而還保有一個有用的物件導向系統。」_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

所以，對 [`class(obj)`][ref-class] 做指定，其實就只是在 `obj` 上多加一個屬性；在這裡，就是把 pt2d 標示為 point2d 類別的一個實例。

建立步驟也可以用 [`structure()`][ref-structure] 合併起來：

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

雖然產生的實例在意義上完全相同，但我們還沒有實作出讓 R 能確認這一點的方法。

### 泛型方法

熟悉其他語言物件導向寫法的人可能會想：_「類別不是應該要能做點事嗎？」_

我們可以檢查 `point2d` 實例有哪些可用的方法，然後發現（相對於底層的 `list`）目前一個都沒有。

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

在大多數物件導向語言裡，方法是在類別定義之內定義的。
有少數語言（尤其是 Ruby）允許你之後再加入和修改類別方法。

S3 類別非常不一樣。
我們不是把方法加到類別上，而是把類別加到泛型方法上。

任何在 R 主控台上互動工作的人，隨時都在用泛型方法，通常根本不會去想它們是怎麼實作的。

一個很常見的例子是 `print()`，即使你很少真的打出這個函式名稱。
在主控台提示字元下單獨輸入一個值 `x`，其實只是 `print(x)` 的語法糖。

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

我們已經可以印出 `pt2d` 了。
雖然 `print()` 對 `point2d` 類別一無所知，但它有合理的預設行為，可以處理各種物件。

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

這樣輸出相當冗長，我們可能會想要一個能把這個點簡潔漂亮印出來的方式。

很簡單：只要加一個名為 `print.point2d()` 的函式就好。
名稱必須是 `methodname.classname` 的形式，這樣分派器才知道要去找什麼。

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

現在假設我們想建立一個新的泛型方法，例如用 `flipvert()` 把 `y` 座標的正負號反過來。

同樣很簡單：

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

這會建立一個分派器，其中 `x` 是我們帶有 S3 類別的物件，而 `...` 則負責處理各種方法定義可能需要的額外引數（即「dot args」，如[函式概念][concept-functions]所述）。

我們接著就可以為 `point2d` 定義這個方法並使用它。

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

R 現在知道怎麼翻轉我們的點，也知道怎麼顯示結果。

我們可以進一步擴充，為 3D、極座標等建立類別，然後為每個類別定義方法。

從一般使用者的角度來看，只有 `flipvert(x, ...)` 這一個函式，我們可以交給 R 去判斷輸入的類別，並使用適當的底層實作。

~~~~exercism/caution
`verb.class` 這種格式的函式名稱，不論對使用者還是對 R 的剖析器來說，看起來都像 S3 方法。
請避免在其他情境使用類似的命名。

不可否認，base R 有時候會違反這條規則。
我們應該把它看成一個不幸的歷史意外（那些函式甚至比 S3 還老），而且是為了向後相容而必須保留的。
~~~~

### 繼承

熱愛物件導向的人可以為繼承、建立子類別、混入等主題寫上好幾章厚厚的教科書。

R 只是讓你可以在 `class` 屬性裡放多個名稱：一個更長的字串向量，而不是單一字串。

冒著把這個例子硬撐到極限的風險，假設我們做了一個泛用的 `point` 類別，想為它建立 `point2d`、`point3d` 等子類別。

那麼 `point2d` 的定義就只要用 `class = c("point2d", "point")`：特定類別加上父類別（父類別可能不只一個）。

像 `print()` 這樣的泛型方法，接著就會依序尋找 `print.point2d()`、`print.point()` 以及（大概還有）`print.default()`，並採用分派器找到的第一個實作。

### 安全性

許多物件導向語言（Java、C# 等）會利用類別內的資料封裝來進行謹慎的編譯期檢查，並強制執行型別安全。

請注意，S3 讓你幾乎想做什麼就做什麼，就算毫無道理也一樣（錯誤訊息要等到之後才會出現，甚至根本不會出現）。

引用 [Advanced R][book-s3]（第 2 版，13.3 節）：

> _如果你用過其他物件導向語言，這可能會讓你覺得不太舒服，但實務上這種彈性很少造成問題。R 不會阻止你朝自己的腳開槍，但只要你不把槍對準自己的腳趾扣下扳機，就不會有問題。_

嗯，_是嗎？_
R 在探索性資料科學與統計上非常出色，尤其是互動式工作的時候。
沒有人是在建議你用它來寫安全性要求極高的企業財務系統！
