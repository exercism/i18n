# 關於

許多程式需要（看起來）隨機的值，來模擬真實世界的事件。

常見又熟悉的例子包括：

- 擲一枚硬幣：一個隨機的值，可能是`"H"`或`"T"`。
- 擲一顆骰子：一個從 1 到 6 的隨機整數。
- 洗一副牌：把一份牌的清單隨機排序。

用電腦產生真正隨機的值，是一項[出乎意料困難的技術挑戰][web-truly-random]，所以你會看到這類結果被稱為「偽隨機」。

***重要***：這個概念並*不*涵蓋密碼學上安全的隨機數，那是困難得多的挑戰。

不過，R 源自一套統計套件，也經常被用在模擬上，因此它提供了豐富多樣的方式來產生隨機值。
對建模、模擬和遊戲裡的大多數應用來說，這些結果已經非常夠用。

## [取後放回與取後不放回的抽樣][yt-sampling-with-replacement]

想像我們有一個袋子，裡面裝了 3 顆紅球和 4 顆綠球，我們隨機從袋子裡抽出一顆球。
要再抽第二顆球，有兩種可能：

1. 把第一顆球放回袋中，充分搖勻之後再抽出另一顆。
   袋中球的數量跟原本一樣（7 顆），而且*紅球與綠球的比例也一樣*。
2. 把第一顆球放到桌上，再抽出第二顆。
   現在袋中只剩 6 顆球，而且*紅綠比例取決於第一顆球的顏色*。

情境 1 是取後放回，情境 2 是取後不放回，而*兩者會得到不同的結果*。

## 用`sample`產生離散的值

想從有限個離散值中挑選時，[`sample()`][ref-sample]可以搭配取後放回或取後不放回使用。
這對整數、字串等都很實用。

```R
sample(1:10, 5) # no repeats by default
#> [1] 8 3 4 2 6

sample(1:10, 5, replace = TRUE) # repeats are OK
#> [1] 10 10  7 10  9

languages <- c("Fortran", "R", "Python", "Julia")
sample(languages, 1)
#> [1] "Python"

sample(c("H", "T"), 5, replace = TRUE) # coin flips
#> [1] "T" "T" "H" "H" "H"

sample(c(TRUE, FALSE), 5, replace = TRUE) # alternative coin flips
#> [1] FALSE  TRUE FALSE  TRUE  TRUE
```

抽樣很適合放進資料管線裡。
例如，要產生隨機的英數字字串：

```R
library(stringr)

c(letters, LETTERS, 0:9) |> sample(50) |> str_flatten()
#> [1] "5tX71jhbM9zUmKrpENBQyGYaZdJPVAx06leSF2s8gcfw3OviIH"
```

另外，抽樣並不限於向量和範圍。
我們會在其他的概念中看到，[陣列][concept-lists]、[矩陣][concept-matrices-arrays]和[資料框][concept-dataframes]都是合法的輸入。
*這正是你對 R 應該有的期待*。

## 洗牌

其他幾個語言有專門用來洗牌（把序列隨機打亂）的函式：Python 的`random.shuffle()`、Julia 的`shuffle()`、Matlab 的`randperm()`等等。

R 沒有洗牌的函式。
*為什麼呢？*

要理解這一點，再看一次[`sample`][ref-sample]函式。

完整的形式是`sample(x, size, replace = FALSE, prob = NULL)`，其中`x`（通常）是要抽樣的序列，`size`則是要挑選的項目數量。

我們已經討論過`replace`，它的預設是取後不放回。
現在先忽略`prob`，它讓你可以給`x`裡各個元素不同的權重。

如果省略`size`，只提供`x`，會發生什麼事？

```R
x <- letters[1:6]
x
#> [1] "a" "b" "c" "d" "e" "f"
sample(x)
#> [1] "e" "a" "f" "b" "c" "d"
```

典型的 R 風格是「向量進、向量出」，而`size`的預設值是`length(x)`。

R 很大程度上是由統計學家所寫、也為統計學家而寫，他們明白「對`x`的所有元素做取後不放回的抽樣」，其實只是「把`x`洗牌」比較技術性的說法。

*因此*，R 沒有`shuffle`函式，因為`sample`已經正好做到我們需要的事了！

## 處理各種分布

上面的例子描述的狀況是，所有結果出現的機率都相同。
例如，`sample(1:100)`給出 1 到 100 之間任何整數的機率都一樣。

這叫做[`uniform`][web-uniform]分布。

現實世界裡的許多情況遠比這複雜。
因此，統計學家創造了各式各樣的[`distributions`][wiki-probability-distribution]，用數學方式描述「真實世界」的結果。

基礎 R 支援的分布數量，多到你大概沒聽過那麼多，另外還有一些分布可以在開源套件裡找到。

本文接下來只會介紹幾種最常見的分布。

## 浮點數

### 均勻分布

想要一組[權重相等的浮點數分布][wiki-uniform]，請用[`runif()`][ref-runif]（重點是「**r**andom-**unif**orm」，要克制住把它讀成「run if」這個自然卻*錯誤*的傾向）。
`min`和`max`都可以指定，預設值分別是 0 和 1。

```R
runif(5)  # generate 5 values
#> [1] 0.3038506 0.3527959 0.3319309 0.4846354 0.4386279

# generate 5 non-negative values <= 100.0
runif(5, max = 100)
#> [1] 79.70762 51.62232 52.85281 71.08571 63.94380
```

### 常態／高斯分布

它也被稱為「鐘形」曲線，是描述測量值不精確程度時非常常見的方式。

舉例來說，假設你工作的工廠剛買了 10,000 支應該要一模一樣的螺栓。
你想設定工廠的機器人來處理它們，於是你秤了其中 100 支的樣本，發現平均（也就是[`mean`][ref-mean]）重量是 4.731g。
這極不可能代表每一支都正好重 4.731g。
也許你發現值落在 4.627 到 4.794g 之間，但大多集中在 4.731g 附近。

這就是[`normal distribution`][wiki-normal-distribution]（或稱「高斯分布」，以數學家卡爾．弗里德里希．高斯命名）。它的機率在平均值處達到高峰，並在兩側對稱地遞減（因此呈「鐘形」）。

要在軟體裡模擬這種情況，我們需要某種方式來指定曲線的寬度（*通常來說，昂貴的螺栓會比便宜的螺栓更緊密地集中在平均值附近！*）。
依照慣例，這是用[`standard deviation`][wiki-standard-deviation]來做的：值小代表曲線高聳狹窄，值大代表曲線低矮寬廣。

數學家熱愛希臘字母，所以你會經常看到用`μ`（'mu'）代表平均值、用`σ`（'sigma'）代表標準差（或`sd`）。
因此，如果你讀到「有 95% 的值落在 μ 的 2σ 之內」或「希格斯玻色子以 5-sigma 的信心水準被偵測到」，這類說法都跟標準差有關。

<!-- 關於這一點，之後在[`Statistics`][statistics]概念裡還會有更多說明。 -->

要用這種分布產生隨機值，R 提供了[`rnorm()`][ref-rnorm]函式。

它是「random normal」的縮寫，`mean`預設為 0、`sd`預設為 1。

```R
rnorm(5)
#> [1]  0.36965357  0.07489948 -0.83827224 -0.83126506 -0.59895825

# Simulating our bolts example
rnorm(5, mean = 4.731, sd = 0.2)
#> [1] 4.564521 4.613237 4.419512 4.772196 4.839102
```

光看這些數字，很難看出原始輸出比均勻分布更集中在平均值附近。
如果你懷疑，就產生 1000 個以上並畫成圖，會更明顯。
本機沒有安裝 RStudio（或類似工具）的學生，可以使用線上 R 執行環境，例如 [rdrr.io][web-rdrr] 或 [WebR ggplot2 Playground][web-ggplot]。

`hist(rnorm(10000), breaks = 40)`這段程式碼會顯示出基本的模式，只是呈現方式不是最優雅的。
隨機數字會被分箱，縱軸則是每個箱裡的結果數量。

~~~~exercism/advanced

前置字母有：

- `d`：密度，機率密度函式在某一點的值

## 離散分布

### 二項分布

如果你擲一枚硬幣（*不作弊*），得到正面或反面的機會相等：兩者的機率都是`p = 0.5`。

如果你把硬幣擲 20 次，會出現幾次正面？
可能是零次，也可能是二十次，但即使完全沒學過統計的人，大概也會猜「*大約 10 次*」。

擲一次時，出現 0 次或 1 次正面的機率比是`1:1`。

擲兩次時，0、1、2 次正面的比例是`1:2:1`；擲三次時是`1:3:3:1`。

這些比例稱為[「二項式係數」][wiki-binom-coeff]。
它們構成了[巴斯卡三角形][wiki-pascal-triangle]，而包括 R 在內的許多 Exercism 學習軌道，都有一個以此為基礎的[練習題][practice-pascal]。

如果我們想要的是某個特定結果的機率，R 提供了[`dbinom()`][ref-rbinom]函式（它計算的是[機率密度][wiki-pdf]）。
從 20 次擲幣中得到 10 次正面的機率將近 18%。

```R
# Probability of exactly 10 heads in 20 flips, fair coin
dbinom(10, size = 20, prob = 0.5)
#> [1] 0.1761971
```

作弊是有可能的，所以把出現正面的機率提高到`p = 0.6`，反而*降低*了得到 10 次正面的機率：

```R
# Probability of exactly 10 heads in 20 flips, biased coin
dbinom(10, size = 20, prob = 0.6)
#> [1] 0.1171416
```

現在 20 次擲幣中出現超過 10 次正面的可能性變大了。
很明顯，我們需要關心所有可能的結果：[二項分布][wiki-binomial]。

R 提供了[`rbinom()`][ref-rbinom]函式，用來產生符合二項分布的隨機值。
你要告訴它要回傳幾個值`n`、要做幾次試驗`size`（例如擲幾次硬幣），以及單一事件的機率`prob`（例如擲一次得到正面的機率）。

要模擬我們的擲幣過程，請在能顯示圖形輸出的地方執行這段程式碼，就像前面常態分布那樣：

```R
# fair coin
hist(rbinom(n = 10000, size = 20, prob = 0.5))

# biased coin
hist(rbinom(n = 10000, size = 20, prob = 0.6))
```

產生的圖顯示，最可能出現的正面次數分別是「大約 10 次」和「大約 12 次」。

擲 20 次時，結果明顯是離散的，直方圖上會呈現很大的階梯，但仍有點像「鐘形」。

如果我們模擬數百萬次擲幣，並使用公平的硬幣讓結果保持對稱，二項分布就會越來越接近（*連續的*）常態分布。

### 卜瓦松分布

每年有多少顆直徑大於 1m 的隕石撞擊地球？

地球上的每個地方都有某種（低度的）天然背景輻射。
如果你打開[蓋革計數器][wiki-geiger]，你會聽到每秒多少次探測到輻射粒子所發出的咔嗒聲？

這些例子的特徵包括：

- 事件彼此*互相獨立*。
- 某個區間內發生事件的機率維持不變。
- 我們在計數的是離散事件。
- 計數沒有*理論上*的上限（不過測量上可能有實際的限制）。

在某個區間內得到 0、1、2……個事件的機率，構成了[卜瓦松分布][wiki-poisson]。

卜瓦松分布的關鍵參數，是所選區間內事件數的[平均][ref-mean]（平均值），通常用希臘字母 λ（'lambda'）來表示。

文獻上把直徑至少 1 公尺、撞擊地球的隕石頻率描述為「每隔幾個月一次」。

舉例來說，取`lambda = 4`，看看用[`rpois()`][ref-rpois]產生的分布長什麼樣子：

```R
hist(rpois(n = 10000, lambda = 4))
```

現在直方圖非常不對稱，高峰落在 2 次撞擊，還有一條長尾顯示 10 次以上的次數並不為零。

## 隨機種子

上面介紹的所有隨機函式，都希望每次執行時得到不同的結果。
畢竟，它們是*隨機*的！

這種行為仰賴每次產生不同的[隨機種子][wiki-seed]。

為了除錯，使用[`set.seed(n)`][ref-set-seed]函式可能會有幫助，其中`n`是你選的整數。
每次設定相同的種子，我們的程式碼就會在每次執行時回傳同一組隨機值。

```R
sample(1:5) #> [1] 5 1 2 4 3
sample(1:5) #> [1] 2 5 4 1 3
sample(1:5) #> [1] 4 2 5 1 3

set.seed(100); sample(1:5) #> [1] 2 3 5 4 1
set.seed(100); sample(1:5) #> [1] 2 3 5 4 1
set.seed(100); sample(1:5) #> [1] 2 3 5 4 1
```

對進階使用者來說，`set.seed()`也讓你可以指定要使用的 RNG（*隨機數字產生器*）類型。

據說預設值是`"Mersenne-Twister"`，所以在嘗試更改之前，請先確認你了解那是什麼意思。
本概念的作者對 RNG 沒有其他建議可提供。
