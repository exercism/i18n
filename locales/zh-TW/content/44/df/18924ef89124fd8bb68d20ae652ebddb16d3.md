# 綁定常式

```sather
   part : ROUT{STR}:STR := bind(shout(_));
   part.call("who's there");
```

## bind

`bind` 接受一個呼叫，其中任何部分都可以用`_`取代。只要不是`_`的部分，都會在**立刻**求值並保留下來；每個`_`則會依照撰寫的順序，成為綁定常式的引數。

```sather
   bind(repeat(2, _))         -- ROUT{STR}:STR
   bind(repeat(_, "Ha"))      -- ROUT{INT}:STR
   bind(repeat(_, _))         -- ROUT{INT,STR}:STR
```

## 型別

| 型別 | 接受 | 回傳 |
| --- | --- | --- |
| `ROUT:INT` | 無 | `INT` |
| `ROUT{STR}` | 一個`STR` | 無 |
| `ROUT{STR}:STR` | 一個`STR` | 一個`STR` |
| `ROUT{INT,INT}:BOOL` | 兩個`INT` | `BOOL` |

`ITER{...}` 用在疊代器上，也是同樣的概念。

## call

`call` 提供其餘的引數。不回傳任何值的綁定常式，呼叫方式相同，只是寫成一個敘述。

## bind 要放在賦值式的右邊

一個 `bind` 可以宣告到變數裡，也可以當成引數傳入：

```sather
   part ::= bind(shout(_));                -- yes
   part : ROUT{STR}:STR := bind(shout(_)); -- yes
   rehearse("line", bind(shout(_)));       -- yes
```

但不能直接放進 `return`：

```sather
   return bind(shout(_));                  -- does not parse
```

請先放進變數，再回傳那個變數。錯誤訊息會指向 `bind`，並提到底線，而這點從那一行本身並不容易看出來。

## 使用時機

只要是需要提供行為的地方，函式庫都會採用它們：

```sather
   names.sort_by(bind(shorter(_, _)));
   scores.count_if(bind(over(10, _)));
   scores.find_if(bind(is_even(_)));
```

排序是最清楚的例子：`sort_by` 懂得怎麼排序，卻對你心中認定的順序一無所知，而綁定常式正是兩者接合的地方。

## 這個編譯器的限制

Sather 1.2 並未實作**分派式**的綁定常式，也就是把常式綁定到抽象型別的變數上。編譯器明白地這麼說：

```
Dispatched bound routines are not implemented yet
```

把常式綁定在具體型別或類別上，一切就沒問題。這也是為什麼這個 track 自己的測試框架，會用手工寫出例外檢查，而不是採用綁定常式。

## 綁定常式還是抽象類別？

兩者都能讓呼叫方提供行為。

綁定常式只是一段常式，不需要類別，而且就寫在使用它的地方。抽象類別則帶有多段常式和一些狀態，當要提供的東西包含多個部分時，才值得這些額外的手續。

只要交出一段常式，就用 bind 綁定它。若要交出的是包含多個部分的合作對象，就寫一個類別。
