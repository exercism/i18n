# 簡介

智慧指標是 C++ 的現代功能，旨在提供自動記憶體管理，協助避免裸指標常見的記憶體洩漏與懸空指標問題。
它們是裸指標的包裝，額外提供一些功能，例如在指標不再需要時自動釋放記憶體。

## 一般語法

智慧指標在 C++ 標準函式庫中通常以類別樣板實作。
最常用的兩種智慧指標是`std::unique_ptr`和`std::shared_ptr`。

## 獨佔指標

`std::unique_ptr`是一種獨佔擁有物件的智慧指標。
它確保在任何時間點，都只有一個`std::unique_ptr`物件擁有該資源。
當持有資源的`std::unique_ptr`被銷毀或重置時，它會自動解構物件並釋放其記憶體。

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## `std::make_unique()`的優點

建立`std::unique_ptr`時，最好使用`std::make_unique()`，而不是直接用`new`配置記憶體。
`std::make_unique()`提供了幾項優點：
1. **例外安全**：`std::make_unique()`保證例外安全。
  如果在建構物件期間拋出例外，記憶體會自動被釋放，避免記憶體洩漏。
2. **清晰**：使用`std::make_unique()`讓程式碼更清晰、更精簡。
  它不需要明確指定要配置的型別，因為樣板引數會自動推導。
3. **最佳化機會**：比起手動用`new`配置記憶體，編譯器有機會更有效地最佳化`std::make_unique()`，可能帶來更好的效能。
4. **避免誤用**：手動建構`std::unique_ptr`時，有可能會刪除底層資源。
  當`std::unique_ptr`在作用域結束時嘗試刪除它，就會導致未定義行為。

## 共享指標

`std::shared_ptr`是一種智慧指標，允許多個`std::shared_ptr`物件共享同一個資源的擁有權。
它會追蹤有多少共享指標參考該資源，只有在最後一個擁有該資源的共享指標離開作用域或被重置時，才會釋放記憶體。

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
在 C++17 及之前的版本，不直接支援透過`std::make_shared<T[]>`將`std::shared_ptr`用於陣列。
雖然可以用`std::make_shared<T[]>`配置陣列，但直接從它們建立共享指標，可能會因為單一物件與陣列在記憶體管理上的差異而導致未定義行為。
建議改用`std::vector`或自訂的刪除函式，來有效地以共享指標管理陣列。
在 C++17 中處理陣列配置與共享指標時，請務必確認與你的編譯器及標準函式庫實作相容。
~~~~

## `std::make_shared()`的優點

與`std::make_unique()`類似，`std::make_shared()`也帶來更好的記憶體效率、例外安全與可讀性等優點。
它將控制區塊與受管理物件的記憶體配置合併為單一操作，提升效率並降低記憶體洩漏的風險。
此外，樣板引數的自動推導讓程式碼更簡單，也提升了可讀性。
在 C++ 中使用`std::shared_ptr`物件時，改用`std::make_shared()`能讓程式碼更簡潔、更安全、更有效率。

## 弱指標

`std::weak_ptr`是搭配`std::shared_ptr`的類別，提供對共享指標所管理之物件的非擁有「弱」參考。

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

在需要打破循環參考以避免記憶體洩漏的情境中，弱指標很有用。
`std::weak_ptr`的設計是為了解決循環擁有的問題，也就是所謂的循環參考，這種情況可能在使用`std::shared_ptr`時發生。
在循環擁有的情境中，兩個或更多`std::shared_ptr`物件互相參考，形成一個循環，其中沒有任何物件能被刪除，因為它們彼此之間有強參考，進而導致記憶體洩漏。
`std::weak_ptr`為這個問題提供了解法：它允許對共享物件建立弱參考，而不會增加其參考計數。
這表示它可以觀察並存取共享物件，但不會阻止該物件被刪除。
~~~~

## 使用建議

預設請使用智慧指標：以`std::unique_ptr`表示獨佔擁有，以`std::shared_ptr`表示共享擁有。
將裸指標保留給非擁有的參考，或與舊有程式碼介接時使用。
大多數情況下，`std::unique_ptr`就足以處理獨佔擁有，因為它提供輕量的記憶體管理，沒有參考計數的額外負擔。
`std::shared_ptr`應謹慎使用，因為除非確實需要共享擁有，否則它會帶來額外負擔與複雜度。
`std::weak_ptr`專門用於打破循環相依或觀察共享物件，但並不常使用。
