# 關於

你很難遇到完全不使用命名空間的正式環境程式碼。

以下是語法的範例：

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

命名空間是用來群組相關程式碼、避免名稱衝突的方式。

根據[官方文件][namespaces]，命名空間有兩個主要用途：

- 第一，.NET 使用命名空間來組織它為數眾多的類別
- 第二，在較大型的程式設計專案中，宣告自己的命名空間有助於你控制類別與方法名稱的作用域。

基底類別庫（BCL）廣泛使用命名空間來組織它的功能。

## 參照命名空間中的型別

要從命名空間外部參照命名空間內的型別時，會在型別名稱前面加上點號語法。另一種做法（通常也更常見）是在檔案最上方（或命名空間內）放一個 `using` 指示詞，這樣一來，匯入的命名空間中的任何型別都能在省略前置詞的情況下使用。在同一個命名空間內，則不需要完整限定型別名稱。

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

這篇[文章][using]清楚地說明了 `using` 指示詞的各種用法：

- `using`：避免每次都要用命名空間限定型別
- `using static`：避免每次都要用型別限定成員（`Math.Max()` 就是個好例子）。
- `using MyAlias = YourNamespace;`：用更好讀的名稱來代替命名空間名稱。

## 命名空間衝突

不同組件中若有兩個同名命名空間，就可能導致完整限定識別碼名稱衝突（例如載入了同一個組件的多個版本），.NET 處理了這個問題。這個問題可透過[命名空間別名限定符][namespace-alias-qualifier]和 [extern alias][extern-alias] 來解決。

之所以提到這個相當冷門的主題，其中一個原因是它用到了 [`::` 運算子][dot-dot-operator]。你經常會看到限定符 `global::` 加在命名空間前面，特別是在產生的程式碼中。這麼做的用意是避免與某個巢狀命名空間或類別名稱產生潛在衝突。在命名空間前面加上 `global::`，就能確保選取的是最上層的命名空間。

## 給 Java 開發者的提醒

在與 Java `packages`的`import`相比較時，有些差異和相似之處值得注意：

- C# 沒有匯入特定型別的對等做法。
- `using static`和`import static`是對等的。
- 在 Java 中，套件名稱在 jar 之間會影響存取範圍。在 C# 中，組件才是關鍵，而且隸屬於同一個命名空間並不會影響存取層級。
- Java 中檔案系統路徑與完整限定類別名稱之間的關係，並未反映在 C# 的命名空間中，不過在情況允許時，讓檔名與其中主要類別的名稱一致仍是個好習慣。
