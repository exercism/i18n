# 貢獻概念與概念練習

[概念練習][product-concept]的目標是教授特定程式語言中的單一概念。它應該有明確的學習目標，並提供足夠的樣板程式碼，讓學生不必學習用不到的程式碼。相關的概念有自己的文件，獨立於概念練習之外。概念可以其他概念作為先修，並且在完成先修概念的概念練習之前保持鎖定。概念練習的難度不應隨著學習軌道推進而增加。任何熟悉先修概念的開發者，都應該能在 5 到 10 分鐘內解出一個概念練習。

現在我們已經了解什麼是概念練習，接著就來詳細說明如何實作一個概念練習，以及與它相關的概念。供參考，[概念練習的詳細規格][concept-exercise-spec]與[概念的詳細規格][concept-spec]都放在 exercism 的 [docs 儲存庫][docs-repo]中。本文件彙整了許多資源的資訊，作為貢獻概念練習的逐步指南。

## 1. 找出尚未實作的概念

## 2. 定義學習目標

了解一個概念練習想教什麼、哪些內容不在範圍內，是很重要的，所以我們先來建立第一個檔案：`exercises/concept/<story-name>/.meta/design.md`。由於概念練習是以所使用的故事命名，我們現在還不知道故事名稱，所以先保留`story-name`，之後再替換。[`design.md` 規格][design-spec]指出，這份文件應定義練習的整體目標、多項學習目標、不在範圍內的內容、它所解鎖的相關概念，以及完成該練習所需的先修概念。你可以用[布林概念練習的`design.md`][design-bool]作為範本的起點。

## 3. 為練習撰寫概念簡介

學習目標明確之後，就可以開始撰寫簡介，說明足夠的概念內容，讓學生能接著解出練習。建立一個檔案`exercises/concept/<story-name>/.docs/introduction.md`。這個檔案的詳細內容說明在[它的規格][exercise-intro-spec]中。你可以用[布林概念練習的`introduction.md`][intro-bool]作為範本的起點。

提供的資訊應該恰好足以介紹概念，讓學生能自己找出練習的解法。使用正確的技術術語，方便學生在網路上搜尋。盡量避免使用連結，改成在行文中簡潔地說明。用程式區塊介紹程式語法。

## 4. 為練習尋找故事

每個概念練習都必須以一個故事或主題為基礎。我們知道 Exercism 在全球被使用，所以盡量讓這些故事具有包容性。第一個選項是重複使用 [docs 中記錄的故事清單][stories]裡已有的故事。如果你想建立新故事，別猶豫，在 PR 中 tag @exercism/leadership。現在你可以把`exercises/concept/<story-name>/`目錄重新命名，以符合你的故事。

## 5. 撰寫練習指示

找到故事之後，我們必須寫出明確的指示，逐一列出學生需要完成的任務。故事和指示都寫在`exercises/concept/<story-name>/.docs/instructions.md`文件中。如[該文件的規格][instructions-spec]所述，每個任務都有自己的二級 Markdown 標題（`## 1. Do X`），後面接著說明和程式碼使用範例。你可以用[布林概念練習的`instructions.md`][instructions-bool]作為範本的起點。

除了`instructions.md`，我們還需要一個`hints.md`檔案。它應該包含和指示檔相同的二級標題（`## 1. Do X`），這樣就能根據學生目前正在進行的任務，給出正確的提示。也可以有一個`## General`區段，用來放適用於所有任務的提示。提示不應該直接寫出解法。另外要注意，會點開提示的人，可能已經對這個練習感到困惑、不知所措或挫折。關於這份文件的更多資訊請見[它的規格][hints-spec]，你也可以用[布林概念練習的`hints.md`][hints-bool]作為範本的起點。

## 6. 開一個草稿 pull request 來驗證設計

現在正是為你的概念練習開一個草稿 pull request 的好時機！我們已經有足夠的材料可以評估這個練習，必要時也能在依目前狀態寫完其餘必要檔案之前先重新調整。如果 CI 的自動檢查因為缺少文件而失敗，別擔心，我們之後會建立它們！

## 7. 撰寫程式碼

我們會先像在解這個練習一樣撰寫程式碼，之後再移動檔案，以符合規格。首先，把[`template/`][template]目錄的內容複製到我們的`exercises/concept/<story-name>/`目錄裡。這樣我們會有下列檔案：

```txt
elm.json           # elm project configuration file
src/Exercise.elm   # code for the exercise
tests/Tests.elm    # tests for the exercise
```

接著把`Exercise.elm`重新命名，改用故事名稱的 PascalCase。例如，`annalyns-infiltration`會變成`AnnalynsInfiltration.elm`。在這個原始碼檔案裡，你現在可以撰寫我們剛才在`instructions.md`中描述的所有函式。

練習實作完成後，更新`tests/Tests.elm`的內容，加入相關測試，並讓測試自然依照`instructions.md`中任務的順序排列。在概念練習的測試中，**請避免使用`Fuzz`**，因為它和用`Debug.log`除錯的能力搭配得不好。改成加入一些邊界情況和一般情況的單元測試。在概念練習的測試中，**請避免直接在`test`或`describe`函式呼叫底下使用`let`運算式**，因為 [elm 測試執行器目前還不支援這種寫法](https://github.com/exercism/elm-test-runner/issues/30)。

等到練習和測試都完成並運作正常後，請做下列幾件事：

- 把`src/<ExerciseSlug>.elm`複製到`.meta/Exemplar.elm`。你的實作會作為這個練習的參考，也就是「範例」實作，在執行學習軌道測試時會用到。
- 移除`src/<ExerciseSlug>.elm`裡所有的實作，只留下讓學生可以開始解練習的起始檔案。

## 8. 撰寫概念文件

為我們的`exercises/concept/<story-name>`練習所相關的概念，建立一個`concepts/<concept>/`目錄。在這個新資料夾裡，我們建立兩個 Markdown 文件 [`introduction.md`][concept-intro-spec] 和 [`about.md`][concept-about-spec]，以及一個 [`links.json`][concept-links-spec] 檔案（連結會連到它們的規格）。

`introduction.md`概念檔包含學生在尚未完成相關概念練習之前，會在概念頁面上看到的介紹。它應該讓學生大致了解，如果開始相關練習會學到什麼。相對地，`about.md`概念檔包含學生只有在完成相關概念練習之後，才會在概念頁面上看到的概念摘要。因此，它們的內容和我們已經寫好的`exercises/concept/<story-name>/.docs/introduction.md`檔案相似，但不完全相同。我建議從練習的簡介文件開始，把它精簡到最核心的部分，作為概念的`introduction.md`。至於`about.md`，則從練習簡介開始，並補齊內容，讓所有和這個概念相關的資訊都出現在該頁面上。`links.json`提供實用的連結，內含關於某個概念的額外資訊。這些可能是官方文件、很棒的教學等等。這些連結不會取代概念 about.md 檔案中更具情境性的連結，而是為學生提供一組快速的整體參考。連結也可以選擇性地帶有 icon_url 欄位，用來自訂連結顯示時所顯示的圖示。如果沒有指定，圖示會預設為 favicon。你可以在 [github.com/exercism/website-icons/tree/main/exercises][icons] 找到可用的圖示。

## 9. 完成各個設定檔

程式碼和文件都完成之後，還剩下幾個設定檔要處理，才能讓這個 PR 完整：

- [`concepts/<concept>/.meta/config.json`][concept-config-json]：把自己設為作者、把可能的審閱者設為貢獻者，並加上一段「blurb」（簡短描述）。
- [`exercises/concept/<story-name>/.meta/config.json`][exercise-config-json]：包含作者（你）、貢獻者、blurb 和其他內容。請參考連結的規格。
- `config.json`：在學習軌道的`config.json`檔案中加入一個[概念項目][track-config-json-concept]和一個[概念練習項目][track-config-json-concept-exercise]。概念練習的 status 鍵請使用「wip」或「beta」。UUID 可以用 exercism 提供的 [configlet 執行檔][configlet] 產生。

## 10. 謝謝你！

感謝你對 exercism 的貢獻，你太棒了！
