# 指令與引數入門

這個學習軌道要談的不是如何把 bash 當成互動式 shell 來使用。
而是要學習用 bash 這個程式語言來寫程式。

bash 程式，也就是_腳本_，是一連串存放在檔案裡的指令。
bash（執行檔本身）會讀取這個檔案，並依序執行這些指令。

## Shebang

腳本的第一行通常是_翻譯員指示_，也稱為 _hashbang_ 或 _shebang_：

```bash
#!/usr/bin/env bash
```

當作業系統執行_非二進位檔案_時，會先讀取檔案的第一行。
如果這一行以`#!`開頭，核心就會根據它來決定要用哪個翻譯員執行這個檔案。
`#!`必須位在檔案最開頭，前面不能有空格或空行。

這裡`env`會在`PATH`裡尋找`bash`執行檔。
你也可能看過更簡單的`#!/bin/bash`，它把翻譯員的位置寫死在裡面；`env`這種寫法的可攜性比較好。

~~~~exercism/note
網路上有些腳本或範例會用`/bin/sh`當作翻譯員，請不要被它們騙了。
**`sh`不是`bash`！**
Bash 本身「相容於 sh」，可以執行大多數`sh`腳本，但有些 bash 功能在`sh`裡會壞掉，或出現非預期的行為。
~~~~

## 註解

以`#`開頭的那一行是_註解_，bash 會忽略它。
註解也可以接在同一行指令的後面：從`#`到該行結尾的內容都會被忽略。
註解是寫給讀腳本的人看的。

## 詞與引數

Bash 會從它的輸入讀取指令（輸入通常是終端機或檔案）。
它讀進來的每一行都會被當成一條_指令_，也就是一個要被執行的指示。
（有少數進階情況，例如跨越多行的指令，之後會再討論。）

Bash 會把每一條指令切成以空白字元（空格與 Tab）分隔的**詞**。
第一個詞就是要執行的_指令_名稱。
其餘的詞都會成為該指令的_引數_（選項、檔案名稱等）。

指令可以是 bash 的_內建指令_，例如`echo`，也可以是_執行檔_程式，例如`head`、`awk`或`sed`。

## `echo`指令

`echo`會印出它的引數，引數之間以一個空格分隔，最後再換行：

```bash
echo flour sugar eggs
```

會輸出：

```text
flour sugar eggs
```

引數之間有多少空白都不重要：

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

不帶任何引數呼叫`echo`時，會印出一行空白。

## 選項也只是引數

許多指令都接受能改變行為的_選項_。
對 bash 來說，選項沒什麼特別：它就是一個普通的詞，和相鄰的詞一樣用空白隔開。
至於要怎麼解讀引數，是由指令本身決定的。
依照慣例，選項會以`-`開頭。

`head`指令會印出檔案的前幾行。
假設有一個檔案`list.txt`：

```bash
head -n 2 list.txt
```

Bash 會把這一行切成四個詞：

| 詞 | 角色 |
| ---------- | ------------------------------------------- |
| `head`     | 要執行的指令 |
| `-n`       | 告訴`head`要計算_行_數的選項 |
| `2`        | `-n`選項的值 |
| `list.txt` | 要讀取的檔案 |

Bash 會把最後三個詞原封不動地交給`head`。
是`head`自己知道`-n`後面要接一個數字，而剩下的那個詞是一個檔案。

因為詞是靠空白分隔的，所以空白放在哪裡就有差別。
`head -n 2`會給`head`兩個引數（`-n`和`2`），而`head -n2`只給它一個（`-n2`）。
許多指令兩種寫法都接受，但這要由指令本身決定。
Bash 並不在意；它只負責把這一行切成一個一個的詞。

## 為引數加上引號

[引號][Quotes] 會把多個詞集合成_單一引數_。
引號內的空白會保留下來，而引號字元本身不算引數的一部分：

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

如果某個引數（例如檔案名稱）含有空白，就要用引號括起來：

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## 執行腳本

要執行腳本，就把它當成引數傳給`bash`指令：

```bash
bash myscript
```

這樣使用時，`#!`這一行就只是註解。
你是在告訴作業系統該怎麼執行這個檔案。

另一種做法是把腳本檔案標記為可執行，然後像執行其他程式一樣執行它：

```bash
chmod +x myscript
./myscript
```

這麼一來，作業系統就會用`#!`這一行來決定要用哪個翻譯員。
