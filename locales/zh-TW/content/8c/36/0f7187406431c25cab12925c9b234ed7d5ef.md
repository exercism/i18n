## 共變與逆變

使用聯合型別時，你必須留意共變與逆變這兩個概念。[文件](https://www.php.net/manual/en/language.oop5.variance.php)中有說明，不過這些範例或許有幫助。

假設我們有一個 Calculator 類別，使用像上面範例那樣的函式：

```php
class Calculator
{
    public function add(int|float $x, int|float $y): int|float
    {
        return $x + $y;
    }
}
```

如果你要擴充這個類別，可以變更參數型別和回傳型別，但必須遵守下列規則。

首先，參數型別可以更「寬」，也就是能接受比基底類別更多的型別。例如下面這樣是允許的：

```php
class StringCalc extends Foo
{
    public function add(float|int|string $x, float|int|string $y): int|float
    {
        if (!is_numeric($x) || !is_numeric($y)) {
            throw new \InvalidArgumentException('$x and $y must be numeric');
        }
        return $x + $y;
    }
}
```

我們可以用`StringCalc`取代原本的`Calculator`，一切仍然能正常運作。呼叫端仍然可以傳入原本就能傳的`float`或`int`，回傳型別也仍然是預期的`int`或`float`。

同樣地，你也可以縮小回傳型別，也就是從聯合型別中移除某些型別，讓它更明確。下面這個範例就運用了這項規則：

```php
class IntCalc extends Calculator
{
    public function add(float|int $x, float|int $y) : int
    {
        return (int)($x + $y);
    }
}
```

由於`IntCalc`仍然接受`int`和`float`，它可以毫無問題地取代原本的`Calculator`。

如果想進一步了解哪些寫法可以、哪些不行，可以參考[里氏替換原則（LSP）](https://en.wikipedia.org/wiki/Liskov_substitution_principle)。

想看一個不被允許的例子，請看看下面的`InvalidCalc`：

```php
class InvalidCalc extends Calculator
{
    public function add(int $x, int $y) : int|float|string
    {
        // Declaration must be compatible with Calculator->add(x: float|int, y: float|int)

        // Return type declaration must be compatible with Calculator->add(x: float|int, y: float|int) : float|int
    }
}
```

`InvalidCalc`類別無法編譯，而且有兩個問題。由於縮減了參數允許的型別，`InvalidCalc`無法取代原本的`Calculator`，因為它不再接受`float`。此外，它現在可以回傳`string`，這也不在原本類別允許的回傳型別之內。
