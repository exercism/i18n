# 提示

## 一般

- `movapd`和`movaps`只應該在已知記憶體運算元已對齊時使用。當兩個運算元都是`xmm`暫存器時，使用它們是安全的。
- 記憶體位址是以整數值傳遞的。前六個整數引數會分別透過`rdi`、`rsi`、`rdx`、`rcx`、`r8`和`r9`傳入函式。

## 1. 合併兩條產線的產出

- 32 位元浮點數的封裝加法是`addps`。
- 三個指標引數都保證是 16 位元組對齊的，因此適合使用對齊版本的搬移指令`movaps`。

## 2. 計算縮放後的偏差

- 64 位元浮點數的封裝減法是`subpd`。
- 64 位元浮點數的封裝乘法是`mulpd`。
- `measured`已對齊，而`target`未對齊，因此它們需要不同的載入變體。

## 3. 校準一批資料

- `reference`和`offset`都已對齊，`raw`則未對齊，因此它們需要不同的載入變體。
- 兩列都需要`reference`和`offset`。
- 雙運算元指令通常會覆寫其目的運算元。
- 若要將`raw`的高 2 個浮點數轉換成倍精度浮點數，請使用`cvtps2pd`，並搭配相對於 raw 指標位移 8 位元組的記憶體運算元。
- 轉換係數應該以 2 個 64 位元浮點數的形式儲存在記憶體中（兩者都等於`0.5`）。
- 結果涵蓋 32 位元組（4 個 64 位元浮點數）：前 16 位元組位於`[result]`，接下來 16 位元組位於`[result + 16]`。

## 4. 將一條產線上的分數正規化

- 雙運算元指令通常會覆寫其目的運算元。
- 記憶體不能作為算術封裝指令的目的運算元。
- 對於`scores`陣列（第一個引數）中的每個 64 位元浮點數`score`，在`gains`陣列（第二個引數）中都有一個對應的`gain`。每個`score`會與相同位置的`gain`進行運算。
- 第三個引數是固定的`scale`，其中包含 2 個封裝的 64 位元浮點數。
- 對於每一對`score`和`gain`，函式會計算`score * gain / scale_lane`。`scale`中的第一個通道負責縮放每一對的第一個元素（位於偶數位置的通道），第二個通道則縮放第二個元素（位於奇數位置的通道）。
- 正規化後的分數會就地儲存在`scores`陣列中，位置與其輸入`score`相同。
- `scores`和`gains`中的元素數量相同，且等於`n`的值（第四個引數）。
- 你應該使用迴圈來處理所有元素對，每次疊代前進 16 位元組（2 個元素）。
