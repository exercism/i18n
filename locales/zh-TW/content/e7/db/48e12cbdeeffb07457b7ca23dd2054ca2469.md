# 介紹

在 C++ 中，宣告與定義通常是分開的。
宣告會被集中到所謂的標頭檔裡，而對應的實作則放在原始檔中。
你可以把標頭檔想成是一份 API。
標頭檔會告訴你一個程式碼庫提供了_什麼_，而不會深入說明_如何_實作。

## 標頭檔與原始檔

標頭檔最常見的副檔名是`.h`。
有些專案會使用`.hpp`，或是乾脆完全省略副檔名。

定義則位於另一個`.cpp`檔案中。
為了把這兩個部分重新結合，原始檔開頭會先_引入_對應的標頭檔。

如果你想寫一個叫做「quick_math」的函式庫，提供一個你經常想使用的「super_root」函式，檔案會長得像這樣：

```cpp
// A file named quick_math.h
#pragma once
namespace quick_math {
    double super_root(double x, int n);
}
```

```cpp
// A file named quick_math.cpp
#include "quick_math.h"
#include <cmath>
double quick_math::super_root(double x, int n) {
    while(n) { x = std::sqrt(x), --n;}
    return x;
}
```

如果你需要引入的標頭檔只有實作會用到，那麼對應的`#include`那一行只需要放在原始檔裡。
凡是標頭檔引入的內容，在`.cpp`檔案裡也都能使用，例如下面範例中的`string`函式庫。
**注意**：標頭檔中的宣告後面需要加上`;`，但原始檔中的定義後面則不需要。

## 類別與標頭檔

類別可以變得非常複雜，它們與標頭檔／原始檔分工之間的關係也可能讓人困惑。
一種可能的安排方式，是把所有實作細節留在原始檔，並把所有宣告和成員變數放在標頭檔：

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0);
            void give_water();
            std::string get_name();
            int get_size();
            void start_next_day();
    };
}
#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"
robots::Flower::Flower(std::string name, int size) {this->name = "Robotica " + name; this->size = size;}
void robots::Flower::start_next_day() {if (!needs_water) ++size; needs_water = true;}
std::string robots::Flower::get_name() {return name;}
int robots::Flower::get_size() {return size;}
```

當標頭檔被當成 API 總覽使用時，人們會在那裡尋找預設值這類資訊。
因此，建構函式`size`參數的預設值是在標頭檔裡處理，而不是在實作裡。
原始檔中的定義前面會冠上命名空間`robots`和類別型別`Flower`。

另一種安排方式是_僅有標頭檔_的函式庫，完全沒有`.cpp`檔案：

```cpp
// A file named robot_flower.h
#pragma once
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0) {this->name = "Robotica " + name; this->size = size;}
            void give_water() {needs_water = false;}
            std::string get_name() {return name;}
            int get_size() {return size;}
            void start_next_day() {if (!needs_water) ++size; needs_water = true;}
    };
}
```

專案可能會混合使用這幾種安排方式，而哪一種最適合各種使用情境，則有許多討論。

## 引入防護

你可能已經注意到上面範例標頭檔中的`#pragma once`那一行。
這叫做引入防護，它能確保檔案內容在編譯過程中只被引入一次，以避免錯誤。
還有一種更複雜的引入防護寫法，以`#ifndef`開頭，並以`#endif`結尾。
它的用途相同，用法也展示在上面的`Flower`類別範例中。
