# 提示

## 一般

這個練習有許多可能的解法，也有許多你可以走的路。沒有哪條路明顯「更好」，不過某條路可能更有趣，或更適合你現在想學或想探索的東西。有些路會犧牲速度換取清晰，有些則可能佔用更多記憶體，但更具擴展性或更好維護。我們鼓勵你多試幾種策略，看看會發生什麼事。

_______
-  Python 有許多處理字串的強大工具。[`str.split`][str.split]、[`str.replace`][str.replace]、[`str.lower`][str.lower] 和 [`str.strip`][str.strip] 在這道挑戰中特別有用。
-  字串方法可以串接在一起（_只要該方法回傳的是 `str`_））
-  `str.split()` 非常_特定_，而 `str.strip()` 的行為不同，還允許更多種組合。
-  [`string`][string] 模組（與 `str` 不同）有一些常數，在處理字串時可以用來篩選和比較。
________

-  [字典][dict] 有助於統計某個項目（鍵）在字串中出現多次的情況。
-  當字典中可能缺少某個鍵時，[`dict.setdefault()`][dict.setdefault] 可以在處理時派上用場。
-  [Collections][collections] 模組為核心的 `dict`（字典）實作了一些非常實用的子型別，專門用來做像[計數][collections.counter]這類的事。
________
-  探索 [`re`][re] 模組和正規表達式可能很有趣，但絕不是解這道挑戰所必需的。
-  [Regex101][regex101] 對實驗正規表達式的邏輯非常有幫助。
-  [`re.sub`][re.sub] 和 [`re.findall`][re.findall] 都是可以採用的有趣策略。
________
-  [推導式][comprehensions] 常常可以「攤平」那些把項目附加到陣列或插入字典的迴圈。
-  當需要可疊代物件時，[產生器運算式][generator expressions] 常常可以「代替」列表推導式。
  產生器運算式以「惰性」方式求值，佔用的記憶體空間比對應的列表推導式更少。
