# 測試產生器

測試產生器讓 track 能自動產生測試，不需要我們自己動手撰寫。每個測試產生器都會讀取該練習的`canonical data`，其中定義了測試的名稱、輸入與輸出。想進一步了解 Exercism 對測試套件的做法，可以看[這裡](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md)。

自動產生測試可以避免建立測試時出現任何人為失誤。我們希望測試能準確對應 canonical data。自動產生測試也讓測試更容易保持最新：當 canonical data 變更時，只要執行對應的產生器，測試就會自動更新。

canonical data 檔案的範例可以在[這裡](https://github.com/exercism/problem-specifications/blob/master/exercises/bob/canonical-data.json)找到。

## 常見術語

在瀏覽 canonical data 和產生器的程式碼時，我們會用到許多共通的術語。以下清單希望能釐清它們各自代表什麼。

* Canonical Data：代表整個測試套件。
* Canonical Data Case：代表單一的測試案例。
* Description：測試的名稱。
* Property：執行測試時要呼叫的方法。
* Input：測試案例的輸入。
* Expected：執行測試案例時預期的值。

## 新增簡單的產生器

新增測試產生器很簡單。只要在 `generators` 資料夾的 `Generators.fs` 檔案中，加入一個以該練習名稱（PascalCase）命名的類別，並繼承 `GeneratorExercise` 抽象類別即可。

Bob 練習就是一個簡單產生器的例子。原始程式碼如下，你也可以在儲存庫的[這裡](https://github.com/exercism/fsharp/blob/master/generators/Generators.fs#L174)看到它。

```fsharp
type Bob() =
    inherit GeneratorExercise()
```

這是一個能完整運作的產生器，不需要再寫其他程式碼。不過它之所以這麼簡單，是因為它的測試套件和程式本身都相對單純。

## 新增複雜的產生器

對許多產生器來說，`GeneratorExercise` 類別的預設行為就已經足夠。但對於更複雜的產生器，可以覆寫它的一或多個虛擬方法：

### 方法：RenderInput

產生測試方法的輸入。

#### 範例

`Gigasecond` 產生器會把輸入值產生為加上括號的 `DateTime` 值：

```fsharp
override __.RenderInput (_, _, value) =
    DateTime.Parse(string value, CultureInfo.InvariantCulture)
    |> DateTime.renderParenthesized
```

請注意，你可以用 `key` 欄位，只針對特定的輸入欄位自訂輸出。`Yacht` 產生器就是這麼做的：

```fsharp
override __.RenderInput (canonicalDataCase, key, value) =
    match key with
    | "category" -> Obj.renderEnum "Category" value
    | _ -> base.RenderInput (canonicalDataCase, key, value)
```

### 方法：RenderExpected

產生測試方法預期的值。

#### 範例

`Connect` 產生器會把預期的值產生為 `Option<T>` 值：

```fsharp
override __.RenderExpected (canonicalDataCase, key, value) =
    match string value with
    | "O" -> "(Some White)"
    | "X" -> "(Some Black)"
    | _   -> "None"
```

### 方法：RenderSut

產生待測系統（System Under Test，SUT）。這是實際用來與預期值比對的值。

#### 範例

`RunLengthEncoding` 產生器有一個測試案例，會驗證先編碼再解碼輸入後，是否得到相同的值。這裡覆寫 `RenderSut` 方法，把原本會是單次呼叫一個不存在的 `consistency` 函式，改成一連串的 `encode |> decode` 呼叫：

```fsharp
override this.RenderSut canonicalDataCase =
    match canonicalDataCase.Property with
    | "consistency" ->
        let parameters = this.RenderSutParameters canonicalDataCase |> String.concat " "
        sprintf "%s |> encode |> decode" parameters
    | _ ->
        base.RenderSut canonicalDataCase
```

### 方法：RenderArrange

產生測試方法中安排的部分。這個部分會建立 SUT。

預設行為通常就是你要的。只有在非常特殊的情況下，才會想改動它。

注意：這個方法會回傳 `string list`，其中每個 `string` 對應到測試檔案中一行產生出來的程式碼。

### 方法：RenderAssert

產生測試方法中斷言的部分。這個部分會進行斷言，驗證 SUT 是否符合預期值。

預設行為通常就是你要的。只有在非常特殊的情況下，才會想改動它。

注意：這個方法會回傳 `string list`，其中每個 `string` 對應到測試檔案中一行產生出來的程式碼。

### 方法：RenderSetup

產生任何額外的工具方法或設定方法。這可以用來定義測試方法中可以使用的輔助方法。

設定程式碼會加在測試方法之前，這樣測試方法就能使用這些設定方法。

注意：這個方法會回傳 `string list`，其中每個 `string` 對應到測試檔案中一行產生出來的程式碼。

#### 範例

`Zipper` 產生器新增了兩個輔助方法，讓測試方法可以用來省去一些繁瑣的樣板程式碼：

```fsharp
override __.RenderSetup _ =
    [ "let subTree value left right = Some (tree value left right)"
      "let leaf value = subTree value None None" ]
    |> String.concat "\n"
```

### 方法：RenderValue

產生單一個值（用來產生輸入參數、預期值和 SUT）。

### 範例

`ComplexNumbers` 產生器會根據值的型別產生不同的值：

```fsharp
override __.PropertiesWithIdentifier canonicalDataCase =
    match canonicalDataCase.Expected.Type with
    | JTokenType.Array -> ["sut"]
    | _ -> base.PropertiesWithIdentifier canonicalDataCase
```

### 方法：MapCanonicalDataCase

對應 canonical data case。如果你想新增或移除屬性，這會很有用。

預設行為通常就是你要的。只有在非常特殊的情況下，才會想改動它。

#### 範例

`ScaleGenerator` 產生器利用 canonical data case 的對應，把缺少的屬性補上 `null` 值（方便後續處理）：

```fsharp
override __.MapCanonicalDataCase canonicalDataCase =
    let input = canonicalDataCase.Input
    match Map.tryFind "intervals" input with
    | Some _ -> canonicalDataCase
    | None   -> { canonicalDataCase with Input = Map.add "intervals" null input }
```

### 方法：PropertiesUsedAsSutParameter

指定哪些屬性應該做為 SUT 的參數。

預設行為通常就是你要的。只有在非常特殊的情況下，才會想改動它。

#### 範例

`RailFenceCipher` 明確指定做為 SUT 參數的屬性，以改變它們的傳遞順序：

```fsharp
override __.PropertiesUsedAsSutParameter _ = ["rails"; "msg"]
```

### 方法：PropertiesWithIdentifier

指定哪些屬性應該被指派識別碼。如果某個屬性出現在這份清單中，它的值會被指派到獨立的一行，使用自己的識別碼。

#### 範例

`Transpose` 產生器選擇為所有屬性使用識別碼：

```fsharp
override this.PropertiesWithIdentifier canonicalDataCase = this.Properties canonicalDataCase
```

### 方法：IdentifierTypeAnnotation

在某些情況下，你會希望識別碼有明確的型別。常見的用法是當值是空陣列時。這種情況下，FsUnit 需要型別標註才能成功執行斷言。

#### 範例

`Minesweeper` 產生器會為空值加上 `string list` 型別標註：

```fsharp
override __.IdentifierTypeAnnotation (_, _, value) =
    match Seq.isEmpty value with
    | true  -> Some "string list"
    | false -> None
```

### 方法：AdditionalNamespaces

回傳測試檔案中要額外開啟的命名空間清單。

#### 範例

`Gigasecond` 產生器會處理 `DateTime` 實例，因此把它的命名空間加入額外命名空間的清單中：

```fsharp
override __.AdditionalNamespaces = [typeof<DateTime>.Namespace]
```

### 方法：AssertTemplate

要使用的斷言範本。你可以在 `generators/Templates/_Assert*.liquid` 找到所有斷言範本的清單。

#### 範例

`RationalNumbers` 產生器使用 `"AssertEqualWithin"` 範本，以便用特定容差檢查 double 是否相等：

```fsharp
override __.AssertTemplate canonicalDataCase =
    match canonicalDataCase.Expected.Type with
    | JTokenType.Float -> "AssertEqualWithin"
    | _ -> base.AssertTemplate(canonicalDataCase)
```

### 方法：TestFileFormat

測試檔案的格式：模組或類別。

預設行為幾乎總是你要的。只有在極少數的情況下，才會想改動它。

#### 範例

`Grep` 產生器把自己定義成測試類別，以便使用設定與清除方法：

```fsharp
override __.TestFileFormat = TestFileFormat.Class
```

### 方法：TestMethodName

指定測試方法的名稱。

預設行為通常就是你要的。只有在非常特殊的情況下，才會想改動它。

#### 範例

`Zipper` 產生器對測試方法的名稱做了一些清理：

```fsharp
override __.RenderTestMethodName canonicalDataCase =
    let testMethodName = base.RenderTestMethodName canonicalDataCase
    testMethodName.Replace("Set_", "Set ")
```

### 方法：UseFullMethodName

指出使用的測試方法名稱是否要採用完整路徑。也就是說，對於巢狀的測試案例，它會在測試方法名稱前面加上上一層的描述。

預設行為通常就是你要的。只有在可能出現多個同名測試方法的情況下，才會想改動它。

#### 方法：Signature

`KindergartenGarden` 產生器使用完整的方法名稱，避免測試方法名稱衝突：

```fsharp
override __.UseFullMethodName _ = true
```

### 方法：SkipTestMethod

指出是否應該用 `Skip = true` 屬性標記測試方法。

預設行為幾乎總是你要的。只有在極少數的情況下，才會想改動它。

#### 方法：Signature

`Markdown` 練習是重構練習，因此它所有測試應該都已經處於有效的狀態。所以它不會為任何測試方法加上 `Skip` 屬性：

```fsharp
override __.SkipTestMethod (_, _) = false
```

## 更新現有檔案

現有的練習有可能與 canonical data 不一致。你可以直接更新練習的 stub 或 example，讓它符合 canonical data，這是沒問題的！

另外，如果你發現現有的產生器或測試套件有問題，只要打開你想更新的產生器，做出修改，然後執行產生器就行了。

## 執行產生器

這個儲存庫是以 [.NET Core 2.x](https://www.microsoft.com/net/core) 撰寫的。要執行產生器，你只需要在 generators 目錄中執行以下指令：

`dotnet run`

這個指令會取用所有已定義的練習產生器，並為每個練習產生所有的測試案例。我們使用反射機制來取得所有練習，所以如果你新增了測試，執行產生器時就會自動納入。

如果你只需要執行單一產生器，可以執行以下指令：

`dotnet run -e <exercise>`

產生器執行完之後，你可以前往該練習的測試檔案，查看產生的結果。舉例來說，Bob 練習的測試套件位於：

`exercises/bob/BobTests.fs`
