# 簡介

## Let 斷言

在 Gleam 中對值進行模式配對時，我們必須確保模式能涵蓋型別中所有可能的值，否則程式碼將無法編譯。

下面這個函式應該被拒絕，因為它沒有處理陣列為空的情況：

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

在大多數 Gleam 程式裡，我們會想處理所有可能的情況；但有些程式，例如原型和臨時寫的指令碼，可能只想專注在正常路徑上，不為其他情況寫程式碼。這時就輪到 Gleam 的 `let assert` 登場了。

使用 let 斷言時，模式只需配對型別中某些可能的值；如果模式沒有配對到某個值，程式就會崩潰。用 `let assert`，我們可以把上面的函式改寫成這樣：

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam 函式庫永遠不該使用 let 斷言，因為它們可能讓程式崩潰。相反地，應該使用 `Result` 型別，讓應用程式的開發者自行決定如何處理錯誤。
