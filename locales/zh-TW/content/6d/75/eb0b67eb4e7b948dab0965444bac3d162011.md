# 簡介

在 Gleam 中對值進行模式比對時，我們必須確保每個模式都能比對到該型別所有可能的值，否則程式碼就無法編譯。

這個函式應該被拒絕，因為它沒有處理陣列為空的情況：

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

在大多數 Gleam 程式裡，我們會想處理所有可能的情況；但在某些程式（例如原型或臨時腳本）中，我們可能只想專注在順利運作的路徑上，而不為其他情況寫程式碼。這時就輪到 Gleam 的`let assert`登場了。

有了 let 斷言，模式可以只比對到型別的部分可能值；一旦模式沒有比對到對應的值，程式就會崩潰。使用 `let assert`，我們可以把上面的函式改寫成這樣：

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam 函式庫絕不應該使用 let 斷言，因為它們可能讓程式崩潰。它們應該改用`Result`型別，並讓應用程式的開發者自行決定如何處理錯誤。
