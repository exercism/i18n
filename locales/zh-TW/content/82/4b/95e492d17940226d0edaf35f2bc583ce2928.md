# 說明

活動企劃 Mika 在工作上獲得了升遷，而隨著新的職責，她開始負責活動資料庫。她很快就注意到，許多資料的儲存方式都讓人很難處理，所以你們要合力寫一支一次性的腳本，把它整理乾淨。

由於這支腳本只會執行一次，而且你對資料的結構很有把握，你覺得這裡很適合使用 Gleam 的 _let 斷言_。

## 1. 擷取錯誤

每場過去的活動都有一份清單，記錄了活動期間發生的問題。這些問題被存成 result，但它們一律都是`Error`變體。

實作`extract_error`函式，它會接受一個預期一律為`Error`的 result，並回傳其中包含的錯誤值。

```gleam
extract_error(Error("Not enough coffee"))
// -> "Not enough coffee"
```

## 2. 移除團隊前綴

團隊名稱前面被加上了「Team 」這個字，但其實並不需要。實作`remove_team_prefix`函式，從團隊名稱中移除這個前綴。

```gleam
remove_team_prefix("Team Turtle")
// -> "Turtle"
```

## 3. 拆分地區與團隊

每場活動都由一個團隊負責，而每個團隊都隸屬於一個地區。在資料庫裡，它們被存成同一個字串，並以逗號分隔。

實作`split_region_and_team`函式，把字串拆成一個由兩個字串組成的元組，一個放地區，一個放團隊。團隊名稱中的「Team 」前綴應該要被移除。

```gleam
split_region_and_team("East,Team Orange")
// -> #("East", "Orange")
```
