# 關於

手寫的組合語言充滿了重複。
同一小段指令會一再出現，變化不大，而且沒什麼抽象機制能減少這些樣板。
不只如此，用組合語言寫程式時，還得管理一些語意並不直觀的值。
這裡沒有具名參數，而且底層機制的大部分細節都得由程式設計師手動處理。

這條學習軌道所使用的組譯器 NASM 提供了一些工具，能幫助程式設計師處理這兩個問題。
這些工具在_組譯時期_執行，早在任何指令送達處理器之前。
它們會指引組譯器如何改寫原始碼文字，甚至在這段文字被轉譯成機器碼之前就完成。

其中最重要的工具是**巨集**，可以把它想成給組譯器的一份食譜。
它們會在使用的位置展開，就好像那段程式碼是親手寫在那裡一樣。

[巨集][macro]可以接受若干字面 token 當作參數，讓它們能在不同的情境中重複使用。
不過，它們不是函式：沒有`call`、沒有`ret`，也不會把控制權轉移到程式碼的另一處。

## 單行巨集

最簡單的定義方式是用`%define`為一個值或簡短的運算式取個名字：

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

組譯之前，之後出現的每個`WIDTH`都會被替換成`8`。
這種替換是文字上的替換，所以這個名字出現在哪裡就會被代換到哪裡，無論是在運算元裡，還是在另一份定義裡。

~~~~exercism/note
對於數值_常數_，請改用`equ`，而不要用`%define`。

用`%define`宣告的單行巨集只會在使用時展開，而且可以被重新指定或取消定義。
相對地，`equ`常數在定義的當下就被求值，之後永遠不會改變。
~~~~

`%define`也可以接受_具名_參數，表現得像一個小型的行內函式：

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
請把整個主體和每個參數都用括號包起來。
用`%define square(x) x*x`時，呼叫`square(1+1)`會展開成`1+1*1+1`，也就是`3`。
改成`%define square(x) ((x)*(x))`的話，同一個呼叫會展開成`((1+1)*(1+1))`，也就是`4`。
~~~~

用`%define`定義的名稱會區分大小寫。
如果想要的話，`%idefine`這個變體會讓名稱不區分大小寫。

單行巨集很適合用來為程式碼的各個部分賦予意義。
只要小心使用，就能提升可讀性，並降低打錯字的機會。
舉例來說，某個在函式裡有專門用途的暫存器，可以用它的用途來定義：

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## 多行巨集

一整段程式碼，無論有幾行，都可以用`%macro`捕捉起來，並以`%endmacro`結束。
名稱後面的數字代表這個巨集接受幾個引數，也可以是零個。
傳入引數時，引數之間以逗號（`,`）分隔：

```x86asm
%macro example_macro 0
...
%endmacro
```

多行巨集裡的引數沒有名字。
它們會依傳入的順序以`%1`、`%2`等等來表示：

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

請注意，引數必須符合巨集主體中所執行運算的語法。
這裡`mult_two eax, ecx`和`mult_two r8, r9`都能組譯成功，但`mult_two eax, cl`不行，因為`imul eax, cl`並沒有被定義。

巨集也可以接受任意數量的引數。
這要用`n-*`這種寫法，其中`n`是引數的最少數量：

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

在多行巨集裡，`%0`代表這個巨集的引數_數量_。
在可能接受任意數量引數的巨集裡，這特別有用。

### 巨集裡的標籤

如果一個巨集定義了普通的標籤，那麼它一被使用兩次就會出錯，因為那個標籤也會被定義兩次。
想在可能被呼叫多次的巨集裡使用標籤，就必須在這種標籤前面加上`%%`。
這會指示組譯器在每次展開時，給這個標籤一個不同且唯一的名稱：

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## 在組譯時期重複

可以使用[`times`][times]重複單行的程式碼區塊。
在記憶體中宣告重複的值時，這特別有用：

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

要重複多行的程式碼，則可以改用`%rep`：

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

請注意，重複次數緊接在`%rep`後面指定，並且要有`%endrep`來結束重複的區塊。

在`%rep`區塊裡使用組譯時期的計數器很常見，就像執行時期的迴圈會用計數器一樣。
雖然如我們先前所見，組譯時期的整數常數可以用`equ`宣告，但組譯時期的整數_變數_則要改用`%assign`。
和`%define`不同的是，`%assign`會立刻求值成一個數字，而且可以被重新指定：

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

前置處理器執行完之後，迴圈就消失了，只剩下四道`add`指令，其中直接內嵌了立即值`0`、`1`、`2`和`3`。
這是組譯器所做的迴圈展開：沒有計數器暫存器，也沒有分支，只有直線執行的程式碼。

`%rep`另一個常見的用途，是處理可能接受任意數量引數的巨集中的引數。
在這種情況下，`%rep`通常會搭配`%rotate`；後者會輪轉巨集中的引數，讓第二個引數變成第一個。
反覆套用`%rotate`會依序讓第三個、第四個等引數成為第一個，確保每個引數都能輪流被處理：

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## 條件式組譯

[前置處理器][preprocessor]提供了各種條件判斷。
它們會在不同路徑之間做選擇，就地展開自己的主體，但只有在條件成立時才會展開。

`%if`...`%elif`...`%else`...`%endif`會依據數值測試選出一個分支：

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef`和`%ifndef`很類似，但測的是某個名稱是否已被定義。
舉例來說，它們可以用來確保某個檔案的內容只被納入一次，即使這個檔案被多個來源引入：

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

你可能已經注意到，在這條學習軌道裡，每個`.asm`檔案的結尾都有這段程式碼：

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn`會比較兩段文字是否完全相符。
內建的`__OUTPUT_FORMAT__`會展開成目前的輸出格式，所以那段程式碼會檢查輸出格式是不是`elf64`，也就是 Linux 系統使用的格式。
如果是的話，就會在目的檔中加入一則註記，宣告堆疊應該具備的權限，這是一種常見的安全措施。
如果不是，就什麼都不會改變。

## 結構

要存取記憶體中某筆記錄的欄位，就是把該欄位的位元組位移加到基底位址上。
把這些位移寫成原始數字不但容易出錯，也掩蓋了它們的意義。
[`struc`][struc]和`endstruc`則改為替某種配置命名，把每個欄位變成在組譯時期計算出來的符號位移。

在這個區塊裡，保留指令`resb`、`resw`、`resd`和`resq`會分別保留一個或多個位元組、字組、雙字組或四字組。
在每個欄位前面加一個`.`，可以讓它的名稱限定在這個結構的範圍內：

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

現在每個欄位名稱都代表它的位移，所以`thread.color`是`0`，`thread.tension`是`4`，而`thread.name`是`12`。
NASM 也會定義`<struc>_size`做為總大小，其中`<struc>`是這個`struc`的名稱。
舉例來說，這裡的`thread_size`會是`4 + 8 + 16 = 28`。

只要把欄位的位移加到基底暫存器上就能存取該欄位，而`thread_size`則是從一筆記錄跨到下一筆的間距：

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

`struc`只描述一種形狀，本身並不會配置記憶體。
要建立一個已初始化的實例，可以在某個標籤之後使用`istruc ... iend`。
在實例裡面，`at`會把值放到指定的具名欄位：

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

請注意，`thread.name`是用`"warp", 0`初始化的，只佔了 5 個位元組。
在`struc`裡為它保留的其他 11 個位元組，會由`iend`自動填零，把這個實例補齊到`thread_size`，補上的是`0`。

`struc`只是語法糖，我們也可以用人工方式宣告同樣的記憶體。
舉例來說，上面的程式碼等於下面這段，其中`times 11 db 0`確保最後配置了 16 個位元組：

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## 拆分成多個檔案

巨集通常會放在自己的檔案裡，再用`%include`把它們納入每個需要它們的原始檔：

```x86asm
%include "patterns.mac"
```

指定的檔案會在組譯之前，原封不動地插入那個位置，就好像它的內容是直接打在那裡一樣。
這麼做可以把定義集中在一個地方，讓多個原始檔共用它們。

如果巨集檔可能被當成獨立檔案來組譯，就應該使用`.asm`副檔名。
請注意，巨集沒有連結性。
即使巨集檔被組譯，它的巨集也只對`%include`它的另一個檔案可見。

否則，只被`%include`的檔案可以有任何副檔名。
使用`.asm`或`.mac`都是常見的慣例。
