# 說明

在這道練習中，你會處理具有 6 種嚴重性等級的日誌訊息。

每一行日誌都是格式如下的字串：`"[<LVL>]: <MESSAGE>"`。

以下是各種日誌等級：

| 等級     | 簡稱   |
| --------- | ----- |
| `Trace`   | `TRC` |
| `Debug`   | `DBG` |
| `Info`    | `INF` |
| `Warning` | `WRN` |
| `Error`   | `ERR` |
| `Fatal`   | `FTL` |

## 1. 解析日誌等級

定義一個`LogLevel`列舉，其中包含 6 個元素，分別對應上面定義的日誌等級。
接著定義`parse_log_level`函式，它接受日誌訊息作為參數，並回傳該等級對應的列舉成員。

```python
parse_log_level("[INF]: File deleted")
#=> LogLevel.Info
```

## 2. 支援未知的日誌等級

可惜的是，有些日誌訊息偶爾會帶著_未知_的嚴重性出現。為了在`parse_log_level`函式中妥善處理這些「神秘」的日誌訊息，請在`LogLevel`列舉中加入一個`Unknown`成員，當解析到未知的日誌等級時就回傳它：

```python
parse_log_level("[XYZ]: Overly specific, out of context message")
#=> LogLevel.Unknown
```

## 3. 將日誌訊息轉換成簡短格式

日誌行的等級相當冗長。為了減少儲存日誌訊息所需的磁碟空間，這裡定義了一種簡短格式：`"[<CODE_LEVEL>]:<MESSAGE>"`。

日誌等級代碼的對應關係很直接：

| 等級     | 代碼 |
| --------- | ---- |
| `Trace`   | `0`  |
| `Debug`   | `1`  |
| `Info`    | `4`  |
| `Warning` | `5`  |
| `Error`   | `6`  |
| `Fatal`   | `7`  |
| `Unknown` | `42` |

定義`convert_to_short_log()`函式，它接受 2 個參數：

1. 日誌等級：傳送的日誌等級。例如：`LogLevel.Error`。
2. 日誌訊息：型別為`str`的訊息。

```python
convert_to_short_log(LogLevel.Error, "Stack overflow")
# => "6:Stack overflow"
```

## 4. 建立別名

看起來使用者建立的日誌寫的是`LogLevel.Warn`，而不是`LogLevel.Warning`。請為`LogLevel.Warning`建立一個`alias`，並在`get_warn_alias`函式中回傳這個新的別名成員。

這可以直接在檔案頂端已經定義好的同一個`LogLevel`列舉類別上完成。這兩個 LogLevel 都應該指向相同的值：`"WRN"`。

```python
get_warn_alias()
#=> LogLevel.Warn

get_warn_alias() == LogLevel.Warning
#=> True
```

## 5. 所有成員的名稱與值

定義`get_members()`函式。

這個函式應該回傳一個由`(name, value)`元組組成的陣列，其中包含`LogLevel`列舉的所有成員。

```python
get_members()
#=> [('Trace', 'TRC'), ('Debug', 'DBG'), ('Info', 'INF'), ('Warning', 'WRN'),
# ('Error', 'ERR'), ('Fatal', 'FTL'), ('Unknown', 'UKN')]
```
