# 不可變類別

```sather
immutable class BEARING is
   readonly attr degrees : INT;
   create(d : INT) : SAME is
      b : SAME;
      return b.degrees(d);
   end;
end;
```

## 有什麼不同

| | 一般類別 | 不可變類別 |
| --- | --- | --- |
| 賦值 | 共用同一個物件 | 複製一份值 |
| 可以為 void | 可以 | 不可以 |
| `attr` 寫入器 | `x.a := v` | `x := x.a(v)` |
| `new` | 有 | 沒有；`x : SAME` 已經存在 |

不可變物件不能為 void，所以 `void(b)` 永遠為 false，而不可變物件上的常式也絕不會因為缺少物件而失敗。這消除了整整一類錯誤，代價是永遠沒有辦法表達「還沒有 bearing」。

## 值儲存在哪裡

值就儲存在變數所在的位置，也就是另一個物件內部或堆疊上，而不是透過參照取得。因此 `ARRAY{BEARING}` 存放的是 bearing 本身，而不是指向它們的指標，這樣佔用的空間更小，走訪起來也更快。

代價是複製：傳遞大型的不可變物件時，每次都會複製一份。所以最好讓它們保持精簡。

## 屬性常式

`readonly attr degrees : INT` 會產生兩個常式：

```sather
   b.degrees          -- read: INT
   b.degrees(90)      -- answer a new BEARING with degrees changed
```

第二個常式即使在 `readonly` 之下也存在，因為它什麼都沒有改變，只是建構出一個新的值。在一般的 `attr` 之下它是公開的；在 `private attr` 之下則不是。

## is_eq and str

兩者都沒有提供。請為 `=` 撰寫 `is_eq`，並撰寫 `str`，讓物件能被列印，也能與字串連接：

```sather
   is_eq(other : SAME) : BOOL is return degrees = other.degrees; end;
   str : STR is return degrees.str + " degrees"; end;
```

寫出 `str` 會讓這個類別符合 `$STR`，這正是讓 `+` 和 `#OUT` 能接受它的原因。

## 內建類別

`INT`、`BOOL`、`CHAR`、`FLTD` 和 `TUP` 全都是不可變類別。它們並沒有任何特別之處：函式庫裡也是用同樣的方式以 Sather 寫成的，而它們之所以有現在的行為，原因就是上面提到的那些。
