# 簡介

## SIMD：位元運算

大多數純量位元運算都有對應的打包版本。
它們遵循與 SIMD 整數運算相同的一般語法，但沒有大小後綴：

| 指令   | 說明                          |
|-------------|-----------------------------------|
| `pand`      | 兩個 128 位元值的位元 AND |
| `por`       | 兩個 128 位元值的位元 OR  |
| `pxor`      | 兩個 128 位元值的位元 XOR |

請注意，並沒有打包版的 `NOT`。
不過，有一個 ANDN 運算，它會先對**目的**運算元取補數（翻轉其中所有位元），然後計算兩個運算元之間的 AND。
可以把它想成是 NOT 與 AND 的結合：

| 指令   | 說明                                                     |
|-------------|-----------------------------------------------------------------|
| `pandn`     | **取補數後**的目的運算元與來源運算元之間的位元 AND |

請注意，位元運算會組合兩個不同運算元中相同位置的位元，因此通道邊界不會改變結果。
這就是這些指令沒有大小後綴的原因：暫存器會表現得像單一 128 位元通道：

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
這個概念中的所有指令都會計算位元，但不會設定任何旗標。
之後的概念會探討搭配打包值的條件判斷。
~~~~

### 各通道位移

位移與純粹的位元運算不同，它確實會把位元移過不同位置，所以需要通道大小來設定邊界。
在每個通道內，它們的行為與純量版本相同，位元永遠不會從一個通道跨到鄰近的通道：

| 指令               | 說明                         |
|---------------------------|-------------------------------------|
| `psllw`, `pslld`, `psllq` | 每通道的邏輯左移        |
| `psrlw`, `psrld`, `psrlq` | 每通道的邏輯右移       |
| `psraw`, `psrad`          | 每通道的算術右移    |

請注意，這些指令遵循打包整數運算的語法，包含大小後綴。
並沒有位元組通道的位移，只有 word、dword，以及（除了算術右移之外）qword。

打包位移與其純量版本之間的一項差異在於運算名稱：

- 我們用的是 `sll` 和 `srl`（分別代表**邏**輯**左**移與**邏**輯**右**移），而非 `shl` 和 `shr`。
- 我們用的是 `sra`（代表算術右移），而非 `sar`。

名稱雖然不同，運算本身卻是一樣的：

- 邏輯右移會用零填滿最高的位元。
  它等於對二的冪次做無號除法。
- 算術右移會用符號位元的值填滿最高的位元。
  它等於對二的冪次做有號除法，並朝負無窮大捨入。
- 左移一律填零（這就是不需要算術左移的原因）。

每個通道的位移量都相同。
它可以是立即值，或是 `xmm` 暫存器的最低 64 位元：

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
大於通道寬度的位移量不會像純量 `shl`/`shr` 系列那樣環繞。
它只會產生零（若是算術右移，則是全部都是符號位元）。
~~~~

### 浮點位元運算

每個位元運算指令也都有以浮點命名的雙生版本，遵循我們在打包浮點運算中看過的相同語法：

| 整數名稱 | 浮點名稱          |
|--------------|----------------------|
| `pand`       | `andps`, `andpd`     |
| `pandn`      | `andnps`, `andnpd`   |
| `por`        | `orps`, `orpd`       |
| `pxor`       | `xorps`, `xorpd`     |

由於位元運算是作用在位元上，實務上整數與浮點運算會算出相同的結果。
名稱之所以不同，有兩個原因：

1. 記錄意圖，就像我們會依所複製位元組的性質，偏好使用 `movdqa`、`movaps` 或 `movapd` 一樣。
2. 整數與浮點運算通常有不同的執行域。
   同一個執行域內的運算通常能更快地排序執行。

浮點值沒有位移運算。

### 浮點數的位元表示法

IEEE 浮點數的位元表示法與整數截然不同。

在無號整數中，每個位元都有統一的意義：它代表對應該位元索引的二的冪次。
整數就是所有設定位元所對應之二的冪次的總和。
這就是為什麼位移位元可以讓數字乘以或除以二的冪次：我們只是在改變每個設定位元的索引。

在有號整數中，大多數位元的解讀方式與無號整數相同。
不過，最高的位元很特別。
如果它被設定，我們就必須減去它對應的二的冪次，而不是把它加到其他位元上，結果會是一個負數。
實務上，要改變一個數字的正負號，概念上需要兩個步驟：翻轉所有位元（`not`），然後對結果加 1（`inc`）。

浮點數中的位元沒有統一的意義，必須依其位置以截然不同的方式解讀：

| 欄位    | 索引（32 位元） | 索引（64 位元） |
|----------|------------------|------------------|
| 符號     | 31               | 63               |
| 指數 | 30-23            | 62-52            |
| 尾數 | 22-0             | 51-0             |

計算出的數字為 `(-1)^sign * 1.fraction * 2^(exponent - bias)`。
偏移量取決於精確度：

| 大小   | 偏移量 |
|--------|------|
| 32 位元 | 127  |
| 64 位元 | 1023 |

在兩種格式中，數字的正負號完全由符號位元決定。
只要翻轉這個位元（一個 XOR 運算），就能改變浮點數的正負號。
只要清除這個位元（一個將該位元清除的 AND），就能取得絕對值：

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

請注意，在這種位元表示法中，位移位元不會有可預測且一致的結果。
尾數可能會「溢出」到指數，指數則可能溢出到符號。

不過，有時把表示法的不同部分隔離出來分別操作會很方便。

例如，指數中的位元應該先解讀為無號數，再從中減去偏移量。
這表示我們可以產生一個 32 位元或 64 位元的整數，其底層的位元表示法對應到相應浮點格式中的某個二的冪次。
然後這個原始位元表示法可以用來乘或除另一個浮點數。

例如：

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

反過來說，我們可以對一個遮罩執行 AND，來取出打包浮點數的指數，其中遮罩的指數位元被設定，其他所有位元都被清除。
結合位移與減法，這就能產生每個通道的未偏移指數，成為有號整數：

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
直接操作浮點數的原始位元雖然在某些情況下很有用，但仍應謹慎為之。
對指數欄位做加法或減法，只有在沒有溢位或下溢、且輸入數字為正規數時才安全。
此外，對 `0.0` 的指數欄位加上有效的 `x` 會得到 `2^(x - bias)`，而不是 `0.0 * 2^x`。
~~~~
