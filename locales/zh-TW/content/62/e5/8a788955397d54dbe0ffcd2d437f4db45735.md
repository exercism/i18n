# 指令補充

## 在 Roc 中記錄計數

你的包裝器負責處理記錄的工作，實際的讀取與寫入則由提供的後端完成。你自己不需要開啟任何檔案或連線。

`Paasio(state, err)`可搭配任何後端狀態與錯誤型別使用。後端會保存它最初的`state`和兩個回呼函式：

- `read!(state, max_bytes)`回傳`{ state, result }`，結果為`Ok(bytes)`或`Err(error)`。
- `write!(state, bytes)`回傳`{ state, result }`，結果為`Ok(bytes_written)`或`Err(error)`。

每個包裝器的四個計數器都從零開始。`create`、`stats`和`get_state`都不得呼叫回呼函式。
每次`read!`或`write!`都要恰好呼叫對應的回呼函式一次，並原封不動地傳入它的引數。
即使失敗，也要保留回傳的狀態與結果，然後回傳`{ io, result }`。
把更新後的`io`帶進下一次呼叫。

## 每一次嘗試都要計數

讀取和寫入的統計資料要分開記錄：

- 每一次呼叫都要計數，包括失敗、EOF、讀到 0 位元組，以及空寫入。
- 只有在成功時才計入位元組：讀取時採用回傳陣列的長度，寫入時則採用回報的數字。
- 即使傳輸的位元組不足，仍然算一次呼叫，不要重試它，也不要重試失敗的操作。

以後端回報的內容為準，你不需要追蹤作業系統的呼叫或緩衝處理。
你可以信任後端的位元組計數，並假設計數器放得進`U64`。

## 執行測試

測試同時使用了記憶體內的後端，以及暫存目錄中的真實檔案，該目錄之後會被清理。

與大多數其他練習不同，這道練習使用有效應的函式（在這裡是基於`basic-cli`平台）。
因此，如果你想在本機執行測試，必須使用`roc --opt=speed paasio-test.roc`，而不是`roc test`（因為`expect`敘述目前無法測試有效應的函式）。

Roc 程式碼回傳的任何錯誤都會由平台回報，格式與平常不同。
