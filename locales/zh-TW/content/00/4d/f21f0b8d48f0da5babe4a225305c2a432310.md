# 關於

[8th](https://8th-dev.com)是一門強型別、衍生自 FORTH 的堆疊式語言，語法採用 RPN。

8th 支援 android、ios32、lin64、mac64、rpi32 與 win64 等平台。8th 讓你在自己偏好的平台上撰寫並測試程式碼。只要按一下，你就能*從*任何 8th 支援的平台，產生*適用於*任何 8th 支援平台的執行檔！

8th 包含你需要的一切：跨平台 GUI 支援、強大的加密功能、SQLite 資料庫支援、FFI、REST 存取、輕鬆的在地化、硬體存取、JSON 支援、REPL，還有更多！

在 8th 裡，安全性不是後來才補上的附加項目。它從一開始就是為了避開最常見的軟體安全問題而設計。我們也持續努力，讓它變得更加安全。

8th 有[論壇](https://8th-dev.com/forum/)，也有豐富的文件，包括一份[手冊](https://8th-dev.com/manual.html)，以及一份用超連結串起內建與函式庫 [word](https://8th-dev.com/words.html) 的字典。[比較](https://8th-dev.com/compare.html)看看 8th 和其他語言的差別吧！


## 「主流」語言使用者的快速入門

如果你原本寫的是 C 或 Java，或是其他更常見的語言，可能會覺得 8th 有點令人費解。為了幫你踏穩腳步，以下是 8th 與「主流」語言之間的一些主要差異，以及幾個實用的小提示：

* 由於翻譯員尋找項目的方式，你必須在第一次使用某個 var 或 word 之前就先宣告它。沒這麼做的話，就會導致 can't find ... 這個例外。
    
* var 是替其他項目命名的一個容器。它不是所指項目的名稱！所以 var x 可以裝著一個陣列，但把 x 當成陣列本身來存取是錯的，這麼做會拋出例外。
    
* 你不能在 word 裡面宣告 var（例如區域的 var），別嘗試！不過你可以用 w:@ 和 w:! 來存取 word 區域變數。
    
* 試著把你自己的 word 寫成能和其他 word 串接在一起的形式。例如：「file words」會對檔案做些操作，並把檔案項目留在堆疊上（可能還有其他資訊），讓下一個 word 接手處理。

* 讓你的 word 保持簡短。為它們加上註解。尤其務必註解堆疊效應，還有……

* ……測試你寫的每一個 word（最好邊寫邊測，或寫完後盡快測試），確保它符合文件記載的 SED（堆疊效應圖）。這能幫你寫出沒有 bug 的程式碼。如果你改了 SED 或程式碼，就重新測試。

* 對於任何你沒把握的 word，查閱 help 和 apropos 這兩個 word，以了解它的 SED 作用和副作用。
    
* 在 8th 裡，例外是致命錯誤，會讓應用程式直接結束（這是預設行為）。別指望能「捕捉」它並有效地處理。
    
* 8th 沒有編譯／連結週期。它是一個引擎，會先翻譯你的程式碼，必要時在執行時再編譯它。在裝置上執行時，你的程式碼是該平台的原生程式碼，而不是在 VM 裡執行的位元組碼。
