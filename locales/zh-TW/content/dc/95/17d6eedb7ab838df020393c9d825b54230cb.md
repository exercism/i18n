# 簡介

你已經知道怎麼用一塊塊的片段*拼出*一份 quotation 並執行它。quotation 就只是一段程式碼序列，所以你所熟悉的那些序列相關的詞也都適用於它：

```factor
USING: kernel math prettyprint quotations sequences ;

{ [ 1 ] [ 2 + ] [ 3 * ] } concat >quotation call .   ! => 9
[ 1 + ] dup append .                                 ! => [ 1 + 1 + ]
```

`append`會接合兩份 quotation，`concat`會把一整個陣列的 quotation 攤平，`map`會把資料變成一份份 quotation，而`>quotation`則讓結果可以被呼叫。`MACRO:`正是把你這項本事搬到**編譯期**。

## 什麼是巨集

一個`MACRO:`定義看起來就像一個普通的詞，但它的主體是在*你的程式被編譯的時候*執行，而不是在程式執行時執行。主體必須在堆疊上留下**一份** quotation。接著編譯器會**把那份 quotation 拼接進呼叫處**，也就是用主體所產生的程式碼取代巨集呼叫。到了執行期，巨集已經不存在，只剩下被產生出來的程式碼。

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- spliced )
    dup append ;
```

不論你在哪裡寫下`[ 1 + ] twice`，編譯器都會：

1. 在堆疊上放著`[ 1 + ]`的狀態下執行主體，
2. `dup append`會建構出 quotation `[ 1 + 1 + ]`，
3. 把其中的程式碼`1 + 1 +`拼接進那個位置。

所以，一個呼叫`twice`的詞，編譯出來的結果就像你親手寫下`1 + 1 +`一樣：

```factor
: inc-twice ( x -- y ) [ 1 + ] twice ;

5 inc-twice .   ! => 7
```

最關鍵的對比是：一般的詞如果接受一份 quotation，會在執行期用`call`呼叫它。巨集則從不呼叫任何東西，它是把*新的程式碼*交給編譯器，讓編譯器在原地編譯這些程式碼。

## 輸入必須是字面值

因為主體是在編譯期執行，巨集的輸入必須在*當時*就已經知道。它們在呼叫處必須是**字面值**，例如一份`[ … ]` quotation、一個數字、一個陣列、一個字串。只存在於執行期的值沒辦法交給巨集。

```factor
! DOCTEST: SKIP — illustrative call sites, not standalone code
[ 1 + ] twice          ! ok: the quotation is a literal
[ 1 + ] 3 repeat-quot  ! ok: the quotation and the number are literals
```

## 工具箱

巨集主體就是一段會回傳 quotation 的普通程式碼。大部分的工作，你已經見過的詞就能勝任：

| 想建構出… | 使用 |
|---|---|
| 從`[ A ]`和`[ B ]`造出`[ A B ]` | `append` |
| 從一整份陣列造出單一份 quotation | `concat >quotation` |
| 為序列的每個元素各造一份 quotation | `map`，然後`concat >quotation` |

還有兩個詞來自`sequences`和`kernel`，湊齊了整套工具。

**`<repetition>`**（位於`sequences`）會把單一元素複製成`n`份，做出一段序列。它的堆疊效應是`( length elt -- repetition )`，其中數量會排在最前面。結果是一段*虛擬*序列，所以照平常的方式把它攤平：

```factor
3 [ 1 + ] <repetition> concat >quotation .   ! => [ 1 + 1 + 1 + ]
```

**`curry`**（位於`kernel`）會把一個值加到 quotation 的最前面，產生一份會先推入那個值的新 quotation：

```factor
3 [ + ] curry .          ! => [ 3 + ]
{ 1 2 3 } [ . ] curry .  ! => [ { 1 2 3 } . ]
```

`curry`就是讓你把某個特定元素嵌進 quotation 的方法，也正是把`{ 10 20 30 }`和`[ + ]`變成`[ 10 + ] [ 20 + ] [ 30 + ]`的關鍵。

## 為什麼這比聽起來簡單

在某些語言裡，巨集需要特別的 quote/unquote 語法，還需要額外的機制來避免名稱衝突。Factor 完全不需要這些：一份 quotation 本身就是一串已經*解析完成*的詞，剖析器在讀到`[ … ]`的時候，就已經查好每個`dup`、`+`和`append`。所以巨集主體不過就是你平常就在做的序列操作，只是它剛好會回傳一份 quotation。

## 近親：`$[ … ]`

巨集回傳的 quotation 會被拼接進一次*呼叫*裡。如果你想要的是在剖析期就算好的單純*值*，`$[ code ]`會在檔案被讀取的同時執行`code`，並把結果以字面值的形式折入原始碼中：

```factor
! DOCTEST: SKIP — compile-time value, shown for contrast
USING: calendar literals ;

CONSTANT: build-time $[ now ]
```

`$[ … ]`出自[`literals`][literals]詞彙，它收集了用來把剖析期結果內插到字面值裡的詞。這裡提到它只是為了完整。接下來你要寫的四個模板：`twice`、`repeat-quot`、`compose-many`和`each-literal`，全都是`MACRO:`宣告。
