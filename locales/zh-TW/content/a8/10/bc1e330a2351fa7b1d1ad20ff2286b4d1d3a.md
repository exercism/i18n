# 簡介

先前的概念介紹過封裝浮點數值：多個數字存放在同一個`xmm`暫存器中，以通道為單位平行運算。
同樣的`xmm`暫存器也能存放封裝_整數_。

## 語法

SIMD 浮點模型大部分都能原封不動地沿用到封裝整數：

- 128 位元的暫存器會劃分成多個通道
- 指令會平行作用於相同位置的通道
- 記憶體運算元遵循相同的 16 位元組對齊規則

不過，語法略有不同：

1. 一個_前綴_`p`，用來指出指令操作的是_封裝_資料。
2. 所執行的操作，名稱與非 SIMD（也稱為_純量_）的對應指令相同（例如`add`、`mul` 等）。
3. 一個後綴，用來指出每個通道的大小。

封裝整數有四種通道大小，每種都有自己的後綴：

| lane width | bytes | lanes in 128 bits | suffix |
|------------|-------|-------------------|--------|
| byte       | 1     | 16                | b      |
| word       | 2     | 8                 | w      |
| dword      | 4     | 4                 | d      |
| qword      | 8     | 2                 | q      |

例如：

| instruction | meaning                              |
|-------------|--------------------------------------|
| `paddb`     | packed `add`, 8-bit lanes (16 lanes) |
| `paddw`     | packed `add`, 16-bit lanes (8 lanes) |
| `paddd`     | packed `add`, 32-bit lanes (4 lanes) |
| `paddq`     | packed `add`, 64-bit lanes (2 lanes) |

有些指令的輸入通道是某種大小，輸出則是另一種大小。
它們遵循相同的通用慣例，但帶有_兩個_大小後綴。
第一個指出輸入通道的大小，第二個指出輸出通道的大小：

| instruction  | meaning                                           |
|--------------|---------------------------------------------------|
| `pmovsxwd`   | packed `movsx`, from 16-bit lanes to 32-bit lanes |
| `pmuldq`     | packed `mul`, from 32-bit lanes to 64-bit lanes   |

## 記憶體搬移

有兩個以整數命名的指令可以在`xmm`暫存器與記憶體之間複製 128 位元：

| instruction | description                                             |
|-------------|---------------------------------------------------------|
| `movdqa`    | copy packed integers to or from an _aligned_ location   |
| `movdqu`    | copy packed integers to or from an _unaligned_ location |

它們的行為和`movaps`與`movups`相同：`movdqa`在未對齊的位址上會發生錯誤，而`movdqu`則接受任何位址。
這四個指令都複製 128 位元，並不會去解讀這些位元。
這對以整數命名的指令依慣例搭配整數資料使用，並非強制要求。

~~~~exercism/note
`dq`在此代表`double-qword`，也就是 128 位元（16 位元組）。
~~~~

## 加法與減法

加法和減法遵循命名規則：

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

沒有另外區分有號與無號的形式。
在二補數中，無論通道被解讀為有號或無號，加法和減法產生的位元都相同，因此一個指令就能同時滿足兩者。
要如何解讀由你決定，就和純量的`add`與`sub`一樣。

這些指令在溢位時會**回繞**，和它們的純量對應指令一樣。
8 位元的通道以 256 取模來存放值，所以`paddb`的`200 + 100`會產生`300 - 256 = 44`，並捨棄裝不下的位元。

請注意，這些多出來的位元不會進位到下一個通道。
每個通道都是各自獨立運算的，即使它們共用同一個暫存器。

## 飽和加法與減法

整數 SIMD 多了浮點 SIMD 沒有的運算：**飽和**加法與減法，它們會_夾限_而不是回繞。
超出通道範圍的結果會變成該通道能容納的最大值；低於範圍的結果則會變成最小值。

飽和形式會在大小後綴之前插入`s`（有號）或`us`（無號）：

| instruction | meaning                                    |
|-------------|--------------------------------------------|
| `paddsb`    | `add`, saturating, signed 8-bit lanes      |
| `paddusb`   | `add`, saturating, unsigned 8-bit lanes    |
| `psubsw`    | `sub`, saturating, signed 16-bit lanes     |
| `psubusw`   | `sub`, saturating, unsigned 16-bit lanes   |

夾限範圍就是對應大小、對應有號或無號的整數所能完整表示的範圍。
以位元組為例：

- 無號位元組會夾限到`[0, 255]`：`paddusb`的`200 + 100`會得到`255`，而`psubusb`的`5 - 10`會得到`0`。
- 有號位元組會夾限到`[-128, 127]`：`paddsb`的`100 + 50`會得到`127`。

當通道存放的是有範圍限制的量時，飽和就顯得重要，例如像素的顏色通道或音訊取樣。
回繞會讓過亮的像素變暗，而夾限則會讓它維持在最大亮度，這才是你想要的結果。

~~~~exercism/note
飽和加法與減法只存在於位元組與字組通道，不適用於雙字組或四字組。
~~~~

## 乘法

兩個 N 位元的值相乘可能產生 2N 位元的乘積，但目的通道只有 N 位元寬。
SIMD 運算的解決方式，是指定要保留乘積的哪一半：較低的 N 位元，或是較高的 N 位元。

對於 16 位元通道，會使用三個指令：

| instruction | meaning                                                       |
|-------------|---------------------------------------------------------------|
| `pmullw`    | `mul`, 16-bit lanes, keep the low 16 bits of each product     |
| `pmulhw`    | `mul`, 16-bit lanes, keep the high 16 bits, signed operands   |
| `pmulhuw`   | `mul`, 16-bit lanes, keep the high 16 bits, unsigned operands |

無論運算元被解讀為有號或無號，乘積的低 16 位元都相同，因此只有一個`pmullw`。

不過，高 16 位元會隨結果的有號或無號而不同。
這就是為什麼取高半部的乘法會分別為有號與無號乘法提供不同的形式：

1. `pmulhw`，用於有號乘法。
2. `pmulhuw`，多了一個`u`，用於無號乘法。

注意語法：

1. 一個`p`，代表封裝整數。
2. 所執行的操作，`mul`。
3. 一個`h`，表示選取結果中較高（「高位」）的位元。
4. 一個可選的`u`，表示結果應解讀為無號（也就是未做符號擴展）。
5. 最後是大小後綴`w`，表示這是字組（16 位元）運算。

字組的封裝乘法完全遵循上述規則。
雙字組（32 位元）乘法也遵循這個規則，但只有選取低半部的變體：`pmulld`。

雙字組乘法沒有選取高位元的變體。
不過，有些變體會_加寬_乘法，儲存_偶數索引_通道的完整 64 位元乘積（也就是位置 0 和 2 的通道）：

| instruction | meaning                                                                          |
|-------------|----------------------------------------------------------------------------------|
| `pmuludq`   | multiply the even-indexed 32-bit elements, unsigned, into 2 full 64-bit products |
| `pmuldq`    | multiply the even-indexed 32-bit elements, signed, into 2 full 64-bit products   |

注意這裡的語法使用了`dq`，無號乘法時前面可能還會加上一個`u`。
這是因為這些指令取用`dword`通道，並輸出`qword`通道。

## 除法

封裝整數沒有除法。
需要除法的程式碼會先把值轉成浮點數，相除之後再轉換回來。

## 整數加寬

`movsx`和`movzx`都有對應的封裝版本。
它們遵循我們先前提到、輸入通道大小與輸出不同的指令所用的相同語法：

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

注意，通道數量由較大（輸出）的寬度決定。
指令會從來源的低位部分讀取這麼多個通道。
這和我們在單精度與雙精度浮點數之間的封裝`cvt`指令所見到的語意相同。

## 整數與浮點數之間的轉換

有些指令可以在 32 位元有號整數與浮點通道之間轉換。
它們遵循`cvt`與`cvtt`指令的一般語法，但封裝整數不用`si`表示，而是用`dq`：

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
使用`pi`代表封裝整數的指令會寫入舊式的`mmx`暫存器，在 x86-64 上實際上已被棄用。
請改用`dq`形式，它們使用`xmm`暫存器。
~~~~

先前針對浮點數與整數之間純量轉換所做的說明，在這裡同樣適用。
浮點數會依照一個稱為 MXCSR 的特殊暫存器來捨入，而在進入函式時，你無法假設它的模式。
有一個`cvtt`變體（多了一個`t`），會一律截斷結果。

也可以在轉換之前先用`round`，讓封裝浮點數值處於已知的狀態。
捨入控制值和純量的`round`相同，而封裝浮點數值的語法也一樣：

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
