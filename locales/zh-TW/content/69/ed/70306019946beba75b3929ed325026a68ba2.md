# 說明

你正在為汽車零件工廠現場的資料系統撰寫程式碼。引擎與底盤零組件會依序經過一連串的加工站。每個加工站都會產生量測資料，這些資料必須先經過合併、比較、校正或正規化，才能進入下一道程序。你在這裡實作的函式，每個加工站各一個。

~~~~exercism/note
這個練習的運算應該使用 SIMD 指令完成，而不是純量運算。
~~~~

## 1. 合併兩條產線的產量

工廠現場有兩條平行運作的組裝線。每到班次結束時，兩條產線都會以單精度數字回報 4 個零件箱的產量。主管的儀表板會顯示每個零件箱合併後的產量，因此兩份報告會逐箱相加。這三個緩衝區都由回報系統管理，而且一律是 16 位元組對齊。

定義一個函式`sum_yields`，它會接收`line_a`與`line_b`每個零件箱的產量，並把逐箱相加的結果寫入`result`。

引數依序為：

1. `line_a`：16 位元組對齊的記憶體位址，存放 4 個 32 位元浮點數
2. `line_b`：16 位元組對齊的記憶體位址，存放 4 個 32 位元浮點數
3. `result`：16 位元組對齊的記憶體位址，函式會在這裡寫入 4 個 32 位元浮點數

這個函式沒有回傳值，結果會改為儲存在傳入的緩衝區（`result`）中：

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. 計算縮放後的偏差

在兩道工序之間，抽樣站會量測加工後的零件，並與目標尺寸比較。量測值會從精密量規串流進一個一律為 16 位元組對齊的緩衝區。目標值則來自工單文件，不保證對齊。偏差在傳給下游的公差檢查器之前，會先乘上每個軸向的靈敏度係數。在這個階段，下游檢查器會直接從 SIMD 暫存器讀取偏差，而不是從記憶體讀取。

定義一個函式`scaled_deviation`，它會接收`measured`、`target`與`sensitivity`，並把縮放後的偏差寫入`result`。

引數依序為：

1. `measured`：16 位元組對齊的記憶體位址，存放 2 個 64 位元浮點數
2. `target`：存放 2 個 64 位元浮點數的記憶體位址（不保證對齊）
3. `sensitivity`：存放 2 個 64 位元浮點數的記憶體位址（不保證對齊）
4. `result`：函式會寫入 2 個 64 位元浮點數的緩衝區記憶體位址（不保證對齊）

縮放後的偏差是`(measured - target) * sensitivity`，採逐通道計算。

這個函式沒有回傳值，結果會以一對 64 位元浮點數的形式，儲存在傳入的緩衝區（`result`）中。

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. 校正批次

在零件進入最終檢驗區之前，一批 4 個零件的尺寸讀數會先重新縮放為雙精度，並針對已知的溫度漂移進行修正。

這 4 筆原始讀數會以單精度數字送達。校正會針對每列 2 筆讀數計算`reference / (raw - offset)`，然後把這個結果乘上一個固定不變的轉換係數`0.5`。

請注意，同一批次的兩列都會使用相同的 reference 與 offset。轉換係數在每次校正時都相同，因此與其把它當成引數接收，你應該在記憶體中將它宣告為一個 16 位元組的 packed 常數。

定義一個函式`calibrate_batch`，它會接收一批`raw`、一個`reference`、一個`offset`，以及一個`result`緩衝區，並把校正後的值寫入`result`。

引數依序為：

1. `raw`：存放 4 個 32 位元浮點數的記憶體位址（不保證對齊）
2. `reference`：16 位元組對齊的記憶體位址，存放 2 個 64 位元浮點數
3. `offset`：16 位元組對齊的記憶體位址，存放 2 個 64 位元浮點數
4. `result`：16 位元組對齊的記憶體位址，函式會在這裡寫入 4 個 64 位元浮點數（共 32 位元組）

這個函式應該針對批次中的兩列，分別執行下列步驟：

1. 把該列的 2 個單精度原始值轉換為雙精度。
2. 從轉換後的這一對值減去`offset`。
3. 用`reference`除以剛才的結果。
4. 把每個 64 位元浮點數逐通道乘上固定的轉換係數`0.5`。
5. 把這 2 個 64 位元浮點數儲存到`result`對應的 16 位元組。

這個函式沒有回傳值，結果會儲存在傳入的緩衝區（`result`）中：

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. 沿產線正規化分數

在產線末端，每個零件都有一個品質分數，在回報之前需要先正規化。每個分數會乘上它自己的對應零件增益，再除以每個軸向的生產比例。增益緩衝區會為每個零件各存放一個增益。

生產比例在整批執行中都是相同的，並以一個存放 2 個 64 位元浮點數的記憶體位址傳入。分數會**原地**更新：原本存放原始分數的同一個緩衝區，之後會存放正規化後的分數。

定義一個函式`normalize_scores`，它會接收`scores`陣列、`gains`陣列、`scale`，以及一個數量`n`，並在原地正規化這些分數。

引數依序為：

1. `scores`：16 位元組對齊的記憶體位址，存放`n`個 64 位元浮點數（會原地修改）
2. `gains`：16 位元組對齊的記憶體位址，存放`n`個 64 位元浮點數
3. `scale`：16 位元組對齊的記憶體位址，存放 2 個 64 位元浮點數
4. `n`：一個 64 位元的正偶數（最小值`2`），代表要正規化的分數數量

這兩個比例通道會分別套用到每一對中的兩個元素。第一個通道會縮放每一對的第一個元素（位於偶數位置的通道），第二個通道則縮放第二個元素（位於奇數位置的通道）。每個分數會乘上對應的增益，再除以適當的比例通道：`score * gain / scale_lane`。

這個函式沒有回傳值，結果會儲存在輸入緩衝區（`scores`）中，位置與被正規化的對應`score`相同：

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
