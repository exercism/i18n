# 簡介

**單指令多資料（SIMD）** 是一種硬體層級的平行處理方式。
CPU 會在同一時間對多個元素執行相同的運算。

舉例來說，假設要把兩個各含四個 32 位元浮點數的陣列逐元素相加。
純量實作會發出四道獨立的`addss`指令，每個元素一道。
SIMD 實作則只用一道`addps`，就平行完成這四次加法。
這表示每道指令做了四倍的工作。

在 x86-64 組合語言中，SIMD 指令通常是透過`xmm`暫存器來執行。
這些指令有些處理整數，有些則處理浮點數。

這些整數或浮點數稱為**打包**資料。
每個值在同一個暫存器內各佔一個空間，稱為**通道**。
SIMD 指令通常會平行處理兩個來源運算元中位於相同通道位置的值。
每個運算的結果會儲存在目的運算元中相同位置的通道。

通道並不是硬性限制。
它只是每道指令對一串位元組所做的解讀。
一個 128 位元的運算元包含 16 個位元組。
視指令而定，這些位元組可以解讀為 16 個_1 位元組_通道、8 個_2 位元組_通道、4 個_4 位元組_通道、2 個_8 位元組_通道，甚至單一一個_16 位元組_通道。

舉例來說，`addps`指令會將打包的單精度（4 位元組）浮點數值相加。
對這道指令而言，運算元中每個 4 位元組的區塊就是一個不同的通道。
在一個 128 位元寬（16 位元組）的運算元中：

| 運算元     | 第 4 通道 | 第 3 通道 | 第 2 通道 | 第 1 通道 |
|:-----------:|:--------:|:--------:|:--------:|:--------:|
| 來源 1    |  1.5     |  2.1     | 6.2      | 3.4      |
|    +        |  +       |  +       | +        | +        |
| 來源 2    |  0.5     |  8.26    | -13.4    | 22.9     |
|    =        |  =       |  =       | =        | =        |
| 結果      |  2.0     |  10.36   | -7.2     | 26.3     |

另一方面，若是`mulpd`，同一個 128 位元的運算元則會被解讀為只有 2 個通道。
這是因為這道指令對雙精度（8 位元組）值執行打包乘法：

| 運算元     | 第 2 通道 | 第 1 通道 |
|:-----------:|:--------:|:--------:|
| 來源 1    |  4.2     |  2.1     |
|    *        |  *       |  *       |
| 來源 2    |  1.0     |  92.4    |
|    =        |  =       |  =       |
| 結果      |  4.2     |  194.04  |

在這個概念裡，我們會聚焦在少數幾道 SIMD 指令。
它們使用`xmm`暫存器來處理打包的浮點數值。

## 浮點數 SIMD 指令

一般而言，處理浮點數值的 SIMD 指令採用雙運算元形式。
它們的名稱遵循一定的結構：

1. 所執行的運算，名稱與其非 SIMD（也稱為_純量_）的對應指令相同（例如`add`、`mul`等）。
2. 後綴`p`，表示指令處理的是_打包_資料，位置就在原本放`s`（代表_純量_資料）的地方。
3. 一個後綴，表示每個通道的大小，語意與非 SIMD 對應指令相同（`s`代表單精度，`d`代表雙精度）。

因此，打包版本的名稱就是把純量名稱助憶符中間的`s`（純量）換成`p`（打包）。
運算名稱與大小後綴維持不變：

| 純量  | 打包  | 意義                                |
|---------|---------|----------------------------------------|
| `addss` | `addps` | 加法，單精度（32 位元通道）   |
| `addsd` | `addpd` | 加法，雙精度（64 位元通道）   |
| `mulss` | `mulps` | 乘法，單精度             |
| `mulsd` | `mulpd` | 乘法，雙精度             |

### 算術運算

算術類的 SIMD 指令遵循上述規則。
以下是一些例子：

```x86asm
addps xmm0, xmm1 ; xmm0 = xmm0 + xmm1 (each 32-bit float at the same position)
subpd xmm2, xmm3 ; xmm2 = xmm2 - xmm3 (each 64-bit float at the same position)
mulps xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (each 32-bit float at the same position)
divpd xmm6, xmm7 ; xmm6 = xmm6 / xmm7 (each 64-bit float at the same position)
```

### 精度之間的轉換

也有 SIMD 指令可在打包的單精度與打包的雙精度浮點數值之間轉換。
它們遵循同樣的命名規則，把代表_純量_的`s`換成代表_打包_的`p`：

| 純量     | 打包     | 意義                                      |
|------------|------------|----------------------------------------------|
| `cvtss2sd` | `cvtps2pd` | 將單精度轉換為雙精度 |
| `cvtsd2ss` | `cvtpd2ps` | 將雙精度轉換為單精度 |

這些指令正好說明了前面提過的觀點：通道是一種解讀方式，而非硬性限制。
來源與目的運算元的通道大小不同，因此通道數量也不同。

以`cvtps2pd`來說，來源（`ps`）有 4 個單精度通道。
目的（`pd`）則有 2 個雙精度通道。
只會讀取來源的低位 2 個通道。
高位的 2 個則會被忽略：

| 運算元              | 第 4 通道 | 第 3 通道 | 第 2 通道 | 第 1 通道 |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| 來源（解讀為`ps`）       | 忽略  | 忽略  | 2.5      | 1.5      |
| 目的（解讀為`pd`）  |          |          | 2.5      | 1.5      |

以`cvtpd2ps`來說，來源（`pd`）有 2 個雙精度通道。
目的（`ps`）則有 4 個單精度通道。
兩個來源通道都會被轉換，並寫入目的運算元低位的 2 個通道。
目的運算元高位的 2 個通道則設為 0：

| 運算元              | 第 4 通道 | 第 3 通道 | 第 2 通道 | 第 1 通道 |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| 來源（解讀為`pd`）       |          |          | 4.0      | 3.0      |
| 目的（解讀為`ps`）  | 0        | 0        | 4.0      | 3.0      |

以下是一些例子：

```x86asm
cvtps2pd xmm0, xmm1 ; xmm0 = xmm1 as 2 doubles (low 2 lanes of xmm1 are read)
cvtpd2ps xmm0, xmm1 ; xmm0 = xmm1 as 2 floats (in low 2 lanes; upper 2 zeroed)
```

### 記憶體運算元

上面介紹的 SIMD 指令，示範時用的都是暫存器對暫存器的運算元。
它們也可以接受記憶體運算元作為來源（但**不能**作為目的）。

從記憶體讀取多少位元組，取決於指令本身。
例如，`addps`會讀取 16 位元組（4 個單精度浮點數）。
相對地，`cvtps2pd`只讀取 8 位元組（2 個單精度浮點數），因為它需要的輸入就這麼多。

```x86asm
addps    xmm0, [rsi]      ; xmm0 = xmm0 + 4 floats at [rsi]
mulpd    xmm1, [rsi + 16] ; xmm1 = xmm1 * 2 doubles at [rsi + 16]
cvtps2pd xmm2, [rsi + 8]  ; xmm2 = (2 floats at [rsi + 8]) converted to 2 doubles
```

當記憶體運算元寬度為 16 位元組時，必須是_16 位元組對齊_。
所謂對齊的記憶體位置，是指其位址為運算大小的倍數（在此為 16 位元組）。

如要宣告對齊的記憶體，可以在 .data 與 .rodata 區段使用`align`指示詞，或在 .bss 區段使用`alignb`：

```x86asm
section .rodata
align 16
mem1: dd 4.0, 3.5, 2.0, -1.0

section .data
align 16
mem2: dq 6.0, 2.1

section .bss
alignb 16
mem3: resb 16

section .text
fn:
    movaps xmm0, oword [rel mem1] ; loads 4 packed 32-bit floats in xmm0
    movapd xmm1, oword [rel mem2] ; loads 2 packed 64-bit floats in xmm1
    movaps oword [rel mem3], xmm0 ; stores 4 packed 32-bit floats in mem3
    ret
```

小於 16 位元組的記憶體運算元，例如`cvtps2pd`的 8 位元組來源，沒有對齊要求。

### 載入與儲存數值

有四道指令可以複製 128 位元的打包浮點數值。
它們作用於兩個`xmm`暫存器之間，或是一個`xmm`暫存器與一個記憶體位置之間：

| 指令 | 說明                                                                       |
|-------------|-----------------------------------------------------------------------------------|
| `movaps`    | 從_對齊_的記憶體位置複製打包的單精度資料，或將資料複製到該位置     |
| `movups`    | 從_未對齊_的記憶體位置複製打包的單精度資料，或將資料複製到該位置   |
| `movapd`    | 從_對齊_的記憶體位置複製打包的雙精度資料，或將資料複製到該位置    |
| `movupd`    | 從_未對齊_的記憶體位置複製打包的雙精度資料，或將資料複製到該位置   |

上述所有指令都可以用來在兩個`xmm`暫存器之間複製值。

如果運算牽涉到記憶體位置，`movaps`與`movapd`會要求該位置必須_對齊_。
若位址未對齊，`movaps`與`movapd`會引發例外。
它們同時也兼具安全檢查的作用，確保你的資料配置確實如你所想。

另一方面，`movups`與`movupd`則可用於任何記憶體位置，無論是否對齊。

在 NASM 中，16 位元組值的大小前綴是`oword`。

## SIMD 擴充

數十年來，SIMD 一直是 x86-64 生態系中積極發展的目標。
每一次架構擴充都會帶來新指令，或是舊指令的新用法。

其中，AVX 與 AVX2 這兩項擴充帶來了一些相關的變化。

第一，支援稱為`ymm`的 256 位元 SIMD 暫存器。
它們擴充了對應的`xmm`暫存器，就像`rax`包含了`eax`一樣。

第二，對於大多數作用於`xmm`（以及`ymm`）暫存器的指令，它們支援三運算元版本。
這不僅包含 SIMD 指令，也包含處理純量浮點數值的指令。
這些版本沿用其 SSE 對應指令的記法，只是在前面加上一個`v`：

```x86asm
vaddsd xmm0, xmm1, xmm2   ; xmm0 = xmm1 + xmm2 (scalar sum of 64-bit floats)
vmulps xmm1, xmm3, xmm4   ; xmm1 = xmm3 * xmm4 (packed multiplication of 32-bit floats)
vmovupd ymm5, yword [mem] ; this copies 32 bytes from the location at mem to ymm5
```

第三，SIMD 記憶體運算元的對齊要求放寬了。
只有明確要求對齊的搬移指令，例如`vmovaps`，才需要這種對齊。

在本 track 中，我們只涵蓋到先前 SSE 擴充為止的指令與暫存器。
這足以教授基礎觀念，並確保能與各式各樣的 CPU 相容。

不過，測試執行器完整支援 AVX 與 AVX2，甚至支援 AVX-512 中較新的擴充。
你可以自由使用它們。

~~~~exercism/note
使用 SIMD 變體時，保持一致是良好的做法。
盡量不要對同一批指令混用 SSE 與 AVX 變體。

如果你的程式碼庫混用這些變體，建議在用完 AVX、要用 SSE 之前先執行`vzeroupper`。
這樣可以打斷相依性鏈，避免 CPU 在 AVX 與 SSE 狀態之間切換時付出高昂的停頓成本。
~~~~
