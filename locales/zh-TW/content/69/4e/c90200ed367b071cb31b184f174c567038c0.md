我們現在已全面推出自動化回饋策略的第二部分：Representer！這篇文章會快速概述它們的運作方式，以及它們為什麼這麼實用。這篇比平常稍微技術一點，所以請坐穩囉！

## 什麼是 Representer？

Representer 是一套軟體，會接收學生的解法，並回傳它的正規化表示。接著我們會用這些表示來簡化自動化回饋與分類。

用一個例子最能說明 Representer。假設有兩位學生用 Ruby 向`hello-world`練習提交了兩份提交內容：

```ruby
# Student 1's submission
def self.hello(name = 'World')
  "Hello, #{name}!"
end
```

```ruby
# Student 2's submission
def self.hello(nom='World')
    "Hello, #{nom}!"
end
```

雖然這兩個解法的程式碼不同（縮排、變數名稱和字串語法都不一樣），但它們本質上相同。所以，只要為它們建立正規化表示，我們就能在提供回饋時將它們_視為_相同。

## 這為什麼有用？

透過建立這些正規化表示，我們可以確保針對某份提交內容給予的回饋會自動套用到其他類似的解法上。這表示，身為學生，你更有可能立即獲得高度相關的回饋。而身為導師，你現在應該再也不需要對類似的解法重複給出同樣的回饋：只要在 Automation UI 中做一次，其餘的就會神奇地自動完成。

我們也可以將 Representer 與現有的 Analyzer 一起使用。Analyzer 可以針對一般性的重點（例如變數名稱、程式碼檢查等）提出意見，而表示則可以專注在應該進行的更廣泛變更上。這裡有很大的潛力，而我們才剛開始觸及表面。

## 誰可以新增回饋？

為表示新增回饋的能力僅限於我們的超級導師，大約 150 人，他們引導過數百位學生，並維持高導師評分。

如果你是超級導師，現在應該會看到導師儀表板上的「Automation」分頁已解鎖，你可以用它來存取可以接受回饋的解法。請仔細閱讀文件喔，因為要把這件事做好，有很多細微的地方要注意！
