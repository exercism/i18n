# 關於

`String`中的個別字元，可以使用和陣列相同的下標方式來存取。
不過，字串使用的[索引][string-indices]並_不是_整數，無法直接操作。
你得改用[`String`][string-docs]和[`NSString`][nsstring-docs]函式庫提供的方法，根據其他已知的索引來計算，例如`startIndex`，它指向非空字串中第一個字元的位置（匯入`Foundation`模組後，Swift 的字串就能取用所有 NSString 的屬性和方法）。

舉例來說，假設有下面這個字串：

```swift
let csv = "apple,pear,peach,orange,cherry,lime,goosberry"
```

你不能寫 `csv[21]` 來取得「orange」裡的「g」，而是必須計算出一個 `String.Index` 型別的值，再提供那個索引。
請注意，這些索引本身並不是設計給人直接理解的。
它們就是所謂的_不透明索引_，人類不需要知道裡面裝了什麼。

```swift
let index = csv.index(csv.startIndex, offsetBy: 21)
csv[index]
// "g"
print(index)
// prints Index(_rawBits: 1376513)
```

不過要注意，如果位移量不是有效的索引，也就是說，算出來的索引落在`startIndex`之前或`endIndex`之後，這個操作就會引發錯誤，讓程式崩潰。
要避免這個問題，你可以指定一個限制索引。
這會回傳一個可選的索引，對於其他無效的索引則會回傳 nil。

```swift
let tooFar = csv.index(csv.startIndex, offsetBy: 200)
// error: Execution was interrupted, reason: EXC_BAD_INSTRUCTION (code=EXC_I386_INVOP, subcode=0x0).
let tooFarButSafe = csv.index(csv.startIndex, offsetBy: 200, limitedBy: csv.endIndex)
// nil
```

此外，索引不能在不同字串之間共用。
舉例來說，拿上面算出的「orange」中「g」的 `index`，去索引字串 `fam = "This is my family: 👨‍👩‍👦‍👦, this is our dog: 🐶, this is our cat: 🐱!"`，也就是 `fam[index]`，會讓程式崩潰。

這一切背後有很多原因，但基本上都可以歸結為一句話：「Unicode 很麻煩」。

一般來說，如果你需要隨機存取個別字元，那你大概該改用其他資料結構，例如 `Array<Character>`。

## 一些實用的方法

Swift 有 `first` 和 `last` 兩個方法，可以取得字串的第一個和最後一個字元。
這些方法會回傳可選的字元，所以如果字串是空的，就會回傳 nil。

```swift
let str = "Hello, world!"
print(str.first) // Prints Optional("H")
print(str.last)  // Prints Optional("!")
```

你也可以用 `prefix` 和 `suffix` 方法來取得字串的子字串。
這些方法接受一個整數作為引數，並回傳包含字串前 n 個或後 n 個字元的子字串。

```swift
let str = "Hello, world!"
print(str.prefix(5)) // Prints "Hello"
print(str.suffix(6)) // Prints "world!"
```

## 深入探討：Unicode 索引

~~~~exercism/advanced

[Unicode][unicode] 是一套文字編碼標準，收錄了來自許多不同語言和文字的大量字元。
它是 ASCII 的超集，也就是說，所有 ASCII 字元同時也是 Unicode 字元。
Unicode 是變動長度的編碼，代表有些字元佔用的位元組比其他字元多。
至於為什麼這件事很重要，下一節會說明。

所以要真正看到問題，得換成其他（非英文的）語言才行。以德文中的字元 "ü" 為例（注意，這裡用的是 2 位元組的版本，另外還有 1 位元組的版本）。
它乍看之下像單一字元，但其實是兩個字元：「u」和「¨」，所以在 Python 這類語言裡印出字串 "ü" 的長度會得到 2。
不過，無論是使用者還是程式設計師，都會說它是一個字元，而 Swift 也同意我們的看法。
但為什麼 Swift 這麼做，Python 卻不呢？
答案是，Swift 採用和 Python 不同的字串表示方式。
在 Python 中，字串表示成一連串的位元組，因此字串的長度就是它在記憶體中佔用的位元組數。
在 Swift 中，字串表示成一連串的字元，因此字串的長度就是它包含的字元數。
這是個非常重要的差別，因為這代表在 Swift 裡，字串的長度不一定等於它在記憶體中佔用的位元組數。
也正因如此，我們不能用整數來索引字串。
~~~~
