# 關於

持有作業系統狀態的資源（檔案控制代碼、socket、鎖）需要有*保證*的清理，即使例外展開堆疊時也一樣。Factor 的[`destructors`][destructors]詞彙為此提供了一套小型框架，而大多數內建資源（`<file-reader>`、`<file-writer>`、socket、…）都已經與它整合。

## 類別與泛型詞

類別只要擴充 `disposable` 並實作 `dispose*`，就能加入這套機制：

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )`會配置元組，*並*將它註冊到目前的 destructor 作用域中，因此從配置到下一个安全點之間就算發生例外，也不會讓資源外洩。這套框架保證每個物件的 `dispose*` **最多只會執行一次**：重複呼叫 `dispose` 不會有任何作用。

## 外部呼叫端使用 `dispose`

| 詞                | 作用                                          |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )`：釋放；重複呼叫也安全 |
| `with-disposal`   | `( disposable quot -- )`：為單一資源建立作用域 |
| `with-destructors`| `( quot -- )`：開啟一個註冊表作用域 |
| `&dispose`        | `( obj -- obj )`：正常*或*失敗結束時都會處置 |
| `|dispose`        | `( obj -- obj )`：只在作用域展開時處置 |

`with-disposal`是單一資源的形式。若有多個資源，請開啟一個 `with-destructors` 作用域，並用 `&dispose`（你一定會想釋放它）或 `|dispose`（只在失敗時釋放，成功路徑會保留它）來註冊每一次取得的資源。

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup`是最基本的原始詞

如果只是要一次性的 try/finally，而且不需要註冊表，那麼來自 `continuations` 的[`cleanup`][cleanup]就是層級較低的詞：

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors`嚴格來說功能更強大（註冊表可以在執行階段增長），但如果取得與釋放的配對固定且侷限在本地，`cleanup`就是最自然的選擇。
