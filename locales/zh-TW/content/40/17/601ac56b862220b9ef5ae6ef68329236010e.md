# 關於

`Option`型別是標準函式庫提供的列舉。它很適合用來表示一個可能不存在的值。
雖然這聽起來很像 `null`或 `nil`，但其實截然不同，而且十分特別。

`Option<T>`可以存放其他型別，並有兩個變體：`Some(T)`和 `None`。

例如，`Option<u32>`存放的型別是 `u32`。

## 用法

### 在 `Option<T>`中使用 `T`

以下是幾種常見的慣用語，可用來取用 `Option`中可能存在的值：

- `if let Some(t) = optional { ... }`.

    `if let`慣用語會從 `Option<T>`取出值，並將它綁定到變數 `t`。這讓你可以在該區塊作用域中直接使用它。

- `match optional { Some(t) => {...}, None => {...}}`

    `match`運算子也讓你能用單一的敘述或運算式拆解並處理 `None`的情況。它是一連串 if 和 else 敘述的替代方案。使用 `match`可以提升某些程式碼段落的可讀性。
- `optional.map(|t| ...)`
   `Option::map`會根據提供的函式就地更新 Option，更新後的型別可能與原本不同。

   **注意**：如果值存在，會對所含的值進行操作。綁定會變成 `Option<U>`，其中給定的閉包是 `FnOnce(T) -> U`。
- `optional.unwrap()`.
   對 `Option<T>`進行 unwrap 會取出 `T`，但如果 `T`不存在就會 panic。在某些情況下，這麼做很省事。

   **重要**：unwrap 能在短期內或測試程式碼中讓開發更輕鬆，但會帶來在執行階段 panic 的可能性。應盡可能避免。

- `optional.expect("Unexpected None found! Aborting program.)`.
   `Option<T>`上的 `expect`方法與 `unwrap()`十分相似，但如果它的值是 `None`，就會帶著提供的訊息 panic。

## 範例

當 `Option<u32>`中存在值時：

```rust
let has_something: Option<u32> = Some(100);
assert_eq!(has_something.unwrap(), 100);
```

當 `Option<u32>`中*不存在*值時：

```rust
let has_nothing: Option<u32> = None;
assert_eq!(has_nothing, None);
```
