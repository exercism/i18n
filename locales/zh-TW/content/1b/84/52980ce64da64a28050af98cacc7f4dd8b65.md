# 關於

[呼叫堆疊][stack]，或簡稱**堆疊**，是一種特殊的資料結構，從記憶體的最高點開始，向下成長。

## Push 與 Pop

堆疊至少支援兩種操作，並有相同名稱的指令：

| 指令 | 執行的操作 |
| ---- | ---------- |
| `push` | 將元素加入堆疊 |
| `pop` | 移除並回傳最近加入的元素 |

這表示堆疊是一種**後進先出（LIFO）**的資料結構。

為了追蹤堆疊目前的位置（也就是最近加入的元素所在之處），會使用暫存器`rsp`。

因此，[push][push] 指令接受一個運算元，並將這個運算元的內容存入堆疊中。
由於堆疊向下成長，`rsp`中的值會減少所儲存值的大小。

同樣地，[pop][pop] 指令接受一個運算元，並將堆疊中最近的值（也就是`rsp`所指的值）存入該運算元。
然後，`rsp`中的值會增加所取出值的大小。

## 區域變數

也可以直接操作`rsp`的值。
這常用來為函式建立區域變數。

```x86asm
sub rsp, 24 ; this reserves 24 bytes of space in the stack
add rsp, 24 ; this restores the previous value of rsp, "reducing" the stack by 24 bytes
```

請注意，在堆疊中保留空間的當下，該空間所儲存的值是_未定義的_。

~~~~exercism/note
無論是`pop`，還是直接操作`rsp`，都不會實際移除儲存在記憶體中的內容。
堆疊的「移除」是從`rsp`中的新位址抽象出來的。

在某些情況下，這可能會因為將內部值暴露給外部來源而引發安全疑慮。
處理這個問題的一種方法，是將函式所使用的任何堆疊空間內容清零。
~~~~

## Call 與 Ret

堆疊的主要用途是追蹤被呼叫函式的回傳位址。

如先前概念所述，有一個特殊的暫存器`rip`，它指向下一個要執行的指令。
這個暫存器用來控制程式的流程，並會由`jmp`和`call`之類的指令修改。

每當使用`call`指令時，`rip`中的目前值會隱式地被推入堆疊。
接著，該指令的運算元會被移入`rip`，讓執行流程在被呼叫的函式中繼續。

`ret`指令則執行相反的動作。
它會從堆疊彈出值到`rip`，讓執行流程回到呼叫端的函式。

在進入函式時，`rsp`指向要回傳的位址。
這是`ret`必須從堆疊彈出的位址。

因此，函式內對`rsp`值的任何變更，無論是直接變更或透過`push`，都必須在函式回傳前還原。

## 被呼叫者儲存與呼叫者儲存暫存器

除了`rsp`之外，還有其他必須在函式呼叫之間保留的暫存器：`rbp`、`rbx`、`r12`、`r13`、`r14`和`r15`。
一般而言，呼叫端的函式預期可以使用這些暫存器，而不會被被呼叫的函式改變。

這表示_被呼叫_的函式必須在使用這些暫存器前先儲存其中的值，並在回傳前還原成原始值。
這就是它們被稱為**被呼叫者儲存暫存器**的原因。

其他一般用途暫存器則可直接供被呼叫的函式使用。

這表示_呼叫端_的函式必須在呼叫任何函式前先儲存這些暫存器中的值，以免它們被被呼叫的函式修改。
這就是它們被稱為**呼叫者儲存暫存器**的原因。

_最常見的暫存器內容儲存方式，就是將其存入堆疊。_

## 前導與結尾

在某些情況下，堆疊可能會被大量使用，在函式回傳前有許多修改。
因此，要追蹤所有這些變更以便還原，可能會很複雜。

在這些情況下，常見的策略是將`rsp`的位址儲存在另一個在函式內保持不變的暫存器中。
然後，`rsp`的值可以在函式回傳前，於結尾用簡單的`mov`指令還原。

雖然任何暫存器都可以用於此目的，但慣例上會使用`rbp`作為基底指標。
由於`rbp`本身是被呼叫者儲存暫存器，這通常會先執行`push rbp`。
這個序列通常稱為**前導**。

在結尾，會用`mov rsp, rbp`還原`rsp`，然後再用`pop`從堆疊還原`rbp`。
這個序列通常稱為**結尾**。

```x86asm
section .text
fn:
    ; prologue
    push rbp
    mov rbp, rsp
    ...
    ; epilogue
    mov rsp, rbp
    pop rbp
    ret
```

~~~~exercism/note
前導/結尾序列的主要用途，是幫助程式設計師追蹤`rsp`的變更。
當然，這對編譯器來說容易得多。

這就是為什麼許多編譯器會產生最佳化，盡可能省略框架指標並移除前導/結尾。
~~~~

## 使用堆疊傳遞引數

在 [System V ABI][SystemV] 呼叫慣例中，引數通常是透過暫存器傳遞給函式。
不過，當引數太多，或它們需要超過一個暫存器的大小時，就可能會使用堆疊。

在這些情況下，值會以相反順序加入堆疊，讓第一個引數較靠近`rsp`。
由於在進入函式時，`rsp`指向回傳位址，而在 x86-64 中這是 8 位元組的值，因此堆疊上的第一個引數（如果有的話）可以透過`rsp + 8`存取：

```x86asm
mov rdi, 4   ; first argument
mov rsi, 8   ; second argument
mov rdx, 15  ; third argument
mov rcx, 16  ; fourth argument
mov r8, 23   ; fifth argument
mov r9, 42   ; sixth argument

; any remaining integer argument goes on the stack in reversed order
sub rsp, 16
mov qword [rsp], 100      ; seventh argument
mov qword [rsp + 8], 300  ; eighth argument

call many_arguments_fn ; call implicitly pushes `rip` to the stack
; so, at point of entry, 'many_arguments_fn' finds the first six integer arguments in the usual registers
; the seventh argument is found in rsp + 8
; and the eighth argument is found in rsp + 16
```

## 堆疊對齊

System V ABI 規定，在執行`call`指令_之前_，堆疊必須是 16 位元組對齊。
由於`call`會將`rip`推入堆疊，因此在進入函式時，被呼叫函式的堆疊**不是** 16 位元組對齊。

這表示呼叫其他函式（尤其是外部函式）的函式，必須在使用`call`之前對齊堆疊。

這可以透過從`rsp`減去一個適當的值來完成。
在進入函式時，這個值必須是 16 的倍數再加 8：8、24、40 等等。
由於`push`指令會從`rsp`減去值，因此也可以使用奇數次的`push`來達到相同效果：

```x86asm
fn_a:
    sub rsp, 24 ; subtracting 8 more than a multiple of 16: this aligns the stack
    call fn_b
    add rsp, 24
    ret

fn_b:
    push rbx    ; odd number of pushes: this aligns the stack
    call fn_c
    pop rbx
    ret
```

## 紅色區域

System V ABI 保留了`rsp`正下方 128 位元組的空間，可以在不調整`rsp`的情況下使用。
這個空間稱為[紅色區域][red-zone]：

```x86asm
fn:
    mov [rsp - 8], rax ; this is safe to use because it is in the red zone
    ret                ; no need to restore rsp
```

紅色區域只有葉函式（也就是不會呼叫其他函式的函式）才能安全使用。
