# 陣列

`LIST{T}`是可增長的、有序的集合，底層由一個陣列支撐，當它裝滿時，會換成更大的陣列。

```sather
   notes ::= #LIST{STR};
   notes.append("muddy boots");
   notes[0]                     -- "muddy boots"
   notes[0] := "clean boots";
   notes.size
   notes.is_empty
   notes.has("clean boots")
   notes.remove_index(0);
```

## `ARRAY`還是`LIST`？

| | `ARRAY{T}` | `LIST{T}` |
| --- | --- | --- |
| 大小 | 建立時固定 | 會改變 |
| 附加 | 不行 | 可以 |
| 移除 | 不行 | 可以 |
| 索引 | `a[i]` | `l[i]` |
| 額外開銷 | 無 | 一個大小，以及預留的空間 |

當大小已知且固定時，就用`ARRAY`，例如一排舞者、1 週的計數。當東西會不斷加入或離開時，就用`LIST`。

## 原地修改，而非函式式

`append`、`remove_index`和`[i] :=`都會直接改變陣列本身。不需要把任何東西指定回去，而且把陣列交給方法處理，也不能保證它不會被改動。

這和`FMAP`與`FSET`正好相反，所以值得弄清楚自己手上拿的是哪一種。簡單的判斷原則：名稱開頭有`F`就是函式式，其他的都是原地修改。

想交出一份誰也破壞不了的陣列，就給出一個副本：

```sather
   return notes.copy;
```

## 附加的成本

附加平均來說很便宜。當底層陣列裝滿時，會取用一個 2 倍大的新陣列，並把所有內容複製過去，所以大部分的附加幾乎不花什麼成本，偶爾才付出一次複製的代價。經過大量附加之後，平均分攤下來每次的成本是固定的，這也是為什麼要一次加倍，而不是每次都只多長 1 格。

`remove_index`就不便宜了：被移除位置之後的每個元素都會往前移動 1 格。從長陣列的前端反覆移除，會慢得讓人不易察覺。

## 實用的方法

| 呼叫 | 作用 |
| --- | --- |
| `l.append(x)` | 加到末端 |
| `l.insert_before(i, x)` | 在某個位置插入 |
| `l.remove_index(i)` | 把某個位置移除 |
| `l.has(x)` | 它在不在裡面？ |
| `l.copy` | 一份獨立的副本 |
| `l.str` | 內容，放在大括號裡 |
| `l.elt!`, `l.ind!` | 逐一走訪值，或走訪位置 |
