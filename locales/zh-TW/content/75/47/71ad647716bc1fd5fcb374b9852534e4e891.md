# 測試

每個練習都會提供單元測試。
你負責提供實作。
每個檔案都會產生一個可執行測試的主控台執行檔。
執行測試執行檔時，會為每個失敗的測試印出訊息，並在測試失敗時回報非零的結束狀態。

*注意* 每次建置專案時，你的程式碼都會接受測試套組的測試。
如果你的程式碼沒有通過其中一或多個測試，但仍是有效的 D 程式碼，它依然會被編譯。

完成每個練習的過程如下：

* 用 `dub test` 執行測試
  * 如果你選擇不安裝 DUB，就改用 `dmd source/*.d -de -w -main -unittest`，然後執行產生的二進位檔。
* 對每個單元測試：
  * 解決編譯錯誤，讓測試能夠失敗。
  * 只實作剛好能讓測試通過的部分。
  * 重構你的實作，以提升可讀性、減少重複等。
  * 啟用下一個測試

*注意：* D 直接在語言層面支援單元測試，所以單元測試通常與實作放在同一個檔案裡。
單元測試會在 main 的主體之前執行，並透過 **-unittest**編譯器參數在最終執行檔中啟用。

## 解讀單元測試輸出

如果所有測試都成功，測試輸出可能看起來像這樣

```none
$ dub test
             Generating test runner configuration 'dnd-character-test-library' for 'library' (library).
    Starting Performing "unittest" build using dmd for x86_64.
    Building dnd-character ~master: building configuration [dnd-character-test-library]
     Linking dnd-character-test-library
     Running dnd-character-test-library
1 modules passed unittests
```
