# 簡介

## RFLAGs

有一個特殊的暫存器叫做 `rflags`。
它的各個位元就像是各種條件的旗標。

以下是其中一些：

| 名稱     | 符號 | 位元 |
| :------- | :----: | :-: |
| 進位    |   CF   |  0  |
| 零      |   ZF   |  6  |
| 符號    |   SF   |  7  |
| 溢位    |   OF   | 11  |

## 比較指令

`rflags` 中的旗標並_不會_被直接修改。
而是由許多不同的指令來設定。

例如，許多算術或位元運算會在結果為零時設定 `ZF`。

用來測試條件最常見的指令之一就是 `cmp`。
它接受兩個運算元並更新旗標，但**不會修改它的運算元**。

### CMP 指令

`cmp` 指令會從第一個運算元減去第二個運算元，並根據結果設定旗標。

若 A 是第一個運算元，B 是第二個：

| 旗標 | 設定時機                        |
| :--: | :----------------------------- |
|  CF  | A < B（無號）                   |
|  ZF  | A == B                         |
|  SF  | A < B（有號，無溢位）             |
|  OF  | 有號減法發生溢位                 |

## 分支

預設情況下，x86-64 的程式碼會由上而下循序執行。

但在許多情況下，必須改變這種行為。
例如，根據某個條件執行另一組指令。

在高階語言中，通常會用 `if...else` 這類抽象來完成。
不過，x86-64 並沒有這些東西。

取而代之的是，x86-64 提供了能把執行流程轉移到程式碼其他位置的指令。
這就叫做 `branching`。

~~~~exercism/note
我們已經看過兩道這樣的指令：`call` 和 `ret`。

呼叫函式時，執行流程會從呼叫者轉移到被呼叫的函式。
而返回時，執行流程會再轉移回呼叫者。

如果找不到 `ret`，執行流程會從一個函式直接落穿到下一個函式。
有時可以用這種方式來最佳化程式流程。
~~~~

### 無條件跳躍

**jmp** 指令會無條件將程式的執行流程轉移到程式碼的另一個位置。
它唯一的運算元是一個標籤，代表執行將繼續的位置的位址。

例如，看看下面的函式：

```x86asm
fn:
    mov rax, 5
    jmp end

    add rax, 10
end:
    ret
```

呼叫 `fn` 時，執行會從 `mov rax, 5` 開始。
此時會把 `rax` 中的值設為 5。

下一道指令是 `jmp end`，會把執行流程轉移到標籤 `end`。

`end` 之後的下一道指令是 `ret`，會把執行流程轉移回呼叫端函式。

注意，由於 `add rax, 10` 位在 `jmp end` 之後、`end` 之前，它永遠不會被執行。
`fn` 返回時，`rax` 的值是 5。

### 條件跳躍

**jcc** 系列指令只在符合特定條件時，才會把程式的執行流程轉移到另一個位置。
否則，執行會循序繼續。

每個條件對應到 `rflags` 中的一個或多個旗標。
有些 `jcc` 變體測試旗標是否被設定，有些則測試是否被清除。

`jcc` 中的 `cc` 並非字面上的意思，而是指與所測試旗標相關的特定後綴。

後綴有很多種，而且許多後綴測試的條件和其他後綴相同。
其中一些直接對應到某個旗標，因此當該旗標被設定時，指令就會跳到某個標籤：

| 後綴 | 跳躍時機 |
| :----: | :------: |
|   z    | ZF == 1  |
|   c    | CF == 1  |
|   s    | SF == 1  |
|   o    | OF == 1  |

還有許多後綴是為了對應它們在 `cmp` 指令中的意義而選用的。
例如：

| 指令 | 後綴 | 跳躍時機         |
| ----------- | :----: | :--------------- |
| cmp A, B    |   e    | A == B           |
| cmp A, B    |   l    | A < B（有號）     |
| cmp A, B    |   b    | A < B（無號）     |
| cmp A, B    |   g    | A > B（有號）     |
| cmp A, B    |   a    | A > B（無號）     |

可以在 `l`、`b`、`g` 或 `a` 後面加上 `e`，把相等的情況也納入條件：

```x86asm
cmp rcx, r8
jge two      ; this jumps to 'two' if rcx is greater than, or equal to, r8 in a signed comparison
jbe two      ; this jumps to 'two' if rcx is lesser than, or equal to, r8 in an unsigned comparison
```

所有後綴都有檢查相反行為的變體。
它們的語法相同，只是在後綴前面多了一個 `n`。

例如，`jnz` 會在 `ZF` **沒有**被設定時跳躍。
同樣地，`jnae` 會在 A **不**大於等於 B 時跳躍（A 和 B 解讀為無號整數）。

~~~~exercism/note
有些後綴是相同條件的別名。
例如，`jz`（後綴 `z`，代表 `ZF`）和 `je`（後綴 `e`，代表相等）都會在 `ZF` 被設定時跳躍。
這是因為使用 `cmp` 時，當減法結果為零就會設定 `ZF`，而這正對應到兩個運算元相等的情況。

不過，其他後綴測試的是多個旗標的組合，無法直接用單一旗標的後綴取代。

請優先選用最能描述你比較語意的後綴。
~~~~

## 區域標籤

標籤在整個原始檔中都可見，它們並不侷限在某個函式內。
因此無法重複使用標籤名稱。

為了模擬區域標籤的行為，NASM 對前面帶有句點（`.`）的標籤宣告有一套特殊的表示法。
這種表示法所定義的標籤，會隱含地包含前一個不帶句點的標籤名稱：

```x86asm
section .text
fn1:
    ...
.example: ; this is fn1.example
    ...
    ret

fn2:
    ...
.example: ; this is fn2.example
    ...
    ret
```

仍然可以從程式碼中的任何位置，使用完整的標籤名稱跳到這個標籤，例如 `jmp fn1.example`。

不過，若跳躍只使用標籤從句點開始的部分，就會跳到上層函式_內部_的那個標籤。
例如，`.example` 的行為就像是區域於該函式：

```x86asm
section .text
fn1:
    ...
.example:
    ...
    jmp .example ; this jumps to fn1.example

fn2:
    ...
.example:
    ...
    jmp .example ; this jumps to fn2.example
```
