# Docker

我們的 Representer 是以 Docker 映像檔的形式部署的。

請閱讀[工具的一般 Docker 資訊](/docs/building/tooling/docker)，熟悉它們的運作方式。

## 整合

當我們執行 Representer 來建立解答的 representation 時，會執行像這樣的 Docker 指令：

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-representer" \
        "${exercise_slug}" "/solution" "/output"
```

可以看到我們傳了三個引數給 Docker 映像檔：

1. 練習的 slug
2. 解答目錄的路徑
3. 輸出目錄的路徑

## 慣例

我們所有的 Representer 在實作上都遵循以下慣例：

- `Dockerfile` 位於儲存庫的根目錄。
- 工作目錄應該是 `/opt/representer`。
- 進入點是 `/opt/representer/bin/run.sh`
- `/opt/representer/bin/run.sh` 指令碼接受 3 個引數：
  1. 練習的 slug
  2. 解答目錄的路徑
  3. 輸出目錄的路徑

更多資訊請參閱[介面](/docs/building/tooling/test-runners/interface)。

```exercism/note
新的 representer 儲存庫預設會採用這些慣例。
```
