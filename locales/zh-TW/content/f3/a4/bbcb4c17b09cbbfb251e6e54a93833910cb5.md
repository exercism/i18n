# 關於

遞迴函式是會呼叫自己的函式。

一個遞迴函式至少需要一個_基本情況_，以及至少一個_遞迴情況_。

_基本情況_會在不再次呼叫函式的情況下回傳一個值。
_遞迴情況_會再次呼叫函式，並修改輸入，讓它在某個時間點符合基本情況。

在 Elm 中，遞迴函式通常會使用模式比對搭配`case`運算式來定義。

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

一個遞迴函式可以有很多個基本情況，也可以有很多個遞迴情況。
舉例來說，[費波那契數列][fibonacci]就是一個帶有兩個基本情況的遞迴數列：

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

請注意，這個特定的實作慢得呈指數成長，因為相關的費波那契數會在兩個獨立的遞迴呼叫中從頭算起。

計算某個給定的值`x`在陣列中出現的次數，會有兩個遞迴情況：

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## 透過遞迴進行迴圈

由於不可變性，Elm 中的迴圈寫法和指令式語言不同。
舉例來說，迴圈通常看起來像這樣：

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

在像 Elm 這樣的函式式語言中，無法修改變數。
因此，迴圈必須用遞迴來實作。

在 Elm 中，`for`迴圈的對等寫法會像這樣：

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

實務上，在 Elm 中疊代陣列和其他資料結構時，最常使用[`List`][module-list]模組裡的函式，例如`List.map`、`List.filter`和`List.foldl`。
在底層，這些函式都是用遞迴實作的。

## 無限執行

遞迴函式如果實作錯誤，或是遞迴呼叫的次數太多，可能永遠不會回傳結果。
這可能會造成問題，因為每次呼叫函式時，執行環境都會在記憶體中儲存一個參考，記錄應該從哪裡回傳結果（就在[呼叫堆疊][wiki-call-stack]上）。
如果一個遞迴函式呼叫自己太多次，甚至無限次，就可能耗盡記憶體，導致執行環境崩潰（也就是[堆疊溢位錯誤][wiki-stack-overflow]）。
Elm 的執行環境針對遞迴和可靠性做了最佳化，但無限遞迴仍然可能造成問題。

這種無限執行的問題，可能由下列原因造成：

- 忘記實作基本情況。
- 沒有在模式比對中處理所有可能的情況。
- 進行遞迴呼叫時沒有正確修改引數，因此永遠無法到達基本情況。
