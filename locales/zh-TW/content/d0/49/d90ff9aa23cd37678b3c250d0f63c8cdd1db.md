# 關於

程式設計師通常會努力寫出完美的軟體，但通常會失敗。

事情總會出乎意料地出錯，而我們必須有能力應付。

有些程式語言的設計者認為，最重要的是盡快偵測到錯誤，然後帶著有助於除錯的說明訊息終止執行。

資料科學領域的程式語言則傾向採取更細緻的做法。
有些錯誤嚴重到必須立刻終止，但很多時候，比較好的做法是把問題標記成之後再處理的事項，然後繼續執行。

我們在[虛無][nothingness]概念中看過，Julia 為有問題的值提供了幾種佔位符：[`missing`][nothing]、[`NaN`][NaN]和`Inf`。
這些做法在特定情況下是否比直接終止程式更好，取決於程式設計師的判斷。

_先談一下用詞_，再進入細節：Julia 的文件把「error」和「exception」這兩個詞大致視為可互換。
以下內容可能也一樣前後不一致。

## 標準錯誤型別

讀到課程大綱的這個階段，你一定已經看過許多 Julia 的錯誤訊息。
例如：

```julia-repl
julia> Int(3.14)
ERROR: InexactError: Int64(3.14)
```

把浮點數轉型成整數會損失精度，所以我們會得到`InexactError`。

`InexactError`是一種型別，是 Julia 內建的幾種標準型別之一（[目前有 25 種][errors]）。
它們全都是`Exception`的子型別：

```julia-repl
julia> supertype(InexactError)
Exception
```

## `throw()`

有些標準錯誤型別可能很適合在你自己的程式中產生。

和所有具體型別一樣，這些錯誤都有建構函式。
它們接受的引數各不相同，所以想用哪一種，請查閱[文件][errors]。

```julia-repl
julia> DomainError(42, "out of range")
DomainError(42, "out of range")
```

要使用這個錯誤，請把建構函式包進 [`throw()`][throw]函式裡：

```julia-repl
julia> throw(DomainError(42, "out of range"))
ERROR: DomainError with 42:
out of range
```

## `error()`

如果想快速了事，[`error()`][error]函式會很方便。
它接受一個字串（或字串的各個組成部分）作為引數：

```julia-repl
julia> happy = false;
julia> happy || error("😞 something went wrong")
ERROR: 😞 something went wrong
```

## 自訂錯誤

建立新的錯誤型別基本上非常簡單。
只要再加上一個`Exception`的子型別就好：

```julia-repl
julia> struct MyError <: Exception end

julia> throw(MyError)
ERROR: MyError
```

不過，上面的範例沒有任何欄位，建構函式也不接受引數，所以我們無法控制錯誤訊息。
我們可以加上一個訊息欄位：

```julia-repl
julia> struct AnotherError <: Exception
           msg::String
       end

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError("Wrong!")
```

單純把建構函式印出來還不太對。
比較一下先前擲出`DomainError`的例子。

要讓自訂錯誤能和內建錯誤以相同的方式處理，我們需要加上一個 [`showerror()`][showerror]方法：

```julia-repl
julia> Base.showerror(io::IO, e::AnotherError) =
           print(io, "AnotherError: ", e.msg)

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError: Wrong!
```

這個文件記載得相當少的功能，本質上是把我們的自訂錯誤型別接進 Julia 標準的錯誤處理系統。

## 斷言

斷言的基本想法是：「這個敘述應該為真，所以如果它為假，就大聲抱怨。」
這樣做的好處主要是在除錯期間，因為正式環境的程式碼不應該讓斷言失敗。

我們在[型別][types]概念中看過，我們可以加上型別斷言，例如檢查函式的回傳型別。

```julia-repl
julia> 42::Number
42

julia> "two"::Number
ERROR: TypeError: in typeassert, expected Number, got a value of type String
```

更一般來說，[`@assert`][assert]巨集讓我們可以測試任何求值結果為布林的運算式：

```julia-repl
julia> n = 22;
julia> @assert isodd(n) "n must be odd"
ERROR: AssertionError: n must be odd
```

## `try`...`catch`

有些錯誤必然是致命的，但我們通常期望程式能優雅地復原。

預設情況下，錯誤會立刻終止目前的函式，而這個錯誤（連同任何說明訊息）會傳遞給呼叫它的函式。

這個過程會沿著呼叫堆疊一路往上，直到最上層的程式碼帶著錯誤訊息終止。

在任何階段，都可以用 [`try...catch`][try-catch]區塊攔截這個錯誤，試著處理它。

```julia-repl
julia> n = -1;
julia> try
           log_n = log(n)
       catch problem
           if problem isa DomainError # number out of range
               # See next section for more on @warn and @info
               @warn "you may have supplied a negative real number: $n"
               @info "trying with complex argument"
               log_n = log(Complex(n))  # fallback calculation

           elseif problem isa MethodError # no idea what n is
               @error "please supply a valid argument"
 
           else
              rethrow() # the error could be anything else
           end
      end
┌ Warning: you may have supplied a negative real number: -1
└ @ Main REPL[3]:5
[ Info: trying with complex argument
0.0 + 3.141592653589793im  # success
```

在上面的例子中，`log(n)`需要`n`是正實數，或是任意的複數。
`try ... catch`會攔截負實數造成的問題，並以數學符號回傳正確的複數答案`iπ`。

如果你傳入的（比如說）是字串引數，那就無法補救，只能請使用者更正。

作為最後的萬能收尾，我們加上了 [`rethrow()`][rethrow]，用來應付既不是`DomainError`也不是`MethodError`的情況。

另外還有一些可選的子句：

- [`else`][else]，在`try`子句成功時執行；
- [`finally`][finally]，不論`try`成功或失敗都可以用來清理外部資源：關閉檔案、中斷資料庫連線...

***注意：***有時候你確實需要`try...catch`，但請避免過度使用。
如果可以改用`if...else`區塊，效能會比捕捉例外好得多。

## 記錄

請注意，上面討論過的`error()`函式不該和 [`@error`][error_macro]巨集混為一談。

這個函式會產生例外，除非被攔截，否則會沿著呼叫堆疊往上傳遞。

`@error`巨集，以及和它對應的 [`@debug`][debug_macro]、[`@info`][info_macro]和 [`@warn`][warn_macro]，都是 [`Logging`][logging]模組的一部分，目的是在不改變程式流程的情況下產生說明訊息。

輸出預設會送到終端機（依嚴重程度以顏色區分），不過在實際的應用程式中還有許多其他可能。

```julia-repl
julia> @warn "Something looks not quite right"
┌ Warning: Something looks not quite right
└ @ Main REPL[55]:1

julia> @error "Panic!"
┌ Error: Panic!
└ @ Main REPL[56]:1
```
