# 提示

## 一般

- 打包比較會寫入一個**遮罩**：條件成立時，每個通道都會設為全 1，不成立時則全為 0。
- 浮點比較會把條件當成立即值，或者你也可以使用 NASM 的虛擬指令，例如`cmpltps`和`cmpeqps`。
- 整數比較則把條件當成後綴：`pcmpgtd`代表有號大於，`pcmpeqd`代表相等。
- 這些區塊是 16 位元組對齊的，所以`movaps`和`movdqa`都可以安全使用。

## 1. 標記高於門檻的分數

- `a > b`等同於`not (a <= b)`（立即值 6），也等同於`b < a`（立即值 1，運算元對調）。
- 相等不能算成高於門檻。

## 2. 標記滿分

- 這是直接使用`cmpeqps`的浮點相等比較。
- 把分數和最大值比較。
  兩者相符時，對應的通道就會被設定。

## 3. 指定等級

- 你可以把門檻`50.0`和等級值`1`、`2`、`3`定義成記憶體中的打包常數，每個各佔四個通道。
- 你可以定義兩個遮罩。
  一個代表「高於門檻」，如同任務 1（但改成和打包常數`50.0`比較）。
  另一個代表「滿分」（如同任務 2）。
- 基本等級是`1`。
  「高於門檻」遮罩被設定的通道，應選用等級`2`。
  滿分遮罩被設定的通道，應選用等級`3`。
- 滿分同時也高於門檻。
  如果先套用「高於門檻」遮罩，滿分遮罩會在必要之處正確地覆蓋它。
- `blendvps`會從`xmm0`取得遮罩，並根據每個通道的最高位元來選擇。
  對於這個位元被設定的通道，它會從來源運算元選取。
  其他通道則保留目的運算元中原本的通道值。

## 4. 計算不及格的數量

- 當等級嚴格低於門檻時就算不及格，也就是`threshold > rank`。
  你可以使用`pcmpgtd`，把門檻當作目的運算元，等級當作來源運算元。
- 對每個區塊，可以用`movmskps`把未達門檻的遮罩壓縮進一般用途暫存器，取出每個通道的最高位元。
  這個一般用途暫存器的大小可以是 32 位元或 64 位元。
- 你可以用`popcnt`計算一般用途暫存器中設定的位元數量。
- 區塊可能不只一個，所以需要一個迴圈來逐一疊代並累加結果。
- 每個區塊是 16 位元組。

## 5. 所有人都通過了嗎？

- 「所有人都通過」在未達門檻的遮罩中會表示為全為 0 的結果。
  只要有一個通道不是 0，結果就是 false。
- 區塊可能不只一個，所以需要一個迴圈來逐一疊代並累加結果。
- 每個區塊是 16 位元組。
- 對同一個暫存器自身使用`ptest`，可以檢查是否全為 0。
- OR 運算會保留設定的位元，AND 運算則保留清除的位元。
  兩者都可以在迴圈中用來累加邏輯值。
- 可以用`setcc`把旗標轉換成`0/1`的結果。
