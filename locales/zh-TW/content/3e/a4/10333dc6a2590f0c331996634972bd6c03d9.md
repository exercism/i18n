# 關於

協定是：

- 一種實現多型的機制。
- 用[`defprotocol`][defprotocol]定義。
- 用[`defimpl`][defimpl]為特定資料型態實作。

協定的一大優勢，在於為特定資料型態實作的協定不需要與該資料型態的定義或協定的定義綁在一起。如此一來，你就能寫出讓使用者輕鬆擴充的函式庫，使它們支援使用者自訂的資料型態，而不必修改函式庫本身。

## 實作

可以為所有 Elixir 型別實作協定：`Tuple`、`Atom`、`List`、`BitString`、`Integer`、`Float`、`Function`、`PID`、`Map`、`Port`、`Reference`、`Any` 以及 struct。

協定可以一次為多個型別實作：

```elixir
defimpl Reversible, for: [Map, List] do
  def reverse(term) do
    Enum.reverse(term)
  end
end
```

直接在定義該 struct 的模組內為該 struct 實作協定時，可以省略`:for`引數：

```elixir
defmodule ShoppingCart do
  defstruct [:items]

  defimpl Reversible do
    def reverse(shopping_cart) do
      Enum.reverse(shopping_cart)
    end
  end
end
```

## 後備至 `Any`

根據預設，對尚未實作某協定的資料型態呼叫該協定，會引發`Protocol.UndefinedError`錯誤：

```elixir
to_string({})
# => ** (Protocol.UndefinedError) protocol String.Chars not implemented for {} of type Tuple
#        (elixir 1.10.3) lib/string/chars.ex:3: String.Chars.impl_for!/1
#        (elixir 1.10.3) lib/string/chars.ex:22: String.Chars.to_string/1
```

你可以提供一個在這種情況下使用的後備實作來避免這個問題。做法是在定義協定時，把[`@fallback_to_any` 模組屬性][fallback-to-any]設為`true`，並為`Any`型別撰寫一個實作：

```elixir
defprotocol Reversible do
  @fallback_to_any true
  def reverse(term)
end

defimpl Reversible, for: Any do
  def reverse(term) do
    term
  end
end
```

請注意，大多數情況下，引發錯誤是比較好的做法，因為很難對_所有_資料型態的協定做出合理的假設。

## 值得注意的內建協定

- [`Enumerable`][enumerable]：來自`Enum`和`Stream`模組的函式，可與實作此協定的資料型態搭配運作。
- [`Collectable`][collectable]：[`Enum.into/2`][enum-into]函式會使用此協定，把可列舉項目插入集合中。
- [`Inspect`][inspect]：你可以實作此協定，改變[`Kernel.inspect/2`][kernel-inspect]把特定資料型態表示為字串的方式。
- [`String.Chars`][string-chars]：你可以實作此協定，改變[`Kernel.to_string/1`][kernel-to-string]把特定資料型態表示為字串的方式。
