# 簡介

如果一個函式_最後_執行的事情是呼叫自己，這個函式就是[尾遞迴][recursion-tc]。

每次呼叫任何函式時，帶有區域變數和引數的_堆疊框架_會被放到[函式呼叫堆疊][call-stack]的最上層。
當函式回傳時，這個堆疊框架就會從堆疊中移除。

尾遞迴函式可以進行[尾呼叫最佳化][tail-call-optimization]（或稱尾呼叫消除）。
這種最佳化讓下一次函式呼叫可以重複使用上一個堆疊框架，因為可以保證前一個函式不再需要它了。
這能減緩函式呼叫堆疊溢位的問題；當函式呼叫堆疊上的框架太多，以致於沒有記憶體可以再建立新的框架時，就會發生堆疊溢位。

## Elm 中的尾呼叫最佳化

在某些條件下，Elm 編譯器在編譯成 JavaScript 時能夠自動進行尾呼叫最佳化。

當一個遞迴函式中某個分支的_最後_一個操作是以簡單的函式應用呼叫函式本身時，這種最佳化就會發生。
我們來看幾個例子：

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

上面的實作不是尾遞迴，因為`else`分支的最後一個操作是乘法`n *`。

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

上面的實作是尾遞迴，因此會被最佳化，因為`else`分支的最後一個操作是`factorialHelper`呼叫自己。
對於型別簽章為`Int -> Int`的函式來說，這是不可行的；實務上，尾呼叫最佳化通常是透過定義輔助函式來達成。
