# 簡介

**呼叫堆疊**（或簡稱**堆疊**）是一種特殊的資料結構，它從記憶體的最高點開始，並向下成長。

## 推入與彈出

堆疊至少支援兩種操作，分別有同名的指令：

| 指令   | 執行的操作                     |
| ------ | ------------------------------ |
| `push` | 將元素加入堆疊                 |
| `pop`  | 移除並回傳最近加入的元素       |

這表示堆疊是一種**後進先出（LIFO）**的資料結構。

為了追蹤堆疊目前的位置，也就是最近加入的元素所在之處，我們會使用暫存器`rsp`。

因此，`push`指令會接受一個運算元，並將這個運算元的內容存入堆疊。
由於堆疊向下成長，`rsp`的值會減少所儲存值的大小。

同樣地，`pop`指令會接受一個運算元，並把堆疊中最近的值（也就是`rsp`所指的那個）存入其中。
接著，`rsp`的值會增加所取出值的大小。

## 區域變數

我們也可以直接操作`rsp`的值。
這經常被用來為函式建立區域變數。

```x86asm
sub rsp, 24 ; this reserves 24 bytes of space in the stack
add rsp, 24 ; this restores the previous value of rsp, "reducing" the stack by 24 bytes
```

請注意，在堆疊中保留空間的當下，該空間所儲存的值是_未定義的_。

~~~~exercism/note
無論是`pop`，還是直接操作`rsp`，其實都沒有真正移除記憶體中所儲存的內容。
堆疊的「移除」只是透過`rsp`中的新位址來抽象表示。

在某些情況下，這可能會將內部的值暴露給外部來源，因而帶來安全上的疑慮。
應對的方法之一，是把函式所使用的任何堆疊空間內容全部清零。
~~~~

## 呼叫與返回

堆疊的主要用途，是追蹤被呼叫函式的返回位址。

正如前一個概念所提到的，有一個特殊的暫存器叫做`rip`，它指向下一條要執行的指令。
這個暫存器用來控制程式的流程，它會被`jmp`和`call`等指令修改。

每當使用`call`指令時，`rip`中目前的值會隱含地被推入堆疊。
接著，該指令的運算元會被移入`rip`，讓執行流程在被呼叫的函式中繼續進行。

`ret`指令則執行相反的動作。
它會從堆疊彈出並存入`rip`，讓執行流程返回呼叫它的函式。

在進入函式時，`rsp`指向即將返回的位址。
這就是`ret`必須從堆疊彈出的位址。

因此，函式內對`rsp`值的任何變更，無論是直接修改還是透過`push`，都必須在函式返回前還原。

## 被呼叫者儲存與呼叫者儲存暫存器

除了`rsp`之外，還有其他必須在函式呼叫之間保持不變的暫存器：`rbp`、`rbx`、`r12`、`r13`、`r14`和`r15`。
一般而言，呼叫的函式會期望自己在使用這些暫存器時，它們不會被被呼叫的函式改變。

這表示_被呼叫_的函式在使用這些暫存器前，必須先儲存其中的值，並在返回前將它們還原成原本的值。
這就是它們被稱為**被呼叫者儲存暫存器**的原因。

其他通用暫存器則可以直接供被呼叫的函式使用。

這表示_呼叫者_函式在呼叫任何函式前，必須先儲存這些暫存器中的值，以防它們被被呼叫的函式修改。
這就是它們被稱為**呼叫者儲存暫存器**的原因。

_儲存暫存器內容最常見的方式，就是將它存入堆疊。_

## 序言與結語

在某些情況下，堆疊可能會被大量使用，在函式返回前發生許多變更。
因此，要追蹤所有這些變更並將它們全部還原，可能會很複雜。

在這些情況下，常見的做法是把`rsp`的位址儲存在另一個在函式內保持不變的暫存器中。
然後，在函式返回前的最後，用一條簡單的`mov`指令就能還原`rsp`的值。

雖然任何暫存器都可以用在這個用途上，但依照慣例會使用`rbp`作為基底指標。
由於`rbp`本身就是被呼叫者儲存暫存器，因此通常會先執行`push rbp`。
這個順序通常稱為**序言**。

在最後，`rsp`的還原會透過`mov rsp, rbp`完成，接著`rbp`也會從堆疊中以`pop`還原。
這個順序通常稱為**結語**。

```x86asm
section .text
fn:
    ; prologue
    push rbp
    mov rbp, rsp
    ...
    ; epilogue
    mov rsp, rbp
    pop rbp
    ret
```

## 使用堆疊傳遞引數

在 System V ABI 呼叫慣例中，引數通常透過暫存器傳遞給函式。
然而，當引數太多，或它們需要的空間超過一個暫存器的大小時，就可能會使用堆疊。

在這些情況下，值會以相反的順序加入堆疊，讓第一個引數最靠近`rsp`。
由於在進入函式時，`rsp`指向返回位址，而在 x86-64 中這是一個 8 位元組的值，因此堆疊上的第一個引數（如果有的話）可以透過`rsp + 8`來存取。

## 堆疊對齊

System V ABI 規定，堆疊必須在`call`指令執行_之前_就完成 16 位元組對齊。
由於`call`會把`rip`推入堆疊，因此在進入被呼叫的函式時，其堆疊**並非** 16 位元組對齊。

這表示，一個會呼叫其他函式（尤其是外部函式）的函式，在使用`call`之前必須先對齊堆疊。

這可以透過從`rsp`減去一個適當的值來完成。
在進入函式時，這個值必須比 16 的倍數多 8：8、24、40，依此類推。
由於`push`指令會從`rsp`減去值，因此使用奇數次的`push`也能達到相同的效果：

```x86asm
fn_a:
    sub rsp, 24 ; subtracting 8 more than a multiple of 16: this aligns the stack
    call fn_b
    add rsp, 24
    ret

fn_b:
    push rbx    ; odd number of pushes: this aligns the stack
    call fn_c
    pop rbx
    ret
```
