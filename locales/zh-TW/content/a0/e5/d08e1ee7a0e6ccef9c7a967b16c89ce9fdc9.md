# 關於

[SIMD][SIMD] 概念引進了封裝的浮點值：多個數字保存在同一個`xmm`暫存器中，並以通道為單位平行運算。
同樣的`xmm`暫存器也能保存封裝的_整數_。

## 語法

SIMD 浮點模型的大部分內容都能原封不動地套用到封裝整數：

- 128 位元的暫存器會分割成多個通道
- 指令會平行作用於相同位置的通道
- 記憶體運算元遵循相同的 16 位元組對齊規則

不過，語法略有不同：

1. 用一個_前綴_`p`表示指令操作的對象是_封裝_資料。
2. 所要執行的運算，名稱與其非 SIMD（也稱為_純量_）的對應版本相同（例如 `add`、`mul` 等）。
3. 用一個後綴表示每個通道的大小。

封裝整數有四種通道大小，每種都有自己的後綴：

| 通道寬度 | 位元組 | 128 位元中的通道數 | 後綴 |
|------------|-------|-------------------|--------|
| byte       | 1     | 16                | b      |
| word       | 2     | 8                 | w      |
| dword      | 4     | 4                 | d      |
| qword      | 8     | 2                 | q      |

例如：

| 指令 | 意義                              |
|-------------|--------------------------------------|
| `paddb`     | 封裝的 `add`，8 位元通道（16 個通道） |
| `paddw`     | 封裝的 `add`，16 位元通道（8 個通道） |
| `paddd`     | 封裝的 `add`，32 位元通道（4 個通道） |
| `paddq`     | 封裝的 `add`，64 位元通道（2 個通道） |

有些指令的輸入通道是一種大小，輸出卻是另一種大小。
它們遵循同樣的一般慣例，但帶有_兩個_大小後綴。
第一個表示輸入通道的大小，第二個表示輸出通道的大小：

| 指令  | 意義                                           |
|--------------|---------------------------------------------------|
| `pmovsxwd`   | 封裝的 `movsx`，從 16 位元通道轉為 32 位元通道 |
| `pmuldq`     | 封裝的 `mul`，從 32 位元通道轉為 64 位元通道   |

## 記憶體搬移

有兩個以整數命名的指令會在`xmm`暫存器與記憶體之間複製 128 位元：

| 指令 | 說明                                             |
|-------------|---------------------------------------------------------|
| `movdqa`    | 將封裝整數複製到_已對齊_的位置，或從該位置複製出來   |
| `movdqu`    | 將封裝整數複製到_未對齊_的位置，或從該位置複製出來 |

它們的行為與`movaps`和`movups`相同：位址未對齊時，`movdqa`會觸發錯誤，`movdqu`則接受任何位址。
這四個指令都會複製 128 位元，但不加以解讀。
這對以整數命名的指令依慣例搭配整數資料使用，並非強制要求。

~~~~exercism/note
這裡的`dq`代表`double-qword`，也就是 128 位元（16 位元組）。
~~~~

## 加法與減法

加法與減法遵循上述的命名規則：

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

沒有分別的有號與無號形式。
在二補數中，無論通道被解讀為有號或無號，加法與減法產生的位元都相同，所以一個指令就能同時滿足兩者。
該如何解讀由你決定，就和純量的`add`與`sub`一樣。

這些指令在溢位時會**環繞**，就像它們的純量對應版本一樣。
8 位元的通道所保存的值以 256 為模，所以對`200 + 100`執行`paddb`會得到`300 - 256 = 44`，放不下的位元會被捨棄。

請注意，這些多出來的位元不會進位到下一個通道。
雖然各通道共用同一個暫存器，但每個通道都是獨立運算的。

## 飽和加法與減法

整數 SIMD 多了一項浮點 SIMD 沒有的運算：[飽和][saturation]加法與減法，它們會_夾限_而非環繞。
結果高於通道的範圍時，會變成該通道能保存的最大值；低於範圍時，則變成最小值。

飽和形式會在大小後綴前面插入`s`（有號）或`us`（無號）：

| 指令 | 意義                                    |
|-------------|--------------------------------------------|
| `paddsb`    | `add`，飽和，有號 8 位元通道      |
| `paddusb`   | `add`，飽和，無號 8 位元通道    |
| `psubsw`    | `sub`，飽和，有號 16 位元通道     |
| `psubusw`   | `sub`，飽和，無號 16 位元通道   |

夾限範圍就是對應大小與正負號性的整數所能完整表示的範圍。
以 byte 為例：

- 無號 byte 夾限在`[0, 255]`：對`200 + 100`執行`paddusb`會得到`255`，對`5 - 10`執行`psubusb`則得到`0`。
- 有號 byte 夾限在`[-128, 127]`：對`100 + 50`執行`paddsb`會得到`127`。

當通道保存的是有範圍限制的量，例如像素通道或音訊取樣時，飽和就很重要。
環繞會讓過亮的像素變暗，夾限則會讓它保持在最大亮度，這才是你想要的結果。

~~~~exercism/note
飽和加減法只適用於 byte 與 word 通道，沒有 dword 或 qword 的版本。
~~~~

## 乘法

兩個 N 位元的值相乘可能產生 2N 位元的乘積，但目的通道只有 N 位元寬。
SIMD 運算的處理方式，是明確指定要保留乘積的哪一半，也就是低 N 位元或高 N 位元。

針對 16 位元通道，會用到三個指令：

| 指令 | 意義                                                       |
|-------------|---------------------------------------------------------------|
| `pmullw`    | `mul`，16 位元通道，保留每個乘積的低 16 位元     |
| `pmulhw`    | `mul`，16 位元通道，保留高 16 位元，有號運算元   |
| `pmulhuw`   | `mul`，16 位元通道，保留高 16 位元，無號運算元 |

無論運算元被解讀為有號或無號，乘積的低 16 位元都相同，所以只有一個`pmullw`。

不過，高 16 位元會隨著結果的正負號性而不同。
這就是為什麼取高半部的乘法會分別為有號與無號乘法提供不同的形式：

1. `pmulhw`，用於有號乘法。
2. `pmulhuw`，多了一個`u`，用於無號乘法。

請注意其語法：

1. `p`，代表封裝整數。
2. 所要執行的運算`mul`。
3. `h`，表示選取結果的上半部（「高」）位元。
4. 可選的`u`，表示結果應解讀為無號（也就是不進行符號擴展）。
5. 最後是大小後綴`w`，表示這是 word（16 位元）運算。

word 的封裝乘法完全遵循上述規則。
dword（32 位元）乘法也遵循這個規則，但只有選取低半部的那種變體：`pmulld`。

dword 乘法沒有選取高位元的變體。
不過，有些變體會_加寬_乘法，保存_偶數索引_通道（也就是位置 0 與 2 的通道）的完整 64 位元乘積：

| 指令 | 意義                                                                          |
|-------------|----------------------------------------------------------------------------------|
| `pmuludq`   | 將偶數索引的 32 位元元素以無號方式相乘，得到 2 個完整的 64 位元乘積 |
| `pmuldq`    | 將偶數索引的 32 位元元素以有號方式相乘，得到 2 個完整的 64 位元乘積   |

請注意，這裡的語法用的是`dq`，無號乘法時前面可能會多一個`u`。
這是因為這些指令接受`dword`通道，輸出`qword`通道。

## 除法

封裝整數沒有除法。
需要除法的程式碼會先把值轉成浮點數，相除之後再轉換回來。

## 加寬整數

`movsx`與`movzx`都有封裝版本。
它們遵循我們先前提到、用於輸入與輸出通道大小不同的指令的同一套語法：

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

請注意，通道的數量由較大的一方（輸出寬度）決定。
指令會從來源的低半部讀取那麼多個通道。
這和我們在單精度與雙精度浮點數之間的封裝`cvt`指令所看到的語意相同。

## 整數與浮點數之間的轉換

有些指令可以在 32 位元有號整數與浮點通道之間轉換。
它們遵循`cvt`與`cvtt`指令的一般語法，但封裝整數是以`dq`表示，而非`si`：

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
使用`pi`代表封裝整數的指令會寫入舊版的`mmx`暫存器，在 x86-64 上實際上已經棄用。
請改用`dq`形式，它們使用`xmm`暫存器。
~~~~

先前針對浮點數與整數之間的純量轉換所做的說明，在這裡同樣適用。
浮點數會依照一個名為 MXCSR 的特殊暫存器進行捨入，你無法假設函式進入時該暫存器處於哪種模式。
有一個`cvtt`變體（多了一個`t`），它一律會截斷結果。

也可以在轉換前先用`round`讓封裝浮點值處於已知的狀態。
`round`的控制值與純量`round`相同，封裝浮點值的語法也一樣：

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
