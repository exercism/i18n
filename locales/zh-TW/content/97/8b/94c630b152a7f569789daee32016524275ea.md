# 簡介

在 C++ 中，宣告經常和定義分開。宣告會被集中到所謂的標頭檔裡，而各自的實作則放在原始檔中。你可以把標頭檔想成是一組 API。標頭檔會告訴你一份程式碼基底提供了_什麼_，而不會深入說明_如何_做到。

## 標頭檔與原始檔

標頭檔最常見的副檔名是`.h`。有些專案會用`.hpp`，或完全不寫副檔名。

定義則放在另一個`.cpp`檔中。為了把這兩個部分重新接起來，原始檔會在一開始_引入_對應的標頭檔。

假設你想寫一個叫做「quick_math」的函式庫，它提供一個你想經常使用的函式「super_root」，那麼檔案看起來會像這樣：

```cpp
// A file named quick_math.h
#pragma once

namespace quick_math {

double super_root(double x, int n);

}  // namespace quick_math
```

```cpp
// A file named quick_math.cpp
#include <cmath>

#include "quick_math.h"

double quick_math::super_root(double x, int n) {
    while (n) {
        x = std::sqrt(x), --n;
    }
    return x;
}
```

如果你需要引入的標頭檔只有實作會用到，那麼對應的`#include`那一行只需要寫在原始檔裡。標頭檔裡引入的所有東西，在`.cpp`檔裡也同樣能用，例如下面範例中的`string`函式庫。**注意**：標頭檔中的宣告後面需要`;`，但原始檔中的定義後面則不需要。

## 類別與標頭檔

類別可以變得非常複雜，它們和標頭檔與原始檔之間的分工關係也可能令人困惑。一種可能的安排方式，是把所有實作細節留在原始檔，並把所有宣告和成員變數放在標頭檔中：

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0);
    void give_water();
    std::string get_name();
    int get_size();
    void start_next_day();
};

}  // namespace robots

#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"

robots::Flower::Flower(std::string name, int size) {
    this->name = "Robotica " + name;
    this->size = size;
}

void robots::Flower::start_next_day() {
    if (!needs_water) {
        ++size;
    }
    needs_water = true;
}

std::string robots::Flower::get_name() { return name; }

int robots::Flower::get_size() { return size; }
```

當標頭檔被當作 API 總覽使用時，人們就會在裡面尋找預設值這類資訊。因此，建構子的`size`參數預設值會寫在標頭檔中，而不是在實作裡。原始檔中的定義會冠上命名空間`robots`和類別`Flower`的前綴。

另一種安排方式是_僅有標頭檔_的函式庫，它完全沒有`.cpp`檔：

```cpp
// A file named robot_flower.h
#pragma once

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0) {
        this->name = "Robotica " + name;
        this->size = size;
    }
    void give_water() { needs_water = false; }
    std::string get_name() { return name; }
    int get_size() { return size; }
    void start_next_day() {
        if (!needs_water) {
            ++size;
        }
        needs_water = true;
    }
};

}  // namespace robots
```

專案可能會混用這些安排方式，而哪一種最適合哪一種使用情境，則有許多討論。

## 引入防護

你可能注意到上面範例標頭檔裡的`#pragma once`這一行。這就是所謂的引入防護，它能確保檔案內容在編譯期間只被引入一次，以避免發生錯誤。引入防護還有另一種更複雜的變體，它以`#ifndef`開頭、以`#endif`結尾。它的用途相同，用法則展示於上面的`Flower`類別範例中。
