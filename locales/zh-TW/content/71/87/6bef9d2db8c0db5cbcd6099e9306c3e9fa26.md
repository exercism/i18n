# 關於

## 複合型別

在程式中定義自訂型別通常很有用。

建立新的原始型別雖然可行，但很少這麼做。
內建的[原始型別][primitive]並不是隨便挑的：它們與 Julia 用於 JIT 編譯的 LLVM 編譯器中的標準型別密切對應。

更有用的是定義帶有具名欄位的[複合型別][composite-types]。

其他語言也有類似的東西，稱之為`structs`或`records`。
Julia 的文件稱之為`composite types`，不過（有點不一致的是）這個語言的語法是用`struct`關鍵字來定義它們。

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

上面的範例有幾點值得注意：

- 沒有為`id`指定型別，所以編譯器會把它解讀成`id::Any`。
  - **注意：**實際上，最好用具象型別指定欄位的型別，來幫助編譯器。
  - 我們會在之後的[概念][parametric]中看到，使用參數是另一種選項。
- 型別名稱會被當作建構子使用，例如`Person(id, name, age)`，用來取得一個型別為`Person`的實例。
- 個別欄位可以用點記法存取，就跟[具名元組][named-tuple]一樣。

`Person`型別的項目是不可變的，所以不允許更新。

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

如果需要可變性，就在定義中加上`mutable`。

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

建構子預設要求欄位出現的順序與定義時相同，這對比較複雜的型別來說就變得不方便了。

使用`@kwdef`巨集可以帶來兩項新能力：

- 建構子使用關鍵字，而不是位置。
- 欄位可以有預設值，也可以選擇在建構子中省略。

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## 複合型別的階層

到目前為止，我們只建立了具體的複合型別。
如果你檢查一下，它們全都是`Any`的子型別。

當你要建立多個彼此相關的型別時，為它們定義一個階層可能更合理。
這做起來非常容易。

首先，建立一個抽象型別：

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

接著，在型別定義中加入`<:`運算子，來表示彼此的關係。

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

視需要重複這個做法，但要記得具體型別不能有子型別。

若階層更複雜，就視需要建立抽象子型別。

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

等我們學到`Multiple Dispatch`概念，看到函式如何處理引數型別時，就會更明白這樣的階層有什麼用處。


## 內部建構子

我們在這個概念開頭看到，型別的名稱會被當作建構子使用，用來建立該型別的項目：

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)
```

在這裡，`Person()`稱為`outer constructor`。
欄位型別會被檢查是否與型別定義相容，必要時會引發錯誤。

假設我們想對傳入的_值_施加限制，而不只是對_型別_呢？

那麼我們可以在型別定義裡加入`inner constructor`，來執行適當的檢查。

舉例來說，我們有個抽象型別`AbstractPoint`，打算用來表示`(x, y)`座標，但想要一個帶有`y > x`限制的子型別。

```julia-repl
julia> abstract type AbstractPoint end;

julia> struct Point <: AbstractPoint
           x::Integer
           y::Integer
       end;

julia> struct ConstrainedPoint <: AbstractPoint
           x::Integer
           y::Integer
           
           ConstrainedPoint(x, y) =
               y > x ? new(x, y) : @error("require y > x")
       end;
       
julia> Point(3, 2)
Point(3, 2)

julia> ConstrainedPoint(3, 2)
Error: require y > x

julia> ConstrainedPoint(3, 5)
ConstrainedPoint(3, 5)
```

`new()`函式_只能_用在內部建構子裡，而且如果輸入被判定為有效，就會回傳想要的項目。

遇到無效的輸入時，我們可以像範例那樣以錯誤訊息中止。
或者，你也可以改用`nothing`或`missing`這類的佔位符。
關於這些，請參閱[`Nothingness`][nothingness]概念。
