# 簡介

## 相等性

簡單型別（字串與基本型別）通常使用`==`和`!=`來測試相等性。

參考型別（類別的執行個體）則是使用繼承自`Object`的`Equals()`方法來比較。如果你進行相等性測試的目的是確認兩個物件是同一個執行個體，那麼仰賴`Object`的實作就足夠了。如果不是，你就需要覆寫`object.Equals()`。

如果你知道類別的所有執行個體都在同一個地方建立，例如某個遊戲或模擬中的角色，那麼參考相等性就足夠了。不過，同一個真實世界實體很可能會建立出多個執行個體（來自資料庫、使用者輸入，或透過網頁請求）。在這種情況下，就必須針對能唯一識別該實體的值來測試相等性。因此必須覆寫`Equals()`，並針對類別中適當的資料成員測試相等性。

覆寫後的`Equals()`方法會包含對簡單型別成員使用`==`的相等性測試，以及對參考型別成員遞迴呼叫`Equals()`。

`Object`類別提供了適當的方法來比較兩個物件，以偵測它們是否為同一個執行個體。

### `Object.GetHashCode()`

`Object.GetHashCode()`方法會以 32 位元整數的形式回傳雜湊碼。雜湊碼會被字典與集合類別使用，例如`Dictionary<T>`和`HashSet<T>`，以便有效率地儲存與取出物件。

雜湊碼與相等性之間的關係是：如果兩個物件相等（`Equal()`回傳 true），那麼這兩個物件的`GetHashCode()`就必須回傳相同的值。反過來則不成立。這並不是對稱的關係。兩個物件擁有相同的雜湊碼，並不代表它們一定相等。想像一個查詢函式，它會先根據雜湊碼找到某個「桶」，再透過相等性測試挑出特定的項目。

HashCode 程式庫的 API 文件討論了產生雜湊碼的最佳方式。

用於相等性測試的值，在雜湊集合使用期間必須保持穩定。如果你用某一組值把物件加入集合，之後又變更這些值，雜湊碼就不再指向正確的「桶」。實務上這意味著物件應該是不可變的。其他做法則可能為維護者帶來陷阱。

## 集合

集合是一組不重複的值。.NET 中集合的預設實作是`HashSet<T>`類別，這是一種只包含不重複值的集合。
