# 抽象類別

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## `$`是名稱的一部分

每個抽象類別的名稱都以開頭的 `$` 命名，而且只有抽象類別如此。所以，以 `$` 開頭的型別，就是你無法用它建立物件的那種；這點在名稱出現的每個地方都看得出來。

## 抽象類別裡可以放什麼

常式與疊代器的簽章，以分號結尾。沒有主體，沒有屬性，也沒有 `create`。抽象類別只描述某個東西可以被*要求*做什麼，從不描述它持有什麼。

## 符合性

```sather
class TRAPEZE < $ACT is
```

類別必須定義清單上的每一個常式，引數型別和回傳型別都要相符。這會在編譯時檢查。

一個類別可以同時符合好幾個：

```sather
class TRAPEZE < $ACT, $RISKY is
```

而抽象類別之間也可以互相擴充：

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## 分派發生的地方

抽象型別的變數會持有某個符合類別的物件參考。對它呼叫常式時，會在執行時期挑選屬於該物件真正類別的那個版本。

這是 Sather 唯一在執行時期做決定之處。對具體型別的變數所做的呼叫，在編譯時就已經確定。

## typecase

有時候種類真的很重要。`typecase`會問：

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

在某個分支裡，變數會是較窄的型別。少用它：對每一種 act 都做 `typecase`，通常代表這個常式本來就該放在抽象類別裡。

## $OB

`$OB`是每個物件都符合的抽象類別。它偶爾有用，但多半代表有個型別在中途被弄丟了。

## 為什麼不用繼承？

Sather 把大多數語言綁在一起的兩件事分開。`<`只說明一個類別能*做*什麼。從別處取得實作靠的是 `include`，那是下下一個練習，而且是一個獨立的決定。
