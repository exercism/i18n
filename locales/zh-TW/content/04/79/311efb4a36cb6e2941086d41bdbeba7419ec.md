# 簡介

## error 介面

在 Go 中，錯誤處理**不是**透過例外完成的。
相反的，錯誤是實作了內建 `error`介面的型別的一般_值_。
`error`介面非常精簡。
它只包含一個方法 `Error()`，用來將錯誤訊息以字串的形式回傳。

```go
type error interface {
  Error() string
}
```

每當你定義一個函式，而執行過程中可能發生需要傳達給呼叫端的錯誤時，就必須把 `error` 列為回傳型別之一。
如果函式有多個回傳值，依照慣例，`error` 一定是最後一個。

```go
func DoSomething() (int, error) {
  // ...
}
```

## 建立並回傳簡單的錯誤

你不一定要自己實作 error 介面。
若要建立簡單的錯誤，你可以使用標準函式庫套件 `errors`中的 `errors.New()`函式。
你只需要傳入以字串表示的錯誤訊息，`errors.New()`就會負責建立一個包含你的訊息、並實作 `error`介面的值。

如果函式要回傳錯誤，良好的做法是為其他所有回傳參數回傳零值：

```go
func DoSomething() (SomeStruct, int, error) {
  // ...
  return SomeStruct{}, 0, errors.New("failed to calculate result")
}
```

~~~~exercism/caution
你不應該假設，當錯誤發生時，所有函式都會為其他回傳值回傳零值。
最好的做法是假設：一旦發生錯誤，使用任何其他回傳值都不安全。
唯一的例外是文件明確指出，在發生錯誤時其他回傳值仍有意義的情況。
~~~~

如果你想在多個地方使用這樣的簡單錯誤，應該為這個錯誤宣告一個變數，而不是在行內使用 `errors.New`。
依照慣例，變數名稱應該以 `Err` 或 `err` 開頭（取決於它是否為匯出）。
這些錯誤變數通常稱為_哨兵錯誤_。

```go
import "errors"

var ErrNotFound = errors.New("resource was not found")

func DoSomething() error {
  // ...
  return ErrNotFound
}
```

將錯誤回傳 `nil`，表示函式執行期間沒有發生任何錯誤：

```go
func Foo() (int, error) {
  return 10, nil
}
```

## 錯誤檢查

如果你呼叫的函式會回傳錯誤，通常會把錯誤值存入名為 `err`的變數。
在使用函式實際的結果之前，你需要先確認沒有發生錯誤。

為了避免讓程式碼的「happy path」形成巢狀結構，應該先處理錯誤的情況。
我們可以用 `==` 和 `!=` 將錯誤與 `nil` 比較，當 `err` 不等於 `nil` 時，就知道發生了錯誤。

```go
func processUserFile() error {
	file, err := os.Open("./users.csv")
	if err != nil {
		return err
	}

	// do something with file
}
```

大多數情況下，錯誤會如上面的範例所示，沿著函式堆疊往上回傳。
另一種處理錯誤的方式，是將它記錄下來，然後繼續進行其他操作。
良好的做法是要嘛回傳錯誤、要嘛記錄錯誤，絕對不要兩者都做。

由於 Go 中大多數函式都會把錯誤列為回傳值之一，你會在 Go 程式碼中到處看到／使用 `if err != nil`這種模式。

## 自訂錯誤型別

如果你希望錯誤包含比錯誤訊息字串更多資訊，可以建立自訂的錯誤型別。
如前所述，在 Go 中，任何實作 `error`介面的東西（也就是具有 `Error() string`方法的型別）都可以當作錯誤使用。

通常會使用結構體來建立自訂的錯誤型別。
依照慣例，自訂錯誤型別的名稱應該以 `Error` 結尾。
此外，最好使用指標接收器來定義 `Error() string`方法，若要了解背後的原因，請參閱這則 [Stackoverflow 留言][stackoverflow-errors]。
請注意，這表示你需要回傳自訂錯誤的指標，否則它不會被視為 `error`，因為非指標的值並不提供 `Error() string`方法。

```go
type MyCustomError struct {
  message string
  details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.message, e.details)
}

func someFunction() error {
  // ...
  return &MyCustomError{
    message: "...",
    details: "...",
  }
}
```
