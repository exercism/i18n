# 可變性

可變性是 Rust 中特定綁定的一項屬性。綁定分為不可變與可變兩種。不可變綁定的值不得更改；可變綁定的值則可以更改。所有綁定預設皆為不可變。

## 綁定

綁定是原始碼中某個變數名稱，與執行期間某塊記憶體區域之間的關聯。嚴格來說，綁定只存在於編譯期間：編譯之前，實際上還沒有配置任何記憶體；編譯之後，機器碼只處理記憶體位址，而不再處理具名變數。

綁定通常以 `let` 關鍵字建立。此外，函式參數以及某些其他情況也會建立綁定。

綁定可以具有各種屬性，其中最重要的就是可變性。可變綁定是指可以合法更改所綁定記憶體之值的綁定。Rust 會嚴格追蹤並強制執行每個綁定的可變性，藉由拒絕那些錯誤嘗試修改本應為不可變之綁定的程式，來協助確保程式正確無誤。

## 可變性

實務上，可變性往往很單純。只要在綁定的定義中使用 `mut` 關鍵字，就能獲得更改該值的能力。

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### 從可變降級為不可變

綁定隨時都能從可變降級為不可變。這項操作是透明的。

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### 從不可變升級為可變

一般而言，只要所有權被轉移，隨時都能將值從不可變升級為可變。

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

在 `(1)` 處，字串的所有權從 `x` 轉移給 `y`，這讓我們能將該值升級為可變。

### 函式參數中的可變性

函式參數要成為可變，有兩種不同的方式。第一種、也是較常見的一種，類似於 C 語言中的傳參考：

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

在這個範例中，可變性在三處被明確標註。這三處可變性宣告都是可變參考得以運作的必要條件。
在 `(2)` 中，綁定 `x` 被宣告為可變。這個綁定是該值的頂層擁有者。
在 `(3)` 中，該值被可變借用，以傳入 `increment` 函式。
在 `(1)` 中，針對該參考建立了一個新的可變綁定 `n`。

還有一種參數可變性的風格，雖然較不常見，有時卻仍然很實用。這種風格下，值是被擁有的，但綁定是可變的。

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

這個範例所需的明確標註較少，因為它實際上是一次內建可變性升級的所有權轉移。它之所以能運作，是因為 `i32` 是 `Copy` 型別，會透明地複製資料。
在 `(1)` 中，我們宣告 `increment_internally` 接受一個可變、被擁有的 `i32`，命名為 `n`，作為它的參數。
在 `(2)` 中，我們宣告 `x` 是值 `1` 的不可變綁定。
在 `(3)` 中，`x` 被複製到記憶體中的新位置。`x` 仍為不可變。`n` 則為可變。

當然，也可以把這些形式組合起來，讓可變綁定指向可變參考（`mut n: &mut i32` 等等），但這很少是真正想要的做法。

### 沒有 `let` 的可變性

Rust 中有幾種結構（`if let`、`match` 等等）也能建立綁定。這些綁定同樣可以是可變的。

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

這個範例會先產生 `v = Some(2)`，然後是 `v = None`。

## 遮蔽

當某個值經過一連串轉換時，可以、而且往往很道地地重複使用同一個變數名稱，做法是用多個 `let` 重新宣告它。這就叫做遮蔽。

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

然而，這並不是可變性的例子；原始的值原則上依然存在。對於非 `Drop` 型別，編譯器可能選擇直接修改某個記憶體位置，而不是另行配置一個新的。不過，若面對的是 `Drop` 型別，或者舊的綁定之後還會再用到，它就絕不會這麼做。

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
