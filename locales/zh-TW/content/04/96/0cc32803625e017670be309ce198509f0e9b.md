# 測試產生器

C# 軌道使用[測試產生器](https://exercism.org/docs/building/tooling/test-generators)來自動產生練習的測試。
它利用了這個事實：[problem-specifications 儲存庫](https://github.com/exercism/problem-specifications/)中定義的大多數練習，也都有一個 `canonical-data.json` 檔，其中包含標準化的測試輸入與輸出，可以用來實作該練習。

## 步驟

要產生練習的測試，測試產生器會：

1. 從練習的 `canonical-data.json` 檔讀取測試案例
2. 使用 `tests.toml` 檔略過被排除的測試案例
3. 使用練習的產生器範本渲染測試案例
4. 使用 Roslyn 格式化渲染後的範本
5. 將格式化後的範本寫入練習的測試檔

### 步驟 1：讀取 `canonical-data.json` 檔

測試產生器會使用 [System.Text.Json 命名空間](https://learn.microsoft.com/en-us/dotnet/api/system.text.json)，從練習的 `canonical-data.json` 剖析測試案例。

由於有些標準資料使用了巢狀結構，剖析後的測試案例會額外帶有一個 `path` 欄位，其中包含任何父元素的 `description` 屬性，以及該測試案例自己的 `description` 屬性。

### 步驟 2：從 `tests.toml` 檔略過被排除的測試

每個練習都有一個 `tests.toml` 檔，可以在其中排除或停用個別的測試。
測試產生器會移除任何被標記為排除（`include = false`）的測試案例。

### 步驟 3：渲染測試案例

接著，（可能經過轉換的）測試案例會傳給 `.meta/Generator.tpl` 檔，這個檔案定義了如何根據這些測試案例來渲染測試。

### 步驟 4：使用 Roslyn 格式化渲染後的範本

接著使用 [Roslyn](https://github.com/dotnet/roslyn) 來格式化渲染後的範本。
這麼做有以下好處：

- 練習的格式會保持一致
- 撰寫範本時，不必太擔心空白與對齊

### 步驟 5：將渲染後的範本寫入練習的測試檔

最後，渲染後的範本輸出會寫入練習的測試檔。

## 範本

範本使用 [Scriban 程式庫](https://github.com/scriban/scriban/)來渲染。

## 命令列介面

測試產生器有兩種執行方式：

1. `bin/update-tests.ps1`：更新所有具有產生器範本的練習的測試
2. `bin/update-tests.ps1 -e <slug>`：更新指定練習的測試，前提是該練習有產生器範本
