# 關於

[條件判斷][conditionals-concept]概念介紹了`jcc`，這是用來依據條件分支的指令家族。
`jcc`只有在條件成立時，才會把執行流程轉移到程式中的另一個位置。

不過，現代 CPU 速度很快，能平行執行許多指令。
若為了等 CPU 在執行期檢查某個條件而讓所有工作停擺，代價實在太高。

因此，CPU 內部其實並不會停下來等。
它會用[分支預測器][branch-predictor]猜測條件的結果，然後開始_預測性地_執行猜中的路徑。

如果猜對了，執行流程就會像沒有分支一樣繼續下去。
但如果猜錯了，CPU 就必須_丟棄在預測路徑上已完成的工作_，改從正確的路徑重新開始。

這稱為**分支預測錯誤**，代價很高，會造成延遲。

當某個分支不容易預測時，這些預測錯誤就會累積起來。
在這種情況下，有時最好完全避開分支，讓同一組指令無論條件為何都照樣執行。
不用`jcc`就能在值之間做選擇的程式碼，稱為**無分支**程式碼。

有幾種方式可以組織程式碼，讓分支發生的頻率降低，或讓現有的分支更容易預測。
特別是 x86-64 提供了兩個指令家族，常用來撰寫無分支程式碼。

## 條件搬移

[cmovcc][cmov] 指令家族只有在特定條件成立時，才會把來源運算元複製到目的運算元。
否則，目的運算元維持不變。

`cc`後綴的命名方式與`jcc`相同，意義也一樣：

| 指令 | 搬移條件 |
|-------------|--------------------------------------|
| `cmove`     | `cmp A, B`之後 A == B              |
| `cmovne`    | `cmp A, B`之後 A != B              |
| `cmovl`     | `cmp A, B`之後 A < B（有號）      |
| `cmovb`     | `cmp A, B`之後 A < B（無號）    |
| `cmovg`     | `cmp A, B`之後 A > B（有號）      |
| `cmova`     | `cmp A, B`之後 A > B（無號）    |

規則和`jcc`類似：

1. `l`和`g`用於有號比較；`b`和`a`用於無號比較。
2. 在後綴加上`e`代表包含相等的情況。
3. 加上`n`會將條件取反。
4. 另外還有一些變體，是根據旗標是否設置來判斷。
   例如`cmovz`和`cmovc`。

來看看求有號整數絕對值的例子：該整數放在`rdi`，結果以`rax`回傳。
用`jcc`撰寫時，這個函式會在其中兩條路徑中選擇一條：

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

改用`cmovcc`撰寫時，兩個候選值都會無條件計算出來，再由條件搬移挑選其中一個：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; if rdi >= 0, rax = rdi
                       ; otherwise rax stays = -rdi
    ; now rax = abs(rdi)
    ret
```

無分支版本永遠執行同一組指令。
沒有`jcc`讓分支預測器去猜。

`cmovcc`的目的運算元必須是暫存器。
來源可以是暫存器或記憶體位置，但不能是立即值。

~~~~exercism/note
在上面的程式碼中，`neg`指令會根據結果設置多個旗標，包括符號旗標（SF）。
這表示`cmp rdi, 0`可以完全省略：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF = 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

當`rdi`為正數時，`neg`會產生負的結果，SF = 1，因此`cmovs`會把`rdi`還原回來。
當`rdi`為零或負數時，`neg`會產生非負的結果，SF = 0，所以`rax`會保留取負後的值（也就是正確的絕對值）。

雖然在組合語言中，`cmp`是比較值的主要方式，但許多指令也會根據自身的結果設置旗標。
每個指令會影響哪些旗標，通常會完整列在它的[參考文件][reference]中。
就`neg`而言，這些旗標是 SF、ZF、CF、OF 和 PF。

[reference]: https://www.felixcloutier.com/x86/
~~~~

## 條件設置

[setcc][set] 指令家族會在特定條件成立時，把目的運算元設為`1`，否則設為`0`。
目的運算元一律是_8 位元運算元_。

`cc`後綴的命名方式與`jcc`和`cmovcc`相同。
例如，`setz`會在`ZF == 1`時把目的運算元設為`1`，否則設為`0`。

由於目的運算元只有 8 位元，當需要更寬的值時，通常會在`setcc`之後接一個`movzx`：

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

這是把比較結果轉成整數`0`或`1`的常見慣用寫法。

## 何時該使用無分支程式碼

無分支程式碼不一定比有分支的程式碼快。
當某個分支非常容易預測時，分支預測器幾乎每次都猜對，`jcc`基本上不花什麼成本。
用無分支程式碼取代這種分支反而更慢，因為它總是會執行兩個候選計算。

迴圈計數器就是最典型的例子。
看看下面這個函式：它會從`rdi`開始，加總`rsi`個 64 位元整數：

```x86asm
sum_array:
    xor rax, rax
.loop:
    add rax, [rdi]
    add rdi, 8
    dec rsi
    jnz .loop          ; taken on every iteration except the last
    ret
```

這正是分支預測器最擅長處理的模式，所以無論`sum_array`處理多少個元素，這個分支基本上不花成本。

當分支難以預測，或無論輸入為何都必須維持穩定時間時，無分支程式碼才會帶來好處。
