# 指令

歡迎，工程師！
你是 Speedywagon 基金會僅存的幾位老將之一，這個祕密組織數十年來一直對抗著 Pillar Men 這類古老的威脅。
在這段過程中，你花了許多年維護基金會的技術系統，這些系統結合了最先進的技術與日漸老舊的函式庫。

然而近來，負責追蹤 Pillar Men 活動的感測器開始故障了。
基金會的系統已經老舊，程式碼還得與一個無法更新的老舊 C++ 函式庫互動。
你的任務是實作四個核心函式，透過老派的指標型函式庫來監控 Pillar Men 感測器的活動。

身為現代的 C++ 工程師，你會偏好使用智慧指標，但無奈老舊的程式碼就是要你尊重舊有的做法。
人類的命運或許就繫在這些指標上，所以請謹慎行事，願 Hamon 能量引導你。

~~~~exercism/note
由於感測器讀數可能非常龐大，我們提供了一個模擬的 _struct_，對應實際函式庫中所使用的版本。

```cpp
struct pillar_men_sensor {
    int activity{};
    std::string location{};
    std::vector<int> data{};
};
```

## 1. 檢查感測器連線（`connection_check`）

你的第一項任務，是確保 Pillar Men 感測器正確連線。
我們可不能讓未連線的感測器觸發誤報。
你要撰寫一個函式`connection_check`，透過檢查`nullptr`來測試感測器的指標是否有效。

- 定義一個函式，接受一個指向`pillar_men_sensor` _struct_ 的指標。
- 若感測器指標不是 null，這個函式應回傳`true`，否則回傳`false`。

```cpp
pillar_men_sensor* sensor{nullptr};
bool isConnected = connection_check(sensor);
// isConnected => false
```

## 2. 計算感測器的活動量（`activity_counter`）

Pillar Men 正潛伏在暗處，我們需要知道感測器是否偵測到任何活動。
你要撰寫`activity_counter`函式，它會接受一個感測器陣列，以及一個代表陣列中感測器數量的容量。

- 定義一個函式，接受一個指向陣列第一個元素的指標，以及該陣列的容量。
- 使用指標運算來走訪感測器陣列，並累加活動讀數。
- 回傳累加後的活動量。

```cpp
pillar_men_sensor sensor_array[3] = {{0}, {101}, {22}};
int totalActivity = activity_counter(sensor_array, 3);
// totalActivity => 123
```

## 3. 警報控制（`alarm_control`）

除非真的發生危險，否則不是每個感測器都該觸發警報。
`alarm_control`函式會確保感測器只有在活動量高於 0 時才觸發警報。
這個函式也應檢查感測器是否為 null，以避免系統當機。

- 定義一個函式，接受一個指向`pillar_men_sensor`的指標。
- 函式應先檢查感測器是否為`nullptr`。若感測器是`nullptr`，就回傳`false`。
- 若感測器有效，且其活動量大於 0，就回傳`true`；否則回傳`false`。

```cpp
pillar_men_sensor db{9008, "songokunoie", {7, 7, 7}};
bool alarm = alarm_control(&db);
// alarm => true
```

## 4. 使用`uv_alarm`函式檢查資料是否有異常

在這項任務中，你要實作`uv_alarm`函式，根據紫外光曝露程度與感測器活動量，判斷是否該觸發警報。
`uv_alarm`函式應使用提供的`uv_light_heuristic`函式，它會處理一份資料向量，並根據特定門檻回傳一個值。
這是正式環境中會執行的複雜程式碼的模擬版本，請不要更動它的介面。

在`speedywagon`命名空間中定義`uv_alarm`函式。它應該：

- 接受一個指向`pillar_men_sensor` _struct_ 的指標，作為它的參數。
- 若感測器指標是 null，就回傳`false`。
- 呼叫`uv_light_heuristic`函式，並傳入感測器`data`陣列的位址。
- 若`uv_light_heuristic`回傳的值大於`sensor->activity`的活動量，就回傳`true`，否則回傳`false`。
