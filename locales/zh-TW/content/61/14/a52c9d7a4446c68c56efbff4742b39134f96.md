# 簡介

正規表達式是一種用途極廣的方式，可以用來對字串進行_模式比對_，它使用的是一套專為此設計的領域特定語言（DSL）。

正規表達式的許多功能都內建在 Base R 中，你也可能在較舊的程式碼裡看到相關範例。

如果是新的程式碼，_強烈_建議使用[`stringr`][web-stringr]套件。

如同[字串概念][concept-strings]所述，`stringr`有不錯的說明文件，通常由套件作者撰寫。

- 一個[參考網站][web-stringr]
- 一份[速查表][cheat-stringr]。
- 「R for Data Science」裡的一個[字串章節][book-strings]和一個[正規表達式章節][book-regex]。

[`Strings`][concept-strings]概念中已經討論過的許多函式，本身就是為了正規表達式搜尋而設計的。

我們在字串概念裡刻意保持簡單，只比對字串常值，不過也可以改用任何正規表達式樣式。

嚴格來說，在 R 中建立正規表達式的方式是呼叫[`regex()`][ref-regex]。
為了方便起見，`stringr`的函式會把任何樣式字串都當成正規表達式。
在下面的範例中，第一個`str_replace_all()`是第二種寫法的語法糖：

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[速查表][cheat-stringr]是很有用的指南：所有帶有 `pattern` 引數（以紅色標示）的函式都接受正規表達式，第 2 頁則整理了正規表達式的語法。

請注意，如果你需要覆寫預設值，例如大小寫敏感度或地區設定，[`regex()`][ref-regex]函式仍然可能很重要。

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

許多正規表達式碼會包含反斜線，例如上面用到的 `\s`。
在一般的 R 字串中，`\`需要用雙寫來跳脫，因此寫成 `"\\s"`。

反斜線可能會不斷增生、變得混亂，所以在複雜的情況下，改用[原始字串][book-raw]可能會有所幫助。

預設用來定義原始字串的語法是 `r"( )"`，但也可以使用其他分隔符號。
由於小括號 `( )`和方括號 `[ ]`在正規表達式語法（用於捕獲群組和選項群組）中都很常見，大括號 `{ }`可能是個不錯的選擇。

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## 偵測比對

這裡有幾個問題，以及一些可以幫助你回答它們的函式。

有些範例使用 `fruit`，這是 `stringr`內建、包含 80 個水果名稱的向量，用來讓你練習。

_字串裡是否含有比對結果？_
`str_detect()`，或者用 `str_starts()`、`str_ends()`來避免使用 `^` 或 `$` 錨點。

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_只想回傳含有比對結果的字串？_
用 `str_subset()`取得字串，用 `str_which()`取得索引。

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_每個字串裡有多少個比對結果？_
使用 `str_count()`。

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_比對結果在哪裡？_
`str_view()`適合互動式使用，一般情況則用 `str_locate()`或 `str_locate_all()`。

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## 捕獲

通常我們會想知道到底比對到_什麼_。
做法是在正規表達式中用小括號加入捕獲群組。

也可以在同一個正規表達式中回頭參照捕獲，方式是使用 `\1`、`\2` 等。
例如，找出重複出現的字母對：

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

用類似的語法，捕獲也可以用在取代字串中：

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

若只想取得第一個比對，可以用 `str_match()`函式蒐集比對結果以便後續處理；若要取得所有比對，則用 `str_match_all()`。

無論在哪一種語言，捕獲群組的輸出通常都很複雜。
R 的做法（_而且還做了向量化，算是額外的挑戰_）是讓 `str_match()`產生一個矩陣，每個輸入字串佔一列，第 1 欄包含完整的比對字串，其餘欄位則包含各個捕獲群組。

使用具名群組可能有好處，因為它們會成為結果矩陣的欄位名稱。

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

這份課程大綱沒有多談矩陣，不過有一份[概念文件][concept-matrices-arrays]可以參考。
矩陣雖然長久以來都是 Base R 的一部分，卻和 Tidyverse 生態系不太合得來。

簡單來說：把矩陣看成帶有 2 個索引的向量，順序是 `[rows, cols]`。
把任一索引留空，就能取得整列或整欄。

當你用 `m[r,]`取得單一列 `r`，或用 `m[,c]`取得單一欄 `c` 時，回傳的值預設會被扁平化成向量。

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

無可避免地，`str_match_all()`產生的輸出結構會更加複雜：

- 結果是一個陣列，每個輸入字串對應一個元素。
- 如果只有一個輸入字串，就用 `[[1]]` 索引把輸出 unlist，做法如[陣列概念][concept-lists]所述。
- 每個元素都是一個矩陣，欄位配置和 `match()`相同。
- 矩陣中的每一列都是一次成功的捕獲。

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

當然，比對也可能失敗。
這時結果會是特殊值 `NA`。
請準備好測試這種情況，做法如[虛無概念][concept-nothingness]所述。

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
