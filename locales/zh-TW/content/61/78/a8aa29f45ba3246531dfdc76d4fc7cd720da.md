# 布林值

`BOOL` 會儲存兩個值的其中一個：`true` 和 `false`。

```sather
   ready : BOOL is
      return true;
   end;
```

## 比較

| 運算子 | 判斷 | 範例 |
| --- | --- | --- |
| `=` | 相同嗎？ | `age = 13` |
| `/=` | 不同嗎？ | `age /= 13` |
| `<` | 小於 | `age < 13` |
| `<=` | 小於或等於 | `age <= 13` |
| `>` | 大於 | `age > 13` |
| `>=` | 大於或等於 | `age >= 13` |

這些運算子可以用在數字上，而 `=` 和 `/=` 也能用在字串上。

## 三種運算子

| 運算子 | 寫法 | 為 true 的時機 |
| --- | --- | --- |
| and | `a and b` | 兩者都為 true |
| or | `a or b` | 至少有一個為 true |
| not | `~a` | `a` 為 false |

`and` 和 `or` 具有**短路**特性：一旦 `a` 是 false，`a and b` 就不會再費心去看 `b`，因為答案早就確定了。
同樣地，如果 `a` 是 true，`a or b` 就會停下來。當右邊那一側的代價很高，或是執行起來會出問題時，這一點就很重要。

## 直接回傳比較結果

如果一個常式的工作就只是提出一個問題，那它應該直接回傳這個問題，而不是用條件式挑一個答案：

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

寫成 `if age >= 13 then return true else return false end`，要用三行程式碼才能說出比較本身早就說過的事，每個有經驗的讀者都會注意到這點。

## 優先順序

`~` 的結合最緊，再來是 `and`，最後是 `or`。所以

```sather
~a and b or c
```

的意思是 `((~a) and b) or c`。寫括號不花什麼成本，只要讀者得靠回想這個順序才看得懂那一行，就很值得加上。
