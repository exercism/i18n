# 關於

函式在呼叫自己時，就是[遞迴][recursion]。

函式呼叫和迴圈的一個關鍵差異是，呼叫函式會把要返回的位址推入堆疊。
這表示遞迴函式通常比等效的迴圈需要更多堆疊空間。

因此，一個不斷呼叫自己的函式最終可能會耗盡所有堆疊空間。
這就叫做[堆疊溢位][stack-overflow]。

這就是為什麼每個遞迴函式都必須至少有一個基底情況，也就是函式不呼叫自己就直接回傳的情況。
任何遞迴呼叫最終都必須抵達基底情況。

例如，階乘函式`n! = n * (n - 1) * ... * 1`可以用`1`作為基底情況來遞迴定義：

```x86asm
factorial:
    ; the argument `n` is passed on `rdi`
    ; the factorial will be returned on `rax`

    cmp rdi, 1
    jle .base_case     ; base case -> if rdi <= 1, return 1

    push rdi           ; save n
    dec rdi            ; rdi = n - 1
    call factorial     ; recursive call, rax = (n - 1)!
    pop rdi            ; restore n
    imul rax, rdi      ; rax = n * (n - 1)! = n!
    ret
.base_case:
    mov rax, 1
    ret
```

注意，`factorial`必須在遞迴之前先`push rdi`，並在之後`pop rdi`。
這是因為在遞迴呼叫回傳之後，它仍然需要`n`才能計算`n * (n-1)!`。

另請注意，使用由被呼叫者保存的暫存器也無法解決這個問題。

即使遞迴函式是它自己的潛在呼叫者，它本身也是某個其他函式的被呼叫者。
這表示函式在使用由被呼叫者保存的暫存器之前，也必須先保存它們，並在使用完之後還原它們的值。
這通常是透過`push`/`pop`序列來完成的，就像我們在前一個概念中看過的一樣。

由於遞迴函式的每一幀（基底情況除外）本身也都是需要保存自己區域變數的呼叫者，因此這個`push`/`pop`序列必須在每一幀重複一次。
即使不使用暫存器、直接把變數存進堆疊，每一幀仍然要花費相同的`8`個位元組。

這表示每個遞迴呼叫都會為`call`推入的返回位址在堆疊上增加`8`個位元組，另外還要為每個需要保存的區域變數增加`8`個位元組。
函式會不斷地為每一幀把這些位元組加進堆疊，直到抵達基底情況。
直到那時，它才開始以相反的順序一層層展開，每個遞迴呼叫視需要執行足夠的`pop`，然後再執行一次`ret`。

例如，如果`factorial`以引數`10`被呼叫，它會先呼叫自己九次，才抵達`1`這個基底情況。
此時，用來儲存每個先前幀的`n`（`8`個位元組）和返回位址（`8`個位元組）的空間已經累積到`144`個位元組。

## 尾呼叫

在某些情況下，函式在呼叫另一個函式之後、回傳之前，不會再做任何其他工作。

舉例來說，考慮：

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    call times_three
    ret
```

函式`triple_of_square`：

- 把傳入的引數（位於`rdi`）乘上自己，得到它的平方；
- 然後呼叫`times_three`，它會回傳傳入引數的三倍。

結果，`triple_of_square`會回傳`3*x²`，其中`x`是它透過`rdi`傳入的引數。

注意，`triple_of_square`在呼叫`times_three`之後沒有做任何工作，函式就直接回傳了。
在這種情況下，函式可以改用`jmp`把執行權轉移給被呼叫的函式，而不使用`call`：

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    jmp times_three
```

這就叫做[尾呼叫][tail]。

尾呼叫的主要優點是省下`call`的額外成本。
`call`會把返回位址推入堆疊，而控制權要回到那個點，就必須有對應的`ret`。

尾呼叫把這兩者都省掉了：沒有返回位址要推入，也沒有額外的`ret`要配對，只有被呼叫函式自己的`ret`。

## 尾遞迴

對於可能在回傳之前呼叫自己很多次的遞迴函式來說，尾呼叫特別有用。

不過，並不是每個遞迴呼叫都能直接轉換成尾呼叫。
因為`jmp`會把控制權轉移給被呼叫的函式，呼叫者在尾呼叫之後就無法再做任何工作。

例如，先前的`factorial`函式**不是**尾遞迴。
在遞迴呼叫之後，它仍然需要用`imul rax, rdi`把結果乘上目前的`n`。

在這種情況下，有時可以使用一個累加器來收集部分的計算結果，並在最後回傳。
例如，我們可以定義一個`factorial_helper`來做大部分的工作，然後讓`factorial`建立累加器並把控制權轉移給`factorial_helper`：

```x86asm
factorial_helper:
    ; the argument `n` is passed on `rdi`
    ; `rax` is used as an accumulator and will be returned at the end

    cmp rdi, 1
    jle .base_case

    imul rax, rdi        ; we accumulate the partial result on `rax`
    dec rdi              ; rdi = n - 1
    jmp factorial_helper ; tail call to accumulate (n - 1)!
.base_case:
    ret                  ; returns the factorial already accumulated on `rax`

factorial:
    mov rax, 1           ; initial value for the accumulator
    jmp factorial_helper ; tail call
```

由於遞迴呼叫之後不再做任何工作，我們也不再需要保存`rdi`了。
沒有`call`，也沒有`push rdi`，所以每個遞迴疊代對堆疊增加`0`個位元組：不會用到額外的堆疊空間。
這個版本可以處理任意大的`n`，而不會讓堆疊溢位。
它既更有效率，也更安全。

在某些情況下，透過調整函式的順序，甚至可以連通往 helper 的`jmp`都省掉。
例如，`factorial`和`triple_of_square`可以這樣改寫：

```x86asm
factorial:
    mov rax, 1
factorial_helper:
    cmp rdi, 1
    jle .base_case

    imul rax, rdi
    dec rdi
    jmp factorial_helper
.base_case:
    ret

triple_of_square:
    imul rdi, rdi
times_three:
    imul rax, rdi, 3
    ret
```

在上面的片段中，`factorial`的執行會直接落到`factorial_helper`。
`triple_of_square`和`times_three`也是如此。
在兩種情況下，執行都會循序地繼續下去，看起來尾端的函式就只是「主」函式裡的一個區域標籤。

實際上，任何區域標籤和函式之間並沒有本質上的差別。
x86-64 組合語言對它們任何一個都不會特別對待，它們就只是可執行程式碼區段中的位址，例如`section .text`。

這樣一來，尾遞迴函式基本上就可以想成和迴圈一樣：遞迴呼叫跳回頂端，而基底情況就是結束迴圈的那個條件。
