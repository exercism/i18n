# Here Document 入門

在 Bash 腳本中，「here document」（或稱「heredoc」）可以把多行輸入重新導向到某個指令或程式，就像你直接在終端機裡輸入這些內容一樣。
這是一項強大的工具，讓你在腳本中嵌入多行文字，而不需要外部檔案或複雜的字串處理。

## 主要特性與語法

1. 分隔符號：here document 以`<<`運算子開頭，後面接著一個分隔字詞（通常稱為「標記」或「結束符號」）。
   這個分隔符號可以是你自己選的任何字詞，不過為了清楚起見，通常會用像 `EOF`、`END` 或 `TEXT` 這樣的字。
   想讓程式碼更好讀，也可以選用更有描述性的分隔符號，例如`END_INSTALLATION_INSTRUCTIONS`。

1. 內容：在開頭的`<< DELIMITER`之後，寫下你想重新導向的內容。
   這可以是好幾行文字、程式碼，或任何其他東西。

1. 結束：當分隔字詞獨自出現在一行、前後都沒有空白字元時，here document 就結束了。

## 基本語法

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## 運作方式

* Bash 會讀取開頭`<< DELIMITER`與結尾`DELIMITER`之間的所有行。
* Bash 會把這些內容接到指令的標準輸入。
* 指令會把這些輸入當成從鍵盤輸入的一樣來處理。

### 範例 1：簡單的文字輸出

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

輸出：

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

在這個範例中：

* `cat`是指令。
* `<< EOF`會啟動 here document，並以`EOF`作為分隔符號。
* 這三行文字就是內容。
* 單獨一行的`EOF`會結束 here document。
* 接著`cat`會輸出它收到的內容。

### 範例 2：搭配 wc 使用（字數統計）

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

輸出：

```plaintext
3
```

在這裡，`wc -l`會計算行數。
here document 則提供這三行作為輸入。

### 範例 3：把資料傳給腳本

腳本：

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

在互動式的 bash 提示字元中，用 here document 呼叫這個腳本：

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

輸出：

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## 變化與進階功能

### 字面內容

Bash 會在 here document 中進行變數展開、指令替換與算術展開。
從這個角度來看，here document 的行為就像雙引號字串。

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

輸出：

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

當分隔符號被引號包住時（使用單引號或雙引號），這些展開就不會發生。
內容會被視為字面文字。
這就像單引號字串。

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

輸出：

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### 移除開頭的定位字元

如果你用`<<-`（後面帶一個連字號）取代`<<`，Bash 會移除 here document 每一行開頭的_定位字元_。
這在腳本中為 here document 的內容縮排時很好用，而且不會影響輸出。

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

輸出時，所有開頭的定位字元都會被移除：

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
作者並不建議這種用法。
雖然這樣做可以提升腳本的可讀性，但是

1. 一不小心就可能把定位字元換成空格（你的編輯器可能會自動這麼做），而且
1. 空格和定位字元之間的差別很難看出來。
~~~~

## 什麼時候該用 Here Document

* 多行輸入：當你需要提供多行文字給某個指令時。
* 設定檔：在腳本中嵌入小小的設定片段。
* 產生程式碼：在腳本中即時產生程式碼。
* 腳本互動：模擬使用者輸入來操作互動式程式。
* 避免外部檔案：當你想避免建立暫存檔時。

一個典型的用法是提供說明文字：

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## 可能的缺點

* 內嵌的大型文件會讓程式碼更難閱讀。
  把腳本與說明文件分成不同檔案來部署，可能會更好。
* Here document 可能會打斷程式碼的流程。
  你可能在很深層的巢狀程式碼中，想傳一些文字給某個程式。
  相較於周圍的程式碼，here document 的縮排看起來會很突兀。

## Here String

就像 here document 一樣，_here string_（或稱「herestring」）可以為指令提供輸入。
不過，here document 提供的是一整塊文字，here string 提供的則是單一字串。
Here string 使用`<<< "text"`語法。

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

輸出：

```plaintext
UPPER CASE THIS STRING
```

和 here document 不同，here string 不需要結尾的分隔符號。

### 為什麼要用 Here String？

我們可以用管線來代替 here string：

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

那麼，為什麼要用 here string 呢？

想想看，如果某個字串是某個耗時計算的輸出，而你想把結果分別餵給兩個不同的指令。
用管線的話，你得把那個計算執行兩次：

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

更有效率的方法是先把計算的輸出存下來（使用指令替換），再用 here string 把輸入提供給接下來這兩個指令：

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

以下是這個例子在真實世界中的應用：

* 取得 REST API 查詢（有分頁）回傳的 JSON 回應，
* 把 JSON 資料交給 jq 程式解析結果並輸出到檔案，然後
* 再把 JSON 資料交給另一個 jq 程式，判斷下一次查詢的 URL。

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

注意輸出重新導向的位置。
這個`while`迴圈產生的所有輸出都會附加到`data.csv`這個檔案。

## Here Document 與 Here String 作為重新導向

因為它們只是重新導向的幾種形式，所以可以和其他重新導向操作合併使用：

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## 總結

Here document（或稱「heredoc」）是管理 Bash 腳本中多行輸入的一種彈性又方便的方式。
它們簡化了把文字和資料直接嵌入腳本的流程，讓腳本更自給自足、也更容易閱讀。

Here string（或稱「herestring」）和 here document 很像，但語法更簡單、更靈活。
