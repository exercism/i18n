# 簡介

Go 的切片類似於其他語言中的陣列。
它們會存放數個特定型別（或介面）的元素。

Go 的切片是以陣列為基礎。
陣列的大小是固定的。
相對地，切片則是一種大小可動態調整、能靈活取用陣列元素的檢視。

切片的寫法類似 `[]T`，其中 `T` 是切片中元素的型別：

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

你可以用方括號記法，取得或設定指定索引（從 0 開始）上的元素：

```go
withData[1] = 5
x := withData[1] // x is now 5
```

你可以從既有的切片取出一個元素範圍，建立新的切片。
同樣使用方括號記法，但要同時指定起始索引（含）與結束索引（不含）。
如果沒有指定起始索引，預設為 0。
如果沒有指定結束索引，預設為切片的長度。

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

你可以使用`append`函式將元素加入切片。
下面我們把`4`和`2`加入`a`切片。

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append`總是會回傳一個新的切片，而當我們只是想將元素加入既有的切片時，通常會把它重新指定回我們當作第一個引數傳入的那個切片變數，就像上面那樣。

`append`也可以用來合併兩個切片：

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## 切片中的索引

使用切片的索引時，應該一律透過某種檢查來保護，確保該索引確實存在。
如果沒有這麼做，會讓整個應用程式崩潰。

## 空切片

`nil`切片是預設的空切片。
相較於不含任何值的切片，它們沒有任何缺點。
`len`函式可以作用在`nil`切片上，不必初始化就能加入項目，諸如此類。
如果要建立新的切片，請優先使用`var s []int`（`nil`切片），而不是`s := []int{}`（空但非`nil`的切片）。

## 效能

當你要建立一個會反覆填入元素的切片時，如果能事先知道切片的最終大小，就有一個能輕鬆提升效能的著手點。
關鍵在於盡量減少記憶體必須配置的次數；配置記憶體的代價相當高，而且當切片成長到超出已配置的記憶體空間時就會發生。
最保險的做法是用`s := make([]int, 0, cap)`指定切片的容量`cap`，然後照往常一樣用`append`把元素加入切片。
這樣一來，雖然切片長度是 0，但會立刻配置好可容納`cap`個項目的空間。
實務上，`cap`常常是另一個切片的長度：`s := make([]int, 0, len(otherSlice))`。

## append 不是純函式

Go 的`append`函式為了效能做了最佳化，因此不會複製輸入的切片。
這表示原始切片（`append`的第一個參數）有時會被改變。
