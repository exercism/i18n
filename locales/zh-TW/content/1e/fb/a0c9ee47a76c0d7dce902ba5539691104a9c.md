# 簡介

## 二進位表示法

**整數**是一種抽象概念，用來表示整數值，例如`4`、`-2`、`0`或`64532`。

若要把整數表示成一連串的位元組，就會使用**二進位表示法**。在這種表示法中，序列裡的每個位元各自代表一個不同的 2 的次方；位元的索引從右往左遞增，數值也隨之變大。

## 無號數

如果一個數只能是非負數，就稱為**無號**數。

無號數會直接表示成其序列中所有設定位元對應的 2 的次方之和。

在一個暫存器中，可表示的非負整數範圍從`0`（沒有任何位元被設定）到`2⁶⁴ - 1`（全部 64 個位元都被設定的總和）。

把無號數擴展到較大的大小，做法是把所有較高的位元都填上`0`，這樣新增的位元就不會對數值有貢獻。這稱為**零擴展**。

`movzx`指令（`z`代表 zero）會把 8 位元或 16 位元的來源運算元零擴展到較大的目的運算元。而 32 位元的來源運算元，只要用單純的`mov`，就會零擴展到目的運算元的全部 64 個位元。

## 有號數

如果一個整數可以是正數或負數，就稱為**有號**數。

為了表示負數，x86-64 使用**二補數**表示法。

在二補數中，有號數同樣表示成設定位元對應的 2 的次方之和。不過，如果最高位的位元被設定，它就會被減去，而不是加到其他位元上。

由於這個位元對應的數值比其餘所有位元的總和還大，實際上這代表帶有此位元的數一定是負數。這個特別的位元稱為**符號位元**。

把有號數擴展到較大的大小，就是把每個新增的較高位置都填上符號位元的副本，讓數值保持不變。這稱為**符號擴展**。

`movsx`指令（`s`代表 sign）會把 8 位元或 16 位元的來源運算元符號擴展到較大的目的運算元。`movsx`有個變體叫做`movsxd`，負責把 32 位元的來源運算元符號擴展到 64 位元的目的運算元。

`neg`指令可以用來改變一個數的符號。

~~~~exercism/caution
在組合語言中，無法分辨一串位元組代表的是有號數還是無號數。這些位元組的意義，必須由程式設計師自行賦予。

善用註解可以大大幫助這件事。
~~~~

## 立即值

在先前的概念中提過，像`4`或`-15`這樣的常數可以當作許多指令的來源運算元。這種數字稱為**立即值**。

立即值並不存在於暫存器或記憶體中，而是直接編碼在指令本身裡。在多數指令中，不論目的運算元有多大，為它保留的空間都只有 32 位元寬。

當目的運算元有 64 位元寬時，這 32 個位元會被_符號擴展_來填滿它。運算元的上半部會完全填滿立即值最高位元的重複副本，所以用這種方式只能寫入落在_32 位元有號整數_範圍內的數：

```x86asm
add rax, -1          ; the immediate is sign-extended, so all 64 bits of rax are affected
add rax, 2147483647  ; the largest immediate an instruction like this accepts
```

超出這個範圍的數字就不能當作立即值使用。這條規則的例外是`mov`；當目的運算元是暫存器時，它可以接受完整的 64 位元立即值。如果需要 64 位元的立即值，可以先用`mov`把它載入暫存器，再使用該暫存器：

```x86asm
mov rax, 3435973837           ; this works, mov can take a 64-bit immediate
mov rdx, 18446744073709551615 ; the largest immediate mov accepts
sub rdx, rax
```

請注意，負的立即值和位元表示法相同的無號數彼此等價，組譯後也會得到完全一樣的值：

```x86asm
mov rax, -1                   ; rax = 18446744073709551615
mov rax, 18446744073709551615 ; rax = -1
```

## 加法

兩個數的相加可以用`add`指令來計算。

另外還有單運算元的`inc`指令，會把`1`加到其運算元中的值：

```x86asm
inc rax ; rax = rax + 1
```

兩個整數的相加，對無號數和有號數而言運作方式完全相同。

## 減法

兩個整數的相減使用`sub`指令來完成。

另外還有單運算元的`dec`指令，會從其運算元中的值減去`1`：

```x86asm
dec rax ; rax = rax - 1
```

兩個整數的相減，對無號數和有號數而言運作方式也完全相同。

## 乘法

在 x86-64 中，有兩個不同的指令可以執行兩數相乘。一般來說，無號乘法使用`mul`指令，有號乘法則使用`imul`。

`mul`指令採用下列的單運算元形式，其中`src`是來源運算元：

```x86asm
mul src
```

`imul`指令可以採用單運算元、雙運算元或三運算元的形式：

```x86asm
imul src
imul dest, src
imul dest, src1, src2
```

### 單運算元乘法

以單運算元形式進行乘法時，會隱含使用兩個暫存器：`rax`和`rdx`。如果相乘的是兩個 64 位元的數，結果的低 64 位元會放在`rax`，高 64 位元則放在`rdx`。

這通常寫成`rdx:rax`，表示兩個暫存器是搭配使用的：

```x86asm
mul rcx ; rax = lower 64 bits of rax * rcx
        ; rdx = upper 64 bits of rax * rcx
```

其他運算元大小也是同樣的情況。舉例來說，如果相乘的是兩個 32 位元的數，就會使用`eax`和`edx`。

例外情況是兩個位元組之間的相乘。

在這種情況下，不會使用`dl:al`，而是使用`ax`。`ax`的低半部（`al`）會取得乘積的低 8 位元，高半部（`ah`）則取得高 8 位元。

~~~~exercism/caution
乘法中隱含使用的暫存器，例如`rax`和`rdx`，一律會被覆寫。如果之後還會用到這些暫存器中的值，應該在運算前先把它們存起來。
~~~~

### 雙運算元乘法

`imul`的雙運算元形式有一個明確的目的運算元，並遵循一般的語法。這種形式不會使用`rdx`，而是把結果截斷以塞進目的運算元。

```x86asm
imul r8, r9 ; r8 = lower 64 bits of r8 * r9
```

### 三運算元乘法

`imul`的三運算元形式有兩個來源運算元，其中第二個一定是立即值（一個常數）。兩個來源運算元會相乘，結果經過截斷後放進目的運算元：

```x86asm
imul r8, r9, 100 ; r8 = lower 64 bits of r9 * 100
```

請注意，目的運算元並沒有參與相乘，它只是接收結果而已。

### 處理溢位

雙運算元和三運算元的乘法，都會把結果截斷以符合目的運算元的大小。單運算元乘法會保留完整的範圍，但結果通常會分成兩個暫存器存放，也就是`rdx`和`rax`。

因此，有時在相乘之前先擴展運算元會很有用，這樣才能把完整的乘積放進單一暫存器。無號運算元會做零擴展，有號運算元則做符號擴展：

```x86asm
movzx eax, di ; di and si hold unsigned 16-bit numbers
movzx ecx, si
mul ecx       ; the 32-bit product fits in eax, and edx is cleared
```

## 除法

和乘法一樣，執行兩數相除也有兩個指令。無號除法使用`div`指令，有號除法則使用`idiv`。

這兩個指令都只使用一個運算元：

```x86asm
div src
idiv src
```

16 位元、32 位元和 64 位元的除法分別使用`dx:ax`、`edx:eax`和`rdx:rax`作為被除數。在這些情況下，兩個暫存器會搭配使用，構成一個 2N 位元的值，其中 N 是運算的大小（16 位元、32 位元或 64 位元）。這個值接著會除以來源運算元。依照運算的大小，商會寫入`ax`、`eax`或`rax`，餘數則寫入`dx`、`edx`或`rdx`。

位元組之間的除法比較特別：它不使用`dl:al`，而是使用`ax`。`ax`的低 8 位元（`al`）會取得運算的商，高 8 位元（`ah`）則取得餘數。

請注意，進行除法之前，被除數中的所有位元都應該設定妥當。`rdx`中被設定的任何位元（8 位元除法時則是`ah`）都會影響被除的值。

在無號除法中，如果被除的值放得進低半部，就應該把高半部清零。任何能清除這些位元的指令都可以。例如在 32 位元除法中，`mov edx, 0`會清除較高的位元。

在有號除法中，則應該對這個值做符號擴展。有些指令可以自動完成這個過程：`cbw`、`cwd`、`cdq`和`cqo`。第一個會依照`al`的符號設定`ah`中的位元。其餘的則分別執行從`ax`到`dx`、從`eax`到`edx`，以及從`rax`到`rdx`的符號擴展。

~~~~exercism/caution
除法中隱含使用的暫存器，例如`rax`和`rdx`，一律會被覆寫。如果之後還會用到這些暫存器中的值，應該在除法前先把它們存起來。
~~~~
