# 簡介

到目前為止，課程大綱還沒有多談型別，但型別在 Julia 中顯然是存在的：

```julia-repl
julia> vals = (42, 4.3, π, "hello", 'Q')
(42, 4.3, π, "hello", 'Q')

julia> typeof(vals)
Tuple{Int64, Float64, Irrational{:π}, String, Char}
```

我們從未指定型別，但 Julia 還是照樣指派了型別。

1. Julia 有 `types`，這是它設計的核心。
2. Julia 通常能「猜出」型別，靠的是 `Type Inference`。

JIT 編譯器會看過（所有）程式碼，了解變數的使用方式，然後_推斷_出一個適合該用途的預設型別。

## 型別提升

在先前幾個概念裡，已經有很多例子把數值型別強制轉成一致的型別，最早從最簡單的算術開始。

```julia-repl
julia> 2 + 1.3
3.3
```

我們把一個整數（Int64）和一個浮點數（Float64）相加，得到的是 Float64 的結果。
同樣地：

```julia-repl
julia> nums = (3, 4.1, 1//4)
(3, 4.1, 1//4)

julia> typeof(nums)
Tuple{Int64, Float64, Rational{Int64}}

julia> [nums...]
3-element Vector{Float64}:
 3.0
 4.1
 0.25
```

在上面的例子中，元組保留了每個元素的型別，但轉成向量後，全部都變成一致的 Float64。

Julia 編譯器了解哪些型別轉換是可行的：整數轉成浮點數沒問題，浮點數轉成整數會失去精度，因此會拋出 `InexactError`。
型別提升會把運算式中的所有值轉成一個共同的型別，這個型別要夠通用，才能和所有輸入相容。

## 型別指定

在解簡單的教學練習時，仰賴型別推斷沒有問題，但對於較大的程式，你很可能需要更精確的控制。

在大多數現代處理器上，整數的預設型別是 `Int64`。
我們在[`Numbers`][numbers]概念中看過，值可以被轉成某個非預設的型別。

```julia-repl
julia> x = Int16(42)
42

julia> typeof(x)
Int16
```

不過，變數 `x` 仍然可以被重新指定成不同的型別：

```julia-repl
julia> x = "changed"
"changed"

julia> typeof(x)
String
```

這就是 `type instability`，它：

- 在小腳本裡非常方便。
- 在較大的程式裡則對效能和可靠性不利。

取而代之，我們可以用 `::` 運算子來設定 `x` 的型別：

```julia-repl
julia> y::Int16 = 42
42

julia> typeof(y)
Int16

julia> y = "changed"
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Int16
The function `convert` exists, but no method is defined for this combination of argument types.
```

現在 `y` 的型別是、而且永遠都會是 `Int16`。
如此一來，編譯器就知道要為它保留多少位元組，也能把其餘的程式碼最佳化成仰賴一個穩定的型別。
就這點而言，這個變數和 C 這類靜態型別語言裡的變數差不多。

## 型別斷言

前面介紹過的型別指定，會用在變數指定的左側，用來限制該變數的型別。

把 `::` 運算子用在一個值、或任何會求值成值的東西上，通常是一種_斷言_，斷言該值必須是這個型別，否則就應該拋出錯誤。

```julia-repl
julia> 42::Number
42

julia> "two"::Number
ERROR: TypeError: in typeassert, expected Number, got a value of type String
```

常見的用法是搭配函式的回傳值，當作最後一個簡單的檢查，確認函式的行為符合預期。

## 型別階層

`Int64`、`Int16`、`String`、`Char`：這些型別到底是從哪裡_「來」_的。

在許多物件導向（OO）語言裡，每個型別都是一個類別，子類別化會把它們排成一個類別階層，並由類別方法定義行為。

Java 和 Ruby 是這種模式的明顯例子，但就連 Python 在內部也是類似的。

***Julia 沒有類別。***

文件上給的理由是，物件導向功能會干擾 JIT 編譯器，並損害執行時期的效能。

然而，看看這段程式碼：

```julia-repl
julia> y::Int16 = 42
42

julia> typeof(y)
Int16

julia> supertype(Int16)
Signed

julia> supertypes(Int16)
(Int16, Signed, Integer, Real, Number, Any)
```

補充一些細節：

- `Int16` 是一個型別，我們可以建立這個型別的變數。
- `Int16` 是 `Signed` 的子型別，`supertype()` 函式會告訴我們這件事。
- 型別構成一個階層，往上經過 `Integer`、`Real` 和 `Number`，最頂端是 `Any`，而 `subtypes()` 會列出階層中的這個分支。

所有分支最後都終止於 `Any`，它的獨特之處在於自己是自己的父型別。

```julia-repl
julia> supertypes(String)
(String, AbstractString, Any)

julia> supertype(Any)
Any
```

所以，Julia 沒有 `class` 階層，但它_確實_有 `type` 階層。

我們終究會試著拆解這一切是怎麼運作的，但還有很多東西要先探索。

## 型別測試

我們可以用 `typeof()` 以平常的方式測試是否相等。

```julia-repl
julia> typeof(11)
Int64

julia> typeof(11) == Int64
true

julia> typeof(11) == Number
false
```

型別的相等必須完全精確，因為這種比較方式並不理解型別階層。

更有彈性的是 `isa`，它會告訴我們某個值的型別是否和比較對象相同，或是它的子型別。
它可以用函式形式或中綴形式使用。

```julia-repl
julia> 12 isa Int64
true

julia> 12 isa Number
true

julia> isa(12, Number)
true

julia> 12 isa String
false
```

注意 `isa` 左邊要放的是 `value`，不是 `type`。

用這種方式比較兩個_型別_會得到出乎意料的結果。
正確的運算子是 `<:`，之後的概念裡我們還會看到很多次。

```julia-repl
julia> Int64 isa Number  ## Don't do this!
false

julia> Int64 <: Number
true
```

## 抽象型別與具體型別

我們看過，型別階層構成一個樹狀結構（就資訊科學的意義來說，樹根在最上面）。

樹裡的每個項目都是一個 `node`，而它們可以分成幾類：

1. 有子型別的節點稱為 `abstract`。
2. 沒有子型別的葉節點稱為 `concrete`。

```julia-repl
julia> subtypes(Integer)  # an abstract type
3-element Vector{Any}:
 Bool
 Signed
 Unsigned

julia> subtypes(Int64)  # a concrete type
Type[]
```

這是一個重要的區別，因為只有具體型別才能被 `instantiated` 成變數。


```julia-repl
julia> a::Int16 = 42
42

julia> typeof(a)
Int16

julia> b::Integer = 42
42

julia> typeof(b)
Int64
```

注意，試著使用抽象型別（在這個例子裡）並不會產生錯誤訊息，但編譯器會建立一個適當的具體型別：`Int64`，而不是 `Integer`。
至少它防止變數被指定成非整數：

```julia-repl
julia> f::Integer = "hello"
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Integer
The function `convert` exists, but no method is defined for this combination of argument types.
```

因此，用抽象型別做型別指定，就是對變數型別的一種_限制_，限制成（上述例子中）`Integer` 的任何子型別。
這在程式語言的世界裡算是少見：比 C 的型別指定弱，比近期版本 Python 的型別提示強。

`isabstracttype()` 和 `isconcretetype()` 這兩個函式可以用來測試。
注意，它們並不只是彼此的否定：之後的概念裡我們會看到，有些型別既不是抽象也不是具體。


```julia-repl
julia> isconcretetype(Integer), isabstracttype(Integer)
(false, true)

julia> isconcretetype(Int64), isabstracttype(Int64)
(true, false)

# Vector is neither
julia> isconcretetype(Vector), isabstracttype(Vector)
(false, false)
```
