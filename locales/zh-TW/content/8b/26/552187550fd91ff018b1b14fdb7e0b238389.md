# 指令

在最近一次資訊安全審查之後，你被要求清理組織封存的日誌檔案。

## 1. 找出混亂的日誌行

你需要大致了解封存中有多少日誌行不符合現行標準。
你認為用一個簡單的測試就能判斷一行日誌是否有效。
一行日誌要被視為有效，必須以下列其中一個字串開頭：

- `[DEBUG]`
- `[INFO]`
- `[WARNING]`
- `[ERROR]`

實作 `is_valid_line` 函式，在日誌行有效時回傳 `True`。

```gleam
log_parser.valid_line("[ERROR] Network Failure")
// -> True

log_parser.valid_line("Network Failure")
// -> False
```

## 2. 拆分日誌行

開始進行日誌解析專案後不久，你發現某個應用程式的日誌不像其他應用程式那樣會分行。在這個專案裡，原本應該是各自獨立的行，卻全部擠在同一行，並以 `<--->` 或 `<*~*~>` 這類花俏的箭頭連接起來。

事實上，任何以 `<` 為第一個字元、以 `>` 為最後一個字元，且中間包含零個或多個 `~`、`*`、`=`、`-` 的字串，都可以在本專案的日誌中當作分隔符號。

實作 `split_line` 函式，它接收一行日誌並回傳一個字串陣列。

```gleam
log_parser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
// -> ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. 為日誌行標上使用者名稱

你注意到有些日誌行包含提到使用者的句子。
這些句子一定包含字串 `"User"`，後面接著一個或多個空白字元，然後是使用者名稱。
你決定為這類日誌行加上標記。

實作 `tag_with_user_name` 函式來處理日誌行：

- 不包含字串 `"User"` 的日誌行維持不變。
- 對於包含字串 `"User"` 的日誌行，在該行前面加上 `[USER]`，後面接著使用者名稱。

```gleam
log_parser.tag_with_user_name("[INFO] User Alice created a new project")
// -> "[USER] Alice [INFO] User Alice created a new project"
```

你可以假設：

- 每一次出現字串 `"User"`，後面都接著一個或多個空白字元以及使用者名稱。
- 每一行最多只會出現一次字串 `"User"`。
- 使用者名稱是非空字串，且不包含空白。
