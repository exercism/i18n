# 字串建構器

`STR`是不可變的，`FSTR`則不是。文字已經完成時用`STR`，還在組裝時用`FSTR`。

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## 一定要把結果指定回去

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR`以**攤銷式倍增**的方式成長：當空間不夠時，它會取得一個新的、更大的陣列（大小是原來的 2 倍），再把內容複製進去。所以結果通常是同一個物件，偶爾才會是另一個。每次都寫成`b := b + x`，在兩種情況下都正確，也是唯一值得記住的寫法。

倍增讓整體工作量與長度成正比，而不是與長度的平方成正比：複製變得更貴的速度，正好和它變得更罕見的速度一樣快。

## 為什麼不直接用 `+` 串接 `STR`？

用`+`串接固定且少量的片段，清楚又好用：

```sather
   return piece + " by " + composer;
```

問題只出在迴圈裡，因為在寫程式的當下，根本不知道總共會串接多少次。一個粗略的判斷原則：如果`+`出現在`loop`裡面，就改用`FSTR`。

## 實用的常式

| 呼叫 | 作用 |
| --- | --- |
| `b + x` | 附加；`x` 可以是 `STR`、`CHAR`、`INT`、`BOOL` 等 |
| `b.size` | 目前有幾個字元 |
| `b.str` | 一個完成的`STR` |
| `b.clear` | 清空內容，但保留已配置的空間 |

## 跳脫字元

| 寫法 | 代表 |
| --- | --- |
| `"\n"` | 換行 |
| `"\t"` | 定位點 |
| `"\""` | 雙引號 |
| `"\\"` | 反斜線 |
