# 關於字元

這可是個可能非常_龐大_的主題！
要為它寫一本厚書完全做得到，而且真的有好幾個人這麼做了（在 Amazon 搜尋「unicode book」就能看到一些例子）。

## 簡史

在幾十年前，電腦處理字元要簡單得多，當時的程式設計師都假設英文是唯一重要的語言。
所以呢：26 個字母（含大小寫）、10 個數字、幾個標點符號，再加上一個會讓鈴聲響起的編碼（0x07），全部都能塞進 7 個位元裡，也就是 [ASCII][wiki-ascii] 字元集。

很自然地，有人開始問：那 à、ä 和 Ł 怎麼辦？接著又有人問起 ऄ、ஹ 和 ญ，而年輕人則想要 emoji 😱。
這該怎麼辦呢？

長話短說，許多聰明又有耐心的人得在委員會裡待上好幾年，才敲定 [Unicode][web-unicode] 字元集，以及 [UTF-8][wiki-utf-8] 之類編碼的細節，而且一大堆軟體都得進行_非常_複雜的改寫。
不僅如此，還順便引入了許多新的 bug。

為了避免_所有東西_都壞掉，Unicode/UTF-8 的設計確保前 127 個編碼和 ASCII 完全相同（_連那個鈴聲也是_）。

## Kotlin 裡的字元

2005 年之後才設計的語言有個巨大的優勢：那時已經有了相當穩定的 Unicode 標準。

Kotlin（2011 年首次發布）可以理所當然地假設，使用者會用到各種（人類）語言，也需要 Unicode 來表達它們。

~~~~exercism/advanced
Kotlin 的[字元][ref-char]是 16 位元（UTF-16）的 [`codepoints`][wiki-codepoint]，和 JVM 的 `char` 一樣。
這足以表達大多數文字系統的字母，但涵蓋不了所有 emoji。

完整的 Unicode 標準每個字元最多用到六個位元組（48 位元），稱為 [`grapheme`][wiki-grapheme]。

Kotlin 的 `Strings` 在需要時會用多個 codepoints 來表示一個字元，藉此支援完整的標準。
例如，😱 會是 `\uD83D` 和 `\uDE31`。

很遺憾，Java 沒有內建的 grapheme 支援，Kotlin 為了相容性也沒有。

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


字元常值寫在單引號裡，和寫在雙引號裡的字串不同。
對來自 C/C++ 世界的人來說，這大概很理所當然，但對 Python 和 JavaScript 程式設計師來說可能很容易搞混。

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

在 `Char` 和 `Int` 之間轉換很簡單：

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

編譯器允許對 `Char` 做_某些_形式的整數運算：

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## 一些用於 `Char` 的函式

一如往常，[函式][ref-char-lib]多到沒辦法在這裡一一討論，所以這裡只挑幾個出來講。

- 對於適用的字母系統，用 [`uppercase()`][ref-uppercase] 和 [`lowercase()`][ref-lowercase] 改變大小寫。
- 用 [`isUpperCase()`][ref-isuppercase] 和 [`isLowerCase()`][ref-islowercase] 測試大小寫。
- 用以下方法測試字元的類型：
  - [`isLetter()`][ref-isletter]：涵蓋許多字母系統（Unicode 中的 Lu、Ll、Lt、Lm 和 Lo 分類）
  - [`isDigit()`][ref-isdigit]：範圍是 0..9（Unicode 中的 Nd 分類）
  - `isLetterOrDigit()`：結合前兩者
  - [`isWhitespace()`][ref-iswhitespace]：任何空白字元（Unicode 中的 Cc、Zp、Zl 和 Zs 分類）

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

此外，[正規表達式][ref-regex]（之後的某個概念會專門介紹）能進行強大的搜尋與操作。

## Char 清單與字串的互轉

要把 `String` 轉成 `Char` 的 `List`，可以用 `toList()`。

要把 `Char` 的 `List` 轉成 `String`，則有 [`joinToString()`][ref-jointostring] 函式，它接受一個分隔符號（通常是空字串）作為引數。

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

注意，`joinToString()` 是作用在 List 或 Array 上。
要把單一 `Char` _轉型_成一個字元的字串，請用 `toString()`。

```kotlin
'a'.toString() // => "a"
```

想檢查某個字元是否出現在 `String`、`Char` 清單或陣列裡，可以用 `in`，它對應到 [`contains()`][ref-contains] 函式。

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
