# 例外

```sather
   raise "Unknown prop: " + prop;
```

```sather
   protect
      ...
   when $STR then
      #OUT + exception.str;
   end;
```

## raise

`raise`接受任何物件。引發`STR`是最簡單的情況，也是這個練習所用的。自己定義的類別能攜帶更多資訊，例如是哪個 prop、原本需要多少個，代價是得找個地方定義它。

例外會往外穿過一層層呼叫者，直到某個`protect`捕捉到它。如果都沒有，程式就會停止並印出它。

Sather 不會記錄一個常式可能引發哪些例外，也不會強迫呼叫者處理它們。常式的型別裡沒有任何地方說明它可能會失敗。

## protect

```sather
   protect
      body
   when $STR then
      ...
   when SOME_CLASS then
      ...
   end;
```

分支會依序嘗試，第一個型別符合所引發之值的分支會執行。`exception`就是那個值，而且只在分支內的作用域裡有效。

沒有符合分支的`protect`不會捕捉：例外會繼續往外傳，就好像這個`protect`不存在一樣。

## 在哪裡捕捉

在真的能採取行動的地方捕捉。一個把例外吞掉、然後拿著捏造的值繼續下去的`protect`，會把大聲的失敗變成安靜的錯誤答案，那更糟。

```sather
   -- almost always wrong
   protect
      return risky;
   when $STR then
      return 0;
   end;
```

## 例外還是契約？

兩者都跟出錯有關，但處理的是相反的狀況。

**例外**用於真的可能發生、而且呼叫者很可能無法預防的事，例如表格裡少了一個 prop、檔案不在那裡。

**契約**是下一個練習的主題，用於絕對不該發生的事，例如呼叫者傳入負的權重，等於宣告呼叫者有 bug。契約只在你要求時才會檢查，而違反契約會讓程式停止，而不是引發可以被捕捉的東西。

大致上：如果一個謹慎的呼叫者仍可能遇上，就用 raise。如果遇上代表呼叫者寫錯了，就把它放進契約裡。
