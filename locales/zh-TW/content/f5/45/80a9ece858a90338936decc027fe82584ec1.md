# 泛型類別

```sather
class LOST_BOX{T} is
   attr item : T;
   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;
end;
```

## 參數是什麼

`T`代表在使用處提供的型別。程式編譯時，Sather 會為實際用到的每個組合建立一個獨立的類別。所以：

- `LOST_BOX{STR}`與`LOST_BOX{INT}`是不相關的型別；
- 不會有執行階段檢查，不會裝箱，也不會轉換；
- 類別裡的錯誤會在使用它的每個型別上各出現一次。

這和 C++ 樣板或 Rust 泛型的做法相同，而和 Java 泛型不同，Java 會抹除型別，所有東西實際上都是物件。

## 受約束的參數

一個未加約束的`T`可以被指定、傳遞和回傳，除此之外什麼都不能做，因為對它一無所知。若要在它上面呼叫常式，就得說明它必須符合什麼：

```sather
class LOST_BOX{T < $STR} is
   describe : STR is return "a box holding " + item.str; end;
end;
```

`T < $STR`要求`T`符合`$STR`，作為回報，`item.str`就可以被呼叫。未加約束的`T`做不到的任何事，都可以靠約束來開放。

少了約束，`item.str`就無法編譯，而且錯誤訊息會指出泛型類別內的那一行，而不是使用它的那一行。

## 泛型常式？

沒有這種東西。只有類別能接受參數。若某個常式需要處理多種型別，它要嘛住在泛型類別裡，要嘛接受像`$STR`這樣的抽象型別。

## 兩者之間如何選擇

| | 泛型類別 | 抽象類別 |
| --- | --- | --- |
| 決定時機 | 編譯時 | 執行時 |
| 容納 | 每個具現化一種型別 | 任何符合的型別 |
| 成本 | 無 | 一次分派 |

`ARRAY{$ACT}`兩者都用上了：在元素型別上是泛型，在元素可以是什麼上則是抽象。

當整個過程中型別都相同，而且類別的使用者知道這一點時，就選用泛型類別。當多種型別必須共存於同一個集合時，就選用抽象類別。
