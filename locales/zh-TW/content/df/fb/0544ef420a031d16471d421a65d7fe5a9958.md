# 提示

## 一般

- 你的解答檔案會被另一份檔案引入，並由那份檔案呼叫你的巨集。
  請讓每個巨集的名稱與引數順序都和任務給定的完全一致，否則檔案將無法組譯。
- 巨集的引數是權杖，在巨集主體中出現的每一處都會以`%1`、`%2`、`%3`的形式代入。
  它們可以是暫存器、位址運算式或字面值，只要每次展開都是有效的指令即可。
- 檢查每個巨集時，不只看它寫入了什麼，也要看它沒有動到哪些暫存器。
  請閱讀每個任務中關於會破壞哪些暫存器的說明，並且只修改它允許修改的暫存器。

## 1. 為格式常數命名

- 單行的`%define`會為某個值取一個名稱，讓程式其餘部分可以讀取這個名稱，而不必直接寫出未命名的數字。
  對於固定不變的數字，`equ`的作用相同，而且通常是定義常數時的慣用選擇。
- 這些位元組常數可以寫成十六進位（`0x20`），也可以寫成字元字面值（`' '`）。
  兩者組譯出來的結果是同一個值。

## 2. 撰寫`fill_run`巨集

- 你應該給`rcx`取一個好讀的名稱`COUNTER`。
- `fill_run`是一個多行巨集，接受 3 個引數。
  多行巨集以`%macro ... %endmacro`定義。
- `fill_run`的第一個引數是放在 64 位元一般用途暫存器中的記憶體位址。
  第二個是計數值，可以透過 64 位元一般用途暫存器或以立即值的形式傳入。
  第三個是要寫入的位元組，以立即值的形式傳入。
  你應該在巨集中規劃程式碼，以符合這些規格。
- `fill_run`唯一允許修改的暫存器是`COUNTER`。
- 巨集內的迴圈通常需要一個加上`%%`前置字元的標籤。
  如果沒有這個前置字元，每次呼叫巨集時都會建立相同的標籤，當巨集被呼叫超過一次時就可能造成錯誤。

## 3. 撰寫`lay_columns`巨集

- `lay_columns`是一個多行巨集，接受 2 個引數。
  多行巨集以`%macro ... %endmacro`定義。
- `lay_columns`的兩個引數都透過 64 位元一般用途暫存器傳入。
  第一個是記憶體位址，第二個是整數。
  你應該在巨集中規劃程式碼，以符合這些規格。
- `lay_columns`唯一允許修改的暫存器，就是當作引數傳入的那兩個。
- 巨集必須寫入的位移數量，在組譯時就已經固定。
  你可以使用`%rep ... %endrep`來重複程式碼。
- 位移的計算方式為`offset[i] = margin + i * COLUMN_STRIDE`。
  `margin`是巨集的第二個引數。
  `i`是迴圈計數器，可以定義為`%assign`變數。

## 4. 撰寫`set_header`巨集

- `set_header`是一個多行巨集，接受 2 個引數。
  多行巨集以`%macro ... %endmacro`定義。
- `set_header`的第一個引數是有效記憶體位址的運算式。
  它接受一個基底暫存器，可與以`1`、`2`、`4`或`8`縮放的索引暫存器相加，並加上一個立即值。
  也就是說，單純的`rdi`是合法的，`rdi+rax*4+2`也是。
- `set_header`的第二個引數是立即值，可能的值為`0`、`1`或`2`。
- `set_header`完全不能修改任何暫存器。
- 你應該在組譯時，依照第二個引數，有條件地將一個位元組複製到目的地位址。
  值為`0`時應複製`PLAIN`，值為`1`時應複製`RULED`，值為`2`時應複製`BOXED`。
