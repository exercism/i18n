# 簡介

## `Base.@kwdef`

巨集`Base.@kwdef`可以自動定義接收關鍵字引數的建構子，方便你定義[結構][struct]，同時也能為欄位設定預設值。

例如，以下的定義

```julia
Base.@kwdef struct HumanStats
    birthyear::Int
    height::Int
    mass::Int
    bmi::Float64 = mass / (0.01 * height)^2
end
```

會一次定義三個建構子

```julia-repl
julia> methods(HumanStats)
# 3 methods for type constructor:
[1] HumanStats(; birthyear, height, mass, bmi) [...]
[2] HumanStats(birthyear::Int64, height::Int64, mass::Int64, bmi::Float64) [...]
[3] HumanStats(birthyear, height, mass, bmi) [...]
```

其中包括一個以關鍵字引數為基礎的建構子

```julia-repl
julia> HumanStats(
           birthyear = 2002,
           height = 193,
           mass = 83
       )
HumanStats(2002, 193, 83, 22.28247738194314)
```

而標準定義

```julia
struct HumanStats
    birthyear::Int
    height::Int
    mass::Int
    bmi::Float64
end
```

只會定義以下兩個

```julia-repl
julia> methods(HumanStats)
# 2 methods for type constructor:
[1] HumanStats(birthyear::Int64, height::Int64, mass::Int64, bmi::Float64) [...]
[2] HumanStats(birthyear, height, mass, bmi) [...]
```

而且還得手動定義一個以關鍵字為基礎的建構子。

### 什麼時候該使用`Base.@kwdef`？

當結構需要接收大量引數時，以關鍵字為基礎的建構子特別好用，尤其是當引數的型別或值與引數本身的意義沒有直接關聯時。

看看以下的定義：

```julia
dirk = BasketballPlayer(1978, 1994, 2019, 213, 111, 42, 1998, [2011], 31560, 11489, 3651)
```

如果不了解這個型別的定義，就看不出每個值代表什麼意思。即使知道定義，大概也得一再回頭查它們的順序。

不過，改用關鍵字建構子時，它們的意思就一目了然：

```julia
dirk = BasketballPlayer(
    birthyear = 1978,
    career_start = 1994,
    career_end = 2019,
    height = 213,
    weight = 111,
    number = 42,
    drafted = 1998,
    championships = [2011],
    points = 31560,
    rebounds = 11489,
    assists = 3651
)
```

~~~~exercism/caution
`Base.@kwdef`沒有被匯出，手冊裡也沒有相關記載，因此不屬於[Julia 的公開 API][public-api]。
這代表它的介面在技術上不保證穩定，可能會在 Julia 的次要版本更新之間改變。

不過，這個巨集在整個生態圈裡被廣泛使用，應該不太可能以破壞相容性的方式改變。
