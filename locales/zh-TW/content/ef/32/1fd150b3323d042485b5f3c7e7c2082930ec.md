# 簡介

Factor 的執行緒屬於*協作式協程*：它們共用同一個 OS 執行緒，在 I/O 與明確的讓出點互相交棒，而且永遠不會真正同時執行。你在讓出點*之間*所做的任何事，都會以一個不中斷的步驟完成。但如果一個複合操作（讀取、修改、寫入）中途讓出，另一個執行緒就可能趁隙介入，在你完成之前改變世界，這就是競爭條件。

這個練習涵蓋四個反覆出現的基本操作：

## `parallel-map`：在序列上進行 fork/join

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

位於 [`concurrency.combinators`][combinators] 中。它會為每個元素啟動一個執行緒，執行 quotation，並依相同順序把結果收集成一個新的序列：

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`：啟動執行緒

```
spawn ( quot name -- thread )
```

位於 [`threads`][threads] 中。quotation 會並行執行；`name` 是供除錯用的標籤。回傳的執行緒控制代碼在這個層級多半沒什麼用，直接 `drop` 掉就好。

## Promise：單次的值交接

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

位於 [`concurrency.promises`][promises] 中。promise 是一次性的信箱：一個執行緒負責履行它，其他執行緒則讀取它。`?promise` 會阻塞，直到 promise 被履行為止，然後回傳該值。

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

`parallel-map` 就是由 `spawn` 加上 `<promise>` 打造出來的；當每個任務做的事不只是「計算一個元素」時，自己動手實作這些東西就很有用。

在序列上典型的 fan-out/join 形式是：為每個輸入建立一個新的 promise，啟動一個負責處理工作並 `fulfill` 該 promise 的執行緒，把所有 promise 收集成一個序列，然後對每一個呼叫 `?promise` 等待完成。Locals 讓這段程式碼更好讀：在 `[| | ]` lambda 內用 `:>` 把 promise 綁定到一個名稱，這樣啟動的 quotation 就能對它形成閉包：

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## 鎖：互斥

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

位於 [`concurrency.locks`][locks] 中。同一時間只有一個執行緒能持有某個鎖。`with-lock` 會取得鎖、執行 quotation、釋放鎖，即使 quotation 拋出例外也一樣。

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

只要一個值*會被多個執行緒讀取或寫入*，而且對它的操作並非天生具備原子性，就該使用鎖。讀取和寫入都需要鎖，因為中途讓出的讀取可能會看到撕裂的狀態。
