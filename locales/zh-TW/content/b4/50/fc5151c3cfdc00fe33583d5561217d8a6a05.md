# Phix 中的數字

Phix 有兩種可以存放數字的資料型態：整數和 atom。
整數是有號的，而且比機器字組少一個位元，因此（劇透警告）即使在 64 位元上也不足以完成這道練習。
而 atom 則可以存放精度更高的整數，至少在 64 位元上已經足夠；當你在 exercism.org 網站上線上執行時，用的必然是 64 位元，在 CLI 上大概也是，只要那是你安裝的版本就行。只要在終端機主控台執行 'p'，它就會顯示出來給你看喔。

## 32 位元機器

不過，即使是在 32 位元上的 atom，其精確度與大小仍然不足以完成這道練習。要解決這個問題，你可以改為回傳字串：字串必須完全精確，不能有逗號或底線，但在 64 位元上你並沒有這個義務。你可以自行手動組出這樣的字串，也可以使用任意精度函式庫，例如 [mpfr][mpfr]。

在使用 p2js 之前，32 位元版本的 Phix 對於在 desktop/Phix 上進行充分的測試仍然不可或缺，因為 JavaScript 本質上就是 32 位元（更精確地說，或許是 53 位元），即使是在 64 位元機器上執行的 64 位元瀏覽器也一樣。

Phix 的整數和 atom 能容納的內容有哪些精確上限，當然在 [manual][manual] 裡有更詳細的說明。

[mpfr]: http://phix.x10.mx/docs/html/mpfr.htm
[manual]: http://phix.x10.mx/docs/html/atoms.htm
