# 例外

有些常式無法回答。當有人向`count_of`要一個不在桌上的道具時，它沒有數字可以給，而零會是謊言，因為零代表「我們一個都沒有」，而不是「根本沒有這種東西」。

**例外**就是常式表達自己無法回答的方式。

## 引發

`raise`會放棄這個常式，並把一個值交給呼叫它的一方。

```sather
   count_of(props : FMAP{STR,INT}, prop : STR) : INT is
      if ~props.has_ind(prop) then
         raise "Unknown prop: " + prop;
      end;
      return props.get(prop);
   end;
```

`raise`之後的程式碼都不會執行。這個常式不會回傳，所以沒有答案可以檢查，呼叫端也無法當作有答案一樣繼續下去。

引發的值通常是一個字串，說明出了什麼錯。

## 捕捉

`protect`會執行一段程式碼，並準備好它可能引發例外。

```sather
   protect
      taken ::= count_of(props, prop);
      #OUT + "There are " + taken;
   when $STR then
      #OUT + "Cannot: " + exception.str;
   end;
```

如果沒有引發任何例外，`protect`之後的部分就會執行，而`when`分支則會被跳過。如果有東西引發例外，`protect`那部分的其餘程式碼就會被放棄，改由相符的`when`執行。

`when $STR then`會捕捉引發的字串。`exception`是剛才被引發的值，在分支內可以取用。

## 向外傳遞

沒有捕捉例外的常式，不必對它做任何處理。例外會向外傳遞，穿過每一層呼叫端，直到某處捕捉到它：

```sather
   take_one(props : FMAP{STR,INT}, prop : STR) : INT is
      -- If this raises, take_one raises too. Nothing here says so.
      have ::= count_of(props, prop);
      ...
   end;
```

這正是例外的重點。發現問題的常式和知道該怎麼處理的常式，通常不是同一個，而中間的其他常式可以完全不管它。
