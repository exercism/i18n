# 說明

管理層開始把達爾文式原則套用到遙控車專案 [exercise:csharp/remote-control-competition]() 上。開發者被拆成 _Red_ 和 _Blue_ 兩個團隊，要各自獨立改良設計，不必理會另一個團隊的設計決定。

他們請你來看看這些程式碼，想想怎麼做最能為測試用途合併兩邊的成果。

## 1. 為兩個團隊的程式碼找到更合適的隔離方式

請使用 `namespaces`，更清楚地表達程式碼的意圖。

目前，`Motor`、`Telemetry` 這類重要的型別，更不用說 `RemoteControlCar` 本身，都巢狀在一個外層的 static class `<Color>RemoteControlCarTeam`裡。這個外層類別唯一的用途，就是讓同名的型別能在程式中並存。用 namespace 來表達這件事會更好。下一個練習你會看到，就這些用途而言，`namespace` 比 `static class` 更有優勢。

## 2. 簡化命名方式

雖然管理層堅持，團隊在定義中就該叫 `RedRemoteControlCarTeam` 和 `BlueRemoteControlCarTeam`，但引用團隊時這些名字實在有點笨重。請找出方法，在打造車子時改用較短的識別字 `Red` 和 `Blue`。
