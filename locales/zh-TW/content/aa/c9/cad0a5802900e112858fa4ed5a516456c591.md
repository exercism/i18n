# 關於

雖然 Elixir 程式設計師常說「let it crash」，也常為「happy path」撰寫程式，但我們經常還是得救援函式呼叫，好回傳特定的值、訊息，或釋放系統資源。

- 在正常情況下會引發錯誤的函式，名稱結尾應該加上`!`。
- 函式也可以改用回傳原子與元組的方式來表示成功與失敗：

  ```elixir
  Map.fetch(%{a: 1}, :a)
  # => {:ok, 1}
  Map.fetch(%{a: 1}, :b)
  # => :error

  Map.fetch!(%{a: 1}, :b)
  # => raises KeyError
  ```

## 避免反模式

避免使用錯誤來控制邏輯流程的程式設計模式。這在 Elixir 裡是反模式。

```elixir
# Avoid using errors for control-flow.
try do
  {:ok, value} = MyModule.janky_function()
  "All good! #{value}."
rescue
  e in RuntimeError ->
    reason = e.message
    "Uh oh! #{reason}."
end

# Rather, use control-flow structures for control-flow.
case MyModule.janky_function() do
  {:ok, value} -> "All good! #{value}."
  {:error, reason} -> "Uh oh! #{reason}."
end
```
