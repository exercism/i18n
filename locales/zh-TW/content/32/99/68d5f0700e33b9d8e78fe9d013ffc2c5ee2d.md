# 簡介

## C++ 中的 `auto` 關鍵字

在 C++ 中，`auto`關鍵字是 C++11 引入的強大功能，用來宣告型別會被推導出來的變數。
編譯器會根據初始值推導出變數的型別，讓程式碼更好讀、也更好維護。

## 使用範例

看看下面這個用`auto`宣告變數的例子：

```cpp
auto dragon_population{3};          // dragon_population is deduced as an integer
auto westeros{7.7777};              // westeros is deduced as a double
auto wedding_location{"The Twins"}; // wedding_location is deduced as a const char*, not std::string
```

每一個例子裡，變數的型別都是從初始化時所用的值推導出來的。

## 型別推導

`auto`關鍵字能減少明寫型別的冗長感，讓程式碼更精簡、更好讀。

```cpp
const std::vector<std::string> pigeon_pie{"flour", "butter", "pigeon", "salt"};
auto purple_wedding_pie{pigeon_pie};
purple_wedding_pie.emplace_back("the strangler");
```

在這段迴圈中，`auto`把`purple_wedding_pie`的型別推導為`std::vector<std::string>`，不必再明寫一次型別。

## 相容性

`auto`關鍵字能與各種 C++ 結構搭配，是現代 C++ 程式設計中用途廣泛的工具。

```cpp
auto& element{array[0]};           // reference to an element
const auto object{otherObject};    // const type version of otherObject's type
auto* ptr{&x};                     // pointer to x with the same type as x, but as a pointer.
```

之後的單元裡，我們會經常看到`auto`關鍵字搭配 lambda 運算式、以範圍為基礎的`for`迴圈，以及迭代器。

## 智慧指標

智慧指標是現代 C++ 的功能，目的是提供自動記憶體管理，協助避免原生指標常見的記憶體洩漏和懸空指標。
它們像是原生指標的包裝，額外提供自動釋放記憶體等功能，在指標不再需要時自動把記憶體釋放掉。

## 一般語法

智慧指標在 C++ 標準函式庫中通常以類別模板實作。
最常用的兩種智慧指標是`std::unique_ptr`和`std::shared_ptr`。

## 獨佔指標

`std::unique_ptr`是一種獨佔物件所有權的智慧指標。
它確保在任何時刻，資源都只由一個`std::unique_ptr`物件所擁有。
當擁有資源的`std::unique_ptr`被銷毀或重置時，它會自動解構物件並釋放記憶體。

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## `std::make_unique()` 的優點

建立`std::unique_ptr`時，建議使用`std::make_unique()`，而不是直接用`new`配置記憶體。
`std::make_unique()`有幾項優點：
1. **例外安全**：`std::make_unique()`能保證例外安全。
  如果在建構物件期間拋出例外，記憶體會自動被釋放，避免記憶體洩漏。
2. **清楚明瞭**：使用`std::make_unique()`讓程式碼更清楚、更精簡。
  它不必明寫要配置的型別，因為模板引數會自動推導出來。
3. **最佳化機會**：比起用`new`手動配置記憶體，編譯器更有機會有效最佳化`std::make_unique()`，效能可能因此提升。
4. **避免誤用**：手動建構`std::unique_ptr`時，有可能把底層資源刪除掉。
  當`std::unique_ptr`在離開作用域時試圖刪除它，就會導致未定義行為。

## 共享指標

`std::shared_ptr`是一種智慧指標，允許讓多個`std::shared_ptr`物件共享同一個資源的所有權。
它會追蹤有多少個共享指標正在引用這個資源，只有在最後一個擁有該資源的共享指標離開作用域或被重置時，才會釋放記憶體。

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
在 C++17 及更早的版本中，並不直接支援透過`std::make_shared<T[]>`將`std::shared_ptr`用於陣列。
雖然可以用`std::make_shared<T[]>`配置陣列，但直接由它建立共享指標可能會導致未定義行為，因為單一物件和陣列在記憶體管理上有所不同。
建議改用`std::vector`或自訂刪除函式，才能有效以共享指標管理陣列。
在 C++17 中處理陣列配置與共享指標時，請務必確認與你的編譯器和標準函式庫實作相容。
~~~~

## `std::make_shared()` 的優點

和`std::make_unique()`類似，`std::make_shared()`也帶來記憶體效率提升、例外安全和可讀性等好處。
它把控制區塊和受管理物件的記憶體配置合併成一次操作，提升效率並降低記憶體洩漏的風險。
此外，自動推導模板引數能簡化程式碼並提升可讀性。
在 C++ 中操作`std::shared_ptr`物件時，使用`std::make_shared()`能寫出更簡潔、更安全、更有效率的程式碼。

## 使用建議

預設使用智慧指標：獨佔所有權用`std::unique_ptr`，共享所有權用`std::shared_ptr`。
原生指標則保留給不具所有權的引用，或與舊有程式碼介接時使用。
大多數情況下，`std::unique_ptr`就足以處理獨佔所有權，因為它提供輕量的記憶體管理，沒有引用計數的額外負擔。
`std::shared_ptr`則應謹慎少用，因為除非真的需要共享所有權，否則它會帶來額外負擔和複雜度。
