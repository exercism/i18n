# 關於

`Result` 型別讓函式可以回傳單一個值，同時表達以下所有資訊：
- 操作成功或失敗
- 成功時，操作產生的值
- 失敗時，失敗的原因

在其他不支援 `Result` 這類型別的程式語言中，常見以下幾種做法來達成上述目標：
- 函式回傳一個數字代碼，表示成功或失敗的原因，並要求一個輸出參數來接收成功時的值。
- 函式成功時回傳值，發生錯誤時回傳 NULL，然後再用另一個函式取得錯誤代碼，以表示失敗的原因。

另一種常見的錯誤處理機制是例外。發生失敗時，例外會突然跳出目前的函式，把控制權轉移给呼叫堆疊中的第一個處理器。
如果沒有處理器「捕捉」到這個例外，程式就會中止。

## 使用 `Result` 型別的優點

* __編譯期安全__：把函式呼叫的成功或失敗明確表達在型別系統中，編譯器就能確保呼叫端的程式碼處理所有失敗情況，避免一大類可能由 null 引發的 bug。

* __執行期安全__：`Result` 型別不使用 `null`，而是用 `Error` 來表示失敗，因此不可能發生 `NullReferenceException`。

* __明確的錯誤處理__：呼叫會回傳 `Result` 的函式時，程式碼必須認知到這個呼叫可能失敗；呼叫端的程式碼必須刻意處理這些失敗。不會有無聲的失敗，也不會有令人意外的例外。

* __可預測的控制流程__：`Result` 就像其他任何值一樣被回傳，不會像例外那樣跳出呼叫堆疊。你隨時都知道錯誤從哪裡產生，又是如何往外傳遞。

* __更好的可讀性與可維護性__：回傳 `Result` 能讓函式簽章清楚指出成功與失敗時的預期行為。

## 用法

`Result` 型別是泛型型別，包含兩種底層型別：
- 操作成功時結果值的型別
- 失敗時表示失敗原因的型別

`Result` 型別也是一種[差別聯集][discriminated-union]，可能包含以下幾種情況：
* `Ok <value>` 代表成功的結果
* `Error <reason>` 代表失敗

以下函式示範如何建立一個 `Result` 值：

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

在這個範例中，`Ok` 的值是字串（傳入的名稱），`Error` 的值也是字串（以人類可讀形式表示的錯誤原因）。

## 讀取 `Result` 值的內容

請看以下的型別定義與函式簽章：

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

呼叫 `openFile` 函式的程式碼可以用模式比對來處理成功與失敗的情況，如下例所示：

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
