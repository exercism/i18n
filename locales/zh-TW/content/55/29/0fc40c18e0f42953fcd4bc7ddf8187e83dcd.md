# 關於

## 表示法、字元與整數

和其他簡單型別（`int`、`bool`等）一樣，`char`也有個相伴或別名的型別，在這裡就是`System.Char`。

這其實是個帶有 16 位元欄位的`struct`，而且預設不可變。

`char`有一些執行個體方法，例如 `Equals`、`ToString` 和 [`CompareTo`][compare-to]。

`char`和 [`ushort`][uint16] 的寬度相同，但一般並不會像某些語言那樣互換使用。`ushort`必須明確轉型成`char`。

順帶一提，`char`可以做算術運算，而這些運算的結果會是整數。

顯然，8 位元的`byte`和 16 位元的`char`之間並不等價。

## 用法

`char`用起來通常很簡單。

它們可以用單引號定義成常值：

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

可以透過（從 0 開始的）索引從字串取出個別的`char`：

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

疊代字串時，每一步都會回傳一個`char`：

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

如上所示，`char`可以轉型成它的`int`值。這對其他文字系統也適用（至少大多數時候是如此）：

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

比較字元時，用的是底層的 Int16：

```fsharp
'A' < 'D'
// => val it: bool = true
```

另外，`int`也可以轉型成`char`：

```fsharp
char 77
// => val it: char = 'M'
```

`System.Char`程式庫包含了 .NET 語言應有的一整套[方法][Char-methods]，例如大小寫轉換（但請留意下一節提到的注意事項）：

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

.NET 程式庫有助於從字串中取出`char`，在這裡用的是`Seq`方法：

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

把字元清單（或陣列）轉換成字串有各種做法，包括以下幾種：

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

關於`char`的一般資訊可以在這裡找到：

- [字元文件][chars-docs]：`char`的參考文件。

不過，`char`有一些粗糙的邊角，詳見下文。這些邊角大多源自兩邊的拉扯：一邊是完整的 Unicode 標準，另一邊則是歷史上文字的表示方式，以及效能和記憶體用量。

## Unicode 相關問題

處理字串時，如果有 [`System.String`][System-string]程式庫的方法可用，你應該盡量找出並使用它們，而不是把字串拆解成一個個字元。

有些文字「字元」是由一個以上的`char`組成，因為 Unicode 標準有超過 65536 個碼位。例如某些測試中出現的表情符號就有 2 個`char`，因為它們是由[代理][surrogates]字元組成。

此外，還有組合序列，例如在某些情況下，一個帶重音的字元可能由一個代表原本字元的`char`，和另一個代表重音的`char`組成。

如果你必須處理個別字元，應該試著使用 [`System.Char.IsControl`][is-control]、[`System.Char.IsDigit`][is-digit] 這類程式庫方法，而不是做像檢查某個字元是否介於 '0' 和 '9' 之間這種天真的比較。

例如，請注意 '٢' 是阿拉伯數字 2。`IsDigit`對阿拉伯版本會回傳 true，所以在驗證時，你必須清楚說明可接受的輸入範圍是什麼。

即使是`System.Char`程式庫的方法，在處理較冷門的語言時，行為也可能和你想的不一樣。

要安全地把字串拆解成顯示用的「字元」，其中一個方法是使用 [`StringInfo`][string-info] 以及 [`GetNexttextElement`][get-next-text-element] 這類方法。如果你在處理全球化或在地化，這可能是必要的。

另一個會用到 Unicode 字元純量值的情況（比如你自己在打造編碼系統），是使用 [runes][runes]。不過，如果你知道自己處理的字元範圍不包含代理字元或組合字元序列（例如拉丁 ASCII），而且輸入經過妥善驗證，那你就可以避開這個做法。

再次強調，最理想的狀況，就是你能使用`String`的程式庫方法。

如果你真的落到必須處理 Unicode 細枝末節這種吃力不討好的處境，那麼[這篇][char-encoding-net]是不錯的起點。

## 全球化

如果你所在的環境會處理多種文化，或者文化在某些部分的程式碼很重要、在其他部分卻不重要，那麼請留意 [`ToUpper`][to-upper] 和 [`ToLower`][to-lower] 接受文化參數的多載版本，以及 [`ToUpperInvariant`][to-upper-invariant] 和 [`ToLowerInvariant`][to-lower-invariant]，後者不論目前的[文化][culture-info]是什麼，都會給出一致的結果。
