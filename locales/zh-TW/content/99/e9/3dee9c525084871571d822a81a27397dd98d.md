# 說明

有位海盜正在規劃一條路線，要穿越一張標著隱密海灣的海圖。
這張海圖是一個以海灣名稱為鍵的雜湊表；每個值都是一個陣列，裝著從該海灣可以直接抵達的海灣。

## 1. 排空潮汐佇列

定義`tide-queue`，接受一個項目陣列，依序把每個項目推入一個全新的雙端佇列，再全部彈出到一個維持原始順序的陣列。這就是 FIFO 的形式：從後端推入，從前端彈出。

```factor
{ "alpha" "bravo" "charlie" } tide-queue .
! => { "alpha" "bravo" "charlie" }
```

## 2. 可到達的海灣

定義`coves-reachable`，接受一個起始海灣和一張海圖，回傳從`start`可到達的每個海灣（包括`start`本身）所組成的雜湊集合。

```factor
"Skull Bay" H{
    { "Skull Bay"   { "Hidden Cove" } }
    { "Hidden Cove" { "Reef Point"  } }
    { "Reef Point"  { } }
} coves-reachable .
! => HS{ "Skull Bay" "Hidden Cove" "Reef Point" }
```

用`<dlist>`當作 BFS 的待探索邊界，並用`HS{ }`當作已造訪集合。

## 3. 跳躍次數

定義`hop-count`，接受一個起始海灣、一個目標海灣和一張海圖，回傳兩者之間最少的跳躍次數；如果目標無法到達，就回傳`f`。

```factor
"Skull Bay" "Hidden Cove"
H{
    { "Skull Bay"   { "Hidden Cove" } }
    { "Hidden Cove" { } }
} hop-count .
! => 1
```

在雙端佇列裡，把每個海灣連同它與起點的距離一起帶著走（用 2 個元素的陣列就行）。

## 4. 黃金數量

程式骨架用`:`宣告了`gold-count`。把它改成`MEMO:`（而不是`:`），這樣每個海灣的結果只會計算一次並快取起來。海灣的黃金數量請查這道練習提供的`gold-distribution`常數。
不在分布裡的海灣，黃金數量為零。

```factor
"Smuggler's Hollow" gold-count .   ! => 200
"Davy Jones' Locker" gold-count .  ! => 0
```

## 5. 藏寶路線

定義`treasure-route`，接受一個起始海灣和一張海圖，回傳可到達的海灣裡黃金最多的那一個。使用任務 2 的`coves-reachable`和任務 4 的`gold-count`。

```factor
"Skull Bay" some-chart treasure-route .
! => "Smuggler's Hollow"   (the richest reachable cove)
```

經過記憶化的`gold-count`讓重複查詢不必重新計算，當演算法裡有好幾個部分都要查同一個海灣時，這點特別好用。
