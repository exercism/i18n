# 簡介

## 字串

### 字元

**字元編碼**是一種特定的慣例，用來把自然語言中的文字元素表示成一連串的位元組。
這裡的「文字元素」可以是任何在自然語言中具有意義的單位，例如字母、空格、標點符號、表情符號、表意文字等等。

NASM（The Netwide Assembler，本 track 使用的組譯器）支援使用 **ASCII** 來定義資料。

NASM 中的字元常數長度最多可達 8 個位元組，可以使用單引號（`'`）、雙引號（`"`）或反引號（`` ` ``）來定義：

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

特殊字元必須用反引號定義，並以 `\` 跳脫：

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

請注意，x86-64 並沒有內建把任何字元編碼當成獨立型別的支援。
在組合語言中，資料就是一連串的位元組，至於要把這些位元組解讀成字元、數字或其他任何東西，都交由程式設計師自行決定。

舉例來說，ASCII 字元 '0' 是單一個位元組，值為 48。
所以，把 48 存入一個位元組，和存入 ASCII 字元 '0' 可說是完全相同的事：

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

基於同樣的理由，操作字元的方式就是直接轉換這些位元組中的值：

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### 字串

**字串**是一連串的字元。
在組合語言中，通常會用陣列來實作。

在 NASM 中，可以用宣告任何陣列的相同方式來宣告字串：

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

字串和其他陣列的其中一項差異，在於 NASM 也支援不用逗號（`,`）分隔值來宣告字串。
也可以把有逗號和沒有逗號的值交錯排列：

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

請注意，如前所述，字元就只是位元組（在 Unicode 編碼中則是一連串的位元組）：

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

由於每個 ASCII 字元只佔一個位元組，因此以較大寬度宣告時，後續的位元組都是 `0`。
舉例來說，把 `'a'` 宣告成 qword（8 位元組）時，第一個位元組是 `'a'`（`97`），其餘七個位元組則全都是 `0`。

基於這個理由，以下幾種寫法全都等價：

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
在組合語言中，字串並不會自動以 ASCII 的 NUL 字元（值 `0`）結尾。

當要與 C 這類更高階的語言介接時，程式設計師必須自行負責在字串結尾加上正確的結束符號（如果需要的話）。
~~~~

### 字串指令

由於字串就是陣列，你可以用處理任何陣列的相同方式來操作它們，也就是明確地對記憶體解引用：

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

除此之外，還有一些指令可以在記憶體中的位元組序列裡載入、搬移和儲存值。
雖然它們被稱為_字串指令_，但可以用於記憶體中任何位元組序列，也就是任何陣列。

最重要的三個字串指令是 `lods`、`stos` 和 `movs`：

| 指令 | 作用 |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | 從 `rsi` 所指的記憶體位置載入一個值到 `rax` |
| `stos`      | 把 `rax` 中的值儲存到 `rdi` 所指的記憶體位置 |
| `movs`      | 從 `rsi` 所指的記憶體位置複製一個值，並把它儲存到 `rdi` 所指的記憶體位置 |

請注意，這些指令並_不_接受任何明確的運算元。
它們的運算元是隱含的。

一般來說，可以依循以下原則：

1. 當來源運算元是記憶體位置時，其位址應存放在 `rsi`（`s` 代表 source，即來源）。
2. 當目的運算元是記憶體位置時，其位址則應存放在 `rdi`（`d` 代表 destination，即目的）。
3. 如果其中一個運算元不是記憶體位置，那就是 `rax` 暫存器。

請注意，這些指令會根據它們實際執行的操作，自動對記憶體位址解引用。

它們全都可以用不同的尺寸運作。
運作尺寸會以附加後綴的方式來表示：

| 後綴 | 意義 | 大小    |
| :----: | ------- | :------ |
|  `b`   | 位元組    | 1 位元組  |
|  `w`   | 字組    | 2 位元組 |
|  `d`   | 雙字組   | 4 位元組 |
|  `q`   | 四字組   | 8 位元組 |

例如：

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

它們也會依照操作的尺寸來更新所用到的位址。
這個更新會依據**方向旗標（DF）**的值來進行：

- 如果 `DF` 被清除，位址會_增加_該操作的尺寸。
- 如果 `DF` 被設定，位址則會_減少_同樣的數量。

System V ABI 規定，進入函式時方向旗標必須是清除狀態。
所以，_預設行為是以位址遞增的順序來讀寫記憶體_。

可以使用 `cld` 指令來清除方向旗標，而 `std` 指令則用來設定它：

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
依照 System V ABI，呼叫者預期任何被呼叫的函式在返回之後，`DF` 都必須是清除狀態。
如果你設定了 `DF`，請務必在 `ret` 之前將它清除。
~~~~

#### Rep

除了這些之外，**rep** 指令並不會直接與記憶體互動。
它反而是作為前綴加在上述其他指令之前，_重複_執行那些指令。

加上 `rep` 前綴後，字串指令會重複執行，次數等於 `rcx` 中的值。
每重複一次，`rcx` 中的值就會減 `1`。
請注意，必須在使用該指令之前先設定好 `rcx` 的值：

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
在現代 CPU 上，要在大型區塊之間搬移資料時，`rep movs` 和 `rep stos` 通常是很快速的選擇。
不過，其他字串指令，甚至是在沒有 `rep` 的情況下運作的 `movs` 和 `stos`，通常都比單純的迴圈還慢。

關於這個主題更深入的說明，可以參閱[這本參考書的第 16.9 章「String instructions」][agner-optimization-guide]。
