# 貢獻指南

如果你想參與 Pharo 軌道的開發，應該遵循以下指示，它們能幫助你踏出第一步。

我們很希望改善這個軌道，並向開發者展示另一種思考寫程式的方式！ :tada:

請閱讀如何[參與 Exercism 軌道](https://github.com/exercism/docs/tree/master/contributing-to-language-tracks)，並且務必閱讀 [Exercism 行為準則](https://exercism.io/code-of-conduct)。

我們歡迎各種形式的 pull request。任何貢獻都不嫌小，尤其是針對現有練習提供的修正與改進。請注意，這個軌道的練習必須符合 [Exercism 全體標準](https://github.com/exercism/docs/tree/master/language-tracks/exercises)，但如果你不確定該如何做出變更，請開一個 GitHub issue，我們會一起討論。

>__注意__：Exercism 組織已決定[暫停 Exercism 更廣泛的社群貢獻](https://exercism.org/blog/freeing-our-maintainers)。由於我們的社群規模相當小，Pharo 軌道選擇退出這項政策（換句話說：任何 Pharo 軌道的貢獻者仍然可以建立 issue 並提交 PR）。

## 必備知識

預期你已經[熟悉](./docs/RESOURCES.md) Pharo 的開發，以及它對 [Iceberg Git](https://github.com/pharo-vcs/iceberg) 的使用。

## 開發環境設定

首先，你需要確認自己具備完整的 Exercism 開發環境，並安裝好以下產出物：

### __Pharo 映像檔與 IDE__

你需要一個 Pharo 開發環境（執行中的 Pharo 映像檔，即 IDE），用來建立實際的程式碼範例。

1. 使用 [PharoLauncher](https://pharo.org/download) 從 `Official distributions` 類別建立一個全新的穩定開發映像檔（截至 05/24，穩定映像檔為：Pharo 12.0 - 64bit (stable)），然後啟動它（如果你熟悉 [zerconf](https://get.pharo.org/)，也可以使用它）。
2. 啟動你的映像檔，測試一切是否正常執行。

> __注意__：如果你遇到任何 TIMEOUT 問題，請參閱[使用者安裝指示](./docs/INSTALLATION.md)。

### __設定 git 儲存庫__

1. 如果你先前還沒做過，請在 GitHub 上 fork `https://exercism/pharo-smalltalk`。
2. 若要複製你的 fork，請在執行中的 Pharo 映像檔的 Playground 中執行以下指令：
```
Metacello new
 baseline: 'Exercism';
 repository: 'github://exercism/pharo-smalltalk:main/releases/latest';
 load: 'dev'
```
這會複製 Pharo 軌道的 git 儲存庫，並將 Pharo 軌道的原始碼載入 Pharo 映像檔，也就是它的開發基準。複製而來的儲存庫，其本地資料夾會位於（取決於你的 Iceberg 偏好設定）：`<path-to-Pharo-image>/pharo-local/iceberg/<your-id/pharo-smalltalk`。
> __注意__：Pharo 映像檔的原始碼會同步並序列化到 `*.st` 檔案，這些檔案位於上述目錄的 `src` 子資料夾中。

2. 另一種做法是透過 CLI 複製你的 fork：`git clone https://github.com/<your id>/pharo-smalltalk`，將它設為 GitHub 專案，並指定 `<your id>` 為擁有者名稱、`pharo-smalltalk` 為專案名稱。
接著在執行中的 Pharo 映像檔裡，使用 Metacello 快顯功能表，在 Iceberg 中安裝 Metacello 基準 `dev`（不是預設的那個）。（例如在剛剛複製的「pharo-smalltalk」專案上按一下滑鼠右鍵，選擇 Metacello 功能表中的第二個選項，然後輸入 `dev`）

3. 將專案載入 Pharo 映像檔後，別忘了 __儲存映像檔__ 變更（功能表項目 Pharo -> Save）。

__選用儲存庫__
1. 或者你也可以 `git clone https://github.com/exercism/pharo-smalltalk`，作為暫存儲存庫，把你要產生並簽入的練習與資源放在那裡（與在 Pharo 中寫程式分開）。請注意，Configlet 工具在這個儲存庫中產生的變更，需要複製到你本地的 fork 儲存庫。建議使用類似 `~/development/exercism/pharo-staging` 的路徑，以免混淆（注意：它可以放在任何位置）。這個儲存庫並非必要；如果你確定要將哪些變更納入提交，你仍然可以直接在 fork 的儲存庫中產生 configlet 變更（該儲存庫與你的 Pharo 映像檔同步）。
2. 如果你想要從頭開發練習，也可以複製 Exercism 的[問題規格](https://github.com/exercism/problem-specifications)。同樣把它放在下方設定的 exercism 工作區的子目錄中（這個儲存庫用於產生練習的 readme.md 檔案，並且是建議測試的參考）。

### __關於所使用的儲存庫分支__

`main` 分支是主要的開發分支，所有內容都會合併到這裡。如果你要開發某個程式碼變更，請從 main 建立功能分支，並在那裡提交你的變更。完成後，在 GitHub 上提交 PR，合併到基礎儲存庫（Exercism/pharo-smalltalk）的 `main`。這個分支以前稱為 `master`，__現已棄用__。

### __設定 Exercism CLI 工具__

需要這些工具才能與 Exercism 專案互動：
1. [exercism 命令列介面](https://exercism.io/cli-walkthrough)，並將它設定到存放 Exercism 練習開發的目錄，也就是工作區（例如 `exercism configure -w ~/development/exercism`）。這可以是你的本地 fork 儲存庫路徑，或（選用）暫存儲存庫路徑。
2. Exercism 的 [configlet](https://github.com/exercism/configlet#usage) 檢查／產生工具，用來產生練習中介資料並執行驗證。若要安裝 Configlet，請遵循[在你的軌道中使用](https://github.com/exercism/configlet#use-in-your-track)段落中的指示（參見 bin/fetch-configlet）。

## 開發 Exercism 練習

Exercism 組織將練習區分為概念練習（解釋程式語言理論）與練習。以下段落目前只聚焦在練習的貢獻。

### __總覽__

完成練習的步驟：
1a. 從頭建立練習（依據問題規格）。
1b. 開發現有練習的解答。
2a. 將練習解答的序列化原始碼檔產生到目錄中，並產生練習中介資料。
2b. 調整專案基準，將新完成的練習納入專案。
3. 將變更提交到你的 fork 儲存庫，並透過提交 PR 來發佈變更。

#### TLDR：產生並匯出練習的快速指南
簡而言之：你只需要從 Pharo 產生並匯出練習，在 Playground 中執行：
```Smalltalk
"Obtain exercise from problem specification"
ExercismExerciseGenerator new generateExerciseFrom: 'path-to-problem-specifications/exercises/slug-name' asFileReference.

"Update exercise version within Pharo image  (with updated test cases) to output exercise directory (once you have solution class defined)"
ExercismGenerator new 
	exercisesDirReference: 'path-to-local-repository/exercises/practice' asFileReference;
	generateForExercise: 'slug-name'.
```
  > __注意__：更多細節請見下方步驟。

![完成練習的工作流程](/docs/images/overview-exercism-pharo-contribution.svg)

### __1. 建立新的練習__
*TLDR：所有與練習產生相關的細節與 API 說明，都可以在 `ExercismExerciseGenerator` 類別的類別註解中找到。*

__從問題儲存庫新增練習__
- 如果你想從頭開始一個全新的練習（步驟 1a），你可以使用問題規格儲存庫，並執行以下指令來為指定的練習產生測試類別：
`ExercismExerciseGenerator generateFrom: <path-to-problem-specifications/exercises>`，這會為問題規格儲存庫中的所有練習產生測試類別，放在 `ExerciseWIP` 套件中。

  > __注意__：你也可以使用 Pharo 映像檔中的功能表項目來達成相同目的（World 功能表 -> Exercism -> Generate test cases）。
- 更精確地說，你可以用以下指令為特定練習產生測試類別：`ExercismExerciseGenerator generateExerciseFrom: '<path-to-problem-specifications/exercises/slug-name>' asFileReference`。

上述指令的結果，會是在 `ExerciseWIP` 套件中新增一個 `<SlugNameTest>`（ExercismTest 的子類別）測試類別，內含產生的測試方法。

__從問題儲存庫重新產生現有練習__
如果你想重新產生現有練習（已在解答套件中定義，例如 `Exercise@TwoFer`）的測試方法，可以使用以下程式碼。請注意，其他方法不會被更動（例如 uuid、version 等）

 `ExercismExerciseGenerator new regenerateExerciseFrom: 'path-to-problem-specifications/exercises/exercise-slug' asFileReference`

__從零開始__
如果你有個有趣的想法，請參閱關於新增練習的文件。

專案中有一個使用者自訂練習的範例，請見：`DieTest`。透過覆寫 customData 方法，產生器會為你建立相關檔案。

請注意：
- 每個練習都必須獨立自主。不要參照練習目錄以外的檔案，因為使用者取得練習時不會包含那些檔案。
- 練習必須符合 [Exercism 全體標準](https://exercism.org/docs/building/tracks/practice-exercises)。
- 練習應只使用 Pharo 核心函式庫。
- 每個練習應該：
  - 儲存在名為 `Exercism@<ExerciseName>` 的最上層專案中
  - 有一個名為 `<ExerciseName>Test`（使用 CamelCase）的 TestCase，以及一個名為 `<ExerciseName>` 的範例解答
  - TestCase 應該有一個 markdown 格式的類別註解來描述該練習。這段文字也會用來產生 README.md 檔案。
- 不要在練習中提交任何設定檔或目錄（未來練習可能會重新檢視這點，如果這造成問題，請告訴我們）。
- 請務必使用 `UUIDGenerator next` 為練習產生新的 UUID，並將該值放入測試的 `uuid` 方法中。

> __注意__：很遺憾，目前的 Pharo UUID 產生器不符合 RFC 4122 第 4 版。因此，應該使用由 configlet 產生的 UUID，執行：`/bin/configlet uuid`

### __2. 開發現有練習__

雖然有許多方式可以幫忙，但目前為止最簡單也最有用的貢獻，就是為任何一個目前「開放」的練習完成解答。

  * 確保你的映像檔已跟上 exercism/pharo-smalltalk 的 main（並將任何變更推送回你的 fork）

  * 所有練習都是由前述的問題規格儲存庫自動產生的 TestCase。你可以在 ExercismWIP 套件中找到它們，它們是 ExercismTest 的子類別。請注意，如果解答已經就位，重新產生的 ExercismTest 可能已經在對應的練習套件中。ExercismWIP 套件用於尚未部署、與解答類別並存的新練習或開發中的練習。

  * 一旦你選好想開發的練習，就在 GitHub 上建立一個 Issue，標題寫「Convert Exercise <name>」。這能讓其他人知道你正在處理這個練習，也會成為你日後 pull request 的基礎。

  * 每個開發中的練習，其類別註解中已經有問題描述。你可以執行它的測試，並以 TDD 開發解答（如果你單獨執行第一個測試，會在除錯器中進行）。

  * 你可能需要 __調整測試，讓它更符合 Smalltalk 的慣例__（我們的產生器相當基本，話雖如此，有些修正或許適合以 PR 的形式回饋到上游的[問題規格](https://github.com/exercism/problem-specifications)文字）。

  * 透過覆寫 #exercise 方法，並填入難度、主題等資訊，來更新練習類別端的練習中介資料。你也應該在 Test 註解分頁中填入一些提示文字（在底部，取代 TBD 文字）

  * 將所選範例的套件更新為 `Exercise@<ExerciseName>`（也就是將它移出 WIP 套件），即步驟 1b。
  * 在 Iceberg 中建立一個新分支，名稱使用你選擇的練習名稱（你可以使用 Iceberg 工具來做這件事，並輸入上面提到的 issue 編號）。
  * 提交 pull request 之前，執行所有 Pharo 練習的測試，並確保它們 __全部通過__。

### 測試

最基本地說，Exercism 一切都在於測試，以及使用[測試套件](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md)來測試。

Pharo 的 exercism 練習會組織成子套件，每個子套件包含一個必須與 [SUunit](https://en.wikipedia.org/wiki/SUnit) 相容的 TestCase。這是最早的 xUnit 函式庫，練習不需要任何額外的第三方框架。

若要測試某個練習，請從內建的測試執行器執行它：點一下測試圓球。如果測試成功，圓球會變成綠色；如果有失敗或錯誤，則分別會變成橘色或紅色。或者，你也可以在 Playground 中手動執行測試：

```smalltalk
<ExerciseName>Test suite run. "single exercise"

AllExercismTests suite run. "all exercises"
```
> __注意：__ 如果你想定義自己的（非產生的）測試案例，可以把它放在測試類別的 `extra` protocol 中。
為了保持一致，我們在測試方法中使用這樣的測試參數順序：`self assert: actual equals: expected`。

若要在非開發映像檔中測試，你應該遵循[使用者安裝步驟](./docs/INSTALLATION.md)。如果你使用該映像檔來測試後續的開發基準，可能需要刪除以下開發目錄，以確保取得最新的程式碼：
`./pharo/pharo-local/iceberg, ./pharo/pharo-local/package-cache`

### __3. 發佈完成的練習__

現在，當你完成解答並提交到你的本地功能分支後，應該完成以下步驟：
#### 產生練習原始碼
這裡指的是步驟 2a：為解答與測試類別 __產生原始碼__ 檔案。

__為所有練習產生輸出原始碼__
- `ExercismGenerator generate` -> 這會產生所有練習的所有原始碼檔案。它會執行 configlet 的 `generate` 指令，並重新產生列出所有有效練習的 `config.json`。（或在 World 功能表中選擇：Exercism -> Regenerate meta data）

#### 為特定練習產生輸出原始碼
- 使用預設目錄（`repository-root/exercises/practice`）
```
ExercismGenerator new generateForExercise: 'slug-name'
```

當需要匯出到特定的練習目錄時：
```
ExercismGenerator new 
	exercisesDirReference: 'path-to-exercises/practice' asFileReference;
	generateForExercise: 'slug-name'
```

> __注意事項__：
  - ExercismGenerator 會自動更新主要的 config.json（若不存在則建立新的）。
  - 會使用 configlet 指令，為指定的練習同步所有文件、中介資料與檔案路徑。詳情請見：[新增練習時使用 sync](https://github.com/exercism/configlet#using-sync-when-adding-a-new-exercise-to-a-track)

#### 更新 Pharo-smalltalk 專案基準
步驟 2b：在 `BaselineOfExercism>>exercisePackageNames` 方法的清單中加入練習名稱，以更新 Pharo-smalltalk 專案基準。這能確保當專案透過 Metacello 指令載入（包含新練習）時，你的練習會被載入。

#### 提交 Pull Request
步驟 3：建立 PR 之前，你應該執行 CLI 指令來檢查 Exercism 的產出物是否正確：
`bin/configlet lint`（提交 PR 時，CI 自動化無論如何都會執行 lint 檢查）。
如果一切正常，就可以建立 PR：
- 將你的分支推送到你的 fork，然後在 `exercism/pharo-Smalltalk` 上建立 pull request

> __最後細節__：

- 請務必[允許維護者編輯](https://help.github.com/en/articles/allowing-changes-to-a-pull-request-branch-created-from-a-fork)，這樣我們才能在你的分支上與你協作。
- Pull request 應該聚焦在單一練習、單一 issue，或概念上連貫的變更。詳情請參閱 Exercism 的 [pull request 指南](https://github.com/exercism/docs/tree/main/building/github#guides)。
- 關注你的 PR，並回答後續的任何問題。
- 最後提交任何調整，維護者會合併你的 pull request，讓最終解答出現在網站上。

## 給維護者的補充資訊

### 程式碼風格

這個儲存庫中的程式碼應盡可能遵循 [Pharo with style](https://github.com/SquareBracketAssociates/Booklet-PharoWithStyle) 的慣例。你也可以參考更通用的 [Smalltalk with style](http://sdmeta.gforge.inria.fr/FreeBooks/WithStyle/SmalltalkWithStyle.pdf)。

建立練習時，你也應該善用內建的程式碼格式化工具（在編輯器中按 meta-t FO），以及程式碼評論。

### 破壞性變更

如果你打算進行重大或破壞性的變更，請先開一個 issue，讓我們在合併前討論。如果這個討論不只與 Pharo 軌道相關，也請在 [exercism/discussions](https://github.com/exercism/discussions/issues) 開一個 issue。
