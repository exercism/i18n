# 簡介

在程式裡定義自訂型別往往很實用。

建立新的基本型別雖然做得到，但很少人這麼做。
內建的基本型別並不是任意挑選的：它們與 Julia 用於 JIT 編譯的 LLVM 編譯器中的標準型別高度對應。

更有用的是定義複合型別的能力，而且每個欄位都能有自己的名字。

其他語言也有類似的東西，只是名稱不同，像是 `structs` 或 `records`。
Julia 的文件把它們稱為 `composite types`，不過（有個小小的不一致）語言的語法其實是用 `struct` 關鍵字來定義它們。

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

上面這個例子有幾點值得注意：

- `id`沒有指定型別，所以編譯器會把它解讀成`id::Any`。
  - 實務上，最好替欄位指定具體型別，藉此幫助編譯器。
- 型別名稱可以當作建構子使用，例如`Person(id, name, age)`就會產生一個型別為`Person`的實例。
- 個別欄位可以用點記法存取，就跟具名元組一樣。

`Person`型別的個體是不可變的，所以不允許更新。

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

如果需要可變性，在定義時加上`mutable`就可以了。

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

建構子預設會要求欄位按照定義時的順序出現，型別一複雜就會顯得不方便。

使用`@kwdef`巨集可以帶來 2 種新能力：

- 建構子改用關鍵字，而不是位置。
- 欄位可以有預設值，也可以在建構子中省略。

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## 複合型別階層

到目前為止，我們只建立了具體的複合型別。
如果你去檢查，會發現它們全都是`Any`的子型別。

要建立多個彼此相關的型別時，替它們定義一套階層通常更合理。
這做起來很容易喔。

首先，建立一個抽象型別：

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

接著，在型別定義裡加上`<:`運算子，表示彼此的關係。

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

依需求重複這個做法，記得具體型別不能有子型別。

如果階層更複雜，就視需要建立抽象的子型別。

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

這種階層的價值，等我們學到`Multiple Dispatch`概念、看到函式如何處理引數型別時，就會更清楚。
