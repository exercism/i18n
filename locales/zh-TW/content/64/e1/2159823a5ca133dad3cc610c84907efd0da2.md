# 簡介

`Complex numbers` 並不複雜。
它們只是需要一個不那麼嚇人的名字。

它們非常實用，尤其在工程與科學領域，因此 R 把複數列為標準的原子型別，與整數、雙精度浮點數、邏輯值、字元以及原始型別並列。

## 基礎

在 R 中，`complex` 數值是一個單一的值。
不過實際使用時，可以把它想成一對數字。
基於一些不幸的歷史因素，這兩部分被稱為「實部」和「虛部」。
同樣地，最好把重點放在它本質上的單純，而不是那些奇怪的名稱。

若要從兩個實數建立複數，只要在虛部加上後綴`i`就好。

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

若要從實數變數建立複數，上面的語法就行不通了。
寫成`r + imi`會讓解析器誤以為`imi`是（不存在的）變數名稱。

你可以把虛部乘上`1i`，或者使用[`complex()`][ref-complex]函式：

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

你也許會想，為什麼是`i`而不是`j`？

大多數工程師偏好`j`。
大多數科學家和數學家偏好代表虛數的數學符號`i`，但這個符號和電機工程中用`i`代表電流的慣例衝突。

R 選擇了`i`，Python 選擇了`j`，而 Julia 則選擇`im`來迴避這場爭議。
在 [STEM][wiki-STEM] 程式語言之間切換時要小心。

若要個別取出複數的各個部分：

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

任一部分都可以是零，數學家可能會因而說這個數「完全是實數」或「完全是虛數」。
不過在 R 中，它仍然是一個複數。

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

你或許聽過「`i`（或`j`）是 -1 的平方根」。

目前為止，這句話只意味著虛部_依定義_滿足下列等式：

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

這是個簡單的想法，卻會帶來有趣的結果。

## 算術

大多數用於浮點數與整數的運算子也能用在複數上：

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

## 函式

大多數數學函式都能接受複數輸入。

除了`Re()`和`Im()`之外，還有幾個函式與複數特別相關。

- `Conj()`只是把複數虛部的正負號反轉（_從 + 變 -，或反之_）。
  - 由於複數乘法的運作方式，這個函式比你想像的還好用。
- `abs(<complex number>)`保證會回傳一個沒有虛部的實數（也就是它的「大小」），而`Mod(<complex number>)`是同義詞。
- `Arg(<complex number>)`會回傳以弧度表示的相位角。

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
