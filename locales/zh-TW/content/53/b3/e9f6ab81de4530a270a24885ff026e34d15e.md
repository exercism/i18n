# 介紹

## 空參照

如果你曾使用過其他程式語言（C/C++、Python、Java、Ruby、Lisp 等），那麼你很可能遇過`null`或`nil`。
使用`null`或`nil`，是這些語言用來表示某個變數沒有值的方式。
然而，這也讓不小心使用到指向`null`的變數，成為一個容易（而且經常）犯下的錯誤。
可以想見，試圖呼叫一個不存在的函式，或存取一個不存在的值，可能導致各種 bug 和當機。
`null`的發明者甚至將它稱為他的[「十億美元錯誤」](https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/)。

## `Option`型別

為了避免這些問題，Rust 不使用空參照。
然而，它仍然需要一種安全的方式，來表示某個變數沒有值。
這就是`Option`派上用場的地方。
與其讓變數缺少值，Rust 的變數可以使用`Option`列舉。
這個列舉有兩個變體：`None`，等同於 Rust 的空值；以及`Some(T)`，其中 T 是任意型別的值。

它長得像這樣：

```rust
enum Option<T> {
    None,
    Some(T),
}
```

你可以把`Option`想成一道安全防線，介於你和空參照可能引發的問題之間，同時仍保留它們在概念上的用處。

## 使用`Option`

把變數設為`None`相當直接：

```rust
let nothing: Option<u32> = None;  // Variable nothing is set to None
```

不過，如果你希望`Option`型別帶有一個值，就不能直接指定這個值。
`Option`型別的變數和，比如說，`i32`型別的變數並不等同。
你需要使用`Some`：

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Some(-4); // This will work
let another_right_way = Some(-4); // Compiler infers that this is Option<i32>
```

也正因如此，下面這樣也不會成功：

```rust
let number = 47;
let option_number = Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

如果你想取得 Some 所含的值，你得先檢查它是否存在：

```rust
let mut some_words = Some("choose something to say"); // some_words set to something

match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "Here, we will choose something to say"

some_words = None; // some_words now set to None

// exactly the same match block as above
match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "I've got nothing to say"
```

除了`match`之外，Rust 還有其他工具可以用來檢查和存取`Option`裡的值，不過`match`現在應該已經讓你很熟悉了。

此外，也可以把這當成一個示範，說明 Rust 為什麼使用`Option`而不是空參照。
重點是，**你_必須_檢查**`Option`變數是`Some`（這種情況下你就可以放心取出並使用裡面含的值），還是`None`。
否則你的程式將無法編譯；編譯器會保護你免受`null`所害。
