# 說明

你又回來處理 [exercise:csharp/object-relational-mapping]() 裡介紹過的 ORM（物件關聯對應）系統了。

我們對 ORM 的使用情形分析顯示，有 95% 的交易都是在同一個呼叫方法內執行的，因此決定改為由單一的 ORM 方法來開啟、寫入並提交交易，這樣會更合適。

資料庫提供了以下幾個執行個體方法：

- `Database.BeginTransaction()` 會在資料庫上開始一筆交易。
- `Database.Write(string data)` 會在交易中將資料寫入資料庫。如果收到錯誤的資料，就會擲回例外。若在尚未呼叫`BeginTransaction()`的情況下嘗試呼叫這個方法，也會擲回例外。如果成功，資料庫的內部狀態會變成`DataWritten`。
- `Database.EndTransaction()` 會將交易提交到資料庫。如果無法關閉交易，或是先前沒有呼叫`Database.BeginTransaction()`，就可能擲回例外。
- 呼叫`Database.Dispose()`可以在交易期間擲回例外時清理資料庫。這會將資料庫的狀態變成`Closed`。

## 1. 寫入資料庫

實作`Orm.Write()`方法，開始一筆資料庫交易、寫入傳入的資料，然後提交交易。所有例外，包括`InvalidOperationException`，都應該直接傳遞給呼叫端，不要記錄例外，也不要做任何其他介入。

```csharp
Database db = new Database();
Orm orm = new Orm(db);
orm.Write("good write");
// => database has an internal state of State.Closed
orm.Write("bad write");
// => an exception is thrown but database is left with an internal state of State.Closed
orm.Write("bad commit");
// => an exception is thrown but database is left with an internal state of State.Closed
```

## 2. 寫入資料庫，並向呼叫端回傳寫入是否成功的指示

自從`Orm.Write()`推出至今已經過了幾個月，團隊內部也出現了分歧。許多開發者希望 _ORM_ 能在擲回例外時自行處理錯誤，並單純向呼叫端回傳成功與否的指示。

請實作`Orm.WriteSafely()`方法，開始一筆資料庫交易、寫入傳入的資料並提交交易（做法同上）。如果_寫入_成功，它應該回傳`true`，否則回傳`false`。不要嘗試記錄例外。

```csharp
Database db = new Database();
Orm orm = new Orm(db);
orm.WriteSafely("good write");
// => true
orm.WriteSafely("bad write");
// => false
orm.WriteSafely("bad commit");
// => false
```
