# 關於

Factor 的 I/O 建立在單一[協定][stream-protocol]之上，任何資料來源或資料接收端都能實作這個協定。內建的資料流（包括`<file-reader>`、`<file-writer>`、`<string-reader>`、`<string-writer>`、網路通訊端、位元組陣列和 tty）全都是類別，它們實作了[`io`][io]裡同樣那幾個泛型詞，並擴充[`destructors`][destructors]中的`disposable`。

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe`是低階的批次讀取：填滿由呼叫端提供的緩衝區，並回傳總共寫入了多少個元素。公開的`stream-read`和`stream-read-partial`則建立在它之上，負責處理配置。大多數使用者自訂的資料流會實作`stream-read1`（一次讀取一個元素時）或`stream-read-unsafe`（讀取可以批次處理時）的其中一個。

`stream-element-type`會回傳 2 個單例符號之一：位元組資料流（檔案讀取器、通訊端）用`+byte+`，字元資料流（字串讀取器、tty）用`+character+`。包裝用的資料流通常只是把工作委派給它底層的資料流。

## 加入混入

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

一個類別可以只加入其中一個，也可以兩個都加入。加入混入後，`input-stream`／`output-stream`上的預設方法就會分派到你的類別，這和`sets`詞彙裡的`set`一樣，都是開放混入模式。

## 可處置框架

`new-disposable ( class -- disposable )`會向目前的解構子作用域註冊一個全新的實例，這樣一來，即使資源設定的過程中發生例外，也能乾淨地回溯：

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose`是公開的詞，`dispose*`則是類別要實作的泛型詞。子類別覆寫`dispose*`時，應該先清理自己的狀態，再處置它擁有的任何資源：

```factor
M: my-stream dispose* underlying>> dispose ;
```

框架保證每個物件最多只會執行 1 次`dispose*`，重複呼叫`dispose`都是空操作。

## 作用域存取子

有 3 個組合子會設定全域的「目前的輸入／輸出資料流」，供`print`、`read1`等使用：

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

每個組合子都會在離開時處置資源，即使引述區塊拋出例外也一樣。大多數程式碼就是靠這種方式使用自訂資料流，而不是把它層層傳進每一次呼叫。
