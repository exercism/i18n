# 簡介

我們在前面的概念中看過，Julia 的型別會形成一個階層，最上層是`Any`。

像`Number`這樣的抽象型別有子型別，但本身無法被實例化。
把變數的型別設為抽象型別，會_限制_這個變數的值只能是該抽象型別的任意子型別。
例如：

```julia-repl
julia> x::Number = 3
3
julia> typeof(x)  # one subtype of Number
Int64
julia> x = 4.2
4.2
julia> typeof(x) # another subtype of Number
Float64
julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

這給了我們一種彈性，可以限制哪些輸入是有效的。

不過，假設我們想讓一個變數同時接受整數和字串的值呢？
這兩個型別並不在階層的同一分支上。

我們可以把型別設為`Any`，或讓它預設就是`Any`，但這樣就完全失去了對允許型別的掌控。

有更好的做法：使用`Union{ }`語法，在大括號裡列出 2 個以上的型別。

```julia-repl
julia> y::Union{Integer, String} = 4
4
julia> typeof(y)
Int64
julia> y = "works"
"works"
julia> typeof(y)
String
julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

另一個例子在函式簽章裡使用了同樣的型別聯集：

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}
julia> f(z::IntOrString) = z^3
f (generic function with 1 method)
julia> f(2) # integers are cubed
8
julia> f("ab") # strings are repeated 3 times
"ababab"
```

這裡我們給這個型別取了名字，這樣可以當作方便的簡寫，但並非絕對必要。
函式`g(z::Union{Integer, String}) = z^3`的行為完全相同。

關於函式簽章，我們在`Multiple Dispatch`概念裡還會談到更多。

## 含有空值的聯集

其他幾種語言也有「可能含有值、也可能不含有值」的型別，名稱像是`Option`、`Nullable`或`Maybe`。

Julia 沒有為此設計特定的語法，但型別聯集就是同一個概念的一般化。

我們在`Nothingness`概念中看過，Julia 有各種表示非值的方式，包括`nothing`和`missing`。
這兩者都可以放進型別聯集裡。

舉例來說，在定義某種鏈結串列時，如果沒有後續的節點，我們需要一個方法來結束這個串列。
`Nothing`是單一值為`nothing`的型別，而這樣的 Node 定義讓我們可以表示鏈結的結尾：

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

同樣地，`missing`可以當作缺少值的佔位符，尤其是在向量這類集合裡。
下面的例子非常刻意，但缺少值在真實世界的資料集中很常見。

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)
julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
