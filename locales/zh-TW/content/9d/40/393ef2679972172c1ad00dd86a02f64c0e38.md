# Lint 檢查

[configlet](/docs/building/configlet) 最主要的用途是 Lint 檢查：檢查某個 track 的設定檔結構是否正確，包括語法與語意兩方面。設定有誤的 track 可能無法正確同步、在網站上顯示異常，或帶給使用者不佳的體驗，因此 configlet 的檢查機制對於維護 Exercism 的完整性扮演著重要角色。

## 用法

你可以使用 `lint` 指令來檢查一個 track。

```
configlet [global-options] lint [command-options]

Global options:
  -h, --help                   Show this help message and exit
      --version                Show this tool's version information and exit
  -t, --track-dir <dir>        Specify a track directory to use instead of the current directory
  -v, --verbosity <verbosity>  The verbosity of output. Allowed values: q[uiet], n[ormal], d[etailed]
```

## 規則

以下是會檢查的 Lint 規則。

### 規則：必備檔案皆存在

Lint 工具應檢查是否所有必備檔案都存在。不屬於個別練習的必備檔案包括：

- `config.json`
- `docs/ABOUT.md`
- `docs/INSTALLATION.md`
- `docs/LEARNING.md`
- `docs/RESOURCES.md`
- `docs/SNIPPET.txt`
- `docs/TESTS.md`
- `exercises/shared/.docs/help.md`
- `exercises/shared/.docs/tests.md`

概念練習專屬的必備檔案包括：

- `exercises/concept/<slug>/.docs/hints.md`
- `exercises/concept/<slug>/.docs/instructions.md`
- `exercises/concept/<slug>/.docs/introduction.md`
- `exercises/concept/<slug>/.meta/config.json`

練習題也會有類似的清單，但我們尚未定義相關規格。

`config.json` 中列出的每個概念都應包含以下檔案：

- `concepts/<slug>/about.md`
- `concepts/<slug>/introduction.md`
- `concepts/<slug>/links.json`

## 詞彙表

1. **非空白字串**：至少包含一個非空白字元的字串。
2. **kebab-case 字串**：只包含 `[a-z0-9]` 範圍內字元的字串，可選擇以連字號分隔（例如 "two-fer"）。它必須符合以下正規表達式：`^[a-z0-9]+(-[a-z0-9]+)*$`
3. **Title Case 字串**：遵循以下 [The Chicago Manual of Style 準則](https://en.wikipedia.org/wiki/Title_case#Chicago_Manual_of_Style)的非空白字串：
   - 標題與副標題的第一個和最後一個字要大寫。
   - 「主要」詞彙（名詞、代名詞、動詞、形容詞、副詞，以及部分連接詞）要大寫。
   - 連接詞 _and_、_but_、_for_、_or_ 和 _nor_ 要小寫。
   - 冠詞 _the_、_a_ 和 _an_ 要小寫。
   - 介系詞一律小寫，不論長度，除非它們被強調、用作副詞或形容詞，或用作連接詞。
   - _to_ 和 _as_ 要小寫。
   - 拉丁物種名稱的第二部分要小寫。
4. **Sentence Case 字串**：遵循以下[準則](https://en.wikipedia.org/wiki/Letter_case#Sentence_case)的非空白字串：
   - 句子中的第一個字要大寫，專有名詞以及其他依更特定規則要求大寫的字也一樣。
5. **有效的 `files` 模式**：指定練習中所用檔案位置的非空白字串¹，該位置相對於練習的目錄。模式可以使用以下其中一個佔位符：

   - `%{kebab_slug}`：`kebab-case` 形式的練習 slug（例如 `bit-manipulation`）
   - `%{snake_slug}`：`snake_case` 形式的練習 slug（例如 `bit_manipulation`）
   - `%{camel_slug}`：`camelCase` 形式的練習 slug（例如 `bitManipulation`）
   - `%{pascal_slug}`：`PascalCase` 形式的練習 slug（例如 `BitManipulation`）

6. **唯一的 version 4 UUID 字串**：符合下列所有條件的字串：

   - 它在某個 Exercism track 的 track 層級 `config.json` 檔中只出現一次
   - 它不存在於任何其他 Exercism track 的 track 層級 `config.json` 檔中
   - 它不存在於 https://github.com/exercism/problem-specifications 的任何 `canonical-data.json` 檔中
   - 它不存在於 Exercism 的任何其他地方
   - 它符合以下正規表達式：

   ```
   ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
   ```

   例如，以下 UUID 的形式是正確的：

   ```
   d334ffe3-657e-4725-a950-290b284b6d9f
   ```

   你可以執行 `configlet uuid` 來產生合適的 UUID。

7. **有效的 analyzer `tag`**：格式為 `<category>:<thing>` 的非空白字串¹。
   `<category>` 值必須是下列其中之一：

- `paradigm`（例如 `paradigm:functional`）
- `technique`（例如 `technique:recursion`）
- `construct`（例如 `construct:bitwise-and`）
- `uses`（例如 `uses:DateTime.add_seconds`）

`<thing>` 值必須是非空白字串¹。
