# 關於

## `jq`中的錯誤

`jq`會回報兩大類錯誤：

1. **編譯期錯誤**：程式本身無效，例如語法錯誤、參照到未定義的函式或變數等。
   `jq`會完全拒絕執行這個程式。

   ```sh
   $ jq -n '1 + $foo + 2'
   jq: error: $foo is not defined at <top-level>, line 1, column 5:
       1 + $foo + 2
           ^^^^
   jq: 1 compile error
   ```

2. **執行階段錯誤**：程式本身有效，但在處理某個值時出了問題，例如用字串索引數字、用`fromjson`解析無效的 JSON 文字、以型別錯誤的引數呼叫函式等。

   ```sh
   $ echo '42' | jq '.foo'
   jq: error (at <stdin>:1): Cannot index number with "foo"
   ```

這個概念要談的是**執行階段錯誤**：如何引發、捕捉，以及停止它們。

未捕捉的執行階段錯誤會讓`jq`將訊息輸出到_標準錯誤_，並以結束狀態`5`結束。

## 引發錯誤：`error`與`error(message)`

[`error`][man-error]篩選器會引發錯誤。

- `error`會引發錯誤，錯誤的值就是**輸入**值。
- `error(message)`會引發錯誤，錯誤的值是`message`的結果。

```jq
"bad input" | try error catch .
# => "bad input"

42 | try error("invalid value: \(.)") catch .
# => "invalid value: 42"
```

~~~~exercism/note
錯誤值可以是_任何_ JSON 值，不只是字串。
引發結構化錯誤可以讓`catch`處理常式根據錯誤內容做出判斷。

```jq
try error({kind: "range", msg: "age must be non-negative"})
catch (if type == "object" then "\(.kind) error: \(.msg)" else "unexpected: \(.)" end)
# => "range error: age must be non-negative"
```
~~~~

如果非字串的錯誤值沒有被捕捉，`jq`會將它印成 JSON，並標上`(not a string)`。

```sh
$ jq -n 'error({code: 42, msg: "boom"})'
jq: error (at <unknown>) (not a string): {"code":42,"msg":"boom"}
```

## 捕捉錯誤：`try`與`catch`

可以使用[`try EXP catch HANDLER`][man-try-catch]來捕捉錯誤。
第一個運算式會先執行；如果它引發錯誤，就會執行`HANDLER`運算式，並**以錯誤值作為它的輸入**。
處理常式的輸出會直接作為輸出，就好像它是被嘗試運算式的輸出。

```jq
true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]

true | try error("some exception") catch .
# => "some exception"
```

較短的形式`try EXP`等同於`try EXP catch empty`：錯誤會被捨棄，也不會產生任何輸出。

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

~~~~exercism/note
在`try`內，錯誤會**中止串流的其餘部分**。
已經產生的值會保留，但錯誤之後的內容都不會再被求值。

```jq
jq -n 'try (1, error("x"), 3) catch "caught: \(.)"'
# outputs:
# 1
# "caught: x"
# (3 is never produced)
```
~~~~

處理常式可以引發新的錯誤，或用單純的`error`重新引發原本的錯誤；由於錯誤值就是處理常式的輸入，這麼做會將它原樣傳遞下去。

```jq
try repeat(f) catch
  if . == "break" then empty else error end
```

## 抑制錯誤：`?`運算子

[`?`運算子][man-question-mark]寫成`EXP?`時，是`try EXP`的簡寫。
它會把失敗的運算式變成不產生任何輸出的運算式。

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]

true | [.a?]
# => []
```

它經常附在索引運算子後面：

- `.foo?`是`.["foo"]?`
- `.[]?`只會在輸入是陣列或物件時進行疊代，否則不會產生任何輸出

~~~~exercism/caution
`?`會抑制**所有**錯誤，包括你沒有預料到的錯誤。
當`user`不是物件時，`user.name?`會默默不產生任何東西，這可能會掩蓋程式中的資料問題或錯字。
當你需要知道某件事_確實_失敗了，或需要明確驗證輸入時，請優先使用`try ... catch`。
~~~~

## 替代運算子`//`

開發者有時候會以為，當`a`失敗時，`a // b`會產生`b`。
在舊版`jq`中的確如此，但從`jq` 1.6 起就不是了。
`//`運算子不會抑制錯誤。
它只會在`a`沒有產生值、產生`false`或`null`時，才以`b`替代；`a`中的錯誤仍然會傳遞出去。

```sh
$ jq -n '(error("x")) // 42'
jq: error (at <unknown>): x
```

如果你想為錯誤準備後備方案，請使用`try a catch b`。

## 解構替代運算子`?//`

[`?//`運算子][man-question-mark-slash-slash]結合了解構與錯誤處理。
它會依序嘗試每個綁定模式，直到其中一個成功；失敗的替代模式所綁定的變數會設為`null`。

```jq
# input:
#   [
#     {"a": 1, "b": 2, "c": {"d": 3, "e": 4}},
#     {"a": 5, "b": 6, "c": [{"d": 7, "e": 8}]}
#   ]

.[] as {$a, $b, c: {$d, $e}} ?// {$a, $b, c: [{$d, $e}]}
| {$a, $b, $d, $e}

# outputs:
# {"a": 1, "b": 2, "d": 3, "e": 4}    # first element: c is an object, first pattern matched
# {"a": 5, "b": 6, "d": 7, "e": 8}    # second element: c is an array, second pattern matched
```

這裡的第一個模式期待`c`是帶有鍵`d`和`e`的_物件_，而第二個模式則期待`c`是包含這種物件的_陣列_。
第一個輸入元素會用第一個模式綁定；第二個元素不符合該模式，因此改為嘗試第二個模式。

這讓單一程式可以解構可能有多種形狀的輸入，而不必寫出明確的`if type == ...`判斷鏈。

## 停止程式：`halt`與`halt_error`

有時候，面對錯誤最恰當的做法就是完全停止處理。

- [`halt`][man-halt]會立即停止`jq`程式，不再產生任何輸出；結束狀態為`0`。
- [`halt_error`][man-halt-error]會停止程式，將它的**輸入**以原始文字輸出到_標準錯誤_（沒有額外裝飾，甚至沒有換行），並以指定的結束狀態結束，預設為`5`。

```sh
$ echo '"Error: something went wrong"' | jq 'halt_error(1)'
Error: something went wrong    # printed on stderr, exit status 1
```

請注意，這些篩選器會立即停止程式，即使還有更多輸入尚未讀取。

### 結束狀態

供參考，`jq`使用這些結束狀態：

| 狀態 | 意義                                          |
| :----: | ------------------------------------------------ |
| `0`    | 成功                                          |
| `2`    | 用法錯誤（命令列選項有誤）           |
| `3`    | 編譯錯誤                                    |
| `5`    | 執行階段錯誤（或沒有引數的`halt_error`） |

使用`--exit-status` / `-e`選項時，狀態會改為反映最後一個輸出值：`true`或數字為`0`，`false`或`null`為`1`，沒有輸出則為`4`。

## 除錯輔助工具

追查錯誤來源時，這些篩選器很有幫助：

- [`debug`][man-debug]會將輸入原樣傳遞，但會將`["DEBUG:", <input>]`輸出到標準錯誤。
  `debug(msgs)`也會將`msgs`輸出為除錯訊息。
- [`stderr`][man-stderr]會將輸入以原始且精簡的形式輸出到標準錯誤。
- [`input_line_number`][man-input-line-number]會輸出目前正在篩選的輸入行號；當檔案包含許多 JSON 文字，而其中一個有問題時，這非常有用。
- [`$__loc__`][man-loc]會輸出一個物件，帶有`file`和`line`鍵，描述它在程式中的出現位置，可以嵌入錯誤訊息中。

```jq
def checked_div($d):
  if $d == 0
  then error("\($__loc__): division by zero")
  else . / $d end;

try (10 | checked_div(0)) catch .
# => "{\"file\":\"<top-level>\",\"line\":3}: division by zero"
```
