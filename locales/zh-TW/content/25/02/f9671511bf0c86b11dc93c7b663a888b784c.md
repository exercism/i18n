# 簡介

在許多物件導向語言中，常見的做法是透過[繼承子類別][wiki-subclass]來擴充父類別，從父類別繼承方法，同時加入新的方法。
如此一來就形成了物件階層。

Julia _沒有類別_，因此延伸來說，它_也沒有子類別_。
那我們要如何繼承並擴充既有的行為呢？

在先前的概念中，我們看過如何建立型別階層，也學到 Julia 如何用[多重派發][concept-multiple-dispatch]根據引數型別來選擇方法。

Julia 也有幾種非正式介面，讓你的自訂型別能掛接到標準型別既有的行為上。

用迭代器介面來說明最清楚。

## 迭代器

在課程大綱的前面部分，我們看過幾種 Julia 逐一處理集合中各個元素的方式。

- [迴圈][concept-loops]，例如 `for item in items...`
- [廣播][concept-vector-operations]：`[1, 2, 3] .- 0.5`
- [高階函式][concept-hof]：`map(√, [1, 4, 9])`
- [推導式][concept-comprehensions]：`[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [生成器][concept-comprehensions]：`(x^2 for x in 1:1e6)`，採惰性求值。

顯然，Julia 知道如何逐一走訪標準集合的每個項目：上面例子中的向量與範圍，還有集合、字典等。

那麼，我們要如何把這個能力加到自己寫的集合上，特別是那種能像生成器一樣惰性迭代的集合？

### 最低需求

要建立一個可迭代的序列，我們至少需要兩樣東西：

1. 取得_第一個_項目的方法。
2. 從目前狀態取得_下一個_項目的方法。

Julia 用 `Base.iterate()` 的方法來完成這些事，步驟如下：

1. 首先會自動呼叫 `Base.iterate(iter)`。
    - 如果沒有東西可以迭代，回傳 `nothing`。
    - 否則，回傳第一個項目與第一個狀態組成的 `Tuple`：`(firstitem, firststate)`。
2. 如果前一次迭代有回傳項目，就會自動呼叫 `Base.iterate(iter, state)`，並把 `firststate` 當作它的 `state` 引數。
    - 如果迭代結束，回傳 `nothing`。
    - 否則，回傳下一個項目與下一個狀態組成的 `Tuple`：`(nextitem, nextstate)`。
3. 重複步驟 2，直到迭代結束。

這些步驟都在「底層」完成，也就是說，方法呼叫與狀態都由迭代協定在內部管理（狀態本身保持不透明），只有項目會暴露給迴圈這類高階結構。
換句話說，我們永遠只看得到 `item`，其他一切都在黑箱裡。

[多重派發][concept-multiple-dispatch]在這裡扮演核心角色。
`iter` 的型別決定要呼叫哪些方法，引數的數量則決定要回傳第一個還是下一個項目。

標準型別的方法都已經定義好了：`Vector`、`Range`、`Set` 等（[目前][ref-iterations-collections]共有 14 種型別）。

想讓自訂的 `MyType` 擁有相同的行為，我們得先定義：
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

這些在抽象層面聽起來可能很令人困惑，但實際上可以很簡單。
舉例來說，想像我們想要一個型別，能產生某個整數 `n` 的次方，最多到指定的次數。

首先，定義一個自訂型別：

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

現在我們可以為這個型別定義 `iterate` 方法，但第一個項目和第一個狀態是什麼？

要取得第一個項目，有些迭代器需要複雜的設定，但在這個簡化的例子裡，我們可以注意到回傳的第一個項目就是底數本身，所以只要檢查 `count` 的值是否大於或等於 1 就行了。

接著來看第一個狀態，它帶著下一次迭代要用的資訊。
你需要自己決定要做到這件事得追蹤哪些資訊，而它可以是任何型別。

在這個例子裡，我們可以只追蹤 `n` 要乘到的「索引」，也可以改用效能更好的做法：使用 `n` 最近的次方（也就是回傳的項目）以及序列中的下一個「索引」。
這兩個數字可以包成一個 `Tuple`，並當作 `state` 回傳。

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

在這個例子中，第一個項目（`p.n`）會回傳給迴圈，而第一個狀態 `(p.n, 2)` 則會傳給 `iterate(P::Powers, state)` 方法。
在那裡，我們可以處理狀態來產生下一個項目：把目前的項目乘上底數，讓它的次方增加 `1`。

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

如果索引值還在 `count` 之內，就回傳一個 `Tuple`，內含 `next` 項目與遞增後的狀態 `Tuple`。
當 `index` 值超過 `count` 時，則改為回傳 `nothing`，表示迭代已經結束。

也許你已經注意到，`iterate(p::Powers)` 與 `iterate(p::Powers, state)` 這兩個方法的函式主體相當類似。
事實上，只要腦筋動得快，這種相似性讓我們能精簡實作：只保留接收兩個引數的版本，並為狀態加上預設引數：`Base.iterate(p::Powers, state=(1, 1))`
這樣一來，就不需要另外那個只收單一引數的 `iterate(p::Powers)`。
實際上只要情況允許，大家通常都會這麼做。

到目前為止，我們已經具備一些實用的功能了：以 3 的前 4 個次方為例，我們可以走訪結果、檢查某個數字是否在結果中，也可以套用 `sum()` 這類聚合函式。

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 其他方法

儘管有這樣好的開始，還不是所有功能都能運作。

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

果然，`length(Powers(3, 4))` 會給出完全相同的錯誤訊息。

這很容易修正，因為長度本來就是型別建構子的一部分：在這個例子裡是 4。
我們只要為這個型別定義 `Base.length()`，之後就能對這個序列使用推導式與 `collect()`。

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

為了效率，最好也定義 `Base.eltype()`：結果的元素型別。
這樣一來，`collect()` 這類函式就能預先為輸出的 `Vector{Int}` 配置空間，不必反覆對 `Vector{Any}` 執行 `push!()`。

注意這個語法，你以前可能沒看過：這個方法定義在_型別_上，而不是型別的_實例_上。

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

迭代器_不一定要_有有限長度。
「無限」序列的用途比較受限，但只要能用某種方式 `break` 跳出迴圈，走訪它們可能還是很有用。
例如，我們可以定義一個 `Powers` 的變體，產生小於某個上限的值（或許是 `typemax(Int)`，以免整數溢位）。

## 總結

介面很難解釋清楚，因為 Julia 的做法和大多數其他語言差太多了。
特別是，實作裡可能從頭到尾都不會提到介面的名字，這和[繼承子類別][wiki-subclass]或[混入][wiki-mixins]非常不同。

不過，實際用起來卻出乎意料地簡單：

1. 定義一個合適的型別。
2. 找出需要哪些方法。
3. 為你的自訂型別實作這些方法；通常只需要幾個方法，而且相當簡短。
4. 讓[多重派發][concept-multiple-dispatch]自動處理剩下的一切。
