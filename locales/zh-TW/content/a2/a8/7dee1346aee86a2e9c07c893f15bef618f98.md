# 關於

## const

[`const`][constants]修飾詞可以（而且通常應該）套用在任何在編譯時期就能得知其值、且在程式生命週期內都不會改變的欄位上。

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

編譯器會引導你了解哪些運算式可以在編譯時期求值。簡單的算術運算和字串串接都沒問題。這排除了任何需要使用堆積或堆疊的求值，因此所有方法呼叫以及對非基本型別的參考都不可用。

網路上有些討論在談`const`相較於變數的效能優勢。若拿來和執行個體的非`const`欄位相比，記憶體用量可能會有明顯的節省，但和靜態變數相比，這點節省顯然微不足道。任何對 CPU 效能的考量，你的同事大概都會視為[過早最佳化][premature-optimization]。

使用`const`更有說服力的理由，在於它能提升維護者推斷程式碼的能力。只要瞥見某個欄位標記為`const`或`readonly`，或某個屬性沒有 setter，維護者就能在分析時大致將它排除在外。它不太可能是 bug 的根源，也不太可能在重構時造成麻煩。這則[Stack Overflow 留言][so-consts]談的就是這件事。

`const`修飾詞也可以套用在方法內的值上：

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

用這種方式以`const`標示某個值，如果它在方法中會用到多次，或你想突顯它的意義，就會很有用。相較於直接內嵌常值，這麼做並沒有效能上的好處。

## readonly

[`readonly`][readonly-fields]修飾詞可以（而且通常應該）套用在任何無法設為`const`的欄位上：這些欄位的值在程式的生命週期內不會改變，而且是由內嵌初始設定式，或在具現化期間（由建構函式，或建構函式所呼叫的方法）設定。

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

使用`readonly`修飾詞的理由和`const`相同，因此也值得鼓勵。用這種方式約束欄位，能幫助維護者推斷程式碼。

請注意，為欄位加上`readonly`修飾詞，只能防止欄位本身的值被改變。若是彙總型別，它並不會保護該型別的欄位或屬性。特別是，它不會保護陣列的內容。

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

若要確保參考型別的所有成員都受到保護，可以把欄位設為`readonly`，並定義不含`set`存取子的自動屬性。

你應該研究基底類別庫中的[唯讀集合][readonly-collections]。

就陣列而言，最接近唯讀版本的做法，是使用 [`Array.AsReadOnly<T>()`][as-read-only] 方法。
