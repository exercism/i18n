# Shell 基礎入門

## Shell 是什麼

_Shell_ 是一種程式，讓你可以輸入指令與作業系統互動。
Shell 也可以是圖形化的；你用滑鼠或觸控板操作的桌面環境就是一種 shell。
我們這裡的重點會放在命令列介面，也就是你輸入指令、結果（通常）會印在終端機裡的介面。

命令列的 shell 有很多種。
Windows 提供 **cmd** 和 **powershell**。
Mac 和 Linux 提供的是「Unix shell」，而且種類很多。
Mac 的預設 shell 是 **zsh**。
**csh** 是較早期的 shell，語法類似 C。
**bash** 是最受歡迎的 shell 之一，在 Linux 上尤其如此。

最早出現的 shell 之一，是 Bourne shell，也就是 **sh**。
後來，這個 shell 被[標準化][posix]，成為每個類 Unix 系統都必須提供的 shell。
許多 shell 都以 Bourne shell 為基礎，通常還額外提供了互動或程式設計方面的功能。

**Bash** 是以 Bourne shell 為基礎，這也是它被稱為「**B**ourne-**a**gain **sh**ell」的原因。
它是許多 Linux 系統的預設 shell。
Bash 提供了許多功能，讓它成為用起來很順手的互動式 shell，包括：

* 可完全自訂的提示字元
* 能從歷史紀錄中叫回並修改指令
* 能操作執行中的行程
* 可減少打字份量的別名
* 以及其他更多功能

這個學習軌道要談的不是如何把 bash 當成互動式 shell 來使用，而是要學習用 bash 寫程式。
重點會放在_只_用 bash 來解決問題，不過要呼叫外部工具也沒有限制。

## Bash 基礎：指令與引數

Bash 會從它的輸入讀取指令（輸入通常是終端機或檔案）。
它讀進來的每一行都會被當成一條_指令_，也就是一個要被執行的指示。
（有少數進階情況，例如跨越多行的指令，之後會再討論。）

Bash 會把每一行切成以空白字元（空格與 Tab）分隔的**詞**。
這一行的第一個詞就是要執行的_指令_名稱。
其餘的詞都會成為該指令的_引數_（選項、檔案名稱等）。

~~~~exercism/note
在下面的範例中，我們會示範一些你可以實際執行的互動式指令。

* `#` 字元代表_註解_的開始。
  註解後面的所有詞都會被 shell 忽略；註解只是寫給人看的。
* `$` 字元代表 shell 提示字元。 
  如果你要複製指令，請不要把提示字元一起複製。
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm` 是一個應用程式，會刪除交給它的檔案。
`*` 是一個 [glob][glob] 字元，也就是一種可符合目前目錄中所有檔案的「萬用字元」模式。
之後我們會再詳細談 glob。

你有沒有注意到 `a` 和 `b` 之間有好幾個空格，而 `b` 和 `c` 之間只有一個？
引數之間有多少空白都不重要！
例如：

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo` 是一個會把引數印到標準輸出的指令（在我們的例子裡就是終端機）。
Bash 會把這個指令切成五個詞，並以四個引數呼叫 `echo` 指令。
第二個例子裡多出來的空格不會造成任何差別。
`echo` 並不知道詞與詞之間原本有多少空格。

如果我們想保留多餘的空白，就得把整句話當成單一一個引數傳進去。
做法是使用[引號][Quotes]：

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

引號會把它們括住的所有內容集合成_單一引數_。
這個引數是 `This    is    a    test.`，包含那幾個特定的空格字元。
注意，引號本身不算引數的一部分，bash 會先把引號拿掉，再把這單一引數交給 `echo`。

引數與指令名稱之間、以及引數彼此之間，都是用空白分隔。
這一點很重要，要記住。
例如，下面這樣是錯的：

```bash
$ [-f file]
bash: [-f: command not found
```

這段的本意是測試名為 `file` 的檔案是否存在。
你可能會很合理地以為 `[` 和 `]` 前後的空白無關緊要，但 `[` 其實是一個指令，而且它要求最後一個引數必須是 `]`。
（我們之後會更詳細地介紹 `[` 指令。） 
因此，我們必須把 `[` 與 `-f` 分開、把 `]` 與 `file` 分開。
否則 bash 會以為我們想執行一個叫 `[-f` 的指令，並帶單一引數 `file]`。
正確的指令會用空白把每個引數分開：

```bash
$ [ -f file ]
```

（我們看過很多人被這個行為搞混；他們以為 `[...]`「只是語法」，可以省略空格；但 `[` 是一個指令，空白是必要的。）

如果檔案名稱含有空白或其他特殊字元，也應該用引號括起來：

```bash
$ [ -f "my file" ]
```

## 指令的種類

Bash 看得懂好幾種不同的指令：別名、函式、內建指令、關鍵字，以及執行檔。
這些全都是_指令_，行為方式也非常相似。

別名預設只在互動式 shell 中啟用，在 shell 腳本裡則不會。這裡我們不談別名。

### 函式

函式裡面包含 shell 指令，運作起來很像一個小型腳本；它甚至可以接受引數、建立區域變數。
呼叫函式時，函式內的指令就會被執行。
函式之後會有更深入的介紹。

### 內建指令

Bash 本身內建了一些基本指令，例如：`cd`（切換目錄）、`echo`（輸出文字）等等。
可以把它們想成已經幫你準備好的函式。

### 關鍵字

關鍵字和內建指令很像，主要差別在於關鍵字其實是 bash 的語法，而且可能會用特殊規則來解析。
例如，`[` 是 bash 的內建指令，而 `[[` 是 bash 的關鍵字；兩者都用來測試各種條件。
但 `[[` 這個關鍵字多了一些功能。
例如，它提供了 `=~` 運算子，可以進行正規表達式的比對。

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

字串比較運算子 `<` 和 `>` 則是另一個例子，說明關鍵字會用不同的方式解析程式碼。
在 `[[...]]` 裡面，這兩個運算子不需要任何特別處理。

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

但在 `[...]` 裡面，你必須把它們加上引號或跳脫，以免 shell 把它們當成重導向運算子來解析。

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### 執行檔

bash 可以執行的最後一種指令是_執行檔_。
這些是你電腦檔案系統上可以執行的執行檔（程式）。
（執行檔有時也稱為_外部指令_或_應用程式_。）
執行檔通常只要輸入名稱就能呼叫，一般不需要完整的檔案路徑。
之所以可以這樣，是因為 bash 使用了一個預先定義好的變數來幫忙找出常用執行檔的位置。
這個變數叫做 `PATH`。
它是一組以冒號分隔的目錄名稱（例如`/usr/bin:/bin`）。
當你指定一個指令（例如 `myprogram` 或 `ls`）卻沒有給檔案路徑（而且它不是別名、函式、內建指令或關鍵字）時，bash 會逐一搜尋 `PATH` 裡的目錄。
搜尋會從左到右依序進行，看看這些目錄裡有沒有名稱相符的執行檔。

如果執行檔不在已知路徑中，就必須指定它的檔案路徑。
對於目前目錄中的 `myprogram` 執行檔，請用 `./myprogram`；如果它在 `/opt/somedirectory` 目錄裡，就用 `/opt/somedirectory/myprogram`。

提示：可以用 `type` 指令來取得指令的詳細資訊：

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## 腳本

_腳本_就是存放於檔案中的一連串指令。
Bash 會讀取這個檔案，並依序處理這些指令。
只有在目前這條指令結束後，才會繼續處理下一條。
例外情況是某條指令被指定要以非同步方式（在背景）執行。
這個情況現在還不用太擔心，之後我們會學到它是怎麼運作的。

這份指南裡的任何命令列範例，也都可以用在腳本裡。

建立腳本很簡單。
先建立一個新檔案，並在第一行寫上：

```bash
#!/bin/bash
```

這一行叫做_翻譯員指示_（也稱為 _hashbang_ 或 **_shebang_**）。
它指定當這個檔案被當成指令中的執行檔時，要用 `/bin/bash` 作為翻譯員。
當作業系統的核心執行_非二進位檔案_時，會讀取檔案的第一行。
如果這一行以 `#!` 開頭，核心就會根據這一行決定要把檔案轉交給哪個翻譯員。
（還有其他可行的做法，請見下文。）
`#!` 必須位在檔案最開頭，前面不能有空格或空行。
我們腳本裡的指令會寫在這一行下面的各行。

提示：除了 `#!/bin/bash` ，你也可以用

```bash
#!/usr/bin/env bash
```

`env` 會依照它的第一個引數（在這裡是「bash」）到 `$PATH` 中尋找同名的執行檔。
如果想更詳細了解這個做法，以及它和單純的 `#!/bin/bash` 有何不同，請參考 [StackOverflow 上的這個問題][env bash]。

網路上有些腳本或範例會用 `/bin/sh` 當作翻譯員，請不要被它們騙了。
**`sh` 不是 `bash`！**
Bash 本身是「相容於 sh」的 shell，也就是說它能執行大多數 `sh` 腳本，語法也有很多相同之處。
但反過來並不成立；bash 的某些功能在 `sh` 裡會壞掉或出現非預期的行為。
事實上，`sh` 並不是單一一種 shell。
有很多 shell 實作都支援 POSIX-sh 語法。
依你的作業系統而定，當你執行 `sh` 時，實際上可能是在執行 bash、ash、dash 或其他 shell。

腳本檔案建立好之後，可以這樣執行：

```bash
$ bash myscript
```

在這個例子裡，我們執行 `bash` 這個_指令_，並要它讀取我們當成_引數_傳入的腳本。
這樣做時，`#!` 這一行就只是_註解_而已。

另一種做法是給腳本可執行的權限。
這樣一來，我們就能像執行其他執行檔一樣執行這個腳本，不必手動呼叫 bash：

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

當我們用這種方式執行指令時，作業系統（OS）會用 `#!` 這一行來決定要用哪個翻譯員來執行你的腳本。
