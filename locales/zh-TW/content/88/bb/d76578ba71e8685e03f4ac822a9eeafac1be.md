# 說明

在最近一次安全審查之後，你被要求清理組織中封存的日誌檔案。

## 1. 找出混亂的日誌行

你需要大致了解封存檔中有多少日誌行不符合目前的標準。
你認為只要一個簡單的測試，就能判斷一行日誌是否有效。
一行日誌要被視為有效，開頭必須是下列其中一個字串：

- [DEBUG]
- [INFO]
- [WARNING]
- [ERROR]

請實作`valid_line?/1`函式，在日誌行有效時回傳`true`。

```elixir
LogParser.valid_line?("[ERROR] Network Failure")
# => true

LogParser.valid_line?("Network Failure")
# => false
```

## 2. 拆分日誌行

開始進行日誌解析專案後不久，你發現某個應用程式的日誌不像其他應用程式那樣被拆分成多行。在這個專案裡，本該分成多行的內容卻全擠在同一行，並用`<--->`或`<*~*~>`這類花俏的箭頭連接起來。

事實上，任何第一個字元是`<`、最後一個字元是`>`，且中間由`~`、`*`、`=`和`-`這些字元任意組合而成的字串，都可以在這份專案的日誌中當作分隔符。

請實作`split_line/1`函式，它接收一行，並回傳一個字串陣列。

```elixir
LogParser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
# => ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. 移除日誌中的殘留內容

你發現日誌經過某些上游處理後，文字 "end-of-line" 會連同緊接在後的數字（中間沒有空格）散落在整份日誌中。

請實作`remove_artifacts/1`函式，接收一個字串，移除所有出現的 end-of-line 文字（不分大小寫），並回傳乾淨的日誌行。

不含 end-of-line 文字的行，應原樣回傳。

只要移除 end of line 字串就好，不需要調整空白。

```elixir
LogParser.remove_artifacts("[WARNING] end-of-line23033 Network Failure end-of-line27")
# => "[WARNING]  Network Failure "
```

## 4. 為日誌行標上使用者名稱

你注意到有些日誌行包含提到使用者的句子。
這些句子一律包含字串`"User"`，後面接著一個或多個空白字元，然後是使用者名稱。
你決定為這類的行加上標記。

請實作`tag_with_user_name/1`函式來處理日誌行：

- 不包含字串`"User"`的行維持不變。
- 對於包含字串`"User"`的行，在開頭加上`[USER]`，後面接著使用者名稱。

```elixir
LogParser.tag_with_user_name("[INFO] User Alice created a new project")
# => "[USER] Alice [INFO] User Alice created a new project"
```

你可以假設：

- 每次出現字串`"User"`時，後面都會接著一個或多個空白字元以及使用者名稱。
- 每一行最多只會出現一次字串`"User"`。
- 使用者名稱是不含空白的非空字串。
