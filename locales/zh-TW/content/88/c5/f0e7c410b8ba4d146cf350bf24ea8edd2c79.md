# 簡介

## 無分支的程式碼

條件式這個概念會介紹 `jcc`，也就是根據條件分支的指令家族。
`jcc` 只有在它的條件成立時，才會把執行流程轉移到程式中的另一個位置。

不過，現代的 CPU 速度很快，而且能平行執行許多指令。
如果 CPU 為了等待執行時期的條件檢查而停擺，所有工作都跟著停頓，代價實在太高了。

這就是為什麼在內部，CPU 並不會等待。
它會用**分支預測器**猜測條件的結果，然後開始 *推測性地* 執行預測出來的路徑。

如果猜對了，執行起來就像根本沒有分支一樣。
但如果猜錯了，CPU 就必須 *丟棄在預測路徑上完成的工作*，改從正確的路徑重新開始。

這叫做**分支預測錯誤**，代價很高，會造成延遲。

當某個分支難以預測時，這些預測錯誤就會不斷累積。
在這種情況下，有時比較好的做法是完全避開分支，讓同一組指令不論條件為何都照樣執行。
這種不需要 `jcc` 就能在多個值之間做選擇的程式碼，就稱為**無分支**。

有幾種方式可以調整程式碼的結構，讓它少分支一點，或是讓它真正擁有的分支更容易預測。
特別是 x86-64 提供了兩個指令家族，經常被用來撰寫無分支的程式碼。

### 條件搬移

`cmovcc` 這個指令家族，只有在特定條件成立時，才會把來源運算元複製到目的運算元。
否則，目的運算元保持不變。

`cc` 後綴的命名方式和 `jcc` 相同，意義也一樣：

| 指令 | 搬移條件 |
|-------------|--------------------------------------|
| `cmove`     | 執行 `cmp A, B` 後，A == B              |
| `cmovne`    | 執行 `cmp A, B` 後，A != B              |
| `cmovl`     | 執行 `cmp A, B` 後，A < B（有號）        |
| `cmovb`     | 執行 `cmp A, B` 後，A < B（無號）        |
| `cmovg`     | 執行 `cmp A, B` 後，A > B（有號）        |
| `cmova`     | 執行 `cmp A, B` 後，A > B（無號）        |

規則和 `jcc` 類似：

1. `l` 和 `g` 用於有號比較，`b` 和 `a` 則用於無號比較。
2. 在後綴加上 `e` 就包含相等的情況。
3. 在後綴加上 `n` 則會把條件取反。
4. 也有一些變體是根據某個旗標是否被設定來判斷。
   例如 `cmovz` 和 `cmovc`。

來看看把 `rdi` 裡的有號整數取絕對值，再從 `rax` 回傳的例子。
用 `jcc` 撰寫時，這個函式會從兩條路徑中選一條：

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

改用 `cmovcc` 撰寫時，兩個候選值都會無條件算出來，再由條件搬移挑選其中一個：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

無分支的版本永遠執行同一組指令，沒有 `jcc` 讓預測器去猜。

`cmovcc` 的目的運算元必須是暫存器。
來源可以是暫存器或記憶體位置，但不能是立即值。

~~~~exercism/note
在以上的程式碼中，`neg` 指令會根據結果設定好幾個旗標，其中包括符號旗標（SF）。
這表示 `cmp rdi, 0` 可以完全省略：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

當 `rdi` 是正數時，`neg` 會產生負的結果，此時 SF == 1，所以 `cmovs` 會把 `rdi` 還原回來。
當 `rdi` 是零或負數時，`neg` 會產生非負的結果，此時 SF == 0，所以 `rax` 會保留取負之後的值（也就是正確的絕對值）。

雖然 `cmp` 是組合語言中比較值的主要方式，但許多指令也會根據自己的結果設定旗標。
某個指令會影響哪些旗標，通常會完整列在它的[參考資料][reference]裡。
就 `neg` 而言，就是 SF、ZF、CF、OF 和 PF。

[reference]: https://www.felixcloutier.com/x86/
~~~~

### 條件設定

`setcc` 這個指令家族，會在特定條件成立時把目的運算元設為 `1`，否則設為 `0`。
目的運算元一律是 *8 位元的運算元*。

`cc` 後綴的命名方式和 `jcc`、`cmovcc` 相同。
例如，當 `ZF == 1` 時，`setz` 會把目的運算元設為 `1`，否則設為 `0`。

由於目的運算元是 8 位元，需要更寬的值時，常見做法是在 `setcc` 之後接著使用 `movzx`：

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

這是把比較結果轉成整數 `0` 或 `1` 的常見慣用寫法。
