# 簡介

## SIMD：整數

先前的主題介紹了 packed 浮點數值：多個數字存放在同一個 `xmm` 暫存器中，以 lane 為單位平行運算。
同樣的 `xmm` 暫存器也可以用來存放 packed 的_整數_。

### 語法

SIMD 浮點數模型的大部分內容，都可以原封不動地套用到 packed 整數上：

- 一個 128 位元的暫存器會切分成多個 lane
- 指令會平行作用於相同位置的 lane
- 記憶體運算元遵循相同的 16 位元組對齊規則

不過，語法上有些微差異：

1. 一個_前綴_ `p`，用來表示該指令處理的是 _packed_ 資料。
2. 執行的運算，名稱與其非 SIMD（也稱為 _scalar_）的對應版本相同（例如 `add`、`mul` 等）。
3. 一個後綴，用來表示每個 lane 的大小。

packed 整數有四種 lane 大小，每種都有自己的後綴：

| lane 寬度 | 位元組 | 128 位元中的 lane 數 | 後綴 |
|-----------|--------|----------------------|------|
| byte      | 1      | 16                   | b    |
| word      | 2      | 8                    | w    |
| dword     | 4      | 4                    | d    |
| qword     | 8      | 2                    | q    |

例如：

| 指令    | 意義                                 |
|---------|--------------------------------------|
| `paddb` | packed `add`，8 位元 lane（16 個 lane） |
| `paddw` | packed `add`，16 位元 lane（8 個 lane） |
| `paddd` | packed `add`，32 位元 lane（4 個 lane） |
| `paddq` | packed `add`，64 位元 lane（2 個 lane） |

有些指令輸入的 lane 是一種大小，輸出的卻是另一種大小。
它們遵循同樣的一般慣例，但帶有_兩個_大小後綴。
第一個表示輸入 lane 的大小，第二個表示輸出 lane 的大小：

| 指令       | 意義                                              |
|------------|---------------------------------------------------|
| `pmovsxwd` | packed `movsx`，從 16 位元 lane 轉為 32 位元 lane |
| `pmuldq`   | packed `mul`，從 32 位元 lane 轉為 64 位元 lane   |

### 記憶體搬移

有兩個名稱帶有 integer 的指令會在 `xmm` 暫存器和記憶體之間複製 128 位元：

| 指令     | 說明                                               |
|----------|----------------------------------------------------|
| `movdqa` | 將 packed 整數複製到或複製自_已對齊_的位置         |
| `movdqu` | 將 packed 整數複製到或複製自_未對齊_的位置         |

它們的行為和 `movaps` 與 `movups` 一樣：`movdqa` 在未對齊的位址上會觸發 fault，而 `movdqu` 則接受任何位址。
這四個指令都會複製 128 位元，而不會解讀其內容。
名稱帶有 integer 的那一對，只是慣例上搭配整數資料使用，並非强制要求。

~~~~exercism/note
這裡的 `dq` 代表 `double-qword`，也就是 128 位元（16 位元組）。
~~~~

### 加法／減法

加法和減法遵循命名規則：

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

沒有另外區分有號和無號的版本。
在二補數中，無論 lane 被解讀為有號還是無號，加法和減法都會產生相同的位元，所以一個指令就能同時服務兩種情況。
要如何解讀由你決定，就和 scalar 的 `add` 與 `sub` 一模一樣。

這些指令在溢位時會**環繞**（wrap around），就和它們的 scalar 對應版本一樣。
一個 8 位元的 lane 存放的是對 256 取模的值，所以 `200 + 100` 的 `paddb` 會產生 `300 - 256 = 44`，並捨棄放不下的位元。

請注意，那些多出來的位元不會進位到下一個 lane。
每個 lane 都是與其他 lane 分開運算的，即使它們共用同一個暫存器也一樣。

### 飽和加法／減法

整數 SIMD 多了一種浮點數 SIMD 沒有的運算：**飽和**（saturating）加減法，它會_箝制_（clamp）而非環繞。
結果高於 lane 的範圍時，會變成該 lane 能容納的最大值；結果低於範圍時，則會變成最小值。

飽和版本會在大小後綴前插入 `s`（有號）或 `us`（無號）：

| 指令      | 意義                                    |
|-----------|-----------------------------------------|
| `paddsb`  | `add`，飽和，有號 8 位元 lane           |
| `paddusb` | `add`，飽和，無號 8 位元 lane           |
| `psubsw`  | `sub`，飽和，有號 16 位元 lane          |
| `psubusw` | `sub`，飽和，無號 16 位元 lane          |

箝制的範圍是對應大小與有號性的整數所能表示的最大範圍。
以 byte 為例：

- 無號 byte 會箝制到 `[0, 255]`：`200 + 100` 的 `paddusb` 會得到 `255`，而 `5 - 10` 的 `psubusb` 會得到 `0`。
- 有號 byte 會箝制到 `[-128, 127]`：`100 + 50` 的 `paddsb` 會得到 `127`。

當一個 lane 存放的是有界數量時，飽和就很重要，例如像素的色版或音訊取樣。
環繞會讓過亮的像素變暗，而箝制則會讓它維持在最大亮度，這才是你想要的結果。

~~~~exercism/note
飽和加減法只適用於 byte 和 word lane，不適用於 dword 或 qword。
~~~~

### 乘法

兩個 N 位元的值相乘，可能產生 2N 位元的乘積，但目的地的 lane 只有 N 位元寬。
SIMD 運算的處理方式，是明確指定要保留乘積的哪一半，也就是低的 N 位元或高的 N 位元。

以 16 位元 lane 為例，會用到三個指令：

| 指令      | 意義                                                          |
|-----------|---------------------------------------------------------------|
| `pmullw`  | `mul`，16 位元 lane，保留每個乘積的低 16 位元                 |
| `pmulhw`  | `mul`，16 位元 lane，保留高 16 位元，運算元為有號             |
| `pmulhuw` | `mul`，16 位元 lane，保留高 16 位元，運算元為無號             |

乘積的低 16 位元，無論運算元被解讀為有號還是無號都相同，所以只有一個 `pmullw`。

然而，高 16 位元會依結果的有號性而有所不同。
這就是為何取高半部的乘法要分成有號和無號兩種形式：

1. `pmulhw`，用於有號乘法。
2. `pmulhuw`，多一個 `u`，用於無號乘法。

注意語法：

1. 一個 `p`，代表 packed 整數。
2. 執行的運算，即 `mul`。
3. 一個 `h`，表示選取結果中較高（「high」）的位元。
4. 一個選用的 `u`，表示結果應被解讀為無號（也就是不做符號延伸）。
5. 最後是大小後綴 `w`，表示這是 word（16 位元）運算。

word 的 packed 乘法完全遵循上述規則。
dword（32 位元）乘法也遵循這個規則，但只有選取低半部的版本：`pmulld`。

dword 乘法沒有選取高位元的版本。
不過，有幾個版本會將乘法_加寬_，把_偶數索引_的 lane（也就是位置 0 和 2 的 lane）完整的 64 位元乘積存起來：

| 指令      | 意義                                                                                 |
|-----------|--------------------------------------------------------------------------------------|
| `pmuludq` | 將偶數索引的 32 位元元素以無號方式相乘，得到 2 個完整的 64 位元乘積                   |
| `pmuldq`  | 將偶數索引的 32 位元元素以有號方式相乘，得到 2 個完整的 64 位元乘積                   |

注意語法使用了 `dq`，無號乘法時前面可能還有一個 `u`。
這是因為這些指令接受 `dword` lane，並輸出 `qword` lane。

### 除法

沒有 packed 整數除法。
需要它的程式碼會把數值轉成浮點數、相除，再轉換回來。

### 加寬整數

`movsx` 和 `movzx` 都有 packed 的對應版本。
它們遵循我們前面提過、輸入與輸出 lane 大小不同的指令所用的相同語法：

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

請注意，lane 的數量是由較大的（輸出）寬度決定的。
指令會從來源的低位部分讀取那麼多個 lane。
這和我們在單精度與雙精度浮點數之間的 packed `cvt` 指令所見到的語意相同。

### 整數與浮點數之間的轉換

有些指令可以在 32 位元有號整數與浮點數 lane 之間轉換。
它們遵循 `cvt` 與 `cvtt` 指令的慣用語法，但 packed 整數不是用 `si`，而是用 `dq` 來表示：

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
使用 `pi` 代表 packed 整數的指令會寫入舊式的 `mmx` 暫存器，在 x86-64 上基本上已被淘汰。
請改用 `dq` 形式，它使用的是 `xmm` 暫存器。
~~~~

前面針對浮點數與整數之間 scalar 轉換所做的說明，在這裡同樣適用。
浮點數會依一個稱為 MXCSR 的特殊暫存器進行捨入，而你在函式進入時無法假設它的模式。
有一個 `cvtt` 版本（多一個 `t`），它一律會截斷結果。

也可以先使用 `round`，讓 packed 浮點數值處於已知的狀態再進行轉換。
捨入控制值和 scalar 的 `round` 相同，packed 浮點數值的語法也一樣：

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
