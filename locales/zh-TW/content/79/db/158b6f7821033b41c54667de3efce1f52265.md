# 關於

`Complex numbers`其實一點也不複雜。
它們只是需要一個不那麼嚇人的名字。

複數在工程和科學領域特別實用，因此 R 把[複數][web-complex]列為標準的[原子型別][ref-atomic]，與 integer、double、logical、character 和 raw 並列。

## 基礎

在 R 裡，一個 `complex` 數字就是單一的一個值。
不過實際使用時，可以把它想成是一對數字。
由於一些不幸的歷史因素，這兩部分被稱為「實部」與「虛部」。
再說一次，最好把焦點放在它背後的簡單本質，而不是那些奇怪的名字。

想用兩個實數建立複數，只要在虛部加上後綴 `i` 就行了。

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

想用實數變數建立複數，上面的語法行不通。
寫成 `r + imi` 會讓剖析器誤以為 `imi` 是一個（不存在的）變數名稱。

你可以把虛部乘上 `1i`，或是使用 [`complex()`][ref-complex] 函式：

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

你可能會想，為什麼是用 `i` 而不是 `j`？

多數工程師偏好 `j`。
多數科學家和數學家偏好用數學符號 `i` 來表示 _虛數_（imaginary），但這個符號會和電機工程中用 `i` 代表 _電流_（current）的慣例衝突。

R 選擇了 `i`，Python 選擇了 `j`，而 Julia 則選擇 `im`，避開了這場爭議。
在不同 [STEM][wiki-STEM] 程式語言之間切換時請多加留意。

如果想個別存取複數的各個部分：

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

任一部分都可以是零，數學家這時會說這個數是「全為實數」或「全為虛數」。
不過在 R 裡，它仍然是複數。

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

你可能聽過「`i`（或 `j`）是 -1 的平方根」這種說法。

目前為止，這句話的意思只是：虛部 _依定義_ 滿足下列等式：

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

這是個簡單的概念，卻會帶來有趣的結果。

## 算術

大多數用於浮點數和整數的[`operators`][ref-operators]也能用在複數上：

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

說明複數乘法和除法的規則超出了這個概念的範圍（_而且你不太可能經常需要「手算」這些運算_）。

如果你想深入研究這個主題，任何[數學][web-math-complex]或[電機工程][web-engineering-complex]的複數入門教材都會涵蓋這些內容。

或者，Exercism 有一個[`Complex Numbers`][exercise-complex-numbers]練習，你可以在其中從基本原理開始，實作一個具備這些運算的複數類別。

整數除法基本上___無法___用在複數上，因此 `%/%` 和 `%%` 運算子對複數型別會失敗。

## 函式

大多數數學函式都能接受複數輸入。

不過，如果提供實數輸入卻期望得到複數輸出，通常行不通。

```r
sqrt(z1)
#> [1] 1.414214+0.707107i

sqrt(-1)  # fails!
#> Warning in sqrt(-1) : NaNs produced
#> [1] NaN

sqrt(-1 + 0i)  # succeeds with complex input
#> [1] 0+1i

sin(z1)
#> [1] 3.752771+0.256554i
```

除了 `Re()` 和 `Im()` 之外，還有幾個函式對複數特別有用。
如果這些內容讓你一頭霧水，請直接跳過！

- `Conj()` 只是把複數虛部的正負號翻轉（_從 + 變成 -，或反過來_）。
  - 由於複數乘法的運作方式，這個功能比你想像的還實用。
- `abs(<complex number>)` 保證會回傳一個不含虛部的實數（也就是它的「量值」），而 `Mod(<complex number>)` 是同義的寫法。
- `Arg(<complex number>)` 會回傳以弧度為單位的相位角。

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```

對於喜歡數學的人，這裡提供一部分的說明（_再次提醒，可以跳過_）：

- `z1` 的 `(real, imag)` 表示法，實際上就是在複數平面上使用笛卡兒座標。
- 同一個複數也可以用極座標，以 `(r, θ)` 記法來表示。
- 在這裡，`r` 和 `θ` 分別由 `abs(z1)` 和 `Arg(z1)` 得出。

以下是一個使用一些常數的例子：

```r
 euler <- exp(1i * pi)

euler
#> [1] -1+0i
```

所以一個簡單的運算式，用上自然界最重要的三個常數 `e`、`i`（或 `j`）和 `pi`，就能得到結果 `-1`。
有些人認為這是全數學中最美的結果。
它可以追溯到 1740 年左右。

### 這難道是什麼奇怪的新純數學嗎？
它的「量
在 16 世紀時，它既陌生又新穎。

500 年後，它成為大多數工程與自然科學的核心。

### 為什麼會有人用這些？

結果發現，複數是描述任何會旋轉、或任何具有波動性質之事物最簡單的方法。
所以它們被廣泛應用於電機工程、音訊處理、物理、電腦遊戲和導航等領域，這還只是其中幾個例子而已。

你可以看見物體旋轉。
複數也許不是讓世界運轉的關鍵，但卻很適合用來說明世界運轉所 _產生的種種現象_：看看任何一張大型風暴的衛星影像就知道了。

不那麼明顯的是，聲音具有波動性，光具有波動性，無線電訊號具有波動性，甚至你家鄉的經濟也至少有一部分帶有波動性。

這類波動處理有很多可以用三角函式（`sin()` 和 `cos()`）來完成，但很快就會變得雜亂。

複數指數要___容易___處理得多。

### 但我又不需要複數！

這句話只有在你是住在洞穴裡、靠覓食維生的情況下才成立。

如果你是在任何一種螢幕上閱讀這段文字，那你就完全依賴著 20 世紀透過複數所達成的一些實用進展。

__半導體晶片__。

- 這些東西在古典物理中毫無道理，只能用量子力學（QM）來解釋（與設計）。
- 在量子力學中，所有東西依定義都是複數值。（_說到底全都是波形_）

__快速傅立葉轉換演算法__。

- FFT 是複數的一種應用，凡是與聲音傳輸、音訊處理、相片和影片相關的 _一切_，都少不了它。

- MP3 和其他音訊格式使用 FFT 進行壓縮，讓更多音訊能塞進更小的儲存空間。
- JPEG 壓縮和 MP4 影片，以及許多其他影像和影片格式，也都使用 FFT 來壓縮。

- FFT 也應用在數位濾波器中，讓手機基地台能把你的個人行動訊號和其他人的區分開來。

所以，你正在使用的科技，很可能每秒都依賴複數運算成千上萬次。
