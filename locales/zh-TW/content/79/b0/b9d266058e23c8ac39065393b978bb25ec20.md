# 關於

動態記憶體是由程式庫函式實作的，程式設計師用這些函式在執行階段配置與釋放記憶體。
由於記憶體的配置與釋放全由程式設計師掌控，動態記憶體安不安全，就取決於程式設計師能不能完全不犯錯。
因此，動態記憶體是程式設計中 bug 的主要來源之一，也是駭客攻擊的主要目標。

動態記憶體用於大小只有在執行階段才能得知的變數。
這對於每次執行時元素數量可能不同的陣列特別有用。
可變長度陣列（VLA）則是另一種處理元素大小只有在執行階段才知道的陣列的方式。
VLA 使用自動儲存，這表示離開定義它的區塊時，它的記憶體就會被銷毀。
（關於儲存的更多內容，請參閱[儲存類別修飾詞](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers)概念。）
VLA 是由 C99 引入 C 語言的，但從 C11 起 VLA 變成選用功能，因此支援 C11 及之後版本的編譯器不一定要支援 VLA。
關於可變長度陣列的詳細分析不在本文的範圍內。

## malloc

`malloc`是宣告在`stdlib.h`中的函式，用來配置動態記憶體。
如果配置成功，會回傳一個指標，指向所配置記憶體的第一個位元組的位址。
如果配置失敗，則回傳`NULL`。
建議檢查`malloc`的回傳值是否為`NULL`，並在失敗時妥善處理。
回傳的指標型別是 pointer-to-void，大致上可以把它想成一種「通用」指標，能轉換成該記憶體實際使用的特定型別。
`malloc`有 1 個參數，也就是想要的記憶體大小（以位元組為單位）。
配置陣列所需的總大小，是每個元素的資料型態大小乘上元素個數。
`sizeof`運算子通常用來取得每個元素資料型態的大小。
以下範例示範了這一點：

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

重要的是要記得，`malloc`新配置的記憶體不會被初始化，裡頭可能存放著垃圾值。
請注意，`numbers`指標的`sizeof`既不是陣列的元素個數，也不是配置的記憶體總量。
`malloc`回傳的指標大小，就是在該特定系統上任何指標的大小。
範例程式是在 64 位元系統上執行的，所以指標大小是 8 位元組（乘以每個位元組 8 位元 = 64 位元）。
這個指標的型別從 pointer-to-void 隱式轉換為 pointer-to-int。
pointer-to-int 要指向單一個`int`，還是指向`pointer-to-void`陣列，就看程式設計師覺得怎麼處理合適。
例如：

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

如果這些值在被讀取之前一定會先寫入，那麼使用`malloc`可以是配置記憶體的有效方式。
但如果這些值有可能在初始化之前就被讀取，那麼使用`malloc`就有風險。
比較安全的配置方式是用`calloc`，它會把新配置的記憶體初始化為零。

請注意，上面的範例都使用了`free(numbers)`。

## free

`free`是宣告在`stdlib.h`中的函式，用來釋放先前動態配置的記憶體。
動態配置的記憶體在被`free`釋放之前，會一直被系統佔用。
有些作業系統會在程式結束時自動釋放動態配置的記憶體，但最好還是別依賴這個行為。
`free`有 1 個參數，是指向那塊動態配置記憶體的指標。
有沒有使用`free`，會牽涉到幾種記憶體問題。

#### 記憶體洩漏

如果指向某塊動態配置記憶體的參考已經走到生命週期終點，或以其他方式被銷毀，卻沒有釋放這塊記憶體，就稱為記憶體洩漏。
洩漏的記憶體是指已被系統佔用，但程式再也無法存取的那塊記憶體。
如果程式在迴圈中配置記憶體、迴圈結束時沒有釋放，下一輪迴圈又再配置一次，這問題就會特別嚴重。
如果配置的記憶體一直沒被釋放，累積到一定程度後，配置記憶體的呼叫就會因為剩餘記憶體不足而失敗。
重要的是要記得，雖然動態配置的記憶體在被釋放前都由系統佔用著，但指向它的指標可能只有區塊作用域。
舉例來說，在`malloc`的範例中，記憶體是在`my_function`裡配置的。
如果指向那塊記憶體的指標沒有被回傳、用來設定`main`裡的`numbers`指標，那塊記憶體就會洩漏。
因此，把那個`numbers`指標傳給`free`，就能釋放在`my_function`中配置的記憶體。

#### 釋放後使用（**UAF**）

如果記憶體在釋放之後又被存取，裡面的值可能是任何東西。
在下面的範例中，`numbers`指向的記憶體被釋放後，又透過`printf`讀取。

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

`numbers`指標在被釋放之後，就稱為懸置指標。
懸置指標可能指向原本預期之外的記憶體。
因此，懸置指標可能導致資料損毀，也可能被用來替換並執行任意程式碼。
指向已配置記憶體、卻沒有設成`NULL`清掉的指標，可能被用來駭入程式。
在上面的範例中，如果`numbers`在釋放後像這樣設成`NULL`：`numbers = NULL;`，那麼接下來的`printf`會導致程式終止，在嘗試讀取`numbers[0]`時甚至可能回報區段錯誤。

#### 重複釋放

如果對同一個指向動態配置記憶體的指標呼叫`free`兩次，就會造成未定義行為（**UB**）。
這表示編譯器可以任意用任何它想要的方式處理。
下面這個範例用 2 個不同的編譯器編譯，可能會得到 2 種不同的結果：

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

當`numbers`在每次呼叫`free`之間被設成`NULL`時，第一個和第二個編譯器都沒有產生執行階段錯誤，但換成第三個編譯器就不保證能行得通。
重複釋放的常見成因，是 2 個指標同時指向同一塊動態配置的記憶體。
其中一個指標可能在程式的某處指向陣列的開頭，另一個指標則在程式的另一處用來逐一遍歷這個陣列。
在程式的不同位置，兩個指標分別被釋放，因而造成重複釋放。

## calloc

`calloc`是宣告在`stdlib.h`中的函式，既能配置動態記憶體，也會把新配置的記憶體初始化為零。
如果配置成功，會回傳一個指標，指向所配置記憶體的第一個位元組的位址。
如果配置失敗，則回傳`NULL`。
建議檢查`calloc`的回傳值是否為`NULL`，並在失敗時妥善處理。
回傳的指標型別是 pointer-to-void，大致上可以把它想成一種「通用」指標，能轉換成該記憶體實際使用的特定型別。
`calloc`有 2 個參數。
第一個參數是要配置多少個指定資料型態的數量。
第二個參數是要配置的指定資料型態的大小。

在下面的範例中，所有的`printf`都應該顯示`0`，因為`calloc`保證會把新配置的值設為零。

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc`是宣告在`stdlib.h`中的函式，用來擴張或縮小已配置的記憶體。
如果重新配置成功，會回傳一個指標，指向重新配置後記憶體的第一個位元組的位址。
如果重新配置失敗，則回傳`NULL`。
建議檢查`realloc`的回傳值是否為`NULL`，並在失敗時妥善處理。
`realloc`有 2 個參數。
第一個參數是指向要重新配置的既有記憶體的指標。
第二個參數是重新配置後的記憶體大小（以位元組為單位）。
在記憶體擴張之前已設定的值會保留下來。
重要的是要記得，擴張記憶體時新增的部分不會初始化為零，它的值可能是任何東西。
另外，縮小記憶體時移除的部分同樣沒有被初始化，可能還留著原來的值。
下面的範例示範了陣列的擴張與縮小：

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## 傳入的大小為 0 時

如果傳給`malloc`、`calloc`或`ints`的大小是`0`，結果會依編譯器怎麼實作而定。
編譯器可能回傳`NULL`指標，也可能回傳非`NULL`的指標。
舉例來說，如果要為指向`char`的指標配置記憶體，編譯器可能回傳`pointer-to-void`，也可能回傳一個指向空字串的非`relloac`指標。
為了避免不同編譯器產生不同結果，最好不要配置大小為 0 的記憶體。
