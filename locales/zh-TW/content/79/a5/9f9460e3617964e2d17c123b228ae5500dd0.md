# 簡介

你已經在`channel-chatter`裡*用過*串流，也在`boatswains-bilge`裡將它們處置掉了。這個練習是你的第一個自訂串流，一個實作了[協定][stream-protocol]的類別，讓那些原本能在`<string-reader>`上運作的`with-input-stream`／`read1`／`stream-read1`程式碼，也能在你的串流上運作。

## Mixin：類別階層的另一半

你已經從`dragons-descendants`認識了`TUPLE: child < parent …`，那是一種單一父類別的階層，槽位會往下繼承。Factor 有*第二種*擴充類別圖的方式：**開放式 mixin**。`MIXIN: m`會宣告一個沒有槽位的類別，其他類別之後可以用`INSTANCE: c m`加入。成員關係是多對多的：一個類別可以同時是任意多個 mixin 的實例。

串流協定用兩個 mixin 來標示一個類別實作了介面的哪一半：

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

一個串流可以是其中一個、另一個，或兩者兼具。`input-stream`（或`output-stream`）上的泛型方法接著會分派到任何加入該 mixin 的類別，這就是環境中的`read1`、`stream-contents`、`with-input-stream`等等找到你的類別的方式。

Mixin 是*開放式*的：你可以在 mixin 宣告之後才加入新成員，甚至可以在不同的詞彙表中加入。這和`TUPLE: < parent`形成對比，後者的關係在子類別宣告時就固定了。

## 協定泛型

協定泛型位於`io`裡：

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

`stream-read1`會回傳下一個位元組，串流結束時則回傳`f`；`stream-write1`則寫入一個位元組。`stream-read-unsafe`是大多數輸入串流提供的較低階批次讀取；`stream-read`建立在其之上，並負責處理配置。`stream-element-type`會說明這個串流處理的是位元組（`+byte+`）還是字元（`+character+`）；當你包裝另一個串流時，最簡單的實作就是直接委派給底層串流。

## 清理機制來自`destructors`

串流是 disposable：自訂串流會繼承`disposable`並實作`dispose*`。那就是`boatswains-bilge`裡的框架，套用到串流類別上：

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

一旦這些就緒，`channel-chatter`裡所有`with-…`的組合子都會自動作用在你的串流上。
