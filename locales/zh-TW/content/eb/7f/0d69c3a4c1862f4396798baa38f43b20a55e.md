# 關於

[單指令多資料（SIMD）][SIMD] 是一種硬體層級的平行處理。CPU 會同時對多個元素執行相同的運算。

舉例來說，假設要把兩個各含四個 32 位元浮點數的陣列逐元素相加。
純量實作會發出四道獨立的`addss`指令，每個元素一道。
SIMD 實作則只用一道`addps`，就平行完成這四次加法。
這讓每道指令的工作量變成四倍。

在 x86-64 組合語言中，SIMD 指令通常使用`xmm`暫存器來執行。
這些指令有些處理整數。
有些則處理浮點數。

這些整數或浮點數稱為**打包**資料。
每一個都佔用同一個暫存器內的一塊空間，稱為**通道**。
SIMD 指令通常會平行處理兩個來源運算元中位於同一通道位置的各別值。
每個運算的結果會存到目的運算元中相同位置的通道裡。

通道並不是硬性限制。
它是每道指令對一串位元組所做的解讀。
一個 128 位元的運算元包含 16 個位元組。
視指令而定，這些位元組可以解讀為 16 個_1 位元組_的通道、8 個_2 位元組_的通道、4 個_4 位元組_的通道、2 個_8 位元組_的通道，甚至單一個_16 位元組_的通道。

舉例來說，指令`addps`會把打包的單精度（4 位元組）浮點數相加。
對這道指令來說，運算元中每 4 個位元組為一塊，各自是不同的通道。
在一個 128 位元寬（16 位元組）的運算元中：

| 運算元     | 第 4 通道 | 第 3 通道 | 第 2 通道 | 第 1 通道 |
|:-----------:|:--------:|:--------:|:--------:|:--------:|
| 來源 1      |  1.5     |  2.1     | 6.2      | 3.4      |
|    +        |  +       |  +       | +        | +        |
| 來源 2      |  0.5     |  8.26    | -13.4    | 22.9     |
|    =        |  =       |  =       | =        | =        |
| 結果        |  2.0     |  10.36   | -7.2     | 26.3     |

另一方面，在`mulpd`的情況下，一個 128 位元的運算元會被解讀為只有 2 個通道。
這是因為這道指令會對雙精度（8 位元組）的值執行打包乘法：

| 運算元     | 第 2 通道 | 第 1 通道 |
|:-----------:|:--------:|:--------:|
| 來源 1      |  4.2     |  2.1     |
|    *        |  *       |  *       |
| 來源 2      |  1.0     |  92.4    |
|    =        |  =       |  =       |
| 結果        |  4.2     |  194.04  |

在這個概念中，我們會聚焦在少數幾道 SIMD 指令。
它們使用`xmm`暫存器來處理打包的浮點數值。

## 浮點數 SIMD 指令

大致說來，處理浮點數值的 SIMD 指令採用雙運算元的形式。
它們的名稱遵循特定的結構：

1. 所執行的運算，名稱與其非 SIMD（也稱為_純量_）版本相同（例如`add`、`mul`等）。
2. 一個後綴`p`，表示這道指令處理的是_打包_資料，位置與原本的`s`（代表_純量_資料）相同。
3. 一個後綴，表示每個通道的大小，語意與其非 SIMD 版本相同（`s`代表單精度，`d`代表雙精度）。

因此，打包版本的名稱就是把純量名稱中助憶碼中間的`s`（純量）替換成`p`（打包）而得到。
運算名稱與大小後綴維持不變：

| 純量    | 打包    | 意義                                   |
|---------|---------|----------------------------------------|
| `addss` | `addps` | 加法，單精度（32 位元通道）            |
| `addsd` | `addpd` | 加法，雙精度（64 位元通道）            |
| `mulss` | `mulps` | 乘法，單精度                           |
| `mulsd` | `mulpd` | 乘法，雙精度                           |

### 算術運算

算術類的 SIMD 指令遵循上述規則。
幾個例子：

```x86asm
addps xmm0, xmm1 ; xmm0 = xmm0 + xmm1 (each 32-bit float at the same position)
subpd xmm2, xmm3 ; xmm2 = xmm2 - xmm3 (each 64-bit float at the same position)
mulps xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (each 32-bit float at the same position)
divpd xmm6, xmm7 ; xmm6 = xmm6 / xmm7 (each 64-bit float at the same position)
```

### 精度之間的轉換

也有一些 SIMD 指令可以在打包的單精度與打包的雙精度浮點數值之間轉換。
它們遵循相同的命名規則，把代表_純量_的`s`換成代表_打包_的`p`：

| 純量       | 打包       | 意義                                         |
|------------|------------|----------------------------------------------|
| `cvtss2sd` | `cvtps2pd` | 將單精度轉換為雙精度                         |
| `cvtsd2ss` | `cvtpd2ps` | 將雙精度轉換為單精度                         |

這些指令正好說明了前面提過的觀點：通道是一種解讀，而不是硬性限制。
來源運算元與目的運算元的通道大小不同，因此通道數量也不同。

對`cvtps2pd`來說，來源（`ps`）有 4 個單精度通道。
目的（`pd`）有 2 個雙精度通道。
只會讀取來源中較低的 2 個通道。
較高的 2 個會被忽略：

| 運算元               | 第 4 通道 | 第 3 通道 | 第 2 通道 | 第 1 通道 |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| 以`ps`解讀的來源     | 忽略     | 忽略     | 2.5      | 1.5      |
| 以`pd`解讀的目的     |          |          | 2.5      | 1.5      |

對`cvtpd2ps`來說，來源（`pd`）有 2 個雙精度通道。
目的（`ps`）有 4 個單精度通道。
兩個來源通道都會被轉換，並寫入目的中較低的 2 個通道。
目的中較高的 2 個通道會設為零：

| 運算元               | 第 4 通道 | 第 3 通道 | 第 2 通道 | 第 1 通道 |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| 以`pd`解讀的來源     |          |          | 4.0      | 3.0      |
| 以`ps`解讀的目的     | 0        | 0        | 4.0      | 3.0      |

幾個例子：

```x86asm
cvtps2pd xmm0, xmm1 ; xmm0 = xmm1 as 2 doubles (low 2 lanes of xmm1 are read)
cvtpd2ps xmm0, xmm1 ; xmm0 = xmm1 as 2 floats (in low 2 lanes; upper 2 zeroed)
```

### 記憶體運算元

上面介紹的 SIMD 指令都是以暫存器對暫存器的運算元呈現。
它們也可以把記憶體運算元當作來源（但**不能**當作目的）。

從記憶體讀取的位元組數量由指令決定。
舉例來說，`addps`會讀取 16 個位元組（4 個單精度浮點數）。
相對地，`cvtps2pd`只讀取 8 個位元組（2 個單精度浮點數），因為這就是它需要的全部輸入。

```x86asm
addps    xmm0, [rsi]      ; xmm0 = xmm0 + 4 floats at [rsi]
mulpd    xmm1, [rsi + 16] ; xmm1 = xmm1 * 2 doubles at [rsi + 16]
cvtps2pd xmm2, [rsi + 8]  ; xmm2 = (2 floats at [rsi + 8]) converted to 2 doubles
```

當記憶體運算元寬度為 16 位元組時，它必須是_16 位元組對齊_。
對齊的記憶體位置，指的是其位址為運算大小的倍數（在此例中為 16 位元組）。

要宣告對齊的記憶體，可以在 .data 與 .rodata 區段使用`align`指示詞，或在 .bss 區段使用`alignb`：

```x86asm
section .rodata
align 16
mem1: dd 4.0, 3.5, 2.0, -1.0

section .data
align 16
mem2: dq 6.0, 2.1

section .bss
alignb 16
mem3: resb 16

section .text
fn:
    movaps xmm0, oword [rel mem1] ; loads 4 packed 32-bit floats in xmm0
    movapd xmm1, oword [rel mem2] ; loads 2 packed 64-bit floats in xmm1
    movaps oword [rel mem3], xmm0 ; stores 4 packed 32-bit floats in mem3
    ret
```

小於 16 位元組的記憶體運算元，例如`cvtps2pd`的 8 位元組來源，沒有對齊要求。

### 載入與儲存數值

有四道指令可以複製 128 位元的打包浮點數值。
它們作用於兩個`xmm`暫存器之間，或是一個`xmm`暫存器與一個記憶體位置之間：

| 指令        | 說明                                                                              |
|-------------|-----------------------------------------------------------------------------------|
| `movaps`    | 從_對齊_的記憶體位置複製打包的單精度資料，或複製到該位置                          |
| `movups`    | 從_未對齊_的記憶體位置複製打包的單精度資料，或複製到該位置                        |
| `movapd`    | 從_對齊_的記憶體位置複製打包的雙精度資料，或複製到該位置                          |
| `movupd`    | 從_未對齊_的記憶體位置複製打包的雙精度資料，或複製到該位置                        |

這些指令全都可以用來在兩個`xmm`暫存器之間複製數值。

如果運算涉及記憶體位置，`movaps`與`movapd`要求該位置必須_對齊_。
如果給定未對齊的位址，`movaps`與`movapd`會引發錯誤。
它們同時也兼作安全檢查，確認你的資料配置和你以為的一致。

另一方面，`movups`與`movupd`可用於任何記憶體位置，無論對齊與否。

在 NASM 中，16 位元組數值的大小前綴是`oword`。

## SIMD 擴充指令集

數十年來，SIMD 一直是 x86-64 生態系中積極發展的目標。
每一次架構擴充都會帶來新指令，或是舊指令的新用法。

特別是 [AVX 與 AVX2][AVX] 這兩項擴充帶來了幾個重要的改變。

第一，支援 256 位元的 SIMD 暫存器，稱為`ymm`。
它們延伸了對應的`xmm`暫存器，就像`rax`包含`eax`一樣。

第二，它們為大多數作用於`xmm`（與`ymm`）暫存器的指令，加入了三運算元變體的支援。
這不僅包含 SIMD 指令，也包含處理純量浮點數值的指令。
這些變體沿用其 SSE 對應指令的相同表示法，並在前面加上一個`v`：

```x86asm
vaddsd xmm0, xmm1, xmm2   ; xmm0 = xmm1 + xmm2 (scalar sum of 64-bit floats)
vmulps xmm1, xmm3, xmm4   ; xmm1 = xmm3 * xmm4 (packed multiplication of 32-bit floats)
vmovupd ymm5, yword [mem] ; this copies 32 bytes from the location at mem to ymm5
```

第三，SIMD 記憶體運算元所需的對齊要求放寬了。
只有像`vmovaps`這類明確對齊的搬移指令才需要這種對齊。

在本 track 中，我們只使用到上一代 SSE 擴充為止的指令與暫存器。
這足以教導基礎，並確保能與各式各樣的 CPU 相容。

不過，test runner 完整支援 AVX 與 AVX2，甚至支援屬於 AVX-512 的較新擴充。
你可以自由使用它們。

~~~~exercism/note
最好能一致地使用同一種 SIMD 變體。
盡量不要為相同的指令混用 SSE 與 AVX 變體。

如果你的程式碼庫混用了這些變體，最好在用完 AVX 之後、改用 SSE 之前執行`vzeroupper`。
這能打斷相依鏈，避免 CPU 在 AVX 與 SSE 狀態之間切換時付出高昂的停滯成本。
