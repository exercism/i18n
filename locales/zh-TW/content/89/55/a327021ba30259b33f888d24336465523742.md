# 指令補充

## `from_quote`的優缺點

`Card.from_quote`函式會將字串剖析成一個`Card`。這麼一來，你就能寫出像這樣的程式碼：

```roc
card : Card
card = "Q"
```

這段程式碼會在編譯期隱含呼叫`Card.from_quote("Q")`。這有可能加快程式的執行速度，因為它不需要在執行期處理剖析；而且能確保被`from_quote`拒絕的牌會在編譯期就被攔下，而不是等到執行期。不只如此，這也讓程式碼簡潔易讀。舉例來說，這是這個練習的其中一個測試：

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

不過，讀到這段程式碼的人可能會以為`simulate_game`函式接收的是一筆包含兩個`List(Str)`的記錄，但實際上它接收的是一筆包含兩個`List(Card)`的記錄。這可能會造成混淆和錯誤。因此，你可能會偏好稍微冗長但更明確的寫法：`"Q".Card`，這種寫法同樣會在編譯期呼叫`from_quote`。

在你自己寫的程式裡，你可能會偏好改用`from_str`：

```roc
Card := { ... }.{
    from_str : Str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

你也可以像這樣在編譯期呼叫`from_str`（或任何其他純函式）：

```roc
Ok(card) = Card.from_str("Q")
```

注意：把這個定義放在最上層會讓它在編譯期執行（因為這個函式是純函式，而且它的輸入在編譯期就已經知道）。在函式內部，你可以在執行期使用`from_str`。
