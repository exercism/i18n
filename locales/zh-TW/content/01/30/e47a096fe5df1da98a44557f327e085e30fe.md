# 關於

雖然這個練習探討的是 `time`的概念，但實際上你很少會單獨處理時間。時間幾乎總是和日期一起處理。這裡並沒有另外一個獨立的 _時間_ 型別，只有 [`DateTime`][date-time]。

一天當中的時間可以用 [`TimeSpan`][time-span] 來表示（事實上，這正是 `DateTime.TimeOfDay` 的回傳型別）。它不是[專門為此設計][skeet-time-of-day]的，所以程式的表達力有時會顯得有點笨拙。舉例來說，對於一個 UTC 形式的 `DateTime` 實例，你預期它的一天當中的時間會是什麼？不過，它還是能完成工作。

討論 _時間_ 會涉及好幾個面向：

- 當地時間與世界協調時間（UTC）
- `DateTime`的運算
- 時區（包括日光節約時間）
- 日期時間字串的解析與格式化。
- 解析度（計時器選擇等）

這個練習涵蓋了當地時間與 UTC、日期時間運算、時區，以及日期時間解析。

[格式化][date-string-formatting]則在 `string-formatting`練習中討論。

解析度和計時器在網路上[有很多討論][so-timers]。`DateTime` API 有特定的常式來處理檔案時間戳記。

長期儲存日期時間時，通常最好以 UTC 形式儲存。如果會用到多個時區，這樣可以確保一致性，也能避免日光節約時間可能帶來的問題。

UTC 時間的缺點是，如果一天當中的時間是重要因素，就必須轉換成當地時間。

大致上，只要處理過程是以你電腦的時區為基準，`DateTime.ToUniversalTime()`和 `DateTime.ToLocalTime()`都能運作得很好。如果牽涉到多個時區，或是和你電腦不同的時區，就需要 [`TimeZoneInfo`][time-zone-info]類別來處理轉換。而不是已經過時的 ~~TimeZone~~ 物件。

你應該還記得，在練習中提過至關重要的時區識別碼在 Windows 和其他平台之間並不相同。這篇[文章][cross-platform-time-zones]對這個跨平台問題有很好的介紹。請注意，`TimeZoneInfo.GetSystemTimeZones()`會列出你所在平台的時區。

這篇[文章][time-overview]對時間和時區有很好的概述。

在練習中處理日期時間運算時，你很可能用過 `TimeSpan`結構。當你需要進行涉及整月或整年的運算時，`DateTime`結構提供了許多方法，例如 `AddHours()`和 `AddMonths()`。

如果日期和時間在你的專案中是無所不在且／或關鍵的一部分，那麼你應該研究一下 [Noda Time][noda-time]。

如果你好奇的話，根據這篇[維基百科文章][wiki-utc]，世界協調時間的縮寫 UTC 源自英語（UCT）和法語（CUT）使用者之間的妥協，好讓兩種語言都不會顯得比較優先。
