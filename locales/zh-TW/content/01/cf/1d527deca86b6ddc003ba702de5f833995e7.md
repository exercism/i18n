# 關於

大多數純量位元運算都有封裝版本。
它們遵循與 [SIMD 整數運算][simd-integers] 相同的一般語法，但沒有尺寸後綴：

| 指令 | 說明 |
|-------------|-----------------------------------|
| `pand`      | 兩個 128 位元值的位元 AND |
| `por`       | 兩個 128 位元值的位元 OR  |
| `pxor`      | 兩個 128 位元值的位元 XOR |

請注意，並沒有封裝版的`NOT`。
不過，有一個 ANDN 運算，它會將**目的**運算元取補數（翻轉其中所有位元），再計算兩個運算元之間的 AND。
可以把它想成是 NOT 與 AND 的組合：

| 指令 | 說明 |
|-------------|-----------------------------------------------------------------|
| `pandn`     | **取補數後**的目的運算元與來源運算元的位元 AND |

請注意，位元運算會合併兩個不同運算元中相同位置的位元，因此通道的邊界不會改變結果。
這就是為什麼這些指令沒有尺寸後綴：暫存器會表現得像單一個 128 位元的通道：

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
這個概念中的所有指令都會計算位元，但不會設定任何旗標。
之後的概念會說明如何處理帶有封裝值的條件判斷。
~~~~

## 逐通道位移

位移和純位元運算不同，它確實會讓位元跨位置移動，因此需要一個通道大小來設定邊界。
在每個通道內，它們的行為就和對應的純量版本一樣，而且位元絕不會從一個通道跨入相鄰的通道：

| 指令 | 說明 |
|---------------------------|-------------------------------------|
| `psllw`、`pslld`、`psllq` | 逐通道的邏輯左移 |
| `psrlw`、`psrld`、`psrlq` | 逐通道的邏輯右移 |
| `psraw`、`psrad`          | 逐通道的算術右移 |

請注意，這些指令遵循封裝整數運算的語法，包括尺寸後綴。
沒有以位元組為通道的位移，只有 word、dword，以及（算術右移除外的）qword。

封裝位移和其純量版本之間的其中一個差異，在於運算的名稱：

- 我們用的不是`shl`和`shr`，而是`sll`和`srl`，分別由 **s**hift（移位）、**l**eft（左）／**r**ight（右）與 **l**ogical（邏輯）組成。
- 我們用的不是`sar`，而是`sra`，由 **s**hift（移位）、**r**ight（右）與 **a**rithmetic（算術）組成。

名稱雖然不同，運算本身卻是一樣的：

- 邏輯右移會用零填補最高位的位元。
  它等同於以無號數除以 2 的次方。
- 算術右移會用符號位元的值填補最高位的位元。
  它等同於以有號數除以 2 的次方，並向負無限大取整。
- 左移一律以零填補（這就是為什麼不需要算術左移）。

位移次數對每個通道都相同。
它可以是立即值，或是`xmm`暫存器的低 64 位元：

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
位移次數若大於通道寬度，並不會像純量`shl`/`shr`系列那樣環繞。
它只會產生零（若是算術右移，則為全部的符號位元）。
~~~~

## 浮點位元運算

每個位元運算指令也都有以浮點命名的對應版本，語法和我們看過的封裝浮點運算相同：

| 整數名稱 | 浮點名稱 |
|--------------|----------------------|
| `pand`       | `andps`、`andpd`     |
| `pandn`      | `andnps`、`andnpd`   |
| `por`        | `orps`、`orpd`       |
| `pxor`       | `xorps`、`xorpd`     |

由於位元運算作用在位元上，實際上整數運算與浮點運算算出的結果相同。
之所以有不同的名稱，有兩個原因：

1. 標示意圖，就像我們會依所複製位元組的性質，偏好選擇`movdqa`、`movaps`或`movapd`一樣。
2. 整數運算與浮點運算往往有不同的執行域。
   同一執行域內的運算通常可以更快地依序執行。

浮點值沒有位移運算。

## 浮點位元表示法

[IEEE 754][ieee-754] 浮點數的位元表示法與整數大不相同。

在無號整數中，每個位元都有統一的意義：它代表對應該位元索引的 2 的次方。
整數就是對應到各設定位元之 2 的次方的總和。
這就是為什麼位移位元可以讓數字乘以或除以 2 的次方：我們只是改變了每個設定位元的索引。

在有號整數中，大多數位元的解讀方式與無號整數相同。
不過，最高位的位元很特別。
如果它被設定，我們不是將它加到其他位元上，而是必須減去對應的 2 的次方，結果會得到負數。
實際上，若要改變一個數字的正負號，概念上需要兩個步驟：翻轉所有位元（`not`），然後將結果加 1（`inc`）。

浮點數中的位元並沒有統一的意義，必須依其位置以非常不同的方式解讀：

| 欄位 | 索引（32 位元） | 索引（64 位元） |
|----------|------------------|------------------|
| 符號     | 31               | 63               |
| 指數     | 30-23            | 62-52            |
| 尾數     | 22-0             | 51-0             |

算出的數字由`(-1)^sign * 1.fraction * 2^(exponent - bias)`求出。
偏差值取決於精度：

| 大小   | 偏差值 |
|--------|------|
| 32 位元 | 127  |
| 64 位元 | 1023 |

在兩種格式中，數字的正負號完全由符號位元決定。
只要翻轉這個位元（一個 XOR 運算），就能改變浮點數的正負號。
只要將它清除（一個把該位元清零的 AND），就能取得絕對值：

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

請注意，在這種位元表示法中，位移位元並沒有可預測且一致的結果。
尾數可能「溢出」到指數，而指數則可能溢到符號位。

不過，有時把表示法的不同部分隔離出來、分別操作會比較方便。

舉例來說，指數中的位元應該先解讀為無號數，之後才從中減去偏差值。
這表示我們可以產生一個 32 位元或 64 位元的整數，其底層位元表示法對應到相應浮點格式中的某個 2 的次方。
接著就能用這個原始位元表示法來乘或除另一個浮點數。

舉例來說：

```x86asm
mov eax, 210       ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23        ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax     ; we move the raw bits to xmm0
mulss xmm1, xmm0   ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

反之，我們可以對封裝浮點數執行 AND，搭配一個設定指數位元、清除其他所有位元的遮罩，藉此擷取出它們的指數。
再結合位移與減法，就能以有號整數的形式，取得每個通道的無偏差指數：

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
直接操作浮點數的原始位元，雖然在某些情況下很有用，但應該謹慎為之。
上述公式只描述**正規**數：指數欄位全為零時，編碼的是零與非正規數；全為一時，編碼的是無限大與 NaN。
只有在沒有溢位或下溢，且輸入數字為正規數時，對指數欄位做加或減才是安全的。
此外，將有效的`x`加到`0.0`的指數欄位，結果會是`2^(x - bias)`，而不是`0.0 * 2^x`。
~~~~

## AVX 及後續擴充

AVX 為這裡的每一個指令提供了加上`v`前綴的三運算元形式，作用在更寬的暫存器上，行為維持不變：

```x86asm
vpand  ymm0, ymm1, ymm2 ; ymm0 = ymm1 AND ymm2, 256 bits
vxorps ymm3, ymm4, ymm5 ; ymm3 = ymm4 XOR ymm5, 256 bits
vpsrad ymm6, ymm7, 2    ; eight 32-bit lanes shifted right arithmetically
```

AVX2 也引入了可變位移，在尺寸後綴前加上`v`。
它們接受一個計數向量，並依對應通道中的計數來位移：

```x86asm
vpsllvd ymm0, ymm1, ymm2  ; each 32-bit lane shifted left by its own count
vpsravd ymm3, ymm4, ymm5  ; each 32-bit lane shifted right arithmetically by its own count
```

AVX-512 補上了 SSE 留下的兩個缺口：

- `vpsraq`終於提供了 64 位元的算術右移。
- `vpternlogd`和`vpternlogq`能以單一指令計算**任何**三輸入的位元函式。
  8 位元的立即值就是真值表本身：立即值的第`i`個位元，就是輸入組合`i`的輸出。
  三個運算元上任何`pand`/`pandn`/`por`/`pxor`的鏈結，都能收斂成單一個`vpternlog`。

提及這些擴充是為了完整起見。
這個學習軌道中的練習採用的是 SSE 形式。
