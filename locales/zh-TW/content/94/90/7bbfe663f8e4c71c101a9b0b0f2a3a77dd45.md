# 建立測試執行器

測試執行器是不可或缺的工具，它能：

- 讓網站自動驗證某個疊代是否通過所有測試。
- 讓學生使用[瀏覽器內的編輯器](/docs/using/solving-exercises/using-the-online-editor)來解練習（[不需要 CLI](/docs/using/solving-exercises/working-locally)）。

想開始打造測試執行器，請參閱[從零開始建立測試執行器](/docs/building/tooling/test-runners/creating-from-scratch)這份文件。

## 實作

軌道的工具通常（大多）是用該軌道的程式語言撰寫的。

```exercism/caution
雖然你可以自由使用其他語言，但每多一種語言，都會讓軌道更難維護、更難貢獻。
因此，我們建議盡可能使用該軌道的程式語言，因為這樣會讓維護和貢獻都更容易。
```

## 部署

測試執行器會打包成 [Docker 容器](/docs/building/tooling/docker)來執行。
測試執行器的 Docker 映像檔會透過 [GitHub Actions 工作流](https://github.com/exercism/generic-test-runner/blob/main/.github/workflows/docker.yml)自動部署。

## 測試

測試執行器建好之後，你可以在軌道的 CI 設定中使用它的 Docker 映像檔，來驗證軌道的練習。
這個做法的主要好處是，它能更貼近正式環境的設定。換句話說，你會更有把握這些東西在正式環境中也能運作。
可能的缺點是，它可能會拖慢 CI 工作流。
哪一種做法最適合你的軌道，就由你這位維護者來決定。
