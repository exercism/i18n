# 關於

轉型和型別轉換[是將運算式從一種型別改成另一種型別的兩種不同方式][wiki-casting]。

[C# 文件][type-testing-and-cast-operators]將型別轉換歸類為使用[`as`運算子][as-operator]或[`is`運算子][is-operator]。而轉型則定義為使用[轉型運算子][cast-operator]。

在 C# 中，很多時候在數值和類別階層以外的情況，你都必須呼叫「目標」型別的某個成員來進行轉換，例如呼叫[`Int32.Parse()`][int32-parse]將字串轉成整數，或是呼叫「來源」型別的成員，例如`object.ToString()`。JavaScript 開發者和其他動態語言的開發者都應該留意這一點。

請注意，還有隱含和明確的轉型[運算子][operator-overloading]（在 [concept:csharp/operator-overloading]() 中討論過），可以讓你的自訂型別實現相當自由的轉型。

## 轉型基本型別：隱含

C# 的型別系統比 _C_ 或 JavaScript 稍微嚴格一些，因此轉型的操作也受到較多限制。只要「目標」型別能保留「來源」型別值的範圍和正負號，[隱含轉型][implicit-casts]就會在兩個數值型別之間發生。請注意文件中關於轉換成實數時可能遺失精確度的例外說明。

隱含轉型不需要任何特殊的語法來表示。例如：

```csharp
int myInt = 1729;
long myLong = myInt;
```

數值（或字串）運算式無法隱含轉換成`bool`。基底類別庫（BCL）為此提供了`Convert.ToBoolean()`。

型別為`char`的運算式可以隱含轉型成`int`。反方向的轉型則必須是明確的。並非所有`int`的值都是有效的 UTF-16 字元。

## 轉型基本型別：明確

當數值型別無法隱含轉型時，你通常可以使用明確轉型[運算子][cast-operator]。

如果被轉型的值因為寬度不足或正負號衝突而無法用「目標」型別表示，那麼在整數的情況下可能會擲回溢位例外，而在 float 和 double 的情況下，「目標」型別的變數則可能得到`Infinity`這個值。

型別為`int`的運算式可以明確轉型成`char`。這可能會產生無效的`char`。

## 轉型基本型別：範例

```csharp
int largeInt = Int32.MaxValue;
int largeNegInt = Int32.MinValue;
ushort shortUnsignedInt = ushort.MaxValue;
float largeFloat = float.MaxValue;
float smallFloat = 17.29f;

// implicit cast
int from_ushort = shortUnsignedInt;          // 65535
float from_int = largeInt;                   // -21474836E+09
int from_char = 'a';                         // 96

// explicit cast
uint from_largeInt = (uint)largeInt;         // 2147483647
uint from_neg = (uint) largeNegInt;          // 2147483648 or OverflowException is thrown (if checked)
int from_smallFloat = (int) smallFloat;      // 17
int from_largeFloat = (int) largeFloat;      // -2147483648 or OverflowException is thrown (if checked)
char from_intc = (char) 32;                  // ' '
char from_invalid_int = (char) 0xdcbf;       // invalid char - no exception thrown

// no cast available
int fromString = Int32.Parse("42");          // 42
string toString = largeInt.ToString();       // "2147483647"
int fromString_bad = Int32.Parse("forty two");     // FormatException is thrown
```

關於 _**checked**_ 關鍵字，請參閱這篇[文章][checked]。

## 階層架構中型別的型別轉換

任何型別都可以隱含轉換成它的基底類別或介面。

```csharp
IList<int> ll = new List<int>();
```

轉型運算子可以用來從基底類別轉換成衍生類別。

```csharp
IList<int> ll = new List<int>();
List<int> l = (List<int>)ll;
```

如果轉型失敗，原因是被轉型的運算式型別與要轉型成的型別不相關，就會擲回`InvalidCastException`。

面對這些型別轉換，更常見的做法是使用[`is`][is-operator]關鍵字：

```csharp
interface IFoo { int Bar(); }
class Foo : IFoo { public int Bar() { return 42; }}
Object r = new Random();
IFoo ifoo = new Foo();
Object o = new Foo();

int result = 1729;

if (ifoo is Foo foo)
{
    result = foo.Bar();
}
// result == 42

result = 1729;
if (o is Foo foo2)
{
    result = foo2.Bar();
}
// result == 42

result = 1729;
if (r is Foo foo3)
{
    result = foo3.Bar();
}
// result == 1729
```

[`as`][as-operator]關鍵字的功能和`is`類似，例如`var foo = ifoo as Foo;`。在這個例子中，如果`ifoo`的型別不是`Foo`，`foo`就會是`null`；否則`ifoo`會被指定給它。

## 自訂轉型運算子

型別可以定義自己的自訂明確和隱含[轉型運算子][custom-casts]。

BCL 中[明確][big-integer-explicit]和[隱含][big-integer-implicit]轉型的例子，就是`BigInteger`結構與其他數值型別之間的相互轉換。

## 使用 `typeof`

如果你需要偵測物件的確切型別，那麼`is`可能稍微過於寬鬆，因為它會把物件轉換成某個類別或它的任何基底類別。在這種情況下，`typeof`和`Object.GetType()`就是解決方案。

```csharp
object o = new List<int>();

o is ICollection<int> // true
o.GetType() == typeof(ICollection<int>) // false
o is List<int> // true
o.GetType() == typeof(List<int>) // true
```
