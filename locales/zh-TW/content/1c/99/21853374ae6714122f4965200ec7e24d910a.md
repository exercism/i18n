# 關於

[`interfaces`][interfaces]是將類別的使用與其實作[解耦][wiki-loose-coupling]的主要手段。這種解耦為實作的維護提供了彈性，也有助於支援型別安全的泛型行為。

介面的語法與類別或結構相似，差別在於方法與屬性只以簽章的形式出現，不提供主體。

```csharp
public interface ILanguage
{
    string Speak();
}

public interface IItalianLanguage : ILanguage
{
    string Speak();
    string SpeakItalian();
}

public interface IScriptConverter
{
    string Version { get; set; }
    string ConvertCyrillicToLatin(string cyrillic);
}
```

實作介面的類別或結構，必須實作介面所定義的所有操作。

介面通常會達成下列一項或多項目的：

- 讓使用端程式碼能以泛型方式處理多個不同的類別。此時介面扮演的角色與基底類別相同
- 只針對特定用途（例如 [`IComparable<T>`][icomparable]）公開一部分功能，或
- 公開類別的公開 API，讓多種實作可以並存。其中一個例子是[測試替身][wiki-test-double]

```csharp
public class ItalianTraveller : IItalianLanguage
{
    public string Speak()
    {
        return "Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class ItalianTravellerV2 : IItalianLanguage
{
    public string Speak()
    {
        return "migliorata - Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class FrenchTraveller : ILanguage
{
    public string Speak()
    {
        return "Ça va?";
    }
}

public class RussianTraveller : ILanguage, IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Speak()
    {
        return "Привет мир";
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}

public class DocumentTranslator : IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Translate(string russian)
    {
        throw new NotImplementedException();
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}
```

使用上述介面與類別的程式碼可以：

- 以相同方式處理所有說話者，不論其語言為何。
- 讓負責處理文字轉換的某個子系統運作時，不必在意它處理的是哪些具體型別。
- 對義大利語說話者的變更毫不知情，這在類別程式碼與使用者程式碼由不同團隊維護時很方便。

介面廣泛用於支援測試，因為它們讓[模擬][so-mocking-interfaces]變得容易。

關於介面可以包含哪些型別的成員，詳見這篇[文章][dt-interfaces]。

介面可以繼承其他介面。

介面成員預設為公開。

介面可以包含巢狀型別，例如 `const`常值、`enums`、`delegates`、`classes`和`structs`。在這裡，介面就像類別與結構一樣，扮演[命名空間][wiki-namespaces]的角色，行為與語法完全相同。

就設計上而言，C# 不支援多重繼承，但透過介面提供了某種類似多重繼承的機制。

此外，[多型可以透過介面實作][interface-polymorphism]這個概念，正是介面機制的基礎。

## 明確介面實作

有時兩個不同的介面會共用相同的方法名稱與簽章。為了提供這些方法各自不同的實作，C# 提供了[介面的明確實作][explicit-implementation]。請注意，若要使用介面的特定實作，你需要將參考該物件的運算式轉換成該介面。透過指定、轉型或當作參數傳遞，都能達到這個目的。

```csharp
public interface IFoo
{
    void X();
}

public interface IBar
{
    void X();
}

public class Census : IFoo, IBar
{
    void IFoo.X()
    {
        Console.Write("This is from Foo");
    }

    void IBar.X()
    {
        Console.Write("This is from Bar");
    }
}

public class User
{
    public void Use()
    {
        IFoo foo = new Census();
        IBar bar = new Census();
        foo.X();
        // => "This is from Foo"
        bar.X();
        // => "This is from Bar"
    }
}
```

常見的使用情境有幾種：

- 領域衝突（如上例所示），此時方法具有完全相同的簽章。
- 方法名稱相同但回傳型別不同：如果你自行實作集合類別，可能會發現需要為舊版的 `IEnumerable.GetEnumerator()` 另外提供明確介面，與 `IEnumerable<T>.GetEnuerator()`並存。你可能永遠不會用到這樣的介面，但編譯器可能會堅持要求。
- 介面之間沒有名稱衝突，但實作的類別適合用該名稱來處理某個相關用途：`IFormattable`有一個`ToString()`方法，除了接受型別為 `IFormatProvider` 的參數之外，還接受一個_格式型別_參數。像是基底類別庫（BCL）中的 `FormattableString` 這類類別，就具有這個介面，以確保它能被接受`IFormattable`的常式使用；但它的主要 `ToString(IFormatProvider)` 版本省略_格式型別_參數會更具表達力，因為該參數在實作中用不到，留著反而會讓 API 使用者感到困惑。

## 預設實作

C# 8 版處理了 API 一個長久以來的惱人問題。如果你為了讓新實作擁有更多功能而在介面中加入方法，就必須修改介面所有現有的實作，讓它們符合 API 合約，即使它們並沒有實作特定的行為。現在 C# 允許把_預設方法_當作介面的一部分提供（Java 開發者應該很熟悉）。以往發生這類變更時，介面的_第 2 版_會與原始版本並存。

這篇[文章][dt-interfaces]是介面的絕佳入門，著重於_預設實作_以及其他輔助性的創新，例如 `static`、`private`和`virtual`成員。
