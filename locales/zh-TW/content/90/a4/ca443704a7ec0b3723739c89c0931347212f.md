# 關於註解

Go 有一套[很棒的指南](https://golang.org/doc/effective_go.html)，說明如何撰寫註解。文件註解有標準格式可以遵循，`godoc` 工具能自動把它變成漂亮的說明文件。

套件註解應該以`Package`這個字開頭，後面接著套件名稱，像這樣：

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

對於匯出的函式、方法、常數以及套件變數，註解應該以名稱開頭，接著用動詞片語說明：

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

[CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences) 的 wiki 進一步指出，文件註解應該是完整的句子，並以句號結尾。

遵循這些建議除了能提升可讀性，也能讓你的程式碼在 [Go 的說明文件工具](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/)（例如 [godoc.org](http://godoc.org)、`godoc` 和 `go doc`）中看起來更好。

不妨花點時間讀一讀官方風格指南 [Effective Go](https://golang.org/doc/effective_go.html) 裡關於文件註解的章節，了解這些選擇背後的理由。
