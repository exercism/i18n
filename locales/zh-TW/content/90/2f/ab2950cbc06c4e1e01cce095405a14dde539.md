# 合約

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| 子句 | 說明 | 違反時是誰的錯 |
| --- | --- | --- |
| `pre` | 進入時必須成立的條件 | 呼叫方的 |
| `post` | 回傳時成立的條件 | 常式的 |

兩者都接受一個`BOOL`，也都可以使用常式的引數和物件的屬性。`post`還可以使用`result`，也就是即將回傳的值。

## assert

在常式主體內，`assert`表示在該處必須成立的事情：

```sather
      assert load <= limit;
```

它與其他子句一樣，由同一個開關控制。

## 類別不變式

一個類別可以宣告一件在呼叫之間對它的每個物件都成立的事：

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

當檢查開啟時，會在進入與離開每個公開常式時檢查。

## 開啟檢查

| 旗標 | 檢查項目 |
| --- | --- |
| `-chk` | 全部：pre、post、assert、invariant、邊界、算術 |
| `-chk_no` | 都不檢查 |

請注意，在這個編譯器中，單獨使用`-chk_pre`*並不會*開啟前置條件檢查，真正有效的是`-chk`。違反時會印出常式和原始碼行，並停止程式。它不是例外，`protect`也攔截不到它。

一般的做法是開發與測試時使用`-chk`，出貨時關掉，這樣檢查在出貨的程式中不占任何成本。但這只有在測試真的走過那些路徑時才划算。

## 什麼樣的合約才算好

說明常式需要什麼，而不是它怎麼運作：

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

只是把主體重述一遍的`post`，對誰都沒有幫助：

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## 繼承

子型別可以放寬`pre`、加強`post`，也就是接受更多、承諾更多，但絕不能反過來，否則針對父型別撰寫的程式碼就會失效。合約存在的目的，就是要讓這條規則可以被檢查。
