# 操作說明

基本的 Take-A-Number 取號機賣得非常好，但有些使用者抱怨，比起市面上其他機型，它少了進階功能。

製造商聽取了使用者的意見回饋，決定推出一款功能更多的豪華版機型，而你又再次負責撰寫這台機器的軟體。

豪華版新增的功能包括：
- 記錄目前排隊中的號碼。
- 設定號碼的下限與上限。這樣就能在同一機構內使用多台豪華版 Take-A-Number 取號機，為不同部門的顧客取號，並透過號碼範圍區分不同部門。
- 允許特定號碼跳過排隊，為孕婦和長者提供優先服務。
- 自動關機，避免不小心讓機器開著整個週末而浪費能源。

這台機器的商業邏輯已經由你的同事實作完成，可以在 `TakeANumberDeluxe.State` 模組裡找到。現在你的任務是用 `GenServer` 把它包裝起來。

## 1. 啟動機器

在 `TakeANumberDeluxe` 模組中使用 `GenServer` 行為。

實作 `start_link/1` 函式以及所需的 `GenServer` 回呼。

傳給 `start_link/1` 的引數是一個關鍵字清單，裡面包含 `:min_number` 和 `:max_number` 這兩個鍵。這些鍵對應的值需要傳給 `TakeANumberDeluxe.State.new/2` 函式。

如果 `TakeANumberDeluxe.State.new/2` 回傳 `{:ok, state}` 元組，機器就應該啟動，並以回傳的狀態作為自身的狀態。如果它回傳的是 `{:error, error}` 元組，機器就應該停止，並以回傳的錯誤作為停止的原因。

```elixir
TakeANumberDeluxe.start_link(min_number: 1, max_number: 9)
# => {:ok, #PID<0.174.0>}

TakeANumberDeluxe.start_link(min_number: 9, max_number: 1)
# => {:error, :invalid_configuration}
```

你可能已經注意到，`TakeANumberDeluxe.State.new/2` 函式還接受一個選用的第三個引數 `auto_shutdown_timeout`。我們會在這個練習的最後一個步驟用到它。

## 2. 回報機器狀態

實作 `report_state/1` 函式以及所需的 `GenServer` 回呼。機器應該以目前的狀態回覆呼叫方。

```elixir
{:ok, machine} = TakeANumberDeluxe.start_link(min_number: 1, max_number: 10)
TakeANumberDeluxe.report_state(machine)
# => %TakeANumberDeluxe.State{
#      max_number: 10,
#      min_number: 1,
#      queue: %TakeANumberDeluxe.Queue{in: [], out: []},
#      auto_shutdown_timeout: :infinity,
#    }
```

## 3. 將新號碼排入佇列

實作 `queue_new_number/1` 函式以及所需的 `GenServer` 回呼。

它應該以機器目前的狀態呼叫 `TakeANumberDeluxe.State.queue_new_number/1` 函式。

如果 `TakeANumberDeluxe.State.queue_new_number/1` 回傳 `{:ok, new_number, new_state}` 元組，機器應該以新號碼回覆呼叫方，並把新狀態設為自身的狀態。如果它回傳的是 `{:error, error}` 元組，機器應該以該錯誤回覆呼叫方，並且不改變自身的狀態。

```elixir
{:ok, machine} = TakeANumberDeluxe.start_link(min_number: 1, max_number: 2)
TakeANumberDeluxe.queue_new_number(machine)
# => {:ok, 1}

TakeANumberDeluxe.queue_new_number(machine)
# => {:ok, 2}

TakeANumberDeluxe.queue_new_number(machine)
# => {:error, :all_possible_numbers_are_in_use}
```

## 4. 服務下一個排隊號碼

實作 `serve_next_queued_number/2` 函式以及所需的 `GenServer` 回呼。

它應該呼叫 `TakeANumberDeluxe.State.serve_next_queued_number/2` 函式，並傳入機器目前的狀態和它第二個選用引數 `priority_number`。

如果 `TakeANumberDeluxe.State.serve_next_queued_number/2` 回傳 `{:ok, next_number, new_state}` 元組，機器應該以下一個號碼回覆呼叫方，並把新狀態設為自身的狀態。如果它回傳的是 `{:error, error}` 元組，機器應該以該錯誤回覆呼叫方，並且不改變自身的狀態。

```elixir
{:ok, machine} = TakeANumberDeluxe.start_link(min_number: 1, max_number: 10)
TakeANumberDeluxe.queue_new_number(machine)
# => {:ok, 1}

TakeANumberDeluxe.serve_next_queued_number(machine)
# => {:ok, 1}

TakeANumberDeluxe.serve_next_queued_number(machine)
# => {:error, :empty_queue}
```

## 5. 重設狀態

實作 `reset_state/1` 函式以及所需的 `GenServer` 回呼。

它應該呼叫 `TakeANumberDeluxe.State.new/2` 函式，用目前狀態的 `min_number` 和 `max_number` 建立一個新狀態。機器應該把新狀態設為自身的狀態，但不回覆呼叫方。

```elixir
{:ok, machine} = TakeANumberDeluxe.start_link(min_number: 1, max_number: 10)

TakeANumberDeluxe.reset_state(machine)
# => :ok
```

## 6. 實作自動關機

調整啟動機器的部分。它應該讀取以 `init_arg` 傳入的關鍵字清單中 `:auto_shutdown_timeout` 這個鍵的值，並將它作為第三個引數傳給 `TakeANumberDeluxe.State.new/3`。如果沒有提供 `:auto_shutdown_timeout`，就使用預設值 `:infinity`。

調整重設機器狀態的部分，讓它也會把 `auto_shutdown_timeout` 傳給 `TakeANumberDeluxe.State.new/3`。

調整所有已實作回呼（`init/1` 以及所有 `handle_*` 回呼）的回傳值，替它們設定逾時。請使用目前機器狀態中 `:auto_shutdown_timeout` 這個鍵的值。不要把逾時加到 `init/1` 的 `{:stop, reason}` 回傳值上。逾時只有在伺服器開始執行它的接收迴圈之後才適用。

實作一個 `GenServer` 回呼來處理 `:timeout` 訊息，當機器在指定的逾時時間內沒有收到其他訊息時，就會收到這個訊息。它應該以 `:normal` 為原因結束行程。

也別忘了處理任何非預期的訊息，忽略它們就好。

```elixir
{:ok, machine} =
  TakeANumberDeluxe.start_link(
    min_number: 1,
    max_number: 10,
    auto_shutdown_timeout: :timer.hours(2)
  )

# after 3 hours...

TakeANumberDeluxe.queue_new_number(machine)
# => ** (exit) exited in: GenServer.call(#PID<0.171.0>, :queue_new_number, 5000)
#        ** (EXIT) no process: the process is not alive or there's no process currently associated with the given name, possibly because its application isn't started
#       (elixir 1.13.0) lib/gen_server.ex:1030: GenServer.call/3
```
