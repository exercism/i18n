# 關於

如同[`Nothingness`][concept-nothingness]概念中所探討的，R 有各種方式來表示不存在（[`NULL`][ref-null]）、未知（[`NA`][ref-na]）或數學上無效（[`NaN`][ref-finite]、[`Inf`][ref-finite]）的資料。
一般來說，R 會試著用這些值就地標記出問題，然後繼續執行，而不引發例外。

## `stop()`

有些問題太過根本，無法讓程式繼續執行下去。
在這種情況下，可以用[`stop(msg)`][ref-stop]立刻中止程式，並附上一個 `Error` 並印出 `msg`。

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

類似於其他語言中的[`assert`][wiki-assert]，[`stopifnot()`][ref-stopifnot]是 `stop()` 的便利包裝。
它的引數是任意數量的布林條件，以逗號分隔，唯有全部為`TRUE`時程式才會繼續執行。

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R 有各種處理錯誤的方式。
這些機制以 Common Lisp 為基礎，和許多熱門語言的做法有明顯差異。

最簡單的方式，是把可能出問題的程式碼包在[`try()`][ref-try]裡。

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning] 和 [`message()`][ref-message]

這些是對非致命狀況的回應，例如：

- 警告程式至少還能部分復原的問題。
- 告知使用者長時間執行的程式目前的進度。

兩者的一個差異是：警告會被快取，並（預設）在函式回傳時才輸出，而訊息則是立即輸出。
改變預設行為的方法有很多，這裡不多談。

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

在 Exercism 上，[`suppressWarnings()`][ref-warning]函式偶爾會很有用，可以避免不必要的輸出讓測試執行器產生混淆。
