# 浮點數

`FLTD`儲存的數字可以帶有小數部分。字面值需要有小數點和一個`d`：

```sather
   440.0d
   0.5d
   -2.25d
```

`FLT`是同樣的概念，精度只有一半。這個軌道全篇使用`FLTD`；除非記憶體吃緊，否則沒有理由動用`FLT`。

## 算術

| 運算子 | 意義 |
| --- | --- |
| `+` `-` `*` | 與`INT`相同 |
| `/` | 除法，保留小數部分 |

`FLTD`沒有`%`運算子。

兩個運算元都必須是`FLTD`。混入`INT`會造成編譯錯誤，而不是默默轉型，這其實是好事：唯一會出問題的地方，正是大家最容易弄錯的地方。

## 轉換

```sather
   7.fltd            -- 7.0, an INT made into an FLTD
   7.5d.int          -- 7, the fraction thrown away
   7.5d.round        -- 8, to the nearest whole number
   7.5d.floor        -- 7.0, down to a whole number
   7.5d.ceiling      -- 8.0, up to a whole number
```

除法之前就要轉換，不要等做完才轉：`n.fltd / 2.0d`會保留那一半，`(n / 2).fltd`則早就把它丟掉了。

## 實用常式

```sather
   (-2.5d).abs       -- 2.5
   2.0d.sqrt         -- 1.41421
   (2.0d).max(3.0d)  -- 3.0
```

## 浮點數是近似的

`FLTD`儲存的是非常接近的近似值，而不是精確的值。大多數十進位小數都無法精確儲存，就像三分之一無法用十進位精確寫出來一樣。所以：

```sather
0.1d + 0.2d          -- very nearly 0.3, but not exactly
```

有兩點值得記住：

**不要用`=`比較。** 兩個理論上結果相同的計算，往往會在最後幾位數出現差異。改用「是否夠接近」來判斷：

```sather
   (a - b).abs < 0.0001d
```

**把許多小數值相加會損失精確度。** 每一次相加都會稍微四捨五入，誤差便逐漸累積。

當數值必須精確時（尤其是金錢），改用`INT`以整數單位來計算（例如用「分」而不是「元」）。

## 列印

`.str`大約顯示六位有效數字，少於實際保有的精確度：

```sather
   #OUT + (1.0d / 3.0d).str;      -- 0.333333
```
