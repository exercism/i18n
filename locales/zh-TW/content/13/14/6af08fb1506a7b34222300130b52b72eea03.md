```exercism/note
撇開這段搞笑的故事不談，這個練習的需求直接取自 GitHub 的 REST API 中，用來處理 Pull Request 審查留言的端點。
```

## 1. 請給我 ID！

你銳利的目光已經發現，留言和使用者都有一個 `id` 欄位，這正是最好的起點。

定義 `decodeId`，讓它能解碼帶有整數 `id` 的 JSON 物件。

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. 我叫什麼名字去了？

你注意到上面的範例中，並非所有使用者都有名字。

定義 `decodeName`，讓它能在有 `name` 欄位時解碼出其中的字串。
沒有名字？沒問題，直接回傳 `Nothing` 就好。
這個解碼器永遠不該失敗。

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. 使用者？我跟他可不熟！

解碼使用者的部分我們大致完成一半了，把它做到底吧。

定義 `decodeUser`，讓它能解碼 JSON 的使用者物件。
請務必在 `decodeUser` 裡使用 `decodeId` 和 `decodeName`。

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. 我是堅強又獨立的留言

Pull Request 審查中有些留言是獨立存在的，因此沒有 `pull_request_review_id`。
不過規格提到，這種情況下仍然應該要有 `pull_request_review_id` 欄位，只是值應該是 `null`，也就是窮人版的 `Nothing`。

定義 `decodePullRequestReviewId`，讓它能在 `pull_request_review_id` 欄位中有整數時解碼出該整數。
如果沒有整數，就應該要有 `null`；如果連 `null` 都沒有，解碼器就應該失敗。

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. 斜槓副業

接下來是看起來很有意思的 `side` 欄位。
在 Pull Request 審查中，你可以對被移除的程式碼（畫面上的 `Left` 側）留言，也可以對新增的程式碼（畫面上的 `Right` 側）留言。

定義 `decodeSide`，讓它能解碼 `side` 欄位中的 `"LEFT"` 或 `"RIGHT"`，並對應到相應的型別變體。

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. 連結甦醒

每個留言都有一組連結，而這些連結在不同留言之間似乎並不一致。

定義 `decodeLinks`，讓它能解碼 `_links` 欄位中的一組 URL。
連結的名稱和數量都可能不同，請確保你能處理這種情況。
這些連結本身是 JSON 物件，裡面一定會有 `href` 欄位。

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. 沒錯，就是留言

就快完成了，把它做完吧。

定義 `decodeComment` 和 `decodeComments`，讓它們分別能解碼單一的 JSON 留言物件和留言陣列。
請務必在 `decodeComment` 裡用到目前為止定義的所有函式，但 `decodeName` 除外。
當然，`decodeComments` 也應該使用 `decodeComment`。

## 8. 全部串起來

這整件事還缺一個功能：能夠把新的留言送到伺服器。
為此，你需要做出解碼器的相反，也就是能把 Elm 的 `Comment` 轉換成 JSON 的 `Value`。

定義 `encodeComment`，讓它能編碼任何有效的 `Comment`。
欄位的順序無所謂，只要編碼器產生的值能被 `decodeComment` 解碼就行。
