# 關於

## 部分應用

Elm 中所有的函式都是[柯里化][currying]的，這表示如果你呼叫函式時沒有傳入所有引數，它就會回傳一個新的函式。

這樣做的結果稱為[部分應用][partial-application]（你並沒有將所有引數都傳入函式，而是只套用了其中一部分）。

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

部分應用一律會依序套用引數。

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## 管線運算子（`|>`）

寫`x |> f`和寫`f x`完全一樣。具體的例子是，`"5" |> String.toInt`和`String.toInt "5"`相同。

這聽起來一開始不太有用，但它之所以叫做[管線運算子][pipe-operator]，是因為它能讓你寫出「管線化」的程式碼。

舉例來說，假設我們有一個 sanitize 函式，用來把使用者的輸入轉成整數：

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

我們可以把它改寫成這樣：

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

這樣可以避開括號，並且依照函式套用的順序呈現（先是`String.trim`，再來是`String.toInt`），有助於閱讀。

另外還有[反向管線運算子`(<|)`][reverse-pipe-operator]。
寫`x <| f`和寫`f x`完全一樣。
乍看之下它也不太有用，使用頻率也絕對比不上管線運算子，但在某些情況下能幫你避開括號。

## 函式組合 / 無點風格

[`(>>)`][forward-composition]運算子的型別是`(a -> b) -> (b -> c) -> (a -> c)`，它會組合兩個型別相容、分別為`a -> b `和`b -> c`的函式，產生一個型別為`a -> c`的函式。
它的做法是取得第一個函式的輸出（型別為`b`），並把它當成第二個函式的第一個引數（後者的型別必須同為`b`）。
產生的函式會接收和第一個函式相同的輸入（型別為`a`），並回傳第二個函式所回傳的`c`。

具體的例子是`String.trim >> String.toInt`。
`String.trim`以字串作為它唯一的參數，所以產生的函式也接收字串。
`String.toInt`回傳`Maybe Int`，所以產生的函式也回傳`Maybe Int`。
`String.trim`回傳`String`，而`String.toInt`接受`String`作為參數，所以這個例子可以編譯。

現在我們可以把`sanitize`函式改寫成這樣：

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

注意，雖然功能完全相同，我們不再使用你在原始範例中看到的`input`參數。
這種建立函式、完全不提及參數的方式稱為「無點風格」。
這種風格的好處是程式碼更精簡，缺點是可能較難理解，尤其對初學者而言。

值得一提的是，Elm 中所有函式都是柯里化的，所以`String.length >> max`可以編譯，結果如下：

- 一個函式（1），它有一個字串參數（`String.length`的輸入）
- `max`是一個有兩個`Int`參數的函式，但函式 1 只傳入單一個`Int`給它（`String.length`的回傳值），所以`max`被部分套用。
- 部分套用後的`max`函式，其回傳值是另一個函式（2），它接收一個`Int`，並回傳這個`Int`與從`String.length`部分套用而來的那個`Int`當中較大者。
- 因此函式 1（`String -> Int`）回傳函式 2（`Int -> Int`）
- 所以`((String.length >> max) "123") 2`會回傳`3`，因為`"123"`的長度是 3，比來自`Int`引數的 2 還大。

## 函式設計

為了在 Elm 中輕鬆寫出優雅的程式碼，你應該把主要的資料結構放在函式的最後一個參數。
標準函式庫中所有常見的函式都這麼做，例如`List.map`（型別簽章如下）。

```elm
map : (a -> b) -> List a -> List b
```

這裡可以看到`map`函式的最後一個參數是`List a`，而它回傳`List b`，所以主要的資料結構（`List`）是最後一個參數。

這讓你能寫出優雅的管線化程式碼，如下所示。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

這也讓函式組合與無點風格變得方便，可以取代管線化的寫法。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

函式組合還能讓你這個例子化簡成單一次對`List.map`的呼叫。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
