# 簡介

Julia 和大多數程式語言一樣，提供了豐富多樣的集合型別。

有些集合天生就有序（包括`Vectors`和更高維度的`Arrays`），所以我們可以依位置存取元素。
其他的集合則沒有順序（`Sets`、`Dicts`），必須用鍵或值來存取元素。

最簡單的情況，假設我們有一個裝著`Ints`的`Vector`，想把它依遞增順序排序。

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

很簡單吧！
`sort()`這個函式的名字很直白，看起來會回傳排序好的`Vector`。

_開玩笑的！_
學到課程大綱的這個階段，你或許已經猜到（而且猜對了），這裡面有些細節值得我們討論。

## 會變更與不會變更的函式

執行`sort(v)`之後，`v`是什麼？

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

原始的向量並沒有被改變。
`sort()`是***不會變更***的函式，它回傳的是輸入的_複本_。

在許多情況下這是很好的設計：我們有一個[純函式][wiki-pure-func]，它的行為很容易推理，即使是在平行、分散式的程式碼裡也一樣。

另一方面，假設我們有一個十億個字串的陣列，想把它排序。

排序大概會很慢。
除此之外，我們還得複製所有東西（_很慢！_），並配置足夠的記憶體（_好幾 GB！_）來存放這份複本。

對照一下這段很類似的程式碼：

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

現在輸入的`Vector`是原地排序，沒有複製，而原本的順序也永久遺失了。

這樣可以很有效率，也可能會有 bug、導致意料之外的副作用，還可能讓其他閱讀你程式碼的人一頭霧水。
_請小心選擇喔！_

`sort!()`是「會變更的函式」，而且依照（_非常強烈的_）慣例，任何會變更輸入的函式都會在名字後面加上`!`，用來提醒寫程式的人。

## 依什麼排序？

排序`Int64`的值相對簡單：連小孩子都知道 2 比 1 大、比 3 小。

其他型別可能更複雜，但一般來說，如果`isless(x, y) == true`，則`x < y`。
Julia 為大多數標準型別都提供了`isless()`的實作。

例如，Unicode 字元（對歐洲字母來說，大寫會排在小寫前面）：

```julia-repl
julia> j = collect("Julia")
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)

julia> sort(j)
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0false069 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
```

我們也可以在排序前，對每個項目套用任意的函式，例如用`abs`忽略正負號，或用`uppercase`做不分大小寫的排序：

```julia-repl
julia> nums = [3, -2, -4, 1]
4-element Vector{Int64}:
  3
 -2
 -4
  1

julia> sort(nums)
4-element Vector{Int64}:
 -4
 -2
  1
  3

julia> sort(nums, by=abs)
4-element Vector{Int64}:
  1
 -2
  3
 -4

# j is from "Julia", as previously

julia> sort(j, by=uppercase)
5-element Vector{Char}:
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)

julia> vecs = [[1, 3], [4, 2], [3, 4], [2, 1]];

julia> sort(vecs)  # by default sorts by the first element of the (2-element) vectors
4-element Vector{Vector{Int64}}:
 [1, 3]
 [2, 1]
 [3, 4]
 [4, 2]

julia> sort(vecs, by=last)
4-element Vector{Vector{Int64}}:
 [2, 1]
 [4, 2]
 [1, 3]
 [3, 4]
```

## 排序索引陣列

如果要排序的元素是很大的物件，改用它們的位置索引來處理可能更容易。

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

因為`langs`是 Vector，所以每個索引都是[範圍][concept-range]`1:length(langs)`裡的整數。
`sortperm()`的輸出是這些整數的一個[排列][wiki-permutation]，對應到輸入向量的排序結果。

## 部分排序

你的程式需要把整個輸入都排序嗎？
如果只有前幾筆或後幾筆項目值得關注，做一次[部分排序][wiki-partial-sort]可能會快上許多。

Julia 提供了`partialsort()`和`partialsort!()`函式，它們保證指定的那一筆項目或那段範圍的項目是正確的，但對輸入剩下的部分則不做任何保證。

第二個引數可以是整數或範圍，代表排序後輸入的索引：

```julia-repl
julia> vsq = [9, 4, 16, 1];  # would be [1, 4, 9, 16] after a full sort

julia> partialsort(vsq, 4)
16

julia> partialsort(vsq, 2:3)
2-element view(::Vector{Int64}, 2:3) with eltype Int64:
 4
 9
```
