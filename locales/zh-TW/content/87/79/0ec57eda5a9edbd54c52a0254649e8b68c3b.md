# 指令補充

## `from_quote`的優點與缺點

這個練習在`Time`型別中定義了一個`from_quote`函式。如此一來，就能寫出像這樣的程式碼：

```roc
time : Time
time = "00:01:23"
```

這段程式碼會在編譯期隱式呼叫`Time.from_quote("00:01:23")`。這可能讓程式跑得更快，因為它不需要在執行期處理解析，而且能確保被`from_quote`拒絕的時間會在編譯期就被攔下，而不是拖到執行期。此外，這也讓程式碼既美觀又好讀。舉例來說，以下是這個練習的其中一個測試：

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

不過，閱讀這段程式碼的人可能會以為`advance_time`函式接受的是`Str`，但實際上它接受的是`Time`。這可能造成混淆和錯誤。因此，你可能會更喜歡稍微長一點、但更明確的寫法：`"00:00:05".Time`，它同樣會在編譯期呼叫`from_quote`。

在你自己的程式裡，你可能會偏好改用`from_str`：

```roc
Time := { ... }.{
    from_str : time_str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

你也可以在編譯期呼叫`from_str`（或任何其他純函式），像這樣：

```roc
Ok(time) = Time.from_str("00:01:23")
```

注意：把這個定義放在最上層，會讓它在編譯期執行（因為這個函式是純函式，而且它的輸入在編譯期就已知）。在函式內部，你可以在執行期使用`from_str`。
