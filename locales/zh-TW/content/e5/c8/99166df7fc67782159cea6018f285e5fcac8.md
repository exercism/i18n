# 關於

連結性（linkage）描述程式碼中的識別字可以從哪裡被存取。
具有區塊、函式或函式原型作用域的值沒有連結性。
這表示它們無法從其作用域之外被存取。
關於作用域的更多說明，請參閱[作用域概念](../scope/introduction.md#Introduction)。

## 外部連結性

具有檔案作用域的識別字預設具有外部連結性。
具有外部連結性的識別字可以從程式中的任何檔案被呼叫。

## 內部連結性

具有檔案作用域的識別字可以透過 `static` 修飾詞使其具有內部連結性。
具有內部連結性的識別字只能在其所屬的檔案內使用。

例如

```c
int public_count = 0; // file scope, external linkage by default
static int private_count = 0;  // file scope, internal linkage 

// file scope, internal linkage
static void some_function()
{
    // code snipped
}

// file scope, external linkage by default
int main()
{
    // code snipped
}
```

靜態連結性不應與靜態儲存持續時間混為一談。
關於靜態儲存持續時間的更多說明，請參閱[儲存持續時間概念](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#static-the-storage-class-specifier-not-to-be-confused-with-the-static-linkage-type)。

如果某個值（而非函式）在標頭檔中宣告，但在原始檔中定義為帶有初始值的 `static` 檔案作用域識別字，那麼它的初始值將無法從其所屬的原始檔之外存取。
這可能可以編譯、連結並執行而不發生錯誤，但該值會是該識別字的零值，即使該值是以 `extern` 宣告也一樣。
（關於 `extern` 的更多說明，請參閱 [`extern` 概念](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#extern-how-to-access-a-variable-in-another-translation-unit)。）
在原始檔中標記為 `static` 的檔案作用域識別字不應在其標頭檔中宣告。
