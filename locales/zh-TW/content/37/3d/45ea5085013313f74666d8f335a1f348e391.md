# 簡介

在程式中定義自訂型別通常很實用。

建立新的基本型別雖然做得到，但很少人這麼做。
內建的基本型別並非隨便挑選的：它們與 Julia 用來進行 JIT 編譯的 LLVM 編譯器中的標準型別緊密相符。

更有用的是能夠定義帶有具名欄位的複合型別。

其他語言也有類似的東西，稱之為 `structs` 或 `records`。
Julia 的文件把它們稱為 `composite types`，不過（有那麼一點不一致的是）語言語法是用`struct`關鍵字來定義它們。

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

上面的例子有幾點值得注意：

- 沒有為`id`指定型別，所以編譯器會把它解讀成`id::Any`。
- 型別名稱可以當作建構子使用，例如`Person(id, name, age)`會產生一個型別為`Person`的實例。
- 個別欄位可以用點記法存取，和具名元組一樣。

`Person`型別的項目是不可變的，因此不允許更新。

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

如果需要可變性，就在定義中加上`mutable`。

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

建構子預設要求欄位的排列順序與定義時相同，這在型別比較複雜時會變得不方便。

使用`@kwdef`巨集可以帶來兩項新能力：

- 建構子改用關鍵字，而不是位置。
- 欄位可以有預設值，而且可以選擇在建構子中省略。

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## 複合型別的階層

到目前為止，我們只建立了具體的複合型別。
如果你檢查一下，會發現它們全都是`Any`的子型別。

當你要建立多個相關的型別時，為它們定義一個階層通常更合理。
這做起來非常簡單。

首先，建立一個抽象型別：

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

接著，在型別定義中加入`<:`運算子，來表示彼此的關係。

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

視需要重複這個做法，並記住不允許對具體型別做子型別化。

如果需要更複雜的階層，就視需要建立抽象子型別。

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

等我們之後學到`Multiple Dispatch`概念，看到函式如何處理引數型別時，就會更清楚這種階層的價值。
