# Nil

Crystal 有一種叫做[`Nil`][nil]的型別，它只能有一個值：`nil`。
它用來表示值不存在的情況，類似於其他語言中的 `null` 或 `None`。

`nil` 值可以由各種方法回傳，例如[`String#[]?`][string-index]，當索引超出範圍時會回傳 `nil`。

```crystal
"foo"[10]? # => nil
```

Crystal 有所謂的**空參考檢查**，也就是說所有型別預設都不能是`nil`。
這表示除非你明確地把它宣告成 `Nil` 型別，否則不能把 `nil` 指定給變數。
因此，編譯器會自動檢查空參考。

## 假值

處理 `nil` 值有幾種做法。
`nil` 和 `false` 一樣都是[假值][truthy-falsey]。
這表示在敘述以及其他需要真值或假值的地方，它都會被當成 `false` 來處理。

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

這表示如果一個可為 `nil` 的變數值是`nil`，就不會進入為真的分支。

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## 檢查是否為 nil

Crystal 有一個方法可以用來檢查某個值是否為`nil`。
它叫做[`nil?`][nil?]，所有物件都可以使用。

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

直接把值用在 `if` 敘述裡，情況會有點不同，因為在前面的範例中，`false` 和 `nil` 都會被視為假。
在這裡只有 `nil` 會被視為假值：如果它其實是 `false`，就不會是 `nil`，因此也就會是真值。

## or 運算子

處理 `nil` 值最簡單的方法，就是從一開始就確保它們不會變成`nil`。
or 運算子（[`||`][or]）經常用來處理 `Bools`，但只要理解正確，它也可以用來處理 `nil` 值。
or 運算子會檢查第一個值是否為真，如果不是，就使用第二個值。
這樣一來，如果值是`nil`，它就是假值，因此會使用第二個值。

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
這種做法應該視為最後手段，只有在**確定**值不是 nil 時才能使用。
如果可行的話，請改用其他做法。
~~~~

[`not_nil!`][not_nil] 是一個方法，讓你可以告訴編譯器某個值不是 nil，藉此讓它持有的型別不能是 nil。
它的做法是：如果值是 nil，就引發例外。

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
