# 簡介

如同大多數程式語言，Julia 提供了豐富多樣的集合型別。

有些集合天生就有順序（包括`Vectors`和更高維度的`Arrays`），因此我們可以依位置存取元素。
其他集合則是無序的（`Sets`、`Dicts`），元素必須透過鍵或值來存取。

最簡單的情況是，假設我們有一個由`Ints`組成的`Vector`，並想將它依遞增順序排序。

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

很簡單！
`sort()`這個函式的名稱淺顯易懂，而且看起來會回傳排序好的`Vector`。

_開玩笑的！_
學到課程大綱的這個階段，你或許已經（正確地）猜到，有些細節值得我們好好討論。

## 會修改與不會修改的函式

執行`sort(v)`之後，`v`會變成什麼？

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

原本的向量並沒有改變。
`sort()`是一個***不會修改***輸入的函式，它會回傳輸入的_副本_。

在許多情境下這是個好設計：我們有一個純函式，行為很容易推斷，即使在平行、分散式的程式碼中也是如此。

另一方面，假設我們有一個包含十億個字串的陣列，並想將它排序。

排序大概會很慢。
此外，我們還得複製所有內容（_很慢！_），並配置足夠的記憶體（_好幾 GB！_）來存放副本。

比較一下這段很類似的程式碼：

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

現在輸入的`Vector`會就地排序，不需複製，而原本的順序則會永久消失。

這樣做可能很有效率，也可能藏有 bug 並導致意想不到的副作用，還可能讓其他使用你程式碼的人感到困惑。
_請謹慎選擇！_

`sort!()`是「會修改」的函式，而且依照（_非常強烈_）的慣例，任何會修改輸入的函式，名稱後面都會加上`!`，提醒程式設計師注意。

## 排序索引陣列

如果要排序的元素是大型物件，改為操作它們的位置索引可能會更容易。

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

因為`langs`是一個 Vector，每個索引都是落在`1:length(langs)`範圍內的整數。
`sortperm()`的輸出是這些整數的一種排列，對應於輸入向量的排序結果。
