# 關於

`<dlist>`（位於 [`dlists`][dlists]）會建立一條全新的雙向鏈結串列。相關操作住在 [`deques`][deques] 裡，並依據 [雙向佇列協定][deque-protocol] 分派，因此其他容器（主要是 `<dlist>`）也能實作這些操作。

| 詞              | 效果                                |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`，全新的空雙向佇列  |
| `push-front`    | `( elt deque -- )`，加到前端 |
| `push-back`     | `( elt deque -- )`，加到後端  |
| `pop-front`     | `( deque -- elt )`，從前端移除 |
| `pop-back`      | `( deque -- elt )`，從後端移除  |
| `peek-front`    | `( deque -- elt )`，讀取前端但不移除 |
| `peek-back`     | `( deque -- elt )`，讀取後端但不移除  |
| `deque-empty?`  | `( deque -- ? )`，雙向佇列是空的嗎？ |
| `dlist-length`  | `( dlist -- n )`，元素數量 |

所有 push/pop 操作都會就地修改雙向佇列，把雙向佇列交給某個詞、之後再從它讀取值，這是很正常的做法。

## 堆疊與佇列

兩種慣用的分派模式：

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

當你只需要 LIFO 順序時，帶有 `push` 和 `pop`（來自 `mutation`）的向量就是正確的選擇，因為 `<dlist>` 得背負鏈結串列的額外開銷。當你需要*兩端*都是 O(1) 時再動用 `<dlist>`，而這幾乎都是為了 FIFO 佇列。

## BFS 模式

廣度優先搜尋是 FIFO 的典型用法：

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

雙向佇列負責攜帶搜尋前緣，雜湊集合則負責去除重複。把 `pop-front` 換成 `pop-back`，同樣的結構就變成深度優先。

## `MEMO:`：自動快取

有時 BFS 呼叫的每個節點查詢相當耗時。Factor 提供了 [`MEMO:`][memo-decl]，用來取代 `:`，會以詞的輸入為鍵，自動快取其結果：

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

`MEMO:` 詞在第一次看到某組輸入時會執行它的內容，之後就回傳快取的結果。快取會一直存活到 image 結束為止，沒有以時間或大小為依據的淘汰機制。當純函式的輸入來自一個有限、可管理的集合時，就很適合使用它。
