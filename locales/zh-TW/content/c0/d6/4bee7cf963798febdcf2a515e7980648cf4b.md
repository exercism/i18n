# 簡介

手寫的組合語言充滿重複。同一小段指令一再出現，變化不大，而能用來減少樣板碼的抽象化機制也很少。不只如此，用組合語言撰寫程式時，還得在沒有明顯語意的情況下管理各種值。這裡沒有具名的參數，而且底層機制的多數細節都必須由程式設計師手動處理。

NASM 是本課程所使用的組譯器，它提供了一些工具，能同時協助程式設計師處理這兩個問題。這些工具在_組譯時期_執行，也就是在任何指令送到處理器之前。它們會指引組譯器，在原始碼還沒被翻譯成機器碼之前，就先決定該如何改寫原始碼。

這些工具中最重要的是**巨集**，可以把它想成給組譯器的一份食譜。巨集會在使用的位置展開，就好像那段程式碼是手寫在那裡一樣。

巨集可以接受若干字面記號作為參數，讓它們能在不同情境中重複使用。不過，它們不是函式：沒有`call`，沒有`ret`，也不會把控制權轉移到程式碼中的另一個位置。

## 單行巨集

最簡單的定義方式，是用`%define`為某個值或一小段運算式取個名字：

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

之後每次出現`WIDTH`，都會在組譯前被替換成`8`。這種替換是文字上的替換，所以這個名字只要出現就會被取代，不管它是在運算元裡，還是在另一個定義之中。

~~~~exercism/note
對於數值_常數_，請改用`equ`，而不要用`%define`。

用`%define`宣告的單行巨集只在使用時展開，而且可以重新指定或解除定義。
相對地，`equ`常數在定義的當下就會求值，而且永遠不會被修改。
~~~~

`%define`也可以接受_具名_參數，行為就像一個小型的行內函式：

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
請把整個主體以及每個參數都用括號包起來。
若寫成`%define square(x) x*x`，呼叫`square(1+1)`會展開成`1+1*1+1`，結果是`3`。
改寫成`%define square(x) ((x)*(x))`之後，同一個呼叫會展開成`((1+1)*(1+1))`，結果是`4`。
~~~~

用`%define`定義的名稱會區分大小寫。若有需要的話，`%idefine`這個變體可以讓名稱不區分大小寫。

單行巨集很適合用來賦予程式碼中各個部分意義。小心使用的話，能提升可讀性，也能減少打錯字的機會。舉例來說，某個在函式裡有特定用途的暫存器，可以依它的用途來命名：

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## 多行巨集

一整個程式碼序列，不論有幾行，都可以用`%macro`捕捉起來，並以`%endmacro`結束。名稱後面接的數字代表這個巨集接受幾個引數，也可以為 0。傳入引數時，引數之間以逗號（`,`）分隔：

```x86asm
%macro example_macro 0
...
%endmacro
```

多行巨集的引數沒有名稱。它們依照傳入的順序，以`%1`、`%2`這樣的方式來表示：

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

請注意，引數必須是巨集主體中實際執行之運算的合法語法。在這裡，`mult_two eax, ecx`和`mult_two r8, r9`都能組譯，但`mult_two eax, cl`不行，因為`imul eax, cl`並沒有被定義。

### 巨集內的標籤

如果巨集定義了一般標籤，只要被使用 2 次就會出錯，因為那個標籤也會被定義 2 次。若想在可能被呼叫多次的巨集裡使用標籤，就必須在標籤前面加上`%%`。這會指示組譯器在每次展開時，給這個標籤一個不同且唯一的名稱：

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## 在組譯時期重複

可以使用`times`重複單行的程式碼區塊。這在宣告記憶體中重複出現的值時特別有用：

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

如果要重複多行的程式碼，可以改用`%rep`：

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

請注意，重複次數寫在`%rep`的正後面，並用`%endrep`結束重複的區塊。

在`%rep`區塊裡使用組譯時期的計數器很常見，就像執行時期的迴圈會用計數器一樣。組譯時期的整數常數可以用`equ`宣告，但組譯時期的整數_變數_要改用`%assign`。和`%define`不同，`%assign`會立刻求值成一個數字，而且可以重新指定：

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

前置處理器執行完之後，迴圈就消失了，只剩下 4 道`add`指令，其中的立即值`0`、`1`、`2`、`3`都已經直接寫入。這就是由組譯器完成的迴圈展開：沒有計數器暫存器，也沒有分支，只有一路直線執行的程式碼。

## 條件組譯

前置處理器提供了多種條件判斷機制。它們會在多條不同的路徑之間做選擇，並把自身主體就地展開，但只有在條件成立時才會這麼做。

`%if`……`%elif`……`%else`……`%endif`會依數值測試的結果選出一條分支：

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## 拆分到檔案

巨集通常會放在自己的檔案裡，需要它們的每個原始檔再用`%include`把它們拉進來：

```x86asm
%include "patterns.mac"
```

被指名的檔案會在該處、在組譯之前原封不動地插入，就像它的內容原本就被打在那裡一樣。這麼做能讓這些定義集中在一處，也讓多個原始檔共用它們。

如果巨集檔可能會被單獨組譯，就應該使用`.asm`副檔名。請注意，巨集沒有連結性。即使巨集檔被組譯過，它的巨集也只對以`%include`引入它的另一個檔案可見。

否則，只用來被`%include`的檔案可以有任意的副檔名。使用`.asm`或`.mac`都是常見的慣例。
