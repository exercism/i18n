# 簡介

如同[`Nothingness`][concept-nothingness]概念中所探討的，R 有各種方式來表示不存在的資料（`NULL`）、未知的資料（`NA`），或是在數學上無效的資料（`NaN`、`Inf`）。一般來說，R 會試著用這些值就地標示問題，然後繼續執行，不會拋出例外。

## `stop()`

有些問題太過根本，沒辦法讓程式繼續執行下去。遇到這種情況時，請使用`stop(msg)`立即中止程式，產生`Error`並印出`msg`。

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

這類似於其他語言中的`assert`，是`stop()`的便利包裝。它的參數是任意數量、以逗號分隔的布林條件，唯有當它們全部為`TRUE`時，程式才會繼續執行。

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R 有許多處理錯誤的方式。這些方式以 Common Lisp 為基礎，和許多熱門語言有顯著差異。

最簡單的做法，就是把可能出問題的程式碼包進`try()`裡。

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()`和`message()`

這些是對非致命狀況的回應，例如：

- 警告程式至少還能部分復原的問題。
- 讓使用者知道長時間執行的程式目前的進度。

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

在 Exercism 上，`suppressWarnings()`函式有時也能派上用場，可以避免不想要的輸出讓測試執行器混淆。
