# 說明

遙控車專案的開發仍在持續進行。遙測系統的頻寬十分寶貴，因此有人請你實作一套訊息協定，用來傳遞遙測資料。

資料是以緩衝區（位元組陣列）的形式傳輸。傳送整數時，會採用以下所述的協定來縮小緩衝區的大小。

每個值都應該用盡可能最小的整數型別來表示（不包含 `byte` 和 `sbyte` 型別，因為省下的空間微不足道）：

| 從                         | 到                        | 型別     |
| -------------------------- | ------------------------- | -------- |
| 4_294_967_296              | 9_223_372_036_854_775_807 | `long`   |
| 2_147_483_648              | 4_294_967_295             | `uint`   |
| 65_536                     | 2_147_483_647             | `int`    |
| 0                          | 65_535                    | `ushort` |
| -32_768                    | -1                        | `short`  |
| -2_147_483_648             | -32_769                   | `int`    |
| -9_223_372_036_854_775_808 | -2_147_483_649            | `long`   |

這個值應該轉換成其指定型別所對應的位元組數。完整的緩衝區包含一個指出緩衝區中額外位元組數量的位元組（_前綴位元組_），後面接著存放整數的位元組（_資料位元組_）。

有些型別使用的位元組數相同（例如 `uint` 和 `int` 型別）。一般來說，它們會有相同的_前綴位元組_，但這會讓解碼變得麻煩。為了解決這個問題，這套協定用了一個小技巧：對於帶正負號的型別，其_前綴位元組_的值是`256`減去緩衝區中額外位元組的數量。

通訊時只會傳送前綴位元組，以及前綴所指示數量的後續位元組。在內部，傳送和接收的常式都會使用一個 9 位元組的緩衝區（視需要補上尾端的零）。

## 1. 將整數值編碼成可傳送的格式

請實作靜態方法`TelemetryBuffer.ToBuffer()`，將傳入方法的參數編碼成緩衝區。

```csharp
// Type: ushort, bytes: 2, signed: no, prefix byte: 2
TelemetryBuffer.ToBuffer(5)
// => {0x2, 0x5, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0 };

// Type: int, bytes: 4, signed: yes, prefix byte: 256 - 4
TelemetryBuffer.ToBuffer(Int32.MaxValue)
// => {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 };
```

## 2. 解碼接收到的緩衝區

請實作靜態方法`TelemetryBuffer.FromBuffer()`，解碼接收到的緩衝區，並以`long`的形式回傳該值。

```csharp
TelemetryBuffer.FromBuffer(new byte[] {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 })
// => 2147483647
```

如果前綴位元組的值並非預期值，就應該回傳`0`。
