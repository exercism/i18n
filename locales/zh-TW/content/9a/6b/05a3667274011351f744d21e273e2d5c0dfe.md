# 簡介

二進位數字最終直接對應到 CPU 或 RAM 裡的電晶體，也就是每個電晶體是「開」還是「關」。

這種低階操作俗稱「bit-twiddling」，在系統程式語言中特別重要。

像 Kotlin 這樣的高階語言通常會把這些細節抽象掉。不過，仍然有一系列基本的位元運算[可以使用][ref-bitwise]。

## 位移運算

`Int`或`Long`型別，無論有號或無號，都可以表示成一串 1 和 0，並以位元序列的方式操作。

也許出乎意料的是，Kotlin 中`Byte`或`Short`型別與大多數的位元運算並不相容。以下所有範例都使用 32 位元整數（`Int`或`UInt`）。

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

位移只是把所有的位元往左或往右移動指定的位置數。有些位元會從一端掉落，另一端則補上 0 或 1。

- 使用 `shl` 左移：補零。
- 使用 `shr` 或 `ushr` 右移：正數時補零（負數稍後說明）。

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

每次左移會讓值變成兩倍，每次右移則讓值減半（可能會截斷）。用十進位表示會更明顯：

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

這種位移比「正式的」算術快上許多，因此這個技巧在低階程式設計中非常受歡迎。

面對*負整數*時，我們得再小心一點。

負數是以[二補數][wiki-2complement]形式儲存的，也就是最左邊的位元是 1。左移沒問題，但右移時，最左邊的位元要補什麼呢？

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

`shr`運算子執行的是[算術移位][wiki-arithmetic]，會保留符號位元。

`ushr`運算子執行的是[邏輯移位][wiki-logical]，會視同無號數一樣補零。

## 位元邏輯

我們在[布林概念][concept-booleans]中看過，運算子`&&`（and）、`||`（or）和`!`（not）是用來處理布林值的。

也有對應的運算子`and`、`or`、`xor`（[互斥或][wiki-xor]）可以用來比較兩個整數中的位元，另外還有`inv`（反轉）函式可以翻轉所有的位元。

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
