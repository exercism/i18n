# 簡介

什麼是函式程式設計？

對我們來說，以下是幾個關鍵特點：

- 純函式，能一致地把輸入對應到輸出，而且沒有副作用。
- 不可變的資料。
- 一級函式，可以像其他型別一樣被當作值來處理。
- 高階函式，接受其他函式作為引數，或作為回傳值。

不過，R 並不是純函式語言（不像 Haskell 那樣）。

把 R 視為一門務實的語言；當函式的做法既乾淨又簡單時，它（越來越常）提供這類能力。一般來說，資料分析才是目標，寫程式只是達成目標的手段。

## 管道

使用管道 `|>`連接函式，是許多語言中越來越常見的技巧。

簡要來說：

- 管道左邊的結果，會成為右邊函式的第一個引數（這裡的「右邊」會忽略可有可無的換行）。
- 其餘的引數可以一併放進函式呼叫裡。
- 在 R 裡，我們必須把管道接到函式的*呼叫*，而不只是*名稱*，所以一定要加上括號（*這點和其他一些語言不同*）。

有些程式設計師在看程式碼時，會把管道讀成「然後」，這樣比較有幫助：先做第 1 步，**然後**做第 2 步……

下面的範例說明了這個語法。

```R
library(stringr)

"Monday-25-February" |> 
  str_split("-") |>     
  unlist() |>               # [1] "Monday"   "25"       "February"
  str_sub(1, 3) |>          # [1] "Mon" "25"  "Feb"
  str_to_upper() |>         # [1] "MON" "25"  "FEB"
  str_flatten(collapse = ", ")
#> [1] "MON, 25, FEB"
```

這種管道是在 v4.1.0 加入 Base R 的，你可能會看到它被稱為「原生管道」。

RStudio 編輯器（以及其他一些編輯器）使用 `Ctrl-Shift-M`這個鍵盤快速鍵，來插入帶有適當空格的管道。

## 套用函式

我們之前看過，R 裡的許多函式都是「向量化」的：它們會作用在整個向量上，不需要寫出明確的迴圈。

只使用向量化函式的函式，本身很可能也會自動被向量化。舉個簡單的例子：

```R
triple <- function(x) return(3 * x)
triple(1:10)
 [1]  3  6  9 12 15 18 21 24 27 30
 ```

不過，比較複雜的函式可能無法接受向量輸入，例如當它們包含迴圈或 if-else 區塊時。

我們需要一種更通用的方式，把函式套用到向量上（類似其他語言裡的 `map()`）。

因為 R 在基礎語言裡有各式各樣豐富的資料結構，它也就有一整套 `*apply()`系列函式來操作這些結構。更技術性地說，程式設計師常把這類函式稱為「高階函式」，數學家則稱為「泛函」，因為它們都把函式當作引數。

現在，先來看看 `lapply()`和`sapply()`。

### `lapply()`

「List-apply」是設計來處理陣列輸入的，但向量在必要時會被悄悄地強制轉成陣列。

輸出會是一個陣列，所以可能需要拆解才能得到向量：

```R
h <- function(size) {
    switch(size,
           "small" = 6,
           "medium" = 8,
           "large" = 10
    )
}

v <- c("small", "large", "medium")

h(v) # bad use of an unvectorized function
#> Error in switch(size, small = 6, medium = 8, large = 10) : 
#>   EXPR must be a length 1 vector

lapply(v, h)  # output is a list
#> [[1]]
#> [1] 6

#> [[2]]
#> [1] 10

#> [[3]]
#> [1] 8

lapply(v, h) |> unlist() # output is a vector
#> [1]  6 10  8
```

熟悉 [Switch 概念][concept-switch]的學生可能會注意到，我們也可以改用 [`dplyr`][ref-dplyr]函式庫中向量化的 [`recode_values()`][ref-recode_values]來取代純量的 `switch`。向量化很好，而現代的 R 提供了多種方式來達成它。

```R
library(dplyr)

h <- function(size) {
  recode_values(size,
         "small" ~ 6,
         "medium" ~ 8,
         "large" ~ 10
  )
}

v <- c("small", "large", "medium")
h(v)
#> [1]  6 10  8
```

### [`sapply()`][ref-lapply]

「Simplified-apply」做的事和 `lapply`類似，但還會試著簡化回傳值：例如回傳具名向量，而不是陣列。依情境而定，可能需要使用 [`unname()`][ref-unname]：

```R
sapply(v, h)
 small  large medium 
     6     10      8 

sapply(v, h) |> unname()
#> [1]  6 10  8
```

## `purrr` 函式庫

`lapply`和`sapply`很簡單，對大多數 R 使用者來說也很熟悉，在向量和簡單陣列上依然相當受歡迎。

Base R 也有*許多*其他的套用函式。為這類混淆提供更簡單、更一致的替代方案，是 Tidyverse 的一項關鍵目標。

現在有了 `purrr`套件，它提供了幾個額外的選項（例如 `map()`），同時在設計上增進一致性，也讓錯誤訊息更清楚。這個套件比 base R 更不受向後相容性的限制，讓 R 明顯更接近其他語言中的現代函式程式設計。

`purrr`裡的函式繁多又多元，很難簡單地總結。幫助你認識這個函式庫的資源包括：

- 一個[網站][web-purrr]，其中包含[入門][web-starting]指南。
- 涵蓋所有函式的[參考頁面][ref-purrr-funcs]。
- PDF 格式的[速查表][cheat-purrr]。
- 從 [Base R][web-from-R] 轉換的指南。

### 眾多的 map 函式

[`map()`][ref-map]函式會把函式套用到輸入中的每個元素，而且一律回傳一個[陣列][concept-lists]。

到目前為止，這聽起來就像 [`lapply()`][ref-lapply]，只是換了個名字，或許還加上更好的錯誤訊息。

不過，`map()`只是一個*龐大*家族裡的其中一員。

挑選函式時，可以想一想這些問題：

- 你想回傳什麼？[`map()`][ref-map]一律回傳陣列，但如果你想要特定型別的原子向量，字串就用 [`map_chr()`][ref-map_chr]，整數就用 [`map_int()`][ref-map_int]，依此類推。
- 你需要輸入中每個位置索引嗎？那就把函式名稱前面加上 `i`，例如 [`imap()`][ref-imap]。
- 你想同時處理多個輸入嗎？
  - 把名稱中的 `map` 換成 `map2`，例如兩個輸入就用 [`map2_dbl()`][ref-map2_dbl]（例如值和權重，用來計算加權平均數）
  - 若是一組平行的輸入陣列，就換成 `pmap`，例如 [`pmap_chr()`][ref-pmap_chr]。沒錯，硬體層級的平行處理也是可行的。
- 你想處理輸入的所有元素嗎？如果不是，可以考慮用 [`map_if()`][ref-map_if]套用述詞（布林）篩選、用 [`map_at()`][ref-map_at]指定位置索引條件，或用 [`head_while()`][ref-head_while]處理輸入，直到某個元素不符合述詞為止。
- 輸入資料是否深度巢狀？針對這種情況，有[函式][ref-plucks]可用。
- 你想讓回傳值一律和輸入是同一種型別嗎？那就改用 [`modify()`][ref-modify]系列函式來取代 `map`，或用 [`modify_tree()`][ref-modify_tree]做遞迴套用。

這些函式在可能的情況下，都會把輸入資料當作第一個引數，以確保它們能和管道搭配得很好。

此外，`purrr`（刻意地）比 Base R 更吹毛求疵。如果你要求特定的事物，這些函式會*精準地*回傳那樣的結果，否則就停下來並顯示錯誤訊息。雖然嚴格，但對於減少難以找出的 bug 非常有效。

### 歸約函式

map 函式的回傳值通常和輸入長度相同。

其他一些函式會*縮減*資料的維度，例如 `sum()`。

```R
sum(1:100)
#> [1] 5050
```

在上面的例子中，我們把長度 100 的向量轉成長度 1 的整數。之後在關於矩陣和陣列的概念中，我們會看到維度縮減這個概念其實更為通用。

`sum()`函式是內建的（許多其他統計函式也是）。不過，我們需要一種方式，用某個等同於 `map()`的高階函式，把任意的維度縮減函式套用到整個資料結構上。

在其他一些語言中，會使用像 `fold`、`foldl` 和 `foldr` 這樣的函式名稱。在 R 裡，對應的函式是 [`reduce()`][ref-reduce]，等同於（對演算法愛好者來說很知名的）MapReduce 框架。

第一個引數一如往常是輸入資料。第二個引數是一個接受兩個引數的函式：通常是匿名函式，也可能簡單到像 `+` 這樣的算術運算子。

```R
# surround an infix operator with backticks, to use as a function
reduce(1:100, `+`)
#> [1] 5050  # same as sum(1:100)

# anonymous function, alternately add and subtract
reduce(1:10, \(accum, nextval) ifelse(nextval %% 2 == 0, accum + nextval, accum - nextval))
#> [1] 7
```

我們從輸入的開頭還是結尾開始套用函式，有差別嗎？

對於像 `+` 或 `*` 這類[具結合性][wiki-associative]的運算子來說，沒有差別。很明顯地，`(1 + 2) + 3 == 1 + (2 + 3)`。

相對地，`-` 和 `/` 不具結合性：

```R
(1 - 2) - 3
#> [1] -4
1 - (2 - 3)
#> [1] 2
```

對於方向有差別的函式，有一個選用的 `.dir` 引數。

```R
# default is .dir = "forward"
reduce(1:10, `-`)
#> [1] -53
reduce(1:10, `-`, .dir = "backward")
#> [1] -5
```

就和 `map()`與`map2()`一樣，也有 [`reduce2()`][ref-reduce]函式可以同時處理兩個輸入向量。

在 R 裡，我們喜歡用向量來工作。假設你不想只看最終的單一數值，而是想看所有的中間步驟。為此，對應的函式是 [`accumulate()`][ref-accumulate]和`accumulate2()`。語法和 `reduce()`類似，但多了一些可選的引數來指定輸出型別。

```R
accumulate(1:10, `+`)
#> [1]  1  3  6 10 15 21 28 36 45 55
 ```

有些常見的 accumulate 類型有自己的函式。[向量函式][concept-vector-functions]概念討論過 Base R 中的 [`cumsum()`][ref-cumsum]和`cumprod()`，而 `dplyr`函式庫則有 [`cummean()`][ref-dplyr-cum]可以計算數值平均，還有用於邏輯向量的 `cumall()`和`cumany()`。

### 篩選函式

我們常常想要納入（或排除）輸入中符合某個述詞的元素。

在[向量篩選][concept-vector-filtering]概念中，我們看過一種道地的做法。

```R
v <- 1:3
v[v >= 2]
#> [1] 2 3
```

這在傳統 R 裡很常用，但不太適合放進現代的函式化流程中。因此，`purrr`提供了一組[述詞函式][ref-predicates]，遵循 `f(input, func, ...)`這個一般的引數慣例，以便和管道搭配使用。

這些名稱和大多數其他語言有點不同（像 `filter` 和 `drop` 這類名稱，在 R 裡已經有完全不同的意思）。

對應的 `purrr`函式包括 [`keep()`][ref-keep]和 [`discard()`][ref-keep]，還有其他幾個。

另外，我們有 [`every()`][ref-every]、[`some()`][ref-every] 和 [`none()`][ref-every]，用來取代 `all()` 和 `any()`，回傳單一的邏輯值。
