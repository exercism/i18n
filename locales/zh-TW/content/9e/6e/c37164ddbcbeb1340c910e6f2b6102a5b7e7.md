# 簡介

## 陣列

在組合語言中，任何資料都是一連串的位元組。
這表示任何資料都可以視為由這些底層位元組構成的**陣列**。

### 存取陣列中的元素

若要存取記憶體中的任何值，就必須計算它的**有效位址**。
有效位址是一個運算式，可能由下列部分組成：

- 一個_基底位址_，例如由變數標籤所指出的位址。
- 一個_索引暫存器_，可以依 `1`、`2`、`4` 或 `8` 縮放。
- 一個帶號 32 位元的_位移量_，也就是要加到（或從中減去）基底位址的數字。

請注意，這個位址是_從 0 開始索引_的，因此不帶任何位移的基底位址會指向變數的第一個位元組。
這就是為什麼只使用標籤、不帶任何位移來解參考記憶體（如同我們在先前的概念中所做的那樣），會得到從第一個位元組開始的值：

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 是[小端序][endianness]。
這表示多位元組值的最低有效位元組會儲存在最小的記憶體位址。

因此，在存取多位元組值的個別位元組時，必須將正的位移加到基底位址上，才能取得更高位的位元組。

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

以一串值宣告的已初始化變數，就是由這些值構成的陣列，每個元素都有指定的大小。
不過，位移一律以**_位元組_**為單位，即使陣列中每個元素的大小更大也一樣：

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

請注意，由於位址是以位元組為單位，因此可以直接存取陣列中任一元素的個別位元組：

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

基於同樣的理由，也可以在單一指令中存取超過一個元素大小的範圍：

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
組合語言不會對陣列存取做邊界檢查。
超出陣列尾端的索引會讀寫陣列之外的記憶體。
這可能導致難以察覺的錯誤結果、破壞其他資料，而且如果被存取的記憶體未被映射，還可能引發執行期錯誤。
程式設計師有責任讓每個有效位址都落在陣列範圍內。
~~~~

### 計算已初始化陣列的大小

NASM（The Netwide Assembler，也就是本 track 使用的組譯器）有一個特殊符號（`$`），用來指出記憶體中的目前位置。
這個符號提供了一個方便的方法，可以用來計算陣列在記憶體中所占用的總大小：

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

當`$`緊接在`example`之後使用時，它會取得陣列結尾在記憶體中的位址。
這表示`$ - example`就是該位址與標籤`example`所指位址之間的差。
這正是`example`所指陣列所占的總大小，以位元組為單位。

所以，用這個值定義`example_length`，我們就建立了一個 8 位元組的變數，用來以位元組為單位儲存陣列的大小（或長度）。

### .bss 區段

未初始化的資料會宣告在**.bss 區段**中。
在大多數平台上，作業系統會在程式開始時將這些資料填入零。

在 NASM 中，未初始化的變數有名稱、一個指出資料大小的指示詞，以及要保留的元素數量。
這幾者之間各以一個空格分隔。

主要的指示詞及其對應的資料大小如下：

| 指示詞 | 大小    |
| :-------: | :------ |
|   resb    | 1 位元組  |
|   resw    | 2 位元組 |
|   resd    | 4 位元組 |
|   resq    | 8 位元組 |

例如，這會在名為`example`的變數中，為`3`個位元組保留未初始化的空間：

```x86asm
section .bss
    example resb 3
```

而這會在名為`arr`的變數中，為`10`乘以`8`個位元組（也就是`80`個位元組）保留未初始化的空間：

```x86asm
section .bss
    arr resq 10
```

`section .bss`中的變數是可變的，也就是說，它們可以讀取和寫入。

未初始化的資料可以用與已初始化資料相同的方式存取，也就是使用它的有效位址。
同樣地，它們也具有靜態儲存期，且可從同一個原始檔中的任何函式存取（若宣告為`global`，也可以從其他原始檔存取）。

### 使用 lea 指令存取陣列位址

如同先前的概念所探討的，`lea`指令會計算有效的記憶體位址。
它可以用來計算陣列中任一元素的位址，遵循相同的語意。

請注意，在相對定址中，通常必須先將變數的位址載入暫存器，才能組出更複雜的位址：

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea`的優點之一是，它利用位址計算的算術來算出一個值，而不會真正存取該位址上的記憶體。
這使得即使沒有任何暫存器存放記憶體位址，它也能用來做算術運算：

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
