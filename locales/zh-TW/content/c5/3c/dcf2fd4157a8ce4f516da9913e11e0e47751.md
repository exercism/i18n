# 關於可空性

在理想的世界裡，我們可以仰賴一切都有完善的定義、具體的值，沒有任何缺口。

這與我們的日常經驗相衝突，因此許多程式語言都有辦法表示「沒有值」：null 或 NULL、nil、None、nothing……

這在導入時很簡單（早在 1965 年），但很快就帶來懊悔。
發明者後來稱它是他的[「十億美元的錯誤」][web-mistake]。

近幾十年來，語言設計者探索了許多方法，讓 null 可以使用但（大致上）安全。

Kotlin 有幾項[一般原則][ref-null-safety]，這些原則[與 Java 有顯著差異][ref-java2kotlin]。
_這些差異意味著 Kotlin 有處理 Java 互通性的特殊功能，不過細節超出這個概念的範圍。_

- Kotlin 有一個特殊的 `null` 值。
- 所有型別_預設_都是不可為 null（也就是不能是 `null`）。
- 所有型別都可以是_可為 null_，但這必須明確指定。
- 可能因例外而失敗的函式，通常會有回傳值可為 null 的版本。
- 特殊且極度精簡的語法，盡可能讓檢查 null 和回應 null 變得容易。

## 建立可為 null 的變數

型別可以加上 `?` 後綴，使其成為[可為 null][ref-nullable-type]（例如用 `String?` 取代 `String`）。

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## 實用的運算子和函式

### [安全呼叫運算子][ref-safe-call] `?.`

對於不可為 null 的 `String`，我們可以取得 `.length` 屬性。

可為 null 的 `String?` 用相同的語法會失敗，但改用 `?.length` 就能顧及 `null` 的可能性。
回傳型別是 `Int?`。

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

如上面最後一行所示，`?.` 也能用於不可為 null 的型別。

### [Elvis 運算子][ref-elvis] `?:`

延伸安全呼叫運算子的概念，[Elvis 運算子][wiki-elvis]讓我們提供一個預設值來取代 `null`。

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### [非 null 斷言運算子][ref-not-null] `!!`

有了這個運算子，當程式設計師有把握時，可為 null 的型別會被強制視為不可為 null。
也許我們有時比過度謹慎的編譯器更了解程式的邏輯？

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

責任現在落到我們身上：如果 `b` 仍然是 `null`，就會得到 `NullPointerException`。

### [let 函式][ref-let] `?.let`

如果要將可為 null 的項目傳入程式碼區塊，我們可以寫明確的 null 檢查 `if (item != null) { do something }`。

改用 `item?.let { do something }` 更簡單也更道地，
`do something` 只會在 `item` 不是 null 時執行。

### 型別為 `somethingOrNone()` 的函式

有些函式可能會失敗，例如在字串或陣列中要求無效的索引時。

與其擲回例外，我們可以使用函式的[`...OrNull` 變體][ref-elem-at-or-null]，取得（在此情況下）`Int?` 回傳值。

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
