## 極簡歷史

幾十年前，在電腦裡處理字元要簡單得多，當時程式設計師假設英文是唯一重要的語言。
所以：26 個字母（大小寫）、10 個數字、幾個標點符號，再加上一個能讓鈴響的碼（0x07），全部塞得進 7 個位元：也就是 ASCII 字元集。

很自然地，人們開始問 à、ä 和 Ł 該怎麼辦，接著其他人開始問 ऄ、ஹ 和 ญ，而年輕人則想要表情符號 😱。
該怎麼辦呢？

長話短說，許多聰明又有耐心的人不得不在委員會裡待上好幾年，把 Unicode 字元集以及 UTF-8 這類編碼的細節一一敲定，而且大量軟體需要_極_複雜的改寫。
除此之外，還引入了許多新的 bug。

為了避免_所有東西_都壞掉，Unicode/UTF-8 的設計確保前 127 個碼與 ASCII 完全相同_（連鈴聲也是）_。

## Julia 中的字元

2005 年左右之後設計的語言有個巨大的優勢：當時已經有相當穩定的 Unicode 標準。
Julia（2012 年首次發布）可以直接假設所有東西都會是 Unicode：字元、字串、變數與函式名稱、數學運算子……

引用手冊的說法：「Julia 讓處理純 ASCII 文字變得簡單又有效率，而處理 Unicode 也盡可能簡單又有效率。」
注意「盡可能」這幾個字，它是這句話很重要的一部分。

***字元常值以單引號書寫，與以雙引號書寫的字串截然不同。***

對來自 C/C++ 世界的人來說這很明顯，但對 Python 和 Javascript 程式設計師來說可能有點混淆。

```julia-repl
julia> a = 'a'  # Roman alphabet
'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)

julia> typeof(a)
Char

julia> jha = 'झ'  # Devanagari alphabet
'झ': Unicode U+091D (category Lo: Letter, other)

julia> typeof(jha)
Char

julia> '❤'  # heart emoji
'❤': Unicode U+2764 (category So: Symbol, other)
```

從這些範例可以看出型別是 `Char`，而且 Julia 對字元的類別有更多資訊。

再仔細看，這些字元似乎可以用 4 個十六進位數字表示。
完整的字元集則最多需要 6 個十六進位數字。

這些數字稱為「碼位」，目前範圍從 U+0000 到 U+10FFFF。
它們會顯示在 REPL 中，但在程式碼裡要取得它們則使用 `codepoints()`。

在 `Char` 和 `Int` 之間轉換很簡單：

```julia-repl
julia> Int('a')
97

julia> Char(97)
'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
```

編譯器允許對 `Char` 進行_某些_形式的整數運算：

```julia-repl
julia> 'b' - 'a'  # interval, in alphabetic order
1

julia> 'b' + 'a'
ERROR: MethodError: no method matching +(::Char, ::Char)

julia> 'a' + 5
'f': ASCII/Unicode U+0066 (category Ll: Letter, lowercase)

julia> 'f' + ('A' - 'a')  # same as `uppercase('f')`
'F': ASCII/Unicode U+0046 (category Lu: Letter, uppercase)
```

## 字元的函式

許多處理字串的函式也能作用於 `Char` 輸入。

- 對合適的字母系統，用 `uppercase()` 和 `lowercase()` 改變大小寫。
- 用 `isuppercase()` 和 `islowercase()` 測試大小寫。
- 用以下函式測試字元型別：
  - `isletter()` 涵蓋許多字母系統
  - `isdigit()`，嚴格測試 0:9
  - `isnumeric()`，比 `isdigit` 更廣，所以對 ¾ 以及各種非歐洲文字系統會是 `true`
  - `isxdigit()`，十六進位數字
  - `isascii()`，Unicode 之前的字元
  - `ispunct()`，標點符號
  - `isspace()`，任何空白字元
  - `isprint()`，可列印字元（相反的是 `iscntrl()`）

```julia
islowercase('A')  # false
uppercase('γ')  # 'Γ': Unicode U+0393 (category Lu: Letter, uppercase)
ispunct('@')  # true
isdigit('A')  # false
isxdigit('A')  # true
```

## Char 向量與字串的互相轉換

要把字串轉成字元向量，可以使用 `collect()`。

要把字元向量轉回字串，則有 `String()` 建構式。

```julia-repl
julia> s = "abcde"
"abcde"

julia> cv = collect(s)
5-element Vector{Char}:
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'b': ASCII/Unicode U+0062 (category Ll: Letter, lowercase)
 'c': ASCII/Unicode U+0063 (category Ll: Letter, lowercase)
 'd': ASCII/Unicode U+0064 (category Ll: Letter, lowercase)
 'e': ASCII/Unicode U+0065 (category Ll: Letter, lowercase)

julia> String(cv)
"abcde"
```

這對任何字元都行得通，不只是 ASCII。

```julia-repl
julia> collect("❤,😱")
3-element Vector{Char}:
 '❤': Unicode U+2764 (category So: Symbol, other)
 ',': ASCII/Unicode U+002C (category Po: Punctuation, other)
 '😱': Unicode U+1F631 (category So: Symbol, other)
```

注意 `String()` 建構式是作用在向量上的。
若要把單一 `Char` _轉型_成單一字元的字串，要用的是 `string()`，開頭是小寫的 `s`。

```julia-repl
julia> string('a')
"a"
```

## 儲存方式

到目前為止，這份文件裡的一切似乎都相對簡單，所以真的沒什麼好擔心的嗎？

可惜的是，這太樂觀了！

其中一個麻煩來自每個碼位可能需要「最多」6 個十六進位數字。
這表示以 UTF-8 編碼時，不同字元在記憶體中需要的空間也不同。

一個位元組只能儲存（無號）到 255 的數字，也就是兩個十六進位數字，所以 UTF-8 會用數量不固定的位元組（1 到 4 個）來儲存一個 `Char`。
這些稱為「碼元」，而 `ncodeunits()` 函式會回傳指定字元所需的數量。

```julia-repl
julia> codepoint(jha)  # jha 'झ' is defined in an earlier example
0x0000091d

julia> ncodeunits(jha)
3

julia> ncodeunits('a')  # ASCII character
1

julia> ncodeunits('😱')  # emoji
4
```

此外，並非所有能在螢幕上顯示的東西都有自己獨一無二的碼位。
有些視覺上不同的字元被視為衍生自其他字元，因此 Unicode 把它們當成一個父字元加上一個修飾符來處理。
