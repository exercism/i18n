# 關於

[迴圈][control] 是一連串的指令，這些指令可能會被執行不只一次，直到結束條件成立為止。

在 x86-64 中，迴圈通常是透過跳躍到先前的標籤來建立的：

```x86asm
example_loop:
    ...
    jmp example_loop
```

請注意，無條件跳躍到先前的標籤，一定會把執行流程轉移到這個標籤。
這表示除非有另一個跳躍把執行流程帶到重複的片段之外，否則迴圈會永遠重複下去。

舉例來說，下面這個迴圈不會結束：

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

而下面這個迴圈則可能會結束，取決於條件是否成立：

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## 計數迴圈

計數迴圈幾乎總是以同樣的方式結尾：一道更新計數器或比較兩個值的指令，緊接著一道決定是否再繞一圈的條件跳躍。

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
在上面的程式碼中，`cmp rsi, 0` 不是必要的，因為 `sub rsi, 1` 在結果為 `0` 時就已經設定了 `zero flag (ZF)`。

雖然 `cmp` 是在組合語言中測試條件的主要方式，但許多指令也會更新旗標。
舉例來說，許多整數運算或位元運算指令會在結果為 `0` 時更新 `ZF`，並在結果為負（也就是最高位元被設定）時更新 `SF`。

你可以查閱[參考資料][reference]，了解每個指令會影響哪些旗標。

[reference]: https://www.felixcloutier.com/x86/
~~~~

請注意，在上面的範例中，我們假設 `rsi` 大於 `0`。
如果它是 `0`，那麼 `sub rsi, 1` 會把 `rsi` 變成 `-1`，也就是一個非常大的無號數。
這樣還需要再疊代 `18,446,744,073,709,551,615` 次，迴圈才會終於結束。
此外，由於陣列的長度是 `0`，任何記憶體存取都會超出範圍。

如果無法保證陣列的長度，有兩種常見的做法。

第一種是把結束條件移到迴圈的開頭，並在結尾放一個無條件跳躍：

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

第二種是在迴圈開始之前，先檢查一次陣列長度是否為零：

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

第二種做法通常比第一種更有效率，因為迴圈主體中的分支比較少。
你會在之後的概念中學到更多這方面的內容。

## 微運算

處理器不會直接執行像 `add` 或 `jnz` 這樣的指令。
CPU 的前端會先把每道指令_解碼_成一個或多個更小的內部步驟，這些步驟稱為**微運算**（或**micro-ops**）。
接著處理器會排程並執行這些微運算，通常每個時脈週期執行好幾個，而且不一定依照原本的順序。

大多數簡單的指令會解碼成單一微運算，而較複雜的指令則可能解碼成好幾個。
由於處理器真正的工作量是這一連串的微運算，因此用更少的微運算完成同樣的工作，就是讓程式碼變快的其中一種方法。

## 巨集融合

如前所述，迴圈通常會以某種條件跳躍結尾。
這個模式非常常見，因此現代處理器在解碼時會特別針對它進行最佳化。

一道設定旗標的指令，如果緊接著一道讀取這些旗標的條件跳躍，兩者可以一起解碼成**單一**微運算，而不是各自解碼成一個。
這就叫做**巨集融合**。

融合後的這一對指令會表現得像單一操作：計數器的更新與分支的判斷會一起完成，合併成一個微運算。
如此一來，迴圈的控制流程在迴圈實際進行的工作之外，幾乎不帶來額外成本。

經驗法則上，有兩種類型的配對通常會這樣融合：

- 算術指令，例如 `add` 或 `sub`，緊接著條件跳躍。
- `cmp`、`test` 或 `and`，緊接著條件跳躍。

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

只有在條件跳躍**緊接**在設定旗標的指令之後、中間沒有任何其他指令時，才會發生融合。

~~~~exercism/note
巨集融合取決於 CPU，而且哪些指令能與哪種條件跳躍融合，會有一些差異。

一個很實用的參考資料是 [Intel、AMD 與 VIA CPU 的微架構，作者 Agner Fog][agner-uarch]。
[Intel 最佳化參考手冊][intel-opt] 的第 3.4.2.2 節（Optimizing for Macrofusion）也列出了 Intel CPU 可融合的配對。

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## `loop` 指令

有些指令可以用來製造類似迴圈的行為。
其中一個就是 [loop][loop]。

它唯一的運算元是一個標籤，這個標籤帶有迴圈開頭的位址。

`loop` 指令會把 `rcx` 中的值當作計數器，每次將它減 1。
一旦 `rcx` 中的值變成零，迴圈就會結束，執行流程接著依序繼續：

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

`loop` 指令有兩個變體，會在每次疊代時檢查零旗標（`ZF`）。
除了在 `rcx` 變成零時停止迴圈之外，當條件_不_成立時，它們也會停止。

| instruction       | condition |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

這些指令**不會設定** `ZF`。
在它們之前必須有一道 `cmp`、`test` 或其他會改變 `ZF` 的指令：

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
儘管 `loop`、`loope` 和 `loopne` 很方便，但在現代處理器上，它們通常比對應的 `sub`/`jnz` 或 `cmp`/`jnz` 序列慢上許多。

關於指令在各種不同 CPU 上的效能，[Agner 的表格][agner-tables] 是很好的參考資料。

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
