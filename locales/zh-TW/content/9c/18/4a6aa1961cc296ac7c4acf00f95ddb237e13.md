# 程式碼納入

`circus-acts`用`<`表示某個類別*能做*某個抽象類別所描述的事，卻完全沒說要怎麼做。

`include`則是另一半：它把另一個類別的實際程式碼拿過來，複製一份放進這個類別裡。

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

`JAZZ_ROUTINE::count`是 8，而`JAZZ_ROUTINE`完全沒有提到它。

## 這是兩個獨立的決定

多數語言把它們綁在一起：一個`extends`既把程式碼傳承下去，也讓子類別在任何需要父類別的地方都能使用。Sather 則把兩者分開。

| 寫法 | 意思 |
| --- | --- |
| `class A < $B` | 任何需要`$B`的地方都能使用`A` |
| `class A is include B` | `A`起始時就有一份`B`的程式碼複本 |

可以只有其中一個，也可以兩者兼具。納入一個類別**並不**會讓它成為子型別：在`include WARM_UP`之後，`JAZZ_ROUTINE`依然無法用在需要`WARM_UP`的地方，而且沒有任何東西會假裝它辦得到。

## 重新命名

被納入的常式可以用不同的名字帶進來：

```sather
   include WARM_UP count -> warm_up_count;
```

要納入好幾個時，用逗號分隔：

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## 略過其中一個

把名稱重新命名為*空*，就等於不將它納入，而這也正是替換它的方式：

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

`count`一如往常地被納入；`describe`則沒有，所以在這裡寫一個並不會衝突。少了`describe -> ;`，編譯器會拒絕編譯：同一個類別裡出現兩個名稱和引數都相同的常式就是錯誤，而 Sather 不會去猜你指的是哪一個。

這就是它和多數語言裡覆寫的差別：替換是明白宣告的，而不是隱含的。
