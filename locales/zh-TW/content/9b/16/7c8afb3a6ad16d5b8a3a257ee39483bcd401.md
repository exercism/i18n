# 關於

`TUPLE: child < parent extra-slots ;`會宣告一個類別，這個類別的實例同時也是`parent`的實例。槽位查詢會沿著階層往上找：`child`擁有父類別宣告的每個槽位，再加上自己的槽位，並依此順序排列。

```factor
TUPLE: vessel name tonnage ;
TUPLE: cargo-vessel < vessel capacity ;
TUPLE: tanker < cargo-vessel fuel-type ;
```

## `boa`引數順序

自動產生的`boa`建構子會依宣告順序接收槽位，*父類別優先*。以上面的`tanker`為例：

```
tanker boa ( name tonnage capacity fuel-type -- tanker )
```

槽位順序由繼承鏈固定，沒有辦法交錯父類別與子類別的槽位，而重新排序父類別的槽位，對每個後代類別的`boa`來說都是破壞性變更。

## 述詞階層

每個`TUPLE:`宣告都會產生一個類別述詞（`name?`）。有了繼承，述詞會巢狀起來：

```factor
"Esso" 50000 100000 "diesel" tanker boa .

! all three predicates fire
dup tanker?        .   ! => t
dup cargo-vessel?  .   ! => t
dup vessel?        .   ! => t
```

`instance?`（來自[`classes`][classes]）用堆疊引數傳入類別來問同樣的問題，而不是把類別寫死在詞名裡；`obj tanker instance?`等同於`obj tanker?`：

```factor
USING: classes ;

"Esso" 50000 100000 "diesel" tanker boa
dup vessel instance? .   ! => t
```

因為類別現在是一個值，同一個呼叫位置可以測試任何傳入的類別，而固定的`name?`述詞做不到這一點。

遞移的`is-a`關係也是`M:`方法分派所依循的路徑；定義在`vessel`上的方法會套用到每個`cargo-vessel`和每個`tanker`，除非有更特定的覆寫先發生。這部分的故事在[`generics`][generics]裡。

## 存取子繼承

存取子詞（`slot>>`、`>>slot`、`change-slot`）來自[`accessors`][accessors]，而且不綁定在當初產生它們的類別上：任何*擁有*該槽位的元組都可以使用它們。

```factor
USING: accessors ;

"Esso" 50000 100000 "diesel" tanker boa
[ 1 + ] change-tonnage tonnage>> .   ! => 50001
```

`change-tonnage`是為`vessel`產生的，但它可以在`tanker`上運作，因為每個`tanker`都是`vessel`。

## 這不是什麼

- **混入**（`MIXIN:` / `INSTANCE:`），一個類別可以加入多個混入；這種關係是多對多，主要用於在共用協定上進行泛型分派。串流概念會在情境中介紹它們。
- **述詞類別**（`PREDICATE:`），透過執行階段述詞從現有類別切出一個子類別。這是 Factor 的另一項功能；這裡不涵蓋。
