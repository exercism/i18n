# 關於

程式執行時，記憶體通常由作業系統（OS）對應成一個通用的配置：

| 位址 | 記憶體區域             |
| :-----: | :--------------------- |
|  高   | 堆疊                   |
|         | ...                    |
|         | 堆積                   |
|         | 可讀寫區段             |
|         | 程式碼／唯讀區段       |
|   低   | 保留                   |

以區段劃分的記憶體，會再依權限不同組織成一個個節區。

到目前為止，我們定義的函式都位於**section .text**中。這個節區存放唯讀的可執行資料。其他節區則用來宣告資料變數，這些變數可能是唯讀或可讀寫，但不可執行。

## .data 節區

已初始化的資料會宣告在 **[section .data][data]** 中。

在 NASM（The Netwide Assembler，本 track 使用的組譯器）中，一個已初始化的變數包含名稱、指出資料大小的指示詞，以及一串以逗號分隔的值。這三者彼此以空格分隔，而標籤後面可以選擇性地加上 `:`。

主要的指示詞及其對應的資料大小如下：

| 指示詞 | 大小    |
| :-------: | :------ |
|    db     | 1 位元組  |
|    dw     | 2 位元組 |
|    dd     | 4 位元組 |
|    dq     | 8 位元組 |

例如，下面這行宣告了一個名為 `space` 的位元組變數，值為 `10`：

```x86asm
section .data
    space db 10
```

宣告在`section .data`中的變數是可變的，也就是可讀寫。它們也具有*靜態*儲存期，代表它們在整個程式執行期間都存在。

## .rodata 節區

**section .rodata**與`section .data`類似。兩個節區都存放已初始化的資料，宣告方式相同，儲存期也一樣。

兩者主要的差別在於，`section .rodata`中的資料不可變，也就是唯讀。

~~~~exercism/note
用`equ`定義的常數，和定義在`section .rodata`中的常數不一樣。

用`equ`定義的常數不會佔用記憶體空間，組譯器會直接用它的值來替換。它實際上只是該值的佔位符。

另一方面，定義在`section .rodata`中的常數確實會儲存在記憶體中，並且有一個位址。
~~~~

## 存取資料

### 標籤與間接參考

宣告的資料必須有一個與之關聯的名稱。這個名稱稱為**標籤**。

標籤是一個符號，編碼了資料在記憶體中的特定位址。**x86-64 的位址是 64 位元的值**。用來保存這種位址的值，無論是放在暫存器裡或存在記憶體中，就是高階語言所稱的**[指標][pointer]**。

在 NASM 中，直接用標籤存取資料，得到的並不是配置到的記憶體，而是它的位址：

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

若要存取某個記憶體位址的內容，就必須對它*解參考*。這稱為**間接參考**。

在 NASM 中，這是用`[]`來完成：

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

不過，有些情況下，被解參考的記憶體大小可能會有歧義。這時就必須使用指定大小的前置詞。

以下是典型 x86-64 程式中最重要的一些前置詞及其大小：

| 前置詞 | 大小    |
| :----- | :------ |
| byte   | 1 位元組  |
| word   | 2 位元組 |
| dword  | 4 位元組 |
| qword  | 8 位元組 |

同樣的載入也可以明確寫出大小：

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

解參考記憶體時一律加上前置詞，是很好的習慣。

### 寫入記憶體

寫入記憶體的做法也一樣，就是對位址解參考：

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

請注意，大多數指令都能直接使用記憶體運算元，不必先把內容載入暫存器。不過，通常無法同時在來源與目的運算元中使用它們，兩者只能取其一：

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### LEA 指令

雖然可以用`mov`把變數的位址存到暫存器，但有一道指令就是專門為此而生：**[lea][lea]**。

這道指令使用記憶體形式的運算元，但它*不會*讀取記憶體，而是計算出有效位址運算式，並把結果寫入目的運算元：

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

用`lea`來計算並把記憶體位址存入暫存器，是比較道地的寫法。

### 相對定址

存取記憶體位置時，NASM 的預設行為是產生**絕對位址**，也就是固定的記憶體位址。

基於安全理由，執行檔經常會建置成 **PIE（Position Independent Executable，位置無關執行檔）**，記憶體區域會被放在隨機化的位置。在`PIE`中，變數的最終位址在連結時期並不知道。因此程式碼改為把位址計算成某個特殊暫存器`rip`中值的位移，而`rip`指向下一個要被執行的指令。

這通常稱為 **RIP 相對定址**。

在 NASM 中，可以用 **[rel 運算子][rel]** 要求使用 RIP 相對存取：

```x86asm
mov rax, qword [rel variable]
```

也可以在原始碼檔案最上方加上`default rel`，把相對定址設為預設。

本 track 的所有練習都會以`PIE`編譯與連結，所以應該使用`rel`來產生相對位址。

前面提到的隨機化配置，是一種稱為位址空間配置隨機化（address space layout randomization）的緩解措施。它讓每個記憶體區域的基底變得不可預測，使攻擊者無法取得許多漏洞利用技巧所依賴的固定位址，而`PIE`正是讓載入器能把這些區域放在任何位置的機制。

因此，在本 track 中，絕對定址不只是不鼓勵使用，而是根本不能用。像`[abs variable]`這樣的絕對參考，會要求組譯器把一個固定的 32 位元位址內嵌到指令中。在 Linux 上，`PIE`連結器會拒絕它產生的重定位；在 macOS 上，`macho64`格式則完全不支援 32 位元的絕對位址，所以檔案會組譯失敗。

RIP 相對定址能避開這兩個問題，因為指令只編碼相對於`rip`的位移，永遠不會是固定位址。因此在`PIE`下，把位址放入暫存器的道地做法，就是搭配`rel`運算元使用`lea`：

```x86asm
default rel

section .data
    variable dq 7

section .text
fn:
    lea rax, [rel variable]       ; materialize the address (PIE-safe)
    mov rcx, qword [rel variable] ; load the value through a RIP-relative access
    ...
```

### 可見性

在任何節區（例如`.text`、`.data`、`.rodata`）中定義的標籤（函式與資料），在同一个原始碼檔案內都是可見的。若宣告為`global`，它們對其他原始碼檔案也可見。

反之，定義在其他原始碼檔案中的標籤，若宣告為`extern`，對目前的原始碼檔案也可見。在這種情況下，組譯碼中並沒有資料大小的資訊，必須事先知道。

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
