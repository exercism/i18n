# 簡介

和許多其他語言一樣，Go 也有指標。
如果你剛接觸指標，可能會覺得它們有點神祕，但一旦熟悉之後，就會發現它們其實相當直觀。
指標是 Go 中至關重要的一部分，所以請花點時間真正理解它們。

在深入細節之前，值得先了解指標的用途。
指標是一種與程式其他部分共享記憶體的方式，這在兩個主要方面很有用：

1. 當我們有大量資料時，在函式之間傳遞時製作副本非常沒有效率。
   改為傳遞資料儲存位置的記憶體位址，我們就能大幅減少程式所佔用的資源。
2. 透過在函式之間傳遞指標，我們可以直接存取並修改那份唯一的資料副本，這表示某個函式所做的任何變更，在函式結束時會立即對程式的其他部分可見。

## 變數與記憶體

假設我們有一個普通的整數變數 `a`：

```go
var a int
```

當我們宣告一個變數時，Go 必須在記憶體中找個地方來儲存它的值。
這對我們來說大部分是抽象的，當我們需要取出那塊記憶體中儲存的值時，只要用變數名稱來取用就好。

例如，當我們寫 `a + 2` 時，實際上就是取出與變數`a`相關聯的記憶體中所儲存的值，並加上 2。

同樣地，當我們需要改變`a`那塊記憶體中的值時，可以用變數名稱來做指定：

```go
a = 3
```

與`a`相關聯的那塊記憶體，現在會儲存值`3`。

## 指標

雖然變數讓我們能取用記憶體中的值，但有時知道變數所指向的**記憶體位址**也很有用。
**指標**儲存這些值的記憶體位址。
只要在底層型別前面加上星號，就能宣告一個指標型別的變數：

```go
var p *int // 'p' contains the memory address of an integer
```

這裡我們宣告了一個型別為「指向 int 的指標」（`*int`）的變數`p`。
這表示`p`會儲存一個整數的記憶體位址。
指標的零值是`nil`，因為`nil`指標不儲存任何記憶體位址。

### 取得指向變數的指標

要找出變數值的記憶體位址，我們可以使用`&`運算子。
例如，如果我們想找出變數`a`的記憶體位址並存到指標`p`中，可以這麼做：

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### 透過指標存取值（解引用）

當我們有一個指標時，可能會想知道該指標所代表的記憶體位址中儲存的值。
我們可以用`*`運算子來做到：

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p`這個運算會取出儲存在`p`中的記憶體位址上的值。
這個運算通常稱為「解引用」。

我們也可以使用解引用運算子，為指標所指向的記憶體位址指定新值：

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

對`*pa`做指定，會改變`pa`所儲存的記憶體位址上的值。
由於`pa`儲存的是`a`的記憶體位址，所以對`*pa`做指定，實際上就是在改變`a`的值！

不過要提醒一點：解引用之前，一定要先確認指標不是`nil`。
對`nil`指標解引用，會讓程式在執行時期崩潰！

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### 指向結構的指標

到目前為止，我們只看過指向基本型別值的指標。
我們也可以為結構建立指標：

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

我們也可以建立一個新的`Person`，並立刻儲存指向它的指標：

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

當我們有指向結構的指標時，存取其中一個欄位之前不需要先解引用：

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## 切片和 map 本身就是指標

切片和 map 是特殊的型別，因為它們的實作中本身就帶有指標。
這表示大多數情況下，我們不需要為這些型別建立指標，就能共享其值的記憶體位址。
想像我們有一個函式，會把 map 中某個鍵的值加一：

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

如果我們建立一個 map 並呼叫這個函式，函式對 map 所做的變更在函式結束後仍然保留。
這和我們使用指標時的行為類似，但請注意，這個例子中我們並沒有用到任何取址／解引用，也沒有用到任何指標語法：

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

修改切片中既有的項目時，也是同樣的道理。

不過，像`append`這種會回傳新切片的操作是特殊情況，**可能不會**修改函式外部的切片。
這是因為切片內部運作方式的關係，但我們不會詳細介紹，因為這是比較進階的主題。
如果你真的很好奇，可以在 [Go Blog: Mechanics of 'append'][mechanics-of-append] 中閱讀更多相關內容。
