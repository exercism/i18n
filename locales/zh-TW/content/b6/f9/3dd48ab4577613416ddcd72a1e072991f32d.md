# 關於

到了課程大綱的這個階段，你已經看過 R 經常被當成命令式語言使用，也越來越常以函式語言的方式出現（尤其是在搭配 [`purrr`][ref-purrr] 和 [`dplyr`][ref-dplyr] 套件時）。

現在如果說 R 主要是物件導向，可能會引來一些懷疑！

奇怪的是，這句話其實是真的。
在內部，R 的實作運用了類別、繼承、多型，以及 OOP 程式設計師特有的那種心態。

然而，任何熟悉 Java 或 Ruby（這些都是明確的 OOP 語言），甚至 Python（在某些方面算是半隱藏式的 OOP）的人，都會覺得 R 的做法…_很陌生_。

首先，類別的設計就有好幾種：常見的大概有三種（S3、S4、R6），另外還有一些主要只有理論意義的設計。

完整的討論可以參考 [Advanced R, 2e][book-advanced-r]，第 12 到 16 章。
這本 2019 年的書，主要對象是想理解並維護 R 內部運作的人，所以 OOP 是不可或缺的。

更多面向終端使用者的教科書，做法就各不相同。

- The Art of R Programming（2011 年，僅紙本）有一章談 OOP，涵蓋 S3 以及（更簡短地）S4，這些在當時都很重要。
  書中說_「S3 類別的結構拼湊得很粗糙」_，這句話至今依然驚人地貼切。
- R in Action（第 3 版，2022 年）把 OOP 壓縮到接近書末「進階程式設計」那一章裡的 3 頁。
- [R for Data Science, 2e][book-r-data-sci]（2023 年，紙本版共 548 頁）則完全沒提到 OOP。

本概念會聚焦在 S3 類別，它最簡單、最常見，也最貼近 Exercism 這類題目。
R track 上有些練習要求你建立 S3 類別，有些則把它列為選填，但會溫柔地鼓勵你嘗試。

## S3 類別

這種類別很老：S3 這個名字只是表示它們是在 S 語言（R 的前身，商業軟體）第 3 版中引入的。

S3 類別本身也非常簡單：通常就是一個 [陣列][concept-lists]，外加至少一個額外的屬性。

引用 [Advanced R][book-s3] 的話：_「S3 是非正式、臨時湊合的，但它的極簡中有一種優雅：你無法從中拿掉任何一部分，還能有個堪用的 OO 系統。」_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

所以，對 [`class(obj)`][ref-class] 進行賦值，只是在 `obj` 上多加一個屬性，在這裡就是把 pt2d 標記成 point2d 類別的實例。

建立步驟也可以和 [`structure()`][ref-structure] 合併使用：

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

雖然產生出來的實例在意義上是相同的，我們還沒實作出讓 R 確認這件事的方法。

### 泛型方法

熟悉其他語言 OOP 的人可能會納悶：_「類別不是應該要能做點事嗎？」_

我們可以查看 `point2d` 實例有哪些可用的方法，然後發現（和底層的 `list` 相反）目前一個都沒有。

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

在大多數 OOP 語言中，方法是在類別定義裡定義的。
有少數語言（尤其是 Ruby）允許你之後再加入和修改類別方法。

S3 類別就很不一樣。
我們不是把方法加到類別上，而是把類別加到泛型方法上。

任何在 R 主控台上互動工作的人，時時都在使用泛型方法，通常根本不會去想它們是怎麼實作的。

一個很常見的例子是 `print()`，即使你很少親自打出這個函式名稱。
在主控台提示字元下單獨輸入一個值 `x`，其實只是 `print(x)` 的語法糖。

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

我們已經可以印出 `pt2d` 了。
雖然 `print()` 對 `point2d` 類別一無所知，但它有合理的預設行為，能處理各式各樣的物件。

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

那樣相當囉嗦，我們可能想要一種能簡潔漂亮列印這個點的方法。

很簡單：只要加一個叫做 `print.point2d()` 的函式。
名稱必須是 `methodname.classname` 這種形式，分派器才知道要尋找什麼。

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

現在假設我們想建立一個新的泛型方法，例如 `flipvert()`，用來把 `y` 座標的正負號反轉。

同樣地，很簡單：

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

這樣就建立了一個分派器，其中 `x` 是我們帶有 S3 類別的物件，而 `...` 則處理方法定義可能需要的任何額外引數（也就是「點參數」，如[函式概念][concept-functions]所述）。

然後我們可以為 `point2d` 定義這個方法並使用它。

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

現在 R 知道怎麼翻轉我們的點，也知道怎麼顯示結果。

我們可以進一步擴充，為 3D、極座標等建立類別，然後為每個類別定義方法。

從終端使用者的角度來看，只有 `flipvert(x, ...)` 這個方法，我們可以放心讓 R 判斷輸入的類別，並使用對應的底層實作。

~~~~exercism/caution
格式為 `verb.class` 的函式名稱，無論對使用者還是對 R 的剖析器來說，看起來都像 S3 方法。
請避免在其他情境中使用類似的命名方式。

不可否認，base R 有時會違反這條規則。
我們應該把它視為一個不幸的歷史意外（那些函式甚至比 S3 還老），基於向後相容性，必須保留下來。
~~~~

### 繼承

熱衷 OOP 的人可以為繼承、建立子類別、混入等主題，寫上好幾章厚厚的教科書內容。

R 只是讓你可以給 `class` 屬性多個名稱：一個更長的字串向量，而不是單一字串。

冒著把這個例子用到極限的風險，假設我們建立了一個泛型的 `point` 類別，並想為它建立子類別 `point2d`、`point3d` 等等。

那麼 `point2d` 的定義只要用 `class = c("point2d", "point")`：也就是特定類別加上父類別（可能不只一個）。

諸如 `print()` 之類的泛型方法，會依序尋找 `print.point2d()`、`print.point()`，以及（很可能）`print.default()`，並採用分派器找到的第一個實作。

### 安全性

許多 OOP 語言（Java、C# 等）會利用類別內的資料封裝，來進行嚴謹的編譯期檢查並強制型別安全。

請注意，S3 讓你幾乎想做什麼都行，即使完全不合理也一樣（錯誤訊息就算會出現，也是之後的事）。

引用 [「Advanced R」][book-s3]（第 2 版，13.3 節）：

> _如果你用過其他 OO 語言，這可能會讓你覺得不太舒服，但實際上這種彈性很少造成問題。R 不會阻止你拿槍打自己的腳，只要你別把槍口對準腳趾、扣下扳機，就不會有問題。_

嗯，_好吧？_
R 在探索式資料科學和統計方面非常出色，尤其在互動工作時。
沒有人是在建議你拿它來寫高度安全的企業財務系統！
