# 指令

這個問題是以即時作業系統的不可搶佔式靜態排程為模型，但也類似只有一種資源的 Job-Shop Scheduling Problem（JSP）。這個問題假設所有任務都是靜態已知的。換句話說，在這個問題中，所有任務的釋放時間在程式開始時就已經知道。但在實務上，任務的釋放時間在程式開始時並不知道，也可能隨時透過 I/O、中斷等方式產生。

給定一份帶有參數的任務陣列，決定出一個排程，讓這些任務能夠依序執行且彼此不重疊。由於這個問題是以即時作業系統的行程排程為模型，我們假設任務之間需要一段非零的時間，也就是所謂的上下文切換負擔。任務有兩種不同的類型：週期性與動態。兩種任務都有一個任務 ID 參數，它是一個字串，用來區分任務陣列中的不同任務。

**週期性任務**的定義是會週期性執行的任務。換句話說，這個任務每隔 T 秒執行一次，其中 T 就是週期。週期性任務由下列參數定義：

* 開始時間：任務第一次重複（也就是第一個實例）開始的時間
* 週期：任務各次重複開始之間的時間
* 執行時間：每次重複執行的持續時間
* 結束時間：整個任務不再被排程的時間

**動態任務**的定義是只執行一次的任務。動態任務由下列參數定義：

* 釋放時間：任務可以被排程的最早時間（和開始時間不同）
* 執行時間：任務執行的持續時間
* 截止時間：任務必須完成執行的時間

待實作的函式有兩個輸入。第一個輸入是一份`RealTimeTask`實例的陣列。`RealTimeTask`的實例會以`PeriodicRealTimeTask`或`DynamicRealTimeTask`實例的形式輸入，而且所有任務參數都是整數。可以使用 Python 的內建函式`isinstance()`來區分陣列中的這兩種任務。陣列的順序無關緊要，只要看任務的參數就好。第二個輸入是單一整數，用來指定上下文切換負擔。上下文切換負擔永遠是非負整數。

輸出應該是一個字典，鍵是來自 RealTimeTask 實例的任務 ID，值則是一份二元組的陣列。二元組的格式是 (開始時間, 結束時間)。動態任務在陣列中只會包含一個二元組，週期性任務則可能包含多個。二元組在陣列中的順序不重要。如果無法從這份任務陣列和給定的上下文切換負擔建立有效的排程，就引發`NoRtosStaticScheduleProducible`例外。請注意，變數的 Z3 模型結果在輸出之前必須先轉換成整數。如果 Z3 模型結果的型別是`IntNumRef`，可以使用`as_long()`這個類別方法將它轉換成整數。

另外還提供了一個函式，讓使用者可以視覺化任務的先後順序。只要在`check()`函式中把`plot`關鍵字引數設為`True`，就能針對個別測試案例啟用這個函式。這個函式會使用分段水平長條圖來繪製並標示每個任務。若要使用這個函式，必須安裝 Python 函式庫 *matplotlib*。*matplotlib* 的安裝說明可以在[這裡](https://matplotlib.org/stable/users/installing.html)找到。
