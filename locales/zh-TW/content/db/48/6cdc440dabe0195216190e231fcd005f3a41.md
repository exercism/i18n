# 關於

像`LocalDate`和`LocalDateTime`這樣的類別，描述的是時間上的*一個點*。`java.time`套件另外還有兩個類別，描述的是*一段*時間的量：

- [`Period`][period-docs]是以日期為基礎的時間量，以年、月、日表示，例如「2 個月又 5 天」。
- [`Duration`][duration-docs]是以時間為基礎的時間量，以時、分、秒、毫秒和奈秒表示，例如「1 小時 30 分鐘」。

這個差別很重要，因為日曆單位沒有固定的長度。一個月可能有 28、29、30 或 31 天，所以「一個月」並不是固定的秒數。`Period`依循日曆，而`Duration`測量的是確切的時間。

| | `Period` | `Duration` |
| --- | --- | --- |
| 儲存的內容 | 年、月、日 | 秒和奈秒 |
| 搭配使用的型別 | `LocalDate`、`LocalDateTime` | `LocalTime`、`LocalDateTime`、`Instant` |

這兩個類別都是不可變的。`plusDays()`或`multipliedBy()`這類方法會回傳一個*新的*實例，原本的實例則保持不變。

## `Period`

### 建立 Period

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

`toString()`的結果會採用 [ISO-8601 期間格式][iso-8601-durations]：`P`後面接著年數（`Y`）、月數（`M`）和日數（`D`）。`Period`裡沒有「週」這個單位：`Period.ofWeeks(2)`會存成 14 天。同樣的表示法可以用`Period.parse()`解析回來：

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### 把 Period 加到日期上

可以用`plus()`和`minus()`，把 Period 加到日期上，或從日期減去：

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

也可以用同樣的方式把 Period 加到`LocalDateTime`，而且一天當中的時間會維持不變：

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

`Instant`沒有日曆，所以只能加上以日為單位的 Period。帶有年或月的 Period 會拋出例外：

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

計算時會先加年，再加月，最後加日。當加上年或月之後，落在不存在的日期時，結果會退回到該月最後一個有效的日期：

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

這也代表，先加上一個 Period 再減掉同樣的 Period，不一定會回到原本的日期：

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### 兩個日期之間的 Period

`Period.between()`會回傳從某個日期（含）到另一個日期（不含）之間的 Period。`LocalDate.until()`也能得到同樣的結果：

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

Period 的各個部分可以透過`getYears()`、`getMonths()`和`getDays()`取得。這些部分彼此獨立：`getDays()`只回傳「日」的部分，而不是總天數。`toTotalMonths()`會把年和月合併成月數回傳，但沒有方法可以取得總天數，因為那取決於牽涉到哪些月份。

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### 正規化 Period

用工廠方法建立的 Period 會原封不動保留指定的單位，而`equals()`會逐一比較這些單位。`normalized()`會把月進位到年，但不會動到日：

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## 用`ChronoUnit`計算單位數量

如果想取得兩個時間點之間某個單位的總數，可以對 [`ChronoUnit`][chronounit-docs] 的其中一個常數呼叫`between()`方法：

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

只會計算完整的單位，而且當第二個引數早於第一個引數時，結果會是負數：

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit`也能用在以時間為基礎的單位和日期時間上：

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### 建立 Duration

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

在 ISO-8601 的表示法裡，`T`用來分隔日期部分和時間部分。`Duration`沒有日期部分，所以它的`toString()`一定以`PT`開頭。`Duration.ofDays()`會把一天當成剛好 24 小時。

Duration 也可以用`Duration.parse()`解析：

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### 把 Duration 加到時間上

可以用`plus()`和`minus()`，把 Duration 加到`LocalTime`、`LocalDateTime`或`Instant`上，或從中減去：

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

如同最後一個範例所示，`LocalTime`會繞過午夜。

`LocalDate`沒有時間，所以不能和`Duration`相加：

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### 兩個時間之間的 Duration

`Duration.between()`會回傳兩個時間或日期時間之間確切的時間量：

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()`不接受兩個`LocalDate`值，因為日期沒有秒可以測量：

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

處理日期時，請改用`Period.between()`或`ChronoUnit.DAYS.between()`。

### 轉換 Duration

`toXxx()`這類方法會把 Duration 轉換成單一單位的*總*量，並向下取整：

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

`toXxxPart()`這類方法會把 Duration 拆成各個部分，就像時鐘上一樣：

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()`最多只到 23，因為超過的小時會由`toDaysPart()`計算。

### 比較與計算 Duration

Duration 可以用`compareTo()`比較，也可以用`isZero()`和`isNegative()`檢查：

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

它們也支援算術運算，例如`plus()`、`minus()`、`multipliedBy()`和`dividedBy()`：

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## 該用`Period`還是`Duration`？

對`LocalDate`或`LocalTime`來說，這個選擇已經替你做好了：日期沒有時間可以測量，時間也沒有日曆。`LocalDateTime`兩者都有，但沒有時區，所以加上`Period.ofDays(1)`或`Duration.ofDays(1)`的結果是一樣的。一旦牽涉到時區，差別就會顯現出來。當日光節約時間把時鐘往前調時，日曆上的一天只有 23 小時：

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

加上一天的`Period`會維持一天當中的時間，而加上一天的`Duration`則是加上剛好 24 小時。當人們以日曆的角度思考時間量時（例如「下個月的同一時間」），請用`Period`；而在計算經過的時間時（例如「停車票有效 2 小時」），則用`Duration`。
