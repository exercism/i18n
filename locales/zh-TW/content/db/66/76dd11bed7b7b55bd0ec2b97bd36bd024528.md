# 精確數字

| 型別 | 可存放 | 限制 |
| --- | --- | --- |
| `INT` | 整數 | 恰好 32 位元 |
| `FLTD` | 分數 | 近似值 |
| `INTI` | 整數 | 記憶體 |
| `RAT` | 分數 | 精確 |

## INTI

```sather
   #INTI(42)
   #INTI("123456789012345678901234567890")
   a + b, a - b, a * b, a / b
   a < b, a = b
   #INTI(25).factorial
   #INTI(48).gcd(#INTI(18))       -- 6
   #INTI(2).pow(100)
   big.str
   small.int                      -- back to an INT, if it fits
```

對兩個`INTI`使用`/`就是整數除法，會捨去餘數，跟用在`INT`上完全一樣。

對一個大到`INT`放不下的值使用`.int`並不會回報這個問題。如果這點重要的話，請先檢查。

## RAT

```sather
   #RAT(1, 3)
   #RAT(6)                        -- from a whole number
   a + b, a - b, a * b, a / b
   a < b, a = b
   r.is_int                       -- is it a whole number?
   r.is_zero, r.is_pos, r.is_neg
   r.abs, r.negate
   r.floor                        -- an INTI, rounded down
   r.str
```

`RAT`一律會化為最簡分數，而且一律把符號放在分子上：`#RAT(1, -2)`就是`-1/2`。兩個`RAT`只有在代表相同分數時才相等，所以`=`的行為正合你意，這正是它和`FLTD`的根本差異。

`RAT`建立在`INTI`之上，所以它的分子和分母也沒有大小限制。把許多分母不同的分數相加，會讓它們越變越大，因為每次相加都會先把分母相乘，再進行約分。

`ceiling`已經宣告，但會拋出「not implemented」。請改用`floor`再自行調整。

## 如何選擇

當某個數量可能超過二十億時，就用`INTI`：階乘、次方、組合數、長時間累計的總和。

當分數必須精確，而且分母不算太大時，就用`RAT`：份額、機率、音符時值，以及任何否則會累積捨入誤差的東西。

預設上兩者都不必用。`INT`和`FLTD`快得多，而且大多數運算並不需要更多。

處理金錢時，兩者通常都不是標準做法：改用`INT`，以整分為單位來計算。
