# 簡介

我們在前面的概念中看到，Julia 裡的型別會構成一個階層，最頂端是 `Any`。

像是 `Number` 這樣的抽象型別有子型別，但本身無法被實例化。
把變數的型別設成某個抽象型別，會_限制_這個變數的值只能是該抽象型別的子型別。
例如：

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

這提供了一種彈性，讓我們能限制哪些輸入是有效的。

不過，假設我們希望某個變數同時接受整數和字串呢？
這兩個型別在階層中並不屬於同一個分支。

我們可以把型別設成 `Any`，或讓它預設就是 `Any`，但這麼一來就完全失去了對允許型別的控制。

更好的做法是使用 `Union{ }` 語法，在大括號內列出兩個以上的型別。

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

另一個例子在函式簽章裡使用了同樣的型別聯集：

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

在這裡，我們幫這個型別取了一個名字，這麼做能提供方便的簡寫，但並不是絕對必要。
函式 `g(z::Union{Integer, String}) = z^3` 的行為完全相同。

關於函式簽章，在多重分派這個概念裡還有更多可以談。

## 與 nothing 的聯集

其他幾種語言有「可能含有值、也可能不含值」的型別，名稱像是 `Option`、`Nullable` 或 `Maybe`。

Julia 沒有專門的語法來表達這件事，但型別聯集正是同一個想法的推廣。

我們在 `Nothingness` 這個概念裡看到，Julia 有各種方式來表示「沒有值」，包括 `nothing` 和 `missing`。
兩者都可以放進型別聯集裡。

例如，在定義某種鏈結串列時，我們需要一種方式，在沒有後續節點時結束這個串列。
`Nothing` 是只有單一值 `nothing` 的型別，下面這個 Node 定義讓我們能表示鏈結的結尾：

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

同樣地，`missing` 可以當成缺少值的佔位符，特別是在向量這類集合裡。
下面這個例子非常刻意，但缺少值在真實世界的資料集中很常見。

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
