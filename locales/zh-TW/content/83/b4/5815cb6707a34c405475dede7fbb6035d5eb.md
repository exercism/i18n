# 深入說明

純量程式碼會依賴各種指令所設定的旗標，藉此依特定條件進行分支。
然而，封裝值代表的不是單一個值，而是平行處理的許多值。
同一個條件可能在某個通道不成立，在另一個通道卻成立。

這就是為什麼 SIMD 程式碼預設是[無分支][branchless-code]的。

封裝比較通常不依賴旗標，而是在目的運算元中產生一個**遮罩**。
對每個通道而言，比較結果為真時會把整個通道填滿 1，為假時則填滿 0。
若以帶正負號的整數來解讀，為真的通道是 `-1`，為假的通道則是 `0`。

接著就能把這個遮罩與[位元運算][simd-bitwise]結合，藉此篩選特定的通道。

## 封裝比較

純量的 `cmp` 之所以泛用，在於它能同時設定多個旗標。
接著其他指令就能取用這些旗標，進行分支或執行運算。

不過，封裝比較同時檢查條件並計算遮罩，因此並不泛用。
比較必須明確指定要測試的條件。

做法有兩種：

- 整數比較把條件寫成後綴：`eq` 代表相等，`gt` 代表大於。
  其他變體則是組合其中之一的結果建構而成。
- 浮點比較則把條件編碼在立即值中。
  這個立即值的不同數值，對應到不同的受測條件。

除了整數比較使用特定的條件後綴之外，語法結構與我們先前看過的相同：

- 整數的部分是 `p` + `cmp` + 條件 + 大小（`b`、`w`、`d` 或 `q`）。
- 浮點的部分是 `cmp` + `p` + 大小（`s` 或 `d`）。
  條件則以額外運算元的形式，透過立即值傳入。

### 整數比較

如前所述，整數比較只有相等與大於兩種：

| 指令                                       | 說明                             |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | 逐通道相等                       |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | 逐通道**帶正負號**的大於         |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

要建立小於的比較，就把運算元對調後使用 `gt`：`a < b` 等同於 `b > a`。

請注意，這個比較是**帶正負號**的。
若要執行不帶正負號的比較，就把兩個運算元的最高位元翻轉。
做法是與一個只有最高位元設為 1 的遮罩做 XOR。

~~~~exercism/note
有兩個好用的慣用技巧：

1. 把暫存器與自己做 XOR，得到全部為 0 的結果。
2. 把暫存器與自己比較，得到全部為 1 的結果。

例如：

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

全 0 與全 1 是常見的遮罩，分別用來表示「全部為假」與「全部為真」。
它們也可以用來表示封裝的 `0` 或封裝的 `-1`，這些是常見的哨兵值。
例如，標記字串結尾的 NUL 就是 `0`。
~~~~

### 浮點比較

浮點通道採用不同的形式：單一指令 `cmpps`（64 位元通道則用 `cmppd`），並把條件放在立即值中：

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM 也提供對應到正確立即值、而且更容易記住的偽指令。
在下列所有項目中，`px` 裡的 `x` 可以是 `s`（32 位元浮點數）或 `d`（64 位元浮點數）：

| 偽指令       | 立即值    | 比較                   |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a 是 NaN 或 b 是 NaN   |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | a 與 b 都不是 NaN      |

~~~~exercism/caution
NaN 的比較是無序的：它不小於、不等於、也不大於任何東西，連與自己比較也一樣。
有序謂詞（例如 `cmpltps`）在任一運算元為 NaN 時會得到假，而無序謂詞則會得到真。
`cmpordps` 與 `cmpunordps` 之所以存在，就是為了明確測試 NaN。
~~~~

## 用遮罩做選擇

遮罩會把某個條件的結果編碼起來。
接著就能依據這個條件，逐通道在兩組值之間做選擇。
遮罩為真時，我們取用其中一個值的通道；為假時，則取用另一個值的通道：

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

這個模式就是無分支選擇的封裝形式。
每個通道都會被計算，單靠遮罩決定哪個值留存下來，完全不需要任何 `jcc`。

## 專用的混合指令

有些指令可以直接執行同樣的選擇，從遮罩暫存器為每個元素讀取一個位元。
這些叫做**混合指令**：

| 指令        | 元素        | 遮罩來源         |
|-------------|-------------|------------------|
| `pblendvb`  | 位元組      | 隱含的 `xmm0`    |
| `blendvps`  | 32 位元通道 | 隱含的 `xmm0`    |
| `blendvpd`  | 64 位元通道 | 隱含的 `xmm0`    |

請注意，第一個指令遵循整數語法，另外兩個則遵循浮點語法。
不過，由於這些指令只是單純挑選原始位元組，因此三者都能同時用於整數與浮點。

對每個元素而言，當對應遮罩元素的最高位元為 0 時，混合指令會保留目的運算元；為 1 時則取用來源運算元。
只會參考那個**最高位元**，而比較產生的遮罩正好符合這點，因為它的通道不是全 1 就是全 0。
遮罩暫存器一律是 `xmm0`，而且是隱含的：

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

也可以使用 `pblendvb`，從任何大小的比較遮罩中挑選通道。
由於為真的通道裡每個位元組都是全 1，`pblendvb` 會把這些位元組全部選進來。

~~~~exercism/note
這些指令都是在所執行的操作（`blend`）之後加上 `v`。
這個 `v` 代表 _variable_，也就是「可變」的意思，因為選擇並非固定不變，而是取決於暫存器。

也有不帶 `v` 的變體，改依立即值來做選擇。
它們遵循同樣的模式：若立即值的第 `i` 個位元為 1，就選取通道 `i`。
~~~~

## 從遮罩回到純量

SIMD 程式碼雖然強大，卻少了純量程式碼的許多彈性。
在許多情況下，必須從封裝暫存器回到純量指令的世界。

`movmsk` 系列指令就是這兩個世界之間的橋樑。
這些指令會把每個通道的**最高位元**擷取到通用暫存器中：

| 指令        | 蒐集的內容                   | 結果寬度 |
|-------------|------------------------------|----------|
| `pmovmskb`  | 16 個位元組各自的最高位元    | 16 位元  |
| `movmskps`  | 4 個雙字組各自的最高位元     | 4 位元   |
| `movmskpd`  | 2 個四字組各自的最高位元     | 2 位元   |

若接在比較之後使用，每個設為 1 的位元代表一個「真」的通道，每個清為 0 的位元則代表一個「假」的通道。
接著就能一如往常地用純量指令來處理這個結果。
例如，`popcnt` 可以數出相符的數量，`tzcnt` 則找出第一個相符的位置。

通用暫存器可以是 32 位元或 64 位元寬。

## 測試整個向量

純量指令 `test` 也有封裝版本：`ptest`。

它與純量版本相似，同樣會對兩個運算元執行 AND 運算，但不修改它們。
與 `test` 不同的是，`ptest` 還會執行 ANDN 運算，把第一個運算元取反。

因此，可以把 `ptest` 想成 `pand` 與 `pandn` 的非破壞性版本，會依結果設定旗標。
`ptest` 的處理方式與這兩個指令大致相同，會把整個 SIMD 暫存器視為單一通道，因此不帶大小前綴。

若 AND 運算的結果為 `0`，就會設定 `ZF`；若 ANDN 運算的結果為 `0`，設定的則是 `CF`。
這表示 `ptest` 可以用來檢查全 1 與全 0 兩種遮罩：

1. 把 `ptest` 用在暫存器與自己身上時，唯有暫存器全為 0 才會設定 `ZF`。
   這沿用了純量常見的慣用技巧：用 `test` 比較暫存器與自己來檢查是否為 `0`。
2. 把 `ptest` 用在暫存器與全 1 遮罩上時，唯有暫存器全為 1 才會設定 `CF`。
   此外，唯有暫存器全為 0 才會設定 `ZF`，因此可以一次檢查兩種遮罩。

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

`ptest` 的結果一如往常，可以用來分支，或用在 `setcc`、`cmovcc` 這類無分支指令中。

## AVX 與後續發展

AVX 為比較、混合與 `ptest` 提供了加上 `v` 前綴、作用於更寬暫存器的形式。

可變混合的形式有所改變。
遮罩不再是隱含的 `xmm0`，而是明確的第四個運算元：

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

AVX-512 擴充更深入地改變了這個模型。

首先，它新增了一類 64 位元組的 SIMD 暫存器，稱為 `zmm`。
它們會擴充對應的 `ymm` 暫存器，就像 `ymm` 暫存器擴充 `xmm` 暫存器一樣。

其次，這些擴充還創造出一整類全新的 **opmask 暫存器**，從 `k0` 到 `k7`，主要用途是作為 SIMD 指令的遮罩。
比較不再寫入向量，而是寫入這些新暫存器之一。
它們也可以在許多指令上直接當作謂詞，搭配 `{k}` 寫入遮罩，_直接_選取通道：

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

最後，還有新的指令可以操作這些新暫存器，包括將它們複製到通用暫存器中。
這讓 `movmsk` 指令變得不再必要，而且 `zmm` 暫存器也不支援 `movmsk` 指令。

提到這些擴充只是為了內容完整。
這個學習軌道裡的練習使用的是 SSE 形式。
