# 指令

現在是赫爾碼頭的夜班時分。貨輪 *Olwen* 停泊在碼頭邊，一群碼頭工人正同時處理貨物清單。每個木箱在上船前都必須先秤重，而港務長維護著一份持續更新的**噸位統計**，每一次吊掛都會更新它。問題是：碼頭邊只有一座起重機，所以不能讓兩位碼頭工人同時更新而撕裂這份統計。

每個木箱都是一個裝著貨物重量的陣列。木箱的重量就是箱內所有項目的總和。

## 1. 秤一個木箱

定義`weigh-crate`，它接受一個木箱並回傳總重量。這是單純的循序作業：一個木箱進，一個數字出。

```factor
{ 12 8 15 } weigh-crate .
! => 35
```

## 2. 平行秤完整份清單

定義`weigh-all`，它接受一個木箱陣列，並依相同順序回傳這些木箱重量的陣列。使用`parallel-map`，讓每個木箱的處理能同時進行。

```factor
{ { 5 5 } { 10 } { 3 4 5 } } weigh-all .
! => { 10 10 12 }
```

## 3. 打造一座全新的起重機

定義`<crane>`來建構一座新的起重機：一個帶有全新`<lock>`和噸位`0`的元組。起重機是共享資源，後續的任務都會保護它。

```factor
<crane> tonnage>> .
! => 0
```

## 4. 把木箱吊掛到累計噸位上

定義`hoist-crate`，它接受一個`weight`和一個`crane`，並**在起重機的鎖之下**把該重量加到起重機的噸位中，讓讀取、相加、寫入這串動作相對於其他同時吊掛的碼頭工人而言是原子性的。

```factor
<crane>
35 over hoist-crate
17 over hoist-crate
tonnage>> .
! => 52
```

## 5. 讀取累計噸位

定義`crane-tonnage`回傳起重機目前的噸位，同樣要在鎖之下進行，這樣讀取時就不會看到吊掛到一半被撕裂的值。

```factor
<crane>
35 over hoist-crate
crane-tonnage .
! => 35
```

## 6. 裝載貨物

定義`load-cargo`，它接受一個木箱陣列和一座起重機，並**為每個木箱各生成一個碼頭工人執行緒**，負責秤該木箱的重量並把重量吊掛到起重機上。這個詞只有在所有碼頭工人都完成後才會回傳。使用`<promise>`和`?promise`來協調會合。

```factor
<crane> :> crane
{ { 5 5 } { 10 } { 3 4 5 } } crane load-cargo
crane crane-tonnage .
! => 32
```
