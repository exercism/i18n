# 關於

`String`和`&str`是 Rust 中處理文字資料的兩種基本方式。了解它們各自的特性，以及它們如何搭配運作，會非常實用。本文件會討論它們重疊的地方，並提供一些基本建議。

`String`是一個擁有所有權的`u8`位元組向量。
`String`是可變的。
`&str`是指向 String 切片的借用參考。
`&str`是不可變的。

`&str`的正確唸法是「ref string」。
`String`是一段以 UTF-8 編碼、可能可變的 Unicode 碼位序列表示。

`&str`是格式良好的 UTF-8 序列的唯讀檢視。
因為它是參考，所以是`Copy`，可以共用。

在 Rust 中，`String`和`&str`不能像在其他語言那樣用索引取值。
舉例來說，下面這段程式碼無法運作：

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

這源自以下幾項特性：

- 字串是 UTF-8，其基本單位不是位元組，而是 Unicode 碼位：`char`。
- Unicode 碼位最寬可達 4 個位元組，但編碼後的寬度是可變的。
- 因此，若不實際疊代編碼後的字元，就無法計算第`n`個碼位的位置，因為過了第一個字元之後，下一個字元的位置取決於前幾個字元的寬度。
- 因此，Rust 標準函式庫的作者選擇不為字串實作`Index`特徵：對位元組陣列取索引只需常數時間，但對字串取索引可能得花上相當長的時間。這違反了最小驚訝原則。

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## 將`String`轉換成`&str`

`String`實作了`Deref<Target=str>`。
這個特徵有一些編譯器特殊處理：這代表任何指向`String`的參考都能自動且透明地被強制轉型成`&str`。
這意味著以下幾點：

- 比如說，任何預期收到`&str`引數的程式碼，都可以改為接受`&String`。
- 任何為`&str`實作的方法，也能在`String`上呼叫。

（如果想以泛型方式接受任何形式的`str`參考，可以把引數型別寫成`impl AsRef<str>`，但一般來說，把引數型別寫成`&str`較為常見。）

## 將`&str`轉換成`String`

從`&str`建立`String`的方法有很多種：

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

上述所有方法都需要為`String`配置記憶體（在堆積上）。
這就是為什麼`&str`在 no_std 中可以使用，而`String`不行。

（在 no_std 中操作字串時，經常會使用 [heapless](https://crates.io/crates/heapless) 套件。）

## 在結構體中使用 String 和`&str`

本節討論結構體的欄位何時該用`String`、何時該用`&str`。
你經常會看到結構體的欄位值用`String`定義，而不是`&str`。

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

使用`String`時，結構體會擁有這些資料。
這讓程式碼更容易閱讀，對初學者來說也更容易教學。
但這也代表每個欄位都會進行堆積配置。
`&str`借用文字資料，因此效能較好，但代價是你的結構體必須定義生命週期參數。
[csv 套件教學][csv-tutorial] 具體地示範並說明了這些概念，相當不錯。

## 效能注意事項

`String`配置在堆積上，因此使用起來成本可能較高。
`&str`是共用參考，因此不需要頻繁地重新配置。
