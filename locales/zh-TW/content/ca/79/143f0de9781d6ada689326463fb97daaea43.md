# 關於

在課程大綱進行到這裡時，你已經看過許多函式定義了。
通常，這些定義並沒有多加說明 REPL 中顯示的輸出：

```julia-repl
julia> f(x) = x^2
f (generic function with 1 method)
```

為什麼會出現「_generic function with 1 method_」呢？

假設我們想更精確地指定引數的型別。

```julia-repl
julia> f(x::Integer) = x^2
f (generic function with 2 methods)

julia> f(x::Real) = x^2
f (generic function with 3 methods)
```

或者，我們也可以改變引數的數量：

```julia-repl
julia> f(x, y) = x * y
f (generic function with 4 methods)
```

看來同一個函式的新定義被稱為「方法」。
方法會被加入一份清單中，而不是覆蓋掉舊的定義。

我們可以輕鬆列出所有方法：

```julia-repl
julia> methods(f)  # output edited for brevity
# 4 methods for generic function "f" from Main:
 [1] f(x, y)
 [2] f(x::Integer)
 [3] f(x::Real)
 [4] f(x)
 ```

當我們呼叫函式`f`時，Julia 似乎知道該使用哪個方法：

```julia-repl
julia> f(2.5)  # Float64
6.25

julia> f(2)  # Int64
4

julia> f(2, 3)  # Int64, Int64
6
```

## 什麼是函式？

根據[手冊][function]，函式是一個把引數元組對應到回傳值的物件。
這和數學家使用的定義很接近。

我們通常會把`f(2, 3)`裡的函式引數想成兩個獨立的項目，但編譯器把它們視為一個[元組][tuple]。
即使只有一個引數也是如此（不過我們得加上逗號才能看得更清楚）：

```julia-repl
julia> typeof( (2, 3) )
Tuple{Int64, Int64}

julia> typeof( (2,) )
Tuple{Int64}
```

把函式看成一個黑盒子，我們可以說元組進去、回傳值出來。
更正式地說，元組會被_映射_到一個回傳值。

## 函式如何處理不同數量與型別的引數？

這通常被稱為[「多型」][polymorphism]。

幾十年來，這一直是資訊科學裡的重要主題，也發展出各種不同的做法。

Julia 的做法很不尋常，但並非獨一無二。

- 函式是[「泛型」][generic]的，意思是同一個函式可以附掛多個方法。
- 在附掛方法之前，函式就只是一個名字。
- 方法可以視需求新增，數量可能很多（目前 `+` 運算子就是一個擁有 161 個方法的函式）。
- 呼叫函式時，Julia 會檢查呼叫簽章：引數的數量，以及每個引數當下的型別。
- 最後會選出與呼叫簽章最相符的方法。
  - 一般來說，引數數量必須完全相符（不過 [splat/slurp][splat] 運算子 `...` 可以部分繞過這項限制）。
  - 型別與呼叫簽章完全相符的方法會優先採用。
  - 必要時，Julia 會沿著呼叫簽章中每個引數的超型別往上找，找出最相符、最具體的方法。
- 選中的方法會與給定的引數一起被[`dispatched`][dispatch]，然後回傳一個結果。
- 如果找不到合適的方法，就會拋出 [`MethodError`][methoderror]。

要注意的是，Julia 是動態型別的語言，所以方法派發發生在_執行期_。

## 多重派發：一個範例

上一節講了很多文字，現在把它們轉換成程式碼吧。
為了簡單起見，下面這些函式都只有一個引數，但擁有數十個引數的函式並不罕見（例如繪圖套件或機器學習領域）。

首先定義一些自訂型別，用來表示幾何圖形。

```julia-repl
julia> abstract type Shape end

julia> struct Circle <: Shape
           radius::Float64
       end

julia> struct Square <: Shape
           side::Float64
       end

julia> struct Rectangle <: Shape
           length::Float64
           width::Float64
       end
```

接著，我們可以定義方法來計算每個圖形的面積。
每個方法都只接受一個引數，而且每個引數都是不同的具體使用者自訂型別。

```julia-repl
julia> area(c::Circle) = π * c.radius^2
area (generic function with 1 method)

julia> area(s::Square) = s.side^2
area (generic function with 2 methods)

julia> area(r::Rectangle) = r.length * r.width
area (generic function with 3 methods)
```

現在我們可以建立幾個圖形並計算面積，全靠 Julia 的派發機制為每個圖形選用正確的公式。

```julia-repl
julia> circle = Circle(2.3)
Circle(2.3)

julia> area(circle)  # call signature Tuple{Circle}
16.619025137490002

julia> square = Square(1.6)
Square(1.6)

julia> area(square)  # call signature Tuple{Square}
2.5600000000000005

julia> rectangle = Rectangle(1.4, 2.1)
Rectangle(1.4, 2.1)

julia> area(rectangle)  # call signature Tuple{Rectangle}
2.94
```

## [參數化方法][parametric]

方法簽章可以接受虛擬的型別值，大致上就和參數化型別一樣。

這種語法很特別，需要一個 `where` 子句：

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T} = true
same_type (generic function with 1 method)

julia> same_type([1, 2], 3)
true

julia> same_type([1, 2], "three")
ERROR: MethodError: no method matching same_type(::Vector{Int64}, ::String)
```

上面的例子要求兩個引數都使用相同的型別 `T`，不論 `T` 究竟是什麼。

我們可以對 `T` 加上限制，讓它更明確：

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T<:Number} = true
same_type (generic function with 2 methods)
```

使用這個方法時，只有型別完全相同的數值才會回傳 `true`。

也可以使用多個虛擬變數，以逗號分隔放在 `where` 子句中。
下面這兩個方法看起來很相似：

```julia-repl
julia> func(v::Vector{Number}, x::Number) = true
func (generic function with 1 method)

julia> func(v::Vector{S}, x::T) where {S<:Number, T<:Number} = true
func (generic function with 2 methods)
```

其中一個差別是，第二個方法可以在函式主體裡使用型別值 `S` 和 `T`。
這種技巧你可能不常使用，但在某些情況下能省下不少麻煩。

舉例來說，在下面的參數化型別定義中，各個欄位必須是相同的型別 `T`，而 `T` 被限制為 `Real` 的子型別：
```julia
struct Point{T<:Real}
    x::T
    y::T
end
```
這個 `Point` 定義可以接受型別相同的 `x` 和 `y`，也可以接受型別不同的 `x` 和 `y`，但這時必須提供明確的轉換型別。
```julia-repl
julia> Point(4, 5)
 Point{Int64}(4, 5)

julia> Point(3.5, 2)
 MethodError: no method matching Point(::Float64, ::Int64)    # Output truncated for brevity

julia> Point{Float32}(3.5, 2)
 Point{Float32}(3.5f0, 2.0f0)

julia> Point{Int64}(3.5, 2) 
 InexactError: Int64(3.5)      # Output truncated for brevity
```
雖然這種程度的型別控制可能很理想，但有一點抽象也很有用。
```julia
Point(x::T, y::S) where {T<:Real, S<:Real} = Point{promote_type(T,  S)}(x, y)
```
這個外部建構子就提供了這樣的功能：讓 `Point` 可以接受型別不一致的 `x` 和 `y`，而不必明確指定轉換型別。
型別值 `T` 和 `S` 會在函式主體裡的 `promote_type(T, S)` 中使用，為原本的定義提供明確的轉換型別。
```julia-repl
julia> Point(3.5, 2)
 Point{Float64}(3.5, 2.0)
```

## 與其他語言的比較

因為 Julia 在選擇方法時會檢查所有引數，所以這被稱為[`multiple dispatch`][multiple-dispatch]。

少數其他語言也支援多重派發，例如 Common Lisp，不過它很少像在 Julia 裡那樣成為語言設計的核心。

相對地，在物件導向（OO）語言中（例如 Ruby），方法通常是對某個[實例][instance]呼叫。
這種定義方式把第一個引數視為優先（在定義中通常命名為 `self` 或 `this`），呼叫時則把方法名稱用點號接在實例後面：

```ruby
irb(main):004:0> "abc".sub("b", "*")
=> "a*c"
```

這稱為[`single dispatch`][single-dispatch]，因為只會用實例的類別（上面例子裡是字串 "abc"）來選擇方法。

有些靜態型別的物件導向語言支援方法的多型，看起來與多重派發有點相似。
最大的差別在於，方法選擇只發生在_編譯期_。

函式語言通常只有單一的函式定義，再搭配某種 Select/Case/Match 運算式來處理各種可能的情況。
你得自行撰寫邏輯，通常會借助簡潔的模式比對語法，而這種語法在 Julia 中並不存在。
當然，Julia 也做某種形式的模式比對，只不過是在派發時進行，而不是在函式主體內。

## 結論

多重派發在 Julia 中既靈活又高效，因此被廣泛使用。

就像 `+` 有 161 個方法這個例子所顯示的，Julia 程式設計師會盡量定義型別範圍狹窄的方法。
在位元碼層級，兩個整數相加和兩個浮點數相加完全不同，而把整數加到浮點數上還多了一層型別提升的麻煩。

型別越具體，編譯器能進行的最佳化就越多：在 Exercism 的小型練習裡影響不大，但對 Julia 所針對的大型數值模擬來說，效能上至關重要。

_如果你知道某個方法會收到什麼輸入，請告訴編譯器！_
