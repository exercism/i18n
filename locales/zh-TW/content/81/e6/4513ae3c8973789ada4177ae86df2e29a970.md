# 說明補充

## `from_quote`的優缺點

這個練習在`DateOfBirth`型別中定義了一個`from_quote`函式。這麼一來，就可以寫出像這樣的程式碼：

```roc
birthdate : DateOfBirth
birthdate = "2019-01-20"
```

這段程式碼會在編譯期隱式呼叫`DateOfBirth.from_quote("2019-01-20")`。這有可能加快程式的速度，因為它不需要在執行期處理剖析；而且能確保被`from_quote`拒絕的日期在編譯期就被攔下，而不是等到執行期才發現。此外，這也讓程式碼既簡潔又好讀。舉例來說，以下是這個練習的其中一個測試：

```roc
# multiple birthdates with one shared birthday
expect {
	shared_birthday(["1966-07-29", "1977-02-12", "2001-07-29", "1980-11-10"])
}
```

不過，讀到這段程式碼的人可能會以為`shared_birthday`函式接受的是`List(Str)`，但實際上它接受的是`List(DateOfBirth)`。這可能會造成混淆和錯誤。因此，你可能會偏好稍微長一點、但更明確的寫法：`"2019-01-20".DateOfBirth`，它同樣會在編譯期呼叫`from_quote`。

在你自己的程式裡，你可能會想提供一個方便的建構子，像這樣：

```roc
DateOfBirth := { year : I64, month : U8, day : U8 }.{
    from_ymd : I64, U8, U8 -> Try(DateOfBirth, [InvalidMonth, InvalidDay])
    from_ymd = |year, month, day| ...
}
```

你也可以在編譯期呼叫這個建構子，像這樣：

```roc
Ok(birthdate) = DateOfBirth.from_ymd(2019, 1, 20)
```

注意：把這個定義放在最上層，會讓它在編譯期執行（因為這個函式是純函式，而且輸入在編譯期就已知）。在函式內部，你可以在執行期使用同一個建構子。
