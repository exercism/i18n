# 關於

Swift 雖然有許多不同的型別，但這些型別都隸屬於兩種不同的分類之一：_值型別_和_參考型別_。在 Swift 中，[結構是值型別][structs-are-value-types]，而[類別是參考型別][classes-are-reference-types]。

值型別與參考型別最主要的差異在於：把值型別指定給變數或常數，或是傳入函式時，真正被指定或傳入的其實是該值的複本，而不是那個值本身。修改結構的其中一份複本並不會影響其他複本。至於參考型別，被指定或傳入的是指向該值的參考，所以兩個不同的名稱可以指向同一個類別的實例。這樣一來，當你透過另一個名稱存取時，就可能改動到原本的實例。

那麼，以遊戲中定義角色的結構與類別，以及它們的遊戲數值為例，我們可以看看這些東西被複製與修改時會發生什麼事。

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

注意修改`charB`的屬性如何連帶影響了`charA`的屬性，因為這兩個名稱指向同一個實例。也注意，就這兩個角色的數值來說，參考型別內部的值型別會隨參考型別一起改變。不過，這並不違反值型別的行為，因為`charA.stats`和`charB.stats`是同一個`CharacterStats`實例，畢竟`charA`和`charB`指向同一個`GameCharacter`類別的實例。舉例來說，我們可以看到，這些值型別的複本彼此不會互相影響。

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

這就是為什麼結構會要求，在會改變結構屬性狀態的方法前面加上`mutating`關鍵字。修改結構的屬性實際上會建立一份新的結構複本，為該屬性設定新的值，再以新的複本取代舊的複本。這是一種視覺提示，表示這種型別的值可能會發生這樣的複製與取代。

這會帶來一個副作用：只要結構實例的可變屬性會改變，無論是透過呼叫 mutating 函式或直接賦值，都_必須_把該實例指定給變數，而不是常數。否則就會產生編譯器錯誤：

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

初始值仍然可以建立與存取，只是不允許改變。這項限制不適用於類別。如果用`let`把類別的實例指定給某個名稱，常數持有的是指向該實例的參考，因此不能改變的是那個參考，而不是實例本身。所以實例本身可以改變，但參考不能改成指向另一個實例。

以下總結以`let`或`var`定義的結構與類別，各自有哪些地方可以改變：

|         | **struct**                                                                                  | **class**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _不能_把新的結構指定給這個名稱。</br>_不能_修改結構的任何屬性。 | _不能_把新的類別指定給這個名稱。</br>_可以_修改類別的可變屬性。 |
| **var** | _可以_把新的結構指定給這個名稱。</br>_可以_修改結構的可變屬性。   | _可以_把新的類別指定給這個名稱。</br>_可以_修改類別的可變屬性。    |

## 身分

由於兩個不同的名稱可能持有同一個類別實例的參考，有時會需要測試是不是這種情況。Swift 用`===`這個_身分_運算子來測試（以及它的否定運算`!==`）。

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

由於沒有兩個名稱能指向同一個結構實例，結構並沒有定義這些身分運算子。

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

請注意，身分和相等並不相同。依許多定義，`char1`和`char3`會被視為相等，因為它們所有的屬性都持有相同的值，但它們並不共享相同的身分。在 Swift 中，所有類別都會自動提供身分，但開發者通常需要自行撰寫相等運算子，來判斷結構或類別的兩個實例是否_相等_。這超出了本練習的範圍。
