# 關於

Go 的切片和其他語言的陣列很像。
切片可以存放多個特定型別（或介面）的元素。

Go 的切片是以陣列為基礎。
陣列的大小是固定的。
切片則不同，它是對陣列元素的一種大小可動態調整、有彈性的檢視。

切片寫成`[]T`，其中`T`是切片中元素的型別：

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

你可以用方括號的寫法，取得或設定某個從 0 開始的索引上的元素：

```go
withData[1] = 5
x := withData[1] // x is now 5
```

你可以從既有的切片建立新的切片，做法是取出一段元素範圍。
同樣是用方括號，但要同時指定起始索引（含）和結束索引（不含）。
如果沒有指定起始索引，預設值為 0。
如果沒有指定結束索引，預設值為切片的長度。

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

你可以使用`append`函式把元素加入切片。
下面我們把`4`和`2`加到`a`切片。

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append`總是回傳一個新的切片。當我們只是想在某個既有切片上附加元素時，常見的做法是把它重新指定回我們當成第一個引數傳入的那個切片變數，就像上面那樣。

`append`也可以用來合併兩個切片：

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## 切片中的索引

處理切片的索引時，一定要用某種檢查來保護，確保該索引確實存在。
如果沒這麼做，整個應用程式就會崩潰。

## 空切片

`nil`切片是預設的空切片。
相較於內容沒有任何值的切片，它沒有任何缺點。
`len`函式可以作用在`nil`切片上，可以在沒有初始化它的情況下加入項目，諸如此類。
如果要建立新的切片，請優先使用`var s []int`（`nil`切片），而不是`s := []int{}`（空的非`nil`切片）。

## 效能

當你要建立會逐步填入內容的切片時，如果事先知道切片最終的大小，就有一個唾手可得的效能改善機會。
關鍵在於盡量減少記憶體必須被配置的次數，因為這件事相當耗費成本，而且只要切片成長到超過已配置的記憶體空間，就會發生。
最保險的做法是用`s := make([]int, 0, cap)`來指定切片的容量`cap`，然後照平常的方式`append`到切片裡。
這樣一來，`cap`個項目的空間會立刻被配置好，而切片的長度仍然是零。
實務上，`cap`常常就是另一個切片的長度：`s := make([]int, 0, len(otherSlice))`。

## append 不是純函式

Go 的`append`函式為了效能而做了最佳化，因此不會複製輸入的切片。
這表示原本的切片（`append`的第 1 個參數）有時會被改變。
