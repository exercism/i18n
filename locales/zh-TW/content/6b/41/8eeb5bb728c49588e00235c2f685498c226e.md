# 關於

嚴格來說，[`Higher Order Function`][HOFunc] 就是一種函式，只要符合下列其中一項即可：

- 接受一個函式作為其中一個引數。
- 回傳一個函式作為結果。

在函式程式設計的世界裡，這個詞的用法通常比較狹義。
它通常指的是`filter`、`map`和`reduce`這類函式，它們會把傳入的函式套用到集合中的每個元素上。

## 對集合進行操作

在課程大綱的這個階段，我們已經看過幾種把某個運算套用到可迭代集合（例如 Vector）所有元素上的方法：

- 使用[迴圈][loops]（就像自數位運算問世以來大多數程式語言的做法）。
- 使用[推導式][comprehensions]（Python 風格）。
- 使用[廣播][broadcasting]（Julia 特有的語法，雖然很大程度上承襲自 R、Matlab 和 NumPy）。

這個概念會聚焦在高階函式（在任何函式語言，例如 Haskell 或 F#，都見得到）。

其他可能的方法包括：

- 遞迴（如同 ML 系語言的做法）。 
  - Julia 允許這麼做，但少了尾端呼叫最佳化，會有堆疊溢位的風險。
- 使用巨集的超程式設計（傳統上是 Lisp 的特色）。 
  - 這在進階的 Julia 程式設計中用得很廣，但大多數情況下要_謹慎使用_。 
  - 其他做法通常比較好寫，除錯起來也輕鬆得多。

## 篩選

[`filter()`][filter] 函式會接受一個回傳布林值的傳入函式，並把它套用到集合上。
只有回傳`true`的元素會被納入回傳值，而回傳值的基本型別和輸入相同（見下文）。

```julia-repl
julia> filter(iseven, 1:6)
3-element Vector{Int64}:
 2
 4
 6

# String is a collection of Chars, so String in -> String out
julia> filter(!isascii, "Hrōðgār")
"ōðā"

# tuple input -> tuple output
julia> filter(iseven, (1, 2, 3, 4, 5))
(2, 4)
```

對多維陣列來說，`filter` 會把輸入的維度攤平，並回傳一個 Vector：_這是輸出型別要與輸入型別相符這條規則的主要例外_。

```julia-repl
julia> m
2×3 Matrix{Int64}:
 1  2  3
 4  5  6

julia> filter(isodd, m)
3-element Vector{Int64}:
 1
 5
 3
```

上面的例子用的是內建函式，但在這種情境下，使用[匿名函式][anonymous]也非常常見。

```julia-repl
julia> filter(x -> x % 3 == 0, 1:20)
6-element Vector{Int64}:
  3
  6
  9
 12
 15
 18
```

也有原地修改的版本 [`filter!()`][filter-bang]，就像這個概念裡的許多函式一樣。

## 映射

[`map()`][map] 函式會對每個元素套用一個函式，藉此轉換集合。
在簡單的情況下，這可能和[廣播][broadcasting]很像，輸出的形狀會和輸入相符。

```julia-repl
julia> map(√, [1, 4, 9])
3-element Vector{Float64}:
 1.0
 2.0
 3.0

julia> map(x -> x^2 + 1, 1:4)
4-element Vector{Int64}:
  2
  5
 10
 17

julia> m
2×3 Matrix{Int64}:
 1  2  3
 4  5  6

julia> map(√, m)
2×3 Matrix{Float64}:
 1.0  1.41421  1.73205
 2.0  2.23607  2.44949
```

`map()` 也能對多個集合逐元素操作。

```julia-repl
julia> map(*, [1, 2], [3, 4])
2-element Vector{Int64}:
 3
 8
```

概念上，我們可以把它想成先對多個輸入集合執行 [`zip()`][zip]，再對中間結果的每個元素執行 `map()`。
_這只是個粗略的類比，並不代表實作方式就是如此！_

和 `zip()` 一樣，形狀不符的集合會被截斷到最小集合的維度。

有時候我們只需要傳入函式的副作用，例如寫入資料庫，或是對陣列 `push!`。
這時就可以用高階函式 [`foreach()`][foreach]，它總是回傳 [`nothing`][nothingness]。

對大型集合來說，`map()` 可能很耗資源。
平行運算不在這個概念的範圍內，但知道有 [`Distributed.pmap()`][pmap] 存在、而且能把運算分散到一群工作節點上，可能會有幫助。
`Distributed` 套件在 Exercism 的測試執行器裡_確實_可以使用。

## 縮減

[`reduce()`][reduce] 函式會接受一個有兩個引數的函式，並把它套用到集合上，產生維度縮減。

抽象地說可能有點難懂，但想想 `sum()` 或 `prod()` 這類函式：它們接受一個集合，回傳單一的值。

```julia-repl
julia> sum(1:4) # add
10

julia> prod(1:4) # multiply
24
```

_這些特殊函式經過高度最佳化，只要能用就該用。_
其他例子還有 `maximum()` 和 `minimum()`、邏輯函式 `all()` 和 `any()`，以及許多統計函式。

_只是為了說明_，看看用更通用的 `reduce()` 實作同樣功能會是什麼樣子（回想一下，中綴運算子 `+` 和 `*` 在內部其實就是函式）。

```julia-repl
julia> reduce(+, 1:4) # add
10

julia> reduce(*, 1:4) # multiply
24
```

和 `sum()` 及其他聚合函式一樣，`reduce()` 可以接受一個選用的關鍵字引數 `dims`，用來指定要縮減的[維度][multidim]。

```julia-repl
julia> m
2×3 Matrix{Int64}:
 1  2  3
 4  5  6

julia> reduce(+, m; dims=1)
1×3 Matrix{Int64}:
 5  7  9
```

這些都是簡單的例子，因為加法和乘法既滿足交換律（`1+2 == 2+1`），也滿足結合律（`(1+2)+3 == 1+(2+3)`）。

但這絕非通例！
即使是減法和除法這麼常見的運算，也不滿足結合律。

還有另一個問題：浮點誤差會在大型集合中累積，所以從左到右的 reduce 可能產生和從右到左略有不同的結果。

Julia 的 `reduce` 函式方向取決於實作，並不保證。

如果要明確控制方向，有 [`foldl()`][foldl] 和 [`foldr()`][foldr] 函式，概念上分別從「左」和「右」開始（對 Vector 來說其實是從上到下）。

```julia-repl
julia> foldl(-, 1:3) # (1 - 2) - 3
-4

julia> foldr(-, 1:3) # 1 - (2 - 3)
2
```

請注意，這兩個函式是為可視為一維的集合而設計的，會回傳純量結果。
`foldl` 和 `foldr` 不支援 `dims` 引數，只有 `reduce` 支援。

在平行運算中，使用 reduce 這類函式會變得更微妙，因為不照順序的計算是常態（不過這超出了這個概念的範圍）。

## MapReduce

把 `map` 操作和 `reduce` 結合起來，在各種程式設計領域中都很常見。

我們可以先依序執行 `map`，再對中間產生的集合執行 `reduce`。
但這種做法頂多效率不佳，而且隨著集合變大，擴展性會變得非常差。

因此_強烈_建議改用結合兩者的 [`mapreduce()`][mapreduce] 函式。
它可以採用效能好得多的演算法，把 map 和 reduce 的操作交錯進行。

第一個引數是要用來 map 的函式，第二個引數是 reduce 用的運算子。

```julia-repl
julia> mapreduce(x -> x^2 + 1, +, 1:3)
17

# equivalent to (2 + 5 + 10)
julia> sum(map(x -> x^2 + 1, 1:3))
17
```

MapReduce 操作在大數據系統（Hadoop、Spark 等）中特別受歡迎，因為它們可以即時處理任意且長度未知的串流，而不會讓記憶體用量暴增。

如我們所料，Julia 也有 [`mapfoldl()`][mapfoldl] 和 [`mapfoldr()`][mapfoldr] 函式，適用於方向很重要的情況。
