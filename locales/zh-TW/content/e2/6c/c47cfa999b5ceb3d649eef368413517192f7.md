# 關於位元

二進位數字最終會直接對應到 CPU 或 RAM 裡的電晶體，以及每一個是「開啟」還是「關閉」。

低階操作，也就是俗稱的「位元操作」，在系統程式語言中特別重要。

像 Kotlin 這類更高階的語言通常會把這些細節大部分都抽象掉。不過，基本的位元層級運算還是[可以使用][ref-bitwise]。

## 位元位移運算

`Int` 或 `Long` 型別，無論有號或無號，都可以表示成由 1 和 0 組成的字串，並當成一串位元來操作。

也許出乎意料的是，`Byte` 或 `Short` 型別和 Kotlin 中大多數的位元運算並不相容。下面所有範例都使用 32 位元整數（`Int` 或 `UInt`）。

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

位元位移會把所有位元往左或往右移動指定的位置數。有些位元會從一端掉出去，另一端則補上 0 或 1。

- 使用 `shl` 的左移：補 0。
- 使用 `shr` 或 `ushr` 的右移：正數補 0（負數請見後面的小節）。

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

每次左移都會讓值變成兩倍，每次右移則減半（會被截斷）。用十進位表示會更明顯：

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

這種位元位移比「正規」的算術快得多，因此這個技巧在低階程式設計中非常受歡迎。

### 位移負整數

處理_負整數_時，我們需要稍微謹慎一點。

負數是以[二補數][wiki-2complement]形式儲存的，這表示最左邊的位元是 1。左移沒問題，但右移時最左邊的位元要怎麼補呢？

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

[`shr`][ref-shr] 運算子執行[算術位移][wiki-arithmetic]，會保留符號位元。

[`ushr`][ref-ushr] 運算子執行[邏輯位移][wiki-logical]，補上 0，彷彿這個數字是無號數。

## 位元邏輯

我們在[布林概念][concept-booleans]看過，運算子 `&&`（and）、`||`（or）和 `!`（not）是用來處理布林值的。

也有對應的運算子 `and`、`or`、`xor`（[互斥或][wiki-xor]）可以比較兩個整數中的位元，還有一個 `inv`（反轉）函式可以把所有位元翻轉。

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
