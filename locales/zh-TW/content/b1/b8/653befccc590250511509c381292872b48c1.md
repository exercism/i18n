# 簡介

當一個函式會呼叫自己時，它就是**遞迴**的。

函式呼叫與迴圈的一個主要差異在於，呼叫函式會把之後要回傳的位址推入堆疊。
這表示遞迴函式通常比等效的迴圈需要更多堆疊空間。

因此，一個不斷呼叫自己的函式最終可能會耗盡所有堆疊空間。
這稱為**堆疊溢位**。

這就是為什麼每個遞迴函式都必須至少有一個基本情況，也就是函式不呼叫自己就回傳的情況。
任何遞迴呼叫最終都必須到達基本情況。

例如，階乘函式`n! = n * (n - 1) * ... * 1`可以用`1`作為基本情況，以遞迴方式定義：

```x86asm
factorial:
    ; the argument `n` is passed on `rdi`
    ; the factorial will be returned on `rax`

    cmp rdi, 1
    jle .base_case     ; base case -> if rdi <= 1, return 1

    push rdi           ; save n
    dec rdi            ; rdi = n - 1
    call factorial     ; recursive call, rax = (n - 1)!
    pop rdi            ; restore n
    imul rax, rdi      ; rax = n * (n - 1)! = n!
    ret
.base_case:
    mov rax, 1
    ret
```

請注意，`factorial`必須在遞迴前`push rdi`，並在遞迴後`pop rdi`。
這是因為當遞迴呼叫回傳後，它仍然需要`n`才能計算`n * (n-1)!`。

另外請注意，使用被呼叫者儲存暫存器也無法解決這個問題。

即使遞迴函式可能是自己的呼叫者，它本身也是其他某個函式的被呼叫者。
這表示函式在使用被呼叫者儲存暫存器之前，也必須先保存它們，並在使用之後還原它們的值。
這通常會透過`push`/`pop`序列來完成，就像我們在先前的概念中看過的一樣。

由於遞迴函式的每個堆疊框架（基本情況除外）也都是呼叫者，需要保留自己的區域變數，因此每個框架都必須重複這個`push`/`pop`序列。
即使不使用暫存器，直接將變數存入堆疊，每個框架仍然會花費相同的`8`個位元組。

這表示每個遞迴呼叫都會因為`call`推入的回傳位址而對堆疊增加`8`個位元組，另外每個需要保存的區域變數也會增加`8`個位元組。
函式每個框架都會持續把這些位元組加入堆疊，直到到達基本情況為止。
只有在那之後，它才會以相反順序開始回溯，每個遞迴呼叫會視需要執行所需的`pop`，然後執行`ret`。

例如，如果以引數`10`呼叫`factorial`，它會在到達基本情況`1`之前先呼叫自己九次。
到那時，用來儲存每個先前框架的`n`（`8`個位元組）和回傳位址（`8`個位元組）的空間總共會是`144`個位元組。

## 尾呼叫

在某些情況下，函式在呼叫另一個函式之後、回傳之前，不會再執行任何其他工作。

例如，考慮以下程式碼：

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    call times_three
    ret
```

函式`triple_of_square`：

- 將傳入的引數（在`rdi`中）乘以自己，得到它的平方；
- 然後呼叫`times_three`，它會回傳三乘以傳入的引數。

結果，`triple_of_square`會回傳`3*x²`，其中`x`是它的引數，透過`rdi`傳入。

請注意，`triple_of_square`在呼叫`times_three`之後不會再做任何工作，函式就直接回傳。
在這種情況下，函式可以使用`jmp`將執行流程轉移到被呼叫的函式，而不是使用`call`：

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    jmp times_three
```

這稱為**尾呼叫**。

尾呼叫的主要優點是避免`call`的額外成本。
`call`會將回傳位址推入堆疊，而為了讓控制權回到那個位置，必須有對應的`ret`。

尾呼叫會跳過這兩者：沒有回傳位址需要推入，也沒有額外的`ret`需要配對，只有被呼叫函式自己的`ret`。

## 尾遞迴

尾呼叫對於可能在回傳之前多次呼叫自己的遞迴函式特別有用。

然而，並非每個遞迴呼叫都可以直接轉換成尾呼叫。
由於`jmp`會將控制權轉移給被呼叫的函式，呼叫者在尾呼叫之後就無法再執行任何工作。

例如，先前的`factorial`函式**不是**尾遞迴。
在遞迴呼叫之後，它仍然需要使用`imul rax, rdi`將結果與目前的`n`相乘。

在這種情況下，有時可以使用累加器來收集部分計算結果，並在最後回傳。
例如，我們可以定義一個`factorial_helper`來執行大部分工作，然後由`factorial`設定累加器並將控制權轉移給`factorial_helper`：

```x86asm
factorial_helper:
    ; the argument `n` is passed on `rdi`
    ; `rax` is used as an accumulator and will be returned at the end

    cmp rdi, 1
    jle .base_case

    imul rax, rdi        ; we accumulate the partial result on `rax`
    dec rdi              ; rdi = n - 1
    jmp factorial_helper ; tail call to accumulate (n - 1)!
.base_case:
    ret                  ; returns the factorial already accumulated on `rax`

factorial:
    mov rax, 1           ; initial value for the accumulator
    jmp factorial_helper ; tail call
```

由於遞迴呼叫之後不會再做任何工作，我們也不再需要保存`rdi`。
沒有`call`或`push rdi`，因此每次遞迴疊代對堆疊增加`0`個位元組：不會使用額外的堆疊空間。
這個版本可以處理任意大的`n`，而不會讓堆疊溢位。
它既更有效率也更安全。

在某些情況下，透過調整函式的順序，甚至可以避免對輔助函式進行`jmp`。
例如，`factorial`和`triple_of_square`可以改寫成這樣：

```x86asm
factorial:
    mov rax, 1
factorial_helper:
    cmp rdi, 1
    jle .base_case

    imul rax, rdi
    dec rdi
    jmp factorial_helper
.base_case:
    ret

triple_of_square:
    imul rdi, rdi
times_three:
    imul rax, rdi, 3
    ret
```

在上面的程式片段中，`factorial`的執行會繼續往下執行到`factorial_helper`。
`triple_of_square`和`times_three`也是一樣。
在這兩種情況下，執行會依序繼續，看起來尾端的函式只是「主要」函式內的一個區域標籤。

實際上，任何區域標籤和函式之間並沒有本質上的差異。
x86-64 組合語言並不會對其中任何一個給予特殊待遇，它們只是在可執行程式碼區段中的位址，例如`section .text`。

這樣一來，尾遞迴函式基本上可以視為等同於一個迴圈，其中遞迴呼叫會跳回頂端，而基本情況則是結束迴圈的條件。
