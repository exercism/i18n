# 簡介

*deque*（雙向佇列）支援在兩端進行 push 和 pop，兩者都是 O(1)。Factor 的標準實作是 [`dlists`][dlists] 裡的 `<dlist>`（雙向連結串列）；相關操作則放在 [`deques`][deques]。

## deque API

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` 會就地清空 deque，適合重複使用時避免重新配置記憶體。

在同一端進行 push 和 pop 會得到 LIFO 堆疊。在一端 push、另一端 pop，則會得到 FIFO 佇列：

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

若要 LIFO，你會改用帶有 `push`/`pop` 的向量（`V{ }`），它每次操作的額外負擔較小。當你需要兩端都達到 O(1) 時，就該改用 `<dlist>`，而這幾乎總是為了 FIFO 佇列。

## 廣度優先搜尋

正是 FIFO 的用法，讓 deque 成為 *BFS* 的理想邊界。你從單一節點開始，把相鄰節點 push 到尾端，從前端 pop 出候選節點，並用雜湊集合去重：

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

較早加入的候選節點會先於較新的候選節點被走訪，因此搜尋會從起點開始一層層向外擴展。這正是 BFS 具有最短路徑性質的原因：你第一次抵達目標節點時，走的就是最少跳躍數的路徑。

## `MEMO:`：自動快取

有時 BFS 呼叫的逐節點查詢相當昂貴。Factor 的 [`memoize`][memoize]詞彙提供了 `MEMO:`，它能直接取代 `:`，並依輸入快取該詞的結果：

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

`MEMO:`詞在首次見到每個輸入時會執行其主體，之後便回傳快取的結果。介面不變，呼叫端不需要額外的呼叫，只是在重複時更快。
