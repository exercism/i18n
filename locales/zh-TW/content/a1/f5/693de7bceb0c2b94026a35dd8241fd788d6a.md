# 指令

你正在運作一個由幾個應用程式組成的系統，這些應用程式會產生許多日誌。你想寫一個小程式，把這些日誌彙整起來，並依照嚴重程度為它們加上標籤。系統中所有應用程式都使用相同的日誌代碼，但有些舊版應用程式不支援全部代碼。

| 日誌代碼              | 日誌標籤 | 舊版應用程式支援嗎？ |
|-----------------------| --------- | ------------------------- |
| 0                     | trace     | 否                        |
| 1                     | debug     | 是                       |
| 2                     | info      | 是                       |
| 3                     | warning   | 是                       |
| 4                     | error     | 是                       |
| 5                     | fatal     | 否                        |
| 其他／不支援 | unknown   | -                         |

## 1. 判斷日誌標籤

實作`LogLevel.to_label/2`函式。它應該接受一個整數代碼，以及一個指出日誌是否來自舊版應用程式的布林旗標，並以 atom 的形式回傳該筆日誌的標籤。

表中未指定的日誌代碼應回傳 _unknown_ 標籤。表中標示為舊版應用程式不支援的日誌代碼，如果日誌來自舊版應用程式，也應回傳 _unknown_ 標籤。

```elixir
LogLevel.to_label(0, false)
# => :trace

LogLevel.to_label(0, true)
# => :unknown
```

## 2. 傳送警示

當意料之外的事情發生時，總得有人收到通知。

實作`LogLevel.alert_recipient/2`函式，判斷警示需要傳送給誰。這個函式應該接受一個整數代碼，以及一個指出日誌是否來自舊版應用程式的布林旗標，並以 atom 的形式回傳收件者的名稱。

請使用上一個任務的`LogLevel.to_label/2`函式。如果日誌標籤是 _error_ 或 _fatal_，就把警示傳送給 _ops_ 團隊。如果你收到來自舊版系統、標籤為 _unknown_ 的日誌，就把警示傳送給 _dev1_ 團隊；其他標籤為 unknown 的日誌則應傳送給 _dev2_ 團隊。其他所有日誌標籤都可以安全地忽略，只要回傳 _false_ 即可。

```elixir
LogLevel.alert_recipient(-1, true)
# => :dev1

LogLevel.alert_recipient(0, false)
# => false
```
