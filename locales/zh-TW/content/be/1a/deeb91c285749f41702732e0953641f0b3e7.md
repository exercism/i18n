# 指令補充

## 實作

如果你剛接觸 Go 的錯誤或 panic，建議先閱讀[這方面的文件](https://blog.golang.org/defer-panic-and-recover)，先了解一下背景脈絡。

在這個練習中，你需要定義一個函式`Use(opener ResourceOpener, input string) error`，它會開啟資源、對取得的資源呼叫`Frob(input)`，然後關閉該資源（無論發生什麼情況）。
你的函式應該妥善處理錯誤與 panic。

`ResourceOpener opener`是一個函式，你可以直接呼叫`opener()`來嘗試「開啟」資源。
它會以 [Go 的慣用風格](https://blog.golang.org/error-handling-and-go)回傳一個`Resource`和一個錯誤值：

請參閱 [common.go](./common.go) 檔案，了解`Resource`、`ResourceOpener`、`FrobError`和`TransientError`的定義。
你的解答要定義在與 [common.go](./common.go) 和 [error_handling_test.go](./error_handling_test.go) 相同的套件裡：「erratum」。
這樣一來，你的解答就能使用這些型別。

你的`Use`函式中有幾個地方可能會發生錯誤：

- 呼叫當作第一個參數傳入 Use 的`ResourceOpener`函式時，它可能會以`TransientError`型別的錯誤失敗，若是如此，請持續嘗試開啟資源。
  如果是其他種類的錯誤，就把它從你的`Use`函式回傳。

- 對`ResourceOpener`函式回傳的`Resource`呼叫`Frob`函式時，它可能會**panic**，並拋出`FrobError`（或其他型別的錯誤）。
  如果確實是`FrobError`，你就必須呼叫該 Resource 的`Defrob`函式，_並以 panic 的`FrobError`的`.defrobTag`變數作為`Defrob`函式的輸入_。
  無論如何，`Use`都應該回傳該錯誤。

- _另外請注意_：如果`Resource`成功開啟，請務必確保無論如何都恰好呼叫它的`Close`函式一次（即使已經發生錯誤）。

測試特定錯誤型別可以透過[型別斷言](https://golang.org/ref/spec#Type_assertions)來進行。
你可能還需要看看[具名回傳值](https://blog.golang.org/defer-panic-and-recover)，這是從 panic 復原時回傳錯誤資訊的實用做法。
