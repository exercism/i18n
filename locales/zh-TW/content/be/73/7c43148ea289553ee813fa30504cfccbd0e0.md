# 關於

和許多其他程式語言一樣，Go 也有指標。
如果你是第一次接觸指標，可能會覺得有點神祕，不過一旦熟悉之後，就會發現它們其實相當直觀。
指標是 Go 非常關鍵的一部分，所以花點時間好好理解它們吧。

在深入細節之前，值得先了解指標的用途。
指標是一種與程式其他部分共用記憶體的方式，這在兩個主要原因上很有用：

1. 當資料量很大時，在函式之間傳遞時製作副本非常沒有效率。
   改成傳遞資料儲存的記憶體位置，就能大幅降低程式的資源用量。
2. 在函式之間傳遞指標，我們就能直接存取並修改同一份資料，也就是說，當函式結束時，某個函式所做的任何變更都會立即被程式其他部分看見。

## 變數與記憶體

假設我們有一個普通的整數變數`a`：

```go
var a int
```

當我們宣告一個變數時，Go 必須在記憶體中找一個位置來儲存它的值。
這對我們來說大部分都被抽象化了，當我們需要取得那塊記憶體中儲存的值時，只要用變數名稱來取用就好。

例如，當我們寫下`a + 2`時，實際上就是取得與變數`a`相關聯的記憶體中所儲存的值，再把它加上 2。

同樣地，當我們需要改變`a`那塊記憶體中的值時，可以用變數名稱來做指定：

```go
a = 3
```

現在與`a`相關聯的那塊記憶體會儲存值`3`。

## 指標

變數讓我們能取用記憶體中的值，但有時候知道變數所指向的**記憶體位址**會很有用。
**指標**儲存的就是那些值的記憶體位址。
只要在底層型別前面加上一個星號，就能宣告一個指標型別的變數：

```go
var p *int // 'p' contains the memory address of an integer
```

這裡我們宣告了一個型別為「指向 int 的指標」（`*int`）的變數`p`。
這表示`p`會儲存某個整數的記憶體位址。
指標的零值是`nil`，因為`nil`指標不儲存任何記憶體位址。

### 取得變數的指標

要找出某個變數的值的記憶體位址，我們可以使用`&`運算子。
例如，如果我們想找出變數`a`的記憶體位址並存進指標`p`，可以這麼做：

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### 透過指標存取值（解參考）

當我們有一個指標時，可能會想知道該指標所代表的記憶體位址中儲存的值。
我們可以用`*`運算子來做到這件事：

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p`這個運算會取得儲存在`p`中的記憶體位址上的值。
這個運算通常稱為「解參考」。

我們也可以用解參考運算子，為指標所指向的記憶體位址指定一個新值：

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

對`*pa`做指定，會改變`pa`所持有的記憶體位址上儲存的值。
由於`pa`持有`a`的記憶體位址，所以對`*pa`做指定，實際上就是在改變`a`的值！

不過要提醒一下：在解參考之前，一定要先檢查指標是不是`nil`。
對`nil`指標解參考會讓程式在執行期間崩潰！

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### 結構體的指標

到目前為止，我們只看過指向基本型別值的指標。
我們也可以為結構體建立指標：

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

我們也可以建立一個新的`Person`，並立刻儲存一個指向它的指標：

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

當我們有一個指向結構體的指標時，不需要先解參考就能存取其中一個欄位：

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## 切片與`map`本身就是指標

切片與`map`是特殊的型別，因為它們的實作中本來就帶有指標。
這表示大多數情況下，我們不需要為這些型別建立指標，就能共用它們的值的記憶體位址。
想像我們有一個函式，會把`map`中某個鍵的值加一：

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

如果我們建立一個`map`並呼叫這個函式，函式對`map`所做的變更在函式結束後仍然保留。
這種行為和我們使用指標時很類似，但注意在這個例子裡，我們完全沒有用到取址／解參考，也沒有用到任何指標語法：

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

在切片中修改既有的元素時也是如此。

不過，像`append`這樣會回傳新切片的操作是特例，**可能不會**修改函式外的切片。
這是因為切片內部的運作方式，但我們不會詳細探討，因為這是比較進階的主題。
如果你真的很好奇，可以在 [Go Blog: Mechanics of 'append'][mechanics-of-append] 讀到更多內容。

## 指標運算

和其他語言不同，Go 不支援指標運算。
這表示你不能透過遞增指標的值，從某個值的記憶體位址移動到另一個值的位址。
所以像下面這樣的程式片段是無效的：

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
