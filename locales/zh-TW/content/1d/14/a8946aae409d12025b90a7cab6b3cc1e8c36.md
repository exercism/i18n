# 簡介

## 尾端呼叫最佳化

每次呼叫函式時，記憶體中都會建立一個新的堆疊框架，用來儲存該函式的引數與區域變數，並在函式回傳時釋放這個堆疊框架。由於 Gleam 使用遞迴函式呼叫，而不是迴圈語法，因此這些堆疊框架可能會占用大量記憶體。

為了解決這個問題，Gleam 支援尾端呼叫最佳化：當函式呼叫是函式最後執行的事情時，編譯器就可以重複使用目前函式的堆疊框架。這表示一個函式可以無限次地呼叫自己，而不會使用任何額外的記憶體。

未經最佳化的遞迴函式，通常可以透過使用_累加器_改寫成經過尾端呼叫最佳化的函式。

累加器是一個隨著資料一起傳遞的變數。它用來傳遞函式執行時的目前狀態，直到達到基本情況為止。

累加器應該由函式的作者初始化，而不是由函式的使用者。為了做到這一點，請宣告兩個函式：一個是只接收必要資料作為引數並初始化累加器的公開函式，另一個是同時接收累加器的私有函式。

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
