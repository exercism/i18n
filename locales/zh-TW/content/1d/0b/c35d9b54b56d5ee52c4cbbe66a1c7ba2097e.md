# 關於

在 C# 中，可以用_繼承_定義_類別_階層，讓衍生類別（`Car`）繼承父類別（`Vehicle`）的行為與資料。如果沒有指定父類別，類別會繼承`object`類別。

父類別可以用 3 種方式提供功能給衍生類別：

- 定義一般方法。
- 定義 [`virtual`方法][virtual-keyword]，它和一般方法類似，但衍生類別_可以_加以變更。
- 定義 [`abstract`方法][abstract-keyword]，這是一種沒有實作的方法，衍生類別_必須_實作它。含有`abstract`方法的類別也必須標示為 [`abstract`][abstract-classes]。抽象類別無法具現化。

[`protected`存取修飾詞][protected-keyword]允許在衍生類別中存取父類別的成員，但會阻擋其他類別存取。因此，衍生類別可以存取父類別的`public`和`protected`成員，但不能存取`private`成員。

衍生類別可以透過 [`base`關鍵字][base-keyword]存取父類別的成員。

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

衍生類別的建構函式會在執行自身建構函式邏輯_之前_，[自動呼叫父類別的建構函式][constructors]。可以用 [`base`關鍵字][base-keyword-constructor]將引數傳給父類別的建構函式。由於抽象類別無法具現化，它們的建構函式可以設為`protected`。

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

當一個基底類別衍生出多個類別時，這些子類別（可能兩個，也可能更多）通常會實作基底類別方法的不同版本。這是一項非常重要的原則，稱為[多型][polymorphism]。舉例來說，在上述例子的變化版本中，我們示範使用`Vehicle`的程式碼如何依據具現化的載具類型改變其行為。

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

若要防止類別被繼承，請加上 [`sealed`修飾詞][sealed-classes]。有些實務工作者會盡量避免繼承具體類別（[這篇 Stack Overflow 問題][pro-sealed]中有相關討論），而 _sealed_ 修飾詞正好支持這種做法。另一方面，許多 C# 開發者認為它們會妨礙維護，[這個問題][anti-sealed]的部分留言中也有相關討論。建議是：在你對如何將它們運用在自身需求上建立信心之前，請斟酌使用 sealed 修飾詞。

下列[文章][new-vs-override]說明`new`可作為`override`修飾詞的替代方案。這偶爾很有用，例如在錯綜複雜的類別階層，或某種程式庫衝突的情況下。
