# 關於

把值準備好以便傳輸，同時代表三件事：將它序列化、從中挑出正確的那個部分，以及在不需要複製時就不要複製。Factor 的三個慣用語涵蓋了這些面向。

## `unparse`，從值到原始碼

[`unparse`][unparse]（位於`prettyprint`）會回傳任何值的原始碼形式文字。它是剖析器的反向操作，來回執行`dup unparse parse`就能重建原本的值。

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

和`>string`（只能處理字元序列）以及`number>string`（只能處理數字）相比，`unparse`是通用的那一個，代價是它會產生 Factor 語法（字串會保留引號），所以當接收端會把文字剖析回值時，它正是正確的工具；但要產生人類可讀的輸出時，它就不適用了。

## 切片，是檢視而非複製

| 詞彙          | 效果                                           |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`，複製前 n 個              |
| `head-slice`  | `( seq n -- slice )`，前 n 個的檢視             |
| `tail`        | `( seq n -- newseq )`，從索引 n 開始複製        |
| `tail-slice`  | `( seq n -- slice )`，從索引 n 開始的檢視       |
| `head*`       | `( seq n -- newseq )`，複製除了最後 n 個以外的全部 |
| `head-slice*` | `( seq n -- slice )`，除了最後 n 個以外全部的檢視 |
| `tail*`       | `( seq n -- newseq )`，複製最後 n 個            |
| `tail-slice*` | `( seq n -- slice )`，最後 n 個的檢視           |

`slice`是一個元組，內含起始索引、結束索引，以及底層序列；它實作了[序列協定][sequence-protocol]，因此任何序列操作都能套用在它上面。當你原本只是為了讀取就得配置記憶體時，就改用切片版本；當底層序列可能變動之後你仍需要保留資料時，就改用複製的版本。

## 多輸入的 cleave，`2bi`、`3bi`、`2tri`、`3tri`

單純的 cleave 詞彙`bi`和`tri`會把兩個或三個 quotation 套用到堆疊上的*一個*輸入。而以`2`開頭和`3`開頭的變體，則會把每個 quotation 分別套用到*兩個*或*三個*輸入：

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

每個 quotation 都會收到*全部*的輸入，所以當兩個投影都取決於這一對值時，就用`2bi`；如果你只是想把同一個投影分別套用到每個輸入，就不要用它（那是`bi@`）。

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

若要把*一個* quotation 分別套用到每個輸入，請改用`bi@`（兩個輸入）或`tri@`（三個輸入）；同一個家族，不同的形狀。
