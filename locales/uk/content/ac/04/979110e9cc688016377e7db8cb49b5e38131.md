# Володіння

У Cairo концепція володіння привʼязана до _змінних_, а не до _значень_, які вони містять.

Значення в Cairo незмінні. Ця незмінність гарантує, що навіть коли багато змінних посилаються на те саме значення, саме значення залишається сталим і незміненим.
Тож компілятор має подбати, щоб програміст використовував їх правильно.
Ось у чому сенс _володіння_ змінною: власник - це код, який може читати цю змінну (і записувати до неї, якщо її можна змінювати).

## Правила володіння змінними

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## Область видимості змінної

Область видимості - це ділянка програми, у якій змінна є чинною.
Розгляньмо приклад, який оголошує змінну `x` беззнакового цілого типу, з коментарями, що позначають, де змінна чинна:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Примітки:

- Коли `x` потрапляє в область видимості, вона стає чинною.
- Вона залишається чинною, доки не вийде з області видимості, у цьому разі - до кінця функції `main()`.

## Переміщення значень

Переміщення відбувається, коли значення передають в іншу функцію: початкова змінна, яка посилалася на це значення, знищується (і стає непридатною), а натомість створюється нова змінна, що містить те саме значення.

Масиви - це приклад складеного типу, який переміщується, коли його передають в іншу функцію.
Ось коротке нагадування про те, як має вигляд масив:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

Як система типів гарантує, що програма на Cairo ніколи не спробує записати в ту саму комірку памʼяті двічі?
Розгляньмо код, у якому ми намагаємося двічі прибрати початок масиву:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

У цьому разі ми намагаємося передати те саме значення (масив у змінній `arr`) в обидва виклики функції.
Це означає, що наш код намагається двічі прибрати перший елемент, тобто двічі записати в ту саму комірку памʼяті, а це заборонено у віртуальній машині Cairo і призводить до помилки під час виконання.
На щастя, цей код насправді не компілюється.
Щойно ми передали масив у функцію `foo`, змінна `arr` більше не придатна до використання.
Ми отримуємо цю помилку під час компіляції, яка повідомляє, що для `Array` потрібно реалізувати трейт `Copy`:

## Трейт `Copy`

Якщо тип реалізує трейт `Copy`, то передавання його у функцію не переміщує значення, а створює нову змінну, яка посилається на те саме значення.
Ця операція нічого не коштує, бо змінні - це абстракція Cairo, а значення завжди незмінні.

Щоб реалізувати трейт `Copy` для свого типу, додамо анотацію `#[derive(Copy)]` до визначення типу.
Проте Cairo не дозволить цього, якщо сам тип або будь-який з його складників не реалізує трейт `Copy`.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## Знищення значень

Лінійні типи можна також використати, знищивши їх, що гарантує правильне вивільнення повʼязаного ресурсу.
Це робиться через реалізацію або виведення трейту `Drop`, який повідомляє компілятору, що тип можна безпечно знищити, коли він більше не потрібен.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

Наразі реалізацію `Drop` можна вивести для всіх типів, крім словників (`Felt252Dict`) і типів, що містять словники.
Це тому, що під час знищення словники потрібно «сплющити».
Для цього ми виводимо трейт `Destruct`:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## Повернені значення та область видимості

Повернення значень рівнозначне їх переміщенню.
У прикладі нижче показано функцію, яка повертає деяке значення:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
