# Узагальнені типи даних

Узагальнення в Cairo дають змогу писати код багаторазового використання, що працює з різними типами, допомагають уникати дублювання та спрощують підтримку.

Узагальнення можна застосовувати до функцій, структур, переліків, трейтів і методів.

## Узагальнені функції

Узагальнена функція працює з різними типами без потреби в окремих реалізаціях.

Наприклад:

```rust
fn largest_list<T>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Тут `T` позначає будь-який тип.

Однак Cairo вимагає обмежень трейтів, щоб узагальнений тип відповідав певним вимогам.

Якщо `T` має підтримувати відкидання, можемо оновити сигнатуру:

```rust
fn largest_list<T, impl TDrop: Drop<T>>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Обмеження трейтів, як-от `Drop` або `PartialOrd`, накладають на узагальнення додаткові вимоги для конкретних операцій.

## Анонімні обмеження

Якщо реалізація трейту не використовується у функції безпосередньо, можна записати анонімні обмеження за допомогою `+`:

```rust
fn smallest_element<T, +PartialOrd<T>, +Drop<T>, +Copy<T>>(list: @Array<T>) -> T {
    let mut smallest = *list[0];
    let mut index = 1;

    while index < list.len() {
        if *list[index] < smallest {
            smallest = *list[index];
        }
        index += 1;
    };

    smallest
}
```

Це позбавляє потреби називати трейти, як-от `TPartialOrd`, і робить код менш багатослівним.

## Структури з узагальненнями

Узагальнення в структурах роблять поля гнучкими.

Наприклад:

```rust
#[derive(Drop)]
struct Wallet<T> {
    balance: T,
}

let w = Wallet { balance: 42 };
```

Якщо структурі потрібно кілька узагальнених типів, просто додамо більше заповнювачів:

```rust
#[derive(Drop)]
struct Wallet<T, U> {
    balance: T,
    address: U,
}

let w = Wallet { balance: 42, address: '0xabc' };
```

## Переліки з узагальненнями

Переліки теж можуть містити узагальнені типи даних.

Наприклад:

```rust
enum Option<T> {
    Some: T,
    None,
}
```

Перелік `Option<T>` може представляти необовʼязкове значення будь-якого типу.

Так само `Result<T, E>` дає змогу визначити типи для успіху та невдачі:

```rust
enum Result<T, E> {
    Ok: T,
    Err: E,
}
```

## Узагальнені методи

Методи також можуть використовувати узагальнення.

Наприклад:

```rust
#[derive(Copy, Drop)]
struct Wallet<T> {
    balance: T,
}

trait WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T;
}

impl WalletImpl<T, +Copy<T>> of WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T {
        *self.balance
    }
}

let w = Wallet { balance: 50 };
assert!(w.balance() == 50);
```

Можна також визначити методи для конкретних узагальнених типів, як-от `Wallet<u128>`:

```rust
trait WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128);
}

impl WalletReceiveImpl of WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128) {
        self.balance += value;
    }
}

let mut w = Wallet { balance: 50 };
w.receive(100);
assert!(w.balance() == 150);
```

## Змішування узагальнених типів

Узагальнення здатні працювати зі складними комбінаціями.

Наприклад, поєднання двох екземплярів `Wallet` різних типів:

```rust
trait WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2>;
}

impl WalletMixImpl<T1, +Drop<T1>, U1, +Drop<U1>> of WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2> {
        Wallet { balance: self.balance, address: other.address }
    }
}

let w1 = Wallet { balance: true, address: 10 };
let w2 = Wallet { balance: 32, address: 100 };
let w3 = w1.mixup(w2);

assert!(w3.balance);
assert!(w3.address == 100);
```

Завдяки додаванню обмежень `+Drop` компілятор забезпечує правильну роботу з ресурсами.

Узагальнення дають великі можливості, але вимагають уважного керування обмеженнями.

Використовуймо їх, щоб писати код багаторазового використання, незалежний від типу та лаконічний.
