# Вступ до основ роботи з оболонкою

## Оболонки

_Оболонкою_ називають програму, яка дає змогу вводити команди для взаємодії з операційною системою.
Оболонки бувають графічними: робоче середовище, яке ми використовуємо з мишкою чи трекпадом, теж є оболонкою.
Ми зосередимося на інтерфейсах командного рядка, де ми вводимо команди, а результати (зазвичай) друкуються в терміналі.

Існує багато різних оболонок командного рядка.
Windows пропонує **cmd** і **powershell**.
Mac і Linux пропонують «Unix-оболонки», яких теж чимало.
У Mac типовою оболонкою є **zsh**.
**csh** - застаріла оболонка із синтаксисом, схожим на C.
**bash** - одна з найпопулярніших оболонок, особливо в Linux.

Однією з найперших оболонок є оболонка Борна, **sh**.
Згодом цю оболонку [стандартизували][posix], щоб її надавали в кожній Unix-подібній системі.
Багато оболонок походять від оболонки Борна й часто додають інтерактивні чи програмні можливості.

**Bash** походить від оболонки Борна.
Саме тому її називають «**B**ourne-**a**gain **sh**ell».
У багатьох системах Linux вона типова.
Bash має багато можливостей, які роблять її приємною інтерактивною оболонкою, зокрема:

* цілком настроюване запрошення,
* можливість пригадати й змінити команди з історії,
* можливість керувати запущеними процесами,
* псевдоніми, які скорочують введення,
* та багато іншого.

Цей трек не про те, як користуватися bash як інтерактивною оболонкою.
Він про те, щоб навчитися писати програми на bash.
Акцент буде на тому, щоб розвʼязувати задачі _лише_ засобами bash, хоча ніщо не забороняє викликати зовнішні інструменти.

## Основи Bash: команди та аргументи

Bash читає команди зі свого вхідного потоку (зазвичай це термінал або файл).
Кожен прочитаний рядок вхідних даних вважається _командою_, тобто вказівкою, яку потрібно виконати.
(Є кілька складніших випадків, як-от команди, що займають кілька рядків; про них ітиметься пізніше.)

Bash розбиває кожен рядок на **слова**, розділені пробільними символами (пробілами й табуляціями).
Перше слово рядка задає назву _команди_, яку потрібно виконати.
Усі решта слів стають _аргументами_ цієї команди (опціями, іменами файлів тощо).

~~~~exercism/note
У прикладах нижче ми покажемо кілька інтерактивних команд, які можна запустити.

* Символ `#` починає _коментар_.
  Усі слова після нього оболонка ігнорує; коментар призначений лише для читання.
* Символ `$` позначає запрошення оболонки. 
  Якщо ми копіюємо команду, запрошення до неї не включаємо.
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm` - це програма, яка видаляє передані їй файли.
`*` - це символ [glob][glob], шаблон-замінник, який збігається з усіма файлами в поточному каталозі.
Докладніше про glob ми поговоримо пізніше.

Чи помітно, що між `a` і `b` кілька пробілів, а між `b` і `c` лише один?
Кількість пробільних символів між аргументами не має значення!
Наприклад:

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo` - це команда, яка виводить свої аргументи у стандартний вивід (у нашому випадку це термінал).
Bash розбиває команду на пʼять слів і викликає команду `echo` з чотирма аргументами.
Зайві пробіли в другому прикладі нічого не змінюють.
`echo` не знає, скільки пробілів було між словами спочатку.

Якщо ми хочемо зберегти зайві пробіли, треба передати речення як один-єдиний аргумент.
Для цього скористаймося [лапками][Quotes]:

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

Лапки обʼєднують усе всередині них в _один аргумент_.
Цим аргументом є `This    is    a    test.` разом із тими конкретними пробілами.
Зауважмо, що лапки не є частиною аргументу: bash прибирає їх, перш ніж передати цей єдиний аргумент команді `echo`.

Аргументи відокремлюються від назви команди та одне від одного пробільними символами.
Це важливо запамʼятати.
Наприклад, ось так неправильно:

```bash
$ [-f file]
bash: [-f: command not found
```

Це має перевіряти, чи існує файл із назвою `file`.
Можна припустити, що пробіли навколо `[` і `]` не мають значення, але насправді `[` - це команда, і її останнім аргументом має бути `]`.
(Про команду `[` докладніше йтиметься пізніше.) 
Тому ми маємо відокремити `[` від `-f`, а `]` від `file`.
Інакше bash думатиме, що ми намагаємося виконати команду з назвою `[-f` з єдиним аргументом `file]`.
Правильна команда відокремлює всі аргументи пробілами:

```bash
$ [ -f file ]
```

(Багато людей плутається в цій поведінці: вони думають, що `[...]` - це «просто синтаксис» і пробіли можна опустити; але `[` - це команда, і пробіли обовʼязкові.)

Якщо в імені файлу є пробіли чи інші спеціальні символи, його теж треба взяти в лапки:

```bash
$ [ -f "my file" ]
```

## Типи команд

Bash розрізняє кілька типів команд: псевдоніми, функції, вбудовані команди, ключові слова та виконувані файли.
Усі вони - _команди_ й поводяться дуже схоже.

Типово псевдоніми доступні лише в інтерактивних оболонках, а не в сценаріях оболонки.
Тут ми їх не будемо розглядати.

### Функції

Функція містить команди оболонки й поводиться майже як маленький сценарій; вона навіть може приймати аргументи та створювати локальні змінні.
Коли функцію викликають, команди в ній виконуються.
Докладніше про функції йтиметься пізніше.

### Вбудовані команди

У Bash є кілька вбудованих базових команд, як-от: `cd` (змінити каталог), `echo` (записати виведення) тощо.
Їх можна вважати функціями, які вже надані.

### Ключові слова

Ключові слова схожі на вбудовані команди, але головна відмінність у тому, що ключові слова - це насправді синтаксис bash, який розбирається за особливими правилами.
Наприклад, `[` - це вбудована команда bash, тоді як `[[` - ключове слово bash; обидва використовуються для перевірки різних умов.
Але ключове слово `[[` має додаткові можливості.
Наприклад, воно надає оператор `=~`, який перевіряє регулярні вирази.

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

Оператори порівняння рядків тексту (англ. string) `<` і `>` - це ще один приклад того, як ключові слова розбирають код інакше.
Усередині `[[...]]` ці оператори не потребують особливої уваги.

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

Але всередині `[...]` їх треба взяти в лапки або екранувати, щоб оболонка не розібрала їх як оператори перенаправлення.

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### Виконувані файли

Останній різновид команд, який може виконати bash, - це _виконуваний файл_.
Це виконувані файли (програми) у файловій системі компʼютера, які можна запустити.
(Виконувані файли також називають _зовнішніми командами_ або _програмами_.)
Виконувані файли зазвичай викликають, вводячи лише їхню назву; повний шлях до файлу зазвичай не потрібен.
Це можливо, бо bash використовує наперед визначену змінну, яка допомагає знайти розташування типових виконуваних файлів.
Ця змінна називається `PATH`.
Це набір назв каталогів, розділених двокрапками (наприклад, `/usr/bin:/bin`). 
Коли команду задано (наприклад, `myprogram` або `ls`) без шляху до файлу (і вона не є псевдонімом, функцією, вбудованою командою чи ключовим словом), bash переглядає каталоги зі змінної `PATH`.
Каталоги переглядаються по порядку, зліва направо, щоб зʼясувати, чи є в них виконуваний файл із такою назвою.

Якщо виконуваний файл лежить поза відомими шляхами, потрібно вказати шлях до нього.
Для виконуваного файлу `myprogram` у поточному каталозі треба використати `./myprogram`; якщо він у каталозі `/opt/somedirectory`, треба використати `/opt/somedirectory/myprogram`.

Порада: команду `type` можна використати, щоб дізнатися більше про команду:

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## Сценарії

_Сценарій_ - це послідовність команд, збережена у файлі.
Bash читає файл і обробляє команди по порядку.
Вона переходить до наступної команди лише тоді, коли завершилася поточна.
Виняток - якщо команду вказано запускати асинхронно (у фоновому режимі).
Поки що не будемо надто перейматися цим випадком; про те, як це працює, дізнаємося пізніше.

Будь-який приклад із командного рядка в цьому посібнику можна використати і в сценарії.

Створити сценарій легко.
Почнімо з того, що створимо новий файл і запишемо ось це в першому рядку:

```bash
#!/bin/bash
```

Цей рядок називають _директивою інтерпретатора_ (її також називають _hashbang_ або **_shebang_**).
Він вказує, що `/bin/bash` слід використовувати як інтерпретатор, коли файл виступає виконуваним файлом у команді.
Коли ядро ОС виконує _небінарний файл_, воно читає перший рядок файлу.
Якщо рядок починається з `#!`, ядро використовує його, щоб визначити інтерпретатор, якому передати файл.
(Є й інші слушні способи зробити це, див. нижче.)
`#!` має бути на самому початку файлу, без пробілів чи порожніх рядків перед ним.
Команди нашого сценарію йтимуть окремими рядками нижче.

Порада: замість `#!/bin/bash` можна використати

```bash
#!/usr/bin/env bash
```

`env` шукає у `$PATH` виконуваний файл, названий у його першому аргументі (у цьому випадку «bash»).
Щоб докладніше дізнатися про цю техніку та її відмінність від звичайного `#!/bin/bash`, див. [це запитання на StackOverflow][env bash].

Не варто обманюватися сценаріями чи прикладами з інтернету, які використовують `/bin/sh` як інтерпретатор.
**`sh` - це не `bash`!**
Сам Bash - оболонка, «сумісна з sh»: він може запускати більшість сценаріїв `sh` і має багато того самого синтаксису.
Однак зворотне не працює: деякі можливості bash у `sh` не працюють або поводяться несподівано.
Насправді єдиної оболонки `sh` не існує.
Існує багато реалізацій оболонок, які підтримують синтаксис POSIX-sh.
Залежно від ОС, запускаючи `sh`, ми насправді можемо виконувати bash, ash, dash або якусь іншу оболонку.

Коли файл сценарію створено, його можна виконати так:

```bash
$ bash myscript
```

У цьому прикладі ми виконуємо _команду_ `bash` і кажемо їй прочитати сценарій, який передали як _аргумент_.
Коли ми робимо так, рядок `#!` - лише _коментар_.

Крім того, ми можемо дати нашим сценаріям права на виконання.
За такого підходу ми можемо виконати сценарій як будь-який інший виконуваний файл, не викликаючи bash вручну:

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

Коли ми запускаємо команду в такий спосіб, операційна система (ОС) використовує рядок `#!`, щоб визначити, який інтерпретатор має запускати наш сценарій.
