# Про

Динамічну памʼять реалізують функції бібліотеки, які програміст використовує, щоб виділяти й звільняти памʼять під час виконання.
Оскільки програміст керує виділенням і звільненням памʼяті, динамічна памʼять настільки безпечна, наскільки програміст вільний від людських помилок.
Тому динамічна памʼять - одне з головних джерел помилок програмування й одна з головних цілей хакерських атак.

Динамічну памʼять використовують для змінних, розмір яких стає відомий лише під час виконання.
Це зазвичай корисно для масивів, кількість елементів яких може відрізнятися від одного запуску до іншого.
Масиви змінної довжини (VLA) - ще один спосіб працювати з масивами, розмір елементів яких відомий лише під час виконання.
VLA використовує автоматичне зберігання, тобто її памʼять знищується після виходу з блоку, де її визначено.
(Докладніше про зберігання дивіться в концепції [специфікатори класу памʼяті](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers).)
VLA було додано до мови C стандартом C99, але починаючи з C11 VLA є необовʼязковими, тож компілятори, що підтримують C11 і новіші, не зобовʼязані підтримувати VLA.
Детальний аналіз масивів змінної довжини виходить за межі цієї статті.

## malloc

Функція `malloc` оголошена в `stdlib.h` і використовується для виділення динамічної памʼяті.
Якщо виділення успішне, повертається вказівник, що вказує на адресу першого байта виділеної памʼяті.
Якщо виділення невдале, повертається `NULL`.
Варто перевіряти результат `malloc` на `NULL` і коректно обробляти невдачу.
Повернений вказівник має тип `pointer-to-void`, який можна приблизно вважати «загальним» вказівником, що його можна перетворити на конкретний тип, який використовує памʼять.
`malloc` має один параметр: розмір потрібної памʼяті в байтах.
Щоб виділити масив, потрібно помножити розмір типу даних одного елемента на кількість елементів.
Оператор `sizeof` зазвичай використовують, щоб отримати розмір типу даних кожного елемента.
Наступний приклад демонструє це

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

Важливо памʼятати, що памʼять, щойно виділена `malloc`, не ініціалізована, але може містити сміттєві значення.
Зауважте, що `sizeof` вказівника `numbers` не дорівнює ані кількості елементів масиву, ані загальному обсягу виділеної памʼяті.
Розмір вказівника, який повертає `malloc`, дорівнює розміру будь-якого вказівника в цій конкретній системі.
Приклад коду виконувався на 64-бітній системі, тож розмір вказівника був 8 байтів (8 бітів на байт, отже 64 біти).
Тип вказівника неявно перетворено з вказівника на void на вказівник на int.
Чи вказує вказівник на int на один `int`, чи на масив `ints`, програміст вирішує на власний розсуд.
Наприклад

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

Якщо значення точно буде записано перед читанням, то `malloc` може бути ефективним способом виділення памʼяті.
Але якщо є ймовірність, що значення прочитають до ініціалізації, то використовувати `malloc` ризиковано.
Безпечніше виділяти памʼять за допомогою `calloc`, який ініціалізує щойно виділену памʼять нулями.

Зауважте, що в прикладах вище використано `free(numbers)`.

## free

Функція `free` оголошена в `stdlib.h` і використовується для звільнення памʼяті, яку було динамічно виділено.
Динамічно виділена памʼять залишається зайнятою, доки її не звільнить `free`.
Деякі операційні системи можуть автоматично звільняти динамічно виділену памʼять після завершення програми, але найкраще не покладатися на це.
`free` має один параметр: вказівник на памʼять, яку було динамічно виділено.
Використання `free` або його відсутність повʼязані з кількома проблемами з памʼяттю.

#### витік памʼяті

Якщо динамічно виділену памʼять не звільнити після того, як посилання на неї вийшло з часу життя або було іншим чином знищене, це називають витоком памʼяті.
У витоку памʼять залишається зайнятою системою, але програма вже не має до неї доступу.
Це може бути особливою проблемою, якщо памʼять виділяють у циклі, не звільняють у кінці циклу й знову виділяють на початку циклу.
Якщо виділити достатньо памʼяті й не звільняти її, виклик виділення памʼяті зазнає невдачі через те, що не залишиться достатньо памʼяті для виділення.
Важливо памʼятати, що хоча динамічно виділена памʼять залишається зайнятою системою, доки її не звільнять, вказівник, якому її присвоєно, може мати лише область видимості блоку.
Наприклад, у прикладах із `malloc` памʼять виділяється у `my_function`.
Ця памʼять стала б витоком, якби вказівник на неї не повернули й не використали для встановлення вказівника `numbers` у `main`.
Отже, передавання цього вказівника `numbers` у `free` звільняє памʼять, виділену в `my_function`.

#### використання після звільнення (**UAF**)

Якщо до памʼяті звернутися після її звільнення, значення може бути будь-яким.
У наступному прикладі памʼять, на яку вказує `numbers`, звільняють, а потім читають із неї в `printf`.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

Вказівник `numbers` після звільнення називають висячим вказівником.
Висячий вказівник може вказувати на іншу памʼять, ніж та, для якої його призначали.
Отже, висячий вказівник може призвести до пошкодження даних, а також довільної підміни й виконання коду.
Вказівник на виділену памʼять, який не очистили, встановивши `NULL`, можна використати для злому програми.
У наведеному вище прикладі, якби `numbers` після звільнення встановили в `NULL` ось так: `numbers = NULL;`, наступний `printf` спричинив би завершення програми, можливо, з повідомленням про помилку сегментації під час спроби прочитати `numbers[0]`.

#### подвійне звільнення

Якщо викликати `free` двічі для вказівника на динамічно виділену памʼять, це спричиняє невизначену поведінку (**UB**).
Це означає, що компілятор може довільно обробити це як завгодно.
Наступний приклад, скомпільований двома різними компіляторами, може мати два різні результати

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

Перший і другий компілятори не згенерували помилки часу виконання, коли `numbers` встановлювали в `NULL` між кожним викликом `free`, але це не гарантовано працюватиме з третім компілятором.
Подвійне звільнення часто виникає, коли два вказівники вказують на ту саму динамічно виділену памʼять.
Один вказівник може вказувати на початок масиву в одному місці програми, а інший вказівник можуть використовувати, щоб перебирати масив в іншому місці програми.
У різних місцях програми кожен вказівник звільняють, що й спричиняє подвійне звільнення.

## calloc

Функція `calloc` оголошена в `stdlib.h` і використовується як для виділення динамічної памʼяті, так і для ініціалізації щойно виділеної памʼяті нулями.
Якщо виділення успішне, повертається вказівник, що вказує на адресу першого байта виділеної памʼяті.
Якщо виділення невдале, повертається `NULL`.
Варто перевіряти результат `calloc` на `NULL` і коректно обробляти невдачу.
Повернений вказівник має тип `pointer-to-void`, який можна приблизно вважати «загальним» вказівником, що його можна перетворити на конкретний тип, який використовує памʼять.
`calloc` має два параметри.
Перший параметр задає кількість елементів указаного типу даних, які потрібно виділити.
Другий параметр задає розмір указаного типу даних, який потрібно виділити.

У наступному прикладі всі інструкції `printf` завжди мають показувати `0`, бо `calloc` гарантовано обнуляє щойно виділені значення.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

Функція `realloc` оголошена в `stdlib.h` і використовується для розширення або звуження вже виділеної памʼяті.
Якщо перевиділення успішне, повертається вказівник, що вказує на адресу першого байта перевиділеної памʼяті.
Якщо перевиділення невдале, повертається `NULL`.
Варто перевіряти результат `realloc` на `NULL` і коректно обробляти невдачу.
`realloc` має два параметри.
Першим параметром є вказівник на наявну памʼять, яку треба перевиділити.
Другий параметр задає розмір у байтах перевиділеної памʼяті.
Значення, встановлені до розширення памʼяті, зберігаються.
Важливо памʼятати, що памʼять, додана під час розширення, не ініціалізується нулями, і її значення може бути будь-яким.
Крім того, памʼять, яку відтинають під час звуження, теж не ініціалізується й може зберігати старі значення.
Наступний приклад демонструє розширення й звуження масиву

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## Коли переданий розмір дорівнює 0

Якщо розмір, переданий у `malloc`, `calloc` або `relloac`, дорівнює `0`, то результат залежить від того, як це реалізує компілятор.
Компілятор може повернути або `NULL`-вказівник, або ненульовий вказівник.
Наприклад, виділяючи памʼять для вказівника на `char`, компілятор може повернути або `NULL`, або ненульовий вказівник на порожній рядок тексту (англ. string).
Щоб уникнути різних результатів у різних компіляторах, краще не виділяти памʼять із розміром 0.
