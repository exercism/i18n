# Вступ

Скалярний код покладається на прапорці, які встановлюють різні інструкції, щоб розгалужуватися у відповідь на певну умову.
Упаковані значення, однак, представляють не одне, а багато значень паралельно.
Одна умова може не виконуватися для однієї доріжки й виконуватися для іншої.

Саме тому код SIMD, як правило, _не містить розгалужень_.

Замість того щоб покладатися на прапорці, упаковані порівняння зазвичай створюють **маску** в операнді призначення.
Для кожної доріжки порівняння заповнює всю доріжку одиницями, коли воно істинне, і нулями, коли хибне.
Якщо читати як знакове ціле число, істинна доріжка дорівнює `-1`, а хибна дорівнює `0`.

Цю маску можна потім поєднати з порозрядними операціями, щоб відфільтрувати конкретні доріжки.

## Упаковані порівняння

Скалярний `cmp` є узагальненим у тому сенсі, що його використовують, щоб одночасно встановлювати різні прапорці.
Потім інша інструкція може використати ці прапорці, щоб або розгалузитися, або виконати обчислення.

Однак, оскільки упаковане порівняння і перевіряє умову, і обчислює маску, воно не є узагальненим.
Порівнянню потрібно надати точну умову, яку перевіряють.

Є два способи це зробити:

- Порівнянням цілих чисел умову задають суфіксом: `eq` для рівності, а `gt` для «більше ніж».
  Інші варіанти будують, поєднуючи результат одного з них.
- Порівнянням чисел з плаваючою комою умову передають закодованою в безпосередньому значенні.
  Різні значення цього безпосереднього значення відповідають різним перевірюваним умовам.

Окрім використання конкретного суфікса умови в порівняннях цілих чисел, синтаксис має ту саму структуру, яку ми вже бачили:

- Для цілих чисел `p` + `cmp` + умова + розмір (`b`, `w`, `d` або `q`).
- Для чисел з плаваючою комою `cmp` + `p` + розмір (`s` або `d`).
  Умову передають у безпосередньому значенні як додатковий операнд.

### Порівняння цілих чисел

Як уже згадувалося, для цілих чисел існують порівняння лише на рівність і на «більше ніж»:

| інструкція                                 | опис                                       |
|--------------------------------------------|--------------------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | рівність для кожної доріжки                |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | **знакове** «більше ніж» для кожної доріжки |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

Щоб створити порівняння «менше ніж», скористаймося `gt` з переставленими операндами: `a < b` == `b > a`.

Зауважмо, що порівняння **знакове**.
Щоб виконати беззнакове порівняння, перевернімо старший біт обох операндів.
Це можна зробити за допомогою XOR з маскою, у якій встановлено лише старший біт.

~~~~exercism/note
Дві корисні ідіоми:

1. XOR регістра із самим собою, щоб отримати всі нулі.
2. Порівняння регістра із самим собою, щоб отримати всі одиниці.

Наприклад:

```x86asm
pxor xmm4, xmm4    ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

Усі нулі та всі одиниці - поширені маски, що кодують «хибно всюди» та «істинно всюди» відповідно.
Їх також можна використати, щоб представити упакований `0` або упакований `-1`, які є поширеними сторожовими значеннями.
Наприклад, NUL, що позначає кінець рядка тексту (англ. string), - це `0`.
~~~~

### Порівняння чисел з плаваючою комою

Доріжки чисел з плаваючою комою мають іншу форму: одна інструкція `cmpps` (і `cmppd` для 64-бітних доріжок), з умовою як безпосереднім значенням:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

У NASM також є псевдооперації, які відповідають правильному безпосередньому значенню і які легше запамʼятати.
У всьому наведеному нижче `x` у `px` може бути `s` (32-бітні числа з плаваючою комою) або `d` (64-бітні числа з плаваючою комою):

| псевдооперація | безпосереднє значення | порівняння                    |
|----------------|-----------------------|-------------------------------|
| `cmpeqpx`      | 0                     | a == b                        |
| `cmpltpx`      | 1                     | a <  b                        |
| `cmplepx`      | 2                     | a <= b                        |
| `cmpunordpx`   | 3                     | a дорівнює NaN або b дорівнює NaN |
| `cmpneqpx`     | 4                     | a != b                        |
| `cmpnltpx`     | 5                     | a >= b                        |
| `cmpnlepx`     | 6                     | a >  b                        |
| `cmpordpx`     | 7                     | ні a, ні b не дорівнює NaN    |

## Вибір за допомогою маски

Маска кодує результат умови.
Її можна потім використати, щоб вибирати, доріжка за доріжкою, між двома наборами значень згідно з цією умовою.
Беремо доріжку з одного значення там, де маска істинна, і з іншого там, де вона хибна:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

Цей прийом - упакована форма вибору без розгалужень.
Кожну доріжку обчислюють, і сама лише маска вирішує, яке значення виживе, без жодного `jcc`.

## Спеціальні інструкції blend

Є інструкції, які виконують той самий вибір безпосередньо, читаючи по одному біту на елемент із регістра маски.
Їх називають інструкціями **blend**:

| інструкція | елемент          | джерело маски    |
|------------|------------------|------------------|
| `pblendvb` | байт             | неявний `xmm0`   |
| `blendvps` | 32-бітна доріжка | неявний `xmm0`   |
| `blendvpd` | 64-бітна доріжка | неявний `xmm0`   |

Зауважмо, що перша інструкція має синтаксис цілих чисел, тоді як дві інші мають синтаксис чисел з плаваючою комою.
Однак, оскільки ці інструкції просто вибирають необроблені байти, будь-яку з них можна використати і з цілими числами, і з числами з плаваючою комою.

Для кожного елемента blend зберігає призначення, коли старший біт відповідного елемента маски дорівнює нулю, і бере джерело, коли його встановлено.
Беруть до уваги лише цей **старший біт**, чому задовольняє маска порівняння, адже її доріжки містять самі одиниці або самі нулі.
Регістр маски завжди `xmm0`, і він неявний:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

Також можна використати `pblendvb`, щоб вибрати доріжки з маски порівняння для будь-якого іншого розміру.
Оскільки всі байти в істинній доріжці дорівнюють одиницям, `pblendvb` вибирає їх усі.

~~~~exercism/note
Усі ці інструкції додають `v` після операції, яку виконують (`blend`).
Ця `v` походить від _variable_, бо вибір не є статичним: він залежить від регістра.

Є також варіанти без `v`, які вибирають згідно з безпосереднім значенням.
Вони мають ту саму схему: вибирають доріжку `i`, якщо встановлено біт `i` безпосереднього значення.
~~~~

## Від маски назад до скалярного коду

Попри всю свою потужність, код SIMD бракує значної частини гнучкості скалярного коду.
У багатьох ситуаціях потрібно перейти від упакованого регістра назад у світ скалярних інструкцій.

Сімейство інструкцій `movmsk` слугує мостом між цими двома світами.
Ці інструкції витягують **старший біт** кожної доріжки в регістр загального призначення:

| інструкція | що збирає                       | ширина результату |
|------------|---------------------------------|-------------------|
| `pmovmskb` | старший біт кожного з 16 байтів | 16 бітів          |
| `movmskps` | старший біт кожного з 4 dword   | 4 біти            |
| `movmskpd` | старший біт кожного з 2 qword   | 2 біти            |

Якщо використати його після порівняння, кожен встановлений біт представляє «істинну» доріжку, а кожен очищений - «хибну».
Цей результат можна потім обробляти як звично за допомогою скалярних інструкцій.
Наприклад, `popcnt` рахує кількість збігів, а `tzcnt` знаходить перший.

Регістр загального призначення може бути 32- або 64-бітної ширини.

## Перевірка всього вектора

Є також упакований варіант скалярної інструкції `test` - `ptest`.

Він схожий на свій скалярний відповідник тим, що виконує операцію AND між двома операндами, не змінюючи їх.
На відміну від `test`, `ptest` також виконує операцію ANDN, заперечуючи перший операнд.

Отже, `ptest` можна розглядати як неразрушальну версію `pand` і `pandn`, яка встановлює прапорці за результатом.
Так само, як і ці дві інструкції, `ptest` розглядає весь регістр SIMD як одну доріжку, тому не приймає префікса розміру.

Якщо результат операції AND дорівнює `0`, встановлюється `ZF`, а якщо операція ANDN дає `0`, то встановлюється саме `CF`.
Це означає, що `ptest` можна використати для перевірки як маски з усіх одиниць, так і маски з усіх нулів:

1. Використання `ptest` на регістрі із самим собою встановлює `ZF`, лише якщо регістр містить самі нулі.
   Це повторює поширену скалярну ідіому використання `test` на регістрі із самим собою для перевірки на `0`.
2. Використання `ptest` на регістрі з маскою з усіх одиниць встановлює `CF`, лише якщо регістр містить самі одиниці.
   Крім того, воно встановлює `ZF`, лише якщо регістр містить самі нулі, що дає змогу перевірити обидві маски одразу.

```x86asm
pxor    xmm0, xmm0   ; all zeros
pcmpeqb xmm1, xmm1   ; all ones
pcmpeqb xmm2, xmm2

ptest xmm0, xmm0     ; ZF set: a register against itself detects all zeros
ptest xmm0, xmm1     ; ZF set, CF clear: xmm0 is all zeros, not all ones
ptest xmm2, xmm1     ; CF is set only if xmm2 is all ones
```

Результат `ptest` можна, як звично, використати для розгалуження або в інструкціях без розгалужень, як-от `setcc` чи `cmovcc`.
