# Докладніше

Словник - це одиниця організації у Factor: іменований набір визначень слів.

```factor
USING: kernel ;
IN: greetings.formal

: hello ( name -- str ) "Greetings, " prepend ;
```

## Структура файлів і каталогів

Назви словників використовують `.` як роздільник. Шлях повторює ці крапки:

| Словник                | Файл                                       |
| ---                    | ---                                        |
| `greetings`            | `greetings/greetings.factor`               |
| `greetings.formal`     | `greetings/formal/formal.factor`           |
| `greetings.casual`     | `greetings/casual/casual.factor`           |

Завантажувач Factor шукає словники, обходячи *корені словників*, тобто корінь
проєкту та вбудовану бібліотеку basis, доки не знайде каталог, назва якого
збігається з кожним сегментом шляху. Останній сегмент повторюється як назва
файлу.

## `USING:` та `IN:`

`USING:` (а також `USE:` для одного словника за раз) додає інші словники до
шляху пошуку поточного файлу. `IN:` оголошує, до якого словника *належать*
слова, визначені в цьому файлі: їхні повні імена починаються з цього префікса.

```factor
USING: kernel sequences greetings.formal ;
IN: greetings

: greet-everyone ( names -- strs )
    [ hello ] map ;
```

Тут `greet-everyone` належить до словника `greetings`, викликає `hello` зі
словника `greetings.formal` і `map` зі словника `sequences`.

## Навіщо розділяти рішення між словниками

Розділення коду між словниками дає змогу:

- Групувати дрібні допоміжні слова за відповідальністю, окремо від
  високорівневої процедури, яка їх поєднує.
- Використовувати ці допоміжні слова повторно з іншого місця, не тягнучи за
  собою основну процедуру.
- Читати кожен файл як один цілісний рівень абстракції.

Завантажувач Factor працює досить швидко й ліниво, тож розділення *вниз* на
менші словники недороге; у стандартній бібліотеці прийнято активно дробити код
на словники.
