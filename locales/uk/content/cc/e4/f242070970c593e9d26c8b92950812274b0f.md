# Докладніше

Вправа з програмування ілюструє низку властивостей параметрів:

- Параметри, [передані][passing-parameters] без модифікатора (такого як `out` чи `ref`), передаються за значенням. Тобто параметр можна використовувати й присвоювати йому значення у викликаному методі, але будь-які зміни не вплинуть на того, хто викликає.
- Коли параметром є посилання на масив або на екземпляр класу, викликаний метод може змінювати елементи чи поля цього екземпляра, і ці зміни побачить той, хто викликає. Це стосується незалежно від наявності модифікатора `ref`.
- Параметр із модифікатором [`out`][out-parameter] передає значення назад із викликаного методу до того, хто викликає. Такий параметр можна передати викликаному методу неініціалізованим, і в будь-якому разі всередині викликаного методу з ним поводяться так, ніби на вході він не був ініціалізований. Найлегше зрозуміти поведінку та правила щодо модифікаторів параметрів на прикладах (див. нижче) і з повідомлень компілятора.

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- У викликаному методі параметру `out` обовʼязково треба присвоїти значення.

- Параметр із модифікатором [`ref`][ref-parameter] передає значення у викликаний метод. Коли метод повертає керування, той, хто викликає, побачить у цьому параметрі будь-які оновлення, зроблені викликаним методом.

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

- Параметри `ref` мають бути змінними, оскільки викликаний метод працюватиме безпосередньо з параметром таким, яким його бачить той, хто викликає.

- Модифікатори `out` і `ref` потрібні як у сигнатурі викликаного методу, так і в місці виклику.
- Параметри `out` можна оголосити безпосередньо в місці виклику, наприклад: `Foo(out int importantValue);`
- Якщо ми викликаємо метод, який має параметри `out`, але нас не цікавить значення, присвоєне одному чи кільком із них, то можна скористатися [відкидачем][discard], фіктивною змінною `_`, як тут: `Foo(out int _);`

Усі правила щодо параметрів `ref` і `out` перевіряє компілятор.

Параметри [`in`][in-parameter] також існують, але вони переважно є оптимізацією продуктивності й розглядаються у вправі `structs`, де вони найдоречніші.

Документацію, посилання на яку наведено вище, узагальнено нижче:

- [Передавання параметрів][passing-parameters]: пояснює, як значення можна передавати як аргументи. Зазначимо, що тему struct і параметрів розглянуто у вправі `structs`.
- [Параметр `ref`][ref-parameter]: описує, як працюють параметри `ref`.
- [Параметр `out`][out-parameter]: описує, як працюють параметри `out`.

Опрацьовуючи документацію, зазначимо, що в ній використано такі терміни:

- параметр / формальний параметр: позначає параметр таким, яким його бачить викликаний метод.
- аргумент: позначає параметр таким, яким його бачить той, хто викликає.

[Можна стверджувати][so-tuples-vs-out], що значною мірою цінність параметрів `out` усунуло запровадження `tuples` у C# 7. У вправі `tuples` показано, як `tuples` використовують для повернення кількох значень.

Хоча `ref` легко використовувати й він не має втрат продуктивності, варто подивитися, як проблеми, які він розвʼязує, розвʼязують у конкретній кодовій базі, перш ніж широко його застосовувати. Є й альтернативи, як-от передавання за значенням і використання значення з інструкції return викликаного методу. І знову ж таки, свою роль можуть відіграти `tuples`.

З [документації][ref-parameter] видно, що `out` і `ref` не можна використовувати в певних ситуаціях, але поки що на них можна не зважати. Компілятор повідомить, коли такі ситуації трапляться.

Зазначимо, що `optional parameters` і `named arguments` розглянуто у вправі `method-overloading`.

Споріднені теми [`ref local`][ref-local] і [`ref return`][ref-return] розглянуто в іншому місці.

## Виділення памʼяті в стеку

Правила щодо параметрів та їхніх модифікаторів досить прості, тож їх можна сприймати буквально й розуміти на їхньому рівні абстракції. Однак якщо виникає цікавість до механізмів, що лежать в основі, і до того, чому ці ключові слова можуть впливати на продуктивність, принаймні у випадку `struct`, то можна почати з цієї [статті у Вікіпедії][calling-conventions], зважаючи на те, що C# використовує `stdcall` на x86/64.

Суть ось у чому: у випадку немодифікованих параметрів **значення** змінної копіюють у стек програми, щоб зробити його доступним для викликаної підпрограми, тоді як для параметрів `ref`, `out` і `in` у стек програми кладуть вказівник (**посилання**) на памʼять, що містить значення, і значення присвоюють тій памʼяті, на яку вказує посилання.
