# Докладніше

`struct` у C# тісно повʼязані з `class`.
Вони мають стан і поведінку.
Вони можуть мати такі самі види членів: конструктори, методи, поля, властивості тощо.

Поля та властивості можуть бути простими типами, `struct` або типами-посиланнями.
`struct` підлягають тим самим правилам щодо області видимості, правил читання та запису й рівнів доступу, що й `class`.

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

Одне з головного, що варто запамʼятати: коли один `struct` присвоюють змінній або передають як параметр, значення копіюються, тож зміни в початковій змінній не вплинуть на копію, і навпаки.
Підсумовуючи, `struct` - це **типи-значення**.

У цій [статті][class-or-struct] розглядаються відмінності між `struct` і `class`.
Зі статті видно, що `struct` зазвичай легковагі та [незмінні][structs-immutable], хоча компілятор чи середовище виконання (типово) цього не вимагають.

Є кілька речей, з якими ми зіткнемося (і про які компілятор нам нагадає):

1. Члени `struct` не можна ініціалізувати одразу в оголошенні.
2. `struct` не можна успадкувати
3. `struct` завжди має типовий конструктор, навіть якщо задано нетиповий, і не можна задати явний конструктор без параметрів.

Тож через пункти 1 і 3 вище розробник `struct` жодним чином не може запобігти появі некоректних примірників.

## Поширені struct-и

З документації видно, що примітиви та `struct` тісно повʼязані між собою.
Наприклад, погляньмо на [`Int32/int`][int32].
Звичніший приклад `struct` - це тип [`TimeSpan`][time-span].

Примірники `TimeSpan` поводяться майже як числа: мають оператори порівняння, як-от `>` і `<`, та арифметичні оператори.
Ці оператори можна реалізувати й для власних `struct`, коли вони потрібні.

Варто зауважити, що `TimeSpan` реалізує низку інтерфейсів, наприклад `IComparable<TimeSpan>`.
Хоча `struct` не можуть бути похідними від інших `struct`, вони можуть реалізовувати інтерфейси.

## Рівність

Перевірка рівності для `struct` часто буває значно простішою, ніж для `class`, адже типово вона просто порівнює поля на рівність.
Немає потреби перевизначати `object.Equals()` (чи `GetHashCode()`).
Памʼятаймо, що, покладаючись на `Object.GetHashCode()`, ми все одно маємо стежити за тим, щоб поля, задіяні у створенні хеш-коду (тобто всі поля), не змінювалися, поки використовується колекція з хешуванням.
По суті, це означає, що `struct`, які використовують у такий спосіб, мають бути незмінними.

На відміну від методу `Equals()`, для операторів рівності `==` і `!=` типової реалізації немає.
Якщо для нашого `struct` вони потрібні, їх доведеться реалізувати.

З іншого боку, у цій [статті][equality] описано, як можна оптимізувати швидкодію, створивши власні методи `Equals()` і `GetHashCode()`, як це часто роблять і для `class`.
У цій вправі різниця становила близько 20% за не дуже строгого порівняння, але це може бути занизька оцінка, бо всі поля мають той самий тип, див. нижче.

В [інтернеті][equality-performance] є обговорення покращення швидкодії, коли метод `Equals()` не перевизначено, якщо всі поля мають той самий тип.
Різниця в цій вправі від додавання різнорідних полів становила близько 60%.
У документації Microsoft про це не згадано, тож це незадокументована деталь реалізації, і користуватися нею варто обережно.

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
