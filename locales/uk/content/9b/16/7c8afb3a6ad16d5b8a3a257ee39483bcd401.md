# Докладніше

`TUPLE: child < parent extra-slots ;` оголошує клас, примірники якого є також
примірниками `parent`. Пошук слота проходить ієрархією: `child` має кожен
слот, оголошений батьківським класом, а також власні, саме в такому порядку.

```factor
TUPLE: vessel name tonnage ;
TUPLE: cargo-vessel < vessel capacity ;
TUPLE: tanker < cargo-vessel fuel-type ;
```

## Порядок аргументів `boa`

Автоматично згенерований конструктор `boa` приймає слоти в порядку
оголошення, *спочатку батьківські*. Для `tanker` вище:

```
tanker boa ( name tonnage capacity fuel-type -- tanker )
```

Порядок слотів визначає ланцюг успадкування: батьківські та дочірні слоти
неможливо перемішати, а зміна порядку слотів у батьківському класі є зворотно
несумісною зміною для `boa` кожного нащадка.

## Ієрархія предикатів

Кожне оголошення `TUPLE:` генерує предикат класу
(`name?`). З успадкуванням предикати вкладаються один в один:

```factor
"Esso" 50000 100000 "diesel" tanker boa .

! all three predicates fire
dup tanker?        .   ! => t
dup cargo-vessel?  .   ! => t
dup vessel?        .   ! => t
```

`instance?` (з [`classes`][classes]) ставить те саме запитання,
але клас передається як аргумент стека, а не вшитий у назву слова:
`obj tanker instance?` робить те саме, що `obj tanker?`:

```factor
USING: classes ;

"Esso" 50000 100000 "diesel" tanker boa
dup vessel instance? .   ! => t
```

Оскільки клас тепер є значенням, те саме місце виклику може перевіряти щодо
будь-якого класу, який йому передадуть, чого фіксований предикат `name?`
зробити не може.

Транзитивним відношенням `is-a` керується також диспетчеризація методів
`M:`: метод, визначений на `vessel`, застосовується до кожного
`cargo-vessel` і кожного `tanker`, якщо тільки першим не спрацює точніше
перевизначення. Про цей бік історії йдеться в
[`generics`][generics].

## Успадкування аксесорів

Слова-аксесори (`slot>>`, `>>slot`, `change-slot`) походять із
[`accessors`][accessors] і не привʼязані до класу, для якого
були згенеровані: будь-який кортеж, що *має* цей слот, може ними
скористатися.

```factor
USING: accessors ;

"Esso" 50000 100000 "diesel" tanker boa
[ 1 + ] change-tonnage tonnage>> .   ! => 50001
```

`change-tonnage` було згенеровано для `vessel`, але він працює з
`tanker`, бо кожен `tanker` є `vessel`.

## Чим це не є

- **Міксини** (`MIXIN:` / `INSTANCE:`): клас може приєднувати багато
  міксинів; звʼязок тут «багато до багатьох», і його використовують
  переважно для узагальненої диспетчеризації за спільним протоколом.
  Концепція потоків знайомить із ними в контексті.
- **Класи-предикати** (`PREDICATE:`): виокремлюють підклас із
  наявного класу за предикатом часу виконання. Це окрема можливість
  Factor, тут вона не розглядається.
