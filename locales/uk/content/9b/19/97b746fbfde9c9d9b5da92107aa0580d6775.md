# Докладніше

Памʼять для програми зазвичай розміщує операційна система (ОС) у загальному вигляді:

| адреса  | ділянка памʼяті         |
| :-----: | :--------------------- |
| висока  | стек                   |
|         | ...                    |
|         | купа                   |
|         | сегмент читання й запису |
|         | сегмент коду/лише для читання |
| низька  | зарезервовано          |

Памʼять у сегментах організовано в секції з різними правами доступу.

Усі функції, які ми визначали досі, були в **секції .text**.
Ця секція містить дані, доступні лише для читання, які можна виконувати.
В інших секціях оголошують змінні даних, які можуть бути доступними лише для читання або для читання й запису, але не можуть виконуватися.

## Секція .data

Ініціалізовані дані оголошують у **[секції .data][data]**.

У NASM (The Netwide Assembler, асемблер, який використовує цей трек) ініціалізована змінна має назву, директиву, що вказує розмір даних, і список значень, розділених комами.
Кожен із них відокремлено від іншого пробілом, а після мітки необовʼязково може стояти `:`.

Основні директиви та відповідні їм розміри даних:

| директива | розмір  |
| :-------: | :------ |
|    db     | 1 байт  |
|    dw     | 2 байти |
|    dd     | 4 байти |
|    dq     | 8 байтів |

Наприклад, ось так оголошують байтову змінну з назвою `space` і значенням `10`:

```x86asm
section .data
    space db 10
```

Змінні, оголошені в `section .data`, є змінюваними, тобто доступними для читання й запису.
Вони також мають _статичний_ час зберігання, тобто існують упродовж усього часу роботи програми.

## Секція .rodata

**Секція .rodata** подібна до `section .data`.
Обидві секції містять ініціалізовані дані, які оголошують однаково, і мають однаковий час зберігання.

Основна відмінність між ними полягає в тому, що дані в `section .rodata` є незмінними, тобто доступними лише для читання.

~~~~exercism/note
Константи, визначені за допомогою `equ`, відрізняються від тих, що визначені в `section .rodata`.

Константа, визначена за допомогою `equ`, не займає місця в памʼяті, і асемблер безпосередньо підставляє замість неї її значення.
Фактично вона є замінником цього значення.

Натомість константи, визначені в `section .rodata`, насправді зберігаються в памʼяті й мають адресу.
~~~~

## Доступ до даних

### Мітки та непряма адресація

Оголошені дані повинні мати повʼязану з ними назву.
Цю назву називають **міткою**.

Мітка - це символ, який кодує конкретну адресу даних у памʼяті.
**Адреси в x86-64 - це 64-бітові значення**.
Значення, яке зберігає таку адресу (неважливо, у регістрі чи в памʼяті), - це те, що мови вищого рівня називають **[вказівником][pointer]**.

У NASM спроба звернутися до даних безпосередньо за їхньою міткою дає не виділену памʼять, а її адресу:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

Щоб отримати вміст певної адреси памʼяті, потрібно її _розіменувати_.
Це називають **непрямою адресацією**.

У NASM це роблять за допомогою `[]`:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

Однак бувають ситуації, коли може виникнути неоднозначність щодо розміру розіменованої памʼяті.
У таких випадках потрібно використати префікс, який указує цей розмір.

Ось найважливіші префікси та їхні розміри в типовій програмі x86-64:

| префікс | розмір  |
| :----- | :------ |
| byte   | 1 байт  |
| word   | 2 байти |
| dword  | 4 байти |
| qword  | 8 байтів |

Те саме завантаження можна записати з явно вказаним розміром:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

Гарна практика - завжди використовувати префікс під час розіменування памʼяті.

### Запис у памʼять

Запис у памʼять відбувається так само: через розіменування адреси:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

Зауважимо, що операнди памʼяті можна використовувати в більшості інструкцій, не завантажуючи спочатку їхній вміст у регістр.
Однак зазвичай їх не можна використовувати одночасно і в операнді-джерелі, і в операнді-призначенні, лише в одному з двох:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### Інструкція LEA

Хоча `mov` і можна використати, щоб зберегти адресу змінної в регістрі, для цієї конкретної мети є інструкція: **[lea][lea]**.

Ця інструкція використовує операнд у формі памʼяті, але _не_ читає памʼять.
Замість цього вона обчислює вираз ефективної адреси й записує результат в операнд-призначення:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

Ідіоматичніше використовувати `lea` для обчислення й збереження адрес памʼяті в регістрах.

### Відносна адресація

Коли ми звертаємося до комірок памʼяті, NASM за типовою поведінкою генерує **абсолютні адреси**, тобто фіксовані адреси памʼяті.

З міркувань безпеки виконувані файли часто збирають як **PIE (Position Independent Executable, позиційно-незалежний виконуваний файл)**, де ділянки памʼяті розміщуються за випадковими адресами.
У `PIE` остаточна адреса змінної невідома на етапі компонування.
Тому код натомість обчислює адреси як зсув від значення в спеціальному регістрі `rip`, який указує на наступну інструкцію для виконання.

Зазвичай це називають **адресацією відносно RIP**.

У NASM можна зажадати доступ відносно RIP за допомогою **[оператора rel][rel]**:

```x86asm
mov rax, qword [rel variable]
```

Відносну адресацію також можна зробити типовою для файлу з кодом, додавши `default rel` на початку.

Усі вправи в цьому треку компілюються й компонуються як `PIE`, тому для генерації відносних адрес слід використовувати `rel`.

Згадане вище випадкове розміщення - це запобіжний захід, відомий як рандомізація адресного простору.
Роблячи основу кожної ділянки памʼяті непередбачуваною, воно позбавляє зловмисника фіксованих адрес, на які покладається багато технік експлуатації, а `PIE` дає змогу завантажувачу розміщувати ці ділянки будь-де.

Через це абсолютна адресація в цьому треку не просто небажана, вона непридатна до використання.
Абсолютне посилання, як-от `[abs variable]`, вимагає від асемблера вбудувати фіксовану 32-бітову адресу в інструкцію.
У Linux компонувальник `PIE` відхиляє переміщення, яке при цьому утворюється, а в macOS формат `macho64` узагалі не підтримує 32-бітові абсолютні адреси, тож файл не вдається зібрати.

Адресація відносно RIP уникає обох проблем, адже інструкція кодує лише зсув від `rip`, а не фіксовану адресу.
Тож ідіоматичний спосіб помістити адресу в регістр за `PIE` - це `lea` з операндом `rel`:

```x86asm
default rel

section .data
    variable dq 7

section .text
fn:
    lea rax, [rel variable]       ; materialize the address (PIE-safe)
    mov rcx, qword [rel variable] ; load the value through a RIP-relative access
    ...
```

### Видимість

Мітки (функції та дані), визначені в будь-якій секції (наприклад, `.text`, `.data`, `.rodata`), видимі в межах того самого файлу з кодом.
Якщо їх оголошено як `global`, вони видимі й для інших файлів з кодом.

І навпаки, мітки, визначені в інших файлах з кодом, видимі для поточного файлу, якщо їх оголошено як `extern`.
У цьому разі в асемблері немає жодної вказівки на розмір даних, його треба знати заздалегідь.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
