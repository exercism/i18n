# Докладніше

Як ми розглядали в концепції [`Nothingness`][concept-nothingness], R має різні способи представити дані, які відсутні ([`NULL`][ref-null]), невідомі ([`NA`][ref-na]) або математично недійсні ([`NaN`][ref-finite], [`Inf`][ref-finite]).
Загалом R намагається використовувати ці значення, щоб позначати проблеми на місці, і продовжує роботу, не викликаючи винятку.

## `stop()`

Деякі проблеми надто фундаментальні, щоб дозволити програмі продовжити роботу.
У такому разі скористайтеся [`stop(msg)`][ref-stop], щоб негайно зупинити програму з помилкою `Error` і вивести `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Подібно до [`assert`][wiki-assert] в інших мовах, [`stopifnot()`][ref-stopifnot] є зручною обгорткою для `stop()`.
Аргументами є довільна кількість булевих умов (англ. Boolean), розділених комами, і програма продовжить роботу, лише якщо всі вони `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R має безліч способів обробки помилок.
Вони базуються на Common Lisp і суттєво відрізняються від багатьох популярних мов.

Найпростіший спосіб - обгорнути потенційно проблемний код у [`try()`][ref-try].

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning] і [`message()`][ref-message]

Це реакції на нефатальні умови, наприклад:

- Щоб попередити про проблему, з якої програма могла б принаймні частково відновитися.
- Щоб повідомити користувача про поступ у довготривалій програмі.

Одна з відмінностей між ними полягає в тому, що попередження кешуються і (типово) виводяться після повернення функції, а повідомлення виводяться негайно.
Існує багато способів змінити типову поведінку, які виходять за межі нашого розгляду.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

Функція [`suppressWarnings()`][ref-warning] іноді може стати в пригоді на Exercism, щоб не заплутати test runner небажаним виводом.
