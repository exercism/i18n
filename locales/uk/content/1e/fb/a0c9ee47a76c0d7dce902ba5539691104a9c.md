# Вступ

## Двійкова нотація

**Ціле число** - це абстракція, яка представляє цілі числа, як-от `4`, `-2`, `0` або `64532`.

Щоб подати ціле число як послідовність байтів, використовують **двійкову нотацію**.
У цій нотації кожен біт у послідовності представляє окремий степінь двійки, причому значення зростає зі збільшенням індексу біта справа наліво.

## Беззнакові числа

Якщо число може бути лише невідʼємним, його називають **беззнаковим** числом.

Беззнакові числа подаються безпосередньо як сума степенів двійки, що відповідають усім встановленим бітам у їхній послідовності.

Діапазон невідʼємних цілих чисел, які можна подати в регістрі, простягається від `0` (жоден біт не встановлено) до `2⁶⁴ - 1` (сума всіх 64 встановлених бітів).

Розширення беззнакового числа до більшого розміру виконується заповненням усіх старших бітів нулями (`0`), щоб жоден новий біт не впливав на значення.
Це називається **нульовим розширенням**.

Інструкція `movzx` (`z` означає zero) виконує нульове розширення 8-бітного або 16-бітного операнда-джерела до більшого операнда-призначення.
32-бітний операнд-джерело завжди зазнає нульового розширення до всіх 64 бітів операнда-призначення звичайною інструкцією `mov`.

## Числа зі знаком

Якщо ціле число може набувати додатних або відʼємних значень, його називають **знаковим** числом.

Для подання відʼємних чисел x86-64 використовує **доповняльний код**.

У доповняльному коді знакові числа також подаються як сума степенів двійки, що відповідають встановленим бітам.
Однак якщо найстарший біт установлено, його віднімають, а не додають до інших.

Оскільки цей біт відповідає більшому значенню, ніж сума всіх інших, на практиці це означає, що число з увімкненим цим бітом завжди відʼємне.
Цей особливий біт називається **бітом знака**.

Розширення знакового числа до більшого розміру означає заповнення кожного нового старшого біта копією біта знака, щоб значення збереглося.
Це називається **знаковим розширенням**.

Інструкція `movsx` (`s` означає sign) виконує знакове розширення 8-бітного або 16-бітного операнда-джерела до більшого операнда-призначення.
Варіант `movsx` під назвою `movsxd` робить те саме з 32-бітного операнда-джерела до 64-бітного операнда-призначення.

Інструкцію `neg` можна використати, щоб змінити знак числа.

~~~~exercism/caution
В асемблері немає способу визначити, чи послідовність байтів представляє знакове або беззнакове число.
Відповідальність програміста - надати цим байтам значення.

Використання коментарів може дуже допомогти в цьому завданні.
~~~~

## Безпосередні значення

У попередньому концепті згадувалося, що стале число, як-от `4` або `-15`, можна використовувати як операнд-джерело для багатьох інструкцій.
Такі числа називаються **безпосередніми значеннями**.

Безпосереднє значення не зберігається в регістрі чи в памʼяті: воно закодоване всередині самої інструкції.
У більшості інструкцій місце, зарезервоване для нього, має лише 32 біти, незалежно від того, наскільки великий операнд-призначення.

Коли операнд-призначення має 64 біти, ці 32 біти _зазнають знакового розширення_, щоб його заповнити.
Верхня половина операнда повністю заповнюється копіями найстаршого біта безпосереднього значення, тож у такий спосіб можна записати лише число в діапазоні _32-бітного цілого числа зі знаком_:

```x86asm
add rax, -1          ; the immediate is sign-extended, so all 64 bits of rax are affected
add rax, 2147483647  ; the largest immediate an instruction like this accepts
```

Число поза цим діапазоном не можна використати як безпосереднє значення.
Виняток із цього правила - `mov`, який може приймати повне 64-бітне безпосереднє значення, коли операнд-призначення є регістром.
Якщо потрібне 64-бітне безпосереднє значення, спочатку використаймо `mov`, щоб завантажити його в регістр, а потім використаймо цей регістр:

```x86asm
mov rax, 3435973837           ; this works, mov can take a 64-bit immediate
mov rdx, 18446744073709551615 ; the largest immediate mov accepts
sub rdx, rax
```

Зауважмо, що відʼємне безпосереднє значення й беззнакове число з тим самим бітовим поданням еквівалентні та асемблюються в те саме значення:

```x86asm
mov rax, -1                   ; rax = 18446744073709551615
mov rax, 18446744073709551615 ; rax = -1
```

## Додавання

Додавання двох чисел можна обчислити за допомогою інструкції `add`.

Є також однооперандна інструкція `inc`, яка додає `1` до значення у своєму операнді:

```x86asm
inc rax ; rax = rax + 1
```

Додавання двох цілих чисел працює однаково як для беззнакових, так і для знакових чисел.

## Віднімання

Віднімання двох цілих чисел виконується за допомогою інструкції `sub`.

Є також однооперандна інструкція `dec`, яка віднімає `1` від значення у своєму операнді:

```x86asm
dec rax ; rax = rax - 1
```

Віднімання двох цілих чисел також працює однаково як для беззнакових, так і для знакових чисел.

## Множення

У x86-64 є дві різні інструкції для множення двох чисел.
Зазвичай беззнакове множення використовує інструкцію `mul`, а знакове множення використовує `imul`.

Інструкція `mul` має таку однооперандну форму, де `src` позначає операнд-джерело:

```x86asm
mul src
```

Інструкція `imul` може мати однооперандну, двооперандну або триоперандну форму:

```x86asm
imul src
imul dest, src
imul dest, src1, src2
```

### Однооперандне множення

Для виконання множення в однооперандній формі неявно використовуються два регістри: `rax` і `rdx`.
Якщо множення охоплює два 64-бітні числа, то молодші 64 біти результату будуть у `rax`, а старші 64 біти будуть у `rdx`.

Це зазвичай називають `rdx:rax`, щоб показати, що обидва регістри використовуються разом:

```x86asm
mul rcx ; rax = lower 64 bits of rax * rcx
        ; rdx = upper 64 bits of rax * rcx
```

Те саме відбувається з іншими розмірами операндів.
Наприклад, якщо множаться два 32-бітні числа, будуть використовуватися `eax` і `edx`.

Винятком є множення двох байтів.

У цьому випадку замість `dl:al` буде використовуватися `ax`.
Молодша частина `ax` (`al`) отримає молодші 8 бітів добутку, а старша частина (`ah`) отримає старші 8 бітів.

~~~~exercism/caution
Регістри, які неявно використовуються в множенні, як-от `rax` і `rdx`, завжди перезаписуються.
Значення в цих регістрах слід зберегти перед операцією, якщо вони знадобляться пізніше.
~~~~

### Двооперандне множення

Двооперандна форма `imul` має явний операнд-призначення і дотримується звичайного синтаксису.
`rdx` не використовується.
Замість цього результат обрізається, щоб уміститися в операнд-призначення.

```x86asm
imul r8, r9 ; r8 = lower 64 bits of r8 * r9
```

### Триоперандне множення

Триоперандна форма `imul` має два операнди-джерела, другий з яких завжди є безпосереднім значенням (сталим числом).
Обидва операнди-джерела перемножуються, результат обрізається й розміщується в операнді-призначенні:

```x86asm
imul r8, r9, 100 ; r8 = lower 64 bits of r9 * 100
```

Зауважмо, що операнд-призначення не використовується в множенні.
Він лише отримує результат.

### Опрацювання переповнення

І двооперандне, і триоперандне множення обрізають результат, щоб умістити його в розмір операнда-призначення.
Однооперандне множення зберігає повний діапазон, але його зазвичай розділяють між двома регістрами, `rdx` і `rax`.

Тож іноді корисно розширити операнди перед множенням, щоб умістити весь добуток в одному регістрі.
Беззнаковий операнд зазнає нульового розширення, а знаковий - знакового розширення:

```x86asm
movzx eax, di ; di and si hold unsigned 16-bit numbers
movzx ecx, si
mul ecx       ; the 32-bit product fits in eax, and edx is cleared
```

## Ділення

Як і у випадку з множенням, є також дві інструкції для ділення двох чисел.
Беззнакове ділення використовує інструкцію `div`, а знакове ділення використовує `idiv`.

Обидві інструкції працюють лише з одним операндом:

```x86asm
div src
idiv src
```

16-бітне, 32-бітне та 64-бітне ділення використовують `dx:ax`, `edx:eax` і `rdx:rax` як ділене відповідно.
У цих випадках обидва регістри діють разом, утворюючи 2N-бітне значення, де N - розмір операції (16, 32 або 64 біти).
Це значення потім ділиться на операнд-джерело.
Частка записується в `ax`, `eax` або `rax`, а остача - у `dx`, `edx` або `rdx`, залежно від розміру операції.

Ділення байтів особливе: замість `dl:al` використовується `ax`.
Молодші 8 бітів `ax` (`al`) отримають частку від операції, а старші 8 бітів (`ah`) - остачу.

Зауважмо, що всі біти в діленому слід належно встановити перед діленням.
Будь-який встановлений біт у `rdx` (або в `ah` для 8-бітного ділення) впливає на значення, яке ділиться.

У беззнаковому діленні, коли значення, яке ділиться, уміщується в молодшій половині, старшу половину слід очистити.
Підійде будь-яка інструкція, яка очищає ці біти.
Наприклад, `mov edx, 0` очищає старші біти в 32-бітному діленні.

У знаковому діленні натомість значення слід знаково розширити.
Є інструкції, які автоматизують цей процес: `cbw`, `cwd`, `cdq` і `cqo`.
Перша встановлює біти в `ah` відповідно до знака `al`.
Інші виконують знакове розширення з `ax` до `dx`, з `eax` до `edx` і з `rax` до `rdx` відповідно.

~~~~exercism/caution
Регістри, які неявно використовуються в діленні, як-от `rax` і `rdx`, завжди перезаписуються.
Значення в цих регістрах слід зберегти перед діленням, якщо вони знадобляться пізніше.
~~~~
