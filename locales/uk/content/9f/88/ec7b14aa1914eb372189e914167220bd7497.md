# Власні ітератори

Ми користуємося ітераторами ще від вправи `bird-survey`. Тепер ми напишемо власний.

## yield

Ітератор має вигляд процедури з двома відмінностями: його назва закінчується на `!`, і він передає значення за допомогою `yield`, а не `return`.

```sather
   markers!(count : INT) : INT is
      loop
         yield 100 * 1.upto!(count);
      end;
   end;
```

`yield` віддає значення циклу, який викликав ітератор, а тоді **чекає**. Коли той цикл заходить на нове коло, ітератор продовжує одразу після `yield`, з усім саме так, як він це залишив: зі своїми змінними, своїм циклом, своїм місцем.

Ось що таке ітератор: процедура, яка може зупинитися посеред роботи, а потім продовжити.

```sather
   loop
      #OUT + TRAIL::markers!(3) + " ";      -- 100 200 300
   end;
```

## Завершення

Ітератор завершується одним із двох способів.

**Вичерпання.** Коли власний цикл ітератора добігає кінця або процедура доходить до свого кінця, усе завершено, і цикл, який його викликав, теж одразу завершується.

**quit.** `quit` завершує його тут же, не віддавши жодного значення.

```sather
   named!(names : ARRAY{STR}) : STR is
      loop
         name ::= names.elt!;
         if name = "" then quit; end;
         yield name;
      end;
   end;
```

Він віддає імена, доки не натрапить на порожнє, і тоді спиняється. `quit` для ітератора те саме, що `return` для процедури, тільки він не несе жодного значення: передавати вже нічого.

## once

Аргумент, позначений `once`, обчислюється лише один раз, коли цикл починається, а не на кожному колі:

```sather
   markers!(once count : INT) : INT is
```

Застосовуймо його до всього, що не змінюється між колами, а це більшість аргументів. Ітератори самої бібліотеки так і роблять: `upto!(once i : SAME)`.

## Ітератори без значення

Ітератор не мусить нічого віддавати. Ось `times!`:

```sather
   steps!(once count : INT) is
      loop
         ignored ::= 1.upto!(count);
         yield;
      end;
   end;
```

Голий `yield` не віддає нічого і просто дає циклу зробити наступне коло.

## Де живе позиція

Кожне *місце в програмі*, яке викликає ітератор, тримає власну позицію, і саме тому два виклики того самого ітератора в одному тілі циклу проходять його двічі. Тепер зрозуміло чому: ці два виклики - це дві окремі зупинені процедури.
