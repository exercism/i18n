# Побудова рядків тексту

`STR` незмінний, а `FSTR` - ні. Використовуймо `STR` для готового тексту, а `FSTR` - для тексту, який ще збираємо.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## Завжди присвоюйте результат назад

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR` зростає завдяки **амортизованому подвоєнню**: коли в ньому закінчується місце, він бере новий, більший масив (удвічі більший) і копіює вміст туди. Тож результатом зазвичай буває той самий обʼєкт, а іноді - інший. Запис `b := b + x` щоразу правильний в обох випадках, і це єдиний запис, який варто запамʼятати.

Саме подвоєння робить загальний обсяг роботи пропорційним до довжини, а не до її квадрата: копіювання стає рідшим настільки ж, наскільки дорожчим.

## Чому б просто не використовувати `+` для `STR`?

Поєднати фіксовану, невелику кількість частин за допомогою `+` цілком зрозуміло й нормально:

```sather
   return piece + " by " + composer;
```

Проблема виникає лише в циклі, де кількість поєднань невідома на момент написання коду. Приблизний орієнтир: якщо `+` стоїть усередині `loop`, використовуймо `FSTR`.

## Корисні процедури

| Виклик | Що робить |
| --- | --- |
| `b + x` | додає в кінець; `x` може бути `STR`, `CHAR`, `INT`, `BOOL` … |
| `b.size` | скільки символів уже накопичено |
| `b.str` | готовий `STR` |
| `b.clear` | спорожнює його, зберігаючи місце |

## Екрановані послідовності

| Запис | Означає |
| --- | --- |
| `"\n"` | новий рядок |
| `"\t"` | табуляція |
| `"\""` | подвійна лапка |
| `"\\"` | зворотний слеш |
