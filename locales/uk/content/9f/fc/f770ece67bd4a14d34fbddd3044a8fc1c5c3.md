# Про символи

Це потенційно _величезна_ тема!
Про неї можна написати цілу книжку, і чимало людей так і зробили (щоб побачити приклади, можна пошукати на Amazon «unicode book»).

## Дуже коротка історія

Обробляти символи в компʼютерах було набагато простіше в попередні десятиліття, коли програмісти вважали, що єдиною важливою мовою є англійська.
Отже: 26 літер у верхньому й нижньому регістрі, 10 цифр, кілька розділових знаків і ще код (0x07), щоб продзвонити в дзвіночок, і все це вміщалося в 7 бітів: набір символів [ASCII][wiki-ascii].

Звісно, люди почали питати, а як щодо à, ä та Ł, потім інші почали питати про ऄ, ஹ та ญ, а молодь захотіла емодзі 😱.
Що робити?

Якщо коротко, багато розумних і терплячих людей роками працювали в комітетах, зʼясовуючи деталі набору символів [Unicode][web-unicode] і таких кодувань, як [UTF-8][wiki-utf-8], а чимало програмного забезпечення потребувало _дуже_ складного переписування.
До того ж зʼявилося багато нових bug.

Щоб _усе_ не зламалося, дизайн Unicode/UTF-8 гарантує, що перші 127 кодів збігаються з ASCII _(навіть дзвіночок)_.

## Символи в Kotlin

Мови, створені приблизно після 2005 року, мають величезну перевагу: досить стабільний стандарт Unicode уже існував.

Kotlin (уперше випущена 2011 року) могла припускати, що користувачі будуть писати різними (людськими) мовами і будуть потребувати Unicode, щоб їх передавати.

~~~~exercism/advanced
[Символи][ref-char] у Kotlin є 16-бітними (UTF-16) [`codepoints`][wiki-codepoint], як і `char` у JVM.
Цього достатньо, щоб передати більшість писемних алфавітів, але не весь діапазон емодзі.

Повний стандарт Unicode використовує до шести байтів (48 бітів) на символ (це називається [`grapheme`][wiki-grapheme]).

Kotlin `Strings` підтримують цей повний стандарт, використовуючи кілька кодових точок на символ, коли це потрібно.
Наприклад, 😱 складається з `\uD83D` і `\uDE31`.

На жаль, у Java немає вбудованої підтримки графем, а задля сумісності її немає і в Kotlin.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


Символьні літерали записують в одинарних лапках, і це відрізняє їх від рядків тексту (англ. string) у подвійних лапках.
Для тих, хто прийшов зі світу C/C++, це, ймовірно, очевидно, але може заплутати програмістів Python і JavaScript.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

Перетворити `Char` на `Int` і навпаки зовсім не складно:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

Компілятор дозволяє _деякі_ форми арифметики над цілими числами для `Char`:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## Деякі функції для `Char`

Як завжди, тут надто [багато функцій][ref-char-lib], щоб обговорити їх усі, тож це лише добірка.

- Для відповідних алфавітів регістр змінюють за допомогою [`uppercase()`][ref-uppercase] та [`lowercase()`][ref-lowercase].
- Перевірити регістр можна за допомогою [`isUpperCase()`][ref-isuppercase] та [`isLowerCase()`][ref-islowercase].
- Перевірити тип символу можна так:
  - [`isLetter()`][ref-isletter] охоплює багато алфавітів (категорії Lu, Ll, Lt, Lm і Lo в Unicode)
  - [`isDigit()`][ref-isdigit] працює в діапазоні 0..9 (категорія Nd в Unicode)
  - `isLetterOrDigit()` поєднує два попередні
  - [`isWhitespace()`][ref-iswhitespace] позначає будь-який пробільний символ (категорії Cc, Zp, Zl і Zs в Unicode)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

Крім того, [регулярні вирази][ref-regex] (яким буде присвячено один із наступних концептів) дають змогу потужно шукати й обробляти текст.

## Взаємні перетворення масивів `Char` і рядків тексту

Щоб перетворити `String` на `List` з `Char`, можна скористатися `toList()`.

Щоб перетворити `List` з `Char` на `String`, є функція [`joinToString()`][ref-jointostring], яка приймає роздільник (часто порожній рядок тексту) як аргумент.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

Зауважмо, що `joinToString()` працює з масивом.
Щоб _привести_ один `Char` до рядка тексту з одного символу, скористаймося `toString()`.

```kotlin
'a'.toString() // => "a"
```

Щоб перевірити, чи є символ у `String` або в масиві `Char`, у нас є `in`, який відповідає функції [`contains()`][ref-contains].

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
