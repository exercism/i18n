# Про

Специфікатори класу зберігання стосуються того, як змінні зберігаються в памʼяті.
Вони тісно повʼязані з тривалістю зберігання (її також називають часом життя) значення.

## auto: типовий клас зберігання для змінних з областю видимості функції або блоку

Оскільки змінні, визначені всередині блоку чи функції, типово є `auto`, явно вживати цей термін доводиться нечасто.
Ще одна причина, чому `auto` часто уникають, полягає в тому, що в C++ він має інше значення.
У кодових базах, де поєднано C і C++, уникання специфікатора зберігання `auto` може зменшити плутанину.
Час життя змінної `auto` починається, коли ми входимо в її блок, і закінчується, коли ми з нього виходимо.
Коли ми входимо в блок, для змінної `auto` виділяється памʼять, _але без типового значення_.
Виняток становлять масиви змінної довжини (VLA).
Памʼять для VLA виділяється там, де його оголошено чи визначено в блоці, і це виділення закінчується, коли ми виходимо з блоку.
Змінну `auto` можна ініціалізувати будь-яким коректним виразом.

## static: специфікатор зберігання, який не варто плутати з різновидом звʼязування static

Змінна, визначена поза блоком чи функцією, має область видимості файлу й завжди має статичну тривалість зберігання.
Область видимості файлу означає, що до неї можна звертатися будь-де у файлі.
Статичне зберігання означає, що вона існує від початку виконання програми до його кінця.
Якщо змінну явно не ініціалізовано, `static`-змінна ініціалізується своїм типовим нульовим значенням.
Якщо змінну з областю видимості файлу позначено `static`, то `static` стосується її звʼязування.
Змінна з областю видимості файлу, позначена `static`, має внутрішнє звʼязування, тобто до неї можна звертатися лише в межах файлу.
Якщо змінну визначено всередині функції або в блоці всередині функції й позначено `static`, вона має тривалість зберігання `static`.
Значення `static`-змінної зберігається між викликами функції або блоку.

У наступному прикладі ми бачимо в дії дві `static`-змінні.
Першу змінну `count` визначено всередині функції `print_stuff`, і вона зберігає своє значення між викликами функції.
Другу змінну `count` визначено в довільному блоці, і в межах свого блоку вона приховує (затіняє) першу змінну `count`.
Друга змінна `count` незалежно зберігає своє значення між входами в блок.

```c
#include <stdio.h>

void print_stuff(void) {
    // static variable is initialized to 0
    static int count;
    count++;
    printf("function count is %d\n", count);
    {
        // static variable is initialized to 0
        static int count;
        count++;
        printf("block count is %d\n", count);
    }
}

int main() {
    // prints
    // function count is 1
    // block count is 1
    print_stuff();
    // prints
    // function count is 2
    // block count is 2    
    print_stuff();
}
```

Якщо `static`-змінну ініціалізовано явно, робити це потрібно константним виразом.
Константний вираз - це вираз, який можна обчислити під час компіляції.

## extern: як отримати доступ до змінної в іншій одиниці трансляції

Одиниця трансляції складається з вихідного файлу та будь-яких інших файлів, які він включає через `#include`.
Хоча змінну з областю видимості файлу можна оголосити й ініціалізувати як `extern`, ключове слово `extern` зазвичай уживають, щоб послатися на наявну змінну, а не щоб визначити нову.
Змінна, на яку посилається `extern`, повинна мати область видимості файлу.
Змінна з областю видимості файлу завжди має зберігання `static`.
Змінна у включеному файлі повинна мати зовнішнє звʼязування, щоб файл, який її включає, міг до неї звертатися.

У наступному прикладі ми використовуємо змінну `val`, оголошену як `extern`, щоб вона посилалася на `val`, визначену в своїй області видимості файлу.
Обидва вживання `extern` називають посилальними оголошеннями, оскільки вони посилаються на змінну, визначену в іншому місці.

```c
#include <stdio.h>

void set_val() {
    // this declares val which is defined elsewhere
    extern int val;
    val += 42;
    // prints val is 42
    printf("val is %d\n", val);
}

int main() {
    set_val();
    // this declares val which is defined elsewhere
    extern int val;
    val += 42;
    // prints val is 84
    printf("val is %d\n", val);
}
// this value could be defined in another source file.
// as a variable with static storage, it is initialized to zero
int val;
```

Якби обидва ключові слова `extern` прибрати, програма могла б надрукувати щось таке

```
val is 22038
val is 42
```

Такий вивід показує, що кожне оголошення `val` без `extern` є визначальним оголошенням і не залежить від інших оголошень `val`.
Якщо взагалі прибрати оголошення `val` з `set_val` і `main`, компіляція завершиться помилкою, що `val` не оголошено в `set_val` і `main`.

Якщо змінна, на яку посилаються як на `extern`, перебуває в тому самому файлі, вона може мати внутрішнє або зовнішнє звʼязування.
Визначення `val` як `static int val;` не вплинуло б на використання `val` у `set_val` чи `main`, хіба що визначення довелося б перенести вище за них, щоб код скомпілювався.
Але якби `val` було визначено вище за функції, їм не потрібно було б оголошувати `val` як `extern`.

Наступний варіант працював би

```c
#include <stdio.h>

// val defining declaration before the function definitions
static int val;

void set_val() {
    val += 42;
    // prints val is 42
    printf("val is %d\n", val);
}

int main() {
    set_val();
    val += 42;
    // prints val is 84
    printf("val is %d\n", val);
}
```

`static` можна було б прибрати з `static int val;`, і тоді `val` мала б зовнішнє звʼязування, а в `set_val` і `main` усе одно працювала б так само.
Якби інший вихідний файл включив цей файл, він міг би використовувати `val`, лише якби `val` мала зовнішнє звʼязування (не була оголошена як `static`) і той інший файл оголосив `extern int val;`.

Змінна, на яку посилаються через `extern`, повинна не лише мати зберігання `static`, а й мати область видимості файлу.
Наступний приклад, найімовірніше, не скомпілюється, бо `val`, хоч і `static`, не має області видимості файлу.

```c
#include <stdio.h>

void set_val() {
    // defined with static storage, but not in file scope
    static int val;
    val += 42;
    printf("val is %d\n", val);
}

int main() {
    set_val();
    extern int val;
    printf("val is %d\n", val);
}
```

## register: як, можливо, пришвидшити доступ до змінної

Змінна, позначена як `register`, виражає бажання програміста, щоб значення розмістили в регістрі для швидкого доступу.
Змінна `register` схожа на змінну `auto` тим, що вона має бути в області видимості функції або блоку.
Оскільки значення призначене для розміщення в регістрі, а не в памʼяті, компілятор має заборонити звертання до адреси змінної, бо адресу регістра взяти не можна.
Утім, саму адресу памʼяті можна розмістити в регістрі.
Наступний приклад це демонструє

```c
#include <stdio.h>

int main() {
    int i = 42;
    register int *i_ptr = &i;
    // prints i is 42, i_ptr is 0x7ffd0c2055c4 (or some other address)
    printf("i is %d, i_ptr is %p", i, i_ptr);
}
```

`register` - це по суті підказка, адже компілятори вільні вибирати, чи дотримуватися цього специфікатора, тож значення може бути, а може й не бути насправді розміщене в регістрі.

## typedef: специфікатор класу зберігання, який насправді ним не є

`typedef` описують як специфікатор класу зберігання лише з синтаксичних причин.
Річ у тім, що специфікатор класу зберігання не можна використовувати разом з іншим специфікатором класу зберігання.
Тож `typedef auto int i = 42;` так само неприпустимий, як і `static auto int i = 42;`.
