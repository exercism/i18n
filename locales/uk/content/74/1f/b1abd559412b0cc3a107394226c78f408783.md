# Докладніше

Парсинг - це процес перетворення тексту на осмислені дані.
Функції з пакета `String` тут обмежені, а регулярні вирази складні у використанні, тому ідіоматичний спосіб парсингу в Elm - використовувати пакет `elm/parser`.

Пройдімося прикладом написання парсера для (підмножини) мови програмування [LOLCODE][lolcode].
Розглянемо таку програму з коментарями:

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

Спочатку напишемо тип Elm, який описуватиме можливі команди:

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

Тоді нашу програму на LOLCODE можна подати як `List Command`.
Почнімо з парсера для рядка `HAI 1`:

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP` побудовано за допомогою _конвеєра парсерів_.
Оператор `(|.)` означає «розібрати рядок тексту (англ. string), але відкинути результат», а `(|=)` означає «розібрати рядок тексту і зберегти результат».
У цьому прикладі `Parser.keyword "HAI"` споживе «HAI», але цей результат буде проігноровано.
`Parser.spaces` споживе будь-яку кількість символів ' ', '\n' і '\r', але його результат теж буде проігноровано.
`Parser.int` розбере ціле число, і його значення (скажімо, 1) буде передано до `Parser.succeed Version` на початку конвеєра, після чого парсер успішно поверне значення `Version 1`.

Якщо хоч один парсер у конвеєрі зазнає невдачі, він поверне `Parser.DeadEnd`, і весь парсер теж зазнає невдачі.
Парсер можна запустити за допомогою `Parser.run`:

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

Розберімо рядок «CAN HAS STDIO?» за допомогою

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP` теж є конвеєром парсерів, але цього разу він завершується `Parser.symbol`, який підходить для розбору таких символів, як «?».
Значення, яке ми хочемо зберегти (назву пакета для імпорту), розбирає

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

Оскільки ми не знаємо, якою буде назва пакета, ми не можемо скористатися `Parser.keyword`, тому натомість використовуємо `Parser.chompWhile`, який споживатиме окремі символи, доки вони задовольняють умову (тут це буквено-цифровий символ).
Ці спожиті символи потім збирає `Parser.getChompedString`, який повертає `Parser String`.
У цьому випадку ми хочемо нормалізувати назви пакетів, тому використовуємо `Parser.map`, щоб змінити рядок тексту всередині парсера й зробити його в нижньому регістрі.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

Далі `VISIBLE "HAI WORLD!"` розбирає

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

Тепер у нас є парсер для кожної команди.
Звісно, у загальній програмі порядок цих команд передбачити неможливо, тому ми будуємо загальний парсер команд

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf` пробує парсери по черзі, у заданому порядку.
Якщо парсер зазнає невдачі, пробують наступний, а якщо він досягає успіху, його результат повертається без спроби решти парсерів.
Якщо ж зазнають невдачі всі парсери, `Parser.oneOf` теж зазнає невдачі.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

Звернімо увагу, як кожна невдала спроба породжує `Parser.DeadEnd`, який збирає `Parser.oneOf`.

Щоб розібрати повну програму, нам треба послідовно розібрати кілька команд за допомогою

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence` - це дуже гнучкий у налаштуванні парсер із низкою опцій.
`start`, `separator` і `end` приймають рядки тексту, які розділяють елементи послідовності; для розбору списку Elm ми б використали "[", "," і "]".
`spaces` додає гнучкості: він приймає парсер, який оброблятиме можливі пробіли між елементами та роздільниками; для розбору списку Elm ми б використали `Parser.spaces`, але в цьому випадку ми не допускаємо жодних пробілів, тому використовуємо `Parser.succeed ()`, який досягає успіху одразу, фактично нічого не споживаючи.
`item` приймає парсер елемента, а `trailing` насамкінець дає змогу вирішити, чи будуть кінцеві роздільники `Parser.Forbidden`, `Parser.Mandatory` або `Parser.Optional`.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

Коли парсери досягають успіху, вони припиняють споживати рядок тексту

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

Тож якщо нам треба переконатися, що ми розібрали весь рядок тексту, можна скористатися `Parser.end`

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

Нарешті, іноді нам треба вирішити, чи провалити парсер, залежно від того, що він розібрав.
Наприклад, якби нам був потрібен парсер, який провалював би програми, що починаються з двох команд «HAI» підряд, ми могли б використати

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen` може переглянути вміст парсера й повертає новий парсер залежно від його значення.
Тут в одному випадку ми провалили парсер із власним повідомленням за допомогою `Parser.problem`, а в іншому повернули початкове значення.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
