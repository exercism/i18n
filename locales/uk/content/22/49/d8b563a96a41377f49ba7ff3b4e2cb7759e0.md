# Інструкції

Helma, наша подруга, створила невелику онлайн-гру, яка швидко набула популярності.
Вона називається _HellMath_.
Невелика спільнота привабила кількох тролів, які роблять гру й форуми досить неприємними.
Helma попросила нас попрацювати над новою системою дозволів, щоб відокремити тих, хто створює проблеми.

Форум підтримує три різні дії:

- Читання
- Написання
- Видалення

Є чотири типи акаунтів, кожен зі своїми типовими дозволами:

- Гості: можуть читати дописи.
- Користувачі та тролі: можуть читати і писати дописи.
- Модератори: можуть читати, писати і видаляти дописи, вони мають усі дозволи.

Helma помітила, що блокувати акаунти тролів не має сенсу.
Її стратегія - створити в них ілюзію, ніби час витрачено «з користю», але їхні дописи показують лише іншим тролям.
У будь-чому, що потребує впорядкування за пріоритетом, тролі стоять останніми в будь-якій послідовності.
Коли вони заходять у гру, коло доступних гравців також обмежується іншими тролями.

Таку практику називають [тіньовим баном][shadow-ban].

## 1. Налаштуйте типи користувачів і дозволи.

Спершу визначте перелік `AccountStatus`, який представляє чотири типи акаунтів: `troll`, `guest`, `user` і `mod`.

Далі визначте перелік `Action`, який представляє три типи дозволів: `read`, `write` і `remove`.


## 2. Показуйте тролів лише іншим тролям.

Кожен допис на форумах зберігає `AccountStatus` автора у своїх метаданих.
Переконайтеся, що дописи тролів показуються лише іншим тролям.

Helma потрібна функція `display_post`, яка приймає два аргументи типу `AccountStatus` і повертає `bool`.
Перший аргумент - статус автора допису, а другий - статус того, хто його переглядає.

```cpp
using namespace hellmath;
display_post(AccountStatus::troll, AccountStatus::user);
// => false
display_post(AccountStatus::mod, AccountStatus::guest);
// => true
```

## 3. Перевіряйте дозволи для різних користувачів.

Helma потрібен спосіб перевірити, чи дозволена певна дія для користувача.

Реалізуйте функцію `permission_check`, яка приймає `Action` як перший аргумент і `AccountStatus` для перевірки.
Вона має повертати `bool` відповідно до дозволів, перелічених у вступі.

```cpp
permission_check(Action::remove, AccountStatus::guest);
// => false
permission_check(Action::write, AccountStatus::mod);
// => true
```

## 4. Надавайте доступ до гри та обʼєднуйте гравців у пари.

Щоб справжні гравці в грі відповідали за свої дії, _Hellmath_ не дає доступу гостьовим користувачам.
Як уже зазначалося, Helma хоче, щоб тролі тролили інших тролів.
Ігрові звʼязки між іншими користувачами не обмежуються.

Реалізуйте функцію `valid_player_combination`, яка перевіряє, чи можуть двоє гравців приєднатися до однієї гри.
Функція має два параметри типу `AccountStatus` і повертає `bool`.

```cpp
valid_player_combination(AccountStatus::guest, AccountStatus::mod);
// => false
valid_player_combination(AccountStatus::troll, AccountStatus::troll);
// => true
```

## 5. Побудуйте чергу з пріоритетами.

Через стрімке зростання гри й форумів Helma тепер має розподіляти обчислювальну потужність і пропускну здатність між користувачами.
Щоб реагувати на непередбачувані ситуації, модератори отримують найвищий пріоритет.
Гості стоять у черзі після звичайних користувачів, а тролі - після всіх інших.

Реалізуйте функцію `has_priority`, яка приймає два аргументи типу `AccountStatus` і повертає `true` тоді й лише тоді, коли перший акаунт має строго вищий пріоритет за другий.

```cpp
has_priority(AccountStatus::guest, AccountStatus::mod);
// => false
has_priority(AccountStatus::user, AccountStatus::troll);
// => true
```
