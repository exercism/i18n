# Вступ

[Зіставлення зі зразком][pattern-matching] дає змогу писати виразний код із розгалуженнями, а [деструктуризація][destructuring] елегантно звʼязує значення зі змінними.
І те, й інше вкрай корисно опанувати програмісту на Elm, а в поєднанні вони суттєво покращують читабельність коду.

## Просте зіставлення зі зразком

Зіставлення зі зразком означає розгалуження коду залежно від форми даних, з якими ми працюємо.
Тому воно природно поєднується з поняттям власних типів, які описують різні форми, яких можуть набувати дані.
Наприклад, якщо власний тип `Color` визначено як `Blue` або `Red`, ми можемо написати функцію `toString`, яка зіставляє колір зі зразком і повертає правильний рядок тексту (англ. string).

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

Зіставлення зі зразком працює і для власних типів, які не є простим переліком.
Розгляньмо функцію `hello`, яка як параметр приймає `Maybe String`, що містить або імʼя людини, або взагалі нічого.
Під час зіставлення зі зразком ми можемо дати даним назву з маленьких літер, щоб звʼязати ці дані зі змінною й використати її в правій частині зіставлення.

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

Зіставлення зі зразком має бути вичерпним, інакше компілятор відмовиться компілювати код.
Але іноді нам байдужі якісь дані чи якісь гілки виразу `case`.
У таких випадках замість того, щоб добирати назву змінної для звʼязування й писати гілку для кожного випадку, ми можемо скористатися символом підстановки `_`.

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## Розширене зіставлення зі зразком

Крім власних типів, ми можемо зіставляти зі зразком і типи, які мають літерали, як-от `Char`, `String`, `Int` та `Floats`.

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

Щоб зіставити більш ніж одне значення без вкладеності, в Elm часто вдаються до такого прийому: обʼєднати значення для зіставлення в [_кортежі ad hoc_][ad-hoc-tuples].

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

А оскільки функційні програмісти дуже люблять масиви, [їх теж можна зіставляти зі зразками][pattern-match-lists], використовуючи той самий синтаксис, що й для їх побудови, та оператор `::`.

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

І нарешті, зіставлення зі зразком працює навіть рекурсивно, що дає змогу занурюватися в складні й рекурсивні типи.

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## Деструктуризація

Деструктуризація дуже схожа на зіставлення зі зразком: вона так само дає змогу звʼязувати змінні з даними всередині типів.
Головна відмінність полягає в тому, що коли можлива лише одна форма, ми називаємо цей механізм «деструктуризацією», а коли форм кілька - зіставленням зі зразком.
Деструктуризацію часто можна побачити у звʼязуваннях `let`, в аргументах функцій і, звісно, у виразах `case`, у поєднанні зі зіставленням зі зразком.

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

Деструктуризацію можна застосовувати до власних типів з єдиним варіантом, до кортежів, а також до записів, де вона особливо зручна.
Щоб [деструктурувати запис][records-pattern-matching], можна взяти будь-яку кількість його полів: одне, два, ..., або всі поля.

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

На жаль, синтаксис Elm не дозволяє рекурсивно деструктурувати записи.
У попередньому прикладі з `Circle` немає способу за один раз дістатися до позицій `x`` and `y центру кола.
Спершу треба дістатися до `center`, а вже потім деструктурувати його, щоб дістати його `x` та `y` координати.

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

І наостанок ще одна порада!
Іноді нам потрібен зручний доступ і до чогось як до цілого, і до його частини.
Тут може стати в пригоді ключове слово [`as`][as-keyword].
Воно дає змогу дати псевдонім чомусь як цілому й при цьому деструктурувати його вміст.

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
