# Докладніше

Файл - це потік з імʼям на диску. Набір слів [`io.files`][io.files] пропонує два способи роботи з ним: зручні слова для роботи з файлом як з єдиним цілим, які читають або записують усе за один виклик, і засоби відкриття потоків (`with-…`-комбінатори) для читання й запису частинами. Обидва спираються на той самий [протокол потоків][stream-protocol], що й потоки в памʼяті з концепції `io-streams`: `<file-reader>` і `<string-reader>` реагують на ті самі слова.

Кожне файлове слово приймає **кодування**, схему, яка зіставляє байти із символами й навпаки. Для тексту це майже завжди [`utf8`][utf8] з `io.encodings.utf8`; для роботи з двійковими даними використовують `latin1` або кодування `<byte-array>`.

## Читання всього файлу

```
file-contents   ( path encoding -- str )
file-lines      ( path encoding -- seq )
```

`file-contents` повертає весь файл як один рядок тексту (англ. string). `file-lines` повертає його рядки як масив, прибравши символи кінця рядка, що зручно, коли кожен рядок є окремим записом.

```factor
USING: io.encodings.utf8 io.files ;

"forecast.txt" utf8 file-contents   ! => "sunny\ncloudy\n"
"forecast.txt" utf8 file-lines      ! => { "sunny" "cloudy" }
```

## Запис усього файлу

```
set-file-contents   ( str path encoding -- )
set-file-lines      ( seq path encoding -- )
```

Обидва **замінюють** файл, створюючи його, якщо він не існує.
`set-file-contents` записує рядок тексту дослівно; `set-file-lines` записує кожен
елемент послідовності в окремому рядку, додаючи символи нового рядка.

```factor
{ "sunny" "cloudy" } "forecast.txt" utf8 set-file-lines
! forecast.txt now holds "sunny\ncloudy\n"
```

## Потоки з областю видимості

Коли треба дописати щось у файл або читати й писати частинами, відкриймо його
`with-…`-комбінатором і скористаймося словами для поточного потоку всередині блоку коду:

```
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
with-file-appender   ( path encoding quot -- )
```

```factor
USING: io io.encodings.utf8 io.files ;

"log.txt" utf8 [ "another line" print ] with-file-appender
```

`with-file-writer` спершу обрізає файл; `with-file-appender` зберігає наявний
вміст і дописує після нього. Кожен із них - це деструкторна область: дескриптор
файлу закривається, коли блок коду завершується, навіть якщо той викидає виняток.
Таку саму гарантію дають комбінатори `boatswains-bilge`, тільки тут вона
стосується файлів.

## Увесь файл чи область?

Коли файл достатньо малий, щоб уміститися в памʼяті, і потрібен одразу весь його
вміст, звертаймося до `file-contents` / `file-lines` / `set-file-contents` /
`set-file-lines`. До засобів відкриття `with-…` звертаймося тоді, коли треба
дописати в кінець, читати великий файл рядок за рядком за допомогою `readln` або
чергувати читання й запис, тобто скрізь, де тримати весь файл у памʼяті було б
марнотратно чи неправильно.
