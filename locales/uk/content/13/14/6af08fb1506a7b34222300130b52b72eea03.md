# Інструкції

Чим більше ми дізнаємося про програмування, тим частіше починаємо думати, що це може бути більше, ніж просто миттєва мода.
Можливо, тут навіть є ділові можливості: люди пишуть код, хочуть його зберегти, поділитися, працювати разом, а може, й отримати відгук.

Гаразд, нумо до справи, створімо сервіс, який спонукає людей програмувати: ну ж бо, ну ж бо, народе, починаймо користуватися git!
Назвімо його... GitHup.

Ми беремося створювати REST JSON API: користувачі, pull request-и, коментарі, і backend швидко готовий.
Ось приклад даних, які сервер віддає, коли ми запитуємо в нього список коментарів до pull request:

```json
[
  {
    "id": 256,
    "pull_request_review_id": 42,
    "user": {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    },
    "body": "Great stuff!",
    "side": "RIGHT",
    "_links": {
      "self": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
      },
      "html": {
        "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1"
      },
      "pull_request": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1"
      }
    }
  },
  {
    "id": 11,
    "pull_request_review_id": null,
    "user": {
      "id": 2,
      "login": "hexacat",
      "name": "Alex Kate",
      "avatar_url": "https://githup.com/images/error/hexacat_happy.gif",
      "site_admin": true
    },
    "body": "Amazing stuff!",
    "side": "LEFT",
    "_links": {
      "self": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
      }
    }
  }
]
```

Звісно, frontend буде зроблено на Elm, але спершу треба розібратися, що це за сумнозвісні декодери й енкодери.

```exercism/note
Жартівлива історія осторонь, вимоги цієї вправи взято безпосередньо з ендпоінтів REST API GitHub для коментарів до рецензій pull request.
Частину полів прибрали зі схем JSON заради простоти, але ближче до реальних застосунків уже годі й уявити.
```

## 1. ID, будь ласка!

Наш пильний погляд помітив, що і коментарі, і користувачі мають поле `id`, ідеальне місце, щоб почати.

Визначмо `decodeId` так, щоб він декодував обʼєкт JSON із цілим числом у полі `id`.

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. То як мене звати?

Ми помічаємо в прикладі вище, що не всі користувачі мають імʼя.

Визначмо `decodeName` так, щоб він декодував рядок тексту (англ. string) у полі `name`, якщо він там є.
Немає імені? Не проблема, просто повертаємо `Nothing`.
Цей декодер ніколи не повинен зазнавати невдачі.

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. Користувач? Я його ледве знаю!

Ми вже майже на півдорозі до декодування користувачів, тож доведімо справу до кінця.

Визначмо `decodeUser` так, щоб він декодував обʼєкт користувача у JSON.
Обовʼязково використаймо `decodeId` і `decodeName` у `decodeUser`.

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. Я сильний незалежний коментар

Деякі коментарі в рецензії pull request є окремими, і тому не мають `pull_request_review_id`.
Однак специфікація згадує, що в такому разі поле `pull_request_review_id` все одно має бути, але його значенням має бути `null`, тобто `Nothing` для бідних.

Визначмо `decodePullRequestReviewId` так, щоб він декодував ціле число в полі `pull_request_review_id`, якщо воно там є.
Якщо цілого числа немає, має бути `null`; якщо немає `null`, декодер має зазнати невдачі.

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. Підробіток

Далі це цікаве поле `side`.
У рецензії pull request ми можемо коментувати код, який видалили (з боку `Left` на екрані), або код, який додали (з боку `Right` на екрані).

Визначмо `decodeSide` так, щоб він декодував або `"LEFT"`, або `"RIGHT"` у полі `side` і зіставляв їх із відповідним варіантом типу.

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. Пробудження посилань

Кожен коментар має набір посилань, який, схоже, не є однаковим для всіх коментарів.

Визначмо `decodeLinks` так, щоб він декодував набір URL у полі `_links`.
Назви й кількість посилань можуть змінюватися, тож переконаймося, що ми це враховуємо.
Самі посилання є обʼєктами JSON, які завжди мають поле `href`.

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. Так, коментарі

Майже готово, доведімо справу до кінця.

Визначмо `decodeComment` і `decodeComments` так, щоб вони декодували відповідно один обʼєкт коментаря JSON або список коментарів.
Обовʼязково використаймо в `decodeComment` усі функції, визначені досі, крім `decodeName`.
Звісно, `decodeComments` теж має використовувати `decodeComment`.

## 8. Усе зводиться докупи

У всьому цьому бракує ще однієї можливості: надсилати новий коментар на сервер.
Для цього потрібне протилежне до декодера: вміння перетворювати `Comment` з Elm на `Value` у JSON.

Визначмо `encodeComment` так, щоб він кодував будь-який коректний `Comment`.
Порядок полів не має значення, аби лише енкодер виробляв значення, яке `decodeComment` може декодувати.
