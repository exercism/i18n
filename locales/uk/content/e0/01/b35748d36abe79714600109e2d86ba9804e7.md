# Докладніше

Тип `Result` дає функції змогу повернути одне значення, яке вказує на все таке:
- Чи завершилася операція успіхом чи невдачею
- У разі успіху: результуюче значення операції
- У разі невдачі: причина невдачі

У мовах програмування, які не підтримують чогось подібного до типу `Result`, для досягнення згаданих цілей часто застосовують такі підходи:
- Функція повертає числовий код, який вказує на успіх або на причину невдачі, і вимагає вихідного параметра, щоб прийняти значення в разі успіху.
- Функція повертає значення в разі успіху або NULL у разі помилки, а потім окрема функція повертає код помилки, який вказує на причину невдачі.

Ще один поширений механізм обробки помилок - виняток, який різко перериває виконання поточної функції та
передає керування першому обробнику в стеку викликів, коли стається збій.  
Якщо жоден обробник не «зловить» виняток, програма аварійно завершується.

## Переваги типу `Result`

* __Безпека під час компіляції__: Якщо успіх чи невдача виклику функції явно виражені в системі типів, компілятор може гарантувати, що код, який викликає функцію, обробить усі випадки невдачі, а це запобігає цілій категорії помилок, які могли б виникнути через значення null.

* __Безпека під час виконання__: Замість `null` тип `Result` використовує `Error`, щоб позначити невдачу, тому `NullReferenceException` статися не може.

* __Явна обробка помилок__: Код, який викликає функцію, що повертає `Result`, має визнати, що
виклик може зазнати невдачі; такий код повинен обробляти ці невдачі свідомо.  Немає жодних мовчазних збоїв і несподіваних винятків.

* __Передбачуваний потік керування__: `Result` повертають так само, як і будь-яке інше значення; він не вистрибує зі стеку викликів, як виняток.  Ми завжди знаємо, звідки беруться помилки і як вони поширюються.

* __Краща читабельність і зручність супроводу__: Повертаючи `Result`, сигнатура функції чітко показує очікувану поведінку в разі успіху та невдачі.

## Використання

Тип `Result` - узагальнений тип, який містить два внутрішні типи:
- Тип результуючого значення у разі успішної операції
- Тип, що представляє причину невдачі в разі невдачі

Тип `Result` також є [розпізнаваним обʼєднанням][discriminated-union] з такими можливими випадками:
* `Ok <value>` представляє успішний результат
* `Error <reason>` представляє невдачу

Наступна функція демонструє, як створити значення `Result`:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

У цьому прикладі значення `Ok` - це рядок тексту (англ. string), тобто передане імʼя, а значення `Error` - теж рядок тексту, тобто причина помилки у зрозумілому для людини вигляді.

## Читання вмісту значення `Result`

Розгляньмо таке визначення типу та сигнатуру функції:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

Код, який викликає функцію `openFile`, може використовувати зіставлення зі зразком, щоб обробити випадки успіху й невдачі, як у наступному прикладі:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
