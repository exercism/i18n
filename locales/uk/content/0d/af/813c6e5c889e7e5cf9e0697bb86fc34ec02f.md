# Винятки

Не кожна підпрограма може дати відповідь. Коли в неї просять реквізит, якого немає на столі, `count_of` не має числа, яке могла б повернути, а нуль був би брехнею, бо нуль означає «у нас немає жодного з них», а не «такого взагалі не існує».

**Виняток** це те, як підпрограма каже, що не може дати відповідь.

## Кидання винятку

`raise` покидає підпрограму й передає значення тому, хто її викликав.

```sather
   count_of(props : FMAP{STR,INT}, prop : STR) : INT is
      if ~props.has_ind(prop) then
         raise "Unknown prop: " + prop;
      end;
      return props.get(prop);
   end;
```

Нічого після `raise` не виконується. Підпрограма не повертає значення, тож немає відповіді, яку можна перевірити, і той, хто її викликав, ніяк не може поводитися так, ніби вона є.

Кинуте значення зазвичай є рядком тексту (англ. string), який каже, що пішло не так.

## Перехоплення винятку

`protect` виконує фрагмент коду й готовий до того, що той кине виняток.

```sather
   protect
      taken ::= count_of(props, prop);
      #OUT + "There are " + taken;
   when $STR then
      #OUT + "Cannot: " + exception.str;
   end;
```

Якщо ніщо не кидає виняток, виконується частина після `protect`, а гілку `when` пропускають. Якщо щось кидає виняток, решту частини `protect` скасовують, і натомість виконується відповідна гілка `when`.

`when $STR then` перехоплює кинутий рядок тексту. `exception` - це те значення, яке кинули; воно доступне всередині гілки.

## Прямування назовні

Підпрограма, яка не перехоплює виняток, не мусить щось із ним робити. Він прямує назовні, крізь усіх, хто викликав, аж поки щось його не перехопить:

```sather
   take_one(props : FMAP{STR,INT}, prop : STR) : INT is
      -- If this raises, take_one raises too. Nothing here says so.
      have ::= count_of(props, prop);
      ...
   end;
```

У цьому й полягає сенс винятків. Підпрограма, яка помічає проблему, і підпрограма, яка знає, що з нею робити, зазвичай не одна й та сама, а все, що між ними, може виняток ігнорувати.
