# Докладніше

Ця вправа показує поведінку різних числових типів під час переповнення, тобто коли їхньої місткості не вистачає, щоб умістити значення, яке є результатом обчислення, наприклад арифметичної операції або приведення типу.

- беззнакові [цілі числа][integral-numeric-types] (`byte`, `ushort`, `uint`, `ulong`) загортаються до нуля (максимальне значення типу + 1 діє як модуль), якщо, [грубо кажучи][checked-compiler-setting], вони не перебувають усередині блоку [`checked`][checked-and-unchecked], у якому випадку буде викинуто примірник `OverflowException`. `int` і `long` поводяться подібно, але загортаються до `int.MinValue` та `long.minValue` відповідно.

```csharp
int one = 1;
checked
{
    int expr = int.MaxValue + one;  // overflow exception is thrown
}

// or

int expr2 = checked(int.MaxValue + one);  // overflow exception is thrown
```

- Якщо літеральний вираз спричинить переповнення змінної, якій він присвоюється, тоді виникає помилка часу компіляції.
- стан `checked` застосовується лише до виразів безпосередньо в блоці. Переповнення у викликаних функціях не перехоплюються.
- типи [`float` і `double`][floating-point-numeric-types] набувають стану _нескінченності_, який можна перевірити за допомогою `float.IsInfinity()` тощо.

```csharp
double d = double.MaxValue;
d *= 2d;
Double.IsFinite(d)
// => false
```

- числа типу [`decimal`][floating-point-numeric-types] спричинять викидання примірника `OverflowException`.
- Існує відповідне ключове слово `unchecked` для випадків, коли потрібно скасувати дію `unchecked` усередині блоку `checked` або коли було використано налаштування компілятора.

Переповнення, які відбуваються без викидання винятку, можуть бути проблемними, бо зазвичай чим раніше вдається повідомити про помилкову ситуацію, тим краще.

Проблеми з переповненням для `int` і `float` можна помʼякшити, присвоївши результат змінній типу `long`, `decimal` або `double`.

Якщо великі цілі числа важливі для нашого коду, тоді можна скористатися типом [`BigInteger`][big-integer].

Звичайно, бувають випадки, коли цілком припустимо дозволити цілому числу загорнутися, особливо коли йдеться про беззнакові значення. Класичний приклад - геш-коди, які використовують розрядність числа як своєрідний модуль.

У кодових базах зазвичай можна помітити, що часто немає жодної перевірки там, де `uint` або `ulong` використовується як ідентифікатор, бо це вважають справою, яка не варта зусиль. Це стосується й випадків, коли із предметної області очевидно, що дуже великих значень не буде. Але погляньмо на [це][computerphile-gangnam-style] як на повчальну історію.
