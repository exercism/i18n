# Nil

У Crystal є тип під назвою [`Nil`][nil], який може мати лише одне значення: `nil`.
Він позначає відсутність значення і подібний до `null` або `None` в інших мовах.

Значення `nil` можуть повертати різні методи, наприклад [`String#[]?`][string-index], який повертає `nil`, якщо індекс виходить за межі.

```crystal
"foo"[10]? # => nil
```

У Crystal є те, що називають **ПЕРЕВІРКАМИ НУЛЬОВИХ ПОСИЛАНЬ**: усі типи за замовчуванням не можуть бути `nil`.
Це означає, що ми не можемо присвоїти `nil` змінній, якщо явно не оголосимо її типом `Nil`.
Своєю чергою, це означає, що компілятор буде автоматично перевіряти нульові посилання.

## Хибне значення

Для роботи зі значеннями `nil` можна застосовувати різні підходи.
`nil` вважається [хибним значенням][truthy-falsey], так само як і `false`.
Це означає, що в інструкціях та інших місцях, де очікується хибне чи істинне значення, воно сприйматиметься так само, як `false`.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Це означає, що гілку з істинним значенням не буде виконано, якщо змінна, яка може бути `nil`, має значення `nil`.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Перевірка на nil

У Crystal є метод, який дає змогу перевірити, чи значення дорівнює `nil`.
Він називається [`nil?`][nil?] і доступний для всіх обʼєктів.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Усе трохи інакше, коли ми просто використовуємо значення в умовній конструкції, адже в попередніх прикладах і `false`, і `nil` вважалися б хибними.
Тут хибним вважається лише `nil`, адже якби значення було `false`, воно не було б `nil`, а отже, було б істинним.

## Оператор або

Найпростіший спосіб мати справу зі значеннями `nil` - подбати, щоб вони взагалі ніколи не ставали `nil`.
Оператор або ([`||`][or]) часто використовують, маючи справу з `Bools`, але якщо добре його зрозуміти, його можна застосовувати і для роботи зі значеннями `nil`.
Оператор або перевіряє, чи перше значення істинне; якщо ні, використовується друге значення.
Завдяки цьому, якщо значення дорівнює `nil`, воно буде хибним, а отже, використається друге значення.

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
До цього підходу варто вдаватися як до останнього засобу і застосовувати його лише тоді, коли ми **впевнені**, що значення не `nil`.
Якщо можливо, краще скористатися іншими підходами.
~~~~

[`not_nil!`][not_nil] дає змогу повідомити компілятору, що значення не є `nil`, і завдяки цьому тип, який воно містить, не може бути `nil`.
Він робить це, викидаючи виняток, якщо значення дорівнює `nil`.

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
