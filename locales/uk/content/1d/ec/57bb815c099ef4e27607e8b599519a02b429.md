# Комбінування ітераторів

Цикл може викликати більше ніж один ітератор. На кожній ітерації в кожного
з них запитують його наступне значення, і вони рухаються вперед разом.

```sather
   loop
      first ::= violin_one.elt!;
      second ::= violin_two.elt!;
      #OUT + first + " against " + second + "\n";
   end;
```

Це проходить обома масивами пліч-о-пліч: перший елемент із першим елементом,
другий із другим.

## Правило, яке всіх дивує

**Цикл завершується щойно, як вичерпається *перший* з його ітераторів.**

Не тоді, коли вичерпається останній. Не тоді, коли вичерпаються всі. А перший.

Тож якщо в `violin_one` чотири такти, а в `violin_two` два, цикл вище
виконається **двічі**. Третій і четвертий такти першої партії взагалі не буде
розглянуто, бо на той момент у другій партії вже нічого не залишиться.

Зазвичай це саме те, що потрібно: поєднувати речі в пари має сенс лише тоді,
коли пари є, але про це треба знати, а не виявляти на власному досвіді.

## Лічба разом

Ітератор, який ніколи не вичерпується, корисний саме через це правило.
`up!` лічить вічно:

```sather
1.up!        -- 1, 2, 3, 4, ... and never ends
```

Сам по собі він зациклився б назавжди. У парі з тим, що вичерпується, він
нумерує значення, анітрохи не вирішуючи, до скількох лічити:

```sather
   loop
      number ::= 1.up!;
      bar ::= part.elt!;
      #OUT + "Bar " + number + ": " + bar + "\n";
   end;
```

`part.elt!` завершує цикл; `1.up!` дає нумерацію. Жодному з них не треба
знати, яка довжина партії.

## Порядок не має значення

Усі ітератори отримують запит раз на ітерацію, тож не має значення, який із
них записано першим. Важливо, щоб кожен отримав запит рівно один раз: якщо
написати `part.elt!` двічі за одну ітерацію, буде взято два значення замість
одного.
