# Детальніше

У C# ієрархію _класів_ можна визначити за допомогою _успадкування_, яке дає змогу похідному класу (`Car`) успадкувати поведінку й дані свого батьківського класу (`Vehicle`). Якщо батьківський клас не вказано, клас успадковується від класу `object`.

Батьківські класи можуть надавати функціональність похідним класам у три способи:

- Визначити звичайний метод.
- Визначити [`virtual`-метод][virtual-keyword], схожий на звичайний метод, але такий, який похідні класи _можуть_ змінювати.
- Визначити [`abstract`-метод][abstract-keyword]: метод без реалізації, який похідні класи _повинні_ реалізувати. Клас з `abstract`-методами також потрібно позначити як [`abstract`][abstract-classes]. З абстрактних класів не можна створити екземпляр.

[Модифікатор доступу `protected`][protected-keyword] дає змогу звертатися до члена батьківського класу в похідному класі, але блокує доступ з інших класів. Отже, похідні класи можуть звертатися до `public` і `protected` членів батьківського класу, але не до `private` членів батьківського класу.

Похідні класи можуть звертатися до членів батьківського класу через [ключове слово `base`][base-keyword].

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

Конструктор похідного класу [автоматично викликає конструктор свого батьківського класу][constructors] _перед_ тим, як виконати логіку власного конструктора. Аргументи можна передати конструктору батьківського класу за допомогою [ключового слова `base`][base-keyword-constructor]. Оскільки з абстрактних класів не можна створити екземпляр, їхні конструктори можна зробити `protected`.

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

Коли від базового класу походять кілька класів, ці два (або більше) підкласи часто реалізують різні версії методу базового класу. Це дуже важливий принцип, який називається [поліморфізмом][polymorphism]. Наприклад, у варіації наведеного вище прикладу ми показуємо, як код, що використовує `Vehicle`, може змінювати свою поведінку залежно від того, екземпляр якого типу транспортного засобу створено.

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

Щоб унеможливити успадкування класу, додамо [модифікатор `sealed`][sealed-classes].
Деякі практики намагаються уникати успадкування від конкретних класів (як обговорюється в [цьому запитанні на SO][pro-sealed]), і модифікатор _sealed_ підтримує цей підхід. З іншого боку, багато розробників C# вважають їх перешкодою для супроводу, як ідеться в частині коментарів до [цього запитання][anti-sealed]. Порада така: використовувати модифікатор sealed помірковано, доки ми не переконаємося, що він доречний для наших потреб.

У [цій статті][new-vs-override] описано `new` як альтернативу модифікатору `override`. Це іноді буває корисно, наприклад із заплутаними ієрархіями класів та/або через певний конфлікт бібліотек.
