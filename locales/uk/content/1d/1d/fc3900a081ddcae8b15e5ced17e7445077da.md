# Докладніше

Підготовка значення до передавання означає одразу три речі: серіалізувати його, вибрати з нього потрібний фрагмент і не копіювати, коли в цьому немає потреби. Цю тему охоплюють три ідіоми Factor.

## `unparse`: від значення до початкового коду

[`unparse`][unparse] (з модуля `prettyprint`) повертає текст будь-якого значення у формі початкового коду. Це операція, обернена до парсера: зворотний прохід `dup unparse parse` відтворює значення.

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

Порівняймо з `>string` (працює лише з послідовностями символів) і `number>string` (лише з числами). `unparse` годиться для всього, але за це доводиться платити: він видає синтаксис Factor (рядки в лапках зберігають свої лапки). Тож він стане правильним інструментом, коли отримувач розбиратиме текст назад, і неправильним - коли потрібен вивід, зручний для читання людиною.

## Зрізи: подання, а не копії

| слово         | дія                                            |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`: копіює перші n          |
| `head-slice`  | `( seq n -- slice )`: подання перших n         |
| `tail`        | `( seq n -- newseq )`: копіює від індексу n і далі |
| `tail-slice`  | `( seq n -- slice )`: подання від індексу n і далі |
| `head*`       | `( seq n -- newseq )`: копіює все, крім останніх n |
| `head-slice*` | `( seq n -- slice )`: подання всього, крім останніх n |
| `tail*`       | `( seq n -- newseq )`: копіює останні n        |
| `tail-slice*` | `( seq n -- slice )`: подання останніх n       |

`slice` - це кортеж, що містить початковий індекс, кінцевий індекс і саму послідовність. Він реалізує [протокол послідовності][sequence-protocol], тож будь-яка операція над послідовностями працює з ним. Обираймо варіанти зі зрізами, коли інакше довелося б виділяти памʼять лише для читання; обираймо копіювальні, коли дані треба зберегти, навіть якщо базова послідовність може змінитися.

## Cleave з кількома входами: `2bi`, `3bi`, `2tri`, `3tri`

Звичайні слова cleave `bi` і `tri` застосовують дві або три quotation до *одного* входу в стеку. Варіанти з префіксом `2` і `3` застосовують кожен quotation до *двох* або *трьох* входів:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

Кожен quotation отримує *усі* входи, тож `2bi` використовуймо, коли обидві проєкції залежать від пари, а не тоді, коли ту саму проєкцію треба застосувати до кожного входу окремо (це `bi@`).

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

Коли треба застосувати *один* quotation до кожного входу окремо, берімо натомість `bi@` (два входи) або `tri@` (три входи): та сама родина, інша форма.
