# Числа з плаваючою комою

`FLTD` зберігає число, яке може мати дробову частину. Літерал потребує десяткової точки та `d`:

```sather
   440.0d
   0.5d
   -2.25d
```

`FLT` втілює ту саму ідею, але з удвічі меншою точністю. У цьому треку скрізь використовується `FLTD`; немає причини братися за `FLT`, хіба що бракує памʼяті.

## Арифметика

| Оператор | Значення |
| --- | --- |
| `+` `-` `*` | як для `INT` |
| `/` | ділення зі збереженням дробової частини |

Для `FLTD` немає `%`.

Обидва операнди мають бути `FLTD`. Якщо домішати до них `INT`, це помилка компіляції, а не тихе перетворення. І це радше перевага: там, де це дається взнаки, люди якраз і припускаються помилок.

## Перетворення

```sather
   7.fltd            -- 7.0, an INT made into an FLTD
   7.5d.int          -- 7, the fraction thrown away
   7.5d.round        -- 8, to the nearest whole number
   7.5d.floor        -- 7.0, down to a whole number
   7.5d.ceiling      -- 8.0, up to a whole number
```

Перетворювати треба до ділення, а не після: `n.fltd / 2.0d` зберігає половину, а `(n / 2).fltd` її вже втратив.

## Корисні методи

```sather
   (-2.5d).abs       -- 2.5
   2.0d.sqrt         -- 1.41421
   (2.0d).max(3.0d)  -- 3.0
```

## Числа з плаваючою комою наближені

`FLTD` зберігає дуже близьке наближення, а не точне значення. Більшість десяткових дробів неможливо зберегти точно, так само як третину неможливо точно записати в десятковому вигляді. Отже:

```sather
0.1d + 0.2d          -- very nearly 0.3, but not exactly
```

Два наслідки, які варто запамʼятати:

**Не порівнюймо через `=`.** Два обчислення, які мали б дати однакову відповідь, часто різняться в останніх кількох цифрах. Натомість запитаймо, чи вони близькі:

```sather
   (a - b).abs < 0.0001d
```

**Додавання багатьох малих значень втрачає точність.** Кожне додавання трохи округлює, і помилки накопичуються.

Коли значення мають бути точними, зокрема гроші, рахуймо цілими одиницями через `INT` (центи, а не долари).

## Виведення

`.str` показує близько шести значущих цифр, а це менше за точність, яку насправді збережено:

```sather
   #OUT + (1.0d / 3.0d).str;      -- 0.333333
```
