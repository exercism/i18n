# Підказки

## Загальні

- Загляньте до [посібника з Elm][elm-guide]: там є гарний розібраний приклад, схожий на цей.

## 1. Визначте типи Model і Msg для застосунку та напишіть функцію init

- `Model` містить стан застосунку, тобто всі дані, які потрібні застосунку.
- Він має бути [записом][record].
- Цьому застосунку потрібен лише `String`, щоб зберігати текст із текстового поля (тести вимагають, щоб він називався `content`).

- Тип `Msg` визначає повідомлення, які передаються функції `update`, щоб спричинити конкретні зміни в моделі.
- Він має бути [власним типом][custom-type].
- Цьому застосунку потрібна лише одна зміна моделі: оновлення моделі, коли змінюється текст у текстовому полі.

- Функція `init` має просто повертати `Model` з якимось розумним типовим значенням (тести вимагають порожнього рядка).

## 2. Напишіть функцію update

- У будь-якому корисному застосунку функція `update` використовує конструкцію `case`, щоб зіставити зі зразком параметр `Msg`.
- У кожній гілці конструкції `case` вона видобуває потрібну їй інформацію з параметра `Msg` і повертає оновлений `Model`
- `Model` має бути записом, і зазвичай використовують [синтаксис оновлення запису][record-update-syntax].

## 3. Напишіть функцію view

- Функція `view` має повертати `div` для кореневого елемента
- Першим дочірнім елементом має бути `input` з атрибутом `value` для поточного тексту та атрибутом або подією `onInput` з відповідним варіантом `Msg`.
- Другим дочірнім елементом має бути ще один `div` із дочірнім елементом `text`, який показує, чи є текст паліндромом.

## 4. Напишіть функцію main

- Функція `main` має лише викликати [`Browser.sandbox`][browser-sandbox]
- `Browser.sandbox` вимагає аргументу-[запису][record] з функціями `init`, `update` і `view`.
