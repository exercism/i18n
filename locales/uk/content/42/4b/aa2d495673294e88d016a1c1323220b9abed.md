# Докладніше

У попередніх концепціях згадувалося, що директива `global` робить функцію або змінну, визначену в одному вихідному файлі, видимою для інших файлів.
Так само директива `extern` повідомляє асемблеру, що функція або змінна, використана в поточному вихідному файлі, визначена в іншому.

Ці дві директиви - головний спосіб, у який код асемблера взаємодіє з іншими вихідними файлами для досягнення модульності.

Для цих директив не має значення, чи зовнішній код визначено або використано в асемблері, чи мовою високого рівня.
Тож, наприклад, навіть функцію, визначену мовою високого рівня, можна використати в коді x86-64, якщо оголосити її `extern`.

Так само угода про виклики спільна для всіх цих функцій, визначених в асемблері чи мовами високого рівня, і навіть з операційною системою (ОС).

Однак, оскільки в асемблері дані - це лише послідовність байтів, важливо розуміти, як мова високого рівня, з якою ми взаємодіємо, керує памʼяттю.

## Типи C

Мову C часто обирають як мову високого рівня для взаємодії з кодом асемблера.
Вона полегшує взаємодію з ОС, пропонуючи високорівневі обгортки для багатьох важливих завдань, як-от виведення на екран, читання з клавіатури чи виділення динамічної памʼяті.

У цьому треку тести написано мовою C, тож важливо дати загальний огляд цієї мови.

~~~~exercism/note
Будь-який із зазначених нижче типів можна кваліфікувати за допомогою `const`.
Це робить їх доступними лише для читання.
~~~~

### Примітивні типи

У C є багато примітивних типів, і їхній розмір у байтах може відрізнятися.
Деякі з них зведено в наступній таблиці із типовим розміром у системі x86-64:

| тип       | кількість байтів | ціле/з плаваючою комою |
|-----------|------------------|------------------------|
| _Bool     | 1                | ціле                   |
| char      | 1                | ціле                   |
| short     | 2                | ціле                   |
| int       | 4                | ціле                   |
| long      | 4 або 8          | ціле                   |
| long long | 8                | ціле                   |
| float     | 4                | з плаваючою комою      |
| double    | 8                | з плаваючою комою      |

Кожен із цих цілочисельних типів може бути знаковим (типово) або беззнаковим.
Якщо вони беззнакові, це потрібно вказати явно, наприклад: `unsigned int`.

Існують псевдоніми для цілочисельних типів, визначені для точного контролю над їхнім розміром:

| псевдонім | кількість байтів |
|-----------|------------------|
| int8_t    | 1                |
| int16_t   | 2                |
| int32_t   | 4                |
| int64_t   | 8                |

Ці псевдоніми можна доповнити префіксом `u`, щоб позначити беззнаковий тип, наприклад: `uint64_t`.

Інші варті уваги псевдоніми:

| псевдонім | тип                                       |
|-----------|-------------------------------------------|
| bool      | _Bool                                     |
| size_t    | зазвичай беззнакове 8-байтове ціле число  |

`_Bool`, або його псевдонім `bool`, особливий тим, що, хоч він займає цілий байт, він може набувати лише одного з двох значень: `true` (`1`) і `false` (`0`).

Значення цих примітивних типів передаються у функції та повертаються з них за звичайними правилами для цілих чисел і чисел з плаваючою комою.

### Переліки

[Перелік][enum] - це тип, який може набувати одного з кількох явно вказаних елементів:

```c
enum example {
    example_1,
    example_2,
    example_3,
    example_4
};
```

У C переліки неявно перетворюються на цілочисельний тип, яким зазвичай є `int`, тобто 4-байтове ціле число.

Типово перший можливий елемент переліку перетворюється на `0`, а всі наступні елементи - на наступне ціле число.
Тож у визначеному вище `enum example` елемент `example_1` мав би значення `0`, `example_2` - значення `1`, і так далі.

Можна вказати значення для будь-якого елемента переліку, і тоді типово наступний елемент матиме значенням наступне ціле число:

```c
enum example_2 {
    example_1 = 4,
    example_2 = 8,
    example_3
}; // example_3 is equal to 9
```

### Адреси памʼяті

У C на адресу памʼяті посилаються через [вказівник][pointer] на тип і позначають його оператором `*`.
Тож, наприклад, `int64_t *` указує на комірку памʼяті для одного або кількох `int64_t`.

Адреси обробляються як 8-байтові цілі числа, як звично.

### Масиви

Масиви передаються у функції та повертаються з них як вказівники на їхній перший елемент.

```c
int64_t example_arr[] = {1, 2, 3}; // this is an array of 3 signed 8-byte integers
fn(example_arr); // this is a function that passes a pointer (int64_t *) to the beginning of the array as argument
```

Кожен елемент масиву має розмір типу елементів масиву.
Визначений вище `example_arr`, наприклад, має 3 елементи по 8 байтів кожен, тобто 24 байти загалом.

Оскільки масиви не зберігають свою довжину, зазвичай потрібне окреме значення, щоб указати кількість елементів, якщо тільки кінець не позначає сторожове значення.

### Рядки тексту

У C рядки тексту (англ. string) - це масив `char`, який займає 1 байт.
Більшість рядків тексту складаються з ASCII-символів і завершуються NUL-байтом, тож вони закінчуються, коли трапляється байт зі значенням `0`.
Це означає, що довжину рядка тексту зазвичай не потрібно передавати окремим аргументом.

## Виклик функцій бібліотеки C

Директива `extern` лише оголошує, що символ визначено в іншому файлі.
Те, як насправді відбувається виклик, залежить від того, як зкомпоновано цей зовнішній код.

Для звичайних функцій, зкомпонованих разом із нашим кодом, компонувальник здатен знайти зовнішню функцію безпосередньо, тож простого `call` достатньо.

Однак стандартні функції бібліотеки C, як-от `malloc`, `free` і `printf`, зазвичай визначаються під час виконання з динамічної бібліотеки, адреса якої невідома, коли наш код асемблюється.
Тож виклик відбувається через заглушку в [таблиці звʼязування процедур (PLT)][plt], розміщену за відомим зміщенням.
Коли ми викликаємо зовнішню функцію бібліотеки з асемблера, NASM вимагає вказівки, що цей виклик слід розвʼязати через PLT.

У `elf64` (формат виводу, який використовують програми Linux) ця вказівка робиться додаванням `wrt ..plt` («з посиланням на plt») після виклику.
Наприклад, `call printf wrt ..plt`.

У програмах `macho64` (формат виводу, який використовують програми macOS), навпаки, достатньо підкреслення перед назвою функції.
Наприклад, `extern _printf`, потім `call _printf`.
Однак, оскільки в цьому треку код `macho64` асемблюється з прапорцем `--prefix _`, це підкреслення автоматично додає асемблер в обох випадках, наприклад, `extern printf`, потім `call printf`.

Зауважмо, що тестовий раннер Exercism працює в образі Linux, тож будь-яке надіслане рішення, яке викликає функції бібліотеки C, має використовувати `wrt ..plt`.
Щоб правильно перемикатися між форматами виводу, можна використати захисну перевірку під час асемблювання:

```x86asm
extern malloc

%ifidn __OUTPUT_FORMAT__,elf64
    call malloc wrt ..plt       ; elf64: reach the function through the PLT
%else
    call malloc                 ; macho64: the linker generates the call stub
                                ; the underscore is added automatically by an assembler flag
%endif
```

## Системні виклики

Є багато операцій, які програми рівня користувача, як-от ті, що виконуються в цьому треку, не можуть виконувати безпосередньо.
Читання зі `stdin`, запис у `stdout`, запит динамічної памʼяті, взаємодія з периферійними пристроями тощо - усе це виконує операційна система (ОС).

Програма рівня користувача має явно попросити ОС виконати ці операції, коли це потрібно.
Це робиться за допомогою інструкції [`syscall`][syscall].
Концептуально цю інструкцію можна уявити як виклик якоїсь наперед визначеної процедури ОС («системний» виклик).

Будь-який аргумент системного виклику слід передавати ОС у регістрах загального призначення: `rdi`, `rsi`, `rdx`, `r10`, `r8` і `r9`.

Зауважмо, що послідовність майже така сама, як у виклику функції, але `rcx` замінено на `r10`.
Це тому, що `syscall` використовує `rcx` і `r11`, щоб зберегти адресу повернення та прапорці (які відновлюються перед поверненням керування до функції, що викликала).
Обидва регістри слід вважати зіпсованими під час кожного `syscall`.

На відміну від `call`, тут немає міток, які вказують на системні «функції».
Натомість до них звертаються через конкретні числа, розміщені в `rax` перед викликом.
Будь-яке повернене значення, якщо воно є, також розміщується в `rax`.

Описані вище угоди наведено [у додатку до System V ABI][linux-convention], який стосується саме Linux і позначений лише як довідковий.
На практиці доступні системні виклики, їхня кількість і те, як повідомляється про помилки, - це деталі рівня ОС, які сильно різняться між різними ОС і навіть між різними версіями однієї ОС.

Багато функцій бібліотеки C та інших справжніх функцій, визначених ОС, є високорівневими обгортками над системним викликом.
ABI рекомендує віддавати перевагу цим обгорткам над простим `syscall`, а Apple [не гарантує сумісності][mac-qa1118] на рівні інтерфейсу системних викликів ядра.
