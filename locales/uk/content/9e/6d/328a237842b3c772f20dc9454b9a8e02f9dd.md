# Вступ

Як ми вже розглянули в концепції [`Nothingness`][concept-nothingness], R має різні способи подати дані, яких немає (`NULL`), які невідомі (`NA`) або математично некоректні (`NaN`, `Inf`).
Загалом R намагається позначати проблеми такими значеннями на місці й продовжувати роботу, не порушуючи винятку.

## `stop()`

Деякі проблеми настільки принципові, що програма не може продовжити роботу.
У такому разі скористаймося `stop(msg)`, щоб негайно зупинити програму з помилкою `Error` і вивести `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Це зручна обгортка для `stop()`, схожа на `assert` в інших мовах.
Параметри - це довільна кількість булевих умов (англ. Boolean), розділених комами, і програма продовжить роботу лише тоді, коли всі вони `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R має чимало способів обробляти помилки.
Вони походять із Common Lisp і суттєво відрізняються від багатьох популярних мов.

Найпростіший - обгорнути потенційно проблемний код у `try()`.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()` і `message()`

Це реакції на нефатальні умови, наприклад:

- Попередити про проблему, з якої програма може хоча б частково відновитися.
- Повідомити користувача про поступ у тривалій програмі.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

Функція `suppressWarnings()` іноді стає в пригоді на Exercism, щоб небажаний вивід не заплутав test runner.
