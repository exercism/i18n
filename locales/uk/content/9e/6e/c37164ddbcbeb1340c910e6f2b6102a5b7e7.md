# Вступ

## Масиви

Будь-які дані в асемблері - це послідовність байтів.
Це означає, що будь-які дані можна розглядати як **масив** тих байтів, з яких вони складаються.

### Доступ до елементів масиву

Щоб отримати доступ до будь-якого значення в памʼяті, потрібно обчислити його **ефективну адресу**.
Ефективна адреса - це вираз, який може складатися з:

- _базової адреси_, наприклад тієї, яку вказує мітка змінної.
- одного _регістра індексу_, можливо, масштабованого на `1`, `2`, `4` чи `8`.
- 32-бітового _зміщення_ зі знаком, тобто числа, яке додають до базової адреси (або віднімають від неї).

Зауважмо, що ця адреса має _індексацію від нуля_, тож базова адреса без будь-якого зміщення вказує на перший байт змінної.
Ось чому розіменування памʼяті за самою лише міткою, без жодного зміщення, як ми робили в попередніх концепціях, дає значення, що починається з її першого байта:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 використовує [порядок байтів від молодшого до старшого][endianness].
Це означає, що найменш значущий байт багатобайтового значення зберігається за найменшою адресою памʼяті.

Отже, отримуючи доступ до окремих байтів багатобайтового значення, потрібно додати додатне зміщення до базової адреси, щоб дістатися до старших байтів.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

Ініціалізована змінна, оголошена зі списком значень, утворює масив цих значень, де кожен елемент має вказаний розмір.
Однак зміщення завжди задають у **_байтах_**, навіть коли кожен елемент масиву має більший розмір:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

Зауважмо, що оскільки адреси задають у байтах, можна напряму отримати доступ до окремого байта будь-якого елемента масиву:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

З тієї ж причини за одну інструкцію можна отримати доступ до більшого обсягу, ніж розмір одного елемента:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
Асемблер не перевіряє межі під час доступу до масиву.
Індекс за межами масиву читає або записує памʼять поза ним.
Це може призвести до непомітно хибних результатів, до пошкодження інших даних, а якщо памʼять, до якої звертаються, не відображена, то до помилки під час виконання.
Відповідальність за те, щоб кожна ефективна адреса залишалася в межах масиву, лежить на програмісті.
~~~~

### Обчислення розміру ініціалізованого масиву

NASM (The Netwide Assembler - асемблер, який використовує цей трек) має спеціальний символ (`$`), що вказує на поточне місце в памʼяті.
Цей символ дає зручний спосіб обчислити загальний обсяг памʼяті, який займає масив:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

Якщо вжити його одразу після `example`, то `$` містить адресу кінця масиву в памʼяті.
Це означає, що `$ - example` дорівнює різниці між цією адресою та тією, на яку вказує мітка `example`.
Це і є загальний розмір у байтах, який займає масив, на який вказує `example`.

Отже, визначивши `example_length` із цим значенням, ми створили 8-байтову змінну, яка зберігає розмір (або довжину) масиву в байтах.

### Секція .bss

Неініціалізовані дані оголошують у **секції .bss**.
На більшості платформ операційна система заповнює ці дані нулями на старті програми.

У NASM неініціалізована змінна має імʼя, директиву, що вказує розмір даних, і кількість елементів, які потрібно зарезервувати.
Кожну з цих частин відокремлюють від іншої пробілом.

Основні директиви та повʼязані з ними розміри даних:

| директива | розмір  |
| :-------: | :------ |
|   resb    | 1 байт  |
|   resw    | 2 байти |
|   resd    | 4 байти |
|   resq    | 8 байтів |

Наприклад, так резервується неініціалізований простір на `3` байти у змінній з іменем `example`:

```x86asm
section .bss
    example resb 3
```

А так резервується неініціалізований простір на `10` разів по `8` байтів (тобто `80` байтів) у змінній з іменем `arr`:

```x86asm
section .bss
    arr resq 10
```

Змінні в `section .bss` можна змінювати, тобто вони доступні для читання й запису.

До неініціалізованих даних можна отримати доступ так само, як до ініціалізованих, використавши їхню ефективну адресу.
Так само вони мають статичну тривалість зберігання й доступні з будь-якої функції в тому самому вихідному файлі (а якщо їх оголосити `global`, то й в інших вихідних файлах).

### Доступ до адрес масиву за допомогою інструкції Lea

Як ми розглядали в попередній концепції, інструкція `lea` обчислює ефективну адресу памʼяті.
Її можна використати, щоб обчислити адресу будь-якого елемента масиву за тією ж семантикою.

Зауважмо, що за відносної адресації часто потрібно спершу завантажити адресу змінної в регістр, а вже потім формувати складнішу адресу:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
Одна з переваг `lea` полягає в тому, що вона використовує арифметику обчислення адрес, щоб отримати значення, фактично не звертаючись до памʼяті за цією адресою.
Завдяки цьому вона стає корисною для арифметичних обчислень, навіть коли жоден з регістрів не містить адреси памʼяті:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
