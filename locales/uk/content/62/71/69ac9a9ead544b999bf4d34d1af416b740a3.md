# Докладніше

Інтерфейс [`IDisposable`][idisposable] має ключове значення для вивільнення ресурсів і виконує в C# дві важливі ролі:

- Він повідомляє користувачам класу, який реалізує цей інтерфейс, що вони відповідальні за те, щоб дати класу знати (викликавши метод [`Dispose()`][dispose]), що він більше не потрібен, аби той міг вивільнити некеровані ресурси або за потреби скинути свій внутрішній стан. Це відрізняється від звичного підходу до очищення, за якого [збирач сміття][garbage-collector] прибирає все (передусім вивільняє памʼять).
- Разом із компілятором і середовищем виконання інтерфейс `IDisposable` підтримує [інструкцію `using`][using-statement], про яку йдеться у вправі `resource-lifetime`.

Цілком можливо, хоч і малоймовірно, що `Dispose()` викликатимуть через інтерфейс у якійсь загальній процедурі очищення.

Найчастіше `IDisposable` трапляється в класах бібліотек, які обгортають ресурси операційної системи (некеровані), як-от [`System.IO.Stream`][stream] і [`System.IO.TextReader`][text-reader]. (Про `Stream` і `TextReader` йдеться в інших вправах).

```csharp
public class TextHandler : IDispoable
{
    private TextReader reader = new TextReader(...);

    public void Dispose()
    {
        reader.Dispose();
    }
}
```

Якщо клас, який ми використовуємо, реалізує інтерфейс `IDispoable`, потрібно подбати про те, щоб `Dispose()` було викликано (за допомогою блоків [`catch` і `finally`][try-catch-finally]), коли екземпляр більше не потрібен. Якщо клас має член, який реалізує `IDisposable`, то цілком імовірно, що й самому класу потрібно реалізувати `IDisposable`, щоб можна було викликати `Dispose()` і позбутися члена, який реалізує `IDisposble`.

```csharp
public class Activity : IDisposable
{
    private MyResource myResource;

    public Activity()
    {
        myResource = new MyResource();
    }

    public void Perform()
    {
        try
        {
            myResource.BeUseful();
        }
        catch (Exception)
        {
            myResource.Dispose();
        }
    }

    public void Dispose()
    {
        myResource.Dispose();
    }
}
```

Інтерфейс `IDisposable` може бути корисним навіть тоді, коли некерованих ресурсів немає. Скажімо, у нас є довгоживучий обʼєкт, який вимагає, щоб короткоживучі обʼєкти реєструвалися в ньому, а потім скасовували реєстрацію, коли вони більше не потрібні. Реалізація `IDisposable` у короткоживучому обʼєкті попереджає розробника, який використовує цей клас, що `Dispose()` потрібно викликати в кінці життєвого циклу короткоживучого обʼєкта.

## Патерн Dispose

У документації ми побачимо згадки про [патерн Dispose][dispose-pattern]. _Патерн Dispose_ передбачає виклик `Dispose()` із [фіналізатора][finalizer] класу та правильну обробку вивільнення ресурсів у базових класах. _Патерн Dispose_ розглядається в одній із наступних вправ.

_Патерн Dispose_ здебільшого стосується некерованих ресурсів. Якщо ми використовуємо [механізм P/Inovke][native-interoperability] і методи `extern`, потрібно розуміти, як і коли застосовувати патерн Dispose. Більшості розробників C# рідко доводиться мати справу з некерованими ресурсами безпосередньо в такий спосіб.
