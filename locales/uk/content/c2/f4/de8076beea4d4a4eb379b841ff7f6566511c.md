# Репутація

Репутація - це система, яка дає людям змогу здобувати «довіру» в екосистемі Exercism.

Репутація - це показник того, наскільки людина долучилася до Exercism: і через внесок у платформу (наприклад, створення програмного забезпечення, вправ і документації), і через внесок у спільноту (наприклад, наставництво).

Репутацію не можна «витратити» чи «використати». Однак досягнення певних порогів репутації відкриває доступ до нових привілеїв і способів долучитися. Простіше кажучи, чим більше репутації має людина, тим більше ми можемо їй довіряти, а отже, тим більше повноважень вона отримує. Крім того, репутація - це загальнодоступний показник того, скільки людина віддала Exercism.

## Мета

Мета системи репутації така:

1. Максимізувати взаємодії між учнями та наставниками, орієнтовані на зростання
2. Посилити бажання наставників долучатися

## Як здобути репутацію

Репутацію можна здобути в різні способи:

| Дія                               | Репутація |
| --------------------------------- | ---------- |
| Успішне наставництво над рішенням | 5          |
| Публікація рішення                | 1-3        |
| Написання вправи                  | 20         |
| Оновлення вправи                  | 10         |
| Написання концепції               | 10         |
| Оновлення концепції               | 5          |
| Створення pull request            | 3-100      |
| Перегляд pull request             | 1-20       |
| Злиття pull request               | 1-5        |

### Успішне наставництво над рішенням

За кожне рішення, над яким наставництво успішно завершилося (обговорення було завершено), нараховується `5` репутації.

### Публікація рішення

За кожне опубліковане рішення репутація нараховується залежно від складності вправи:

| Мітка    | Репутація |
| -------- | ---------- |
| `easy`   | 1          |
| `medium` | 2          |
| `hard`   | 3          |

### Написання вправи

За кожну вправу, де користувача зазначено як автора, нараховується `20` репутації.

### Оновлення вправи

За кожну вправу, де користувача зазначено як контрибʼютора, нараховується `10` репутації.

### Написання концепції

За кожну концепцію, де користувача зазначено як автора, нараховується `10` репутації.

### Оновлення концепції

За кожну концепцію, де користувача зазначено як контрибʼютора, нараховується `5` репутації.

### Створення pull request

За замовчуванням `12` репутації нараховується, коли зливають pull request, який відкрив користувач.

Залежно від вмісту pull request мейнтейнер може нарахувати більше (або менше) репутації, додавши до pull request одну з таких міток:

| Мітка           | Репутація | Приклади                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x:rep/tiny`    | 3          | <ul><li>Виправлення однієї одруківки або посилання</li><li>Видалення порожнього рядка або додавання розриву рядка</li><li>Зміна або додавання одного коментаря в коді</li></ul>                                                                                                                                                                                       |
| `x:rep/small`   | 5          | <ul><li>Виправлення одного тестового випадку, завдання або прикладу</li><li>Виправлення кількох одруківок чи посилань в одному файлі</li><li>Уточнення вмісту додаванням кількох рядків до файлу</li></ul>                                                                                                                                                           |
| `x:rep/medium`  | 12         | <ul><li>Синхронізація вправи з problem-specifications (разом із правками)</li><li>Додавання одного чи кількох тестових випадків з нуля</li><li>Покращення кількох файлів у вправі</li><li>Додавання нотаток для наставників з нуля</li><li>Виправлення невеликої помилки в засобі запуску тестів, аналізаторі чи репрезентері</li><li>Додавання коментарів аналізатора для однієї вправи</li></ul> |
| `x:rep/large`   | 30         | <ul><li>Додавання нової концептуальної або практичної вправи</li><li>Додавання нової документації з концепції</li><li>Ґрунтовне переписування наявної концепції або вправи</li><li>Додавання нових скриптів CI або іншої автоматизації</li></ul>                                                                                                                     |
| `x:rep/massive` | 100        | <ul><li>Створення засобу запуску тестів, аналізатора, репрезентера або генератора з нуля</li><li>Великі рефакторинги цих інструментів</li><li>Створення великої документації з нуля (наприклад, посібників із внеску чи тестування)</li></ul>                                                                                                                        |

Наведені вище приклади можуть слугувати приблизним орієнтиром, яку мітку застосовувати, але мейнтейнери можуть керуватися власним розсудом.

- Оцінку витраченого часу слід розуміти як середній час, який витратив би _мейнтейнер_ на виконання PR.
- Якщо вказано більше ніж одну мітку, нараховану репутацію визначає мітка з найвищим значенням репутації.
- Якщо pull request ще відкритий, репутація (поки що) не нараховується.
- Якщо pull request закрито _без_ злиття, репутація не нараховується.

_Задля зворотної сумісності ми також підтримуємо використання міток `x:size` для визначення нарахованої репутації._

### Перегляд pull request

За кожен злитий або закритий pull request, який переглянув користувач, нараховується `5` репутації.

- Якщо pull request ще відкритий, репутація (поки що) не нараховується.
- Репутація за перегляд нараховується лише один раз на користувача й на pull request.
- Користувач, який відкрив pull request, _не_ отримує репутації за перегляд власного pull request.

- Репутація, нарахована за перегляд pull request, змінюється, якщо до pull request додати одну з таких міток:

  | Мітка           | Репутація |
  | --------------- | ---------- |
  | `x:rep/tiny`    | 1          |
  | `x:rep/small`   | 2          |
  | `x:rep/medium`  | 5          |
  | `x:rep/large`   | 10         |
  | `x:rep/massive` | 20         |

  Використовувати різні «розміри» репутації для автора й рецензента pull request _не_ можна.
  Обидва базуються на одній і тій самій мітці `x:rep`.

  Якщо вказано більше ніж одну мітку, нараховану репутацію визначає мітка з найвищим значенням репутації.

  _Задля зворотної сумісності ми також підтримуємо використання міток `x:size` для визначення нарахованої репутації._

### Злиття pull request

За кожен pull request, який злив користувач, нараховується `1` репутації.

- Якщо pull request ще відкритий, репутація (поки що) не нараховується.
- Якщо pull request закрито _без_ злиття, репутація не нараховується.
- Користувач, який відкрив pull request, _не_ отримує репутації за злиття власного pull request.
- Якщо pull request не має жодного перегляду, натомість нараховується `5` репутації.

### Створення issue

Як і у випадку з pull request, за замовчуванням, коли створюють issue, **репутація не нараховується**.
На відміну від pull request, репутація нараховується лише за великі чи масштабні issue.

Залежно від вмісту issue мейнтейнер може вирішити нарахувати репутацію, додавши до issue одну з таких міток:

| Мітка           | Репутація | Приклади                                             |
| --------------- | ---------- | ---------------------------------------------------- |
| `x:rep/large`   | 30         | <ul><li>Повністю опрацьована концептуальна вправа</li></ul> |
| `x:rep/massive` | 100        | <ul><li>Проєктування навчальної програми треку</li></ul>       |

Наведені вище приклади можуть слугувати приблизним орієнтиром, яку мітку застосовувати, але мейнтейнери можуть керуватися власним розсудом.

- Репутація має відображати обсяг зусиль, які _мейнтейнер_ витратив би на створення issue.

- Якщо вказано більше ніж одну мітку, нараховану репутацію визначає мітка з найвищим значенням репутації.
