# Вступ

Деякі цикли не можна записати як «зроби це для кожного елемента послідовності»: доводиться повторювати, доки не зміниться певна умова. Саме для цього й потрібен комбінатор `while` у Factor: quotation-предикат каже «продовжувати?», quotation-тіло виконує роботу одного кроку, а `while` повторює, доки предикат не дасть `f`.

## `while` й `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` і `body` — це quotation; обидва працюють зі стеком даних. `while` продовжує цикл, доки `pred` залишає істинне значення; `until` робить навпаки: повторює, *доки* `pred` не стане істинним (тобто доки `pred` залишає `f`).

Одне значення стану може передаватися на стеку між предикатом і тілом:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

Розглянемо покроково: предикат `dup 0 >` зазирає до поточного лічильника; тіло `dup . 1 -` друкує його й зменшує на одиницю; цикл зупиняється, коли лічильник досягає `0`. `drop` у кінці відкидає той фінальний `0` зі стека.

## `while*`: зберегти значення предиката

```
while* ( pred body -- )
```

`while` зважає лише на те, чи залишив його предикат істинне значення, а саме значення відкидає перед виконанням тіла. `while*` натомість *передає це значення тілу*. Він стає в пригоді щоразу, коли перевірка й тіло потребують того самого щойно обчисленого результату: результату пошуку, збігу, розібраного токена.

Тут кожне імʼя вказує на наступне в ланцюжку. Предикат шукає поточне імʼя; доки є наступне імʼя, `while*` передає його тілу, яке друкує його й рухається далі:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at` повертає наступне імʼя або `f`, коли для імені немає запису. Доки він повертає імʼя, `while*` віддає це імʼя `dup .`, який друкує його й залишає як ключ для наступного пошуку. Перший `f` зупиняє цикл: `while*` відкидає його, тож зайвого на стеку не лишається.

## Кілька значень стану з локальними змінними

Коли цикл несе більше ніж одне значення (скажімо, список залишку й поточну суму), перекидання значень на стеку стає надто заплутаним. Найчистіший підхід - оголосити *локальні змінні* через `::`:

```
:: word ( inputs -- outputs ) ... ;
```

Усередині тіла `:> name!` додає локальну змінну, яку можна змінювати; для читання використовують `name`, а для запису `name!` (який забирає нове значення зі стека й присвоює його).

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

Дві локальні змінні тут (`rest` і `running`) охоплюють увесь стан циклу: предикат їх переглядає, тіло їх оновлює, а наприкінці повертається підсумкове значення.

`unclip ( seq -- rest first )` знімає перший елемент послідовності, що стає в пригоді, коли цикл має брати зі списку по одному елементу за ітерацію. Форма `[ rest! ] dip` оновлює `rest` до залишкового хвоста й водночас залишає щойно знятий елемент на стеку, щоб ним скористалося тіло.
