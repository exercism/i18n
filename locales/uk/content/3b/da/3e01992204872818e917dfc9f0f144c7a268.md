# Включення коду

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

`include` копіює код іншого класу в цей. Це операція часу компіляції, яка нічого не коштує під час виконання і не створює жодних звʼязків під час виконання: після цього два класи вже не повʼязані.

## Конструкція

```
   include CLASS  old_name -> new_name , old_name -> ;
```

Кожен запис перейменовує одну складову. `-> ;` без нової назви означає, що її не включають. Усе, чого не згадано, потрапляє сюди без змін.

Перейменування стосується того, що бачить *зовнішній світ*. Виклики між включеними підпрограмами працюють і далі: якщо `describe` викликає `count`, а `count` перейменовано на `beats`, то `describe` викликає `beats`.

## Включення кількох класів

```sather
   include WARM_UP;
   include COOL_DOWN;
```

Це дозволено, і саме так Sather отримує те, що інші мови називають множинним успадкуванням, без звичних клопотів: конфлікт тут є помилкою компіляції, і щоб його виправити, досить перейменувати одну з них або не включати її. Тут нічого не вирішує порядок пріоритетів, який довелося б запамʼятовувати.

## private include

```sather
   private include WARM_UP;
```

приносить код для власного вжитку цього класу, не розкриваючи його. Стане в пригоді, коли нам потрібна реалізація, а не інтерфейс.

## Разом

Звична форма для родини класів:

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

`< $ACT` каже, що клас уміє робити; `include ACT_BASICS` дає частину того, як він це робить. Навіть якщо ми передумаємо щодо того, як, `<` не зрушить з місця.

## Чому це зроблено саме так

Абстрактний клас не має коду, тому від нього не можна випадково успадкувати, і не існує такого поняття, як суперклас, поведінка якого змінюється під нами. Повторне використання - це копія, взята під час компіляції, з класу, який ми назвали, де кожне перейменування записано.

Ціна цього в тому, що повторне використання треба явно попросити в кожному класі. Такий компроміс: доводиться більше писати, зате нічого неявного.
