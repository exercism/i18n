# Інструкції

Сезон із нетболу завершився, і саме турнірна таблиця вирішує, хто гратиме у фіналах.

У заготовці вже є клас `TEAM`. Напишіть `FINALS_LADDER` під ним.

## 1. Хто над ким?

`higher` приймає дві команди й повертає, чи має перша стояти над другою. Команда з більшою кількістю очок стоїть вище. Команди з однаковою кількістю очок розділяє різниця закинутих мʼячів: вище стоїть та, у якої різниця більша.

```sather
FINALS_LADDER::higher(#TEAM("Vixens", 24, 40), #TEAM("Magpies", 20, 90))
-- => true
```

## 2. Турнірна таблиця

`ladder` приймає команди в будь-якому порядку й повертає їх у порядку місць. Переданий масив має залишитися без змін.

```sather
FINALS_LADDER::ladder(teams)
-- => the same teams, best first
```

## 3. Виводимо турнірну таблицю

`names` приймає масив команд і повертає їхні назви, зʼєднані через `", "`.

```sather
FINALS_LADDER::names(FINALS_LADDER::ladder(teams))
-- => "Vixens, Magpies, Swifts"
```

## 4. Переможці

`premiers` приймає команди в будь-якому порядку й повертає назву команди, що стоїть на вершині. Якщо команд немає взагалі, відповідь - `""`.

```sather
FINALS_LADDER::premiers(teams)
-- => "Vixens"
```

## 5. Зовсім інший порядок

`shortest_first` приймає масив рядків тексту (англ. string) і повертає їх упорядкованими за довжиною, від найкоротшого. Рядки тексту однакової довжини йдуть в алфавітному порядку.

```sather
FINALS_LADDER::shortest_first(|"Magpies", "Vixens", "Swifts"|)
-- => "Swifts", "Vixens", "Magpies"
```

Розвʼязання нічиєї - не просто прикраса. Сортування не є стабільним, тож без нього дві назви однакової довжини могли б розташуватися в будь-якому порядку.

Це та сама процедура сортування, що й у завданні 2, лише з іншим правилом. У цьому й полягає суть вправи.
