# Встановлення

## Передмова

Хоча Regina Rexx портовано на багато платформ, ці інструкції зі встановлення зосередяться на 64-бітних настільних платформах під керуванням Windows, Linux або MacOS.

## Кроки встановлення

Зауважте, що цей трек потребує встановленої найновішої версії [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) (3.9.5 на момент написання). Наведене посилання веде прямо до розділу Files, де можна вибрати файл для завантаження.

### Windows

Встановлення для роботи нативно під Windows (через вікно CMD або Powershell) легко виконати в браузері за допомогою кнопки [`Download Latest Version`](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/Regina395w64.exe/download). Усе, що потрібно зробити - клацнути, завантажити й встановити.

Якщо вже є або потрібно використати середовища емуляції Linux, як-от:

* [Git for Windows](https://gitforwindows.org/)
* [Cygwin](https://cygwin.com/)
* [MinGW](http://mingw.org/)

то рідні бінарники Regina для Windows мають бути доступні, тож їх можна просто виконати в цих середовищах, і для більшості випадків це цілком прийнятно.

Однак є одна засторога: інструкція ADDRESS працює неправильно (бо взаємодіє з операційною системою). Для найкращого результату в цих середовищах візьміть пакет, призначений для конкретного середовища, і встановіть його. Наприклад, на сайті Regina є [збірка для Cygwin](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-pc-cygwin.tgz/download), яку можна встановити.

Або, якщо є потреба використати _справжній_ дистрибутив Linux під Windows, як-от [WSL](https://docs.microsoft.com/en-us/windows/wsl/about) чи [Virtual Box](https://www.virtualbox.org/), просто дотримуйтеся інструкцій із розділу Linux для відповідного дистрибутива.

### Linux

Встановлення в Linux зазвичай досить просте, якщо скористатися системним менеджером пакетів. Однак воно стає проблемним, коли доступні пакети _не_ найновіші. На жаль, саме так із Regina.

Встановлення з пакета все ще можливе, якщо вручну взяти найновіший пакет. На сайті [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) є пакети для дистрибутивів родини Debian (зокрема Ubuntu) та родини RHEL (зокрема Fedora, CentOS, Rocky й Alma), серед інших.

Для вибраного дистрибутива потрібно завантажити два пакети: пакет бібліотеки та пакет бінарників. Наприклад, щоб встановити на Debian чи Ubuntu, зробіть так:

```plain
sudo apt update && sudo apt -y install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx_3.9.5-2_amd64-Debian-11.deb > regina-rexx_3.9.5-2_amd64-Debian-11.deb
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3_3.9.5-2_amd64-Debian-11.deb > libregina3_3.9.5-2_amd64-Debian-11.deb
sudo apt -y install libregina3_3.9.5-2_amd64-Debian-11.deb regina-rexx_3.9.5-2_amd64-Debian-11.deb
```

А на CentOS і RHEL 7 спробуйте:
```plain
sudo yum update && sudo yum install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
sudo yum localinstall libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
```

А на Fedora, Rocky та Alma спробуйте:
```plain
sudo dnf update && sudo dnf install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
sudo dnf localinstall libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
```

Там, де встановлення з пакета неможливе або з якихось причин виявилося проблемним, завжди можна зібрати з вихідного коду, а архів можна взяти тут:

```plain
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5.tar.gz > regina-rexx-3.9.5.tar.gz
```

Якщо стандартні інструменти збірки (gcc, make) встановлено (якщо ні, дотримуйтеся інструкцій тут: [Встановлення інструментів розробки](https://ostechnix.com/install-development-tools-linux/)), виконайте такі кроки:

```plain
tar -xzvf regina-rexx-3.9.5.tar.gz && cd regina-rexx-3.9.5
./configure
sudo make
sudo make install
```

Встановлюються бібліотека (`libregina.so`) і два набори бінарників (`rexx` і `regina`) (типове розташування - `/usr/local/bin`).

Бінарник `rexx` зібрано статично, тож він самодостатній і готовий до використання.

Бінарник `regina` зібрано динамічно, тож він потребує певного налаштування, щоб під час роботи знаходити спільну бібліотеку `libregina.so`. Щоб це зробити, виконайте такі кроки:

```plain
# Configure shared library location
sudo su
echo /usr/local/lib64/ > /etc/ld.so.conf.d/regina-rexx-3.9.5-x86_64.conf
echo /usr/local/lib64/regina-rexx/addons > /etc/ld.so.conf.d/regina-rexx-addons-x86_64.conf
cd /usr/local/lib64
rm -f libregina.so libregina.so.3
ln -s libregina.so.3.9 libregina.so
ln -s libregina.so.3.9 libregina.so.3
ldconfig
exit

# Check symbolic link creation
ls -l /usr/local/lib64/

# Output should be similar. Note symbolic links.
-rw-r--r--. 1 root root 3887554 Dec  1 18:22 libregina.a
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so -> libregina.so.3.9
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so.3 -> libregina.so.3.9
-rwxr-xr-x. 1 root root  574104 Dec  1 18:22 libregina.so.3.9
drwxr-xr-x. 2 root root      26 Dec  1 18:22 pkgconfig
drwxr-xr-x. 4 root root      33 Dec  1 18:22 regina-rexx

# Check library path, and executable using that path
ldconfig -p | grep regina
ldd /usr/local/bin/regina

# Alternate for local user
export LD_LIBRARY_PATH=${LD_LIBRARY_PATH}:/usr/local/lib64:/usr/local/lib64/regina-rexx/addons
```

Зауважте: збірка з вихідного коду та повʼязане з нею налаштування системи - завдання, за яке краще братися досвідченим користувачам.

### MacOS

Встановлення складається з трьох кроків:

* Встановіть менеджер пакетів [Homebrew](https://brew.sh)
* Знайдіть і запустіть застосунок `Terminal`
* У командному рядку `Terminal` введіть таке:

   `brew install regina-rexx`

Це _має_ встановити найновішу версію.

Якщо ні, можна завантажити пакет [Regina for MacOS](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-apple-darwin21.6.0.tgz/download) і встановити його вручну.

## Після встановлення

### Перевірка встановлення

Після завершення встановлення можна перевірити, чи [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) встановилася успішно, виконавши в терміналі таку команду:

```plain
rexx --version=v
```

І на Windows, і на Linux у терміналі зʼявиться такий вивід:

```plain
3.9.5
```

а це номер версії інтерпретатора.

Також встановлюється другий бінарник, `regina`. Він ідентичний до `rexx` у всьому, крім того що компонується зі спільною бібліотекою, і саме його слід використовувати, якщо потрібен доступ до зовнішніх службових функцій. Див. розділ [Доступ до зовнішніх процедур](###accessing-external-routines).

Жодних інших програмних компонентів встановлювати не потрібно, щоб почати працювати з треком (за умови, що інтерфейс командного рядка Exercism уже встановлено).

Наведені нижче нотатки про використання дадуть базове уявлення про роботу з інтерпретатором із командного рядка.

### Використання

Скрипт Rexx зазвичай має розширення _`.rexx`_, хоча це не обовʼязково: інтерпретатор спробує виконати будь-яке імʼя файлу, передане як аргумент, і якщо той містить коректний код Rexx, він успішно виконається.

Наступна команда спробує виконати файл із назвою `hello.rexx`:

```plain
rexx hello.rexx
```

Припустімо, файл містить такий код:

```rexx
say "Hello, world!"
exit 0
```

тоді вивід у терміналі буде таким:

```plain
Hello, world!
```

Той самий вивід у терміналі зʼявиться, якщо перейменувати файл на `hello.txt` і виконати його так:

```plain
rexx hello.txt
```

Варто також знати, що код скрипту можна подати інтерпретатору через конвеєр, а не тримати у файлі. Попередній код можна виконати через конвеєр так:

```plain
echo "say 'Hello, world' ; exit 0" | rexx
```

і це однаково добре працює як у терміналі Linux, так і в терміналі Windows Powershell.

### Розширене використання

Файлам скриптів можна передавати один або більше аргументів командного рядка, і вони можуть повертати довільні цілочисельні коди повернення. Однак інтерпретатор має знати, що скрипту буде передано кілька аргументів, а це робиться за допомогою опції `-a`.

Наприклад, припустімо, файл `multiarg.rexx` містить такий код:

```rexx
say "My name is" ARG(1) || ", your name is" ARG(2) || ", and the script return code will be" ARG(3) || "."
exit ABS(ARG(3))
```

Щоб кілька аргументів скрипту було правильно розтлумачено, скрипт виконують так:

```plain
rexx -a multiarg.rexx "John" "Jill" 5
```

що дає такий вивід у терміналі:

```plain
My name is John, your name is Jill, and the script return code will be 5.
```

а код повернення програми (доступний через `$?` у Linux або `%errorlevel%` у Windows) дорівнюватиме 5.

### Доступ до зовнішніх процедур

Regina підтримує використання процедур, що містяться у зовнішніх спільних бібліотеках. Кілька з них доступні на сайті Regina. Утім, встановлення таких бібліотек тут не розглядається.

Однак Regina постачається з однією такою бібліотекою, _regutil_. Вона містить кілька процедур загального призначення, зокрема для математики, роботи з файлами та файловою системою і завдань доступу до системи.

Жодних додаткових кроків встановлення не потрібно. Однак, щоб скористатися цими процедурами у скрипті, їх потрібно зареєструвати під час завантаження інтерпретатора. Для цього досить двох викликів функцій, і процес показано тут.

Файл `access-external.rexx` містить такий код:

```rexx
/* Register external library and functions */
call RxFuncAdd 'SysLoadFuncs', 'regutil', 'SysLoadFuncs'
call SysLoadFuncs

say "Value of pi is" SysPi()
say "Square root of 25 is" SysSqrt(25)
say "Square root of 2 is" SysSqrt(2)

/* Deregister */
call SysDropFuncs

exit 0
```

Щоб завантажити й використати ці процедури, потрібно скористатися бінарником `regina`, тож скрипт виконують так:

```plain
regina access-external.rexx
```

і зʼявляється такий вивід у терміналі:

```plain
Value of pi is 3.141592654
Square root of 25 is 5.000000000
Square root of 2 is 1.414213562
```

Якби натомість використали бінарник `rexx`, вивід у терміналі на платформі Windows був би таким:

```plain
'SYSLOADFUNCS' is not recognized as an internal or external command,
operable program or batch file.
'SYSPI' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSDROPFUNCS' is not recognized as an internal or external command,
operable program or batch file.
```

а на платформі Linux вивід у терміналі був би таким:

```plain
sh: SYSLOADFUNCS: command not found
sh: SYSPI: command not found
sh: SYSSQRT: command not found
sh: SYSSQRT: command not found
sh: SYSDROPFUNCS: command not found
```
