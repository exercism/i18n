# Вступ

## Інтерфейс `error`

У Go обробка помилок **не** відбувається через винятки.
Натомість помилки - це звичайні _значення_ типів, які реалізують вбудований інтерфейс `error`.
Інтерфейс `error` дуже мінімальний.
Він містить лише один метод `Error()`, який повертає повідомлення про помилку як рядок тексту (англ. string).

```go
type error interface {
  Error() string
}
```

Щоразу, коли ми визначаємо функцію, під час виконання якої може статися помилка, яку потрібно донести до того, хто викликав функцію, треба включити `error` до типів, які функція повертає.
Якщо функція має кілька повернених значень, за домовленістю `error` завжди стоїть останнім.

```go
func DoSomething() (int, error) {
  // ...
}
```

## Створення і повернення простої помилки

Не обовʼязково щоразу самостійно реалізовувати інтерфейс `error`.
Щоб створити просту помилку, можна використати функцію `errors.New()` зі стандартного пакета `errors`.
Єдине, що потрібно передати, - це повідомлення про помилку як рядок тексту, а `errors.New()` подбає про створення значення, яке містить наше повідомлення й реалізує інтерфейс `error`.

Якщо функція повертає помилку, гарна практика - повертати нульове значення для решти значень, які вона повертає:

```go
func DoSomething() (SomeStruct, int, error) {
  // ...
  return SomeStruct{}, 0, errors.New("failed to calculate result")
}
```

~~~~exercism/caution
Не варто припускати, що всі функції повертають нульові значення для решти значень, якщо помилка є.
Найкраще вважати, що користуватися жодним з інших повернених значень небезпечно, якщо сталася помилка.
Єдині винятки - це випадки, коли документація чітко зазначає, що інші повернені значення мають сенс у разі помилки.
~~~~

Якщо таку просту помилку потрібно використати в кількох місцях, краще оголосити для неї змінну, а не викликати `errors.New` безпосередньо в коді.
За домовленістю назва такої змінної має починатися з `Err` або `err` (залежно від того, експортована вона чи ні).
Такі змінні для помилок часто називають _вартовими помилками_.

```go
import "errors"

var ErrNotFound = errors.New("resource was not found")

func DoSomething() error {
  // ...
  return ErrNotFound
}
```

Повернімо `nil` як помилку, щоб показати, що під час виконання функції помилок не було:

```go
func Foo() (int, error) {
  return 10, nil
}
```

## Перевірка помилок

Якщо ми викликаємо функцію, яка повертає помилку, зазвичай зберігаємо значення помилки у змінній з назвою `err`.
Перш ніж використати справжній результат функції, потрібно перевірити, що помилки не було.

Щоб не вкладати «щасливий шлях» нашого коду, випадки з помилками слід обробляти першими.
Ми можемо використати `==` і `!=`, щоб порівняти помилку з `nil`, і знаємо, що сталася помилка, коли `err` не дорівнює `nil`.

```go
func processUserFile() error {
	file, err := os.Open("./users.csv")
	if err != nil {
		return err
	}

	// do something with file
}
```

Найчастіше помилку повертають далі вгору стеком викликів, як показано в прикладі вище.
Інший спосіб обробити помилку - записати її в журнал і продовжити з якоюсь іншою операцією.
Гарна практика - або повернути помилку, або записати її в журнал, і ніколи не робити й того, й іншого.

Оскільки більшість функцій у Go повертають помилку як одне з повернених значень, ми всюди в коді Go будемо бачити та використовувати конструкцію `if err != nil`.

## Власні типи помилок

Якщо потрібно, щоб помилка містила більше інформації, ніж просто рядок тексту з повідомленням про помилку, можна створити власний тип помилки.
Як уже згадувалося, усе, що реалізує інтерфейс `error` (тобто має метод `Error() string`), може бути помилкою в Go.

Зазвичай для створення власного типу помилки використовують структуру.
За домовленістю назви власних типів помилок мають закінчуватися на `Error`.
Крім того, метод `Error() string` найкраще визначати з приймачем-вказівником; про причини цього читайте в цьому [коментарі на Stack Overflow][stackoverflow-errors].
Зауважмо, що тоді потрібно повертати вказівник на власну помилку, інакше вона не вважатиметься `error`, бо значення без вказівника не надає методу `Error() string`.

```go
type MyCustomError struct {
  message string
  details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.message, e.details)
}

func someFunction() error {
  // ...
  return &MyCustomError{
    message: "...",
    details: "...",
  }
}
```
