# Змінність

Змінність - це властивість конкретного звʼязування в Rust. Звʼязування буває або незмінним, або змінним. Значення незмінного звʼязування не можна змінити; значення змінного звʼязування змінити можна. Усі звʼязування типово незмінні.

## Звʼязування

Звʼязування - це звʼязок між певним імʼям змінної, як воно записане у вихідному коді, і певною ділянкою памʼяті, яка існує під час виконання. Строго кажучи, звʼязування існують лише під час компіляції: до компіляції жодної памʼяті ще не виділено, а після компіляції машинний код працює виключно з адресами памʼяті, а не з іменованими змінними.

Зазвичай звʼязування створюють за допомогою ключового слова `let`. Крім того, звʼязування виникають із параметрів функції та за деяких інших обставин.

Звʼязування можуть мати різні властивості, найважливіша з яких - змінність. Змінне звʼязування - це таке звʼязування, для якого змінювати значення звʼязаної памʼяті дозволено. Rust суворо відстежує та забезпечує змінність кожного звʼязування, щоб програми були правильними, відкидаючи програми, які неправильно намагаються змінити звʼязування, що має бути незмінним.

## Змінність

На практиці зі змінністю зазвичай усе просто. Якщо використати ключове слово `mut` у визначенні звʼязування, отримаємо змогу змінювати значення.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### Зниження зі змінного до незмінного

Звʼязування завжди можна знизити зі змінного до незмінного. Ця операція прозора.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### Підвищення з незмінного до змінного

Загалом значення можна підвищити з незмінного до змінного будь-коли, коли передається володіння.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

У `(1)` володіння рядком тексту (англ. string) передається від `x` до `y`, що дає змогу підвищити значення до змінного.

### Змінність у параметрах функції

Існують два різні способи зробити параметри функції змінними. Перший, поширеніший спосіб нагадує передавання за посиланням у C:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

У цьому прикладі змінність явно позначено в трьох місцях. Усі три оголошення змінності потрібні, щоб змінні посилання працювали.
У `(2)` звʼязування `x` оголошено змінним. Це звʼязування володіє значенням на верхньому рівні.
У `(3)` це значення позичається як змінне, щоб передати його у функцію `increment`.
У `(1)` створюється нове, змінне звʼязування `n` для відповідного посилання.

Є ще один стиль змінності параметрів, менш поширений, але іноді корисний. У цьому стилі значення перебуває у володінні, але звʼязування змінне.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

Цей приклад потребує менше явних позначень, бо насправді це передавання володіння з вбудованим підвищенням до змінності. Він працює, тому що `i32` належить до типу `Copy`, який прозоро копіює дані.
У `(1)` ми оголошуємо, що `increment_internally` приймає змінне `i32` у володінні з іменем `n` як свій параметр.
У `(2)` ми оголошуємо `x` незмінним звʼязуванням зі значенням `1`.
У `(3)` `x` копіюється в нове місце в памʼяті. `x` залишається незмінним. `n` - змінне.

Звісно, форми можна й поєднувати, отримуючи змінне звʼязування для змінного посилання (`mut n: &mut i32` тощо), але насправді це потрібно рідко.

### Змінність без `let`

Деякі конструкції в Rust (`if let`, `match` тощо) також можуть створювати звʼязування. Ці звʼязування теж можуть бути змінними.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

Цей приклад спершу дає `v = Some(2)`, а потім `v = None`.

## Затінення

Можна (і часто так і роблять) повторно використати імʼя змінної, коли значення перетворюється, оголосивши його заново кількома викликами `let`. Це називають затіненням.

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

Однак це не випадок змінності; початкові значення в принципі все ще існують. Для типів без `Drop` компілятор може змінити комірку памʼяті замість того, щоб виділити нову. Однак він ніколи не робить цього для типу `Drop` або якщо старе звʼязування використовується знову.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
