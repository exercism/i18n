# Тести

Кожна вправа містить набір модульних тестів і все необхідне, щоб їх зібрати й запустити.
Реалізацію ж пишемо ми.

## Запуск тестів

Відкрийте термінал у теці вправи й виконайте:

```
make
```

Ця команда компілює рішення й тести, а потім запускає тести.
Запускайте її знову щоразу, коли змінюєте рішення.

Якщо у вас є [Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally), натомість можна скористатися цією командою, яка теж запускає `make`:

```
exercism test
```

Щоб видалити файли, створені збіркою, виконайте `make clean`.

### Без make

Якщо `make` немає (наприклад, у Windows), тести можна скомпілювати й запустити напряму.
Для вправи «Bob»:

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

Потім запустіть тести в Linux або macOS:

```
./run_tests
```

Або у Windows:

```
.\run_tests
```

## Робота над вправою

Файли кожної вправи названо за нею.
Для вправи «Bob»:

| Файл             | Вміст                                                             |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90`        | заглушка рішення, яку залишилося заповнити                         |
| `bob_test.f90`   | тести                                                             |
| `TesterMain.f90` | бібліотека тестів                                                 |
| `Makefile`       | інструкції для `make`                                             |
| `CMakeLists.txt` | інструкції для [CMake](#using-cmake-instead), який необовʼязковий |

Редагувати потрібно лише файл рішення.

Працюючи над кожною вправою, ми повторюємо ці кроки, доки всі тести не пройдуть:

- Виправити помилки компіляції, а потім запустити тести, щоб побачити, які з них не проходять.
- Реалізувати рівно стільки, щоб наступний невдалий тест пройшов.
- Відрефакторити реалізацію, щоб покращити читабельність, зменшити дублювання тощо.
- Знову запустити тести й перейти до наступного невдалого тесту.

Для кожного невдалого тесту друкується повідомлення, а потім підсумок.
Якщо якісь тести не пройшли, `make` завершується з помилкою.

У кожному тесті є коментар з описом тесту, а потім і сам тест, який починається з `call assert_equal`, наприклад:

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Щоб вимкнути тест, досить закоментувати його за допомогою `'!'`, наприклад:

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## Використання CMake натомість

CMake не обовʼязковий, але може стати в пригоді, якщо ми працюємо в IDE, як-от Visual Studio чи Xcode, або використовуємо компілятор, відмінний від GFortran.

Тека вправи повинна зберегти свою початкову назву, бо CMake використовує її для пошуку вихідних файлів.
Почніть у теці вправи:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

Після зміни рішення потрібні лише останні дві команди.

**Примітка:** завжди запускайте `cmake` з окремої теки, наприклад `build`.
Запуск `cmake .` у теці вправи замінює `Makefile`, який постачається зі вправою.

CMake сам вибирає відповідний генератор для нашої системи.
Щоб вибрати інший, скористайтеся опцією `-G`, наприклад `cmake -G Xcode ..`.
Запустіть `cmake --help`, щоб побачити список доступних генераторів.
Із Visual Studio чи Xcode запускайте тести командою `ctest -V -C Debug`.

Якщо в теці вправи немає `Makefile`, її завантажено ще до того, як ці файли додали до вправ.
CMake усе одно можна використовувати.
