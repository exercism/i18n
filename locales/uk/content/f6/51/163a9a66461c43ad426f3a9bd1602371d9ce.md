# Основи Unison

## Терми та функції

Терми та функції - це базові одиниці, з яких будується програма мовою Unison.

«Терм» - це те, що ми називаємо статичним значенням. Його визначають записом `name = expression`, перед яким за потреби стоїть сигнатура типу вигляду `name : MyType`. Unison підтримує виведення типів, тож у простих визначеннях сигнатуру типу можна й не побачити.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Функції в Unison мають такий вигляд: `myFunctionName argument1 argument2 = myImplementation`; вони починаються з назви функції, за якою йдуть аргументи, розділені пробілами.

```
getMax a b = Nat.max a b
```

Функція може за потреби мати сигнатуру типу. Останній тип праворуч - це завжди кінцевий тип повернення функції, а кожен аргумент відокремлюють стрілкою функції `->`.

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Щоб викликати функцію, пишемо її назву, а потім аргументи, розділені лише пробілами.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Коли ми викликаємо функцію, Unison намагається вважати її аргументом те, що стоїть безпосередньо праворуч, а це не завжди дає бажаний порядок обчислення функцій.

Скажімо, ми хочемо отримати значення `1` із наведеного виразу

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

У такому записі `shouldBe1` обчислюється до `0`, бо неявний порядок застосування функцій такий: спершу `getMax 1 10`, тобто `10`, а потім `10 - 10`, тобто `0`.

Можна використати дужки, щоб перегрупувати вираз у бажаний порядок операцій.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Вирази спостереження

Unison надає спосіб швидко обчислити код під назвою «вираз спостереження». Вираз спостереження починається зі символу `>`, за яким іде вираз для обчислення. Вирази спостереження можна писати в будь-якому файлі з розширенням `.u`. Після збереження файлу ми побачимо в консолі Unison Codebase Manager (UCM), до чого обчислюється вираз. Де це можливо, у цій документації ми будемо намагатися показати вираз разом з його очікуваним результатом після обчислення у виразі спостереження.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Багаторядкові функції

Багаторядкові функції в Unison використовують відступи або блоки `let`, щоб задати межі коду, тобто лексичну область видимості.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Усе на одному рівні відступу має спільну область видимості, тому в останньому рядку ми можемо звертатися до змінної `newBeginning`.

## Простори імен та інструкції `use`

Простори імен - це те, як ми групуємо та впорядковуємо функції Unison. Їх можна уявити як аналоги «каталогів». Вони дають структуру та логічне групування.

Можна внести функції з простору імен в область видимості за допомогою інструкції `use`.

Скажімо, ми пишемо функцію, яка використовує значення `List` у Unison. Ми знаємо, що нам знадобляться такі функції, як `List.map` і `List.flatMap`, де `List` - це простір імен, а `map` і `flatMap` - функції. Щоб не повторюватися, можна внести все з простору імен `List` у лексичну область видимості функції ось так:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

Рядок `use List` усуває неоднозначність посилань на `map` і `flatMap`. Докладніше про [інструкції `use` можна прочитати тут][use-statements].

## Стандартна бібліотека Unison

Стандартна бібліотека Unison називається `base`. Якщо ми скористалися посібником зі швидкого старту і маємо локально створену кодову базу, стандартна бібліотека мала завантажитися автоматично. Документацію до стандартної бібліотеки можна переглянути онлайн на [Unison Share][unison-share-base].

## Коментарі та літерали документації

Коментарі в Unison - доволі незвична особливість. Пишучи код Unison, ми можемо створити у файлі з розширенням `.u` текст, який не інтерпретується, за допомогою такого синтаксису:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Однак_, оскільки код Unison зберігається як хеш його абстрактного синтаксичного дерева, а не як текстові файли у файловій системі, коментарі, які є текстовими «оздобами» певної функції чи терму Unison у файлі, насправді не можна зберегти й показати наново, щоб поділитися ними. Якщо ми хочемо додати інформацію до свого терму Unison так, щоб вона збереглася й інші могли її прочитати та зрозуміти, можна скористатися літералом документації.

Документація - повноправне значення в мові програмування Unison. Це означає, що елемент `Doc` можна присвоїти змінній, передати як значення у функцію або повернути як значення функції. Елементи літералів документації відкриваються та закриваються подвійними фігурними дужками. Ось як ми могли б використати елемент `Doc` як коментар.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
