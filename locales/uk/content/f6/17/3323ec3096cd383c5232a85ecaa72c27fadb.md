# Докладніше

У мові C [struct][struct] - це складений тип, що складається з різних полів. Кожне поле має власний тип і розмір.

Наприклад, ось визначення типу, що складається з трьох цілих чисел: двох розміром 4 байти й одного розміром 8 байтів:

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

Також struct може містити інші struct:

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

Якщо одне з полів struct є масивом, усі байти, виділені для цього масиву, входять до складу struct. Але якщо поле - лише вказівник на масив, то сам масив має зберігатися деінде:

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## Вирівнювання

Вирівнювання типу - це невідʼємний степінь двійки (1, 2, 4, 8, ...), що задає вимогу до адреси обʼєкта. Кожен обʼєкт цього типу має розташовуватися за адресою, кратною його вирівнюванню.

Для примітивного типу вирівнювання зазвичай дорівнює його розміру, тож, наприклад, `int32_t` зазвичай має 4-байтове вирівнювання. Це означає, що `int32_t` потрібно розміщувати на межах, кратних 4 байтам.

Вирівнювання struct, однак, - це максимальне вирівнювання серед усіх його полів. Так, наприклад, struct `struct example`, визначений вище, мав би вирівнювання 8 байтів, оскільки саме таке вирівнювання має `uint64_t`.

Якщо вирівнювання поля struct менше за вирівнювання самої struct, після цього поля можуть бути вставлені заповнювальні байти. Це гарантує, що наступні поля й struct загалом відповідають вимогам вирівнювання. На практиці це означає, що хоча ці заповнювальні байти й додаються до розміру struct, вони не входять до значення struct:

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

Зауважте, що в struct, визначеній вище, поле 'one_byte' має вирівнювання 1 і може розташовуватися за будь-якою адресою. Оскільки поле 'four_byte' має вирівнювання 4, поля в struct також мають дотримуватися меж, кратних 4 байтам. Це означає, що між будь-якими двома полями struct має бути кількість байтів, кратна 4. Оскільки 'one_byte' займає лише 1 байт, після нього вставляють 3 заповнювальні байти, щоб дотриматися цієї межі.

Суміжні поля групуються, коли це можливо, щоб звести до мінімуму потрібну кількість заповнювальних байтів:

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

Це групування також має зважати на вирівнювання кожного поля:

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

Це означає, що зміна порядку полів у struct іноді може призвести до різниці в розмірі:

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

Зауважте, що вирівнювання масиву збігається з вирівнюванням його базового типу:

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

Елементи масиву можна групувати так само, якби вони не були частиною масиву:

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

Важливо враховувати всі можливі заповнювальні байти, коли ми звертаємося до struct у коді асемблера.

## Угода про виклики

Загалом значення передаються до функцій і повертаються з них природним чином:

- Цілі значення, зокрема адреси памʼяті та переліки, передаються в регістрах загального призначення (GPR).
- Значення з плаваючою комою передаються в регістрах `xmm`.

Struct, однак, - це особливий випадок. Як правило, усі поля struct займають суміжний простір у памʼяті, і їх слід розміщувати в одному регістрі, коли це можливо:

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

Якщо struct має поля з цілими значеннями, а також поля зі значеннями з плаваючою комою, кожні послідовні 8 байтів у struct потрібно класифікувати окремо:

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

Якщо цілі значення та значення з плаваючою комою потрапляють в одні й ті самі 8 байтів, тип уважається цілим, і весь 8-байтовий фрагмент (разом зі значенням з плаваючою комою) розміщується в GPR:

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
Коли виконується перетворення з плаваючої коми в ціле за допомогою `cvtss2si` або `cvtsd2si`, це змінює організацію відповідних байтів.

Можна використати [movd][mov] (для 32-бітних значень) або [movq][mov] (для 64-бітних значень), щоб перемістити необроблені байти з регістра `xmm` до GPR, не змінюючи бітового представлення.

[mov]: https://www.felixcloutier.com/x86/movd:movq
~~~~

Однак struct розміром понад 16 байтів зазвичай розміщують у памʼяті, незалежно від типу кожного 8-байтового фрагмента:

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

Коли struct передається як аргумент до функції, використовується стільки регістрів, скільки потрібно. Якщо struct розміщено в памʼяті, натомість використовується стек.

Схожі правила діють і для struct, які повертаються з функції. Зазвичай такі struct повертають спершу в `rax` і `rdx` (якщо значення ціле) або в `xmm0` і `xmm1` (якщо значення з плаваючою комою). Якщо ж struct розміщено в памʼяті, той, хто викликає, має зарезервувати для неї місце й передати адресу цієї ділянки памʼяті як неявний перший аргумент функції (у `rdi`). Тоді функція зберігає struct у цьому місці й повертає адресу цієї ділянки в `rax`.
