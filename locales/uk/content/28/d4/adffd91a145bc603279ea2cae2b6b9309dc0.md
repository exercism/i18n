# Додаток до інструкцій

## Повідомлення про винятки

Іноді потрібно [порушити виняток][raising-exceptions].
Коли ми це робимо, слід завжди додавати **змістовне повідомлення про помилку**, яке вказує, що саме стало її джерелом.
Це робить код зрозумілішим і значно допомагає з налагодженням.
Якщо ми знаємо, що джерело помилки матиме певний тип, можна порушити один із [вбудованих типів помилок][error-base-classes], але повідомлення все одно має бути змістовним.


Коректна гра в `Tic Tac Toe` завершується перемогою одного з гравців.
Якщо обидва гравці перебувають у виграшному стані, ця вправа передбачає, що ми скористаємося [інструкцією raise][raise] і «кинемо» `ValueError` у своєму рішенні.
Також очікується, що наш код порушить `ValueError`, якщо виявиться, що один гравець зробив два ходи підряд або зробив перший хід, коли йому було призначено робити другий.


Щоб порушити `ValueError` з повідомленням, передамо повідомлення як аргумент типу `exception`:

```python
# Example when player O goes before player X.
raise ValueError("Wrong turn order: O started")

# Example when player X goes twice.
raise ValueError("Wrong turn order: X went twice")

# Example when player X wins AND player O wins.
raise ValueError("Impossible board: game should have ended after the game was won")
```

Тести перевіряють точний збіг повідомлення про помилку, тож уважно читаймо очікувані результати.

[error-base-classes]: https://docs.python.org/3/library/exceptions.html#base-classes
[raise]: https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement
