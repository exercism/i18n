# Докладніше

## JSON

[JSON][json] (JavaScript Object Notation) - це зрозумілий людині формат даних і файлів, який часто використовують для обміну даними, зокрема у вебзастосунках.
Тож не дивно, що він посідає особливе місце в мові Elm.

Elm надає основні модулі [`Json.Decode`][decode] та [`Json.Encode`][encode] для розбору й запису даних JSON.
Декодери JSON дають змогу _оголосити_, який тип даних очікується і якій структурі даних мають відповідати ці дані.

Якщо ми приходимо з динамічно типізованих мов, декодери часто здаються громіздкими або надто жорсткими на перший погляд.
Хоч вони, принаймні в Elm, і справді багатослівні, це цінний інструмент, щоб явно описати очікування програм щодо вхідних даних, і вони [не менш виразні, ніж динамічні типи][dynamic-types-not-more-open].

Імпортуймо кілька псевдонімів і типів із модулів:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Якщо використати `Decode.decodeString : Decoder a -> String -> Result Error a` з декодером і рядком тексту JSON (англ. string), то або все вдасться, якщо рядок відповідає специфікаціям декодера, або станеться помилка.
Під час визначення декодера немає способу зазирнути в необроблені дані JSON, що може здатися незвичним, якщо ми приходимо з імперативних мов.

## Декодери базових типів даних

JSON має невелику кількість базових типів даних:

- Рядок тексту: кодується подвійними лапками `"hello world"`
- Булеве значення (англ. Boolean): або `true`, або `false`
- Число: наприклад, `34` або `0.12`
- Null: відсутність даних `null`

Кожен із них повʼязаний із функцією `Decode`:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Зауважмо, що `Decode.null` дає змогу вирішити, як моделювати `null` у нашій програмі, вимагаючи довільне значення як аргумент (можливо, `()`, `Nothing` або будь-що доречне для нашої програми).

## Поєднання декодерів

JSON також визначає дві структури даних для збирання базових типів даних:

- Масив: набір інших типів даних `[0, null, "none", []]`
- Обʼєкт: набір пар ключ-значення `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` також пропонує функції для декодування цих структур:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Ці функції `Decode.list : Decoder a -> Decoder (List a)` і `Decode.dict : Decoder a -> Decoder (Dict String a)` кожна приймає декодер як аргумент, який має декодувати кожен окремий елемент структури даних.
Якщо декодер-аргумент не зможе декодувати якийсь елемент масиву чи обʼєкта, весь декодер зазнає невдачі, і це поширений прийом.

Основна ідея цієї техніки полягає в поєднанні простих декодерів у складніші.
Ми розглянемо ще кілька функцій, які можна використати, щоб побудувати як завгодно складні декодери реальних даних, на прикладі.

## GeoJSON

Щоб потренуватися поєднувати базові декодери для розбору складних даних JSON, побудуймо декодери для розбору (підмножини) даних GeoJSON.
[GeoJSON][geojson] - це спеціалізований формат даних на основі JSON, який використовують для подання географічних обʼєктів, як-от місць, шляхів або регіонів, заданих 2D- чи 3D-географічними координатами, разом з іншими властивостями.

### Обʼєкт геометрії

Обʼєкт геометрії GeoJSON - це обʼєкт, який містить поле `type` зі значенням-рядком тексту (можливі 7 значень типу) і поле `coordinates` з географічними координатами (зібраними в структуру, що залежить від типу).
Наприклад,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

або

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Обʼєкт геометрії можна подати в Elm таким типом

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Щоб дослідити значення певного поля, можна використати `Decode.field : String -> Decoder a -> Decoder a`, який декодує значення конкретного ключа обʼєкта.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Щоб перетворити значення, успішно розібране декодером, можна використати `Decode.map : (a -> value) -> Decoder a -> Decoder value` або будь-який із його родичів, від `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` до `Decode.map8`.

У цьому випадку ми хочемо вирішити, який декодер координат використати залежно від значення в полі `type`, і для цього чудово підходить `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` та його друзі `Decode.succeed : a -> Decoder a` і `Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

Зауважмо на цьому етапі, що ми могли б використати `Decode.andThen`, щоб перевірити координати (переконатися, що координати йдуть парами або трійками, і що значення координат мають географічний сенс).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### Обʼєкт Feature

Обʼєкт Feature у GeoJSON представляє щось просторово обмежене: він має поле `type` зі значенням `"Feature"`, поле `geometry` з обʼєктом геометрії або `null`, поле `properties` з довільним обʼєктом JSON або `null` та необовʼязкове поле `id` зі значенням-рядком тексту або числом JSON.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

або

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Спершу візьмімося за поле `id`.
Якщо воно існує, то має вміщати рядки тексту або числа, тож ми можемо або ввести власний тип для значення, або завжди зберігати його як рядок тексту.

Щоб вибрати між двома можливими декодерами, можна використати `Decode.oneOf : List (Decoder a) -> Decoder a`.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Щоб виразити, що поле необовʼязкове, ми могли б використати той самий прийом

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Але натомість можна використати `Decode.maybe : Decoder a -> Decoder (Maybe a)`

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Зауважмо, що `decodeMaybeFeatureId` (або будь-який декодер, обгорнутий у `Decode.maybe`) завжди завершуватиметься успішно, бо завжди може повернутися до `Ok Nothing`, хоч декодер, який його використовує, усе одно може зазнати невдачі

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

Далі зосередьмося на полі `geometry`, яке може бути або обʼєктом геометрії, або `null`.
Ми могли б знову використати `Decode.oneOf`, але є кращий варіант: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` і `Decode.nullable` мають однакову сигнатуру, але поводяться по-різному, бо результат `OK Nothing` у `Decode.nullable` може виникнути лише з конкретного значення JSON `null`.

Нарешті, поле `properties` може містити довільний обʼєкт JSON або `null`, і для цього підходить `Decode.value : Decoder Value`.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Зауважмо, що `Value` - це непрозорий тип, тобто ми не можемо легко зазирнути в його вміст.
Щоб його використати, можна або написати для нього декодер і запустити його з `Decode.decodeValue : Decoder a -> Value -> Result Error a`, або надіслати його безпосередньо в JavaScript через порт.

Тепер ми готові розбирати обʼєкти Feature:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## Кодувальники JSON

Кодувальники дають змогу записувати валідний JSON зі значень Elm за допомогою функції `Encode.encode : Int -> Value -> String`.
Перший аргумент задає величину відступу в остаточному результаті, а другий аргумент - це значення JSON, яке треба записати.

`Value` можна або отримати з `Decode.value`, або створити одним із кодувальників:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

а також за допомогою `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Визначмо кодувальники для декодерів GeoJSON, визначених раніше

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

Загалом, добра перевірка для пари декодер-кодувальник полягає в тому, щоб переконатися, що `elmValue |> encoder |> decoder == elmValue`.

## Що ще?

Ми не розглянули кожну окрему функцію в модулях `Json`.
Деякі речі, не згадані тут, включають: декодери для перетворення масивів у `Array` або обʼєктів у `List (String, a)`, декодери для масивів з одним або кількома елементами, декодери для конкретних полів у вкладених обʼєктах JSON або конкретних елементів у масивах, як декодувати рекурсивні структури, а також різні варіанти `Error` і як їх показувати.

Інші часто використовувані пакети включають [`Json.Decode.Pipeline`][pipeline], який запроваджує зручний потік для складної структури JSON, і [`Json.Decode.Extra`][extra], який надає більше декодерів, кодувальників і допоміжних функцій.
