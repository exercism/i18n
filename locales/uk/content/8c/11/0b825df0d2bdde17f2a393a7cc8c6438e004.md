# Вступ до команд і аргументів

Цей трек не про те, як користуватися bash як інтерактивною оболонкою.
Ідеться про те, щоб навчитися писати програми мовою програмування bash.

Програма на bash, або _сценарій_, - це послідовність команд, збережена у файлі.
bash (виконуваний файл) читає цей файл і виконує команди по порядку.

## Shebang

Перший рядок сценарію зазвичай є _директивою інтерпретатора_, яку також називають _hashbang_ або _shebang_:

```bash
#!/usr/bin/env bash
```

Коли операційна система виконує небінарний файл, вона читає перший рядок.
Якщо рядок починається з `#!`, ядро використовує його, щоб визначити, який інтерпретатор має виконати файл.
`#!` має бути на самому початку файлу, без пробілів чи порожніх рядків перед ним.

Тут `env` шукає у `PATH` виконуваний файл `bash`.
Можна також побачити простіший варіант `#!/bin/bash`, у якому розташування інтерпретатора задано жорстко; форма з `env` переносніша.

~~~~exercism/note
Не варто обманюватися сценаріями чи прикладами з інтернету, які використовують `/bin/sh` як інтерпретатор.
**`sh` - це не `bash`!**
Bash є «сумісним із sh» і може запускати більшість сценаріїв `sh`, але деякі можливості bash у `sh` зламаються або поводитимуться непередбачувано.
~~~~

## Коментарі

Рядок, що починається з `#`, - це _коментар_, і bash його ігнорує.
Коментар може також стояти після команди в тому самому рядку: усе від `#` до кінця рядка ігнорується.
Коментарі існують для людей, які читають сценарій.

## Слова й аргументи

Bash читає команди зі свого вхідного потоку (зазвичай це термінал або файл).
Кожен прочитаний рядок вхідних даних вважається _командою_, тобто вказівкою, яку потрібно виконати.
(Є кілька складніших випадків, як-от команди, що займають кілька рядків; про них ітиметься пізніше.)

Bash розбиває кожну команду на **слова**, розділені пробільними символами (пробілами й табуляціями).
Перше слово задає назву _команди_, яку потрібно виконати.
Усі решта слів стають _аргументами_ цієї команди (опціями, іменами файлів тощо).

Командою може бути вбудована команда bash, як-от `echo`, або _виконувана_ програма, як-от `head`, `awk` чи `sed`.

## Команда `echo`

`echo` виводить свої аргументи, розділені одним пробілом, і завершує виведення символом нового рядка:

```bash
echo flour sugar eggs
```

виводить:

```text
flour sugar eggs
```

Кількість пробільних символів між аргументами не має значення:

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

Виклик `echo` без аргументів виводить порожній рядок.

## Опції - це просто аргументи

Багато команд приймають _опції_, які змінюють їхню поведінку.
Для bash опція не є чимось особливим: це таке саме слово, як і будь-яке інше, відокремлене від сусідів пробільними символами.
Сама команда вирішує, як тлумачити свої аргументи.
За домовленістю опції починаються з `-`.

Команда `head` виводить перші рядки файлу.
Нехай маємо файл `list.txt`:

```bash
head -n 2 list.txt
```

Bash розбиває цей рядок на чотири слова:

| Слово      | Роль                                    |
| ---------- | --------------------------------------- |
| `head`     | команда, яку треба виконати             |
| `-n`       | опція, яка каже `head` рахувати _рядки_ |
| `2`        | значення для опції `-n`                 |
| `list.txt` | файл, який треба прочитати              |

Bash передає останні три слова команді `head` без змін.
Саме `head` розуміє, що після `-n` іде число, а останнє слово - це файл.

Оскільки слова розділяють саме пробільні символи, важливо, де їх поставити.
`head -n 2` дає `head` два аргументи (`-n` і `2`), а `head -n2` - один (`-n2`).
Багато команд приймають обидві форми, але це вирішує сама команда.
Bash це байдуже: вона лише розбиває рядок на слова.

## Як брати аргументи в лапки

[Лапки][Quotes] обʼєднують слова в _один аргумент_.
Пробільні символи всередині лапок зберігаються, а самі символи лапок не є частиною аргументу:

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

Якщо аргумент, наприклад імʼя файлу, містить пробільні символи, його треба взяти в лапки:

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## Запуск сценарію

Щоб запустити сценарій, передаймо його як аргумент команді `bash`:

```bash
bash myscript
```

У такому разі рядок `#!` - лише коментар.
Ми самі кажемо операційній системі, як запускати файл.

Або позначимо файл сценарію як виконуваний і запустімо його як будь-яку іншу програму:

```bash
chmod +x myscript
./myscript
```

Тепер операційна система використовує рядок `#!`, щоб визначити, який інтерпретатор використовувати.
