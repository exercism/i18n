# Docker

Наші репрезентери розгортаються як Docker-образи.

Прочитайте [загальну інформацію про Docker в інструментарії](/docs/building/tooling/docker), щоб ознайомитися з тим, як вони працюють.

## Інтеграція

Коли ми запускаємо репрезентер, щоб створити представлення рішення, ми виконуємо команду Docker, яка має такий вигляд:

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-representer" \
        "${exercise_slug}" "/solution" "/output"
```

Як бачимо, ми передаємо три аргументи Docker-образу:

1. Слаг вправи
2. Шлях до каталогу рішення
3. Шлях до каталогу вихідних даних

## Конвенції

Усі наші репрезентери в реалізації використовують такі конвенції:

- `Dockerfile` міститься в кореневому каталозі репозиторію.
- Робочий каталог має бути `/opt/representer`.
- Точка входу - `/opt/representer/bin/run.sh`
- Скрипт `/opt/representer/bin/run.sh` приймає 3 аргументи:
  1. Слаг вправи
  2. Шлях до каталогу рішення
  3. Шлях до каталогу вихідних даних

Щоб дізнатися більше, дивіться [Інтерфейс](/docs/building/tooling/test-runners/interface).

```exercism/note
Нові репозиторії репрезентерів типово будуть використовувати ці конвенції.
```
