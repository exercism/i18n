# Тести

Запустіть тести так:

```shell
$ busted
```

Про встановлення `busted` ідеться в розділі [Установлення Lua локально][install].

[install]: https://exercism.org/docs/tracks/lua/installation

## Налагодження модульних тестів

Цей посібник покаже, як налаштувати [VSCode](https://code.visualstudio.com/) із тестовим framework [Busted](https://github.com/lunarmodules/busted) та [Local Lua Debugger](https://marketplace.visualstudio.com/items?itemName=tomblind.local-lua-debugger-vscode), щоб ми могли ставити точки зупину і в специфікації тестів, і у файлі, який вона перевіряє, а отже працювати за простою схемою [розробки через тестування](https://en.wikipedia.org/wiki/Test-driven_development). Це не канонічний підхід, існує багато методів, які можуть спрацювати, але цей принаймні допоможе нам усе запустити (зауваження: його перевірено, він працює на Windows 10 та Ubuntu 20.04).

Коли з термінологією розібралися, почнімо.

> Ці частини можна пропустити, вони лише пояснюють процес.

У **VSCode** вимкніть або видаліть усі інші розширення для налагодження **Lua** і встановіть [Local Lua Debugger](https://marketplace.visualstudio.com/items?itemName=tomblind.local-lua-debugger-vscode). Потім створіть [власну конфігурацію запуску](https://code.visualstudio.com/docs/editor/debugging#_launch-configurations) такого вигляду:

```json
{
	"name": "Busted",
	"type": "lua-local",
	"request": "launch",
	"program": {
		"command": "busted"
	},
	"cwd": "${workspaceFolder}/${relativeFileDirname}",
	"args": ["${file}"],
	"integratedTerminal": true
}
```

**Примітка:** властивість `integratedTerminal` видасть попередження `Property integratedTerminal is not allowed`, але його можна спокійно проігнорувати.

> Властивість `cwd` задає поточну робочу директорію, а це важливо для розвʼязання шляхів. Усталено **Exercism** установлює кожну вправу в окрему теку всередині теки з назвою треку. Тож у випадку **Lua** це має такий вигляд:
>
> ```
> └── Exercism/
>     ├── lua/
>     │   ├── armstrong-numbers
>     │   ├── bank-account
>     │   ├── binarysearch
>     │   └── etc...
>     └── python/
>         └── etc...
> ```
>
> Отже, коли ми відкриваємо **VSCode** з теки `/lua` ось так:
>
> > `C:\users\<username>\Exercism\lua> code .`
> >
> > або
> >
> > `/home/<username>/exercism/lua> code .`
>
> **VSCode** покаже кожну вправу в її власній теці в нашому робочому просторі. Це означає, що нам потрібно, щоб конфігурація запуску змінювала поточну робочу директорію, `cwd`, на теку кожної окремої вправи. Ми робимо це за допомогою комбінації [змінних VSCode](https://code.visualstudio.com/docs/editor/variables-reference#_settings-command-variables-and-input-variables) `${workspaceFolder}` та `${relativeFileDirname}`.
>
> Властивість `args` визначає, який аргумент слід передати **Busted**. У цьому випадку ми використовуємо змінну `${file}`, щоб указати на поточний відкритий файл.

Потім додайте ці три рядки на початок файлу тестів вправи, яку виконуємо, а саме файлу з назвою `<exercise_name>_spec.lua`:

```lua
if os.getenv("LOCAL_LUA_DEBUGGER_VSCODE") == "1" then
  require("lldebugger").start()
end
```

Тепер, коли ми хочемо запустити тести з налагоджувачем, відкриймо файл тестів, а потім запустімо конфігурацію запуску, яку щойно створили, з бічної панелі `Run and Debug` (Ctrl+Shift+D) ліворуч. Якщо файл тестів у фокусі, конфігурація запуску запустить ці тести, зупиняючись на точках зупину, і виведе результат на вкладці `DEBUG CONSOLE` у вбудованому терміналі внизу.

Гарного кодування!
