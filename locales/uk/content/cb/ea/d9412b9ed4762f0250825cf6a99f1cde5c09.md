# Контракти

Аргументи підпрограми та тип її поверненого значення кажуть, якого роду річ входить і виходить. Вони не можуть сказати, що вага має бути додатною, або що стенд ніколи не повідомляє про більший вільний запас місткості, ніж у нього є.

**Контракт** каже ці речі у самому заголовку підпрограми, де їх побачить кожен, хто її читає.

## pre

`pre` стверджує, що має бути правдою, коли викликають підпрограму. Він стоїть між типом поверненого значення і `is`.

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

Це вимога до того, хто викликає: не можна викликати цю підпрограму з відʼємним навантаженням.

## post

`post` стверджує, що буде правдою, коли підпрограма повертає результат. Усередині нього `result` - це значення, яке повертається.

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

Це обіцянка тому, хто викликає. Підпрограма, у якої є і `pre`, і `post`, - це домовленість: ми даємо їй те, що вона вимагає, і отримуємо те, що вона обіцяє.

Кілька умов поєднують за допомогою `and`, як і будь-які булеві значення (англ. Boolean):

```sather
      pre load >= 0 and load <= limit
```

## Контракти - не винятки

Породжений виняток призначений для того, що може статися. Порушений контракт означає **bug**: хтось викликав підпрограму неправильно, або підпрограма зробила не те, що обіцяла.

Тож порушений контракт не породжує нічого, що можна перехопити. Коли перевірку контрактів увімкнено, програма зупиняється і виводить, яка це підпрограма і яка умова. Коли її вимкнено, умову навіть не перевіряють, і програма виконується далі, аж доки не натрапить на якусь нісенітницю.

Тому контракт - це твердження про правильність, а не спосіб обробки некоректних вхідних даних. Якщо некоректні вхідні дані передбачені, перевірмо їх і зробимо `raise`. Якщо некоректні вхідні дані означають, що помиляється той, хто викликає, скажімо це за допомогою `pre`.

## Як увімкнути перевірку

Цей Sather перевіряє контракти, коли компілятору передають `-chk`:

```
sacomp -chk mine.sa -main MAIN -o mine
```

Без неї `pre` і `post` - це лише документація, яку компілятор прочитав і визнав коректно побудованою, і більше нічого. Тести для цієї вправи зібрано без `-chk`, тож вони не перехоплять порушений контракт за нас; вони перевіряють, що підпрограми роблять усе правильно, коли їх використовують належно.
