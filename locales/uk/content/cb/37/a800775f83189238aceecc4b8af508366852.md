# Докладніше

Вбудовані типи Swift мають низку проблем, коли їх використовують для моделювання чогось із помірною кількістю можливих станів чи значень, як-от 63 офіційні коди стану HTTP або 8 кнопок контролера NES.

Наприклад, можна спробувати використати наявні типи, як-от рядки тексту (англ. string) чи цілі числа, щоб подати їхні значення, подібно до того, як це зробили з кодами стану HTTP, але це призводить до кількох різних проблем. Одна з проблем полягає в тому, що хоча компʼютер може й нормально обробити припустимі значення, як-от 103, 226 і 505, сама програма також мусить постійно перевіряти, чи не отримала вона неприпустимих значень, як-от 213, 427, 512 чи 601. Водночас _програміст_ відповідає за те, щоб під час розгляду коду, на який слід відреагувати, перевірялося кожне припустиме значення, тож жоден припустимий код не залишиться поза увагою.

Ще одна проблема в тому, що втрачається смислове значення. Людині, яка читає (або пише) програму, буває важко згадати, що значення 103, 226 і 505 означають «Early Hints», «IM Used» та «HTTP Version Not Supported». Так само можна було б змоделювати перемикач за допомогою `Bool`, адже в обох лише два стани, але що для перемикача означає `true`: що він розімкнений чи що замкнений?

Можна було б зменшити цю проблему, використавши рядок тексту для подання текстової версії коду стану чи стану перемикача, але це може спричинити помилки, коли хтось намагається порівняти вхідний код стану з «HTTP Version not Supoorted» замість очікуваного «HTTP Version not Supported». Такі помилки трапляються часто, і їх важко виявити.

Як підхід до розвʼязання цієї проблеми Swift, як і багато сучасних мов, пропонує мовну можливість, яку називає [_переліками_][enumerations], або скорочено _enum_.

Переліки в Swift - це механізм створення нових типів, які містять скінченну кількість іменованих значень, що можуть нести додаткову повʼязану інформацію і які можна перевірити під час компіляції на повноту та правильність використання. Крім того, переліки можуть мати прикріплені до них властивості та методи, що надають додаткову інформацію й функціональність залежно від поточного значення переліку.

## Визначення переліків

Найпростіші переліки визначають у Swift ключовим словом `enum`, після якого йде назва типу, а потім тіло переліку у фігурних дужках, що містить список значень переліку, які вводять ключовим словом `case`. Дотримуючись [посібника зі стилю Swift][api-design-guidelines], назва типу має бути в UpperCamelCase, а значення - у lowerCamelCase.

```swift
enum NESButton {
  case up
  case down
  case left
  case right
  case a
  case b
  case select
  case start
}
```

Для стислості кілька варіантів також можна записати в один рядок, розділивши комами, з одним ключовим словом `case`.

```swift
enum NESButton {
  case up, down, left, right, a, b, select, start
}
```

Це визначає новий тип із назвою `NESButton` з можливими значеннями `up`, `down`, `left`, `right`, `a`, `b`, `select` і `start`. Посилатися на ці значення можна, записавши після назви типу крапку (`.`) і значення. Там, де назву типу можна вивести, достатньо лише крапки й значення. Далі ці значення можна використовувати, як і будь-які інші значення в Swift.

```swift
var lastPressed = NESButton.up

// Now that the type of lastPressed is set as NESButton
lastPressed = .down

let konamiCode = [NESButton.up, .up, .down, .down, .left, .right, .left, .right, .b, .a]
```

Зауважмо, що оскільки всі елементи масиву мають бути одного типу, назву типу достатньо вказати лише для одного з елементів, а решту можна подати самими значеннями. Назва типу не знадобилася б для жодного з них, якби константі дали належну анотацію типу, напр. `let konamiCode: [NESButton] = …`.

## Переліки та інструкції `switch`

Переліки часто використовують [разом з інструкціями `switch`][enums-and-switches], які визначають дію залежно від значення переліку.

```swift
lastPressed = .left
switch lastPressed {
case .up: print("You pressed the UP button")
case .down: print("You pressed the DOWN button")
case .left: print("You pressed the LEFT button")
case .right: print("You pressed the RIGHT button")
case .a: print("You pressed the A button")
case .b: print("You pressed the B button")
case .select: print("You pressed the SELECT button")
case .start: print("You pressed the START button")
}

// prints "You pressed the LEFT button"
```

Оскільки інструкції `switch` мають бути вичерпними, компілятор попередить, якщо представлено не всі варіанти.

```swift
switch lastPressed {
case .up, .down, .left, .right:
  print("You pressed a direction button.")
}
// Error: Switch must be exhaustive
```

Це особливо корисно, коли в процесі розвитку програми до переліків додають нові варіанти. Компілятор може вказати всі місця, де невичерпні `switch` треба оновити, щоб урахувати новий варіант.

Зауважмо, що цю помилку можна виправити, використавши в `switch` варіант `default`.

```swift
lastPressed = .select
switch lastPressed {
case .up, .down, .left, .right:
  print("You pressed a direction button.")
default:
  print("You pressed a non-direction button.")
}
// prints: "You pressed a non-directional button."
```

Однак це автоматично робить будь-який `switch` вичерпним, тож якби ми додали до переліку, скажімо, діагональні варіанти напрямку, як-от `.upAndLeft`, ми б не знали, що той `switch` треба оновити, і нам хибно повідомили б, що натиснуто кнопку, яка не задає напрямку. Щоб цього не сталося, краще явно перелічити всі варіанти, де це можливо.

```swift
lastPressed = .select
switch lastPressed {
case .up, .down, .left, .right:
  print("You pressed a direction button.")
case .a, .b, .select, .start:
  print("You pressed a non-direction button.")
}
// prints: "You pressed a non-directional button."
```

Оскільки компілятор знає всі можливі значення переліку, він також може виявляти помилки, як-от одруківки, що закрадаються в програми, де для подання значень використовують рядки тексту.

```swift
lastPressed = .selcet
// Error: Type 'NESButton' has no member 'selcet'
```

## Методи

Як і інші типи в Swift, переліки можуть містити методи, які дають змогу переліку надавати функціональність залежно від свого поточного значення.

Методи подібні до функцій, лише вони визначені всередині тіла переліку й привʼязані до поточного значення переліку. До них звертаються через _точкову нотацію_: після назви значення переліку ставлять крапку (`.`), а далі назву методу та його параметри.

Усередині методу на значення переліку можна посилатися як на `self`, а в сигнатурі типу, якщо приймають параметр або повертають значення переліку, на сам тип можна посилатися як на `Self`.

### Ініціалізатори

Ініціалізатори - це особливі методи, які використовують, щоб створити значення переліку. Їхнє визначення дуже схоже на визначення методу, лише немає ключового слова `func`, немає типу повернення, назва має бути `init`, а ініціалізатор _мусить_ присвоїти `self` значення переліку. Ініціалізатори викликають або через точкову нотацію, або передавши параметри ініціалізатора назві переліку.

Переліки можуть також мати ініціалізатори, що можуть зазнати невдачі й повертають необовʼязкові значення переліку. Їх використовують, коли за вхідними даними ініціалізатора може не існувати припустимого значення для ініціалізації, і тоді `self` можна присвоїти `nil`. У таких випадках назву ініціалізатора записують як `init?`, хоча під час виклику ініціалізатора знак питання опускають.

```swift
enum Coin {
  case heads
  case tails

  init(_ i: Int) {
    if i.isMultiple(of: 2) {
      self = .heads
    } else {
      self = .tails
    }
  }

  func flip() -> Self {
    switch self {
    case .heads: return .tails
    case .tails: return .heads
    }
  }
}

let tails = Coin.init(13)
// .tails
let heads = Coin(0)
// .heads
let anotherTails = heads.flip()
// .tails
```

### Сирі значення

Переліки також можуть нести із собою внутрішнє значення, відоме як [_сире значення_][raw-values]. Усі сирі значення мають бути одного типу, який оголошують у визначенні переліку. Тож ми могли б, наприклад, присвоїти нашому переліку `NESButton` значення типу `Character`, змінивши визначення:

```swift
enum NESButton: Character {
  case up = "⬆️"
  case down = "⬇️"
  case left = "⬅️"
  case right = "➡️"
  case a = "🅰️"
  case b = "🅱️"
  case select = "✅"
  case start = "🚦"
}
```

Тут `: Character` повідомляє компілятору, що сирі значення матимуть тип `Character`, а присвоєння сирого значення йде після кожного варіанта.

До сирих значень можна дістатися через автоматично згенеровану властивість `rawValue` кожного варіанта.

```swift
NESButton.left.rawValue
// => "⬅️"
NESButton.b.rawValue
// => "🅱️"
```

Сирі значення також можна використовувати для ініціалізації значень типу переліку. Зауважмо, що повернене значення є необовʼязковим, оскільки може бути передано неприпустиме сире значення.

```swift
let upButton = NESButton.init(rawValue: "⬆️")
// => Optional(.up)
let invalid = NESButton.init(rawValue: "🙄")
// => nil
```

Swift може неявно присвоювати сирі значення для типів `String` і `Int`. Якщо вказано тип сирого значення `String`, сире значення неявно присвоюється назві варіанта як рядок тексту, якщо тільки неявне значення не перекрито явним присвоєнням.

Якщо вказано тип сирого значення `Int`, сире значення неявно присвоюється числу на 1 більшому за сире значення попереднього варіанта, якщо його не перекрито явним присвоєнням. Типове сире значення для першого варіанта дорівнює 0, якщо не вказано іншого.

```swift
enum Coin: String {
  case heads
  case tails = "eagle"
}

Coin.head.rawValue
// => "heads"
Coin.tails.rawValue
// => "eagle"

enum Dwarf: Int {
  case grumpy, sleepy, sneezy, happy = 8, bashful, dopey, doc
}

Dwarf.grumpy.rawValue
// => 0
Dwarf.sneezy.rawValue
// => 2
Dwarf.happy.rawValue
// => 8
Dwarf.bashful.rawValue
// => 9
```

### Повʼязані значення

Переліки в Swift можуть також нести ще один тип інформації, відомий як [_повʼязані значення_][associated-values]. Із повʼязаними значеннями кожен варіант переліку може мати значення іншого типу, яке можна нести разом зі значенням переліку. Типи повʼязаних значень вказують в оголошенні переліку. Ці значення потім можна видобути й використати через зіставлення зі зразком.

```swift
enum Suit: Character {
  case diamonds = "♦️", clubs = "♣️", hearts = "♥️", spades = "♠️"

  func print() {
    switch self {
    case .ace(let suit): print("A\(suit.rawValue)")
    case .king(let suit): print("K\(suit.rawValue)")
    case .queen(let suit): print("Q\(suit.rawValue)")
    case .jack(let suit): print("J\(suit.rawValue)")
    case let .number(suit, value): print("\(value)\(suit.rawValue)")
    }
  }
}

enum Card {
  case ace(Suit), king(Suit), queen(Suit), jack(Suit)
  case number(Suit, Int)
}

let aceOfSpades = Card.ace(.spades)
let twoOfHearts = Card.number(.hearts, 2)

aceOfSpades.print()
// prints "A♠️"

twoOfHearts.print()
// prints "2♥️"
```

Зауважмо, що переліки можуть мати або сирі значення, або повʼязані значення, або ж ні того, ні того, але не можуть мати обидва.

### Рекурсивні переліки

Як видно з попереднього прикладу, повʼязаний тип варіанта переліку може бути будь-якого типу, зокрема й типу переліку. У деяких випадках може знадобитися зробити типом повʼязаного значення тип переліку, який містить цей варіант. У Swift це можна зробити, написавши ключове слово `indirect` перед кожним варіантом, що використовує ці [рекурсивні повʼязані типи][recursive-enumerations], або поставивши `indirect` перед ключовим словом `enum`, щоб зробити всі варіанти переліку непрямими.

```swift
enum BinaryTree {
  case leaf(value: Int)
  indirect case node(left: BinaryTree, value: Int, right: BinaryTree)
}

enum BinaryTree {
  case leaf(value: Int)
  indirect case node(left: BinaryTree, value: Int, right: BinaryTree)
}

let tree: BinaryTree = .node(left: .leaf(value: 1), value: 3, right: .node(left: .leaf(value: 5), value: 6, right: .leaf(value: 9)))
```
