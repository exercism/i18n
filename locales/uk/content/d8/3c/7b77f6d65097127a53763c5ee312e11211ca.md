# Вступ

## Коментарі

Common Lisp дозволяє програмісту писати «коментарі», які компʼютер ігнорує. Однорядкові коментарі починаються з однієї або кількох крапок з комою (`;`), і час від часу можна побачити таке:

```lisp
(code...) ; => value
```

Тут коментар ужито, щоб позначити, яке значення повертає Common Lisp після виконання коду в цьому рядку.

Ідіоматично вживати одну крапку з комою для короткого коментаря в кінці рядка, дві - для довшого коментаря над ділянкою коду, три - для довгого коментаря, що описує щось, наприклад функцію, і чотири - для коментаря на кшталт заголовка на початку вихідного файлу.

## Конси

Усі обʼєкти Common Lisp є або «атомами» (поодинокими, неподільними значеннями), або «консами» (утвореними функцією-конструктором «cons»).
Cons складається з двох частин: першого елемента та решти елементів.
З історичних причин ці дві частини називають `car` і `cdr`.
Коли ці конси обчислюють як код, перший елемент (`car`) представляє функцію, яку викликають, а решта елементів
(`cdr`) представляють аргументи цієї функції:

```lisp
(<function> <arg1> <arg2> ... <argN>)
; ^ car ^  |        ^ cdr ^
```

## Вирази

Увесь код Common Lisp складається з S-виразів (символьних виразів). Їх скорочено називають sexpr. Кожен sexpr є або атомом, або консом. Коли S-вирази обчислюються, вони автоматично повертають деяке значення, яке заступає місце виразу. Коли ми пишемо власні функції (за допомогою `defun`), останнє значення в тілі `defun` повертається автоматично:

```lisp
;; Defining a new function
(defun gimme-foo () 'foo)
;; Calling the function as an S-Expression
(gimme-foo) ; => FOO
```

## Символи

Символи в Common Lisp - це особливі значення, які можуть указувати на інші значення або, у випадку _ключових слів_, на самих себе.
Коли Lisp обчислює символи, він замінює їх на значення, на які вони вказують:

```lisp
foo  ; => <whatever-foo-points-to>
:foo ; => :FOO
```

Зауважмо, що ключові слова позначено провідною двокрапкою (`:`).

Цитування, тобто додавання `'` перед S-виразом, вказує Lisp не обчислювати цей вираз.
Зацитувавши `'foo` у нашому прикладі з `defun`, ми уникнули того, що Lisp намагався б знайти (і не знайшов) те, на що мав указувати `FOO`; натомість повернулося саме значення `FOO`.
Якщо `FOO` ніде в нашій програмі не визначено:

```lisp
foo  ; => <ERROR! Lisp doesn't know what foo points to!>
'foo ; => FOO
```

Поки що це можна розглядати просто як спосіб повертати символи з функції, але ми повернемося до цитування і глибше дослідимо його наслідки в майбутніх концептуальних вправах.
