# Тести

Запуск тестів передбачає виконання `cmake -G`, а потім команди збірки, відповідної для платформи, якою ми користуємося.
Детальні інструкції про те, як це зробити, можна знайти на сторінці [Запуск тестів][cpp-tests-instructions] для C++ на exercism.org.

## Проходження тестів

Коли ми починаємо нову вправу локально, файли налаштовані так, що виконується лише перший тест.
Зробімо так, щоб цей перший тест компілювався, компонувався і проходив, дотримуючись [трьох правил розробки через тестування][three-laws-of-tdd].
Створімо рівно стільки структури (оголосивши простори імен, функції, класи тощо), щоб прибрати помилки компілятора й домогтися, щоб тест не проходив.
Потім напишімо рівно стільки коду, щоб тест почав проходити.
Коли це зроблено, розкоментуймо наступний тест, перемістивши рядок `if defined(EXERCISM_RUN_ALL_TESTS)` за наступний тест.

Дивімося на приклад нижче з вправи Bob (файл `bob_test.cpp`, рядок 15):

```diff
-#if defined(EXERCISM_RUN_ALL_TESTS)
TEST_CASE("shouting")
{
    REQUIRE("Whoa, chill out!" == bob::hey("WATCH OUT!"));
}
+#if defined(EXERCISM_RUN_ALL_TESTS)
```

Переміщення цього рядка за наступний тест може спричинити помилки компіляції, адже можуть викликатися нові конструкції, які ми ще не оголосили чи не визначили.
Знову ж таки, виправмо помилки компіляції мінімально, щоб отримати тест, який не проходить, потім мінімально змінімо код, щоб тест проходив, відрефакторімо нашу реалізацію задля читабельності й виразності та перейдімо до наступного тесту.

Намагаймося використовувати стандартні засоби C++17, а не писати власні низькорівневі алгоритми чи засоби вручну.
