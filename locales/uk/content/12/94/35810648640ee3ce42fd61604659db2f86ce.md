# Вступ

Усі помилки в Elixir реалізують _поведінку винятків_. Так само, як і _поведінка доступу_, _поведінка винятків_ визначає колбеки, які модуль має реалізувати, щоб виконати програмний контракт поведінки. Щойно помилку визначено, вона має такі властивості:

- Назва модуля визначає назву помилки.
- Модуль визначає структуру помилки.
- Структура матиме поле `:message`.
- Модуль можна використовувати з `raise/1` та `raise/2`, щоб спричинити потрібну помилку

Поведінка винятків також визначає два колбеки: `message/1` та `exception/1`. Якщо їх не реалізовано, будуть використовуватися типові реалізації. `message/1` перетворює структуру помилки на читабельне повідомлення, коли його викликають разом із `raise`. `exception/1` дає змогу додати до повідомлення додатковий контекст, коли його викликають разом із `raise/2`

## Визначення винятку

Щоб визначити виняток із модуля помилки, скористаймося макросом `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

## Використання винятків

Визначені помилки можна використовувати так само, як вбудовану помилку, за допомогою `raise/1` або `raise/2`.

- `raise/1` спричиняє конкретну помилку за назвою її модуля, а якщо аргумент є рядком тексту (англ. string), то спричинить `RuntimeError` з цим рядком як повідомленням.
- `raise/2` спричиняє конкретну помилку за назвою її модуля та приймає аргумент з атрибутами, який використовується, щоб отримати помилку з відповідним повідомленням.
