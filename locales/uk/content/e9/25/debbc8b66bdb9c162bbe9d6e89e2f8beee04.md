# Умовні конструкції

```sather
   if score >= 5 then
      return "Recalled";
   else
      return "Thank you";
   end;
```

Умова між `if` і `then` має бути `BOOL`. Sather не прийме там число, тому немає звички, як у C, вважати нуль неправдою.

## Будова

```sather
   if first_question then
      ...
   elsif second_question then
      ...
   elsif third_question then
      ...
   else
      ...
   end;
```

Умови перевіряються згори вниз, і перемагає перша, яка виявиться правдою. Усе, що нижче, пропускається без перевірки. Ось чому ланцюжок має йти від найконкретнішої умови до найзагальнішої: якщо поставити `score >= 5` вище за `score >= 8`, до другої умови ніколи не дійде.

`else` необовʼязковий. `elsif` можна повторювати стільки разів, скільки потрібно.

## Умовні конструкції належать до інструкцій, а не до значень

`if` сам не створює значення, тож так у Sather не пишуть:

```sather
   -- wrong
   grade := if score > 5 then "pass" else "fail" end;
```

Можна або повернути значення зсередини кожної гілки, або присвоїти його змінній у кожній гілці.

## Коли не варто використовувати умовну конструкцію

Підпрограма, яка відповідає на запитання, повинна повертати саму умову:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;

   -- not this
   old_enough(age : INT) : BOOL is
      if age >= 13 then return true; else return false; end;
   end;
```

Другий варіант не каже нічого, чого не каже перший, але втричі довший.

## Вкладеність

Одна умовна конструкція `if` може містити іншу. Часто це не потрібно: дві умови, які обидві мають виконуватися, можна натомість зʼєднати оператором `and`, і це читається краще.

```sather
   if score >= 8 and sings then
      return "Lead";
   end;
```
