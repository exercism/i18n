# Вступ

Час перейти до однієї з ключових парадигм C++: обʼєктно-орієнтованого програмування (ООП).
ООП будується навколо `classes`, тобто визначених користувачем типів даних із власним набором повʼязаних функцій.
Почнімо з основ, а складніші теми розглянемо далі по дереву силабусу.

## Члени

Класи можуть мати **змінні-члени** та **функції-члени**.
Доступ до них отримують через оператор **вибору члена** `.`.
Як і змінні поза `classes`, змінні-члени варто ініціалізувати значенням під час оголошення.
Тоді це значення стане типовим для новостворених обʼєктів цього класу.

## Інкапсуляція та приховування інформації

Класи дають змогу обмежити доступ до своїх членів.
Існують два базові випадки: `private` і `public`.
Члени `private` недоступні ззовні класу.
Члени `public` можна викликати вільно.
Усі члени типово оголошуються як `private`, і їх потрібно явно позначити, щоб ними можна було користуватися поза класом.

## Базовий приклад

Визначення нового `class` наведено в прикладі нижче.
Звернімо увагу на `;` після визначення.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

Усередині класу ми маємо доступ до всіх змінних.
Погляньмо на `damage` усередині функції `cast_spell`.
Поза класом ми не можемо читати або змінювати члени `private`:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## Конструктори

Конструктори дають змогу присвоювати значення змінним-членам під час створення обʼєкта.
Вони мають таку саму назву, як і `class`, і не мають типу поверненого значення.
Клас може мати кілька конструкторів.
Це стає в пригоді, коли не завжди потрібно задавати всі змінні.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

Тема конструкторів велика й має багато нюансів.
Якщо ми явно не визначаємо `constructor` для свого `class`, тоді (і тільки тоді) компілятор зробить це за нас.
Саме це сталося в першому прикладі вище.
Обʼєкт _silverhand_ створюється викликом типового конструктора, без жодних аргументів.
Усі змінні отримують значення, указане у визначенні класу.
Якби ми не вказали жодних значень у тому визначенні, змінні могли б залишитися неініціалізованими, що могло б мати непередбачені наслідки.

## Структури

Структури походять від початкових коренів мови в C і такі ж давні, як сам C++.
По суті, вони те саме, що й `classes`, з однією важливою відмінністю.
Типово все в `class` оголошується як `private`.
Структури ж, навпаки, залишаються `public`, доки не визначено інакше.
За усталеною практикою ключове слово `struct` часто використовують для **структур лише з даними**.
Ключове слово `class` краще підходить для обʼєктів, яким потрібно гарантувати певні властивості.
Такою інваріантою могло б бути те, що `damage` вашого `class` `Wizzard` не може стати відʼємним.
Змінна `damage` приватна, тож будь-яка функція, яка її змінює, гарантувала б збереження інваріанти.
