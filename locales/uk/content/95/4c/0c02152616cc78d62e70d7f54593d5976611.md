# Вступ

Кортежі можуть розширювати інші кортежі. `TUPLE: child < parent slots ;`
оголошує клас, чиї екземпляри також є екземплярами `parent`.
Вони отримують слоти батька на додачу до власних, і методи доступу
батька теж працюють на них, наче їх визначили на нащадку.

```factor
USING: accessors ;

TUPLE: animal name age ;
TUPLE: dog < animal breed ;

"Rex" 4 "labrador" dog boa .
! => T{ dog { name "Rex" } { age 4 } { breed "labrador" } }

"Rex" 4 "labrador" dog boa name>> .   ! => "Rex"   (inherited accessor)
```

## Порядок слотів у `boa`

Конструктор `boa` приймає слоти в *порядку оголошення, спочатку батьки*.
Для `dog` вище:

```
dog boa ( name age breed -- dog )
```

Онук `puppy < dog `, що додає `weeks`, матиме такий вигляд:

```
puppy boa ( name age breed weeks -- puppy )
```

## Ієрархія предикатів

Кожне оголошення `TUPLE:` породжує предикат (`name?`).
З успадкуванням предикати вкладаються одне в одне: кожен нащадок
задовольняє предикати своїх предків:

```factor
"Rex" 4 "labrador" dog boa
dup dog? .        ! => t
dup animal? .     ! => t
```

Зворотне неправильне: `animal`, який не є `dog`, не задовольняє
`dog?`.

## Забігаючи наперед

Узагальнені методи (`M:`, про які йдеться в [`generics`][generics]),
теж диспетчеризуються вгору по ієрархії: метод на `animal` спрацьовує для
кожного нащадка, якщо конкретніше перевизначення не має
пріоритету. Ми побачимо це в `boatswains-bilge` одразу
після цієї вправи.

[generics]: https://docs.factorcode.org/content/article-generic.html
