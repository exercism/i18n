# Вступ

Асемблерний код, написаний вручну, сповнений повторень.
Той самий короткий набір інструкцій трапляється знову й знову, майже без варіацій, а абстракцій, які могли б скоротити рутинний код, обмаль.
До того ж, пишучи асемблерним кодом, доводиться керувати значеннями без очевидної семантики.
Тут немає іменованих параметрів, і більшість деталей того, як працює машина, програміст мусить опрацьовувати вручну.

NASM, асемблер, який використовує трек, пропонує інструменти, здатні допомогти програмісту з обома проблемами.
Ці інструменти працюють під час _асемблювання_, ще до того, як будь-яка інструкція потрапить до процесора.
Вони підказують асемблеру, як переписати вихідний текст, ще до того, як його перекладено в машинний код.

Найважливіші з цих інструментів, **макроси**, можна уявити як рецепт для асемблера.
Вони розгортаються в тому місці, де їх використано, наче цей код було написано там вручну.

Макрос може приймати кілька літеральних токенів як параметри, завдяки чому його можна використовувати повторно в різних контекстах.
Однак це не функції: тут немає ні `call`, ні `ret`, ні передачі керування в інше місце коду.

## Однорядкові макроси

Найпростіше визначення дає імʼя значенню або короткому виразу за допомогою `%define`:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Кожне наступне входження `WIDTH` замінюється на `8` ще до асемблювання.
Заміна є текстовою, тож імʼя підставляється всюди, де воно трапляється, чи то в операнді, чи всередині іншого визначення.

~~~~exercism/note
Для числових _констант_ краще використовувати `equ`, а не `%define`.

Однорядковий макрос, оголошений через `%define`, розгортається лише тоді, коли його використано, і його можна переприсвоїти або зняти визначення.
Константа `equ`, навпаки, обчислюється в місці визначення і вже ніколи не змінюється.
~~~~

`%define` може також приймати _іменовані_ параметри, поводячись як маленька вбудована функція:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Беріть у дужки і все тіло, і кожен параметр.
Якщо написати `%define square(x) x*x`, виклик `square(1+1)` розгорнеться в `1+1*1+1`, тобто в `3`.
Якщо ж записати `%define square(x) ((x)*(x))`, той самий виклик розгорнеться в `((1+1)*(1+1))`, тобто в `4`.
~~~~

Імена, визначені через `%define`, чутливі до регістру.
Варіант `%idefine` робить імʼя нечутливим до регістру, якщо це потрібно.

Однорядкові макроси допомагають надати сенсу різним частинам коду.
Якщо користуватися ними обережно, це покращує читабельність і зменшує ймовірність одруківок.
Наприклад, регістр, який усередині функції має особливе призначення, можна назвати за цим призначенням:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Багаторядкові макроси

Цілу послідовність коду, з будь-якою кількістю рядків, записують за допомогою `%macro` і закривають `%endmacro`.
Число після назви вказує, скільки аргументів приймає макрос; воно може бути нулем.
Аргументи передають через кому (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Аргументи в багаторядкових макросах не мають імен.
До них звертаються як `%1`, `%2` і так далі, у тому порядку, у якому їх передано:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Зауважмо, що аргументи мають бути синтаксично придатні для операцій, які виконуються в тілі макроса.
Тут і `mult_two eax, ecx`, і `mult_two r8, r9` асемблюються, а от `mult_two eax, cl` ні, бо `imul eax, cl` не визначено.

### Мітки всередині макроса

Макрос, який визначає звичайну мітку, ламається, щойно його використано двічі, бо тоді й мітку буде визначено двічі.
Щоб використовувати мітки в макросі, який може викликатися більше ніж один раз, перед такою міткою треба поставити `%%`.
Це вказує асемблеру давати цій мітці інше, унікальне імʼя під час кожного розгортання:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Повторення під час асемблювання

Повторити однорядковий блок коду можна за допомогою `times`.
Це особливо зручно, коли треба оголосити повторювані значення в памʼяті:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Для повторення багаторядкового коду натомість можна скористатися `%rep`:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Зауважмо, що кількість повторень указують одразу після `%rep`, а повторюваний блок закриває `%endrep`.

Усередині блоку `%rep` часто використовують лічильник часу асемблювання, так само як цикл під час виконання використовує лічильник.
Цілу константу часу асемблювання можна оголосити через `equ`, але для цілих _змінних_ часу асемблювання ми натомість використовуємо `%assign`.
На відміну від `%define`, `%assign` одразу обчислюється до числа, і його можна переприсвоїти:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Після роботи препроцесора цикл зникає, і залишаються чотири інструкції `add` із уже вбудованими безпосередніми значеннями `0`, `1`, `2` і `3`.
Це розгортання циклу, яке виконує асемблер: ані регістра-лічильника, ані переходу, лише лінійний код.

## Умовне асемблювання

Препроцесор має в розпорядженні чимало умовних конструкцій.
Вони вибирають один із кількох шляхів і розгортають своє тіло на місці, але лише тоді, коли їхня умова істинна.

`%if` ... `%elif` ... `%else` ... `%endif` вибирають гілку за числовою перевіркою:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## Розділення на файли

Макроси часто тримають в окремому файлі й долучають до кожного джерела, якому вони потрібні, за допомогою `%include`:

```x86asm
%include "patterns.mac"
```

Названий файл вставляється дослівно в це місце ще до асемблювання, точно так, ніби його вміст набрали просто там.
Так визначення залишаються в одному місці, і кілька вихідних файлів можуть ними користуватися.

Якщо файл макросів може асемблюватися окремо, він повинен мати розширення `.asm`.
Зауважмо, що макроси не мають зовнішніх звʼязків.
Навіть якщо файл макросів асемблюється, його макроси видимі лише іншому файлу, який долучає його через `%include`.

В іншому разі файл, призначений лише для `%include`, може мати будь-яке розширення.
Зазвичай використовують розширення `.asm` або `.mac`.
