# Детальніше

`<dlist>` (у [`dlists`][dlists]) створює новий двобічно звʼязаний список. Операції живуть у [`deques`][deques] і диспетчеризуються за протоколом дека, тож інші контейнери, передусім `<dlist>`, можуть їх реалізовувати.

| слово            | дія                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )` - новий порожній дек  |
| `push-front`    | `( elt deque -- )` - додати на початок |
| `push-back`     | `( elt deque -- )` - додати в кінець  |
| `pop-front`     | `( deque -- elt )` - вилучити з початку |
| `pop-back`      | `( deque -- elt )` - вилучити з кінця  |
| `peek-front`    | `( deque -- elt )` - прочитати початок, не вилучаючи |
| `peek-back`     | `( deque -- elt )` - прочитати кінець, не вилучаючи  |
| `deque-empty?`  | `( deque -- ? )` - чи порожній дек? |
| `dlist-length`  | `( dlist -- n )` - кількість елементів |

Усі операції push/pop змінюють дек на місці. Передати дек у процедуру, а потім знову прочитати з нього - це звична практика.

## Стек проти черги

Дві звичні схеми диспетчеризації:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

Вектор із `push` і `pop` (з `mutation`) - правильний вибір, коли потрібен лише порядок LIFO, адже `<dlist>` тягне за собою накладні витрати звʼязаного списку. До `<dlist>` варто звертатися, коли потрібна O(1) на *обох* кінцях, а це майже завжди черга FIFO.

## Схема пошуку в ширину (BFS)

Пошук у ширину - канонічний приклад використання FIFO:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

Дек несе фронт пошуку; хеш-множина відповідає за усунення дублікатів. Замінімо `pop-front` на `pop-back` - і та сама схема стане пошуком у глибину.

## `MEMO:` - автоматичне кешування

Іноді пошук для кожного вузла, до якого звертається BFS, обходиться дорого. Factor надає [`MEMO:`][memo-decl], заміну для `:`, яка автоматично кешує результат слова, використовуючи його вхідні дані як ключ:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

Слово `MEMO:` виконує своє тіло першого разу, коли зустрічається кожне вхідне значення, а далі повертає кешований результат. Кеш живе протягом усього часу існування образу; жодного витіснення за часом чи розміром немає. Використовуймо його для чистих функцій, вхідні дані яких походять із скінченної, осяжної множини.
