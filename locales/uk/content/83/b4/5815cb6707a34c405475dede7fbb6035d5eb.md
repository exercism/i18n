# Докладніше

Скалярний код покладається на прапорці, які встановлюють різні інструкції, щоб розгалужуватися у відповідь на певну умову.
Упаковані значення, однак, представляють не одне, а багато значень паралельно.
Одна умова може бути хибною для однієї доріжки й істинною для іншої.

Саме тому код SIMD за замовчуванням [не має розгалужень][branchless-code].

Замість того щоб покладатися на прапорці, упаковані порівняння зазвичай утворюють **маску** в операнді призначення.
Для кожної доріжки порівняння заповнює всю доріжку одиницями, коли воно істинне, і нулями, коли воно хибне.
Прочитана як ціле число зі знаком, істинна доріжка дорівнює `-1`, а хибна - `0`.

Цю маску потім можна скомпонувати з [порозрядними операціями][simd-bitwise], щоб відфільтрувати конкретні доріжки.

## Упаковані порівняння

Скалярний `cmp` є загальним у тому сенсі, що його використовують, щоб установити різні прапорці водночас.
Інша інструкція потім може спожити ці прапорці, щоб або розгалузитися, або виконати обчислення.

Однак, оскільки упаковане порівняння і перевіряє умову, і обчислює маску, воно не є загальним.
Порівнянню треба задати точну умову, яку перевіряють.

Зробити це можна двома способами:

- Цілочисельні порівняння отримують умову як суфікс: `eq` для рівності та `gt` для «більше ніж».
  Інші варіанти будують, компонуючи результат одного з них.
- Порівняння чисел з плаваючою комою отримують умову, закодовану в безпосередньому операнді.
  Різні значення цього безпосереднього операнда відповідають різним умовам, які перевіряють.

Окрім використання конкретного умовного суфікса в цілочисельних порівняннях, синтаксис дотримується тієї самої структури, яку ми вже бачили:

- Для цілих чисел: `p` + `cmp` + умова + розмір (`b`, `w`, `d` або `q`).
- Для чисел з плаваючою комою: `cmp` + `p` + розмір (`s` або `d`).
  Умову передають у безпосередньому операнді як додатковий операнд.

### Цілочисельні порівняння

Як уже згадано, існують лише цілочисельні порівняння для рівності та «більше ніж»:

| інструкція                                | опис                                      |
|--------------------------------------------|-------------------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | рівність для кожної доріжки               |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | **знакове** «більше ніж» для кожної доріжки |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

Щоб утворити порівняння «менше ніж», використаймо `gt` з переставленими операндами: `a < b` == `b > a`.

Зауважмо, що порівняння **знакове**.
Щоб виконати беззнакове порівняння, перевернімо старший біт обох операндів.
Це можна зробити за допомогою XOR із маскою, у якій установлено лише старший біт.

~~~~exercism/note
Дві корисні ідіоми:

1. XOR регістра із самим собою, щоб отримати всі нулі.
2. Порівняння регістра із самим собою, щоб отримати всі одиниці.

Наприклад:

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

Маски з усіх нулів і з усіх одиниць уживають, щоб закодувати «хибно всюди» та «істинно всюди» відповідно.
Їх також можна використати, щоб представити упакований `0` або упакований `-1`, які є поширеними сторожовими значеннями.
Наприклад, NUL, який позначає кінець рядка тексту (англ. string), це `0`.
~~~~

### Порівняння чисел з плаваючою комою

Доріжки чисел з плаваючою комою мають іншу форму: одна інструкція, `cmpps` (і `cmppd` для 64-бітних доріжок), з умовою як безпосереднім операндом:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

У NASM також є псевдооперації, які відображаються на правильний безпосередній операнд і які легше запамʼятати.
У всьому наведеному нижче `x` у `px` може бути `s` (32-бітні числа з плаваючою комою) або `d` (64-бітні числа з плаваючою комою):

| псевдооперація | безпосередній операнд | порівняння             |
|----------------|-----------------------|------------------------|
| `cmpeqpx`      | 0                     | a == b                 |
| `cmpltpx`      | 1                     | a <  b                 |
| `cmplepx`      | 2                     | a <= b                 |
| `cmpunordpx`   | 3                     | a є NaN або b є NaN    |
| `cmpneqpx`     | 4                     | a != b                 |
| `cmpnltpx`     | 5                     | a >= b                 |
| `cmpnlepx`     | 6                     | a >  b                 |
| `cmpordpx`     | 7                     | ні a, ні b не є NaN    |

~~~~exercism/caution
NaN порівнюється як невпорядковане: воно не є ні меншим, ні рівним, ні більшим за будь-що, включно із самим собою.
Упорядковані предикати, як-от `cmpltps`, дають хибність, коли будь-який з операндів є NaN, тоді як невпорядковані предикати дають істинність.
Саме тому й існують `cmpordps` і `cmpunordps`, щоб явно перевіряти на NaN.
~~~~

## Вибір за допомогою маски

Маска кодує результат умови.
Потім її можна використати, щоб вибирати, доріжка за доріжкою, між двома наборами значень згідно з цією умовою.
Ми беремо доріжку з одного значення там, де маска істинна, і з іншого там, де вона хибна:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

Ця закономірність є упакованою формою вибору без розгалужень.
Кожну доріжку обчислюють, і сама лише маска вирішує, яке значення виживе, без жодного `jcc`.

## Спеціалізовані змішування

Є інструкції, які виконують той самий вибір безпосередньо, читаючи по одному біту на елемент із регістра маски.
Їх називають інструкціями **змішування**:

| інструкція | елемент     | джерело маски   |
|------------|-------------|-----------------|
| `pblendvb` | байт        | неявний `xmm0`  |
| `blendvps` | 32-бітна доріжка | неявний `xmm0`  |
| `blendvpd` | 64-бітна доріжка | неявний `xmm0`  |

Зауважмо, що перша інструкція дотримується цілочисельного синтаксису, тоді як дві інші дотримуються синтаксису чисел з плаваючою комою.
Однак, оскільки ці інструкції просто вибирають сирі байти, будь-яку з них можна використати і з цілими числами, і з числами з плаваючою комою.

Для кожного елемента змішування зберігає призначення, коли старший біт відповідного елемента маски дорівнює нулю, і бере джерело, коли він установлений.
Зважають лише на цей **старший біт**, що його задовольняє маска порівняння, оскільки її доріжки складаються із самих одиниць або із самих нулів.
Регістр маски завжди `xmm0`, і він неявний:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

Також можна використати `pblendvb`, щоб вибирати доріжки з маски порівняння для будь-якого іншого розміру.
Оскільки всі байти в істинній доріжці складаються із самих одиниць, `pblendvb` вибирає їх усі.

~~~~exercism/note
Усі ці інструкції додають `v` після операції, яку виконують (`blend`).
Це `v` походить від англійського _variable_, бо вибір не є статичним: він залежить від регістра.

Є також варіанти без `v`, які вибирають згідно з безпосереднім операндом.
Вони дотримуються тієї самої закономірності, вибираючи доріжку `i`, якщо біт `i` безпосереднього операнда встановлено.
~~~~

## Від маски назад до скаляра

Хоч код SIMD і потужний, йому бракує значної частини гнучкості скалярного коду.
У багатьох ситуаціях потрібно перейти від упакованого регістра назад у світ скалярних інструкцій.

Родина інструкцій `movmsk` править за міст між двома світами.
Ці інструкції видобувають **старший біт** кожної доріжки в регістр загального призначення:

| інструкція | збирає                        | ширина результату |
|------------|-------------------------------|-------------------|
| `pmovmskb` | старший біт кожного з 16 байтів | 16 бітів          |
| `movmskps` | старший біт кожного з 4 dword | 4 біти            |
| `movmskpd` | старший біт кожного з 2 qword | 2 біти            |

Якщо використати їх після порівняння, кожен установлений біт представляє «істинну» доріжку, а кожен скинутий біт - «хибну» доріжку.
Цей результат потім можна обробляти як звично скалярними інструкціями.
Наприклад, `popcnt` рахує кількість збігів, а `tzcnt` знаходить перший.

Регістр загального призначення може бути завширшки 32 або 64 біти.

## Перевірка цілого вектора

Є також упакований варіант скалярної інструкції `test`: `ptest`.

Він подібний до свого скалярного відповідника тим, що виконує операцію AND між двома операндами, не змінюючи їх.
На відміну від `test`, `ptest` також виконує операцію ANDN, заперечуючи перший операнд.

Отже, `ptest` можна розглядати як недеструктивну версію `pand` і `pandn`, яка встановлює прапорці згідно з результатом.
Так само, як ці дві інструкції, `ptest` розглядає весь регістр SIMD як одну доріжку, а отже, не приймає префікса розміру.

Якщо результат операції AND дорівнює `0`, то встановлюється `ZF`, а якщо операція ANDN дає `0`, то встановлюється `CF`.
Це означає, що `ptest` можна використати, щоб перевірити і маску з самих одиниць, і маску з самих нулів:

1. Використання `ptest` на регістрі з ним самим установлює `ZF`, лише якщо регістр складається із самих нулів.
   Це повторює поширену скалярну ідіому використання `test` на регістрі з ним самим, щоб перевірити на `0`.
2. Використання `ptest` на регістрі з маскою з самих одиниць установлює `CF`, лише якщо регістр складається із самих одиниць.
   Крім того, він установлює `ZF`, лише якщо регістр складається із самих нулів, що дає змогу перевірити обидві маски водночас.

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

Результат `ptest` можна, як звично, використати для розгалуження або в інструкціях без розгалужень, як-от `setcc` чи `cmovcc`.

## AVX і далі

AVX дає порівнянням, змішуванням і `ptest` форму з префіксом `v` на ширших регістрах.

Змінне змішування змінює форму.
Маска більше не є неявним `xmm0`, а є явним четвертим операндом:

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

Розширення AVX-512 змінюють модель глибше.

По-перше, воно додає новий клас 64-байтових регістрів SIMD, які називають `zmm`.
Вони розширюють відповідні регістри `ymm` так само, як регістри `ymm` розширюють регістри `xmm`.

По-друге, ці розширення також створюють цілий новий клас **регістрів маски операндів**, від `k0` до `k7`, чия головна мета - слугувати масками для інструкцій SIMD.
Порівняння більше не пишуть у вектори, а в один із цих нових регістрів.
Їх також можна безпосередньо використовувати в багатьох інструкціях як предикати з маскою запису `{k}`, вибираючи доріжки _безпосередньо_:

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

Нарешті, є нові інструкції для роботи з цими новими регістрами, зокрема копіювання їх у регістри загального призначення.
Це робить інструкції `movmsk` непотрібними, і немає підтримки інструкцій `movmsk` на регістрах `zmm`.

Ці розширення згадано для повноти.
Вправи в цьому треку використовують форми SSE.
