# Докладніше

Єдина домовленість про передавання даних у Factor - це *стек даних*: слова знімають свої вхідні дані зі стека й кладуть на нього вихідні. Кожне визначення слова оголошує *стековий ефект*, який документує цю домовленість.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

Назви всередині `( … -- … )` існують для зручності читача; компілятор перевіряє лише *кількість* вхідних і вихідних даних. Невідповідність спричиняє помилку компіляції, і це відсіює цілий клас помилок, які в динамічно типізованій мові без таких оголошень були б помилками виконання.

Оскільки стек позиційний, нам постійно доводиться переставляти елементи на його верхівці, перш ніж зможе виконатися наступне слово. Саме цим і займаються **слова-перестановки** з `kernel`:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

Повна родина перестановок розширює цей набір: `-rot` (прокрутити в інший бік), «родичі» із суфіксом `d`, які діють на один елемент глибше (`dupd`, `swapd`), «родичі» з префіксом `2`, які працюють з парами (`2dup`, `2drop`, `2nip`), а також інші, як-от `pick` і `tuck`. Ми знайомимося з ними в міру того, як вони знадобляться в пізніших вправах; хапатися одразу за надто багато слів-перестановок зазвичай означає, що *локальна змінна* (іменоване значення) читалася б краще.

За домовленістю слова записують у `lowercase-kebab-case`, предикати закінчуються на `?` і повертають булеве значення (англ. Boolean), як-от `even?` чи `empty?`, для сетерів використовують запис `>>name`, а для гетерів `name>>`; крім того, слово та його варіант, що змінює дані, часто мають ту саму назву, і розрізнити їх можна лише за контекстом.
