# Підказки
Поширене використання `Either` - позначати обчислення, яке може завершитися помилкою
(якщо сама помилка не має значення, то простіший тип `Option` може виявитися кращим вибором).
Якщо помилки немає, результатом зазвичай буває `Right` (мнемоніка: «правильне» значення),
а помилку позначає `Left`, наприклад `Left[String]` із повідомленням про помилку.
Варто зауважити, що в Scala 2.12 `Either` типово зміщений праворуч, тож він працює так, як очікується, для таких операцій, як `filter`, `map`, `flatMap`, або в конструкції `for`.
Якщо ми ще не знайомі з `Either`, можна прочитати [цей посібник](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html). Але варто памʼятати, що цей посібник стосується версій Scala до 2.12. У Scala 2.12 можна сміливо не зважати на `RightProjection` і не писати `.right`.
`Either` - це так звана [монада](https://en.wikipedia.org/wiki/Monad_(functional_programming)), яка охоплює «обчислювальний аспект»,
а саме обробку помилок.
Правильне використання монад дає змогу писати дуже лаконічний, але елегантний
і зрозумілий код. Неправильне використання легко призводить до протилежного.
Щоб дізнатися більше, можна подивитися [це відео](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA).
## Поширені пастки, яких варто уникати
Для `Either` є кілька орієнтовних правил:
1. Якщо воно не потрібне, не варто його використовувати. Замість
```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```
краще мати
```scala
def add1(x: Int): Int = x + 1
```
(є `Either.map`, щоб застосовувати такі прості функції,
тож не потрібно захаращувати їх `Either`).
2. Не варто «розгортати» значення, якщо це справді не потрібно.
Часто для цього вже є вбудовані функції. Ознаки передчасного
розгортання - це `isLeft/isRight` або зіставлення зі зразком. Наприклад, замість
```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```
краще мати
```scala
x fold (identity, _ + 1)
```
3. Монади можна використовувати всередині конструкції `for`. І це чудово.
Це радимо, коли потрібно «скомпонувати» кілька примірників `Either`. Замість
```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```
краще мати
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
