# Вступ

Часто буває корисно визначати власні типи у наших програмах.

Створювати нові примітивні типи можливо, але роблять це рідко.
Вбудовані примітивні типи вибрано не довільно: вони близько відповідають стандартним типам у компіляторі LLVM, який Julia використовує для JIT-компіляції.

Значно кориснішою є можливість визначати складені типи з іменованими полями.

В інших мовах є щось подібне, їх називають `structs` або `records`.
Документація Julia називає їх `composite types`, хоч (через невелику розбіжність) синтаксис мови визначає їх ключовим словом `struct`.

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

У наведеному вище прикладі варто зауважити кілька моментів:

- Для `id` тип не вказано, тож компілятор інтерпретує це як `id::Any`.
  - На практиці краще допомогти компілятору, вказавши для поля конкретний тип
- Назва типу використовується як конструктор, наприклад `Person(id, name, age)`, щоб отримати екземпляр типу `Person`.
- До окремих полів можна звертатися через точкову нотацію, так само як до іменованих кортежів.

Екземпляри типу `Person` незмінні, тому їх не можна оновлювати.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

Якщо потрібна змінність, додаймо `mutable` до визначення.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

Конструктор типово вимагає, щоб поля зʼявлялися в тому самому порядку, що й у визначенні, а це стає незручно для складніших типів.

Використання макросу `@kwdef` дає дві нові можливості:

- Конструктор використовує ключові слова, а не позиції.
- Поля можуть мати типові значення, і їх за бажанням можна не вказувати в конструкторі.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## Ієрархії складених типів

Досі ми створювали лише конкретні складені типи.
Якщо перевірити, усі вони є підтипами `Any`.

Коли ми створюємо кілька повʼязаних типів, ймовірно, логічніше визначити для них ієрархію.
Це дуже легко зробити.

Спершу створімо абстрактний тип:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

Далі додамо оператор `<:` до визначення типу, щоб показати звʼязок.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

Повторімо за потреби, памʼятаючи, що підтипування конкретних типів не дозволено.

Для складнішої ієрархії створімо абстрактні підтипи за потреби.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

Користь від такої ієрархії стане зрозумілішою, коли ми дійдемо до концепції `Multiple Dispatch` і побачимо, як функції працюють з типами аргументів.
