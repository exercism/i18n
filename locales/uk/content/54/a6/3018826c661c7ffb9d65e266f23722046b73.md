# Вступ до арифметики в оболонці Bash

Bash уміє виконувати арифметичні дії, але _лише з цілими числами_.
Якщо потрібні обчислення з плаваючою комою, доведеться звертатися до якоїсь зовнішньої програми (наприклад, [awk][awk] або [bc][bc]).

Арифметичні оператори перелічено (у порядку пріоритету) в документації: [Арифметика оболонки][arithmetic].

Крім того, Bash виконує арифметичні дії лише в певних місцях (так званих арифметичних «контекстах»).

## Арифметичне розширення

Арифметичне розширення схоже на [підстановку команд][cmd-sub], але з подвійними дужками.

```bash
$(( expression ))
```

Цей синтаксис розгортається в результат обчислення виразу.
Його часто використовують, щоб зберегти результат у змінній:

```bash
x=$(( 3 + 4 ))
```

~~~~exercism/note
Кількість пробілів усередині дужок ми обираємо самі.
Це питання стилю та читабельності.

```bash
x=$(( 3 + 4 ))
y=$((5+6))
```

Автор цих рядків полюбляє додавати пробіли, щоб арифметичний вираз було краще видно в дужках.
~~~~

## Арифметична умова

Арифметичну умову виконують у подвійних дужках _без_ провідного `$`:

```bash
(( expression ))
```

Вона не розгортається в результат.
Натомість вона дає _статус завершення_.

* Статус завершення дорівнює 0 (успіх), якщо результат виразу **ненульовий**.
* Статус завершення дорівнює 1 (невдача), якщо результат виразу **нульовий**.

~~~~exercism/note
Усередині `((` Bash використовує те саме розуміння правди й неправди, що й мова C: нуль - це неправда, ненульове значення - правда.
**Це протилежно до того, як Bash оцінює статуси завершення!**
~~~~

Цей синтаксис зазвичай використовують у двох місцях:

1. як частину COMMAND у [умовній конструкції `if`][conditional-if] або [циклі `while`][looping-while].

   ```bash
   if (( x == y - 1 )); then ...
   while (( y > 0 )); do ...
   ```

1. як окрему команду для зміни значення змінної.

   ```bash
   (( x = x + 1 ))
   echo "new value for x is $x"
   ```

   ~~~~exercism/caution
   Будьмо обережні, коли поєднуємо арифметику в такий спосіб із `set -e`.
   Якщо вираз обчислюється в нуль, статус завершення буде ненульовим, і Bash завершиться.

   ```bash
   x=0
   (( x++ ))
   echo "you will see this"

   set -e
   x=0
   (( x++ ))
   echo "shell exits on the previous line; you won't see this"
   ```

   Докладніше про оператор `++` можна прочитати в статті [Постінкремент проти преінкремента][incr]

   [incr]: https://thisvsthat.io/postincrement-vs-preincrement
   ~~~~


## Інші місця з арифметичним контекстом

Є ще кілька місць, які є арифметичними контекстами:

* [Арифметичний цикл for][looping-for].

  ```bash
  for (( i = 0; i < 10; i++ )); do
      echo "$i"
  done
  ```

* Частина з індексом у масиві, індексованому числами.

  ```bash
  echo "The next element is ${array[x + 1]}"
  # ................................^^^^^
  ```

  Докладніше про масиви можна прочитати в документі концепції [Масиви][arrays].

* Частини offset і length у розкритті `${var:offset:length}`.
* [Вбудована команда `let`][let].
  * Зауважимо, що `(( expression ))` краще, ніж `let "expresson"`.
    На відміну від арифметичної умовної конструкції, вираз `let` підлягає розгортанню імен файлів і розбиттю на слова, і його потрібно брати в лапки.
* Присвоєння змінній, коли змінна має «цілочисельний атрибут».

  ```bash
  # variable x does not have the integer attribute
  x="3 + 4"
  declare -p x      # => declare -- x="3 + 4"

  # variable y has the integer attribute
  declare -i y
  y="4 + 5"
  declare -p y      # => declare -i y="9"
  ```

  ~~~~exercism/note
  На думку автора, `declare -i` має обмежене застосування.
  Його основна перевага - дозволяти «голу» арифметику (без синтаксису арифметичного виразу).
  Це може заплутати читачів коду, адже арифметичні вирази обчислюються в несподіваних місцях.
  ~~~~

## Використання змінних в арифметичних виразах

Ось один аспект арифметичних контекстів, який покращує читабельність.

```bash
height=10
width=20
area=$(( height * width ))
```

Чи помітно, що знаки долара `$` відсутні біля змінних в арифметичному виразі?
Bash дозволяє так робити.
Це робить вирази значно легшими для читання.

У документації сказано:

> Усередині виразу на змінні оболонки можна також посилатися за назвою, не використовуючи синтаксис розкриття параметрів.

Це працює навіть для елементів масиву:

```bash
point1=(10 15)  # these are (x, y) coordinates
point2=(20 7)
distance_squared=$(( (point1[0] - point2[0])**2 + (point1[1] - point2[1])**2 ))
```

Але інші вирази з параметрами мають використовувати свій спеціальний синтаксис.
Наприклад, подвоєння довжини рядка тексту (англ. string):

```bash
s="hello world"
len=$(( ${#s} * 2 ))
```

І позиційні параметри теж.
Якщо перші два позиційні параметри задають ширину і висоту:

```bash
area=$(( $1 * $2 ))
```
