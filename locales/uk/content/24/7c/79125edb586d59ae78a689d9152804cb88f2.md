# Про

**Число з плаваючою комою** - це число, яке може мати дробову частину, наприклад `-1.23` або `3.1415`.

Щоб подати таке число як послідовність байтів, x86-64 використовує стандарт [IEEE-754][ieee].
Цей стандарт має два найпоширеніші формати: числа з плаваючою комою одинарної точності та числа з плаваючою комою подвійної точності.
x86-64 підтримує обидва.

Число з плаваючою комою одинарної точності має ширину 32 біти, а подвійної - 64 біти.

## Регістри XMM

У x86-64 є 16 виділених регістрів для арифметики з плаваючою комою, з назвами від `xmm0` до `xmm15`.

Ці регістри мають ширину щонайменше 128 бітів, але новіші процесори збільшують її до 256 або 512 бітів.
Утім, на практиці більшість чисел з плаваючою комою використовують лише молодші 32 або 64 біти, залежно від потрібної точності.

## Перетворення між числами

Існує родина інструкцій для перетворення між форматами чисел: `cvtxx2yy`.

Під `xx` і `yy` маються на увазі не літерали, а заповнювачі:

- `xx` - це заповнювач для типу операнда-джерела.
- `yy` - це заповнювач для типу операнда-призначення.

Цей заповнювач може набувати багатьох форм, зокрема:

| заповнювач | значення               |
| ----------- | --------------------- |
| `si`        | ціле число зі знаком        |
| `ss`        | 32-бітове число з плаваючою комою |
| `sd`        | 64-бітове число з плаваючою комою |

Наприклад:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

Зауважмо, що можна перетворити 32-бітове ціле число на 64-бітове число з плаваючою комою або 64-бітове ціле на 32-бітове число з плаваючою комою.
Так само можна перетворити 32-бітове число з плаваючою комою на 64-бітове ціле або 64-бітове число з плаваючою комою на 32-бітове ціле.
Іншими словами, розміри обох операндів у `cvtxx2yy` _не обовʼязково мають бути однаковими_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

Коли число з плаваючою комою не можна точно виразити як ціле, `cvtxx2si` округлює його відповідно до керування округленням у спеціальному регістрі `mxcsr`.
Це може бути округлення до найближчого, округлення вниз, округлення вгору або відкидання дробової частини.
На вході у функцію гарантованого типового значення немає.

Зауважмо, що точний результат не округлюється і, отже, на нього не впливає керування округленням.
Наприклад, `42.0` _завжди_ перетворюється на `42`.

Існує подібна родина інструкцій формату `cvttxx2si` (з додатковою `t`), які завжди відкидають дробову частину результату.

## Округлення

Родина інструкцій `roundxx` перетворює число з плаваючою комою в операнді-джерелі на округлене число з плаваючою комою, збережене в операнді-призначенні.

Тут `xx`, як завжди, є заповнювачем для типу операндів: `ss` для чисел одинарної точності, `sd` для чисел подвійної точності.

Ці інструкції приймають константне число як третій операнд.
Це число вказує режим округлення:

| Число | Режим         |
| :----- | :----------- |
| 0      | До найближчого      |
| 1      | Униз (floor) |
| 2      | Угору (ceil)    |
| 3      | Відкидання дробової частини     |

Наприклад:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

Оскільки ці інструкції дають точний результат, їх можна використовувати для підготовки до `cvtxx2si`.

## Арифметичні інструкції

Багато операцій із числами з плаваючою комою використовують інструкції з назвою, подібною до їхніх аналогів для цілих чисел, але з додаванням потрібного заповнювача (`ss` або `sd`) у кінці.
Ці інструкції дводоперандні, зі звичайною семантикою, навіть ті, що виконують множення або ділення:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## Переміщення

Інструкції для переміщення з одного регістра XMM до іншого: `movss` або `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

**Не** можна безпосередньо перемістити безпосереднє значення (константне ціле число зі знаком) у регістр xmm.
Спочатку це число потрібно перемістити в регістр загального призначення, а потім перетворити за допомогою `cvtsi2xx`:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## Порівняння

Існують дві групи інструкцій для порівняння двох чисел з плаваючою комою.
Вони мають вигляд `comixx` і `ucomixx`, де `xx` може бути або `ss`, або `sd`.
Обидві встановлюють прапорці в `rflags`, як зазвичай, дотримуючись тієї самої семантики, що й `cmp`.

Різниця між ними в тому, що `ucomixx` встановлює `parity flag (PF)`, якщо одне з двох чисел з плаваючою комою має значення `NaN`, тоді як `comixx` у цьому випадку викликає виняток.

Порівняння між значеннями з плаваючою комою є _беззнаковим_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## Інші інструкції

Існує багато інших інструкцій для роботи з числами з плаваючою комою, які реалізують поширені операції.
Деякі з них:

| Інструкція | Опис                                      |
| :---------- | :----------------------------------------------- |
| `sqrtxx`    | Обчислює квадратний корінь (`sqrt(x)`)                 |
| `rcpss`     | Обчислює обернене значення (`1/x`)                      |
| `rsqrtss`   | Обчислює обернене значення квадратного кореня (`1/sqrt(x)`) |
| `minxx`     | Обчислює мінімум (`min(x, y)`)                   |
| `maxxx`     | Обчислює максимум (`max(x, y)`)                   |

Де використовується заповнювач `xx`, він, як завжди, може набувати форми `ss` або `sd`.
Однак `rcpss` і `rsqrtss` працюють лише з числами з плаваючою комою одинарної точності.

Усі ці інструкції дводоперандні.

## Угода про виклик

У System V ABI перші вісім аргументів з плаваючою комою передаються функціям по порядку, від `xmm0` до `xmm7`.
Значення з плаваючою комою повертаються з функцій у `xmm0`, а якщо потрібно, то в `xmm1`.

Усі регістри `xmm` можна вільно використовувати, жоден із них не зарезервовано для того, хто викликає.

## Памʼять

Значення з плаваючою комою можна визначати в памʼяті за тією самою семантикою, що й цілі числа того самого розміру.
NASM (The Netwide Assembler - асемблер, який використовується тут) також дозволяє оголошувати значення з плаваючою комою в науковій нотації.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```

## AVX/AVX2

Розширення AVX/AVX2 архітектури x86-64 вводять нові триоперандні форми інструкцій для чисел з плаваючою комою, відокремлюючи призначення від джерел.
Вони мають префікс `v` (від _вектора_), щоб відрізняти їх від застарілої форми SSE, яку ми бачили вище:

```x86asm
vaddss xmm0, xmm1, xmm2 ; xmm0 = xmm1 + xmm2 (32-bit floating-point)
vmulsd xmm2, xmm3, xmm4 ; xmm2 = xmm3 * xmm4 (64-bit floating-point)
```

Тут ми обмежилися інструкціями та регістрами до попередніх розширень SSE.
Цього достатньо, щоб викласти основи, і це забезпечує сумісність із широким спектром процесорів.

Однак засіб запуску тестів повністю підтримує AVX і AVX2.
Ними можна вільно користуватися.
