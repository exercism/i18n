# Вступ

## Ітератори

`Iterator` у Gleam схожий на масив тим, що це впорядкована колекція значень, де всі значення мають один і той самий тип. Він відрізняється від масиву тим, що лінивий: тобто не зберігає всі свої значення в памʼяті одразу, а натомість обчислює їх тоді, коли вони потрібні.

Це стає в пригоді, коли ми працюємо з послідовностями, які дуже великі або навіть нескінченні, бо дає змогу працювати з ними навіть тоді, коли вільної памʼяті не вистачає, щоб зберегти їх усі одразу.

Модуль `gleam/iterator` визначає тип `Iterator`, а також функції для роботи з ітераторами.

Багато функцій для масивів існують і для ітераторів, як-от `map`, `filter` і `take`. Ці функції повертають ітератори, тож насправді вони не виконують жодної роботи, доки ітератор не буде спожито.

```gleam
let iter = 
  [1, 2, 3, 4, 5, 6]
  |> iterator.from_list
  |> iterator.filter(fn(x) { x > 2 })
  |> iterator.take(2)

// No work has been done yet as the iterator has not been consumed

// Consume the iterator and collect the values into a list
iterator.to_list(iter)
// -> [3, 4]
```

Функцію `unfold` можна використати, щоб створювати ітератори з функції, яку викликають знову й знову, аби отримати наступне значення послідовності.

Тут функцію `unfold` використано, щоб створити ітератор, який породжує послідовність Фібоначчі:

```gleam 
iterator.unfold(#(0, 1), fn(pair) {
  let x = pair.0 + pair.1
  iterator.Next(element: x, accumulator: #(pair.1, x))
})
|> iterator.take(6)
|> iterator.to_list
// -> [1, 2, 3, 5, 8, 13]
```

Послідовність тут нескінченна, тож функцію `take` використано, щоб зробити її скінченною, перш ніж зібрати значення в масив. Якщо викликати `to_list` на нескінченному ітераторі, програма працюватиме, доки їй не забракне памʼяті, і тоді аварійно завершиться.
