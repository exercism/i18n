# Інструкції

Після нещодавньої перевірки безпеки нас попросили навести лад в архівних файлах логів організації.

## 1. Визначити спотворені рядки логу

Нам потрібно хоч приблизно уявляти, скільки рядків логу в архіві не відповідають поточним стандартам.
Ми вважаємо, що простий тест показує, чи правильний рядок логу.
Щоб рядок вважався правильним, він має починатися з одного з таких рядків тексту (англ. string):

- `[DEBUG]`
- `[INFO]`
- `[WARNING]`
- `[ERROR]`

Реалізуйте функцію `is_valid_line`, щоб вона повертала `True`, якщо рядок логу правильний.

```gleam
log_parser.valid_line("[ERROR] Network Failure")
// -> True

log_parser.valid_line("Network Failure")
// -> False
```

## 2. Розділити рядок логу

Невдовзі після початку проєкту з розбору логів ми помічаємо, що логи одного застосунку не розбиті на рядки, як в інших. У цьому проєкті те, що мало бути окремими рядками, міститься в одному рядку, зʼєднане химерними стрілками, як-от `<--->` або `<*~*~>`.

Насправді як розділювач у логах цього проєкту можна використати будь-який рядок тексту, що починається символом `<`, закінчується символом `>`, а між ними має нуль або більше таких символів: `~`, `*`, `=` та `-`.

Реалізуйте функцію `split_line`, яка приймає рядок логу і повертає масив рядків тексту.

```gleam
log_parser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
// -> ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. Позначити рядки іменами користувачів

Ми помітили, що деякі рядки логу містять речення, які згадують користувачів.
Ці речення завжди містять рядок тексту `"User"`, після якого йде один або більше символів пробілу, а потім імʼя користувача.
Ми вирішуємо позначити такі рядки.

Реалізуйте функцію `tag_with_user_name`, яка обробляє рядки логу:

- Рядки, що не містять рядка тексту `"User"`, залишаються без змін.
- У рядках, що містять рядок тексту `"User"`, додайте на початок рядка `[USER]`, за яким іде імʼя користувача.

```gleam
log_parser.tag_with_user_name("[INFO] User Alice created a new project")
// -> "[USER] Alice [INFO] User Alice created a new project"
```

Можна припустити, що:

- Кожне входження рядка тексту `"User"` супроводжується одним або більше символами пробілу та іменем користувача.
- У кожному рядку є щонайбільше одне входження рядка тексту `"User"`.
- Імена користувачів - це непорожні рядки тексту, які не містять символів пробілу.
