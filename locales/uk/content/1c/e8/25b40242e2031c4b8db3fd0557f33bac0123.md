# Про

«Дати й час - це те, чого ми вчимо малих дітей. Що тут складного?»

Багато розробників припускалися цієї помилки, і подальший досвід зазвичай погано впливає на їхнє здоровʼя та щастя.

Будь-хто, хто займається нетривіальним програмуванням із датами й часом, має бути принаймні готовий розуміти потенційні проблеми та помʼякшувати їх.

У цьому документі ми спробуємо дати загальний огляд того, як Julia працює з датами й часом, але для подробиць потрібно буде звернутися до [посібника][Dates].
Також є [Вікіпідручник][Wikibook], пояснення в якому деяким читачам можуть здатися зрозумілішими, і він містить корисну [діаграму][type-hierarchy] ієрархії типів.

## Модуль `Dates`

Більшість базової функціональності міститься в `Dates`, модулі, який входить до типового встановлення, але не є частиною стандартної бібліотеки.

Щоб скористатися модулем, є два варіанти:

1. Додати `import Dates`, а потім додавати `Dates.` перед усіма викликами функцій.
2. Додати `using Dates`, що вносить увесь модуль у поточний простір імен (_крім кількох проблемних назв_).

```julia-repl
# option 1
julia> import Dates

julia> Dates.now()
2025-06-21T16:02:39.080

julia> now()  # wrong: need to include `Dates.` after an import
ERROR: UndefVarError: `now` not defined in `Main`


# option 2
julia> using Dates

julia> now()  # functions are now in the namespace
2025-06-21T16:03:04.161
```

Модуль `Dates` великий і складний, але він надає чотири основні типи функціональності:

- `Dates.Date`, який включає день, місяць і рік, але не час доби.
- `Dates.Time`, який включає час доби з точністю до наносекунд, але не дату.
- `Dates.DateTime`, який поєднує дату й час із точністю до мілісекунд.
- `Dates.Period`, який працює з інтервалами часу й дат.

Зауважмо, що `DateTime` зазвичай _не_ містить інформації про часовий пояс (у Python це назвали б «наївним» datetime).
Один виняток - `now()`, який бере місцевий час із системного годинника й за потреби може перетворити його на UTC.

Інші обчислення з часовими поясами потребують пакета `TimeZones.jl`, який не входить до типового встановлення.
Станом на червень 2025 року він недоступний на Exercism, але його можуть додати в майбутньому.

Мабуть, найчастіші потреби такі:

- Розібрати відповідний формат вхідних даних, щоб створити тип `Dates`.
- Отримати потрібний числовий формат або формат рядка тексту (англ. string) з типу `Dates`.
- Застосувати зміщення до значення `Date`, `Time` або `DateTime`.
- Обчислити інтервал між двома такими значеннями.
- Отримати поточну дату (за допомогою `today()`) та/або час (за допомогою `now()`).

~~~~exercism/note
Щоб зменшити візуальне відволікання, більшість прикладів коду в решті цього документа припускає `using Dates` і не включає назву модуля `Dates.` у виклики функцій.
~~~~

### Формати дати й часу

Існує багато способів запису дат і часу, які часто залежать від культури.
Дати, записані самими числами, як-от «7/6/23», неоднозначні, заплутані й призводили до багатьох дорогих помилок у міжнародних організаціях (_автор каже це з гіркого особистого досвіду_).

Міжнародний стандарт визначено в [`ISO 8601`][ISO8601], і він має дві головні переваги:

- Розбір швидкий і недвозначний.
- Сортування просте, бо дату й час можна вважати звичайним текстом і сортувати за алфавітом.

У попередньому прикладі ми бачили, що `Date.now()` повернув `2025-06-21T16:03:04.161`.

Він складається з різних частин:

- `YYYY-MM-DD` для частини дати.
- `hh:mm:ss` для частини часу.
- Необовʼязково мілісекунди (або ще менша одиниця) після десяткової коми.

Інші формати рядків тексту розглянемо в пізнішому розділі.

## Дати

`Dates.Date` - відносно простий тип лише для дати, який не розуміє ані часу, ані часових поясів.

```julia-repl
# constructor with year, month, day arguments
julia> date1 = Date(2025, 06, 23)
2025-06-23

# constructor with ISO 8601 string
julia> date2 = Date("2025-06-23")
2025-06-23

julia> date1 == date2
true

julia> typeof(date1)
Date
```

Є функції доступу до окремих частин дати, і вони йдуть парами, які розрізняються регістром.

```julia-repl
# lowercase returns an integer
julia> month(date1)
6

julia> typeof(month(date1))
Int64

# Propercase returns a Period type
julia> Month(date1)
6 months

julia> typeof(Month(date1))
Month

# various compound methods are also available, returning a tuple
julia> monthday(date1)
(6, 23)
```

### Функції запитів

Є різні [функції запитів][query-func], які певною мірою розуміють календар.
У наступному прикладі показано лише кілька з них.

```julia-repl
julia> date1
2025-06-23

julia> dayofweek(date1) # 1 = Monday, 7 = Sunday
1

julia> dayname(date1)
"Monday"

julia> daysinmonth(date1)
30

julia> isleapyear(date1)
false

julia> lastdayofmonth(date1)
2025-06-30
```

## Час

`Dates.Time` - базовий тип лише для часу.
Він не розуміє дат: значення часу автоматично переходять до `Time(0, 0, 0)` опівночі.

Повний формат конструктора - `Time(hour, min, sec, millisec, microsec)` або відповідний формат ISO 8601.

Усі параметри необовʼязкові й типово дорівнюють `0`.

```julia-repl
julia> Time(14, 57, 25, 142)
14:57:25.142

julia> Time(14, 57, 25, 142, 32)`
14:57:25.142032

julia> Time("14:57:25.142")
14:57:25.142
```

Як і з `Date`, окремі частини доступні через функції доступу:

```julia-repl
julia> minute(t) # => integer
57

julia> Minute(t) # => Period
57 minutes
```

## DateTime

`Dates.DateTime` поєднує більшість можливостей типів `Date` і `Time`.
Це найуніверсальніший із цих трьох класів, хоча роздільна здатність часу обмежена мілісекундами (`Time` може мати роздільну здатність до наносекунд).

```julia-repl
julia> dt1 = DateTime(2025, 6, 23, 14, 57, 25, 142)
2025-06-23T14:57:25.142

# date1 and t were defined in previous examples
julia> dt2 = DateTime(date1, t)
2025-06-23T14:57:25.142
```

Параметри року, місяця й дня типово дорівнюють `1`, а всі часові параметри типово дорівнюють `0`.

Не заплутатися в усіх цих параметрах може бути складно, тож формат ISO може бути кращим.

Крім того, `DateTime` можна створити з `Date` і `Time`, як у наведеному вище прикладі.

## Періоди

Кожен складник дати/часу має власний тип [`Period`][period], від `Year` до `Nanosecond`, що представляє інтервал часу.
Вони особливо корисні для арифметики.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Year(21)
21 years

julia> Second(61)
61 seconds

julia> dt1 + Year(21) - Second(61)
2046-06-23T14:56:24.142

julia> Date(2025, 07, 03) - Date(2025, 04, 25)
69 days
```

Також є тип [`CompoundPeriod`][compound-period], який може поєднувати кілька типів `Period`.
Дивно, але зараз він потребує назви модуля, щоб уникнути помилки простору імен (_що схоже на bug_).

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> offset = Dates.CompoundPeriod(Year(21), Second(-61))
21 years, -61 seconds

julia> dt1 + offset
2046-06-23T14:56:24.142
```

Коли ми віднімаємо дати/час, період буде подано в днях (для дат) або наносекундах (для часу).
Може бути корисно [`canonicalize`][canonicalize] їх до `CompoundPeriod`.

```julia-repl
julia> diff = Time(23, 14, 00) - Time(1, 23, 52)
78608000000000 nanoseconds

julia> canonicalize(diff)
21 hours, 50 minutes, 8 seconds

julia> typeof(canonicalize(diff))
Dates.CompoundPeriod
```

Працюючи з типами `Period`, Julia намагається розумно поводитися з календарними нерівностями, як-от різна довжина місяців, і за потреби округлює.

```julia-repl
# February has fewer days than January
julia> Date(2025, 1, 31) + Month(1) 
2025-02-28
```

## [Округлення][rounding]

Функції `floor`, `ceil` і `round` мають бути знайомі з роботи з цілими числами та числами з плаваючою комою, але також працюють із датами й часом.
Другим аргументом потрібно вказати `Period`, до якого округлювати.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> floor(dt1, Minute(15))
2025-06-23T14:45:00

julia> ceil(dt1, Minute(30))
2025-06-23T15:00:00

julia> ceil(dt1, Month(1))
2025-07-01T00:00:00
```

## Представлення рядків тексту

Раніше ми згадували стандарт ISO 8601, який є типовим представленням дати/часу в Julia під час форматування або розбору рядків тексту.

Очевидно, що багато інших форматів часто використовують, нерідко в культурно зумовлений спосіб.
Щоб працювати з ними, Julia має тип `DateFormat`, який можна створити з рядка формату довільної складності.

```julia-repl
# dateformat"" string syntax
julia> dtfmt = dateformat"d/m/y"
dateformat"d/m/y"

julia> typeof(dtfmt)
DateFormat{Symbol("d/m/y"), Tuple{Dates.DatePart{'d'}, Dates.Delim{Char, 1}, Dates.DatePart{'m'}, Dates.Delim{Char, 1}, Dates.DatePart{'y'}}}

# DateFormat constructor
julia> DateFormat("d/m/y")
dateformat"d/m/y"
```

Наведений вище приклад дуже простий: це просто дата у форматі день/місяць/рік, поширеному в Європі.
Показано два варіанти синтаксису, але результат ідентичний.

Потім `DateFormat` можна використати для розбору будь-якого відповідного рядка тексту:

```julia-repl
julia> DateTime("14/7/2023", dtfmt)
2023-07-14T00:00:00
```

Створення `DateFormat` потребує значних накладних витрат, тож зробити цей крок лише раз (як тут із `dtfmt`) корисно для продуктивності, коли ми перебираємо багато рядків із датами/часом.

Формати можуть бути значно складнішими, тож подробиці можна знайти в [посібнику][dateformat].

Ті, хто знайомий з іншими мовами, можуть помітити родинну схожість із функціями `strptime` і `strftime`, яким уже десятки років.
Версія Julia запозичує з цієї спадщини, але прагне бути стислішою й гнучкішою.

Той самий `DateFormat` можна також використати, щоб вивести дату/час у будь-якому потрібному форматі рядка тексту за допомогою функції [`Dates.format()`][format].

На жаль, схоже, є конфлікт простору імен із `format` (принаймні станом на Julia 1.11.5), тож краще додавати префікс `Dates.` навіть після `using Dates`.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Dates.format(dt1, dateformat"e, u d")
"Mon, Jun 23"
```

Як [описано][wiki-format], `"e, u d"` дає скорочене текстове представлення дня тижня й місяця.

Текстове представлення типово англійською.
Можна додати інші мови, хоча підтримка цього зараз неоптимальна.
