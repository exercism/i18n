# Вступ

У Factor ми поєднуємо слова просто записуючи їх одне за одним: порядок,
у якому ми їх записуємо, і *є* тим, як вони поєднуються. (Програмісти
називають це *композицією функцій*.) Тіло слова саме є послідовністю
слів: кожне з них забирає зі стека певні
значення та кладе свій результат, а наступне слово підхоплює там, де
зупинилося попереднє. Отже, таке визначення

```factor
! DOCTEST: SKIP   (cleanupname is hypothetical here — the exercise's job)
: firstletter ( name -- letter ) cleanupname first 1string ;
```

уже *є* композицією `cleanupname`, `first` і `1string`.

У цій вправі ми також знайомимося з **квотейшенами**: це фрагмент коду,
який можна зберегти як значення й виконати пізніше, замість того щоб
виконувати його одразу.

## Квотейшени

Квотейшн - це фрагмент коду, загорнутий у квадратні дужки. Він не
виконується, коли його записано, а лежить на стеку як значення:

```factor
[ 2 * ] .       ! => [ 2 * ]
```

`call` виконує квотейшн:

```factor
3 [ 2 * ] call .    ! => 6
```

Ми пишемо квотейшн, коли потрібно передати код як дані: щоб виконати
його пізніше або передати в *комбінатор*, тобто слово, яке приймає
квотейшн як вхідні дані.

## `compose`

`compose ( quot1 quot2 -- combined )` поєднує два квотейшени в один,
виконуючи їх у тому порядку, у якому їх записано:

```factor
[ 2 * ] [ 1 + ] compose .    ! => [ 2 * 1 + ]
```

Зазвичай ми побачимо, що визначити невелике слово через `:` ... `;`
читається краще, ніж `compose`, але `compose` стає в пригоді, коли треба
будувати квотейшени на ходу. Коли складові вже не є квотейшенами,
`>quotation ( seq -- quot )` (з
[`quotations`][quotations]) перетворює послідовність значень і посилань
на слова в квотейшн, який можна викликати:

```factor
USING: quotations sequences ;

{ [ 1 ] [ 2 + ] [ 3 * ] } concat >quotation call .   ! => 9
```

## Застосування одного квотейшена до двох входів

`bi@ ( x y quot -- ... )` виконує квотейшн для `x`, а потім ще раз для
`y`, залишаючи обидва результати на стеку:

```factor
3 4 [ 2 * ] bi@ .s
! => 6
! => 8
```

Завдання `couple` у цій вправі приймає два імені; `bi@` - це природний
спосіб застосувати `initial` до кожного з них.

## Кілька слів для роботи з рядками тексту

Вправі потрібно кілька невеликих слів для роботи з рядками тексту
(англ. string), узятих із трьох наборів слів:
[`sequences`][sequences], [`ascii`][ascii] і [`strings`][strings]:

- `replace ( seq old new -- new-seq )` (у `splitting`): заміна
  підрядків.
- `[ blank? ] trim` (`trim` у `sequences`, `blank?` у `ascii`): відкинути
  провідні та кінцеві пробільні символи.
- `1string ( char -- str )` (у `strings`): загорнути окремий символ у
  рядок тексту.
- `>upper ( str -- upper )` (у `ascii`): перевести рядок тексту у верхній
  регістр.
- `append ( s1 s2 -- s )` (у `sequences`): зʼєднати два рядки тексту.
- `prepend ( s1 s2 -- s )` (у `sequences`): зʼєднати `s2`, а потім `s1`
  (`append` з вхідними даними в іншому порядку).
- `glue ( s1 s2 sep -- s )` (у `sequences`): зʼєднати два рядки тексту
  із розділювачем між ними.
- `surround ( seq pre post -- new )` (у `sequences`): загорнути рядок
  тексту в префікс і суфікс.

Символи Unicode можна записати як `\u{XXXX}` усередині рядка тексту, де
`XXXX` - це кодова позиція в шістнадцятковій формі. Серце `\u{2764}` (❤)
трапляється в цій вправі.

## Форматований вивід

Коли `append`/`glue`/`surround` не дають достатньо виразності,
[`formatting`][formatting] надає `sprintf` у стилі printf:

```
sprintf ( inputs... format-string -- str )
```

`%s` підставляє рядок тексту, `%d` ціле число, `%f` число з плаваючою
комою; необовʼязкові модифікатори ширини, точності й доповнення стоять
між `%` і літерою типу:

```factor
USING: formatting ;

"Alice" "Bob" "%s & %s" sprintf .   ! => "Alice & Bob"
3.14159 "%.2f" sprintf .             ! => "3.14"
42 "%05d" sprintf .                  ! => "00042"
```

Для взаємного перетворення чисел і рядків тексту
[`math.parser`][math.parser] має `number>string` і
`string>number`:

```factor
USING: math.parser ;

42 number>string .       ! => "42"
"3.14" string>number .   ! => 3.14
```
