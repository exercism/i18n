# Вступ

## RFLAGS

Існує спеціальний регістр під назвою `rflags`.
Його біти діють як прапорці для різних умов.

Деякі з них наведено нижче:

| назва        | символ | біт |
| :----------- | :----: | :-: |
| перенесення  |   CF   |  0  |
| нуль         |   ZF   |  6  |
| знак         |   SF   |  7  |
| переповнення |   OF   | 11  |

## Інструкції порівняння

Прапорці в `rflags` _не_ змінюються напряму.
Натомість їх встановлюють багато різних інструкцій.

Наприклад, `ZF` встановлюється багатьма арифметичними або порозрядними операціями, коли результат дорівнює нулю.

Однією з найпоширеніших інструкцій, які застосовують для перевірки умов, є `cmp`.
Вона приймає два операнди й оновлює прапорці, але **не змінює свої операнди**.

### Інструкція CMP

Інструкція `cmp` віднімає другий операнд від першого і встановлює прапорці відповідно до результату.

Якщо A - перший операнд, а B - другий:

| прапорець | встановлюється, коли                     |
| :-------: | :--------------------------------------- |
|    CF     | A < B (беззнакове)                       |
|    ZF     | A == B                                   |
|    SF     | A < B (знакове, без переповнення)        |
|    OF     | переповнення під час знакового віднімання |

## Розгалуження

Типово код у x86-64 виконується послідовно, згори вниз.

Але є багато ситуацій, коли цю поведінку потрібно змінити.
Наприклад, щоб виконати інший набір інструкцій у відповідь на умову.

У мовах вищого рівня для цього зазвичай використовують абстракції, як-от умовні конструкції `if...else`.
Однак у x86-64 їх немає.

Натомість x86-64 надає інструкції, які фактично передають виконання в інше місце коду.
Це називається `branching`.

~~~~exercism/note
Ми вже бачили дві такі інструкції: `call` і `ret`.

Коли функцію викликають, виконання переходить від того, хто її викликав, до викликаної функції.
А під час повернення виконання передається назад тому, хто викликав.

Якщо `ret` не знайдено, виконання переходить з однієї функції в наступну.
Іноді це можна використати для оптимізації потоку виконання коду.
~~~~

### Безумовний перехід

Інструкція **jmp** безумовно передає виконання програми в іншу точку коду.
Її єдиний операнд - це мітка, яка містить адресу точки, де виконання продовжиться.

Розгляньмо, наприклад, таку функцію:

```x86asm
fn:
    mov rax, 5
    jmp end

    add rax, 10
end:
    ret
```

Коли викликають `fn`, виконання починається з `mov rax, 5`.
Це встановлює значення в `rax` рівним 5 на цей момент.

Наступна інструкція - `jmp end`, яка передає виконання мітці `end`.

Після `end` наступна інструкція - `ret`, яка передає виконання назад у функцію, що викликала.

Зауважмо, що оскільки `add rax, 10` розташована після `jmp end` і перед `end`, вона ніколи не виконується.
Значення `rax` на момент повернення з `fn` дорівнює 5.

### Умовний перехід

Сімейство інструкцій **jcc** передає виконання програми в іншу точку лише за виконання певної умови.
Інакше виконання продовжується послідовно.

Кожна умова відповідає одному або кільком прапорцям у `rflags`.
Деякі варіанти `jcc` перевіряють, що прапорець встановлено, інші - що його скинуто.

`cc` у `jcc` не буквальне позначення, а вказівка на конкретний суфікс, повʼязаний із прапорцем, який перевіряють.

Існує багато суфіксів, і багато з них перевіряють ту саму умову, що й інший.
Деякі з них посилаються безпосередньо на прапорець, тож інструкція переходить до мітки, якщо цей прапорець встановлено:

| суфікс | переходить, якщо |
| :----: | :--------------: |
|   z    |     ZF == 1      |
|   c    |     CF == 1      |
|   s    |     SF == 1      |
|   o    |     OF == 1      |

Багато інших обрано так, щоб вони вказували на своє значення в інструкції `cmp`.
Наприклад:

| інструкція | суфікс | переходить, якщо  |
| ---------- | :----: | :---------------- |
| cmp A, B   |   e    | A == B            |
| cmp A, B   |   l    | A < B (знакове)   |
| cmp A, B   |   b    | A < B (беззнакове) |
| cmp A, B   |   g    | A > B (знакове)   |
| cmp A, B   |   a    | A > B (беззнакове) |

Можна додати `e` після `l`, `b`, `g` або `a`, щоб включити рівність в умову:

```x86asm
cmp rcx, r8
jge two      ; this jumps to 'two' if rcx is greater than, or equal to, r8 in a signed comparison
jbe two      ; this jumps to 'two' if rcx is lesser than, or equal to, r8 in an unsigned comparison
```

Для всіх суфіксів існують варіанти, які перевіряють протилежну поведінку.
Вони мають той самий синтаксис, але з `n` перед суфіксом.

Наприклад, `jnz` переходить, коли `ZF` **не** встановлено.
Так само `jnae` переходить, коли A **не** >= B (A і B розглядаються як беззнакові цілі числа).

~~~~exercism/note
Деякі суфікси - синоніми тих самих умов.
Наприклад, `jz` (суфікс `z`, для `ZF`) і `je` (суфікс `e`, для рівності) обидва переходять, коли `ZF` встановлено.
Це тому, що в `cmp` `ZF` встановлюється, коли віднімання дає нуль, а це відповідає рівності двох операндів.

Однак інші суфікси перевіряють комбінацію прапорців, і їх не можна безпосередньо замінити одним суфіксом для окремого прапорця.

Надавайте перевагу суфіксу, який точніше описує семантику порівняння.
~~~~

## Локальні мітки

Мітки видимі в усьому файлі вихідного коду, вони не локальні для функції.
Тому повторно використати назву мітки неможливо.

Щоб відтворити поведінку локальної мітки, NASM має спеціальну нотацію для мітки, оголошеної з крапкою (`.`) перед нею.
Ця нотація визначає мітку, яка неявно включає назву попередньої мітки без крапки:

```x86asm
section .text
fn1:
    ...
.example: ; this is fn1.example
    ...
    ret

fn2:
    ...
.example: ; this is fn2.example
    ...
    ret
```

Усе ще можна перейти до цієї мітки з будь-якого місця коду, використавши повну назву мітки, наприклад `jmp fn1.example`.

Однак перехід, який використовує частину назви мітки, починаючи з крапки, буде виконано до мітки _всередині_ зовнішньої функції.
Наприклад, `.example` поводиться так, ніби вона локальна для функції:

```x86asm
section .text
fn1:
    ...
.example:
    ...
    jmp .example ; this jumps to fn1.example

fn2:
    ...
.example:
    ...
    jmp .example ; this jumps to fn2.example
```
