# Інструкції

Ця задача змодельована за принципом невитісняльного статичного планування в операційних
системах реального часу, але також подібна до задачі планування робіт у цеху
(Job-Shop Scheduling Problem, JSP) лише з одним ресурсом. У цій задачі припускається, що
всі задачі відомі статично. Інакше кажучи, час вивільнення всіх задач тут відомий на
початку роботи програми. На практиці час вивільнення задач невідомий на старті програми
й може виникати будь-коли через введення-виведення, переривання тощо.

Для заданого масиву задач із параметрами потрібно визначити розклад, у якому задачі
виконуються послідовно, без перекриття. Оскільки задача змодельована за плануванням
процесів у RTOS, припускаємо, що між задачами потрібен ненульовий час, відомий як
накладні витрати на перемикання контексту. Існують два різні типи задач: періодичні та
динамічні. Обидва типи мають параметр ідентифікатора задачі, який є рядком тексту
(англ. string) і використовується, щоб розрізняти різні задачі в масиві задач.

**Періодична задача** визначається як задача, що виконується періодично. Інакше кажучи,
задача виконується раз на T секунд, де T позначає період.
Періодична задача описується такими параметрами:
* Час початку - час, коли починається перше повторення, або екземпляр, задачі
* Період - час між початками повторень задачі
* Час виконання - час, протягом якого виконується кожне повторення
* Час завершення - час, коли вся задача перестає плануватися

**Динамічна задача** визначається як задача, що виконується лише один раз.
Динамічна задача описується такими параметрами:
* Час вивільнення - найраніший час, коли задачу МОЖНА запланувати (НЕ те саме, що час початку)
* Час виконання - час, протягом якого виконується задача
* Крайній термін - час, до якого задача має завершити виконання

Функція, яку потрібно реалізувати, приймає два аргументи. Першим аргументом є масив
екземплярів `RealTimeTask`. Екземпляри `RealTimeTask` подаються або як екземпляри
`PeriodicRealTimeTask`, або як `DynamicRealTimeTask`, де всі параметри задачі є цілими числами.
Вбудовану функцію Python `isinstance()` можна використати, щоб розрізнити ці два типи задач
в масиві. Порядок елементів у масиві не має значення; дивимося лише на параметри задач.
Другим аргументом є одне ціле число, яке задає накладні витрати на перемикання контексту.
Накладні витрати на перемикання контексту завжди будуть невідʼємним цілим числом.

Результатом має бути словник, ключами якого є ідентифікатори задач з екземплярів
`RealTimeTask`, а значеннями - масиви двоелементних кортежів. Формат двоелементних кортежів
такий: (час початку, час завершення). Динамічні задачі мають містити в масиві лише один
двоелементний кортеж, а періодичні можуть містити більше ніж один. Порядок двоелементних
кортежів у масиві не має значення. Якщо з масиву задач із заданими накладними витратами на
перемикання контексту не вдається створити коректний розклад, потрібно викликати виняток
`NoRtosStaticScheduleProducible`. Зауважте, що результати моделі Z3 для змінних потрібно
перетворити на цілі числа, перш ніж виводити їх. Якщо результат моделі Z3 має тип
`IntNumRef`, для перетворення на ціле число можна використати метод класу `as_long()`.

Додатково надається функція, яка дає змогу візуалізувати послідовний порядок задач. Цю
функцію також можна ввімкнути для окремих тестових випадків, встановивши ключовий аргумент
`plot` у значення `True` у функції `check()`. Для побудови графіка та підписування кожної
задачі використовується діаграма з розірваними горизонтальними смугами. Щоб скористатися
цією функцією, потрібно встановити бібліотеку Python *matplotlib*. Деталі встановлення
*matplotlib* можна знайти [тут](https://matplotlib.org/stable/users/installing.html).
