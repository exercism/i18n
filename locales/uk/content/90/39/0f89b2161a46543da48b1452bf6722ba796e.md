# Основи Unison

## Терми та функції

Терми та функції - базові одиниці написання програми Unison.

«Термом» ми називаємо статичне значення. Його визначають за допомогою `name = expression`, а перед цим необовʼязково може йти сигнатура типу вигляду `name : MyType`. Unison підтримує виведення типів, тож для простих визначень сигнатуру типу часто опускають.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Функції Unison мають такий вигляд: `myFunctionName argument1 argument2 = myImplementation`; вони починаються з назви функції, після якої йдуть аргументи, розділені пробілами.

```
getMax a b = Nat.max a b
```

Функції можуть необовʼязково містити сигнатуру типу. Останній тип праворуч завжди задає підсумковий тип повернення функції, а кожен аргумент відділено стрілкою функції `->`.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Щоб викликати функцію, пишімо її назву, а далі аргументи, розділені лише пробілами.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Коли ми викликаємо функцію, Unison намагається вважати аргументом те, що стоїть безпосередньо праворуч, а це не завжди дає бажаний порядок обчислення функцій.

Припустімо, ми хочемо отримати значення `1` з такого виразу

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Як записано, `shouldBe1` обчислюється до `0`, бо неявний порядок застосування функцій такий: `getMax 1 10` дає `10`, а тоді `10 - 10` дає `0`.

Можна використати дужки, щоб перегрупувати вираз у бажаний порядок операцій.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Вирази спостереження

Unison надає спосіб швидко обчислити код, який називається «виразом спостереження». Вираз спостереження починається із символу `>`, після якого йде вираз для обчислення. Вирази спостереження можна писати в будь-якому файлі з розширенням `.u`. Після збереження файлу ми побачимо в консолі Unison Codebase Manager (UCM), до чого обчислюється вираз. Де можливо, у цих документах ми показуватимемо вираз разом із очікуваним результатом після обчислення у виразі спостереження.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Багаторядкові функції

Багаторядкові функції в Unison використовують відступи або блоки `let`, щоб задати межі коду, тобто «лексичну область видимості».

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Усе на одному рівні відступів має спільну область видимості, тому ми можемо звернутися до змінної `newBeginning` в останньому рядку.

## Простори імен та інструкції `use`

За допомогою просторів імен ми групуємо та впорядковуємо функції Unison. Їх можна уявити як аналоги «каталогів». Вони дають структуру та логічне групування.

Функції з простору імен можна ввести в область видимості за допомогою інструкції `use`.

Уявімо, ми пишемо функцію, яка використовує значення `List` з Unison. Нам знадобляться такі функції, як `List.map` і `List.flatMap`, де `List` є простором імен, а `map` і `flatMap` - функціями. Щоб не повторюватися, можна ввести все з простору імен `List` у лексичну область видимості функції ось так:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

Рядок `use List` усуває неоднозначність посилань на `map` і `flatMap`. Докладніше про інструкції `use` можна [прочитати тут][use-statements].

## Стандартна бібліотека Unison

Стандартна бібліотека Unison називається `base`. Якщо ми пройшли посібник зі швидкого старту й створили базу коду локально, стандартна бібліотека мала завантажитися автоматично. Документацію стандартної бібліотеки можна переглянути онлайн на [Unison Share][unison-share-base].

## Коментарі та літерали документації

Коментарі в Unison - доволі незвична можливість. Пишучи код Unison, ми можемо створити у файлі з розширенням `.u` текст, який не інтерпретується, за допомогою такого синтаксису:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Однак_ код Unison зберігається як хеш його абстрактного синтаксичного дерева, а не як текстові файли у файловій системі, тож коментарі, які є текстовими «прикрасами» певної функції чи терма Unison у файлі, насправді не можна зберегти й показати для інших. Якщо ми хочемо додати до свого терма Unison інформацію, яка збережеться, щоб інші могли її прочитати й зрозуміти, можна скористатися літералом документації.

Документація - значення першого класу в мові програмування Unison. Це означає, що елемент `Doc` можна присвоїти значенню, передати у функцію як значення або повернути як значення функції. Елементи літералів документації відкриваються й закриваються подвійними фігурними дужками. Ось як можна використати елемент `Doc` як коментар.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
