# розділ про коментарі

У мові Go є [ґрунтовні настанови](https://golang.org/doc/effective_go.html) щодо того, як писати коментарі. Існує стандартний формат для коментарів для документації, які інструмент `godoc` потім автоматично перетворює на гарну документацію.

Коментар до пакета має починатися зі слова `Package`, після якого йде назва пакета, ось так:

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

Для експортованих функцій, методів, констант і змінних пакета коментар має починатися з назви й продовжуватися дієслівним зворотом:

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

Вікі [CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences) додатково уточнює, що коментарі для документації мають бути повними реченнями, які закінчуються крапкою.

Окрім того, що дотримання цих рекомендацій робить код зручнішим для читання, воно ще й покращує вигляд коду в [інструментах документування Go](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/), як-от [godoc.org](http://godoc.org), `godoc` і `go doc`.

Приділіть хвилинку й прочитайте розділ про коментарі для документації в офіційному посібнику зі стилю [Effective Go](https://golang.org/doc/effective_go.html), щоб побачити міркування, з яких випливають ці рішення.
