# Контракти

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| Пункт | Що говорить | Чия провина, якщо порушено |
| --- | --- | --- |
| `pre` | що має виконуватися на вході | того, хто викликає |
| `post` | що виконується на виході | підпрограми |

Обидва приймають `BOOL` і можуть використовувати аргументи підпрограми та атрибути обʼєкта. `post` також може використовувати `result`, значення, яке повертається.

## assert

У тілі підпрограми `assert` стверджує щось, що має бути правдою в цій точці:

```sather
      assert load <= limit;
```

Він перевіряється тим самим перемикачем, що й інші.

## Інваріанти класу

Клас може стверджувати щось, що є правдою для кожного свого обʼєкта між викликами:

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

Перевіряється на вході та виході кожної публічної підпрограми, коли перевірку ввімкнено.

## Увімкнення

| Прапорець | Що перевіряє |
| --- | --- |
| `-chk` | усе: pre, post, assert, invariant, bounds, arithmetic |
| `-chk_no` | нічого |

Зауважте, що `-chk_pre` сам по собі *не* вмикає перевірку передумов у цьому компіляторі; працює саме `-chk`. Порушення виводить підпрограму та рядок коду і зупиняє програму. Це не виняток, і `protect` його не перехопить.

Зазвичай розробляють і тестують із `-chk`, а постачають без нього, щоб перевірки нічого не коштували в готовій програмі. Це виправдано лише тоді, коли тести справді проходять ці шляхи.

## Що робить контракт хорошим

Скажімо, що потрібно підпрограмі, а не як вона працює:

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

`post`, який переказує тіло, нікого нічого не навчить:

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## Успадкування

Підтип може послабити `pre` і підсилити `post` (приймати більше, обіцяти більше), але ніколи навпаки, інакше код, написаний для надтипу, зламається. Це те правило, яке контракти покликані зробити перевірюваним.
