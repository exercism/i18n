# Абстрактні класи

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## Символ $ входить до назви

Назва кожного абстрактного класу починається із символу `$`, і так називають
лише абстрактні класи. Тож тип, назва якого починається з `$`, не дозволяє
створити обʼєкт, і це видно всюди, де трапляється така назва.

## Що може міститися в ньому

Сигнатури процедур і ітераторів, що закінчуються крапкою з комою. Жодних
тіл, жодних атрибутів, жодного `create`. Абстрактний клас описує, що можна
*запитати* в чогось, але ніколи те, що воно містить.

## Відповідність

```sather
class TRAPEZE < $ACT is
```

Клас повинен визначити кожну перелічену процедуру, з відповідними типами
аргументів і типом поверненого значення. Це перевіряється під час компіляції.

Клас може відповідати кільком одразу:

```sather
class TRAPEZE < $ACT, $RISKY is
```

а абстрактні класи можуть розширювати один одного:

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## Де відбувається диспетчеризація

Змінна абстрактного типу містить посилання на якийсь обʼєкт, що відповідає
цьому типу. Коли ми викликаємо процедуру на такій змінній, обирається версія,
що належить справжньому класу обʼєкта, під час виконання.

Це єдине місце, де Sather ухвалює рішення під час виконання. Виклик на змінній
конкретного типу визначається під час компіляції.

## typecase

Іноді вид справді має значення. `typecase` запитує:

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

Усередині гілки змінна має вужчий тип. Вдаваймося до цього рідко: `typecase`
для кожного виду дії зазвичай означає процедуру, якій і місце в абстрактному
класі.

## $OB

Кожен обʼєкт відповідає абстрактному класу `$OB`. Іноді він буває корисним,
але найчастіше означає, що тип десь загубився.

## А чому не успадкування?

Sather розділяє дві речі, які більшість мов обʼєднує. `<` каже лише те, що
клас може *робити*. Реалізацію з іншого місця дає `include`, до якого ми
дійдемо через одну вправу, і це окреме рішення.
