# Трейти

Трейт визначає набір методів, які тип може реалізувати.
Трейти корисні для визначення методів, які мають бути спільними для різних типів.
Коли трейти використовуються з узагальненими типами, визначені методи можна викликати для конкретного типу, але також можна викликати їх і для іншого типу даних.
Якщо говорити абстрактно, за допомогою _обмежень трейту_ ми можемо вказати, що узагальнений тип повинен мати певну поведінку.

> **Примітка:** Трейти мають спільні риси з тим, що в інших мовах програмування називають інтерфейсами, але з деякими відмінностями.

## Визначення трейту

Визначення трейту допомагає окреслити сигнатури функцій, які складають набір поведінок, що їх тип може реалізувати для досягнення результату.
Ці методи формують поведінку типу.
Якщо ми можемо викликати ті самі методи для різних типів, це означає, що задіяні типи мають однакову поведінку.

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

Згідно з наведеним вище визначенням трейту `Summary`, метод `summarize` є поведінкою, яку можна викликати лише для типу структури `NewsArticle`.
Якщо викликати його для екземплярів іншого типу, це спричинить помилку компіляції.
Оголошення трейту з ключовим словом `pub` робить трейт у цьому крейті доступним для інших крейтів, які теж мають намір його використовувати.
Звернімо також увагу, що після оголошення сигнатур методів у трейтах ми ставимо крапку з комою.

Трейт можна визначити з узагальненим аргументом, що дає змогу функції приймати аргумент будь-якого типу даних.
Це додає гнучкості сигнатурі функції, дозволяючи їй працювати з різними типами даних.
У випадку трейту `Summary` нижче його перероблено так, щоб він працював з будь-яким типом даних: коли для них викликається метод `summarize`, він повертає ByteArray.

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

Трейт може містити більше ніж один метод у своєму тілі; кожна оголошена сигнатура методу записується одним рядком і закінчується крапкою з комою.

## Реалізація трейту для типу

Після визначення сигнатур функцій, з яких складається трейт, компілятор вимагатиме, щоб для типів, які приймають цей трейт, було так само визначено реалізацію.
Нижче ми написали бібліотечний крейт `aggregator` для медіа, який підсумовує деякі дані з екземплярів `NewsArticle` та `Tweet`.
Для структури `NewsArticle` ми використаємо заголовок, автора та місце, щоб повернути значення для методу `summarize` з трейту `Summary`, а для структури `Tweet` використаємо імʼя користувача та вміст, припускаючи, що вміст твіта обмежено 280 символами.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## Типові реалізації

Іноді трейт можна визначити з типовою реалізацією для частини або й усіх методів, з яких він складається.
Це робиться, щоб не вимагати реалізації всіх методів для кожного типу, а також для кращої читабельності коду.
Якщо якомусь конкретному типу потрібна особлива реалізація методу трейту, він може перекрити типову реалізацію.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## Як використовувати зовнішні трейти та керувати ними

Трейти та реалізації можна визначати в зовнішньому модулі й використовувати в інших модулях, якщо їх належно імпортовано.
Припустімо, у нас є трейт `ShapeGeometry` з методом `boundary`, який потрібно реалізувати і для структури `Circle`, і для структури `Rectangle`.
Нижче наведено приклад того, як імпортувати, супроводжувати та використовувати трейт і реалізацію в різних модулях.

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

Видимість реалізацій `CircleGeometry` та `RectangleGeometry` не обовʼязково робити публічною, оскільки трейт `ShapeGeometry` зроблено публічним, і компілятор має легко його знаходити.

## Псевдоніми impl

Реалізації можна перейменовувати за допомогою псевдонімів під час імпорту, використовуючи ключове слово `impl`.
Це допомагає, коли потрібно інстанціювати узагальнену реалізацію для конкретних типів.
Визначмо просту реалізацію трейту `Two` для всіх типів, які реалізують трейт `One`, просто додавши значення `One` двічі та повернувши суму.
Після цього ми можемо надати реалізацію `Two`, яка працює лише для типів `u8` та `u128`.

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

Узагальнену реалізацію можна записати в приватному модулі, а за допомогою псевдоніма impl ми можемо інстанціювати узагальнену реалізацію для цих двох конкретних типів.
Перевага приватної та неоприлюдненої узагальненої реалізації в тому, що вона запобігає дублюванню коду між файлами.
Це також зберігає публічний API простим і чистим.
