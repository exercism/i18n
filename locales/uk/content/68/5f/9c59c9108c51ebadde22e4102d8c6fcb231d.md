# Інструкції

Наш друг Лінус працює машиністом локомотива й водить вантажні потяги між містами.
Хоч він чудово дає раду потягам, із логістикою та компʼютерами в нього не так добре.
Він хотів би, щоб ми допомогли йому з програмуванням: упорядкували дані про потяги та виправили помилки в даних маршрутів.

~~~~exercism/note
Цю вправу можна було б легко розвʼязати за допомогою зрізів, індексації та різних методів `hash`.
Однак, розвʼязуючи кожне із завдань нижче, ми хочемо попрактикувати пакування, розпакування та множинне присвоєння.
~~~~

## 1. Створити масив усіх вагонів

Наш друг веде облік ідентифікаторів (ID) кожного вагона, але ніколи не знає наперед, скільки вагонів системі доведеться обробити.
Решті логістичної програми було б набагато простіше, якби ці дані були запаковані в один **масив**.

Реалізуйте метод `generate_list_of_wagons()`, який приймає довільну кількість ID вагонів.
Кожен ID - додатне ціле число.
Далі метод має повернути (`return`) передані ID як один **масив**.

```ruby
LocomotiveEngineer.generate_list_of_wagons(1, 7, 12, 3, 14, 8, 5)
# => [1, 7, 12, 3, 14, 8, 5]
```

## 2. Виправити масив вагонів

На цьому етапі ми вже потроху розуміємо дані та те, як вони використовуються в логістичній програмі.
Система ID завжди присвоює локомотиву ID **1**, а решті вагонів у потязі - випадково вибраний ID, більший за **1**.

Наш друг причепив до потяга два нові вагони й забув оновити систему!
Тепер перші два вагони в **масиві** потяга треба перемістити в кінець, інакше порядок порушиться.

А щоб було ще складніше, наш друг щойно знайшов другий **масив**, який, схоже, містить зниклі ID вагонів.
Він памʼятає лише, що після переміщення нових вагонів ID із цього другого **масиву** треба поставити одразу після локомотива.

Лінус буде дуже вдячний нам за виправлення його помилок і впорядкування даних.

Реалізуйте метод `fix_list_of_wagons()`, який приймає два **масиви** з ID вагонів.
Він має перемістити перші два елементи першого **масиву** в кінець і вставити значення з другого **масиву** позаду (_праворуч від_) ID локомотива (**1**).
Далі метод має повернути (`return`) **масив** із цими змінами.

```ruby
LocomotiveEngineer.fix_list_of_wagons([2, 5, 1, 7, 4, 12, 6, 3, 13], [3, 17, 6, 15])
# => [1, 3, 17, 6, 15, 7, 4, 12, 6, 3, 13, 2, 5]
```

## 3. Додати відсутні зупинки

Тепер, коли всі дані про вагони правильні, Лінус хотів би, щоб ми оновили інформацію про маршрути системи.
На транспортному маршруті потяг може зупинятися на кількох різних станціях, щоб узяти й/або залишити вантаж.
У кожної подорожі може бути різна кількість таких проміжних точок доставки.
Наш друг хотів би, щоб ми оновили **хеш** маршрутизації системи, додавши будь-яку відсутню або додаткову інформацію про доставку.

Реалізуйте метод `add_missing_stops()`, який приймає **хеш** маршрутизації, а далі довільну кількість іменованих аргументів.
Ці аргументи можуть бути подані як **хеш** з однією чи кількома зупинками або як будь-яка кількість пар іменованих аргументів `stop_<number>: "city"`.
Далі метод має повернути **хеш** маршрутизації, доповнений додатковим **ключем**, який містить **масив** усіх доданих зупинок у порядку.

```ruby
LocomotiveEngineer.add_missing_stops({from: "New York", to: "Miami"},
                    stop_1: "Washington, DC", stop_2: "Charlotte", stop_3: "Atlanta",
                    stop_4: "Jacksonville", stop_5: "Orlando")
# => {from: "New York", to: "Miami", stops: ["Washington, DC", "Charlotte", "Atlanta", "Jacksonville", "Orlando"]}
```

~~~~exercism/note
Зупинки завжди передаються в правильному порядку, тож про їхнє сортування дбати не потрібно.
~~~~

## 4. Розширити інформацію про маршрути

Лінус працював над програмою маршрутизації й помітив, що в деяких маршрутах бракує важливих деталей.
Початкову інформацію про маршрут побудовано як **хеш**, і наш друг хотів би, щоб ми доповнили цей **хеш** усім, чого бракує.
Кожен маршрут у системі потребує трохи інших деталей, тож Лінус дуже хотів би мати універсальне рішення.

Реалізуйте метод `extend_route_information()`, який приймає два **хеші**.
Перший **хеш** містить міста відправлення й прибуття, між якими пролягає маршрут потяга.

Другий **хеш** містить інші деталі маршруту, як-от швидкість, довжину чи температуру.
Метод має повернути зведений **хеш** з усією інформацією про маршрут.

~~~~exercism/note
Другий **хеш** може містити інші або додаткові властивості, ніж ті, що показані в прикладі.
~~~~

```ruby
LocomotiveEngineer.extend_route_information({"from": "Berlin", "to": "Hamburg"}, {"length": "100", "speed": "50"})
# => {"from": "Berlin", "to": "Hamburg", "length": "100", "speed": "50"}
```
