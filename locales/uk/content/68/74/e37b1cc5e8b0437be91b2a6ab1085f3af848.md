# Докладніше

[concept:csharp/resource-cleanup]() використовує інтерфейс `IDispose`, щоб подати сигнал тим, хто викликає клас: є ресурси або стан програми, які потрібно вчасно звільнити чи скинути, коли відповідний обʼєкт більше не потрібен. У цій вправі ми додали трохи синтаксичного цукру, а саме ключове слово `using`, завдяки якому код стає менш багатослівним і менш схильним до того, що важливі виклики буде пропущено.

`using` можна розглядати як заміну [`try/finally`][try-finally] для деяких випадків використання.

```csharp
File file = null;
try
{
    file = new File("myStuff.txt");
    file.Write("more stuff");
}
finally
{
    file.Dispose();
}
```

Цей синтаксис замінюється на компактніший і надійніший:

```csharp
using (var file = new File("myStuff.txt")
{
    file.Write("more stuff");
}
```

Зауважмо, що кілька ресурсів можна зручно поєднати, дотримуючись стандартних правил для однорядкових блоків:

```csharp
using (var file = new File("mystuff.txt")
using (var fileWriter = new StreamWriter(file)
{
     ...
}
```

У C# 8 було додано такий варіант, де інструкція `using` стоїть на початку блоку:

```csharp
using var file = new File("myStuff.txt");
file.Write("more stuff");
```

Це дає змогу мати кілька обʼєктів, які потребують звільнення, в одному блоці та природніше обробляти [`try/catch`][try-catch]:

```csharp
using var fileIn = new File("myStuff.txt");
using var fileOut = new File("yourStuff.txt");
try
{
    var stuff = fileIn.Read();
    fileOut.Write(stuff);
}
catch (Exception)
{
    LogStuff();
}
```

Правила щодо того, як можна використовувати ключове слово `using` і з примірниками яких типів, докладно описано [тут][using-statement].

## Примітка для розробників Java

Розробники Java можуть упізнати в цьому аналог механізму [_автоматичного керування ресурсами_][automatic-resource-management], доданого в Java 7. Вони дуже схожі. Синтаксис Java, який перепрофілює `try`, має перевагу: він природніше вбудовує блоки `catch`, ніж `using` у C#.

## Версії

Зауважмо, що гнучкіший варіант `using`, який не має власного синтаксичного блоку, було додано в C# 8, тож, можливо, варто перевірити, чи база коду, з якою ми працюємо, використовує C# 8 чи новішу версію.
