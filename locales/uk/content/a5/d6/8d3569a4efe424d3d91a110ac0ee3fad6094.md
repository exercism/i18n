# Вступ

Більшість слів для послідовностей, які ми вже бачили, повертають *нові* послідовності й не чіпають своїх вхідних даних: `suffix`, `reverse`, `map` тощо.
Але масиви й вектори також підтримують **мутацію на місці**, і те, і те стає в пригоді, коли ми хочемо зафіксувати стан, який змінюється з часом.

## Два різновиди змінюваної послідовності

- **Масиви** (`{ … }`) мають фіксовану довжину. `<array> ( n elt -- array )` (у [`arrays`][arrays]) створює новий масив довжини `n`, заповнений копіями `elt`.
- **Вектори** (`V{ … }`) збільшуються й зменшуються. Щоб отримати новий порожній вектор, скористаймося `V{ } clone`; `<vector> ( n -- vector )` (у [`vectors`][vectors]) заздалегідь виділяє місткість для `n` елементів.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## Зміна комірки

Ці два слова працюють з обома видами послідовностей. Обидва приймають послідовність після індексу:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth` присвоює значення; `change-nth` застосовує quotation до елемента на позиції `n`.
Обидва ці слова з [`sequences`][sequences] нічого не повертають на стек: їхній ефект саме в мутації.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## Зростання й зменшення

Ці три мають сенс лише для векторів, бо масиви не можуть змінювати довжину:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## З вектора в масив

Коли ми накопичили вектор і хочемо повернути масив фіксованої довжини, `>array ( seq -- array )` (у [`arrays`][arrays]) повертає новий масив із тими самими елементами:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`: зберігаємо знімок

Мутація змінює послідовність на місці. Якщо хтось передає нам послідовність і ми збираємося її змінити, `clone` (у [`kernel`][kernel]) дає нам нову незалежну копію, щоб у того, хто її передав, нічого не змінилося:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

Той самий запобіжний захід стосується `V{ }` та інших порожніх літералів. У деяких мовах `[]` або `vec![]` виділяє новий контейнер щоразу, коли обчислюється вираз. У Factor літерал `V{ }`, записаний у нашому коді, є *одним* обʼєктом, спільним для кожного місця виклику, яке його згадує. Якщо ми зробимо `push` безпосередньо в `V{ }`, наступний виклик побачить залишки. `V{ } clone` створює ту нову копію, яку ми майже завжди й хочемо.
