# Про

`String` і `&str` - це два фундаментальні способи роботи з текстовими даними в Rust.
Розуміння їхніх характеристик і того, як вони працюють разом, дуже стає в пригоді.
У цьому документі ми розглянемо, як вони перетинаються, і дамо кілька базових порад.
`String` - це вектор байтів `u8`, який володіє своїми даними.
`String` можна змінювати.
`&str` - це позичене посилання на зріз String.
`&str` не можна змінювати.

Правильно вимовляти `&str` як «ref string».
`String` - це потенційно змінне подання послідовності кодових точок Unicode у кодуванні UTF-8.

`&str` дає змогу лише читати правильно сформовану послідовність UTF-8.
Оскільки це посилання, воно реалізує `Copy` і ним можна ділитися.

У Rust до `String` і `&str` не можна звертатися за індексом так, як це роблять в інших мовах.
Наприклад, ось це не працюватиме:

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

Це випливає з таких властивостей:

- Рядки тексту (англ. string) кодуються в UTF-8, і їхньою елементарною одиницею є не байт, а кодова точка Unicode: `char`.
- Кодові точки Unicode займають до 4 байтів, але кодуються зі змінною шириною.
- Тому обчислити позицію `n`-ї кодової точки неможливо, не перебравши фактично закодовані символи, адже після першого символу позиція наступного залежить від того, якої ширини були попередні.
- Тому автори стандартної бібліотеки Rust вирішили не реалізовувати трейт `Index` для рядків тексту: індексування масиву байтів займає сталий час, а індексування рядка тексту може тривати досить довго. Це порушує принцип найменшого подиву.

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## Перетворення `String` на `&str`

`String` реалізує `Deref<Target=str>`.
Для цього трейту компілятор має особливу підтримку: будь-яке посилання на `String` може автоматично й прозоро приводитися до `&str`.
Із цього випливає таке:

- Будь-який код, який, наприклад, приймає аргумент `&str`, може натомість прийняти `&String`.
- Будь-який метод, реалізований для `&str`, можна викликати і для `String`.

(Якби ми хотіли узагальнено приймати будь-яку форму посилання на `str`, можна було б узяти аргумент типу `impl AsRef<str>`, але зазвичай аргументи типізують як `&str`, і це поширено.)

## Перетворення `&str` на `String`

Існує багато способів створити `String` з `&str`:

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

Усі ці способи вимагають виділення памʼяті для `String` (у купі).
Саме тому `&str` доступний у no_std, а `String` - ні.

(Для роботи з рядками тексту в no_std часто використовують крейт [heapless](https://crates.io/crates/heapless).)

## Використання String і `&str` у структурах

У цьому розділі ми розглянемо, коли для полів структури використовувати `String`, а коли `&str`.
Структури часто визначають із `String`, а не з `&str`, для значень полів.

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

Використовуючи `String`, структура володіє даними.
Завдяки цьому код легше читати, і його простіше пояснювати початківцям.
Але це також означає, що для кожного поля відбуватиметься виділення памʼяті в купі.
`&str` позичає текстові дані, тож працюватиме швидше, але за це структура має визначати параметри часу життя.
У [посібнику з крейту csv][csv-tutorial] ці ідеї досить вдало показано на практиці й пояснено.

## Зауваження щодо продуктивності

Значення `String` виділяються в купі, тож користуватися ними може бути дорожче.
`&str` - це спільне посилання, тож воно не потребує частого повторного виділення памʼяті.
