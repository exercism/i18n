# Вступ

## JSON

JSON (JavaScript Object Notation) - це людиночитний формат даних і файлів, який часто використовують для обміну даними, зокрема у вебзастосунках.
Тож не дивно, що він посідає особливе місце в мові Elm.

Elm надає базові модулі `Json.Decode` і `Json.Encode`, щоб розбирати й записувати дані JSON.
JSON-декодери - це спосіб _оголосити_, який тип даних має приймати декодер і на яку структуру даних ці дані мають відображатися.

Імпортуймо кілька псевдонімів і типів із цих модулів:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Якщо використати `Decode.decodeString : Decoder a -> String -> Result Error a` із декодером і рядком JSON, то операція або завершиться успішно, якщо рядок відповідає специфікації декодера, або зазнає невдачі в іншому разі.
Немає способу оглянути необроблені дані JSON під час визначення декодера, що може здатися незвичним тим, хто звик до імперативних мов.

## Базові декодери типів даних

JSON має невелику кількість базових типів даних:

- Рядок тексту (англ. string): кодується подвійними лапками `"hello world"`
- Булеве значення (англ. Boolean): або `true`, або `false`
- Число: наприклад, `34` або `0.12`
- Null: відсутність даних `null`

Кожен із них повʼязаний з відповідною функцією `Decode`:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Зауважмо, що `Decode.null` дає змогу вирішити, як моделювати `null` у нашій програмі, вимагаючи довільне значення як аргумент (можливо, `()`, `Nothing` або будь-що доречне для нашої програми).

## Поєднання декодерів

JSON також визначає дві структури даних для збирання базових типів даних:

- Масив: набір інших типів даних `[0, null, "none", []]`
- Обʼєкт: набір пар ключ-значення `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` також пропонує функції для декодування цих структур:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Ці функції `Decode.list : Decoder a -> Decoder (List a)` і `Decode.dict : Decoder a -> Decoder (Dict String a)` приймають декодер як аргумент, який має декодувати кожен окремий елемент структури даних.
Якщо декодер-аргумент не може декодувати якийсь елемент масиву чи обʼєкта, то весь декодер зазнає невдачі, що є поширеним прийомом.

Поєднання простих декодерів у складніші - це основна ідея цієї техніки.
Ми розглянемо ще кілька функцій, які можна використати, щоб побудувати довільно складні декодери реальних даних, на прикладі.

## GeoJSON

Щоб потренуватися поєднувати базові декодери для розбору складних даних JSON, побудуймо декодери для розбору (підмножини) даних GeoJSON.
GeoJSON - це спеціалізований формат даних на основі JSON, який використовують для подання географічних обʼєктів, як-от місцевості, шляхи чи регіони, задані двовимірними або тривимірними географічними координатами, разом з іншими властивостями.

### Геометричний обʼєкт

Геометричний обʼєкт GeoJSON - це обʼєкт, який містить поле `type` зі значенням рядка тексту (можливі 7 значень типу) і поле `coordinates` з географічними координатами (зібраними в структуру, що залежить від типу).
Наприклад,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

або

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Геометричний обʼєкт можна представити в Elm таким типом

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Щоб отримати значення певного поля, можна використати `Decode.field : String -> Decoder a -> Decoder a`, який декодує значення конкретного ключа обʼєкта.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Щоб перетворити значення, успішно розібране декодером, можна використати `Decode.map : (a -> value) -> Decoder a -> Decoder value` або будь-яку з його супутніх функцій, від `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` до `Decode.map8`.

У цьому випадку ми хочемо вирішити, який декодер координат використати залежно від значення в полі `type`, і для цього ідеально підходить `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` та його супутники `Decode.succeed : a -> Decoder a` і `Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

Зауважмо, що на цьому етапі ми могли б використати `Decode.andThen`, щоб перевірити координати (переконатися, що координати йдуть парами або трійками, і що їхні значення мають географічний сенс).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### Обʼєкт Feature

Обʼєкт Feature у GeoJSON представляє щось просторово обмежене: він має поле `type` зі значенням `"Feature"`, поле `geometry` з геометричним обʼєктом або `null`, поле `properties` з довільним обʼєктом JSON або `null`, і необовʼязкове поле `id` зі значенням рядка тексту або числа JSON.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

або

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Розгляньмо спершу поле `id`.
Якщо воно існує, воно має вміщати рядки тексту або числа, тож ми могли б або ввести власний тип для значення, або завжди зберігати його як рядок тексту.

Щоб вибрати між двома можливими декодерами, можна використати `Decode.oneOf : List (Decoder a) -> Decoder a`.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Щоб зазначити, що поле необовʼязкове, можна скористатися тим самим прийомом

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Але натомість можна використати `Decode.maybe : Decoder a -> Decoder (Maybe a)`

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Зауважмо, що `decodeMaybeFeatureId` (або будь-який декодер, обгорнутий у `Decode.maybe`) завжди завершується успішно, бо завжди може повернутися до `Ok Nothing`, хоча декодер, який його використовує, усе одно може зазнати невдачі

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

Далі зосередьмося на полі `geometry`, яке може бути або геометричним обʼєктом, або `null`.
Ми могли б знову використати `Decode.oneOf`, але є кращий варіант: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` і `Decode.nullable` мають однакову сигнатуру, але поводяться по-різному, бо результат `OK Nothing` у `Decode.nullable` може виникнути лише з конкретного значення JSON `null`.

Нарешті, поле `properties` може містити довільний обʼєкт JSON або `null`, і для цього підходить `Decode.value : Decoder Value`.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Зауважмо, що `Value` - це непрозорий тип, а отже, не можна легко дослідити його вміст.
Щоб його використати, можна або написати для нього декодер і запустити його за допомогою `Decode.decodeValue : Decoder a -> Value -> Result Error a`, або надіслати його безпосередньо в JavaScript через порт.

Ми готові розбирати обʼєкти Feature:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## Енкодери JSON

Енкодери дають змогу записувати коректний JSON зі значень Elm за допомогою функції `Encode.encode : Int -> Value -> String`.
Перший аргумент задає розмір відступу в остаточному результаті, а другий - значення JSON, яке треба записати.

`Value` можна або отримати з `Decode.value`, або створити за допомогою одного з енкодерів:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

а також за допомогою `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Визначмо енкодери для декодерів GeoJSON, визначених раніше

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

Загалом, хороший тест для пари декодер-енкодер полягає в перевірці того, що `elmValue |> encoder |> decoder == elmValue`.
