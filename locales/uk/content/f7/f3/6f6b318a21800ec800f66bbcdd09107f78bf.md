# Докладніше

Функція вважається [хвостово-рекурсивною][recursion-tc], якщо _останнє_, що вона виконує, це виклик самої себе.

Щоразу, коли викликається якась функція, на вершину [стеку викликів][call-stack] додається _кадр стека_ з її локальними змінними й аргументами.
Коли функція завершує роботу, її кадр стека знімається зі стека.

Хвостово-рекурсивні функції дають змогу застосувати [оптимізацію хвостового виклику][tail-call-optimization] (або усунення хвостового виклику).
Це оптимізація, яка дозволяє наступному виклику функції використати той самий кадр стека, коли попередня функція вже точно його не потребує.
Це зменшує ризик переповнення стеку викликів, тобто ситуації, коли кадрів у стеку викликів так багато, що для створення нового вже не залишається памʼяті.

## Оптимізація хвостового виклику в Elm

За певних умов компілятор Elm здатен автоматично виконати оптимізацію хвостового виклику під час компіляції в JavaScript.

Оптимізація можлива для рекурсивної функції, коли _остання_ операція в гілці полягає у виклику самої функції простим застосуванням функції.
Розглянемо кілька прикладів:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

Наведена вище реалізація не є хвостово-рекурсивною, бо остання операція в гілці `else` полягає в множенні `n *`.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

Наведена вище реалізація хвостово-рекурсивна, і її буде оптимізовано, бо остання операція в гілці `else` полягає в тому, що `factorialHelper` викликає сам себе.
Це було б неможливо для функції з сигнатурою типу `Int -> Int`, і на практиці оптимізації хвостового виклику часто досягають, визначаючи допоміжні функції.

## Крайні випадки

У деяких випадках компілятор не може оптимізувати рекурсивні функції. Розглянемо кілька прикладів.

Хоча `f x = f (x - 1)` хвостово-рекурсивна, `f x = (x - 1) |> f` ні, бо останньою операцією тут є застосування функції `|>`, яке вважається окремим від `f`.
Так само функції, що закінчуються булевими умовами (англ. Boolean) `f x = x > 0 || f (x - 1)`, не є хвостово-рекурсивними.

Функція `f x = if f (x - 1) then 1 else 0` не є хвостово-рекурсивною, бо вираз у `if` не вважається гілкою.
Так само рекурсивний виклик у конструкції `case` теж не буде оптимізовано.

Функція `f x = let y = f (x - 1) in y` не є хвостово-рекурсивною, бо вона викликає себе в конструкції `let`, яка не вважається гілкою.
Однак у `f x = let g x = g (x - 1) in g x` функція `g` хвостово-рекурсивна, і її буде оптимізовано, навіть попри те, що вона визначена в конструкції `let`.

Функція `f x = if x > 0 then f (x + 1) else 1 + f x` буде оптимізована _частково_: гілку `then` можна оптимізувати, а гілку `else` ні.
Часткова оптимізація - це найкраще, чого можна досягти в деяких ситуаціях, як-от обхід деревоподібних структур чи визначення корекурсивних функцій.
