# Вступ

## Нульові посилання

Якщо нам уже доводилося працювати з іншою мовою програмування (C/C++, Python, Java, Ruby, Lisp тощо), то ми, найімовірніше, вже стикалися з `null` або `nil`.
За допомогою `null` або `nil` ці мови позначають, що певна змінна не має значення.
Однак через це випадкове використання змінної зі значенням `null` стає легкою (і частою) помилкою.
Як неважко уявити, спроба викликати функцію, якої немає, або отримати доступ до значення, якого не існує, може призвести до найрізноманітніших багів і збоїв.
Творець `null` навіть назвав його своєю [«помилкою на мільярд доларів»][billion-dollar-mistake].

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## Тип `Option`

Щоб уникнути цих проблем, змінні в Cairo можуть використовувати enum `Option`, аби безпечно позначити відсутність значення.
Цей enum має два варіанти: `None` - аналог `null` у Cairo; і `Some(T)`, де `T` - значення будь-якого типу.

Він має такий вигляд:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

`Option` можна уявити як прошарок безпеки між нами і проблемами, які можуть спричинити нульові посилання, і який водночас зберігає їхню концептуальну користь.

## Використання `Option`

Присвоїти змінній `None` досить просто:

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

Однак, якщо ми хочемо, щоб тип `Option` ніс у собі значення, присвоїти це значення напряму не вийде.
Змінна типу `Option` і, скажімо, змінна типу `i32` не є еквівалентними.
Потрібно використати `Some`:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

З тієї ж причини не спрацює й таке:

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

Щоб отримати значення, яке містить `Some`, спочатку потрібно перевірити, чи воно там є:

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

У Cairo є й інші інструменти, крім `match`, для перевірки та доступу до значень, що містяться в `Option`, але `match` уже має бути нам знайомим.

Нехай це буде демонстрацією того, чому Cairo використовує `Option` замість нульового посилання.
Річ у тім, що **ми _мусимо_ перевірити**, чи змінна `Option` дорівнює `Some` (і тоді можна сміливо дістати й використати значення, яке в ній міститься), чи `None`.
Інакше наша програма не скомпілюється; компілятор захищає нас від `null`.
