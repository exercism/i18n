# Докладніше

Ruby - це динамічна мова зі строгою типізацією.
У динамічних мовах тип змінної чи обʼєкта визначається під час виконання, а це означає, що її значення чи тип можна змінити аж до останнього моменту (коли його розбирає інтерпретатор).
А що ми маємо на увазі під строгою типізацією?
Коли нам уже відомий тип змінної чи обʼєкта, Ruby суворо стежить за тим, що з ним можна робити, наприклад:

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**Але**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

Памʼятаймо, що в Ruby все - це обʼєкт.
Навіть класи - це екземпляри класу `Class`.

Наприклад:

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

Це означає, що ми можемо також визначати класи ось так:

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

І наостанок, маймо на увазі, що обʼєкт `Integer` містить значення, які можна записати як одну чи більше (послідовних) цифр, а його методи підтримують багато [математичних операторів][integers-docs].

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
У документації часто посилаються на методи екземплярів у синтаксисі на кшталт `Class#method_name`, тоді як методи рівня класу чи модуля записують як `Class::method_name`.
`::` називають _оператором розвʼязання області видимості_, і він указує на константу чи метод на рівні класу або модуля.
Ми зустрінемо це в документації Ruby, у списках розсилки та в інших місцях, де надають підтримку.
У нашому тексті ми, натомість, посилаємося на методи класу чи модуля як `ClassName.method_name` або `ModuleName.method_name`.
~~~~
