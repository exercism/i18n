# Докладніше

Рекурсивна функція викликає саму себе.

Рекурсивна функція повинна мати щонайменше один _базовий випадок_ і щонайменше один _рекурсивний випадок_.

_Базовий випадок_ повертає значення, не викликаючи функцію знову.
_Рекурсивний випадок_ викликає функцію знову, змінюючи вхідні дані так, щоб колись вони збіглися з базовим випадком.

У Elm рекурсивні функції зазвичай визначають за допомогою зіставлення зі зразком у виразах `case`.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

Рекурсивна функція може мати багато базових випадків і/або багато рекурсивних випадків.
Наприклад, [послідовність Фібоначчі][fibonacci] є рекурсивною послідовністю з двома базовими випадками:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

Зауважмо, що ця конкретна реалізація працює експоненційно повільно, бо повʼязані числа Фібоначчі обчислюються з нуля у двох незалежних рекурсивних викликах.

Підрахунок кількості входжень деякого заданого значення `x` у масиві має два рекурсивні випадки:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## Цикли через рекурсію

Через незмінність цикли в Elm пишуться інакше, ніж в імперативних мовах.
Наприклад, цикли зазвичай мають такий вигляд:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

У функціональній мові, як-от Elm, змінювати змінні неможливо.
Тож цикли доводиться реалізовувати через рекурсію.

Аналог циклу `for` в Elm мав би такий вигляд:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

На практиці перебирання масивів та інших структур даних в Elm найчастіше виконують за допомогою функцій із модуля [`List`][module-list], як-от `List.map`, `List.filter` і `List.foldl`.
Усередині ці функції реалізовано через рекурсію.

## Нескінченне виконання

Рекурсивні функції, якщо їх реалізовано неправильно або кількість рекурсивних викликів завелика, можуть так і не повернути свій результат.
Це може бути проблемою, бо щоразу, коли функція викликається, у памʼяті зберігається посилання на місце, куди середовище виконання має повернути результат (у [стеку викликів][wiki-call-stack]).
Якщо рекурсивна функція викликає себе забагато або навіть нескінченно, може забракнути памʼяті, і середовище виконання аварійно завершиться ([помилка переповнення стека][wiki-stack-overflow]).
Середовище виконання Elm оптимізовано для рекурсії та надійності, але нескінченна рекурсія все одно може спричинити проблеми.

Цю проблему нескінченного виконання можуть спричиняти:

- Забутий базовий випадок.
- Необроблені всі можливі випадки під час зіставлення зі зразком.
- Неправильна зміна аргументу під час рекурсивного виклику, через що базовий випадок ніколи не досягається.
