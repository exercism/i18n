# Про це

## Вступ

Непрозорі типи - це техніка інкапсуляції в Elm.
Дехто також називає це приховуванням інформації або приховуванням деталей реалізації.
Їх також часто використовують, щоб забезпечити валідацію за допомогою підходу [Parse, dont validate][parse-dont-validate].
Наприклад, можна мати непрозорий тип `EmailAddress`, який може містити лише коректні адреси електронної пошти (на відміну від `String`, який може містити будь-що).

## Створення непрозорого типу

[Власні типи][custom-types] мають один або кілька *варіантів*, і компілятор автоматично генерує функцію для створення кожного *варіанта*, використовуючи назву *варіанта*.
Це єдиний спосіб створити власний тип.
Компілятор також дозволяє деструктуризацію цих варіантів.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

Спочатку все це є внутрішнім для файлу чи модуля, і ми використовуємо ключове слово `exposing`, щоб вибрати, що експортувати.
Щоб створити непрозорий тип, достатньо не експортувати *варіанти*.

Коли ми так робимо, майже завжди потрібно надати інший спосіб створювати й отримувати *варіанти*, експортувавши власні функції.
Ці власні функції дають змогу застосовувати певну логіку під час створення й отримання *варіантів*.
Це приховує внутрішні деталі реалізації модуля і означає, що деталі реалізації можна змінювати як завгодно, аби лише експортовані функції залишалися тими самими.

## Parse, don't validate

Найчастіше непрозорі типи застосовують, щоб забезпечити валідацію за допомогою підходу [Parse, dont validate][parse-dont-validate].
У цьому підході ми експортуємо функцію, яка приймає вхідні дані з меншою структурою чи меншою типобезпекою, ніж потрібно, наприклад `String`, а потім розбирає їх у структурованіший тип, наприклад `EmailAddress`, повертаючи або цей тип, або помилку (зазвичай `Maybe` чи `Result`).

Наприклад, у наведеному нижче коді зовнішні модулі можуть створити тип `EmailAddress` лише за допомогою функції `parseEmailAddress`, тож коли ми працюємо з типом `EmailAddress`, ми певні, що він коректний.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
