# Про мову

Настав час розібратися з однією з основних парадигм C++: обʼєктно-орієнтованим програмуванням (ООП). ООП будується навколо `classes`, тобто визначених користувачем типів даних із власним набором повʼязаних функцій. Почнімо з основ, а складніші теми розглянемо далі в навчальній програмі.

## Члени

Класи можуть мати **змінні-члени** та **функції-члени**. До них звертаються через **оператор вибору члена** `.`. Як і зі змінними поза `classes`, змінні-члени бажано ініціалізувати значенням одразу під час оголошення. Це значення стане типовим для новостворених обʼєктів цього класу.

## Інкапсуляція та приховування інформації

Класи дають змогу обмежувати доступ до своїх членів. Два базові випадки: `private` і `public`. До `private` членів не можна дістатися ззовні класу. `public` члени можна викликати вільно. Усі члени типово є `private`, і щоб ними можна було користуватися поза класом, їх треба позначити явно.

## Базовий приклад

Визначення нового `class` можна побачити в наступному прикладі. Звернімо увагу на `;` після визначення.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

Усі змінні доступні зсередини класу. Погляньмо на `damage` всередині функції `cast_spell`. Читати чи змінювати `private` члени ззовні класу не можна:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## Конструктори

Конструктори дають змогу присвоювати значення змінним-членам під час створення обʼєкта. Вони мають таку саму назву, як і `class`, і не мають типу повернення. Клас може мати кілька конструкторів. Це стає в пригоді, коли не завжди потрібно задавати всі змінні.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

Конструктори - це велика тема з багатьма нюансами. Якщо ми явно не визначаємо `constructor` для свого `class`, то лише тоді компілятор зробить це за нас. Так сталося й у першому прикладі вище. Обʼєкт _silverhand_ створюється викликом типового конструктора, жодних аргументів не передано. Усі змінні отримують значення, зазначене у визначенні класу. Якщо у визначенні не вказати жодних значень, змінні можуть залишитися неініціалізованими, а це може мати непередбачувані наслідки.

## Структури

Структури прийшли з первісних коренів мови в C і такі самі давні, як і сам C++. По суті, вони - те саме, що й `classes`, з однією важливою відмінністю. Типово все в `class` є `private`. Структури ж залишаються `public`, доки не визначено інакше. За домовленістю ключове слово `struct` часто використовують для **структур лише з даними**. Ключове слово `class` надають перевагу для обʼєктів, які мають гарантувати певні властивості. Таким інваріантом може бути те, що `damage` у класі `Wizzard` не може стати відʼємним. Змінна `damage` приватна, і будь-яка функція, що змінює damage, гарантувала б збереження інваріанта.
