# Вступ

`Complex numbers` не такі вже й складні.
Просто їм потрібна назва, яка не так лякає.

Вони настільки корисні, особливо в інженерії та науці, що R включає комплексні числа як стандартні атомарні типи поряд із цілими числами, числами з плаваючою комою, логічними значеннями, символами та raw.

## Основи

Число типу `complex` у R - це одне значення.
Однак у роботі його можна уявляти як пару чисел.
Їх називають «дійсною» та «уявною» частинами, з нещасливих історичних причин.
І знову ж таки, краще зосередитися на простоті, що лежить в основі, а не на дивних назвах.

Щоб створити комплексне число з двох дійсних чисел, достатньо додати суфікс `i` до уявної частини.

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

Але щоб створити комплексне число з дійсних змінних, наведений вище синтаксис не спрацює.
Запис `r + imi` збиває парсер із пантелику, і він вважає `imi` назвою (неіснуючої) змінної.

Можна або помножити уявну частину на `1i`, або скористатися функцією [`complex()`][ref-complex]:

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

Можливо, виникає питання: чому `i`, а не `j`?

Більшість інженерів віддають перевагу `j`.
Більшість науковців і математиків віддають перевагу математичному позначенню `i` для _уявної_ частини, але це позначення конфліктує з використанням `i` на позначення _струму_ в електротехніці.

У R обрали `i`, у Python - `j`, а в Julia оминули суперечку, обравши `im`.
Варто бути уважними, перемикаючись між мовами програмування [STEM][wiki-STEM].

Щоб отримати частини комплексного числа окремо:

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

Будь-яка з частин може дорівнювати нулю, і тоді математики можуть казати, що число «цілком дійсне» або «цілком уявне».
Однак у R це все одно комплексне число.

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

Можливо, ви чули, що «`i` (або `j`) - це квадратний корінь із -1».

Поки що це означає лише те, що уявна частина _за означенням_ задовольняє таку рівність:

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

Це проста ідея, але вона веде до цікавих наслідків.

## Арифметика

Більшість операторів, які використовуються з числами з плаваючою комою та цілими числами, також працюють із комплексними числами:

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

## Функції

Більшість математичних функцій працюють із комплексними вхідними даними.

Окрім `Re()` та `Im()`, є кілька функцій, особливо дотичних до комплексних чисел.

- `Conj()` просто змінює знак уявної частини комплексного числа (_з + на - або навпаки_).
  - Через те, як працює комплексне множення, це корисніше, ніж може здатися.
- `abs(<complex number>)` гарантовано повертає дійсне число без уявної частини (його «модуль»), а `Mod(<complex number>)` - це синонім.
- `Arg(<complex number>)` повертає фазовий кут у радіанах.

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
