# Включення коду

`circus-acts` використовував `<`, щоб сказати, що клас *може робити* те, що описує абстрактний клас. А от про те, як саме, він не сказав нічого.

`include` - це друга половина: він бере справжній код з іншого класу й кладе його копію в цей.

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

`JAZZ_ROUTINE::count` дорівнює 8, хоч `JAZZ_ROUTINE` про нього й не згадує.

## Це два окремі рішення

У більшості мов вони поєднані: один `extends` і передає код у спадок, і робить підклас придатним скрізь, де годиться надклас. Sather їх розділяє.

| Написано | Означає |
| --- | --- |
| `class A < $B` | `A` можна використати скрізь, де потрібен `$B` |
| `class A is include B` | `A` починається з копії коду `B` |

Одне без одного або обидва разом. Включення класу **не** робить його підтипом: після `include WARM_UP` `JAZZ_ROUTINE` усе ще не можна використати там, де потрібен `WARM_UP`, і ніщо не вдає іншого.

## Перейменування

Включену підпрограму можна привнести під іншим іменем:

```sather
   include WARM_UP count -> warm_up_count;
```

Кілька з них розділяються комами:

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## Пропускання однієї з них

Перейменування на *ніщо* залишає її поза, і саме так її замінюють:

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

`count` потрапляє сюди як звичайно, а `describe` ні, тож написати його тут не буде конфліктом. Без `describe -> ;` компілятор відмовився б: дві підпрограми з однаковим іменем і аргументами в одному класі - це помилка, і Sather не вгадуватиме, яку з них мали на увазі.

Ось у чому різниця з перевизначенням у більшості мов: заміну оголошують явно, а не мають на увазі.
