# Докладніше

[Цикл][control] - це послідовність інструкцій, які потенційно виконуються більше ніж один раз, доки не буде досягнуто умови завершення.

У x86-64 цикл зазвичай створюють за допомогою переходу на попередню мітку:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Зауважмо, що безумовний перехід на попередню мітку завжди буде передавати керування цій самій мітці.
Це означає, що цикл буде повторюватися вічно, якщо тільки не буде іншого переходу за межі повторюваної послідовності.

Наприклад, ось цей цикл не завершується:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

А ось цей цикл може завершитися, залежно від того, чи справдиться умова:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Цикли з лічильником

Цикл із лічильником майже завжди завершується однаково: інструкція, яка оновлює лічильник або порівнює два значення, за якою одразу йде умовний перехід, що вирішує, чи повторювати цикл ще раз.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0` не потрібна в коді вище, бо `sub rsi, 1` уже встановлює `zero flag (ZF)`, коли результат дорівнює `0`.

Хоча `cmp` і є основним способом перевірки умов в асемблері, багато інструкцій оновлюють прапорці.
Наприклад, багато інструкцій цілочисельної арифметики чи побітових операцій встановлюють `ZF`, коли результат дорівнює `0`, і `SF`, коли результат відʼємний (тобто старший біт установлено).

У [довіднику][reference] можна подивитися, які прапорці змінює кожна інструкція.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Зауважмо, що в прикладі вище передбачається, що `rsi` більший за `0`.
Якби він дорівнював `0`, то `sub rsi, 1` зменшила б `rsi` до `-1`, а це дуже велике беззнакове число.
Знадобилося б ще `18,446,744,073,709,551,615` ітерацій, перш ніж цикл нарешті завершився б.
Крім того, оскільки довжина масиву - `0`, будь-яке звернення до памʼяті вийде за межі.

Якщо немає жодних гарантій щодо довжини масиву, є два поширені підходи.

Перший - перенести умову завершення на початок циклу, а в кінці поставити безумовний перехід:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

Другий - один раз перевірити, чи не порожній масив, перед початком циклу:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Цей другий підхід зазвичай ефективніший за перший, бо в тілі циклу менше розгалужень.
Докладніше про це йтиметься в одному з наступних понять.

## Мікрооперації

Процесор не виконує таку інструкцію, як `add` чи `jnz`, безпосередньо.
Спочатку фронтенд процесора _декодує_ кожну інструкцію в один або кілька менших внутрішніх кроків, які називаються **мікроопераціями** (скорочено **мікроопи**).
Далі процесор планує та виконує ці мікрооперації, часто по кілька за такт і не в початковому порядку.

Більшість простих інструкцій декодуються в одну мікрооперацію, а складніша інструкція може декодуватися в кілька.
Оскільки справжнє навантаження процесора становить потік мікрооперацій, то створення меншої їхньої кількості для тієї самої задачі робить код швидшим.

## Макрозлиття

Як уже згадувалося, цикл зазвичай завершується якимось умовним переходом.
Це настільки поширено, що сучасні процесори оптимізовано під цю закономірність ще на етапі декодування.

Інструкцію, яка встановлює прапорці, а одразу за нею йде умовний перехід, що читає ці прапорці, процесор може декодувати разом в **одну** мікрооперацію, а не в окрему мікрооперацію для кожної з них.
Це називається **макрозлиттям**.

Обʼєднана пара поводиться як одна операція: лічильник оновлюється, і рішення про перехід ухвалюється разом, в одній мікрооперації.
Тоді керування потоком виконання циклу майже нічого не додає до роботи, яку цикл насправді виконує.

Як правило, у такий спосіб зазвичай зливаються два види пар:

- Арифметичні інструкції, як-от `add` чи `sub`, за якими одразу йде умовний перехід.
- `cmp`, `test` чи `and`, за якими одразу йде умовний перехід.

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

Злиття відбувається лише тоді, коли умовний перехід іде **одразу** після інструкції, що встановлює прапорці, і між ними немає нічого.

~~~~exercism/note
Макрозлиття залежить від процесора, і є певні варіації щодо того, які інструкції зливаються з яким умовним переходом.

Корисним джерелом є [Мікроархітектура процесорів Intel, AMD і VIA від Агнера Фога][agner-uarch].
У розділі 3.4.2.2 (оптимізація під макрозлиття) [довідкового керівництва Intel з оптимізації][intel-opt] також наведено пари, які зливаються, для процесорів Intel.

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## Інструкція `loop`

Є кілька інструкцій, які можна використати, щоб отримати поведінку, схожу на цикл.
Одна з них - [loop][loop].

Її єдиний операнд - мітка, яка містить адресу початку циклу.

Інструкція `loop` використовує значення в `rcx` як лічильник, зменшуючи його на 1 щоразу.
Щойно значення в `rcx` сягне нуля, цикл завершується, і виконання продовжується послідовно:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

В інструкції `loop` є два варіанти, які на кожній ітерації перевіряють прапорець нуля (`ZF`).
Крім зупинки циклу, коли `rcx` сягає нуля, вони також зупиняються, коли умова _не_ виконується.

| інструкція        | умова     |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

Ці інструкції **не встановлюють** `ZF`.
Перед ними має бути `cmp`, `test` або інша інструкція, яка змінює `ZF`:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
Попри зручність, `loop`, `loope` і `loopne` на сучасних процесорах зазвичай значно повільніші за відповідну послідовність `sub`/`jnz` або `cmp`/`jnz`.

Гарним джерелом про швидкодію інструкцій на багатьох різних процесорах є [таблиці Агнера][agner-tables].

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
~~~~
