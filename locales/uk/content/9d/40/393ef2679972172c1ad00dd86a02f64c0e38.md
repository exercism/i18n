# Лінтування

Основне призначення [configlet](/docs/building/configlet) - лінтування: перевірка того, чи правильно структуровані файли конфігурації треку, як із погляду синтаксису, так і семантики. Неправильно налаштовані треки можуть синхронізуватися некоректно, мати неправильний вигляд на сайті або давати користувачам не найкращий досвід, тож перевірки configlet відіграють важливу роль у підтриманні цілісності Exercism.

## Використання

Команду `lint` можна використати для лінтування треку.

```
configlet [global-options] lint [command-options]

Global options:
  -h, --help                   Show this help message and exit
      --version                Show this tool's version information and exit
  -t, --track-dir <dir>        Specify a track directory to use instead of the current directory
  -v, --verbosity <verbosity>  The verbosity of output. Allowed values: q[uiet], n[ormal], d[etailed]
```

## Правила

Ось правила лінтування, які перевіряються.

### Правило: наявність обовʼязкових файлів

Лінтер має перевіряти, чи наявні всі обовʼязкові файли. Файли, які не належать до конкретних вправ і мають бути наявні:

- `config.json`
- `docs/ABOUT.md`
- `docs/INSTALLATION.md`
- `docs/LEARNING.md`
- `docs/RESOURCES.md`
- `docs/SNIPPET.txt`
- `docs/TESTS.md`
- `exercises/shared/.docs/help.md`
- `exercises/shared/.docs/tests.md`

Файли, специфічні для концептуальних вправ, які мають бути наявні:

- `exercises/concept/<slug>/.docs/hints.md`
- `exercises/concept/<slug>/.docs/instructions.md`
- `exercises/concept/<slug>/.docs/introduction.md`
- `exercises/concept/<slug>/.meta/config.json`

Подібний перелік буде і для практичних вправ, але специфікацію для них ще не визначено.

Кожна концепція, перелічена в `config.json`, має мати такі файли:

- `concepts/<slug>/about.md`
- `concepts/<slug>/introduction.md`
- `concepts/<slug>/links.json`

## Глосарій

1. **Непорожній рядок тексту**: рядок тексту, який містить принаймні один символ, що не є пробільним.

2. **Рядок тексту у форматі kebab-case**: рядок тексту, який містить лише символи з діапазону `[a-z0-9]`, необовʼязково розділені дефісами (наприклад, «two-fer»). Він має відповідати регулярному виразу: `^[a-z0-9]+(-[a-z0-9]+)*$`

3. **Рядок тексту у стилі Title Case**: непорожній рядок тексту, який відповідає наведеним нижче [настановам Chicago Manual of Style](https://en.wikipedia.org/wiki/Title_case#Chicago_Manual_of_Style):
   - Пишіть з великої літери перше й останнє слово заголовків і підзаголовків.
   - Пишіть з великої літери «головні» слова (іменники, займенники, дієслова, прикметники, прислівники та деякі сполучники).
   - Пишіть з малої літери сполучники _and_, _but_, _for_, _or_ та _nor_.
   - Пишіть з малої літери артиклі _the_, _a_ та _an_.
   - Пишіть з малої літери прийменники, незалежно від довжини, крім випадків, коли на них падає наголос, коли вони вживаються як прислівники чи прикметники або як сполучники.
   - Пишіть з малої літери слова _to_ та _as_.
   - Пишіть з малої літери другу частину латинських назв видів.

4. **Рядок тексту у стилі Sentence Case**: непорожній рядок тексту, який відповідає наведеним нижче [настановам](https://en.wikipedia.org/wiki/Letter_case#Sentence_case):
   - Пишіть з великої літери перше слово речення, а також власні назви та інші слова, якщо цього вимагає конкретніше правило.

5. **Коректний шаблон `files`**: непорожній рядок тексту¹, який задає розташування файлу, використаного у вправі, відносно каталогу вправи. Шаблон може використовувати один із таких заповнювачів:

   - `%{kebab_slug}`: слаг вправи у `kebab-case` (наприклад, `bit-manipulation`)
   - `%{snake_slug}`: слаг вправи у `snake_case` (наприклад, `bit_manipulation`)
   - `%{camel_slug}`: слаг вправи у `camelCase` (наприклад, `bitManipulation`)
   - `%{pascal_slug}`: слаг вправи у `PascalCase` (наприклад, `BitManipulation`)

6. **Унікальний рядок тексту UUID версії 4**: рядок тексту, який задовольняє всі ці умови:

   - Він трапляється лише один раз у файлі `config.json` рівня треку для конкретного треку Exercism
   - Він не трапляється у файлі `config.json` рівня треку жодного іншого треку Exercism
   - Він не трапляється в жодному файлі `canonical-data.json` у https://github.com/exercism/problem-specifications
   - Він не трапляється більше ніде на Exercism
   - Він відповідає регулярному виразу:

   ```
   ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
   ```

   Наприклад, наведений нижче UUID має правильну форму:

   ```
   d334ffe3-657e-4725-a950-290b284b6d9f
   ```

   Щоб згенерувати придатний UUID, можна виконати `configlet uuid`.

7. **Коректний `tag` аналізатора**: непорожній рядок тексту¹ у форматі `<category>:<thing>`.
   Значення `<category>` має бути одним із:

- `paradigm` (наприклад, `paradigm:functional`)
- `technique` (наприклад, `technique:recursion`)
- `construct` (наприклад, `construct:bitwise-and`)
- `uses` (наприклад, `uses:DateTime.add_seconds`)

Значення `<thing>` має бути непорожнім рядком тексту¹.
