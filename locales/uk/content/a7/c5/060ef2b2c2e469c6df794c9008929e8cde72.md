# Вступ

Ця вправа знайомить з умовними конструкціями, тобто з вибором між двома або більше варіантами дій залежно від значення. Вона спирається на булеві значення (англ. Boolean), з якими ми познайомилися у вправі [Інфільтрація Анналін][annalyns], та на арифметику цілих чисел зі вправи [Конвертація валют][currency-conversion].

## Слова порівняння

Усі вони містяться в [`math`][math] (а `=` - у [`kernel`][kernel]):

```
=  ( x y -- ? )    ! equal
<  ( x y -- ? )    ! less than
<= ( x y -- ? )    ! less than or equal
>  ( x y -- ? )    ! greater than
>= ( x y -- ? )    ! greater than or equal
```

```factor
3 3 = .     ! => t
2 3 < .     ! => t
3 3 <= .    ! => t
3 4 = not . ! => t    (inequality: combine = with not)
```

`zero?` (у [`math`][math]) - це скорочення для поширеної перевірки `0 =`: він споживає число і кладе на стек те, чи було воно нулем:

```
zero? ( n -- ? )    ! t when n is 0
```

## Перевірки діапазону

`between?` (у [`math.order`][math.order]) перевіряє, чи лежить значення в діапазоні разом з його межами. Він стає в пригоді, коли дія залежить від того, у який діапазон потрапляє число:

```
between? ( x lo hi -- ? )    ! lo <= x <= hi (inclusive)
```

```factor
5 1 10 between? .    ! => t
0 1 10 between? .    ! => f
10 1 10 between? .   ! => t   (inclusive at both ends)
```

Ми часто бачимо його як предикат `cond` (`dup 1 4 between?`), щоб вибрати гілку за діапазоном, а не за одним значенням.

## Квотації

Слова порівняння вище дають булеві значення. Щоб *діяти* за булевим значенням, ми передаємо умовній конструкції одну або кілька **квотацій**. Квотація - це фрагмент коду в квадратних дужках, `[ ... ]`. Коли ми її пишемо, код потрапляє на стек як значення, а не виконується, а слово на кшталт `if` потім вирішує, яку квотацію запустити.

```factor
[ neg ]   ! a quotation that negates the top of the stack
[ ]       ! the empty quotation — does nothing
```

Пізніша вправа розповість про квотації докладніше. А поки що читаймо `[ ... ]` як «код, який треба виконати для цієї гілки».

## `if`, `when`, `unless`

`if` (у [`kernel`][kernel]) приймає булеве значення і дві квотації. Він виконує першу квотацію, коли булеве значення правдиве, і другу, коли воно неправдиве:

```
if ( ? then-quot else-quot -- )
```

```factor
: abs ( x -- y ) dup 0 < [ neg ] [ ] if ;
```

`when` виконує свою квотацію, лише коли булеве значення правдиве, а `unless` - лише коли воно неправдиве:

```
when   ( ? quot -- )
unless ( ? quot -- )
```

## `if*`, `when*` і `unless*`

Три варіанти з `kernel` ставляться до булевого значення як до *значення*, яке варто зберегти, коли воно правдиве. Це стає в пригоді, коли слово повертає «річ або `f`»:

```
if*     ( ? true false -- )    ! truthy: true is called WITH ? on stack
when*   ( ? true       -- )    ! truthy: true is called WITH ? on stack
unless* ( ? false      -- )    ! falsy: false runs and pushes a default
```

`if*` - це форма з двома гілками. Правдиву гілку викликають зі значенням, що залишається на стеку, а неправдиву - без нього:

```factor
42 [ ] [ "nothing" ] if* .   ! prints 42
f  [ ] [ "nothing" ] if* .   ! prints "nothing"
```

`unless*` - це класичний прийом «значення або типове значення». Якщо значення правдиве, його залишають як є. Якщо воно `f`, значення відкидають, і запускається квотація, яка кладе на стек замінник:

```factor
"hello" [ "anonymous" ] unless* .   ! => "hello"
f       [ "anonymous" ] unless* .   ! => "anonymous"
```

`when*` - це форма `if*` з однією гілкою: він виконує свою квотацію (зі значенням, що все ще на стеку) лише тоді, коли значення правдиве, і просто відкидає його, коли воно `f`. Він стане в пригоді, коли треба вкласти результат «річ або `f`» у поточне значення, не турбуючись про випадок `f`:

```factor
0 41 [ + ] when* .   ! => 41   (truthy: 41 added to the running total)
0 f  [ + ] when* .   ! => 0    (falsy: f dropped, total left untouched)
```

## `cond`

Коли треба вибрати одну з кількох альтернативних дій, `cond` (у [`combinators`][combinators]) підходить найкраще. Він приймає масив пар `{ predicate body }` і виконує тіло першого предиката, який дає правдиве значення:

```factor
USING: combinators ;

: classify ( n -- label )
    {
        { [ dup 0 <  ] [ drop "negative" ] }
        { [ dup 0 =  ] [ drop "zero"     ] }
        [ drop "positive" ]
    } cond ;
```

Кілька деталей, на які варто звернути увагу:

- Пари перевіряються по порядку. Перемагає перший збіг.
- Запис без предиката (просто одна квотація) у кінці діє як типовий варіант.
- Кожен предикат оглядає вхідні дані, але має залишити стек даних таким, яким його знайшов. Зазвичай для цього використовують прийом `dup ... <test>`.
- Тіло вибраної пари отримує той самий стек, який бачив предикат, тож зазвичай воно починається з того, що відкидає вхідні дані через `drop` і кладе на стек результат.
