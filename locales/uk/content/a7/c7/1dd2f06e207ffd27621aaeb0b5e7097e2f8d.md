# Додаток до інструкцій

## Банківські рахунки в Roc

У коді Roc ми зазвичай зосереджуємося на бізнес-логіці, а конкурентністю та спільним станом опікується платформа. Тому в цій вправі достатньо реалізувати операції з рахунком у `BankAccount.roc`, не турбуючись про конкурентність. Рахунки створюються закритими, повторне відкриття скидає баланс, а суми поповнень і зняттів мають бути додатними.

## Необовʼязковий демо-сервер

Доданий файл `bank-account-demo.roc` показує, як нашу реалізацію можна використати в невеликому вебсервісі. Його можна прочитати в редакторі, але він не повʼязаний із тестами і не є частиною нашого рішення.

Щоб запустити демо-сервер, [встановіть Roc](https://www.roc-lang.org/install/) на своїй машині, встановіть [Exercism CLI](https://exercism.org/cli-walkthrough), а потім виконайте цю команду в терміналі:

```sh
exercism download --exercise=bank-account --track=roc
```

Далі реалізуйте `BankAccount.roc` і перевірте його такою командою (якщо шлях, який надрукував CLI, відрізняється від наведеного нижче, змініть місце завантаження):

```sh
cd ~/Exercism/roc/bank-account
roc test bank-account-test.roc
```

Коли всі тести проходять, можна запустити демо-сервер такою командою:

```sh
roc bank-account-demo.roc
```

Сервер використовує [платформу basic-webserver](https://github.com/roc-lang/basic-webserver) і її вбудовану підтримку SQLite (Roc завантажує платформу під час першого запуску).
Окремий сервер бази даних не потрібен.
Сервер слухає на `http://127.0.0.1:8000` і створює `bank-account-demo.db` у поточному каталозі (щоб використати інший файл бази даних, задайте `DB_PATH`).
Зупиніть сервер комбінацією Ctrl-C.
Дані зберігаються між перезапусками.

В іншому терміналі можна звертатися до вебсервісу через `curl` (у Windows всюди використовуйте `curl.exe`, щоб не натрапити на псевдонім `curl` у PowerShell).
Наприклад, ось як відкрити рахунок №123, покласти 50, зняти 10 і перевірити його баланс:

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/open
curl -X POST http://127.0.0.1:8000/accounts/123/deposit/50
curl -X POST http://127.0.0.1:8000/accounts/123/withdraw/10
curl http://127.0.0.1:8000/accounts/123/balance
```

Баланс становитиме `40`.
Ідентифікатори рахунків і суми мають бути беззнаковими цілими числами.
Операції оновлення повертають `OK` у разі успіху або помилку з нашої реалізації рахунку в разі невдачі.
Щоб закрити рахунок №123:

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/close
```

Щоб спробувати конкурентні запити в Linux/macOS, візьміть новий ідентифікатор рахунку й надішліть 100 поповнень від восьми клієнтів:

```sh
curl -X POST http://127.0.0.1:8000/accounts/456/open
seq 100 | xargs -P 8 -I '{}' curl --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1
curl http://127.0.0.1:8000/accounts/456/balance
```

У Windows для паралельного прикладу використовуйте [PowerShell 7+](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows):

```powershell
curl.exe -X POST http://127.0.0.1:8000/accounts/456/open
1..100 | ForEach-Object -Parallel { curl.exe --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1 } -ThrottleLimit 8
curl.exe http://127.0.0.1:8000/accounts/456/balance
```

Усі поповнення мають пройти успішно, а баланс має становити `100`.

## Як демо-сервер працює з конкурентністю

Кожен запит читає рахунок, викликає наші функції Roc і зберігає результат у межах транзакції SQLite `Immediate`.
Невдалі операції відкочуються, не змінюючи рахунок.
SQLite дозволяє лише одного записувача водночас, тому конкурентні запити не перезаписують оновлення одне одного (навіть для різних рахунків).

Примітка: вправа використовує `U64`, але демо-сервер зберігає баланси як цілі числа SQLite і відхиляє оновлення, що перевищують максимальне значення `I64` (`9223372036854775807`).

Приклад запуску незалежних обчислень паралельно є у [вправі parallel-letter-frequency](https://exercism.org/tracks/roc/exercises/parallel-letter-frequency).
