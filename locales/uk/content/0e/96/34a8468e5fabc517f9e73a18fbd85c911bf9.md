# Про

[Цикл `for`][for-statement] дозволяє багаторазово виконувати код, доки не виконається умова.

```csharp
for (int i = 0; i < 5; i++)
{
    System.Console.Write(i);
}

// => 01234
```

Цикл `for` складається з чотирьох частин:

1. Ініціалізатор: виконується один раз перед входом у цикл. Зазвичай використовується для визначення змінних, які використовуються в циклі.
2. Умова: виконується перед кожною ітерацією циклу. Цикл продовжує виконуватися, доки це обчислюється як `true`.
3. Ітератор: виконується після кожної ітерації циклу. Зазвичай використовується для зміни (часто: збільшення/зменшення) змінної (або змінних) циклу.
4. Тіло: код, який виконується на кожній ітерації циклу.

## Цикли for та foreach

Загалом [concept:csharp/foreach-loops]() кращі за цикли `for` з таких причин:

- Цикл `foreach` гарантовано перебирає _всі_ значення. У циклі `for` легко пропустити елементи, наприклад через помилку на одиницю.
- Цикл `foreach` більш _декларативний_: код повідомляє, _що_ ми хочемо зробити, а не _як_ це зробити, як у циклі `for`.
- Цикл `foreach` захищає від помилок, тоді як у циклах `for` легко припуститися помилки на одиницю.
- Цикл `foreach` працює з усіма типами колекцій, зокрема з тими, які не підтримують використання індексатора для доступу до елементів.

Щоб гарантувати, що цикл `foreach` перебере _всі_ значення, компілятор не дозволяє оновлювати колекцію всередині циклу `foreach`:

```csharp
char[] vowels = new [] { 'a', 'e', 'i', 'o', 'u' };

foreach (char vowel in vowels)
{
    // This would result in a compiler error
    // vowel = 'Y';
}
```

Цикл `for` має деякі переваги над циклом `foreach`:

- Можна почати або зупинитися на потрібному індексі.
- Можна використати будь-яку (булеву) умову завершення.
- Можна пропускати елементи, налаштувавши збільшення змінної циклу.
- Можна обробляти колекції від кінця до початку, рахуючи у зворотному напрямку.
- Можна використовувати цикли `for` у сценаріях, які не повʼязані з колекціями.
