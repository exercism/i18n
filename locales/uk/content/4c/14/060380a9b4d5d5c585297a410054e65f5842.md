# Вступ

Іноді, перебираючи послідовність, нам потрібна не лише сама *позиція* елемента, а й сам елемент. Сімейство `*-index` у [`sequences`][sequences] віддає і те, і те в quotation для кожного елемента. `times` - близький родич для простої ітерації з підрахунком; він стане в пригоді, коли потрібен лише підрахунок, а не послідовність.

## `each-index` і `map-index` - індекс у quotation

```
each-index ( seq quot: ( elt index -- )       -- )
map-index  ( seq quot: ( elt index -- newelt ) -- newseq )
```

Quotation отримує елемент під індексом, тобто `index` лежить **на вершині** стека:

```factor
USING: io kernel math.parser sequences ;

{ "alice" "bob" "carol" } [
    number>string ": " glue print
] each-index
! prints:
! alice: 0
! bob:   1
! carol: 2

{ 10 20 30 } [ + ] map-index .
! => { 10 21 32 }       (index added to each element)
```

`each-index` виконує quotation заради його побічного ефекту й нічого не повертає. `map-index` збирає результати для кожного елемента в нову послідовність того самого типу, що й вхідні дані.

## `times` - ітерація з підрахунком

`times` (з [`math`][math]) виконує свій quotation `n` разів.

```
times ( n quot: ( -- ) -- )
```

Опублікована форма `( -- )` описує лише *мінімум*: адже `times` є `inline`, тож quotation зі збалансованим ефектом, як-от `( str -- str )`, цілком підходить, а стек передається від ітерації до ітерації. Так ми отримуємо накопичувач із підрахунком і без жодного змінюваного стану:

```factor
USING: kernel sequences ;

"" 3 [ "clop " append ] times .    ! => "clop clop clop "
```

Тіло кожної ітерації бачить поточний рядок тексту (англ. string), дописує до нього й залишає новий рядок тексту на стеку для наступної ітерації. Той самий прийом спрацює і для `each-index`, і для `map-index`, якщо ми хочемо протягнути крізь них накопичувач.
