# Вступ

Жонглювання стеком цілком годиться для коротких слів. Коли слово має кілька вхідних даних і до них потрібно звертатися за назвою, Factor пропонує *локальні змінні*: іменовані привʼязки, які вводять за допомогою `::` (для визначень слів) або `[| | ]` (для інлайн-лямбд).

## `:: ( inputs -- outputs )`

Якщо замінити `:` на `::`, назви вхідних даних стануть локальними змінними в тілі:

```factor
USING: locals ;

:: hypotenuse ( a b -- c )
    a a *
    b b *
    + sqrt ;
```

Порівняймо з версією, де значення переставляють на стеку:

```factor
! DOCTEST: SKIP   (shown for comparison — would re-define hypotenuse)
: hypotenuse ( a b -- c )
    [ sq ] bi@ + sqrt ;
```

Обидва варіанти правильні: локальні змінні особливо доречні, коли до одного вхідного значення звертаються більше ніж раз або коли природний порядок дій не збігається з порядком на стеку.

## Привʼязування проміжних значень за допомогою `:>`

Усередині тіла `::` (або інлайн-лямбди `[| ... |]`) `:>` знімає значення зі стеку даних і привʼязує його до нової локальної змінної:

```
value :> name      ! immutable binding
value :> name!     ! mutable binding (name! is its setter)
```

Зазвичай використовують незмінну форму. Нею дають назву проміжному значенню, і тоді тіло читається згори вниз:

```factor
USING: locals math ;

:: average-3 ( x y z -- avg )
    x y + z + :> sum
    sum 3 / ;
```

Варіант із `!` позначає локальну змінну як змінювану; далі в тілі `value name!` (без двокрапки й без `:>`) присвоює їй нове значення:

```factor
USING: kernel locals math math.order ;

:: clamped ( x lo hi -- y )
    x :> v!
    v lo < [ lo v! ] when
    v hi > [ hi v! ] when
    v ;
```

Змінювані локальні змінні особливо доречні в словах для ітерації, з якими ми познайомимося в наступних вправах (наприклад, `while`).

## `[let` - область видимості звідусіль

`:>` працює лише всередині лексичної області видимості, яку `::` і `[| ... |]` створюють автоматично. Щоб увести локальні змінні зі звичайного слова `:` або в лістенері, обгорнімо код у `[let ... ]`:

```
[let code :> name code :> name ... body ]
```

Кожне `:> name` привʼязує значення на вершині стеку з попереднього виразу; ці привʼязки видно в решті форми.

```factor
USING: locals math ;

[let 3 :> x 4 :> y x x * y y * + ] .   ! => 25
```

`[let` - це місток між визначеннями `:` у стековому стилі та іменованими привʼязками; він стає в пригоді, коли від локальних змінних виграє лише частина слова.

## Лямбди - `[| inputs | body ]`

Усередині квотейшна `[| inputs | body ]` уводить локальні змінні, до яких тіло може звертатися за назвою. Це особливо зручно зі словами вищого порядку, як-от `assoc-map`, чий квотейшн отримує `key` *і* `value`:

```factor
USING: assocs locals ;

H{ { "a" 1 } { "b" 2 } }
[| key value | key value neg ] assoc-map .
! => H{ { "a" -1 } { "b" -2 } }
```

Та сама форма працює і для `map-index` (у [`sequences`][sequences]), чий квотейшн отримує елемент *і* його індекс. Назви ясно показують, який операнд яку роль відіграє:

```factor
USING: locals sequences ;

! Divide each element by its 1-based position:
{ 10 80 270 } [| elt i | elt i 1 + / ] map-index .
! => { 10 40 90 }
```

Стековий ефект лямбди визначають список вхідних даних і те, що породжує її тіло.

## Коли використовувати локальні змінні

До локальних змінних варто вдаватися, коли:

- Те саме вхідне значення використовується більше ніж в одному місці.
- Природний порядок дій не збігається з порядком на стеку, а `dup`/`swap`/`rot` для виправлення важко читати.
- Ми всередині інлайн-лямбди, переданої слову вищого порядку, яке одразу віддає кілька значень (як у `assoc-map`).

Коли тіло є чистим лінійним потоком, звичайні визначення `:` залишаються коротшими й не менш читабельними.

## `assoc-map` - по одному запису за раз

`assoc-map` (у [`assocs`][assocs]) застосовує квотейшн до кожного запису асоціативної колекції:

```
assoc-map ( assoc quot: ( key value -- newkey newvalue ) -- newassoc )
```

Лямбда з локальними змінними - найчистіший спосіб написати квотейшн.

## `cond` знову

Коли потрібно розгалужуватися за `f` *або* за числовим значенням, `cond` - саме та форма, яка потрібна; `case` не потрібен, бо немає єдиного значення для порівняння.
