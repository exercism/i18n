# Вступ

## Винятки

Усі помилки в Elixir реалізують _Exception Behaviour_. Так само, як і _Access Behaviour_, _Exception Behaviour_ визначає функції зворотного виклику, які модуль має реалізувати, щоб виконати програмний контракт цієї поведінки. Щойно помилку визначено, вона має такі властивості:

- Назва модуля визначає назву помилки.
- Модуль визначає структуру помилки.
- Ця структура матиме поле `:message`.
- Модуль можна використовувати з `raise/1` і `raise/2`, щоб згенерувати потрібну помилку.

_Exception Behaviour_ також визначає дві функції зворотного виклику: `message/1` та `exception/1`. Якщо їх не реалізовано, використовуються типові реалізації. `message/1` перетворює структуру помилки на читабельне повідомлення, коли його викликають через `raise`. `exception/1` дає змогу додати до повідомлення додатковий контекст, коли його викликають через `raise/2`.

### Визначення винятку

Щоб визначити виняток на основі модуля помилки, скористаймося макросом `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### Використання винятків

Визначені помилки можна використовувати так само, як вбудовану помилку, за допомогою `raise/1` або `raise/2`.

- `raise/1` генерує конкретну помилку за назвою її модуля, а якщо аргумент є рядком тексту (англ. string), буде згенеровано `RuntimeError` із цим рядком тексту як повідомленням.
- `raise/2` генерує конкретну помилку за назвою її модуля та приймає аргумент з атрибутами, який використовується, щоб отримати помилку з відповідним повідомленням.
