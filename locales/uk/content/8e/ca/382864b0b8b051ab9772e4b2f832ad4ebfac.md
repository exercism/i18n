# Тести

Кожна вправа надає модульні тести та рецепт збірки для CMake. Реалізацію пишемо ми.
Кожен тестовий файл лінкується з нашою реалізацією, утворюючи консольний виконуваний файл, який запускає тести. Запуск цього виконуваного файлу виводить повідомлення про кожен тест, що не пройшов, і повертає ненульовий код виходу, коли тести не проходять.

Тестовий файл матиме назву `<exercise>_test.f90`, тож для вправи «Боб» файл із тестами називається `bob_test.f90`. Кожен тест супроводжується коментарем з описом тесту, а далі йде сам тест, що починається з `call assert_equal`, наприклад:

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Щоб вимкнути тест, досить закоментувати його символом `'!'`, наприклад:

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Робота над кожною вправою складається з таких кроків:

* Створення початкової збірки з CMake
* Для кожного модульного тесту:
 * Усунення помилок компіляції, щоб тест не пройшов.
 * Реалізація рівно настільки, щоб тест пройшов.
 * Рефакторинг реалізації заради кращої читабельності, меншого дублювання тощо.
 * Розкоментування наступного тесту


## Створення початкової збірки з CMake

Кожна вправа постачається з файлом `CMakeLists.txt` разом із модульними тестами. Він містить готовий рецепт CMake, який виконує збірку за нас. Редагувати цей файл не доведеться. Наданий рецепт припускає, що наша реалізація лежить у файлі вихідного коду, названому за назвою вправи.

Наприклад, вправа «Боб» передбачає реалізацію у файлі `bob.f90`.

**Створіть початкові файли реалізації перед запуском CMake.**
Якщо під час запуску CMake для вправи «Боб» файлу `bob.f90` немає, CMake видасть помилку про те, що файлів не знайдено.
**Ці файли можуть бути порожніми, але вони повинні існувати.**

Користуючись цим рецептом, CMake може згенерувати відповідний проєкт для нашого середовища: для цього запускаємо `cmake -G` з відповідним генератором і шляхом до каталогу з вправою. CMake створить сценарій збірки, придатний для нашої операційної системи. Щоб відокремити ці згенеровані файли від вихідного коду вправи, зазвичай створюють каталог `build` для згенерованих файлів збірки та скомпільованого коду.

Так папка з вправою залишається чистою та охайною.

**Примітка: коли `cmake` запускається вперше, [testlib](###-Testlib) завантажиться автоматично. `testlib` потрібна, щоб модульні тести працювали.

Оскільки ми запускатимемо CMake, щоб створити інструкції збірки для кожної вправи, варто створити bash-скрипт (Linux/MacOS) або bat-файл (Windows) для цієї команди.

Коли CMake створить середовище збірки, ми можемо зібрати код відповідною командою для свого середовища:

* Linux з make: `make`
* Windows з Visual Studio: виберіть Build / Build Solution у меню.
* Windows з MingW: `mingw32-make.exe`
* Windows з nMake: `nmake.exe`
* MacOS з Xcode: виберіть Build на панелі інструментів

Нижче наведено приклади запуску CMake для різних середовищ.

### Linux\MacOS з Make

Генератор для CMake називається `Unix Makefiles`.
Припустімо, ми виконуємо вправу `bob` і перебуваємо в папці цієї вправи:

```
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

Цей приклад показує, як створити порожні файли реалізації перед запуском CMake.

Просто введіть make у каталозі збірки, щоб скомпілювати тести. Це має породити помилки часу компіляції. Коли помилки виправлено, запустіть `make` знову. Коли всі помилки збірки виправлено, запустіть тести:

```
$ ctest -V
```
### Windows з Visual Studio 2017

Генератор для CMake називається `Visual Studio 15`. Той самий генератор підтримує всі IDE-редакції Visual Studio 2017: Community, Professional та Enterprise. Припустімо, ми виконуємо вправу `bob` і перебуваємо в папці цієї вправи:

```
> copy nul: bob.f90
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

Цей приклад показує, як створити порожні файли реалізації перед запуском CMake.

### Testlib

Тести залежать від невеликої бібліотеки `testlib`, яку завантажують із GitHub, коли збірку вперше налаштовують за допомогою cmake.

Якщо завантаження не вдасться, його можна виконати вручну, наприклад:

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/TesterMain.f90
```
