# Посібник зі стилю C

Цей посібник описує стиль, призначений для файлів зразків і тестів вправ треку C.

Правила в цьому посібнику доповнюють правила, задані файлом [.clang-format][], або ж звертають на них увагу.

## Стандарт C

Код має відповідати стандарту C99, який офіційно називається ISO/IEC 9899:1999.
Не слід використовувати POSIX або інші нестандартні бібліотечні функції, типи чи посилання, зовнішні щодо реалізації.

## Імена

Загалом в іменах типів, змінних, структур і файлів використовують зміїний регістр: усі літери малі, а компоненти імені розділяють підкресленнями `_`.

```c
void some_foo_function(char * input_string, int input_string_length);
```

### Переліки

Імена переліків зазвичай мають бути в однині, а не в множині.

Мітки переліків слід записувати у зміїному регістрі великими літерами.

```c
enum heading {
    HEADING_NORTH,
    HEADING_EAST,
    HEADING_SOUTH,
    HEADING_WEST
}
```

### Макроси

Макроси, що визначають константи, іменують у зміїному регістрі великими літерами.

```c
#define CONSTANT 0x4000
```

Для імен макросів вітається зміїний регістр великими літерами, але макроси, схожі на функції, можна іменувати зміїним регістром малими літерами.

### Типи

Стандартні типи фіксованої ширини (у `stdint.h`) мають перевагу над базовими типами цілих чисел.

Типу `bool` (з `stdbool.h`) віддають перевагу над `_Bool`.

Так само для представлення величин, повʼязаних із памʼяттю, перевагу віддають `size_t` і `ptrdiff_t` (із `stddef.h`).

Типи, визначені програмою через `typedef`, слід іменувати із суфіксом `_t`.
Хоча POSIX і залишає суфікс `_t` за собою, трек наразі не використовує POSIX.

## Вартові включення

Вартові включення слід використовувати в усіх заголовних файлах.

Зазвичай один набір вартових включень має охоплювати весь вміст заголовка.

Вартові у прикладі реалізації (`.meta/example.h`) та в заготовці вправи (`exercise_name.h`) мають використовувати імена макросів, що відповідають назві вправи.
Імена макросів вартових мають підлягати наведеному вище правилу щодо регістру для макросів.

Наприклад, для вправи `hello-world` слід використовувати:

```c
#ifndef HELLO_WORLD_H
#define HELLO_WORLD_H

//...

#endif
```

## Параметри

Параметри функцій слід називати як в оголошенні, так і у визначенні всіх функцій.
Це стосується і файлів `.c`, і файлів `.h`.
Використані імена мають збігатися в усіх випадках.
Тобто наведений нижче прототип функції є коректним C, але стиль неправильний, бо параметр не названо: `void foo(int);`.
Правильний прототип, за умови що всі інші оголошення та визначення теж використовують імʼя параметра `bar`, матиме такий вигляд: `void foo(int bar);`.

Там, де це простіше або доречніше, перевагу віддають параметрам, які вимагають передавання аргументів за значенням, а не за вказівником.
Звернімо особливу увагу, що це стосується й параметрів типу `struct`.

Якщо від студента не очікують зміни значень параметра-вказівника в його реалізації, такий параметр має бути кваліфікований як `const`.

## Структура файлу тестів

Файл тестів кожної вправи має певну структуру.
Така структура покликана і допомогти контрибʼюторам розпізнавати частини файлу, і допомогти учням зрозуміти, як працюють тести.

Як і більшість вихідних файлів C, файл тестів починається з директив включення.

```c
#include "vendor/unity.h"
#include "../src/file_under_test.h"
// any other includes here
```

Після включень ідуть функції `setUp()` і `tearDown()`.
Наразі жодна вправа їх не використовує (тіла функцій порожні), але вони мають залишатися на місці, щоб файли тестів компілювалися правильно на всіх платформах.

```c
void setUp(void)
{
}

void tearDown(void)
{
}
```

Далі йдуть допоміжні функції, які використовують тестові функції.
Імена таких допоміжних функцій не повинні мати префікс `test_`.

Далі йдуть самі тестові функції.
Імена цих функцій мають префікс `test_`.
За винятком першої, кожна тестова функція має мати `TEST_IGNORE();` своєю першою інструкцією.
Після першого такого входження має йти рядковий коментар `// delete this line to run test`.

Наприклад:

```c
static void test_the_first(void)
{
   test_first_foo();
}

static void test_the_second(void)
{
   TEST_IGNORE();               // delete this line to run test
   test_second_foo();
}

static void test_the_third(void)
{
   TEST_IGNORE();
   char grade = 'A';
   test_third_foo(grade);
}
```

Останньою у файлі йде функція `main()`.
Тіло функції main також має певну структуру.
Спершу виклик `UNITY_BEGIN()`, потім порожній рядок, а далі тести.
Після останнього тесту йде ще один порожній рядок, перш ніж повертається результат `UNITY_END()`.

```c
int main(void)
{
    UNITY_BEGIN();

    RUN_TEST(test_foo);
    RUN_TEST(test_bar);

    return UNITY_END();
}
```
