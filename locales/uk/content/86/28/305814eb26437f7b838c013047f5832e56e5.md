# Вступ

Знання типу, до якого належить фрагмент даних, часто дуже важливе для того, щоб код працював гладко й без помилок.

У JavaScript є кілька способів перевірити тип значення або обʼєкта.

```exercism/note
Механізми перевірки типів у JavaScript можуть бути дещо ненадійними.

Для кращої безпеки типів і суворіших типів, імовірно, варто використовувати TypeScript, мову, що будується на JavaScript, але з синтаксисом типів статично типізованої мови.
```

## Оператор `typeof`

Оператор `typeof` повертає тип свого операнда.
Вихідні дані - це рядок тексту (англ. string), що збігається з назвою одного з [примітивних типів даних][primitives], крім `"null"`.
Також вони можуть дорівнювати `"function"` або `"object"`.

```javascript
typeof undefined;
// => "undefined"

typeof true;
// => "boolean"

typeof 42;
// => "number"

typeof 'Hello, World!';
// => "string"

typeof function () {
  return 'Hello, World';
};
// => "function"

typeof [1, 2, 3, 4];
// => "object"

typeof { city: 'Stockholm', country: 'Sweden' };
// => "object"
```

Через [історичні причини][`typeof null` is `"object"`].

## Оператор `instanceof`

Щоб перевірити тип обʼєкта, можна використати оператор `instanceof`.
Він обчислюється в `boolean` залежно від того, чи входить другий операнд до [ланцюжка прототипів][prototype chain] першого операнда.
Уточнімо: `instanceof` поверне, чи є перший операнд екземпляром другого операнда або одного з його дочірніх класів.
`instanceof` працює лише з обʼєктами.

```javascript
class Beverage {
  // ...
}

// The Coffee class is a child of the Beverage class.
class Coffee extends Beverage {
  // ...
}

const java = new Coffee();

java instanceof Coffee;
// => true

java instanceof Beverage;
// => true
```

````exercism/advanced
Клас `Array` має метод `Array.isArray()`, який перевіряє, чи є його аргумент масивом.

Хоча `instanceof Array` не працюватиме з масивом, створеним в іншому середовищі, наприклад в `iframe` на вебсторінці, `Array.isArray()` спрацює.

Це тому, що клас Array має різний конструктор у кожному середовищі, і кожен `iframe` має власне середовище, а отже, функція в ланцюжку прототипів буде іншою, через що `instanceof Array` не спрацює.
`Array.isArray()` здатний це проігнорувати, і його варто завжди використовувати, коли це можливо.

Він також допомагає уникнути хибних спрацювань, коли обʼєкт насправді не є `Array`, а лише має `Array` у своєму ланцюжку прототипів.

```javascript
({ __proto__: Array.prototype }) instanceof Array
// => true

Array.isArray({ __proto__: Array.prototype })
// => false
```

````

## Оператор `in`

Оператор `in` повертає, чи є перший операнд властивістю другого операнда.
Він не перевіряє, чи має властивість визначене значення.
Властивість, встановлену в `undefined`, `in` усе одно виявить.

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
    this.isDarkMatter = undefined;
  }

  coolDown() {
    this.temperature = 'warm';
  }
}

const espresso = new Coffee();

'temperature' in espresso;
// => true

'color' in espresso;
// => false

'isDarkMatter' in espresso;
// => true
```

````exercism/note
`in` повертатиме `true` для успадкованих властивостей і методів.

```javascript
"coolDown" in espresso
// => true

"constructor" in espresso
// => true
```

Щоб цього уникнути, натомість використовуйте `Object.hasOwn()`
````

## Функція `Object.hasOwn()`

Метод `Object.hasOwn()` повертає, чи _належить заданому обʼєкту вказана властивість_ (тобто чи не успадкована вона і чи не є методом).

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
  }

  coolDown() {
    this.temperature = 'warm';
  }
}
const cappuccino = new Coffee();

Object.hasOwn(cappucino, 'temperature');
// => true

Object.hasOwn(cappucino, 'constructor');
// => false

Object.hasOwn(cappucino, 'coolDown');
// => false
```
