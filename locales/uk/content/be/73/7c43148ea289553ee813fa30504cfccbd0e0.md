# Детальніше

Як і багато інших мов, Go має вказівники.
Якщо ми тільки починаємо знайомитися з вказівниками, вони можуть здаватися трохи загадковими, але щойно ми до них звикнемо, вони стануть цілком зрозумілими.
Це надзвичайно важлива частина Go, тож приділімо трохи часу, щоб справді їх зрозуміти.

Перш ніж заглиблюватися в деталі, варто зрозуміти, для чого потрібні вказівники.
Вказівники дають змогу ділити памʼять з іншими частинами нашої програми, і це корисно з двох основних причин:

1. Коли ми маємо великі обсяги даних, створення копій для передавання між функціями є дуже неефективним.
   Натомість, якщо ми передаємо адресу памʼяті, де зберігаються дані, ми можемо суттєво зменшити споживання ресурсів нашими програмами.
2. Передаючи вказівники між функціями, ми можемо напряму звертатися до єдиної копії даних і змінювати її. Це означає, що будь-які зміни, зроблені однією функцією, одразу стають видимими для інших частин програми, коли функція завершується.

## Змінні та памʼять

Припустімо, у нас є звичайна змінна `a` цілого типу:

```go
var a int
```

Коли ми оголошуємо змінну, Go має знайти місце в памʼяті, щоб зберегти її значення.
Для нас це переважно приховано: коли нам потрібно дістати значення, збережене в цій ділянці памʼяті, ми просто звертаємося до нього за назвою змінної.

Наприклад, коли ми пишемо `a + 2`, ми фактично дістаємо значення, збережене в памʼяті, повʼязаній зі змінною `a`, і додаємо до нього 2.

Так само, коли нам потрібно змінити значення в ділянці памʼяті, що відповідає `a`, ми можемо використати назву змінної, щоб виконати присвоєння:

```go
a = 3
```

Тепер ділянка памʼяті, повʼязана з `a`, зберігатиме значення `3`.

## Вказівники

Хоча змінні дають нам змогу звертатися до значень у памʼяті, іноді корисно знати **адресу памʼяті**, на яку вказує змінна.
**Вказівники** зберігають адреси памʼяті цих значень.
Щоб оголосити змінну типу вказівника, ми ставимо зірочку перед базовим типом:

```go
var p *int // 'p' contains the memory address of an integer
```

Тут ми оголошуємо змінну `p` типу «вказівник на int» (`*int`).
Це означає, що `p` зберігатиме адресу памʼяті цілого числа.
Нульовим значенням вказівників є `nil`, бо вказівник зі значенням `nil` не зберігає жодної адреси памʼяті.

### Як отримати вказівник на змінну

Щоб знайти адресу памʼяті значення змінної, ми можемо скористатися оператором `&`.
Наприклад, якщо ми хочемо знайти адресу памʼяті змінної `a` і зберегти її у вказівнику `p`, ми можемо зробити так:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Доступ до значення через вказівник (розіменування)

Коли в нас є вказівник, нам може знадобитися дізнатися значення, збережене за адресою памʼяті, яку він представляє.
Для цього можна скористатися оператором `*`:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

Операція `*p` дістає значення, збережене за адресою памʼяті, що міститься в `p`.
Цю операцію часто називають «розіменуванням».

Оператор розіменування також дає змогу присвоїти нове значення за адресою памʼяті, на яку посилається вказівник:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

Присвоєння `*pa` змінить значення, збережене за адресою памʼяті, яку містить `pa`.
Оскільки `pa` містить адресу памʼяті `a`, присвоюючи `*pa`, ми фактично змінюємо значення `a`!

Однак варто застерегти: перш ніж розіменовувати вказівник, завжди перевіряймо, чи він не `nil`.
Розіменування вказівника `nil` призведе до аварійного завершення програми під час виконання!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Вказівники на структури

Досі ми бачили лише вказівники на примітивні значення.
Ми також можемо створювати вказівники на структури:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

Ми могли б також створити нового `Person` і одразу зберегти вказівник на нього:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Коли в нас є вказівник на структуру, нам не потрібно розіменовувати його, щоб звернутися до одного з полів:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## Зрізи та мапи вже є вказівниками

Зрізи та мапи є особливими типами, бо вже містять вказівники у своїй реалізації.
Це означає, що здебільшого нам не потрібно створювати вказівники для цих типів, щоб поділитися адресою памʼяті їхніх значень.
Уявімо, що в нас є функція, яка збільшує значення за ключем у мапі:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Якщо ми створимо мапу й викличемо цю функцію, зміни, які функція внесла в мапу, збережуться після її завершення.
Це схоже на те, що ми отримали б, використовуючи вказівник, але звернімо увагу: у цьому прикладі ми не використовуємо ні взяття адреси, ні розіменування, ні будь-який інший синтаксис вказівників:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

Те саме стосується зміни наявного елемента у зрізі.

Однак дії, що повертають новий зріз, як-от `append`, є окремим випадком і **можуть не** змінити зріз поза функцією.
Це повʼязано з тим, як зрізи працюють усередині, але ми не будемо розглядати це докладно, бо це складніша тема.
Якщо нам справді цікаво, більше про це можна прочитати в [Go Blog: Mechanics of 'append'][mechanics-of-append]

## Арифметика вказівників

На відміну від інших мов, Go не підтримує арифметику вказівників.
Це означає, що не можна перейти від адреси памʼяті одного значення до адреси іншого, збільшуючи значення вказівника.
Тож такі фрагменти коду недійсні:

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
