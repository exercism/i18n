# Додаток до інструкцій

## Переваги та недоліки `from_quote`
У цій вправі визначено функцію `from_quote` у типі `Card`. Завдяки цьому можна писати такий код:

```roc
card : Card
card = "Q"
```

Цей код неявно викликає `Card.from_quote("Q")` під час компіляції. Це може потенційно пришвидшити програму, адже їй не потрібно виконувати розбір під час виконання, а також гарантує, що картки, відкинуті `from_quote`, буде виявлено під час компіляції, а не під час виконання. До того ж це робить код приємним і читабельним. Наприклад, ось один із тестів у цій вправі:

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

Однак той, хто читає цей код, може припустити, що функція `simulate_game` приймає запис із двома `List(Str)`, тоді як насправді це запис із двома `List(Card)`. Це може призводити до плутанини й помилок. Тому краще віддати перевагу трохи довшому, але явнішому формату: `"Q".Card`, який теж викликає `from_quote` під час компіляції.

У своїх програмах краще використовувати `from_str`:

```roc
Card := { ... }.{
    from_str : card_str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

Також можна викликати `from_str` (або будь-яку іншу чисту функцію) під час компіляції, ось так:

```roc
Ok(card) = Card.from_str("Q")
```

Зауваження: якщо розмістити це визначення на верхньому рівні, воно буде виконуватися під час компіляції (адже функція чиста, а її вхідні дані відомі під час компіляції). Усередині функції `from_str` можна використовувати під час виконання.
