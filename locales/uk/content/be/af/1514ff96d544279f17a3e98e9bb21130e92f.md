# Вступ

Пригадаймо, як ми вперше вивчали алгебру, ще в старших класах школи?

Зазвичай нам давали систему рівнянь і просили знайти `x` і `y`.

```
4x - 3y = -2
2x + 7y = 16
```

Два рівняння, дві невідомі: трохи підстановки, і ми швидко побачимо, що `x = 1, y = 2`.

Погляньмо ще раз на ліву частину попереднього прикладу.
Вона має вигляд матриці `[4 -3; 2 7]`, яка множить невідомий вектор `[x, y]` і дає вектор `[-2, 16]`.

У записі лінійної алгебри: **A** **x** = **b**, за звичною домовленістю: великі літери позначають матриці, а малі - вектори.

## **A x = 0** і нульовий простір

Розгляньмо важливий окремий випадок, коли всі наші рівняння мають нуль у правій частині.

```
4x - 3y = 0
2x + 7y = 0
```

У наведеному вище прикладі єдиним розвʼязком буде `x = y = 0`, і це зазвичай нецікаво.

Нетривіальні розвʼязки для **A x = 0** існують лише тоді, коли [визначник][wiki-determinant] **A** дорівнює нулю.

```julia-repl
julia> using LinearAlgebra

julia> A = [4 -3; 2 7]
2×2 Matrix{Int64}:
 4  -3
 2   7

julia> det(A)  # not zero!
34.0
```

Розгляньмо натомість такі рівняння:

```
4x - 3y = 0
8x + 6y = 0
```

Друге рівняння - це просто подвоєне перше рівняння, яке не додає нової інформації.
Будь-які значення, де `x = 0.75y`, будуть розвʼязком.

Ці значення `(x, y)` лежать уздовж прямої у двовимірному просторі.
Існує безліч розвʼязків, і вони утворюють [нульовий простір][wiki-nullspace] матриці.

У цьому випадку рядки матриці не є [лінійно незалежними][indep], і [ранг][rank] матриці менший за кількість рядків або стовпців.

```julia-repl
julia> A = [4 -3; 8 -6]
2×2 Matrix{Int64}:
 4  -3
 8  -6

julia> det(A)
0.0

julia> size(A)  # total number of rows and columns
(2, 2)

julia> rank(A)  # number of linearly-independent rows (or columns)
1

julia> nullspace(A)
2×1 Matrix{Float64}:
 -0.6
 -0.8

julia> nullspace(A) |> norm  # Julia returns unit vectors when possible
1.0
```

Функція [`nullspace()`][ref-nullspace] повертає одну точку, [нормовану][wiki-unit-vec] до одиничного вектора, але будь-яке скалярне кратне цього вектора теж належить нульовому простору.

## Розвʼязування **A x = b**

А тепер уявімо, що в нас 1000 рівнянь із 1000 невідомими?
Якщо це звучить безглуздо, згадаймо, що бездротові цифрові давачі тепер дешеві й універсальні (вимірюють деформацію, швидкість вітру, прискорення по трьох осях, що завгодно...).
Цілком розумно мати 1000 таких давачів, які стежать за сучасною спорудою, наприклад підвісним мостом.
Потрібна система керування, яка інтерпретує потік даних і готова подати сигнал тривоги, якщо ситуація стане загрозливою.

Знову **A** **x** = **b**, де в нас є **A** (з інженерного проєкту) і **b** (виміряні значення з давачів), але потрібно знайти **x**.

Перша думка, якщо ми з цим не знайомі, - спробувати якось «поділити все на **A**», щоб перенести його в праву частину.

Насправді **A** має обернену матрицю (вона є в більшості, хоч і не в усіх квадратних матриць: [визначник][wiki-determinant] має бути ненульовим), і обчислення працює (_повільно!_).

```julia-repl
julia> A = [4 -3; 2 7]
2×2 Matrix{Int64}:
 4  -3
 2   7

julia> b = [-2, 16]
2-element Vector{Int64}:
 -2
 16

# the inverse matrix
julia> inv(A)
2×2 Matrix{Float64}:
  0.205882   0.0882353
 -0.0588235  0.117647

julia> inv(A) * b
2-element Vector{Float64}:
 0.9999999999999999
 2.0
```

На жаль, обчислення оберненої матриці повільне для малих матриць і крижано повільне для великих.
Не найкращий варіант, якщо міст завалиться під час обчислення!

На щастя, інші алгоритми значно швидші (у цьому випадку [метод Гауса][gaussian-elim]).

Julia (наслідуючи Matlab) просто використовує зворотний слеш для розвʼязувача (технічно «ліве ділення»).

```julia-repl
julia> x = A \ b
2-element Vector{Float64}:
 1.0
 2.0
```

Це тривіальний приклад, але є кілька деталей, за якими варто стежити.

- Коефіцієнти мають шикуватися в стовпці, тож додаймо нулі там, де бракує доданків.
- Рівняння (а отже, і рядки матриці) мають бути [лінійно незалежними][indep]. Якщо рядок 3 - це просто сума рядків 1 і 2, він не додає нової інформації, і задача недовизначена.

Команда [`rank()`][rank] дасть кількість лінійно незалежних рядків/стовпців, тож прагнімо, щоб вона дорівнювала кількості невідомих змінних.

```julia-repl
julia> rank(A)
2
```

### Прямокутні матриці

Колись у дитинстві нам, мабуть, казали, що для `N` невідомих потрібна система з `N` рівнянь.

Як і в більшості речей у математиці, реальність трохи складніша (і не лише через деталь про лінійну незалежність, згадану в попередньому розділі).

#### «Замало» рядків

Із `N-1` рівняннями (рядками в матриці `A`) задача недовизначена.
Чи здамося ми у відчаї?

Залежить від ситуації!

`N-1` рівнянь усе ще містять багато інформації.
У геометричних термінах, щоб визначити розвʼязок як _точку_ в N-вимірному просторі, потрібно `N` рівнянь, але `N-1` скаже нам, що розвʼязок лежить десь на _прямій_.

Це залишає нам безліч розвʼязків, але також безліч точок у просторі параметрів, де розвʼязків _немає_.

Чи проходить наша пряма розвʼязків через ділянку простору параметрів, про яку порядний інженер мав би хвилюватися?
Або яка могла б виправдати закриття споруди для відвідувачів (_підвісні мости можуть розгойдуватися на сильному боковому вітрі_)?
Можливо, варто зробити ще кілька обчислень, щоб це зʼясувати!

```julia-repl
julia> A3 = [4 -3 1; 2 2 2; 3 -4 -3]
3×3 Matrix{Int64}:
 4  -3   1
 2   2   2
 3  -4  -3

julia> b3 = [1, 12, -14]
3-element Vector{Int64}:
   1
  12
 -14

# fully-determined solution
julia> A3 \ b3
3-element Vector{Float64}:
 1.0
 2.0
 3.0

# remove row 3 from A3 and B3
julia> A2 = A3[1:2, :]
2×3 Matrix{Int64}:
 4  -3  1
 2   2  2

julia> b2 = b3[1:2]
2-element Vector{Int64}:
  1
 12

# an under-determined solution
julia> z1 = A2 \ b2
3-element Vector{Float64}:
 1.594594594594594
 2.445945945945947
 1.9594594594594592
```

Розвʼязувач зі зворотним слешем дає нам розвʼязок!
[Неофіційно][underdet] це, вочевидь, розвʼязок із найменшою нормою (геометрично найближчий до початку координат).

Щоб отримати інші розвʼязки, нам потрібен [`nullspace`][ref-nullspace] для `A2`.

Додавання будь-якого скалярного кратного нульового простору до початкового розвʼязку дасть ще один дійсний розвʼязок.

```julia-repl
# get the nummspace of A2
julia> N = nullspace(A2)
3×1 Matrix{Float64}:
 -0.46499055497527725
 -0.3487429162314578
  0.813733471206735

# add a random multiple of the nullspace to the earlier solution
julia> z = z1 + rand() * N
3×1 Matrix{Float64}:
 1.274331860650258
 2.205748895487695
 2.5199192438620472

# our random z is a valid solution, recovering b2 = [1, 12]
julia> A2 * z
2×1 Matrix{Float64}:
  0.9999999999999947
 12.0
```

Так само `N-2` рівнянь обмежать (безліч) розвʼязків площиною, і діятимуть ті самі принципи.

#### «Забагато» рядків

Протилежна ситуація виникає, коли рівнянь _більше_, ніж невідомих, але вони все одно якимось чином лінійно незалежні.

_У реальній інженерії це цілком нормально, і це навіть добре!_

Давачі мають обмежену точність, вектор **b** має обмежену точність, і в обчисленнях є шум.
Тепер розвʼязок - це [наближення методом найменших квадратів][least-squares] до зашумлених даних.

Найпростіший спосіб використовує [`pseudoinverse`][pseudoinv] матриці, яку Julia реалізує як функцію [`pinv()`][pinv].

Його можна застосовувати майже так само, як обернену матрицю (невиродженої) квадратної матриці, даючи оцінку змінних методом найменших квадратів, а не точний розвʼязок.

```julia-repl
# create 5-row A and b for 2 variables
julia> A5 = [4 -3; 2 7; -1 2; 1 -1; 3 1]
5×2 Matrix{Int64}:
  4  -3
  2   7
 -1   2
  1  -1
  3   1

julia> rank(A5)
2

# add some random-normal noise to b5
julia> b5n = [-2, 16, 3, -1, 5] + randn(5) * 0.1
5-element Vector{Float64}:
 -1.9337349223581917
 16.024913008059457
  3.0087646177373992
 -0.8675748721176717
  4.914568047308805

# solve to get x ≈ 1, y ≈ 2, using the pseudoinverse
julia> pinv(A5) * b5n
2-element Vector{Float64}:
 1.006117942769543
 1.9962973764508272
```

## Власні значення та власні вектори

У попередньому розділі йшлося про розвʼязки **A** **x** = **b**, що відповідають звичній алгебрі.

Цей розділ про розвʼязки **A** **x** = λ **x**, де λ - скаляр.

Це характерна концепція лінійної алгебри, але ми можемо витлумачити її геометрично:

_Для відповідних значень **x** і λ квадратна матриця **A** масштабує ненульовий вектор **x** у λ разів за довжиною, не змінюючи його напрямку (хіба що відʼємне λ змінює його на протилежний)_.

Це звучить вузькоспеціально, але виявляється _неймовірно_ корисним!

***Термінологія:*** Допустимі значення λ - це _власні значення_ матриці **A**, а відповідні значення **x** - _власні вектори_ **A**.
_На жаль, нам доводиться миритися зі словами, які змінюють мову на півдорозі._

Студентів зазвичай учать обчислювати власні значення й вектори для матриць 2×2 вручну, але за допомогою компʼютера це набагато простіше (хоч усе ще досить повільно, і в загальному випадку масштабується як `O(n^3)` для матриці `n×n`).

```julia-repl
julia> A = rand(-9:9, 2, 2)
2×2 Matrix{Int64}:
 9  5
 3  2

julia> F = eigen(A)
Eigen{Float64, Float64, Matrix{Float64}, Vector{Float64}}
values:
2-element Vector{Float64}:
  0.27984674554472466
 10.720153254455274
vectors:
2×2 Matrix{Float64}:
 -0.497417  0.945605
  0.867511  0.325317

# eigenvalues
julia> F.values
2-element Vector{Float64}:
  0.27984674554472466
 10.720153254455274

# each column is an eigenvector, normalized to a unit vector
julia> F.vectors
2×2 Matrix{Float64}:
 -0.497417  0.945605
  0.867511  0.325317
```

Загалом матриця `n×n` матиме `n` власних значень, хоч і не завжди _різних_.
Уявімо їх як корені многочлена `n`-го степеня (його називають [характеристичним многочленом][wiki-char-poly]), які можуть повторюватися і часто є комплексними навіть для дійснозначної матриці.

Кожен власний вектор задає напрямок, і будь-яке скалярне кратне теж є допустимим власним вектором.
Для зручності подальших обчислень Julia повертає одиничні вектори з [нормою][wiki-norm] 1.

### Застосування

Пояснення того, чому власні вектори важливі, - це радше справа для 500-сторінкового підручника, а не кількох коротких абзаців.
Ця тема пронизує _надзвичайно багато_ сучасної прикладної математики.

На найвищому рівні власні вектори задають «найважливіші» осі (напрямки) в наборі даних.
Власні значення вказують на «відносну важливість» кожної осі (_за певних припущень про нормалізацію вхідних даних_).

Що це насправді _означає_, залежить від застосування.

#### Аналіз головних компонент

У типовій задачі з науки про дані в нас може бути 100 або більше «ознак», збережених як стовпці даних.
Майже неминуче будуть шум, надлишковість і небажані кореляції.

Нам потрібно зменшити розмірність, і [PCA][wiki-PCA] - це один зі способів внести лад у цей хаос:

- Обчислімо [коваріаційну матрицю][wiki-cov-matrix] даних.
- Тепер у нас є квадратна матриця, тож далі обчислімо власні значення та власні вектори.
- Упорядкуймо власні вектори за спаданням їхніх власних значень (точніше, за абсолютною величиною `|λ|`).
- Перші `k` власних векторів тепер і є `principal components`, де `k` значно менше за початкову кількість ознак.
- Спроєктуймо весь набір даних на ці `k` осей і почнімо шукати цікаві закономірності.

У такому вигляді PCA використовували найрізноманітніші групи: від медичних дослідників, які намагаються покращити властивості молекул під час розробки ліків, до політичних агітаторів, які намагаються зрозуміти вподобання виборців за даними опитувань.
Імовірно, також маркетингові групи, які намагаються щось нам продати, але будь-яку технологію можна використати як на добро, так і на зло.

PCA не входить до мінімальної інсталяції Julia, але (поза Exercism) пакет [MultivariateStats][ref-multistats] містить усе потрібне.

#### Обробка зображень

Розвиваючи ідею PCA далі, цифрові зображення - це просто матриці значень пікселів, і для них можна обчислити головні компоненти.

Це десятиліттями використовують у стисненні зображень, де PCA підказує, що найважливіше зберегти під час зменшення розміру файлу.

Дедалі частіше PCA - важлива складова класифікаторів зображень, як-от розпізнавання облич.
Наступного разу, коли ми проходимо через аеропорт, [Великий Брат][wiki-big-brother] не просто спостерігає, він ще й використовує лінійну алгебру, щоб зрозуміти те, що бачить!

#### Машинобудування

Менш суперечливо: головні осі механічної деталі - це власні вектори її [тензора моменту інерції][wiki-I-tensor] ***I*** (матриці під трохи іншою назвою).

Кожне колесо нашого автомобіля, ймовірно, має один або кілька балансувальних вантажів, підібраних так, щоб обнулити позадіагональні елементи цього тензора ***I***.
Автомеханік, безперечно, уникає цих розрахунків (на відміну від конструкторів літаків та інженерів-ракетників), але «биття» - це лише побутове слово для перехресних членів тензора, які в цьому випадку зробили б нашу поїздку менш комфортною і прискорили б механічний знос підшипників.
