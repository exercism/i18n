# Вступ

`Complex numbers` не такі вже й складні.
Їм просто потрібна менш лякаюча назва.

Вони настільки корисні, особливо в інженерії та науці, що Julia включає комплексні числа до стандартних числових типів поряд із цілими числами та числами з плаваючою комою.

## Основи

Значення `complex` у Julia по суті є парою чисел: зазвичай, але не завжди, з плаваючою комою.
Ці частини називають «дійсною» та «уявною», через прикрі історичні причини.
І знову ж таки, краще зосередитися на внутрішній простоті, а не на дивних назвах.

Щоб створити комплексне число з двох дійсних чисел, достатньо додати суфікс `im` до уявної частини.

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im
julia> typeof(z)
ComplexF64 (alias for Complex{Float64})
julia> zi = 1 + 2im
1 + 2im
julia> typeof(zi)
Complex{Int64}
```

Отже, існують різні типи `Complex`, похідні від відповідного цілого типу або типу з плаваючою комою.

Щоб створити комплексне число з дійсних змінних, наведений вище синтаксис не спрацює.
Запис `a + bim` збиває парсер з пантелику, і він вважає `bim` (неіснуючою) назвою змінної.

Записати `b*im` можна, але кращий спосіб використовує функцію `complex()`, яка оминає операції множення й додавання.

```julia-repl
julia> a = 1.2; b = 3.4; complex(a, b)
1.2 + 3.4im
```

Щоб отримати частини комплексного числа окремо:

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im
julia> real(z)
1.2
julia> imag(z)
3.4
```

Або разом:

```julia-repl
julia> reim(z)
(1.2, 3.4)
```

Будь-яка з частин може дорівнювати нулю, і тоді математики можуть казати, що число «цілком дійсне» або «цілком уявне».
Однак у Julia це все одно комплексне число.

```julia-repl
julia> zr = 1.2 + 0im
1.2 + 0.0im
julia> typeof(zr)
ComplexF64 (alias for Complex{Float64})
julia> zi = 3.4im
0.0 + 3.4im
julia> typeof(zi)
ComplexF64 (alias for Complex{Float64})
```

Можливо, доводилося чути, що «`i` (або `j`) - це квадратний корінь з -1».

Поки що це означає лише те, що уявна частина _за визначенням_ задовольняє таку рівність:

```julia-repl
julia> 1im * 1im == -1
true
```

Ідея проста, але вона веде до цікавих наслідків.

## Арифметика

Усі стандартні математичні `operators` та елементарні функції, які застосовують до чисел з плаваючою комою та цілих чисел, працюють і з комплексними числами. Невеликий приклад:

```julia-repl
julia> z1 = 1.5 + 2im
1.5 + 2.0im
julia> z2 = 2 + 1.5im
2.0 + 1.5im
julia> z1 + z2  # addition
3.5 + 3.5im
julia> z1 * z2  # multiplication
0.0 + 6.25im
julia> z1 / z2  # division
0.96 + 0.28im
julia> z1^2  # exponentiation
-1.75 + 6.0im
julia> 2^z1  # another exponentiation
0.5188946835878313 + 2.7804223253571183im
```

## Функції

Крім `real()` та `imag()`, є кілька функцій, особливо доречних для комплексних чисел.

- `conj()` просто змінює знак уявної частини комплексного числа (_з + на - або навпаки_).
    - Через те, як працює множення комплексних чисел, це корисніше, ніж може здатися.
- `abs(<complex number>)` гарантовано повертає дійсне число без уявної частини.
- `abs2(<complex number>)` повертає квадрат `abs(<complex number>)`: обчислюється швидше за `abs()` і часто саме те, що потрібно в обчисленні.
- `angle(<complex number>)` повертає фазовий кут у радіанах.

```julia-repl
julia> z1
1.5 + 2.0im
julia> conj(z1)
1.5 - 2.0im
julia> abs(z1)
2.5
julia> abs2(z1)
6.25
julia> angle(z1)
0.9272952180016122
```
Часткове пояснення, для тих, хто любить математику:

- Запис `(real, imag)` для `z1` по суті використовує декартові координати на комплексній площині.
- Те саме комплексне число можна подати в записі `(r, θ)` за допомогою полярних координат.
- Тут `r` і `θ` задають за допомогою `abs(z1)` та `angle(z1)` відповідно.

Ось приклад із кількома константами:

```julia-repl
julia> euler = exp(1im * π)
-1.0 + 1.2246467991473532e-16im
julia> real(euler)
-1.0
julia> round(imag(euler), digits=15)  # round to 15 decimal places
0.0
```

Полярний запис `(r, θ)` настільки корисний, що існують вбудовані функції `cis` (скорочення від `cos(x) + isin(x)`) та `cispi` (скорочення від `cos(πx) + isin(πx)`), які допомагають будувати його ефективніше.

Корисність полярного запису розкривається у витонченій формулі Ейлера, `ℯ^(iθ) = cos(θ) + isin(θ) = x + iy`, де `|x + iy| = 1`.
Якщо `|x + iy| = r`, отримуємо загальнішу полярну форму `r * ℯ^(iθ) = r * (cos(θ) + isin(θ)) = x + iy`.
Зауважмо, що експоненційна форма особливо компактна й зручна для перетворень.

```julia-repl
julia> exp(1im * π) ≈ cis(π) ≈ cispi(1)
true
```

Наближена рівність вище виникає тому, що функції `cis` і `cispi` можуть давати приємніші числові результати, особливо `cispi`, коли йдеться про аргументи, які є довільними множниками π (наприклад, радіани!).

```julia-repl
julia> cis(π)
-1.0 + 0.0im
julia> cispi(1)
-1.0 + 0.0im
julia> θ = π/2;
julia> exp(im*θ)
6.123233995736766e-17 + 1.0im
julia> cis(θ)
6.123233995736766e-17 + 1.0im
julia> cispi(θ / π)  # θ/π == 1/2
0.0 + 1.0im
```

До речі, саме завдяки цьому комплексні числа дуже корисні для виконання обертань і радіальних зсувів у 2D.

Для обертань комплексне число `z = x + iy` можна повернути на кут `θ` навколо початку координат простим множенням: `z * ℯ^(iθ)`.
Зауважмо, що `x` і `y` тут - це звичайні координати на дійсній двовимірній декартовій площині, а додатний кут дає обертання *проти годинникової стрілки*, тоді як відʼємний - *за годинниковою стрілкою*.

Так само просто можна здійснити радіальний зсув `Δr`, додавши його до модуля `r` комплексного числа в полярній формі (напр. `z = r * ℯ^(iθ)` -> `z' = (r + Δr) * ℯ^(iθ)`).
Зауважмо, що кутова частина залишається незмінною, а змінюється лише модуль `r`, як і очікувалося.
