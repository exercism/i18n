# Докладніше

Оператор `|>` називають [оператором конвеєра][pipe]. Він дає змогу поєднувати виклики функцій у ланцюжок так, що значення, повернене попереднім викликом функції, передається як перший аргумент наступному викликові.

```elixir
String.replace_suffix(String.upcase(String.duplicate("go ", 3)), " ", "!")

# versus

"go "
|> String.duplicate(3)
|> String.upcase()
|> String.replace_suffix(" ", "!")
```

Його також можна записати в одному рядку коду:

```elixir
"go " |> String.duplicate(3) |> String.upcase() |> String.replace_suffix(" ", "!")
```

Функції з модуля `Kernel` зазвичай викликають без імені модуля `Kernel`, але це імʼя потрібне, коли ми використовуємо такі функції в ланцюжку конвеєра. Наприклад, `2 * 3 == 6` можна також записати як:

```elixir
2 |> Kernel.*(3) |> Kernel.==(6)
```

Коли використовувати оператор конвеєра, а коли ні, кожен вирішує сам. Деякі розробники Elixir воліють дотримуватися таких правил:

- Не варто використовувати оператор конвеєра, коли потрібен лише один виклик функції.

  ```elixir
  # do
  String.split("hello", "")

  # don't
  "hello" |> String.split("")
  ```

- Не варто створювати анонімні функції безпосередньо в ланцюжку конвеєра.

  ```elixir
  # do
  take_n_letters = fn n -> Enum.take(?a..?z, n) end
  2 |> Kernel.*(3) |> take_n_letters.()

  # don't
  2 |> Kernel.*(3) |> (fn n -> Enum.take(?a..?z, n) end).()
  ```

- Ланцюжок конвеєра завжди варто починати зі змінної або літерального значення, а не з виклику функції.

  ```elixir
  # do
  "hello" |> String.upcase() |> String.split("")

  # don't
  String.upcase("hello") |> String.split("")
  ```

[pipe]: https://hexdocs.pm/elixir/Kernel.html#%7C%3E/2
