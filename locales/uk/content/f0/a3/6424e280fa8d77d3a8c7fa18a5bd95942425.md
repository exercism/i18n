# Докладніше

## Опціонали

Swift використовує [_опціонали_][optionals], щоб дати програмістам змогу позначати можливу відсутність значення.
Опціонал - це тип, який може або містити значення, або бути [`nil`][nil], що позначає відсутність значення.
Щоб скористатися опціоналом, програма має спершу перевірити, чи значення справді існує, а вже потім розгорнути його й використати.

Будь-який тип можна зробити опціональним, дописавши `?` у кінці назви типу.
Тож опціональне ціле число буде мати тип `Int?`, а опціональний рядок тексту (англ. string) - тип `String?`.
Оголошення констант або змінних опціонального типу та присвоєння їм значень відбувається так само, як і для значень неопціональних типів.

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

Можна присвоїти відсутність значення змінній опціонального типу, присвоївши їй спеціальне значення `nil`.
`nil` можна використовувати з усіма опціональними типами, але `nil`, присвоєні двом різним опціональним типам, мають різні типи, тож їх не можна ні замінювати одне на одне, ні навіть порівнювати.

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

Звернімо увагу також на те, що хоч `nil` можна присвоїти будь-якому опціональному типу, його не можна присвоїти неопціональному типу (навіть якщо той насправді не містить `nil`).
А методу, який приймає неопціональний тип, не можна передати опціональний тип, не розгорнувши його спершу.

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## Використання опціоналів

Оскільки опціональні типи не є тими самими типами, що й їхні базові типи, ці два типи не можна використовувати однаково.
Наприклад, `Int("123") + 1` спричиняє помилку компіляції «Value of optional type 'Int?' must be unwrapped to a value of type 'Int'».
Річ у тім, що `Int("123")` повертає опціональний тип `Int?`, а не тип `Int`, бо якщо рядок тексту не вдасться перетворити на ціле число, результатом буде `nil`.
Щоб дістати `Int` після перетворення, його треба спершу «розгорнути».

Найчастіше в Swift для цього використовують конструкції `if-let` та `guard-let` для [_привʼязування опціоналів_][optional-binding]: вони перевіряють на `nil` і, якщо значення існує, виконують один шлях коду, привʼязуючи розгорнуте значення до заданої назви, а якщо трапився `nil` - інший шлях.

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

Варто зауважити, що змінна `safeNum` має тип `Int`, а не `Int?`.
У прикладі нижче `num` має тип `Int?`, а `safeNum` - тип `Int`.

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

Це _привʼязування опціоналів_ важливе, бо воно розгортає (або «прибирає») опціональний тип зі значення, дозволяючи використати його як неопціональне значення.
Якби ми просто перевірили умовою, чи значення дорівнює `nil`, значення все одно мало б опціональний тип:

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

Варіант із `guard-let` теж можна використати там, де потрібне дострокове повернення:

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## Порівняння опціоналів

Зауважмо, що навіть якщо базові типи пари опціоналів можна порівнювати стандартними операторами порівняння, самі опціонали порівнювати не можна.
Їх можна лише перевіряти на рівність.
Два опціонали рівні, якщо обидва дорівнюють `nil` або якщо значення, які вони містять, рівні в межах своїх базових типів.

Утім, можна написати код для власного порівняння двох опціональних значень.
Нижче наведено приклад конструкції `switch`, яка поверне `true` лише тоді, коли обидва опціональні значення не дорівнюють `nil`, а перше з них менше за друге.
Для цього вона використовує _шаблон опціоналу_ `varName?`, який збігається лише з опціоналами, що не дорівнюють `nil`, і привʼязує значення всередині опціоналу до назви `varName`.

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## Обʼєднання з nil

Є ще один спосіб розгортання: можна скористатися [запасним значенням][fallback], якщо трапився `nil`.
Це робиться за допомогою _оператора обʼєднання з nil_, `??`.
Нехай `x` має тип `Int?`. Якщо написати `let y = x ?? 0`, Swift перевірить, чи `x` дорівнює `nil`.
Якщо ні, він розгорне `x` і присвоїть розгорнуте значення `y`; а якщо `x` _таки_ `nil`, то присвоїть `y` значення 0.

Оскільки `x ?? y` - це лише скорочений запис для `x != nil ? x! : y`, то якщо `x` не дорівнює nil, вираз `y` взагалі не обчислюється.

І наостанок зауважимо, що оператор обʼєднання з nil має праву асоціативність, що може дати несподівані результати для непідготовлених.

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

Докладніше про оператор обʼєднання з nil можна прочитати в [A Tour of Swift: Nil-Coalescing Operator][nil-coalescing].
