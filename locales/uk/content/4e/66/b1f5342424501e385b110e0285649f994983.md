# Інструкції

Ми підтримуємо набір інструментів для генерації коду на сигнальній станції.
Кожен макрос - це *трафарет*, невеликий шаблон, який компілятор використовує, щоб
відтискати спеціалізований код у кожному місці виклику.

Ми пишемо лише чотири макроси. Файл тестів визначає невеликі слова-обгортки, які
*викликають* наші макроси (макрос можна спостерігати лише через код, який він
генерує), а потім перевіряє результати виконання цих обгорток. Обгортки
залишаємо без змін.

Для кожного завдання тіло отримує літеральні вхідні дані місця виклику на стеку
й повинно залишити **один quotation**. Рядки «compiles to» показують лінійний код,
який має згенерувати наша quotation.

## 1. Двічі підряд

`twice` приймає літеральну quotation і повертає quotation, що запускає оригінал
двічі підряд.

```factor
! : inc-twice ( x -- y ) [ 1 + ] twice ;
! body receives [ 1 + ]  ->  must build [ 1 + 1 + ]
5 inc-twice .   ! => 7
```

## 2. N повторень

`repeat-quot` приймає літеральну quotation і літеральну кількість `n`
та повертає quotation, що запускає оригінал `n` разів підряд.
`n = 0` повертає порожню quotation `[ ]`.

```factor
! : inc-thrice ( x -- y ) [ 1 + ] 3 repeat-quot ;
! body receives [ 1 + ] 3  ->  must build [ 1 + 1 + 1 + ]
5 inc-thrice .   ! => 8
```

## 3. Поєднання багатьох

`compose-many` приймає літеральний масив quotation і повертає
одну quotation, що запускає кожну з них по черзі. Порожній масив
повертає порожню quotation.

```factor
! : pipeline ( x -- y ) { [ 1 + ] [ 2 * ] [ 1 - ] } compose-many ;
! body receives { [ 1 + ] [ 2 * ] [ 1 - ] }  ->  must build [ 1 + 2 * 1 - ]
5 pipeline .   ! => 11
```

## 4. Розгорнута ітерація

`each-literal` приймає літеральну послідовність і quotation. Він
повертає quotation, що для кожного елемента послідовності кладе
цей елемент на стек, а потім запускає quotation. Ітерація
відбувається під час компіляції, тож згенерований код буде лінійним.

```factor
! : sum-three ( -- n ) 0 { 10 20 30 } [ + ] each-literal ;
! body receives { 10 20 30 } [ + ]  ->  must build [ 10 + 20 + 30 + ]
sum-three .   ! => 60
```

Це найструктурніше із чотирьох завдань: і довжина послідовності,
*і* значення її елементів визначають згенерований код. У підказках
ми покроково розберемо, як його побудувати.
