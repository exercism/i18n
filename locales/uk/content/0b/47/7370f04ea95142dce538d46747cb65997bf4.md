# Вступ

Концепція умовних конструкцій представляє `jcc`, родину інструкцій для розгалуження за умовою.
`jcc` передає керування в іншу точку програми лише тоді, коли виконано її умову.

Однак сучасні процесори швидкі й здатні виконувати багато інструкцій паралельно.
Було б надто затратно зупиняти всю роботу, поки процесор чекає на перевірку умови під час виконання.

Саме тому всередині процесор не чекає.
Він використовує **передбачувач розгалужень**, щоб угадати результат умови, і починає _спекулятивно_ виконувати передбачений шлях.

Якщо передбачення правильне, виконання триває так, ніби розгалуження не було.
Однак якщо передбачення хибне, процесор мусить _відкинути роботу, виконану_ на передбаченому шляху, і перезапуститися на правильному.

Це називають **помилковим передбаченням розгалуження**, і воно дороге, бо спричиняє затримку.

Коли розгалуження важко передбачити, ці помилкові передбачення накопичуються.
У таких випадках іноді краще взагалі уникнути розгалуження, щоб ті самі інструкції виконувалися незалежно від умови.
Код, який вибирає між значеннями без `jcc`, називають **кодом без розгалужень**.

Є кілька способів структурувати код так, щоб він розгалужувався рідше або щоб наявні розгалуження були передбачуванішими.
Зокрема, x86-64 надає дві родини інструкцій, які зазвичай використовують для написання коду без розгалужень.

## Умовні переміщення

Родина інструкцій `cmovcc` копіює операнд-джерело в призначення лише тоді, коли виконано певну умову.
Інакше призначення залишається без змін.

Суфікс `cc` має те саме найменування, що й у `jcc`, і те саме значення:

| інструкція | перемістити, якщо                     |
|-------------|--------------------------------------|
| `cmove`     | A == B після `cmp A, B`              |
| `cmovne`    | A != B після `cmp A, B`              |
| `cmovl`     | A < B (зі знаком) після `cmp A, B`   |
| `cmovb`     | A < B (без знаку) після `cmp A, B`   |
| `cmovg`     | A > B (зі знаком) після `cmp A, B`   |
| `cmova`     | A > B (без знаку) після `cmp A, B`   |

Правила схожі на `jcc`:

1. `l` і `g` використовують для порівнянь зі знаком, а `b` і `a` для порівнянь без знаку.
2. Додавання `e` до суфікса включає рівність.
3. Додавання `n` заперечує умову.
4. Є також варіанти, що вказують на встановлений прапорець.
   Наприклад, `cmovz` і `cmovc`.

Розгляньмо абсолютне значення цілого числа зі знаком у `rdi`, яке повертають у `rax`.
Записана через `jcc`, функція вибирає один із двох шляхів:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Записана через `cmovcc`, вона обчислює обидва можливі значення безумовно, а умовне переміщення вибирає одне з них:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

Версія без розгалужень завжди виконує ті самі інструкції.
Тут немає `jcc`, яке міг би вгадати передбачувач.

Призначенням `cmovcc` має бути регістр.
Джерелом може бути регістр або комірка памʼяті, але не безпосереднє значення.

~~~~exercism/note
У наведеному вище коді інструкція `neg` встановлює кілька прапорців відповідно до результату, зокрема прапорець знаку (SF).
Це означає, що `cmp rdi, 0` можна взагалі прибрати:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Для додатного `rdi` інструкція `neg` дає відʼємний результат і SF == 1, тож `cmovs` відновлює `rdi`.
Для нуля або відʼємного `rdi` інструкція `neg` дає невідʼємний результат і SF == 0, тож `rax` зберігає заперечене значення (яке і є правильним абсолютним значенням).

Хоча `cmp` - основний спосіб порівнювати значення в асемблерному коді, багато інструкцій також встановлюють прапорці відповідно до свого результату.
Повний список прапорців, на які впливає інструкція, зазвичай наведено в її [довіднику][reference].
Для `neg` зокрема це SF, ZF, CF, OF і PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

## Умовне встановлення

Родина інструкцій `setcc` встановлює операнд призначення в `1`, якщо виконано певну умову, і в `0` інакше.
Призначення завжди є _8-бітним операндом_.

Суфікс `cc` має те саме найменування, що й у `jcc` та `cmovcc`.
Наприклад, `setz` встановлює призначення в `1`, якщо `ZF == 1`, і в `0` інакше.

Оскільки призначення 8-бітне, зазвичай після `setcc` ставлять `movzx`, коли потрібне ширше значення:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Це поширений прийом для перетворення результату порівняння на ціле число `0` або `1`.
