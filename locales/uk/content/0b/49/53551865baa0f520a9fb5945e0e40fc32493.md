# Вступ

*Сигнальник* на борту корабля берегової охорони веде журнал повідомлень. Необроблені сигнальні прапорці надходять обрамлені маркерними символами; показники треба готувати для передачі по дроту; пари й трійки спостережень підсумовуються на ходу. Більшу частину роботи виконують кілька ідіом зі стандартної бібліотеки Factor.

## `unparse` - від значення до вихідного коду

[`unparse`][unparse] (у `prettyprint`) повертає текст будь-якого значення у вихідній формі:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` виконує обернену до парсера операцію: круговий обіг `dup unparse parse` відтворює значення. Це правильний інструмент для серіалізації у формат дроту, який одержувач розбере назад, і неправильний інструмент для виведення, призначеного для читання людиною (рядки тексту (англ. string) зберігають свої лапки, вектори зберігають свої `V{ ... }` тощо).

## Варіанти зрізу - представлення, а не копії

`head` і `tail` з `sequences` *копіюють* ту частину, яку ми залишаємо, у нову послідовність. Їхні відповідники `-slice` повертають обʼєкт `slice` (кортеж із початковим індексом, кінцевим індексом і базовою послідовністю), який реалізує [протокол послідовностей][sequence-protocol] без копіювання:

| слово         | дія                                             |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )` - копіює перші n          |
| `head-slice`  | `( seq n -- slice )` - представлення перших n   |
| `tail`        | `( seq n -- newseq )` - копіює від індексу n і далі |
| `tail-slice`  | `( seq n -- slice )` - представлення від індексу n і далі |
| `head*`       | `( seq n -- newseq )` - копіює все, крім останніх n |
| `head-slice*` | `( seq n -- slice )` - представлення всього, крім останніх n |
| `tail*`       | `( seq n -- newseq )` - копіює останні n        |
| `tail-slice*` | `( seq n -- slice )` - представлення останніх n |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

`slice` *є* послідовністю, тож усе, що приймає послідовність, приймає й зріз: `length`, `first`, `each` тощо працюють без копіювання. Тести, яким треба порівняти з літеральним рядком тексту, можуть привести його через `>string`.

## `?head` і `?tail` - знімаємо маркер, якщо він присутній

Обрамлені показники містять маркерний текст, якого може й не бути. `?head` і `?tail` (у `splitting`) намагаються зняти префікс або суфікс, повертаючи (можливо, скорочену) послідовність *і* булеве значення (англ. Boolean), яке повідомляє, чи знайдено маркер:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

Булеве значення в кінці робить їх природним вибором для захисної перевірки: поєднаймо `?head` з `if`, щоб розгалузитися залежно від того, чи було обрамлення, або з `unless`, щоб відкинути вхідні дані, у яких немає очікуваного маркера.

## `<repetition>` - N копій, віртуально

[`<repetition>`][repetition] (у `sequences`) - ще одна віртуальна послідовність без копіювання: `( len elt -- repetition )` будує послідовність із `len` елементів, які всі дорівнюють `elt`, не виділяючи стільки місця в памʼяті:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

Сам `elt` може бути послідовністю, і кожна копія - це та сама послідовність. Тоді `concat` зʼєднує копії послідовно, одну за одною:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

Як і `slice`, результат *є* послідовністю: `length`, `each` та інші працюють із ним безпосередньо. Вдаваймося до неї, щоб доповнити код сигналу до фіксованої ширини чи викласти низку повторюваних маркерів; приводимо до конкретної послідовності через `>string` (або `>array`) лише тоді, коли вона справді потрібна.

## `<clumps>` - вікна, що перекриваються, віртуально

[`<clumps>`][clumps] (у `grouping`) - третя віртуальна послідовність без копіювання: `( seq n -- clumps )` розглядає `seq` як низку вікон довжини `n`, що *перекриваються*, і кожне таке вікно є зрізом:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

Послідовність із `length` елементів дає `length - n + 1` вікон. Оскільки кожне вікно - це зріз, попарне зіставлення послідовних показників не коштує жодного копіювання: `[ first2 ]` на кожному 2-вікні дає нам усі послідовні пари, з яких можна проєктувати. (А його родич без перекриття, `<groups>`, натомість розбиває послідовність на блоки, що не перетинаються.)

## Багатовходовий cleave - `2bi`, `3bi`, `2tri`, `3tri`

Звичайні слова cleave `bi` і `tri` застосовують два або три квотейшни до *одного* входу. Варіанти з префіксом `2` і `3` застосовують кожен квотейшн до *двох* або *трьох* входів:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

Кожен квотейшн отримує *усі* входи. Використовуймо їх тоді, коли від однієї пари (чи трійки) значень залежить більше ніж одна проєкція, а не тоді, коли треба застосувати *ту саму* операцію до кожного входу окремо (для цього є `bi@` або `tri@`).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
