# Докладніше

Factor поділяє потокове введення-виведення на два рівні. Нижчий рівень - це
API *явних потоків*: кожне слово приймає потік як аргумент. Верхній рівень -
це API *поточного потоку*: короткі однорядкові слова, які діють на тому
потоці, що привʼязаний зараз. Обидва рівні спираються на той самий
[протокол][stream-protocol]: слова верхнього рівня лише беруть поточний потік
і переадресовують виклик.

## Слова явних потоків

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents` вичерпує все; `stream-lines` вичерпує й розбиває за межами
рядків; `stream-readln` повертає по одному рядку за раз (або `f` у кінці
потоку).

## Слова поточного потоку

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

Це повсякденні слова для введення-виведення. Вони беруть поточний потік
введення або виведення з динамічних змінних `input-stream` / `output-stream`
і передають його далі. Ось чому, щоб перенаправити `print` у рядок тексту
(англ. string), достатньо привʼязати `output-stream` на час виконання
квотейшена.

## Готові конструктори потоків

| слово             | модуль               | що він створює                  |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | читає з рядкового літерала      |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | збирає записи в рядок тексту    |
| `<file-reader>`   | [`io.files`][io.files]           | читає файл із заданим кодуванням   |
| `<file-writer>`   | [`io.files`][io.files]           | записує файл із заданим кодуванням  |

Усі чотири створюють обʼєкти, які можна звільнити: вони розширюють
`disposable` з `destructors`, тож наведені нижче комбінатори `with-…`
звільняють їх при виході.

## Привʼязування в межах області видимості

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

Кожен із них відкриває потік, привʼязує його як поточний потік введення або
виведення для внутрішнього квотейшена і звільняє його при виході, навіть
якщо квотейшен викине помилку. Це комбінатори-деструктори з
`boatswains-bilge`, спеціалізовані для потоків.

`with-string-writer` - особливо чистий варіант: він автоматично створює
новий `<string-writer>`, виконує квотейшен, узявши цей записувач за поточний
вивід, і повертає накопичений рядок тексту. Увесь прийом «захопити вивід
квотейшена» зводиться до одного слова.

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## Навіщо взагалі поточний потік?

Завдяки привʼязуванню через динамічні змінні `print` працює в програмі, яка не
знає, чи її запускають інтерактивно, чи вона пише у файл журналу, чи в
захоплений буфер тестів. Достатньо один раз замінити привʼязування, і кожне
слово, яке викликає `print`, робить те, що треба, без жодного
перепідключення. Саме цю інверсію й дає нам верхній рівень.

Щоб *реалізувати* потік, тобто визначити власний клас, який вбудовується в
протокол, звернімося до концепції `streams` (вона викладається в
`telegraphers-tape`).
