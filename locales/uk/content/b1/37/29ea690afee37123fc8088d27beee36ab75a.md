# Узагальнені класи

Ми використовуємо `ARRAY{STR}`, `FMAP{STR,INT}` і `FSET{STR}` від самого початку.
У фігурних дужках завжди стояв тип. Тепер ми пишемо клас із власними дужками.

## Проблема

Бюро знахідок потребує коробки, яка зберігає одну річ і памʼятає, хто її здав.
Коробка для светра:

```sather
class JUMPER_BOX is
   attr item : JUMPER;
   ...
end;
```

а потім той самий клас ще раз для пляшки для води і ще раз для телефона.
Три копії, які відрізняються одним словом.

## Параметр типу

```sather
class LOST_BOX{T} is

   attr item : T;

   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;

end; -- class LOST_BOX{T}
```

`{T}` після назви класу задає **параметр типу**. `T` — не тип, а замінник
будь-якого типу, який передають під час використання класу. Усередині класу
`T` використовують точно так само, як будь-яку іншу назву типу.

## Як це використовувати

Тип передають у фігурних дужках:

```sather
   jumper ::= #LOST_BOX{STR}("blue jumper");
   count ::= #LOST_BOX{INT}(3);

   jumper.item      -- "blue jumper", a STR
   count.item       -- 3, an INT
```

`LOST_BOX{STR}` і `LOST_BOX{INT}` дають два різні типи. Якщо підставити один
там, де потрібен інший, компілятор зловить помилку, точно так, як якби ми
написали обидва класи вручну, що, власне, і відбувається: Sather будує
окремий клас за зразком для кожного типу, який фактично використано.

Тож у час виконання це нічого не коштує й не втрачає інформації про тип:
`jumper.item` справді має тип `STR`, а не щось, що доводиться перевіряти чи
перетворювати.

## Більше ніж один

Клас може приймати кілька параметрів, розділених комами. `FMAP{K,T}` —
приклад, який ми вже знаємо.

```sather
class LABELLED{L,T} is
   attr label : L;
   attr item : T;
   ...
end;
```

## Назви

За домовленістю використовують однолітерні великі літери: `T` для речі, `K`
для ключа, `E` для елемента. Бібліотека використовує їх усюди.
