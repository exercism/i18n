# Вступ

*Регулярний вираз* (regex) - це невеликий шаблон, який описує, як має
виглядати якийсь текст. Замість того, щоб перевіряти рядок тексту (англ.
string) символ за символом самостійно, ми записуємо потрібну форму один
раз, а зіставлення доручаємо Factor. Інструменти Factor для регулярних
виразів містяться у словнику [`regexp`][regexp].

## Як записати шаблон

У Factor регулярний вираз записують між `R/ ` і `/`:

```factor
R/ cat/      ! the pattern that matches the letters c, a, t
```

Більшість символів у шаблоні означають самі себе: `R/ cat/` збігається з
текстом `cat`. Уся сила в кількох особливих елементах, які позначають
*види* символів або *скільки* їх.

### Класи символів - «один символ із набору»

```
\d        ! any digit, 0–9
\D        ! any NON-digit (the opposite of \d)
\s        ! any space, tab, or newline
\S        ! any NON-space character (the opposite of \s)
\w        ! a "word" character: a letter, a digit, or an underscore
\W        ! any NON-word character (the opposite of \w)
[A-Z]     ! any one capital letter A to Z
[a-z]     ! any one lowercase letter
[0-9]     ! any one digit (same as \d)
.         ! any single character at all
```

Клас збігається рівно з *одним* символом. `[A-Z]` збігається з `Q`, але
не з `QQ`.

### Квантифікатори - «скільки разів»

Поставмо один із них *після* елемента, щоб указати, скільки разів він
може повторитися:

```
{4}       ! exactly 4 times
{2,5}     ! between 2 and 5 times
+         ! one or more
*         ! zero or more
?         ! zero or one (optional)
```

Отже, `\d{4}` означає чотири цифри підряд, а `[A-Z]+` означає одну або
більше великих літер. Зібравши все докупи, `R/ [A-Z]+-\d+/` описує «одну
або більше великих літер, дефіс, а потім одну або більше цифр», тобто
текст на кшталт `SALE-2024`. Дефіс `-` тут - звичайний символ: поза
`[ ]` він просто збігається з дефісом (усередині класу, як у `[A-Z]`, він
позначає діапазон).

## Зіставлення цілого рядка тексту

`matches?` відповідає на запитання «чи вписується в шаблон *увесь* рядок
тексту?»: шаблон має враховувати кожен символ, від початку до кінця:

```
matches? ( string regexp -- ? )
```

```factor
USING: regexp ;

"SALE-2024"     R/ [A-Z]+-\d+/ matches? .   ! => t
"GET SALE-2024" R/ [A-Z]+-\d+/ matches? .   ! => f   (extra text before)
"SALE-2024 NOW" R/ [A-Z]+-\d+/ matches? .   ! => f   (extra text after)
"sale-2024"     R/ [A-Z]+-\d+/ matches? .   ! => f   (lowercase letters)
```

Навіть попри те, що `SALE-2024` міститься всередині `"GET SALE-2024"`,
`matches?` усе одно повертає `f`: зайві символи є частиною рядка тексту і
не вписуються в шаблон. Коли нам важливо лише те, чи трапляється шаблон
*десь* усередині, звернімося до `re-contains?`: він повертає `t` саме
там, де `matches?` повертав `f`:

```
re-contains? ( string regexp -- ? )
```

```factor
USING: regexp ;

"GET SALE-2024" R/ [A-Z]+-\d+/ matches? .      ! => f
"GET SALE-2024" R/ [A-Z]+-\d+/ re-contains? .  ! => t
```

## Пошук збігів у довшому тексті

`re-contains?` повідомляє лише *чи* є шаблон усередині. Наступні слова
зазирають усередину й повідомляють, *що* збіглося: `all-matching-subseqs`
повертає кожне місце, де шаблон збігається, як послідовність рядків
тексту, а `count-matches` просто рахує їх:

```
all-matching-subseqs ( string regexp -- seq )
count-matches        ( string regexp -- n )
```

```factor
USING: regexp ;

"3 cats, 12 dogs, 1 fish" R/ \d+/ all-matching-subseqs .
! => { "3" "12" "1" }            (every run of digits)

"the quick fox" R/ \S+/ all-matching-subseqs .
! => { "the" "quick" "fox" }     (every run of non-space characters)

"id_7!" R/ \w/ count-matches .   ! => 4   (i, d, _ and 7 count; ! does not)
```

## Заміна збігів

`re-replace` замінює кожен збіг на текст заміни й повертає новий рядок
тексту:

```
re-replace ( string regexp replacement -- result )
```

```factor
USING: regexp ;

"page 7 of 12" R/ \d+/ "N" re-replace .
! => "page N of N"
```

У словнику `regexp` є й інші слова, які варто знати. Деталі за
посиланнями: [`first-match`][first-match] (лише перший збіг) і
[`re-split`][re-split] (розбити рядок тексту в кожному місці, де
збігається шаблон).
