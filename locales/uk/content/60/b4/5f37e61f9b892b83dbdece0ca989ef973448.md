# Вступ

[Власні типи][custom-types] в Elm задають фіксовану кількість іменованих випадків. Кожне значення відповідає рівно одному з цих іменованих випадків.

Власний тип визначають за допомогою ключового слова `type`, і він потребує дуже мало синтаксису. Це одна з найважливіших технік у програмуванні мовою Elm: за її допомогою можливі значення в коді точно відповідають припустимим значенням у реальному житті. Тоді не залишається місця для некоректних даних, а [неможливі стани неможливо представити в коді][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Кожен випадок власного типу може необовʼязково мати повʼязані з ним дані, а різні випадки можуть мати дані різних типів. Якщо жоден з випадків не має повʼязаних даних, розмічене обʼєднання схоже на те, що в інших мовах зазвичай називають _переліченням_ (або _enum_).

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Створити значення для конкретного випадку можна, звернувшись до його назви (`Spring`), якщо його визначено в тому самому модулі або імпортовано синтаксисом `import SeasonModule exposing (Season(..))`, або звернувшись до його повного імені (`Season.Spring`), якщо його імпортовано синтаксисом `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Власні типи, як і все в Elm, мають _структурну рівність_. Це означає, що два значення для того самого випадку та з однаковими (необовʼязковими) даними еквівалентні.

Найкращий спосіб працювати з власними типами - [зіставлення зі зразками][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
