# Детальніше

## Представлення, символи та цілі числа

Як і в інших простих типів (`int`s, `bool`s тощо), у `char` є супутній тип, або тип-псевдонім, у цьому випадку `System.Char`.

Насправді `char` визначено як `struct` із 16-бітним полем, який за замовчуванням не можна змінювати.

У `char` є кілька методів екземпляра, як-от `Equals`, `ToString` і [`CompareTo`][compare-to].

`char` має ту саму ширину, що й [`ushort`][uint16], але їх зазвичай не використовують взаємозамінно, як це роблять у деяких мовах. `ushort` потрібно явно привести до `char`.

Зауважимо, що над `char` можна виконувати арифметичні операції. Результатом таких операцій буде ціле число.

Звісно, між 8-бітним `byte` і 16-бітним `char` немає жодної відповідності.

## Використання

Зазвичай із `char` легко працювати.

Їх можна задавати літералами в одинарних лапках:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

Окремий `char` можна дістати з рядка тексту (англ. string) за допомогою індексації (з нуля):

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

Перебираючи рядок тексту, на кожному кроці отримуємо `char`:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

Як показано вище, `char` можна привести до його значення `int`.
Це також працює (*принаймні іноді*) для інших систем письма:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

Під час порівняння символів використовується базовий Int16:

```fsharp
'A' < 'D'
// => val it: bool = true
```

Також `int` можна привести до `char`:

```fsharp
char 77
// => val it: char = 'M'
```

Бібліотека `System.Char` містить повний набір [методів][Char-methods], притаманних мовам .NET, як-от перетворення на верхній/нижній регістр (але про застереження йтиметься в наступному розділі):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

Бібліотеки .NET допомагають вилучати `char` з рядків тексту, у цьому випадку методами `Seq`:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

Є різні способи перетворити список (або масив) символів на рядок тексту, зокрема такі:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

Загальну інформацію про `char` можна знайти тут:

- [Документація про `char`][chars-docs]: довідкова документація про `char`.

Однак із `char` повʼязано чимало гострих кутів, про які йдеться далі. Ці гострі кути здебільшого стосуються протиставлення повного стандарту Unicode, з одного боку, та історичних способів подання тексту, а також продуктивності й використання памʼяті, з іншого.

## Проблеми з Unicode

Коли ми маємо справу з рядками тексту, якщо доступні методи бібліотеки [`System.String`][System-string], варто шукати саме їх і використовувати, а не розбивати рядок тексту на символи.

Деякі текстові «символи» складаються з більш ніж одного `char`, бо стандарт Unicode має понад 65536 кодових точок. Наприклад, емодзі, які трапляються в деяких тестах, містять 2 `char`, оскільки складаються із [сурогатних][surrogates] символів.

Крім того, існують комбіновані послідовності: подекуди символ із діакритичним знаком може складатися з одного `char` для самого символу і ще одного `char` для діакритичного знака.

Якщо доводиться працювати з окремими символами, варто використовувати методи бібліотеки, як-от [`System.Char.IsControl`][is-control], [`System.Char.IsDigit`][is-digit], а не робити наївних порівнянь, наприклад перевіряти, чи символ розташований між '0' і '9'.

Наприклад, зауважмо, що '٢' позначає арабську цифру 2. Для арабського варіанта `IsDigit` поверне `true`, тож під час перевірки треба чітко визначити, який діапазон входів прийнятний.

Навіть методи бібліотеки `System.Char` можуть поводитися не так, як ми очікуємо, коли маємо справу з менш поширеними мовами.

Один зі способів безпечно розбити рядок тексту на «символи» для відображення - скористатися [`StringInfo`][string-info] і такими методами, як [`GetNexttextElement`][get-next-text-element].
Це може знадобитися, якщо ми маємо справу з глобалізацією чи локалізацією.

Ще один підхід, де важливі скалярні значення символів Unicode (скажімо, коли ми пишемо власну систему кодування) - скористатися [`Rune`][runes]. Однак, якщо відомо, що діапазон символів, з якими ми працюємо, не містить сурогатів чи комбінованих послідовностей (наприклад, латинський ASCII), а вхідні дані добре перевірено, цього можна й уникнути.

І знову ж таки, найкраща ситуація - коли можна скористатися методами бібліотеки `String`.

Якщо ж ми опинимося в незавидному становищі, розбираючись із дрібницями Unicode, то [це][char-encoding-net] стане гарною відправною точкою.

## Глобалізація
