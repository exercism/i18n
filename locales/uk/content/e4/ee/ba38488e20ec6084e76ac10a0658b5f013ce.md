# Вступ

## Символи

**Кодування символів** - це конкретна домовленість про те, як подати елементи тексту природною мовою у вигляді послідовності байтів.
«Елементом тексту» тут може бути будь-яка одиниця, що має значення в природній мові: наприклад, літери, пробіли, розділові знаки, емодзі, ідеограми тощо.

У NASM (The Netwide Assembler, асемблер, який використовують у цьому треку) є підтримка визначення даних за допомогою **ASCII**.

Символьні константи в NASM можуть бути завдовжки до 8 байтів і можуть визначатися за допомогою одинарних лапок (`'`), подвійних лапок (`"`) або зворотних лапок (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Спеціальні символи потрібно визначати у зворотних лапках і екранувати за допомогою `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Зауважмо, що в x86-64 немає вбудованої підтримки будь-якого кодування символів як окремого типу.
Дані в асемблері - це послідовність байтів, а те, чи тлумачити ці байти як символ, число чи щось інше, програміст вирішує сам.

Наприклад, символ ASCII '0' - це один байт зі значенням 48.
Отже, зберегти 48 у байті - це те саме, що зберегти символ ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

З цієї ж причини робота із символами полягає в безпосередньому перетворенні значень у цих байтах:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Рядки тексту

**Рядок тексту** (англ. *string*) - це послідовність символів.
В асемблері його зазвичай реалізують як масив.

У NASM рядок тексту можна оголосити так само, як оголошують будь-який масив:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Одна з відмінностей рядків тексту від інших масивів у тому, що NASM також підтримує оголошення рядків тексту без коми (`,`), яка розділяє значення.
Також можна чергувати значення з комами:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Зауважмо, що, як уже згадувалося, символи - це просто байти (або послідовність байтів у кодуванні Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Оскільки кожен символ ASCII займає один байт, будь-який наступний байт у ширшому розмірі дорівнює `0`.
Наприклад, якщо оголосити `'a'` як qword (8 байтів), перший байт буде `'a'` (`97`), а решта сім байтів дорівнюють `0`.

З цієї причини всі вони рівнозначні:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
В асемблері рядки тексту не завершуються автоматично символом ASCII NUL (значення `0`).

Під час взаємодії з мовами вищого рівня, як-от C, саме програміст відповідає за те, щоб у кінці рядка тексту було додано правильний термінатор, якщо він потрібен.
~~~~

## Рядкові інструкції

Оскільки рядки тексту - це масиви, з ними можна працювати так само, як з будь-яким масивом, явно розіменовуючи памʼять:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Крім того, є кілька інструкцій для завантаження, переміщення й збереження значень у послідовностях байтів у памʼяті.
Хоча їх називають _рядковими інструкціями_, їх можна використовувати з будь-якою послідовністю байтів у памʼяті, тобто з будь-яким масивом.

Три найважливіші рядкові інструкції - це `lods`, `stos` і `movs`:

| інструкція | що вона робить                                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | завантажує значення з комірки памʼяті, на яку вказує `rsi`, у `rax`                                              |
| `stos`      | зберігає значення з `rax` у комірці памʼяті, на яку вказує `rdi`                                                 |
| `movs`      | копіює значення з комірки памʼяті, на яку вказує `rsi`, і зберігає його в комірці памʼяті, на яку вказує `rdi`    |

Зауважмо, що ці інструкції _не_ приймають жодного явного операнда.
Їхні операнди неявні.

Як орієнтовне правило:

1. Коли їхній операнд-джерело - це комірка памʼяті, її адресу слід зберігати в `rsi` (`s` від source).
2. Коли їхній операнд-призначення - це комірка памʼяті, її адресу слід зберігати в `rdi` (`d` від destination).
3. Якщо один з операндів не є коміркою памʼяті, то це регістр `rax`.

Зауважмо, що ці інструкції автоматично розіменовують адреси памʼяті відповідно до конкретної операції, яку вони виконують.

Усі вони можуть працювати з різними розмірами.
Щоб указати цей розмір, до них додають суфікс:

| суфікс | значення            | розмір  |
| :----: | ------------------- | :------ |
|  `b`   | байт                | 1 байт  |
|  `w`   | слово               | 2 байти |
|  `d`   | подвійне слово      | 4 байти |
|  `q`   | чотириразове слово  | 8 байтів |

Наприклад:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

Вони також змінюють кожну використану адресу на розмір операції.
Ця зміна відбувається відповідно до значення **прапорця напрямку (DF)**:

- Якщо `DF` скинуто, адреси _збільшуються_ на розмір операції.
- Якщо `DF` встановлено, адреси, навпаки, _зменшуються_ на ту саму величину.

System V ABI зазначає, що прапорець напрямку має бути скинуто на вході у функцію.
Отже, _типова поведінка полягає в тому, що памʼять читають і записують у порядку зростання адрес_.

Інструкцію `cld` можна використати, щоб скинути прапорець напрямку, а інструкцію `std` - щоб його встановити:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Той, хто викликає, розраховує на те, що після повернення з будь-якої викликаної функції `DF` буде скинуто, згідно з System V ABI.
Якщо колись доведеться встановити `DF`, перед `ret` його обовʼязково потрібно скинути.
~~~~

### Rep

Крім них, інструкція **rep** безпосередньо не взаємодіє з памʼяттю.
Натомість її можна додати як префікс до інших згаданих інструкцій, _повторюючи_ ці інструкції.

З префіксом `rep` рядкові інструкції повторюються стільки разів, скільки дорівнює значення в `rcx`.
Щоразу значення в `rcx` зменшується на `1`.
Зауважмо, що значення в `rcx` потрібно встановити до використання інструкції:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
На сучасних процесорах `rep movs` і `rep stos` зазвичай швидкі варіанти, коли дані переміщують великими блоками.
Однак інші рядкові інструкції, і навіть `movs` і `stos` без `rep`, зазвичай повільніші за звичайний цикл.

Докладніше про це можна прочитати в [розділі 16.9, «String instructions», цієї довідки][agner-optimization-guide].
