# Словники та множини

| Тип | Що містить | Пошук за |
| --- | --- | --- |
| `ARRAY{T}` | значення в порядку | позицією |
| `FMAP{K,T}` | пари ключ-значення | ключем |
| `FSET{T}` | значення без повторів | належністю |

## FMAP

```sather
   m ::= #FMAP{STR,INT};
   m := m.insert("emu", 2);
   m.get("emu")          -- 2
   m.has_ind("emu")      -- true
   m.size                -- 1
   m := m.delete("emu");
```

`m["emu"]` — **не** спосіб прочитати значення зі словника. У `FMAP` немає такої процедури, і цей рядок не скомпілюється. Для цього є `get`.

### Відсутні ключі

`get` для ключа, якого немає, повертає порожнє значення для цього типу, а не скаржиться: `0`, `false` або void. `STR` зі значенням void не зазнає збою там, де його створено; збій станеться пізніше, там, де його зрештою використають. Варто виробити звичку спершу викликати `has_ind`.

## FSET

```sather
   s ::= #FSET{STR};
   s := s.insert("emu");
   s.has("emu")          -- true
   s.size                -- 1
   s := s.delete("emu");
```

Множини поєднуються:

```sather
   a.union(b)            -- in either
   a.intersect(b)        -- in both
   a.difference(b)       -- in a but not b
   a.is_subset(b)
```

## Присвоєння назад і копіювання

`insert` і `delete` повертають контейнер, який слід використовувати далі. Зазвичай це той самий обʼєкт, змінений на місці; коли йому потрібно вирости, це новий, більший. Отже:

```sather
   m := m.insert(k, v);     -- always
```

і після цього довіряти можна лише імені ліворуч. Інше імʼя для того самого словника, взяте до `insert`, може застаріти.

Щоб мати незалежну копію, спершу візьмімо її:

```sather
   n ::= m.copy.insert(k, v);      -- m is unchanged
```

з одним застереженням: словник, у який жодного разу нічого не вставляли, має значення **void**, і `copy` для такого словника зазнає збою. `insert`, `get`, `has_ind` і `size` усі вміють працювати зі словником зі значенням void (`#FMAP{K,T}` має значення void, і саме вставляння в нього створює словник), але `copy` не вміє.

`HMAP` і `HSET` — це версії, які завжди змінюються лише на місці. Вони швидші, коли потрібно збудувати щось велике, і поки ми вчимося, брати їх за основу не варто.

## Обхід

| Ітератор | Дає |
| --- | --- |
| `m.ind!` | кожен ключ |
| `m.target!` | кожне значення |
| `m.pair!` | кожен ключ і значення разом |
| `s.elt!` | кожне значення множини |

Ні словник, ні множина не мають порядку. Два запуски можуть обійти їх по-різному, тож ніколи не варто писати нічого, що залежить від того, що йде першим.

```sather
   loop
      #OUT + guide.ind! + "\n";
   end;
```
