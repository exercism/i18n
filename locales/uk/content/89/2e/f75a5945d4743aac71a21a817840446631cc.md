# Докладніше

У C# кортеж - це структура даних, яка впорядковує дані й містить два або більше полів будь-якого типу.

Кортеж зазвичай створюють, розмістивши два або більше виразів, розділених комами, у дужках.

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

Як і будь-який інший вираз, кортеж можна використовувати по-різному: у [присвоєннях][tuple-assignment], для ініціалізації поля чи змінної, як [повернене значення][tuple-return-values] з методу або як переданий параметр. Кортежі можна перевіряти на [рівність][tuple-equality]. Рівність кортежів повністю показано у вправі `pattern-matching-tuples`, але для повноти приклад наведено в коді нижче.

Поля витягують за допомогою синтаксису з крапкою. Типово перше поле - це `Item1`, друге - `Item2` і так далі. Нетипові назви розглянуто нижче в розділі _Іменування_.

Кортеж можна використовувати як узагальнений параметр, наприклад `IList<(bool, string)>`.

Крім того, кортежі підтримують «деконструкцію», про яку йдеться нижче, і їх можна використовувати в зіставленні з шаблоном, яке розглянуто в одній із наступних вправ.

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

Цей [вступ][tuples] показує, як визначати кортежі та користуватися ними.

## Іменування

Назви полів `Item1` тощо не роблять код читабельним. Є три способи дати полям назви: а) в оголошенні типу, б) у виразі, який його створює, в) за допомогою [ініціалізаторів проєкції кортежу][tuple-projection-initializers] (тут не показано).

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

Не намагаймося бути занадто винахідливими з механізмом іменування. Насправді це лише синтаксичний цукор. Наприклад, не можна змінити назви кортежу, коли ми присвоюємо йому значення з іншого кортежу.

## Деконструкція

Іноді зручно взяти кортеж і присвоїти його поля кільком змінним, ініціалізувавши їх за потреби.
Цей механізм називають [деконструкцією][tuple-deconstruction]. (Його також
можна застосувати до власних обʼєктів. Див. [тут][udt-deconstruction]).

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## Присвоєння полям

Полям кортежів можна присвоювати значення поодинці.
Однак з огляду на тенденцію в C# до незмінності таке
використання не набуло поширення. Кортежі часто використовують так, ніби вони незмінні,
хоча, звісно, це не так.

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## Передісторія

Кортежі, про які ми говоримо, не варто плутати з [`System.Tuple`][system-tuple],
який, імовірно, трапляється лише в застарілих кодових базах.

Ситуація трохи заплутаніша, коли йдеться про `System.ValueTuple`.
[Документація][system-value-tuple] для останнього перевантаження [`System.ValueTuple`][system-value-tuple] зазначає, що
«типи кортежів-значень надають реалізацію середовища виконання, яка підтримує кортежі в C#».
Під «типами кортежів-значень» тут мають на увазі узагальнені перевантаження `System.ValueTuple`.
Під «кортежами» вони мають на увазі те, про що йшлося в цій вправі.
Фактично вони кажуть, що `System.ValueTuple` - це деталь реалізації кортежів. Імовірно,
це здебільшого мало кого цікавить. На жаль, більша частина
документації про «кортежі», зокрема й документація самої Microsoft, рясніє посиланнями
на `System.ValueTuple`. Імовірно, такі посилання можна спокійно оминати.

## Інші застосування та обмеження

Зіставлення з шаблоном - особливо плідне застосування кортежів. Його
розглянуто в одній із наступних вправ.

Кортежі дають змогу навести ще кілька дрібних стилістичних штрихів:

- Множинне присвоєння (особливо в конструкторах), наприклад `(this.field1, this.field2) = (arg1, arg2);`
- Обмін або повторне використання значень, наприклад `(a, b) = (b, a);`
- Використання замість `struct` у масиві
- Використання як ключа словника або вмісту множини.
- Використання в LINQ. (LINQ розглядають у пізніших вправах).

Документація описує кортежі як легковаговий механізм, і саме в цьому запорука
успішного їх використання. Використання кортежу замість класу чи структури може призвести до втомливого
повторення типів його полів, а можливо, і назв. Це особливо стосується
використання його як аргументу методу або як узагальненого аргументу в колекціях.

Краще використовувати такі прийоми, як множинне присвоєння та обмін, розважливо.

Операції відношення, крім рівності та нерівності, не підтримуються.

Зауважмо, що кортежі зʼявилися в мові відносно недавно (C# 7),
тож якщо ми хочемо їх використовувати, варто переконатися, що наша кодова база
використовує [версію][language-version] 7 або новішу.
