# Вступ

## Регулярні вирази

Регулярні вирази в Elixir відповідають специфікації **PCRE** (**P**erl **C**ompatible **R**egular **E**xpressions), подібно до інших популярних мов, як-от Java, JavaScript чи Ruby.

Модуль `Regex` пропонує функції для роботи з регулярними виразами. Деякі функції модуля `String` також приймають регулярні вирази як аргументи.

~~~~exercism/note
Ця вправа припускає, що ми вже знаємо синтаксис регулярних виразів, зокрема класи символів, квантифікатори, групи та захоплення.

Якщо потрібно освіжити знання регулярних виразів, погляньмо на одне з цих джерел: [Regular-Expressions.info](https://www.regular-expressions.info), [Rex Egg](https://www.rexegg.com/), [RegexOne](https://regexone.com/), [Regular Expressions 101](https://regex101.com/), [RegExr](https://regexr.com/).
~~~~

### Сигіли

Найпоширеніший спосіб створити регулярний вираз - скористатися сигілом `~r`.

```elixir
~r/test/
```

Зауважмо, що всі сигіли в Elixir підтримують [різні види роздільників][sigils], не лише `/`.

### Зіставлення

Оператор `=~/2` можна використати, щоб виконати зіставлення з регулярним виразом, яке повертає результат типу `boolean`. Крім того, функції `match?/2` є і в модулі `Regex`, і в модулі `String`.

```elixir
"this is a test" =~ ~r/test/
# => true

String.match?("Alice has 7 apples", ~r/\d{2}/)
# => false
```

### Захоплення

Якщо простої булевої перевірки (англ. Boolean) недостатньо, скористаймося функцією `Regex.run/3`, щоб отримати список усіх захоплень (або `nil`, якщо збігу не було). Перший елемент у поверненому списку завжди є збігом для всього регулярного виразу, а наступні елементи - це групи, які збіглися.

```elixir
Regex.run(~r/(\d) apples/, "Alice has 7 apples")
# => ["7 apples", "7"]
```

### Модифікатори

Поведінку регулярного виразу можна змінити, додавши спеціальні прапорці. Коли ми створюємо регулярний вираз за допомогою сигіла, модифікатори додаються після другого роздільника.

Поширені модифікатори:
- `i` - робить зіставлення нечутливим до регістру.
- `u` - вмикає специфічні для Unicode шаблони, як-от `\p`, і змушує класи символів на кшталт `\w`, `\s` тощо також зіставлятися з символами Unicode.

```elixir
"this is a TEST" =~ ~r/test/i
# => true
```

[sigils]: https://hexdocs.pm/elixir/syntax-reference.html#sigils
