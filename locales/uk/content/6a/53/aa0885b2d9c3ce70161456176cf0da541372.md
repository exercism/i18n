# Концепції вправи «Паралельна частота літер»

Ця вправа може похвалитися широким розмаїттям можливих рішень, зокрема завдяки зовнішнім крейтам. Щоб обсяг роботи залишався керованим, цей документ містить невелику добірку можливих варіантів. Рішення на Crossbeam мають подібний набір концепцій, як тут перелічено, а Rayon потребує лише частини з них.

## Підсумок

- **Примітиви**
  - `usize`
  - `char`
  - значення з плаваючою комою
    - Ділення чисел з плаваючою комою проти ділення цілих чисел
- **Незмінність/явна змінність**
- **Рядки тексту (англ. string)**
  - тип `&str`
- **Unicode**
  - методи Unicode проти методів ASCII
- **Зрізи**
- **Кортежі**
- **Деструктурування**
- **Функції**
  - Функції вищого порядку
  - Замикання
- **Видимість**
- **Колекції даних**
  - `HashMap`
- **Тип `Option`**
- **Ітератори**
  - Ліниве обчислення
  - Споживні/неспоживні
  - Як у другому прикладі: трейт `FromIterator`
- **Цикл `for`**
- **Посилання**
  - Лічильники посилань (`Arc` у цій ситуації)
  - Розіменування
- **Час життя**
  - `'Static`
  - `move`
  - Знищення
- **Крейти**
- **Паралелізм**
  - Породження та приєднання

### Концепції, повʼязані з паралелізмом

- **Канали**
- **`Mutex` і `RwLock`**
- **Фʼючерси**
- **Підрахунок посилань**

\*<sub>Повʼязані, але тут не застосовні для розумних рішень</sub>

## Загальне

- Рядки тексту: зокрема, `str` тут завжди має значення
- Unicode: поступки в продуктивності та можливостях методів ASCII проти методів Unicode. Порівняння швидкості викривлюється, коли бенчмарк використовує методи Unicode, а рішення - методи ASCII.
- Ітератори: перебирання вхідних даних або їхніх фрагментів.
- Колекції: перебирання `HashMap` і використання `Entry`. Зазвичай дескриптори збираються у `Vec`.
- Посилання
- Числа: зокрема трейт `Add`
- Цикл `for`: через `move` не можна приєднати потоки в ітераторі.
- **Необовʼязково** Видимість: деталі реалізації залишаються непублічними
- **Необовʼязково** зрізи: `.chunks()` - часто використовуваний метод для поділу вхідних даних між робочими потоками. Як альтернативу використовують підзрізи.
- **Необовʼязково** Функції вищого порядку: колекції `HashMap` можна обʼєднати функцією вищого порядку з ітератором.
- **Необовʼязково** Типи: щоб поділити вхідні дані, ми можемо привести цілі числа до чисел з плаваючою комою і застосувати округлення
- **Необовʼязково** Крейти

## Підхід зі стандартною бібліотекою: з каналами або без них

- Паралелізм - підтема породження/приєднання потоків.
- Ітератори - підтема лінивого обчислення: породження й приєднання потоків з одним і тим самим ітератором унеможливлює паралелізм.
- Час життя - підтеми: `'static lifetime` і явна семантика `move`
- Ітератори/час життя - підтема споживних ітераторів: потоки не можна приєднати за допомогою ітератора.
- Тип `Option`: розгортання результатів потоків або каналів
- Функції: зокрема, для породження потоків потрібні функції вищого порядку. Замикання тут - один із варіантів.

## Підхід зі стандартною бібліотекою та каналами

- Паралелізм - підтема каналів.
- Кортежі: `mpsc::channel()` повертає кортеж
- Деструктурування: кортеж можна деструктурувати під час присвоєння
- Час життя: `drop()`

## Альтернативний підхід зі спільними змінними

- Підрахунок посилань: спільне використання агрегованих даних між потоками за допомогою колекції з підрахунком посилань.
- **Варте згадки**: паралелізм - підтема мʼютексів. Для цієї вправи не потрібно й не корисно, але це поширена концепція. Повʼязане: `RwLock`.

### Приклад зі стандартною бібліотекою та каналами

```rust
use std::collections::HashMap;
use std::thread;
use std::sync::mpsc;

pub fn frequency(input: &[&str], worker_count: usize) -> HashMap<char, usize> {
    let (tx, rx) = mpsc::channel();

    let _handles = input.chunks((input.len() as f64 / worker_count as f64).ceil() as usize)
        .map(|slice| slice.concat())
        .map(|slice| {
            let tx = tx.clone();
            thread::spawn(move || {
                let mut map: HashMap<char, usize> = HashMap::new();
                for chr in slice.chars().filter(|c| c.is_alphabetic()) {
                    if let Some(c) = chr.to_lowercase().next() {
                        (*map.entry(c).or_insert(0)) += 1;
                    };
                }
                tx.send(map).unwrap()
            })
        }).collect::<Vec<_>>();

    drop(tx);

    let mut result: HashMap<char, usize> = HashMap::new();
    for received in rx {
        for (c, count) in received {
            *result.entry(c).or_insert(0) += count;
        }
    }

    result
}
```

### Приклад із крейтом і `Arc`

```rust
use std::collections::HashMap;
use std::iter::FromIterator;
use std::sync::Arc;
use dashmap::DashMap;

pub fn frequency(input: &[&str], worker_count: usize) -> HashMap<char, usize> {
    let map: Arc<DashMap<char, usize>> = Arc::new(DashMap::new());

    let handles = input
        .chunks((input.len() as f64 / worker_count as f64).ceil() as usize)
        .map(|slice| slice.concat())
        .map(|slice| {
            let map = map.clone();
            std::thread::spawn(move || {
                for c in slice.chars().filter(|c|c.is_alphabetic())
                  .flat_map(|c| c.to_lowercase().next()) {
                    *map.entry(c).or_insert(0) += 1;
                }
            })
        }).collect::<Vec<_>>();

    for h in handles {
        h.join().unwrap();
    }

    map.iter().map(|x| (*x.key(), *x.value())).collect()
}
```
