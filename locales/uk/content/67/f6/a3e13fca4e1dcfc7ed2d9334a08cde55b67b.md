# Вступ

## Документація

Документація в Elixir є повноправною частиною мови.

Для документування коду зазвичай використовують два атрибути модуля: `@moduledoc` для документування модуля та `@doc` для документування функції, що йде після атрибута. Атрибут `@moduledoc` зазвичай стоїть у першому рядку модуля, а атрибут `@doc` зазвичай стоїть безпосередньо перед визначенням функції або перед специфікацією типів цієї функції, якщо вона є. Документацію зазвичай записують багаторядковим рядком тексту (англ. string) за допомогою синтаксису heredoc.

Документацію в Elixir пишуть мовою [**Markdown**][markdown].

```elixir
defmodule String do
  @moduledoc """
  Strings in Elixir are UTF-8 encoded binaries.
  """

  @doc """
  Converts all characters in the given string to uppercase according to `mode`.

  ## Examples

      iex> String.upcase("abcd")
      "ABCD"

      iex> String.upcase("olá")
      "OLÁ"
  """
  def upcase(string, mode \\ :default)
end
```

## Специфікації типів

Elixir належить до динамічно типізованих мов, а це означає, що вона не перевіряє типи під час компіляції. Утім, специфікації типів можна використовувати як різновид документації.

Специфікацію типу можна додати до функції за допомогою атрибута модуля `@spec` безпосередньо перед визначенням функції. Після `@spec` записують назву функції та список типів усіх її аргументів у дужках, розділених комами. Тип поверненого значення відокремлюють від аргументів функції подвійною двокрапкою `::`.

```elixir
@spec longer_than?(String.t(), non_neg_integer()) :: boolean()
def longer_than?(string, length), do: String.length(string) > length
```

### Типи

Найпоширеніші типи:

- булеві значення (англ. Boolean): `boolean()`
- рядки тексту: `String.t()`
- числа: `integer()`, `non_neg_integer()`, `pos_integer()`, `float()`
- масиви: `list()`
- значення будь-якого типу: `any()`

Деякі типи можна також параметризувати: наприклад, `list(integer)` позначає масив цілих чисел.

Як типи можна використовувати й літеральні значення.

Обʼєднання типів можна записати за допомогою вертикальної риски `|`. Наприклад, `integer() | :error` означає або ціле число, або літерал атома `:error`.

Повний список усіх типів можна знайти в [розділі «Typespecs» в офіційній документації][types].

### Іменування аргументів

Аргументи у специфікації типу можна також назвати, що допомагає розрізняти кілька аргументів одного типу. Назва аргументу, після якої йде подвійна двокрапка, ставиться перед типом аргументу.

```elixir
@spec to_hex({hue :: integer, saturation :: integer, lightness :: integer}) :: String.t()
```

### Власні типи

Специфікації типів не обмежуються лише вбудованими типами. Власні типи можна визначати за допомогою атрибута модуля `@type`. Визначення власного типу починається з назви типу, далі йде подвійна двокрапка, а потім сам тип.

```elixir
@type color :: {hue :: integer, saturation :: integer, lightness :: integer}

@spec to_hex(color()) :: String.t()
```

Власний тип можна використовувати в тому самому модулі, де його визначено, або в іншому модулі.
