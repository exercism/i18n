# Debug

YS має вбудовану функцію `DBG`, яка може стати в пригоді під час налагодження коду рішення.
Вона приймає будь-яку кількість аргументів і виводить їх у консоль через stderr.
Вона повертає останній аргумент, тож його можна використати безпосередньо в коді.


Можна скористатися оператором `.>`, який скорочує запис `.DBG()`.

Ось приклад файлу з кодом:

```yaml
# file: program.ys

!YS-v0

defn do-it(nums):
  x =: 5

  DBG: -'my vars' x nums

  nums: .map(\(_ * x)).>
        .reverse().>
        .map(str).>
        .join(' - ')

say: do-it(3 .. 5)
```

Коли ми запустимо цей код командою `ys`, побачимо такий вивід:

```txt
>>>
"my vars"
5
(3 4 5)
<<<
>>>(15 20 25)<<<
>>>(25 20 15)<<<
>>>("25" "20" "15")<<<
25 - 20 - 15
```


## Компіляція

Ще один поширений спосіб розібратися з проблемою - подивитися на код Clojure, у який компілюється наш код на YS.

Це можна зробити, запустивши інтерпретатор командного рядка `ys` з прапорцем `-c`.

Ось який вигляд має наведений вище файл `program.ys` після компіляції:

```clojure
$ ys -c program.ys
(defn do-it [nums]
 (let [x 5]
  (DBG "my vars" x nums)
  (join
   (DBG
    (+map
     (DBG (reverse (DBG (+map nums (fn [& [_1]] (mul+ _1 x))))))
     str))
   " - ")))
(say (do-it (rng 3 5)))
```

Тут добре видно, як оператор `.>` скомпілювався у виклик функції `DBG`.
