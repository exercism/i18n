# Для супровідників

## Генерування тестів: `bin/generate_tests.py`

Тестові файли генеруються з канонічних даних у
[exercism/problem-specifications](https://github.com/exercism/problem-specifications)
за допомогою шаблону Jinja, який зберігається в кожній вправі за шляхом `.meta/template.j2`.

```bash
bin/generate_tests.py bob            # regenerate one exercise
bin/generate_tests.py                # regenerate every exercise that has a template
bin/generate_tests.py --no-pull bob  # skip `git pull` of problem-specifications
```

Скрипт читає problem-specifications із кешу configlet
(`~/.cache/exercism/configlet/problem-specifications`, який заповнює `bin/configlet sync`),
або з батьківського каталогу з назвою `problem-specifications`.
Генеруються лише випадки, внесені до `.meta/tests.toml`.

Літерали рядків тексту (англ. string) у Fortran не можуть містити escape-послідовності, як-от `\n` і `\t`.
Фільтр шаблону `escape_quote_whitespace` переписує їх як
`" // NEWLINE // "`, `" // TAB // "` і `" // CARRIAGE_RETURN // "`,
тож шаблон повинен оголошувати ці константи (див. `exercises/practice/bob/.meta/template.j2`).

### Передумови

- Робочі CMake і компілятор Fortran
- Python 3.12+ з `jinja2`
- git

### Робочий процес додавання нової вправи

Розгляньмо приклад із `bob`:

- Створити нову гілку, напр. `git checkout -b exercise-bob`
- Запустити `bin/add-exercise bob` (потрібні `jq` і `curl`). Це:
  - завантажує configlet і запускає `configlet create`, що додає вправу до `config.json` та синхронізує її документацію, метадані й `tests.toml` з problem-specifications
  - сортує `config.json` за допомогою `bin/reorder-exercises`
  - копіює `exercises/shared/CMakeLists.txt` до каталогу вправи
  - записує заготівку рішення, заготівку `.meta/example.f90` і стартовий `.meta/template.j2` (з `exercises/shared/template.j2`)

  Скрипт запитує імʼя користувача GitHub, якщо не передати `-a <username>`, і встановлює складність 1, якщо не передати `-d <difficulty>`.

- Відредагувати `.meta/template.j2`, щоб кожен випадок викликав потрібну функцію з потрібними вхідними даними, а потім згенерувати тести:

  ```bash
  bin/generate_tests.py bob
  ```

- Написати робоче рішення в `.meta/example.f90`. Замінити файл учня (напр. `bob.f90`) на скелет функцій або підпрограм, які викликають тести, щоб учневі було легше почати
- Переконатися, що всі тести проходять, виконавши повне збирання з кореня репозиторію:

  ```bash
  mkdir -p build && cd build
  cmake ..
  cmake --build .
  ctest -V -R bob
  ```

- Запустити `bin/reorder-exercises` і `bin/configlet lint`
- Якщо все проходить, відкрити pull request зі своїми змінами

### Зміна `CMakeLists.txt`

Коли ми змінюємо файл cmake, потрібно оновити головну копію в `exercises/shared/` і за допомогою `bin/update-cmake-files` скопіювати її до всіх каталогів вправ.
