# Вступ

У Gleam поширено писати й використовувати функції вищого порядку, тобто функції, які приймають інші функції як аргументи. Іноді, коли ми використовуємо багато функцій вищого порядку одночасно, код стає важко читати через численні рівні відступів.

Наприклад, ось функція, яка викликає кілька функцій, що повертають `Result(Int, Nil)`, і підсумовує значення, якщо всі чотири успішні.

```gleam
import gleam/result

pub fn main() -> Result(Int, Nil) {
  result.try(function1(), fn(a) {
    result.try(function2(), fn(b) {
      result.try(function3(), fn(c) {
        result.try(function4(), fn(d) {
          Ok(a + b + c + d)
        })
      })
    })
  })
}
```

Вирази `use` у Gleam дають змогу записати цей код без відступів, що часто робить його легшим для читання.

```gleam
import gleam/result

pub fn main() -> Result(Int, Nil) {
  use a <- result.try(function1())
  use b <- result.try(function2())
  use c <- result.try(function3())
  use d <- result.try(function4())
  Ok(a + b + c + d)
}
```

Вираз `use` збирає всі наступні інструкції в блоці й передає їх як функцію зворотного виклику останнім аргументом у виклик функції. Змінні між ключовим словом `use` і символом `<-` задають назви аргументів, які буде передано у функцію зворотного виклику.

```gleam
// This use expression
use a <- function(1, 2)
io.println("Hello!")
a

// Is equivalent to this normal function call
function(1, 2, fn(a) {
  io.println("Hello!")
  a
})
```

Функція зворотного виклику може приймати будь-яку кількість аргументів або жодного.

```gleam
use a, b, c, d <- call_4_function()

use <- call_0_function()
```

Щоб створити функцію, яку можна викликати за допомогою виразу `use`, немає жодних особливих вимог, окрім того, що вона приймає функцію зворотного виклику останнім аргументом.

```gleam
pub fn call_twice(function: fn() -> t) -> #(t, t) {
  let first = function()
  let second = function()
  #(first, second)
}
```

Вирази `use` у Gleam дають дуже потужну можливість, яку можна застосувати до багатьох задач, але за надмірного використання вони можуть робити код важким для читання. Зазвичай краще використовувати звичайний синтаксис виклику функцій і вдаватися до виразів `use` лише тоді, коли вони роблять код легшим для читання.
