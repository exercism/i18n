# Вступ

## Переліки

Досі ми переважно мали справу з числами та рядками тексту (англ. string).
Щоб моделювати реальний світ, нам може знадобитися обмежена кількість значень, які може набувати змінна.
Можливо, нам потрібен окремий тип із кількома різними значеннями, що мають різні назви.
Наприклад, на фабриці скейтбордів матеріал деки може бути лише з клена, бамбука або пластику.

Ми могли б використати цілі числа, щоб закодувати ці значення, але довелося б використати зайвий code, щоб перевірити, чи не надходить із системи неприпустиме значення для матеріалу.
Значення цих [_магічних чисел_][magic numbers] важко простежити в source code, і їх легко переплутати.
`enumerations` можна використовувати, щоб заохотити виразний code і обмежити ненавмисні помилки порівняння.

## Приклад використання

Конкретний термін для такого переліку - `scoped enumeration`.
Фрагмент нижче показує, як написати `DeckMaterial` `enumeration`.
Зауважмо ключове слово `enum class` і `;` в кінці визначення:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
Тепер погляньмо на функцію ціноутворення в крамниці скейтбордів і звернімо увагу на оператор розвʼязання області видимості (`::`), який уточнює `enumerator` з `enumeration`:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## Область видимості

Уявімо, що у нас є другий `enumeration` для матеріалу коліс:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
Хоча колеса й дека можуть обидва бути з _plastic_, їх не можна переплутати.
Це різні _типи_: `DeckMaterial` plastic і `WheelMaterial` plastic.
Кожен `enumeration` матиме свої `enumerators` у власній області видимості, у власному `namespace`.
Саме тому їх називають `scoped enumerations`.

## Необмежені переліки
Можна подумати, що з назвою `scoped` існують також `unscoped` переліки, і це справді так.
`Unscoped enumerations` стають дедалі менш популярними, бо всі вони поділяють той самий глобальний namespace.
Через це не можна мати два `unscoped enumerations` з однаковими `enumerators`, як _plastic_ у прикладі вище.

Також `unscoped enumerations` неявно перетворюються на цілі числа.
Погляньмо на приклад нижче, щоб побачити несподіваний результат:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

Якщо ми хочемо перетворити `scoped enumerations` на цілі числа, можна використати `static_cast<int>`.
