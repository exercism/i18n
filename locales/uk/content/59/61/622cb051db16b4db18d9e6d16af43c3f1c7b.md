# Докладніше

Ми вже бачили в попередніх концепціях, що типи в Julia утворюють ієрархію, на вершині якої стоїть `Any`.

Абстрактні типи, як-от `Number`, мають підтипи, але створити їхній примірник неможливо.
Присвоєння змінній абстрактного типу _обмежує_ її значення будь-яким підтипом цього абстрактного типу.
Наприклад:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Це дає нам один вид гнучкості в обмеженні того, які вхідні дані допустимі.

Однак припустімо, що ми хочемо, щоб змінна приймала як цілі числа, так і рядки тексту (англ. string)?
Ці типи не належать до однієї гілки ієрархії.

Ми могли б задати тип [`Any`][any] або залишити його як типове значення, але тоді ми повністю втрачаємо контроль над дозволеними типами.

Кращий підхід дає синтаксис [`Union{ }`][union], у якому всередині фігурних дужок перелічено два або більше типів.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Інший приклад застосовує те саме обʼєднання типів у сигнатурі функції:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

Тут ми дали типові імʼя, що може бути зручним скороченням, але не є строго необхідним.
Функція `g(z::Union{Integer, String}) = z^3` поводиться так само.

Про сигнатури функцій ще буде багато сказано в концепції «Множинна диспетчеризація».

## Обʼєднання з nothing

У кількох інших мовах є типи, які можуть містити значення, а можуть і не містити, з такими назвами, як `Option`, `Nullable` чи `Maybe`.

У Julia немає спеціального синтаксису для цього, але обʼєднання типів є узагальненням цієї самої ідеї.

Ми бачили в концепції [`Nothingness`][nothingness], що в Julia є різні способи подати відсутні значення, зокрема [`nothing`][nothing] та [`missing`][missing].
Будь-яке з них можна включити до обʼєднання типів.

Наприклад, визначаючи якийсь [звʼязаний список][linked], нам потрібен спосіб завершити список, якщо більше немає вузлів.
`Nothing` - це тип із єдиним значенням `nothing`, і це визначення `Node` дає змогу позначити кінець ланцюга:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

Так само `missing` можна використовувати як заповнювач для відсутніх значень, особливо в колекціях, як-от вектори.
Наведений нижче приклад дуже надуманий, але відсутні значення часто трапляються в реальних наборах даних.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
