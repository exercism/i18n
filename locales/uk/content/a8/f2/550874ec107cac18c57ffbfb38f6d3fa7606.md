## Smalltalk і рядки тексту

Що стосується рядків тексту, є кілька очевидних дрібниць: подвійні лапки для коментарів, одинарні лапки для рядків тексту й спеціальний синтаксис для символів (наприклад, $x для символу «x»), які можуть збити з пантелику під час першого читання, адже ці конвенції відрізняються від тих, які використовують в інших мовах.

Є також поняття symbol. Це рядок тексту, унікальний у межах усієї памʼяті; тобто коли його створюють (зазвичай під час компіляції), виконується пошук у памʼяті, щоб зʼясувати, чи вже існує такий самий, і використовується лише оригінал. Причина не лише в економії памʼяті, а й у значному прискоренні порівняння symbol.

```smalltalk
"this is a comment"
'this is a string'
#'this is a symbol'
#thisIsASymbolToo
```

У програмах Smalltalk також дуже мало ком, бо вони не відіграють жодної синтаксичної ролі.
Саме тому літерали масивів, наприклад, обходяться без ком; наприклад,
`#(1 2 3 4 5)`
Однак кома і сама є оператором, і ми помітимо це, коли зʼєднуємо два рядки тексту; наприклад,
`'string1', 'string2'`

Нарешті, варто знати, що рядки тексту й символи є різними класами. Рядок тексту є колекцією символів. Це може заскочити нас зненацька, коли ми перебираємо рядки тексту, бо можемо передати символи методу, який приймає рядки тексту. Розгляньмо...
```smalltalk
(('hello' at: 2) = $e) inspect.
(('hello' at: 2) = 'e') inspect.
```

## Smalltalk і потоки
Потоки стають у пригоді для послідовного читання й запису.  Вони роблять код чистішим, позбавляючи потреби збільшувати індекс на одиницю.
Потоки працюють з будь-якою колекцією.
```smalltalk
stream := WriteStream on: String new.
stream nextPut: $h ; nextPutAll: 'ell' ; nextPut: $o.
stream contents inspect
```
