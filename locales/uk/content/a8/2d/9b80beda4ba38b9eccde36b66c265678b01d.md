# Вступ

## Інтерфейс як набір методів

У найпростішій формі **інтерфейсний тип** - це набір сигнатур методів.
Ось приклад визначення інтерфейсу, який містить два методи `Add` і `Value`:

```go
type Counter interface {
    Add(increment int)
    Value() int
}
```

Імена параметрів, як-от `increment`, можна опустити у визначенні інтерфейсу, але вони часто підвищують читабельність.

Назви інтерфейсів у Go не містять слова `Interface` чи `I`.
Натомість вони часто закінчуються на `er`, наприклад `Reader`, `Stringer`.

## Реалізація інтерфейсу

Будь-який тип, що визначає методи інтерфейсу, автоматично й неявно «реалізує» цей інтерфейс.
У Go немає ключового слова `implements`.

Наведений нижче тип реалізує інтерфейс `Counter`, який ми бачили раніше.

```go
type Stats struct {
    value int
    // ...
}

func (s Stats) Add(v int) {
    s.value += v
}

func (s Stats) Value() int {
    return s.value
}

func (s Stats) SomeOtherMethod() {
    // The type can have additional methods not mentioned in the interface.
}
```

Для реалізації інтерфейсу не має значення, чи метод має отримувач-значення, чи отримувач-вказівник.
(Якщо щодо них є сумніви, повернімося до [концепції методів][concept-methods].)

> Значення інтерфейсного типу може зберігати будь-яке значення, яке реалізує ці методи. ((Тур Go: Інтерфейси)[go-tour-interfaces])

Це означає, що `Stats` тепер можна використовувати скрізь, де потрібен інтерфейс `Counter`.

```go
func SetUpAnalytics(counter Counter) {
    // ...
}

stats := Stats{}
SetUpAnalytics(stats)
// works because Stats implements Counter
```

Оскільки інтерфейси реалізуються неявно, тип може легко реалізувати кілька інтерфейсів.
Для цього йому достатньо визначити всі потрібні методи.

## Порожній інтерфейс

У Go є один дуже особливий інтерфейсний тип - **порожній інтерфейс**, який не містить жодного методу.
Порожній інтерфейс записують так: `interface{}`.
У Go 1.18 і новіших версіях також можна використовувати `any`.
Його було визначено як псевдонім.

Оскільки порожній інтерфейс не має методів, кожен тип реалізує його неявно.
Це зручно для визначення функції, яка може приймати будь-яке значення.
У такому разі параметр функції використовує порожній інтерфейсний тип.
