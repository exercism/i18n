# Докладніше

Ресурси, які тримають стан операційної системи (файлові дескриптори, сокети, блокування),
потребують *гарантованого* очищення, навіть коли виняток розкручує стек. Словник
[`destructors`][destructors] у Factor дає для цього невеликий фреймворк, і більшість
вбудованих ресурсів (`<file-reader>`, `<file-writer>`, сокети, …) уже працюють із ним.

## Клас і узагальнене слово

Клас долучається до цього фреймворку, успадкувавши `disposable` і реалізувавши
`dispose*`:

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )` виділяє кортеж *і* реєструє його в поточній області
деструкторів, тож виняток між виділенням і наступною безпечною точкою не призведе до
витоку ресурсу. Фреймворк гарантує, що `dispose*` виконується **щонайбільше один раз** для
кожного обʼєкта: повторні виклики `dispose` нічого не роблять.

## Зовнішній код використовує `dispose`

| слово             | дія                                           |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )`, звільняє ресурс; безпечно викликати двічі |
| `with-disposal`   | `( disposable quot -- )`, дає область для одного ресурсу |
| `with-destructors`| `( quot -- )`, відкриває область із реєстром  |
| `&dispose`        | `( obj -- obj )`, звільняє за нормального *або* аварійного виходу |
| `|dispose`        | `( obj -- obj )`, звільняє лише за аварійного виходу з області |

`with-disposal` працює з одним ресурсом. Якщо ресурсів більше ніж один, відкриваємо
область `with-destructors` і реєструємо кожне отримання через `&dispose` (який ми завжди
хочемо звільнити) або `|dispose` (звільняємо лише за помилки, а за успішного виходу
залишаємо його).

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup` - примітив у чистому вигляді

Коли потрібен одноразовий try/finally без реєстру, беремо нижчорівневе слово
[`cleanup`][cleanup] (із `continuations`):

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` значно потужніший (реєстр може рости під час виконання), але якщо пара
«захоплення/звільнення» фіксована й локальна, природно підходить саме `cleanup`.

[destructors]: https://docs.factorcode.org/content/vocab-destructors.html
[cleanup]: https://docs.factorcode.org/content/word-cleanup%2Ccontinuations.html
