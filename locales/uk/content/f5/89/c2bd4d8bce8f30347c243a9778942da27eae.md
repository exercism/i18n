# Вступ

`Complex numbers` зовсім не складні.
Їм просто потрібна назва, яка не так лякає.

Вони настільки корисні, особливо в інженерії та науці, що R включає [комплексні числа][web-complex] як стандартні 
[атомарні типи][ref-atomic] поряд з integer, double, logical, character та raw.

## Основи

`complex`-число в R - це одне значення.
У роботі ж його можна уявляти як пару чисел.
Їх називають «дійсною» та «уявною» частинами, і на це є прикрі історичні причини.
І знову ж таки, краще зосередитися на прихованій простоті, а не на дивних назвах.

Щоб створити комплексне число з двох дійсних чисел, достатньо додати суфікс `i` до уявної частини.

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

Щоб створити комплексне число з дійсних змінних, наведений вище синтаксис не працюватиме.
Запис `r + imi` заплутує парсер, і він починає вважати `imi` назвою (неіснуючої) змінної.

Можна або помножити уявну частину на `1i`, або скористатися функцією [`complex()`][ref-complex]:

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

Можна замислитися, чому `i`, а не `j`?

Більшість інженерів віддають перевагу `j`.
Більшість науковців і математиків віддають перевагу математичному позначенню `i` для _уявного_, але це позначення конфліктує
з використанням `i` на позначення _струму_ в електротехніці.

R обрав `i`, Python обрав `j`, а Julia оминула суперечку, обравши `im`.
Будьмо уважними, перемикаючись між мовами програмування зі [STEM][wiki-STEM].

Щоб отримати частини комплексного числа окремо:

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

Кожна з частин може дорівнювати нулю, і тоді математики можуть казати, що число «цілком дійсне» або «цілком уявне».
Однак у R це все одно комплексне число.

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

Можливо, доводилося чути, що «`i` (або `j`) - це квадратний корінь із -1».

Поки що це означає лише те, що уявна частина _за визначенням_ задовольняє таку рівність:

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

Це проста ідея, але вона має цікаві наслідки.

## Арифметика

Більшість [`operators`][ref-operators], які використовуються з числами з плаваючою комою та цілими числами, працюють і з комплексними числами:

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

Пояснення правил множення й ділення комплексних чисел виходить за межі цієї концепції (_і навряд чи доведеться часто виконувати ці операції «вручну»_).

Будь-який [математичний][web-math-complex] чи [електротехнічний][web-engineering-complex] вступ до комплексних чисел розкриває цю тему, якщо захочеться заглибитися в неї.

Крім того, на Exercism є практична вправа [`Complex Numbers`][exercise-complex-numbers], де можна реалізувати клас комплексного числа з цими операціями з найосновніших засад.

Ділення цілих чисел загалом ___не___ можливе для комплексних чисел, тому оператори `%/%` і `%%` не будуть працювати 
з типом комплексного числа.

## Функції

Більшість математичних функцій працюють із комплексними вхідними даними.

Однак подавати дійсні вхідні дані й сподіватися на комплексний результат зазвичай не спрацює.

```r
sqrt(z1)
#> [1] 1.414214+0.707107i

sqrt(-1)  # fails!
#> Warning in sqrt(-1) : NaNs produced
#> [1] NaN

sqrt(-1 + 0i)  # succeeds with complex input
#> [1] 0+1i

sin(z1)
#> [1] 3.752771+0.256554i
```

Є кілька функцій, крім `Re()` та `Im()`, які мають особливе значення для комплексних чисел.

- `Conj()` просто змінює знак уявної частини комплексного числа (_з + на - або навпаки_).
  - Через те, як працює множення комплексних чисел, це корисніше, ніж може здатися.
- `abs(<complex number>)` гарантовано повертає дійсне число без уявної частини (його «величину»), а `Mod(<complex number>)` - синонім.
- `Arg(<complex number>)` повертає фазовий кут у радіанах.

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
