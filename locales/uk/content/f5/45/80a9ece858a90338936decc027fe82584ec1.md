# Узагальнені класи

```sather
class LOST_BOX{T} is
   attr item : T;
   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;
end;
```

## Що це за параметр

`T` позначає тип, який підставляють у місці використання. Sather будує окремий клас для кожної комбінації, яку фактично використано, коли програму скомпільовано. Отже:

- `LOST_BOX{STR}` і `LOST_BOX{INT}` - це неповʼязані між собою типи;
- немає жодної перевірки під час виконання, жодного упакування і жодного перетворення;
- помилка в класі проявляється для кожного типу, з яким його використано.

Це той самий підхід, що в шаблонах C++ чи в узагальненнях Rust, і не такий, як в узагальненнях Java, де тип стирається, а все насправді є обʼєктом.

## Обмежені параметри

`T` без обмежень можна присвоїти, передати й повернути - і більше нічого, бо більше про нього нічого не відомо. Щоб викликати на ньому підпрограми, треба вказати, чому він має відповідати:

```sather
class LOST_BOX{T < $STR} is
   describe : STR is return "a box holding " + item.str; end;
end;
```

`T < $STR` вимагає, щоб `T` відповідав `$STR`, а натомість дозволяє викликати `item.str`. Усе, чого не може `T` без обмежень, дозволяє саме обмеження.

Без обмеження `item.str` не скомпілюється, і в повідомленні буде названо рядок усередині узагальненого класу, а не той рядок, де його використано.

## Узагальнені підпрограми?

Їх немає. Параметри приймають лише класи. Підпрограма, якій потрібно працювати з кількома типами, або міститься в узагальненому класі, або приймає абстрактний тип, як-от `$STR`.

## Як обирати між ними

| | узагальнений клас | абстрактний клас |
| --- | --- | --- |
| вирішується | під час компіляції | під час виконання |
| містить | один тип на кожен створений екземпляр | будь-який відповідний тип |
| ціна | немає | диспетчеризація |

`ARRAY{$ACT}` поєднує обидва підходи: він узагальнений за типом елемента й абстрактний щодо того, чим цей елемент може бути.

До узагальненого класу варто звертатися, коли тип однаковий усюди і користувач класу це знає. До абстрактного класу варто звертатися, коли в одній колекції мають співіснувати кілька типів.
