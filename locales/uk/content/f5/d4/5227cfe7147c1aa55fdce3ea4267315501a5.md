# Тести

Кожна вправа містить файл із тестами.
Запустімо тести за допомогою програми `bats`.

```bash
bats test-hello-world.bats
```

`bats` потрібно встановити.
Дивіться сторінку [Тестування на треку Bash][bash], щоб дізнатися, як встановити `bats` для своєї системи.

### bats реалізовано на bash

Файл bats є скриптом bash зі спеціальними функціями, які розпізнає команда `bats`.
Ми побачимо тести такого вигляду:

```sh
jq -f some-exercise.jq <<< "{some,json,here}"
```

Цей синтаксис `<<<` називається [Here String][here-string] у bash.
Він надсилає рядок тексту (англ. string), що стоїть праворуч, до стандартного вводу програми, що стоїть ліворуч.
Це ([приблизно][so]) те саме, що й

```sh
echo "{some,json,here}" | jq -f some-exercise.jq
```

## Довідка щодо функцій assert

Тести використовують функції з бібліотеки [bats-assert][bats-assert].
Довідку про різні функції `assert*` можна знайти там.

## Пропущені тести

Вправа вважається розвʼязаною, коли проходять усі її тести.
Типово під час запуску тестів виконується лише один тест (перший).
Це зроблено навмисно, щоб ми могли зосередитися лише на проходженні цього одного тесту.
Коли він пройде, ми зможемо увімкнути наступний тест, закоментувавши або видаливши

    [[ $BATS_RUN_SKIPPED == true ]] || skip

анотації, що стоять перед іншими тестами.

## Перевизначення пропусків

Щоб запустити всі тести, зокрема ті, що мають анотації `skip`, можна виконати:

```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Буває зручно використати функцію-обгортку, щоб менше друкувати: у `bash` можна зробити так:

```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```

Тоді запускати тести можна просто так:

```bash
bats
```

## Налагодження в `jq`

`jq` має зручний фільтр [`debug`][debug].
Використовуймо його під час розробки рішень вправ, щоб переглядати дані, які зараз перебувають у конвеєрі jq.
Докладніше дивіться в [документі про налагодження][debugging].
