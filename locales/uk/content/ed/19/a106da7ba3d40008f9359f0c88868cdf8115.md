# Докладніше

Коли ми виконуємо зіставлення зі зразком для значення в Gleam, треба подбати, щоб зразки охоплювали кожне можливе значення типу, інакше код не скомпілюється.

Цю функцію буде відхилено, бо вона не обробила випадок, коли масив порожній:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Зазвичай у програмах Gleam ми хочемо обробляти кожен можливий випадок, але в деяких програмах, як-от прототипах чи швидких скриптах, може знадобитися зосередитися лише на щасливому шляху й не писати код для решти випадків. Саме тут у пригоді стає `let assert` із Gleam.

Із let-твердженнями зразок може збігатися лише з частиною можливих значень типу, а якщо зразок не збігається зі значенням, програма аварійно завершиться. За допомогою `let assert` ми можемо написати наведену вище функцію так:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Бібліотеки Gleam ніколи не повинні використовувати let-твердження, бо через них програма може аварійно завершитися. Натомість їм слід використовувати тип `Result` і дозволити розробнику застосунку вирішити, як обробляти помилки.
