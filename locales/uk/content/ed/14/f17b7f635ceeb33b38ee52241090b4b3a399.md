# Докладніше

Щоб зрозуміти [`Box`][box], варто розібратися, що таке [стек і купа][stack and heap].

Стек - це ділянка памʼяті, яка працює як буфер за принципом «останній прийшов, перший вийшов» (LIFO). Покласти дані на стек дуже швидко, і так само швидко зняти їх звідти.
Ці дані можуть містити змінні або адреси функцій, але на час компіляції вони повинні мати відомий, фіксований розмір.

Якщо на час компіляції розмір даних невідомий або може змінитися, тоді під них потрібно виділити памʼять у купі. Процес виділення має знайти в купі достатньо місця,
щоб зберегти дані, записати ці дані в купу й покласти адресу цих даних на стек, а все це займає
значно більше часу, ніж просте покладання даних на стек. Отримання даних із купи трохи повільніше, бо треба пройти за адресою на стеку
й за нею дістатися до місця розташування даних у купі.

`Box` - це розумний вказівник, який виділяє памʼять під дані в купі. Адреса зберігається на стеку й указує на дані в купі. Одна з [причин][reasons] використовувати `Box` -
покласти дані в купу, коли в нас є тип, розмір якого неможливо знати на час компіляції, і ми хочемо використати значення цього типу в контексті, який вимагає
точного розміру. Один практичний випадок цього - коли в нас є кілька структур, які ми хочемо обробляти однаково через трейт, який вони всі реалізують,
як у прикладі нижче.

Скажімо, у нас є дві структури. Кожна структура описує щось, що може дратувати. Ми можемо зробити так, щоб кожна структура реалізувала трейт Annoyance, ось так:

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

Тепер скажімо, що нам потрібна функція, яка поверне нам Annoyance залежно від часу доби, переданого їй. Спершу можемо спробувати ось це й виявимо, що воно не компілюється

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

Компілятор, з усією своєю любʼязністю, каже нам точно, що робити: повернути трейт-обʼєкт, загорнутий у `Box`. Якщо ми не знаємо, що таке трейт-обʼєкт,
найпростіше описати його так: це спосіб повернути конкретний обʼєкт через [динамічну диспетчеризацію][dynamic dispatch] з функції, яка могла б повернути будь-який обʼєкт,
що реалізує заданий трейт. Оскільки нам потрібна динамічна диспетчеризація, можемо спробувати просто поставити `dyn` перед назвою трейту й подивитися, чи це спрацює.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

Одна з помилок полягає в тому, що розмір `dyn Annoyance` неможливо визначити на час компіляції. Це тому, що `annoy_me` не знає, який саме трейт-обʼєкт
він поверне, ще до того, як його викличуть. Структури, що реалізують Annoyance, можуть мати різні поля й бути різного розміру. І нам нагадують, що
одне із застосувань `Box` - це тип, розмір якого неможливо знати на час компіляції. Тож тепер спробуємо повертати значення, загорнуте в `Box`, і загортаємо в `Box` значення, які повертає
вираз match, ось так:

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

Сигнатура `Box` - це `Box<T>`, де `T` позначає конкретний тип, який потрібно загорнути; він стоїть усередині кутових дужок, як у `Box<dyn Annoyance>` вище.

Скористатися загорнутим у `Box` трейт-обʼєктом можна ось так:

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

що виводить

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

Оскільки `my_annoyance` має тип `Box<dyn Annoyance>`, його потрібно розіменувати з `Box` за допомогою оператора розіменування `*`. Потім на нього посилаються як на
`dyn Annoyance`, щоб функція `be_annoying` могла його позичити.

Інший спосіб зробити це - прибрати вимогу, щоб параметр мав відомий розмір. У такому разі компіляція створила б окрему функцію
для кожного варіанта Annoyance, щоб застосувати до нього статичну диспетчеризацію (цей процес називається [мономорфізацією][monomorphization]), ось так:

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

Ще один спосіб - зробити так, щоб функція `be_annoying` приймала `Box<dyn Annoyance>` і застосовувала [приведення через розіменування][deref coercion], щоб не
розіменовувати `Box` вручну. Це передало б право володіння трейт-обʼєктом Annoyance функції `be_annoying`. Він вийшов би з області
видимості в кінці функції й більше не був би доступним.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
