# Тести

Кожна вправа містить файл з тестами.
Запустіть тести за допомогою програми `bats`.
```bash
bats test-hello-world.bats
```

`bats` потрібно встановити.
Дивіться сторінку [Тестування на треку Bash][bash], щоб дізнатися, як встановити `bats` у своїй системі.

### bats написано на bash

Файл bats - це скрипт на bash із кількома спеціальними функціями, які розпізнає команда `bats`.
Деякі тести мають такий вигляд:
```sh
gawk -f some-exercise.awk <<< "some,input,here"
```
Цей синтаксис `<<<` - це [Here String][here-string] у bash.
Він передає рядок тексту (англ. string) із правого боку до стандартного вводу програми з лівого боку.
Це ([приблизно][so]) те саме, що й
```sh
echo "some,input,here" | gawk -f some-exercise.awk
```

Довідку про різні функції `assert*` можна знайти там.

## Пропущені тести

Розвʼязати вправу означає домогтися, щоб усі її тести проходили.
Коли ми запускаємо тести, типово виконується лише один тест (перший).
Це зроблено навмисно: так ми можемо зосередитися лише на тому, щоб цей один тест пройшов.
Щойно він пройде, можна увімкнути наступний тест, закоментувавши або видаливши

    [[ $BATS_RUN_SKIPPED == true ]] || skip

анотації, які стоять перед іншими тестами.

## Як обійти пропуски

Щоб запустити всі тести, зокрема ті, що мають анотації `skip`, виконайте таку команду:
```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Буває зручно скористатися функцією-обгорткою, щоб менше друкувати: у `bash` можна зробити так:
```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```
Тоді запускати тести можна просто командою:
```bash
bats
```

## Виведення для налагодження

```exercism/caution
Це працює локально з `bats`, але **не** в онлайн-редакторі Exercism.
```

Під час запуску тестів `bats` перехоплює і stdout, і stderr, щоб порівняти їх з очікуваними вихідними даними.
Якщо надрукувати повідомлення для налагодження у stdout або stderr, вони потраплять до перехоплених вихідних даних і можуть спричинити помилку тесту.

Щоб виводити інформацію для налагодження й не впливати на результати тестів, `bats` надає для цього дескриптор файлу **3**.
Усе, що виведено у файл `/dev/fd/3`, буде показано під час запуску тестів, але не потрапить до перехоплених вихідних даних, які використовуються для тверджень.

Приклад:

```awk
BEGIN {
    # This debug message will not interfere with test output comparison
    print "a debug message" > "/dev/fd/3"

    # Normal program output (this is what your tests will see and compare)
    print "Hello, World!"
}
```

Приклад запуску:

```none
$ bats test-hello-world.bats
test-hello-world.bats
 ✓ Say Hi!
a debug message

1 test, 0 failures
```

Так можна побачити корисне виведення для налагодження й не вплинути на тести.

Якщо використовувати це в кількох місцях коду, можна винести подробиці у функцію, щоб код читався легше:

```awk
BEGIN {
    debug("starting ...")
}

# do stuff here ...

END {
    debug("... finished")
}

function debug(msg) {print msg > "/dev/fd/3"}
```
