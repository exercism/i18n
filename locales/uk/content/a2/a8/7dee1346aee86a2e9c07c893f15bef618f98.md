# Докладніше

## const

Модифікатор [`const`][constants] можна (і зазвичай варто) застосовувати до будь-якого поля, значення якого відоме під час компіляції й не змінюється протягом життєвого циклу програми.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

Компілятор підкаже, які вирази можна обчислити під час компіляції. Прості арифметичні операції дозволені, як і конкатенація рядків тексту (англ. string). Це виключає будь-яке обчислення, яке вимагало б використання купи чи стека, тож усі виклики методів і посилання на непримітивні типи недоступні.

У мережі точаться деякі дискусії про переваги `const` над змінними щодо продуктивності. У разі порівняння з полями екземпляра, не позначеними `const`, може спостерігатися помітна економія памʼяті, але порівняно зі статичними змінними вона безумовно тривіальна. Будь-які міркування про продуктивність процесора колеги, найімовірніше, сприймуть як [передчасну оптимізацію][premature-optimization].

Переконливіша причина використовувати `const` полягає в тому, що це полегшує супроводжувачу міркування про код. Побачивши, що поле позначене як `const` чи `readonly`, або що властивість не має сетера, супроводжувач може здебільшого виключити його зі свого аналізу. Малоймовірно, що саме тут гніздяться помилки. Малоймовірно, що воно ускладнить рефакторинг. Про це йдеться в [цьому коментарі на Stack Overflow][so-consts].

Модифікатор `const` можна також застосовувати до значень усередині методів:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

Позначення значення через `const` у такий спосіб може бути корисним, якщо воно використовується в методі кілька разів або якщо ми хочемо привернути увагу до його сенсу. Жодного виграшу в продуктивності порівняно з літералами, вбудованими в код, немає.

## readonly

Модифікатор [`readonly`][readonly-fields] можна (і зазвичай варто) застосовувати до будь-якого поля, яке не можна зробити `const`, якщо його значення не змінюється протягом життєвого циклу програми й задається або вбудованим ініціалізатором, або під час створення екземпляра (конструктором чи методом, який викликає конструктор).

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

Використання модифікатора `readonly` заохочується з тих самих причин, що й `const`. Такий спосіб обмеження полів допомагає супроводжувачам міркувати про код.

Зауважмо, що додавання модифікатора `readonly` до поля забороняє змінювати лише значення самого поля. Для складених типів він не захищає поля чи властивості цього типу. Зокрема, він не захищає вміст масивів.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

Щоб захистити всі члени типу-посилання, поля можна зробити `readonly`, а автоматичні властивості оголосити без аксесора `set`.

Варто ознайомитися з [колекціями лише для читання][readonly-collections] у базовій бібліотеці класів.

Для масивів найближчим наближенням до версії лише для читання є метод [`Array.AsReadOnly<T>()`][as-read-only].
