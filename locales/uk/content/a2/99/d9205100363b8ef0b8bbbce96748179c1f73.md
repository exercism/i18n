# Тести

Тести можна запустити, виконавши таку команду в каталозі вправи:

```bash
dub test
```

## Як пройти тести

Зробімо так, щоб перший тест компілювався, компонувався й проходив, дотримуючись [трьох
правил розробки через тестування](http://butunclebob.com/ArticleS.UncleBob.TheThreeRulesOfTdd).
Створімо рівно стільки структури, оголосивши простори імен, функції, класи
тощо, щоб усунути помилки компіляції й домогтися того, щоб тест провалився. Потім напишімо
рівно стільки коду, щоб тест пройшов. Коли це зроблено,
розкоментуймо наступний тест, перемістивши наведений нижче рядок далі за наступний тест.

```D
static if (all_tests_enabled)
```

Це може призвести до помилок компіляції, адже можуть викликатися нові конструкції, які
ми ще не оголосили чи не визначили. Знову ж таки, виправмо помилки компіляції мінімально,
щоб отримати тест, який провалюється, потім мінімально змінімо код, щоб тест пройшов,
відрефакторімо власну реалізацію для читабельності й виразності, а тоді
перейдімо до наступного тесту.

Спробуймо використовувати стандартні засоби D замість того, щоб писати власні
низькорівневі алгоритми чи засоби вручну.
