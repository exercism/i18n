# Вступ

Винятки в Ruby, як і в багатьох інших мовах, дають змогу працювати з непередбачуваними подіями. Належна обробка винятків важлива, коли ми намагаємося вберегти свою програму від аварійного завершення.

Коли виникає виняток, байдуже, викликали ми його явно чи його викликав інтерпретатор Ruby, програма збивається зі звичного ходу роботи й зрештою завершується, виводячи повідомлення про помилку:

```ruby
raise ArgumentError.new("Something went wrong!")
=> Traceback (most recent call last):
.
.
ArgumentError (Something went wrong!)
```

```ruby
1/0
=> Traceback (most recent call last):
.
.
ZeroDivisionError (divided by 0)
```

Якщо ж ми хочемо зупинити це аварійне завершення, нам потрібно відреагувати на виняток. Це називається «рятуванням» винятку:

```ruby
begin
  # ...any code that raises an exception
rescue
  puts 'Got an exception'
end
```

Ця програма не зазнає аварії й виведе "Got an exception". Замість завершення роботи Ruby виконує код у блоці `rescue`, який виводить повідомлення.

Як і все в Ruby, винятки - це також обʼєкти, і зазвичай вони зберігають дані про виняток. Ось як ми можемо отримати обʼєкт винятку:

```ruby
begin
  # ...any code that raises an exception
rescue => e
  puts "Exception class: #{ e.class.name }"
  puts "Exception Message:#{e.message}"
end
```

У Ruby також можна викликати власні винятки. Наприклад:

```ruby
begin
  raise ArgumentError.new("Invalid argument")
rescue ArgumentError => e
  puts e.message
end
```

Наведений вище виняток - один із вбудованих винятків Ruby, але ми також можемо визначати власні винятки й викликати їх:

```ruby
class CustomError < StandardError
end

raise CustomError.new("Something went wrong")
```
