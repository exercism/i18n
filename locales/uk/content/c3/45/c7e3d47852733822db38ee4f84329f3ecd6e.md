# Вступ

Здебільшого Factor виконує ітерацію через комбінатори, як-от `each`, `map` і `count`. Іноді, втім, найчистіший спосіб записати обчислення - це **рекурсія**, тобто слово, яке викликає саме себе.

## Визначення рекурсивного слова

Визначення `:` може викликати саме себе безпосередньо:

```factor
: count-down ( n -- )
    dup 0 = [ drop ] [ dup . 1 - count-down ] if ;

5 count-down
! prints 5 4 3 2 1
```

## Розгалуження: порожня послідовність чи ні

`if-empty` (з [`sequences`][sequences]) - це природний базовий випадок рекурсії:

```
if-empty ( seq emptyquot nonemptyquot -- )
```

```factor
{ 4 0 9 } [ "empty" ] [ "got data" ] if-empty .
! => "got data"
```

`emptyquot` виконується, коли (порожню) послідовність уже знято зі стека; `nonemptyquot` виконується, коли послідовність ще лежить на стеку.

## `cond` - ланцюжок гілок із перевірками

Коли в нашій рекурсії більше ніж два випадки, `cond` (з [`combinators`][combinators]) допомагає зберегти код читабельним:

```factor
: classify ( n -- label )
    {
        { [ dup 0 < ] [ drop "negative" ] }
        { [ dup 0 = ] [ drop "zero"     ] }
        [ drop "positive" ]
    } cond ;
```

## Посилання вперед за допомогою `DEFER:`

Визначення `:` може викликати саме себе безпосередньо, але коли два слова викликають *одне одного*, парсер бачить перше з них раніше, ніж існує друге. `DEFER:` резервує імʼя, щоб перше визначення могло скомпілюватися:

```factor
DEFER: even?

: odd? ( n -- ? ) dup 0 = [ drop f ] [ 1 - even? ] if ;
: even? ( n -- ? ) dup 0 = [ drop t ] [ 1 - odd? ] if ;
```

`DEFER:` також стає в пригоді, коли допоміжне слово природніше читати *після* слова, яке його використовує.
