# Додаток до інструкцій

## Підказки

Один із головних аспектів функціонального програмування - мати функції без побічних ефектів, щоб не доводилося гадати, які приховані обʼєкти змінила функція.  

У реактивному програмуванні замість того, щоб component активно шукав роботу, цю роботу передають до component. Це схоже на колбеки, але на значно вищому рівні, з потужнішими абстракціями. Дуже часто реактивне програмування використовують разом із функціональним програмуванням.

У цій вправі ми будемо використовувати [RxJava](https://github.com/ReactiveX/RxJava), відому бібліотеку для реактивного програмування з Java API.

Змодельований контекст цієї вправи - застосунок, який приймає два вхідні потоки:

- нові слова для вгадування, які надсилає якийсь ігровий рушій,
- літери, які обирає гравець.

 Ці два вхідні потоки реалізовано за допомогою [Observables](http://reactivex.io/documentation/observable.html), а саме класу [io.reactivex.Observable](http://reactivex.io/RxJava/2.x/javadoc/io/reactivex/Observable.html).
 По суті, ми можемо підписатися на `Observable`, щоб «реагувати» на значення, які десь створюються. Наприклад, ігровий рушій надсилає нові слова, коли виявляє, що почалася нова гра, а події клавіатури породжують вхідні літери.  
 Але багато реактивних фреймворків пропонують потужні абстракції, як-от [`map`](http://reactivex.io/documentation/operators/map.html), що дає змогу змінити отримані вхідні дані, або [`combine`](http://reactivex.io/documentation/operators/combinelatest.html), що дає змогу поєднати один або кілька `Observable`.

Клас `Output` - це очікуваний результат обробки вправи, який дає змогу frontend показати повний стан гри, не вимагаючи від нього жодної форми сховища. Це також робить його функціональним.  

У цій вправі нам треба знайти спосіб використати обидва вхідні потоки, щоб згенерувати ці вихідні дані у вигляді `Observable`.
