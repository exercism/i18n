# Докладніше

Класи, як-от `LocalDate` і `LocalDateTime`, описують _точку_ в часі.
Пакет `java.time` також має два класи, які описують _кількість_ часу:

- [`Period`][period-docs] - це календарний проміжок у роках, місяцях і днях, наприклад «2 місяці і 5 днів».
- [`Duration`][duration-docs] - це часовий проміжок у годинах, хвилинах, секундах, мілісекундах і наносекундах, наприклад «1 година і 30 хвилин».

Ця різниця важлива, бо календарні одиниці не мають фіксованої тривалості.
Місяць може мати 28, 29, 30 або 31 день, тому «один місяць» не відповідає фіксованій кількості секунд.
`Period` дотримується календаря, а `Duration` вимірює точний час.

| | `Period` | `Duration` |
| --- | --- | --- |
| Зберігає | роки, місяці та дні | секунди й наносекунди |
| Використовується з | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

Обидва класи незмінні.
Методи, як-от `plusDays()` або `multipliedBy()`, повертають _новий_ екземпляр і залишають початковий без змін.

## `Period`

### Створення періоду

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

Результат `toString()` використовує [формат тривалості ISO-8601][iso-8601-durations]: `P`, після якого записано кількість років (`Y`), місяців (`M`) і днів (`D`).
У `Period` немає тижнів: `Period.ofWeeks(2)` зберігається як 14 днів.
Той самий запис можна розібрати назад за допомогою `Period.parse()`:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### Додавання періоду до дати

Період додають до дати або віднімають від неї за допомогою `plus()` і `minus()`:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

Період можна додати до `LocalDateTime` так само, і час доби залишиться той самий:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

`Instant` не має календаря, тому до нього можна додати лише період у днях.
Додавання періоду з роками або місяцями кидає виняток:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

Спочатку додають роки, потім місяці, а потім дні.
Коли додавання років або місяців припадає на день, якого не існує, результат переносять назад на останній дійсний день цього місяця:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

Це також означає, що додавання періоду й подальше його віднімання не завжди повертає початкову дату:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### Період між двома датами

`Period.between()` повертає період від однієї дати (включно) до іншої (не включно).
Той самий результат можна отримати через `LocalDate.until()`:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

Частини періоду доступні через `getYears()`, `getMonths()` і `getDays()`.
Ці частини незалежні одна від одної: `getDays()` повертає лише частину днів, а не загальну кількість днів.
`toTotalMonths()` повертає роки й місяці разом як кількість місяців, але методу для загальної кількості днів немає, бо вона залежить від того, які місяці враховано.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### Нормалізація періоду

Період, створений фабричним методом, зберігає свої одиниці точно такими, як їх задано, а `equals()` порівнює одиниці одну за одною.
`normalized()` переносить місяці в роки, але не змінює дні:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## Підрахунок одиниць за допомогою `ChronoUnit`

Щоб отримати загальну кількість однієї одиниці між двома точками в часі, використаймо метод `between()` для однієї з констант [`ChronoUnit`][chronounit-docs]:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

Враховують лише повні одиниці, а результат відʼємний, коли другий аргумент стоїть перед першим:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit` також працює з часовими одиницями й обʼєктами дати та часу:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### Створення тривалості

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

У записі ISO-8601 літера `T` відокремлює частину дати від частини часу.
`Duration` не має частини дати, тому його `toString()` завжди починається з `PT`.
`Duration.ofDays()` вважає один день точно 24 годинами.

Тривалість також можна розібрати за допомогою `Duration.parse()`:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### Додавання тривалості до часу

Тривалість додають до `LocalTime`, `LocalDateTime` або `Instant` і віднімають від них за допомогою `plus()` та `minus()`:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

`LocalTime` переходить через опівніч, як показує останній приклад.

`LocalDate` не має часу, тому його не можна поєднати з `Duration`:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### Тривалість між двома часами

`Duration.between()` повертає точну кількість часу між двома часами або обʼєктами дати й часу:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()` не приймає два значення `LocalDate`, бо дата не має секунд для вимірювання:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

Натомість для дат варто використати `Period.between()` або `ChronoUnit.DAYS.between()`.

### Перетворення тривалості

Методи `toXxx()` перетворюють тривалість на _загальну_ кількість однієї одиниці, округлену вниз:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

Методи `toXxxPart()` розкладають тривалість на частини, як на годиннику:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()` зупиняється на 23, бо години понад це враховує `toDaysPart()`.

### Порівняння та обчислення з тривалостями

Тривалості можна порівнювати за допомогою `compareTo()` і перевіряти за допомогою `isZero()` та `isNegative()`:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

Вони також підтримують арифметичні дії, як-от `plus()`, `minus()`, `multipliedBy()` і `dividedBy()`:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` чи `Duration`?

Для `LocalDate` або `LocalTime` вибір уже зроблено: дата не має часу для вимірювання, а час не має календаря.
`LocalDateTime` має і дату, і час, але не має часового поясу, тому додавання `Period.ofDays(1)` або `Duration.ofDays(1)` до нього дає той самий результат.
Різниця стає видимою з часовими поясами.
Коли стрілки переводять уперед через перехід на літній час, календарна доба має лише 23 години:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

Додавання `Period` на один день зберігає час доби, а додавання `Duration` на один день додає рівно 24 години.
Використовуймо `Period` для величин, про які люди думають у календарних термінах («той самий час наступного місяця»), і `Duration` для часу, що минув («паркувальний талон дійсний 2 години»).
