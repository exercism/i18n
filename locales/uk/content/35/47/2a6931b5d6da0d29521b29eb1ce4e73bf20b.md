# Вступ

Концепт [`Basics`][basics] представив два способи визначення функції.

Найзагальніший варіант - багаторядкова форма:

```julia
function muladd(x, y, z)
    x * y + z
end
```

Форма «присвоєння», або «однорядкова», для коротких визначень:
```julia
muladd(x, y, z) = x * y + z
```

У третій, ще коротшій формі коротку функцію для одноразового використання можна створити без назви:

```julia-repl
julia> map(x -> 2x, 1:3)
4-element Vector{Int64}:
 2
 4
 6

julia> map((x, y) -> x * y, 1:3, 4:6)
3-element Vector{Int64}:
  4
 10
 18
```

У цьому випадку `x -> 2x` - анонімна функція.
Це те саме, що в деяких інших мовах називають «лямбда-функцією».

Зауважмо, що для кількох аргументів потрібні дужки, як у `(x, y) -> x * y`.

Анонімні функції часто трапляються в коді Julia, особливо в поєднанні з функціями вищого порядку, як-от `map()` і `filter()` (докладніше про них ітиметься в одному з наступних концептів).

```julia-repl
julia> map(x -> x^4, [1, 2, 3])
3-element Vector{Int64}:
  1
 16
 81
```

## Аргументи функцій

Досі в силабусі ми розглядали лише функції з точно визначеною кількістю аргументів, які вимагають, щоб у виклику функції були передані всі вони, у правильному порядку.
Це було б обмежувально й незручно, тому існує кілька інших варіантів.

### Необовʼязкові аргументи

Як і багато мов, Julia дозволяє у визначенні функції задавати типові значення для окремих аргументів.

Тоді виклик функції може або передати значення для цього аргументу, або пропустити його й покластися на типове значення.

```julia-repl
julia> f(x, y=10) = x * y
f (generic function with 2 methods)

julia> f(2, 3)
6

julia> f(2)
20
```

Усі аргументи _без_ типових значень мають іти перед аргументами _з_ типовими значеннями, тож `f(x=2, y)` буде некоректним.

### Ключові аргументи

У всіх прикладах досі використовуються `positional arguments`, де значення, передані у виклику функції, мають відповідати порядку відповідних аргументів у визначенні функції.

Як і багато мов, Julia також дозволяє `keyword arguments`.
У виклику функції потрібно вказати назву аргументу, але кілька ключових аргументів можна тоді вказати в будь-якому порядку.

Характерна риса Julia полягає в тому, що перед ключовими аргументами (якщо вони є) у визначенні функції має стояти крапка з комою `;`, яка відділяє їх від позиційних аргументів.
У виклику функції між останнім позиційним аргументом і першим ключовим аргументом можна використати або `;`, або `,`.

```julia-repl
julia> b(x; y) = x + y
b (generic function with 1 method)

julia> b(2, y=3)
5

# keyword is required when calling
julia> b(2, 3)
ERROR: MethodError: no method matching b(::Int64, ::Int64)
The function `b` exists, but no method is defined for this combination of argument types.
```

Типові значення можна за потреби вказати так само, як і для позиційних аргументів.

Часто у виклику функції виникає синтаксис на кшталт `myarg=myarg`, коли змінну з тією самою назвою, що й параметр, було обчислено заздалегідь.
У такій ситуації можна використати скорочений синтаксис:

```julia-repl
julia> width = 4.0
4.0

julia> height = √ width
2.0

julia> area(; width, height) = width * height
area (generic function with 1 method)

# repetition
julia> area(; width=width, height=height)
8.0

# shorthand form
julia> area(; width, height)
8.0
```

### Splat і slurp

Це усталені назви однієї корисної особливості синтаксису Julia, якщо комусь було цікаво.
Обидві позначають оператор `...`.

#### Splat

Splat використовують у _викликах_ функцій, щоб розгорнути колекції в окремі значення, яких потребує функція.

Це, мабуть, легше показати, ніж пояснити:

```julia-repl
julia> fxyz(x, y, z) = x * y * z
fxyz (generic function with 1 method)

julia> xyz = [2, 3, 4]
3-element Vector{Int64}:
 2
 3
 4

# Using the vector directly in a function call is invalid
julia> fxyz(xyz)
ERROR: MethodError: no method matching fxyz(::Vector{Int64})
The function `fxyz` exists, but no method is defined for this combination of argument types.

# splatting converts the vector to 3 numbers, used as positional arguments
julia> fxyz(xyz...)
24
```

Деякі «виклики функцій» приховані синтаксичним цукром, тож splat можна використати й у менш очевидних місцях.

Наприклад, множинне присвоєння всередині використовує функцію-конструктор кортежу:

```julia-repl
julia> first, rest... = [1, 2, 3, 4]
4-element Vector{Int64}:
 1
 2
 3
 4

julia> first
1

julia> rest
3-element Vector{Int64}:
 2
 3
 4
```

Ключові аргументи також можна передати через splat, зазвичай за допомогою `named tuple`. 
`Dict` теж підійде, але ключі мають бути символами, а не рядками тексту (англ. string).

```julia-repl
# function with 3 keyword arguments
julia> fabc(; a, b, c) = a + b + c
fabc (generic function with 1 method)

# named tuple
julia> abc_nt = (a=2, b=3, c=4)
(a = 2, b = 3, c = 4)

# there are no positional arguments, so need to use ; before kw argument
julia> fabc(;abc_nt...)
9

# Dict
julia> abc_dict = Dict(:a=>2, :b=>3, :c=>4)
Dict{Symbol, Int64} with 3 entries:
  :a => 2
  :b => 3
  :c => 4

julia> fabc(;abc_dict...)
9
```

#### Slurp

Slurp використовують у _визначенні_ функції, щоб зібрати довільну кількість окремих значень у колекцію.

```julia-repl
julia> f_more(i, j, more...) = i + j + sum(more)
f_more (generic function with 1 method)

julia> f_more(1, 3, 5, 7, 9, 11)
36
```

Назва аргументу, який збирається через slurp (у цьому випадку `more`), не має значення.
Тип цієї змінної обирає компілятор, але для позиційних аргументів це, найімовірніше, буде `tuple` або щось подібне.

Ключові аргументи теж можна зібрати через slurp, отримавши `Dict` (або подібне).

```julia-repl
julia> f_kwslurp(x, y; switches...) = :mult in keys(switches) ? x * y : x + y
f_kwslurp (generic function with 1 method)

julia> f_kwslurp(5, 6; mult=true)
30

julia> f_kwslurp(5, 6)
11
```

У виклику можна використати будь-які ключові аргументи.
Саме визначення функції вирішує, на які ключові аргументи реагувати, а які ігнорувати.
