# Підказки
`Option` використовують, щоб позначити обчислення, яке може не мати корисного результату (наприклад, через помилку або некоректні вхідні дані).
Якщо `Option` нам незнайомий, можемо прочитати [цей посібник](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html).
`Option` належить до так званих [монад](https://en.wikipedia.org/wiki/Monad_(functional_programming)), які охоплюють «обчислювальний аспект», у цьому випадку можливу відсутність значення.
Правильне використання монад дає змогу отримати дуже лаконічний, але водночас елегантний і зрозумілий код. Неправильне використання легко може призвести до протилежного.
Щоб дізнатися більше, подивімося [це відео](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA).
## Поширені пастки, яких варто уникати
Для `Option` є кілька простих правил:
1. Якщо `Option` не потрібен, не варто його використовувати. Замість цього
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
краще написати
```scala
def add1(x: Int): Int = x + 1
```
(існує `Option.map`, щоб застосовувати такі прості функції, тож не потрібно захаращувати їх `Option`).
2. Не варто «розгортати», якщо в цьому немає справжньої потреби.
Часто для цього вже є вбудовані функції. Ознаки передчасного розгортання - `isDefined/isEmpty` або зіставлення зі зразком. Замість цього
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
краще написати
```scala
x map (_ + 1) getOrElse 0
```
3. Монади можна використовувати всередині for-виразу, і це чудово.
Це варто робити, коли потрібно «скомпонувати» кілька примірників `Option`. Замість цього
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
краще написати
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
