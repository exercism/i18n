# Докладніше

## Булеві значення в Julia

Тип `Bool` представляє значення «правда» та «неправда», тобто булеві значення (англ. Boolean).
Він містить лише два значення: `true` і `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

На відміну від кількох інших мов, у Julia навмисно немає поняття «truthiness», і лише вирази, які обчислюються до `true` або `false`, розглядатимуться як `Bool`.

Зокрема, порожні масиви чи рядки тексту (англ. string) *не* інтерпретуватимуться як `false`.
Якщо нам потрібна спеціальна обробка порожніх значень, має бути відповідний тест, наприклад `isempty()`.

## Булеві оператори

У Julia є три [булеві оператори][boolean-operators].

`&&` (логічне і) позначає булеве «і».
Він обчислюється до `true`, якщо вирази з *обох* боків від `&&` дорівнюють `true`.

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||` (логічне або) позначає булеве «або».
Він обчислюється до `true`, якщо вираз з *будь-якого* боку від `||` дорівнює `true`.

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!` позначає булеве «не».
Він замінює (інвертує) значення `true` та `false`.

```julia-repl
julia> !true
false

julia> !false
true
```

Подібні оператори концептуально знайомі тим, хто користується багатьма іншими мовами, хоча точний синтаксис може відрізнятися залежно від мови.

## Пріоритет операторів

У складніших виразах корисно знати, що `&&` має трохи вищий [пріоритет][operator-precedence], ніж `||` *(так само як в арифметичних виразах `*` застосовується раніше за `+`)*.

Покладатися на це може заплутувати й призводити до помилок.
Для ясності краще використати дужки, щоб чітко показати свій намір.

## Скорочене обчислення

Чи залежить вираз `true || x` від значення `x`, чи компілятор може знехтувати `x`?

Julia обчислює булеві вирази зліва направо й зупиняється, коли результат стає однозначним.

Наприклад, `true || x` обовʼязково має бути `true` незалежно від `x`, тож `x` не обчислюється.
Так само `false && y` дорівнює `false`, і обчислювати `y` не потрібно.

І навпаки, `true && x` дорівнює `true` *лише тоді*, коли `x` дорівнює `true`, тож `x` доведеться обчислити.

Так само, якщо ми поєднуємо кілька операторів:

```julia-repl
julia> true && false && something_else
false
```

Оскільки `true && false` обовʼязково дорівнює `false`, `something_else` не має значення, і компілятор його ігнорує.

У цьому випадку змінної `something_else` не існувало, але її використання в цьому контексті не спричинило помилки *(перевірмо це в REPL, якщо є сумніви)*.

Програмісти Julia доволі часто використовують таке скорочене обчислення як спосіб перехопити проблеми часу виконання та крайні випадки:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

Наприклад, `do_something` може бути достроковим `return` із функції, якщо `all_ok` дорівнює `false`, або присвоєнням типового значення змінній, перш ніж рухатися далі.

Це невелике зловживання булевим синтаксисом, але воно буває дуже зручним.

## Як булеві значення працюють всередині

Якщо булеве значення потрапляє в *арифметичний* вираз, `true` інтерпретується як `1`, а `false` як `0`, що відображає те, як вони зберігаються.

Якщо ми звикли до низькорівневих мов (C та подібних), *постараймося* не використовувати це часто.
Це знижує читабельність коду й ускладнює налагодження.

Іноді можна побачити, як числові значення використовують як швидкий спосіб порахувати, скільки чогось дорівнює `true`.

```julia-repl
julia> true + false + true
2
```
