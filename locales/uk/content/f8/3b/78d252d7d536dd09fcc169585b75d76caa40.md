# Вступ

Памʼять зазвичай відображається для програми операційною системою (ОС) за такою загальною схемою:

| адреса | ділянка памʼяті                 |
| :-----: | :------------------------------ |
|  висока   | стек                          |
|         | ...                             |
|         | купа                            |
|         | сегмент читання й запису        |
|         | сегмент коду/лише для читання   |
|   низька   | зарезервовано                 |

Памʼять у сегментах організовано в секції з різними правами доступу.

Усі функції, які ми досі визначали, були в **секції .text**.
У цій секції зберігаються виконувані дані, доступні тільки для читання.
В інших секціях оголошують змінні даних, які можуть бути доступними тільки для читання або для читання й запису, але не є виконуваними.

## Секція .data

Ініціалізовані дані оголошують у **секції .data**.

У NASM (The Netwide Assembler - асемблер, який використовується в цьому треку) ініціалізована змінна має назву, директиву, яка вказує розмір даних, і список значень, розділених комами.
Кожен із них відокремлюють пробілом від іншого, а після мітки необовʼязково може стояти `:`.

Основні директиви та відповідні їм розміри даних:

| директива | розмір    |
| :-------: | :-------- |
|    db     | 1 байт    |
|    dw     | 2 байти   |
|    dd     | 4 байти   |
|    dq     | 8 байтів  |

Наприклад, ось так оголошують байтову змінну з назвою `space` і значенням `10`:

```x86asm
section .data
    space db 10
```

Змінні, оголошені в `section .data`, можна змінювати, тобто вони доступні для читання й запису.
Вони також мають _статичну_ тривалість зберігання, тобто існують протягом усього часу виконання програми.

## Секція .rodata

**Секція .rodata** схожа на `section .data`.
Обидві секції містять ініціалізовані дані, які оголошують однаково, і мають однакову тривалість зберігання.

Головна різниця між ними в тому, що дані в `section .rodata` незмінні, тобто доступні тільки для читання.

~~~~exercism/note
Сталі, визначені за допомогою `equ`, відрізняються від сталих, визначених у `section .rodata`.

Стала, визначена за допомогою `equ`, не займає місця в памʼяті, і асемблер безпосередньо підставляє її значення.
Фактично вона є замінником цього значення.

З іншого боку, сталі, визначені в `section .rodata`, насправді зберігаються в памʼяті й мають адресу.
~~~~

## Доступ до даних

### Мітки та непряма адресація

Оголошені дані повинні мати повʼязану з ними назву.
Цю назву називають **міткою**.

Міткою називають символ, який кодує конкретну адресу даних у памʼяті.
**Адреси в x86-64 - це 64-бітні значення**.

У NASM спроба звернутися до даних безпосередньо за їхньою міткою дає не виділену памʼять, а її адресу:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

Щоб отримати вміст за адресою памʼяті, її потрібно _розіменувати_.
Це називають **непрямою адресацією**.

У NASM це роблять за допомогою `[]`:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

Однак бувають ситуації, коли розмір розіменованої памʼяті може бути неоднозначним.
У таких випадках потрібно використовувати префікс, який указує цей розмір.

Ось найважливіші префікси та їхні розміри в типовій програмі x86-64:

| префікс | розмір    |
| :----- | :------ |
| byte   | 1 байт  |
| word   | 2 байти |
| dword  | 4 байти |
| qword  | 8 байтів |

Те саме завантаження можна записати із явно зазначеним розміром:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

Вважається хорошою практикою завжди використовувати префікс під час розіменування памʼяті.

### Запис у памʼять

Запис у памʼять відбувається так само, через розіменування адреси:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

Зауважмо, що в більшості інструкцій можна використовувати операнди памʼяті, не завантажуючи спершу вміст у реєстр.
Однак зазвичай їх не можна використовувати одночасно і як операнд-джерело, і як операнд-призначення, лише як один із двох:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### Інструкція LEA

Хоча `mov` можна використати, щоб зберегти адресу змінної в реєстрі, для цього є спеціальна інструкція: **lea**.

Ця інструкція використовує операнд у формі памʼяті, але _не_ читає памʼять.
Натомість вона обчислює вираз ефективної адреси й записує результат в операнд-призначення:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

Ідіоматичніше використовувати `lea`, щоб обчислювати адреси памʼяті й зберігати їх у реєстрах.

### Відносна адресація

Коли ми звертаємося до комірок памʼяті, NASM типово генерує **абсолютні адреси**, тобто фіксовані адреси памʼяті.

З міркувань безпеки виконувані файли часто збирають як **PIE (Position Independent Executable, позиційно-незалежний виконуваний файл)**, де ділянки памʼяті розміщуються за випадковими адресами.
У `PIE` кінцева адреса змінної невідома під час компонування.
Тож код натомість обчислює адреси як зсув від значення в особливому реєстрі `rip`, який указує на наступну інструкцію для виконання.

Зазвичай це називають **адресацією відносно RIP**.

У NASM можна запросити доступ відносно RIP за допомогою оператора `rel`:

```x86asm
mov rax, qword [rel variable]
```

Відносну адресацію також можна зробити типовою для файлу з кодом, додавши `default rel` на початку.

Усі вправи в цьому треку компілюються і компонуються як `PIE`, тож для генерації відносних адрес слід використовувати `rel`.

### Видимість

Мітки (функції та дані), визначені в будь-якій секції (наприклад, `.text`, `.data`, `.rodata`), видимі в межах того самого файлу з кодом.
Якщо їх оголосити `global`, вони стають видимими й для інших файлів з кодом.

І навпаки: мітки, визначені в інших файлах з кодом, видимі з поточного файлу, якщо оголошені `extern`.
У цьому випадку в асемблері немає вказівки на розмір даних, його потрібно знати заздалегідь.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
