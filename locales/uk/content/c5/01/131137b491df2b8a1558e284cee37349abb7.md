# Вступ

Мова програмування Java використовує _винятки_ для обробки помилок та інших виняткових подій.

## Що таке виняток

Виняток - це подія, яка виникає під час виконання програми та порушує звичайний потік інструкцій.
У Java винятки створюються явно, і сам процес створення винятку називається _киданням винятку_.
Процес обробки винятку називається _перехопленням винятку_.

У Java всі винятки є підкласами класу `Exception`, який, своєю чергою, є підкласом `Throwable`.

Java розрізняє два типи винятків:

1. Контрольовані винятки
2. Неконтрольовані винятки

### Контрольовані винятки

_Контрольовані винятки_ - це виняткові ситуації, які застосунок має передбачати й уміти відновлюватися після них.
Приклад контрольованого винятку - `FileNotFoundException`, який виникає, коли метод намагається прочитати файл, якого не існує.

Цей тип винятку перевіряється під час компіляції: методи, які кидають контрольовані винятки, мають зазначити це у своїй сигнатурі, а код, що викликає метод, який може кинути контрольований виняток, зобовʼязаний його обробити, інакше код не скомпілюється.

Усі контрольовані винятки є підкласами `Exception`, які не розширюють `RuntimeException`.

### Неконтрольовані винятки

_Неконтрольовані винятки_ - це виняткові ситуації, які застосунок зазвичай не може передбачити або відновитися після них.
Приклад неконтрольованого винятку - `NullPointerException`, який виникає, коли метод замість непорожнього значення отримує `null`.

Цей тип винятку не перевіряється під час компіляції: методи, які кидають неконтрольовані винятки, не зобовʼязані зазначати це у своїй сигнатурі, а код, що викликає метод, який може кинути неконтрольований виняток, не зобовʼязаний його обробляти.

Усі неконтрольовані винятки успадковують `RuntimeException`, який, своєю чергою, розширює `Exception`.

## Кидання винятків

Метод у Java може кинути виняток за допомогою інструкції `throw`.

### Кидання контрольованого винятку

Коли метод кидає контрольований виняток, потрібно зазначити це в сигнатурі методу за допомогою ключового слова `throws`, як показано в прикладі нижче.
Це змушує код, що викликає цей метод, передбачити, що виняток може бути кинутий, і відповідно його обробити.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### Кидання неконтрольованого винятку

Коли метод кидає неконтрольований виняток, зазначати це в сигнатурі методу не потрібно, хоча це й підтримується.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## Обробка винятків

Обробка винятків у Java виконується за допомогою ключових слів `try`, `catch` і `finally`.

- Інструкції коду, які можуть кинути виняток, варто загортати в блок `try`.
- Після блоку `try` іде один або кілька блоків `catch`, які перехоплюють винятки, кинуті в блоці `try`.
- За блоками `catch` необовʼязково йде блок `finally`, який завжди виконується після блоку `try`, незалежно від того, був кинутий виняток чи ні.

Наступний приклад показує, як працюють ці ключові слова:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

У цьому прикладі, коли жодного винятку не кинуто, виводиться таке:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

Однак якщо інструкція `bankAccount.withdraw(amount)` кине `InsufficientBalanceException`, виводиться таке:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

Або, якщо `bankAccount.withdraw(amount)` кидає неконтрольований виняток, виводиться таке:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## Помилки

У Java також є окрема категорія під назвою _помилки_, до якої належать серйозні проблеми, зовнішні щодо застосунку.
Приклад помилки - `OutOfMemoryError`, який виникає, коли застосунок намагається використати більше памʼяті, ніж доступно в системі.

Як і неконтрольовані винятки, помилки не перевіряються під час компіляції.
Різниця в тому, що вони становлять проблеми системного рівня і зазвичай кидаються віртуальною машиною Java або середовищем, а не застосунком.
Застосунки зазвичай не повинні намагатися їх перехоплювати чи обробляти.

Усі помилки в Java успадковують клас `Error`.
