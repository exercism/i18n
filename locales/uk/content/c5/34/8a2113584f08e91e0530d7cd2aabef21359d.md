# Вступ

Як і багато інших мов, C++ має _вказівники_.
Ми вже знаємо, що _посилання_ та _вказівники_ схожі, але сприймаймо їх як ще один рівень ближче до внутрішньої будови компʼютера.
_Вказівники_ - це змінні, які зберігають адреси обʼєктів.
Їх використовують, щоб безпосередньо взаємодіяти з обʼєктами, що уможливлює динамічне виділення памʼяті та ефективну роботу з даними в C++.

Якщо ми тільки починаємо знайомитися зі _вказівниками_, вони можуть здаватися трохи загадковими, але щойно ми до них звикнемо, вони стануть цілком зрозумілими.

Це надзвичайно важлива частина C++, тож приділімо їм трохи часу, щоб справді їх зрозуміти.
Найпростіший варіант, про який ідеться в цьому концепті, також називають _дурним вказівником_ або _сирим вказівником_.
У сучасному C++ є також _розумні вказівники_, а базовий тип зовсім не розумний, і всю роботу доводиться виконувати вручну.

Перш ніж заглиблюватися в деталі, варто зрозуміти, для чого потрібні _вказівники_.
_Вказівники_ - це спосіб поділитися адресою обʼєкта з іншими частинами нашої програми, і це корисно з трьох основних причин:

1. Як і _посилання_, вказівники дають змогу уникнути копіювання та зменшити споживання ресурсів програмою.
1. На відміну від _посилань_, вказівник можна перенаправити на інший обʼєкт.
1. Вказівник також може вказувати на нульове значення, показуючи, що зараз він не вказує на жоден обʼєкт.

## Загальний синтаксис

Оголошення вказівника в C++ передбачає вказівку типу даних, на який вказує вказівник, а потім зірочку (`*`) та імʼя вказівника.
Коли вказівники оголошують, їх не ініціалізують автоматично.
Без явного присвоєння вказівник зазвичай містить невизначене значення, яке часто називають «сміттєвою адресою».
Хоча деякі компілятори можуть ініціалізувати вказівники значенням `nullptr`, така поведінка не гарантована для всіх компіляторів, тож покладатися на неї не можна.
Найкраща практика - явно ініціалізувати сирі вказівники й перевіряти, що вони не є нульовими, перш ніж ними користуватися, щоб уникнути можливих проблем.

```cpp
int* ptr{nullptr}; // Declares a pointer and makes sure it is not invalid
```

Щоб присвоїти вказівнику адресу змінної, використовують оператор взяття адреси (`&`).
Розіменування вказівника виконують за допомогою _оператора розіменування_ (`*`).

```cpp
std::string opponent{"Solomon Lane"};
// 'ethan' points to the address of the string opponent
std::string* ethan{&opponent};
// Instead of ethan's, the opponent's name address is given to the passPort
std::string passportName{*ethan};
```

Звернімо увагу: розіменування потрібно виконувати явно, тоді як _посилання_ просто працюють як псевдонім.

## Арифметика вказівників

_Арифметика вказівників_ дає змогу виконувати арифметичні операції над вказівниками, що особливо корисно під час роботи з масивами.
Додавання цілого числа до вказівника змушує його вказувати на інший елемент.

```cpp
// Stargate Coordinate Code
int gateCode[] = {462, 753, 218, 611, 977};
// 'ptr' points to the first element of 'gateCode'
int* ptr{&gateCode[0]};
// Accesses the third Stargate address through pointer arithmetic
int dialedAddress{*(ptr + 2)};
// Chevron encoded! Dialing Stargate address:
openStarGate(dialedAddress);
```

~~~~exercism/caution
Арифметика вказівників у C++ може легко призвести до __невизначеної поведінки__, якщо поводитися з нею необережно.
Невизначена поведінка може проявлятися як несподівані результати роботи програми, збої чи навіть уразливості безпеки.
Один сумнозвісний приклад наслідків невизначеної поведінки стався 1996 року: [вибух ракети «Аріан-5»][ariane-flight-v88], де програмний виняток, спричинений перетворенням 64-бітного числа з плаваючою комою на 16-бітне ціле число зі знаком, призвів до катастрофічної відмови.

## Доступ до змінних-членів

У C++ оператор `->` використовують для доступу до членів обʼєкта через вказівник на цей обʼєкт.
Це скорочений запис, який спрощує доступ до членів обʼєктів, на які вказують вказівники.
Наприклад, якщо `ptr` - вказівник на обʼєкт із змінною-членом `x`, то замість `(*ptr).x` можна одразу скористатися `ptr->x`.
Цей оператор підвищує читабельність коду й позбавляє зайвої багатослівності під час роботи з вказівниками на обʼєкти.

Ось короткий приклад зі _struct_ `Superhero`, яка має змінну-член `superpower`.
Головна функція створює вказівник `dianaPrince` на обʼєкт `Superhero` (який уособлює Диво-жінку).
Оператор `->` використовують для доступу до змінної-члена `superpower`, демонструючи культове «Lasso of Truth» Диво-жінки.

```cpp
struct Superhero {
    std::string superpower;
};

Superhero wonder_woman{};
Superhero* dianaPrince = &wonder_woman;
dianaPrince->superpower = "Lasso of Truth";

// Using the -> operator to access member variable superpower:
std::cout << "Wonder Woman, possesses the mighty " << dianaPrince->superpower;

// Memory cleanup:
delete dianaPrince;
```

## Вказівники та посилання

І вказівники, і посилання дають змогу непрямо звертатися до обʼєктів, але вони відрізняються своїми можливостями та міркуваннями безпеки.
Вказівники дають змогу змінювати обʼєкт, на який вони вказують, і їм можна присвоїти null.
Однак така гнучкість породжує ризики, як-от розіменування нульових вказівників або створення висячих вказівників.
Посилання ж не можуть бути нульовими й привʼязані до дійсних обʼєктів уже під час створення, що дає змогу уникнути цих ризиків.
Оскільки посилання безпечніші, їм варто віддавати перевагу над вказівниками, якщо тільки не потрібні додаткові можливості, які дають вказівники.

## Динамічне виділення памʼяті та нульові вказівники

У C++ `new` використовують, щоб динамічно виділяти памʼять для обʼєктів у купі під час виконання програми.
Він повертає вказівник на виділену адресу памʼяті, завдяки чому час життя обʼєктів не привʼязаний до конкретної області видимості.
Однак важливо завжди поєднувати `new` з `delete`, щоб належно звільняти памʼять.
До динамічного виділення памʼяті варто ставитися обережно, щоб не допустити поширених проблем, як-от витоків памʼяті та звернення до вже звільненої памʼяті.

Вказівнику також можна надати особливе значення під назвою _нульовий вказівник_, яке означає, що він не вказує на дійсну адресу.
Нульові вказівники часто використовують, щоб ініціалізувати вказівники, перш ніж присвоїти їм дійсні значення.

```cpp
// There is a dark mark bearer, but who is it?
std::string* darkMarkBearer{nullptr};
// It is Bellatrix!
darkMarkBearer = new std::string{"Bellatrix Lestrange"};
// She has been defeated
delete darkMarkBearer;
// Reset pointer to null, symbolizing there is no more darkMarkBearer at the moment
darkMarkBearer = nullptr;
```

Вказівник має або зберігати адресу дійсного обʼєкта, або бути встановленим у `nullptr`.
Тоді достатньо перевіряти вказівники на null і можна вважати будь-який ненульовий вказівник дійсним.
Коли обʼєкт знищено, усі вказівники на нього залишаються _висячими_ (їх не буде автоматично встановлено в `nullptr`).
Наша відповідальність - виявляти такі випадки й дбати про те, щоб ці вказівники згодом було встановлено в `nullptr`.


У старішому коді можна натрапити на дві альтернативи `nullptr`.
По-перше, літерал `0` спеціально інтерпретують як нульове значення для вказівників, хоча це єдиний випадок, коли цілочисельний літерал можна присвоїти вказівнику.
По-друге, `preprocessor macro` `NULL`, успадкований із C і визначений у заголовку `<cstddef>`, - це ще одне представлення нульового вказівника, хоча в сучасному коді C++ його використовують рідше.
