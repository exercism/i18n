# Вступ

*Дек* (двостороння черга) підтримує додавання й вилучення з обох кінців за O(1). Стандартна реалізація у Factor - `<dlist>` (двобічно звʼязаний список) у [`dlists`][dlists], а операції живуть у [`deques`][deques].

## API дека

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` спорожнює дек на місці, що корисно для повторного використання без повторного виділення памʼяті.

Якщо додавати й вилучати з одного кінця, отримаємо стек LIFO. Якщо додавати з одного кінця, а вилучати з іншого, отримаємо чергу FIFO:

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

Для LIFO краще взяти вектор (`V{ }`) з `push`/`pop`: він має менші накладні витрати на операцію. Берімо `<dlist>`, коли потрібен O(1) з *обох* кінців, а це майже завжди означає чергу FIFO.

## Пошук у ширину

Саме використання FIFO робить деки природним фронтом для *BFS*. Ми починаємо з одного вузла, додаємо сусідів у кінець, вилучаємо кандидатів із початку й усуваємо дублікати за допомогою хеш-множини:

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

Старіших кандидатів відвідуємо раніше за новіших, тож пошук розгортається шарами назовні від старту. Саме це дає BFS властивість найкоротшого шляху: перший раз, коли ми досягаємо цільового вузла, шлях має найменшу кількість переходів.

## Автоматичне кешування з `MEMO:`

Іноді пошук для кожного вузла, який викликає BFS, дорогий. Модуль [`memoize`][memoize] у Factor дає нам `MEMO:`, повноцінну заміну `:`: вона кешує результат слова, привʼязуючи його до вхідних даних:

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

Слово з `MEMO:` виконує своє тіло, коли вперше бачить кожне вхідне значення, а далі повертає кешований результат: той самий інтерфейс, жодних зайвих викликів у місці виклику, просто швидше за повторів.
