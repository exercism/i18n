# Вступ

Як і багато інших мов, Go має вказівники.
Якщо вказівники для нас у новинку, вони можуть здаватися трохи загадковими, але щойно ми звикнемо до них, вони стануть цілком зрозумілими.
Це надзвичайно важлива частина Go, тож варто приділити час, щоб справді їх зрозуміти.

Перш ніж заглиблюватися в деталі, варто зрозуміти, для чого потрібні вказівники.
Вказівники дають змогу ділити памʼять з іншими частинами нашої програми, і це корисно з двох основних причин:

1. Коли ми маємо великі обсяги даних, створювати копії, щоб передавати їх між функціями, дуже неефективно.
   Натомість, якщо передавати адресу памʼяті, де ці дані зберігаються, ми можемо різко зменшити обсяг ресурсів, які споживають наші програми.
2. Передаючи вказівники між функціями, ми можемо напряму звертатися до єдиного примірника даних і змінювати його, а отже, будь-які зміни, зроблені однією функцією, одразу стають видимими для інших частин програми, коли функція завершується.

## Змінні та памʼять

Припустімо, у нас є звичайна змінна цілого типу `a`:

```go
var a int
```

Коли ми оголошуємо змінну, Go має знайти місце в памʼяті, щоб зберегти її значення.
Від нас це значною мірою приховано: коли нам потрібно дістати значення, збережене в цій ділянці памʼяті, достатньо звернутися до нього за іменем змінної.

Наприклад, коли ми пишемо `a + 2`, ми фактично дістаємо значення, збережене в памʼяті, повʼязаній зі змінною `a`, і додаємо до нього 2.

Так само, коли нам потрібно змінити значення в ділянці памʼяті `a`, ми можемо виконати присвоєння за допомогою імені змінної:

```go
a = 3
```

Тепер ділянка памʼяті, повʼязана з `a`, зберігатиме значення `3`.

## Вказівники

Хоча змінні дають нам змогу посилатися на значення в памʼяті, іноді корисно знати **адресу памʼяті**, на яку вказує змінна.
**Вказівники** зберігають адреси памʼяті цих значень.
Щоб оголосити змінну типу-вказівника, потрібно поставити зірочку перед базовим типом:

```go
var p *int // 'p' contains the memory address of an integer
```

Тут ми оголошуємо змінну `p` типу «вказівник на int» (`*int`).
Це означає, що `p` зберігатиме адресу памʼяті цілого числа.
Вказівники мають нульове значення `nil`, бо вказівник зі значенням `nil` не містить жодної адреси памʼяті.

### Як отримати вказівник на змінну

Щоб знайти адресу памʼяті значення змінної, ми можемо скористатися оператором `&`.
Наприклад, якщо ми хочемо знайти адресу памʼяті змінної `a` і зберегти її у вказівнику `p`, можна зробити так:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Доступ до значення через вказівник (розіменування)

Маючи вказівник, ми можемо захотіти дізнатися значення, збережене за адресою памʼяті, на яку цей вказівник указує.
Для цього можна скористатися оператором `*`:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

Операція `*p` дістає значення, збережене за адресою памʼяті, що міститься в `p`.
Цю операцію часто називають «розіменуванням».

Оператор розіменування також дає змогу присвоїти нове значення за адресою памʼяті, на яку посилається вказівник:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

Присвоєння до `*pa` змінить значення, збережене за адресою памʼяті, яку містить `pa`.
Оскільки `pa` містить адресу памʼяті `a`, присвоюючи до `*pa`, ми фактично змінюємо значення `a`!

Однак є застереження: перш ніж розіменовувати вказівник, завжди перевіряймо, чи він не `nil`.
Розіменування вказівника зі значенням `nil` призведе до аварійного завершення програми під час виконання!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Вказівники на структури

Досі ми бачили лише вказівники на примітивні значення.
Вказівники можна створювати й на структури:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

Ми могли б також створити нову `Person` і одразу зберегти вказівник на неї:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Коли ми маємо вказівник на структуру, перед доступом до одного з полів його не потрібно розіменовувати:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## Зрізи та словники вже є вказівниками

Зрізи та словники належать до особливих типів, бо у своїй реалізації вони вже містять вказівники.
Це означає, що здебільшого нам не потрібно створювати вказівники для цих типів, щоб ділити адресу памʼяті їхніх значень.
Уявімо, що в нас є функція, яка збільшує значення ключа у словнику:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Якщо ми створимо словник і викличемо цю функцію, зміни, які функція внесла до словника, збережуться після її завершення.
Таку саму поведінку ми отримали б, використовуючи вказівник, але звернімо увагу: у цьому прикладі ми не використовуємо ні взяття адреси, ні розіменування, ні будь-який інший синтаксис вказівників:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

Те саме стосується зміни наявного елемента у зрізі.

Однак дії, що повертають новий зріз, як-от `append`, є особливим випадком і **можуть не** змінити зріз за межами функції.
Це повʼязано з тим, як зрізи працюють усередині, але ми не будемо розглядати це докладно, бо це складніша тема.
