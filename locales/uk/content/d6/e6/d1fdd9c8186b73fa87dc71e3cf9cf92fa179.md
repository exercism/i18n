# Інструкції

Ми пишемо цифрове ядро невеликого мікшерного пульта в студії звукозапису.

Звук надходить як потік семплів.
Кожен семпл - це число, що описує положення дифузора гучномовця в певний момент.
Пульт обробляє цілий блок семплів за раз, застосовуючи ту саму операцію до кожного.

На нас чекає пʼять завдань, кожне з яких працює з блоком семплів, що зберігається в памʼяті.
Операнди ми отримуємо через адреси памʼяті, а відповідь записуємо через адресу результату.

~~~~exercism/note
Обчислення у цій вправі слід виконувати за допомогою інструкцій SIMD, а не скалярних операцій.
~~~~

## 1. Змішати два треки

Іноді студія записує інструменти на різні доріжки.
Щоб відтворити їх через ті самі колонки, ми додаємо дві доріжки в одну.

Реалізуйте функцію `mix_tracks`, яка додає дві доріжки семпл за семплом.
Кожна доріжка - це блок із 8 знакових 16-бітних семплів.
Сума, яка виходить за межі діапазону знакових 16-бітних чисел, повинна насичуватися, а не загортатися.

Ця функція приймає як аргументи, у такому порядку:

- `result`: адреса памʼяті, вирівняна на 16 байтів, для буфера, куди записуються 8 змішаних семплів.
- `track_a`: адреса памʼяті першої доріжки, вирівняна на 16 байтів, із 8 знаковими 16-бітними семплами.
- `track_b`: адреса памʼяті другої доріжки, вирівняна на 16 байтів, із 8 знаковими 16-бітними семплами.

```c
track_a = {10000, 30000, 20000, -30000, -20000, -100,  100, 0}
track_b = { 5000,  5000, 20000,  -5000, -20000,  100, -100, 0}
result  = {15000, 32767, 32767, -32768, -32768,    0,    0, 0}
```

Ця функція не повертає значення.

## 2. Прибрати просочування

Коли два мікрофони записують одночасно, кожен із них уловлює слабку копію джерела іншого.
Цю небажану копію називають _просочуванням_.
Щойно це просочування виміряно, його потрібно відняти, щоб очистити доріжку.

Реалізуйте функцію `remove_bleed`, яка віднімає блок просочування від блоку доріжки, семпл за семплом.
Кожен блок - це 8 знакових 16-бітних семплів, і віднімання має насичуватися.

Ця функція приймає як аргументи, у такому порядку:

- `result`: адреса памʼяті, куди записуються 8 очищених семплів (вирівнювання не гарантовано).
- `track`: адреса памʼяті записаної доріжки, вирівняна на 16 байтів, 8 знакових 16-бітних семплів.
- `bleed`: адреса памʼяті просочування, яке треба прибрати, 8 знакових 16-бітних семплів (вирівнювання не гарантовано).

```c
track  = {10000, -30000, 5000, 32767, 0,  200, -200, 15000}
bleed  = { 2000,   5000, 5000,    -5, 0,  300,  300,  5000}
result = { 8000, -32768,    0, 32767, 0, -100, -500, 10000}
```

Ця функція не повертає значення.

## 3. Обʼєднати індикатори

Над кожним каналом розташований індикатор рівня, невеличка смужка, яскравість якої показує, наскільки гучний цей канал.
На передній панелі є один головний індикатор, який має світитися так само яскраво, як два канали разом.
Ми додаємо два блоки індикаторів, щоб керувати ним.

Звернімо увагу, що яскравий індикатор залишається на повній яскравості, а не загортається назад до темного, тож сума насичується.

Реалізуйте функцію `combine_meters`, яка додає два блоки індикаторів семпл за семплом.
Ця функція приймає як аргументи, у такому порядку:

- `result`: адреса памʼяті, вирівняна на 16 байтів, куди записуються 16 обʼєднаних значень.
- `meter_a`: адреса памʼяті блоку індикатора першого каналу, вирівняна на 16 байтів, із 16 упакованими беззнаковими 8-бітними значеннями.
- `meter_b`: адреса памʼяті блоку індикатора другого каналу, вирівняна на 16 байтів, із 16 упакованими беззнаковими 8-бітними значеннями.

Кожен блок - це 16 беззнакових 8-бітних значень.
Їх треба додати, насичуючи до беззнакового діапазону.

```c
meter_a = {200, 100,  50, 255, 0, 128, 10, 240, 1, 2, 3, 4, 5, 6, 7, 8}
meter_b = {100, 100, 200,   1, 0, 128, 10,  20, 1, 2, 3, 4, 5, 6, 7, 8}
result  = {255, 200, 250, 255, 0, 255, 20, 255, 2, 4, 6, 8, 10, 12, 14, 16}
```

Ця функція не повертає значення.

## 4. Застосувати затухання

Пісня не повинна обриватися різко, а має плавно затухати в кінці.
У нас є блок _коефіцієнтів підсилення_, по одному на кожен семпл, які дедалі зменшуються.

Кожен коефіцієнт - це дріб, виражений у частках від `65536`.
Наприклад, якщо семпл має значення `16384`, він насправді виражає `16384 / 65536`, тобто `1 / 4`.
Найбільше придатне значення, `32767`, трохи менше за половину.

Оскільки `65536` - це `2^16`, множення семплу на його коефіцієнт зі збереженням _старшої половини_ добутку дає `sample * gain / 65536`.

Реалізуйте функцію `apply_fade`, яка масштабує кожен семпл на його коефіцієнт.
Ця функція приймає як аргументи, у такому порядку:

- `result`: адреса памʼяті, вирівняна на 16 байтів, куди записуються всі масштабовані семпли.
- `track`: адреса памʼяті доріжки, вирівняна на 16 байтів, із `n` знаковими 16-бітними семплами.
- `gains`: адреса памʼяті коефіцієнтів підсилення, вирівняна на 16 байтів, із `n` знаковими 16-бітними значеннями, кожне в діапазоні від `0` до `32767`.
- `n`: кількість семплів, яка завжди відмінна від нуля й кратна `8`, як 64-бітне беззнакове ціле число.

Звернімо увагу, що доріжка - це масив, який містить `n` знакових 16-бітних семплів, де `n` ніколи не дорівнює нулю й завжди кратне `8`.
Для кожного семплу масштабований результат - це _старші_ 16 бітів знакового добутку: `sample * gain`.

```c
track  = {20000, 20000, 20000, 20000, -20000, -20000, -20000, -20000}
gains  = {32767, 24576, 16384,  8192,  32767,  24576,  16384,   8192}
result = { 9999,  7500,  5000,  2500, -10000,  -7500,  -5000,  -2500}
```

~~~~exercism/note
Збереження старшої половини округлює в напрямку мінус нескінченності.
Ось чому `20000 * 32767` масштабується до `9999`, а `-20000 * 32767` масштабується до `-10000`, а не до `-9999`.
~~~~

Ця функція не повертає значення.

## 5. Послабити доріжку

Барабанщика записали занадто гучно.
Щоб знизити рівень усієї доріжки, ми ділимо кожен семпл на константу.

Реалізуйте функцію `attenuate_track`.
Ця функція приймає як аргументи, у такому порядку:

- `result`: адреса памʼяті, вирівняна на 16 байтів, куди записуються результати як 32-бітні знакові цілі числа.
- `samples`: адреса памʼяті семплів, вирівняна на 16 байтів, `n` знакових 16-бітних значень.
- `divisor`: адреса памʼяті 4 однакових копій дільника, вирівняна на 16 байтів, як 32-бітні цілі числа.
- `n` - це кількість семплів, яка завжди відмінна від нуля й кратна `4`, як 64-бітне беззнакове ціле число.

Звернімо увагу, що `samples` - це масив, який містить `n` знакових 16-бітних семплів, де `n` ніколи не дорівнює нулю й завжди кратне `4`.

Дільник подається як `4` копії одного й того самого 32-бітного цілого числа, уже розмножені, тож ним можна одразу заповнити всі чотири смуги.

У цілочисельному SIMD немає упакованого ділення, тож роботу виконують в упакованій плаваючій комі, а потім перетворюють назад на упаковані 32-бітні цілі числа, щоб зберегти в `result`.
Перетворюйте назад, відкидаючи дробову частину в напрямку нуля, тож частка `2.3` стає `2`, а `-2.3` перетворюється на `-2`.

```c
samples = {300, 150, 90, -120, 100, 50, -50, 7}
divisor = {3, 3, 3, 3}
result  = {100,  50, 30,  -40,  33, 16, -16, 2}
```

Ця функція не повертає значення.
