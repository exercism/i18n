# Вступ до перенаправлення

У світі інтерфейсу командного рядка програми часто взаємодіють із трьома стандартними потоками даних:

1. **Стандартний ввід** (`stdin`): звідки програма отримує свої вхідні дані (зазвичай з клавіатури).
1. **Стандартний вивід** (`stdout`): куди програма надсилає свій звичайний вивід (зазвичай на екран термінала).
1. **Стандартний потік помилок** (`stderr`): куди програма надсилає повідомлення про помилки (зазвичай на екран термінала).

Пригадаймо, що ми вже розглядали їх у розділі [Конвеєри та списки команд][pipelines].

~~~~exercism/note
Конвеєри можна вважати різновидом перенаправлення: стандартний вивід однієї програми надсилається безпосередньо на стандартний ввід іншої.
Конвеєри ми вже розглянули.
Ця тема охопить перенаправлення у файли та з файлів.
~~~~

Перенаправлення в оболонці - потужний механізм, який дає змогу змінювати призначення цих потоків.
Замість того щоб програма читала з клавіатури чи писала на екран, можна перенаправити ввід із файлу або надіслати вивід у файл.
Це дає чималу гнучкість і контроль над тим, як програми працюють із даними.

## Основні оператори перенаправлення

Ось найпоширеніші оператори перенаправлення та те, що вони роблять:

### `>` (перенаправлення виводу)

* Призначення: перенаправити стандартний вивід (`stdout`) команди у файл.
* Поведінка:
  * Якщо файл не існує, його буде створено.
  * Якщо файл існує, його вміст буде перезаписано.
* Приклад:

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
Перенаправлення виконується **до** запуску команди.
Це означає, що не можна перенаправляти у той самий файл, з якого потрібно читати.

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

У другій команді з наведеного прикладу

1. Bash спершу обрізає файл, названий у перенаправленні.
   Це знищує попередній вміст, залишаючи порожній файл.
2. Потім bash читає щойно спорожнений файл.
3. Далі bash записує вміст (тобто нічого) назад у файл.
~~~~

### `>>` (дописування виводу)

* Призначення: дописати стандартний вивід (`stdout`) команди у файл.
* Поведінка:
  * Якщо файл не існує, його буде створено.
  * Якщо файл існує, вивід додається в кінець файлу.
* Приклад:

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<` (перенаправлення вводу)

* Призначення: перенаправити стандартний ввід (`stdin`) команди з файлу.
* Поведінка: команда читає вхідні дані із зазначеного файлу, а не з клавіатури.
* Приклад:

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>` (перенаправлення помилок):

* Призначення: перенаправити стандартний потік помилок (`stderr`) команди у файл.
* Поведінка: повідомлення про помилки надсилаються у зазначений файл, а не в термінал.
* Приклад:
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

Стандартний потік помилок можна _дописати_ у файл за допомогою `2>>`.

## `/dev/null`

`/dev/null` - це спеціальний файл, який

* порожній, коли ми з нього читаємо, і
* відкидає всі дані, записані в нього.

Іноді його називають «біт-кошиком».
Він стає в пригоді, коли треба придушити вивід або помилки.

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## Поєднання перенаправлень

Кілька перенаправлень можна задати одночасно.

```bash
some_command < input.txt > output.txt 2> error.txt
```

Перенаправлення можна скопіювати.

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

Коли ми бачимо `2>&1`, читаймо це як «перенаправити stderr туди, _куди **зараз** вказує stdout_».
Bash обробляє інструкції перенаправлення строго зліва направо, а отже, можна зробити так:

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## Файлові дескриптори

У контексті програмування оболонки та операційних систем, як-от Linux/Unix, файловий дескриптор (FD) - це невідʼємне ціле число, яке слугує ідентифікатором або маркером для відкритого файлу чи ресурсу вводу-виводу (I/O).
Уявімо його як мітку або номер посилання, який операційна система використовує, щоб відстежувати відкриті файли та потоки даних.

Числа, які ми бачимо з лівого боку перенаправлень, - це файлові дескриптори.

Перші 3 файлові дескриптори відведено стандартним потокам вводу-виводу:

* стандартний ввід - це FD 0
* стандартний вивід - це FD 1
* стандартний потік помилок - це FD 2

Нові файлові дескриптори можна задати або створити за допомогою команди `exec` та операторів перенаправлення.

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

Ця техніка може здатися досить заплутаною, але вона буває дуже корисною, коли наш скрипт запускає якийсь інший програмний пакет, а стандартний вивід автоматично перехоплюється цим пакетом.
Команда `bats`, яку використовують для запуску модульних тестів у цьому треку, працює саме так: `bats` перехоплює stdout і stderr тесту, але налагоджувальні повідомлення, надіслані у FD 3, показуються в терміналі.
~~~~

## Підсумок

Для чого потрібне перенаправлення?

* Збереження виводу: зберігати результати команди для подальшого перегляду чи обробки.
* Журналювання: перехоплювати повідомлення про помилки для налагодження.
* Автоматизація: поєднувати команди в ланцюжки, використовуючи вивід однієї як ввід іншої.
* Фільтрування: відкидати непотрібний вивід.
* Пакетна обробка: обробляти дані з файлів, а не вводити їх вручну.
* Написання скриптів: перенаправлення необхідні для написання надійних скриптів оболонки.

Перенаправлення в оболонці дають змогу тонко керувати тим, як програми працюють із даними, і будувати складні робочі процеси та ефективно керувати інформацією.
