# Вступ

Регулярні вирази - це надзвичайно універсальний спосіб _зіставляти рядки тексту зі шаблоном_, використовуючи предметно-орієнтовану мову (DSL), розроблену саме для цієї мети.

Багато можливостей роботи з регулярними виразами вбудовано в Base R, і ми можемо побачити приклади в старішому коді.

Для нового коду _наполегливо_ рекомендується використовувати бібліотеку [`stringr`][web-stringr].

Як зазначено в [концепції «Strings»][concept-strings], `stringr` має хорошу документацію, зазвичай написану автором (або авторами) пакета.

- [Довідковий вебсайт][web-stringr]
- [Шпаргалка][cheat-stringr].
- [Розділ про рядки тексту][book-strings] та [розділ про регулярні вирази][book-regex] у книзі «R for Data Science».

Багато функцій, уже розглянутих у [концепції `Strings`][concept-strings], призначені для пошуку за регулярними виразами як стандарт.

Ми зробили концепцію Strings відносно простою, зіставляючи лише з рядковими літералами, але замість цього можна використати будь-який шаблон регулярного виразу.

Формально регулярний вираз у R створюється викликом [`regex()`][ref-regex].
Для зручності функції `stringr` вважатимуть будь-який рядок тексту зі шаблоном за регулярний вираз.
У наведеному нижче прикладі перший `str_replace_all()` - це синтаксичний цукор для другої версії:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[Шпаргалка][cheat-stringr] - корисний посібник: усі функції з аргументом `pattern` (надрукованим червоним) приймають регулярний вираз, а сторінка 2 підсумовує синтаксис регулярних виразів.

Зауважмо, що функція [`regex()`][ref-regex] усе ще може бути важливою, якщо потрібно перевизначити типові значення, як-от чутливість до регістру чи локаль.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

Багато кодів регулярних виразів містять зворотну скісну риску, як-от `\s`, використаний вище.
У звичайних рядках тексту R `\` потрібно екранувати, подвоївши його, звідси `"\\s"`.

Зворотні скісні риски можуть розмножуватися й заплутувати, тож у складних випадках може допомогти використання [необроблених рядків][book-raw].

Типово синтаксис для визначення необробленого рядка - `r"( )"`, але дозволені й інші роздільники.
Оскільки круглі дужки `( )` і квадратні дужки `[ ]` однаково поширені в синтаксисі регулярних виразів (для груп захоплення та груп опцій), фігурні дужки `{ }` можуть бути хорошим вибором.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## Виявлення збігів

Ось кілька запитань і функцій, які можуть допомогти знайти на них відповіді.

Деякі приклади використовують `fruit` - вектор із 80 назв фруктів, включений у `stringr` для практики.

_Чи містить рядок тексту збіг?_
`str_detect()`, або `str_starts()`, `str_ends()`, щоб уникнути використання прив'язок `^` чи `$`.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_Повернути лише рядки тексту, що містять збіг?_
Використаймо `str_subset()`, щоб отримати рядки тексту, і `str_which()`, щоб отримати індекси.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_Скільки збігів у кожному рядку тексту?_
Скористаймося `str_count()`.

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_Де розташований збіг?_
`str_view()` для інтерактивного використання, `str_locate()` чи `str_locate_all()` для загальніших випадків.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## Захоплення

Часто ми хочемо знати, _що_ саме збігається. 
Це досягається включенням груп захоплення в круглі дужки всередині регулярного виразу.

У межах одного регулярного виразу можна посилатися на захоплення назад, використовуючи `\1`, `\2` тощо.
Наприклад, пошук повторюваних пар літер:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

За схожим синтаксисом захоплення можна використовувати в рядках тексту для заміни:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

Збираймо збіги для подальшої обробки за допомогою функції `str_match()` лише для першого збігу, або `str_match_all()` для всіх збігів.

Групи захоплення зазвичай дають складні вихідні дані будь-якою мовою.
Підхід R (_який до того ж векторизований, що додає складності_) - згенерувати матрицю з `str_match()`, де один рядок припадає на кожен вхідний рядок тексту, стовпець 1 містить повний рядок зі збігом, а решта стовпців - різні групи захоплення.

Використання іменованих груп може бути перевагою, оскільки вони стають назвами стовпців у матриці результатів.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

~~~~exercism/note
Ми небагато розповіли про матриці в цьому силабусі, хоч є [документ концепції][concept-matrices-arrays], до якого можна звернутися.
Матриці погано вписуються в екосистему Tidyverse, попри те, що давно є частиною Base R.

Коротко: поводьмося з матрицями як з векторами з двома індексами, у порядку `[rows, cols]`.
Залишмо будь-який з індексів порожнім, щоб отримати весь рядок чи весь стовпець.

Коли ми отримуємо один рядок `r` за допомогою `m[r,]` або один стовпець `c` за допомогою `m[,c]`, повернене значення типово сплющується у вектор.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```
~~~~

Неминуче `str_match_all()` дає вихідні дані з ще складнішою структурою:

- Результат - список, по одному елементу на кожен вхідний рядок тексту.
- Якщо вхідний рядок тексту лише один, розберемо вихідні дані на частини за допомогою індексації `[[1]]`, як описано в [концепції «Lists»][concept-lists].
- Кожен елемент - матриця, зі стовпцями як для `match()`.
- Кожен рядок у матриці - успішне захоплення.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

Звісно, збіги можуть не знаходитися.
Тоді результатом буде спеціальне значення `NA`.
Будьмо готові перевіряти це, як описано в [концепції «Nothingness»][concept-nothingness].

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
