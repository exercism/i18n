# Тести

Один зі способів розвʼязувати вправи Exercism - зайти на сайт і скористатися редактором у браузері, де можна редагувати й тестувати своє рішення.

Або ж вправи можна завантажити на свій локальний компʼютер, де ми використовуємо власний редактор і набір інструментів, щоб створити, протестувати і зрештою надіслати рішення.

Для цього потрібен інтерфейс командного рядка Exercism, або CLI, застосунок, що працює в терміналі чи вікні командного рядка. Інструкції зі встановлення можна знайти тут: [Документація Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally).

## Підхід до тестування
Exercism припускає, що в нас уже є певний досвід розробки через тестування. Кожна вправа складається з _`stub file`_, _`test file`_ із серією заздалегідь написаних тестів і _`test script`_, який використовується для запуску тестів.

Щоб розвʼязати вправу, потрібно поступово доповнювати _`stub file`_ кодом, який зрештою проходитиме всі тести.

На практиці це означає, що ми будемо активно редагувати і _`stub file`_, і _`test file`_. Зауважмо: _`test file`_ редагується не для того, щоб змінити тестовий код, а щоб закоментувати тести, які не проходять.

Спочатку всі тести, крім одного, будуть закоментовані, а потім, у міру просування _`stub file`_ до робочого рішення, ми будемо розкоментовувати дедалі більше тестів, доки всі тести не почнуть проходити успішно.

## Інфраструктура тестування
Додаткового програмного забезпечення встановлювати не потрібно, адже компоненти тестувального фреймворку вже входять до завантаженої вправи.

Тестувальний фреймворк складається з трьох файлів Rexx, які під час тестування обʼєднуються з рішенням вправи в модуль тестового коду; цей модуль виконує _`test script`_, а результати тестів виводяться в терміналі.

Будь ласка, не редагуйте і не видаляйте _`test script`_ чи будь-який інший файл тестувального фреймворку. Якщо ж це сталося через ґремлінів, просто завантажте вправу заново через Exercism CLI, подбавши про збереження коду рішення.

## Запуск тестів
Розвʼязання вправи відбувається так:

1. Відкрийте термінал
2. Завантажте обрану вправу
3. Перейдіть до каталогу вправи
4. Завантажте stub-файл і тестовий файл у свій редактор
5. Ітеративно:

    1. Запускайте тестовий скрипт
    2. Пишіть код у stub-файлі (поступово перетворюючи його на файл рішення) і коментуйте / розкоментовуйте тести у тестовому файлі

6. Коли всі тести пройдуть, надішліть рішення на Exercism
7. Закрийте термінал
8. Відсвяткуйте свій успіх

Конкретний приклад у терміналі Linux із вправою `acronym` (припустімо, робочий простір Exercism розташовано в `/home/exercism`)

Завантажте вправу:

`exercism download --track=rexx --exercise=acronym`

Перейдіть до каталогу вправи:

`cd /home/exercism/rexx/acronym`

З іншого вікна, можливо, з графічним інтерфейсом, завантажте у свій редактор `acronym.rexx` і `acronym-check.rexx`, тобто stub-файл і тестовий файл відповідно.

Запустіть тестовий скрипт: `./test-acronym`

і всі тести мають провалитися:

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Закоментуйте всі тести, крім першого, у файлі `acronym-check.rexx` і знову запустіть тестовий скрипт; у результаті має бути такий вивід:

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

Доопрацьовуйте `acronym.rexx`, доки він не міститиме робочий код, і зрештою вивід від запуску тестового скрипта має стати таким:

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

Далі розкоментуйте решту тестів, знову запустіть тестовий скрипт, і зрештою вивід має стати таким:

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Тепер можна надіслати рішення вправи:

`exercism submit acronym.rexx`

і отримати ще один бал репутації. Коли все готово, закрийте термінал.

Для користувача MacOS процес буде досить схожим, адже це операційна система, похідна від UNIX.

Для користувачів Windows процес загалом схожий, але є кілька дрібних відмінностей:

- Роль термінала виконує вікно _Command Prompt_.
- У шляхах зворотні слеші замінюють прямі, тож робочий каталог може мати такий вигляд:

  `cd C:\Users\MyName\exercism\rexx\acronym`

- Тестовий скрипт запускається так:

  `test-acronym`  або  `test-acronym.bat`

Вивід тестів буде однаковий.
