# Вступ

У версії Go 1.18 зʼявилася підтримка **дженериків**.
Дженерики дають змогу писати функції та структури даних, які працюють з різними типами без дублювання коду.

## Навіщо потрібні дженерики?

У Go функції та типи зазвичай працюють з конкретними типами, такими як `int` чи `string`.
До появи дженериків ми мали два варіанти підтримки кількох типів.
По-перше, можна було написати кілька функцій з різними назвами, наприклад `SumInts` і `SumFloats`.
Такий підхід створює дубльований код, який важко підтримувати.
По-друге, можна було скористатися порожнім інтерфейсом `any` (`interface{}`).
Однак порожній інтерфейс усуває перевірки типів під час компіляції та вимагає перевірок типу під час виконання.
Дженерики розвʼязують цю проблему: вони забезпечують типову безпеку й водночас дають змогу уникнути дублювання коду.

## Дженерик-функції

Ми визначаємо дженерик-функцію, додавши **параметри типу** в квадратних дужках `[...]` після назви функції.
Ось приклад дженерик-функції, яка повертає перевернутий зріз:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

У цьому прикладі `T` - параметр типу.
`T` можна уявляти собі як заповнювач для справжнього типу.
Ключове слово `any` у квадратних дужках - це **обмеження типу**.
Обмеження каже компілятору, які типи дозволені для `T`.
Тут `any` означає, що `T` може бути будь-якого типу.

### Виклик дженерик-функцій

Ми можемо викликати дженерик-функцію, передавши справжній тип у квадратних дужках.
Цей справжній тип називають **аргументом типу**.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

У більшості випадків компілятор Go сам визначає тип з аргументів функції.
Ця можливість називається **виведенням типу**.
Завдяки виведенню типу не потрібно писати аргумент типу в квадратних дужках.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

У цьому прикладі компілятор бачить, що `words` має тип зрізу рядків тексту (англ. string), тому робить висновок, що `T` має тип `string`.

## Обмеження типів

Кожен параметр типу повинен мати обмеження.
Обмеження визначає, які типи можна використовувати як аргументи типу.
Обмеження також визначає операції, які дозволено виконувати над значеннями цього типу.

### Обмеження `any`

Обмеження `any` дозволяє будь-який тип.
У Go `any` - це псевдонім порожнього інтерфейсу `interface{}`.
Оскільки `any` дозволяє кожен тип, функція може виконувати лише ті операції, які працюють з усіма типами Go.
Наприклад, якщо ми маємо два значення `any`, у яких зберігаються зрізи, їх не можна порівнювати за допомогою `==`, бо зрізи не можна порівнювати через `==`.

### Обмеження `comparable`

Go надає вбудоване обмеження `comparable`.
Обмеження `comparable` дозволяє будь-який тип, який підтримує оператори `==` і `!=`.
До порівнюваних типів належать булеві значення (англ. Boolean), числа, рядки тексту, вказівники, канали, а також структури чи масиви, складені з порівнюваних типів.

Ось приклад функції, яка перевіряє, чи містить зріз певний елемент:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Оскільки `T` використовує обмеження `comparable`, вираз `elem == target` коректний.
Якщо замінити `comparable` на `any`, компілятор повідомить про помилку.

### Власні обмеження через набори типів в інтерфейсах

Починаючи з Go 1.18, інтерфейси можуть визначати набори типів окрім методів.
Символ вертикальної риски `|` дозволяє перелічити в інтерфейсі типи, які дозволені.

```go
type Number interface {
    int | int64 | float64
}
```

Тепер `Number` можна використовувати як обмеження для функції:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Оскільки всі типи в `Number` підтримують оператор `*`, Go дозволяє `value * 2` усередині функції.

### Наближення базового типу за допомогою `~`

Іноді ми створюємо власний тип на основі примітивного типу:

```go
type MyInt int
```

Обмеження `Number`, визначене вище, дозволяє лише точні типи `int`, `int64` і `float64`.
Якщо передати значення `MyInt` у `Double`, компілятор видасть помилку, бо `MyInt` не збігається з `int`.
Щоб дозволити будь-який тип, базовим типом якого є `int`, додамо тильду `~` перед типом:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

Тепер `Double` можна використовувати зі значеннями типу `MyInt`.

### Обмеження `cmp.Ordered`

Стандартна бібліотека надає обмеження `cmp.Ordered` у [пакеті `cmp`][doc-cmp].
Обмеження `cmp.Ordered` дозволяє будь-який тип, який підтримує оператори порівняння `<`, `<=`, `>` і `>=`.

## Дженерик-типи

За допомогою параметрів типу можна також визначати дженерик-типи, наприклад структури.
Ось приклад дженерик-структури даних `Stack`:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Оголошуючи змінну дженерик-типу, ми повинні вказати аргумент типу в квадратних дужках:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

Виведення типу працює лише для дженерик-функцій.
Створюючи значення дженерик-типу, аргумент типу потрібно вказувати завжди.

## Коли використовувати дженерики

Дженерики - це потужна можливість, але їх не обовʼязково застосовувати до кожної задачі.

Використовуймо дженерики в таких ситуаціях:
- Ми будуємо структури даних, як-от дерева, звʼязані списки чи кеші, що працюють з будь-яким типом елементів.
- Ми пишемо допоміжні функції, які працюють зі зрізами чи мапами будь-якого типу, наприклад фільтрування, сортування чи пошук.
- Нам потрібна та сама реалізація для кількох типів, і ми хочемо мати типову безпеку під час компіляції.

Натомість інтерфейси варто використовувати в таких ситуаціях:
- Нам важлива поведінка і методи, а не базовий тип даних.
  Наприклад, якщо ми хочемо читати й обробляти дані з різних джерел (файлів, мережі, TTY), варто використати `func Process(src io.Reader)`, а не `func Process[T](src T)`.
- Різні типи потребують різних реалізацій методів для своєї роботи.
