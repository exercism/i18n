# Доповнення до інструкцій

## Завдання

Реалізуйте дві процедури.

- `custom_error_message message` спричиняє помилку, а `message` - це текст помилки.
- `handle_error script` запускає переданий скрипт і повертає рядок тексту (англ. string), який описує, що сталося:

  | Коли скрипт…                      | повертає                |
  | --------------------------------- | ----------------------- |
  | ділить на нуль                    | `"division by zero"`    |
  | відкриває файл, якого не існує    | `"file does not exist"` |
  | викликає процедуру, якої не існує | `"proc does not exist"` |
  | спричиняє будь-яку іншу помилку   | `"unknown error"`       |
  | завершується успішно              | `"success"`             |

## Спричинення помилок

У Tcl є дві команди, щоб спричинити помилку.

```tcl
error "something went wrong"
throw {MYAPP BADTHING} "something went wrong"
```

`throw` вимагає _код помилки_ як перший аргумент.
Код помилки - це список, який підказує обробнику, яка саме помилка сталася, тож він може відреагувати, не розбираючи текст повідомлення.
Його вміст ми обираємо самі: `{MYAPP BADTHING}` - лише приклад, і підійде будь-який непорожній список.
За домовленістю він іде від загального до конкретного.
Обробник перехоплює його за допомогою відповідного шаблону `try ... trap` (описано нижче), наприклад `trap {MYAPP BADTHING}`, або `trap {MYAPP}`, щоб перехопити будь-яку помилку `MYAPP`.
`error` приймає необовʼязковий код помилки як третій аргумент: `error message ?info? ?code?`.

## Обробка помилок за допомогою `catch`

[`catch`][catch] запускає скрипт і замість того, щоб спричинити помилку, повертає ціле число - _код завершення_:

| код | значення   |
| --- | ---------- |
| 0   | `ok`       |
| 1   | `error`    |
| 2   | `return`   |
| 3   | `break`    |
| 4   | `continue` |

```tcl
if {[catch {expr {1 / 0}} result options] == 1} {
    puts "error message: $result"
    puts "error code:    [dict get $options -errorcode]"
}
```
```none
error message: divide by zero
error code:    ARITH DIVZERO {divide by zero}
```

Необовʼязковий другий аргумент отримує результат (або текст помилки).
Необовʼязковий третій аргумент отримує _словник параметрів_, у якому є `-errorcode` та `-errorinfo` (трасування стека).

Переваги:

- Він компактний і гнучкий.
- Він короткий для простих випадків, як-от `if {[catch {open $f} fh]} {...}`.

Недоліки:

- Код завершення доводиться перевіряти самостійно.
  Необачний `if {[catch ...] != 0} { handle error }` вважає помилками також `return`, `break` і `continue`.
- Помилки, які ми не обробили, зникають безслідно, якщо не спричинити їх повторно.
- Немає вбудованого способу виконати код очищення незалежно від того, чи скрипт зазнав невдачі.

## Обробка помилок за допомогою `try`

[`try`][try] запускає скрипт і передає результат першому відповідному обробнику.
Необовʼязковий блок `finally` виконується завжди, тож це гарне місце, щоб звільнити ресурси, як-от файлові канали.

```tcl
set fh [open $filename r]
try {
    set data [read $fh]
} on error {msg options} {
    puts "could not read $filename: $msg"
} finally {
    close $fh
}
```

Переваги:

- Структура зрозуміла: окремий обробник для кожного типу результату.
- `finally` виконується завжди.
- Результати, яким не відповідає жоден обробник, передаються тому, хто викликав, без змін.

Недоліки:

- Для простих випадків він трохи багатослівніший, ніж `catch`.

### `try ... on` проти `try ... trap`

Є два різновиди обробників.

`on code {msgVar optionsVar}` відповідає _коду завершення_: `ok`, `error`, `return`, `break` або `continue`.
Кожна помилка має код завершення `error`, тож `on error` не відрізнить ділення на нуль від відсутнього файлу.
Доведеться дивитися на текст повідомлення, а це ненадійно: повідомлення призначені для людей і можуть змінюватися між версіями Tcl.

```tcl
try {
    expr {$a / $b}
} on error {msg} {
    if {[string match "*divide by zero*" $msg]} { ... }
}
```

`trap pattern {msgVar optionsVar}` відповідає _коду помилки_.
Обробник спрацьовує, коли шаблон є префіксом списку `-errorcode`.
Так різновид помилки визначається надійно.

```tcl
try {
    expr {$a / $b}
} trap {ARITH DIVZERO} {} {
    puts "division by zero"
} trap {} {msg} {
    puts "some other error: $msg"
}
```

Порожній шаблон, `trap {}`, відповідає будь-якій помилці.
Обробники перевіряються по черзі, тож загальний обробник ставте останнім.

## Як знайти код помилки

Де задокументовано `ARITH DIVZERO`?
Переважно лише у вихідному коді, але Tcl покаже його нам.
Після помилки глобальна змінна `errorCode` містить код найостаннішої помилки:

```none
$ tclsh
% set a 1; set b 0
% expr {$a / $b}
divide by zero
% set errorInfo     ;# this is the stack trace
divide by zero
    while executing
"expr {$a / $b}"
% set errorCode     ;# this is what we're after
ARITH DIVZERO {divide by zero}
```

Усередині програми його можна взяти зі словника параметрів:

```tcl
try {
    expr {$a / $b}
} on error {msg options} {
    puts [dict get $options -errorcode]
}
```

Останній елемент коду помилки часто є зрозумілим для людини повідомленням або назвою того, що спричинило помилку.
Не додавайте його до шаблону `trap`: перехоплюйте `{ARITH DIVZERO}`, а не `{ARITH DIVZERO {divide by zero}}`.

### Деякі поширені коди помилок

Ця таблиця неповна.
Скористайтеся наведеним вище прийомом, щоб знайти код будь-якої іншої помилки.

| Ситуація                         | Приклад             | Код помилки               |
| -------------------------------- | ------------------- | ------------------------- |
| Ділення на нуль                  | `expr {1 / 0}`      | `ARITH DIVZERO ...`       |
| Помилка області визначення       | `expr {sqrt(-1)}`   | `ARITH DOMAIN ...`        |
| Файл не знайдено                 | `open nosuchfile r` | `POSIX ENOENT ...`        |
| Доступ заборонено                | `open /root/x w`    | `POSIX EACCES ...`        |
| Невідома команда                 | `no::such::proc`    | `TCL LOOKUP COMMAND name` |
| Невідома змінна                  | `set nosuchvar`     | `TCL LOOKUP VARNAME name` |
| Неправильна кількість аргументів | `string length a b` | `TCL WRONGARGS`           |
| Некоректний словник              | `dict size {1 2 3}` | `TCL VALUE DICTIONARY`    |
| Некоректний список               | `llength "a \{b"`   | `TCL VALUE LIST ...`      |

Коди помилок `POSIX` використовують назви `errno` операційної системи, як-от `ENOENT`, `EACCES` та `EEXIST`.

## Підказка: де виконується скрипт

`handle_error` отримує скрипт від того, хто його викликав.
Якщо запустити його через `try $script`, він обчислюється в області видимості `handle_error`, а не того, хто викликав.
Щоб обчислити його там, де його написано, скористайтеся [`uplevel`][uplevel]: `try {uplevel 1 $script} ...`.
