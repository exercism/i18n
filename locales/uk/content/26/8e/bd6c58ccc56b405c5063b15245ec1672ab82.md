# Докладно

У Go 1.18 зʼявилася підтримка **дженериків**.
Дженерики дають змогу писати функції та структури даних, які працюють із різними типами, не дублюючи код.

## Навіщо потрібні дженерики?

У Go функції та типи зазвичай працюють із конкретними типами, наприклад `int` або `string`.
До появи дженериків було два варіанти підтримати кілька типів.
По-перше, можна було написати кілька функцій із різними назвами, наприклад `SumInts` і `SumFloats`.
Такий підхід породжує дубльований код, який важко підтримувати.
По-друге, можна було скористатися порожнім інтерфейсом `any` (`interface{}`).
Однак порожній інтерфейс прибирає перевірки типів на етапі компіляції і вимагає перевірок типу під час виконання.
Дженерики розвʼязують цю проблему: вони забезпечують безпеку типів і водночас дають змогу уникнути дублювання коду.

## Дженеричні функції

Щоб визначити дженеричну функцію, ми додаємо **параметри типу** у квадратних дужках `[...]` після назви функції.
Ось приклад дженеричної функції, яка повертає обернений слайс:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

У цьому прикладі `T` виступає параметром типу.
`T` можна уявити як заповнювач для справжнього типу.
Ключове слово `any` у квадратних дужках - це **обмеження типу**.
Обмеження вказує компілятору, які типи дозволені для `T`.
Тут `any` означає, що `T` може бути будь-якого типу.

### Виклик дженеричних функцій

Дженеричну функцію можна викликати, передавши справжній тип у квадратних дужках.
Такий справжній тип називають **аргументом типу**.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

У більшості випадків компілятор Go сам визначає тип з аргументів функції.
Ця можливість називається **виведенням типу**.
Завдяки виведенню типу писати аргумент типу в квадратних дужках не потрібно.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

У цьому прикладі компілятор бачить, що `words` має тип слайс рядків тексту (англ. string), і виводить, що `T` дорівнює `string`.

## Обмеження типів

Кожен параметр типу повинен мати обмеження.
Обмеження визначає, які типи можна використовувати як аргументи типу.
Воно також визначає операції, які дозволено виконувати над значеннями цього типу.

### Обмеження `any`

Обмеження `any` дозволяє будь-який тип.
У Go `any` - це псевдонім порожнього інтерфейсу `interface{}`.
Оскільки `any` дозволяє будь-який тип, функція може виконувати лише ті операції, які працюють для всіх типів Go.
Наприклад, якщо два значення `any` містять слайси, їх не можна порівняти за допомогою `==`, бо слайси не підтримують порівняння через `==`.

### Обмеження `comparable`

Go має вбудоване обмеження `comparable`.
Обмеження `comparable` дозволяє будь-який тип, який підтримує оператори `==` і `!=`.
До порівнюваних типів належать булеві значення (англ. Boolean), числа, рядки тексту, вказівники, канали, а також структури чи масиви, складені з порівнюваних типів.

Ось приклад функції, яка перевіряє, чи містить слайс певний елемент:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Оскільки `T` використовує обмеження `comparable`, вираз `elem == target` коректний.
Якщо замінити `comparable` на `any`, компілятор повідомить про помилку.

### Власні обмеження за допомогою множин типів в інтерфейсах

Починаючи з Go 1.18, інтерфейси можуть визначати не лише методи, а й множини типів.
Можна використати символ вертикальної риски `|`, щоб перелічити дозволені типи в інтерфейсі.

```go
type Number interface {
    int | int64 | float64
}
```

Тепер `Number` можна використати як обмеження для функції:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Оскільки всі типи в `Number` підтримують оператор `*`, Go дозволяє вираз `value * 2` усередині функції.

### Наближення базового типу `~`

Іноді ми створюємо власне визначення типу на основі примітивного типу:

```go
type MyInt int
```

Обмеження `Number`, визначене вище, дозволяє лише точні типи `int`, `int64` і `float64`.
Якщо передати значення `MyInt` у `Double`, компілятор видасть помилку, бо `MyInt` не збігається з `int`.
Щоб дозволити будь-який тип, базовий тип якого дорівнює `int`, додамо тильду `~` перед типом:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

Тепер `Double` можна використовувати зі значеннями типу `MyInt`.

### Обмеження `cmp.Ordered`

Стандартна бібліотека надає обмеження `cmp.Ordered` у [пакеті `cmp`][doc-cmp].
Обмеження `cmp.Ordered` дозволяє будь-який тип, який підтримує оператори порівняння `<`, `<=`, `>` і `>=`.

## Дженеричні типи

Параметри типу можна використовувати й для визначення дженеричних типів, наприклад структур.
Ось приклад дженеричної структури даних `Stack`:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Коли ми оголошуємо змінну дженеричного типу, потрібно вказати аргумент типу в квадратних дужках:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

Виведення типу працює лише для дженеричних функцій.
Створюючи значення дженеричного типу, аргумент типу доводиться вказувати завжди.

## Коли використовувати дженерики

Дженерики дають чимало можливостей, але застосовувати їх до кожної задачі не потрібно.

Дженерики варто використовувати в таких ситуаціях:
- Ми створюємо структури даних, як-от дерева, звʼязані списки чи кеші, які працюють з будь-яким типом елементів.
- Ми пишемо допоміжні функції, які працюють зі слайсами або мапами будь-якого типу, як-от фільтрування, сортування чи пошук.
- Нам потрібна та сама реалізація для кількох типів, і ми хочемо безпеки типів на етапі компіляції.

Натомість інтерфейси варто використовувати в таких ситуаціях:
- Нам важлива поведінка й методи, а не базовий тип даних.
  Наприклад, якщо ми хочемо читати й обробляти дані з різних джерел (файлів, мережі, TTY), краще використати `func Process(src io.Reader)`, а не `func Process[T](src T)`.
- Різним типам потрібні різні реалізації методів, щоб виконати свою роботу.
