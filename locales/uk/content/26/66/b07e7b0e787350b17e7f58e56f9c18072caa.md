# Про

## Символи

[Кодування символів][char-encoding] - це певна угода, яка використовується для подання елементів тексту природною мовою як послідовності байтів.
«Елементом тексту» тут може бути будь-яка одиниця, що має значення в природній мові, наприклад літери, пробіли, розділові знаки, емодзі, ідеограми тощо.

NASM (The Netwide Assembler, асемблер, який використовується в цьому треку) має підтримку визначення даних за допомогою [ASCII][ascii].

Символьні константи в NASM можуть бути завдовжки до 8 байтів і можуть визначатися за допомогою одинарних лапок (`'`), подвійних лапок (`"`) або зворотних лапок (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Спеціальні символи потрібно визначати у зворотних лапках і екранувати за допомогою `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASM також має підтримку [символів Unicode][unicode] у [UTF-8][utf8], які задаються за допомогою `\u` або `\U` і в зворотних лапках:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

Зауважмо, що в x86-64 немає вбудованої підтримки жодного кодування символів як окремого типу.
Дані в асемблері - це послідовність байтів, а те, як тлумачити ці байти (як символ, число чи щось інше), вирішує сам програміст.

Наприклад, символ ASCII '0' займає один байт зі значенням 48.
Отже, зберегти 48 у байт можна точно так само, як зберегти символ ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

З цієї ж причини робота з символами полягає в безпосередньому перетворенні значень у цих байтах:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Рядки

[Рядок тексту][string] (англ. string) - це послідовність символів.
В асемблері його зазвичай реалізують як масив.

У NASM рядок можна оголосити так само, як оголошують будь-який масив:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Одна з відмінностей рядків від інших масивів полягає в тому, що NASM також підтримує оголошення рядків без коми (`,`), яка розділяє значення.
Також можна чергувати значення з комами:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Зауважмо, що, як уже згадувалося, символи - це просто байти (або послідовність байтів у кодуванні Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Оскільки кожен символ ASCII займає один байт, будь-який наступний байт у ширшому розмірі дорівнює `0`.
Наприклад, оголошення `'a'` як qword (8 байтів) означає, що перший байт - це `'a'` (`97`), а всі решта сім байтів дорівнюють `0`.

З цієї причини всі вони еквівалентні:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
В асемблері рядки не завершуються автоматично символом ASCII NUL (значення `0`).

Під час взаємодії з мовами вищого рівня, як-от C, саме програміст відповідає за те, щоб у кінці рядка було додано правильний термінатор, якщо він узагалі потрібен.
~~~~

## Рядкові інструкції

Оскільки рядки - це масиви, з ними можна працювати так само, як з будь-яким масивом, явно розіменовуючи памʼять:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Крім того, існують інструкції для завантаження, переміщення та збереження значень у послідовностях байтів у памʼяті.
Хоча їх називають _рядковими інструкціями_, їх можна використовувати з будь-якою послідовністю байтів у памʼяті, тобто з будь-яким масивом:

| інструкція   | що вона робить                                                                                                    |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | завантажує значення з комірки памʼяті, на яку вказує `rsi`, у `rax`                                               |
| [stos][stos] | зберігає значення з `rax` у комірку памʼяті, на яку вказує `rdi`                                                  |
| [movs][movs] | копіює значення з комірки памʼяті, на яку вказує `rsi`, і зберігає його в комірці памʼяті, на яку вказує `rdi`    |
| [cmps][cmps] | порівнює значення в комірці памʼяті, на яку вказує `rsi`, зі значенням у комірці памʼяті, на яку вказує `rdi`     |
| [scas][scas] | порівнює значення в `rax` зі значенням у комірці памʼяті, на яку вказує `rdi`                                     |

Зауважмо, що ці інструкції _не_ приймають жодного явного операнда.
Їхні операнди неявні.

Як правило:

1. Якщо операнд-джерело вказує на комірку памʼяті, її адресу слід зберігати в `rsi` (`s` від англ. source).
2. Якщо операнд-призначення вказує на комірку памʼяті, її адресу слід зберігати в `rdi` (`d` від англ. destination).
3. Якщо один з операндів не вказує на комірку памʼяті, то це регістр `rax`.

Зауважмо, що ці інструкції автоматично розіменовують адреси памʼяті відповідно до конкретної операції, яку вони виконують.

Усі вони можуть працювати з різними розмірами.
Щоб указати цей розмір, додають суфікс:

| суфікс | що означає | розмір  |
| :----: | ---------- | :------ |
|  `b`   | байт       | 1 байт  |
|  `w`   | слово      | 2 байти |
|  `d`   | dword      | 4 байти |
|  `q`   | qword      | 8 байтів |

Наприклад:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

Вони також зсувають кожну задіяну адресу на розмір операції.
Це оновлення відбувається відповідно до значення **прапорця напрямку (DF)**:

- Якщо `DF` скинуто, адреси _збільшуються_ на розмір операції.
- Якщо `DF` встановлено, адреси, навпаки, _зменшуються_ на ту саму величину.

ABI System V вимагає, щоб прапорець напрямку було скинуто на вході у функцію.
Отже, _типова поведінка полягає в тому, що читання й запис памʼяті відбуваються в порядку зростання адрес_.

Інструкцію [cld][cld] можна використати, щоб скинути прапорець напрямку, а інструкцію [std][std] - щоб його встановити:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Той, хто викликає, очікує, що `DF` буде скинуто після повернення з будь-якої викликаної функції, згідно з ABI System V.
Якщо ми колись встановлюємо `DF`, потрібно подбати про те, щоб скинути його перед `ret`.
~~~~

### Lods

Ця інструкція _читає_ з комірки памʼяті, адреса якої міститься в `rsi`, і копіює значення в `rax`.

Значення в `rsi` змінюється на кількість прочитаних байтів:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

Ця інструкція копіює значення з `rax` і _записує_ його в комірку памʼяті, адреса якої міститься в `rdi`.

Значення в `rdi` змінюється на кількість записаних байтів:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

Ця інструкція _читає_ з комірки памʼяті, адреса якої міститься в `rsi`, і _записує_ значення в комірку памʼяті, адреса якої міститься в `rdi`.
Ця інструкція не впливає на значення в `rax`.

І `rsi`, і `rdi` змінюються на кількість байтів, скопійованих з однієї комірки памʼяті в іншу:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

Ця інструкція _читає_ з комірки памʼяті, адреса якої міститься в `rsi`, а також _читає_ з комірки памʼяті, адреса якої міститься в `rdi`.
Потім вона порівнює ці значення й оновлює прапорці, як це робить `cmp`.

І `rsi`, і `rdi` змінюються на кількість байтів, прочитаних з обох комірок:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

Ця інструкція порівнює значення в `rax` зі значенням, яке вона _читає_ з комірки памʼяті, адреса якої міститься в `rdi`.
Потім вона оновлює прапорці, як це робить `cmp`.

Значення в `rdi` змінюється на кількість прочитаних байтів:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

Крім них, інструкція [rep][rep] безпосередньо не взаємодіє з памʼяттю.
Натомість її можна додати як префікс до інших згаданих інструкцій, _повторюючи_ їх.

З префіксом `rep` рядкові інструкції повторюються стільки разів, скільки вказано в `rcx`.
Щоразу значення в `rcx` зменшується на `1`.
Зауважмо, що значення в `rcx` потрібно встановити перед використанням інструкції:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

Крім використання `rcx` як лічильника, `repe` (або `repz`) і `repne` (або `repnz`) припиняють виконання, якщо `zero flag (ZF)` скинуто або встановлено відповідно:

| інструкція      | куди можна додати      | чи може зупинитися раніше   |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`, `lods`, `stos` | ні                      |
| `repe`,`repz`    | `cmps`, `scas`         | так, зупиняється, коли ZF дорівнює 0 |
| `repne`, `repnz` | `cmps`, `scas`         | так, зупиняється, коли ZF дорівнює 1 |

~~~~exercism/advanced
На сучасних процесорах `rep movs` і `rep stos` зазвичай є швидким варіантом, коли потрібно перемістити великі блоки даних.
Проте інші рядкові інструкції, і навіть `movs` і `stos` під час роботи без `rep`, зазвичай повільніші за звичайний цикл.

Докладніше про це можна прочитати в [розділі 16.9 «String instructions» цієї довідкової книги][agner-optimization-guide].
