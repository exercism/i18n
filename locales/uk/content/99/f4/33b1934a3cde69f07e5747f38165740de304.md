# Вступ

Літерали - це фіксовані значення, які використовують безпосередньо в коді.
Вони не потребують жодних обчислень під час виконання програми.
Вони бувають різних форм, щоб ефективно подавати різні типи даних.
Найчастіше трапляються числові літерали, але є й літеральні оператори для типів дати, часу та рядків тексту (англ. string).
У пізнішому концепті ми побачимо, як можна використовувати літеральні оператори, визначені користувачем.

## Числові літерали

Числові літерали охоплюють десяткове, вісімкове, шістнадцяткове та двійкове подання.
Про ці основи вже йшлося в [концепті чисел][numbers-concept].

Усі подання, як-от `23`, `0x50f7ba11` та `0xba5eba11`, компілятор розуміє як `int`.
Загальний тип `int` є знаковим і (залежно від компілятора та системи) часто має діапазон від `-2'147'483'648` до `2'147'483'647`.
Цього здебільшого достатньо, і нам не потрібно перейматися конкретним типом.

Деякі задачі вимагають більших діапазонів або дуже малого обсягу памʼяті для програм.
Щоб указати це явно, можна прямо вказати конкретний тип цілого числа разом із числовим літералом.

Коли відʼємні числа не потрібні, але потрібен додатковий діапазон, використовують суфікс `u` або `U` для _беззнакових_ цілих чисел.
Для більших діапазонів можна використати `L` або навіть `LL` для типів long і long long.

~~~~exercism/caution
Використовувати малу `l` дозволено, але її легко сплутати з числом `1`, тому це не рекомендується.
~~~~

```cpp
auto net_worth_christian_grey{2'500'000'000U}; // out of range for 32-bit integers
auto net_worth_carlisle_cullen{46'000'000'000LL}; // int and uint are not enough
```

Числа з плаваючою комою під час компіляції зазвичай набувають типу `double`.
Це вдалий типовий варіант, а задачі з вужчим типом `float` трапляються рідше, ніж приклад із беззнаковим числом вище.

~~~~exercism/advanced
[Стандарт C++23][cpp23-literals] запроваджує точніший контроль за допомогою таких літералів, як `f128` чи `F16`.
Деякі компілятори дозволяють власні літерали.
GCC дозволяє використовувати `d` як літерал, але стандарт цього не передбачає, і це може завадити кросплатформній сумісності.

[cpp23-literals]: https://en.cppreference.com/w/cpp/language/floating_literal

~~~~

```cpp
auto light_year_in_m{9.46073e+15f}; // well in the range of float
auto earth_to_edge_comoving_distance_in_nm{4.32355e+32}; // needs double type for magnitude
auto eulers_number{2.718281828459045}; // needs double type for precision
```

## Символьні та рядкові літерали

В інших концептах уже використовували символьні літерали в одинарних лапках, як-от `'}'` чи `'@'`.

У C++ `char` обмежений першими 128 [кодами символів ASCII][ascii-code].
Щоб використати кілька символів ASCII або розширені символи ASCII, як-от `‰`, чи навіть символи Unicode, як-от `麗` та `ẞ`, потрібні інші типи.
У попередньому концепті рядкові літерали було представлено з _подвійними лапками_: `"一体どういう意味ですか。C++です"`.
Фактичний тип цієї японської фрази - `const char (&)[46]`, рядок у стилі C.

Використання рядкових літералів не вмикається автоматично.
Щоб скористатися літералом _рядка_ `""s` або літералом _string-view_ `""sv`, потрібно явно вказати їх використання через відповідний простір імен:

```cpp
#include <string>
#include <string_view>

using namespace std::literals;

auto green_light{"무궁화 꽃 이 피었 습니다"};
// green_light type is const char (&)[36]
auto umbrella{"달고나"s};
// umbrella type is std::basic_string<char>, the same as std::string
auto il_nam{"보는 것이 하는 것보다 더 재미있을 수가 없지"sv};
// il_nam type is std::basic_string_view<char>
```

_String_view_ можна розглядати як посилання на константний рядок.
