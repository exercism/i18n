# Вступ

Звʼязування описує, звідки в коді можна отримати доступ до ідентифікатора.
Значення з областю видимості блоку, функції або прототипу функції не мають звʼязування.
Це означає, що до них не можна звернутися ззовні їхньої області видимості.
Докладніше про область видимості дивіться в [концепції області видимості](../scope/introduction.md#Introduction).

## Зовнішнє звʼязування

Ідентифікатори з областю видимості файлу типово мають зовнішнє звʼязування.
Ідентифікатор із зовнішнім звʼязуванням можна викликати з будь-якого файлу програми.

## Внутрішнє звʼязування

Ідентифікатору з областю видимості файлу можна надати внутрішнє звʼязування за допомогою специфікатора `static`.
Ідентифікатор із внутрішнім звʼязуванням можна використовувати лише в межах його файлу.

Наприклад

```c
int public_count = 0; // file scope, external linkage by default
static int private_count = 0;  // file scope, internal linkage 

// file scope, internal linkage
static void some_function()
{
    // code snipped
}

// file scope, external linkage by default
int main()
{
    // code snipped
}
```

Статичне звʼязування не варто плутати зі статичною тривалістю зберігання.
Докладніше про статичну тривалість зберігання дивіться в [концепції тривалості зберігання](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#static-the-storage-specifier-not-to-be-confused-with-the-static-linkage-type).
