# Докладніше

Оголошення `MACRO:` - це слово, *тіло* якого виконується під час компіляції. Тіло бере літеральні аргументи зі стека часу компіляції й повинно залишити на ньому один quotation. Далі компілятор підставляє цей quotation замість виклику макросу, тож програма під час виконання ніколи не бачить макросу, лише код, який він породив.

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- compound )
    dup append ;
```

Якщо написати виклик `[ 1 + ] twice`, компілятор виконає тіло, маючи `[ 1 + ]` на стеку, отримає назад `[ 1 + 1 + ]` і вставить його на місце виклику. Жодних накладних витрат під час виконання немає, адже цикл або комбінатор, який замінив макрос, просто зник.

## Вхідні дані мають бути літералами

Оскільки тіло виконується під час компіляції, кожне вхідне значення в місці виклику має бути *літералом*: quotation `[ … ]`, число, масив, рядок тексту (англ. string). Передати нелітеральне значення (те, яке відомо лише під час виконання) не можна: це помилка часу компіляції.

```factor
! works: [ 1 + ] is a literal quotation
: inc-twice ( x -- y ) [ 1 + ] twice ;

! refused: f is a literal, but the macro can't run with a non-quotation
! input where the body expects to call `append` on it
```

## Структурні вхідні дані зумовлюють структурні вихідні дані

Цікаві макроси приймають *структуру* (масив, літеральну послідовність пар) і породжують код, форма якого залежить від цієї структури. `each-literal` із цієї вправи приймає літеральну послідовність і quotation та для кожного елемента породжує окрему копію quotation, частково застосовану й убудовану в код. Програма під час виконання - це прямолінійний код, без `each` і без диспетчеризації на кожен елемент, а перебирання послідовності відбулося повністю під час компіляції.

## Чому проблеми з гігієною не виникає

Макроси в Lisp борються з *гігієною*: макрос, який уводить локальне імʼя, може зіткнутися з іменами в місці виклику, і тоді доводиться брати `gensym` або систему гігієни. У Factor такої проблеми немає, бо quotation складаються з *розвʼязаних посилань на слова*: кожне слово шукається під час розбору, а не символічно під час розкриття. `dup` усередині quotation, побудованого макросом, завжди буде `kernel:dup`, хоч би які імена існували в місці виклику.

Ціна цього: макроси Factor не вміють уводити нові звʼязування так, як це вміє `defmacro`. Вони будують код зі слів, які парсер уже бачив. Для більшості завдань метапрограмування цього достатньо.

## Суміжні форми (тут не використовуються)

- `MACRO::` - варіант `MACRO:` із локальними змінними, так само як `::` - форма `:` із локальними змінними. Стає в пригоді, коли тіло звертається до своїх вхідних даних більше ніж один раз.
- `<< … >>` - блок обчислення під час розбору. Виконує звичайний код Factor під час компіляції без вимоги повернути quotation. Стає в пригоді, коли треба обчислити значення, яке має існувати вже під час розбору (наприклад, `CONSTANT:`, виведений з пошуку в середовищі).
- `SYNTAX:` - *слова розбору*. Це зовсім інша річ: вони працюють із потоком токенів парсера, а не зі значеннями, і виконуються на ще ранішій фазі. Ними визначають новий літеральний синтаксис (`T{ }`, `H{ }`). Ця тема виходить за межі цього концепту.
- `functor:` - декларативні шаблони, які породжують набори споріднених слів з однієї специфікації. Побудовані на макромеханізмі; це царина авторів бібліотек.
