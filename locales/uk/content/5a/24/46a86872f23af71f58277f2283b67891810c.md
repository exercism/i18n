# Вступ до here-документів

У сценаріях Bash «here-документ» (або «heredoc») спрямовує кілька рядків вводу до команди чи програми, ніби ми вводимо їх безпосередньо в терміналі.
Це потужний інструмент для вбудовування багаторядкового тексту у сценарії без потреби у зовнішніх файлах чи складному опрацюванні рядків тексту (англ. string).

## Ключові особливості та синтаксис

1. Роздільник: here-документ починається з оператора `<<`, за яким іде слово-роздільник (його часто називають «маркером» або «термінатором»).
   Це слово може бути будь-яким, але для ясності зазвичай беруть щось на кшталт `EOF`, `END` чи `TEXT`.
   Для читабельнішого коду можна взяти описове слово, наприклад `END_INSTALLATION_INSTRUCTIONS`.

1. Вміст: після початкового `<< DELIMITER` пишемо вміст, який хочемо спрямувати.
   Це можуть бути кілька рядків тексту, коду чи будь-чого іншого.

1. Завершення: here-документ закінчується, коли слово-роздільник знову зʼявляється на окремому рядку, без пробілів на початку чи в кінці.

## Базовий синтаксис

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## Як це працює

* Bash читає всі рядки між початковим `<< DELIMITER` і кінцевим `DELIMITER`.
* Bash зʼєднує цей вміст зі стандартним вводом команди.
* Команда опрацьовує цей ввід, ніби він надходить із клавіатури.

### Приклад 1: простий вивід тексту

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

Вивід:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

У цьому прикладі:

* `cat` - це команда.
* `<< EOF` починає here-документ, а `EOF` виступає роздільником.
* Три рядки тексту - це вміст.
* `EOF` на окремому рядку завершує here-документ.
* Після цього `cat` виводить отриманий вміст.

### Приклад 2: використання з wc (підрахунок слів)

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

Вивід:

```plaintext
3
```

Тут `wc -l` рахує кількість рядків.
Here-документ надає ці три рядки як ввід.

### Приклад 3: передавання даних у сценарій

Сценарій:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

Викличмо сценарій з інтерактивного запрошення bash за допомогою here-документа:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

Вивід:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## Варіації та розширені можливості

### Буквальний вміст

Bash виконує розкриття змінних, підстановку команд і арифметичне розкриття всередині here-документа.
У цьому сенсі here-документи поводяться як рядки тексту в подвійних лапках.

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

Вивід:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

Коли роздільник узято в лапки (одинарні чи подвійні), ці розкриття не виконуються.
Вміст сприймається буквально.
Це як рядки тексту в одинарних лапках.

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

Вивід:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### Видалення провідних символів табуляції

Якщо використати `<<-` (з дефісом у кінці) замість `<<`, Bash прибирає всі провідні _символи табуляції_ з кожного рядка here-документа.
Це зручно, коли треба зробити відступи для вмісту here-документа всередині сценарію, не впливаючи на вивід.

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

Вивід друкується з усіма видаленими провідними табуляціями:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
Автор не радить користуватися цим прийомом.
Хоча він може поліпшити читабельність сценарію,

1. легко випадково замінити символи табуляції пробілами (редактор може зробити це автоматично), і 
1. різницю між пробілами й табуляціями важко помітити.
~~~~

## Коли використовувати here-документи

* Багаторядковий ввід: коли треба передати команді кілька рядків тексту.
* Файли конфігурації: вбудовування невеликих фрагментів налаштувань у сценарій.
* Генерування коду: створення коду на льоту всередині сценарію.
* Взаємодія зі сценаріями: імітація вводу користувача для інтерактивних програм.
* Уникнення зовнішніх файлів: коли не хочеться створювати тимчасові файли.

Типове застосування - надати текст довідки:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## Можливі недоліки

* Великі вбудовані документи ускладнюють читання коду.
  Краще розгортати сценарій із документацією в окремих файлах.
* Here-документи можуть порушувати плин коду.
  Можна опинитися в глибоко вкладеній ділянці коду, коли треба передати програмі якийсь текст.
  Відступи here-документа можуть мати різкий вигляд порівняно з навколишнім кодом.

## Here-рядки

Як і here-документи, _here-рядки_ (або «herestrings») надають ввід команді.
Але якщо here-документи задаються блоком тексту, то here-рядки - одним рядком тексту.
Here-рядки використовують синтаксис `<<< "text"`.

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

Вивід:

```plaintext
UPPER CASE THIS STRING
```

На відміну від here-документів, кінцевий роздільник не потрібен.

### Навіщо використовувати here-рядки?

Замість here-рядка можна використати конвеєр:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

То навіщо використовувати here-рядок?

Уявімо випадок, коли рядок тексту є виводом тривалого обчислення, і цей результат треба подати двом окремим командам.
З конвеєрами доведеться виконати обчислення двічі:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

Ефективніший підхід - зберегти вивід обчислення (за допомогою підстановки команд) і подати його як ввід двом наступним командам за допомогою here-рядків:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

Ось реальний приклад такого застосування:

* зберегти відповідь JSON на запит до REST API (що розбитий на сторінки),
* передати дані JSON програмі jq, щоб розібрати результати й вивести їх у файл, а потім
* передати дані JSON іншій програмі jq, щоб визначити URL наступного запиту.

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

Звернімо увагу на позицію перенаправлення виводу.
Увесь вивід циклу `while` буде дописано до файлу `data.csv`.

## Here-документи й here-рядки як перенаправлення

Оскільки це лише різновиди перенаправлення, їх можна поєднувати з іншими операціями перенаправлення:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## Підсумок

Here-документи (або «heredocs») - гнучкий і зручний спосіб керувати багаторядковим вводом у сценаріях Bash.
Вони спрощують вбудовування тексту й даних безпосередньо у сценарії, роблячи їх самодостатнішими й легшими для читання.

Here-рядки (або «herestrings») схожі на here-документи, але мають простіший і динамічніший синтаксис.
