# Інструкції

Ми пишемо код для системи даних у цеху заводу з виробництва автомобільних деталей.
Компоненти двигунів і шасі проходять через низку станцій механічної обробки.
Кожна станція видає вимірювання, які потрібно поєднати, порівняти, відкалібрувати чи нормалізувати, перш ніж запуститься наступний етап.
Функції, які ми тут реалізуємо, відповідають по одній на кожну станцію.

~~~~exercism/note
Обчислення в цій вправі слід виконувати за допомогою SIMD-інструкцій, а не скалярних операцій.
~~~~

## 1. Поєднати випуск із двох ліній

У цеху працюють дві паралельні складальні лінії.
Наприкінці кожної зміни обидві лінії повідомляють свій випуск для 4 контейнерів деталей як числа одинарної точності.
Панель керування майстра показує сумарний випуск для кожного контейнера, тож два звіти додаються контейнер за контейнером.
Усі три буфери керуються системою звітності й завжди вирівняні на 16 байтів.

Визначте функцію `sum_yields`, яка приймає випуск для кожного контейнера з `line_a` і `line_b` й записує суму за контейнерами в `result`.
Аргументи, у порядку:

1. `line_a`: адреса памʼяті, вирівняна на 16 байтів, що містить 4 32-бітові числа з плаваючою комою
2. `line_b`: адреса памʼяті, вирівняна на 16 байтів, що містить 4 32-бітові числа з плаваючою комою
3. `result`: адреса памʼяті, вирівняна на 16 байтів, куди функція запише 4 32-бітові числа з плаваючою комою

Ця функція не має поверненого значення; натомість результат зберігається в переданому буфері (`result`):

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. Обчислити масштабоване відхилення

Між операціями станція відбору проб вимірює оброблені деталі й порівнює їх із цільовими розмірами.
Виміряні значення надходять потоком із прецизійного вимірювача в буфер, який завжди вирівняний на 16 байтів.
Цільові значення надходять із пакета робочого замовлення, для якого вирівнювання не гарантовано.
Відхилення множиться на коефіцієнт чутливості для кожної осі, перш ніж його передадуть у наступний перевіряльник допусків.
На цьому етапі наступний перевіряльник читає відхилення безпосередньо з SIMD-регістра, а не з памʼяті.

Визначте функцію `scaled_deviation`, яка приймає `measured`, `target` і `sensitivity` й записує масштабоване відхилення в `result`.
Аргументи, у порядку:

1. `measured`: адреса памʼяті, вирівняна на 16 байтів, що містить 2 64-бітові числа з плаваючою комою
2. `target`: адреса памʼяті, що містить 2 64-бітові числа з плаваючою комою (вирівнювання не гарантоване)
3. `sensitivity`: адреса памʼяті, що містить 2 64-бітові числа з плаваючою комою (вирівнювання не гарантоване)
4. `result`: адреса памʼяті для буфера, куди функція запише 2 64-бітові числа з плаваючою комою (вирівнювання не гарантоване)

Масштабоване відхилення обчислюється як `(measured - target) * sensitivity` для кожної доріжки.

Ця функція не має поверненого значення; натомість результат зберігається в переданому буфері (`result`) як пара 64-бітових чисел з плаваючою комою.

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. Відкалібрувати партію

Перш ніж деталі потраплять у відсік фінального контролю, виміри розмірів із партії з 4 деталей перераховуються в подвійну точність і виправляються з урахуванням відомого температурного дрейфу.

4 первинні виміри надходять як числа одинарної точності.
Для кожного рядка з 2 вимірів калібрування обчислює `reference / (raw - offset)`, а потім множить цей результат на сталий коефіцієнт перетворення `0.5`.

Зауважте, що `reference` та `offset` однакові для обох рядків партії.
Коефіцієнт перетворення однаковий за кожного калібрування, тож замість того щоб приймати його як аргумент, його слід оголосити як упаковану 16-байтову константу в памʼяті.

Визначте функцію `calibrate_batch`, яка приймає партію `raw`, `reference`, `offset` і буфер `result` й записує відкалібровані значення в `result`.
Аргументи, у порядку:

1. `raw`: адреса памʼяті, що містить 4 32-бітові числа з плаваючою комою (вирівнювання не гарантоване)
2. `reference`: адреса памʼяті, вирівняна на 16 байтів, що містить 2 64-бітові числа з плаваючою комою
3. `offset`: адреса памʼяті, вирівняна на 16 байтів, що містить 2 64-бітові числа з плаваючою комою
4. `result`: адреса памʼяті, вирівняна на 16 байтів, куди функція запише 4 64-бітові числа з плаваючою комою (32 байти загалом)

Для кожного з двох рядків партії функція має:

1. Перетворити 2 первинні значення одинарної точності рядка на подвійну точність.
2. Відняти `offset` від перетвореної пари.
3. Поділити `reference` на результат.
4. Поелементно помножити кожне 64-бітове число з плаваючою комою на сталий коефіцієнт перетворення `0.5`.
5. Зберегти 2 64-бітові числа з плаваючою комою у відповідні 16 байтів `result`.

Ця функція не має поверненого значення; натомість результат зберігається в переданому буфері (`result`):

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. Нормалізувати оцінки вздовж лінії

Наприкінці лінії кожна деталь має оцінку якості, яку потрібно нормалізувати, перш ніж її буде звітовано.
Кожна оцінка множиться на власний коефіцієнт підсилення для деталі, а потім ділиться на виробничий масштаб для осі.
Буфер `gains` містить по одному коефіцієнту підсилення на деталь.

Виробничий масштаб однаковий для всього запуску й передається в адресі памʼяті, що містить два 64-бітові числа з плаваючою комою.
Оцінки оновлюються **на місці**: той самий буфер, який містив первинні оцінки, тепер містить нормалізовані оцінки.

Визначте функцію `normalize_scores`, яка приймає масив `scores`, масив `gains`, `scale` і лічильник `n` й нормалізує оцінки на місці.
Аргументи, у порядку:

1. `scores`: адреса памʼяті, вирівняна на 16 байтів, що містить `n` 64-бітових чисел з плаваючою комою (змінюється на місці)
2. `gains`: адреса памʼяті, вирівняна на 16 байтів, що містить `n` 64-бітових чисел з плаваючою комою
3. `scale`: адреса памʼяті, вирівняна на 16 байтів, що містить 2 64-бітові числа з плаваючою комою
4. `n`: додатне парне 64-бітове ціле число (мінімум `2`), кількість оцінок для нормалізації

Дві доріжки масштабу застосовуються до двох елементів кожної пари.
Перша доріжка масштабує перший елемент кожної пари (доріжки на парних позиціях), друга доріжка масштабує другий (доріжки на непарних позиціях).
Кожна оцінка множиться на відповідний коефіцієнт підсилення, а потім ділиться на відповідну доріжку масштабу: `score * gain / scale_lane`.

Ця функція не має поверненого значення; натомість результат зберігається у вхідному буфері (`scores`), на тій самій позиції відповідної оцінки `score`, яку було нормалізовано:

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
