# Вступ

Коли в Gleam ми зіставляємо значення зі зразком, маємо переконатися, що зразки відповідають кожному можливому значенню типу, інакше код не скомпілюється.

Цю функцію буде відхилено, оскільки вона не обробила випадок, коли масив порожній:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Здебільшого в програмах на Gleam ми хочемо обробити кожен можливий випадок, але в деяких програмах, як-от прототипи та швидкі скрипти, ми можемо хотіти зосередитися лише на щасливому шляху й не писати код для інших випадків. Ось тут і стає в пригоді `let assert` у Gleam.

З let assert зразок може відповідати лише деяким можливим значенням типу, і якщо зразок не відповідає значенню, програма аварійно завершиться. Використовуючи `let assert`, ми можемо записати наведену вище функцію так:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Бібліотеки Gleam ніколи не повинні використовувати let assert, оскільки вони можуть аварійно завершити програму. Натомість вони повинні використовувати тип `Result` і дозволити розробнику застосунку вирішувати, як обробляти помилки.
