# Вступ

Як і багато інших мов, C++ має _вказівники_.
Ми вже знаємо, що _посилання_ та _вказівники_ схожі між собою, але уявімо вказівники як рівень, ближчий до внутрішньої будови компʼютера.
_Вказівники_ - це змінні, які зберігають адреси обʼєктів.
Їх використовують, щоб безпосередньо взаємодіяти з обʼєктами, а це дає змогу динамічно виділяти памʼять та ефективно працювати з даними в C++.

Якщо ми тільки починаємо працювати з _вказівниками_, вони можуть здаватися трохи загадковими, але щойно ми до них звикнемо, вони стануть цілком зрозумілими.

Це важлива частина C++, тож приділімо їм достатньо часу, щоб справді їх зрозуміти.
Найпростіший варіант, про який ідеться в цьому концепті, ще називають _дурним вказівником_ або _сирим вказівником_.
У сучасному C++ є також _розумні вказівники_, а базовий тип зовсім не розумний, тож усю роботу доведеться виконувати вручну.

Перш ніж заглиблюватися в деталі, варто зрозуміти, навіщо потрібні _вказівники_.
_Вказівники_ дають змогу поділитися адресою обʼєкта з іншими частинами нашої програми, і це корисно з двох основних причин:

1. Як і _посилання_, вказівники уникають копіювання та допомагають зменшити обсяг ресурсів, які споживає наша програма.
1. На відміну від _посилань_, вказівники можна перепризначати на інші обʼєкти.
1. Вказівники також можуть указувати на нульове значення, щоб позначити, що зараз вони не вказують на жоден обʼєкт.

## Загальний синтаксис

Оголошення вказівника в C++ передбачає вказівку типу даних, на який вказує вказівник, потім зірочку (`*`) і назву вказівника.
Коли ми оголошуємо вказівники, вони не ініціалізуються автоматично.
Без явного присвоєння вказівник зазвичай містить невизначене значення, яке часто називають «сміттєвою адресою».
Хоча деякі компілятори можуть ініціалізувати вказівники значенням `nullptr`, така поведінка гарантована не для всіх компіляторів, тож покладатися на неї не варто.
Найкраще явно ініціалізувати сирі вказівники й перевіряти, що вони не дорівнюють null, перш ніж їх використовувати, щоб уникнути можливих проблем.

```cpp
int* ptr{nullptr}; // Declares a pointer and makes sure it is not invalid
```

Щоб присвоїти вказівнику адресу змінної, ми використовуємо оператор взяття адреси (`&`).
Розіменування вказівника виконують за допомогою _оператора розіменування_ (`*`).

```cpp
std::string opponent{"Solomon Lane"};
// 'ethan' points to the address of the string opponent
std::string* ethan{&opponent};
// Instead of ethan's, the opponent's name address is given to the passPort
std::string passportName{*ethan};
```

Звернімо увагу: розіменування потрібно виконувати явно, тоді як _посилання_ просто працювали як псевдонім.

## Арифметика вказівників

_Арифметика вказівників_ дає змогу виконувати арифметичні операції над вказівниками, що особливо корисно під час роботи з масивами.
Додавання цілого числа до вказівника змушує його вказувати на інший елемент.

```cpp
// Stargate Coordinate Code
int gateCode[] = {462, 753, 218, 611, 977};
// 'ptr' points to the first element of 'gateCode'
int* ptr{&gateCode[0]};
// Accesses the third Stargate address through pointer arithmetic
int dialedAddress{*(ptr + 2)};
// Chevron encoded! Dialing Stargate address:
openStarGate(dialedAddress);
```

~~~~exercism/caution
Арифметика вказівників у C++ може легко призвести до __невизначеної поведінки__, якщо поводитися з нею необережно.
Невизначена поведінка може проявлятися як несподівані результати роботи програми, збої або навіть уразливості в системі безпеки.
Один сумнозвісний приклад наслідків невизначеної поведінки стався 1996 року під час [вибуху ракети Ariane 5][ariane-flight-v88], коли програмний виняток, спричинений перетворенням 64-бітного числа з плаваючою комою в 16-бітне знакове ціле число, призвів до катастрофічної відмови.

[ariane-flight-v88]: https://en.wikipedia.org/wiki/Ariane_flight_V88

## Доступ до змінних-членів

У C++ оператор `->` використовують, щоб отримати доступ до членів обʼєкта через вказівник на цей обʼєкт.
Це скорочений запис, який спрощує доступ до членів обʼєктів, на які вказують вказівники.
Наприклад, якщо `ptr` - це вказівник на обʼєкт зі змінною-членом `x`, то замість `(*ptr).x` можна одразу написати `ptr->x`.
Цей оператор підвищує читабельність коду й робить його менш багатослівним, коли ми працюємо з вказівниками на обʼєкти.

Ось короткий приклад зі _структурою_ `Superhero`, яка має змінну-член `superpower`.
Функція `main` створює вказівник `dianaPrince` на обʼєкт `Superhero` (який уособлює Диво-жінку).
Оператор `->` використовують для доступу до змінної-члена `superpower`, демонструючи культове «Ласо істини» Диво-жінки.

```cpp
struct Superhero {
    std::string superpower;
};
Superhero wonder_woman{};
Superhero* dianaPrince = &wonder_woman;
dianaPrince->superpower = "Lasso of Truth";
// Using the -> operator to access member variable superpower:
std::cout << "Wonder Woman, possesses the mighty " << dianaPrince->superpower;
// Memory cleanup:
delete dianaPrince;
```

## Вказівники проти посилань

І вказівники, і посилання дають змогу звертатися до обʼєктів опосередковано, але вони різняться своїми можливостями й тим, наскільки вони безпечні.
Вказівники дають гнучкість: їх можна переспрямовувати на інший обʼєкт і присвоювати їм null.
Однак ця гнучкість несе й ризики, наприклад розіменування нульових вказівників або створення висячих вказівників.
Посилання ж не можуть бути нульовими й одразу після створення привʼязуються до дійсних обʼєктів, тож цих ризиків не виникає.
Оскільки посилання безпечніші, їм варто віддавати перевагу над вказівниками, якщо тільки не потрібні додаткові можливості, які дають вказівники.
