# Функції в `jq`

У `jq` можна визначати власні **функції**, щоб інкапсулювати потрібну нам логіку.
_Функції_ поводяться так само, як вбудовані: вони приймають вхідні дані та видають нуль, одні або більше вихідних даних.

## Визначення функції

Визначити _функцію_ в `jq` можна за таким синтаксисом:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- починається з ключового слова `def`,
- двокрапка перед тілом функції,
- тіло складається з одного виразу,
- завершується крапкою з комою,
- як і в решті синтаксису `jq`, можна довільно розставляти пробіли для читабельності.

## Де розміщувати функції

_Функції_ потрібно визначити до того, як їх використати: ось це помилка:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Отже, _функції_ слід розміщувати на початку коду `jq`, перед «головним» виразом.

### Вкладені функції

_Функції_ можна вкладати:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Тут _функція_ `B` видима лише в тілі `A`.

## Область видимості

_Функція_ створює нову **область видимості** для змінних і вкладених функцій.

## Аргументи

**Аргументи** _функції_ розділяються _крапками з комою_, а не комами.
Наприклад, _функція_, яка приймає число, а потім додає число й множить на число:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
Крапки з комою потрібні, бо кома в `jq` вже має своє призначення: це оператор, який зʼєднує потоки.

Якщо замість крапки з комою поставити кому, `jq` спробує зробити два виклики _функції_ `add_mul` з _одним аргументом_, якої не існує, тож перший же виклик зазнає невдачі:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

Кома в `5, 4` зʼєднує числа 5 і 4 в потік.
Коли ми викликаємо функцію з потоком як аргументом, `jq` викличе цю функцію кілька разів, по одному на кожне значення в потоці.
Це приклад «неявної ітерації», притаманної потокам `jq`.
`10 | add_mul(5, 4)` рівнозначний такому запису.

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
Тепер зрозуміло, звідки береться помилка `add_mul/1 is not defined`.
~~~~

<!-- prettier-ignore-end -->

### Аргументи - це _вирази_

_Аргументи_ функції - це фільтри, а не значення.
У цьому сенсі вони поводяться подібно до того, що в інших мовах називають функціями зворотного виклику:

Візьмімо функцію `add_mul` за приклад:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

Що ж тут відбувається?

- аргумент `adder` отримує _вираз_ `. + 5`
  - коли функція виконує `. + adder`, це перетворюється на `. + . + 5`
  - це дає 25, оскільки `. == 10`
- так само аргумент `multiplier` є виразом `. - 2`
  - це дає 8
  - тоді результат `25 * 8 == 200`

### Аргументи як значення

Іноді потрібно «матеріалізувати» _аргумент_ у змінну:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Для цього є скорочений запис:

```jq
def my_func($arg):
    other stuff ...
;
```

Зауважмо, що це лише «синтаксичний цукор»: імʼя `arg` без `$` усе ще перебуває в області видимості _функції_.

<!-- prettier-ignore -->
~~~~exercism/caution
Наприклад, я написав щось таке, щоб розвʼязати вправу:

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

і я був здивований, що кожне значення масиву дорівнювало ключу.

Сталося це тому, що `jq` побачив функцію `equals` як

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

**Аргумент** `code` _перекрив_ раніше визначену **функцію** `code`.
Тобто `(. | code)` просто видає **аргумент**, а не обчислює новий код на основі вхідного значення.
Отже, `$this_code` і `$code` завжди були однакові.
~~~~

<!-- prettier-ignore-end -->

## Арність

_Функції_ мають **арність**, тобто кількість _аргументів_, які вони приймають.

_Функції_ можуть мати однакове імʼя з різною _арністю_.
Вбудована функція [`range`][man-range] це демонструє: `range/1`, `range/2` і `range/3` співіснують.

Це буває корисно для визначення рекурсивних функцій, які переносять стан через аргументи.
Наприклад, `map` _можна_ було б реалізувати так:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Рекурсія

`jq` виконує оптимізацію хвостових викликів, але лише для функцій з арністю 0.

## Модулі

Модуль `jq` - це файл, який містить лише функції.
Модулі підключаються до програми `jq` командами [`include`][man-include] або [`import`][man-import].
