# Вступ

У C++ оголошення часто відокремлені від визначень.
Оголошення згруповані в так звані заголовні файли, а відповідні реалізації розміщено у файлах вихідного коду.
Заголовні файли можна уявляти собі як API.
Заголовний файл розповість, _що_ пропонує кодова база, не заглиблюючись у подробиці _як_.

## Заголовні та вихідні файли

Найпоширеніше розширення для заголовних файлів - `.h`.
Деякі проєкти використовують `.hpp` або взагалі обходяться без розширення.

Визначення розміщені в окремому файлі `.cpp`.
Щоб знову поєднати частини, вихідний файл починається з _підключення_ відповідного заголовного файлу.

Якщо ми хочемо написати бібліотеку під назвою «quick_math», яка пропонує функцію «super_root», яку ми хочемо часто використовувати, файли матимуть такий вигляд:

```cpp
// A file named quick_math.h
#pragma once
namespace quick_math {
    double super_root(double x, int n);
}
```

```cpp
// A file named quick_math.cpp
#include "quick_math.h"
#include <cmath>
double quick_math::super_root(double x, int n) {
    while(n) { x = std::sqrt(x), --n;}
    return x;
}
```

Якщо потрібно підключити заголовок, який використовує лише реалізація, то відповідний рядок `#include` знадобиться лише у файлі вихідного коду.
Усе, що підключено в заголовку, також доступне у файлі `.cpp`, як-от бібліотека `string` у прикладі нижче.
**Увага**: символ `;` потрібен після оголошення в заголовному файлі, але не після визначення у файлі вихідного коду.

## Класи та заголовки

Класи можуть ставати дуже складними, і їхній звʼязок із поділом на заголовки та вихідний код може заплутувати.
Один із можливих варіантів компонування - тримати всі подробиці реалізації у файлі вихідного коду, а всі оголошення та змінні-члени **-** у заголовку:

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0);
            void give_water();
            std::string get_name();
            int get_size();
            void start_next_day();
    };
}
#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"
robots::Flower::Flower(std::string name, int size) {this->name = "Robotica " + name; this->size = size;}
void robots::Flower::start_next_day() {if (!needs_water) ++size; needs_water = true;}
std::string robots::Flower::get_name() {return name;}
int robots::Flower::get_size() {return size;}
```

Коли заголовок використовують як огляд API, саме там шукатимуть таку інформацію, як типові значення.
Тому типове значення параметра `size` конструктора задають у заголовку, а не в реалізації.
Визначення у файлі вихідного коду мають префікс із простору імен `robots` та типу класу `Flower`.

Ще один варіант компонування - бібліотека _лише із заголовком_, яка взагалі не має файлу `.cpp`:

```cpp
// A file named robot_flower.h
#pragma once
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0) {this->name = "Robotica " + name; this->size = size;}
            void give_water() {needs_water = false;}
            std::string get_name() {return name;}
            int get_size() {return size;}
            void start_next_day() {if (!needs_water) ++size; needs_water = true;}
    };
}
```

Проєкти можуть поєднувати ці варіанти компонування, і точаться чималі дискусії про те, що найкраще підходить для кожного випадку.

## Захист від повторного включення

Можливо, ми помітили рядок `#pragma once` у наведеному вище прикладі заголовного файлу.
Це називається захистом від повторного включення. Він гарантує, що вміст файлу підключається під час компіляції лише один раз, щоб уникнути помилок.
Існує ще один, складніший різновид захисту від повторного включення, який починається з `#ifndef` і закінчується `#endif`.
Він слугує тій самій меті, і його застосування показано в наведеному вище прикладі класу `Flower`.
