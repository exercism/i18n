# Сортування

```sather
   numbers.sort;                                  -- the natural order
   words.insertion_sort_by(bind(before(_, _)));   -- an order you supply
```

## Що потрібно `sort`

`sort` вимагає, щоб тип елемента мав `is_lt`. `INT`, `STR`, `CHAR`,
`FLTD` та `INTI` його мають. А от власний клас його не має, доки ми не
напишемо відповідний.

`insertion_sort_by` не вимагає від типу елемента нічого: усе, що йому
потрібно знати, міститься в процедурі, яку ми йому передаємо.

## Яким має бути порівняння

Процедура має задавати узгоджений порядок, інакше результат не визначено:

- якщо `before(a, b)` — правда, то `before(b, a)` має бути неправдою;
- якщо `a` стоїть перед `b`, а `b` перед `c`, то `a` стоїть перед `c`;
- `before(a, a)` має бути неправдою.

Саме на останньому найчастіше спотикаються. Якщо написати `<=` замість
`<`, це означає, що річ стоїть перед самою собою, і сортування з такою
умовою може видати будь-що.

## Рівні елементи

Ані `sort`, ані `insertion_sort_by` не є **стабільними**: елементи, які
порівняння називає рівними, можуть вийти в будь-якому порядку, і в цій
бібліотеці вони зазвичай виходять у зворотному.

Тож прийом із сортуванням двічі, коли спершу впорядковуємо за назвою,
а потім за очками й сподіваємося, що команди з однаковою кількістю очок
залишаться в алфавітному порядку, тут не працює. Так само не варто
покладатися на порядок вхідних даних.

Якщо рівні елементи важливі, розвʼязуймо це **у самому порівнянні**.
Зробімо його повним порядком, щоб жодні два різні елементи ніколи не
вважалися рівними:

```sather
   shorter(a, b : STR) : BOOL is
      if a.size /= b.size then return a.size < b.size; end;
      return a < b;                  -- same length: alphabetical
   end;
```

Це варто робити навіть тоді, коли здається, що рівних елементів не може
бути. Порівняння, яке в обидва боки відповідає неправдою, залишає
результат невизначеним, а помилка проявляється як порядок, що змінюється
без жодної видимої причини.

## Інші

| Виклик | Що робить |
| --- | --- |
| `a.sort` | на місці, природний порядок, нестабільне |
| `a.insertion_sort_by(lt)` | на місці, власний порядок, стабільне |
| `a.is_sorted` | перевірка |
| `a.is_sorted_by(lt)` | перевірка за власним порядком |
| `a.binary_search(e)` | пошук у відсортованому масиві |
| `a.binary_search_by(e, lt)` | пошук за власним порядком |

`binary_search` на невідсортованому масиві не зазнає невдачі, а видає
безглуздий результат. Його передумова прямо про це й говорить, а
передумови не перевіряються, якщо компілятору не передати `-chk`.

## Вартість

Сортування вставками виконує роботу, пропорційну квадрату довжини, що
нормально для турнірної таблиці з десятка команд і неприйнятно для
десяти тисяч записів. `ARR_SORT_ALG::sort_by` втілює ту саму ідею у
варіанті швидкого сортування, для випадків, коли масив великий і
стабільність не має значення.
