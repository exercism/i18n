# Виняток

В ідеальному світі все працює бездоганно.
Але в реальному світі щось може піти не так, і те, як ми поводимося в таких ситуаціях, визначає, чи буде наше програмне забезпечення стійким і надійним.
Винятки - це ключове поняття в програмуванні, яке дає нам змогу коректно обробляти помилки та непередбачувані ситуації.

Якщо помилку не обробити, вона зупинить програму й виведе повідомлення про помилку.
У більшості випадків ми не хочемо, щоб програма зупинялася, коли виникає помилка; натомість ми хочемо обробити цю помилку й далі виконувати програму.

## Викидання винятку

У Crystal винятки викидають за допомогою ключового слова `raise`, якому можна передати або `String`, або обʼєкт `Exception`.
Якщо їх не обробити, програма зупиниться й надрукує повідомлення про помилку.

```crystal
raise "This is an error"
```

У Crystal є кілька вбудованих винятків, як-от `ArgumentError`, `IndexError`, `KeyError`, `IOError`, `SystemCallError`, `TypeError`, `ZeroDivisionError` та багато інших.
Для них потрібно передати повідомлення.

```crystal
raise ArgumentError.new("This is an argument error")
```

## [Обробка винятків][exception-handling]

Ми ж не хочемо, щоб наша програма аварійно завершувалася, коли виникає виняток.
Тому, коли ми знаємо, що якась частина коду схильна до помилок, ми можемо обгорнути її в блок `begin` і перехопити виняток блоком `rescue`.
Блок `begin` позначає початок коду, який може викинути виняток, а блок `rescue` обробляє цей виняток.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
end
```

У блоці `rescue` також можна вказати змінну, щоб отримати обʼєкт винятку.

```crystal
begin
 raise "This is an error"
rescue ex
 puts "An error occurred: #{ex.message}"
end
```

У блоці `rescue` також можна вказати конкретний тип винятку, щоб перехопити лише його.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
end

# or

begin
 raise ArgumentError.new("This is an argument error")
rescue ex : ArgumentError
 puts "An argument error occurred: #{ex.message}"
end
```

Можна використовувати кілька блоків `rescue`, щоб обробити різні типи винятків.
У наведеному нижче прикладі перший блок `rescue` перехопить `ArgumentError`, а другий блок `rescue` перехопить будь-який інший виняток.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
rescue
 puts "An error occurred!"
end
```

Блок `begin` також може мати блок `else`, який виконується, якщо виняток не виник.

```crystal
begin
 puts "No error occurred"
rescue
 puts "An error occurred!"
else
 puts "No error occurred"
end
```

І нарешті, є блок `ensure`, який виконується завжди, незалежно від того, чи виник виняток.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
ensure
 puts "This is always executed"
end
```

## Конвенція методів

Деякі методи мають дві версії: одну з `!` і одну без.
Це може означати дві різні речі.
Або метод змінює обʼєкт, або метод може викинути виняток.

Але є й інша конвенція щодо завершення назви методу знаком `?`, про яку йдеться в концепції булевих значень (англ. Boolean).
Деякі методи типово викидають виняток, але також мають версію, назва якої закінчується на `?` і яка повертає `nil` замість викидання винятку.

Це ідеально підходить, коли ми хочемо уникнути виникнення помилки. 
Це може допомогти продуктивності, оскільки не потрібно створювати трасування стеку, а за правильного налаштування код може стати безпечнішим.

## Власні винятки

Ми також можемо створювати власні винятки, успадковуючи їх від класу [`Exception`][exception].
У цьому разі ми можемо за бажанням перевизначити метод `initialize`, щоб задати повідомлення винятку.
Це можна зробити, присвоївши змінній екземпляра з назвою `@message` потрібне повідомлення.

```crystal
class MyException < Exception
 def initialize
   @message = "This is my exception"
 end
end

raise MyException.new
```
