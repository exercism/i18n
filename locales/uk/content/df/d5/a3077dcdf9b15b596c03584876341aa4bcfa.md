# Вступ

Майже кожна програма на Factor - це послідовність слів, які споживають і породжують значення на *стеці даних*. Коли вхідні та вихідні дані впорядковуються охайно, код читається зліва направо без зайвого клопоту. Коли ні, доводиться братися за *слова перемішування*, і код швидко стає заплутаним.

Ця вправа проведе нас крізь стандартне рішення Factor: комбінатори.

## Слова перемішування

Найпоширеніші слова перемішування містяться в [`kernel`][kernel]:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

Ми вже використовували `dup` і `swap`. `over` створює копію *другого* елемента від верхівки. Це зручно, коли одні й ті самі вхідні дані мають живити два обчислення:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

Це нормально для одного використання. Але коли зчепити їх докупи, послідовності з `dup`, `swap`, `over`, `rot` швидко стають нечитабельними.

## `keep` - зберегти вхідні дані

`keep` (у [`kernel`][kernel]) викликає quotation на верхівці стека, але залишає початкове значення над результатом:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

Це замінює шаблон, де за `dup` іде щось, а потім перемішування: замість `dup something swap` можна просто написати `[ something ] keep`.

## `bi` - дві функції від одного вхідного значення

`bi` (у [`kernel`][kernel]) застосовує *два* quotation до одного й того самого значення, залишаючи обидва результати на стеку:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

Без `bi` ми написали б `dup sq swap neg`: це ще досить читабельно для двох операцій, але для трьох уже складно.

## `tri` і `cleave` - багато функцій від одного вхідного значення

`tri` розширює `bi` до трьох quotation:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

`cleave` (у [`combinators`][combinators]) робить те саме для *масиву* з будь-якої кількості quotation:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

Порожній quotation `[ ]` діє як тотожність. Це зручно, коли одна з позицій у наборі має бути самим вхідним значенням.

## `dip` і `2dip` - діяти під верхівкою

`dip` (у [`kernel`][kernel]) викликає quotation на значеннях *під* верхівкою стека, не чіпаючи саму верхівку. `2dip` робить те саме, але захищає *два* верхні значення:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

Тут `dip` сховав `11`, виконав `9 10 +` і повернув `11` назад на верхівку. `2dip` сховав `11 12`, виконав `9 10 +` під ними, а потім відновив `11 12`.

`dip` - правильний інструмент, коли природний порядок аргументів залишає «наскрізне» значення на верхівці стека. Вдаймося до нього замість «сендвіча» зі `swap … swap`.

## `bi@` - та сама операція над двома значеннями

`bi@` (у [`kernel`][kernel]) застосовує один quotation до двох значень на стеці:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*` - різні операції над двома значеннями

`bi*` (у [`kernel`][kernel]) застосовує *різні* quotation до двох значень на стеці, перший quotation до нижчого значення, а другий до верхівки:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

Вдаймося до `bi@`, коли обидва значення обробляються однаково, і до `bi*`, коли кожне потребує власної обробки.

## `tri*` - різні операції над трьома значеннями

`tri*` (у [`combinators`][combinators]) розширює `bi*` до трьох значень і трьох quotation, застосовуючи кожен quotation по черзі до одного значення:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```

[combinators]: https://docs.factorcode.org/content/vocab-combinators.html
