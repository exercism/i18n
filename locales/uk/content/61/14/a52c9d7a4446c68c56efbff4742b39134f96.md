# Вступ

Регулярні вирази - це надзвичайно гнучкий спосіб _зіставляти зі зразком_ рядки тексту (англ. string), використовуючи для цього спеціально створену предметно-орієнтовану мову (DSL).

Багато можливостей для регулярних виразів вбудовано в Base R, і ми можемо натрапити на приклади в старішому коді.

Для нового коду _наполегливо_ радимо використовувати бібліотеку [`stringr`][web-stringr].

Як зазначено в [концепції «Рядки»][concept-strings], у `stringr` добра документація, яку зазвичай пишуть самі автори пакета.

- [Розділ про рядки][book-strings] і [розділ про регулярні вирази][book-regex] у книзі «R for Data Science».

Багато функцій, які ми вже розглянули в концепції [`Strings`][concept-strings], призначені для пошуку за регулярними виразами.

Ми залишили концепцію «Рядки» відносно простою, зіставляючи лише рядкові літерали, але натомість можна використати будь-який зразок регулярного виразу.

Формально регулярний вираз у R створюють, викликаючи [`regex()`][ref-regex].
Для зручності функції `stringr` будуть вважати будь-який рядок-зразок регулярним виразом.
У прикладі нижче перший виклик `str_replace_all()` - це синтаксичний цукор для другого варіанта:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

Корисним довідником буде [шпаргалка][cheat-stringr]: усі функції з аргументом `pattern` (надруковані червоним) приймають регулярний вираз, а на сторінці 2 стисло викладено синтаксис регулярних виразів.

Зауважмо, що функція [`regex()`][ref-regex] усе одно може бути важливою, якщо потрібно перевизначити типові значення, як-от чутливість до регістру чи локаль.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

Багато кодів у регулярних виразах містять зворотну скісну риску, наприклад `\s`, використаний вище.
У звичайних рядках R символ `\` потрібно екранувати, подвоївши його, звідси `"\\s"`.

Зворотні скісні риски можуть множитися й заплутувати, тож у складних випадках може допомогти скористатися [необробленими рядками][book-raw].

Типово синтаксис для визначення необробленого рядка має вигляд `r"( )"`, але припустимі й інші роздільники.
Оскільки і круглі дужки `( )`, і квадратні дужки `[ ]` часто трапляються в синтаксисі регулярних виразів (для груп захоплення й груп опцій), вдалим вибором можуть бути фігурні дужки `{ }`.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## Виявлення збігів

Ось кілька запитань і функції, які допоможуть знайти на них відповідь.

У деяких прикладах використовується `fruit` - вектор із 80 назв фруктів, що входить до `stringr` для практики.

_Чи містить рядок тексту збіг?_
`str_detect()`, або `str_starts()`, `str_ends()`, щоб не вживати `^` чи `$`.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_Повернути лише рядки тексту, що містять збіг?_
Використовуймо `str_subset()`, щоб отримати рядки, і `str_which()`, щоб отримати індекси.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_Скільки збігів у кожному рядку тексту?_
Використовуймо `str_count()`.

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_Де міститься збіг?_
`str_view()` для інтерактивної роботи, `str_locate()` або `str_locate_all()` у загальнішому випадку.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## Захоплення

Часто нам потрібно дізнатися, _що_ саме збігається.
Цього досягають, додаючи до регулярного виразу групи захоплення в круглих дужках.

Можна посилатися на захоплення всередині того самого регулярного виразу за допомогою `\1`, `\2` тощо.
Наприклад, пошук повторюваних пар літер:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

За допомогою подібного синтаксису захоплення можна використовувати в рядках заміни:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

Щоб зібрати збіги для подальшої обробки, використовуємо функцію `str_match()` для першого збігу або `str_match_all()` для всіх збігів.

Групи захоплення зазвичай дають складний результат будь-якою мовою.
Підхід R (_який до того ж векторизовано, що додає складності_) полягає в тому, щоб створити матрицю з `str_match()`: один рядок на кожен вхідний рядок тексту, стовпець 1 містить повний збіг, а решта стовпців - різні групи захоплення.

Використання іменованих груп може бути перевагою, адже вони стають назвами стовпців у матриці результатів.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

У цьому силабусі ми небагато говорили про матриці, хоча є [документ про концепцію][concept-matrices-arrays], до якого можна звернутися.
Матриці погано вписуються в екосистему Tidyverse, хоч і є частиною Base R уже давно.

Коротко кажучи: розглядаймо матриці як вектори з двома індексами, у порядку `[rows, cols]`.
Залишимо будь-який з індексів порожнім, щоб отримати весь рядок або весь стовпець.

Коли ми отримуємо один рядок `r` за допомогою `m[r,]` або один стовпець `c` за допомогою `m[,c]`, повернене значення типово зводиться до вектора.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

Неминуче `str_match_all()` дає результат із ще складнішою структурою:

- Результат - це список, де кожен елемент відповідає одному вхідному рядку тексту.
- Якщо вхідний рядок лише один, розгорніть результат за допомогою індексації `[[1]]`, як описано в [концепції «Списки»][concept-lists].
- Кожен елемент - це матриця з такими самими стовпцями, як у `match()`.
- Кожен рядок матриці - одне успішне захоплення.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

Звісно, збіги можуть не знаходитися.
Тоді результатом буде спеціальне значення `NA`.
Будьмо готові перевіряти це, як описано в [концепції «Ніщо»][concept-nothingness].

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
