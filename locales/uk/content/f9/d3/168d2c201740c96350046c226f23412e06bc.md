# Докладніше

У Go рядки тексту (англ. string) є незмінними.
Якщо ми зʼєднуємо рядки тексту оператором `+` у циклі, це спричиняє часті виділення памʼяті та багаторазове копіювання даних.
Пакет [`strings`](https://pkg.go.dev/strings) надає [`Builder`](https://pkg.go.dev/strings#Builder), щоб звести накладні витрати памʼяті до мінімуму завдяки ефективному збиранню рядків тексту.

## Побудова рядків тексту

Нульове значення `strings.Builder` готове до використання одразу, без будь-якої явної ініціалізації чи виділення памʼяті.
Ми можемо додавати нові дані до `Builder` за допомогою спеціальних методів запису.
Кожен метод запису повертає значення помилки, щоб відповідати стандартним інтерфейсам Go, але гарантовано, що воно завжди `nil`, тож у повсякденному коді його зазвичай ігнорують.

Ось найуживаніші методи:

- `WriteString(s string) (int, error)`: додає рядок тексту в буфер.
- `WriteRune(r rune) (int, error)`: додає UTF-8-кодування руни.
- `WriteByte(c byte) error`: додає один байт.

```go
var sb strings.Builder

sb.WriteString("Hello")
var r rune = ' '
sb.WriteRune(r)
var b byte = '.'
sb.WriteByte(b)
```

## Отримання результату й скидання

Коли ми завершили збирання тексту, накопичений вміст можна отримати як звичайний рядок тексту Go, викликавши метод `String()`.
Виклик `String()` коштує дуже дешево, адже він повертає внутрішній зріз байтів як рядок тексту безпосередньо, без копіювання накопичених даних.

Якщо нам потрібно повторно використати той самий примірник `Builder`, щоб зібрати новий рядок тексту (наприклад, у циклі), можна викликати метод `Reset()`.
Він очищає внутрішній буфер, тож ми починаємо з чистого аркуша й будуємо наступний рядок тексту, зберігаючи при цьому вже виділену ємність памʼяті.

```go
var sb strings.Builder

sb.WriteString("Task One")
fmt.Println(sb.String()) // Output: Task One

// Clear the buffer for resource reuse
sb.Reset()

sb.WriteString("Task Two")
fmt.Println(sb.String()) // Output: Task Two
```
