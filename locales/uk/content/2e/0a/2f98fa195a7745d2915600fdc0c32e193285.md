# Докладніше

У Rust ітератором є будь-яке значення, що реалізує трейт [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html).
Значення ітератора можна просувати вручну, викликаючи метод `next` на ітераторі.

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Багато з [`collections`](https://doc.rust-lang.org/std/collections/index.html) у Rust реалізують
[`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html),
що може створити `Iterator` зі значень колекції.

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

Зауважмо, що хоч `IntoIterator::into_iter` і споживає свій тип `self`, цей тип не обовʼязково має бути власним значенням.
Отже, існують реалізації `IntoIterator` для [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2),
для [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)
і для [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1).
Ці реалізації для різних ступенів володіння дають корисну гнучкість.

Розуміння `traits` для цього поняття не потрібне, і в нас буде ціла вправа для опанування `traits`.
Поки що просто запамʼятаймо, що:

- Будь-який тип, що реалізує `IntoIterator`, називають _ітерабельним_, бо його можна перетворити на ітератор.
- Будь-який тип, що реалізує `Iterator`, є ітератором, який _виробляє_ значення і по якому можна _перебирати_.
- Ітератор можна отримати з будь-якого типу, що реалізує `IntoIterator`, викликавши його метод `into_iter`.
- Кожен ітератор [реалізує `IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25) і виробляє сам себе.
- Цикли `for` завжди працюють з ітераторами й неявно викликають `IntoIterator` для свого аргументу-діапазону.

## `into_iter` і цикли `for`

Ми, ймовірно, вже знайомі з циклами `for` по вектору:

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

По суті, цикл `for` - це лише скорочення для виклику методу `into_iter` свого аргументу,
а потім виклику `next()`, доки він не перестане виробляти елементи. Інакше кажучи, попередній цикл розгортається так:

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## Методи `iter` і `iter_mut`

Більшість типів-колекцій у Rust надають методи `iter` і `iter_mut`.
Для колекції типу `T` ці два методи за домовленістю роблять таке:

- Ітератор, який повертає `iter`, видаватиме незмінно позичене `&T`.
- Ітератор, який повертає `iter_mut`, видаватиме змінно позичене `&mut T`.

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## Різниця між `iter`, `iter_mut` і `into_iter`

Якщо `iter`, `iter_mut` і `into_iter` усі створюють ітератори, то в чому різниця?

- Ітератор, який повертає `iter`, за домовленістю видаватиме незмінно позичене `&T`.
- Ітератор, який повертає `iter_mut`, за домовленістю видаватиме змінно позичене `&mut T`.
- Ітератор, який повертає `into_iter`, може видавати `T`, `&T` або `&mut T` залежно від контексту.

Що є контекстом для виклику `into_iter`?
Його тип `self`.
Пригадаймо, що існують реалізації `IntoIterator` для `Vec`, `&'a Vec` і `&'a mut Vec`.
Отже:

- `(&v).into_iter()` дорівнює `v.iter()` => повертає `&T`
- `(&mut v).into_iter()` дорівнює `v.iter_mut()` => повертає `&mut T`
- `v.into_iter()` => повертає `T` і переміщує значення

Найясніше це видно в циклах `for`:

- `for num in &v {...}` => звʼязує `&T`
- `for num in &mut v {...}` => звʼязує `&mut T`
- `for num in v {...}` => звʼязує `T` і переміщує значення

Часто зрозуміліше написати `v.iter()` замість `(&v).into_iter()`.
Тож є ергономічні причини віддавати перевагу `iter` і `iter_mut` над `into_iter`.

## Використання вбудованих методів ітераторів

Ітератори надають численні вбудовані методи, як-от `map`, `filter`, `collect`.
Ці методи іноді використовують разом із замиканнями.

`map` використовує замикання, щоб перетворити значення ітератора.
`take` обрізає (потенційно нескінченний) ітератор до такого, що завершується після щонайбільше вказаної кількості елементів.

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter` перетворює ітератор на такий, що повертає лише ті значення, для яких замикання обчислюється як `true`.
`count` споживає ітератор, повертаючи кількість вироблених елементів.

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map` перетворює ітератор, перетворюючи кожен елемент на новий ітератор за допомогою наданого замикання,
а потім сплющує всі створені нові ітератори, зчіплюючи їх разом.
`collect` створює нову колекцію,
якщо тип колекції реалізує [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html).

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

[Трейт `Iterator`](https://doc.rust-lang.org/std/iter/trait.Iterator.html) надає _багато_ таких корисних перетворень ітераторів;
варто прочитати документацію і ознайомитися з ними.

## Лінивість

Важливо знати, що ітератори в Rust ліниві:
вони не виробляють значень, доки ми не споживемо ітератор.
Якщо ми напишемо й запустимо такий код:

```rust
(0..5).map(|x| x * x);
```

Ми отримаємо таку помилку компілятора:

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

Це тому, що `map` - це метод-адаптер, який повертає інший ітератор.

Щоб спожити ітератор, треба або скористатися циклом `for`, або скористатися методом ітератора, який виробляє якесь значення, що саме не є ітератором.

Наприклад, `collect` - це метод-споживач (його сигнатура функції повертає не ітератор, а узагальнений тип):

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
