# Про

Написаний вручну код мовою асемблера сповнений повторень.
Той самий короткий набір інструкцій повторюється знову й знову, майже без варіацій, а абстракцій, які б скоротили повторюваний код, обмаль.
До того ж писати мовою асемблера означає керувати значеннями без очевидної семантики.
Іменованих параметрів тут немає, а більшість деталей внутрішнього устрою програміст має опрацьовувати вручну.

NASM, асемблер, який використовує цей трек, пропонує інструменти, що можуть допомогти з обома проблемами.
Ці інструменти працюють на етапі _асемблювання_, перш ніж хоч одна інструкція дійде до процесора.
Вони підказують асемблеру, як переписати початковий текст, ще до того, як його буде перекладено в машинний код.

Найважливіший із цих інструментів - **макроси**, які можна уявити як рецепт для асемблера.
Вони розгортаються в тому місці, де їх використано, наче код було написано там вручну.

[Макроси][macro] можуть приймати як параметри довільну кількість літеральних токенів, що робить їх багаторазовими в різних контекстах.
Однак це не функції: тут немає ні `call`, ні `ret`, ні передавання керування в інше місце коду.

## Однорядкові макроси

Найпростіше визначення дає імʼя значенню або короткому виразу за допомогою `%define`:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Кожне наступне входження `WIDTH` замінюється на `8` ще до асемблювання.
Заміна є текстовою, тож імʼя підставляється всюди, де воно трапляється, чи то в операнді, чи то всередині іншого визначення.

~~~~exercism/note
Для числових _констант_ краще використовувати `equ`, а не `%define`.

Однорядковий макрос, оголошений через `%define`, розгортається лише тоді, коли його використано, і його можна перепризначити або зняти визначення.
Константа `equ`, натомість, обчислюється в місці визначення і ніколи не змінюється.
~~~~

`%define` також може приймати _іменовані_ параметри, поводячись як маленька вбудована функція:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Беріть у дужки і все тіло, і кожен параметр.
Із `%define square(x) x*x` виклик `square(1+1)` розгортається в `1+1*1+1`, що дорівнює `3`.
Якщо ж записати `%define square(x) ((x)*(x))`, той самий виклик розгорнеться в `((1+1)*(1+1))`, що дорівнює `4`.
~~~~

Імена, визначені через `%define`, чутливі до регістру.
Варіант `%idefine` робить імʼя нечутливим до регістру, якщо це потрібно.

Однорядкові макроси допомагають надати сенсу різним частинам коду.
Якщо вживати їх обережно, це покращує читабельність і зменшує ймовірність одруківок.
Наприклад, регістр, який усередині функції має особливе призначення, можна визначити за цим призначенням:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Багаторядкові макроси

Цілу послідовність коду, з будь-якою кількістю рядків, задають через `%macro` і закривають `%endmacro`.
Число після імені вказує, скільки аргументів приймає макрос; воно може бути нулем.
Коли аргументи передаються, їх розділяють комою (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Аргументи в багаторядкових макросах не мають імен.
До них звертаються як до `%1`, `%2` і так далі, у тому порядку, у якому їх передано:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Зауважмо, що аргументи мають бути синтаксично коректними для операцій, які виконуються в тілі макросу.
Тут і `mult_two eax, ecx`, і `mult_two r8, r9` асемблюються, а от `mult_two eax, cl` не асемблюється, бо `imul eax, cl` не визначено.

Макроси також можуть приймати довільну кількість аргументів.
Це роблять за допомогою запису `n-*`, де `n` позначає мінімальну кількість аргументів:

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

У багаторядковому макросі `%0` позначає _кількість_ аргументів макросу.
Це особливо корисно в макросах, які можуть приймати довільну кількість аргументів.

### Мітки всередині макросу

Макрос, який визначає звичайну мітку, ламається, щойно його використано двічі, бо тоді й мітку буде визначено двічі.
Щоб використовувати мітки всередині макросу, який може викликатися більше ніж раз, таку мітку потрібно починати з `%%`.
Це вказує асемблеру давати цій мітці інше, унікальне імʼя під час кожного розгортання:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Повторення під час асемблювання

Однорядковий блок коду можна повторити за допомогою [`times`][times].
Це особливо корисно, коли треба оголосити повторювані значення в памʼяті:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Для повторення багаторядкового коду натомість можна використати `%rep`:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Зауважмо, що кількість повторень указують одразу після `%rep`, а повторюваний блок закриває `%endrep`.

Усередині блоку `%rep` часто використовують лічильник часу асемблювання, так само як цикл часу виконання використовує лічильник.
Хоча цілочисельну константу часу асемблювання можна оголосити через `equ`, як ми вже бачили, для цілочисельних _змінних_ часу асемблювання натомість використовують `%assign`.
На відміну від `%define`, `%assign` одразу обчислюється до числа і його можна перепризначити:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Після роботи препроцесора цикл зникає, залишаються чотири інструкції `add`, у які вбудовано безпосередні значення `0`, `1`, `2` і `3`.
Це розгортання циклу, яке виконує асемблер: без регістра-лічильника і без жодного переходу, лише лінійний код.

Ще одне поширене застосування `%rep` - опрацьовувати аргументи в макросі, який може приймати будь-яку їх кількість.
У такому разі `%rep` зазвичай поєднують із `%rotate`, який обертає аргументи макросу так, що другий аргумент стає першим.
Повторні застосування `%rotate` роблять першим то третій, то четвертий, і так далі аргумент, тож кожен аргумент можна опрацювати по черзі:

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## Умовне асемблювання

У [препроцесора][preprocessor] є різні умовні конструкції.
Вони обирають один із кількох різних шляхів, розгортаючи своє тіло на місці, але лише тоді, коли їхня умова істинна.

`%if` ... `%elif` ... `%else` ... `%endif` обирають гілку за числовою перевіркою:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef` та `%ifndef` схожі, але перевіряють, чи визначено імʼя.
Наприклад, з їхньою допомогою можна забезпечити, що вміст файлу буде включено лише раз, навіть коли файл підключають із кількох джерел:

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

Можна помітити, що в кінці кожного файлу `.asm` у цьому треку є такий фрагмент коду:

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn` порівнює два фрагменти тексту на точний збіг.
Вбудований `__OUTPUT_FORMAT__` розгортається в поточний формат виводу, тож цей код перевіряє, чи формат виводу - `elf64`, який використовують системи Linux.
Якщо так, до обʼєктного файлу додають нотатку, яка оголошує права стека; це поширений захід безпеки.
Якщо ні, нічого не змінюється.

## Структури

Щоб дістатися поля запису в памʼяті, до базової адреси додають байтовий зсув цього поля.
Запис цих зсувів голими числами легко призводить до помилок і приховує їхній сенс.
Натомість [`struc`][struc] і `endstruc` дають імʼя розкладці, перетворюючи кожне поле на символічний зсув, обчислений під час асемблювання.

Усередині блоку директиви резервування `resb`, `resw`, `resd` і `resq` відводять один або більше байтів, слів, подвійних слів чи четвірних слів.
Провідний символ `.` перед іменем кожного поля залишає його імʼя в межах структури:

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

Тепер кожне імʼя поля позначає свій зсув, тож `thread.color` дорівнює `0`, `thread.tension` - `4`, а `thread.name` - `12`.
NASM також визначає `<struc>_size` як загальний розмір, де `<struc>` позначає імʼя `struc`.
Наприклад, тут `thread_size` дорівнюватиме `4 + 8 + 16 = 28`.

Щоб дістатися поля, його зсув додають до базового регістра, а `thread_size` - це крок від одного запису до наступного:

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

`struc` лише описує форму, сам він не виділяє памʼять.
Щоб створити ініціалізований примірник, можна використати `istruc ... iend` після якоїсь мітки.
Усередині примірника `at` розміщує значення в іменованому полі:

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

Зауважмо, що `thread.name` ініціалізується значенням `"warp", 0`, яке займає лише 5 байтів.
Решту 11 байтів, зарезервованих для нього в `struc`, `iend` автоматично заповнює нулями, доповнюючи примірник до `thread_size` значеннями `0`.

`struc` - лише синтаксичний цукор для памʼяті, яку можна оголосити й вручну.
Наприклад, наведений вище код еквівалентний такому, де `times 11 db 0` забезпечує виділення 16 байтів у кінці:

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## Розбиття на файли

Макроси часто тримають в окремому файлі й підключають до кожного джерела, яке їх потребує, через `%include`:

```x86asm
%include "patterns.mac"
```

Названий файл вставляється дослівно в це місце, до асемблювання, так наче його вміст було набрано там.
Так визначення залишаються в одному місці, і кілька файлів із кодом можуть ними користуватися.

Якщо файл макросів може асемблюватися окремо, він має мати розширення `.asm`.
Зауважмо, що макроси не мають звʼязків.
Навіть якщо файл макросів асемблюється, його макроси видимі лише іншому файлу, який підключає його через `%include`.

Інакше файл, призначений лише для `%include`, може мати будь-яке розширення.
Використання як `.asm`, так і `.mac` - поширена домовленість.
