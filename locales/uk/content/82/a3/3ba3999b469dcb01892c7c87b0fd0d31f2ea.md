# Незмінні класи

```sather
immutable class BEARING is
   readonly attr degrees : INT;
   create(d : INT) : SAME is
      b : SAME;
      return b.degrees(d);
   end;
end;
```

## Що змінюється

| | звичайний клас | незмінний клас |
| --- | --- | --- |
| присвоєння | використовує той самий обʼєкт | копіює значення |
| може бути void | так | ні |
| запис через `attr` | `x.a := v` | `x := x.a(v)` |
| `new` | так | ні; `x : SAME` уже існує |

Незмінний обʼєкт не може бути void, тому `void(b)` завжди неправда, і жоден метод на ньому не може зазнати невдачі через брак самого обʼєкта. Так ми позбуваємося цілого класу помилок, але ціною того, що ніколи не можемо сказати «обʼєкта ще немає».

## Де зберігається значення

Значення зберігається там, де й змінна, тобто всередині іншого обʼєкта або на стеку, а не досягається через посилання. Тож `ARRAY{BEARING}` містить самі обʼєкти, а не вказівники на них, а це менше за розміром і швидше для обходу.

Плата за це - копіювання: коли ми передаємо великий незмінний обʼєкт, він щоразу копіюється. Тому такі обʼєкти краще тримати невеликими.

## Методи атрибута

`readonly attr degrees : INT` дає два методи:

```sather
   b.degrees          -- read: INT
   b.degrees(90)      -- answer a new BEARING with degrees changed
```

Другий метод існує навіть за `readonly`, бо він нічого не змінює, а будує нове значення. За звичайного `attr` він публічний, а за `private attr` - ні.

## is_eq та str

Жодного з них не надано. Напишімо `is_eq` для `=`, а `str` - щоб обʼєкт можна було друкувати й зʼєднувати з рядками тексту (англ. string):

```sather
   is_eq(other : SAME) : BOOL is return degrees = other.degrees; end;
   str : STR is return degrees.str + " degrees"; end;
```

Завдяки `str` клас стає сумісним із `$STR`, і саме це дозволяє `+` та `#OUT` приймати його.

## Вбудовані класи

`INT`, `BOOL`, `CHAR`, `FLTD` і `TUP` - усі незмінні класи. Нічого особливого в них немає: у бібліотеці вони так само написані мовою Sather і поводяться так само з наведених вище причин.
