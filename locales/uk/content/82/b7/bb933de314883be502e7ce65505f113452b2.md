# Інструкції

У цій вправі ми будемо працювати з повідомленнями журналу, які мають шість рівнів важливості.

Кожен рядок журналу - це рядок тексту (англ. string), відформатований так: `"[<LVL>]: <MESSAGE>"`.

Ось які бувають рівні журналу:

| РІВЕНЬ    | LVL   |
| --------- | ----- |
| `Trace`   | `TRC` |
| `Debug`   | `DBG` |
| `Info`    | `INF` |
| `Warning` | `WRN` |
| `Error`   | `ERR` |
| `Fatal`   | `FTL` |

## 1. Розбір рівня журналу

Визначте enum `LogLevel`, який має шість елементів, що відповідають рівням журналу, визначеним вище.
Далі визначте функцію `parse_log_level`, яка приймає повідомлення журналу як параметр і повертає елемент enum, що відповідає його рівню.

```python
parse_log_level("[INF]: File deleted")
#=> LogLevel.Info
```

## 2. Підтримка невідомого рівня журналу

На жаль, деякі повідомлення журналу іноді надходять із _невідомим_ рівнем важливості. Щоб коректно обробити ці «загадкові» повідомлення журналу у функції `parse_log_level`, додайте елемент `Unknown` до enum `LogLevel`, який повертається під час розбору невідомого рівня журналу:

```python
parse_log_level("[XYZ]: Overly specific, out of context message")
#=> LogLevel.Unknown
```

## 3. Перетворення повідомлення журналу на короткий формат

Записувати рівень журналу в кожному рядку досить громіздко. Щоб зменшити місце на диску, потрібне для зберігання повідомлень журналу, визначено короткий формат: `"[<CODE_LEVEL>]:<MESSAGE>"`.

Коди рівнів журналу відповідають такому простому зіставленню:

| РІВЕНЬ    | КОД  |
| --------- | ---- |
| `Trace`   | `0`  |
| `Debug`   | `1`  |
| `Info`    | `4`  |
| `Warning` | `5`  |
| `Error`   | `6`  |
| `Fatal`   | `7`  |
| `Unknown` | `42` |

Визначте функцію `convert_to_short_log()`, яка приймає два параметри:

1. Рівень журналу - рівень журналу надісланого повідомлення. Наприклад: `LogLevel.Error`.
2. Повідомлення журналу - повідомлення типу `str`.

```python
convert_to_short_log(LogLevel.Error, "Stack overflow")
# => "6:Stack overflow"
```

## 4. Створення псевдоніма

Схоже, користувач створив журнали з `LogLevel.Warn` замість `LogLevel.Warning`. Створіть `alias` для `LogLevel.Warning` і поверніть новий елемент-псевдонім у функції `get_warn_alias`.

Це можна зробити в тому самому класі enum `LogLevel`, уже визначеному на початку файлу. Обидва елементи `LogLevel` мають указувати на те саме значення: `"WRN"`.

```python
get_warn_alias()
#=> LogLevel.Warn

get_warn_alias() == LogLevel.Warning
#=> True
```

## 5. Усі назви та значення елементів

Визначте функцію `get_members()`.

Ця функція має повертати масив кортежів `(name, value)`, що містить усі елементи enum `LogLevel`.

```python
get_members()
#=> [('Trace', 'TRC'), ('Debug', 'DBG'), ('Info', 'INF'), ('Warning', 'WRN'),
# ('Error', 'ERR'), ('Fatal', 'FTL'), ('Unknown', 'UKN')]
```
