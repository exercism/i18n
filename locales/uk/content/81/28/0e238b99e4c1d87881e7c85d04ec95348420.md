# Про методи

У Rust методи - це функції, визначені для `struct` (або `enum`, або обʼєкта `trait`).
Це змінює спосіб виклику: замість `frobnicate(foo)` метод викликають як `foo.frobnicate()`.

Методи схожі на функції: їх оголошують за допомогою ключового слова `fn`,
вони мають імʼя, і вони можуть мати параметри та повернені значення.

На відміну від функцій, перший параметр методу завжди `self` (або його варіант),
який представляє екземпляр `struct`, для якого викликають метод (докладніше нижче).

Створімо `enum` для гуртожитків Гогвортсу та `struct`, який описує `age` і `house` чарівника:

```rust
#[derive(Debug)]
enum House {
    Gryffindor,
    Hufflepuff,
    Ravenclaw,
    Slytherin,
}

struct Wizard {
    age: u32,
    house: House,
}
```

## Визначення методів

Щоб визначити методи для `struct` `Wizard`, ми починаємо блок `impl` (скорочення від implementation) для `Wizard`.

```rust
impl Wizard { }
```

Усе всередині цього блоку `impl` буде повʼязане з типом `Wizard`.
Зауважмо, що `struct` може мати кілька блоків `impl`.

### Використання `self`

Першим параметром методу повинен бути параметр з іменем `self` типу `Self`.
Тип `Self` - це псевдонім для типу, для якого призначено блок `impl`.
У нашому прикладі `Self` представляє `Wizard`.

Rust для зручності дозволяє скоротити це до самого лише імені `self` на місці першого параметра.
До поширених типів `self` для методів належать:

- `self`: скорочення для `self: Self`. Сама сигнатура `self` споживає екземпляр.
- `&self`: скорочення для `self: &Self`. Це незмінно запозичує екземпляр.
- `&mut self`: скорочення для `self: &mut Self`. Це змінно запозичує екземпляр.

У складнішому коді можна також побачити сигнатури на кшталт `self: Pin<&self>`, `self: Rc<Self>` тощо.
Однак це виходить за межі цього туторіалу.

### Визначення методу з `&self`

Якщо ми хочемо реалізувати метод `info`, який показує базову інформацію про чарівника,
ми можемо визначити цей метод усередині блоку `impl` для `Wizard`:

```rust
impl Wizard {
    fn info(&self) {
        println!(
            "A wizard of age {} who studies in House {:?} at Hogwarts",
            self.age,
            self.house,
        );
    }
}
```

Зауважмо, що в сигнатурі `info` ми незмінно запозичуємо екземпляр за допомогою `&self`.
Так ми можемо прочитати поля `age` і `house` екземпляра `Wizard`, не змінюючи їх.
Якби ми використали `self`, який споживає екземпляр, замість запозичення, то екземпляр став би недоступним після виклику методу.

Коли метод `info` реалізовано, ми можемо надрукувати базову інформацію про чарівника:

```rust
let harry = Wizard { age: 11, house: House::Gryffindor };
harry.info();
// => A wizard of age 11 who studies in House Gryffindor at Hogwarts
```

### Визначення методу з `&mut self`

Якщо ми хочемо реалізувати метод, який змінює поля екземпляра `struct`,
у сигнатурі методу ми змінно запозичуємо екземпляр за допомогою `&mut self`.

Припустімо, ми хочемо запровадити в Гогвортсі нове правило, яке дозволяє студентам змінювати гуртожиток.
Ми можемо реалізувати метод `switch_house` так:

```rust
impl Wizard {
    fn switch_house(&mut self, new_house: House) {
        self.house = new_house;
    }
}
```

Тепер ми можемо змінити гуртожиток для чарівника, який навчається в Гогвортсі:

```rust
// Note that the variable must be mutable
let mut cedric = Wizard {age: 14, house: House::Hufflepuff};
cedric.info();
// => A wizard of age 14 who studies in House Hufflepuff at Hogwarts
cedric.switch_house(House::Slytherin);
cedric.info()
// => A wizard of age 14 who studies in House Slytherin at Hogwarts
```

## Кілька блоків «impl»

У Rust кожен елемент може мати кілька блоків `impl`.
Тож ми можемо згрупувати всі методи в одному блоці `impl` або мати кілька блоків `impl` для різних груп методів.
Обидва підходи синтаксично правильні, але типове впорядкування проєкту використовує один блок `impl` на кожен унікальний набір обмежень `where` рівня `impl`.

## Асоційовані функції

У блоці `impl` можна визначати функції, які не містять параметра `self`.
Оскільки в них немає параметра `self`, вони не є методами.
Однак вони все одно повʼязані з типом, для якого реалізовано блок, і їх викликають, називаючи цей тип.
Тому їх називають асоційованими функціями (або функціями, асоційованими з типом).

Ми вже бачили деякі асоційовані функції, наприклад `String::from()`:

```rust
let some_string = String::from("This is an associated function but not a method");
```

Конструктори часто реалізують як асоційовані функції.
Створімо функцію `new`, асоційовану з типом `Wizard`:

```rust
impl Wizard {
    fn new(age: u32, house: House) -> Self {
        Self {
            age,
            house,
        }
    }
}
```

Зауважмо, що ми можемо використати `Self` замість `Wizard`, щоб указати тип, який поверне функція.
Використовувати псевдонім типу `Self` у такий спосіб не обовʼязково, але це може спростити реалізацію для типів зі складними чи довгими іменами.
Тепер ми можемо виконати таке:

```rust
let myrtle = Wizard::new(14, House::Ravenclaw);

myrtle.info();
// => A wizard of age 14 who studies in House Ravenclaw at Hogwarts
```
