# Вступ

TypeScript - це JavaScript із синтаксисом для типів. Це строго типізована мова програмування, яка підтримує обʼєктно-орієнтований, імперативний і декларативний (наприклад, функціональний) стилі програмування та дає кращий інструментарій за будь-якого масштабу.

[Оскільки не можна вивчити TypeScript, не вивчивши JavaScript][handbook-js-or-ts], частина вмісту цього треку присвячена вивченню концепцій JavaScript, а частина концепцій зосереджена лише на можливостях, властивих TypeScript.

## (Пере)присвоєння

Існує кілька основних способів присвоїти значення іменам у TypeScript: за допомогою змінних або констант.
На Exercism змінні завжди записуємо в [camel case][wiki-camel-case], а константи - у [SCREAMING_SNAKE_CASE][wiki-snake-case].
Немає офіційного посібника, якого слід дотримуватися, а різні компанії та організації мають різні настанови зі стилю.
_Змінні можна писати як завгодно_.
Перевага запису змінних так, як це підготовлено у вправах, полягає в тому, що вебінтерфейс і більшість IDE будуть підсвічувати їх по-різному.

Змінні в TypeScript можна визначати за допомогою ключового слова [`const`][mdn-const], [`let`][mdn-let] або [`var`][mdn-var].

Протягом свого існування змінна може вказувати на різні значення, якщо використовувати `let` або `var`.
Наприклад, `myFirstVariable` можна визначати й перевизначати багато разів за допомогою оператора присвоєння `=`:

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

На відміну від `let` і `var`, змінні, визначені за допомогою `const`, можна присвоїти лише один раз.
Так у TypeScript визначають константи.

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

Оскільки TypeScript може виявити це статично, компілятор TypeScript також видасть помилку:

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

Це означає, що не потрібно запускати код, щоб виявити `TypeError`.

## Виведення типів

Не заглиблюючись надто в тему [виведення типів][handbook-type-inference], варто знати, що присвоєна змінна зазвичай має виведений тип, навіть без анотації типу.

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

Цей тип надалі перевіряється по всьому коду.
Це також означає, що наведений нижче код є коректним JavaScript:

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

а в TypeScript він видає помилку:

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

Ця можливість забезпечує типобезпеку, навіть коли анотації типів не використовуються.

## Оголошення функцій

У TypeScript одиниці функціональності інкапсульовані у _функції_. Зазвичай функції, які належать одна до одної, групують разом в одному файлі.
Такі функції можуть приймати параметри (аргументи) і можуть _повертати_ значення за допомогою ключового слова `return`.
Функції викликають за допомогою синтаксису `()`.

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

Параметри функції зазвичай варто анотувати типом, використовуючи двокрапку (`:`), після якої вказують тип.
Повернені значення функцій можна анотувати після закриття списку параметрів, використовуючи двокрапку (`:`), після якої вказують тип.

<!--prettier-ignore -->
~~~~exercism/note
💡 У TypeScript існує _багато_ різних способів оголосити функцію.
Ці інші способи мають інший вигляд, ніж використання ключового слова `function`.
Трек намагається поступово знайомити з ними, але якщо ці способи вже знайомі, можна сміливо використовувати будь-який із них.
У більшості випадків використання одного чи іншого не краще й не гірше.
~~~~

## Анотації типів

Як показано в оголошенні функції `add`, параметри мають явну анотацію типу `: number`.
Оголошення змінних, властивості класів, оголошення функцій та багато іншого підтримують анотації типів.

І явні анотації типу, і виведені типи контролює перевірка типів.

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## Надання доступу іншим файлам

Щоб зробити `function`, константу чи змінну доступними в _інших файлах_, їх потрібно [експортувати][mdn-export] за допомогою ключового слова `export`.
Тоді інший файл може [імпортувати][mdn-import] їх за допомогою ключового слова `import`.
Це також називають системою модулів.
Чудовий приклад - те, як працюють усі тести.
Кожна вправа має щонайменше один файл, наприклад `lasagna.ts`, який містить _реалізацію_.
Крім того, є щонайменше один інший файл, наприклад `lasagna.test.ts`, який містить _тести_.
Цей файл _імпортує_ публічні (тобто експортовані) сутності, щоб перевірити реалізацію:

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
