# Вступ

## Ключове слово `auto` у C++

У C++ ключове слово `auto` - це потужна можливість, запроваджена в C++11, яку використовують для оголошення змінних із виведеним типом даних.
Компілятор виводить тип змінної на основі її ініціалізатора, що може зробити код зрозумілішим і легшим у супроводі.

## Приклад використання

Розглянемо наступний приклад, де `auto` використовують для оголошення змінних:

```cpp
auto dragon_population{3};          // dragon_population is deduced as an integer
auto westeros{7.7777};              // westeros is deduced as a double
auto wedding_location{"The Twins"}; // wedding_location is deduced as a const char*, not std::string
```

У кожному випадку тип змінної виводиться зі значення, яким її ініціалізовано.

## Виведення типу

Ключове слово `auto` допомагає писати лаконічніший і зрозуміліший код, зменшуючи багатослівність явних типів.

```cpp
const std::vector<std::string> pigeon_pie{"flour", "butter", "pigeon", "salt"};
auto purple_wedding_pie{pigeon_pie};
purple_wedding_pie.emplace_back("the strangler");
```

У цьому циклі `auto` виводить тип `purple_wedding_pie` як `std::vector<std::string>`, уникаючи потреби знову явно вказувати тип.

## Сумісність

Ключове слово `auto` сумісне з різними конструкціями C++, що робить його універсальним інструментом у сучасному програмуванні на C++.

```cpp
auto& element{array[0]};           // reference to an element
const auto object{otherObject};    // const type version of otherObject's type
auto* ptr{&x};                     // pointer to x with the same type as x, but as a pointer.
```

У наступних концепціях ми часто будемо бачити ключове слово `auto` з лямбда-виразами, циклами `for` на основі діапазону та ітераторами.

## Розумні вказівники

Розумні вказівники - це сучасна можливість C++, покликана забезпечувати автоматичне керування памʼяттю, допомагаючи запобігати витокам памʼяті та завислим вказівникам, які зазвичай повʼязують із сирими вказівниками.
Вони діють як обгортки навколо сирих вказівників, додаючи додаткову функціональність, як-от автоматичне звільнення памʼяті, коли вказівник більше не потрібен.

## Загальний синтаксис

Розумні вказівники зазвичай реалізовані як шаблони класів у стандартній бібліотеці C++.
Два найпоширеніші розумні вказівники - це `std::unique_ptr` і `std::shared_ptr`.

## Унікальні вказівники

`std::unique_ptr` - це розумний вказівник, який одноосібно володіє обʼєктом.
Він гарантує, що в будь-який момент лише один обʼєкт `std::unique_ptr` володіє ресурсом.
Коли `std::unique_ptr`, що володіє ресурсом, знищується або скидається, він автоматично знищує обʼєкти та звільняє його памʼять.

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## Переваги `std::make_unique()`

Створюючи `std::unique_ptr`, краще використовувати `std::make_unique()` замість прямого використання `new` для виділення памʼяті.
`std::make_unique()` має кілька переваг:
1. **Безпека винятків**: `std::make_unique()` гарантує безпеку винятків.
  Якщо під час конструювання обʼєкта виникає виняток, памʼять буде автоматично звільнено, що запобігає витокам памʼяті.
2. **Ясність**: Використання `std::make_unique()` робить код яснішим і лаконічнішим.
  Воно усуває потребу явно вказувати тип, що виділяється, оскільки аргументи шаблону виводяться автоматично.
3. **Можливості оптимізації**: Компілятори мають змогу оптимізувати `std::make_unique()` ефективніше, ніж виділяти памʼять вручну за допомогою `new`, що може призвести до покращення продуктивності.
4. **Уникнення неправильного використання**: Видалення базового ресурсу можливе, коли `std::unique_ptr` сконструйовано вручну.
  Це призведе до невизначеної поведінки, коли `std::unique_ptr` спробує видалити його в кінці своєї області видимості.

## Спільні вказівники

`std::shared_ptr` - це розумний вказівник, який дозволяє кільком обʼєктам `std::shared_ptr` спільно володіти одним і тим самим ресурсом.
Він відстежує, скільки спільних вказівників посилаються на ресурс, і звільняє памʼять лише тоді, коли останній спільний вказівник, що володіє ресурсом, виходить з області видимості або скидається.

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
У C++17 і раніших версіях використання `std::shared_ptr` із масивами через `std::make_shared<T[]>` напряму не підтримується.
Хоча виділити масиви за допомогою `std::make_shared<T[]>` можливо, створення спільних вказівників безпосередньо з них може призвести до невизначеної поведінки через відмінності в керуванні памʼяттю між окремими обʼєктами та масивами.
Замість цього розглянемо використання `std::vector` або власних функцій видалення, щоб ефективно керувати масивами зі спільними вказівниками.
Завжди слід переконатися в сумісності зі своїм компілятором і реалізацією стандартної бібліотеки, коли маємо справу з виділенням масивів і спільними вказівниками в C++17.
~~~~

## Переваги `std::make_shared()`

Подібно до `std::make_unique()`, `std::make_shared()` пропонує переваги, як-от підвищена ефективність використання памʼяті, безпека винятків і зрозумілість.
Він поєднує виділення памʼяті для контрольного блоку та керованого обʼєкта в одну операцію, підвищуючи ефективність і зменшуючи ризик витоків памʼяті.
Крім того, автоматичне виведення аргументів шаблону спрощує код і підвищує зрозумілість.
Використання `std::make_shared()` сприяє чистішому, безпечнішому та ефективнішому коду під час роботи з обʼєктами `std::shared_ptr` у C++.

## Поради щодо використання

Типово використовуймо розумні вказівники: `std::unique_ptr` для одноосібного володіння, а `std::shared_ptr` для спільного володіння.
Залишаймо сирі вказівники для посилань без володіння або для взаємодії із застарілим кодом.
У більшості випадків `std::unique_ptr` достатньо для одноосібного володіння, оскільки він забезпечує легке керування памʼяттю без накладних витрат на підрахунок посилань.
`std::shared_ptr` слід використовувати ощадливо, оскільки він додає накладні витрати й складність, якщо тільки не потрібне справжнє спільне володіння.
