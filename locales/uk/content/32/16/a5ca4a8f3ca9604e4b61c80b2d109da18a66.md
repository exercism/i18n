# Підказки

## Загальне

- Контракт розміщується після типу поверненого значення і перед `is`:

  ```sather
     spare_capacity(load : INT) : INT
        pre load >= 0
     is
        ...
     end;
  ```

- Усередині контракту можна використовувати аргументи й атрибути обʼєкта, тож `limit` доступний.
- Тести збираються без `-chk`, тож неправильний контракт їх не провалить. Пишіть їх для читача.

## 1. Спорядіть обвʼязку

- `pre kg > 0` у `create`.
- Тіло - звичайний `new`: встановіть атрибут і поверніть його.

## 2. Скільки ще залишилося запасу?

- Дві умови, зʼєднані через `and`: `pre load >= 0 and load <= limit`.
- `post result >= 0`. Це випливає з `pre`, і саме тому його варто записати: він фіксує, чому цій відповіді можна довіряти.

## 3. Наскільки він заповнений?

- `pre load >= 0` і `post result >= 0`.
- `load * 100 / limit`, саме в такому порядку. Якщо поділити спочатку, усе пропаде, як це було б і в `tuning-the-strings`.

## 4. Чи це безпечно?

- Жодного `pre`: уся суть у тому, що запитувати можна про будь-яке навантаження.
- `post` повторює питання: `post result = (load <= limit)`. Дужки, бо `=` використовується двічі для різних речей.
