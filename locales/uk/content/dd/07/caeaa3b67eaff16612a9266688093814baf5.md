# Про

## Вступ

Узагальнення - це можливість мови, яка дає змогу повторно використовувати код.
Наприклад, не повинно мати значення, який тип зберігає масив, щоб обчислити його довжину.
Саме тому функція `length` використовує параметр узагальненого типу `a` у своїй сигнатурі типу.

```elm
length : List a -> Int
```

## Параметри в типах

Коли тип є узагальненим щодо іншого типу, ми використовуємо для цього іншого типу імʼя в нижньому регістрі й називаємо його параметром типу.
Поширені приклади: власні типи `List`, `Maybe` та `Result`.

```elm
-- Maybe is generic over the type a
type Maybe a
    = Nothing
    | Just a

someString : Maybe String
someString = Just "hello"

someInt : Maybe Int
someInt = Just 42
```

Важливе зауваження щодо імен параметрів типу: вони можуть містити кілька символів.
Єдине обмеження полягає в тому, що це мають бути імена в нижньому регістрі.
Тож коли це доречно, ми зазвичай даємо їм описові імена.

Тип може бути узагальненим щодо кількох інших типів і, відповідно, мати кілька параметрів типу.
У такому разі кожен незалежний тип отримує інше імʼя в нижньому регістрі.
Незалежність не заважає їм стати одним і тим самим типом, вона лише дає їм змогу бути різними.

```elm
-- Result is generic over the types error and value
type Result error value
    = Ok value
    | Err error
```

Псевдоніми типу запису також можуть мати параметри типу, хоч це трапляється рідше.

```elm
-- Event is generic over the type a
type alias Event a =
    { at : Time
    , data : a 
    }
```

> Саме тому пакет `Html` визначає тип `Html msg` з одним параметром типу на імʼя `msg`.
> Архітектура Elm спонукає нас створювати власний тип `Msg`, який описує всі повідомлення, які може запускати наша вебсторінка.
> У результаті наш код буде будувати представлення типу `Html Msg`, де `Msg` - це конкретний тип, який ми визначили.
> Початківці іноді плутаються між помилками, у яких згадується `Html msg` (у нижньому регістрі), і помилками з `Html Msg`.
> Тепер ми це знаємо!
> Різниця в тому, що перша є узагальненою щодо будь-якого типу `msg`, а друга стосується саме нашого типу `Msg`.

## Параметри типу у функціях

Оскільки типи можуть бути узагальненими, то й функції можуть бути такими.
Можна писати функції, які працюють з узагальненими типами, наприклад `Maybe.withDefault`.

```elm
withDefault : a -> Maybe a -> a
withDefault default maybe =
    case maybe of
      Just value -> value
      Nothing -> default
```

Функції, які приймають інші функції як параметри, називаються функціями вищого порядку, і вони теж можуть бути узагальненими.

```elm
map : (a -> b) -> Maybe a -> Maybe b
map function maybe =
  case maybe of
    Just value ->
      Just (function value)

    Nothing ->
      Nothing
```

Параметри типу можуть траплятися як у вхідних даних, так і у вихідних даних функції, а узагальненість, яку забезпечують параметри типу, зазвичай називають **параметричним поліморфізмом**.
Це відрізняється від ad-hoc поліморфізму, також відомого як перевантаження функцій, де те саме імʼя функції можна використати в кількох реалізаціях, у яких типи різняться.
Це також відрізняється від поліморфізму підтипів, де типи можна визначити в ієрархії, і функції, визначені для типу, можна також викликати з аргументами його підтипів.
В Elm єдиний доступний механізм узагальненості - це параметричний поліморфізм.
