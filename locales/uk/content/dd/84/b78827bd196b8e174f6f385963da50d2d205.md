# Вступ

Розумні вказівники - це сучасна можливість C++, покликана забезпечити автоматичне керування памʼяттю та допомогти уникнути витоків памʼяті й висячих вказівників, які зазвичай повʼязують із сирими вказівниками.
Вони діють як обгортки навколо сирих вказівників, додаючи додаткову функціональність, наприклад автоматичне звільнення памʼяті, коли вказівник більше не потрібен.

## Загальний синтаксис

Розумні вказівники зазвичай реалізовано як шаблони класів у стандартній бібліотеці C++.
Два найуживаніші розумні вказівники - це `std::unique_ptr` і `std::shared_ptr`.

## Унікальні вказівники

`std::unique_ptr` - це розумний вказівник, який володіє обʼєктом одноосібно.
Він гарантує, що в будь-який момент часу лише один обʼєкт `std::unique_ptr` володіє ресурсом.
Коли `std::unique_ptr`-власник знищується або скидається, він автоматично знищує обʼєкти та звільняє їхню памʼять.

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## Переваги `std::make_unique()`

Створюючи `std::unique_ptr`, краще використовувати `std::make_unique()`, ніж безпосередньо виділяти памʼять через `new`.
`std::make_unique()` дає кілька переваг:
1. **Безпека винятків**: `std::make_unique()` гарантує безпеку винятків.
  Якщо під час конструювання обʼєкта буде викинуто виняток, памʼять буде автоматично звільнено, що запобігає витокам памʼяті.
2. **Ясність**: Використання `std::make_unique()` робить код яснішим і лаконічнішим.
  Воно позбавляє потреби явно вказувати тип, який виділяється, адже аргументи шаблону виводяться автоматично.
3. **Можливості оптимізації**: Компілятори мають можливість оптимізувати `std::make_unique()` ефективніше, ніж ручне виділення памʼяті через `new`, що потенційно дає кращу продуктивність.
4. **Уникнення неправильного використання**: Коли `std::unique_ptr` створено вручну, можна видалити ресурс, що лежить в його основі.
  Це призведе до невизначеної поведінки, коли `std::unique_ptr` спробує видалити його в кінці своєї області видимості.

## Спільні вказівники

`std::shared_ptr` - це розумний вказівник, який дозволяє кільком обʼєктам `std::shared_ptr` спільно володіти одним ресурсом.
Він відстежує, скільки спільних вказівників посилається на ресурс, і звільняє памʼять лише тоді, коли останній спільний вказівник, що володіє ресурсом, виходить з області видимості або скидається.

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

У C++17 і раніших версіях використання `std::shared_ptr` з масивами через `std::make_shared<T[]>` прямо не підтримується.
Хоча виділити масиви за допомогою `std::make_shared<T[]>` можливо, створення спільних вказівників безпосередньо з них може призвести до невизначеної поведінки через відмінності в керуванні памʼяттю між окремими обʼєктами та масивами.
Натомість розгляньмо використання `std::vector` або власних функцій видалення, щоб ефективно керувати масивами за допомогою спільних вказівників.
Завжди слід переконатися в сумісності зі своїм компілятором і реалізацією стандартної бібліотеки, коли маємо справу з виділенням масивів і спільними вказівниками в C++17.
~~~~

## Переваги `std::make_shared()`

Подібно до `std::make_unique()`, `std::make_shared()` дає такі переваги, як краща ефективність використання памʼяті, безпека винятків і читабельність.
Воно обʼєднує виділення памʼяті для керуючого блоку та керованого обʼєкта в одну операцію, підвищуючи ефективність і зменшуючи ризик витоків памʼяті.
Крім того, автоматичний вивід аргументів шаблону спрощує код і покращує читабельність.
Використання `std::make_shared()` робить код чистішим, безпечнішим і ефективнішим у роботі з обʼєктами `std::shared_ptr` у C++.

## Слабкі вказівники

`std::weak_ptr` - це супутній клас до `std::shared_ptr`, який надає «слабке» посилання без володіння на обʼєкт, яким керує спільний вказівник.

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

Слабкі вказівники корисні в ситуаціях, коли потрібно розірвати циклічні посилання, щоб запобігти витокам памʼяті.
`std::weak_ptr` було створено, щоб розвʼязати проблему циклічного володіння, відомого також як кругові посилання, яка може виникнути під час використання `std::shared_ptr`.
У сценарії циклічного володіння два або більше обʼєктів `std::shared_ptr` посилаються один на одного, утворюючи цикл, у якому жоден з обʼєктів не можна видалити, бо вони мають сильні посилання один на одного, що призводить до витоків памʼяті.
`std::weak_ptr` дає розвʼязок цієї проблеми, дозволяючи слабкі посилання на спільні обʼєкти, не збільшуючи їхній лічильник посилань.
Це означає, що він може спостерігати за спільним обʼєктом і звертатися до нього, але не перешкоджає його видаленню.
~~~~

## Поради щодо використання

За замовчуванням використовуймо розумні вказівники: `std::unique_ptr` для одноосібного володіння та `std::shared_ptr` для спільного володіння.
Сирі вказівники залишмо для посилань без володіння або для взаємодії із застарілим кодом.
У більшості випадків `std::unique_ptr` достатньо для одноосібного володіння, адже він забезпечує легке керування памʼяттю без накладних витрат на підрахунок посилань.
`std::shared_ptr` варто використовувати помірно, бо він додає накладних витрат і складності, якщо справжнє спільне володіння не потрібне.
`std::weak_ptr` призначений спеціально для розривання циклічних залежностей або спостереження за спільними обʼєктами, але його використовують нечасто.
