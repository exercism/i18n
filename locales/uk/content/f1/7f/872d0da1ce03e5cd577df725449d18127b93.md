# Додаток до інструкцій

JavaScript за своєю природою однопоточна, тому їй бракує багатьох мовних можливостей, які мають інші мови для роботи з паралельним виконанням коду.
Насправді єдиний спосіб досягти «справжнього» паралельного виконання коду полягає у використанні `Worker threads` (їх також називають `Web Workers`).

Майже завжди код, який нібито виконується паралельно,
наприклад `async functions` чи `Promises`, насправді виконується конкурентно.
Часто це навіть краще, адже сучасний JavaScript оптимізовано саме під таке використання,
і ми часто бачимо код, який «імітує» (або «підробляє») паралельне виконання за допомогою `Promise.all()` та інших методів конкурентного виконання.

## Конкурентність і паралелізм

Ось коротке визначення кожного з них, яке показує різницю між ними:

- Конкурентність означає, що два або більше завдань можуть починатися, виконуватися й завершуватися в періоди, які перекриваються, а виконує їх один і той самий обчислювальний блок.
- Паралелізм означає, що два або більше завдань можуть починатися й виконуватися одночасно, незалежно одне від одного, окремими обчислювальними блоками.

Для повноти картини ось визначення синхронного виконання:

- Синхронне виконання означає, що завдання має дочекатися завершення іншого завдання, перш ніж почати виконуватися.

## Паралелізм у JavaScript

Хоча JavaScript типово однопоточна, існує спосіб виконувати код паралельно.

Якщо JavaScript виконується у браузері (наприклад, у вебзастосунку),
то досягти паралелізму можна через [Web Worker API][mdn-demo].
Як описує MDN:

> Web Workers дають змогу виконувати операцію зі скриптом в окремому фоновому потоці, відмінному від головного потоку виконання застосунку.

З іншого боку, якщо JavaScript виконується в Node.js, який є цільовим середовищем виконання на Exercism,
ця сама концепція має назву [Worker threads][node].

<!-- prettier-ignore -->
~~~@exercism/caution
Be aware that the implementation of the worker API differs largely between browsers and other JavaScript environments.

Make sure to read the documentation for your specific runtime!
~~~

Ось простий приклад використання `Web Worker API` (узятий з [Medium][medium-demo])

```js
// main.js
const myWorker = new Worker('worker.js');

myWorker.postMessage(5);

myWorker.onmessage = function (event) {
  console.log('Received result from worker:', event.data);
};
```

```js
// worker.js
onmessage = function (event) {
  console.log('Received number from main thread:', event.data);

  // Perform computation
  const result = event.data * 2;

  // Send result back to the main thread
  postMessage(result);
};
```

А ось приклад використання `Worker threads API` (узятий з [документації][node])

```js
const {
  Worker,
  isMainThread,
  parentPort,
  workerData,
} = require('node:worker_threads');

if (isMainThread) {
  module.exports = function parseJSAsync(script) {
    return new Promise((resolve, reject) => {
      const worker = new Worker(__filename, {
        workerData: script,
      });
      worker.on('message', resolve);
      worker.on('error', reject);
      worker.on('exit', (code) => {
        if (code !== 0)
          reject(new Error(`Worker stopped with exit code ${code}`));
      });
    });
  };
} else {
  const { parse } = require('some-js-parsing-library');
  const script = workerData;
  parentPort.postMessage(parse(script));
}
```
