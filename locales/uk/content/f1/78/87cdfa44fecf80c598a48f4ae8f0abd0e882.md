# Основи Unison

## Терми та функції

Терми та функції - базові одиниці написання програми мовою Unison.

«Терм» - це те, що ми називаємо статичним значенням. Його визначають за допомогою `name = expression`, перед яким необовʼязково може стояти сигнатура типу у формі `name : MyType`. Unison підтримує виведення типів, тож для простих визначень сигнатуру типу можна не вказувати.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Функції Unison мають такий вигляд: `myFunctionName argument1 argument2 = myImplementation`; вони починаються з назви функції, за якою йдуть розділені пробілами аргументи.

```
getMax a b = Nat.max a b
```

Функції можуть необовʼязково містити сигнатуру типу. Останній тип праворуч - це завжди підсумковий тип повернення функції, а кожен аргумент відокремлений стрілкою функції `->`.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Щоб викликати функцію, використовуємо її назву, за якою йдуть аргументи, розділені лише пробілами.

```
maximum = getMax 1 10
```

Коли ми викликаємо функцію, Unison намагається сприймати те, що стоїть безпосередньо праворуч, як її аргумент, що не завжди дає бажаний порядок обчислення функції.

Припустімо, ми хочемо отримати значення `1` з такого виразу

```
shouldBe1 = getMax 1 10 - 10
```

Як записано, `shouldBe1` обчислюється до `0`, бо неявний порядок застосування функції такий: `getMax 1 10` дає `10`, а тоді `10 - 10` дає `0`.

Можна використати дужки, щоб перегрупувати вираз у бажаний порядок операцій.

```
shouldBe1 = getMax 1 (10 - 10)
```

## Багаторядкові функції

Багаторядкові функції Unison використовують відступи або блоки `let`, щоб задати межі коду, тобто «лексичну область видимості».

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Усе на однаковому рівні відступу має спільну область видимості, тому ми можемо посилатися на змінну `newBeginning` в останньому рядку.

## Простори імен та інструкції `use`

Простори імен - це те, як ми групуємо та впорядковуємо функції Unison. Їх можна уявляти собі як аналоги «каталогів». Вони дають структуру та логічне групування.

Можна внести функції з простору імен в область видимості за допомогою інструкції `use`.

Уявімо, що ми пишемо функцію, яка використовує значення `List` з Unison. Ми знаємо, що нам знадобляться такі функції, як `List.map` і `List.flatMap`, де `List` - простір імен, а `map` і `flatMap` - функції. Щоб не повторюватися, можна внести все з простору імен `List` у лексичну область видимості функції ось так:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

Рядок `use List` усуває неоднозначність посилань на `map` і `flatMap`. Докладніше про [інструкції `use` можна прочитати тут][use-statements].

## Стандартна бібліотека Unison

Стандартна бібліотека Unison називається `base`. Якщо ми скористалися посібником зі швидкого старту й маємо локально створену кодову базу, стандартна бібліотека мала завантажитися автоматично. Переглянути документацію стандартної бібліотеки онлайн можна на [Unison Share][unison-share-base].

## Коментарі та літерали документації

Коментарі в Unison - доволі незвична можливість. Пишучи код Unison, ми можемо створити у файлі з розширенням `.u` текст, який не інтерпретується, за допомогою такого синтаксису:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Однак_ код Unison зберігається як хеш його абстрактного синтаксичного дерева, а не як текстові файли у файловій системі, тож коментарі, які є текстовими «прикрасами» певної функції чи терма Unison у файлі, насправді не можна зберегти й відтворити для поширення. Якщо ми хочемо додати інформацію до терма Unison у спосіб, який збережеться, щоб інші могли її прочитати й зрозуміти, можна скористатися літералом документації.

Документація - це повноправне значення в мові програмування Unison. Це означає, що елемент `Doc` можна присвоїти значенню, передати як значення у функцію або повернути як значення функції. Елементи літерала документації відкриваються й закриваються подвійними фігурними дужками. Ось як ми могли б використати елемент `Doc` як коментар.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
