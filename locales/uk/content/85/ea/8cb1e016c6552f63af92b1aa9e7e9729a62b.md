# Інструкції

Леслі, прибулець із Lisp, програмує свого робота для лабіринту (як і заведено в молодих прибульців із Lisp) і потребує невеликої допомоги. Лабіринт складається з низки кімнат. У кожній кімнаті на вибір є кілька дверей. Кожні двері потребують ключа. Якщо ми використаємо неправильний ключ, двері, найімовірніше, вибухнуть (за робота не хвилюймося: шкоди не буде, але відполіровувати сліди від опіків Леслі буде досить прикро). Якщо в робота не буде ключа, який відчиняє хоч якісь двері, то вся кімната вибухне! (Знову ж таки, не хвилюймося: шкоди це не завдасть, але прибирати буде досить прикро.)

Щоб допомогти Леслі, нам треба дати роботу правильний ключ для кожної кімнати. Робот використає ключ на кожних дверях у кімнаті по черзі й пройде через перші двері, які відчиняться.

Кожен тест представляє лабіринт, а кожне твердження - кімнату. Нам потрібно буде написати функції-предикати, які дають `T`, коли аргументи рівні, і `NIL`, коли вони не рівні.

## 1. Лабіринт рівності обʼєктів

У цьому лабіринті лише одна кімната. Потрібно надати функцію, яка може визначити, чи два обʼєкти є тим самим обʼєктом.

Наприклад:

```lisp
a                         ; => "pizza"
b                         ; => "pizza"

(key-object-identity a a) ; => T
(key-object-identity a b) ; => NIL
```

адже хоч `a` і `b` здаються однаковими, це не той самий обʼєкт.

## 2. Лабіринт чисел

У цьому лабіринті дві кімнати. У першій є двері, які можна відчинити, якщо наш ключ уміє визначити, чи два числа строго рівні одне одному. Другій кімнаті потрібен ключ, який дає певну гнучкість під час перевірки чисел на рівність.

Наприклад:

```lisp
a                                    ; => 13
b                                    ; => 13.0
c                                    ; => 13

(key-numbers a b)                    ; => NIL
(key-numbers a c)                    ; => T
(key-numbers-of-different-types a b) ; => T
```

адже хоч `a` і `b` чисельно однакові, вони належать до різних типів.

## 3. Лабіринт символів

У цьому лабіринті дві кімнати. У першій є двері, які можна відчинити, якщо наш ключ уміє визначити, чи два символи строго рівні одне одному. Другій кімнаті потрібен ключ, який дозволяє порівнювати символи без урахування регістру.

Наприклад:

```lisp
a                                       ; => #\X
b                                       ; => #\x
c                                       ; => #\X

(key-characters a b)                    ; => NIL
(key-characters a c)                    ; => T
(key-characters-case-insensitively a b) ; => T
```

адже лише дуже поблажливі предикати рівності ігнорують регістр, порівнюючи два символи.

## 4. Лабіринт рядків тексту (англ. string)

Як і в лабіринті символів, першій кімнаті потрібен ключ, який перевіряє, чи два рядки тексту рівні; другій кімнаті потрібен ключ, який дозволяє порівнювати їх без урахування регістру.

Наприклад:

```lisp
a                                    ; => "pizza"
b                                    ; => "PIZZA"
c                                    ; => "pizza"

(key-strings a b)                    ; => NIL
(key-strings a c)                    ; => T
(key-strings-case-insensitively a b) ; => T
```

адже лише дуже поблажливі предикати рівності ігнорують регістр, порівнюючи два рядки тексту.

## 5. Лабіринт cons

Це великий лабіринт із багатьма кімнатами. Кожній кімнаті потрібен ключ, який перевірить, чи cons _містять_ рівні між собою речі. Кожна кімната перевірятиме рівність cons із різним вмістом: символів Lisp, чисел, символів, а деяким знадобляться гнучкіші визначення рівності для цього вмісту.

Наприклад:

```lisp
syms-a                                     ; => (left . right)
syms-b                                     ; => (up . down)
syms-c                                     ; => (left . right)
chars-a                                    ; => (#\x . #\y)
chars-b                                    ; => (#\x . #\Y)
chars-c                                    ; => (#\x . #\y)
nums-a                                     ; => (13 . 23)
nums-b                                     ; => (13 . 23.0)
nums-c                                     ; => (13 . 23)


(key-conses-of-symbols syms-a syms-b)      ; => NIL
(key-conses-of-symbols syms-a syms-c)      ; => T

(key-conses-of-characters chars-a chars-b) ; => NIL
(key-conses-of-characters chars-a chars-c) ; => T
(key-conses-of-characters-case-insensitively 
  chars-a chars-b)                         ; => T

(key-conses-of-numbers nums-a nums-b)      ; => NIL
(key-conses-of-numbers nums-a nums-c)      ; => T
(key-conses-of-numbers-of-different-types 
  nums-a nums-b)                           ; => T
```

адже навіть предикат рівності, який зазирає всередину cons, може виявитися недостатньо поблажливим, щоб ігнорувати регістр чи числовий тип під час порівняння.

## 6. Лабіринт масивів

Цей лабіринт простіший: у ньому лише дві кімнати. 
Першій потрібен ключ, який перевіряє, чи масиви є тими самими масивами. 
Другій потрібен ключ, який перевірить вміст масивів.

Наприклад:

```lisp
a                        ; => #[13 23]
b                        ; => #[13 23]
c                        ; => #[13 23.0]

(key-arrays a b)         ; => NIL
(key-arrays a c)         ; => NIL
(key-arrays-loosely a b) ; => T
(key-arrays-loosely a c) ; => T
```

адже лише дуже поблажливі перевірки на рівність зазирають у вміст масиву.
