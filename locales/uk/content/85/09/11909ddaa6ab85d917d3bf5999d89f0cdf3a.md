# Про

Charlists створюються за допомогою сигіла `~c`.

```elixir
~c"hello"
```

~~~~exercism/note
Зауважимо, що в старіших версіях Elixir charlists записуються як `'hello'` в одинарних лапках.
~~~~

Charlist - це масив цілих чисел. Цілі числа представляють значення Unicode певного символу, які також називають кодовими точками.

```elixir
[65, 66, 67]
# => ~c"ABC"
```

## Charlists _це_ масив

```elixir
~c"" === []
# => true

is_list(~c"hello")
# => true
```

Оскільки charlist - це масив, з ними можна працювати так само, як із будь-яким іншим масивом: за допомогою рекурсії та зіставлення зі зразком, або за допомогою модуля [`List`][list].

```elixir
[first_letter | _] = ~c"cat"
first_letter
# => 99

List.first(~c"hello")
# => 104
List.pop_at(~c"hello", 0)
# => {104, ~c"ello"}

```

Два масиви можна зʼєднати разом за допомогою [`++`][kernel-concat-list].

```elixir
~c"hi" ++ ~c"!"
# => ~c"hi!"
```

Чим довший перший масив, тим повільніша конкатенація, тому варто уникати повторного додавання елементів до масивів довільної довжини.

## Друкованість

Якщо масив цілих чисел містить лише цілі числа, які є кодовими точками друкованих символів, його буде показано як charlist. Навіть якщо його було задано за допомогою синтаксису `[]`.

```elixir
~c"ABC"
# => ~c"ABC"

[65, 66, 67]
# => ~c"ABC"
```

Якщо масив цілих чисел містить хоча б одну кодову точку недрукованого символу (наприклад, `0-6`, `14-26`, `28-31`), його буде показано як масив. Навіть якщо його було задано за допомогою синтаксису `~c""`.

```elixir
~c"ABC\0"
# => [65, 66, 67, 0]

[65, 66, 67, 0]
# => [65, 66, 67, 0]
```

Друкованість можна перевірити за допомогою [`List.ascii_printable?`][list-ascii-printable].

```elixir
List.ascii_printable?([65, 66, 67])
# => true
List.ascii_printable?([65, 66, 67, 0])
# => false
```

Варто памʼятати, що це два різні способи _показати_ ті самі дані. Значення строго рівні.

```elixir
~c"ABC" === [65, 66, 67]
# => true
```

Коли ми друкуємо масив за допомогою [`IO.inspect`][io-inspect], можна використати опцію [`:charlists`][inspect-opts], щоб керувати тим, як друкуються масиви.

```elixir
IO.inspect(~c"ABC", charlists: :as_charlists)
# => prints ~c"ABC"

IO.inspect(~c"ABC", charlists: :as_lists)
# => prints [65, 66, 67]
```

## Кодові точки

Щоб отримати кодову точку символу, можна поставити перед ним `?`.

```elixir
?A
# => 65

[?:, ?)]
# => ~c":)"
```

## Charlists проти рядків тексту

Charlists і рядки тексту (англ. string), що складаються з тих самих символів, не вважаються рівними.

```elixir
~c"hello" == "hello"
false
```

Кожне значення в charlist - це [кодова точка символу Unicode][unicode-table], тоді як у рядку тексту кодові точки закодовано як [UTF-8][utf8].

```elixir
IO.inspect(~c"tschüss", charlists: :as_lists)
# => prints [116, 115, 99, 104, 252, 115, 115]

IO.inspect("tschüss", binaries: :as_binaries)
# => prints <<116, 115, 99, 104, 195, 188, 115, 115>>
```

Звернімо увагу, як `ü`, кодова точка `252`, закодовано в UTF-8 як `195` і `188`.

**На практиці charlists використовують рідко**. Їхнє основне призначення - взаємодія з Erlang, зокрема під час роботи зі старішими бібліотеками, які не приймають бінарні дані як аргументи.

Працюючи з Elixir, **для зберігання тексту використовуймо рядки тексту**. Модуль `String` пропонує широкий вибір функцій для обробки тексту, яких немає для charlists.

Charlists можна перетворити на рядок тексту за допомогою [`to_string`][kernel-to-string].

```elixir
to_string(~c"hello")
# => "hello"
```
