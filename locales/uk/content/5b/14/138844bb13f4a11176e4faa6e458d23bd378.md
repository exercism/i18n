# Підказки

## 1. `weigh-crate`

- Достатньо одного слова з `sequences`.

## 2. `weigh-all`

- `parallel-map` (у [`concurrency.combinators`][combinators])
  має ту саму форму, що й `map`. Передайте цитату,
  яка перетворює один ящик на одну вагу.

## 3. `<crane>`

- Кортеж `crane` (слоти `lock` і `tonnage`) уже
  оголошено у файлі вправи.
- Використайте `<lock>` (у [`concurrency.locks`][locks]) для слота
  блокування та `0` для початкового тоннажу. `boa` будує
  кортеж зі значень у стеку в порядку слотів.

## 4. `hoist-crate`

- `with-lock ( lock quot -- )` виконує цитату, тримаючи
  блокування. Цитата має прочитати тоннаж крана,
  додати `weight` і зберегти результат назад. `change-tonnage`
  (автоматично згенерований `TUPLE:`) виконує саме крок
  читання-зміни-запису одним словом.
- Локальні змінні роблять це читабельним: `:: hoist-crate ( weight crane -- )`
  дозволяє посилатися на `weight` і `crane` усередині тіла блокування.

## 5. `crane-tonnage`

- Читачу теж потрібне блокування, щоб запис, який виконується,
  не виявився наполовину завершеним, коли ми його спостерігаємо.

## 6. `load-cargo`

- Для кожного ящика створіть `<promise>` і викличте `spawn`,
  щоб запустити потік, який зважує ящик, піднімає його
  і викликає `fulfill` для промісу. Виконане значення може бути
  будь-яким, наприклад сторожовим, адже проміс слугує лише
  для сигналу про завершення.
- Збирайте проміси в послідовність у міру запуску (локальні змінні
  роблять це зручним; `map` із лямбдою чудово підходить).
- Після запуску всіх потоків переберіть послідовність промісів
  і викличте `?promise` для кожного. `?promise` блокується, доки цей
  потік не завершиться, тож коли повертається останній проміс,
  усі піднімання вже завершено.
