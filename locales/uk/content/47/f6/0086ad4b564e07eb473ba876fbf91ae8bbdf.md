# Вступ

Функції ми вже розглядали в концепції [Основи][concept-basics], з такими, наприклад, прикладами:

```R
squareit <- function(x) {
    x * x
}

squareit(3)
#> [1] 9

# shorter form
squareit_short <- function(x) x ^ 2
```

Придивившись уважніше до визначення `squareit`, побачимо кілька частин:

- Функція приймає формальний параметр `x`.
- Є тіло функції, зазвичай у фігурних дужках `{ }`.
- Після створення обʼєкта функції його присвоюють змінній `squareit`.

У R функція є обʼєктом першого класу, подібно до чисел і рядків тексту (англ. string).
Отже, `squareit <- function...` є присвоєнням, синтаксично таким самим, як `x <- 42`.

## Аргументи

R не робить чіткого розрізнення між позиційними та іменованими аргументами, на відміну від інших скриптових мов, як-от Python і Julia.

У виклику функції значення можна передавати позиційно або за іменем.
Другий спосіб стає в пригоді для складних функцій із багатьма аргументами, де важко запамʼятати їхній порядок.

```R
f <- function(x, y) x / y

# call positionally
f(4, 2)
#> [1] 2

# call by name
f(y = 2, x = 4)
#> [1] 2
```

### Необовʼязкові аргументи

Типові значення аргументів можна вказати у визначенні функції, але вони повинні йти після всіх аргументів без типових значень.

Тоді ми можемо вибрати: прийняти типове значення чи перекрити його.

```R
g <- function(x, y = 2) x / y

# default y value
g(6)
#> [1] 3

# explicit y value
g(6, 3)
#> [1] 2
```

### Додаткові аргументи

Щоб приймати довільну кількість додаткових аргументів, у визначенні використовують `...` (еліпсис).
Будь-які додаткові значення з виклику функції можна перетворити на вектор, але читаймо далі, щоб дізнатися про альтернативний спосіб роботи з цими «крапковими аргументами» (*у кількох інших мовах їх називають «varargs»*).

```R
var_f <- function(x, y, ...) {
  print(c(...))
}

var_f(2, 3, "opt1", "opt2")
#> [1] "opt1" "opt2"
```

## Середовище функції

Раніше ми казали, що і формальні параметри, і тіло є складниками функції.

Насправді є третій складник: *середовище*, у якому функцію визначено.

Це можна проілюструвати на прикладі вкладених функцій:

```R
outer_func <- function(x) {
  inner_func <- function(y) {
    x * y
  }
  
  inner_func(3)
}

outer_func(5)
#> [1] 15
```

Виклик функції передає `x = 5` у зовнішню функцію, і це значення доступне в тілі цієї функції.

Внутрішня функція є *частиною* тіла зовнішньої функції й має доступ до значення `x`.
Інакше кажучи, `x = 5` перебуває в *середовищі* внутрішньої функції.

Технічно це називають [замиканням][wiki-closure].

Середовище особливо важливе для крапкових аргументів, адже будь-які значення, передані в такий спосіб, можна передати далі у виклики функцій у тілі функції.
Зовнішній функції не потрібно знати чи перейматися тим, що означають крапкові аргументи.

```R
f_var <- function(x, ...) {
  sum(x, ...)
}

x <- c(1, 2, NA, 6)

# for sum(), na.rm defaults to FALSE
f_var(x)
#> [1] NA

# pass through the na.rm value
f_var(x, na.rm = TRUE)
#> [1] 9
```

Цей прийом широко використовують бібліотеки Tidyverse, як-от [`stringr`][ref-stringr].
Багато функцій `stringr` - це зручна для користувача обгортка навколо низькорівневих функцій із `stringi` та базового R.

Додаткові аргументи, передані функціям `str_*()`, просто передаються далі тим низькорівневим функціям.

## Функції як повернені значення

Зовнішня функція може визначити внутрішню функцію (іменовану або анонімну, як описано нижче) і використати її як повернене значення.

Повернена функція міститиме середовище, у якому її було визначено.

```R
times_y <- function(x) {
  # anonymous function - see next section
  \(y) x * y
}

f <- times_y(3)
class(f)
#> [1] "function"

f(4)
#> [1] 12
```

## Анонімні функції

Коли ми визначаємо функцію, то зазвичай привʼязуємо отриманий обʼєкт функції до змінної:

```R
x <- 2

# function definition captures x from the environment
doubleit_short <- function(y) x * y
```

Це дозволяє легко використати функцію пізніше в скрипті, але таке привʼязування не є обовʼязковим.
Коротка функція, яку використовують лише раз, може стати в пригоді безпосередньо в цьому місці.
Без привʼязування до імені її називають *анонімною функцією*.

Анонімні функції використовують настільки часто, що (*починаючи з R v4.1.0*) існує скорочений синтаксис для їх визначення: слово `function` замінюють на зворотний слеш `\`.

Приклад цього ми бачили в попередньому розділі, присвяченому поверненим значенням.

## Копіювання при зміні

R дозволяє присвоювати значення окремим елементам вектора.
Якщо ми передаємо вектор як аргумент функції та змінюємо його в тілі функції перед поверненням, то отримуємо змінений вектор.

Але що сталося з початковим вектором?

```R
f <- function(vec) {
  vec[1] <- 42
  vec
}

vals <- c(1, 3, 4)

# f() returns a modified vector
f(vals)
#> [1] 42  3  4  

# the original vector is unchanged.
vals
#> [1] 1 3 4
```

R - мова, створена для науки про дані.
Збирання цих даних може коштувати багато часу, зусиль і, можливо, приголомшливих грошей: *важливо не пошкодити їх!*

Загальний принцип (з кількома винятками) - *копіювання при зміні*.
Якщо обʼєкт (наприклад, вектор) змінюють у спосіб, який міг би спричинити проблеми пізніше, R повертає *змінену копію* й залишає оригінал без змін.

Копіювання великих структур даних може бути обчислювально витратним, але зазвичай це менше зло, коли альтернатива - пошкодження даних.

Векторизація або функції вищого порядку можуть допомогти нам уберегтися від таких убивць продуктивності.
