# Вступ

У мові C **структура** - це складений тип даних, утворений з різних полів. Кожне поле має власний тип і розмір.

Наприклад, ось означення типу, утвореного з трьох цілих чисел: двох завбільшки 4 байти й одного завбільшки 8 байтів:

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

Структура також може містити інші структури:

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

Якщо одне з полів структури є масивом, усі байти, виділені під цей масив, є частиною структури. Якщо ж поле - це лише вказівник на масив, то масив потрібно зберігати деінде:

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## Вирівнювання

**Вирівнювання** типу - це невідʼємний степінь двійки (1, 2, 4, 8, ...), який задає вимогу до його адреси. Кожен обʼєкт цього типу має розташовуватися за адресою, кратною його вирівнюванню.

Для примітивного типу вирівнювання зазвичай дорівнює його розміру, тож, наприклад, `int32_t` зазвичай має вирівнювання 4 байти. Це означає, що `int32_t` потрібно виділяти на межах, кратних 4 байтам.

Вирівнювання структури, однак, дорівнює найбільшому вирівнюванню серед її полів. Так, наприклад, вирівнювання означеної вище `struct example` становитиме 8 байтів, адже саме таке вирівнювання має `uint64_t`.

Якщо вирівнювання поля структури менше за вирівнювання самої структури, після цього поля можуть вставлятися байти заповнення. Це гарантує, що наступні поля й структура загалом відповідають вимогам вирівнювання. На практиці це означає, що хоча ці байти заповнення й додаються до розміру структури, вони не беруть участі у значенні структури:

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

Зауважмо, що в означеній вище структурі поле 'one_byte' має вирівнювання 1 і може розташовуватися за будь-якою адресою. Оскільки поле 'four_byte' має вирівнювання 4, поля в структурі також мають дотримуватися меж, кратних 4 байтам. Це означає, що між будь-якими двома полями структури має бути кількість байтів, кратна 4. Оскільки 'one_byte' займає лише 1 байт, після нього вставляють 3 байти заповнення, щоб дотриматися цієї межі.

Суміжні поля групують, коли це можливо, щоб мінімізувати кількість потрібних байтів заповнення:

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

Це групування також має дотримуватися вирівнювання кожного поля:

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

Це означає, що зміна порядку полів у структурі іноді може призвести до різниці в її розмірі:

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

Зауважмо, що вирівнювання масиву збігається з вирівнюванням його базового типу:

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

Елементи масиву можна групувати так само, як якби вони не були частиною масиву:

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

Важливо зважати на всі можливі байти заповнення, коли ми звертаємося до структури в асемблері.

## Угода про виклик

Загалом значення передають у функції та повертають із них так, як і слід очікувати:

- Цілі значення, зокрема адреси памʼяті та `enum`, передають у регістрах загального призначення (GPR).
- Значення з плаваючою комою передають у регістрах `xmm`.

Структури ж - окремий випадок. Як правило, усі поля структури займають суміжний простір у памʼяті, і їх слід розміщувати в одному регістрі, коли це можливо:

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

Якщо в структурі є поля з цілими значеннями, а також поля зі значеннями з плаваючою комою, кожні послідовні 8 байтів структури слід класифікувати окремо:

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

Якщо цілі числа та значення з плаваючою комою опиняються в одних і тих самих 8 байтах, тип вважається цілим, і всі ці 8 байтів (разом зі значенням з плаваючою комою) розміщують у GPR:

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
Коли ми перетворюємо значення з плаваючою комою на ціле число за допомогою `cvtss2si` або `cvtsd2si`, це змінює організацію відповідних байтів.

Щоб перемістити необроблені байти з регістра `xmm` до GPR, не змінюючи бітового представлення, можна використати `movd` (для 32-бітних значень) і `movq` (для 64-бітних значень).
~~~~

Однак структури розміром понад 16 байтів зазвичай розміщують у памʼяті, незалежно від типу кожних 8 байтів:

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

Коли структуру передають як аргумент функції, використовується стільки регістрів, скільки потрібно. Якщо ж її розміщено в памʼяті, натомість використовують стек.

Схожі правила діють і для структур, які функція повертає. Зазвичай їх повертають передусім у `rax` і `rdx` (якщо значення ціле) або в `xmm0` і `xmm1` (якщо значення з плаваючою комою). Якщо ж структуру розміщено в памʼяті, той, хто викликає функцію, має зарезервувати для неї місце й передати адресу цього місця в памʼяті як неявний перший аргумент функції (у `rdi`). Тоді функція зберігає структуру в цьому місці й повертає її адресу в `rax`.
