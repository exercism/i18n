# Посібник зі стилю Rexx

Цей посібник описує стиль, призначений для файлів тестів і прикладів до вправ треку Rexx.

## Стандарт Rexx

Код має відповідати рівню 5.0 мови Rexx.

Можна використовувати розширення Regina Rexx і функції стандарту SAA для доступу до зовнішніх бібліотек.

Розширення AREXX і процедури роботи з буферами CMS використовувати не слід.

## Платформа

Середовище виконання тестів працює на Linux, тому у викликах інструкції ADDRESS можна використовувати лише команди, доступні в цьому середовищі. Їх слід чітко позначати в коментарях до коду.

## Назви

### Інструкції

Інструкції (зарезервовані слова) слід писати **_малими літерами_**. Отже, наведений нижче код відповідає рекомендаціям посібника зі стилю:

```rexx
do while input \= ''
  parse var input char +1 input
  say char
end
```

а жоден із наведених нижче варіантів вимогам не відповідає, тож не рекомендується:

```rexx
/* *** Not recommended *** */
Do While input \= ''
  Parse Var input char +1 input
  Say char
End
```

і:

```rexx
/* *** Not recommended *** */
DO WHILE input \= ''
  PARSE VAR input char +1 input
  SAY char
END
```

### Вбудовані функції (BIFs)

Вбудовані функції слід писати **_великими літерами_**, як показано тут:

```rexx
input = 'ABCDE'
say 'Length of input is' LENGTH(input)
say 'First letter of input is' SUBSTR(input, 1, 1)
```

### Мітки (функції, визначені користувачем)

Назви міток слід записувати у **_Pascal case_**, як показано тут:

```rexx
greeting = MyFuncSayHello()
say greeting

exit 0

MyFuncSayHello : procedure
  hello = 'Hello there!'
return hello
```

### Змінні

Назви змінних мають починатися з **_малої літери_**, тож однослівні змінні будуть записані малими літерами.

Багатослівні змінні можна записувати як у **_camel case_**, так і в **_snake case_**.

У межах треку прийнято таку домовленість: використовувати _camel case для більшості змінних_, а snake case залишати для змінних у тестах. Змінні, призначені для констант, за бажанням також можна писати великими літерами.

```rexx
input = 'ABCDE'
i = 0

personName = 'Alice'
test_person_description = 'Brown hair, blue eyes'

TRUE = 1
PI_CONSTANT = 3.14159
```

## Літерали

Рядки тексту (англ. string) можна позначати одинарними або подвійними лапками, **`'`** і **`"`** відповідно. Наведені нижче записи рівнозначні:

```rexx
say "Hello, world!"

say 'Hello, world!'
```

Кожен із них можна вкладати в інший без символу екранування:

```rexx
say "Please don't do that as it's wrong."

say 'He said, "Please sir, may I have more?".'
```

Якщо рядки тексту не містять вбудованих лапок і тому не потребують змішування лапок, їх краще позначати **_одинарними лапками_**.

### Шістнадцяткові та двійкові рядки тексту

Двійкові та шістнадцяткові значення можна подати, додавши до рядка тексту **`B`** або **`X`** відповідно. Приклади:

```rexx
hexvalue = "0A"X

binvalue = "00001010"B
```

Такі значення рекомендується брати в **_подвійні лапки_**.

Разом із попередньою рекомендацією позначати звичайні рядки тексту одинарними лапками ця домовленість має полегшити розпізнавання двійкових і шістнадцяткових рядків тексту в коді.

### Термінатор нового рядка

У багатьох мовах, що походять від UNIX або C, літерал **_`\n`_** використовується як термінатор **_нового рядка_**. Такий підхід поширений, і кілька вправ цього треку передбачають використання та обробку рядків тексту з цим термінатором.

Rexx не підтримує цей термінатор, а також не підтримує **_`\`_** (чи будь-який інший символ) як символ екранування.

Еквівалентом символу нового рядка в Rexx є (залежне від платформи) шістнадцяткове значення; на платформах, похідних від UNIX, він такий:

**_`"0A"X`_**

Еквівалент у Rexx для такого рядка тексту з вбудованими новими рядками (у bash):

```bash
printf "I have\nthree embedded\nnewlines.\n"
```

такий:

```rexx
say 'I have' || "0A"X || 'three embedded' || "0A"X || 'newlines.' || "0A"X
```

Вправи цього треку перетворюють **_`\n`_** на **_`"0A"X`_** лише тоді, коли це потрібно в рядку тексту, призначеному для показу на терміналі. Інакше рядок тексту **_`\n`_** просто тлумачитиметься як логічний новий рядок.

## Інші стилістичні рекомендації

Відступ може становити два, три або чотири символи ПРОБІЛУ, хоча перевага надається відступу в _два символи_ та послідовності у відступах.

Остання інструкція **_return_** у функції має вирівнюватися за назвою мітки, що чітко позначає кінець цієї функції, і _завжди_ має повертати значення.

Оператор логічного заперечення можна подати кількома різними символами. У цьому треку перевага надається символу **`\`**, і для узгодженості з цим вживанням оператор порівняння «не дорівнює» має бути **`\=`**.

Булеві значення (англ. Boolean) **`false`** і **`true`** подаються як **`0`** і **`1`** відповідно. Наперед визначених літералів для цих значень не існує.

Стани помилки позначаються за допомогою повернених значень: на помилку вказує або порожній рядок тексту, **`''`**, або **`-1`**, залежно від контексту.

## Структура файлу тестів

Кожна вправа має один файл тестів, розташований у каталозі верхнього рівня цієї вправи, з назвою: `<exercise>-check.rexx`

Якщо дотримуватися цієї домовленості, файл тестів для вправи `acronym` матиме назву `acronym-check.rexx`

Файл тестів кожної вправи має вільну, але цілком визначену структуру, яка і допомагає учням зрозуміти вимоги вправи, і полегшує роботу контрибʼютора, який реалізує або розширює тести.

Нижче наведено фрагмент файлу тестів для вправи `acronym`:

```rexx
/* Unit Test Runner: t-rexx */
function = 'Abbreviate'
context('Checking the' function 'function')

/* Unit tests */
check('basic' function||'("Portable Network Graphics")',,
      function||'("Portable Network Graphics")',, 'to be', 'PNG')

check('lowercase words' function||'("Ruby on Rails")',,
      function||'("Ruby on Rails")',, 'to be', 'ROR')
```

Файл поділено на два логічні розділи, кожен з яких позначено рядком коментаря.

У першому розділі назву **_функції, яку тестують_** (тут це функція `Abbreviate`), присвоюють змінній `function`. Ця назва змінної описова, але довільна, і на неї посилаються далі у файлі всюди, де потрібна назва функції, яку тестують.

У цьому ж розділі є виклик функції `context`, призначення якого очевидне.

Наступний розділ містить модульні тести. Кожен виклик функції `check` є окремим модульним тестом. Очікувані параметри:

```rexx
check(<test description>,
      <function invocation>,
      [<actual result variable>],
      <test comparator>,
      <expected result>)
```

**\<test description>** - це рядок тексту, який виводиться під час виконання тесту. Щоб опис був якомога детальнішим, рекомендується використовувати рядок тексту, який складається з назви функції, яку тестують, і переданих їй аргументів, як у прикладі.

**\<function invocation>** - це сам виклик функції, тож його повернене значення передається в `check` для порівняння в тесті.

**\<actual result variable>** - це необовʼязковий параметр; якщо його використано, це назва змінної, що містить значення для порівняння в тесті.

Причина його використання - дати змогу перевіряти результати, _похідні від_ поверненого значення функції, яку тестують, а не саме повернене значення. Очевидний приклад, коли повернене значення - це рядок тексту обсягом у кілька кілобайтів, як показано нижче:

```rexx
expected_length = LENGTH(FUT(...))

check('...', FUT(...), expected_length, 'to be', 50)
```

Зауважимо, що аргумент \<function invocation> все одно потрібно передати.

**\<test comparator>** - це рядок тексту, що описує тип порівняння, яке потрібно виконати. У більшості випадків це рядок тексту 'to be', який запитує порівняння на рівність. Інші варіанти порівняння дивіться в документації до framework для модульних тестів.

**\<expected result>** - це, очевидно, значення, з яким порівнюється фактичний результат.

У файлі тестів можна вільно оголошувати змінні (звісно, до їх використання) і використовувати їх замість літералів як аргументи для `check`.
