# Вступ

Оголошення `GENERIC:` створює слово, поведінка якого залежить від *класу* одного з його аргументів. Конкретну поведінку задають *методи*, визначені за допомогою `M:`.

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

Коли викликають `area`, Factor зазирає на верхівку стеку, знаходить найконкретніший метод, чий клас збігається, і запускає його. Із локальними змінними можна використовувати `M::`:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

Дженерики дають змогу пізніше додавати нові представлення, не змінюючи код, який їх викликає: `area` уже працював для `square` і `circle`, а метод для `rectangle` підхоплюється автоматично всюди, де викликають `area`.

## Коли доречно використати дженерик

До `GENERIC:` варто звертатися, коли:

- Одна операція має *справді різні* реалізації для різних вхідних даних.
- Ми очікуємо, що нові типи додасть майбутній код.
- Ми хочемо, щоб система типів вимагала визначень для кожного класу окремо.

Якщо вся варіація зводиться до невеликого переліку міток, `case` простіший.

## Приєднання до міксину за допомогою `INSTANCE:`

Міксином називають дженерик-клас, який є *відкритим*: будь-хто може зареєструвати новий клас як його члена. Багато вбудованих протоколів Factor (послідовності, множини, потоки, …) надаються як міксини, тож власний кортеж може долучитися до типових методів протоколу, оголосивши себе його екземпляром:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

Після `INSTANCE:` кожен типовий метод `M: shape …` автоматично диспетчеризується на `my-shape`, і будь-який код, який вимагає `shape`, приймає `my-shape`. `M:` призначений для додавання методів до дженерика, а `INSTANCE:` - для приєднання класу до міксину.

## `TYPED::` - перевірені вхідні дані для звичайного слова

`GENERIC:`/`M:` вибирають метод за класом аргументу. Іноді диспетчеризація не потрібна - потрібне лише *одне* слово, яке вимагає, щоб його вхідні дані належали до заданого класу. `TYPED::` (зі словника `typed`) - це `::` з класом, записаним після кожного імені вхідних даних:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

`n: integer` читається так само, як локальні змінні, які ми вже використовуємо, тільки клас записано після двокрапки. Диспетчеризації тут немає: одне визначення, одна поведінка. Але тепер кожен аргумент перевіряється на відповідність своєму класу: невідповідність на кшталт `"x" triple` відхиляється (*expected input value of type integer but got string*), а не проходить крізь мовчки.

Вихідні дані можна анотувати так само. Слово `yes?` задає типи і для вхідних даних, і для результату:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## Математичні функції та константи

У цій вправі ми також спираємося на кілька слів зі словників `math.constants` і `math.functions`, з якими тут зустрічаємося вперше:

- `pi` - константа π зі словника `math.constants`.
- `sin ( x -- y )`, `cos ( x -- y )` - синус і косинус кута в радіанах.
- `e^ ( x -- y )` - число `e` у степені `x`. (Для довільної основи використовуйте `^`.)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
