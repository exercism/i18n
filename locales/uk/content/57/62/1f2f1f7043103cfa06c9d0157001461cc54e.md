# Вступ

Функція називається [хвостово-рекурсивною][recursion-tc], якщо _останнє_, що вона виконує, - виклик самої себе.

Щоразу, коли викликають будь-яку функцію, на верхівку [стека викликів функцій][call-stack] кладуть _кадр стека_ з її локальними змінними та аргументами. Коли функція повертає значення, кадр стека знімають зі стека.

Хвостово-рекурсивні функції дозволяють застосувати [оптимізацію хвостових викликів][tail-call-optimization] (або усунення хвостових викликів). Завдяки цій оптимізації наступний виклик функції може повторно використати останній кадр стека, якщо попередня функція вже точно не потребуватиме його. Це зменшує ризик переповнення стека викликів функцій. Переповнення стається тоді, коли кадрів на стеку так багато, що не залишається памʼяті створити ще один.

## Оптимізація хвостових викликів в Elm

За певної умови компілятор Elm здатен автоматично виконувати оптимізацію хвостових викликів під час компіляції в JavaScript.

Оптимізація може статися для рекурсивної функції, коли _останню_ операцію в гілці виконує виклик самої функції у простому застосуванні функції. Розглянемо кілька прикладів:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

У наведеній вище реалізації немає хвостової рекурсії, бо остання операція в гілці `else` - це множення `n *`.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

У наведеній вище реалізації є хвостова рекурсія, і її буде оптимізовано, бо остання операція в гілці `else` - це виклик `factorialHelper`, який викликає сам себе. Це було б неможливо для функції із сигнатурою типу `Int -> Int`, і на практиці оптимізації хвостових викликів часто досягають, визначаючи допоміжні функції.
