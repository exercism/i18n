# Докладніше

Список ключових слів - це список [кортежів][exercism-tuples] `{key, value}`. Є два способи записати список ключових слів:

```elixir
# concise
[month: "April", year: 2018]

# explicit
[{:month, "April"}, {:year, 2018}]
```

## Ключі мають бути атомами

Не кожен список двоелементних кортежів є списком ключових слів. Ключі мають бути атомами:

```elixir
Keyword.keyword?([{"month", "April"}])
# => false
```

Якщо в ключі потрібні символи, відмінні від літер, цифр і `_`, його треба взяти в лапки. Проте це не робить його рядком тексту (англ. string) - це все ще атом.

[//]: # (elixir-formatter-disable-next-block)

```elixir
Keyword.keyword?(["day of week": "Monday"])
# => true
```

## Ключі можуть повторюватися

Ключі в списку ключових слів можуть повторюватися, а [пари ключ-значення впорядковані][keyword-duplicate-keys-and-ordering]. Коли ми намагаємося отримати одне значення за певним ключем, ми отримаємо перше значення, а решту значень за тим самим ключем буде мовчки проігноровано.

```elixir
list = [month: "April", month: "May"]

Keyword.get_values(list, :month)
# => ["April", "May"]

Keyword.get(list, :month)
# => "April"
```

Списки ключових слів також підтримують [_поведінку Access_][access-behaviour].

```elixir
list[:month]
# => "April"
```

## Списки ключових слів як опції

Завдяки своїм особливостям списки ключових слів стали типовим механізмом передавання опцій у функції в Elixir.

Коли ми вивчали `if`, ми бачили спеціальний коротший синтаксис:

```elixir
if age >= 16, do: "beer", else: "no beer"
```

Може здатися, що `if` приймає два аргументи, але пара `do:` та `else:` насправді є одним аргументом - списком ключових слів. Той самий код можна записати так:

[//]: # (elixir-formatter-disable-next-block)

```elixir
if age >= 16, [do: "beer", else: "no beer"]
# or
if age >= 16, [{:do, "beer"}, {:else, "no beer"}]
```

Використання списків ключових слів як опцій функцій настільки поширене, що Elixir дозволяє [пропустити квадратні дужки, коли список ключових слів є останнім аргументом][keyword-call-syntax], переданим у функцію.

Оскільки кортежі, списки, мапи та інші структури в синтаксисі Elixir обробляються так само, як виклики функцій, ця особливість доступна й для них.

```elixir
[1, 2, three: 3]
# => [1, 2, {:three, 3}]
```

## Зіставлення зі зразком

Щоб успішно зіставити список ключових слів зі зразком за допомогою короткого синтаксису, нам доведеться вказати всі ключі в правильному порядку. Через це зіставлення зі зразком навряд чи варто обирати для роботи зі списками ключових слів. Натомість скористаймося модулем [`Keyword`][keyword] або [_поведінкою Access_][access-behaviour].

```elixir
[month: month] = [month: "April", year: 2018]
# => ** (MatchError) no match of right hand side value: [month: "April", year: 2018]

[year: year, month: month] = [month: "April", year: 2018]
# => ** (MatchError) no match of right hand side value: [month: "April", year: 2018]
```

## Списки ключових слів проти мап

|                  | Список ключових слів          | Мапа                                 |
| ---------------- | ----------------------------- | ------------------------------------ |
| Тип ключа        | Атоми                         | Будь-який, можна змішувати в одній мапі |
| Повторювані ключі | Так                          | Ні                                   |
| Порядок ключів   | Зберігається                  | Не зберігається                      |
| Доступ           | `list[:key]`, `Keyword.get/2` | `map.key`, `map[:key]`, `Map.get/2`  |
| Час доступу      | Лінійний                      | Логарифмічний                        |
| Зіставлення зі зразком | Не дуже корисне         | Корисне                              |

Швидший час доступу, гнучкий тип ключа та корисне зіставлення зі зразком роблять мапи типовим вибором у більшості випадків.

Використовуймо списки ключових слів, коли даних небагато, але потрібні повторювані ключі або ключі в певному порядку.
