# Вступ

Система помилок у Factor складається з трьох частин: `throw`, щоб сигналізувати про помилку, `recover`, щоб її опрацювати, і `ERROR:`, щоб визначити власний різновид помилки.

## `throw`

`throw` (з [`kernel`][kernel]) породжує помилку. Аргументом може бути *будь-яке* значення: рядок тексту (англ. string), число або кортеж. Саме воно й стає помилкою, яку потім можна оглянути:

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw` не повертає керування; решту поточного слова пропущено.

## `recover`

`recover` (з [`continuations`][continuations]) виконує роль try/catch у Factor. Він приймає *try*-quotation і *recovery*-quotation:

```
recover ( try recovery -- )
```

Якщо `try` завершується, не породивши помилки, `recovery` ігнорується. Якщо `try` породжує помилку, ця помилка кладеться на стек, і запускається `recovery`:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

`when` із [`kernel`][kernel] - природний супутник: він запускає quotation лише тоді, коли значення на вершині стека правдиве:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:` визначає клас кортежу *і* слово, яке створює новий примірник і породжує його:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

Помилка без слотів - це просто `ERROR: name ;`; виклик `name` породжує порожній примірник. Кортежі, визначені з `ERROR:`, мають предикат класу `name?`, який можна використати, щоб перевірити, чи була перехоплена помилка саме цього типу.

## Як дістати значення зі слотів

Перехоплена помилка - це просто кортеж, тож кожен слот, оголошений у `ERROR:`, має такий самий автоматично згенерований читач `slot>>`, як і будь-який інший кортеж.

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
