# Тести

Кожна вправа надає модульні тести.
Реалізацію надаємо ми.
Кожен файл створює консольний виконуваний файл, який запускає тести.
Запуск виконуваного файлу з тестами виводить повідомлення для кожного невдалого тесту та повертає ненульовий код виходу, коли тести не проходять.

*Зауваження* Ваш код перевіряється набором тестів щоразу, коли ми збираємо свій проєкт.
Якщо код не проходить один або більше тестів, але є коректним кодом D, його все одно буде скомпільовано.

Робота над кожною вправою складається з таких кроків:

* Запуск тестів за допомогою `dub test`
  * Якщо ми вирішили не встановлювати DUB, натомість скористаємося `dmd source/*.d -de -w -main -unittest`, а потім запустимо отриманий виконуваний файл.
* Для кожного модульного тесту:
  * Задовольнити помилки компіляції, щоб тест не проходив.
  * Реалізувати рівно стільки, щоб тест пройшов.
  * Відрефакторити свою реалізацію, щоб покращити читабельність, зменшити дублювання тощо.
  * Увімкнути наступний тест

*Зауваження:* D підтримує модульне тестування безпосередньо в мові, тому зазвичай модульні тести лежать у тому самому файлі, що й реалізація.
Модульні тести виконуються перед тілом main і вмикаються у фінальному виконуваному файлі за допомогою перемикача компілятора **-unittest**.

## Як читати вивід модульних тестів

Якщо всі тести проходять, вивід тестів може мати такий вигляд:

```none
$ dub test
             Generating test runner configuration 'dnd-character-test-library' for 'library' (library).
    Starting Performing "unittest" build using dmd for x86_64.
    Building dnd-character ~master: building configuration [dnd-character-test-library]
     Linking dnd-character-test-library
     Running dnd-character-test-library
1 modules passed unittests
```
