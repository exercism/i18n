# Вступ

## Класи

Час дістатися до однієї з основних парадигм C++: обʼєктно-орієнтованого програмування (ООП).
ООП будується навколо `classes`: це визначені користувачем типи даних із власним набором повʼязаних функцій.
Почнімо з основ, а складніші теми розглянемо далі за деревом силабусу.

### Члени

Класи можуть мати **змінні-члени** та **функції-члени**.
До них звертаються через оператор **вибору члена** `.`.
Як і у випадку зі змінними поза `classes`, змінні-члени бажано ініціалізувати значенням одразу під час оголошення.
Це значення стане типовим для новостворених обʼєктів цього класу.

### Інкапсуляція та приховування інформації

Класи дають змогу обмежити доступ до своїх членів.
Є два базові `access specifiers`: `private` і `public`.
`private`-члени недоступні ззовні класу.
До `public`-членів можна звертатися вільно.
Усі члени `class` типово є `private`.
Лише члени, явно позначені як `public`, можна вільно використовувати поза класом.

### Базовий приклад

Означення `class` можна побачити в наступному прикладі.
Звернімо увагу на `;` після означення:

```cpp
class Wizard {
  public:               // from here on all members are publicly accessible
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

До всіх змінних-членів можна звертатися зсередини класу.
Погляньмо на `damage` всередині функції `cast_spell`.
Читати або змінювати `private`-члени поза класом не можна:

```cpp
Wizard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

### Конструктори

Конструктори дають змогу присвоювати значення змінним-членам під час створення обʼєкта.
Вони мають ту саму назву, що й `class`, і не мають типу поверненого значення.
Клас може мати кілька конструкторів.
Це стає в пригоді, коли не завжди потрібно задавати всі змінні.
Іноді може знадобитися залишити все типовим, але змінити змінну `name`.
А для могутнього `Wizard` може знадобитися ще й змінити шкоду, тож потрібні два `constructors`.

```cpp
class Wizard {
  public:
    Wizard(std::string new_name) {
      name = new_name;
    }
    Wizard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizard el{"Eleven"};       // deals  5 damage
Wizard vecna{"Vecna", 50}; // deals 50 damage
```

Тема конструкторів велика й має багато нюансів.
Якщо ми явно не визначаємо `constructor` для свого `class`, то (і тільки тоді) компілятор зробить це за нас.
Саме це сталося в першому прикладі вище.
Обʼєкт _silverhand_ створюється викликом конструктора за промовчанням, жодних аргументів не передано.
Усі змінні набувають значення, зазначеного в означенні класу.
Якби ми не вказали жодних значень у цьому означенні, змінні могли б залишитися неініціалізованими, що могло б мати непередбачувані наслідки.

## Структури

Структури походять від первісних коренів мови в C і такі ж давні, як сам C++.
По суті, вони те саме, що й `classes`, з однією важливою відмінністю.
Типово все в `class` є `private`.
Структури ж, навпаки, є `public`, доки не визначено інше.
За домовленістю ключове слово `struct` часто використовують для **структур, що містять лише дані**.
Ключове слово `class` краще підходить для обʼєктів, які повинні гарантувати певні властивості.
Таким інваріантом може бути те, що `damage` вашого `class` `Wizard` не може стати відʼємним.
Змінна `damage` приватна, і будь-яка функція, яка змінює шкоду, гарантуватиме збереження інваріанта.
