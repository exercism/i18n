# Про біти

Двійкові цифри зрештою прямо відповідають стану транзисторів у процесорі чи оперативній памʼяті: «увімкнено» чи «вимкнено».

Низькорівнева робота з бітами, яку неформально називають «жонглюванням бітами», особливо важлива в системних мовах.

Високорівневі мови, як-от Kotlin, зазвичай приховують більшість цих деталей.
Однак базовий набір операцій на рівні бітів [доступний][ref-bitwise].

~~~~exercism/note
Щоб побачити двійковий вивід у читабельному вигляді, майже всі приклади нижче потрібно обгорнути у функцію [`Integer.toBinaryString()`][web-binstring] або перетворити за допомогою `toString(radix = 2)`.
 
Це відволікає візуально, тому більшість входжень цієї функції прибрано з прикладів, а результати подано в записі `0b`.

## Операції зсуву бітів

Типи `Int` і `Long`, як знакові, так і беззнакові, можна подати як рядок тексту (англ. string) з одиниць і нулів і працювати з ними як із послідовністю бітів.

Можливо, несподівано, але типи `Byte` і `Short` не сумісні з більшістю побітових операцій у Kotlin.
У всіх прикладах нижче використано 32-бітні цілі числа (`Int` чи `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Зсуви переміщують усе ліворуч або праворуч на вказану кількість позицій.
Частина бітів зникає з одного кінця, а інший кінець заповнюється нулями чи одиницями.

- Зсув ліворуч за допомогою `shl`: заповнення нулями.
- Зсув праворуч за допомогою `shr` чи `ushr`: заповнення нулями для додатних чисел (про відʼємні числа йдеться в наступному розділі).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Кожен зсув ліворуч подвоює значення, а кожен зсув праворуч ділить його навпіл (з відкиданням дробової частини).
Це помітніше в десятковому записі:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Такий зсув бітів набагато швидший за «справжню» арифметику, тому цей прийом дуже популярний у низькорівневому програмуванні.

### Зсув відʼємних цілих чисел

З _відʼємними цілими числами_ варто бути трохи обережнішими.

Відʼємні значення зберігаються у формі [доповняльного коду][wiki-2complement], тобто найлівіший біт дорівнює 1.
Для зсуву ліворуч це не проблема, але як під час зсуву праворуч заповнювати найлівіші біти?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

Оператор [`shr`][ref-shr] виконує [арифметичний зсув][wiki-arithmetic], зберігаючи знаковий біт.

Оператор [`ushr`][ref-ushr] виконує [логічний зсув][wiki-logical] і заповнює нулями, ніби число беззнакове.

## Побітова логіка

Ми бачили в [концепції булевих значень][concept-booleans], що оператори `&&` (логічне і), `||` (логічне або) та `!` (логічне заперечення) застосовують до булевих значень (англ. Boolean).

Існують відповідні оператори `and`, `or`, `xor` ([виключне «або»][wiki-xor]) для порівняння бітів у двох цілих числах, а також функція `inv` (інверсія), яка перевертає всі біти.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
