# Nil

У Crystal є тип [`Nil`][nil], який може мати лише одне значення: `nil`.
Його використовують, щоб позначити відсутність значення; він подібний до `null` або `None` в інших мовах.

Значення `nil` можуть повертати різні методи, наприклад [`String#[]?`][string-index], який повертає `nil`, якщо індекс виходить за межі.

```crystal
"foo"[10]? # => nil
```

Crystal має так звані **NULL REFERENCE CHECKS**, а це означає, що всі типи не можуть набувати значення `nil`, якщо не вказати цього явно.
Тобто не можна присвоїти `nil` змінній, якщо явно не оголосити її як тип `Nil`.
Своєю чергою, це означає, що компілятор автоматично перевірятиме нульові посилання.

## Неправдиве значення

Існують різні підходи до роботи зі значеннями `nil`.
`nil`, як і `false`, є [неправдивим][truthy-falsey] значенням.
Це означає, що в умовних конструкціях та інших місцях, де потрібне неправдиве або правдиве значення, він поводитиметься так само, як `false`.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Це означає, що правдива гілка не виконається, якщо змінна, яка може містити `nil`, має значення `nil`.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Перевірка на nil

У Crystal є метод, який дає змогу перевірити, чи значення дорівнює `nil`.
Він називається [`nil?`][nil?] і доступний для всіх обʼєктів.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Ситуація трохи інша, якщо просто використати значення в умовній конструкції, адже в попередніх прикладах і `false`, і `nil` вважалися б неправдою.
Тут неправдивим вважається лише `nil`, бо якби це був `false`, то він не був би `nil`, а отже, був би правдивим.

## Оператор or

Найпростіший спосіб мати справу зі значеннями `nil` - подбати про те, щоб вони взагалі ніколи не ставали `nil`.
Оператор or ([`||`][or], логічне або) часто використовують, коли мають справу з `Bools`, але якщо правильно його зрозуміти, його можна застосовувати й для роботи зі значеннями `nil`.
Оператор or перевіряє, чи перше значення є правдивим; якщо ні, використовується друге значення.
Це дає змогу зробити так, що якщо значення дорівнює `nil`, воно буде неправдивим, і тому використається друге значення.

```crystal
"foo"[10]? || "bar" # => "bar"
```
