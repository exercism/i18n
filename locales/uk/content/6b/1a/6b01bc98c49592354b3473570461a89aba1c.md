# Про

## Модулі

Код Gleam організовано в модулі, і кожен файл є окремим модулем Gleam.

Дотепер ми писали функції за допомогою синтаксису `pub fn`, який визначає функцію, загальнодоступну для інших модулів. Функції, визначені за допомогою `fn`, є приватними для модуля, у якому їх визначено, і не можуть використовуватися іншими модулями.

```gleam
// This function is public
pub fn add(x, y) {
  x + y
}

// This function is private
fn subtract(x, y) {
  x - y
}
```

Модулі Gleam мають назви, і назва ґрунтується на шляху до файлу в каталозі `src` або `test`.

Наприклад, модуль, визначений у `src\geometry\rectangle.gleam` (у Windows) або `src/geometry/rectangle.gleam` (у UNIX-подібних операційних системах), матиме назву `geometry/rectangle`.

## Імпорт функцій з інших модулів

Доступ до функцій, визначених в інших модулях, здійснюється через імпорт.
Усі функції, які модуль надає, стають доступними, коли ми імпортуємо цей модуль.
Але те, як до них отримати доступ, залежить від того, як імпортовано модуль.

Типовими є кваліфіковані імпорти, а доступ до функції в такому модулі (наприклад, функції `map` у модулі `gleam/list`) здійснюється додаванням префікса назви модуля (`list.map`).

```gleam
// Import the int module
import gleam/int

pub fn run(x: Int) -> String {
  // Use the to_string function from the int module
  int.to_string(x)
}
```

Типово назва, яку використовують для посилання на модуль, є останньою частиною назви модуля, у цьому випадку `int`, але це можна змінити за допомогою ключового слова `as`.

```gleam
// Import the int module and refer to it as i
import gleam/int as i

pub fn run(x: Int) -> String {
  i.to_string(x)
}
```

Некваліфіковані імпорти дають прямий доступ до наданих функцій цього модуля без додавання префікса.

```gleam
// Import the to_string function from the int module
import gleam/int.{to_string}

pub fn run(x: Int) -> String {
  to_string(x)
}
```

Кваліфіковані імпорти кращі, бо чіткіше показують читачеві, звідки походить функція, і допомагають уникати конфліктів імен.
