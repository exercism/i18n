# Вступ

**Цикл** - це послідовність інструкцій, які потенційно виконуються більше ніж один раз, доки не буде досягнуто кінцевої умови.

У x86-64 цикл зазвичай створюють за допомогою переходу до попередньої мітки:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Зауважмо, що безумовний перехід до попередньої мітки завжди передає виконання на цю мітку.
Це означає, що цикл буде повторюватися вічно, якщо тільки немає іншого переходу за межі послідовності, що повторюється.

Наприклад, цей цикл не завершується:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

А цей цикл може завершитися, залежно від того, чи виконається умова:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Цикли з лічильником

Цикл із лічильником майже завжди завершується однаково: інструкція, яка оновлює лічильник або порівнює два значення, одразу за якою йде умовний перехід, що вирішує, чи повертатися ще раз.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0` не потрібна в наведеному вище коді, бо `sub rsi, 1` уже встановлює `zero flag (ZF)`, коли результат дорівнює `0`.

Хоча `cmp` - основний спосіб перевірки умов в асемблері, багато інструкцій оновлюють прапорці.
Наприклад, багато інструкцій цілочисельної арифметики чи порозрядних інструкцій оновлюють `ZF`, коли результат дорівнює `0`, та `SF`, коли результат відʼємний (тобто старший біт установлено).

Можна переглянути [довідку][reference], щоб побачити, на які прапорці впливає кожна інструкція.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Зауважмо, що в наведеному вище прикладі передбачається, що `rsi` більше ніж `0`.
Якби він дорівнював `0`, то `sub rsi, 1` зменшила б `rsi` до `-1`, а це дуже велике беззнакове число.
Знадобилося б ще `18,446,744,073,709,551,615` ітерацій, перш ніж цикл нарешті завершився б.
Крім того, оскільки довжина масиву дорівнює `0`, будь-яке звернення до памʼяті буде поза межами.

Якщо немає жодних гарантій щодо довжини масиву, є два поширені підходи.

Перший - перенести кінцеву умову на початок циклу, а в кінці зробити безумовний перехід:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

Другий - зробити одну перевірку на масив нульової довжини перед початком циклу:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Цей другий підхід зазвичай ефективніший за перший, бо в тілі циклу менше розгалужень.
Дізнаємося про це більше в одній із наступних концепцій.

~~~~exercism/advanced
У деяких ситуаціях сучасні процесори здатні обʼєднати дві різні інструкції в одну операцію.
Таку оптимізацію називають **macrofusion**.

Багато арифметичних інструкцій, як-от `sub` й `add`, а також `cmp` і `test`, зазвичай поєднуються з умовним переходом, який іде відразу після неї.
Це означає, що інструкцію, як-от `cmp rax, rdx`, за якою відразу йде умовний перехід, процесор зазвичай може розглядати як одну операцію.

Macrofusion залежить від процесора, і є певні варіації щодо того, які інструкції поєднуються з яким умовним переходом.

Корисна довідка - [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
Розділ 3.4.2.2 (Optimizing for Macrofusion) з [Intel optimization reference manual][intel-opt] також наводить перелік пар інструкцій, які можна поєднати, для процесорів Intel.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
