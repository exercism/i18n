# Вступ

Потоки Factor - це *кооперативні корутини*: вони поділяють один потік операційної системи, передають керування одне одному під час введення-виведення та в явних точках yield і ніколи не виконуються по-справжньому одночасно. Усе, що ми робимо *між* точками yield, виконується як один неперервний крок. Але якщо складена операція (читання-зміна-запис) передає керування десь посередині, інший потік може вклинитися й змінити світ, перш ніж ми завершимо, і це і є гонка.

У цій вправі ми розглянемо чотири примітиви, які трапляються знову і знову:

## `parallel-map`: fork/join над послідовністю

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

У [`concurrency.combinators`][combinators]. Створює по одному потоку на кожен елемент, виконує quotation і збирає результати назад у нову послідовність у тому самому порядку:

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`: запуск потоку

```
spawn ( quot name -- thread )
```

У [`threads`][threads]. Quotation виконується паралельно; `name` - це мітка для налагодження. Повернений дескриптор потоку на цьому рівні майже нецікавий, тож просто відкиньмо його через `drop`.

## Проміси: одноразова передача значення

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

У [`concurrency.promises`][promises]. Проміс - це одноразова поштова скринька: один потік його виконує, інші читають. `?promise` блокується, доки проміс не буде виконано, а потім повертає значення.

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

`spawn` + `<promise>` - це те, з чого побудовано `parallel-map`; писати їх вручну буває корисно, коли кожне завдання робить щось інше, ніж «обчислення одного елемента».

Типова схема розгалуження й обʼєднання над послідовністю така: для кожного вхідного значення створити новий проміс, запустити потік, який виконує роботу та викликає `fulfill` для проміса, зібрати всі проміси в послідовність, а потім викликати `?promise` для кожного, щоб дочекатися завершення. Локальні змінні роблять це читабельним: привʼяжімо проміс до імені через `:>` усередині лямбди `[| | ]`, щоб запущений quotation міг його захопити:

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## Блокування: взаємне виключення

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

У [`concurrency.locks`][locks]. Лише один потік може одночасно утримувати певне блокування. `with-lock` захоплює блокування, виконує quotation і звільняє його, навіть якщо quotation викине виняток.

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

Використовуймо блокування щоразу, коли значення *читає або записує більш ніж один потік* і операції над ним не є природно атомарними. І читання, і запис потребують блокування: читання, яке передає керування посередині, може побачити розірваний стан.
