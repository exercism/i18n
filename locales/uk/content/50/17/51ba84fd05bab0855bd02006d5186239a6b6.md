# Докладніше

Хоч у Swift є багато різних типів, кожен із них належить до однієї з двох класифікацій: _типи значень_ і _типи посилань_. У Swift [структури є типами значень][structs-are-value-types], а [класи є типами посилань][classes-are-reference-types].

Головна відмінність між типами значень і типами посилань полягає в тому, що коли тип значення присвоюють змінній або константі чи передають у функцію, насправді присвоюється чи передається копія значення, а не саме те значення. Зміна однієї копії структури не вплине на інші копії. З типами посилань присвоюється чи передається посилання на це значення, тож два різні імена можуть посилатися на той самий екземпляр класу. Це може призвести до зміни початкового екземпляра, коли до нього звертаються під іншим іменем.

Отже, маючи структуру й клас, які описують персонажа гри, та їхню ігрову статистику, можна подивитися, що станеться, коли ці обʼєкти копіюють і змінюють.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

Звернімо увагу, як зміна властивостей `charB` вплинула на `charA`, адже обидва імена посилаються на той самий екземпляр. Звернімо також увагу, що разом зі статистикою обох персонажів змінюються й типи значень усередині типу посилання. Однак це не порушує поведінки типів значень, бо `charA.stats` - це той самий екземпляр `CharacterStats`, що й `charB.stats`, адже `charA` і `charB` посилаються на той самий екземпляр класу `GameCharacter`. Як бачимо, копії цих типів значень не впливають одна на одну.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

Саме тому структури вимагають ключового слова `mutating` перед методами, які змінюють стан властивостей структури. Зміна властивості структури насправді створює нову копію структури з новим значенням цієї властивості, і ця нова копія замінює стару. Це наочний індикатор того, що для значень цього типу може відбуватися таке копіювання і заміщення.

Це має побічний наслідок: будь-які екземпляри структур, у яких змінюються змінні властивості, чи то через виклик мутувальних функцій, чи то через пряме присвоєння, _мають_ бути присвоєні змінним, а не константам. Інакше компілятор видасть помилку:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

Початкові значення все ще можна створити й отримати до них доступ, але змінювати їх не дозволено. Це обмеження не поширюється на класи. Якщо екземпляр класу присвоїти імені через `let`, то константа зберігає посилання на екземпляр, і саме воно не може змінитися, а не сам екземпляр. Тож сам екземпляр може змінюватися, але посилання не можна змінити так, щоб воно вказувало на інший екземпляр.

Підсумок того, що можна змінювати у структурах і класах, оголошених через `let` або `var`, має такий вигляд

|         | **struct**                                                                                  | **class**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _Не можна_ присвоїти імені нову структуру.</br>_Не можна_ змінювати жодну властивість структури. | _Не можна_ присвоїти імені новий клас.</br>_Можна_ змінювати змінні властивості класу. |
| **var** | _Можна_ присвоїти імені нову структуру.</br>_Можна_ змінювати змінні властивості структури.   | _Можна_ присвоїти імені новий клас.</br>_Можна_ змінювати змінні властивості класу.    |

## Ідентичність

Оскільки два різні імена можуть містити посилання на той самий екземпляр класу, іноді корисно перевірити, чи це так. Swift для цього використовує оператор _ідентичності_ `===` (а також його заперечення `!==`).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

Оскільки жодні два імені не можуть посилатися на той самий екземпляр структури, ці оператори ідентичності для структур не визначені.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

Зауважмо, що ідентичність - не те саме, що рівність. За багатьма означеннями `char1` і `char3` вважалися б рівними, бо всі їхні властивості містять однакові значення, але вони не мають однакової ідентичності. Ідентичність автоматично доступна для всіх класів у Swift, але розробникам зазвичай доводиться писати власні оператори рівності, щоб визначити, чи два екземпляри структури або класу _рівні_. Це виходить за межі цієї вправи.
