# Вступ

Як ми вже бачили в концепції [`Nothingness`][concept-nothingness], R має різні способи подати дані, яких немає (`NULL`), які невідомі (`NA`) або математично некоректні (`NaN`, `Inf`).
Загалом R намагається використовувати їх, щоб позначати проблеми на місці й продовжувати роботу, не викликаючи винятку.

## `stop()`

Деякі проблеми настільки принципові, що програма не може продовжити роботу.
У такому разі скористаймося `stop(msg)`, щоб негайно зупинити програму з помилкою `Error` і вивести `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Подібно до `assert` в інших мовах, це зручна обгортка навколо `stop()`.
Параметри - це довільна кількість булевих (англ. Boolean) умов, розділених комами, і програма продовжить роботу, лише якщо всі вони `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `warning()` та `message()`

Це реакції на некритичні умови, наприклад:

- Попередити про проблему, після якої програма може хоча б частково продовжити роботу.
- Повідомити користувача про хід виконання довготривалої програми.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

Функція `suppressWarnings()` іноді може стати в пригоді на Exercism, щоб небажані вихідні дані не збили з пантелику test runner.
