# Докладніше

Локальні змінні не замінюють код зі стеком, вони живуть поруч із ним. Звертаймося до них, коли:

- Одні й ті самі вхідні дані використовуються більше ніж один раз.
- Природний порядок операцій не збігається з порядком на стеці.
- Ми всередині слова вищого порядку, яке передає лямбді кілька значень одразу (`assoc-map` і його `( key value -- newkey newvalue )`).

```factor
USING: locals ;

! Two references to ratio: stack-shuffled vs. local.
: average  ( a b -- avg ) + 2 / ;
:: average ( a b -- avg ) a b + 2 / ;        ! same effect
```

`[let code :> name code :> name ... body ]` уводить локальні звʼязування всередині quotation або в listener, де `:>` інакше не мав би лексичної області видимості, куди звʼязувати:

```factor
[let 5 :> x 10 :> y x y + ] .   ! => 15
```

Суфікс мутації `:>` дозволяє перепривʼязувати локальну змінну, що стає в пригоді в циклах з імперативним присмаком:

```factor
:: collatz ( n -- count )
    n :> current!
    0 :> count!
    [ current 1 = ] [
        current odd?
        [ current 3 * 1 + current! ]
        [ current 2 / current! ] if
        count 1 + count!
    ] until
    count ;
```
