# Докладніше

Хеш-множини реалізують [протокол][set-protocol] [`sets`][sets], усередині використовуючи хешування, що дає в середньому O(1) на вставляння, пошук і видалення.
Їх можна змінювати на місці, що робить їх ідеальними для шаблону *множини відвіданих* в обході графів.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| слово         | дія                                       |
|---------------|-------------------------------------------|
| `HS{ }`       | порожній літерал хеш-множини (спільний, тож викличмо `clone`!) |
| `>hash-set`   | `( seq -- set )` - побудувати нову множину з послідовності (усуває дублікати) |
| `adjoin`      | `( elt set -- )` - деструктивне вставляння |
| `in?`         | `( elt set -- ? )` - перевірка належності |
| `delete`      | `( elt set -- )` - деструктивне вилучення |
| `cardinality` | `( set -- n )` - кількість елементів      |
| `null?`       | `( set -- ? )` - правда, коли множина порожня |
| `members`     | `( set -- seq )` - перелічити як послідовність |
| `union`       | `( set1 set2 -- set )` - обʼєднання       |
| `intersect`   | `( set1 set2 -- set )` - перетин          |
| `diff`        | `( set1 set2 -- set )` - різниця          |
| `set-like`    | `( set exemplar -- set' )` - звести `set` до класу `exemplar` |

Щоб побудувати множину з даних, які в нас уже є, `>hash-set` перетворює будь-яку послідовність за один крок, відкидаючи дублікати: `{ 2 3 2 5 }
>hash-set` gives `HS{ 2 3 5 }`. It's the bulk counterpart to
growing a set with repeated `adjoin`.

Тонкий момент щодо `in?` проти `member?` (з `sequences`): обидва перевіряють належність, але `member?` виконує лінійний перегляд послідовності, тоді як `in?` звертається до відповідного методу протоколу типу множини. Для `HS{ }` це пошук у хеші. Використовуймо `in?`, коли в нашому контейнері «відвіданих» більше ніж кілька елементів.

`null?` дає відповідь на питання «чи порожня ця множина?», не обчислюючи повністю `cardinality`. Це природна перевірка для питання «чи залишилося що-небудь обробити?». Для робочого списку, що зберігається як множина, `[ set null? ]
[ … ] until` спорожнює його до нуля.

## Гарно поєднується з хеш-таблицями

`HS{ }` для питання «чи X відвідано?» природно поєднується з `H{ }` для питання «хто сусіди X?». Класичний DFS записується так:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

Множина відвіданих усуває дублікати роботи; стек протягує граничні вузли (LIFO через `push`/`pop`); мапа сусідів (хеш-таблиця) надає граф. Порядок відвідування не має значення для питання досяжності, тому вектора в ролі стека цілком достатньо. Справжній BFS на тій самій структурі замінює вектор на [`<dlist>`][dlist] і натомість вилучає елементи з початку.
