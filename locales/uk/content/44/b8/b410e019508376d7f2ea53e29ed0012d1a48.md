# Докладніше

Оголошення `GENERIC:` вводить слово, поведінка якого залежить від класу одного з його аргументів. Конкретну поведінку забезпечують *методи* (`M:`), націлені на конкретні класи.

```factor
GENERIC: stringify ( obj -- str )
M: integer stringify number>string ;
M: string  stringify ;
M: f       stringify drop "(none)" ;
```

Коли викликають `stringify`, Factor заглядає на верхівку стека, знаходить найконкретніший метод, клас якого збігається, і виконує його. Якщо жоден метод не збігається, виникає помилка.

## Клас диспетчеризації

Типово диспетчеризація відбувається за найверхнішим аргументом (першим вхідним значенням, оголошеним у стековому ефекті). Для диспетчеризації за кількома аргументами дивіться `HOOK:` і `MATH:`; вони диспетчеризують за другим аргументом та за числовим підвищенням відповідно.

## Додавання методів до дженерика

Дженерик можна розширювати будь-коли, навіть із іншого словника, якщо ми можемо `USE:` і дженерик, і клас:

```factor
USING: math ;
M: ratio  area drop 0 ;     ! adds an `area` method for ratios
```

## Методи для вбудованих класів

Дженерики працюють так само добре з вбудованими класами (`integer`, `string`, `array`, `f`, `t`), як і з користувацькими кортежами. Методи для `f` і `t` особливо корисні для предикатів у стилі «чи встановлено?», які мають природні типові значення.

## Коли варто обирати дженерик

До `GENERIC:` варто звертатися, коли:

- Одна операція має *дійсно різні* реалізації для різних вхідних даних (а не просто `case` за мітками).
- Ми очікуємо, що інший код пізніше додасть нові типи.
- Ми хочемо, щоб система типів гарантувала, що операція визначена для кожного відповідного класу: Factor може навіть перелічити відсутні методи.

Якщо варіацій небагато і це фіксований перелік міток, простіше використати `case`.
