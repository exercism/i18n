# Докладніше

Elixir використовує [_поведінки_][behaviours], щоб забезпечити спільні універсальні інтерфейси й водночас дозволити кожному модулю, який реалізує поведінку, мати власну конкретну реалізацію. До таких поведінок належить _поведінка доступу_.

_Поведінка доступу_ надає спільний інтерфейс для отримання даних за ключем зі структури даних. Її реалізовано для словників і масивів ключових слів.

Модуль [`Access`][access] визначає колбеки, потрібні для цього інтерфейсу. А модулі [`Map`][map] і [`Keyword`][keyword] реалізують потрібні колбеки: [`fetch/2`][map-fetch], [`get_and_update/3`][map-get-and-update] і [`pop/2`][map-pop].

Щоб скористатися цією поведінкою, можна поставити після змінної, якій присвоєно значення, _квадратні дужки_, а потім за допомогою ключа отримати значення, повʼязане з цим ключем. Словники підтримують ключі будь-якого типу, а масиви ключових слів - лише ключі-атоми.

```elixir
# Atom as key
my_map = %{key: "my value"}
my_map[:key]
# => "my value"

# String as key
another_map = %{"key" => "my value"}
another_map["key"]
# => "my value"
```

Якщо ключа немає в структурі даних, повертається `nil`. Це може спричинити непередбачувану поведінку, бо при цьому не виникає помилки.

```elixir
my_map = %{key: "my value"}
my_map[:wrong_key][:other_wrong_key]
# => nil
```

Зауважмо, що `nil` сам реалізує поведінку доступу й завжди повертає `nil` для будь-якого ключа.

```elixir
nil[:key]
# => nil
```

Структури не реалізують поведінку доступу.

## Скорочення для доступу

- [`Kernel`][kernel] надає кілька функцій, які полегшують роботу з вкладеними даними за допомогою поведінки доступу. Ось посилання на документацію бібліотеки:
  - [`get_in/2`][get-in-2]
  - [`get_and_update_in/2`][get-and-update-in-2]
  - [`get_and_update_in/3`][get-and-update-in-3]
  - [`pop_in/1`][pop-in-1]
  - [`pop_in/2`][pop-in-2]
  - [`put_in/2`][put-in-2]
  - [`put_in/3`][put-in-3]
  - [`update_in/2`][update-in-2]
  - [`update_in/3`][update-in-3]
