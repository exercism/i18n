# Тести

Запустіть тести командою:

```shell
corepack pnpm test
```

Подбайте, щоб код відповідав найкращим практикам і стилю кодування, як це роблять інші, за допомогою ESLint, інструмента для статичного аналізу коду.
Іноді такі інструменти економлять час, виявляючи одруківки чи дурні помилки в коді JavaScript:

```shell
corepack pnpm lint
```

Також можна запустити Jest у режимі «watch»: він автоматично буде перезапускати тести, коли ми зберігаємо зміни в коді або тестовому модулі:

```shell
corepack pnpm watch
```

## Як працюють пропущені тести

Метод skip указує набору тестів не запускати тест, і цю функцію можна також використати під псевдонімами: `it.skip(name, fn)` або `xit(name, fn)` або `xtest(name, fn)`

- Чому їх пропускають?

Щоб можна було зосередитися на одному тесті за раз і вмикати їх по одному в міру того, як ми доопрацьовуємо рішення.

- Як їх увімкнути?

Змініть `xtest` на `test`.

```javascript
test('title cased phrases', () => {
  expect(Acronyms.parse('Portable Network Graphics')).toEqual('PNG');
});
```

## Створюємо перший модуль JavaScript 2015

Зазвичай тести в цьому треку завантажують власну реалізацію, імпортуючи її як модуль JavaScript: `import { Bob } from './bob.js';`.
Потрібно лише експортувати реалізацію із зазначеного файлу `bob.js`:

```javascript
export function hey(message) {}
```

Більше інформації про модулі можна знайти в [документації Babel](https://babeljs.io/docs/learn-es2015/#modules).
Щоб було легше почати, у директорії є _скелетний_ файл JavaScript.
