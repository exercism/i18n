# Докладніше

Винятки - це одна з форм обробки помилок.
Їх називають винятками, бо зазвичай вони виникають, коли ми маємо справу з якоюсь несподіваною подією.

У будь-якому місці нашого коду ми можемо «збудити» виняток.
Ми робимо це за допомогою методу `raise`, передаючи обʼєкт, зазвичай обʼєкт винятку, хоча можна передати й звичайний рядок тексту (англ. string).
Наприклад, у заготовках вправ ми побачимо, що використовуємо вбудований `RuntimeError`, щоб повідомити Ruby, що метод ще не реалізовано.
Можна також скористатися скороченим синтаксисом `raise(ExceptionObject, params)`.
Якщо клас винятку не вказано, типово використовується `RuntimeError`.

Наприклад:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

Побачивши це, Ruby піднімає помилку на найвищий рівень програми й завершує роботу.

Наприклад, якщо ми спробуємо поділити щось на нуль, то побачимо приблизно таке:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

Важливо зауважити, що винятки варто використовувати в тих випадках, коли трапляється щось виняткове: помилка, яка потребує особливої обробки.
Не варто використовувати винятки для керування потоком виконання програми, бо це вважається поганим проєктуванням, яке часто призводить до поганої продуктивності та супроводжуваності.

## Ієрархія класів

У Ruby винятки утворюють ієрархію класів, де роль базового класу виконує `Exception`.
Ось найпоширеніші вбудовані винятки Ruby:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

Перехоплення помилок конкретного класу також перехоплює помилки його дочірніх класів.
Саме тому перехоплення `Exception` може бути небезпечним.
Ruby також використовує винятки для обробки повідомлень від «сигналів» операційної системи, наприклад `ctrl-c`.
Це означає, що перехоплення `Exception` також перехопить ці системні «сигнали».
Тож щоб запобігти несподіваній поведінці, зазвичай для перехоплення «всіх помилок» використовують `StandardError`.

## Синтаксис `rescue`
Ruby також надає розширені конструкції `rescue` для ситуацій, які потребують особливої обробки:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

Це може стати в пригоді, наприклад, під час роботи з мережевим вводом-виводом, де нам завжди потрібно памʼятати про закриття зʼєднання.

Блоки `rescue` у Ruby також можуть використовувати ключове слово `retry`, яке повторно виконує все між begin і rescue:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
