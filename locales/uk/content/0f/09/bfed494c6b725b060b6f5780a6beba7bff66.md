# Вступ до конвеєрів і списків команд

Ми бачили, як писати прості команди, де за командою йдуть аргументи.
Тепер побачимо, як створювати складніші команди, поєднуючи прості команди.

## Ввід і вивід

Перш ніж почати, короткий вступ до вводу/виводу.

Процеси мають «стандартні канали вводу/виводу».

* Процес може споживати _ввід_ зі «stdin».
* Процес може видавати _вивід_ у «stdout».
* Процес може видавати _вивід про помилки_ у «stderr».

Команда `tr` - дуже чистий приклад цього.
Вона лише читає текст зі свого входу, виконує транслітерацію символів і друкує отриманий текст на свій вихід.

Про маніпуляції зі «stdio»-каналами ми побачимо далі в силабусі.

## Конвеєри

Це одна з «ключових можливостей» програмування оболонки.
Конвеєри дозволяють створювати складні перетворення потоку тексту.

Щоб отримати відсортований список користувачів:

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

Символ конвеєра (`|`) зʼєднує вихід однієї команди з входом іншої.
`cut` читає вихід `cat`, а `sort` читає вихід `cut`.

~~~~exercism/advanced
* За замовчуванням кожна команда в конвеєрі виконується в окремій підоболонці.
  (Підоболонка - це дочірній процес, який є копією поточної оболонки.)

* Виконання конвеєрів має витрати на продуктивність.
  Якщо у нас довгі конвеєри з подібних команд, варто розглянути можливість обʼєднати їх в одну команду.
  Наприклад, конвеєри, що використовують кілька екземплярів `grep`, `cut`, `sed`, `awk` і `tr`, зазвичай можна обʼєднати в одну команду `awk` для ефективності.

* Код виходу конвеєра - це код виходу останньої команди в конвеєрі.
  Це означає, що якщо якась попередня команда зазнала невдачі, але остання команда успішна, код виходу всього конвеєра дорівнює нулю.

  Існує налаштування оболонки, яке може це змінити;
  якщо увімкнено налаштування «pipefail» (за допомогою `set -o pipefail`), тоді код виходу конвеєра буде:
  * нуль, якщо всі команди успішні, інакше
  * _**останній** ненульовий код виходу_ команд у конвеєрі.
~~~~

## Списки команд

Список команд - це послідовність конвеєрів, розділених `;` (або новим рядком), `&&` або `||`.

* `A; B` - це список команд, де `B` виконується після завершення `A`.
* `A && B`, де `B` виконується лише якщо `A` успішна (завершується з кодом нуль).
* `A || B`, де `B` виконується лише якщо `A` зазнає невдачі (завершується з ненульовим кодом).

Код виходу списку команд - це код виходу останньої виконаної команди.

Оператори `&&` і `||` можна обʼєднувати в ланцюжок, щоб наступна команда виконувалася умовно, залежно від статусу попередніх команд.
Наприклад

```bash
A && B && C && D || E
```

* B виконується, якщо A успішна,
* C виконується, якщо A і B успішні,
* D виконується, якщо A, B і C успішні,
* E виконується, якщо **будь-яка** з A, B, C або D зазнає невдачі.

~~~~exercism/caution
Використовуйте ці логічні оператори помірно.
Вони можуть швидко призвести до нечитабельного коду або логіки, яку важко зрозуміти.

Наприклад, може здатися, що це одне й те саме:

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

Різниця в тому: коли виконується C?

* У першому фрагменті (умовна конструкція if), C виконується лише якщо A зазнає невдачі.
* У другому фрагменті, C виконується, якщо A зазнає невдачі _або якщо A успішна, але B зазнає невдачі_!
~~~~

### Використання списків команд

Ось кілька прикладів, де списки команд можуть спростити код.

#### Читання блоків рядків з файлу

Припустімо, у нас є файл даних, що містить дані про трикутники,
і трикутник представлений трьома окремими рядками, які містять сторони трикутника.

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

Ми можемо використати цикл `while`, де умова - це три окремі команди `read`:

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

Якщо припустити, що `is_pythagorean` - це команда, яка визначає, чи задовольняють три сторони рівняння Піфагора, вивід буде таким:

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### Твердження

Багато мов програмування мають форму твердження, де виняток викидається, якщо деяка умова не виконується

```
assert(user == "Administrator", "wrong user");
```

Ми можемо використати логічний оператор або в Bash, щоб змоделювати цю функцію:

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## Міркування стилю

Довгі списки команд досить швидко стають важкими для читання.
Щедре використання нових рядків може дуже допомогти.

Розгляньмо цей приклад, де слово додається до масиву, якщо виконуються дві умови.

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

Bash дозволяє додати новий рядок після конвеєра або логічного оператора.

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

Однак оператор можна легко пропустити в кінці рядка.
Використання _продовження рядка_ означає, що ми можемо поставити оператор на початку, що робить очевиднішим, що список продовжується:

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
_Продовження рядка_ - це послідовність із двох символів: «зворотна коса риска» та «новий рядок» (`\` + `\n`).
Коли Bash бачить цю послідовність, вона просто вилучається з коду, тим самим _продовжуючи_ поточний рядок наступним рядком.
Подбаймо, щоб не було жодних пробілів між зворотною косою рискою та новим рядком.
~~~~

Ось ще один приклад

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

або

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
