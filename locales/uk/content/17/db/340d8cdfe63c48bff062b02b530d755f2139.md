# Докладніше

Common Lisp дає програмістові кілька різних умовних конструкцій, які можна класифікувати за кількістю «гілок», які вони підтримують.

Крім того, на відміну від багатьох інших мов програмування, всі умовні конструкції в Common Lisp є _виразами_, а не інструкціями.
Це означає, що всі умовні конструкції Lisp обчислюються в деяке значення, і їх можна підставляти замість конкретних параметрів.

Наприклад:

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## Умовні конструкції з однією гілкою

Умовні конструкції `when` і `unless` виконують код лише тоді, коли надана перевірка є відповідно істинною або хибною, а в іншому разі обчислюються в `nil`.

Частина після виразу-перевірки може містити більше ніж один вираз.

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## Умовна конструкція з двома гілками

Умовна конструкція `if` обчислює перший вираз тіла, коли перевірка істинна, і другий, коли вона хибна.

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

Зауважимо, що і гілка `then`, і гілка `else` можуть містити лише один вираз.

## Умовні конструкції з багатьма гілками

«Суперумовною» конструкцією в Lisp є `cond`, яка може мати нескінченну кількість гілок.
Кожна гілка має умову-перевірку та вираз тіла, які оточені додатковою парою дужок.
Якщо всі перевірки виявляться хибними, повертається `nil`.

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

Зауважимо, що кількість виразів після виразу-перевірки не обмежена.

Якщо потрібно лише перевірити одне значення на відповідність низці гілок, можна скористатися зручнішим виразом `case`.
Якщо жоден із варіантів не збігається, повертається `nil`.
І `t`, і `otherwise` можна використовувати як варіанти, що збігаються з будь-чим:

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

Зауважимо, що, як і в `cond`, кількість виразів після виразу-перевірки не обмежена.

## Приховані умовні конструкції

Операції `and` і `or` у Common Lisp працюють із булевими значеннями (англ. Boolean). Це макроси зі скороченим обчисленням, які допомагають зменшити дублювання деяких умовних виразів.

Макрос `and` негайно повертає `nil`, щойно трапиться хоч одне хибне значення, а інакше повертає останнє істинне значення, яке отримав:

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

Макрос `or` повертає перше істинне значення, яке трапиться, або `nil`, якщо істинних значень не було:

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## Я вже вичерпався...

Як уже згадувалося, коли жодна з гілок у конструкції `case` не збігається і немає гілки `otherwise`, повертається `nil`.
Іноді ж невдачу в зіставленні з будь-якою гілкою слід вважати помилкою, і саме тут стає в пригоді `ecase` (від **exhaustive**, тобто вичерпного зіставлення).

Його використовують точно так само, як `case`, але коли збігу немає, він сигналізує про помилку, а не повертає `nil`.

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
