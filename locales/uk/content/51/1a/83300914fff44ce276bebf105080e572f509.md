# Основи `match`

Вираз `match` дає змогу легко порівнювати значення з низкою шаблонів, а потім виконувати код залежно від того, який шаблон збігся. Шаблон може складатися з літеральних значень, назв змінних, символів-замінників і багато чого іншого.

```rust
#[derive(Drop)]
enum Color {
    Red,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red => println!("The color is Red"),
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Yellow;
    print_color_type(color); // prints "The color is Yellow"
}
```

Щоб гілка `match` містила кілька рядків коду, її треба взяти у фігурні дужки `{}`:

```rust
fn specified_color(color: Color) -> felt252 {
    let mut response: felt252 = '';

    match color {
        Color::Red => {
            response = 'You passed in Red';
        },
        Color::Yellow => {
            response = 'You passed in Yellow';
        },
        Color::Green => {
            response = 'You passed in Green';
        },
    }

    response
}
```

Вираз `match` також уміє звʼязуватися зі значеннями, що відповідають шаблону. Завдяки цьому можна витягти повʼязане значення варіанта переліку.

```rust
#[derive(Drop, Debug)]
enum ColorType {
    Light,
    Dark,
}

#[derive(Drop)]
enum Color {
    Red: ColorType,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red(state) => {
            println!("The color is Red");
            println!("The Color Type is {:?}", state);
        },
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Red(ColorType::Dark);
    print_color_type(color);
}
```

Тут варіант `Red` переліку `Color` розширено так, що він має повʼязаний перелік. За допомогою виразу `match` ми можемо витягти повʼязане значення, `state`. Це просто назва змінної, яку потім можна використати в гілці коду.

## Зіставлення з переліком `Option`

Вбудований перелік `Option` теж можна обробляти за допомогою виразу `match`.

Створімо функцію, яка приймає параметр `Option<u8>`.
Якщо в наданому параметрі є значення, додаймо до нього одиницю, інакше функція має повернути значення `None`, не виконуючи жодних дій.

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
        Option::None => Option::None,
    }
}

fn main() {
    let three: Option<u8> = Option::Some(3);
    let four: Option<u8> = add_one(three);
    let none = add_one(Option::None);

    println!("{three:?}"); // prints "Option::Some(3)"
    println!("{four:?}"); // prints "Option::Some(4)"
    println!("{none:?}"); // prints "Option::None(())"
}
```

> Зауваження: `{:?}` - це спеціальний синтаксис форматування, який дає змогу надрукувати налагоджувальну форму параметра, переданого макросу `println!`.
> Докладніше про це можна дізнатися в [The Cairo Book][debugging].

Одна з переваг конструкції керування потоком `match` - її вичерпність: шаблони гілок мають покривати _всі_ можливості.
Розгляньмо версію попереднього прикладу, яка не обробляє випадок `None`:

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
    }
     // this code does not compile, as we forgot to handle the `None` case
}
```

## Універсальний шаблон із символом-замінником `_`

Маючи переліки, ми можемо виконувати особливі дії для кількох конкретних значень, а для всіх інших значень робити одну типову дію, додавши нову гілку з `_` як шаблоном для останньої гілки виразу `match`.
Шаблон `_` - це особливий шаблон, який збігається з будь-яким значенням і не звʼязується з ним.

Функція `is_red` приймає параметр і повертає `true`, якщо колір `Red`, та `false` для будь-якого іншого кольору:

```rust
fn is_red(color: Color) -> bool {
    match color {
        Color::Red => true,
        _ => false,
    }
}
```

## Зіставлення з оператором `|`

Конструкція керування потоком `match` у Cairo дає змогу зіставляти значення з кількома шаблонами за допомогою оператора `|` (_або_).
Це допомагає спростити код.

Наприклад, використовуючи перелік `Color`, ми хочемо написати функцію, яка повертає `true` для кольорів `Red` або `Green` і `false` для інших кольорів:

```rust
fn is_red_or_green(color: Color) -> bool {
    match color {
        Color::Red | Color::Green => true,
        _ => false,
    }
}
```

## Зіставлення `felt252` і цілих змінних

Можна зіставляти `felt252` і цілі змінні з набором значень.
Однак є деякі обмеження:

- Підтримуються лише цілі числа, які вміщаються в один `felt252` (тобто `u256` не підтримується).
- 0 має бути першою гілкою.
- Кожна гілка має утворювати послідовний відрізок разом з іншими гілками.

Реалізуймо гру в кидання шестигранного кубика.
Коли кубик кидають, ми отримуємо число від 0 до 5.
Якщо випадає 0, 1 або 2, ми виграємо.
Якщо випадає 3, можна кинути ще раз.
Для інших значень ми програємо:

```rust
fn toss(value: u8) {
    match value {
        0 | 1 | 2 => println!("you won!"),
        3 => println!("you can roll again!"),
        _ => println!("you lost...")
    }
}

fn main() {
    toss(2); // prints "you won!".
    toss(3); // prints "you can roll again!".
    toss(5); // prints "you lost...".
}
```

## Зіставлення кортежів

Кортежі теж можна зіставляти з набором шаблонів.
Ці шаблони записуються так само, як кортеж.

```rust
#[derive(Drop)]
enum DayType {
    Week,
    Weekend,
    Holiday
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn vending_machine_accept(c: (DayType, Coin)) -> bool {
    match c {
        (DayType::Week, _) => true, // accepts all coins during week day
        (_, Coin::Dime) | (_, Coin::Quarter) => true, // accepts only Dime or Quarter coin for all specified days
        (_, _) => false, // returns false for other instances
    }
}
```

В останній гілці `match` не має значення, використати `(_, _)` чи просто символ-замінник `_`, щоб зіставити будь-яку комбінацію дня й кольору, бо функціонально вони однакові.
