# Доповнення до інструкцій

## Процес Node

На відміну від інших вправ, `grep.js` _не_ імпортується всередині тестового файлу `grep.spec.js`. Натомість його використовуватимуть так, ніби це виконуваний файл. Щоб це стало можливим, файл `grep.js` уже містить шебанг і коментар, який пояснює, що це таке:

```javascript
#!/usr/bin/env node

// The above line is a shebang. On Unix-like operating systems, or environments,
// this will allow the script to be run by node, and thus turn this JavaScript
// file into an executable. In other words, to execute this file, you may run
// the following from your terminal:
//
// ./grep.js args
//
// If you do not have a Unix-like operating system or environment, for example
// Windows without WSL, you can use the following inside a window terminal,
// such as cmd.exe:
//
// node grep.js args
//
// Read more about shebangs here: https://en.wikipedia.org/wiki/Shebang_(Unix)
```

Тести запускають новий _процес_ node, виконуючи `grep.js`.

## Читання аргументів

Щоб отримати аргументи, з якими було запущено _процес_, скористайтеся `process.argv`.

## Читання файлів

Функцію `readLines` уже надано. Не потрібно нічого робити зі шляхом до файлу, щоб нею скористатися. Функція `readlines` _визначить_ шлях від поточного робочого каталогу, який для процесів `grep.js` вказує на каталог вправи.

## Запис вихідних даних

Щоб записати вихідні дані, скористайтеся такими засобами:

- `console.log`, щоб писати в стандартний потік вихідних даних,
- `console.error`, щоб писати в стандартний потік помилок.

Тести вважають виконання успішним (resolved), якщо в стандартний потік помилок нічого не записано, і неуспішним (rejected), якщо в стандартний потік помилок щось записано.
