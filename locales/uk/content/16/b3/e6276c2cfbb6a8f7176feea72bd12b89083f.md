# Про це

Тип `Result` розвʼязує в мові Elm задачу повідомлення про помилки та відновлення після них. Він дещо схожий на тип `Maybe`, але тоді як `Nothing` у `Maybe` позначає якусь невдачу, він нічого не каже про те, _чому_ вона сталася. Натомість `Result` містить контекст: чому саме щось не вдалося.

## Визначення та змінна типу

Тип `Result` визначено так:

```elm
type Result error value
  = Ok value
  | Err error
```

Коротко кажучи, цей тип кодує результат операції, яка може або вдатися й повернути `value`, або зазнати невдачі й повернути пояснення цієї невдачі (`error`).

У термінології Elm це називають визначенням «власного типу».
Власні типи докладно розглядаються в іншому понятті цього треку, але для розуміння саме `Result` вони нам не потрібні.
`error` і `value` у `OK value` та `Error error` позначають змінну типу, тобто це може бути будь-який тип, наприклад `Int`, `Bool` чи `String`.
Отже, значення `Result String Int` має містити `Int`, і якщо станеться помилка, її буде представлено як `String`.

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## Читання вмісту значення Result

Вміст значення `Result` читають за допомогою «зіставлення зі зразком».
Зіставлення зі зразком також докладніше розглядається в іншому понятті, тож зосередимося лише на тому, як воно працює із `Result`.

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

Щоразу, коли ми використовуємо значення `Result`, компілятор Elm перевіряє, що наш код опрацьовує всі можливі випадки, тож ми ніколи не зможемо зіставити `Result` зі зразком і опрацювати лише випадок `Ok value`.
Спершу це може дратувати, але це одна з найбільших переваг мови Elm.
Це запобігає сотням Bug і робить рефакторинг під керівництвом компілятора безстрашним і вдячним заняттям.

## Робота з вмістом значення Result

Є різні функції для роботи з типами `Result`, яким зазвичай віддають перевагу перед зіставленням зі зразком. `Result.map` можна використати, щоб перетворити значення, а `Result.andThen` - щоб поєднати функції, які можуть зазнати невдачі.

Result.map використовують, щоб змінити значення Ok, і він стає в пригоді, коли треба поєднати функції в ланцюжок, не переймаючись тим, чи містить Result помилку. Якщо значення є Ok, Result.map викликає приєднану функцію (`formatAge` нижче), а якщо сталася помилка, Result.map нічого не робить і просто повертає цю помилку.

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

Result.andThen використовують, щоб змінити значення Ok, і він стає в пригоді, коли треба поєднати функції, не переймаючись тим, чи містить Result помилку. Він схожий на Result.map, але Result.andThen працює з приєднаною функцією (`formatSpecialBirthday` нижче), яка теж повертає Result. `Result.map` теж може це зробити, але тоді додається зайвий рівень вкладеності, якого `andThen` вправно уникає.

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
