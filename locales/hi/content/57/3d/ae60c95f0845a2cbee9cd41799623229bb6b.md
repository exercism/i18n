# परिचय

एक `GENERIC:` डिक्लेरेशन ऐसा शब्द बनाता है जिसका व्यवहार उसके किसी एक आर्गुमेंट की *क्लास* पर निर्भर करता है। ठोस व्यवहार *मेथड* से मिलता है, जिन्हें `M:` से बनाया जाता है।

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

जब `area` को कॉल किया जाता है, तो Factor स्टैक के सबसे ऊपर वाली वैल्यू देखता है। फिर वह ऐसा मेथड ढूँढता है जिसकी क्लास सबसे विशिष्ट रूप से मेल खाती हो, और उसे चलाता है। लोकल्स के साथ आप `M::` इस्तेमाल कर सकते हैं:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

जेनेरिक की मदद से आप बाद में नए रेप्रेज़ेंटेशन जोड़ सकते हैं, और इसके लिए कॉल करने वाला कोड बदलने की ज़रूरत नहीं पड़ती। `area` पहले से ही `square` और `circle` के लिए काम करता था, और जहाँ भी `area` को कॉल किया जाता है, वहाँ `rectangle` मेथड अपने आप चुन लिया जाता है।

## जेनेरिक कब सही चुनाव है

`GENERIC:` तब चुनिए जब:

- किसी एक ही ऑपरेशन के अलग-अलग इनपुट के लिए *वाकई अलग* इम्प्लीमेंटेशन हों।
- आपको लगता है कि आगे लिखा जाने वाला कोड नए टाइप जोड़ेगा।
- आप चाहते हैं कि टाइप सिस्टम यह सुनिश्चित करे कि हर क्लास की अपनी परिभाषा हो।

अगर अंतर सिर्फ कुछ लेबलों की छोटी सी सूची है, तो `case` ज़्यादा आसान है।

## `INSTANCE:` की मदद से मिक्सिन से जुड़ना

*मिक्सिन* एक जेनेरिक क्लास है जो *खुली* होती है: कोई भी किसी नई क्लास को उसका सदस्य बना सकता है। Factor के बहुत से बिल्ट-इन प्रोटोकॉल (सीक्वेंस, सेट, स्ट्रीम, …) मिक्सिन के रूप में उपलब्ध हैं। इसलिए कोई कस्टम टपल खुद को उस प्रोटोकॉल का इंस्टेंस घोषित करके उसके डिफॉल्ट मेथड अपना सकता है:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

`INSTANCE:` के बाद, हर डिफॉल्ट मेथड `M: shape …` अपने आप `my-shape` पर डिस्पैच होता है, और जो भी कोड `shape` माँगता है वह `my-shape` को भी स्वीकार करता है। `M:` किसी जेनेरिक में मेथड जोड़ने के लिए है; `INSTANCE:` किसी क्लास को मिक्सिन से जोड़ने के लिए है।

## `TYPED::`: साधारण शब्द के लिए जाँचे हुए इनपुट

`GENERIC:`/`M:` किसी आर्गुमेंट की क्लास के आधार पर मेथड चुनते हैं। कभी-कभी आपको डिस्पैच नहीं चाहिए, बल्कि सिर्फ *एक* ऐसा शब्द चाहिए जो ज़ोर देकर कहे कि उसके इनपुट किसी दी गई क्लास के ही हों। `TYPED::` (`typed` वोकैबुलरी में) वही `::` है, बस हर इनपुट नाम के बाद एक क्लास लिख दी जाती है:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

`n: integer` उन्हीं लोकल्स की तरह पढ़ा जाता है जो आप पहले से इस्तेमाल करते हैं, बस कोलन के बाद क्लास लिखी होती है। यहाँ कोई डिस्पैच नहीं होता: एक परिभाषा, एक व्यवहार। लेकिन अब हर आर्गुमेंट की जाँच उसकी क्लास से होती है। `"x" triple` जैसी बेमेल चीज़ चुपचाप पास होने के बजाय रद्द कर दी जाती है (*expected input value of type integer but got string*)।

आउटपुट पर भी इसी तरह टाइप लिखा जा सकता है। `yes?` अपने इनपुट और नतीजे, दोनों का टाइप लिखता है:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## गणित के फंक्शन और स्थिरांक

इस अभ्यास में `math.constants` और `math.functions` के कुछ ऐसे शब्दों का भी इस्तेमाल है, जिनसे आपकी मुलाकात यहाँ पहली बार होगी:

- `pi`: स्थिरांक π, `math.constants` से।
- `sin ( x -- y )`, `cos ( x -- y )`: रेडियन में दिए गए कोण की साइन और कोसाइन।
- `e^ ( x -- y )`: `e` की घात `x`। (किसी भी आधार के लिए `^` इस्तेमाल कीजिए।)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
