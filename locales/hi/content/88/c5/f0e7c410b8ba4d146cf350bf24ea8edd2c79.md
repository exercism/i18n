# परिचय

## ब्रांचलेस कोड

शर्तों का कॉन्सेप्ट `jcc` से परिचित कराता है, जो शर्त के आधार पर ब्रांच करने वाले निर्देशों का समूह है।
एक `jcc` प्रोग्राम में निष्पादन को किसी अन्य बिंदु पर स्थानांतरित करता है, लेकिन केवल तभी जब उसकी शर्त पूरी होती है।

लेकिन आधुनिक CPU तेज़ होते हैं और कई निर्देशों को समानांतर में निष्पादित कर सकते हैं।
जब CPU किसी शर्त की रनटाइम जाँच का इंतज़ार कर रहा हो, तब सारे काम को रोक देना बहुत महंगा पड़ेगा।

इसीलिए CPU अंदर से इंतज़ार नहीं करता।
यह किसी शर्त के परिणाम का अनुमान लगाने के लिए **ब्रांच-प्रेडिक्टर** का उपयोग करता है और अनुमानित रास्ते पर _काल्पनिक रूप से_ निष्पादन शुरू कर देता है।

अगर अनुमान सही होता है, तो निष्पादन ऐसे आगे बढ़ता है जैसे कोई ब्रांच ही नहीं था।
लेकिन अगर अनुमान गलत होता है, तो CPU को अनुमानित रास्ते पर _किए गए काम को छोड़ना_ पड़ता है और सही रास्ते पर फिर से शुरू करना पड़ता है।

इसे **ब्रांच मिसप्रेडिक्शन** कहते हैं और यह महंगा पड़ता है, जिससे देरी होती है।

जब किसी ब्रांच का अनुमान लगाना मुश्किल होता है, तो ऐसे मिसप्रेडिक्शन की संख्या बढ़ जाती है।
ऐसे मामलों में, कभी-कभी ब्रांच को पूरी तरह से टालना बेहतर होता है, ताकि शर्त चाहे जो हो, वही निर्देश निष्पादित हों।
वह कोड जो `jcc` के बिना मानों के बीच चयन करता है, **ब्रांचलेस** कहलाता है।

कोड को इस तरह लिखने के कई तरीके हैं कि वह कम बार ब्रांच करे, या उसमें जो ब्रांच हों वे ज़्यादा अनुमानित हों।
विशेष रूप से, x86-64 दो निर्देश परिवार प्रदान करता है जो आमतौर पर ब्रांचलेस कोड लिखने के लिए उपयोग किए जाते हैं।

### शर्तीय मूव्स

`cmovcc` निर्देशों का परिवार स्रोत ऑपरेंड को गंतव्य में केवल तभी कॉपी करता है जब कोई विशिष्ट शर्त पूरी होती है।
अन्यथा, गंतव्य अपरिवर्तित रहता है।

`cc` प्रत्यय `jcc` की तरह ही नामकरण का पालन करता है, और उसका वही अर्थ होता है:

| निर्देश | कब मूव करें                              |
|-------------|--------------------------------------|
| `cmove`     | `cmp A, B` के बाद A == B              |
| `cmovne`    | `cmp A, B` के बाद A != B              |
| `cmovl`     | `cmp A, B` के बाद A < B (signed)      |
| `cmovb`     | `cmp A, B` के बाद A < B (unsigned)    |
| `cmovg`     | `cmp A, B` के बाद A > B (signed)      |
| `cmova`     | `cmp A, B` के बाद A > B (unsigned)    |

नियम `jcc` के समान हैं:

1. `l` और `g` signed तुलना के लिए उपयोग किए जाते हैं, और `b` और `a` unsigned के लिए।
2. किसी प्रत्यय में `e` जोड़ने से समानता शामिल हो जाती है।
3. `n` जोड़ने से शर्त का निषेध हो जाता है।
4. कुछ ऐसे भी प्रकार हैं जो फ्लैग सेट होने को संदर्भित करते हैं।
   उदाहरण के लिए, `cmovz` और `cmovc`।

`rdi` में दिए गए signed पूर्णांक के निरपेक्ष मान पर विचार कीजिए, जो `rax` में लौटाया जाता है।
`jcc` के साथ लिखने पर, फंक्शन दो रास्तों में से एक चुनता है:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

`cmovcc` के साथ लिखने पर, दोनों संभावित मान बिना शर्त के गणना किए जाते हैं और शर्तीय मूव उनमें से एक चुनता है:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

ब्रांचलेस संस्करण हमेशा वही निर्देश निष्पादित करता है।
प्रेडिक्टर के अनुमान लगाने के लिए कोई `jcc` नहीं होता।

`cmovcc` का गंतव्य एक रजिस्टर होना चाहिए।
स्रोत एक रजिस्टर या मेमोरी लोकेशन हो सकता है, लेकिन इमीडिएट नहीं।

~~~~exercism/note
ऊपर दिए गए कोड में, `neg` निर्देश परिणाम के अनुसार कई फ्लैग सेट करता है, जिनमें साइन फ्लैग (SF) भी शामिल है।
इसका मतलब है कि `cmp rdi, 0` को पूरी तरह से हटाया जा सकता है:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

सकारात्मक `rdi` के लिए, `neg` एक ऋणात्मक परिणाम देता है और SF == 1 होता है, इसलिए `cmovs` `rdi` को पुनर्स्थापित कर देता है।
शून्य या ऋणात्मक `rdi` के लिए, `neg` एक गैर-ऋणात्मक परिणाम देता है और SF == 0 होता है, इसलिए `rax` नेगेट किया गया मान रखता है (जो सही निरपेक्ष मान है)।

हालाँकि असेंबली कोड में मानों की तुलना करने का मुख्य तरीका `cmp` है, कई निर्देश अपने परिणाम के अनुसार फ्लैग भी सेट करते हैं।
किसी निर्देश पर पड़ने वाले फ्लैग की पूरी सूची आमतौर पर उसके [संदर्भ][reference] में दी जाती है।
विशेष रूप से `neg` के लिए, वे SF, ZF, CF, OF, और PF हैं।

[reference]: https://www.felixcloutier.com/x86/
~~~~

### शर्तीय सेट

`setcc` निर्देशों का परिवार गंतव्य ऑपरेंड को `1` पर सेट करता है अगर कोई विशिष्ट शर्त पूरी होती है, अन्यथा `0` पर।
गंतव्य हमेशा एक _8-बिट ऑपरेंड_ होता है।

`cc` प्रत्यय `jcc` और `cmovcc` की तरह ही नामकरण का पालन करता है।
उदाहरण के लिए, `setz` गंतव्य को `1` पर सेट करता है अगर `ZF == 1` हो, और अन्यथा `0` पर।

चूँकि गंतव्य 8-बिट है, जब व्यापक मान की आवश्यकता होती है तो `setcc` के बाद `movzx` का उपयोग करना आम है:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

यह तुलना परिणाम को पूर्णांक `0` या `1` में बदलने का एक आम तरीका है।
