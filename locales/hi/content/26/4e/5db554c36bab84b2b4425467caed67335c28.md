# परिचय

Swift में [क्लोज़र][closures] कोड के ऐसे ब्लॉक होते हैं जो अपने आप में पूरे होते हैं। आप इन्हें पैरामीटर देकर चला सकते हैं और ये वैल्यू लौटाते हैं।
क्लोज़र अपने वातावरण से वैल्यू भी पकड़ लेते हैं और उन्हें अपनी गणना में इस्तेमाल करते हैं।
चूँकि ये अपने आप में पूरे होते हैं, इसलिए इन्हें प्रोग्राम में दूसरी वैल्यू की तरह एक जगह से दूसरी जगह भेजा जा सकता है, या स्थिरांक और वेरिएबल में असाइन किया जा सकता है।

क्लोज़र सुनने में Swift के फंक्शन जैसे लग सकते हैं। वाकई वे जैसे हैं, और इसकी एक अच्छी वजह है।
Swift में फंक्शन क्लोज़र के ही एक खास रूप होते हैं, जिनका एक नाम होना ज़रूरी है और जिन्हें थोड़े अलग सिंटैक्स से बनाया जाता है।

Swift में फंक्शन तकनीकी रूप से क्लोज़र ही हैं, लेकिन जब लोग Swift में "क्लोज़र" कहते हैं, तो उनका मतलब [क्लोज़र एक्सप्रेशन][closure-expressions] होता है।
क्लोज़र एक्सप्रेशन लिखने का तरीका यह है: पहले पैरामीटर की सूची, उसके बाद रिटर्न टाइप, फिर कीवर्ड `in`, और उसके बाद क्लोज़र के अंदर का कोड। यह सब घुंघराले ब्रैकेट के एक जोड़े के अंदर रहता है:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}
```

यह `(Double, Double) -> Double` टाइप का एक क्लोज़र एक्सप्रेशन बनाता है। इसे इस टाइप के किसी फंक्शन की तरह ही चलाया जा सकता है, बस उचित टाइप के पैरामीटर देकर:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}(10.0, 15.0)
// returns 12.5
```

हर बार चलाने के लिए पूरा क्लोज़र एक्सप्रेशन लिखना बहुत सुविधाजनक नहीं होता, इसलिए क्लोज़र को Swift की दूसरी वैल्यू की तरह किसी नाम पर असाइन किया जा सकता है।
फिर उस नाम को पैरामीटर देकर क्लोज़र को कॉल किया जा सकता है:

```swift
let mean = { (a: Double, b: Double) -> Double in
  (a + b) / 2.0
}

mean(13.0, 100.0)
// returns 56.5
```

जैसा ऊपर दिखा, क्लोज़र भी आम फंक्शन की तरह `return` कीवर्ड छोड़ सकते हैं, अगर क्लोज़र के अंदर सिर्फ एक एक्सप्रेशन हो।

अक्सर क्लोज़र हायर-ऑर्डर फंक्शन के साथ इस्तेमाल होते हैं, या तो पैरामीटर के रूप में दिए जाते हैं या नतीजे के रूप में लौटाए जाते हैं:

```swift
[11, 75, 3, 99, 53].contains(where: { (x: Int) -> Bool in x > 100 })
// returns false

["apple", "ball", "carrot"].sorted(by: { (s1: String, s2: String) -> Bool in s1.count < s2.count })
// returns ["ball", "apple", "carrot"]

func makeAdder(base: Int) -> (Int) -> Int {
  { (x: Int) -> Int in base + x }
}
```

## क्लोज़र टाइप का अनुमान लगाना

जब रिटर्न टाइप या पैरामीटर के टाइप [कॉन्टेक्स्ट से अनुमान लगाए जा सकते हैं][inferring-closure-types], तो उन्हें क्लोज़र एक्सप्रेशन में लिखना छोड़ा जा सकता है।
इसके अलावा, अगर पैरामीटर के टाइप छोड़े जा सकते हैं, तो पैरामीटर के नामों के आसपास के गोल ब्रैकेट भी छोड़े जा सकते हैं:

```swift
let mean: (Double, Double) -> Double = { a, b in a + b / 2.0 }

func makeAdder(base: Int) -> (Int) -> Int {
  { x in base + x }
}

["apple", "ball", "carrot"].sorted(by: { s1, s2 in s1.count < s2.count })
```

- पहले उदाहरण में टाइप का अनुमान स्थिरांक `mean` पर लगे एनोटेशन से लगाया जा सकता है।
- दूसरे में कंपाइलर को `makeAdder` की परिभाषा से पता है कि `base` एक int है और जो फंक्शन लौटाया जाता है उसका टाइप `(Int) -> Int` होना चाहिए। इसी आधार पर कंपाइलर जाँच सकता है कि अगर `x` एक `Int` है, तो क्लोज़र का टाइप `(Int) -> Int` होगा। इसलिए क्लोज़र में टाइप सिग्नेचर लिखना छोड़ा जा सकता है, क्योंकि `(Int) -> Int` ही एकमात्र मान्य सिग्नेचर है जो इस क्लोज़र का हो सकता है।
- तीसरा उदाहरण भी ऐसा ही है, लेकिन यहाँ कंपाइलर को कुछ टाइप की जानकारी उस ऐरे से लेनी पड़ती है जिस पर मेथड इस्तेमाल हो रहा है। कंपाइलर जानता है कि `sorted(by:)` मेथड पैरामीटर के रूप में एक ऐसा क्लोज़र लेता है जिसके दो पैरामीटर उसी टाइप के हैं जिस टाइप के जमा किए जा रहे कलेक्शन के एलिमेंट हैं, और जो एक `Bool` लौटाता है। इसलिए कंपाइलर अनुमान लगा सकता है कि क्लोज़र का रिटर्न टाइप `Bool` ही होगा। और चूँकि मेथड एक स्ट्रिंग ऐरे पर इस्तेमाल हो रहा है, कंपाइलर तय कर सकता है कि `s1` और `s2` दोनों पैरामीटर का टाइप `String` ही होगा।

## क्लोज़र की सीमाएँ

जैसा ऊपर बताया गया, Swift में फंक्शन और क्लोज़र बहुत मिलते-जुलते हैं, पर कुछ ज़रूरी अंतर भी हैं:

- क्लोज़र बाहरी आर्गुमेंट लेबल इस्तेमाल नहीं कर सकते। इन्हें बनाने का कोई तरीका नहीं है, और क्लोज़र को कॉल करते समय पैरामीटर का नाम इस्तेमाल करने पर एरर मिलती है:

```swift
let add5 = { x in x + 5 }
add5(x: 10)
// Error: Extraneous argument label 'x:' in call
```

- क्लोज़र के पैरामीटर की कोई डिफ़ॉल्ट पैरामीटर वैल्यू नहीं हो सकती।
- क्लोज़र के पैरामीटर वेरिएडिक पैरामीटर हो सकते हैं, लेकिन उनका नाम और टाइप एनोटेशन होना ज़रूरी है।
