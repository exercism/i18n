# विवरण

## अक्षर

[कैरेक्टर एन्कोडिंग][char-encoding] एक ऐसी विशेष परिपाटी है जिसका उपयोग किसी प्राकृतिक भाषा के टेक्स्ट के तत्वों को बाइट के क्रम के रूप में निरूपित करने के लिए किया जाता है।
यहाँ "टेक्स्ट का तत्व" किसी भी ऐसी इकाई को कह सकते हैं जिसका किसी प्राकृतिक भाषा में महत्व हो, जैसे अक्षर, स्पेस, विराम चिह्न, इमोजी, आइडियोग्राम, आदि।

NASM (The Netwide Assembler, इस ट्रैक में इस्तेमाल होने वाला असेंबलर) में [ASCII][ascii] के ज़रिए डेटा परिभाषित करने का समर्थन है।

NASM में कैरेक्टर कॉन्स्टेंट अधिकतम 8 बाइट लंबे हो सकते हैं और इन्हें सिंगल कोट (`'`), डबल कोट (`"`) या बैकटिक (`` ` ``) का उपयोग करके परिभाषित किया जा सकता है:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

विशेष अक्षरों को बैकटिक में परिभाषित करना ज़रूरी है और उन्हें `\` से एस्केप करना होता है:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASM में [UTF-8][utf8] में [यूनिकोड अक्षरों][unicode] का समर्थन भी है, जिन्हें `\u` या `\U` के साथ और बैकटिक में दिया जाता है:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

ध्यान दीजिए कि x86-64 में किसी भी कैरेक्टर एन्कोडिंग के लिए अलग टाइप के रूप में कोई बिल्ट-इन समर्थन नहीं है।
असेंबली में डेटा बाइट का एक क्रम होता है, और उन बाइट को अक्षर, संख्या या किसी और चीज़ के रूप में कैसे समझा जाए, यह प्रोग्रामर पर छोड़ दिया जाता है।

उदाहरण के लिए, ASCII अक्षर '0' एक ही बाइट है जिसकी वैल्यू 48 है।
इसलिए किसी बाइट में 48 संग्रहीत करना ठीक वैसा ही है जैसे ASCII अक्षर '0' संग्रहीत करना:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

इसी कारण अक्षरों पर काम करना उन बाइट में मौजूद वैल्यू को सीधे बदलकर किया जाता है:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## स्ट्रिंग

[स्ट्रिंग][string] अक्षरों का एक क्रम होती है।
असेंबली में इसे आम तौर पर ऐरे के रूप में लागू किया जाता है।

NASM में स्ट्रिंग को उसी तरह घोषित करना संभव है जैसे कोई भी ऐरे घोषित किया जा सकता है:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

स्ट्रिंग और दूसरे ऐरे में एक अंतर यह है कि NASM में स्ट्रिंग को वैल्यू अलग करने वाले कॉमा (`,`) के बिना भी घोषित करने का समर्थन है।
वैल्यू के बीच कॉमा डालना भी संभव है:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

ध्यान दीजिए कि जैसा पहले बताया गया, अक्षर बस बाइट होते हैं (या यूनिकोड एन्कोडिंग में बाइट का एक क्रम):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

चूँकि हर ASCII अक्षर एक ही बाइट लेता है, किसी बड़े साइज़ में इसके बाद आने वाला हर बाइट `0` होता है।
उदाहरण के लिए, `'a'` को qword (8 बाइट) के रूप में घोषित करने का मतलब है कि पहला बाइट `'a'` (`97`) है और बाकी सात बाइट सब `0` हैं।

इस कारण ये सब बराबर हैं:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
असेंबली में स्ट्रिंग अपने आप ASCII NUL अक्षर (वैल्यू `0`) पर समाप्त नहीं होती।

C जैसी उच्च-स्तरीय भाषाओं के साथ काम करते समय यह प्रोग्रामर की ज़िम्मेदारी है कि वह सुनिश्चित करे कि स्ट्रिंग के अंत में सही टर्मिनेटर जोड़ा गया है, अगर कोई ज़रूरी हो।
~~~~

## स्ट्रिंग इंस्ट्रक्शन

चूँकि स्ट्रिंग एक ऐरे होती है, आप उसके साथ किसी भी ऐरे की तरह काम कर सकते हैं, यानी मेमोरी को सीधे डीरेफरेंस करके:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

इसके अलावा, मेमोरी में बाइट के क्रम में वैल्यू लोड करने, एक जगह से दूसरी जगह ले जाने और संग्रहीत करने के लिए कुछ इंस्ट्रक्शन हैं।
इन्हें _स्ट्रिंग इंस्ट्रक्शन_ कहा जाता है, लेकिन इनका उपयोग मेमोरी में बाइट के किसी भी क्रम के साथ, यानी किसी भी ऐरे के साथ किया जा सकता है:

| इंस्ट्रक्शन  | यह क्या करता है                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | `rsi` से इंगित मेमोरी लोकेशन से एक वैल्यू को `rax` में लोड करता है                                                |
| [stos][stos] | `rax` से एक वैल्यू को `rdi` से इंगित मेमोरी लोकेशन में संग्रहीत करता है                                               |
| [movs][movs] | `rsi` से इंगित मेमोरी लोकेशन से एक वैल्यू की प्रतिलिपि बनाकर उसे `rdi` से इंगित मेमोरी लोकेशन में संग्रहीत करता है    |
| [cmps][cmps] | `rsi` से इंगित मेमोरी लोकेशन की वैल्यू की तुलना `rdi` से इंगित मेमोरी लोकेशन की वैल्यू से करता है |
| [scas][scas] | `rax` की वैल्यू की तुलना `rdi` से इंगित मेमोरी लोकेशन की वैल्यू से करता है                                |

ध्यान दीजिए कि ये इंस्ट्रक्शन कोई स्पष्ट ऑपरेंड _नहीं_ लेते।
इनके ऑपरेंड अंतर्निहित होते हैं।

एक सामान्य नियम यह है:

1. जब इनका स्रोत ऑपरेंड कोई मेमोरी लोकेशन हो, तो उसका एड्रेस `rsi` में रखा जाना चाहिए (`s` अर्थात स्रोत)।
2. जब इनका गंतव्य ऑपरेंड कोई मेमोरी लोकेशन हो, तो उसका एड्रेस `rdi` में रखा जाना चाहिए (`d` अर्थात गंतव्य)।
3. अगर इनमें से एक ऑपरेंड मेमोरी लोकेशन न हो, तो वह `rax` रजिस्टर होता है।

ध्यान दीजिए कि ये इंस्ट्रक्शन जो काम करते हैं, उसी के अनुसार मेमोरी एड्रेस को अपने आप डीरेफरेंस कर लेते हैं।

ये सभी अलग-अलग साइज़ में काम कर सकते हैं।
साइज़ बताने के लिए इनके अंत में एक सफिक्स लगाया जाता है:

| सफिक्स | अर्थ | साइज़    |
| :----: | ------- | :------ |
|  `b`   | बाइट    | 1 बाइट  |
|  `w`   | वर्ड    | 2 बाइट |
|  `d`   | ड्वर्ड   | 4 बाइट |
|  `q`   | क्वर्ड   | 8 बाइट |

उदाहरण के लिए:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

ये जिन एड्रेस का उपयोग करते हैं, उन्हें ऑपरेशन के साइज़ के बराबर बढ़ा या घटा भी देते हैं।
यह बदलाव **डायरेक्शन फ्लैग (DF)** की वैल्यू के अनुसार होता है:

- अगर `DF` क्लियर हो, तो एड्रेस ऑपरेशन के साइज़ के बराबर _बढ़ा_ दिए जाते हैं।
- अगर `DF` सेट हो, तो एड्रेस इसके बजाय उतने ही बराबर _घटा_ दिए जाते हैं।

System V ABI कहता है कि फंक्शन में प्रवेश करते समय डायरेक्शन फ्लैग क्लियर होना चाहिए।
इसलिए _डिफॉल्ट व्यवहार यह है कि मेमोरी को एड्रेस के बढ़ते क्रम में पढ़ा/लिखा जाता है_।

डायरेक्शन फ्लैग क्लियर करने के लिए [cld][cld] इंस्ट्रक्शन का उपयोग किया जा सकता है, जबकि उसे सेट करने के लिए [std][std] इंस्ट्रक्शन का:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
कॉलर यह अपेक्षा करता है कि System V ABI के अनुसार कोई भी कॉल किया गया फंक्शन लौटने के बाद `DF` क्लियर हो।
अगर आप कभी `DF` सेट करें, तो `ret` से पहले उसे क्लियर करना सुनिश्चित कीजिए।
~~~~

### Lods

यह इंस्ट्रक्शन उस मेमोरी लोकेशन से _पढ़ता_ है जिसका एड्रेस `rsi` में है और उस वैल्यू की प्रतिलिपि `rax` में बना देता है।

`rsi` में मौजूद वैल्यू पढ़े गए बाइट की संख्या के बराबर अपडेट हो जाती है:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

यह इंस्ट्रक्शन `rax` की वैल्यू की प्रतिलिपि बनाकर उसे उस मेमोरी लोकेशन में _लिखता_ है जिसका एड्रेस `rdi` में है।

`rdi` में मौजूद वैल्यू लिखे गए बाइट की संख्या के बराबर अपडेट हो जाती है:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

यह इंस्ट्रक्शन उस मेमोरी लोकेशन से _पढ़ता_ है जिसका एड्रेस `rsi` में है और उस वैल्यू को उस मेमोरी लोकेशन में _लिखता_ है जिसका एड्रेस `rdi` में है।
इस इंस्ट्रक्शन का `rax` की वैल्यू पर कोई असर नहीं पड़ता।

`rsi` और `rdi` दोनों एक मेमोरी लोकेशन से दूसरी में कॉपी किए गए बाइट की संख्या के बराबर अपडेट हो जाते हैं:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

यह इंस्ट्रक्शन उस मेमोरी लोकेशन से _पढ़ता_ है जिसका एड्रेस `rsi` में है और साथ ही उस मेमोरी लोकेशन से भी _पढ़ता_ है जिसका एड्रेस `rdi` में है।
फिर यह `cmp` के अनुसार वैल्यू की तुलना करके फ्लैग अपडेट करता है।

`rsi` और `rdi` दोनों दोनों लोकेशन से पढ़े गए बाइट की संख्या के बराबर अपडेट हो जाते हैं:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

यह इंस्ट्रक्शन `rax` की वैल्यू की तुलना उस वैल्यू से करता है जिसे वह उस मेमोरी लोकेशन से _पढ़ता_ है जिसका एड्रेस `rdi` में है।
फिर यह `cmp` के अनुसार फ्लैग अपडेट करता है।

`rdi` में मौजूद वैल्यू पढ़े गए बाइट की संख्या के बराबर अपडेट हो जाती है:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

इनके अलावा, [rep][rep] इंस्ट्रक्शन मेमोरी के साथ सीधे काम नहीं करता।
इसके बजाय इसे ऊपर बताए गए दूसरे इंस्ट्रक्शन के आगे प्रीफिक्स के रूप में लगाया जा सकता है, जिससे वे इंस्ट्रक्शन _दोहराए_ जाते हैं।

जब इनके आगे `rep` लगाया जाता है, तो स्ट्रिंग इंस्ट्रक्शन `rcx` में मौजूद वैल्यू के बराबर बार दोहराए जाते हैं।
हर बार `rcx` की वैल्यू `1` कम हो जाती है।
ध्यान दीजिए कि इंस्ट्रक्शन का उपयोग करने से पहले `rcx` की वैल्यू सेट करनी ज़रूरी है:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

`rcx` को काउंटर के रूप में उपयोग करने के अलावा, `repe` (या `repz`) और `repne` (या `repnz`) क्रमशः तब चलना रोक देते हैं जब `zero flag (ZF)` क्लियर या सेट हो:

| इंस्ट्रक्शन      | कहाँ जोड़ा जा सकता है     | क्या पहले रुक सकता है        |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`, `lods`, `stos` | नहीं                      |
| `repe`,`repz`    | `cmps`, `scas`         | हाँ, ZF के 0 होने पर रुक जाता है |
| `repne`, `repnz` | `cmps`, `scas`         | हाँ, ZF के 1 होने पर रुक जाता है |

आधुनिक CPU पर, बड़े ब्लॉक में डेटा ले जाते समय `rep movs` और `rep stos` आम तौर पर तेज़ विकल्प होते हैं।
लेकिन दूसरे स्ट्रिंग इंस्ट्रक्शन, और यहाँ तक कि `movs` और `stos` भी जब वे `rep` के बिना चलते हैं, आम तौर पर एक साधारण लूप से धीमे होते हैं।

इस विषय पर और गहराई से जानकारी [इस संदर्भ पुस्तक के अध्याय 16.9, "String instructions"][agner-optimization-guide] में मिल सकती है।
