# विस्तृत परिचय

बाकी कई भाषाओं की तरह Go में भी पॉइंटर होते हैं।
अगर आप पॉइंटर के लिए नए हैं, तो ये थोड़े रहस्यमय लग सकते हैं, लेकिन एक बार इनकी आदत पड़ जाने के बाद ये काफी सीधे-सरल लगते हैं।
ये Go का बहुत ज़रूरी हिस्सा हैं, इसलिए इन्हें ठीक से समझने में थोड़ा समय ज़रूर लगाइए।

बारीकियों में जाने से पहले यह समझ लेना अच्छा रहेगा कि पॉइंटर किस काम आते हैं।
पॉइंटर हमारे प्रोग्राम के दूसरे हिस्सों के साथ मेमोरी साझा करने का तरीका हैं। यह दो बड़े कारणों से काम का है:

1. जब हमारे पास बहुत सारा डेटा होता है, तो फंक्शन से फंक्शन तक उसकी कॉपी बनाकर भेजना बहुत अकुशल होता है।
   इसके बजाय उस जगह की मेमोरी लोकेशन भेजकर हम अपने प्रोग्राम पर पड़ने वाले संसाधनों का भार बहुत कम कर सकते हैं।
2. फंक्शनों के बीच पॉइंटर भेजकर हम डेटा की उस एक ही कॉपी तक सीधे पहुँच सकते हैं और उसे बदल सकते हैं। इसका मतलब है कि किसी एक फंक्शन ने जो भी बदलाव किए, फंक्शन खत्म होते ही प्रोग्राम के दूसरे हिस्सों को वे तुरंत दिख जाते हैं।

## वेरिएबल और मेमोरी

मान लीजिए हमारे पास एक साधारण पूर्णांक वेरिएबल `a` है:

```go
var a int
```

जब हम कोई वेरिएबल घोषित करते हैं, तो Go को उसकी वैल्यू रखने के लिए मेमोरी में जगह ढूँढनी पड़ती है।
यह काम हमसे काफी हद तक छिपा रहता है। जब हमें उस मेमोरी में रखी वैल्यू निकालनी होती है, तो हम बस वेरिएबल का नाम लेकर उसे पा सकते हैं।

जैसे, जब हम `a + 2` लिखते हैं, तो हम वाकई वेरिएबल `a` से जुड़ी मेमोरी में रखी वैल्यू निकालकर उसमें 2 जोड़ रहे होते हैं।

इसी तरह, जब हमें `a` वाली मेमोरी में रखी वैल्यू बदलनी होती है, तो हम वेरिएबल का नाम इस्तेमाल करके उस पर नई वैल्यू असाइन कर सकते हैं:

```go
a = 3
```

अब `a` से जुड़ी मेमोरी में वैल्यू `3` रखी होगी।

## पॉइंटर

वेरिएबल हमें मेमोरी में रखी वैल्यू को इंगित करने देते हैं, लेकिन कभी-कभी यह जानना भी काम का होता है कि वेरिएबल जिस **मेमोरी एड्रेस** की ओर इशारा कर रहा है, वह कौन-सा है।
**पॉइंटर** उन वैल्यू के मेमोरी एड्रेस रखते हैं।
पॉइंटर टाइप वाला वेरिएबल घोषित करने के लिए आप मूल टाइप से पहले एक एस्टरिस्क लगाते हैं:

```go
var p *int // 'p' contains the memory address of an integer
```

यहाँ हमने "int की ओर पॉइंटर" टाइप (`*int`) का एक वेरिएबल `p` घोषित किया है।
इसका मतलब है कि `p` में एक पूर्णांक का मेमोरी एड्रेस रहेगा।
पॉइंटर की ज़ीरो वैल्यू `nil` होती है, क्योंकि `nil` पॉइंटर के पास कोई मेमोरी एड्रेस नहीं होता।

### किसी वेरिएबल का पॉइंटर पाना

किसी वेरिएबल की वैल्यू का मेमोरी एड्रेस पाने के लिए हम `&` ऑपरेटर इस्तेमाल कर सकते हैं।
जैसे, अगर हम वेरिएबल `a` का मेमोरी एड्रेस ढूँढकर पॉइंटर `p` में रखना चाहते हैं, तो हम यह कर सकते हैं:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### पॉइंटर के ज़रिए वैल्यू तक पहुँचना (डीरेफरेंसिंग)

जब हमारे पास कोई पॉइंटर होता है, तो हम यह जानना चाह सकते हैं कि पॉइंटर जिस मेमोरी एड्रेस को दर्शाता है, उसमें कौन-सी वैल्यू रखी है।
यह हम `*` ऑपरेटर की मदद से कर सकते हैं:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p` ऑपरेशन `p` में रखे मेमोरी एड्रेस पर पड़ी वैल्यू निकाल लाता है।
इस ऑपरेशन को अक्सर "डीरेफरेंसिंग" कहा जाता है।

हम डीरेफरेंस ऑपरेटर का इस्तेमाल करके पॉइंटर द्वारा इंगित मेमोरी एड्रेस पर नई वैल्यू असाइन भी कर सकते हैं:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa` पर वैल्यू असाइन करने से उस मेमोरी एड्रेस पर रखी वैल्यू बदल जाती है जो `pa` के पास है।
चूँकि `pa` के पास `a` का मेमोरी एड्रेस है, इसलिए `*pa` पर असाइन करके हम वाकई `a` की वैल्यू बदल रहे होते हैं!

लेकिन एक सावधानी ज़रूरी है: डीरेफरेंस करने से पहले हमेशा जाँच लीजिए कि पॉइंटर `nil` नहीं है।
`nil` पॉइंटर को डीरेफरेंस करने पर प्रोग्राम रनटाइम पर क्रैश हो जाएगा!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### स्ट्रक्ट के पॉइंटर

अब तक हमने सिर्फ प्रिमिटिव वैल्यू के पॉइंटर देखे हैं।
स्ट्रक्ट के लिए भी पॉइंटर बनाए जा सकते हैं:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

हम एक नया `Person` बनाकर सीधे उसका पॉइंटर भी रख सकते थे:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

जब हमारे पास किसी स्ट्रक्ट का पॉइंटर होता है, तो उसके किसी फील्ड तक पहुँचने से पहले पॉइंटर को डीरेफरेंस करने की ज़रूरत नहीं होती:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## स्लाइस और मैप पहले से ही पॉइंटर हैं

स्लाइस और मैप खास टाइप हैं, क्योंकि इनकी अंदरूनी बनावट में पहले से पॉइंटर होते हैं।
इसका मतलब है कि इन टाइप की वैल्यू का मेमोरी एड्रेस साझा करने के लिए अक्सर हमें इनके पॉइंटर बनाने की ज़रूरत नहीं पड़ती।
सोचिए, हमारे पास एक फंक्शन है जो किसी मैप में एक की की वैल्यू बढ़ाता है:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

अगर हम एक मैप बनाकर इस फंक्शन को कॉल करें, तो फंक्शन के खत्म होने के बाद भी मैप में किए गए बदलाव बने रहते हैं।
पॉइंटर इस्तेमाल करने पर भी हमें ऐसा ही व्यवहार मिलता, लेकिन ध्यान दीजिए कि इस उदाहरण में हमने न कोई रेफरेंसिंग या डीरेफरेंसिंग की, न पॉइंटर का कोई और सिंटैक्स इस्तेमाल किया:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

स्लाइस में पहले से मौजूद किसी एलिमेंट को बदलने पर भी यही बात लागू होती है।

लेकिन `append` जैसी क्रियाएँ, जो नया स्लाइस लौटाती हैं, एक खास मामला हैं। हो सकता है कि वे फंक्शन के बाहर वाले स्लाइस को बदलें ही नहीं।
ऐसा स्लाइस के अंदरूनी काम करने के तरीके की वजह से होता है, लेकिन हम इस पर विस्तार से नहीं जाएँगे, क्योंकि यह एक अधिक उन्नत विषय है।
अगर आप सच में जानने को उत्सुक हैं, तो इसके बारे में और पढ़ सकते हैं: [Go ब्लॉग: 'append' की कार्यप्रणाली][mechanics-of-append]

## पॉइंटर अंकगणित

दूसरी भाषाओं के उलट Go में पॉइंटर अंकगणित का समर्थन नहीं है।
इसका मतलब है कि पॉइंटर की वैल्यू बढ़ाकर आप एक वैल्यू के मेमोरी एड्रेस से दूसरी वैल्यू के एड्रेस तक नहीं पहुँच सकते।
इसलिए नीचे जैसे कोड टुकड़े मान्य नहीं हैं:

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
