# परिचय

## रिज़ल्ट

Gleam एरर हैंडलिंग के लिए एक्सेप्शन का उपयोग नहीं करता। इसके बजाय जो फंक्शन सफल भी हो सकते हैं और असफल भी, वे जेनेरिक `Result` टाइप लौटाते हैं।

`Result` टाइप भाषा में ही बना हुआ है, इसलिए आपको इसे बनाना या इम्पोर्ट करना नहीं पड़ता। लेकिन अगर आप इसे खुद बनाते, तो वह ऐसा दिखता:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

जब कोई फंक्शन सफल होता है, तब `Ok` वेरिएंट लौटाया जाता है; और जब कोई फंक्शन असफल होता है, तब `Error` वेरिएंट लौटाया जाता है।

रिज़ल्ट Gleam में बहुत आम हैं, और Gleam के प्रोग्रामर इनके साथ काम करना आसान बनाने के लिए आमतौर पर [`gleam/result` मॉड्यूल](https://hexdocs.pm/gleam_stdlib/gleam/result.html) का उपयोग करते हैं।

`result.map` फंक्शन की मदद से आप रिज़ल्ट के अंदर मौजूद वैल्यू पर कोई फंक्शन कॉल कर सकते हैं, बशर्ते वह `Ok` हो; और अगर वह `Error` हो तो उसे बिना बदले आगे भेज सकते हैं।

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

`result.try` फंक्शन भी ऐसा ही है, लेकिन इसमें कॉलबैक फंक्शन से उम्मीद की जाती है कि वह एक रिज़ल्ट लौटाए। यह कई ऐसे फंक्शन को एक साथ जोड़ने में काम आता है जो रिज़ल्ट लौटाते हैं।

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
