# परिचय

## एरर इंटरफेस

Go में एरर हैंडलिंग के लिए एक्सेप्शन का इस्तेमाल **नहीं** किया जाता।
इसके बजाय, एरर उन टाइप की सामान्य _वैल्यू_ होती हैं जो बिल्ट-इन `error` इंटरफेस को लागू करते हैं।
`error` इंटरफेस बहुत छोटा है।
इसमें सिर्फ एक मेथड `Error()` है, जो एरर का संदेश एक स्ट्रिंग के रूप में लौटाता है।

```go
type error interface {
  Error() string
}
```

अगर ऐसा फंक्शन बना रहे हैं जिसमें चलते समय कोई एरर हो सकती है और वह एरर कॉल करने वाले तक पहुँचनी चाहिए, तो रिटर्न टाइप में `error` भी शामिल करना ज़रूरी है।
अगर फंक्शन एक से अधिक वैल्यू लौटाता है, तो परंपरा के मुताबिक `error` हमेशा सबसे बाद में रहता है।

```go
func DoSomething() (int, error) {
  // ...
}
```

## साधारण एरर बनाना और लौटाना

एरर इंटरफेस हमेशा खुद लागू करना ज़रूरी नहीं है।
एक साधारण एरर बनाने के लिए आप स्टैंडर्ड लाइब्रेरी पैकेज `errors` का फंक्शन `errors.New()` इस्तेमाल कर सकते हैं।
इसमें सिर्फ एरर का संदेश स्ट्रिंग के रूप में देना होता है, और `errors.New()` खुद ही एक ऐसी वैल्यू बना देता है जिसमें आपका संदेश होता है और जो `error` इंटरफेस को लागू करती है।

अगर फंक्शन एरर लौटाता है, तो बाकी सभी रिटर्न पैरामीटर के लिए शून्य वैल्यू लौटाना अच्छा तरीका माना जाता है:

```go
func DoSomething() (SomeStruct, int, error) {
  // ...
  return SomeStruct{}, 0, errors.New("failed to calculate result")
}
```

~~~~exercism/caution
यह नहीं मान लेना चाहिए कि एरर होने पर सभी फंक्शन बाकी रिटर्न वैल्यू के लिए शून्य वैल्यू ही लौटाते हैं।
बेहतर यही है कि एरर आने पर बाकी किसी भी रिटर्न वैल्यू को इस्तेमाल करना सुरक्षित न माना जाए।
इसके अपवाद सिर्फ वे मामले हैं जहाँ डॉक्युमेंटेशन साफ़ कहता है कि एरर की स्थिति में बाकी रिटर्न वैल्यू का कोई मतलब रहता है।
~~~~

अगर ऐसी साधारण एरर आपको कई जगहों पर चाहिए, तो `errors.New` को सीधे जहाँ-तहाँ लिखने के बजाय एरर के लिए एक वेरिएबल घोषित कीजिए।
परंपरा के मुताबिक वेरिएबल का नाम `Err` या `err` से शुरू होना चाहिए (यह इस पर निर्भर करता है कि वह एक्सपोर्टेड है या नहीं)।
ऐसे एरर वेरिएबलो को अक्सर _सेंटिनल एरर_ कहा जाता है।

```go
import "errors"

var ErrNotFound = errors.New("resource was not found")

func DoSomething() error {
  // ...
  return ErrNotFound
}
```

अगर फंक्शन के चलने के दौरान कोई एरर नहीं हुई, तो यह बताने के लिए एरर की जगह `nil` लौटाइए:

```go
func Foo() (int, error) {
  return 10, nil
}
```

## एरर की जाँच

जब आप कोई ऐसा फंक्शन कॉल करते हैं जो एरर लौटाता है, तो आम तौर पर एरर की वैल्यू `err` नाम के वेरिएबल में रखी जाती है।
फंक्शन के वास्तविक नतीजे का उपयोग करने से पहले आपको जाँच लेना चाहिए कि कोई एरर नहीं थी।

अपने कोड के "हैपी पाथ" को और अंदर तक नेस्ट होने से बचाने के लिए एरर वाले मामलों को पहले निपटा देना चाहिए।
एरर की `nil` से तुलना करने के लिए हम `==` और `!=` इस्तेमाल कर सकते हैं, और जब `err` की वैल्यू `nil` न हो तो हमें पता चल जाता है कि कोई एरर हुई थी।

```go
func processUserFile() error {
	file, err := os.Open("./users.csv")
	if err != nil {
		return err
	}

	// do something with file
}
```

ज़्यादातर मामलों में एरर ऊपर दिए उदाहरण की तरह फंक्शन स्टैक में ऊपर तक लौटा दी जाती है।
एरर को संभालने का एक और तरीका यह हो सकता है कि उसे लॉग में लिख दिया जाए और फिर कोई और काम जारी रखा जाए।
अच्छा तरीका यही है कि एरर को या तो लौटाया जाए या लॉग में लिखा जाए, दोनों कभी नहीं।

चूँकि Go में ज़्यादातर फंक्शन अपनी रिटर्न वैल्यू में एरर भी शामिल करते हैं, इसलिए Go कोड में आपको हर जगह `if err != nil` पैटर्न दिखेगा और आप उसका इस्तेमाल भी करेंगे।

## कस्टम एरर टाइप

अगर आप चाहते हैं कि आपकी एरर में सिर्फ एरर संदेश वाली स्ट्रिंग से ज़्यादा जानकारी हो, तो आप एक कस्टम एरर टाइप बना सकते हैं।
जैसा पहले बताया गया, Go में हर वह चीज़ एरर का काम कर सकती है जो `error` इंटरफेस को लागू करती है (यानी जिसमें `Error() string` मेथड हो)।

कस्टम एरर टाइप बनाने के लिए आम तौर पर स्ट्रक्ट का उपयोग किया जाता है।
परंपरा के मुताबिक कस्टम एरर टाइप के नाम के अंत में `Error` होना चाहिए।
साथ ही, `Error() string` मेथड को पॉइंटर रिसीवर के साथ बनाना सबसे अच्छा होता है; इसके पीछे की वजह जानने के लिए यह [Stackoverflow टिप्पणी][stackoverflow-errors] देखिए।
ध्यान रखिए, इसका मतलब है कि आपको अपनी कस्टम एरर का पॉइंटर लौटाना होगा, वरना वह `error` की तरह नहीं गिनी जाएगी, क्योंकि बिना पॉइंटर वाली वैल्यू `Error() string` मेथड नहीं देती।

```go
type MyCustomError struct {
  message string
  details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.message, e.details)
}

func someFunction() error {
  // ...
  return &MyCustomError{
    message: "...",
    details: "...",
  }
}
```
