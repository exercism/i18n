# म्यूटेबिलिटी

म्यूटेबिलिटी Rust में किसी एक खास बाइंडिंग का गुण है। हर बाइंडिंग या तो इम्यूटेबल होती है या म्यूटेबल। इम्यूटेबल बाइंडिंग की वैल्यू बदली नहीं जा सकती, जबकि म्यूटेबल बाइंडिंग की वैल्यू बदली जा सकती है। डिफॉल्ट रूप से हर बाइंडिंग इम्यूटेबल होती है।

## बाइंडिंग

बाइंडिंग, सोर्स कोड में दिखने वाले किसी वेरिएबल नाम और प्रोग्राम चलते समय मेमोरी के किसी खास हिस्से के बीच का जुड़ाव है। सख्ती से कहें तो बाइंडिंग सिर्फ कंपाइलेशन के दौरान ही होती है। कंपाइल होने से पहले मेमोरी में कुछ आवंटित ही नहीं हुआ होता, और कंपाइल होने के बाद मशीन कोड नाम वाले वेरिएबलो से नहीं, सिर्फ मेमोरी एड्रेस से काम करता है।

बाइंडिंग आम तौर पर `let` कीवर्ड से बनती हैं। इसके अलावा फंक्शन के पैरामीटर से, और कुछ और मौकों पर भी बाइंडिंग बनती हैं।

बाइंडिंग के कई गुण हो सकते हैं, जिनमें सबसे ज़रूरी है म्यूटेबिलिटी। म्यूटेबल बाइंडिंग वह है जिसकी बँधी हुई मेमोरी की वैल्यू बदलना वैध होता है। प्रोग्राम सही रहें, यह सुनिश्चित करने के लिए Rust हर बाइंडिंग की म्यूटेबिलिटी पर सख्ती से ध्यान रखता है और उसे लागू करता है। जो प्रोग्राम किसी इम्यूटेबल होनी चाहिए थी ऐसी बाइंडिंग को गलत तरीके से बदलने की कोशिश करते हैं, Rust उन्हें अस्वीकार कर देता है।

## म्यूटेबिलिटी

व्यवहार में म्यूटेबिलिटी अक्सर आसान होती है। बाइंडिंग बनाते समय `mut` कीवर्ड लगाइए, और आप उसकी वैल्यू बदल सकते हैं।

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### म्यूटेबल से इम्यूटेबल में बदलना

किसी म्यूटेबल बाइंडिंग को हमेशा इम्यूटेबल बनाया जा सकता है। यह बदलाव भीतर ही भीतर हो जाता है।

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### इम्यूटेबल से म्यूटेबल में बदलना

आम तौर पर जब भी ओनरशिप ट्रांसफर होती है, उस वक्त किसी वैल्यू को इम्यूटेबल से म्यूटेबल बनाया जा सकता है।

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

बिंदु `(1)` पर स्ट्रिंग की ओनरशिप `x` से `y` को चली जाती है, और इसी वजह से हम उस वैल्यू को म्यूटेबल बना पाते हैं।

### फंक्शन के पैरामीटर में म्यूटेबिलिटी

फंक्शन के पैरामीटर म्यूटेबल बनाने के दो तरीके हैं। पहला, और जो अधिक आम है, C में रेफरेंस से पास करने जैसा है:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

इस उदाहरण में म्यूटेबिलिटी तीन जगह साफ-साफ लिखी गई है। म्यूटेबल रेफरेंस काम करें, इसके लिए तीनों घोषणाएँ ज़रूरी हैं।
`(2)` में बाइंडिंग `x` को म्यूटेबल घोषित किया गया है। इस वैल्यू का सबसे ऊपर वाला मालिक यही बाइंडिंग है।
`(3)` में उस वैल्यू को म्यूटेबल रूप से बॉरो किया जाता है, ताकि उसे `increment` फंक्शन में पास किया जा सके।
`(1)` में उसी रेफरेंस के लिए एक नई म्यूटेबल बाइंडिंग `n` बनती है।

पैरामीटर को म्यूटेबल बनाने का एक और तरीका भी है, जो कम आम है, पर कभी-कभी काम आता है। इसमें वैल्यू की ओनरशिप होती है, पर बाइंडिंग म्यूटेबल होती है।

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

इस उदाहरण में कम घोषणाएँ लिखनी पड़ती हैं, क्योंकि यह असल में ओनरशिप का ट्रांसफर है जिसमें म्यूटेबिलिटी अपने आप बढ़ जाती है। यह इसलिए काम करता है कि `i32` एक `Copy` टाइप है, जो डेटा की कॉपी भीतर ही भीतर बना देता है।
`(1)` में हम घोषित करते हैं कि `increment_internally` अपने पैरामीटर के रूप में `n` नाम का म्यूटेबल `i32` स्वीकार करता है, जिसकी ओनरशिप उसी के पास है।
`(2)` में हम `x` को वैल्यू `1` की इम्यूटेबल बाइंडिंग घोषित करते हैं।
`(3)` में `x` मेमोरी की एक नई जगह पर कॉपी हो जाता है। `x` इम्यूटेबल ही रहता है, जबकि `n` म्यूटेबल है।

इन दोनों तरीकों को मिलाना भी संभव है, यानी म्यूटेबल रेफरेंस के लिए म्यूटेबल बाइंडिंग देना (`mut n: &mut i32` वगैरह), पर असल में ऐसा कम ही चाहिए होता है।

### `let` के बिना म्यूटेबिलिटी

Rust में कुछ और रचनाएँ भी बाइंडिंग बनाती हैं, जैसे `if let`, `match` वगैरह। ये बाइंडिंग भी म्यूटेबल हो सकती हैं।

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

यह उदाहरण पहले `v = Some(2)` देता है, और उसके बाद `v = None`.

## शैडोइंग

किसी वैल्यू को बदलते-बदलते उसी वेरिएबल नाम को `let` से बार-बार दोबारा घोषित करके फिर से इस्तेमाल करना संभव है, और अक्सर यही ठीक तरीका भी होता है। इसे शैडोइंग कहते हैं।

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

लेकिन यह म्यूटेबिलिटी का मामला नहीं है; सिद्धांत रूप से पुरानी वैल्यू अब भी मौजूद रहती हैं। `Drop` न होने वाले टाइप के मामले में कंपाइलर नई मेमोरी आवंटित करने के बजाय उसी मेमोरी जगह को बदल देना चुन सकता है। पर `Drop` टाइप के मामले में, या जब पुरानी बाइंडिंग दोबारा इस्तेमाल होती हो, तो कंपाइलर ऐसा कभी नहीं करता।

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
