# विवरण

[`interfaces`][interfaces] किसी क्लास के उपयोग को उसके कार्यान्वयन से [अलग करने][wiki-loose-coupling] का मुख्य तरीका है। यह अलगाव कार्यान्वयन के रखरखाव में लचीलापन देता है और टाइप-सेफ जेनेरिक व्यवहार को सहारा देने में मदद करता है।

इंटरफेस का सिंटैक्स क्लास या स्ट्रक्चर जैसा ही होता है, बस फर्क इतना है कि मेथड और प्रॉपर्टी सिर्फ सिग्नेचर के रूप में दिखते हैं और उनका कोई बॉडी नहीं दिया जाता।

```csharp
public interface ILanguage
{
    string Speak();
}

public interface IItalianLanguage : ILanguage
{
    string Speak();
    string SpeakItalian();
}

public interface IScriptConverter
{
    string Version { get; set; }
    string ConvertCyrillicToLatin(string cyrillic);
}
```

इंटरफेस को लागू करने वाला क्लास या स्ट्रक्चर इंटरफेस में परिभाषित सभी ऑपरेशन ज़रूर लागू करता है।

इंटरफेस आम तौर पर इनमें से एक या ज़्यादा काम करते हैं:

- कई अलग-अलग क्लास को इस्तेमाल करने वाले कोड द्वारा एक ही तरह से, यानी जेनेरिक रूप में, संभाले जाने देना। ऐसे में इंटरफेस वही भूमिका निभाते हैं जो बेस क्लास निभाती है
- किसी खास उद्देश्य के लिए फंक्शनैलिटी का एक हिस्सा सामने लाना (जैसे [`IComparable<T>`][icomparable]), या
- किसी क्लास का पब्लिक API सामने लाना ताकि कई कार्यान्वयन साथ-साथ रह सकें। इसका एक उदाहरण [टेस्ट डबल][wiki-test-double] है

```csharp
public class ItalianTraveller : IItalianLanguage
{
    public string Speak()
    {
        return "Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class ItalianTravellerV2 : IItalianLanguage
{
    public string Speak()
    {
        return "migliorata - Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class FrenchTraveller : ILanguage
{
    public string Speak()
    {
        return "Ça va?";
    }
}

public class RussianTraveller : ILanguage, IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Speak()
    {
        return "Привет мир";
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}

public class DocumentTranslator : IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Translate(string russian)
    {
        throw new NotImplementedException();
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}
```

ऊपर दिए गए इंटरफेस और क्लास का इस्तेमाल करने वाला कोड यह कर सकता है:

- भाषा चाहे कोई भी हो, सभी स्पीकर के साथ एक ही तरह का व्यवहार करना।
- स्क्रिप्ट कन्वर्ज़न संभालने वाले किसी सबसिस्टम को यह परवाह किए बिना काम करने देना कि वह किन खास टाइप के साथ काम कर रहा है।
- इटैलियन स्पीकर में हुए बदलावों से अनजान बने रहना, जो तब सुविधाजनक होता है जब क्लास का कोड और उसे इस्तेमाल करने वाला कोड अलग-अलग टीमें संभालती हों

इंटरफेस टेस्टिंग को सहारा देने के लिए बहुत इस्तेमाल किए जाते हैं, क्योंकि ये आसान [मॉकिंग][so-mocking-interfaces] की सुविधा देते हैं।

इंटरफेस में किस तरह के मेंबर शामिल किए जा सकते हैं, इसका ब्यौरा इस [लेख][dt-interfaces] में देखिए।

इंटरफेस दूसरे इंटरफेस से इनहेरिट कर सकते हैं।

इंटरफेस के मेंबर डिफाल्ट रूप से पब्लिक होते हैं।

इंटरफेस के अंदर नेस्टेड टाइप रखे जा सकते हैं, जैसे `const` लिटरल, `enums`, `delegates`, `classes` और `structs`। यहाँ इंटरफेस उसी तरह [नेमस्पेस][wiki-namespaces] का काम करते हैं जैसे क्लास और स्ट्रक्चर करते हैं, और व्यवहार तथा सिंटैक्स बिल्कुल एक जैसा होता है।

C# जान-बूझकर मल्टीपल इनहेरिटेंस का समर्थन नहीं करता, लेकिन इंटरफेस के ज़रिए यह एक तरह के मल्टीपल इनहेरिटेंस की सुविधा देता है।

इसके अलावा, [इंटरफेस के ज़रिए पॉलिमॉर्फिज़्म लागू किया जा सकता है][interface-polymorphism], और यही अवधारणा इंटरफेस की पूरी व्यवस्था की बुनियाद है।

## स्पष्ट इंटरफेस कार्यान्वयन

कभी-कभी मेथड के नाम और सिग्नेचर दो अलग-अलग इंटरफेस में एक जैसे हो सकते हैं। इन मेथड का अलग-अलग कार्यान्वयन देने के लिए C# [इंटरफेस का स्पष्ट कार्यान्वयन][explicit-implementation] देता है। ध्यान रखिए कि किसी इंटरफेस के किसी खास कार्यान्वयन का इस्तेमाल करने के लिए आपको ऑब्जेक्ट को संदर्भित करने वाले एक्सप्रेशन को उस इंटरफेस में बदलना होगा। असाइनमेंट, कास्टिंग या उसे पैरामीटर के रूप में पास करना, इनमें से कोई भी तरीका यह काम कर देगा।

```csharp
public interface IFoo
{
    void X();
}

public interface IBar
{
    void X();
}

public class Census : IFoo, IBar
{
    void IFoo.X()
    {
        Console.Write("This is from Foo");
    }

    void IBar.X()
    {
        Console.Write("This is from Bar");
    }
}

public class User
{
    public void Use()
    {
        IFoo foo = new Census();
        IBar bar = new Census();
        foo.X();
        // => "This is from Foo"
        bar.X();
        // => "This is from Bar"
    }
}
```

इसके इस्तेमाल के कई मामले हैं:

- डोमेन का टकराव (जैसा ऊपर दिखाया गया है), जहाँ मेथड के सिग्नेचर बिल्कुल एक जैसे हों।
- एक ही नाम के मेथड, लेकिन अलग रिटर्न टाइप: अगर आप अपनी खुद की कलेक्शन क्लास बनाते हैं, तो आप पाएँगे कि पुराने `IEnumerable.GetEnumerator()` के लिए, `IEnumerable<T>.GetEnuerator()` के साथ-साथ, एक स्पष्ट इंटरफेस ज़रूरी हो जाता है। हो सकता है आप उस इंटरफेस का कभी इस्तेमाल ही न करें, पर कंपाइलर ज़िद कर सकता है।
- वे मेथड जहाँ इंटरफेस के नामों में कोई टकराव नहीं है, लेकिन यह बेहतर है कि लागू करने वाली क्लास उस नाम का इस्तेमाल किसी जुड़े हुए काम के लिए करे: `IFormattable` में एक `ToString()` मेथड है जो _फॉर्मैट टाइप_ पैरामीटर के साथ-साथ `IFormatProvider` टाइप का पैरामीटर भी लेता है। बेस क्लास लाइब्रेरी (BCL) की `FormattableString` जैसी क्लास में यह इंटरफेस इसलिए होता है ताकि वह उन रूटीन से इस्तेमाल की जा सके जो `IFormattable` लेते हैं, लेकिन इसके मुख्य `ToString(IFormatProvider)` संस्करण के लिए _फॉर्मैट टाइप_ पैरामीटर छोड़ देना ज़्यादा साफ़ है, क्योंकि कार्यान्वयन में इसका इस्तेमाल नहीं होता और यह API के इस्तेमाल करने वालों को उलझा देता है।

## डिफाल्ट कार्यान्वयन

C# का वर्ज़न 8 API से जुड़ी एक पुरानी समस्या का हल देता है। अगर आप नए कार्यान्वयन के लिए फंक्शनैलिटी बढ़ाने के वास्ते किसी इंटरफेस में मेथड जोड़ते हैं, तो उस इंटरफेस के सभी मौजूदा कार्यान्वयन को भी बदलना पड़ता है ताकि वे API-कॉन्ट्रैक्ट का पालन करें, भले ही उनका अपना कोई खास व्यवहार न हो। अब C# इंटरफेस का हिस्सा बनाकर एक _डिफाल्ट मेथड_ देने की सुविधा देता है (Java डेवलपर इसे पहचानेंगे)। पहले ऐसा बदलाव होने पर मूल इंटरफेस के साथ उसका _वर्ज़न 2_ भी रखना पड़ता था।

यह [लेख][dt-interfaces] इंटरफेस पर एक बढ़िया शुरुआती परिचय है और इसमें _डिफाल्ट कार्यान्वयन_ तथा `static`, `private` और `virtual` मेंबर जैसी दूसरी सहायक नई सुविधाओं पर ध्यान दिया गया है।
