# संकेत
`Option` का उपयोग ऐसी गणना दिखाने के लिए किया जाता है जिसका शायद कोई उपयोगी परिणाम न निकले
(जैसे किसी एरर या गलत इनपुट की वजह से)।
अगर आप `Option` से परिचित नहीं हैं, तो आप [यह ट्यूटोरियल](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html) पढ़ सकते हैं।
`Option` एक तरह का [मोनैड](https://en.wikipedia.org/wiki/Monad_(functional_programming)) है, जो गणना के एक पहलू को समेटता है; यहाँ यह पहलू वैल्यू का संभवतः मौजूद न होना है।
मोनैड का सही उपयोग बहुत संक्षिप्त, फिर भी सुंदर
और पढ़ने में आसान कोड दे सकता है। गलत उपयोग से उलटा नतीजा आसानी से मिल सकता है।
और जानने के लिए [यह वीडियो](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) देखिए।
## आम गलतियाँ जिनसे आपको बचना चाहिए
`Option` के लिए कुछ आम नियम हैं:
1. जहाँ इसकी ज़रूरत नहीं है, वहाँ इसका उपयोग न कीजिए। इसके बजाय
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
यह लिखना बेहतर है
```scala
def add1(x: Int): Int = x + 1
```
(`Option.map` ऐसे सरल फंक्शन लगाने के लिए मौजूद है,
इसलिए आपको उन्हें `Option` से उलझाने की ज़रूरत नहीं)।
2. जब सचमुच ज़रूरत न हो, तो "unwrap" न कीजिए।
अक्सर आपके काम के लिए पहले से बने फंक्शन मौजूद होते हैं। समय से पहले
unwrap करने के संकेत हैं `isDefined/isEmpty` या पैटर्न मैचिंग। इसके बजाय
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
यह लिखना बेहतर है
```scala
x map (_ + 1) getOrElse 0
```
3. फोर-कॉम्प्रिहेंशन के अंदर मोनैड इस्तेमाल किए जा सकते हैं, और यह बहुत बढ़िया तरीका है।
यह तब अच्छा रहता है जब आप कई `Option` इंस्टेंस आपस में जोड़ना चाहते हैं। इसके बजाय
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
यह लिखना बेहतर है
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
