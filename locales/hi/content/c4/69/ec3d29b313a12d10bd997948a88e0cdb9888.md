# इसके बारे में

Gleam एरर संभालने के लिए एक्सेप्शन का उपयोग नहीं करता। इसके बजाय, जो फंक्शन सफल भी हो सकते हैं और असफल भी, वे जेनेरिक `Result` टाइप लौटाते हैं।

`Result` टाइप भाषा में पहले से मौजूद है, इसलिए आपको इसे बनाने या इम्पोर्ट करने की ज़रूरत नहीं है। लेकिन अगर आप इसे खुद बनाते, तो वह कुछ इस तरह दिखता:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

जब कोई फंक्शन सफल होता है, तो `Ok` वेरिएंट लौटाया जाता है, और जब कोई फंक्शन असफल होता है, तो `Error` वेरिएंट लौटाया जाता है।

Gleam में रिज़ल्ट बहुत आम हैं, और Gleam प्रोग्रामर इनके साथ काम करना आसान बनाने के लिए अक्सर [`gleam/result` मॉड्यूल](https://hexdocs.pm/gleam_stdlib/gleam/result.html) का उपयोग करते हैं।

अगर रिज़ल्ट `Ok` है, तो `result.map` फंक्शन की मदद से उसके अंदर की वैल्यू पर कोई फंक्शन कॉल किया जा सकता है। और अगर वह `Error` है, तो उसे बिना बदले आगे भेजा जा सकता है।

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

`result.try` फंक्शन भी ऐसा ही है, लेकिन इसमें कॉलबैक फंक्शन से अपेक्षा की जाती है कि वह एक रिज़ल्ट लौटाए। यह तब काम आता है जब कई ऐसे फंक्शन को एक के बाद एक जोड़ना हो जो रिज़ल्ट लौटाते हैं।

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
