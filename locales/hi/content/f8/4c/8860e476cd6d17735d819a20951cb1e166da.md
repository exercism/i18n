# परिचय

## Julia में बूलियन

सही या गलत वैल्यू को `Bool` टाइप से दर्शाया जाता है।
इसमें केवल दो वैल्यू होती हैं: `true` और `false`।

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

कई अन्य भाषाओं के विपरीत, Julia में जानबूझकर "ट्रुथिनेस" की कोई अवधारणा नहीं है, और केवल वे एक्सप्रेशन जिनका मूल्यांकन `true` या `false` होता है, `Bool` के रूप में माने जाएँगे।

खास तौर पर, खाली ऐरे या स्ट्रिंग को `false` के रूप में *नहीं* समझा जाएगा।
अगर आप खाली वैल्यू के लिए खास व्यवहार चाहते हैं, तो `isempty()` जैसी उपयुक्त जाँच होनी चाहिए।

## बूलियन ऑपरेटर

Julia में तीन [बूलियन ऑपरेटर][boolean-operators] हैं।

`&&` बूलियन "और" है।
इसका मूल्यांकन `true` होता है जब `&&` के *दोनों* ओर के एक्सप्रेशन `true` हों।

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||` बूलियन "या" है।
इसका मूल्यांकन `true` होता है जब `||` के *किसी एक* ओर का एक्सप्रेशन `true` हो।

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!` बूलियन "नहीं" है।
यह `true` और `false` वैल्यू को एक-दूसरे में बदल देता है।

```julia-repl
julia> !true
false

julia> !false
true
```

इसी तरह के ऑपरेटर कई अन्य भाषाओं के इस्तेमाल करने वालों के लिए अवधारणा के स्तर पर परिचित होंगे, हालाँकि अलग-अलग भाषाओं में सटीक सिंटैक्स अलग हो सकता है।

## ऑपरेटर प्राथमिकता

अधिक जटिल एक्सप्रेशनों में यह जानना उपयोगी हो सकता है कि `&&` की [प्राथमिकता][operator-precedence] `||` से थोड़ी ज़्यादा है *(जैसे अंकगणितीय एक्सप्रेशनों में `*` को `+` से पहले लागू किया जाता है)*।

इस पर भरोसा करना भ्रम पैदा कर सकता है और गलतियाँ करा सकता है।
स्पष्टता के लिए, अपना इरादा साफ़ रखने के लिए कोष्ठकों का उपयोग कीजिए।

## शॉर्ट-सर्किट मूल्यांकन

क्या एक्सप्रेशन `true || x` `x` की वैल्यू पर निर्भर करता है, या कंपाइलर `x` को नज़रअंदाज़ कर सकता है?

Julia बूलियन एक्सप्रेशनों का मूल्यांकन बाएँ से दाएँ करता है, और जब परिणाम स्पष्ट हो जाता है तो रुक जाता है।

उदाहरण के लिए, `true || x` का परिणाम `x` चाहे कुछ भी हो, `true` ही होगा, इसलिए `x` का मूल्यांकन नहीं किया जाता।
इसी तरह, `false && y` `false` होता है, और `y` का मूल्यांकन करने की ज़रूरत नहीं होती।

इसके विपरीत, `true && x` `true` तभी होता है जब `x` `true` हो, इसलिए `x` का मूल्यांकन करना ज़रूरी है।

इसी तरह, अगर हम कई ऑपरेटरों की श्रृंखला बनाते हैं:

```julia-repl
julia> true && false && something_else
false
```

चूँकि `true && false` `false` ही होगा, `something_else` महत्वपूर्ण नहीं है और कंपाइलर उसे नज़रअंदाज़ कर देता है।

इस मामले में, `something_else` एक वेरिएबल के रूप में मौजूद नहीं था, लेकिन इस संदर्भ में इसे शामिल करने पर कोई एरर नहीं आई *(अगर संदेह हो तो इसे REPL में जाँचिए)*।

ऐसे शॉर्ट-सर्किट मूल्यांकन का इस्तेमाल Julia प्रोग्रामर अक्सर रनटाइम समस्याओं और एज केस को पकड़ने के लिए शॉर्टकट के रूप में करते हैं:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

उदाहरण के लिए, `do_something` फंक्शन से जल्दी `return` हो सकता है अगर `all_ok` `false` हो, या आगे बढ़ने से पहले किसी वेरिएबल को डिफॉल्ट वैल्यू असाइन करना हो सकता है।

यह बूलियन सिंटैक्स का थोड़ा दुरुपयोग है, लेकिन यह बहुत सुविधाजनक हो सकता है।

## Bool अंदर से कैसे काम करता है

अगर किसी *अंकगणितीय* एक्सप्रेशन में Bool शामिल हो, तो `true` को `1` और `false` को `0` के रूप में समझा जाता है, जो दर्शाता है कि इन्हें कैसे संग्रहीत किया जाता है।

अगर आप निम्न-स्तरीय भाषाओं (C और उस जैसी) के आदी हैं, तो *कृपया* इसका बार-बार इस्तेमाल करने से बचें।
इससे कोड की पठनीयता घटेगी और डीबगिंग मुश्किल हो जाएगी।

आपको कभी-कभी संख्यात्मक वैल्यू यह गिनने के शॉर्टकट के रूप में इस्तेमाल होती दिख सकती हैं कि कितनी चीज़ें `true` हैं।

```julia-repl
julia> true + false + true
2
```
