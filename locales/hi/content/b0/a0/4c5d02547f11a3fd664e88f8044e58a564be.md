# परिचय

## JSON

[JSON][json] (JavaScript Object Notation) एक ऐसा डेटा और फाइल फॉर्मेट है जिसे इंसान पढ़ सकते हैं और जिसका उपयोग आमतौर पर डेटा का आदान-प्रदान करने में होता है, खासकर वेब एप्लिकेशन के लिए। इसलिए यह कोई आश्चर्य की बात नहीं है कि Elm भाषा में इसकी एक खास जगह है।

JSON डेटा को पार्स करने और लिखने के लिए Elm दो कोर मॉड्यूल देता है: [`Json.Decode`][decode] और [`Json.Encode`][encode]। JSON डिकोडर यह _घोषित_ करने का तरीका है कि किस तरह का डेटा अपेक्षित है और डेटा को किस डेटा स्ट्रक्चर में ढलना चाहिए।

डायनामिक टाइप वाली भाषाओं से आने वालों को डिकोडर अक्सर बोझिल लगते हैं, या पहली नज़र में बहुत कठोर। हालाँकि Elm में ये निश्चित रूप से शब्दबहुल हैं, फिर भी ये एक बहुत काम का टूल हैं, जो साफ़-साफ़ बताते हैं कि प्रोग्राम आने वाले डेटा से क्या उम्मीद करता है, और [डायनामिक टाइप से कम अभिव्यक्तिपूर्ण नहीं हैं][dynamic-types-not-more-open]।

चलिए इन मॉड्यूल से कुछ अलियास और टाइप इम्पोर्ट करते हैं:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

`Decode.decodeString : Decoder a -> String -> Result Error a` को किसी डिकोडर और एक JSON स्ट्रिंग के साथ इस्तेमाल करने पर, अगर स्ट्रिंग डिकोडर की शर्तों के मुताबिक है तो नतीजा सफल होता है, वरना विफल। डिकोडर बनाते समय कच्चे JSON डेटा को देखने का कोई तरीका नहीं होता, जो इम्पेरेटिव भाषाओं से आने वालों को असामान्य लग सकता है।

## बुनियादी डेटा टाइप के डिकोडर

JSON में कुछ ही मूल डेटा टाइप होते हैं:

- स्ट्रिंग: डबल कोट के अंदर लिखी जाती है, जैसे `"hello world"`
- बूलियन: या तो `true` या `false`
- संख्या: जैसे `34` या `0.12`
- Null: डेटा का अभाव, `null`

इनमें से हर एक के लिए `Decode` में एक फंक्शन है:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

ध्यान दीजिए कि `Decode.null` आपको यह तय करने देता है कि अपने प्रोग्राम में `null` को कैसे दर्शाना है; इसके लिए यह आर्गुमेंट के रूप में कोई भी वैल्यू माँगता है (जैसे `()`, `Nothing`, या आपके प्रोग्राम के लिए जो भी उपयुक्त हो)।

## डिकोडर को जोड़ना

मूल डेटा टाइप को समेटने के लिए JSON में दो डेटा स्ट्रक्चर भी परिभाषित हैं:

- ऐरे: और डेटा टाइप का संग्रह, `[0, null, "none", []]`
- ऑब्जेक्ट: की-वैल्यू जोड़ों का संग्रह, `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` में इन्हें डिकोड करने के लिए भी फंक्शन हैं:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

ये दोनों फंक्शन, `Decode.list : Decoder a -> Decoder (List a)` और `Decode.dict : Decoder a -> Decoder (Dict String a)`, आर्गुमेंट के रूप में एक डिकोडर लेते हैं, और वह डिकोडर डेटा स्ट्रक्चर के हर एक एलिमेंट को डिकोड करता है। अगर आर्गुमेंट वाला डिकोडर ऐरे या ऑब्जेक्ट की वैल्यू के किसी भी एलिमेंट को डिकोड नहीं कर पाता, तो पूरा डिकोडर विफल हो जाता है, और यह एक आम पैटर्न है।

इस तकनीक का मूल विचार यही है कि साधारण डिकोडरों को जोड़कर ज़्यादा जटिल डिकोडर बनाए जाएँ। हम एक उदाहरण के ज़रिए कुछ और फंक्शन देखेंगे, जिनसे असल दुनिया के मनमाने जटिल डेटा के डिकोडर बनाए जा सकते हैं।

## GeoJSON

बुनियादी डिकोडरों को जोड़कर जटिल JSON डेटा पार्स करने का अभ्यास करने के लिए, चलिए (GeoJSON के एक हिस्से को) पार्स करने वाले डिकोडर बनाएँ।
[GeoJSON][geojson] एक खास तरह का JSON आधारित डेटा फॉर्मेट है, जिसका उपयोग भौगोलिक चीज़ों को दर्शाने के लिए होता है, जैसे कि स्थान, रास्ते या क्षेत्र। ऐसी चीज़ें 2D या 3D भौगोलिक निर्देशांकों के साथ, और कुछ और प्रॉपर्टी के साथ, बताई जाती हैं।

### ज्यामिति ऑब्जेक्ट

GeoJSON का ज्यामिति ऑब्जेक्ट एक ऑब्जेक्ट होता है जिसमें एक `type` फील्ड होता है जिसकी वैल्यू एक स्ट्रिंग होती है (टाइप की 7 संभावित वैल्यू हो सकती हैं) और एक `coordinates` फील्ड होता है जिसमें भौगोलिक निर्देशांक होते हैं (जो एक ऐसी संरचना में एकत्र किए जाते हैं जो `type` पर निर्भर करती है)।
जैसे,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

या

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Elm में एक ज्यामिति ऑब्जेक्ट को इस टाइप से दर्शाया जा सकता है

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

किसी फील्ड की वैल्यू जाँचने के लिए हम `Decode.field : String -> Decoder a -> Decoder a` का उपयोग कर सकते हैं, जो ऑब्जेक्ट में किसी एक नाम की वैल्यू को डिकोड करता है।

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

किसी डिकोडर से सफलतापूर्वक पार्स हुई वैल्यू को बदलने के लिए हम `Decode.map : (a -> value) -> Decoder a -> Decoder value` इस्तेमाल कर सकते हैं, या इसके किसी भी साथी फंक्शन का, `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` से लेकर `Decode.map8` तक।

यहाँ हमें `type` फील्ड की वैल्यू के हिसाब से यह तय करना है कि कौन सा निर्देशांक डिकोडर इस्तेमाल करना है। यह काम `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` और उसके साथी फंक्शन `Decode.succeed : a -> Decoder a` तथा `Decode.fail : String -> Decoder a` के लिए एकदम सही है।

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

यहाँ ध्यान दीजिए कि हम निर्देशांकों को जाँचने के लिए भी `Decode.andThen` इस्तेमाल कर सकते हैं (यह देखना कि निर्देशांक जोड़ों या तिकड़ियों में आते हैं, और यह देखना कि निर्देशांकों की वैल्यू भौगोलिक रूप से समझ में आती हैं)।

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### फीचर ऑब्जेक्ट

GeoJSON का फीचर ऑब्जेक्ट किसी ऐसी चीज़ को दर्शाता है जिसका एक तय भौगोलिक दायरा होता है: इसमें एक `type` फील्ड होता है जिसकी वैल्यू `"Feature"` होती है, एक `geometry` फील्ड होता है जिसमें ज्यामिति ऑब्जेक्ट या `null` होता है, एक `properties` फील्ड होता है जिसमें कोई भी JSON ऑब्जेक्ट या `null` होता है, और एक वैकल्पिक `id` फील्ड होता है जिसमें JSON स्ट्रिंग या संख्या वाली वैल्यू होती है।

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

या

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

चलिए पहले `id` फील्ड को देखते हैं।
अगर यह मौजूद होता है, तो इसमें स्ट्रिंग या संख्या दोनों आ सकते हैं। इसलिए हम या तो इस वैल्यू के लिए एक कस्टम टाइप बना सकते हैं, या इसे हमेशा स्ट्रिंग के रूप में सेव कर सकते हैं।

दो संभावित डिकोडरों में से चुनने के लिए हम `Decode.oneOf : List (Decoder a) -> Decoder a` इस्तेमाल कर सकते हैं।

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

यह बताने के लिए कि फील्ड वैकल्पिक है, हम वही तकनीक इस्तेमाल कर सकते हैं

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

लेकिन इसके बजाय हम `Decode.maybe : Decoder a -> Decoder (Maybe a)` इस्तेमाल कर सकते हैं

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

ध्यान दीजिए कि `decodeMaybeFeatureId` (या `Decode.maybe` में लिपटा कोई भी डिकोडर) हमेशा सफल होगा, क्योंकि यह हमेशा `Ok Nothing` पर लौट सकता है, हालाँकि इसका इस्तेमाल करने वाला डिकोडर अब भी विफल हो सकता है

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

अब चलिए `geometry` फील्ड पर ध्यान देते हैं, जिसमें या तो ज्यामिति ऑब्जेक्ट हो सकता है या `null`।
हम फिर से `Decode.oneOf` इस्तेमाल कर सकते हैं, लेकिन इससे बेहतर विकल्प भी है: `Decode.nullable : Decoder a -> Decoder (Maybe a)`।

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` और `Decode.nullable` का सिग्नेचर एक जैसा है, लेकिन इनका व्यवहार अलग है, क्योंकि `Decode.nullable` का `OK Nothing` नतीजा सिर्फ़ JSON की उस खास वैल्यू `null` से ही आता है।

अंत में, `properties` फील्ड में कोई भी JSON ऑब्जेक्ट या `null` हो सकता है। यह काम `Decode.value : Decoder Value` का है।

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

ध्यान दीजिए कि `Value` एक अपारदर्शी टाइप है, यानी आप उसकी सामग्री को आसानी से नहीं जाँच सकते।
इसका इस्तेमाल करने के लिए आप या तो इसके लिए एक डिकोडर लिखकर उसे `Decode.decodeValue : Decoder a -> Value -> Result Error a` से चला सकते हैं, या इसे किसी पोर्ट के ज़रिए सीधे JavaScript को भेज सकते हैं।

अब हम फीचर ऑब्जेक्ट पार्स करने के लिए तैयार हैं:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## JSON एनकोडर

एनकोडर की मदद से Elm की वैल्यू से मान्य JSON लिखा जा सकता है, और इसके लिए `Encode.encode : Int -> Value -> String` फंक्शन इस्तेमाल होता है।
पहला आर्गुमेंट बताता है कि अंतिम नतीजे में कितनी इंडेंटेशन होगी, और दूसरा आर्गुमेंट वह JSON वैल्यू है जिसे लिखना है।

कोई `Value` या तो `Decode.value` से मिल सकती है, या किसी एनकोडर से बनाई जा सकती है:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

साथ ही `Encode.object : List ( String, Value ) -> Value` से भी:

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

चलिए अब उन GeoJSON डिकोडरों के लिए एनकोडर बनाएँ जो हमने पहले बनाए थे

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

सामान्य तौर पर, अपने डिकोडर-एनकोडर जोड़ों की अच्छी जाँच यह है कि आप देखें कि `elmValue |> encoder |> decoder == elmValue`।

## और क्या?

हमने `Json` मॉड्यूल के हर एक फंक्शन को नहीं समझा।
जो चीज़ें यहाँ नहीं बताई गईं, उनमें शामिल हैं: ऐरे को `Array` में या ऑब्जेक्ट को `List (String, a)` में बदलने वाले डिकोडर, एक या ज़्यादा एलिमेंट वाले ऐरे के डिकोडर, नेस्टेड JSON ऑब्जेक्ट के किसी खास फील्ड या ऐरे के किसी खास एलिमेंट के डिकोडर, रिकर्सिव संरचनाओं को डिकोड करने का तरीका, और `Error` के अलग-अलग रूप तथा उन्हें प्रदर्शित करने का तरीका।

अक्सर इस्तेमाल होने वाले कुछ और पैकेज भी हैं: [`Json.Decode.Pipeline`][pipeline], जो जटिल JSON संरचना के लिए एक सुविधाजनक तरीका देता है, और [`Json.Decode.Extra`][extra], जो और डिकोडर, एनकोडर और हेल्पर देता है।
