# परिचय

**फ्लोटिंग-पॉइंट** एक ऐसी संख्या है जिसमें भिन्नात्मक भाग हो सकता है, जैसे `-1.23` या `3.1415`।

ऐसी संख्या को बाइटों के क्रम के रूप में निरूपित करने के लिए x86-64 **IEEE-754** मानक का उपयोग करता है।
इस मानक में दो सबसे आम फॉर्मैट हैं: सिंगल-प्रिसिजन फ्लोटिंग-पॉइंट और डबल-प्रिसिजन फ्लोटिंग-पॉइंट संख्याएँ।
x86-64 दोनों का समर्थन करता है।

एक सिंगल-प्रिसिजन फ्लोटिंग-पॉइंट संख्या 32 बिट चौड़ी होती है, जबकि डबल-प्रिसिजन 64 बिट चौड़ी होती है।

## XMM रजिस्टर

x86-64 में फ्लोटिंग-पॉइंट गणित करने के लिए 16 समर्पित रजिस्टर हैं, जिनके नाम `xmm0` से `xmm15` तक हैं।

ये रजिस्टर कम से कम 128 बिट चौड़े होते हैं, लेकिन नए प्रोसेसर इसे बढ़ाकर 256 बिट या 512 बिट कर देते हैं।
हालाँकि व्यवहार में ज़्यादातर फ्लोटिंग-पॉइंट संख्याएँ ज़रूरत की प्रिसिजन के हिसाब से सिर्फ सबसे नीचे वाले 32 बिट या 64 बिट इस्तेमाल करती हैं।

## संख्याओं के बीच रूपांतरण

संख्या फॉर्मैट के बीच रूपांतरण करने के लिए निर्देशों का एक समूह है: `cvtxx2yy`।

`xx` और `yy` दोनों अक्षरशः मान नहीं, बल्कि प्लेसहोल्डर हैं:

- `xx` स्रोत ऑपरेंड के टाइप के लिए प्लेसहोल्डर है।
- `yy` गंतव्य ऑपरेंड के टाइप के लिए प्लेसहोल्डर है।

ये प्लेसहोल्डर कई रूप ले सकता है, जिनमें शामिल हैं:

| प्लेसहोल्डर | अर्थ                  |
| ----------- | --------------------- |
| `si`        | साइन्ड पूर्णांक       |
| `ss`        | 32-बिट फ्लोटिंग-पॉइंट |
| `sd`        | 64-बिट फ्लोटिंग-पॉइंट |

उदाहरण के लिए:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

ध्यान दीजिए कि 32-बिट पूर्णांक को 64-बिट फ्लोटिंग-पॉइंट में, या 64-बिट पूर्णांक को 32-बिट फ्लोटिंग-पॉइंट में बदलना संभव है।
इसी तरह 32-बिट फ्लोटिंग-पॉइंट को 64-बिट पूर्णांक में, या 64-बिट फ्लोटिंग-पॉइंट को 32-बिट पूर्णांक में भी बदला जा सकता है।
दूसरे शब्दों में, `cvtxx2yy` में दोनों ऑपरेंड का आकार _एक जैसा होना ज़रूरी नहीं है_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

जब किसी फ्लोटिंग-पॉइंट संख्या को पूर्णांक के रूप में ठीक-ठीक व्यक्त नहीं किया जा सकता, तब `cvtxx2si` उस संख्या को `mxcsr` नाम के एक विशेष रजिस्टर में मौजूद राउंडिंग कंट्रोल के हिसाब से राउंड करता है।
यह निकटतम तक राउंड करना, नीचे की ओर राउंड करना, ऊपर की ओर राउंड करना या ट्रंकेट करना हो सकता है।
फंक्शन में प्रवेश के समय कोई डिफॉल्ट तय नहीं होता।

ध्यान दीजिए कि जो परिणाम ठीक-ठीक आता है, वह राउंड नहीं किया जाता और इसलिए राउंडिंग कंट्रोल का असर उस पर नहीं पड़ता।
उदाहरण के लिए, `42.0` _हमेशा_ `42` में बदला जाएगा।

ऐसा ही एक और निर्देश समूह है, जिसका फॉर्मैट `cvttxx2si` है (एक अतिरिक्त `t` के साथ) और जो परिणाम को हमेशा ट्रंकेट कर देता है।

## राउंड

`roundxx` निर्देश समूह स्रोत ऑपरेंड में मौजूद फ्लोटिंग-पॉइंट को राउंड करके गंतव्य ऑपरेंड में संग्रहीत कर देता है।

यहाँ `xx` हमेशा की तरह ऑपरेंड के टाइप के लिए प्लेसहोल्डर है: सिंगल-प्रिसिजन के लिए `ss` और डबल-प्रिसिजन फ्लोट के लिए `sd`।

ये निर्देश तीसरे ऑपरेंड के रूप में एक स्थिर संख्या लेते हैं।
यह संख्या राउंडिंग मोड बताती है:

| संख्या | मोड          |
| :----- | :----------- |
| 0      | निकटतम       |
| 1      | फ्लोर (नीचे) |
| 2      | सील (ऊपर)    |
| 3      | ट्रंकेट      |

उदाहरण के लिए:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

चूँकि ये निर्देश ठीक-ठीक परिणाम देते हैं, इन्हें `cvtxx2si` की तैयारी में इस्तेमाल किया जा सकता है।

## अंकगणितीय निर्देश

फ्लोटिंग-पॉइंट संख्याओं वाली कई क्रियाओं के निर्देशों के नाम पूर्णांकों वाले उनके समान निर्देशों जैसे ही होते हैं, बस अंत में ज़रूरी प्लेसहोल्डर (`ss` या `sd`) जोड़ दिया जाता है।
ये निर्देश दो-ऑपरेंड वाले होते हैं और उनका अर्थ हमेशा जैसा ही रहता है, यहाँ तक कि गुणा या भाग करने वाले निर्देशों का भी:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## मूव

एक XMM रजिस्टर से दूसरे में मान ले जाने वाले निर्देश `movss` या `movsd` हैं:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

किसी इमीडिएट (एक स्थिर साइन्ड पूर्णांक) को सीधे किसी xmm रजिस्टर में ले जाना **संभव नहीं** है।
इस संख्या को पहले किसी जनरल-पर्पस रजिस्टर में ले जाना पड़ता है और फिर `cvtsi2xx` की मदद से बदलना पड़ता है:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## तुलना

दो फ्लोटिंग-पॉइंट संख्याओं की तुलना करने के लिए निर्देशों के दो समूह हैं।
इनका रूप `comixx` और `ucomixx` होता है, जहाँ `xx` या तो `ss` होता है या `sd`।
दोनों हमेशा की तरह `rflags` में फ्लैग सेट करते हैं और `cmp` जैसा ही अर्थ रखते हैं।

इनमें फर्क यह है कि अगर दोनों में से किसी एक फ्लोटिंग-पॉइंट संख्या की वैल्यू `NaN` हो, तो `ucomixx` `parity flag (PF)` सेट करता है, जबकि ऐसी स्थिति में `comixx` एक एक्सेप्शन उठाता है।

फ्लोटिंग-पॉइंट वैल्यू के बीच तुलना _अनसाइन्ड_ होती है:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## कॉलिंग कन्वेंशन

System V ABI में पहले आठ फ्लोटिंग-पॉइंट आर्गुमेंट फंक्शन को क्रम से, `xmm0` से `xmm7` तक, पास किए जाते हैं।
फंक्शन से फ्लोटिंग-पॉइंट वैल्यू `xmm0` में लौटाई जाती है और ज़रूरत पड़ने पर `xmm1` में भी।

सभी `xmm` रजिस्टर खुलकर इस्तेमाल किए जा सकते हैं, इनमें से कोई भी कॉलर के लिए आरक्षित नहीं है।

## मेमोरी

फ्लोटिंग-पॉइंट वैल्यू मेमोरी में उसी आकार के पूर्णांकों जैसे अर्थ के साथ परिभाषित की जा सकती हैं।
NASM (The Netwide Assembler, यानी इस ट्रैक में इस्तेमाल होने वाला असेंबलर) फ्लोटिंग-पॉइंट वैल्यू को वैज्ञानिक संकेतन में घोषित करने की सुविधा भी देता है।

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```
