# परिचय

## शब्दावली

आप कुछ कॉन्सेप्ट में C++ के फंक्शन इस्तेमाल कर चुके हैं और लिख भी चुके हैं। अब थोड़ा तकनीकी होने का समय है। नीचे दिए कोड स्निपेट में सबसे आम शब्द दिए गए हैं, ताकि आप उन्हें आसानी से देख सकें। C++ व्हाइटस्पेस को नज़रअंदाज़ करता है, इसलिए फॉर्मैटिंग बदलकर हर एलिमेंट को एक ही लाइन पर रखा गया है।

```cpp
// Function declaration:
bool                                              // Return type
admin_detected(string user, string password)      // Type signature
;                                                 // Don't forget the ';' for the declaration

// Function definition:
bool                                              // Return type
admin_detected                                    // Function name
(string user, string password)                    // Parameter list
{ return user == "admin" && password == "1234"; } // Function body
```
~~~~exercism/advanced
घोषणा कंपाइलर के लिए एक नोट की तरह काम करती है, जो बताती है कि इस नाम, रिटर्न टाइप और पैरामीटर सूची वाला एक फंक्शन मौजूद है। अगर परिभाषा न हो, तो कोड काम नहीं करेगा। घोषणाएँ ज़रूरी नहीं हैं, लेकिन अगर आप फंक्शन को उसकी परिभाषा से पहले इस्तेमाल करते हैं, तो इनकी ज़रूरत पड़ती है। घोषणाएँ साइक्लिक रेफरेंस जैसी समस्याएँ हल कर सकती हैं, और इन्हें इंटरफेस को इम्प्लीमेंटेशन से अलग रखने के लिए भी इस्तेमाल किया जा सकता है।
~~~~

## const क्वालिफायर

कभी-कभी आप यह सुनिश्चित करना चाहते हैं कि वैल्यू इनिशियलाइज़ होने के बाद बदली न जा सके। C++ कॉन्स्टेंट के लिए क्वालिफायर की तरह `const` कीवर्ड इस्तेमाल करता है।

```cpp
const int number_of_dragon_balls{7};
number_of_dragon_balls--; // compilation error
```

~~~~exercism/note
आप कॉन्स्टेंट को अक्सर _UPPER_SNAKE_CASE_ में लिखा हुआ देखेंगे। अगर कोई और परंपरा न हो, तो इस केसिंग को सिर्फ मैक्रो के लिए रखने की सलाह दी जाती है।
~~~~

अगर आप किसी कॉन्स्टेंट वेरिएबल को सेट होने के बाद बदलने की कोशिश करते हैं, तो आपका कोड कंपाइल नहीं होगा। इससे अनचाहे बदलावों से बचने में मदद मिलती है, और कंपाइलर के लिए ऑप्टिमाइज़ेशन के मौके भी खुलते हैं। इंसान के तौर पर कोड के बारे में सोचना भी आसान हो जाता है, जब आपको पता हो कि कुछ हिस्से बदले नहीं जाएँगे।

आप `const` को फंक्शन के पैरामीटर के लिए क्वालिफायर की तरह भी इस्तेमाल कर सकते हैं।

```cpp
string guess_number(const int& secret, const int& guess) {
    if (secret < guess) return "lower.";
    if (secret > guess) return "higher.";
    return "exact!";
}
```

जब आप फंक्शन को कोई `const` रेफरेंस पास करते हैं, तो आप निश्चिंत रह सकते हैं कि वह बदला नहीं जाएगा। लंबी स्ट्रिंग जैसे ऐसे ऑब्जेक्ट के लिए अक्सर `const` रेफरेंस देखने को मिलते हैं, जिनकी कॉपी बनाना महँगा पड़ सकता है। `const` क्वालिफायर का तीसरा उपयोग ऐसे मेंबर फंक्शन हैं, जो क्लास के इंस्टेंस को नहीं बदलते।

```cpp
class Stubborn {
    public:
    Stubborn(string reply) {
        response = reply;
    }
    string answer(const string& question) const {
        if (question.length() == 0) { return ""; }
        return response;
    }
    private:
    string response{};
};
```

`Stubborn` का मेंबर फंक्शन `answer` पैरामीटर की तरह एक `const string&` रेफरेंस लेता है। इससे उस मूल ऑब्जेक्ट की कॉपी बनाने से बचा जाता है, जो फंक्शन को पास किया गया था।

## फंक्शन ओवरलोडिंग

अगर पैरामीटर सूची अलग हो, तो कई फंक्शन का नाम एक ही हो सकता है। इसे फंक्शन ओवरलोडिंग कहते हैं, और यह आमतौर पर तब किया जाता है जब ये फंक्शन लगभग एक जैसे काम करते हों।

रिटर्न टाइप के बिना फंक्शन का हेडर ही फंक्शन का __टाइप सिग्नेचर__ होता है। टाइप सिग्नेचर में बदलाव होने पर एक नया फंक्शन बनता है।

`play_sound` उदाहरण में अलग-अलग स्थितियों के लिए छह अलग ओवरलोड हैं:

```cpp
// different argument types:
void play_sound(char note);         // C, D, E, ..., B
void play_sound(string solfege);    // do, re, mi, ..., ti
void play_sound(int jianpu);        // 1, 2, 3, ..., 7

// different number of arguments:
void play_sound(string solfege, double duration);

// different qualifiers:
void play_sound(vector<string>& solfege);
void play_sound(const vector<string>& solfege);
```

~~~~exercism/advanced
टाइप सिग्नेचर फंक्शन के नाम, पैरामीटर की संख्या, उनके टाइप और उनके क्वालिफायर से तय होता है (लेकिन उनके नाम से नहीं)। रिटर्न टाइप जान-बूझकर टाइप सिग्नेचर का हिस्सा नहीं है, और अगर आपके दो फंक्शन सिर्फ रिटर्न टाइप में अलग हों, तो आपको कंपाइल एरर मिलेंगी। कंपाइलर शिकायत करेगा, क्योंकि यह साफ़ नहीं होगा कि इन दोनों में से किसे इस्तेमाल करना चाहिए।
~~~~

## डिफॉल्ट आर्गुमेंट

कुछ फंक्शन काफी लंबे हो सकते हैं, और उन्हें कॉल करते समय ज़्यादातर पैरामीटर के लिए अक्सर एक ही वैल्यू देनी पड़ती है। ऐसी कॉल में दोहराव से बचने के लिए डिफॉल्ट आर्गुमेंट काम आते हैं।

```cpp
void record_new_horse_birth(string name, int weight, string color="brown-ish", string dam="Alruccaba", string sire="Poseidon");

record_new_horse_birth("Urban Sea", 130); // color will be brown, dam "Alruccabam", sire "Poseidon"
record_new_horse_birth("Highclere", 175, "off-white", "Fall Aspen");   // sire will be "Poseidon"
```

फंक्शन की घोषणा अक्सर परिभाषा से पहले पढ़ी जाती है, इसलिए डिफॉल्ट आर्गुमेंट घोषणा में सेट करना बेहतर होता है। अगर किसी एक पैरामीटर के लिए डिफॉल्ट दिया गया है, तो उसके दाईं ओर के सभी पैरामीटर के लिए भी डिफॉल्ट देना ज़रूरी है। कभी-कभी उलझे हुए फंक्शन ओवरलोड को डिफॉल्ट आर्गुमेंट वाले कम फंक्शनों में बदला जा सकता है, जिससे रखरखाव आसान हो जाता है।
