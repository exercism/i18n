# परिचय


अब समय आ गया है कि हम C++ के मुख्य पैराडाइमों में से एक की ओर बढ़ें: ऑब्जेक्ट-ओरिएंटेड प्रोग्रामिंग (OOP)।
OOP का केंद्र `classes` हैं, यानी उपयोगकर्ता द्वारा बनाए गए डेटा टाइप, जिनके अपने जुड़े हुए फंक्शनों का समूह होता है।
हम बुनियादी बातों से शुरू करेंगे और सिलेबस में नीचे जाते-जाते और भी उन्नत विषयों पर पहुँचेंगे।

## सदस्य

किसी क्लास में **सदस्य वेरिएबल** और **सदस्य फंक्शन** हो सकते हैं।
इन्हें **सदस्य चयन** ऑपरेटर `.` की मदद से इस्तेमाल किया जाता है।
`classes` के बाहर के वेरिएबलों की तरह ही, घोषणा के समय ही सदस्य वेरिएबल को कोई वैल्यू दे देना बेहतर होता है।
तब यह वैल्यू इस क्लास से बनने वाले नए ऑब्जेक्टों के लिए डिफ़ॉल्ट बन जाती है।

## एनकैप्सुलेशन और जानकारी छिपाना

क्लास यह विकल्प देती है कि उसके सदस्यों तक पहुँच को सीमित किया जा सके।
दो बुनियादी स्थितियाँ हैं: `private` और `public`।
`private` सदस्यों को क्लास के बाहर से इस्तेमाल नहीं किया जा सकता।
`public` सदस्यों को खुलकर कॉल किया जा सकता है।
डिफ़ॉल्ट रूप से सभी सदस्य `private` होते हैं, और क्लास के बाहर इस्तेमाल करने के लिए उन्हें साफ़-साफ़ चिह्नित करना पड़ता है।

## एक बुनियादी उदाहरण

एक नई `class` की परिभाषा नीचे के उदाहरण में देख सकते हैं।
परिभाषा के बाद लगे `;` पर ध्यान दीजिए।

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

क्लास के अंदर से आप सभी वेरिएबल इस्तेमाल कर सकते हैं।
`cast_spell` फंक्शन के अंदर मौजूद `damage` को देखिए।
क्लास के बाहर से आप `private` सदस्यों को न पढ़ सकते हैं और न बदल सकते हैं:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## कंस्ट्रक्टर

कंस्ट्रक्टर ऑब्जेक्ट बनाते समय सदस्य वेरिएबलों को वैल्यू असाइन करने का मौका देते हैं।
इनका नाम `class` के नाम जैसा ही होता है और इनका कोई रिटर्न टाइप नहीं होता।
एक क्लास में कई कंस्ट्रक्टर हो सकते हैं।
यह तब काम आता है जब आपको हमेशा सभी वेरिएबल सेट करने की ज़रूरत न हो।

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

कंस्ट्रक्टर एक बड़ा विषय है और इसमें कई बारीकियाँ हैं।
अगर आप अपनी `class` के लिए साफ़-साफ़ कोई `constructor` नहीं बनाते, तो सिर्फ़ तभी कंपाइलर यह काम आपके लिए कर देता है।
ऊपर के पहले उदाहरण में ऐसा ही हुआ है।
_silverhand_ ऑब्जेक्ट डिफ़ॉल्ट कंस्ट्रक्टर को कॉल करके बनाया गया है, कोई आर्गुमेंट पास नहीं किया गया।
सभी वेरिएबल उस वैल्यू पर सेट कर दिए जाते हैं जो क्लास की परिभाषा में लिखी गई थी।
अगर उस परिभाषा में आपने कोई वैल्यू नहीं दी होती, तो वे वेरिएबल बिना इनिशियलाइज़ हुए रह सकते थे, जिसके अनचाहे परिणाम हो सकते हैं।

## स्ट्रक्ट

स्ट्रक्ट भाषा की मूल C जड़ों से आए हैं और C++ जितने ही पुराने हैं।
ये असल में `classes` जैसी ही चीज़ हैं, बस एक अहम अपवाद के साथ।
डिफ़ॉल्ट रूप से `class` में सब कुछ `private` होता है।
वहीं स्ट्रक्ट तब तक `public` रहते हैं जब तक कुछ और न कहा जाए।
आम तौर पर `struct` कीवर्ड **सिर्फ़ डेटा रखने वाले स्ट्रक्चर** के लिए इस्तेमाल किया जाता है।
जिन ऑब्जेक्टों को कुछ गुण बनाए रखने होते हैं, उनके लिए `class` कीवर्ड को प्राथमिकता दी जाती है।
ऐसा इनवेरिएंट यह हो सकता है कि आपकी `Wizzard` `class` का `damage` कभी ऋणात्मक न हो।
`damage` वेरिएबल private है और damage बदलने वाला कोई भी फंक्शन यह सुनिश्चित करेगा कि इनवेरिएंट बना रहे।
