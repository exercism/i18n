# अधिक जानकारी

Go की स्लाइस दूसरी भाषाओं के ऐरे जैसी होती हैं।
इनमें किसी एक खास टाइप (या इंटरफेस) के कई एलिमेंट रहते हैं।

Go की स्लाइस ऐरे पर आधारित होती हैं।
ऐरे का आकार निश्चित होता है।
वहीं स्लाइस ऐरे के एलिमेंट्स को देखने का एक लचीला तरीका है, जिसका आकार डायनामिक होता है।

स्लाइस को `[]T` की तरह लिखा जाता है, जहाँ `T` स्लाइस के एलिमेंट्स का टाइप होता है:

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

आप चौकोर ब्रैकेट का इस्तेमाल करके शून्य से शुरू होने वाले किसी इंडेक्स पर मौजूद एलिमेंट पढ़ सकते हैं या उसे बदल सकते हैं:

```go
withData[1] = 5
x := withData[1] // x is now 5
```

आप एलिमेंट्स की एक रेंज लेकर किसी मौजूदा स्लाइस से नई स्लाइस बना सकते हैं।
यहाँ भी चौकोर ब्रैकेट का ही इस्तेमाल होता है, लेकिन इसमें शुरुआती (शामिल) और अंतिम (शामिल नहीं) दोनों इंडेक्स बताए जाते हैं।
अगर शुरुआती इंडेक्स नहीं बताया जाए, तो वह अपने आप 0 मान लिया जाता है।
अगर अंतिम इंडेक्स नहीं बताया जाए, तो वह अपने आप स्लाइस की लंबाई मान लिया जाता है।

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

आप `append` फंक्शन की मदद से स्लाइस में एलिमेंट जोड़ सकते हैं।
नीचे हम `a` स्लाइस में `4` और `2` जोड़ते हैं।

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append` हमेशा एक नई स्लाइस लौटाता है। जब हमें किसी मौजूदा स्लाइस में सिर्फ एलिमेंट जोड़ने हों, तो आम तौर पर हम जो स्लाइस पहले आर्गुमेंट के तौर पर देते हैं, उसी वेरिएबल में नतीजा दोबारा असाइन कर देते हैं, जैसा ऊपर किया गया है।

`append` की मदद से दो स्लाइस को आपस में जोड़ा भी जा सकता है:

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## स्लाइस में इंडेक्स

स्लाइस के इंडेक्स के साथ काम करते समय हमेशा किसी न किसी तरह की जाँच ज़रूरी है, जो यह पक्का करे कि इंडेक्स वाकई मौजूद है।
ऐसा न करने पर पूरा एप्लिकेशन क्रैश हो जाएगा।

## खाली स्लाइस

`nil` स्लाइस ही डिफॉल्ट खाली स्लाइस होती है।
इनमें उस स्लाइस के मुकाबले कोई नुकसान नहीं है जिसमें कोई वैल्यू न हो।
`len` फंक्शन `nil` स्लाइस पर भी काम करता है, उसे इनिशियलाइज़ किए बिना ही एलिमेंट जोड़े जा सकते हैं, वगैरह।
नई स्लाइस बनाते समय `s := []int{}` (खाली, गैर-`nil` स्लाइस) के बजाय `var s []int` (`nil` स्लाइस) को प्राथमिकता दीजिए।

## परफॉर्मेंस

जब स्लाइस बार-बार भरते हुए बनाई जा रही हो और स्लाइस का अंतिम आकार पता हो, तो परफॉर्मेंस सुधारने का एक आसान तरीका मौजूद रहता है।
असली बात यह है कि मेमोरी कम से कम बार अलॉक करनी पड़े, क्योंकि यह काफी महँगा काम है और तब होता है जब स्लाइस अपनी अलॉक की गई मेमोरी से आगे बढ़ जाती है।
ऐसा करने का सबसे सुरक्षित तरीका है स्लाइस के लिए `s := make([]int, 0, cap)` के ज़रिए कैपेसिटी `cap` तय करना और फिर आम तरह से स्लाइस में `append` करते जाना।
इस तरह `cap` एलिमेंट्स के लिए जगह तुरंत अलॉक हो जाती है, जबकि स्लाइस की लंबाई शून्य रहती है।
व्यवहार में `cap` अक्सर किसी दूसरी स्लाइस की लंबाई होती है: `s := make([]int, 0, len(otherSlice))`।

## `append` प्योर फंक्शन नहीं है

Go का `append` फंक्शन परफॉर्मेंस के लिए ऑप्टिमाइज़ किया गया है, इसलिए यह इनपुट स्लाइस की कॉपी नहीं बनाता।
इसका मतलब है कि मूल स्लाइस (यानी `append` का पहला पैरामीटर) कभी-कभी बदल जाती है।
