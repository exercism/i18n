# इसके बारे में

मुख्य रूप से लूप दो तरह के होते हैं:

1. किसी शर्त के पूरा होने तक लूप चलाना।
2. किसी संग्रह के सभी एलिमेंट पर लूप चलाना।

R में दोनों [संभव हैं][web-loops], हालाँकि पहला ज़्यादा आम हो सकता है।

## `while` और `repeat`

जिन समस्याओं का अंत पहले से तय नहीं होता और यह भी पता नहीं होता कि लूप कितनी बार चलेगा, उनके लिए R में एक शर्त वाला [`while`][ref-control] लूप है, और बिना शर्त वाला [`repeat`][ref-control] लूप भी (जो `while (TRUE)` के बराबर है)।

इसका बुनियादी रूप काफ़ी आसान है:

```R
while (condition) {
  do_something()
}
```

ऐसे में प्रोग्राम तब तक लूप में चलता रहता है जब तक `condition` का मान `TRUE` न रहे।

लूप से जल्दी बाहर निकलने के दो तरीके हैं:

- `break` लगाने से लूप खत्म हो जाता है, और कोड लूप के बंद होने वाले कर्ली ब्रैकेट `}` के बाद वाली अगली लाइन से चलता रहता है।
- `return(x)` मौजूदा फंक्शन का चलना रोक देता है और रिटर्न वैल्यू `x` को कॉल करने वाले को लौटा देता है।

इन विकल्पों के होते हुए कभी-कभी `repeat { ... }` से एक "अनंत" लूप बनाना और फिर लूप के अंदर का कोड चलते समय रुकने की कोई शर्त मिलने पर `break` या `return` चला देना सुविधाजनक रहता है।

इन तीनों तरीकों का नतीजा एक ही होता है, और तीनों के अंत में `x == 0.4444...` होता है।

```R
x <- 12
while (x > 1) {
  x <- x / 3
}

x <- 12
while (TRUE) {
  x <- x/3
  if (x <= 1) break
}

x <- 12
# no boolean clause 
repeat { 
  x <- x/3
  if (x <= 1) break
}
```

## वेक्टर (या किसी और संग्रह) पर इटरेशन करना

R में अक्सर इसकी ज़रूरत नहीं पड़ती।
जैसा कि दूसरे कॉन्सेप्ट में बताया गया है, बहुत से फंक्शन पूरे वेक्टर पर एक साथ काम करते हैं।

लेकिन कभी-कभी साफ़-साफ़ लिखा गया लूप टाला नहीं जा सकता।
यह खासकर तब होता है जब:

- लूप के अंदर के कोड के साइड इफेक्ट हों, जैसे कुछ छापना या फाइल I/O करना।
- किसी मापदंड के पूरा होने तक लगातार लूप चलता रहे, और यह पहले से पता न हो कि कितने इटरेशन लगेंगे।

लूप की शर्त गोल ब्रैकेट में होनी चाहिए।
जैसे फंक्शन बॉडी के साथ होता है, वैसे ही एक लाइन वाले लूप के अंदर के कोड के लिए कर्ली ब्रैकेट रखना ज़रूरी नहीं है (लेकिन अक्सर रखे जाते हैं)।

```R
words <- c("This", "is", "a", "loop")
for (w in words) { print(w) } # the braces are optional here
#> [1] "This"
#> [1] "is"
#> [1] "a"
#> [1] "loop"
```

अगर मौजूदा इटरेशन किसी शर्त को पूरा नहीं करता, तो `next` की मदद से सीधे अगले इटरेशन पर पहुँचा जा सकता है:

```R
for (n in 1:5) {
  if (n %% 2 == 0) next
  print(n)
}
#> [1] 1
#> [1] 3
#> [1] 5
```

अगर संख्यात्मक इंडेक्स की ज़रूरत हो, तो [`seq_along()`][ref-seq_along] का इस्तेमाल कीजिए।

```R
v <- LETTERS[1:3]
v
#> [1] "A" "B" "C"

for (i in seq_along(v)) { print(sprintf("%s%i", v[i], i)) }
#> [1] "A1"
#> [1] "B2"
#> [1] "C3"
```

`i in 1:length(v)` का उपयोग करने की सलाह _नहीं_ दी जाती, क्योंकि जब `length(v)` शून्य हो तो इससे दिक्कतें आ सकती हैं।
रेंज `1:0` असल में `c(1, 0)` के बराबर है, इसलिए लूप के अंदर का कोड चलेगा और शायद एरर पैदा करेगा।
`seq_along()` फंक्शन इस स्थिति को ठीक से संभालने के लिए ही बनाया गया है।
