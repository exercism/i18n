# निर्देश अपेंड

## एक्सेप्शन संदेश

कभी-कभी किसी एक्सेप्शन को [उठाना][raise-an-exception] ज़रूरी होता है। ऐसा करते समय आपको हमेशा एक **अर्थपूर्ण एरर संदेश** शामिल करना चाहिए, जो बताए कि एरर का स्रोत क्या है। इससे आपका कोड और पढ़ने योग्य बनता है और डीबगिंग में काफी मदद मिलती है। जिन स्थितियों में आपको पता है कि एरर का स्रोत किसी खास टाइप का ही होगा, वहाँ आप [बिल्ट-इन एरर टाइप][built-in-errors] में से कोई एक उठाना चुन सकते हैं, लेकिन तब भी एक अर्थपूर्ण संदेश ज़रूर शामिल कीजिए।

इस अभ्यास में आपको [raise स्टेटमेंट][raise-statement] का इस्तेमाल करके `ValueError` "फेंकना" होता है, अगर `answer()` को दिया गया प्रश्न गलत या अमान्य है, या उसमें कोई अज्ञात ऑपरेशन है। टेस्ट तभी पास होंगे जब आप `exception` को `raise` करें और उसके साथ एक संदेश भी दें।
**ध्यान दीजिए**: हर परिस्थिति के लिए ज़रूरी संदेश अलग होता है, भले ही एक ही _एरर टाइप_ उठाया जा रहा हो।
टेस्ट ध्यान से देखिए।

संदेश के साथ [`ValueError`][value-error] उठाने के लिए, संदेश को `exception` टाइप के आर्गुमेंट के रूप में लिखिए:


```python
# if the question contains an unknown operation.
raise ValueError("unknown operation")

# if the question is malformed or invalid.
raise ValueError("syntax error")
```

किसी खास कोड ब्लॉक में उठाई गई एरर को _संभालने_ के लिए [try-except][handling-exceptions] इस्तेमाल किया जा सकता है।
`try-except` ब्लॉक उस कोड को "लपेट" लेते हैं जिससे संभवतः कोई एरर हो सकती है, और हर एक्सेप्शन के लिए तय कर देते हैं कि उसे एक एरर, कई एरर, या समस्या से निपटने वाला कोई दूसरा कोड कैसे संभालेगा:


```python
while len(equation) > 1:
        try:
           # The questionable/error-prone code goes here,in an indented block
           # It can contain statements, loops, if-else blocks, or other executable code.
           x_value, operation, y_value, *rest = equation
           ...
           ...

        except:
            # Code for what to do when an error gets thrown in the code above.
            # This could be one error, or more complicated logging, error checking and messaging.
            raise ValueError("syntax error")
```
