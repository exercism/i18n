# परिचय

Java प्रोग्रामिंग भाषा एरर और अन्य असाधारण घटनाओं को संभालने के लिए _एक्सेप्शन_ का उपयोग करती है।

## एक्सेप्शन क्या है

एक एक्सेप्शन एक ऐसी घटना है जो प्रोग्राम के चलने के दौरान होती है और निर्देशों के सामान्य प्रवाह को बाधित करती है।
Java में एक्सेप्शन स्पष्ट रूप से उठाए जाते हैं, और एक्सेप्शन उठाने की क्रिया को _एक्सेप्शन फेंकना_ कहा जाता है।
एक्सेप्शन संभालने की क्रिया को _एक्सेप्शन पकड़ना_ कहा जाता है।

Java में, सभी एक्सेप्शन `Exception` क्लास के उपवर्ग हैं, जो स्वयं `Throwable` का उपवर्ग है।

Java दो प्रकार के एक्सेप्शन में भेद करता है:

1. चेक्ड एक्सेप्शन
2. अनचेक्ड एक्सेप्शन

### चेक्ड एक्सेप्शन

_चेक्ड एक्सेप्शन_ ऐसी असाधारण स्थितियाँ हैं जिनका पहले से अनुमान लगाना और उनसे उबरना एक एप्लिकेशन के लिए आवश्यक है।
चेक्ड एक्सेप्शन का एक उदाहरण `FileNotFoundException` है, जो तब होती है जब कोई मेथड ऐसी फाइल पढ़ने की कोशिश कर रहा हो जो मौजूद नहीं है।

इस प्रकार के एक्सेप्शन की जाँच कंपाइल-टाइम पर की जाती है: जो मेथड चेक्ड एक्सेप्शन फेंकते हैं, उन्हें अपने मेथड सिग्नेचर में यह निर्दिष्ट करना चाहिए, और जो कोड ऐसे मेथड को कॉल करता है जो चेक्ड एक्सेप्शन फेंक सकता है, उसे उस एक्सेप्शन को संभालना आवश्यक है, अन्यथा कोड कंपाइल नहीं होगा।

सभी चेक्ड एक्सेप्शन `Exception` के उपवर्ग हैं जो `RuntimeException` का विस्तार नहीं करते।

### अनचेक्ड एक्सेप्शन

_अनचेक्ड एक्सेप्शन_ ऐसी असाधारण स्थितियाँ हैं जिनका किसी एप्लिकेशन द्वारा सामान्यतः पहले से अनुमान नहीं लगाया जा सकता या उनसे उबरा नहीं जा सकता।
अनचेक्ड एक्सेप्शन का एक उदाहरण `NullPointerException` है, जो तब होती है जब कोई मेथड जो नॉन-नल वैल्यू की अपेक्षा कर रहा हो, `null` प्राप्त करता है।

इस प्रकार के एक्सेप्शन की जाँच कंपाइल-टाइम पर नहीं की जाती है: जो मेथड अनचेक्ड एक्सेप्शन फेंकते हैं, उन्हें अपने मेथड सिग्नेचर में यह निर्दिष्ट करना आवश्यक नहीं है, और जो कोड ऐसे मेथड को कॉल करता है जो अनचेक्ड एक्सेप्शन फेंक सकता है, उसे उसे संभालना आवश्यक नहीं है।

सभी अनचेक्ड एक्सेप्शन `RuntimeException` से विरासत में मिलते हैं, जो स्वयं `Exception` का विस्तार है।

## एक्सेप्शन फेंकना

Java में एक मेथड `throw` स्टेटमेंट का उपयोग करके एक्सेप्शन फेंक सकता है।

### चेक्ड एक्सेप्शन फेंकना

जब किसी मेथड से चेक्ड एक्सेप्शन फेंका जाता है, तो `throws` कीवर्ड का उपयोग करके मेथड सिग्नेचर में यह निर्दिष्ट करना आवश्यक है, जैसा कि नीचे दिए उदाहरण में दिखाया गया है।
यह कॉल करने वाले कोड को मजबूर करता है कि वह अपेक्षा करे कि एक्सेप्शन फेंका जा सकता है और उसे उसी अनुसार संभाले।

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### अनचेक्ड एक्सेप्शन फेंकना

जब किसी मेथड से अनचेक्ड एक्सेप्शन फेंका जाता है, तो मेथड सिग्नेचर में यह निर्दिष्ट करना आवश्यक नहीं है, हालाँकि यह समर्थित है।

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## एक्सेप्शन संभालना

Java में एक्सेप्शन संभालना `try`, `catch` और `finally` कीवर्ड का उपयोग करके किया जाता है।

- जो कोड स्टेटमेंट एक्सेप्शन फेंक सकते हैं, उन्हें `try` ब्लॉक में लपेटा जाना चाहिए।
- `try` ब्लॉक के बाद एक या अधिक `catch` ब्लॉक होते हैं जो `try` ब्लॉक में फेंके गए एक्सेप्शन को पकड़ते हैं।
- `catch` ब्लॉक के बाद वैकल्पिक रूप से एक `finally` ब्लॉक होता है जो `try` ब्लॉक के बाद हमेशा निष्पादित होता है, चाहे एक्सेप्शन फेंका गया हो या नहीं।

निम्नलिखित उदाहरण दिखाता है कि ये कीवर्ड कैसे काम करते हैं:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

इस उदाहरण में, जब कोई एक्सेप्शन नहीं फेंका जाता, तो निम्नलिखित प्रिंट होता है:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

हालाँकि, यदि `bankAccount.withdraw(amount)` स्टेटमेंट एक `InsufficientBalanceException` फेंकता है, तो निम्नलिखित प्रिंट होता है:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

या, यदि `bankAccount.withdraw(amount)` द्वारा एक अनचेक्ड एक्सेप्शन फेंका जाता है, तो निम्नलिखित प्रिंट होता है:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## एरर

Java में एक अलग श्रेणी भी है जिसे _एरर_ कहा जाता है, जो गंभीर समस्याएँ हैं और किसी एप्लिकेशन के बाहर की होती हैं।
एरर का एक उदाहरण `OutOfMemoryError` है, जो तब होती है जब कोई एप्लिकेशन सिस्टम पर उपलब्ध से अधिक मेमोरी का उपयोग करने की कोशिश कर रहा हो।

अनचेक्ड एक्सेप्शन की तरह, एरर की जाँच कंपाइल-टाइम पर नहीं की जाती।
अंतर यह है कि वे सिस्टम स्तर की समस्याओं का प्रतिनिधित्व करते हैं और आमतौर पर एप्लिकेशन के बजाय Java वर्चुअल मशीन या वातावरण द्वारा फेंके जाते हैं।
एप्लिकेशन को सामान्यतः इन्हें पकड़ने या संभालने की कोशिश नहीं करनी चाहिए।

Java में सभी एरर `Error` क्लास से विरासत में मिलते हैं।
