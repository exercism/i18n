# परिचय

बाइनरी डेटा के साथ काम करना मुश्किल हो सकता है। इसलिए Gleam एक `BitArray` टाइप और उसके साथ की सिंटैक्स देता है, जिससे आप बाइनरी डेटा बना भी सकते हैं और उस पर पैटर्न मैचिंग भी कर सकते हैं।

बिट ऐरे लिटरल `<<>>` सिंटैक्स से लिखे जाते हैं। बिट ऐरे लिटरल लिखते समय उसे सेगमेंट में बाँटा जाता है। हर सेगमेंट में एक वैल्यू और एक एनोटेशन होता है, और दोनों के बीच `:` लगाया जाता है। एनोटेशन बताता है कि वैल्यू को एनकोड करने के लिए कितने बिट लगेंगे। इसे पूरी तरह छोड़ा भी जा सकता है, और ऐसा करने पर वैल्यू 8-बिट पूर्णांक मान ली जाती है।

```gleam
// This defines a bit array with three segments of a single bit each
<<0:1, 1:1, 0:1>>

// This defines a bit array with three segments of 8 bits each
<<0, 1, 0>>
```

`:1` लिखकर टाइप बताना `:size(1)` लिखने का छोटा रूप है। अगर बिट का साइज़ किसी वेरिएबल से आ रहा हो, तो लंबा सिंटैक्स इस्तेमाल करना पड़ेगा।

```gleam
let segment_size = 1
<<0:size(segment_size), 1:size(segment_size), 0:size(segment_size)>>
```

## बाइनरी

बाइनरी पूर्णांक लिटरल लिखते समय हम लिटरल के आगे `0b` लगाकर उसे सीधे आधार-2 संकेतन में लिख सकते हैं। ध्यान रखिए कि टेस्ट में या आपके प्रोग्राम में प्रिंट होने पर ये दशमलव संख्याओं के रूप में दिखेंगे।

```gleam
<<0b1011:4>> == <<11:4>>
// -> True
```

## छोटा करना

अगर सेगमेंट की वैल्यू उसके टाइप की क्षमता से बड़ी हो जाए, तो उसे बाएँ से काट दिया जाएगा।

```gleam
<<0b1011:3>> == <<0b0011:3>>
// -> True
```

## आगे और पीछे जोड़ना

बिट ऐरे सिंटैक्स की मदद से आप किसी मौजूदा बिट ऐरे के आगे भी जोड़ सकते हैं और पीछे भी। मौजूदा बिट ऐरे के लिए `:bits` एनोटेशन इस्तेमाल करना ज़रूरी है।

```gleam
let value = <<0b110:3, 0b001:3>>
let new_value = <<0b011:3, value:bits, 0b000:3>>
// -> <<120, 8:size(4)>>
```

## जोड़ना

इस सिंटैक्स की मदद से हम वेरिएबलो में रखे बिट ऐरे जोड़ सकते हैं। अलग-अलग साइज़ के दो बिट ऐरे जोड़ते समय `:bits` एनोटेशन इस्तेमाल करना ज़रूरी है।

```gleam
let first = <<0b110:3>>
let second = <<0b001:3>>
let concatenated = <<first:bits, second:bits>>
// -> <<49:size(6)>>
```

## पैटर्न मैचिंग

बिट ऐरे से वैल्यू निकालने के लिए पैटर्न मैचिंग भी की जा सकती है। जिस-जिस हिस्से को आप पकड़ना चाहते हैं, उसके बिट की संख्या आपको पता होनी चाहिए। एक अपवाद है: किसी अज्ञात साइज़ वाले बिट ऐरे पर पैटर्न मैचिंग के लिए `:bits` एनोटेशन इस्तेमाल किया जा सकता है, लेकिन इसका इस्तेमाल सिर्फ अंतिम हिस्से के लिए ही हो सकता है।

```gleam
let assert <<value:4, rest:bits>> = <<0b01101001:8>>
value == 0b0110
// -> true
```

## बिट ऐरे को देखना

~~~~exercism/note
बिट ऐरे जिस फॉर्मेट में बनाए गए थे, उससे अलग फॉर्मेट में प्रिंट हो सकते हैं। बिट ऐरे सीखते समय यह अक्सर उलझन पैदा करता है।
~~~~

बिट ऐरे आम तौर पर 8 बिट (यानी एक बाइट) के हिस्सों में दिखाए जाते हैं, भले ही आपने उन्हें किसी और साइज़ के हिस्सों में बनाया हो।

```gleam
<<2011:11>>
// -> <<251, 3:size(3)>>
```

अगर आप ऐसा बिट ऐरे बनाते हैं जो किसी प्रिंट करने योग्य UTF-8 स्ट्रिंग को दर्शाता है, तो `io.debug` जैसे फंक्शन उसे स्ट्रिंग के रूप में दिखा सकते हैं। इसकी वजह Gleam के अंदरूनी कार्यान्वयन की एक बारीकी है, जिसमें वह स्ट्रिंग को एक खास तरीके से रखता है।

```gleam
<<>>
// -> ""

<<65, 66, 67>>
// -> "ABC"
```
