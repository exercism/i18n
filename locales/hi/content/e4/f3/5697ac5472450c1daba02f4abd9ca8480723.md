# परिचय

जब आपको `n` वैल्यू की एक पंक्ति चाहिए और हर वैल्यू अपनी स्थिति पर निर्भर करती हो, तो Factor के `<iota>` और `map` मिलकर यह काम बिना लूप काउंटर लिखे कर देते हैं।

## `<iota>` और `map`

`<iota>` ([`sequences`][sequences] में) एक गैर-ऋणात्मक पूर्णांक `n` लेता है और पूर्णांकों `0, 1, …, n-1` का एक *वर्चुअल* सीक्वेंस लौटाता है। फिर `map` उस पर चलकर हर एलिमेंट पर आपका क्वोटेशन लागू करता है:

```factor
USING: math sequences ;

5 <iota> [ 2 * ] map .   ! => { 0 2 4 6 8 }
```

क्वोटेशन को एक पूर्णांक मिलता है, यानी इंडेक्स, और वह उस स्थिति की वैल्यू स्टैक पर छोड़ देता है।

## गिनती के अनुसार इटरेशन और दोहराव

जब आपको हर इंडेक्स पर जाने के सिर्फ *साइड इफेक्ट* चाहिए, कोई नया सीक्वेंस नहीं, तो `each-integer` ([`math`][math] में) `0, 1, …, n-1` पर एक क्वोटेशन चलाता है:

```
each-integer ( n quot: ( i -- ) -- )
```

`replicate` ([`sequences`][sequences] में) एक क्वोटेशन को `n` बार कॉल करता है और इंडेक्स को छोड़कर परिणाम इकट्ठा कर लेता है। यह `n` स्वतंत्र वैल्यू बनाने में बहुत काम आता है:

```
replicate ( n quot: ( -- elt ) -- seq )
```

```factor
USING: sequences ;

3 [ { 0 0 } ] replicate .   ! => { { 0 0 } { 0 0 } { 0 0 } }
```

## सीमित रेंज

जब इंडेक्स की रेंज `0` से शुरू न हो, या आपको उसमें दोनों सिरे शामिल करने हों, तो [`ranges`][ranges] शब्दावली ब्रैकेट नोटेशन वाले लिटरल देती है। चौकोर ब्रैकेट अंतिम बिंदु को शामिल करते हैं, गोल ब्रैकेट उसे बाहर छोड़ देते हैं।

```
[a..b]    ! a, a+1, …, b      (inclusive)
[a..b)    ! a, a+1, …, b-1    (half-open at the top)
```

```factor
USING: math ranges sequences ;

3 7 [a..b] [ 2 * ] map .   ! => { 6 8 10 12 14 }
3 7 [a..b) [ 2 * ] map .   ! => { 6 8 10 12 }
```

कुछ आम एक-आर्गुमेंट शॉर्टहैंड:

```
[1..b]    ! 1, 2, …, b        (same as 1 b [a..b])
[1..b)    ! 1, 2, …, b-1      (same as 1 b [a..b))
[0..b)    ! 0, 1, …, b-1      (same as 0 b [a..b), and same as `b <iota>`)
```

```factor
6 [1..b] [ sq ] map .      ! => { 1 4 9 16 25 36 }
6 [1..b) [ sq ] map .      ! => { 1 4 9 16 25 }
4 [0..b) [ 1 + ] map .     ! => { 1 2 3 4 }
```

`<iota>` सबसे आम रूप है। जब रेंज `0` के अलावा कहीं और से शुरू हो या उसमें ऊपरी सीमा भी शामिल करनी हो, तो `[a..b]` और उस जैसे रूप सही टूल हैं।

## खुली निचली सीमाएँ और खाली हो सकने वाली रेंज

चौकोर ब्रैकेट अंतिम बिंदु को *शामिल* करते हैं, गोल ब्रैकेट उसे *बाहर* छोड़ देते हैं। बाईं तरफ यही तरकीब `(a..b]` और `(a..b)` देती है:

```
(a..b]    ! a+1, …, b              (lower open, upper inclusive)
(a..b)    ! a+1, …, b-1            (both open)
```

`0 n (a..b]` `n > 0` के लिए `{ 1 … n }` देता है और `n = 0` के लिए `{ }`। जब आप "`n` समेत हर धनात्मक पूर्णांक" पर इटरेशन करते हैं, तो यही स्वाभाविक रूप है।

## घटते क्रम की रेंज

`a > b` होने पर चारों ब्रैकेट रूप (`[a..b]`, `[a..b)`, `(a..b]` और `(a..b)`) खाली परिणाम की ओर नहीं जाते, बल्कि *घटते क्रम में* गिनती करते हैं:

```factor
USING: ranges sequences ;

5 1 [a..b] >array .   ! => { 5 4 3 2 1 }
1 0 [a..b] >array .   ! => { 1 0 }   (not empty!)
```

## स्थिति के अनुसार स्ट्रिंग बनाना

`map` वही रूप देता है जो उसका क्वोटेशन लौटाता है। अगर क्वोटेशन स्टैक पर एक अक्षर कोड छोड़ता है, तो `>string` ([`strings`][strings] में) परिणाम को स्ट्रिंग में बदल देता है:

```factor
USING: math sequences strings ;

4 <iota> [ 2 * CHAR: A + ] map >string .   ! => "ACEG"
```

`CHAR: A` पार्स होकर पूर्णांक `65` बनता है। यहाँ क्वोटेशन इंडेक्स को दोगुना करता है और उसमें वह आधार जोड़ता है, जिससे हर दूसरे बड़े अक्षर पर पहुँच जाता है। इंडेक्स पर आप जो भी गणित जोड़ते हैं, वही तय करता है कि उस स्थिति पर कौन-सा अक्षर आएगा।

## स्थिति के अनुसार चुनना

जब अक्षर इंडेक्स से जुड़ी किसी *शर्त* पर निर्भर करता हो, तो चुनाव क्वोटेशन के अंदर कीजिए:

```factor
USING: kernel math sequences strings ;

5 <iota> [ 3 < [ CHAR: a ] [ CHAR: b ] if ] map >string .
! => "aaabb"
```

पहली तीन स्थितियों में `i 3 <` का परिणाम `t` आता है, इसलिए उन्हें `a` मिलता है और बाकी को `b`। यही रूप, यानी `[ <test> [ <yes> ] [ <no> ] if ]`, `even?` / `odd?` ([`math`][math] में) से सम-विषम की जाँच और `mod` तथा `zero?` से "हर k-वीं स्थिति" की जाँच के लिए भी काम करता है।
