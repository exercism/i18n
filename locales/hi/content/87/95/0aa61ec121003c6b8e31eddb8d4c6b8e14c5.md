# परिचय

## इनहेरिटेंस

C# में _इनहेरिटेंस_ की मदद से _क्लास_ का पदानुक्रम बनाया जा सकता है। इससे किसी डेराइव्ड क्लास (`Car`) को अपनी पैरेंट क्लास (`Vehicle`) का व्यवहार और डेटा विरासत में मिल जाता है। अगर कोई पैरेंट तय नहीं किया गया हो, तो क्लास `object` क्लास से इनहेरिट करती है।

पैरेंट क्लासें डेराइव्ड क्लास को तीन तरीकों से फंक्शनैलिटी दे सकती हैं:

- एक साधारण मेथड बनाना।
- एक `virtual` मेथड बनाना, जो साधारण मेथड जैसा ही होता है, बस उसे डेराइव्ड क्लास _बदल_ सकती हैं।
- एक `abstract` मेथड बनाना। यह ऐसा मेथड होता है जिसे लागू नहीं किया गया होता, और जिसे डेराइव्ड क्लास को _ज़रूर_ लागू करना होता है। जिस क्लास में `abstract` मेथड हों, उसे भी `abstract` घोषित करना ज़रूरी है। `abstract` क्लास का ऑब्जेक्ट नहीं बनाया जा सकता।

`protected` एक्सेस मॉडिफायर की मदद से पैरेंट क्लास के मेंबर को डेराइव्ड क्लास में एक्सेस किया जा सकता है, लेकिन बाकी क्लासों से यह एक्सेस बंद रहता है।

डेराइव्ड क्लासें, पैरेंट क्लास के मेंबर को `base` कीवर्ड के ज़रिए एक्सेस कर सकती हैं।

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

डेराइव्ड क्लास का कंस्ट्रक्टर, अपने कंस्ट्रक्टर का कोड चलाने से _पहले_ अपनी पैरेंट क्लास के कंस्ट्रक्टर को अपने आप कॉल करता है। `base` कीवर्ड की मदद से पैरेंट क्लास के कंस्ट्रक्टर को आर्गुमेंट भी भेजे जा सकते हैं:

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

जब किसी बेस क्लास से एक से ज़्यादा क्लासें बनती हैं, तो अक्सर वे दो (या उससे ज़्यादा) क्लासें बेस क्लास के मेथड के अलग-अलग रूप लागू करती हैं। यह पॉलिमॉर्फिज़्म नाम का बहुत ज़रूरी सिद्धांत है। उदाहरण के लिए, ऊपर वाले उदाहरण में थोड़ा बदलाव करके हम दिखाते हैं कि `Vehicle` इस्तेमाल करने वाला कोड अपना व्यवहार कैसे बदल सकता है। यह इस पर निर्भर करता है कि किस तरह के वाहन का ऑब्जेक्ट बनाया गया है।

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```
