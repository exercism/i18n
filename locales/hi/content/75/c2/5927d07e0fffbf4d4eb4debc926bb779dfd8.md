# परिचय

## क्लास

अब समय है C++ के मुख्य पैराडाइम में से एक पर आने का: ऑब्जेक्ट-ओरिएंटेड प्रोग्रामिंग (OOP)।
OOP `classes` के इर्द-गिर्द घूमती है, यानी उपयोगकर्ता द्वारा परिभाषित डेटा टाइप, जिनके अपने संबंधित फंक्शन होते हैं।
हम बुनियादी बातों से शुरू करेंगे और सिलेबस में आगे जाने पर और भी उन्नत विषयों पर बात करेंगे।

### मेंबर

क्लास में **मेंबर वेरिएबल** और **मेंबर फंक्शन** हो सकते हैं।
इन्हें **मेंबर सेलेक्शन** ऑपरेटर `.` से एक्सेस किया जाता है।
क्लास के बाहर के वेरिएबल की तरह ही, मेंबर वेरिएबल को घोषित करते समय ही कोई वैल्यू देकर इनिशियलाइज़ कर देना बेहतर होता है।
तब यह वैल्यू इस क्लास के नए बनाए गए ऑब्जेक्ट के लिए डिफॉल्ट बन जाती है।

### एनकैप्सुलेशन और सूचना छिपाना

क्लास अपने मेंबर तक पहुँच सीमित करने का विकल्प देती है।
दो बुनियादी `access specifiers` हैं `private` और `public`।
`private` मेंबर क्लास के बाहर से एक्सेस नहीं किए जा सकते।
`public` मेंबर खुलकर एक्सेस किए जा सकते हैं।
`class` के सारे मेंबर डिफॉल्ट रूप से `private` होते हैं।
क्लास के बाहर खुलकर सिर्फ वही मेंबर इस्तेमाल किए जा सकते हैं, जिन्हें साफ तौर पर `public` चिह्नित किया गया हो।

### एक बुनियादी उदाहरण

एक `class` की परिभाषा नीचे के उदाहरण में देखी जा सकती है।
ध्यान दीजिए कि परिभाषा के बाद `;` लगता है:

```cpp
class Wizard {
  public:               // from here on all members are publicly accessible
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

क्लास के अंदर से आप सभी मेंबर वेरिएबल एक्सेस कर सकते हैं।
`cast_spell` फंक्शन के अंदर `damage` पर एक नज़र डालिए।
क्लास के बाहर से आप `private` मेंबर को न पढ़ सकते हैं, न बदल सकते हैं:

```cpp
Wizard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

### कंस्ट्रक्टर

कंस्ट्रक्टर ऑब्जेक्ट बनाते समय मेंबर वेरिएबल को वैल्यू असाइन करने का मौका देते हैं।
इनका नाम `class` जैसा ही होता है और इनका कोई रिटर्न टाइप नहीं होता।
एक क्लास में कई कंस्ट्रक्टर हो सकते हैं।
यह तब काम आता है, जब आपको हर बार सभी वेरिएबल सेट करने की ज़रूरत न हो।
कभी-कभी आप सब कुछ डिफॉल्ट पर रखना चाहते हैं, लेकिन `name` वेरिएबल बदलना चाहते हैं।
किसी खास Wizard के मामले में आप damage भी बदलना चाह सकते हैं, इसलिए आपको दो `constructors` चाहिए।

```cpp
class Wizard {
  public:
    Wizard(std::string new_name) {
      name = new_name;
    }
    Wizard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizard el{"Eleven"};       // deals  5 damage
Wizard vecna{"Vecna", 50}; // deals 50 damage
```

कंस्ट्रक्टर एक बड़ा विषय है और इसमें कई बारीकियाँ हैं।
अगर आप अपनी `class` के लिए साफ तौर पर कोई `constructor` नहीं बनाते, तो तभी, और सिर्फ तभी, कंपाइलर यह काम आपके लिए कर देगा।
ऊपर के पहले उदाहरण में यही हुआ है।
_silverhand_ ऑब्जेक्ट डिफॉल्ट कंस्ट्रक्टर को कॉल करके बनाया गया है, कोई आर्गुमेंट पास नहीं किया गया।
सभी वेरिएबल उसी वैल्यू पर सेट हो जाते हैं जो क्लास की परिभाषा में लिखी थी।
अगर आपने उस परिभाषा में कोई वैल्यू न दी होती, तो वेरिएबल बिना इनिशियलाइज़ किए रह सकते थे, जिसके अनचाहे परिणाम हो सकते हैं।

## स्ट्रक्ट

स्ट्रक्ट भाषा की शुरुआती C जड़ों से आए हैं और C++ जितने ही पुराने हैं।
व्यावहारिक रूप से ये `classes` जैसी ही चीज़ें हैं, बस एक जरूरी अपवाद के साथ।
डिफॉल्ट रूप से `class` में सब कुछ `private` होता है।
दूसरी ओर, स्ट्रक्ट तब तक `public` रहते हैं जब तक कुछ और तय न किया जाए।
परंपरा से `struct` कीवर्ड का इस्तेमाल अक्सर **सिर्फ डेटा रखने वाली संरचनाओं** के लिए किया जाता है।
जिन ऑब्जेक्ट को कुछ निश्चित गुण सुनिश्चित करने होते हैं, उनके लिए `class` कीवर्ड को प्राथमिकता दी जाती है।
ऐसा इनवेरिएंट यह हो सकता है कि आपकी `Wizard` `class` का `damage` कभी ऋणात्मक न हो जाए।
`damage` वेरिएबल private है और जो भी फंक्शन damage को बदलता है, वह यह सुनिश्चित करेगा कि इनवेरिएंट बना रहे।
