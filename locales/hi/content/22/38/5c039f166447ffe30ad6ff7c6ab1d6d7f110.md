# परिचय

[पैटर्न मैचिंग][pattern-matching] से आप अभिव्यक्तिपूर्ण कोड लिख सकते हैं जो अलग-अलग हालात में अलग-अलग शाखाओं पर जाता है, और [डीस्ट्रक्चरिंग][destructuring] वैल्यू को वेरिएबलो से बाँधने का सुंदर तरीका देती है। Elm प्रोग्रामर के रूप में इन दोनों को अच्छी तरह सीख लेना बहुत काम आता है, और जब इन्हें साथ में इस्तेमाल किया जाए, तो कोड पढ़ने में बहुत आसान हो जाता है।

## सरल पैटर्न मैचिंग

पैटर्न मैचिंग का मतलब है ऐसा कोड लिखना जो इस पर निर्भर करता है कि जिस डेटा पर काम हो रहा है उसका आकार क्या है। इसीलिए यह कस्टम टाइप की अवधारणा के साथ स्वाभाविक रूप से मेल खाती है, जो बताते हैं कि कोई डेटा कौन-कौन से आकार ले सकता है। उदाहरण के लिए, मान लीजिए एक `Color` कस्टम टाइप है जो या तो `Blue` है या `Red`। अब हम एक `toString` फंक्शन लिख सकते हैं, जो रंग पर पैटर्न मैचिंग करके सही स्ट्रिंग लौटाता है।

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

पैटर्न मैचिंग ऐसे कस्टम टाइप के लिए भी काम करती है जो सिर्फ साधारण नामों की सूची नहीं हैं। आइए एक `hello` फंक्शन देखते हैं, जो पैरामीटर के तौर पर एक `Maybe String` लेता है, जिसमें या तो किसी व्यक्ति का नाम होता है या कुछ भी नहीं। पैटर्न मैचिंग करते समय हम डेटा को छोटे अक्षरों वाला नाम देकर उस डेटा को उस वेरिएबल से बाँध सकते हैं, और फिर मैच के दाईं ओर उस वेरिएबल का इस्तेमाल कर सकते हैं।

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

पैटर्न मैचिंग में सारे केस कवर होने चाहिए, वरना कंपाइलर कंपाइल करने से इनकार कर देगा। लेकिन कभी-कभी हमें किसी डेटा की या case एक्सप्रेशन की किसी शाखा की परवाह नहीं होती। ऐसे में हर केस के लिए बाँधने का वेरिएबल नाम ढूँढना और हर केस की अलग शाखा बनाना ज़रूरी नहीं रहता; हम अंडरस्कोर वाइल्डकार्ड `_` इस्तेमाल कर सकते हैं।

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## उन्नत पैटर्न मैचिंग

कस्टम टाइप के अलावा, हम उन टाइप पर भी पैटर्न मैचिंग कर सकते हैं जिनके लिटरल होते हैं, जैसे `Char`, `String`, `Int` और `Floats`।

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

एक से अधिक वैल्यू को बिना नेस्ट किए मैच करने के लिए Elm में एक आम तरीका है: जिन वैल्यू को मैच करना है, उन्हें [_एड हॉक टपल_][ad-hoc-tuples] में इस तरह जोड़ दीजिए:

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

और चूँकि ऐरे फंक्शनल प्रोग्रामर के दिल के बहुत करीब होते हैं, [इन पर भी पैटर्न मैचिंग की जा सकती है][pattern-match-lists]। इसके लिए वही सिंटैक्स इस्तेमाल होता है जिससे ऐरे बनाए जाते हैं, यानी `::` ऑपरेटर।

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

अंत में, पैटर्न मैचिंग रिकर्सिव रूप से भी काम करती है, जिससे जटिल और रिकर्सिव टाइप की गहराई में उतरना संभव हो जाता है।

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## डीस्ट्रक्चरिंग

डीस्ट्रक्चरिंग पैटर्न मैचिंग से बहुत मिलती-जुलती है, इस अर्थ में कि यह टाइप के अंदर के डेटा को वेरिएबलो से बाँधने देती है। मुख्य फर्क यह है कि जब सिर्फ एक ही आकार संभव हो, तो हम इस तंत्र को "डीस्ट्रक्चरिंग" कहते हैं, और जब कई आकार हों, तो इसे पैटर्न मैचिंग कहते हैं। डीस्ट्रक्चरिंग अकसर `let` बाइंडिंग में, फंक्शन आर्गुमेंट में, और निश्चित रूप से case एक्सप्रेशन में पैटर्न मैचिंग के साथ मिली-जुली दिखती है।

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

डीस्ट्रक्चरिंग का इस्तेमाल एक ही वेरिएंट वाले कस्टम टाइप, टपल, और रिकॉर्ड के लिए भी किया जा सकता है, जहाँ यह बहुत सुविधाजनक होती है। [किसी रिकॉर्ड को डीस्ट्रक्चर करने][records-pattern-matching] के लिए आप उसके जितने भी फील्ड चाहें इस्तेमाल कर सकते हैं: एक, दो, ..., या सारे फील्ड।

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

दुर्भाग्य से, Elm का सिंटैक्स रिकॉर्ड की रिकर्सिव डीस्ट्रक्चरिंग की सुविधा नहीं देता। पिछले `Circle` उदाहरण में, वृत्त के केंद्र की `x`` and `y स्थिति तक एक ही बार में पहुँचने का कोई तरीका नहीं है। पहले हमें `center` तक पहुँचना होगा, और फिर उसकी `x` और `y` स्थिति निकालने के लिए उसे डीस्ट्रक्चर करना होगा।

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

और अंत में एक सुझाव भी है! कभी-कभी हम चाहते हैं कि किसी चीज़ तक पूरी चीज़ के रूप में भी पहुँच हो और उसके एक हिस्से तक भी। यहीं [`as` कीवर्ड][as-keyword] काम आ सकता है। इससे किसी चीज़ को पूरा होने के रूप में एक एलियस नाम दिया जा सकता है, और साथ ही उसकी सामग्री को डीस्ट्रक्चर भी किया जा सकता है।

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
