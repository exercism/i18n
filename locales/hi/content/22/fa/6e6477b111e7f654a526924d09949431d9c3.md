# परिचय

फाइल डिस्क पर एक नाम के साथ रहने वाली एक स्ट्रीम होती है। किसी फाइल के साथ काम करने के लिए [`io.files`][io.files] वोकैबुलरी दो तरीके देती है: पूरी फाइल के लिए सुविधाजनक शब्द, जो एक ही कॉल में सब कुछ पढ़ या लिख देते हैं, और स्ट्रीम खोलने वाले शब्द (यानी `with-…` कॉम्बिनेटर), जो थोड़ा-थोड़ा करके पढ़ने या लिखने के काम आते हैं। दोनों उसी [स्ट्रीम प्रोटोकॉल][stream-protocol] पर टिके हैं जिस पर `io-streams` कॉन्सेप्ट की मेमोरी में रहने वाली स्ट्रीमें टिकी हैं। एक `<file-reader>` और एक `<string-reader>` दोनों एक ही शब्दों पर काम करते हैं।

फाइल से जुड़ा हर शब्द एक **एन्कोडिंग** लेता है, यानी वह तरीका जो बाइट्स को अक्षरों में बदलता है और अक्षरों को वापस बाइट्स में। टेक्स्ट के लिए यह लगभग हमेशा `io.encodings.utf8` की [`utf8`][utf8] होती है; बाइनरी काम के लिए `latin1` या कोई `<byte-array>` एन्कोडिंग इस्तेमाल होती है।

## पूरी फाइल पढ़ना

```
file-contents   ( path encoding -- str )
file-lines      ( path encoding -- seq )
```

`file-contents` पूरी फाइल को एक ही स्ट्रिंग के रूप में लौटाता है। `file-lines` उसकी लाइनों को एक ऐरे के रूप में लौटाता है, और लाइन टर्मिनेटर हटा देता है। यह तब काम आता है जब हर लाइन एक रिकॉर्ड हो।

```factor
USING: io.encodings.utf8 io.files ;

"forecast.txt" utf8 file-contents   ! => "sunny\ncloudy\n"
"forecast.txt" utf8 file-lines      ! => { "sunny" "cloudy" }
```

## पूरी फाइल लिखना

```
set-file-contents   ( str path encoding -- )
set-file-lines      ( seq path encoding -- )
```

दोनों फाइल को **बदल देते हैं**, और अगर फाइल मौजूद न हो तो उसे बना देते हैं। `set-file-contents` एक स्ट्रिंग ज्यों की त्यों लिख देता है; `set-file-lines` किसी सीक्वेंस का हर एलिमेंट अपनी अलग लाइन पर लिखता है, और न्यूलाइन खुद जोड़ देता है।

```factor
{ "sunny" "cloudy" } "forecast.txt" utf8 set-file-lines
! forecast.txt now holds "sunny\ncloudy\n"
```

## स्कोप वाली स्ट्रीम

जब आप किसी फाइल में कुछ जोड़ना चाहें, या टुकड़े-टुकड़े करके पढ़ना-लिखना चाहें, तो उसे किसी `with-…` कॉम्बिनेटर से खोलिए और कोटेशन के अंदर स्ट्रीम के वे शब्द इस्तेमाल कीजिए जो अपने आप उपलब्ध होते हैं:

```
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
with-file-appender   ( path encoding quot -- )
```

```factor
USING: io io.encodings.utf8 io.files ;

"log.txt" utf8 [ "another line" print ] with-file-appender
```

`with-file-writer` पहले फाइल को खाली कर देता है; `with-file-appender` मौजूदा सामग्री बनाए रखता है और उसके बाद लिखता है। इनमें से हर एक डेस्ट्रक्टर स्कोप है: कोटेशन पूरा होते ही फाइल हैंडल बंद हो जाता है, भले ही उसमें कोई एरर आ जाए। यही गारंटी `boatswains-bilge` कॉम्बिनेटर भी देते हैं, बस यहाँ वह फाइलों के लिए है।

## पूरी फाइल या स्कोप?

जब फाइल इतनी छोटी हो कि वह मेमोरी में समा जाए और आपको पूरी फाइल एक साथ चाहिए, तो `file-contents` / `file-lines` / `set-file-contents` / `set-file-lines` इस्तेमाल कीजिए। और जब आपको फाइल में कुछ जोड़ना हो, किसी बड़ी फाइल को `readln` से एक-एक लाइन पढ़ते जाना हो, या पढ़ना और लिखना बारी-बारी करना हो, तो `with-…` खोलने वाले शब्द इस्तेमाल कीजिए। जहाँ भी पूरी फाइल मेमोरी में रखना फिजूल या गलत होगा, वहाँ यही तरीका सही है।
