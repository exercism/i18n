# निर्देश

आपकी दोस्त हेल्मा ने एक छोटा ऑनलाइन गेम बनाया था, जो बहुत तेज़ी से लोकप्रिय हो गया। इसका नाम _HellMath_ है। इस छोटे से समुदाय में कुछ ट्रोल भी आ गए, जो गेम और फोरम दोनों को काफी अप्रिय बना देते हैं। हेल्मा ने आपसे कहा है कि आप एक नया अनुमति सिस्टम बनाइए, ताकि उपद्रवियों को अलग किया जा सके।

फोरम तीन अलग-अलग कार्रवाइयों का समर्थन करता है:

- पढ़ना
- लिखना
- हटाना

खातों के चार प्रकार हैं, और हर प्रकार की अपनी अलग डिफॉल्ट अनुमतियाँ हैं:

- गेस्ट: पोस्ट पढ़ सकते हैं।
- यूज़र और ट्रोल: पोस्ट पढ़ और लिख सकते हैं।
- मॉडरेटर: पोस्ट पढ़, लिख और हटा सकते हैं, उनके पास सारी अनुमतियाँ हैं।

हेल्मा ने देखा है कि ट्रोल खातों पर पाबंदी लगाने से कोई फायदा नहीं होता। उसकी योजना यह है कि उन्हें यह भ्रम दिया जाए कि उनका समय "अच्छे से लगाया गया" है, लेकिन उनकी पोस्ट सिर्फ दूसरे ट्रोल्स को दिखाई जाएँ। जहाँ भी प्राथमिकता के हिसाब से क्रम लगाना हो, वहाँ ट्रोल हर क्रम में सबसे पीछे होते हैं। जब वे कोई गेम शुरू करते हैं, तो उपलब्ध खिलाड़ियों का समूह भी सिर्फ दूसरे ट्रोल्स तक सीमित रहता है।

इस तरीके को [शैडो-बैनिंग][shadow-ban] कहते हैं।

## 1. यूज़र टाइप और अनुमतियाँ सेट कीजिए।

सबसे पहले, खातों के चारों प्रकारों को दर्शाने के लिए एक `AccountStatus` एन्यूमरेशन बनाइए: `troll`, `guest`, `user`, और `mod`.

इसके बाद, तीनों अनुमति प्रकारों को दर्शाने के लिए एक `Action` एन्यूमरेशन बनाइए: `read`, `write`, और `remove`.


## 2. ट्रोल्स को सिर्फ दूसरे ट्रोल्स को ही दिखाइए।

फोरम की हर पोस्ट अपने मेटाडेटा में पोस्ट करने वाले का `AccountStatus` संग्रहीत करती है। ध्यान रखिए कि ट्रोल्स की पोस्ट सिर्फ दूसरे ट्रोल्स को ही दिखाई जाएँ।

हेल्मा को एक `display_post` फंक्शन चाहिए, जो `AccountStatus` टाइप के दो आर्गुमेंट लेता है और एक `bool` लौटाता है। पहला आर्गुमेंट पोस्ट करने वाले का स्टेटस है, और दूसरा देखने वाले का।

```cpp
using namespace hellmath;
display_post(AccountStatus::troll, AccountStatus::user);
// => false
display_post(AccountStatus::mod, AccountStatus::guest);
// => true
```

## 3. अलग-अलग यूज़रों के लिए अनुमतियाँ जाँचिए।

हेल्मा को यह जाँचने का तरीका चाहिए कि किसी यूज़र के लिए कोई खास कार्रवाई करने की अनुमति है या नहीं।

कृपया एक `permission_check` फंक्शन बनाइए, जो पहले आर्गुमेंट के रूप में एक `Action` लेता है और जाँचने के लिए उसके बाद एक `AccountStatus`। इसे परिचय में दी गई अनुमतियों के अनुसार एक `bool` लौटाना चाहिए।

```cpp
permission_check(Action::remove, AccountStatus::guest);
// => false
permission_check(Action::write, AccountStatus::mod);
// => true
```

## 4. गेम का एक्सेस दीजिए और खिलाड़ियों की जोड़ी बनाइए।

गेम के असली खिलाड़ियों को उनके कामों के लिए जवाबदेह बनाए रखने के लिए, _Hellmath_ गेस्ट यूज़रों को गेम का एक्सेस नहीं देता। जैसा ऊपर बताया गया है, हेल्मा चाहती है कि ट्रोल दूसरे ट्रोल्स को ही ट्रोल करें। बाकी यूज़रों के बीच गेम में जुड़ने पर कोई रोक नहीं है।

`valid_player_combination` फंक्शन बनाइए, जो जाँचता है कि दो खिलाड़ी एक ही गेम में शामिल हो सकते हैं या नहीं। इस फंक्शन में `AccountStatus` टाइप के दो पैरामीटर हैं और यह एक `bool` लौटाता है।

```cpp
valid_player_combination(AccountStatus::guest, AccountStatus::mod);
// => false
valid_player_combination(AccountStatus::troll, AccountStatus::troll);
// => true
```

## 5. प्राथमिकता वाली कतार बनाइए।

गेम और फोरम के तेज़ी से बढ़ने के कारण अब हेल्मा को यूज़रों के बीच कंप्यूटिंग पावर और बैंडविड्थ बाँटनी पड़ती है। आपात स्थितियों से निपटने के लिए मॉडरेटरों को सबसे ज़्यादा प्राथमिकता दी जाती है। गेस्ट सामान्य यूज़रों के बाद कतार में लगते हैं, और ट्रोल सबसे पीछे रखे जाते हैं।

`has_priority` फंक्शन बनाइए, जो `AccountStatus` टाइप के दो आर्गुमेंट लेता है। यह तभी `true` लौटाता है जब, और सिर्फ तभी जब, पहले खाते की प्राथमिकता दूसरे खाते से सख्ती से ज़्यादा हो।

```cpp
has_priority(AccountStatus::guest, AccountStatus::mod);
// => false
has_priority(AccountStatus::user, AccountStatus::troll);
// => true
```
