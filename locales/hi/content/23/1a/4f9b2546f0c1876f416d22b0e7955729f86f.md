# परिचय

C# में _इनहेरिटेंस_ की मदद से _क्लास_ का पदानुक्रम बनाया जा सकता है। इसमें एक डेराइव्ड क्लास (`Car`) अपनी पैरेंट क्लास (`Vehicle`) का व्यवहार और डेटा इनहेरिट कर सकती है। अगर कोई पैरेंट क्लास नहीं बताई जाती, तो क्लास `object` क्लास से इनहेरिट करती है।

पैरेंट क्लासें डेराइव्ड क्लासों को तीन तरीकों से सुविधाएँ दे सकती हैं:

- एक सामान्य मेथड बनाना।
- एक `virtual` मेथड बनाना, जो सामान्य मेथड जैसा ही होता है, लेकिन डेराइव्ड क्लासें उसे _बदल_ सकती हैं।
- एक `abstract` मेथड बनाना, यानी ऐसा मेथड जिसका कोई इम्प्लीमेंटेशन नहीं होता और जिसे डेराइव्ड क्लासों को लागू करना _ज़रूरी_ होता है। जिस क्लास में `abstract` मेथड हों, उसे भी `abstract` घोषित करना ज़रूरी है। जो क्लास `abstract` होती है, उसका ऑब्जेक्ट नहीं बनाया जा सकता।

`protected` एक्सेस मॉडिफायर की मदद से पैरेंट क्लास के किसी सदस्य को डेराइव्ड क्लास में एक्सेस किया जा सकता है, लेकिन दूसरी क्लासें उसे एक्सेस नहीं कर सकतीं।

डेराइव्ड क्लासें `base` कीवर्ड के ज़रिए पैरेंट क्लास के सदस्यों को एक्सेस कर सकती हैं।

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

डेराइव्ड क्लास का कंस्ट्रक्टर अपने कंस्ट्रक्टर का लॉजिक चलाने से _पहले_ अपनी पैरेंट क्लास का कंस्ट्रक्टर अपने आप कॉल करता है। `base` कीवर्ड के ज़रिए पैरेंट क्लास के कंस्ट्रक्टर को आर्गुमेंट दिए जा सकते हैं:

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

जब एक ही पैरेंट क्लास से एक से ज़्यादा क्लासें डेराइव्ड होती हैं, तो अक्सर ये दो (या ज़्यादा) क्लासें पैरेंट क्लास के किसी मेथड के अलग-अलग वर्शन लागू करती हैं। यह एक बहुत ज़रूरी सिद्धांत है, जिसे पॉलिमॉर्फिज़्म कहते हैं। उदाहरण के लिए, ऊपर वाले उदाहरण में थोड़ा बदलाव करके हम दिखाते हैं कि `Vehicle` इस्तेमाल करने वाला कोड अपना व्यवहार कैसे बदल सकता है। यह इस पर निर्भर करता है कि किस तरह के वाहन का ऑब्जेक्ट बनाया गया है।

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```
