# परिचय

_क्लोज़र_ JavaScript में प्रोग्रामिंग का एक तरीका है, जिसमें किसी बाहरी [लेक्सिकल स्कोप][wiki-lexical-scope] के वेरिएबलो को कोड के अंदर एक नेस्टेड ब्लॉक में इस्तेमाल किया जा सकता है। JavaScript में क्लोज़र बिना किसी अतिरिक्त काम के चलते हैं, और अक्सर लोग यह जाने बिना भी इन्हें इस्तेमाल कर लेते हैं कि ये असल में क्या हैं।

```javascript
// Top-level declarations are global-scope
const dozen = 12;

// Functions create a new function-scope and block-scope.
// Referencing the outer variable here is a closure.
function nDozen(n) {
  return dozen * n;
}
```

_क्लोज़र_ नाम ऐतिहासिक रूप से [_λ-कैलकुलस_][wiki-lambda-calculus] से लिया गया है और इसे [_scheme_][wiki-scheme] ने लोकप्रिय बनाया ([स्रोत][wiki-closure]); यह नाम किसी फंक्शन के खुले और बंद वेरिएबल बाइंडिंगों की ओर इशारा करता है।

## JavaScript में क्लोज़र इस्तेमाल करने के कारण

1. डेटा प्राइवेसी / डेटा एनकैप्सुलेशन
   - दूसरी भाषाओं के विपरीत, 2020 में _प्राइवेट_ वेरिएबलो को घोषित करने का कोई तरीका नहीं था। इसलिए क्लोज़र की मदद से _प्राइवेट_ वेरिएबलो की नकल बहुत अच्छी तरह की जा सकती है (प्राइवेट वेरिएबल लिखने का एक प्रस्ताव था, जो शायद आपके इसे पढ़ने तक मानक बन चुका हो)।

   ```javascript
   // Consider this function:

   const saveNumber = (number) => {
     // The saved value is unaccessible by the outer lexical scope.
     const value = number;

     // We can provide access to the primitive value with a function, but the original will never change
     return () => value;
   };

   // Attempting to set the variable outside of its lexical scope results in an error
   value = 42;
   ```

2. पार्शियल एप्लीकेशन
   - फंक्शन दूसरे फंक्शन लौटा सकते हैं। जब लौटाया गया फंक्शन उस फंक्शन के आर्गुमेंट इस्तेमाल करता है जिसने उसे बनाया था, तो यह क्लोज़र की मदद से पार्शियल एप्लीकेशन करने का उदाहरण है। कभी-कभी इसे फंक्शन की _करीइंग_ कहा जाता है।

   ```javascript
   // The arguments are applied one-by-one, using closures to arrive at the final result
   function partialBuildUri(scheme) {
     return function (domain) {
       return function (path) {
         return `${scheme}://${domain}/${path}`;
       };
     };
   }

   // A function could apply them all at once.
   function buildUri(scheme, domain, path) {
     return partialBuildUri(scheme)(domain)(path);
   }

   // Or apply a few to create a flexible system of functions for reuse.
   function buildHttpsExercismUri(path) {
     return partialBuildUri('https')('exercism.org');
   }
   ```

## वेरिएबलो के लिए लेक्सिकल स्कोप

किसी भी प्रोग्रामिंग भाषा में **क्लोज़र** का वेरिएबल स्कोप से गहरा संबंध होता है। JavaScript में वेरिएबलो के लिए तीन तरह के लेक्सिकल स्कोप होते हैं:

1. **ग्लोबल स्कोप**: ये वे वेरिएबल होते हैं जो फंक्शन और ब्लॉक के बाहर घोषित किए जाते हैं।
1. **फंक्शन स्कोप**: ये वे वेरिएबल होते हैं जो किसी फंक्शन के अंदर `var` कीवर्ड से घोषित किए जाते हैं।
1. **ब्लॉक स्कोप**: ये वे वेरिएबल होते हैं जो किसी ब्लॉक (`{...}`) के अंदर `let` और `const` कीवर्ड से घोषित किए जाते हैं।

व्यवहार में क्लोज़र तब बनता है जब कोई फंक्शन (या ब्लॉक) किसी बाहरी स्कोप का वेरिएबल इस्तेमाल करता है। JavaScript में यह अपने आप काम करता है, इसलिए अक्सर लोग बिना जाने ही क्लोज़र इस्तेमाल कर लेते हैं।

### फंक्शन स्कोप

`var` कीवर्ड एक **फंक्शन स्कोप** वाला वेरिएबल बनाता है। इसका मतलब है कि `var` से बनाए गए वेरिएबल उस फंक्शन में कहीं भी इस्तेमाल किए जा सकते हैं जहाँ वे बनाए गए हैं, और उसके अंदर के हर लेक्सिकल स्कोप (**फंक्शन** हो या **ब्लॉक**) में भी।

```javascript
{
  var five = 5;
}

// This will succeed because 'five' exists in the same scope
var tenTimes = five * 10;
```

### ब्लॉक स्कोप

`let` और `const` कीवर्ड **ब्लॉक स्कोप** वाले वेरिएबल बनाते हैं। `let` ऐसा वेरिएबल बनाता है जिसे बदला जा सकता है, यानी उसकी वैल्यू कई बार रखी जा सकती है और उसे बिना शुरुआती वैल्यू दिए भी बनाया जा सकता है। `const` ऐसा वेरिएबल बनाता है जिसे बनाते समय ही उसकी शुरुआती वैल्यू देनी पड़ती है, और उसके बाद उसकी वैल्यू नहीं बदली जा सकती। अगर `const` वेरिएबल में कोई प्रिमिटिव वैल्यू रखी जाए, तो उसे बदला नहीं जा सकता। अगर `const` वेरिएबल में कोई रेफरेंस वैल्यू रखी जाए, जैसे कोई _ऐरे_ या _ऑब्जेक्ट_, तो रेफरेंस तो नहीं बदलेगा, पर ऐरे के अंदर की चीज़ें बदली जा सकती हैं।

इस ब्लॉक को देखिए:

```javascript
// 'two' is defined at the top-level, therefore available to the global-scope
const two = 2;

{
  // This succeeds, as 'two' is available from the outer lexical scope
  const oneLess = two - 1;
}

// This throws an error because oneLess is not defined outside of the previous inner lexical scope
console.log(oneLess);
```

हालाँकि हम ब्लॉक बनाने के लिए ब्रेसिज़ (`{...}`) का इस्तेमाल कहीं भी कर सकते हैं, पर अक्सर ये _if स्टेटमेंट_, _फंक्शन_ और _क्लास_ के आसपास ही दिखते हैं।

```javascript
const PI = 3.14;

// This function uses a closure for the value of PI (π)
function areaOfCircle(radius) {
  return PI * radius * radius;
}
```
