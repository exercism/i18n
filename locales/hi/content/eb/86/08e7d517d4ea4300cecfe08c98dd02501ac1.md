# परिचय

`Complex numbers` जटिल नहीं हैं।
इन्हें बस एक कम डरावने नाम की ज़रूरत है।

ये इतनी उपयोगी हैं, खासकर इंजीनियरिंग और विज्ञान में, कि Julia इन्हें पूर्णांकों और दशमलव संख्याओं के साथ मानक संख्यात्मक टाइपों के रूप में शामिल करता है।

## बुनियादी बातें

Julia में एक `complex` वैल्यू वास्तव में दो संख्याओं का एक जोड़ा होती है: आमतौर पर दशमलव, लेकिन हमेशा नहीं।
ऐतिहासिक कारणों से, और वे भी दुर्भाग्यपूर्ण, इन्हें "वास्तविक" और "काल्पनिक" भाग कहा जाता है।
फिर कहें तो, अजीब नामों पर नहीं, इनके पीछे की सादगी पर ध्यान देना ही बेहतर है।

दो वास्तविक संख्याओं से कॉम्प्लेक्स संख्याएँ बनाने के लिए, काल्पनिक भाग के आगे बस `im` लगा दीजिए।

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im
julia> typeof(z)
ComplexF64 (alias for Complex{Float64})
julia> zi = 1 + 2im
1 + 2im
julia> typeof(zi)
Complex{Int64}
```

इस तरह `Complex` के कई टाइप होते हैं, जो संबंधित पूर्णांक या दशमलव संख्या टाइप से बनते हैं।

वास्तविक वेरिएबलो से कॉम्प्लेक्स संख्या बनाने के लिए ऊपर दिया गया तरीका काम नहीं करेगा।
`a + bim` लिखने से पार्सर यह सोच बैठता है कि `bim` किसी (न होने वाले) वेरिएबल का नाम है।

`b*im` लिखना भी संभव है, लेकिन इसका पसंदीदा तरीका `complex()` फंक्शन है, जिसमें गुणा और जोड़ अलग से करने की ज़रूरत नहीं होती।

```julia-repl
julia> a = 1.2; b = 3.4; complex(a, b)
1.2 + 3.4im
```

किसी कॉम्प्लेक्स संख्या के अलग-अलग भाग देखने के लिए:

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im
julia> real(z)
1.2
julia> imag(z)
3.4
```

या फिर दोनों को एक साथ:

```julia-repl
julia> reim(z)
(1.2, 3.4)
```

कोई भी भाग शून्य हो सकता है, और तब गणितज्ञ उस संख्या को "पूरी तरह वास्तविक" या "पूरी तरह काल्पनिक" कह सकते हैं।
लेकिन Julia में यह फिर भी एक कॉम्प्लेक्स संख्या ही होती है।

```julia-repl
julia> zr = 1.2 + 0im
1.2 + 0.0im
julia> typeof(zr)
ComplexF64 (alias for Complex{Float64})
julia> zi = 3.4im
0.0 + 3.4im
julia> typeof(zi)
ComplexF64 (alias for Complex{Float64})
```

आपने शायद सुना होगा कि "`i` (या `j`) -1 का वर्गमूल है"।

अभी के लिए इसका मतलब बस इतना है कि काल्पनिक भाग _परिभाषा से_ नीचे दी गई समानता को संतुष्ट करता है:

```julia-repl
julia> 1im * 1im == -1
true
```

यह एक सीधा-सादा विचार है, लेकिन इसके नतीजे दिलचस्प होते हैं।

## अंकगणित

दशमलव और पूर्णांक संख्याओं के साथ इस्तेमाल होने वाले सभी मानक गणितीय `operators` और बुनियादी फंक्शन कॉम्प्लेक्स संख्याओं के साथ भी काम करते हैं। एक छोटा-सा नमूना:

```julia-repl
julia> z1 = 1.5 + 2im
1.5 + 2.0im
julia> z2 = 2 + 1.5im
2.0 + 1.5im
julia> z1 + z2  # addition
3.5 + 3.5im
julia> z1 * z2  # multiplication
0.0 + 6.25im
julia> z1 / z2  # division
0.96 + 0.28im
julia> z1^2  # exponentiation
-1.75 + 6.0im
julia> 2^z1  # another exponentiation
0.5188946835878313 + 2.7804223253571183im
```

## फंक्शन

`real()` और `imag()` के अलावा भी कई फंक्शन हैं जो कॉम्प्लेक्स संख्याओं के लिए खास तौर पर उपयोगी हैं।

- `conj()` किसी कॉम्प्लेक्स संख्या के काल्पनिक भाग का चिह्न बस उलट देता है (_+ से - या इसके उलट_)।
    - कॉम्प्लेक्स गुणा जिस तरह काम करता है, उसकी वजह से यह उससे ज़्यादा उपयोगी है जितना आप सोचते हैं।
- `abs(<complex number>)` हमेशा एक ऐसी वास्तविक संख्या लौटाता है जिसका कोई काल्पनिक भाग नहीं होता।
- `abs2(<complex number>)` `abs(<complex number>)` का वर्ग लौटाता है: यह `abs()` से जल्दी निकलता है, और अक्सर किसी गणना में यही चाहिए होता है।
- `angle(<complex number>)` रेडियन में फेज़ कोण लौटाता है।

```julia-repl
julia> z1
1.5 + 2.0im
julia> conj(z1)
1.5 - 2.0im
julia> abs(z1)
2.5
julia> abs2(z1)
6.25
julia> angle(z1)
0.9272952180016122
```
गणित में रुचि रखने वालों के लिए एक छोटी-सी व्याख्या:

- `z1` का `(real, imag)` रूप वास्तव में कॉम्प्लेक्स तल पर कार्तीय निर्देशांक इस्तेमाल करता है।
- वही कॉम्प्लेक्स संख्या ध्रुवीय निर्देशांकों का उपयोग करते हुए `(r, θ)` संकेतन में भी लिखी जा सकती है।
- यहाँ `r` और `θ` क्रमशः `abs(z1)` और `angle(z1)` से मिलते हैं।

यहाँ कुछ स्थिरांकों का इस्तेमाल करते हुए एक उदाहरण है:

```julia-repl
julia> euler = exp(1im * π)
-1.0 + 1.2246467991473532e-16im
julia> real(euler)
-1.0
julia> round(imag(euler), digits=15)  # round to 15 decimal places
0.0
```

ध्रुवीय `(r, θ)` संकेतन इतना उपयोगी है कि इसके लिए बिल्ट-इन फंक्शन `cis` (जो `cos(x) + isin(x)` का छोटा रूप है) और `cispi` (जो `cos(πx) + isin(πx)` का छोटा रूप है) मौजूद हैं, जो इसे ज़्यादा कुशलता से बनाने में मदद करते हैं।

ध्रुवीय संकेतन की उपयोगिता यूलर के सुंदर सूत्र `ℯ^(iθ) = cos(θ) + isin(θ) = x + iy` में दिखती है, जहाँ `|x + iy| = 1` है।
`|x + iy| = r` लेने पर हमें इसका ज़्यादा सामान्य ध्रुवीय रूप `r * ℯ^(iθ) = r * (cos(θ) + isin(θ)) = x + iy` मिलता है।
ध्यान दीजिए कि एक्सपोनेंशियल रूप खास तौर पर छोटा और इस्तेमाल में आसान होता है।

```julia-repl
julia> exp(1im * π) ≈ cis(π) ≈ cispi(1)
true
```

ऊपर दी गई लगभग-बराबरी इसलिए है क्योंकि `cis` और `cispi` फंक्शन ज़्यादा साफ़ संख्यात्मक परिणाम दे सकते हैं। खास तौर पर `cispi`, जब आर्गुमेंट π के मनमाने गुणज हों (जैसे रेडियन!)।

```julia-repl
julia> cis(π)
-1.0 + 0.0im
julia> cispi(1)
-1.0 + 0.0im
julia> θ = π/2;
julia> exp(im*θ)
6.123233995736766e-17 + 1.0im
julia> cis(θ)
6.123233995736766e-17 + 1.0im
julia> cispi(θ / π)  # θ/π == 1/2
0.0 + 1.0im
```

वैसे, इसी वजह से कॉम्प्लेक्स संख्याएँ 2D में घुमाव और त्रिज्या की दिशा में खिसकाव करने के लिए बहुत उपयोगी हो जाती हैं।

घुमाव के लिए, कॉम्प्लेक्स संख्या `z = x + iy` को मूल बिंदु के चारों ओर `θ` कोण से बस एक गुणा करके घुमाया जा सकता है: `z * ℯ^(iθ)`।
ध्यान दीजिए कि यहाँ `x` और `y` वास्तविक 2D कार्तीय तल के सामान्य निर्देशांक ही हैं। धनात्मक कोण से *वामावर्त* घुमाव होता है, और ऋणात्मक कोण से *दक्षिणावर्त* घुमाव।

उसी तरह आसानी से, ध्रुवीय रूप में लिखी कॉम्प्लेक्स संख्या के परिमाण `r` में `Δr` जोड़कर त्रिज्या की दिशा में खिसकाव किया जा सकता है (जैसे `z = r * ℯ^(iθ)` -> `z' = (r + Δr) * ℯ^(iθ)`)।
ध्यान दीजिए कि कोण वाला भाग वैसा ही रहता है और जैसा अपेक्षित है, सिर्फ परिमाण `r` बदलता है।
