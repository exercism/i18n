# बूलियन टाइप

Cairo में बूलियन टाइप तार्किक संक्रियाओं और शर्त वाले स्टेटमेंट के लिए ज़रूरी होता है।
Cairo में बूलियन का आकार एक `felt252` होता है, जिससे जगह का उपयोग कुशल रहता है और सही/गलत तर्क की सादगी भी बनी रहती है।

Cairo में बूलियन टाइप को `bool` कीवर्ड से लिखा जाता है।
इससे भाषा में बूलियन वेरिएबलो को घोषित करना और उनका इस्तेमाल करना संभव होता है।
उदाहरण के लिए, नीचे दिए गए कोड को देखिए:

```rust
fn main() {
    let t = true;
    let f: bool = false; // with explicit type annotation
}
```

इस उदाहरण में दो बूलियन वेरिएबलो घोषित किए गए हैं।
वेरिएबल `t` को `true` वैल्यू असाइन की जाती है और वह अपने आप बूलियन टाइप के रूप में घोषित हो जाता है, जबकि वेरिएबल `f` पर साफ `bool` टाइप लिखा जाता है और उसे `false` वैल्यू असाइन की जाती है।

ध्यान देने वाली एक ज़रूरी बात यह है कि Cairo में बूलियन वेरिएबल घोषित करते समय वैल्यू के तौर पर `true` या `false` लिटरल में से किसी एक का इस्तेमाल करना ज़रूरी होता है।
इसका मतलब है कि `0` या `1` जैसे पूर्णांक लिटरल को `false` या `true` के विकल्प के रूप में इस्तेमाल नहीं किया जा सकता।
इस नियम का सख्ती से पालन टाइप सुरक्षा सुनिश्चित करता है और स्मार्ट कॉन्ट्रैक्ट डेवलपमेंट में हो सकने वाली तार्किक गलतियों को रोकता है।

## Cairo में बूलियन ऑपरेटर

- `||` (तार्किक OR): अगर ऑपरेंड में से कम से कम एक `true` है तो यह `true` लौटाता है।
- `&&` (तार्किक AND): अगर दोनों ऑपरेंड `true` हैं तो यह `true` लौटाता है।
- `!` (तार्किक NOT): यह ऑपरेंड की उलटी बूलियन वैल्यू लौटाता है।

## उदाहरण कोड

नीचे दिया गया कोड दिखाता है कि Cairo में बूलियन टाइप का इस्तेमाल कैसे किया जाता है।
इसमें बूलियन वेरिएबलो को घोषित करना, बूलियन एक्सप्रेशन असाइन करना, और बूलियन तर्क की सही होने की जाँच के लिए असर्शन का इस्तेमाल दिखाया गया है:

```rust
fn main() {
    // Declaration of Boolean variables
    let t: bool = true;
    let f: bool = false;

    // Boolean expression evaluation
    let true_expr = 5 == 5; // true
    let false_expr = 7 == 5; // false

    // Using Boolean operators
    let or_expr = t || f; // true || false => true
    let and_expr = t && f; // true && false => false
    let not_expr = !f; // !false => true

    // Assertions to verify the correctness
    assert(t == true_expr, 'this should be true'); // t == true
    assert(f == false_expr, 'this should be false'); // f == false
    assert(or_expr == true, 'this should be true for OR'); // true
    assert(and_expr == false, 'this should be false for AND'); // false
    assert(not_expr == true, 'this should be true for NOT'); // true
}
```
