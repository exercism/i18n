# परिचय

## निरूपण, अक्षर और पूर्णांक

अन्य सरल टाइपों (`int`, `bool` आदि) की तरह `char` का भी एक साथी या उपनाम टाइप होता है, जो यहाँ `System.Char` है।

यह वास्तव में 16 बिट के फील्ड वाला एक `struct` है, और डिफ़ॉल्ट रूप से अपरिवर्तनीय होता है।

`char` में `Equals`, `ToString` और [`CompareTo`][compare-to] जैसे कुछ इंस्टेंस मेथड होते हैं।

`char` की चौड़ाई [`ushort`][uint16] जितनी ही होती है, लेकिन कुछ भाषाओं की तरह इन दोनों का इस्तेमाल आम तौर पर एक-दूसरे की जगह नहीं किया जाता। `ushort` को स्पष्ट रूप से `char` में कास्ट करना पड़ता है।

यह भी जान लीजिए कि `char` पर अंकगणितीय संक्रियाएँ की जा सकती हैं। इन संक्रियाओं का परिणाम एक पूर्णांक होता है।

यह स्पष्ट है कि 8 बिट के `byte` और 16 बिट के `char` में कोई समानता नहीं है।

## उपयोग

`char` का इस्तेमाल आम तौर पर आसान होता है।

इन्हें सिंगल कोट्स के साथ लिटरल के रूप में लिखा जा सकता है:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

किसी स्ट्रिंग से (शून्य-आधारित) इंडेक्सिंग की मदद से एक अलग `char` निकाला जा सकता है:

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

स्ट्रिंग पर इटरेशन करने पर हर चरण में एक `char` मिलता है:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

जैसा ऊपर दिखाया गया है, एक `char` को उसकी `int` वैल्यू में कास्ट किया जा सकता है।
यह (*कम से कम कुछ मामलों में*) दूसरी लिपियों के लिए भी काम करता है:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

अक्षरों की तुलना करते समय अंदर वाला Int16 इस्तेमाल होता है:

```fsharp
'A' < 'D'
// => val it: bool = true
```

साथ ही, एक `int` को `char` में भी कास्ट किया जा सकता है:

```fsharp
char 77
// => val it: char = 'M'
```

`System.Char` लाइब्रेरी में .NET भाषा के लिए अपेक्षित सभी [मेथड][Char-methods] मौजूद होते हैं, जैसे अपरकेस/लोअरकेस में बदलना (लेकिन अगले भाग में दी गई चेतावनियाँ भी देखिए):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

.NET लाइब्रेरी स्ट्रिंग से `char` निकालने में मदद करती हैं। यहाँ `Seq` के मेथड देखिए:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

अक्षरों की सूची (या ऐरे) को स्ट्रिंग में बदलने के कई तरीके हैं, जिनमें ये भी शामिल हैं:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

`char` के बारे में सामान्य जानकारी यहाँ मिल सकती है:

- [Chars दस्तावेज़][chars-docs]: `char` के लिए संदर्भ दस्तावेज़।

लेकिन `char` में कई दिक्कतें हैं, जिनका ब्यौरा नीचे दिया गया है। ये दिक्कतें ज़्यादातर इस टकराव से जुड़ी हैं: एक ओर पूरा यूनिकोड मानक है, और दूसरी ओर टेक्स्ट का पुराना निरूपण, प्रदर्शन और मेमोरी का इस्तेमाल।

## यूनिकोड से जुड़ी समस्याएँ

स्ट्रिंग के साथ काम करते समय, अगर [`System.String`][System-string] लाइब्रेरी के मेथड उपलब्ध हैं, तो आपको स्ट्रिंग को अक्षरों में तोड़ने के बजाय उन्हीं मेथड को ढूँढकर इस्तेमाल करना चाहिए।

कुछ टेक्स्ट वाले "अक्षर" एक से ज़्यादा `char` से बने होते हैं, क्योंकि यूनिकोड मानक में 65536 से ज़्यादा कोड पॉइंट होते हैं। उदाहरण के लिए, कुछ टेस्ट में दिखने वाले इमोजी में 2 `char` होते हैं, क्योंकि वे [सरोगेट][surrogates] अक्षरों से बने होते हैं।

इसके अलावा कंबाइनिंग सीक्वेंस भी होते हैं, जहाँ कुछ मामलों में एक एक्सेंट वाला अक्षर सादे अक्षर के लिए एक `char` और एक्सेंट के लिए दूसरे `char` से बना हो सकता है।

अगर आपको अलग-अलग अक्षरों के साथ काम करना पड़े, तो [`System.Char.IsControl`][is-control], [`System.Char.IsDigit`][is-digit] जैसे लाइब्रेरी मेथड इस्तेमाल करने की कोशिश कीजिए, बजाय इसके कि आप '0' और '9' के बीच जाँचने जैसी सीधी तुलना करें।

उदाहरण के लिए, ध्यान दीजिए कि '٢' अरबी का अंक 2 है। `IsDigit` अरबी वाले रूप के लिए सही लौटाएगा, इसलिए जाँच करते समय आपको साफ़ तय करना होगा कि इनपुट की कौन-सी रेंज स्वीकार्य है।

यहाँ तक कि `System.Char` लाइब्रेरी के मेथड भी कम प्रचलित भाषाओं के साथ काम करते समय वैसा व्यवहार नहीं कर सकते जैसी आप उम्मीद करते हैं।

किसी स्ट्रिंग को सुरक्षित तरीके से प्रदर्शन योग्य "अक्षरों" में तोड़ने का एक तरीका यह है कि [`StringInfo`][string-info] और [`GetNexttextElement`][get-next-text-element] जैसे मेथड इस्तेमाल किए जाएँ।
ग्लोबलाइज़ेशन/लोकलाइज़ेशन से काम पड़ने पर यह ज़रूरी हो सकता है।

एक और रास्ता, जहाँ यूनिकोड अक्षरों के स्केलर मान ज़रूरी हो जाते हैं (मान लीजिए आप अपनी खुद की एन्कोडिंग प्रणाली बना रहे हैं), [रून्स][runes] का इस्तेमाल करना है। लेकिन अगर आप जानते हैं कि आप जिन अक्षरों के साथ काम करते हैं उनकी रेंज में सरोगेट या कंबाइनिंग अक्षर क्रम शामिल नहीं हैं (जैसे लैटिन ASCII) और आपका इनपुट अच्छी तरह जाँचा गया है, तो आप इससे बच सकते हैं।

फिर से कहें तो, सबसे अच्छी स्थिति वही है जहाँ आप `String` की लाइब्रेरी मेथड इस्तेमाल कर सकें।

अगर आपको यूनिकोड की बारीकियों से जूझना ही पड़े, तो [यह][char-encoding-net] शुरुआत के लिए अच्छी जगह है।

## ग्लोबलाइज़ेशन

अगर आप ऐसे वातावरण में काम कर रहे हैं जहाँ आपको कई कल्चरों से काम पड़ता है, या कोड के कुछ हिस्सों में कल्चर मायने रखता है और कुछ में नहीं, तो [`ToUpper`][to-upper] और [`ToLower`][to-lower] के ओवरलोड के बारे में जान लीजिए, जो कल्चर लेते हैं, और [`ToUpperInvariant`][to-upper-invariant] तथा [`ToLowerInvariant`][to-lower-invariant] के बारे में भी, जो मौजूदा [कल्चर][culture-info] की परवाह किए बिना एक समान परिणाम देते हैं।
