# परिचय

## भूमिका

जेनेरिक्स भाषा की एक ऐसी सुविधा है जिससे कोड का दोबारा उपयोग किया जा सकता है।
उदाहरण के लिए, किसी ऐरे की लंबाई निकालने के लिए यह मायने नहीं रखना चाहिए कि उसमें किस टाइप की वैल्यू रखी है।
इसीलिए `length` फंक्शन अपने टाइप सिग्नेचर में एक जेनेरिक टाइप पैरामीटर `a` का उपयोग करता है।

```elm
length : List a -> Int
```

## टाइप में पैरामीटर

जब कोई टाइप किसी दूसरे टाइप के ऊपर जेनेरिक होता है, तो उस दूसरे टाइप के लिए हम छोटे अक्षरों वाला नाम इस्तेमाल करते हैं और उसे टाइप पैरामीटर कहते हैं।
आम उदाहरण `List`, `Maybe` और `Result` कस्टम टाइप हैं।

```elm
-- Maybe is generic over the type a
type Maybe a
    = Nothing
    | Just a

someString : Maybe String
someString = Just "hello"

someInt : Maybe Int
someInt = Just 42
```

टाइप पैरामीटरों के नामों के बारे में एक ज़रूरी बात यह है कि वे एक से ज़्यादा अक्षरों के हो सकते हैं।
बस एक शर्त है कि वे छोटे अक्षरों वाले नाम होने चाहिए।
इसलिए जहाँ यह फायदेमंद लगता है, वहाँ हम उन्हें विवरणात्मक नाम देते हैं।

एक टाइप कई दूसरे टाइपों के ऊपर जेनेरिक हो सकता है, और इस तरह उसके कई टाइप पैरामीटर हो सकते हैं।
ऐसी स्थिति में हर स्वतंत्र टाइप को अलग छोटे अक्षरों वाला नाम मिलता है।
स्वतंत्र होने का मतलब यह नहीं है कि वे एक ही टाइप नहीं बन सकते, इससे बस इतना संभव होता है कि वे अलग-अलग हो सकें।

```elm
-- Result is generic over the types error and value
type Result error value
    = Ok value
    | Err error
```

रिकॉर्ड टाइप एलियस में भी टाइप पैरामीटर हो सकते हैं, हालाँकि यह कम आम है।

```elm
-- Event is generic over the type a
type alias Event a =
    { at : Time
    , data : a 
    }
```

> इसीलिए `Html` पैकेज `Html msg` टाइप परिभाषित करता है, जिसमें `msg` नाम का एक टाइप पैरामीटर होता है।
> Elm आर्किटेक्चर आपको एक कस्टम टाइप `Msg` बनाने की राह दिखाता है, जो उन सभी संदेशों का वर्णन करता है जो आपका वेब पेज चला सकता है।
> इसके परिणामस्वरूप आपका कोड `Html Msg` टाइप के व्यू बनाता है, जहाँ `Msg` वह ठोस टाइप है जिसे आपने परिभाषित किया है।
> शुरुआत करने वाले कभी-कभी `Html msg` (छोटे अक्षर वाले) का उल्लेख करने वाली एरर और `Html Msg` वाली एरर में उलझ जाते हैं।
> अब आप जान गए!
> फर्क यह है कि पहला किसी भी `msg` टाइप के ऊपर जेनेरिक है, जबकि दूसरा आपके `Msg` टाइप के लिए खास है।

## फंक्शन में टाइप पैरामीटर

चूँकि टाइप जेनेरिक हो सकते हैं, इसलिए फंक्शन भी हो सकते हैं।
जेनेरिक टाइपों से काम करने वाले फंक्शन लिखे जा सकते हैं, जैसे `Maybe.withDefault`।

```elm
withDefault : a -> Maybe a -> a
withDefault default maybe =
    case maybe of
      Just value -> value
      Nothing -> default
```

जो फंक्शन दूसरे फंक्शनों को पैरामीटर के रूप में लेते हैं, उन्हें हायर ऑर्डर फंक्शन कहते हैं, और ये भी जेनेरिक हो सकते हैं।

```elm
map : (a -> b) -> Maybe a -> Maybe b
map function maybe =
  case maybe of
    Just value ->
      Just (function value)

    Nothing ->
      Nothing
```

टाइप पैरामीटर किसी फंक्शन के इनपुट और आउटपुट, दोनों में आ सकते हैं, और टाइप पैरामीटरों से मिलने वाली जेनेरिकता को आम तौर पर **पैरामेट्रिक पॉलिमोर्फिज़्म** कहा जाता है।
इसके उलट एड हॉक पॉलिमोर्फिज़्म है, जिसे फंक्शन ओवरलोडिंग भी कहते हैं, जहाँ एक ही फंक्शन नाम का उपयोग अलग-अलग टाइपों वाले कई इम्प्लीमेंटेशन पर किया जा सकता है।
यह सबटाइप पॉलिमोर्फिज़्म से भी अलग है, जहाँ टाइपों को एक पदानुक्रम में परिभाषित किया जा सकता है, और किसी टाइप पर परिभाषित फंक्शन को उसके सबटाइप के आर्गुमेंट के साथ भी कॉल किया जा सकता है।
Elm में जेनेरिकता के लिए उपलब्ध एकमात्र तरीका पैरामेट्रिक पॉलिमोर्फिज़्म है।
