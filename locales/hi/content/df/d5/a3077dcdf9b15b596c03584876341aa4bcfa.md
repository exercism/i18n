# परिचय

Factor का लगभग हर प्रोग्राम शब्दों का एक क्रम होता है। ये शब्द *डेटा स्टैक* से वैल्यू लेते हैं और उस पर वैल्यू बनाते हैं। जब इनपुट और आउटपुट ठीक से मेल खाते हैं, तो कोड बिना किसी अड़चन के बाएँ से दाएँ पढ़ा जा सकता है। जब मेल नहीं खाते, तो आप *शफल शब्दों* का सहारा लेते हैं, और कोड जल्दी ही उलझा हुआ लगने लगता है।

यह अभ्यास आपको Factor के मानक हल से परिचित कराता है: कॉम्बिनेटर।

## शफल शब्द

सबसे आम शफल शब्द [`kernel`][kernel] में रहते हैं:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

आप `dup` और `swap` तो पहले ही इस्तेमाल कर चुके हैं। `over` ऊपर से *दूसरे* एलिमेंट की एक कॉपी बनाता है। यह तब काम आता है जब एक ही इनपुट को दो गणनाओं में देना हो:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

एक बार के इस्तेमाल के लिए यह ठीक है। लेकिन जब `dup`, `swap`, `over`, `rot` एक के बाद एक जुड़ते चले जाते हैं, तो ऐसा सिलसिला जल्दी ही पढ़ने लायक नहीं रह जाता।

## `keep`: इनपुट को सुरक्षित रखना

`keep` ([`kernel`][kernel] में) स्टैक के ऊपर वाली वैल्यू पर एक कोटेशन कॉल करता है, लेकिन मूल वैल्यू को नतीजे के ऊपर बनाए रखता है:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

यह `dup` के बाद कुछ और, फिर शफल, वाले तरीके की जगह लेता है: जहाँ आप `dup something swap` लिखते, वहाँ आप सीधे `[ something ] keep` लिख सकते हैं।

## `bi`: एक इनपुट पर दो फंक्शन

`bi` ([`kernel`][kernel] में) एक ही वैल्यू पर *दो* कोटेशन लगाता है और दोनों नतीजे स्टैक पर छोड़ देता है:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

`bi` के बिना आप `dup sq swap neg` लिखते। दो ऑपरेशन के लिए यह अभी पढ़ा जा सकता है, लेकिन तीन के लिए उलझा हुआ हो जाता है।

## `tri` और `cleave`: एक इनपुट पर कई फंक्शन

`tri`, `bi` को बढ़ाकर तीन कोटेशन तक ले जाता है:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

`cleave` ([`combinators`][combinators] में) यही बात है, लेकिन किसी भी संख्या के कोटेशनों के *ऐरे* के लिए:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

खाली कोटेशन `[ ]` आइडेंटिटी का काम करता है। यह तब काम आता है जब कोटेशनों की सूची के किसी स्थान पर खुद इनपुट ही होना चाहिए।

## `dip` और `2dip`: नीचे की वैल्यूओं पर काम करना

`dip` ([`kernel`][kernel] में) स्टैक के ऊपर वाली वैल्यू के *नीचे* की वैल्यूओं पर एक कोटेशन कॉल करता है और ऊपर वाली वैल्यू को वैसी ही रहने देता है। `2dip` भी यही करता है, लेकिन यह ऊपर की *दो* वैल्यूओं को सुरक्षित रखता है:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

यहाँ `dip` ने `11` को छिपाया, `9 10 +` चलाया, और `11` को वापस ऊपर रख दिया। `2dip` ने `11 12` छिपाए, उनके नीचे `9 10 +` चलाया, और फिर `11 12` को बहाल कर दिया।

जब आर्गुमेंट का स्वाभाविक क्रम "पास-थ्रू" वैल्यू को स्टैक के ऊपर छोड़ देता है, तब `dip` सही टूल है। `swap … swap` वाले सैंडविच की जगह इसी का इस्तेमाल कीजिए।

## `bi@`: दो वैल्यूओं पर एक ही ऑपरेशन

`bi@` ([`kernel`][kernel] में) दो स्टैक वैल्यूओं पर एक कोटेशन लगाता है:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*`: दो वैल्यूओं पर अलग-अलग ऑपरेशन

`bi*` ([`kernel`][kernel] में) दो स्टैक वैल्यूओं पर *अलग-अलग* कोटेशन लगाता है। पहला कोटेशन नीचे वाली वैल्यू पर, और दूसरा ऊपर वाली वैल्यू पर:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

जब दोनों वैल्यूओं के साथ एक ही बर्ताव करना हो तो `bi@` का इस्तेमाल कीजिए, और जब हर एक को अपना अलग बर्ताव चाहिए तो `bi*` का।

## `tri*`: तीन वैल्यूओं पर अलग-अलग ऑपरेशन

`tri*` ([`combinators`][combinators] में) `bi*` को बढ़ाकर तीन वैल्यूओं और तीन कोटेशनों तक ले जाता है, और हर कोटेशन को बारी-बारी से एक-एक वैल्यू पर लगाता है:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
