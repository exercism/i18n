# एक्सेप्शन

आदर्श दुनिया में सब कुछ बिल्कुल ठीक चलता है।
लेकिन वास्तविक दुनिया में चीज़ें गड़बड़ा सकती हैं, और ऐसी स्थितियों को हम कैसे संभालते हैं, यह इस बात के लिए मायने रखता है कि हमारा सॉफ्टवेयर मज़बूत और भरोसेमंद बना रहे।
एक्सेप्शन प्रोग्रामिंग की एक बहुत ज़रूरी अवधारणा है, जिसकी मदद से हम एरर और अप्रत्याशित स्थितियों को सहजता से संभाल सकते हैं।

एरर उठाने पर, अगर उसे संभाला न जाए, तो प्रोग्राम रुक जाता है और एक एरर संदेश दिखाता है।
ज़्यादातर मामलों में आप नहीं चाहते कि एरर आने पर आपका प्रोग्राम रुक जाए; आप चाहते हैं कि एरर को संभालकर प्रोग्राम चलता रहे।

## एक्सेप्शन उठाना

Crystal में एक्सेप्शन `raise` कीवर्ड की मदद से उठाए जाते हैं, और उन्हें या तो कोई `String` या कोई `Exception` ऑब्जेक्ट दिया जा सकता है।
अगर उसे संभाला न जाए, तो प्रोग्राम रुक जाएगा और एरर संदेश छाप देगा।

```crystal
raise "This is an error"
```

Crystal में कई बिल्ट-इन एक्सेप्शन मौजूद हैं, जैसे `ArgumentError`, `IndexError`, `KeyError`, `IOError`, `SystemCallError`, `TypeError`, `ZeroDivisionError` और भी बहुत से।
इनमें आपको एक्सेप्शन को एक संदेश देना पड़ता है।

```crystal
raise ArgumentError.new("This is an argument error")
```

## [एक्सेप्शन संभालना][exception-handling]

हम नहीं चाहेंगे कि एक्सेप्शन उठने पर हमारा प्रोग्राम क्रैश हो जाए।
इसलिए, जब हमें पता हो कि कोड के किसी हिस्से में एरर की गुंजाइश है, तो हम उसे एक `begin` ब्लॉक में लपेट सकते हैं और `rescue` ब्लॉक की मदद से उस एक्सेप्शन को संभाल सकते हैं।
`begin` ब्लॉक उस कोड की शुरुआत बताता है जिसमें एक्सेप्शन उठ सकता है, और `rescue` ब्लॉक उस एक्सेप्शन को संभालता है।

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
end
```

`rescue` ब्लॉक के साथ एक वेरिएबल भी दे सकते हैं, जिससे एक्सेप्शन ऑब्जेक्ट मिल जाता है।

```crystal
begin
 raise "This is an error"
rescue ex
 puts "An error occurred: #{ex.message}"
end
```

`rescue` ब्लॉक के साथ कोई खास एक्सेप्शन टाइप भी दे सकते हैं, ताकि सिर्फ वही एक्सेप्शन पकड़ा जाए।

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
end

# or

begin
 raise ArgumentError.new("This is an argument error")
rescue ex : ArgumentError
 puts "An argument error occurred: #{ex.message}"
end
```

अलग-अलग तरह के एक्सेप्शन संभालने के लिए कई `rescue` ब्लॉक इस्तेमाल कर सकते हैं।
नीचे के उदाहरण में पहला `rescue` ब्लॉक `ArgumentError` पकड़ेगा, और दूसरा `rescue` ब्लॉक बाकी किसी भी एक्सेप्शन को पकड़ेगा।

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
rescue
 puts "An error occurred!"
end
```

`begin` ब्लॉक के साथ एक `else` ब्लॉक भी हो सकता है, जो तब चलता है जब कोई एक्सेप्शन न उठे।

```crystal
begin
 puts "No error occurred"
rescue
 puts "An error occurred!"
else
 puts "No error occurred"
end
```

अंत में एक `ensure` ब्लॉक होता है, जो हमेशा चलता है, चाहे एक्सेप्शन उठा हो या नहीं।

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
ensure
 puts "This is always executed"
end
```

## मेथड कन्वेंशन

कुछ मेथड के दो वर्शन होते हैं, एक `!` के साथ और दूसरा उसके बिना।
इसका मतलब दो अलग-अलग चीज़ें हो सकता है।
एक यह कि मेथड ऑब्जेक्ट को बदल देता है, और दूसरा यह कि मेथड एक्सेप्शन उठा सकता है।

लेकिन बूलियन कॉन्सेप्ट में बताया गया एक और कन्वेंशन भी है, जो मेथड के नाम के अंत में `?` लगाने से जुड़ा है।
कुछ मेथड डिफॉल्ट रूप से एक्सेप्शन उठाते हैं, लेकिन उनका `?` पर खत्म होने वाला एक वर्शन भी होता है, जो एक्सेप्शन उठाने की जगह `nil` लौटाता है।

यह तब बहुत काम का है जब आप नहीं चाहते कि कोई एरर उठे।
इससे कार्यक्षमता को फायदा हो सकता है, क्योंकि स्टैकट्रेस बनाने की ज़रूरत नहीं पड़ती, और सही तरीके से इस्तेमाल करने पर यह कोड को ज़्यादा सुरक्षित भी बना सकता है।

## कस्टम एक्सेप्शन

आप [`Exception`][exception] क्लास से इनहेरिट करके अपने खुद के एक्सेप्शन भी बना सकते हैं।
ऐसा करते समय आप चाहें तो `initialize` मेथड को ओवरराइड करके एक्सेप्शन का संदेश तय कर सकते हैं।
इसके लिए `@message` नाम के इंस्टेंस वेरिएबल को वह संदेश असाइन किया जाता है।

```crystal
class MyException < Exception
 def initialize
   @message = "This is my exception"
 end
end

raise MyException.new
```

[exception-handling]: https://crystal-lang.org/reference/syntax_and_semantics/exception_handling.html
[exception]: https://crystal-lang.org/api/Exception.html
