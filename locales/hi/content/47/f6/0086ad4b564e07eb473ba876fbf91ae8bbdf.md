# परिचय

फंक्शन पहले [मूल बातें][concept-basics] कॉन्सेप्ट में पेश किए गए थे, जिसमें इस तरह के उदाहरण थे:

```R
squareit <- function(x) {
    x * x
}

squareit(3)
#> [1] 9

# shorter form
squareit_short <- function(x) x ^ 2
```

`squareit` की परिभाषा को ध्यान से देखें तो हमें इसके अलग-अलग हिस्से पहचानने को मिलते हैं:

- यह फंक्शन एक औपचारिक आर्गुमेंट `x` लेता है।
- इसकी एक फंक्शन बॉडी होती है, जो आमतौर पर ब्रेस `{ }` में होती है।
- फंक्शन ऑब्जेक्ट बन जाने के बाद उसे वेरिएबल `squareit` में असाइन किया जाता है।

R में फंक्शन एक फर्स्ट-क्लास ऑब्जेक्ट है, बिल्कुल संख्याओं और स्ट्रिंग की तरह।
इसलिए, `squareit <- function...` एक असाइनमेंट है, जो सिंटैक्स की दृष्टि से बिल्कुल `x <- 42` जैसा है।

## आर्गुमेंट

Python और Julia जैसी दूसरी स्क्रिप्टिंग भाषाओं के उलट, R पोज़िशनल आर्गुमेंट और कीवर्ड आर्गुमेंट के बीच कोई साफ अंतर नहीं करता।

फंक्शन कॉल में वैल्यू या तो पोज़िशन से पास की जा सकती है या नाम से।
नाम से पास करना उन जटिल फंक्शन के लिए उपयोगी है जिनमें कई आर्गुमेंट होते हैं और उनका क्रम याद रखना मुश्किल होता है।

```R
f <- function(x, y) x / y

# call positionally
f(4, 2)
#> [1] 2

# call by name
f(y = 2, x = 4)
#> [1] 2
```

### वैकल्पिक आर्गुमेंट

फंक्शन की परिभाषा में आर्गुमेंट की डिफॉल्ट वैल्यू दी जा सकती है, लेकिन वे उन सभी आर्गुमेंट के बाद आनी चाहिए जिनकी कोई डिफॉल्ट वैल्यू नहीं है।

फिर हम चुन सकते हैं कि डिफॉल्ट को स्वीकार करें या उसके बजाय अपनी वैल्यू दें।

```R
g <- function(x, y = 2) x / y

# default y value
g(6)
#> [1] 3

# explicit y value
g(6, 3)
#> [1] 2
```

### अतिरिक्त आर्गुमेंट

किसी भी संख्या में अतिरिक्त आर्गुमेंट लेने के लिए परिभाषा में `...` (इलिप्सिस) का इस्तेमाल कीजिए।
फंक्शन कॉल में मिली अतिरिक्त वैल्यू को वेक्टर में बदलना संभव है, लेकिन इन "डॉट आर्ग्स" को इस्तेमाल करने का दूसरा तरीका जानने के लिए आगे पढ़िए (*कई दूसरी भाषाओं में इन्हें "वरआर्ग्स" कहा जाता है*)।

```R
var_f <- function(x, y, ...) {
  print(c(...))
}

var_f(2, 3, "opt1", "opt2")
#> [1] "opt1" "opt2"
```

## फंक्शन का वातावरण

पहले हमने कहा था कि औपचारिक आर्गुमेंट और बॉडी दोनों फंक्शन के हिस्से होते हैं।

वास्तव में, एक तीसरा हिस्सा भी होता है: वह *वातावरण* जिसमें फंक्शन परिभाषित किया जाता है।

इसे नेस्टेड फंक्शन के उदाहरण से समझा जा सकता है:

```R
outer_func <- function(x) {
  inner_func <- function(y) {
    x * y
  }
  
  inner_func(3)
}

outer_func(5)
#> [1] 15
```

फंक्शन कॉल बाहरी फंक्शन को `x = 5` पास करती है, और यह वैल्यू उस फंक्शन बॉडी के अंदर उपलब्ध रहती है।

भीतरी फंक्शन बाहरी फंक्शन बॉडी का *हिस्सा* होता है, और उसके पास `x` की वैल्यू तक पहुँच होती है।
दूसरे शब्दों में, `x = 5` भीतरी फंक्शन के *वातावरण* में है।

तकनीकी रूप से इसे [क्लोज़र][wiki-closure] कहा जाता है।

वातावरण खास तौर पर डॉट आर्ग्स के साथ ज़रूरी होता है, क्योंकि इस तरह दी गई कोई भी वैल्यू फंक्शन बॉडी में फंक्शन कॉल तक पास की जा सकती है।
बाहरी फंक्शन को यह जानने या परवाह करने की ज़रूरत नहीं होती कि डॉट आर्ग्स का मतलब क्या है।

```R
f_var <- function(x, ...) {
  sum(x, ...)
}

x <- c(1, 2, NA, 6)

# for sum(), na.rm defaults to FALSE
f_var(x)
#> [1] NA

# pass through the na.rm value
f_var(x, na.rm = TRUE)
#> [1] 9
```

यह तरीका Tidyverse की [`stringr`][ref-stringr] जैसी लाइब्रेरी में बहुत इस्तेमाल होता है।
`stringr` के कई फंक्शन `stringi` और base R के लो-लेवल फंक्शन के ऊपर एक यूज़र-फ्रेंडली रैपर होते हैं।

`str_*()` फंक्शन को दिए गए अतिरिक्त आर्गुमेंट सीधे उन निचले स्तर के फंक्शन तक पास कर दिए जाते हैं।

## रिटर्न वैल्यू के रूप में फंक्शन

कोई बाहरी फंक्शन एक भीतरी फंक्शन बना सकता है (चाहे उसका नाम हो, या वह नीचे बताए गए अनुसार अनाम हो) और उसे रिटर्न वैल्यू के रूप में इस्तेमाल कर सकता है।

जो फंक्शन लौटाया जाता है, उसमें वह वातावरण भी शामिल रहता है जिसमें उसे परिभाषित किया गया था।

```R
times_y <- function(x) {
  # anonymous function - see next section
  \(y) x * y
}

f <- times_y(3)
class(f)
#> [1] "function"

f(4)
#> [1] 12
```

## अनाम फंक्शन

जब हम कोई फंक्शन बनाते हैं, तो आमतौर पर बने फंक्शन ऑब्जेक्ट को किसी वेरिएबल से बाँध देते हैं:

```R
x <- 2

# function definition captures x from the environment
doubleit_short <- function(y) x * y
```

इससे स्क्रिप्ट में बाद में उस फंक्शन का इस्तेमाल करना आसान हो जाता है, लेकिन ऐसा बाँधना ज़रूरी नहीं है।
एक छोटा, एक बार इस्तेमाल होने वाला फंक्शन उसी जगह काम आ सकता है।
नाम से बाँधे बिना इसे *अनाम फंक्शन* कहा जाता है।

अनाम फंक्शन का इस्तेमाल इतना आम है कि (*R v4.1.0 से*) इन्हें बनाने के लिए एक शॉर्टहैंड सिंटैक्स मौजूद है: `function` शब्द की जगह बैकस्लैश `\` लिखिए।

इसका एक उदाहरण पिछले हिस्से में, रिटर्न वैल्यू पर दिया गया था।

## बदलने पर कॉपी

R किसी वेक्टर के अलग-अलग एलिमेंट को असाइन करने की अनुमति देता है।
अगर हम किसी फंक्शन आर्गुमेंट के रूप में एक वेक्टर देते हैं और उसे लौटाने से पहले फंक्शन बॉडी में बदल देते हैं, तो हमें बदला हुआ वेक्टर मिलता है।

लेकिन मूल वेक्टर का क्या हुआ?

```R
f <- function(vec) {
  vec[1] <- 42
  vec
}

vals <- c(1, 3, 4)

# f() returns a modified vector
f(vals)
#> [1] 42  3  4  

# the original vector is unchanged.
vals
#> [1] 1 3 4
```

R डेटा साइंस के लिए बनाई गई भाषा है।
उस डेटा को इकट्ठा करने में बहुत समय, मेहनत और शायद चौंका देने वाली रकम लग सकती है: *इसे खराब होने से बचाना ज़रूरी है!*

सामान्य नीति (कुछ अपवादों के साथ) *बदलने पर कॉपी* है।
अगर कोई ऑब्जेक्ट (जैसे कोई वेक्टर) इस तरह बदला जाता है कि बाद में समस्या हो सकती है, तो R एक *बदली हुई कॉपी* लौटाता है और मूल को अछूता छोड़ देता है।

बड़े डेटा स्ट्रक्चर की कॉपी बनाना कंप्यूटेशनल रूप से महँगा हो सकता है, लेकिन जब दूसरा विकल्प डेटा के खराब होने का हो, तो आमतौर पर यह कम बुरा है।

~~~~exercism/caution
उन ऑपरेशन से सावधान रहिए जिनकी वजह से एक ही डेटा की बार-बार कॉपी बनती है।

(Tidyverse के लेखक) Hadley Wickham के कहे को दूसरे शब्दों में:

> लूप अपने आप में धीमे नहीं होते, लेकिन वे लूप के अंदर धीमे ऑपरेशन डालना खतरनाक तरीके से आसान बना देते हैं।

वेक्टराइज़ेशन या हायर-ऑर्डर फंक्शन आपको परफॉर्मेंस बर्बाद करने वाली इस चीज़ से बचाने में मदद कर सकते हैं।
