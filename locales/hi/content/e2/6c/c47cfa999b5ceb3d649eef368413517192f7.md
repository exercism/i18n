# बिट्स के बारे में

बाइनरी अंक अंततः आपके CPU या RAM के ट्रांजिस्टरों से सीधे जुड़े होते हैं: हर ट्रांजिस्टर या तो "चालू" होता है या "बंद"।

निम्न-स्तरीय हेर-फेर, जिसे अनौपचारिक रूप से "बिट-ट्विडलिंग" कहा जाता है, सिस्टम भाषाओं में खास तौर पर ज़रूरी होता है।

Kotlin जैसी उच्च-स्तरीय भाषाएँ आमतौर पर इनमें से ज़्यादातर विवरण छिपा देती हैं।
फिर भी, बिट-स्तर के कुछ बुनियादी ऑपरेशन [उपलब्ध हैं][ref-bitwise]।

~~~~exercism/note
मनुष्य के पढ़ने लायक बाइनरी आउटपुट देखने के लिए, नीचे दिए गए लगभग सभी उदाहरणों को [`Integer.toBinaryString()`][web-binstring] फंक्शन में लपेटना पड़ता है, या `toString(radix = 2)` से बदलना पड़ता है।
 
यह देखने में ध्यान भटकाता है, इसलिए इस फंक्शन को ज़्यादातर जगहों से हटा दिया गया है, और परिणाम `0b` संकेतन में दिखाए गए हैं।

[web-binstring]: https://www.baeldung.com/kotlin/int-binary-representation
~~~~

## बिट-शिफ्ट ऑपरेशन

`Int` या `Long` टाइप, साइन्ड हों या अनसाइन्ड, को 1 और 0 की स्ट्रिंग के रूप में दिखाया जा सकता है और बिट्स के क्रम की तरह उस पर काम किया जा सकता है।

शायद हैरानी की बात है कि Kotlin में `Byte` या `Short` टाइप ज़्यादातर बिटवाइज़ ऑपरेशनों के साथ काम नहीं करते।
नीचे दिए गए सभी उदाहरण 32-बिट पूर्णांक (`Int` या `UInt`) इस्तेमाल करते हैं।

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

बिट-शिफ्ट किसी तय संख्या में स्थानों तक सब कुछ बाएँ या दाएँ खिसका देते हैं।
कुछ बिट्स एक सिरे से गिर जाते हैं, और दूसरे सिरे को शून्यों या इकाइयों से भर दिया जाता है।

- `shl` से बाएँ शिफ्ट: शून्यों से भरना।
- `shr` या `ushr` से दाएँ शिफ्ट: धनात्मक संख्याओं के लिए शून्यों से भरना (ऋणात्मक संख्याओं के लिए आगे का भाग देखिए)।

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

हर बाईं शिफ्ट वैल्यू को दोगुना कर देती है, और हर दाईं शिफ्ट उसे आधा कर देती है (दशमलव भाग काटकर)।
यह दशमलव रूप में और साफ़ दिखता है:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

ऐसी बिट-शिफ्टिंग "पक्के" अंकगणित से कहीं ज़्यादा तेज़ होती है, इसीलिए यह तरीका निम्न-स्तरीय कोडिंग में बहुत लोकप्रिय है।

### ऋणात्मक पूर्णांकों को बिट-शिफ्ट करना

_ऋणात्मक पूर्णांकों_ के साथ हमें थोड़ा ज़्यादा सावधान रहना पड़ता है।

ऋणात्मक वैल्यू [टू कॉम्प्लिमेंट][wiki-2complement] रूप में संग्रहीत की जाती हैं, यानी सबसे बाईं ओर वाला बिट 1 होता है।
बाईं शिफ्ट में कोई दिक्कत नहीं, लेकिन दाईं शिफ्ट करते समय हम सबसे बाईं ओर के बिट्स को कैसे भरें?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

[`shr`][ref-shr] ऑपरेटर [अंकगणितीय शिफ्ट][wiki-arithmetic] करता है, जो साइन बिट को सुरक्षित रखती है।

[`ushr`][ref-ushr] ऑपरेटर [तार्किक शिफ्ट][wiki-logical] करता है, और शून्यों से भर देता है, जैसे संख्या अनसाइन्ड हो।

## बिटवाइज़ लॉजिक

[बूलियन कॉन्सेप्ट][concept-booleans] में हमने देखा था कि ऑपरेटर `&&` (and), `||` (or) और `!` (not) बूलियन वैल्यू के साथ इस्तेमाल होते हैं।

दो पूर्णांकों के बिट्स की तुलना करने के लिए इसी तरह के ऑपरेटर `and`, `or`, `xor` ([एक्सक्लूसिव-ओर][wiki-xor]) हैं, और सारे बिट्स उलटने के लिए एक `inv` (इनवर्ज़न) फंक्शन है।

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
