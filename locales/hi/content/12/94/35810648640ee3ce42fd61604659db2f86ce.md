# परिचय

Elixir में सभी एरर _एक्सेप्शन बिहेवियर_ को लागू करती हैं। ठीक _एक्सेस बिहेवियर_ की तरह, _एक्सेप्शन बिहेवियर_ भी ऐसे कॉलबैक फंक्शन तय करता है जिन्हें किसी मॉड्यूल को बिहेवियर के सॉफ्टवेयर कॉन्ट्रैक्ट को पूरा करने के लिए लागू करना पड़ता है। एरर परिभाषित हो जाने के बाद उसमें ये विशेषताएँ होती हैं:

- मॉड्यूल का नाम ही एरर का नाम तय करता है।
- मॉड्यूल एक एरर-स्ट्रक्ट परिभाषित करता है।
- इस स्ट्रक्ट में एक `:message` फील्ड होगा।
- मॉड्यूल को `raise/1` और `raise/2` के साथ इस्तेमाल करके इच्छित एरर उठाई जा सकती है।

_एक्सेप्शन बिहेवियर_ दो कॉलबैक भी तय करता है: `message/1` और `exception/1`। अगर इन्हें लागू न किया जाए, तो डिफ़ॉल्ट इम्प्लीमेंटेशन ही इस्तेमाल होते हैं। जब `message/1` को `raise` के साथ कॉल किया जाता है, तो यह एरर-स्ट्रक्ट को एक पढ़ने योग्य संदेश में बदल देता है। और जब `exception/1` को `raise/2` के साथ कॉल किया जाता है, तो इसकी मदद से संदेश में अतिरिक्त संदर्भ भी जोड़ा जा सकता है।

## एक्सेप्शन परिभाषित करना

किसी एरर मॉड्यूल से एक्सेप्शन बनाने के लिए हम `defexception` मैक्रो इस्तेमाल करते हैं:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

## एक्सेप्शन का उपयोग करना

परिभाषित एरर को पहले से मौजूद किसी एरर की तरह `raise/1` या `raise/2` की मदद से उठाया जा सकता है।

- `raise/1` किसी विशेष एरर को उसके मॉड्यूल नाम से उठाता है। अगर आर्गुमेंट एक स्ट्रिंग है, तो यह उस स्ट्रिंग को संदेश बनाकर `RuntimeError` उठाता है।
- `raise/2` किसी विशेष एरर को उसके मॉड्यूल नाम से उठाता है और एक एट्रिब्यूट्स आर्गुमेंट लेता है, जिससे उचित संदेश वाली एरर मिलती है।
