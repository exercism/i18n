# परिचय

एक *डेक* (double-ended queue, यानी दोनों सिरों वाली क्यू) दोनों सिरों पर पुश और पॉप, दोनों को O(1) में कर सकता है। Factor का मानक कार्यान्वयन [`dlists`][dlists] में `<dlist>` है (एक डबल-लिंक्ड लिस्ट)। ऑपरेशन [`deques`][deques] में मौजूद हैं।

## डेक API

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` डेक को उसी जगह खाली कर देता है। यह बिना दोबारा मेमोरी लिए उसे दोबारा इस्तेमाल करने में काम आता है।

एक ही सिरे पर पुश और पॉप करने से आपको LIFO स्टैक मिलता है। एक सिरे पर पुश और दूसरे सिरे पर पॉप करने से आपको FIFO क्यू मिलती है:

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

LIFO के लिए आप `V{ }` वेक्टर लेंगे और उसके `push`/`pop` इस्तेमाल करेंगे, जिसमें हर ऑपरेशन का खर्च कम होता है। जब आपको *दोनों* सिरों पर O(1) चाहिए, तब `<dlist>` चुनिए, और ऐसा लगभग हमेशा FIFO क्यू के लिए ही होता है।

## चौड़ाई-पहले खोज

FIFO वाला उपयोग ही डेक को *BFS* के लिए सही फ्रंटियर बनाता है। आप एक अकेले नोड से शुरू करते हैं, पड़ोसियों को पीछे पुश करते हैं, उम्मीदवारों को आगे से पॉप करते हैं, और हैश-सेट से डुप्लीकेट हटाते हैं:

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

पुराने उम्मीदवार नए उम्मीदवारों से पहले देखे जाते हैं, इसलिए खोज शुरू से परतों में बाहर की ओर फैलती जाती है। यही BFS को सबसे छोटे रास्ते वाला गुण देता है: किसी लक्ष्य नोड तक आप पहली बार सबसे कम कदमों वाले रास्ते से पहुँचते हैं।

## `MEMO:` से अपने आप कैशिंग

कभी-कभी BFS जो हर नोड के लिए लुकअप करती है, वह महँगा पड़ता है। Factor का [`memoize`][memoize] वोकैब आपको `MEMO:` देता है, जिसे `:` की जगह सीधे लगाया जा सकता है और जो वर्ड के नतीजे को उसके इनपुट के आधार पर कैश कर लेता है:

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

एक `MEMO:` वर्ड हर इनपुट को पहली बार देखे जाने पर अपनी बॉडी चलाता है और उसके बाद कैश किया हुआ नतीजा लौटा देता है। इंटरफ़ेस वही रहता है, कॉल करने की जगह पर कोई अतिरिक्त कॉल नहीं करनी पड़ती, बस दोहराव पर यह ज़्यादा तेज़ हो जाता है।
