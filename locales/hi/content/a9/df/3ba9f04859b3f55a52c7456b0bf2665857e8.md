# निर्देश

आप _Instruments of Texas_ में अपना काम जारी रख रहे हैं। इस बीच RPN कैल्कुलेटर को Elixir में बनाने का काम भी आगे बढ़ रहा है। आपकी टीम ऐसे एरर उठाना चाहती है जो स्टैंडर्ड लाइब्रेरी के दिए गए सामान्य एरर से ज़्यादा विशिष्ट हों। आप कुछ शोध कर रहे हैं, लेकिन आपने दो नए एरर बनाने का फैसला किया है, जो _एक्सेप्शन बिहेवियर_ लागू करते हैं।

## 1. शून्य से भाग देने पर एरर

किसी संख्या को शून्य से भाग देने पर एक अपरिभाषित परिणाम मिलता है। टीम तय करती है कि इसे एरर के रूप में दिखाना ही सबसे अच्छा है।

`DivisionByZeroError` मॉड्यूल बनाइए, ताकि उसका एरर संदेश यह हो: `"division by zero occurred"`

```elixir
raise DivisionByZeroError
# => ** (DivisionByZeroError) division by zero occurred
```

## 2. स्टैक अंडरफ्लो मिलने पर एरर

RPN कैल्कुलेटर संख्याओं को जोड़ने से पहले उनका हिसाब रखने के लिए एक _स्टैक_ का उपयोग करते हैं। टीम इस _स्टैक_ को संख्याओं के एक ऐरे से दिखाती है (पूर्णांक और दशमलव संख्या), जैसे: `[3, 4.0]`। हर ऑपरेशन को अपनी गणना करने के लिए स्टैक पर एक निश्चित संख्या में संख्याएँ चाहिए। जब स्टैक पर पर्याप्त संख्याएँ नहीं होतीं, तो इसे स्टैक अंडरफ्लो एरर कहते हैं। `StackUnderflowError` एक्सेप्शन बनाइए, जो एक डिफाल्ट संदेश और वैकल्पिक अतिरिक्त संदर्भ देता है

```elixir
raise StackUnderflowError
# => ** (StackUnderflowError) stack underflow occurred

raise StackUnderflowError, "when dividing"
# => ** (StackUnderflowError) stack underflow occurred, context: when dividing
```

## 3. भाग देने वाला फंक्शन लिखिए

`divide/1` फंक्शन बनाइए, जो एक स्टैक _(दो संख्याओं का ऐरे)_ लेता है और:

- जब स्टैक में पर्याप्त संख्याएँ न हों, तो _स्टैक अंडरफ्लो_ एरर उठाता है
- जब भाजक 0 हो, तो _शून्य से भाग_ एरर उठाता है (ध्यान दें कि संख्याओं का स्टैक उलटे क्रम में संग्रहीत होता है)
- जब कोई एरर न उठे, तो भाग देता है

```elixir
RPNCalculator.Exception.divide([])
# => ** (StackUnderflowError) stack underflow occurred, context: when dividing

RPNCalculator.Exception.divide([0, 100])
# => ** (DivisionByZeroError) division by zero occurred

RPNCalculator.Exception.divide([4, 16])
# => 4
```

> ध्यान दें कि ऐरे का क्रम उलटा है!
