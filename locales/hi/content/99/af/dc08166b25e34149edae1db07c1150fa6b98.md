# परिचय

बाकी कई भाषाओं की तरह Go में भी पॉइंटर होते हैं।
अगर आप पॉइंटर के लिए नए हैं, तो शुरुआत में ये थोड़े रहस्यमय लग सकते हैं, लेकिन एक बार इनकी आदत पड़ जाने पर ये काफी सीधे-सरल लगते हैं।
ये Go का बहुत ज़रूरी हिस्सा हैं, इसलिए इन्हें ठीक से समझने के लिए थोड़ा समय ज़रूर दीजिए।

बारीकियों में उतरने से पहले यह समझ लेना फायदेमंद है कि पॉइंटर काम किस तरह आते हैं।
पॉइंटर हमारे प्रोग्राम के दूसरे हिस्सों के साथ मेमोरी साझा करने का तरीका हैं, और यह दो बड़े कारणों से काम आता है:

1. जब हमारे पास बहुत सारा डेटा होता है, तो उसे फंक्शन के बीच पास करने के लिए हर बार कॉपी बनाना बहुत कम कुशल होता है।
   इसके बजाय उस जगह का मेमोरी लोकेशन पास करके, जहाँ डेटा संग्रहीत है, हम अपने प्रोग्राम की संसाधन-खपत बहुत कम कर सकते हैं।
2. फंक्शन के बीच पॉइंटर पास करके हम डेटा की उसी एक कॉपी तक सीधे पहुँच सकते हैं और उसे बदल सकते हैं। इसका मतलब है कि किसी एक फंक्शन द्वारा किए गए बदलाव फंक्शन खत्म होते ही प्रोग्राम के बाकी हिस्सों को तुरंत दिख जाते हैं।

## वेरिएबल और मेमोरी

मान लीजिए हमारे पास एक साधारण पूर्णांक वेरिएबल `a` है:

```go
var a int
```

जब हम कोई वेरिएबल घोषित करते हैं, तो Go को उसकी वैल्यू रखने के लिए मेमोरी में जगह ढूँढनी पड़ती है।
यह बात हमसे काफी हद तक छिपी रहती है। जब हमें उस मेमोरी में रखी वैल्यू निकालनी होती है, तो हम सिर्फ वेरिएबल का नाम लेकर उसे पा सकते हैं।

जैसे, जब हम `a + 2` लिखते हैं, तो असल में हम वेरिएबल `a` से जुड़ी मेमोरी में रखी वैल्यू निकालते हैं और उसमें 2 जोड़ते हैं।

इसी तरह, जब हमें `a` वाली मेमोरी में रखी वैल्यू बदलनी होती है, तो हम वेरिएबल का नाम इस्तेमाल करके असाइनमेंट कर सकते हैं:

```go
a = 3
```

अब `a` से जुड़ी मेमोरी में वैल्यू `3` संग्रहीत हो जाएगी।

## पॉइंटर

वेरिएबल हमें मेमोरी में रखी वैल्यू का संदर्भ देते हैं, लेकिन कई बार यह जानना भी काम आता है कि वेरिएबल किस **मेमोरी एड्रेस** की ओर इशारा कर रहा है। **पॉइंटर** उन वैल्यू के मेमोरी एड्रेस अपने पास रखते हैं।
पॉइंटर टाइप का वेरिएबल घोषित करने के लिए मूल टाइप से पहले एक तारा चिह्न (*) लगाइए:

```go
var p *int // 'p' contains the memory address of an integer
```

यहाँ हम `p` नाम का वेरिएबल घोषित कर रहे हैं, जिसका टाइप "पूर्णांक का पॉइंटर" (`*int`) है।
इसका मतलब है कि `p` में एक पूर्णांक का मेमोरी एड्रेस रहेगा।
पॉइंटर की ज़ीरो वैल्यू `nil` होती है, क्योंकि `nil` पॉइंटर के पास कोई मेमोरी एड्रेस नहीं होता।

### वेरिएबल का पॉइंटर पाना

किसी वेरिएबल की वैल्यू का मेमोरी एड्रेस पाने के लिए हम `&` ऑपरेटर इस्तेमाल कर सकते हैं।
उदाहरण के लिए, अगर हम वेरिएबल `a` का मेमोरी एड्रेस ढूँढकर पॉइंटर `p` में रखना चाहते हैं, तो हम यह कर सकते हैं:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### पॉइंटर के ज़रिए वैल्यू तक पहुँचना (डीरेफरेंसिंग)

जब हमारे पास कोई पॉइंटर होता है, तो कई बार हम यह जानना चाहते हैं कि जिस मेमोरी एड्रेस की ओर वह पॉइंटर इशारा करता है, उसमें कौन-सी वैल्यू रखी है।
इसके लिए हम `*` ऑपरेटर इस्तेमाल कर सकते हैं:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p` ऑपरेशन उस वैल्यू को निकालता है जो `p` में रखे मेमोरी एड्रेस पर संग्रहीत है।
इस ऑपरेशन को अक्सर "डीरेफरेंसिंग" कहा जाता है।

हम डीरेफरेंस ऑपरेटर का इस्तेमाल करके पॉइंटर द्वारा संदर्भित मेमोरी एड्रेस पर नई वैल्यू भी असाइन कर सकते हैं:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa` पर असाइन करने से उस मेमोरी एड्रेस पर रखी वैल्यू बदल जाएगी जो `pa` अपने पास रखता है।
चूँकि `pa` में `a` का मेमोरी एड्रेस है, इसलिए `*pa` पर असाइन करके हम असल में `a` की वैल्यू ही बदल रहे हैं!

लेकिन एक सावधानी ज़रूरी है: डीरेफरेंस करने से पहले हमेशा जाँच लीजिए कि पॉइंटर `nil` नहीं है।
`nil` पॉइंटर को डीरेफरेंस करने से प्रोग्राम रनटाइम पर क्रैश हो जाएगा!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### स्ट्रक्ट के पॉइंटर

अब तक हमने सिर्फ बुनियादी वैल्यू के पॉइंटर देखे हैं।
हम स्ट्रक्ट के लिए भी पॉइंटर बना सकते हैं:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

हम एक नया `Person` बनाकर तुरंत उसका पॉइंटर भी रख सकते थे:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

जब हमारे पास किसी स्ट्रक्ट का पॉइंटर होता है, तो उसके किसी फील्ड तक पहुँचने से पहले पॉइंटर को डीरेफरेंस करने की ज़रूरत नहीं होती:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## स्लाइस और मैप पहले से ही पॉइंटर हैं

स्लाइस और मैप खास टाइप हैं, क्योंकि इनके अंदरूनी काम में पहले से ही पॉइंटर होते हैं।
इसका मतलब है कि इन टाइप की वैल्यू का मेमोरी एड्रेस साझा करने के लिए हमें ज़्यादातर इनके पॉइंटर बनाने की ज़रूरत नहीं पड़ती।
सोचिए, हमारे पास एक ऐसा फंक्शन है जो मैप के किसी एक की की वैल्यू बढ़ा देता है:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

अगर हम एक मैप बनाकर इस फंक्शन को कॉल करें, तो फंक्शन खत्म होने के बाद भी मैप में किए गए बदलाव बने रहते हैं।
यह व्यवहार वैसा ही है जैसा पॉइंटर इस्तेमाल करने पर मिलता है, लेकिन ध्यान दीजिए कि इस उदाहरण में हम कोई रेफरेंसिंग/डीरेफरेंसिंग या पॉइंटर का कोई सिंटैक्स इस्तेमाल नहीं कर रहे:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

यही बात स्लाइस में पहले से मौजूद किसी एलिमेंट को बदलने पर भी लागू होती है।

लेकिन `append` जैसे वे काम, जो नया स्लाइस लौटाते हैं, एक खास मामला हैं और हो सकता है कि फंक्शन के बाहर वाले स्लाइस को बदलें ही नहीं।
ऐसा स्लाइस के अंदरूनी तरीके की वजह से होता है, लेकिन यह विषय काफी उन्नत है, इसलिए इस अभ्यास में हम इस पर विस्तार से नहीं जाएँगे।
अगर आप और जानने के इच्छुक हैं, तो इसके बारे में और पढ़ सकते हैं: [Go Blog: Mechanics of 'append'][mechanics-of-append]
