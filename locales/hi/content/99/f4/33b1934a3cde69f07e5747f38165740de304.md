# परिचय

लिटरल फिक्स्ड वैल्यू होते हैं जिन्हें कोड में सीधे इस्तेमाल किया जाता है।
इन्हें रन-टाइम पर किसी गणना की ज़रूरत नहीं होती।
अलग-अलग तरह के डेटा को कुशलता से दर्शाने के लिए ये कई रूपों में आते हैं।
सबसे ज़्यादा मिलने वाले लिटरल संख्याओं से जुड़े होते हैं, लेकिन तारीख, समय और स्ट्रिंग टाइप के लिए भी लिटरल ऑपरेटर होते हैं।
आगे कोई कॉन्सेप्ट दिखाएगा कि उपयोगकर्ता द्वारा बनाए गए लिटरल ऑपरेटरों का इस्तेमाल कैसे किया जा सकता है।

## संख्यात्मक लिटरल

संख्यात्मक लिटरल में दशमलव, ऑक्टल, हेक्साडेसिमल और बाइनरी रूप शामिल हैं।
इन बुनियादी बातों को [संख्या कॉन्सेप्ट][numbers-concept] में पहले ही समझाया जा चुका है।

`23`, `0x50f7ba11` और `0xba5eba11` जैसे सभी रूपों को कंपाइलर `int` मानता है।
सामान्य `int` टाइप signed होता है और ([कंपाइलर और सिस्टम के अनुसार][in-depth-integers]) अक्सर इसकी रेंज `-2'147'483'648` से `2'147'483'647` तक होती है।
यह ज़्यादातर मामलों में काफी होता है और आपको किसी खास टाइप की चिंता करने की ज़रूरत नहीं है।

कुछ मामलों में बड़ी रेंज या प्रोग्राम में बहुत कम मेमोरी इस्तेमाल करने की ज़रूरत होती है।
स्पष्ट रहने के लिए आप संख्यात्मक लिटरल के साथ सीधे कोई खास पूर्णांक टाइप लिख सकते हैं।

जब ऋणात्मक संख्याओं की ज़रूरत न हो, लेकिन बड़ी रेंज चाहिए, तो _unsigned_ पूर्णांकों के लिए `u` या `U` सफिक्स इस्तेमाल किया जाता है।
बड़ी रेंज के लिए long और long long टाइप के साथ `L` या `LL` तक इस्तेमाल किया जा सकता है।

~~~~exercism/caution
छोटे अक्षर `l` का इस्तेमाल मान्य है, लेकिन इसे संख्या `1` से आसानी से भ्रम हो जाता है, इसलिए इससे बचने की सलाह दी जाती है।
~~~~

```cpp
auto net_worth_christian_grey{2'500'000'000U}; // out of range for 32-bit integers
auto net_worth_carlisle_cullen{46'000'000'000LL}; // int and uint are not enough
```

कंपाइल के समय फ्लोटिंग-पॉइंट संख्याएँ आम तौर पर `double` मानी जाती हैं।
यह एक अच्छा डिफॉल्ट है, और ऊपर वाले unsigned उदाहरण से ऐसे मामले कम होते हैं जिनमें छोटे `float` टाइप का इस्तेमाल होता है।

~~~~exercism/advanced
[C++23 मानक][cpp23-literals] में `f128` या `F16` जैसे लिटरल के ज़रिए और बारीक नियंत्रण मिलता है।
कुछ कंपाइलर अपने खुद के लिटरल की अनुमति देते हैं।
GCC `d` को लिटरल के तौर पर इस्तेमाल करने की अनुमति देता है, लेकिन यह मानक में तय नहीं है और क्रॉस-प्लेटफॉर्म कंपैटिबिलिटी में रुकावट डाल सकता है।

[cpp23-literals]: https://en.cppreference.com/w/cpp/language/floating_literal

~~~~

```cpp
auto light_year_in_m{9.46073e+15f}; // well in the range of float
auto earth_to_edge_comoving_distance_in_nm{4.32355e+32}; // needs double type for magnitude
auto eulers_number{2.718281828459045}; // needs double type for precision
```

## अक्षर और स्ट्रिंग लिटरल

दूसरे कॉन्सेप्टों में पहले ही `'}'` या `'@'` जैसे सिंगल कोट्स वाले अक्षर लिटरल इस्तेमाल हो चुके हैं।

C++ में `char` सिर्फ पहले 128 [ascii अक्षर कोड][ascii-code] तक सीमित है।
कई ascii अक्षरों या `‰` जैसे विस्तृत ascii अक्षरों, या `麗` और `ẞ` जैसे यूनिकोड अक्षरों का इस्तेमाल करने के लिए दूसरे टाइप चाहिए।
पिछले कॉन्सेप्ट में स्ट्रिंग लिटरल _डबल कोट्स_ के साथ पेश किए गए थे: `"一体どういう意味ですか。C++です"`।
इस जापानी वाक्यांश का वास्तविक टाइप `const char (&)[46]` है, जो C शैली की स्ट्रिंग है।

स्ट्रिंग लिटरल का इस्तेमाल डिफॉल्ट रूप से चालू नहीं होता।
_string_ लिटरल `""s` या _string-view_ लिटरल `""sv` इस्तेमाल करने के लिए उपयोगकर्ता को संबंधित नेमस्पेस इस्तेमाल करके यह तय करना होता है:

```cpp
#include <string>
#include <string_view>

using namespace std::literals;

auto green_light{"무궁화 꽃 이 피었 습니다"};
// green_light type is const char (&)[36]
auto umbrella{"달고나"s};
// umbrella type is std::basic_string<char>, the same as std::string
auto il_nam{"보는 것이 하는 것보다 더 재미있을 수가 없지"sv};
// il_nam type is std::basic_string_view<char>
```

एक _string_view_ को const स्ट्रिंग के रेफरेंस की तरह देखा जा सकता है।
