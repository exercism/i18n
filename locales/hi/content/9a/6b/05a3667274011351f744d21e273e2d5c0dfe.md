# परिचय

बाइनरी अंक अंततः सीधे तौर पर आपके CPU या RAM के ट्रांजिस्टर से जुड़े होते हैं, और इससे कि हर ट्रांजिस्टर "चालू" है या "बंद"।

निम्न स्तर पर बिट संभालना, जिसे अनौपचारिक रूप से "बिट-ट्विडलिंग" कहते हैं, सिस्टम भाषाओं में खासतौर पर अहम होता है।

Kotlin जैसी उच्च-स्तरीय भाषाएँ आमतौर पर इनमें से ज़्यादातर बारीकियाँ छिपा देती हैं। फिर भी, बिट-स्तर के ऑपरेशन की एक बुनियादी रेंज [उपलब्ध है][ref-bitwise]।

## बिट-शिफ्ट ऑपरेशन

`Int` या `Long` टाइप, चाहे साइन्ड हों या अनसाइन्ड, 1 और 0 की स्ट्रिंग के रूप में दर्शाए जा सकते हैं और बिट के क्रम के तौर पर उन पर काम किया जा सकता है।

शायद हैरानी की बात है कि `Byte` या `Short` टाइप Kotlin में ज़्यादातर बिटवाइज़ ऑपरेशन के साथ संगत नहीं होते। नीचे दिए गए सारे उदाहरण 32-बिट पूर्णांक (`Int` या `UInt`) इस्तेमाल करते हैं।

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

बिट-शिफ्ट बस सब कुछ तय संख्या में स्थानों तक बाएँ या दाएँ खिसका देते हैं। कुछ बिट एक सिरे से गिर जाते हैं, और दूसरे सिरे को शून्य या एक से भर दिया जाता है।

- `shl` से बाएँ शिफ्ट: शून्य भरा जाता है।
- `shr` या `ushr` से दाएँ शिफ्ट: धनात्मक संख्याओं के लिए शून्य भरा जाता है (ऋणात्मक संख्याओं के लिए आगे देखिए)।

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

हर बाएँ शिफ्ट वैल्यू को दोगुना कर देता है, और हर दाएँ शिफ्ट उसे आधा कर देता है (काट-छाँट के अधीन)। दशमलव रूप में लिखने पर यह ज़्यादा साफ दिखता है:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

ऐसी बिट-शिफ्टिंग "पक्के" अंकगणित से बहुत तेज़ होती है, इसलिए यह तरीका निम्न-स्तरीय कोडिंग में बहुत लोकप्रिय है।

_ऋणात्मक पूर्णांकों_ के साथ हमें थोड़ा और ध्यान रखना पड़ता है।

ऋणात्मक वैल्यू [दो का पूरक][wiki-2complement] रूप में संग्रहीत की जाती हैं, जिसका मतलब है कि सबसे बाएँ वाला बिट 1 होता है। बाएँ शिफ्ट में कोई दिक्कत नहीं, लेकिन दाएँ शिफ्ट करते समय हम सबसे बाएँ वाले बिट कैसे भरें?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

`shr` ऑपरेटर [अंकगणितीय शिफ्ट][wiki-arithmetic] करता है, जो साइन बिट बनाए रखता है।

`ushr` ऑपरेटर [लॉजिकल शिफ्ट][wiki-logical] करता है, जिसमें शून्य से पैडिंग होती है, जैसे संख्या अनसाइन्ड हो।

## बिटवाइज़ लॉजिक

हमने [बूलियन कॉन्सेप्ट][concept-booleans] में देखा था कि ऑपरेटर `&&` (और), `||` (या) और `!` (नहीं) बूलियन वैल्यू के साथ इस्तेमाल होते हैं।

दो पूर्णांकों के बिट की तुलना करने के लिए बराबर के ऑपरेटर `and`, `or`, `xor` ([एक्सक्लूसिव-ओर][wiki-xor]) हैं, और सारे बिट उलटने के लिए एक `inv` (इनवर्शन) फंक्शन है।

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
