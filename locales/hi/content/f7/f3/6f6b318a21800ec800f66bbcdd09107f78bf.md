# विवरण

एक फंक्शन तब [टेल-रिकर्सिव][recursion-tc] होता है जब उस फंक्शन द्वारा चलाई जाने वाली _अंतिम_ चीज़ खुद को कॉल करना हो।

जब भी कोई फंक्शन कॉल किया जाता है, तो उसके लोकल वेरिएबलो और आर्गुमेंट के साथ एक _स्टैक फ्रेम_ [फंक्शन कॉल स्टैक][call-stack] के ऊपर रख दिया जाता है।
जब कोई फंक्शन लौटता है, तो उसका स्टैक फ्रेम स्टैक से हटा दिया जाता है।

टेल-रिकर्सिव फंक्शन [टेल कॉल ऑप्टिमाइज़ेशन][tail-call-optimization] (या टेल कॉल एलिमिनेशन) की सुविधा देते हैं।
यह एक ऐसा ऑप्टिमाइज़ेशन है जो तब अगले फंक्शन कॉल के लिए पिछले स्टैक फ्रेम का दोबारा उपयोग करने देता है, जब यह निश्चित हो कि उस पिछले फंक्शन को अब उसकी ज़रूरत नहीं पड़ेगी।
यह फंक्शन कॉल स्टैक के ओवरफलो होने की चिंता कम करता है। ऐसी स्थिति तब बनती है जब फंक्शन कॉल स्टैक पर इतने फ्रेम हो जाते हैं कि एक और फ्रेम बनाने के लिए मेमोरी ही नहीं बचती।

## Elm में टेल कॉल ऑप्टिमाइज़ेशन

कुछ शर्तों के तहत, JavaScript में कंपाइल करते समय Elm कंपाइलर अपने आप टेल कॉल ऑप्टिमाइज़ेशन कर पाता है।

यह ऑप्टिमाइज़ेशन किसी रिकर्सिव फंक्शन के लिए तब हो सकता है जब किसी ब्रांच में _अंतिम_ ऑपरेशन उसी फंक्शन को एक सामान्य फंक्शन एप्लिकेशन में कॉल करके किया गया हो।
चलिए कुछ उदाहरण देखते हैं:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

ऊपर दिया गया कोड टेल-रिकर्सिव नहीं है, क्योंकि `else` ब्रांच में अंतिम ऑपरेशन एक गुणा `n *` है।

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

ऊपर दिया गया कोड टेल-रिकर्सिव है और ऑप्टिमाइज़ किया जाएगा, क्योंकि `else` ब्रांच में अंतिम ऑपरेशन `factorialHelper` का खुद को कॉल करना है।
`Int -> Int` टाइप सिग्नेचर वाले फंक्शन के लिए यह संभव नहीं होगा, और व्यवहार में टेल कॉल ऑप्टिमाइज़ेशन अक्सर हेल्पर फंक्शन बनाकर हासिल किया जाता है।

## एज केस

कुछ मामलों में कंपाइलर रिकर्सिव फंक्शन को ऑप्टिमाइज़ नहीं कर पाता। चलिए कुछ उदाहरण देखते हैं।

`f x = f (x - 1)` टेल कॉल रिकर्सिव है, लेकिन `f x = (x - 1) |> f` नहीं है, क्योंकि यहाँ अंतिम ऑपरेशन फंक्शन एप्लिकेशन `|>` है और इसे `f` से अलग माना जाता है।
इसी तरह, बूलियन शर्तों पर खत्म होने वाले फंक्शन, जैसे `f x = x > 0 || f (x - 1)`, टेल-रिकर्सिव नहीं होते।

फंक्शन `f x = if f (x - 1) then 1 else 0` टेल-रिकर्सिव नहीं है, क्योंकि `if` के अंदर के एक्सप्रेशन को ब्रांच नहीं माना जाता।
इसी तरह, `case` स्टेटमेंट में किया गया रिकर्सिव कॉल भी ऑप्टिमाइज़ नहीं होगा।

फंक्शन `f x = let y = f (x - 1) in y` टेल-रिकर्सिव नहीं है, क्योंकि यह `let` स्टेटमेंट में खुद को कॉल करता है, और `let` को ब्रांच नहीं माना जाता।
लेकिन `f x = let g x = g (x - 1) in g x` में फंक्शन `g` टेल-रिकर्सिव है और ऑप्टिमाइज़ किया जाएगा, भले ही यह `let` स्टेटमेंट में बनाया गया हो।

फंक्शन `f x = if x > 0 then f (x + 1) else 1 + f x` _आंशिक रूप से_ ऑप्टिमाइज़ होगा: `then` ब्रांच ऑप्टिमाइज़ हो सकती है, लेकिन `else` ब्रांच नहीं।
कुछ स्थितियों में, जैसे पेड़ जैसी संरचनाओं में घूमते समय या को-रिकर्सिव फंक्शन बनाते समय, आंशिक ऑप्टिमाइज़ेशन ही सबसे अच्छा होता है जो किया जा सकता है।
