# परिचय

C# में ऑब्जेक्ट-ओरिएंटेड प्रोग्रामिंग की मुख्य संरचना _क्लास_ है, जो डेटा ([_फील्ड_][fields]) और व्यवहार ([_मेथड_][methods]) का मेल होती है। क्लास के फील्ड और मेथड को उसके _सदस्य_ कहा जाता है।

सदस्यों तक पहुँच को एक्सेस मॉडिफायर के ज़रिए सीमित किया जा सकता है। इनमें दो सबसे आम ये हैं:

- [`public`][public]: इस सदस्य तक किसी भी कोड से पहुँचा जा सकता है (कोई प्रतिबंध नहीं)।
- [`private`][private]: इस सदस्य तक सिर्फ उसी क्लास का कोड पहुँच सकता है।

हर सदस्य के लिए एक एक्सेस मॉडिफायर लिखना आम बात है। अगर कोई एक्सेस मॉडिफायर नहीं लिखा गया, तो डिफॉल्ट रूप से `private` माना जाता है।

जुड़े हुए डेटा और व्यवहार को एक साथ रखना, और सदस्यों तक पहुँच सीमित करना, [एनकैप्सुलेशन][encapsulation] कहलाता है, जो ऑब्जेक्ट-ओरिएंटेड की मुख्य अवधारणाओं में से एक है।

किसी एक समय पर किसी ऑब्जेक्ट के फील्ड की वैल्यू का मेल उस ऑब्जेक्ट की [स्थिति][object-state] कहलाता है।

आप क्लास को उसके इंस्टेंस बनाने का टेम्पलेट मान सकते हैं। किसी क्लास का [इंस्टेंस बनाने][creating-objects] के लिए (जिसे _ऑब्जेक्ट_ भी कहते हैं), [`new` कीवर्ड][new] का इस्तेमाल किया जाता है:

```csharp
class Car
{
}

// Create two car instances
var myCar = new Car();
var yourCar = new Car();
```

[फील्ड][fields] का एक टाइप होता है और इन्हें क्लास में कहीं भी परिभाषित किया जा सकता है।
पब्लिक फील्ड [PascalCase][pascal-case] में लिखे जाते हैं और प्राइवेट फील्ड [camelCase][camel-case] में, जिनके आगे अंडरस्कोर `_` लगाया जाता है:

```csharp
class Car
{
    // Accessible by anyone
    public int Weight;

    // Only accessible by code in this class
    private string _color;
}
```

किसी फील्ड को शुरुआती वैल्यू देना ज़रूरी नहीं है। अगर कोई फील्ड शुरुआती वैल्यू नहीं देता, तो उसे उसके टाइप की [डिफॉल्ट वैल्यू][default-values] दी जाती है। किसी इंस्टेंस के फील्ड की वैल्यू को डॉट-नोटेशन से पढ़ा और बदला जा सकता है।

```csharp
class Car
{
    // Will be set to specified value
    public int Weight = 2500;

    // Will be set to default value (0)
    public int Year;
}

var newCar = new Car();
newCar.Weight; // => 2500
newCar.Year;   // => 0

// Update value of the field
newCar.Year = 2018;
```

प्राइवेट फील्ड आम तौर पर किसी मेथड को कॉल करने के साइड इफेक्ट के रूप में बदले जाते हैं। ऐसे मेथड आम तौर पर कोई वैल्यू नहीं लौटाते; ऐसे में रिटर्न टाइप [`void`][void] होना चाहिए:

```csharp
class CarImporter
{
    private int _carsImported;

    public void ImportCars(int numberOfCars)
    {
        // Update private field
        _carsImported = _carsImported + numberOfCars;
    }
}
```

ध्यान दीजिए कि C# क्लास में पब्लिक फील्ड इस्तेमाल करना आम बात नहीं है। या तो प्राइवेट फील्ड इस्तेमाल होते हैं, या दूसरे तरह के सदस्य, जिनकी चर्चा आगे के अभ्यासों में की जाएगी।

क्लास के अंदर [`this` कीवर्ड][this] मौजूदा क्लास को दर्शाता है। यह खास तौर पर तब काम आता है जब किसी पैरामीटर का नाम किसी फील्ड के नाम जैसा हो:

```csharp
class CarImporter
{
    private int carsImported;

    public void SetImportedCars(int carsImported)
    {
        // Update private field from public method
        this.carsImported = carsImported;
    }
}
```

क्लास और मेथड की बनावट प्रोग्राम के एलिमेंट, जैसे फील्ड और मेथड, की दृश्यता सीमित करने का एक स्वाभाविक तरीका देती है और [ग्लोबल स्टेट की मशहूर समस्या][so-global-state-problem] से बचाती है। क्लास के बाहर का कोड पब्लिक फील्ड, मेथड और दूसरे सदस्यों को देख सके, इसके लिए उनके साथ ऑब्जेक्ट का नाम लिखा जाना चाहिए, `object.field` या `object.method()` (स्टैटिक के मामले में क्लास का नाम)। किसी मेथड के अंदर घोषित वेरिएबल और पैरामीटर सिर्फ उसी मेथड के अंदर दिखते हैं।

इस तरीके में एक बात का ध्यान रखना ज़रूरी है: अगर किसी फील्ड का नाम और मेथड के अंदर के किसी वेरिएबल या पैरामीटर का नाम एक जैसा हो, तो मेथड के अंदर का कोड उस फील्ड के नाम को नज़रअंदाज़ कर देगा, जो शायद आप नहीं चाहते। आम तौर पर आपको जहाँ तक हो सके इससे बचना चाहिए, हालाँकि कंस्ट्रक्टर में यह एक आम पैटर्न है। अगर फील्ड और वेरिएबल का नाम एक जैसा रखना ही ठीक हो, तो मेथड के अंदर फील्ड के नाम से पहले `this` कीवर्ड लगाइए।

इन [एक्सेस मॉडिफायर][access-modifiers] से दृश्यता और सीमित की जा सकती है।
