# परिचय

एक आदर्श दुनिया में हम यह मान सकते थे कि हर चीज़ ठीक से तय है, हर जगह ठोस वैल्यू है और कोई कमी नहीं।

यह हमारे रोज़मर्रा के अनुभव से मेल नहीं खाता, इसलिए बहुत-सी प्रोग्रामिंग भाषाओं में यह दिखाने का तरीका होता है कि कोई वैल्यू मौजूद नहीं है: null या NULL, nil, None, nothing...

इसे शुरू करना आसान था (1965 में), लेकिन जल्द ही इस पर पछतावा हुआ।
बाद में इसके आविष्कारक ने इसे अपनी "Billion Dollar Mistake" कहा।

पिछले कुछ दशकों में भाषा के डिज़ाइनरों ने ऐसे कई तरीके खोजे हैं जिनसे नल उपलब्ध भी रहे और (अधिकतर) सुरक्षित भी।

Kotlin में कुछ [सामान्य सिद्धांत][ref-null-safety] हैं, जो Java से काफी अलग हैं।


- Kotlin में एक खास `null` वैल्यू होती है।
- सभी टाइप _डिफ़ॉल्ट रूप से_ नॉन-नेलेबल होते हैं।
- अधिकांश टाइप को _नेलेबल बनाया_ जा सकता है, लेकिन प्रोग्रामर को यह स्पष्ट रूप से बताना पड़ता है।
- जो फंक्शन किसी एक्सेप्शन के कारण विफल हो सकते हैं, उनमें अक्सर नेलेबल रिटर्न वैल्यू वाला एक वेरिएंट भी होता है।
- कुछ खास और बेहद संक्षिप्त सिंटैक्स की वजह से नल की जाँच करना और उससे निपटना जितना आसान हो सके उतना आसान बन गया है।

## नेलेबल वेरिएबल बनाना

मानक टाइप का आम तौर पर एक नेलेबल रूप भी होता है, जिसके अंत में `?` लगता है: जैसे `String` के बजाय `String?`।

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## काम के ऑपरेटर और फंक्शन

### सेफ कॉल ऑपरेटर `?.`

नॉन-नेलेबल `String` पर हम `.length` प्रॉपर्टी निकाल सकते हैं।

नेलेबल `String?` पर यही सिंटैक्स विफल हो जाता है, लेकिन `?.length` इस्तेमाल करने से `null` हो सकने की स्थिति भी संभल जाती है।
रिटर्न टाइप `Int?` होता है।

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

जैसा कि ऊपर अंतिम लाइन में दिखा, `?.` नॉन-नेलेबल टाइप के साथ भी काम करता है।

### एल्विस ऑपरेटर `?:`

सेफ-कॉल ऑपरेटर के इसी विचार को आगे बढ़ाते हुए, [एल्विस ऑपरेटर][wiki-elvis] की मदद से हम `null` की जगह कोई डिफ़ॉल्ट वैल्यू दे सकते हैं।

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### नॉट-नल असर्शन ऑपरेटर `!!`

जब प्रोग्रामर को पूरा भरोसा हो, तब इस ऑपरेटर से नेलेबल टाइप के साथ नॉन-नेलेबल जैसा बर्ताव किया जाता है।
शायद कभी-कभी हम प्रोग्राम के तर्क को बहुत अधिक सतर्क कंपाइलर से बेहतर समझ लेते हैं?

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

अब जिम्मेदारी हमारी है: अगर `b` अब भी `null` है, तो हमें `NullPointerException` मिलता है।

### let फंक्शन `?.let`

अगर किसी कोड ब्लॉक को कोई नेलेबल चीज़ देनी हो, तो हम नल की अलग-अलग जाँचें कर सकते हैं, जैसे `if (item != null) { do something }`।

`item?.let { do something }` इस्तेमाल करना आसान भी है और अधिक स्वाभाविक भी।
यह `do something` तभी चलेगा जब `item` नल न हो।

### `somethingOrNone()` टाइप के फंक्शन

कुछ फंक्शन विफल हो सकते हैं, जैसे किसी स्ट्रिंग या ऐरे में गलत इंडेक्स माँगने पर।

किसी एक्सेप्शन को फेंकने के बजाय हम फंक्शन के `...OrNull` वेरिएंट का इस्तेमाल कर सकते हैं, जिससे (इस मामले में) `Int?` रिटर्न वैल्यू मिलती है।

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
