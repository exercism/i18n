# बूलियन

`BOOL` दो वैल्यू में से एक रखता है: `true` और `false`।

```sather
   ready : BOOL is
      return true;
   end;
```

## तुलना

| ऑपरेटर | क्या पूछता है | उदाहरण |
| --- | --- | --- |
| `=` | एक जैसे? | `age = 13` |
| `/=` | अलग? | `age /= 13` |
| `<` | से छोटा | `age < 13` |
| `<=` | से छोटा या बराबर | `age <= 13` |
| `>` | से बड़ा | `age > 13` |
| `>=` | से बड़ा या बराबर | `age >= 13` |

ये संख्याओं पर काम करते हैं, और `=` तथा `/=` स्ट्रिंग पर भी काम करते हैं।

## तीन ऑपरेटर

| ऑपरेटर | लिखा जाता है | सही कब होता है |
| --- | --- | --- |
| and | `a and b` | दोनों सही हों |
| or | `a or b` | कम से कम एक सही हो |
| not | `~a` | `a` गलत हो |

`and` और `or` में **शॉर्ट-सर्किट** होता है: अगर `a` गलत निकला, तो `a and b` अब `b` को देखता ही नहीं, क्योंकि जवाब पहले ही तय हो चुका है। इसी तरह `a or b` तब रुक जाता है जब `a` सही हो। यह तब मायने रखता है जब दाईं ओर वाला हिस्सा महँगा हो, या चलने पर कुछ गड़बड़ कर जाए।

## तुलना सीधे लौटाना

जिस रूटीन का पूरा काम ही एक सवाल पूछना है, उसे सवाल ही लौटाना चाहिए, न कि किसी शर्त से जवाब चुनना:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

जो बात तुलना पहले ही कह चुकी है, उसे कहने में `if age >= 13 then return true else return false end` लिखकर तीन लाइनें लगती हैं, और हर अनुभवी पाठक इसे पकड़ लेता है।

## प्राथमिकता

`~` की प्राथमिकता सबसे ऊँची है, फिर `and`, फिर `or`। इसलिए

```sather
~a and b or c
```

का मतलब है `((~a) and b) or c`। ब्रैकेट लिखने में कोई खर्च नहीं लगता, और जहाँ इसके बिना पाठक को पंक्ति समझने के लिए यह क्रम याद रखना पड़े, वहाँ ब्रैकेट लगाना फायदेमंद रहता है।
