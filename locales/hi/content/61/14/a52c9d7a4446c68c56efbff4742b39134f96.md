# परिचय

रेगुलर एक्सप्रेशन स्ट्रिंग्स को _पैटर्न मैच_ करने का एक बहुत लचीला तरीका है। इसके लिए एक खास तरह की डोमेन स्पेसिफिक लैंग्वेज (DSL) बनाई गई है।

रेगेक्स की कई क्षमताएँ Base R में पहले से मौजूद हैं, और पुराने कोड में आपको इसके उदाहरण भी मिल सकते हैं।

नए कोड के लिए [`stringr`][web-stringr] लाइब्रेरी इस्तेमाल करने की दृढ़ता से सलाह दी जाती है।

जैसा कि [स्ट्रिंग्स कॉन्सेप्ट][concept-strings] में बताया गया है, `stringr` का दस्तावेज़ीकरण अच्छा है और आम तौर पर इसे पैकेज के लेखकों ने ही लिखा होता है।

- एक [रेफरेंस वेबसाइट][web-stringr]
- एक [चीटशीट][cheat-stringr]।
- "R for Data Science" में एक [स्ट्रिंग्स चैप्टर][book-strings] और एक [रेगेक्स चैप्टर][book-regex]।

[`Strings`][concept-strings] कॉन्सेप्ट में पहले ही चर्चा किए गए कई फंक्शन डिफ़ॉल्ट रूप से रेगेक्स सर्च के लिए ही बने होते हैं।

हमने स्ट्रिंग्स कॉन्सेप्ट को तुलनात्मक रूप से सरल रखा था और सिर्फ स्ट्रिंग लिटरल पर मैच किया था। लेकिन इसकी जगह कोई भी रेगेक्स पैटर्न इस्तेमाल किया जा सकता है।

तकनीकी रूप से, R में रेगेक्स [`regex()`][ref-regex] को कॉल करके बनाया जाता है। सुविधा के लिए `stringr` के फंक्शन हर पैटर्न स्ट्रिंग को रेगेक्स मान लेते हैं। नीचे दिए उदाहरण में पहला `str_replace_all()` दूसरे रूप का सिंटैक्टिक शुगर है:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[चीटशीट][cheat-stringr] एक उपयोगी गाइड है: जिन सभी फंक्शन में `pattern` आर्गुमेंट होता है (जो लाल रंग में छपा है), वे रेगेक्स स्वीकार करते हैं, और पेज 2 में रेगेक्स सिंटैक्स का सार दिया गया है।

ध्यान दीजिए कि अगर आपको डिफ़ॉल्ट सेटिंग बदलनी हो, जैसे केस सेंसिटिविटी या लोकेल, तो [`regex()`][ref-regex] फंक्शन अब भी काम आ सकता है।

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

रेगेक्स के कई कोड में बैकस्लैश होता है, जैसे ऊपर इस्तेमाल किया गया `\s`।

आम R स्ट्रिंग में `\` को दोहराकर लिखना पड़ता है, इसलिए `"\\s"` लिखा जाता है।

बैकस्लैश बढ़ते चले जाते हैं और उलझन पैदा कर सकते हैं, इसलिए जटिल मामलों में [रॉ स्ट्रिंग][book-raw] इस्तेमाल करना मददगार हो सकता है।

डिफ़ॉल्ट रूप से रॉ स्ट्रिंग बनाने का सिंटैक्स `r"( )"` है, लेकिन दूसरे डेलिमिटर भी इस्तेमाल किए जा सकते हैं। चूँकि रेगेक्स सिंटैक्स में गोल ब्रैकेट `( )` और चौकोर ब्रैकेट `[ ]` दोनों ही आम हैं (कैप्चर ग्रुप और ऑप्शन ग्रुप के लिए), इसलिए घुंघराले ब्रैकेट `{ }` एक अच्छा विकल्प हो सकता है।

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## मैच का पता लगाना

यहाँ कुछ प्रश्न हैं, और ऐसे फंक्शन भी जो इनका उत्तर देने में मदद कर सकते हैं।

कुछ उदाहरणों में `fruit` इस्तेमाल किया गया है, जो `stringr` के साथ अभ्यास के लिए दिया गया 80 फलों के नामों का वेक्टर है।

_क्या किसी स्ट्रिंग में मैच मौजूद है?_
इसके लिए `str_detect()` इस्तेमाल कीजिए, या `^` और `$` एंकर से बचने के लिए `str_starts()` और `str_ends()`।

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_सिर्फ वही स्ट्रिंग लौटानी हैं जिनमें मैच मौजूद हो?_
स्ट्रिंग पाने के लिए `str_subset()` और इंडेक्स पाने के लिए `str_which()` इस्तेमाल कीजिए।

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_हर स्ट्रिंग में कितने मैच हैं?_
`str_count()` इस्तेमाल कीजिए।

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_मैच कहाँ है?_
इंटरैक्टिव इस्तेमाल के लिए `str_view()`, और आम तौर पर `str_locate()` या `str_locate_all()`।

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## कैप्चर

आम तौर पर हमें यह जानना होता है कि _क्या_ मैच हुआ है।
यह रेगेक्स के अंदर गोल ब्रैकेट में कैप्चर ग्रुप डालकर किया जाता है।

एक ही रेगेक्स के अंदर `\1`, `\2` आदि की मदद से कैप्चर को दोबारा इस्तेमाल किया जा सकता है।
उदाहरण के लिए, अक्षरों के दोहराए गए जोड़े ढूँढना:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

इसी तरह के सिंटैक्स से कैप्चर को रिप्लेसमेंट स्ट्रिंग में भी इस्तेमाल किया जा सकता है:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

बाद में काम के लिए मैच इकट्ठा करने के लिए सिर्फ पहले मैच के लिए `str_match()` फंक्शन, या सारे मैचों के लिए `str_match_all()` इस्तेमाल कीजिए।

कैप्चर ग्रुप किसी भी भाषा में आम तौर पर जटिल आउटपुट ही देते हैं।
R का तरीका यह है कि `str_match()` से एक मैट्रिक्स बनाई जाती है (_यहाँ R वेक्टराइज़्ड तरीका अपनाता है, जिससे यह थोड़ा और मुश्किल हो जाता है_): हर इनपुट स्ट्रिंग के लिए एक पंक्ति, पहले कॉलम में पूरी मैच हुई स्ट्रिंग, और बाकी कॉलमों में अलग-अलग कैप्चर ग्रुप।

नेम्ड ग्रुप इस्तेमाल करना लाभदायक हो सकता है, क्योंकि ये नतीजों की मैट्रिक्स में कॉलम के नाम बन जाते हैं।

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

इस सिलेबस में हमने मैट्रिक्स के बारे में ज़्यादा बात नहीं की है, हालाँकि एक [कॉन्सेप्ट दस्तावेज़][concept-matrices-arrays] मौजूद है जिसे आप देख सकते हैं।
मैट्रिक्स Tidyverse इकोसिस्टम के साथ ठीक से मेल नहीं खातीं, भले ही ये लंबे समय से Base R का हिस्सा रही हैं।

संक्षेप में: मैट्रिक्स को 2 इंडेक्स वाले वेक्टर की तरह समझिए, `[rows, cols]` के क्रम में।
पूरी पंक्ति या पूरा कॉलम पाने के लिए कोई भी इंडेक्स खाली छोड़ दीजिए।

जब `m[r,]` से एक अकेली पंक्ति `r` या `m[,c]` से एक अकेला कॉलम `c` निकाला जाता है, तो लौटाई गई वैल्यू डिफ़ॉल्ट रूप से सपाट करके एक वेक्टर बना दी जाती है।

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

स्वाभाविक रूप से, `str_match_all()` का आउटपुट और भी ज़्यादा संरचना वाला होता है:

- नतीजा एक ऐरे होता है, जिसमें हर इनपुट स्ट्रिंग के लिए एक एलिमेंट होता है।
- अगर सिर्फ एक ही इनपुट स्ट्रिंग हो, तो [ऐरे कॉन्सेप्ट][concept-lists] में बताए अनुसार `[[1]]` इंडेक्सिंग से आउटपुट को एक सपाट वेक्टर में बदल दीजिए।
- हर एलिमेंट एक मैट्रिक्स होती है, जिसके कॉलम `match()` की तरह होते हैं।
- मैट्रिक्स की हर पंक्ति एक सफल कैप्चर होती है।

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

मैच फेल भी हो सकते हैं।
तब नतीजा `NA` नाम की खास वैल्यू होती है।
इसकी जाँच के लिए तैयार रहिए, जैसा कि [शून्यता कॉन्सेप्ट][concept-nothingness] में बताया गया है।

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
