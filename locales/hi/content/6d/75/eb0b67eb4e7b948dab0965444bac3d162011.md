# परिचय

Gleam में किसी वैल्यू पर पैटर्न मैचिंग करते समय हमें यह सुनिश्चित करना होता है कि पैटर्न उस टाइप की हर संभव वैल्यू से मेल खाए। ऐसा न होने पर कोड कंपाइल नहीं होगा।

इस फंक्शन को अस्वीकार कर देना चाहिए, क्योंकि इसमें उस स्थिति को संभाला नहीं गया है जहाँ ऐरे खाली हो:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Gleam के प्रोग्राम में ज़्यादातर हम हर संभव स्थिति को संभालना चाहते हैं। लेकिन प्रोटोटाइप और छोटी स्क्रिप्ट जैसे कुछ प्रोग्रामों में हम केवल उसी रास्ते पर ध्यान देना चाहते हैं जहाँ सब कुछ ठीक चलता हो, और बाकी स्थितियों के लिए कोड नहीं लिखना चाहते। यहीं Gleam का `let assert` काम आता है।

let assertions की मदद से ज़रूरी नहीं कि कोई पैटर्न किसी टाइप की हर संभव वैल्यू से मेल खाए; वह केवल कुछ वैल्यू से मेल खा सकता है। अगर पैटर्न किसी वैल्यू से मेल नहीं खाता, तो प्रोग्राम क्रैश हो जाता है। `let assert` का उपयोग करके हम ऊपर वाला फंक्शन इस तरह लिख सकते हैं:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam की लाइब्रेरी में कभी भी let assertions का उपयोग नहीं करना चाहिए, क्योंकि इससे प्रोग्राम क्रैश हो सकता है। इसके बजाय उन्हें `Result` टाइप का उपयोग करना चाहिए और एरर को संभालने का तरीका ऐप्लिकेशन डेवलपर पर छोड़ देना चाहिए।
