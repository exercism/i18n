# परिचय

Go 1.18 में Go ने **जेनेरिक्स** का समर्थन जोड़ा। जेनेरिक्स आपको अलग-अलग टाइप के साथ काम करने वाले फंक्शन और डेटा स्ट्रक्चर लिखने देते हैं, बिना कोड को दोहराए।

## जेनेरिक्स की ज़रूरत क्यों?

Go में फंक्शन और टाइप सामान्यतः किसी खास टाइप के साथ काम करते हैं, जैसे `int` या `string`। जेनेरिक्स से पहले कई टाइप के समर्थन के लिए आपके पास दो विकल्प थे। पहला, आप अलग-अलग नामों वाले कई फंक्शन लिख सकते थे, जैसे `SumInts` और `SumFloats`। इस तरीके से डुप्लिकेट कोड बनता है जिसे बनाए रखना मुश्किल होता है। दूसरा, आप खाली इंटरफेस `any` (`interface{}`) इस्तेमाल कर सकते थे। लेकिन खाली इंटरफेस कंपाइल-टाइम टाइप जाँच हटा देता है और रनटाइम पर टाइप असर्शन मांगता है। जेनेरिक्स टाइप सेफ्टी देकर और डुप्लिकेट कोड से बचकर इस समस्या को हल करते हैं।

## जेनेरिक फंक्शन

आप फंक्शन के नाम के बाद चौकोर ब्रैकेट `[...]` में **टाइप पैरामीटर** जोड़कर एक जेनेरिक फंक्शन बनाते हैं। यहाँ एक जेनेरिक फंक्शन का उदाहरण है जो उलटा किया गया स्लाइस लौटाता है:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

इस उदाहरण में `T` एक टाइप पैरामीटर है। आप `T` को किसी वास्तविक टाइप के लिए प्लेसहोल्डर मान सकते हैं। चौकोर ब्रैकेट के अंदर `any` कीवर्ड एक **टाइप कंस्ट्रेंट** है। कंस्ट्रेंट कंपाइलर को बताता है कि `T` के लिए कौन-कौन से टाइप अनुमत हैं। यहाँ `any` का मतलब है कि `T` कोई भी टाइप हो सकता है।

### जेनेरिक फंक्शन को कॉल करना

आप चौकोर ब्रैकेट में वास्तविक टाइप देकर जेनेरिक फंक्शन को कॉल कर सकते हैं। इस वास्तविक टाइप को **टाइप आर्गुमेंट** कहा जाता है।

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

अधिकतर मामलों में Go कंपाइलर फंक्शन के आर्गुमेंट से टाइप अपने आप पहचान सकता है। इस सुविधा को **टाइप इन्फरेंस** कहा जाता है। टाइप इन्फरेंस के साथ आपको चौकोर ब्रैकेट में टाइप आर्गुमेंट लिखने की ज़रूरत नहीं होती।

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

इस उदाहरण में कंपाइलर देखता है कि `words` स्ट्रिंग का स्लाइस है, इसलिए वह अनुमान लगाता है कि `T` का टाइप `string` है।

## टाइप कंस्ट्रेंट

हर टाइप पैरामीटर का एक कंस्ट्रेंट होना चाहिए। कंस्ट्रेंट बताता है कि आप किन टाइप को टाइप आर्गुमेंट के रूप में इस्तेमाल कर सकते हैं। कंस्ट्रेंट यह भी तय करता है कि उस टाइप की वैल्यू पर आप कौन-कौन से ऑपरेशन कर सकते हैं।

### `any` कंस्ट्रेंट

`any` कंस्ट्रेंट किसी भी टाइप को अनुमति देता है। Go में `any`, खाली इंटरफेस `interface{}` का एलियस है। चूँकि `any` हर टाइप को अनुमति देता है, फंक्शन केवल वे ऑपरेशन कर सकता है जो सभी Go टाइप पर काम करते हैं। उदाहरण के लिए, अगर आपके पास स्लाइस रखने वाली दो `any` वैल्यू हैं, तो उन्हें `==` से तुलना नहीं की जा सकती, क्योंकि स्लाइस की `==` से तुलना नहीं हो सकती।

### `comparable` कंस्ट्रेंट

Go में `comparable` नाम का एक अंतर्निहित कंस्ट्रेंट है। `comparable` कंस्ट्रेंट उन सभी टाइप को अनुमति देता है जो `==` और `!=` ऑपरेटर सपोर्ट करते हैं। तुलना योग्य टाइप में बूलियन, संख्याएँ, स्ट्रिंग, पॉइंटर, चैनल, और तुलना योग्य टाइप से बने स्ट्रक्ट या ऐरे शामिल हैं।

यहाँ एक फंक्शन का उदाहरण है जो जाँचता है कि किसी स्लाइस में कोई खास आइटम है या नहीं:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

चूँकि `T` में `comparable` कंस्ट्रेंट है, `elem == target` का इस्तेमाल मान्य है। अगर आप `comparable` की जगह `any` रखेंगे, तो कंपाइलर एरर देगा।

### इंटरफेस टाइप सेट से कस्टम कंस्ट्रेंट

Go 1.18 से इंटरफेस मेथड के अलावा टाइप के सेट भी परिभाषित कर सकते हैं। इंटरफेस में अनुमत टाइप की सूची बनाने के लिए आप पाइप चिह्न `|` इस्तेमाल कर सकते हैं।

```go
type Number interface {
    int | int64 | float64
}
```

अब आप किसी फंक्शन के कंस्ट्रेंट के रूप में `Number` इस्तेमाल कर सकते हैं:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

चूँकि `Number` में सभी टाइप `*` ऑपरेटर सपोर्ट करते हैं, Go फंक्शन के अंदर `value * 2` की अनुमति देता है।

### अंडरलाइंग टाइप का अनुमान `~`

कभी-कभी आप किसी प्रिमिटिव टाइप के आधार पर कस्टम टाइप डेफिनिशन बनाते हैं:

```go
type MyInt int
```

ऊपर परिभाषित `Number` कंस्ट्रेंट केवल सटीक टाइप `int`, `int64` और `float64` को अनुमति देता है। अगर आप `Double` को `MyInt` टाइप की वैल्यू देते हैं, तो कंपाइलर एरर देता है क्योंकि `MyInt`, `int` से मेल नहीं खाता। ऐसे किसी भी टाइप को अनुमति देने के लिए जिसका अंडरलाइंग टाइप `int` है, टाइप से पहले टिल्ड `~` जोड़िए:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

अब आप `MyInt` टाइप की वैल्यू के साथ `Double` इस्तेमाल कर सकते हैं।

### `cmp.Ordered` कंस्ट्रेंट

स्टैंडर्ड लाइब्रेरी [`cmp` पैकेज][doc-cmp] में `cmp.Ordered` कंस्ट्रेंट देती है। `cmp.Ordered` कंस्ट्रेंट उन सभी टाइप को अनुमति देता है जो तुलना ऑपरेटर `<`, `<=`, `>` और `>=` सपोर्ट करते हैं।

## जेनेरिक टाइप

आप टाइप पैरामीटर का इस्तेमाल जेनेरिक टाइप, जैसे स्ट्रक्ट, बनाने के लिए भी कर सकते हैं। यहाँ एक जेनेरिक `Stack` डेटा स्ट्रक्चर का उदाहरण है:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

जेनेरिक टाइप का वेरिएबल घोषित करते समय आपको चौकोर ब्रैकेट में टाइप आर्गुमेंट देना होता है:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

टाइप इन्फरेंस केवल जेनेरिक फंक्शन के लिए काम करता है। जेनेरिक टाइप की वैल्यू बनाते समय आपको हमेशा टाइप आर्गुमेंट देना होता है।

## जेनेरिक्स कब इस्तेमाल करें

जेनेरिक्स एक शक्तिशाली फीचर है, लेकिन हर समस्या के लिए उनका इस्तेमाल करना ज़रूरी नहीं है।

इन स्थितियों में जेनेरिक्स का इस्तेमाल कीजिए:
- आप ऐसे डेटा स्ट्रक्चर बना रहे हैं, जैसे ट्री, लिंक्ड लिस्ट या कैश, जो किसी भी एलिमेंट टाइप के साथ काम करते हैं।
- आप ऐसे यूटिलिटी फंक्शन लिख रहे हैं जो किसी भी टाइप के स्लाइस या मैप पर काम करते हैं, जैसे फिल्टर करना, सॉर्ट करना या खोजना।
- आपको कई टाइप के लिए बिल्कुल एक जैसा इम्प्लीमेंटेशन चाहिए, और आप कंपाइल-टाइम टाइप सेफ्टी चाहते हैं।

इन स्थितियों में इसके बजाय इंटरफेस का इस्तेमाल कीजिए:
- आपका ध्यान अंडरलाइंग डेटा टाइप के बजाय व्यवहार और मेथड पर है। उदाहरण के लिए, अगर आप अलग-अलग टाइप के स्रोतों (फाइल, नेटवर्क, TTY) से डेटा पढ़कर प्रोसेस करना चाहते हैं, तो `func Process[T](src T)` के बजाय `func Process(src io.Reader)` इस्तेमाल करेंगे।
- अलग-अलग टाइप को अपना काम पूरा करने के लिए अलग-अलग मेथड इम्प्लीमेंटेशन चाहिए।
