# परिचय

स्टोरेज-क्लास स्पेसिफायर इस बात से जुड़े हैं कि वेरिएबल मेमोरी में कैसे रखे जाते हैं। इनका गहरा संबंध किसी वैल्यू की स्टोरेज अवधि से होता है, जिसे जीवनकाल भी कहा जाता है।

## auto: फंक्शन या ब्लॉक स्कोप वाले वेरिएबलो के लिए डिफॉल्ट स्टोरेज क्लास

चूँकि किसी ब्लॉक या फंक्शन के अंदर परिभाषित वेरिएबल डिफॉल्ट रूप से `auto` होते हैं, इसलिए इस शब्द का साफ़-साफ़ इस्तेमाल करना आम नहीं है। `auto` से अक्सर बचने की एक और वजह यह है कि C++ में इसका मतलब कुछ और होता है। जिन कोडबेस में C और C++ दोनों हैं, वहाँ `auto` स्टोरेज स्पेसिफायर से बचने पर भ्रम कम हो सकता है। किसी `auto` वेरिएबल का जीवनकाल उसके ब्लॉक में प्रवेश करने पर शुरू होता है और ब्लॉक से बाहर निकलने पर खत्म हो जाता है। ब्लॉक में प्रवेश करते समय `auto` वेरिएबल के लिए मेमोरी तो दी जाती है, _लेकिन उसमें कोई डिफॉल्ट वैल्यू नहीं होती_। इसका एक अपवाद वेरिएबल लेंथ ऐरे (VLA) हैं। VLA के लिए मेमोरी उसके ब्लॉक में जहाँ उसे घोषित या परिभाषित किया गया हो वहीं दी जाती है, और ब्लॉक से बाहर निकलने पर वह खत्म हो जाती है। किसी `auto` वेरिएबल को किसी भी मान्य एक्सप्रेशन से शुरुआती वैल्यू दी जा सकती है।

## static: वह स्टोरेज स्पेसिफायर जिसे static लिंकेज वाले प्रकार से भ्रमित नहीं करना चाहिए

किसी ब्लॉक या फंक्शन के बाहर परिभाषित वेरिएबल का स्कोप फाइल होता है और उसकी स्टोरेज अवधि हमेशा static होती है। फाइल स्कोप का मतलब है कि उसे फाइल में कहीं भी इस्तेमाल किया जा सकता है। static स्टोरेज का मतलब है कि वह प्रोग्राम का चलना शुरू होने से लेकर उसके खत्म होने तक मौजूद रहता है। अगर साफ़-साफ़ शुरुआती वैल्यू न दी जाए, तो `static` वेरिएबल को उसकी डिफॉल्ट शून्य वैल्यू दी जाती है। अगर फाइल स्कोप वाले वेरिएबल पर `static` लगा हो, तो वह `static` उसके लिंकेज को बताता है। `static` लगा फाइल स्कोप वेरिएबल इंटरनल लिंकेज रखता है, यानी उसे सिर्फ फाइल के अंदर ही इस्तेमाल किया जा सकता है। अगर कोई वेरिएबल किसी फंक्शन के अंदर, या फंक्शन के किसी ब्लॉक में परिभाषित है और उस पर `static` लगा है, तो उसकी स्टोरेज अवधि `static` होती है। उस `static` वेरिएबल की वैल्यू फंक्शन या ब्लॉक को बार-बार कॉल करने के बीच बनी रहती है।

अगले उदाहरण में हम दो `static` वेरिएबल काम करते हुए देखते हैं। पहला `count` वेरिएबल `print_stuff` फंक्शन के अंदर परिभाषित है और फंक्शन को बार-बार कॉल करने पर भी अपनी वैल्यू बनाए रखता है। दूसरा `count` वेरिएबल एक मनमाने ब्लॉक के अंदर परिभाषित है और अपने ब्लॉक में पहले `count` वेरिएबल को छिपा देता है (यानी शैडो कर देता है)। दूसरा `count` वेरिएबल ब्लॉक में दोबारा प्रवेश करने पर स्वतंत्र रूप से अपनी वैल्यू बनाए रखता है।

```c
#include <stdio.h>

void print_stuff(void) {
    // static variable is initialized to 0
    static int count;
    count++;
    printf("function count is %d\n", count);
    {
        // static variable is initialized to 0
        static int count;
        count++;
        printf("block count is %d\n", count);
    }
}

int main() {
    // prints
    // function count is 1
    // block count is 1
    print_stuff();
    // prints
    // function count is 2
    // block count is 2    
    print_stuff();
}
```

अगर किसी `static` वेरिएबल को साफ़-साफ़ शुरुआती वैल्यू दी जाए, तो वह किसी कॉन्स्टेंट एक्सप्रेशन से ही दी जानी चाहिए। कॉन्स्टेंट एक्सप्रेशन वह होता है जिसका मूल्यांकन कंपाइल समय पर ही किया जा सके।

## extern: किसी दूसरी ट्रांसलेशन यूनिट में मौजूद वेरिएबल का इस्तेमाल कैसे करें

एक ट्रांसलेशन यूनिट में एक सोर्स फाइल और वे सभी फाइलें शामिल होती हैं जिन्हें वह `#include` करती है। फाइल स्कोप वाले वेरिएबल को `extern` के रूप में घोषित किया जा सकता है और उसे शुरुआती वैल्यू दी जा सकती है, फिर भी `extern` कीवर्ड आमतौर पर किसी पहले से मौजूद वेरिएबल को इंगित करने के लिए इस्तेमाल होता है, न कि नया वेरिएबल परिभाषित करने के लिए। `extern` से इंगित वेरिएबल का स्कोप फाइल होना चाहिए। फाइल स्कोप वाले वेरिएबल की स्टोरेज हमेशा `static` होती है। किसी इंक्लूड की गई फाइल में मौजूद वेरिएबल का एक्सटर्नल लिंकेज होना ज़रूरी है, ताकि उसे इंक्लूड करने वाली फाइल इस्तेमाल कर सके।

अगले उदाहरण में हम `extern` के रूप में घोषित वेरिएबल `val` का इस्तेमाल करते हैं, ताकि वह उसी फाइल स्कोप में परिभाषित `val` को इंगित करे। `extern` के दोनों इस्तेमाल रेफरेंसिंग डिक्लेरेशन कहलाते हैं, क्योंकि वे कहीं और परिभाषित वेरिएबल का संदर्भ देते हैं।

```c
#include <stdio.h>

void set_val() {
    // this declares val which is defined elsewhere
    extern int val;
    val += 42;
    // prints val is 42
    printf("val is %d\n", val);
}

int main() {
    set_val();
    // this declares val which is defined elsewhere
    extern int val;
    val += 42;
    // prints val is 84
    printf("val is %d\n", val);
}
// this value could be defined in another source file.
// as a variable with static storage, it is initialized to zero
int val;
```

अगर दोनों `extern` कीवर्ड हटा दिए जाएँ, तो प्रोग्राम कुछ ऐसा छाप सकता है

```
val is 22038
val is 42
```

ऐसा आउटपुट दिखाता है कि `extern` के बिना `val` का हर घोषण एक डिफाइनिंग डिक्लेरेशन है और `val` के बाकी घोषणों से स्वतंत्र है। अगर `set_val` और `main` से `val` की घोषणाएँ पूरी तरह हटा दी जाएँ, तो कंपाइल एरर आएगी कि `set_val` और `main` में `val` घोषित नहीं है।

अगर `extern` से इंगित वेरिएबल उसी फाइल में हो, तो उसका लिंकेज इंटरनल या एक्सटर्नल, दोनों में से कोई भी हो सकता है। `val` को `static int val;` के रूप में परिभाषित करने से `set_val` या `main` में `val` के इस्तेमाल पर कोई फर्क नहीं पड़ेगा, बस कंपाइल होने के लिए उस परिभाषा को इन दोनों के ऊपर ले जाना पड़ेगा। लेकिन अगर `val` इन फंक्शनों के ऊपर परिभाषित होता, तो इन्हें `val` को `extern` घोषित करने की ज़रूरत ही न पड़ती।

नीचे दिया गया कोड काम करेगा

```c
#include <stdio.h>

// val defining declaration before the function definitions
static int val;

void set_val() {
    val += 42;
    // prints val is 42
    printf("val is %d\n", val);
}

int main() {
    set_val();
    val += 42;
    // prints val is 84
    printf("val is %d\n", val);
}
```

`static int val;` से `static` हटाया जा सकता है, जिससे `val` को एक्सटर्नल लिंकेज मिल जाएगा, और तब भी `set_val` और `main` में `val` पहले जैसा ही काम करेगा। अगर कोई दूसरी सोर्स फाइल इस फाइल को इंक्लूड करती, तो वह `val` का इस्तेमाल तभी कर पाती जब `val` का लिंकेज एक्सटर्नल होता (यानी `static` घोषित न होता) और उस दूसरी फाइल में `extern int val;` घोषित होता।

`extern` से इंगित वेरिएबल की स्टोरेज `static` होनी ही चाहिए, साथ ही उसका स्कोप भी फाइल होना चाहिए। नीचे दिया गया उदाहरण शायद ही कंपाइल होगा, क्योंकि `val` `static` होते हुए भी फाइल स्कोप में नहीं है।

```c
#include <stdio.h>

void set_val() {
    // defined with static storage, but not in file scope
    static int val;
    val += 42;
    printf("val is %d\n", val);
}

int main() {
    set_val();
    extern int val;
    printf("val is %d\n", val);
}
```

## register: किसी वेरिएबल तक पहुँच को शायद तेज़ कैसे बनाएँ

`register` लगा वेरिएबल प्रोग्रामर की यह चाहत जताता है कि वैल्यू तेज़ पहुँच के लिए रजिस्टर में रखी जाए। `register` वेरिएबल `auto` वेरिएबल जैसा ही है, क्योंकि यह भी फंक्शन या ब्लॉक स्कोप में ही हो सकता है। चूँकि वैल्यू को मेमोरी के बजाय रजिस्टर में रखने का इरादा होता है, कंपाइलर को वेरिएबल के एड्रेस तक पहुँचने की अनुमति नहीं देनी चाहिए, क्योंकि रजिस्टर का एड्रेस नहीं लिया जा सकता। लेकिन मेमोरी एड्रेस खुद रजिस्टर में रखा जा सकता है। नीचे दिया गया उदाहरण यह दिखाता है

```c
#include <stdio.h>

int main() {
    int i = 42;
    register int *i_ptr = &i;
    // prints i is 42, i_ptr is 0x7ffd0c2055c4 (or some other address)
    printf("i is %d, i_ptr is %p", i, i_ptr);
}
```

register` असल में सिर्फ एक संकेत है, क्योंकि कंपाइलर खुद तय करते हैं कि इस स्पेसिफायर का पालन करना है या नहीं, इसलिए वैल्यू वाकई रजिस्टर में रखी जाए या न रखी जाए, यह तय नहीं।

## typedef: वह स्टोरेज क्लास स्पेसिफायर जो असल में है ही नहीं

`typedef` को सिर्फ सिंटैक्स की वजह से स्टोरेज क्लास स्पेसिफायर कहा जाता है। वजह यह है कि एक स्टोरेज क्लास स्पेसिफायर का इस्तेमाल दूसरे स्टोरेज क्लास स्पेसिफायर के साथ नहीं किया जा सकता। इसलिए `typedef auto int i = 42;` उतना ही अवैध है जितना `static auto int i = 42;`.
