# परिचय

## टेल कॉल ऑप्टिमाइज़ेशन

हर बार जब किसी फंक्शन को कॉल किया जाता है, तो मेमोरी में एक नया स्टैक फ्रेम बनाया जाता है, जिसमें फंक्शन के आर्गुमेंट और स्थानीय वेरिएबल रखे जाते हैं। फंक्शन के लौटने पर यह स्टैक फ्रेम मुक्त कर दिया जाता है। चूँकि Gleam लूपिंग सिंटैक्स के बजाय रिकर्सिव फंक्शन कॉल का उपयोग करता है, इसलिए इन स्टैक फ्रेम से बहुत अधिक मेमोरी का उपयोग हो सकता है।

इस समस्या से बचने के लिए Gleam टेल कॉल ऑप्टिमाइज़ेशन का समर्थन करता है, जो कंपाइलर को यह सुविधा देता है कि यदि किसी फंक्शन में आखिरी काम फंक्शन कॉल ही हो, तो वह वर्तमान फंक्शन के स्टैक फ्रेम का दोबारा उपयोग कर सके। इसका मतलब है कि कोई फंक्शन बिना किसी अतिरिक्त मेमोरी के खुद को अनंत बार कॉल कर सकता है।

अनऑप्टिमाइज़्ड रिकर्सिव फंक्शनों को अक्सर एक _एक्युमुलेटर_ का उपयोग करके टेल कॉल ऑप्टिमाइज़्ड फंक्शनों में दोबारा लिखा जा सकता है।

एक्युमुलेटर एक वेरिएबल होता है जो डेटा के अतिरिक्त भी साथ भेजा जाता है। इसका उपयोग फंक्शन के चलने की वर्तमान स्थिति को तब तक भेजने के लिए किया जाता है जब तक कि बेस केस तक न पहुँच जाए।

एक्युमुलेटर को फंक्शन के लेखक द्वारा इनिशियलाइज़ किया जाना चाहिए, न कि फंक्शन के उपयोगकर्ता द्वारा। इसे पाने के लिए दो फंक्शन घोषित कीजिए: एक पब्लिक फंक्शन, जो केवल आवश्यक डेटा को आर्गुमेंट के रूप में लेता है और एक्युमुलेटर को इनिशियलाइज़ करता है; और एक प्राइवेट फंक्शन, जो एक्युमुलेटर भी लेता है।

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
