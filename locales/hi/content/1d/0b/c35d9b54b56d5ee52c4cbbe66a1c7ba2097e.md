# विवरण

C# में _क्लास_ का एक पदानुक्रम _इनहेरिटेंस_ की मदद से बनाया जा सकता है। इससे एक व्युत्पन्न क्लास (`Car`) अपने पैरेंट क्लास (`Vehicle`) के व्यवहार और डेटा को इनहेरिट कर सकती है। अगर कोई पैरेंट तय नहीं किया गया हो, तो यह क्लास `object` क्लास से इनहेरिट करती है।

पैरेंट क्लासें व्युत्पन्न क्लासों को तीन तरीकों से कार्यक्षमता दे सकती हैं:

- एक सामान्य मेथड बनाना।
- एक [`virtual` मेथड][virtual-keyword] बनाना, जो सामान्य मेथड जैसा ही होता है, बस व्युत्पन्न क्लासें उसे _बदल_ सकती हैं।
- एक [`abstract` मेथड][abstract-keyword] बनाना, यानी ऐसा मेथड जिसका कोई कार्यान्वयन नहीं होता और जिसे व्युत्पन्न क्लासों को _ज़रूरी_ रूप से लागू करना होता है। जिन क्लासों में `abstract` मेथड होते हैं, उन्हें भी [`abstract`][abstract-classes] के रूप में चिह्नित करना ज़रूरी है। एब्सट्रैक्ट क्लासों का ऑब्जेक्ट नहीं बनाया जा सकता।

[`protected` एक्सेस मॉडिफायर][protected-keyword] पैरेंट क्लास के किसी सदस्य तक व्युत्पन्न क्लास में पहुँचने की अनुमति देता है, लेकिन दूसरी क्लासों की पहुँच रोक देता है। इस तरह व्युत्पन्न क्लासें पैरेंट क्लास के `public` और `protected` सदस्यों तक पहुँच सकती हैं, लेकिन `private` सदस्यों तक नहीं।

व्युत्पन्न क्लासें [`base` कीवर्ड][base-keyword] के ज़रिए पैरेंट क्लास के सदस्यों तक पहुँच सकती हैं।

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

व्युत्पन्न क्लास का कंस्ट्रक्टर, अपने कंस्ट्रक्टर का कोड चलाने से _पहले_, [अपने पैरेंट के कंस्ट्रक्टर को अपने आप कॉल कर लेता है][constructors]। [`base` कीवर्ड][base-keyword-constructor] की मदद से पैरेंट क्लास के कंस्ट्रक्टर को आर्गुमेंट पास किए जा सकते हैं। चूँकि एब्सट्रैक्ट क्लासों का ऑब्जेक्ट नहीं बनाया जा सकता, इसलिए इनके कंस्ट्रक्टरों को `protected` बनाया जा सकता है।

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

अगर एक बेस क्लास से एक से अधिक क्लासें व्युत्पन्न हों, तो वे दो (या अधिक) सब-क्लासें अक्सर बेस क्लास के मेथड के अलग-अलग रूप लागू करती हैं। यह एक बहुत ज़रूरी सिद्धांत है, जिसे [पॉलिमॉर्फिज़्म][polymorphism] कहते हैं। उदाहरण के लिए, ऊपर के उदाहरण में थोड़ा बदलाव करके हम दिखाते हैं कि `Vehicle` का इस्तेमाल करने वाला कोड, किस तरह का वाहन बनाया गया है, उसके हिसाब से अपना व्यवहार कैसे बदल सकता है।

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

किसी क्लास को इनहेरिट होने से रोकने के लिए [`sealed` मॉडिफायर][sealed-classes] जोड़िए।
कुछ डेवलपर कंक्रीट क्लासों से इनहेरिट करने से बचने की कोशिश करते हैं (जैसा [इस SO प्रश्न][pro-sealed] में बताया गया है), और _sealed_ मॉडिफायर इस तरीके का समर्थन करता है। दूसरी ओर, बहुत से C# डेवलपर इन्हें रखरखाव में बाधा मानते हैं, जैसा [इस प्रश्न][anti-sealed] पर कुछ टिप्पणियों में बताया गया है। सलाह यह है कि जब तक आपको अपनी ज़रूरतों के लिए इनके इस्तेमाल पर भरोसा न हो जाए, तब तक `sealed` मॉडिफायर का इस्तेमाल कम ही कीजिए।

नीचे दिया गया [लेख][new-vs-override] बताता है कि `override` मॉडिफायर के विकल्प के रूप में `new` का इस्तेमाल भी किया जा सकता है। यह कभी-कभी काम आता है, जैसे जटिल क्लास पदानुक्रमों में या लाइब्रेरीज़ के आपसी टकराव जैसी किसी स्थिति में।
