# परिचय

किसी वैल्यू को भेजने के लिए तैयार करने में एक साथ तीन चीज़ें शामिल हैं: उसे सीरियलाइज़ करना, उसमें से सही हिस्सा चुनना, और ज़रूरत न होने पर कॉपी न बनाना। इन तीनों के लिए Factor में तीन तरीके हैं।

## `unparse`: वैल्यू से सोर्स

[`unparse`][unparse] (`prettyprint` में) किसी भी वैल्यू का सोर्स रूप वाला टेक्स्ट लौटाता है। यह पार्सर का उल्टा है: `dup unparse parse` राउंड-ट्रिप वैल्यू को फिर से बना देता है।

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

इसकी तुलना `>string` (जो सिर्फ अक्षरों के क्रम पर काम करता है) और `number>string` (सिर्फ संख्याओं पर) से कीजिए। `unparse` हर चीज़ पर काम करता है, बस इसकी एक कीमत है: यह Factor सिंटैक्स बनाता है (कोटेशन वाली स्ट्रिंग अपने कोटेशन बनाए रखती है)। इसलिए जब टेक्स्ट पाने वाला उसे वापस पार्स करेगा तब यह सही टूल है, और इंसानों के पढ़ने लायक आउटपुट के लिए यह गलत टूल है।

## स्लाइस: कॉपी नहीं, व्यू

| वर्ड | काम |
|------|-----|
| `head` | `( seq n -- newseq )`: पहले n की कॉपी बनाता है |
| `head-slice` | `( seq n -- slice )`: पहले n का व्यू |
| `tail` | `( seq n -- newseq )`: इंडेक्स n से आगे की कॉपी बनाता है |
| `tail-slice` | `( seq n -- slice )`: इंडेक्स n से आगे का व्यू |
| `head*` | `( seq n -- newseq )`: अंतिम n को छोड़कर बाकी सब की कॉपी बनाता है |
| `head-slice*` | `( seq n -- slice )`: अंतिम n को छोड़कर बाकी सब का व्यू |
| `tail*` | `( seq n -- newseq )`: अंतिम n की कॉपी बनाता है |
| `tail-slice*` | `( seq n -- slice )`: अंतिम n का व्यू |

`slice` एक टपल होता है जिसमें एक शुरुआती इंडेक्स, एक अंतिम इंडेक्स और मूल सीक्वेंस रखे होते हैं। यह [सीक्वेंस प्रोटोकॉल][sequence-protocol] लागू करता है, इसलिए सीक्वेंस का कोई भी ऑपरेशन इस पर काम करता है। जब आपको सिर्फ पढ़ने के लिए नई जगह बनानी पड़े, तब स्लाइस वाले रूप चुनिए। और जब मूल सीक्वेंस बदल जाने के बाद भी डेटा अपने पास रखना हो, तब कॉपी करने वाले रूप चुनिए।

## कई इनपुट वाला क्लीव: `2bi`, `3bi`, `2tri`, `3tri`

सादे क्लीव वर्ड `bi` और `tri` स्टैक पर *एक* इनपुट पर दो या तीन कोटेशन लगाते हैं। `2` वाले और `3` वाले रूप हर कोटेशन को *दो* या *तीन* इनपुट पर लगाते हैं:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

हर कोटेशन को *सारे* इनपुट मिलते हैं। इसलिए `2bi` तब इस्तेमाल कीजिए जब दोनों प्रोजेक्शन उस जोड़ी पर निर्भर हों, न कि तब जब आप वही प्रोजेक्शन हर इनपुट पर अलग-अलग लगाना चाहते हों (उसके लिए `bi@` है)।

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

*एक* ही कोटेशन को हर इनपुट पर अलग-अलग लगाने के लिए `bi@` (दो इनपुट) या `tri@` (तीन इनपुट) चुनिए। ये एक ही परिवार के हैं, बस आकार अलग है।
