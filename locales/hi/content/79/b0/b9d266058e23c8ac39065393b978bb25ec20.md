# इस बारे में

डायनामिक मेमोरी लाइब्रेरी फंक्शनो से बनाई जाती है। प्रोग्रामर इन फंक्शनो को प्रोग्राम चलने के समय मेमोरी आवंटित करने और मुक्त करने के लिए इस्तेमाल करता है।
चूँकि मेमोरी आवंटित करना और मुक्त करना प्रोग्रामर के हाथ में होता है, इसलिए डायनामिक मेमोरी उतनी ही सुरक्षित रहती है, जितना प्रोग्रामर मानवीय गलतियों से बचा रहता है।
इसी वजह से डायनामिक मेमोरी प्रोग्रामिंग बग का एक बड़ा स्रोत है और हैकिंग हमलों का बड़ा निशाना भी।

डायनामिक मेमोरी उन वेरिएबलो के लिए इस्तेमाल होती है जिनका आकार प्रोग्राम चलने के समय ही पता चलता है।
यह आम तौर पर ऐसे ऐरे के लिए काम आता है जिनके एलिमेंट की संख्या एक बार प्रोग्राम चलने से दूसरी बार चलने के बीच बदल सकती है।
वेरिएबल लेंथ ऐरे (VLA) ऐसे ऐरे संभालने का दूसरा तरीका है जिनके एलिमेंट का आकार केवल प्रोग्राम चलने के समय पता चलता है।
एक VLA स्वचालित स्टोरेज का इस्तेमाल करता है, यानी जिस ब्लॉक में उसे बनाया गया है, उससे बाहर निकलते ही उसकी मेमोरी नष्ट हो जाती है।
(स्टोरेज के बारे में और जानने के लिए [स्टोरेज क्लास स्पेसिफायर](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers) कॉन्सेप्ट देखिए।)
VLA को C भाषा में C99 ने जोड़ा था, लेकिन C11 से VLA वैकल्पिक हो गए, इसलिए C11 और उसके बाद के मानकों का सपोर्ट करने वाले कंपाइलर के लिए VLA का सपोर्ट करना ज़रूरी नहीं है।
वेरिएबल लेंथ ऐरे का विस्तृत विश्लेषण इस लेख के दायरे से बाहर है।

## malloc

`malloc` एक फंक्शन है जो `stdlib.h` में घोषित है और डायनामिक मेमोरी आवंटित करने के लिए इस्तेमाल होता है।
अगर आवंटन सफल होता है, तो एक पॉइंटर लौटाया जाता है जो आवंटित मेमोरी के पहले बाइट का पता बताता है।
अगर आवंटन सफल नहीं होता, तो `NULL` लौटाया जाता है।
`malloc` का नतीजा `NULL` है या नहीं, यह जाँच लेना और नाकाम होने पर उसे सलीके से संभाल लेना समझदारी है।
लौटाया गया पॉइंटर `pointer-to-void` टाइप का होता है। इसे मोटे तौर पर एक "जेनेरिक" पॉइंटर मान सकते हैं, जिसे उस मेमोरी में इस्तेमाल होने वाले खास टाइप में बदला जा सकता है।
`malloc` में एक पैरामीटर होता है, जो चाही गई मेमोरी का आकार बाइट में बताता है।
किसी ऐरे को आवंटित करने का कुल आकार हर एलिमेंट के डेटा टाइप के आकार को एलिमेंट की संख्या से गुणा करके निकाला जाता है।
हर एलिमेंट के डेटा टाइप का आकार पाने के लिए आम तौर पर `sizeof` ऑपरेटर इस्तेमाल किया जाता है।
नीचे दिया गया उदाहरण इसे दिखाता है।

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

यह याद रखना ज़रूरी है कि `malloc` से नई आवंटित मेमोरी इनिशियलाइज़ नहीं होती, बल्कि उसमें कचरा वैल्यू पड़ी हो सकती हैं।
ध्यान दीजिए कि `numbers` पॉइंटर के `sizeof` का मतलब न ऐरे के एलिमेंट की संख्या है, न आवंटित की गई कुल मेमोरी।
`malloc` जो पॉइंटर लौटाता है, उसका आकार उस खास सिस्टम पर किसी भी पॉइंटर के आकार जितना होता है।
उदाहरण का कोड 64-बिट सिस्टम पर चलाया गया था, इसलिए पॉइंटर का आकार 8 बाइट था (8 बिट प्रति बाइट से गुणा करने पर = 64 बिट)।
पॉइंटर का टाइप अपने आप pointer-to-void से pointer-to-int में बदल गया।
pointer-to-int किसी अकेले `int` की ओर इशारा करता है या `ints` के ऐरे की ओर, यह प्रोग्रामर अपनी ज़रूरत के हिसाब से तय कर सकता है।
उदाहरण के लिए

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

अगर वैल्यू पढ़े जाने से पहले पक्का लिखी जाएगी, तो मेमोरी आवंटित करने का `malloc` एक कारगर तरीका हो सकता है।
लेकिन अगर वैल्यू इनिशियलाइज़ होने से पहले पढ़े जाने की कोई गुंजाइश है, तो `malloc` का इस्तेमाल जोखिम भरा है।
मेमोरी आवंटित करने का ज़्यादा सुरक्षित तरीका `calloc` है, जो नई आवंटित मेमोरी को शून्य से इनिशियलाइज़ कर देता है।

ऊपर के उदाहरणों में ध्यान दीजिए कि `free(numbers)` इस्तेमाल किया गया था।

## free

`free` एक फंक्शन है जो `stdlib.h` में घोषित है और डायनामिक रूप से आवंटित की गई मेमोरी को मुक्त करने के लिए इस्तेमाल होता है।
डायनामिक रूप से आवंटित मेमोरी `free` से मुक्त होने तक सिस्टम के कब्ज़े में बनी रहती है।
कुछ ऑपरेटिंग सिस्टम प्रोग्राम खत्म होने पर डायनामिक रूप से आवंटित मेमोरी अपने आप मुक्त कर देते हैं, लेकिन उस पर निर्भर न रहना ही अच्छा तरीका है।
`free` में एक पैरामीटर होता है, जो डायनामिक रूप से आवंटित की गई मेमोरी का पॉइंटर होता है।
`free` का इस्तेमाल करना या न करना कई मेमोरी समस्याओं से जुड़ा है।

#### मेमोरी लीक

अगर डायनामिक रूप से आवंटित मेमोरी का रेफरेंस अपने जीवनकाल के अंत तक पहुँच जाता है या किसी और तरह नष्ट हो जाता है, और उसके बाद भी मेमोरी मुक्त न की जाए, तो इसे मेमोरी लीक कहा जाता है।
लीक हुई मेमोरी वह मेमोरी है जो सिस्टम के कब्ज़े में तो रहती है, लेकिन प्रोग्राम की पहुँच से बाहर हो जाती है।
यह खास तौर पर तब समस्या बनती है जब किसी लूप के अंदर मेमोरी आवंटित की जाए, लूप के अंत में उसे मुक्त न किया जाए, और लूप की शुरुआत में फिर मेमोरी आवंटित की जाए।
अगर बिना मुक्त किए बहुत सारी मेमोरी आवंटित कर दी जाए, तो आवंटित करने के लिए पर्याप्त मेमोरी बचे बिना आगे का आवंटन नाकाम हो जाएगा।
यह याद रखना ज़रूरी है कि डायनामिक रूप से आवंटित मेमोरी पर मुक्त होने तक सिस्टम का कब्ज़ा बना रहता है, लेकिन जिस पॉइंटर को वह असाइन की जाती है, उसका स्कोप सिर्फ ब्लॉक तक सीमित हो सकता है।
जैसे `malloc` के उदाहरणों में मेमोरी `my_function` के अंदर आवंटित होती है।
अगर उस मेमोरी का पॉइंटर लौटाया न जाता और `main` में `numbers` पॉइंटर सेट करने के लिए इस्तेमाल न होता, तो वह मेमोरी लीक हो जाती।
इस तरह उस `numbers` पॉइंटर को `free` को देने पर `my_function` में आवंटित मेमोरी मुक्त हो जाती है।

#### यूज़ आफ़्टर फ्री (**UAF**)

अगर मेमोरी मुक्त होने के बाद उसे पढ़ा जाए, तो उसमें कुछ भी हो सकता है।
नीचे के उदाहरण में `numbers` जिस मेमोरी की ओर इशारा करता है, उसे मुक्त किया जाता है और फिर `printf` में पढ़ा जाता है।

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

मुक्त होने के बाद `numbers` पॉइंटर को डैंगलिंग पॉइंटर कहा जाता है।
एक डैंगलिंग पॉइंटर उस मेमोरी के अलावा किसी और मेमोरी की ओर इशारा कर सकता है, जिसके लिए उसे बनाया गया था।
इस तरह एक डैंगलिंग पॉइंटर डेटा खराब होने और मनमाने कोड को डालकर चलाए जाने का कारण बन सकता है।
आवंटित मेमोरी का जो पॉइंटर `NULL` सेट करके साफ़ नहीं किया गया हो, उसका इस्तेमाल प्रोग्राम को हैक करने के लिए किया जा सकता है।
ऊपर के उदाहरण में अगर मुक्त करने के बाद `numbers` को इस तरह `NULL` सेट किया जाता: `numbers = NULL;`, तो अगला `printf` प्रोग्राम को बंद कर देता और `numbers[0]` पढ़ने की कोशिश में शायद सेगमेंटेशन फॉल्ट भी बताता।

#### डबल फ्री

अगर डायनामिक रूप से आवंटित मेमोरी के पॉइंटर पर `free` दो बार कॉल किया जाए, तो इसका नतीजा अपरिभाषित व्यवहार (**UB**) होता है।
यानी कंपाइलर इसे अपनी मर्ज़ी से किसी भी तरह संभाल सकता है।
नीचे दिया गया उदाहरण दो अलग-अलग कंपाइलर से कंपाइल करने पर दो अलग नतीजे दे सकता है।

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

जब हर `free` कॉल के बीच `numbers` को `NULL` सेट किया गया, तो पहले और दूसरे कंपाइलर ने कोई रनटाइम एरर नहीं दी, लेकिन तीसरे कंपाइलर के साथ यही बात पक्की नहीं है।
डबल फ्री की एक आम वजह यह है कि दो पॉइंटर एक ही डायनामिक रूप से आवंटित मेमोरी की ओर इशारा करें।
प्रोग्राम में कहीं एक पॉइंटर ऐरे के शुरू की ओर इशारा कर सकता है, और कहीं दूसरा पॉइंटर उसी ऐरे पर एक-एक करके आगे बढ़ने के लिए इस्तेमाल हो सकता है।
प्रोग्राम में अलग-अलग जगहों पर दोनों पॉइंटर मुक्त कर दिए जाते हैं, जिससे डबल फ्री हो जाता है।

## calloc

`calloc` एक फंक्शन है जो `stdlib.h` में घोषित है और डायनामिक मेमोरी आवंटित करने तथा नई आवंटित मेमोरी को शून्य से इनिशियलाइज़ करने, दोनों कामों के लिए इस्तेमाल होता है।
अगर आवंटन सफल होता है, तो एक पॉइंटर लौटाया जाता है जो आवंटित मेमोरी के पहले बाइट का पता बताता है।
अगर आवंटन सफल नहीं होता, तो `NULL` लौटाया जाता है।
`calloc` का नतीजा `NULL` है या नहीं, यह जाँच लेना और नाकाम होने पर उसे सलीके से संभाल लेना समझदारी है।
लौटाया गया पॉइंटर `pointer-to-void` टाइप का होता है। इसे मोटे तौर पर एक "जेनेरिक" पॉइंटर मान सकते हैं, जिसे उस मेमोरी में इस्तेमाल होने वाले खास टाइप में बदला जा सकता है।
`calloc` में दो पैरामीटर होते हैं।
पहला पैरामीटर बताता है कि बताए गए डेटा टाइप की कितनी संख्या आवंटित करनी है।
दूसरा पैरामीटर बताता है कि आवंटित किए जाने वाले बताए गए डेटा टाइप का आकार क्या है।

नीचे के उदाहरण में सभी `printf` स्टेटमेंट हमेशा `0` दिखाने चाहिए, क्योंकि `calloc` नई आवंटित वैल्यू को पक्का शून्य कर देता है।

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` एक फंक्शन है जो `stdlib.h` में घोषित है और पहले से आवंटित मेमोरी को बढ़ाने या घटाने, दोनों के लिए इस्तेमाल होता है।
अगर पुनः आवंटन सफल होता है, तो एक पॉइंटर लौटाया जाता है जो फिर से आवंटित मेमोरी के पहले बाइट का पता बताता है।
अगर पुनः आवंटन सफल नहीं होता, तो `NULL` लौटाया जाता है।
`realloc` का नतीजा `NULL` है या नहीं, यह जाँच लेना और नाकाम होने पर उसे सलीके से संभाल लेना समझदारी है।
`realloc` में दो पैरामीटर होते हैं।
पहला पैरामीटर उस मौजूदा मेमोरी का पॉइंटर है जिसे फिर से आवंटित करना है।
दूसरा पैरामीटर फिर से आवंटित होने वाली मेमोरी का आकार बाइट में बताता है।
मेमोरी बढ़ाने से पहले जो वैल्यू सेट की गई थीं, वे बनी रहती हैं।
यह याद रखना ज़रूरी है कि मेमोरी बढ़ाते समय जोड़ी गई मेमोरी शून्य से इनिशियलाइज़ नहीं होती और उसमें कुछ भी हो सकता है।
साथ ही, मेमोरी घटाते समय हटाई गई मेमोरी भी इनिशियलाइज़ नहीं होती और उसमें पुरानी वैल्यू पड़ी रह सकती हैं।
नीचे दिया गया उदाहरण ऐरे को बढ़ाना और घटाना दिखाता है।

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## जब पास किया गया आकार 0 हो

अगर `malloc`, `calloc` या `relloac` को पास किया गया आकार `0` हो, तो क्या होगा यह इस पर निर्भर करता है कि कंपाइलर उसे कैसे लागू करता है।
कंपाइलर या तो `NULL` पॉइंटर लौटा सकता है या कोई नॉन-नल पॉइंटर।
जैसे अगर `char` के पॉइंटर के लिए मेमोरी आवंटित की जा रही हो, तो कंपाइलर या तो `NULL` लौटा सकता है या खाली स्ट्रिंग की ओर इशारा करने वाला नॉन-नल पॉइंटर।
अलग-अलग कंपाइलर से अलग-अलग नतीजे पाने से बचने के लिए बेहतर है कि आकार 0 से आवंटन न किया जाए।
