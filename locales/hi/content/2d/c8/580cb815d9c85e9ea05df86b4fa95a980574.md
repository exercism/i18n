# मूल बातें के बारे में

Kotlin एक स्टैटिकली टाइप्ड भाषा है, जिसे Java के साथ पूरी तरह मिलकर काम करने के लिए बनाया गया है।

Kotlin को Java से अलग बनाती हैं ये बातें:

- इसका सिंटैक्स ज़्यादा साफ और संक्षिप्त है;
- इसमें फंक्शनल भाषाओं की कई विशेषताएँ शामिल हैं;
- null हो सकने वाली वैल्यू के लिए इसमें व्यापक समर्थन है।

## वेरिएबल

चूँकि Kotlin स्टैटिकली टाइप्ड है, इसलिए कंपाइल के समय हर वैल्यू का टाइप _जानना_ ज़रूरी होता है।

लेकिन Kotlin का [टाइप इन्फरेंस][inference] बहुत शक्तिशाली है, इसलिए टाइप _बताना_ अक्सर ज़रूरी नहीं होता।

वेरिएबल घोषित करने के दो तरीके हैं।

1. `val` एक अपरिवर्तनीय वेरिएबल बनाता है, और उसे बदलने की कोशिश करने पर कंपाइल के समय एरर मिलती है।

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. `var` एक परिवर्तनीय वेरिएबल बनाता है।

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

अपरिवर्तनीय वेरिएबल आम गलतियों की एक पूरी किस्म को खत्म कर देते हैं, इसलिए जहाँ भी संभव हो `val` का उपयोग करने के लिए प्रोत्साहित किया जाता है।

साथ ही, एक `var` भी अपना टाइप नहीं बदल सकता:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

देखने में ध्यान भटकाने वाली चीज़ें कम करने के लिए, इस सिलेबस में स्पष्ट टाइप ज़्यादातर छोड़ दिए जाएँगे।
फिर भी, कम से कम इनके लिए टाइप बताने की सलाह दी जाती है:

- सार्वजनिक API
- फंक्शन सिग्नेचर
- जहाँ दस्तावेज़ीकरण की ज़रूरत हो

कुछ कंपनियाँ और संगठन सख्त टाइप सुरक्षा की माँग करते हैं और टाइप इन्फरेंस की अनुमति नहीं देते, जबकि कुछ इसे सिर्फ "आसान" टाइप तक सीमित रखते हैं, या टाइप इन्फरेंस को पूरी तरह अपना लेते हैं।

```kotlin
val x: Int = 42  // => 42
```

आम तौर पर वेरिएबल और फंक्शन के नाम `camelCase` में होने चाहिए, `snake_case` में नहीं।

## फंक्शन

किसी फंक्शन को `fun` कीवर्ड से घोषित कीजिए।
Java के विपरीत, फंक्शन का किसी क्लास का हिस्सा होना ज़रूरी नहीं है।

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

कुछ बातें ध्यान देने योग्य हैं:

- फंक्शन के नाम के बाद वे दो ब्रैकेट `()` ज़रूरी होते हैं, भले ही फंक्शन कोई आर्गुमेंट न लेता हो।
- फंक्शन के आर्गुमेंट में टाइप बताना ज़रूरी होता है: यहाँ टाइप इन्फरेंस नहीं होता (वेरिएबल के विपरीत)।
- फंक्शन के अंदर का कोड घुंघराले ब्रैकेट `{ }` के बीच रखा जाता है (हालाँकि नीचे भी देखिए)।
- अगर फंक्शन कोई वैल्यू लौटाता है, तो `return` कीवर्ड ज़रूरी है।
- लाइन के अंत में लगने वाला सेमीकोलन `;` ज़रूरी नहीं है, और आम तौर पर छोड़ दिया जाता है।
- अंकगणित के ऑपरेटर `+`, `-`, `*`, `/` ज़्यादातर प्रमुख भाषाओं के जैसे ही होते हैं।

लेकिन इन बहुत ही आसान, "सिंगल-एक्सप्रेशन" फंक्शन के लिए एक संक्षिप्त सिंटैक्स भी है:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
फंक्शन के पैरामीटर डिफाल्ट वैल्यू के साथ भी हो सकते हैं। 
अगर फंक्शन को कॉल करते समय इन्हें न दिया जाए, तो यही वैल्यू इस्तेमाल की जाती हैं:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

Exercism के फंक्शन आम तौर पर एक वैल्यू लौटाते हैं (क्योंकि टेस्ट रनर का ढाँचा ऐसा ही है)।
Kotlin का इस्तेमाल और जगहों पर करने के लिए यह जानना काम आ सकता है कि जो फंक्शन कोई वैल्यू नहीं लौटाता, वह रिटर्न टाइप और `return` कीवर्ड छोड़ सकता है।

तब ऐसे फंक्शन का रिटर्न टाइप `Unit` कहा जाता है, जो Java और कई दूसरी भाषाओं के `void` के बराबर है।

## कमेंट

सिंगल-लाइन कमेंट `//` से शुरू होते हैं, और उसके बाद की पूरी लाइन नज़रअंदाज़ कर दी जाती है।

मल्टी-लाइन कमेंट `/*` से शुरू होते हैं और `*/` पर खत्म होते हैं।

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

यह Java जैसा ही है।
