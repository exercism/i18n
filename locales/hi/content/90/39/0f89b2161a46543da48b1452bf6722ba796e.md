# Unison की मूल बातें

## टर्म और फंक्शन

टर्म और फंक्शन, Unison प्रोग्राम लिखने की मूल इकाइयाँ हैं।

हम स्थिर वैल्यू को "टर्म" कहते हैं। इसे `name = expression` से परिभाषित किया जाता है, और इससे पहले वैकल्पिक रूप से `name : MyType` रूप का टाइप सिग्नेचर लिखा जा सकता है। Unison टाइप इन्फरेंस का समर्थन करता है, इसलिए आसान परिभाषाओं में आप टाइप सिग्नेचर छोड़ा हुआ देख सकते हैं।

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison के फंक्शन `myFunctionName argument1 argument2 = myImplementation` जैसे दिखते हैं; ये फंक्शन के नाम से शुरू होते हैं और उसके बाद स्पेस से अलग किए गए आर्गुमेंट आते हैं।

```
getMax a b = Nat.max a b
```

फंक्शन में वैकल्पिक रूप से टाइप सिग्नेचर भी हो सकता है। दाईं ओर का अंतिम टाइप हमेशा फंक्शन का अंतिम रिटर्न टाइप होता है, और हर आर्गुमेंट को फंक्शन एरो `->` से अलग किया जाता है।

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

किसी फंक्शन को कॉल करने के लिए उसका नाम लिखिए और उसके बाद उसके आर्गुमेंट, जिन्हें सिर्फ स्पेस से अलग किया गया हो।

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

फंक्शन कॉल करते समय Unison जो कुछ भी ठीक दाईं ओर आता है उसे आर्गुमेंट मानने की कोशिश करता है, और इससे हमेशा फंक्शन के मूल्यांकन का मनचाहा क्रम नहीं बनता।

मान लीजिए हम नीचे दिए एक्सप्रेशन से वैल्यू `1` पाना चाहते हैं

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

जैसा यह लिखा गया है, `shouldBe1` का मान `0` आता है क्योंकि फंक्शन लगाने का निहित क्रम `getMax 1 10` है, जो `10` देता है, और फिर `10 - 10`, जो `0` देता है।

आप गोल ब्रैकेट की मदद से एक्सप्रेशन को क्रियाओं के मनचाहे क्रम में फिर से बाँट सकते हैं।

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## वॉच एक्सप्रेशन

Unison कोड को जल्दी मूल्यांकित करने का एक तरीका देता है, जिसे "वॉच एक्सप्रेशन" कहते हैं। वॉच एक्सप्रेशन `>` चिह्न से शुरू होता है और उसके बाद वह एक्सप्रेशन आता है जिसका मूल्यांकन करना है। वॉच एक्सप्रेशन किसी भी `.u` एक्सटेंशन वाली फाइल में लिखे जा सकते हैं। फाइल सेव करने पर आपको Unison Codebase Manager (UCM) कंसोल में दिख जाएगा कि एक्सप्रेशन का मान क्या आता है। इन डॉक्स में जहाँ संभव हो, हम एक्सप्रेशन को वॉच एक्सप्रेशन में मूल्यांकित करने के बाद उसका अपेक्षित आउटपुट दिखाने की कोशिश करेंगे।

```
> helloThere
  ⧩
  "Hello, World!"
```

## मल्टी-लाइन फंक्शन

Unison के मल्टी-लाइन फंक्शन कोड की सीमाएँ तय करने के लिए इंडेंटेशन या `let` ब्लॉक का उपयोग करते हैं, जिसे "लेक्सिकल स्कोप" कहते हैं।

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

एक ही इंडेंटेशन लेवल पर मौजूद हर चीज़ का स्कोप एक ही होता है, इसीलिए हम आखिरी लाइन में वेरिएबल `newBeginning` का संदर्भ दे सकते हैं।

## नेमस्पेस और `use` स्टेटमेंट

नेमस्पेस वह तरीका है जिससे हम Unison के फंक्शन को समूहित और व्यवस्थित करते हैं। आप इन्हें "डायरेक्टरी" जैसा मान सकते हैं। ये ढाँचा और तार्किक समूहीकरण देते हैं।

आप `use` स्टेटमेंट की मदद से किसी नेमस्पेस के फंक्शन को स्कोप में ला सकते हैं।

मान लीजिए आप एक फंक्शन लिख रहे हैं जो Unison की `List` वैल्यू का उपयोग करता है। आप जानते हैं कि आपको `List.map` और `List.flatMap` जैसे फंक्शन चाहिए, जहाँ `List` नेमस्पेस है और `map` तथा `flatMap` फंक्शन हैं। खुद को दोहराने से बचने के लिए आप अपने फंक्शन में `List` नेमस्पेस की हर चीज़ को इस तरह लेक्सिकल स्कोप में ला सकते हैं:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List` लाइन `map` और `flatMap` के संदर्भों की अस्पष्टता दूर करती है। आप [`use` स्टेटमेंट के बारे में यहाँ][use-statements] और पढ़ सकते हैं।

## Unison की स्टैंडर्ड लाइब्रेरी

Unison की स्टैंडर्ड लाइब्रेरी को `base` कहते हैं। अगर आपने क्विकस्टार्ट गाइड का पालन किया है और आपने लोकली कोडबेस बनाया है, तो स्टैंडर्ड लाइब्रेरी अपने आप डाउनलोड हो जानी चाहिए थी। आप स्टैंडर्ड लाइब्रेरी का डॉक्युमेंटेशन ऑनलाइन [Unison Share][unison-share-base] पर देख सकते हैं।

## कमेंट और डॉक्युमेंटेशन लिटरल

Unison में कमेंट एक ज़रा असामान्य फीचर है। Unison कोड लिखते समय आप अपनी `.u` एक्सटेंशन वाली फाइल में ऐसा टेक्स्ट बना सकते हैं जिसे इंटरप्रेट नहीं किया जाता, इस सिंटैक्स से:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_लेकिन_, चूँकि Unison कोड फाइल सिस्टम पर टेक्स्ट-आधारित फाइलों के रूप में नहीं, बल्कि अपने एब्स्ट्रैक्ट सिंटैक्स ट्री के हैश के रूप में सेव होता है, इसलिए फाइल में किसी Unison फंक्शन या टर्म के टेक्स्ट-आधारित "सजावट" वाले कमेंट वाकई सेव होकर साझा करने के लिए दोबारा रेंडर नहीं हो सकते। अगर आप अपने Unison टर्म में ऐसी जानकारी जोड़ना चाहते हैं जो दूसरों के पढ़ने और समझने के लिए संग्रहीत रहे, तो आप डॉक्युमेंटेशन लिटरल का उपयोग कर सकते हैं।

Unison प्रोग्रामिंग भाषा में डॉक्युमेंटेशन एक फर्स्ट-क्लास वैल्यू है। इसका मतलब है कि एक `Doc` एलिमेंट को किसी वैल्यू को असाइन किया जा सकता है, किसी फंक्शन को वैल्यू के रूप में पास किया जा सकता है, या फंक्शन की वैल्यू के रूप में लौटाया जा सकता है। डॉक्युमेंटेशन लिटरल एलिमेंट दोहरे कर्ली ब्रैकेट से खोले और बंद किए जाते हैं। यहाँ दिखाया गया है कि हम `Doc` एलिमेंट को कमेंट की तरह कैसे उपयोग कर सकते हैं।

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
