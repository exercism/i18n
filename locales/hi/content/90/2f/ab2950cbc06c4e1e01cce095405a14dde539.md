# कॉन्ट्रैक्ट

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| क्लॉज़ | क्या कहता है | टूटने पर गलती किसकी |
| --- | --- | --- |
| `pre` | प्रवेश के समय क्या सच होना चाहिए | कॉल करने वाले की |
| `post` | लौटते समय क्या सच होना चाहिए | रूटीन की |

दोनों एक `BOOL` लेते हैं, और दोनों रूटीन के आर्गुमेंट और ऑब्जेक्ट के एट्रिब्यूट इस्तेमाल कर सकते हैं। `post` `result` का भी इस्तेमाल कर सकता है, यानी उस वैल्यू का जो लौटाई जा रही है।

## assert

रूटीन के अंदर, `assert` बताता है कि उस जगह क्या सच होना चाहिए:

```sather
      assert load <= limit;
```

इसकी जाँच भी बाकी जाँचों की तरह उसी स्विच के तहत होती है।

## क्लास इनवेरिएंट

एक क्लास यह बता सकती है कि कॉलों के बीच उसके हर ऑब्जेक्ट के लिए क्या सच रहता है:

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

जाँच चालू होने पर हर पब्लिक रूटीन में प्रवेश और उससे निकास पर इसकी जाँच होती है।

## इसे चालू करना

| फ्लैग | क्या जाँचता है |
| --- | --- |
| `-chk` | सब कुछ: pre, post, assert, invariant, bounds, arithmetic |
| `-chk_no` | कुछ नहीं |

ध्यान दीजिए कि इस कंपाइलर में अकेला `-chk_pre` प्रीकंडीशन की जाँच चालू *नहीं* करता; `-chk` ही काम करता है। उल्लंघन होने पर रूटीन और सोर्स लाइन छापकर प्रोग्राम रोक दिया जाता है। यह कोई एक्सेप्शन नहीं है, और `protect` इसे नहीं पकड़ेगा।

आम तरीका यह है कि डेवलप और टेस्ट `-chk` के साथ किया जाए, और रिलीज़ इसके बिना, ताकि रिलीज़ हो चुके प्रोग्राम में इन जाँचों की कोई कीमत न पड़े। यह तभी फल देता है जब टेस्ट वाकई उन रास्तों को चलाते हों।

## अच्छा कॉन्ट्रैक्ट क्या होता है

बताइए कि रूटीन को क्या चाहिए, यह नहीं कि वह कैसे काम करता है:

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

जो `post` बॉडी को दोहरा देता है, वह किसी को कुछ नहीं सिखाता:

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## इनहेरिटेंस

एक सबटाइप `pre` को कमज़ोर कर सकता है और `post` को मज़बूत, यानी ज़्यादा स्वीकार करना और ज़्यादा वादा करना, लेकिन कभी उल्टा नहीं, वरना सुपरटाइप के हिसाब से लिखा गया कोड टूट जाएगा। यही वह नियम है जिसे जाँचने लायक बनाने के लिए कॉन्ट्रैक्ट होते हैं।
