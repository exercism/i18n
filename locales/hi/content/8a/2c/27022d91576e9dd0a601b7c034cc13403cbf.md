# परिचय

## एक्सेप्शन

Elixir में हर एरर _एक्सेप्शन बिहेवियर_ को कार्यान्वित करती है। _एक्सेस बिहेवियर_ की तरह ही _एक्सेप्शन बिहेवियर_ भी कुछ कॉलबैक फंक्शन बनाता है। बिहेवियर का सॉफ्टवेयर अनुबंध पूरा करने के लिए मॉड्यूल को ये फंक्शन कार्यान्वित करने पड़ते हैं। एक बार एरर बन जाने के बाद उसमें ये विशेषताएँ होती हैं:

- मॉड्यूल का नाम ही एरर का नाम तय करता है।
- मॉड्यूल एक एरर स्ट्रक्ट बनाता है।
- इस स्ट्रक्ट में `:message` फील्ड होता है।
- इच्छित एरर उठाने के लिए इस मॉड्यूल का उपयोग `raise/1` और `raise/2` के साथ किया जा सकता है।

_एक्सेप्शन बिहेवियर_ दो कॉलबैक भी तय करता है: `message/1` और `exception/1`। अगर इन्हें कार्यान्वित न किया जाए, तो पहले से मौजूद कार्यान्वयन इस्तेमाल हो जाते हैं। `raise` के साथ कॉल किए जाने पर `message/1` एरर स्ट्रक्ट को एक पढ़ने योग्य संदेश में बदल देता है। `raise/2` के साथ कॉल किए जाने पर `exception/1` संदेश में अतिरिक्त संदर्भ जोड़ने देता है।

### एक्सेप्शन बनाना

किसी एरर मॉड्यूल से एक्सेप्शन बनाने के लिए हम `defexception` मैक्रो का उपयोग करते हैं:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### एक्सेप्शन का उपयोग करना

बनाए गए एरर का उपयोग किसी अंतर्निहित एरर की तरह `raise/1` या `raise/2` से किया जा सकता है।

- `raise/1` किसी विशेष एरर को उसके मॉड्यूल नाम से उठाता है। अगर आर्गुमेंट एक स्ट्रिंग है, तो यह उस स्ट्रिंग को संदेश बनाकर एक `RuntimeError` उठाता है।
- `raise/2` किसी विशेष एरर को उसके मॉड्यूल नाम से उठाता है और एक एट्रिब्यूट्स आर्गुमेंट लेता है, जिससे उचित संदेश वाली एरर प्राप्त की जाती है।
