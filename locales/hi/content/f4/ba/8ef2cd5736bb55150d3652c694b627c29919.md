# एब्सट्रैक्ट क्लास

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## $ भी नाम का हिस्सा है

हर एब्सट्रैक्ट क्लास का नाम आगे `$` लगाकर रखा जाता है, और ऐसा सिर्फ एब्सट्रैक्ट क्लासों के साथ होता है। इसलिए जिस टाइप के नाम की शुरुआत `$` से होती है, उसका ऑब्जेक्ट आप बना ही नहीं सकते। यह बात हर उस जगह दिख जाती है जहाँ वह नाम आता है।

## इसमें क्या-क्या रह सकता है

इसमें रूटीन और इटरेटर के सिग्नेचर रह सकते हैं, जो सेमीकोलन पर खत्म होते हैं। कोई बॉडी नहीं, कोई एट्रिब्यूट नहीं, कोई `create` नहीं। एक एब्सट्रैक्ट क्लास यह बताती है कि किसी चीज़ से क्या *पूछा* जा सकता है, यह कभी नहीं कि उसके अंदर क्या रखा है।

## अनुरूपता

```sather
class TRAPEZE < $ACT is
```

क्लास को सूची में दिए गए हर रूटीन को बनाना ही होगा, और उसके आर्गुमेंट टाइप तथा रिटर्न टाइप भी वही होने चाहिए जो बताए गए हैं। इसकी जाँच कंपाइल करते समय की जाती है।

एक क्लास एक साथ कई एब्सट्रैक्ट क्लासों के अनुरूप हो सकती है:

```sather
class TRAPEZE < $ACT, $RISKY is
```

और एक एब्सट्रैक्ट क्लास किसी दूसरी एब्सट्रैक्ट क्लास के अनुरूप भी हो सकती है:

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## डिस्पैच कहाँ होता है

एब्सट्रैक्ट टाइप के वेरिएबल में किसी अनुरूप ऑब्जेक्ट का रेफरेंस रखा जाता है। उस पर कोई रूटीन कॉल करने पर रन टाइम पर ऑब्जेक्ट की असली क्लास वाला रूप चुना जाता है।

यही एक जगह है जहाँ Sather रन टाइम पर कुछ तय करता है। कंक्रीट टाइप के वेरिएबल पर किया गया कॉल कंपाइल करते समय ही तय हो जाता है।

## typecase

कभी-कभी यह सचमुच मायने रखता है कि चीज़ किस तरह की है। `typecase` पूछता है:

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

`typecase` की किसी एक ब्रांच के अंदर वेरिएबल का टाइप और संकरा हो जाता है। इसका इस्तेमाल कम ही कीजिए: हर तरह के act के लिए लिखा गया `typecase` आम तौर पर ऐसा रूटीन होता है जो शुरू से ही एब्सट्रैक्ट क्लास में होना चाहिए था।

## $OB

`$OB` वह एब्सट्रैक्ट क्लास है जिसके अनुरूप हर ऑब्जेक्ट होता है। यह कभी-कभार काम आती है, और ज़्यादातर यह संकेत होती है कि रास्ते में कहीं कोई टाइप खो गया है।

## इनहेरिटेंस क्यों नहीं?

Sather उन दो चीज़ों को अलग रखता है जिन्हें ज़्यादातर भाषाएँ जोड़ देती हैं। `<` सिर्फ यह बताता है कि एक क्लास क्या *कर* सकती है। कहीं और से इम्प्लीमेंटेशन लेना `include` है, जो अगले के बाद वाले अभ्यास में आता है, और यह एक अलग फैसला है।
