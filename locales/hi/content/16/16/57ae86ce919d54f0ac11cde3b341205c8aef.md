# निर्देश परिशिष्ट

## Node प्रोसेस

बाकी अभ्यासों से अलग, `grep.js` को टेस्ट फाइल `grep.spec.js` के अंदर इम्पोर्ट _नहीं_ किया जाता। इसके बजाय इसका इस्तेमाल ऐसे किया जाएगा जैसे यह कोई एक्ज़ीक्यूटेबल हो। इसे आसान बनाने के लिए `grep.js` फाइल को एक शीबैंग और एक कमेंट के साथ तैयार किया गया है, जो बताता है कि यह क्या करता है:

```javascript
#!/usr/bin/env node

// The above line is a shebang. On Unix-like operating systems, or environments,
// this will allow the script to be run by node, and thus turn this JavaScript
// file into an executable. In other words, to execute this file, you may run
// the following from your terminal:
//
// ./grep.js args
//
// If you do not have a Unix-like operating system or environment, for example
// Windows without WSL, you can use the following inside a window terminal,
// such as cmd.exe:
//
// node grep.js args
//
// Read more about shebangs here: https://en.wikipedia.org/wiki/Shebang_(Unix)
```

टेस्ट एक नया node प्रोसेस शुरू करते हैं, जो `grep.js` को चलाता है।

## आर्गुमेंट पढ़ना

जिन आर्गुमेंट के साथ प्रोसेस शुरू किया गया था, उन्हें पाने के लिए `process.argv` का उपयोग कीजिए।

## फाइलें पढ़ना

`readLines` फंक्शन पहले से दिया गया है। इसका उपयोग करने के लिए फाइल के पाथ को बदलने की ज़रूरत नहीं है। `readlines` फंक्शन मौजूदा वर्किंग डायरेक्टरी से पाथ को _रिज़ॉल्व_ करता है। `grep.js` प्रोसेस के लिए यह डायरेक्टरी अभ्यास डायरेक्टरी पर सेट की गई है।

## आउटपुट लिखना

आउटपुट लिखने के लिए इनका उपयोग कीजिए।

- स्टैंडर्ड आउटपुट स्ट्रीम पर लिखने के लिए `console.log` का उपयोग कीजिए,
- और स्टैंडर्ड एरर स्ट्रीम पर लिखने के लिए `console.error` का उपयोग कीजिए।

अगर स्टैंडर्ड एरर स्ट्रीम पर कुछ नहीं लिखा जाता, तो टेस्ट चलने को सफल (resolved) मानते हैं, और अगर स्टैंडर्ड एरर स्ट्रीम पर कुछ लिखा जाता है, तो उसे असफल (rejected) मानते हैं।
