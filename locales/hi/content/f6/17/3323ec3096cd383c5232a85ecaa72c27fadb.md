# परिचय

C भाषा में, [struct][struct] एक कंपोजिट टाइप होता है, जो अलग-अलग फील्ड से बना होता है।
हर फील्ड का अपना टाइप और आकार होता है।

उदाहरण के लिए, यह तीन पूर्णांकों से बना एक टाइप परिभाषित करता है, जिनमें दो 4 बाइट के और एक 8 बाइट का है:

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

struct में दूसरे struct भी हो सकते हैं:

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

अगर struct के किसी फील्ड का टाइप ऐरे है, तो ऐरे के लिए एलोकेट किए गए सभी बाइट struct का हिस्सा होते हैं।
लेकिन अगर फील्ड केवल ऐरे का पॉइंटर है, तो ऐरे को कहीं और संग्रहीत करना होगा:

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## अलाइनमेंट

किसी टाइप का [अलाइनमेंट][alignment] दो की गैर-ऋणात्मक घात (1, 2, 4, 8, ...) होता है, जो उसके पते पर एक आवश्यकता बताता है।
उस टाइप के हर ऑब्जेक्ट को ऐसे पते पर होना चाहिए जो उसके अलाइनमेंट का गुणज हो।

किसी प्रिमिटिव टाइप के लिए, अलाइनमेंट आम तौर पर उसके आकार के बराबर होता है, इसलिए, उदाहरण के लिए, एक `int32_t` का अलाइनमेंट आम तौर पर 4 बाइट का होता है।
इसका मतलब है कि `int32_t` को 4 बाइट की सीमाओं पर एलोकेट किया जाना चाहिए।

लेकिन struct का अलाइनमेंट उसके किसी भी फील्ड के अलाइनमेंट में से अधिकतम होता है।
इसलिए, उदाहरण के लिए, ऊपर परिभाषित `struct example` का अलाइनमेंट 8 बाइट का होगा, क्योंकि यही `uint64_t` का अलाइनमेंट है।

अगर किसी struct फील्ड का अलाइनमेंट struct के अलाइनमेंट से छोटा है, तो उस फील्ड के बाद पैडिंग बाइट जोड़े जा सकते हैं।
यह सुनिश्चित करता है कि आगे के फील्ड और पूरा struct अलाइनमेंट की आवश्यकताओं को पूरा करें।
व्यवहार में, इसका मतलब है कि हालाँकि वे पैडिंग बाइट struct के आकार में योगदान देते हैं, वे struct की वैल्यू में उपयोग नहीं होते:

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

ध्यान दें कि ऊपर परिभाषित struct में, फील्ड 'one_byte' का अलाइनमेंट 1 है और इसे किसी भी पते पर रखा जा सकता है।
चूँकि फील्ड 'four_byte' का अलाइनमेंट 4 है, struct के फील्ड को भी 4 बाइट की सीमाओं का पालन करना चाहिए।
इसका मतलब है कि struct में किन्हीं दो फील्ड के बीच बाइट की संख्या 4 का गुणज होनी चाहिए।
चूँकि 'one_byte' केवल 1 बाइट घेरता है, इसलिए इस सीमा का पालन करने के लिए उसके बाद 3 पैडिंग बाइट जोड़े जाते हैं।

आस-पास के फील्ड को जब भी संभव हो समूहित किया जाता है, ताकि ज़रूरी पैडिंग बाइट की संख्या कम से कम हो:

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

इस समूहन में हर फील्ड के अलाइनमेंट का भी पालन करना चाहिए:

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

इसका मतलब है कि struct में फील्ड का क्रम बदलने से कभी-कभी उसके आकार में अंतर आ सकता है:

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

ध्यान दें कि ऐरे का अलाइनमेंट उसके मूल टाइप के अलाइनमेंट के बराबर होता है:

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

ऐरे के एलिमेंट को उसी तरह समूहित किया जा सकता है जैसे वे ऐरे का हिस्सा न हों:

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

असेंबली में struct को एक्सेस करते समय किसी भी संभावित पैडिंग बाइट का ध्यान रखना ज़रूरी है।

## कॉलिंग कन्वेंशन

आम तौर पर, वैल्यू फंक्शन को उसी तरह पास की जाती हैं और फंक्शन से लौटाई जाती हैं जैसा आप अपेक्षा करेंगे:

- पूर्णांक वैल्यू, जिनमें मेमोरी एड्रेस और एनम शामिल हैं, जनरल-पर्पस रजिस्टर (GPR) में पास की जाती हैं।
- फ्लोटिंग-पॉइंट वैल्यू `xmm` रजिस्टर में पास की जाती हैं।

लेकिन struct एक खास मामला है।
आम तौर पर, struct के सभी फील्ड मेमोरी में आस-पास जगह घेरते हैं और जब भी संभव हो उन्हें एक ही रजिस्टर में रखा जाना चाहिए:

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

अगर struct में पूर्णांक वैल्यू वाले फील्ड और फ्लोटिंग-पॉइंट वैल्यू वाले फील्ड दोनों हैं, तो struct के हर लगातार 8 बाइट को अलग-अलग वर्गीकृत किया जाना चाहिए:

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

अगर पूर्णांक और फ्लोटिंग-पॉइंट वैल्यू एक ही 8 बाइट में हों, तो टाइप पूर्णांक माना जाता है और पूरी 8 बाइट (फ्लोटिंग-पॉइंट वैल्यू समेत) GPR में रखी जाती है:

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
जब `cvtss2si` या `cvtsd2si` का उपयोग करके फ्लोटिंग-पॉइंट से पूर्णांक में कन्वर्जन किया जाता है, तो इससे अंदरूनी बाइट का संगठन बदल जाता है।

आप `xmm` रजिस्टर से GPR में रॉ बाइट बिना बिट रिप्रेजेंटेशन बदले ले जाने के लिए [movd][mov] (32-बिट वैल्यू के लिए) या [movq][mov] (64-बिट वैल्यू के लिए) का उपयोग कर सकते हैं।

[mov]: https://www.felixcloutier.com/x86/movd:movq
~~~~

लेकिन 16 बाइट से बड़े struct आम तौर पर मेमोरी में रखे जाते हैं, चाहे हर 8 बाइट का टाइप कुछ भी हो:

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

जब किसी फंक्शन को आर्गुमेंट के रूप में struct पास किया जाता है, तो वह जितने रजिस्टर ज़रूरी हों उतने उपयोग करता है।
अगर इसे मेमोरी में रखा जाता है, तो इसके बजाय स्टैक का उपयोग होता है।

फंक्शन से लौटाए गए struct पर भी इसी तरह के नियम लागू होते हैं।
इन्हें आम तौर पर पहले `rax` और `rdx` में लौटाया जाता है (अगर पूर्णांक वैल्यू है) या `xmm0` और `xmm1` में (अगर फ्लोटिंग-पॉइंट वैल्यू है)।
लेकिन अगर इसे मेमोरी में रखा गया है, तो कॉलर को इसके लिए जगह आरक्षित करनी होती है और इस मेमोरी लोकेशन का पता फंक्शन को उसके पहले अंतर्निहित आर्गुमेंट के रूप में (`rdi` में) पास करना होता है।
फिर फंक्शन struct को इस जगह में संग्रहीत करता है और उसका पता `rax` में लौटाता है।
