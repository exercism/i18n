# Unison की मूल बातें

## टर्म और फंक्शन

Unison प्रोग्राम लिखने की मूल इकाइयाँ टर्म और फंक्शन हैं।

"टर्म" वह होता है जिसे हम स्टैटिक वैल्यू कहते हैं। इसे `name = expression` से बनाया जाता है, और इससे पहले वैकल्पिक रूप से `name : MyType` रूप का टाइप सिग्नेचर आ सकता है। Unison टाइप इनफेरेंस का समर्थन करता है, इसलिए सरल परिभाषाओं में टाइप सिग्नेचर छोड़ा हुआ दिख सकता है।

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison के फंक्शन `myFunctionName argument1 argument2 = myImplementation` जैसे दिखते हैं। इनमें सबसे पहले फंक्शन का नाम आता है, और उसके बाद स्पेस से अलग किए गए आर्गुमेंट।

```
getMax a b = Nat.max a b
```

फंक्शन में वैकल्पिक रूप से टाइप सिग्नेचर भी हो सकता है। दाईं ओर का अंतिम टाइप हमेशा फंक्शन का अंतिम रिटर्न टाइप होता है, और हर आर्गुमेंट को फंक्शन ऐरो `->` से अलग किया जाता है।

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

किसी फंक्शन को कॉल करने के लिए उसका नाम लिखिए और उसके बाद उसके आर्गुमेंट, जिन्हें केवल स्पेस से अलग किया जाता है।

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

फंक्शन कॉल करते समय Unison जो कुछ भी ठीक दाईं ओर आता है, उसे आर्गुमेंट मानने की कोशिश करता है। इससे फंक्शन के मूल्यांकन का मनचाहा क्रम हमेशा नहीं बनता।

मान लीजिए हम नीचे दिए गए एक्सप्रेशन से वैल्यू `1` पाना चाहते हैं

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

जैसा लिखा गया है, `shouldBe1` का मान `0` आता है, क्योंकि फंक्शन एप्लिकेशन का जो क्रम यहाँ माना जाता है वह `getMax 1 10` है, यानी `10`, और उसके बाद `10 - 10`, यानी `0`।

एक्सप्रेशन को मनचाहे क्रम में फिर से समूहित करने के लिए आप गोल ब्रैकेट का उपयोग कर सकते हैं।

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## वॉच एक्सप्रेशन

Unison कोड को तेज़ी से मूल्यांकित करने का एक तरीका देता है, जिसे "वॉच एक्सप्रेशन" कहते हैं। वॉच एक्सप्रेशन `>` चिह्न से शुरू होता है, और उसके बाद वह एक्सप्रेशन आता है जिसका मूल्यांकन करना है। वॉच एक्सप्रेशन `.u` सफिक्स वाली किसी भी फाइल में लिखे जा सकते हैं। फाइल सेव करने पर आपको Unison कोडबेस मैनेजर (UCM) कंसोल में दिख जाएगा कि उस एक्सप्रेशन का मान क्या आता है। इन डॉक्स में जहाँ संभव होगा, हम किसी एक्सप्रेशन को वॉच एक्सप्रेशन में मूल्यांकित करने के बाद उसका अपेक्षित आउटपुट दिखाने की कोशिश करेंगे।

```
> helloThere
  ⧩
  "Hello, World!"
```

## मल्टी-लाइन फंक्शन

Unison के मल्टी-लाइन फंक्शन कोड की सीमाएँ तय करने के लिए इंडेंटेशन या `let` ब्लॉक का उपयोग करते हैं, जिसे "लेक्सिकल स्कोप" कहते हैं।

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

एक ही इंडेंटेशन लेवल पर मौजूद हर चीज़ का स्कोप एक ही होता है। इसी वजह से हम अंतिम लाइन में वेरिएबल `newBeginning` का इस्तेमाल कर पाते हैं।

## नेमस्पेस और `use` स्टेटमेंट

नेमस्पेस वह तरीका है जिससे हम Unison के फंक्शन को समूहित और व्यवस्थित करते हैं। आप इन्हें "डायरेक्टरी" जैसा मान सकते हैं। ये कोड को ढाँचा और तार्किक समूह देते हैं।

आप `use` स्टेटमेंट की मदद से किसी नेमस्पेस के फंक्शन को स्कोप में ला सकते हैं।

मान लीजिए आप एक ऐसा फंक्शन लिख रहे हैं जो Unison की `List` वैल्यू का इस्तेमाल करता है। आप जानते हैं कि आपको `List.map` और `List.flatMap` जैसे फंक्शन चाहिए, जहाँ `List` नेमस्पेस है और `map` तथा `flatMap` फंक्शन हैं। बार-बार दोहराने से बचने के लिए आप अपने फंक्शन में `List` नेमस्पेस की हर चीज़ को इस तरह लेक्सिकल स्कोप में ला सकते हैं:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List` लाइन `map` और `flatMap` के रेफरेंस को स्पष्ट कर देती है। आप [`use` स्टेटमेंट के बारे में यहाँ][use-statements] और पढ़ सकते हैं।

## Unison की स्टैंडर्ड लाइब्रेरी

Unison की स्टैंडर्ड लाइब्रेरी को `base` कहा जाता है। अगर आपने क्विकस्टार्ट गाइड का पालन किया है और आपने अपने कंप्यूटर पर कोडबेस बनाया है, तो स्टैंडर्ड लाइब्रेरी अपने आप डाउनलोड हो चुकी होनी चाहिए। आप स्टैंडर्ड लाइब्रेरी का डॉक्युमेंटेशन ऑनलाइन [Unison Share][unison-share-base] पर देख सकते हैं।

## कमेंट और डॉक्युमेंटेशन लिटरल

Unison में कमेंट एक ज़रा अनोखी सुविधा है। Unison कोड लिखते समय आप अपनी `.u` सफिक्स वाली फाइल में ऐसा टेक्स्ट बना सकते हैं जिसकी व्याख्या नहीं होती, और उसका सिंटैक्स इस तरह है:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_लेकिन_ Unison का कोड फाइल सिस्टम पर टेक्स्ट वाली फाइलों के रूप में नहीं, बल्कि अपने एब्स्ट्रैक्ट सिंटैक्स ट्री के हैश के रूप में सेव होता है। इसलिए फाइल में किसी Unison फंक्शन या टर्म के टेक्स्ट वाले "सजावट" वाले कमेंट असल में सेव नहीं हो पाते और साझा करने के लिए दोबारा नहीं दिखाए जा सकते। अगर आप अपने Unison टर्म में कुछ ऐसी जानकारी जोड़ना चाहते हैं जो दूसरों के पढ़ने और समझने के लिए संग्रहीत रहे, तो आप डॉक्युमेंटेशन लिटरल का उपयोग कर सकते हैं।

Unison प्रोग्रामिंग भाषा में डॉक्युमेंटेशन एक फर्स्ट-क्लास वैल्यू है। इसका मतलब है कि `Doc` एलिमेंट को किसी वैल्यू पर असाइन किया जा सकता है, फंक्शन को वैल्यू के रूप में पास किया जा सकता है, या फंक्शन की वैल्यू के रूप में लौटाया जा सकता है। डॉक्युमेंटेशन लिटरल एलिमेंट डबल करली ब्रैकेट से खोले और बंद किए जाते हैं। कमेंट के रूप में `Doc` एलिमेंट का इस्तेमाल हम इस तरह कर सकते हैं।

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
