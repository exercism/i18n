# परिचय

रेगुलर एक्सप्रेशन स्ट्रिंग में _पैटर्न मैच_ करने का एक बहुत लचीला तरीका हैं। इसके लिए खास तौर पर बनाई गई एक डोमेन स्पेसिफिक लैंग्वेज (DSL) इसमें काम आती है।

रेगेक्स की कई सुविधाएँ Base R में पहले से मौजूद हैं, और पुराने कोड में आपको इसके उदाहरण मिल सकते हैं।

नए कोड के लिए [`stringr`][web-stringr] लाइब्रेरी इस्तेमाल करने की _पुरज़ोर_ सलाह दी जाती है।

जैसा कि [स्ट्रिंग्स कॉन्सेप्ट][concept-strings] में कहा गया है, `stringr` का डॉक्युमेंटेशन अच्छा है, और यह आम तौर पर पैकेज के लेखकों ने ही लिखा होता है।

- एक [संदर्भ वेबसाइट][web-stringr]
- एक [चीटशीट][cheat-stringr]।
- "R for Data Science" में एक [स्ट्रिंग्स अध्याय][book-strings] और एक [रेगेक्स अध्याय][book-regex]।

[`Strings`][concept-strings] कॉन्सेप्ट में पहले जिन फंक्शनों की चर्चा हो चुकी है, उनमें से कई डिफॉल्ट रूप से रेगेक्स खोज के लिए ही बने हैं।

हमने स्ट्रिंग्स कॉन्सेप्ट को अपेक्षाकृत आसान रखा, क्योंकि हमने सिर्फ स्ट्रिंग लिटरल पर मैच किया। लेकिन उसकी जगह कोई भी रेगेक्स पैटर्न इस्तेमाल किया जा सकता है।

औपचारिक रूप से, R में रेगेक्स [`regex()`][ref-regex] को कॉल करके बनाया जाता है।
सुविधा के लिए, `stringr` के फंक्शन किसी भी पैटर्न स्ट्रिंग को रेगेक्स मान लेते हैं।
नीचे दिए उदाहरण में पहला `str_replace_all()` दूसरे रूप का सिंटैक्टिक शुगर है:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[चीटशीट][cheat-stringr] एक काम की गाइड है: जिन सभी फंक्शनों में `pattern` आर्गुमेंट होता है (जो लाल रंग में छपा है), वे रेगेक्स स्वीकार करते हैं, और पेज 2 पर रेगेक्स सिंटैक्स का सार दिया गया है।

ध्यान दीजिए कि अगर आपको डिफॉल्ट सेटिंग बदलनी हो, जैसे केस सेंसिटिविटी या लोकेल, तो [`regex()`][ref-regex] फंक्शन अब भी काम का हो सकता है।

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

रेगेक्स के कई कोड में बैकस्लैश होता है, जैसे ऊपर इस्तेमाल हुआ `\s`।
आम R स्ट्रिंग में `\` को डबल करके एस्केप करना पड़ता है, इसीलिए `"\\s"` लिखा जाता है।

बैकस्लैश की संख्या बढ़ती जा सकती है और चीज़ें उलझने लगती हैं, इसलिए जटिल मामलों में [रॉ स्ट्रिंग][book-raw] इस्तेमाल करना मददगार हो सकता है।

डिफॉल्ट रूप से रॉ स्ट्रिंग बनाने का सिंटैक्स `r"( )"` है, लेकिन दूसरे डेलिमिटर भी इस्तेमाल किए जा सकते हैं।
चूँकि रेगेक्स सिंटैक्स में गोल ब्रैकेट `( )` और चौकोर ब्रैकेट `[ ]` दोनों ही आम हैं (कैप्चर ग्रुप और ऑप्शन ग्रुप के लिए), तो ब्रेसेज़ `{ }` एक अच्छा विकल्प हो सकता है।

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## मैच पहचानना

यहाँ कुछ सवाल दिए गए हैं, और साथ में वे फंक्शन जो इनका जवाब देने में मदद कर सकते हैं।

कुछ उदाहरणों में `fruit` इस्तेमाल हुआ है, जो अभ्यास के लिए `stringr` के साथ दिया गया 80 फलों के नामों का वेक्टर है।

_क्या किसी स्ट्रिंग में कोई मैच है?_
इसके लिए `str_detect()` है, या `^` और `$` एंकर इस्तेमाल करने से बचने के लिए `str_starts()` और `str_ends()`।

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_सिर्फ वे स्ट्रिंग लौटानी हैं जिनमें मैच है?_
स्ट्रिंग पाने के लिए `str_subset()` इस्तेमाल कीजिए, और इंडेक्स पाने के लिए `str_which()`।

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_हर स्ट्रिंग में कितने मैच हैं?_
इसके लिए `str_count()` इस्तेमाल कीजिए।

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_मैच कहाँ है?_
इंटरैक्टिव इस्तेमाल के लिए `str_view()`, और आम तौर पर `str_locate()` या `str_locate_all()`।

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## कैप्चर

आम तौर पर हम जानना चाहते हैं कि _क्या_ मैच हुआ है।
इसके लिए रेगेक्स में गोल ब्रैकेट के अंदर कैप्चर ग्रुप डाले जाते हैं।

एक ही रेगेक्स के अंदर `\1`, `\2` आदि की मदद से कैप्चर को दोबारा इस्तेमाल किया जा सकता है।
उदाहरण के लिए, दोहराए गए अक्षरों के जोड़े ढूँढ़ना:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

इसी तरह के सिंटैक्स से कैप्चर को रिप्लेसमेंट स्ट्रिंग में भी इस्तेमाल किया जा सकता है:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

बाद में इस्तेमाल के लिए मैच इकट्ठा करने के लिए `str_match()` फंक्शन सिर्फ पहला मैच देता है, और `str_match_all()` सारे मैच देता है।

कैप्चर ग्रुप किसी भी भाषा में उलझा हुआ आउटपुट देते हैं।
R का तरीका यह है (_और एक अतिरिक्त कठिनाई के तौर पर यह वेक्टराइज़्ड भी है_) कि `str_match()` से एक मैट्रिक्स बनाया जाए, जिसमें हर इनपुट स्ट्रिंग के लिए एक पंक्ति हो, पहले कॉलम में पूरी मैच हुई स्ट्रिंग हो, और बाकी कॉलमों में अलग-अलग कैप्चर ग्रुप हों।

नेम्ड ग्रुप इस्तेमाल करना फायदेमंद हो सकता है, क्योंकि वे नतीजों वाली मैट्रिक्स में कॉलम के नाम बन जाते हैं।

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

~~~~exercism/note
इस सिलेबस में हमने मैट्रिक्स के बारे में ज़्यादा कुछ नहीं कहा, हालाँकि एक [कॉन्सेप्ट डॉक्युमेंट][concept-matrices-arrays] है जिसे आप देख सकते हैं।
मैट्रिक्स Tidyverse इकोसिस्टम के साथ ठीक से नहीं बैठते, भले ही वे लंबे समय से Base R का हिस्सा रहे हैं।

संक्षेप में: मैट्रिक्स को 2 इंडेक्स वाले वेक्टर की तरह समझिए, `[rows, cols]` के क्रम में।
पूरी पंक्ति या पूरा कॉलम पाने के लिए कोई भी इंडेक्स खाली छोड़ दीजिए।

`m[r,]` से एक पंक्ति `r` या `m[,c]` से एक कॉलम `c` निकालने पर, लौटाई गई वैल्यू डिफॉल्ट रूप से एक वेक्टर में बदल दी जाती है।

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```
~~~~

स्वाभाविक रूप से, `str_match_all()` का आउटपुट और भी ज़्यादा संरचना वाला होता है:

- नतीजा एक लिस्ट होता है, जिसमें हर इनपुट स्ट्रिंग के लिए एक एलिमेंट होता है।
- अगर इनपुट स्ट्रिंग सिर्फ एक है, तो [लिस्ट्स कॉन्सेप्ट][concept-lists] में बताए अनुसार `[[1]]` इंडेक्सिंग से आउटपुट को अनलिस्ट कर दीजिए।
- हर एलिमेंट एक मैट्रिक्स होता है, जिसके कॉलम `match()` जैसे होते हैं।
- मैट्रिक्स की हर पंक्ति एक कामयाब कैप्चर होती है।

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

हो सकता है कि मैच फेल हो जाएँ।
तब नतीजा खास वैल्यू `NA` होता है।
इसकी जाँच के लिए तैयार रहिए, जैसा कि [नथिंगनेस कॉन्सेप्ट][concept-nothingness] में बताया गया है।

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
