# परिचय

एक **फ्लोटिंग-पॉइंट** ऐसी संख्या है जिसमें भिन्नात्मक भाग हो सकता है, जैसे `-1.23` या `3.1415`।

ऐसी संख्या को बाइट्स के अनुक्रम के रूप में निरूपित करने के लिए, x86-64 [IEEE-754][ieee] मानक का उपयोग करता है।
इस मानक में दो सबसे आम फॉर्मेट सिंगल-प्रिसिजन फ्लोटिंग-पॉइंट और डबल-प्रिसिजन फ्लोटिंग-पॉइंट संख्याएँ हैं।
x86-64 दोनों का समर्थन करता है।

एक सिंगल-प्रिसिजन फ्लोटिंग-पॉइंट संख्या 32-बिट चौड़ी होती है, जबकि डबल-प्रिसिजन 64-बिट चौड़ी होती है।

~~~~exercism/note
चूँकि फ्लोटिंग-पॉइंट संख्याएँ सभी वास्तविक संख्याओं का एक अनुमान भर हैं, इनके साथ किए गए ऑपरेशन अशुद्ध परिणाम दे सकते हैं।

गहराई से समझने के लिए, कृपया Oracle की Numerical Computation Guide के [परिशिष्ट D][guide] को देखिए, जिसका शीर्षक है "What Every Computer Scientist Should Know About Floating-Point Arithmetic"।

[Float Toy पेज][toy] पर एक अच्छी, चित्रात्मक व्याख्या है कि कैसे फ्लोटिंग-पॉइंट संख्या के बिट्स वास्तविक फ्लोटिंग-पॉइंट वैल्यू में बदले जाते हैं।

## XMM रजिस्टर

x86-64 में फ्लोटिंग-पॉइंट अंकगणित करने के लिए 16 समर्पित रजिस्टर हैं, जिनके नाम `xmm0` से `xmm15` हैं।

वे रजिस्टर कम से कम 128-बिट चौड़े होते हैं, लेकिन हाल के प्रोसेसर इसे बढ़ाकर 256-बिट या 512-बिट कर देते हैं।
हालाँकि व्यवहार में, अधिकांश फ्लोटिंग-पॉइंट संख्याएँ केवल सबसे निचले 32-बिट या 64-बिट का उपयोग करती हैं, जो वांछित परिशुद्धता पर निर्भर करता है।

## संख्याओं के बीच रूपांतरण

संख्या फॉर्मेटों के बीच रूपांतरण के लिए निर्देशों का एक परिवार है: `cvtxx2yy`।

`xx` और `yy` दोनों लिटरल नहीं, बल्कि प्लेसहोल्डर हैं:

- `xx` स्रोत ऑपरेंड के प्रकार के लिए प्लेसहोल्डर है।
- `yy` गंतव्य ऑपरेंड के प्रकार के लिए प्लेसहोल्डर है।

यह प्लेसहोल्डर कई रूप ले सकता है, जिनमें शामिल हैं:

| placeholder | meaning               |
| ----------- | --------------------- |
| `si`        | साइन्ड पूर्णांक        |
| `ss`        | 32-बिट फ्लोटिंग-पॉइंट |
| `sd`        | 64-बिट फ्लोटिंग-पॉइंट |

उदाहरण के लिए:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

ध्यान दीजिए कि 32-बिट पूर्णांक को 64-बिट फ्लोटिंग-पॉइंट में, या 64-बिट पूर्णांक को 32-बिट फ्लोटिंग-पॉइंट में बदलना संभव है।
इसी तरह, 32-बिट फ्लोटिंग-पॉइंट को 64-बिट पूर्णांक में, या 64-बिट फ्लोटिंग-पॉइंट को 32-बिट पूर्णांक में बदलना भी संभव है।
दूसरे शब्दों में, `cvtxx2yy` में दोनों ऑपरेंड का आकार _समान होना ज़रूरी नहीं है_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

जब फ्लोटिंग-पॉइंट संख्या को पूर्णांक के रूप में ठीक-ठीक व्यक्त नहीं किया जा सकता, तब `cvtxx2si` संख्या को `mxcsr` नामक एक विशेष रजिस्टर में मौजूद राउंडिंग कंट्रोल के अनुसार राउंड करता है।
यह निकटतम तक राउंड, नीचे की ओर राउंड, ऊपर की ओर राउंड, या ट्रंकेट हो सकता है।
फंक्शन में प्रवेश के समय कोई गारंटीड डिफ़ॉल्ट नहीं होता।

ध्यान दीजिए कि एक सटीक परिणाम राउंड नहीं किया जाता और इसलिए राउंडिंग कंट्रोल से प्रभावित नहीं होता।
उदाहरण के लिए, `42.0` को _हमेशा_ `42` में बदला जाएगा।

`cvttxx2si` फॉर्मेट वाले निर्देशों का एक समान परिवार है (एक अतिरिक्त `t` के साथ), जो परिणाम को हमेशा ट्रंकेट करता है।

## राउंड

`roundxx` निर्देश-परिवार स्रोत ऑपरेंड में दिए फ्लोटिंग-पॉइंट को गंतव्य ऑपरेंड में संग्रहीत राउंड किए गए फ्लोटिंग-पॉइंट में बदलता है।

यहाँ `xx`, हमेशा की तरह, ऑपरेंड के प्रकार के लिए प्लेसहोल्डर है: `ss` सिंगल-प्रिसिजन के लिए और `sd` डबल-प्रिसिजन फ्लोट्स के लिए।

वे निर्देश तीसरे ऑपरेंड के रूप में एक स्थिर संख्या लेते हैं।
यह संख्या राउंडिंग मोड बताती है:

| Number | Mode         |
| :----- | :----------- |
| 0      | निकटतम       |
| 1      | फ्लोर (नीचे) |
| 2      | सील (ऊपर)    |
| 3      | ट्रंकेट      |

उदाहरण के लिए:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

चूँकि वे निर्देश सटीक परिणाम देते हैं, इन्हें `cvtxx2si` की तैयारी में इस्तेमाल किया जा सकता है।

## अंकगणितीय निर्देश

फ्लोटिंग-पॉइंट संख्याओं के कई ऑपरेशनों के लिए जिन निर्देशों का उपयोग होता है, उनके नाम पूर्णांकों के समकक्ष निर्देशों जैसे ही होते हैं, बस अंत में आवश्यक प्लेसहोल्डर (`ss` या `sd`) जोड़ा जाता है।
वे निर्देश दो-ऑपरेंड वाले होते हैं, सामान्य सिमेंटिक्स के साथ, यहाँ तक कि गुणा या भाग करने वाले निर्देश भी:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## मूव

एक XMM रजिस्टर से दूसरे में मूव करने वाले निर्देश `movss` या `movsd` हैं:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

किसी इमीडिएट (एक स्थिर साइन्ड पूर्णांक) को सीधे xmm रजिस्टर में मूव करना **संभव नहीं** है।
इस संख्या को पहले एक जनरल-पर्पस रजिस्टर में मूव करना होता है और फिर `cvtsi2xx` की मदद से बदलना होता है:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## तुलनाएँ

दो फ्लोटिंग-पॉइंट संख्याओं के बीच तुलना करने के लिए निर्देशों के दो समूह हैं।
वे `comixx` और `ucomixx` रूप लेते हैं, जहाँ `xx` या तो `ss` है या `sd`.
दोनों `rflags` में फ्लैग सेट करते हैं, हमेशा की तरह, `cmp` के समान सिमेंटिक्स का पालन करते हुए।

इनमें अंतर यह है कि अगर दोनों फ्लोटिंग-पॉइंट संख्याओं में से किसी एक की वैल्यू `NaN` है, तो `ucomixx` `parity flag (PF)` सेट करता है, जबकि `comixx` इस स्थिति में एक्सेप्शन उत्पन्न करता है।

फ्लोटिंग-पॉइंट वैल्यू के बीच तुलना _अनसाइन्ड_ होती है:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## अन्य निर्देश

फ्लोटिंग-पॉइंट संख्याओं के साथ काम करने के लिए कई और निर्देश हैं, जो सामान्य ऑपरेशन लागू करते हैं।
इनमें से कुछ ये हैं:

| Instruction | Description                                      |
| :---------- | :----------------------------------------------- |
| `sqrtxx`    | वर्गमूल निकालता है (`sqrt(x)`)                    |
| `rcpss`     | व्युत्क्रम निकालता है (`1/x`)                     |
| `rsqrtss`   | वर्गमूल का व्युत्क्रम निकालता है (`1/sqrt(x)`)    |
| `minxx`     | न्यूनतम निकालता है (`min(x, y)`)                  |
| `maxxx`     | अधिकतम निकालता है (`max(x, y)`)                   |

जहाँ `xx` प्लेसहोल्डर इस्तेमाल होता है, वहाँ यह हमेशा की तरह `ss` या `sd` का रूप ले सकता है।
हालाँकि `rcpss` और `rsqrtss` केवल सिंगल-प्रिसिजन फ्लोटिंग-पॉइंट संख्याओं के साथ काम करते हैं।

वे सभी निर्देश दो-ऑपरेंड वाले हैं।

## कॉलिंग कन्वेंशन

System V ABI में, पहले आठ फ्लोटिंग-पॉइंट आर्गुमेंट फंक्शनों को क्रम से पास किए जाते हैं, `xmm0` से `xmm7` तक।
फ्लोटिंग-पॉइंट वैल्यू फंक्शनों से `xmm0` में लौटाई जाती हैं और ज़रूरत पड़ने पर `xmm1` में।

सभी `xmm` रजिस्टर इस्तेमाल के लिए स्वतंत्र रूप से उपलब्ध हैं, इनमें से कोई भी कॉलर के लिए आरक्षित नहीं है।

## मेमोरी

फ्लोटिंग-पॉइंट वैल्यू को मेमोरी में उसी तरह परिभाषित किया जा सकता है जैसे समान आकार के पूर्णांकों को किया जाता है।
NASM (The Netwide Assembler, इस ट्रैक में इस्तेमाल होने वाला असेंबलर) फ्लोटिंग-पॉइंट वैल्यू को वैज्ञानिक संकेतन में घोषित करने की सुविधा भी देता है।

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```

## AVX/AVX2

x86-64 आर्किटेक्चर के AVX/AVX2 एक्सटेंशन फ्लोटिंग-पॉइंट निर्देशों के लिए नए तीन-ऑपरेंड रूप पेश करते हैं, जो गंतव्य को स्रोतों से अलग करते हैं।
वे इन्हें ऊपर देखे गए लीगेसी SSE रूप से अलग करने के लिए `v` (यानी _वेक्टर_) उपसर्ग लेते हैं:

```x86asm
vaddss xmm0, xmm1, xmm2 ; xmm0 = xmm1 + xmm2 (32-bit floating-point)
vmulsd xmm2, xmm3, xmm4 ; xmm2 = xmm3 * xmm4 (64-bit floating-point)
```

इस ट्रैक में, हमने खुद को पिछले SSE एक्सटेंशन तक के निर्देशों और रजिस्टरों तक सीमित रखा है।
यह बुनियादी बातें सिखाने के लिए पर्याप्त है और बड़ी संख्या में CPUs के साथ संगतता सुनिश्चित करता है।

हालाँकि, टेस्ट-रनर AVX और AVX2 का पूरी तरह समर्थन करता है।
आप इन्हें इस्तेमाल करने के लिए स्वतंत्र हैं।
