# परिचय

## नल रेफरेंस

अगर आपने कभी कोई दूसरी प्रोग्रामिंग भाषा (C/C++, Python, Java, Ruby, Lisp, आदि) इस्तेमाल की है, तो बहुत संभव है कि आपका सामना पहले `null` या `nil` से हो चुका हो।
`null` या `nil` का इस्तेमाल इन भाषाओं में यह बताने का तरीका है कि किसी खास वेरिएबल के पास कोई वैल्यू नहीं है।
लेकिन इस वजह से ऐसे वेरिएबल को गलती से इस्तेमाल कर लेना, जो `null` की ओर इशारा करता है, एक आसान और बार-बार होने वाली गलती बन जाता है।
जैसा आप सोच सकते हैं, ऐसा फंक्शन कॉल करने की कोशिश करना जो है ही नहीं, या ऐसी वैल्यू तक पहुँचने की कोशिश करना जो मौजूद ही नहीं है, कई तरह के बग और क्रैश पैदा कर सकता है।
`null` को बनाने वाले ने तो इसे अपनी ['अरबों डॉलर की गलती'.](https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/) कहा था।

## `Option` टाइप

इन समस्याओं से बचने के लिए Rust नल रेफरेंस का इस्तेमाल नहीं करता।
लेकिन फिर भी इसे एक सुरक्षित तरीका चाहिए, जिससे यह बता सके कि किसी खास वेरिएबल के पास कोई वैल्यू नहीं है।
यहीं `Option` काम आता है।
ऐसे वेरिएबल की जगह, जिसके पास कोई वैल्यू न हो, Rust के वेरिएबल `Option` एनम का इस्तेमाल कर सकते हैं।
इस एनम के दो वेरिएंट होते हैं: `None`, जो Rust में null के बराबर है; और `Some(T)`, जहाँ T किसी भी टाइप की वैल्यू है।

यह कुछ ऐसा दिखता है:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

आप `Option` को अपने और नल रेफरेंस से होने वाली समस्याओं के बीच सुरक्षा की एक परत मान सकते हैं, और फिर भी नल रेफरेंस की उपयोगिता बनी रहती है।

## `Option` का इस्तेमाल

किसी वेरिएबल को `None` कर देना काफी आसान है:

```rust
let nothing: Option<u32> = None;  // Variable nothing is set to None
```

लेकिन अगर आप चाहते हैं कि `Option` टाइप के अंदर कोई वैल्यू रहे, तो आप वह वैल्यू सीधे असाइन नहीं कर सकते।
एक `Option` टाइप का वेरिएबल और, मान लीजिए, एक `i32` टाइप का वेरिएबल, दोनों एक जैसे नहीं होते।
आपको `Some` का इस्तेमाल करना होगा:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Some(-4); // This will work
let another_right_way = Some(-4); // Compiler infers that this is Option<i32>
```

इसी वजह से आगे लिखा हुआ भी काम नहीं करेगा:

```rust
let number = 47;
let option_number = Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

अगर आप Some के अंदर रखी वैल्यू निकालना चाहते हैं, तो पहले यह जाँचना होगा कि वह वहाँ मौजूद है या नहीं:

```rust
let mut some_words = Some("choose something to say"); // some_words set to something

match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "Here, we will choose something to say"

some_words = None; // some_words now set to None

// exactly the same match block as above
match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "I've got nothing to say"
```

`match` के अलावा `Option` के अंदर रखी वैल्यू को जाँचने और निकालने के लिए Rust में और भी टूल हैं, लेकिन `match` तो अब तक आपके लिए परिचित होना चाहिए।

इसके अलावा, इसे इस बात का उदाहरण भी मानिए कि Rust नल रेफरेंस की जगह `Option` क्यों इस्तेमाल करता है।
बात यह है कि **आपको जाँचना _ज़रूर_ होगा** कि `Option` वेरिएबल `Some` है (ऐसी स्थिति में आप उसके अंदर रखी वैल्यू निकालकर उसका इस्तेमाल कर सकते हैं) या `None`।
इसके अलावा कुछ और किया, तो आपका प्रोग्राम कंपाइल ही नहीं होगा; कंपाइलर आपको `null` से सुरक्षित रखता है।
