# जेनेरिक टाइप का परिचय

**जेनेरिक टाइप** ऐसी जेनेरिक क्लास या इंटरफेस को कहते हैं, जिसे टाइप के हिसाब से पैरामीटर किया जाता है। इससे कंपाइलर उस क्लास या इंटरफेस पर टाइप सेफ्टी लागू कर पाता है।

इस नॉन-जेनेरिक `Container` इंटरफेस को देखिए:

```java
class Container {
    private Object object;

    public void set(Object object) { this.object = object; }
    public Object get() { return object; }
}
```

यह ऑब्जेक्ट टाइप लेता भी है और लौटाता भी है, इसलिए यह किसी भी नॉन-प्रिमिटिव टाइप के साथ काम करता है। लेकिन इसकी एक कीमत चुकानी पड़ती है। कुछ कोड `get` को कॉल करते समय `Integer` की उम्मीद कर सकते हैं, जबकि कुछ और कोड `set` को कॉल करके `String` डाल देते हैं, और इससे रनटाइम एक्सेप्शन आ जाता है।

**जेनेरिक क्लास** और **जेनेरिक इंटरफेस** का रूप ऐसा होता है:

```java
class ClassName<T1, T2, ..., Tn> { ... }
interface InterfaceName<T1, T2, ..., Tn> { ... }
```

क्लास या इंटरफेस के नाम के बाद एंगल ब्रैकेट (`<>`) में दिया गया टाइप पैरामीटर सेक्शन उन टाइप पैरामीटर को बताता है, जिन्हें टाइप वेरिएबल भी कहते हैं: `T1`, `T2`, ..., और `Tn`। जेनेरिक टाइप सेफ्टी पाने के लिए इन्हें क्लास या इंटरफेस के अंदर इस्तेमाल किया जा सकता है।

यहाँ `Container` का जेनेरिक रूप है:

```java
class Container<E> {
    private E object;

    public void set(E object) { this.object = object; }
    public E get() { return object; }
}
```

अब इसे बनाते समय हमें यह घोषित करना पड़ता है कि इसमें किस टाइप की वैल्यू रखी जाएगी, और कंपाइलर उसी बंधन को लागू करता है:

```java
// empty <> can infer from context
Container<String> stringContainer = new Container<>();
// compiler knows this is a String, so it is allowed
stringContainer.set("Some string");
// no cast needed, compiler knows it is a String
String result = stringContainer.get();
// this causes a compiler error:
stringContainer.set(42);
```
