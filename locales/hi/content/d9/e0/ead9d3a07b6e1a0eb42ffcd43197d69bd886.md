# परिचय

ऐसा प्रोडक्शन कोड मिलना बहुत कम है जिसमें नेमस्पेस का इस्तेमाल न हो।

इस सिंटैक्स का एक उदाहरण यह है:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

नेमस्पेस एक तरीका है जिससे जुड़े हुए कोड को एक साथ रखा जाता है और नामों के टकराव से बचा जाता है।

[आधिकारिक डॉक्युमेंटेशन][namespaces] के अनुसार नेमस्पेस की दो मुख्य भूमिकाएँ हैं:

- पहला, .NET अपनी ढेरों क्लासों को व्यवस्थित करने के लिए नेमस्पेस का उपयोग करता है
- दूसरा, अपने नेमस्पेस घोषित करने से आप बड़े प्रोग्रामिंग प्रोजेक्ट में क्लास और मेथड के नामों का स्कोप संभाल सकते हैं।

बेस क्लास लाइब्रेरी (BCL) अपनी कार्यक्षमता को व्यवस्थित करने के लिए नेमस्पेस का खूब इस्तेमाल करती है।

## नेमस्पेस वाले टाइप के संदर्भ

नेमस्पेस में रखे टाइपों का इस्तेमाल नेमस्पेस के बाहर करते समय टाइप के नाम के आगे डॉट सिंटैक्स लगाना पड़ता है। या फिर, जो ज़्यादातर मामलों में किया जाता है, आप फाइल के ऊपर (या नेमस्पेस के अंदर) एक `using` डायरेक्टिव रख सकते हैं, और जिस नेमस्पेस को आयात किया गया हो, उसके किसी भी टाइप का इस्तेमाल बिना उपसर्ग के किया जा सकता है। एक ही नेमस्पेस के अंदर टाइप के नाम के साथ नेमस्पेस लिखने की ज़रूरत नहीं होती।

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

यह [लेख][using] साफ़-साफ़ बताता है कि `using` डायरेक्टिव का इस्तेमाल किन-किन तरीकों से किया जा सकता है:

- `using`: टाइप के नाम के आगे नेमस्पेस लिखने की ज़रूरत नहीं रहती
- `using static`: मेंबर के आगे टाइप लिखने की ज़रूरत नहीं रहती (इसका अच्छा उदाहरण `Math.Max()` है)।
- `using MyAlias = YourNamespace;`: नेमस्पेस के नाम की जगह एक ज़्यादा पढ़ने लायक नाम रखें।

## नेमस्पेस का टकराव

कभी-कभी अलग-अलग एसेंबली में एक ही नाम के दो नेमस्पेस होते हैं, और तब नेमस्पेस सहित पूरे आइडेंटिफायर नामों का टकराव हो सकता है (जैसे उस स्थिति में जब किसी एसेंबली के कई वर्शन लोड हों)। .NET इस समस्या का हल [नेमस्पेस एलियस क्वालिफायर][namespace-alias-qualifier] और [extern एलियस][extern-alias] से करता है।

इस थोड़े खास विषय को यहाँ उठाने की एक वजह यह है कि इसमें [`::` ऑपरेटर][dot-dot-operator] का इस्तेमाल होता है। आप अक्सर देखेंगे कि नेमस्पेस के आगे `global::` क्वालिफायर लगा होता है, खासकर ऐसे कोड में जो अपने आप बनाया जाता है। यहाँ उद्देश्य यह है कि किसी नेस्टेड नेमस्पेस या क्लास के नाम से हो सकने वाले टकराव से बचा जाए। किसी नेमस्पेस के आगे `global::` लगाकर आप यह पक्का करते हैं कि सबसे ऊपरी स्तर का नेमस्पेस ही चुना जाए।

## Java डेवलपर के लिए एक नोट

Java के `packages` वाले `import` से तुलना करते समय कुछ अंतर और समानताएँ ध्यान में रखनी चाहिए:

- C# में किसी खास टाइप को आयात करने जैसा कोई समकक्ष नहीं है।
- `using static` और `import static` समकक्ष हैं।
- Java में पैकेज के नाम का असर jars के बीच एक्सेस पर पड़ता है। C# में एसेंबली सबसे अहम होती हैं, और एक ही नेमस्पेस में होने से एक्सेस लेवल पर कोई असर नहीं पड़ता।
- Java में फाइल सिस्टम के पाथ और नेमस्पेस सहित पूरे क्लास नामों के बीच जो संबंध होता है, वह C# के नेमस्पेस में नहीं दिखता। फिर भी जहाँ हो सके, किसी फाइल को उसमें मौजूद मुख्य क्लास का ही नाम देना अच्छा तरीका माना जाता है।
