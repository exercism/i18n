# शर्तों का परिचय

## Bash में सत्यता

Bash में बूलियन वैल्यू की कोई अवधारणा नहीं है।
यहाँ स्ट्रिंग भी हैं, संख्याएँ भी, और स्ट्रिंग या संख्याओं के ऐरे भी।
तो शर्त वाले कमांड सही और गलत के साथ कैसे काम करते हैं?

## एग्ज़िट स्टेटस

कमांड जब खत्म होते हैं तो एक _एग्ज़िट स्टेटस_ देते हैं।
एग्ज़िट स्टेटस 0 से 255 तक (दोनों शामिल) का एक पूर्णांक होता है।
Bash **शून्य** एग्ज़िट स्टेटस को _सफलता_ मानता है।
बाकी कोई भी एग्ज़िट स्टेटस _विफलता_ दर्शाता है।

यह सभी कमांड पर लागू होता है, जिनमें bash के बिल्ट-इन कमांड, कीवर्ड और फंक्शन शामिल हैं।

## "if" कमांड

`if` कमांड का मूल सिंटैक्स यह है

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

इसकी शुरुआत `if` से होती है; `then` शर्त वाले कमांड को "सफलता" वाले कमांड से अलग करता है; और इसका अंत `fi` से होता है।
`else` भाग वैकल्पिक है।

CONDITIONAL_COMMANDS एक अकेला कमांड हो सकता है, या [कमांड की सूची][command-list] हो सकती है।

CONDITIONAL_COMMANDS चलाए जाते हैं, और

* अगर एग्ज़िट स्टेटस शून्य (सफलता) है, तो TRUE_COMMANDS चलाए जाते हैं।
* अगर एग्ज़िट स्टेटस शून्य नहीं है (विफलता), तो FALSE_COMMANDS चलाए जाते हैं, जब वे दिए गए हों।

`elif` की मदद से एक के बाद एक कई शाखाएँ दी जा सकती हैं
```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

`then`, `elif`, `else` और `fi` शब्दों से पहले एक सेमीकोलन या नई लाइन होनी चाहिए।

खास बात यह है: प्रवाह को नियंत्रित करने वाला शर्त वाले कमांड का **एग्ज़िट स्टेटस** ही है।
उदाहरण के लिए, `grep` मैच मिलने पर 0 लौटाता है, और मैच न मिलने पर 1।
`-q` विकल्प आउटपुट रोक देता है और सिर्फ एग्ज़िट स्टेटस देता है।

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## "[" और "test" कमांड

CONDITIONAL_COMMANDS के आसपास कोई खास सिंटैक्स नहीं होता।
आपने ऐसे if स्टेटमेंट देखे होंगे:

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

`[` कोई खास सिंटैक्स नहीं है।
यह एक _कमांड_ है जो शर्त वाले एक्सप्रेशन का मूल्यांकन करता है और सफलता या विफलता के स्टेटस के साथ बाहर निकलता है।
सभी कमांड की तरह, इसके और इसके आर्गुमेंट के बीच खाली जगह **ज़रूरी** है।

`[` वास्तव में `test` कमांड का ही पर्याय है।
दोनों बिल्कुल एक जैसे हैं, बस `[` का अंतिम आर्गुमेंट `]` ही _होना चाहिए_।

### शर्त वाले एक्सप्रेशन

`[` और `]` के अंदर आप एक शर्त वाला एक्सप्रेशन लिखते हैं।
कुछ आम शर्त वाले एक्सप्रेशन ये हैं:

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

और भी कई ऑपरेशन उपलब्ध हैं; इनकी सूची मैनुअल के [Bash के शर्त वाले एक्सप्रेशन][cond-expr] भाग में दी गई है।

~~~~exercism/note
ऊपर के उदाहरणों में ध्यान दीजिए कि सभी वेरिएबलो को कोट किया गया है।
`test` और `[` साधारण कमांड हैं, जिनमें आर्गुमेंट पर बाकी किसी भी कमांड की तरह शब्द-विभाजन और फाइलनाम एक्सपैंशन लागू होते हैं।

यह बताना इसलिए ज़रूरी है क्योंकि शर्त वाले एक्सप्रेशन इस आधार पर अलग-अलग तरीके से मूल्यांकित होते हैं कि आप _कितने आर्गुमेंट_ देते हैं:

* 0 आर्गुमेंट: एग्ज़िट स्टेटस शून्य नहीं होता (विफलता)
* 1 आर्गुमेंट: अगर आर्गुमेंट खाली नहीं है तो एग्ज़िट स्टेटस शून्य (सफलता) होता है, और अगर खाली है तो शून्य नहीं।
* 2 आर्गुमेंट: पहला आर्गुमेंट एक यूनरी ऑपरेटर होना चाहिए (जैसे `[ -z "$name" ]`), या एक `!` (जो 1-आर्गुमेंट वाले टेस्ट के स्टेटस को उलट देता है)
* और [बहुत कुछ][test]।

अगर आप कोट करना भूल जाएँ तो आपको अनपेक्षित परिणाम मिल सकते हैं:

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## "[[" कीवर्ड

[`[[...]]` शर्त वाला ढाँचा][cond-construct] एक _कमांड_ नहीं है, यह एक **कीवर्ड** है।
इसका मतलब है कि भले ही इसे बाकी किसी कमांड की तरह ही संभाला जाता है, इसके पार्सिंग के नियम खास हैं।
`[[` की खास बात यह है कि जो वेरिएबल इसके अंदर खोले जाते हैं, उन पर शब्द-विभाजन या फाइलनाम एक्सपैंशन **लागू नहीं** होते।
इसका मतलब है कि यह कमांड बिना कोट किए भी वैसा ही काम करता है जैसी आप उम्मीद करते हैं।

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

`[[` वे सारे शर्त वाले एक्सप्रेशन इस्तेमाल कर सकता है जो `test` और `[` संभाल सकते हैं।
इसके अलावा, `[[` ये सुविधाएँ भी देता है:

* `=~` रेगुलर-एक्सप्रेशन मैचिंग ऑपरेटर,
* `==` और `!=` ग्लॉब-पैटर्न मैचिंग ऑपरेटर की तरह,
* `&&` और `||` लॉजिकल ऑपरेटर की तरह (खास पार्सिंग नियम),
* `<` और `>` सादे स्ट्रिंग तुलना ऑपरेटर की तरह (खास पार्सिंग नियम: ये रीडायरेक्शन चिह्न हैं, इसलिए `[` में इन्हें एस्केप करना पड़ता है)।

आम तौर पर माना जाता है कि ये खास सुविधाएँ इतनी फायदेमंद हैं कि `[[` का ही इस्तेमाल करना चाहिए।
(उदाहरण के लिए, [Google Shell Style Guide][goog-test] देखिए।)

## "case" कमांड

[`case`][case] एक और कंट्रोल फ्लो कमांड है।
यह दूसरी भाषाओं के "switch" स्टेटमेंट जैसा है।

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

WORD का मिलान हर PATTERN से किया जाता है।
जब कोई एक मैच हो जाता है, तो COMMANDS चलाए जाते हैं।

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

COMMANDS वाले हर भाग का अंत **दो** सेमीकोलन, `;;`, से होना चाहिए।

   जानकारी के लिए [मैनुअल][case] देखिए।
