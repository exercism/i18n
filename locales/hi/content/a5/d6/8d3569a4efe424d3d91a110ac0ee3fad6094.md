# परिचय

आपने अब तक जो सीक्वेंस से जुड़े शब्द देखे हैं, उनमें से ज़्यादातर *नए* सीक्वेंस लौटाते हैं और अपने इनपुट को वैसा ही छोड़ देते हैं, जैसे `suffix`, `reverse`, `map` वगैरह। लेकिन ऐरे और वेक्टर **जगह पर ही बदलाव** का समर्थन भी करते हैं, और दोनों तब काम आते हैं जब आपको समय के साथ बदलती रहने वाली स्थिति दर्ज करनी हो।

## बदलने योग्य सीक्वेंस के दो प्रकार

- **ऐरे** (`{ … }`) की लंबाई तय होती है। `<array> ( n elt -- array )` ([`arrays`][arrays] में) लंबाई `n` का एक नया ऐरे बनाता है, जिसमें `elt` की प्रतियाँ भरी होती हैं।
- **वेक्टर** (`V{ … }`) बढ़ते और घटते हैं। नया खाली वेक्टर पाने के लिए `V{ } clone` इस्तेमाल कीजिए; `<vector> ( n -- vector )` ([`vectors`][vectors] में) `n` एलिमेंट के लिए जगह पहले से आरक्षित कर लेता है।

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## स्लॉट बदलना

ये दोनों किसी भी तरह के सीक्वेंस पर काम करते हैं, और दोनों इंडेक्स के बाद सीक्वेंस की अपेक्षा करते हैं:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth` वैल्यू असाइन करता है; `change-nth` स्थान `n` वाले एलिमेंट पर एक क्वोटेशन लागू करता है। ये दोनों [`sequences`][sequences] शब्द स्टैक पर कुछ नहीं लौटाते; असर यही बदलाव होता है।

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## बढ़ना और घटना

ये तीनों सिर्फ वेक्टर पर ही मायने रखते हैं, क्योंकि ऐरे की लंबाई बदल नहीं सकती:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## वेक्टर → ऐरे

जब आप एक वेक्टर बना चुके हों और तय लंबाई का ऐरे लौटाना चाहते हों, तो `>array ( seq -- array )` ([`arrays`][arrays] में) वही एलिमेंट लेकर एक नया ऐरे लौटाता है:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`: एक स्नैपशॉट रखिए

बदलाव सीक्वेंस को जगह पर ही बदल देता है। अगर कोई कॉलर आपको एक सीक्वेंस देता है और आप उसे बदलने वाले हैं, तो `clone` ([`kernel`][kernel] में) आपको एक नई स्वतंत्र कॉपी देता है, ताकि कॉलर को दिखने वाला सीक्वेंस उसके नीचे से न बदल जाए:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

यही सावधानी `V{ }` और दूसरे खाली लिटरल पर भी लागू होती है। कुछ भाषाओं में `[]` या `vec![]` हर बार एक्सप्रेशन के मूल्यांकन पर नया कंटेनर बना देता है। Factor में, आपके सोर्स में लिखा लिटरल `V{ }` *एक ही* ऑब्जेक्ट होता है, जिसे हर वह कॉल साइट साझा करती है जहाँ उसका ज़िक्र होता है। अगर आप सीधे `V{ }` पर `push` करते हैं, तो अगली कॉल को पहले से जमा एलिमेंट भी दिखते हैं। `V{ } clone` वही नई कॉपी बनाता है, जो लगभग हमेशा आपको चाहिए होती है।
