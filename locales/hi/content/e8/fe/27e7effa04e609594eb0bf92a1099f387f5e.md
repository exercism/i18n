# परिचय

Elm के टाइप जेनेरिक टाइप की सुविधा देते हैं, जो आम तौर पर किसी इंटरफ़ेस में लचीलापन बढ़ाते हैं।
उदाहरण के लिए, `Maybe a` टाइप किसी भी टाइप की वैल्यू रख सकता है।

```elm
type Maybe a = Nothing | Just a
```

ध्यान दीजिए कि ऊपर के उदाहरण में टाइप पैरामीटर `a` बराबर के चिह्न `=` के दोनों ओर इस्तेमाल होता है।
हम कहते हैं कि `a` टाइप की परिभाषा के अंदर किसी डेटा से बंधा हुआ है।

## फैंटम टाइप तकनीक

लेकिन कुछ मामलों में टाइप पैरामीटर सिर्फ समीकरण के बाईं ओर ही दिखता है।

```elm
type Distance unit = Distance Float
```

ऊपर दी गई `Distance` की परिभाषा में `unit` एक फ्री टाइप पैरामीटर है, जो टाइप के किसी डेटा से बंधा नहीं है।
ऐसे टाइप को हम **फैंटम टाइप** भी कहते हैं।

जब हम कंपाइल के समय कुछ बंधन लागू करना चाहते हैं, तब यह आश्चर्यजनक रूप से बहुत उपयोगी साबित होता है।
उदाहरण के लिए, हम यह सुनिश्चित करना चाहते हैं कि हम सिर्फ एक ही यूनिट की दूरियाँ ही जोड़ें।

```elm
-- Distance is an opaque type, since the module does not expose its variants.
-- This means that users may only use the functions meter, foot and add to manipulate distances.
module Distance exposing (Distance, Meter, Foot, meter, foot, add)

-- The Distance type has a phantom type 'unit'.
type Distance unit = Distance Float

-- We define two types that will be used in place
-- of the phantom type 'unit' in our constructor functions.
type Meter = Meter
type Foot = Foot

-- Constructor for Meter
meter : Distance Meter
meter = Distance 1.0

-- Constructor for Foot
foot : Distance Foot
foot = Distance 0.3048

-- The add function cannot take two parameters of different types.
-- So we cannot add meters and feet by mistake.
add : Distance unit -> Distance unit -> Distance unit
add (Distance d1) (Distance d2) = Distance (d1 + d2)
```

उस मॉड्यूल के बाहर का कोड `Distance` टाइप के अंदरूनी हिस्से तक नहीं पहुँच सकता।
उपयोगकर्ता दो `Distance Meter` जोड़ सकते हैं, लेकिन एक `Distance Meter` को `Distance Foot` के साथ नहीं जोड़ सकते।

```elm
import Distance exposing (Distance)

-- Compiles
twoMeters = Distance.add Distance.meter Distance.meter

-- Does not compile
errDist = Distance.add Distance.meter Distance.foot
```

## फैंटम टाइप के रूप में एक्सटेंसिबल रिकॉर्ड

कौन-कौन से टाइप फैंटम बन सकते हैं, इस पर कोई रोक नहीं है, और रिकॉर्ड टाइप भी इसी तरह इस्तेमाल किए जा सकते हैं।
फैंटम टाइप के रूप में इस्तेमाल किए जाने पर रिकॉर्ड जटिल बंधन व्यक्त कर सकते हैं, जिन्हें फंक्शनों के ज़रिए बदला जा सकता है।

चलिए `Distance` मॉड्यूल के अंदर `LegoBlock` नाम की एक नई दूरी-यूनिट जोड़ते हैं।
असली ब्लॉक नियमों से बनी चीज़ें होती हैं, इसलिए उनमें हमेशा दो प्रॉपर्टी होती हैं: उनकी दूरियाँ न भिन्नात्मक होती हैं और न ऋणात्मक।

```elm
type LegoBlock = LegoBlock

fourStuds : Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
fourStuds = Distance 4.0
```

`nonFractional` और `nonNegative` ऐसे रिकॉर्ड के फील्ड हैं जो टाइप आर्गुमेंट के बाहर कहीं मौजूद नहीं होता, इसलिए इन दोनों को `()` टाइप देना ठीक बैठता है। इसे __यूनिट टाइप__ कहते हैं, जिसमें इस बात के अलावा कि यह वहाँ मौजूद है, कोई और जानकारी नहीं होती।

मनमानी `LegoBlock` दूरियाँ निकालना निश्चित रूप से संभव है, जैसे दूरियों के अंतर या अनुपात निकालने के बाद।

```elm
negativeStud : Distance { properties | unit: LegoBlock, nonFractional : () }
negativeStud = Distance -1.0

threeFiddyStud : Distance { properties | unit: LegoBlock, nonNegative : () }
threeFiddyStud = Distance 3.50

crazyStud : Distance { properties | unit: LegoBlock }
crazyStud = Distance -13.37
```

ऊपर दी गई सभी वैल्यू मान्य हैं और कंपाइल हो जाएँगी। लेकिन हमारी खास दिलचस्पी `fourStuds` जैसी वैल्यू में है, जिसमें `nonFractional` और `nonNegative` दोनों प्रॉपर्टी मौजूद हैं, क्योंकि यह ऐसे असली ब्लॉक दर्शाती है जिन्हें नीचे दिए गए फंक्शन से जोड़ा जा सकता है:

```elm
combineLegoBlocks
  :  Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
  -> Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
  -> Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
combineLegoBlocks = add
```

चलिए कुछ फंक्शन जोड़ते हैं, जिनसे उपयोगकर्ता `LegoBlock` दूरियाँ बना सकें और उन्हें बेहतर बना सकें।

```elm
newLegoBlock : Float -> Distance { properties | unit: LegoBlock }
newLegoBlock dist = Distance dist

floorDistance : Distance properties -> Distance { properties | nonFractional : () }
floorDistance (Distance dist) = Distance (toFloat (floor dist))

ceilingDistance : Distance properties -> Distance { properties | nonFractional : () }
ceilingDistance (Distance dist) = Distance (toFloat (ceiling dist))

absDistance : Distance properties -> Distance { properties | nonNegative : () }
absDistance (Distance dist) = Distance (abs dist)
```

ध्यान दीजिए कि `floorDistance`, `ceilingDistance` और `absDistance` `LegoBlock` के अलावा दूसरी यूनिटों को भी संभाल सकते हैं। ये आम तौर पर इनपुट प्रॉपर्टी के बारे में कोई अनुमान नहीं लगाते, बस इतनी गारंटी देते हैं कि आउटपुट में एक खास प्रॉपर्टी ज़रूर होगी, चाहे `nonFractional` हो या `nonNegative`।

चलिए कुछ नतीजे देखते हैं।

```elm
import Distance exposing (Distance)

-- Compiles
distance1 = combineLegoBlocks fourStuds fourStuds

-- Does not compile
distance2 = combineLegoBlocks fourStuds threeFiddyStud

-- Compiles
distance3 = combineLegoBlocks fourStuds (floorDistance threeFiddyStud)

-- Does not compile
distance4 = combineLegoBlocks fourStuds negativeStud

-- Compiles
distance5 = combineLegoBlocks fourStuds (absDistance negativeStud)

-- Does not compile
distance6 = combineLegoBlocks fourStuds crazyStud

-- Compiles
distance7 = combineLegoBlocks fourStuds (floorDistance (absDistance crazyStud))

-- Compiles
distance8 = combineLegoBlocks fourStuds (ceilingDistance (absDistance crazyStud))
```

आम तौर पर `floorDistance` और `ceilingDistance` अलग-अलग नतीजे देते हैं, लेकिन एक जैसी गारंटी देते हैं।
यही फैंटम टाइप तकनीक की सबसे बड़ी बात है: उपयोगकर्ताओं को लचीले विकल्प देना, और साथ ही मज़बूत गारंटी बनाए रखना।
