# निर्देश

आप लाइब्रेरियन हैं और सदस्यों के खातों का बहीखाता रखते हैं। हर हफ्ते आपकी मेज़ पर दो तरह का काम आता है:

- **अनुरोध** की एक कतार — वे क्रेडिट जो सदस्य लागू करवाना चाहता है (किताबें लौटाना, चुकाया गया जुर्माना) और सिस्टम द्वारा दर्ज नए डेबिट (देर से लौटाने पर जुड़े नए जुर्माने)। सदस्य का खाता *क्रेडिट-संरक्षित* है: इतना बड़ा क्रेडिट जो सदस्य को घाटे में ले जाए, वह जितना बकाया है उतना ही लागू होता है, इसलिए चलता बैलेंस कभी शून्य से नीचे नहीं जाता।
- **लेन-देन** की एक सूची — खाते में पहले से दर्ज प्रविष्टियाँ। धनात्मक राशियाँ डेबिट (नए जुर्माने) हैं, ऋणात्मक राशियाँ क्रेडिट (भुगतान) हैं।

हर हफ्ते आप बहीखाता मिलाते हैं: अनुरोध पूरे करने के बाद का अंतिम बैलेंस, लेन-देन से बनने वाला हर दिन का चलता बैलेंस, और जुर्माने बढ़ने के दौर को चिह्नित करने वाला चलता न्यूनतम स्तर।

## 1. अनुरोध की कतार पूरी कीजिए

`protected-balance` को परिभाषित कीजिए। यह एक `opening` बैलेंस और `requests` का एक ऐरे (धनात्मक या ऋणात्मक राशियाँ) लेता है और बारी-बारी हर अनुरोध पूरा करने के बाद अंतिम बैलेंस लौटाता है। जो निकासी बैलेंस को शून्य से नीचे ले जाए, वह केवल उपलब्ध राशि तक ही पूरी की जाती है, इसलिए चलता बैलेंस शून्य पर ही रुक जाता है।

```factor
100 { 50 -200 30 } protected-balance .
! => 30

500 { 100 -300 -250 } protected-balance .
! => 50

0 { -10 50 } protected-balance .
! => 50
```

## 2. चलता बैलेंस

`running-balance` को परिभाषित कीजिए। यह `transactions` का एक ऐरे लेता है और उतनी ही लंबाई का एक क्रम लौटाता है, जिसका `i`-वाँ एलिमेंट पहले `i+1` लेन-देन के बाद का बैलेंस है (शून्य शुरुआती बैलेंस के सापेक्ष)।

```factor
{ 50 -30 -20 100 } running-balance .
! => { 50 20 0 100 }
```

## 3. अब तक का सबसे कम बैलेंस

`least-balance-so-far` को परिभाषित कीजिए। यह `transactions` का एक ऐरे लेता है और उतनी ही लंबाई का एक क्रम लौटाता है, जिसका `i`-वाँ एलिमेंट स्थान `i` तक (उस सहित) देखा गया *सबसे कम* चलता बैलेंस है। यही चलता न्यूनतम स्तर है, जो उन दिनों को पहचानने में काम आता है जब खाता जोखिम भरा लगता था।

```factor
{ 50 -30 -20 100 } least-balance-so-far .
! => { 50 20 0 0 }

{ 200 -50 -100 -200 } least-balance-so-far .
! => { 200 150 50 -150 }
```

## 4. लक्ष्य तक आधा कीजिए

पुस्तकालय जुर्माना-माफी कार्यक्रम चला रहा है: सदस्य का बकाया बैलेंस हर भुगतान अवधि में आधा कर दिया जाता है, जब तक वह माफी की सीमा तक या उससे नीचे न आ जाए। `halve-until` को परिभाषित कीजिए। यह एक `principal` और एक `target` लेता है और आधा की गई वैल्यू का क्रम लौटाता है (पूर्णांक विभाजन का उपयोग करके)। यह क्रम पहली बार आधा करने से शुरू होता है और तब तक चलता है जब तक चलती वैल्यू `target` से सख्ती से ऊपर बनी रहे। अंतिम बार निकाली गई वैल्यू वह पहली वैल्यू होगी जो `target` तक या उससे नीचे आ जाती है।

```factor
100 5 halve-until .
! => { 50 25 12 6 3 }

64 1 halve-until .
! => { 32 16 8 4 2 1 }

3 5 halve-until .
! => { }
```
