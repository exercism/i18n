# परिचय

`Complex numbers` मुश्किल नहीं हैं।
इन्हें बस एक कम डरावने नाम की ज़रूरत है।

कॉम्प्लेक्स संख्याएँ इतनी उपयोगी हैं, खास तौर पर इंजीनियरिंग और विज्ञान में, कि R इन्हें integer, double, logical, character और raw जैसे मानक एटॉमिक टाइप के साथ शामिल करता है।

## बुनियादी बातें

R में एक `complex` संख्या एक अकेली वैल्यू होती है।
लेकिन इस्तेमाल करते समय इसे दो संख्याओं के एक जोड़े की तरह देखा जा सकता है।
ऐतिहासिक कारणों से इन्हें "वास्तविक" और "काल्पनिक" भाग कहा जाता है, जो बदकिस्मती है।
फिर भी, बेहतर यही होगा कि आप इन अजीब नामों के बजाय इसकी मूल सादगी पर ध्यान दें।

दो वास्तविक संख्याओं से कॉम्प्लेक्स संख्याएँ बनाने के लिए काल्पनिक भाग के आगे बस `i` लगा दीजिए।

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

वास्तविक वेरिएबलो से कॉम्प्लेक्स संख्या बनाने के लिए ऊपर दिया गया सिंटैक्स काम नहीं करेगा।
`r + imi` लिखने पर पार्सर को लगता है कि `imi` कोई वेरिएबल नाम है, हालाँकि ऐसा कोई वेरिएबल है ही नहीं।

या तो काल्पनिक भाग को `1i` से गुणा कीजिए, या [`complex()`][ref-complex] फंक्शन का इस्तेमाल कीजिए:

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

आप सोच सकते हैं कि `j` की जगह `i` क्यों?

ज़्यादातर इंजीनियर `j` को पसंद करते हैं।
ज़्यादातर वैज्ञानिक और गणितज्ञ _काल्पनिक_ के लिए गणितीय संकेतन `i` पसंद करते हैं, लेकिन यह संकेतन इलेक्ट्रिकल इंजीनियरिंग में _धारा_ के अर्थ में `i` के इस्तेमाल से टकराता है।

R ने `i` चुना, Python ने `j` चुना, और Julia ने `im` चुनकर इस विवाद को टाल दिया।
[STEM][wiki-STEM] प्रोग्रामिंग भाषाओं के बीच आते-जाते समय सावधान रहिए।

कॉम्प्लेक्स संख्या के भागों को अलग-अलग निकालने के लिए:

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

कोई भी भाग शून्य हो सकता है, और ऐसी स्थिति में गणितज्ञ उस संख्या को "पूरी तरह वास्तविक" या "पूरी तरह काल्पनिक" कह सकते हैं।
लेकिन R में यह फिर भी एक कॉम्प्लेक्स संख्या ही रहती है।

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

आपने यह सुना होगा कि "`i` (या `j`) -1 का वर्गमूल है"।

फिलहाल, इसका मतलब बस इतना है कि काल्पनिक भाग _परिभाषा से_ नीचे दी गई समानता को संतुष्ट करता है:

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

यह एक सरल विचार है, लेकिन इसके दिलचस्प परिणाम सामने आते हैं।

## अंकगणित

दशमलव संख्याओं और पूर्णांकों के साथ इस्तेमाल होने वाले ज़्यादातर ऑपरेटर कॉम्प्लेक्स संख्याओं के साथ भी काम करते हैं:

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

## फंक्शन

ज़्यादातर गणितीय फंक्शन कॉम्प्लेक्स इनपुट के साथ काम करते हैं।

`Re()` और `Im()` के अलावा कुछ और फंक्शन भी हैं, जो कॉम्प्लेक्स संख्याओं के लिए खास तौर पर काम के हैं।

- `Conj()` कॉम्प्लेक्स संख्या के काल्पनिक भाग का चिह्न बस उलट देता है (_+ से - या इसके उलट_)।
  - कॉम्प्लेक्स गुणा जिस तरह काम करता है, उस हिसाब से यह आपकी सोच से कहीं ज़्यादा उपयोगी है।
- `abs(<complex number>)` हमेशा एक वास्तविक संख्या लौटाता है जिसका कोई काल्पनिक भाग नहीं होता (इसका "मापांक"), और `Mod(<complex number>)` इसका समानार्थी है।
- `Arg(<complex number>)` रेडियन में फेज़ कोण लौटाता है।

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
