# विवरण

जबकि Elixir प्रोग्रामर अक्सर ["इसे क्रैश होने दें"][let-it-crash] कहते हैं और ["सफल मार्ग"][happy-path] के लिए कोड लिखते हैं, अक्सर ऐसा समय आता है जब हमें फंक्शन कॉल को रेस्क्यू करने की ज़रूरत होती है ताकि कोई विशेष वैल्यू, संदेश लौटाया जा सके या सिस्टम संसाधन मुक्त किए जा सकें।

- जो फंक्शन सामान्य परिस्थितियों में एरर उठाते हैं, उनके नाम के अंत में `!` होना चाहिए।
- फंक्शन वैकल्पिक रूप से सफलता और विफलता दर्शाने के लिए एटम और टपल लौटा सकते हैं:

  ```elixir
  Map.fetch(%{a: 1}, :a)
  # => {:ok, 1}
  Map.fetch(%{a: 1}, :b)
  # => :error

  Map.fetch!(%{a: 1}, :b)
  # => raises KeyError
  ```

## एंटी-पैटर्न से बचिए

ऐसे प्रोग्रामिंग पैटर्न से बचिए जो लॉजिकल फ्लो को नियंत्रित करने के लिए एरर का उपयोग करते हैं। Elixir में यह एक एंटी-पैटर्न है।

```elixir
# Avoid using errors for control-flow.
try do
  {:ok, value} = MyModule.janky_function()
  "All good! #{value}."
rescue
  e in RuntimeError ->
    reason = e.message
    "Uh oh! #{reason}."
end

# Rather, use control-flow structures for control-flow.
case MyModule.janky_function() do
  {:ok, value} -> "All good! #{value}."
  {:error, reason} -> "Uh oh! #{reason}."
end
```
