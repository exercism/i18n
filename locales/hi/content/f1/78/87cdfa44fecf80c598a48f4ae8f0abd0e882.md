# Unison की बुनियादी बातें

## टर्म और फंक्शन

Unison प्रोग्राम लिखने की बुनियादी इकाइयाँ टर्म और फंक्शन हैं।

हम स्थिर वैल्यू को "टर्म" कहते हैं। इसे `name = expression` से बनाया जाता है, और चाहें तो इससे पहले `name : MyType` के रूप में टाइप सिग्नेचर भी लिखा जा सकता है। Unison टाइप इन्फरेंस का समर्थन करता है, इसलिए आसान परिभाषाओं में टाइप सिग्नेचर हटा हुआ भी दिख सकता है।

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison के फंक्शन ऐसे दिखते हैं: `myFunctionName argument1 argument2 = myImplementation`। यानी पहले फंक्शन का नाम, और उसके बाद स्पेस से अलग किए गए आर्गुमेंट।

```
getMax a b = Nat.max a b
```

फंक्शन में टाइप सिग्नेचर देना ज़रूरी नहीं है। दाईं ओर का अंतिम टाइप हमेशा फंक्शन का अंतिम रिटर्न टाइप होता है, और हर आर्गुमेंट को फंक्शन ऐरो `->` से अलग किया जाता है।

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

किसी फंक्शन को कॉल करने के लिए उसका नाम लिखिए और उसके बाद सिर्फ स्पेस से अलग किए गए आर्गुमेंट लिखिए।

```
maximum = getMax 1 10
```

जब आप किसी फंक्शन को कॉल करते हैं, तो Unison अपने ठीक दाईं ओर जो कुछ भी आता है, उसे आर्गुमेंट मानने की कोशिश करता है। इससे फंक्शन के मूल्यांकन का क्रम हमेशा वैसा नहीं बन पाता जैसा आप चाहते हैं।

मान लीजिए हम नीचे दिए एक्सप्रेशन से वैल्यू `1` पाना चाहते हैं

```
shouldBe1 = getMax 1 10 - 10
```

जैसा यह लिखा है, `shouldBe1` का मान `0` आता है, क्योंकि फंक्शन लगाने का जो क्रम यहाँ बनता है वह `getMax 1 10` है, जो `10` देता है, और फिर `10 - 10` बचता है, जो `0` है।

ब्रैकेट लगाकर आप एक्सप्रेशन को दोबारा समूहों में बाँट सकते हैं, ताकि ऑपरेशन उसी क्रम में हों जिस क्रम में आप चाहते हैं।

```
shouldBe1 = getMax 1 (10 - 10)
```

## कई पंक्तियों वाले फंक्शन

Unison में कई पंक्तियों वाले फंक्शन इंडेंटेशन या `let` ब्लॉक से तय करते हैं कि कोड की सीमाएँ कहाँ हैं। इसे ही "लेक्सिकल स्कोप" कहते हैं।

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

एक ही इंडेंटेशन लेवल पर लिखी हर चीज़ एक ही स्कोप में आती है, इसीलिए हम आखिरी लाइन में वेरिएबल `newBeginning` का इस्तेमाल कर पाते हैं।

## नेमस्पेस और `use` स्टेटमेंट

नेमस्पेस से ही हम Unison के फंक्शन को समूहों में बाँटते और व्यवस्थित करते हैं। इन्हें आप "डायरेक्टरी" जैसा समझ सकते हैं। ये कोड को ढाँचा देते हैं और उसे तार्किक समूहों में बाँटते हैं।

`use` स्टेटमेंट की मदद से आप किसी नेमस्पेस के फंक्शन को स्कोप में ले आ सकते हैं।

मान लीजिए आप ऐसा फंक्शन लिख रहे हैं जिसमें Unison की `List` वैल्यू का इस्तेमाल होता है। आपको पता है कि आपको `List.map` और `List.flatMap` जैसे फंक्शन चाहिए, जिनमें `List` नेमस्पेस है और `map` तथा `flatMap` फंक्शन हैं। बार-बार वही लिखने से बचने के लिए आप `List` नेमस्पेस की हर चीज़ अपने फंक्शन के लेक्सिकल स्कोप में ले आ सकते हैं, ऐसे:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List` वाली लाइन `map` और `flatMap` के संदर्भों को साफ़ कर देती है। [`use` स्टेटमेंट के बारे में यहाँ और पढ़ सकते हैं][use-statements]।

## Unison की स्टैंडर्ड लाइब्रेरी

Unison की स्टैंडर्ड लाइब्रेरी का नाम `base` है। अगर आपने क्विकस्टार्ट गाइड का पालन किया है और आपने अपने कंप्यूटर पर स्थानीय रूप से एक कोडबेस बना लिया है, तो स्टैंडर्ड लाइब्रेरी अपने आप डाउनलोड हो जानी चाहिए थी। स्टैंडर्ड लाइब्रेरी का दस्तावेज़ आप [Unison Share][unison-share-base] पर ऑनलाइन देख सकते हैं।

## कमेंट और डॉक्युमेंटेशन लिटरल

Unison में कमेंट एक ज़रा अलग तरह की चीज़ हैं। Unison कोड लिखते समय आप `.u` एक्सटेंशन वाली फाइल में ऐसा टेक्स्ट लिख सकते हैं जिसे इंटरप्रेट नहीं किया जाता। उसका सिंटैक्स यह है:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_लेकिन_, Unison कोड फाइल सिस्टम पर टेक्स्ट वाली फाइलों के रूप में नहीं, बल्कि उसके एब्स्ट्रैक्ट सिंटैक्स ट्री के हैश के रूप में सहेजा जाता है। इसलिए फाइल में किसी Unison फंक्शन या टर्म पर लगे वे टेक्स्ट वाले "सजावटी" कमेंट असल में सहेजे नहीं जा सकते और दूसरों के साथ साझा करने के लिए दोबारा नहीं दिखाए जा सकते। अगर आप अपने Unison टर्म में ऐसी जानकारी जोड़ना चाहते हैं जो सहेजी जाए और जिसे दूसरे पढ़ और समझ सकें, तो आप डॉक्युमेंटेशन लिटरल का इस्तेमाल कर सकते हैं।

Unison प्रोग्रामिंग भाषा में डॉक्युमेंटेशन एक फर्स्ट-क्लास वैल्यू है। इसका मतलब है कि किसी `Doc` एलिमेंट को वैल्यू में असाइन किया जा सकता है, फंक्शन को वैल्यू के रूप में दिया जा सकता है, या फंक्शन की वैल्यू के रूप में लौटाया जा सकता है। डॉक्युमेंटेशन लिटरल एलिमेंट दोहरे घुंघराले ब्रैकेट से खोले और बंद किए जाते हैं। नीचे दिखाया गया है कि हम `Doc` एलिमेंट को कमेंट की तरह कैसे इस्तेमाल कर सकते हैं।

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
