# इंस्टॉलेशन

## प्रस्तावना

Regina Rexx को कई प्लेटफॉर्म पर पोर्ट किया गया है, लेकिन यहाँ इंस्टॉलेशन निर्देश 64-बिट डेस्कटॉप प्लेटफॉर्म तक सीमित रहेंगे, यानी उन प्लेटफॉर्म तक जिन पर Windows, Linux या MacOS चलता है।

## इंस्टॉलेशन के चरण

ध्यान दीजिए कि यह ट्रैक [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) के नवीनतम संस्करण के इंस्टॉल होने की अपेक्षा करता है (यह लिखे जाने के समय 3.9.5)। ऊपर दिया गया हाइपरलिंक आपको सीधे Files सेक्शन पर ले जाता है, जहाँ से आप डाउनलोड करने के लिए फाइल चुन सकते हैं।

### Windows

Windows पर मूल रूप से चलाने के लिए इंस्टॉलेशन (CMD या Powershell विंडो के ज़रिए) ब्राउज़र में [`Download Latest Version`](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/Regina395w64.exe/download) बटन से आसानी से हो जाता है। इसमें सिर्फ क्लिक करना, डाउनलोड करना और इंस्टॉल करना है।

अगर आपके पास नीचे दिए जैसे Linux एमुलेशन वातावरण हैं, या आप उनका इस्तेमाल करना चाहते हैं:

* [Git for Windows](https://gitforwindows.org/)
* [Cygwin](https://cygwin.com/)
* [MinGW](http://mingw.org/)

तो Windows के लिए बनी Regina बाइनरी इनमें उपलब्ध रहनी चाहिए, यानी आप उन्हें इन वातावरणों में सीधे चला सकते हैं। ज़्यादातर कामों के लिए यह ठीक रहता है।

लेकिन एक बात का ध्यान रखें: ADDRESS निर्देश ठीक से काम नहीं करता (क्योंकि यह होस्ट ऑपरेटिंग सिस्टम से जुड़ता है)। इन वातावरणों में सबसे अच्छे नतीजों के लिए उस वातावरण के लिए बना पैकेज सोर्स कीजिए और उसे इंस्टॉल कीजिए। उदाहरण के लिए, Regina की वेबसाइट पर [Cygwin-specific](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-pc-cygwin.tgz/download) बिल्ड उपलब्ध है, जिसे इंस्टॉल किया जा सकता है।

इसके अलावा, अगर आपके पास Windows के अंदर कोई _असली_ Linux डिस्ट्रीब्यूशन है, जैसे [WSL](https://docs.microsoft.com/en-us/windows/wsl/about) या [Virtual Box](https://www.virtualbox.org/), या आप उसका इस्तेमाल करना चाहते हैं, तो संबंधित डिस्ट्रीब्यूशन के लिए Linux सेक्शन में दिए निर्देशों का पालन कीजिए।

### Linux

सिस्टम के पैकेज मैनेजर से Linux का इंस्टॉलेशन आम तौर पर काफी आसान रहता है। लेकिन दिक्कत तब आती है, जब उपलब्ध पैकेज _नवीनतम_ न हों। अफसोस की बात है कि Regina के साथ यही स्थिति है।

पैकेज के ज़रिए इंस्टॉलेशन तब भी हो सकता है, अगर आप नवीनतम पैकेज खुद सोर्स कर लें। [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) की वेबसाइट Debian परिवार (जिसमें Ubuntu शामिल है) और RHEL परिवार (जिसमें Fedora, CentOS, Rocky और Alma शामिल हैं) के डिस्ट्रीब्यूशन के लिए पैकेज उपलब्ध कराती है।

अपने चुने हुए डिस्ट्रीब्यूशन के लिए आपको दो पैकेज डाउनलोड करने होंगे: एक लाइब्रेरी पैकेज और एक बाइनरी पैकेज। उदाहरण के लिए, Debian या Ubuntu पर इंस्टॉल करने के लिए ऐसा कीजिए:

```plain
sudo apt update && sudo apt -y install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx_3.9.5-2_amd64-Debian-11.deb > regina-rexx_3.9.5-2_amd64-Debian-11.deb
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3_3.9.5-2_amd64-Debian-11.deb > libregina3_3.9.5-2_amd64-Debian-11.deb
sudo apt -y install libregina3_3.9.5-2_amd64-Debian-11.deb regina-rexx_3.9.5-2_amd64-Debian-11.deb
```

और CentOS तथा RHEL 7 पर आज़माइए:
```plain
sudo yum update && sudo yum install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
sudo yum localinstall libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
```

और Fedora, Rocky तथा Alma पर आज़माइए:
```plain
sudo dnf update && sudo dnf install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
sudo dnf localinstall libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
```

जहाँ पैकेज के ज़रिए इंस्टॉलेशन संभव न हो, या वह किसी और वजह से दिक्कत भरा साबित हो, वहाँ सोर्स से बिल्ड करना हमेशा संभव है। आर्काइव इस तरह मिल सकता है:

```plain
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5.tar.gz > regina-rexx-3.9.5.tar.gz
```

यह मानकर चलिए कि मानक बिल्ड टूल (gcc, make) इंस्टॉल हैं (अगर नहीं हैं, तो यहाँ दिए निर्देश देखिए: [Install Development Tools](https://ostechnix.com/install-development-tools-linux/))। फिर नीचे दिए चरण पूरे कीजिए:

```plain
tar -xzvf regina-rexx-3.9.5.tar.gz && cd regina-rexx-3.9.5
./configure
sudo make
sudo make install
```

लाइब्रेरी (`libregina.so`) और दो सेट बाइनरी (`rexx` और `regina`) इंस्टॉल हो जाते हैं (डिफॉल्ट जगह `/usr/local/bin` है)।

`rexx` बाइनरी स्टैटिक रूप से लिंक होती है, इसलिए वह आत्मनिर्भर है और तुरंत इस्तेमाल के लिए तैयार रहती है।

`regina` बाइनरी डायनैमिक रूप से लिंक होती है, इसलिए इसे थोड़ी कॉन्फिगरेशन की ज़रूरत पड़ती है, ताकि रनटाइम पर यह `libregina.so` शेयर्ड लाइब्रेरी ढूँढ सके। इसके लिए ये चरण कीजिए:

```plain
# Configure shared library location
sudo su
echo /usr/local/lib64/ > /etc/ld.so.conf.d/regina-rexx-3.9.5-x86_64.conf
echo /usr/local/lib64/regina-rexx/addons > /etc/ld.so.conf.d/regina-rexx-addons-x86_64.conf
cd /usr/local/lib64
rm -f libregina.so libregina.so.3
ln -s libregina.so.3.9 libregina.so
ln -s libregina.so.3.9 libregina.so.3
ldconfig
exit

# Check symbolic link creation
ls -l /usr/local/lib64/

# Output should be similar. Note symbolic links.
-rw-r--r--. 1 root root 3887554 Dec  1 18:22 libregina.a
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so -> libregina.so.3.9
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so.3 -> libregina.so.3.9
-rwxr-xr-x. 1 root root  574104 Dec  1 18:22 libregina.so.3.9
drwxr-xr-x. 2 root root      26 Dec  1 18:22 pkgconfig
drwxr-xr-x. 4 root root      33 Dec  1 18:22 regina-rexx

# Check library path, and executable using that path
ldconfig -p | grep regina
ldd /usr/local/bin/regina

# Alternate for local user
export LD_LIBRARY_PATH=${LD_LIBRARY_PATH}:/usr/local/lib64:/usr/local/lib64/regina-rexx/addons
```

ध्यान दीजिए कि सोर्स से बिल्ड करना और उसके साथ आने वाली सिस्टम कॉन्फिगरेशन, ये काम अनुभवी उपयोगकर्ताओं के लिए ही बेहतर हैं।

### MacOS

इंस्टॉलेशन तीन चरणों में होता है:

* [Homebrew](https://brew.sh) पैकेज मैनेजर इंस्टॉल कीजिए
* `Terminal` ऐप ढूँढिए और उसे खोलिए
* `Terminal` के कमांड लाइन से यह लिखिए:

   `brew install regina-rexx`

इससे _नवीनतम संस्करण_ इंस्टॉल हो जाना चाहिए।

अगर ऐसा न हो, तो आप [Regina for MacOS](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-apple-darwin21.6.0.tgz/download) पैकेज डाउनलोड करके उसे खुद इंस्टॉल कर सकते हैं।

## इंस्टॉलेशन के बाद

### इंस्टॉलेशन की जाँच

इंस्टॉलेशन पूरा करने के बाद आप टर्मिनल में यह कमांड चलाकर जाँच सकते हैं कि [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) ठीक से इंस्टॉल हुआ या नहीं:

```plain
rexx --version=v
```

Windows और Linux दोनों प्लेटफॉर्म पर टर्मिनल में यह आउटपुट दिखेगा:

```plain
3.9.5
```

यह इंटरप्रेटर के संस्करण की संख्या है।

एक दूसरी बाइनरी, `regina`, भी इंस्टॉल होती है। यह हर तरह से `rexx` जैसी ही है, बस यह एक शेयर्ड लाइब्रेरी से लिंक होती है। अगर आप बाहरी यूटिलिटी फंक्शन इस्तेमाल करना चाहते हैं, तो इसी इंटरप्रेटर का इस्तेमाल कीजिए। देखिए [Accessing External Routines](###accessing-external-routines) सेक्शन।

ट्रैक का इस्तेमाल शुरू करने के लिए और किसी सॉफ्टवेयर कंपोनेंट को इंस्टॉल करने की ज़रूरत नहीं है (यह मानकर कि Exercism CLI इंस्टॉल है)।

नीचे दिए इस्तेमाल के नोट्स आपको कमांड लाइन से इंटरप्रेटर इस्तेमाल करने की बुनियादी समझ देंगे।

### इस्तेमाल

आम तौर पर Rexx स्क्रिप्ट का एक्सटेंशन _`.rexx`_ होता है, हालाँकि यह ज़रूरी नहीं है। इंटरप्रेटर उस फाइल को चलाने की कोशिश करता है जिसका नाम आर्गुमेंट के रूप में दिया जाए, और अगर उसमें सही Rexx कोड है, तो वह सफलतापूर्वक चल जाती है।

यह कमांड `hello.rexx` नाम की फाइल को चलाने की कोशिश करेगा:

```plain
rexx hello.rexx
```

मान लीजिए फाइल में यह कोड है:

```rexx
say "Hello, world!"
exit 0
```

तो टर्मिनल पर यह आउटपुट आएगा:

```plain
Hello, world!
```

अगर फाइल का नाम बदलकर `hello.txt` कर दिया जाए और उसे इस तरह चलाया जाए, तो भी टर्मिनल पर यही आउटपुट दिखेगा:

```plain
rexx hello.txt
```

यह जानना भी काम का है कि स्क्रिप्ट कोड को फाइल में रखने के बजाय पाइप करके भी इंटरप्रेटर को दिया जा सकता है। ऊपर वाला कोड पाइप करके इस तरह चलाया जा सकता है:

```plain
echo "say 'Hello, world' ; exit 0" | rexx
```

और यह Linux टर्मिनल तथा Windows Powershell टर्मिनल, दोनों में एक जैसा काम करता है।

### उन्नत इस्तेमाल

स्क्रिप्ट फाइल को एक या एक से अधिक कमांड-लाइन आर्गुमेंट दिए जा सकते हैं, और वह मनचाहा पूर्णांक रिटर्न कोड लौटा सकती है। लेकिन इंटरप्रेटर को यह पता होना चाहिए कि स्क्रिप्ट को कई आर्गुमेंट दिए जाएँगे, और यह काम `-a` ऑप्शन से होता है।

उदाहरण के लिए, मान लीजिए फाइल `multiarg.rexx` में यह कोड है:

```rexx
say "My name is" ARG(1) || ", your name is" ARG(2) || ", and the script return code will be" ARG(3) || "."
exit ABS(ARG(3))
```

स्क्रिप्ट के कई आर्गुमेंट ठीक से पढ़े जाएँ, इसके लिए स्क्रिप्ट को इस तरह चलाया जाता है:

```plain
rexx -a multiarg.rexx "John" "Jill" 5
```

जिससे टर्मिनल पर यह आउटपुट आता है:

```plain
My name is John, your name is Jill, and the script return code will be 5.
```

और प्रोग्राम का रिटर्न कोड (जो Linux पर `$?` से और Windows पर `%errorlevel%` से देखा जा सकता है) 5 पर सेट हो जाता है।

### बाहरी रूटीन का इस्तेमाल

Regina ऐसे रूटीन के इस्तेमाल का समर्थन करती है जो बाहरी शेयर्ड लाइब्रेरी में रहते हैं। Regina की वेबसाइट पर ऐसी कई लाइब्रेरी उपलब्ध हैं। लेकिन ऐसी लाइब्रेरी इंस्टॉल करने की चर्चा यहाँ नहीं की गई है।

Regina के साथ एक ऐसी लाइब्रेरी, _regutil_, पहले से आती है। इसमें कई सामान्य कामों के रूटीन हैं, जैसे गणित, फाइल और फाइलसिस्टम से जुड़े काम, और सिस्टम तक पहुँचने के काम।

किसी अतिरिक्त इंस्टॉलेशन चरण की ज़रूरत नहीं है। लेकिन स्क्रिप्ट में इन रूटीन का इस्तेमाल करने के लिए यह ज़रूरी है कि इंटरप्रेटर लोड होते समय ये रजिस्टर कर दिए जाएँ। इसके लिए सिर्फ दो फंक्शन कॉल चाहिए, और यह प्रक्रिया यहाँ दिखाई गई है।

फाइल `access-external.rexx` में यह कोड है:

```rexx
/* Register external library and functions */
call RxFuncAdd 'SysLoadFuncs', 'regutil', 'SysLoadFuncs'
call SysLoadFuncs

say "Value of pi is" SysPi()
say "Square root of 25 is" SysSqrt(25)
say "Square root of 2 is" SysSqrt(2)

/* Deregister */
call SysDropFuncs

exit 0
```

इन रूटीन को लोड करके इस्तेमाल करने के लिए `regina` बाइनरी का इस्तेमाल करना पड़ेगा, इसलिए स्क्रिप्ट इस तरह चलाई जाएगी:

```plain
regina access-external.rexx
```

और टर्मिनल पर यह आउटपुट दिखेगा:

```plain
Value of pi is 3.141592654
Square root of 25 is 5.000000000
Square root of 2 is 1.414213562
```

इसके बजाय अगर `rexx` बाइनरी इस्तेमाल की गई होती, तो Windows प्लेटफॉर्म पर टर्मिनल का आउटपुट यह होता:

```plain
'SYSLOADFUNCS' is not recognized as an internal or external command,
operable program or batch file.
'SYSPI' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
```
