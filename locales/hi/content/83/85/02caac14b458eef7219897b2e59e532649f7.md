# परिचय

फंक्शन व्यवस्थित और दोबारा इस्तेमाल किए जा सकने वाले कोड का एक ब्लॉक होता है, जिसका इस्तेमाल कोई काम करने के लिए किया जाता है।
JavaScript में फंक्शन बनाने के कई तरीके हैं।
यहाँ हम _फंक्शन डिक्लेरेशन_ और _फंक्शन एक्सप्रेशन_ देखेंगे।
[एरो फंक्शन][concept-arrow-functions] जैसी दूसरी संभावनाओं को अन्य कॉन्सेप्ट में समझाया जाएगा।

## फंक्शन डिक्लेरेशन

JavaScript में फंक्शन बनाने का मानक तरीका _फंक्शन डिक्लेरेशन_ है, जिसे _फंक्शन डेफिनिशन_ या _फंक्शन स्टेटमेंट_ भी कहा जाता है।

इसमें `function` कीवर्ड, फंक्शन का नाम, और गोल ब्रैकेट में कॉमा से अलग किए गए पैरामीटर होते हैं।
इसके बाद फंक्शन के अंदर का कोड आता है (उन स्टेटमेंट का समूह, जो तय करते हैं कि फंक्शन क्या करता है), जिसे कर्ली ब्रैकेट में लिखा जाता है।

```javascript
function someName(param1, param2, param3) {
  // ...
}
```

JavaScript में किसी फंक्शन को कॉल करने के लिए उसका नाम लिखा जाता है और उसके बाद वे ब्रैकेट लगाए जाते हैं जिनमें आर्गुमेंट होते हैं।

```javascript
someName(arg1, arg2, arg3);
```

## पैरामीटर

फंक्शन के अंदर पैरामीटर के साथ काम करते समय संभावित साइड इफेक्ट का ध्यान रखिए।

- [प्रिमिटिव डेटा टाइप][mdn-primitives] की वैल्यू _अपरिवर्तनीय_ होती हैं।
  फंक्शन के अंदर आर्गुमेंट के साथ जो होता है, उसका असर मूल वैल्यू पर कभी नहीं पड़ता।
- बाकी सभी वैल्यू (ऑब्जेक्ट, ऐरे, फंक्शन) के लिए, दोबारा असाइन करने से मूल वैल्यू पर असर नहीं पड़ता।
  लेकिन अगर आप ऐसे आर्गुमेंट को बदलते हैं (जैसे किसी ऑब्जेक्ट में कोई की जोड़ते हैं), तो इससे वह मूल वैल्यू भी बदल जाती है जो पास की गई थी।

JavaScript में डिफ़ॉल्ट रूप से फंक्शन डिक्लेरेशन में बनाए गए सारे पैरामीटर वैकल्पिक होते हैं।
अगर आप पैरामीटर की संख्या से कम आर्गुमेंट देते हैं, तो फंक्शन के अंदर छूटे हुए आर्गुमेंट `undefined` हो जाते हैं। [नल और अनडिफ़ाइंड][concept-null-undefined] देखिए।
कई मामलों में `undefined` के बजाय कोई ज़्यादा उपयुक्त डिफ़ॉल्ट वैल्यू असाइन करना ठीक रहता है।
यह फंक्शन डेफिनिशन में सीधे डिफ़ॉल्ट पैरामीटर देकर किया जा सकता है।

```javascript
function someName(param1 = defaultValue1, param2 = defaultValue2) {
  // ...
}
```

## `return` स्टेटमेंट

`return` स्टेटमेंट फंक्शन का चलना रोक देता है और बताता है कि फंक्शन को कॉल करने वाले को कौन-सी वैल्यू लौटाई जाए। एक फंक्शन में एक से ज़्यादा `return` स्टेटमेंट हो सकते हैं।

```javascript
function checkNumber(num) {
  if (num === 0) {
    return 'You passed 0, please provide another number.';
  }

  return 'Thanks for passing such a nice number.';
}
```

जो फंक्शन कोई वैल्यू `return` नहीं करता या जिसमें `return` स्टेटमेंट नहीं है, उसका परिणाम `undefined` होता है।
JavaScript में `return` अपने आप नहीं लगता।

```javascript
function nakedReturn(a) {
  a * 2;
  return;
}

nakedReturn(1);
// => undefined

function noReturn(a) {
  a * 2;
}

noReturn(1);
// => undefined
```

JavaScript में आप ठीक एक ही वैल्यू लौटा सकते हैं।
अगर आपको ज़्यादा जानकारी देनी है, तो पहले उसे एक चीज़ में जोड़ना होगा, आम तौर पर किसी [ऑब्जेक्ट][concept-objects] या [ऐरे][concept-arrays] में।

```javascript
function divide(a, b) {
  return {
    quotient: Math.floor(a / b),
    remainder: a % b,
  };
}
```

## फंक्शन एक्सप्रेशन

फंक्शन डिक्लेरेशन एक अलग स्टेटमेंट होता है।
लेकिन कभी-कभी फंक्शन को किसी दूसरे एक्सप्रेशन के हिस्से के रूप में बनाना काम आता है, जैसे किसी असाइनमेंट में, फंक्शन के पैरामीटर के रूप में ([कॉलबैक][concept-callbacks]) या किसी [ऑब्जेक्ट][concept-objects] में वैल्यू के रूप में।
यह फंक्शन एक्सप्रेशन से किया जा सकता है।
इसका सिंटैक्स फंक्शन डिक्लेरेशन जैसा ही होता है, बस फंक्शन का नाम हटाकर एक _अनाम फंक्शन_ बनाया जा सकता है।

```javascript
const someFunction = function (param) {
  // ...
};

someOtherFunction(function (param) {
  // ...
});

const obj = {
  someFunction: function (param) {
    // ...
  },
};
```
