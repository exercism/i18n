# परिचय

## पार्शियल एप्लीकेशन और फंक्शन कंपोज़िशन

### पार्शियल एप्लीकेशन

Elm में सभी फंक्शन [करीड][currying] होते हैं, यानी अगर आप किसी फंक्शन को उसके सारे आर्गुमेंट दिए बिना कॉल करते हैं, तो वह एक नया फंक्शन लौटाता है।

ऐसा करने के परिणाम को [पार्शियल एप्लीकेशन][partial-application] कहते हैं (आप फंक्शन को सारे आर्गुमेंट नहीं दे रहे हैं, बल्कि उनमें से कुछ ही आंशिक रूप से लगा रहे हैं)।

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

पार्शियल एप्लीकेशन आर्गुमेंट को हमेशा उसी क्रम में लगाता है।

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

### पाइप ऑपरेटर (`|>`)

`x |> f` लिखना बिल्कुल `f x` लिखने जैसा ही है। एक ठोस उदाहरण: `"5" |> String.toInt` वही है जो `String.toInt "5"` है।

पहली नज़र में यह बहुत काम का नहीं लगता, लेकिन इसे [पाइप ऑपरेटर][pipe-operator] कहते हैं क्योंकि इससे आप “पाइपलाइन” वाला कोड लिख सकते हैं।

उदाहरण के लिए, मान लीजिए हमारे पास एक sanitize फंक्शन है जो उपयोगकर्ता के इनपुट को पूर्णांक में बदलता है:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

हम इसे इस तरह फिर से लिख सकते हैं:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

इससे ब्रैकेट लगाने की ज़रूरत नहीं रहती, और फंक्शन उसी क्रम में दिखते हैं जिस क्रम में वे लागू होते हैं (पहले `String.trim`, फिर `String.toInt`), जिससे कोड पढ़ने में आसानी होती है।

एक [उल्टा पाइप ऑपरेटर `(<|)`][reverse-pipe-operator] भी होता है।
`f <| x` लिखना बिल्कुल `f x` लिखने जैसा है।
पहली नज़र में यह भी बहुत काम का नहीं लगता, और पाइप ऑपरेटर जितना इसका उपयोग भी नहीं होता, लेकिन कुछ जगहों पर यह ब्रैकेट से बचने में मदद करता है।

### फंक्शन कंपोज़िशन / पॉइंट फ्री स्टाइल

[`(>>)`][forward-composition] ऑपरेटर का टाइप `(a -> b) -> (b -> c) -> (a -> c)` होता है और यह दो मेल खाते फंक्शन, जिनके टाइप `a -> b ` और `b -> c` हैं, को जोड़कर `a -> c` टाइप का एक फंक्शन बनाता है।
यह ऐसा पहले फंक्शन के आउटपुट (जिसका टाइप `b` है) को लेकर और उसे दूसरे फंक्शन के पहले आर्गुमेंट के रूप में इस्तेमाल करके करता है (दूसरे फंक्शन का टाइप भी वही `b` होना चाहिए)।
जो फंक्शन बनता है, वह वही इनपुट (जिसका टाइप `a` है) लेगा जो पहला फंक्शन लेता है, और जो `c` दूसरा फंक्शन लौटाता है वही लौटाएगा।

एक ठोस उदाहरण `String.trim >> String.toInt` है।
`String.trim` अपने एकमात्र पैरामीटर के रूप में एक स्ट्रिंग लेता है, इसलिए बनने वाला फंक्शन भी वही लेता है।
`String.toInt` एक `Maybe Int` लौटाता है, इसलिए बनने वाला फंक्शन भी वही लौटाता है।
`String.trim` एक `String` लौटाता है, जिसे `String.toInt` पैरामीटर के रूप में स्वीकार करता है, इसलिए यह उदाहरण कंपाइल हो जाता है।

अब हम अपना `sanitize` फंक्शन इस तरह फिर से लिख सकते हैं:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

ध्यान दीजिए कि अब हम वह `input` पैरामीटर इस्तेमाल नहीं करते जो मूल उदाहरण में दिखता है, भले ही काम बिल्कुल वही है।
अपने पैरामीटर का कोई ज़िक्र न करने वाले फंक्शन बनाने के इस तरीके को "पॉइंट फ्री स्टाइल" कहते हैं।
इस स्टाइल का फायदा यह है कि कोड ज़्यादा संक्षिप्त होता है, और नुकसान यह है कि इसे समझना मुश्किल हो सकता है, खास तौर पर शुरुआती लोगों के लिए।

यह याद रखने लायक है कि Elm में सभी फंक्शन करीड होते हैं, इसलिए `String.length >> max` कंपाइल हो जाता है।

- [`(>>)`][forward-composition] ऑपरेटर का टाइप `(a -> b) -> (b -> c) -> (a -> c)` होता है।
- `String.length` का टाइप `String -> Int` है, जो `(a -> b)` वाला हिस्सा है, इसलिए `a` `String` है और `b` - `Int` है।
- `max` का टाइप `Int -> Int -> Int` है, जो `b -> c` वाला हिस्सा है।
- `b` `Int` है, इसलिए `max` पर पार्शियल एप्लीकेशन होता है, इसलिए `c` इस पार्शियल एप्लीकेशन का परिणाम (`Int -> Int`) है।
- तो `String.length >> max` का टाइप `String -> (Int -> Int)` है।
- तो `((String.length >> max) "123") 2` `3` लौटाता है, क्योंकि `"123"` की लंबाई 3 है, जो `Int` आर्गुमेंट वाले 2 से बड़ी है।

### फंक्शन डिज़ाइन

Elm में सुंदर कोड आसानी से लिख पाने के लिए, आपको मुख्य डेटा स्ट्रक्चर को फंक्शन का आखिरी पैरामीटर बनाना चाहिए।
स्टैंडर्ड लाइब्रेरी के सभी आम फंक्शन ऐसा ही करते हैं, जैसे `List.map` (नीचे उसका टाइप सिग्नेचर दिया है)।

```elm
map : (a -> b) -> List a -> List b
```

यहाँ हम देख सकते हैं कि `map` फंक्शन का आखिरी पैरामीटर `List a` है और यह `List b` लौटाता है, इसलिए मुख्य डेटा स्ट्रक्चर (`List`) आखिरी पैरामीटर है।

इससे नीचे जैसा सुंदर पाइपलाइन वाला कोड लिखना मुमकिन हो जाता है।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

इससे फंक्शन कंपोज़िशन और पॉइंट फ्री स्टाइल का उपयोग करना भी सुविधाजनक हो जाता है, पाइपलाइन के विकल्प के रूप में।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

फंक्शन कंपोज़िशन से आप इस उदाहरण को `List.map` के एक ही कॉल तक सीमित कर सकते हैं।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
