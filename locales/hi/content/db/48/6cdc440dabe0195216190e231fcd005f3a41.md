# इस विषय के बारे में

`LocalDate` और `LocalDateTime` जैसी क्लासें समय में एक _बिंदु_ बताती हैं।
`java.time` पैकेज में दो और क्लासें भी हैं जो समय की एक _मात्रा_ बताती हैं:

- [`Period`][period-docs] सालों, महीनों और दिनों में समय की तिथि-आधारित मात्रा है, जैसे "2 महीने और 5 दिन"।
- [`Duration`][duration-docs] घंटों, मिनटों, सेकंडों, मिलीसेकंडों और नैनोसेकंडों में समय की मात्रा है, जैसे "1 घंटा और 30 मिनट"।

यह अंतर इसलिए ज़रूरी है क्योंकि कैलेंडर की इकाइयों की लंबाई तय नहीं होती।
एक महीने में 28, 29, 30 या 31 दिन हो सकते हैं, इसलिए "एक महीना" सेकंडों की एक तय संख्या नहीं है।
`Period` कैलेंडर का पालन करता है, जबकि `Duration` सटीक समय नापता है।

| | `Period` | `Duration` |
| --- | --- | --- |
| संग्रहीत करता है | साल, महीने और दिन | सेकंड और नैनोसेकंड |
| किनके साथ इस्तेमाल होता है | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

दोनों क्लासें इम्यूटेबल हैं।
`plusDays()` या `multipliedBy()` जैसे मेथड एक _नया_ इंस्टेंस लौटाते हैं और मूल इंस्टेंस को बदलते नहीं।

## `Period`

### पीरियड बनाना

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

`toString()` का परिणाम [ISO-8601 ड्यूरेशन फॉर्मेट][iso-8601-durations] इस्तेमाल करता है: `P` के बाद सालों की संख्या (`Y`), महीनों की संख्या (`M`) और दिनों की संख्या (`D`) आती है।
`Period` में हफ्ते नहीं होते: `Period.ofWeeks(2)` को 14 दिनों के रूप में संग्रहीत किया जाता है।
इसी नोटेशन को `Period.parse()` से वापस पार्स किया जा सकता है:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### तिथि में पीरियड जोड़ना

किसी तिथि में `plus()` और `minus()` से पीरियड जोड़ा या घटाया जाता है:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

इसी तरह `LocalDateTime` में भी पीरियड जोड़ा जा सकता है, और दिन का समय वही रहता है:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

`Instant` के पास कैलेंडर नहीं होता, इसलिए उसमें सिर्फ दिनों वाला पीरियड जोड़ा जा सकता है।
साल या महीने वाला पीरियड एक्सेप्शन थ्रो करता है:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

पहले साल जोड़े जाते हैं, फिर महीने और फिर दिन।
जब साल या महीने जोड़ने पर ऐसी तिथि बनती है जो मौजूद नहीं है, तो परिणाम को उस महीने के आखिरी मान्य दिन पर ले जाया जाता है:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

इसका मतलब यह भी है कि पीरियड जोड़कर फिर उसे घटाने पर हमेशा मूल तिथि वापस नहीं मिलती:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### दो तिथियों के बीच का पीरियड

`Period.between()` एक तिथि से (उसे शामिल करते हुए) दूसरी तिथि तक (उसे शामिल किए बिना) का पीरियड लौटाता है।
यही परिणाम `LocalDate.until()` से भी मिलता है:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

पीरियड के हिस्से `getYears()`, `getMonths()` और `getDays()` से मिलते हैं।
ये हिस्से एक-दूसरे से स्वतंत्र हैं: `getDays()` सिर्फ दिनों वाला हिस्सा लौटाता है, दिनों की कुल संख्या नहीं।
`toTotalMonths()` सालों और महीनों को मिलाकर महीनों की संख्या के रूप में लौटाता है, लेकिन दिनों की कुल संख्या के लिए कोई मेथड नहीं है, क्योंकि यह इस पर निर्भर करता है कि कौन से महीने शामिल हैं।

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### पीरियड को नॉर्मलाइज़ करना

फैक्ट्री मेथड से बनाया गया पीरियड अपनी इकाइयों को ठीक वैसे ही रखता है जैसे दिया गया था, और `equals()` इकाइयों की एक-एक करके तुलना करता है।
`normalized()` महीनों को सालों में बदल देता है, लेकिन दिनों को नहीं छेड़ता:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## `ChronoUnit` से इकाइयाँ गिनना

समय के दो बिंदुओं के बीच किसी एक इकाई की कुल संख्या निकालने के लिए [`ChronoUnit`][chronounit-docs] के किसी एक कॉन्स्टेंट पर `between()` मेथड इस्तेमाल कीजिए:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

सिर्फ पूरी इकाइयाँ गिनी जाती हैं, और जब दूसरा आर्गुमेंट पहले आर्गुमेंट से पहले का समय होता है, तो परिणाम ऋणात्मक होता है:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit` समय-आधारित इकाइयों और तिथि-समय के साथ भी काम करता है:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### ड्यूरेशन बनाना

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

ISO-8601 नोटेशन में `T` तिथि वाले हिस्से को समय वाले हिस्से से अलग करता है।
`Duration` में तिथि वाला हिस्सा नहीं होता, इसलिए इसका `toString()` हमेशा `PT` से शुरू होता है।
`Duration.ofDays()` एक दिन को ठीक 24 घंटे मानता है।

ड्यूरेशन को `Duration.parse()` से भी पार्स किया जा सकता है:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### समय में ड्यूरेशन जोड़ना

`LocalTime`, `LocalDateTime` या `Instant` में `plus()` और `minus()` से ड्यूरेशन जोड़ा या घटाया जाता है:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

जैसा कि पिछले उदाहरण से दिखता है, `LocalTime` आधी रात के बाद 00:00 से फिर शुरू हो जाता है।

`LocalDate` में समय नहीं होता, इसलिए इसे `Duration` के साथ नहीं जोड़ा जा सकता:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### दो समयों के बीच का ड्यूरेशन

`Duration.between()` दो समयों या तिथि-समयों के बीच का सटीक समय लौटाता है:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()` दो `LocalDate` वैल्यू स्वीकार नहीं करता, क्योंकि तिथि में नापने के लिए सेकंड नहीं होते:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

तिथियों के लिए इसके बजाय `Period.between()` या `ChronoUnit.DAYS.between()` इस्तेमाल कीजिए।

### ड्यूरेशन को बदलना

`toXxx()` मेथड ड्यूरेशन को एक ही इकाई की _कुल_ मात्रा में बदलते हैं, नीचे की ओर राउंड करके:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

`toXxxPart()` मेथड ड्यूरेशन को उसके हिस्सों में बाँटते हैं, जैसे घड़ी पर होता है:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()` 23 पर रुक जाता है, क्योंकि उससे ऊपर के घंटे `toDaysPart()` गिनता है।

### ड्यूरेशन की तुलना और गणना

ड्यूरेशन की तुलना `compareTo()` से की जा सकती है, और `isZero()` तथा `isNegative()` से जाँच की जा सकती है:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

ये अंकगणित का भी समर्थन करते हैं, जैसे `plus()`, `minus()`, `multipliedBy()` और `dividedBy()`:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` या `Duration`?

`LocalDate` या `LocalTime` के लिए चुनाव अपने आप हो जाता है: तिथि में नापने के लिए समय नहीं होता, और समय में कैलेंडर नहीं होता।
`LocalDateTime` में दोनों होते हैं, लेकिन टाइम ज़ोन नहीं होता, इसलिए उसमें `Period.ofDays(1)` या `Duration.ofDays(1)` जोड़ने पर एक ही परिणाम मिलता है।
यह अंतर टाइम ज़ोन के साथ दिखाई देता है।
जब डेलाइट सेविंग टाइम के लिए घड़ियाँ आगे बढ़ाई जाती हैं, तो कैलेंडर का एक दिन सिर्फ 23 घंटे का होता है:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

एक दिन का `Period` जोड़ने पर दिन का समय वही रहता है, जबकि एक दिन का `Duration` जोड़ने पर ठीक 24 घंटे जुड़ते हैं।
जिन मात्राओं को लोग कैलेंडर के हिसाब से सोचते हैं ("अगले महीने उसी समय") उनके लिए `Period` इस्तेमाल कीजिए, और बीते हुए समय ("पार्किंग टिकट 2 घंटे के लिए मान्य है") के लिए `Duration` इस्तेमाल कीजिए।
