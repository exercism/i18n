# निर्देश

प्रोग्रामिंग के बारे में आप जितना अधिक सीखते हैं, उतना ही आप सोचने लगते हैं कि यह सिर्फ एक चलन भर से ज़्यादा हो सकता है।
इसमें कारोबार के मौके भी हो सकते हैं: लोग कोड लिखते हैं, वे उसे सहेजना चाहते हैं, साझा करना चाहते हैं, मिलकर काम करना चाहते हैं, और शायद कुछ प्रतिक्रिया भी पाना चाहते हैं।

ठीक है, चलिए करते हैं, चलिए एक ऐसी सेवा बनाते हैं जो लोगों को कोड करने के लिए प्रेरित करे: हुप, हुप, लोगो, git का इस्तेमाल शुरू कीजिए!
चलिए इसका नाम रखते हैं... GitHup.

आप एक REST JSON API बनाना शुरू करते हैं: यूज़र, पुल रिक्वेस्ट, कमेंट, बैकएंड जल्दी ही तैयार हो जाता है।
यहाँ एक उदाहरण है, जब आप सर्वर से किसी पुल रिक्वेस्ट पर कमेंट की सूची माँगते हैं तो जो पेलोड मिलता है:

```json
[
  {
    "id": 256,
    "pull_request_review_id": 42,
    "user": {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    },
    "body": "Great stuff!",
    "side": "RIGHT",
    "_links": {
      "self": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
      },
      "html": {
        "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1"
      },
      "pull_request": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1"
      }
    }
  },
  {
    "id": 11,
    "pull_request_review_id": null,
    "user": {
      "id": 2,
      "login": "hexacat",
      "name": "Alex Kate",
      "avatar_url": "https://githup.com/images/error/hexacat_happy.gif",
      "site_admin": true
    },
    "body": "Amazing stuff!",
    "side": "LEFT",
    "_links": {
      "self": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
      }
    }
  }
]
```

बेशक, फ्रंटएंड Elm में बनेगा, लेकिन पहले आपको समझना होगा कि वे मशहूर डिकोडर और एनकोडर वास्तव में क्या हैं।

```exercism/note
हास्य कहानी को एक तरफ रखकर, इस अभ्यास की आवश्यकताएँ सीधे GitHub के REST API एंडपॉइंट से ली गई हैं, जो पुल रिक्वेस्ट रिव्यू कमेंट के लिए हैं।
कुछ फील्ड JSON स्कीमा से आसानी के लिए हटा दिए गए हैं, लेकिन यह वास्तविक दुनिया के अनुप्रयोगों के जितना करीब हो सकता है, उतना करीब है।
```

## 1. आईडी, प्लीज़!

आपकी तेज़ नज़र ने देख लिया है कि कमेंट और यूज़र, दोनों में एक `id` फील्ड है, शुरू करने की बढ़िया जगह।

`decodeId` को इस तरह बनाइए कि यह एक JSON ऑब्जेक्ट डिकोड कर सके, जिसमें एक पूर्णांक `id` हो।

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. मेरा नाम फिर से क्या है?

आप ऊपर के उदाहरण में देखते हैं कि सभी यूज़र के पास नाम नहीं होता।

`decodeName` को इस तरह बनाइए कि अगर `name` फील्ड में कोई स्ट्रिंग हो तो यह उसे डिकोड कर सके।
नाम नहीं है? कोई बात नहीं, बस `Nothing` लौटाइए।
यह डिकोडर कभी फेल नहीं होना चाहिए।

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. यूज़र? हम तो इसे जानते ही नहीं!

यूज़र डिकोड करने में हम लगभग आधे रास्ते पर हैं, चलिए इसे पूरा करते हैं।

`decodeUser` को इस तरह बनाइए कि यह एक JSON यूज़र ऑब्जेक्ट डिकोड कर सके।
ध्यान रखिए कि `decodeUser` में `decodeId` और `decodeName` का इस्तेमाल कीजिए।

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. मैं एक मज़बूत और स्वतंत्र कमेंट हूँ

पुल रिव्यू में कुछ कमेंट अलग-थलग होते हैं, और इसलिए उनमें `pull_request_review_id` नहीं होता।
लेकिन स्पेसिफिकेशन कहता है कि ऐसी स्थिति में भी `pull_request_review_id` फील्ड होना चाहिए, बस उसकी वैल्यू `null` होनी चाहिए, यानी गरीब आदमी का `Nothing`।

`decodePullRequestReviewId` को इस तरह बनाइए कि अगर `pull_request_review_id` फील्ड में कोई पूर्णांक हो तो यह उसे डिकोड कर सके।
अगर पूर्णांक नहीं है, तो वहाँ `null` होना चाहिए, और अगर `null` नहीं है तो डिकोडर फेल हो जाना चाहिए।

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. साइड का काम

अगला है यह दिलचस्प दिखने वाला `side` फील्ड।
पुल रिव्यू में आप उस कोड पर कमेंट कर सकते हैं जो हटाया गया था (स्क्रीन के `Left` तरफ) या उस कोड पर जो जोड़ा गया था (स्क्रीन के `Right` तरफ)।

`decodeSide` को इस तरह बनाइए कि यह `side` फील्ड में `"LEFT"` या `"RIGHT"` डिकोड कर सके और उसे उसके मिलते-जुलते टाइप वेरिएंट से मिला सके।

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. लिंक्स की जागृति

हर कमेंट में लिंक का एक समूह होता है, जो हर कमेंट में एक जैसा नहीं लगता।

`decodeLinks` को इस तरह बनाइए कि यह `_links` फील्ड में URL के एक संग्रह को डिकोड कर सके।
लिंक के नाम और संख्या बदल सकते हैं, ध्यान रखिए कि आप इसे संभाल सकें।
लिंक खुद JSON ऑब्जेक्ट होते हैं, जिनमें हमेशा एक `href` फील्ड होना चाहिए।

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. हाँ, कमेंट

बस थोड़ी ही दूर बाकी है, चलिए इसे पूरा करते हैं।

`decodeComment` और `decodeComments` को इस तरह बनाइए कि ये क्रमशः एक अकेले JSON कमेंट ऑब्जेक्ट या कमेंट की एक सूची को डिकोड कर सकें।
ध्यान रखिए कि `decodeComment` में अब तक बनाए गए सभी फंक्शन इस्तेमाल हों, `decodeName` को छोड़कर।
बेशक, `decodeComments` को भी `decodeComment` इस्तेमाल करना चाहिए।

## 8. अब सब जुड़ता है

इन सबमें एक फीचर अभी भी छूटा हुआ है: सर्वर को एक नया कमेंट भेज पाना।
इसके लिए आपको डिकोडर के उलट करना है, यानी आपको एक Elm `Comment` को JSON `Value` में बदल पाना चाहिए।

`encodeComment` को इस तरह बनाइए कि यह किसी भी मान्य `Comment` को एनकोड कर सके।
फील्ड का क्रम मायने नहीं रखता, बस एनकोडर ऐसी वैल्यू बनाए जिसे `decodeComment` डिकोड कर सके।
