# परिचय

Gleam एरर संभालने के लिए एक्सेप्शन का उपयोग नहीं करता। इसके बजाय, जो फंक्शन सफल या असफल हो सकते हैं, वे जेनेरिक `Result` टाइप लौटाते हैं।

`Result` टाइप भाषा में पहले से मौजूद है, इसलिए आपको इसे बनाने या इम्पोर्ट करने की ज़रूरत नहीं है। लेकिन अगर आप इसे खुद बनाते, तो यह कुछ इस तरह दिखता:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

जब कोई फंक्शन सफल होता है, तो `Ok` वेरिएंट लौटाया जाता है। जब कोई फंक्शन असफल होता है, तो `Error` वेरिएंट लौटाया जाता है।

Gleam में रिज़ल्ट बहुत आम हैं, और Gleam प्रोग्रामर उनके साथ काम करना आसान बनाने के लिए अक्सर [`gleam/result` मॉड्यूल](https://hexdocs.pm/gleam_stdlib/gleam/result.html) का इस्तेमाल करते हैं।

अगर रिज़ल्ट `Ok` है, तो `result.map` फंक्शन की मदद से उसके अंदर की वैल्यू पर किसी फंक्शन को कॉल किया जा सकता है। और अगर वह `Error` है, तो उसे बिना बदले आगे भेजा जा सकता है।

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

`result.try` फंक्शन भी ऐसा ही है, लेकिन इसमें कॉलबैक फंक्शन से यह उम्मीद की जाती है कि वह एक रिज़ल्ट लौटाए। यह कई ऐसे फंक्शन को एक साथ जोड़ने के काम आता है जो रिज़ल्ट लौटाते हैं।

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
