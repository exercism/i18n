# विवरण

## पार्शियल एप्लीकेशन

Elm में सारे फंक्शन [करीड][currying] होते हैं। इसका मतलब है कि अगर आप किसी फंक्शन को कॉल करते समय उसके सारे आर्गुमेंट नहीं देते, तो वह एक नया फंक्शन लौटाता है।

ऐसा करने के परिणाम को [पार्शियल एप्लीकेशन][partial-application] कहते हैं। यानी आप फंक्शन को उसके सारे आर्गुमेंट नहीं देते, बल्कि उनमें से कुछ ही देते हैं।

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

पार्शियल एप्लीकेशन आर्गुमेंट को हमेशा क्रम में ही लागू करता है।

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## पाइप ऑपरेटर (`|>`)

`x |> f` लिखना बिल्कुल `f x` लिखने जैसा ही है। एक ठोस उदाहरण देखिए: `"5" |> String.toInt` वही है जो `String.toInt "5"` है।

पहली बार देखने पर यह बहुत काम का नहीं लगता, लेकिन इसे [पाइप ऑपरेटर][pipe-operator] कहते हैं, क्योंकि इससे आप “पाइपलाइन” वाला कोड लिख सकते हैं।

मान लीजिए, हमारे पास एक sanitize फंक्शन है जो उपयोगकर्ता के इनपुट को पूर्णांक में बदलता है:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

हम इसे ऐसे फिर से लिख सकते हैं:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

इसमें ब्रैकेट लगाने की ज़रूरत नहीं पड़ती और फंक्शन उसी क्रम में दिखते हैं जिस क्रम में वे लागू होते हैं (पहले `String.trim`, फिर `String.toInt`)। इससे कोड पढ़ना आसान हो जाता है।

एक [उल्टा पाइप ऑपरेटर `(<|)`][reverse-pipe-operator] भी होता है।
`x <| f` लिखना बिल्कुल `f x` लिखने जैसा ही है।
पहली बार देखने पर यह भी बहुत काम का नहीं लगता। पाइप ऑपरेटर की तरह इसका इस्तेमाल भी उतना नहीं होता, लेकिन कुछ जगहों पर यह ब्रैकेट से बचने में मदद करता है।

## फंक्शन कंपोज़िशन / पॉइंट फ्री स्टाइल

[`(>>)`][forward-composition] ऑपरेटर का टाइप `(a -> b) -> (b -> c) -> (a -> c)` होता है। यह दो ऐसे फंक्शन जोड़ता है जो एक-दूसरे से मेल खाते हैं, एक का टाइप `a -> b ` और दूसरे का `b -> c`, और इस तरह `a -> c` टाइप का नया फंक्शन बनाता है।
यह पहले फंक्शन का आउटपुट (टाइप `b`) लेता है और उसे दूसरे फंक्शन के पहले आर्गुमेंट की तरह इस्तेमाल करता है। दूसरे फंक्शन का टाइप भी `b` ही होना चाहिए।
जो फंक्शन बनता है, वह वही इनपुट (टाइप `a`) लेता है जो पहला फंक्शन लेता है, और जो भी `c` दूसरा फंक्शन लौटाता है, वही लौटाता है।

एक ठोस उदाहरण है `String.trim >> String.toInt`।
`String.trim` अपने इकलौते पैरामीटर की तरह एक स्ट्रिंग लेता है, इसलिए नया फंक्शन भी वही लेता है।
`String.toInt` एक `Maybe Int` लौटाता है, इसलिए नया फंक्शन भी वही लौटाता है।
`String.trim` एक `String` लौटाता है, और `String.toInt` उसे पैरामीटर की तरह स्वीकार करता है, इसलिए यह उदाहरण कंपाइल हो जाता है।

अब हम अपने `sanitize` फंक्शन को ऐसे फिर से लिख सकते हैं:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

ध्यान दीजिए कि अब हम वह `input` पैरामीटर इस्तेमाल नहीं करते जो मूल उदाहरण में दिख रहा था, हालाँकि दोनों का काम करने का तरीका एक जैसा ही है।
अपने पैरामीटर का ज़िक्र किए बिना फंक्शन बनाने के इस तरीके को "पॉइंट फ्री स्टाइल" कहते हैं।
इस स्टाइल का फायदा यह है कि कोड ज़्यादा संक्षिप्त होता है, और नुकसान यह है कि इसे समझना मुश्किल हो सकता है, खासकर शुरुआती लोगों के लिए।

यह याद रखने लायक है कि Elm में सारे फंक्शन करीड होते हैं। इसलिए `String.length >> max` कंपाइल हो जाता है, और उसका नतीजा यह होता है:

- एक फंक्शन (1), जिसका एक स्ट्रिंग पैरामीटर है (`String.length` का इनपुट)
- `max` एक ऐसा फंक्शन है जिसके दो `Int` पैरामीटर हैं, लेकिन फंक्शन 1 उसे सिर्फ एक `Int` देता है, यानी `String.length` से लौटी वैल्यू। इसलिए `max` पर पार्शियल एप्लीकेशन होता है।
- पार्शियल एप्लीकेशन वाले `max` फंक्शन का रिटर्न वैल्यू एक और फंक्शन (2) है, जो एक `Int` लेता है और इस `Int` तथा `String.length` से मिले `Int` में से बड़ी वैल्यू लौटाता है
- इसलिए फंक्शन 1 (`String -> Int`) फंक्शन 2 (`Int -> Int`) लौटाता है
- इस तरह `((String.length >> max) "123") 2` का मान `3` आता है, क्योंकि `"123"` की लंबाई 3 है, जो `Int` आर्गुमेंट वाले 2 से बड़ी है।

## फंक्शन का डिज़ाइन

Elm में साफ-सुथरा कोड लिखना आसान बनाने के लिए आपको मुख्य डेटा स्ट्रक्चर को फंक्शन का अंतिम पैरामीटर रखना चाहिए।
स्टैंडर्ड लाइब्रेरी के सारे आम फंक्शन ऐसा ही करते हैं, जैसे `List.map` (उसका टाइप सिग्नेचर नीचे दिया है)।

```elm
map : (a -> b) -> List a -> List b
```

यहाँ हम देख सकते हैं कि `map` फंक्शन का अंतिम पैरामीटर `List a` है और यह `List b` लौटाता है। यानी मुख्य डेटा स्ट्रक्चर (`List`) ही अंतिम पैरामीटर है।

इससे नीचे जैसा सुंदर पाइपलाइन वाला कोड लिखना संभव हो जाता है।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

इससे पाइपलाइन के बजाय फंक्शन कंपोज़िशन और पॉइंट फ्री स्टाइल का इस्तेमाल करना भी आसान हो जाता है।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

फंक्शन कंपोज़िशन से आप इस उदाहरण को `List.map` के एक ही कॉल तक सीमित कर सकते हैं।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
