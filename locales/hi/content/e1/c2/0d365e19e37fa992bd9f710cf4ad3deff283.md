# परिचय

TypeScript, JavaScript ही है जिसमें टाइप लिखने का सिंटैक्स जोड़ा गया है। इसी वजह से यह एक सख्त टाइपिंग वाली प्रोग्रामिंग भाषा है, जो ऑब्जेक्ट-ओरिएंटेड, इम्परेटिव और डिक्लेरेटिव (जैसे फंक्शनल प्रोग्रामिंग) शैलियों को सपोर्ट करती है और किसी भी पैमाने पर आपको बेहतर टूलिंग देती है।

चूँकि [JavaScript सीखे बिना आप TypeScript नहीं सीख सकते][handbook-js-or-ts], इस ट्रैक की कुछ सामग्री JavaScript की अवधारणाएँ सिखाने पर केंद्रित है और कुछ अवधारणाएँ सिर्फ TypeScript के अपने फीचर पर।

## (दोबारा) असाइन करना

TypeScript में नामों को वैल्यू असाइन करने के कुछ मुख्य तरीके हैं: वेरिएबल या कॉन्स्टेंट इस्तेमाल करना।
Exercism पर वेरिएबल हमेशा [camelCase][wiki-camel-case] में लिखे जाते हैं और कॉन्स्टेंट [SCREAMING_SNAKE_CASE][wiki-snake-case] में।
इसके लिए कोई आधिकारिक गाइड नहीं है, और अलग-अलग कंपनियों तथा संगठनों के अपने-अपने स्टाइल गाइड होते हैं।
_आप अपने वेरिएबल जिस तरह चाहें लिख सकते हैं_।
अगर आप उन्हें वैसे लिखें जैसे अभ्यासों में तैयार किया गया है, तो फायदा यह है कि वेब इंटरफेस और ज़्यादातर IDE में वे अलग तरह से हाइलाइट किए जाएँगे।

TypeScript में वेरिएबल [`const`][mdn-const], [`let`][mdn-let] या [`var`][mdn-var] कीवर्ड की मदद से बनाए जा सकते हैं।

`let` या `var` इस्तेमाल करने पर एक वेरिएबल अपने पूरे जीवनकाल में अलग-अलग वैल्यू रख सकता है।
उदाहरण के लिए, असाइनमेंट ऑपरेटर `=` की मदद से `myFirstVariable` को कई बार बनाया और दोबारा बदला जा सकता है:

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

`let` और `var` के उलट, `const` से बनाए गए वेरिएबल को सिर्फ एक बार ही वैल्यू असाइन की जा सकती है।
TypeScript में कॉन्स्टेंट बनाने के लिए यही तरीका इस्तेमाल होता है।

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

चूँकि TypeScript इसे स्टैटिक रूप से पकड़ लेता है, TypeScript कंपाइलर भी एक एरर देता है:

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

इसका मतलब है कि `TypeError` पकड़ने के लिए आपको कोड चलाने की ज़रूरत नहीं है।

💡 आगे के एक लर्निंग अभ्यास में _कॉन्स्टेंट_ असाइनमेंट / बाइंडिंग और _कॉन्स्टेंट_ वैल्यू के बीच के फर्क को समझा और बताया जाएगा।
~~~~

## टाइप इन्फरेंस

[टाइप इन्फरेंस][handbook-type-inference] के विषय में बहुत गहराई में जाए बिना भी आपको यह पता होना चाहिए कि असाइन किए गए वेरिएबल का टाइप आम तौर पर अपने आप अनुमानित हो जाता है, भले ही उस पर कोई टाइप एनोटेशन लिखा न गया हो।

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

इसके बाद यह टाइप पूरे कोड में लागू रहता है।
इसका यह भी मतलब है कि जहाँ नीचे दिया गया कोड सही JavaScript है:

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

वहीं TypeScript में यही कोड एरर देता है:

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

यह फीचर टाइप-सुरक्षा सुनिश्चित करता है, भले ही टाइप एनोटेशन इस्तेमाल न किए गए हों।

## फंक्शन घोषणाएँ

TypeScript में काम करने वाली इकाइयाँ _फंक्शन_ के रूप में एनकैप्सुलेट होती हैं। जो फंक्शन एक-दूसरे से जुड़े होते हैं, उन्हें आम तौर पर एक ही फाइल में एक साथ रखा जाता है।
ये फंक्शन पैरामीटर (आर्गुमेंट) ले सकते हैं और `return` कीवर्ड की मदद से एक वैल्यू _लौटा_ सकते हैं।
फंक्शन को `()` सिंटैक्स से कॉल किया जाता है।

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

फंक्शन के पैरामीटर पर आम तौर पर कोलन (`:`) और उसके बाद टाइप लिखकर टाइप एनोटेशन किया जाना चाहिए।
पैरामीटर लिस्ट बंद करने के बाद फंक्शन की रिटर्न वैल्यू पर भी कोलन (`:`) और उसके बाद टाइप लिखकर एनोटेशन किया जा सकता है।

<!--prettier-ignore -->
~~~~exercism/note
💡 TypeScript में फंक्शन घोषित करने के _कई_ अलग-अलग तरीके हैं।
इन दूसरे तरीकों की शक्ल `function` कीवर्ड इस्तेमाल करने से अलग होती है।
यह ट्रैक इन्हें धीरे-धीरे पेश करने की कोशिश करता है, लेकिन अगर आप इन्हें पहले से जानते हैं, तो इनमें से कोई भी इस्तेमाल करने में संकोच न कीजिए।
ज़्यादातर मामलों में किसी एक का इस्तेमाल करना बेहतर या खराब नहीं होता।
~~~~

## टाइप एनोटेशन

जैसा कि `add` की फंक्शन घोषणा में दिखाया गया है, उसके पैरामीटर पर साफ-साफ टाइप एनोटेशन `: number` लिखा है।
वेरिएबल घोषणाएँ, क्लास की प्रॉपर्टी, फंक्शन घोषणाएँ और भी बहुत कुछ, सब टाइप एनोटेशन को सपोर्ट करते हैं।

साफ लिखे गए टाइप एनोटेशन और अनुमानित टाइप, दोनों को टाइप-चेकर लागू करता है।

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## दूसरी फाइलों के लिए उपलब्ध कराना

किसी `function`, कॉन्स्टेंट या वेरिएबल को _दूसरी फाइलों_ में उपलब्ध कराने के लिए उन्हें `export` कीवर्ड से [एक्सपोर्ट][mdn-export] करना पड़ता है।
इसके बाद कोई दूसरी फाइल इन्हें `import` कीवर्ड से [इम्पोर्ट][mdn-import] कर सकती है।
इसे मॉड्यूल सिस्टम भी कहा जाता है।
सारे टेस्ट कैसे काम करते हैं, यह इसका बढ़िया उदाहरण है।
हर अभ्यास में कम से कम एक फाइल होती है, जैसे `lasagna.ts`, जिसमें _इम्प्लीमेंटेशन_ रहता है।
इसके अलावा कम से कम एक और फाइल होती है, जैसे `lasagna.test.ts`, जिसमें _टेस्ट_ रहते हैं।
यह फाइल इम्प्लीमेंटेशन को टेस्ट करने के लिए सार्वजनिक (यानी एक्सपोर्ट किए गए) हिस्सों को _इम्पोर्ट_ करती है:

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
