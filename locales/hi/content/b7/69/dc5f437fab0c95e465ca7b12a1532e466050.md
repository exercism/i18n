# परिचय

## कॉपी और रेफरेंस

अभी तक जो हम जानते हैं, उसके हिसाब से किसी फंक्शन की मदद से वेरिएबल को अपडेट करना थोड़ा मुश्किल काम है।
फंक्शन का हर आर्गुमेंट एक कॉपी की तरह लिया जाता है, इसलिए वह मूल वैल्यू को नहीं बदलता।
आपके टाइप के आकार के हिसाब से यह आपके कोड के परफॉर्मेंस पर गंभीर असर डाल सकता है।

```cpp
int adjust_salary(int base, int kids) {
    return base + kids * 500;
}
int now_a_mother_of_twins{2500};
adjust_salary(now_a_mother_of_twins, 2);

// now_a_mother_of_twins is still 2500
now_a_mother_of_twins = adjust_salary(now_a_mother_of_twins, 2);
// now_a_mother_of_twins is now 3500
```

`References` को किसी वेरिएबल के दूसरे नाम की तरह देखा जा सकता है। इनमें किए गए बदलाव मूल वेरिएबल पर असर डालते हैं।
`References` की टाइप घोषणा में **एम्परसैंड** (`&`) लगाया जाता है।

```cpp
int balance{1000};
int& budget{balance};
int pro_computer_wheels{699};
budget -= pro_computer_wheels;
// budget is now 301;
// balance is also 301;
```
रीसीटिंग (किसी `reference` की बाइंडिंग बदलना) संभव नहीं है।
आप बिना इनिशियलाइज़ किए `reference` नहीं रख सकते।
`References` को किसी मौजूदा वेरिएबल से इनिशियलाइज़ करना ज़रूरी है।

```cpp
int main_acc{1'000'000};
int side_acc{-20};
int& savings{main_acc};
// => main_acc and savings are 1'000'000

// try to reseat savings to use main account
savings = side_acc;
// savings and main_acc are now -20
// as this uses the **value** of side_acc
savings += 20;
// savings and main_acc are now 0, side_acc is stil -20

int& future_budget;
// => compiler error, reference must be bound!
```

## `void`

`references` की मदद से आपको शायद फंक्शन से कोई वैल्यू लौटाने की ज़रूरत ही न पड़े।
ऐसी स्थिति में `void` को रिटर्न टाइप की तरह इस्तेमाल किया जाता है।

```cpp
void increase_power(int& level) {
    level += 500;
}
int goku{8700};
increase_power(goku);
// goku's power level?
// It's over 9000!
```
