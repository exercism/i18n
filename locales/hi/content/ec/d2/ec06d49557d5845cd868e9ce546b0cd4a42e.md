# परिचय

Factor का इनपुट/आउटपुट एक ही [प्रोटोकॉल][stream-protocol] पर बना है, जिसे कोई भी डेटा स्रोत या गंतव्य लागू कर सकता है। साथ में दिए गए सभी स्ट्रीम, जैसे `<file-reader>`, `<file-writer>`, `<string-reader>`, `<string-writer>`, नेटवर्क सॉकेट, बाइट ऐरे और tty, ऐसी क्लास हैं जो [`io`][io] के उन्हीं कुछ जेनेरिक को लागू करती हैं और [`destructors`][destructors] के `disposable` का विस्तार करती हैं।

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe` निचले स्तर की बैच रीड है: यह कॉल करने वाले का दिया हुआ बफ़र भरता है और लौटाता है कि कितने एलिमेंट लिखे गए। सार्वजनिक `stream-read` और `stream-read-partial` इसी पर बने हैं और मेमोरी आवंटन का काम संभालते हैं। उपयोगकर्ता के बनाए ज़्यादातर स्ट्रीम या तो `stream-read1` लागू करते हैं (जब पढ़ना एक-एक एलिमेंट करके होता है) या `stream-read-unsafe` (जब पढ़ना बैच में हो सकता है)।

`stream-element-type` दो सिंगलटन टोकन में से एक लौटाता है: बाइट स्ट्रीम (फाइल रीडर, सॉकेट) के लिए `+byte+`, और अक्षर स्ट्रीम (स्ट्रिंग रीडर, tty) के लिए `+character+`। रैपर स्ट्रीम आम तौर पर सिर्फ अपने नीचे वाले स्ट्रीम को काम सौंप देता है।

## मिक्सिन से जुड़ना

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

कोई क्लास इनमें से एक हो सकती है, दूसरी हो सकती है, या दोनों। मिक्सिन से जुड़ने पर `input-stream` / `output-stream` के डिफ़ॉल्ट मेथड आपकी क्लास पर भेजे जाते हैं। यह वही ओपन-मिक्सिन पैटर्न है जो `sets` वोकैब का `set` अपनाता है।

## डिस्पोज़ेबल फ्रेमवर्क

`new-disposable ( class -- disposable )` एक नई इंस्टेंस को मौजूदा डिस्ट्रक्टर स्कोप में दर्ज करता है, ताकि संसाधन तैयार करने के बीच में आया एक्सेप्शन साफ़-सुथरे ढंग से समेट दिया जाए:

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose` सार्वजनिक वर्ड है; `dispose*` वह जेनेरिक है जिसे क्लास लागू करती है। सबक्लास में `dispose*` को ओवरराइड करते समय पहले अपनी स्थिति साफ़ करनी चाहिए और फिर अपने पास मौजूद सभी संसाधन डिस्पोज़ कर देने चाहिए:

```factor
M: my-stream dispose* underlying>> dispose ;
```

फ्रेमवर्क की गारंटी है कि `dispose*` हर ऑब्जेक्ट पर ज़्यादा से ज़्यादा एक बार ही चलता है। बार-बार `dispose` कॉल करने का कोई असर नहीं होता।

## स्कोप वाले एक्सेसर

तीन कॉम्बिनेटर ग्लोबल "मौजूदा इनपुट/आउटपुट स्ट्रीम" सेट करते हैं, जिसे `print`, `read1` आदि इस्तेमाल करते हैं:

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

हर एक बाहर निकलते समय संसाधन को डिस्पोज़ कर देता है, चाहे क्वोटेशन एक्सेप्शन दे ही क्यों न दे। ज़्यादातर कोड अपने कस्टम स्ट्रीम को हर कॉल में पास करते जाने के बजाय इसी तरीके से इस्तेमाल करते हैं।
