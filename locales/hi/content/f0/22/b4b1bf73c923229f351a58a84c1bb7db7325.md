# टेस्ट चलाइए

टर्मिनल से, अभ्यास की बेस डायरेक्टरी में जाइए और फिर इसके साथ टेस्ट चलाइए:

```bash
$ mix test
```

यह `test` सबफोल्डर में मौजूद उस टेस्ट फाइल को चलाएगा जिसका नाम `_test.exs` पर खत्म होता है।

डॉक्यूमेंटेशन:

* [`mix test` - Elixir का टेस्ट चलाने वाला टूल](https://hexdocs.pm/mix/Mix.Tasks.Test.html)
* [`ExUnit` - Elixir की यूनिट टेस्ट लाइब्रेरी](https://hexdocs.pm/ex_unit/ExUnit.html)

## पेंडिंग टेस्ट

प्रैक्टिस अभ्यासों के टेस्ट सूट में, पहले टेस्ट को छोड़कर बाकी सभी टेस्ट को स्किप करने के लिए टैग किया गया है।

एक बार जब कोई टेस्ट पास हो जाए, तो आप अगले टेस्ट को संबंधित `@tag :pending` को `#` चिह्न से कमेंट आउट करके अनस्किप कर सकते हैं।

उदाहरण के लिए:

```elixir
# @tag :pending
test "shouting" do
  assert Bob.hey("WATCH OUT!") == "Whoa, chill out!"
end
```

यदि आप सभी टेस्ट एक साथ चलाना चाहें, तो आप `mix test` कमांड पर `--include` फ्लैग का उपयोग करके सभी स्किप किए गए टेस्ट को शामिल कर सकते हैं:

```bash
$ mix test --include pending
```

या, आप फाइल `test/test_helper.exs` में `ExUnit.configure` लाइन को कमेंट आउट करके सभी टेस्ट चालू कर सकते हैं।

```elixir
# ExUnit.configure(exclude: :pending, trace: true)
```

## उपयोगी `mix test` विकल्प

* `test/<FILE>.exs:LINENUM` - केवल एक ही टेस्ट चलाता है, यानी `<FILE>.exs` से वह टेस्ट जिसकी परिभाषा `LINENUM` लाइन पर है।
* `--failed` - केवल वे टेस्ट चलाता है जो पिछली बार चलने पर फेल हुए थे।
* `--max-failures` - जब टेस्ट फेल होने की यह संख्या पहुँच जाती है, तो सूट टेस्ट का मूल्यांकन रोक देता है।
* `--seed 0` - रैंडमाइज़ेशन को बंद कर देता है ताकि एक ही फाइल के टेस्ट हमेशा उसी क्रम में चलें जिस क्रम में उन्हें परिभाषित किया गया था।
