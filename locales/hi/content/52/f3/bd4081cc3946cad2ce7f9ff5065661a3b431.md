# विवरण

Factor स्ट्रीम I/O को दो परतों में बाँटता है। नीचे वाली परत *एक्सप्लिसिट स्ट्रीम* API है: इसमें हर वर्ड स्ट्रीम को एक आर्गुमेंट के रूप में लेता है। ऊपर वाली परत *एम्बिएंट स्ट्रीम* API है: छोटे-छोटे, एक लाइन वाले वर्ड, जो उसी स्ट्रीम पर काम करते हैं जो उस समय बाइंड है। दोनों परतें एक ही [प्रोटोकॉल][stream-protocol] पर टिकी हैं। ऊपरी परत के वर्ड बस एम्बिएंट स्ट्रीम देख लेते हैं और कॉल आगे भेज देते हैं।

## एक्सप्लिसिट स्ट्रीम के वर्ड

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents` स्ट्रीम का सारा डेटा पढ़ लेता है; `stream-lines` सारा डेटा पढ़कर उसे लाइनों की सीमाओं पर बाँट देता है; और `stream-readln` एक बार में एक लाइन लौटाता है (या स्ट्रीम के अंत पर `f`)।

## एम्बिएंट स्ट्रीम के वर्ड

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

ये रोज़मर्रा के I/O वर्ड हैं। ये मौजूदा इनपुट या आउटपुट स्ट्रीम को डायनैमिक वेरिएबलो `input-stream` / `output-stream` से देख लेते हैं और कॉल आगे भेज देते हैं। इसीलिए `print` को किसी स्ट्रिंग पर रीडायरेक्ट करना बस इतनी बात है कि आप किसी कोटेशन के चलने की अवधि तक `output-stream` बाइंड कर दें।

## साथ आने वाले स्ट्रीम कंस्ट्रक्टर

| वर्ड              | वोकैब                | यह क्या बनाता है                |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | एक लिटरल स्ट्रिंग पढ़ता है       |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | लिखे जाने वाले डेटा को एक स्ट्रिंग में जमा करता है |
| `<file-reader>`   | [`io.files`][io.files]           | एन्कोडिंग के साथ एक फाइल पढ़ता है |
| `<file-writer>`   | [`io.files`][io.files]           | एन्कोडिंग के साथ एक फाइल में लिखता है |

ये चारों डिस्पोज़ेबल बनाते हैं। ये `destructors` के `disposable` को एक्सटेंड करते हैं, इसलिए नीचे दिए गए `with-…` कॉम्बिनेटर बाहर निकलते समय इन्हें रिलीज़ कर देते हैं।

## स्कोप्ड बाइंडिंग

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

इनमें से हर वर्ड एक स्ट्रीम खोलता है, अंदर चलने वाले कोटेशन के लिए उसे एम्बिएंट इनपुट या आउटपुट बना देता है, और बाहर निकलते समय उसे डिस्पोज़ कर देता है, भले ही वह कोटेशन कोई एक्सेप्शन फेंके। ये `boatswains-bilge` के डिस्ट्रक्टर कॉम्बिनेटर हैं, जो स्ट्रीम के लिए खास तौर पर बनाए गए हैं।

`with-string-writer` खास तौर पर साफ-सुथरा रूप है: यह अपने आप एक नया `<string-writer>` बनाता है, उस राइटर को एम्बिएंट आउटपुट बनाकर कोटेशन चलाता है, और जमा हुई स्ट्रिंग लौटा देता है। "कोटेशन का आउटपुट पकड़ लेना" वाला पूरा पैटर्न बस एक ही वर्ड में है।

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## एम्बिएंट स्ट्रीम की ज़रूरत क्यों?

डायनैमिक वेरिएबलो की यह बाइंडिंग ही वजह है कि `print` ऐसे प्रोग्राम में भी काम करता है, जिसे पता नहीं होता कि उसे इंटरैक्टिव तरीके से चलाया जा रहा है, किसी लॉग फाइल में लिखा जा रहा है, या किसी टेस्ट बफर में आउटपुट जमा किया जा रहा है। बाइंडिंग को एक बार बदल दीजिए, और `print` को कॉल करने वाला हर वर्ड अपने आप सही काम करने लगता है। किसी तार को दोबारा जोड़ने की ज़रूरत नहीं। ऊपरी परत की देन यही उलटफेर है।

किसी स्ट्रीम को *लागू करने* के बारे में, यानी अपनी खुद की ऐसी क्लास बनाने के बारे में जो इस प्रोटोकॉल से जुड़ती है, `streams` कॉन्सेप्ट में देखिए (यह `telegraphers-tape` में सिखाया जाता है)।
