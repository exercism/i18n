# लूपिंग का परिचय

Bash में लूप करने के दो रूप हैं:

* _किसी सूची के हर आइटम के लिए_ कुछ कमांड दोहराना,
* _जब तक कोई शर्त सही (या गलत) है_, तब तक कुछ कमांड दोहराना।

## `for` लूप

आइटम की किसी सूची पर इटरेशन करने के लिए हम `for` लूप का उपयोग करते हैं।

```bash
for varname in words; do COMMANDS; done
```

`words` का विस्तार वर्ड स्प्लिटिंग और फाइलनेम एक्सपैंशन से होता है (जिसके बारे में हमने [कोटिंग कॉन्सेप्ट][quoting] में सीखा था)।
हर शब्द बारी-बारी से `varname` को असाइन किया जाता है, और COMMANDS चलाए जाते हैं।

यहाँ कुछ उदाहरण दिए गए हैं जो बताते हैं कि for लूप कब काम का हो सकता है

* फाइलों के एक समूह पर कुछ कमांड चलाना।

    ```bash
    # source all the bash library files in the current directory
    for file in ./*.bash; do
        source "$file"
    done
    ```

* किसी स्क्रिप्ट या फंक्शन के हर पैरामीटर पर कुछ कमांड चलाना।

    ```bash
    for arg in "$@"; do
        echo "argument: ${arg}"
    done
    ```

* किसी कमांड के आउटपुट में व्हाइटस्पेस से अलग किए गए हर शब्द के लिए कुछ कमांड चलाना।

    ```bash
    for i in $(seq 10); do
        echo "${i} squared is $((i * i))"
    done
    ```

    इस तरीके के बारे में कुछ चेतावनियाँ हम आगे देखेंगे।

### अंकगणितीय `for` लूप

Bash में अंकगणितीय लूप मौजूद है।
दूसरी प्रोग्रामिंग भाषाएँ सीख चुके लोगों को यह थोड़ा परिचित लगेगा।

```bash
for ((INITIALIZATION; CONDITION; INCREMENT)); do COMMANDS; done
```

bash में दोहरे गोल ब्रैकेट एक अंकगणितीय संदर्भ दर्शाते हैं (bash के अंकगणित के बारे में हमें आगे के किसी कॉन्सेप्ट में और देखने को मिलेगा)।
`seq` वाला ऊपर का उदाहरण इस तरह लिखा जा सकता है

```bash
for ((i = 1; i <= 10; i++)); do
    echo "${i} squared is $((i * i))"
done
```

### `for` का उपयोग कब न करें

[`for` से लाइनें न पढ़ें][bashfaq1]।

यह एक एंटी-पैटर्न है जो आपको अक्सर दिखेगा: `cat` के आउटपुट पर इटरेशन करना।

```bash
for line in $(cat some.file); do 
    do_something_with "$line"
done
```

यह दो कारणों से गलत है।

1. कमांड सबस्टिट्यूशन बिना कोट के है, इसलिए यह वर्ड स्प्लिटिंग के अधीन है।
   वर्ड स्प्लिटिंग डिफ़ॉल्ट रूप से सिर्फ न्यूलाइन पर नहीं, बल्कि _व्हाइटस्पेस_ पर टूटती है।
   यह for लूप फाइल के **शब्दों** पर इटरेशन कर रहा है, लाइनों पर नहीं।
2. कमांड सबस्टिट्यूशन बिना कोट के है, इसलिए यह फाइलनेम एक्सपैंशन के अधीन है।
   फाइल के हर शब्द को एक ग्लोब पैटर्न की तरह मैच किया जाएगा।

जैसा कि हमने [कोटिंग कॉन्सेप्ट][quoting] में सीखा, वर्ड स्प्लिटिंग को `IFS` वेरिएबल से नियंत्रित किया जा सकता है, और फाइलनेम एक्सपैंशन को बंद किया जा सकता है।
लेकिन यह हल कमज़ोर साबित होता है।
किसी फाइल की लाइनों पर इटरेशन करने के लिए `for` गलत तरीका है।
फाइल पढ़ने का प्रचलित तरीका `while` लूप है।

## `while` लूप

कुछ कमांड के क्रम को _जब तक_ कोई शर्त सही है, दोहराने के लिए `while` का उपयोग कीजिए।

```bash
while CONDITION_COMMANDS; do COMMANDS; done
```

जैसे `if` के साथ होता है (जैसा हमने [कंडीशनल्स कॉन्सेप्ट][conditionals] में सीखा, CONDITION_COMMANDS के लिए कोई खास सिंटैक्स नहीं होता।
कमांड सूची का एग्ज़िट स्टेटस तय करेगा कि वह "सही" है या "गलत"।

## लूप को नियंत्रित करना

`break` कमांड लूप से बाहर निकाल देता है।
इसके बाद नियंत्रण लूप के `done` टर्मिनेटर के बाद आने वाले कमांड से जारी होता है।

`continue` कमांड लूप के अगले इटरेशन पर पहुँचा देता है।

## फाइल की लाइनें पढ़ना

जैसा कहा गया, फाइल पढ़ने का प्रचलित तरीका `while` लूप है।

```bash
while IFS= read -r line; do
    do_something_with "$line"
done < some.file
```

* फाइल की सामग्री `<` रीडायरेक्शन के ज़रिए लूप को इनपुट के रूप में दी जाती है।
* `read` कमांड "सही" लौटाता है अगर वह अपने इनपुट से एक पूरी लाइन पढ़ पाता है।
  जब इनपुट खत्म हो जाता है, या अंतिम लाइन बिना अंत में न्यूलाइन के खत्म होती है, तो read "गलत" लौटाता है।
  * फाइल की लाइनें पढ़ने का _सचमुच_ प्रचलित तरीका, भले ही अंतिम लाइन न्यूलाइन पर खत्म न हो, यह है

    ```bash
    while IFS= read -r line || [[ -n "$line" ]]; do ...
    ```

* `-r` विकल्प `read` को कहता है कि वह बैकस्लैश सीक्वेंस को प्रतिस्थापित न करे: बैकस्लैश सिर्फ एक साधारण अक्षर है।
* `IFS=` खाली स्ट्रिंग को सिर्फ read कमांड की अवधि के लिए IFS में असाइन करता है।
  इससे वर्ड स्प्लिटिंग अस्थायी रूप से बंद हो जाती है, जिससे आने वाली टेक्स्ट लाइन के आगे या पीछे का कोई भी व्हाइटस्पेस सुरक्षित रहता है।

## Until

`until` कंस्ट्रक्ट कुछ कमांड के क्रम को तब तक दोहराता है जब तक कोई शर्त **गलत** रहती है।
लूप तब तक दोहराता है _जब तक_ शर्त सही न हो जाए।

```bash
until CONDITION_COMMANDS; do COMMANDS; done
```

`until` का उपयोग कम ही होता है।
इसके बजाय "जब तक नहीं" वाला लूप ज़्यादा आम है।

```bash
while ! CONDITION_COMANDS; do ...
```

## अनंत लूप

कभी-कभी आपको हमेशा के लिए लूप करना होता है।
इसके दो तरीके हैं।

1. ऐसा while लूप जिसकी शर्त का एग्ज़िट स्टेटस हमेशा सफल होता है

    ```bash
    while true; do ...
    ```

2.  खाली एक्सप्रेशन वाला अंकगणितीय for लूप

    ```bash
    for ((;;)); do ...
    ```

## Do-While

कोई स्पष्ट do-while कंस्ट्रक्ट नहीं है, लेकिन आप वही असर पा सकते हैं:

```bash
while true; do
    COMMANDS

    if END_CONDITION; then
        break
    fi
done
```
