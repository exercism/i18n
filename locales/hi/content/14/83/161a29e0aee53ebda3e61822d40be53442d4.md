# परिचय

`MACRO:` घोषणा `:` जैसी ही होती है, लेकिन इसमें बॉडी *कंपाइल समय* पर चलती है और उसे एक क्वोटेशन लौटाना होता है। कंपाइलर मैक्रो कॉल की जगह उसी लौटाए गए क्वोटेशन को रख देता है। बॉडी साधारण Factor कोड ही होती है, इसलिए नतीजे वाला क्वोटेशन बनाना सिर्फ वर्ड के सीक्वेंस को संभालने का काम है।

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- compound )
    dup append ;

: shout-twice ( name -- ) [ " ahoy!" append print ] twice ;
! At compile time, the call site is replaced with
! [ " ahoy!" append print " ahoy!" append print ].
```

मैक्रो को जो इनपुट मिलते हैं, वे *कॉल की जगह पर मौजूद लिटरल* होते हैं। अगर आप कोई ऐसी वैल्यू भेजें जो लिटरल नहीं है, तो कंपाइलर उसे स्पेशलाइज़ करने से मना कर देगा। वजह यह है कि मैक्रो की बॉडी को यह वैल्यू कंपाइल समय पर चाहिए, रनटाइम पर नहीं।

इसका एक करीबी रिश्तेदार `<< … >>` पार्स-टाइम इवैल्युएशन ब्लॉक है, जो कोड कंपाइल होते समय मनमाना Factor कोड चलाता है और क्वोटेशन लौटाने की शर्त भी नहीं रखता। दोनों ही Factor के [`macros`][macros] तंत्र के अंदर आते हैं।

[macros]: https://docs.factorcode.org/content/vocab-macros.html
