## <a name="virtual-environments"></a>वर्चुअल एनवायरनमेंट

Python के वर्चुअल एनवायरनमेंट रनटाइम और पैकेज के लिए हल्का आइसोलेशन देते हैं।
ये आपके प्रोजेक्ट व्यवस्थित करने में मदद करते हैं, क्योंकि आप जो Python पैकेज इंस्टॉल करते हैं, वे किसी एक खास एनवायरनमेंट डायरेक्टरी के अंदर एक साथ रखे रहते हैं।
अलग-अलग एनवायरनमेंट में Python रनटाइम के अलग-अलग संस्करण, साथ में प्रोजेक्ट या लाइब्रेरी की निर्भरताएँ भी रखी जा सकती हैं।
इससे ऐसे बग और असंगतताओं से बचने में मदद मिलती है जो किसी एक प्रोजेक्ट के लिए लाइब्रेरी अपग्रेड करने पर पैदा होती हैं और किसी दूसरे प्रोजेक्ट की निर्भरता को "तोड़" देती हैं।

आज बहुत से *वर्चुअल एनवायरनमेंट* और *वर्चुअल एनवायरनमेंट जैसे* टूल इस्तेमाल में हैं, और वर्चुअल एनवायरनमेंट की जगह [इनलाइन स्क्रिप्ट मेटाडेटा][PEP723], [डेव कंटेनर][dev containers] या [docker][docker] इस्तेमाल करने का चलन बढ़ रहा है।
यह ज़रूरी है कि आप अलग-अलग तरीके आज़माकर देखें और ऐसा तरीका चुनें जो आपकी डेवलपमेंट शैली और प्रोजेक्ट की ज़रूरतों के अनुकूल हो।
यह न मान लीजिए कि यहाँ बताए गए तरीके हर जगह लागू होते हैं, या यही आपके पास एकमात्र विकल्प हैं।
यहाँ न बताए गए टूल की अधिक सामान्य जानकारी के लिए [Bas Nijholt की यह ब्लॉग पोस्ट][bas nihholt] देखिए और जिज्ञासु बने रहिए।


यहाँ हम तीन मुख्य *वर्चुअल एनवायरनमेंट* टूल पर चर्चा करेंगे: Python की स्टैंडर्ड लाइब्रेरी [`venv`][venv], तीसरे पक्ष का [`conda env`][condaenv], जो [`conda`][conda] पैकेज मैनेजर और (_आमतौर पर_) Anaconda Python डिस्ट्रिब्यूशन का उपयोग करता है, और तीसरे पक्ष का `pip` + `venv` का विकल्प [`uv`][uv]।
तीनों को इस्तेमाल करना और/या इंस्टॉल करना काफी सीधा है।

इसके अलावा, [`PyEnv`][pyenv], [`Poetry`][poetry] और [virtualenvwrapper][virtualenvwrapper] ऐसे टूल हैं जो एक ही मशीन पर Python के कई संस्करण और कई Python एनवायरनमेंट मैनेज करने में मदद कर सकते हैं।

### <a name="creating-a-virtual-environment-with-venv"></a>`venv` से वर्चुअल एनवायरनमेंट बनाना

`venv` से वर्चुअल एनवायरनमेंट बनाने के लिए उस डायरेक्टरी में `cd` कीजिए जहाँ आप अपने एनवायरनमेंट रखना चाहते हैं।
यह डायरेक्टरी आपके प्रोजेक्ट के कोड से **अलग** होनी चाहिए, और ऐसी होनी चाहिए जिसे आप सोर्स कंट्रोल में **नहीं** डालेंगे।
इसके बाद `venv` कमांड उस फोल्डर के नाम के साथ चलाइए जहाँ आप यह खास **एनवायरनमेंट** रखना चाहते हैं।
आम तौर पर उस फोल्डर का नाम `<project-name-here>_venv` रखा जाता है:

**Windows**

```powershell
PS C:\Users\foobar> py -m venv {name_of_virtualenv}
```
वर्चुअल एनवायरनमेंट सक्रिय करने के लिए यह कमांड चलाइए:

```powershell
PS> .\{name_of_virtual_env}\Scripts\activate.bat
(venv) PS> _
```

<br>

**Linux/MacOS**

```bash
$ python3 -m venv {name_of_virtualenv}
created virtual environment ... in 8568ms
```

वर्चुअल एनवायरनमेंट सक्रिय करने के लिए यह कमांड चलाइए:

```bash
$ source {name_of_virtual_env}/bin/activate
(venv) $ _
```

एक बार कोई `venv` सक्रिय हो जाने पर, आप एनवायरनमेंट के "अंदर" पैकेज इंस्टॉल करने के लिए `pip` कमांड चला सकते हैं।
इंस्टॉल किए गए पैकेज `venv` के Python संस्करण से जुड़े होंगे और `{name_of_virtual_env}/Lib` के अंदर रखे जाएँगे।

किसी वर्चुअल एनवायरनमेंट को _निष्क्रिय_ करने के लिए `deactivate` स्क्रिप्ट को कॉल करना होता है, जो `activate` वाली ही डायरेक्टरी में रहती है।

<br>

### <a name="creating-a-virtual-environment-using-conda"></a>`conda` का उपयोग करके वर्चुअल एनवायरनमेंट बनाना

*`conda` का नवीनतम संस्करण [miniconda][miniconda] से इंस्टॉल किया जा सकता है।*
यह [`conda` चीटशीट][conda-cheatsheet] बहुत उपयोगी है, और [`conda` के दस्तावेज़][conda-docs] भी।

शुरू में `conda` को "वैज्ञानिक Python" वाले लोकप्रिय [`Anaconda distribution`][anaconda] के लिए Python पैकेज मैनेजर के रूप में बनाया गया था, बाद में इसे सामान्य और विस्तृत किया गया।
conda एनवायरनमेंट `venv` जैसे ही होते हैं, पर मुख्य अंतर यह है कि conda, Python के अलावा कई और प्रोग्रामिंग भाषाओं के लिए भी वर्चुअल एनवायरनमेंट बना सकता है और पैकेज इंस्टॉल कर सकता है।

conda द्वारा समर्थित भाषाओं में `R`, `JavaScript`, `Ruby`, `Fortran`, `C/C++`, `Scala`, `Java` और बहुत कुछ शामिल हैं।
conda और venv कमांड की तुलना के लिए conda का [कमांड संदर्भ][conda command ref] देखिए।

<br>

### <a name="uv">UV

uv के साथ प्रोजेक्ट पर काम करना: [uv][uv-docs]

`uv` [Astral][astral] का बनाया हुआ एक Python पैकेज + प्रोजेक्ट मैनेजमेंट टूल है, जो [Rust][rust programming language] में लिखा गया है।
इसे `pip`, `venv`, `poetry` और Python के अन्य पैकेजिंग/निर्भरता प्रबंधन टूल की जगह लेने के लिए बनाया गया था।
`Conda` या `Mamba` के विपरीत, uv सिर्फ Python के लिए खास तौर पर बनाया गया है।
हालाँकि, uv दूसरी भाषाओं, जैसे Fortran, में लिखे गए Python एक्सटेंशन मॉड्यूल बनाने का समर्थन करता है।
Astral लोकप्रिय [Ruff][ruff] लिंटर और [TY][ty] का भी डेवलपर है, जो Python टाइप हिंट के लिए एक स्टैटिक टाइप चेकर है। दोनों Rust में लिखे गए हैं।


यहाँ विस्तार में जाने के बजाय, इंस्टॉलेशन और सेटअप के लिए [UV का दस्तावेज़][uv documentation] आपका सबसे अच्छा स्रोत है।

### <a name="virtual-environment-wrapper">वर्चुअल एनवायरनमेंट रैपर

दस्तावेज़ और पृष्ठभूमि: [virtualenvwrapper][virtualenvwrapper]।

`virtualenvwrapper` पैकेज `venv` के ऊपर काम करता है और आपके सारे वर्चुअल एनवायरनमेंट एक ही जगह मैनेज करता है।
आप `lsvirtualenv` (_एनवायरनमेंट की सूची देखने के लिए_) और `mkvirtualenv` (_एनवायरनमेंट बनाने के लिए_) जैसे linux जैसे कमांड से एनवायरनमेंट बना, कॉपी, डिलीट और बदल सकते हैं।
यह एक्सटेंशन की मदद से और भी मैनेजमेंट टूल जोड़ने की सुविधा देता है।
आप [यह ट्यूटोरियल][venv wrapper tutorial] देखकर इस टूल के लिए अपने खुद के एक्सटेंशन भी बना सकते हैं।

### <a name="pyenv"></a>PyEnv

`pyenv` लोकप्रिय `rbenv`/`ruby-build` टूल का Python के लिए बनाया गया फोर्क है।
यह मूल रूप से स्क्रिप्ट और शिम का एक ऐसा समूह है जिससे आप Python के संस्करण पूरे सिस्टम के लिए और हर उपयोगकर्ता के लिए अलग-अलग सेट कर सकते हैं।
यह Unix की उस परंपरा का पालन करने की कोशिश करता है, जिसमें एक टूल सिर्फ एक काम करता है और वह भी अच्छी तरह, बिना किसी दखल के।

`pyenv` और इसके दस्तावेज़ [GitHub][pyenv on github] पर मिल सकते हैं।

### <a name="visual-studio-code"></a>Visual Studio Code

[Visual Studio Code (VS Code)][vscode] Microsoft का बनाया हुआ एक मुफ्त कोड एडिटर है।
इसमें [वर्चुअल/conda एनवायरनमेंट][virtual environments in vscode] के साथ-साथ [`docker`][docker in vscode] (_[docker प्लग-इन][vs code docker plugin] के ज़रिए_) का भी बढ़िया समर्थन है, और इसे [टेस्टिंग][python testing in vscode], [लिंटिंग][linting python in vscode], [फॉर्मेटिंग][formatting python in vscode] और [वेब डेवलपमेंट][python web dev in vscode] के लिए कई अलग-अलग प्लगइन से बढ़ाया जा सकता है।

#### <a name="python-for-vs-code"></a>VS Code के लिए Python

_Extension-id: ms-python.python_

![VS Code पर Python एक्सटेंशन हेडर](https://raw.githubusercontent.com/exercism/python/main/docs/img/VSCode-EXT-Python-Header.png)

[Microsoft का Python एक्सटेंशन][MS Python extension] VS Code के लिए Microsoft का आधिकारिक Python एक्सटेंशन है, और इसे इंस्टॉल करने की सलाह ज़रूर दी जाती है।
इसमें एनवायरनमेंट मैनेजमेंट, टेस्ट मैनेजमेंट, लिंटिंग और डीबगिंग सहित कई फीचर हैं।
[नवीनतम रिलीज़][vs code python latest release] के अनुसार, MS Python एक्सटेंशन इंस्टॉल करने पर [pylance][vs code pylance] (_Python कोड की लिंटिंग और जाँच के लिए एक लोकप्रिय पैकेज_) और [jupyter][vs code jupyter] (_Jupyter Notebooks के साथ काम करने के लिए_) भी डाउनलोड हो जाते हैं।

- सेटअप के लिए [यहाँ ट्यूटोरियल][python extension setup tutorial] उपलब्ध है, और [सेटिंग्स संदर्भ][vs code python settings reference] बहुत उपयोगी है।
- Python संस्करण सेट करने या वर्चुअल एनवायरनमेंट के साथ काम करने की जानकारी [यहाँ][virtual environments in vscode] मिल सकती है।
- VS Code में unittest और pytest सेट करने और उनके साथ काम करने की जानकारी [यहाँ][python testing in vscode] मिल सकती है।

### <a name="pycharm"></a>PyCharm

[PyCharm][pycharm download] [JetBrains][jetbrains] का बनाया हुआ एक `IDE` (_इंटीग्रेटेड डेवलपमेंट एनवायरनमेंट_) है।
यह खास तौर पर Python के लिए बनाया गया है और पेशेवरों में लोकप्रिय है।
VS Code की तरह, इसे भी कई मुफ्त और पेड प्लगइन, थीम और फॉर्मेटर से बढ़ाया जा सकता है।
पेड संस्करण [Django डेवलपमेंट][pycharm django dev], [Docker डेवलपमेंट][pycharm docker] और [डेटाबेस इंटीग्रेशन][pycharm database tools] का भी समर्थन करता है।

- Python संस्करण सेट करने की जानकारी [Python इंटरप्रेटर कॉन्फिगर करना][pycharm interpreter config] और [वर्चुअल एनवायरनमेंट कॉन्फिगर करना][pycharm config venv] में मिल सकती है।

<details>
    <summary>Pycharm और Pytest</summary>

  - pycharm के साथ pytest सेट करने के चरण [यहाँ][pycharm pytest docs] मिल सकते हैं।
  - pycharm डिफॉल्ट रूप से `unittest` इस्तेमाल करता है, इसलिए जिस एनवायरनमेंट के साथ आप pycharm चला रहे हैं उसमें `pytest` इंस्टॉल होना चाहिए (_ऊपर दिए गए इंटरप्रेटर और एनवायरनमेंट के दस्तावेज़ देखिए_), और फिर pycharm को उसी की ओर इंगित करना पड़ता है।
  - [टेस्ट चलाना][pycharm gui running tests] सीधे GUI से काफी आसान है, लेकिन उसके पीछे के [pytest पैरामीटर](TESTS.md#extra-arguments) को अच्छे से देखना न भूलें, ताकि यह आपकी पसंद के मुताबिक सेट हो जाए।
  - pycharm में टेस्ट चलाने और डीबग करने का सामान्य दस्तावेज़ [यहाँ][pycharm run tests] मिल सकता है।

</details>

- डीबगिंग के अतिरिक्त टूल और मार्गदर्शन [यहाँ][pycharm debugging tools] मिल सकते हैं।
  -  **चेतावनी**: `pytest` के लिए `coverage` प्लगइन pycharm के डीबगर को तोड़ देगा।
     अधिक जानकारी के लिए [run/debug configuration: pytest][pycharm debug configuration] देखिए।

### <a name="spyder-ide">Spyder IDE

[Spyder][spyder-ide] एक क्रॉस-प्लेटफॉर्म, मुफ्त और ओपन सोर्स Python IDE है, जो वैज्ञानिक समुदाय के लिए बनाई गई है।
यह आमतौर पर Python के Anaconda डिस्ट्रिब्यूशन के साथ आता है, लेकिन इसे [अकेले भी इंस्टॉल][spyder standalone installers] किया जा सकता है और Python के किसी भी संस्करण के साथ इस्तेमाल किया जा सकता है।
हम स्टैंडअलोन इंस्टॉलेशन की सलाह देते हैं, ताकि अधिकतम लचीलापन मिले और पैकेज में कोई टकराव न हो।

Spyder `venv` और `conda` एनवायरनमेंट का पूरा समर्थन करता है।
इसमें एक इंटीग्रेटेड [IPython][ipython] इंटरैक्टिव टर्मिनल, एक इंटरैक्टिव डीबगर, और एडिटर के भीतर ग्राफ बनाने और डेटा खोजने का भरपूर समर्थन शामिल है।
अतिरिक्त कोड कम्पलीशन और लिंटिंग [kite][kite] के ज़रिए उपलब्ध होती है।
[Jupyter Notebooks][spyder notebook plugin] और [टेस्टिंग टूल][spyder unittest plugin] के साथ इंटीग्रेशन समुदाय द्वारा बनाए गए प्लगइन के ज़रिए उपलब्ध हैं।
आप Spyder API का उपयोग करके [अपने खुद के प्लगइन][writing spyder plugins] भी लिख सकते हैं।

### <a name="vim"></a>Vim

[Vim][vimdotorg] Unix के स्टैंडर्ड `vi` टेक्स्ट एडिटर का मुफ्त और "बेहतर" संस्करण है।
यह कई तरह के ऑपरेटिंग सिस्टम और Linux/Unix वेरिएंट पर उपलब्ध है।
Real Python पर एक बढ़िया [इंस्टॉलेशन और सेटअप गाइड][vim setup at real python] उपलब्ध है, और काम के चीट शीट [vimsheet][vim cheat sheet], [glump][glump vim cheatsheet] और [rtorr][rtorr vim cheat sheet] पर मिल सकते हैं।


भले ही आपको लगे कि `vim` में Python कोड एडिट करना आपके लिए नहीं है, फिर भी कुछ बुनियादी कमांड से परिचित हो जाना अच्छा रहता है।
Linux और Unix डिस्ट्रिब्यूशन में `vim` या `vi` अक्सर "बेस" या "डिफॉल्ट" टेक्स्ट एडिटर होता है, और उन सिस्टम पर `git` कमिट संदेशों (_और दूसरी कई चीज़ों_) के लिए यही डिफॉल्ट एडिटर होता है।
बहुत संभव है कि आप किसी *nix सिस्टम पर फँस जाएँ और आपको सिर्फ `vi` के साथ कोई कॉन्फिगरेशन फाइल एडिट करनी पड़े, इसलिए [vim से बाहर निकलना][how do I quit vim] जानना (_कम से कम_) अच्छी आत्मरक्षा है।

<br>

- spacemacs का [python layer][spacemacs python layer] टेस्टिंग, लिंटिंग, एनवायरनमेंट मैनेजमेंट और कोड फॉर्मेटिंग की सुविधा जोड़ता है।
