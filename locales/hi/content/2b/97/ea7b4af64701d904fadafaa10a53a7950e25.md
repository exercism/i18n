# परिचय

हैश-सेट भीतर हैशिंग का इस्तेमाल करते हुए [`sets`][sets] [प्रोटोकॉल][set-protocol] लागू करते हैं, और औसतन O(1) समय में इनमें एलिमेंट जोड़ना, ढूँढना और हटाना संभव होता है। ये मौके पर ही बदले जा सकते हैं, इसलिए ग्राफ ट्रैवर्सल में *विज़िट किए गए सेट* वाले पैटर्न के लिए ये एकदम उपयुक्त हैं।

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| वर्ड          | प्रभाव                                    |
|---------------|-------------------------------------------|
| `HS{ }`       | खाली हैश-सेट लिटरल (यह साझा होता है, इसलिए उसे `clone` कीजिए!) |
| `>hash-set`   | `( seq -- set )`, किसी सीक्वेंस से नया सेट बनाता है (डुप्लीकेट हटाकर) |
| `adjoin`      | `( elt set -- )`, मौजूदा सेट में ही एलिमेंट जोड़ता है     |
| `in?`         | `( elt set -- ? )`, बताता है कि एलिमेंट सेट में है या नहीं           |
| `delete`      | `( elt set -- )`, मौजूदा सेट से ही एलिमेंट हटाता है     |
| `cardinality` | `( set -- n )`, सेट में कितने एलिमेंट हैं, यह बताता है       |
| `null?`       | `( set -- ? )`, सेट खाली हो तो सही देता है |
| `members`     | `( set -- seq )`, सेट के सारे एलिमेंट सीक्वेंस के रूप में देता है  |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )`, `set` को `exemplar` की क्लास में बदल देता है |

जो डेटा आपके पास पहले से है, उससे सेट बनाने के लिए `>hash-set` किसी भी सीक्वेंस को एक ही कदम में बदल देता है और डुप्लीकेट हटा देता है। जैसे `{ 2 3 2 5 } >hash-set` का परिणाम `HS{ 2 3 5 }` होता है। बार-बार `adjoin` करके सेट बढ़ाने की तुलना में यह पूरे डेटा पर एक साथ काम करने वाला रूप है।

`in?` और `member?` (`sequences` से) के बीच एक बारीक फ़र्क़ यह है: दोनों यही जाँचते हैं कि कोई चीज़ मौजूद है या नहीं, लेकिन `member?` सीक्वेंस पर एक-एक करके यानी लीनियर स्कैन करता है, जबकि `in?` यह काम सेट टाइप के प्रोटोकॉल मेथड को सौंप देता है, और `HS{ }` के लिए वह मेथड हैश लुकअप करता है। जब आपका "विज़िट" कंटेनर कुछ गिने-चुने एलिमेंट से ज़्यादा रखने लगे, तब `in?` इस्तेमाल कीजिए।

`null?` पूरी `cardinality` निकाले बिना बताता है कि सेट खाली है या नहीं। यह इस सवाल की स्वाभाविक जाँच है कि "क्या अब भी कुछ बचा है जिसे पूरा करना है?"। जब काम की सूची किसी सेट में रखी हो, तो `[ set null? ] [ … ] until` उसे तब तक चलाता है जब तक सेट खाली न हो जाए।

## हैशटेबल के साथ अच्छी जोड़ी बनती है

`HS{ }` इस सवाल के लिए कि "X देखा जा चुका है या नहीं?" और `H{ }` इस सवाल के लिए कि "X के पड़ोसी कौन-कौन हैं?", एक स्वाभाविक जोड़ी हैं। किताबी DFS बस इतना ही है:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

विज़िट सेट यह पक्का करता है कि एक ही काम दोबारा न हो। स्टैक फ्रंटियर नोड्स को एक-एक करके आगे बढ़ाता है (`push` और `pop` की मदद से LIFO क्रम में), और पड़ोसियों का मैप यानी हैशटेबल ग्राफ का डेटा देता है। किसी नोड तक पहुँच सकते हैं या नहीं, इस सवाल में नोड्स के देखे जाने का क्रम मायने नहीं रखता, इसीलिए स्टैक के तौर पर एक वेक्टर काफी है। उसी ढाँचे पर असली BFS में वेक्टर की जगह [`<dlist>`][dlist] होता है और एलिमेंट सामने से निकाले जाते हैं।
