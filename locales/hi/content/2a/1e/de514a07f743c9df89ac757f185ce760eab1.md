# परिचय

ओएस की स्थिति संभालने वाले रिसोर्स (फाइल हैंडल, सॉकेट, लॉक) को *गारंटी के साथ* साफ-सफाई की ज़रूरत होती है, तब भी जब कोई एक्सेप्शन स्टैक को खोलते हुए बाहर निकल रहा हो। Factor का [`destructors`][destructors] वोकैब इसके लिए एक छोटा फ्रेमवर्क देता है, और ज़्यादातर बिल्ट-इन रिसोर्स (`<file-reader>`, `<file-writer>`, सॉकेट, …) पहले से ही इससे जुड़े हुए हैं।

## क्लास और जेनेरिक

कोई क्लास इस फ्रेमवर्क में शामिल होने के लिए `disposable` का विस्तार करती है और `dispose*` लागू करती है:

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )` टपल को आवंटित करता है *और* उसे मौजूदा डिस्ट्रक्टर स्कोप के साथ रजिस्टर करता है, इसलिए आवंटन और अगले सुरक्षित बिंदु के बीच कोई एक्सेप्शन आ जाए, तो भी रिसोर्स लीक नहीं होता। फ्रेमवर्क यह गारंटी देता है कि `dispose*` हर ऑब्जेक्ट के लिए **अधिकतम एक बार** ही चलता है। बार-बार किए गए `dispose` कॉल कुछ नहीं करते।

## बाहरी कॉलर `dispose` का इस्तेमाल करते हैं

| शब्द              | असर                                        |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )` — रिसोर्स मुक्त कर देता है; दो बार कॉल करना सुरक्षित है |
| `with-disposal`   | `( disposable quot -- )` — एक रिसोर्स के लिए स्कोप बनाता है |
| `with-destructors`| `( quot -- )` — एक रजिस्ट्री स्कोप खोलता है |
| `&dispose`        | `( obj -- obj )` — सामान्य रूप से निकलने पर *या* फेल होकर निकलने पर मुक्त कर देता है |
| `|dispose`        | `( obj -- obj )` — सिर्फ तब मुक्त करता है जब स्कोप किसी एक्सेप्शन के कारण बंद हो रहा हो |

`with-disposal` एक ही रिसोर्स वाला रूप है। एक से अधिक रिसोर्स के लिए `with-destructors` स्कोप खोलिए और हर बार कोई रिसोर्स लेते समय उसे `&dispose` (आप उसे हमेशा छोड़ना चाहते हैं) या `|dispose` (सिर्फ फेल होने पर छोड़िए, सफल होने पर वह बना रहता है) के साथ रजिस्टर कीजिए।

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup` सबसे बुनियादी रूप है

एक बार वाले try/finally के लिए, जिसमें कोई रजिस्ट्री न हो, [`cleanup`][cleanup] (`continuations` वोकैब से) कम स्तर का शब्द है:

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` निश्चित रूप से ज़्यादा शक्तिशाली है (रजिस्ट्री रनटाइम पर बढ़ सकती है), लेकिन जब रिसोर्स लेने और छोड़ने की जोड़ी तय हो और उसी जगह सीमित हो, तब `cleanup` ही स्वाभाविक चुनाव है।
