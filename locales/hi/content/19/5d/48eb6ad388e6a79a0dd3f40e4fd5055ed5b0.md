# परिचय

## नल रेफरेंस

अगर आपने पहले कभी कोई दूसरी प्रोग्रामिंग भाषा (C/C++, Python, Java, Ruby, Lisp, वगैरह) इस्तेमाल की है, तो बहुत संभव है कि आपका सामना पहले भी `null` या `nil` से हुआ हो।
ये भाषाएँ `null` या `nil` का इस्तेमाल करके बताती हैं कि किसी खास वेरिएबल में कोई वैल्यू नहीं है।
लेकिन इसकी वजह से गलती से किसी `null` वेरिएबल का इस्तेमाल कर देना बहुत आसान और आम गलती बन जाती है।
जैसा कि आप सोच सकते हैं, ऐसे फंक्शन को कॉल करने की कोशिश करना जो मौजूद ही नहीं है, या ऐसी वैल्यू तक पहुँचने की कोशिश करना जो है ही नहीं, कई तरह के बग और क्रैश पैदा कर सकती है।
`null` बनाने वाले ने तो इसे अपनी ['अरबों डॉलर की गलती'][billion-dollar-mistake] तक कह दिया।

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## `Option` टाइप

इन समस्याओं से बचने के लिए Cairo के वेरिएबलो `Option` इनम का इस्तेमाल कर सकते हैं, जो वैल्यू न होने की स्थिति को सुरक्षित तरीके से दर्शाता है।
इस इनम के दो वेरिएंट होते हैं: `None`, जो Cairo में `null` जैसा ही है; और `Some(T)`, जहाँ `T` किसी भी टाइप की एक वैल्यू हो सकती है।

यह कुछ ऐसा दिखता है:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

`Option` को आप अपने और उन समस्याओं के बीच सुरक्षा की एक परत की तरह सोच सकते हैं जो नल रेफरेंस पैदा कर सकते हैं, और फिर भी उनकी उपयोगिता बनी रहती है।

## `Option` का इस्तेमाल

किसी वेरिएबल को `None` पर सेट करना काफी आसान है:

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

लेकिन अगर आप चाहते हैं कि `Option` टाइप कोई वैल्यू अपने अंदर रखे, तो आप उस वैल्यू को सीधे असाइन नहीं कर सकते।
एक `Option` टाइप का वेरिएबल और, मान लीजिए, एक `i32` टाइप का वेरिएबल एक जैसे नहीं होते।
आपको `Some` का इस्तेमाल करना होगा:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

इसी वजह से यह भी काम नहीं करेगा:

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

`Some` के अंदर रखी वैल्यू पाने के लिए पहले यह जाँचना ज़रूरी है कि वह मौजूद है:

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

`Option` के अंदर रखी वैल्यू को जाँचने और उस तक पहुँचने के लिए Cairo में `match` के अलावा दूसरे टूल भी हैं, लेकिन `match` तो अब आपके लिए परिचित होना चाहिए।

इसे इस बात का उदाहरण मानिए कि Cairo नल रेफरेंस की जगह `Option` क्यों इस्तेमाल करता है।
बात यह है कि **आपको _हर हाल में_ जाँचना ही होगा** कि `Option` वेरिएबल `Some` है या नहीं (ऐसी स्थिति में आप आगे बढ़कर उसके अंदर रखी वैल्यू निकालकर इस्तेमाल कर सकते हैं), या `None`।
वरना आपका प्रोग्राम कंपाइल नहीं होगा; कंपाइलर आपको `null` से बचाए रखता है।
