# निर्देश परिशिष्ट

## Odin के लिए खास निर्देश

Odin डिफॉल्ट आर्गुमेंट का समर्थन करता है। डिफॉल्ट आर्गुमेंट एक बहुत काम का फीचर है। इससे एक ही प्रोसीजर को अलग-अलग पैरामीटर के सेट के साथ कॉल किया जा सकता है, ऐसी जगहों पर जहाँ आपको आपस में जुड़े, पर अलग-अलग API चाहिए हों।

डिफॉल्ट आर्गुमेंट के बिना आपको अपने API के लिए ढेरों अलग-अलग प्रोसीजर बनाने पड़ सकते हैं। जिन भाषाओं में डिफॉल्ट आर्गुमेंट नहीं होते, जैसे Java, वे यही नतीजा पाने के लिए मेथड ओवरलोडिंग का सहारा लेती हैं (और कोड भी ज़्यादा लिखना पड़ता है)। या फिर उन्हें ऐसे प्रोसीजर बनाने पड़ते हैं जो बहुत सारे आर्गुमेंट ले सकें।

चलिए `greeting` प्रोसीजर का उदाहरण लेते हैं। इसमें हम चाहते हैं कि भाषा बताई जा सके, यह भी पता चले कि नाम बड़े अक्षरों में है या नहीं, और यह भी तय हो कि ग्रीटिंग के अंत में विस्मयादिबोधक चिह्न लगाना है या नहीं। थोड़ी जाँच के बाद हमने पाया कि सबसे बड़ा वर्ग अंग्रेज़ी को भाषा के रूप में चुनता है, नाम को बड़े अक्षरों में नहीं बदलता, और अंत में विस्मयादिबोधक चिह्न नहीं चाहता। दूसरे सबसे बड़े वर्ग को ग्रीटिंग के अंत में विस्मयादिबोधक चिह्न चाहिए।

हम सारे आर्गुमेंट लेने वाला एक ही प्रोसीजर बना सकते हैं:

```odin
greeting :: proc(name: string, language: Language, do_uppercase: bool, add_exclamation: bool) {
	...
}
```

तब हर यूज़र को हर आर्गुमेंट का डॉक्युमेंटेशन पढ़ना पड़ेगा और हर बार उसे भरना भी पड़ेगा।

डिफॉल्ट आर्गुमेंट के बिना हम अलग-अलग पैरामीटर लेने वाले कई प्रोसीजर भी बना सकते हैं:

```odin
greeting_common :: proc(name: string) {...}

greeting_with_exclamation :: proc(name: string) {...}

greeting_general :: proc(name: string, language: Language, do_uppercase: bool, add_exclamation: bool) {...}

// Odin supports overloading but it has to be explicitly defined
greeting :: proc {
	greeting_common,
	greeting_with_exclamation,
	greeting_general,
}
```

अगर आपकी भाषा डिफॉल्ट आर्गुमेंट का समर्थन करती है, जैसे Odin करता है, तो आप सबसे कम इस्तेमाल होने वाले आर्गुमेंट को उपयुक्त डिफॉल्ट वैल्यू दे सकते हैं। कॉल करने वाले इन डिफॉल्ट आर्गुमेंट को छोड़ सकते हैं, और तब प्रोसीजर दी गई डिफॉल्ट वैल्यू ही इस्तेमाल करता है। चाहें तो वे उनकी जगह अपनी वैल्यू दे सकते हैं।

```odin
greeting :: proc(name: string, language: Language = Language.English, do_uppercase : bool = false, add_exclamation: bool = false) {...}

// Note: because Odin supports type inference, we can simplify the interface.
greeting :: proc(name: string, language:= Language.English, do_uppercase := false, add_exclamation:= false) {...}
```

प्रोसीजर को सारे डिफॉल्ट आर्गुमेंट के साथ भी कॉल किया जा सकता है:

```odin
greeting("John Doe")
```

कॉल करने वाले के लिए ज़रूरी आर्गुमेंट की जगह नई वैल्यू दी जा सकती है:

```odin
greeting("John Doe", Language.Spanish)
```

अगर आपको ज़रूरी आर्गुमेंट ऊपर के उदाहरण की तरह क्रम से मिल रहे हैं, तो उनके नाम लिखने की ज़रूरत नहीं है। लेकिन अगर बीच के कुछ आर्गुमेंट छोड़ने हैं, तो छोड़े गए पहले आर्गुमेंट के बाद वाले हर आर्गुमेंट का नाम लिखना पड़ेगा।

```odin
greeting("John Doe", add_exclamation=true)
```

## मेमोरी प्रबंधन

इस अभ्यास में आपको एक ऐसा प्रोसीजर लिखना है जो स्ट्रिंग लौटाता है और उसके लिए ज़रूरी मेमोरी खुद आवंटित करता है। उस स्ट्रिंग की मेमोरी मुक्त करना प्रोसीजर को कॉल करने वाले का काम है।

```odin
// The procedure will be called like that:
str := two_fer("Alice")
// ...
// and eventually the caller will delete the string
delete(str)
```
