# परिचय

[रिकॉर्ड][records] ऐसी डेटा संरचनाएँ हैं जो आपस में जुड़ी जानकारी को लेबल के साथ एक साथ रखती हैं। ये JavaScript या Java के ऑब्जेक्ट, या C या Rust के स्ट्रक्ट जैसे होते हैं, लेकिन इनमें कुछ अहम अंतर होते हैं।

## रिकॉर्ड बनाना

रिकॉर्ड घुंघराले ब्रैकेट से [बनाए जाते हैं][create] और उनके एलिमेंट कोमा से अलग किए जाते हैं।

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

रिकॉर्ड का टाइप भी इसी तरह के सिंटैक्स से परिभाषित किया जाता है, बस बराबर के चिह्न `=` की जगह कोलन चिह्न `:` लगते हैं।

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

इन टाइप परिभाषाओं को बार-बार लिखना झंझट भरा होता है, इसलिए परिभाषा साझा करने के लिए [टाइप एलियास][record-types] इस्तेमाल करना एक आम तरीका है।

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

टाइप एलियास रिकॉर्ड के लिए अपने आप एक कंस्ट्रक्टर फंक्शन भी दे देता है। यह कभी-कभी चौंकाने वाला लगता है, क्योंकि Elm में फंक्शन का नाम छोटे अक्षर से शुरू होना चाहिए, लेकिन टाइप कंस्ट्रक्टर इसका एक अपवाद हैं।

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

## रिकॉर्ड के फील्ड पढ़ना

किसी रिकॉर्ड इंस्टेंस के फील्ड की वैल्यू [पढ़ने][access] का मुख्य तरीका डॉट-नोटेशन इस्तेमाल करना है, जैसे `firefly.creator`. Elm का कंपाइलर ऐसे खास एक्सेसर फंक्शन भी देता है जो डॉट `.` से शुरू होते हैं, जैसे `.creator`, और ऐसे किसी भी रिकॉर्ड पर काम करते हैं जिसमें उस नाम का फील्ड हो। यह उस नियम का दूसरा अपवाद है कि फंक्शन का नाम छोटे अक्षर से शुरू होना चाहिए। दरअसल उपयोगकर्ता द्वारा बनाए गए फंक्शन का नाम छोटे अक्षर से ही शुरू होना चाहिए, लेकिन हमने अभी जो दो उदाहरण देखे, वे कंपाइलर बनाता है, प्रोग्रामर नहीं।

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

रिकॉर्ड को बाइंडिंग में [रिकॉर्ड पैटर्न मैचिंग][pattern-matching] की मदद से _डीस्ट्रक्चर_ भी किया जा सकता है। डीस्ट्रक्चरिंग ऐसे हर रिकॉर्ड के साथ काम करती है जिसमें उन नामों के फील्ड हों।

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

## रिकॉर्ड अपडेट करना

Elm की हर चीज़ की तरह रिकॉर्ड भी अपरिवर्तनीय होते हैं, इसलिए एक बार रिकॉर्ड बन जाने के बाद उसके फील्ड की वैल्यू कभी नहीं बदल सकती। मौजूदा रिकॉर्ड की कॉपी बनाने, पर उसमें एक या अधिक फील्ड बदलने का [एक खास सिंटैक्स][update] होता है। यह सिंटैक्स पाइप चिह्न `|` से मूल रिकॉर्ड और उन फील्ड को अलग करता है जो बदलेंगे, जैसे `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

## रिकॉर्ड की तुलना करना

Elm [स्ट्रक्चरल इक्वालिटी][equality] इस्तेमाल करता है, यानी एक ही रिकॉर्ड के दो इंस्टेंस जिनकी वैल्यू समान हों, बराबर माने जाते हैं।

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

## एक्सटेंसिबल रिकॉर्ड

Elm [स्ट्रक्चरल टाइपिंग][structural-typing] का भी समर्थन करता है, यानी अगर किसी फंक्शन को x और y फील्ड वाला रिकॉर्ड चाहिए, तो वह ऐसे किसी भी रिकॉर्ड के साथ काम करेगा जिसमें ये फील्ड हों, जैसे 2D बिंदु, 3D बिंदु, अंतरिक्ष यान आदि। ऐसे रिकॉर्ड टाइप की परिभाषा में पाइप `|` होता है, जैसे `{ a | x : Float, y : Float }`, और Elm की शब्दावली में इन्हें "एक्सटेंसिबल रिकॉर्ड" कहा जाता है। ध्यान रखिए कि टाइप परिभाषा में लगने वाले पाइप `|` (जो एक्सटेंसिबल रिकॉर्ड की परिभाषा है, जैसे `{ a | x : Int }`) और किसी असली रिकॉर्ड इंस्टेंस में लगने वाले पाइप `|` में फर्क है। दूसरे का मतलब है कि हम उस रिकॉर्ड के कुछ फील्ड बदल रहे हैं।

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
