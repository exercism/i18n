# परिचय

पिछले कॉन्सेप्ट में हमने देखा था कि Julia में टाइप एक पदानुक्रम बनाते हैं, जिसके सबसे ऊपर `Any` होता है।

`Number` जैसे एब्स्ट्रैक्ट टाइप के सबटाइप होते हैं, लेकिन इन्हें खुद इंस्टैंशिएट नहीं किया जा सकता।
जब आप किसी वेरिएबल का टाइप कोई एब्स्ट्रैक्ट टाइप रखते हैं, तो वेरिएबल की वैल्यू उस एब्स्ट्रैक्ट टाइप के किसी भी सबटाइप तक _सीमित_ हो जाती है।
उदाहरण के लिए:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

इससे हमें यह तय करने में एक तरह का लचीलापन मिलता है कि कौन से इनपुट मान्य होंगे।

लेकिन मान लीजिए, हम चाहते हैं कि कोई वेरिएबल पूर्णांक और स्ट्रिंग, दोनों तरह की वैल्यू ले सके?
ये दोनों टाइप पदानुक्रम की एक ही शाखा में नहीं हैं।

हम टाइप को [`Any`][any] पर सेट कर सकते हैं, या उसे डिफॉल्ट रूप से वही रहने दे सकते हैं, लेकिन तब हमें अनुमत टाइपों पर से पूरा नियंत्रण खो जाता है।

बेहतर तरीका यह है कि हम [`Union{ }`][union] सिंटैक्स इस्तेमाल करें, जिसमें ब्रैकेट के अंदर दो या ज़्यादा टाइप लिखे जाते हैं।

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

एक और उदाहरण में वही टाइप यूनियन किसी फंक्शन के सिग्नेचर में इस्तेमाल हुआ है:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

यहाँ हमने टाइप को एक नाम दिया है, जो काम को आसान बनाता है, लेकिन यह करना ज़रूरी नहीं है।
फंक्शन `g(z::Union{Integer, String}) = z^3` भी बिल्कुल इसी तरह काम करता है।

फंक्शन सिग्नेचर के बारे में बहुत कुछ कहने को है, जो हम मल्टीपल डिस्पैच कॉन्सेप्ट में करेंगे।

## `nothing` वाली यूनियन

कई और भाषाओं में ऐसे टाइप होते हैं जिनमें वैल्यू हो भी सकती है और नहीं भी, जैसे `Option`, `Nullable` या `Maybe`।

Julia में इसके लिए कोई खास सिंटैक्स नहीं है, लेकिन टाइप यूनियन इसी विचार का एक व्यापक रूप हैं।

[`Nothingness`][nothingness] कॉन्सेप्ट में हमने देखा था कि Julia में ऐसी चीज़ों को दर्शाने के कई तरीके हैं जिनकी कोई वैल्यू नहीं होती, जिनमें [`nothing`][nothing] और [`missing`][missing] भी शामिल हैं।
इनमें से कोई भी टाइप यूनियन में शामिल किया जा सकता है।

उदाहरण के लिए, किसी [लिंक्ड लिस्ट][linked] को बनाते समय हमें लिस्ट को खत्म करने का एक तरीका चाहिए, जब आगे कोई नोड न हो।
`Nothing` वह टाइप है जिसकी एकमात्र वैल्यू `nothing` है, और Node की यह परिभाषा चेन के अंत का संकेत देना संभव बनाती है:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

इसी तरह, `missing` को अनुपस्थित वैल्यू के लिए प्लेसहोल्डर की तरह इस्तेमाल किया जा सकता है, खास तौर पर वेक्टर जैसे कलेक्शन में।
नीचे दिया गया उदाहरण बहुत बनावटी है, लेकिन वास्तविक दुनिया के डेटा सेट में missing वैल्यू आम होती हैं।

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
