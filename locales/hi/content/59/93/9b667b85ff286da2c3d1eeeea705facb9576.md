# परिचय

[रिकॉर्ड][records] डेटा स्ट्रक्चर हैं जो आपस में जुड़ी जानकारी को लेबल के साथ एक साथ रखते हैं।
ये JavaScript या Java के ऑब्जेक्ट, या C या Rust के स्ट्रक्ट जैसे होते हैं, लेकिन इनमें कुछ खास अंतर होते हैं।

## रिकॉर्ड बनाना

रिकॉर्ड कर्ली ब्रैकेट से [बनाए जाते हैं][create] और उनके एलिमेंट कोमा से अलग किए जाते हैं।

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

रिकॉर्ड का टाइप भी लगभग इसी तरह की सिंटैक्स से परिभाषित किया जाता है, बस बराबर के चिह्न `=` की जगह कोलन के चिह्न `:` लगा दिए जाते हैं।

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

इन टाइप परिभाषाओं को बार-बार लिखना झंझटपूर्ण होता है, इसलिए परिभाषा को साझा करने के लिए [टाइप एलियस][record-types] का उपयोग करना एक आम तरीका है।

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

टाइप एलियस रिकॉर्ड के लिए अपने आप एक कंस्ट्रक्टर फंक्शन भी देता है।
यह कभी-कभी चौंकाने वाला लगता है, क्योंकि Elm में फंक्शन का नाम छोटे अक्षर से शुरू होना चाहिए, लेकिन टाइप कंस्ट्रक्टर इसका एक अपवाद होते हैं।

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

## रिकॉर्ड के फील्ड तक पहुँचना

किसी रिकॉर्ड इंस्टेंस के किसी फील्ड की वैल्यू [एक्सेस करने][access] का मुख्य तरीका डॉट-नोटेशन का उपयोग करना है, जैसे `firefly.creator`.
Elm कंपाइलर ऐसे विशेष एक्सेसर फंक्शन भी सपोर्ट करता है जो डॉट `.` से शुरू होते हैं, जैसे `.creator`, और ऐसे किसी भी रिकॉर्ड पर काम करते हैं जिसमें उस नाम का फील्ड हो।
यह उस नियम का दूसरा अपवाद है कि फंक्शन का नाम छोटे अक्षर से ही शुरू होना चाहिए।
वास्तव में, उपयोगकर्ता द्वारा बनाए गए फंक्शन का नाम छोटे अक्षर से ही शुरू होना चाहिए, लेकिन हमने अभी जो दो उदाहरण देखे, उन्हें कंपाइलर बनाता है, प्रोग्रामर नहीं।

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

रिकॉर्ड को बाइंडिंग में [रिकॉर्ड पैटर्न मैचिंग][pattern-matching] की मदद से _डीस्ट्रक्चर_ भी किया जा सकता है।
डीस्ट्रक्चरिंग ऐसे किसी भी रिकॉर्ड के साथ काम करती है जिसमें उन्हीं नामों के फील्ड हों।

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

## रिकॉर्ड अपडेट करना

Elm में सब कुछ की तरह रिकॉर्ड भी अपरिवर्तनीय होते हैं, इसलिए एक बार रिकॉर्ड परिभाषित हो जाने पर उसके फील्ड की वैल्यू कभी नहीं बदल सकतीं।
मौजूदा रिकॉर्ड की कॉपी बनाने, लेकिन उसके एक या अधिक फील्ड बदलने के लिए एक [विशेष सिंटैक्स है][update]।
यह सिंटैक्स मूल रिकॉर्ड और उन फील्ड को अलग करने के लिए पाइप चिह्न `|` का उपयोग करता है जो बदलेंगे, जैसे `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

## रिकॉर्ड की तुलना

Elm [स्ट्रक्चरल इक्वालिटी][equality] का उपयोग करता है, यानी एक ही रिकॉर्ड के दो इंस्टेंस जिनकी वैल्यू बिल्कुल समान हों, बराबर माने जाते हैं।

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

## एक्सटेंसिबल रिकॉर्ड

Elm [स्ट्रक्चरल टाइपिंग][structural-typing] को भी सपोर्ट करता है, यानी अगर किसी फंक्शन को x और y फील्ड वाला रिकॉर्ड चाहिए, तो वह ऐसे किसी भी रिकॉर्ड के साथ काम करेगा जिसमें वे फील्ड हों, जैसे 2D बिंदु, 3D बिंदु, अंतरिक्ष यान, वगैरह।
उन रिकॉर्ड टाइप की परिभाषा में पाइप `|` होता है, जैसे `{ a | x : Float, y : Float }`, और Elm की शब्दावली में इन्हें "एक्सटेंसिबल रिकॉर्ड" कहा जाता है।
ध्यान रखिए कि टाइप परिभाषा में लगे पाइप `|`, जो एक्सटेंसिबल रिकॉर्ड की परिभाषा है (`{ a | x : Int }`), और किसी असली रिकॉर्ड इंस्टेंस में लगे पाइप `|`, जिसका मतलब है कि हम उस रिकॉर्ड के कुछ फील्ड अपडेट कर रहे हैं, इन दोनों में फर्क होता है।

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
