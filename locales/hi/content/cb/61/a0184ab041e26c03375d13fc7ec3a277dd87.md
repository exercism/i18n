# परिचय

Python एक [डायनामिक और स्ट्रॉन्गली टाइप्ड][dynamic typing in python] प्रोग्रामिंग भाषा है।
यह [टाइप हिंट्स][type hints] के ज़रिए [डक टाइपिंग][duck typing] और [ग्रेजुअल टाइपिंग][gradual typing] दोनों का इस्तेमाल करती है।
Python कोड की पठनीयता पर बहुत ज़ोर देती है और (_Haskell की तरह_) फंक्शन, मेथड और क्लास की परिभाषाएँ दर्शाने के लिए [सिग्निफिकेंट इंडेंटेशन][significant indentation] का इस्तेमाल करती है।

Guido van Rossum ने Python बनाया और यह पहली बार 1991 में जारी हुई।

इंपरेटिव, डिक्लेरेटिव (जैसे फंक्शनल) और ऑब्जेक्ट-ओरिएंटेड, प्रोग्रामिंग की ये _शैलियाँ_ सभी काम करती हैं, लेकिन भीतर से **[Python में हर चीज़ एक ऑब्जेक्ट है][everythings an object]**।

जैसे-जैसे हम Python ट्रैक के कॉन्सेप्ट आगे बढ़ेंगे, हम इन सबका मतलब और गहराई से समझेंगे।

यह पहला कॉन्सेप्ट (`basics`) Python भाषा की 4 मुख्य विशेषताओं से परिचित कराता है:
1.  नाम असाइन करना (_वेरिएबल और कॉन्स्टेंट_),
2.  फंक्शन (_`def` कीवर्ड और `return` कीवर्ड_),
3.  कमेंट, और
4.  डॉकस्ट्रिंग।

<br>

## नाम असाइन करना (वेरिएबल और कॉन्स्टेंट)

प्रोग्रामर असाइनमेंट `=` ऑपरेटर का इस्तेमाल करके किसी भी टाइप के ऑब्जेक्ट से [_नाम_][facts-and-myths-about-python-names] (जिन्हें _वेरिएबल_ भी कहते हैं) बाँध सकते हैं: `<name> = <value>`।
एक नाम को उसके जीवनकाल में बार-बार अलग-अलग वैल्यू (यानी अलग-अलग ऑब्जेक्ट टाइप) असाइन या दोबारा बाँधा जा सकता है:


```python
>>> my_first_variable = 1  # <--my_first_variable bound to an integer object of value one.
>>> my_first_variable = 2  # <--my_first_variable re-assigned to integer value 2.

>>> print(type(my_first_variable))
<class 'int'>

>>> print(my_first_variable)
2

>>> my_first_variable = "Now, I'm a string." # <--You may re-bind a name to a different object type and value.
>>> print(type(my_first_variable))
<class 'str'>

>>> my_first_variable = 'You can call me "str".' # <--Strings can be declared using single or double quote marks.
>>> print(my_first_variable)
You can call me "str".
```


### कॉन्स्टेंट

कॉन्स्टेंट ऐसे नाम होते हैं जिन्हें किसी प्रोग्राम में सिर्फ एक बार असाइन करना होता है, हालाँकि Python दोबारा असाइन करने से रोकती नहीं है।
`SCREAMING_SNAKE_CASE` इस्तेमाल करने से कोड पढ़ने वाले हर व्यक्ति को यह संकेत मिलता है कि इस नाम को दोबारा असाइन **नहीं** करना चाहिए और इसकी वैल्यू नहीं बदलनी चाहिए।
कॉन्स्टेंट को [मॉड्यूल][module] (फाइल) के लेवल पर परिभाषित करना चाहिए, और ये आम तौर पर प्रोग्राम के सभी फंक्शन और क्लास को दिखाई देते हैं।



## फंक्शन

`def` कीवर्ड एक [फंक्शन की परिभाषा][function definition] शुरू करता है।
हर फंक्शन में `()` ब्रैकेट के अंदर शून्य या उससे अधिक औपचारिक [पैरामीटर][parameters] हो सकते हैं, जिनके बाद एक `:` कोलन आता है।
फंक्शन के _अंदर के कोड_ के स्टेटमेंट `def` के बाद वाली लाइन से शुरू होते हैं और उन्हें _एक ब्लॉक में इंडेंट_ करना ज़रूरी है।


```python
# The body of this function is indented by 2 spaces & prints the sum of the numbers.
def add_two_numbers(number_one, number_two):
  total = number_one + number_two
  print(total)  

>>> add_two_numbers(3, 4)
7


# Inconsistent indentation in your code blocks will raise an error.
>>> def add_three_numbers_misformatted(number_one, number_two, number_three):
...     result = number_one + number_two + number_three   # This was indented by 4 spaces.
...    print(result)     # <--This was only indented by 3 spaces.
...
...
  File "<stdin>", line 3
    print(result)
    ^
IndentationError: unindent does not match any outer indentation level
```


फंक्शन [`return`][return] कीवर्ड के ज़रिए _स्पष्ट रूप से_ कोई वैल्यू या ऑब्जेक्ट लौटाते हैं:


```python
# Function definition on first line, explicit return used on final line.
def add_two_numbers(number_one, number_two):
  return number_one + number_two   


# Calling the function in the Python shell returns the sum of the numbers.
>>> add_two_numbers(3, 4)
7

# Assigning the function call to a variable and printing 
# the variable will also return the value.
>>> sum_with_return = add_two_numbers(5, 6)
>>> print(sum_with_return)
11
```


जो फंक्शन `return` के बाद कोई _स्पष्ट_ एक्सप्रेशन नहीं लिखते, वे _अपने आप_ [`None`][none] ऑब्जेक्ट लौटाते हैं।
`None` के बारे में विस्तार से आगे आने वाले किसी कॉन्सेप्ट में बताया जाएगा।
इस अभ्यास और इस समझ के संदर्भ में, `None` एक ऐसा प्लेसहोल्डर है जो कुछ नहीं, यानी null को दर्शाता है:


```python
# This function will return `None`
def square_a_number(number):
    square = number * number
    return # <-- note that this return is not followed by an expression

# Calling the function in the Python shell appears 
# to not return anything at all.
>>> square_a_number(2)
>>>


# Using print() with the function call shows that 
# the function is actually returning the **None** object.
>>> print(square_a_number(2))
None
```

जो फंक्शन `return` नहीं लिखते, वे भी _अपने आप_ [`None`][none] ऑब्जेक्ट लौटाते हैं।
इसका मतलब है कि अगर आप किसी फंक्शन में `return` का इस्तेमाल नहीं करते, तो Python आपके लिए `None` ऑब्जेक्ट लौटाती है।

```python
# This function omits a return keyword altogether.
def add_two_numbers(number_one, number_two):
  result = number_one + number_two

>>> add_two_numbers(5, 7)
>>> print(add_two_numbers(5, 7))
None

# Assigning the function call to a variable and printing 
# the variable will also show None.
>>> sum_without_return = add_two_numbers(5, 6)
>>> print(sum_without_return)
None
```


## कमेंट

Python में [कमेंट][comments] ऐसे `#` से शुरू होते हैं जो किसी स्ट्रिंग का हिस्सा नहीं होता, और लाइन के अंत तक चलते हैं।
बाकी कई प्रोग्रामिंग भाषाओं के उलट, Python मल्टी-लाइन कमेंट के निशान का **समर्थन नहीं करती**।
कमेंट ब्लॉक की हर लाइन `#` अक्षर से शुरू होनी चाहिए।


## डॉकस्ट्रिंग

फंक्शन के अंदर का पहला स्टेटमेंट चाहें तो एक [_डॉकस्ट्रिंग_][docstring] हो सकता है, जो फंक्शन या ऑब्जेक्ट के उद्देश्य को संक्षेप में बताती है।
डॉकस्ट्रिंग को [Sphinx][sphinx] जैसे ऑटोमेटेड डॉक्युमेंटेशन टूल पढ़ते हैं, और फंक्शन, मेथड या क्लास के नाम पर खास एट्रिब्यूट `.__doc__` कॉल करने पर यही डॉकस्ट्रिंग मिलती है।
डॉकस्ट्रिंग से जुड़े सामान्य नियम [PEP257][pep257] में दिए गए हैं, लेकिन सही फॉर्मैट प्रोजेक्ट और टीम के हिसाब से बदलते रहते हैं।
डॉकस्ट्रिंग तीन डबल कोट्स (""") के साथ घोषित की जाती हैं और कोड ब्लॉक के समान लेवल पर इंडेंट की जाती हैं:
