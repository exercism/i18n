# अनुबंध

किसी रूटीन के आर्गुमेंट और रिटर्न टाइप यह बताते हैं कि उसमें किस *तरह* की चीज़ जाती है और बाहर क्या आता है। वे यह नहीं बता सकते कि किसी वज़न का धनात्मक होना ज़रूरी है, या यह कि कोई हार्नेस कभी अपनी असली क्षमता से ज़्यादा बची हुई क्षमता नहीं बताता।

इन बातों को **अनुबंध** रूटीन के ही हेडर में बताता है, जहाँ उसे पढ़ने वाला हर कोई उन्हें देख सकता है।

## pre

`pre` यह बताता है कि रूटीन को कॉल करते समय क्या सही होना चाहिए। यह रिटर्न टाइप और `is` के बीच लिखा जाता है।

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

यह **कॉलर** पर एक माँग है: इस रूटीन को ऋणात्मक load के साथ कॉल न कीजिए।

## post

`post` यह बताता है कि रूटीन के जवाब देने पर क्या सही होगा। इसके अंदर `result` वह वैल्यू है जो लौटाई जा रही है।

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

यह कॉलर से किया गया एक वादा है। जिस रूटीन में दोनों हों, वह एक सौदा है: मुझे यह दीजिए, और मैं आपको वह दूँगा।

कई शर्तें `and` से जुड़ती हैं, जैसे बूलियन जुड़ते हैं:

```sather
      pre load >= 0 and load <= limit
```

## अनुबंध एक्सेप्शन नहीं हैं

जो एक्सेप्शन उठाया जाता है, वह उस चीज़ के लिए होता है जो हो सकती है। टूटा हुआ अनुबंध **बग** का मतलब है। यानी किसी ने रूटीन को गलत तरीके से कॉल किया, या रूटीन ने वह नहीं किया जो उसने कहा था।

तो टूटा हुआ अनुबंध कोई ऐसी चीज़ नहीं उठाता जिसे पकड़ा जा सके। जब अनुबंध की जाँच चालू होती है, तो प्रोग्राम रुक जाता है और दिखाता है कि कौन-सा रूटीन और कौन-सी शर्त। जब वह बंद होती है, तो उस शर्त की जाँच भी नहीं होती, और प्रोग्राम आगे चलता रहता है, चाहे उसके बाद जो भी बेतुकी चीज़ें हों।

इसीलिए अनुबंध सही होने के बारे में एक दावा है, बुरे इनपुट को संभालने का तरीका नहीं। अगर बुरा इनपुट आने की उम्मीद है, तो उसे जाँचिए और `raise` कीजिए। अगर बुरा इनपुट यह बताता है कि कॉलर में ही गड़बड़ी है, तो `pre` से यह बात बताइए।

## जाँच चालू करना

यह Sather अनुबंधों की जाँच तब करता है जब कंपाइलर को `-chk` दिया जाता है:

```
sacomp -chk mine.sa -main MAIN -o mine
```

इसके बिना `pre` और `post` ऐसा डॉक्युमेंटेशन हैं जिसे कंपाइलर ने पढ़ लिया और मान लिया कि यह सही बना हुआ है, और उससे ज़्यादा कुछ नहीं। इस अभ्यास के टेस्ट `-chk` के बिना बनाए गए हैं, इसलिए वे आपके लिए टूटा हुआ अनुबंध पकड़ नहीं सकते। वे यह जाँचते हैं कि सही तरीके से इस्तेमाल करने पर रूटीन ठीक काम करते हैं।
