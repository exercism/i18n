# बारे में

## परिचय

ऑपेक टाइप Elm में एनकैप्सुलेशन की एक तकनीक है।
कुछ लोग इसे जानकारी छिपाना या कार्यान्वयन का विवरण छिपाना भी कहते हैं।
इनका इस्तेमाल आम तौर पर वैलिडेशन लागू करने के लिए भी होता है, और उसमें [पार्स कीजिए, वैलिडेट मत कीजिए][parse-dont-validate] पैटर्न अपनाया जाता है।
उदाहरण के लिए, आपके पास एक `EmailAddress` ऑपेक टाइप हो सकता है, जिसमें सिर्फ वैध ईमेल पते ही रह सकते हैं (`String` के उलट, जिसमें कुछ भी रह सकता है)।

## ऑपेक टाइप बनाना

[कस्टम टाइप][custom-types] में एक या अधिक *वेरिएंट* होते हैं, और कंपाइलर हर *वेरिएंट* को बनाने के लिए उसी *वेरिएंट* के नाम से एक फंक्शन अपने आप बना देता है।
यही वे फंक्शन हैं जिनसे कस्टम टाइप बनाए जा सकते हैं।
कंपाइलर इन वेरिएंट के लिए डीस्ट्रक्चरिंग की भी अनुमति देता है।

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

डिफ़ॉल्ट रूप से यह सब फाइल या मॉड्यूल के अंदर ही रहता है, और क्या एक्सपोर्ट करना है यह चुनने के लिए हम `exposing` कीवर्ड इस्तेमाल करते हैं।
ऑपेक टाइप बनाने के लिए आप बस यह तय कीजिए कि *वेरिएंट* एक्सपोर्ट नहीं करने हैं।

ऐसा करने पर लगभग हमेशा आपको *वेरिएंट* बनाने और निकालने का कोई दूसरा तरीका देना पड़ता है, यानी कस्टम फंक्शन एक्सपोर्ट करना।
इन कस्टम फंक्शन की मदद से आप *वेरिएंट* बनाते और निकालते समय कुछ तर्क लगा सकते हैं।
इससे मॉड्यूल के अंदर कार्यान्वयन का विवरण छिप जाता है, और जब तक एक्सपोर्ट किए गए फंक्शन वैसे ही रहें, आप कार्यान्वयन जितना चाहें बदल सकते हैं।

## पार्स कीजिए, वैलिडेट मत कीजिए

ऑपेक टाइप का सबसे आम इस्तेमाल वैलिडेशन लागू करना है, और उसके लिए [पार्स कीजिए, वैलिडेट मत कीजिए][parse-dont-validate] पैटर्न अपनाया जाता है।
इस पैटर्न में आप एक ऐसा फंक्शन एक्सपोर्ट करते हैं जो इनपुट के तौर पर आप जितनी संरचना या टाइप सुरक्षा चाहते हैं उससे कम वाली कोई चीज़ लेता है, जैसे `String`, और फिर उसे पार्स करके उससे ज़्यादा संरचना वाले टाइप में बदल देता है, जैसे `EmailAddress`।
यह फंक्शन या तो वह टाइप लौटाता है, या एक एरर लौटाता है (आम तौर पर `Maybe` या `Result`)।

उदाहरण के लिए, नीचे दिए गए कोड में बाहरी मॉड्यूल `EmailAddress` टाइप सिर्फ `parseEmailAddress` फंक्शन से ही बना सकते हैं।
इसलिए जब आप `EmailAddress` टाइप के साथ काम करते हैं, तो आप निश्चित हो सकते हैं कि वह पता वैध है।

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
