# परिचय

## एन्यूमरेशन

अब तक हमने ज़्यादातर संख्याओं और स्ट्रिंग के साथ काम किया है।
वास्तविक दुनिया की चीज़ों को दर्शाने के लिए हमें कभी-कभी ऐसी वैल्यू चाहिए होती हैं जो गिनी-चुनी हों और जिन्हें कोई वेरिएबल अपने अंदर ले सके।
आपको एक अलग टाइप चाहिए हो सकता है, जिसकी कुछ गिनी-चुनी वैल्यू हों और हर वैल्यू का अपना अलग नाम हो।
मान लीजिए, किसी स्केटबोर्ड फैक्ट्री में डेक की सामग्री के लिए सिर्फ maple, bamboo या plastic में से चुनाव करना हो।

इन वैल्यू को पूर्णांकों में एनकोड किया जा सकता है, लेकिन तब आपको अतिरिक्त कोड लिखना पड़ेगा, जो यह जाँचे कि सामग्री के लिए सिस्टम से कोई अमान्य वैल्यू तो नहीं आ रही।
ऐसी [_जादुई संख्याएँ_][magic numbers] का अर्थ पूरे सोर्स कोड में ढूँढ़ना मुश्किल होता है, और इनमें गड़बड़ी होने का खतरा भी बना रहता है।
`enumerations` की मदद से ऐसा कोड लिखा जा सकता है जो अपना मतलब साफ़ बताए, और अनजाने में होने वाली तुलना की गलतियों को रोका जा सकता है।

## उदाहरण

इस तरह के एन्यूमरेशन का खास नाम `scoped enumeration` है।
नीचे दिया गया कोड दिखाता है कि `DeckMaterial` नाम का `enumeration` कैसे लिखा जाता है।
यहाँ `enum class` कीवर्ड और परिभाषा के अंत में लगा `;` ध्यान से देखिए:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
अब स्केट की दुकान के कीमत तय करने वाले फंक्शन को देखिए, और गौर कीजिए कि स्कोप रिज़ॉल्यूशन ऑपरेटर (`::`) `enumeration` के किसी `enumerator` को कैसे बताता है:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## स्कोपिंग

सोचिए, आपके पास पहियों की सामग्री के लिए एक और `enumeration` है:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
पहिए और डेक, दोनों _plastic_ के बने हो सकते हैं, फिर भी इन दोनों को आपस में मिलाया नहीं जा सकता।
ये दोनों अलग-अलग टाइप हैं: `DeckMaterial` वाला plastic और `WheelMaterial` वाला plastic।
हर `enumeration` के `enumerators` अपने अलग स्कोप में रहते हैं, यानी अपने अलग `namespace` में।
इसी वजह से इन्हें `scoped enumerations` कहा जाता है।

## अनस्कोप्ड एन्यूमरेशन
आप सोच रहे होंगे कि जब नाम `scoped` है, तो `unscoped` एन्यूमरेशन भी होंगे, और आप सही सोच रहे हैं।
`Unscoped enumerations` का इस्तेमाल धीरे-धीरे कम हो रहा है, क्योंकि इन सबका ग्लोबल नेमस्पेस एक ही होता है।
नेमस्पेस साझा होने की वजह से आपके पास ऐसे दो `unscoped enumerations` नहीं हो सकते जिनके `enumerators` एक जैसे हों, जैसे ऊपर के उदाहरण में _plastic_।

साथ ही, `unscoped enumerations` अपने आप पूर्णांकों में बदल जाते हैं।
नीचे दिए उदाहरण में एक चौंकाने वाला नतीजा देखिए:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

अगर आप `scoped enumerations` को पूर्णांकों में बदलना चाहते हैं, तो `static_cast<int>` का उपयोग कर सकते हैं।
~~~~
