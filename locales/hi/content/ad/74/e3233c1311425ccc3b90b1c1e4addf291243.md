# परिचय

## लूप

**लूप** निर्देशों का ऐसा क्रम है जिसे अंत की शर्त पूरी होने तक एक से ज़्यादा बार चलाया जा सकता है।

x86-64 में लूप आम तौर पर पिछले लेबल पर जंप करके बनाया जाता है:

```x86asm
example_loop:
    ...
    jmp example_loop
```

ध्यान दीजिए कि पिछले लेबल पर बिना शर्त वाला जंप हमेशा निष्पादन को उसी लेबल पर पहुँचा देता है।
इसका मतलब है कि लूप हमेशा दोहराता रहेगा, जब तक कि दोहराए जाने वाले क्रम से बाहर जाने वाला कोई दूसरा जंप न हो।

उदाहरण के लिए, यह लूप खत्म नहीं होता:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

और यह लूप खत्म हो भी सकता है, अगर शर्त पूरी हो जाए:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### गिनती वाले लूप

गिनती वाला लूप लगभग हमेशा एक ही तरह से खत्म होता है: एक निर्देश जो काउंटर बदलता है या दो वैल्यू की तुलना करता है, और ठीक उसके बाद एक शर्त वाला जंप, जो तय करता है कि एक और चक्कर लगाना है या नहीं।

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
ऊपर के कोड में `cmp rsi, 0` की ज़रूरत नहीं है, क्योंकि `sub rsi, 1` परिणाम `0` होने पर पहले ही `zero flag (ZF)` सेट कर देता है।

हालाँकि असेंबली में शर्तें जाँचने का मुख्य तरीका `cmp` ही है, फिर भी कई निर्देश फ्लैग बदल देते हैं।
उदाहरण के लिए, कई पूर्णांक अंकगणितीय या बिटवाइज़ निर्देश परिणाम `0` होने पर `ZF` बदल देते हैं, और परिणाम ऋणात्मक होने पर `SF` बदल देते हैं (यानी जब सबसे ऊपर वाला बिट सेट हो)।

कौन-सा निर्देश किन फ्लैग को बदलता है, यह देखने के लिए आप एक [संदर्भ][reference] देख सकते हैं।

[reference]: https://www.felixcloutier.com/x86/
~~~~

ध्यान दीजिए कि ऊपर के उदाहरण में मान लिया गया है कि `rsi` `0` से बड़ा है।
अगर यह `0` होता, तो `sub rsi, 1` इसे `-1` बना देता, जो कि बिना चिह्न वाली बहुत बड़ी संख्या है।
लूप के अंत में खत्म होने से पहले इसे और `18,446,744,073,709,551,615` इटरेशन लगते।
साथ ही, ऐरे की लंबाई `0` होने की वजह से मेमोरी का कोई भी एक्सेस सीमा से बाहर चला जाता।

अगर ऐरे की लंबाई के बारे में कोई भरोसा न हो, तो दो आम तरीके हैं।

पहला तरीका यह है कि अंत की शर्त को लूप के शुरू में ले आया जाए, और फिर अंत में बिना शर्त वाला जंप रखा जाए:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

दूसरा तरीका यह है कि लूप शुरू होने से पहले एक बार जाँच लिया जाए कि ऐरे की लंबाई शून्य तो नहीं है:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

यह दूसरा तरीका आम तौर पर पहले वाले से ज़्यादा कुशल होता है, क्योंकि लूप के अंदर के कोड में ब्रांच कम होती हैं।
इसके बारे में आप आगे के किसी कॉन्सेप्ट में और जानेंगे।

~~~~exercism/advanced
कुछ स्थितियों में आधुनिक CPU दो अलग-अलग निर्देशों को एक ही ऑपरेशन में मिला देते हैं।
इस अनुकूलन को **मैक्रोफ्यूज़न** कहते हैं।

`sub` और `add` जैसे कई अंकगणितीय निर्देश, तथा `cmp` और `test`, अक्सर ठीक बाद आने वाले शर्त वाले जंप के साथ जुड़ जाते हैं।
इसका मतलब है कि `cmp rax, rdx` जैसे किसी निर्देश के ठीक बाद शर्त वाला जंप आने पर CPU आम तौर पर इन दोनों को एक ही ऑपरेशन मान लेता है।

मैक्रोफ्यूज़न CPU पर निर्भर करता है, और यह भी CPU के हिसाब से बदलता है कि कौन-सा निर्देश किस शर्त वाले जंप के साथ जुड़ता है।

एक उपयोगी संदर्भ [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch] है।
साथ ही, [Intel optimization reference manual][intel-opt] के अनुभाग 3.4.2.2 (Optimizing for Macrofusion) में Intel CPUs के लिए जुड़ सकने वाले जोड़ों की सूची दी गई है।

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
