# परिचय

असेंबली में हर डेटा बाइट्स का एक क्रम होता है।
इसका मतलब है कि किसी भी डेटा को उन आधारभूत बाइट्स के **ऐरे** के रूप में देखा जा सकता है।

## ऐरे के एलिमेंट तक पहुँचना

मेमोरी में किसी भी वैल्यू तक पहुँचने के लिए उसका **प्रभावी एड्रेस** निकालना ज़रूरी होता है।
प्रभावी एड्रेस एक एक्सप्रेशन होता है, जो इन चीज़ों से मिलकर बन सकता है:

- एक _बेस एड्रेस_, जैसे कि किसी वेरिएबल के लेबल से बताया गया एड्रेस।
- एक _इंडेक्स रजिस्टर_, जिसे `1`, `2`, `4` या `8` से स्केल किया जा सकता है।
- एक साइन्ड 32-बिट _डिस्प्लेसमेंट_, यानी वह संख्या जिसे बेस एड्रेस में जोड़ा (या उससे घटाया) जाता है।

ध्यान दीजिए कि यह एड्रेस _0 से शुरू होता है_, यानी बिना किसी ऑफसेट वाला बेस एड्रेस किसी वेरिएबल के पहले बाइट की ओर इशारा करता है।
इसी वजह से, जैसा हमने पिछले कॉन्सेप्ट में किया था, किसी लेबल का इस्तेमाल बिना किसी ऑफसेट के करके मेमोरी को डीरेफरेंस करने पर ऐसी वैल्यू मिलती है जो उसके पहले बाइट से शुरू होती है:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 [लिटिल एंडियन][endianness] है।
इसका मतलब है कि किसी मल्टीबाइट वैल्यू का सबसे कम महत्वपूर्ण बाइट सबसे छोटे मेमोरी एड्रेस पर संग्रहीत होता है।

इसलिए जब हम किसी मल्टीबाइट वैल्यू के अलग-अलग बाइट्स तक पहुँचते हैं, तो ज़्यादा महत्वपूर्ण बाइट्स तक पहुँचने के लिए बेस एड्रेस में एक धनात्मक ऑफसेट जोड़ना ज़रूरी होता है।

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

किसी वैल्यू की सूची के साथ घोषित किया गया इनिशलाइज़्ड वेरिएबल उन वैल्यू का ऐरे होता है, और हर एलिमेंट का आकार वही होता है जो बताया गया हो।
लेकिन ऑफसेट हमेशा **_बाइट्स_** के हिसाब से होते हैं, भले ही ऐरे के हर एलिमेंट का आकार इससे बड़ा हो:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

ध्यान दीजिए कि चूँकि एड्रेस बाइट्स के हिसाब से होते हैं, इसलिए ऐरे के किसी भी एलिमेंट का कोई एक बाइट सीधे एक्सेस किया जा सकता है:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

इसी कारण एक ही इंस्ट्रक्शन में किसी एलिमेंट के आकार से ज़्यादा बाइट्स भी एक्सेस की जा सकती हैं:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
असेंबली ऐरे एक्सेस पर कोई बाउंड्स चेकिंग नहीं करती।
ऐरे के अंत से आगे का कोई इंडेक्स ऐरे के बाहर की मेमोरी पढ़ता या लिखता है।
इससे चुपचाप गलत परिणाम आ सकते हैं, दूसरा डेटा खराब हो सकता है, और अगर एक्सेस की गई मेमोरी मैप नहीं है तो रनटाइम फॉल्ट भी हो सकता है।
हर प्रभावी एड्रेस को ऐरे के अंदर ही रखने की ज़िम्मेदारी प्रोग्रामर की है।
~~~~

## इनिशलाइज़्ड ऐरे का आकार निकालना

NASM (The Netwide Assembler, यानी वह असेंबलर जिसका इस्तेमाल इस ट्रैक में किया जाता है) में एक खास सिंबल (`$`) होता है, जो मेमोरी में मौजूदा जगह बताता है।
यह सिंबल ऐरे ने मेमोरी में जितनी जगह ली है, उसका कुल आकार निकालने का एक आसान तरीका देता है:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

जब `example` के ठीक बाद इस्तेमाल किया जाता है, तो `$` में ऐरे के अंत वाला मेमोरी एड्रेस होता है।
इसका मतलब है कि `$ - example` उस एड्रेस और लेबल `example` द्वारा दर्शाए गए एड्रेस के बीच का अंतर है।
यही `example` द्वारा दर्शाए गए ऐरे का कुल आकार है, बाइट्स में।

तो इस वैल्यू के साथ `example_length` बनाकर हमने एक 8-बाइट का वेरिएबल बनाया है, जो ऐरे का आकार यानी लंबाई बाइट्स में संग्रहीत करता है।

## सेक्शन .bss

अनइनिशलाइज़्ड डेटा **सेक्शन .bss** में घोषित किया जाता है।
ज़्यादातर प्लेटफॉर्म पर प्रोग्राम की शुरुआत में OS इस डेटा को शून्य से भर देता है।

NASM में अनइनिशलाइज़्ड वेरिएबल में एक नाम होता है, एक डायरेक्टिव होता है जो डेटा का आकार बताता है, और वे एलिमेंट होते हैं जिनके लिए जगह आरक्षित करनी है।
इनमें से हर एक को दूसरे से एक स्पेस द्वारा अलग किया जाता है।

मुख्य डायरेक्टिव और उनसे जुड़े डेटा आकार ये हैं:

| डायरेक्टिव | आकार    |
| :-------: | :------ |
|   resb    | 1 बाइट  |
|   resw    | 2 बाइट |
|   resd    | 4 बाइट |
|   resq    | 8 बाइट |

उदाहरण के लिए, यह `example` नाम के वेरिएबल में `3` बाइट के लिए अनइनिशलाइज़्ड जगह आरक्षित करता है:

```x86asm
section .bss
    example resb 3
```

और यह `arr` नाम के वेरिएबल में `10` गुना `8` बाइट (यानी `80` बाइट) के लिए अनइनिशलाइज़्ड जगह आरक्षित करता है:

```x86asm
section .bss
    arr resq 10
```

`section .bss` के वेरिएबल म्यूटेबल होते हैं, यानी उन्हें पढ़ा और लिखा दोनों जा सकता है।

अनइनिशलाइज़्ड डेटा तक इनिशलाइज़्ड डेटा की तरह ही उसके प्रभावी एड्रेस का इस्तेमाल करके पहुँचा जा सकता है।
इसी तरह इनकी स्टोरेज अवधि भी स्टैटिक होती है और ये उसी सोर्स फाइल के किसी भी फंक्शन से एक्सेस किए जा सकते हैं (और अगर `global` घोषित हों, तो दूसरी सोर्स फाइलों से भी)।

## Lea इंस्ट्रक्शन से ऐरे के एड्रेस तक पहुँचना

जैसा कि पिछले कॉन्सेप्ट में देखा गया था, `lea` इंस्ट्रक्शन एक प्रभावी मेमोरी एड्रेस निकालता है।
इसे ऐरे के किसी भी एलिमेंट का एड्रेस उसी तरह निकालने के लिए इस्तेमाल किया जा सकता है।

ध्यान दीजिए कि रिलेटिव एड्रेसिंग में अक्सर ज़्यादा जटिल एड्रेस बनाने से पहले वेरिएबल का एड्रेस एक रजिस्टर में लोड करना ज़रूरी होता है:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea` का एक फायदा यह है कि यह कोई वैल्यू निकालने के लिए एड्रेस की गणना वाला अंकगणित इस्तेमाल करता है, बिना उस एड्रेस की मेमोरी को असल में एक्सेस किए।
इसी वजह से यह अंकगणितीय गणनाएँ करने के लिए भी काम आता है, भले ही किसी रजिस्टर में कोई मेमोरी एड्रेस न हो:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
