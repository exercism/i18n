# कोड को शामिल करना

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

`include` किसी दूसरी क्लास के कोड को इस क्लास में कॉपी कर देता है। यह कंपाइल के समय होता है। इसका रनटाइम पर कोई खर्च नहीं होता, और रनटाइम पर दोनों क्लासों का कोई संबंध भी नहीं रहता। इसके बाद वे दोनों क्लासें जुड़ी नहीं रहतीं।

## क्लॉज़

```
   include CLASS  old_name -> new_name , old_name -> ;
```

हर प्रविष्टि एक फीचर का नाम बदलती है। `-> ;` में नया नाम नहीं दिया जाता, इसलिए उस फीचर को छोड़ दिया जाता है। जिस फीचर का नाम नहीं लिखा जाता, वह बिना किसी बदलाव के अंदर आ जाता है।

नाम बदलने का असर सिर्फ बाहरी दुनिया को दिखने वाली चीज़ों पर पड़ता है। शामिल किए गए रूटीनों के आपसी कॉल पहले की तरह काम करते रहते हैं: अगर `describe` के अंदर `count` को कॉल किया जाता है, और `count` का नाम बदलकर `beats` कर दिया गया है, तो `describe` अब `beats` को कॉल करेगा।

## कई क्लासें शामिल करना

```sather
   include WARM_UP;
   include COOL_DOWN;
```

यह मान्य है, और इसी तरह Sather वह चीज़ पाता है जिसे दूसरी भाषाएँ मल्टीपल इनहेरिटेंस कहती हैं। इसमें वे आम परेशानियाँ साथ नहीं आतीं, क्योंकि टकराव होने पर कंपाइल एरर मिलती है और उसे ठीक करने के लिए नाम बदलना या किसी एक फीचर को छोड़ देना काफी होता है। कुछ भी किसी ऐसे प्राथमिकता-क्रम से तय नहीं होता जिसे आपको रटना पड़े।

## private include

```sather
   private include WARM_UP;
```

कोड को इस क्लास के अपने इस्तेमाल के लिए अंदर ले आता है, लेकिन उसे बाहर नहीं दिखाता। यह तब काम आता है जब आपको इम्प्लीमेंटेशन चाहिए, इंटरफ़ेस नहीं।

## दोनों को साथ इस्तेमाल करना

क्लासों के एक परिवार के लिए आम ढाँचा कुछ इस तरह दिखता है:

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

`< $ACT` बताता है कि यह क्लास क्या कर सकती है। `include ACT_BASICS` यह बताता है कि वह काम कैसे होगा, यानी "कैसे" का एक हिस्सा देता है। अगर आप "कैसे" के बारे में अपना मन बदल दें, तो `<` अपनी जगह से नहीं हिलता।

## यह तरीका क्यों अपनाया जाता है

एब्स्ट्रैक्ट क्लास में कोई कोड नहीं होता, इसलिए गलती से उससे इनहेरिट करना संभव ही नहीं है। यहाँ ऐसी कोई सुपरक्लास नहीं होती जिसका व्यवहार आपके नीचे बदल जाए। यहाँ रीयूज़ का मतलब है कंपाइल के समय ली गई एक कॉपी। यह कॉपी उसी क्लास से आती है जिसका नाम आपने लिखा है, और उसमें हर नाम-बदलाव साफ़-साफ़ लिखा होता है।

इसकी कीमत यह है कि हर क्लास में रीयूज़ के लिए अलग से कहना पड़ता है। यही सौदा है: टाइप करना अधिक, पर कुछ भी छिपा हुआ नहीं।
