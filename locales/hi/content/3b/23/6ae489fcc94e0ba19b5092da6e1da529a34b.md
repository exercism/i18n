# निर्देश परिशिष्ट

## Python में यह अभ्यास कैसे लागू किया जाता है: रिकर्शन

यह अभ्यास लूप के बजाय [concept:python/recursion]() का उपयोग करके पूरा करने के लिए बनाया गया है।
रिकर्सिव फंक्शन वह फंक्शन होता है जो खुद को कॉल करता है। ऐसा फंक्शन उन समस्याओं को हल करने में काम आता है जो खुद अपने ही रूप में परिभाषित होती हैं।
अनंत रिकर्शन से बचने के लिए (या यूँ कहें कि स्टैक के ओवरफ्लो होने से बचने के लिए) "बेस केस" नाम की एक चीज़ इस्तेमाल की जाती है।
जब बेस केस तक पहुँच जाते हैं, तो एक ऐसी वैल्यू लौटाई जाती है जो रिकर्सिव नहीं है। इससे पिछली फंक्शन कॉल पूरी होकर अपनी वैल्यू लौटा पाती है, और यह क्रम स्टैक में नीचे की ओर चलता रहता है, जब तक कि पहली फंक्शन कॉल अंतिम उत्तर न लौटा दे।
5! (यानी 5 * 4 * 3 * 2 * 1) का उत्तर निकालने के लिए हम एक रिकर्सिव फंक्शन ऐसे लिख सकते हैं:

````python
def factorial(number):
  if number <= 1:  # base case
    return 1

  return number * factorial(number - 1) # recursive case

print(factorial(5)) # returns 120
````

अंत में यह ध्यान रखने की बात है कि Python रिकर्सिव कॉल की संख्या सीमित रखता है (डिफाल्ट रूप से 1000) और [टेल रिकर्शन][tail-recursion] के लिए ऑप्टिमाइज़ नहीं करता।

## एक्सेप्शन संदेश

कभी-कभी [एक्सेप्शन उठाना][raising] ज़रूरी हो जाता है।
ऐसा करते समय आपको हमेशा एक **अर्थपूर्ण एरर संदेश** शामिल करना चाहिए, जो बताए कि एरर का स्रोत क्या है।
इससे आपका कोड पढ़ने में आसान हो जाता है और डीबग करने में काफी मदद मिलती है।
जिन स्थितियों में आपको पता हो कि एरर का स्रोत एक खास टाइप का होगा, वहाँ आप [बिल्ट-इन एरर टाइप][built-in-errors] में से कोई एक उठाना चुन सकते हैं, लेकिन फिर भी एक अर्थपूर्ण संदेश ज़रूर शामिल कीजिए।

इस खास अभ्यास में, अगर `rows()` फंक्शन को कोई ऋणात्मक संख्या दी जाए, तो आपको [raise स्टेटमेंट][raise-statement] का उपयोग करके कई `ValueErrors` "फेंकने" हैं।
टेस्ट तभी पास होंगे जब आप `exception` को `raise` भी करें और उसके साथ एक संदेश भी शामिल करें।

किसी संदेश के साथ `ValueError` उठाने के लिए, संदेश को `exception` टाइप के आर्गुमेंट के रूप में लिखिए:

```python
# if the rows function is passed a negative number.
raise ValueError("number of rows is negative")
```
