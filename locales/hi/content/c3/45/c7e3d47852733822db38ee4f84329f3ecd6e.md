# परिचय

अधिकतर मामलों में Factor इटरेशन का काम `each`, `map` और `count` जैसे कॉम्बिनेटरों के ज़रिए करता है। लेकिन कभी-कभी किसी गणना को लिखने का सबसे साफ़ तरीका **रिकर्शन** होता है, यानी एक ऐसा वर्ड जो खुद को कॉल करता है।

## रिकर्शन वाला वर्ड बनाइए

एक `:` डेफिनिशन खुद को सीधे कॉल कर सकता है:

```factor
: count-down ( n -- )
    dup 0 = [ drop ] [ dup . 1 - count-down ] if ;

5 count-down
! prints 5 4 3 2 1
```

## खाली और गैर-खाली की शाखा बनाइए

`if-empty` ([`sequences`][sequences] में मौजूद) रिकर्शन का स्वाभाविक बेस केस है:

```
if-empty ( seq emptyquot nonemptyquot -- )
```

```factor
{ 4 0 9 } [ "empty" ] [ "got data" ] if-empty .
! => "got data"
```

`emptyquot` तब चलता है जब (खाली) सीक्वेंस पहले ही स्टैक से हट चुका हो; `nonemptyquot` तब चलता है जब सीक्वेंस अब भी स्टैक पर हो।

## `cond` से शर्तों वाली कई शाखाएँ बनाइए

जब आपके रिकर्शन में दो से अधिक केस हों, तब `cond` ([`combinators`][combinators] में मौजूद) कोड को पढ़ने में आसान बनाए रखता है:

```factor
: classify ( n -- label )
    {
        { [ dup 0 < ] [ drop "negative" ] }
        { [ dup 0 = ] [ drop "zero"     ] }
        [ drop "positive" ]
    } cond ;
```

## `DEFER:` के साथ फॉरवर्ड रेफरेंस बनाइए

एक `:` डेफिनिशन खुद को सीधे कॉल कर सकता है, लेकिन जब दो वर्ड *एक-दूसरे को* कॉल करते हैं, तब पार्सर दूसरे के अस्तित्व में आने से पहले पहले वर्ड को पढ़ लेता है। `DEFER:` एक नाम सुरक्षित रखता है ताकि पहली परिभाषा कंपाइल हो सके:

```factor
DEFER: even?

: odd? ( n -- ? ) dup 0 = [ drop f ] [ 1 - even? ] if ;
: even? ( n -- ? ) dup 0 = [ drop t ] [ 1 - odd? ] if ;
```

`DEFER:` तब भी काम आता है जब किसी हेल्पर वर्ड को उस वर्ड के *बाद* पढ़ना अधिक स्वाभाविक लगता है जो उसका उपयोग करता है।
