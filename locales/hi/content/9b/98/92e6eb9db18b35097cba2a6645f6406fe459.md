# परिचय

जैसा कि [`Nothingness`][concept-nothingness] कॉन्सेप्ट में बताया गया है, R में ऐसे डेटा को दर्शाने के कई तरीके हैं जो अनुपस्थित ([`NULL`][ref-null]), अज्ञात ([`NA`][ref-na]) या गणितीय रूप से अमान्य ([`NaN`][ref-finite], [`Inf`][ref-finite]) हो सकता है।
आम तौर पर R इन वैल्यू का उपयोग करके समस्याओं को वहीं चिह्नित करने की कोशिश करता है और बिना एक्सेप्शन उठाए आगे चलता रहता है।

## `stop()`

कुछ समस्याएँ इतनी बुनियादी होती हैं कि प्रोग्राम को आगे बढ़ने नहीं दिया जा सकता।
ऐसे में [`stop(msg)`][ref-stop] का उपयोग कीजिए, जो प्रोग्राम को तुरंत `Error` के साथ रोक देता है और `msg` प्रिंट करता है।

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

दूसरी भाषाओं के [`assert`][wiki-assert] की तरह, [`stopifnot()`][ref-stopifnot] भी `stop()` का एक सुविधाजनक रैपर है।
इसके आर्गुमेंट कॉमा से अलग की गई मनमानी संख्या में बूलियन शर्तें हैं, और प्रोग्राम तभी आगे बढ़ता है जब ये सभी `TRUE` हों।

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

एरर को संभालने के लिए R में कई तरीके हैं।
ये Common Lisp पर आधारित हैं और कई लोकप्रिय भाषाओं से काफी अलग हैं।

सबसे आसान तरीका यह है कि संभावित रूप से समस्या पैदा करने वाले कोड को [`try()`][ref-try] में लपेट दिया जाए।

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning] और [`message()`][ref-message]

ये ऐसी परिस्थितियों की प्रतिक्रियाएँ हैं जो घातक नहीं होतीं, जैसे:

- किसी ऐसी समस्या की चेतावनी देने के लिए, जिससे प्रोग्राम कम से कम कुछ हद तक उबर सकता हो।
- किसी लंबे समय तक चलने वाले प्रोग्राम की प्रगति की जानकारी उपयोगकर्ता को देने के लिए।

इनमें एक अंतर यह है कि चेतावनियाँ कैश हो जाती हैं और डिफ़ॉल्ट रूप से फंक्शन के लौटने पर ही आउटपुट होती हैं, जबकि संदेश तुरंत आउटपुट होते हैं।
डिफ़ॉल्ट व्यवहार बदलने के कई तरीके हैं, जिन पर यहाँ चर्चा करना हमारे दायरे से बाहर है।

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

[`suppressWarnings()`][ref-warning] फंक्शन कभी-कभी Exercism के भीतर उपयोगी हो सकता है, ताकि अनचाहे आउटपुट से टेस्ट रनर को भ्रमित होने से बचाया जा सके।

## शर्त हैंडलर

एरर स्थितियों से निपटने का R में एक वैकल्पिक तरीका है, जो भावना में Java और उससे जुड़ी भाषाओं के तरीके के करीब है।

इस कॉन्सेप्ट में विवरण हमारे दायरे से बाहर है, लेकिन जिसे रुचि हो, वह [`tryCatch`][ref-conditions] और [`withCallingHandlers`][ref-conditions] देख सकता है।

Advanced R के [अनुभाग 8.4][book-handling] में इस पर अच्छी चर्चा है।
