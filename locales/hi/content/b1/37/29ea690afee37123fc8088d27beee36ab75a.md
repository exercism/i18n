# जेनेरिक क्लास

आपने शुरुआत से ही `ARRAY{STR}`, `FMAP{STR,INT}` और `FSET{STR}` का इस्तेमाल किया है।
इन ब्रैकेट के अंदर हमेशा एक टाइप रहा है। अब आप ऐसी क्लास लिखते हैं जिसके अपने
ब्रैकेट होते हैं।

## समस्या

खोई हुई चीज़ों के दफ्तर को ऐसा डिब्बा चाहिए जो एक चीज़ रखता है और याद रखता है कि उसे
किसने जमा किया था। स्वेटर के लिए एक डिब्बा:

```sather
class JUMPER_BOX is
   attr item : JUMPER;
   ...
end;
```

और फिर पानी की बोतल के लिए वही क्लास दोबारा, और फोन के लिए एक बार और।
तीन प्रतियाँ, जो सिर्फ एक शब्द में अलग हैं।

## टाइप पैरामीटर

```sather
class LOST_BOX{T} is

   attr item : T;

   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;

end; -- class LOST_BOX{T}
```

क्लास के नाम के बाद `{T}` एक **टाइप पैरामीटर** है। `T` कोई टाइप नहीं है, बल्कि
क्लास के इस्तेमाल के समय दिए जाने वाले किसी भी टाइप के लिए एक प्रतिनिधि है। क्लास के
अंदर `T` का इस्तेमाल ठीक वैसे ही होता है जैसे किसी भी टाइप के नाम का इस्तेमाल होता है।

## इसे इस्तेमाल करना

ब्रैकेट में टाइप दीजिए:

```sather
   jumper ::= #LOST_BOX{STR}("blue jumper");
   count ::= #LOST_BOX{INT}(3);

   jumper.item      -- "blue jumper", a STR
   count.item       -- 3, an INT
```

`LOST_BOX{STR}` और `LOST_BOX{INT}` दो अलग-अलग टाइप हैं। एक को वहाँ रखना जहाँ दूसरे
की ज़रूरत है, एक एरर है जिसे कंपाइलर पकड़ लेता है, ठीक वैसे ही जैसे आपने दोनों क्लास
हाथ से लिखी हों। वास्तव में होता यही है: Sather हर वास्तव में इस्तेमाल होने वाले
टाइप के लिए उस पैटर्न से एक अलग क्लास बनाता है।

तो रन टाइम पर इसका कोई खर्च नहीं होता, और टाइप की जानकारी का कोई नुकसान भी नहीं
होता: `jumper.item` वास्तव में एक `STR` है, ऐसा कुछ नहीं जिसे जाँचना या बदलना पड़े।

## एक से अधिक

एक क्लास कई पैरामीटर ले सकती है, जिन्हें कॉमा से अलग किया जाता है। `FMAP{K,T}` वह
उदाहरण है जिसे आप पहले से जानते हैं।

```sather
class LABELLED{L,T} is
   attr label : L;
   attr item : T;
   ...
end;
```

## नाम कैसे रखें

परंपरा से एक-एक बड़ा अक्षर: `T` किसी चीज़ के लिए, `K` किसी की के लिए, `E`
किसी एलिमेंट के लिए। लाइब्रेरी इनका इस्तेमाल हर जगह करती है।
