# परिचय

यह अभ्यास [Backyard Birdwatcher][backyard-birdwatcher] में देखी गई बातों को आगे बढ़ाता है। इसमें हम वे हायर-ऑर्डर वर्ड पेश करते हैं जो काम चलाने के लिए एक *कोटेशन* लेते हैं, यानी `[ ]` ब्रैकेट में लिखा कोड का एक टुकड़ा।

## वैल्यू के रूप में कोटेशन

कोटेशन कोड का एक लिटरल टुकड़ा भर है। आप इसे डेटा की तरह किसी दूसरे वर्ड को पास कर सकते हैं:

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

यहाँ `[ 2 > ]` एक कोटेशन है जो एक संख्या लेता है और बदले में एक बूलियन छोड़ता है। `count` इसे हर एलिमेंट पर चलाता है और सही निकलने वाले नतीजों की गिनती करता है।

## फिल्टर करना और अस्वीकार करना

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

`without` अपने दूसरे आर्गुमेंट को एक सेट की तरह मानता है: `seq` का कोई भी एलिमेंट जो `exclude` के *किसी भी* एलिमेंट के `=` है, हटा दिया जाता है। `sift`, `reject` का बिना-कोटेशन वाला खास रूप है: यह `f` को छोड़कर हर एलिमेंट रखता है, जो पिछले `map` से बची रिक्तियों को साफ करने के लिए काम आता है।

### टेस्ट के नतीजे को बचाए रखना

`find` मिलता हुआ *एलिमेंट* ही लौटा देता है। जब टेस्ट पहले ही वह वैल्यू *निकाल* देता है जो आपको असल में चाहिए, तो `map-find` आपको दूसरा चक्कर बचा देता है: यह हर एलिमेंट पर कोटेशन चलाता है और पहला गैर-`f` नतीजा **और** वह एलिमेंट, जिसने वह नतीजा दिया, दोनों लौटाता है।

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

जो एलिमेंट शर्त पूरी नहीं करते, उनके लिए कोटेशन `f` लौटाता है, और जो पूरी करता है उसके लिए वह नतीजा लौटाता है जिसे आप रखना चाहते हैं। अगर कोई भी शर्त पूरी नहीं करता, तो `map-find`, `find` की तरह ही `f f` छोड़ देता है।

### स्लॉट के हिसाब से रिकॉर्ड फिल्टर करना

जब एलिमेंट *टपल* होते हैं, तो प्रेडिकेट आम तौर पर अपने अपने-आप बने रीडर `slot>>` से कोई स्लॉट निकालता है और उसी पर टेस्ट करता है:

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## `with` की मदद से एक तय वैल्यू साथ चलाना

कभी-कभी प्रेडिकेट को ऐसी वैल्यू चाहिए होती है जो हर कॉल पर एक जैसी रहे, जैसे कोई थ्रेशोल्ड, कोई भाजक, या कोई लक्ष्य स्ट्रिंग। `with` ([`kernel`][kernel] में) उस तय वैल्यू को कोटेशन में बैठा देता है, और दो-आर्गुमेंट वाले कोटेशन `( value elt -- ? )` को उस एक-आर्गुमेंट वाले कोटेशन में बदल देता है जिसकी `filter`, `count`, `map` और `each` उम्मीद करते हैं:

```
with ( value seq quot -- seq curry )
```

हर एलिमेंट वाली कॉल को स्टैक पर `( value elt )` दिखता है, यानी पहले तय वैल्यू और उसके बाद मौजूदा एलिमेंट:

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## मैप करना और इटरेशन करना

`map` ([`sequences`][sequences] में) हर एलिमेंट पर एक कोटेशन लगाता है और नतीजों का ऐरे लौटाता है। `each` भी वही सफर तय करता है, पर नतीजों को छोड़ देता है, जो तब काम आता है जब कोटेशन सिर्फ अपने साइड इफेक्ट के लिए चलता हो। `2map` *दो* सीक्वेंसों को कदम से कदम मिलाकर चलाता है और मिलते-जुलते एलिमेंट जोड़ता है; `2each` और `2reduce` उसके क्रमशः सिर्फ-साइड-इफेक्ट वाले और फोल्ड करने वाले रिश्तेदार हैं; `zip` का छोटा रूप यही कहता है कि "जोड़े बना दो, पर उन्हें मिलाओ मत":

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

`2reduce` एक एक्युमुलेटर को एक साथ दोनों सीक्वेंसों में से गुज़ारता है। इसका कोटेशन `( accumulator elt1 elt2 -- accumulator' )` लेता है। यहाँ यह डॉट प्रोडक्ट जोड़ता जाता है: हर जोड़े को गुणा किया जाता है, और गुणनफलों को जोड़ दिया जाता है (`1*10 + 2*20 + 3*30`):

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

`map-as`, `map` का वह रिश्तेदार है जो आउटपुट सीक्वेंस का टाइप तय कर देता है। इनपुट-टाइप के डिफॉल्ट को बदलने के लिए एग्ज़ेंप्लर के तौर पर एक खाली `{ }` या `V{ }` पास कीजिए (वरना जब Factor नतीजों को वापस एक स्ट्रिंग में पैक करने की कोशिश करता है, तो स्ट्रिंग को गैर-अक्षरों में मैप करने पर एरर मिलती है)।

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

दोनों दो-सीक्वेंस वाले रूप छोटे इनपुट की लंबाई पर रुक जाते हैं। `zip`, `[ 2array ] 2map` जैसा ही है, यानी जोड़ों को बचाना, उन्हें मिलाना नहीं।

## सॉर्ट करना

`sort` प्राकृतिक क्रम में एक सॉर्ट की हुई कॉपी लौटाता है; `sort-by` ([`sorting`][sorting] में) हर एलिमेंट से निकाली गई की के हिसाब से सॉर्ट करता है:

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## एकत्र करना

`map-sum` ([`sequences`][sequences] में) पूरे सीक्वेंस पर एक कोटेशन मैप करता है और एक ही चक्कर में नतीजों का जोड़ दे देता है:

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## न्यूनतम और अधिकतम

`minimum` और `maximum` सीधे किसी सीक्वेंस का सबसे छोटा या सबसे बड़ा एलिमेंट लौटा देते हैं। `minimum-by` और `maximum-by` (दोनों [`sequences`][sequences] में) वह एलिमेंट लौटाते हैं जिसकी निकाली गई की सबसे छोटी या सबसे बड़ी होती है:

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## अपना हायर-ऑर्डर वर्ड लिखना

जब *आपका* वर्ड रनटाइम आर्गुमेंट के तौर पर एक कोटेशन लेता है और उसे `map`, `filter`, `each` वगैरह को आगे भेज देता है, तो अपने वर्ड को `; inline` के साथ घोषित कीजिए। इससे कंपाइलर को पता चलता है कि हर कॉल साइट पर आपके वर्ड को इनलाइन कर देना है, जहाँ कोटेशन एक ज्ञात लिटरल होता है। इसके बिना कंपाइलर के पास कोटेशन का स्टैक इफेक्ट जानने का कोई तरीका नहीं होता।

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

सिर्फ लिटरल कोटेशनों से बने वर्ड को `inline` की ज़रूरत नहीं होती, सिर्फ उन्हें जो *आने वाले* कोटेशन को आगे भेजते हैं।

अगर ऐसा कोई `inline` वर्ड कभी *खुद को* कॉल करे, यानी एक रिकर्सिव कॉम्बिनेटर हो, तो उसे `; inline recursive` के साथ घोषित कीजिए। यह अतिरिक्त वर्ड जोड़े बिना कंपाइलर *"The inline recursive word ... must be declared recursive"* कहकर रुक जाता है, जो आपको ठीक-ठीक बताता है कि क्या जोड़ना है।

## दूसरा एलिमेंट निकालना

दो एलिमेंट वाले ऐरे के लिए, `second` उसका दूसरा एलिमेंट लौटाता है। `first` पहला लौटाता है। दोनों [`sequences`][sequences] में हैं।

## संख्याओं से स्ट्रिंग

`number>string ( n -- str )` ([`math.parser`][math.parser] में) किसी संख्या को उसके दशमलव-स्ट्रिंग रूप में बदल देता है:

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
