# टेस्ट

हर अभ्यास के साथ यूनिट टेस्ट और एक CMake बिल्ड रेसिपी आते हैं। इम्प्लीमेंटेशन आपको लिखना है।
हर टेस्ट फाइल आपके इम्प्लीमेंटेशन के साथ लिंक होकर एक कंसोल एक्ज़ीक्यूटेबल बनाती है, जो टेस्ट चलाता है। टेस्ट एक्ज़ीक्यूटेबल चलाने पर हर फेल होने वाले टेस्ट के लिए संदेश छपते हैं, और टेस्ट फेल होने पर यह शून्य से अलग एग्ज़िट स्टेटस बताता है।

टेस्ट फाइल का नाम `<exercise>_test.f90` होता है, इसलिए अभ्यास "Bob" के लिए टेस्ट वाली फाइल `bob_test.f90` है। हर टेस्ट में एक कमेंट होता है जो टेस्ट का वर्णन करता है, और उसके बाद असली टेस्ट `call assert_equal` से शुरू होता है, जैसे:

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

किसी टेस्ट को बंद करने के लिए बस उसके आगे `'!'` लगाकर उसे कमेंट बना दीजिए, जैसे:

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

हर अभ्यास को पूरा करने का तरीका इस तरह है:

* CMake से शुरुआती बिल्ड बनाना
* हर यूनिट टेस्ट के लिए:
 * कंपाइल एरर ठीक कीजिए, जिससे टेस्ट फेल हो।
 * इतना ही लिखिए जितने से टेस्ट पास हो जाए।
 * अपने इम्प्लीमेंटेशन को रीफैक्टर कीजिए, जिससे कोड पढ़ने में आसान हो, दोहराव कम हो, वगैरह।
 * अगले टेस्ट को अनकमेंट कीजिए


## CMake से शुरुआती बिल्ड बनाना

हर अभ्यास के साथ यूनिट टेस्ट के अलावा एक `CMakeLists.txt` फाइल भी आती है। इसमें पहले से तैयार CMake रेसिपी होती है, जो आपके लिए बिल्ड का काम संभाल लेती है। आपको इस फाइल को बदलने की ज़रूरत नहीं पड़नी चाहिए। दी गई रेसिपी यह मानकर चलती है कि आपका इम्प्लीमेंटेशन उस अभ्यास के नाम वाली सोर्स फाइल में मौजूद है।

जैसे, अभ्यास "Bob" को `bob.f90` फाइल में इम्प्लीमेंटेशन चाहिए।

**CMake चलाने से पहले अपनी शुरुआती इम्प्लीमेंटेशन फाइलें बना लीजिए।**
अगर अभ्यास "Bob" के लिए CMake चलाते समय आपके पास `bob.f90` फाइल नहीं है, तो CMake यह एरर देगा कि फाइलें नहीं मिलीं।
**ये फाइलें खाली हो सकती हैं, लेकिन उनका होना ज़रूरी है।**

इस रेसिपी की मदद से CMake आपके वातावरण के लिए उपयुक्त प्रोजेक्ट बना सकता है। इसके लिए `cmake -G` चलाइए और उसके साथ उपयुक्त जनरेटर तथा अभ्यास वाली डायरेक्टरी का पता दीजिए। CMake आपके ऑपरेटिंग सिस्टम के लिए उपयुक्त बिल्ड स्क्रिप्ट बनाएगा। इन जनरेट हुई फाइलों को अपने अभ्यास के सोर्स कोड से अलग रखने के लिए आमतौर पर `build` नाम की एक डायरेक्टरी बनाई जाती है, जिसमें ये जनरेट हुई बिल्ड फाइलें और कंपाइल किया गया कोड रखा जाता है।

इससे आपका अभ्यास फोल्डर साफ-सुथरा और बिना भीड़-भाड़ वाला रहेगा।

**ध्यान दीजिए: पहली बार `cmake` चलाने पर [testlib](###-Testlib) अपने आप डाउनलोड हो जाता है। यूनिट टेस्ट के काम करने के लिए `testlib` ज़रूरी है।

चूँकि हर असाइनमेंट के लिए बिल्ड निर्देश बनाने के लिए आपको CMake चलाना होगा, इसलिए हो सकता है कि आप इस कमांड के लिए एक bash स्क्रिप्ट (Linux/MacOS) या बैच फाइल (Windows) बना लेना चाहें।

CMake द्वारा बिल्ड वातावरण बन जाने के बाद, आप अपने वातावरण के लिए उपयुक्त कमांड से अपना कोड बिल्ड कर सकते हैं:

* Linux में make के साथ: `make`
* Windows में Visual Studio के साथ: मेन्यू से Build / Build Solution चुनिए।
* Windows में MingW के साथ: `mingw32-make.exe`
* Windows में nMake के साथ: `nmake.exe`
* MacOS में Xcode के साथ: टूलबार से Build चुनिए।

अलग-अलग वातावरणों के लिए CMake चलाने के उदाहरण नीचे दिए गए हैं।

### Linux\MacOS में Make के साथ

CMake के लिए जनरेटर का नाम `Unix Makefiles` है।
मान लीजिए कि मौजूदा अभ्यास `bob` है और हम अभ्यास वाले फोल्डर में हैं:

```
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

यह उदाहरण दिखाता है कि CMake चलाने से पहले इम्प्लीमेंटेशन के लिए खाली फाइलें कैसे बनाई जाती हैं।

टेस्ट कंपाइल करने के लिए बस build डायरेक्टरी में make टाइप कीजिए। इससे कंपाइल-टाइम एरर आने चाहिए। एरर ठीक हो जाने पर `make` फिर से चलाइए।
जब सारी बिल्ड एरर ठीक हो जाएँ, तो टेस्ट चलाइए:

```
$ ctest -V
```
### Windows में Visual Studio 2017 के साथ

CMake के लिए जनरेटर का नाम `Visual Studio 15` है। यही जनरेटर Visual Studio 2017 के सभी IDE संस्करणों को सपोर्ट करता है: Community, Professional और Enterprise। मान लीजिए कि मौजूदा अभ्यास `bob` है और हम अभ्यास वाले फोल्डर में हैं:

```
> copy nul: bob.f90
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

यह उदाहरण दिखाता है कि CMake चलाने से पहले इम्प्लीमेंटेशन के लिए खाली फाइलें कैसे बनाई जाती हैं।

### Testlib

टेस्ट एक छोटी लाइब्रेरी `testlib` पर निर्भर करते हैं, जो cmake के साथ पहली बार बिल्ड कॉन्फिगर होने पर github से डाउनलोड हो जाती है।

अगर डाउनलोड फेल हो जाए, तो इसे हाथ से डाउनलोड किया जा सकता है, जैसे:

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/TesterMain.f90
```
