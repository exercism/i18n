# C स्टाइल गाइड

यह गाइड उस स्टाइल के बारे में बताती है जिसका इस्तेमाल C ट्रैक के अभ्यासों की उदाहरण फाइलों और टेस्ट फाइलों में करना है।

इस गाइड के नियम [.clang-format][] फाइल में तय किए गए नियमों के अतिरिक्त हैं, या उन्हें साफ-साफ बताने के लिए हैं।

## C मानक

कोड को C99 मानक का पालन करना चाहिए, जिसे औपचारिक रूप से ISO/IEC 9899:1999 कहा जाता है।
POSIX, या फिर गैर-मानक लाइब्रेरी फंक्शन, टाइप या इम्प्लीमेंटेशन के बाहर के दूसरे संदर्भों का उपयोग नहीं करना चाहिए।

## नाम

सामान्य तौर पर, टाइप, वेरिएबलो, स्ट्रक्चर और फाइलों के नाम स्नेक केस में होने चाहिए, जिनमें सारे अक्षर छोटे हों और नाम के हिस्सों को अलग करने के लिए अंडरस्कोर `_` का इस्तेमाल किया जाए।

```c
void some_foo_function(char * input_string, int input_string_length);
```

### एनम

एनम के नाम आमतौर पर बहुवचन की जगह एकवचन में होने चाहिए।

एनम लेबल स्नेक केस में होने चाहिए और उनमें सारे अक्षर बड़े होने चाहिए।

```c
enum heading {
    HEADING_NORTH,
    HEADING_EAST,
    HEADING_SOUTH,
    HEADING_WEST
}
```

### मैक्रो

कॉन्स्टेंट तय करने वाले मैक्रो के नाम स्नेक केस में रखे जाते हैं और उनमें सारे अक्षर बड़े होते हैं।

```c
#define CONSTANT 0x4000
```

मैक्रो के नामों के लिए अपर-केस स्नेक केस पसंद किया जाता है, लेकिन फंक्शन जैसे दिखने वाले मैक्रो के नाम लोअर-केस स्नेक केस में रखे जा सकते हैं।

### टाइप

बुनियादी इंटीजर टाइप की जगह मानक फिक्स्ड-विड्थ टाइप (`stdint.h` में) बेहतर माने जाते हैं।

`_Bool` की जगह `bool` टाइप (`stdbool.h` से) बेहतर माना जाता है।

इसी तरह, मेमोरी से जुड़ी मात्राएँ दिखाने के लिए `size_t` और `ptrdiff_t` (`stddef.h` के) बेहतर माने जाते हैं।

`typedef` की मदद से किसी प्रोग्राम द्वारा तय किए गए टाइप के नाम के अंत में `_t` लगाना चाहिए।
हम जानते हैं कि POSIX `_t` सफिक्स को अपने लिए आरक्षित रखता है, फिर भी यह ट्रैक फिलहाल POSIX का इस्तेमाल नहीं करता।

## इन्क्लूड गार्ड

सभी हेडर फाइलों में इन्क्लूड गार्ड का इस्तेमाल करना चाहिए।

आमतौर पर इन्क्लूड गार्ड का एक सेट पूरी हेडर फाइल को घेरना चाहिए।

उदाहरण इम्प्लीमेंटेशन (`.meta/example.h`) और अभ्यास के स्टब (`exercise_name.h`) में मौजूद गार्ड ऐसे मैक्रो नाम इस्तेमाल करें जो अभ्यास के नाम पर आधारित हों।
गार्ड मैक्रो के नाम केसिंग के लिए ऊपर दिए गए मैक्रो नियम का पालन करने चाहिए।

उदाहरण के लिए, `hello-world` अभ्यास के लिए यह लिखिए:

```c
#ifndef HELLO_WORLD_H
#define HELLO_WORLD_H

//...

#endif
```

## पैरामीटर

सभी फंक्शन के घोषणा और परिभाषा, दोनों में फंक्शन पैरामीटर के नाम होने चाहिए।
यह बात `.c` और `.h`, दोनों तरह की फाइलों पर लागू होती है।
हर जगह एक ही नाम इस्तेमाल होना चाहिए।
यानी नीचे दिया गया फंक्शन प्रोटोटाइप मान्य C है, फिर भी यह स्टाइल गलत है क्योंकि इसमें पैरामीटर का नाम नहीं है: `void foo(int);`.
सही प्रोटोटाइप `void foo(int bar);` होगा, बशर्ते बाकी सारी घोषणाओं और परिभाषा में भी पैरामीटर का नाम `bar` हो।

जहाँ यह ज़्यादा आसान या ज़्यादा उपयुक्त हो, वहाँ पॉइंटर की जगह वैल्यू से आर्गुमेंट पास करने वाले पैरामीटर बेहतर माने जाते हैं।
खास ध्यान दीजिए कि इसमें `struct` टाइप के पैरामीटर भी शामिल हैं।

अगर यह उम्मीद न हो कि छात्र अपने इम्प्लीमेंटेशन में पॉइंटर-टाइप पैरामीटर की वैल्यू बदलेगा, तो उस पैरामीटर के साथ `const` लगाना चाहिए।

## फॉर्मेट

यह रिपॉज़िटरी `clang-format` टूल का इस्तेमाल करती है, जैसा [योगदान गाइड][contributing guide] में बताया गया है।

## टेस्ट फाइल का लेआउट

हर अभ्यास की टेस्ट फाइल एक खास लेआउट का पालन करती है।
इस लेआउट का उद्देश्य दोहरा है: यह कंट्रीब्यूटरों को फाइल के अलग-अलग हिस्से पहचानने में मदद करता है, और सीखने वालों को यह समझने में मदद करता है कि टेस्ट कैसे काम करते हैं।

C की ज़्यादातर सोर्स फाइलों की तरह, टेस्ट फाइल भी इन्क्लूड से शुरू होती है।

```c
#include "vendor/unity.h"
#include "../src/file_under_test.h"
// any other includes here
```

इन्क्लूड के बाद `setUp()` और `tearDown()` फंक्शन आते हैं।
अब तक कोई भी अभ्यास इनका इस्तेमाल नहीं करता (इन फंक्शन के शरीर खाली हैं), फिर भी इन्हें यहीं बना रहना चाहिए ताकि टेस्ट फाइलें हर प्लेटफॉर्म पर ठीक से कंपाइल हो सकें।

```c
void setUp(void)
{
}

void tearDown(void)
{
}
```

इसके बाद वे हेल्पर फंक्शन आते हैं जिन्हें टेस्ट फंक्शन इस्तेमाल करते हैं।
ऐसे हेल्पर फंक्शन के नाम के आगे `test_` प्रीफिक्स नहीं लगाना चाहिए।

इसके बाद खुद टेस्ट फंक्शन आते हैं।
इन फंक्शन के नाम में `test_` प्रीफिक्स लगता है।
पहले वाले को छोड़कर, हर टेस्ट फंक्शन का पहला स्टेटमेंट `TEST_IGNORE();` होना चाहिए।
इसके पहली बार आने के बाद लाइन कमेंट `// delete this line to run test` होना चाहिए।

उदाहरण के लिए:

```c
static void test_the_first(void)
{
   test_first_foo();
}

static void test_the_second(void)
{
   TEST_IGNORE();               // delete this line to run test
   test_second_foo();
}

static void test_the_third(void)
{
   TEST_IGNORE();
   char grade = 'A';
   test_third_foo(grade);
}
```

फाइल में सबसे अंत में `main()` फंक्शन आता है।
main के फंक्शन बॉडी का भी अपना एक खास लेआउट होता है।
सबसे पहले `UNITY_BEGIN()` को कॉल किया जाता है, उसके बाद एक खाली लाइन आती है, और फिर टेस्ट आते हैं।
अंतिम टेस्ट के बाद एक और खाली लाइन आती है, और उसके बाद `UNITY_END()` का नतीजा लौटाया जाता है।

```c
int main(void)
{
    UNITY_BEGIN();

    RUN_TEST(test_foo);
    RUN_TEST(test_bar);

    return UNITY_END();
}
```
