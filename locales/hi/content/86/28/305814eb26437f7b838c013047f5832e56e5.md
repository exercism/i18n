# परिचय

यह जानना कि किसी डेटा का टाइप क्या है, कोड को सुचारू रूप से और बिना एरर के चलाने के लिए अक्सर बहुत ज़रूरी होता है।

JavaScript में किसी वैल्यू या ऑब्जेक्ट का टाइप जाँचने के कई तरीके हैं।

```exercism/note
JavaScript के टाइप जाँचने के तरीके कुछ हद तक अविश्वसनीय हो सकते हैं।

बेहतर टाइप सुरक्षा और मज़बूत टाइप के लिए, आपको शायद TypeScript इस्तेमाल करना चाहिए। यह एक ऐसी भाषा है जो JavaScript पर बनी है, लेकिन इसका टाइप सिंटैक्स स्टैटिक-टाइप्ड भाषा जैसा है।
```

## `typeof` ऑपरेटर

`typeof` ऑपरेटर अपने ऑपरेंड का टाइप लौटाता है।
इसका आउटपुट एक स्ट्रिंग है जो किसी एक [प्रिमिटिव डेटा टाइप][primitives] के नाम से मेल खाती है, सिवाय `"null"` के।
यह `"function"` या `"object"` भी हो सकता है।

```javascript
typeof undefined;
// => "undefined"

typeof true;
// => "boolean"

typeof 42;
// => "number"

typeof 'Hello, World!';
// => "string"

typeof function () {
  return 'Hello, World';
};
// => "function"

typeof [1, 2, 3, 4];
// => "object"

typeof { city: 'Stockholm', country: 'Sweden' };
// => "object"
```

यह [ऐतिहासिक कारणों][`typeof null` is `"object"`] से ऐसा होता है।

## `instanceof` ऑपरेटर

किसी ऑब्जेक्ट का टाइप जाँचने के लिए आप `instanceof` ऑपरेटर इस्तेमाल कर सकते हैं।
इसका परिणाम एक `boolean` होता है, जो इस पर निर्भर करता है कि दूसरा ऑपरेंड पहले ऑपरेंड की [प्रोटोटाइप चेन][prototype chain] में शामिल है या नहीं।
स्पष्ट करने के लिए, `instanceof` बताता है कि पहला ऑपरेंड दूसरे ऑपरेंड का इंस्टेंस है या उसकी किसी चाइल्ड क्लास का।
`instanceof` सिर्फ ऑब्जेक्ट पर ही काम करता है।

```javascript
class Beverage {
  // ...
}

// The Coffee class is a child of the Beverage class.
class Coffee extends Beverage {
  // ...
}

const java = new Coffee();

java instanceof Coffee;
// => true

java instanceof Beverage;
// => true
```

````exercism/advanced
`Array` क्लास में `Array.isArray()` नाम का एक मेथड होता है, जो जाँचता है कि उसका आर्गुमेंट एक ऐरे है या नहीं।

हालाँकि `instanceof Array` किसी अलग रीयल्म में बनाए गए ऐरे के साथ काम नहीं करेगा, जैसे किसी वेब पेज के `iframe` में, लेकिन `Array.isArray()` करेगा।

इसका कारण यह है कि हर रीयल्म में Array क्लास का कंस्ट्रक्टर अलग होता है, और हर `iframe` का अपना रीयल्म होता है। इसका मतलब है कि प्रोटोटाइप चेन में फंक्शन अलग होगा, जिससे `instanceof Array` फेल हो जाता है।
`Array.isArray()` इस बात को नज़रअंदाज़ कर सकता है, और जहाँ संभव हो वहाँ इसे हमेशा इस्तेमाल करना चाहिए।

यह उन गलत पॉज़िटिव से भी बचा लेता है जहाँ कोई ऑब्जेक्ट वास्तव में `Array` नहीं है, बल्कि उसकी प्रोटोटाइप चेन में सिर्फ `Array` है।

```javascript
({ __proto__: Array.prototype }) instanceof Array
// => true

Array.isArray({ __proto__: Array.prototype })
// => false
```
````

## `in` ऑपरेटर

`in` ऑपरेटर बताता है कि पहला ऑपरेंड दूसरे ऑपरेंड की प्रॉपर्टी है या नहीं।
यह नहीं जाँचता कि उस प्रॉपर्टी की कोई परिभाषित वैल्यू है या नहीं।
`undefined` पर सेट की गई प्रॉपर्टी भी `in` से पकड़ में आ जाती है।

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
    this.isDarkMatter = undefined;
  }

  coolDown() {
    this.temperature = 'warm';
  }
}

const espresso = new Coffee();

'temperature' in espresso;
// => true

'color' in espresso;
// => false

'isDarkMatter' in espresso;
// => true
```

````exercism/note
`in` विरासत में मिली प्रॉपर्टी और मेथड के लिए भी `true` लौटाता है।

```javascript
"coolDown" in espresso
// => true

"constructor" in espresso
// => true
```
````

## `Object.hasOwn()` फंक्शन

`Object.hasOwn()` मेथड बताता है कि निर्दिष्ट ऑब्जेक्ट _दी गई प्रॉपर्टी का मालिक है_ या नहीं (यानी वह प्रॉपर्टी विरासत में नहीं मिली है और मेथड भी नहीं है)।

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
  }

  coolDown() {
    this.temperature = 'warm';
  }
}
const cappuccino = new Coffee();

Object.hasOwn(cappucino, 'temperature');
// => true

Object.hasOwn(cappucino, 'constructor');
// => false

Object.hasOwn(cappucino, 'coolDown');
// => false
```
