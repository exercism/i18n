# निर्देश परिशिष्ट

## Roc में बैंक खाते

Roc कोड में हम आम तौर पर बिज़नेस लॉजिक पर ध्यान देते हैं, जबकि कंकरेंसी और साझा स्थिति का काम प्लेटफॉर्म संभालता है।
इसलिए इस अभ्यास में आपको सिर्फ `BankAccount.roc` में खाते के ऑपरेशन लागू करने हैं; कंकरेंसी की चिंता आपको नहीं करनी।
खाते शुरू में बंद रहते हैं, दोबारा खोलने पर बैलेंस रीसेट हो जाता है, और जमा तथा निकासी की राशि धनात्मक होनी चाहिए।

## वैकल्पिक सर्वर डेमो

साथ दिया गया `bank-account-demo.roc` दिखाता है कि आपके कार्यान्वयन को एक छोटी वेब सर्विस में कैसे इस्तेमाल किया जा सकता है।
आप इसे एडिटर में पढ़ सकते हैं, लेकिन यह टेस्ट से अलग है और आपके हल का हिस्सा नहीं है।

डेमो चलाने के लिए आपको अपनी मशीन पर [Roc इंस्टॉल करना](https://www.roc-lang.org/install/) होगा, [Exercism CLI](https://exercism.org/cli-walkthrough) इंस्टॉल करना होगा, और फिर टर्मिनल में यह कमांड चलानी होगी:

```sh
exercism download --exercise=bank-account --track=roc
```

इसके बाद `BankAccount.roc` लागू कीजिए और नीचे दी गई कमांड से उसे टेस्ट कीजिए (अगर CLI जो डाउनलोड पाथ छापता है वह नीचे दिए पाथ से अलग हो, तो उसे बदल दीजिए):

```sh
cd ~/Exercism/roc/bank-account
roc test bank-account-test.roc
```

सारे टेस्ट पास हो जाने पर आप नीचे दी गई कमांड से डेमो सर्वर शुरू कर सकते हैं:

```sh
roc bank-account-demo.roc
```

यह सर्वर [basic-webserver प्लेटफॉर्म](https://github.com/roc-lang/basic-webserver) और उसके अंदर बने SQLite सपोर्ट का उपयोग करता है (Roc पहली बार चलाने पर प्लेटफॉर्म डाउनलोड कर लेता है)।
किसी अलग डेटाबेस सर्वर की ज़रूरत नहीं है।
सर्वर `http://127.0.0.1:8000` पर सुनता है और आपकी मौजूदा डायरेक्टरी में `bank-account-demo.db` बना देता है (अलग डेटाबेस फाइल इस्तेमाल करने के लिए `DB_PATH` सेट कीजिए)।
सर्वर को Ctrl-C दबाकर रोकिए।
डेटा रीस्टार्ट के बाद भी बना रहता है।

किसी दूसरे टर्मिनल में आप `curl` से वेबसर्विस को कॉल कर सकते हैं (Windows पर PowerShell के `curl` एलियस से बचने के लिए हर जगह `curl.exe` इस्तेमाल कीजिए)।
उदाहरण के लिए, खाता #123 खोलने, 50 जमा करने, 10 निकालने और उसका बैलेंस देखने का तरीका यह है:

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/open
curl -X POST http://127.0.0.1:8000/accounts/123/deposit/50
curl -X POST http://127.0.0.1:8000/accounts/123/withdraw/10
curl http://127.0.0.1:8000/accounts/123/balance
```

बैलेंस `40` होगा।
खाता ID और राशियाँ अनसाइन्ड पूर्णांक होनी चाहिए।
अपडेट सफल होने पर `OK` लौटाते हैं, और असफल होने पर आपके खाता कार्यान्वयन से मिली एरर लौटाते हैं।
खाता #123 बंद करने के लिए:

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/close
```

Linux/macOS पर एक साथ कई अनुरोध आज़माने के लिए नया खाता ID लीजिए और आठ क्लाइंट से 100 जमा भेजिए:

```sh
curl -X POST http://127.0.0.1:8000/accounts/456/open
seq 100 | xargs -P 8 -I '{}' curl --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1
curl http://127.0.0.1:8000/accounts/456/balance
```

Windows पर समानांतर उदाहरण के लिए [PowerShell 7+](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows) इस्तेमाल कीजिए:

```powershell
curl.exe -X POST http://127.0.0.1:8000/accounts/456/open
1..100 | ForEach-Object -Parallel { curl.exe --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1 } -ThrottleLimit 8
curl.exe http://127.0.0.1:8000/accounts/456/balance
```

सारी जमा सफल होनी चाहिए और बैलेंस `100` होना चाहिए।

## डेमो कंकरेंसी को कैसे संभालता है

हर अनुरोध खाते को पढ़ता है, आपके Roc फंक्शन कॉल करता है, और नतीजे को एक SQLite `Immediate` ट्रांजैक्शन के अंदर सहेज देता है।
असफल ऑपरेशन खाते को बदले बिना पहले जैसी स्थिति में लौट जाते हैं।
SQLite एक समय में एक ही लिखने वाले को अनुमति देता है, जिससे एक साथ आए अनुरोध एक-दूसरे के अपडेट पर नहीं लिख पाते (अलग-अलग खातों के मामले में भी)।

ध्यान दें: अभ्यास `U64` इस्तेमाल करता है, लेकिन डेमो बैलेंस को SQLite पूर्णांक के रूप में संग्रहीत करता है और `I64` की अधिकतम वैल्यू (`9223372036854775807`) से बड़े अपडेट अस्वीकार कर देता है।

समानांतर में स्वतंत्र गणनाएँ चलाने का उदाहरण देखने के लिए [parallel-letter-frequency अभ्यास](https://exercism.org/tracks/roc/exercises/parallel-letter-frequency) आज़माइए।
