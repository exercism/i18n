# संकेत
`Either` का एक आम उपयोग ऐसी गणना दिखाना है जिसके परिणामस्वरूप एरर मिल सकती है (अगर असली एरर में कोई दिलचस्पी न हो, तो सरल `Option` टाइप बेहतर विकल्प हो सकता है)।
एरर न होने पर परिणाम आम तौर पर `Right` होता है (याद रखने का तरीका: यह "सही" वैल्यू है), जबकि एरर होने पर `Left`, जैसे कि एरर संदेश वाला `Left[String]`।
ध्यान दीजिए कि Scala 2.12 में `Either` डिफ़ॉल्ट रूप से राइट-बायस्ड होता है, इसलिए यह `filter`, `map`, `flatMap` जैसे ऑपरेशनों में या किसी for-कॉम्प्रिहेंशन में अपेक्षा के अनुसार काम करता है।
अगर आप `Either` से परिचित नहीं हैं, तो आप [यह ट्यूटोरियल](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html) पढ़ सकते हैं। लेकिन ध्यान रखिए कि यह ट्यूटोरियल 2.12 से पहले के Scala वर्शनों के बारे में है। Scala 2.12 में आप `RightProjection` को बेझिझक नज़रअंदाज़ कर सकते हैं और `.right` हटा सकते हैं।
`Either` को [मोनैड](https://en.wikipedia.org/wiki/Monad_(functional_programming)) कहा जाता है, जो एक "गणना संबंधी पहलू" को कवर करता है, इस मामले में एरर हैंडलिंग।
मोनैड का सही उपयोग बहुत संक्षिप्त, फिर भी सुंदर और पढ़ने योग्य कोड दे सकता है। गलत उपयोग से आसानी से उल्टा नतीजा मिल सकता है।
और जानने के लिए [यह वीडियो](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) देखिए।
## आम गलतियाँ जिनसे बचना चाहिए
`Either` के लिए कुछ व्यावहारिक नियम हैं:
1. अगर ज़रूरत नहीं है, तो `Either` का उपयोग न कीजिए। इसके बजाय
```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```
बेहतर यह होगा
```scala
def add1(x: Int): Int = x + 1
```
(ऐसे सरल फंक्शन लगाने के लिए `Either.map` मौजूद है, इसलिए उन्हें `Either` से भरने की ज़रूरत नहीं पड़ती)।
2. अगर वाकई ज़रूरत न हो, तो "अनरैप" न कीजिए।
अक्सर आपके उद्देश्य के लिए बिल्ट-इन फंक्शन मौजूद होते हैं। समय से पहले अनरैप करने के संकेत `isLeft/isRight` या पैटर्न मैचिंग हैं। उदाहरण के लिए, इसके बजाय
```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```
बेहतर यह होगा
```scala
x fold (identity, _ + 1)
```
3. मोनैड को किसी for-कॉम्प्रिहेंशन के अंदर इस्तेमाल करना भी बढ़िया तरीका है।
जब आप कई `Either` इंस्टेंस को "जोड़ना" चाहते हैं, तब यह करना बेहतर होता है। इसके बजाय
```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```
बेहतर यह होगा
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
