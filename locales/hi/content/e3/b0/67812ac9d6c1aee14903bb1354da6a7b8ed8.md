# विवरण

Factor में डेटा भेजने का एक ही तरीका है: *डेटा स्टैक*। वर्ड अपना इनपुट स्टैक से हटा लेते हैं और अपना आउटपुट स्टैक पर रख देते हैं। हर वर्ड की परिभाषा एक *स्टैक इफेक्ट* भी घोषित करती है, जो इस करार को लिखित रूप में बताता है।

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

`( … -- … )` के अंदर लिखे नाम पढ़ने वाले की सुविधा के लिए हैं। कंपाइलर सिर्फ यह जाँचता है कि इनपुट और आउटपुट की *संख्या* ठीक है। इनमें मेल न खाना कंपाइल के समय ही एरर बन जाता है, और इससे ऐसी गलतियाँ पकड़ में आ जाती हैं जो इस तरह की घोषणा न रखने वाली डायनामिक टाइपिंग वाली भाषा में रनटाइम एरर बनतीं।

स्टैक में हर चीज़ अपनी जगह के हिसाब से रखी जाती है, इसलिए अगला वर्ड चलने से पहले आपको उसका ऊपरी हिस्सा बार-बार बदलना पड़ता है। `kernel` के **शफल वर्ड** यही काम करते हैं:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

शफल वर्ड का पूरा परिवार इनसे आगे जाता है: `-rot` (उलटी दिशा में घुमाना), `d` लगे रूप जो एक चीज़ और गहराई तक काम करते हैं (`dupd`, `swapd`), `2` लगे रूप जो जोड़ों पर काम करते हैं (`2dup`, `2drop`, `2nip`), और `pick` व `tuck` जैसे कुछ और वर्ड। ये तब आते हैं जब आगे के अभ्यासों में उनकी ज़रूरत पड़ती है। एक साथ ढेर सारे शफल वर्ड उठा लेना आम तौर पर इस बात का संकेत है कि *लोकल* (नाम वाली वैल्यू) ज़्यादा साफ़ पढ़ी जाती।

आम परंपरा यह है कि वर्ड के नाम `lowercase-kebab-case` में लिखे जाते हैं, प्रेडिकेट `?` पर खत्म होते हैं और बूलियन देते हैं (`even?`, `empty?`), सेटर `>>name` की तरह और गेटर `name>>` की तरह लिखे जाते हैं, और कई बार एक वर्ड और उसका बदलाव करने वाला रूप एक ही नाम रखते हैं, जिनमें फ़र्क सिर्फ संदर्भ से पता चलता है।
