# ट्रेट

ट्रेट मेथड का एक समूह तय करता है, जिन्हें कोई टाइप लागू कर सकता है।
ट्रेट तब काम आते हैं जब हमें ऐसे मेथड बनाने हों जो कई टाइप के बीच साझा हों।
जब ट्रेट का उपयोग जेनेरिक टाइप के साथ किया जाता है, तो परिभाषित मेथड को किसी खास टाइप पर कॉल किया जा सकता है, और दूसरे डेटा टाइप पर भी कॉल किया जा सकता है।
अमूर्त रूप से कहें तो, _ट्रेट बाउंड्स_ की मदद से हम यह तय कर सकते हैं कि जेनेरिक टाइप में कोई खास व्यवहार ज़रूर होना चाहिए।

> **नोट:** ट्रेट की सुविधा दूसरी प्रोग्रामिंग भाषाओं के इंटरफेस जैसी होती है, बस कुछ अंतरों के साथ।

## ट्रेट की परिभाषा

ट्रेट परिभाषित करने से हमें उन फंक्शन सिग्नेचर की पहचान होती है जो मिलकर वह व्यवहार बनाते हैं जिसे कोई टाइप लागू कर सकता है।
ये मेथड मिलकर किसी टाइप का व्यवहार बनाते हैं।
अगर हम अलग-अलग टाइप पर एक ही मेथड कॉल कर सकते हैं, तो इसका मतलब है कि उन टाइप का व्यवहार एक जैसा है।

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

ऊपर दी गई `Summary` ट्रेट की परिभाषा के मुताबिक, `summarize` एक ऐसा व्यवहार है जिसे सिर्फ `NewsArticle` स्ट्रक्ट टाइप ही कॉल कर सकता है।
किसी दूसरे टाइप के इंस्टेंस पर इसे कॉल करने पर कंपाइलेशन एरर मिलती है।
`pub` कीवर्ड के साथ ट्रेट घोषित करने से यह ट्रेट इस क्रेट में उन दूसरे क्रेट के लिए भी उपलब्ध हो जाता है जो इसका उपयोग करना चाहते हैं।
यह भी ध्यान दीजिए कि ट्रेट में मेथड सिग्नेचर घोषित करने के बाद सेमीकॉलन लगाया जाता है।

किसी ट्रेट को जेनेरिक आर्गुमेंट के साथ परिभाषित किया जा सकता है, जिससे कोई फंक्शन किसी भी डेटा टाइप का आर्गुमेंट ले सकता है।
इससे फंक्शन सिग्नेचर में लचीलापन आता है और वे तरह-तरह के डेटा टाइप संभाल सकते हैं।
नीचे दिए गए `Summary` ट्रेट को इस तरह फिर से बनाया गया है कि वह किसी भी डेटा टाइप के लिए काम करे, और जब उस पर `summarize` मेथड कॉल किया जाए तो वह एक ByteArray लौटाता है।

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

एक ट्रेट के अंदर एक से ज़्यादा मेथड हो सकते हैं।
हर घोषित मेथड सिग्नेचर एक ही लाइन का होता है और सेमीकॉलन पर खत्म होता है।

## किसी टाइप पर ट्रेट लागू करना

ट्रेट बनाने वाले फंक्शन सिग्नेचर परिभाषित करने के बाद कंपाइलर यह सुनिश्चित करता है कि जो टाइप इस ट्रेट को अपनाते हैं, उनके लिए इम्प्लीमेंटेशन भी ठीक से परिभाषित हो।
नीचे हमने एक मीडिया `aggregator` लाइब्रेरी क्रेट लिखी है, जो `NewsArticle` और `Tweet` के इंस्टेंस से कुछ डेटा का सारांश बनाती है।
`NewsArticle` स्ट्रक्ट के लिए हम `Summary` ट्रेट के `summarize` मेथड की वैल्यू लौटाने के लिए शीर्षक, लेखक और स्थान का उपयोग करेंगे।
वहीं `Tweet` स्ट्रक्ट के लिए हम यूज़रनेम और कंटेंट का उपयोग करेंगे, यह मानते हुए कि ट्वीट के कंटेंट की सीमा 280 अक्षर है।

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## डिफॉल्ट इम्प्लीमेंटेशन

कभी-कभी किसी ट्रेट को उसके कुछ या सभी मेथड के लिए डिफॉल्ट इम्प्लीमेंटेशन के साथ परिभाषित किया जा सकता है।
इससे हर टाइप पर सभी मेथड का इम्प्लीमेंटेशन लिखने की ज़रूरत नहीं पड़ती और कोड पढ़ने में भी आसान रहता है।
अगर किसी खास टाइप को ट्रेट के किसी मेथड का विशेष इम्प्लीमेंटेशन चाहिए, तो वह डिफॉल्ट इम्प्लीमेंटेशन को ओवरराइड कर सकता है।

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## बाहरी ट्रेट का उपयोग और प्रबंधन

ट्रेट और इम्प्लीमेंटेशन किसी बाहरी मॉड्यूल में परिभाषित किए जा सकते हैं और दूसरे मॉड्यूल में उपयोग किए जा सकते हैं, लेकिन इसके लिए उन्हें ठीक से इम्पोर्ट करना ज़रूरी है।
मान लीजिए हमारे पास एक `ShapeGeometry` ट्रेट है, जिसमें `boundary` मेथड है और इसे `Circle` तथा `Rectangle` दोनों स्ट्रक्ट के लिए लागू करना ज़रूरी है।
नीचे एक उदाहरण है जिसमें दिखाया गया है कि ट्रेट और उसके इम्प्लीमेंटेशन को अलग-अलग मॉड्यूल में कैसे इम्पोर्ट, प्रबंधित और उपयोग किया जाता है।

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

`CircleGeometry` और `RectangleGeometry` दोनों की विजिबिलिटी सार्वजनिक होने की ज़रूरत नहीं है, क्योंकि `ShapeGeometry` ट्रेट सार्वजनिक बनाया गया है और कंपाइलर को वह आसानी से मिल जाना चाहिए।

## impl एलियस

इम्प्लीमेंटेशन को इम्पोर्ट करते समय `impl` कीवर्ड का उपयोग करके एलियस बनाया जा सकता है।
यह तब काम आता है जब किसी कंक्रीट टाइप के लिए जेनेरिक इम्प्लीमेंटेशन बनाना हो।
चलिए, उन सभी टाइप के लिए `Two` ट्रेट का एक साधारण इम्प्लीमेंटेशन बनाते हैं जो `One` ट्रेट लागू करते हैं; इसमें `One` की वैल्यू को दो बार जोड़कर योग लौटाया जाता है।
इसके बाद हम `Two` का वह इम्प्लीमेंटेशन सामने ला सकते हैं जो सिर्फ `u8` और `u128` टाइप के लिए काम करता है।

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

जेनेरिक इम्प्लीमेंटेशन को किसी प्राइवेट मॉड्यूल में लिखा जा सकता है, और impl एलियस की मदद से हम इन दोनों कंक्रीट टाइप के लिए जेनेरिक इम्प्लीमेंटेशन बना सकते हैं।
प्राइवेट और बाहर से छिपे जेनेरिक इम्प्लीमेंटेशन का फायदा यह है कि इससे अलग-अलग फाइलों में एक ही कोड दोहराने की ज़रूरत नहीं पड़ती।
इससे सार्वजनिक API भी सरल और साफ रहता है।
