# परिचय

[`Basics`][basics] कॉन्सेप्ट में फंक्शन बनाने के दो तरीके बताए गए थे।

सबसे आम तौर पर, कई लाइनों वाला रूप:

```julia
function muladd(x, y, z)
    x * y + z
end
```

छोटी परिभाषाओं के लिए "असाइनमेंट" या "सिंगल-लाइन" रूप:
```julia
muladd(x, y, z) = x * y + z
```

तीसरे और इससे भी छोटे रूप में, छोटा और सिर्फ एक बार इस्तेमाल होने वाला फंक्शन बिना नाम के बनाया जा सकता है:

```julia-repl
julia> map(x -> 2x, 1:3)
4-element Vector{Int64}:
 2
 4
 6

julia> map((x, y) -> x * y, 1:3, 4:6)
3-element Vector{Int64}:
  4
 10
 18
```

यहाँ `x -> 2x` एक "एनोनिमस फंक्शन" है।
यह वही चीज़ है जिसे कुछ अन्य भाषाएँ "लैम्ब्डा फंक्शन" कहती हैं।

ध्यान दीजिए कि कई आर्गुमेंट के लिए गोल ब्रैकेट ज़रूरी होते हैं, जैसे `(x, y) -> x * y` में।

एनोनिमस फंक्शन Julia कोड में आम हैं, खास तौर पर जब इन्हें `map()` और `filter()` जैसे हायर-ऑर्डर फंक्शन के साथ इस्तेमाल किया जाता है (इन पर आगे किसी कॉन्सेप्ट में और विस्तार से बात की जाएगी)।

```julia-repl
julia> map(x -> x^4, [1, 2, 3])
3-element Vector{Int64}:
  1
 16
 81
```

## फंक्शन आर्गुमेंट

अब तक सिलेबस में हमने सिर्फ ऐसे फंक्शन देखे हैं जिनमें आर्गुमेंट की एक तय संख्या होती है, और फंक्शन कॉल करते समय उन सभी को सही क्रम में देना ज़रूरी होता है।
यह सीमित और असुविधाजनक होगा, इसलिए कुछ और विकल्प भी हैं।

### वैकल्पिक आर्गुमेंट

कई अन्य भाषाओं की तरह, Julia में फंक्शन बनाते समय अलग-अलग आर्गुमेंट के लिए डिफ़ॉल्ट वैल्यू दी जा सकती है।

इसके बाद फंक्शन कॉल या तो उस आर्गुमेंट के लिए कोई वैल्यू दे सकती है, या उसे छोड़कर डिफ़ॉल्ट पर भरोसा कर सकती है।

```julia-repl
julia> f(x, y=10) = x * y
f (generic function with 2 methods)

julia> f(2, 3)
6

julia> f(2)
20
```

डिफ़ॉल्ट _बिना_ वाले सभी आर्गुमेंट, डिफ़ॉल्ट _वाले_ किसी भी आर्गुमेंट से पहले आने चाहिए, यानी `f(x=2, y)` अमान्य होगा।

### कीवर्ड आर्गुमेंट

अब तक के सभी उदाहरण `positional arguments` इस्तेमाल करते हैं, जहाँ फंक्शन कॉल में दी गई वैल्यू को फंक्शन की परिभाषा में उनसे जुड़े आर्गुमेंट के क्रम से मेल खाना चाहिए।

कई अन्य भाषाओं की तरह, Julia भी `keyword arguments` की अनुमति देती है।
फंक्शन कॉल में आर्गुमेंट का नाम बताना ज़रूरी होता है, लेकिन फिर कई कीवर्ड आर्गुमेंट किसी भी क्रम में दिए जा सकते हैं।

Julia की एक खास बात यह है कि फंक्शन की परिभाषा में कीवर्ड आर्गुमेंट (अगर कोई हों) से पहले सेमीकोलन `;` लगाना ज़रूरी होता है, ताकि वे पोज़िशनल आर्गुमेंट से अलग हो जाएँ।
फंक्शन कॉल में अंतिम पोज़िशनल आर्गुमेंट और पहले कीवर्ड आर्गुमेंट के बीच `;` या `,` दोनों में से कोई भी इस्तेमाल किया जा सकता है।

```julia-repl
julia> b(x; y) = x + y
b (generic function with 1 method)

julia> b(2, y=3)
5

# keyword is required when calling
julia> b(2, 3)
ERROR: MethodError: no method matching b(::Int64, ::Int64)
The function `b` exists, but no method is defined for this combination of argument types.
```

डिफ़ॉल्ट वैल्यू भी दी जा सकती हैं, ठीक पोज़िशनल आर्गुमेंट की तरह।

फंक्शन कॉल के अंदर `myarg=myarg` जैसा सिंटैक्स बन जाना आम बात है, तब जब पैरामीटर के समान नाम वाला वेरिएबल पहले से निकाल लिया गया हो।
ऐसी स्थिति में संक्षिप्त सिंटैक्स की अनुमति होती है:

```julia-repl
julia> width = 4.0
4.0

julia> height = √ width
2.0

julia> area(; width, height) = width * height
area (generic function with 1 method)

# repetition
julia> area(; width=width, height=height)
8.0

# shorthand form
julia> area(; width, height)
8.0
```

### स्प्लैट और स्लर्प

ये Julia सिंटैक्स के एक काम के पहलू के मानक नाम हैं, अगर आप जानना चाहें।
दोनों `...` ऑपरेटर की ओर इशारा करते हैं।

#### स्प्लैट

फंक्शन _कॉल_ करते समय स्प्लैटिंग इस्तेमाल होती है, ताकि किसी संग्रह को उन अलग-अलग वैल्यू में फैलाया जा सके जो फंक्शन माँगता है।

इसे समझाने से ज़्यादा दिखाना आसान होगा:

```julia-repl
julia> fxyz(x, y, z) = x * y * z
fxyz (generic function with 1 method)

julia> xyz = [2, 3, 4]
3-element Vector{Int64}:
 2
 3
 4

# Using the vector directly in a function call is invalid
julia> fxyz(xyz)
ERROR: MethodError: no method matching fxyz(::Vector{Int64})
The function `fxyz` exists, but no method is defined for this combination of argument types.

# splatting converts the vector to 3 numbers, used as positional arguments
julia> fxyz(xyz...)
24
```

कुछ "फंक्शन कॉल" सिंटैक्टिक शुगर के पीछे छिपी होती हैं, इसलिए स्प्लैटिंग का इस्तेमाल कम स्पष्ट तरीकों से भी हो सकता है।

उदाहरण के लिए, मल्टीपल असाइनमेंट अंदर ही अंदर एक टपल कंस्ट्रक्टर फंक्शन इस्तेमाल करता है:

```julia-repl
julia> first, rest... = [1, 2, 3, 4]
4-element Vector{Int64}:
 1
 2
 3
 4

julia> first
1

julia> rest
3-element Vector{Int64}:
 2
 3
 4
```

कीवर्ड आर्गुमेंट भी स्प्लैटिंग से दिए जा सकते हैं, आम तौर पर `named tuple` इस्तेमाल करके। 
`Dict` भी काम करेगा, लेकिन उसकी की सिंबल होनी चाहिए (स्ट्रिंग नहीं चलेंगी)।

```julia-repl
# function with 3 keyword arguments
julia> fabc(; a, b, c) = a + b + c
fabc (generic function with 1 method)

# named tuple
julia> abc_nt = (a=2, b=3, c=4)
(a = 2, b = 3, c = 4)

# there are no positional arguments, so need to use ; before kw argument
julia> fabc(;abc_nt...)
9

# Dict
julia> abc_dict = Dict(:a=>2, :b=>3, :c=>4)
Dict{Symbol, Int64} with 3 entries:
  :a => 2
  :b => 3
  :c => 4

julia> fabc(;abc_dict...)
9
```

#### स्लर्प

स्लर्पिंग का इस्तेमाल फंक्शन की _परिभाषा_ में होता है, ताकि किसी भी संख्या में अलग-अलग वैल्यू को एक संग्रह में भरा जा सके।

```julia-repl
julia> f_more(i, j, more...) = i + j + sum(more)
f_more (generic function with 1 method)

julia> f_more(1, 3, 5, 7, 9, 11)
36
```

स्लर्प किए गए आर्गुमेंट का नाम (यहाँ `more`) मायने नहीं रखता।
इस वेरिएबल का टाइप कंपाइलर तय करता है, लेकिन पोज़िशनल आर्गुमेंट के मामले में यह आम तौर पर `tuple` या उसी जैसा कुछ होता है।

कीवर्ड आर्गुमेंट को भी स्लर्प किया जा सकता है, जिससे एक `Dict` (या उसी जैसा कुछ) मिलता है।

```julia-repl
julia> f_kwslurp(x, y; switches...) = :mult in keys(switches) ? x * y : x + y
f_kwslurp (generic function with 1 method)

julia> f_kwslurp(5, 6; mult=true)
30

julia> f_kwslurp(5, 6)
11
```

कॉल में कोई भी कीवर्ड आर्गुमेंट इस्तेमाल किए जा सकते हैं।
यह तय करना फंक्शन की परिभाषा का काम है कि किन कीवर्ड पर जवाब देना है और किन्हें नज़रअंदाज़ करना है।
