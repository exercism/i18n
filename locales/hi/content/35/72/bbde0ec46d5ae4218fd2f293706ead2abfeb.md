# लूप

**लूप** एक ही काम बार-बार करता है।

```sather
   loop
      ...
   end;
```

अकेला लूप कभी नहीं रुकता, इसलिए इसके अंदर कुछ ऐसा होना चाहिए जो इसे रोक दे।

## गिनती रखने की जगह

लूप को लगभग हमेशा एक ऐसी वैल्यू चाहिए जो चलते-चलते बदलती रहे। यही **वेरिएबल** है, और `::=` से एक बनता है:

```sather
   total ::= 0;
```

इस वेरिएबल का नाम `total` है, यह `0` से शुरू होता है, और Sather `0` को देखकर समझ लेता है कि इसमें एक `INT` रखा है। इसके बाद `:=` इसमें नई वैल्यू डालता है:

```sather
   total := total + 5;
```

इसे दाएँ से बाएँ पढ़िए: `total` में अभी जो वैल्यू है उसे लीजिए, उसमें 5 जोड़िए, और जवाब को वापस `total` में रख दीजिए।

इस तरह बनाया गया वेरिएबल रूटीन के खत्म होने तक रहता है।

## until!

`until!` एक सवाल लेता है। लूप के हर चक्कर में यह सवाल पूछा जाता है, और जब जवाब सही होता है तो लूप वहीं तुरंत रुक जाता है।

```sather
   sum_to(last : INT) : INT is
      total ::= 0;
      n ::= 1;
      loop
         until!(n > last);
         total := total + n;
         n := n + 1;
      end;
      return total;
   end;
```

`n` गिनती करता है 1, 2, 3 ... और जैसे ही `n` पहली बार `last` से आगे निकलता है, लूप खत्म हो जाता है। अगर `n := n + 1` न हो, तो सवाल का जवाब कभी नहीं बदलेगा और लूप हमेशा के लिए चलता रहेगा।

`until!` का पहली लाइन में होना ज़रूरी नहीं है। इसे वहाँ रखिए जहाँ सवाल का मतलब बनता हो: ऊपर रखने पर लूप शायद एक बार भी न चले; नीचे रखने पर यह हमेशा कम से कम एक बार चलता है।

`!` नाम का ही हिस्सा है। Sather कुछ चीज़ों को इस तरह चिह्नित करता है; इस चिह्न का मतलब आगे बताया जाएगा।

## break!

`break!` लूप को तुरंत खत्म कर देता है, बिना किसी सवाल के। यह तब काम आता है जब रुकने की वजह काम के बीच में निकलती है।

```sather
   loop
      if too_far then break!; end;
      ...
   end;
```

`until!` और `break!` का मतलब सिर्फ `loop` के अंदर ही है। इनमें से कोई भी अकेले इस्तेमाल नहीं किया जा सकता।
