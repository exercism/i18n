# परिचय

Gleam में `case` एक्सप्रेशन की मदद से कोड को शर्त के अनुसार चलाया जा सकता है। case एक्सप्रेशन से एक वैल्यू का मिलान एक या अधिक _पैटर्न_ से किया जा सकता है। ऐसे पैटर्न का एक उदाहरण _लिटरल पैटर्न_ है, जो किसी वैल्यू का मिलान किसी लिटरल वैल्यू (जैसे `1` या `"hello"`) से करता है।

case एक्सप्रेशन `case` कीवर्ड से लिखे जाते हैं:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    1 -> "One"
  }
}
```

हालाँकि यह दूसरी भाषाओं के `switch` स्टेटमेंट जैसा लग सकता है, लेकिन पैटर्न मैचिंग की असली खूबी तब सामने आती है जब दूसरे पैटर्न भी इस्तेमाल किए जाएँ। ऐसा ही एक पैटर्न _वेरिएबल पैटर्न_ है, जिससे किसी वेरिएबल को एक वैल्यू असाइन की जा सकती है। इस उदाहरण में, अगर `number` की वैल्यू `0` नहीं है, तो वेरिएबल `i` को उसकी वैल्यू असाइन कर दी जाएगी:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i -> "Non zero"
  }
}
```

कुछ मामलों में आप किसी पैटर्न में एक और शर्त जोड़ना चाह सकते हैं। इसे _गार्ड_ (क्लॉज़) कहा जाता है, जिसे `if` कीवर्ड की मदद से जोड़ा जा सकता है:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
  }
}
```

परफॉर्मेंस के कारण गार्ड में सिर्फ बुनियादी गणितीय और बूलियन ऑपरेटर इस्तेमाल किए जा सकते हैं; गार्ड में दूसरे फंक्शन इस्तेमाल नहीं किए जा सकते।

ऊपर के उदाहरण में, हर संभव इनपुट के लिए मेल खाता पैटर्न नहीं होगा। कंपाइलर इसे पहचान लेगा और एक एरर दिखाएगा। इसे _एक्सहॉस्टिव चेकिंग_ कहा जाता है। इस चेतावनी को दूर करने के लिए सभी मामलों को संभालना पड़ता है। इसके लिए _डिस्कार्ड पैटर्न_ इस्तेमाल किया जा सकता है, जो किसी भी वैल्यू से मेल खाता है:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
    _ -> "Positive number"
  }
}

// No compiler error
```

case एक्सप्रेशन एक वैल्यू को ऊपर से नीचे तक एक-एक पैटर्न से जाँचता है। जैसे ही कोई मेल खाता पैटर्न मिलता है, वह उस पैटर्न से जुड़ा कोड चला देता है। पैटर्न का क्रम मायने रखता है!
