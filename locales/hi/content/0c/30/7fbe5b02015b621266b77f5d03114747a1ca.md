# परिचय

JavaScript में एक अंतर्निहित ऑब्जेक्ट `Date` होता है, जो तारीख और समय संग्रहीत करता है और उनके प्रबंधन के लिए मेथड देता है।

<!-- prettier-ignore -->
~~~exercism/caution
यह Java की `java.util.Date` क्लास पर आधारित था, जिसे 2010 के दशक की शुरुआत में बदल दिया गया, लेकिन बैकवर्ड कंपैटिबिलिटी के लिए JavaScript का `Date` अब भी बना हुआ है।

सामान्य रूप से तारीखों के साथ काम करना कितना कठिन है, और टाइमज़ोन संभालना कितना खराब या लगभग अनुपस्थित है, इन्हीं वजहों से `moment.js`, `day.js`, `date-fns` और `luxon` जैसी बहुत सी लाइब्रेरी मौजूद हैं।
इनमें से कोई भी Exercism पर उपलब्ध नहीं है।

अपने प्रोजेक्ट में `moment.js` जैसे पुराने या बिना देखरेख वाले पैकेज का इस्तेमाल न कीजिए, बल्कि `luxon` जैसे ज़्यादा आधुनिक विकल्पों पर भरोसा कीजिए, या उस [Temporal][mdn-temporal] पर जो अभी व्यापक रूप से उपलब्ध नहीं है।
यह अभ्यास `Date` पर केंद्रित है, जो JavaScript के अंत तक प्रासंगिक बना रहेगा।

## बनाना

एक `Date` ऑब्जेक्ट, `Date` क्लास का एक इंस्टेंस होता है।
इसे कंस्ट्रक्टर फंक्शन को कोई आर्गुमेंट पास किए बिना बनाया जा सकता है।
इससे एक ऐसा `Date` ऑब्जेक्ट बनता है जो वर्तमान तारीख और समय दर्शाता है:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### Unix टाइमस्टैम्प (संख्या)

अगर कोई संख्या पास की जाती है, तो उसे `timestamp` के रूप में समझा जाएगा।
टाइमस्टैम्प एक पूर्णांक संख्या है, जो **1 जनवरी 1970 [UTC][defn-utc]+0** से अब तक बीते **मिलीसेकंड** की संख्या बताता है।

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

कोई यह उम्मीद कर सकता है कि `new Date(0)` सबसे "शुरुआती" तारीख ऑब्जेक्ट बनाएगा, लेकिन JavaScript तारीख को आपके स्थानीय टाइमज़ोन में बदल देता है। इसका मतलब है कि वास्तव में केवल वही लोग [Unix epoch][defn-unix-epoch] वैल्यू पाएँगे जिनका टाइमज़ोन [GMT / UTC+0][defn-gmt] के आसपास है।

### ISO 8601 टाइमस्टैम्प (स्ट्रिंग)

आप `Date` कंस्ट्रक्टर को तारीख दर्शाने वाली एक स्ट्रिंग वैल्यू पास कर सकते हैं।
हर इम्प्लीमेंटेशन में एक जैसा रहने वाला **एकमात्र** फॉर्मेट अंतरराष्ट्रीय स्तर पर मान्यता प्राप्त और मानकीकृत तथाकथित [ISO 8601 टाइमस्टैम्प स्ट्रिंग][defn-iso8601] का [सरलीकृत रूप][mdn-date-string-format] है।

[UTC][defn-gmt] में समय का एक क्षण ऐसा दिखता है:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

जहाँ निम्नलिखित प्रतिस्थापन होते हैं:

| कुंजी | विवरण                                            | डिफ़ॉल्ट |
| ---- | ------------------------------------------------ | ------- |
| YYYY | कैलेंडर वर्ष, 4 अंकों में                        |         |
| MM   | कैलेंडर महीना, 2 अंकों में                       | 01      |
| DD   | कैलेंडर दिन, 2 अंकों में                         | 01      |
| T    | शाब्दिक अक्षर T, जो तारीख और समय को अलग करता है  | T       |
| HH   | 24 घंटे की घड़ी में घंटे, 2 अंकों में            | 00      |
| mm   | मिनट, 2 अंकों में                                | 00      |
| ss   | सेकंड, 2 अंकों में                               | 00      |
| mss  | मिलीसेकंड, 3 अंकों में                           | 000     |
| Z    | शाब्दिक अक्षर Z, या `+/-HH:mm` का ऑफ़सेट         |         |

शाब्दिक अक्षर `Z` UTC दर्शाता है (कोई टाइमज़ोन नहीं, कोई डेलाइट सेविंग नहीं)।

क्योंकि अधिकांश कंपोनेंट के लिए डिफ़ॉल्ट वैल्यू होती हैं, इसलिए अंत से कुछ हिस्से हटा देना भी सही है:

```text
YYYY-MM-DD
```

डिफ़ॉल्ट समय 00:00:00.000 होता है।

अगर टाइमस्टैम्प `Z` पर खत्म नहीं होता, और `+HH:mm` या `-HH:mm` (जो टाइमज़ोन ऑफ़सेट दर्शाते हैं) पर भी खत्म नहीं होता, तो ऐतिहासिक कारणों से यह नियम लागू होता है:

> जब टाइम ज़ोन ऑफ़सेट मौजूद नहीं होता, तो केवल तारीख वाले रूप UTC समय के रूप में समझे जाते हैं और तारीख-समय वाले रूप स्थानीय समय के रूप में।
> UTC समय के रूप में समझे जाने की वजह एक ऐतिहासिक स्पेक त्रुटि है, जो ISO 8601 के अनुरूप नहीं थी, लेकिन वेब कंपैटिबिलिटी के कारण उसे बदला नहीं जा सका।
> देखिए [Broken Parser – A Web Reality Issue][ref-broken-parser]।

### तारीख ऑब्जेक्ट

किसी मौजूदा तारीख ऑब्जेक्ट को भी कंस्ट्रक्टर आर्गुमेंट के रूप में इस्तेमाल किया जा सकता है।
इससे मौजूदा `Date` ऑब्जेक्ट की एक प्रति बनती है, जिसमें वही तारीख और समय होता है।

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### तारीख और समय के अलग-अलग कंपोनेंट की वैल्यू देना

तारीख दर्शाने वाला ऑब्जेक्ट तीन संख्याएँ पास करके बनाया जा सकता है।
तारीख और समय दर्शाने वाला ऑब्जेक्ट 6 संख्याएँ पास करके बनाया जा सकता है।

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

दूसरी वैल्यू `month` है, जो जनवरी के लिए `0` से शुरू होकर दिसंबर के लिए `11` तक जाती है।

## `Date.parse()`

आपको कहीं तारीख पार्स करने वाले फंक्शन `Date.parse` का उल्लेख या संदर्भ मिल सकता है।
क्योंकि इस फंक्शन के लिए केवल कुछ ही अपरिवर्तनीय नियम (यानी हमेशा सच रहने वाली बातें) हैं, और बाकी इम्प्लीमेंटेशन निर्दिष्ट नहीं है (और इसलिए मानक भी नहीं), इसलिए इसका उपयोग नहीं करना चाहिए।

## `Date` के कंपोनेंट एक्सेस करना

तारीख ऑब्जेक्ट पर कई मेथड होते हैं जो तारीख के कंपोनेंट लौटाते हैं:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

इनमें से हर एक के लिए वैल्यू अपडेट करने वाला एक संबंधित `set` रूप भी होता है (जैसे `setFullYear`)।
सीमा से बाहर जाने वाली कोई भी वैल्यू अगले कंपोनेंट में चली जाती है:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

उन सभी मेथड के लिए UTC रूप भी हैं जो स्थानीय टाइमज़ोन को अनदेखा करते हैं।

## तारीख से कन्वर्ट करना

तारीख ऑब्जेक्ट में एक मेथड `getTime()` होता है जो UNIX टाइमस्टैम्प मिलीसेकंड में लौटाता है, यानी 1 जनवरी 1970 UTC की आधी रात से अब तक बीते मिलीसेकंड की संख्या।
इसके अलावा, तारीख ऑब्जेक्ट को ISO 8601 टाइमस्टैम्प स्ट्रिंग में बदलने के लिए एक मेथड `toISOString()` भी उपलब्ध है।

## तारीखों की तुलना

बड़ा है (`>`) और बड़ा या बराबर है (`>=`), तथा छोटा है (`<`) और छोटा या बराबर है (`<=`), इनका इस्तेमाल सीधे दो तारीखों के बीच या एक तारीख और एक संख्या के बीच किया जा सकता है।
यह इसलिए काम करता है क्योंकि JavaScript तारीख को एक प्रिमिटिव में बदलने की कोशिश करता है।

<!-- prettier-ignore -->
~~~exercism/advanced
जब दो तारीखों के बीच या एक तारीख और एक संख्या के बीच तुलना की जाती है, तो JavaScript [`[Symbol.toPrimitive]("number")`][mdn-to-primitive] को कॉल करता है, जो अंदर से [`date.valueOf()`][mdn-date-value-of] को कॉल करता है।
यह दूसरा वाला [`date.getTime()`][mdn-date-get-time] को कॉल करने जैसा ही है।

अगर आप इस व्यवहार पर निर्भर नहीं रहना चाहते, तो पहले `getTime()` का इस्तेमाल करके संख्या में बदल लीजिए।
