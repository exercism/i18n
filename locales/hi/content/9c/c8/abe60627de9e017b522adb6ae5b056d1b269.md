# और जानकारी

एक [लूप][control] निर्देशों का ऐसा क्रम है जिसे अंत की शर्त पूरी होने तक एक से अधिक बार चलाया जा सकता है।

x86-64 में लूप आम तौर पर पिछले लेबल पर जंप लगाकर बनाया जाता है:

```x86asm
example_loop:
    ...
    jmp example_loop
```

ध्यान दीजिए कि पिछले लेबल पर बिना शर्त का जंप हमेशा निष्पादन को उसी लेबल पर भेज देता है।
इसका मतलब है कि लूप हमेशा के लिए दोहराता रहेगा, जब तक कि दोहराए जा रहे क्रम से बाहर जाने वाला कोई दूसरा जंप न हो।

उदाहरण के लिए, यह लूप कभी खत्म नहीं होता:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

और यह लूप खत्म हो सकता है, यह इस बात पर निर्भर करता है कि शर्त पूरी होती है या नहीं:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## गिनती वाले लूप

गिनती करने वाला लूप लगभग हमेशा एक ही तरह से खत्म होता है: काउंटर को बदलने वाला या दो वैल्यू की तुलना करने वाला निर्देश, और ठीक उसके बाद एक शर्त वाला जंप, जो तय करता है कि एक और चक्कर लगाना है या नहीं।

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
ऊपर दिए गए कोड में `cmp rsi, 0` की ज़रूरत नहीं है, क्योंकि परिणाम `0` होने पर `sub rsi, 1` पहले ही `zero flag (ZF)` सेट कर देता है।

हालाँकि असेंबली में शर्तें जाँचने का मुख्य तरीका `cmp` ही है, फिर भी बहुत से निर्देश फ्लैग बदल देते हैं।
उदाहरण के लिए, पूर्णांक पर गणित करने वाले या बिटवाइज़ काम करने वाले कई निर्देश परिणाम `0` होने पर `ZF` बदल देते हैं, और परिणाम ऋणात्मक होने पर `SF` (यानी सबसे ऊपर वाला बिट सेट हो)।

कौन-सा निर्देश किन फ्लैग को बदलता है, यह देखने के लिए आप [रेफरेंस][reference] देख सकते हैं।

[reference]: https://www.felixcloutier.com/x86/
~~~~

ध्यान दीजिए कि ऊपर के उदाहरण में मान लिया गया है कि `rsi` `0` से बड़ा है।
अगर यह `0` होता, तो `sub rsi, 1` `rsi` को `-1` तक घटा देता, जो बिना चिह्न वाली बहुत बड़ी संख्या होती।
लूप अंततः खत्म होने से पहले और `18,446,744,073,709,551,615` इटरेशन लगते।
साथ ही, ऐरे की लंबाई `0` होने के कारण मेमोरी का कोई भी एक्सेस ऐरे की सीमा से बाहर चला जाता।

अगर ऐरे की लंबाई के बारे में कोई निश्चितता न हो, तो आम तौर पर दो तरीके अपनाए जाते हैं।

पहले तरीके में अंत की शर्त को लूप की शुरुआत में ले जाया जाता है, और लूप के अंत में बिना शर्त का जंप रखा जाता है:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

दूसरे तरीके में लूप शुरू होने से पहले एक बार जाँच लिया जाता है कि ऐरे की लंबाई शून्य तो नहीं:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

यह दूसरा तरीका आम तौर पर पहले वाले से ज़्यादा कारगर होता है, क्योंकि लूप के अंदर ब्रांच कम होती हैं।
इसके बारे में आप आगे आने वाले किसी कॉन्सेप्ट में और जानेंगे।

## माइक्रो-ऑप्स

प्रोसेसर `add` या `jnz` जैसे किसी निर्देश को सीधे नहीं चलाता।
CPU का फ्रंट-एंड पहले हर निर्देश को एक या अधिक छोटे आंतरिक चरणों में _डिकोड_ करता है, जिन्हें **माइक्रो-ऑपरेशन** (या **माइक्रो-ऑप्स**) कहते हैं।
इसके बाद प्रोसेसर इन माइक्रो-ऑप्स को क्रम में लगाता है और निष्पादित करता है, अक्सर एक चक्र में कई और अपने मूल क्रम से अलग।

ज़्यादातर सरल निर्देश एक ही माइक्रो-ऑप में डिकोड होते हैं, जबकि कोई जटिल निर्देश कई माइक्रो-ऑप्स में डिकोड हो सकता है।
चूँकि प्रोसेसर का वास्तविक काम माइक्रो-ऑप्स की धारा है, इसलिए एक ही काम के लिए कम माइक्रो-ऑप बनाना कोड को तेज़ करने का एक तरीका है।

## मैक्रोफ्यूज़न

जैसा पहले बताया गया, लूप आम तौर पर किसी शर्त वाले जंप के साथ खत्म होता है।
यह इतना आम है कि आधुनिक प्रोसेसर डिकोडिंग के दौरान इस पैटर्न के लिए खास तौर पर तैयार किए जाते हैं।

फ्लैग सेट करने वाले निर्देश के ठीक बाद अगर उन्हीं फ्लैग को पढ़ने वाला शर्त वाला जंप आए, तो दोनों मिलकर **एक ही** माइक्रो-ऑप में डिकोड हो सकते हैं, अलग-अलग एक-एक की जगह।
इसे **मैक्रोफ्यूज़न** कहते हैं।

जुड़ी हुई यह जोड़ी एक ही ऑपरेशन की तरह व्यवहार करती है: काउंटर बदलना और ब्रांच का फैसला, दोनों एक ही माइक्रो-ऑप में साथ-साथ होते हैं।
तब लूप का कंट्रोल फ्लो, लूप जो काम वास्तव में करता है उसके ऊपर लगभग कुछ नहीं जोड़ता।

मोटे तौर पर, दो तरह की जोड़ियाँ आम तौर पर इस तरह जुड़ जाती हैं:

- `add` या `sub` जैसे गणित के निर्देश, जिनके ठीक बाद शर्त वाला जंप आता है।
- `cmp`, `test` या `and`, जिनके ठीक बाद शर्त वाला जंप आता है।

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

फ्यूज़न तभी होता है जब शर्त वाला जंप फ्लैग सेट करने वाले निर्देश के **ठीक बाद** आए, बीच में कुछ भी न हो।

~~~~exercism/note
मैक्रोफ्यूज़न CPU पर निर्भर करता है, और कौन-से निर्देश किस शर्त वाले जंप के साथ जुड़ते हैं, इसमें कुछ अंतर होता है।

एक उपयोगी रेफरेंस है [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]।
Intel CPUs के लिए जुड़ने वाली जोड़ियों की सूची [Intel optimization reference manual][intel-opt] के सेक्शन 3.4.2.2 (Optimizing for Macrofusion) में भी दी गई है।

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## `loop` निर्देश

कुछ निर्देश ऐसे हैं जिनसे लूप जैसा व्यवहार बनाया जा सकता है।
इनमें से एक है [loop][loop]।

इसका एकमात्र ऑपरेंड एक लेबल होता है, जिसमें लूप के शुरू होने का एड्रेस होता है।

`loop` निर्देश `rcx` की वैल्यू को काउंटर की तरह इस्तेमाल करता है और हर बार उसे 1 से घटाता है।
जैसे ही `rcx` की वैल्यू शून्य तक पहुँचती है, लूप खत्म हो जाता है और निष्पादन क्रम से आगे बढ़ता रहता है:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

`loop` निर्देश के दो रूप हैं, जो हर इटरेशन में ज़ीरो फ्लैग (`ZF`) की जाँच करते हैं।
`rcx` के शून्य तक पहुँचने पर लूप रोकने के अलावा, ये तब भी रुक जाते हैं जब शर्त _न_ पूरी हो।

| निर्देश           | शर्त      |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

`ZF` **इन निर्देशों से सेट नहीं होता**।
इनसे पहले `cmp`, `test` या `ZF` बदलने वाला कोई और निर्देश होना चाहिए:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
सुविधाजनक होने के बावजूद, आधुनिक प्रोसेसर पर `loop`, `loope` और `loopne` आम तौर पर उनके बराबर वाले `sub`/`jnz` या `cmp`/`jnz` क्रम से कहीं ज़्यादा धीमे होते हैं।

कई अलग-अलग CPUs पर निर्देशों के प्रदर्शन के बारे में एक अच्छा रेफरेंस [Agner's tables][agner-tables] है।

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
~~~~
