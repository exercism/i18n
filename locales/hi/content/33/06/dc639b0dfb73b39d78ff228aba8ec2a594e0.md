# परिचय

F# में [`list`][lists] शून्य या उससे अधिक वैल्यू का एक इम्यूटेबल कलेक्शन होता है। किसी ऐरे में सभी वैल्यू का टाइप एक ही होना चाहिए। चूँकि ऐरे इम्यूटेबल होते हैं, एक बार ऐरे बन जाने के बाद उसकी वैल्यू कभी नहीं बदल सकती। F# के ऐरे में एक _हेड_ (पहला एलिमेंट) और एक _टेल_ (पहले एलिमेंट के बाद आने वाली सभी वैल्यू) होते हैं। किसी ऐरे का टेल खुद भी एक ऐरे ही होता है।

ऐरे इस तरह बनाए जा सकते हैं:

```fsharp
let empty = []
let emptyAlternative = List.empty

let singleValue = [5]
let singleValueAlternative = List.singleton 5

let threeValues = ["a"; "b"; "c"]
```

किसी ऐरे में एलिमेंट जोड़ने का सबसे आम तरीका `::` (कॉन्स) ऑपरेटर है:

```fsharp
let twoToFour = [2; 3; 4]
let oneToFour = 1 :: twoToFour
// => [1; 2; 3; 4]
```

ऐरे को `@` ऑपरेटर या `List.append` की मदद से भी जोड़ा जा सकता है:

```fsharp
[6; 7] @ [8; 9]           // => [6; 7; 8; 9]
List.append [6; 7] [8; 9] // => [6; 7; 8; 9]
```

ऐरे को [`List` मॉड्यूल][list-module] में परिभाषित फंक्शन और ऑपरेटर संभालते हैं। इनमें से कुछ फंक्शन किसी `list` इंस्टेंस की [प्रॉपर्टी][list-properties] के रूप में भी उपलब्ध होते हैं:

```fsharp
List.length [7; 8] // => 2
[7; 8].Length      // => 2
```

यहाँ कोई विकल्प सही या गलत नहीं है। आम तौर पर `List` मॉड्यूल के फंक्शन टाइप इन्फरेंस के साथ बेहतर चलते हैं, जबकि प्रॉपर्टी की मदद से कोड ज़्यादा संक्षिप्त लिखा जा सकता है।

जो फंक्शन या ऑपरेटर ऐरे को बदलते दिखाई देते हैं (जैसे एलिमेंट जोड़ना), वे वास्तव में एक नया ऐरे लौटाते हैं। हालाँकि परफॉर्मेंस आम तौर पर कोई समस्या नहीं होती, क्योंकि ऐरे का इम्प्लीमेंटेशन बेवजह एलोकेशन और कॉपी रोकता है।

चूँकि ऐरे सिंगली लिंक्ड लिस्ट के रूप में इम्प्लीमेंट किए जाते हैं, किसी एलिमेंट को सबसे आगे जोड़ना (`::` ऑपरेटर से) बहुत तेज़ है, जबकि इंडेक्स से कोई एलिमेंट निकालना शायद काफी धीमा हो सकता है।

ऐरे को [_list_][list-pattern] और [_cons_][cons-pattern] पैटर्न के ज़रिए पैटर्न मैचिंग से भी प्रोसेस किया जा सकता है:

```fsharp
let describe list =
    match list with
    | [] -> "Empty list"
    | [ 1 ] -> "Singleton list with 1"
    | head::tail -> sprintf "Non-empty list with head: %d" head

describe []        // => "Empty list"
describe [1]       // => "Singleton list with 1"
describe [5; 7; 9] // => "Non-empty with head: 5"
```

[lists]: https://docs.microsoft.com/en-us/dotnet/fsharp/language-reference/lists
[list-module]: https://fsharp.github.io/fsharp-core-docs/reference/fsharp-collections-listmodule.html
[list-properties]: https://docs.microsoft.com/en-us/dotnet/fsharp/language-reference/lists#properties
[cons-pattern]: https://docs.microsoft.com/en-us/dotnet/fsharp/language-reference/pattern-matching#cons-pattern
[list-pattern]: https://docs.microsoft.com/en-us/dotnet/fsharp/language-reference/pattern-matching#list-pattern

पैटर्न मैचिंग करते समय आप किसी वैल्यू को _छोड़_ भी सकते हैं; जब किसी खास केस में आपको किसी वैल्यू की परवाह न हो (यानी आप उस वैल्यू का _उपयोग_ नहीं करने वाले हैं), तो यह बताने के लिए आप अंडरस्कोर (`'_'`) इस्तेमाल कर सकते हैं:

```fsharp
let describe list =
    match list with
    | [] -> "Empty list"
    | [x] -> "List with one item"
    | [_; y] -> "List with two items (first item ignored)"
    | _ -> "List with many items (all items ignored)"

describe []        // => "Empty list"
describe [1]       // => "List with one item"
describe [5; 7]     // => "List with two items (first item ignored)"
describe [5; 7; 9] // => "List with many items (all items ignored)"
```

पैटर्न मैचिंग में अकेला `'_'` हमेशा _सबसे अंत में_ आना चाहिए; जो भी वैल्यू बाकी किसी भी केस से मैच नहीं करती, उसे यही केस संभाल लेता है।
