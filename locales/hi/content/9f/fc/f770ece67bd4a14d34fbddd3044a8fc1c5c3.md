# अक्षरों के बारे में

यह विषय काफी _बड़ा_ हो सकता है!
इस पर एक लंबी किताब लिखी जा सकती है, और कई लोगों ने ऐसा किया भी है (कुछ उदाहरण देखने के लिए Amazon पर "unicode book" खोजिए)।

## एक बहुत संक्षिप्त इतिहास

पुराने दशकों में कंप्यूटर में अक्षरों को संभालना कहीं ज़्यादा आसान था, जब प्रोग्रामर मानते थे कि अंग्रेज़ी ही एकमात्र ज़रूरी भाषा है।
तो यह था: 26 अक्षर, बड़े और छोटे रूपों में, 10 अंक, कुछ विराम चिह्न, और घंटी बजाने के लिए एक कोड (0x07)। यह सब 7 बिट में समा जाता था: [ASCII][wiki-ascii] अक्षर सेट।

स्वाभाविक रूप से, लोग पूछने लगे कि à, ä और Ł का क्या होगा; फिर दूसरे लोग पूछने लगे कि ऄ, ஹ और ญ का क्या होगा; और युवाओं को इमोजी 😱 चाहिए थे।
अब क्या किया जाए?

लंबी कहानी छोटी करें तो, कई बुद्धिमान और धैर्यवान लोगों को सालों तक समितियों में काम करना पड़ा, ताकि [Unicode][web-unicode] अक्षर सेट और [UTF-8][wiki-utf-8] जैसी एनकोडिंग के ब्यौरे तय हो सकें; और बहुत सारे सॉफ्टवेयर को _बहुत_ जटिल तरीके से दोबारा लिखने की ज़रूरत पड़ी।
साथ ही, बहुत सारे नए बग पैदा हो गए।

सब कुछ टूटने से बचाने के लिए, Unicode/UTF-8 का डिज़ाइन यह सुनिश्चित करता है कि पहले 127 कोड ASCII जैसे ही हों _(घंटी वाला कोड भी)_।

## Kotlin में अक्षर

2005 के करीब के बाद बनी भाषाओं के पास यह बड़ा फायदा था कि तब तक Unicode का एक काफी स्थिर मानक मौजूद था।

Kotlin (जो पहली बार 2011 में जारी हुई थी) यह मान सकती थी कि उपयोगकर्ता अलग-अलग (मानव) भाषाएँ इस्तेमाल करेंगे और उन्हें व्यक्त करने के लिए Unicode की ज़रूरत होगी।

~~~~exercism/advanced
Kotlin में [अक्षर][ref-char] 16-बिट (UTF-16) [`codepoints`][wiki-codepoint] होते हैं, ठीक वैसे ही जैसे JVM का `char`।
यह ज़्यादातर लिखित वर्णमालाओं को व्यक्त करने के लिए काफी है, लेकिन इमोजी की पूरी श्रृंखला के लिए नहीं।

पूरा Unicode मानक हर अक्षर के लिए अधिकतम छह बाइट (48 बिट) इस्तेमाल करता है (जिसे [`grapheme`][wiki-grapheme] कहते हैं)।

Kotlin की `Strings` ज़रूरत पड़ने पर हर अक्षर के लिए कई कोडपॉइंट इस्तेमाल करके इस पूरे मानक का समर्थन करती हैं।
उदाहरण के लिए, 😱 `\uD83D` और `\uDE31` होगा।

दुर्भाग्य से, Java में ग्राफीम का कोई बिल्ट-इन समर्थन नहीं है, और अनुकूलता के लिए Kotlin में भी नहीं।

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


अक्षर लिटरल सिंगल कोट्स में लिखे जाते हैं, और डबल कोट्स में लिखी स्ट्रिंग से अलग होते हैं।
C/C++ की दुनिया से आने वालों के लिए यह शायद साफ है, लेकिन Python और JavaScript प्रोग्रामर के लिए भ्रमित करने वाला हो सकता है।

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

`Char` और `Int` के बीच बदलना सीधा-सादा है:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

कंपाइलर `Char` पर पूर्णांक गणित के _कुछ_ रूपों की अनुमति देता है:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## `Char` के लिए कुछ फंक्शन

हमेशा की तरह, यहाँ चर्चा करने के लिए [बहुत सारे फंक्शन][ref-char-lib] हैं, इसलिए यह सिर्फ एक चयन है।

- जिन वर्णमालाओं पर लागू हो, उनमें [`uppercase()`][ref-uppercase] और [`lowercase()`][ref-lowercase] से केस बदलिए।
- [`isUpperCase()`][ref-isuppercase] और [`isLowerCase()`][ref-islowercase] से केस जाँचिए।
- अक्षर का प्रकार इनसे जाँचिए:
  - [`isLetter()`][ref-isletter], कई वर्णमालाओं को कवर करता है (unicode की Lu, Ll, Lt, Lm और Lo श्रेणियाँ)
  - [`isDigit()`][ref-isdigit], 0..9 की सीमा में (unicode की Nd श्रेणी)
  - `isLetterOrDigit()`, पिछले दो को जोड़ता है
  - [`isWhitespace()`][ref-iswhitespace], कोई भी व्हाइटस्पेस अक्षर (unicode की Cc, Zp, Zl और Zs श्रेणियाँ)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

साथ ही, [रेगुलर एक्सप्रेशन][ref-regex] (जो आगे आने वाले किसी कॉन्सेप्ट का विषय होंगे) शक्तिशाली खोज और बदलाव की सुविधा देते हैं।

## Char ऐरे और स्ट्रिंग के आपसी रूपांतरण

किसी `String` को `Char` के `List` में बदलने के लिए हम `toList()` इस्तेमाल कर सकते हैं।

`Char` के `List` को `String` में बदलने के लिए [`joinToString()`][ref-jointostring] फंक्शन है, जो एक सेपरेटर (अक्सर खाली स्ट्रिंग) को आर्गुमेंट के रूप में लेता है।

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

ध्यान दीजिए कि `joinToString()` किसी ऐरे पर काम करता है।
किसी एक `Char` को 1 अक्षर की स्ट्रिंग में _बदलने_ के लिए `toString()` इस्तेमाल कीजिए।

```kotlin
'a'.toString() // => "a"
```

यह जाँचने के लिए कि कोई अक्षर किसी `String` में, या `Char` के ऐरे में मौजूद है या नहीं, हमारे पास `in` है, जो [`contains()`][ref-contains] फंक्शन से जुड़ा है।

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
