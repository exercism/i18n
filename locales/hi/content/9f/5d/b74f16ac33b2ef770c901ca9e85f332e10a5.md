# स्ट्रिंग बिल्डर

`STR` को बदला नहीं जा सकता; `FSTR` को बदला जा सकता है। तैयार हो चुके टेक्स्ट के लिए `STR` इस्तेमाल कीजिए, और अभी बन रहे टेक्स्ट के लिए `FSTR`।

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## परिणाम हमेशा वापस असाइन कीजिए

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR` **एमॉर्टाइज़्ड डबलिंग** से बढ़ता है: जब उसमें जगह खत्म हो जाती है, तो वह एक नया और बड़ा ऐरे ले लेता है, जो पिछले से दोगुना होता है, और उसमें सब कॉपी कर देता है। इसलिए परिणाम आमतौर पर वही ऑब्जेक्ट होता है, और कभी-कभी कोई दूसरा। हर बार `b := b + x` लिखना दोनों ही स्थितियों में सही है, और सीखने लायक यही एकमात्र रूप है।

डबलिंग ही कुल काम को लंबाई के वर्ग के बजाय लंबाई के अनुपात में रखती है: कॉपियाँ जितनी तेज़ी से महँगी होती जाती हैं, उतनी ही तेज़ी से कम भी होती जाती हैं।

## `STR` पर सिर्फ `+` क्यों नहीं इस्तेमाल करें?

कुछ ही तय टुकड़ों को `+` से जोड़ना साफ़ और ठीक है:

```sather
   return piece + " by " + composer;
```

दिक्कत सिर्फ लूप में है, जहाँ कोड लिखते समय यह पता नहीं होता कि कितनी बार जोड़ना पड़ेगा। मोटा-मोटा नियम: अगर `+` किसी `loop` के अंदर हो, तो `FSTR` का सहारा लीजिए।

## उपयोगी रूटीन

| कॉल | क्या करता है |
| --- | --- |
| `b + x` | जोड़ता है; `x` कुछ भी हो सकता है, `STR`, `CHAR`, `INT`, `BOOL` … |
| `b.size` | अब तक कितने अक्षर हैं |
| `b.str` | तैयार `STR` |
| `b.clear` | इसे खाली करता है, जगह बरकरार रखते हुए |

## एस्केप

| लिखा जाता है | मतलब |
| --- | --- |
| `"\n"` | नई लाइन |
| `"\t"` | एक टैब |
| `"\""` | डबल कोट |
| `"\\"` | बैकस्लैश |
