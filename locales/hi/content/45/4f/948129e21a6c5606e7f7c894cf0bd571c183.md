# परिचय

JavaScript में एक अंतर्निहित ऑब्जेक्ट `Date` मौजूद है, जो दिनांक और समय संग्रहीत करता है और उन्हें संभालने के लिए मेथड देता है।

<!-- prettier-ignore -->
~~~exercism/caution
यह Java की `java.util.Date` क्लास पर आधारित था, जिसे 2010 के दशक की शुरुआत में बदल दिया गया, लेकिन बैकवर्ड कंपैटिबिलिटी के लिए JavaScript का `Date` अब भी बना हुआ है।

सामान्य तौर पर `Date` के साथ काम करना जितना मुश्किल है, और टाइमज़ोन संभालना जितना खराब या लगभग अनुपलब्ध है, उसकी वजह से `moment.js`, `day.js`, `date-fns` और `luxon` जैसी बहुत सारी लाइब्रेरी मौजूद हैं।
इनमें से कोई भी Exercism पर उपलब्ध नहीं है।

अपने प्रोजेक्ट में `moment.js` जैसा अप्रचलित या बिना रखरखाव वाला पैकेज इस्तेमाल न कीजिए, बल्कि `luxon` जैसे ज़्यादा आधुनिक विकल्पों पर भरोसा कीजिए, या उस [Temporal][mdn-temporal] पर जो अभी व्यापक रूप से उपलब्ध नहीं है।
यह अभ्यास `Date` पर केंद्रित है, जो JavaScript के अंत तक प्रासंगिक बना रहेगा।

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal
~~~

## निर्माण

`Date` ऑब्जेक्ट `Date` क्लास का एक इंस्टेंस होता है।
इसे कंस्ट्रक्टर फंक्शन को कोई आर्गुमेंट दिए बिना बनाया जा सकता है।
इससे एक ऐसा `Date` ऑब्जेक्ट बनता है जो मौजूदा दिनांक और समय दर्शाता है:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### Unix टाइमस्टैम्प (संख्या)

अगर कोई संख्या दी जाए, तो उसे `timestamp` के रूप में समझा जाता है।
टाइमस्टैम्प एक पूर्णांक होता है जो बताता है कि **1 जनवरी 1970 [UTC][defn-utc]+0** से अब तक कितने **मिलीसेकंड** बीत चुके हैं।

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

कोई सोच सकता है कि `new Date(0)` सबसे "शुरुआती" दिनांक वाला ऑब्जेक्ट बनाएगा, लेकिन JavaScript उस दिनांक को आपके स्थानीय टाइमज़ोन में बदल देता है। इसका मतलब है कि वास्तव में [GMT या UTC+0][defn-gmt] टाइमज़ोन वाले इलाकों में ही लोगों को [Unix epoch][defn-unix-epoch] वाली वैल्यू मिलेगी।

### ISO 8601 टाइमस्टैम्प (स्ट्रिंग)

आप `Date` कंस्ट्रक्टर को दिनांक दर्शाने वाली स्ट्रिंग वैल्यू दे सकते हैं।
दुनिया भर में मान्यता प्राप्त और मानकीकृत तथाकथित [ISO 8601 टाइमस्टैम्प स्ट्रिंग][defn-iso8601] होती है। हर इम्प्लीमेंटेशन में एक जैसा रहने वाला **एकमात्र** फॉर्मेट उसका [सरलीकृत रूप][mdn-date-string-format] है।

[UTC][defn-gmt] में कोई समय-बिंदु ऐसा दिखता है:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

इसमें नीचे दिए विकल्प रखे जाते हैं:

| कुंजी | विवरण                                   | डिफ़ॉल्ट |
| ---- | --------------------------------------------- | ------- |
| YYYY | कैलेंडर वर्ष, 4 अंकों में    |         |
| MM   | कैलेंडर महीना, 2 अंकों में   | 01      |
| DD   | कैलेंडर दिन, 2 अंकों में     | 01      |
| T    | एक वास्तविक अक्षर T, जो दिनांक को समय से अलग करता है |         |
| HH   | 24 घंटे की घड़ी के घंटे, 2 अंकों में        | 00      |
| mm   | मिनट, 2 अंकों में                         | 00      |
| ss   | सेकंड, 2 अंकों में                        | 00      |
| mss  | मिलीसेकंड, 3 अंकों में                    | 000     |
| Z    | एक वास्तविक अक्षर Z, या कोई ऑफ़सेट `+/-HH:mm`   |         |

वास्तविक अक्षर `Z` UTC को दर्शाता है (कोई टाइमज़ोन नहीं, कोई डेलाइट सेविंग नहीं)।

चूँकि ज़्यादातर हिस्सों की डिफ़ॉल्ट वैल्यू होती है, अंत से कुछ हिस्से हटा देना भी मान्य है:

```text
YYYY-MM-DD
```

डिफ़ॉल्ट समय 00:00:00.000 रहता है।

अगर टाइमस्टैम्प `Z` पर खत्म नहीं होता, और `+HH:mm` या `-HH:mm` (यानी टाइमज़ोन ऑफ़सेट) पर भी खत्म नहीं होता, तो ऐतिहासिक कारणों से यह नियम लागू होता है:

> जब टाइमज़ोन ऑफ़सेट मौजूद न हो, तो सिर्फ़ दिनांक वाले रूप UTC समय माने जाते हैं और दिनांक-समय वाले रूप स्थानीय समय माने जाते हैं।
> UTC समय के रूप में यह व्याख्या एक ऐतिहासिक स्पेक त्रुटि की वजह से है, जो ISO 8601 से मेल नहीं खाती थी, लेकिन वेब कंपैटिबिलिटी की वजह से उसे बदला नहीं जा सका।
> देखिए [Broken Parser – A Web Reality Issue][ref-broken-parser]।

### Date ऑब्जेक्ट

किसी मौजूदा दिनांक ऑब्जेक्ट को भी कंस्ट्रक्टर आर्गुमेंट की तरह इस्तेमाल किया जा सकता है।
इससे मौजूदा `Date` ऑब्जेक्ट की एक कॉपी बनती है, जिसमें वही दिनांक और समय होता है।

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### दिनांक और समय के अलग-अलग हिस्सों की वैल्यू देना

सिर्फ़ दिनांक दर्शाने वाला ऑब्जेक्ट तीन संख्याएँ देकर बनाया जा सकता है।
दिनांक और समय दर्शाने वाला ऑब्जेक्ट 6 संख्याएँ देकर बनाया जा सकता है।

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

दूसरी वैल्यू `month` होती है, जो जनवरी के लिए `0` से शुरू होकर दिसंबर के लिए `11` तक जाती है।

## `Date.parse()`

आपको कहीं-कहीं दिनांक पार्स करने वाले फंक्शन `Date.parse` का ज़िक्र या संदर्भ मिल सकता है।
इस फंक्शन के लिए सिर्फ़ कुछ ही अपरिवर्तनीय नियम (सच्चाइयाँ) तय हैं और बाकी इम्प्लीमेंटेशन तय नहीं है (और इसलिए मानक भी नहीं), इसलिए इसका उपयोग नहीं करना चाहिए।

## `Date` के हिस्सों तक पहुँचना

दिनांक ऑब्जेक्ट पर कई मेथड होते हैं, जो दिनांक के अलग-अलग हिस्से लौटाते हैं:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

इनमें से हर एक का एक मिलता-जुलता `set` रूप भी होता है (जैसे `setFullYear`), जिससे वैल्यू अपडेट की जा सकती है।
सीमा से बढ़ी हुई कोई भी वैल्यू अगले हिस्से में चली जाती है:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

उन सभी मेथड के लिए UTC रूप भी हैं, जो स्थानीय टाइमज़ोन को नज़रअंदाज़ करते हैं।

## दिनांक से दूसरे रूप में बदलना

`Date` ऑब्जेक्ट में एक मेथड `getTime()` होता है, जो UNIX टाइमस्टैम्प मिलीसेकंड में लौटाता है, यानी 1 जनवरी 1970 की मध्यरात्रि (UTC) से अब तक बीते मिलीसेकंड।
इसके अलावा, दिनांक ऑब्जेक्ट को ISO 8601 टाइमस्टैम्प स्ट्रिंग में बदलने के लिए `toISOString()` मेथड भी उपलब्ध है।

## दिनांकों की तुलना

दो दिनांकों के बीच, या किसी दिनांक और संख्या के बीच, सीधे बड़ा-से (`>`) और बड़ा-या-बराबर (`>=`) तथा छोटा-से (`<`) और छोटा-या-बराबर (`<=`) का उपयोग किया जा सकता है।
यह इसलिए काम करता है क्योंकि JavaScript दिनांक को किसी प्रिमिटिव में बदलने की कोशिश करता है।

<!-- prettier-ignore -->
~~~exercism/advanced
दो दिनांकों के बीच, या किसी दिनांक और संख्या के बीच तुलना करते समय JavaScript [`[Symbol.toPrimitive]("number")`][mdn-to-primitive] को कॉल करता है, जो अंदर से [`date.valueOf()`][mdn-date-value-of] को कॉल करता है।
यही बात [`date.getTime()`][mdn-date-get-time] को कॉल करने पर भी लागू होती है।

अगर आप इस व्यवहार पर निर्भर नहीं रहना चाहते, तो पहले `getTime()` से दिनांक को संख्या में बदल लीजिए।

[mdn-to-primitive]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/Symbol.toPrimitive

[mdn-date-get-time]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/getTime
~~~

समानता (`==` और `===`) से दिनांकों की तुलना नहीं की जा सकती, लेकिन `.getTime()` के नतीजे की की जा सकती है।
