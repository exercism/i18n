# अनदेखा कीजिए

## jq के लिए अतिरिक्त कमांड लाइन विकल्प

टेस्ट में आपको `jq` के लिए कुछ अतिरिक्त विकल्प दिखाई देंगे।

```sh
run jq -s -R -c -f flower-field.jq << 'END_INPUT'
```

ये क्या हैं?

- `-s`

  यह "स्लर्प" मोड है।
  इनपुट को JSON ऑब्जेक्ट की स्ट्रीम की तरह संभालने के बजाय,
  पूरा इनपुट एक ऐरे में डाल दिया जाता है।

  ```sh
  $ seq 5 | jq -c '.'
  1
  2
  3
  4
  5
  $ seq 5 | jq -s -c '.'
  [1,2,3,4,5]
  ```

- `-R`

  आपने `-r` शायद पहले देखा होगा, जो "रॉ" स्ट्रिंग आउटपुट करता है (कोट के बिना)।
  यह उसका उल्टा है।
  इनपुट की हर लाइन को एक स्ट्रिंग माना जाता है।

  दो उदाहरण:

  ```sh
  $ seq 5 | jq -R -c .
  "1"
  "2"
  "3"
  "4"
  "5"

  $ echo 42 | jq '. * 2'      # input is a JSON number
  84
  $ echo 42 | jq -R '. * 2'   # input is a JSON string
  "4242"
  ```

जब आप इन दोनों विकल्पों को साथ इस्तेमाल करते हैं, तो आपको स्ट्रिंग का ऐरे _नहीं_ मिलता। पूरा इनपुट एक ही स्ट्रिंग के रूप में मिलता है, जिसमें लाइन के अंत के न्यूलाइन भी शामिल होते हैं।

```sh
$ seq 5 | jq -s -R -c .
"1\n2\n3\n4\n5\n"
```

इसे संभालना इस अभ्यास की चुनौती का हिस्सा है।
