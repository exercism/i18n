# परिचय

तटीय गश्ती पोत पर सवार एक *सिग्नलर* संदेश लॉग बनाए रखता है। कच्चे सिग्नल झंडे मार्कर अक्षरों के साथ फ्रेम किए हुए आते हैं; रीडिंग को वायर के लिए तैयार करना पड़ता है; और अवलोकनों के जोड़े और तीन के समूह तुरंत सारांशित हो जाते हैं। Factor की स्टैंडर्ड लाइब्रेरी के कुछ ही तरीके ज़्यादातर काम कर देते हैं।

## `unparse`: वैल्यू से सोर्स

[`unparse`][unparse] (`prettyprint` में) किसी भी वैल्यू का सोर्स रूप वाला टेक्स्ट लौटाता है:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` पार्सर का उल्टा है। `dup unparse parse` का राउंड-ट्रिप वैल्यू को फिर से बना देता है। जब रिसीवर उसे वापस पार्स करेगा, ऐसे वायर फॉर्मैट में सीरियलाइज़ करने के लिए यह सही टूल है। लेकिन इंसानों के पढ़ने लायक आउटपुट के लिए यह गलत टूल है (स्ट्रिंग अपने कोट्स बनाए रखती हैं, वेक्टर अपना `V{ ... }` रखते हैं, वगैरह)।

## स्लाइस के वेरिएंट: व्यू, कॉपी नहीं

`sequences` से आने वाले `head` और `tail` जिस हिस्से को आप रखते हैं उसे *कॉपी* करके एक नए सीक्वेंस में डाल देते हैं। इनके `-slice` वाले रूप एक `slice` ऑब्जेक्ट लौटाते हैं, यानी from-index, to-index और मूल सीक्वेंस रखने वाला एक टपल, जो बिना कॉपी किए [सीक्वेंस प्रोटोकॉल][sequence-protocol] लागू करता है:

| शब्द          | प्रभाव                                          |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )`, पहले n कॉपी करता है           |
| `head-slice`  | `( seq n -- slice )`, पहले n का व्यू            |
| `tail`        | `( seq n -- newseq )`, इंडेक्स n से आगे कॉपी करता है   |
| `tail-slice`  | `( seq n -- slice )`, इंडेक्स n से आगे का व्यू      |
| `head*`       | `( seq n -- newseq )`, अंतिम n को छोड़कर बाकी सब कॉपी करता है    |
| `head-slice*` | `( seq n -- slice )`, अंतिम n को छोड़कर बाकी सब का व्यू    |
| `tail*`       | `( seq n -- newseq )`, अंतिम n कॉपी करता है            |
| `tail-slice*` | `( seq n -- slice )`, अंतिम n का व्यू            |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

एक `slice` खुद एक सीक्वेंस *है*, इसलिए जो भी चीज़ सीक्वेंस लेती है वह स्लाइस भी लेती है। `length`, `first`, `each` वगैरह सब बिना कॉपी किए काम करते हैं। जिन टेस्ट को किसी लिटरल स्ट्रिंग से तुलना करनी हो, वे `>string` की मदद से उसे स्ट्रिंग में बदल सकते हैं।

## `?head` और `?tail`: मार्कर मौजूद हो तो हटाइए

फ्रेम की गई रीडिंग के साथ मार्कर टेक्स्ट हो भी सकता है और नहीं भी। `?head` और `?tail` (`splitting` में) प्रीफिक्स या सफिक्स हटाने की कोशिश करते हैं और (छोटा हो चुका) सीक्वेंस *तथा* एक बूलियन लौटाते हैं, जो बताता है कि मार्कर मिला या नहीं:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

अंत में आने वाला बूलियन इन्हें गार्ड के लिए बढ़िया बनाता है: `?head` को `if` के साथ जोड़िए ताकि फ्रेम मौजूद था या नहीं, इस पर शाखा बन सके, या `unless` के साथ जोड़िए ताकि अपेक्षित मार्कर से रहित इनपुट अस्वीकार हो जाए।

## `<repetition>`: N कॉपियाँ, वर्चुअल रूप से

[`<repetition>`][repetition] (`sequences` में) एक और नॉन-कॉपिंग वर्चुअल सीक्वेंस है, `( len elt -- repetition )` `len` एलिमेंट का ऐसा सीक्वेंस बनाता है जो सब `elt` हैं, बिना उतने स्लॉट बाँटे:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

`elt` खुद भी एक सीक्वेंस हो सकता है, और हर कॉपी वही सीक्वेंस होती है। फिर `concat` इन कॉपियों को एक के बाद एक जोड़ देता है:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

किसी `slice` की तरह यह नतीजा भी खुद एक सीक्वेंस *है*, इसलिए `length`, `each` और इनके जैसे दूसरे शब्द इस पर सीधे काम करते हैं। इसे सिग्नल कोड को तय चौड़ाई तक पैड करने के लिए या लगातार दोहराए जाने वाले मार्कर बिछाने के लिए इस्तेमाल कीजिए। `>string` (या `>array`) से तभी बदलिए जब वाकई ठोस सीक्वेंस की ज़रूरत हो।

## `<clumps>`: ओवरलैपिंग विंडो, वर्चुअल रूप से

[`<clumps>`][clumps] (`grouping` में) तीसरा नॉन-कॉपिंग वर्चुअल सीक्वेंस है, `( seq n -- clumps )` `seq` को उस पर बनी *ओवरलैप करती* लंबाई-`n` वाली विंडो की श्रृंखला की तरह देखता है, और हर विंडो एक स्लाइस होती है:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

`length` वाले सीक्वेंस से `length - n + 1` विंडो मिलती हैं। चूँकि हर विंडो एक स्लाइस होती है, लगातार रीडिंग को जोड़ने में कोई कॉपी नहीं करनी पड़ती। हर `2`-क्लंप पर `[ first2 ]` लगाने से आपको हर क्रमागत जोड़ा मिल जाता है, जिससे आगे प्रोजेक्ट कर सकते हैं। (बिना ओवरलैप वाला इसका रिश्तेदार, `<groups>`, इसके बजाय सीक्वेंस को अलग-अलग ब्लॉकों में काट देता है।)

## मल्टी-इनपुट क्लीव: `2bi`, `3bi`, `2tri`, `3tri`

सादे क्लीव शब्द `bi` और `tri` दो या तीन क्वोटेशन को *एक* इनपुट पर लगाते हैं। `2` और `3` लगे वेरिएंट हर क्वोटेशन को *दो* या *तीन* इनपुट पर लगाते हैं:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

हर क्वोटेशन को *सारे* इनपुट मिलते हैं। इनका इस्तेमाल तब कीजिए जब एक से ज़्यादा प्रोजेक्शन वैल्यू के एक ही जोड़े (या तिकड़ी) पर निर्भर करते हों, न कि तब जब आप *वही* ऑपरेशन हर इनपुट पर अलग-अलग लगाना चाहते हों (उसके लिए `bi@` या `tri@` है)।

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
