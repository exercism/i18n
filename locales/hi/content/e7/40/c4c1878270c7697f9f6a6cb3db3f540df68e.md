# `jq` में फंक्शन

आप `jq` में अपने खुद के **कस्टम फंक्शन** बना सकते हैं, ताकि जो भी लॉजिक आपको चाहिए, उसे उनमें समेट सकें।
_फंक्शन_ बिल्ट-इन की तरह ही काम करते हैं: वे एक इनपुट लेते हैं और शून्य, एक या अधिक आउटपुट देते हैं।

## फंक्शन बनाना

आप नीचे दिए सिंटैक्स से `jq` _फंक्शन_ बना सकते हैं:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- `def` कीवर्ड से शुरू होता है,
- फंक्शन के बॉडी से पहले एक कोलन होता है,
- बॉडी एक ही एक्सप्रेशन से बनी होती है,
- अंत में एक सेमीकोलन होता है,
- `jq` के बाकी सिंटैक्स की तरह, पढ़ने में आसानी के लिए आप जितना चाहें व्हाइटस्पेस लगा सकते हैं।

## फंक्शन कहाँ रखें

_फंक्शन_ इस्तेमाल करने से पहले बनाना ज़रूरी है: यह एक एरर है:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

इसका मतलब है कि _फंक्शन_ आपके `jq` कोड में सबसे ऊपर, "मुख्य" एक्सप्रेशन से पहले रखने होंगे।

### नेस्टेड फंक्शन

_फंक्शन_ नेस्टेड हो सकते हैं:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

यहाँ `B` _फंक्शन_ सिर्फ `A` के बॉडी में ही दिखता है।

## स्कोप

एक _फंक्शन_ वेरिएबलो और नेस्टेड फंक्शन के लिए एक नया **स्कोप** बनाता है।

## आर्गुमेंट

_फंक्शन_ के **आर्गुमेंट** _सेमीकोलन_ से अलग किए जाते हैं, कॉमा से नहीं।
उदाहरण के लिए, एक ऐसा _फंक्शन_ जो एक संख्या लेता है, फिर एक संख्या जोड़ता है और एक संख्या से गुणा करता है:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
सेमीकोलन इसलिए ज़रूरी हैं क्योंकि `jq` में कॉमा का पहले से एक काम है: स्ट्रीम जोड़ने वाला ऑपरेटर।

सेमीकोलन की जगह कॉमा इस्तेमाल करने पर _1-आर्गुमेंट_ वाले `add_mul` फंक्शन को दो बार कॉल करने की कोशिश होगी, जो मौजूद नहीं है, इसलिए पहली कोशिश में ही फेल हो जाएगी:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

`5, 4` में कॉमा संख्याओं 5 और 4 को एक स्ट्रीम में जोड़ देता है।
जब हम किसी फंक्शन को आर्गुमेंट के तौर पर एक स्ट्रीम देकर कॉल करते हैं, तो `jq` उस फंक्शन को कई बार कॉल करता है, स्ट्रीम की हर वैल्यू के लिए एक बार।
यह `jq` स्ट्रीम में मौजूद "अंतर्निहित इटरेशन" का एक उदाहरण है।
`10 | add_mul(5, 4)` नीचे दिए गए कोड के बराबर है।

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
अब हम देख सकते हैं कि `add_mul/1 is not defined` एरर कैसे आती है।
~~~~

### आर्गुमेंट _एक्सप्रेशन_ होते हैं

फंक्शन के _आर्गुमेंट_ फिल्टर होते हैं, वैल्यू नहीं।
इस अर्थ में, वे वैसे ही काम करते हैं जिन्हें दूसरी भाषाएँ कॉलबैक कहती हैं:

`add_mul` फंक्शन को उदाहरण के तौर पर लेते हैं:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

यहाँ क्या हो रहा है?

- `adder` आर्गुमेंट को _एक्सप्रेशन_ `. + 5` मिलता है
  - जब फंक्शन `. + adder` करता है, तो वह `. + . + 5` बन जाता है
  - चूँकि `. == 10` है, यह 25 देता है
- इसी तरह, `multiplier` आर्गुमेंट एक्सप्रेशन `. - 2` है
  - यह 8 देता है
  - फिर परिणाम `25 * 8 == 200` होता है

### आर्गुमेंट को वैल्यू बनाना

कभी-कभी आप किसी _आर्गुमेंट_ को वेरिएबल में "बदलकर रखना" चाहेंगे:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

इसका एक शॉर्टहैंड है:

```jq
def my_func($arg):
    other stuff ...
;
```

ध्यान दें कि यह सिर्फ "सिंटैक्टिक शुगर" है: बिना `$` वाला `arg` नाम अब भी _फंक्शन_ के स्कोप में होता है।

<!-- prettier-ignore -->
~~~~exercism/caution
उदाहरण के लिए, मैंने एक अभ्यास हल करने के लिए कुछ ऐसा लिखा था:

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

और मुझे हैरानी हुई कि ऐरे की हर वैल्यू उस की के बराबर थी।

ऐसा इसलिए हुआ क्योंकि jq ने `equals` फंक्शन को ऐसे देखा:

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

**आर्गुमेंट** `code` ने पहले बनाए गए **फंक्शन** `code` को _ओवरराइड_ कर दिया।
इसका मतलब था कि `(. | code)` इनपुट वैल्यू के आधार पर नया कोड निकालने के बजाय सिर्फ **आर्गुमेंट** आउटपुट करता है।
इसलिए `$this_code` और `$code` हमेशा एक जैसे ही रहते थे।
~~~~

## आर्टी

_फंक्शन_ की एक **आर्टी** होती है, यानी वे कितने _आर्गुमेंट_ लेते हैं।

_फंक्शन_ एक ही नाम को अलग-अलग _आर्टी_ के साथ इस्तेमाल कर सकते हैं।
बिल्ट-इन [`range`][man-range] फंक्शन इसका उदाहरण है: `range/1`, `range/2` और `range/3` तीनों साथ मौजूद रहते हैं।

यह ऐसे रिकर्शन वाले फंक्शन बनाने में काम आ सकता है जो आर्गुमेंट के ज़रिए स्थिति लेकर चलते हैं।
उदाहरण के लिए `map` को ऐसे लागू _किया जा सकता है_:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## रिकर्शन

`jq` टेलकॉल ऑप्टिमाइज़ेशन करता है, लेकिन सिर्फ 0-आर्टी वाले फंक्शन के लिए।

## मॉड्यूल

एक `jq` मॉड्यूल एक फाइल है जिसमें सिर्फ फंक्शन होते हैं।
मॉड्यूल को [`include`][man-include] या [`import`][man-import] कमांड से किसी jq प्रोग्राम में शामिल किया जाता है।
