# परिचय

C++ में घोषणाएँ और परिभाषाएँ अक्सर अलग-अलग रखी जाती हैं।
घोषणाएँ तथाकथित हेडर फाइलों में समूहित की जाती हैं, और उनसे जुड़े इम्प्लीमेंटेशन सोर्स फाइलों में रखे जाते हैं।
हेडर फाइलों को आप एक API की तरह समझ सकते हैं।
हेडर फाइल आपको बताती है कि किसी कोडबेस में _क्या_ उपलब्ध है, बिना इस बारीकी में जाए कि वह _कैसे_ काम करता है।

## हेडर और सोर्स

हेडर फाइलों का सबसे आम फाइल एक्सटेंशन `.h` है।
कुछ प्रोजेक्ट्स `.hpp` इस्तेमाल करते हैं, और कुछ एक्सटेंशन बिल्कुल छोड़ देते हैं।

परिभाषाएँ अलग `.cpp` फाइल में रखी जाती हैं।
इन हिस्सों को फिर से जोड़ने के लिए सोर्स फाइल की शुरुआत में संबंधित हेडर फाइल को _इन्क्लूड_ किया जाता है।

मान लीजिए आप "quick_math" नाम की एक लाइब्रेरी लिखना चाहते हैं, जो "super_root" नाम का फंक्शन देती है और जिसे आप बार-बार इस्तेमाल करना चाहते हैं। तब फाइलें ऐसी दिखेंगी:

```cpp
// A file named quick_math.h
#pragma once
namespace quick_math {
    double super_root(double x, int n);
}
```

```cpp
// A file named quick_math.cpp
#include "quick_math.h"
#include <cmath>
double quick_math::super_root(double x, int n) {
    while(n) { x = std::sqrt(x), --n;}
    return x;
}
```

अगर कोई हेडर सिर्फ इम्प्लीमेंटेशन के लिए ज़रूरी है, तो उसकी `#include` लाइन सिर्फ सोर्स फाइल में लिखनी होती है।
हेडर में इन्क्लूड की गई हर चीज़ `.cpp` फाइल में भी उपलब्ध रहती है, जैसे नीचे के उदाहरण में `string` लाइब्रेरी।
**ध्यान दें**: हेडर फाइल में घोषणा के बाद `;` लगाना ज़रूरी है, लेकिन सोर्स फाइल में परिभाषा के बाद नहीं।

## क्लास और हेडर

क्लास बहुत जटिल हो सकती हैं, और हेडर तथा सोर्स के इस बँटवारे से उनका रिश्ता उलझा हुआ लग सकता है।
एक तरीका यह है कि इम्प्लीमेंटेशन की सारी बारीकियाँ सोर्स फाइल में रहें, और सारी घोषणाएँ तथा मेंबर वेरिएबल हेडर में:

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0);
            void give_water();
            std::string get_name();
            int get_size();
            void start_next_day();
    };
}
#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"
robots::Flower::Flower(std::string name, int size) {this->name = "Robotica " + name; this->size = size;}
void robots::Flower::start_next_day() {if (!needs_water) ++size; needs_water = true;}
std::string robots::Flower::get_name() {return name;}
int robots::Flower::get_size() {return size;}
```

जब हेडर को API के अवलोकन की तरह इस्तेमाल किया जाता है, तो डिफॉल्ट वैल्यू जैसी जानकारी लोग वहीं ढूँढ़ते हैं।
इसीलिए कंस्ट्रक्टर के `size` पैरामीटर का डिफॉल्ट हेडर में संभाला जाता है, इम्प्लीमेंटेशन में नहीं।
सोर्स फाइल में हर परिभाषा से पहले नेमस्पेस `robots` और क्लास टाइप `Flower` लिखा जाता है।

दूसरा तरीका _हेडर ओनली_ लाइब्रेरी का है, जिसमें `.cpp` फाइल बिल्कुल नहीं होती:

```cpp
// A file named robot_flower.h
#pragma once
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0) {this->name = "Robotica " + name; this->size = size;}
            void give_water() {needs_water = false;}
            std::string get_name() {return name;}
            int get_size() {return size;}
            void start_next_day() {if (!needs_water) ++size; needs_water = true;}
    };
}
```

प्रोजेक्ट्स इन तरीकों का मेल भी इस्तेमाल कर सकते हैं, और इस पर खूब चर्चा होती है कि किस काम के लिए कौन-सा तरीका सबसे अच्छा बैठता है।

## इन्क्लूड गार्ड

ऊपर दिए गए उदाहरण हेडर फाइल में आपने `#pragma once` लाइन देखी होगी।
इसे इन्क्लूड गार्ड कहते हैं। यह सुनिश्चित करता है कि कंपाइलेशन के दौरान फाइल की सामग्री सिर्फ एक बार इन्क्लूड हो, ताकि एरर न हों।
इन्क्लूड गार्ड का एक और रूप भी है, जो ज़्यादा जटिल है और `#ifndef` से शुरू होकर `#endif` पर खत्म होता है।
यह भी वही काम करता है, और इसका इस्तेमाल ऊपर दिए गए `Flower` क्लास के उदाहरण में दिखाया गया है।
