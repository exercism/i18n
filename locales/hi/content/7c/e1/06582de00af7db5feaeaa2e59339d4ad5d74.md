# परिचय

`if/else` एक्सप्रेशन से शर्तों के आधार पर लॉजिक चलाया जा सकता है, लेकिन Haskell में यही काम करने का एक और भी शक्तिशाली तरीका है: [पैटर्न मैचिंग][pattern-matching]।
पैटर्न मैचिंग में किसी वैल्यू की तुलना एक या अधिक _पैटर्न_ से की जाती है।
ऐसे ही एक पैटर्न का उदाहरण _कॉन्स्टेंट पैटर्न_ है, जो किसी वैल्यू को एक कॉन्स्टेंट से मिलाता है (जैसे `1` या `"hello"`)।

फंक्शन बनाते समय आप अलग-अलग पैटर्न के लिए अलग-अलग फंक्शन बॉडी बना सकते हैं।
इससे ऐसा साफ-सुथरा कोड लिखा जाता है जो सरल और पढ़ने में आसान होता है।
आप किसी भी डेटा टाइप पर पैटर्न मैचिंग कर सकते हैं, जैसे संख्याएँ, अक्षर, ऐरे, ट्यूपल, वगैरह।

उदाहरण के लिए, एक छोटा-सा फंक्शन जो एक पूर्णांक (`Int`) लेता है और उसे _0_ के _1_ कदम और पास ले आता है, ऐसा लिखा जा सकता है:

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero 1 = 0
```

पैटर्न मैचिंग की शक्ति तब और साफ़ दिखती है जब इसे दूसरे पैटर्न के साथ मिलाकर इस्तेमाल किया जाए, जैसे _वेरिएबल पैटर्न_ के साथ:

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero n = n - 1
```

यह उदाहरण _0_ को छोड़कर बाकी सभी इनपुट को एक ही तरह संभालता है और ऋणात्मक संख्याओं के लिए गलत परिणाम देगा।
इसे शर्त वाले पैटर्न से हल किया जा सकता है, जिन्हें _गार्ड_ कहते हैं और जो `|` चिह्न से लिखे जाते हैं:

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
```

ऊपर के उदाहरणों में सभी संभावित इनपुट के लिए मिलता हुआ पैटर्न मौजूद नहीं है।
कंपाइलर इसे पकड़ लेता है और एक चेतावनी देता है।
Haskell की यह बहुत उपयोगी विशेषता है, जो यह सुनिश्चित करने में मदद करती है कि रन-टाइम एरर से बचने के लिए सभी संभावित रास्ते कवर हो जाएँ।
इसे _एक्सहॉस्टिव चेकिंग_ कहते हैं।
चेतावनी दूर करने के लिए आपको हर केस संभालना होगा।
_गार्ड_ के अंदर बाकी सभी पैटर्न पकड़ने के लिए आप `otherwise` एक्सप्रेशन को `True` की सिंटैक्टिक शुगर की तरह इस्तेमाल कर सकते हैं।

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
    | otherwise = 0
```

पैटर्न मैचिंग किसी वैल्यू की तुलना ऊपर से नीचे तक एक-एक करके हर पैटर्न से करती है, जब तक कि उसे मिलता हुआ पैटर्न मिल न जाए और वह उस पैटर्न से जुड़ा लॉजिक चला न दे।
**पैटर्न का क्रम मायने रखता है!**
