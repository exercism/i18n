# परिचय

बाकी कई भाषाओं की तरह Go में भी पॉइंटर होते हैं।
अगर आप पॉइंटर के बारे में नए हैं, तो ये शुरू में थोड़े रहस्यमय लग सकते हैं, लेकिन एक बार इनकी आदत पड़ जाने पर ये काफी सीधे-सरल लगते हैं।
ये Go का एक अहम हिस्सा हैं, इसलिए इन्हें ठीक से समझने के लिए थोड़ा समय ज़रूर लीजिए।

बारीकियों में उतरने से पहले यह समझ लेना अच्छा है कि पॉइंटर किस काम आते हैं।
पॉइंटर हमारे प्रोग्राम के दूसरे हिस्सों के साथ मेमोरी साझा करने का एक तरीका हैं, और यह दो बड़े कारणों से उपयोगी है:

1. जब हमारे पास बहुत सारा डेटा होता है, तो फंक्शन के बीच पास करने के लिए उसकी कॉपी बनाना बहुत ही अकुशल होता है।
   इसके बजाय जहाँ डेटा संग्रहीत है उसका मेमोरी एड्रेस पास करने से, हम अपने प्रोग्राम में संसाधनों पर पड़ने वाला बोझ बहुत कम कर सकते हैं।
2. फंक्शन के बीच पॉइंटर पास करने से हम डेटा की उसी एक कॉपी को सीधे देख और बदल सकते हैं। इसका मतलब है कि एक फंक्शन ने जो भी बदलाव किए, फंक्शन खत्म होते ही वे बदलाव प्रोग्राम के दूसरे हिस्सों को तुरंत दिखने लगते हैं।

## वेरिएबल और मेमोरी

मान लीजिए हमारे पास एक साधारण पूर्णांक वेरिएबल `a` है:

```go
var a int
```

जब हम कोई वेरिएबल घोषित करते हैं, तो Go को उसकी वैल्यू संग्रहीत करने के लिए मेमोरी में जगह ढूँढनी पड़ती है।
यह काम हमसे काफी हद तक छिपा रहता है। जब हमें उस मेमोरी में संग्रहीत वैल्यू निकालनी होती है, तो हम बस वेरिएबल के नाम से उसे पा सकते हैं।

उदाहरण के लिए, जब हम `a + 2` लिखते हैं, तो हम वेरिएबल `a` से जुड़ी मेमोरी में संग्रहीत वैल्यू निकाल रहे होते हैं और उसमें 2 जोड़ रहे होते हैं।

इसी तरह, जब हमें `a` वाली मेमोरी में रखी वैल्यू बदलनी होती है, तो हम वेरिएबल के नाम से उसमें नई वैल्यू असाइन कर सकते हैं:

```go
a = 3
```

अब `a` से जुड़ी मेमोरी में वैल्यू `3` संग्रहीत हो जाएगी।

## पॉइंटर

वेरिएबल हमें मेमोरी में रखी वैल्यू का हवाला देने की सुविधा देते हैं, लेकिन कभी-कभी यह जानना भी काम का होता है कि वह वेरिएबल किस **मेमोरी एड्रेस** की ओर इशारा कर रहा है।
**पॉइंटर** उन वैल्यू के मेमोरी एड्रेस रखते हैं।
किसी वेरिएबल को पॉइंटर टाइप का घोषित करने के लिए उसके मूल टाइप से पहले तारक चिह्न लगाइए:

```go
var p *int // 'p' contains the memory address of an integer
```

यहाँ हमने "pointer to int" टाइप (`*int`) का एक वेरिएबल `p` घोषित किया है।
इसका मतलब है कि `p` में एक पूर्णांक का मेमोरी एड्रेस रहेगा।
पॉइंटर की शून्य वैल्यू `nil` होती है, क्योंकि `nil` पॉइंटर में कोई मेमोरी एड्रेस नहीं होता।

### किसी वेरिएबल का पॉइंटर पाना

किसी वेरिएबल की वैल्यू का मेमोरी एड्रेस ढूँढने के लिए हम `&` ऑपरेटर का उपयोग कर सकते हैं।
उदाहरण के लिए, अगर हम वेरिएबल `a` का मेमोरी एड्रेस ढूँढकर पॉइंटर `p` में रखना चाहते हैं, तो हम यह कर सकते हैं:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### पॉइंटर से वैल्यू पाना (डीरेफरेंसिंग)

जब हमारे पास कोई पॉइंटर होता है, तो कभी-कभी हम यह जानना चाहते हैं कि उस पॉइंटर के मेमोरी एड्रेस में कौन-सी वैल्यू संग्रहीत है।
इसके लिए हम `*` ऑपरेटर का उपयोग कर सकते हैं:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p` ऑपरेशन `p` में संग्रहीत मेमोरी एड्रेस पर रखी वैल्यू निकालता है।
इस ऑपरेशन को अक्सर "डीरेफरेंसिंग" कहा जाता है।

हम डीरेफरेंस ऑपरेटर का उपयोग पॉइंटर के मेमोरी एड्रेस पर नई वैल्यू असाइन करने के लिए भी कर सकते हैं:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa` में असाइन करने से उस मेमोरी एड्रेस पर रखी वैल्यू बदल जाएगी जो `pa` में है।
चूँकि `pa` में `a` का मेमोरी एड्रेस है, इसलिए `*pa` में असाइन करने का मतलब है कि हम `a` की वैल्यू बदल रहे हैं!

लेकिन एक सावधानी की बात है: डीरेफरेंस करने से पहले हमेशा जाँच लीजिए कि पॉइंटर `nil` नहीं है।
`nil` पॉइंटर को डीरेफरेंस करने पर प्रोग्राम रनटाइम पर क्रैश हो जाएगा!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### स्ट्रक्ट के पॉइंटर

अब तक हमने सिर्फ प्रिमिटिव वैल्यू के पॉइंटर देखे हैं।
हम स्ट्रक्ट के लिए भी पॉइंटर बना सकते हैं:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

हम एक नया `Person` बनाकर उसका पॉइंटर तुरंत संग्रहीत भी कर सकते थे:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

जब हमारे पास किसी स्ट्रक्ट का पॉइंटर होता है, तो उसके किसी फील्ड को देखने से पहले पॉइंटर को डीरेफरेंस करने की ज़रूरत नहीं होती:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## स्लाइस और मैप पहले से ही पॉइंटर होते हैं

स्लाइस और मैप खास टाइप हैं, क्योंकि इनके अंदरूनी कार्यान्वयन में पहले से पॉइंटर होते हैं।
इसका मतलब है कि इन टाइप की वैल्यू का मेमोरी एड्रेस साझा करने के लिए हमें अधिकतर इनके लिए अलग से पॉइंटर बनाने की ज़रूरत नहीं पड़ती।
मान लीजिए हमारे पास एक फंक्शन है जो मैप में किसी की की वैल्यू बढ़ाता है:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

अगर हम एक मैप बनाकर इस फंक्शन को कॉल करें, तो फंक्शन ने मैप में जो बदलाव किए वे फंक्शन खत्म होने के बाद भी बने रहते हैं।
यह व्यवहार वैसा ही है जैसा पॉइंटर इस्तेमाल करने पर मिलता है।
लेकिन ध्यान दीजिए कि इस उदाहरण में हमने कोई रेफरेंसिंग या डीरेफरेंसिंग या पॉइंटर का कोई भी सिंटैक्स इस्तेमाल नहीं किया:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

यही बात स्लाइस में मौजूद किसी एलिमेंट को बदलने पर भी लागू होती है।

लेकिन `append` जैसे वे काम, जो एक नया स्लाइस लौटाते हैं, एक खास मामला हैं और फंक्शन के बाहर वाला स्लाइस **शायद ही बदलते हैं**।
ऐसा स्लाइस के अंदरूनी काम करने के तरीके की वजह से होता है, लेकिन हम यहाँ इसकी बारीकी में नहीं जाएँगे, क्योंकि यह एक अधिक उन्नत विषय है।
अगर आपकी जिज्ञासा सचमुच बहुत है, तो इसके बारे में और पढ़ सकते हैं [Go Blog: Mechanics of 'append'][mechanics-of-append]
