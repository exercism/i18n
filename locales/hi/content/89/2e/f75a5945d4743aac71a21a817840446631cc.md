# परिचय

C# में टपल एक डेटा स्ट्रक्चर है जो डेटा को व्यवस्थित करता है और किसी भी टाइप की दो या उससे अधिक फील्ड रखता है।

आम तौर पर टपल दो या अधिक एक्सप्रेशन को कॉमा से अलग करके गोल ब्रैकेट के एक जोड़े के अंदर रखकर बनाया जाता है।

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

किसी भी अन्य एक्सप्रेशन की तरह टपल का उपयोग कई तरह से किया जा सकता है: [असाइनमेंट][tuple-assignment] में, किसी फील्ड या वेरिएबल को इनिशियलाइज़ करने में, किसी मेथड से [रिटर्न वैल्यू][tuple-return-values] के रूप में, या पैरामीटर के रूप में पास करने में। [समानता][tuple-equality] की जाँच भी इन पर की जा सकती है। टपल की समानता को `pattern-matching-tuples` अभ्यास में पूरी तरह समझाया गया है, लेकिन पूर्णता के लिए नीचे दिए गए कोड में एक उदाहरण भी दिया गया है।

फील्ड को डॉट सिंटैक्स से निकाला जाता है। डिफॉल्ट रूप से पहली फील्ड `Item1` होती है, दूसरी `Item2`, और इसी तरह। डिफॉल्ट से अलग नामों की चर्चा नीचे _नामकरण_ में की गई है।

टपल को जेनेरिक पैरामीटर के रूप में भी इस्तेमाल किया जा सकता है, जैसे `IList<(bool, string)>`

इसके अलावा, टपल "डीकंस्ट्रक्शन" का समर्थन करते हैं, जिसकी चर्चा नीचे की गई है, और इन्हें पैटर्न मैचिंग में भी इस्तेमाल किया जा सकता है, जो आगे के एक अभ्यास में शामिल है।

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

यह [परिचय][tuples] दिखाता है कि टपल को कैसे बनाया और इस्तेमाल किया जाता है।

## नामकरण

`Item1` जैसे फील्ड नामों से पढ़ने लायक कोड नहीं बनता। फील्ड को नाम देने के तीन तरीके हैं: a) टाइप डिक्लेरेशन में, b) उस एक्सप्रेशन में जो टपल बनाता है, c) [टपल प्रोजेक्शन इनिशियलाइज़र][tuple-projection-initializers] के ज़रिए (यहाँ दिखाया नहीं गया है)।

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

नामकरण की इस व्यवस्था में ज़्यादा चतुर बनने की कोशिश न कीजिए। यह वास्तव में केवल सिंटैक्स की सुविधा है। उदाहरण के लिए, जब आप किसी दूसरे टपल से वैल्यू असाइन करते हैं, तो आप टपल के नाम नहीं बदल सकते।

## डीकंस्ट्रक्शन

कभी-कभी किसी टपल की फील्ड को कई वेरिएबल में असाइन करना और ज़रूरत हो तो उन्हें इनिशियलाइज़ करना सुविधाजनक होता है। इस व्यवस्था को [डीकंस्ट्रक्शन][tuple-deconstruction] कहते हैं। (इसे अपने ऑब्जेक्ट पर भी लागू किया जा सकता है। [यहाँ][udt-deconstruction] देखिए।)

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## फील्ड असाइनमेंट

टपल की फील्ड को अलग-अलग असाइन किया जा सकता है। लेकिन C# में अपरिवर्तनीयता की ओर जो रुझान है, उसे देखते हुए इस तरह का उपयोग बहुत नहीं होता। टपल का इस्तेमाल अक्सर ऐसे किया जाता है मानो वे अपरिवर्तनीय हों, जबकि वे वास्तव में नहीं हैं।

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## पृष्ठभूमि

हम जिन टपल की बात कर रहे हैं, उन्हें [`System.Tuple`][system-tuple] से नहीं मिलाना चाहिए, जो शायद सिर्फ पुराने कोड बेस में ही मिलेगा।

`System.ValueTuple` की बात करते समय स्थिति थोड़ी और उलझी हुई लगती है। [`System.ValueTuple`][system-value-tuple] के अंतिम ओवरलोड के [डॉक्स][system-value-tuple] कहते हैं कि "वैल्यू टपल टाइप वह रनटाइम इम्प्लीमेंटेशन देते हैं जो C# में टपल का समर्थन करता है"। यहाँ "वैल्यू टपल टाइप" से उनका मतलब `System.ValueTuple` के जेनेरिक ओवरलोड से है। और "टपल" से उनका मतलब उन चीज़ों से है जिनकी चर्चा इस अभ्यास में हम कर रहे हैं। वास्तव में वे यह कह रहे हैं कि `System.ValueTuple` टपल का एक इम्प्लीमेंटेशन डिटेल है। ज़्यादातर लोगों को, ज़्यादातर समय, इसमें शायद खास दिलचस्पी न हो। दुर्भाग्य से "टपल" पर लिखे बहुत से डॉक्युमेंटेशन में, Microsoft के अपने दस्तावेज़ों में भी, `System.ValueTuple` के संदर्भ खूब बिखरे हुए हैं। ऐसे संदर्भों को नज़रअंदाज़ कर देना शायद ठीक रहेगा।

## अन्य उपयोग और सीमाएँ

पैटर्न मैचिंग टपल का खासा उपयोगी इस्तेमाल है। इस पर आगे के एक अभ्यास में चर्चा की गई है।

टपल स्टाइल के कुछ और छोटे उपयोग भी संभव बनाते हैं:

- एक साथ कई असाइनमेंट (खास तौर पर कंस्ट्रक्टर में), जैसे `(this.field1, this.field2) = (arg1, arg2);`
- वैल्यू की अदला-बदली या दोबारा उपयोग, जैसे `(a, b) = (b, a);`
- सूची में `struct` के बजाय उपयोग
- डिक्शनरी की की या किसी सेट की सामग्री के रूप में उपयोग।
- LINQ में उपयोग। (LINQ पर आगे के अभ्यासों में चर्चा की गई है।)

डॉक्युमेंटेशन टपल को एक हल्की व्यवस्था बताता है, और इसका सफल इस्तेमाल इसी में है। क्लास या स्ट्रक्ट के बजाय टपल का उपयोग करने पर उसके फील्ड टाइप और शायद नाम भी बार-बार उबाऊ ढंग से दोहराने पड़ सकते हैं। यह खास तौर पर तब लागू होता है जब टपल को मेथड आर्गुमेंट या कलेक्शन में जेनेरिक आर्गुमेंट के रूप में इस्तेमाल किया जाता है।

एक साथ कई असाइनमेंट और अदला-बदली जैसी तरकीबों का इस्तेमाल समझदारी से करना ही बेहतर है।

समानता और असमानता के अलावा अन्य रिलेशनल ऑपरेशन समर्थित नहीं हैं।

ध्यान दीजिए कि टपल भाषा में अपेक्षाकृत हाल ही में आए हैं (C# 7), इसलिए अगर आप इन्हें इस्तेमाल करना चाहते हैं, तो यह सुनिश्चित कीजिए कि आपका कोड बेस भाषा के [वर्ज़न][language-version] 7 या उससे नए वर्ज़न का उपयोग कर रहा है।
