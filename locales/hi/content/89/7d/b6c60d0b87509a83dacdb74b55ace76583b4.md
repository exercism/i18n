# विवरण

असेंबली में कोई भी डेटा बाइटों का एक क्रम होता है। इसका मतलब है कि किसी भी डेटा को उन मूल बाइटों के **[ऐरे][array]** के रूप में देखा जा सकता है।

## ऐरे के एलिमेंट तक पहुँचना

मेमोरी में किसी भी वैल्यू तक पहुँचने के लिए उसका **प्रभावी एड्रेस** निकालना ज़रूरी होता है। एक प्रभावी एड्रेस एक ऐसा एक्सप्रेशन होता है जिसमें ये चीज़ें शामिल हो सकती हैं:

- एक _बेस एड्रेस_, जैसे कि किसी वेरिएबल के लेबल से दर्शाया गया एड्रेस।
- एक _इंडेक्स रजिस्टर_, जिसे ज़रूरत पड़ने पर `1`, `2`, `4` या `8` से स्केल किया जा सकता है।
- एक साइन्ड 32-बिट _डिस्प्लेसमेंट_, यानी ऐसी संख्या जिसे बेस एड्रेस में जोड़ा (या उसमें से घटाया) जाता है।

ध्यान दीजिए कि यह एड्रेस _0-इंडेक्स्ड_ होता है, इसलिए बिना किसी ऑफ़सेट वाला बेस एड्रेस किसी वेरिएबल के पहले बाइट की ओर इशारा करता है। इसीलिए जब हम किसी लेबल का इस्तेमाल करके बिना किसी ऑफ़सेट के सीधे मेमोरी को डीरेफरेंस करते हैं, जैसा कि पिछली अवधारणाओं में किया गया था, तो हमें पहले बाइट से शुरू होने वाली एक वैल्यू मिलती है:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 [लिटिल एंडियन][endianness] है। इसका मतलब है कि किसी मल्टीबाइट वैल्यू का सबसे कम महत्वपूर्ण बाइट सबसे छोटे मेमोरी एड्रेस पर संग्रहीत होता है।

इसलिए किसी मल्टीबाइट वैल्यू के अलग-अलग बाइटों तक पहुँचने के लिए बेस एड्रेस में एक धनात्मक ऑफ़सेट जोड़ना ज़रूरी होता है, ताकि अधिक महत्वपूर्ण बाइटों तक पहुँचा जा सके।

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

जिस वेरिएबल को कई वैल्यू देकर इनिशलाइज़ किया जाता है, वह उन वैल्यू का एक ऐरे होता है, और हर एलिमेंट का आकार वही होता है जो बताया गया है। लेकिन ऑफ़सेट हमेशा _बाइटों_ में होते हैं, भले ही ऐरे के हर एलिमेंट का आकार उससे बड़ा हो:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

ध्यान दीजिए कि चूँकि एड्रेस बाइटों के हिसाब से होते हैं, इसलिए ऐरे के किसी भी एलिमेंट के किसी एक अलग बाइट तक सीधे पहुँचा जा सकता है:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

इसी कारण से एक ही निर्देश में किसी एलिमेंट के आकार से भी अधिक बाइटों तक पहुँचा जा सकता है:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
असेंबली ऐरे तक पहुँचने पर कोई बाउंड जाँच नहीं करती। ऐरे के अंत से आगे वाला इंडेक्स ऐरे के बाहर की मेमोरी पढ़ता या लिखता है। इससे चुपचाप गलत परिणाम मिल सकते हैं, दूसरा डेटा खराब हो सकता है, और अगर जिस मेमोरी तक पहुँचा जा रहा है वह मैप नहीं है, तो रनटाइम फॉल्ट भी हो सकता है। हर प्रभावी एड्रेस को ऐरे के अंदर रखने की ज़िम्मेदारी प्रोग्रामर की है।
~~~~

## इनिशलाइज़्ड ऐरे का आकार निकालना

NASM (नेटवाइड असेंबलर, यानी वह असेंबलर जिसका इस्तेमाल इस ट्रैक में होता है) में एक खास सिंबल (`$`) होता है, जो मेमोरी में मौजूदा जगह बताता है। यह सिंबल किसी ऐरे ने मेमोरी में जितनी जगह घेरी है, उसका कुल आकार निकालने का एक आसान तरीका देता है:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

जब `$` का इस्तेमाल ठीक `example` के बाद किया जाता है, तो उसके पास ऐरे के अंत वाली मेमोरी का एड्रेस होता है। इसका मतलब है कि `$ - example` उस एड्रेस और `example` लेबल से दर्शाए गए एड्रेस के बीच का अंतर है। यह ठीक उतना ही कुल आकार है, बाइटों में, जितनी जगह `example` से दर्शाया गया ऐरे घेरता है।

तो इस वैल्यू के साथ `example_length` को परिभाषित करके हमने एक 8-बाइट वेरिएबल बनाया है, जो ऐरे का आकार, यानी लंबाई, बाइटों में संग्रहीत करता है।

## .bss सेक्शन

बिना इनिशलाइज़ किया गया डेटा **[.bss सेक्शन][bss]** में घोषित किया जाता है। ज़्यादातर प्लेटफॉर्म पर प्रोग्राम की शुरुआत में ऑपरेटिंग सिस्टम इस डेटा को शून्य से भर देता है।

NASM में बिना इनिशलाइज़ किए वेरिएबल में एक नाम, डेटा का आकार बताने वाला एक डायरेक्टिव, और आरक्षित किए जाने वाले एलिमेंट की संख्या होती है। इनमें से हर चीज़ को दूसरी से एक स्पेस से अलग किया जाता है।

मुख्य डायरेक्टिव और उनसे जुड़े डेटा आकार ये हैं:

| डायरेक्टिव | आकार |
| :-------: | :------ |
|   resb    | 1 बाइट  |
|   resw    | 2 बाइट |
|   resd    | 4 बाइट |
|   resq    | 8 बाइट |

उदाहरण के लिए, यह `example` नाम के वेरिएबल में `3` बाइट के लिए बिना इनिशलाइज़ की जगह आरक्षित करता है:

```x86asm
section .bss
    example resb 3
```

और यह `arr` नाम के वेरिएबल में `10` गुना `8` बाइट (यानी `80` बाइट) के लिए बिना इनिशलाइज़ की जगह आरक्षित करता है:

```x86asm
section .bss
    arr resq 10
```

`section .bss` में मौजूद वेरिएबल म्यूटेबल होते हैं, यानी उन्हें पढ़ा भी जा सकता है और लिखा भी जा सकता है।

बिना इनिशलाइज़ किए डेटा तक उसी तरह पहुँचा जा सकता है जैसे इनिशलाइज़्ड डेटा तक, यानी उसके प्रभावी एड्रेस का इस्तेमाल करके। इसी तरह, ऐसे डेटा की स्टोरेज अवधि भी स्टैटिक होती है और उसी सोर्स फाइल के किसी भी फंक्शन से इसे इस्तेमाल किया जा सकता है (और अगर इसे `global` घोषित किया गया हो, तो दूसरी सोर्स फाइलों से भी)।

## Lea निर्देश से ऐरे के एड्रेस तक पहुँचना

जैसा कि पिछली अवधारणा में देखा गया था, `lea` निर्देश एक प्रभावी मेमोरी एड्रेस की गणना करता है। यह ऐरे के किसी भी एलिमेंट का एड्रेस निकालने में भी उसी तरह काम करता है।

ध्यान दीजिए कि रिलेटिव एड्रेसिंग में अक्सर किसी ज़्यादा जटिल एड्रेस को बनाने से पहले वेरिएबल का एड्रेस किसी रजिस्टर में लोड करना ज़रूरी होता है:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea` का एक फायदा यह है कि यह एड्रेस की गणना वाले अंकगणित का इस्तेमाल करके वैल्यू निकालता है, बिना उस एड्रेस की मेमोरी तक असल में पहुँचे। इससे यह तब भी गणना करने के काम आता है जब किसी भी रजिस्टर में कोई मेमोरी एड्रेस मौजूद न हो:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
