# निर्देश परिशिष्ट

## `from_quote` के फायदे और नुकसान

`Card.from_quote` फंक्शन एक स्ट्रिंग को पार्स करके `Card` में बदल देता है। इससे ऐसा कोड लिखना संभव हो जाता है:

```roc
card : Card
card = "Q"
```

यह कोड कंपाइल टाइम पर अपने आप `Card.from_quote("Q")` को कॉल करता है। इससे प्रोग्राम तेज़ चल सकता है, क्योंकि रनटाइम पर पार्सिंग संभालने की ज़रूरत नहीं पड़ती। साथ ही, जो कार्ड `from_quote` अस्वीकार करता है, वे रनटाइम पर नहीं, बल्कि कंपाइल टाइम पर ही पकड़ लिए जाते हैं। इसके अलावा, इससे कोड साफ़ और पढ़ने में आसान रहता है। उदाहरण के लिए, इस अभ्यास का एक टेस्ट देखिए:

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

लेकिन इस कोड को पढ़ने वाला कोई व्यक्ति यह मान सकता है कि `simulate_game` फंक्शन दो `List(Str)` वाला रिकॉर्ड लेता है, जबकि वास्तव में वह दो `List(Card)` वाला रिकॉर्ड लेता है। इससे उलझन और गलतियाँ हो सकती हैं। इसीलिए आप थोड़ा लंबा, पर ज़्यादा स्पष्ट तरीका पसंद कर सकते हैं: `"Q".Card`, जो कंपाइल टाइम पर `from_quote` को भी कॉल करता है।

अपने खुद के प्रोग्राम में आप इसकी जगह `from_str` इस्तेमाल करना पसंद कर सकते हैं:

```roc
Card := { ... }.{
    from_str : Str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

आप `from_str` (या कोई भी दूसरा प्योर फंक्शन) कंपाइल टाइम पर भी कॉल कर सकते हैं, इस तरह:

```roc
Ok(card) = Card.from_str("Q")
```

ध्यान दें: इस परिभाषा को टॉप लेवल पर रखने से यह कंपाइल टाइम पर चलती है (क्योंकि यह फंक्शन प्योर है और उसका इनपुट कंपाइल टाइम पर ही ज्ञात होता है)। किसी फंक्शन के अंदर आप `from_str` को रनटाइम पर इस्तेमाल कर सकते हैं।

## संकेत

<details>
<summary>संकेत देखें</summary>

खाली डेक को उसके अगले कार्ड और बाकी कार्डों से अलग पहचानने के लिए `[]` और `[card, .. as rest]` के साथ `match` का उपयोग कीजिए।
`{ ..state, pile: new_pile }` जैसे रिकॉर्ड अपडेट खेल में होने वाले बदलावों को बिना म्यूटेबल स्थिति के स्पष्ट रख सकते हैं।
पहले देखी गई खेल स्थितियों पर नज़र रखते समय एक `Set` टुपल या लिस्ट को की के रूप में संग्रहीत कर सकता है।
