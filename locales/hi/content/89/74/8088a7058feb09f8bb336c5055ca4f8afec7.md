# विवरण

## शब्दावली

आप पहले ही कुछ कॉन्सेप्ट में C++ फंक्शन इस्तेमाल कर चुके हैं और लिख चुके हैं।
अब तकनीकी विवरण में उतरने का समय है।
आसान संदर्भ के लिए नीचे दिया गया कोड स्निपेट सबसे आम शब्द दिखाता है।
चूँकि C++ व्हाइटस्पेस को नज़रअंदाज़ करता है, इसलिए फॉर्मैटिंग बदलकर हर एलिमेंट को एक ही लाइन पर रखा गया है।

```cpp
// Function declaration:
bool                                              // Return type
admin_detected(string user, string password)      // Type signature
;                                                 // Don't forget the ';' for the declaration

// Function definition:
bool                                              // Return type
admin_detected                                    // Function name
(string user, string password)                    // Parameter list
{ return user == "admin" && password == "1234"; } // Function body
```
~~~~exercism/advanced
डिक्लेरेशन कंपाइलर के लिए एक नोट की तरह काम करता है, कि उस नाम, रिटर्न टाइप और पैरामीटर लिस्ट वाला एक फंक्शन मौजूद है।
अगर डेफिनिशन गायब हो, तो कोड काम नहीं करेगा।
डिक्लेरेशन वैकल्पिक होते हैं, इनकी ज़रूरत तब होती है जब आप फंक्शन को उसकी डेफिनिशन से पहले इस्तेमाल करते हैं।
डिक्लेरेशन चक्रीय संदर्भ जैसी समस्याएँ हल कर सकते हैं और इनका उपयोग इंटरफेस को इम्प्लीमेंटेशन से अलग करने के लिए किया जा सकता है।
~~~~

## `const` क्वालिफायर

कभी-कभी आप यह सुनिश्चित करना चाहते हैं कि वैल्यू इनिशियलाइज़ होने के बाद बदली न जा सके।
C++ `const` कीवर्ड का उपयोग कॉन्स्टेंट के लिए क्वालिफायर के रूप में करता है।

```cpp
const int number_of_dragon_balls{7};
number_of_dragon_balls--; // compilation error
```

~~~~exercism/note
आप कॉन्स्टेंट को अक्सर _UPPER_SNAKE_CASE_ में लिखा हुआ देखेंगे।
अगर कोई और तय तरीका न हो, तो इस केसिंग को मैक्रो के लिए ही रखने की सलाह दी जाती है।
~~~~

अगर आप किसी कॉन्स्टेंट वेरिएबल को सेट होने के बाद बदलने की कोशिश करते हैं, तो आपका कोड कंपाइल नहीं होगा।
इससे अनजाने बदलावों से बचने में मदद मिलती है और साथ ही कंपाइलर के लिए ऑप्टिमाइज़ेशन के मौके भी खुलते हैं।
इंसान के तौर पर भी कोड के बारे में सोचना आसान हो जाता है, जब आपको पता हो कि कुछ हिस्से प्रभावित नहीं होंगे।

आप `const` को फंक्शन पैरामीटर के लिए क्वालिफायर के रूप में भी इस्तेमाल कर सकते हैं।

```cpp
string guess_number(const int& secret, const int& guess) {
    if (secret < guess) return "lower.";
    if (secret > guess) return "higher.";
    return "exact!";
}
```

जब आप फंक्शन को `const` संदर्भ पास करते हैं, तो आप निश्चिंत रह सकते हैं कि वह बदला नहीं जाएगा।
जिन ऑब्जेक्ट को कॉपी करना महँगा पड़ सकता है, जैसे लंबी स्ट्रिंग, उनके लिए आप अक्सर `const` संदर्भ देखेंगे।
`const` क्वालिफायर का तीसरा उपयोग ऐसे मेंबर फंक्शन हैं जो क्लास के इंस्टेंस को नहीं बदलते।

```cpp
class Stubborn {
    public:
    Stubborn(string reply) {
        response = reply;
    }
    string answer(const string& question) const {
        if (question.length() == 0) { return "";}
        return response;
    }
    private:
    string response{};
};
```

`Stubborn` का मेंबर फंक्शन `answer` पैरामीटर के रूप में `const string&` संदर्भ लेता है।
इससे फंक्शन को पास किए गए मूल ऑब्जेक्ट की कॉपी बनाने की ज़रूरत नहीं पड़ती।

## फंक्शन ओवरलोडिंग

अगर पैरामीटर लिस्ट अलग हो, तो कई फंक्शन का नाम एक ही हो सकता है।
इसे फंक्शन ओवरलोडिंग कहते हैं और यह आमतौर पर तब किया जाता है जब ये फंक्शन बहुत मिलते-जुलते काम करते हों।

रिटर्न टाइप को छोड़कर फंक्शन का हेडर ही फंक्शन का __टाइप सिग्नेचर__ होता है।
टाइप सिग्नेचर में बदलाव होने पर एक नया फंक्शन बनता है।

`play_sound` के उदाहरण में अलग-अलग स्थितियों के लिए छह अलग-अलग ओवरलोड हैं:

```cpp
// different argument types:
void play_sound(char note);         // C, D, E, ..., B
void play_sound(string solfege);    // do, re, mi, ..., ti
void play_sound(int jianpu);        // 1, 2, 3, ..., 7

// different number of arguments:
void play_sound(string solfege, double duration);

// different qualifiers:
void play_sound(vector<string>& solfege);
void play_sound(const vector<string>& solfege);
```

~~~~exercism/advanced
टाइप सिग्नेचर फंक्शन के नाम, पैरामीटर की संख्या, उनके टाइप और उनके क्वालिफायर से तय होता है (लेकिन उनके नाम से नहीं)।
रिटर्न टाइप जान-बूझकर टाइप सिग्नेचर का हिस्सा नहीं है, और अगर आपके पास ऐसे दो फंक्शन हों जो सिर्फ रिटर्न टाइप में अलग हों, तो आपको कंपाइलेशन एरर मिलेंगी।
कंपाइलर शिकायत करेगा, क्योंकि साफ नहीं होता कि इन दोनों में से किसे इस्तेमाल करना चाहिए।
~~~~

## डिफॉल्ट आर्गुमेंट

कुछ फंक्शन बहुत लंबे हो सकते हैं और उनके कई कॉल में ज़्यादातर पैरामीटर की वैल्यू एक ही हो सकती है।
ऐसे कॉल में दोहराव डिफॉल्ट आर्गुमेंट की मदद से टाला जा सकता है।

```cpp
void record_new_horse_birth(string name, int weight, string color="brown-ish", string dam="Alruccaba", string sire="Poseidon");

record_new_horse_birth("Urban Sea", 130); // color will be brown, dam "Alruccabam", sire "Poseidon"
record_new_horse_birth("Highclere", 175, "off-white", "Fall Aspen");   // sire will be "Poseidon"
```

चूँकि फंक्शन डिक्लेरेशन अक्सर डेफिनिशन से पहले पढ़ा जाता है, डिफॉल्ट आर्गुमेंट सेट करने की बेहतर जगह वही है।
अगर एक पैरामीटर का डिफॉल्ट डिक्लेरेशन है, तो उसके दाईं ओर के सभी पैरामीटर का भी डिफॉल्ट डिक्लेरेशन होना चाहिए।
कभी-कभी उलझे हुए फंक्शन ओवरलोड को डिफॉल्ट आर्गुमेंट वाले कम फंक्शन में बदला जा सकता है, जिससे रखरखाव बेहतर होता है।
