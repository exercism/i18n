# परिचय

## let assert

जब हम Gleam में किसी वैल्यू पर पैटर्न मैचिंग करते हैं, तो हमें यह सुनिश्चित करना होता है कि पैटर्न उस टाइप की हर संभावित वैल्यू से मेल खाता है, वरना कोड कंपाइल नहीं होगा।

यह फंक्शन अस्वीकार कर दिया जाएगा क्योंकि इसने ऐसी स्थिति को नहीं संभाला है जहाँ ऐरे खाली है:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Gleam प्रोग्राम में ज़्यादातर हम हर संभावित स्थिति को संभालना चाहते हैं। लेकिन कुछ प्रोग्राम, जैसे प्रोटोटाइप और जल्दी लिखी जाने वाली स्क्रिप्ट, में हम सिर्फ ऐसे रास्ते पर ध्यान देना चाहते हैं जहाँ सब कुछ ठीक चलता है और बाकी स्थितियों के लिए कोड नहीं लिखना चाहते। यहीं पर Gleam का `let assert` काम आता है।

let assert की मदद से कोई पैटर्न किसी टाइप की सिर्फ कुछ संभावित वैल्यू से मेल खा सकता है, और अगर पैटर्न किसी वैल्यू से मेल नहीं खाता, तो प्रोग्राम क्रैश हो जाएगा। `let assert` का उपयोग करके हम ऊपर दिया गया फंक्शन ऐसे लिख सकते हैं:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam की लाइब्रेरी में कभी भी let assert का उपयोग नहीं करना चाहिए, क्योंकि इससे प्रोग्राम क्रैश हो सकता है। इसके बजाय उन्हें `Result` टाइप का उपयोग करना चाहिए और एप्लिकेशन डेवलपर को यह तय करने देना चाहिए कि एरर को कैसे संभालना है।
