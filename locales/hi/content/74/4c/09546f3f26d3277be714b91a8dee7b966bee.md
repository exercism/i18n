# परिचय

## पार्शियल एप्लिकेशन

Elm में सारे फंक्शन [करीड][currying] होते हैं, यानी अगर आप किसी फंक्शन को उसके सारे आर्गुमेंट पास किए बिना कॉल करते हैं, तो वह एक नया फंक्शन लौटाता है।

ऐसा करने के नतीजे को [पार्शियल एप्लिकेशन][partial-application] कहते हैं (आप फंक्शन को सारे आर्गुमेंट नहीं पास कर रहे, बल्कि उनमें से कुछ आंशिक रूप से लगा रहे हैं)।

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

पार्शियल एप्लिकेशन आर्गुमेंट को हमेशा क्रम से लगाता है।

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## पाइप ऑपरेटर (`|>`)

`x |> f` लिखना बिल्कुल `f x` लिखने जैसा है। एक ठोस उदाहरण देखिए, `"5" |> String.toInt` वही है जो `String.toInt "5"` है।

पहली नज़र में यह बहुत उपयोगी नहीं लगता, लेकिन इसे [पाइप ऑपरेटर][pipe-operator] कहते हैं, क्योंकि इसकी मदद से आप "पाइपलाइन" वाला कोड लिख सकते हैं।

मान लीजिए, हमारे पास एक sanitize फंक्शन है जो उपयोगकर्ता के इनपुट को पूर्णांक में बदलता है:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

हम इसे ऐसे फिर से लिख सकते हैं:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

इसमें ब्रैकेट लगाने की ज़रूरत नहीं पड़ती, और फंक्शन उसी क्रम में दिखते हैं जिस क्रम में वे लगाए जाते हैं (पहले `String.trim`, फिर `String.toInt`), जिससे कोड पढ़ने में आसानी होती है।

एक [उल्टा पाइप ऑपरेटर `(<|)`][reverse-pipe-operator] भी होता है।
`f <| x` लिखना बिल्कुल `f x` लिखने जैसा है।
पहली नज़र में यह भी बहुत उपयोगी नहीं लगता, और पाइप ऑपरेटर जितना इसका उपयोग नहीं होता, लेकिन कुछ जगहों पर यह ब्रैकेट से बचने में मदद करता है।

## फंक्शन कंपोज़िशन / पॉइंट फ्री स्टाइल

[`(>>)`][forward-composition] ऑपरेटर का टाइप `(a -> b) -> (b -> c) -> (a -> c)` होता है, और यह `a -> b ` तथा `b -> c` टाइप वाले दो मेल खाते फंक्शन को जोड़कर `a -> c` टाइप का एक फंक्शन बनाता है।
यह पहले फंक्शन से आउटपुट (टाइप `b`) लेकर उसे दूसरे फंक्शन के पहले आर्गुमेंट की तरह इस्तेमाल करता है (जिसका टाइप भी वही `b` होना चाहिए)।
बना हुआ फंक्शन वही इनपुट (टाइप `a`) लेता है जो पहला फंक्शन लेता है, और दूसरा फंक्शन जो `c` लौटाता है वही लौटाता है।

एक ठोस उदाहरण है `String.trim >> String.toInt`।
`String.trim` अपने एकमात्र पैरामीटर की तरह एक स्ट्रिंग लेता है, इसलिए बना हुआ फंक्शन भी यही लेता है।
`String.toInt` एक `Maybe Int` लौटाता है, इसलिए बना हुआ फंक्शन भी यही लौटाता है।
`String.trim` एक `String` लौटाता है, जिसे `String.toInt` पैरामीटर की तरह स्वीकार करता है, इसलिए यह उदाहरण कंपाइल हो जाता है।

अब हम अपना `sanitize` फंक्शन ऐसे फिर से लिख सकते हैं:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

ध्यान दीजिए कि अब हम वह `input` पैरामीटर इस्तेमाल नहीं करते जो मूल उदाहरण में दिखता है, हालाँकि काम बिल्कुल वही है।
अपने पैरामीटर का कोई ज़िक्र न करने वाले फंक्शन बनाने के इस तरीके को "पॉइंट फ्री स्टाइल" कहते हैं।
इस स्टाइल का फायदा यह है कि कोड ज़्यादा संक्षिप्त होता है, और नुकसान यह कि इसे समझना मुश्किल हो सकता है, खासकर शुरुआती लोगों के लिए।

यह ध्यान रखने लायक है कि Elm में सारे फंक्शन करीड होते हैं, इसलिए `String.length >> max` कंपाइल हो जाता है।

- [`(>>)`][forward-composition] ऑपरेटर का टाइप `(a -> b) -> (b -> c) -> (a -> c)` होता है।
- `String.length` का टाइप `String -> Int` है, जो `(a -> b)` वाला हिस्सा है, इसलिए `a` यानी `String` और `b` यानी `Int`।
- `max` का टाइप `Int -> Int -> Int` है, जो `b -> c` वाला हिस्सा है।
- `b` यानी `Int`, इसलिए `max` पार्शियल रूप से लगाया जाता है, तो `c` इस पार्शियल एप्लिकेशन का नतीजा है (`Int -> Int`)।
- इसलिए `String.length >> max` का टाइप `String -> (Int -> Int)` है।
- इसलिए `((String.length >> max) "123") 2` `3` लौटाता है, क्योंकि `"123"` की लंबाई 3 है, जो `Int` आर्गुमेंट वाले 2 से बड़ी है।

## फंक्शन डिज़ाइन

Elm में सुंदर कोड आसानी से लिखने के लिए, आपको मुख्य डेटा स्ट्रक्चर को फंक्शन का आखिरी पैरामीटर बनाना चाहिए।
स्टैंडर्ड लाइब्रेरी के सारे आम फंक्शन ऐसा ही करते हैं, जैसे `List.map` (नीचे टाइप सिग्नेचर दिया है)।

```elm
map : (a -> b) -> List a -> List b
```

यहाँ हम देख सकते हैं कि `map` फंक्शन का आखिरी पैरामीटर `List a` है और यह `List b` लौटाता है, इसलिए मुख्य डेटा स्ट्रक्चर (`List`) आखिरी पैरामीटर है।

इससे नीचे जैसा सुंदर पाइपलाइन वाला कोड लिखना मुमकिन हो जाता है।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

इससे पाइपलाइन के विकल्प के तौर पर फंक्शन कंपोज़िशन और पॉइंट फ्री स्टाइल का उपयोग करना भी सुविधाजनक हो जाता है।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

फंक्शन कंपोज़िशन की मदद से आप इस उदाहरण को `List.map` के एक ही कॉल तक छोटा कर सकते हैं।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
