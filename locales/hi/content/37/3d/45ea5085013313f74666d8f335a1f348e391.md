# परिचय

अपने प्रोग्राम में कस्टम टाइप बनाना अक्सर उपयोगी होता है।

नए प्रिमिटिव टाइप बनाना संभव है, लेकिन ऐसा कम ही किया जाता है।
बिल्ट-इन प्रिमिटिव टाइप कोई मनमाना चुनाव नहीं हैं: ये उन मानक टाइप से बहुत मेल खाते हैं जो LLVM कंपाइलर में होते हैं और जिसका Julia JIT कंपाइलेशन के लिए उपयोग करता है।

इससे कहीं ज़्यादा उपयोगी है नाम वाले फील्ड के साथ कंपोज़िट टाइप बनाने की क्षमता।

दूसरी भाषाओं में भी कुछ ऐसा ही होता है, जिन्हें वे `structs` या `records` कहती हैं।
Julia का डॉक्युमेंटेशन इन्हें `composite types` कहता है, हालाँकि थोड़े अंतर के साथ भाषा का सिंटैक्स इन्हें `struct` कीवर्ड से परिभाषित करता है।

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

ऊपर के उदाहरण में कुछ बातें ध्यान देने योग्य हैं:

- `id` के लिए कोई टाइप नहीं बताया गया है, इसलिए कंपाइलर इसे `id::Any` मानता है।
- टाइप का नाम ही कंस्ट्रक्टर की तरह इस्तेमाल होता है, जैसे `Person(id, name, age)`, और इससे टाइप `Person` का एक इंस्टेंस मिलता है।
- अलग-अलग फील्ड को डॉट नोटेशन से एक्सेस किया जा सकता है, ठीक वैसे ही जैसे नेम्ड ट्यूपल में।

टाइप `Person` की चीज़ें इम्यूटेबल होती हैं, इसलिए उन्हें बदला नहीं जा सकता।

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

अगर बदलाव की ज़रूरत हो, तो परिभाषा में `mutable` जोड़िए।

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

डिफॉल्ट रूप से कंस्ट्रक्टर चाहता है कि फील्ड उसी क्रम में दिए जाएँ जिस क्रम में परिभाषा में हैं। ज़्यादा जटिल टाइप के लिए यह असुविधाजनक हो जाता है।

`@kwdef` मैक्रो का उपयोग करने से दो नई सुविधाएँ मिलती हैं:

- कंस्ट्रक्टर फील्ड को क्रम से नहीं, कीवर्ड से लेता है।
- फील्ड के डिफॉल्ट वैल्यू हो सकती हैं, और ज़रूरी न हो तो उन्हें कंस्ट्रक्टर में छोड़ा जा सकता है।

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## कंपोज़िट टाइप के पदानुक्रम

अब तक हमने सिर्फ कंक्रीट कंपोज़िट टाइप बनाए हैं।
अगर आप जाँचें, तो ये सभी `Any` के सबटाइप हैं।

जब कई संबंधित टाइप बनाने हों, तो उनके लिए एक पदानुक्रम बनाना ज़्यादा तर्कसंगत लगता है।
यह बहुत आसानी से किया जा सकता है।

सबसे पहले एक एब्स्ट्रैक्ट टाइप बनाइए:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

इसके बाद टाइप की परिभाषा में `<:` ऑपरेटर लगाइए, जो यह संबंध बताता है।

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

जितनी बार ज़रूरत हो, यही दोहराइए, लेकिन ध्यान रखिए कि कंक्रीट टाइप का सबटाइपिंग मान्य नहीं है।

और जटिल पदानुक्रम के लिए ज़रूरत के हिसाब से एब्स्ट्रैक्ट सबटाइप बनाइए।

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

ऐसे पदानुक्रम की उपयोगिता तब और साफ हो जाएगी जब हम `Multiple Dispatch` कॉन्सेप्ट पर पहुँचेंगे और देखेंगे कि फंक्शन आर्गुमेंट के टाइप को कैसे संभालते हैं।
