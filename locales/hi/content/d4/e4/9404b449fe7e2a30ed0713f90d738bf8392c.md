# परिचय

JavaScript में एक अंतर्निहित ऑब्जेक्ट `Date` है। यह तारीख और समय संग्रहीत करता है और उनके प्रबंधन के लिए मेथड देता है।

सामान्य रूप से तारीखों के साथ काम करना जितना मुश्किल है, और टाइमज़ोन संभालने का तरीका जितना खराब या लगभग न के बराबर है, उसकी वजह से `moment.js`, `day.js`, `date-fns` और `luxon` जैसी बहुत सी लाइब्रेरी मौजूद हैं।
इनमें से कोई भी Exercism पर उपलब्ध नहीं है।

यह अभ्यास `Date` पर केंद्रित है, जो JavaScript के अंत तक प्रासंगिक बना रहेगा।

## निर्माण

`Date` ऑब्जेक्ट `Date` क्लास का एक इंस्टेंस होता है।
इसे कंस्ट्रक्टर फंक्शन को कोई आर्गुमेंट पास किए बिना बनाया जा सकता है।
इससे एक ऐसा `Date` ऑब्जेक्ट बनता है जो वर्तमान तारीख और समय दर्शाता है:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### **Unix टाइमस्टैम्प (संख्या)**

अगर कोई संख्या दी जाती है, तो उसे `timestamp` के रूप में समझा जाएगा।
टाइमस्टैम्प एक पूर्णांक संख्या है जो बताती है कि **1 जनवरी 1970 [UTC][defn-utc]+0** के बाद से कितने **मिलीसेकंड** बीत चुके हैं।

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

कोई यह सोच सकता है कि `new Date(0)` सबसे "शुरुआती" तारीख वाला ऑब्जेक्ट बनाएगा, लेकिन JavaScript तारीख को आपके लोकल टाइमज़ोन में बदल देता है। इसका मतलब है कि असल में सिर्फ वे लोग जिनका टाइमज़ोन [GMT / UTC+0][defn-gmt] है, उन्हें ही [Unix epoch][defn-unix-epoch] वैल्यू मिलेगी।

### **ISO 8601 टाइमस्टैम्प (स्ट्रिंग)**

आप `Date` कंस्ट्रक्टर को तारीख दर्शाने वाली एक स्ट्रिंग वैल्यू पास कर सकते हैं।
हर इम्प्लीमेंटेशन में एक जैसा रहने वाला **एकमात्र** फॉर्मेट अंतरराष्ट्रीय स्तर पर मान्य और मानकीकृत तथाकथित [ISO 8601 टाइमस्टैम्प स्ट्रिंग][defn-iso8601] का [सरल रूप][mdn-date-string-format] है।

[UTC][defn-gmt] में समय का एक क्षण ऐसा दिखता है:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

जहाँ नीचे दिए गए हिस्सों की जगह ये चीज़ें आती हैं:

| चिह्न | विवरण                                            | डिफॉल्ट |
| ----- | ------------------------------------------------ | ------- |
| YYYY  | कैलेंडर वर्ष, 4 अंकों में                        |         |
| MM    | कैलेंडर महीना, 2 अंकों में                       | 01      |
| DD    | कैलेंडर दिन, 2 अंकों में                         | 01      |
| T     | एक अक्षर T, जो तारीख को समय से अलग करता है       |         |
| HH    | 24 घंटे की घड़ी के घंटे, 2 अंकों में             | 00      |
| mm    | मिनट, 2 अंकों में                                | 00      |
| ss    | सेकंड, 2 अंकों में                               | 00      |
| mss   | मिलीसेकंड, 3 अंकों में                           | 000     |
| Z     | एक अक्षर Z, या एक ऑफसेट `+/-HH:mm`               |         |

अक्षर `Z` UTC दर्शाता है (न टाइमज़ोन, न डेलाइट सेविंग)।

चूँकि ज़्यादातर हिस्सों के लिए डिफॉल्ट वैल्यू मौजूद हैं, इसलिए अंत से कुछ हिस्से हटा देना भी सही है:

```text
YYYY-MM-DD
```

इसका डिफॉल्ट समय 00:00:00.000 होता है

अगर टाइमस्टैम्प `Z` पर खत्म नहीं होता, और `+HH:mm` या `-HH:mm` (यानी टाइमज़ोन ऑफसेट) पर भी नहीं खत्म होता, तो ऐतिहासिक कारणों से यह लागू होता है:

> जब टाइमज़ोन ऑफसेट मौजूद नहीं होता, तो सिर्फ तारीख वाले रूप UTC समय माने जाते हैं और तारीख-समय वाले रूप लोकल समय माने जाते हैं।
> UTC समय माने जाने की वजह स्पेक में हुई एक ऐतिहासिक गलती है, जो ISO 8601 से मेल नहीं खाती थी, लेकिन वेब कंपैटिबिलिटी की वजह से उसे बदला नहीं जा सका।
> देखिए [टूटा पार्सर: वेब की एक वास्तविक समस्या][ref-broken-parser]।

### **Date ऑब्जेक्ट**

किसी मौजूदा तारीख ऑब्जेक्ट को भी कंस्ट्रक्टर आर्गुमेंट के रूप में इस्तेमाल किया जा सकता है।
इससे मौजूदा `Date` ऑब्जेक्ट की एक कॉपी बनती है, जिसमें वही तारीख और समय होता है।

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### **तारीख और समय के अलग-अलग घटकों की वैल्यू देना**

सिर्फ तारीख दर्शाने वाली तारीख तीन संख्याएँ पास करके बनाई जा सकती है।
तारीख और समय दर्शाने वाली तारीख 6 संख्याएँ पास करके बनाई जा सकती है।

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

दूसरी वैल्यू `month` होती है, जो जनवरी के लिए `0` से शुरू होकर दिसंबर के लिए `11` तक जाती है।

## `Date.parse()`

आपको कहीं तारीख पार्स करने वाले फंक्शन `Date.parse` का ज़िक्र या संदर्भ मिल सकता है।
इस फंक्शन के लिए बहुत कम अपरिवर्तनीय (हमेशा सही) बातें हैं, और बाकी इम्प्लीमेंटेशन तय नहीं है (यानी मानक नहीं है), इसलिए इसका उपयोग नहीं करना चाहिए।

## `Date` के घटकों को एक्सेस करना

तारीख ऑब्जेक्ट पर कई मेथड होते हैं जो तारीख के घटक लौटाते हैं:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

इनमें से हर एक के लिए वैल्यू अपडेट करने वाला एक `set` रूप भी मौजूद है (जैसे `setFullYear`)।
सीमा से बढ़ी हुई कोई भी वैल्यू अगले घटक में चली जाती है:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

उन सभी मेथड के UTC रूप भी हैं जो लोकल टाइमज़ोन को नहीं मानते।

## तारीख को दूसरे रूप में बदलना

तारीख ऑब्जेक्ट में एक मेथड `getTime()` होता है, जो UNIX टाइमस्टैम्प मिलीसेकंड में लौटाता है, यानी 1 जनवरी 1970 की आधी रात, UTC से अब तक बीते मिलीसेकंड की संख्या।
इसके अलावा, तारीख ऑब्जेक्ट को ISO 8601 टाइमस्टैम्प स्ट्रिंग में बदलने के लिए एक मेथड `toISOString()` भी उपलब्ध है।

## तारीखों की तुलना करना

दो तारीखों के बीच, या किसी तारीख और संख्या के बीच, इससे बड़ा (`>`), इससे बड़ा या बराबर (`>=`), इससे छोटा (`<`) और इससे छोटा या बराबर (`<=`) सीधे इस्तेमाल किए जा सकते हैं।
यह इसलिए काम करता है क्योंकि JavaScript तारीख को एक प्रिमिटिव में बदलने की कोशिश करता है।

<!-- prettier-ignore -->
~~~exercism/advanced
दो तारीखों के बीच, या तारीख और संख्या के बीच तुलना करते समय, JavaScript [`[Symbol.toPrimitive]("number")`][mdn-to-primitive] को कॉल करता है, जो अंदर से [`date.valueOf()`][mdn-date-value-of] को कॉल करता है।

अगर आप इस व्यवहार पर निर्भर नहीं रहना चाहते, तो पहले `getTime()` से संख्या में बदल लीजिए।
