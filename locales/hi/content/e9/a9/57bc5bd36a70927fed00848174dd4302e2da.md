# परिचय

अब समय है C++ के एक मुख्य पैराडाइम, ऑब्जेक्ट-ओरिएंटेड प्रोग्रामिंग (OOP) की ओर बढ़ने का। OOP का केंद्र `classes` हैं, यानी ऐसे डेटा टाइप जिन्हें उपयोगकर्ता खुद बनाता है और जिनके अपने संबंधित फंक्शन होते हैं। हम बुनियादी बातों से शुरू करेंगे और सिलेबस में आगे चलकर और उन्नत विषयों पर भी बात करेंगे।

## सदस्य

क्लास में **सदस्य वेरिएबल** और **सदस्य फंक्शन** हो सकते हैं। इन्हें **सदस्य चयन** ऑपरेटर `.` से इस्तेमाल किया जाता है। `classes` के बाहर के वेरिएबलो की तरह ही, सदस्य वेरिएबलो को भी घोषित करते समय ही कोई वैल्यू देना अच्छा रहता है। यह वैल्यू तब इस क्लास से बनने वाले नए ऑब्जेक्ट के लिए डिफॉल्ट बन जाती है।

## एनकैप्सुलेशन और सूचना छिपाना

क्लास अपने सदस्यों तक पहुँच सीमित करने का विकल्प देती हैं। इसके दो बुनियादी रूप हैं: `private` और `public`. `private` सदस्य क्लास के बाहर से इस्तेमाल नहीं किए जा सकते। `public` सदस्यों को खुलकर कॉल किया जा सकता है। डिफॉल्ट रूप से सभी सदस्य `private` होते हैं और क्लास के बाहर इस्तेमाल करने के लिए उन्हें स्पष्ट रूप से चिह्नित करना पड़ता है।

## एक बुनियादी उदाहरण

नीचे दिए उदाहरण में एक नई `class` की परिभाषा देखी जा सकती है। परिभाषा के बाद लगे `;` पर ध्यान दीजिए।

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

आप क्लास के अंदर से हर वेरिएबल इस्तेमाल कर सकते हैं। `cast_spell` फंक्शन के अंदर मौजूद `damage` को देखिए। क्लास के बाहर से आप `private` सदस्यों को न पढ़ सकते हैं, न बदल सकते हैं:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## कंस्ट्रक्टर

कंस्ट्रक्टर ऑब्जेक्ट बनाते समय सदस्य वेरिएबलो को वैल्यू असाइन करने का मौका देते हैं। इनका नाम `class` जैसा ही होता है और इनका कोई रिटर्न टाइप नहीं होता। एक क्लास में कई कंस्ट्रक्टर हो सकते हैं। यह तब काम आता है जब आपको हर बार सारे वेरिएबल सेट करने की ज़रूरत न हो।

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

कंस्ट्रक्टर एक बड़ा विषय है और इसमें बहुत सारी बारीकियाँ हैं। अगर आप अपनी `class` के लिए साफ-साफ कोई `constructor` नहीं बनाते, तो कंपाइलर यह काम खुद कर देता है, और ऐसा वह सिर्फ तभी करता है। पहले वाले उदाहरण में यही हुआ है। _silverhand_ ऑब्जेक्ट डिफॉल्ट कंस्ट्रक्टर को कॉल करके बनाया गया है, कोई आर्गुमेंट पास नहीं किया गया। सारे वेरिएबल उस वैल्यू पर सेट कर दिए जाते हैं जो क्लास की परिभाषा में लिखी थी। अगर उस परिभाषा में आपने कोई वैल्यू न दी हो, तो वेरिएबल बिना शुरुआती वैल्यू के रह सकते हैं, जिसके अनजाने परिणाम हो सकते हैं।

## स्ट्रक्ट

स्ट्रक्ट भाषा की शुरुआती C जड़ों से आए हैं और C++ जितने ही पुराने हैं। ये वास्तव में `classes` जैसी ही चीज़ हैं, बस एक अहम अपवाद के साथ। डिफॉल्ट रूप से `class` में सब कुछ `private` होता है। स्ट्रक्ट दूसरी तरफ, जब तक अलग से तय न किया जाए, `public` होते हैं। परंपरा के तौर पर `struct` कीवर्ड का इस्तेमाल अक्सर **सिर्फ डेटा वाली संरचनाओं** के लिए किया जाता है। जिन ऑब्जेक्ट को कुछ गुण सुनिश्चित करने होते हैं, उनके लिए `class` कीवर्ड को प्राथमिकता दी जाती है। ऐसा ही एक नियम यह हो सकता है कि आपकी `Wizzard` `class` का `damage` कभी ऋणात्मक न हो। `damage` वेरिएबल private है, और जो भी फंक्शन damage बदलता है, वह इस नियम को बनाए रखना सुनिश्चित करेगा।
