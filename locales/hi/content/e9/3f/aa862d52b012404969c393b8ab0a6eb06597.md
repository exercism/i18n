# परिचय

[`Basics`][basics] कॉन्सेप्ट में फंक्शन बनाने के दो तरीके बताए गए थे।

सबसे सामान्य रूप में, बहु-पंक्ति वाला रूप:

```julia
function muladd(x, y, z)
    x * y + z
end
```

छोटी परिभाषाओं के लिए "असाइनमेंट", या "सिंगल-लाइन" रूप:
```julia
muladd(x, y, z) = x * y + z
```

तीसरे और इससे भी छोटे रूप में, एक छोटा, सिर्फ एक बार इस्तेमाल होने वाला फंक्शन बिना नाम के बनाया जा सकता है:

```julia-repl
julia> map(x -> 2x, 1:3)
4-element Vector{Int64}:
 2
 4
 6

julia> map((x, y) -> x * y, 1:3, 4:6)
3-element Vector{Int64}:
  4
 10
 18
```

इस स्थिति में, `x -> 2x` एक "अनाम फंक्शन" है।
यह वही चीज़ है जिसे कुछ अन्य भाषाएँ "लैम्ब्डा फंक्शन" कहती हैं।

ध्यान दीजिए कि कई आर्गुमेंट के लिए गोल ब्रैकेट चाहिए, जैसा कि `(x, y) -> x * y` में है।

अनाम फंक्शन Julia कोड में आम हैं, खासकर जब इन्हें `map()` और `filter()` जैसे हायर-ऑर्डर फंक्शन के साथ इस्तेमाल किया जाता है।

## फंक्शन के आर्गुमेंट

सिलेबस में अब तक हमने केवल ऐसे फंक्शन देखे हैं जिनमें आर्गुमेंट की एक निश्चित संख्या होती है, और फंक्शन कॉल में उन सभी को सही क्रम में देना ज़रूरी होता है।
यह सीमित और असुविधाजनक होता, इसलिए कई और विकल्प भी हैं।

### वैकल्पिक आर्गुमेंट

कई भाषाओं की तरह, Julia में फंक्शन की परिभाषा में अलग-अलग आर्गुमेंट के लिए डिफॉल्ट वैल्यू दी जा सकती है।

फिर फंक्शन कॉल में या तो उस आर्गुमेंट के लिए कोई वैल्यू दी जा सकती है, या उसे छोड़कर डिफॉल्ट पर निर्भर रहा जा सकता है।

```julia-repl
julia> f(x, y=10) = x * y
f (generic function with 2 methods)

julia> f(2, 3)
6

julia> f(2)
20
```

जिन आर्गुमेंट का डिफॉल्ट _नहीं_ है, वे सभी उन आर्गुमेंट से पहले आने चाहिए जिनका डिफॉल्ट _है_; यानी `f(x=2, y)` अमान्य होगा।

### कीवर्ड आर्गुमेंट

अब तक के सभी उदाहरण `positional arguments` इस्तेमाल करते हैं, जिनमें फंक्शन कॉल में दी गई वैल्यू का क्रम फंक्शन की परिभाषा में मौजूद संबंधित आर्गुमेंट के क्रम से मेल खाना चाहिए।

कई भाषाओं की तरह, Julia में `keyword arguments` भी इस्तेमाल किए जा सकते हैं।
फंक्शन कॉल में आर्गुमेंट का नाम बताना ज़रूरी होता है, लेकिन कई कीवर्ड आर्गुमेंट फिर किसी भी क्रम में दिए जा सकते हैं।

Julia की एक खास बात यह है कि फंक्शन की परिभाषा में कीवर्ड आर्गुमेंट (अगर हों) से पहले एक सेमीकोलन `;` लगाना ज़रूरी होता है, ताकि उन्हें किसी भी पोज़िशनल आर्गुमेंट से अलग किया जा सके।
फंक्शन कॉल में आखिरी पोज़िशनल आर्गुमेंट और पहले कीवर्ड आर्गुमेंट के बीच `;` या `,` में से कोई भी इस्तेमाल किया जा सकता है।

```julia-repl
julia> b(x; y) = x + y
b (generic function with 1 method)

julia> b(2, y=3)
5

# keyword is required when calling
julia> b(2, 3)
ERROR: MethodError: no method matching b(::Int64, ::Int64)
The function `b` exists, but no method is defined for this combination of argument types.
```

डिफॉल्ट वैल्यू वैकल्पिक रूप से दी जा सकती हैं, ठीक वैसे ही जैसे पोज़िशनल आर्गुमेंट के लिए दी जाती हैं।

जब पैरामीटर के समान नाम वाले वेरिएबल की गणना पहले ही की जा चुकी हो, तो फंक्शन कॉल में `myarg=myarg` जैसा सिंटैक्स आना आम बात है।
ऐसी स्थिति में एक संक्षिप्त सिंटैक्स की अनुमति होती है:

```julia-repl
julia> width = 4.0
4.0

julia> height = √ width
2.0

julia> area(; width, height) = width * height
area (generic function with 1 method)

# repetition
julia> area(; width=width, height=height)
8.0

# shorthand form
julia> area(; width, height)
8.0
```

### स्प्लैट और स्लर्प

अगर आप सोच रहे हों, तो ये Julia सिंटैक्स के एक उपयोगी पहलू के मानक नाम हैं।
दोनों `...` ऑपरेटर को दर्शाते हैं।

#### स्प्लैट

स्प्लैटिंग का उपयोग फंक्शन _कॉल_ में किया जाता है, ताकि संग्रह को उन अलग-अलग वैल्यू में खोला जा सके जो फंक्शन को चाहिए।

इसे समझाने से दिखाना ज़्यादा आसान होगा:

```julia-repl
julia> fxyz(x, y, z) = x * y * z
fxyz (generic function with 1 method)

julia> xyz = [2, 3, 4]
3-element Vector{Int64}:
 2
 3
 4

# Using the vector directly in a function call is invalid
julia> fxyz(xyz)
ERROR: MethodError: no method matching fxyz(::Vector{Int64})
The function `fxyz` exists, but no method is defined for this combination of argument types.

# splatting converts the vector to 3 numbers, used as positional arguments
julia> fxyz(xyz...)
24
```

कुछ "फंक्शन कॉल" सिंटैक्टिक शुगर के पीछे छिपे होते हैं, इसलिए स्प्लैटिंग का इस्तेमाल कम स्पष्ट तरीकों से भी किया जा सकता है।

उदाहरण के लिए, मल्टीपल असाइनमेंट अंदर से एक टपल कंस्ट्रक्टर फंक्शन इस्तेमाल करता है:

```julia-repl
julia> first, rest... = [1, 2, 3, 4]
4-element Vector{Int64}:
 1
 2
 3
 4

julia> first
1

julia> rest
3-element Vector{Int64}:
 2
 3
 4
```

कीवर्ड आर्गुमेंट भी स्प्लैटिंग से दिए जा सकते हैं, आम तौर पर `named tuple` इस्तेमाल करके। 
`Dict` भी काम करेगा, लेकिन उसकी कुंजियाँ सिंबल होनी चाहिए (स्ट्रिंग काम नहीं करेंगी)।

```julia-repl
# function with 3 keyword arguments
julia> fabc(; a, b, c) = a + b + c
fabc (generic function with 1 method)

# named tuple
julia> abc_nt = (a=2, b=3, c=4)
(a = 2, b = 3, c = 4)

# there are no positional arguments, so need to use ; before kw argument
julia> fabc(;abc_nt...)
9

# Dict
julia> abc_dict = Dict(:a=>2, :b=>3, :c=>4)
Dict{Symbol, Int64} with 3 entries:
  :a => 2
  :b => 3
  :c => 4

julia> fabc(;abc_dict...)
9
```

#### स्लर्प

स्लर्पिंग का उपयोग फंक्शन की _परिभाषा_ में किया जाता है, ताकि किसी भी संख्या में अलग-अलग वैल्यू को एक संग्रह में पैक किया जा सके।

```julia-repl
julia> f_more(i, j, more...) = i + j + sum(more)
f_more (generic function with 1 method)

julia> f_more(1, 3, 5, 7, 9, 11)
36
```

स्लर्प किए गए आर्गुमेंट का नाम (इस मामले में `more`) मायने नहीं रखता।
इस वेरिएबल का टाइप कंपाइलर चुनता है, लेकिन पोज़िशनल आर्गुमेंट के लिए यह संभवतः `tuple` या कुछ ऐसा ही होता है।

कीवर्ड आर्गुमेंट को भी स्लर्प किया जा सकता है, जिससे एक `Dict` (या ऐसा ही कुछ) मिलता है।

```julia-repl
julia> f_kwslurp(x, y; switches...) = :mult in keys(switches) ? x * y : x + y
f_kwslurp (generic function with 1 method)

julia> f_kwslurp(5, 6; mult=true)
30

julia> f_kwslurp(5, 6)
11
```

कॉल में कोई भी कीवर्ड आर्गुमेंट इस्तेमाल किए जा सकते हैं।
यह फंक्शन की परिभाषा तय करती है कि किन कीवर्ड का जवाब देना है और किन्हें नज़रअंदाज़ करना है।
