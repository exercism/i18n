# शर्तें

```sather
   if score >= 5 then
      return "Recalled";
   else
      return "Thank you";
   end;
```

`if` और `then` के बीच लिखी शर्त एक `BOOL` होनी चाहिए। Sather वहाँ कोई संख्या स्वीकार नहीं करता, इसलिए शून्य को गलत मानने की C जैसी आदत यहाँ नहीं चलती।

## ढाँचा

```sather
   if first_question then
      ...
   elsif second_question then
      ...
   elsif third_question then
      ...
   else
      ...
   end;
```

शर्तें ऊपर से नीचे तक एक-एक करके जाँची जाती हैं, और जो पहली शर्त सही निकलती है, वही जीत जाती है। उसके नीचे की हर शर्त बिना जाँचे छोड़ दी जाती है। इसीलिए शर्तों का क्रम सबसे विशिष्ट जाँच से शुरू होकर सबसे सामान्य जाँच तक जाना चाहिए: `score >= 5` को `score >= 8` के ऊपर रखने का मतलब है कि दूसरी जाँच तक कभी पहुँचा ही नहीं जाएगा।

`else` लिखना ज़रूरी नहीं है। `elsif` को जितनी बार चाहें, दोहराया जा सकता है।

## शर्तें स्टेटमेंट होती हैं, वैल्यू नहीं

`if` खुद कोई वैल्यू नहीं बनाता, इसलिए यह Sather में नहीं चलेगा:

```sather
   -- wrong
   grade := if score > 5 then "pass" else "fail" end;
```

या तो हर शाखा के अंदर से ही लौटाइए, या हर शाखा के अंदर किसी वेरिएबल को वैल्यू असाइन कीजिए।

## कब इसका उपयोग नहीं करना चाहिए

जो रूटीन यह बताता है कि कोई शर्त सही है या नहीं, उसे वही शर्त लौटा देना चाहिए:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;

   -- not this
   old_enough(age : INT) : BOOL is
      if age >= 13 then return true; else return false; end;
   end;
```

दूसरा वह कुछ नहीं कहता जो पहला नहीं कहता, और तीन गुना लंबा है।

## नेस्टिंग

एक `if` के अंदर दूसरा `if` भी रखा जा सकता है। अक्सर ऐसा करने की ज़रूरत नहीं पड़ती: जिन दो शर्तों का सही होना ज़रूरी है, उन दोनों को इसके बजाय `and` से जोड़ा जा सकता है, जो पढ़ने में बेहतर लगता है।

```sather
   if score >= 8 and sings then
      return "Lead";
   end;
```
