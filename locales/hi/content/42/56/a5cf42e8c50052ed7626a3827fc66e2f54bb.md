# परिचय

## पैरामीटर की डिफॉल्ट वैल्यू

[डिफॉल्ट पैरामीटर वैल्यू][default-parameter-values] फंक्शन के किसी भी पैरामीटर के लिए दी जा सकती है। इसके लिए पैरामीटर लिस्ट में उस पैरामीटर के टाइप एनोटेशन के बाद एक वैल्यू असाइन की जाती है। जब डिफॉल्ट वैल्यू दी गई हो, तो फंक्शन को कॉल करते समय कॉल करने वाला उस पैरामीटर को छोड़ सकता है, और उसकी जगह डिफॉल्ट वैल्यू इस्तेमाल की जाती है।

```swift
func greeting(name: String = "guest", duration: Int = 2) -> String {
  "Welcome, \(name). Enjoy your \(duration) night stay."
}

greeting(name: "Bobo", duration: 7)
// Returns "Welcome, Bobo. Enjoy your 7 night stay."
greeting(duration: 3)
// Returns "Welcome, guest. Enjoy your 3 night stay."
greeting(name: "Wynona")
// Returns "Welcome, Wynona. Enjoy your 2 night stay."
greeting()
// Returns "Welcome, guest. Enjoy your 2 night stay."
```

## वेरिएडिक पैरामीटर

[वेरिएडिक पैरामीटर][variadic-parameters] की मदद से कोई फंक्शन एक ही पैरामीटर के लिए किसी तय टाइप की शून्य या अधिक वैल्यू ले सकता है।
वेरिएडिक पैरामीटर बनाने के लिए पैरामीटर के टाइप एनोटेशन के आगे तीन बिंदु (`...`) लगाइए।

फंक्शन के अंदर Swift इन वैल्यू को बताए गए टाइप के ऐरे के रूप में उपलब्ध कराता है:

```swift
import Foundation

func geometricMean(_ numbers: Double...) -> Double {
    var total = 1.0
    for number in numbers {
        total *= number
    }
    return pow(total, 1.0 / Double(numbers.count))
}

let result = geometricMean(1, 2, 3, 4, 5)
// result is 2.605171084697352
```

~~~~exercism/note
अगर किसी फंक्शन में वेरिएडिक पैरामीटर के बाद और पैरामीटर भी हों, तो वेरिएडिक पैरामीटर के बाद आने वाले पहले पैरामीटर का आर्गुमेंट लेबल साफ़ तौर पर लिखा होना **ज़रूरी** है, ताकि Swift को पता चले कि वेरिएडिक आर्गुमेंट की सूची कहाँ खत्म होती है।
~~~~


## इन-आउट पैरामीटर

किसी फंक्शन के अंदर पैरामीटर को वेरिएबल नहीं, कॉन्स्टेंट माना जाता है। पैरामीटर की वैल्यू बदलने की कोशिश करने पर कंपाइल के समय एरर मिलती है।
अगर किसी फंक्शन को पैरामीटर की वैल्यू बदलनी है, तो उसे [_इन-आउट पैरामीटर_][in-out-parameters] इस्तेमाल करना होगा, ताकि यह साफ़ हो जाए कि वैल्यू बदली जा सकती है।

इन-आउट पैरामीटर इस्तेमाल करने के लिए प्रोग्रामर को तीन बातों का ध्यान रखना होता है:

1. फंक्शन बनाते समय पैरामीटर के टाइप एनोटेशन में `:` और टाइप के नाम के बीच `inout` कीवर्ड लिखकर इन-आउट पैरामीटर को साफ़ तौर पर चिह्नित करना होता है।
2. इन-आउट पैरामीटर को पास की जाने वाली वैल्यू वेरिएबल के रूप में घोषित होनी चाहिए, कॉन्स्टेंट के रूप में नहीं। इसी तरह वह कोई लिटरल भी नहीं हो सकती।
3. फंक्शन को कॉल करते समय वेरिएबल के नाम से पहले एक `&` लगाना होता है, जिससे साफ़ हो जाए कि इसे बदला जा सकता है।

ऐसा करने पर फंक्शन इन-आउट पैरामीटर की अंदर ही एक कॉपी बनाता है, फंक्शन के अंदर बताए अनुसार उसे बदलता है, और फिर फंक्शन लौटते समय बदली हुई वैल्यू को उसी वेरिएबल में वापस कॉपी कर देता है जो पास की गई थी।

```swift
func updateVersion(_ record: inout (version: Int, title: String)) {
  record.version += 1
}

var dbRecord = (version: 2, title: "Exercism")
updateVersion(&dbRecord)

// dbRecord is now (3, "Exercism")
```

~~~~exercism/warning
इन-आउट पैरामीटर के बारे में दो-एक अतिरिक्त नियम भी ध्यान में रखने चाहिए।

1  इन-आउट पैरामीटर वाले फंक्शन के अंदर उस वेरिएबल को संदर्भित नहीं किया जा सकता जो इन-आउट पैरामीटर के रूप में पास किया गया था।
2. एक ही फंक्शन में एक ही वेरिएबल को कई इन-आउट पैरामीटर के रूप में पास नहीं किया जा सकता।
   जैसे, `inoutFunc(&mutVar, &mutVar)` लिखने पर कंपाइलर एरर देता है।
~~~~

## नेस्टेड फंक्शन

Swift में आप [दूसरे फंक्शन के अंदर फंक्शन][nested-functions] बना सकते हैं।
इन्हें **नेस्टेड फंक्शन** कहते हैं।

नेस्टेड फंक्शन आम तौर पर ऐसे प्राइवेट हेल्पर होते हैं, जो अपने बाहरी फंक्शन के लिए कुछ खास काम करते हैं और बाहरी स्कोप को अव्यवस्थित नहीं करते:

```swift
func makeNumber(_ number: Int) -> Int {
    func double(_ x: Int) -> Int {
        x * 2
    }

    func increment(_ x: Int) -> Int {
        x + 1
    }

    return number.isMultiple(of: 2) ? increment(double(number)) : double(number)
}

print(makeNumber(3)) // Prints 6
print(makeNumber(4)) // Prints 9
```

नेस्टेड फंक्शन आम फंक्शन की तरह ही व्यवहार करते हैं, लेकिन इन्हें सिर्फ बाहरी फंक्शन के अंदर ही देखा जा सकता है।
