## प्रॉमिस का जीवनचक्र

एक `Promise` की तीन स्थितियाँ होती हैं:

1. pending
2. fulfilled
3. rejected

बनाते समय प्रॉमिस pending स्थिति में होता है।
भविष्य में किसी समय वह _resolve_ या _reject_ हो सकता है।
एक बार कोई प्रॉमिस resolve या reject हो जाए, तो वह दोबारा कभी resolve या reject नहीं हो सकता, और न ही उसकी स्थिति बदल सकती है।

दूसरे शब्दों में:

1. pending स्थिति में एक प्रॉमिस:
   - fulfilled या rejected, इन दोनों में से किसी भी स्थिति में जा सकता है।
2. fulfilled स्थिति में एक प्रॉमिस:
   - किसी भी अन्य स्थिति में नहीं जा सकता।
   - उसके पास एक वैल्यू होनी चाहिए, जो बदलनी नहीं चाहिए।
3. rejected स्थिति में एक प्रॉमिस:
   - किसी भी अन्य स्थिति में नहीं जा सकता।
   - उसके पास एक कारण होना चाहिए, जो बदलना नहीं चाहिए।

## प्रॉमिस को resolve करना

किसी प्रॉमिस को कई तरीकों से resolve किया जा सकता है:

```javascript
// Creates a promise that is immediately resolved
Promise.resolve(value);

// Creates a promise that is immediately resolved
new Promise((resolve) => {
  resolve(value);
});

// Chaining a promise leads to a resolved promise
somePromise.then(() => {
  // ...
  return value;
});
```

ऊपर के उदाहरणों में `value` _कुछ भी_ हो सकती है, जिसमें एक एरर, `undefined`, `null` या कोई दूसरा प्रॉमिस भी शामिल है।
आम तौर पर आप ऐसी वैल्यू के साथ resolve करना चाहते हैं जो एरर न हो।

## प्रॉमिस को reject करना

किसी प्रॉमिस को कई तरीकों से reject किया जा सकता है:

```javascript
// Creates a promise that is immediately rejected
Promise.reject(reason)

// Creates a promise that is immediately rejected
new Promise((_, reject) {
  reject(reason)
})

// Chaining a promise with an error leads to a rejected promise
somePromise.then(() => {
  // ...
  throw reason
})
```

ऊपर के उदाहरणों में `reason` _कुछ भी_ हो सकता है, जिसमें एक एरर, `undefined` या `null` भी शामिल है।
आम तौर पर आप एक एरर के साथ reject करना चाहते हैं।

## प्रॉमिस को chain करना

किसी प्रॉमिस के resolve या reject होने पर उसे भविष्य की किसी क्रिया के साथ _जारी रखा जा सकता है_।

- `promise` के resolve होने पर [`promise.then()`][promise-then] कॉल किया जाता है
- `promise` के reject होने पर [`promise.catch()`][promise-catch] कॉल किया जाता है
- `promise` के resolve या reject, किसी भी तरह पूरा होने पर [`promise.finally()`][promise-finally] कॉल किया जाता है

### **then**

हर प्रॉमिस "thenable" होता है।
इसका मतलब है कि उस पर एक `then` फंक्शन उपलब्ध होता है, जो मूल प्रॉमिस के resolve होने पर चलाया जाता है।
`promise.then(onResolved)` देने पर कॉलबैक `onResolved` को वह वैल्यू मिलती है जिसके साथ मूल प्रॉमिस resolve हुआ था।
यह हमेशा एक _नया_ प्रॉमिस लौटाता है, जो चेन में जुड़ जाता है।

`then` से कोई `value` लौटाने पर चेन में जुड़ा प्रॉमिस resolve हो जाता है।
`then` में कोई `reason` throw करने पर चेन में जुड़ा प्रॉमिस reject हो जाता है।

```javascript
const promise1 = new Promise(function (resolve, reject) {
  setTimeout(() => {
    resolve('Success!');
  }, 1000);
});

const promise2 = promise1.then(function (value) {
  console.log(value);
  // expected output: "Success!"

  return true;
});
```

यह लगभग 1000 ms के बाद `"Success!"` लॉग करेगा।
`promise1` की स्थिति `resolved` और वैल्यू `"Success!"` होगी।
`promise2` की स्थिति `resolved` और वैल्यू `true` होगी।

एक दूसरा आर्गुमेंट भी उपलब्ध है, जो मूल प्रॉमिस के reject होने पर चलता है।
`promise.then(onResolved, onRejected)` देने पर कॉलबैक `onResolved` को वह वैल्यू मिलती है जिसके साथ मूल प्रॉमिस resolve हुआ था, या कॉलबैक `onRejected` को वह कारण मिलता है जिसके साथ प्रॉमिस reject हुआ था।

```javascript
const promise1 = new Promise(function (resolve, reject) {
  setTimeout(() => {
    resolve('Success!');
  }, 1000);

  if (Math.random() < 0.5) {
    reject('Nope!');
  }
});

function log(value) {
  console.log(value);
  return true;
}

function shout(reason) {
  console.error(reason.toUpperCase());
  return false;
}

const promise2 = promise1.then(log, shout);
```

- लगभग आधे मामलों में यह करीब 1000 ms के बाद `"Success!"` लॉग करेगा।
  - `promise1` की स्थिति `resolved` और वैल्यू `"Success!"` होगी।
  - `promise2` की स्थिति `resolved` और वैल्यू `true` होगी।
- लगभग आधे मामलों में यह तुरंत `"NOPE!"` लॉग करेगा।
  - `promise1` की स्थिति `rejected` और वैल्यू `Nope!` होगी।
  - `promise2` की स्थिति `resolved` और वैल्यू `false` होगी।

यह समझना ज़रूरी है कि जीवनचक्र के नियमों की वजह से, जब कोई प्रॉमिस `reject` होता है, तो लगभग 1000ms बाद आने वाला `resolve` चुपचाप नज़रअंदाज़ कर दिया जाता है, क्योंकि एक बार reject या resolve हो जाने के बाद अंदरूनी स्थिति बदल नहीं सकती।
यह भी समझना ज़रूरी है कि किसी प्रॉमिस से कोई वैल्यू लौटाना उसे resolve कर देता है, और कोई वैल्यू throw करना उसे reject कर देता है।
जब `promise1` resolve होता है और उसके साथ एक चेन में जुड़ा `onResolved` होता है: `then(onResolved)`, तो वह आगे वाला एक नया प्रॉमिस होता है, जो resolve या reject हो सकता है।
जब `promise1` reject होता है, लेकिन उसके साथ एक चेन में जुड़ा `onRejected` होता है: `then(, onRejected)`, तो वह आगे वाला एक नया प्रॉमिस होता है, जो resolve या reject हो सकता है।

### **catch**

कभी-कभी आप एरर पकड़ना चाहते हैं और सिर्फ तभी आगे बढ़ना चाहते हैं जब मूल प्रॉमिस `reject` हो।
`promise.catch(onCatch)` देने पर कॉलबैक `onCatch` को वह कारण मिलता है जिसके साथ मूल प्रॉमिस reject हुआ था।
यह हमेशा एक _नया_ प्रॉमिस लौटाता है, जो चेन में जुड़ जाता है।

`catch` से कोई `value` लौटाने पर चेन में जुड़ा प्रॉमिस resolve हो जाता है।
`catch` में कोई `reason` throw करने पर चेन में जुड़ा प्रॉमिस reject हो जाता है।

```javascript
const promise1 = new Promise(function (resolve, reject) {
  setTimeout(() => {
    resolve('Success!');
  }, 1000);

  if (Math.random() < 0.5) {
    reject('Nope!');
  }
});

function log(value) {
  console.log(value);
  return 'done';
}

function recover(reason) {
  console.error(reason.toUpperCase());
  return 42;
}

const promise2 = promise1.catch(recover).then(log);
```

लगभग आधे मामलों में यह करीब 1000 ms के बाद `"Success!"` लॉग करेगा।
बाकी आधे मामलों में यह तुरंत `42` लॉग करेगा।

- अगर `promise1` resolve होता है, तो `catch` छोड़ दिया जाता है और यह `then` तक पहुँचकर वैल्यू लॉग करता है।
  - `promise1` की स्थिति `resolved` और वैल्यू `"Success!"` होगी।
  - `promise2` की स्थिति `resolved` और वैल्यू `"done"` होगी;
- अगर `promise1` reject होता है, तो `catch` चलाया जाता है, जो _एक वैल्यू लौटाता है_, और इस तरह चेन अब `resolved` हो जाती है, फिर यह `then` तक पहुँचकर वैल्यू लॉग करता है।
  - `promise1` की स्थिति `rejected` और वैल्यू `"Nope!"` होगी।
  - `promise2` की स्थिति `resolved` और वैल्यू `"done"` होगी;

### **finally**

कभी-कभी आप किसी प्रॉमिस के settle होने के बाद कोड चलाना चाहते हैं, चाहे वह resolve हो या reject।
`promise.finally(onSettled)` देने पर कॉलबैक `onSettled` को कुछ नहीं मिलता।
यह हमेशा एक _नया_ प्रॉमिस लौटाता है, जो चेन में जुड़ जाता है।

`finally` से कोई `value` लौटाने पर मूल प्रॉमिस की स्थिति और वैल्यू वैसी ही रहती हैं, और लौटाई गई `value` को अनदेखा कर दिया जाता है।
`finally` में कोई `reason` throw करने पर चेन में जुड़ा प्रॉमिस reject हो जाता है, और मूल प्रॉमिस की स्थिति, वैल्यू या कारण पर वही लिख देता है।

## उदाहरण

कई मेथड एक साथ:

```javascript
const myPromise = new Promise(function (resolve, reject) {
  const sampleData = [2, 4, 6, 8];
  const randomNumber = Math.round(Math.random() * 5);

  if (sampleData[randomNumber]) {
    resolve(sampleData[randomNumber]);
  } else {
    reject('Sampling did not result in a sample');
  }
});

const finalPromise = myPromise
  .then(function (sampled) {
    // If the random number was 0, 1, 2, or 3, this will be
    // reached and the number 2, 4, 6, or 8 will be logged.
    console.log(`Sampled data: ${sampled}`);
    return 'yay';
  })
  .catch(function (reason) {
    // If the random number was 4 or 5, this will be reached and
    // reason will be "An error occurred". The entire chain will
    // then reject with an Error with the reason as message.
    throw new Error(reason);
  })
  .finally(function () {
    // This will always log after either the sampled data is
    // logged or the error is raised.
    console.log('Promise completed');
  });
```

- जिन मामलों में `randomNumber` का मान `0-3` होता है:
  - `myPromise` वैल्यू `2, 4, 6, or 8` के साथ resolve होता है
  - `finalPromise` वैल्यू `'yay'` के साथ resolve होता है
  - दो लॉग होंगे:
    - `Sampled data: ...`
    - `Promise completed`
- जिन मामलों में `randomNumber` का मान `4-5` होता है:
  - `myPromise` कारण `'Sampling did not result in a sample'` के साथ reject होता है
  - `finalPromise` कारण `Error('Sampling did not result in a sample')` के साथ reject होता है
  - एक लॉग होगा:
    - `Promise completed`
    - _कुछ एनवायरनमेंट में_ यह `"uncaught rejected promise: Error('Sampling did not result in a sample')"` लॉग देगा

जैसा ऊपर दिखाया गया है, `reject` एक स्ट्रिंग के साथ भी काम करता है, और कोई प्रॉमिस एक `Error` के साथ भी reject कर सकता है।
