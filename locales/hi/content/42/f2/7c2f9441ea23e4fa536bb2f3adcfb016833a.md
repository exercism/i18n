# परिचय

## रिकॉर्ड

[रिकॉर्ड][records] ऐसे डेटा स्ट्रक्चर होते हैं जो जुड़ी हुई जानकारी को लेबल के साथ एक साथ रखते हैं। ये JavaScript या Java के ऑब्जेक्ट, या C या Rust के structs जैसे होते हैं, लेकिन इनमें कुछ खास फर्क हैं।

### रिकॉर्ड बनाना

रिकॉर्ड घुंघराले ब्रैकेट से [बनाए जाते हैं][create] और उनके एलिमेंट को कॉमा से अलग किया जाता है।

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

रिकॉर्ड का टाइप भी मिलते-जुलते सिंटैक्स से परिभाषित किया जाता है, बस बराबर के चिह्न `=` की जगह कोलन चिह्न `:` लगते हैं।

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

इन टाइप परिभाषाओं को बार-बार लिखना झंझट भरा है, इसलिए परिभाषा साझा करने के लिए [टाइप एलियस][record-types] का इस्तेमाल करना एक आम तरीका है।

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

टाइप एलियस रिकॉर्ड के लिए एक कंस्ट्रक्टर फंक्शन भी अपने आप बना देता है। यह कभी-कभी चौंकाने वाला लगता है, क्योंकि Elm में फंक्शन का नाम छोटे अक्षर से शुरू होना चाहिए। लेकिन टाइप कंस्ट्रक्टर इस नियम का एक अपवाद हैं।

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

### रिकॉर्ड के फील्ड तक पहुँचना

किसी रिकॉर्ड इंस्टेंस के फील्ड की वैल्यू [पढ़ने का मुख्य तरीका][access] डॉट नोटेशन है, जैसे `firefly.creator`।

Elm का कंपाइलर डॉट `.` से शुरू होने वाले खास एक्सेसर फंक्शन भी देता है, जैसे `.creator`, जो ऐसे किसी भी रिकॉर्ड पर काम करता है जिसमें उस नाम का फील्ड हो।

यह उस नियम का दूसरा अपवाद है कि फंक्शन का नाम छोटे अक्षर से ही शुरू होना चाहिए। वास्तव में, उपयोगकर्ता द्वारा बनाए गए फंक्शन का नाम छोटे अक्षर से शुरू होना चाहिए, लेकिन जिन दो उदाहरणों को हमने अभी देखा, उन्हें कंपाइलर बनाता है, प्रोग्रामर नहीं।

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

रिकॉर्ड को बाइंडिंग में [रिकॉर्ड पैटर्न मैचिंग][pattern-matching] के ज़रिए _डीस्ट्रक्चर_ भी किया जा सकता है। डीस्ट्रक्चरिंग किसी भी ऐसे रिकॉर्ड के साथ काम करती है जिसमें पैटर्न में लिखे नामों वाले फील्ड हों।

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

### रिकॉर्ड को बदलना

रिकॉर्ड अपरिवर्तनीय होते हैं, Elm में जैसे सब कुछ, इसलिए एक बार रिकॉर्ड परिभाषित हो जाने के बाद उसके फील्ड की वैल्यू कभी नहीं बदल सकती। किसी मौजूदा रिकॉर्ड की कॉपी बनाने, लेकिन उसके एक या अधिक फील्ड बदलने के लिए [एक खास सिंटैक्स][update] है। यह सिंटैक्स मूल रिकॉर्ड और बदलने वाले फील्ड को अलग पहचानने के लिए पाइप चिह्न `|` का इस्तेमाल करता है, जैसे `{ oldRecord | field1 = newValue }`।

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

### रिकॉर्ड की तुलना

Elm [स्ट्रक्चरल इक्वैलिटी][equality] का इस्तेमाल करता है, यानी एक ही रिकॉर्ड के दो इंस्टेंस जिनकी वैल्यू बिल्कुल समान हैं, बराबर माने जाते हैं।

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

### एक्सटेंसिबल रिकॉर्ड

Elm [स्ट्रक्चरल टाइपिंग][structural-typing] का भी समर्थन करता है, यानी अगर किसी फंक्शन को x और y फील्ड वाला रिकॉर्ड चाहिए, तो वह ऐसे किसी भी रिकॉर्ड के साथ काम करेगा जिसमें ये फील्ड हों, जैसे द्वि-आयामी बिंदु, त्रि-आयामी बिंदु, अंतरिक्ष यान, वगैरह।

ऐसे रिकॉर्ड टाइप की परिभाषा में पाइप `|` होता है, जैसे `{ a | x : Float, y : Float }`, और Elm की शब्दावली में इन्हें "एक्सटेंसिबल रिकॉर्ड" कहा जाता है।

टाइप परिभाषा में पाइप `|` और असली रिकॉर्ड इंस्टेंस में पाइप `|`, इन दोनों के फर्क का ध्यान रखिए। टाइप परिभाषा में पाइप `|` एक्सटेंसिबल रिकॉर्ड की परिभाषा (`{ a | x : Int }`) होता है, जबकि असली रिकॉर्ड इंस्टेंस में पाइप `|` का मतलब है कि हम उस रिकॉर्ड के कुछ फील्ड बदल रहे हैं।

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
