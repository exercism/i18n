# परिचय

Swift में कई तरह के टाइप होते हैं, लेकिन हर टाइप इन दो वर्गों में से किसी एक में आता है: _वैल्यू टाइप_ और _रेफरेंस टाइप_। Swift में [स्ट्रक्चर वैल्यू टाइप होते हैं][structs-are-value-types], जबकि [क्लास रेफरेंस टाइप होती हैं][classes-are-reference-types]।

वैल्यू टाइप और रेफरेंस टाइप में मुख्य अंतर यह है कि जब कोई वैल्यू टाइप किसी वेरिएबल या कॉन्स्टेंट को असाइन किया जाता है, या किसी फंक्शन को पास किया जाता है, तो असल में असाइन या पास उस वैल्यू की एक कॉपी होती है, वह वैल्यू खुद नहीं। स्ट्रक्चर की एक कॉपी में बदलाव करने से दूसरी कॉपियों पर कोई असर नहीं पड़ता। रेफरेंस टाइप में उस वैल्यू का एक रेफरेंस असाइन या पास होता है, इसलिए दो अलग-अलग नाम किसी क्लास के एक ही इंस्टेंस को दर्शा सकते हैं। ऐसे में किसी दूसरे नाम से इस्तेमाल करने पर मूल इंस्टेंस में भी बदलाव हो सकता है।

तो मान लीजिए किसी गेम में एक पात्र को परिभाषित करने वाले स्ट्रक्चर और क्लास हैं, और उनके गेम के आँकड़े भी। अब देखते हैं कि इन चीज़ों को कॉपी करके बदलने पर क्या होता है।

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

ध्यान दीजिए कि `charB` की प्रॉपर्टी बदलने का असर `charA` की प्रॉपर्टी पर भी पड़ा, क्योंकि दोनों नाम एक ही इंस्टेंस को दर्शाते हैं। यह भी ध्यान दीजिए कि दोनों पात्रों के आँकड़ों के मामले में, रेफरेंस टाइप के अंदर रखे वैल्यू टाइप उसी रेफरेंस टाइप के भीतर बदल जाते हैं। हालाँकि यह वैल्यू टाइप के व्यवहार का उल्लंघन नहीं है, क्योंकि `charA.stats` और `charB.stats`, `CharacterStats` का एक ही इंस्टेंस हैं: `charA` और `charB` दोनों `GameCharacter` क्लास के उसी इंस्टेंस को दर्शाते हैं। जैसा कि नीचे के उदाहरण से पता चलता है, इन वैल्यू टाइप की कॉपियाँ एक-दूसरे पर असर नहीं डालतीं।

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

इसी वजह से स्ट्रक्चर में उन मेथड के आगे `mutating` कीवर्ड लगाना पड़ता है जो स्ट्रक्चर की प्रॉपर्टी की स्थिति बदलते हैं। स्ट्रक्चर की कोई प्रॉपर्टी बदलने पर असल में उस स्ट्रक्चर की एक नई कॉपी बनती है, जिसमें उस प्रॉपर्टी के लिए नई वैल्यू सेट होती है, और यह नई कॉपी पुरानी कॉपी की जगह ले लेती है। यह एक दिखाई देने वाला संकेत है कि इस टाइप की वैल्यू के लिए यह कॉपी और बदलाव हो सकते हैं।

इसका एक साइड-इफेक्ट यह है कि जिन स्ट्रक्चर इंस्टेंस में बदल सकने वाली प्रॉपर्टी बदलती हैं, चाहे वह mutating फंक्शन कॉल करने से हो या सीधे असाइन करने से, उन्हें वेरिएबल में ही असाइन करना _ज़रूरी_ है, कॉन्स्टेंट में नहीं। वरना कंपाइलर एक एरर दिखाएगा:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

शुरुआती वैल्यू अब भी बनाई और इस्तेमाल की जा सकती हैं, लेकिन उन्हें बदला नहीं जा सकता। यह पाबंदी क्लास पर लागू नहीं होती। अगर किसी क्लास के इंस्टेंस को `let` से किसी नाम को दिया जाए, तो कॉन्स्टेंट में उस इंस्टेंस का जो रेफरेंस रखा जाता है, वही नहीं बदल सकता, इंस्टेंस खुद नहीं। यानी इंस्टेंस खुद बदल सकता है, लेकिन रेफरेंस को बदलकर किसी दूसरे इंस्टेंस की ओर नहीं किया जा सकता।

`let` या `var` से बने स्ट्रक्चर और क्लास में क्या-क्या बदला जा सकता है, इसका सारांश इस प्रकार है

|         | **struct**                                                                                  | **class**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | नाम को नया स्ट्रक्चर असाइन _नहीं_ किया जा सकता।</br>स्ट्रक्चर की कोई भी प्रॉपर्टी _नहीं_ बदली जा सकती। | नाम को नई क्लास असाइन _नहीं_ की जा सकती।</br>क्लास की बदल सकने वाली प्रॉपर्टी _बदली जा सकती हैं_। |
| **var** | नाम को नया स्ट्रक्चर असाइन _किया जा सकता है_।</br>स्ट्रक्चर की बदल सकने वाली प्रॉपर्टी _बदली जा सकती हैं_।   | नाम को नई क्लास असाइन _की जा सकती है_।</br>क्लास की बदल सकने वाली प्रॉपर्टी _बदली जा सकती हैं_।    |

## आइडेंटिटी

चूँकि दो अलग-अलग नाम किसी क्लास के एक ही इंस्टेंस का रेफरेंस रख सकते हैं, इसलिए कभी-कभी यह जाँचना उपयोगी होता है कि ऐसा है या नहीं। इसकी जाँच के लिए Swift `===` _आइडेंटिकल_ ऑपरेटर इस्तेमाल करता है, और इसके उलटे रूप `!==` का भी।

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

चूँकि दो नाम किसी स्ट्रक्चर के एक ही इंस्टेंस को नहीं दर्शा सकते, इसलिए ये आइडेंटिटी ऑपरेटर स्ट्रक्चर के लिए परिभाषित नहीं हैं।

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

ध्यान दीजिए कि आइडेंटिटी और समानता एक ही चीज़ नहीं हैं। कई परिभाषाओं के अनुसार `char1` और `char3` बराबर माने जाएँगे, क्योंकि उनकी सारी प्रॉपर्टी में एक ही वैल्यू होती हैं, लेकिन दोनों की आइडेंटिटी एक नहीं है। Swift में हर क्लास के लिए आइडेंटिटी अपने-आप उपलब्ध रहती है, लेकिन यह तय करने के लिए कि स्ट्रक्चर या क्लास के दो इंस्टेंस _बराबर_ हैं या नहीं, डेवलपर को आम तौर पर खुद के समानता ऑपरेटर लिखने पड़ते हैं। ऐसा करना इस अभ्यास के दायरे से बाहर है।
