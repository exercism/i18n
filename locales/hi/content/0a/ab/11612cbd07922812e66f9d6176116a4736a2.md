# परिचय

Elm टाइप जेनेरिक टाइप की अनुमति देते हैं, जो सामान्यतः किसी इंटरफ़ेस में लचीलापन जोड़ते हैं।
उदाहरण के लिए, `Maybe a` टाइप किसी भी टाइप की वैल्यू रख सकता है।

```elm
type Maybe a = Nothing | Just a
```

ध्यान दीजिए कि ऊपर के उदाहरण में टाइप पैरामीटर `a` बराबर चिह्न `=` के दोनों ओर इस्तेमाल होता है।
हम कहते हैं कि `a` टाइप की परिभाषा के अंदर किसी डेटा से बँधा होता है।

## फैंटम टाइप का तरीका

लेकिन कुछ मामलों में टाइप पैरामीटर समीकरण के सिर्फ बाईं ओर दिखाई देता है।

```elm
type Distance unit = Distance Float
```

ऊपर `Distance` की परिभाषा में `unit` एक फ्री टाइप पैरामीटर है, जो टाइप में किसी डेटा से नहीं बँधा होता।
हम इस टाइप को **फैंटम टाइप** भी कह सकते हैं।

जब हम कंपाइल के समय प्रतिबंध लागू करना चाहते हैं, तो यह आश्चर्यजनक रूप से उपयोगी होता है।
उदाहरण के लिए, हम यह सुनिश्चित करना चाहते हैं कि हम सिर्फ एक ही इकाई की दूरियाँ जोड़ें।

```elm
-- Distance is an opaque type, since the module does not expose its variants.
-- This means that users may only use the functions meter, foot and add to manipulate distances.
module Distance exposing (Distance, Meter, Foot, meter, foot, add)

-- The Distance type has a phantom type 'unit'.
type Distance unit = Distance Float

-- We define two types that will be used in place
-- of the phantom type 'unit' in our constructor functions.
type Meter = Meter
type Foot = Foot

-- Constructor for Meter
meter : Distance Meter
meter = Distance 1.0

-- Constructor for Foot
foot : Distance Foot
foot = Distance 0.3048

-- The add function cannot take two parameters of different types.
-- So we cannot add meters and feet by mistake.
add : Distance unit -> Distance unit -> Distance unit
add (Distance d1) (Distance d2) = Distance (d1 + d2)
```

उस मॉड्यूल के बाहर का कोड `Distance` टाइप के अंदरूनी हिस्से तक नहीं पहुँच सकता।
उपयोगकर्ता दो `Distance Meter` जोड़ सकते हैं, लेकिन एक `Distance Meter` को एक `Distance Foot` के साथ नहीं जोड़ सकते।

```elm
import Distance exposing (Distance)

-- Compiles
twoMeters = Distance.add Distance.meter Distance.meter

-- Does not compile
errDist = Distance.add Distance.meter Distance.foot
```

## फैंटम टाइप के रूप में एक्सटेंसिबल रिकॉर्ड

इस पर कोई प्रतिबंध नहीं है कि कौन से टाइप फैंटम हो सकते हैं, और रिकॉर्ड टाइप भी इस्तेमाल किए जा सकते हैं।
Elm रिकॉर्ड [एक्सटेंसिबल][extensible-records] होते हैं, जिसका मतलब है कि उनमें उनके घोषित फील्ड से ज़्यादा फील्ड हो सकते हैं।
जब फैंटम टाइप के रूप में इस्तेमाल होते हैं, तो रिकॉर्ड जटिल प्रतिबंध व्यक्त कर सकते हैं जो फंक्शन के ज़रिए बदल सकते हैं।

चलिए `Distance` मॉड्यूल के अंदर `LegoBlock` नाम की एक नई दूरी इकाई जोड़ते हैं।
भौतिक ब्लॉक, नियमों से बँधी वस्तुएँ होने के नाते, हमेशा दो प्रॉपर्टी रखते हैं: उनकी दूरियाँ गैर-भिन्नात्मक और गैर-ऋणात्मक होती हैं।

```elm
type LegoBlock = LegoBlock

fourStuds : Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
fourStuds = Distance 4.0
```

`nonFractional` और `nonNegative` एक ऐसे रिकॉर्ड के फील्ड हैं जो टाइप आर्गुमेंट के बाहर मौजूद नहीं होता, इसलिए उन्हें `()` टाइप देना उचित है, जिसे __यूनिट टाइप__ कहते हैं और जो इस तथ्य के अलावा कि वह वहाँ है, कोई जानकारी नहीं रखता।

मनमानी `LegoBlock` दूरियाँ प्राप्त करना निश्चित रूप से संभव है, उदाहरण के लिए दूरियों के अंतर या अनुपात निकालने के बाद।

```elm
negativeStud : Distance { properties | unit: LegoBlock, nonFractional : () }
negativeStud = Distance -1.0

threeFiddyStud : Distance { properties | unit: LegoBlock, nonNegative : () }
threeFiddyStud = Distance 3.50

crazyStud : Distance { properties | unit: LegoBlock }
crazyStud = Distance -13.37
```

ऊपर दी गई सभी वैल्यू मान्य हैं और कंपाइल हो जाएँगी। हालाँकि हमारी विशेष रुचि `fourStuds` जैसी वैल्यू में है, जिनमें `nonFractional` और `nonNegative` दोनों प्रॉपर्टी हैं, क्योंकि वे ऐसे भौतिक ब्लॉक दर्शाती हैं जिन्हें एक-दूसरे के साथ जोड़ा जा सकता है।

```elm
combineLegoBlocks
  :  Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
  -> Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
  -> Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
combineLegoBlocks = add
```

चलिए कुछ फंक्शन जोड़ते हैं ताकि उपयोगकर्ता `LegoBlock` दूरियाँ बना सकें और सुधार सकें।

```elm
newLegoBlock : Float -> Distance { properties | unit: LegoBlock }
newLegoBlock dist = Distance dist

floorDistance : Distance properties -> Distance { properties | nonFractional : () }
floorDistance (Distance dist) = Distance (toFloat (floor dist))

ceilingDistance : Distance properties -> Distance { properties | nonFractional : () }
ceilingDistance (Distance dist) = Distance (toFloat (ceiling dist))

absDistance : Distance properties -> Distance { properties | nonNegative : () }
absDistance (Distance dist) = Distance (abs dist)
```

ध्यान दीजिए कि `floorDistance`, `ceilingDistance` और `absDistance`, `LegoBlock` के अलावा दूसरी इकाइयों को भी संभाल सकते हैं। ये सामान्य रूप से इनपुट प्रॉपर्टी के बारे में कोई धारणा नहीं बनाते, बस गारंटी देते हैं कि आउटपुट में एक खास प्रॉपर्टी होगी, या तो `nonFractional` या `nonNegative`.

चलिए कुछ परिणाम देखते हैं।

```elm
import Distance exposing (Distance)

-- Compiles
distance1 = combineLegoBlocks fourStuds fourStuds

-- Does not compile
distance2 = combineLegoBlocks fourStuds threeFiddyStud

-- Compiles
distance3 = combineLegoBlocks fourStuds (floorDistance threeFiddyStud)

-- Does not compile
distance4 = combineLegoBlocks fourStuds negativeStud

-- Compiles
distance5 = combineLegoBlocks fourStuds (absDistance negativeStud)

-- Does not compile
distance6 = combineLegoBlocks fourStuds crazyStud

-- Compiles
distance7 = combineLegoBlocks fourStuds (floorDistance (absDistance crazyStud))

-- Compiles
distance8 = combineLegoBlocks fourStuds (ceilingDistance (absDistance crazyStud))
```

सामान्य रूप से `floorDistance` और `ceilingDistance` अलग-अलग परिणाम देते हैं, लेकिन एक जैसी गारंटी देते हैं।
यही फैंटम टाइप तरीके की शक्ति है: उपयोगकर्ताओं को लचीले विकल्प देते हुए मज़बूत गारंटी बनाए रखना।
