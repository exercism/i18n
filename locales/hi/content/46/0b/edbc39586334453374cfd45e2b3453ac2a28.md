# निर्देश परिशिष्ट

## `from_quote` के साथ टाइम लिटरल

`Time.from_quote` फंक्शन `"HH:MM:SS"` के रूप में लिखी गई स्ट्रिंग को पार्स करके एक `Time` बनाता है। इससे ऐसा कोड लिखना संभव हो जाता है:

```roc
time : Time
time = "00:01:23"
```

यह कोड कंपाइल होते समय अप्रत्यक्ष रूप से `Time.from_quote("00:01:23")` को कॉल करता है। इस तरीके से (या नीचे बताए गए दूसरे तरीकों से) कोड को कंपाइल होते समय चलाने से प्रोग्राम तेज़ चल सकता है, क्योंकि कोड चलते समय पार्सिंग और डेटा की जाँच संभालने की ज़रूरत नहीं पड़ती। साथ ही, इससे यह सुनिश्चित होता है कि गलत डेटा (जैसे किसी तारीख का गलत फॉर्मैट) कोड चलते समय नहीं, बल्कि कंपाइल होते समय ही अस्वीकार कर दिया जाता है, जिससे आपका ऐप ज़्यादा मज़बूत बनता है। अंत में, इससे कोड सुंदर और पढ़ने में आसान बनता है। उदाहरण के लिए, इस अभ्यास के टेस्ट में से एक यह है:

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

लेकिन इस कोड को पढ़ने वाला कोई व्यक्ति यह मान बैठ सकता है कि `advance_time` फंक्शन `Str` लेता है, जबकि वास्तव में वह `Time` लेता है। इससे उलझन और एरर हो सकती हैं। इसलिए आप शायद कुछ लंबा, पर ज़्यादा स्पष्ट रूप पसंद करें: `"00:00:05".Time`। यह भी कंपाइल होते समय `from_quote` को कॉल करता है।

अपने प्रोग्राम में आप इसके बजाय `from_str` इस्तेमाल करना पसंद कर सकते हैं:

```roc
Time := { ... }.{
    from_str : Str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

आप `from_str` (या कोई भी अन्य प्योर फंक्शन) कंपाइल होते समय भी कॉल कर सकते हैं, ऐसे:

```roc
Ok(time) = Time.from_str("00:01:23")
```

ध्यान दें: इस परिभाषा को टॉप लेवल पर रखने से यह कंपाइल होते समय चलती है (क्योंकि फंक्शन प्योर है और उसका इनपुट कंपाइल होते समय ही ज्ञात होता है)। किसी फंक्शन के अंदर आप `from_str` को कोड चलते समय इस्तेमाल कर सकते हैं।
