# परिचय

चारलिस्ट `~c` सिगिल की मदद से बनाए जाते हैं।

```elixir
~c"hello"
```

~~~~exercism/note
ध्यान दीजिए कि Elixir के पुराने वर्शन में चारलिस्ट को सिंगल कोट्स के साथ `'hello'` के रूप में लिखा जाता था।
~~~~

चारलिस्ट पूर्णांकों का एक ऐरे होता है। ये पूर्णांक किसी अक्षर के Unicode मान को दर्शाते हैं, जिन्हें कोड पॉइंट भी कहा जाता है।

```elixir
[65, 66, 67]
# => ~c"ABC"
```

## चारलिस्ट _ऐरे_ होते हैं

```elixir
~c"" === []
# => true

is_list(~c"hello")
# => true
```

चूँकि चारलिस्ट ऐरे होते हैं, आप इन पर किसी भी दूसरे ऐरे की तरह काम कर सकते हैं। इसके लिए रिकर्शन और पैटर्न मैचिंग इस्तेमाल कीजिए, या [`List`][list] मॉड्यूल का उपयोग कीजिए।

```elixir
[first_letter | _] = ~c"cat"
first_letter
# => 99

List.first(~c"hello")
# => 104
List.pop_at(~c"hello", 0)
# => {104, ~c"ello"}

```

आप दो ऐरे को [`++`][kernel-concat-list] की मदद से आपस में जोड़ सकते हैं।

```elixir
~c"hi" ++ ~c"!"
# => ~c"hi!"
```

पहला ऐरे जितना लंबा होगा, जोड़ना उतना ही धीमा होगा। इसलिए मनमानी लंबाई वाले ऐरे में बार-बार एलिमेंट जोड़ते रहने से बचिए।

## प्रिंट होने की क्षमता

अगर पूर्णांकों के किसी ऐरे में सिर्फ ऐसे पूर्णांक हों जो प्रिंट हो सकने वाले अक्षरों के कोड पॉइंट हैं, तो उसे चारलिस्ट के रूप में प्रदर्शित किया जाएगा। भले ही उसे `[]` सिंटैक्स से बनाया गया हो।

```elixir
~c"ABC"
# => ~c"ABC"

[65, 66, 67]
# => ~c"ABC"
```

अगर पूर्णांकों के किसी ऐरे में ऐसे अक्षर का एक भी कोड पॉइंट हो जो प्रिंट नहीं हो सकता (जैसे `0-6`, `14-26`, `28-31`), तो उसे ऐरे के रूप में प्रदर्शित किया जाएगा। भले ही उसे `~c""` सिंटैक्स से बनाया गया हो।

```elixir
~c"ABC\0"
# => [65, 66, 67, 0]

[65, 66, 67, 0]
# => [65, 66, 67, 0]
```

प्रिंट होने की क्षमता [`List.ascii_printable?`][list-ascii-printable] से जाँची जा सकती है।

```elixir
List.ascii_printable?([65, 66, 67])
# => true
List.ascii_printable?([65, 66, 67, 0])
# => false
```

ध्यान रखिए कि ये एक ही डेटा को _प्रदर्शित_ करने के दो अलग तरीके हैं। वैल्यू पूरी तरह बराबर होती हैं।

```elixir
~c"ABC" === [65, 66, 67]
# => true
```

[`IO.inspect`][io-inspect] से किसी ऐरे को प्रिंट करते समय आप [`:charlists`][inspect-opts] विकल्प इस्तेमाल कर सकते हैं, जिससे यह तय होता है कि ऐरे कैसे प्रिंट होंगे।

```elixir
IO.inspect(~c"ABC", charlists: :as_charlists)
# => prints ~c"ABC"

IO.inspect(~c"ABC", charlists: :as_lists)
# => prints [65, 66, 67]
```

## कोड पॉइंट

किसी अक्षर के आगे `?` लगाकर आप उसका कोड पॉइंट पा सकते हैं।

```elixir
?A
# => 65

[?:, ?)]
# => ~c":)"
```

## चारलिस्ट बनाम स्ट्रिंग

एक जैसे अक्षरों से बने चारलिस्ट और स्ट्रिंग बराबर नहीं माने जाते।

```elixir
~c"hello" == "hello"
false
```

चारलिस्ट में हर वैल्यू किसी अक्षर का [Unicode कोड पॉइंट][unicode-table] होती है, जबकि स्ट्रिंग में कोड पॉइंट [UTF-8][utf8] के रूप में एन्कोड किए जाते हैं।

```elixir
IO.inspect(~c"tschüss", charlists: :as_lists)
# => prints [116, 115, 99, 104, 252, 115, 115]

IO.inspect("tschüss", binaries: :as_binaries)
# => prints <<116, 115, 99, 104, 195, 188, 115, 115>>
```

ध्यान दीजिए कि `ü`, जिसका कोड पॉइंट `252` है, UTF-8 में `195` और `188` के रूप में एन्कोड होता है।

**व्यवहार में चारलिस्ट बहुत कम इस्तेमाल होते हैं**। इनका मुख्य उपयोग Erlang के साथ काम करना है, खास तौर पर ऐसी पुरानी लाइब्रेरी इस्तेमाल करते समय जो आर्गुमेंट के रूप में बाइनरी स्वीकार नहीं करतीं।

Elixir के साथ काम करते समय टेक्स्ट संग्रहीत करने के लिए **स्ट्रिंग इस्तेमाल कीजिए**। `String` मॉड्यूल टेक्स्ट को प्रोसेस करने के लिए कई फंक्शन देता है, ऐसे फंक्शन जो चारलिस्ट के लिए उपलब्ध नहीं हैं।

चारलिस्ट को [`to_string`][kernel-to-string] से स्ट्रिंग में बदला जा सकता है।

```elixir
to_string(~c"hello")
# => "hello"
```
