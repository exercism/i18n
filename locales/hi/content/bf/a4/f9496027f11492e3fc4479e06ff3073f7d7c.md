# परिचय

## कमेंट

Exercism में x86-64 ट्रैक अपने असेंबलर के रूप में **NASM** (The Netwide Assembler) का उपयोग करता है।
NASM में कमेंट से पहले सेमीकोलन (`;`) लगाया जाता है।

कमेंट प्रोग्राम में कहीं भी लिखे जा सकते हैं। `;` के बाद लिखी हर चीज़ को असेंबलर नज़रअंदाज़ कर देता है।

## कॉन्स्टेंट

NASM में **equ** की मदद से असेंबलर के समय का कॉन्स्टेंट बनाया जा सकता है।
जैसे यहाँ `UNIVERSE` नाम का कॉन्स्टेंट `42` वैल्यू के साथ बनाया गया है:

```x86asm
UNIVERSE equ 42
```

कॉन्स्टेंट का मूल्यांकन बनाते समय एक ही बार होता है। बाद में उन्हें दोबारा परिभाषित नहीं किया जा सकता।

## जनरल पर्पज़ रजिस्टर (GPRs)

असेंबली में हम आम तौर पर वेरिएबल की जगह रजिस्टरों में वैल्यू रखते हैं।
**CPU रजिस्टर** कंप्यूटर के प्रोसेसर के अंदर मौजूद तेज़ मेमोरी का एक टुकड़ा होता है।
अधिकांश गणनाएँ CPU के रजिस्टरों में ही होती हैं।

कुछ रजिस्टर कई तरह की अलग-अलग गणनाओं के लिए इस्तेमाल होते हैं। इन्हें **जनरल पर्पज़ रजिस्टर (GPRs)** कहा जाता है।
बाकी रजिस्टरों के अपने खास या निर्धारित काम होते हैं।

x86-64 में 16 जनरल पर्पज़ रजिस्टर (GPRs) हैं, जो 64 बिट के होते हैं। इन्हें 32 बिट, 16 बिट या 8 बिट के रूप में भी एक्सेस किया जा सकता है।
GPRs नीचे दिए गए हैं। इनमें `rn` के `n` का मान 8 से 15 तक होता है: `r8`, `r9`, `r10`, `r11`, `r12`, `r13`, `r14` और `r15`.

| 64-bit | 32-bit | 16-bit | 8-bit |
| :----: | :----: | :----: | :---: |
|  rax   |  eax   |   ax   | ah/al |
|  rbx   |  ebx   |   bx   | bh/bl |
|  rcx   |  ecx   |   cx   | ch/cl |
|  rdx   |  edx   |   dx   | dh/dl |
|  rsi   |  esi   |   si   |  sil  |
|  rdi   |  edi   |   di   |  dil  |
|  rbp   |  ebp   |   bp   |  bpl  |
|  rsp   |  esp   |   sp   |  spl  |
|   rn   |  rnd   |  rnw   |  rnb  |

जब 64 बिट से कम का उपयोग होता है, तो आम तौर पर रजिस्टर के निचले हिस्से वाली बिट ही एक्सेस होती हैं।
इस नियम का अपवाद `ah`, `bh`, `ch` और `dh` हैं, जो रजिस्टर के 16 बिट वाले हिस्से के ऊपरी 8 बिट एक्सेस करते हैं।

नीचे दिखाया गया है कि `rax` रजिस्टर की बिट कैसे एक्सेस होती हैं:

```
+--------+---------------------------------------+
| 64-bit |                  rax                  |
+--------+-------------------+-------------------+
| 32-bit |                   |        eax        |
+--------+-------------------+---------+---------+
| 16-bit |                             |    ax   |
+--------+-----------------------------+----+----+
| 8-bit  |                             | ah | al |
+--------+-----------------------------+----+----+
```

इनमें से कुछ रजिस्टरों को फंक्शन कॉल के दौरान सुरक्षित रखना ज़रूरी है: `rbp`, `rsp`, `rbx`, `r12`, `r13`, `r14` और `r15`.
इन्हें सुरक्षित न रखने पर एरर आ सकती है या अपरिभाषित व्यवहार हो सकता है।

बाकी रजिस्टरों को सुरक्षित रखना ज़रूरी नहीं है, और उन्हें खुलकर इस्तेमाल किया जा सकता है: `rax`, `rcx`, `rdx`, `rdi`, `rsi`, `r8`, `r9`, `r10` और `r11`.

~~~~exercism/caution
सिलेबस में आगे आप सीखेंगे कि रजिस्टरों को कैसे सुरक्षित रखा जाता है।
फिलहाल सिर्फ दूसरे तरह के रजिस्टर इस्तेमाल कीजिए: `rax`, `rcx`, `rdx`, `rdi`, `rsi`, `r8`, `r9`, `r10` और `r11`.
~~~~

## निर्देश

निर्देश गणना के वे टुकड़े हैं जो CPU कर सकता है।
इनका रूप आम तौर पर ऐसा होता है:

```x86asm
name destination, source
```

यानी पहले निर्देश का नाम आता है, फिर कम से कम एक खाली जगह, उसके बाद डेस्टिनेशन ऑपरेंड, फिर कॉमा (`,`) और अंत में सोर्स ऑपरेंड।
निर्देश आम तौर पर सोर्स ऑपरेंड को नहीं बदलता, सिर्फ डेस्टिनेशन ऑपरेंड को बदलता है।

जब तक कुछ और न कहा जाए, दोनों ऑपरेंड का साइज़ एक ही होना चाहिए।
जैसे अगर सोर्स ऑपरेंड 16 बिट का है, तो डेस्टिनेशन ऑपरेंड भी 16 बिट का होना चाहिए।

जैसे किसी रजिस्टर में वैल्यू रखने के लिए हम `mov` निर्देश इस्तेमाल कर सकते हैं:

```x86asm
mov rax, rdx  ; rax = rdx
              ; mov is the name, rax is the destination operand and rdx is the source operand
```

ऊपर दिया गया कोड `rdx` (सोर्स ऑपरेंड) के सभी 64 बिट की सामग्री को `rax` के सभी 64 बिट में कॉपी करता है। यहाँ `rax` इस निर्देश का डेस्टिनेशन ऑपरेंड है।

अधिकांश निर्देशों में कॉन्स्टेंट पूर्णांक संख्याओं को सोर्स ऑपरेंड के रूप में इस्तेमाल किया जा सकता है (डेस्टिनेशन ऑपरेंड के रूप में नहीं):

```x86asm
mov rcx, 42 ; rcx = 42
            ; rcx is the destination operand and 42 is the source operand
```

ध्यान दीजिए कि 32 बिट के रजिस्टर में लिखने से ऊपरी बिट भी साफ़ हो जाते हैं। इसलिए `mov eax, 42` और `mov rax, 42` एक ही बात है।
16 बिट और 8 बिट के रजिस्टरों के लिए यह सच नहीं है।

जोड़, घटाव और गुणा जैसी अंकगणितीय क्रियाओं के लिए हम `add`, `sub` और `imul` निर्देश इस्तेमाल कर सकते हैं:

```x86asm
add rax, rsi ; rax = rax + rsi
imul rax, rdi ; rax = rax * rdi
sub rax, r8 ; rax = rax - r8
```

## फंक्शन

निर्देश फंक्शनों में व्यवस्थित रहते हैं।
सभी फंक्शन सोर्स फाइल के **section .text** में रखे जाते हैं।

फंक्शन की घोषणा में ये चीज़ें होती हैं:

1. फंक्शन के नाम वाला एक लेबल, जिसके बाद `:`।
2. वे निर्देश जो फंक्शन बनाते हैं।
3. फंक्शन से लौटने वाला निर्देश, `ret`।

यह ट्रैक System V AMD64 ABI कॉलिंग कन्वेंशन इस्तेमाल करता है। इसमें फंक्शन के पहले छह पूर्णांक आर्गुमेंट रजिस्टरों में पास किए जाते हैं।
इन्हें इस क्रम में पास किया जाता है: `rdi`, `rsi`, `rdx`, `rcx`, `r8` और `r9`।

फंक्शन से पूर्णांक वैल्यू `rax` रजिस्टर में लौटाई जाती है।

फंक्शन को कॉल करने के लिए हम `call` निर्देश इस्तेमाल करते हैं।
किसी फंक्शन को उसी सोर्स फाइल में कहीं भी कॉल किया जा सकता है।
किसी फंक्शन को दूसरी सोर्स फाइलों के लिए दिखाने के लिए `global` डायरेक्टिव इस्तेमाल करना ज़रूरी है।

जैसे यहाँ `sum` नाम का फंक्शन घोषित किया गया है:

```x86asm
section .text ; functions are placed here

global sum ; sum is visible to other source files

sum:
    ; first argument is passed in rdi
    ; second argument is passed in rsi
    ; return value is placed in rax

    mov rax, rdi ; rax is now equal to rdi
    add rax, rsi ; rax = rax + rsi

    ret ; function return
```

और यहाँ हमारे `sum` फंक्शन को 3 और 5 आर्गुमेंट के साथ कॉल किया गया है:

```x86asm
mov rdi, 3  ; First argument in rdi
mov rsi, 5  ; Second argument in rsi
call sum

; The rax register now contains the value 8 (3 + 5), after sum returns
```
