# परिचय

## एक्सेप्शन

C# में एक्सेप्शन, रनटाइम के दौरान होने वाली एरर स्थितियों को संभालने का एक व्यवस्थित, एक-जैसा और टाइप-सुरक्षित तरीका देते हैं। ऐप्लिकेशन को क्रैश होने से बचाने के लिए एक्सेप्शन और एरर को ठीक से संभालना ज़रूरी है।

C# में सभी एक्सेप्शन का बेस टाइप `System.Exception` क्लास होती है। इसमें `Message` जैसी ज़रूरी प्रॉपर्टी होती हैं, जिनमें इंसान के पढ़ने लायक भाषा में लिखा होता है कि एक्सेप्शन क्यों थ्रो हुआ।

कोड के किसी हिस्से में एरर होनी चाहिए, यह बताने के लिए एक नया एक्सेप्शन ऑब्जेक्ट बनाना पड़ता है और फिर `throw` कीवर्ड से उसे थ्रो करना पड़ता है:

```csharp
using System;
static int Square(int number)
{
    if (number >= 46341)
    {
        throw new ArgumentException($"Argument {number} cannot be higher than 46340 as its' square doesn't fit into int type.");
    }
    return number * number;
}
```

जब कोई एक्सेप्शन थ्रो होता है, तो रनटाइम का काम ऐसा कोड ढूँढना होता है जो उस एक्सेप्शन को संभालने का ज़िम्मा उठाए। अगर कोई सही हैंडलर न मिले, तो रनटाइम प्रोग्राम को चलना बंद कर देता है और साथ ही अनहैंडल्ड एक्सेप्शन का संदेश भी दिखाता है।

किसी एक्सेप्शन के लिए हैंडलर बनाने के लिए C# में try-catch स्टेटमेंट इस्तेमाल होता है, जिसमें एक `try` ब्लॉक और एक या अधिक `catch` क्लॉज़ होते हैं। `try` ब्लॉक में वह कोड रहता है जिससे एक्सेप्शन थ्रो हो सकता है, और यही ब्लॉक उसकी निगरानी करता है। `catch` क्लॉज़ में वह कोड रहना चाहिए जो एरर होने के बाद प्रोग्राम का व्यवहार संभालता है। ध्यान रखने वाली बात यह है कि `try` ब्लॉक के बाद एक्सेप्शन का क्रम मायने रखता है, क्योंकि जब कई एक्सेप्शन दिए गए हों, तो सबसे पहला मेल खाने वाला `catch` क्लॉज़ ही चलता है।

```csharp
try
{
   if (number == 42)
   {
       throw new ArgumentException("The number cannot be equal to 42.", "number");
   }

   if (number < 0)
   {
      throw new ArgumentOutOfRangeException("number", "The number cannot be negative.");
   }

    // Process number ...
}
catch (ArgumentOutOfRangeException e)
{
    Console.WriteLine($"Number is out of range: {e.Message}.");
}
catch (ArgumentException)
{
    Console.WriteLine("Invalid number.");
}
```
