# परिचय

टपल किसी अन्य टपल का विस्तार कर सकते हैं। `TUPLE: child < parent slots ;` से ऐसी क्लास घोषित होती है जिसके इंस्टेंस `parent` के भी इंस्टेंस होते हैं। इन्हें अपने स्लॉट के अतिरिक्त parent के स्लॉट भी मिलते हैं, और parent के एक्सेसर इन पर भी वैसे ही काम करते हैं जैसे वे child पर ही परिभाषित हुए हों।

```factor
USING: accessors ;

TUPLE: animal name age ;
TUPLE: dog < animal breed ;

"Rex" 4 "labrador" dog boa .
! => T{ dog { name "Rex" } { age 4 } { breed "labrador" } }

"Rex" 4 "labrador" dog boa name>> .   ! => "Rex"   (inherited accessor)
```

## `boa` स्लॉट का क्रम

`boa` कंस्ट्रक्टर स्लॉट *घोषणा के क्रम में, पहले पैरेंट* लेता है। ऊपर दिए गए `dog` के लिए:

```
dog boa ( name age breed -- dog )
```

एक और अगली पीढ़ी की क्लास, `puppy < dog `, जो `weeks` जोड़ती है, ऐसी होगी:

```
puppy boa ( name age breed weeks -- puppy )
```

## प्रेडिकेट का पदानुक्रम

हर `TUPLE:` घोषणा एक प्रेडिकेट (`name?`) बनाती है। इनहेरिटेंस के साथ ये प्रेडिकेट एक के अंदर एक हो जाते हैं। हर वंशज अपने पूर्वजों के प्रेडिकेट को संतुष्ट करता है:

```factor
"Rex" 4 "labrador" dog boa
dup dog? .        ! => t
dup animal? .     ! => t
```

इसका उल्टा सही नहीं है: जो `animal` `dog` नहीं है, वह `dog?` में फेल हो जाता है।

## आगे की बात

जेनेरिक मेथड (`M:`, जिन्हें [`generics`][generics] में पढ़ाया गया है) भी पदानुक्रम में ऊपर की ओर डिस्पैच करते हैं। `animal` पर बना मेथड हर वंशज के लिए चलता है, जब तक कि कोई अधिक विशिष्ट ओवरराइड प्राथमिकता न ले ले। यह आप इस अभ्यास के ठीक बाद `boatswains-bilge` में देखेंगे।
