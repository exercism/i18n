# हियर डॉक्युमेंट का परिचय

Bash स्क्रिप्टिंग में "हियर डॉक्युमेंट" (या "हियरडॉक") इनपुट की कई लाइनों को किसी कमांड या प्रोग्राम को इस तरह भेज देता है, जैसे आप उन्हें सीधे टर्मिनल में टाइप कर रहे हों।
यह आपकी स्क्रिप्ट के अंदर, बिना किसी बाहरी फाइल या स्ट्रिंग बदलने के जटिल काम की ज़रूरत के, कई लाइनों वाला टेक्स्ट शामिल करने का एक शक्तिशाली टूल है।

## मुख्य विशेषताएँ और सिंटैक्स

1. डेलिमिटर: हियरडॉक `<<` ऑपरेटर से शुरू होता है, जिसके बाद एक डेलिमिटर शब्द आता है (इसे अक्सर "मार्कर" या "टर्मिनेटर" भी कहा जाता है)।
   यह डेलिमिटर आपकी पसंद का कोई भी शब्द हो सकता है, लेकिन स्पष्टता के लिए आमतौर पर `EOF`, `END` या `TEXT` जैसा कुछ इस्तेमाल किया जाता है।
   ज़्यादा पढ़ने लायक कोड के लिए आप डेलिमिटर के तौर पर कोई वर्णनात्मक शब्द भी रख सकते हैं, जैसे `END_INSTALLATION_INSTRUCTIONS`।

1. कंटेंट: शुरुआती `<< DELIMITER` के बाद आप वह कंटेंट लिखते हैं जिसे रीडायरेक्ट करना है।
   यह कई लाइनों का टेक्स्ट, कोड या कुछ और भी हो सकता है।

1. समाप्ति: हियरडॉक तब ख़त्म होता है जब डेलिमिटर शब्द फिर से अकेले एक लाइन पर आ जाए, आगे या पीछे कोई व्हाइटस्पेस न हो।

## बुनियादी सिंटैक्स

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## यह कैसे काम करता है

* Bash शुरुआती `<< DELIMITER` और अंत के `DELIMITER` के बीच की सारी लाइनें पढ़ता है।
* Bash इस कंटेंट को कमांड के स्टैंडर्ड इनपुट से जोड़ देता है।
* कमांड इस इनपुट को वैसे ही संभालता है जैसे वह कीबोर्ड से आ रहा हो।

### उदाहरण 1: साधारण टेक्स्ट आउटपुट

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

आउटपुट:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

इस उदाहरण में:

* `cat` कमांड है।
* `<< EOF` हियरडॉक को शुरू करता है और `EOF` डेलिमिटर होता है।
* टेक्स्ट की तीन लाइनें कंटेंट हैं।
* अपनी अलग लाइन पर अकेला `EOF` हियरडॉक को ख़त्म करता है।
* फिर `cat` अपने पाए हुए कंटेंट को आउटपुट करता है।

### उदाहरण 2: wc (शब्द गणना) के साथ इस्तेमाल

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

आउटपुट:

```plaintext
3
```

यहाँ `wc -l` लाइनों की संख्या गिनता है।
हियरडॉक इनपुट के तौर पर वे तीन लाइनें देता है।

### उदाहरण 3: स्क्रिप्ट को डेटा देना

स्क्रिप्ट:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

किसी इंटरैक्टिव bash प्रॉम्प्ट से हियरडॉक की मदद से स्क्रिप्ट को कॉल कीजिए:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

आउटपुट:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## विभिन्न रूप और उन्नत फीचर

### शाब्दिक कंटेंट

Bash हियरडॉक के अंदर वेरिएबल एक्सपैंशन, कमांड सब्स्टिट्यूशन और अर्थमेटिक एक्सपैंशन करता है।
इस अर्थ में हियरडॉक डबल कोटेड स्ट्रिंग की तरह काम करते हैं।

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

आउटपुट:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

जब डेलिमिटर कोट में लिखा हो (सिंगल या डबल कोट के साथ), तो ये एक्सपैंशन नहीं होते।
कंटेंट ज्यों का त्यों लिया जाता है।
यह सिंगल कोटेड स्ट्रिंग की तरह है।

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

आउटपुट:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### शुरुआत की टैब हटाना

अगर आप `<<` की जगह `<<-` (अंत में हाइफन के साथ) इस्तेमाल करें, तो Bash हियरडॉक की हर लाइन से शुरुआत के सारे _टैब अक्षर_ हटा देगा।
यह आपकी स्क्रिप्ट में हियरडॉक के कंटेंट को इंडेंट करने के लिए काम आता है, बिना आउटपुट पर असर डाले।

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

आउटपुट में शुरुआत की सारी टैब हटाकर छापा जाता है:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
लेखक इस तरह इस्तेमाल करने की सलाह नहीं देते।
हालाँकि इससे स्क्रिप्ट पढ़ने में आसान हो सकती है,

1. गलती से टैब अक्षरों की जगह स्पेस डाल देना आसान है (हो सकता है आपका एडिटर यह अपने आप कर दे), और 
1. स्पेस और टैब के बीच का अंतर पहचानना मुश्किल है।
~~~~

## हियर डॉक्युमेंट कब इस्तेमाल करें

* कई लाइनों वाला इनपुट: जब आपको किसी कमांड को कई लाइनों का टेक्स्ट देना हो।
* कॉन्फिगरेशन फाइलें: किसी स्क्रिप्ट के अंदर छोटे कॉन्फिगरेशन टुकड़े शामिल करना।
* कोड बनाना: किसी स्क्रिप्ट के अंदर तुरंत कोड तैयार करना।
* इंटरैक्शन की स्क्रिप्टिंग: इंटरैक्टिव प्रोग्रामों के लिए यूज़र इनपुट की नकल करना।
* बाहरी फाइलों से बचना: जब आप अस्थायी फाइलें बनाने से बचना चाहें।

एक आम इस्तेमाल किसी मदद का टेक्स्ट देना हो सकता है:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## संभावित कमियाँ

* बड़े एम्बेडेड डॉक्युमेंट आपके कोड को पढ़ना मुश्किल बना सकते हैं।
  बेहतर यह हो सकता है कि आप अपनी स्क्रिप्ट के साथ डॉक्युमेंटेशन अलग फाइलों में रखकर डिप्लॉय करें।
* हियर डॉक्युमेंट कोड का प्रवाह तोड़ सकते हैं।
  आप कोड के किसी गहरे नेस्टेड हिस्से में हो सकते हैं, जहाँ आप किसी प्रोग्राम को कुछ टेक्स्ट देना चाहते हैं।
  आसपास के कोड की तुलना में हियरडॉक का इंडेंटेशन अटपटा लग सकता है।

## हियर स्ट्रिंग

हियर डॉक्युमेंट की तरह, _हियर स्ट्रिंग_ (या "हियरस्ट्रिंग") भी किसी कमांड को इनपुट देते हैं।
लेकिन हियरडॉक अगर टेक्स्ट के एक ब्लॉक के रूप में दिए जाते हैं, तो हियरस्ट्रिंग टेक्स्ट की एक ही स्ट्रिंग के रूप में दिए जाते हैं।
हियर स्ट्रिंग `<<< "text"` सिंटैक्स इस्तेमाल करते हैं।

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

आउटपुट:

```plaintext
UPPER CASE THIS STRING
```

हियरडॉक के विपरीत, इनमें अंत का डेलिमिटर देने की ज़रूरत नहीं होती।

### हियर स्ट्रिंग क्यों इस्तेमाल करें?

हियर स्ट्रिंग की जगह पाइपलाइन भी इस्तेमाल की जा सकती है:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

तो हियर स्ट्रिंग क्यों इस्तेमाल करें?

ऐसी स्थिति पर विचार कीजिए जहाँ आपको किसी लंबी चलने वाली गणना से आउटपुट के रूप में एक स्ट्रिंग मिलती है, और आप उस परिणाम को दो अलग-अलग कमांडों को देना चाहते हैं।
पाइपलाइनों का इस्तेमाल करते हुए आपको वही गणना दो बार चलानी पड़ती है:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

इससे ज़्यादा कुशल तरीका यह है कि आप गणना का आउटपुट (कमांड सब्स्टिट्यूशन की मदद से) पकड़ लें, और फिर उन दो अगली कमांडों को इनपुट देने के लिए हियर स्ट्रिंग इस्तेमाल करें:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

इस उदाहरण का एक वास्तविक इस्तेमाल ऐसा है:

* किसी REST API क्वेरी (जो पेजों में बँटी है) की JSON रिस्पॉन्स पकड़ें,
* उस JSON डेटा को किसी jq प्रोग्राम को दें ताकि वह नतीजों को पार्स करके उन्हें एक फाइल में लिख दे, और फिर
* उसी JSON डेटा को दूसरे jq प्रोग्राम को दें ताकि वह अगली क्वेरी का URL तय कर सके।

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

आउटपुट रीडायरेक्शन की जगह पर ध्यान दीजिए।
`while` लूप का सारा आउटपुट `data.csv` फाइल के अंत में जुड़ता चला जाएगा।

## रीडायरेक्शन के रूप में हियरडॉक और हियरस्ट्रिंग

चूँकि ये रीडायरेक्शन के ही रूप हैं, इन्हें दूसरे रीडायरेक्शन कामों के साथ जोड़ा जा सकता है:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## सारांश

हियर डॉक्युमेंट (या "हियरडॉक") Bash स्क्रिप्ट में कई लाइनों वाले इनपुट को संभालने का एक लचीला और सुविधाजनक तरीका हैं।
ये टेक्स्ट और डेटा को सीधे आपकी स्क्रिप्ट के अंदर शामिल करने का काम आसान बना देते हैं, जिससे स्क्रिप्ट ज़्यादा आत्मनिर्भर और पढ़ने में आसान हो जाती हैं।

हियर स्ट्रिंग (या "हियरस्ट्रिंग") हियर डॉक्युमेंट की तरह ही हैं, लेकिन ये ज़्यादा सरल और गतिशील सिंटैक्स देते हैं।
