# परिचय

## ओपेक टाइप

### परिचय

ओपेक टाइप, Elm में एनकैप्सुलेशन की एक तकनीक है।
कुछ लोग इसे जानकारी छिपाना, या इम्प्लीमेंटेशन के ब्यौरे छिपाना भी कहते हैं।
इनका इस्तेमाल आमतौर पर वैलिडेशन लागू करने के लिए भी किया जाता है, और इसके लिए [पार्स कीजिए, वैलिडेट नहीं][parse-dont-validate] पैटर्न अपनाया जाता है।
उदाहरण के लिए, आपके पास एक `EmailAddress` ओपेक टाइप हो सकता है, जिसमें सिर्फ मान्य ईमेल पते ही रखे जा सकते हैं (`String` के उलट, जिसमें कुछ भी हो सकता है)।

### ओपेक टाइप बनाना

[कस्टम टाइप][custom-types] में एक या अधिक *वेरिएंट* होते हैं, और कंपाइलर हर *वेरिएंट* को बनाने के लिए उस *वेरिएंट* के नाम से अपने आप एक फंक्शन बना देता है।
कस्टम टाइप बनाने का यही एकमात्र तरीका है।
कंपाइलर इन वेरिएंट के लिए डीस्ट्रक्चरिंग की भी सुविधा देता है।

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

डिफॉल्ट रूप से यह सब फाइल या मॉड्यूल के अंदर ही रहता है, और क्या एक्सपोर्ट करना है, यह चुनने के लिए हम `exposing` कीवर्ड का इस्तेमाल करते हैं।
ओपेक टाइप बनाने के लिए, आप बस *वेरिएंट* को एक्सपोर्ट न करने का फैसला करते हैं।

ऐसा करने पर आपको लगभग हमेशा *वेरिएंट* बनाने और पाने का कोई और तरीका देना पड़ता है, यानी कुछ कस्टम फंक्शन एक्सपोज़ करने पड़ते हैं।
ये कस्टम फंक्शन आपको *वेरिएंट* बनाते और पाते समय कुछ लॉजिक लगाने देते हैं।
इससे मॉड्यूल के अंदरूनी इम्प्लीमेंटेशन का ब्यौरा छिप जाता है, और इसका मतलब है कि आप इम्प्लीमेंटेशन का ब्यौरा जितना चाहें बदल सकते हैं, बशर्ते एक्सपोज़ किए गए फंक्शन वही रहें।

### पार्स कीजिए, वैलिडेट नहीं

ओपेक टाइप का सबसे आम इस्तेमाल शायद वैलिडेशन लागू करना है, और इसके लिए [पार्स कीजिए, वैलिडेट नहीं][parse-dont-validate] पैटर्न अपनाया जाता है।
इस पैटर्न में आप एक ऐसा फंक्शन एक्सपोज़ करते हैं जो ऐसा इनपुट लेता है जिसमें आप जितना ढाँचा और टाइप सुरक्षा चाहते हैं उससे कम हो, जैसे कोई `String`, और फिर उसे पार्स करके ज़्यादा ढाँचे वाले टाइप में बदल देता है, जैसे `EmailAddress`।
वह या तो वह टाइप लौटाता है, या कोई एरर लौटाता है (आमतौर पर `Maybe` या `Result`)।

उदाहरण के लिए, नीचे दिए कोड में बाहरी मॉड्यूल के लिए `EmailAddress` टाइप सिर्फ `parseEmailAddress` फंक्शन की मदद से बनाना संभव है, इसलिए जब आप `EmailAddress` टाइप के साथ काम करते हैं, तो आप निश्चित हो सकते हैं कि वह मान्य है।

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
