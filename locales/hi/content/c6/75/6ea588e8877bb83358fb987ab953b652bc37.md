# परिचय

Factor के एरर सिस्टम में तीन हिस्से हैं: एरर पैदा करने के लिए `throw`, उसे संभालने के लिए `recover`, और अपनी खुद की तरह की एरर बनाने के लिए `ERROR:`।

## `throw`

`throw` ([`kernel`][kernel] में मौजूद) एरर पैदा करता है। इसका आर्गुमेंट *कोई भी* वैल्यू हो सकता है, चाहे स्ट्रिंग हो, संख्या हो या टपल, और यही वैल्यू वह एरर बन जाती है जिसे आप बाद में जाँच सकते हैं:

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw` लौटता नहीं है; मौजूदा वर्ड का बाकी हिस्सा छोड़ दिया जाता है।

## `recover`

`recover` ([`continuations`][continuations] में मौजूद) Factor का try/catch है। यह एक *try* कोटेशन और एक *recovery* कोटेशन लेता है:

```
recover ( try recovery -- )
```

अगर `try` बिना कोई एरर पैदा किए पूरा हो जाता है, तो `recovery` को अनदेखा कर दिया जाता है। अगर `try` एरर पैदा करता है, तो वह एरर स्टैक पर रख दी जाती है और `recovery` चलाया जाता है:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

[`kernel`][kernel] से आने वाला `when` इसका स्वाभाविक साथी है: यह कोटेशन तभी चलाता है जब स्टैक के सबसे ऊपर की वैल्यू सही हो:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:` एक टपल क्लास *और* एक वर्ड बनाता है, जो एक नया इंस्टेंस बनाकर उसे एरर के रूप में पैदा कर देता है:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

बिना स्लॉट वाली एरर के लिए बस `ERROR: name ;` लिखना ही काफी है। `name` को कॉल करने पर एक खाली इंस्टेंस पैदा होता है। `ERROR:` से बनाए गए टपल के साथ एक क्लास प्रेडिकेट `name?` आता है, जिसकी मदद से आप जाँच सकते हैं कि पकड़ी गई एरर उसी टाइप की थी या नहीं।

## स्लॉट वापस पढ़ना

पकड़ी गई एरर असल में एक टपल ही होती है, इसलिए `ERROR:` के हर स्लॉट के साथ वही अपने आप बनने वाला `slot>>` रीडर मिलता है जो किसी भी दूसरे टपल के साथ मिलता है।

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
