# परिचय

Elixir के निश्चयात्मक और मुहावरेदार कोड में पैटर्न मैचिंग का इस्तेमाल प्रमुख है। आपको याद होगा कि `=/2` को असाइनमेंट ऑपरेटर नहीं, बल्कि मैच ऑपरेटर कहा जाता है। मैच ऑपरेटर इस्तेमाल करते समय, अगर बाईं ओर का पैटर्न दाईं ओर से मेल खाता है, तो बाईं ओर के सभी वेरिएबलो बाइंड हो जाते हैं, और दाईं ओर की वैल्यू लौटा दी जाती है। अगर मेल नहीं मिलता, तो `MatchError` उठाई जाती है।

```elixir
2 = 2
# => 2
# Literals can be matched if they are the same

2 = 3
# => ** (MatchError) no match of right hand side value: 3

{_, denominator} = Float.ratio(0.25)
# => {1, 4}
# the variable `denominator` is bound to the value 4
```

याद रखिए, मैच दाईं ओर से बाईं ओर होते हैं।

पिछले उदाहरण में, अगर पैटर्न मैच में हमें किसी वेरिएबल की ज़रूरत नहीं है, तो हम `_` लिखकर उसे छोड़ सकते हैं। जो भी वेरिएबल `_` से शुरू होता है, रनटाइम उसका हिसाब नहीं रखता।

## नाम वाले फंक्शनों में पैटर्न मैचिंग

कई फंक्शन क्लॉज़ बनाते समय पैटर्न मैचिंग एक उपयोगी टूल भी है। फंक्शन के आर्गुमेंट पर पैटर्न मैचिंग इस्तेमाल की जा सकती है, जो यह तय करती है कि कौन-सा फंक्शन क्लॉज़ कॉल किया जाएगा। यह फाइल के ऊपर से शुरू होकर नीचे की ओर पहले मैच तक जाती है। वेरिएबलो को फंक्शन हेड में बाइंड किया जा सकता है और फंक्शन बॉडी में इस्तेमाल किया जा सकता है।

```elixir
defmodule Example do
  def named_function(:a = variable_a) do
    {variable_a, 1}
  end

  def named_function(:b = variable_b) do
    {variable_b, 2}
  end
end

Example.named_function(:a)
# => {:a, 1}

Example.named_function(:b)
# => {:b, 2}

Example.named_function(:c)
# => ** (FunctionClauseError) no function clause matching in Example.named_function/1
```
