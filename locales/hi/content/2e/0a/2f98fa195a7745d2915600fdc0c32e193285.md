# परिचय

Rust में इटरेटर वह कोई भी वैल्यू होती है जो [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html) ट्रेट को लागू करती है।
इटरेटर की वैल्यूओं को इटरेटर पर `next` मेथड कॉल करके मैन्युअल रूप से आगे बढ़ाया जा सकता है।

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Rust के बहुत से [`collections`](https://doc.rust-lang.org/std/collections/index.html) [`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html) को लागू करते हैं, जो कलेक्शन की वैल्यूओं से एक `Iterator` बना सकता है।

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

ध्यान दीजिए: `IntoIterator::into_iter` अपने `self` टाइप को कंज़्यूम कर देता है, लेकिन ज़रूरी नहीं कि वह टाइप ओन्ड वैल्यू ही हो।
इसलिए `IntoIterator` के इम्प्लीमेंटेशन [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2) के लिए भी हैं, [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator) के लिए भी, और [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1) के लिए भी।
ओनरशिप के अलग-अलग स्तरों वाले ये इम्प्लीमेंटेशन उपयोगी लचीलापन देते हैं।

इस कॉन्सेप्ट के लिए `traits` को समझना ज़रूरी नहीं है। `traits` को पूरी तरह सीखने के लिए आपको एक पूरा अभ्यास मिलेगा।
अभी के लिए बस इतना याद रखिए:

- जो भी टाइप `IntoIterator` को लागू करता है, उसे _इटरेबल_ कहा जाता है, क्योंकि उसे इटरेटर में बदला जा सकता है।
- जो भी टाइप `Iterator` को लागू करता है वह एक इटरेटर है, जो वैल्यू _पैदा करता है_ और जिस पर _इटरेशन किया जा सकता है_।
- आप ऐसे किसी भी टाइप से इटरेटर पा सकते हैं जो `IntoIterator` को लागू करता है, बस उसका `into_iter` मेथड कॉल कीजिए।
- हर इटरेटर [`IntoIterator` को लागू करता है](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25) और खुद को ही पैदा करता है।
- `for` लूप हमेशा इटरेटर पर ही काम करते हैं और अपने रेंज आर्गुमेंट पर `IntoIterator` को अपने आप कॉल करते हैं।

## `into_iter` और `for` लूप

आप शायद वेक्टर पर चलने वाले `for` लूप से परिचित हैं:

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

मूल रूप से `for` लूप अपने आर्गुमेंट का `into_iter` मेथड कॉल करने, और फिर `next()` को तब तक कॉल करते रहने का छोटा रूप भर है, जब तक वह आइटम पैदा करना बंद न कर दे। दूसरे शब्दों में, पिछला लूप वास्तव में इस तरह लिखा जा सकता है:

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## `iter` और `iter_mut` मेथड

Rust के अधिकांश कलेक्शन टाइप `iter` और `iter_mut` मेथड देते हैं।
`T` टाइप के कलेक्शन के लिए ये दोनों मेथड परंपरा से यह काम करते हैं:

- `iter` से मिलने वाला इटरेटर अपरिवर्तनीय उधार के रूप में `&T` देता है।
- `iter_mut` से मिलने वाला इटरेटर परिवर्तनीय उधार के रूप में `&mut T` देता है।

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## `iter`, `iter_mut` और `into_iter` में अंतर

अगर `iter`, `iter_mut` और `into_iter` सभी इटरेटर पैदा करते हैं, तो इनमें अंतर क्या है?

- `iter` से मिलने वाला इटरेटर परंपरा से अपरिवर्तनीय उधार के रूप में `&T` देता है।
- `iter_mut` से मिलने वाला इटरेटर परंपरा से परिवर्तनीय उधार के रूप में `&mut T` देता है।
- `into_iter` से मिलने वाला इटरेटर अपने कॉन्टेक्स्ट के हिसाब से `T`, `&T` या `&mut T` दे सकता है।

`into_iter` को कॉल करने का कॉन्टेक्स्ट क्या होता है?
उसका `self` टाइप।
याद कीजिए कि `IntoIterator` के इम्प्लीमेंटेशन `Vec`, `&'a Vec` और `&'a mut Vec` के लिए मौजूद हैं।
इसलिए:

- `(&v).into_iter()` बराबर है `v.iter()` => `&T` लौटाता है
- `(&mut v).into_iter()` बराबर है `v.iter_mut()` => `&mut T` लौटाता है
- `v.into_iter()` => `T` लौटाता है और वैल्यूओं को मूव कर देता है

यह `for` लूप में सबसे साफ़ दिखता है:

- `for num in &v {...}` => `&T` बाइंड करता है
- `for num in &mut v {...}` => `&mut T` बाइंड करता है
- `for num in v {...}` => `T` बाइंड करता है और वैल्यूओं को मूव कर देता है

`(&v).into_iter()` की जगह `v.iter()` लिखना अक्सर अधिक साफ़ होता है।
इसलिए `into_iter` के बजाय `iter` और `iter_mut` चुनने के व्यावहारिक कारण भी हैं।

## इटरेटर के बिल्ट-इन मेथड इस्तेमाल करना

इटरेटर कई बिल्ट-इन मेथड देते हैं, जैसे `map`, `filter`, `collect`।
ये मेथड कभी-कभी क्लोज़र के साथ इस्तेमाल किए जाते हैं।

`map` एक क्लोज़र की मदद से इटरेटर की वैल्यूओं को बदलता है।
`take` एक (संभवतः अनंत) इटरेटर को ऐसे इटरेटर में बदल देता है जो बताई गई संख्या में आइटम देने के बाद खत्म हो जाता है।

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter` इटरेटर को ऐसे इटरेटर में बदल देता है जो सिर्फ़ उन्हीं वैल्यूओं को लौटाता है जिनके लिए क्लोज़र `true` देता है।
`count` इटरेटर को कंज़्यूम कर लेता है और पैदा हुए आइटम की संख्या लौटाता है।

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map` हर आइटम को दिए गए क्लोज़र की मदद से एक नए इटरेटर में बदलता है, और फिर उन सभी नए इटरेटर को एक-दूसरे से जोड़कर एक सपाट इटरेटर बना देता है।
`collect` एक नया कलेक्शन बनाता है, बशर्ते कलेक्शन टाइप [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html) को लागू करता हो।

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

[`Iterator` ट्रेट](https://doc.rust-lang.org/std/iter/trait.Iterator.html) ऐसे काम के _कई_ इटरेटर ट्रांसफ़ॉर्म देता है; इसका डॉक्यूमेंटेशन पढ़ना और इनसे परिचित होना फ़ायदेमंद रहेगा।

## आलस्य

यह जानना ज़रूरी है कि Rust के इटरेटर आलसी होते हैं: जब तक हम इटरेटर को कंज़्यूम नहीं करते, वे कोई वैल्यू नहीं देते।
अगर आप नीचे दिया गया कोड लिखकर चलाइए:

```rust
(0..5).map(|x| x * x);
```

तो आपको यह कंपाइलर एरर मिलेगी:

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

ऐसा इसलिए होता है क्योंकि `map` एक अडैप्टर मेथड है जो एक और इटरेटर लौटाता है।

इटरेटर को कंज़्यूम करने के लिए या तो `for` लूप इस्तेमाल कीजिए, या ऐसा इटरेटर मेथड इस्तेमाल कीजिए जो कोई ऐसी वैल्यू पैदा करता है जो खुद इटरेटर न हो।

उदाहरण के लिए, `collect` एक कंज़्यूमर मेथड है (इसका फंक्शन सिग्नेचर इटरेटर नहीं, बल्कि एक जेनेरिक टाइप लौटाता है):

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
