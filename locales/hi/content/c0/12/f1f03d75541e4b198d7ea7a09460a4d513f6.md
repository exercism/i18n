# परिचय

`<dlist>` ([`dlists`][dlists] में) एक नई डबली-लिंक्ड लिस्ट बनाता है। ऑपरेशन [`deques`][deques] में रहते हैं और [डेक प्रोटोकॉल][deque-protocol] पर डिस्पैच करते हैं, इसलिए दूसरे कंटेनर, मुख्य रूप से `<dlist>`, इन्हें लागू कर सकते हैं।

| वर्ड            | प्रभाव                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`, नया खाली डेक  |
| `push-front`    | `( elt deque -- )`, सामने जोड़ना |
| `push-back`     | `( elt deque -- )`, पीछे जोड़ना  |
| `pop-front`     | `( deque -- elt )`, सामने से हटाना |
| `pop-back`      | `( deque -- elt )`, पीछे से हटाना  |
| `peek-front`    | `( deque -- elt )`, सामने को हटाए बिना पढ़ना |
| `peek-back`     | `( deque -- elt )`, पीछे को हटाए बिना पढ़ना  |
| `deque-empty?`  | `( deque -- ? )`, क्या डेक खाली है? |
| `dlist-length`  | `( dlist -- n )`, एलिमेंट की संख्या |

सभी push/pop ऑपरेशन डेक को उसी जगह बदलते हैं; डेक को किसी रूटीन को देना और फिर उससे दोबारा पढ़ना सामान्य तरीका है।

## स्टैक बनाम क्यू

दो पारंपरिक डिस्पैच पैटर्न:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

`push` और `pop` वाला एक वेक्टर (`mutation` से) तब सही चुनाव है जब आपको केवल LIFO क्रम चाहिए; `<dlist>` लिंक्ड लिस्ट का ओवरहेड ढोता है। जब आपको *दोनों* सिरों पर O(1) चाहिए, और ऐसा लगभग हमेशा FIFO क्यू के लिए होता है, तब `<dlist>` का इस्तेमाल कीजिए।

## BFS पैटर्न

ब्रैड्थ-फर्स्ट सर्च FIFO का मानक उपयोग है:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

डेक सर्च फ्रंटियर को संभालता है; हैश-सेट डुप्लीकेट हटाने का काम करता है। `pop-front` की जगह `pop-back` इस्तेमाल कीजिए और वही ढाँचा डेप्थ-फर्स्ट बन जाता है।

## `MEMO:`: स्वचालित कैशिंग

कभी-कभी BFS द्वारा किया जाने वाला प्रति-नोड लुकअप महँगा होता है। Factor [`MEMO:`][memo-decl] देता है, जो `:` का विकल्प है और वर्ड के परिणाम को उसके इनपुट के आधार पर स्वतः कैश कर देता है:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

`MEMO:` वर्ड पहली बार हर इनपुट देखे जाने पर अपने अंदर का कोड चलाता है और उसके बाद कैश किया गया परिणाम लौटाता है। कैश इमेज के जीवनकाल तक रहता है; समय या आकार के आधार पर कैश से कुछ नहीं हटाया जाता। इसका इस्तेमाल उन प्योर फंक्शन के लिए कीजिए जिनके इनपुट एक सीमित, संभालने योग्य समूह से आते हैं।
