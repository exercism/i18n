# परिचय

## रेफरेंस

### कॉपी और रेफरेंस

अभी जो हम जानते हैं उसके हिसाब से किसी फंक्शन की मदद से कोई वेरिएबल अपडेट करना थोड़ा झंझट भरा काम है।
हर फंक्शन आर्गुमेंट की एक कॉपी बनती है और मूल वैल्यू नहीं बदलती।
आपके टाइप का आकार कितना बड़ा है, उसके हिसाब से यह आपके कोड की परफॉर्मेंस पर गंभीर असर डाल सकता है।

```cpp
int adjust_salary(int base, int kids) {
    return base + kids * 500;
}
int now_a_mother_of_twins{2500};
adjust_salary(now_a_mother_of_twins, 2);

// now_a_mother_of_twins is still 2500
now_a_mother_of_twins = adjust_salary(now_a_mother_of_twins, 2);
// now_a_mother_of_twins is now 3500
```

`References` को उपनाम की तरह देखा जा सकता है। इनमें किया गया बदलाव मूल वेरिएबल पर असर डालता है।
`References` को टाइप घोषित करते समय **एम्परसैंड** (`&`) लगाया जाता है।

```cpp
int balance{1000};
int& budget{balance};
int pro_computer_wheels{699};
budget -= pro_computer_wheels;
// budget is now 301;
// balance is also 301;
```
किसी `reference` का जुड़ाव बदलना संभव नहीं है, यानी उसे किसी दूसरे वेरिएबल से नहीं जोड़ा जा सकता।
बिना इनिशियलाइज़ किया हुआ `reference` नहीं रखा जा सकता।
`References` को किसी पहले से मौजूद वेरिएबल से इनिशियलाइज़ करना ज़रूरी है।

```cpp
int main_acc{1'000'000};
int side_acc{-20};
int& savings{main_acc};
// => main_acc and savings are 1'000'000

// try to reseat savings to use main account
savings = side_acc;
// savings and main_acc are now -20
// as this uses the **value** of side_acc
savings += 20;
// savings and main_acc are now 0, side_acc is still -20

int& future_budget;
// => compiler error, reference must be bound!
```

### `void`

`references` की शक्ति का उपयोग करके आपको किसी फंक्शन से कोई वैल्यू लौटाने की ज़रूरत ही न पड़े।
ऐसी स्थिति में रिटर्न टाइप के तौर पर `void` का उपयोग किया जाता है।

```cpp
void increase_power(int& level) {
    level += 500;
}
int goku{8700};
increase_power(goku);
// goku's power level?
// It's over 9000!
```
