# विवरण

Gleam में जब हम किसी वैल्यू पर पैटर्न मैचिंग करते हैं, तो हमें यह सुनिश्चित करना होता है कि पैटर्न उस टाइप की हर संभव वैल्यू से मैच करें। ऐसा न होने पर कोड कंपाइल नहीं होगा।

यह फंक्शन अस्वीकार किया जाना चाहिए, क्योंकि इसमें उस स्थिति का ध्यान नहीं रखा गया जहाँ ऐरे खाली है:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Gleam प्रोग्राम में ज़्यादातर हमें हर संभव स्थिति संभालनी होती है। लेकिन प्रोटोटाइप और छोटी स्क्रिप्ट जैसे कुछ प्रोग्राम में हम केवल उस सामान्य स्थिति पर ध्यान देना चाहते हैं जहाँ सब ठीक चलता है, और बाकी स्थितियों के लिए कोड नहीं लिखना चाहते। यहीं Gleam का `let assert` काम आता है।

`let assert` की मदद से कोई पैटर्न किसी टाइप की सिर्फ कुछ वैल्यू से ही मैच कर सकता है। अगर पैटर्न किसी वैल्यू से मैच नहीं करता, तो प्रोग्राम क्रैश हो जाता है। इसी `let assert` का उपयोग करके हम ऊपर वाला फंक्शन ऐसे लिख सकते हैं:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam की लाइब्रेरी में `let assert` का उपयोग कभी नहीं करना चाहिए, क्योंकि इससे प्रोग्राम क्रैश हो सकता है। इसके बजाय लाइब्रेरी को `Result` टाइप का उपयोग करना चाहिए और एरर को संभालने का तरीका एप्लिकेशन डेवलपर पर छोड़ देना चाहिए।
