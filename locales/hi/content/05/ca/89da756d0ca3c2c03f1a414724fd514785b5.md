# टेस्ट

हर अभ्यास के साथ यूनिट टेस्ट का एक सेट आता है, और उन्हें बिल्ड करके चलाने के लिए ज़रूरी सब कुछ भी।
इम्प्लीमेंटेशन आप लिखते हैं।

## टेस्ट चलाना

अभ्यास फोल्डर में टर्मिनल खोलिए और यह चलाइए:

```
make
```

यह आपके हल और टेस्ट, दोनों को कंपाइल करता है और फिर टेस्ट चलाता है।
अपने हल में हर बदलाव के बाद इसे फिर से चलाइए।

अगर आपके पास [Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally) है, तो इसके बजाय यह कमांड चला सकते हैं, जो `make` भी चला देता है:

```
exercism test
```

बिल्ड से बनी फाइलें हटाने के लिए `make clean` चलाइए।

### make के बिना

अगर आपके पास `make` नहीं है (जैसे Windows पर), तो आप टेस्ट सीधे कंपाइल करके चला सकते हैं।
"Bob" अभ्यास के लिए:

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

फिर Linux या macOS पर टेस्ट चलाइए:

```
./run_tests
```

या Windows पर:

```
.\run_tests
```

## अभ्यास पर काम करना

हर अभ्यास की फाइलों के नाम उसी अभ्यास के नाम पर होते हैं।
"Bob" अभ्यास के लिए:

| फाइल | सामग्री |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90`        | हल का स्टब, जिसे आपको पूरा करना है |
| `bob_test.f90`   | टेस्ट |
| `TesterMain.f90` | टेस्ट लाइब्रेरी |
| `Makefile`       | `make` के लिए निर्देश |
| `CMakeLists.txt` | [CMake](#using-cmake-instead) के लिए निर्देश, जो ज़रूरी नहीं है |

आपको सिर्फ हल वाली फाइल बदलनी है।

हर अभ्यास पर काम करने का तरीका यह है कि जब तक सारे टेस्ट पास न हो जाएँ, इन चरणों को दोहराइए:
- कंपाइल एरर ठीक कीजिए, फिर टेस्ट चलाकर देखिए कि कौन-से टेस्ट फेल होते हैं।
- अगला फेल होने वाला टेस्ट पास हो जाए, बस उतना ही इम्प्लीमेंट कीजिए।
- अपने इम्प्लीमेंटेशन को रीफैक्टर कीजिए ताकि वह पढ़ने में आसान हो, दोहराव कम हो, वगैरह।
- टेस्ट फिर से चलाइए और अगले फेल होने वाले टेस्ट की ओर बढ़िए।

हर फेल होने वाले टेस्ट के लिए एक संदेश छपता है, और उसके बाद एक सारांश आता है।
अगर कोई भी टेस्ट फेल होता है, तो `make` एक एरर के साथ खत्म होता है।

हर टेस्ट में एक कमेंट होता है जो उस टेस्ट का वर्णन करता है, और उसके बाद असली टेस्ट आता है जो `call assert_equal` से शुरू होता है। जैसे:

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

किसी टेस्ट को बंद करने के लिए उसके आगे `'!'` लगाकर उसे कमेंट बना दीजिए। जैसे:

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## इसके बजाय CMake इस्तेमाल करना

CMake ज़रूरी नहीं है, लेकिन अगर आप Visual Studio या Xcode जैसे किसी IDE में काम करते हैं, या GFortran के अलावा किसी दूसरे कंपाइलर का इस्तेमाल करते हैं, तो यह काम आ सकता है।

अभ्यास फोल्डर का नाम वही रहना चाहिए, क्योंकि CMake सोर्स फाइलें उसी नाम से ढूँढता है।
अभ्यास फोल्डर से शुरू कीजिए:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

हल बदलने के बाद सिर्फ आखिरी दो कमांड चलाने की ज़रूरत होती है।

**ध्यान दें:** `cmake` हमेशा किसी अलग फोल्डर से चलाइए, जैसे `build`।
अभ्यास फोल्डर में `cmake .` चलाने से अभ्यास के साथ आने वाली `Makefile` बदल जाती है।

CMake आपके सिस्टम के लिए उपयुक्त जेनरेटर चुन लेता है।
कोई दूसरा जेनरेटर चुनने के लिए `-G` विकल्प इस्तेमाल कीजिए, जैसे `cmake -G Xcode ..`।
आप कौन-कौन से जेनरेटर इस्तेमाल कर सकते हैं, यह देखने के लिए `cmake --help` चलाइए।
Visual Studio या Xcode के साथ टेस्ट `ctest -V -C Debug` से चलाइए।

अगर आपके अभ्यास फोल्डर में `Makefile` नहीं है, तो वह तब डाउनलोड हुआ था जब ये फाइलें अभ्यासों में शामिल नहीं की गई थीं।
आप फिर भी CMake इस्तेमाल कर सकते हैं।
