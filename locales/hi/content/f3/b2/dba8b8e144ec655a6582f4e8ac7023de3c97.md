# निर्देश

आप एक रेट्रो हैंडहेल्ड कंसोल के स्कोरिंग सिस्टम के लिए फर्मवेयर लिख रहे हैं।
इस मशीन का CPU साधारण है, और स्कोरबोर्ड डिस्प्ले एक तय दर से रीफ्रेश होता है।
तस्वीर स्मूद बनी रहे, इसके लिए ज़रूरी है कि स्कोरिंग रूटीन हर बार एक निश्चित संख्या के साइकल में चलें, चाहे खिलाड़ी कुछ भी कर रहा हो।

आपको चार काम करने हैं।

~~~~exercism/note
कामों का कोड ब्रांचलेस होना चाहिए।
सशर्त जंप की जगह `cmovcc`, `setcc` और अंकगणित का इस्तेमाल कीजिए।
~~~~

## 1. डिस्प्ले को ओवरफ्लो किए बिना बोनस जोड़िए

हैंडहेल्ड के LCD के स्कोर वाले हिस्से में छह दशमलव अंकों की जगह है।
यह `999999` से ऊपर की कोई भी संख्या नहीं दिखा सकता।
जब कोई बोनस चालू कुल को इस सीमा से आगे धकेल देता, तो दिखने वाला कुल रैप होकर घूमने के बजाय अधिकतम पर ही टिका रहता है।

एक फंक्शन `add_bonus` बनाइए, जो चालू कुल और जोड़ने के लिए बोनस लेकर `999999` पर सीमित नया कुल लौटाता है।
आर्गुमेंट इस क्रम में हैं:

1. `total`: चालू स्कोर कुल (हमेशा `0` और `999999` के बीच)
2. `bonus`: जोड़ने वाला बोनस (हमेशा गैर-ऋणात्मक)

अगर यह जोड़ `999999` से कम या उसके बराबर हो तो रिटर्न वैल्यू `total + bonus` होती है, वरना `999999` होती है:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

दोनों आर्गुमेंट और रिटर्न वैल्यू 64-बिट साइन्ड पूर्णांक हैं।

~~~~exercism/note
आप यह मान सकते हैं कि `total + bonus` किसी 64-बिट साइन्ड पूर्णांक को ओवरफ्लो नहीं करता।
~~~~

## 2. दो स्कोर की तुलना कीजिए

हैंडहेल्ड अपनी सेव फाइल में खिलाड़ी के हाल के बेहतरीन स्कोर का एक छोटा लीडरबोर्ड रखता है।
हर बार खेलने के बाद नया स्कोर लीडरबोर्ड में सही जगह पर डाला जाता है।
सॉर्ट रूटीन पूछता है कि दो स्कोर में से कौन आगे है, और जवाब एक छोटे पूर्णांक के रूप में चाहता है।

एक फंक्शन `compare_scores` बनाइए, जो दो स्कोर लेकर यह लौटाता है:

- `+1`, अगर पहला स्कोर _ज़्यादा_ है
- `-1`, अगर पहला स्कोर _कम_ है
- `0`, अगर दोनों स्कोर _बराबर_ हैं

उदाहरण:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

दोनों आर्गुमेंट और रिटर्न वैल्यू 64-बिट साइन्ड पूर्णांक हैं।

## 3. कच्चे स्कोर की जाँच कीजिए

हैंडहेल्ड मल्टीप्लेयर मैच के बाद स्कोर साझा करने के लिए अपने लिंक केबल से दूसरी यूनिट से जुड़ सकता है।
यह केबल विद्युत रूप से शोरग्रस्त है, और आने वाले बाइट कभी-कभी खराब हो जाते हैं, जिससे वैल्यू वैध न्यूनतम से बहुत नीचे या वैध अधिकतम से बहुत ऊपर पहुँच जाती हैं।
बाकी सिस्टम इसे देखे, उससे पहले जाँच करने वाला हिस्सा हर आने वाले स्कोर को वैध सीमा में सीमित कर देता है।

एक फंक्शन `validate_score` बनाइए, जो कच्चा स्कोर और वैध सीमाएँ लेकर स्कोर को `[min, max]` में सीमित करके लौटाता है।
आर्गुमेंट इस क्रम में हैं:

1. `score`: लिंक केबल पर मिला कच्चा स्कोर
2. `min`: सबसे छोटा अनुमत स्कोर
3. `max`: सबसे बड़ा अनुमत स्कोर

अगर `score < min` हो तो रिटर्न वैल्यू `min` होती है, अगर `score > max` हो तो `max`, वरना `score`।
आप यह मान सकते हैं कि `min <= max` है।

उदाहरण:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

सभी आर्गुमेंट और रिटर्न वैल्यू 64-बिट साइन्ड पूर्णांक हैं।

## 4. दो सबसे ऊँचे स्कोर पर नज़र रखिए

हर खेल सत्र के अंत में हैंडहेल्ड अपनी सेव फाइल में हाल के खेलों के लॉग को स्कैन करता है, ताकि अब तक दर्ज दो सबसे ऊँचे स्कोर ढूँढ सके।
यह लॉग मेमोरी में 64-बिट साइन्ड पूर्णांकों का एक साधारण ऐरे है।
यह स्कैन ऐरे पर एक बार चलता है और दो चालू अधिकतम रखता है: अब तक देखा गया सबसे ऊँचा, और उससे अगला सबसे ऊँचा।

ध्यान दीजिए कि दोनों संख्याएँ कम से कम `0` होनी चाहिए।
किसी भी ऋणात्मक संख्या को छोड़ दिया जाता है।

फंक्शन का पहला संस्करण एक के बाद एक आने वाले सशर्त जंप के साथ लिखा गया था।
हर उम्मीदवार के लिए कोड देखता है कि वह कहाँ फिट बैठता है (पहले से ऊपर, पहले और दूसरे के बीच, या कहीं नहीं), और उसी हिसाब से चालू अधिकतम को आगे बढ़ाता है, किसी भी ऋणात्मक परिणाम को छोड़ते हुए।

यह काम करता है।
लेकिन चूँकि इनपुट वैल्यू रैंडम होती हैं, हर सशर्त जंप कई ब्रांच मिसप्रेडिक्शन की वजह बनता है।
इसीलिए आपने मुख्य लूप को रीफैक्टर करके ब्रांचलेस बनाने का फैसला किया है।

नीचे वह फंक्शन दिया गया है, जिसमें ब्रांच वाले हिस्से को कमेंट कर दिया गया है:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

कमेंट किए गए हिस्से को ब्रांचलेस कार्यान्वयन से बदल दीजिए।
नए कोड में सिर्फ वही जंप की अनुमति है जो ऐरे के नए एलिमेंट की जाँच के लिए लूप की शुरुआत पर वापस जाता है।

इस फंक्शन की कोई रिटर्न वैल्यू नहीं है और यह ब्रांच वाले संस्करण की तरह ही आर्गुमेंट लेता है:

1. `out`: आउटपुट बफर, जहाँ फंक्शन दो सबसे ऊँचे गैर-ऋणात्मक स्कोर को घटते क्रम में, 64-बिट साइन्ड पूर्णांक के रूप में लिखेगा
2. `array`: 64-बिट साइन्ड पूर्णांकों का इनपुट ऐरे
3. `length`: ऐरे में एलिमेंट की संख्या, 64-बिट अनसाइन्ड पूर्णांक के रूप में

~~~~exercism/note
अगर ऐरे में एक जैसी वैल्यू दोहराई गई हों, और वे दोनों सबसे ऊँचे स्कोर हों, तो वे दोनों आउटपुट स्लॉट में आ सकती हैं।
~~~~
