# बारे में

रिकर्सिव फंक्शन ऐसे फंक्शन होते हैं जो खुद को कॉल करते हैं।

एक रिकर्सिव फंक्शन में कम से कम एक _बेस केस_ और कम से कम एक _रिकर्सिव केस_ होना ज़रूरी है।

_बेस केस_ फंक्शन को दोबारा कॉल किए बिना एक वैल्यू लौटाता है।
_रिकर्सिव केस_ फंक्शन को दोबारा कॉल करता है, और इनपुट में ऐसा बदलाव करता है कि वह किसी समय बेस केस से मेल खाने लगे।

Elm में रिकर्सिव फंक्शन आम तौर पर `case` एक्सप्रेशन के साथ पैटर्न मैचिंग की मदद से बनाए जाते हैं।

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

एक रिकर्सिव फंक्शन में कई बेस केस और/या कई रिकर्सिव केस हो सकते हैं।
उदाहरण के लिए, [फिबोनाची अनुक्रम][fibonacci] दो बेस केस वाला एक रिकर्सिव अनुक्रम है:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

ध्यान दीजिए कि यह इम्प्लीमेंटेशन घातीय रूप से धीमा है, क्योंकि संबंधित फिबोनाची संख्याएँ दो अलग-अलग रिकर्सिव कॉल में शुरू से गिनी जाती हैं।

किसी ऐरे में दी गई वैल्यू `x` कितनी बार आती है, यह गिनने में दो रिकर्सिव केस होते हैं:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## रिकर्सन से लूप बनाना

इम्यूटेबिलिटी की वजह से Elm में लूप इम्पेरेटिव भाषाओं से अलग तरीके से लिखे जाते हैं।
उदाहरण के लिए, लूप आम तौर पर ऐसे दिखते हैं:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

Elm जैसी फंक्शनल भाषा में वेरिएबलो को बदलना संभव नहीं होता।
इसलिए लूप रिकर्सन से ही बनाने पड़ते हैं।

Elm में `for` लूप के बराबर कोड ऐसा दिखेगा:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

व्यवहार में, Elm में ऐरे और दूसरे डेटा स्ट्रक्चर पर इटरेशन करना अक्सर [`List`][module-list] मॉड्यूल के फंक्शन से किया जाता है, जैसे `List.map`, `List.filter` और `List.foldl`।
अंदरूनी रूप से ये फंक्शन रिकर्सन से बने हैं।

## अनंत निष्पादन

अगर कोई रिकर्सिव फंक्शन गलत तरीके से लिखा गया हो, या रिकर्सिव कॉल की संख्या बहुत ज़्यादा हो, तो वह अपना परिणाम कभी नहीं लौटा पाता।
यह समस्या बन सकती है, क्योंकि हर बार फंक्शन कॉल होने पर मेमोरी में एक रेफरेंस संग्रहीत किया जाता है, जो बताता है कि रनटाइम को परिणाम कहाँ लौटाना है ([कॉल स्टैक][wiki-call-stack] पर)।
अगर कोई रिकर्सिव फंक्शन खुद को बहुत बार, या अनंत बार कॉल करता रहे, तो मेमोरी खत्म हो सकती है और रनटाइम क्रैश हो सकता है (यह [स्टैक ओवरफ्लो एरर][wiki-stack-overflow] होती है)।
Elm का रनटाइम रिकर्सन और विश्वसनीयता के लिए ऑप्टिमाइज़ किया गया है, फिर भी अनंत रिकर्सन समस्या पैदा कर सकता है।

अनंत निष्पादन की यह समस्या इन वजहों से हो सकती है:

- बेस केस बनाना भूल जाना।
- पैटर्न मैचिंग में सारे संभव केस न संभालना।
- रिकर्सिव कॉल करते समय आर्गुमेंट ठीक से न बदलना, जिससे बेस केस तक पहुँचना ही न हो।
