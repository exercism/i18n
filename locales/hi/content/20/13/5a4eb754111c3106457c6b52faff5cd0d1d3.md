# परिचय

जब आपके पास चुनने के लिए कई अलग-अलग संभावित वैल्यू हों, तो `if`s की लंबी कड़ी के मुकाबले `case` (जो [`combinators`][combinators] में मौजूद है) एक ज़्यादा साफ़ तरीका है।

## `case`

```
case ( obj assoc -- )
```

`case` स्टैक के ऊपर से वैल्यू उठाता है और क्लॉज़ की एक *एसोस* लेता है। हर क्लॉज़ `{ value [ body ] }` रूप का होता है। जिस क्लॉज़ की वैल्यू इनपुट के `=` होती है, वही पहले जीत जाता है। उस क्लॉज़ का बॉडी तब चलता है, जब इनपुट वैल्यू *पहले ही स्टैक से हट चुकी* होती है। आखिर में रखी कोई एंट्री जो सिर्फ `[ body ]` हो, वह डिफ़ॉल्ट होती है। जब वह चलती है, तब इनपुट *अब भी स्टैक पर* होता है।

```factor
USING: combinators ;

: name-of ( n -- s )
    {
        { 1 [ "one" ] }
        { 2 [ "two" ] }
        [ drop "many" ]
    } case ;
```

बराबरी `=` से तय होती है, इसलिए जो भी चीज़ `=` से बराबर मिलती है, उसे `case` में की के रूप में इस्तेमाल किया जा सकता है। संख्याएँ, स्ट्रिंग और सिंबल, सभी ऐसा कर सकते हैं।

## शर्त वाली शाखाओं के लिए `cond`

जब चुनाव बराबरी पर नहीं, बल्कि किसी *प्रेडिकेट* पर निर्भर करता हो (जैसे `x > 11`), तो उसके लिए सही टूल `cond` है। `cond` आपने [Cars, Assemble!][cars-assemble] में देखा था।

## सिंबल

`SYMBOL:` एक ऐसा वर्ड घोषित करता है जो खुद को स्टैक पर रख देता है, यानी एक ऐसा टैग वैल्यू जो अपना मूल्यांकन खुद करता है। `SYMBOLS:` एक साथ कई ऐसे वर्ड घोषित करता है:

```factor
SYMBOLS: yes no maybe ;
```

अब `yes` एक वैल्यू है जिसकी तुलना `=` से की जा सकती है, और जिसे आप `case` में की के रूप में इस्तेमाल कर सकते हैं:

```factor
: invert ( ? -- ?' )
    { { yes [ no ] } { no [ yes ] } [ ] } case ;
```
