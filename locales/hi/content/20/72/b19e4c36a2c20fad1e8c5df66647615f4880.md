# परिचय

कुछ लूप ऐसे लिखे ही नहीं जा सकते कि "सीक्वेंस के हरेक एलिमेंट के लिए यह कीजिए"। कभी-कभी आपको तब तक चलते रहना पड़ता है जब तक कोई शर्त न बदल जाए। Factor का `while` कॉम्बिनेटर इसी काम का टूल है: एक प्रेडिकेट क्वोटेशन बताता है कि "चलते रहना है?", बॉडी क्वोटेशन एक कदम का काम करता है, और `while` तब तक दोहराता है जब तक प्रेडिकेट `f` न दे दे।

## `while` और `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` और `body` दोनों क्वोटेशन हैं जो डेटा स्टैक पर काम करते हैं। `while` तब तक लूप करता रहता है जब तक `pred` कोई सत्य वैल्यू छोड़ता है; `until` इसका उल्टा है: यह तब तक लूप करता रहता है जब तक `pred` सत्य न हो जाए (यानी जब तक `pred` `f` छोड़ता रहे)।

स्थिति का एक ही टुकड़ा स्टैक पर प्रेडिकेट और बॉडी के बीच बह सकता है:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

ट्रेस: प्रेडिकेट `dup 0 >` चलते हुए काउंटर को देखता है; बॉडी `dup . 1 -` उसे छापती है और घटाती है; काउंटर के `0` तक पहुँचते ही लूप रुक जाता है। अंत में लगा `drop` उस अंतिम `0` को स्टैक से हटा देता है।

## `while*`: प्रेडिकेट की वैल्यू बनाए रखना

```
while* ( pred body -- )
```

`while` को सिर्फ इस बात से मतलब है कि उसके प्रेडिकेट ने कोई सत्य वैल्यू छोड़ी या नहीं, और वह खुद उस वैल्यू को बॉडी चलाने से पहले फेंक देता है। `while*` इसके उल्टे उस वैल्यू को बॉडी को सौंप देता है। जब भी टेस्ट और बॉडी को वही अभी निकाली गई चीज़ चाहिए हो, तब इसका इस्तेमाल कीजिए: कोई लुकअप, कोई मैच, या कोई पार्स किया गया टोकन।

यहाँ हर नाम एक ज़ंजीर में अगले नाम की ओर इशारा करता है। प्रेडिकेट मौजूदा नाम को खोजता है; जब तक कोई अगला नाम मौजूद है, `while*` उसे बॉडी को सौंप देता है, और बॉडी उसे छापकर वहीं से आगे बढ़ती है:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at` अगला नाम लौटाता है, और जब किसी नाम की कोई एंट्री न हो तो `f`। जब तक यह कोई नाम लौटाता है, `while*` उस नाम को `dup .` को देता है, जो उसे छापता है और अगली लुकअप के लिए की के रूप में छोड़ देता है। पहला `f` लूप रोक देता है, और `while*` उसे हटा देता है, इसलिए कुछ भी बचता नहीं।

## लोकल्स के साथ कई वैल्यू वाली स्थिति

जब लूप एक से ज़्यादा वैल्यू लिए चलता है, मान लीजिए कोई बचा हुआ ऐरे और कोई चलता हुआ जोड़, तो स्टैक को इधर-उधर करना उलझन भरा हो जाता है। सबसे साफ़ तरीका यह है कि आप `::` से लोकल्स घोषित करें:

```
:: word ( inputs -- outputs ) ... ;
```

बॉडी के अंदर `:> name!` एक बदल सकने वाला लोकल जोड़ता है; पढ़ने के लिए `name` इस्तेमाल होता है, लिखने के लिए `name!` (जो स्टैक से नई वैल्यू ले लेता है और उसे असाइन कर देता है)।

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

यहाँ दो लोकल (`rest` और `running`) पूरे लूप की स्थिति सँभालते हैं: प्रेडिकेट उन्हें जाँचता है, बॉडी उन्हें अपडेट करती है, और अंत में वह वैल्यू लौटा दी जाती है।

`unclip ( seq -- rest first )` किसी सीक्वेंस का पहला एलिमेंट अलग कर देता है, जो तब काम आता है जब लूप हर इटरेशन में ऐरे का एक एलिमेंट खत्म करना चाहता हो। `[ rest! ] dip` रूप `rest` को बचे हुए भाग में बदल देता है और अभी स्टैक से निकाले गए एलिमेंट को बॉडी के इस्तेमाल के लिए स्टैक पर छोड़ देता है।
