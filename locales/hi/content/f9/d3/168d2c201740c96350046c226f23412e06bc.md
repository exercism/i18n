# परिचय

Go में स्ट्रिंग अपरिवर्तनीय होती हैं। लूप में `+` से स्ट्रिंग जोड़ने पर बार-बार मेमोरी अलॉक होती है और डेटा कई बार कॉपी होता है। मेमोरी ओवरहेड कम करने के लिए [`strings` पैकेज](https://pkg.go.dev/strings) [`Builder`](https://pkg.go.dev/strings#Builder) देता है, जो स्ट्रिंग को कुशलता से जोड़कर बनाता है।

## स्ट्रिंग बनाना

`strings.Builder` का ज़ीरो वैल्यू बिना किसी स्पष्ट इनिशियलाइज़ेशन या अलॉकेशन के तुरंत इस्तेमाल के लिए तैयार रहती है। आप कुछ खास राइट मेथड से बिल्डर में नया डेटा डाल सकते हैं। हर राइट मेथड Go के स्टैंडर्ड इंटरफेस की ज़रूरत पूरी करने के लिए एक एरर वैल्यू लौटाता है। लेकिन यह गारंटी है कि वह हमेशा `nil` होती है, और रोज़मर्रा के कोड में उसे आमतौर पर अनदेखा किया जाता है।

सबसे अधिक इस्तेमाल होने वाले मेथड ये हैं:

- `WriteString(s string) (int, error)`: बफर में एक स्ट्रिंग जोड़ता है।
- `WriteRune(r rune) (int, error)`: किसी रून का UTF-8 एनकोडिंग जोड़ता है।
- `WriteByte(c byte) error`: एक बाइट जोड़ता है।

```go
var sb strings.Builder

sb.WriteString("Hello")
var r rune = ' '
sb.WriteRune(r)
var b byte = '.'
sb.WriteByte(b)
```

## स्ट्रिंग प्राप्त करना और रीसेट करना

जब आप अपना टेक्स्ट तैयार कर लें, तो `String()` मेथड कॉल करके आप जमा हुए कंटेंट को स्टैंडर्ड Go स्ट्रिंग के रूप में निकाल सकते हैं। `String()` को कॉल करना बहुत कम खर्च वाला ऑपरेशन है, क्योंकि यह जमा हुए डेटा को कॉपी किए बिना मूल बाइट स्लाइस को सीधे स्ट्रिंग के रूप में लौटाता है।

अगर आपको नई स्ट्रिंग बनाने के लिए उसी बिल्डर इंस्टेंस का दोबारा इस्तेमाल करना हो (जैसे किसी लूप के अंदर), तो आप `Reset()` मेथड कॉल कर सकते हैं। यह अंदरूनी बफर को खाली कर देता है, जिससे आप नए सिरे से शुरू करके अगली स्ट्रिंग बना सकते हैं और पहले से अलॉक की गई मेमोरी क्षमता भी अंदर ही अंदर सुरक्षित रहती है।

```go
var sb strings.Builder

sb.WriteString("Task One")
fmt.Println(sb.String()) // Output: Task One

// Clear the buffer for resource reuse
sb.Reset()

sb.WriteString("Task Two")
fmt.Println(sb.String()) // Output: Task Two
```
