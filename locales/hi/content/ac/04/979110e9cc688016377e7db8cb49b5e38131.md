# स्वामित्व

Cairo में स्वामित्व की अवधारणा _वेरिएबलो_ से जुड़ी होती है, उन _वैल्यू_ से नहीं जो वे रखते हैं।

Cairo में वैल्यू अपरिवर्तनीय होती हैं। यह अपरिवर्तनीयता यह सुनिश्चित करती है कि चाहे कई वेरिएबल एक ही वैल्यू की ओर इशारा करें, वह वैल्यू खुद स्थिर और बिना बदले रहती है।
इसलिए कंपाइलर को यह सुनिश्चित करना होता है कि प्रोग्रामर उनका सही उपयोग करे।
वेरिएबल के _स्वामित्व_ का यही मतलब है: मालिक वह कोड होता है जो उस वेरिएबल को पढ़ सकता है (और अगर वह परिवर्तनीय है तो लिख भी सकता है)।

## वेरिएबल के स्वामित्व के नियम

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## वेरिएबल का स्कोप

स्कोप किसी प्रोग्राम के अंदर वह दायरा है जिसमें एक वेरिएबल वैध रहता है।
चलिए नीचे दिए गए उदाहरण को देखते हैं। यह `x` नाम का एक अहस्ताक्षरित पूर्णांक टाइप वाला वेरिएबल घोषित करता है, और टिप्पणियों में बताता है कि वह वेरिएबल कहाँ वैध है:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

ध्यान दें:

- जब `x` स्कोप में आता है, तो वह वैध होता है।
- यह तब तक वैध रहता है जब तक स्कोप से बाहर न चला जाए, यानी इस उदाहरण में `main()` फंक्शन के अंत तक।

## वैल्यू का स्थानांतरण

स्थानांतरण तब होता है जब कोई वैल्यू किसी दूसरे फंक्शन को दी जाती है। ऐसा होने पर जिस मूल वेरिएबल के पास वह वैल्यू थी वह नष्ट हो जाता है (और इस तरह वह वेरिएबल बेकार हो जाता है), और उसी वैल्यू को रखने के लिए एक नया वेरिएबल बन जाता है।

ऐरे ऐसे जटिल टाइप का उदाहरण हैं जो किसी दूसरे फंक्शन को दिए जाने पर स्थानांतरित हो जाते हैं।
नीचे छोटा-सा उदाहरण है कि ऐरे दिखता कैसा है:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

टाइप सिस्टम यह कैसे सुनिश्चित करता है कि Cairo का प्रोग्राम एक ही मेमोरी सेल में दो बार लिखने की कोशिश कभी न करे?
नीचे दिए गए कोड को देखिए, जिसमें हम ऐरे के आगे वाला हिस्सा दो बार हटाने की कोशिश करते हैं:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

यहाँ हम एक ही वैल्यू (यानी `arr` वेरिएबल में रखे ऐरे) को दोनों फंक्शन कॉल को देने की कोशिश करते हैं।
इसका मतलब है कि हमारा कोड पहले एलिमेंट को दो बार हटाने की कोशिश करता है, यानी एक ही मेमोरी सेल में दो बार लिखने की कोशिश होती है। Cairo VM इसे मना करता है, जिससे रनटाइम एरर आती है।
अच्छी बात है कि यह कोड असल में कंपाइल ही नहीं होता।
एक बार जब हम ऐरे को `foo` फंक्शन को दे देते हैं, तो `arr` वेरिएबल अब इस्तेमाल के लायक नहीं रहता।
हमें यह कंपाइल-टाइम एरर मिलती है, जो बताती है कि हमें `Array` में `Copy` ट्रेट लागू करनी होगी:

## Copy ट्रेट

अगर कोई टाइप `Copy` ट्रेट लागू करता है, तो उसे किसी फंक्शन को देने पर वैल्यू स्थानांतरित नहीं होती, बल्कि उसी वैल्यू की ओर इशारा करने वाला एक नया वेरिएबल बन जाता है।
यह काम किसी अतिरिक्त खर्च के बिना हो जाता है, क्योंकि वेरिएबल असल में Cairo का एक एब्स्ट्रैक्शन हैं और वैल्यू हमेशा अपरिवर्तनीय होती हैं।

अपने टाइप पर `Copy` ट्रेट लागू करने के लिए टाइप की परिभाषा में `#[derive(Copy)]` एनोटेशन जोड़िए।
लेकिन Cairo यह तब नहीं करने देगा, जब वह टाइप या उसका कोई भी हिस्सा `Copy` ट्रेट लागू नहीं करता।

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## वैल्यू को नष्ट करना

लीनियर टाइप का उपयोग उन्हें नष्ट करके भी किया जा सकता है, जिससे यह सुनिश्चित होता है कि जुड़ा हुआ संसाधन ठीक से मुक्त हो जाए।
यह `Drop` ट्रेट लागू करके या उससे व्युत्पन्न करके किया जाता है, जो कंपाइलर को बताता है कि टाइप के काम का न रहने पर उसे सुरक्षित रूप से नष्ट किया जा सकता है।

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

इस समय, `Drop` का कार्यान्वयन सभी टाइपों के लिए व्युत्पन्न किया जा सकता है, सिवाय डिक्शनरी (`Felt252Dict`) और डिक्शनरी रखने वाले टाइपों के।
ऐसा इसलिए है क्योंकि डिक्शनरी को नष्ट करते समय उन्हें "स्क्वैश" करना पड़ता है।
इसके लिए हम `Destruct` ट्रेट व्युत्पन्न करते हैं:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## रिटर्न वैल्यू और स्कोप

वैल्यू लौटाना उन्हें स्थानांतरित करने के बराबर है।
नीचे दिया गया उदाहरण एक ऐसा फंक्शन दिखाता है जो कोई वैल्यू लौटाता है:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
