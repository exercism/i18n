# कस्टम इटरेटर

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | रूटीन | इटरेटर |
| --- | --- | --- |
| नाम | `foo` | `foo!` |
| वैल्यू वापस देता है | `return` | `yield` |
| समाप्त होता है | `return`, या अंत | `quit`, या खत्म हो जाने पर |
| कॉल किया जा सकता है | कहीं भी | सिर्फ `loop` के अंदर |
| अपनी जगह बनाए रखता है | नहीं | हाँ |

## yield

`yield` एक वैल्यू सौंपता है और वहीं रुक जाता है। अगले इटरेशन पर सब कुछ पहले जैसा हो जाता है: लोकल वेरिएबलो, इटरेटर के अपने लूप में उसकी जगह, और उन इटरेटरों की जगह भी जिन्हें वह खुद कॉल कर रहा है।

नेस्टेड लूप के अंदर किया गया `yield` सबसे अंदर वाले लूप से आगे बढ़ता है, और इसी वजह से नेस्टेड चीज़ों पर एक-एक करके चलने वाला कोड लिखना सीधा-सरल हो जाता है:

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

यह इटरेटर को समाप्त कर देता है, और उसके साथ उस लूप को भी जो उसे कॉल कर रहा है। यह कोई वैल्यू नहीं देता: `quit` कोई अंतिम परिणाम नहीं है, बल्कि यह बताता है कि कोई परिणाम है ही नहीं।

जिस इटरेटर का रिटर्न टाइप हो, उसे हर बार `yield` करते समय एक वैल्यू देनी ही पड़ती है; और जब वह ऐसा नहीं करना चाहता, तो `quit` से करता है।

## once

```sather
   markers!(once count : INT) : INT is
```

`once` आर्गुमेंट की गणना लूप में प्रवेश करते समय एक बार होती है और वह परिणाम बनाए रखा जाता है। साधारण आर्गुमेंट की गणना हर इटरेशन पर दोबारा होती है, और यह तब मायने रखता है जब पास किए गए एक्सप्रेशन में किसी दूसरे इटरेटर को कॉल किया गया हो:

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

जब तक आपको जान-बूझकर यही न चाहिए हो, आर्गुमेंट को `once` बनाइए। पूरी लाइब्रेरी यही करती है।

## self और इटरेटर

किसी इटरेटर को किसी ऑब्जेक्ट पर कॉल किया जा सकता है, और तब `self` वही ऑब्जेक्ट होता है। उसकी रुकी हुई स्थिति कॉल साइट की होती है, ऑब्जेक्ट की नहीं, इसलिए एक ही ऑब्जेक्ट पर चलने वाले दो लूप एक-दूसरे में दखल नहीं देते।

## कब लिखना है

इटरेटर तब लिखिए जब जवाब एक क्रम के रूप में हो और यह तय करना कॉल करने वाले पर छोड़ना हो कि उसमें से कितना लेना है। जल्दी रुक जाने में कोई खर्च नहीं होता, और जो इस्तेमाल नहीं होगा वह बनाया भी नहीं जाता। वहीं, एक `ARRAY` लौटाने वाले रूटीन को पहले पूरी चीज़ बनानी ही पड़ती है।
