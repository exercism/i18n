# परिचय

Go में स्ट्रिंग अपरिवर्तनीय होती हैं।
लूप में `+` से स्ट्रिंग जोड़ने पर बार-बार मेमोरी आवंटन होता है और डेटा कई बार कॉपी होता है।
[`strings` पैकेज](https://pkg.go.dev/strings) [`Builder`](https://pkg.go.dev/strings#Builder) देता है, जिससे स्ट्रिंग को कुशलता से जोड़कर मेमोरी का ओवरहेड कम किया जा सकता है।

## स्ट्रिंग बनाना

किसी `strings.Builder` की ज़ीरो वैल्यू बिना किसी स्पष्ट इनिशियलाइज़ेशन या आवंटन के तुरंत इस्तेमाल के लिए तैयार होती है।
आप कुछ खास राइट मेथड की मदद से बिल्डर में नया डेटा भेज सकते हैं।
हर राइट मेथड Go के मानक इंटरफेस को पूरा करने के लिए एक एरर वैल्यू लौटाता है, लेकिन गारंटी यह है कि वह हमेशा `nil` ही होगी और आम कोड में उसे आम तौर पर नज़रअंदाज़ किया जाता है।

सबसे ज़्यादा इस्तेमाल होने वाले मेथड ये हैं:

- `WriteString(s string) (int, error)`: बफर में एक स्ट्रिंग जोड़ता है।
- `WriteRune(r rune) (int, error)`: बफर में किसी रून की UTF-8 एन्कोडिंग जोड़ता है।
- `WriteByte(c byte) error`: बफर में एक बाइट जोड़ता है।

```go
var sb strings.Builder

sb.WriteString("Hello")
var r rune = ' '
sb.WriteRune(r)
var b byte = '.'
sb.WriteByte(b)
```

## स्ट्रिंग निकालना और रीसेट करना

अपना टेक्स्ट जोड़ना पूरा करने के बाद आप `String()` मेथड को कॉल करके जमा हुए कंटेंट को एक मानक Go स्ट्रिंग के रूप में निकाल सकते हैं।
`String()` को कॉल करना बहुत सस्ता ऑपरेशन है, क्योंकि यह अंदरूनी बाइट स्लाइस को बिना जमा हुआ डेटा कॉपी किए सीधे स्ट्रिंग के रूप में लौटाता है।

अगर आपको नई स्ट्रिंग बनाने के लिए उसी बिल्डर इंस्टेंस को फिर से इस्तेमाल करना हो (जैसे किसी लूप के अंदर), तो आप `Reset()` मेथड को कॉल कर सकते हैं।
यह अंदरूनी बफर को खाली कर देता है। इससे आप नई शुरुआत करके अगली स्ट्रिंग बना सकते हैं, और अंदर ही अंदर पहले से आवंटित मेमोरी क्षमता भी बनी रहती है।

```go
var sb strings.Builder

sb.WriteString("Task One")
fmt.Println(sb.String()) // Output: Task One

// Clear the buffer for resource reuse
sb.Reset()

sb.WriteString("Task Two")
fmt.Println(sb.String()) // Output: Task Two
```
