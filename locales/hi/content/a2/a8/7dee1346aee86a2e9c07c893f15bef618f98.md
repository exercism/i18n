# विवरण

## const

[`const`][constants] मॉडिफायर को किसी भी ऐसी फील्ड पर लगाया जा सकता है (और सामान्यतः लगाना चाहिए) जिसकी वैल्यू कंपाइल समय पर ज्ञात हो और प्रोग्राम के जीवनकाल में नहीं बदलेगी।

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

कंपाइलर आपको बताएगा कि कौन-से एक्सप्रेशन कंपाइल समय पर मूल्यांकित किए जा सकते हैं। साधारण अंकगणितीय संक्रियाएँ की जा सकती हैं, और स्ट्रिंग जोड़ना भी। इसमें वे सभी मूल्यांकन शामिल नहीं हैं जिनके लिए हीप या स्टैक के उपयोग की ज़रूरत होगी, इसलिए सभी मेथड कॉल और नॉन-प्रिमिटिव टाइप के रेफरेंस उपलब्ध नहीं हैं।

वेब पर इस बारे में कुछ चर्चा है कि वेरिएबल के मुकाबले `const` के प्रदर्शन में क्या फायदे हैं। इंस्टेंस वाले नॉन-`const` फील्ड से तुलना करने पर मेमोरी में ध्यान देने योग्य बचत हो सकती है, लेकिन स्टैटिक वेरिएबल के मुकाबले यह बिल्कुल मामूली है। CPU प्रदर्शन पर किसी भी तरह का विचार आपके सहकर्मी [समय से पहले का ऑप्टिमाइज़ेशन][premature-optimization] मानेंगे।

`const` इस्तेमाल करने की एक और ठोस वजह यह है कि इससे मेंटेनर के लिए कोड को समझना आसान हो जाता है। किसी फील्ड पर `const` या `readonly` का निशान होना, या किसी प्रॉपर्टी में सेटर न होना, देखते ही मेंटेनर उसे अपने विश्लेषण से काफी हद तक बाहर कर सकता है। ऐसी जगह बग होने की संभावना कम होती है। रीफैक्टरिंग करते समय यह मुश्किलें खड़ी करने की संभावना कम रहती है। [Stack Overflow पर यह कमेंट][so-consts] इसी विषय पर बात करता है।

`const` मॉडिफायर को मेथड के अंदर की वैल्यू पर भी लगाया जा सकता है:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

किसी वैल्यू को इस तरह `const` से पहचानना तब उपयोगी हो सकता है जब वह मेथड में कई बार इस्तेमाल होती हो, या जब आप उसके अर्थ की ओर ध्यान खींचना चाहते हों। इनलाइन लिटरल इस्तेमाल करने के मुकाबले प्रदर्शन में कोई फायदा नहीं मिलता।

## readonly

[`readonly`][readonly-fields] मॉडिफायर को किसी भी ऐसी फील्ड पर लगाया जा सकता है (और सामान्यतः लगाना चाहिए) जिसे `const` नहीं बनाया जा सकता और जिसकी वैल्यू प्रोग्राम के जीवनकाल में नहीं बदलेगी, तथा जो या तो किसी इनलाइन इनिशियलाइज़र से सेट होती है या इंस्टैंशिएशन के दौरान (कंस्ट्रक्टर से या कंस्ट्रक्टर द्वारा कॉल किए गए किसी मेथड से)।

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

`readonly` मॉडिफायर के इस्तेमाल को उन्हीं कारणों से प्रोत्साहित किया जाता है जो `const` पर लागू होते हैं। फील्ड को इस तरह सीमित करने की आदत मेंटेनर को कोड समझने में मदद करती है।

ध्यान दीजिए कि किसी फील्ड पर `readonly` मॉडिफायर लगाना केवल उस फील्ड की वैल्यू को बदलने से रोकता है। अग्रीगेट टाइप के मामले में यह उस टाइप की फील्ड या प्रॉपर्टी को सुरक्षित नहीं रखता। खास तौर पर, यह ऐरे की सामग्री को सुरक्षित नहीं रखता।

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

किसी रेफरेंस टाइप के सभी सदस्यों को सुरक्षित रखने के लिए फील्ड को `readonly` बनाया जा सकता है और ऑटोमैटिक प्रॉपर्टी को `set` एक्सेसर के बिना परिभाषित किया जा सकता है।

आपको Base Class Library में [रीड-ओनली कलेक्शन][readonly-collections] देखने चाहिए।

ऐरे के लिए रीड-ओनली रूप के सबसे करीब आप [`Array.AsReadOnly<T>()`][as-read-only] मेथड से पहुँच सकते हैं।
