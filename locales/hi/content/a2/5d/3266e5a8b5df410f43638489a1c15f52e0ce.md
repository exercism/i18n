# टेस्ट

हर अभ्यास में एक टेस्ट फाइल होती है।
टेस्ट चलाने के लिए `bats` प्रोग्राम इस्तेमाल कीजिए।
```bash
bats test-hello-world.bats
```

`bats` को इंस्टॉल करना होगा।
अपने सिस्टम पर `bats` इंस्टॉल करने के निर्देशों के लिए [Bash ट्रैक पर टेस्ट चलाना][bash] पेज देखिए।

### bats खुद bash में लिखा गया है

bats फाइल एक bash स्क्रिप्ट है, जिसमें कुछ खास फंक्शन होते हैं जिन्हें `bats` कमांड पहचानता है।
आपको कुछ टेस्ट ऐसे दिखेंगे:
```sh
gawk -f some-exercise.awk <<< "some,input,here"
```
यह `<<<` सिंटैक्स bash का [Here String][here-string] है।
यह दाईं ओर की स्ट्रिंग को बाईं ओर वाले प्रोग्राम के स्टैंडर्ड इनपुट में भेज देता है।
यह ([लगभग][so]) इसके बराबर है:
```sh
echo "some,input,here" | gawk -f some-exercise.awk
```

## assert फंक्शन के लिए मदद

ये टेस्ट [bats-assert][bats-assert] लाइब्रेरी के फंक्शन इस्तेमाल करते हैं।
अलग-अलग `assert*` फंक्शन के लिए मदद वहीं मिल जाएगी।

## स्किप किए गए टेस्ट

किसी अभ्यास को हल करने का मतलब है कि उसके सारे टेस्ट पास हो जाएँ।
डिफॉल्ट रूप से, जब आप टेस्ट चलाते हैं तो सिर्फ एक टेस्ट (पहला वाला) चलता है।
यह जानबूझकर ऐसा रखा गया है, ताकि आपका ध्यान सिर्फ उसी एक टेस्ट को पास कराने पर टिका रहे।
एक बार वह पास हो जाए, तो अगला टेस्ट चालू करने के लिए बाकी टेस्टों के आगे लगे इन

    [[ $BATS_RUN_SKIPPED == true ]] || skip

एनोटेशन को कॉमेंट कर दीजिए या हटा दीजिए।

## स्किप को ओवरराइड करना

सभी टेस्ट चलाने के लिए, यानी उन टेस्टों समेत जिन पर `skip` एनोटेशन लगे हैं, आप यह चला सकते हैं:
```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

टाइपिंग कम करने के लिए रैपर फंक्शन इस्तेमाल करना सुविधाजनक रहता है। `bash` में आप ऐसा कर सकते हैं:
```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```
फिर टेस्ट चलाने के लिए सिर्फ इतना लिखिए:
```bash
bats
```

## डीबग आउटपुट

```exercism/caution
यह `bats` के साथ आपकी अपनी मशीन पर काम करता है, लेकिन Exercism के ऑनलाइन एडिटर में **नहीं**।
```

टेस्ट चलाते समय `bats` stdout और stderr दोनों को कैप्चर कर लेता है, ताकि उनकी अपेक्षित आउटपुट से तुलना की जा सके।
अगर आप stdout या stderr पर डीबग संदेश प्रिंट करते हैं, तो वे कैप्चर किए गए आउटपुट में शामिल हो जाएँगे और इससे टेस्ट फेल हो सकता है।

टेस्ट के नतीजों पर असर डाले बिना डीबग जानकारी प्रिंट करने के लिए `bats` इस काम के लिए फाइल डिस्क्रिप्टर **3** देता है।
`/dev/fd/3` फाइल पर प्रिंट हुई कोई भी चीज़ टेस्ट चलने के दौरान दिखाई देगी, लेकिन जाँच के लिए इस्तेमाल होने वाले कैप्चर किए गए आउटपुट में शामिल नहीं होगी।

उदाहरण:

```awk
BEGIN {
    # This debug message will not interfere with test output comparison
    print "a debug message" > "/dev/fd/3"

    # Normal program output (this is what your tests will see and compare)
    print "Hello, World!"
}
```

चलाने का उदाहरण:

```none
$ bats test-hello-world.bats
test-hello-world.bats
 ✓ Say Hi!
a debug message

1 test, 0 failures
```

इससे आप टेस्ट पर असर डाले बिना काम की डीबग जानकारी देख सकते हैं।

अगर आप अपने कोड में कई जगहों पर ऐसा करते हैं, तो इन विवरणों को एक फंक्शन के अंदर छिपा देना पढ़ने में आसानी बढ़ा सकता है:

```awk
BEGIN {
    debug("starting ...")
}

# do stuff here ...

END {
    debug("... finished")
}

function debug(msg) {print msg > "/dev/fd/3"}
```
