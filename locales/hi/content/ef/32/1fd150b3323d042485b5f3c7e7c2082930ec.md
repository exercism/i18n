# परिचय

Factor के थ्रेड *कोऑपरेटिव कोरूटीन* होते हैं। ये एक ही OS थ्रेड साझा करते हैं, I/O के समय और साफ़-साफ़ बताए गए यील्ड पॉइंट पर एक-दूसरे को कंट्रोल सौंपते हैं, और कभी सचमुच एक साथ नहीं चलते। यील्ड के *बीच* में आप जो कुछ भी करते हैं, वह एक ही बिना रुके चलने वाले स्टेप के तौर पर होता है। लेकिन अगर कोई मिली-जुली क्रिया (रीड-मॉडिफाई-राइट) बीच में ही यील्ड कर दे, तो आपके काम पूरा करने से पहले कोई दूसरा थ्रेड बीच में घुसकर दुनिया बदल सकता है, और यही रेस है।

इस अभ्यास में चार ऐसे प्रिमिटिव हैं जो बार-बार सामने आते हैं:

## `parallel-map`: किसी सीक्वेंस पर फोर्क/जॉइन

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

[`concurrency.combinators`][combinators] में। यह हर एलिमेंट के लिए एक थ्रेड बनाता है, क्वोटेशन चलाता है, और नतीजों को उसी क्रम में एक नए सीक्वेंस में इकट्ठा कर देता है:

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`: एक थ्रेड शुरू कीजिए

```
spawn ( quot name -- thread )
```

[`threads`][threads] में। क्वोटेशन साथ-साथ चलता है; `name` डिबगिंग के लिए एक लेबल है। इस स्तर पर लौटाया गया थ्रेड हैंडल ज़्यादा काम का नहीं होता, उसे `drop` कर दीजिए।

## प्रॉमिस: वैल्यू एक बार में सौंपना

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

[`concurrency.promises`][promises] में। प्रॉमिस एक ऐसा मेलबॉक्स है जो सिर्फ एक बार काम करता है: कोई एक थ्रेड उसे पूरा करता है, बाकी उसे पढ़ते हैं। `?promise` तब तक रुकता है जब तक प्रॉमिस पूरा न हो जाए, और फिर वैल्यू लौटाता है।

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

`parallel-map` इन्हीं `spawn` और `<promise>` से बनाया गया है; इन्हें खुद से जोड़ना तब काम आता है जब हर टास्क "एक एलिमेंट निकालने" के अलावा कुछ और करता हो।

किसी सीक्वेंस पर फैन-आउट/जॉइन का आम ढाँचा यह है: हर इनपुट के लिए एक नया प्रॉमिस बनाइए, एक थ्रेड शुरू कीजिए जो काम करके प्रॉमिस `fulfill` कर दे, सारे प्रॉमिस को एक सीक्वेंस में इकट्ठा कीजिए, और फिर पूरा होने का इंतज़ार करने के लिए हर एक पर `?promise` कीजिए। लोकल्स इसे पढ़ने लायक बना देते हैं: `[| | ]` लैम्डा के अंदर `:>` से प्रॉमिस को किसी नाम से बाँधिए, ताकि शुरू किया गया क्वोटेशन उस तक पहुँच सके:

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## लॉक: पारस्परिक अपवर्जन

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

[`concurrency.locks`][locks] में। किसी लॉक को एक बार में सिर्फ एक ही थ्रेड पकड़ सकता है। `with-lock` लॉक लेता है, क्वोटेशन चलाता है, और उसे छोड़ देता है, भले ही क्वोटेशन कोई एरर फेंके।

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

जब भी किसी वैल्यू को *एक से ज़्यादा थ्रेड पढ़ते या लिखते* हों और उस पर होने वाली क्रियाएँ अपने आप अटॉमिक न हों, तब लॉक का इस्तेमाल कीजिए। पढ़ने और लिखने, दोनों के लिए लॉक ज़रूरी है, क्योंकि बीच में यील्ड करने वाला रीड टूटी हुई स्थिति देख सकता है।
