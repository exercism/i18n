# परिचय

## `Base.@kwdef`

किसी स्ट्रक्ट की परिभाषा के लिए कीवर्ड आर्गुमेंट लेने वाले कंस्ट्रक्टर अपने आप बनाने में `Base.@kwdef` मैक्रो का इस्तेमाल किया जा सकता है।
इससे फील्ड के लिए डिफॉल्ट वैल्यू भी तय की जा सकती है।

उदाहरण के लिए, नीचे दी गई परिभाषा

```julia
Base.@kwdef struct HumanStats
    birthyear::Int
    height::Int
    mass::Int
    bmi::Float64 = mass / (0.01 * height)^2
end
```

एक साथ तीन कंस्ट्रक्टर बनाती है

```julia-repl
julia> methods(HumanStats)
# 3 methods for type constructor:
[1] HumanStats(; birthyear, height, mass, bmi) [...]
[2] HumanStats(birthyear::Int64, height::Int64, mass::Int64, bmi::Float64) [...]
[3] HumanStats(birthyear, height, mass, bmi) [...]
```

जिसमें कीवर्ड आर्गुमेंट पर आधारित एक कंस्ट्रक्टर भी शामिल है

```julia-repl
julia> HumanStats(
           birthyear = 2002,
           height = 193,
           mass = 83
       )
HumanStats(2002, 193, 83, 22.28247738194314)
```

जबकि मानक परिभाषा

```julia
struct HumanStats
    birthyear::Int
    height::Int
    mass::Int
    bmi::Float64
end
```

सिर्फ नीचे दिए गए दो ही बनाती है

```julia-repl
julia> methods(HumanStats)
# 2 methods for type constructor:
[1] HumanStats(birthyear::Int64, height::Int64, mass::Int64, bmi::Float64) [...]
[2] HumanStats(birthyear, height, mass, bmi) [...]
```

और इसमें कीवर्ड आधारित कंस्ट्रक्टर खुद से बनाना पड़ेगा।

### `Base.@kwdef` का इस्तेमाल कब करें?

कीवर्ड आधारित कंस्ट्रक्टर ऐसे स्ट्रक्ट बनाने के लिए खास काम आते हैं जो बहुत सारे आर्गुमेंट लेते हैं, खासकर तब जब आर्गुमेंट का टाइप या वैल्यू उसके मतलब से सीधे जुड़ा न हो।

इस परिभाषा को देखिए:

```julia
dirk = BasketballPlayer(1978, 1994, 2019, 213, 111, 42, 1998, [2011], 31560, 11489, 3651)
```

टाइप की परिभाषा जाने बिना यह साफ नहीं होता कि हर वैल्यू का क्या मतलब है।
और अगर परिभाषा पता भी हो, तो भी शायद हर बार क्रम दोबारा देखना पड़ेगा।

लेकिन कीवर्ड आधारित कंस्ट्रक्टर इस्तेमाल करने पर उनका मतलब तुरंत साफ हो जाता है:

```julia
dirk = BasketballPlayer(
    birthyear = 1978,
    career_start = 1994,
    career_end = 2019,
    height = 213,
    weight = 111,
    number = 42,
    drafted = 1998,
    championships = [2011],
    points = 31560,
    rebounds = 11489,
    assists = 3651
)
```

<!-- ऊपर दिए गए उदाहरणों के लिए यह टाइप परिभाषा इस्तेमाल की गई थी:
```julia
struct BasketballPlayer
    birthyear::Int
    career_start::Int
    career_end::Int
    height::Int
    weight::Int
    number::Int
    drafted::Int
    championships::Vector{Int}
    points::Int
    rebounds::Int
    assists::Int
end
```
-->

~~~~exercism/caution
`Base.@kwdef` को एक्सपोर्ट नहीं किया गया है और मैनुअल में इसका दस्तावेज़ीकरण नहीं है, इसलिए यह [Julia के सार्वजनिक API][public-api] का हिस्सा नहीं है।
इसका मतलब है कि तकनीकी रूप से इसका इंटरफेस स्थिर होने की गारंटी नहीं है और यह Julia के छोटे अपडेट के बीच बदल सकता है।

लेकिन यह मैक्रो पूरे इकोसिस्टम में बहुत इस्तेमाल किया जाता है, और इस बात की संभावना कम है कि इसे किसी ब्रेकिंग तरीके से बदला जाए।
