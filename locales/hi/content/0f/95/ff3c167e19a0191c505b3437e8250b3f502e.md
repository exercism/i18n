# एक्सेप्शन के बारे में

एक्सेप्शन एरर हैंडलिंग का एक तरीका है।
इन्हें एक्सेप्शन इसलिए कहा जाता है, क्योंकि ये आम तौर पर तब सामने आते हैं जब कोई ऐसी बात होती है जिसकी उम्मीद नहीं थी।

अपने कोड में कहीं भी हम एक एक्सेप्शन उठा सकते हैं।
इसके लिए हम `raise` मेथड इस्तेमाल करते हैं और उसे एक ऑब्जेक्ट देते हैं। आम तौर पर यह एक Exception ऑब्जेक्ट होता है, हालाँकि हम साधारण स्ट्रिंग भी दे सकते हैं।
जैसे, अभ्यास के स्टब में आप देखेंगे कि हम बिल्ट-इन `RuntimeError` इस्तेमाल करते हैं। इससे Ruby को पता चलता है कि कोई मेथड अभी लागू नहीं किया गया है।
आप `raise(ExceptionObject, params)` का छोटा रूप भी इस्तेमाल कर सकते हैं।
अगर एक्सेप्शन क्लास नहीं दी जाती, तो डिफ़ॉल्ट रूप से `RuntimeError` इस्तेमाल होता है।

उदाहरण के लिए:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

जब Ruby यह देखता है, तो वह एरर को प्रोग्राम के सबसे ऊपर तक पहुँचा देता है और फिर प्रोग्राम बंद हो जाता है।

जैसे, अगर आप किसी संख्या को शून्य से भाग देने की कोशिश करें, तो आपको कुछ ऐसा दिखेगा:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

यह ध्यान रखना ज़रूरी है कि एक्सेप्शन सिर्फ़ उन हालातों में इस्तेमाल करने चाहिए जहाँ कुछ असाधारण होता है, कोई ऐसी एरर जिसे खास तरीके से संभालने की ज़रूरत होती है।
एक्सेप्शन का इस्तेमाल किसी प्रोग्राम के कंट्रोल-फ्लो के लिए नहीं करना चाहिए, क्योंकि इसे खराब डिज़ाइन माना जाता है। इससे अक्सर परफॉर्मेंस और मेंटेनेबिलिटी खराब होती है।

## क्लास हाइरार्की

Ruby में एक्सेप्शन एक क्लास हाइरार्की का पालन करते हैं, जिसमें `Exception` बेस क्लास होती है।
Ruby के सबसे आम बिल्ट-इन एक्सेप्शन ये हैं:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

किसी खास क्लास की एरर पकड़ने पर उसके चाइल्ड क्लासों की एरर भी पकड़ी जाती हैं।
इसीलिए `Exception` को पकड़ना खतरनाक हो सकता है।
Ruby एक्सेप्शन का इस्तेमाल ऑपरेटिंग सिस्टम के "सिग्नल" संदेशों को संभालने के लिए भी करता है, जैसे `ctrl-c`।
इसका मतलब है कि `Exception` को पकड़ने पर ये सिस्टम "सिग्नल" भी पकड़ लिए जाएँगे।
इसलिए अनपेक्षित व्यवहार रोकने के लिए "सारी एरर" पकड़ने का आम तरीका `StandardError` को पकड़ना है।

## रेस्क्यू सिंटैक्स
Ruby उन हालातों के लिए विस्तृत रेस्क्यू क्लॉज़ भी देता है जिनमें खास देखभाल की ज़रूरत होती है:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

यह तब काम आ सकता है, जैसे जब हम नेटवर्क IO पर काम कर रहे हों और हमें हमेशा कनेक्शन बंद करना याद रखना पड़ता हो।

Ruby के रेस्क्यू ब्लॉक `retry` कीवर्ड का इस्तेमाल भी कर सकते हैं, जो `begin` और `rescue` के बीच का सारा कोड फिर से चलाता है:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
