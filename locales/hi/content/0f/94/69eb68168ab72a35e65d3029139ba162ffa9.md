# परिचय

फंक्शन कोड का एक व्यवस्थित और दोबारा इस्तेमाल किए जा सकने वाला ब्लॉक है, जिसे कोई काम करने के लिए इस्तेमाल किया जाता है।
JavaScript में फंक्शन बनाने के कई तरीके हैं।
यहाँ हम _फंक्शन डिक्लरेशन_ और _फंक्शन एक्सप्रेशन_ देखेंगे।
अन्य संभावनाएँ, जैसे [ऐरो फंक्शन][concept-arrow-functions], दूसरे कॉन्सेप्ट में बताई जाएँगी।

## फंक्शन डिक्लरेशन

JavaScript में फंक्शन बनाने का मानक तरीका _फंक्शन डिक्लरेशन_ है, जिसे _फंक्शन की परिभाषा_ या _फंक्शन स्टेटमेंट_ भी कहा जाता है।

इसमें `function` कीवर्ड, फंक्शन का नाम, और गोल ब्रैकेट में कॉमा से अलग किए गए पैरामीटर की सूची होती है।
इसके बाद फंक्शन बॉडी आती है (उन स्टेटमेंट का समूह जो तय करते हैं कि फंक्शन क्या करता है), जिसे कर्ली ब्रैकेट में लिखा जाता है।

```javascript
function someName(param1, param2, param3) {
  // ...
}
```

JavaScript में फंक्शन को कॉल करने के लिए उसका नाम लिखा जाता है और उसके बाद गोल ब्रैकेट लगाए जाते हैं, जिनमें आर्गुमेंट होते हैं।

```javascript
someName(arg1, arg2, arg3);
```

## पैरामीटर

फंक्शन बॉडी के अंदर पैरामीटर के साथ काम करते समय संभावित साइड इफेक्ट के बारे में ध्यान रखिए।

- [प्रिमिटिव डेटा टाइप][mdn-primitives] की वैल्यू _अपरिवर्तनीय_ होती हैं।
  फंक्शन बॉडी में आर्गुमेंट के साथ जो कुछ होता है, उसका असर मूल वैल्यू पर कभी नहीं पड़ता।
- बाकी सभी वैल्यू (ऑब्जेक्ट, ऐरे, फंक्शन) के लिए, दोबारा असाइन करने से मूल वैल्यू पर कोई असर नहीं पड़ता।
  लेकिन अगर आप ऐसे आर्गुमेंट में बदलाव करते हैं (जैसे किसी ऑब्जेक्ट में एक की जोड़ना), तो इससे वह मूल वैल्यू भी बदल जाती है जो पास की गई थी।

JavaScript में डिफॉल्ट रूप से, फंक्शन डिक्लरेशन में बनाए गए सभी पैरामीटर वैकल्पिक होते हैं।
अगर आप उतने आर्गुमेंट नहीं देते जितने पैरामीटर हैं, तो फंक्शन के अंदर वे छूटे हुए आर्गुमेंट `undefined` होंगे। देखिए [Null and Undefined][concept-null-undefined]।
कई मामलों में, `undefined` के बजाय कोई ज़्यादा उपयुक्त डिफॉल्ट वैल्यू असाइन करना ठीक रहता है।
यह फंक्शन की परिभाषा में सीधे डिफॉल्ट पैरामीटर देकर किया जा सकता है।

```javascript
function someName(param1 = defaultValue1, param2 = defaultValue2) {
  // ...
}
```

## `return` स्टेटमेंट

`return` स्टेटमेंट फंक्शन का निष्पादन समाप्त करता है और बताता है कि फंक्शन को कॉल करने वाले को कौन-सी वैल्यू लौटाई जानी है। एक फंक्शन में कई `return` स्टेटमेंट हो सकते हैं।

```javascript
function checkNumber(num) {
  if (num === 0) {
    return 'You passed 0, please provide another number.';
  }

  return 'Thanks for passing such a nice number.';
}
```

फंक्शन की रिटर्न वैल्यू को एक वेरिएबल में रखा जा सकता है।

```javascript
function sum(x, y) {
  return x + y;
}

const total = sum(5, 10);
// => 15
```

जो फंक्शन कोई वैल्यू `return` नहीं करता या जिसमें `return` स्टेटमेंट नहीं है, उसका परिणाम `undefined` होता है।
JavaScript में कोई अंतर्निहित `return` नहीं होता।

```javascript
function nakedReturn(a) {
  a * 2;
  return;
}

nakedReturn(1);
// => undefined

function noReturn(a) {
  a * 2;
}

noReturn(1);
// => undefined
```

JavaScript में आप केवल एक ही वैल्यू लौटा सकते हैं।
अगर आपको ज़्यादा जानकारी देनी है, तो पहले उसे एक चीज़ में मिलाना पड़ेगा, आम तौर पर किसी [ऑब्जेक्ट][concept-objects] या [ऐरे][concept-arrays] में।

```javascript
function divide(a, b) {
  return {
    quotient: Math.floor(a / b),
    remainder: a % b,
  };
}
```

## फंक्शन एक्सप्रेशन

फंक्शन डिक्लरेशन एक अलग स्टेटमेंट होता है।
लेकिन कभी-कभी फंक्शन को किसी दूसरे एक्सप्रेशन के हिस्से के रूप में बनाना काम आता है, जैसे किसी असाइनमेंट में, फंक्शन के पैरामीटर के रूप में ([कॉलबैक][concept-callbacks]), या किसी [ऑब्जेक्ट][concept-objects] की वैल्यू के रूप में।
यह फंक्शन एक्सप्रेशन से किया जा सकता है।
इसका सिंटैक्स फंक्शन डिक्लरेशन जैसा ही होता है, बस फंक्शन का नाम हटाया जा सकता है, जिससे एक _अनाम फंक्शन_ बनता है।

```javascript
const someFunction = function (param) {
  // ...
};

someOtherFunction(function (param) {
  // ...
});

const obj = {
  someFunction: function (param) {
    // ...
  },
};
```
