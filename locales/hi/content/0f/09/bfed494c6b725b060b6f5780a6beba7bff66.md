# पाइपलाइन और कमांड लिस्ट का परिचय

हमने देखा है कि सरल कमांड कैसे लिखी जाती हैं, जिनमें कमांड के बाद आर्गुमेंट आते हैं।
अब हम देखेंगे कि सरल कमांड को जोड़कर ज़्यादा जटिल कमांड कैसे बनाई जाती हैं।

## इनपुट और आउटपुट

शुरू करने से पहले, इनपुट/आउटपुट का एक छोटा परिचय।

प्रोसेस के पास "स्टैंडर्ड I/O चैनल" होते हैं।

* कोई प्रोसेस "stdin" पर _इनपुट_ ले सकता है।
* कोई प्रोसेस "stdout" पर _आउटपुट_ दे सकता है।
* कोई प्रोसेस "stderr" पर _एरर आउटपुट_ दे सकता है।

`tr` कमांड इसका बहुत साफ उदाहरण है।
यह बस अपने इनपुट से टेक्स्ट पढ़ती है, अक्षरों का ट्रांसलिटरेशन करती है, और नतीजा टेक्स्ट अपने आउटपुट पर छापती है।

"stdio" चैनलों को संभालने के बारे में हम सिलेबस में आगे और देखेंगे।

## पाइपलाइन

यह शेल प्रोग्रामिंग के "सबसे खास फीचर्स" में से एक है।
पाइपलाइन की मदद से आप टेक्स्ट की स्ट्रीम पर जटिल बदलाव कर सकते हैं।

उपयोगकर्ताओं की क्रमबद्ध सूची बनाने के लिए:

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

पाइप चिह्न (`|`) एक कमांड के आउटपुट को दूसरी कमांड के इनपुट से जोड़ता है।
`cut`, `cat` का आउटपुट पढ़ता है, और `sort`, `cut` का आउटपुट पढ़ता है।

~~~~exercism/advanced
* डिफ़ॉल्ट रूप से, पाइपलाइन की हर कमांड एक अलग सबशेल में चलती है।
  (सबशेल एक चाइल्ड प्रोसेस होता है जो अभी चल रहे शेल की कॉपी होता है।)

* पाइपलाइन चलाने पर परफॉर्मेंस का खर्च लगता है।
  अगर आपके पास एक जैसी कमांडों की लंबी पाइपलाइनें हों, तो उन्हें एक ही कमांड में जोड़ने के बारे में सोचिए।
  उदाहरण के लिए, `grep`, `cut`, `sed`, `awk` और `tr` का बार-बार इस्तेमाल करने वाली पाइपलाइनों को आम तौर पर एक ही `awk` कमांड में जोड़कर तेज़ बनाया जा सकता है।

* पाइपलाइन का एग्ज़िट स्टेटस पाइपलाइन की अंतिम कमांड का एग्ज़िट स्टेटस होता है।
  इसका मतलब है कि अगर कोई पिछली कमांड फेल हुई हो, लेकिन अंतिम कमांड सफल रही हो, तो पूरी पाइपलाइन का एग्ज़िट स्टेटस शून्य होता है।

  एक शेल सेटिंग है जो इसे बदल सकती है;
  अगर "pipefail" सेटिंग चालू हो ( `set -o pipefail` के साथ), तो पाइपलाइन का एग्ज़िट स्टेटस यह होगा:
  * शून्य, अगर सभी कमांड सफल हों, अन्यथा
  * पाइपलाइन की कमांडों का _**अंतिम** गैर-शून्य एग्ज़िट स्टेटस_।
~~~~

## कमांड लिस्ट

कमांड लिस्ट पाइपलाइनों का एक क्रम होती है, जिन्हें `;` (या नई लाइन), `&&` या `||` से अलग किया जाता है।

* `A; B` एक कमांड लिस्ट है जिसमें `A` पूरी होने के बाद `B` चलती है।
* `A && B`, जिसमें `B` तभी चलती है जब `A` सफल हो (शून्य स्टेटस के साथ बाहर निकले)।
* `A || B`, जिसमें `B` तभी चलती है जब `A` फेल हो (गैर-शून्य स्टेटस के साथ बाहर निकले)।

कमांड लिस्ट का एग्ज़िट स्टेटस उस अंतिम कमांड का एग्ज़िट स्टेटस होता है जो चली थी।

`&&` और `||` ऑपरेटरों को एक के बाद एक जोड़ा जा सकता है, ताकि अगली कमांड पिछली कमांडों के स्टेटस के आधार पर शर्त के साथ चले।
उदाहरण के लिए

```bash
A && B && C && D || E
```

* B तब चलती है जब A सफल हो,
* C तब चलती है जब A और B सफल हों,
* D तब चलती है जब A, B और C सफल हों,
* E तब चलती है जब A, B, C या D में से **कोई भी** फेल हो।

~~~~exercism/caution
इन लॉजिकल ऑपरेटरों का इस्तेमाल सोच-समझकर कीजिए।
ये जल्दी ही ऐसा कोड बना सकते हैं जिसे पढ़ना मुश्किल हो, या ऐसी लॉजिक जिसे समझना कठिन हो।

उदाहरण के लिए, आपको लग सकता है कि ये दोनों एक जैसे हैं:

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

फर्क यह है: C कब चलती है?

* पहले स्निपेट में (if स्टेटमेंट), C तभी चलेगी जब A फेल हो।
* दूसरे स्निपेट में, C तब चलेगी जब A फेल हो _या जब A सफल हो लेकिन B फेल हो_!
~~~~

### कमांड लिस्ट के उपयोग

यहाँ कुछ उदाहरण हैं जहाँ कमांड लिस्ट कोड को आसान बना सकती हैं।

#### फाइल से लाइनों के ब्लॉक पढ़ना

मान लीजिए आपके पास त्रिभुजों के डेटा वाली एक फाइल है,
और हर त्रिभुज को तीन अलग लाइनों से दर्शाया जाता है, जिनमें उसकी भुजाएँ होती हैं।

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

आप एक `while` लूप इस्तेमाल कर सकते हैं जिसमें शर्त तीन अलग-अलग read कमांड हों:

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

यह मानते हुए कि `is_pythagorean` एक कमांड है जो तय करती है कि तीनों भुजाएँ पाइथागोरस समीकरण को संतुष्ट करती हैं या नहीं, आउटपुट यह होगा:

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### असर्शन

बहुत सी प्रोग्रामिंग भाषाओं में एक तरह का असर्शन होता है, जिसमें कोई शर्त फेल होने पर एक एक्सेप्शन फेंका जाता है

```
assert(user == "Administrator", "wrong user");
```

उस काम की नकल करने के लिए हम Bash में OR ऑपरेटर का इस्तेमाल कर सकते हैं:

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## स्टाइल से जुड़ी बातें

लंबी कमांड लिस्टें बहुत जल्दी पढ़ने में मुश्किल हो जाती हैं।
नई लाइनों का भरपूर इस्तेमाल बहुत मदद कर सकता है।

इस उदाहरण को देखिए, जिसमें दो शर्तें पूरी होने पर एक ऐरे में एक शब्द जोड़ा जाता है।

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

Bash में आप पाइप या लॉजिकल ऑपरेटर के बाद नई लाइन जोड़ सकते हैं।

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

लेकिन लाइन के अंत में ऑपरेटर पर ध्यान न जाना आसान है।
_लाइन कंटीन्यूएशन_ इस्तेमाल करने पर आप ऑपरेटर को शुरू में रख सकते हैं, जिससे यह और साफ पता चलता है कि लिस्ट आगे जारी है:

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
एक _लाइन कंटीन्यूएशन_ दो अक्षरों का क्रम है, "बैकस्लैश" और "नई लाइन" (`\` + `\n`)।
जब Bash उस क्रम को देखता है, तो उसे कोड से बस हटा दिया जाता है, जिससे मौजूदा लाइन अगली लाइन के साथ _जारी_ रहती है।
ध्यान रखिए कि बैकस्लैश और नई लाइन के बीच कोई स्पेस न हो।
~~~~

यहाँ एक और उदाहरण है

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

या

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
