# परिचय

कभी-कभी किसी सीक्वेंस पर चलते समय आपको एलिमेंट के साथ-साथ उसका *स्थान* भी चाहिए होता है। [`sequences`][sequences] में `*-index` परिवार ये दोनों चीज़ें हर एलिमेंट के लिए चलने वाले क्वोटेशन को सौंप देता है। सादे गिने हुए इटरेशन के लिए `times` इसका करीबी साथी है। यह तब काम आता है जब आपको सिर्फ गिनती चाहिए, कोई सीक्वेंस नहीं।

## `each-index` और `map-index`: क्वोटेशन में इंडेक्स

```
each-index ( seq quot: ( elt index -- )       -- )
map-index  ( seq quot: ( elt index -- newelt ) -- newseq )
```

क्वोटेशन को एलिमेंट इंडेक्स के नीचे मिलता है, यानी `index` स्टैक के **सबसे ऊपर** रहता है:

```factor
USING: io kernel math.parser sequences ;

{ "alice" "bob" "carol" } [
    number>string ": " glue print
] each-index
! prints:
! alice: 0
! bob:   1
! carol: 2

{ 10 20 30 } [ + ] map-index .
! => { 10 21 32 }       (index added to each element)
```

`each-index` अपने क्वोटेशन को सिर्फ साइड इफेक्ट के लिए चलाता है और कुछ लौटाता नहीं। `map-index` हर एलिमेंट से मिले नतीजों को इनपुट जैसे ही तरह के नए सीक्वेंस में जमा करता है।

## `times`: गिना हुआ इटरेशन

[`math`][math] में मौजूद `times` अपना क्वोटेशन `n` बार चलाता है।

```
times ( n quot: ( -- ) -- )
```

दिया गया `( -- )` रूप *न्यूनतम* है। चूँकि `times` `inline` है, `( str -- str )` जैसा संतुलित इफेक्ट वाला क्वोटेशन भी ठीक चलता है, और स्टैक हर इटरेशन में आगे बढ़ता रहता है। इससे आपको बिना किसी बदलने योग्य स्थिति के गिनती करने वाला एक्युमुलेटर मिल जाता है:

```factor
USING: kernel sequences ;

"" 3 [ "clop " append ] times .    ! => "clop clop clop "
```

हर इटरेशन में अंदर का कोड चल रही स्ट्रिंग को देखता है, उसमें जोड़ता है, और अगले इटरेशन के लिए नई स्ट्रिंग स्टैक पर छोड़ देता है। यही तरीका `each-index` और `map-index` के लिए भी काम करता है, जब आपको एक्युमुलेटर को आगे तक ले जाना हो।
