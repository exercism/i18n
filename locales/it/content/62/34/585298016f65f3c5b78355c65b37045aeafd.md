# Test

## I file dell'esercizio

Un esercizio scaricato include questi file per compilare e testare la soluzione:

```text
hello-world/
├── HelloWorld.vb       # Your solution
├── HelloWorldTests.vb  # The test suite
├── HelloWorld.vbproj   # Project and build configuration
└── packages.lock.json  # Resolved project dependencies
```

I nomi dei file variano da esercizio a esercizio.
Scrivi la soluzione nel file `.vb` il cui nome non termina con `Tests`.
Il file che termina con `Tests.vb` è la suite di test xUnit: normalmente dovresti modificarlo solo per rimuovere gli argomenti `Skip`.
Di norma non è necessario modificare il file di progetto o il file di lock.

## Eseguire i test

Apri un terminale nella directory dell'esercizio ed esegui:

```bash
dotnet test
```

Il comando ripristina le dipendenze del progetto, compila il progetto ed esegue i suoi test.
Puoi anche usare `dotnet watch test` per rieseguire i test ogni volta che un file sorgente cambia.

## Test saltati

Gli esercizi abilitano inizialmente solo il primo test, permettendoti di risolvere i restanti un passo alla volta.
Apri il file che termina con `Tests.vb` per trovare i test.
Ogni test è una subroutine `Sub` contrassegnata da un attributo `<Fact>` di xUnit.
Un test viene saltato finché il suo attributo `<Fact>` ha un argomento `Skip`:

```vb
<Fact(Skip:="Remove this Skip property to run this test")>
Public Sub Lowercase_words()
    Assert.Equal("ROR", Abbreviate("Ruby on Rails"))
End Sub
```

Per abilitare il test, rimuovi semplicemente l'argomento `Skip`:

```vb
<Fact>
Public Sub Lowercase_words()
    Assert.Equal("ROR", Abbreviate("Ruby on Rails"))
End Sub
```

Dopo che il test appena abilitato passa, ripeti questa procedura con il prossimo test saltato.
Quando tutti i test sono abilitati e superati, hai finito.
