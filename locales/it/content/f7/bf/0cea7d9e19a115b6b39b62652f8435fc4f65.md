# Introduzione

## Tipi personalizzati

I [tipi personalizzati][custom-types] in Elm rappresentano un numero fisso di casi denominati. Ogni valore corrisponde esattamente a uno di questi casi.

Un tipo personalizzato si definisce con la parola chiave `type` e richiede pochissima sintassi. È una delle tecniche più importanti della programmazione in Elm. Serve a far coincidere esattamente i valori possibili nel codice con i valori validi nella realtà: così non c'è spazio per dati non validi e diventa [impossibile rappresentare nel codice stati impossibili][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Ogni caso di un tipo personalizzato può avere dei dati associati, e casi diversi possono avere tipi di dati diversi. Se nessuno dei casi ha dati associati, l'unione discriminata è simile a quella che in altri linguaggi si chiama di solito _enumerazione_ (o _enum_).

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Per creare un valore di un caso specifico puoi riferirti al suo nome (`Spring`) quando il tipo è definito nello stesso modulo, oppure quando è importato con la sintassi `import SeasonModule exposing (Season(..))`. In alternativa puoi usare il nome completo (`Season.Spring`) quando il tipo è importato con la sintassi `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

I tipi personalizzati, come tutto in Elm, hanno l'_uguaglianza strutturale_: due valori dello stesso caso con gli stessi dati (opzionali) sono equivalenti.

Il modo preferito per lavorare con i tipi personalizzati è il [pattern matching][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
