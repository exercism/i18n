# Informazioni

Una funzione è [ricorsiva in coda][recursion-tc] se l'_ultima_ cosa eseguita dalla funzione è una chiamata a se stessa.

Ogni volta che viene chiamata una funzione, un _stack frame_ con le sue variabili locali e i suoi argomenti viene messo in cima allo [stack delle chiamate di funzione][call-stack].
Quando una funzione termina, il suo stack frame viene rimosso dallo stack.

Le funzioni ricorsive in coda consentono l'[ottimizzazione delle chiamate in coda][tail-call-optimization] (o l'eliminazione delle chiamate in coda).
È un'ottimizzazione che permette di riutilizzare l'ultimo stack frame per la successiva chiamata di funzione, quando è garantito che la funzione precedente non ne abbia più bisogno.
Questo attenua il problema del superamento della capacità dello stack delle chiamate di funzione, cioè la situazione in cui ci sono così tanti stack frame sullo stack delle chiamate che non è rimasta memoria per crearne un altro.

## L'ottimizzazione delle chiamate in coda in Elm

In alcune condizioni, il compilatore Elm è in grado di eseguire automaticamente un'ottimizzazione delle chiamate in coda quando compila in JavaScript.

L'ottimizzazione può avvenire per una funzione ricorsiva quando l'_ultima_ operazione di un ramo consiste nel chiamare la funzione stessa in una semplice applicazione di funzione.
Vediamo alcuni esempi:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

L'implementazione qui sopra non è ricorsiva in coda, perché l'ultima operazione del ramo `else` è una moltiplicazione, `n *`.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

L'implementazione qui sopra è ricorsiva in coda e verrà ottimizzata, perché l'ultima operazione del ramo `else` è `factorialHelper` che chiama se stessa.
Questo non sarebbe possibile per una funzione con la firma di tipo `Int -> Int` e, in pratica, l'ottimizzazione delle chiamate in coda si ottiene spesso definendo funzioni ausiliarie.

## Casi limite

In alcuni casi il compilatore non riesce a ottimizzare le funzioni ricorsive. Vediamo alcuni esempi.

Mentre `f x = f (x - 1)` è ricorsiva in coda, `f x = (x - 1) |> f` non lo è, perché l'applicazione di funzione `|>` è l'ultima operazione ed è considerata separata da `f`.
Allo stesso modo, le funzioni che terminano con condizioni booleane, `f x = x > 0 || f (x - 1)`, non sono ricorsive in coda.

La funzione `f x = if f (x - 1) then 1 else 0` non è ricorsiva in coda, perché l'espressione nell'`if` non è considerata un ramo.
Allo stesso modo, nemmeno una chiamata ricorsiva in un'istruzione `case` verrebbe ottimizzata.

La funzione `f x = let y = f (x - 1) in y` non è ricorsiva in coda, perché chiama se stessa in un'istruzione `let`, che non è considerata un ramo.
Tuttavia, in `f x = let g x = g (x - 1) in g x` la funzione `g` è ricorsiva in coda e verrà ottimizzata, anche se è definita in un'istruzione `let`.

La funzione `f x = if x > 0 then f (x + 1) else 1 + f x` verrà ottimizzata solo _parzialmente_: il ramo `then` può essere ottimizzato, ma il ramo `else` no.
L'ottimizzazione parziale è il meglio che si possa ottenere in alcune situazioni, come quando si attraversano strutture ad albero o si definiscono funzioni co-ricorsive.
