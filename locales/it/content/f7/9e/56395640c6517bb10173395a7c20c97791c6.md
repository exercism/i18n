# Workflow

GitHub Actions usa il concetto di _workflow_, cioè script che vengono eseguiti automaticamente ogni volta che si verifica un evento specifico (ad esempio il push di un commit).

Ogni workflow di GitHub Actions è definito in un file `.yml` nella directory `.github/workflows`.
Per informazioni sui workflow, consulta la documentazione seguente:

- [Sintassi dei workflow](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions)
- [Scegliere quando viene eseguito il workflow](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow)
- [Scegliere dove viene eseguito il workflow](https://docs.github.com/en/actions/writing-workflows/choosing-where-your-workflow-runs)
- [Scegliere cosa fa il workflow](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does)
- [Scrivere i workflow](https://docs.github.com/en/actions/writing-workflows)
- [Buone pratiche](/docs/building/github/gha-best-practices)

## Workflow condivisi

Alcuni workflow sono condivisi tra i repository.

```exercism/caution
I workflow condivisi vengono sincronizzati automaticamente (dal [repository org-wide-files](https://github.com/exercism/org-wide-files/)).
Per questo motivo, non modificarne manualmente il contenuto.
```

### Workflow generali

- [Sincronizza le etichette](/docs/building/tracks/ci/workflows/sync-labels): sincronizza le etichette del repository a partire da un file

### Workflow specifici del track

- [configlet](/docs/building/tracks/ci/workflows/configlet): controlla che i file (di configurazione) del track siano strutturati correttamente, sia dal punto di vista sintattico che semantico
- [Nessun file importante modificato](/docs/building/tracks/ci/workflows/no-important-files-changed): commenta le pull request che causerebbero un nuovo test delle soluzioni esistenti
- [Test](/docs/building/tracks/new/setup-continuous-integration#h-test-workflow): verifica gli esercizi del track

### Workflow specifici del tooling

- [Rilascio](/docs/building/tracks/ci/workflows/deploy): rilascia l'immagine Docker del tooling del track su Docker Hub ed ECR

### Workflow opzionali

Ci sono anche alcuni workflow a cui i track possono aderire:

- [Metti in pausa i contributi della community](/docs/building/tracks/ci/workflows/pause-community-contributions): commenta automaticamente le nuove issue e PR create da utenti che non sono membri dell'organizzazione GitHub di Exercism
