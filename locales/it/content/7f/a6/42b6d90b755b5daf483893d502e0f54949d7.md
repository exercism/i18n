# Introduzione ai fondamenti della shell

## Le shell

Una _shell_ è un programma che ti permette di inserire comandi per interagire con il sistema operativo.
Le shell possono essere grafiche; l'ambiente desktop che usi con un mouse o un trackpad è una shell.
Ci concentreremo sulle interfacce a riga di comando, dove digiti i comandi e i risultati vengono (di solito) stampati nel terminale.

Esistono molte shell a riga di comando diverse.
Windows offre **cmd** e **powershell**.
Mac e Linux offrono le «Unix shell», che sono molte.
La shell predefinita su Mac è **zsh**.
**csh** è una shell legacy con una sintassi simile a quella del C.
**bash** è una delle shell più diffuse, soprattutto su Linux.

Una delle prime shell in assoluto è la Bourne shell, **sh**.
Con il tempo, questa shell è stata [standardizzata][posix] per essere fornita su ogni sistema di tipo Unix.
Molte shell si basano sulla Bourne shell e spesso offrono funzionalità interattive o di programmazione aggiuntive.

**Bash** si basa sulla Bourne shell.
Ecco perché si chiama «**B**ourne-**a**gain **sh**ell».
È la shell predefinita su molti sistemi Linux.
Bash offre molte funzionalità che la rendono una shell interattiva piacevole da usare, tra cui:

* un prompt completamente personalizzabile,
* la possibilità di richiamare e modificare i comandi dalla cronologia,
* la possibilità di gestire i processi in esecuzione,
* gli alias che riducono la digitazione,
* e molto altro.

Questo track non riguarda come usare bash come shell interattiva, ma come imparare a scrivere programmi con bash.
L'accento sarà posto sull'uso di _solo_ bash per risolvere i problemi, anche se non ci sono limiti nel richiamare strumenti esterni.

## Fondamenti di bash: comandi e argomenti

Bash legge i comandi dal suo input (che di solito è un terminale o un file).
Ogni riga di input che legge viene trattata come un _comando_, cioè un'istruzione da eseguire.
(Ci sono alcuni casi avanzati, come i comandi che occupano più righe, di cui parleremo più avanti.)

Bash suddivide ogni riga in **parole** delimitate da un carattere di spazio bianco (spazi e tabulazioni).
La prima parola della riga è il nome del _comando_ da eseguire.
Tutte le parole rimanenti diventano _argomenti_ di quel comando (opzioni, nomi di file, ecc.).

~~~~exercism/note
Negli esempi che seguono ti mostreremo alcuni comandi interattivi che puoi eseguire.

* Il carattere `#` avvia un _commento_.
  Tutte le parole che seguono il commento vengono ignorate dalla shell; il commento serve solo a essere letto.
* Il carattere `$` indica il prompt della shell.
  Se stai copiando il comando, non includere il prompt.
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm` è un'applicazione che rimuove i file che le vengono passati.
`*` è un carattere [glob][glob], un modello «wildcard» che corrisponde a tutti i file nella directory corrente.
Parleremo più diffusamente dei glob più avanti.

Hai notato che ci sono diversi spazi tra `a` e `b` e uno solo tra `b` e `c`?
La quantità di spazio bianco tra gli argomenti non ha importanza!
Per esempio:

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo` è un comando che stampa i suoi argomenti sull'output standard (che nel nostro caso è il terminale).
Bash suddivide il comando in cinque parole e chiama il comando `echo` con quattro argomenti.
Gli spazi in più nel secondo esempio non fanno alcuna differenza.
`echo` non sa come erano originariamente gli spazi tra le parole.

Se vogliamo conservare lo spazio bianco in più, dobbiamo passare la frase come un unico argomento.
Possiamo farlo usando le [virgolette][Quotes]:

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

Le virgolette raggruppano tutto ciò che contengono in un _unico argomento_.
L'argomento è `This    is    a    test.`, inclusi quei caratteri di spazio specifici.
Nota che le virgolette non fanno parte dell'argomento: bash le rimuove prima di passare quell'unico argomento a `echo`.

Gli argomenti sono separati dal nome del comando e tra loro da uno spazio bianco.
È importante ricordarlo.
Per esempio, il seguente è sbagliato:

```bash
$ [-f file]
bash: [-f: command not found
```

Questo dovrebbe verificare l'esistenza di un file chiamato `file`.
È ragionevole supporre che lo spazio bianco attorno a `[` e `]` non abbia importanza, ma in realtà `[` è un comando e richiede che il suo ultimo argomento sia `]`.
(Tratteremo il comando `[` più in dettaglio avanti.)
Dobbiamo quindi separare `[` da `-f` e `]` da `file`.
Altrimenti bash penserà che stiamo cercando di eseguire un comando chiamato `[-f` con un unico argomento `file]`.
Il comando corretto separa tutti gli argomenti con uno spazio bianco:

```bash
$ [ -f file ]
```

(Vediamo molte persone che rimangono confuse da questo comportamento: pensano che `[...]` sia «solo sintassi» e che possano omettere gli spazi; `[` è un comando e lo spazio bianco è obbligatorio.)

Se il nome del nostro file contiene spazi bianchi o altri caratteri speciali, anche esso va messo tra virgolette:

```bash
$ [ -f "my file" ]
```

## Tipi di comandi

Bash riconosce diversi tipi di comandi: alias, funzioni, builtin, parole chiave ed eseguibili.
Sono tutti _comandi_ e si comportano tutti in modo molto simile.

Per impostazione predefinita, gli alias sono abilitati solo nelle shell interattive, non negli script di shell.
Non li tratteremo qui.

### Funzioni

Una funzione contiene comandi di shell e si comporta più o meno come un piccolo script; può persino accettare argomenti e creare variabili locali.
Quando una funzione viene chiamata, i comandi al suo interno vengono eseguiti.
Le funzioni saranno trattate in profondità più avanti.

### Builtin

Bash ha alcuni comandi di base integrati, come `cd` (cambia directory), `echo` (scrive l'output) e così via.
Si possono considerare come funzioni già fornite.

### Parole chiave

Le parole chiave sono simili ai builtin, con la differenza principale che sono effettivamente sintassi di bash e possono essere analizzate con regole speciali.
Per esempio, `[` è un builtin di bash, mentre `[[` è una parola chiave di bash; entrambi servono a verificare diverse condizioni.
Ma la parola chiave `[[` ha qualche funzionalità in più.
Per esempio, fornisce l'operatore `=~` che esegue il confronto con espressioni regolari.

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

Gli operatori di confronto tra stringhe `<` e `>` sono un altro esempio di come le parole chiave analizzano il codice in modo diverso.
Dentro `[[...]]`, questi operatori non richiedono alcuna attenzione particolare.

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

Ma dentro `[...]` devi metterli tra virgolette o fare l'escape per impedire alla shell di interpretarli come operatori di reindirizzamento.

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### Eseguibili

L'ultimo tipo di comando che bash può eseguire è un _eseguibile_.
Sono file eseguibili (programmi) presenti nel filesystem del tuo computer che puoi eseguire.
(Gli eseguibili possono anche essere chiamati _comandi esterni_ o _applicazioni_.)
Di solito gli eseguibili si richiamano digitando solo il loro nome; di norma non serve il percorso completo del file.
Questo è possibile perché bash usa una variabile predefinita che lo aiuta a trovare la posizione dei file eseguibili più comuni.
Questa variabile si chiama `PATH`.
È un insieme di nomi di directory separati da due punti (ad es. `/usr/bin:/bin`).
Quando si specifica un comando (ad es. `myprogram` o `ls`) senza un percorso di file (e non è un alias, una funzione, un builtin o una parola chiave), bash cerca nelle directory elencate in `PATH`.
Le directory vengono cercate in ordine, da sinistra a destra, per vedere se contengono un eseguibile con il nome indicato.

Se l'eseguibile si trova fuori da un percorso noto, bisognerà specificare il percorso del file dell'eseguibile.
Per l'eseguibile `myprogram` nella directory corrente, usa `./myprogram`; se si trova nella directory `/opt/somedirectory`, usa `/opt/somedirectory/myprogram`.

Suggerimento: il comando `type` può essere usato per ottenere dettagli su un comando:

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## Script

Uno _script_ è una sequenza di comandi memorizzata in un file.
Bash legge il file ed esegue i comandi in ordine.
Passa al comando successivo solo quando quello corrente è terminato.
L'eccezione è quando un comando è stato specificato per essere eseguito in modo asincrono (in background).
Non preoccuparti troppo di questo caso per ora; vedremo come funziona più avanti.

Qualsiasi esempio di riga di comando in questa guida può essere usato anche in uno script.

Creare uno script è facile.
Inizia creando un nuovo file e scrivi questo sulla prima riga:

```bash
#!/bin/bash
```

Questa riga si chiama _direttiva dell'interprete_ (è anche chiamata _hashbang_ o **_shebang_**).
Specifica che `/bin/bash` deve essere usato come interprete quando il file viene usato come eseguibile in un comando.
Quando il kernel del sistema operativo esegue un _file non binario_, legge la prima riga del file.
Se la riga inizia con `#!`, il kernel usa la riga per determinare l'interprete a cui passare il file.
(Ci sono anche altri modi validi per farlo, vedi sotto.)
Il `#!` deve trovarsi all'inizio assoluto del file, senza spazi né righe vuote prima.
I comandi del nostro script compariranno su righe separate sotto questa.

Suggerimento: invece di `#!/bin/bash`, potresti usare

```bash
#!/usr/bin/env bash
```

`env` cerca in `$PATH` l'eseguibile indicato dal suo primo argomento (in questo caso, «bash»).
Per una spiegazione più dettagliata di questa tecnica e di come differisce dal semplice `#!/bin/bash`, vedi [questa domanda su StackOverflow][env bash].

Non farti ingannare da script o esempi su Internet che usano `/bin/sh` come interprete.
**`sh` non è `bash`!**
Bash stesso è una shell «compatibile con sh», il che significa che può eseguire la maggior parte degli script `sh` e mantiene gran parte della stessa sintassi.
Tuttavia, non è vero il contrario; alcune funzionalità di bash si romperanno o causeranno comportamenti inattesi in `sh`.
In realtà, non esiste un'unica shell `sh`.
Esistono molte implementazioni di shell che supportano la sintassi POSIX-sh.
A seconda del tuo sistema operativo, quando esegui `sh` potresti in realtà eseguire bash, ash, dash o qualche altra shell.

Una volta creato il file dello script, lo si può eseguire così:

```bash
$ bash myscript
```

In questo esempio eseguiamo il _comando_ `bash` e gli diciamo di leggere lo script che gli abbiamo passato come _argomento_.
Quando lo facciamo così, la riga `#!` è solo un _commento_.

In alternativa, possiamo dare ai nostri script i permessi di esecuzione.
Con questo metodo possiamo eseguire lo script come qualsiasi altro eseguibile, invece di chiamare bash manualmente:

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

Quando eseguiamo il comando in questo modo, il sistema operativo (OS) usa la riga `#!` per determinare quale interprete usare per eseguire lo script.
