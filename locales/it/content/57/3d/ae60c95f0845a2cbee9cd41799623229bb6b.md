# Introduzione

Una dichiarazione `GENERIC:` crea una parola il cui comportamento dipende dalla *classe* di uno dei suoi argomenti. Il comportamento concreto arriva dai *metodi*, definiti con `M:`.

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

Quando viene chiamata `area`, Factor ispeziona la cima dello stack, cerca il metodo più specifico la cui classe corrisponde e lo esegue. Con le variabili locali puoi usare `M::`:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

I generici ti permettono di aggiungere in seguito nuove rappresentazioni senza modificare il codice chiamante: `area` funzionava già per `square` e `circle`, e il metodo `rectangle` viene ripreso automaticamente ovunque si chiami `area`.

## Quando un generico è la scelta giusta

Ricorri a `GENERIC:` quando:

- Una singola operazione ha implementazioni *davvero diverse* per input diversi.
- Ti aspetti che codice futuro aggiunga nuovi tipi.
- Vuoi che il sistema dei tipi imponga definizioni specifiche per ogni classe.

Se la variazione è solo una piccola enumerazione di etichette, un `case` è più semplice.

## Unirsi a un mixin con `INSTANCE:`

Un *mixin* è una classe generica *aperta*: chiunque può registrare una nuova classe come membro. Molti dei protocolli integrati di Factor (sequenze, insiemi, stream, …) sono esposti come mixin, così una tupla personalizzata può aderire ai metodi predefiniti del protocollo dichiarandosi un'istanza:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

Dopo `INSTANCE:`, ogni metodo predefinito `M: shape …` si applica automaticamente a `my-shape`, e qualsiasi codice che richieda una `shape` accetta una `my-shape`. `M:` serve ad aggiungere metodi a un generico; `INSTANCE:` serve a unire una classe a un mixin.

## `TYPED::`: input controllati per una parola semplice

`GENERIC:`/`M:` scelgono un metodo in base alla classe di un argomento. A volte non vuoi il dispatch: ti serve solo *una* parola che pretenda che i suoi input siano di una data classe. `TYPED::` (nel vocabolario `typed`) è `::` con una classe scritta dopo il nome di ogni input:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

`n: integer` si legge come le variabili locali che già usi, con la classe scritta dopo i due punti. Non c'è dispatch, una definizione, un comportamento, ma ora ogni argomento viene controllato rispetto alla sua classe: una mancata corrispondenza come `"x" triple` viene rifiutata (*expected input value of type integer but got string*) invece di passare silenziosamente.

Anche l'output può essere annotato allo stesso modo. `yes?` dichiara il tipo sia del suo input sia del suo risultato:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## Funzioni e costanti matematiche

Questo esercizio si appoggia anche ad alcune parole di `math.constants` e `math.functions` che incontrerai qui per la prima volta:

- `pi`: la costante π, da `math.constants`.
- `sin ( x -- y )`, `cos ( x -- y )`: seno e coseno di un angolo in radianti.
- `e^ ( x -- y )`: `e` elevato alla potenza di `x`. (Per una base arbitraria, usa `^`.)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
