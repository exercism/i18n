# Informazioni

Per capire [`Box`][box] è utile capire cosa sono lo [stack e lo heap][stack and heap].

Lo stack è un'area di memoria che funziona come un buffer last-in-first-out (LIFO). Impilare dati sullo stack è molto veloce ed è altrettanto veloce estrarli.
I dati possono includere variabili o indirizzi di funzioni, ma devono avere una dimensione fissa e nota al momento della compilazione.

Se i dati hanno una dimensione sconosciuta al momento della compilazione o una dimensione che può cambiare, allora devono essere allocati sullo heap. Il processo di
allocazione deve trovare nello heap uno spazio abbastanza grande da contenere i dati, scrivere i dati nello heap e impilare sullo stack l'indirizzo di memoria di
quei dati: tutto questo richiede molto più tempo che mettere semplicemente i dati sullo stack. Recuperare dati dallo heap è un po' più lento, perché bisogna
passare per l'indirizzo sullo stack e seguirlo fino alla posizione dei dati nello heap.

`Box` è uno smart pointer che alloca dati sullo heap. L'indirizzo è sullo stack e punta ai dati sullo heap. Una delle [ragioni][reasons] per usare `Box`
è mettere dati sullo heap quando hai un tipo la cui dimensione non può essere nota al momento della compilazione e vuoi usare un valore di quel tipo in un contesto che
richiede una dimensione esatta. Un caso pratico è quando hai più struct che vuoi gestire allo stesso modo tramite un trait che tutte implementano, come
nell'esempio qui sotto.

Diciamo che abbiamo due struct. Ogni struct rappresenta qualcosa che può essere fastidioso. Possiamo far implementare a ciascuna struct un trait Annoyance, così

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

Ora diciamo che vogliamo una funzione che ci restituisca un'Annoyance in base all'ora del giorno che le passiamo. Possiamo provare prima con questo, che scopriamo non compilare

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

Il compilatore, in tutta la sua gentilezza, ci dice esattamente cosa fare: restituire un trait object incapsulato in un `Box`. Se non sai cos'è un trait object,
un modo semplice per descriverlo è come un modo per restituire un oggetto specifico tramite [dispatch dinamico][dynamic dispatch] da una funzione che potrebbe restituire qualsiasi oggetto
che implementa un dato trait. Dato che ci serve il dispatch dinamico, possiamo provare a mettere semplicemente un `dyn` davanti al nome del trait e vedere se la cosa funziona.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

Uno degli errori è che la dimensione di `dyn Annoyance` non può essere nota al momento della compilazione. Questo perché `annoy_me` non sa in anticipo quale specifico trait object
restituirà quando viene chiamata. Le struct che implementano Annoyance potrebbero avere campi diversi ed essere di dimensioni diverse. E ci viene ricordato che
uno degli usi di `Box` è per un tipo la cui dimensione non può essere nota al momento della compilazione. Quindi ora proviamo a usare un valore restituito incapsulato in un `Box`,
e mettiamo in un `Box` i valori restituiti dall'espressione match, così

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

La firma di `Box` è `Box<T>`, dove `T` indica il tipo specifico da incapsulare, che viene messo tra le parentesi angolari, come in `Box<dyn Annoyance>` qui sopra.

Possiamo usare il trait object incapsulato in un `Box` così

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

che stampa

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

Dato che `my_annoyance` è di tipo `Box<dyn Annoyance>`, occorre dereferenziarla dal `Box` usando l'operatore di dereferenziazione `*`. Viene poi riferita come una
`dyn Annoyance` perché la funzione `be_annoying` possa prenderla in prestito.

Un altro modo per implementarlo sarebbe rimuovere il requisito che il parametro abbia una dimensione nota. In quel caso, la compilazione creerebbe una funzione separata
per ogni variante di Annoyance, così da poter fare dispatch statico (un processo chiamato [monomorfizzazione][monomorphization]), così

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

Un altro modo ancora per implementarlo sarebbe far accettare alla funzione `be_annoying` un `Box<dyn Annoyance>` e usare la [coercizione di deref][deref coercion] per evitare
di dover dereferenziare manualmente il `Box`. Questo trasferirebbe la proprietà del trait object Annoyance alla funzione `be_annoying`. Alla fine della funzione
uscirebbe dallo scope e non sarebbe più disponibile.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
