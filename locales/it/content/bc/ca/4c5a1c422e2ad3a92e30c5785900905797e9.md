# Permessi del repo dei maintainer

Un maintainer di una track è un membro del team GitHub della track.
Diventare membro del team di una track è _solo su invito_.

```exercism/note
Se desideri diventare maintainer di una track, apri un topic sul [forum](https://forum.exercism.org/c/exercism/building-exercism/125).
```

## Categoria di manutenzione

Ci sono cinque categorie di manutenzione:

1. `wip-track`
2. `unmaintained`
3. `maintained-solitary`
4. `maintained-autonomous`
5. `maintained`

La categoria di manutenzione di una track è determinata da tre variabili:

1. Se la track è attiva (cioè se gli studenti possono unirsi alla track sul sito)
2. Il numero di maintainer della track
3. Il numero di maintainer della track che fanno anche parte del team GitHub `cross-track-maintainers`

Per determinare la categoria di manutenzione, trova in questa tabella la prima categoria che corrisponde alla track:

| Categoria             | Attiva? | Numero di maintainer  | Numero di maintainer cross-track  |
| --------------------- | ------- | --------------------- | --------------------------------- |
| wip-track             | No      | Qualsiasi             | Qualsiasi                         |
| unmaintained          | Sì      | 0                     | 0                                 |
| maintained-autonomous | Sì      | > 0                   | = Numero di maintainer            |
| maintained-solitary   | Sì      | 1                     | 0                                 |
| maintained            | Sì      | > 1                   | < Numero di maintainer            |

## Permessi del repo

La categoria di manutenzione viene usata per impostare i permessi del o dei repo GitHub della track.

| Categoria             | Richiede una PR | Richiede l'approvazione della PR | Revisioni del team cross-track |
| --------------------- | --------------- | -------------------------------- | ------------------------------ |
| wip-track             | No              | No                               | No                             |
| unmaintained          | Sì              | Sì                               | Sì                             |
| maintained-solitary   | Sì              | Sì                               | Sì                             |
| maintained-autonomous | Sì              | No                               | No                             |
| maintained            | Sì              | No                               | No                             |

```exercism/caution
La categoria `wip-track` è l'unica che consente ai maintainer di fare push su `main`.
```

```exercism/caution
I repo degli strumenti richiederanno _sempre_ l'approvazione della PR, perché i loro contenuti sono protetti tramite un [file CODEOWNERS](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners).
```
