# Informazioni

[Lua](https://lua.org) è un linguaggio di scripting semplice ma potente, efficiente, leggero e incorporabile. È stato progettato, implementato e mantenuto alla [PUC-RIO](https://www.puc-rio.br/) in Brasile dal 1993 dal team di Roberto Ierusalimschy, Waldemar Celes e Luiz Henrique de Figueiredo.

## Commenti

I commenti su una sola riga in Lua iniziano con `--`, mentre quelli su più righe iniziano con `--[[` e terminano con `]]`.
```lua
-- This is a single line comment.

--[[This is
a multiline
comment
]]
```

## Variabili

In Lua ci sono tre tipi di variabili: variabili globali, variabili locali e campi di tabella. Per semplicità, qui spiegheremo solo le variabili locali. Di default tutte le variabili sono globali, quindi dobbiamo dichiarare quelle locali come tali con la parola chiave `local`.
```lua
local x
```

Un valore può essere assegnato a una variabile usando l'operatore `=`.
```lua
local x = 1
```

Lo scope di una variabile `local` è limitato al blocco in cui è dichiarata. Un blocco può essere il corpo di una struttura di controllo, il corpo di una funzione oppure un file o una stringa in cui la variabile è dichiarata.
```lua
local x = 1

if x == 1 then
  local x = 2
  print(x) -- prints 2
end

print(x) -- prints 1
```

## Funzioni

Una funzione si dichiara con la parola chiave `function` e, come le variabili, di default è globale. Una definizione di funzione ha un nome, un elenco di parametri e un corpo. La funzione termina quando si raggiunge la parola chiave `return` e restituisce tutti i valori elencati dopo di essa. Senza un `return` specificato, la funzione restituirà `nil`.

```lua
-- Defining a local function which returns "Hello " followed by 
-- the name which was given as parameter
local function say_hello(name)
  return 'Hello ' .. name
end
```

## Tabelle

Le tabelle sono l'unico meccanismo di strutturazione dei dati in Lua, e sono molto potenti. Si usano per rappresentare array, insiemi, oggetti, moduli e molto altro. In sostanza, una tabella in Lua è un array associativo.
```lua
-- create a table and assign its reference to tbl
local tbl = {}

-- new entry with key 'x' and value 1
tbl['x'] = 1

-- printing the value
print(tbl['x'])  --> 1

-- uninitialized table fields evaluate to nil
print(tbl['y'])  --> nil

-- there is also syntactic sugar - the following is the same as above
tbl.y = 1
print(tbl.y)    --> 1
```

Questa è solo una piccola anticipazione, necessaria per la prossima sezione. Torneremo su questo argomento in dettaglio più avanti.

## Moduli

Un modulo è una raccolta di codice salvata in un file sorgente `.lua`. Tutto ciò che il modulo esporta è memorizzato in una tabella, e questa tabella viene restituita alla fine del file. Quindi la tabella funge sostanzialmente da una sorta di namespace.
```lua
-- say-hello.lua

-- defining the table 'say' which is exported at the end
local say = {}

-- defining the function 'hello' as a table field
-- this is syntax sugar for: say.hello = function() print('Hello!') end
function say.hello()
  print('Hello!')
end

-- returning (exporting) the table 'say'
return say
```

Quel modulo può poi essere caricato in un altro file tramite la funzione `require`, che restituisce la tabella.
```lua
-- lets_say_hello.lua
local say = require('say-hello')
say.hello() -- prints "Hello!"
```

Quando vediamo `say.hello`, penseremmo a «la funzione `hello` del modulo `say`». Ma sapendo che il nostro `say-hello.lua` restituisce una tabella, e rileggendo la sezione sulle tabelle, notiamo che in Lua l'espressione significa «accedere alla tabella `say` usando la stringa `hello` come chiave».

Anche se è buona norma che un modulo restituisca una tabella, è altrettanto possibile restituire qualsiasi altro tipo, come una funzione.

```lua
--- say-bye.lua
local function bye()
  print('Bye!')
end

return bye
```
