# Appendice alle istruzioni

## Personalizzare e sollevare le eccezioni

A volte è necessario sia [personalizzare](https://docs.python.org/3/tutorial/errors.html#user-defined-exceptions) sia [`raise`](https://docs.python.org/3/tutorial/errors.html#raising-exceptions) le eccezioni nel codice. Quando lo fai, dovresti sempre includere un **messaggio di errore significativo** per indicare qual è l'origine dell'errore. Questo rende il codice più leggibile e aiuta notevolmente durante il debug. 

Le eccezioni personalizzate si possono creare tramite nuove classi di eccezione (vedi [`classes`](https://docs.python.org/3/tutorial/classes.html#tut-classes) per maggiori dettagli.) che di solito sono sottoclassi di [`Exception`](https://docs.python.org/3/library/exceptions.html#Exception).

Per le situazioni in cui sai che l'origine dell'errore sarà una derivata di un certo tipo di eccezione, puoi scegliere di ereditare da uno dei [`built in error types`](https://docs.python.org/3/library/exceptions.html#base-classes) sotto la classe _Exception_. Quando sollevi l'errore, dovresti comunque includere un messaggio significativo.

Questo particolare esercizio richiede che tu crei un'_eccezione personalizzata_ da [sollevare](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement)/«lanciare» quando lo stack non è riempito a sufficienza. I test passeranno solo se personalizzi un'eccezione appropriata, fai `raise` di quella eccezione e includi messaggi di errore appropriati.


```python
# subclassing the Exception to create a StackUnderflowError
class StackUnderflowError(Exception):
    """Exception raised when Stack is not full.
       message: explanation of the error.
    """
    def __init__(self, message):
        self.message = message

        
# raising a StackUnderflowError
raise StackUnderflowError("Insufficient number of items in stack")
```

Inoltre, questo esercizio richiede che tu sollevi diverse `built-in exceptions` con messaggi di errore.
Per sollevare una `built-in exception` con un messaggio, scrivi il messaggio come argomento al tipo `exception`:

```python
# an example when division by zero is attempted.
raise ZeroDivisionError("divide by zero")

#an example when the operation is undefined.
raise ValueError("undefined operation")
```
