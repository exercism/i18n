# Tag degli analyzer

I tag degli analyzer servono a identificare _come_ è stata risolta una soluzione.

Questi tag possono poi essere usati per:

- Collegare una soluzione agli approcci
- Collegare una soluzione ai concetti
- Cercare soluzioni con determinati tag

## Formato

Un tag è una stringa formattata così: `<category>:<thing>`.

Supportiamo quattro categorie diverse, dal livello più alto a quello più basso:

| Categoria   | Descrizione                                      | Specificità                                   | Esempi                                |
| ----------- | ------------------------------------------------ | --------------------------------------------- | ------------------------------------- |
| `paradigm`  | Un [paradigma di programmazione][programming-paradigms] | Di altissimo livello, non specifico del track | `imperative`, `functional`            |
| `technique` | Una tecnica utilizzata                           | Di alto livello, per la maggior parte non specifici del track | `recursion`, `immutability`           |
| `construct` | Un costrutto del linguaggio                      | Molti non saranno specifici del track         | `bitwise-and`, `for-loop`             |
| `uses`      | Uso specifico del linguaggio, come tipi o metodi | Di basso livello, specifico del track         | `DateTime.add_seconds`, `IEnumerable` |

Alcuni esempi di tag:

- `paradigm:functional`
- `technique:recursion`
- `construct:bitwise-and`
- `uses:DateTime.add_seconds`

## Tag di uso comune

Sebbene i track siano liberi di taggare le soluzioni come preferiscono, ti consigliamo di provare a usare, quando possibile, la lista di tag di uso comune riportata qui sotto.
Usare un insieme comune di tag ci permetterà di fare cose interessanti, come collegare le soluzioni tra track diversi.
