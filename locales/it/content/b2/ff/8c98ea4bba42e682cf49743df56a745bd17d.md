# Introduzione

In altre parti del percorso abbiamo visto vari tipi di dati con caratteristiche diverse.

- I vettori atomici sono monodimensionali e omogenei per tipo.
- Gli array sono monodimensionali e gli elementi possono essere di tipi eterogenei.
- Matrici e array sono multidimensionali e omogenei.

Questo concetto esaminerà i modi per memorizzare dati multidimensionali ed eterogenei.
In pratica, _la maggior parte_ dei dati del mondo reale è così, quindi adesso arriviamo al cuore di come R viene usato (per lo più) nella pratica.

## Varianti di dataframe

Nel corso dei decenni, R ha aggiunto diversi tipi di dati per gestire i dati tabellari.

Questo percorso si concentrerà principalmente sui tibble, ma è utile conoscere le alternative.

### Il `data.frame`

Nel R base, un `data.frame` è un `list` di `vectors` di uguale lunghezza.
Lo si può immaginare come una tabella rettangolare di dati, in cui ogni colonna è omogenea, ma ogni riga può contenere (e di solito contiene) tipi di dati diversi.

Un esempio per illustrarlo:

```R
# create the column vectors
languages <- c("Fortran", "R", "Python", "Julia")
created <- c(1957, 1993, 1991, 2012)
has.syllabus <- c(FALSE, TRUE, TRUE, TRUE)

# join columns to create the dataframe
df <- data.frame(languages, created, has.syllabus)
df
#>   languages created has.syllabus
#> 1   Fortran    1957        FALSE
#> 2         R    1993         TRUE
#> 3    Python    1991         TRUE
#> 4     Julia    2012         TRUE
 ```

 Abbiamo una colonna di stringhe di caratteri, una colonna di numeri e una colonna di valori booleani.
 Su scala più ampia, questo è un modo intuitivo per rappresentare molte raccolte di dati del mondo reale.

### Il `tibble`

Il design del `data.frame` è _vecchio_.

L'esperienza di più decenni, insieme ai cambiamenti nel modo in cui si usa R, ha portato a una riprogettazione: nel Tidyverse è nata un'alternativa modernizzata, i tibble.

Rispetto al R base, i tibble hanno:

- Valori predefiniti diversi, per ridurre i problemi più comuni.
- Minore tendenza a forzare la conversione dei tipi di dati in fase di input.
- Messaggi di errore più numerosi e più chiari.
- Formati di visualizzazione diversi, di solito migliori.

In breve, un `tibble` punta a «_fare meno e lamentarsi di più_», descritto anche come «_pigro e scontroso_».

I due tipi sono di solito intercambiabili: qualsiasi funzione che accetta un `data.frame` accetterà anche un `tibble`, e _viceversa_.

Le conversioni tra i due tipi sono semplici, con `as_tibble(df)` e `as.data.frame(tbl)`.

Per il codice nuovo, usare i tibble ti aiuterà probabilmente a scrivere codice più robusto.
Tuttavia, nel mondo di R il codice e i dati ereditati sono molto abbondanti, quindi è probabile che il `data.frame` resti comune ancora a lungo.

```R
# column vectors are same as for data.frame
library(tibble)
tbl <- tibble(languages, created, has.syllabus)
tbl
  # A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 R            1993 TRUE        
#> 3 Python       1991 TRUE        
#> 4 Julia        2012 TRUE      
```

Nota il formato di stampa predefinito: la riga di commento con le dimensioni viene stampata automaticamente e vengono mostrati anche i tipi delle colonne.

## Lavorare con i tibble

I tibble sono una parte fondamentale del Tidyverse: aggiungili con `library(tibble)` o con `library(tidyverse)`.

### Creare un tibble

Nel modo più semplice, possiamo usare la funzione `tibble()` per unire vettori colonna, come per `data.frame()`.
Un esempio è stato mostrato in una sezione precedente.

Se è più comodo inserire i valori riga per riga, la funzione corrispondente è `tribble()`.

In pratica esistono decine di modi per creare tibble, perché sono il formato di output predefinito di numerose funzioni del Tidyverse.

## Manipolare un tibble

Il concetto di programmazione funzionale ha presentato la libreria `purrr` per manipolare vettori e array (strutture di dati monodimensionali).

Per i dataframe (tradizionali o tibble), la libreria da usare è `dplyr`.

### Sottoinsiemi

I dataframe, compresi i tibble, possono essere trattati come array di vettori colonna, quindi indicizzandoli come array si recupera una colonna specifica.

```R
tbl
# A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 R            1993 TRUE        
#> 3 Python       1991 TRUE        
#> 4 Julia        2012 TRUE    

tbl$created
#> [1] 1957 1993 1991 2012
```

Un dataframe può anche essere indicizzato con l'indicizzazione in stile matrice.

```R
tbl[c(2, 4), 1:2]
  # A tibble: 2 × 2
#>   languages created
#>   <chr>       <dbl>
#> 1 R            1993
#> 2 Julia        2012
```

Nel R moderno con l'ecosistema Tidyverse, le funzioni di `dplyr` sono in genere più flessibili e comode, e saranno al centro del resto di questo concetto.

### Operazioni per colonna

Ottieni una singola colonna con `pull()`, indicando il nome o il numero progressivo (i numeri negativi contano da destra verso sinistra).

```R
tbl |> pull(created)
#> [1] 1957 1993 1991 2012
```

È lo stesso risultato di `tbl$created`, ma usando una funzione adatta alle pipeline.

Per ottenere più colonne, la funzione adatta è `select()`, molto versatile.
Ottieni (o escludi) colonne in base alle proprietà del loro nome o del loro tipo.

```R
# Range with position and/or name
tbl |> select(1:created)
  # A tibble: 4 × 2
#>   languages created
#>   <chr>       <dbl>
#> 1 Fortran      1957
#> 2 R            1993
#> 3 Python       1991
#> 4 Julia        2012      

# Use type of column
tbl |> select(where(is.numeric))
  # A tibble: 4 × 1
#>   created
#>     <dbl>
#> 1    1957
#> 2    1993
#> 3    1991
#> 4    2012
```

Si possono usare più criteri, con gli operatori booleani `&`, `|` e `!` (and, or, not).

Tutta questa potenza sembra piuttosto ridicola con il nostro dataframe di esempio sui linguaggi.
Per fortuna, il tibble `starwars` è incluso in `dplyr` e ci offre qualcosa di più grande su cui esercitarci.

```R
# pick a subset of columns
starwars |> 
  select(name | ends_with("color")) |> 
  head(5)
  # A tibble: 5 × 4
#>   name           hair_color skin_color  eye_color
#>   <chr>          <chr>      <chr>       <chr>    
#> 1 Luke Skywalker blond      fair        blue     
#> 2 C-3PO          NA         gold        yellow   
#> 3 R2-D2          NA         white, blue red      
#> 4 Darth Vader    none       white       yellow   
#> 5 Leia Organa    brown      light       brown    
```

### Operazioni per riga

Ottieni le righe che soddisfano un criterio con `filter()`, oppure escludile con `filter_out()`.

```R
starwars |> 
  select(name:mass) |> 
  filter(between(height, 150, 165) & !is.na(mass))
  # A tibble: 4 × 3
#>   name               height  mass
#>   <chr>               <int> <dbl>
#> 1 Leia Organa           150    49
#> 2 Beru Whitesun Lars    165    75
#> 3 Nien Nunb             160    68
#> 4 Ben Quadinaros        163    65
```

I criteri di filtro possono essere complessi quanto si vuole, ma si basano sempre sul _contenuto_ delle righe.

Se conosciamo i _numeri_ delle righe, possiamo usare le varie funzioni `slice()`.

```R
starwars |> 
  select(name | homeworld) |> 
  slice(20:25)
  # A tibble: 6 × 2
#>   name             homeworld
#>   <chr>            <chr>    
#> 1 Palpatine        Naboo    
#> 2 Boba Fett        Kamino   
#> 3 IG-88            NA       
#> 4 Bossk            Trandosha
#> 5 Lando Calrissian Socorro  
#> 6 Lobot            Bespin   
```

## Modificare un tibble

Prima avvertenza: il comportamento predefinito di _copy-on-modify_ significa che il tibble originale di solito resta invariato.

La maggior parte delle modifiche si applica per colonna.

I nomi delle colonne si possono cambiare con `rename(newname = oldname)`, oppure con `rename_with()` per applicare una funzione.
Nota la sintassi dentro `rename()`.
Il _contenuto_ della colonna `oldname` viene _associato_ al nome `newname`: da qui l'ordine.

L'ordine delle colonne si può cambiare con `relocate()`.
Per impostazione predefinita, le colonne specificate vengono spostate nelle posizioni più a sinistra, ma si possono usare gli argomenti `.before` o `.after` per un posizionamento più preciso.

```R
sw <- starwars |> select(name:species) |> slice(1:4)
sw
  # A tibble: 4 × 11
#>   name           height  mass hair_color skin_color  eye_color birth_year sex   gender    homeworld species
#>   <chr>           <int> <dbl> <chr>      <chr>       <chr>          <dbl> <chr> <chr>     <chr>     <chr>  
#> 1 Luke Skywalker    172    77 blond      fair        blue            19   male  masculine Tatooine  Human  
#> 2 C-3PO             167    75 NA         gold        yellow         112   none  masculine Tatooine  Droid  
#> 3 R2-D2              96    32 NA         white, blue red             33   none  masculine Naboo     Droid  
#> 4 Darth Vader       202   136 none       white       yellow          41.9 male  masculine Tatooine  Human  

sw |> relocate(c(species, homeworld), .after = name)
  # A tibble: 4 × 11
#>   name           species homeworld height  mass hair_color skin_color  eye_color birth_year sex   gender   
#>   <chr>          <chr>   <chr>      <int> <dbl> <chr>      <chr>       <chr>          <dbl> <chr> <chr>    
#> 1 Luke Skywalker Human   Tatooine     172    77 blond      fair        blue            19   male  masculine
#> 2 C-3PO          Droid   Tatooine     167    75 NA         gold        yellow         112   none  masculine
#> 3 R2-D2          Droid   Naboo         96    32 NA         white, blue red             33   none  masculine
#> 4 Darth Vader    Human   Tatooine     202   136 none       white       yellow          41.9 male  masculine
```

Per modifiche più grandi, `mutate()` ti permette di:

- Creare nuove colonne che sono funzioni di colonne esistenti.
- Sostituire una colonna esistente, creando una nuova colonna con lo stesso nome.
- Eliminare una colonna, impostando il suo valore a `NULL`.

Chiaramente `mutate()` è potente, potenzialmente confuso, e un motivo per essere molto grati al copy-on-modify.

Non c'è un motivo evidente per interessarsi all'indice di massa corporea dei personaggi di Star Wars, ma non si sa mai:

```R
starwars |> 
  select(c(name, species, height, mass)) |> 
  mutate(BMI = mass / (height / 100)^2) |> 
  head(4)
  # A tibble: 4 × 5
#>   name           species height  mass   BMI
#>   <chr>          <chr>    <int> <dbl> <dbl>
#> 1 Luke Skywalker Human      172    77  26.0
#> 2 C-3PO          Droid      167    75  26.9
#> 3 R2-D2          Droid       96    32  34.7
#> 4 Darth Vader    Human      202   136  33.3
```

Le **operazioni per riga** sono meno comuni quando si modifica un singolo tibble (l'unione di più tibble sarà trattata in un concetto successivo).

Un'eccezione: `arrange()` ordina le righe in base ai valori di una o più colonne.

```R
tbl
#>       A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 R            1993 TRUE        
#> 3 Python       1991 TRUE        
#> 4 Julia        2012 TRUE  

tbl |> arrange(languages)
#>       A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 Julia        2012 TRUE        
#> 3 Python       1991 TRUE        
#> 4 R            1993 TRUE     
```
