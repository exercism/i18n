# Introduzione

## Le let assertion

Quando facciamo pattern matching su un valore in Gleam, dobbiamo assicurarci che i pattern coprano ogni possibile valore del tipo, altrimenti il codice non verrà compilato.

Questa funzione dovrebbe essere rifiutata, perché non ha gestito il caso in cui la lista è vuota:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Nella maggior parte dei programmi Gleam vogliamo gestire ogni caso possibile, ma in alcuni programmi, come i prototipi e gli script rapidi, potremmo voler concentrarci solo sul percorso principale e non scrivere codice per gli altri casi. È qui che entra in gioco `let assert` di Gleam.

Con le let assertion un pattern può corrispondere solo ad alcuni dei possibili valori di un tipo e, se il pattern non corrisponde a nessun valore, il programma andrà in crash. Usando `let assert` possiamo scrivere la funzione qui sopra così:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Le librerie Gleam non dovrebbero mai usare le let assertion, perché possono mandare in crash il programma. Dovrebbero invece usare il tipo `Result` e lasciare che lo sviluppatore dell'applicazione decida come gestire gli errori.
