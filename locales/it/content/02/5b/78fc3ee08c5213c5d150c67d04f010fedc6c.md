# Suggerimenti
`Option` si usa per indicare un calcolo che potrebbe non avere un risultato utile
(per esempio a causa di un errore o di un input non valido).
Se non conosci `Option`, puoi leggere [questo tutorial](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html).
`Option` è una cosiddetta [Monad](https://en.wikipedia.org/wiki/Monad_(functional_programming)) che copre un «aspetto computazionale», in questo caso la possibile assenza di un valore.
Un uso corretto delle Monad può portare a un codice molto conciso ma elegante
e leggibile. Un uso scorretto può facilmente portare all'opposto.
Guarda [questo video](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) per saperne di più.
## Insidie comuni da evitare
Ci sono alcune regole pratiche per `Option`:
1. Se non ti serve, non usarlo. Invece di
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
meglio avere
```scala
def add1(x: Int): Int = x + 1
```
(esiste `Option.map` per applicare funzioni così semplici,
quindi non devi appesantirle con `Option`).
2. Non fare «unwrap» se non ne hai davvero bisogno.
Spesso ci sono funzioni integrate che fanno al caso tuo. Indicatori di un unwrap prematuro
sono `isDefined/isEmpty` o il pattern matching. Invece di
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
meglio avere
```scala
x map (_ + 1) getOrElse 0
```
3. Le Monad si possono usare dentro una for-comprehension, ottimo.
Questo è consigliabile quando vuoi «comporre» più istanze di `Option`. Invece di
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
meglio avere
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
