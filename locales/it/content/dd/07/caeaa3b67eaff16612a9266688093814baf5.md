# Informazioni

## Introduzione

I generici sono una funzionalità del linguaggio che permette di riutilizzare il codice.
Per esempio, non dovrebbe importare quale tipo contenga un array per calcolarne la lunghezza.
Ecco perché la funzione `length` usa un parametro di tipo generico `a` nella sua firma di tipo.

```elm
length : List a -> Int
```

## Parametri nei tipi

Quando un tipo è generico rispetto a un altro tipo, usiamo un nome minuscolo per quest'altro tipo e lo chiamiamo parametro di tipo.
Esempi comuni sono i tipi personalizzati `List`, `Maybe` e `Result`.

```elm
-- Maybe is generic over the type a
type Maybe a
    = Nothing
    | Just a

someString : Maybe String
someString = Just "hello"

someInt : Maybe Int
someInt = Just 42
```

Un'osservazione importante sui nomi dei parametri di tipo è che possono essere lunghi più di un carattere.
L'unico vincolo è che devono essere nomi minuscoli.
Per questo, quando è utile, tendiamo a dare loro nomi descrittivi.

Un tipo può essere generico rispetto a più tipi e quindi avere più parametri di tipo.
In questo caso, ogni tipo indipendente riceve un nome minuscolo diverso.
Il fatto di essere indipendenti non impedisce che diventino lo stesso tipo: permette solo che siano diversi.

```elm
-- Result is generic over the types error and value
type Result error value
    = Ok value
    | Err error
```

Gli alias di tipo dei record possono avere parametri di tipo, anche se è meno comune.

```elm
-- Event is generic over the type a
type alias Event a =
    { at : Time
    , data : a 
    }
```

> Ecco perché il pacchetto `Html` definisce il tipo `Html msg`, con un parametro di tipo chiamato `msg`.
> L'architettura di Elm ti guida verso la creazione di un tipo personalizzato `Msg` che descrive tutti i messaggi che la pagina web può generare.
> Di conseguenza, il codice costruirà viste di tipo `Html Msg`, dove `Msg` è il tipo concreto che hai definito.
> I principianti a volte fanno confusione tra gli errori che menzionano `Html msg` (minuscolo) e quelli con `Html Msg`.
> Adesso lo sai!
> La differenza è che il primo è generico rispetto a qualsiasi tipo `msg`, mentre il secondo è specifico per il tipo `Msg` che hai definito.

## Parametri di tipo nelle funzioni

Dato che i tipi possono essere generici, lo possono essere anche le funzioni.
Si possono scrivere funzioni che gestiscono tipi generici, come `Maybe.withDefault`.

```elm
withDefault : a -> Maybe a -> a
withDefault default maybe =
    case maybe of
      Just value -> value
      Nothing -> default
```

Le funzioni che prendono altre funzioni come parametri si chiamano funzioni di ordine superiore, e anche queste possono essere generiche.

```elm
map : (a -> b) -> Maybe a -> Maybe b
map function maybe =
  case maybe of
    Just value ->
      Just (function value)

    Nothing ->
      Nothing
```

I parametri di tipo possono comparire sia negli input sia nell'output di una funzione, e la genericità resa possibile dai parametri di tipo è di solito chiamata **polimorfismo parametrico**.
Questo è in contrasto con il polimorfismo ad hoc, noto anche come overloading delle funzioni, in cui lo stesso nome di funzione può essere usato su più implementazioni in cui i tipi differiscono.
È anche in contrasto con il polimorfismo di sottotipo, in cui i tipi possono essere definiti in una gerarchia e le funzioni definite su un tipo possono essere chiamate anche con argomenti dei suoi sottotipi.
In Elm, l'unico meccanismo di genericità disponibile è il polimorfismo parametrico.
