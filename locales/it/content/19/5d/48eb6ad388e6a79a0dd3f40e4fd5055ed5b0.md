# Introduzione

## Riferimenti null

Se hai mai usato un altro linguaggio di programmazione (C/C++, Python, Java, Ruby, Lisp, ecc.), è probabile che tu abbia già incontrato `null` o `nil`.
Questi linguaggi usano `null` o `nil` per indicare che una determinata variabile non ha alcun valore.
Tuttavia, questo rende l'uso accidentale di una variabile `null` un errore facile (e frequente) da commettere.
Come puoi immaginare, provare a chiamare una funzione che non c'è, o ad accedere a un valore che non esiste, può portare a ogni sorta di bug e crash.
Il creatore di `null` è arrivato persino a definirlo il suo [«errore da un miliardo di dollari»][billion-dollar-mistake].

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## Il tipo `Option`

Per evitare questi problemi, le variabili di Cairo possono usare l'enum `Option` per rappresentare in modo sicuro l'assenza di un valore.
Questo enum ha due varianti: `None`, l'equivalente di null in Cairo; e `Some(T)`, dove `T` è un valore di qualsiasi tipo.

Si presenta così:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

Puoi pensare a `Option` come a uno strato di sicurezza tra te e i problemi che i riferimenti null possono causare, pur conservando la loro utilità concettuale.

## Come usare `Option`

Impostare una variabile a `None` è piuttosto semplice:

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

Tuttavia, se vuoi che il tipo `Option` contenga un valore, non puoi assegnare questo valore direttamente.
Una variabile di tipo `Option` e, per esempio, una variabile di tipo `i32` non sono equivalenti.
Devi usare `Some`:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

Per lo stesso motivo, il codice seguente non funzionerà:

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

Per ottenere il valore contenuto in `Some`, devi prima verificare che esista:

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

Cairo ha altri strumenti oltre a `match` per verificare e accedere ai valori contenuti in `Option`, ma ormai `match` dovrebbe esserti familiare.

Considera questo come una dimostrazione del perché Cairo usa `Option` invece di un riferimento null.
Il punto è che **devi _assolutamente_ verificare** se la variabile `Option` è `Some` (nel qual caso puoi procedere a estrarre e usare il valore che contiene), oppure `None`.
Altrimenti il programma non verrà compilato; il compilatore ti tiene al sicuro da `null`.
