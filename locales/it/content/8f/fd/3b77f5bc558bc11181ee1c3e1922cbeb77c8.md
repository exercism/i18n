# Introduzione

Le eccezioni in Ruby, come in molti linguaggi, offrono un modo per gestire eventi imprevisti. Una corretta gestione delle eccezioni è importante quando si cerca di evitare che il programma vada in crash.

Quando viene sollevata un'eccezione, o perché la sollevi esplicitamente o perché la solleva l'interprete Ruby, il programma interrompe il normale funzionamento e alla fine termina con un messaggio di errore:

```ruby
raise ArgumentError.new("Something went wrong!")
=> Traceback (most recent call last):
.
.
ArgumentError (Something went wrong!)
```

```ruby
1/0
=> Traceback (most recent call last):
.
.
ZeroDivisionError (divided by 0)
```

Se vogliamo impedire questo arresto, dobbiamo reagire all'eccezione. Questa operazione si chiama «recupero» di un'eccezione:

```ruby
begin
  # ...any code that raises an exception
rescue
  puts 'Got an exception'
end
```

Questo programma non andrà in crash e produrrà come output «Got an exception». Anziché uscire, Ruby esegue il codice nel blocco rescue, che stampa un messaggio.

Come ogni cosa in Ruby, anche le eccezioni sono oggetti e di solito contengono dati sull'eccezione. Ecco come possiamo ottenere l'oggetto eccezione:

```ruby
begin
  # ...any code that raises an exception
rescue => e
  puts "Exception class: #{ e.class.name }"
  puts "Exception Message:#{e.message}"
end
```

In Ruby è anche possibile sollevare le proprie eccezioni. Per esempio:

```ruby
begin
  raise ArgumentError.new("Invalid argument")
rescue ArgumentError => e
  puts e.message
end
```

L'eccezione precedente è una delle eccezioni integrate di Ruby, ma è anche possibile definire eccezioni personalizzate e sollevarle:

```ruby
class CustomError < StandardError
end

raise CustomError.new("Something went wrong")
```
