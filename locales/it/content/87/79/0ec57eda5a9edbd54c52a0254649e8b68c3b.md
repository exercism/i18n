# Appendice alle istruzioni

## Pro e contro di `from_quote`
Questo esercizio definisce una funzione `from_quote` nel tipo `Time`. Così è possibile scrivere codice come questo:

```roc
time : Time
time = "00:01:23"
```

Questo codice chiama implicitamente `Time.from_quote("00:01:23")` in fase di compilazione. La cosa può potenzialmente velocizzare il programma, perché non deve gestire il parsing a runtime, e garantisce che i tempi rifiutati da `from_quote` vengano intercettati in fase di compilazione anziché a runtime. Inoltre, rende il codice bello e leggibile. Per esempio, ecco uno dei test di questo esercizio:

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

Tuttavia, chi legge questo codice potrebbe pensare che la funzione `advance_time` accetti una `Str`, quando in realtà accetta un `Time`. Questo può portare a confusione ed errori. Per questo motivo, potresti preferire il formato un po' più lungo ma più esplicito: `"00:00:05".Time`, che chiama anch'esso `from_quote` in fase di compilazione.

Nei tuoi programmi, potresti invece preferire l'uso di `from_str`:

```roc
Time := { ... }.{
    from_str : time_str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

Puoi anche chiamare `from_str` (o qualsiasi altra funzione pura) in fase di compilazione, così:

```roc
Ok(time) = Time.from_str("00:01:23")
```

Nota: collocare questa definizione al livello più alto la fa eseguire in fase di compilazione (dato che la funzione è pura e il suo input è noto in fase di compilazione). All'interno di una funzione, puoi usare `from_str` a runtime.
