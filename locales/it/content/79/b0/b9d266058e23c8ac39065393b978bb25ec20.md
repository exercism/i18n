# Informazioni

La memoria dinamica è implementata da funzioni di libreria che il programmatore usa per allocare e deallocare memoria durante l'esecuzione.
Dato che è il programmatore a controllare l'allocazione e la deallocazione della memoria, la memoria dinamica è sicura solo nella misura in cui il programmatore è immune dall'errore umano.
Per questo motivo, la memoria dinamica è una delle principali fonti di bug di programmazione e uno dei principali bersagli degli attacchi informatici.

La memoria dinamica si usa per variabili la cui dimensione è nota solo durante l'esecuzione.
È comunemente utile per gli array il cui numero di elementi può variare da un'esecuzione all'altra.
Gli array a lunghezza variabile (VLA) sono un altro modo per gestire array la cui dimensione degli elementi è nota solo durante l'esecuzione.
Un VLA usa la memoria automatica, il che significa che la sua memoria viene distrutta all'uscita dal blocco in cui è definito.
(Per saperne di più sulla memoria, consulta il concetto [specificatori di classe di memorizzazione](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers).)
I VLA sono stati introdotti nel linguaggio C con C99, ma a partire da C11 sono opzionali, quindi i compilatori che supportano C11 e versioni successive non sono obbligati a supportarli.
Un'analisi dettagliata degli array a lunghezza variabile esula dallo scope di questo articolo.

## malloc

`malloc` è una funzione dichiarata in `stdlib.h` che si usa per allocare memoria dinamica.
Se l'allocazione riesce, viene restituito un puntatore che punta all'indirizzo del primo byte della memoria allocata.
Se l'allocazione non riesce, viene restituito `NULL`.
È prudente controllare che il risultato di `malloc` non sia `NULL` e gestire con garbo l'eventuale fallimento.
Il puntatore restituito è di tipo `pointer-to-void`, che si può considerare all'incirca come un puntatore «generico» convertibile nel tipo specifico usato dalla memoria.
`malloc` ha un parametro, cioè la dimensione in byte della memoria desiderata.
La dimensione totale per allocare un array è la dimensione del tipo di dato di ogni elemento moltiplicata per il numero di elementi.
L'operatore `sizeof` si usa comunemente per ottenere la dimensione del tipo di dato di ogni elemento.
L'esempio seguente lo dimostra

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

È importante ricordare che la memoria appena allocata da `malloc` non è inizializzata e può contenere valori spazzatura.
Nota che `sizeof` del puntatore `numbers` non è il numero di elementi dell'array, né la quantità totale di memoria allocata.
La dimensione del puntatore restituito da `malloc` è la dimensione di qualsiasi puntatore su quel particolare sistema.
Il codice di esempio è stato eseguito su un sistema a 64 bit, quindi la dimensione del puntatore era 8 byte (moltiplicata per 8 bit per byte = 64 bit).
Il tipo del puntatore è stato convertito implicitamente da pointer-to-void a pointer-to-int.
Se il pointer-to-int punti a un singolo `int` o a un array di `ints` è qualcosa che il programmatore può gestire come ritiene opportuno.
Per esempio

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

Se i valori verranno sicuramente scritti prima di essere letti, usare `malloc` può essere un modo efficiente di allocare memoria.
Ma se c'è la possibilità che i valori vengano letti prima di essere inizializzati, usare `malloc` è rischioso.
Un modo più sicuro di allocare memoria è usare `calloc`, che inizializza a zero la memoria appena allocata.

Nota negli esempi precedenti che è stato usato `free(numbers)`.

## free

`free` è una funzione dichiarata in `stdlib.h` che si usa per deallocare memoria allocata dinamicamente.
La memoria allocata dinamicamente resta occupata finché non viene rilasciata da `free`.
Alcuni sistemi operativi possono liberare automaticamente la memoria allocata dinamicamente quando il programma termina, ma è buona norma non farci affidamento.
`free` ha un parametro, cioè un puntatore alla memoria che è stata allocata dinamicamente.
L'uso o il mancato uso di `free` è associato a diversi problemi di memoria.

#### Perdita di memoria

Non liberare la memoria allocata dinamicamente dopo che il riferimento a quella memoria ha raggiunto la fine del suo ciclo di vita, o è stato altrimenti distrutto, è detto perdita di memoria.
La memoria persa è memoria che il sistema occupa ma che non è più accessibile al programma.
Può essere un problema particolare se la memoria viene allocata in un ciclo, non liberata alla fine del ciclo e allocata di nuovo all'inizio del ciclo.
Se viene allocata abbastanza memoria senza liberarla, la chiamata per allocare memoria fallirà perché la memoria rimanente non è sufficiente.
È importante ricordare che, sebbene la memoria allocata dinamicamente resti occupata dal sistema finché non viene liberata, il puntatore a cui è assegnata può avere solo lo scope di blocco.
Per esempio, negli esempi con `malloc`, la memoria viene allocata in `my_function`.
Quella memoria andrebbe persa se il puntatore ad essa non venisse restituito e usato per impostare il puntatore `numbers` in `main`.
Quindi, passare quel puntatore `numbers` a `free` rilascia la memoria allocata in `my_function`.

#### Uso dopo la liberazione (**UAF**)

Se si accede alla memoria dopo che è stata liberata, i valori potrebbero essere qualsiasi cosa.
Nell'esempio seguente, la memoria puntata da `numbers` viene liberata e poi letta in `printf`.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

Il puntatore `numbers`, dopo essere stato liberato, è detto dangling pointer.
Un dangling pointer può riferirsi a memoria diversa da quella a cui era destinato.
Quindi, un dangling pointer può portare a corruzione dei dati e a sostituzione ed esecuzione arbitraria di codice.
Un puntatore a memoria allocata che non è stata azzerata impostandolo a `NULL` può essere usato per violare il programma.
Nell'esempio precedente, se `numbers` fosse stato impostato a `NULL` così: `numbers = NULL;` dopo essere stato liberato, il `printf` successivo comporterebbe la terminazione del programma, segnalando forse un segmentation fault nel tentativo di leggere `numbers[0]`.

#### Doppia liberazione

Se `free` viene chiamata due volte su un puntatore a memoria allocata dinamicamente, si ottiene un comportamento indefinito (**UB**).
Ciò significa che il compilatore può gestirlo arbitrariamente come vuole.
L'esempio seguente, compilato con due compilatori diversi, può avere due esiti diversi

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

Il primo e il secondo compilatore non hanno generato errori durante l'esecuzione quando `numbers` è stato impostato a `NULL` tra una chiamata e l'altra a `free`, ma non è detto che funzioni con un terzo compilatore.
Una causa comune di doppia liberazione è avere due puntatori che puntano alla stessa memoria allocata dinamicamente.
Un puntatore può puntare all'inizio di un array in un punto del programma, mentre l'altro può essere usato per scorrere l'array in un altro punto del programma.
In punti diversi del programma, ciascun puntatore viene liberato, causando così una doppia liberazione.

## calloc

`calloc` è una funzione dichiarata in `stdlib.h` che si usa sia per allocare memoria dinamica sia per inizializzare a zero la memoria appena allocata.
Se l'allocazione riesce, viene restituito un puntatore che punta all'indirizzo del primo byte della memoria allocata.
Se l'allocazione non riesce, viene restituito `NULL`.
È prudente controllare che il risultato di `calloc` non sia `NULL` e gestire con garbo l'eventuale fallimento.
Il puntatore restituito è di tipo `pointer-to-void`, che si può considerare all'incirca come un puntatore «generico» convertibile nel tipo specifico usato dalla memoria.
`calloc` ha due parametri.
Il primo parametro indica quanti elementi del tipo di dato specificato devono essere allocati.
Il secondo parametro indica la dimensione del tipo di dato specificato da allocare.

Nell'esempio seguente tutte le istruzioni `printf` dovrebbero sempre mostrare `0`, dato che `calloc` garantisce di azzerare i valori appena allocati.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` è una funzione dichiarata in `stdlib.h` che si usa per espandere o ridurre memoria già allocata.
Se la riallocazione riesce, viene restituito un puntatore che punta all'indirizzo del primo byte della memoria riallocata.
Se la riallocazione non riesce, viene restituito `NULL`.
È prudente controllare che il risultato di `realloc` non sia `NULL` e gestire con garbo l'eventuale fallimento.
`realloc` ha due parametri.
Il primo parametro è un puntatore alla memoria esistente da riallocare.
Il secondo parametro indica la dimensione in byte della memoria riallocata.
I valori impostati prima che la memoria venga espansa vengono conservati.
È importante ricordare che la memoria aggiunta quando si espande la memoria non è inizializzata a zero e i suoi valori potrebbero essere qualsiasi cosa.
Inoltre, la memoria rimossa quando si riduce la memoria non è inizializzata e potrebbe conservare i valori.
L'esempio seguente mostra come espandere e ridurre un array

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## Quando la dimensione passata è 0

Se la dimensione passata a `malloc`, `calloc` o `relloac` è `0`, quello che succede dipende da come il compilatore la implementa.
Un compilatore può restituire un puntatore `NULL` oppure un puntatore non nullo.
Per esempio, se si alloca memoria per un puntatore a `char`, il compilatore può restituire `NULL` oppure un puntatore non nullo a una stringa vuota.
Per evitare risultati diversi con compilatori diversi, è meglio non allocare con una dimensione pari a 0.
