# Introduzione

Hai già *usato* gli stream in `channel-chatter` e li hai smaltiti in `boatswains-bilge`. Questo esercizio è il primo stream personalizzato che scriverai: una classe che implementa il [protocollo][stream-protocol], così lo stesso codice `with-input-stream` / `read1` / `stream-read1` che funzionava su un `<string-reader>` funziona anche su quello che scrivi.

## I mixin: l'altra metà della gerarchia delle classi

Conosci già `TUPLE: child < parent …` da `dragons-descendants`: una gerarchia a genitore singolo in cui gli slot scendono verso il basso. Factor ha un *secondo* modo per estendere il grafo delle classi: i **mixin aperti**. Un `MIXIN: m` dichiara una classe senza slot a cui altre classi possono unirsi in un secondo momento con `INSTANCE: c m`. L'appartenenza è molti-a-molti: una classe può essere istanza di quanti mixin vuole.

Il protocollo degli stream usa due mixin per indicare quale metà dell'interfaccia implementa una classe:

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

Uno stream può essere l'uno, l'altro o entrambi. I metodi generici su `input-stream` (o `output-stream`) vanno poi in dispatch verso qualunque classe che abbia aderito al mixin: è così che le funzioni ambientali come `read1`, `stream-contents`, `with-input-stream` e così via trovano la strada verso la classe che scrivi.

I mixin sono *aperti*: puoi aggiungere un nuovo membro dopo che il mixin è stato dichiarato, anche in un vocabolario diverso. È qui il contrasto con `TUPLE: < parent`, dove la relazione è fissata nel momento in cui si dichiara la classe figlia.

## I generici del protocollo

I generici del protocollo vivono in `io`:

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

`stream-read1` restituisce il byte successivo (o `f` alla fine dello stream); `stream-write1` ne scrive uno. `stream-read-unsafe` è la lettura in blocco di livello più basso che la maggior parte degli stream di input fornisce; `stream-read` è costruita sopra di essa e gestisce l'allocazione. `stream-element-type` dice se lo stream tratta byte (`+byte+`) o caratteri (`+character+`); quando avvolgi un altro stream, l'implementazione più semplice delega semplicemente a quello sottostante.

## La pulizia arriva da `destructors`

Gli stream sono disposable: uno stream personalizzato estende `disposable` e implementa `dispose*`. È il framework di `boatswains-bilge`, applicato a una classe di stream:

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

Una volta che tutto questo è a posto, tutti i combinatori `with-…` di `channel-chatter` funzionano automaticamente sul tuo stream.
