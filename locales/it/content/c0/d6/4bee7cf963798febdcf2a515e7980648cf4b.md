# Introduzione

L'assembly scritto a mano è pieno di ripetizioni.
La stessa breve sequenza di istruzioni compare ancora e ancora, con poche variazioni, e ci sono poche astrazioni per ridurre il codice ripetitivo.
Non solo: programmare in assembly richiede di gestire valori senza una semantica ovvia.
Non ci sono parametri con un nome e la maggior parte dei dettagli della macchina sottostante deve essere gestita manualmente da chi programma.

NASM, l'assemblatore usato dal percorso, offre alcuni strumenti che possono aiutare chi programma con entrambi i problemi.
Questi strumenti vengono eseguiti al _momento dell'assemblaggio_, prima che qualsiasi istruzione raggiunga il processore.
Guidano l'assemblatore su come riscrivere il testo sorgente prima ancora che venga tradotto in codice macchina.

Lo strumento più importante tra questi sono le **macro**, che si possono immaginare come una ricetta per l'assemblatore.
Vengono espanse nel punto in cui sono usate, come se il codice fosse stato scritto lì a mano.

Le macro possono accettare un certo numero di token letterali come parametri, il che le rende riutilizzabili in contesti diversi.
Tuttavia, non sono funzioni: non c'è `call`, non c'è `ret`, nessun trasferimento di controllo verso un altro punto del codice.

## Macro a riga singola

La definizione più semplice dà un nome a un valore o a una breve espressione con `%define`:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Ogni occorrenza successiva di `WIDTH` viene sostituita da `8` prima dell'assemblaggio.
La sostituzione è testuale, quindi il nome viene rimpiazzato ovunque compaia, sia in un operando sia dentro un'altra definizione.

~~~~exercism/note
Per le _costanti_ numeriche, preferisci `equ` a `%define`.

Una macro a riga singola dichiarata con `%define` viene espansa solo quando è usata, e può essere riassegnata o annullata.
Una costante `equ`, invece, viene valutata nel punto in cui è definita e non viene mai modificata.
~~~~

Un `%define` può anche accettare parametri _con un nome_, comportandosi come una piccola funzione inline:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Racchiudi tra parentesi sia l'intero corpo sia ogni parametro.
Con `%define square(x) x*x`, la chiamata `square(1+1)` si espande in `1+1*1+1`, che è `3`.
Scritta come `%define square(x) ((x)*(x))`, la stessa chiamata si espande in `((1+1)*(1+1))`, che è `4`.
~~~~

I nomi definiti con `%define` distinguono maiuscole e minuscole.
La variante `%idefine` rende il nome insensibile alle maiuscole e minuscole, se lo si desidera.

Le macro a riga singola sono utili per dare un significato a varie parti del codice.
Se usate con attenzione, migliorano la leggibilità e riducono la possibilità di errori di battitura.
Per esempio, un registro che ha uno scopo dedicato all'interno di una funzione può essere definito in base al suo scopo:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Macro su più righe

Un'intera sequenza di codice, con un numero qualsiasi di righe, viene racchiusa con `%macro` e chiusa da `%endmacro`.
Un numero dopo il nome indica quanti argomenti accetta la macro, e può essere zero.
Quando vengono passati degli argomenti, sono separati da una virgola (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Gli argomenti nelle macro su più righe non hanno un nome.
Ci si riferisce a essi come `%1`, `%2` e così via, nell'ordine in cui vengono passati:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Nota che gli argomenti devono essere una sintassi valida per le operazioni eseguite nel corpo della macro.
Qui `mult_two eax, ecx` e `mult_two r8, r9` si assemblano entrambi, ma `mult_two eax, cl` no, dato che `imul eax, cl` non è definito.

### Etichette all'interno di una macro

Una macro che definisce un'etichetta ordinaria si rompe nel momento in cui viene usata due volte, perché anche l'etichetta verrebbe definita due volte.
Per usare etichette all'interno di una macro che può essere chiamata più di una volta, bisogna anteporre a tali etichette `%%`.
Questo indica all'assemblatore di dare a questa etichetta un nome diverso e unico a ogni espansione:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Ripetere al momento dell'assemblaggio

È possibile ripetere un blocco di codice di una riga usando `times`.
Questo è particolarmente utile quando si dichiarano valori ripetuti in memoria:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Per ripetere codice su più righe, possiamo usare invece `%rep`:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Nota che il numero di ripetizioni è specificato subito dopo `%rep` e c'è un `%endrep` per chiudere il blocco ripetuto.

È comune usare un contatore al momento dell'assemblaggio dentro un blocco `%rep`, proprio come un ciclo a tempo di esecuzione usa un contatore.
Mentre una costante intera al momento dell'assemblaggio può essere dichiarata con `equ`, per le _variabili_ intere al momento dell'assemblaggio usiamo invece `%assign`.
A differenza di `%define`, `%assign` viene valutato immediatamente come numero e può essere riassegnato:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Dopo che il preprocessore è stato eseguito, il ciclo è scomparso e restano quattro istruzioni `add`, con gli immediati `0`, `1`, `2` e `3` incorporati.
Questo è lo srotolamento del ciclo fatto dall'assemblatore: nessun registro contatore e nessun salto, solo codice lineare.

## Assemblaggio condizionale

Il preprocessore ha a disposizione varie condizioni.
Selezionano tra diversi percorsi, espandendo il proprio corpo sul posto, ma solo quando la loro condizione è vera.

`%if` ... `%elif` ... `%else` ... `%endif` selezionano un ramo da un test numerico:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## Suddividere in file

Le macro sono spesso tenute in un file a parte e richiamate in ogni sorgente che ne ha bisogno con `%include`:

```x86asm
%include "patterns.mac"
```

Il file indicato viene inserito alla lettera in quel punto, prima dell'assemblaggio, esattamente come se il suo contenuto fosse stato digitato lì.
Questo tiene le definizioni in un unico posto e permette a più file sorgente di condividerle.

Se il file di macro può essere assemblato da solo, dovrebbe avere l'estensione `.asm`.
Nota che le macro non hanno collegamento.
Anche se il file di macro viene assemblato, le sue macro sono visibili solo a un altro file che lo `%include`.

Altrimenti, un file destinato solo a `%include` può avere qualsiasi estensione.
L'uso di `.asm` o `.mac` è una convenzione comune.
