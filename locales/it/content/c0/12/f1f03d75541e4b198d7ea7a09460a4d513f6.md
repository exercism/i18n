# Informazioni

`<dlist>` (in [`dlists`][dlists]) costruisce una nuova lista doppiamente collegata. Le operazioni si trovano in [`deques`][deques] e usano il dispatch del [protocollo deque][deque-protocol], così anche altri contenitori, principalmente `<dlist>`, possono implementarle.

| parola          | effetto                             |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`: deque nuovo e vuoto |
| `push-front`    | `( elt deque -- )`: aggiunge in testa |
| `push-back`     | `( elt deque -- )`: aggiunge in coda |
| `pop-front`     | `( deque -- elt )`: rimuove dalla testa |
| `pop-back`      | `( deque -- elt )`: rimuove dalla coda |
| `peek-front`    | `( deque -- elt )`: legge la testa senza rimuoverla |
| `peek-back`     | `( deque -- elt )`: legge la coda senza rimuoverla |
| `deque-empty?`  | `( deque -- ? )`: il deque è vuoto? |
| `dlist-length`  | `( dlist -- n )`: numero di elementi |

Tutte le operazioni di push e di pop modificano il deque sul posto: passare un deque a una routine e poi leggerlo di nuovo è il pattern normale.

## Pila e coda

Due schemi convenzionali di dispatch:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

Un vector con `push` e `pop` (da `mutation`) è la scelta giusta quando ti serve solo l'ordine LIFO: `<dlist>` porta con sé l'overhead di una lista collegata. Ricorri a `<dlist>` quando ti serve O(1) a *entrambe* le estremità, quasi sempre per una coda FIFO.

## Lo schema BFS

La ricerca in ampiezza è l'uso canonico di una coda FIFO:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

Il deque trasporta la frontiera della ricerca, mentre l'hash-set si occupa della deduplicazione. Scambia `pop-front` con `pop-back` e la stessa struttura diventa una ricerca in profondità.

## Memorizzazione automatica con `MEMO:`

A volte l'accesso per nodo che la BFS esegue è costoso. Factor fornisce [`MEMO:`][memo-decl], un sostituto di `:` che memorizza automaticamente il risultato della parola in base ai suoi input:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

Una parola `MEMO:` esegue il proprio corpo la prima volta che vede ciascun input e in seguito restituisce il risultato memorizzato nella cache. La cache vive per tutta la durata dell'immagine; non esiste alcuna eliminazione basata sul tempo o sulla dimensione. Usalo per le funzioni pure i cui input provengono da un insieme finito e gestibile.
