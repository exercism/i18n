# Informazioni

Per capire i riferimenti è necessario capire la proprietà. Ogni valore ha un solo proprietario. Quando si esce dal suo scope, il valore viene rilasciato.
Per esempio:

```rust
fn log(msg: String) { // msg takes ownership of the value passed to it
    let formatted_datetime = String::new();
    // code  to format current datetime snipped
    println!("{msg} at {formatted_datetime}");
} // msg is dropped here

pub fn main() {
    let my_string = "Something happened".to_string();
    log(my_string); // passing my_string transfers ownership of its value to msg
    //println!("{my_string:?}"); // uncommenting this line will error because my_string's value has been dropped while owned by msg
}
```

Un [riferimento][borrow] rappresenta un _prestito_ di un valore posseduto. Invece di trasferire la proprietà di `my_string`, possiamo far sì che `log` lo prenda in prestito e poi lo restituisca a `my_string` in `main` alla fine di `log`.

Per farlo, definiamo `msg` come riferimento anteponendo una e commerciale. Il tipo `&String` si legge «riferimento a una `String`».

Dato che ora l'argomento di `log` è un riferimento, dobbiamo passare un riferimento. Per ottenere un riferimento a `my_string`, anteponi una e commerciale, che è l'[operatore di prestito](https://doc.rust-lang.org/reference/expressions/operator-expr.html#borrow-operators). Questo presta `my_string` a `log` per tutta la durata di quella funzione.

```rust
fn log(msg: &String) { //msg is defined as a reference with an ampersand
    let formatted_datetime: String;
    // code  to format current datetime snipped
    println!("{msg} at {formatted_datetime}");
}

pub fn main() {
    let my_string = "Something happened".to_string();
    log(&my_string); // my_string is passed as a reference with an ampersand
    println!("{my_string:?}");
}
```

## I riferimenti sono immutabili per impostazione predefinita

In qualsiasi momento un valore può avere più riferimenti, purché siano tutti immutabili, come mostrato qui sotto

```rust
fn main() {
    let fibonacci = vec![1, 1, 2, 3, 5, 8, 13];
    // fibonacci is simultaneously passed by reference three times, which is okay because they are all immutable references
    println!(
        "{:#?}",
        check_shapes(&fibonacci[..=1], &fibonacci[1..=3], &fibonacci[2..],)
    );
}

fn check_shapes(constant: &[u8], linear: &[u8], superlinear: &[u8]) -> (bool, bool, bool) {
    (
        is_constant(constant),
        is_linear(linear),
        is_superlinear(superlinear),
    )
}

// understanding the implementations of the following functions is not necessary for this example
// but are provided should you be interested

fn is_constant(slice: &[u8]) -> bool {
    slice
        .first()
        .map(|first| slice.iter().all(|v| v == first))
        .unwrap_or_default()
}

fn is_linear(slice: &[u8]) -> bool {
    let diffs: Vec<_> = slice
        .windows(2)
        .map(|window| window[1] - window[0])
        .collect();
    is_constant(&diffs)
}

fn is_superlinear(slice: &[u8]) -> bool {
    let diffs: Vec<_> = slice
        .windows(2)
        .map(|window| window[1] - window[0])
        .collect();
    diffs.windows(2).all(|window| window[1] > window[0])
}
```

## I riferimenti possono essere dereferenziati

A volte un riferimento deve essere dereferenziato per accedere al suo valore.

```rust
fn is_meaning_of_life(value: &u8) -> bool {
  value == 42
}
// oops! compiler error: `==` operator is not defined for `&u8`, `u8`
```

Per accedere al valore, si antepone al riferimento l'operatore di dereferenziazione (`*`), come mostrato qui sotto

```rust
fn is_meaning_of_life(value: &u8) -> bool {
  *value == 42 // okay, the reference is dereferenced from `&u8` to `u8` which `==` can compare with another `u8`
}
```

## I riferimenti possono essere mutabili

I riferimenti possono essere resi mutabili aggiungendo `mut` alla e commerciale, come mostrato qui sotto

```rust
fn add_five(counter: &mut i32) { //counter is defined as a mutable reference
    *counter += 5; // counter is dereferenced to access its value
}

pub fn main() {
    let mut my_count = 0; // my_count must be defined as mutable
    println!("{my_count:?}");
    add_five(&mut my_count); // my_count is passed as a mutable reference
    println!("{my_count:?}");
}
```

Stampa
`0`
`5`

In qualsiasi momento un valore può avere o un solo riferimento mutabile o un numero qualsiasi di riferimenti immutabili, come mostrato qui sotto

```rust
fn add_five(counter: &mut i32) {
    *counter += 5;
}

pub fn main() {
    let mut my_count = 0;
    println!("{my_count:?}");
    let mut my_count2 = &mut my_count; // first mutable reference to my_count
    add_five(&mut my_count); // this errors because my_count's mutable borrow by my_count2 will be used on the next line
    add_five(my_count2);
    println!("{my_count:?}");
}
```

Questo funziona perché il compilatore sa che i prestiti mutabili non si sovrappongono

```rust
fn add_five(counter: &mut i32) {
    *counter += 5;
}

pub fn main() {
    let mut my_count = 0;
    println!("{my_count:?}");
    let mut my_count2 = &mut my_count; // first mutable reference to my_count
    add_five(my_count2); // my_count2's borrow of my_count is not used afer this point
    add_five(&mut my_count); // compiler allows second mutable borrow of my_count
    println!("{my_count:?}"); // because it does not conflict with first mutable borrow
}
```

Stampa
`0`
`10`
