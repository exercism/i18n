# Informazioni

## Applicazione parziale

In Elm tutte le funzioni sono [curried][currying], il che significa che se chiami una funzione senza passare tutti gli argomenti, ottieni in cambio una nuova funzione.

Il risultato di questa operazione si chiama [applicazione parziale][partial-application] (non stai passando tutti gli argomenti alla funzione, ma ne stai applicando solo alcuni).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

L'applicazione parziale applica sempre gli argomenti nell'ordine in cui sono dichiarati.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## Operatore pipe (`|>`)

Scrivere `x |> f` è esattamente la stessa cosa di `f x`. Un esempio concreto: `"5" |> String.toInt` equivale a `String.toInt "5"`.

A prima vista non sembra molto utile, ma si chiama [operatore pipe][pipe-operator] perché ti permette di scrivere codice «a pipeline».

Per esempio, supponiamo di avere una funzione sanitize che trasforma l'input dell'utente in numeri interi:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Possiamo riscriverla così:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

In questo modo si evitano le parentesi e si vedono le funzioni nell'ordine in cui vengono applicate (prima `String.trim`, poi `String.toInt`), il che aiuta la leggibilità.

C'è anche un [operatore pipe inverso `(<|)`][reverse-pipe-operator].
Scrivere `x <| f` è esattamente la stessa cosa di `f x`.
Anche questo a prima vista non sembra molto utile e di certo non è usato quanto l'operatore pipe, ma in alcune situazioni aiuta a evitare le parentesi.

## Composizione di funzioni / stile point free

L'operatore [`(>>)`][forward-composition] ha il tipo `(a -> b) -> (b -> c) -> (a -> c)` e crea una funzione di tipo `a -> c` componendo due funzioni compatibili, di tipo `a -> b ` e `b -> c`.
Lo fa prendendo l'output (di tipo `b`) dalla prima funzione e usandolo come primo argomento della seconda funzione (che deve essere dello stesso tipo `b`).
La funzione creata prenderà lo stesso input (di tipo `a`) della prima funzione e restituirà qualunque `c` restituisca la seconda funzione.

Un esempio concreto è `String.trim >> String.toInt`.
`String.trim` prende una stringa come unico parametro, quindi è questo che prende la funzione creata.
`String.toInt` restituisce un `Maybe Int`, quindi è questo che restituisce la funzione creata.
`String.trim` restituisce una `String`, che `String.toInt` accetta come parametro, quindi l'esempio compila.

Ora possiamo riscrivere la funzione `sanitize` in questo modo:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Nota che non usiamo più il parametro `input` che vedi nell'esempio originale, anche se la funzionalità è identica.
Questo modo di creare funzioni che non fanno riferimento ai loro parametri si chiama «Point Free Style».
Il vantaggio di questo stile è che il codice è più conciso, lo svantaggio è che può essere più difficile da capire, soprattutto per chi comincia.

Vale la pena ricordare che in Elm tutte le funzioni sono curried, quindi `String.length >> max` compila e dà come risultato quanto segue:

- Una funzione (1) che ha un parametro di tipo stringa (l'input di `String.length`)
- `max` è una funzione che ha due parametri `Int`, ma la funzione 1 le passa un solo `Int` (il valore restituito da `String.length`), quindi `max` è applicata parzialmente.
- Il valore restituito dalla funzione `max` applicata parzialmente è un'altra funzione (2) che prende un `Int` e restituisce il maggiore tra questo `Int` e l'`Int` applicato parzialmente da `String.length`
- Quindi la funzione 1 (`String -> Int`) restituisce la funzione 2 (`Int -> Int`)
- Quindi `((String.length >> max) "123") 2` restituisce `3`, perché `"123"` ha lunghezza 3, che è maggiore del 2 passato come argomento `Int`.

## Progettazione delle funzioni

Per scrivere facilmente codice elegante in Elm, conviene mettere la struttura dati principale come ultimo parametro delle funzioni.
Tutte le funzioni comuni della libreria standard lo fanno, come `List.map` (la cui firma di tipo è qui sotto).

```elm
map : (a -> b) -> List a -> List b
```

Qui vediamo che l'ultimo parametro della funzione `map` è `List a` e che restituisce `List b`, quindi la struttura dati principale (`List`) è l'ultimo parametro.

Questo permette di scrivere codice elegante «a pipeline», come qui sotto.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Inoltre rende comodo usare la composizione di funzioni e lo stile point free come alternativa alla pipeline.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

La composizione di funzioni permette anche di ridurre questo esempio a una sola chiamata a `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
