# Approfondimento

## Gli errori in `jq`

`jq` segnala due grandi categorie di errori:

1. **Errori in fase di compilazione**: il programma stesso non è valido, cioè errori di sintassi, riferimenti a funzioni o variabili non definite e così via.
   `jq` si rifiuta di eseguire del tutto il programma.

   ```sh
   $ jq -n '1 + $foo + 2'
   jq: error: $foo is not defined at <top-level>, line 1, column 5:
       1 + $foo + 2
           ^^^^
   jq: 1 compile error
   ```

2. **Errori in fase di esecuzione**: il programma è valido, ma qualcosa va storto mentre elabora un valore, ad esempio indicizzare un numero con una stringa, analizzare un testo JSON non valido con `fromjson`, chiamare una funzione con argomenti del tipo sbagliato e così via.

   ```sh
   $ echo '42' | jq '.foo'
   jq: error (at <stdin>:1): Cannot index number with "foo"
   ```

Questo concetto riguarda gli **errori in fase di esecuzione**: come sollevarli, come intercettarli e come fermarli.

Un errore in fase di esecuzione non intercettato fa sì che `jq` stampi un messaggio su _standard error_ e termini con stato `5`.

## Sollevare errori: `error` e `error(message)`

Il filtro [`error`][man-error] solleva un errore.

- `error` solleva un errore il cui valore è il valore di **input**.
- `error(message)` solleva un errore il cui valore è il risultato di `message`.

```jq
"bad input" | try error catch .
# => "bad input"

42 | try error("invalid value: \(.)") catch .
# => "invalid value: 42"
```

~~~~exercism/note
Il valore dell'errore può essere _qualsiasi_ valore JSON, non solo una stringa.
Sollevare errori strutturati permette a un gestore `catch` di prendere decisioni in base al contenuto dell'errore.

```jq
try error({kind: "range", msg: "age must be non-negative"})
catch (if type == "object" then "\(.kind) error: \(.msg)" else "unexpected: \(.)" end)
# => "range error: age must be non-negative"
```
~~~~

Se un valore di errore che non è una stringa non viene intercettato, `jq` lo stampa come JSON, contrassegnato con `(not a string)`.

```sh
$ jq -n 'error({code: 42, msg: "boom"})'
jq: error (at <unknown>) (not a string): {"code":42,"msg":"boom"}
```

## Intercettare errori: `try` e `catch`

Gli errori si possono intercettare con [`try EXP catch HANDLER`][man-try-catch].
Viene eseguita la prima espressione; se solleva un errore, viene eseguita l'espressione `HANDLER` **con il valore dell'errore come suo input**.
L'output del gestore viene emesso come se fosse stato l'output dell'espressione provata.

```jq
true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]

true | try error("some exception") catch .
# => "some exception"
```

La forma più breve `try EXP` equivale a `try EXP catch empty`: l'errore viene scartato e non viene prodotto alcun output.

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

~~~~exercism/note
Un errore **interrompe il resto del flusso** all'interno del `try`.
I valori già prodotti vengono mantenuti, ma nulla di ciò che segue l'errore viene valutato.

```jq
jq -n 'try (1, error("x"), 3) catch "caught: \(.)"'
# outputs:
# 1
# "caught: x"
# (3 is never produced)
```
~~~~

Un gestore può sollevare un nuovo errore, oppure rilanciare quello originale con un semplice `error`: dato che il valore dell'errore è l'input del gestore, in questo modo viene propagato invariato.

```jq
try repeat(f) catch
  if . == "break" then empty else error end
```

## Sopprimere gli errori: l'operatore `?`

L'[operatore `?`][man-question-mark], usato come `EXP?`, è una scorciatoia per `try EXP`.
Trasforma un'espressione che fallisce in un'espressione che semplicemente non produce alcun output.

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]

true | [.a?]
# => []
```

Lo si vede spesso attaccato agli operatori di indicizzazione:

- `.foo?` equivale a `.["foo"]?`
- `.[]?` itera solo se l'input è un array o un oggetto, altrimenti è vuoto

~~~~exercism/caution
`?` sopprime **ogni** errore, compresi quelli che non avevi previsto.
`user.name?` non produce nulla, in silenzio, quando `user` non è un oggetto: così puoi nascondere problemi nei dati o errori di battitura nel programma.
Preferisci `try ... catch` quando hai bisogno di sapere _che_ qualcosa è fallito, oppure convalida l'input in modo esplicito.
~~~~

## L'operatore alternativo `//`

A volte chi programma si aspetta che `a // b` produca `b` quando `a` fallisce.
Era vero nelle vecchie versioni di `jq`, ma non da `jq` 1.6 in poi.
L'operatore `//` non sopprime gli errori.
Sostituisce `b` solo quando `a` non produce alcun valore, oppure produce `false` o `null`; gli errori in `a` vengono comunque propagati.

```sh
$ jq -n '(error("x")) // 42'
jq: error (at <unknown>): x
```

Se vuoi un valore di riserva per gli errori, usa `try a catch b`.

## L'operatore alternativo di destrutturazione `?//`

L'[operatore `?//`][man-question-mark-slash-slash] combina la destrutturazione con la gestione degli errori.
Prova a turno ogni modello di assegnazione finché uno riesce, e le variabili assegnate dalle alternative che falliscono vengono impostate a `null`.

```jq
# input:
#   [
#     {"a": 1, "b": 2, "c": {"d": 3, "e": 4}},
#     {"a": 5, "b": 6, "c": [{"d": 7, "e": 8}]}
#   ]

.[] as {$a, $b, c: {$d, $e}} ?// {$a, $b, c: [{$d, $e}]}
| {$a, $b, $d, $e}

# outputs:
# {"a": 1, "b": 2, "d": 3, "e": 4}    # first element: c is an object, first pattern matched
# {"a": 5, "b": 6, "d": 7, "e": 8}    # second element: c is an array, second pattern matched
```

Qui il primo modello si aspetta che `c` sia un _oggetto_ con le chiavi `d` ed `e`, mentre il secondo si aspetta che `c` sia un _array_ che contiene un oggetto di quel tipo.
Il primo elemento di input si lega al primo modello; il secondo elemento fa fallire quel modello, quindi si prova il secondo.

Così un unico programma può destrutturare input che possono assumere una fra diverse forme, senza scrivere catene esplicite di `if type == ...`.

## Fermare il programma: `halt` e `halt_error`

A volte la risposta giusta a un errore è smettere del tutto di elaborare.

- [`halt`][man-halt] ferma immediatamente il programma `jq` senza ulteriore output. Lo stato di uscita è `0`.
- [`halt_error`][man-halt-error] ferma il programma, stampa il suo **input** su _standard error_ come testo grezzo (senza decorazioni, nemmeno un carattere di nuova riga) ed esce con lo stato indicato, che per impostazione predefinita è `5`.

```sh
$ echo '"Error: something went wrong"' | jq 'halt_error(1)'
Error: something went wrong    # printed on stderr, exit status 1
```

Tieni presente che questi filtri fermano il programma immediatamente, anche se restano altri input da leggere.

### Stati di uscita

Per riferimento, `jq` usa questi stati di uscita:

| Stato | Significato                                          |
| :----: | ------------------------------------------------ |
| `0`    | successo                                          |
| `2`    | errore d'uso (opzioni della riga di comando non valide)           |
| `3`    | errore di compilazione                                    |
| `5`    | errore in fase di esecuzione (oppure `halt_error` senza argomento) |

Con l'opzione `--exit-status` / `-e`, lo stato riflette invece l'ultimo valore di output: `0` per `true` o per i numeri, `1` per `false` o `null`, `4` quando non c'è alcun output.

## Strumenti di debug

Quando cerchi di capire da dove viene un errore, questi filtri possono aiutarti:

- [`debug`][man-debug] lascia passare il suo input invariato, ma stampa `["DEBUG:", <input>]` su standard error.
  Anche `debug(msgs)` stampa `msgs` come messaggi di debug.
- [`stderr`][man-stderr] stampa il suo input, grezzo e compatto, su standard error.
- [`input_line_number`][man-input-line-number] produce in output il numero di riga dell'input che si sta filtrando in quel momento: prezioso quando un file contiene molti testi JSON e uno di essi è difettoso.
- [`$__loc__`][man-loc] produce in output un oggetto con le chiavi `file` e `line` che descrive dove compare nel programma, così puoi incorporarlo nei messaggi di errore.

```jq
def checked_div($d):
  if $d == 0
  then error("\($__loc__): division by zero")
  else . / $d end;

try (10 | checked_div(0)) catch .
# => "{\"file\":\"<top-level>\",\"line\":3}: division by zero"
```
