# Introduzione

Il più delle volte Factor gestisce l'iterazione tramite combinatori come
`each`, `map` e `count`. A volte, però, il modo più pulito per
esprimere un calcolo è la **ricorsione**: una parola che chiama se stessa.

## Definire una parola ricorsiva

Una definizione `:` può chiamare se stessa direttamente:

```factor
: count-down ( n -- )
    dup 0 = [ drop ] [ dup . 1 - count-down ] if ;

5 count-down
! prints 5 4 3 2 1
```

## Ramificazione: vuoto o non vuoto

`if-empty` (in [`sequences`][sequences]) è il caso base naturale della
ricorsione:

```
if-empty ( seq emptyquot nonemptyquot -- )
```

```factor
{ 4 0 9 } [ "empty" ] [ "got data" ] if-empty .
! => "got data"
```

`emptyquot` viene eseguito con la sequenza (vuota) già consumata;
`nonemptyquot` viene eseguito con la sequenza ancora sullo stack.

## `cond`: una catena di rami condizionati

Quando la ricorsione ha più di due casi, `cond` (in
[`combinators`][combinators]) mantiene il codice leggibile:

```factor
: classify ( n -- label )
    {
        { [ dup 0 < ] [ drop "negative" ] }
        { [ dup 0 = ] [ drop "zero"     ] }
        [ drop "positive" ]
    } cond ;
```

## Riferimenti in avanti con `DEFER:`

Una definizione `:` può chiamare se stessa direttamente, ma quando due
parole si chiamano *a vicenda* il parser vede la prima prima che la
seconda esista. `DEFER:` riserva un nome in modo che la prima definizione
possa essere compilata:

```factor
DEFER: even?

: odd? ( n -- ? ) dup 0 = [ drop f ] [ 1 - even? ] if ;
: even? ( n -- ? ) dup 0 = [ drop t ] [ 1 - odd? ] if ;
```

`DEFER:` è utile anche quando una parola ausiliaria si legge più
naturalmente *dopo* la parola che la usa.
