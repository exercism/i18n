# I trait

Un trait specifica un insieme di metodi che un tipo può implementare.
I trait sono utili per definire metodi che devono essere condivisi tra tipi diversi.
Quando i trait vengono usati con tipi generici, i metodi definiti possono essere chiamati su un tipo particolare, ma è anche possibile chiamarli su altri tipi di dato.
In modo astratto, con l'uso dei _vincoli di trait_, possiamo specificare che il tipo generico deve condividere un certo comportamento.

> **Nota:** i trait condividono caratteristiche simili a quelle che in altri linguaggi di programmazione vengono chiamate interfacce, pur presentando alcune differenze.

## Definizione di un trait

Definire un trait aiuta a individuare la firma della funzione che costituirà l'insieme di comportamenti che un tipo può implementare per ottenere un risultato.
Questi metodi costituiscono il comportamento di un tipo.
Se possiamo chiamare gli stessi metodi su tipi diversi, significa che i tipi coinvolti hanno lo stesso comportamento.

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

In base alla definizione del trait `Summary` qui sopra, il metodo `summarize` è un comportamento che può essere chiamato solo dal tipo struct `NewsArticle`.
Se viene chiamato su istanze di altri tipi, genera un errore di compilazione.
Dichiarare il trait con la parola chiave `pub` espone il trait di questo crate agli altri crate che intendono usarlo.
Nota anche che usiamo un punto e virgola dopo aver dichiarato le firme dei metodi nei trait.

Un trait può essere definito con un argomento generico, il che permette a una funzione di ricevere argomenti di qualsiasi tipo di dato.
Questo introduce una maggiore flessibilità nella firma della funzione, permettendole di gestire tipi di dato diversi.
Nel caso del trait `Summary` qui sotto, questo è stato riprogettato per funzionare con qualsiasi tipo di dato, così che quando il metodo `summarize` viene chiamato su di essi, restituisce un ByteArray.

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

Un trait può avere più di un metodo nel suo corpo; ogni firma di metodo dichiarata è una riga singola che termina con un punto e virgola.

## Implementare un trait su un tipo

Dopo aver definito le firme delle funzioni che compongono un trait, il compilatore verificherà che sia definita anche un'implementazione per i tipi che adottano il trait.
Qui sotto abbiamo scritto un crate libreria `aggregator` per i media, che riassume alcuni dati dalle istanze di `NewsArticle` e `Tweet`.
Per la struct `NewsArticle`, useremmo headline, author e location per restituire il valore del metodo `summarize` del trait `Summary`, mentre per la struct `Tweet` useremmo username e content, supponendo che il contenuto del tweet abbia un limite di 280 caratteri.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## Implementazioni predefinite

A volte un trait può essere definito con un'implementazione predefinita per alcuni o tutti i metodi che lo compongono.
Questo serve a evitare di dover implementare tutti i metodi per ogni tipo, e a rendere il codice più leggibile.
Se un tipo particolare richiede un'implementazione speciale di un metodo del trait, può sovrascrivere l'implementazione predefinita.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## Come usare e gestire i trait esterni

I trait e le implementazioni possono essere definiti in un modulo esterno e usati in altri moduli, purché siano importati correttamente.
Supponiamo di avere un trait `ShapeGeometry` con il metodo `boundary`, che deve essere implementato sia per la struct `Circle` sia per la struct `Rectangle`.
Qui sotto c'è un esempio di come il trait e la sua implementazione vengono importati, gestiti e usati tra moduli diversi.

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

La visibilità dell'implementazione di `CircleGeometry` e `RectangleGeometry` non deve essere pubblica, dato che il trait `ShapeGeometry` è reso pubblico e il compilatore dovrebbe trovarlo facilmente.

## Alias di impl

Le implementazioni possono avere un alias al momento dell'importazione, usando la parola chiave `impl`.
Questo è utile quando si istanzia un'implementazione generica per tipi concreti.
Definiamo un'implementazione banale del trait `Two` per tutti i tipi che implementano il trait `One`, semplicemente sommando due volte il valore di `One` e restituendo la somma.
Possiamo poi esporre l'implementazione di `Two` che funziona solo per i tipi `u8` e `u128`.

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

L'implementazione generica può essere scritta in un modulo privato e, con l'uso di un alias di impl, possiamo istanziare l'implementazione generica di questi due tipi concreti.
Il vantaggio di usare un'implementazione generica privata e non esposta è che evita la duplicazione del codice tra i file.
Inoltre mantiene l'API pubblica semplice e pulita.
