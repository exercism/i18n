# Informazioni

[concept:csharp/resource-cleanup]() usa l'interfaccia `IDispose` per segnalare a chi chiama una classe che ci sono risorse o uno stato del programma da rilasciare o ripristinare in modo tempestivo quando l'oggetto in questione non serve più. In questo esercizio abbiamo introdotto un po' di zucchero sintattico, con la parola chiave `using`, che rende il codice meno verboso e riduce la probabilità che chiamate importanti vengano omesse.

`using` può essere visto come un sostituto di [`try/finally`][try-finally] in alcuni casi d'uso.

```csharp
File file = null;
try
{
    file = new File("myStuff.txt");
    file.Write("more stuff");
}
finally
{
    file.Dispose();
}
```

Questa sintassi viene sostituita con la versione più compatta e a prova di errore:

```csharp
using (var file = new File("myStuff.txt")
{
    file.Write("more stuff");
}
```

Nota che più risorse possono essere combinate comodamente seguendo le regole standard per i blocchi su una sola riga:

```csharp
using (var file = new File("mystuff.txt")
using (var fileWriter = new StreamWriter(file)
{
     ...
}
```

In C# 8 è stata introdotta la seguente variante, in cui l'istruzione `using` compare all'inizio di un blocco:

```csharp
using var file = new File("myStuff.txt");
file.Write("more stuff");
```

Questo ti permette di avere più oggetti disposable nello stesso blocco e di gestire [`try/catch`][try-catch] in modo più naturale:

```csharp
using var fileIn = new File("myStuff.txt");
using var fileOut = new File("yourStuff.txt");
try
{
    var stuff = fileIn.Read();
    fileOut.Write(stuff);
}
catch (Exception)
{
    LogStuff();
}
```

Le regole relative a come può essere usata la parola chiave `using` e su quali tipi di istanze si applica sono descritte [qui][using-statement].

## Nota per gli sviluppatori Java

Gli sviluppatori Java potrebbero riconoscere in questo un analogo del meccanismo di [_gestione automatica delle risorse_][automatic-resource-management] introdotto in Java 7. Sono molto simili. La sintassi di Java, che riutilizza `try`, ha il vantaggio di incorporare i blocchi `catch` in modo più naturale di quanto faccia `using` di C#.

## Versioni

Nota che la versione più flessibile di `using`, quella che non ha un proprio blocco sintattico, è stata introdotta in C# 8, quindi potresti dover controllare se la base di codice su cui stai lavorando usa C# 8 o versioni successive.
