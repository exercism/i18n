# Introduzione

## Confronti

Python supporta i seguenti operatori di confronto di base:

| Operatore | Operazione                 | Descrizione                                                               |
| -------- | -------------------------- | ------------------------------------------------------------------------- |
| `>`      | «maggiore di»              | `a > b` è `True` se `a` è **strettamente** maggiore in valore di `b`      |
| `<`      | «minore di»                | `a < b` è `True` se `a` è **strettamente** minore in valore di `b`        |
| `==`     | «uguale a»                 | `a == b` è `True` se `a` è **strettamente** uguale a `b` in valore        |
| `>=`     | «maggiore o uguale a»      | `a >= b` è `True` se `a > b` OPPURE `a == b` in valore                    |
| `<=`     | «minore o uguale a»        | `a <= b` è `True` se `a < b` o `a == b` in valore                         |
| `!=`     | «diverso da»               | `a != b` è `True` se `a == b` è `False`                                   |
| `is`     | «identità»                 | `a is b` è `True` se **_e solo se_** `a` e `b` sono lo stesso _oggetto_   |
| `is not` | «identità negata»          | `a is not b` è `True` se `a` e `b` **non** sono lo stesso _oggetto_       |
| `in`     | «test di appartenenza»     | `a in b` è `True` se `a` è membro, sottoinsieme o elemento di `b`         |
| `not in` | «test di appartenenza negato» | `a not in b` è `True` se `a` non è membro, sottoinsieme o elemento di `b` |

Hanno tutti la stessa priorità (_che è più alta di quella delle [operazioni booleane][boolean operations], ma più bassa di quella delle operazioni aritmetiche o bit a bit_).

## Confronto tra tipi di dati diversi

Gli oggetti di tipi diversi (_tranne i tipi numerici_) non risultano mai uguali per impostazione predefinita.
Anche le istanze non identiche di una `class` _**non**_ risulteranno uguali, a meno che la `class` non definisca metodi speciali di [confronto ricco][rich comparisons] che personalizzano il comportamento di confronto predefinito di `object`.
La personalizzazione tramite `rich comparisons` sarà trattata in un esercizio successivo.
Per (molti) più dettagli su questo argomento, vedi [Confronti di valore][value comparisons] nella documentazione di Python.

I tipi numerici sono (per lo più) un'eccezione a questa regola di corrispondenza tra tipi.
Un `integer` **può** essere considerato uguale a un `float` (_o un [`octal`][octal] uguale a un [`hexadecimal`][hex]_), purché i tipi possano essere convertiti implicitamente per il confronto.

Per gli altri tipi numerici nella libreria standard di Python ([complex][complex numbers], [decimal][decimal numbers], [fractions][rational numbers]), gli operatori di confronto sono definiti dove «ha senso» (_dove la conversione implicita non cambia il risultato_), ma generano un `TypeError` se gli oggetti sottostanti non possono essere convertiti accuratamente per il confronto.
Per maggiori informazioni sulle regole che Python usa per la _conversione numerica_, vedi [conversioni aritmetiche][arithmetic conversions] nella documentazione di Python.

```python
>>> import fractions

# A string cannot be converted to an int.
>>> 17 == '17'
False

# An int can be converted to float for comparison.
>>> 17 == 17.0
True

# The fraction 6/3 can be converted to the int 2
# The int 2 can be converted to 0b10 in binary.
>>> 6/3 == 0b10
True

# An int can be converted to a complex number with a 0 imaginary part.
>>> 17 == complex(17)
True

# The fraction 2/5 can be converted to the float 0.4
>>> 0.4 == 2/5
True

>>> complex(2/5, 1/2) == complex(0.4, 0.5)
True
```

Qualsiasi confronto ordinato di un numero con un tipo `NaN` (_not a number_) è `False`.
Un effetto collaterale confuso della definizione di `NaN` in Python è che `NaN` non è mai uguale a `NaN`.

```python
>>> x = float('NaN')

>>> 3 < x
False

>>> x < 3
False

# NaN never compares equal to NaN
>>> x == x
False
```

## Confronto tra stringhe

A differenza dei numeri, le stringhe (`str`) vengono confrontate [_lessicograficamente_][lexographic order], usando i loro singoli punti di codice Unicode (_il risultato del passaggio di ogni punto di codice nella `str` alla funzione incorporata [`ord()`][ord], che restituisce un `int`_).
Se tutti i punti di codice in entrambe le stringhe corrispondono e sono _**nello stesso ordine**_, le due stringhe sono considerate uguali.
Questo confronto viene fatto in modo «a coppie»: primo con primo, secondo con secondo, ecc.
In Python 3.x, `str` e `bytes` non possono essere convertiti/confrontati direttamente.

```python
>>> 'Python' > 'Rust'
False

>>> 'Python' > 'JavaScript'
True

# Examples with Mandarin.
# hello < goodbye
>>> '你好' < '再见'
True

# ord() of first characters
>>> ord('你'), ord('再')
(20320, 20877)

# ord() of second characters
>>> ord('好'), ord('见')
(22909, 35265)

# And with Korean words.
# Pretty < beautiful.
>>> '예쁜' < '아름다운'
False

>>> ord('예'), ord('아')
(50696, 50500)
```

## Concatenamento dei confronti

Gli operatori di confronto possono essere concatenati _arbitrariamente_, nel senso che possono essere usati in qualsiasi combinazione e di qualsiasi lunghezza.
Nota che la valutazione di un'espressione avviene da `left` a `right`.

Ad esempio, `x < y <= z` è equivalente a `x < y` `and` `y <= z`, tranne per il fatto che `y` viene valutato **una sola volta**.
In entrambi i casi, `z` _non_ viene valutato **affatto** quando `x < y` risulta `False`.
Questo è spesso chiamato `short-circuit evaluation`: la valutazione si ferma se il valore di verità dell'espressione è già stato determinato.

Il `Short circuiting` è supportato da vari operatori booleani, funzioni e anche dal concatenamento di confronti in Python.
A differenza di molti altri linguaggi di programmazione, tra cui `C`, `C++`, `C#` e `Java`, le espressioni concatenate come `a < b < c` in Python hanno una convenzionale [interpretazione matematica][three way boolean comparison] e una precedenza.

```python
>>> x = 2
>>> y = 5
>>> z = 10

>>> x < y < z
True

>>> x < y > z
False

>>> x > y < z
False
```

## Confronto dell'identità degli oggetti

Gli operatori `is` e `is not` verificano l'_[identità_][object identity] di un oggetto, in contrapposizione al _valore_ dell'oggetto.
L'identità di un oggetto non cambia mai dopo la creazione e può essere trovata usando la funzione [`id()`][id function].

`<apple> is <orange>` valuta a `True` se _**e solo se**_ `id(<apple>)` == `id(<orange>)`.
`<apple> is not <orange>` restituisce l'inverso.

A causa del loro stato di singleton, `None` e `NotImplemented` dovrebbero sempre essere confrontati con gli elementi usando `is` e `is not`.
Vedi la documentazione di riferimento di Python su [confronti di valore][value comparisons none] e [PEP8][pep8 programming recommendations] per maggiori dettagli su questa convenzione.

```python
>>> my_fav_numbers = [1, 2, 3]

>>> your_fav_numbers = my_fav_numbers

>>> my_fav_numbers is your_fav_numbers
True

# The returned id will differ by system and python version.
>>> id(my_fav_numbers)
4517478208

# your_fav_numbers is only an alias pointing to the original my_fav_numbers object.
# Assigning a new name does not create a new object.
>>> id(your_fav_numbers)
4517478208


>>> my_fav_numbers is not your_fav_numbers
False

>>> my_fav_numbers is not None
True

>>> my_fav_numbers is NotImplemented
False
```

## Confronti di appartenenza

Gli operatori `in` e `not in` verificano l'_appartenenza_.
`<fish> in <soup>` valuta a `True` se `<fish>` è un membro di `<soup>` (_se `<fish>` è un sottoinsieme di `<soup>` o è contenuto in `<soup>`_), e valuta `False` altrimenti.
`<fish> not in <soup>` restituisce la negazione, o l'_opposto di_ `<fish> in <soup>`.

Per i tipi string e bytes, `<name> in <fullname>` è `True` _**se e solo se**_ `<name>` è una sottostringa di `<fullname>`.

```python
# A set of lucky numbers.
>>> lucky_numbers = {11, 22, 33}
>>> 22 in lucky_numbers
True

>>> 44 in lucky_numbers
False

# A dictionary of employee information.
>>> employee = {'name': 'John Doe', 
                'id': 67826, 'age': 33, 
                'title': 'ceo'}

# Checking for the membership of certain keys.
>>> 'age' in employee
True

>>> 33 in employee
False

>>> 'lastname' not in employee
True

# Checking for substring membership
>>> name = 'Super Batman'
>>> 'Bat' in name
True

>>> 'Batwoman' in name
False
```
