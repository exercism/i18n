# Informazioni

Le risorse che mantengono lo stato del sistema operativo (handle di file, socket, lock) hanno bisogno di una pulizia *garantita*, anche quando un'eccezione risale lo stack. Il vocab [`destructors`][destructors] di Factor fornisce un piccolo framework per questo, e la maggior parte delle risorse integrate (`<file-reader>`, `<file-writer>`, socket, …) si aggancia già ad esso.

## La classe e il generico

Una classe vi si unisce estendendo `disposable` ed implementando `dispose*`:

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )` alloca la tupla *e* la registra nello scope del distruttore corrente, quindi un'eccezione tra l'allocazione e il successivo punto sicuro non può causare la perdita della risorsa. Il framework garantisce che `dispose*` venga eseguito **al massimo una volta** per ogni oggetto: le chiamate ripetute a `dispose` non hanno alcun effetto.

## Chi chiama dall'esterno usa `dispose`

| parola            | effetto                                       |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )`: rilascia; è sicuro chiamarla due volte |
| `with-disposal`   | `( disposable quot -- )`: circoscrive una sola risorsa |
| `with-destructors`| `( quot -- )`: apre uno scope con registro   |
| `&dispose`        | `( obj -- obj )`: rilascia all'uscita normale *o* in caso di fallimento |
| `|dispose`        | `( obj -- obj )`: rilascia solo se lo scope si chiude in modo anomalo |

`with-disposal` è la forma per una singola risorsa. Per più di una risorsa, apri uno scope `with-destructors` e registra ogni acquisizione con `&dispose` (vuoi sempre rilasciarla) o `|dispose` (rilascia solo in caso di fallimento: il percorso di successo la mantiene).

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup` è la primitiva essenziale

Per un try/finally una tantum senza registro, [`cleanup`][cleanup] (da `continuations`) è la parola di livello inferiore:

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` è strettamente più potente (il registro può crescere a runtime), ma `cleanup` è la scelta naturale quando l'accoppiamento tra acquisizione e rilascio è fisso e locale.
