# Introduzione

Con Go 1.18, Go ha aggiunto il supporto per i **generici**.
I generici ti permettono di scrivere funzioni e strutture dati che funzionano con tipi diversi senza duplicare il codice.

## Perché i generici?

In Go, funzioni e tipi di norma lavorano con tipi specifici, come `int` o `string`.
Prima dei generici avevi due possibilità per supportare più tipi.
La prima era scrivere più funzioni con nomi diversi, come `SumInts` e `SumFloats`.
Questo approccio crea codice duplicato difficile da mantenere.
La seconda era usare l'interfaccia vuota `any` (`interface{}`).
Tuttavia, l'interfaccia vuota elimina i controlli dei tipi in fase di compilazione e richiede asserzioni di tipo a runtime.
I generici risolvono questo problema offrendo sicurezza dei tipi e, allo stesso tempo, evitando il codice duplicato.

## Funzioni generiche

Definisci una funzione generica aggiungendo dei **parametri di tipo** tra parentesi quadre (`[...]`) dopo il nome della funzione.
Ecco un esempio di funzione generica che restituisce uno slice invertito:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

In questo esempio, `T` è un parametro di tipo.
Puoi pensare a `T` come a un segnaposto per un tipo reale.
La parola chiave `any` all'interno delle parentesi quadre è un **vincolo di tipo**.
Il vincolo indica al compilatore quali tipi sono ammessi per `T`.
Qui `any` significa che `T` può essere un tipo qualsiasi.

### Chiamare le funzioni generiche

Puoi chiamare una funzione generica passando il tipo effettivo tra parentesi quadre.
Questo tipo effettivo si chiama **argomento di tipo**.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

Nella maggior parte dei casi, il compilatore Go riesce a rilevare automaticamente il tipo dagli argomenti della funzione.
Questa funzionalità si chiama **inferenza del tipo**.
Con l'inferenza del tipo non devi scrivere l'argomento di tipo tra parentesi quadre.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

In questo esempio, il compilatore vede che `words` è uno slice di stringhe, quindi deduce che `T` è `string`.

## Vincoli di tipo

Ogni parametro di tipo deve avere un vincolo.
Un vincolo specifica quali tipi puoi usare come argomenti di tipo.
Un vincolo determina anche le operazioni che puoi eseguire sui valori di quel tipo.

### Il vincolo `any`

Il vincolo `any` permette qualsiasi tipo.
In Go, `any` è un alias dell'interfaccia vuota `interface{}`.
Poiché `any` permette ogni tipo, la funzione può eseguire solo operazioni valide per tutti i tipi Go.
Per esempio, se hai due valori `any` che contengono degli slice, non puoi confrontarli con `==`, perché gli slice non si possono confrontare con `==`.

### Il vincolo `comparable`

Go fornisce un vincolo predefinito chiamato `comparable`.
Il vincolo `comparable` permette qualsiasi tipo che supporta gli operatori `==` e `!=`.
I tipi comparabili includono i booleani, i numeri, le stringhe, i puntatori, i channel e le struct o gli array composti da tipi comparabili.

Ecco un esempio di funzione che controlla se uno slice contiene un elemento specifico:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Poiché `T` usa il vincolo `comparable`, l'espressione `elem == target` è valida.
Se sostituisci `comparable` con `any`, il compilatore segnala un errore.

### Vincoli personalizzati tramite insiemi di tipi nelle interfacce

A partire da Go 1.18, le interfacce possono definire insiemi di tipi oltre ai metodi.
Puoi usare il carattere pipe `|` per elencare i tipi ammessi in un'interfaccia.

```go
type Number interface {
    int | int64 | float64
}
```

Ora puoi usare `Number` come vincolo per una funzione:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Poiché tutti i tipi in `Number` supportano l'operatore `*`, Go permette `value * 2` all'interno della funzione.

### L'approssimazione del tipo sottostante `~`

A volte crei una definizione di tipo personalizzata basata su un tipo primitivo:

```go
type MyInt int
```

Il vincolo `Number` definito sopra permette solo i tipi esatti `int`, `int64` e `float64`.
Se passi un valore `MyInt` a `Double`, il compilatore produce un errore, perché `MyInt` non corrisponde a `int`.
Per permettere qualsiasi tipo il cui tipo sottostante è `int`, aggiungi una tilde `~` prima del tipo:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

Ora puoi usare `Double` con valori di tipo `MyInt`.

### Il vincolo `cmp.Ordered`

La libreria standard fornisce il vincolo `cmp.Ordered` nel [pacchetto `cmp`][doc-cmp].
Il vincolo `cmp.Ordered` permette qualsiasi tipo che supporta gli operatori di confronto `<`, `<=`, `>` e `>=`.

## Tipi generici

Puoi anche usare i parametri di tipo per definire tipi generici, come le struct.
Ecco un esempio di una struttura dati `Stack` generica:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Quando dichiari una variabile di un tipo generico, devi indicare l'argomento di tipo tra parentesi quadre:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

L'inferenza del tipo funziona solo con le funzioni generiche.
Devi sempre specificare l'argomento di tipo quando crei valori di un tipo generico.

## Quando usare i generici

I generici sono una funzionalità potente, ma non devi usarli per ogni problema.

Usa i generici in situazioni come queste:
- Stai costruendo strutture dati, come alberi, liste concatenate o cache, che funzionano con qualsiasi tipo di elemento.
- Stai scrivendo funzioni di utilità che operano su slice o map di qualsiasi tipo, come filtrare, ordinare o cercare.
- Ti serve esattamente la stessa implementazione per diversi tipi e vuoi la sicurezza dei tipi in fase di compilazione.

Usa invece le interfacce in situazioni come queste:
- Ti interessano il comportamento e i metodi, più che il tipo di dato sottostante.
  Per esempio, se vuoi leggere ed elaborare dati da sorgenti di vario tipo (file, rete, TTY), è meglio usare `func Process(src io.Reader)` invece di `func Process[T](src T)`.
- Tipi diversi richiedono implementazioni diverse dei metodi per svolgere il loro lavoro.
