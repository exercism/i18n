# Introduzione

Sai già come *costruire* una quotation a partire da pezzi e come eseguirla. Una quotation è soltanto una sequenza di codice, quindi le parole che già conosci per le sequenze valgono anche per lei:

```factor
USING: kernel math prettyprint quotations sequences ;

{ [ 1 ] [ 2 + ] [ 3 * ] } concat >quotation call .   ! => 9
[ 1 + ] dup append .                                 ! => [ 1 + 1 + ]
```

`append` unisce due quotation, `concat` appiattisce un array di quotation, `map` trasforma i dati in quotation e `>quotation` rende il risultato chiamabile. `MACRO:` prende esattamente questa abilità e la sposta a **tempo di compilazione**.

## Che cos'è una macro

Una definizione `MACRO:` somiglia a una parola qualsiasi, ma il suo corpo viene eseguito *mentre il programma viene compilato*, non mentre viene eseguito. Il corpo deve lasciare **una sola quotation** sullo stack. Il compilatore poi **inserisce quella quotation nel punto di chiamata**: sostituisce la chiamata alla macro con il codice prodotto dal corpo. A tempo di esecuzione non resta alcuna macro, solo il codice generato.

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- spliced )
    dup append ;
```

Ogni volta che scrivi `[ 1 + ] twice`, il compilatore:

1. esegue il corpo con `[ 1 + ]` sullo stack,
2. `dup append` costruisce la quotation `[ 1 + 1 + ]`,
3. inserisce il suo codice, `1 + 1 +`, in quel punto.

Quindi una parola che chiama `twice` viene compilata come se avessi scritto `1 + 1 +` a mano:

```factor
: inc-twice ( x -- y ) [ 1 + ] twice ;

5 inc-twice .   ! => 7
```

Il contrasto chiave: una parola normale che riceve una quotation la esegue con `call` a tempo di esecuzione. Una macro non chiama mai nulla: consegna al compilatore del *codice nuovo* da compilare al suo posto.

## Gli input devono essere letterali

Poiché il corpo viene eseguito a tempo di compilazione, gli input di una macro devono essere noti *in quel momento*. Devono essere dei **letterali** nel punto di chiamata: una quotation `[ … ]`, un numero, un array, una stringa. Un valore che esiste solo a tempo di esecuzione non può essere passato a una macro.

```factor
! DOCTEST: SKIP — illustrative call sites, not standalone code
[ 1 + ] twice          ! ok: the quotation is a literal
[ 1 + ] 3 repeat-quot  ! ok: the quotation and the number are literals
```

## La cassetta degli attrezzi

Il corpo di una macro è codice normale che restituisce una quotation. Le parole che hai già incontrato fanno quasi tutto il lavoro:

| per costruire…                         | usa                  |
|----------------------------------------|----------------------|
| `[ A B ]` da `[ A ]` e `[ B ]`         | `append`             |
| una quotation da un array di quotation | `concat >quotation`  |
| una quotation per ogni elemento di una sequenza | `map`, poi `concat >quotation` |

Altre due parole, da `sequences` e `kernel`, completano la cassetta degli attrezzi.

**`<repetition>`** (in `sequences`) crea una sequenza di `n` copie di un unico elemento. Il suo effetto sullo stack è `( length elt -- repetition )`: il conteggio viene per primo. Il risultato è una sequenza *virtuale*, quindi appiattiscila nel solito modo:

```factor
3 [ 1 + ] <repetition> concat >quotation .   ! => [ 1 + 1 + 1 + ]
```

**`curry`** (in `kernel`) antepone un valore a una quotation, producendo una nuova quotation che inserisce quel valore per primo:

```factor
3 [ + ] curry .          ! => [ 3 + ]
{ 1 2 3 } [ . ] curry .  ! => [ { 1 2 3 } . ]
```

`curry` è il modo in cui incorpori un elemento specifico in una quotation: è esattamente ciò che trasforma `{ 10 20 30 }` e `[ + ]` in `[ 10 + ] [ 20 + ] [ 30 + ]`.

## Perché è più semplice di quanto sembri

In alcuni linguaggi, le macro richiedono una sintassi speciale di quote/unquote e meccanismi aggiuntivi per evitare collisioni di nomi. Factor non ha bisogno di nulla di tutto ciò: una quotation è già una sequenza di parole *risolte*, perché il parser ha cercato ciascun `dup`, `+` e `append` quando ha letto il `[ … ]`. Quindi il corpo di una macro non è altro che la manipolazione di sequenze che già fai, che però restituisce una quotation.

## Un parente stretto: `$[ … ]`

Una macro restituisce una quotation da inserire in una *chiamata*. Quando invece vuoi un semplice *valore* calcolato a tempo di analisi, `$[ code ]` esegue `code` mentre il file viene letto e inserisce il risultato nel sorgente come letterale:

```factor
! DOCTEST: SKIP — compile-time value, shown for contrast
USING: calendar literals ;

CONSTANT: build-time $[ now ]
```

`$[ … ]` proviene dal vocabolario [`literals`][literals], che raccoglie le parole per interpolare nei letterali i risultati ottenuti a tempo di analisi. È menzionato per completezza. I quattro stencil che scriverai, `twice`, `repeat-quot`, `compose-many` ed `each-literal`, sono tutte dichiarazioni `MACRO:`.
