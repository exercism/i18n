# Inclusione del codice

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

Un `include` copia il codice di un'altra classe dentro questa. È un'operazione in fase di compilazione, senza alcun costo in fase di esecuzione e senza alcun legame in fase di esecuzione: le due classi, in seguito, non sono collegate.

## La clausola

```
   include CLASS  old_name -> new_name , old_name -> ;
```

Ogni voce rinomina una caratteristica. `-> ;` senza un nuovo nome la esclude. Tutto ciò che non viene menzionato entra invariato.

La rinomina riguarda ciò che vede l'*esterno*. Le chiamate tra le routine incluse continuano a funzionare: se `describe` chiama `count` e `count` viene rinominato in `beats`, `describe` chiama `beats`.

## Includerne diverse

```sather
   include WARM_UP;
   include COOL_DOWN;
```

è consentito, ed è così che Sather ottiene quello che altri linguaggi chiamano ereditarietà multipla, senza i soliti problemi: un conflitto è un errore di compilazione e la soluzione è rinominare o escludere una delle due. Nulla viene risolto da un ordine di precedenza che devi memorizzare.

## private include

```sather
   private include WARM_UP;
```

porta il codice dentro per uso interno di questa classe, senza esporlo. Utile quando vuoi l'implementazione e non l'interfaccia.

## Le due cose insieme

La forma tipica per una famiglia di classi:

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

`< $ACT` dice cosa può fare; `include ACT_BASICS` fornisce una parte del come. Se cambi idea sul come, il `<` non si sposta.

## Perché si fa così

Una classe astratta non ha codice, quindi non può essere ereditata per sbaglio, e non esiste una superclasse il cui comportamento cambi all'improvviso. Il riutilizzo è una copia presa in fase di compilazione, da una classe che hai nominato, con ogni rinomina messa per iscritto.

Il costo è che il riutilizzo va richiesto esplicitamente in ogni classe. Questo è lo scambio: più da scrivere, nulla di implicito.
