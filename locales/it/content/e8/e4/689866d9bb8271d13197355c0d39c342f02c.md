# Introduzione

A volte una parte di stato deve essere condivisa tra diverse word senza doverla passare ogni volta attraverso i loro stack effect. Le *variabili dinamiche* di Factor, dichiarate con `SYMBOL:`, danno a ogni word accesso a un valore conservato in un namespace.

## `SYMBOL:` e `SYMBOLS:`

`SYMBOL: name` dichiara una variabile. `SYMBOLS: a b c ;` ne dichiara diverse in una sola volta:

```factor
USING: namespaces ;

SYMBOLS: counter total ;
```

## Impostare e leggere

`set-global` e `get-global` (in [`namespaces`][namespaces]) operano sul namespace globale:

```
set-global    ( value variable -- )
get-global    ( variable -- value )
change-global ( variable quot: ( old -- new ) -- )
```

```factor
0 counter set-global
counter get-global .         ! => 0
counter [ 10 + ] change-global
counter get-global .         ! => 10
```

Per lo stato a livello di modulo, le varianti `-global` sono quelle che ti servono.

## Associazioni con scope tramite `with-variable`

Una variabile dinamica supporta anche una seconda variante, quella *con scope*. `set` / `get` / `change` (senza il suffisso `-global`) leggono e scrivono nello scope dinamico *corrente*, e `with-variable` (in [`namespaces`][namespaces]) crea uno scope nuovo per la durata di una quotation:

```
with-variable ( value variable quot -- )
set           ( value variable -- )
get           ( variable -- value )
change        ( variable quot: ( old -- new ) -- )
```

La variabile è legata a `value` mentre `quot` viene eseguita; quando questa termina, il legame scompare. Così chi chiama dall'esterno può «iniettare» un valore che il codice interno può leggere senza doverlo passare attraverso ogni stack signature.

```factor
SYMBOL: greeting

"Hello" greeting [
    greeting get .                ! => "Hello"
    "Howdy" greeting set
    greeting get .                ! => "Howdy"
    greeting [ "!" append ] change
    greeting get .                ! => "Howdy!"
] with-variable

greeting get-global .    ! => f   (the scoped binding is gone)
```

In questo esercizio useremo la variante globale dall'inizio alla fine, ma riconoscere la famiglia parallela `set`/`get`/`change` è utile quando leggi il codice di altre persone.

## Vettori mutabili

Dato che le variabili dinamiche contengono un riferimento, puoi conservare una collezione *mutabile* dentro una di esse e aggiornarla sul posto:

```factor
SYMBOL: history

V{ } clone history set-global
"first event" history get-global push
"second event" history get-global push
history get-global .
! => V{ "first event" "second event" }
```

`V{ … }` è un vettore letterale. Fai sempre `clone` di un letterale `V{ }` prima di memorizzarlo: i letterali sono condivisi tra le chiamate.

## `find`: la prima corrispondenza

`find` (in [`sequences`][sequences]) restituisce il primo elemento per cui un predicato risulta vero, insieme al suo indice:

```
find ( seq quot -- index elt/f )
```

Se non c'è nessuna corrispondenza, entrambi i valori sono `f`. Scartare l'indice con `nip` e usare `unless*` è la combinazione standard per il «valore predefinito se manca qualcosa».

## `reject`: scartare le corrispondenze

`reject` (sempre in [`sequences`][sequences]) è l'opposto di `filter`: restituisce gli elementi che *non superano* il predicato.
