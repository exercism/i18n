# Informazioni

In Swift, i [closure][closures] sono blocchi di codice autonomi a cui si possono passare dei parametri per attivarne il calcolo e che restituiscono dei valori.
Le closure catturano anche dei valori dal loro ambiente e li usano nei loro calcoli.
Poiché sono autonome, possono essere passate in giro in un programma come qualsiasi altro valore, oppure assegnate a costanti e variabili.

I closure potrebbero sembrare molto simili alle funzioni di Swift, e in effetti lo sono, per una buona ragione.
Le funzioni in Swift sono casi particolari di closure, che devono avere un nome e vengono definite con una sintassi leggermente diversa.

Anche se in Swift le funzioni sono tecnicamente delle closure, quando si parla di «closure» in Swift ci si riferisce alle [espressioni closure][closure-expressions].
Le espressioni closure si scrivono come una lista di parametri seguita da un tipo restituito e dalla parola chiave `in`, seguita dal corpo della closure, il tutto racchiuso tra una coppia di parentesi graffe:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}
```

Questo definisce un'espressione closure di tipo `(Double, Double) -> Double`, che può essere eseguita in modo simile a una funzione di questo tipo, applicandola a parametri del tipo appropriato:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}(10.0, 15.0)
// returns 12.5
```

Siccome non è molto comodo scrivere ogni volta l'intera espressione closure quando la si vuole eseguire, le closure possono essere assegnate a dei nomi, come qualsiasi altro valore in Swift.
A quel punto si possono chiamare applicando il nome ai parametri:

```swift
let mean = { (a: Double, b: Double) -> Double in
  (a + b) / 2.0
}

mean(13.0, 100.0)
// returns 56.5
```

Come si è visto sopra, le closure, proprio come le funzioni normali, possono omettere la parola chiave `return` se il corpo della closure è una singola espressione.

Molto spesso le closure si usano con le funzioni di ordine superiore, passandole come parametri o restituendole come risultati:

```swift
[11, 75, 3, 99, 53].contains(where: { (x: Int) -> Bool in x > 100 })
// returns false

["apple", "ball", "carrot"].sorted(by: { (s1: String, s2: String) -> Bool in s1.count < s2.count })
// returns ["ball", "apple", "carrot"]

func makeAdder(base: Int) -> (Int) -> Int {
  { (x: Int) -> Int in base + x }
}
```

## Inferire i tipi delle closure

Quando il tipo restituito o i tipi dei parametri possono essere [inferiti dal contesto][inferring-closure-types], si possono omettere dall'espressione closure.
Inoltre, se si possono omettere i tipi dei parametri, si possono omettere anche le parentesi attorno ai nomi dei parametri:

```swift
let mean: (Double, Double) -> Double = { a, b in a + b / 2.0 }

func makeAdder(base: Int) -> (Int) -> Int {
  { x in base + x }
}

["apple", "ball", "carrot"].sorted(by: { s1, s2 in s1.count < s2.count })
```

- Nel primo esempio, il tipo può essere inferito dall'annotazione sulla costante `mean`.
- Nel secondo, il compilatore sa dalla definizione di `makeAdder` che `base` è un intero e che la funzione restituita deve essere di tipo `(Int) -> Int`. Da lì può verificare che, se `x` è un `Int`, allora la closure avrà tipo `(Int) -> Int`, e quindi possiamo omettere la firma di tipo nella closure, dato che `(Int) -> Int` è l'unica firma valida possibile che la closure possa avere.
- Il terzo esempio è simile, ma il compilatore deve ricavare alcune informazioni sul tipo dall'array con cui il metodo viene usato. Sa che il metodo `sorted(by:)` prende come parametro una closure con due parametri dello stesso tipo degli elementi della collezione che viene ordinata, e che restituisce un `Bool`, quindi il compilatore può inferire che il tipo restituito dalla closure deve essere `Bool`. E dato che il metodo viene usato con un array di stringhe, può determinare che i tipi dei parametri `s1` e `s2` devono essere entrambi `String`.

## Limiti delle closure

Come accennato sopra, in Swift le funzioni e le closure sono molto simili, ma ci sono alcune differenze importanti:

- Le closure non possono usare etichette di argomento esterne. Non c'è modo di definirle, e provare a usare il nome di un parametro quando si chiama la closure produce un errore:

```swift
let add5 = { x in x + 5 }
add5(x: 10)
// Error: Extraneous argument label 'x:' in call
```

- I parametri nelle closure non possono avere un valore predefinito.
- I parametri nelle closure possono essere parametri variadici, ma devono avere un nome ed un'annotazione di tipo.
