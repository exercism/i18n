# Informazioni

## Caratteri

Una [codifica dei caratteri][char-encoding] è una convenzione specifica usata per rappresentare in una sequenza di byte gli elementi di testo di una lingua naturale.
Un «elemento di testo», qui, può essere qualsiasi unità che abbia un significato in una lingua naturale: lettere, spazi, punteggiatura, emoji, ideogrammi e così via.

NASM (The Netwide Assembler, l'assembler usato da questa traccia) supporta la definizione di dati tramite [ASCII][ascii].

Le costanti di carattere in NASM possono essere lunghe fino a 8 byte e si possono definire con virgolette singole (`'`), virgolette doppie (`"`) o backtick (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Per i caratteri speciali bisogna usare i backtick e l'escape con `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASM supporta anche i [caratteri Unicode][unicode] in [UTF-8][utf8], specificati con `\u` o `\U` e racchiusi tra backtick:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

Nota che in x86-64 non esiste un supporto integrato per una codifica dei caratteri come tipo distinto.
In assembly i dati sono una sequenza di byte, e l'interpretazione di quei byte come carattere, numero o qualsiasi altra cosa è lasciata a chi programma.

Per esempio, il carattere ASCII '0' è un singolo byte con valore 48.
Quindi memorizzare 48 in un byte equivale esattamente a memorizzare il carattere ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Per lo stesso motivo, per manipolare i caratteri si trasformano direttamente i valori contenuti in quei byte:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Stringhe

Una [stringa][string] è una sequenza di caratteri.
In assembly, di solito è implementata come un array.

Si può dichiarare una stringa in NASM nello stesso modo in cui si dichiarerebbe qualsiasi array:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Una differenza tra le stringhe e gli altri array è che NASM supporta anche la dichiarazione di stringhe senza una virgola (`,`) che separi i valori.
È anche possibile alternare i valori con le virgole:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Nota che, come già accennato, i caratteri sono solo byte (o una sequenza di byte, con la codifica Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Dato che ogni carattere ASCII occupa un solo byte, ogni byte successivo in una dimensione maggiore è `0`.
Per esempio, dichiarare `'a'` come qword (8 byte) significa che il primo byte è `'a'` (`97`) e gli altri sette byte sono tutti `0`.

Per questo motivo, tutti questi sono equivalenti:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
In assembly, le stringhe non terminano automaticamente con un carattere NUL ASCII (valore `0`).

Quando si interagisce con linguaggi di livello superiore, come C, spetta a chi programma assicurarsi che alla fine della stringa venga aggiunto il terminatore corretto, se previsto.
~~~~

## Istruzioni per le stringhe

Dato che le stringhe sono array, puoi lavorarci come con qualsiasi array, dereferenziando la memoria in modo esplicito:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Oltre a questo, esistono alcune istruzioni per caricare, spostare e memorizzare valori in sequenze di byte in memoria.
Anche se si chiamano _istruzioni per le stringhe_, si possono usare con qualsiasi sequenza di byte in memoria, cioè con qualsiasi array:

| istruzione   | cosa fa                                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | carica un valore da una posizione di memoria indicata da `rsi` in `rax`                                           |
| [stos][stos] | memorizza un valore da `rax` in una posizione di memoria indicata da `rdi`                                        |
| [movs][movs] | copia un valore da una posizione di memoria indicata da `rsi` e lo memorizza in una posizione di memoria indicata da `rdi` |
| [cmps][cmps] | confronta il valore in una posizione di memoria indicata da `rsi` con il valore in una posizione di memoria indicata da `rdi` |
| [scas][scas] | confronta il valore in `rax` con il valore in una posizione di memoria indicata da `rdi`                          |

Nota che queste istruzioni _non_ accettano alcun operando esplicito.
I loro operandi sono impliciti.

Come regola generale:

1. Quando il loro operando sorgente è una posizione di memoria, il suo indirizzo va memorizzato in `rsi` (`s` sta per source).
2. Quando il loro operando di destinazione è una posizione di memoria, il suo indirizzo va invece memorizzato in `rdi` (`d` sta per destination).
3. Se uno degli operandi non è una posizione di memoria, si tratta del registro `rax`.

Nota che queste istruzioni dereferenziano automaticamente gli indirizzi di memoria in base all'operazione specifica che eseguono.

Tutte possono operare in dimensioni diverse.
Per indicarlo, si aggiunge un suffisso:

| suffisso | significato | dimensione |
| :------: | ----------- | :--------- |
|   `b`    | byte        | 1 byte     |
|   `w`    | word        | 2 byte     |
|   `d`    | dword       | 4 byte     |
|   `q`    | qword       | 8 byte     |

Per esempio:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

Inoltre aggiornano ogni indirizzo usato della dimensione dell'operazione.
Questo aggiornamento avviene in base al valore del **direction flag (DF)**:

- Se il `DF` è azzerato, gli indirizzi vengono _aumentati_ della dimensione dell'operazione.
- Se il `DF` è impostato, gli indirizzi vengono invece _diminuiti_ della stessa quantità.

L'ABI System V stabilisce che il direction flag deve essere azzerato all'ingresso di una funzione.
Quindi, _il comportamento predefinito è che la memoria venga letta/scritta in ordine crescente di indirizzi_.

L'istruzione [cld][cld] si può usare per azzerare il direction flag, mentre l'istruzione [std][std] per impostarlo:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Secondo l'ABI System V, chi chiama si aspetta che il `DF` sia azzerato dopo il ritorno di qualsiasi funzione chiamata.
Se imposti il `DF`, assicurati di azzerarlo prima di `ret`.
~~~~

### Lods

Questa istruzione _legge_ da una posizione di memoria il cui indirizzo è in `rsi` e copia il valore in `rax`.

Il valore in `rsi` viene aggiornato del numero di byte letti:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

Questa istruzione copia il valore in `rax` e lo _scrive_ in una posizione di memoria il cui indirizzo è in `rdi`.

Il valore in `rdi` viene aggiornato del numero di byte scritti:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

Questa istruzione _legge_ da una posizione di memoria il cui indirizzo è in `rsi` e _scrive_ il valore in una posizione di memoria il cui indirizzo è in `rdi`.
Il valore in `rax` non è influenzato da questa istruzione.

Sia `rsi` sia `rdi` vengono aggiornati del numero di byte copiati da una posizione di memoria all'altra:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

Questa istruzione _legge_ da una posizione di memoria il cui indirizzo è in `rsi` e _legge_ anche da una posizione di memoria il cui indirizzo è in `rdi`.
Poi confronta i valori e aggiorna i flag, come fa `cmp`.

Sia `rsi` sia `rdi` vengono aggiornati del numero di byte letti da entrambe le posizioni:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

Questa istruzione confronta il valore in `rax` con il valore che _legge_ da una posizione di memoria il cui indirizzo è in `rdi`.
Poi aggiorna i flag, come fa `cmp`.

Il valore in `rdi` viene aggiornato del numero di byte letti:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

Oltre a queste, l'istruzione [rep][rep] non interagisce direttamente con la memoria.
Si può invece aggiungere come prefisso alle altre istruzioni menzionate, _ripetendole_.

Quando sono precedute da `rep`, le istruzioni per le stringhe vengono ripetute un numero di volte pari al valore in `rcx`.
Ogni volta, il valore in `rcx` viene diminuito di `1`.
Nota che il valore in `rcx` va impostato prima di usare l'istruzione:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

Oltre a usare `rcx` come contatore, `repe` (o `repz`) e `repne` (o `repnz`) interrompono l'esecuzione se il `zero flag (ZF)` è rispettivamente azzerato o impostato:

| istruzione       | dove si può aggiungere | può interrompersi prima  |
| ---------------- | ---------------------- | ------------------------ |
| `rep`            | `movs`, `lods`, `stos` | no                       |
| `repe`,`repz`    | `cmps`, `scas`         | sì, si ferma quando ZF è 0 |
| `repne`, `repnz` | `cmps`, `scas`         | sì, si ferma quando ZF è 1 |

~~~~exercism/advanced
Sulle CPU moderne, `rep movs` e `rep stos` sono di solito opzioni veloci quando si spostano dati in blocchi grandi.
Le altre istruzioni per le stringhe, e persino `movs` e `stos` quando operano senza `rep`, sono invece di solito più lente di un semplice ciclo.
