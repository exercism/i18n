# Costruttori di stringhe

`STR` è immutabile; `FSTR` no. Usa `STR` per il testo finito e `FSTR` per il testo ancora in fase di composizione.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## Riassegna sempre il risultato

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR` cresce per **raddoppio ammortizzato**: quando finisce lo spazio, prende un nuovo array più grande, il doppio, e vi copia dentro. Quindi il risultato è di solito lo stesso oggetto, e occasionalmente uno diverso. Scrivere `b := b + x` ogni volta è corretto in entrambi i casi, ed è l'unica forma che vale la pena imparare.

Il raddoppio è ciò che rende il lavoro totale proporzionale alla lunghezza invece che al suo quadrato: le copie diventano più rare con la stessa rapidità con cui diventano più costose.

## Perché non usare semplicemente `+` su STR?

Unire con `+` un numero fisso e piccolo di pezzi è chiaro e va bene:

```sather
   return piece + " by " + composer;
```

Il problema si presenta solo in un ciclo, in cui il numero di concatenazioni non è noto quando si scrive il codice. Una guida approssimativa: se il `+` è dentro un `loop`, ricorri a `FSTR`.

## Routine utili

| Chiamata | Cosa fa |
| --- | --- |
| `b + x` | aggiunge in coda; `x` può essere `STR`, `CHAR`, `INT`, `BOOL` … |
| `b.size` | quanti caratteri finora |
| `b.str` | un `STR` finito |
| `b.clear` | lo svuota, conservando lo spazio |

## Sequenze di escape

| Scritto | È |
| --- | --- |
| `"\n"` | una nuova riga |
| `"\t"` | una tabulazione |
| `"\""` | un doppio apice |
| `"\\"` | una barra rovesciata |
