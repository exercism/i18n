# Informazioni sui caratteri

Questo è potenzialmente un argomento _vasto_!
Si potrebbe scrivere un lungo libro al riguardo, e diverse persone l'hanno fatto (cerca «unicode book» su Amazon per vedere qualche esempio).

## Una brevissima storia

Gestire i caratteri nei computer era molto più semplice nei decenni passati, quando i programmatori davano per scontato che l'inglese fosse l'unica lingua importante.
Dunque: 26 lettere, maiuscole e minuscole, 10 cifre, alcuni segni di punteggiatura, più un codice (0x07) per far suonare un campanello, e il tutto stava in 7 bit: il set di caratteri [ASCII][wiki-ascii].

Naturalmente, le persone hanno iniziato a chiedersi che fine avessero fatto à, ä e Ł, poi altre persone hanno iniziato a chiedersi che fine avessero fatto ऄ, ஹ e ญ, e i più giovani volevano le emoji 😱.
Che fare?

Per farla breve, molte persone intelligenti e pazienti hanno dovuto far parte di comitati per anni, elaborando i dettagli del set di caratteri [Unicode][web-unicode] e di codifiche come [UTF-8][wiki-utf-8], e tantissimo software ha avuto bisogno di una riscrittura _molto_ complicata.
Inoltre, sono stati introdotti molti nuovi bug.

Per evitare che _tutto_ si rompesse, il design di Unicode/UTF-8 garantisce che i primi 127 codici siano identici all'ASCII _(anche il campanello)_.

## I caratteri in Kotlin

I linguaggi progettati dopo il 2005 circa hanno l'enorme vantaggio che esisteva già uno standard Unicode ragionevolmente stabile.

Kotlin (pubblicato per la prima volta nel 2011) ha potuto dare per scontato che gli utenti usassero lingue (umane) diverse e che avessero bisogno di Unicode per esprimerle.

~~~~exercism/advanced
I [caratteri][ref-char] in Kotlin sono [`codepoints`][wiki-codepoint] a 16 bit (UTF-16), come un `char` della JVM.
Questo basta per esprimere la maggior parte degli alfabeti scritti, ma non l'intera gamma delle emoji.

Lo standard Unicode completo usa fino a sei byte (48 bit) per carattere (chiamato [`grapheme`][wiki-grapheme]).

Le `Strings` di Kotlin supportano questo standard completo usando più codepoint per carattere, quando necessario.
Per esempio, 😱 sarebbe `\uD83D` e `\uDE31`.

Purtroppo Java non ha un supporto integrato per i grapheme, e per compatibilità non ce l'ha nemmeno Kotlin.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


I letterali carattere si scrivono tra virgolette singole e sono distinti dalle stringhe, scritte tra virgolette doppie.
Questo è probabilmente ovvio per chi viene dal mondo C/C++, ma può confondere i programmatori Python e JavaScript.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

Convertire tra `Char` e `Int` è semplice:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

Il compilatore consente _alcune_ forme di aritmetica intera sui `Char`:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## Alcune funzioni per `Char`

Come sempre, ci sono [troppe funzioni][ref-char-lib] per parlarne qui, quindi questa è solo una selezione.

- Per gli alfabeti appropriati, cambia il caso con [`uppercase()`][ref-uppercase] e [`lowercase()`][ref-lowercase].
- Verifica il caso con [`isUpperCase()`][ref-isuppercase] e [`isLowerCase()`][ref-islowercase].
- Verifica il tipo di carattere con:
  - [`isLetter()`][ref-isletter], copre molti alfabeti (le categorie Lu, Ll, Lt, Lm e Lo di Unicode)
  - [`isDigit()`][ref-isdigit], nell'intervallo 0..9 (la categoria Nd di Unicode)
  - `isLetterOrDigit()`, combina le due precedenti
  - [`isWhitespace()`][ref-iswhitespace], qualsiasi carattere di spazio bianco (le categorie Cc, Zp, Zl e Zs di Unicode)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

Inoltre, le [espressioni regolari][ref-regex] (che saranno l'argomento di un concetto successivo) consentono ricerche e manipolazioni potenti.

## Conversioni tra `List` di `Char` e `String`

Per convertire una `String` in una `List` di `Char`, possiamo usare `toList()`.

Per convertire una `List` di `Char` in una `String`, c'è la funzione [`joinToString()`][ref-jointostring], che accetta un separatore (spesso la stringa vuota) come argomento.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

Nota che `joinToString()` opera su una List o un Array.
Per eseguire un _cast_ di un singolo `Char` in una stringa di un solo carattere, usa `toString()`.

```kotlin
'a'.toString() // => "a"
```

Per verificare se un carattere è presente in una `String`, o in una lista o un array di `Char`, abbiamo `in`, che corrisponde alla funzione [`contains()`][ref-contains].

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
