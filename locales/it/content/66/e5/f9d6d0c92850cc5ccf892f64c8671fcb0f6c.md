# Introduzione

Ogni volta che una funzione viene chiamata, viene creato in memoria un nuovo stack frame per memorizzare gli argomenti e le variabili locali della funzione; questo stack frame viene deallocato quando la funzione termina. Poiché Gleam usa chiamate di funzione ricorsive invece di una sintassi di ciclo, questi stack frame possono arrivare a occupare molta memoria.

Per evitare questo problema, Gleam supporta l'ottimizzazione della chiamata in coda: questa permette al compilatore di riutilizzare lo stack frame della funzione corrente se una chiamata di funzione è l'ultima cosa che la funzione fa. Di conseguenza, una funzione può chiamare se stessa infinite volte senza usare memoria aggiuntiva.

Spesso è possibile riscrivere le funzioni ricorsive non ottimizzate in funzioni ottimizzate per la chiamata in coda usando un _accumulatore_.

Un accumulatore è una variabile che viene passata insieme ai dati. Serve a trasmettere lo stato attuale dell'esecuzione della funzione, finché non si raggiunge il caso base.

Gli accumulatori dovrebbero essere inizializzati da chi scrive la funzione, non da chi la usa. Per ottenere questo, dichiara due funzioni: una funzione pubblica che accetta come argomenti solo i dati necessari e inizializza l'accumulatore, e una funzione privata che accetta anche un accumulatore.

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
