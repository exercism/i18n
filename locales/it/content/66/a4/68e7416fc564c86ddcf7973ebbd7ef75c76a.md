# Informazioni

## Introduzione

I tipi opachi sono una tecnica di incapsulamento in Elm.
Alcuni la chiamano anche occultamento delle informazioni, o occultamento dei dettagli implementativi.
Vengono usati comunemente anche per imporre la validazione, usando il pattern [Parse, dont validate][parse-dont-validate].
Per esempio, potresti avere un tipo opaco `EmailAddress`, che può contenere solo indirizzi email validi (al contrario di una `String`, che può contenere qualsiasi cosa).

## Creare un tipo opaco

I [custom types][custom-types] hanno una o più *varianti*, e il compilatore genera automaticamente una funzione per creare ogni *variante*, usando il nome della *variante*.
Queste funzioni sono l'unico modo per creare i custom types.
Il compilatore permette anche di destrutturare queste varianti.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

Per impostazione predefinita, tutto questo è interno al file / modulo, e usiamo la parola chiave `exposing` per scegliere cosa esportare.
Per creare un tipo opaco, devi semplicemente scegliere di non esportare le *varianti*.

Quando lo fai, quasi sempre devi fornire un altro modo per creare e ottenere le *varianti*, esponendo delle funzioni personalizzate.
Queste funzioni personalizzate ti permettono di applicare una certa logica quando crei e ottieni le *varianti*.
Questo nasconde i dettagli implementativi interni del modulo e significa che puoi cambiare i dettagli implementativi quanto vuoi, purché le funzioni esposte rimangano le stesse.

## Parse, don't validate

Probabilmente l'uso più comune dei tipi opachi è imporre la validazione, usando il pattern [Parse, dont validate][parse-dont-validate].
In questo pattern esponi una funzione che accetta un input con meno struttura / sicurezza di tipo di quanta ne vorresti, come una `String`, e poi ne fai il parsing per ottenere un tipo più strutturato, come `EmailAddress`, restituendo il tipo oppure un errore (di solito `Maybe` o `Result`).

Per esempio, nel codice qui sotto, per i moduli esterni è possibile creare un tipo `EmailAddress` solo usando la funzione `parseEmailAddress`, quindi quando lavori con il tipo `EmailAddress` hai la certezza che sia valido.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
