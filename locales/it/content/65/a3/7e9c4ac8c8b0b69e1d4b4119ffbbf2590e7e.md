# Introduzione

In Gleam, un'espressione `case` può essere usata per eseguire del codice in modo condizionale. Con un'espressione case, un valore può essere confrontato con uno o più _pattern_. Un esempio di questi pattern è il _pattern letterale_, che confronta un valore con un valore letterale (ad esempio `1` o `"hello"`).

Le espressioni case si scrivono con la parola chiave `case`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    1 -> "One"
  }
}
```

Anche se può sembrare un'istruzione `switch` di altri linguaggi, il pattern matching dà il meglio di sé quando si usano anche altri pattern. Uno di questi è il _pattern variabile_, che permette di assegnare un valore a una variabile. In questo esempio, alla variabile `i` sarà assegnato il valore di `number` se questo non è `0`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i -> "Non zero"
  }
}
```

In alcuni casi, potresti voler aggiungere una condizione ulteriore a un pattern. Questa è nota come _guardia_ (clausola), e si può aggiungere con la parola chiave `if`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
  }
}
```

Per motivi di prestazioni, nelle guardie sono ammessi solo gli operatori matematici e booleani di base: le altre funzioni non possono essere usate.

Nell'esempio precedente, non tutti i possibili input hanno un pattern corrispondente. Il compilatore se ne accorge e produce un errore. Questo si chiama _controllo di esaustività_. Per risolvere l'avviso, bisogna gestire tutti i casi. A questo scopo si può usare il _pattern jolly_, che è un pattern che corrisponde a qualsiasi valore:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
    _ -> "Positive number"
  }
}

// No compiler error
```

Le espressioni case confrontano un valore con ogni pattern, dall'alto verso il basso, finché non ne trovano uno corrispondente, ed eseguono la logica associata a quel pattern. L'ordine dei pattern è importante!
