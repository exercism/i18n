# golint non soddisfatto

Esiste un ottimo strumento chiamato [`golint`](https://github.com/golang/lint) che esamina il codice alla ricerca di problemi comuni e di questioni di stile.
Esegui `golint` sulla soluzione, ad esempio: `golint two_fer.go`. Ti darà alcuni suggerimenti utili.

È una buona idea controllare sempre il codice con `golint`.
Quando si scrive software Go per la produzione, molte pipeline di build falliscono automaticamente se il codice non supera `golint`.

Se vuoi ottenere molti più feedback dai linter, esiste il progetto [golangci-lint](https://github.com/golangci/golangci-lint), che ti permette di eseguire molti linter con un solo comando.
Un file di configurazione del progetto può adattare il comportamento alle esigenze del progetto.

```
> golint
%{golint}
```
