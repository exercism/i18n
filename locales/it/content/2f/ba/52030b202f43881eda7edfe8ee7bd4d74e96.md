# Introduzione

## Stringhe

### Caratteri

Una **codifica di caratteri** è una convenzione specifica usata per rappresentare elementi di testo di una lingua naturale come una sequenza di byte.
Un «elemento di testo» qui può essere qualsiasi unità che abbia significato in una lingua naturale, per esempio lettere, spazi, punteggiatura, emoji, ideogrammi, ecc.

NASM (The Netwide Assembler, l'assembler usato da questo track) supporta la definizione di dati tramite **ASCII**.

Le costanti di carattere in NASM possono essere lunghe fino a 8 byte e possono essere definite usando virgolette singole (`'`), virgolette doppie (`"`) o backtick (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

I caratteri speciali devono essere definiti tra backtick e con escape tramite `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Nota che in x86-64 non esiste un supporto integrato per alcuna codifica di caratteri come tipo distinto.
In assembly i dati sono una sequenza di byte, e l'interpretazione di quei byte come carattere, numero o qualsiasi altra cosa è lasciata al programmatore.

Per esempio, il carattere ASCII '0' è un singolo byte con il valore 48.
Quindi, memorizzare 48 in un byte è esattamente la stessa cosa che memorizzare il carattere ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Per lo stesso motivo, la manipolazione dei caratteri avviene trasformando direttamente i valori contenuti in quei byte:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### Stringhe

Una **stringa** è una sequenza di caratteri.
In assembly, di solito è implementata come un array.

È possibile dichiarare una stringa in NASM allo stesso modo in cui si dichiarerebbe un array:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Una differenza tra le stringhe e gli altri array è che NASM supporta anche la dichiarazione di stringhe senza una virgola (`,`) che separi i valori.
È anche possibile alternare valori con le virgole:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Nota che, come già accennato, i caratteri sono solo byte (o una sequenza di byte nella codifica Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Dato che ogni carattere ASCII occupa un singolo byte, ogni byte successivo in una dimensione più ampia è `0`.
Per esempio, dichiarare `'a'` come qword (8 byte) significa che il primo byte è `'a'` (`97`) e gli altri sette byte sono tutti `0`.

Per questo motivo, sono tutti equivalenti:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
In assembly, le stringhe non vengono terminate automaticamente da un carattere NUL ASCII (valore `0`).

Quando si interfaccia il codice con linguaggi di livello più alto, come il C, è responsabilità del programmatore assicurarsi che il terminatore corretto, se presente, sia aggiunto alla fine di una stringa.
~~~~

### Istruzioni per le stringhe

Dato che le stringhe sono array, puoi lavorarci allo stesso modo di qualsiasi array, dereferenziando la memoria esplicitamente:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Oltre a questo, ci sono alcune istruzioni per caricare, spostare e memorizzare valori in sequenze di byte in memoria.
Anche se vengono chiamate _istruzioni per le stringhe_, si possono usare con qualsiasi sequenza di byte in memoria, cioè con qualsiasi array.

Le tre istruzioni per le stringhe più importanti sono `lods`, `stos` e `movs`:

| istruzione | cosa fa                                                                                                           |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | carica un valore da una locazione di memoria indicata da `rsi` in `rax`                                            |
| `stos`      | memorizza un valore da `rax` in una locazione di memoria indicata da `rdi`                                         |
| `movs`      | copia un valore da una locazione di memoria indicata da `rsi` e lo memorizza in una locazione di memoria indicata da `rdi` |

Nota che queste istruzioni _non_ accettano alcun operando esplicito.
I loro operandi sono impliciti.

Come regola generale:

1. Quando il loro operando sorgente è una locazione di memoria, il suo indirizzo va memorizzato in `rsi` (`s` di source).
2. Quando il loro operando di destinazione è una locazione di memoria, il suo indirizzo va invece memorizzato in `rdi` (`d` di destination).
3. Se uno degli operandi non è una locazione di memoria, si tratta del registro `rax`.

Nota che queste istruzioni dereferenziano automaticamente gli indirizzi di memoria in base all'operazione specifica che eseguono.

Tutte possono operare con dimensioni diverse.
Alla fine viene aggiunto un suffisso per indicare questa dimensione:

| suffisso | significato | dimensione |
| :----: | ------- | :------ |
|  `b`   | byte    | 1 byte  |
|  `w`   | word    | 2 byte |
|  `d`   | dword   | 4 byte |
|  `q`   | qword   | 8 byte |

Per esempio:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

Aggiornano inoltre qualsiasi indirizzo usato, in base alla dimensione dell'operazione.
Questo aggiornamento avviene in base al valore del **direction flag (DF)**:

- Se il `DF` è azzerato, gli indirizzi vengono _aumentati_ della dimensione dell'operazione.
- Se il `DF` è impostato, gli indirizzi vengono invece _diminuiti_ della stessa quantità.

La System V ABI stabilisce che il direction flag deve essere azzerato all'ingresso di una funzione.
Quindi, _il comportamento predefinito è che la memoria venga letta/scritta in ordine crescente di indirizzi_.

L'istruzione `cld` può essere usata per azzerare il direction flag, mentre l'istruzione `std` per impostarlo:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Chi chiama si aspetta che il `DF` sia azzerato dopo il ritorno di qualsiasi funzione chiamata, come stabilito dalla System V ABI.
Se imposti il `DF`, assicurati di azzerarlo prima di `ret`.
~~~~

#### Rep

A parte queste, l'istruzione **rep** non interagisce direttamente con la memoria.
Può invece essere aggiunta come prefisso alle altre istruzioni menzionate, _ripetendole_.

Quando sono precedute da `rep`, le istruzioni per le stringhe vengono ripetute un numero di volte pari al valore in `rcx`.
Ogni volta, il valore in `rcx` viene diminuito di `1`.
Nota che il valore in `rcx` deve essere impostato prima che l'istruzione venga usata:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
Sulle CPU moderne, `rep movs` e `rep stos` sono di solito opzioni veloci quando si spostano dati in blocchi grandi.
Le altre istruzioni per le stringhe, e persino `movs` e `stos` quando operano senza `rep`, sono invece di solito più lente di un semplice ciclo.

Una panoramica più approfondita di questo argomento si trova nel [capitolo 16.9, «String instructions», di questo libro di riferimento][agner-optimization-guide].
