# Mutabilità

La mutabilità è una proprietà di un particolare binding in Rust. Un binding è immutabile o mutabile. Il valore di un binding immutabile non può essere modificato; quello di un binding mutabile sì. Per impostazione predefinita, tutti i binding sono immutabili.

## I binding

Un binding è l'associazione tra un particolare nome di variabile, così come appare nel codice sorgente, e una particolare regione di memoria, così come appare durante l'esecuzione. A rigor di termini, i binding esistono solo durante la compilazione: prima della compilazione non c'è memoria effettivamente allocata, e dopo la compilazione il codice macchina ha a che fare esclusivamente con indirizzi di memoria, non con variabili dotate di un nome.

Di solito i binding vengono creati con la parola chiave `let`. Inoltre, i binding vengono creati anche a partire dai parametri di funzione e in alcune altre circostanze.

I binding possono avere varie proprietà, la più importante delle quali è la mutabilità. Un binding mutabile è un binding per cui è lecito modificare il valore della memoria a cui è legato. Rust tiene traccia rigorosamente della mutabilità di ogni binding e la fa rispettare, e per contribuire a garantire che i programmi siano corretti rifiuta quelli che tentano erroneamente di modificare un binding che dovrebbe essere immutabile.

## Mutabilità

In pratica, la mutabilità è spesso semplice. Usando la parola chiave `mut` nella definizione del binding, ottieni la possibilità di modificarne il valore.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### Declassare da mutabile a immutabile

Un binding può sempre essere declassato da mutabile a immutabile. Questa operazione è trasparente.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### Promuovere da immutabile a mutabile

In generale, è possibile promuovere un valore da immutabile a mutabile ogni volta che l'ownership viene trasferita.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

In `(1)`, l'ownership della stringa viene trasferita da `x` a `y`, il che ci permette di promuovere il valore a mutabile.

### La mutabilità nei parametri di funzione

Ci sono due modi diversi per rendere mutabili i parametri di funzione. Il primo, e più comune, assomiglia al passaggio per riferimento in C:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

In questo esempio, la mutabilità è stata annotata esplicitamente in tre punti. Tutte e tre le dichiarazioni di mutabilità sono necessarie perché i riferimenti mutabili funzionino.
In `(2)`, il binding `x` è dichiarato mutabile. Questo binding è il proprietario di primo livello del valore.
In `(3)`, quel valore viene preso in prestito in modo mutabile, per essere passato alla funzione `increment`.
In `(1)`, viene creato un nuovo binding mutabile `n` sul riferimento appropriato.

Esiste un altro stile di mutabilità dei parametri, meno comune ma a volte comunque utile. In questo stile il valore viene posseduto, ma il binding è mutabile.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

Questo esempio richiede meno annotazioni esplicite, perché in realtà è un trasferimento di ownership con una promozione a mutabile integrata. Funziona perché `i32` è un tipo `Copy`, che copia i dati in modo trasparente.
In `(1)` dichiariamo che `increment_internally` accetta come parametro un `i32` posseduto e mutabile di nome `n`.
In `(2)` dichiariamo che `x` è un binding immutabile al valore `1`.
In `(3)` `x` viene copiato in una nuova posizione in memoria. `x` resta immutabile. `n` è mutabile.

È naturalmente possibile combinare le forme, assegnando un binding mutabile a un riferimento mutabile (`mut n: &mut i32` ecc.), ma raramente è quello che si vuole davvero.

### La mutabilità senza `let`

Diverse costruzioni di Rust (`if let`, `match`, ecc.) possono creare anch'esse dei binding. Anche questi binding possono essere mutabili.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

Questo esempio produce prima `v = Some(2)`, poi `v = None`.

## Shadowing

È possibile, e spesso idiomatico, riutilizzare un nome di variabile man mano che un particolare valore viene trasformato, ridichiarandolo con più invocazioni di `let`. Questa operazione è nota come «shadowing».

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

Tuttavia, questo non è un caso di mutabilità: i valori originali, in linea di principio, esistono ancora. Con i tipi che non sono `Drop`, il compilatore può scegliere di modificare una posizione di memoria invece di allocarne una nuova. Tuttavia non lo farà mai con un tipo `Drop`, né se il vecchio binding viene usato di nuovo.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
