# Introduzione

Come visto nel concetto [`Nothingness`][concept-nothingness], R ha vari modi per rappresentare dati assenti (`NULL`), sconosciuti (`NA`) o matematicamente non validi (`NaN`, `Inf`).
In generale, R cercherà di usarli per segnalare i problemi sul posto e continuare, senza sollevare un'eccezione.

## `stop()`

Alcuni problemi sono troppo fondamentali per lasciare che il programma continui.
In questo caso, usa `stop(msg)` per interrompere immediatamente il programma con un `Error` e stampare `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Simile a un `assert` in altri linguaggi, è un comodo wrapper per `stop()`.
I parametri sono un numero arbitrario di condizioni booleane separate da virgole; il programma continuerà solo se sono tutte `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R ha vari modi per gestire gli errori.
Si basano su Common Lisp e differiscono parecchio da molti linguaggi diffusi.

Il più semplice è racchiudere il codice potenzialmente problematico in `try()`.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()` e `message()`

Sono risposte a condizioni non fatali, ad esempio:

- Avvisare di un problema da cui il programma può almeno in parte riprendersi.
- Informare l'utente sui progressi di un programma di lunga durata.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

La funzione `suppressWarnings()` può a volte essere utile su Exercism, per evitare di confondere il test runner con output indesiderato.
