# Introduzione

## Commenti

Common Lisp permette al programmatore di scrivere dei «commenti» che il computer ignora.
I commenti su una sola riga iniziano con uno o più punti e virgola (`;`) e, occasionalmente, potresti vedere quanto segue:

```lisp
(code...) ; => value
```

Qui il commento serve a indicare quale valore viene restituito da Common Lisp dopo l'esecuzione del codice su quella riga.

È idiomatico usare un solo punto e virgola per un commento breve alla fine di una riga, due per un commento più lungo sopra una sezione di codice, tre per un commento lungo che descrive qualcosa come una funzione e quattro per un commento come un'intestazione in cima a un file sorgente.

## Cons

Tutti gli oggetti di Common Lisp sono o «atomi» (valori singoli e indivisibili) o «cons» (costruiti dalla funzione di costruzione «cons»).
Un cons è formato da due parti: il primo elemento e il resto degli elementi.
Per ragioni storiche queste due parti si chiamano `car` e `cdr`.
Quando questi cons vengono valutati come codice, il primo elemento (`car`) rappresenta la funzione che viene chiamata, mentre il resto degli elementi
(`cdr`) rappresenta gli argomenti di quella funzione:

```lisp
(<function> <arg1> <arg2> ... <argN>)
; ^ car ^  |        ^ cdr ^
```

## Espressioni

Tutto il codice di Common Lisp è fatto di S-Expressions (Symbolic Expressions). Per brevità vengono chiamate sexpr. Ogni sexpr è un atomo o un cons. Quando le S-Expressions vengono valutate, restituiscono automaticamente un valore che prende il posto dell'espressione. Quando scrivi le tue funzioni (usando `defun`), l'ultimo valore all'interno del corpo della `defun` viene restituito automaticamente:

```lisp
;; Defining a new function
(defun gimme-foo () 'foo)
;; Calling the function as an S-Expression
(gimme-foo) ; => FOO
```

## Simboli

I simboli in Common Lisp sono valori speciali che possono puntare ad altri valori o, nel caso delle _keywords_, a se stessi.
Quando Lisp valuta i simboli, questi vengono sostituiti con i valori a cui puntano:

```lisp
foo  ; => <whatever-foo-points-to>
:foo ; => :FOO
```

Nota che le keywords sono indicate da un due punti iniziale (`:`).

Il quoting, cioè l'aggiunta di `'` prima di un S-expression, dice a Lisp di non valutare quell'espressione.
Quotando `'foo` nel nostro esempio con `defun`, abbiamo evitato che Lisp tentasse di cercare (senza trovarlo) ciò a cui `FOO` doveva puntare, restituendo invece il valore `FOO` stesso.
Se `FOO` non è stato definito da nessuna parte nel programma:

```lisp
foo  ; => <ERROR! Lisp doesn't know what foo points to!>
'foo ; => FOO
```

Per ora, puoi considerarlo semplicemente come un modo per restituire simboli da una funzione, ma torneremo sul quoting ed esploreremo ulteriormente le sue implicazioni nei prossimi esercizi sui concetti.
