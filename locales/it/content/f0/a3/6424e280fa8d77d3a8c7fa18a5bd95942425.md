# Informazioni

## Gli optional

Swift usa gli [_optional_][optionals] per permettere ai programmatori di rappresentare la possibile assenza di un valore.
Optional è un tipo che può contenere un valore oppure essere [`nil`][nil], che rappresenta l'assenza di un valore.
Per usare un optional, un programma deve controllare che il valore esista davvero prima di usarlo, una volta estratto.

Qualsiasi tipo può diventare un optional aggiungendo un `?` alla fine del nome del tipo.
Quindi un intero optional ha tipo `Int?` e una stringa optional ha tipo `String?`.
Definire costanti o variabili di tipo optional e assegnare loro dei valori funziona allo stesso modo che per i valori di tipo non optional.

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

Puoi assegnare l'assenza di un valore a una variabile di tipo optional assegnandole il valore speciale `nil`.
`nil` si può usare con qualsiasi tipo optional, ma i `nil` assegnati a due tipi optional diversi non hanno lo stesso tipo e non si possono scambiare né tantomeno confrontare.

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

Nota anche che, anche se `nil` può essere assegnato a qualsiasi tipo optional, non può essere assegnato a un tipo non optional (anche se in realtà non contiene `nil`).
E a un metodo che si aspetta un tipo non optional non si può passare un tipo optional senza prima estrarlo.

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## Usare gli optional

Dato che un tipo optional non è uguale al suo tipo di base, i due tipi non si possono usare allo stesso modo.
Per esempio, `Int("123") + 1` produce un errore del compilatore: «Value of optional type 'Int?' must be unwrapped to a value of type 'Int'».
Questo perché `Int("123")` restituisce un tipo optional `Int?`, non un tipo `Int`: se la stringa non può essere convertita in un intero, il risultato sarà `nil`.
Per accedere all'`Int` risultante dalla conversione, bisogna prima «estrarre» il valore.

In Swift, il modo più comune è usare i costrutti `if-let` e `guard-let` per l'[_optional binding_][optional-binding]: controllano se il valore è `nil` e, se il valore esiste, seguono un ramo di codice in cui il valore estratto viene associato a un nome fornito, mentre ne seguono un altro se trovano `nil`.

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

Vale la pena notare che la variabile `safeNum` ha tipo `Int` e non `Int?`.
Nell'esempio qui sotto, `num` è di tipo `Int?` e `safeNum` è di tipo `Int`.

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

Questo _optional binding_ è importante perché estrae (o «rimuove») il tipo optional dal valore, permettendo di usarlo come valore non optional.
Se ti limitassi a un controllo condizionale per vedere se il valore è `nil`, il valore resterebbe comunque di tipo optional:

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

Si può usare anche l'opzione `guard-let`, nei casi in cui serve un'uscita anticipata:

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## Confrontare gli optional

Nota che, anche se il tipo di base di una coppia di optional si può confrontare usando i normali operatori di confronto, gli optional stessi non si possono confrontare.
Si può solo verificare se sono uguali.
Due optional sono uguali se sono entrambi `nil` oppure se i valori che racchiudono sono uguali all'interno dei rispettivi tipi di base.

Tuttavia, si può scrivere del codice per eseguire un confronto personalizzato tra due valori optional.
Qui sotto c'è un esempio di istruzione `switch` che restituisce `true` solo se entrambi i valori optional sono diversi da nil e il primo è minore del secondo. 
Per farlo usa l'_optional pattern_ `varName?`, che corrisponde solo agli optional diversi da nil e associa il valore contenuto nell'optional al nome `varName`.

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## Coalescenza di nil

Esiste un'altra opzione per estrarre il valore: usare un [valore di fallback][fallback] quando è presente `nil`.
Si può fare con l'_operatore di coalescenza di nil_, `??`. Supponendo che `x` sia un `Int?`, se si scrive `let y = x ?? 0`, Swift controllerà se `x` è `nil`.
Se non lo è, estrarrà `x` e assegnerà il valore estratto a `y`; se invece `x` _è_ `nil`, assegnerà `0` a `y`.

Dato che `x ?? y` è solo una forma abbreviata di `x != nil ? x! : y`, se `x` non è nil, l'espressione `y` non viene valutata affatto.

Infine, vale la pena notare che l'operatore di coalescenza di nil è associativo a destra, il che può portare a risultati sorprendenti per chi non lo sa.

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

Puoi leggere di più sull'operatore di coalescenza di nil in [A Tour of Swift: Nil-Coalescing Operator][nil-coalescing].
