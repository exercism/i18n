# Introduzione

## Applicazione parziale

In Elm tutte le funzioni sono [curried][currying]: se chiami una funzione senza passare tutti gli argomenti, ottieni una nuova funzione.

Il risultato di questa operazione si chiama [applicazione parziale][partial-application]: non stai passando tutti gli argomenti alla funzione, ma ne stai applicando solo alcuni.

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

L'applicazione parziale applica sempre gli argomenti in ordine.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## L'operatore pipe (`|>`)

Scrivere `x |> f` è esattamente come scrivere `f x`. Un esempio concreto: `"5" |> String.toInt` equivale a `String.toInt "5"`.

A prima vista non sembra molto utile, ma si chiama [operatore pipe][pipe-operator] perché ti permette di scrivere codice «a pipeline».

Per esempio, supponiamo di avere una funzione sanitize che trasforma l'input dell'utente in numeri interi:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Possiamo riscriverla così:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

In questo modo evitiamo di usare le parentesi e vediamo le funzioni nell'ordine in cui vengono applicate (prima `String.trim`, poi `String.toInt`), il che aiuta la leggibilità.

Esiste anche un [operatore pipe inverso `(<|)`][reverse-pipe-operator].
Scrivere `f <| x` è esattamente come scrivere `f x`.
Anche questo, a prima vista, non sembra molto utile, e sicuramente non è usato quanto l'operatore pipe, ma in alcune situazioni aiuta a evitare le parentesi.

## Composizione di funzioni / stile point free

L'operatore [`(>>)`][forward-composition] ha il tipo `(a -> b) -> (b -> c) -> (a -> c)` e crea una funzione di tipo `a -> c` componendo due funzioni compatibili di tipo `a -> b ` e `b -> c`.
Per farlo, prende l'output (di tipo `b`) della prima funzione e lo usa come primo argomento della seconda (che deve essere dello stesso tipo `b`).
La funzione creata prenderà lo stesso input (di tipo `a`) della prima funzione e restituirà qualunque `c` restituisca la seconda funzione.

Un esempio concreto è `String.trim >> String.toInt`.
`String.trim` accetta una stringa come unico parametro, quindi è questo che prenderà la funzione creata.
`String.toInt` restituisce un `Maybe Int`, quindi è questo che restituirà la funzione creata.
`String.trim` restituisce una `String`, che `String.toInt` accetta come parametro, quindi l'esempio compila.

Ora possiamo riscrivere la nostra funzione `sanitize` così:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Nota che non usiamo più il parametro `input` che vedi nell'esempio originale, anche se la funzionalità è identica.
Questo modo di creare funzioni che non fanno riferimento ai loro parametri si chiama «Point Free Style».
Il vantaggio di questo stile è che il codice è più conciso; lo svantaggio è che può essere più difficile da capire, soprattutto per i principianti.

Vale la pena ricordare che in Elm tutte le funzioni sono curried, quindi `String.length >> max` compila.

- L'operatore [`(>>)`][forward-composition] ha il tipo `(a -> b) -> (b -> c) -> (a -> c)`.
- `String.length` ha tipo `String -> Int`, che è la parte `(a -> b)`, quindi `a` è `String` e `b` è `Int`.
- `max` ha tipo `Int -> Int -> Int`, che è la parte `b -> c`.
- `b` è `Int`, quindi `max` viene applicata parzialmente e `c` è il risultato di questa applicazione parziale (`Int -> Int`).
- Quindi il tipo di `String.length >> max` è `String -> (Int -> Int)`.
- Quindi `((String.length >> max) "123") 2` restituisce `3`, perché `"123"` ha lunghezza 3, che è maggiore del 2 dell'argomento `Int`.

## Progettazione delle funzioni

Per scrivere facilmente codice elegante in Elm, conviene mettere la struttura dati principale come ultimo parametro delle funzioni.
Tutte le funzioni comuni della libreria standard fanno così, come `List.map` (la cui firma di tipo è qui sotto).

```elm
map : (a -> b) -> List a -> List b
```

Qui possiamo vedere che l'ultimo parametro della funzione `map` è `List a` e che restituisce `List b`, quindi la struttura dati principale (`List`) è l'ultimo parametro.

Questo permette di scrivere codice elegante a pipeline, come qui sotto.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Rende anche comodo usare la composizione di funzioni e lo stile point free, come alternativa al pipeline.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

La composizione di funzioni permette anche di ridurre questo esempio a una singola chiamata a `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
