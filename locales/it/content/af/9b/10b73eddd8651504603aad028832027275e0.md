# Test

Per eseguire i test devi eseguire `cmake -G` e poi usare il comando di build adatto alla tua piattaforma.
Istruzioni dettagliate su come fare si trovano nella pagina [Eseguire i test][cpp-tests-instructions] per il C++ su exercism.org.

## Superare i test

Quando inizi un nuovo esercizio in locale, i file sono configurati in modo che venga eseguito solo il primo test.
Fai in modo che quel primo test venga compilato, collegato e superato seguendo le [tre regole dello sviluppo guidato dai test][three-laws-of-tdd].
Crea solo la struttura necessaria, dichiarando namespace, funzioni, classi e così via, per soddisfare gli errori del compilatore e far fallire il test.
Poi scrivi solo il codice necessario per far passare il test.
Una volta fatto, togli il commento al test successivo spostando la riga `if defined(EXERCISM_RUN_ALL_TESTS)` dopo il test successivo.

Guarda l'esempio qui sotto, tratto dall'esercizio Bob (file `bob_test.cpp`, riga 15):

```diff
-#if defined(EXERCISM_RUN_ALL_TESTS)
TEST_CASE("shouting")
{
    REQUIRE("Whoa, chill out!" == bob::hey("WATCH OUT!"));
}
+#if defined(EXERCISM_RUN_ALL_TESTS)
```

Spostare questa riga dopo il test successivo può causare errori di compilazione, perché potrebbero essere usate nuove costruzioni che non hai ancora dichiarato o definito.
Ancora una volta, correggi gli errori di compilazione in modo minimale per ottenere un test che fallisce, poi modifica il codice in modo minimale per far passare il test, riorganizza l'implementazione per renderla più leggibile ed espressiva e infine passa al test successivo.

Cerca di usare le funzionalità standard del C++17 invece di scrivere a mano algoritmi o funzionalità di basso livello.
