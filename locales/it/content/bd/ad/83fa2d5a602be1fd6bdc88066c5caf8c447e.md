# Introduzione

## Ciclo di vita delle risorse

[concept:csharp/resource-cleanup]() usa l'interfaccia `IDispose` per segnalare che la risorsa di un oggetto, o un'altra parte dello stato del programma, doveva essere rilasciata o reimpostata quando l'oggetto non serviva più (e che affidarsi al garbage collector non l'avrebbe ottenuto né avrebbe fornito il livello di controllo richiesto), e che il metodo `IDisposable.Dispose()` era il posto naturale per questo tipo di operazioni di pulizia.

Esiste un'altra costruzione, il blocco `using`, che permette, dal punto di vista di chi chiama, di raccogliere in un'unica istruzione tutta la gestione del ciclo di vita delle risorse.

```csharp
using (var file = new File("my_secrets"))
{
    file.WriteSecret("xxxxxxx");
}
```

Nell'esempio qui sopra, le risorse del file system associate a `file` vengono restituite al sistema operativo all'uscita dal blocco `using`.

Perché il meccanismo funzioni, la variabile nell'istruzione using deve essere un tipo di riferimento che implementa l'interfaccia `IDisposable` e deve rilasciare le risorse o reimpostare lo stato del programma nel suo metodo `Dispose()`.

C# 8 introduce un perfezionamento di questo meccanismo. Un'istruzione using può essere collocata all'inizio di un blocco.

```csharp
using var drawingResource = some_provided_or_new_object;
try
{
    drawingResource.DrawSomething();
}
catch (Exception)
{
    throw;
}
```

Gli sviluppatori Java potrebbero riconoscere in questo un analogo del meccanismo di _gestione automatica delle risorse_ introdotto in Java 7.
