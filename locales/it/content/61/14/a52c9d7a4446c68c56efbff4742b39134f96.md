# Introduzione

Le espressioni regolari sono un modo estremamente versatile per _trovare corrispondenze_ nelle stringhe, usando un linguaggio specifico di dominio (DSL) progettato proprio per questo scopo.

Molte funzionalità delle regex sono integrate in Base R e potresti vedere esempi in codice più vecchio.

Per il codice nuovo, si raccomanda _vivamente_ di usare la libreria [`stringr`][web-stringr].

Come osservato nel [concetto Strings][concept-strings], `stringr` ha una buona documentazione, di solito scritta dall'autore o dagli autori del pacchetto.

- Un [sito di riferimento][web-stringr]
- Un [cheatsheet][cheat-stringr].
- Un [capitolo sulle stringhe][book-strings] ed un [capitolo sulle regex][book-regex] in «R for Data Science».

Molte delle funzioni già discusse nel concetto [`Strings`][concept-strings] sono pensate per fare ricerche con le regex per impostazione predefinita.

Abbiamo mantenuto il concetto Strings relativamente semplice, cercando le corrispondenze solo su stringhe letterali, ma al suo posto si può usare qualsiasi pattern regex.

Formalmente, in R una regex si crea chiamando [`regex()`][ref-regex].
Per comodità, le funzioni di `stringr` trattano qualsiasi stringa di pattern come una regex.
Nell'esempio qui sotto, il primo `str_replace_all()` è zucchero sintattico per la seconda versione:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

Il [cheatsheet][cheat-stringr] è una guida utile: tutte le funzioni con un argomento `pattern` (stampato in rosso) accettano una regex, e la pagina 2 riassume la sintassi delle regex.

Nota che la funzione [`regex()`][ref-regex] può comunque essere importante se devi sovrascrivere i valori predefiniti, come la distinzione tra maiuscole e minuscole o il locale.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

Molti codici regex contengono una barra rovesciata, come la `\s` usata sopra.
Nelle stringhe R normali, `\` va protetta raddoppiandola, da cui `"\\s"`.

Le barre rovesciate possono moltiplicarsi e diventare confuse, quindi nei casi complessi può essere utile usare le [stringhe raw][book-raw].

Per impostazione predefinita, la sintassi per definire una stringa raw è `r"( )"`, ma sono ammessi altri delimitatori.
Dato che le parentesi tonde `( )` e le parentesi quadre `[ ]` sono entrambe comuni nella sintassi delle regex (per i gruppi di cattura e i gruppi di opzioni), le parentesi graffe `{ }` potrebbero essere una buona scelta.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## Individuare le corrispondenze

Ecco alcune domande e le funzioni che possono aiutarti a rispondere.

Alcuni esempi usano `fruit`, un vettore di 80 nomi di frutta incluso in `stringr` per fare pratica.

_Una stringa contiene una corrispondenza?_
`str_detect()`, oppure `str_starts()` e `str_ends()` per evitare di usare le ancore `^` o `$`.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_Restituire solo le stringhe che contengono una corrispondenza?_
Usa `str_subset()` per ottenere le stringhe, `str_which()` per ottenere gli indici.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_Quante corrispondenze ci sono in ogni stringa?_
Usa `str_count()`.

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_Dov'è la corrispondenza?_
`str_view()` per un uso interattivo, più in generale `str_locate()` o `str_locate_all()`.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## Catture

Spesso vogliamo sapere _cosa_ corrisponde.
Per farlo, si includono gruppi di cattura tra parentesi all'interno della regex.

È possibile fare riferimento alle catture all'interno della stessa regex, usando `\1`, `\2`, ecc.
Per esempio, per trovare coppie di lettere ripetute:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

Con una sintassi simile, le catture si possono usare nelle stringhe di sostituzione:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

Per raccogliere le corrispondenze e riutilizzarle dopo, usa la funzione `str_match()` se ti serve solo la prima corrispondenza, oppure `str_match_all()` per tutte.

I gruppi di cattura tendono a produrre un output complicato in qualsiasi linguaggio.
L'approccio di R (_che, come sfida aggiuntiva, è anche vettorizzato_) è generare una matrice da `str_match()`: una riga per ogni stringa di input, la colonna 1 con l'intera stringa corrispondente e le colonne restanti con i vari gruppi di cattura.

Usare gruppi con nome può essere un vantaggio, perché diventano i nomi delle colonne nella matrice dei risultati.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

Non abbiamo detto molto sulle matrici in questo syllabus, ma esiste un [documento del concetto][concept-matrices-arrays] che puoi consultare.
Le matrici non si integrano bene con l'ecosistema Tidyverse, nonostante facciano parte di Base R da molto tempo.

In breve: tratta le matrici come vettori con 2 indici, nell'ordine `[rows, cols]`.
Lascia vuoto uno dei due indici per ottenere l'intera riga o colonna.

Quando prendi una singola riga `r` con `m[r,]` o una singola colonna `c` con `m[,c]`, il valore restituito viene appiattito in un vettore, per impostazione predefinita.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

Inevitabilmente, `str_match_all()` produce un output con una struttura ancora più complessa:

- Il risultato è una lista, con un elemento per ogni stringa di input.
- Se c'è una sola stringa di input, estrai l'output dalla lista con l'indicizzazione `[[1]]`, come descritto nel [concetto Lists][concept-lists].
- Ogni elemento è una matrice, con le colonne come per `match()`.
- Ogni riga della matrice è una cattura riuscita.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

Naturalmente, le corrispondenze possono fallire.
In quel caso il risultato sarà il valore speciale `NA`.
Preparati a verificarlo, come descritto nel [concetto Nothingness][concept-nothingness].

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
