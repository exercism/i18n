# Booleani

`BOOL` può assumere uno di due valori: `true` e `false`.

```sather
   ready : BOOL is
      return true;
   end;
```

## Confronto

| Operatore | Chiede | Esempio |
| --- | --- | --- |
| `=` | uguali? | `age = 13` |
| `/=` | diversi? | `age /= 13` |
| `<` | minore di | `age < 13` |
| `<=` | minore o uguale a | `age <= 13` |
| `>` | maggiore di | `age > 13` |
| `>=` | maggiore o uguale a | `age >= 13` |

Funzionano sui numeri, mentre `=` e `/=` funzionano anche sulle stringhe.

## I tre operatori

| Operatore | Scritto | Vero quando |
| --- | --- | --- |
| and | `a and b` | entrambi sono veri |
| or | `a or b` | almeno uno è vero |
| not | `~a` | `a` è falso |

`and` e `or` sono **a corto circuito**: `a and b` non guarda nemmeno `b`
quando `a` risulta falso, perché la risposta è già stabilita. Allo stesso
modo, `a or b` si ferma se `a` è vero. Questo conta quando il lato destro
è costoso da valutare, o darebbe problemi se venisse eseguito.

## Restituire direttamente un confronto

Una routine il cui unico compito è porre una domanda dovrebbe restituire la
domanda, non scegliere una risposta con un condizionale:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

Scrivere `if age >= 13 then return true else return false end` richiede tre
righe per dire quello che il confronto diceva già, e ogni lettore esperto
se ne accorgerà.

## Precedenza

`~` ha la precedenza più alta, poi `and`, poi `or`. Quindi

```sather
~a and b or c
```

significa `((~a) and b) or c`. Le parentesi non costano nulla da scrivere, e
valgono la pena ogni volta che un lettore dovrebbe altrimenti ricordare
quell'ordine per seguire la riga.
