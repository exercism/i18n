# Informazioni

Ruby è un linguaggio dinamico e fortemente tipizzato.
Nei linguaggi dinamici, il tipo di una variabile o di un oggetto viene risolto a runtime, il che significa che il suo valore o il suo tipo possono essere cambiati fino all'ultimo momento (quando viene analizzato dall'interprete).
E che cosa intendiamo per «fortemente tipizzato»?
Una volta che conosciamo il tipo di una variabile o di un oggetto, Ruby è rigido su ciò che puoi farci, per esempio:

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**Ma**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

Ricorda, in Ruby tutto è un oggetto.
Persino le classi sono istanze della classe `Class`.

Per esempio:

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

Questo significa che possiamo anche definire classi in questo modo:

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

Infine, tieni presente che l'oggetto `Integer` contiene valori che possono essere definiti come una o più cifre (consecutive) e i suoi metodi supportano molti degli [operatori matematici][integers-docs].

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
Nella documentazione si fa spesso riferimento ai metodi di istanza usando una sintassi come `Class#method_name`, mentre i metodi a livello di classe o di modulo sono indicati come `Class::method_name`.
Il `::` è chiamato _Scope Resolution Operator_, ovvero la costante o il metodo a livello di classe o di modulo a cui si fa riferimento.
Lo incontrerai nella documentazione di Ruby, nelle mailing list e in altre aree di supporto.
Scoprirai invece che nei nostri testi facciamo riferimento ai metodi di classe e di modulo come `ClassName.method_name` o `ModuleName.method_name`.
~~~~
