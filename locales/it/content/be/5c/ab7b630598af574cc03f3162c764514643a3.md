# Test

Ogni esercizio fornisce i test unitari e una ricetta di build per Make.
L'implementazione la fornisci tu.

Ogni file di test è pensato per essere collegato all'implementazione, così da produrre un eseguibile da console che esegue i test.
Eseguire l'eseguibile dei test stampa un messaggio per ogni test che fallisce e segnala un codice di uscita non nullo quando i test falliscono.

Per affrontare un esercizio:

* Crea la build iniziale con Make
* Per ogni test unitario:
  * Rimuovi la riga `TEST_IGNORE()`.
  * Risolvi gli errori di compilazione in modo che il test possa fallire.
  * Implementa solo quanto basta per far passare il test.
  * Riorganizza l'implementazione per migliorarne la leggibilità, ridurre le duplicazioni e così via.

## Compilare ed eseguire i test

Ogni esercizio include un file `makefile` insieme a un `.c` con i test unitari.
Non dovresti aver bisogno di modificare il makefile.
Il makefile fornito presuppone che l'implementazione sia composta da un file di intestazione (`.h`) e da un file sorgente (`.c`) con il nome dell'esercizio.

Per esempio, l'esercizio `bob` si aspetta un'implementazione in `bob.h` e `bob.c`.
Per gli esercizi con trattini nel nome, si presuppone che i file sorgente usino gli underscore, quindi `word-count` si aspetta `word_count.h` e `word_count.c`.
Puoi decidere che l'implementazione è abbastanza semplice da stare interamente nel file di intestazione, nel qual caso puoi omettere il file `.c`.

**Crea i file di implementazione iniziali prima di eseguire Make.**
Se non hai i file `bob.h` e `bob.c` quando esegui Make per l'esercizio `bob`, Make genererà un errore che segnala che i file non sono stati trovati.
**Questi file possono essere vuoti, ma devono esistere.**

### Compila il codice

Il modo più semplice per compilare il codice è usare `make` dalla riga di comando (CLI).
Su Linux la CLI è disponibile in bash o simili, su MacOS usa Terminal.
Su Windows 10 è disponibile Windows Subsystem for Linux (WSL) Bash.

Per farlo, supponendo che la directory corrente sia la cartella dell'esercizio:

```console
$ make
```

Questo compilerà il codice ed eseguirà i test.

Il `makefile` include anche una build che controlla alcuni errori comuni relativi alle perdite di memoria ed agli accessi agli array fuori dai limiti.
Per eseguire questi controlli, usa il comando seguente dalla riga di comando:

```console
$ make memcheck
```

### Pulizia

Per fare pulizia dopo una build, puoi dire a `make` di eliminare tutto l'output della build, eseguibile compreso:

```console
$ make clean
```

#### Alternativa di build su MacOS

Su MacOS puoi anche usare Xcode.
Per compilare il codice, seleziona _Build_ dalla barra degli strumenti.
