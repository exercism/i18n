# Appendice alle istruzioni

## Pro e contro di `from_quote`

Questo esercizio definisce una funzione `from_quote` nel tipo `Card`. Questo permette di scrivere codice come questo:

```roc
card : Card
card = "Q"
```

Questo codice chiama implicitamente `Card.from_quote("Q")` in fase di compilazione. Questo può potenzialmente velocizzare il programma, dato che non deve gestire il parsing a runtime, e garantisce che le carte rifiutate da `from_quote` vengano intercettate in fase di compilazione invece che a runtime. Inoltre, rende il codice bello e leggibile. Per esempio, ecco uno dei test di questo esercizio:

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

Tuttavia, chi legge questo codice potrebbe pensare che la funzione `simulate_game` accetti un record contenente due `List(Str)`, quando in realtà è un record contenente due `List(Card)`. Questo può portare a confusione ed errori. Per questo motivo, potresti preferire il formato leggermente più lungo ma più esplicito: `"Q".Card`, che chiama anch'esso `from_quote` in fase di compilazione.

Nei tuoi programmi, potresti preferire usare `from_str`:

```roc
Card := { ... }.{
    from_str : card_str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

Puoi anche chiamare `from_str` (o qualsiasi altra funzione pura) in fase di compilazione, come qui:

```roc
Ok(card) = Card.from_str("Q")
```

Nota: mettere questa definizione al livello superiore la fa eseguire in fase di compilazione (dato che la funzione è pura e il suo input è noto in fase di compilazione). All'interno di una funzione, puoi usare `from_str` a runtime.
