# Introduzione a comandi e argomenti

Questo track non riguarda come usare bash come shell interattiva.
Riguarda imparare a scrivere programmi usando bash, il linguaggio di programmazione.

Un programma bash, o _script_, è una sequenza di comandi memorizzata in un file.
bash (l'eseguibile) legge il file ed esegue i comandi in ordine.

## Lo shebang

La prima riga di uno script è di solito una _direttiva dell'interprete_, nota anche come _hashbang_ o _shebang_:

```bash
#!/usr/bin/env bash
```

Quando il sistema operativo esegue un file non binario, ne legge la prima riga.
Se la riga inizia con `#!`, il kernel la usa per determinare quale interprete deve eseguire il file.
Il `#!` deve trovarsi all'inizio assoluto del file, senza spazi né righe vuote prima.

Qui `env` cerca in `PATH` l'eseguibile `bash`.
Potresti anche vedere la forma più semplice `#!/bin/bash`, che fissa la posizione dell'interprete; la forma con `env` è più portabile.

~~~~exercism/note
Non farti ingannare da script o esempi su Internet che usano `/bin/sh` come interprete.
**`sh` non è `bash`!**
Bash è «compatibile con sh» e può eseguire la maggior parte degli script `sh`, ma alcune funzionalità di bash si romperanno o si comporteranno in modo inatteso in `sh`.
~~~~

## I commenti

Una riga che inizia con `#` è un _commento_, e bash la ignora.
Un commento può anche seguire un comando sulla stessa riga: tutto ciò che va dal `#` alla fine della riga viene ignorato.
I commenti esistono per le persone che leggono lo script.

## Parole e argomenti

Bash legge i comandi dal suo input (che di solito è un terminale o un file).
Ogni riga di input che legge viene trattata come un _comando_, cioè un'istruzione da eseguire.
(Ci sono alcuni casi avanzati, come i comandi che occupano più righe, di cui parleremo più avanti.)

Bash suddivide ogni comando in **parole** delimitate da caratteri di spazio bianco (spazi e tabulazioni).
La prima parola è il nome del _comando_ da eseguire.
Tutte le parole rimanenti diventano _argomenti_ di quel comando (opzioni, nomi di file, ecc.).

Un comando può essere un _builtin_ di bash, come `echo`, oppure un programma _eseguibile_, come `head`, `awk` o `sed`.

## Il comando `echo`

`echo` stampa i suoi argomenti separati da un singolo spazio e termina con un a capo:

```bash
echo flour sugar eggs
```

produce:

```text
flour sugar eggs
```

La quantità di spazio bianco tra gli argomenti non ha importanza:

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

Chiamare `echo` senza argomenti stampa una riga vuota.

## Le opzioni sono solo argomenti

Molti comandi accettano _opzioni_ che ne cambiano il comportamento.
Per bash un'opzione non ha nulla di speciale: è una parola come le altre, separata dalle parole vicine da spazio bianco.
È il comando stesso a decidere come interpretare i suoi argomenti.
Per convenzione, le opzioni iniziano con un `-`.

Il comando `head` stampa le prime righe di un file.
Dato un file `list.txt`:

```bash
head -n 2 list.txt
```

Bash suddivide questa riga in quattro parole:

| Parola     | Ruolo                                               |
| ---------- | --------------------------------------------------- |
| `head`     | il comando da eseguire                              |
| `-n`       | un'opzione, che dice a `head` di contare le _righe_ |
| `2`        | il valore dell'opzione `-n`                         |
| `list.txt` | il file da leggere                                  |

Bash passa le ultime tre parole a `head` senza modificarle.
È `head` a capire che `-n` è seguito da un numero e che la parola rimanente è un file.

Poiché è lo spazio bianco a separare le parole, conta dove lo metti.
`head -n 2` dà a `head` due argomenti (`-n` e `2`), mentre `head -n2` gliene dà uno solo (`-n2`).
Molti comandi accettano entrambe le forme, ma dipende dal comando.
A bash non importa: divide solo la riga in parole.

## Mettere tra virgolette gli argomenti

Le [virgolette][Quotes] raggruppano le parole in un _unico argomento_.
Lo spazio bianco dentro le virgolette viene conservato, e i caratteri di virgoletta stessi non fanno parte dell'argomento:

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

Se un argomento, come un nome di file, contiene spazio bianco, mettilo tra virgolette:

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## Eseguire uno script

Per eseguire uno script, passalo come argomento al comando `bash`:

```bash
bash myscript
```

Usata così, la riga `#!` è solo un commento.
Stai dicendo al sistema operativo come eseguire il file.

In alternativa, contrassegna il file dello script come eseguibile ed eseguilo come qualsiasi altro programma:

```bash
chmod +x myscript
./myscript
```

Ora il sistema operativo usa la riga `#!` per determinare quale interprete usare.
