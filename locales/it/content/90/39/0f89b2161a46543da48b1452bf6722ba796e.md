# Le basi di Unison

## Termini e funzioni

I termini e le funzioni sono le unità di base per scrivere un programma Unison.

Un «termine» è quello che chiamiamo un valore statico. Si definisce con `name = expression`, eventualmente preceduto da una firma di tipo nella forma `name : MyType`. Unison supporta l'inferenza di tipo, quindi nelle definizioni semplici potresti vedere la firma di tipo omessa.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Le funzioni in Unison hanno la forma `myFunctionName argument1 argument2 = myImplementation`: iniziano con il nome della funzione, seguito da argomenti separati da spazi.

```
getMax a b = Nat.max a b
```

Le funzioni possono includere facoltativamente una firma di tipo. L'ultimo tipo a destra è sempre il tipo restituito finale della funzione, e ogni argomento è separato dalla freccia di funzione `->`.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Per chiamare una funzione, scrivi il suo nome seguito dai suoi argomenti, separati soltanto da spazi.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Quando chiami una funzione, Unison cerca di trattare come suo argomento quello che si trova immediatamente alla sua destra. Non sempre però questo produce l'ordine di valutazione desiderato.

Diciamo che vogliamo ottenere il valore `1` dalla seguente espressione

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Così com'è scritta, `shouldBe1` vale `0`, perché l'ordine implicito di applicazione delle funzioni è `getMax 1 10`, che vale `10`, e poi `10 - 10`, che vale `0`.

Puoi usare le parentesi per raggruppare l'espressione nell'ordine di operazioni desiderato.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Espressioni di controllo

Unison offre un modo per valutare rapidamente il codice, chiamato «espressione di controllo». Un'espressione di controllo inizia con il simbolo `>` ed è seguita dall'espressione da valutare. Le espressioni di controllo si possono scrivere in qualsiasi file con suffisso `.u`. Quando salvi il file, dovresti vedere nella console di Unison Codebase Manager (UCM) a cosa viene valutata l'espressione. Dove possibile, in questa documentazione cercheremo di mostrare un'espressione con il suo output previsto, dopo averla valutata in un'espressione di controllo.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Funzioni su più righe

Le funzioni Unison su più righe usano l'indentazione o i blocchi `let` per delimitare il codice, ovvero quello che si chiama «scope lessicale».

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Tutto ciò che sta allo stesso livello di indentazione condivide lo stesso scope, ed è per questo che possiamo fare riferimento alla variabile `newBeginning` nell'ultima riga.

## Namespace e istruzioni `use`

I namespace sono il modo in cui raggruppiamo e organizziamo le funzioni di Unison. Puoi pensarli come analoghi alle «directory». Offrono struttura e raggruppamento logico.

Puoi portare le funzioni di un namespace nello scope con un'istruzione `use`.

Diciamo che stai scrivendo una funzione che usa i valori `List` di Unison. Sai che ti serviranno funzioni come `List.map` e `List.flatMap`, dove `List` è il namespace e `map` e `flatMap` sono funzioni. Per non ripeterti, potresti scegliere di portare tutto dal namespace `List` nello scope lessicale della tua funzione, così:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

La riga `use List` disambigua i riferimenti a `map` e `flatMap`. Puoi leggere di più sulle [istruzioni `use` qui][use-statements].

## La libreria standard di Unison

La libreria standard di Unison si chiama `base`. Se hai seguito la guida rapida e hai creato un codebase in locale, la libreria standard dovrebbe essere stata scaricata automaticamente. Puoi consultare online la documentazione della libreria standard su [Unison Share][unison-share-base].

## Commenti e letterali di documentazione

I commenti in Unison sono una caratteristica un po' insolita. Quando scrivi codice Unison, puoi creare nel tuo file con suffisso `.u` del testo che non viene interpretato, con la seguente sintassi:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Tuttavia_, poiché il codice Unison viene salvato come hash del suo albero sintattico astratto e non come file testuali sul file system, i commenti che sono «decorazioni» testuali di una determinata funzione o di un determinato termine Unison nel file non possono davvero essere salvati e riprodotti per la condivisione. Se vuoi aggiungere un'informazione al tuo termine Unison in un modo che venga conservato, così che altri possano leggerlo e capirlo, puoi usare un letterale di documentazione.

La documentazione è un valore di prima classe nel linguaggio di programmazione Unison. Questo significa che un elemento `Doc` può essere assegnato a un valore, passato come valore a una funzione o restituito come valore di una funzione. Gli elementi dei letterali di documentazione si aprono e si chiudono con doppie parentesi graffe. Ecco come potremmo usare l'elemento `Doc` come commento.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
