# Contratti

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| Clausola | Dice | Di chi è la colpa se viene violata |
| --- | --- | --- |
| `pre` | cosa deve valere all'ingresso | di chi chiama |
| `post` | cosa vale all'uscita | della routine |

Entrambe le clausole accettano un `BOOL`, ed entrambe possono usare gli argomenti della routine e gli attributi dell'oggetto. `post` può usare anche `result`, il valore che viene restituito.

## assert

All'interno del corpo di una routine, `assert` afferma qualcosa che deve essere vero in quel punto:

```sather
      assert load <= limit;
```

Viene verificato con la stessa opzione usata per gli altri.

## Invarianti di classe

Una classe può affermare qualcosa che è vero per ogni suo oggetto tra una chiamata e l'altra:

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

Viene verificato all'ingresso e all'uscita di ogni routine pubblica, quando i controlli sono attivi.

## Come attivarlo

| Flag | Cosa verifica |
| --- | --- |
| `-chk` | tutto: pre, post, assert, invariant, bounds, arithmetic |
| `-chk_no` | niente |

Tieni presente che `-chk_pre` da solo *non* attiva il controllo delle precondizioni in questo compilatore; è `-chk` che funziona. Una violazione stampa la routine e la riga di codice sorgente, e ferma il programma. Non è un'eccezione: `protect` non la cattura.

La prassi abituale è sviluppare e testare con `-chk` e rilasciare senza, così i controlli non costano nulla nel programma rilasciato. Ne vale la pena solo se i test esercitano davvero i percorsi.

## Che cosa rende buono un contratto

Indica quello che la routine richiede, non come funziona:

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

Un `post` che ripete il corpo non insegna niente a nessuno:

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## Ereditarietà

Un sottotipo può indebolire un `pre` e rafforzare un `post`, accettare di più e promettere di più, ma mai il contrario: altrimenti il codice scritto per il supertipo si romperebbe. È per rendere verificabile questa regola che esistono i contratti.
