# Sezione sui commenti

Go ha [ottime linee guida](https://golang.org/doc/effective_go.html) su come scrivere i commenti. Esiste un formato standard da usare per i commenti di documentazione, che lo strumento `godoc` può poi trasformare automaticamente in una documentazione ben fatta.

Il commento del pacchetto dovrebbe iniziare con la parola `Package`, seguita dal nome del pacchetto, così:

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

Per le funzioni esportate, i metodi, le costanti e le variabili di pacchetto, il commento dovrebbe iniziare con il nome e proseguire con una frase verbale:

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

La wiki [CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences) specifica inoltre che i commenti di documentazione dovrebbero essere frasi complete, che terminano con un punto.

Oltre ad ottimizzare la leggibilità, seguire queste raccomandazioni migliora l'aspetto del codice negli [strumenti di documentazione di Go](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/) come [godoc.org](http://godoc.org), `godoc` e `go doc`.

Prenditi un momento per leggere la sezione sui commenti di documentazione nella guida di stile ufficiale, [Effective Go](https://golang.org/doc/effective_go.html), per capire il ragionamento che sta dietro a queste scelte.
