# Debug

YS ha una funzione `DBG` integrata che può essere utile per fare debug del codice
della soluzione.
Accetta un numero qualsiasi di argomenti e li stampa sulla console, su stderr.
Restituisce l'ultimo argomento, quindi puoi usarla inline nel codice.


Puoi usare l'operatore inline `.>`, che è una scorciatoia per `.DBG()`.

Ecco un file di codice di esempio:

```yaml
# file: program.ys

!YS-v0

defn do-it(nums):
  x =: 5

  DBG: -'my vars' x nums

  nums: .map(\(_ * x)).>
        .reverse().>
        .map(str).>
        .join(' - ')

say: do-it(3 .. 5)
```

Quando esegui questo codice con `ys`, vedrai il seguente output:

```txt
>>>
"my vars"
5
(3 4 5)
<<<
>>>(15 20 25)<<<
>>>(25 20 15)<<<
>>>("25" "20" "15")<<<
25 - 20 - 15
```


## Compilation

Un altro modo comune per capire un problema è guardare il codice Clojure in cui
viene compilato il codice YS.

Puoi farlo eseguendo l'interprete a riga di comando `ys` con il flag `-c`.

Ecco come appare il file `program.ys` qui sopra quando viene compilato:

```clojure
$ ys -c program.ys
(defn do-it [nums]
 (let [x 5]
  (DBG "my vars" x nums)
  (join
   (DBG
    (+map
     (DBG (reverse (DBG (+map nums (fn [& [_1]] (mul+ _1 x))))))
     str))
   " - ")))
(say (do-it (rng 3 5)))
```

Puoi vedere chiaramente come l'operatore `.>` sia stato compilato nella chiamata
alla funzione `DBG`.
