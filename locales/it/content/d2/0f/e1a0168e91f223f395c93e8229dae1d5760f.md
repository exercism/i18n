# Introduzione

In Gleam, un `Iterator` è simile a un array: è una collezione ordinata di valori, in cui tutti i valori sono dello stesso tipo. Si differenzia da un array perché è pigro: non conserva tutti i suoi valori in memoria in una sola volta, ma li calcola man mano che servono.

Questo è utile quando si lavora con sequenze molto grandi o addirittura infinite, perché permette di lavorarci anche quando non abbiamo abbastanza memoria libera per conservarle tutte in una volta.

Il modulo `gleam/iterator` definisce il tipo `Iterator` e anche le funzioni per lavorare con gli iteratori.

Molte delle funzioni per gli array esistono anche per gli iteratori, come `map`, `filter` e `take`. Queste funzioni restituiscono iteratori, quindi non eseguono alcun lavoro finché l'iteratore non viene consumato.

```gleam
let iter = 
  [1, 2, 3, 4, 5, 6]
  |> iterator.from_list
  |> iterator.filter(fn(x) { x > 2 })
  |> iterator.take(2)

// No work has been done yet as the iterator has not been consumed

// Consume the iterator and collect the values into a list
iterator.to_list(iter)
// -> [3, 4]
```

La funzione `unfold` può essere usata per creare iteratori a partire da una funzione che viene chiamata ripetutamente per produrre il valore successivo della sequenza.

Qui la funzione `unfold` viene usata per creare un iteratore che produce la sequenza di Fibonacci:

```gleam 
iterator.unfold(#(0, 1), fn(pair) {
  let x = pair.0 + pair.1
  iterator.Next(element: x, accumulator: #(pair.1, x))
})
|> iterator.take(6)
|> iterator.to_list
// -> [1, 2, 3, 5, 8, 13]
```

La sequenza qui è infinita, quindi la funzione `take` viene usata per renderla finita prima di raccogliere i valori in un array. Se `to_list` viene chiamata su un iteratore infinito, il programma continuerà a essere eseguito finché non esaurisce la memoria e va in crash.
