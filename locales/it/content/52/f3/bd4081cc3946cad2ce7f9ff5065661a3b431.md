# Informazioni

Factor divide l'I/O su stream in due livelli. Il livello inferiore è l'API a *stream esplicito*: ogni parola riceve lo stream come argomento. Il livello superiore è l'API a *stream implicito*: parole brevi, di una sola riga, che agiscono sullo stream di volta in volta associato. Entrambi i livelli poggiano sullo stesso [protocollo][stream-protocol]: le parole del livello superiore si limitano a cercare lo stream implicito e a inoltrare la chiamata.

## Le parole dello stream esplicito

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents` consuma tutto; `stream-lines` consuma e divide in corrispondenza delle interruzioni di riga; `stream-readln` restituisce una riga alla volta (o `f` alla fine dello stream).

## Le parole dello stream implicito

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

Queste sono le parole I/O di tutti i giorni. Cercano lo stream di input o di output corrente nelle variabili dinamiche `input-stream` / `output-stream` e inoltrano la chiamata. Ecco perché reindirizzare `print` verso una stringa è solo questione di associare `output-stream` per la durata di una quotation.

## Costruttori di stream inclusi

| parola            | vocabolario          | cosa costruisce                 |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | legge una stringa letterale     |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | raccoglie ciò che viene scritto in una stringa |
| `<file-reader>`   | [`io.files`][io.files]           | legge un file con una codifica  |
| `<file-writer>`   | [`io.files][io.files]`           | scrive un file con una codifica |

Tutti e quattro producono oggetti disposable: estendono `disposable` di `destructors`, quindi i combinatori `with-…` qui sotto li rilasciano all'uscita.

## Associazione con ambito

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

Ognuna apre uno stream, lo associa come input o output implicito per la quotation interna e lo rilascia all'uscita, anche se la quotation lancia un'eccezione. Sono i combinatori di distruzione di `boatswains-bilge`, specializzati per gli stream.

`with-string-writer` è una variante particolarmente pulita: costruisce automaticamente un `<string-writer>` nuovo, esegue la quotation con quel writer come output implicito e restituisce la stringa accumulata. L'intero schema «catturare l'output di una quotation» è una sola parola.

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## Perché lo stream implicito?

L'associazione delle variabili dinamiche è il motivo per cui `print` funziona in un programma che non sa se viene eseguito in modo interattivo, in un file di log o in un buffer di test catturato. Basta sostituire l'associazione una volta e ogni parola che chiama `print` fa la cosa giusta, senza bisogno di ricablare nulla. È l'inversione che ti offre il livello superiore.

Per *implementare* uno stream, cioè definire una tua classe che si innesta nel protocollo, vedi il concetto `streams` (insegnato in `telegraphers-tape`).
