# Informazioni

Il tipo `Option` è il meccanismo del linguaggio F# per gestire valori che possono esistere o meno.
Offre un'alternativa sicura dal punto di vista dei tipi all'uso di `null`, comune in altri linguaggi per gestire questo genere di valori.
È usato in molte funzioni della libreria standard di F#, quindi capirlo è essenziale per usare la libreria standard in modo efficace.

## Vantaggi dell'uso del tipo `Option`

* __Sicurezza in fase di compilazione__: rendendo esplicita nel sistema dei tipi la presenza o l'assenza di un valore, il compilatore può garantire che il caso «nessun valore» venga gestito, prevenendo così un'ampia categoria di bug che potrebbero verificarsi con i null.

* __Sicurezza in fase di esecuzione__: invece di usare `null`, F# usa `None` per rappresentare l'assenza di un valore, rendendo impossibile che si verifichi una `NullReferenceException`.

* __Impone una gestione esplicita__: il sistema dei tipi richiede che il codice gestisca esplicitamente sia il caso `Some value` sia il caso `None`, rendendo il codice più robusto e prevedibile.

* __Funziona con il pattern matching__: gli `Option` si integrano perfettamente con l'idioma del pattern matching di F#, offrendo un modo pulito e sicuro per destrutturare e gestire il valore se esiste, oppure per eseguire un'azione diversa se non esiste.

## Utilizzo

Il tipo `Option` è un tipo generico (che ha un tipo sottostante).  
I valori di tipo `Option` sono `Some value`, che rappresenta un valore specifico, oppure `None`, che rappresenta l'assenza di valore.

La funzione seguente mostra come creare un valore di tipo `Option`:

```fsharp
let keepIfPositive (a: int) : int option = if a > 0 then Some a else None
```

~~~~exercism/note
`T option` è la sintassi postfissa equivalente a `Option<T>`; le due forme sintattiche sono intercambiabili.
Tuttavia, secondo la Guida di stile di F#, per i tipi Option è preferibile la notazione postfissa (vedi [sezione della Guida di stile di F# sulla formattazione dei tipi e delle annotazioni di tipo](https://learn.microsoft.com/en-us/dotnet/fsharp/style-guide/formatting#for-types-prefer-prefix-syntax-for-generics-foot-with-some-specific-exceptions)). 
~~~~

Le funzioni di ricerca sono un caso d'uso tipico di `Option`. 
Per esempio, la funzione `List.tryFind` restituisce `Some index` quando l'elemento è nella lista (dove `index` è la posizione del valore cercato nella lista), oppure `None` quando l'elemento non è nella lista.

## Leggere il contenuto di un valore di tipo Option

Il modo idiomatico per leggere un valore di tipo `Option` è tramite il pattern matching, come mostrato nell'esempio seguente:

```fsharp
// Returns "Hello, <name>!" if the name is provided; otherwise returns "Hello, you!"
let sayHello (optionalName: string option): string = 
    match optionalName with
    | Some name -> "Hello, " + name + "!"
    | None -> "Hello, you!"

sayHello (Some "Matthieu")
// --> "Hello, Matthieu!"

sayHello None
// --> "Hello, you!"
```

## Estrarre il contenuto di un Option con valori predefiniti

Gli `Option` si possono «unwrap» (convertire nel tipo che contengono) fornendo un valore predefinito con la funzione `Option.defaultValue`. 
Questo è particolarmente utile quando vuoi assicurarti che il valore non sia `None`.
Per esempio:

```fsharp
Option.defaultValue "" (Some "F#")
// --> "F#"

Option.defaultValue 0 None
// --> 0
```

## Altre funzioni nel modulo `Option`

Il modulo `Option` include anche funzioni che corrispondono a quelle disponibili per liste, array, sequenze ed altri tipi di collezione, come `Option.map`, `Option.iter`, `Option.forall` e `Option.count`. 
Queste funzioni permettono di trattare gli `Option` come una collezione di zero o un elemento.
