# Istruzioni

Inizi il tuo primo giorno in un'azienda australiana chiamata "Doctor Data", specializzata nel recupero di informazioni.
Hai superato il colloquio di lavoro grazie alla tua conoscenza del C++ e delle [sonde di von Neumann][van-neumann-probes].
Dato che hai visto molti file di test, il tuo nuovo capo vuole che tu ricrei i rispettivi file sorgente e di intestazione a partire da del codice di test che l'azienda ha recuperato di recente.

In questo esercizio ricreerai dei file perduti.
Al momento il contenuto dei file è un insieme di dati inutilizzabili.

~~~~exercism/note
Il flusso di lavoro di questo esercizio sui concetti è molto simile alla struttura degli esercizi di pratica di Exercism.
Il testo di introduzione dell'esercizio è solo una parte della specifica.
Il file di test è la tua guida definitiva per risolvere un dato problema.

Se ricevi errori di compilazione, potrebbero sparire una volta che avrai affrontato tutte le attività e i test.
~~~~

Hai quattro attività, tutte legate al recupero del codice perduto nei file di intestazione e sorgente.

## 1. Prova a estrarre i primi indizi

Dai un'occhiata a due righe recuperate dai file di test:

```cpp
heaven::Vessel bob{"Robert Johansson", 1};
heaven::Vessel will{"Riker", 2, star_map::System::BetaHydri};
```

Il tuo occhio attento ha riconosciuto all'istante un namespace `heaven`.
Vedi anche che deve esserci una classe chiamata `Vessel`.
A quanto pare, il costruttore può essere chiamato con due o tre argomenti.
Il primo argomento sembra essere di tipo `string`, il secondo è un numero.
È possibile inizializzare la classe `Vessel` con un terzo argomento.
Il terzo argomento proviene da un namespace `star_map`.
È un enumeratore di tipo `System`.
Hai persino ottenuto una delle enumerazioni: `BetaHydri`.

Prepara i file sorgente e di intestazione con le informazioni che hai scoperto.
Ti servono due namespace: `heaven` e `star_map`.
Il namespace `heaven` ha una classe `Vessel`, che può essere chiamata con due o tre argomenti.
L'enum `System` va inserito nel namespace `star_map` e ha un'enumerazione `BetaHydri`.
Tieni d'occhio le altre enumerazioni, così da poter aggiornare continuamente l'enum `System`.

## 2. Trova altri dettagli

Scopri altre righe dal test:

```cpp
heaven::Vessel bob{"Robert Johansson", 1};
REQUIRE(bob.current_system == star_map::System::Sol);
REQUIRE(bob.generation == 1);
heaven::Vessel bob5 = bob.replicate("Mario");
REQUIRE(bob5.current_system == star_map::System::Sol);
REQUIRE(bob5.generation == 2);
```

Le righe di test appena trovate rivelano un'altra funzione membro della classe `Vessel`: `replicate`.
Questa funzione riceve una stringa e restituisce un'altra istanza di `Vessel`.
Ti fai un'idea del valore predefinito del terzo argomento del costruttore a partire dall'attività precedente.
Vedi anche due variabili membro pubbliche della classe `Vessel` e la specifica della funzione membro `replicate`.

Aggiungi la funzione `replicate` e le variabili membro pubbliche `current_system` e `generation` ai file di intestazione e sorgente.

## 3. Esamina il funzionamento interno

Trovi altre righe interessanti nei file di test recuperati:

```cpp
heaven::Vessel bob6{"Homer", 3, star_map::System::EpsilonEridani};
REQUIRE(bob6.busters == 0);
bob6.make_buster();
REQUIRE(bob6.busters == 1);
bool success = bob6.shoot_buster();
REQUIRE(success);
REQUIRE(bob6.busters == 0);
success = bob6.shoot_buster();
REQUIRE_FALSE(success);
```

A quanto pare, la classe `Vessel` ha una variabile membro `busters`, che può essere modificata con le due funzioni membro della classe `make_buster` e `shoot_buster`.
Finché non emergono altre informazioni, ipotizzi che la funzione `make_buster` restituisca `void`.
Dato che c'è un test per il valore restituito di `shoot_buster`, supponi che la funzione restituisca un `bool`.

Aggiungi le due funzioni e la variabile membro alla classe `Vessel`.
Continua a cercare altri enumeratori di `System`.

## 4. Completa il quadro

Mentre scorri i file di test, trovi solo due sezioni di codice ancora scoperte:

```cpp
heaven::Vessel bob1{"Bob", 1, star_map::System::AlphaCentauri};
heaven::Vessel marv{"Marvin", 2, star_map::System::DeltaEridani};
heaven::Vessel milo{"Milo", 3, star_map::System::DeltaEridani};
heaven::Vessel howie{"Howard", 4, star_map::System::Omicron2Eridani};

REQUIRE("Bob" == heaven::get_older_bob(bob1, marv));
REQUIRE(heaven::in_the_same_system(marv, milo));
REQUIRE_FALSE(heaven::in_the_same_system(marv, howie));
```

Vedi due funzioni che non sono membri della classe `Vessel`, dato che non vengono chiamate su un'istanza.
`get_older_bob` confronta due istanze di `Vessel` e restituisce una `string`.
`in_the_same_system` confronta due istanze di `Vessel` e restituisce un `bool`.

Implementa le ultime funzioni mancanti a partire dalle righe recuperate qui sopra.
