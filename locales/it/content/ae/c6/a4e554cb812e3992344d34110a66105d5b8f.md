# Introduzione ai cicli

Bash ha due forme di ciclo:

* Ripetere alcuni comandi _per ogni elemento di una lista di elementi_,
* Ripetere alcuni comandi _finché una condizione è vera (o falsa)_.

## Il ciclo for

Per iterare su una lista di elementi, usiamo il ciclo `for`.

```bash
for varname in words; do COMMANDS; done
```

`words` viene espanso tramite la suddivisione in parole e l'espansione dei nomi di file (di cui abbiamo parlato nel concetto di [Quoting][quoting]).
Ogni parola viene assegnata a turno alla `varname`, e i COMMANDS vengono eseguiti.

Ecco alcuni esempi che mostrano quando il ciclo for può essere utile

* Eseguire alcuni comandi su un gruppo di file.

    ```bash
    # source all the bash library files in the current directory
    for file in ./*.bash; do
        source "$file"
    done
    ```

* Eseguire un comando su ciascuno dei parametri di uno script o di una funzione.

    ```bash
    for arg in "$@"; do
        echo "argument: ${arg}"
    done
    ```

* Eseguire un comando per ogni parola separata da spazi nell'output di un comando.

    ```bash
    for i in $(seq 10); do
        echo "${i} squared is $((i * i))"
    done
    ```

    Più avanti vedremo alcuni avvertimenti su questo stile.

### Il ciclo for aritmetico

Bash ha anche un ciclo aritmetico.
Risulterà in qualche modo familiare a chi conosce altri linguaggi di programmazione.

```bash
for ((INITIALIZATION; CONDITION; INCREMENT)); do COMMANDS; done
```

Le doppie parentesi in bash rappresentano un contesto aritmetico (vedremo di più sull'aritmetica di bash in un concetto successivo).
L'esempio di sopra con `seq` si può scrivere così

```bash
for ((i = 1; i <= 10; i++)); do
    echo "${i} squared is $((i * i))"
done
```

### Quando non usare il for

[Non leggere righe con `for`][bashfaq1].

Questo è un anti-pattern che vedrai spesso: iterare sull'output di `cat`.

```bash
for line in $(cat some.file); do 
    do_something_with "$line"
done
```

Questo è sbagliato per 2 motivi.

1. La sostituzione di comando non è tra virgolette, quindi è soggetta alla suddivisione in parole.
   Per impostazione predefinita, la suddivisione in parole divide sugli _spazi bianchi_, non solo sulle interruzioni di riga.
   Questo ciclo for itera sulle **parole** del file, non sulle righe.
2. La sostituzione di comando non è tra virgolette, quindi è soggetta all'espansione dei nomi di file.
   Ogni parola del file verrà confrontata come pattern glob.

Come abbiamo visto nel concetto di [Quoting][quoting], la suddivisione in parole si può controllare con la variabile `IFS`, e l'espansione dei nomi di file si può disattivare.
Ma di solito è una soluzione fragile.
`for` non è il metodo giusto per iterare sulle righe di un file.
Il modo idiomatico per leggere un file è usare un ciclo `while`.

## I cicli while

Usa `while` per ripetere una sequenza di comandi _finché_ una condizione è vera.

```bash
while CONDITION_COMMANDS; do COMMANDS; done
```

Come con `if` (come abbiamo visto nel concetto di [Conditionals][conditionals], non esiste una sintassi speciale per CONDITION_COMMANDS.
Lo stato di uscita della lista di comandi determinerà "true" o "false".

## Controllare i cicli

Il comando `break` esce dal ciclo.
Il controllo riprende con il comando che segue il terminatore `done` del ciclo.

Il comando `continue` salta all'iterazione successiva del ciclo.

## Leggere le righe di un file

Come accennato, un ciclo while è il modo idiomatico per leggere un file. 

```bash
while IFS= read -r line; do
    do_something_with "$line"
done < some.file
```

* Il contenuto del file viene fornito come input al ciclo con la redirezione `<`.
* Il comando `read` restituisce "true" se riesce a leggere una riga completa dal suo input.
  Quando l'input è esaurito, oppure se l'ultima riga non termina con un carattere di nuova riga, `read` restituisce "false".
  * Il modo _davvero_ idiomatico per leggere le righe di un file, anche se l'ultima riga non termina con un carattere di nuova riga, è

    ```bash
    while IFS= read -r line || [[ -n "$line" ]]; do ...
    ```

* L'opzione `-r` dice a `read` di non sostituire le sequenze con barra rovesciata: una barra rovesciata è solo un carattere normale.
* `IFS=` assegna la stringa vuota a IFS solo per la durata del comando read.
  Questo disattiva temporaneamente la suddivisione in parole, così che gli spazi bianchi all'inizio o alla fine della riga di testo in arrivo vengano preservati.

## Until

Il costrutto `until` ripete una sequenza di comandi finché una condizione è **falsa**.
Il ciclo si ripete _finché_ la condizione non diventa vera.

```bash
until CONDITION_COMMANDS; do COMMANDS; done
```

È raro usare `until`.
È più comune usare un ciclo «while not».

```bash
while ! CONDITION_COMANDS; do ...
```

## I cicli infiniti

A volte vuoi ripetere all'infinito.
Ecco due modi per farlo.

1. un ciclo while con una condizione che ha sempre uno stato di uscita di successo

    ```bash
    while true; do ...
    ```

2. un ciclo for aritmetico con espressioni vuote

    ```bash
    for ((;;)); do ...
    ```

## Do-while

Non esiste un costrutto do-while esplicito, ma si può ottenere lo stesso effetto:

```bash
while true; do
    COMMANDS

    if END_CONDITION; then
        break
    fi
done
```
