# Informazioni

I [Custom Type][custom-types] in Elm rappresentano un numero fisso di casi denominati. Ogni valore corrisponde esattamente a uno di questi casi. In altri linguaggi e contesti sono noti come _tipi somma_, _unioni discriminate_, _unioni etichettate_ e _tipi di dati algebrici_.

Ogni caso di un'unione discriminata può avere dei dati associati, e casi diversi possono avere tipi di dati diversi. Se nessun caso ha dati associati, l'unione discriminata è simile a quella che in altri linguaggi viene di solito chiamata _enumerazione_ (o _enum_).

Un Custom Type si definisce con la parola chiave `type` e richiede pochissima sintassi. È una delle tecniche più importanti nella programmazione in Elm: serve a far corrispondere esattamente i valori possibili nel codice ai valori validi nella vita reale, il che non lascia spazio a dati non validi e rende [impossibile rappresentare nel codice gli stati impossibili][impossible-states].

```elm
-- Custom Type without associated data
type Season
    = Spring
    | Summer
    | Autumn
    | Winter

-- Custom Type with associated data
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Per creare un valore per un caso specifico puoi riferirti al suo nome (`Spring`), quando il caso è definito nello stesso modulo o è importato con la sintassi `import SeasonModule exposing (Season(..))`, oppure al suo nome completo (`Season.Spring`), quando è importato con la sintassi `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

I Custom Type, come tutto in Elm, hanno l'_uguaglianza strutturale_: due valori dello stesso caso e con gli stessi dati (facoltativi) sono equivalenti.

Il modo preferito per lavorare con i Custom Type è il [pattern matching][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
