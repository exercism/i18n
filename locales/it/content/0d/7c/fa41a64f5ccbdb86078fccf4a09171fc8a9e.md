# Descrizione

Qualsiasi valore può essere un errore. `throw` (in `kernel`) segnala; l'effetto sullo stack della parola corrente viene abbandonato e il controllo risale fino al `recover` più vicino che lo racchiude.

```factor
[ 0 1 / ] [ "div by zero" prepend ] recover
```

`ERROR:` è una parola di parsing che definisce una classe di tuple di errore *e* una parola costruttrice in un colpo solo:

```factor
ERROR: not-found path ;
! defines:
!   TUPLE: not-found path ;
!   : not-found ( path -- * ) \ not-found boa throw ;
!   : not-found? ( object -- ? ) … class predicate
```

Così ogni errore personalizzato ottiene una classe unica, un costruttore comodo per lanciarlo e un predicato di classe (`name?`) con cui verificare gli errori catturati:

```factor
[ "/missing" not-found ]
[ dup not-found? [ path>> "missing: " prepend ] [ drop "other" ] if ]
recover
```

Per una pulizia in stile finally, vedi `cleanup` in `continuations`. Per le condizioni riavviabili, vedi `condition`.
