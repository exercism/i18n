# Introduzione alle virgolette

Un consiglio che i nuovi programmatori bash si sentiranno ripetere più e più volte:

> Metti tra virgolette le tue variabili!

Come mai?

Quando espandi una variabile (come `$name`) vuoi quasi sempre usare il _valore_ della variabile come un'unica stringa (o un unico numero).
Non vuoi che il valore venga gestito inaspettatamente come due o più stringhe separate.

## Le virgolette

Mettere tra virgolette è il meccanismo principale per assicurarsi che un pezzo di testo sia trattato come una sola parola.
Esistono due tipi principali di virgolette.

### Virgolette doppie

Le virgolette doppie consentono l'espansione dei parametri, l'espansione aritmetica e la sostituzione di comandi al loro interno.

```bash
echo "This is bash version $BASH_VERSION"
```

Puoi includere una virgoletta doppia letterale all'interno di una stringa tra virgolette doppie facendola precedere da una barra rovesciata.

```bash
echo "She said \"Let me teach you about bash.\""
```

### Virgolette singole

Le virgolette singole _non consentono_ alcuna espansione al loro interno.

```bash
echo 'This is bash version $BASH_VERSION'
# ...^..................................^
# prints exactly: This is bash version $BASH_VERSION
```

_Non è possibile_ incorporare una virgoletta singola all'interno di una stringa tra virgolette singole.

## L'importanza delle virgolette

Cosa c'è che non va in `echo $name`, esattamente?

Quando la shell analizza una riga di codice, esegue [diversi tipi di espansione][expansions], in ordine.
Due delle ultime espansioni sono la _suddivisione in parole_ e l'_espansione dei nomi di file_.

### Suddivisione in parole

Qualsiasi risultato dell'espansione dei parametri, della sostituzione di comandi o dell'espansione aritmetica _che non si è verificato all'interno di virgolette doppie_ è soggetto alla «suddivisione in parole».
La shell prende il risultato espanso e lo divide su qualsiasi sequenza di caratteri presente nel valore di `$IFS`.
Per impostazione predefinita, si tratta di spazio, tabulazione e nuova riga.

Possiamo vederlo in azione con un ciclo della shell:

```bash
sentence="The quick brown fox jumps."
i=0
for word in "$sentence"; do echo "$((++i)) $word"; done
# ..........^.........^
```
produce
```none
1 The quick brown fox jumps.
```

Ma senza virgolette:

```bash
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
produce
```none
1 The
2 quick
3 brown
4 fox
5 jumps.
```

Vediamolo con un valore diverso di `$IFS`:

```bash
csv="first,second,third"
IFS=","
for word in $csv; do echo "$word"; done
```
produce
```none
first
second
third
```

#### Disattivare la suddivisione in parole

Una tecnica per disattivare la suddivisione in parole consiste nell'impostare `$IFS` su una stringa vuota

```bash
sentence="The quick brown fox jumps."
IFS=    # or explicitly, IFS=""
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
produce
```none
1 The quick brown fox jumps.
```

Tuttavia, lasciare le variabili senza virgolette non è consigliato, a meno che tu non disattivi anche l'espansione dei nomi di file.
Vedremo come farlo qui sotto.

### Espansione dei nomi di file

I pattern "glob" servono a esprimere un pattern conciso che corrisponde a un insieme di file.
Ad esempio, potresti trovare tutti i file Markdown in una directory con `*.md`.
[I pattern glob][glob] esistono fin dall'invenzione di Unix.

I caratteri jolly glob sono:

* `*` corrisponde a zero o più caratteri qualsiasi,
* `?` corrisponde esattamente a un carattere qualsiasi,
* `[...]` corrisponde esattamente a un carattere dell'insieme di caratteri elencati tra le parentesi quadre.

   ~~~~exercism/advanced
   <details><summary>
   Ci sono molti dettagli sugli insiemi di caratteri.
   Clicca qui per mostrarli.
   </summary>

    * `[abc]` corrisponde esattamente a un carattere che sia una `a`, una `b` o una `c`.
        * per includere una parentesi quadra chiusa letterale nell'espressione, rendila il primo carattere dopo la parentesi aperta (dopo un `^` facoltativo)
            * `[][]` è un insieme di caratteri che corrisponde a una parentesi quadra chiusa o a una aperta.
            * oppure eseguine l'escape con una barra rovesciata: `[[\]]`
    * `[x-y]` corrisponde esattamente a un carattere che sia nell'_intervallo_ da `x` a `y`
        * per includere un trattino letterale in un insieme di caratteri, deve essere il primo carattere dopo la parentesi aperta (dopo un `^` facoltativo) oppure l'ultimo carattere prima della parentesi chiusa.
            * `[-xy]` o `[xy-]` corrispondono ciascuno esattamente a un carattere che sia un `-`, una `x` o una `y`
            * oppure eseguine l'escape con una barra rovesciata: `[x\-y]`
        * si possono specificare più intervalli, ad esempio `[0-9A-Fa-f]` corrisponde a una cifra esadecimale
    * `[^abc]` corrisponde esattamente a un carattere che **NON** sia una `a`, una `b` o una `c`,
    * `[^x-y]` corrisponde esattamente a un carattere che **NON** sia nell'intervallo da `x` a `y`
    * `[[:character_class:]]` corrisponde a un carattere che appartiene alla classe di caratteri indicata dal nome «character_class»
        * le classi di caratteri disponibili sono: 
            * `lower`: lettere minuscole
            * `upper`: lettere maiuscole
            * `alpha`: lettere
            * `digit`: cifre
            * `alnum`: lettere e cifre
            * `space`: spazi bianchi
            * `blank`: spazi bianchi orizzontali (spazio e tabulazione)
            * `xdigit`: cifre esadecimali
            * `word`: caratteri ammessi in un identificatore (lettere, numeri, underscore)
            * `punct`: punteggiatura
            * `cntrl`: caratteri di controllo
            * `graph`: caratteri "visibili"
            * `print`: caratteri visibili più lo spazio
        * possono essere combinate:
            * la classe `[[:alpha:]]` è composta da `[[:lower:][:upper:]]`
            * la classe `[[:alnum:]]` è composta da `[[:alpha:][:digit:]]`
            * la classe `[[:word:]]` è composta da `[[:alnum:]_]`
            * l'underscore (ottale 137) è sia `[[:word:]]` sia `[[:punct:]]`
            * la classe `[[:graph:]]` è composta da `[[:alnum:][:punct:]]`
            * la classe `[[:print:]]` è composta da `[[:graph:] ]`: solo lo spazio (ottale 040), non qualsiasi altro spazio bianco.
   </details>   
   ~~~~

#### Iterare su un elenco di file

Puoi iterare su un elenco di file con un ciclo `for`

```bash
for file in *.csv; do
    do_something_with "$file"
done
```

Nota che la variabile `"$file"` è tra virgolette.
Il pattern glob può restituire file che contengono spazi nel nome.
Dobbiamo mettere tra virgolette la variabile, così che il comando `do_something_with` riceva esattamente un argomento, il nome del file.

#### I pattern glob non sono espressioni regolari

I pattern glob **non sono** espressioni regolari.

* corrispondono esattamente a un carattere
   * regex `.`
   * glob `?`
* corrispondono a zero o più caratteri
   * regex `.*`
   * glob `*`
        * il pattern glob `.*` significa «corrisponde a un nome di file in cui il primo carattere è un punto letterale seguito da zero o più caratteri qualsiasi».
* corrispondono a uno o più caratteri
   * regex `.+`
   * glob `?*`
* gli insiemi di caratteri delle regex e quelli dei glob si comportano allo stesso modo.

#### Virgolette ed espansione dei nomi di file

Ci sono momenti in cui vuoi sopprimere l'espansione dei nomi di file.
La gestione dell'input dell'utente è uno di questi.
Considera questo frammento di codice

```bash
read -p "Enter something: " user_input
echo $user_input
```

Se l'utente digita un asterisco (`*`), cosa verrà stampato? 
L'elenco dei file nella directory corrente.
Probabilmente non è quello che vuoi fare.

Un altro esempio è passare pattern come argomenti a programmi che si aspettano dei pattern.
Il programma `tr` è spesso usato per la manipolazione di testo. Per convertire in minuscolo il valore di una variabile, puoi fare così

```bash
var="My Puppet"
echo "$var" | tr '[:upper:]' '[:lower:]'
```
produce
```none
my puppet
```

Un errore comune è dimenticare di mettere tra virgolette gli argomenti di `tr`: `tr [:upper:] [:lower:]`

~~~~exercism/caution
Perché è un problema? 
I pattern glob senza virgolette verranno espansi nell'elenco dei file che corrispondono.
Supponi che la persona che usa il tuo script abbia dei file chiamati `p`, `u` e `w` nella directory corrente:

```bash
touch p u w
var="My Puppet"
echo "$var" | tr [:upper:] [:lower:]
```

Questo produce un errore!

Il pattern `[:upper:]` senza virgolette corrisponde a uno qualsiasi tra `:`, `u`, `p`, `e` o `r`.
Il pattern `[:lower:]` senza virgolette corrisponde a uno qualsiasi tra `:`, `l`, `o`, `w`, `e` o `r`.
Bash trova i file `p` e `u` per il primo pattern, e il file `w` per il secondo, e `tr` viene chiamato così

```bash
echo "$var" | tr p u w
```

E questo è il numero sbagliato di argomenti per `tr`.
~~~~

#### Disattivare l'espansione dei nomi di file

Puoi usare il comando [`set`][set] per disattivare l'espansione dei nomi di file.

```bash
echo *      # prints a list of files
set -f      # disable filename expansion
echo *      # prints a literal asterisk
set +f      # enable filename expansion
```

#### Controllare l'espansione dei nomi di file

Ci sono diverse impostazioni per il comando builtin [`shopt`][shopt] che controllano come funziona l'espansione dei nomi di file.
Un paio interessanti sono:

* `shopt -s nocaseglob`: esegue la corrispondenza senza distinzione tra maiuscole e minuscole
* `shopt -s extglob`: attiva i pattern estesi
* `shopt -s nullglob`: se nessun file corrisponde, sostituisce il pattern con nulla.
   Il comportamento predefinito è lasciare il pattern al suo posto come stringa letterale.
