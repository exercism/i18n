# Istruzioni

Fai parte dell'helpdesk IT e vuoi rendere il sistema di ticketing più efficiente e fornire statistiche al tuo manager.

Un ticket ha uno stato (new, in progress...), un creatore (identificato da un nome utente e da un ID dipendente), può essere assegnato a un dipendente IT e contiene una cronologia di commenti.

Ecco quattro attività che miglioreranno l'attuale sistema di ticketing.

## 1. Rilevare i commenti vuoti

I commenti vuoti ingombrano l'interfaccia e non portano alcuna informazione: vuoi eliminarli.

Definisci una funzione ausiliaria `emptyComment` che prende una coppia utente/commento e restituisce `True` per i commenti vuoti.

Usa la destrutturazione per estrarre l'utente e il commento direttamente nell'argomento della funzione. Ignora l'utente, dato che quell'informazione non ti serve.

```elm
emptyComment ( User "Alice", "" )
-- => True
```

## 2. Contare il numero di commenti del creatore

Il tuo manager vuole avere statistiche sul coinvolgimento degli utenti nel processo di gestione dei ticket.
Ti chiede di verificare quanti commenti sono stati aggiunti dal creatore del ticket.

Definisci `numberOfCreatorComments`, che prende un ticket e restituisce il numero di commenti aggiunti dal creatore del ticket.

Usa la destrutturazione nell'argomento della funzione per estrarre il record dal tipo `Ticket`, insieme ai campi del record che ti servono.
Poi destruttura `createdBy` in un binding `let`, così da poter contare i commenti rilevanti.
Usa le funzioni di `List` per fare il conteggio e usa la destrutturazione nell'argomento di una funzione anonima per separare la coppia utente/commento.

```elm
numberOfCreatorComments
numberOfCreatorComments
    (Ticket
        { status = Closed
        , createdBy = ( User "Chiaki", 1 )
        , assignedTo = Nothing
        , comments = [ ( User "Chiaki", "Never mind, fixed it." ) ]
        }
    )
-- => 1
```

## 3. Rilevare i ticket assegnati al Dev Team

Alcuni ticket devono essere escalati ad Alice, Bob o Charlie del Dev Team.
È importante tenerli d'occhio per assicurarsi che facciano progressi.

Definisci una funzione ausiliaria `assignedToDevTeam` che verifica se un ticket è assegnato a uno dei membri del Dev Team.

Usa la destrutturazione nell'argomento della funzione per estrarre il record dal tipo `Ticket` e anche il campo che ti serve.
Poi usa un'unica istruzione `case` per verificare se il ticket è assegnato ad Alice, Bob o Charlie, usando il pattern matching ricorsivo per estrarre i loro nomi utente e il pattern matching letterale per riconoscerli.

```elm
assignedToDevTeam
    (Ticket
        { status = InProgress
        , createdBy = ( User "Bill", 2 )
        , assignedTo = Just (User "Alice")
        , comments = [ ( User "Bill", "What's an 'undefined'?" ) ]
        }
    )
-- => True
```

## 4. Assegnare i ticket ai dipendenti IT

A volte diversi ticket devono essere riassegnati ad altri dipendenti IT.

Definisci una funzione `assignTicketTo` che ti aiuti a farlo. La funzione riceve due argomenti: un utente a cui assegnare il ticket e un ticket.
Se lo stato del ticket è `New`, assegnalo al nuovo utente e cambia lo stato in `InProgress`.
Per gli altri stati, riassegna semplicemente il ticket ai nuovi utenti, tranne per i ticket con stato `Archived`, che non vanno modificati affatto.

Usa la destrutturazione nell'argomento della funzione per estrarre il record dal tipo `Ticket` e anche il campo che ti serve, e usa anche la parola chiave `as` per catturare l'intero record così com'è.
Usa un'unica istruzione `case` per fare pattern matching sullo stato e restituire il ticket appropriato, creato modificando il record originale che hai catturato con la parola chiave `as`.

```elm
assignTicketTo (User "Danny")
    (Ticket
        { status = New
        , createdBy = ( User "Jesse", 3 )
        , assignedTo = Just (User "Alice")
        , comments = [ ( User "Jesse", "I've been waiting for 6 months!!" ) ]
        }
    )
```
