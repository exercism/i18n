# Tipi di dati generici

I generici in Cairo ti permettono di scrivere codice riutilizzabile che funziona con tipi diversi, evitando la duplicazione e migliorando la manutenibilità.

Puoi usare i generici con funzioni, struct, enum, trait e metodi.

## Funzioni generiche

Una funzione generica opera su tipi diversi senza bisogno di implementazioni separate.

Per esempio:

```rust
fn largest_list<T>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Qui, `T` è un segnaposto per qualsiasi tipo.

Tuttavia, Cairo richiede dei vincoli di trait per assicurarsi che il tipo generico soddisfi requisiti specifici.

Se `T` deve supportare il drop, possiamo aggiornare la firma:

```rust
fn largest_list<T, impl TDrop: Drop<T>>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

I vincoli di trait, come `Drop` o `PartialOrd`, aggiungono restrizioni ai generici per operazioni specifiche.

## Vincoli anonimi

Se un'implementazione di trait non viene usata direttamente in una funzione, puoi scrivere vincoli anonimi usando `+`:

```rust
fn smallest_element<T, +PartialOrd<T>, +Drop<T>, +Copy<T>>(list: @Array<T>) -> T {
    let mut smallest = *list[0];
    let mut index = 1;

    while index < list.len() {
        if *list[index] < smallest {
            smallest = *list[index];
        }
        index += 1;
    };

    smallest
}
```

In questo modo eviti di dare un nome a trait come `TPartialOrd`, riducendo la verbosità.

## Struct con i generici

I generici nelle struct permettono ai campi di essere flessibili.

Per esempio:

```rust
#[derive(Drop)]
struct Wallet<T> {
    balance: T,
}

let w = Wallet { balance: 42 };
```

Se una struct ha bisogno di più tipi generici, basta aggiungere altri segnaposto:

```rust
#[derive(Drop)]
struct Wallet<T, U> {
    balance: T,
    address: U,
}

let w = Wallet { balance: 42, address: '0xabc' };
```

## Enum con i generici

Anche gli enum possono contenere tipi di dati generici.

Per esempio:

```rust
enum Option<T> {
    Some: T,
    None,
}
```

L'enum `Option<T>` può rappresentare un valore opzionale di qualsiasi tipo.

Allo stesso modo, `Result<T, E>` permette di definire i tipi di successo e di fallimento:

```rust
enum Result<T, E> {
    Ok: T,
    Err: E,
}
```

## Metodi generici

Anche i metodi possono usare i generici.

Per esempio:

```rust
#[derive(Copy, Drop)]
struct Wallet<T> {
    balance: T,
}

trait WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T;
}

impl WalletImpl<T, +Copy<T>> of WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T {
        *self.balance
    }
}

let w = Wallet { balance: 50 };
assert!(w.balance() == 50);
```

Puoi anche definire metodi per tipi generici specifici, come `Wallet<u128>`:

```rust
trait WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128);
}

impl WalletReceiveImpl of WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128) {
        self.balance += value;
    }
}

let mut w = Wallet { balance: 50 };
w.receive(100);
assert!(w.balance() == 150);
```

## Combinare i tipi generici

I generici possono gestire combinazioni complesse.

Per esempio, combinando due istanze di `Wallet` di tipi diversi:

```rust
trait WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2>;
}

impl WalletMixImpl<T1, +Drop<T1>, U1, +Drop<U1>> of WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2> {
        Wallet { balance: self.balance, address: other.address }
    }
}

let w1 = Wallet { balance: true, address: 10 };
let w2 = Wallet { balance: 32, address: 100 };
let w3 = w1.mixup(w2);

assert!(w3.balance);
assert!(w3.address == 100);
```

Aggiungendo i vincoli `+Drop`, il compilatore garantisce una gestione corretta delle risorse.

I generici sono potenti, ma richiedono una gestione attenta dei vincoli.

Usali per scrivere codice riutilizzabile, indipendente dal tipo e conciso.
