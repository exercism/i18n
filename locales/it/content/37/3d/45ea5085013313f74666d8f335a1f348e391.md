# Introduzione

Spesso è utile definire tipi personalizzati nei nostri programmi.

Creare nuovi tipi primitivi è possibile, ma è raro farlo.
I tipi primitivi integrati non sono una scelta arbitraria: corrispondono da vicino ai tipi standard nel compilatore LLVM usato da Julia per la compilazione JIT.

Molto più utile è la capacità di definire tipi compositi, con campi denominati.

Altri linguaggi hanno qualcosa di simile e li chiamano `structs` o `records`.
La documentazione di Julia li chiama `composite types`, anche se (con una leggera discrepanza) la sintassi del linguaggio li definisce con la parola chiave `struct`.

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

Nell'esempio precedente vale la pena notare alcuni punti:

- Non viene specificato alcun tipo per `id`, quindi il compilatore lo interpreta come `id::Any`.
- Il nome del tipo viene usato come costruttore, come in `Person(id, name, age)`, per creare un'istanza di tipo `Person`.
- È possibile accedere ai singoli campi con la notazione con punto, come per le tuple con nome.

Gli elementi di tipo `Person` sono immutabili, quindi gli aggiornamenti non sono consentiti.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

Se è necessaria la mutabilità, aggiungi `mutable` alla definizione.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

Per impostazione predefinita, il costruttore richiede che i campi appaiano nello stesso ordine della definizione. Questo diventa scomodo per tipi più complessi.

Usare la macro `@kwdef` consente due nuove possibilità:

- Il costruttore usa argomenti con parola chiave, non la posizione.
- I campi possono avere valori predefiniti e, facoltativamente, possono essere omessi dal costruttore.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## Gerarchie di tipi compositi

Finora abbiamo creato solo tipi compositi concreti.
Se controlli, sono tutti sottotipi di `Any`.

Quando crei più tipi correlati, probabilmente ha più senso definire una gerarchia per loro.
È molto semplice da fare.

Per prima cosa, crea un tipo astratto:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

Poi, includi un operatore `<:` in una definizione di tipo, per mostrare la relazione.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

Ripeti secondo necessità, ricordando che non è consentito creare sottotipi di tipi concreti.

Per una gerarchia più complessa, crea sottotipi astratti secondo necessità.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

Il valore di una gerarchia simile diventerà più chiaro quando arriveremo al concetto `Multiple Dispatch` e vedremo come le funzioni gestiscono i tipi degli argomenti.
