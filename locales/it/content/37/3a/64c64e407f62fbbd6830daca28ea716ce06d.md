# Informazioni

## Trailing closures

Swift offre un'altra variante della sua sintassi per gestire le closure, nota come [trailing closures][trailing-closures]. Si parla di trailing closures quando l'ultimo parametro della lista dei parametri di una funzione è di tipo funzione. In questo caso, se si passa una closure, la si può scrivere _dopo_ la parentesi di chiusura e l'etichetta dell'argomento viene omessa. Nota che se la funzione ha un solo parametro, le parentesi si possono omettere del tutto.

```swift
func fetchURL(_ urlString: String,
              uponReceipt handleResult: (String) -> ()
             )  -> () {
  if let url = URL(string: urlString), let htmlString = fetch(url) {
    handleResult(htmlString)
  }
}

fetchURL("https://www.swift.org") { print($0) }
// prints the fetched html string

["apple", "ball", "carrot"].sorted { $0.count < $1.count }
```

## Più trailing closures

Mentre le versioni precedenti di Swift supportavano solo l'uso di una singola trailing closure, a partire dalla versione 5.2.4 Swift supporta più trailing closures.

Se una funzione ha più di una closure alla fine della sua lista di parametri, si può usare la sintassi delle trailing closures per spostarle tutte fuori dalle parentesi. Tuttavia, viene omessa solo l'etichetta del primo argomento: le altre devono avere un'etichetta.

```swift
func fetchURL(_ urlString: String,
              uponReceipt handleResult: (String) -> (),
              onFailure handleFailure: () -> ()
             )  -> () {
  if let url = URL(string: urlString), let htmlString = fetch(url) {
    handleResult(htmlString)
  } else {
    handleFailure()
  }
}

fetchURL("https://www.swift.org") {
  print($0)
} onFailure: {
  print("Error: https://www.swift.org could not be fetched")
}
// prints the fetched html string on successful fetch or prints error message on failure
```

[trailing-closures]: https://docs.swift.org/swift-book/LanguageGuide/Closures.html#ID102
