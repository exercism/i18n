# Suggerimenti

## Generale

Il linguaggio SGF ha una definizione ricorsiva:

```none
GameTree = "(" Sequence { GameTree } ")"
```

In altre parole, un GameTree è un pezzo di testo che inizia con un `(`, seguito da un testo chiamato «Sequence» (una lista di nodi del gioco), _seguito da **zero o più** GameTree figli_, e termina con un `)`.

Potresti voler usare le espressioni regolari per analizzare un testo SGF.
Tuttavia, poiché gli alberi di gioco possono essere annidati uno dentro l'altro a qualsiasi profondità, le espressioni regolari standard non sono abbastanza potenti per tenere traccia dei livelli di annidamento.

Ci sono un paio di approcci per risolvere questo esercizio:

### Macchina a stati

Potresti scandire la stringa di input carattere per carattere, mantenendo una variabile che tiene traccia della tua posizione attuale.
Puoi tenere traccia dello stato attuale del testo analizzato in base al carattere che si trova nella posizione attuale.
Lo «stato attuale» potrebbe essere qualcosa come «leggere il nome di una proprietà» oppure «dentro il valore di una proprietà».
Con questo approccio ci sono molti valori di cui devi tenere traccia.

### Parser

Un [parser basato su PEG][PEG-parser] è un ottimo modo per analizzare un linguaggio che ha una grammatica definita.
[LPeg][LPeg] è un parser PEG ed è una delle dipendenze richieste di MoonScript, quindi avrai già accesso ad esso.
Un parser ti permette di scrivere regole che descrivono come dovrebbe apparire il testo.
Per esempio, «il nome di una proprietà è composto da tutte lettere maiuscole» oppure «il valore di una proprietà è racchiuso tra parentesi quadre».
Il parser poi si occupa della parte difficile: confrontare il testo di input con le regole che hai scritto.
