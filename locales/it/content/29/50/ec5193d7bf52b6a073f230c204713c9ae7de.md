# Routine vincolate

Finora abbiamo sempre passato in giro dei *valori*: numeri, stringhe, oggetti. Una **routine vincolata** ti permette di passare in giro una routine stessa, qualcosa che verrà chiamato più tardi da codice che non sa cosa sia.

Un sostituto è esattamente questa idea: il direttore di scena dispone di un modo per interpretare la parte, senza sapere chi sia o cosa farà.

## Crearne una

`bind` prende una chiamata con dei buchi, scritti `_`:

```sather
   shout(line : STR) : STR is return line.upper; end;

   ...

   part ::= bind(shout(_));
```

`part` ora è un valore come qualsiasi altro. La chiamata avviene più tardi:

```sather
   part.call("who's there")      -- "WHO'S THERE"
```

## Il tipo

Il tipo di una routine vincolata è `ROUT`, con i tipi degli argomenti tra parentesi graffe ed il tipo restituito dopo i due punti:

```sather
   part : ROUT{STR}:STR := bind(shout(_));
```

Leggi `ROUT{STR}:STR` come «una routine che prende un `STR` e restituisce un `STR`».

| Scritto | Significato |
| --- | --- |
| `ROUT{STR}:STR` | prende un `STR`, restituisce un `STR` |
| `ROUT{INT,INT}:BOOL` | prende due `INT`, restituisce un `BOOL` |
| `ROUT{STR}` | prende un `STR`, non restituisce nulla |
| `ROUT:INT` | non prende nulla, restituisce un `INT` |

Dato che è un tipo, può essere un argomento:

```sather
   rehearse(line : STR, part : ROUT{STR}:STR) : STR is
      return part.call(line);
   end;
```

`rehearse` non ha la più pallida idea di cosa faccia `part`. Ed è proprio questo il punto: gli si può passare `shout`, oppure `whisper`, o qualsiasi altra cosa con quella forma.

## Riempire alcuni argomenti

Non tutti gli argomenti devono essere un buco. Tutto ciò che è scritto per esteso viene fissato nel momento in cui avviene il bind:

```sather
   repeat(times : INT, line : STR) : STR is ... end;

   twice ::= bind(repeat(2, _));      -- ROUT{STR}:STR
```

`twice` prende solo la riga, perché il `2` è già deciso. Il valore viene calcolato nel momento del binding e conservato, quindi cambiare dopo la variabile da cui proviene non fa alcuna differenza.

È così che una routine generica diventa tante routine specifiche.

## Vincolare anche l'oggetto

Per una routine su un oggetto, l'oggetto è la prima cosa nella chiamata e può essere fissato oppure lasciato come buco:

```sather
   bind(board.home_goal)      -- this board's, always
   bind(_.home_goal)          -- whichever board is handed in later
```
