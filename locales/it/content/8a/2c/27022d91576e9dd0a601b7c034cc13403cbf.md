# Introduzione

## Eccezioni

Tutti gli errori in Elixir implementano l'_Exception Behaviour_. Proprio come l'_Access Behaviour_, l'_Exception Behaviour_ definisce delle funzioni di callback che un modulo deve implementare per rispettare il contratto software del behaviour. Una volta che un errore è definito, ha le seguenti proprietà:

- Il nome del modulo definisce il nome dell'errore.
- Il modulo definisce una struct di errore.
- La struct avrà un campo `:message`.
- Il modulo può essere usato con `raise/1` e `raise/2` per sollevare l'errore desiderato.

L'_Exception Behaviour_ specifica anche due callback: `message/1` e `exception/1`. Se non vengono implementate, verranno usate le implementazioni predefinite. `message/1` trasforma la struct di errore in un messaggio leggibile quando viene chiamata con `raise`. `exception/1` permette di aggiungere contesto al messaggio quando viene chiamata con `raise/2`.

### Definire un'eccezione

Per definire un'eccezione a partire da un modulo di errore, usiamo la macro `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### Usare le eccezioni

Gli errori definiti possono essere usati come un errore integrato, usando `raise/1` o `raise/2`.

- `raise/1` solleva un errore specifico tramite il nome del suo modulo oppure, se l'argomento è una stringa, solleva un `RuntimeError` con la stringa come messaggio.
- `raise/2` solleva un errore specifico tramite il nome del suo modulo e accetta un argomento di attributi che viene usato per ottenere l'errore con il messaggio appropriato.
