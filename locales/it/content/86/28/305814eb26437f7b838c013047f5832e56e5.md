# Introduzione

Sapere qual è il tipo di un dato è spesso molto importante per far funzionare il codice senza intoppi e senza errori.

JavaScript ha diversi modi per controllare il tipo di un valore o di un oggetto.

```exercism/note
I meccanismi di controllo dei tipi di JavaScript possono essere alquanto inaffidabili.

Per una maggiore sicurezza dei tipi e una tipizzazione più forte, probabilmente dovresti usare TypeScript, un linguaggio che si basa su JavaScript, ma con la sintassi dei tipi di un linguaggio a tipizzazione statica.
```

## L'operatore `typeof`

L'operatore `typeof` restituisce il tipo del suo operando.
L'output è una stringa che corrisponde al nome di uno dei [tipi di dati primitivi][primitives], tranne che per `"null"`.
Può anche essere `"function"` o `"object"`.

```javascript
typeof undefined;
// => "undefined"

typeof true;
// => "boolean"

typeof 42;
// => "number"

typeof 'Hello, World!';
// => "string"

typeof function () {
  return 'Hello, World';
};
// => "function"

typeof [1, 2, 3, 4];
// => "object"

typeof { city: 'Stockholm', country: 'Sweden' };
// => "object"
```

Per [ragioni storiche][`typeof null` is `"object"`].

## L'operatore `instanceof`

Per controllare il tipo di un oggetto, puoi usare l'operatore `instanceof`.
Restituisce un valore `boolean` a seconda che il secondo operando sia incluso nella [catena di prototipi][prototype chain] del primo operando.
Per chiarire, `instanceof` restituirà se il primo operando è un'istanza del secondo operando o di una delle sue classi figlie.
`instanceof` funziona solo con gli oggetti.

```javascript
class Beverage {
  // ...
}

// The Coffee class is a child of the Beverage class.
class Coffee extends Beverage {
  // ...
}

const java = new Coffee();

java instanceof Coffee;
// => true

java instanceof Beverage;
// => true
```

````exercism/advanced
La classe `Array` ha un metodo chiamato `Array.isArray()` che controlla se il suo argomento è un array.

Mentre `instanceof Array` non funzionerà con un array creato in un ambiente di esecuzione diverso, come un `iframe` in una pagina web, `Array.isArray()` sì.

Questo perché la classe Array ha un costruttore diverso in ogni ambiente di esecuzione, e ogni `iframe` ha il proprio ambiente di esecuzione, il che significa che la funzione nella catena di prototipi sarà diversa, facendo fallire `instanceof Array`.
`Array.isArray()` è in grado di ignorarlo, e dovrebbe sempre essere usato quando possibile.

Può anche sopravvivere ai falsi positivi in cui un oggetto non è in realtà un `Array`, e ha semplicemente `Array` nella sua catena di prototipi.

```javascript
({ __proto__: Array.prototype }) instanceof Array
// => true

Array.isArray({ __proto__: Array.prototype })
// => false
```

````

## L'operatore `in`

L'operatore `in` restituisce se il primo operando è una proprietà del secondo operando.
Non controlla che la proprietà abbia un valore definito.
Una proprietà impostata su `undefined` verrà comunque rilevata da `in`.

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
    this.isDarkMatter = undefined;
  }

  coolDown() {
    this.temperature = 'warm';
  }
}

const espresso = new Coffee();

'temperature' in espresso;
// => true

'color' in espresso;
// => false

'isDarkMatter' in espresso;
// => true
```

````exercism/note
`in` restituirà `true` per proprietà e metodi ereditati.

```javascript
"coolDown" in espresso
// => true

"constructor" in espresso
// => true
```

Per evitare questo, usa invece `Object.hasOwn()`
````

## La funzione `Object.hasOwn()`

Il metodo `Object.hasOwn()` restituisce se l'oggetto specificato _possiede la proprietà indicata_ (non è ereditata e non è un metodo).

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
  }

  coolDown() {
    this.temperature = 'warm';
  }
}
const cappuccino = new Coffee();

Object.hasOwn(cappucino, 'temperature');
// => true

Object.hasOwn(cappucino, 'constructor');
// => false

Object.hasOwn(cappucino, 'coolDown');
// => false
```
