# Introduzione

Il sistema di gestione degli errori di Factor è composto da tre parti: `throw` per lanciare un errore, `recover` per gestirne uno e `ERROR:` per definire un tipo di errore personalizzato.

## `throw`

`throw` (in [`kernel`][kernel]) lancia un errore. L'argomento può essere un valore *qualsiasi*, una stringa, un numero o una tupla, e diventa l'errore che potrai esaminare in seguito:

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw` non restituisce nulla: il resto della parola corrente viene saltato.

## `recover`

`recover` (in [`continuations`][continuations]) è il try/catch di Factor. Prende una *quotation* di prova e una *quotation* di recupero:

```
recover ( try recovery -- )
```

Se `try` termina senza lanciare un errore, `recovery` viene ignorata. Se `try` lancia un errore, l'errore viene inserito nello stack e `recovery` viene eseguita:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

`when` di [`kernel`][kernel] è il compagno naturale: esegue una quotation solo quando l'elemento in cima allo stack è vero:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:` definisce una classe di tuple *e* una parola che ne costruisce una nuova istanza e la lancia:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

Un errore senza slot è semplicemente `ERROR: name ;`: chiamare `name` lancia un'istanza vuota. Le tuple definite con `ERROR:` hanno un predicato di classe `name?` che puoi usare per verificare se un errore catturato era di quel tipo.

## Rileggere gli slot

Un errore catturato è solo una tupla, quindi ogni slot di `ERROR:` ha lo stesso lettore `slot>>` generato automaticamente di qualsiasi altra tupla.

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
