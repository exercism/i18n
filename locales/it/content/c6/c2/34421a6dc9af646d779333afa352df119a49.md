# Tipi di stringa

Cairo non ha un tipo di dato nativo per le stringhe.
Tuttavia, ci sono due modi per rappresentare un tipo stringa: stringhe corte che usano un singolo `felt252` e stringhe di lunghezza arbitraria che usano `ByteArray`.

## Stringhe corte

Una stringa corta è formata con virgolette singole dove ogni carattere che compone la stringa è codificato su un byte seguendo lo [standard ASCII][ascii-table].

Come stringa ASCII, per esempio, `'abc'` sarà:

- `'a'` è equivalente a `0x61`
- `'b'` è equivalente a `0x62`
- `'c'` è equivalente a `0x63`
- `'abc'` è equivalente a `0x616263`

Il tipo di dato `felt252` contiene le stringhe corte in Cairo.
Poiché `felt252` contiene 251 bit, una stringa corta è limitata a 31 caratteri (31 \* 8 = 248 bit, che è il massimo multiplo di 8 che rientra in 251 bit).

Esempi di dichiarazioni di stringhe corte:

```rust
    let my_first_char = 'D';
    let my_first_char_in_hex = 0x44;

    let my_first_string = 'Hello world';
    let my_first_string_in_hex = 0x48656C6C6F20776F726C64;
```

### ByteArray

La struct ByteArray è stata introdotta in Cairo 2.4.0.
Le stringhe ByteArray si scrivono con virgolette doppie come segue:

```rust
    let long_string: ByteArray = "this is a string which has more than 31 characters";
```

Tecnicamente, l'aggiornamento ha anche introdotto il tipo `bytes31` che contiene 31 byte e che rientra in un felt.
La struct `ByteArray` rappresenta essenzialmente una stringa lunga usando un array di `bytes31` che contengono le «parole intere» (cioè parole che riempiono l'intero felt) e un singolo campo felt che contiene una «parola incompleta» (il numero di byte al suo interno è specificato in un campo di lunghezza separato).

```rust
#[derive(Drop, Clone, PartialEq, Serde, Default)]
struct ByteArray {
    data: Array<bytes31>,
    pending_word: felt252,
    pending_word_len: usize,
}
```
