# I test

Ogni esercizio fornisce i test di unità.
L'implementazione la scrivi tu.
Ogni file produrrà un eseguibile da console che esegue i test.
Eseguire l'eseguibile dei test stampa un messaggio per ogni test che fallisce e segnala uno stato di uscita diverso da zero quando i test falliscono.

*Nota*: il codice viene confrontato con la suite di test ogni volta che compili il progetto.
Se il codice non supera uno o più test ma è codice D valido, verrà comunque compilato.

Affrontare ogni esercizio è un percorso fatto di:

* Eseguire i test con `dub test`
  * Se hai scelto di non installare DUB, userai invece `dmd source/*.d -de -w -main -unittest`, poi esegui il binario risultante.
* Per ogni test di unità:
  * Risolvi gli errori di compilazione per far fallire il test.
  * Implementa solo quanto basta per far passare il test.
  * Riorganizza l'implementazione per migliorare la leggibilità, ridurre le duplicazioni, ecc.
  * Abilita il test successivo

*Nota:* D supporta i test di unità direttamente nel linguaggio, quindi di solito i test di unità si trovano nello stesso file dell'implementazione.
I test di unità vengono eseguiti prima del corpo di main e sono abilitati nell'eseguibile finale usando l'opzione del compilatore **-unittest**.
