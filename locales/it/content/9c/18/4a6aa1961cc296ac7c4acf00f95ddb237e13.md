# Inclusione del codice

`circus-acts` usava `<` per dire che una classe *può fare* ciò che descrive una classe astratta. Non diceva nulla su come farlo.

`include` è l'altra metà: prende il codice vero e proprio da un'altra classe e ne mette una copia in questa.

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

`JAZZ_ROUTINE::count` è 8, senza che `JAZZ_ROUTINE` lo menzioni.

## Sono due decisioni separate

Nella maggior parte dei linguaggi sono unite: un solo `extends` tramanda il codice e rende la sottoclasse utilizzabile ovunque sia utilizzabile la superclasse. Sather le tiene separate.

| Scritto | Cosa dice |
| --- | --- |
| `class A < $B` | un `A` può essere usato ovunque serva un `$B` |
| `class A is include B` | `A` parte con una copia del codice di `B` |

L'una senza l'altra, o entrambe. Includere una classe **non** la rende un sottotipo: dopo `include WARM_UP`, un `JAZZ_ROUTINE` non può comunque essere usato dove serve un `WARM_UP`, e nessuno fa finta del contrario.

## Rinominare

Una routine inclusa può essere importata con un nome diverso:

```sather
   include WARM_UP count -> warm_up_count;
```

Se sono più di una, si separano con virgole:

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## Lasciarne fuori una

Rinominare verso il *nulla* la lascia fuori, ed è così che la si sostituisce:

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

`count` entra come al solito; `describe` no, quindi scriverne una qui non crea un conflitto. Senza il `describe -> ;` il compilatore rifiuterebbe: due routine con lo stesso nome e gli stessi argomenti in una sola classe sono un errore, e Sather non tira a indovinare quale intendevi.

È questa la differenza rispetto a un override nella maggior parte dei linguaggi: la sostituzione viene annunciata, non implicita.
