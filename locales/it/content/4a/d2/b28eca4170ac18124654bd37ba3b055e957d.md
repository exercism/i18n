# Introduzione

## Uguaglianza

Di solito, i tipi semplici (stringhe e primitivi) si testano per uguaglianza con `==` e `!=`.

I tipi di riferimento (istanze di classi) si confrontano usando il metodo `Equals()` ereditato da `Object`. Se il tuo obiettivo con il test di uguaglianza è assicurarti che due oggetti siano esattamente la stessa istanza, allora affidarti all'implementazione di `Object` sarà sufficiente. In caso contrario, devi eseguire l'override di `object.Equals()`.

Se sai che tutte le istanze della classe vengono create in un unico posto, ad esempio i personaggi di un gioco o di una simulazione, l'uguaglianza per riferimento è sufficiente. Tuttavia, è probabile che vengano create più istanze della stessa entità del mondo reale (da un database, dall'input dell'utente, tramite una richiesta web). In questo caso, i valori che identificano univocamente l'entità devono essere testati per uguaglianza. Quindi è necessario eseguire l'override di `Equals()` e testare per uguaglianza i membri dati appropriati della classe.

Un metodo `Equals()` di cui è stato eseguito l'override conterrà test di uguaglianza sui membri di tipi semplici tramite `==`, e sui tipi di riferimento tramite chiamate ricorsive a `Equals()`.

La classe `Object` fornisce metodi appropriati per confrontare due oggetti e rilevare se sono la stessa identica istanza.

### `Object.GetHashCode()`

Il metodo `Object.GetHashCode()` restituisce un codice hash sotto forma di un intero a 32 bit. Il codice hash è usato dalle classi _dictionary_ e _set_, come `Dictionary<T>` e `HashSet<T>`, per archiviare e recuperare oggetti in modo performante.

La relazione tra codice hash e uguaglianza è questa: se due oggetti sono uguali (`Equal()` restituisce true), allora `GetHashCode()` dei due oggetti deve restituire lo stesso valore. Questo non vale nella direzione opposta. La relazione non è simmetrica. Il fatto che due oggetti abbiano lo stesso codice hash non significa che debbano essere uguali. Immagina una funzione di ricerca che prima va in un «bucket» in base al codice hash e poi estrae l'elemento specifico usando il test di uguaglianza.

La documentazione dell'API della libreria HashCode illustra il modo migliore per generare un codice hash.

I valori usati nel test di uguaglianza devono essere stabili finché la collezione con hash è in uso. Se aggiungi un oggetto alla collezione con un insieme di valori e poi cambi quei valori, il codice hash non punterà più al «bucket» corretto. In pratica, questo significa che l'oggetto dovrebbe essere immutabile. Altri approcci rischiano di creare trappole per chi dovrà mantenere il codice.

## I set

Un set è una raccolta di valori unici. L'implementazione predefinita di un set in .NET è la classe `HashSet<T>`, una raccolta che contiene solo valori unici.
