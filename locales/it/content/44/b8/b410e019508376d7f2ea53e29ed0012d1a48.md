# Informazioni

Una dichiarazione `GENERIC:` introduce una parola il cui comportamento
dipende dalla classe di uno dei suoi argomenti. Il comportamento concreto
è fornito dai *metodi* (`M:`) che si rivolgono a classi specifiche.

```factor
GENERIC: stringify ( obj -- str )
M: integer stringify number>string ;
M: string  stringify ;
M: f       stringify drop "(none)" ;
```

Quando si chiama `stringify`, Factor ispeziona la cima dello stack,
cerca il metodo più specifico la cui classe corrisponde e lo esegue. Se
nessun metodo corrisponde, viene generato un errore.

## Classe di dispatch

Per impostazione predefinita, il dispatch avviene sull'argomento più in
alto (il primo input dichiarato nell'effetto sullo stack). Per il
dispatch su più argomenti, vedi `HOOK:` e `MATH:`, che fanno dispatch
sul secondo argomento o sulla promozione numerica, rispettivamente.

## Aggiungere metodi a un generico

Puoi estendere un generico in qualsiasi momento, anche da un vocabolario
diverso, purché tu possa fare `USE:` sia del generico sia della classe:

```factor
USING: math ;
M: ratio  area drop 0 ;     ! adds an `area` method for ratios
```

## Metodi sulle classi integrate

I generici funzionano altrettanto bene sulle classi integrate (`integer`,
`string`, `array`, `f`, `t`) che sulle tuple definite dall'utente. I
metodi su `f` e `t` sono particolarmente utili per i predicati nello
stile «is-set?», che hanno valori predefiniti naturali.

## Quando un generico è la scelta giusta

Ricorri a `GENERIC:` quando:

- Una singola operazione ha implementazioni *davvero diverse* per input
  diversi (non solo un `case` su etichette).
- Prevedi che in seguito altro codice aggiunga nuovi tipi.
- Vuoi che il sistema dei tipi garantisca che l'operazione sia definita
  per ogni classe rilevante: Factor può elencarti i metodi mancanti.

Se la variazione è una piccola enumerazione fissa di etichette, un
`case` è più semplice.
