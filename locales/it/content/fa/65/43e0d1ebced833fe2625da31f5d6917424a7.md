# Per i manutentori

## Script di supporto per creare i test Fortran: create_fortran_test.py

Un modo semplice per creare il test di un esercizio è usare lo script
`bin/create\_fortran\_test.py`

Usa questo script per creare un file iniziale <exercise>\_test.f90 che puoi usare come modello per il tuo test.
In genere dovrai sostituire la funzione 'response' nel file generato con la chiamata alla funzione corretta.

Tieni anche presente che Fortran ha problemi con i caratteri speciali come `\n` e `\t`, quindi presta particolare attenzione a gestirli.

### Prerequisiti

- CMake e un compilatore Fortran funzionanti
- Python3.x (potresti riuscire a farlo funzionare con Python2, ma non ho fatto lo
  sforzo di renderlo compatibile con le versioni precedenti)
- l'ultima versione di https://github.com/exercism/problem-specifications.git
- git

### Flusso di lavoro per creare un nuovo test

- scarica le ultime modifiche da `exercism/problem-specifications`, ad esempio git clone git@github.com:exercism/problem-specifications.git
- crea un nuovo branch per il nuovo esercizio, ad esempio git checkout -b exercise-bob
- esegui questo script per l'esempio che vuoi creare
- copia `config/CMakeLists.txt` nella directory dell'esercizio (per questo puoi usare `bin/update-cmake-files`)
- implementa un esercizio funzionante
- correggi i test potenzialmente problematici (vedi ad esempio exercise/bob "Test 20" e "Test 24")
- assicurati che il comando `ctest` venga eseguito senza errori
- copia la soluzione in .meta/example.f90 e rimuovi l'implementazione vera e propria dal file dell'esercizio, ad esempio bob.f90
- aggiorna le directory .docs e .meta
  - cp ../problem-specifications/exercises/bob/description.md exercises/practice/bob/.docs/instructions.md
    - sostituisci "# Description" con "# Instructions"
  - compila manualmente .meta/tests.toml (finché non esiste un modo automatico)
  - compila manualmente .meta/config.json (finché non esiste un modo automatico)
    - usa ../problem-specifications/exercises/bob/metadata.yml
- apri una pull request con le modifiche

Per l'esempio bob:

```bash
$ python bin/create_fortran_test.py -j ../problem-specifications/main/exercises/bob/canonical-data.json -t exercises/practice/bob/bob_test.f90
Namespace(json='../problem-specifications/main/exercises/bob/canonical-data.json', target='exercises/practice/bob/bob_test.f90')
Wrote : exercises/practice/bob/bob_test.f90
$ cp config/CMakeLists.txt exercises/practice/bob/.
$ cd exercises/practice/bob
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake ..
$ make
$ ctest -V
```

### Modificare `CMakeLists.txt`

Quando modifichi il file cmake, aggiorna la copia principale in `config/` e usa `bin/update-cmake-files` per copiarla in tutte le directory degli esercizi.

## Soluzione

Quando hai una soluzione, copiala nella directory ".meta" come "example.f90".

Forse vuoi lasciare un'implementazione scheletro della funzione o della subroutine che aiuti lo studente e lasciare nella directory dell'esercizio il file con il nome dell'esercizio.
