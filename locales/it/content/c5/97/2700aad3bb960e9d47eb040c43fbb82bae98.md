# Appendice alle istruzioni

## Messaggi di eccezione

A volte è necessario [sollevare un'eccezione][raise-an-exception]. Quando lo fai, dovresti sempre includere un **messaggio di errore significativo** che indichi qual è l'origine dell'errore. Questo rende il codice più leggibile e aiuta molto a fare debug. Nei casi in cui sai che l'origine dell'errore sarà di un certo tipo, puoi scegliere di sollevare uno dei [tipi di errore predefiniti][built-in-errors], ma dovresti comunque includere un messaggio significativo.

Questo esercizio in particolare richiede che tu usi l'[istruzione raise][raise-statement] per «lanciare» un `ValueError` se la domanda passata ad `answer()` è malformata o non valida, oppure contiene un'operazione sconosciuta. I test passeranno solo se usi `raise` sull'`exception` e includi anche un messaggio insieme ad essa.
**Nota bene**: il messaggio necessario è diverso per ogni scenario, anche se viene sollevato lo stesso _tipo di errore_.
Controlla i test con attenzione.

Per sollevare un [`ValueError`][value-error] con un messaggio, scrivi il messaggio come argomento del tipo `exception`:


```python
# if the question contains an unknown operation.
raise ValueError("unknown operation")

# if the question is malformed or invalid.
raise ValueError("syntax error")
```

Per _gestire_ un errore sollevato all'interno di un particolare blocco di codice, si può usare un [try-except][handling-exceptions]. I blocchi `try-except` «avvolgono» il codice che potrebbe causare un errore, associando tutte le eccezioni a un errore, a più errori o ad altre porzioni di codice che si occupano del problema:


```python
while len(equation) > 1:
        try:
           # The questionable/error-prone code goes here,in an indented block
           # It can contain statements, loops, if-else blocks, or other executable code.
           x_value, operation, y_value, *rest = equation
           ...
           ...

        except:
            # Code for what to do when an error gets thrown in the code above.
            # This could be one error, or more complicated logging, error checking and messaging.
            raise ValueError("syntax error")
```
