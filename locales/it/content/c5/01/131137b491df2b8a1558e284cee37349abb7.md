# Introduzione

Il linguaggio di programmazione Java usa le _eccezioni_ per gestire errori ed altri eventi eccezionali.

## Che cos'è un'eccezione

Un'eccezione è un evento che si verifica durante l'esecuzione di un programma e che interrompe il normale flusso delle istruzioni.
In Java le eccezioni vengono sollevate esplicitamente, e l'atto di sollevare un'eccezione si chiama _lanciare un'eccezione_.
L'atto di gestire un'eccezione si chiama _catturare un'eccezione_.

In Java, tutte le eccezioni sono sottoclassi della classe `Exception`, che a sua volta è una sottoclasse di `Throwable`.

Java distingue due tipi di eccezioni:

1. Eccezioni controllate
2. Eccezioni non controllate

### Eccezioni controllate

Le _eccezioni controllate_ sono condizioni eccezionali che un'applicazione dovrebbe prevedere e dalle quali dovrebbe riuscire a riprendersi.
Un esempio di eccezione controllata è `FileNotFoundException`, che si verifica quando un metodo tenta di leggere un file che non esiste.

Questo tipo di eccezione viene controllato in fase di compilazione: i metodi che lanciano eccezioni controllate devono specificarlo nella firma del metodo, ed il codice che chiama un metodo che potrebbe lanciare un'eccezione controllata deve gestirla, altrimenti non verrà compilato.

Tutte le eccezioni controllate sono sottoclassi di `Exception` che non estendono `RuntimeException`.

### Eccezioni non controllate

Le _eccezioni non controllate_ sono condizioni eccezionali che un'applicazione di solito non può prevedere e da cui non può riprendersi.
Un esempio di eccezione non controllata è `NullPointerException`, che si verifica quando un metodo si aspetta un valore non nullo ma riceve `null`.

Questo tipo di eccezione non viene controllato in fase di compilazione: i metodi che lanciano eccezioni non controllate non sono tenuti a specificarlo nella firma del metodo, ed il codice che chiama un metodo che potrebbe lanciare un'eccezione non controllata non è tenuto a gestirla.

Tutte le eccezioni non controllate ereditano da `RuntimeException`, che a sua volta è un'estensione di `Exception`.

## Lanciare eccezioni

Un metodo in Java può lanciare un'eccezione usando l'istruzione `throw`.

### Lanciare un'eccezione controllata

Quando si lancia un'eccezione controllata da un metodo, è necessario specificarlo nella firma del metodo usando la parola chiave `throws`, come mostrato nell'esempio seguente.
Questo obbliga il codice chiamante a prevedere che possa essere lanciata un'eccezione ed a gestirla di conseguenza.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### Lanciare un'eccezione non controllata

Quando si lancia un'eccezione non controllata da un metodo, non è necessario specificarlo nella firma del metodo, anche se è comunque consentito.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## Gestire le eccezioni

In Java, la gestione delle eccezioni avviene tramite le parole chiave `try`, `catch` e `finally`.

- Le istruzioni di codice che potrebbero lanciare un'eccezione dovrebbero essere racchiuse in un blocco `try`.
- Il blocco `try` è seguito da uno o più blocchi `catch` che catturano le eccezioni lanciate nel blocco `try`.
- Ai blocchi `catch` può seguire, facoltativamente, un blocco `finally` che viene sempre eseguito dopo il blocco `try`, indipendentemente dal fatto che sia stata lanciata o meno un'eccezione.

L'esempio seguente mostra come funzionano queste parole chiave:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

In questo esempio, quando non viene lanciata alcuna eccezione, viene stampato quanto segue:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

Se invece l'istruzione `bankAccount.withdraw(amount)` lancia una `InsufficientBalanceException`, viene stampato quanto segue:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

Oppure, se `bankAccount.withdraw(amount)` lancia un'eccezione non controllata, viene stampato quanto segue:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## Errori

Java ha anche una categoria separata chiamata _Errors_, che raccoglie problemi gravi esterni all'applicazione.
Un esempio di errore è `OutOfMemoryError`, che si verifica quando un'applicazione tenta di usare più memoria di quanta ne sia disponibile nel sistema.

Come le eccezioni non controllate, gli errori non vengono controllati in fase di compilazione.
La differenza è che rappresentano problemi a livello di sistema ed in genere vengono lanciati dalla macchina virtuale Java o dall'ambiente, non dall'applicazione.
In generale, le applicazioni non dovrebbero tentare di catturarli o gestirli.

Tutti gli errori in Java ereditano dalla classe `Error`.
