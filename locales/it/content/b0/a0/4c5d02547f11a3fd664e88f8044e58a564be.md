# Informazioni

## JSON

[JSON][json] (JavaScript Object Notation) è un formato di dati e di file leggibile da esseri umani, comunemente usato per scambiare dati, in particolare per le applicazioni web.
Non sorprende quindi che occupi un posto speciale nel linguaggio Elm.

Elm fornisce i moduli principali [`Json.Decode`][decode] e [`Json.Encode`][encode] per analizzare e scrivere dati JSON.
I decoder JSON sono un modo per _dichiarare_ che tipo di dati ci si aspetta e a quale struttura di dati devono essere associati.

Se si viene da linguaggi a tipizzazione dinamica, i decoder sembrano spesso macchinosi, o troppo rigidi a prima vista.
Pur essendo certamente verbosi, almeno in Elm, sono uno strumento prezioso per descrivere esplicitamente le aspettative dei programmi sui dati in arrivo, e [non sono meno espressivi dei tipi dinamici][dynamic-types-not-more-open].

Importiamo alcuni alias e tipi dai moduli:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Usare `Decode.decodeString : Decoder a -> String -> Result Error a` con un decoder e una stringa JSON avrà successo se la stringa è conforme alle specifiche del decoder, oppure fallirà in caso contrario.
Non c'è modo di ispezionare i dati JSON grezzi quando si definisce il decoder, il che potrebbe sembrare insolito se si viene da linguaggi imperativi.

## Decoder dei tipi di dati di base

JSON ha un piccolo numero di tipi di dati fondamentali:

- Stringa: codificata con virgolette doppie `"hello world"`
- Booleano: `true` oppure `false`
- Numero: come `34` o `0.12`
- Null: l'assenza di dati `null`

Ognuno di questi è associato a una funzione di `Decode`:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Nota che `Decode.null` ti permette di decidere come modellare un `null` nel programma, richiedendo un valore arbitrario come argomento (magari `()`, `Nothing`, o qualsiasi cosa appropriata al programma).

## Combinare i decoder

JSON definisce anche due strutture di dati per raccogliere i tipi di dati fondamentali:

- Array: una raccolta di altri tipi di dati `[0, null, "none", []]`
- Oggetto: una raccolta di coppie chiave-valore `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` offre anche funzioni per decodificarli:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Queste funzioni `Decode.list : Decoder a -> Decoder (List a)` e `Decode.dict : Decoder a -> Decoder (Dict String a)` richiedono ciascuna un decoder come argomento, che si aspetta di decodificare ogni singolo elemento della struttura di dati.
Se il decoder passato come argomento non riesce a decodificare un elemento qualsiasi di un array o di un oggetto, l'intero decoder fallisce, il che è un pattern comune.

Combinare decoder semplici in decoder più complessi è l'idea centrale della tecnica.
Con un esempio introdurremo diverse altre funzioni che si possono usare per costruire decoder di dati del mondo reale arbitrariamente complessi.

## GeoJSON

Per esercitarci a combinare decoder di base per analizzare dati JSON complessi, costruiamo dei decoder per analizzare (un sottoinsieme di) dati GeoJSON.
[GeoJSON][geojson] è un formato di dati specializzato basato su JSON, usato per rappresentare elementi geografici, come luoghi, percorsi o regioni, specificati con coordinate geografiche 2D o 3D, insieme ad altre proprietà.

### Oggetto Geometry

Un Oggetto Geometry GeoJSON è un oggetto che contiene un campo `type` con un valore di tipo stringa (ci sono 7 possibili valori di `type`) e un campo `coordinates` con coordinate geografiche (raccolte in una struttura che dipende dal tipo).
Per esempio,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

oppure

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Un Oggetto Geometry potrebbe essere rappresentato in Elm con il seguente tipo

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Per ispezionare il valore di un certo campo, possiamo usare `Decode.field : String -> Decoder a -> Decoder a`, che decodifica il valore di una chiave specifica di un oggetto.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Per trasformare il valore analizzato con successo da un decoder, possiamo usare `Decode.map : (a -> value) -> Decoder a -> Decoder value`, o uno qualsiasi dei suoi fratelli, da `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` a `Decode.map8`.

In questo caso, vogliamo decidere quale decoder di coordinate usare in base al valore del campo `type`, un lavoro perfetto per `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` ed i suoi amici `Decode.succeed : a -> Decoder a` e `Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

Nota a questo punto che potremmo usare `Decode.andThen` per validare le coordinate (verificando che arrivino in coppie o terzine e che i valori delle coordinate abbiano senso geografico).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### Oggetto Feature

Un Oggetto Feature GeoJSON rappresenta qualcosa delimitato spazialmente: ha un campo `type` con il valore `"Feature"`, un campo `geometry` con un Oggetto Geometry o un `null`, un campo `properties` con un Oggetto JSON arbitrario o un `null`, ed un campo opzionale `id` con un valore JSON di tipo stringa o numero.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

oppure

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Occupiamoci prima del campo `id`.
Se esiste, deve poter accogliere stringhe o numeri, quindi potremmo introdurre un tipo personalizzato per il valore, oppure salvarlo sempre come stringa.

Per scegliere tra due possibili decoder, possiamo usare `Decode.oneOf : List (Decoder a) -> Decoder a`.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Per esprimere che il campo è opzionale, potremmo usare la stessa tecnica

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Ma potremmo invece usare `Decode.maybe : Decoder a -> Decoder (Maybe a)`

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Nota che `decodeMaybeFeatureId` (o qualsiasi decoder racchiuso con `Decode.maybe`) avrà sempre successo, dato che può sempre ripiegare su `Ok Nothing`, anche se un decoder che lo usa potrebbe comunque fallire

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

Passiamo ora al campo `geometry`, che può essere un Oggetto Geometry oppure `null`.
Potremmo usare di nuovo `Decode.oneOf`, ma c'è un'opzione migliore: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` e `Decode.nullable` hanno la stessa firma, ma il loro comportamento è diverso, dato che il risultato `OK Nothing` di un `Decode.nullable` deriverà solo dallo specifico valore JSON `null`.

Infine, il campo `properties` può contenere un Oggetto JSON arbitrario o un `null`, un compito per `Decode.value : Decoder Value`.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Nota che `Value` è un tipo opaco, il che significa che non puoi facilmente ispezionarne il contenuto.
Per usarlo, puoi scrivere un decoder per esso ed eseguirlo con `Decode.decodeValue : Decoder a -> Value -> Result Error a`, oppure inviarlo direttamente a JavaScript tramite un port.

Siamo pronti ad analizzare gli Oggetti Feature:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## Encoder JSON

Gli encoder permettono di scrivere JSON valido a partire da valori Elm usando la funzione `Encode.encode : Int -> Value -> String`.
Il primo argomento specifica la quantità di indentazione nel risultato finale, ed il secondo argomento è il valore JSON da scrivere.

Un `Value` può essere ottenuto da `Decode.value` oppure prodotto da uno degli encoder:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

così come con `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Definiamo gli encoder per i decoder GeoJSON definiti prima

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

In generale, un buon test per le coppie decoder-encoder è verificare che `elmValue |> encoder |> decoder == elmValue`.

## Cos'altro?

Non abbiamo coperto ogni singola funzione dei moduli `Json`.
Tra le cose non menzionate ci sono: decoder per trasformare gli array in `Array` o gli oggetti in `List (String, a)`, decoder per array con uno o più elementi, decoder per campi specifici di oggetti JSON annidati o elementi specifici di array, come decodificare strutture ricorsive, così come le diverse varianti di `Error` e come visualizzarle.

Altri pacchetti usati di frequente includono [`Json.Decode.Pipeline`][pipeline], che introduce un flusso comodo per strutture JSON complesse, e [`Json.Decode.Extra`][extra], che fornisce altri decoder, encoder e funzioni ausiliarie.
