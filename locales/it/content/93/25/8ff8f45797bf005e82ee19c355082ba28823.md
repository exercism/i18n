# Informazioni

Quattro parole di [`grouping`][grouping] e [`splitting`][splitting] coprono quasi ogni esigenza di «tagliare una sequenza in pezzi»:

```factor
USING: grouping kernel sequences splitting splitting.monotonic ;

! Disjoint chunks of N elements
{ 1 2 3 4 5 6 7 } 3 group .
! => { { 1 2 3 } { 4 5 6 } { 7 } }

! Overlapping sliding window of N elements
{ 1 2 3 4 5 } 2 clump .
! => { { 1 2 } { 2 3 } { 3 4 } { 4 5 } }

! Split wherever a predicate fires on an element
{ 1 2 0 3 4 0 5 } [ zero? ] split-when .
! => { { 1 2 } { 3 4 } { 5 } }

! Group runs where adjacent elements are "the same" by some test
{ 1 1 2 2 2 3 } [ = ] monotonic-split .
! => { { 1 1 } { 2 2 2 } { 3 } }
```

| parola            | effetto                                                                  |
|-------------------|-------------------------------------------------------------------------|
| `group`           | `( seq n -- groups )` — blocchi disgiunti di *n* elementi                |
| `clump`           | `( seq n -- clumps )` — finestre sovrapposte di *n* elementi             |
| `split-when`      | `( seq quot: ( elt -- ? ) -- pieces )` — interrompi quando il quot è vero |
| `monotonic-split` | `( seq quot: ( a b -- ? ) -- pieces )` — interrompi quando il quot su elementi *adiacenti* è `f` |

Un modello mentale utile:

- **`group` / `clump`** guardano le dimensioni; il parametro *n* dice quanto è grande ogni finestra.
- **`split-when`** guarda i *singoli elementi*; il predicato decide se ogni elemento è un «punto di rottura».
- **`monotonic-split`** guarda le *coppie*; il predicato decide se due elementi adiacenti fanno ancora parte della stessa sequenza.
