# Introduzione

## Enumerazioni

Finora abbiamo gestito soprattutto numeri e stringhe.
Per modellare il mondo reale, potremmo voler avere un numero limitato di valori che una variabile può assumere.
Potresti volere un tipo dedicato con alcuni valori distinti, ciascuno con un nome distinto.
Per esempio, in una fabbrica di skateboard, avere come materiale della tavola una scelta tra solo maple, bamboo o plastic.

Potresti usare numeri interi per codificare quei valori, ma dovresti scrivere del codice aggiuntivo per controllare se dal sistema arriva un valore non valido per il materiale.
Il significato di quei [_numeri magici_][magic numbers] è difficile da seguire nel codice sorgente ed è facile confonderli tra loro.
Le `enumerations` si possono usare per incoraggiare un codice espressivo e per limitare gli errori di confronto involontari.

## Esempio di utilizzo

Il termine specifico per questo tipo di enumerazione è `scoped enumeration`.
Lo snippet qui sotto mostra come scrivere la `enumeration` `DeckMaterial`.
Nota la parola chiave `enum class` e il `;` alla fine della definizione:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
Ora guarda una funzione che calcola il prezzo nel negozio di skateboard e nota l'operatore di risoluzione dello scope (`::`), che specifica un `enumerator` dell'`enumeration`:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## Scope

Immagina di avere una seconda `enumeration` per il materiale delle ruote:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
Anche se le ruote e la tavola possono essere entrambe fatte di _plastic_, le due non si possono confondere.
Sono _tipi_ diversi: `DeckMaterial` plastic e `WheelMaterial` plastic.
Ogni `enumeration` avrà i suoi `enumerators` nel proprio scope, il proprio `namespace`.
È per questo che si chiamano `scoped enumerations`.

## Enumerazioni senza scope
Potresti pensare che, con il nome `scoped`, esistano anche le enumerazioni `unscoped`, e avresti ragione.
Le `Unscoped enumerations` stanno diventando meno popolari perché condividono tutte lo stesso namespace globale.
Proprio per questa condivisione non potresti avere due `unscoped enumerations` con gli stessi `enumerators`, come _plastic_ nell'esempio qui sopra.

Inoltre, le `unscoped enumerations` si convertono implicitamente in numeri interi.
Guarda l'esempio qui sotto per un risultato sorprendente:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

Se vuoi convertire le `scoped enumerations` in numeri interi, puoi usare `static_cast<int>`.
