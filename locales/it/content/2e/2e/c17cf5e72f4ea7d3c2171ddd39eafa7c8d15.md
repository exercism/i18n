# Introduzione

L'uso del pattern matching è predominante nel codice Elixir assertivo e idiomatico. Ricorderai che `=/2` viene descritto come un operatore di match e non come un operatore di assegnazione. Quando usi l'operatore di match, se il pattern a sinistra corrisponde a quello a destra, le variabili a sinistra vengono legate e viene restituito il valore del lato destro. Se non c'è un match, viene sollevato un `MatchError`.

```elixir
2 = 2
# => 2
# Literals can be matched if they are the same

2 = 3
# => ** (MatchError) no match of right hand side value: 3

{_, denominator} = Float.ratio(0.25)
# => {1, 4}
# the variable `denominator` is bound to the value 4
```

Ricorda: il match avviene da destra verso sinistra.

Nell'ultimo esempio, se in un pattern match non ci serve una variabile, possiamo scartarla scrivendo `_`. Il runtime non tiene traccia di alcuna variabile che inizia con un `_`.

## Il pattern matching nelle funzioni con nome

Il pattern matching è anche uno strumento utile quando definisci più clausole di una funzione. Si può usare sugli argomenti delle funzioni, e questo determina quale clausola viene chiamata: si parte dall'inizio del file e si scende fino al primo match. Le variabili possono essere legate nella testa della funzione e usate nel corpo della funzione.

```elixir
defmodule Example do
  def named_function(:a = variable_a) do
    {variable_a, 1}
  end

  def named_function(:b = variable_b) do
    {variable_b, 2}
  end
end

Example.named_function(:a)
# => {:a, 1}

Example.named_function(:b)
# => {:b, 2}

Example.named_function(:c)
# => ** (FunctionClauseError) no function clause matching in Example.named_function/1
```
