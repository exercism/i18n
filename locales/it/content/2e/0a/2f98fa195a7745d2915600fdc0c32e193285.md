# Informazioni

In Rust, un iteratore è qualsiasi valore che implementa il trait [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html).
Un iteratore può essere fatto avanzare manualmente chiamando il metodo `next` sull'iteratore stesso.

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Molte delle [`collections`](https://doc.rust-lang.org/std/collections/index.html) di Rust implementano
[`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html),
che può produrre un `Iterator` a partire dai valori della collezione.

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

Nota che, anche se `IntoIterator::into_iter` consuma il proprio tipo `self`, quel tipo non deve necessariamente essere un valore posseduto.
Esistono quindi implementazioni di `IntoIterator` per [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2),
per [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)
e per [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1).
Queste implementazioni per diversi gradi di proprietà offrono una flessibilità utile.

Non è necessario capire i `traits` per questo concetto: avremo un intero esercizio dedicato a padroneggiare i `traits`.
Per ora, ricorda solo che:

- Qualsiasi tipo che implementa `IntoIterator` è chiamato _iterabile_ perché può essere trasformato in un iteratore.
- Qualsiasi tipo che implementa `Iterator` è un iteratore, che _produce_ valori e su cui si può _iterare_.
- Puoi ottenere un iteratore da qualsiasi tipo che implementa `IntoIterator` chiamando il suo metodo `into_iter`.
- Ogni iteratore [implementa `IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25) e produce se stesso.
- I cicli `for` operano sempre su iteratori e chiamano `IntoIterator` implicitamente sul proprio argomento di tipo range.

## `into_iter` e i cicli for

Probabilmente conosci già i cicli for su un vettore:

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

In sostanza, un ciclo `for` è solo una scorciatoia per chiamare il metodo `into_iter` del suo argomento,
e poi chiamare `next()` finché non smette di produrre elementi. In altre parole, il ciclo precedente si traduce in:

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## I metodi `iter` e `iter_mut`

La maggior parte dei tipi collezione di Rust fornisce i metodi `iter` e `iter_mut`.
Per una collezione di tipo `T`, questi due metodi si comportano per convenzione nel modo seguente:

- L'iteratore restituito da `iter` produce un `&T` preso in prestito in modo immutabile.
- L'iteratore restituito da `iter_mut` produce un `&mut T` preso in prestito in modo mutabile.

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## Differenza tra `iter`, `iter_mut` e `into_iter`

Se `iter`, `iter_mut` e `into_iter` producono tutti degli iteratori, quali sono le differenze?

- L'iteratore restituito da `iter` produce per convenzione un `&T` preso in prestito in modo immutabile.
- L'iteratore restituito da `iter_mut` produce per convenzione un `&mut T` preso in prestito in modo mutabile.
- L'iteratore restituito da `into_iter` può produrre `T`, `&T` o `&mut T`, a seconda del contesto.

Qual è il contesto di una chiamata a `into_iter`?
Il suo tipo `self`.
Ricorda che esistono implementazioni di `IntoIterator` per `Vec`, `&'a Vec` e `&'a mut Vec`.
Pertanto:

- `(&v).into_iter()` equivale a `v.iter()` => restituisce `&T`
- `(&mut v).into_iter()` equivale a `v.iter_mut()` => restituisce `&mut T`
- `v.into_iter()` => restituisce `T` e sposta i valori

Questo è più chiaro nei cicli for:

- `for num in &v {...}` => associa `&T`
- `for num in &mut v {...}` => associa `&mut T`
- `for num in v {...}` => associa `T` e sposta i valori

Spesso è più chiaro scrivere `v.iter()` invece di `(&v).into_iter()`.
Ci sono quindi ragioni di ergonomia per preferire `iter` e `iter_mut` a `into_iter`.

## Usare i metodi integrati per gli iteratori

Gli iteratori offrono numerosi metodi integrati, come `map`, `filter` e `collect`.
A volte questi metodi si usano insieme alle closure.

`map` usa una closure per trasformare i valori di un iteratore.
`take` tronca un iteratore (potenzialmente infinito) in uno che termina dopo al massimo il numero di elementi specificato.

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter` trasforma l'iteratore in uno che restituisce solo i valori per cui la closure restituisce `true`.
`count` consuma l'iteratore e restituisce il numero di elementi prodotti.

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map` trasforma un iteratore trasformando ogni elemento in un nuovo iteratore tramite la closure fornita,
per poi appiattire tutti i nuovi iteratori prodotti concatenandoli tra loro.
`collect` produce una nuova collezione,
a patto che il tipo della collezione implementi [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html).

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

Il [trait `Iterator`](https://doc.rust-lang.org/std/iter/trait.Iterator.html) fornisce _molte_ trasformazioni utili di questo tipo;
vale la pena leggere la documentazione e prenderci familiarità.

## Pigrizia

È importante sapere che gli iteratori di Rust sono pigri:
non producono alcun valore finché non consumiamo l'iteratore.
Se scrivi ed esegui il codice seguente:

```rust
(0..5).map(|x| x * x);
```

Otterrai il seguente errore del compilatore:

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

Questo succede perché `map` è un metodo adattatore che restituisce un altro iteratore.

Per consumare un iteratore, usa un ciclo `for` oppure un metodo dell'iteratore che produce un valore che non è esso stesso un iteratore.

Per esempio, `collect` è un metodo consumatore (la sua firma di funzione non restituisce un iteratore ma un tipo generico):

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
