# Approfondimento

È improbabile che ti imbatterai in molto codice di produzione che non faccia uso dei namespace.

Un esempio della sintassi è:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

I namespace sono un modo per raggruppare codice correlato ed evitare conflitti di nomi.

Secondo la [documentazione ufficiale][namespaces], i namespace hanno due ruoli principali:

- Primo, .NET usa i namespace per organizzare le sue numerose classi
- Secondo, dichiarare i propri namespace può aiutarti a controllare lo scope dei nomi di classi e metodi in progetti di programmazione più grandi.

I namespace sono ampiamente usati dalla libreria di classi di base (BCL) per organizzare le sue funzionalità.

## Riferimenti ai tipi nei namespace

I tipi racchiusi nei namespace vengono indicati, al di fuori del namespace, anteponendo al nome del tipo la sintassi con il punto. In alternativa, e più spesso, puoi inserire una direttiva `using` all'inizio del file (o all'interno di un namespace), e qualsiasi tipo del namespace importato può essere usato senza il prefisso. All'interno dello stesso namespace non c'è bisogno di qualificare i nomi dei tipi.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

Questo [articolo][using] spiega chiaramente in quali modi si può usare la direttiva `using`:

- `using`: evita di dover qualificare i tipi con il namespace
- `using static`: evita di dover qualificare i membri con i tipi (un buon esempio è `Math.Max()`).
- `using MyAlias = YourNamespace;`: sostituisce il nome del namespace con uno più leggibile.

## Conflitto tra namespace

.NET affronta il problema di due namespace con lo stesso nome in assembly diversi, dove ci sarebbe un conflitto tra nomi di identificatori completamente qualificati (magari uno scenario in cui vengono caricate più versioni di un assembly). Questo problema viene risolto con il [qualificatore di alias di namespace][namespace-alias-qualifier] e l'[alias extern][extern-alias].

Uno dei motivi per affrontare questo argomento piuttosto di nicchia è l'uso dell'[operatore `::`][dot-dot-operator]. Spesso vedrai il qualificatore `global::` anteposto ai namespace, soprattutto nel codice generato. L'intento è evitare un potenziale conflitto con un namespace annidato o un nome di classe. Anteponendo `global::` a un namespace, ti assicuri che venga selezionato un namespace di primo livello.

## Nota per gli sviluppatori Java

Confrontando con l'`import` dei `packages` di Java, vale la pena notare alcune differenze e somiglianze:

- In C# non esiste un equivalente dell'importazione di tipi specifici.
- `using static` e `import static` sono equivalenti.
- In Java, i nomi dei package hanno un impatto sull'accessibilità tra i jar. In C#, gli assembly sono fondamentali e appartenere allo stesso namespace non influisce sul livello di accesso.
- La relazione tra i percorsi del file system e i nomi di classe completamente qualificati in Java non si ritrova nei namespace di C#, anche se è buona pratica, quando possibile, dare a un file lo stesso nome della classe principale che contiene.
