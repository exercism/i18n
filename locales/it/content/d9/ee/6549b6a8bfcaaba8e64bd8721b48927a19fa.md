# Introduzione ai condizionali

## Il concetto di verità in Bash

Bash non ha il concetto di valori booleani.
Ci sono stringhe e numeri, e array di stringhe o numeri.
Quindi, come fanno i comandi condizionali a gestire vero e falso?

## Lo stato di uscita

I comandi producono uno _stato di uscita_ quando terminano.
Uno stato di uscita è un numero intero compreso tra 0 e 255 inclusi.
Bash considera uno stato di uscita **zero** come _successo_.
Qualsiasi altro stato di uscita rappresenta un _fallimento_.

Questo vale per tutti i comandi, compresi i comandi incorporati di bash, le parole chiave e le funzioni.

## Il comando "if"

La sintassi di base del comando `if` è

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

Inizia con `if`; `then` separa i comandi della condizione dai comandi del «successo»; e termina con `fi`.
La clausola `else` è opzionale.

CONDITIONAL_COMMANDS può essere un singolo comando oppure una [lista di comandi][command-list].

I CONDITIONAL_COMMANDS vengono eseguiti e

* se lo stato di uscita è zero (successo), allora vengono eseguiti i TRUE_COMMANDS.
* se lo stato di uscita è diverso da zero (fallimento), allora vengono eseguiti i FALSE_COMMANDS, se presenti.

Si possono creare rami a cascata con `elif`
```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

Ci deve essere un punto e virgola o una nuova riga prima delle parole `then`, `elif`, `else` e `fi`.

Per sottolinearlo: è lo **stato di uscita** dei comandi condizionali a controllare il flusso.
Per esempio, `grep` restituisce 0 se trova una corrispondenza e 1 se non la trova.
L'opzione `-q` sopprime l'output e produce solo lo stato di uscita.

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## I comandi "[" e "test"

Non c'è alcuna sintassi speciale attorno ai CONDITIONAL_COMMANDS.
Forse sei abituato a vedere istruzioni if che assomigliano a questa:

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

`[` non è una sintassi speciale.
È un _comando_ che valuta l'espressione condizionale ed esce con uno stato di successo o di fallimento.
Come per tutti i comandi, lo spazio bianco è **obbligatorio** tra esso e i suoi argomenti.

`[` è in realtà un sinonimo del comando `test`.
Sono esattamente la stessa cosa, tranne per il fatto che l'ultimo argomento di `[` _deve_ essere `]`.

### Le espressioni condizionali

Tra `[` e `]` scrivi un'espressione condizionale.
Alcune espressioni condizionali tipiche sono:

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

Ci sono molte altre operazioni disponibili; sono elencate nella sezione [Bash Conditional Expressions][cond-expr] del manuale.

~~~~exercism/note
Negli esempi qui sopra, nota che tutte le variabili sono tra virgolette.
I comandi `test` e `[` sono comandi normali, in cui gli argomenti sono soggetti alla suddivisione in parole e all'espansione dei nomi di file come per qualsiasi altro comando.

È importante sottolinearlo perché le espressioni condizionali vengono valutate in modo diverso a seconda di _quanti argomenti_ fornisci:

* 0 argomenti: lo stato di uscita è diverso da zero (fallimento)
* 1 argomento: lo stato di uscita è zero (successo) se l'argomento non è vuoto, diverso da zero se è vuoto.
* 2 argomenti: il primo argomento deve essere un operatore unario (come `[ -z "$name" ]`) oppure un `!` (che nega lo stato del test a 1 argomento)
* e [altri ancora][test].

Puoi ottenere risultati inattesi se dimentichi le virgolette:

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## La parola chiave "[["

Il [costrutto condizionale `[[...]]`][cond-construct] non è un _comando_, è una **parola chiave**.
Questo significa che, anche se viene gestito come qualsiasi altro comando, ha regole di parsing speciali.
La particolarità di `[[` è che le variabili espanse al suo interno **non** sono soggette alla suddivisione in parole né all'espansione dei nomi di file.
Ciò significa che questo comando si comporta come ti aspetti, anche senza virgolette.

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

`[[` supporta tutte le espressioni condizionali che `test` e `[` sanno gestire.
Inoltre, `[[` offre

* l'operatore `=~` per la corrispondenza con espressioni regolari,
* `==` e `!=` che funzionano come operatori di corrispondenza con pattern glob,
* `&&` e `||` come operatori logici (regola di parsing speciale),
* `<` e `>` come operatori di confronto tra stringhe «nudi» (regola di parsing speciale: poiché sono simboli di redirezione, in `[` devono essere preceduti da un carattere di escape).

È opinione diffusa che queste funzionalità speciali offrano così tanti vantaggi che `[[` dovrebbe essere usato in via esclusiva.
(Per esempio, la [Google Shell Style Guide][goog-test].)

## Il comando "case"

[`case`][case] è un altro comando di controllo del flusso.
È simile a un'istruzione «switch» di altri linguaggi.

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

La WORD viene confrontata con ciascun PATTERN.
Quando uno corrisponde, i COMMANDS vengono eseguiti.

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

Ogni clausola COMMANDS deve terminare con **due** punti e virgola, `;;`.
