# Test

Ogni esercizio fornisce i test unitari e una ricetta di build per CMake. L'implementazione la scrivi tu.

Ogni file di test è pensato per essere collegato all'implementazione, così da produrre un eseguibile da console che esegue i test. Eseguendo l'eseguibile dei test vengono stampati messaggi per ogni test che fallisce e viene riportato uno stato di uscita diverso da zero quando i test falliscono.

*Nota:* il codice viene testato con la suite di test ogni volta che compili il progetto. Se il codice non supera uno o più test ma è comunque codice C++ valido, verrà compilato lo stesso.

Lavorare su ogni esercizio è un processo fatto di:

* Creare la build iniziale con CMake
* Per ogni test unitario:
  * Risolvere gli errori di compilazione per far fallire il test.
  * Implementare solo quanto basta per far passare il test.
  * Riorganizzare l'implementazione per migliorarne la leggibilità, ridurre le duplicazioni e così via.
  * Togliere il commento dal test successivo

## Creare la build iniziale con CMake

Ogni esercizio porta con sé un file `CMakeLists.txt` insieme ai test unitari. Contiene la ricetta CMake preconfezionata che gestisce la build. Non dovresti avere bisogno di modificare questo file. La ricetta fornita presuppone che l'implementazione esista sotto forma di un file header e di un file sorgente che prendono il nome dall'esercizio.

Per esempio, l'esercizio `bob` si aspetta un'implementazione in `bob.h` e `bob.cpp`. Per gli esercizi con un trattino nel nome, si presume che i file sorgente usino gli underscore, quindi `word-count` si aspetta `word_count.h` e `word_count.cpp`. Puoi decidere che l'implementazione sia abbastanza semplice da stare interamente nell'header, nel qual caso puoi omettere il file `cpp`.

**Crea i file di implementazione iniziali prima di eseguire CMake.** Se non hai i file `bob.h` e `bob.cpp` quando esegui CMake per l'esercizio `bob`, CMake genererà un errore perché non trova i file. **Questi file possono essere vuoti, ma devono esistere.**

Con questa ricetta, CMake può generare un progetto adatto al tuo ambiente eseguendo `cmake -G` con un generatore adeguato e il percorso della cartella dell'esercizio. CMake genererà uno script di build appropriato per il tuo sistema operativo. Per tenere i file generati separati dal codice sorgente dell'esercizio, è comune creare una cartella chiamata `build` che contenga sia questi file di build generati sia il codice compilato. Così la cartella dell'esercizio resta ordinata e pulita.

Una volta che CMake ha creato l'ambiente di build, puoi compilare il codice con il comando appropriato per il tuo ambiente:

* Linux con make: `make`
* Windows con Visual Studio: seleziona Build / Build Solution dal menu.
* MacOS con Xcode: seleziona Build dalla barra degli strumenti
* MacOS con "Unix Makefile": `make` _se usi l'app CLI di Exercism_

Qui sotto trovi alcuni esempi di esecuzione di CMake in ambienti diversi.

### Linux con Make

Il nome del generatore per CMake è `Unix Makefiles`.
Supponendo che l'esercizio corrente sia `bob` e che ci troviamo nella cartella dell'esercizio:

```sh
$ touch bob.{h,cpp}
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

Questo esempio mostra come creare file vuoti per l'implementazione prima di eseguire CMake.

Digita semplicemente `make` nella cartella di build per compilare i test. Dovrebbero comparire errori di compilazione. Una volta risolti, `make` compilerà ed eseguirà i test.

### Windows con Visual Studio

Visual Studio supporta nativamente i progetti CMake, quindi non dovresti aver bisogno di installare CMake separatamente né di eseguirlo fuori da Visual Studio. Segui
[questa guida](https://docs.microsoft.com/en-us/cpp/build/cmake-projects-in-visual-studio)
per configurare il progetto CMake in Visual Studio.

### MacOS con Xcode

Il nome del generatore per CMake è `Xcode`.
Supponendo che l'esercizio corrente sia `bob` e che ci troviamo nella cartella dell'esercizio:

```sh
$ touch bob.{h,cpp}
$ mkdir build
$ cd build
$ cmake -G Xcode ..
```

Questo esempio genera i file XCode in modo che tu possa aprire il progetto in XCode.
Con il progetto aperto in XCode potresti dover aggiungere un altro target.
Per aggiungere un nuovo target, vai su File -> New -> Target dal menu, _OS X \ Application \ Command Line Tool_, poi Next, scegli _C++_ come linguaggio e indica un nome per il target. Esegui il codice usando il target.

Se il terminale restituisce un errore `Xcode x.x not supported`, è molto probabile che Xcode non sia installato sul tuo computer o che la tua versione sia obsoleta.
Scarica e installa Xcode dall'App Store oppure da [questo link][web-xcode-download].
Errori simili a `The CXX compiler identification is unknown` si risolvono probabilmente seguendo le [istruzioni per installare GCC][cpp-installation-instructions] oppure aggiungendo un altro target in Xcode come descritto nel paragrafo precedente.

[web-xcode-download]: https://apps.apple.com/us/app/xcode/id497799835?mt=12
[cpp-installation-instructions]: https://exercism.org/docs/tracks/cpp/installation

### MacOS con Make _quando usi la CLI di Exercism_
#### Questo esempio è pensato appositamente per chi vuole usare l'app CLI di Exercism per configurare, testare e inviare i propri esercizi C++.

Il nome del generatore per CMake è `Unix Makefiles`.
Supponendo che l'esercizio corrente sia `bob` e che ci troviamo nella cartella dell'esercizio:

```sh
$ touch bob.{h,cpp}
$ cmake -G "Unix Makefiles" .
$ exercism test
```

In questo esempio creiamo effettivamente dei file vuoti per l'implementazione prima di eseguire CMake, ma **non** creiamo una cartella di build vuota.
Il motivo è che la CLI di Exercism usa il file `.exercism/metadata.json` nella cartella principale per analizzare i casi di test.

Digita semplicemente `exercism test` nella cartella principale per compilare i test. Dovrebbero comparire errori di compilazione.
Una volta risolti, eseguendo di nuovo `exercism test` la CLI di Exercism compilerà ed eseguirà i test.

[cpp-installation-instructions]: https://exercism.org/docs/tracks/cpp/installation
