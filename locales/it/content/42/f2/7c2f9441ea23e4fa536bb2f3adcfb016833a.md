# Introduzione

## Record

[I record][records] sono strutture dati che raggruppano insieme informazioni correlate con delle etichette. Sono simili agli oggetti in JavaScript o Java, o alle struct in C o Rust, ma con alcune differenze importanti.

### Creare i record

I record si [creano][create] con le parentesi graffe (`{}`) e i loro elementi sono separati da virgole.

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Anche il tipo di un record si definisce con una sintassi simile, tranne per il fatto che i segni di uguale `=` vengono sostituiti dai segni di due punti `:`.

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Ripetere queste definizioni di tipo è scomodo, quindi usare un [type alias][record-types] per condividere la definizione è un idioma comune.

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

L'alias di tipo fornisce anche automaticamente una funzione costruttrice per il record.
Questo a volte sorprende, dato che in Elm le funzioni devono iniziare con una lettera minuscola, ma i costruttori di tipo sono una delle eccezioni.

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

### Accedere ai campi di un record

Il modo principale per [accedere al valore di un campo di un'istanza di un record][access] è usare la notazione con il punto, come `firefly.creator`.
Il compilatore Elm supporta anche speciali funzioni di accesso che iniziano con un punto `.`, come `.creator`, che funzionano su qualsiasi record con un campo con quel nome.
Questa è la seconda eccezione alla regola secondo cui le funzioni devono iniziare con una lettera minuscola.
In realtà le funzioni definite dall'utente devono iniziare con una lettera minuscola, ma i due esempi che abbiamo appena visto sono generati dal compilatore, non dal programmatore.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

I record si possono anche _destrutturare_ nelle associazioni, usando il [record pattern matching][pattern-matching].
La destrutturazione funziona con qualsiasi record che abbia campi con i nomi in questione.

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

### Aggiornare i record

I record sono immutabili, come tutto in Elm, quindi una volta definito un record, i valori dei suoi campi non possono mai cambiare.
Esiste una [sintassi speciale per creare una copia di un record esistente cambiando uno o più campi][update].
Questa sintassi usa il simbolo pipe `|` per distinguere il record originale dai campi che cambieranno, come in `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

### Confrontare i record

Elm usa l'[uguaglianza strutturale][equality], il che significa che due istanze dello stesso record con valori identici sono uguali.

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

### Record estensibili

Elm supporta anche la [tipizzazione strutturale][structural-typing], il che significa che se una funzione richiede un record con un campo x e un campo y, funzionerà con qualsiasi record che abbia quei campi, come punti 2D, punti 3D, astronavi e così via.
Quei tipi di record hanno una pipe `|` nella loro definizione, come `{ a | x : Float, y : Float }`, e nella terminologia di Elm sono chiamati «record estensibili».
Attenzione alla differenza tra una pipe `|` in una definizione di tipo, che è una definizione di record estensibile (`{ a | x : Int }`), e una pipe `|` in un'istanza di record vera e propria, che significa che stiamo aggiornando alcuni campi di quel record.

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
