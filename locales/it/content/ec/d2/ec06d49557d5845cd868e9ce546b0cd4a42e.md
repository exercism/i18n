# Informazioni

L'I/O di Factor è costruito su un unico [protocollo][stream-protocol] che qualsiasi sorgente o destinazione di dati può implementare. Gli stream inclusi, `<file-reader>`, `<file-writer>`, `<string-reader>`, `<string-writer>`, i socket di rete, gli array di byte, i tty, sono tutte classi che implementano lo stesso piccolo insieme di parole generiche di [`io`][io] ed estendono `disposable` di [`destructors`][destructors].

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe` è la lettura batch di basso livello: riempi un buffer fornito da chi chiama e restituisci quanti elementi sono stati scritti. Le parole pubbliche `stream-read` e `stream-read-partial` sono costruite su di essa e gestiscono l'allocazione. La maggior parte degli stream definiti dall'utente implementa `stream-read1` (quando le letture avvengono un elemento alla volta) oppure `stream-read-unsafe` (quando le letture possono essere raggruppate).

`stream-element-type` restituisce uno di due token singleton: `+byte+` per gli stream di byte (lettori di file, socket) e `+character+` per gli stream di caratteri (lettori di stringhe, tty). Uno stream wrapper di solito si limita a delegare allo stream sottostante.

## Aderire ai mixin

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

Una classe può essere l'uno, l'altro o entrambi. Aderire al mixin fa sì che i metodi predefiniti di `input-stream` / `output-stream` facciano dispatch sulla tua classe: lo stesso schema open-mixin di `set` nel vocabolario `sets`.

## Il framework disposable

`new-disposable ( class -- disposable )` registra una nuova istanza nello scope attuale dei distruttori, così che un'eccezione a metà della preparazione delle risorse si risolva in modo pulito:

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose` è la parola pubblica, `dispose*` è la parola generica che la classe implementa. Un override di `dispose*` in una sottoclasse dovrebbe ripulire il proprio stato e poi liberare le risorse che possiede:

```factor
M: my-stream dispose* underlying>> dispose ;
```

Il framework garantisce che `dispose*` venga eseguita al massimo una volta per oggetto: le chiamate ripetute a `dispose` non hanno alcun effetto.

## Accessor con scope

Tre combinatori impostano lo stream globale «input/output corrente» usato da `print`, `read1`, ecc.:

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

Ciascuno libera la risorsa all'uscita, anche se la quotation lancia un'eccezione. È così che la maggior parte del codice usa uno stream personalizzato, invece di passarlo attraverso ogni chiamata.
