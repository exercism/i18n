# Informazioni

Il tipo `Result` consente a una funzione di restituire un unico valore che indica tutte queste cose:
- Se l'operazione è riuscita o è fallita
- In caso di successo, il valore risultante dell'operazione
- In caso di fallimento, il motivo del fallimento

In altri linguaggi di programmazione che non supportano qualcosa come un tipo `Result`, è comune trovare i seguenti schemi per raggiungere gli obiettivi appena citati:
- Una funzione che restituisce un codice numerico che indica il successo o il motivo del fallimento e che richiede un parametro di output per accogliere il valore in caso di successo.
- Una funzione che restituisce il valore in caso di successo o NULL in caso di errore, e poi un'altra funzione per ottenere il codice di errore che indica il motivo del fallimento.

Un altro meccanismo comune di gestione degli errori è l'eccezione, che interrompe bruscamente l'esecuzione della funzione corrente e
trasferisce il controllo al primo gestore nello stack di chiamate quando si verifica un errore.  
Se nessun gestore «cattura» l'eccezione, il programma termina.

## Vantaggi dell'uso del tipo `Result`

* __Sicurezza a tempo di compilazione__: rendendo espliciti nel sistema dei tipi il successo o il fallimento di una chiamata di funzione, il compilatore può garantire che il codice chiamante gestisca tutti i casi di fallimento, prevenendo un'ampia categoria di bug che potrebbero verificarsi con i valori null.

* __Sicurezza a tempo di esecuzione__: invece di usare `null`, il tipo `Result` usa `Error` per rappresentare un fallimento, rendendo impossibile il verificarsi di una `NullReferenceException`.

* __Gestione esplicita degli errori__: il codice che chiama una funzione che restituisce un `Result` deve riconoscere che la
chiamata può fallire; il codice chiamante deve gestire questi fallimenti in modo intenzionale.  Non ci sono fallimenti silenziosi e nessuna eccezione a sorpresa.

* __Flusso di controllo prevedibile__: un `Result` viene restituito come qualsiasi altro valore; non salta fuori dallo stack di chiamate come un'eccezione.  Sai sempre da dove hanno origine gli errori e come si propagano.

* __Leggibilità e manutenibilità migliorate__: restituendo un `Result`, la firma di una funzione indica chiaramente il comportamento previsto in caso di successo e di fallimento.

## Utilizzo

Il tipo `Result` è un tipo generico che contiene due tipi sottostanti:
- In caso di operazione riuscita, il tipo del valore risultante
- In caso di fallimento, il tipo che ne rappresenta il motivo

Il tipo `Result` è anche un'[unione discriminata][discriminated-union] con i seguenti casi possibili:
* `Ok <value>` che rappresenta un risultato riuscito
* `Error <reason>` che rappresenta un fallimento

La funzione seguente mostra come creare un valore `Result`:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

In questo esempio, il valore `Ok` è una stringa (il nome fornito) e anche il valore `Error` è una stringa (la causa dell'errore, in una forma leggibile da una persona).

## Leggere il contenuto di un valore `Result`

Considera la seguente definizione di tipo e la seguente firma di funzione:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

Il codice che chiama la funzione `openFile` può usare il pattern matching per gestire i casi di successo e di fallimento, come nell'esempio seguente:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
