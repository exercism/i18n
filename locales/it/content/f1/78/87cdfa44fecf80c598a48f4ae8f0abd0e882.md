# Le basi di Unison

## I termini e le funzioni

I termini e le funzioni sono le unità di base per scrivere un programma Unison.

Un «termine» è quello che chiamiamo un valore statico. Si definisce con `name = expression`, eventualmente preceduto da una firma di tipo nella forma `name : MyType`. Unison supporta l'inferenza dei tipi, quindi per le definizioni semplici potresti vedere la firma di tipo omessa.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Le funzioni di Unison hanno la forma `myFunctionName argument1 argument2 = myImplementation`: iniziano con il nome della funzione, seguito dagli argomenti separati da spazi.

```
getMax a b = Nat.max a b
```

Le funzioni possono includere facoltativamente una firma di tipo. L'ultimo tipo a destra è sempre il tipo restituito dalla funzione, ed ogni argomento è separato dalla freccia di funzione `->`.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Per chiamare una funzione, usa il suo nome seguito dagli argomenti separati solo da spazi.

```
maximum = getMax 1 10
```

Quando chiami una funzione, Unison prova a considerare come suo argomento qualunque cosa si trovi immediatamente alla sua destra: questo può non produrre l'ordine di valutazione delle funzioni che desideri.

Supponiamo di voler ottenere il valore `1` dalla seguente espressione

```
shouldBe1 = getMax 1 10 - 10
```

Così com'è scritta, `shouldBe1` vale `0`, perché l'ordine implicito di applicazione della funzione è `getMax 1 10`, cioè `10`, e poi `10 - 10`, cioè `0`.

Puoi usare le parentesi per raggruppare l'espressione nell'ordine delle operazioni che desideri.

```
shouldBe1 = getMax 1 (10 - 10)
```

## Funzioni su più righe

Le funzioni Unison su più righe usano l'indentazione o i blocchi `let` per delimitare le porzioni di codice, il cosiddetto «scope lessicale» (ambito di visibilità).

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Tutto ciò che si trova allo stesso livello di indentazione condivide lo stesso scope: è per questo che possiamo riferirci alla variabile `newBeginning` nell'ultima riga.

## I namespace e le istruzioni `use`

I namespace servono a raggruppare ed organizzare le funzioni di Unison. Puoi vederli come l'equivalente delle «directory»: offrono struttura e raggruppamento logico.

Puoi portare le funzioni di un namespace nello scope con un'istruzione `use`.

Immagina di scrivere una funzione che usa i valori `List` di Unison. Sai che ti serviranno funzioni come `List.map` e `List.flatMap`, dove `List` è il namespace e `map` e `flatMap` sono funzioni. Per non ripeterti, puoi portare tutto il namespace `List` nello scope lessicale della funzione, così:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

La riga `use List` chiarisce i riferimenti a `map` e `flatMap`. Puoi leggere di più sulle [istruzioni `use` qui][use-statements].

## La libreria standard di Unison

La libreria standard di Unison si chiama `base`. Se hai seguito la guida di avvio rapido e hai una codebase creata in locale, la libreria standard dovrebbe essere stata scaricata automaticamente. Puoi consultare la documentazione della libreria standard online su [Unison Share][unison-share-base].

## I commenti e i letterali di documentazione

I commenti in Unison sono una caratteristica un po' insolita. Quando scrivi codice Unison, puoi creare del testo in un file con estensione `.u` che non viene interpretato, con la seguente sintassi:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Tuttavia_, poiché il codice Unison viene salvato come hash del suo albero sintattico astratto, e non come file di testo sul file system, i commenti, che sono «decorazioni» testuali di una data funzione o di un dato termine Unison nel file, non possono davvero essere salvati e riprodotti per la condivisione. Se vuoi aggiungere un'informazione ad un termine Unison in modo che venga conservata perché altri possano leggerla e capirla, puoi usare un letterale di documentazione.

La documentazione è un valore di prima classe nel linguaggio di programmazione Unison. Questo significa che un elemento `Doc` può essere assegnato ad un valore, passato come valore ad una funzione o restituito come valore di una funzione. Gli elementi letterali di documentazione si aprono e si chiudono con doppie parentesi graffe. Ecco come potremmo usare l'elemento `Doc` come commento.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
