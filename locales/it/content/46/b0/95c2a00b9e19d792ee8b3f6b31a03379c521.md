# Appendice alle istruzioni

## Note aggiuntive per l'implementazione in C++

Ci sono diversi modi per ottenere il parallelismo in C++.
Il runner online di Exercism supporta C++17, quindi puoi usare le politiche di esecuzione della [libreria degli algoritmi][algorithm].
Un'altra opzione è gestire manualmente i [thread][thread].
Tieni però presente che generare un thread è piuttosto costoso (usare un [pool][pool] di thread aiuterebbe).

Quando lavori in locale, puoi naturalmente usare quello che vuoi.
Una soluzione che usa librerie non standard, però, molto probabilmente non funzionerà con il runner online di Exercism.

### Benchmark

Quando lavori in locale, puoi facoltativamente eseguire un benchmark per avere un'idea del miglioramento delle prestazioni delle diverse implementazioni.
Attivando il flag CMake `EXERCISM_INCLUDE_BENCHMARK` si abilita il benchmark:
```
cmake -DEXERCISM_RUN_ALL_TESTS=1 -DEXERCISM_INCLUDE_BENCHMARK=1 .
```

### Supporto dei compilatori agli algoritmi paralleli

L'implementazione della libreria standard C++ da parte di GCC (`libstdc++`) si basa su [TBB][tbb].
Se TBB non è disponibile, verrà usata una versione sequenziale come ripiego, anche quando è richiesta l'esecuzione parallela.

Su Ubuntu, devi installare il pacchetto `libtbb-dev`:
```
apt-get install libtbb-dev
```

Su macOS, puoi usare [Homebrew][homebrew] per installare TBB:
```
brew install tbb
```

A partire dalla versione 17, `libc++` di Clang offre un supporto sperimentale e parziale per gli algoritmi paralleli.
Per attivarlo, bisogna passare il flag del compilatore `-fexperimental-library`.

Apple Clang 15 e versioni precedenti _non_ supportano gli algoritmi paralleli.

Su Linux e macOS ti consigliamo di usare GCC (insieme alla `libstdc++` predefinita) per questo esercizio.

MSVC di Microsoft supporta gli algoritmi paralleli almeno da VS 2017 15.7, senza dover installare librerie aggiuntive.
