# Istruzioni

Stai scrivendo il firmware per il sistema di punteggio di una console portatile retrò.
La CPU della macchina è modesta, ed il display del tabellone dei punteggi si aggiorna ad una frequenza fissa.
Per mantenere l'immagine fluida, le routine di punteggio devono essere eseguite in un numero prevedibile di cicli, indipendentemente da ciò che sta facendo il giocatore.

Ci sono quattro attività da svolgere.

~~~~exercism/note
Il codice delle attività deve essere senza diramazioni.
Usa `cmovcc`, `setcc` e l'aritmetica al posto dei salti condizionali.
~~~~

## 1. Aggiungere un bonus senza mandare in overflow il display

La zona del punteggio dell'LCD della console ha spazio per sei cifre decimali.
Non può mostrare alcun numero superiore a `999999`.
Quando un bonus porterebbe il totale corrente oltre quel limite, il totale visualizzato viene mantenuto al massimo invece di ripartire da zero.

Definisci una funzione `add_bonus` che, dato un totale corrente e un bonus da aggiungere, restituisce il nuovo totale limitato a `999999`.
Gli argomenti, in ordine, sono:

1. `total`: il totale attuale del punteggio (sempre compreso tra `0` e `999999`)
2. `bonus`: il bonus da aggiungere (sempre non negativo)

Il valore restituito è `total + bonus` se tale somma è minore o uguale a `999999`, e `999999` in caso contrario:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

Sia gli argomenti sia il valore restituito sono interi con segno a 64 bit.

~~~~exercism/note
Puoi presumere che `total + bonus` non mandi in overflow un intero con segno a 64 bit.
~~~~

## 2. Confrontare due punteggi

La console conserva nel file di salvataggio una piccola classifica dei migliori punteggi recenti del giocatore.
Dopo ogni partita, il nuovo punteggio viene inserito nella classifica nella posizione corretta.
La routine di ordinamento chiede quale dei due punteggi sia in vantaggio e si aspetta la risposta come un piccolo intero.

Definisci una funzione `compare_scores` che, dati due punteggi, restituisce:

- `+1` se il primo punteggio è _più alto_
- `-1` se il primo punteggio è _più basso_
- `0` se i due punteggi sono _uguali_

Esempio:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

Sia gli argomenti sia il valore restituito sono interi con segno a 64 bit.

## 3. Convalidare un punteggio grezzo

La console può collegarsi a un'altra unità tramite il cavo di collegamento per condividere i punteggi dopo una partita multigiocatore.
Il cavo è elettricamente rumoroso e i byte in arrivo a volte si corrompono, producendo valori molto al di sotto del minimo consentito o molto al di sopra del massimo consentito.
Il validatore riporta ogni punteggio in arrivo nell'intervallo consentito prima che il resto del sistema lo veda.

Definisci una funzione `validate_score` che, dato un punteggio grezzo e i limiti consentiti, restituisce il punteggio limitato a `[min, max]`.
Gli argomenti, in ordine, sono:

1. `score`: il punteggio grezzo ricevuto dal cavo di collegamento
2. `min`: il punteggio minimo consentito
3. `max`: il punteggio massimo consentito

Il valore restituito è `min` se `score < min`, `max` se `score > max`, e `score` in caso contrario.
Puoi presumere che `min <= max`.

Esempio:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

Tutti gli argomenti e il valore restituito sono interi con segno a 64 bit.

## 4. Tenere traccia dei due punteggi più alti

Alla fine di ogni sessione di gioco, la console analizza il registro delle partite recenti nel file di salvataggio per trovare i due punteggi più alti mai registrati.
Il registro è un semplice array di interi con segno a 64 bit in memoria.
La scansione percorre l'array una sola volta e mantiene due massimi correnti: il più alto visto finora ed il secondo più alto.

Nota che entrambi i numeri devono essere almeno `0`.
Qualsiasi numero negativo viene ignorato.

Una prima versione della funzione era stata scritta con salti condizionali a cascata.
Per ogni candidato, il codice chiede dove si colloca (sopra il primo, tra il primo ed il secondo, oppure da nessuna parte) e sposta di conseguenza i massimi correnti, scartando ogni risultato negativo.

Questo funziona.
Tuttavia, poiché i valori di input sono casuali, ogni salto condizionale provoca molti errori di predizione delle diramazioni.
Ecco perché hai deciso di riorganizzare il ciclo principale in modo che sia senza diramazioni.

Qui sotto c'è la funzione con la sezione piena di diramazioni commentata:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

Sostituisci la sezione commentata con un'implementazione senza diramazioni.
L'unico salto consentito nel nuovo codice è quello che torna all'inizio del ciclo per controllare un nuovo elemento dell'array.

La funzione non ha valore restituito e accetta gli stessi argomenti della versione con diramazioni:

1. `out`: buffer di output in cui la funzione scriverà i due punteggi non negativi più alti in ordine decrescente, come interi con segno a 64 bit
2. `array`: array di input di interi con segno a 64 bit
3. `length`: il numero di elementi dell'array, come intero senza segno a 64 bit

~~~~exercism/note
Se l'array contiene valori duplicati, i duplicati possono comparire in entrambe le posizioni dell'output se sono i due punteggi più alti.
~~~~
