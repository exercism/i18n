# Informazioni

Le funzioni ricorsive sono funzioni che chiamano se stesse.

Una funzione ricorsiva deve avere almeno un _caso base_ e almeno un _caso ricorsivo_.

Un _caso base_ restituisce un valore senza chiamare di nuovo la funzione.
Un _caso ricorsivo_ chiama di nuovo la funzione, modificando l'input in modo che a un certo punto corrisponda al caso base.

In Elm, le funzioni ricorsive vengono in genere definite usando il pattern matching con le espressioni `case`.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

Una funzione ricorsiva può avere molti casi base e/o molti casi ricorsivi.
Per esempio, [la sequenza di Fibonacci][fibonacci] è una sequenza ricorsiva con due casi base:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

Nota che questa particolare implementazione è esponenzialmente lenta, dato che i numeri di Fibonacci correlati vengono calcolati da zero in due chiamate ricorsive indipendenti.

Contare il numero di occorrenze di un certo valore `x` in un array ha due casi ricorsivi:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## I cicli tramite la ricorsione

A causa dell'immutabilità, in Elm i cicli si scrivono diversamente rispetto ai linguaggi imperativi.
Per esempio, di solito un ciclo ha questo aspetto:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

In un linguaggio funzionale come Elm, non è possibile mutare le variabili.
Quindi i cicli vanno implementati con la ricorsione.

L'equivalente di un ciclo `for` in Elm sarebbe questo:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

In pratica, in Elm per iterare su array e altre strutture dati si usano il più delle volte funzioni del modulo [`List`][module-list], come `List.map`, `List.filter` e `List.foldl`.
Sotto il cofano, queste funzioni sono implementate usando la ricorsione.

## Esecuzione infinita

Le funzioni ricorsive, se implementate in modo errato o per un numero troppo grande di chiamate ricorsive, potrebbero non restituire mai il loro risultato.
Questo può essere problematico, perché ogni volta che una funzione viene chiamata viene memorizzato in memoria un riferimento al punto in cui il runtime deve restituire il risultato (sullo [stack di chiamate][wiki-call-stack]).
Se una funzione ricorsiva chiama se stessa troppe volte o addirittura all'infinito, si può esaurire la memoria e far andare in crash il runtime (un [errore di stack overflow][wiki-stack-overflow]).
Il runtime di Elm è ottimizzato per la ricorsione e l'affidabilità, ma la ricorsione infinita può comunque causare problemi.

Questo problema di esecuzione infinita può essere causato da:

- Dimenticare di implementare un caso base.
- Non gestire tutti i casi possibili nel pattern matching.
- Non modificare correttamente l'argomento quando si effettua la chiamata ricorsiva, e quindi non raggiungere mai il caso base.
