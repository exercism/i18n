# Nil

Crystal ha un tipo chiamato [`Nil`][nil], che può avere un solo valore: `nil`.
Viene usato per rappresentare l'assenza di un valore ed è simile a `null` o `None` in altri linguaggi.

I valori nil possono essere restituiti da vari metodi, per esempio [`String#[]?`][string-index], che restituisce `nil` se l'indice è fuori dai limiti.

```crystal
"foo"[10]? # => nil
```

Crystal ha quelli che vengono chiamati **CONTROLLI SUI RIFERIMENTI NULLI**, il che significa che tutti i tipi non possono essere `nil` per impostazione predefinita.
Questo significa che non puoi assegnare `nil` a una variabile, a meno che tu non la dichiari esplicitamente come tipo `Nil`.
Di conseguenza, il compilatore controllerà automaticamente i riferimenti nulli.

## Valore falso

Si possono adottare diversi approcci per gestire i valori `nil`.
`nil` è un valore [falso][truthy-falsey], così come lo è `false`.
Questo significa che nelle istruzioni e negli altri contesti in cui ci si aspetta un valore falso o veritiero, verrà trattato allo stesso modo di `false`.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Questo significa che il ramo veritiero non verrà percorso se una variabile che può essere `nil` ha valore `nil`.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Verificare nil

Crystal ha un metodo che può essere usato per verificare se un valore è `nil`.
Si chiama [`nil?`][nil?] ed è disponibile su tutti gli oggetti.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Questo è un po' diverso quando si usa semplicemente il valore in un'istruzione if, dato che negli ultimi esempi sia false che nil verrebbero trattati come falsi.
Qui solo `nil` viene trattato come falso, perché se fosse stato false non sarebbe stato nil e quindi sarebbe stato veritiero.

## Operatore or

Il modo più semplice per gestire i valori `nil` è assicurarsi che non diventino mai `nil` fin dall'inizio.
L'operatore or ([`||`][or]) viene spesso usato quando si ha a che fare con `Bools`, ma, se compreso correttamente, può essere usato anche per gestire i valori `nil`.
L'operatore or controlla se il primo valore è veritiero; in caso contrario, viene usato il secondo valore.
Questo può servire a fare in modo che, se il valore è `nil`, venga considerato falso e quindi venga usato il secondo valore.

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
Questo approccio va considerato come ultima risorsa e dovrebbe essere usato solo se sei **sicuro** che il valore non sia nil.
Se possibile, usa invece gli altri approcci.
~~~~

[`not_nil!`][not_nil] è un metodo che ti permette di comunicare al compilatore che un valore non è nil, facendo sì che il tipo che contiene non possa essere nil.
Lo fa sollevando un'eccezione se il valore è nil.

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
