# Introduzione

In C#, una gerarchia di _classi_ può essere definita usando l'_ereditarietà_, che permette a una classe derivata (`Car`) di ereditare il comportamento e i dati della sua classe genitore (`Vehicle`). Se non viene specificato alcun genitore, la classe eredita dalla classe `object`.

Le classi genitore possono fornire funzionalità alle classi derivate in tre modi:

- Definire un metodo normale.
- Definire un metodo `virtual`, che è come un metodo normale, ma che le classi derivate _possono_ cambiare.
- Definire un metodo `abstract`, cioè un metodo senza implementazione che le classi derivate _devono_ implementare. Una classe con metodi `abstract` deve essere contrassegnata come `abstract` a sua volta. Le classi astratte non possono essere istanziate.

Il modificatore di accesso `protected` permette di accedere a un membro della classe genitore in una classe derivata, ma blocca l'accesso dalle altre classi.

Le classi derivate possono accedere ai membri della classe genitore tramite la parola chiave `base`.

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

Il costruttore di una classe derivata chiamerà automaticamente il costruttore del suo genitore _prima_ di eseguire la logica del proprio costruttore. Gli argomenti possono essere passati al costruttore di una classe genitore usando la parola chiave `base`:

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

Quando più di una classe deriva da una classe base, le due (o più) classi implementeranno spesso versioni diverse di un metodo della classe base. Questo è un principio molto importante chiamato polimorfismo. Per esempio, in una variante dell'esempio precedente mostriamo come il codice che usa `Vehicle` possa cambiare comportamento a seconda del tipo di veicolo istanziato.

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```
