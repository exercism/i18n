# Classi astratte

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## Il $ fa parte del nome

Ogni classe astratta ha un `$` all'inizio del nome, e solo le classi astratte ce l'hanno. Quindi, se un tipo inizia con `$`, non puoi creare un oggetto di quel tipo, e la cosa si vede ovunque compaia il nome.

## Cosa può contenere

Firme di routine e iteratori, che terminano al punto e virgola. Niente corpi, niente attributi, niente `create`. Una classe astratta descrive ciò che si può *chiedere* a qualcosa, mai ciò che contiene.

## Conformità

```sather
class TRAPEZE < $ACT is
```

La classe deve definire ogni routine elencata, con tipi degli argomenti e tipo restituito corrispondenti. Il controllo avviene in fase di compilazione.

Una classe può essere conforme a più di una:

```sather
class TRAPEZE < $ACT, $RISKY is
```

e le classi astratte possono estendere l'una l'altra:

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## Dove avviene il dispatch

Una variabile di un tipo astratto contiene un riferimento a un oggetto conforme. Chiamare una routine su di essa sceglie la versione che appartiene alla classe effettiva dell'oggetto, a runtime.

Questo è l'unico punto in cui Sather decide qualcosa a runtime. Una chiamata su una variabile di un tipo concreto viene risolta in fase di compilazione.

## typecase

A volte il tipo preciso conta davvero. `typecase` chiede:

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

All'interno di un ramo, la variabile ha il tipo più specifico. Usalo raramente: un `typecase` su ogni tipo di atto di solito è una routine che sarebbe dovuta stare nella classe astratta fin dall'inizio.

## $OB

`$OB` è la classe astratta a cui ogni oggetto è conforme. A volte è utile, ma per lo più indica che un tipo è andato perso per strada.

## Perché non l'ereditarietà?

Sather separa due cose che la maggior parte dei linguaggi unisce. `<` dice solo ciò che una classe può *fare*. Ottenere un'implementazione da qualche altra parte è `include`, che è l'esercizio dopo il prossimo, e rappresenta una decisione separata.
