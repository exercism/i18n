# Introduzione

## Codice branchless

Il concetto dei condizionali introduce `jcc`, la famiglia di istruzioni per effettuare salti in base a una condizione.
Una `jcc` trasferisce l'esecuzione a un altro punto del programma solo se la sua condizione è soddisfatta.

Tuttavia, le CPU moderne sono veloci e capaci di eseguire molte istruzioni in parallelo.
Sarebbe troppo costoso bloccare tutto il lavoro mentre la CPU aspetta un controllo della condizione in fase di esecuzione.

Ecco perché, internamente, la CPU non aspetta.
Usa un **branch predictor** per prevedere l'esito di una condizione e inizia a eseguire _speculativamente_ il percorso previsto.

Se la previsione è corretta, l'esecuzione procede come se non ci fosse alcun branch.
Se invece la previsione è sbagliata, la CPU deve _scartare il lavoro svolto_ sul percorso previsto e ricominciare da quello corretto.

Questo si chiama **branch misprediction** ed è costoso: comporta un ritardo.

Quando un branch è difficile da prevedere, le branch misprediction si accumulano.
In quei casi, a volte è preferibile evitare del tutto il branch, così che le stesse istruzioni vengano eseguite indipendentemente dalla condizione.
Il codice che seleziona tra valori senza una `jcc` si chiama **branchless**.

Ci sono diversi modi di strutturare il codice in modo che esegua meno branch, o che i branch che esegue siano più prevedibili.
In particolare, x86-64 fornisce due famiglie di istruzioni comunemente usate per scrivere codice branchless.

### Spostamenti condizionali

La famiglia di istruzioni `cmovcc` copia l'operando sorgente nella destinazione solo se una condizione specifica è soddisfatta.
Altrimenti, la destinazione resta invariata.

Il suffisso `cc` segue la stessa nomenclatura di `jcc`, con lo stesso significato:

| istruzione | sposta se                              |
|-------------|--------------------------------------|
| `cmove`     | A == B dopo `cmp A, B`              |
| `cmovne`    | A != B dopo `cmp A, B`              |
| `cmovl`     | A < B (con segno) dopo `cmp A, B`      |
| `cmovb`     | A < B (senza segno) dopo `cmp A, B`    |
| `cmovg`     | A > B (con segno) dopo `cmp A, B`      |
| `cmova`     | A > B (senza segno) dopo `cmp A, B`    |

Le regole sono simili a quelle di `jcc`:

1. I suffissi `l` e `g` si usano per i confronti con segno, mentre `b` e `a` per quelli senza segno.
2. Aggiungendo `e` a un suffisso si include anche l'uguaglianza.
3. Aggiungendo `n` si nega la condizione.
4. Esistono anche varianti che si riferiscono al flag impostato.
   Per esempio, `cmovz` e `cmovc`.

Prendiamo il valore assoluto di un intero con segno in `rdi`, restituito in `rax`.
Scritta con `jcc`, la funzione seleziona uno dei due percorsi:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Scritta con `cmovcc`, entrambi i valori candidati vengono calcolati incondizionatamente e lo spostamento condizionale ne sceglie uno:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

La versione branchless esegue sempre le stesse istruzioni.
Non c'è alcuna `jcc` che il branch predictor debba prevedere.

La destinazione di una `cmovcc` deve essere un registro.
La sorgente può essere un registro o una locazione di memoria, ma non un immediato.

~~~~exercism/note
Nel codice qui sopra, l'istruzione `neg` imposta diversi flag in base al risultato, incluso il flag di segno (SF).
Questo significa che `cmp rdi, 0` si può eliminare del tutto:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Per `rdi` positivi, `neg` produce un risultato negativo e SF == 1, quindi `cmovs` ripristina `rdi`.
Per `rdi` uguali a zero o negativi, `neg` produce un risultato non negativo e SF == 0, quindi `rax` mantiene il valore negato (che è il valore assoluto corretto).

Sebbene `cmp` sia il modo principale per confrontare valori nel codice assembly, molte istruzioni impostano comunque dei flag in base al loro risultato.
L'elenco completo dei flag influenzati da un'istruzione è di solito riportato nel suo [riferimento][reference].
Per `neg` in particolare, sono SF, ZF, CF, OF e PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

### Set condizionale

La famiglia di istruzioni `setcc` imposta l'operando di destinazione a `1` se una condizione specifica è soddisfatta, e a `0` altrimenti.
La destinazione è sempre un _operando a 8 bit_.

Il suffisso `cc` segue la stessa nomenclatura di `jcc` e `cmovcc`.
Per esempio, `setz` imposta la destinazione a `1` se `ZF == 1` e a `0` altrimenti.

Poiché la destinazione è a 8 bit, è comune far seguire `setcc` da un `movzx` quando serve un valore più largo:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Questo è un idioma comune per trasformare il risultato di un confronto nell'intero `0` o `1`.
