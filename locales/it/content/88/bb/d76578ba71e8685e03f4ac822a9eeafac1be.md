# Istruzioni

In seguito a una recente revisione della sicurezza, ti è stato chiesto di ripulire i file di log archiviati dell'organizzazione.

## 1. Individuare le righe di log corrotte

Ti serve un'idea di quante righe di log dell'archivio non rispettino gli standard attuali.
Ritieni che un semplice test riveli se una riga di log è valida.
Per essere considerata valida, una riga deve iniziare con una delle seguenti stringhe:

- [DEBUG]
- [INFO]
- [WARNING]
- [ERROR]

Implementa la funzione `valid_line?/1` in modo che restituisca `true` se la riga di log è valida.

```elixir
LogParser.valid_line?("[ERROR] Network Failure")
# => true

LogParser.valid_line?("Network Failure")
# => false
```

## 2. Suddividere la riga di log

Poco dopo aver iniziato il progetto di analisi dei log, ti accorgi che i log di un'applicazione non sono suddivisi in righe come gli altri. In questo progetto, quello che dovrebbe essere su righe separate si trova invece su un'unica riga, collegato da bizzarre frecce come `<--->` o `<*~*~>`.

In realtà, qualsiasi stringa che abbia come primo carattere `<`, come ultimo carattere `>` e, in mezzo, una qualsiasi combinazione dei seguenti caratteri `~`, `*`, `=` e `-` può essere usata come separatore nei log di questo progetto.

Implementa la funzione `split_line/1` che prende una riga e restituisce un array di stringhe.

```elixir
LogParser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
# => ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. Rimuovere gli artefatti dal log

Hai scoperto che un'elaborazione a monte dei log ha disseminato il testo «end-of-line» seguito da un numero di riga (senza spazio in mezzo) in tutti i log.

Implementa la funzione `remove_artifacts/1` che prende una stringa, rimuove tutte le occorrenze del testo end-of-line (senza distinguere tra maiuscole e minuscole) e restituisce una riga di log pulita.

Le righe che non contengono il testo end-of-line devono essere restituite senza modifiche.

Rimuovi solo la stringa end of line, non serve sistemare gli spazi bianchi.

```elixir
LogParser.remove_artifacts("[WARNING] end-of-line23033 Network Failure end-of-line27")
# => "[WARNING]  Network Failure "
```

## 4. Etichettare le righe con i nomi utente

Hai notato che alcune righe di log contengono frasi che si riferiscono agli utenti.
Queste frasi contengono sempre la stringa `"User"`, seguita da uno o più caratteri di spazio, e poi da un nome utente.
Decidi di etichettare queste righe.

Implementa una funzione `tag_with_user_name/1` che elabora le righe di log:

- Le righe che non contengono la stringa `"User"` restano invariate.
- Per le righe che contengono la stringa `"User"`, anteponi alla riga `[USER]` seguito dal nome utente.

```elixir
LogParser.tag_with_user_name("[INFO] User Alice created a new project")
# => "[USER] Alice [INFO] User Alice created a new project"
```

Puoi presumere che:

- Ogni occorrenza della stringa `"User"` è seguita da uno o più caratteri di spazio e dal nome utente.
- C'è al massimo un'occorrenza della stringa `"User"` in ogni riga.
- I nomi utente sono stringhe non vuote che non contengono spazi.
