# Eccezione

Nel mondo ideale, tutto funziona perfettamente.
Ma nel mondo reale, le cose possono andare storte, e il modo in cui gestiamo queste situazioni è importante per garantire che il nostro software sia robusto e affidabile.
Le eccezioni sono un concetto cruciale nella programmazione che ci permette di gestire errori e situazioni impreviste con eleganza.

Sollevare un errore, se non gestito, interrompe il programma e genera un messaggio di errore.
Nella maggior parte dei casi, non vuoi che il tuo programma si interrompa quando si verifica un errore: invece, vuoi gestire l'errore e continuare a eseguire il programma.

## Sollevare un'eccezione

In Crystal, le eccezioni vengono sollevate usando la parola chiave `raise` e possono ricevere una `String` o un oggetto `Exception`.
Se non gestita, il programma si interromperà e stamperà il messaggio di errore.

```crystal
raise "This is an error"
```

In Crystal esistono diverse eccezioni integrate, come `ArgumentError`, `IndexError`, `KeyError`, `IOError`, `SystemCallError`, `TypeError`, `ZeroDivisionError` e molte altre.
Queste richiedono di passare un messaggio all'eccezione.

```crystal
raise ArgumentError.new("This is an argument error")
```

## [Gestire le eccezioni][exception-handling]

Non vorremmo che il nostro programma si blocchi quando viene sollevata un'eccezione.
Perciò, quando sappiamo che un pezzo di codice è soggetto a errori, possiamo racchiuderlo in un blocco `begin` e gestire l'eccezione con un blocco `rescue`.
Il blocco `begin` segna l'inizio del codice che potrebbe sollevare un'eccezione, e il blocco `rescue` gestisce l'eccezione.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
end
```

Il blocco `rescue` può anche specificare una variabile per ottenere l'oggetto dell'eccezione.

```crystal
begin
 raise "This is an error"
rescue ex
 puts "An error occurred: #{ex.message}"
end
```

Il blocco `rescue` può anche specificare un tipo specifico di eccezione per catturare solo quell'eccezione.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
end

# or

begin
 raise ArgumentError.new("This is an argument error")
rescue ex : ArgumentError
 puts "An argument error occurred: #{ex.message}"
end
```

Si possono usare più blocchi `rescue` per gestire diversi tipi di eccezioni.
Nell'esempio seguente, il primo blocco `rescue` catturerà un `ArgumentError`, e il secondo blocco `rescue` catturerà qualsiasi altra eccezione.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
rescue
 puts "An error occurred!"
end
```

Il blocco `begin` può anche avere un blocco `else`, che viene eseguito se non viene sollevata alcuna eccezione.

```crystal
begin
 puts "No error occurred"
rescue
 puts "An error occurred!"
else
 puts "No error occurred"
end
```

Infine, c'è un blocco `ensure` che viene sempre eseguito, indipendentemente dal fatto che sia stata sollevata un'eccezione.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
ensure
 puts "This is always executed"
end
```

## Convenzione sui metodi

Alcuni metodi hanno due versioni: una con `!` e l'altra senza.
Questo può significare due cose diverse.
Una è che il metodo modifica l'oggetto, l'altra è che il metodo può sollevare un'eccezione.

Ma esiste anche un'altra convenzione riguardo al terminare un metodo con `?`, menzionata nel concetto booleano.
Alcuni metodi sollevano un'eccezione per impostazione predefinita, ma hanno anche una versione che termina con `?` e restituisce `nil` invece di sollevare un'eccezione.

Questo è l'ideale quando vuoi evitare che venga sollevato un errore. 
Può migliorare le prestazioni, dato che non deve creare una traccia dello stack e, se impostato correttamente, potrebbe rendere il codice più sicuro.

## Eccezioni personalizzate

Puoi anche creare le tue eccezioni ereditando dalla classe [`Exception`][exception].
Così facendo, puoi facoltativamente sovrascrivere il metodo `initialize` per impostare il messaggio dell'eccezione.
Questo può essere fatto assegnando il messaggio a una variabile di istanza chiamata `@message`.

```crystal
class MyException < Exception
 def initialize
   @message = "This is my exception"
 end
end

raise MyException.new
```
