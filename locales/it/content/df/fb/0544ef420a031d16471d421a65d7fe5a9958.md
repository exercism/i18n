# Suggerimenti

## Generali

- Il file della soluzione viene incluso in un altro, che chiama le macro.
  Mantieni il nome e l'ordine degli argomenti di ogni macro esattamente come li fornisce il compito, altrimenti il file non si assemblerà.
- Gli argomenti di una macro sono token, sostituiti come `%1`, `%2`, `%3` ovunque compaiano nel corpo.
  Possono essere registri, espressioni di indirizzo o valori letterali, purché ogni espansione sia un'istruzione valida.
- Ogni macro viene verificata in base ai registri che lascia invariati, non solo in base a ciò che scrive.
  Leggi la nota sui registri modificati in ogni compito e modifica solo i registri che essa consente.

## 1. Dai un nome alle costanti di formato

- Un `%define` su una sola riga dà un nome a un valore, così il resto del codice può leggere il nome invece di un numero nudo.
  Per un numero fisso, `equ` fa la stessa cosa ed è la scelta abituale per una costante.
- Le costanti di byte si possono scrivere sia in esadecimale (`0x20`) sia come valore letterale di carattere (`' '`).
  Entrambe si assemblano allo stesso valore.

## 2. Scrivi la macro `fill_run`

- Assegna a `rcx` il nome leggibile `COUNTER`.
- `fill_run` è una macro multi-riga che accetta 3 argomenti.
  Le macro multi-riga si definiscono con `%macro ... %endmacro`.
- Il primo argomento di `fill_run` è un indirizzo di memoria in un registro generico a 64 bit.
  Il secondo è il conteggio, che può essere passato in un registro generico a 64 bit o come valore immediato.
  Il terzo è un byte da scrivere, come valore immediato.
  Progetta il codice della macro tenendo conto di queste specifiche.
- L'unico registro che `fill_run` può modificare è `COUNTER`.
- Un ciclo all'interno di una macro di solito richiede un'etichetta con il prefisso `%%`.
  Senza questo prefisso, ogni chiamata della macro crea la stessa etichetta: può causare un errore se la macro viene chiamata più di una volta.

## 3. Scrivi la macro `lay_columns`

- `lay_columns` è una macro multi-riga che accetta 2 argomenti.
  Le macro multi-riga si definiscono con `%macro ... %endmacro`.
- Entrambi gli argomenti di `lay_columns` vengono passati in registri generici a 64 bit.
  Il primo è un indirizzo di memoria, il secondo è un intero.
  Progetta il codice della macro tenendo conto di queste specifiche.
- Gli unici registri che `lay_columns` può modificare sono i due passati come argomenti.
- Il numero di offset che la macro deve scrivere è fisso in fase di assemblaggio.
  Puoi usare `%rep ... %endrep` per ripetere il codice.
- Il calcolo dell'offset si fa con `offset[i] = margin + i * COLUMN_STRIDE`.
  `margin` è il secondo argomento della macro.
  `i` è un contatore di ciclo che può essere definito come variabile `%assign`.

## 4. Scrivi la macro `set_header`

- `set_header` è una macro multi-riga che accetta 2 argomenti.
  Le macro multi-riga si definiscono con `%macro ... %endmacro`.
- Il primo argomento di `set_header` è l'espressione di un indirizzo di memoria effettivo.
  Prende un registro di base, che può essere sommato a un registro indice moltiplicato per `1`, `2`, `4` o `8`, e un valore immediato.
  Questo significa che un semplice `rdi` è valido, così come `rdi+rax*4+2`.
- Il secondo argomento di `set_header` è un valore immediato che può assumere i valori `0`, `1` o `2`.
- `set_header` non deve modificare alcun registro.
- Devi copiare un byte all'indirizzo di destinazione in modo condizionale, in fase di assemblaggio, in base al secondo argomento.
  Un valore di `0` deve copiare `PLAIN`, un valore di `1` deve copiare `RULED` e un valore di `2` deve copiare `BOXED`.
