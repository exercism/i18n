# Introduzione

Quasi ogni programma Factor è una sequenza di parole che consumano e producono valori sulla *pila dei dati*. Quando input e output combaciano senza problemi, il codice si legge da sinistra a destra senza complicazioni. Quando non combaciano, si ricorre alle *parole di riordino*, e il codice diventa subito caotico.

In questo esercizio ti guideremo attraverso la soluzione standard di Factor: i combinatori.

## Parole di riordino

Le parole di riordino più comuni si trovano in [`kernel`][kernel]:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

Hai già usato `dup` e `swap`. `over` fa una copia del *secondo* elemento a partire dalla cima: è comodo quando lo stesso input deve alimentare due calcoli:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

Va bene per un solo uso. Ma messe in fila, sequenze di `dup`, `swap`, `over`, `rot` diventano rapidamente illeggibili.

## `keep`: conservare l'input

`keep` (in [`kernel`][kernel]) chiama una quotation in cima alla pila, ma lascia il valore originale sopra il risultato:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

Questo sostituisce uno schema fatto di `dup`, qualcosa e poi un riordino: ovunque scriveresti `dup something swap`, puoi semplicemente scrivere `[ something ] keep`.

## `bi`: due funzioni di un solo input

`bi` (in [`kernel`][kernel]) applica *due* quotation allo stesso valore, lasciando entrambi i risultati sulla pila:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

Senza `bi` scriveresti `dup sq swap neg`, leggibile abbastanza per due operazioni, ma ostico per tre.

## `tri` e `cleave`: molte funzioni di un solo input

`tri` estende `bi` a tre quotation:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

`cleave` (in [`combinators`][combinators]) è la stessa idea per un *array* con un numero qualsiasi di quotation:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

La quotation vuota `[ ]` funge da identità, utile quando una delle caselle della cut card deve essere l'input stesso.

## `dip` e `2dip`: operare al di sotto

`dip` (in [`kernel`][kernel]) chiama una quotation sui valori *sotto* la cima della pila, lasciando la cima intatta. `2dip` fa lo stesso, ma protegge i *due* valori in cima:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

Qui `dip` ha nascosto `11`, ha eseguito `9 10 +` e ha rimesso `11` in cima. `2dip` ha nascosto `11 12`, ha eseguito `9 10 +` al di sotto e poi ha ripristinato `11 12`.

`dip` è lo strumento giusto quando l'ordine naturale degli argomenti lascia il valore «pass-through» in cima alla pila. Usalo invece del sandwich `swap … swap`.

## `bi@`: la stessa operazione su due valori

`bi@` (in [`kernel`][kernel]) applica una sola quotation a due valori della pila:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*`: operazioni diverse su due valori

`bi*` (in [`kernel`][kernel]) applica quotation *diverse* ai due valori della pila, la prima al valore più in basso, la seconda a quello in cima:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

Usa `bi@` quando entrambi i valori ricevono lo stesso trattamento, e `bi*` quando ognuno ha bisogno del proprio.

## `tri*`: operazioni diverse su tre valori

`tri*` (in [`combinators`][combinators]) estende `bi*` a tre valori e tre quotation, applicando ciascuna quotation a un valore, in ordine:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
