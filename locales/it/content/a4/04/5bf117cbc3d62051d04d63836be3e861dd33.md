# Informazioni

Elm è un linguaggio delizioso per costruire applicazioni web affidabili.
Ha messaggi di errore amichevoli, prestazioni eccellenti, asset di piccole dimensioni e nessuna eccezione a runtime.

La parte di Elm probabilmente più famosa e più imitata è The Elm Architecture, un semplice schema per strutturare le applicazioni web: è il modo in cui si scrivono tutte le applicazioni web in Elm.

L'idea centrale è che il codice ruota attorno a un `Model` dello stato dell'applicazione, a un modo per `update` il modello e a un modo per `view` il modello.

Il `Model` contiene lo stato dell'applicazione: tutti i dati di cui l'applicazione ha bisogno.
Può essere di qualsiasi tipo, ma in qualsiasi applicazione utile è di solito un [record][record].
Se immagini una semplice applicazione con una casella di testo e un testo che ne mostra il contenuto al contrario, il modello sarebbe come qui sotto.
Puoi vedere questo esempio anche nella [Elm Guide][elm-guide-text-fields].

```elm
type alias Model =
  { text : String
  }
```

`update` è una funzione che viene chiamata con un `Msg` quando c'è un cambiamento (ad esempio quando l'utente fa clic su un pulsante).
Riceve il `Msg` e il `Model` corrente, e restituisce un nuovo `Model`.
Il `Msg` può essere di qualsiasi tipo, ma di solito è un [custom type][custom-type].

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

Come per tutti i custom type, le varianti del `Msg` possono includere tutte le informazioni arbitrarie di cui hanno bisogno.
Nell'esempio sopra, la variante `TextChanged` include una `String`.

`view` è una funzione che restituisce l'HTML da mostrare all'utente nel browser.
Riceve il `Model` corrente e restituisce un `Html Msg` (il tipo che Elm usa per rappresentare l'HTML).
Ogni elemento HTML (ad esempio `<div>`) ha una funzione Elm corrispondente (`Html.div`), nel pacchetto `Html`.
Ognuna di queste funzioni riceve due parametri: il primo è una lista di attributi (dai pacchetti `Html.Attributes` e `Html.Events`), il secondo è una lista di elementi figli (funzioni del pacchetto `Html`).
C'è anche una funzione `text` che rappresenta il contenuto HTML di tipo stringa: riceve solo un parametro di tipo stringa, ma per il resto si usa allo stesso modo di tutte le altre funzioni ed elementi del pacchetto `Html`.

La funzione `view` può specificare che determinati eventi, come fare clic su un pulsante o modificare il testo in una casella di testo, producano la creazione di un `Msg`: l'Elm Runtime lo userà per chiamare la funzione `update`, modificare il `Model` e generare l'HTML aggiornato.
Nel codice qui sotto questo accade con `Html.Events.onInput TextChanged`.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

`Html.Events.onInput` si aspetta che gli venga passata una funzione (`String -> Msg`) che userà per creare il `Msg`.
Eventi diversi si aspettano funzioni diverse a seconda delle informazioni che possono fornire: ad esempio, `Html.Events.onCheck` (per le caselle di controllo) si aspetta `Bool -> Msg`, mentre `Html.Events.onClick` si aspetta semplicemente un `Msg`.

Il linguaggio Elm è puro e funzionale e non è possibile alcuna mutazione, quindi l'Elm Runtime gestisce tutto ciò che cambia.
Puoi vedere tutti i diversi [Elementi HTML][html-elements], [Attributi degli elementi][element-attributes] ed [Eventi HTML][html-events] nel registro dei pacchetti di Elm.

In Elm puoi scrivere applicazioni web di 4 «livelli», che diventano progressivamente più potenti e più complesse (anche se Elm resta un linguaggio e un ecosistema deliziosamente semplici).
Sono tutti definiti nel [pacchetto Browser][browser-package]:

- [sandbox][browser-sandbox]: reagisci all'input dell'utente, come pulsanti e caselle di controllo
- [element][browser-element]: comunica con il mondo esterno, usando HTTP e l'interoperabilità con JavaScript
- [document][browser-document]: controlla il `<title>` e il `<body>` di una pagina web
- [application][browser-application]: crea applicazioni complete a pagina singola che gestiscono il routing e le variazioni di url

Questo concetto usa [sandbox][browser-sandbox], perché è il più semplice (e, trattandosi di una sandbox, è relativamente facile lavorare con l'editor online di Exercism).
Il modulo di ingresso di un programma Elm deve chiamarsi `Main`, e la funzione che crea l'applicazione deve chiamarsi `main`, come qui sotto.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

Abbiamo già visto le funzioni `update` e `view`, e [sandbox][browser-sandbox] richiede in più una funzione `init`, che restituisce lo stato iniziale del `Model`.
