# Istruzioni

Questo problema è modellato sulla schedulazione statica non preemptive dei sistemi operativi in tempo reale, ma è simile anche al Job-Shop Scheduling Problem (JSP) con una sola risorsa. Il problema presuppone che tutte le attività siano note staticamente. In altre parole, i tempi di rilascio di tutte le attività sono noti all'inizio del programma. In pratica, i tempi di rilascio delle attività non sono noti all'inizio di un programma e possono essere generati in qualsiasi momento tramite I/O, interrupt e così via.

Dato un array di attività con i relativi parametri, determina una schedulazione in cui le attività possano essere eseguite in sequenza, senza sovrapposizioni. Poiché il problema è modellato sulla schedulazione dei processi di un RTOS, assumeremo che tra un'attività e l'altra sia necessario un tempo diverso da zero, noto anche come overhead di context switching. Esistono due tipi diversi di attività: quelle periodiche e quelle dinamiche. Entrambi i tipi hanno un parametro ID dell'attività, una stringa che serve a distinguere le diverse attività nell'array delle attività.

Un'**attività periodica** è definita come un'attività che viene eseguita periodicamente. In altre parole, l'attività viene eseguita una volta ogni T secondi, dove T è definito come il periodo.
Un'attività periodica è definita dai seguenti parametri:
* Start Time: momento in cui inizia la prima ripetizione, o istanza, dell'attività
* Period: tempo che intercorre tra l'inizio di una ripetizione e quello della successiva
* Execution Time: durata di ogni ripetizione
* End Time: momento in cui l'attività nel suo complesso smette di essere schedulata

Un'**attività dinamica** è definita come un'attività che viene eseguita una sola volta.
Un'attività dinamica è definita dai seguenti parametri:
* Release Time: primo momento in cui l'attività PUÒ essere schedulata (NON è la stessa cosa del tempo di avvio)
* Execution Time: durata dell'esecuzione dell'attività
* Deadline: momento entro cui l'attività deve aver terminato l'esecuzione

La funzione da implementare ha due input. Il primo input è un array di istanze di `RealTimeTask`. Le istanze di `RealTimeTask` saranno passate come istanze di `PeriodicRealTimeTask` oppure di `DynamicRealTimeTask`, con tutti i parametri dell'attività espressi come interi. La funzione built-in di Python `isinstance()` può essere usata per distinguere i due tipi di attività nell'array. L'ordine dell'array non ha importanza: guarda solo i parametri delle attività. Il secondo input è un singolo intero che specifica l'overhead di context switching. L'overhead di context switching è sempre un intero non negativo.

L'output deve essere un dizionario in cui le chiavi sono l'ID dell'attività ricavato dalle istanze di `RealTimeTask` e il valore è un array di tuple di due elementi. Il formato delle tuple di due elementi è (momento di inizio, momento di fine). Le attività dinamiche devono contenere una sola tupla di due elementi nell'array, mentre le attività periodiche possono contenerne più di una. L'ordine delle tuple di due elementi nell'array non ha importanza. Se non è possibile creare una schedulazione valida dall'array delle attività con l'overhead di context switching indicato, solleva un'eccezione `NoRtosStaticScheduleProducible`. Tieni presente che i risultati del modello Z3 per le variabili dovranno essere convertiti in int prima di essere restituiti in output. Se il risultato del modello Z3 è di tipo `IntNumRef`, si può usare il metodo di classe `as_long()` per convertirlo in un intero.

Viene fornita un'ulteriore funzione che permette di visualizzare l'ordine sequenziale delle attività. Questa funzione si può attivare anche per singoli casi di test impostando l'argomento keyword `plot` a `True` nella funzione `check()`. Per rappresentare graficamente ed etichettare ogni attività viene usato un grafico a barre orizzontali spezzate. Per utilizzare questa funzione, è necessario installare la libreria Python *matplotlib*. Le istruzioni per installare *matplotlib* le trovi [qui](https://matplotlib.org/stable/users/installing.html).
