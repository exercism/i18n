# Test

Ogni esercizio arriva con una serie di unit test e tutto il necessario per compilarli ed eseguirli.
L'implementazione la fornisci tu.

## Eseguire i test

Apri un terminale nella cartella dell'esercizio ed esegui:

```
make
```

Questo comando compila la soluzione e i test, poi esegue i test.
Eseguilo di nuovo ogni volta che modifichi la soluzione.

Se hai la [Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally), puoi usare invece questo comando, che esegue anche `make`:

```
exercism test
```

Per rimuovere i file creati dalla build, esegui `make clean`.

### Senza make

Se non hai `make` (su Windows, per esempio), puoi compilare ed eseguire i test direttamente.
Per l'esercizio "Bob":

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

Poi esegui i test su Linux o macOS:

```
./run_tests
```

Oppure su Windows:

```
.\run_tests
```

## Svolgere un esercizio

I file di ogni esercizio prendono il nome dall'esercizio stesso.
Per l'esercizio "Bob":

| File             | Contenuto                                                          |
| ---------------- | ------------------------------------------------------------------ |
| `bob.f90`        | uno stub della soluzione, pronto per essere completato             |
| `bob_test.f90`   | i test                                                             |
| `TesterMain.f90` | la libreria di test                                                |
| `Makefile`       | le istruzioni per `make`                                           |
| `CMakeLists.txt` | le istruzioni per [CMake](#using-cmake-instead), che è facoltativo  |

Devi modificare solo il file della soluzione.

Svolgere ogni esercizio è un processo che ripete questi passaggi finché tutti i test non passano:

- Risolvi eventuali errori di compilazione, poi esegui i test per vedere quali falliscono.
- Implementa solo lo stretto necessario perché il prossimo test che fallisce passi.
- Riorganizza l'implementazione per migliorare la leggibilità, ridurre le duplicazioni, ecc.
- Esegui di nuovo i test e passa al prossimo test che fallisce.

Per ogni test che fallisce viene stampato un messaggio, seguito da un riepilogo.
Se qualche test fallisce, `make` termina con un errore.

Ogni test ha un commento che lo descrive e poi il test vero e proprio, che inizia con `call assert_equal`, ad esempio

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Per disabilitare un test, basta trasformarlo in commento con un `'!'`, ad esempio

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## Usare CMake invece

CMake non ti serve, ma può essere utile se lavori in un IDE come Visual Studio o Xcode, o se usi un compilatore diverso da GFortran.

La cartella dell'esercizio deve mantenere il nome originale, perché CMake lo usa per trovare i file sorgente.
Parti dalla cartella dell'esercizio:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

Dopo aver modificato la soluzione servono solo gli ultimi due comandi.

**Nota:** esegui sempre `cmake` da una cartella separata, come `build`.
Eseguire `cmake .` nella cartella dell'esercizio sostituisce il `Makefile` che accompagna l'esercizio.

CMake sceglie un generatore adatto al tuo sistema.
Per sceglierne un altro, usa l'opzione `-G`, ad esempio `cmake -G Xcode ..`.
Esegui `cmake --help` per elencare i generatori che puoi usare.
Con Visual Studio o Xcode, esegui i test con `ctest -V -C Debug`.

Se la cartella dell'esercizio non contiene un `Makefile`, è stata scaricata prima che questi file fossero aggiunti agli esercizi.
Puoi comunque usare CMake.
