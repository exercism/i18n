# Le basi di Unison

## Termini e funzioni

I termini e le funzioni sono le unità di base per scrivere un programma Unison.

Un «termine» è quello che chiamiamo un valore statico. Si definisce con `name = expression`, eventualmente preceduto da una firma di tipo nella forma `name : MyType`. Unison supporta l'inferenza dei tipi: per le definizioni semplici potresti vedere la firma di tipo omessa.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Le funzioni in Unison hanno la forma `myFunctionName argument1 argument2 = myImplementation`: iniziano con il nome della funzione, seguito da argomenti separati da spazi.

```
getMax a b = Nat.max a b
```

Le funzioni possono includere, facoltativamente, una firma di tipo. L'ultimo tipo a destra è sempre il tipo restituito finale della funzione, e ogni argomento è separato dalla freccia di funzione `->`.

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Per chiamare una funzione, scrivi il suo nome seguito dai suoi argomenti separati solo da spazi.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Quando chiami una funzione, Unison cercherà di trattare come suo argomento qualunque cosa si trovi immediatamente alla sua destra: questo non sempre produce l'ordine di valutazione delle funzioni che desideri.

Supponiamo di voler ottenere il valore `1` dalla seguente espressione

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Così com'è scritto, `shouldBe1` si valuta a `0`, perché l'ordine implicito di applicazione delle funzioni è `getMax 1 10`, che vale `10`, e poi `10 - 10`, che vale `0`.

Puoi usare le parentesi per raggruppare di nuovo l'espressione nell'ordine di operazioni desiderato.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Le watch expression

Unison offre un modo per valutare rapidamente il codice chiamato «watch expression». Una watch expression inizia con il simbolo `>` ed è seguita dall'espressione da valutare. Le watch expression si possono scrivere in qualsiasi file con estensione `.u`. Quando salvi il file, dovresti vedere il risultato della valutazione dell'espressione nella console dell'Unison Codebase Manager (UCM). Dove possibile, in questa documentazione cercheremo di mostrare un'espressione con il suo output atteso dopo averla valutata in una watch expression.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Funzioni su più righe

Le funzioni Unison su più righe usano l'indentazione o i blocchi `let` per delimitare il codice, vale a dire lo «scope» lessicale.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Tutto ciò che si trova allo stesso livello di indentazione condivide lo stesso scope: ecco perché possiamo fare riferimento alla variabile `newBeginning` nell'ultima riga.

## I namespace e le istruzioni `use`

I namespace servono a raggruppare e organizzare le funzioni Unison. Puoi pensarli come analoghi alle «directory». Offrono struttura e raggruppamento logico.

Con un'istruzione `use` puoi portare nello scope le funzioni di un namespace.

Immagina di scrivere una funzione che usa valori `List` di Unison. Sai che ti serviranno funzioni come `List.map` e `List.flatMap`, dove `List` è il namespace e `map` e `flatMap` sono funzioni. Per evitare di ripeterti, potresti scegliere di portare tutto il namespace `List` nello scope lessicale della funzione, così:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

La riga `use List` risolve l'ambiguità dei riferimenti a `map` e `flatMap`. Puoi leggere di più sulle [istruzioni `use` qui][use-statements].

## La libreria standard di Unison

La libreria standard di Unison si chiama `base`. Se hai seguito la guida di avvio rapido e hai una codebase creata in locale, la libreria standard dovrebbe essere stata scaricata automaticamente. Puoi consultare online la documentazione della libreria standard su [Unison Share][unison-share-base].

## I commenti e i letterali di documentazione

I commenti in Unison sono una funzionalità un po' insolita. Quando scrivi codice Unison, puoi creare testo in un file con estensione `.u` che non viene interpretato, con la seguente sintassi:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Tuttavia_, dato che il codice Unison viene salvato come hash del suo albero sintattico astratto, e non come file di testo sul file system, i commenti, che sono «decorazioni» testuali di una data funzione o di un dato termine Unison nel file, non possono davvero essere salvati e riprodotti per la condivisione. Se vuoi aggiungere informazioni al tuo termine Unison in modo che vengano conservate perché altri possano leggerle e capirle, puoi usare un letterale di documentazione.

La documentazione è un valore di prima classe nel linguaggio di programmazione Unison. Questo significa che un elemento `Doc` può essere assegnato a un valore, passato come valore a una funzione, o restituito come valore di una funzione. Gli elementi di un letterale di documentazione si aprono e si chiudono con doppie parentesi graffe. Ecco come potremmo usare l'elemento `Doc` come commento.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
