# A proposito dei bit

Le cifre binarie, in ultima analisi, corrispondono direttamente ai transistor della tua CPU o RAM, e al fatto che ciascuno sia «on» o «off».

La manipolazione di basso livello, informalmente chiamata «bit-twiddling», è particolarmente importante nei linguaggi di sistema.

I linguaggi di livello più alto come Kotlin di solito astraggono gran parte di questi dettagli.
Tuttavia, una gamma di base di operazioni a livello di bit [è disponibile][ref-bitwise].

~~~~exercism/note
Per vedere un output binario leggibile, quasi tutti gli esempi che seguono vanno racchiusi in una funzione [`Integer.toBinaryString()`][web-binstring], oppure convertiti con `toString(radix = 2)`.

Questo è visivamente fastidioso, quindi molte occorrenze di questa funzione sono state eliminate, e i risultati sono rappresentati con la notazione `0b`.

[web-binstring]: https://www.baeldung.com/kotlin/int-binary-representation
~~~~

## Operazioni di bit-shift

I tipi `Int` o `Long`, sia con segno che senza segno, possono essere rappresentati come una stringa di 1 e 0, e manipolati come una sequenza di bit.

Forse sorprendentemente, i tipi `Byte` o `Short` non sono compatibili con la maggior parte delle operazioni bit a bit in Kotlin.
Tutti gli esempi che seguono usano interi a 32 bit (`Int` o `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Gli shift spostano tutto verso sinistra o verso destra di un numero specificato di posizioni.
Alcuni bit cadono da un'estremità, e l'altra estremità viene riempita con zeri o uni.

- Shift a sinistra con `shl`: riempimento con zeri.
- Shift a destra con `shr` o `ushr`: riempimento con zeri per i numeri positivi (vedi la sezione successiva per i numeri negativi).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Ogni shift a sinistra raddoppia il valore, e ogni shift a destra lo dimezza (soggetto a troncamento).
Questo è più evidente nella rappresentazione decimale:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Questo tipo di shift è molto più veloce dell'aritmetica «vera», il che rende la tecnica molto popolare nella programmazione di basso livello.

### Shift di numeri interi negativi

Con i _numeri interi negativi_, dobbiamo essere un po' più cauti.

I valori negativi sono memorizzati nella forma in [complemento a due][wiki-2complement], il che significa che il bit più a sinistra è 1.
Nessun problema per uno shift a sinistra, ma quando spostiamo a destra come riempiamo i bit più a sinistra?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

L'operatore [`shr`][ref-shr] esegue uno [shift aritmetico][wiki-arithmetic], preservando il bit di segno.

L'operatore [`ushr`][ref-ushr] esegue uno [shift logico][wiki-logical], riempiendo con zeri come se il numero fosse senza segno.

## Logica bit a bit

Abbiamo visto nel [concetto Booleani][concept-booleans] che gli operatori `&&` (and), `||` (or) e `!` (not) si usano con i valori booleani.

Esistono operatori equivalenti `and`, `or`, `xor` ([or esclusivo][wiki-xor]) per confrontare i bit di due interi, e una funzione `inv` (inversione) per invertire tutti i bit.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
