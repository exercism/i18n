# Informazioni

Il tipo `Result` è la soluzione che il linguaggio Elm offre per segnalare e recuperare gli errori. È in parte simile al tipo `Maybe`, ma mentre il `Nothing` di `Maybe` codifica un qualche tipo di fallimento, non dice nulla sul _perché_ sia fallito. `Result` include invece un contesto sul motivo per cui qualcosa è fallito.

## Definizione e variabile di tipo

Il tipo `Result` è definito come segue:

```elm
type Result error value
  = Ok value
  | Err error
```

In breve, questo tipo codifica il risultato di un'operazione che può riuscire e restituire un `value` oppure fallire e restituire una spiegazione del fallimento (`error`).

Nella terminologia di Elm, questa si chiama definizione di «tipo personalizzato».
I tipi personalizzati vengono introdotti in dettaglio in un altro concetto di questo percorso, ma non ci serviranno per capire `Result` nello specifico.
L'`error` e il `value` in `OK value` e `Error error` rappresentano una variabile di tipo: possono cioè essere di qualsiasi tipo, come `Int`, `Bool` o `String`.
Di conseguenza, un `Result String Int` è un valore che ci si aspetta contenga un `Int` e, in caso di errore, questo sarà rappresentato da una `String`.

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## Leggere il contenuto di un valore Result

Per leggere il contenuto di un valore `Result` si usa il «pattern matching».
Anche il pattern matching viene introdotto più in dettaglio in un altro concetto, quindi ci concentreremo solo su come funziona il pattern matching applicato a un `Result`.

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

Ogni volta che usi un valore `Result`, il compilatore di Elm controlla che il tuo codice gestisca tutte le possibilità: non puoi fare pattern matching su un `Result` gestendo solo il caso in cui c'è un `Ok value`.
All'inizio può sembrare fastidioso, ma è uno dei più grandi punti di forza del linguaggio Elm.
Previene centinaia di bug e rende la riorganizzazione guidata dal compilatore un'esperienza senza paura e gratificante.

## Manipolare il contenuto di un valore Result

Esistono varie funzioni per lavorare con i tipi `Result`, di solito preferibili al pattern matching. `Result.map` serve a mappare il valore, mentre `Result.andThen` serve a concatenare tra loro funzioni che possono fallire.

Result.map serve a modificare il valore Ok ed è utile per concatenare funzioni senza doversi preoccupare se il Result contenga un errore o no. Se il valore è Ok, Result.map chiama la funzione concatenata (`formatAge` qui sotto); se invece c'è un errore, Result.map non fa nulla e restituisce semplicemente l'errore.

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

Result.andThen serve a modificare il valore Ok ed è utile per concatenare funzioni senza doversi preoccupare se il Result contenga un errore o no. È simile a Result.map, ma Result.andThen lavora con una funzione concatenata (`formatSpecialBirthday` qui sotto) che restituisce a sua volta un Result. Anche `Result.map` può farlo, ma si finisce con uno strato di annidamento in più, che `andThen` evita abilmente.

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
