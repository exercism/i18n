# Appendice alle istruzioni

## Il processo Node

A differenza degli altri esercizi, `grep.js` _non_ viene importato all'interno del file di test `grep.spec.js`. Verrà invece usato come se fosse un eseguibile. Per rendere possibile tutto questo, il file `grep.js` è stato impostato con uno shebang ed un commento che spiega a cosa serve:

```javascript
#!/usr/bin/env node

// The above line is a shebang. On Unix-like operating systems, or environments,
// this will allow the script to be run by node, and thus turn this JavaScript
// file into an executable. In other words, to execute this file, you may run
// the following from your terminal:
//
// ./grep.js args
//
// If you do not have a Unix-like operating system or environment, for example
// Windows without WSL, you can use the following inside a window terminal,
// such as cmd.exe:
//
// node grep.js args
//
// Read more about shebangs here: https://en.wikipedia.org/wiki/Shebang_(Unix)
```

I test avvieranno un nuovo _processo_ Node che eseguirà `grep.js`.

## Leggere gli argomenti

Per recuperare gli argomenti con cui è stato avviato il _processo_, usa `process.argv`.

## Leggere i file

La funzione `readLines` è già disponibile. Non serve trasformare il percorso del file per usarla. La funzione `readlines` _risolve_ il percorso a partire dalla directory di lavoro corrente che, per i processi di `grep.js`, è impostata sulla directory dell'esercizio.

## Scrivere l'output

Per scrivere l'output usa

- `console.log` per scrivere sul flusso di output standard,
- `console.error` per scrivere sul flusso di errore standard.

I test considerano l'esecuzione riuscita (resolved) se non viene scritto nulla sul flusso di errore standard, e non riuscita (rejected) se qualcosa viene scritto sul flusso di errore standard.
