# Proprietà

In Cairo, il concetto di proprietà è associato alle _variabili_ piuttosto che ai _valori_ che contengono.

I valori in Cairo sono immutabili: questa immutabilità garantisce che, anche se molte variabili fanno riferimento allo stesso valore, il valore stesso rimane costante e inalterato.
Quindi il compilatore deve garantirne l'uso corretto da parte del programmatore.
Questo è il significato della _proprietà_ delle variabili: il proprietario è il codice che può leggere (e scrivere, se mutabile) la variabile.

## Regole di proprietà delle variabili

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## Scope della variabile

Uno scope è l'intervallo all'interno di un programma in cui una variabile è valida.
Vediamo il seguente esempio che dichiara una variabile `x` di tipo intero senza segno, con commenti che annotano dove la variabile è valida:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Note:

- Quando `x` entra nello scope, è valida.
- Rimane valida finché non esce dallo scope, in questo caso fino alla fine della funzione `main()`.

## Spostamento dei valori

Uno spostamento avviene quando un valore viene passato a un'altra funzione, distruggendo la variabile originale che faceva riferimento al valore (rendendo così la variabile inutilizzabile) e creando una nuova variabile per contenere lo stesso valore.

Gli array sono un esempio di tipo complesso che viene spostato quando viene passato a un'altra funzione.
Ecco un breve promemoria di come appare un array:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

In che modo il sistema dei tipi garantisce che il programma Cairo non tenti mai di scrivere due volte nella stessa cella di memoria?
Considera il seguente codice, in cui proviamo a rimuovere il primo elemento dell'array due volte:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

In questo caso, proviamo a passare lo stesso valore (l'array nella variabile `arr`) a entrambe le chiamate di funzione.
Ciò significa che il nostro codice tenta di rimuovere il primo elemento due volte. Questo tentativo di scrivere due volte nella stessa cella di memoria è vietato dalla Cairo VM e porta a un errore a runtime.
Per fortuna, questo codice in realtà non viene compilato.
Una volta passato l'array alla funzione `foo`, la variabile `arr` non è più utilizzabile.
Otteniamo questo errore di compilazione, che ci dice che avremmo bisogno che `Array` implementi il trait `Copy`:

## Il trait Copy

Se un tipo implementa il trait `Copy`, passarlo a una funzione non sposta il valore ma crea una nuova variabile che fa riferimento allo stesso valore.
Questa è un'operazione gratuita perché le variabili sono un'astrazione di Cairo e i valori sono sempre immutabili.

Per implementare il trait `Copy` sul tuo tipo, aggiungi l'annotazione `#[derive(Copy)]` alla definizione del tipo.
Tuttavia, Cairo non lo permette se il tipo o uno qualsiasi dei suoi componenti non implementa il trait `Copy`.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## Distruzione dei valori

I tipi lineari possono anche essere utilizzati facendoli distruggere, il che garantisce che la risorsa associata venga rilasciata correttamente.
Ciò si ottiene implementando o derivando il trait `Drop`, che segnala al compilatore che il tipo può essere distrutto in sicurezza una volta che non è più utile.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

Al momento, l'implementazione di `Drop` può essere derivata per tutti i tipi, tranne che per i dizionari (`Felt252Dict`) e i tipi che contengono dizionari.
Questo perché i dizionari devono essere «compattati» quando vengono distrutti.
Per questo, deriviamo il trait `Destruct`:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## Valori restituiti e scope

Restituire valori equivale a spostarli.
L'esempio seguente mostra una funzione che restituisce un valore:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
