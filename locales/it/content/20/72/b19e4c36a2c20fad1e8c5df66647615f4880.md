# Introduzione

Alcuni cicli non si possono scrivere come «fai questo per ogni elemento di una sequenza»: bisogna andare avanti finché una condizione non cambia. Il combinator `while` di Factor è lo strumento giusto per farlo: la quotation del predicato dice «continuiamo?», quella del corpo esegue il lavoro di un singolo passo, e `while` ripete finché il predicato non restituisce `f`.

## `while` e `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` e `body` sono entrambe quotation che operano sullo stack dei dati. `while` continua a iterare finché `pred` lascia un valore vero; `until` è l'opposto: continua a iterare *finché* `pred` non diventa vero (cioè finché `pred` lascia `f`).

Un singolo pezzo di stato può passare sullo stack tra il predicato e il corpo:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

Traccia: il predicato `dup 0 >` sbircia il contatore in corso; il corpo `dup . 1 -` lo stampa e lo decrementa; il ciclo si ferma quando il contatore raggiunge `0`. Il `drop` in coda scarta dallo stack quello `0` conclusivo.

## `while*`: conservare il valore del predicato

```
while* ( pred body -- )
```

A `while` interessa solo se il suo predicato ha lasciato un valore vero: il valore in sé viene buttato via prima di eseguire il corpo. `while*` invece *passa quel valore al corpo*. Ricorri a `while*` ogni volta che il test e il corpo vogliono la stessa cosa appena calcolata: una ricerca, una corrispondenza, un token analizzato.

Qui ogni nome punta al successivo in una catena. Il predicato cerca il nome corrente; finché c'è un nome successivo, `while*` lo passa al corpo, che lo stampa e prosegue da lì:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at` restituisce il nome successivo, oppure `f` quando un nome non ha una voce. Finché restituisce un nome, `while*` dà quel nome a `dup .`, che lo stampa e lo lascia come chiave per la ricerca successiva. Il primo `f` ferma il ciclo: `while*` lo scarta, quindi non avanza niente.

## Più valori di stato con le variabili locali

Quando il ciclo porta più di un valore, per esempio una lista rimanente e un totale parziale, destreggiarsi con lo stack diventa caotico. Lo schema più pulito è dichiarare *variabili locali* con `::`:

```
:: word ( inputs -- outputs ) ... ;
```

All'interno del corpo, `:> name!` aggiunge una variabile locale modificabile; per leggere si usa `name`, per scrivere `name!` (che consuma il nuovo valore dallo stack e lo assegna).

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

Due variabili locali, qui (`rest` e `running`), coprono lo stato dell'intero ciclo: il predicato le ispeziona, il corpo le aggiorna e alla fine viene restituito il valore.

`unclip ( seq -- rest first )` stacca il primo elemento di una sequenza: torna comodo quando il ciclo vuole consumare una lista un elemento per iterazione. La forma `[ rest! ] dip` aggiorna `rest` con la coda rimanente, lasciando sullo stack l'elemento appena estratto perché il corpo lo usi.
