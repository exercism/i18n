# Descrizione

Gli hash-set implementano il [protocollo][set-protocol] [`sets`][sets] con l'hashing sotto il cofano, offrendo inserimento, ricerca e cancellazione in media O(1). Sono modificabili sul posto, il che li rende ideali per il pattern dell'*insieme dei visitati* negli attraversamenti dei grafi.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| parola        | effetto                                   |
|---------------|-------------------------------------------|
| `HS{ }`       | letterale hash-set vuoto (condiviso: usa `clone`!) |
| `>hash-set`   | `( seq -- set )`: costruisce un insieme nuovo a partire da una sequenza (elimina i duplicati) |
| `adjoin`      | `( elt set -- )`: inserimento distruttivo |
| `in?`         | `( elt set -- ? )`: appartenenza          |
| `delete`      | `( elt set -- )`: rimozione distruttiva   |
| `cardinality` | `( set -- n )`: numero di elementi        |
| `null?`       | `( set -- ? )`: vero quando l'insieme è vuoto |
| `members`     | `( set -- seq )`: enumera come sequenza   |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )`: converte `set` alla classe di `exemplar` |

Per costruire un insieme a partire da dati che hai già, `>hash-set` converte qualsiasi sequenza in un solo passaggio, scartando i duplicati: `{ 2 3 2 5 } >hash-set` dà `HS{ 2 3 5 }`. È la controparte in blocco della crescita di un insieme con ripetuti `adjoin`.

Un punto sottile su `in?` rispetto a `member?` (di `sequences`): entrambi verificano l'appartenenza, ma `member?` esegue una scansione lineare su una sequenza, mentre `in?` fa dispatch al metodo di protocollo del tipo di insieme, qualunque esso sia: per `HS{ }` si tratta di una ricerca hash. Usa `in?` quando il tuo contenitore «visited» ha più di una manciata di elementi.

`null?` risponde alla domanda «questo insieme è vuoto?» senza calcolare l'intera `cardinality`: è la guardia naturale per «ci è rimasto qualcosa da elaborare?». Per una lista di lavoro tenuta come insieme, `[ set null? ] [ … ] until` la svuota fino a esaurirla.

## Si sposa bene con le hashtable

`HS{ }` per «X è stato visitato?» si sposa naturalmente con `H{ }` per «chi sono i vicini di X?». Un DFS da manuale è semplicemente:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

L'insieme dei visitati elimina il lavoro duplicato; lo stack porta i nodi di frontiera (LIFO tramite `push`/`pop`); la mappa dei vicini (una hashtable) fornisce il grafo. L'ordine di visita non conta per una domanda di raggiungibilità, ed è per questo che un vettore usato come stack basta: un vero BFS sulla stessa struttura sostituisce il vettore con una [`<dlist>`][dlist] ed estrae invece dalla testa.
