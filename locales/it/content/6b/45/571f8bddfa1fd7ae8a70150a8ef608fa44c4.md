# Introduzione

Gli specificatori di classe di memorizzazione riguardano il modo in cui le variabili vengono archiviate in memoria.
Sono strettamente legati alla durata di memorizzazione (detta anche durata di vita) di un valore.

## auto: la classe di memorizzazione predefinita per le variabili con scope di funzione o di blocco

Dato che le variabili definite all'interno di un blocco o di una funzione sono `auto` per impostazione predefinita, non è comune usare esplicitamente questo termine.
La durata di vita di una variabile `auto` inizia quando si entra nel suo blocco e termina quando se ne esce.
A una variabile `auto`, quando si entra nel suo blocco, viene allocata memoria, _ma senza alcun valore predefinito_.

## static: lo specificatore di memorizzazione da non confondere con il tipo di collegamento static

Se una variabile è definita al di fuori di un blocco o di una funzione ed è contrassegnata con `static`, quel `static` si riferisce al suo collegamento: significa che vi si può accedere solo all'interno del file.
Se una variabile è definita all'interno di una funzione o in un blocco dentro una funzione ed è contrassegnata con `static`, ha una durata di memorizzazione `static`.
Il valore della variabile `static` persiste tra una chiamata e l'altra alla funzione o al blocco.

## extern: come accedere a una variabile in un'altra unità di traduzione

Un'unità di traduzione è composta da un file sorgente e da tutti gli altri file che esso `#include`.
Sebbene una variabile con scope di file possa essere dichiarata e inizializzata come `extern`, la parola chiave `extern` si usa di solito per riferirsi a una variabile esistente, non per definirne una nuova.
La variabile a cui si riferisce `extern` deve avere scope di file.
Una variabile con scope di file ha sempre durata di memorizzazione `static`.
Una variabile in un file incluso deve avere collegamento esterno per essere accessibile dal file che lo include.

## register: come velocizzare, eventualmente, l'accesso a una variabile

Una variabile contrassegnata come `register` esprime il desiderio del programmatore di avere il valore inserito in un registro per accedervi rapidamente.
Una variabile `register` è simile a una variabile `auto`, nel senso che deve trovarsi nello scope di una funzione o di un blocco.
Poiché il valore è destinato a essere inserito in un registro anziché in memoria, il compilatore dovrebbe impedire di accedere all'indirizzo della variabile, dato che l'indirizzo di un registro non può essere preso.
Tuttavia, un indirizzo di memoria può esso stesso essere inserito in un registro.
`register` è essenzialmente un suggerimento, dato che il valore può o meno finire davvero in un registro.

## typedef: lo specificatore di classe di memorizzazione che in realtà non lo è

`typedef` è descritto come specificatore di classe di memorizzazione solo per ragioni sintattiche.
Questo perché uno specificatore di classe di memorizzazione non può essere usato insieme a un altro specificatore di classe di memorizzazione.
Quindi, `typedef auto int i = 42;` è tanto illegale quanto `static auto int i = 42;`.
