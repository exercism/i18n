# Introduzione

Ricorda che un programma `jq` è una _pipeline di espressioni_.
**L'assegnazione di variabile** segue questa regola: un'_assegnazione di variabile_ è un'espressione che assomiglia a:

```jq
... | expr as $varname | ...
```

## L'output del filtro è l'input

Come l'_espressione identità_ `.`, l'output dell'_assegnazione di variabile_ è uguale al suo input.
Impostare il valore della variabile è un effetto collaterale.

Esempio: mostra che `.` dopo l'assegnazione è uguale all'input iniziale:

```sh
$ jq -c -n '42 | (. * 2) as $double | [., $double]'
[42,84]
```

## Lo scope di una variabile

Lo scope della variabile è «lessicale»: la variabile resterà nello scope per il resto della pipeline.
Le variabili definite nelle funzioni (arriveremo alle funzioni più avanti) sono «locali» alla funzione.

## I nomi delle variabili

La variabile deve iniziare con `$`.
Il resto del nome della variabile è un **identificatore**: inizia con una lettera o un underscore, seguiti da lettere, numeri o underscore.

## Assegnazione con destrutturazione

Dal manuale:

> Si possono dichiarare più variabili con un'unica espressione `as`, fornendo un pattern che _corrisponde alla struttura dell'input_ (questa tecnica è nota come «destrutturazione»).

Esempi:

```jq
[1, 2, 3] as [$a, $b, $c]
| [$a, $b, $c]     # => [1, 2, 3]
```

```jq
{"foo": "bar", "len": [10, 20]} as {foo: $f, len: [$h, $w]}
| [$f, $h, $w]     # => ["bar", 10, 20]
```

Far corrispondere il nome della variabile alla _chiave dell'oggetto_ offre una scorciatoia:

```jq
{"x": 4, "y": 7} as {$x, $y}
| [$x, $y]         # => [4, 7]
```

```jq
{"foo": "bar", "len": [10, 20]} as {$foo, $len}
| [$foo, $len]     # => ["bar", [10, 20]]
```

## Le costanti

Come mostrato nell'esempio qui sopra, le variabili sono comode per memorizzare le costanti.
È meglio dare un nome alle costanti invece di far comparire «numeri magici» nel codice.

## Spesso le variabili non servono

Spesso è più leggibile omettere le variabili.

Considera il calcolo della media di un array di numeri

```jq
[2, 4, 8, 7]
| add as $sum
| length as $len
| $sum / $len
```

rispetto a

```jq
[2, 4, 8, 7] | add / length
```

Questo mette in luce uno degli aspetti più potenti di `jq`: l'input di un filtro viene fornito a _ogni_ sotto-espressione:

- l'array di input `[2,4,8,7]` viene passato ad `add` (che somma i numeri applicando l'operatore `+` a tutti gli elementi)
- _in parallelo_, anche `[2,4,8,7]` viene passato a `length`
- quando queste sotto-espressioni terminano, i loro risultati vengono divisi, restituendo il valore medio dei numeri nell'array di input.

## Gli operatori `jq` che ti servono per l'esercizio di apprendimento

### L'operatore alternativo: `//`

L'espressione `a // b` produce `b` se `a` è false o null, altrimenti produce `a`.
Nel contesto dell'assegnazione di una variabile, questo è molto comodo per fornire un valore predefinito:

```jq
(.input.theAnswer // 42) as $answer | ...
```

### Gli operatori aritmetici

- `+`, `-`, `*` sono i soliti operatori numerici di addizione, sottrazione e moltiplicazione.
