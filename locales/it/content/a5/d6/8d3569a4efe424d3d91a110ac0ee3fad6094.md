# Introduzione

La maggior parte delle parole sulle sequenze che hai visto restituisce sequenze *nuove* e lascia intatti i suoi input: `suffix`, `reverse`, `map` e così via. Ma gli array e i vector supportano anche la **mutazione in place**, ed entrambi tornano utili quando vuoi registrare uno stato che cambia nel tempo.

## Due tipi di sequenza mutabile

- **Gli array** (`{ … }`) hanno una lunghezza fissa. `<array> ( n elt -- array )` (in [`arrays`][arrays]) costruisce un array nuovo di lunghezza `n`, riempito con copie di `elt`.
- **I vector** (`V{ … }`) crescono e si riducono. Usa `V{ } clone` per averne uno nuovo e vuoto; `<vector> ( n -- vector )` (in [`vectors`][vectors]) prealloca la capacità per `n` elementi.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## Cambiare uno slot

Queste due funzionano su entrambi i tipi di sequenza: entrambe si aspettano la sequenza dopo l'indice:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth` assegna; `change-nth` applica una quotation all'elemento in posizione `n`. Entrambe queste parole di [`sequences`][sequences] non restituiscono nulla sullo stack: la mutazione è l'effetto.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## Crescere e ridursi

Queste tre hanno senso solo sui vector, dato che gli array non possono cambiare lunghezza:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## Da vector ad array

Quando hai costruito un vector e vuoi restituire un array a lunghezza fissa, `>array ( seq -- array )` (in [`arrays`][arrays]) restituisce un nuovo array con gli stessi elementi:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`, per conservare un'istantanea

La mutazione modifica la sequenza in place. Se chi chiama ti passa una sequenza e stai per modificarla, `clone` (in [`kernel`][kernel]) ti dà una copia nuova e indipendente, così la vista di chi ha chiamato non cambia sotto i suoi occhi:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

La stessa precauzione vale per `V{ }` e per altri letterali vuoti. In alcuni linguaggi, `[]` o `vec![]` allocano un contenitore nuovo ogni volta che l'espressione viene valutata. In Factor, il letterale `V{ }` scritto nel codice è *un unico* oggetto, condiviso da ogni punto di chiamata che lo menziona. Se fai `push` direttamente su `V{ }`, la chiamata successiva vede quel che è rimasto. `V{ } clone` crea la copia nuova che vuoi quasi sempre.
