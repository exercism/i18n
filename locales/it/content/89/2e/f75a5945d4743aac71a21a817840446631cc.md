# Informazioni

In C#, una tupla è una struttura dati che organizza i dati, contenendo due o più campi di qualsiasi tipo.

Di solito una tupla si crea mettendo 2 o più espressioni separate da virgole all'interno di una coppia di parentesi tonde.

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

Come qualsiasi altra espressione, una tupla può essere usata in diversi modi: nelle [assegnazioni][tuple-assignment], per inizializzare un campo o una variabile, come [valore restituito][tuple-return-values] da un metodo oppure passata come parametro. Se ne può verificare l'[uguaglianza][tuple-equality]. L'uguaglianza delle tuple è illustrata in dettaglio nell'esercizio `pattern-matching-tuples`, ma qui sotto trovi un esempio per completezza.

I campi si estraggono con la sintassi del punto. Per impostazione predefinita, il primo campo è `Item1`, il secondo `Item2`, e così via. I nomi non predefiniti sono trattati più avanti nella sezione _Denominazione_.

Una tupla può essere usata come parametro generico, ad esempio `IList<(bool, string)>`

Inoltre, le tuple supportano la «decostruzione», di cui parliamo più avanti, e possono essere usate nel pattern matching, che è trattato in un esercizio successivo.

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

Questa [introduzione][tuples] mostra come definire e usare le tuple.

## Denominazione

I nomi dei campi come `Item1` non rendono il codice leggibile. Ci sono 3 modi per dare un nome ai campi: a) nella dichiarazione del tipo, b) nell'espressione che lo crea, c) tramite gli [inizializzatori di proiezione delle tuple][tuple-projection-initializers] (non illustrati qui).

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

Non cercare di essere troppo astuto con il meccanismo di denominazione. In realtà è solo zucchero sintattico. Per esempio, non puoi cambiare i nomi di una tupla quando le assegni i valori di un'altra tupla.

## Decostruzione

A volte è comodo prendere una tupla, assegnare i campi a più variabili e inizializzarle se serve.
Questo meccanismo si chiama [decostruzione][tuple-deconstruction]. (Può anche
essere applicato ai tuoi oggetti. Vedi [qui][udt-deconstruction]).

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## Assegnazione dei campi

Ai campi delle tuple si può assegnare un valore individualmente.
Tuttavia, vista la tendenza di C# verso l'immutabilità, questo
tipo di uso non è molto diffuso. Spesso le tuple si usano come se fossero immutabili,
cosa che ovviamente non sono.

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## Contesto

Le tuple di cui stiamo parlando non vanno confuse con [`System.Tuple`][system-tuple],
che probabilmente si trova solo in basi di codice legacy.

La situazione è un po' più confusa quando si parla di `System.ValueTuple`.
La [documentazione][system-value-tuple] dell'ultimo overload di [`System.ValueTuple`][system-value-tuple] afferma che
«i tipi value tuple forniscono l'implementazione runtime che supporta le tuple in C#».
Con «tipi value tuple», qui si riferiscono agli overload generici di `System.ValueTuple`.
Con «tuple» intendono le cose di cui ci siamo occupati in questo esercizio.
In sostanza, dicono che `System.ValueTuple` è un dettaglio implementativo delle tuple. Molto
probabilmente, nella maggior parte dei casi, questo interessa poco ai più. Purtroppo gran parte della
documentazione sulle «tuple», compresa quella di Microsoft, è costellata di riferimenti
a `System.ValueTuple`. Probabilmente non è un problema sorvolare su questi riferimenti.

## Altri usi e limitazioni

Il pattern matching è un uso particolarmente produttivo per le tuple. È
trattato in un esercizio successivo.

Le tuple permettono anche qualche altro piccolo tocco stilistico:

- Assegnazione multipla (soprattutto nei costruttori), ad esempio `(this.field1, this.field2) = (arg1, arg2);`
- Scambiare o riciclare valori, ad esempio `(a, b) = (b, a);`
- Usarle al posto di uno `struct` in una lista
- Usarle come chiave di un dizionario o come contenuto di un insieme.
- Usarle in LINQ. (LINQ è trattato in esercizi successivi).

La documentazione descrive le tuple come un meccanismo leggero, e questa è la chiave del
loro uso efficace. Usare una tupla invece di una classe o di uno struct può portare a una noiosa
ripetizione dei tipi dei suoi campi e, forse, dei loro nomi. Questo vale in particolare quando
la si usa come argomento di un metodo o come argomento generico nelle collezioni.

È meglio usare con giudizio trucchi come l'assegnazione multipla e lo scambio.

Le operazioni relazionali diverse da uguaglianza e disuguaglianza non sono supportate.

Nota che le tuple sono state introdotte nel linguaggio relativamente di recente (C# 7),
quindi se vuoi usarle dovresti assicurarti che la tua base di codice
usi la [versione][language-version] 7 o successiva del linguaggio.
