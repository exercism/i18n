# Approfondimento

In assembly, qualsiasi dato è una sequenza di byte.
Questo significa che qualsiasi dato può essere visto come un **[array][array]** di quei byte sottostanti.

## Accedere agli elementi di un array

Per accedere a un qualsiasi valore in memoria, è necessario calcolare il suo **indirizzo effettivo**.
Un indirizzo effettivo è un'espressione che può essere composta da:

- un _indirizzo di base_, per esempio quello indicato dall'etichetta di una variabile.
- un _registro indice_, eventualmente scalato di `1`, `2`, `4` o `8`.
- un _displacement_ con segno a 32 bit, cioè un numero da sommare (o sottrarre) all'indirizzo di base.

Nota che questo indirizzo è _indicizzato da 0_, quindi un indirizzo di base, senza alcun offset, punta al primo byte di una variabile.
Ecco perché dereferenziare la memoria usando solo un'etichetta senza alcun offset, come abbiamo fatto nei concetti precedenti, restituisce un valore che inizia dal suo primo byte:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 è [little endian][endianness].
Questo significa che il byte meno significativo di un valore multibyte è memorizzato all'indirizzo di memoria più basso.

Di conseguenza, quando si accede ai singoli byte di un valore multibyte, è necessario aggiungere un offset positivo all'indirizzo di base per raggiungere i byte più significativi.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

Una variabile inizializzata dichiarata con una lista di valori è un array di quei valori, e ogni elemento ha la dimensione specificata.
Tuttavia, gli offset sono sempre in _byte_, anche quando ogni elemento dell'array ha una dimensione maggiore:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

Nota che, dato che gli indirizzi sono in byte, è possibile accedere direttamente a un singolo byte di qualsiasi elemento di un array:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

Per lo stesso motivo, è possibile accedere a più della dimensione di un elemento con una sola istruzione:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
L'assembly non esegue alcun controllo dei limiti sugli accessi agli array.
Un indice oltre la fine di un array legge o scrive memoria al di fuori di esso.
Questo può portare a risultati errati in modo silenzioso, alla corruzione di altri dati e, se la memoria a cui si accede non è mappata, a un errore a runtime.
Il programmatore è responsabile di mantenere ogni indirizzo effettivo all'interno dell'array.
~~~~

## Calcolare la dimensione di un array inizializzato

NASM (The Netwide Assembler, l'assembler usato da questo track) ha un simbolo speciale (`$`) che indica la posizione corrente in memoria.
Questo simbolo offre un modo comodo per calcolare la dimensione totale in memoria occupata da un array:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

Usato subito dopo `example`, `$` contiene l'indirizzo in memoria della fine dell'array.
Questo significa che `$ - example` è la differenza tra quell'indirizzo e quello puntato dall'etichetta `example`.
Questa è esattamente la dimensione totale, in byte, occupata dall'array puntato da `example`.

Quindi, definendo `example_length` con questo valore, abbiamo creato una variabile di 8 byte che memorizza la dimensione, o lunghezza, dell'array, in byte.

## La sezione .bss

I dati non inizializzati si dichiarano nella **[sezione .bss][bss]**.
Sulla maggior parte delle piattaforme, questi dati vengono riempiti con zero dal sistema operativo all'avvio del programma.

In NASM, una variabile non inizializzata ha un nome, una direttiva che indica la dimensione dei dati e il numero di elementi da riservare.
Ognuno di questi elementi è separato dagli altri da uno spazio.

Le direttive principali e le dimensioni di dati a esse associate sono:

| direttiva | dimensione |
| :-------: | :------ |
|   resb    | 1 byte  |
|   resw    | 2 byte |
|   resd    | 4 byte |
|   resq    | 8 byte |

Per esempio, questo riserva spazio non inizializzato per `3` byte in una variabile chiamata `example`:

```x86asm
section .bss
    example resb 3
```

E questo riserva spazio non inizializzato per `10` volte `8` byte (quindi, `80` byte) in una variabile chiamata `arr`:

```x86asm
section .bss
    arr resq 10
```

Le variabili in `section .bss` sono mutabili, cioè si possono leggere e scrivere.

Ai dati non inizializzati si può accedere allo stesso modo dei dati inizializzati, usando il loro indirizzo effettivo.
Allo stesso modo, hanno anche una durata di memorizzazione statica e sono accessibili da qualsiasi funzione nello stesso file sorgente (e, se dichiarati `global`, anche in altri file sorgente).

## Accedere agli indirizzi di un array con l'istruzione lea

Come abbiamo visto in un concetto precedente, l'istruzione `lea` calcola un indirizzo di memoria effettivo.
Può essere usata per calcolare l'indirizzo di qualsiasi elemento di un array, seguendo la stessa semantica.

Nota che nell'indirizzamento relativo è spesso necessario caricare l'indirizzo della variabile in un registro prima di formare un indirizzo più complesso:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
Uno dei vantaggi di `lea` è che usa l'aritmetica del calcolo degli indirizzi per calcolare un valore senza accedere davvero alla memoria a quell'indirizzo.
Questo lo rende utile per fare calcoli aritmetici anche quando nessuno dei registri contiene un indirizzo di memoria:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
