# A proposito dei condizionali

## Operatori di confronto

Gli [operatori di confronto][operators] sono simili a quelli di molti altri linguaggi, con qualche estensione.

Per l'uguaglianza, gli operatori sono `==` (uguale) e `!=` (diverso).

```Kotlin
val txt = "abc"
txt == "abc" // => true
txt != "abc" // => false
```

Inoltre, gli operatori `===` e `!==` verificano l'[«uguaglianza referenziale»][referential-equality]: `a === b` se e solo se `a` e `b` puntano allo stesso oggetto. Questo avrà più senso più avanti nel percorso.

Anche gli operatori di maggiore e minore sono quelli consueti.

```Kotlin
1 < 3 // => true
3 > 3 // => false
3 <= 3 // => true
4 >= 3 // => true
```

## Ramificazioni con `if`

Questa è la forma completa di un'[espressione `if`][if-else]:

```Kotlin
if (conditional1) {
//    something...
} else if (conditional2) {
//    something...
} else {
//    something...
}
```

- Le parentesi tonde `()` attorno a ogni condizione sono obbligatorie.
- Una condizione deve restituire un valore booleano `true` o `false`.
  Kotlin non ha il concetto di «truthy» e «falsy» che si trova in alcuni linguaggi.
- Le parentesi graffe `{}` sono facoltative se c'è una sola espressione.
- Sia `else if` sia `else` sono facoltativi, e possono esserci più blocchi `else if`.

L'espressione `if` può anche essere usata per «scegliere» un valore:

```Kotlin
val number = 100000
val description = if (number > 100) "number is over 100" else "number is less than 100"
// => description = "number is over 100"
```

## Alternative?

Per una scelta deliberata, Kotlin _non_ ha l'operatore ternario `? :` che si trova in Java.
Si preferisce una forma concisa di `if ... else`:

```Kotlin
val result = if (isOk) goodValue else badValue

return if (isOK) goodValue else badValue
```

A differenza di Ruby, la forma concisa `if ... else` ha *sempre* bisogno di un `else` e quindi non può essere usata come istruzione di guardia:

```kotlin
return 42 if (isOk)
// Syntax error: Unexpected tokens (use ';' to separate expressions on the same line).
// Syntax error: Expecting an expression.

return if (isOk) true
// 'if' must have both main and 'else' branches when used as an expression.
```

Nota che in Kotlin `if` è un'[_espressione_][expression] che restituisce un valore.
Non è un'[_istruzione_][statement] come in Java.

Vedremo in un concetto successivo che Kotlin ha un potente costrutto [`when`][when], pensato per sostituire lunghe catene di clausole `else if` con il pattern matching.
