L'interfaccia pubblica di una base di codice va progettata con attenzione: ogni funzione pubblica aumenta i costi di manutenzione a lungo termine e rende più difficile la riorganizzazione.

In ogni esercizio di Exercism, l'interfaccia pubblica è definita dalla suite di test.
Se una funzione viene testata, deve essere pubblica.
Tutte le altre funzioni dovrebbero essere private, comprese quelle con lo stesso nome ma con arietà diverse.

```elixir
# you defined the following public function

%{actual}

# make it private like this

%{expected}
```
Nota che gli argomenti predefiniti modificano l'arietà di una funzione.

Quando si scrive una libreria, spesso è necessario rendere pubbliche le funzioni perché siano utilizzabili tra i moduli.
Per nascondere queste funzioni alla documentazione, chi scrive una libreria aggiunge `@doc false` prima delle definizioni delle funzioni, oppure `@moduledoc false` per nascondere l'intero modulo.
