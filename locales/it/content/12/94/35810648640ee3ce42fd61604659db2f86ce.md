# Introduzione

In Elixir, tutti gli errori implementano l'_Exception Behaviour_. Proprio come l'_Access Behaviour_, l'_Exception Behaviour_ definisce le funzioni di callback che un modulo deve implementare per rispettare il contratto software del behaviour. Una volta definito un errore, questo ha le seguenti proprietà:

- Il nome del modulo definisce il nome dell'errore.
- Il modulo definisce uno struct di errore.
- Lo struct avrà un campo `:message`.
- Il modulo può essere usato con `raise/1` e `raise/2` per sollevare l'errore desiderato

L'_Exception Behaviour_ specifica anche due callback: `message/1` e `exception/1`. Se non vengono implementate, si useranno le implementazioni predefinite. `message/1` trasforma lo struct di errore in un messaggio leggibile quando viene chiamata con `raise`. `exception/1` permette di aggiungere ulteriore contesto al messaggio quando viene chiamata con `raise/2`

## Definire un'eccezione

Per definire un'eccezione a partire da un modulo di errore, usiamo la macro `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

## Usare le eccezioni

Un errore definito si può usare come un errore integrato, tramite `raise/1` o `raise/2`.

- `raise/1` solleva un errore specifico tramite il nome del suo modulo oppure, se l'argomento è una stringa, solleva un `RuntimeError` con la stringa come messaggio.
- `raise/2` solleva un errore specifico tramite il nome del suo modulo e accetta un argomento di attributi, usato per ottenere l'errore con il messaggio appropriato.
