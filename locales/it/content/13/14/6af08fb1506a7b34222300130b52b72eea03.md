# Istruzioni

Più impari a programmare, più inizi a pensare che questa possa essere più di una semplice moda.
Potrebbero esserci anche delle opportunità di business: le persone scrivono codice, vogliono salvarlo, condividerlo, collaborare, magari ricevere anche qualche feedback.

Va bene, facciamolo, costruiamo un servizio per incoraggiare le persone a programmare: hup, hup, gente, iniziate a usare git!
Chiamiamolo... GitHup.

Ti metti a costruire un'API REST JSON: utenti, pull request, commenti, il backend è fatto in fretta.
Ecco un esempio del payload che viene servito quando chiedi al server la lista dei commenti su una pull request:

```json

        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
      },

        "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1"

        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1"
```

Certo, il frontend sarà fatto in Elm, ma prima devi capire cosa sono quei famigerati decoder/encoder.

```exercism/note
A parte la storia umoristica, i requisiti dell'esercizio sono presi direttamente dagli endpoint dell'API REST di GitHub per i commenti di revisione delle pull request.
Alcuni campi sono stati rimossi dagli schemi JSON per semplicità, ma questo è il più vicino possibile alle applicazioni del mondo reale.
```

## 1. L'ID, per favore!

Il tuo occhio di falco ha notato che sia i commenti sia gli utenti hanno un campo `id`, un punto perfetto da cui iniziare.

Definisci `decodeId` in modo che possa decodificare un oggetto JSON con un `id` intero.

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. Come mi chiamo, già?

Nell'esempio qui sopra noti che non tutti gli utenti hanno un nome.

Definisci `decodeName` in modo che possa decodificare una stringa nel campo `name`, se c'è.
Nessun nome? Nessun problema, restituisci semplicemente `Nothing`.
Questo decoder non dovrebbe mai fallire.

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. User? Lo conosco a malapena!

Per decodificare gli utenti siamo praticamente a metà strada, finiamolo.

Definisci `decodeUser` in modo che possa decodificare un oggetto utente JSON.
Assicurati di usare `decodeId` e `decodeName` in `decodeUser`.

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. Sono un commento forte e indipendente

Alcuni commenti in una revisione di una pull sono autonomi, e quindi non hanno un `pull_request_review_id`.
Tuttavia, la specifica dice che in tal caso dovrebbe comunque esserci un campo `pull_request_review_id`, ma il valore dovrebbe essere `null`, il `Nothing` dei poveri.

Definisci `decodePullRequestReviewId` in modo che possa decodificare un intero nel campo `pull_request_review_id`, se c'è.
Se non c'è un intero, dovrebbe esserci un `null`; se non c'è un `null`, il decoder dovrebbe fallire.

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. Attività collaterale

Passiamo a questo interessante campo `side`.
In una revisione di una pull, puoi commentare il codice che è stato rimosso (sul lato `Left` dello schermo) o il codice che è stato aggiunto (sul lato `Right` dello schermo).

Definisci `decodeSide` in modo che possa decodificare `"LEFT"` o `"RIGHT"` nel campo `side` e associarli alla variante di tipo corrispondente.

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. Il risveglio dei link

Ogni commento ha un insieme di link, che non sembra essere coerente tra i vari commenti.

Definisci `decodeLinks` in modo che possa decodificare una collezione di URL nel campo `_links`.
I nomi e il numero di link possono variare, assicurati di tenerne conto.
I link stessi sono oggetti JSON che dovrebbero sempre avere un campo `href`.

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. Commenti sì

Ci siamo quasi, finiamolo.

Definisci `decodeComment` e `decodeComments` in modo che possano decodificare rispettivamente un singolo oggetto commento JSON o una lista di commenti.
Assicurati di usare in `decodeComment` tutte le funzioni definite finora, con l'eccezione di `decodeName`.
Naturalmente, anche `decodeComments` dovrebbe usare `decodeComment`.

## 8. Tutto si ricollega

Manca ancora una funzionalità in tutto questo: poter inviare un nuovo commento al server.
Per questo devi ottenere l'opposto di un decoder, devi essere in grado di trasformare un `Comment` di Elm in un `Value` JSON.

Definisci `encodeComment` in modo che possa codificare qualsiasi `Comment` valido.
L'ordine dei campi non conta, purché l'encoder riesca a produrre un valore che `decodeComment` possa decodificare.
