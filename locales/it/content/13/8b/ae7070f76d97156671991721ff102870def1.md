# Librerie

Exercism si propone di insegnare la [fluidità](/docs/using/product/fluency) nella sintassi, negli idiomi e nella libreria standard del linguaggio.
Qui non si parla esplicitamente di librerie esterne (non integrate), perché quelle rientrano nella _competenza_.
Gli esercizi devono quindi, con poche eccezioni, essere risolvibili senza usare librerie.

## Perché supportare le librerie

Ci sono un paio di motivi per cui un track potrebbe comunque voler supportare le librerie:

1. Il linguaggio ha una libreria standard (molto) minimale.
   Un esempio di linguaggio di questo tipo è Rust.
2. La libreria aggiunge funzionalità di testing.
   Un esempio è una libreria che aggiunge il supporto al testing basato sulle proprietà.
3. L'esercizio può essere risolto solo usando una libreria.
   Un esempio di esercizio di questo tipo è l'[esercizio lens-person](https://exercism.org/exercises/lens-person), che nella maggior parte dei linguaggi può essere risolto solo usando una libreria.

## Supportare le librerie nel test runner

Dato che il test runner non ha accesso a internet mentre è in esecuzione, non è possibile scaricare le librerie in fase di esecuzione.
L'**unica** soluzione a questo problema è installare/scaricare le librerie in fase di build, dove _hai_ accesso a internet.
In pratica, questo significa che dovrai installare/scaricare le librerie all'interno del Dockerfile.

Ad esempio, il [Dockerfile del test runner per Prolog](https://github.com/exercism/prolog-test-runner/blob/ed7447a7518ede6ee3405e649f50aaec828e318b/Dockerfile) installa la libreria `date_time`:

```dockerfile
RUN swipl pack install date_time -y
```
