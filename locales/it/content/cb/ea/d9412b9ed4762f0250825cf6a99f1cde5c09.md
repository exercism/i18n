# Contratti

Gli argomenti e il tipo restituito di una routine dicono che *tipo* di cosa entra ed esce. Non possono dire che un peso deve essere positivo, né che un harness non riporti mai più capacità libera di quanta ne abbia.

Un **contratto** dice queste cose, nell'intestazione della routine stessa, dove chiunque la legga le vedrà.

## pre

`pre` stabilisce cosa deve essere vero quando la routine viene chiamata. Va tra il tipo restituito e `is`.

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

Questa è una richiesta al **chiamante**: non chiamarla con un load negativo.

## post

`post` stabilisce cosa sarà vero quando la routine risponde. Al suo interno, `result` è il valore restituito.

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

Questa è una promessa al chiamante. Una routine che li ha entrambi è un patto: dammi questo e io ti darò quello.

Più condizioni si uniscono con `and`, come fanno tutti i valori booleani:

```sather
      pre load >= 0 and load <= limit
```

## I contratti non sono eccezioni

Un'eccezione sollevata serve per qualcosa che può accadere. Un contratto violato significa un **bug**: qualcuno ha chiamato la routine in modo sbagliato, oppure la routine non ha fatto ciò che aveva dichiarato.

Quindi un contratto violato non solleva qualcosa che si possa catturare. Quando il controllo dei contratti è attivo, il programma si ferma e stampa quale routine e quale condizione. Quando è disattivato, la condizione non viene nemmeno verificata e il programma va avanti verso qualunque assurdità ne segua.

Ecco perché un contratto è un'affermazione sulla correttezza, non un modo per gestire input non validi. Se ci si aspetta input non validi, controllali e chiama `raise`. Se input non validi significano che il chiamante è sbagliato, dillo con `pre`.

## Attivare il controllo

Questo Sather controlla i contratti quando si passa `-chk` al compilatore:

```
sacomp -chk mine.sa -main MAIN -o mine
```

Senza di esso, `pre` e `post` sono documentazione che il compilatore ha letto e ha riconosciuto come ben formata, e nulla di più. I test di questo esercizio vengono compilati senza `-chk`, quindi non possono individuare al posto tuo un contratto violato; verificano che le routine facciano la cosa giusta quando vengono usate correttamente.
