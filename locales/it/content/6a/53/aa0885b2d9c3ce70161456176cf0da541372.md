# Concetti di frequenza delle lettere in parallelo

Questo esercizio vanta una grande varietà di possibili soluzioni, anche con l'aiuto di crate esterni. Per mantenere il carico di lavoro gestibile, questo documento contiene una piccola selezione di possibilità. Le soluzioni con Crossbeam hanno un insieme di concetti simile a quello elencato qui, mentre Rayon ne richiede solo un sottoinsieme.

## Aspetti generali

- Stringhe: in particolare, qui il tipo `str` è sempre un fattore determinante
- Unicode: i compromessi in termini di prestazioni e funzionalità tra metodi ASCII e metodi Unicode. Il benchmarking risulta falsato quando il benchmark usa metodi Unicode e la soluzione usa metodi ASCII.
- Iteratori: iterare sull'input o su sue parti.
- Collezioni: iterare su una `HashMap` e usare `Entry`. Di solito gli handle vengono raccolti in un `Vec`.
- Riferimenti
- Numeri: in particolare il trait `Add`
- Ciclo for: non è possibile fare join dei thread in un Iterator a causa di move.
- **Opz** Visibilità: mantenere i dettagli implementativi non pubblici
- **Opz** slice: `.chunks()` è un metodo spesso usato per suddividere l'input tra i thread di lavoro. In alternativa si usano le sottoslice.
- **Opz** Funzioni di ordine superiore: le HashMap si possono unire con una funzione di ordine superiore insieme a un Iterator.
- **Opz** Tipi: per suddividere l'input possiamo convertire numeri interi in valori in virgola mobile per applicare l'arrotondamento
- **Opz** Crate

## Approccio std con o senza canali

- Parallelismo: sottotema spawn e join dei thread.
- Iteratori: sottotema valutazione pigra. Fare spawn e join di thread con lo stesso Iterator impedisce il parallelismo.
- Lifetime: sottotemi la lifetime `'static lifetime` e la semantica esplicita di `move`
- Iteratori/lifetime: sottotema iteratori che consumano. I thread non possono essere sottoposti a join usando un Iterator.
- Tipo Option: estrarre i risultati di thread o canali
- Funzioni: in particolare, per fare spawn dei thread servono funzioni di ordine superiore. Le closure sono un'opzione.

## Approccio std con canali

- Parallelismo: sottotema canali.
- Tuple: `mpsc::channel()` restituisce una tupla
- Destrutturazione: una tupla può essere destrutturata al momento dell'assegnazione
- Lifetime: `drop()`

## Approccio alternativo con variabili condivise

- Conteggio dei riferimenti: condividere dati aggregati tra thread con una collezione a conteggio di riferimenti.
- **Menzione d'onore**: parallelismo, sottotema mutex. Non è necessario né utile per questo esercizio, ma resta un concetto comune. Correlato: `RwLock`.

### Esempio di approccio std con canali

```rust
use std::collections::HashMap;
use std::thread;
use std::sync::mpsc;

pub fn frequency(input: &[&str], worker_count: usize) -> HashMap<char, usize> {
    let (tx, rx) = mpsc::channel();

    let _handles = input.chunks((input.len() as f64 / worker_count as f64).ceil() as usize)
        .map(|slice| slice.concat())
        .map(|slice| {
            let tx = tx.clone();
            thread::spawn(move || {
                let mut map: HashMap<char, usize> = HashMap::new();
                for chr in slice.chars().filter(|c| c.is_alphabetic()) {
                    if let Some(c) = chr.to_lowercase().next() {
                        (*map.entry(c).or_insert(0)) += 1;
                    };
                }
                tx.send(map).unwrap()
            })
        }).collect::<Vec<_>>();

    drop(tx);

    let mut result: HashMap<char, usize> = HashMap::new();
    for received in rx {
        for (c, count) in received {
            *result.entry(c).or_insert(0) += count;
        }
    }

    result
}
```

### Esempio con crate e Arc

```rust
use std::collections::HashMap;
use std::iter::FromIterator;
use std::sync::Arc;
use dashmap::DashMap;

pub fn frequency(input: &[&str], worker_count: usize) -> HashMap<char, usize> {
    let map: Arc<DashMap<char, usize>> = Arc::new(DashMap::new());

    let handles = input
        .chunks((input.len() as f64 / worker_count as f64).ceil() as usize)
        .map(|slice| slice.concat())
        .map(|slice| {
            let map = map.clone();
            std::thread::spawn(move || {
                for c in slice.chars().filter(|c|c.is_alphabetic())
                  .flat_map(|c| c.to_lowercase().next()) {
                    *map.entry(c).or_insert(0) += 1;
                }
            })
        }).collect::<Vec<_>>();

    for h in handles {
        h.join().unwrap();
    }

    map.iter().map(|x| (*x.key(), *x.value())).collect()
}
```
