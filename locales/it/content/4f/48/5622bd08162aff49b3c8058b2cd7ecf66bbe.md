# Introduzione

## Risultati

Gleam non usa le eccezioni per la gestione degli errori: al loro posto, le funzioni che possono avere successo o fallire restituiscono il tipo generico `Result`.

Il tipo `Result` è integrato nel linguaggio, quindi non devi definirlo né importarlo, ma se lo definissi tu sarebbe così:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

La variante `Ok` viene restituita quando una funzione ha successo, mentre la variante `Error` viene restituita quando una funzione fallisce.

I result sono molto comuni in Gleam, e chi programma in Gleam usa di norma il [modulo `gleam/result`](https://hexdocs.pm/gleam_stdlib/gleam/result.html) per lavorarci più facilmente.

La funzione `result.map` può essere usata per chiamare una funzione sul valore contenuto in un result, se questo è un `Ok`, oppure per lasciar passare un `Error` invariato.

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

La funzione `result.try` è simile, ma la funzione di callback deve restituire un result. È utile per concatenare più funzioni che restituiscono dei result.

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
