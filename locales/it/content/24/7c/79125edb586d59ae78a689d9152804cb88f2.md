# Informazioni

Un **numero in virgola mobile** è un numero che può avere una parte frazionaria, come `-1.23` o `3.1415`.

Per rappresentare un numero di questo tipo come una sequenza di byte, x86-64 usa lo standard [IEEE-754][ieee].
I due formati più comuni di questo standard sono i numeri in virgola mobile a precisione singola e quelli a precisione doppia.
x86-64 li supporta entrambi.

Un numero in virgola mobile a precisione singola è largo 32 bit, mentre uno a precisione doppia è largo 64 bit.

## I registri XMM

In x86-64 ci sono 16 registri dedicati all'aritmetica in virgola mobile, chiamati da `xmm0` a `xmm15`.

Questi registri sono larghi almeno 128 bit, ma i processori recenti arrivano a 256 o 512 bit.
In pratica, però, la maggior parte dei numeri in virgola mobile usa solo i 32 o i 64 bit più bassi, a seconda della precisione desiderata.

## La conversione tra numeri

Esiste una famiglia di istruzioni per convertire tra formati numerici: `cvtxx2yy`.

Sia `xx` che `yy` non sono valori letterali, ma segnaposto:

- `xx` è un segnaposto per il tipo dell'operando sorgente.
- `yy` è un segnaposto per il tipo dell'operando di destinazione.

Questi segnaposto possono assumere molte forme, tra cui:

| segnaposto | significato            |
| ----------- | --------------------- |
| `si`        | intero con segno      |
| `ss`        | virgola mobile a 32 bit |
| `sd`        | virgola mobile a 64 bit |

Per esempio:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

Nota che è possibile convertire un intero a 32 bit in un numero in virgola mobile a 64 bit, o un intero a 64 bit in un numero in virgola mobile a 32 bit.
Allo stesso modo, è anche possibile convertire un numero in virgola mobile a 32 bit in un intero a 64 bit, o un numero in virgola mobile a 64 bit in un intero a 32 bit.
In altre parole, la dimensione dei due operandi di una `cvtxx2yy` _non deve necessariamente essere la stessa_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

Quando il numero in virgola mobile non può essere espresso esattamente come numero intero, `cvtxx2si` arrotonda il numero in base al controllo di arrotondamento contenuto in uno speciale registro chiamato `mxcsr`.
L'arrotondamento può essere al più vicino, per difetto, per eccesso o per troncamento.
All'ingresso di una funzione non esiste un valore predefinito garantito.

Nota che un risultato esatto non viene arrotondato e quindi non è influenzato dal controllo di arrotondamento.
Ad esempio, `42.0` verrà _sempre_ convertito in `42`.

Esiste una famiglia simile di istruzioni con il formato `cvttxx2si` (con una `t` in più) che tronca sempre il risultato.

## L'arrotondamento

La famiglia di istruzioni `roundxx` converte un numero in virgola mobile presente nell'operando sorgente in un numero in virgola mobile arrotondato, memorizzato nell'operando di destinazione.

Qui `xx` è un segnaposto per il tipo degli operandi, come al solito: `ss` per la precisione singola e `sd` per la precisione doppia.

Queste istruzioni prendono come terzo operando un numero costante.
Questo numero indica la modalità di arrotondamento:

| Numero | Modalità        |
| :----- | :----------- |
| 0      | Al più vicino    |
| 1      | Per difetto (floor) |
| 2      | Per eccesso (ceil)    |
| 3      | Troncamento     |

Per esempio:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

Dato che queste istruzioni producono un risultato esatto, possono essere usate come preparazione a una `cvtxx2si`.

## Le istruzioni aritmetiche

Molte operazioni con i numeri in virgola mobile usano istruzioni con un nome simile a quello della loro equivalente per gli interi, ma con l'aggiunta del segnaposto necessario (`ss` o `sd`) alla fine.
Queste istruzioni hanno due operandi, con la semantica abituale, anche quelle che eseguono moltiplicazioni o divisioni:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## Lo spostamento

Le istruzioni per spostare un valore da un registro XMM a un altro sono `movss` e `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

**Non** è possibile spostare un valore immediato (un intero costante con segno) direttamente in un registro xmm.
Questo numero deve prima essere spostato in un registro di uso generale e poi convertito con `cvtsi2xx`:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## I confronti

Esistono due gruppi di istruzioni per fare un confronto tra due numeri in virgola mobile.
Hanno la forma `comixx` e `ucomixx`, dove `xx` è `ss` o `sd`.
Entrambi impostano i flag in `rflags` come al solito, seguendo la stessa semantica di `cmp`.

La differenza tra loro è che `ucomixx` imposta il `parity flag (PF)` se uno dei due numeri in virgola mobile ha valore `NaN`, mentre `comixx` solleva un'eccezione in questo caso.

Il confronto tra valori in virgola mobile è _senza segno_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## Altre istruzioni

Ci sono molte altre istruzioni per lavorare con i numeri in virgola mobile, che implementano operazioni comuni.
Alcune di esse sono:

| Istruzione | Descrizione                                      |
| :---------- | :----------------------------------------------- |
| `sqrtxx`    | Calcola la radice quadrata (`sqrt(x)`)                 |
| `rcpss`     | Calcola il reciproco (`1/x`)                      |
| `rsqrtss`   | Calcola il reciproco della radice quadrata (`1/sqrt(x)`) |
| `minxx`     | Calcola il minimo (`min(x, y)`)                   |
| `maxxx`     | Calcola il massimo (`max(x, y)`)                   |

Dove viene usato il segnaposto `xx`, questo può assumere la forma `ss` o `sd`, come al solito.
Tuttavia, `rcpss` e `rsqrtss` funzionano solo con numeri in virgola mobile a precisione singola.

Queste istruzioni hanno tutte due operandi.

## La convenzione di chiamata

Nella System V ABI, i primi otto argomenti in virgola mobile vengono passati alle funzioni in ordine, da `xmm0` a `xmm7`.
I valori in virgola mobile vengono restituiti dalle funzioni in `xmm0` e, se necessario, in `xmm1`.

Tutti i registri `xmm` sono liberamente utilizzabili, nessuno di essi è riservato al chiamante.

## La memoria

I valori in virgola mobile possono essere definiti in memoria seguendo la stessa semantica degli interi della stessa dimensione.
NASM (The Netwide Assembler, l'assembler usato in questa traccia) permette anche di dichiarare valori in virgola mobile in notazione scientifica.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```

## AVX/AVX2

Le estensioni AVX/AVX2 dell'architettura x86-64 introducono nuove forme a tre operandi per le istruzioni in virgola mobile, che separano la destinazione dalle sorgenti.
Prendono un prefisso `v` (da _vettore_) per distinguerle dalla forma SSE legacy che abbiamo visto sopra:

```x86asm
vaddss xmm0, xmm1, xmm2 ; xmm0 = xmm1 + xmm2 (32-bit floating-point)
vmulsd xmm2, xmm3, xmm4 ; xmm2 = xmm3 * xmm4 (64-bit floating-point)
```

In questa traccia ci siamo limitati alle istruzioni e ai registri fino alle precedenti estensioni SSE.
Questo basta per insegnare le basi e garantisce la compatibilità con un'ampia gamma di CPU.

Tuttavia, il test runner supporta pienamente AVX e AVX2.
Sei libero di usarli.
