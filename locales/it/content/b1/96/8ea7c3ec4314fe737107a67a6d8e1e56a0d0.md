# Introduzione

Questo esercizio riprende quanto hai visto in [Birdwatching in giardino][backyard-birdwatcher] e introduce le parole di ordine superiore che accettano una *quotation*, cioè un frammento di codice tra parentesi quadre (`[ ]`), per guidare l'operazione.

## Le quotation come valori

Una quota è semplicemente un frammento di codice letterale. Puoi passarla come dato a un'altra parola:

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

Qui `[ 2 > ]` è una quotation che accetta un numero e lascia un valore booleano. `count` la esegue su ogni elemento e conta i risultati veri.

## Filtrare e scartare

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

`without` tratta il suo secondo argomento come un insieme: qualsiasi elemento di `seq` che sia `=` a *qualsiasi* elemento di `exclude` viene eliminato. `sift` è il caso speciale di `reject` senza quotation: mantiene ogni elemento tranne `f`, comodo per ripulire i vuoti lasciati da un precedente `map`.

### Conservare il risultato del test

`find` restituisce l'*elemento* corrispondente. Quando il test *calcola* già il valore che ti serve davvero, `map-find` ti risparmia un secondo passaggio: esegue la quotation su ogni elemento e restituisce il primo risultato diverso da `f` **e** l'elemento che l'ha prodotto.

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

La quotation restituisce `f` per gli elementi che non soddisfano il test e il risultato da conservare per quello che lo soddisfa. Se nessun elemento lo soddisfa, `map-find` lascia `f f`, proprio come `find`.

### Filtrare i record in base a uno slot

Quando gli elementi sono *tuple*, il predicato di solito estrae uno slot tramite il suo reader generato automaticamente `slot>>` e verifica su quello:

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## Inserire un valore fisso con `with`

A volte il predicato ha bisogno di un valore che resta uguale a ogni chiamata, come una soglia, un divisore o una stringa di destinazione. `with` (in [`kernel`][kernel]) incorpora quel valore fisso nella quotation e trasforma una quotation a due argomenti `( value elt -- ? )` nella quotation a un argomento che `filter`, `count`, `map` ed `each` si aspettano:

```
with ( value seq quot -- seq curry )
```

Ogni chiamata per elemento vede `( value elt )` sullo stack, con il valore fisso per primo e l'elemento corrente per secondo:

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## Mappare e iterare

`map` (in [`sequences`][sequences]) applica una quotation a ogni elemento e restituisce l'array dei risultati. `each` fa lo stesso percorso ma scarta i risultati: è utile quando la quotation viene eseguita solo per i suoi effetti collaterali. `2map` percorre *due* sequenze in parallelo e combina gli elementi corrispondenti; `2each` e `2reduce` sono i suoi cugini, rispettivamente solo per gli effetti collaterali e per il folding; `zip` è la scorciatoia per «accoppiarli senza combinarli»:

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

`2reduce` fa scorrere un accumulatore attraverso entrambe le sequenze contemporaneamente: la sua quotation accetta `( accumulator elt1 elt2 -- accumulator' )`. Qui accumula un prodotto scalare: ogni coppia viene moltiplicata e i prodotti vengono sommati (`1*10 + 2*20 + 3*30`):

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

`map-as` è il cugino di `map` che forza il tipo della sequenza di output: passa un `{ }` o un `V{ }` vuoto come esemplare per ignorare il tipo predefinito dell'input (altrimenti il mapping di una stringa verso elementi che non sono caratteri dà errore quando Factor prova a rimpacchettare i risultati in una stringa).

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

Entrambe le forme a due sequenze si fermano alla lunghezza dell'input più corto. `zip` equivale a `[ 2array ] 2map`: conserva le coppie invece di ridurle.

## Ordinare

`sort` restituisce una copia ordinata in ordine naturale; `sort-by` (in [`sorting`][sorting]) ordina in base a una chiave estratta da ogni elemento:

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## Aggregare

`map-sum` (in [`sequences`][sequences]) applica una quotation lungo la sequenza e somma i risultati in un solo passaggio:

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## Minimo e massimo

`minimum` e `maximum` restituiscono direttamente l'elemento più piccolo o più grande di una sequenza. `minimum-by` e `maximum-by` (tutti in [`sequences`][sequences]) restituiscono l'elemento la cui chiave estratta è la più piccola o la più grande:

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## Scrivere la tua parola di ordine superiore

Quando la *tua* parola accetta una quotation come argomento a runtime e la inoltra a `map`, `filter`, `each` ecc., dichiara la parola con `; inline`. Questo dice al compilatore di inlineare la tua parola in ogni punto di chiamata, dove la quotation è un letterale noto: senza, il compilatore non ha modo di conoscere l'effetto sullo stack della quotation.

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

Le parole costruite solo da quotation letterali non hanno bisogno di `inline`, ma solo quelle che fanno passare una quotation *in entrata*.

Se una di queste parole `inline` arriva a chiamare *sé stessa*, cioè è un combinatore ricorsivo, dichiarala `; inline recursive`. Senza la parola in più il compilatore si ferma con *«The inline recursive word ... must be declared recursive»*, che ti dice esattamente cosa aggiungere.

## Estrarre il secondo elemento

Per un array di 2 elementi, `second` restituisce il secondo elemento. `first` restituisce il primo. Entrambi sono in [`sequences`][sequences].

## Da numeri a stringhe

`number>string ( n -- str )` (in [`math.parser`][math.parser]) trasforma un numero nella sua forma di stringa decimale:

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
