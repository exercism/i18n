# Istruzioni

In seguito a una recente revisione di sicurezza, ti è stato chiesto di ripulire i file di log archiviati dell'organizzazione.

## 1. Identificare le righe di log corrotte

Ti serve un'idea di quante righe di log nell'archivio non rispettino gli standard attuali.
Ritieni che un semplice test riveli se una riga di log è valida.
Per essere considerata valida, una riga deve iniziare con una delle seguenti stringhe:

- `[DEBUG]`
- `[INFO]`
- `[WARNING]`
- `[ERROR]`

Implementa la funzione `is_valid_line` in modo che restituisca `True` se la riga di log è valida.

```gleam
log_parser.valid_line("[ERROR] Network Failure")
// -> True

log_parser.valid_line("Network Failure")
// -> False
```

## 2. Dividere la riga di log

Poco dopo aver iniziato il progetto di analisi dei log, ti rendi conto che i log di un'applicazione non sono divisi in righe come gli altri. In questo progetto, quelle che sarebbero dovute essere righe separate si trovano invece su un'unica riga, collegate da strane frecce come `<--->` o `<*~*~>`.

In effetti, qualsiasi stringa che abbia come primo carattere `<`, come ultimo carattere `>` e, nel mezzo, zero o più dei seguenti caratteri `~`, `*`, `=` e `-` può essere usata come separatore nei log di questo progetto.

Implementa la funzione `split_line` che prende una riga e restituisce un array di stringhe.

```gleam
log_parser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
// -> ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. Etichettare le righe con i nomi utente

Hai notato che alcune righe di log contengono frasi che si riferiscono agli utenti.
Queste frasi contengono sempre la stringa `"User"`, seguita da uno o più caratteri di spaziatura e poi da un nome utente.
Decidi di etichettare queste righe.

Implementa una funzione `tag_with_user_name` che elabora le righe di log:

- Le righe che non contengono la stringa `"User"` restano invariate.
- Per le righe che contengono la stringa `"User"`, anteponi alla riga `[USER]` seguito dal nome utente.

```gleam
log_parser.tag_with_user_name("[INFO] User Alice created a new project")
// -> "[USER] Alice [INFO] User Alice created a new project"
```

Puoi presumere che:

- Ogni occorrenza della stringa `"User"` è seguita da uno o più caratteri di spaziatura e dal nome utente.
- C'è al massimo un'occorrenza della stringa `"User"` su ogni riga.
- I nomi utente sono stringhe non vuote che non contengono spazi.
