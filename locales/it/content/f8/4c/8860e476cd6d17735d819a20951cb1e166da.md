# Informazioni

## I booleani in Julia

I valori vero o falso sono rappresentati dal tipo `Bool`.
Contiene solo due valori: `true` e `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

A differenza di diversi altri linguaggi, Julia non ha di proposito alcun concetto di «truthiness»: solo le espressioni che restituiscono `true` o `false` vengono trattate come un `Bool`.

In particolare, array o stringhe vuote *non* verranno interpretati come `false`.
Se vuoi una gestione speciale per i valori vuoti, deve esserci un test appropriato come `isempty()`.

## Gli operatori booleani

In Julia ci sono tre [operatori booleani][boolean-operators].

`&&` è l'«and» booleano.
Restituisce `true` se le espressioni su *entrambi* i lati di `&&` sono `true`.

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||` è l'«or» booleano.
Restituisce `true` se un'espressione su *uno dei due* lati di `||` è `true`.

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!` è il «not» booleano.
Scambia (inverte) i valori `true` e `false`.

```julia-repl
julia> !true
false

julia> !false
true
```

Operatori simili saranno concettualmente familiari a chi usa molti altri linguaggi, anche se la sintassi precisa può variare da un linguaggio all'altro.

## La precedenza degli operatori

Nelle espressioni più complesse può essere utile sapere che `&&` ha una [precedenza][operator-precedence] leggermente maggiore di `||` *(allo stesso modo in cui `*` viene applicato prima di `+` nelle espressioni aritmetiche)*.

Fare affidamento su questo può confondere ed essere fonte di errori.
Per chiarezza, usa le parentesi per rendere esplicita la tua intenzione.

## La valutazione a corto circuito

L'espressione `true || x` dipende dal valore di `x`, oppure il compilatore può ignorare `x`?

Julia valuta le espressioni booleane da sinistra a destra e si ferma quando ha un risultato inequivocabile.

Per esempio, `true || x` deve essere `true`, indipendentemente da `x`, quindi `x` non viene valutato.
Allo stesso modo, `false && y` è `false`, senza bisogno di valutare `y`.

Al contrario, `true && x` è `true` *solo se* `x` è `true`, quindi `x` deve essere valutato.

Allo stesso modo, se concateniamo più operatori:

```julia-repl
julia> true && false && something_else
false
```

Poiché `true && false` deve essere `false`, il `something_else` non è importante e viene ignorato dal compilatore.

In questo caso, `something_else` non esisteva come variabile, ma includerlo in questo contesto non ha dato alcun errore *(verificalo nella REPL se hai dei dubbi)*.

Questo tipo di valutazione a corto circuito è usata abbastanza spesso da chi programma in Julia come scorciatoia per intercettare problemi a runtime e casi limite:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

Per esempio, `do_something` potrebbe essere un `return` anticipato dalla funzione se `all_ok` è `false`, oppure l'assegnazione di un valore predefinito a una variabile prima di continuare.

È un leggero abuso della sintassi booleana, ma può essere molto comodo.

## Come funzionano internamente i Bool

Se un Bool è incluso in un'espressione *aritmetica*, `true` viene interpretato come `1` e `false` come `0`, rispecchiando il modo in cui sono memorizzati.

Se sei abituato a linguaggi di livello più basso (C e simili), *per favore* evita di usarlo spesso.
Riduce la leggibilità del codice e rende il debug più difficile.

A volte potresti vedere i valori numerici usati come modo rapido per contare quante cose sono `true`.

```julia-repl
julia> true + false + true
2
```
