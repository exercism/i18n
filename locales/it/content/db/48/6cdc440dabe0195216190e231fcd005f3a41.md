# Informazioni

Classi come `LocalDate` e `LocalDateTime` descrivono un _punto_ nel tempo.
Il pacchetto `java.time` contiene anche due classi che descrivono una _quantità_ di tempo:

- [`Period`][period-docs] è una quantità di tempo basata sulle date, espressa in anni, mesi e giorni, ad esempio «2 mesi e 5 giorni».
- [`Duration`][duration-docs] è invece una quantità di tempo assoluta, espressa in ore, minuti, secondi, millisecondi e nanosecondi, ad esempio «1 ora e 30 minuti».

La differenza è importante perché le unità del calendario non hanno una durata fissa.
Un mese può avere 28, 29, 30 o 31 giorni, quindi «un mese» non corrisponde a un numero fisso di secondi.
Un `Period` segue il calendario, mentre una `Duration` misura il tempo esatto.

| | `Period` | `Duration` |
| --- | --- | --- |
| Memorizza | anni, mesi e giorni | secondi e nanosecondi |
| Si usa con | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

Entrambe le classi sono immutabili.
Metodi come `plusDays()` o `multipliedBy()` restituiscono una _nuova_ istanza e lasciano invariata quella originale.

## `Period`

### Creare un periodo

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

Il risultato di `toString()` usa il [formato ISO-8601 delle durate][iso-8601-durations]: `P` seguito dal numero di anni (`Y`), di mesi (`M`) e di giorni (`D`).
In un `Period` non ci sono le settimane: `Period.ofWeeks(2)` viene memorizzato come 14 giorni.
La stessa notazione si può analizzare di nuovo con `Period.parse()`:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### Aggiungere un periodo a una data

Un periodo si aggiunge o si sottrae a una data con `plus()` e `minus()`:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

Allo stesso modo, un periodo si può aggiungere a un `LocalDateTime`, e l'ora del giorno resta la stessa:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

Un `Instant` non ha un calendario, quindi gli si può aggiungere solo un periodo di giorni.
Un periodo con anni o mesi lancia un'eccezione:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

Prima si aggiungono gli anni, poi i mesi e infine i giorni.
Quando l'aggiunta di anni o mesi cade su un giorno che non esiste, il risultato viene spostato all'ultimo giorno valido di quel mese:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

Questo significa anche che aggiungere un periodo e poi sottrarlo di nuovo non sempre restituisce la data di partenza:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### Il periodo tra due date

`Period.between()` restituisce il periodo da una data (inclusa) a un'altra (esclusa).
Lo stesso risultato si ottiene con `LocalDate.until()`:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

Le parti di un periodo si ottengono con `getYears()`, `getMonths()` e `getDays()`.
Queste parti sono indipendenti l'una dall'altra: `getDays()` restituisce solo la parte dei giorni, non il numero totale di giorni.
`toTotalMonths()` restituisce gli anni e i mesi combinati come numero di mesi, ma non esiste un metodo per il numero totale di giorni, perché dipende da quali mesi sono coinvolti.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### Normalizzare un periodo

Un periodo creato con un metodo factory mantiene le unità esattamente come sono state indicate, e `equals()` confronta le unità una per una.
`normalized()` trasferisce i mesi in eccesso negli anni, ma lascia stare i giorni:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## Contare le unità con `ChronoUnit`

Per ottenere il numero totale di una singola unità tra due punti nel tempo, usa il metodo `between()` su una delle costanti di [`ChronoUnit`][chronounit-docs]:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

Vengono contate solo le unità complete, e il risultato è negativo quando il secondo argomento precede il primo:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit` funziona anche con le unità di tempo e con i valori di data e ora:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### Creare una durata

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

Nella notazione ISO-8601, la `T` separa la parte relativa alla data da quella relativa all'ora.
Una `Duration` non ha una parte di data, quindi il suo `toString()` inizia sempre con `PT`.
`Duration.ofDays()` considera un giorno esattamente come 24 ore.

Anche una durata si può analizzare con `Duration.parse()`:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### Aggiungere una durata a un orario

Una durata si aggiunge o si sottrae a un `LocalTime`, a un `LocalDateTime` o a un `Instant` con `plus()` e `minus()`:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

Come mostra l'ultimo esempio, un `LocalTime` riparte da zero dopo la mezzanotte.

Un `LocalDate` non ha un orario, quindi non si può combinare con una `Duration`:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### La durata tra due orari

`Duration.between()` restituisce la quantità esatta di tempo tra due orari o due valori di data e ora:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()` non accetta due valori `LocalDate`, perché una data non ha secondi da misurare:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

Per le date, usa invece `Period.between()` o `ChronoUnit.DAYS.between()`.

### Convertire una durata

I metodi `toXxx()` convertono una durata in una quantità _totale_ di una singola unità, arrotondata per difetto:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

I metodi `toXxxPart()` scompongono una durata nelle sue parti, come su un orologio:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()` si ferma a 23, perché le ore successive vengono contate da `toDaysPart()`.

### Confrontare e calcolare con le durate

Le durate si possono confrontare con `compareTo()` e controllare con `isZero()` e `isNegative()`:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

Supportano anche operazioni aritmetiche, come `plus()`, `minus()`, `multipliedBy()` e `dividedBy()`:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` o `Duration`?

Per un `LocalDate` o un `LocalTime` la scelta è obbligata: una data non ha un orario da misurare e un orario non ha un calendario.
Un `LocalDateTime` ha entrambi, ma non ha un fuso orario, quindi aggiungervi `Period.ofDays(1)` o `Duration.ofDays(1)` dà lo stesso risultato.
La differenza si vede con i fusi orari.
Quando le lancette vanno avanti per l'ora legale, un giorno di calendario dura solo 23 ore:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

Aggiungere un `Period` di un giorno mantiene l'ora del giorno, mentre aggiungere una `Duration` di un giorno aggiunge esattamente 24 ore.
Usa un `Period` per le quantità che le persone ragionano in termini di calendario («la stessa ora il mese prossimo») e una `Duration` per il tempo trascorso («il biglietto del parcheggio vale 2 ore»).
