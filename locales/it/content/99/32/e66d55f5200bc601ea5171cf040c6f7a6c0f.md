# Introduzione

Prima dell'introduzione della classe `Promise`, c'era un solo modo per gestire il codice asincrono: il _pattern callback_.

Una callback è una funzione che viene passata come argomento a un'altra funzione e verrà chiamata quando un'azione all'interno di quell'altra funzione è terminata. Un pattern comune per queste funzioni callback è che accettano un "error" come primo parametro (vedi l'esempio qui sotto).

```javascript
function callback(error, arg2, arg3) {}
```

Come si collega tutto questo al codice asincrono?

Storicamente, le callback sono state usate per permetterci di svolgere del lavoro dopo che un'attività asincrona era stata completata, senza bloccare l'intero programma.

```javascript
fetchProduct(productId, function (error, data) {
  if (error) {
    // Handle the error
  } else {
    // Do some work
  }
});
```

Nell'esempio qui sopra, la funzione `fetchProduct` (che è asincrona) prende una callback come secondo argomento, che decide cosa fare quando i dati del prodotto sono stati recuperati.
