# Introduzione

## Struct

Le struct sono tipi di dati personalizzati che permettono di dare un nome e raggruppare insieme più valori correlati.

Per definire una struct, usa la parola chiave `struct` seguita da un nome e da parentesi graffe che contengono i campi con i loro nomi e tipi:

```rust
#[derive(Drop)]
struct User {
    active: bool,
    username: ByteArray,
    email: ByteArray,
    sign_in_count: u64,
}
```

Per creare un'istanza di una `struct`, specifica il nome della `struct` e usa le parentesi graffe con coppie chiave-valore per i campi.

```rust
let user = User {
   active: true, username: "someusername123", email: "someone@example.com", sign_in_count: 1
};
```

Usa la notazione con il punto per accedere ai campi di un'istanza di `struct` mutabile o per modificarli.

```rust
let mut user = User {
    active: true, username: "someusername123", email: "someone@example.com", sign_in_count: 1
};
user.email = "anotheremail@example.com";
```

## Ownership

I valori in Cairo sono immutabili, e questa immutabilità garantisce che, anche se molte variabili si riferiscono allo stesso valore, il valore stesso rimane costante e inalterato.
Il _proprietario_ di una variabile è il codice che può leggere (e scrivere, se mutabile) quella variabile.

Regole di ownership in Cairo:

1. Ogni variabile in Cairo ha un proprietario.
2. Ci può essere solo un proprietario alla volta.
3. Quando il proprietario esce dallo scope, la variabile viene distrutta.

Lo scope (_ambito di visibilità_) è l'intervallo all'interno di un programma in cui una variabile è valida.

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Quando una variabile esce dallo scope viene distrutta, il che garantisce che la risorsa associata venga rilasciata correttamente.
Questo si ottiene implementando o derivando il trait `Drop`, che segnala al compilatore che il tipo può essere distrutto in sicurezza una volta che non è più utile.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

Al momento, l'implementazione di `Drop` può essere derivata per tutti i tipi, tranne che per i dizionari (`Felt252Dict`) e i tipi che contengono dizionari.

Un valore può anche essere _spostato_: questo accade quando un valore viene passato a un'altra funzione, distruggendo la variabile originale che faceva riferimento al valore (rendendola così inutile) e creando una nuova variabile che contiene lo stesso valore.

```rust
fn foo(num: u32) { 
    // do something with p
}

fn main() {
    let num: u32 = 10;
    foo(num);
    // ownership of `num` was moved into `foo` and is thus no longer valid in this scope
}
```

Restituire valori equivale a spostarli.

L'esempio qui sotto mostra una funzione che restituisce un valore:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    // main now owns a1
    let a1 = gives_ownership();

    // a2 comes into scope
    let a2 = A {};

    // a2 is moved into takes_and_gives_back, which also moves its return value into a3
    let a3 = takes_and_gives_back(a2);
} // Here, a3 and a1 go out of scope and are dropped. a2 was moved, so nothing happens.

// Moves its return value into the function that calls it
fn gives_ownership() -> A {
    let some_a = A {};
    some_a
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A {
    some_a
}
```

Poiché una variabile viene distrutta dopo essere stata spostata, il compilatore ci impedisce di riutilizzarla in seguito.

```rust
#[derive(Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(p: Point) { 
    // do something with p
}

fn main() {
    let p = Point { x: 5, y: 10 };
    foo(p);
    foo(p); // compiler error: Variable was previously moved.
}
```

In questo caso, proviamo a passare lo stesso valore (la struct `Point` nella variabile `p`) a entrambe le chiamate di funzione.
Una volta passata la variabile alla funzione `foo` la prima volta, la variabile non è più utilizzabile.

Un modo per risolvere è derivare il trait `Copy` sulla nostra struct: in questo modo cambierebbe ciò che accade quando passiamo una variabile `Copy` a una funzione. Il valore non verrebbe più spostato, ma verrebbe creata una nuova variabile che fa riferimento allo stesso valore.
È un'operazione gratuita, perché le variabili sono un'astrazione di Cairo e i valori sono sempre immutabili.

Per implementare il trait `Copy` sul tuo tipo, aggiungi l'annotazione `#[derive(Copy)]` alla definizione del tipo.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(p: Point) { 
    // do something with p
}

fn main() {
    let p = Point { x: 5, y: 10 };
    foo(p);
    foo(p); // this now works
}
```

## Reference e snapshot

Cairo ha due funzionalità per passare un valore senza distruggerlo o spostarlo, chiamate `references` e `snapshots`.

Gli snapshot forniscono una «vista» immutabile di un valore in un certo momento, permettendoti di mantenere la proprietà di una variabile mentre ne accedi allo stato.
Qualsiasi modifica alla variabile crea una nuova cella di memoria, lasciando invariata la vista dello snapshot.

Per creare uno snapshot, è sufficiente anteporre `@` all'istanza della variabile.

```rust
// this function takes in a snapshot using `@` with the data-type
fn get_len(arr: @Array<u128>) -> u32 { // 
    arr.len()
}

fn foo(arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let mut new_arr: Array<u128> = array![1, 2, 3, 4, 5, 6, 7, 8];
    let snapshot = @new_arr; // using `@` to create a snapshot of a variable
    let len = get_len(snapshot); // pass the snapshot as argument, retaining ownership
    foo(new_arr); // `new_arr` is still valid up until here and no further
}
```

Per riconvertire uno snapshot in una variabile normale, puoi usare l'operatore di desnap `*`, che è l'opposto dell'operatore `@`.
Solo i tipi che implementano il trait `Copy` possono subire il desnap.

```rust
fn square(n: @u32) -> u32 {
    let n = *n; // we desnap the value
    n * n
}

fn main() {
    let num: u32 = 10;
    let squared = square(@num); // we use `@` to create a snapshot
    println!("{} squared = {}", num, squared);
}
```

I reference ti permettono di passare valori mutabili alle funzioni facendoli restituire implicitamente, mantenendo la proprietà nel contesto chiamante.
Questo si può ottenere usando il modificatore `ref`, a condizione che la variabile sia dichiarata mutabile con la parola chiave `mut`.

Possiamo aggiornare il precedente esempio `Point` per usare reference mutabili invece di affidarci al trait `Copy` e funzionerebbe comunque.

```rust
#[derive(Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(ref p: Point) { 
    // we can now update the passed values and the changes
    // will be visible in the calling context
    p.x += 1;
}

fn main() {
    let mut p = Point { x: 5, y: 10 };
    foo(ref p);
    foo(ref p); // this now works even without the Copy trait
    println!("p.x = {}", p.x); // p.x = 7 
}
```
