# Istruzioni

Stai lavorando a un sistema per semplificare il processo di accesso alla rete della tua organizzazione. I compiti riguardano la parte di autenticazione. Il sistema usa il riconoscimento facciale per provare l'identità.

In tutti i casi è garantito che il parametro del colore degli occhi non sia nullo.

## 1. Assicurati che i tratti del viso corrispondano

Implementa `Authenticator.AreSameFace()` per verificare che due volti corrispondano.

Aggiungi routine di uguaglianza per la classe `FacialFeatures`.

```csharp
Authenticator.AreSameFace(new FacialFeatures("green", 0.9m), new FacialFeatures("green", 0.9m);
// => true
Authenticator.AreSameFace(new FacialFeatures("blue", 0.9m), new FacialFeatures("green", 0.9m);
// => false
```

## 2. Autentica l'amministratore di sistema

Nonostante le tue proteste, l'amministratore di sistema insiste per avere un'identità integrata durante i test di accettazione, così da poter essere sempre autenticato.

L'email dell'amministratore è admin@exerc.ism. Ha gli occhi verdi e un filtro con una larghezza di 0.9.

Aggiungi routine di uguaglianza per la classe `Identity`.

Implementa il metodo `Authenticator.IsAdmin()` per verificare che l'identità passata corrisponda a quella dell'amministratore.

```csharp
var authenticator = new Authenticator();
authenticator.IsAdmin(new Identity("admin@exerc.ism", new FacialFeatures("green", 0.9m)));
// => true
authenticator.IsAdmin(new Identity("admin@thecompetition.com", new FacialFeatures("green", 0.9m)));
// => false
```

## 3. Registra nuove identità

Implementa il metodo `Authenticator.Register()`, che memorizza un'identità nell'autenticatore stesso, in modo che le chiamate a `IsRegistered()` restituiscano `true` per questa identità; altrimenti `IsRegistered()` restituisce `false`.

Per rilevare tentativi duplicati di registrare un'identità, se l'identità è già stata registrata, `Authenticator.Register()` restituisce `false`, altrimenti `true`.

```csharp
var authenticator = new Authenticator();
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.IsRegistered(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => false
```

## 4. Impedisci che le identità non valide vengano autenticate

Implementa il metodo `Authenticator.IsRegistered()` e assicurati che restituisca false quando non è stata registrata alcuna identità.

```csharp
var authenticator = new Authenticator();
authenticator.IsRegistered(new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.8m)));
// => false
```

## 5. Aggiungi una diagnostica per rilevare tentativi multipli di autenticazione

È stato segnalato un bug: il metodo `Authenticator.IsRegistered()` viene chiamato più volte in rapida successione per la stessa identità. Ritieni che ci sia una specie di problema di «bounce», in cui lo stesso identico record viene inviato più volte. Il tuo compito è aggiungere una routine diagnostica, `Authenticator.AreSameObject()`, a supporto di qualsiasi test venga effettuato. La routine confronta due oggetti e restituisce `true` se sono esattamente la stessa istanza, altrimenti `false`.

```csharp
var identityA = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityB = identityA;
Authenticator.AreSameObject(identityA, identityB);
// => true

var identityC = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityD = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
Authenticator.AreSameObject(identityC, identityD);
// => false
```
