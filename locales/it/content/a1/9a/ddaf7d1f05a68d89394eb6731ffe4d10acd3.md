# Introduzione

Una *deque* (coda a doppia estremità) permette di fare push e pop da entrambe le estremità in O(1). L'implementazione standard di Factor è `<dlist>` (una lista doppiamente collegata) in [`dlists`][dlists]; le operazioni si trovano in [`deques`][deques].

## L'API di deque

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` svuota la deque sul posto: utile per riutilizzarla senza riallocare.

Fare push e pop dalla stessa estremità dà uno stack LIFO. Fare push da un'estremità e pop dall'altra dà una coda FIFO:

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

Per una struttura LIFO useresti un vector (`V{ }`) con `push`/`pop`, che ha meno overhead per operazione. Usa `<dlist>` quando ti serve O(1) a *entrambe* le estremità: quasi sempre per una coda FIFO.

## La ricerca in ampiezza

È l'uso FIFO che rende le deque la frontiera giusta per la *ricerca in ampiezza*. Si parte da un singolo nodo, si fa push dei vicini in fondo, si fa pop dei candidati dalla testa e si eliminano i duplicati con un hash-set:

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

I candidati più vecchi vengono visitati prima di quelli più recenti, quindi la ricerca si espande verso l'esterno a strati partendo dall'inizio. È questo che dà alla ricerca in ampiezza la sua proprietà di cammino minimo: la prima volta che raggiungi un nodo obiettivo ci arrivi tramite un percorso con il minor numero di salti.

## `MEMO:`: memorizzazione automatica

A volte la ricerca per nodo che la ricerca in ampiezza esegue è costosa. Il vocabolario [`memoize`][memoize] di Factor ti dà `MEMO:`, un sostituto diretto di `:` che mette in cache il risultato della funzione in base ai suoi input:

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

Una funzione `MEMO:` esegue il suo corpo la prima volta che vede ogni input e da lì in poi restituisce il risultato in cache: stessa interfaccia, nessuna chiamata in più nel punto di chiamata, solo più veloce quando si ripete.
