# Informazioni

Le eccezioni sono una forma di gestione degli errori.
Si chiamano eccezioni perché di norma compaiono quando si verifica un evento inaspettato.

In qualsiasi punto del nostro codice possiamo «sollevare» un'eccezione.
Lo facciamo usando il metodo `raise`, passando un oggetto, di norma un oggetto Exception, anche se possiamo usare anche delle semplici stringhe.
Per esempio, negli stub degli esercizi vedrai che usiamo la `RuntimeError` predefinita per dire a Ruby che un metodo non è stato implementato.
Puoi anche usare la sintassi abbreviata `raise(ExceptionObject, params)`.
Se si omette la classe dell'eccezione, viene usata `RuntimeError` per impostazione predefinita.

Per esempio:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

Quando Ruby lo incontra, propaga l'errore fino alla cima del programma e poi esce.

Per esempio, se provi a dividere qualcosa per zero, vedrai qualcosa del genere:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

È importante notare che le eccezioni dovrebbero essere usate nei casi in cui accade qualcosa di eccezionale, un errore che richiede una gestione speciale.
Le eccezioni non dovrebbero essere usate per il flusso di controllo di un programma, perché è considerata una cattiva progettazione, che spesso comporta scarse prestazioni e difficoltà di manutenzione.

## Gerarchia delle classi

In Ruby le eccezioni seguono una gerarchia di classi in cui `Exception` è la classe base.
Queste sono le eccezioni predefinite di Ruby più comuni:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

Intercettare gli errori di una classe specifica intercetta anche gli errori delle sue classi figlie.
Ecco perché è pericoloso intercettare da `Exception`.
Ruby usa le eccezioni anche per gestire i messaggi provenienti dal sistema operativo, i «segnali», per esempio `ctrl-c`.
Questo significa che intercettare da `Exception` catturerà anche questi «segnali» di sistema.
Quindi, per evitare comportamenti inaspettati, la pratica comune per catturare «tutti gli errori» è intercettare da `StandardError`.

## Sintassi di rescue

Ruby fornisce anche clausole rescue estese per le situazioni che richiedono un trattamento speciale:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

Questo può essere utile, per esempio, quando lavoriamo con l'I/O di rete, dove bisogna sempre ricordarsi di chiudere una connessione.

I blocchi rescue di Ruby possono anche usare la parola chiave `retry`, che riesegue tutto ciò che sta tra begin e rescue:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
