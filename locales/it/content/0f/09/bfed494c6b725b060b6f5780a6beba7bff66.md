# Introduzione alle pipeline e agli elenchi di comandi

Abbiamo visto come scrivere comandi semplici, dove un comando è seguito da argomenti.
Ora vedremo come creare comandi più complessi componendo comandi semplici.

## Input e Output

Prima di iniziare, una rapida introduzione all'input/output.

I processi hanno "canali di input/output standard".

* Un processo può consumare _input_ su «stdin».
* Un processo può emettere _output_ su «stdout».
* Un processo può emettere _output di errore_ su «stderr».

Il comando `tr` è un esempio molto puro di questo.
Tutto ciò che fa è leggere testo dal suo input, eseguire traslitterazioni di caratteri e stampare il testo risultante sul suo output.

Vedremo di più sulla gestione dei canali «stdio» più avanti nel percorso.

## Pipeline

Questa è una delle «killer feature» della programmazione shell.
Le pipeline ti permettono di creare trasformazioni sofisticate su un flusso di testo.

Per produrre un elenco ordinato di utenti:

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

Il simbolo pipe (`|`) collega l'output di un comando all'input di un altro.
`cut` legge l'output di `cat`, e `sort` legge l'output di `cut`.

~~~~exercism/advanced
* Per impostazione predefinita, ogni comando in una pipeline viene eseguito in una subshell separata.
  (Una subshell è un processo figlio che è una copia della shell attualmente in esecuzione.)

* C'è un costo in termini di prestazioni nell'eseguire pipeline.
  Se ti ritrovi con lunghe pipeline di comandi simili, valuta di combinarli in un unico comando.
  Ad esempio, le pipeline che utilizzano più istanze di `grep`, `cut`, `sed`, `awk` e `tr` possono generalmente essere combinate in un unico comando `awk` per efficienza.

* Lo stato di uscita di una pipeline è lo stato di uscita dell'ultimo comando della pipeline.
  Ciò significa che se un comando precedente fallisce ma l'ultimo comando riesce, lo stato di uscita dell'intera pipeline è zero.

  C'è un'impostazione della shell che può cambiare questo;
  se l'impostazione «pipefail» è abilitata (con `set -o pipefail`), allora lo stato di uscita della pipeline sarà:
  * zero se tutti i comandi riescono, altrimenti
  * l'_**ultimo** stato di uscita non-zero_ dei comandi nella pipeline.
~~~~

## Elenchi di comandi

Un elenco di comandi è una sequenza di pipeline separate da `;` (o newline), `&&` o `||`.

* `A; B` è un elenco di comandi in cui `B` viene eseguito dopo che `A` è completato.
* `A && B`, dove `B` viene eseguito solo se `A` riesce (esce con stato zero).
* `A || B`, dove `B` viene eseguito solo se `A` fallisce (esce con stato non-zero).

Lo stato di uscita di un elenco di comandi è lo stato di uscita dell'ultimo comando eseguito.

Gli operatori `&&` e `||` possono essere concatenati in modo che il comando successivo venga eseguito condizionatamente in base allo stato dei comandi precedenti.
Per esempio

```bash
A && B && C && D || E
```

* B viene eseguito se A riesce,
* C viene eseguito se A e B riescono,
* D viene eseguito se A, B e C riescono,
* E viene eseguito se **uno qualsiasi** di A, B, C o D fallisce.

~~~~exercism/caution
Usa questi operatori logici con parsimonia.
Possono portare rapidamente a codice illeggibile o ad una logica difficile da comprendere.

Per esempio, potresti pensare che questi siano uguali:

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

La differenza è: quando viene eseguito C?

* Nel primo frammento (l'istruzione if), C verrà eseguito solo se A fallisce.
* Nel secondo frammento, C verrà eseguito se A fallisce _o se A riesce ma B fallisce_!
~~~~

### Utilizzi degli elenchi di comandi

Ecco un paio di esempi in cui gli elenchi di comandi possono semplificare il codice.

#### Leggere blocchi di righe da un file

Supponi di avere un file di dati contenente dati su triangoli,
ed un triangolo è rappresentato da tre righe separate che contengono i lati del triangolo.

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

Puoi usare un ciclo while in cui la condizione è costituita da tre comandi read separati:

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

Supponendo che `is_pythagorean` sia un comando che determina se i tre lati soddisfano l'equazione di Pitagora, l'output sarebbe:

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### Asserzioni

Molti linguaggi di programmazione hanno una forma di asserzione in cui viene lanciata un'eccezione se una condizione fallisce

```
assert(user == "Administrator", "wrong user");
```

Possiamo usare un operatore OR in Bash per simulare quella funzione:

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## Considerazioni sullo stile

Gli elenchi di comandi lunghi diventano difficili da leggere abbastanza rapidamente.
Un uso abbondante di a capo può aiutare molto.

Considera questo esempio in cui una parola viene aggiunta ad un array se due condizioni sono soddisfatte.

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

Bash ti permette di aggiungere un a capo dopo una pipe o un operatore logico.

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

Tuttavia, l'operatore può essere facile da non notare alla fine della riga.
Usare una _continuazione di riga_ significa che puoi mettere l'operatore all'inizio, il che rende più evidente che l'elenco sta continuando:

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
Una _continuazione di riga_ è la sequenza di due caratteri «backslash» e «newline» (`\` + `\n`).
Quando Bash vede quella sequenza, viene semplicemente rimossa dal codice, _continuando_ così la riga corrente con la riga successiva.
Fai attenzione a non lasciare spazi tra il backslash e il newline.
~~~~

Ecco un altro esempio

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

o 

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
