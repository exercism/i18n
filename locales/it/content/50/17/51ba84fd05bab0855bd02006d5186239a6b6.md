# Informazioni

Anche se Swift ha molti tipi diversi, ognuno di essi ricade in una delle due classificazioni, _tipi valore_ e _tipi riferimento_. In Swift, [gli struct sono tipi valore][structs-are-value-types] mentre [le classi sono tipi riferimento][classes-are-reference-types].

La differenza principale tra tipi valore e tipi riferimento è che, quando i tipi valore vengono assegnati a una variabile o a una costante, o quando vengono passati a una funzione, ciò che viene assegnato o passato è in realtà una copia del valore, non quel particolare valore. Modificare una copia di uno struct non influenzerà le altre copie. Con i tipi riferimento, invece, viene assegnato o passato un riferimento a quel valore, quindi due nomi diversi possono riferirsi alla stessa istanza di una classe. Questo può portare alla modifica dell'istanza originale quando vi si accede con un nome diverso.

Quindi, dati lo struct e la classe che definiscono un personaggio di un gioco e le relative statistiche, possiamo osservare cosa succede quando questi elementi vengono copiati e modificati.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

Nota come la modifica delle proprietà di `charB` abbia influito su quelle di `charA`, dato che entrambi i nomi si riferiscono alla stessa istanza. Nota anche come, con le statistiche dei due personaggi, i tipi valore all'interno di un tipo riferimento cambino all'interno del tipo riferimento. Questo non è però una violazione del comportamento dei tipi valore, perché `charA.stats` è la stessa istanza di `CharacterStats` di `charB.stats`, dato che `charA` e `charB` si riferiscono alla stessa istanza della classe `GameCharacter`. Come possiamo vedere, per esempio, le copie di quei tipi valore non si influenzeranno a vicenda.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

Ecco perché gli struct richiedono la parola chiave `mutating` davanti ai metodi che alterano lo stato delle proprietà dello struct. Modificare la proprietà di uno struct crea in realtà una nuova copia dello struct, con il nuovo valore impostato per quella proprietà, e la nuova copia sostituisce quella vecchia. È un indicatore visivo del fatto che questa copia e questa sostituzione possono avvenire per i valori di quel tipo.

Questo ha come effetto collaterale che qualsiasi istanza di struct in cui le proprietà variabili cambiano, sia chiamando funzioni mutating sia tramite un'assegnazione diretta, _deve_ essere assegnata a variabili, non a costanti. Altrimenti verrà generato un errore del compilatore:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

I valori iniziali si possono comunque creare e leggere, ma non possono essere modificati. Questa restrizione non si applica alle classi. Se un'istanza di una classe viene assegnata a un nome usando `let`, quello che la costante contiene è il riferimento all'istanza, e quindi è il riferimento a non poter cambiare, non l'istanza stessa. Quindi l'istanza stessa può cambiare, ma il riferimento non può essere modificato per puntare a un'istanza diversa.

Un riepilogo di ciò che può essere modificato con gli struct e le classi definiti con `let` o `var` è il seguente

|         | **struct**                                                                                  | **class**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _Non si può_ assegnare un nuovo struct al nome.</br>_Non si può_ modificare nessuna proprietà dello struct. | _Non si può_ assegnare una nuova classe al nome.</br>_Si può_ modificare le proprietà mutabili della classe. |
| **var** | _Si può_ assegnare un nuovo struct al nome.</br>_Si può_ modificare le proprietà mutabili dello struct.   | _Si può_ assegnare una nuova classe al nome.</br>_Si può_ modificare le proprietà mutabili della classe.    |

## Identità

Poiché due nomi diversi possono contenere un riferimento alla stessa istanza di una classe, a volte è utile verificare se è così. Swift usa l'operatore `===` _identico_ per verificarlo (insieme alla sua negazione, `!==`).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

Poiché nessun nome diverso può riferirsi alla stessa istanza di uno struct, questi operatori di identità non sono definiti per gli struct.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

Nota che l'identità non è la stessa cosa dell'uguaglianza. Secondo molte definizioni, `char1` e `char3` sarebbero considerati uguali perché tutte le loro proprietà contengono gli stessi valori, ma non condividono la stessa identità. L'identità è resa disponibile automaticamente per tutte le classi in Swift, ma gli sviluppatori di solito devono scrivere i propri operatori di uguaglianza per determinare se due istanze di uno struct o di una classe sono _uguali_. Farlo va oltre lo scopo di questo esercizio.
