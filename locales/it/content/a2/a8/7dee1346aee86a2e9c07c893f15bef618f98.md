# Informazioni

## const

Il modificatore [`const`][constants] può essere applicato (e in genere dovrebbe esserlo) a qualsiasi campo il cui valore sia noto in fase di compilazione e non cambi durante la vita del programma.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

Il compilatore ti guiderà su quali espressioni possono essere valutate in fase di compilazione. Sono ammesse le semplici operazioni aritmetiche e la concatenazione di stringhe. Questo esclude qualsiasi valutazione che richiederebbe l'uso dell'heap o dello stack: tutte le chiamate a metodi e i riferimenti a tipi non primitivi non sono disponibili.

Sul web si discute molto dei vantaggi in termini di prestazioni di `const` rispetto alle variabili. Nel caso di un confronto con campi di istanza non `const` potrebbe esserci un risparmio di memoria percepibile, ma rispetto alle variabili statiche è decisamente trascurabile. Qualsiasi considerazione sulle prestazioni della CPU sarà probabilmente vista dai tuoi colleghi come una [ottimizzazione prematura][premature-optimization].

Una ragione più convincente per usare `const` è che migliora la capacità del manutentore di ragionare sul codice. Vedere che un campo è contrassegnato come `const` o `readonly`, o che una proprietà non ha un setter, permette al manutentore di escluderlo in gran parte dalla propria analisi. È improbabile che sia la sede di bug. È improbabile che ponga difficoltà in un esercizio di riorganizzazione. Questo [commento su Stack Overflow][so-consts] affronta la questione.

Il modificatore `const` può anche essere applicato a valori all'interno dei metodi:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

Identificare un valore con `const` in questo modo può essere utile se lo si usa più volte nel metodo o se si vuole richiamare l'attenzione sul suo significato. Non c'è alcun guadagno in termini di prestazioni rispetto all'uso di valori letterali inline.

## readonly

Il modificatore [`readonly`][readonly-fields] può essere applicato (e in genere dovrebbe esserlo) a qualsiasi campo che non possa essere reso `const`, il cui valore non cambi durante la vita del programma e che sia impostato da un inizializzatore inline oppure al momento dell'istanziazione (dal costruttore o da un metodo chiamato dal costruttore).

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

L'uso del modificatore `readonly` è incoraggiato per le stesse ragioni valide per `const`. La pratica di vincolare i campi in questo modo aiuta i manutentori a ragionare sul codice.

Nota che aggiungere il modificatore `readonly` a un campo impedisce solo la modifica del valore del campo. Nel caso di tipi aggregati non protegge i campi o le proprietà di quel tipo. In particolare, non protegge il contenuto degli array.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

Per garantire che tutti i membri di un tipo riferimento siano protetti, si possono rendere i campi `readonly` e definire proprietà automatiche senza una funzione di accesso `set`.

Vale la pena esaminare le [collezioni di sola lettura][readonly-collections] nella libreria di classi di base.

Per gli array, la versione di sola lettura a cui puoi avvicinarti di più è il metodo [`Array.AsReadOnly<T>()`][as-read-only].
