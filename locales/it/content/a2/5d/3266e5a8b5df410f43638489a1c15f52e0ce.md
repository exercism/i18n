# Test

Ogni esercizio contiene un file di test.
Esegui i test con il programma `bats`.
```bash
bats test-hello-world.bats
```

`bats` deve essere installato.
Vedi la pagina [Eseguire i test sul track Bash][bash] per le istruzioni su come installare `bats` sul tuo sistema.

### bats è implementato in bash

Il file bats è uno script bash, con alcune funzioni speciali riconosciute dal comando `bats`.
Vedrai alcuni test che assomigliano a
```sh
gawk -f some-exercise.awk <<< "some,input,here"
```
La sintassi `<<<` è un [Here String][here-string] di bash.
Invia la stringa a destra nello standard input del programma a sinistra.
È ([più o meno][so]) equivalente a
```sh
echo "some,input,here" | gawk -f some-exercise.awk
```

## Aiuto per le funzioni assert

I test usano funzioni della libreria [bats-assert][bats-assert].
Lì puoi trovare aiuto per le varie funzioni `assert*`.

## Test saltati

Risolvere un esercizio significa far passare tutti i suoi test.
Per impostazione predefinita, quando esegui i test viene eseguito un solo test (il primo).
È intenzionale: ti permette di concentrarti solo sul far passare quel singolo test.
Una volta che passa, puoi abilitare il test successivo commentando o rimuovendo le

    [[ $BATS_RUN_SKIPPED == true ]] || skip

annotazioni che precedono gli altri test.

## Sovrascrivere gli skip

Per eseguire tutti i test, compresi quelli con le annotazioni `skip`, esegui:
```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Può essere comodo usare una funzione wrapper per risparmiare sulla digitazione: in `bash` puoi fare così:
```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```
Poi esegui i test con un semplice:
```bash
bats
```

## Output di debug

```exercism/caution
Funziona in locale con `bats`, ma **non** nell'editor online di Exercism.
```

Quando esegue i test, `bats` cattura sia stdout sia stderr per confrontarli con l'output atteso.
Se stampi messaggi di debug su stdout o stderr, verranno inclusi nell'output catturato e potrebbero far fallire il test.

Per stampare informazioni di debug senza influire sui risultati dei test, `bats` mette a disposizione il descrittore di file **3**.
Qualsiasi cosa stampata sul file `/dev/fd/3` verrà mostrata durante l'esecuzione dei test, ma non sarà inclusa nell'output catturato usato per le affermazioni.

Esempio:

```awk
BEGIN {
    # This debug message will not interfere with test output comparison
    print "a debug message" > "/dev/fd/3"

    # Normal program output (this is what your tests will see and compare)
    print "Hello, World!"
}
```

Esempio di esecuzione:

```none
$ bats test-hello-world.bats
test-hello-world.bats
 ✓ Say Hi!
a debug message

1 test, 0 failures
```

Così puoi vedere un utile output di debug senza influire sui test.

Nascondere i dettagli in una funzione può migliorare la leggibilità se la usi in più punti del codice:

```awk
BEGIN {
    debug("starting ...")
}

# do stuff here ...

END {
    debug("... finished")
}

function debug(msg) {print msg > "/dev/fd/3"}
```
