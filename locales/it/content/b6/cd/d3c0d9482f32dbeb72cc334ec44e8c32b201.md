# Installare Factor

Il track di Factor usa **Factor 0.101**. Le versioni precedenti non sono supportate.

Puoi installare una build [stabile](#stable) o [nightly](#nightly), oppure [compilare dai sorgenti](#build-from-source).

Verifica la tua installazione eseguendo `factor -e='vm-version print'`: dovrebbe stampare `0.101` o una versione superiore.

---
### Stabile

<https://factorcode.org#stable-release> fornisce binari stabili nella sezione "Stable release".

---
### Nightly

<https://factorcode.org#development-release> fornisce binari nightly nella sezione "Development release". Questi binari sono compilati da git, ma vengono mostrate solo le build che passano.

---
### Compilare dai sorgenti

Se vuoi il bleeding edge e persino la build nightly è troppo vecchia per te, allora ti serviranno un compilatore C++ moderno (GCC >=4.8 o Clang >=3.5), `make` e `curl`.

Una volta soddisfatti questi semplici requisiti, puoi:

1. Scaricare lo script shell `build`: [**qui** per sistemi Unix-like / shell POSIX](https://raw.githubusercontent.com/factor/factor/master/build.sh) oppure [**qui** per Windows](https://raw.githubusercontent.com/factor/factor/master/build.cmd). Mettilo nella directory sotto cui vuoi installare Factor. Verrà creata una directory chiamata `factor` contenente la base di codice.

2. Eseguirlo con `./build.sh install`, oppure `.\build.cmd install` su Windows. <sub>Questo clonerà il repository `git` di Factor, lo compilerà e scaricherà un'immagine della VM di Factor da <https://factorcode.org>. Il processo può richiedere tra 2 e 20 minuti, a seconda della velocità della tua connessione e della frequenza della CPU.</sub>

3. Ora puoi eseguire il binario `factor` o `factor.exe` generato all'interno della sottodirectory `factor`. Prova `factor --help` per ottenere assistenza. Puoi anche accedere alla documentazione dalla riga di comando, oppure premendo <kbd>F1</kbd> nel Listener della GUI, che aprirà il browser della guida.

4. In futuro, usa `build.sh` (o `build.cmd` su Windows) all'interno della sottodirectory `factor` per scaricare le novità da git e ricompilare sul posto, scaricando una nuova immagine della VM se necessario.

La struttura dei file potrebbe ora apparire così:

```
.
├── build.sh                   <- delete if you like
└── factor
    ├── basis
    ├── boot.unix-x86.64.image
    ├── build.cmd              <- use these from now on
    ├── build.sh               <-
    ├── core
    ├── extra
    ├── factor
    ├── Factor.app
    ├── factor.image
    ├── GNUmakefile
    ├── libfactor.a
    ├── libfactor-ffi-test.so
    ├── LICENSE.txt
    ├── misc
    ├── Nmakefile
    ├── README.md
    ├── unmaintained
    ├── vm
    └── work
```

Non ti serve più lo script `build` di primo livello: in futuro dovresti usare quello scaricato.

---

### Compilare manualmente dai sorgenti (sconsigliato)

Clona il [repository](https://github.com/factor/factor) e usa `make` in quella cartella.

Se `make` fallisce con un errore relativo a un target non presente, prova `make factor` oppure, se sai leggere un Makefile, cerca il target make per la tua piattaforma in `GNUmakefile`.

Se anche *questo* fallisce, apri una issue su [factor/factor](https://github.com/factor/factor) includendo l'errore: gli sviluppatori, sempre disponibili, saranno felici di aiutarti.
