# Introduzione

In Julia si usano tre tipi principali di istruzioni condizionali:

- espressioni `if`
- l'operatore ternario
- la valutazione a corto circuito

## Espressioni `if`

Le espressioni `if` in Julia sono simili a quelle che si trovano in altri linguaggi:

```julia-repl
julia> function say_if_positive(n)
           if n > 0
               println("n is positive!")
           else
               println("n is not positive!")
           end
       end
say_if_positive (generic function with 1 method)

julia> say_if_positive(10)
n is positive!

julia> say_if_positive(-10)
n is not positive!
```

Se l'espressione booleana che segue l'`if` si valuta come `true`, viene eseguito il primo blocco di codice e il secondo viene saltato.
Se l'espressione booleana che segue l'`if` si valuta come `false`, il primo blocco di codice viene saltato e il secondo viene eseguito.
Il programma continua l'esecuzione dalla prima riga di codice dopo la parola chiave `end`.

~~~~exercism/note
In Julia, la parola chiave `end` indica la fine di tutte le espressioni a blocco.
Questa sintassi non è specifica delle espressioni `if` o delle definizioni di funzione.
~~~~

Nei casi in cui il secondo blocco di codice sarebbe solo un'altra espressione `if`, `elseif` ci permette di evitare di annidare espressioni `if` all'interno del blocco:

```julia-repl
julia> function dessert(fruit)
           if fruit == "apple"
               return "Apple Crumble"
           elseif fruit == "lemon"
               return "Lemon Meringue Pie"
           else
               return "Fruit Salad"
           end
       end
dessert (generic function with 1 method)

julia> dessert("apple")
"Apple Crumble"

julia> dessert("lemon")
"Lemon Meringue Pie"

julia> dessert("peach")
"Fruit Salad"
```

Se un'espressione `if` deve eseguire codice solo per uno dei casi, non serve scrivere il ramo `else`.

## Operatore ternario

Le semplici istruzioni `if-else` si possono scrivere anche usando l'operatore ternario `a ? b : c`.
Se `a` è vero, viene valutato `b`.
Altrimenti si valuta `c`.

Per esempio, la seguente funzione

```julia-repl
julia> function diagnose(heartrate)
           if heartrate > 100
               println("Elevated heart rate.")
           else
               println("Nominal heart rate or dead.")
           end
       end
diagnose (generic function with 1 method)
```

si può scrivere anche come

```julia-repl
julia> diagnose(heartrate) = heartrate > 100 ? println("Elevated heart rate.") : println("Nominal heart rate or dead.")
diagnose (generic function with 1 method)
```

Questo è particolarmente utile se vuoi assegnare a una variabile un valore diverso a seconda di una condizione.
`x = a ? b : c` assegna `b` a `x` se `a` è `true`, altrimenti assegna `c` a `x`.
Per esempio:

```julia-repl
julia> function patient_status(heartrate)
           status = heartrate > 0 ? "alive" : "dead"

           println("The patient is ", status)
       end

julia> patient_status(100)
The patient is alive

julia> patient_status(0)
The patient is dead
```

## Valutazione a corto circuito

Se più espressioni booleane sono concatenate con gli operatori `&&` e `||`, Julia valuta solo il minor numero di espressioni necessarie per determinare il valore dell'intera catena.

Per esempio, considera la catena di espressioni `n > 0 && k > 10`.
Se `n` è uguale a `5`, la prima parte della catena, `n > 0`, è `true`, ed è necessario valutare la seconda espressione `k > 10` per determinare se l'intera espressione è `true`.
Se invece `n` è uguale a `-5`, sappiamo che la catena nel suo complesso **non può** essere `true`, perché la sua prima espressione è `false`.

Se invece consideriamo `n > 0 || k > 10`, succede il contrario.
Se `n` è uguale a `5`, la prima parte della catena, `n > 0`, è `true` e sappiamo che l'intera catena sarà `true` indipendentemente dalla seconda espressione.
Se invece `n` è uguale a `-5`, è necessario valutare la seconda espressione.

Questo comportamento permette di scrivere istruzioni `if` molto brevi:

```julia
if a
    b
end
```

equivale a

```julia
a && b
```

L'ultima espressione di una catena di `&&` e `||` non deve necessariamente essere un'espressione booleana.
Capita spesso di vedere questa funzionalità usata per lanciare errori o restituire valori in anticipo.
Per esempio, usando la funzione `dessert(fruit)` di sopra:

```julia-repl
julia> function whats_for_dessert(fruit, allergic_to)
           fruit == allergic_to && return "I can't eat that, guess I'll not have dessert tonight!"

           return dessert(fruit)
       end
whats_for_dinner (generic function with 1 method)

julia> whats_for_dinner("apple", "peach")
"Apple Crumble"

julia> whats_for_dinner("apple", "apple")
"I can't eat that, guess I'll not have dessert tonight!"
```
