# Le funzioni in `jq`

In `jq` puoi definire le tue **funzioni personalizzate** per racchiudere la logica di cui hai bisogno.
Le _funzioni_ si comportano proprio come le funzioni integrate: prendono un input ed emettono zero, uno o più output.

## Definire una funzione

Puoi definire una _funzione_ di `jq` usando la seguente sintassi:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- inizia con la parola chiave `def`,
- due punti prima del corpo della funzione,
- il corpo è composto da una sola espressione,
- termina con un punto e virgola,
- come per il resto della sintassi di `jq`, puoi usare spazi bianchi arbitrari per la leggibilità.

## Dove collocare le funzioni

Le _funzioni_ devono essere definite prima di essere usate: questo è un errore:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Questo implica che devi collocare le _funzioni_ all'inizio del tuo codice `jq`, prima dell'espressione «main».

### Funzioni annidate

Le _funzioni_ possono essere annidate:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Qui la _funzione_ `B` è visibile solo nel corpo di `A`.

## Scope

Una _funzione_ introduce un nuovo **scope** per le variabili e le funzioni annidate.

## Argomenti

Gli **argomenti** di una _funzione_ sono separati da _punti e virgola_, non da virgole.
Per esempio, una _funzione_ che prende un numero, poi aggiunge un numero e moltiplica per un numero:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
I punti e virgola sono necessari perché la virgola ha già uno scopo in `jq`: è un operatore che unisce gli stream.

Usare una virgola invece di un punto e virgola tenta di effettuare due chiamate a una funzione `add_mul` _a 1 argomento_, che non esiste, e quindi fallirà alla prima chiamata:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

La virgola in `5, 4` concatena i numeri 5 e 4 in uno stream. 
Quando chiamiamo una funzione con uno stream come argomento, `jq` chiamerà quella funzione più volte, una per ogni valore dello stream. 
Questo è un esempio dell'«iterazione implicita» insita negli stream di `jq`.
`10 | add_mul(5, 4)` equivale a quanto segue.

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
Ora possiamo vedere come salta fuori l'errore `add_mul/1 is not defined`.
~~~~

<!-- prettier-ignore-end -->

### Gli argomenti sono _espressioni_

Gli _argomenti_ di una funzione sono filtri, non valori.
In questo senso si comportano come quello che altri linguaggi chiamano callback:

Prendiamo come esempio la funzione `add_mul`:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

Cosa succede qui?

- l'argomento `adder` riceve l'_espressione_ `. + 5`
  - quando la funzione esegue `. + adder`, questa diventa `. + . + 5`
  - che restituisce 25 dato che `. == 10`
- allo stesso modo, l'argomento `multiplier` è l'espressione `. - 2`
  - che restituisce 8
  - quindi il risultato è `25 * 8 == 200`

### Argomenti come valori

A volte vorrai «materializzare» un _argomento_ in una variabile:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Esiste una forma abbreviata per farlo:

```jq
def my_func($arg):
    other stuff ...
;
```

Tieni presente che questo è solo «zucchero sintattico»: il nome `arg` senza `$` è comunque nello scope della _funzione_.

<!-- prettier-ignore -->
~~~~exercism/caution
Per esempio, ho scritto qualcosa del genere per risolvere un esercizio:

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

e sono rimasto sorpreso che ogni valore dell'array fosse uguale alla chiave.

Questo è successo perché jq vedeva la funzione `equals` come

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

L'**argomento** `code` _sovrascriveva_ la **funzione** `code` definita in precedenza.
Ciò significava che `(. | code)` restituiva semplicemente l'**argomento** invece di calcolare un nuovo codice basato sul valore di input.
Così `$this_code` e `$code` erano sempre uguali.
~~~~

## Arità

Le _funzioni_ hanno un'**arità**, cioè il numero di _argomenti_ che accettano.

Le _funzioni_ possono usare lo stesso nome con _arità_ diverse.
La funzione integrata [`range`][man-range] lo dimostra: `range/1`, `range/2` e `range/3` coesistono.

Questo può essere utile per definire funzioni ricorsive che trasportano uno stato tramite gli argomenti.
Per esempio `map` _potrebbe_ essere implementata così:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Ricorsione

`jq` esegue l'ottimizzazione delle chiamate in coda, ma solo per le funzioni a 0 argomenti.

## Moduli

Un modulo `jq` è un file che contiene solo funzioni.
I moduli si includono in un programma jq con i comandi [`include`][man-include] o [`import`][man-import].
