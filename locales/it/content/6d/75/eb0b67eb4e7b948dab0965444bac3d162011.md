# Introduzione

Quando facciamo pattern matching su un valore in Gleam, dobbiamo assicurarci che i pattern corrispondano a ogni possibile valore del tipo, altrimenti il codice non verrà compilato.

Questa funzione dovrebbe essere rifiutata perché non gestisce il caso in cui la lista è vuota:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Il più delle volte, nei programmi Gleam, vogliamo gestire ogni caso possibile, ma in alcuni programmi, come prototipi e script rapidi, potremmo volerci concentrare solo sul percorso ideale e non scrivere codice per gli altri casi. È qui che entra in gioco `let assert` di Gleam.

Con le asserzioni let, un pattern può corrispondere solo ad alcuni dei possibili valori di un tipo, e se il pattern non corrisponde a un valore il programma andrà in crash. Usando `let assert`, possiamo scrivere la funzione precedente in questo modo:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Le librerie Gleam non dovrebbero mai usare le asserzioni let, perché possono mandare in crash il programma. Dovrebbero invece usare il tipo `Result` e lasciare che lo sviluppatore dell'applicazione decida come gestire gli errori.
