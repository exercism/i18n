# Introduzione

Il [pattern matching][pattern-matching] permette di scrivere codice con diramazioni espressivo e la [destrutturazione][destructuring] consente di associare i valori alle variabili in modo elegante.
Entrambi sono estremamente utili da padroneggiare per chi programma in Elm e, usati insieme, migliorano molto la leggibilità del codice.

## Pattern matching semplice

Il pattern matching indica codice che si dirama in base alla forma dei dati manipolati.
Si sposa quindi naturalmente con il concetto di tipi personalizzati, che esprimono le molteplici forme che un dato può assumere.
Prendiamo per esempio un tipo personalizzato `Color` definito come `Blue` o `Red`: possiamo scrivere una funzione `toString` che fa pattern matching sul colore per restituire la stringa corretta.

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

Il pattern matching funziona anche con i tipi personalizzati che non sono semplici enumerazioni.
Consideriamo una funzione `hello` che prende come parametro un `Maybe String`, contenente il nome di una persona oppure nulla.
Quando facciamo pattern matching, possiamo dare ai dati nomi in minuscolo per associarli a quella variabile e poterli usare nella parte destra del match.

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

Il pattern matching deve essere esaustivo, altrimenti il compilatore rifiuterà di compilare.
Ma a volte non ci interessano alcuni dati o alcuni rami di un'espressione case.
In questi casi, invece di dover trovare un nome di variabile a cui associarli e di dover avere un ramo per ogni caso, possiamo usare il carattere jolly underscore `_`.

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## Pattern matching avanzato

Oltre ai tipi personalizzati, possiamo fare pattern matching anche su tipi che hanno valori letterali, come `Char`, `String`, `Int` e `Floats`.

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

Per fare il match su più valori senza annidamento, un trucco comune in Elm è combinare i valori da confrontare in [_tuple ad hoc_][ad-hoc-tuples] in questo modo:

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

E dato che le liste sono care ai programmatori funzionali, [si può fare pattern matching anche su di esse][pattern-match-lists], con la stessa sintassi che si usa per costruirle, tramite l'operatore `::`.

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

Infine, il pattern matching funziona persino in modo ricorsivo, permettendo di addentrarsi in tipi complessi e ricorsivi.

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## Destrutturazione

La destrutturazione è molto simile al pattern matching, nel senso che permette di associare variabili ai dati contenuti nei tipi.
La differenza principale è che chiamiamo questo meccanismo «destrutturazione» quando c'è una sola forma possibile, e pattern matching quando le forme sono più di una.
La destrutturazione si trova spesso nelle associazioni `let`, negli argomenti delle funzioni e, naturalmente, nelle espressioni case, mescolata al pattern matching.

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

La destrutturazione si può usare con i tipi personalizzati ad una sola variante, con le tuple e anche con i record, dove è molto comoda.
Per [destrutturare un record][records-pattern-matching], si può usare un numero qualsiasi dei suoi campi: uno, due, ... o tutti.

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

Purtroppo la sintassi di Elm non permette la destrutturazione ricorsiva dei record.
Nell'esempio precedente di `Circle`, non c'è modo di accedere alle posizioni `x`` and `y`center`center`x`x`y`y`.

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

E abbiamo un ultimo consiglio!
A volte vogliamo accedere facilmente sia a una cosa nel suo insieme sia ad una sua parte.
È qui che la [parola chiave `as`][as-keyword] può tornare utile.
Permette di dare un nome alias a una cosa nel suo insieme, potendone comunque destrutturare il contenuto.

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
