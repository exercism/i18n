# Introduzione

TypeScript è JavaScript con la sintassi per i tipi: questo lo rende un linguaggio di programmazione fortemente tipizzato, che supporta gli stili orientato agli oggetti, imperativo e dichiarativo (per esempio la programmazione funzionale), offrendoti strumenti migliori a qualsiasi scala.

Poiché [non puoi imparare TypeScript senza imparare JavaScript][handbook-js-or-ts], parte dei contenuti di questo percorso è incentrata sull'insegnamento dei concetti di JavaScript, mentre altri concetti riguardano solo le funzionalità specifiche di TypeScript.

## (Ri)assegnazione

In TypeScript ci sono alcuni modi principali per assegnare valori ai nomi: usare variabili o costanti.
Su Exercism, le variabili si scrivono sempre in [camelCase][wiki-camel-case]; le costanti si scrivono in [SCREAMING_SNAKE_CASE][wiki-snake-case].
Non esiste una guida ufficiale da seguire, e aziende e organizzazioni diverse hanno guide di stile diverse.
_Sentiti libero di scrivere le variabili come preferisci_.
Il vantaggio di scriverle nel modo in cui sono preparati gli esercizi è che verranno evidenziate in modo diverso nell'interfaccia web e nella maggior parte degli IDE.

Le variabili in TypeScript si possono definire con la parola chiave [`const`][mdn-const], [`let`][mdn-let] o [`var`][mdn-var].

Quando si usa `let` o `var`, una variabile può riferirsi a valori diversi nel corso della sua esistenza.
Per esempio, `myFirstVariable` può essere definita e ridefinita molte volte usando l'operatore di assegnazione `=`:

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

A differenza di `let` e `var`, le variabili definite con `const` possono essere assegnate una sola volta.
Questo è il modo in cui si definiscono le costanti in TypeScript.

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

Poiché TypeScript è in grado di rilevarlo staticamente, anche il compilatore TypeScript restituirà un errore:

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

Questo significa che non devi eseguire il codice per rilevare il `TypeError`.

## Inferenza dei tipi

Senza addentrarci troppo nel tema dell'[inferenza dei tipi][handbook-type-inference], devi sapere che una variabile a cui viene assegnato un valore di solito ha un tipo inferito, anche senza un'annotazione di tipo.

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

Questo tipo viene poi imposto in tutto il codice.
Questo significa anche che, laddove il codice seguente è JavaScript valido:

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

In TypeScript, invece, dà errore:

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

Questa funzionalità garantisce la sicurezza dei tipi anche quando non si usano le annotazioni di tipo.

## Dichiarazioni di funzione

In TypeScript, le unità di funzionalità sono incapsulate in _funzioni_; di solito le funzioni che vanno insieme vengono raggruppate nello stesso file.
Queste funzioni possono accettare parametri (argomenti) e possono _restituire_ un valore usando la parola chiave `return`.
Le funzioni si chiamano usando la sintassi `()`.

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

Di solito conviene annotare i parametri di una funzione con un tipo, usando i due punti (`:`) seguiti dal tipo.
Il valore restituito da una funzione si può annotare dopo la chiusura dell'elenco dei parametri, usando i due punti (`:`) seguiti dal tipo.

<!--prettier-ignore -->
~~~~exercism/note
💡 In TypeScript ci sono _molti_ modi diversi per dichiarare una funzione.
Questi altri modi sono diversi dall'uso della parola chiave `function`.
Il percorso cerca di introdurli gradualmente, ma se li conosci già, sentiti libero di usare quello che preferisci.
Nella maggior parte dei casi, usare l'uno o l'altro non è né meglio né peggio.
~~~~

## Annotazioni di tipo

Come mostrato nella dichiarazione della funzione `add`, i parametri hanno un'annotazione di tipo esplicita `: number`.
Le dichiarazioni di variabili, le proprietà delle classi, le dichiarazioni di funzioni e altro ancora supportano tutte le annotazioni di tipo.

Sia le annotazioni di tipo esplicite sia i tipi inferiti vengono imposti dal controllo dei tipi.

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## Esportare verso altri file

Per rendere una `function`, una costante o una variabile disponibile in _altri file_, bisogna [esportarle][mdn-export] usando la parola chiave `export`.
Un altro file può quindi [importarle][mdn-import] usando la parola chiave `import`.
Questo è anche noto come sistema di moduli.
Un ottimo esempio è come funzionano tutti i test.
Ogni esercizio ha almeno un file, per esempio `lasagna.ts`, che contiene l'_implementazione_.
Inoltre, c'è almeno un altro file, per esempio `lasagna.test.ts`, che contiene i _test_.
Questo file _importa_ le entità pubbliche (cioè esportate) per mettere alla prova l'implementazione:

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
