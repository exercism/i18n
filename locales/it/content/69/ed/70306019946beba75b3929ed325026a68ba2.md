# Istruzioni

Stai scrivendo il codice per il sistema dati di un reparto produttivo di componenti automobilistici.
Componenti di motori e telai passano attraverso una serie di stazioni di lavorazione.
Ogni stazione produce misurazioni che devono essere combinate, confrontate, calibrate o normalizzate prima che parta la fase successiva.
Le funzioni che implementerai qui sono una per ogni stazione.

~~~~exercism/note
I calcoli in questo esercizio dovrebbero essere eseguiti usando istruzioni SIMD, non operazioni scalari.
~~~~

## 1. Combina le rese di due linee

Il reparto produttivo gestisce due linee di assemblaggio parallele.
Alla fine di ogni turno, entrambe le linee riportano le proprie rese per 4 contenitori di componenti come numeri a precisione singola.
Il pannello di controllo del supervisore mostra la resa combinata per contenitore, quindi i due rapporti vengono sommati contenitore per contenitore.
Tutti e tre i buffer sono gestiti dal sistema di rendicontazione e sono sempre allineati a 16 byte.

Definisci una funzione `sum_yields` che, date le rese per contenitore di `line_a` e `line_b`, scrive in `result` la somma contenitore per contenitore.
Gli argomenti, nell'ordine, sono:

1. `line_a`: indirizzo di memoria allineato a 16 byte che contiene 4 numeri in virgola mobile a 32 bit
2. `line_b`: indirizzo di memoria allineato a 16 byte che contiene 4 numeri in virgola mobile a 32 bit
3. `result`: indirizzo di memoria allineato a 16 byte in cui la funzione scriverà 4 numeri in virgola mobile a 32 bit

Questa funzione non ha valore restituito: il risultato viene invece memorizzato nel buffer passato (`result`):

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. Calcola lo scostamento scalato

Tra un'operazione e l'altra, una stazione di campionamento misura i componenti lavorati e li confronta con le dimensioni target.
I valori misurati arrivano da un calibro di precisione in un buffer che è sempre allineato a 16 byte.
I valori target provengono dal fascicolo dell'ordine di lavoro, che non ha garanzie di allineamento.
Lo scostamento viene moltiplicato per un fattore di sensibilità per asse prima di essere passato al controllo di tolleranza a valle.
In questa fase, il controllo a valle legge lo scostamento direttamente da un registro SIMD anziché dalla memoria.

Definisci una funzione `scaled_deviation` che, dati `measured`, `target` e una `sensitivity`, scrive lo scostamento scalato in `result`.
Gli argomenti, nell'ordine, sono:

1. `measured`: indirizzo di memoria allineato a 16 byte che contiene 2 numeri in virgola mobile a 64 bit
2. `target`: indirizzo di memoria che contiene 2 numeri in virgola mobile a 64 bit (allineamento non garantito)
3. `sensitivity`: indirizzo di memoria che contiene 2 numeri in virgola mobile a 64 bit (allineamento non garantito)
4. `result`: indirizzo di memoria di un buffer in cui la funzione scriverà 2 numeri in virgola mobile a 64 bit (allineamento non garantito)

Lo scostamento scalato è `(measured - target) * sensitivity`, lane per lane.

Questa funzione non ha valore restituito: il risultato viene invece memorizzato nel buffer passato (`result`) come coppia di numeri in virgola mobile a 64 bit.

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. Calibra un lotto

Prima che i componenti entrino nella baia di ispezione finale, le letture dimensionali di un lotto di 4 componenti vengono riscalate in doppia precisione e corrette per la deriva di temperatura nota.

Le 4 letture grezze arrivano come numeri a precisione singola.
Per ogni riga di 2 letture, la calibrazione calcola `reference / (raw - offset)` e poi moltiplica questo risultato per un fattore di conversione costante di `0.5`.

Nota che il riferimento e l'offset sono gli stessi per entrambe le righe del lotto.
Il fattore di conversione è lo stesso in ogni calibrazione, quindi invece di riceverlo come argomento dovresti dichiararlo come costante impacchettata di 16 byte in memoria.

Definisci una funzione `calibrate_batch` che, dati un lotto `raw`, un `reference`, un `offset` e un buffer `result`, scrive i valori calibrati in `result`.
Gli argomenti, nell'ordine, sono:

1. `raw`: indirizzo di memoria che contiene 4 numeri in virgola mobile a 32 bit (allineamento non garantito)
2. `reference`: indirizzo di memoria allineato a 16 byte che contiene 2 numeri in virgola mobile a 64 bit
3. `offset`: indirizzo di memoria allineato a 16 byte che contiene 2 numeri in virgola mobile a 64 bit
4. `result`: indirizzo di memoria allineato a 16 byte in cui la funzione scriverà 4 numeri in virgola mobile a 64 bit (32 byte in totale)

La funzione deve, per ciascuna delle due righe del lotto:

1. Convertire i 2 valori grezzi a precisione singola della riga in doppia precisione.
2. Sottrarre `offset` dalla coppia convertita.
3. Dividere `reference` per il risultato.
4. Moltiplicare lane per lane ogni numero in virgola mobile a 64 bit per il fattore di conversione fisso di `0.5`.
5. Memorizzare i 2 numeri in virgola mobile a 64 bit nei corrispondenti 16 byte di `result`.

Questa funzione non ha valore restituito: il risultato viene invece memorizzato nel buffer passato (`result`):

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. Normalizza i punteggi lungo una linea

Alla fine della linea, ogni componente ha un punteggio di qualità che deve essere normalizzato prima di essere riportato.
Ogni punteggio viene moltiplicato per il proprio guadagno per componente, poi diviso per una scala di produzione per asse.
Il buffer dei guadagni contiene un guadagno per componente.

La scala di produzione è la stessa per l'intera esecuzione e viene passata in un indirizzo di memoria che contiene due numeri in virgola mobile a 64 bit.
I punteggi vengono aggiornati **in place**: lo stesso buffer che conteneva i punteggi grezzi ora contiene i punteggi normalizzati.

Definisci una funzione `normalize_scores` che, dati un array `scores`, un array `gains`, una `scale` e un conteggio `n`, normalizza i punteggi in place.
Gli argomenti, nell'ordine, sono:

1. `scores`: indirizzo di memoria allineato a 16 byte che contiene `n` numeri in virgola mobile a 64 bit (modificati in place)
2. `gains`: indirizzo di memoria allineato a 16 byte che contiene `n` numeri in virgola mobile a 64 bit
3. `scale`: indirizzo di memoria allineato a 16 byte che contiene 2 numeri in virgola mobile a 64 bit
4. `n`: un numero intero positivo pari a 64 bit (minimo `2`), il numero di punteggi da normalizzare

Le due lane della scala si applicano ai due elementi di ciascuna coppia.
La prima lane scala il primo elemento di ogni coppia (lane in posizioni pari), la seconda scala il secondo (lane in posizioni dispari).
Ogni punteggio viene moltiplicato per il guadagno corrispondente, poi diviso per la lane della scala appropriata: `score * gain / scale_lane`.

Questa funzione non ha valore restituito: il risultato viene invece memorizzato nel buffer di input (`scores`), nella stessa posizione del `score` corrispondente che è stato normalizzato:

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
