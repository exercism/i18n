# Installazione

## Premessa

Sebbene Regina Rexx sia stato portato su moltissime piattaforme, le istruzioni di installazione si concentreranno sulle piattaforme desktop a 64 bit con Windows, Linux o MacOS.

## Passaggi di installazione

Tieni presente che questo track richiede l'installazione della versione più recente di [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) (la 3.9.5, al momento in cui scriviamo). Il collegamento ipertestuale fornito ti porta direttamente alla sezione Files, da cui scegliere il file da scaricare.

### Windows

Un'installazione per eseguire Regina in modo nativo sotto Windows (tramite una finestra CMD o Powershell) si effettua facilmente dal browser con il pulsante [`Download Latest Version`](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/Regina395w64.exe/download). Basta fare clic, scaricare e installare.

Se disponi di ambienti di emulazione Linux, o vuoi usarne uno, come:

* [Git for Windows](https://gitforwindows.org/)
* [Cygwin](https://cygwin.com/)
* [MinGW](http://mingw.org/)

i binari di Regina nativi per Windows dovrebbero essere accessibili, quindi puoi semplicemente eseguirli in questi ambienti e, per la maggior parte degli scopi, va benissimo.

Un'avvertenza, però: l'istruzione ADDRESS non funziona correttamente (perché si interfaccia con il sistema operativo ospite). Per ottenere i risultati migliori in questi ambienti, procurati il pacchetto specifico per l'ambiente e installalo. Il sito di Regina, per esempio, ospita una build [specifica per Cygwin](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-pc-cygwin.tgz/download) che si può installare.

In alternativa, se disponi di una distribuzione Linux _vera_ sotto Windows, o vuoi usarne una, come [WSL](https://docs.microsoft.com/en-us/windows/wsl/about) o [Virtual Box](https://www.virtualbox.org/), segui semplicemente le istruzioni della sezione Linux per la distribuzione che ti interessa.

### Linux

Le installazioni su Linux sono in genere piuttosto semplici quando si usa il gestore di pacchetti del sistema. Diventa però problematico quando i pacchetti disponibili _non_ sono i più recenti. Purtroppo è il caso di Regina.

Un'installazione basata sui pacchetti è comunque possibile procurandosi manualmente il pacchetto più recente. Il sito di [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) ospita pacchetti per le distribuzioni della famiglia Debian (che include Ubuntu) e della famiglia RHEL (che include Fedora, CentOS, Rocky e Alma), tra le altre.

Per la distribuzione scelta, dovrai scaricare due pacchetti: un pacchetto di libreria e un pacchetto di binari. Per esempio, per installare su Debian o Ubuntu, procedi così:

```plain
sudo apt update && sudo apt -y install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx_3.9.5-2_amd64-Debian-11.deb > regina-rexx_3.9.5-2_amd64-Debian-11.deb
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3_3.9.5-2_amd64-Debian-11.deb > libregina3_3.9.5-2_amd64-Debian-11.deb
sudo apt -y install libregina3_3.9.5-2_amd64-Debian-11.deb regina-rexx_3.9.5-2_amd64-Debian-11.deb
```

E su CentOS e RHEL 7, prova:
```plain
sudo yum update && sudo yum install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
sudo yum localinstall libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
```

E su Fedora, Rocky e Alma, prova:
```plain
sudo dnf update && sudo dnf install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
sudo dnf localinstall libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
```

Dove un'installazione basata sui pacchetti non è possibile, o si è comunque rivelata problematica, è sempre possibile compilare dai sorgenti, con l'archivio ottenibile da:

```plain
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5.tar.gz > regina-rexx-3.9.5.tar.gz
```

Dando per scontato che gli strumenti di compilazione standard (gcc, make) siano installati (in caso contrario, segui le istruzioni qui: [Install Development Tools](https://ostechnix.com/install-development-tools-linux/)), esegui i seguenti passaggi:

```plain
tar -xzvf regina-rexx-3.9.5.tar.gz && cd regina-rexx-3.9.5
./configure
sudo make
sudo make install
```

Vengono installate la libreria (`libregina.so`) e due serie di binari, `rexx` e `regina`; il percorso predefinito è `/usr/local/bin`.

Il binario `rexx` è linkato staticamente, quindi è autonomo e pronto all'uso.

Il binario `regina` è linkato dinamicamente, quindi richiede un po' di configurazione per riuscire a trovare la libreria condivisa `libregina.so` in fase di esecuzione. Per farlo, segui questi passaggi:

```plain
# Configure shared library location
sudo su
echo /usr/local/lib64/ > /etc/ld.so.conf.d/regina-rexx-3.9.5-x86_64.conf
echo /usr/local/lib64/regina-rexx/addons > /etc/ld.so.conf.d/regina-rexx-addons-x86_64.conf
cd /usr/local/lib64
rm -f libregina.so libregina.so.3
ln -s libregina.so.3.9 libregina.so
ln -s libregina.so.3.9 libregina.so.3
ldconfig
exit

# Check symbolic link creation
ls -l /usr/local/lib64/

# Output should be similar. Note symbolic links.
-rw-r--r--. 1 root root 3887554 Dec  1 18:22 libregina.a
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so -> libregina.so.3.9
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so.3 -> libregina.so.3.9
-rwxr-xr-x. 1 root root  574104 Dec  1 18:22 libregina.so.3.9
drwxr-xr-x. 2 root root      26 Dec  1 18:22 pkgconfig
drwxr-xr-x. 4 root root      33 Dec  1 18:22 regina-rexx

# Check library path, and executable using that path
ldconfig -p | grep regina
ldd /usr/local/bin/regina

# Alternate for local user
export LD_LIBRARY_PATH=${LD_LIBRARY_PATH}:/usr/local/lib64:/usr/local/lib64/regina-rexx/addons
```

Tieni presente che compilare dai sorgenti, con la relativa configurazione di sistema, è un compito che è meglio lasciare agli utenti esperti.

### MacOS

L'installazione si articola in tre passaggi:

* Installa il gestore di pacchetti [Homebrew](https://brew.sh)
* Individua e avvia l'applicazione `Terminal`
* Dalla riga di comando di `Terminal`, digita quanto segue:

   `brew install regina-rexx`

Questo _dovrebbe_ installare la versione più recente.

Se non lo fa, puoi scaricare il pacchetto [Regina for MacOS](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-apple-darwin21.6.0.tgz/download) e installarlo manualmente.

## Dopo l'installazione

### Verifica dell'installazione

Dopo aver completato l'installazione, puoi verificare se [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) è stata installata correttamente eseguendo questo comando in un terminale:

```plain
rexx --version=v
```

Sia su Windows che su Linux, apparirà il seguente output nel terminale:

```plain
3.9.5
```

che è il numero di versione dell'interprete.

Viene installato anche un secondo binario, `regina`. È identico a `rexx` sotto ogni aspetto, tranne per il fatto che si collega a una libreria condivisa, ed è l'interprete da usare se vuoi accedere a funzioni di utilità esterne. Vedi la sezione [Accesso a routine esterne](###accessing-external-routines).

Per iniziare a usare il track non serve installare altri componenti software (dando per scontato che la CLI di Exercism sia già installata).

Le note d'uso che seguono ti daranno le basi per usare l'interprete dalla riga di comando.

### Utilizzo

Uno script Rexx ha di solito l'estensione _`.rexx`_, anche se non è obbligatoria: l'interprete tenta di eseguire qualunque nome di file gli venga passato come argomento e, se il file contiene codice Rexx valido, verrà eseguito correttamente.

Il comando seguente tenta di eseguire un file chiamato `hello.rexx`:

```plain
rexx hello.rexx
```

Supponendo che il file contenesse il seguente codice:

```rexx
say "Hello, world!"
exit 0
```

l'output nel terminale sarebbe:

```plain
Hello, world!
```

Lo stesso output apparirebbe se il file fosse rinominato in `hello.txt` ed eseguito come:

```plain
rexx hello.txt
```

Vale anche la pena sapere che il codice di uno script può essere inviato all'interprete tramite pipe, invece di risiedere in un file. Il codice precedente si può eseguire tramite pipe così:

```plain
echo "say 'Hello, world' ; exit 0" | rexx
```

e funziona altrettanto bene sia da un terminale Linux sia da un terminale Windows Powershell.

### Utilizzo avanzato

Agli script si possono passare uno o più argomenti dalla riga di comando, e possono restituire codici di ritorno arbitrari, purché siano numeri interi. L'interprete, però, deve sapere che allo script verranno passati più argomenti: cosa che si ottiene con l'opzione `-a`.

Per esempio, supponi che il file `multiarg.rexx` contenga il seguente codice:

```rexx
say "My name is" ARG(1) || ", your name is" ARG(2) || ", and the script return code will be" ARG(3) || "."
exit ABS(ARG(3))
```

Per assicurarti che i molteplici argomenti dello script siano interpretati correttamente, lo script si esegue così:

```plain
rexx -a multiarg.rexx "John" "Jill" 5
```

il che produce il seguente output nel terminale:

```plain
My name is John, your name is Jill, and the script return code will be 5.
```

e il codice di ritorno del programma (accessibile tramite `$?` su Linux o `%errorlevel%` su Windows) è impostato al valore 5.

### Accesso a routine esterne

Regina supporta l'uso di routine residenti in librerie condivise esterne. Diverse sono disponibili sul sito di Regina. L'installazione di tali librerie, però, non viene trattata qui.

Regina viene fornito con una libreria di questo tipo, _regutil_. Contiene diverse routine di uso generale, tra cui per la matematica, la manipolazione di file e filesystem e le attività di accesso al sistema.

Non sono necessari passaggi di installazione aggiuntivi. Per usare queste routine in uno script, però, è necessario che vengano registrate al momento del caricamento dell'interprete. Non servono più di due chiamate di funzione, e il procedimento è illustrato qui.

Un file, `access-external.rexx`, contiene il seguente codice:

```rexx
/* Register external library and functions */
call RxFuncAdd 'SysLoadFuncs', 'regutil', 'SysLoadFuncs'
call SysLoadFuncs

say "Value of pi is" SysPi()
say "Square root of 25 is" SysSqrt(25)
say "Square root of 2 is" SysSqrt(2)

/* Deregister */
call SysDropFuncs

exit 0
```

Per caricare e usare queste routine, bisogna usare il binario `regina`, quindi lo script si eseguirebbe così:

```plain
regina access-external.rexx
```

e appare il seguente output nel terminale:

```plain
Value of pi is 3.141592654
Square root of 25 is 5.000000000
Square root of 2 is 1.414213562
```

Se invece fosse stato usato il binario `rexx`, l'output nel terminale su Windows sarebbe:

```plain
'SYSLOADFUNCS' is not recognized as an internal or external command,
operable program or batch file.
'SYSPI' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSDROPFUNCS' is not recognized as an internal or external command,
operable program or batch file.
```

mentre su Linux l'output nel terminale sarebbe:

```plain
sh: SYSLOADFUNCS: command not found
sh: SYSPI: command not found
sh: SYSSQRT: command not found
sh: SYSSQRT: command not found
sh: SYSDROPFUNCS: command not found
```
