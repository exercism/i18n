# Introduzione agli here document

Nella scrittura di script Bash, un «here document» (o «heredoc») reindirizza più righe di input a un comando o a un programma, come se le stessi digitando direttamente nel terminale.
È uno strumento potente per incorporare testo su più righe negli script, senza aver bisogno di file esterni o di complicate manipolazioni di stringhe.

## Caratteristiche principali e sintassi

1. Delimitatore: un heredoc inizia con l'operatore `<<` seguito da una parola delimitatrice (spesso chiamata «marcatore» o «terminatore»).
   Questa parola delimitatrice può essere qualsiasi parola tu scelga, ma per chiarezza è comune usarne una come `EOF`, `END` o `TEXT`.
   Per avere un codice più leggibile, puoi usare come delimitatore qualcosa di descrittivo, per esempio `END_INSTALLATION_INSTRUCTIONS`.

1. Contenuto: dopo l'iniziale `<< DELIMITER`, scrivi il contenuto che vuoi reindirizzare.
   Può essere testo su più righe, codice o qualsiasi altra cosa.

1. Terminazione: l'heredoc termina quando la parola delimitatrice ricompare da sola su una riga, senza spazi all'inizio né alla fine.

## Sintassi di base

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## Come funziona

* Bash legge tutte le righe comprese tra il `<< DELIMITER` iniziale e il `DELIMITER` finale.
* Bash collega questo contenuto all'input standard del comando.
* Il comando elabora questo input come se arrivasse dalla tastiera.

### Esempio 1: semplice output di testo

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

Output:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

In questo esempio:

* `cat` è il comando.
* `<< EOF` avvia l'heredoc con `EOF` come delimitatore.
* Le tre righe di testo sono il contenuto.
* `EOF` da solo su una riga chiude l'heredoc.
* `cat` produce poi in output il contenuto che ha ricevuto.

### Esempio 2: uso con wc (conteggio parole)

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

Output:

```plaintext
3
```

Qui `wc -l` conta il numero di righe.
L'heredoc fornisce le tre righe come input.

### Esempio 3: passare dati a uno script

Lo script:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

Chiama lo script da un prompt bash interattivo con un heredoc:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

Output:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## Varianti e funzionalità avanzate

### Contenuto letterale

Bash esegue l'espansione delle variabili, la sostituzione dei comandi e l'espansione aritmetica all'interno di un heredoc.
In questo senso, gli heredoc si comportano come stringhe tra doppi apici.

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

Output:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

Quando il delimitatore è racchiuso tra apici (singoli o doppi), queste espansioni vengono disattivate.
Il contenuto viene preso alla lettera.
È come accade con le stringhe tra apici singoli.

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

Output:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### Rimuovere le tabulazioni iniziali

Se usi `<<-` (con un trattino finale) invece di `<<`, Bash rimuove ogni _carattere di tabulazione_ iniziale da ciascuna riga dell'heredoc.
È utile per indentare il contenuto dell'heredoc all'interno dello script senza influire sull'output.

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

L'output viene stampato con tutte le tabulazioni iniziali rimosse:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
L'autore non consiglia questo utilizzo.
Anche se può migliorare la leggibilità dello script,

1. è facile sostituire accidentalmente i caratteri di tabulazione con degli spazi (il tuo editor potrebbe farlo automaticamente), e 
1. è difficile notare la differenza tra spazi e tabulazioni.
~~~~

## Quando usare gli here document

* Input su più righe: quando devi fornire più righe di testo a un comando.
* File di configurazione: incorporare piccoli frammenti di configurazione all'interno di uno script.
* Generazione di codice: creare codice al volo all'interno di uno script.
* Interazioni negli script: simulare l'input dell'utente per programmi interattivi.
* Evitare file esterni: quando vuoi evitare di creare file temporanei.

Un uso tipico può essere fornire un testo di aiuto:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## Possibili svantaggi

* Documenti incorporati di grandi dimensioni possono rendere il codice più difficile da leggere.
  Può essere meglio rilasciare lo script con la documentazione in file separati.
* Gli here document possono spezzare il flusso del codice.
  Potresti trovarti in una sezione di codice profondamente annidata quando vuoi passare del testo a un programma.
  L'indentazione dell'heredoc può risultare stridente rispetto al codice circostante.

## Here string

Come gli here document, le _here string_ (o «herestring») forniscono input a un comando.
Tuttavia, mentre gli heredoc vengono passati come un blocco di testo, le here string vengono passate come una singola stringa di testo.
Le here string usano la sintassi `<<< "text"`.

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

Output:

```plaintext
UPPER CASE THIS STRING
```

A differenza degli heredoc, non serve alcun delimitatore finale.

### Perché usare le here string?

Al posto di una here string si può usare una pipeline:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

Quindi perché usare una here string?

Immagina il caso in cui ottieni la stringa come output di un calcolo che richiede molto tempo e vuoi passare il risultato a due comandi diversi.
Usando le pipeline, devi eseguire il calcolo due volte:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

Un approccio più efficiente consiste nel catturare l'output del calcolo (usando la sostituzione dei comandi) e usare le here string per fornire l'input ai due comandi successivi:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

Ecco un'applicazione reale di quell'esempio:

* catturare la risposta JSON di una query a un'API REST (che è paginata),
* passare i dati JSON a un programma jq per analizzare i risultati e scriverli in un file, e poi
* passare i dati JSON a un altro programma jq per determinare l'URL della query successiva.

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

Nota la posizione della redirezione dell'output.
Tutto l'output del ciclo while verrà aggiunto in coda al file `data.csv`.

## Heredoc e here string come redirezione

Dato che sono solo forme di redirezione, si possono combinare con altre operazioni di redirezione:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## In sintesi

Gli here document (o «heredoc») sono un modo flessibile e comodo per gestire input su più righe negli script Bash.
Semplificano il processo di incorporare testo e dati direttamente negli script, rendendoli più autonomi e più facili da leggere.

Le here string (o «herestring») sono simili agli here document, ma offrono una sintassi più semplice e più dinamica.
