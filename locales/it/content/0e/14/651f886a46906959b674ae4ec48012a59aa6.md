# Test

I test per un progetto Elm si trovano nella sottodirectory `tests/` di quel progetto.
La suite di test di ogni esercizio può essere eseguita dalla directory radice dell'esercizio.

```bash
$ cd ~/exercism/elm/hello-world
$ elm-test
```

## Controllare le modifiche

Riesegui automaticamente i test quando salvi le modifiche:

```bash
$ elm-test --watch
```

## Flusso di sviluppo guidato dai test

Nella maggior parte degli esercizi, i test sono già scritti nel file `tests/Tests.elm`.
Il tuo obiettivo è farli passare scrivendo il codice richiesto nel file `src/<exercise>.elm`.
Concentrati sul primo test che fallisce, correggilo,
poi rimuovi o trasforma in commento il successivo frammento `skip <|` nel file dei test e ripeti
finché tutti i test non passano.

## Ti senti bloccato?

Il primo obiettivo è far compilare il codice, anche con `Debug.todo` al suo interno.
Se ti sembra di non sapere come fare qualcosa,
spesso è utile estrarre quella parte in una funzione non implementata a sé stante.

```elm
complexOperationOnMultipleStrings : List String -> List String
complexOperationOnMultipleStrings allStrings =
    List.map complexOperation allStrings


complexOperation : String -> String
complexOperation input =
    Debug.todo "Extracted operation into its own function"
```

Aggiungere un'annotazione di tipo su questa funzione estratta
aiuterà sia il tuo ragionamento sia il compilatore a fornirti messaggi di errore migliori.

## Riordinare il codice

Valuta di eseguire [`elm-format`](https://github.com/avh4/elm-format) sul codice prima di inviarlo
e persino di configurarlo nel tuo editor di testo per la formattazione automatica al salvataggio.
