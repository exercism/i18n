# Le funzioni in `jq`

Puoi definire **funzioni personalizzate** in `jq` per incapsulare la logica che ti serve.
Le _funzioni_ si comportano esattamente come le funzioni integrate: ricevono un input ed emettono zero, uno o più output.

## Definire una funzione

Puoi definire una _funzione_ `jq` con la seguente sintassi:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- inizia con la parola chiave `def`,
- due punti prima del corpo della funzione,
- il corpo consiste in una sola espressione,
- termina con un punto e virgola,
- come per il resto della sintassi di `jq`, puoi usare spazi bianchi arbitrari per rendere il codice più leggibile.

## Dove definire le funzioni

Le _funzioni_ devono essere definite prima di essere usate: questo è un errore:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Questo implica che devi posizionare le _funzioni_ all'inizio del tuo codice `jq`, prima dell'espressione «principale».

### Funzioni annidate

Le _funzioni_ possono essere annidate:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Qui, la _funzione_ `B` è visibile solo nel corpo di `A`.

## Scope

Una _funzione_ introduce un nuovo **scope** per le variabili e le funzioni annidate.

## Argomenti

Gli **argomenti** di una _funzione_ sono separati da _punti e virgola_, non da virgole.
Per esempio, una _funzione_ che riceve un numero, poi ne aggiunge uno e moltiplica per un altro:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

I punti e virgola sono necessari perché in `jq` la virgola ha già uno scopo: è un operatore che unisce i flussi.

Se usi una virgola al posto di un punto e virgola, tenterai di fare due chiamate a una funzione `add_mul` a _1 argomento_, che non esiste: il primo tentativo di chiamata fallirà.

```jq
10 | add_mul(5, 4)

```

### Gli argomenti sono _espressioni_

Gli _argomenti_ di una funzione sono filtri, non valori.
In questo senso si comportano come ciò che altri linguaggi chiamano callback:

Prendiamo come esempio la funzione `add_mul`:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

Cosa succede qui?

- l'argomento `adder` riceve l'_espressione_ `. + 5`
  - quando la funzione esegue `. + adder`, questo diventa `. + . + 5`
  - che vale 25, dato che `. == 10`
- allo stesso modo, l'argomento `multiplier` è l'espressione `. - 2`
  - che vale 8
  - quindi il risultato è `25 * 8 == 200`

### Argomenti come valori

A volte vorrai «materializzare» un _argomento_ in una variabile:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Esiste una forma abbreviata per questo:

```jq
def my_func($arg):
    other stuff ...
;
```

Tieni presente che questo è solo «zucchero sintattico»: il nome `arg` senza `$` resta comunque nello scope della _funzione_.

## Arity

Le _funzioni_ hanno un'**arity**: il numero di _argomenti_ che accettano.

Le _funzioni_ possono usare lo stesso nome con _arity_ diverse.
La funzione integrata [`range`][man-range] lo dimostra: `range/1`, `range/2` e `range/3` coesistono.

Questo può essere utile per definire funzioni ricorsive che mantengono lo stato tramite gli argomenti.
Per esempio, `map` _potrebbe_ essere implementata così:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Ricorsione

`jq` esegue l'ottimizzazione delle chiamate in coda, ma solo per le funzioni a 0 argomenti.

## Moduli

Un modulo `jq` è un file che contiene solo funzioni.
I moduli si includono in un programma `jq` con i comandi [`include`][man-include] o [`import`][man-import].
