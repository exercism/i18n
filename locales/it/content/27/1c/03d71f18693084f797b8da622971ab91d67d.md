# Generatore di test del track Python di Exercism

Il track Python usa uno script generatore e i template [Jinja2][Jinja2] per
creare i file di test a partire dai [dati canonici][canonical data] di Exercism.

## Uso dello script

Per generare i test serve una copia locale del repository
[problem-specifications][problem-specifications].
Lo script va eseguito dalla directory `python` principale, per accedere
correttamente agli esercizi.

Esegui `bin/generate_tests.py --help` per informazioni sull'uso.


## Template di test

I template di test supportano la sintassi di [Jinja2] e hanno a disposizione le
seguenti variabili di contesto, ricavate dai dati canonici:
- `exercise`: il nome dell'esercizio con i trattini (es.: `two-fer`)
- `version`: la versione dei dati canonici (es.: `1.2.0`)
- `cases`: un array di oggetti caso oppure un array di array `cases`. Per la
struttura esatta dell'esercizio a cui stai lavorando, consulta
`canonical-data.json`
- `has_error_case`: indica se qualche caso di test prevede che venga
sollevato un errore (es.: `False`)
- `additional_cases`: struttura simile a `cases`, ma viene popolata dal file `.meta/additional_tests.json` dell'esercizio, se esiste (per un esempio, vedi `exercises/word-count/.meta/additional_tests.json`)

Inoltre, per comodità sono stati aggiunti i seguenti filtri per i template:
- `to_snake`: converte una stringa in snake_case (es.: `{{ "CamelCaseString" | to_snake }}` -> `camel_case_string`)
- `camel_case`: converte una stringa in CamelCase (es.: `{{ "snake_case_string" | camel_case }}` -> `SnakeCaseString` )
- `error_case`: controlla se un caso di test prevede che venga sollevato un errore (es.: `{% for case in cases%}{% if case is error_case}`)
- `regex_replace`: sostituzione di stringhe con espressioni regolari (es.: `{{ "abc123" | regex_replace("\\d", "D") }}` -> `abcDDD`)


### Convenzioni

- Le macro di uso generale per le strutture di template molto ripetute sono definite in `config/generator_macros.j2`.
  - Si possono importare così:
  `{%- import "generator_macros.j2" as macros with context -%}`
- Tutti i template di test dovrebbero terminare con `{{ macros.footer() }}`.
- Tutti i nomi delle classi Python dovrebbero essere in CamelCase (es.: `TwoFer`).
  - Convertili con `{{ "two-fer" | camel_case }}`
- Tutti i nomi dei moduli e delle funzioni Python dovrebbero essere in snake_case
(es.: `high_scores`, `personal_best`).
  - Convertili con `{{ "personalBest" | to_snake }}`
- I test specifici del track sono definiti nel file di opzioni `.meta/additional_tests.json`. L'oggetto JSON definito in questo file deve
avere una sola chiave, `cases`, che ha la stessa struttura di `cases` in
`canonical-data.json`.
- I test specifici del track vanno inseriti dopo i test canonici nei file di
test.
- I test specifici del track vanno contrassegnati nel file di test con questo commento:
```
# Additional tests for this track
```


### Struttura

La maggior parte dei template sarà più o meno così:

```Jinja2
{%- import "generator_macros.j2" as macros with context -%}
{{ macros.header() }}

class {{ exercise | camel_case }}Test(unittest.TestCase):
    {% for case in cases -%}
    def test_{{ case["description"] | to_snake }}(self):
        value = {{ case["input"]["value"] }}
        expected = {{ case["expected"] }}
        self.assertEqual({{ case["property"] }}(value), expected)

    {% endfor %}

{{ macros.footer() }}
```


### Sovrascrivere gli import

I nomi importati in `macros.header()` possono essere sovrascritti aggiungendo
un array di nomi alternativi da importare (es.: `clock`):

```Jinja2
{{ macros.header(["Clock"])}}
```


### Ignorare le proprietà

In rare occasioni può essere necessario escludere le proprietà che
non vengono testate in questo track. La macro `header` accetta anche un
argomento `ignore` (es.: `high-scores`):

```Jinja2
{{ macros.header(ignore=["scores"]) }}
```

## Creare un template

1. Crea il file `.meta/template.j2` per l'esercizio che stai implementando
  e aprilo nel tuo editor.
2. Copia e incolla la [struttura di esempio](#Layout) nel file del template
  e salva.
3. Apporta le modifiche necessarie al file del template finché non produce
  codice di test valido, facendo riferimento al `canonical-data.json` dell'esercizio per
  i nomi degli input e la struttura dei casi.
    - Usa le [macro disponibili](../config/generator_macros.j2) per evitare di riscrivere le sezioni standardizzate.
    - Se stai implementando un template per un esercizio esistente,
    non è obbligatorio rispettare esattamente la struttura del file di test
    esistente, ma ridurre al minimo le differenze renderà la revisione della PR
    molto più scorrevole per tutti.
