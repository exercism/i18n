# Informazioni

Come visto nel concetto [`Nothingness`][concept-nothingness], R ha vari modi per rappresentare i dati assenti ([`NULL`][ref-null]), sconosciuti ([`NA`][ref-na]) o matematicamente non validi ([`NaN`][ref-finite], [`Inf`][ref-finite]).
In generale, R cercherà di usare questi valori per segnalare i problemi sul posto e di proseguire senza sollevare un'eccezione.

## `stop()`

Alcuni problemi sono troppo fondamentali per lasciare che il programma continui.
In questo caso, usa [`stop(msg)`][ref-stop] per interrompere immediatamente il programma con un `Error` e stampare `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Simile a un [`assert`][wiki-assert] di altri linguaggi, [`stopifnot()`][ref-stopifnot] è un comodo wrapper per `stop()`.
Gli argomenti sono un numero arbitrario di condizioni booleane, separate da virgole, ed il programma continuerà solo se sono tutte `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R ha diversi modi per gestire gli errori.
Questi si basano su Common Lisp e differiscono notevolmente da molti linguaggi diffusi.

Il più semplice è racchiudere il codice potenzialmente problematico in [`try()`][ref-try].

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning] e [`message()`][ref-message]

Queste sono risposte a condizioni non fatali, per esempio:

- Per avvisare di un problema da cui il programma potrebbe almeno in parte riprendersi.
- Per informare l'utente dei progressi di un programma di lunga durata.

Una differenza tra loro è che gli avvisi vengono memorizzati nella cache e (per impostazione predefinita) emessi quando la funzione termina, mentre i messaggi vengono emessi immediatamente.
Ci sono molti modi per cambiare il comportamento predefinito, ma esulano dagli scopi di questa pagina.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

La funzione [`suppressWarnings()`][ref-warning] può occasionalmente essere utile su Exercism, per evitare di confondere il test runner con un output indesiderato.

## Gestori di condizioni

R ha un modo alternativo per gestire gli stati di errore, più vicino nello spirito all'approccio di Java e di linguaggi simili.

I dettagli esulano dagli scopi di questo concetto, ma chi è interessato può dare un'occhiata a [`tryCatch`][ref-conditions] e [`withCallingHandlers`][ref-conditions].

C'è una buona discussione nella [sezione 8.4][book-handling] di Advanced R.
