# Suggerimenti

Un uso comune di `Either` è indicare un calcolo che può potenzialmente produrre un errore (se l'errore in sé non interessa, il tipo più semplice `Option` potrebbe essere una scelta migliore).
In assenza di un errore il risultato è di solito un `Right` (aiuto mnemonico: il valore «right»), mentre un errore è un `Left`, per esempio un `Left[String]` che contiene un messaggio di errore.
Nota che in Scala 2.12 `Either` è right-biased per impostazione predefinita, quindi funziona come previsto per operazioni come `filter`, `map`, `flatMap` o dentro una for-comprehension.
Se non hai familiarità con `Either`, puoi leggere [questo tutorial](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html). Tieni però presente che questo tutorial riguarda versioni di Scala precedenti alla 2.12. Per Scala 2.12 puoi tranquillamente ignorare `RightProjection` e omettere `.right`.
`Either` è una cosiddetta [Monade](https://en.wikipedia.org/wiki/Monad_(functional_programming)) che copre un «aspetto computazionale», in questo caso la gestione degli errori.
L'uso corretto delle monadi può portare a codice molto conciso ma elegante e leggibile. Un uso improprio può facilmente portare al contrario.
Guarda [questo video](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) per saperne di più.

## Errori comuni da evitare

Ci sono alcune regole pratiche per `Either`:

1. Se non ti serve, non usarlo. Invece di
```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```
è meglio avere
```scala
def add1(x: Int): Int = x + 1
```
(esiste `Either.map` per applicare funzioni così semplici, quindi non devi appesantirle con `Either`).

2. Non fare «unwrap» se non ne hai davvero bisogno.
Spesso esistono funzioni integrate per il tuo scopo. Indicatori di unwrapping prematuro sono `isLeft/isRight` o il pattern matching. Per esempio, invece di
```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```
è meglio avere
```scala
x fold (identity, _ + 1)
```

3. Le monadi si possono usare dentro una for-comprehension, FTW.
Questo è consigliabile quando vuoi «comporre» diverse istanze di `Either`. Invece di
```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```
è meglio avere
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
