# Informazioni

L'unica convenzione di Factor per passare i dati è lo *stack di dati*: i word prelevano i loro input e impilano i loro output. Ogni definizione di word dichiara un *effetto sullo stack* che documenta questo contratto.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

I nomi all'interno di `( … -- … )` servono al lettore; quello che il compilatore controlla è il *numero* di input e output. Una discrepanza è un errore in fase di compilazione: intercetta una classe di bug che, in un linguaggio a tipizzazione dinamica privo di questo tipo di dichiarazione, sarebbero errori in fase di esecuzione.

Dato che lo stack è posizionale, devi riordinare continuamente la sua cima prima che il word successivo possa essere eseguito. I **word di shuffle** del `kernel` fanno esattamente questo:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

La famiglia completa dei word di shuffle li estende con `-rot` (che rotola nella direzione opposta), i cugini con il suffisso `d` che agiscono un elemento più in profondità (`dupd`, `swapd`), i cugini con il prefisso `2` che agiscono su coppie (`2dup`, `2drop`, `2nip`) e altri ancora come `pick` e `tuck`. Vengono introdotti man mano che gli esercizi successivi ne hanno bisogno; ricorrere a troppi word di shuffle tutti in una volta è di solito il segno che un *local* (un valore con un nome) si leggerebbe meglio.

Per convenzione, i word usano il `lowercase-kebab-case`, i predicati terminano con `?` e producono un valore booleano (`even?`, `empty?`), i setter si scrivono `>>name` e i getter `name>>`, e un word e la sua variante mutante spesso condividono lo stesso nome, distinti solo dal contesto.
