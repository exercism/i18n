# Introduzione

Come molti altri linguaggi, Go ha i puntatori.
Se è la prima volta che li incontri, possono sembrare un po' misteriosi, ma una volta che ci prendi la mano diventano piuttosto semplici.
Sono una parte cruciale di Go, quindi prenditi il tempo necessario per capirli davvero.

Prima di addentrarci nei dettagli, vale la pena capire a cosa servono i puntatori.
I puntatori sono un modo per condividere la memoria con le altre parti del nostro programma, e questo è utile per due motivi principali:

1. Quando abbiamo grandi quantità di dati, fare copie da passare tra le funzioni è molto inefficiente.
   Passando invece la posizione di memoria in cui i dati sono memorizzati, possiamo ridurre drasticamente il consumo di risorse dei nostri programmi.
2. Passando i puntatori tra le funzioni, possiamo accedere e modificare direttamente l'unica copia dei dati: questo significa che le modifiche fatte da una funzione sono immediatamente visibili alle altre parti del programma quando la funzione termina.

## Variabili e memoria

Diciamo che abbiamo una normale variabile intera `a`:

```go
var a int
```

Quando dichiariamo una variabile, Go deve trovare un posto in memoria per memorizzarne il valore.
Tutto questo è in gran parte astratto per noi: quando dobbiamo recuperare il valore memorizzato in quella porzione di memoria, ci basta riferirci a esso con il nome della variabile.

Per esempio, quando scriviamo `a + 2`, di fatto recuperiamo il valore memorizzato nella memoria associata alla variabile `a` e vi aggiungiamo 2.

Allo stesso modo, quando dobbiamo cambiare il valore nella porzione di memoria di `a`, possiamo usare il nome della variabile per fare un'assegnazione:

```go
a = 3
```

La porzione di memoria associata ad `a` ora conterrà il valore `3`.

## Puntatori

Le variabili ci permettono di riferirci ai valori in memoria, ma a volte è utile conoscere l'**indirizzo di memoria** verso cui punta la variabile.
I **puntatori** contengono proprio gli indirizzi di memoria di quei valori.
Si dichiara una variabile con tipo puntatore anteponendo un asterisco al tipo sottostante:

```go
var p *int // 'p' contains the memory address of an integer
```

Qui dichiariamo una variabile `p` di tipo «pointer to int» (`*int`).
Questo significa che `p` conterrà l'indirizzo di memoria di un intero.
Il valore zero dei puntatori è `nil`, perché un puntatore `nil` non contiene alcun indirizzo di memoria.

### Ottenere un puntatore a una variabile

Per trovare l'indirizzo di memoria del valore di una variabile possiamo usare l'operatore `&`.
Per esempio, se vogliamo trovare e memorizzare l'indirizzo di memoria della variabile `a` nel puntatore `p`, possiamo fare così:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Accedere al valore tramite un puntatore (dereferenziazione)

Quando abbiamo un puntatore, potremmo voler conoscere il valore memorizzato all'indirizzo di memoria che il puntatore rappresenta.
Possiamo farlo con l'operatore `*`:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

L'operazione `*p` recupera il valore memorizzato all'indirizzo di memoria contenuto in `p`.
Questa operazione è spesso chiamata «dereferenziazione».

Possiamo anche usare l'operatore di dereferenziazione per assegnare un nuovo valore all'indirizzo di memoria a cui il puntatore fa riferimento:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

Assegnare a `*pa` cambierà il valore memorizzato all'indirizzo di memoria contenuto in `pa`.
Dato che `pa` contiene l'indirizzo di memoria di `a`, assegnando a `*pa` stiamo di fatto cambiando il valore di `a`!

Un avvertimento però: controlla sempre che un puntatore non sia `nil` prima di dereferenziarlo.
Dereferenziare un puntatore `nil` farà andare in crash il programma a runtime!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Puntatori a struct

Finora abbiamo visto solo puntatori a valori primitivi.
Possiamo creare puntatori anche per le struct:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

Avremmo anche potuto creare una nuova `Person` e memorizzare subito un puntatore a essa:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Quando abbiamo un puntatore a una struct, non serve dereferenziare il puntatore prima di accedere a uno dei campi:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## Le slice e le map sono già dei puntatori

Le slice e le map sono tipi speciali, perché nella loro implementazione contengono già dei puntatori.
Questo significa che il più delle volte non abbiamo bisogno di creare puntatori per questi tipi per condividere l'indirizzo di memoria dei loro valori.
Immaginiamo di avere una funzione che incrementa il valore di una chiave in una map:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Se creiamo una map e chiamiamo questa funzione, le modifiche fatte dalla funzione alla map restano anche dopo che la funzione è terminata.
È un comportamento simile a quello che otterremmo usando un puntatore, ma nota come in questo esempio non usiamo alcun riferimento, alcuna dereferenziazione né alcuna parte della sintassi dei puntatori:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

Lo stesso vale quando si cambia un elemento esistente in una slice.

Tuttavia, le operazioni che restituiscono una nuova slice come `append` sono un caso particolare e **potrebbero non** modificare la slice al di fuori della funzione.
Questo dipende da come funzionano internamente le slice, ma non lo tratteremo nei dettagli, perché è un argomento più avanzato.
Se sei davvero curioso, puoi leggere di più a riguardo in [Go Blog: Mechanics of 'append'][mechanics-of-append]
