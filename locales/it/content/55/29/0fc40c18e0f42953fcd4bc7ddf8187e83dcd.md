# Informazioni

## Rappresentazione, caratteri e numeri interi

Come per gli altri tipi semplici (`int`, `bool`, ecc.), `char` ha un tipo complementare o un alias, in questo caso `System.Char`.

Si tratta in realtà di una `struct` con un campo a 16 bit, ed è immutabile per impostazione predefinita.

`char` ha alcuni metodi di istanza come `Equals`, `ToString` e [`CompareTo`][compare-to].

`char` ha la stessa larghezza di un [`ushort`][uint16], ma in genere non vengono usati in modo intercambiabile come accade in altri linguaggi. `ushort` deve essere convertito esplicitamente in un `char`.

Vale la pena sapere che i `char` possono essere sottoposti a operazioni aritmetiche. Il risultato di queste operazioni è un numero intero.

Ovviamente non c'è equivalenza tra un `byte` a 8 bit e un `char` a 16 bit.

## Utilizzo

In genere, i `char` sono facili da usare.

Possono essere definiti come letterali con virgolette singole:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

Un singolo `char` può essere estratto da una stringa con l'indicizzazione (che parte da zero):

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

Iterando su una stringa si ottiene un `char` a ogni passo:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

Come mostrato sopra, un `char` può essere convertito nel suo valore `int`.
Questo funziona (*almeno a volte*) anche per altri sistemi di scrittura:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

Il valore Int16 sottostante viene usato quando si confrontano i caratteri:

```fsharp
'A' < 'D'
// => val it: bool = true
```

Inoltre, un `int` può essere convertito in `char`:

```fsharp
char 77
// => val it: char = 'M'
```

La libreria `System.Char` contiene l'insieme completo di [metodi][Char-methods] previsti per un linguaggio .NET, come le conversioni da maiuscolo a minuscolo (ma vedi le avvertenze nella prossima sezione):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

Le librerie .NET aiutano a estrarre i `char` dalle stringhe, in questo caso con i metodi di `Seq`:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

Ci sono vari modi per convertire una lista (o un array) di caratteri in una stringa, tra cui questi:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

Qui puoi trovare informazioni generali sui `char`:

- [Chars documentation][chars-docs]: documentazione di riferimento per `char`.

Tuttavia, i `char` presentano diverse asperità, come descritto in dettaglio di seguito. Queste asperità riguardano per lo più il contrasto tra lo standard Unicode completo da un lato e le rappresentazioni storiche del testo, le prestazioni e l'uso della memoria dall'altro.

## Problemi con Unicode

Quando hai a che fare con le stringhe, se sono disponibili i metodi della libreria [`System.String`][System-string] è meglio cercarli e usarli, invece di scomporre la stringa in caratteri.

Alcuni «caratteri» testuali sono composti da più di un `char`, perché lo standard Unicode ha più di 65536 punti di codice. Per esempio, le emoji che compaiono in alcuni test hanno 2 `char`, perché sono composte da caratteri [surrogati][surrogates].

Inoltre, esistono sequenze combinanti: per esempio, in alcuni casi un carattere accentato può essere formato da un `char` per il carattere semplice e un altro `char` per l'accento.

Se devi avere a che fare con caratteri singoli, cerca di usare metodi di libreria come [`System.Char.IsControl`][is-control] e [`System.Char.IsDigit`][is-digit], invece di fare confronti ingenui, come verificare che un carattere sia compreso tra '0' e '9'.

Per esempio, nota che '٢' è la cifra araba 2. `IsDigit` restituirà true per la versione araba, quindi devi essere chiaro, ad esempio in fase di convalida, su quale intervallo di input sia accettabile.

Persino i metodi della libreria `System.Char` potrebbero non comportarsi come ti aspetti quando hai a che fare con linguaggi più oscuri.

Un modo sicuro per suddividere una stringa in «caratteri» da visualizzare è usare [`StringInfo`][string-info] e metodi come [`GetNexttextElement`][get-next-text-element].
Questo potrebbe essere necessario se hai a che fare con la globalizzazione o la localizzazione.

Un'altra strada, quando i valori scalari dei caratteri Unicode sono importanti (per esempio se stai costruendo un tuo sistema di codifica), è usare i [runes][runes]. Tuttavia, se sai che l'intervallo di caratteri che tratti non include surrogati o sequenze di caratteri combinanti (ad esempio l'ASCII latino) e il tuo input è ben convalidato, puoi evitarlo.

Ancora una volta, la situazione migliore è quella in cui puoi usare i metodi della libreria di `String`.

Se ti ritrovi nella poco invidiabile posizione di dover affrontare i dettagli minuti di Unicode, allora [questo][char-encoding-net] è un buon punto di partenza.

## Globalizzazione

Se lavori in un ambiente in cui hai a che fare con più culture, oppure la cultura è importante in alcune parti del codice ma non in altre, tieni presente gli overload di [`ToUpper`][to-upper] e [`ToLower`][to-lower] che accettano una cultura, e [`ToUpperInvariant`][to-upper-invariant] e [`ToLowerInvariant`][to-lower-invariant] che forniscono un risultato coerente indipendentemente dalla [cultura][culture-info] corrente.
