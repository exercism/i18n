# Informazioni

Una funzione è [ricorsiva in coda][recursion-tc] se l'_ultima_ cosa eseguita dalla funzione è una chiamata a se stessa.

Ogni volta che viene chiamata una funzione, uno stack frame con le sue variabili locali, i suoi argomenti ecc. viene messo in cima allo [stack delle chiamate di funzione][call-stack]. Quando una funzione restituisce, lo stack frame viene rimosso dallo stack.

Le funzioni ricorsive in coda consentono l'[ottimizzazione delle chiamate in coda][tail-call-optimization]. È un'ottimizzazione che permette alla chiamata successiva di riutilizzare l'ultimo stack frame, perché la funzione precedente non ne ha più bisogno. Questo riduce il rischio di overflow dello stack delle chiamate di funzione, cioè la situazione in cui ci sono così tanti frame sullo stack che non è rimasta memoria per crearne un altro.

- Per ottenere la ricorsione in coda in Elixir, spesso serve un accumulatore, a causa delle regole di immutabilità dei dati.

  - Un accumulatore è una variabile che viene passata di chiamata in chiamata e mantiene lo stato attuale della funzione ricorsiva _fino a quel momento_, finché il risultato finale non viene restituito nel caso base.

    ```elixir
    # Count the length of a list without an accumulator
    def count([]), do: 0
    def count([_head | tail]), do: 1 + count(tail)

    # Count the length of a list with an accumulator
    def count(list), do: do_count(list, 0)

    defp do_count([], count), do: count
    defp do_count([_head | tail], count), do: do_count(tail, count + 1)
    ```

- Quando lavori con le liste, ricorda che sono implementate come liste semplicemente concatenate: le operazioni di prepend sono molto veloci, mentre quelle di append sono molto lente.

  ```elixir
  # Reverse a list with an accumulator
  def reverse(list), do: do_reverse(list, [])

  defp do_reverse([], acc), do: acc

  defp do_reverse([head | tail], acc) do
    do_reverse(tail, [head | acc])
  end
  ```
