# Introduzione

Il concetto dei condizionali introduce `jcc`, la famiglia di istruzioni per il salto condizionato in base a una condizione.
Una `jcc` trasferisce l'esecuzione in un altro punto del programma solo se la sua condizione è soddisfatta.

Tuttavia, le CPU moderne sono veloci e capaci di eseguire molte istruzioni in parallelo.
Sarebbe troppo costoso bloccare tutto il lavoro mentre la CPU attende una verifica della condizione a runtime.

Ecco perché, al suo interno, la CPU non aspetta.
Usa un **predittore di salto** per indovinare l'esito di una condizione e inizia a eseguire _in modo speculativo_ il percorso previsto.

Se la previsione è corretta, l'esecuzione procede come se non ci fosse alcun salto.
Se invece la previsione è sbagliata, la CPU deve _scartare il lavoro svolto_ sul percorso previsto e ricominciare da quello corretto.

Questa si chiama **predizione errata del salto** ed è costosa: comporta un ritardo.

Quando un salto è difficile da prevedere, queste previsioni errate si accumulano.
In questi casi, a volte è preferibile evitare del tutto il salto, così che le stesse istruzioni vengano eseguite indipendentemente dalla condizione.
Il codice che sceglie tra valori senza una `jcc` si chiama **senza salti**.

Ci sono diversi modi per strutturare il codice in modo che salti meno spesso, o che i salti che fa siano più prevedibili.
In particolare, x86-64 offre due famiglie di istruzioni usate comunemente per scrivere codice senza salti.

## Spostamenti condizionali

La famiglia di istruzioni `cmovcc` copia l'operando sorgente nella destinazione solo se una condizione specifica è soddisfatta.
In caso contrario, la destinazione rimane invariata.

Il suffisso `cc` segue la stessa nomenclatura di `jcc`, con lo stesso significato:

| istruzione | sposta se                            |
|-------------|--------------------------------------|
| `cmove`     | A == B dopo `cmp A, B`              |
| `cmovne`    | A != B dopo `cmp A, B`              |
| `cmovl`     | A < B (con segno) dopo `cmp A, B`      |
| `cmovb`     | A < B (senza segno) dopo `cmp A, B`    |
| `cmovg`     | A > B (con segno) dopo `cmp A, B`      |
| `cmova`     | A > B (senza segno) dopo `cmp A, B`    |

Le regole sono simili a quelle di `jcc`:

1. `l` e `g` si usano per i confronti con segno, mentre `b` e `a` per quelli senza segno.
2. Aggiungere `e` a un suffisso include l'uguaglianza.
3. Aggiungere `n` nega la condizione.
4. Esistono anche varianti che si riferiscono al flag impostato.
   Per esempio, `cmovz` e `cmovc`.

Consideriamo il valore assoluto di un intero con segno in `rdi`, restituito in `rax`.
Scritta con `jcc`, la funzione seleziona uno dei due percorsi:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Scritta con `cmovcc`, entrambi i valori candidati vengono calcolati incondizionatamente e lo spostamento condizionale ne sceglie uno:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

La versione senza salti esegue sempre le stesse istruzioni.
Non c'è nessuna `jcc` che il predittore debba indovinare.

La destinazione di una `cmovcc` deve essere un registro.
La sorgente può essere un registro o una locazione di memoria, ma non un valore immediato.

~~~~exercism/note
Nel codice qui sopra, l'istruzione `neg` imposta diversi flag in base al risultato, incluso il flag di segno (SF).
Questo significa che `cmp rdi, 0` si può eliminare del tutto:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Se `rdi` è positivo, `neg` produce un risultato negativo e SF == 1, quindi `cmovs` ripristina `rdi`.
Se invece `rdi` è zero o negativo, `neg` produce un risultato non negativo e SF == 0, quindi `rax` mantiene il valore negato (che è il valore assoluto corretto).

Sebbene `cmp` sia il modo principale per confrontare valori nel codice assembly, molte istruzioni impostano i flag in base al proprio risultato.
L'elenco completo dei flag che un'istruzione influenza è di solito riportato nella sua [documentazione di riferimento][reference].
Per `neg` in particolare, sono SF, ZF, CF, OF e PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

## Impostazione condizionale

La famiglia di istruzioni `setcc` imposta l'operando di destinazione a `1` se una condizione specifica è soddisfatta, altrimenti a `0`.
La destinazione è sempre un _operando a 8 bit_.

Il suffisso `cc` segue la stessa nomenclatura di `jcc` e `cmovcc`.
Per esempio, `setz` imposta la destinazione a `1` se `ZF == 1`, altrimenti a `0`.

Dato che la destinazione è a 8 bit, è comune far seguire `setcc` da un `movzx` quando serve un valore più ampio:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Questo è un idioma comune per trasformare il risultato di un confronto nell'intero `0` o `1`.
