# Introduzione

Un *segnalatore* a bordo di una nave di pattuglia costiera tiene il
registro dei messaggi. Le bandiere di segnalazione grezze arrivano
incorniciate da caratteri marcatore; le letture vanno rese per la
trasmissione; coppie e terne di osservazioni vengono riassunte al volo.
Un pugno di idiomi della libreria standard di Factor fa quasi tutto il
lavoro.

## `unparse`: dal valore al sorgente

[`unparse`][unparse] (in `prettyprint`) restituisce il testo in forma
sorgente di qualsiasi valore:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` è l'inverso del parser: il giro completo
`dup unparse parse` ricostruisce il valore. È lo strumento giusto per
serializzare verso un formato di trasmissione che il ricevente
rileggerà con il parser, e quello sbagliato per un output leggibile da
una persona (le stringhe mantengono le virgolette, i vettori mantengono
il loro `V{ ... }`, e così via).

## Varianti slice: viste, non copie

`head` e `tail` di `sequences` *copiano* la parte che tieni in una
sequenza nuova. Le loro controparti `-slice` restituiscono invece un
oggetto `slice`, una tupla che contiene l'indice di partenza, l'indice
di arrivo e la sequenza sottostante, e che implementa il
[protocollo delle sequenze][sequence-protocol] senza copiare:

| parola       | effetto                                          |
|--------------|--------------------------------------------------|
| `head`        | `( seq n -- newseq )`, copia i primi n           |
| `head-slice`  | `( seq n -- slice )`, vista dei primi n          |
| `tail`        | `( seq n -- newseq )`, copia dall'indice n in poi |
| `tail-slice`  | `( seq n -- slice )`, vista dall'indice n in poi |
| `head*`       | `( seq n -- newseq )`, copia tutti tranne gli ultimi n |
| `head-slice*` | `( seq n -- slice )`, vista di tutti tranne gli ultimi n |
| `tail*`       | `( seq n -- newseq )`, copia gli ultimi n        |
| `tail-slice*` | `( seq n -- slice )`, vista degli ultimi n       |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

Uno `slice` *è* una sequenza, quindi tutto ciò che accetta una sequenza
accetta uno slice: `length`, `first`, `each` e compagnia funzionano
senza copiare. I test che devono confrontare con una stringa letterale
possono convertire con `>string`.

## `?head` e `?tail`: rimuovere un marcatore se presente

Le letture incorniciate portano un testo marcatore che può esserci o no.
`?head` e `?tail` (in `splitting`) provano a rimuovere un prefisso o un
suffisso, e restituiscono la sequenza (eventualmente accorciata) *e* un
booleano che indica se il marcatore è stato trovato:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

Il booleano in coda li rende adatti come guardia: abbina `?head` a `if`
per ramificare a seconda che la cornice fosse presente, oppure a
`unless` per rifiutare input privi del marcatore atteso.

## `<repetition>`: N copie, virtuali

[`<repetition>`][repetition] (in `sequences`) è un'altra sequenza
virtuale che non copia: `( len elt -- repetition )` costruisce una
sequenza di `len` elementi tutti uguali a `elt`, senza allocare
altrettanti slot:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

Lo stesso `elt` può essere una sequenza: ogni copia è quella stessa
sequenza. Poi `concat` unisce le copie una dopo l'altra:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

Come uno `slice`, il risultato *è* una sequenza: `length`, `each` e
compagnia funzionano direttamente su di essa. Usalo per portare un
codice di segnalazione a una larghezza fissa o per produrre una serie di
marcatori ripetuti; converti con `>string` (o `>array`) solo quando
serve davvero una sequenza concreta.

## `<clumps>`: finestre sovrapposte, virtuali

[`<clumps>`][clumps] (in `grouping`) è una terza sequenza virtuale che
non copia: `( seq n -- clumps )` vede `seq` come la serie di finestre
di lunghezza `n` *sovrapposte*, ognuna delle quali è uno slice:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

Una sequenza lunga n produce `length - n + 1` finestre. Dato che ogni
finestra è uno slice, accoppiare letture successive non costa alcuna
copia: `[ first2 ]` su ogni clump di `2` ti dà ogni coppia consecutiva
da cui proiettare. (Il cugino non sovrapposto, `<groups>`, spezza invece
la sequenza in blocchi disgiunti.)

## Cleave multi-input: `2bi`, `3bi`, `2tri`, `3tri`

Le parole cleave semplici `bi` e `tri` applicano due o tre quotation a
*un* input. Le varianti con prefisso `2` e `3` applicano ogni quotation
a *due* o *tre* input:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

Ogni quotation riceve *tutti* gli input. Usale quando più di una
proiezione dipende dalla stessa coppia (o terna) di valori, non quando
vuoi applicare la *stessa* operazione a ogni input separatamente (in
quel caso sono `bi@` o `tri@`).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
