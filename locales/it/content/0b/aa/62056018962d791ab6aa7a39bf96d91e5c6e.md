# Segnaposto

## Nuovi concetti di AWK

Questo è il primo esercizio in cui la soluzione non è uno script «main».
L'obiettivo è scrivere una libreria di funzioni da includere in altri programmi awk.
In questo esercizio ci sono diversi nuovi concetti interessanti da scoprire.

Le sezioni seguenti contrassegnate con "(gawk)" sono estensioni specifiche di GNU awk.

### Leggere da un file

In questo esercizio leggerai i dati da un file, non dal flusso di input principale. 
Leggi la documentazione su [`getline`][getline] nel manuale di Gnu awk,
in particolare le forme `Getline/File` e `Getline/Variable/File`.

### Ancora sugli array

Un array bidimensionale potrebbe essere un modo per implementare questa soluzione.
GNU awk ha due modi per rappresentarlo:

* [array multidimensionali][multi]
* [array di array][a-of-a] <sup><sup>(gawk)</sup></sup>

### File inclusi <sup><sup>(gawk)</sup></sup>

Nota la direttiva [`@include`][d-include] nel file di test.  
Indica a gawk di leggere e valutare il file indicato.

### Namespace <sup><sup>(gawk)</sup></sup>

Tutte le variabili di awk sono globali (tranne i parametri delle funzioni, che sono locali alla funzione).
C'è un alto rischio di collisioni di nomi, soprattutto quando si includono librerie di terze parti. 
I [namespace][namespaces] sono un modo per suddividere dove vengono memorizzate le variabili.
Nota la direttiva [`@namespace`][d-namespace] nei file dell'esercizio.

Il namespace predefinito si chiama «awk». 
Avere un namespace predefinito permette al programmatore di chiamare una funzione integrata di awk dall'interno di una funzione che si trova in un namespace diverso.

### Come vengono passati i parametri delle funzioni

I parametri di tipo array vengono passati **per riferimento**.
Le modifiche apportate all'array dentro la funzione sono visibili a chi l'ha chiamata.

I parametri che non sono array vengono passati **per valore**.

Per i parametri _non tipizzati_, dipende da cosa ne fa la funzione:
- se la funzione lo inizializza come array, allora diventa un parametro passato per riferimento,
- se la funzione lo inizializza come valore scalare (un numero o una stringa), allora non è un riferimento.

Tutti i dettagli sono nel manuale, in [Passaggio degli argomenti di funzione per valore o per riferimento][pass-by].

#### Variabili locali

Le variabili con scope di funzione (locali) si possono creare usando parametri passati per valore.
Non è un errore passare a una funzione meno valori del numero di parametri elencati;
i parametri in eccesso sono «untyped» finché non vengono usati.
Restano disponibili per ricevere valori scalari dentro la funzione, valori che non vengono memorizzati nel namespace globale.

- Se assegni un valore scalare a un parametro, questo è locale alla funzione.
- Se assegni un valore scalare a una variabile **non** presente nell'elenco dei parametri, quella variabile è globale.

Per convenzione, nella firma della funzione i parametri previsti compaiono per primi, seguiti da uno spazio e poi dai parametri locali.
Un esempio:

```awk
function add(a, b,    total) {
    # here, `typeof(total)` is "untyped"
    total = a + b
    # now, `typeof(total)` is "number"
    return total
}

BEGIN {
    sum = add(5, 10)
    print sum             # 15
    print typeof(total)   # untyped, meaning "total" is unused in this scope
}
```
