# Informazioni

Le [comprensioni][for] offrono un meccanismo per trasformare gli _Enumerable_ in modo semplice e dichiarativo. Sono _zucchero sintattico_ per iterare sugli enumerable in Elixir.

[//]: # (elixir-formatter-disable-next-block)

```elixir
for s <- ["a", "b", "hello", "c"], # 1. generator
  String.length(s) == 1,           # 2. filter
  into: "",                        # 3. collectable
  do: String.upcase(s)

# => "ABC"
```

Una comprensione è composta da tre parti:

1. _generatori_:
   - Valori enumerati da strutture che implementano il protocollo [_Enumerable_][enumerable].
   - Espressioni di pattern matching per destrutturare i valori enumerati.
2. _filtri_: condizioni booleane, usate per selezionare quali valori enumerati usare quando si creano i nuovi valori.
3. _collectable_: una struttura che implementa il protocollo [_Collectable_][collectable], usata per raccogliere i nuovi valori.

Esistono comprensioni su una sola riga e comprensioni su più righe. Quando si usa più di un generatore, viene enumerato un [prodotto cartesiano][cartesian-product] dei valori generati. Questo significa che ogni valore generato dal primo generatore verrà accoppiato una volta con ogni valore generato dal secondo generatore.

```elixir
for n <- [0, 1, 2, 3], do: n + 1
# => [1, 2, 3, 4]

for x <- [0, 1],
    y <- [0, 1] do
  {x, y}
end

# => [{0, 0}, {0, 1}, {1, 0}, {1, 1}]
```

Il valore nel blocco do viene inserito nel _collectable_ **per ogni valore generato** dall'_enumerable_.

```elixir
for _ <- [1, 2, 3], do: :a
# => [:a, :a, :a]
```

Il pattern matching può avvenire all'interno della comprensione, sia sul lato sinistro di `<-` sia su una riga a sé stante.

```elixir
for {atom, str} <- [a: "string"], do: str
# => ["string"]

for pair <- [a: "string"],
    {atom, str} = pair do
  str
end

# => ["string"]
```
