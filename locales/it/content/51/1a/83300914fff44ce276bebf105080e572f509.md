# Nozioni di base su match

L'espressione `match` consente di confrontare facilmente un valore con una serie di pattern e poi eseguire il codice in base al pattern corrispondente.
Valori letterali, nomi di variabili, wildcard e molte altre cose costituiscono un pattern.

```rust
#[derive(Drop)]
enum Color {
    Red,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red => println!("The color is Red"),
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Yellow;
    print_color_type(color); // prints "The color is Yellow"
}
```

Per gestire più righe di codice, il ramo `match` deve essere racchiuso tra parentesi graffe (`{}`):

```rust
fn specified_color(color: Color) -> felt252 {
    let mut response: felt252 = '';

    match color {
        Color::Red => {
            response = 'You passed in Red';
        },
        Color::Yellow => {
            response = 'You passed in Yellow';
        },
        Color::Green => {
            response = 'You passed in Green';
        },
    }

    response
}
```

L'espressione `match` ha anche la caratteristica di associare i valori che corrispondono al pattern.
Questo rende possibile estrarre il valore associato di una variante di un enum.

```rust
#[derive(Drop, Debug)]
enum ColorType {
    Light,
    Dark,
}

#[derive(Drop)]
enum Color {
    Red: ColorType,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red(state) => {
            println!("The color is Red");
            println!("The Color Type is {:?}", state);
        },
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Red(ColorType::Dark);
    print_color_type(color);
}
```

Estendendo la variante `Red` dell'enum `Color` per avere un enum associato.
Con l'aiuto dell'espressione `match`, possiamo estrarre il valore associato; `state`.
Questo è semplicemente un nome di variabile che può essere usato in seguito nel ramo del codice.

## Corrispondenza con il tipo enum `Option`

Anche l'enum `Option` predefinito può essere gestito con l'espressione `match`.

Progettiamo una funzione che accetta un parametro `Option<u8>`.
Se il parametro fornito contiene un valore, aggiungi uno a questo valore; altrimenti la funzione deve restituire il valore `None` senza eseguire alcuna operazione.

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
        Option::None => Option::None,
    }
}

fn main() {
    let three: Option<u8> = Option::Some(3);
    let four: Option<u8> = add_one(three);
    let none = add_one(Option::None);

    println!("{three:?}"); // prints "Option::Some(3)"
    println!("{four:?}"); // prints "Option::Some(4)"
    println!("{none:?}"); // prints "Option::None(())"
}
```

> Nota: `{:?}` è una sintassi di formattazione speciale che permette di stampare una forma di debug del parametro passato alla macro `println!`.
> Puoi trovare maggiori informazioni a riguardo in [The Cairo Book][debugging].

Uno dei vantaggi dell'uso del controllo di flusso `match` è la sua natura esaustiva: i pattern dei rami devono coprire _tutte_ le possibilità.
Considera la versione dell'esempio precedente che non gestisce il caso `None`:

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
    }
     // this code does not compile, as we forgot to handle the `None` case
}
```

## Pattern universale con la wildcard `_`

Usando gli enum, possiamo anche eseguire azioni speciali per alcuni valori particolari, ma per tutti gli altri valori eseguire un'azione predefinita aggiungendo un nuovo ramo con `_` come pattern per l'ultimo ramo dell'espressione `match`.
Il pattern `_` è un pattern speciale che corrisponde a qualsiasi valore e non lo associa.

La funzione `is_red` riceve un parametro e restituisce `true` se il colore è `Red` e `false` per qualsiasi altro colore:

```rust
fn is_red(color: Color) -> bool {
    match color {
        Color::Red => true,
        _ => false,
    }
}
```

## Pattern matching con l'operatore `|`

Il costrutto di controllo di flusso `match` di Cairo permette di confrontare un valore con più pattern usando l'operatore `|` (_oppure_).
Questo aiuta a semplificare il codice.

Ad esempio, usando l'enum `Color`, vogliamo scrivere una funzione che restituisce `true` per i colori `Red` o `Green` e `false` per gli altri colori:

```rust
fn is_red_or_green(color: Color) -> bool {
    match color {
        Color::Red | Color::Green => true,
        _ => false,
    }
}
```

## Pattern matching con `felt252` e variabili intere

È possibile confrontare `felt252` e variabili intere con un insieme di valori.
Tuttavia, ci sono alcune limitazioni;

- Sono supportati solo gli interi che rientrano in un singolo `felt252` (ad esempio `u256` non è supportato).
- 0 deve essere il primo ramo.
- Ogni ramo deve seguire un segmento sequenziale, in modo contiguo agli altri rami.

Implementiamo un gioco di lancio di un dado a sei facce.
Quando lanciamo il dado, otteniamo un numero tra 0 e 5.
Se il lancio dà 0, 1 o 2, vinci.
Lanci di nuovo se ottieni 3.
Perdi per altri valori:

```rust
fn toss(value: u8) {
    match value {
        0 | 1 | 2 => println!("you won!"),
        3 => println!("you can roll again!"),
        _ => println!("you lost...")
    }
}

fn main() {
    toss(2); // prints "you won!".
    toss(3); // prints "you can roll again!".
    toss(5); // prints "you lost...".
}
```

## Pattern matching con le tuple

Anche le tuple possono essere confrontate con un insieme di pattern.
Questi pattern sono progettati in modo simile a una tupla.

```rust
#[derive(Drop)]
enum DayType {
    Week,
    Weekend,
    Holiday
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn vending_machine_accept(c: (DayType, Coin)) -> bool {
    match c {
        (DayType::Week, _) => true, // accepts all coins during week day
        (_, Coin::Dime) | (_, Coin::Quarter) => true, // accepts only Dime or Quarter coin for all specified days
        (_, _) => false, // returns false for other instances
    }
}
```

Nell'ultimo ramo del `match`, non importa se usiamo `(_, _)` o solo la wildcard `_` per trovare una corrispondenza con qualsiasi combinazione di giorno e colore, perché sono funzionalmente equivalenti.
