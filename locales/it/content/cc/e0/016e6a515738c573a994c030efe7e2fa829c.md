# Informazioni

Gli `struct` di C# sono strettamente legati alle `class`.
Hanno stato e comportamento.
Possono avere gli stessi tipi di membri: costruttori, metodi, campi, proprietà e così via.

I campi e le proprietà possono essere di tipi semplici, `struct` o tipi di riferimento.
Gli `struct` seguono le stesse regole delle `class` per quanto riguarda lo scope, le regole di lettura e scrittura e i livelli di accesso.

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

Una delle cose principali da ricordare è che quando uno struct viene assegnato a una variabile o passato come parametro, i valori vengono copiati: le modifiche alla variabile originale non avranno effetto su quella copiata, e viceversa.
In sintesi, gli `struct` sono **tipi di valore**.

Questo [articolo][class-or-struct] illustra le differenze tra `struct` e `class`.
Dall'articolo vedrai che gli `struct` tendono a essere leggeri e [immutabili][structs-immutable], anche se questa indicazione non è imposta (per impostazione predefinita) dal compilatore o dal runtime.

Ci sono un paio di cose che incontrerai (e su cui il compilatore ti richiamerà l'attenzione):

1. I membri di uno `struct` non possono essere inizializzati inline.
2. Uno `struct` non può essere ereditato
3. Uno `struct` ha sempre un costruttore predefinito, anche se ne viene fornito uno non predefinito, e non puoi fornire un costruttore senza parametri esplicito.

Per via dei punti 1 e 3 appena visti, chi sviluppa uno `struct` non ha alcun modo di impedire che vengano create istanze non valide.

## Struct comuni

Dalla documentazione vedrai che esiste uno stretto rapporto tra i tipi primitivi e gli struct.
Guarda [`Int32/int`][int32] per un esempio.
Un esempio più convenzionale di `struct` è il tipo [`TimeSpan`][time-span].

Le istanze di `TimeSpan` si comportano più o meno come i numeri, con operatori di confronto come `>` e `<` e operatori aritmetici.
Puoi implementare questi operatori per i tuoi `struct` quando ne hai bisogno.

Una cosa da notare di `TimeSpan` è che implementa diverse interfacce, ad esempio `IComparable<TimeSpan>`.
Anche se gli `struct` non possono derivare da altri `struct`, possono implementare interfacce.

## Uguaglianza

Il test di uguaglianza per gli `struct` può spesso essere molto più semplice di quello per le `class`, perché per impostazione predefinita confronta semplicemente i campi.
Non è necessario eseguire l'override di `object.Equals()` (o di `GetHashCode()`).
Ricorda che se ti affidi a `Object.GetHashCode()` devi comunque assicurarti che i campi coinvolti nella generazione del codice hash (cioè tutti i campi) non cambino mentre una collezione basata su hash è in uso.
In pratica, questo significa che gli struct usati in questo modo dovrebbero essere immutabili.

A differenza del metodo `Equals()`, non esiste un'implementazione predefinita degli operatori di uguaglianza `==` e `!=`.
Se il tuo `struct` ne ha bisogno, dovrai implementarli.

D'altra parte, questo [articolo][equality] descrive come sia possibile ottimizzare le prestazioni creando metodi `Equals()` e `GetHashCode()` personalizzati, come si fa spesso con le `class`.
Nel caso di questo esercizio la differenza è stata di circa il 20% in un confronto non molto rigoroso, ma potrebbe essere una stima per difetto, perché tutti i campi sono dello stesso tipo: vedi più avanti.

Ci sono discussioni sul [web][equality-performance] riguardo ai miglioramenti di velocità quando il metodo `Equals()` non viene sovrascritto, se tutti i campi sono dello stesso tipo.
In questo esercizio, includendo campi di tipo diverso, la differenza è stata di circa il 60%.
Questo non è menzionato nella documentazione di Microsoft, il che lo rende un dettaglio implementativo non documentato, da sfruttare con giudizio.

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
