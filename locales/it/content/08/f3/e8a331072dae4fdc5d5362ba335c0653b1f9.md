# Test

Esegui i test con:

```bash
$ wrenc exercise-name.spec.wren
```

Ad esempio per `hello-world`:

```bash
$ wrenc hello-world.spec.wren
```


## Capire i test saltati

Il metodo `skip` indica alla suite di test di non eseguire un particolare test.

- Perché vengono saltati?

Per permettere agli utenti di concentrarsi su un test alla volta e di attivarli man mano che la soluzione evolve.

- Come attivarli?

Un test saltato:

```js
// this test will be skipped and not run
skip.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

Basta cambiare `skip.test` in `do.test`.

```js
// now the test will be run normally
do.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

## Creare il tuo primo modulo Wren

I test di questo percorso caricano l'implementazione importandola come modulo Wren:
`import "./bob" for Bob`. Non c'è una sintassi speciale per esportare
l'implementazione. Basta chiamare la classe `Bob` in modo che corrisponda alle
istruzioni di import `for Bob` e tutto dovrebbe funzionare.

```javascript
class Bob {
  static hey(message) {
    // Your solution to the exercise goes here
  }
}
```

Puoi trovare maggiori informazioni sui moduli nella
[documentazione sulla modularità di Wren][modularity].
Per rendere più semplice iniziare, nella directory di ogni esercizio c'è un file
Wren _scheletro_.

[modularity]: https://wren.io/modularity.html
