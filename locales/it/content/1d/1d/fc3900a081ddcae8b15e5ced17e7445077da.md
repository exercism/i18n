# Informazioni

Preparare un valore per la trasmissione significa tre cose allo stesso tempo: serializzarlo, sceglierne la parte giusta e non copiare quando non serve. Tre idiomi di Factor coprono questi aspetti.

## `unparse`: dal valore al codice sorgente

[`unparse`][unparse] (in `prettyprint`) restituisce la forma sorgente testuale di qualsiasi valore. È l'inverso del parser: il percorso di andata e ritorno `dup unparse parse` ricostruisce il valore.

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

A differenza di `>string` (che funziona solo sulle sequenze di caratteri) e di `number>string` (solo sui numeri), `unparse` è quello universale, al prezzo di produrre sintassi Factor (le stringhe tra virgolette mantengono le virgolette). È quindi lo strumento giusto quando chi riceve il testo lo analizzerà di nuovo, e quello sbagliato per un output leggibile da una persona.

## Le slice: viste, non copie

| parola        | effetto                                        |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`: copia i primi n          |
| `head-slice`  | `( seq n -- slice )`: vista dei primi n         |
| `tail`        | `( seq n -- newseq )`: copia dall'indice n in poi |
| `tail-slice`  | `( seq n -- slice )`: vista dall'indice n in poi |
| `head*`       | `( seq n -- newseq )`: copia tutto tranne gli ultimi n |
| `head-slice*` | `( seq n -- slice )`: vista di tutto tranne gli ultimi n |
| `tail*`       | `( seq n -- newseq )`: copia gli ultimi n       |
| `tail-slice*` | `( seq n -- slice )`: vista degli ultimi n      |

Una `slice` è una tupla che contiene un indice di partenza, un indice di arrivo e la sequenza sottostante: implementa il [protocollo delle sequenze][sequence-protocol], quindi qualsiasi operazione sulle sequenze funziona su di essa. Ricorri alle varianti slice quando altrimenti dovresti allocare solo per leggere; ricorri a quelle che copiano quando devi conservare i dati anche se la sequenza sottostante potrebbe cambiare.

## Cleave a più input: `2bi`, `3bi`, `2tri`, `3tri`

Le parole cleave semplici `bi` e `tri` applicano due o tre quotation a *un solo* input sullo stack. Le varianti con il prefisso `2` e `3` applicano ogni quotation a *due* o *tre* input:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

Ogni quotation riceve *tutti* gli input. Usa quindi `2bi` quando entrambe le proiezioni dipendono dalla coppia, non quando vuoi applicare la stessa proiezione a ciascun input separatamente (quello è `bi@`).

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

Per *una* sola quotation applicata a ciascun input separatamente, usa invece `bi@` (due input) o `tri@` (tre input): stessa famiglia, forma diversa.
