# Informazioni

In C#, una gerarchia di _classi_ può essere definita usando l'_ereditarietà_, che permette a una classe derivata (`Car`) di ereditare il comportamento e i dati della sua classe padre (`Vehicle`). Se non viene specificato alcun genitore, la classe eredita dalla classe `object`.

Le classi padre possono fornire funzionalità alle classi derivate in tre modi:

- Definire un metodo normale.
- Definire un metodo [`virtual`][virtual-keyword], che è come un metodo normale ma che le classi derivate _possono_ modificare.
- Definire un metodo [`abstract`][abstract-keyword], cioè un metodo senza implementazione che le classi derivate _devono_ implementare. Una classe con metodi `abstract` deve essere contrassegnata a sua volta come [`abstract`][abstract-classes]. Le classi astratte non possono essere istanziate.

Il [modificatore di accesso `protected`][protected-keyword] permette di accedere a un membro della classe padre all'interno di una classe derivata, ma blocca l'accesso dalle altre classi. Le classi derivate possono quindi accedere ai membri `public` e `protected` della classe padre, ma non ai membri `private`.

Le classi derivate possono accedere ai membri della classe padre tramite la [parola chiave `base`][base-keyword].

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

Il costruttore di una classe derivata [chiamerà automaticamente il costruttore della classe padre][constructors] _prima_ di eseguire la logica del proprio costruttore. Gli argomenti possono essere passati al costruttore di una classe padre usando la [parola chiave `base`][base-keyword-constructor]. Dato che le classi astratte non possono essere istanziate, i loro costruttori possono essere resi `protected`.

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

Quando più di una classe deriva da una classe base, le due (o più) sottoclassi implementano spesso versioni diverse di un metodo della classe base. Questo è un principio molto importante chiamato [polimorfismo][polymorphism]. Ad esempio, in una variante dell'esempio precedente mostriamo come il codice che usa `Vehicle` possa cambiare comportamento a seconda del tipo di veicolo istanziato.

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

Per impedire che una classe venga ereditata, aggiungi il [modificatore `sealed`][sealed-classes]. Alcuni sviluppatori cercano di evitare di ereditare da classi concrete (come discusso in [questa domanda su SO][pro-sealed]) e il modificatore _sealed_ supporta questo approccio. D'altra parte, molti sviluppatori C# li considerano un ostacolo alla manutenzione, come discusso in alcuni dei commenti a [questa domanda][anti-sealed]. Il consiglio è di usare il modificatore sealed con moderazione, finché non avrai acquisito sicurezza nel loro uso per le tue esigenze.

Il [seguente articolo][new-vs-override] descrive `new` come alternativa al modificatore `override`. A volte è utile, magari con gerarchie di classi complicate e/o una qualche forma di conflitto tra librerie.
