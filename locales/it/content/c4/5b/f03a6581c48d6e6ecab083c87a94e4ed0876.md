# Test

Esegui i test con:

```shell
corepack pnpm test
```

Assicurati che il codice segua le buone pratiche e gli stili di codifica, come fanno gli altri utenti, con ESLint, uno strumento che esegue l'analisi statica del codice.
A volte strumenti come questo ti fanno risparmiare tempo nell'individuare errori di battitura o sviste nel codice JavaScript:

```shell
corepack pnpm lint
```

Puoi anche eseguire Jest in modalità "watch": rieseguirà i test automaticamente quando salvi le modifiche al codice o al modulo di test:

```shell
corepack pnpm watch
```

## Capire i test saltati

Il metodo skip indica alla suite di test di non eseguire un test. Questa funzione si può usare anche con gli alias: `it.skip(name, fn)` o `xit(name, fn)` o `xtest(name, fn)`

- Perché vengono saltati?

Per permettere agli utenti di concentrarsi su un test alla volta e di attivarli uno alla volta man mano che sviluppano la soluzione.

- Come attivarli?

Sostituisci `xtest` con `test`.

```javascript
test('title cased phrases', () => {
  expect(Acronyms.parse('Portable Network Graphics')).toEqual('PNG');
});
```

## Creare il tuo primo modulo JavaScript 2015

Di solito, i test di questo percorso caricano l'implementazione importandola come modulo JavaScript: `import { Bob } from './bob.js';`.
Devi solo esportare l'implementazione dal file di riferimento, `bob.js`:

```javascript
export function hey(message) {}
```

Puoi trovare maggiori informazioni sui moduli nella [documentazione di Babel](https://babeljs.io/docs/learn-es2015/#modules).
Per facilitare l'avvio, nella directory c'è un file JavaScript _skeleton_.
