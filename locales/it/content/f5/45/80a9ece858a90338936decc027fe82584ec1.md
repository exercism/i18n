# Classi generiche

```sather
class LOST_BOX{T} is
   attr item : T;
   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;
end;
```

## Che cos'è il parametro

`T` rappresenta un tipo che viene fornito al momento dell'uso. Sather costruisce
una classe distinta per ogni combinazione effettivamente usata, quando il
programma viene compilato. Quindi:

- `LOST_BOX{STR}` e `LOST_BOX{INT}` sono tipi non correlati tra loro;
- non c'è alcun controllo a tempo di esecuzione, nessun boxing e nessuna conversione;
- un errore nella classe si manifesta per ogni tipo con cui viene usata.

È lo stesso approccio dei template del C++ o dei generici di Rust, e diverso dai
generici di Java, dove il tipo viene cancellato e tutto è in realtà un oggetto.

## Parametri vincolati

Un `T` senza vincoli può essere assegnato, passato e restituito: nient'altro,
perché di lui non si sa nient'altro. Per chiamare delle routine su di esso,
specifica a che cosa deve conformarsi:

```sather
class LOST_BOX{T < $STR} is
   describe : STR is return "a box holding " + item.str; end;
end;
```

`T < $STR` richiede che `T` si conformi a `$STR` e, in cambio, permette di
chiamare `item.str`. Un vincolo è il modo per permettere tutto ciò che un `T`
senza vincoli non può fare.

Senza il vincolo, `item.str` non verrà compilato, e il messaggio indicherà la
riga all'interno della classe generica, non la riga che l'ha usata.

## Routine generiche?

Non ce ne sono. Solo le classi accettano parametri. Una routine che deve
funzionare con più tipi o vive in una classe generica, oppure accetta un tipo
astratto come `$STR`.

## Scegliere tra le due

| | classe generica | classe astratta |
| --- | --- | --- |
| stabilito | al momento della compilazione | al momento dell'esecuzione |
| contiene | un tipo per ogni istanziazione | qualsiasi tipo conforme |
| costo | nessuno | un dispatch |

`ARRAY{$ACT}` usa entrambe le cose: generica nel tipo degli elementi, astratta
in ciò che quell'elemento può essere.

Ricorri a una classe generica quando il tipo è lo stesso dall'inizio alla fine e
chi usa la classe lo sa. Ricorri a una classe astratta quando più tipi devono
coesistere in un'unica collezione.
