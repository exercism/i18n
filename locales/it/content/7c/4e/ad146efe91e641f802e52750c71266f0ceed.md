# Per i manutentori

## Generare i test: `bin/generate_tests.py`

I file di test vengono generati a partire dai dati canonici di
[exercism/problem-specifications](https://github.com/exercism/problem-specifications)
usando un template Jinja salvato in ogni esercizio in `.meta/template.j2`.

```bash
bin/generate_tests.py bob            # regenerate one exercise
bin/generate_tests.py                # regenerate every exercise that has a template
bin/generate_tests.py --no-pull bob  # skip `git pull` of problem-specifications
```

Lo script legge problem-specifications dalla cache di configlet
(`~/.cache/exercism/configlet/problem-specifications`, popolata da `bin/configlet sync`),
oppure da una directory padre chiamata `problem-specifications`.
Vengono generati solo i casi inclusi in `.meta/tests.toml`.

I letterali stringa di Fortran non possono contenere sequenze di escape come `\n` e `\t`.
Il filtro del template `escape_quote_whitespace` le riscrive come
`" // NEWLINE // "`, `" // TAB // "` e `" // CARRIAGE_RETURN // "`,
quindi il template deve dichiarare quelle costanti (vedi `exercises/practice/bob/.meta/template.j2`).

### Prerequisiti

- CMake e un compilatore Fortran funzionanti
- Python 3.12+ con `jinja2`
- git

### Flusso di lavoro per aggiungere un nuovo esercizio

Prendiamo `bob` come esempio:

- Crea un nuovo branch, ad esempio `git checkout -b exercise-bob`
- Esegui `bin/add-exercise bob` (servono `jq` e `curl`). Lo script:
  - scarica configlet ed esegue `configlet create`, che aggiunge l'esercizio a `config.json` e sincronizza la sua documentazione, i metadati e `tests.toml` da problem-specifications
  - ordina `config.json` con `bin/reorder-exercises`
  - copia `exercises/shared/CMakeLists.txt` nella directory dell'esercizio
  - scrive una soluzione stub, un `.meta/example.f90` stub e un `.meta/template.j2` iniziale (a partire da `exercises/shared/template.j2`)

  Ti chiede il tuo nome utente GitHub a meno che tu non passi `-a <username>`, e imposta la difficoltà a 1 a meno che tu non passi `-d <difficulty>`.

- Modifica `.meta/template.j2` in modo che ogni caso chiami la funzione giusta con gli input giusti, poi genera i test:

  ```bash
  bin/generate_tests.py bob
  ```

- Scrivi una soluzione funzionante in `.meta/example.f90`. Sostituisci il file dello studente (ad esempio `bob.f90`) con uno scheletro delle funzioni o subroutine che i test chiamano, per aiutare lo studente a iniziare
- Assicurati che tutti i test passino, eseguendo la build completa dalla radice del repository:

  ```bash
  mkdir -p build && cd build
  cmake ..
  cmake --build .
  ctest -V -R bob
  ```

- Esegui `bin/reorder-exercises` e `bin/configlet lint`
- Se tutto passa, apri una pull request con le modifiche

### Modificare `CMakeLists.txt`

Quando modifichi il file cmake, aggiorna la copia principale in `exercises/shared/` e usa `bin/update-cmake-files` per copiarla in tutte le directory degli esercizi.
