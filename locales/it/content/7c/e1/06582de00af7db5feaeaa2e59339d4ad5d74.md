# Introduzione

Sebbene le espressioni `if/else` permettano di eseguire logica condizionale, Haskell offre anche un modo più potente per farlo: il [pattern matching][pattern-matching].
Con il pattern matching, un valore può essere verificato rispetto a uno o più _pattern_.
Un esempio di pattern è il _pattern costante_, che confronta un valore con una costante (ad esempio `1` o `"hello"`).

Quando definisci una funzione, puoi definire corpi separati per pattern diversi.
Il risultato è codice pulito, semplice e leggibile.
Puoi fare pattern matching su qualsiasi tipo di dato: numeri, caratteri, liste, tuple e così via.

Ad esempio, una funzione semplice che prende un numero intero (`Int`) e lo avvicina di _1_ a _0_ si potrebbe esprimere così:

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero 1 = 0
```

Il pattern matching dà il meglio di sé quando viene usato insieme ad altri pattern, per esempio il _pattern variabile_:

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero n = n - 1
```

L'esempio qui sopra tratta allo stesso modo tutti gli input diversi da _0_ e produrrebbe risultati sbagliati per i numeri negativi.
Il problema si può risolvere con i pattern condizionali, noti come _guards_, che si esprimono con il simbolo `|`:

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
```

Negli esempi precedenti non tutti gli input possibili hanno un pattern corrispondente.
Il compilatore se ne accorgerà e produrrà un avviso.
Questa è una funzionalità molto utile di Haskell: aiuta a garantire che tutti i percorsi possibili siano coperti, per evitare errori a run-time.
È nota come _verifica di esaustività_.
Per risolvere l'avviso, devi gestire tutti i casi.
All'interno delle _guards_ puoi usare l'espressione `otherwise` come zucchero sintattico per `True`, in modo da coprire tutti i pattern rimanenti.

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
    | otherwise = 0
```

Il pattern matching verifica un valore rispetto a ogni pattern, dall'alto verso il basso, finché non trova un pattern corrispondente ed esegue la logica associata a quel pattern.
**L'ordine dei pattern è importante!**
