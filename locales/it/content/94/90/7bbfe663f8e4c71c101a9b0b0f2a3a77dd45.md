# Costruire il test runner

Il test runner è uno strumento essenziale che permette:

- al sito web di verificare automaticamente se un'iterazione supera tutti i test;
- agli studenti di risolvere gli esercizi usando l'[editor nel browser](/docs/using/solving-exercises/using-the-online-editor) ([non serve la CLI](/docs/using/solving-exercises/working-locally)).

Per iniziare a costruire un test runner, dai un'occhiata al documento [Creare un test runner da zero](/docs/building/tooling/test-runners/creating-from-scratch).

## Implementazione

Gli strumenti di un track sono di solito (per la maggior parte) scritti nel linguaggio del track.

```exercism/caution
Sei libero di usare altri linguaggi, ma ogni linguaggio aggiuntivo renderà più difficile mantenere il track o contribuire ad esso.
Per questo consigliamo di usare il linguaggio del track quando è possibile: rende più facile mantenerlo e contribuire.
```

## Rilascio

Il test runner viene impacchettato ed eseguito come [container Docker](/docs/building/tooling/docker).
Le immagini Docker del test runner vengono rilasciate automaticamente usando un [workflow di GitHub Actions](https://github.com/exercism/generic-test-runner/blob/main/.github/workflows/docker.yml).

## Test

Dopo aver costruito un test runner, puoi usarne l'immagine Docker nella configurazione CI del tuo track per verificare gli esercizi del track.
Il vantaggio principale di questo approccio è che imita meglio la configurazione di produzione: in altre parole, puoi avere più fiducia che le cose funzionino anche in produzione.
Un possibile svantaggio è che potrebbe rallentare il workflow della CI.
Sta a te, in quanto manutentore, decidere quale approccio funziona meglio per il tuo track.
