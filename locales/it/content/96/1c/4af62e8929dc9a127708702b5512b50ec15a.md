# Introduzione

## Variabili

Elixir è un linguaggio a tipizzazione dinamica: il tipo di una variabile viene controllato solo a runtime. Con l'operatore di corrispondenza `=` possiamo associare a un nome di variabile un valore di qualsiasi tipo:

```elixir
# Bound an integer value of 1
count = 1
# You may re-bind variables
count = 2

# You may re-bind any type to a variable
count = false

# Strings can be created by enclosing characters within double quotes
message = "Success!"
```

## Moduli

Elixir è un [linguaggio di programmazione funzionale][functional-programming] e richiede che tutte le funzioni con nome siano definite all'interno di un _modulo_. La parola chiave `defmodule` serve a definire un modulo. Tutti i moduli sono disponibili per gli altri moduli a runtime e non richiedono un _modificatore di accesso_ per essere visibili alle altre parti del programma. Un _modulo_ è analogo a una _classe_ in altri linguaggi di programmazione.

```elixir
defmodule Calculator do
  # ...
end
```

## Funzioni con nome

Le _funzioni con nome_ devono essere definite all'interno di un modulo. La parola chiave `def` serve a definire una funzione con nome _pubblica_.

Ogni funzione può avere zero o più argomenti. Il valore dell'ultima espressione di una funzione viene sempre _restituito implicitamente_.

```elixir
defmodule Calculator do
  def add(x, y) do
    x + y
  end
end
```

Per chiamare una funzione si specificano il modulo e il nome della funzione e si passa un valore per ciascuno dei suoi argomenti.

```elixir
sum = Calculator.add(1, 2)
# => 3
```

Al posto di `def` si può usare la parola chiave `defp` per definire una funzione _privata_. Le funzioni private si possono usare solo dall'interno dello stesso modulo che le ha definite.

Quando si chiama una funzione all'interno dello stesso modulo in cui è definita, si può omettere il nome del modulo.

Puoi anche scrivere funzioni brevi usando una sintassi su una sola riga (nota la virgola `,` e i due punti `:` intorno alla parola chiave `do`).

```elixir
defmodule Calculator do
  def subtract(x, y) do
    private_subtract(x, y)
  end

  defp private_subtract(x, y), do: x - y
end

difference = Calculator.subtract(7, 2)
# => 5

difference = Calculator.private_subtract(7, 2)
# => ** (UndefinedFunctionError) function Calculator.private_subtract/2 is undefined or private
#       Calculator.private_subtract(7, 2)
```

## Arità delle funzioni

È comune riferirsi alle funzioni indicandone l'_arità_. L'_arità_ di una funzione è il numero di argomenti che accetta.

```elixir
# add/3 because this function has three arguments, thus an arity of 3
def add(x, y, z) do
  x + y + z
end
```

## Convenzioni di denominazione

I nomi dei moduli dovrebbero usare il `PascalCase`. Il nome di un modulo deve iniziare con una lettera maiuscola `A-Z` e può contenere lettere `a-zA-Z`, numeri `0-9` e underscore `_`.

I nomi delle variabili e delle funzioni dovrebbero usare lo `snake_case`. Il nome di una variabile o di una funzione deve iniziare con una lettera minuscola `a-z` o con un underscore `_`, può contenere lettere `a-zA-Z`, numeri `0-9` e underscore `_`, e può terminare con un punto interrogativo `?` o un punto esclamativo `!`.

## Libreria standard

Elixir ha una libreria standard molto ricca e ben documentata. La documentazione è disponibile online su [hexdocs.pm/elixir][docs]. Salva questo link da qualche parte: ti servirà spesso!

La maggior parte dei tipi di dati predefiniti ha un modulo corrispondente che offre funzioni per lavorare con quel tipo di dati. Ad esempio, esiste il modulo `Integer` per gli interi, il modulo `String` per le stringhe, il modulo `List` per gli array e così via.

Un modulo degno di nota è il modulo `Kernel`. Fornisce le funzionalità di base su cui è costruito il resto della libreria standard, come gli operatori aritmetici, le macro di controllo del flusso e molto altro. Le funzioni del modulo `Kernel` vengono importate automaticamente, quindi puoi usarle senza il prefisso `Kernel.`.

## Commenti nel codice

I commenti si possono usare per lasciare delle note ad altri sviluppatori che leggono il codice sorgente. In Elixir, i commenti su una sola riga sono preceduti da `#`.
