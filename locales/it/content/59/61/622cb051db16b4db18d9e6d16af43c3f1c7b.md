# Approfondimento

Nei concetti precedenti abbiamo visto che in Julia i tipi formano una gerarchia, con `Any` in cima.

I tipi astratti come `Number` hanno sottotipi, ma non possono a loro volta essere istanziati.
Assegnare a una variabile un tipo astratto _vincola_ i valori della variabile a essere un qualsiasi sottotipo del tipo astratto.
Per esempio:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Questo ci offre un primo tipo di flessibilità nel vincolare quali input sono validi.

Supponiamo però di volere che una variabile accetti sia valori interi sia stringhe?
Questi tipi non si trovano nello stesso ramo della gerarchia.

Potremmo impostare il tipo su [`Any`][any], o lasciare che sia quello predefinito, ma così perderemmo ogni controllo sui tipi ammessi.

Per un approccio migliore, abbiamo la sintassi [`Union{ }`][union], con due o più tipi elencati all'interno delle parentesi graffe.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Un altro esempio usa la stessa unione di tipi nella firma di una funzione:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

Qui abbiamo dato un nome al tipo, cosa che può offrire una scorciatoia comoda ma non è strettamente necessaria.
La funzione `g(z::Union{Integer, String}) = z^3` si comporta allo stesso modo.

Ci sarà molto altro da dire sulle firme delle funzioni nel concetto Multiple Dispatch.

## Unioni con nothing

Diversi altri linguaggi hanno tipi che possono contenere o meno un valore, con nomi come `Option`, `Nullable` o `Maybe`.

Julia non ha una sintassi specifica per questo, ma le unioni di tipi sono una generalizzazione della stessa idea.

Nel concetto [`Nothingness`][nothingness] abbiamo visto che Julia ha vari modi per rappresentare i non-valori, tra cui [`nothing`][nothing] e [`missing`][missing].
Ognuno di questi può essere incluso in un'unione di tipi.

Per esempio, nel definire una sorta di [lista concatenata][linked], ci serve un modo per terminare la lista quando non ci sono altri nodi.
`Nothing` è il tipo con il valore singleton `nothing`, e questa definizione di Node permette di segnalare la fine della catena:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

Allo stesso modo, `missing` può essere usato come segnaposto per valori assenti, soprattutto in collezioni come i vettori.
L'esempio qui sotto è molto artificioso, ma i valori mancanti sono comuni nei set di dati del mondo reale.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
