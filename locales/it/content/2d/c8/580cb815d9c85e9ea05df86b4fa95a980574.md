# Informazioni sulle basi

Kotlin è un linguaggio a tipizzazione statica, progettato per essere completamente interoperabile con Java.

Rispetto a Java, Kotlin:

- ha una sintassi più pulita e più concisa;
- integra molte funzionalità dei linguaggi funzionali;
- ha un ampio supporto per i valori nullable.

## Variabili

Poiché Kotlin è a tipizzazione statica, è necessario _conoscere_ il tipo di ogni valore in fase di compilazione.

Tuttavia, l'[inferenza di tipo][inference] di Kotlin è molto potente, quindi _specificare_ il tipo è spesso facoltativo.

Ci sono due modi per dichiarare una variabile.

1. `val` crea una variabile immutabile, e provare a modificarla è un errore in fase di compilazione.

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. `var` crea una variabile mutabile.

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

Poiché le variabili immutabili eliminano una classe comune di bug, l'uso di `val` è incoraggiato ogni volta che è possibile.

Inoltre, neanche una `var` può cambiare tipo:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

Per ridurre la distrazione visiva, in questo percorso i tipi espliciti saranno per lo più omessi. Ciononostante, è consigliabile specificare i tipi almeno per:

- le API pubbliche
- le firme delle funzioni
- dove serve documentazione

Alcune aziende e organizzazioni richiedono una rigorosa sicurezza dei tipi e vietano l'inferenza di tipo, mentre altre la limitano ai tipi «semplici», oppure abbracciano pienamente l'inferenza di tipo.

```kotlin
val x: Int = 42  // => 42
```

In generale, i nomi delle variabili e delle funzioni dovrebbero essere in `camelCase`, non in `snake_case`.

## Funzioni

Dichiara una funzione con la parola chiave `fun`. A differenza di Java, le funzioni non devono necessariamente far parte di una classe.

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

Alcuni punti da notare:

- Le parentesi tonde (`()`) sono necessarie dopo il nome della funzione, anche se la funzione non accetta argomenti.
- Gli argomenti delle funzioni devono specificare il tipo: non c'è inferenza di tipo (a differenza delle variabili).
- Il corpo della funzione è racchiuso tra parentesi graffe (`{ }`) (ma vedi sotto).
- La parola chiave `return` è necessaria, se si restituisce un valore.
- I punti e virgola `;` alla fine delle righe sono facoltativi, e di solito vengono omessi.
- Gli operatori aritmetici `+`, `-`, `*`, `/` sono simili a quelli della maggior parte dei linguaggi più diffusi.

Tuttavia, per queste funzioni molto semplici, «a espressione singola», esiste una sintassi abbreviata:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
Le funzioni possono avere parametri con valori predefiniti. 
Questi valori vengono usati se vengono omessi nel punto in cui la funzione viene chiamata:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

Le funzioni su Exercism di solito restituiscono un valore (per come è strutturato il test runner).
Per usare Kotlin in modo più ampio, può essere utile sapere che una funzione che non restituisce alcun valore può omettere il tipo restituito e la parola chiave return.

In quel caso si dice che ha un tipo restituito `Unit`: equivalente a `void` in Java e in diversi altri linguaggi.

## Commenti

I commenti su una sola riga iniziano con `//`, e il resto della riga viene poi ignorato.

I commenti su più righe iniziano con `/*` e finiscono con `*/`.

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

Questo è uguale a Java.
