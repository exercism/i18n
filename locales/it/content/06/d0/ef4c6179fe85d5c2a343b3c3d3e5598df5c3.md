# Test

Un modo per risolvere gli esercizi di Exercism è accedere al sito e usare l'editor nel browser, dove puoi modificare e testare la soluzione.

In alternativa, puoi scaricare gli esercizi sul tuo computer e usare il tuo editor e una serie di strumenti per creare, testare e infine inviare la soluzione.

Per questo serve l'interfaccia a riga di comando di Exercism, o CLI, un'applicazione che viene eseguita all'interno di un terminale o di una finestra a riga di comando. Le istruzioni per l'installazione le trovi qui: [Documentazione della CLI di Exercism](https://exercism.org/docs/using/solving-exercises/working-locally).

## L'approccio ai test

Exercism dà per scontata una certa esperienza con lo sviluppo guidato dai test. Ogni esercizio è composto da uno _`stub file`_, da un _`test file`_ che contiene una serie di test già scritti e da un _`test script`_ usato per eseguire i test.

Per risolvere un esercizio, lo _`stub file`_ va sviluppato un po' alla volta, finché non contiene il codice che, alla fine, supererà tutti i test.

In pratica, questo significa che sia lo _`stub file`_ sia il _`test file`_ verranno modificati attivamente. Attenzione: il _`test file`_ non si modifica per cambiare il codice dei test, ma per trasformare in commento i test che falliscono.

All'inizio, tutti i test tranne uno saranno trasformati in commento; poi, man mano che lo _`stub file`_ si avvicina a una soluzione funzionante, altri test vengono tolti dal commento, finché non passano tutti.

## L'infrastruttura di test

Non serve installare software aggiuntivo: i componenti del framework di test sono inclusi nel download dell'esercizio.

Il framework di test comprende tre file Rexx che, al momento del test, vengono uniti alla soluzione dell'esercizio per formare l'unità di codice dei test; questa viene poi eseguita dallo _`test script`_ e i risultati dei test vengono stampati sul terminale.

Non modificare né eliminare lo _`test script`_ o qualsiasi altro file del framework di test. Se qualche diavoletto dovesse combinare questo guaio, scarica di nuovo l'esercizio tramite la CLI di Exercism, facendo attenzione a salvare il codice della soluzione.

## Eseguire i test

Per risolvere un esercizio si procede così:

1. Apri un terminale
2. Scarica l'esercizio scelto
3. Entra nella directory dell'esercizio
4. Carica lo stub file e il test file nel tuo editor
5. In modo iterativo,

    1. Esegui il test script
    2. Scrivi il codice nello stub file (trasformandolo lentamente nella soluzione) e trasforma in commento o togli dal commento i test nel test file

6. Quando tutti i test passano, invia la soluzione a Exercism
7. Chiudi il terminale
8. Festeggia il tuo successo

Un esempio concreto in un terminale Linux con l'esercizio `acronym` (supponiamo che il workspace di Exercism sia: `/home/exercism`)

Scarica l'esercizio:

`exercism download --track=rexx --exercise=acronym`

Entra nella directory dell'esercizio:

`cd /home/exercism/rexx/acronym`

Da un'altra finestra, magari con interfaccia grafica, carica nel tuo editor `acronym.rexx` e `acronym-check.rexx`, rispettivamente lo stub file e il test file.

Esegui il test script: `./test-acronym`

e tutti i test dovrebbero fallire:

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Trasforma in commento tutti i test tranne il primo nel file `acronym-check.rexx` e riesegui il test script; dovresti ottenere l'output seguente:

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

Continua a lavorare su `acronym.rexx` finché non contiene codice funzionante: alla fine, eseguendo il test script, dovresti ottenere:

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

Passa a togliere dal commento gli altri test, riesegui il test script e alla fine dovresti ottenere:

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Ora puoi inviare la soluzione dell'esercizio:

`exercism submit acronym.rexx`

e guadagnare un altro punto di reputazione. Quando hai finito, chiudi il terminale.

Per chi usa MacOS la procedura è più o meno la stessa, dato che si tratta di un sistema operativo derivato da UNIX.

Per chi usa Windows la procedura è in linea di massima simile, ma ci sono alcune piccole differenze:

- La finestra _Command Prompt_ è il terminale
- Le barre rovesciate sostituiscono le barre nei percorsi, quindi la directory di lavoro potrebbe essere:

  `cd C:\Users\MyName\exercism\rexx\acronym`

- L'esecuzione del test script avviene tramite:

  `test-acronym`  oppure  `test-acronym.bat`

L'output dei test sarà identico.
