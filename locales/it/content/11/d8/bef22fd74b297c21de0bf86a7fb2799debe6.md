# Istruzioni

Sei l'ufficiale di guardia a bordo di un cutter in transito nello
Stretto di Bering. Tre fonti segnalano la posizione di ogni banco di
ghiaccio e di ogni promontorio in vista:

- Il **tavolo nautico** parla in direzioni della bussola:
  `north`, `east`, `south`, `west`. Solo una direzione, nessuna
  distanza.
- Il **navigatore** parla in coordinate *polari* a partire
  dall'ultimo punto stimato del cutter: una magnitudine in miglia
  nautiche e un rilevamento in gradi in senso orario da nord (quindi
  `0` è north, `90` è east, `180` è south, `270` è west).
- La **vedetta dell'albero** parla in coordinate *relative*: una
  distanza in avanti e uno tra `ahead`, `starboard`, `behind`,
  `port`. I rilevamenti relativi si misurano rispetto alla *rotta
  attuale della nave*: il comandante annuncia quella rotta sul ponte
  di comando prima di ogni turno di guardia.

Il tuo compito è convertire tutte e tre in un unico sistema
cartesiano `(x, y)`, così da poter tracciare i punti sulla carta. I
rilevamenti sono in gradi; `(0, 1)` è un miglio nautico verso nord,
`(1, 0)` è un miglio nautico verso est.

## 1. Il modello dei dati e il cartesiano per cardinal

Per prima cosa, disponi i pezzi condivisi da tutto l'esercizio:

- Definisci tre tuple: `cardinal` (uno slot, `direction`), `polar`
  (gli slot `magnitude` e `bearing`) e `relative` (gli slot
  `distance` e `bearing`).
- Dichiara i simboli di rotta con `SYMBOLS:`: `north`, `east`,
  `south`, `west`, `ahead`, `starboard`, `behind`, `port`.
- Dichiara una variabile dinamica `heading` con `SYMBOL:` (l'attività
  3 la usa).
- Dichiara due parole generiche:
  `GENERIC: >cartesian ( direction -- x y )` e
  `GENERIC: flip ( direction -- direction' )`. Ne aggiungerai i
  metodi nelle attività successive.

Poi aggiungi il metodo `M: cardinal` di `>cartesian`, che restituisce
il vettore unitario per la direzione indicata.

```factor
T{ cardinal { direction north } } >cartesian . .
! => 1
! => 0
! (top of stack is `y`, just below it is `x`)
```

## 2. Il cartesiano per polar

Aggiungi un metodo `M: polar` a `>cartesian` che converte la forma
polare in `(x, y)`:

```
x = magnitude * sin(bearing-in-radians)
y = magnitude * cos(bearing-in-radians)
```

```factor
T{ polar { magnitude 10 } { bearing 90 } } >cartesian . .
! => 0   (close to zero — the cosine of π/2 isn't exactly 0 in floats)
! => 10
```

## 3. Il cartesiano per relative

Aggiungi un metodo `M: relative` a `>cartesian`. Il punto delicato: un
rilevamento relativo si misura rispetto alla *rotta attuale della
nave*, che non fa parte della tupla. Leggi la variabile `heading`
(dichiarata nell'attività 1) con `heading get`, aggiungi l'offset del
rilevamento (`ahead = 0`, `starboard = 90`, `behind = 180`,
`port = 270`) e produci il punto cartesiano. Chi chiama imposta
`heading` all'interno di un blocco `with-variable`.

```factor
0 heading [
    T{ relative { distance 5 } { bearing starboard } } >cartesian
] with-variable . .
! => 0   (heading 0 is north; starboard is east; (5, 0))
! => 5
```

## 4. Flip

Aggiungi i metodi del generico `flip` (dichiarato nell'attività 1) in
modo che restituisca la direzione opposta.

- Per `cardinal`: north ↔ south, east ↔ west.
- Per `polar`: aggiungi 180° al rilevamento (modulo 360).
- Per `relative`: ahead ↔ behind, starboard ↔ port.

```factor
T{ cardinal { direction north } } flip .
! => T{ cardinal { direction south } }

T{ polar { magnitude 10 } { bearing 90 } } flip .
! => T{ polar { magnitude 10 } { bearing 270 } }

T{ relative { distance 5 } { bearing ahead } } flip .
! => T{ relative { distance 5 } { bearing behind } }
```

## 5. Sommare i rilevamenti

Definisci `add-bearings ( a b -- x y )` che converte entrambe le
direzioni in cartesiane e restituisce la loro somma. Funziona con
qualsiasi combinazione di `cardinal`, `polar` e `relative`: è il
vantaggio di usare un generico per `>cartesian`.

```factor
T{ cardinal { direction north } } T{ cardinal { direction east } } add-bearings . .
! => 1
! => 1
```
