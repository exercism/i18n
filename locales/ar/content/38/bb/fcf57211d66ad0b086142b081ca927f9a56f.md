# مقدمة

## التحميل الزائد للطرق

في Java، التحميل الزائد للطرق ميزة تسمح للصنف بأن يحتوي على أكثر من طريقة تحمل الاسم نفسه، إذا اختلفت قوائم معاملاتها.
وهو مرتبط بتعدد الأشكال في وقت الترجمة (أو الساكن).
هذا المفهوم جوهري
لإنشاء طرق تؤدي مهامًا متشابهة لكن بمدخلات مختلفة.

### لماذا نُحمّل الطرق تحميلًا زائدًا؟

التحميل الزائد للطرق يزيد من سهولة قراءة البرنامج.
يمكن إعطاء طرق مختلفة الاسم نفسه لكن
بمعاملات مختلفة.
وحسب عدد المعاملات أو أنواعها، تُستدعى الطريقة المناسبة.

### كيف نُحمّل الطرق تحميلًا زائدًا؟

مفتاح التحميل الزائد للطرق هو توقيع الطريقة.
تُعدّ الطريقتان مختلفتين إذا اختلف توقيعهما.
وهناك أسلوبان لتحميل الطرق تحميلًا زائدًا:

1. **عدد مختلف من المعاملات**: يمكن أن تحمل الطرق الاسم نفسه لكن بعدد مختلف من المعاملات.

   ```java
   public class Display {

       public void show(int x) {
           System.out.println("Show with int: " + x);
       }

       public void show(int x, int y) {
           System.out.println("Show with two ints: " + x + ", " + y);
       }
   }
   ```

2. **أنواع مختلفة من المعاملات**: يمكن أن تحمل الطرق الاسم نفسه والعدد نفسه من المعاملات لكن
   بأنواع مختلفة.

   ```java
   public class Display {

       public void show(int x) {
           System.out.println("Show with int: " + x);
       }

       public void show(String s) {
           System.out.println("Show with String: " + s);
       }
   }
   ```

### نقاط يجب تذكّرها

- الطرق المُحمّلة يجب أن تغيّر قائمة الوسائط.
- الطرق المُحمّلة يمكنها أيضًا تغيير نوع الإرجاع، لكن مجرد تغيير نوع الإرجاع لا يُعدّ تحميلًا
  زائدًا للطرق.
- يمكن تحميل الطرق تحميلًا زائدًا في الصنف نفسه أو في صنف فرعي.

في هذا المفهوم، سنستكشف أمثلة وفروقًا دقيقة متعددة للتحميل الزائد للطرق في Java.
