# الاختبارات

يأتي كل تمرين مع مجموعة من اختبارات الوحدة وكل ما تحتاجه لبنائها وتشغيلها.
وأنت تقدّم التنفيذ.

## تشغيل الاختبارات

افتح نافذة طرفية في مجلد التمرين، ثم شغّل:

```
make
```

هذا الأمر يترجم حلّك والاختبارات، ثم يشغّل الاختبارات.
شغّله مرة أخرى في كل مرة تغيّر فيها حلّك.

إذا كانت لديك [واجهة سطر الأوامر الخاصة بـ Exercism](https://exercism.org/docs/using/solving-exercises/working-locally)، فيمكنك استخدام هذا الأمر بدلًا من ذلك، وهو يشغّل `make` أيضًا:

```
exercism test
```

لإزالة الملفات التي ينشئها البناء، شغّل `make clean`.

### بدون أداة `make`

إذا لم تكن لديك أداة `make` (على ويندوز، على سبيل المثال)، فيمكنك ترجمة الاختبارات وتشغيلها مباشرة.
بالنسبة لتمرين «Bob»:

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

ثم شغّل الاختبارات على لينكس أو ماك:

```
./run_tests
```

أو على ويندوز:

```
.\run_tests
```

## العمل على تمرين

سُمّيت ملفات كل تمرين باسمه.
بالنسبة لتمرين «Bob»:

| الملف | المحتويات |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90` | نسخة أولية من الحل، جاهزة لتُكملها |
| `bob_test.f90` | الاختبارات |
| `TesterMain.f90` | مكتبة الاختبارات |
| `Makefile` | تعليمات خاصة بأمر `make` |
| `CMakeLists.txt` | تعليمات خاصة بـ [CMake](#using-cmake-instead)، وهو اختياري |

ما عليك سوى تعديل ملف الحل.

العمل على كل تمرين هو عملية تكرار هذه الخطوات حتى تنجح كل الاختبارات:

- أصلح أي أخطاء ترجمة، ثم شغّل الاختبارات لترى أيها يفشل.
- نفّذ القدر الكافي فقط ليجتاز الاختبار الفاشل التالي.
- أعد هيكلة تنفيذك لتحسين قابلية القراءة وتقليل التكرار وما إلى ذلك.
- شغّل الاختبارات مرة أخرى وانتقل إلى الاختبار الفاشل التالي.

تُطبع رسالة لكل اختبار فاشل، تليها خلاصة.
وإذا فشل أي اختبار، ينتهي `make` بخطأ.

يحتوي كل اختبار على تعليق يصف الاختبار، ثم يأتي الاختبار الفعلي بدءًا من `call assert_equal`، مثل:

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

لتعطيل اختبار ما، ما عليك سوى تحويله إلى تعليق بإضافة `'!'`، مثل:

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## استخدام CMake بدلًا من ذلك

لا تحتاج إلى CMake، لكنه قد يكون مفيدًا إذا كنت تعمل في بيئة تطوير متكاملة مثل Visual Studio أو Xcode، أو تستخدم مترجمًا غير GFortran.

يجب أن يحتفظ مجلد التمرين باسمه الأصلي، لأن CMake يستخدمه للعثور على الملفات المصدرية.
ابدأ من داخل مجلد التمرين:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

بعد تغيير حلّك، لا تحتاج إلا إلى الأمرين الأخيرين.

**ملاحظة:** شغّل `cmake` دائمًا من مجلد منفصل، مثل `build`.
تشغيل `cmake .` داخل مجلد التمرين يستبدل ملف `Makefile` المرفق بالتمرين.

يختار CMake مولّدًا مناسبًا لنظامك.
لاختيار مولّد آخر، استخدم الخيار `-G`، مثل `cmake -G Xcode ..`.
شغّل `cmake --help` لعرض المولّدات التي يمكنك استخدامها.
مع Visual Studio أو Xcode، شغّل الاختبارات بالأمر `ctest -V -C Debug`.

إذا لم يكن مجلد تمرينك يحتوي على ملف `Makefile`، فهو قد نُزّل قبل إضافة هذه الملفات إلى التمارين.
ويمكنك مع ذلك استخدام CMake.
