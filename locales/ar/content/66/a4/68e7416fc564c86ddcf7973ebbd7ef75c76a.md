# حول

## مقدمة

الأنواع المعتمة تقنية تغليف في Elm. ويسمّيها بعضهم أيضًا إخفاء المعلومات، أو إخفاء تفاصيل التنفيذ. وهي تُستخدم أيضًا بشكل شائع لفرض التحقق، باستخدام نمط [Parse, dont validate][parse-dont-validate]. على سبيل المثال، قد يكون لديك نوع معتم `EmailAddress` لا يمكن أن يحتوي إلا على عناوين بريد إلكتروني صالحة (على عكس `String`، الذي يمكن أن يحتوي على أي شيء).

## إنشاء نوع معتم

[الأنواع المخصصة][custom-types] لها *صيغة* واحدة أو أكثر، ويولّد المترجم تلقائيًا دالة لإنشاء كل *صيغة*، باستخدام اسم *الصيغة*. وهذه هي الطريقة الوحيدة التي يمكن بها إنشاء الأنواع المخصصة. ويسمح المترجم أيضًا بالتفكيك لهذه الصيغ.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

افتراضيًا، يكون كل هذا داخليًا في الملف/الوحدة، ونستخدم الكلمة المفتاحية `exposing` لاختيار ما نريد تصديره. لإنشاء نوع معتم، ما عليك سوى اختيار عدم تصدير *الصيغ*.

وعندما تفعل ذلك، ستحتاج في الغالب إلى توفير طريقة أخرى لإنشاء *الصيغ* والحصول عليها، عبر تصدير دوال مخصصة. تتيح لك هذه الدوال المخصصة تطبيق بعض المنطق عند إنشاء *الصيغ* والحصول عليها. وهذا يخفي تفاصيل التنفيذ الداخلية للوحدة، ويعني أنه يمكنك تغيير تفاصيل التنفيذ كما تشاء، ما دامت الدوال المصدَّرة كما هي.

## Parse, don't validate

ربما يكون الاستخدام الأكثر شيوعًا للأنواع المعتمة هو فرض التحقق، باستخدام نمط [Parse, dont validate][parse-dont-validate]. في هذا النمط، تصدّر دالة تأخذ مُدخلًا ببنية أو أمان أنواع أقل مما تريد، مثل `String`، ثم تحلّله إلى نوع أكثر بنية، مثل `EmailAddress`، فإما أن تُرجع النوع، وإما أن تُرجع خطأ (عادةً `Maybe` أو `Result`).

على سبيل المثال، في الكود أدناه، لا يمكن للوحدات الخارجية إنشاء نوع `EmailAddress` إلا باستخدام دالة `parseEmailAddress`، لذا عندما تعمل مع نوع `EmailAddress`، فأنت متأكد من أنه صالح.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
