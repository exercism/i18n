# الاختبارات

نستخدم [pytest][Getting Started Guide] كمشغّل اختبارات على موقعنا.
ستحتاج إلى تثبيت `pytest` على جهاز التطوير لديك إذا أردت تنزيل اختبارات التمارين لمسار Python وتشغيلها محليًا.
ينبغي أيضًا أن تثبّت إضافات `pytest` التالية:

- [pytest-cache][pytest-cache]
- [pytest-subtests][pytest-subtests]

نوصي أيضًا باستخدام برنامج فحص الكود [pylint][pylint]، فهو جزء من التغذية الراجعة الآلية على الموقع، ويمكن أن يكون أداة مفيدة جدًا لتحليل الكود الساكن.
وللسهولة في الاستخدام، تتيح لك إضافة [pytest-pylint][pytest-pylint] الخاصة بـ `pytest` تشغيل `pylint` عبر `pytest` من سطر الأوامر.

قد يكون ضبط Pylint مرهقًا بعض الشيء، لذا قد يفيدك هذا [البرنامج التعليمي من pylint.readthedocs.io][tutorial from pylint.readthedocs.io] للبدء، وكذلك هذه النظرة العامة على [جودة الكود: الأدوات وأفضل الممارسات][Code Quality: Tools and Best Practices] من Real Python.

## تثبيت pytest

يمكن تثبيت Pytest وتحديثه باستخدام أداة Python المدمجة [`pip`][pip].

لمزيد من النصائح، لدى Brett Cannon [دليل سريع وعملي حول كيفية تثبيت الحزم في python][quick-and-dirty]، مع شرح رائع لـ [لماذا ينبغي أن تستخدم `python -m pip`][python-m-pip].
لمزيد من المعلومات عن وسائط سطر الأوامر في Python، راجع [سطر الأوامر والبيئة][python command line] في وثائق Python.

**ملاحظة:** قد يكون `Python3` و`py` اسمين بديلين لـ Python على نظامك، وقد لا يكونان كذلك.
عدّل أوامر التثبيت أدناه وفقًا لذلك.
لتثبيت `pytest` في بيئة افتراضية، تأكد من أن البيئة **مفعّلة** قبل تنفيذ الأوامر.
وإلا فسيكون تثبيت `pytest` عامًّا.

#### Windows

```powershell
PS C:\Users\foobar> py -m pip install pytest pytest-cache pytest-subtests pytest-pylint
Successfully installed pytest-8.3.3 ...
```

#### Linux / MacOS

```bash
$ python3 -m pip install pytest pytest-cache pytest-subtests pytest-pylint
Successfully installed pytest-8.3.3 ...

```

للتحقق من نجاح التثبيت:

```bash
$ python3 -m pytest --version
pytest 8.3.3
```

## تشغيل الاختبارات

لتشغيل الاختبارات، انتقل إلى المجلد الذي يوجد فيه التمرين باستخدام `cd` في الطرفية (_استبدل `<exercise-folder-location>` أدناه بمسارك_).

```bash
$ cd <exercise-folder-location>
```

<br>

~~~~exercism/note
تشير `<exercise-folder-location>` أو معظم الأشياء داخل الأقواس الزاوية إلى **_قيمة بديلة_**.
وينبغي كتابة المسار أو اسم الملف العادي _بدون_ أي أقواس.  


على سبيل المثال: `/Users/janedoe/exercism/python/exercises/concept/chaitanas-colossal-coaster` (على أنظمة *nix)، أو `C:\Users\janedoe\exercism\python\exercises\practice\hello-world\` (على Windows)، أو `myFolder` أو `my_file.py`.
~~~~  

<br>


الملف الذي ستحتاج إلى تشغيله ينتهي عادةً بـ `_test.py`.
يحتوي هذا الملف على اختبارات حل التمرين، وهي نفس الاختبارات التي تُشغَّل على الموقع عند رفع الحل.
بعد ذلك، نفّذ الأمر التالي في الطرفية، مع استبدال `<exercise_test.py>` بموقع/اسم ملف الاختبار:

```bash
$ python3 -m pytest -o markers=task <exercise_test.py>
==================== 7 passed in 0.08s ====================
```

### إصلاح التحذيرات

إذا لم تستخدم `pytest -o markers=task` في الأمر أعلاه، فمن المحتمل أن تظهر لك `warnings` بشأن "unknown markers" عند تشغيل اختبار يستعمل الصياغة _الجديدة_ لدينا.

لتجنّب كتابة `pytest -o markers=task` في كل اختبار تشغّله، يمكنك استخدام ملف الإعدادات `pytest.ini`، الذي يمكن تنزيله من المستوى الأعلى لمجلد مسار Python: [pytest.ini][pytest.ini].

ويمكنك أيضًا إنشاء ملف `pytest.ini` خاص بك بالمحتوى التالي:

```ini
[pytest]
markers =
    task: A concept exercise task.
```

وضع هذا الملف في المجلد _الجذر_ أو المجلد _العامل_ لتمارين Exercism يسجّل العلامات ويوقف التحذيرات.
يمكنك العثور على مزيد من المعلومات عن علامات pytest في وثائق `pytest` حول [تعليم دوال الاختبار][marking test functions with attributes] ووثائق `pytest` حول [العمل مع علامات مخصّصة][working with custom markers].

_يمكنك العثور على مزيد من المعلومات حول تخصيص إعدادات pytest في وثائق pytest حول [تنسيقات ملفات الإعدادات][configuration file formats]_

### حالات فشل الاختبارات

عند فشل الاختبارات، يطبع `pytest` نص كل اختبار فاشل إلى الطرفية، مع قيمتَي `return` المتوقعة والفعلية لكل منها.
فيما يلي مثال عام على اختبار فاشل:

```bash
$(my_venv) python3 -m pytest -o markers=task <exercise_test.py>

=================== FAILURES ====================
______________ name_of_failed_test ______________
# Test code inside of <exercise_test.py> that failed.
...
E   TypeOfError: ReturnedValue != ExpectedValue

exercise_test.py:<line_of_failed_test>: TypeOfError
============ short test summary info ============
FAILED exercise_test.py::ExerciseTest::name_of_failed_test
========== 1 failed, 2 passed in 0.13s ==========
```

#### التوقف بعد أول فشل [`-x`]

استخدام العلامة `-x` يشغّل الاختبارات كالمعتاد، لكنه يوقف تشغيل الاختبارات عند أول فشل في أحدها.
ويفيد ذلك عندما تريد تصحيح مهمة واحدة أو فشل اختبار واحد في كل مرة:

```bash
$(my_venv) python3 -m pytest -o markers=task -x exercises/<exercise_name>/<test_file_test.py>

=================== FAILURES ====================
_______________ example_test_foo ________________
...
...
============ short test summary info ============
FAILED example_test.py::ExampleTest::example_test_foo
!!!!!!!!!!! stopping after 1 failures !!!!!!!!!!!
========== 1 failed, 5 passed in 0.28s ==========
```

#### الاختبارات الفاشلة أولًا [`--ff`]

تتذكّر إضافة `pytest-cache` الاختبارات التي فشلت في آخر مرة شغّلت فيها `pytest`، لذا فإن استخدام العلامة `--ff` يخبر `pytest` بتشغيل الاختبارات التي فشلت سابقًا **أولًا**، ثم المتابعة ببقية الاختبارات.
قد يسرّع هذا اختباراتك إذا كنت تجري الكثير من الإصلاحات الصغيرة حول مهمة معينة أو مجموعة مدخلات معينة.

```bash
$(my_venv) python3 -m pytest -o markers=task --ff <example_file_test.py>
==================== 7 passed in 503s ====================
```

### سير العمل الموصى به

نوصي باستخدام الأوامر التالية لجعل تصحيحك أسهل و(ربما) أسرع:

غيّر أولًا مجلد العمل الحالي إلى مجلد التمرين الذي تريد اختباره:

```bash
$(my_venv) cd path/to/exercise
```

ثم شغّل الاختبارات مع الوسيطين `-x` و`--ff` اللذين شرحناهما سابقًا:

```bash
$(my_venv) python3 -m pytest -o markers=task -x --ff <example_file_test.py>
```

سيؤدي هذا إلى اختبار حلّك.
عندما يصادف `pytest` اختبارًا فاشلًا، يتوقف البرنامج ويخبرك بالاختبار الذي فشل.
وعندما تجري إصلاحات وتشغّل الاختبار مرة أخرى، يشغّل `pytest` أولًا الاختبار الذي فشل سابقًا، ثم يتابع ببقية الاختبارات.

### استخدام PDB، مصحّح أخطاء Python، مع pytest

إذا أردت أن "تصحّح الأخطاء باحتراف"، يمكنك استخدام الوسيط `--pdb` بعد أمر `pytest`، والدخول إلى [مصحّح أخطاء Python][pdb] المدمج، `PDB`.

```bash
$(my_venv) python3 -m pytest -o markers=task -x --ff --pdb <example_file_test.py>
=============== 4 passed in 0.15s ===============
```

عند فشل اختبار، فإن الدخول إلى `PDB` يتيح لك التنقل خطوة بخطوة في كودك مع رؤية النطاق الحالي، وكذلك التحقق من قيم المتغيرات وتوقيع الدوال المختلفة.
يمكنك العثور على مزيد من التفاصيل عن وحدة `PDB` في [وثائق Python حول PDB][pdb].
بالإضافة إلى ذلك، فإن [وثائق pytest حول PDB][pytest-pdb] و[هذا الدليل من Real Python](https://realpython.com/python-debugging-pdb/) مفيدة للغاية.

## معلومات إضافية

### إضافة python إلى PATH

**ملاحظة:** إذا ثبّت Python على Windows عبر [مثبّت PSF][psf-installer]، فسيكون الأمر `py` بدلًا من `python3`.

قد تصبح كتابة `python3 -m` في كل مرة تريد تشغيل وحدة أمرًا مزعجًا بعض الشيء.
لتجنب ذلك، يمكنك إضافة مجلد `Scripts` الخاص بتثبيت Python إلى مسارك (path).
وإذا لم تكن تعرف أين ثبّت Python، فنفّذ الأمر التالي في الطرفية:

```bash
$ python3 -c "import os, sys; print(os.path.dirname(sys.executable))"
<python_directory>
```

المجلد _المُرجَع_ هو المكان الذي ثُبّت فيه نسخة Python النشطة حاليًا، ويُشار إليه في هذا القسم بـ `<python_directory>`.

#### Windows

انقر زر `Windows Start` وابحث عن _Edit the system environment variables_ ثم اضغط Enter.
بعد ذلك اضغط `Environment Variables...`:

![اضغط الزر الأزرق، هههه](https://raw.githubusercontent.com/exercism/python/main/docs/img/Windows-SystemProperties.png)

ثم ابحث عن المتغير `Path` في _User variables_ لديك، وحدده، وانقر `Edit...`:

![تحديد متغير المسار](https://raw.githubusercontent.com/exercism/python/main/docs/img/Windows-EnvironmentVariables.png)

ثم أضف سطرًا جديدًا، كما في الصورة، مع استبدال `<python_directory>` بمجلد تثبيت Python لديك:

![إضافة python إلى path](https://raw.githubusercontent.com/exercism/python/main/docs/img/Windows-AddPythonPath.png)

#### MacOS/Linux

ينبغي أن يعمل ما يلي مع معظم توزيعات Linux وإصدارات MacOS التي تستخدم صدفة `bash`.
وقد تختلف الأوامر بحسب توزيعة Linux، وما إذا كانت الصدفة `fish` أو `zsh`.
استبدل `<python_directory>` بناتج `python3 -c "import os, sys; print(os.path.dirname(sys.executable))"`

```bash
export PATH="$PATH:<python_directory>"
```
