# مقدمة إلى الأوامر والوسائط

لا يتناول هذا المسار كيفية استخدام bash كصدفة تفاعلية.
بل يتناول تعلّم كتابة البرامج باستخدام bash، لغة البرمجة.

برنامج bash، أو _النص البرمجي_، تسلسل من الأوامر مخزّن في ملف.
تقرأ bash (الملف التنفيذي) الملف وتنفّذ الأوامر بالترتيب.

## سطر shebang

السطر الأول من النص البرمجي عادةً _توجيه المفسّر_، ويُعرف أيضًا بـ_hashbang_ أو _shebang_:

```bash
#!/usr/bin/env bash
```

عندما ينفّذ نظام التشغيل ملفًا غير ثنائي، فإنه يقرأ السطر الأول.
وإذا بدأ السطر بـ`#!`، فإن النواة تستخدمه لتحديد المفسّر الذي ينبغي أن ينفّذ الملف.
ويجب أن يكون `#!` في بداية الملف تمامًا، دون مسافات أو أسطر فارغة قبله.

هنا يبحث `env` في `PATH` عن الملف التنفيذي `bash`.
وقد ترى أيضًا الصيغة الأبسط `#!/bin/bash`، وهي تثبّت موقع المفسّر مباشرة؛ وصيغة `env` أكثر قابلية للنقل.

~~~~exercism/note
لا تنخدع بنصوص برمجية أو أمثلة على الإنترنت تستخدم `/bin/sh` كمفسّر.
**`sh` ليس `bash`!**
فـbash «متوافقة مع sh» وتستطيع تشغيل معظم نصوص `sh` البرمجية، لكن بعض ميزات bash تتعطل أو تتصرّف بغير المتوقع في `sh`.
~~~~

## التعليقات

السطر الذي يبدأ بـ`#` هو _تعليق_، وتتجاهله bash.
ويمكن أن يأتي التعليق بعد أمر في السطر نفسه: فكل شيء من `#` حتى نهاية السطر يُتجاهل.
التعليقات موجودة ليقرأها البشر الذين يطالعون النص البرمجي.

## الكلمات والوسائط

تقرأ Bash الأوامر من مدخلاتها (وهي عادةً إما طرفية وإما ملف).
وكل سطر من المدخلات تقرؤه يُعامل على أنه _أمر_، أي تعليمة يجب تنفيذها.
(هناك حالات متقدمة قليلة، مثل الأوامر الممتدة على عدة أسطر، سنتناولها لاحقًا.)

تقسم Bash كل أمر إلى **كلمات** تفصل بينها محارف المسافات البيضاء (المسافات وحروف الجدولة).
الكلمة الأولى هي اسم _الأمر_ المطلوب تنفيذه.
وتصبح كل الكلمات المتبقية _وسائط_ لذلك الأمر (خيارات، أسماء ملفات، وما إلى ذلك).

قد يكون الأمر _أمرًا مدمجًا_ في bash، مثل `echo`، أو برنامجًا _تنفيذيًا_، مثل `head` أو `awk` أو `sed`.

## الأمر `echo`

يطبع `echo` وسائطه، مفصولة بمسافة واحدة، وينتهي بسطر جديد:

```bash
echo flour sugar eggs
```

فيكون الخرج:

```text
flour sugar eggs
```

لا يهم مقدار المسافات البيضاء بين الوسائط:

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

واستدعاء `echo` دون أي وسائط يطبع سطرًا فارغًا.

## الخيارات ليست إلا وسائط

تقبل أوامر كثيرة _خيارات_ تغيّر كيفية عملها.
بالنسبة إلى bash، الخيار ليس شيئًا خاصًا: فهو كلمة كأي كلمة أخرى، تفصله عن جيرانه مسافة بيضاء.
والأمر نفسه هو الذي يقرر كيف يفسّر وسائطه.
وبحسب العُرف، تبدأ الخيارات بـ`-`.

يطبع الأمر `head` الأسطر الأولى من ملف.
ولنفترض أن لدينا ملفًا اسمه `list.txt`:

```bash
head -n 2 list.txt
```

تقسم Bash هذا السطر إلى أربع كلمات:

| الكلمة | الدور |
| ---------- | ------------------------------------------- |
| `head` | الأمر المطلوب تنفيذه |
| `-n` | خيار يطلب من `head` عدّ _الأسطر_ |
| `2` | قيمة الخيار `-n` |
| `list.txt` | الملف المطلوب قراءته |

تمرّر Bash الكلمات الثلاث الأخيرة إلى `head` دون تغيير.
و`head` هو الذي يفهم أن `-n` يتبعها عدد، وأن الكلمة المتبقية ملف.

ولأن المسافات هي ما يفصل الكلمات، فموضعها مهم.
فـ`head -n 2` يعطي `head` وسيطين (`-n` و`2`)، بينما `head -n2` يعطيه وسيطًا واحدًا (`-n2`).
وتقبل أوامر كثيرة الصيغتين، لكن ذلك متروك للأمر نفسه.
أما Bash فلا يهمها الأمر؛ فهي تكتفي بتقسيم السطر إلى كلمات.

## تنصيق الوسائط

تجمّع [علامات التنصيص][Quotes] الكلمات في _وسيط واحد_.
وتُحفظ المسافات البيضاء داخل علامات التنصيص، ولا تكون علامات التنصيص نفسها جزءًا من الوسيط:

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

إذا احتوى وسيط، مثل اسم ملف، على مسافات بيضاء، فنسّقه:

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## تشغيل نص برمجي

لتشغيل نص برمجي، مرّره وسيطًا للأمر `bash`:

```bash
bash myscript
```

وعند استخدامه بهذه الطريقة، لا يكون سطر `#!` إلا تعليقًا.
فأنت تخبر نظام التشغيل كيف يشغّل الملف.

بدلًا من ذلك، اجعل ملف النص البرمجي قابلًا للتنفيذ وشغّله كأي برنامج آخر:

```bash
chmod +x myscript
./myscript
```

الآن يستخدم نظام التشغيل سطر `#!` لتحديد المفسّر الذي سيُستخدم.
