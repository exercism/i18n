# مقدمة

## الواجهة كمجموعة من الطرق

في أبسط صورها، **نوع الواجهة** هو مجموعة من توقيعات الطرق.
إليك مثالًا على تعريف واجهة يتضمن طريقتين هما `Add` و `Value`:

```go
type Counter interface {
    Add(increment int)
    Value() int
}
```

يمكن حذف أسماء المعاملات مثل `increment` من تعريف الواجهة، لكنها غالبًا ما تزيد من قابلية القراءة.

أسماء الواجهات في Go لا تحتوي على الكلمة `Interface` أو الحرف `I`.
بل غالبًا ما تنتهي بـ `er`، مثل `Reader` و `Stringer`.

## تنفيذ واجهة

أي نوع يعرّف طرق الواجهة ينفّذ الواجهة تلقائيًا وضمنيًا.
لا توجد كلمة مفتاحية `implements` في Go.

النوع التالي ينفّذ واجهة `Counter` التي رأيناها أعلاه.

```go
type Stats struct {
    value int
    // ...
}

func (s Stats) Add(v int) {
    s.value += v
}

func (s Stats) Value() int {
    return s.value
}

func (s Stats) SomeOtherMethod() {
    // The type can have additional methods not mentioned in the interface.
}
```

لتنفيذ الواجهة، لا يهم ما إذا كانت الطريقة لها مستقبل قيمة أو مستقبل مؤشر.
(راجع [مفاهيم الطرق][concept-methods] إن لم تكن متأكدًا منها.)

> يمكن لقيمة من نوع الواجهة أن تحمل أي قيمة تنفّذ تلك الطرق. [^1]

هذا يعني أنه يمكن الآن استخدام `Stats` في كل المواضع التي تتوقع واجهة `Counter`.

```go
func SetUpAnalytics(counter Counter) {
    // ...
}

stats := Stats{}
SetUpAnalytics(stats)
// works because Stats implements Counter
```

لأن الواجهات تُنفَّذ ضمنيًا، يمكن للنوع أن ينفّذ عدة واجهات بسهولة.
كل ما يحتاجه هو أن تكون كل الطرق اللازمة معرّفة فيه.

## الواجهة الفارغة

يوجد في Go نوع واجهة خاص جدًا، هو نوع **الواجهة الفارغة** الذي لا يحتوي على أي طرق.
تُكتب الواجهة الفارغة هكذا: `interface{}`.
و`any` اسم بديل لـ `interface{}`، وهو أكثر شيوعًا في الاستخدام.

ولأن الواجهة الفارغة لا تحتوي على طرق، فكل نوع ينفّذها ضمنيًا.
هذا مفيد لتعريف دالة يمكنها قبول أي قيمة بشكل عام.
في هذه الحالة، يستخدم معامل الدالة نوع الواجهة الفارغة.
