# عن قابلية أن تكون القيمة `null`

في عالم مثالي، كان يمكننا الاعتماد على أن كل شيء معرَّف بشكل جيد، بقيم محددة وبلا فراغات.

لكن هذا يتعارض مع تجربتنا اليومية، ولذلك تمتلك لغات البرمجة وسائل لتمثيل غياب القيمة: `null` أو `NULL` أو `nil` أو `None` أو لا شيء...

كان إدخال هذا المفهوم سهلًا (بالعودة إلى عام 1965)، لكنه أدى سريعًا إلى الندم.
وسمّاه مخترعه لاحقًا ["خطأ المليار دولار"][web-mistake].

في العقود الأخيرة، استكشف مصممو اللغات طرقًا عديدة لجعل القيم `null` متاحة لكن آمنة (في معظمها).

لدى Kotlin بعض [المبادئ العامة][ref-null-safety]، التي [تختلف اختلافًا كبيرًا عن Java][ref-java2kotlin].
_تعني هذه الاختلافات أن Kotlin تمتلك وظائف خاصة للتعامل مع التشغيل البيني مع Java، لكن تفاصيل ذلك خارج نطاق هذا المفهوم._

- تمتلك Kotlin قيمة خاصة هي `null`.
- كل الأنواع تكون _افتراضيًا_ غير قابلة لأن تكون `null` (أي لا يمكن أن تساوي `null`).
- يمكن جعل كل الأنواع _قابلة لأن تكون `null`_، لكن ذلك يجب أن يحدث بشكل صريح.
- الدوال التي قد تفشل برمي استثناء غالبًا ما تكون لها نسخة بديلة تُرجع قيمة يمكن أن تكون `null`.
- توجد صيغة خاصة ومقتضبة جدًا تحاول أن تجعل فحص القيم `null` والتعامل معها سهلًا قدر الإمكان.

## إنشاء متغيرات قابلة لأن تكون `null`

يمكن جعل النوع [قابلًا لأن يكون `null`][ref-nullable-type] بإضافة اللاحقة `?` (مثل `String?` بدلًا من `String`).

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## عوامل ودوال مفيدة

### [عامل الاستدعاء الآمن][ref-safe-call] `?.`

بالنسبة إلى `String` غير القابل لأن يكون `null`، يمكننا الحصول على الخاصية `.length`.

أما `String?` القابل لأن يكون `null` فيفشل مع الصيغة نفسها، لكن استخدام `?.length` يأخذ في الحسبان احتمال أن تكون القيمة `null`.
نوع القيمة المُرجَعة هو `Int?`.

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

وكما رأينا في السطر الأخير أعلاه، يعمل `?.` أيضًا مع الأنواع غير القابلة لأن تكون `null`.

### [عامل إلفيس][ref-elvis] `?:`

وبناءً على فكرة عامل الاستدعاء الآمن، يتيح لنا [عامل إلفيس][wiki-elvis] توفير قيمة افتراضية تحل محل `null`.

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### [عامل تأكيد عدم القيمة `null`][ref-not-null] `!!`

مع هذا العامل، يُجبَر النوع القابل لأن يكون `null` على أن يُعامَل كنوع غير قابل لذلك، عندما يكون المبرمج واثقًا من ذلك.
ربما نفهم منطق البرنامج في بعض الأحيان أفضل من مُصرِّف مفرط في الحذر؟

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

تقع المسؤولية الآن علينا: إذا كانت `b` لا تزال `null` فسنحصل على `NullPointerException`.

### [دالة `let`][ref-let] `?.let`

إذا كنا نمرر عنصرًا يمكن أن يكون `null` إلى كتلة من الكود، فيمكننا إجراء فحوص محددة للقيمة `null` مثل `if (item != null) { do something }`.

لكن الأبسط وأقرب إلى أسلوب اللغة هو استخدام `item?.let { do something }`؛ فلن يُنفَّذ `do something` إلا عندما لا تكون `item` مساوية لـ `null`.

### دوال من نوع `somethingOrNone()`

قد تفشل بعض الدوال، مثلًا عند طلب فهرس غير صالح في سلسلة نصية أو مصفوفة.

وبدلًا من رمي استثناء، يمكننا استخدام [النسخة `...OrNull`][ref-elem-at-or-null] من الدالة، للحصول (في هذه الحالة) على قيمة مُرجَعة من النوع `Int?`.

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
