# مقدمة

تستخدم لغة البرمجة Java *الاستثناءات* للتعامل مع الأخطاء والأحداث الاستثنائية الأخرى.

## ما هو الاستثناء؟

الاستثناء حدثٌ يقع أثناء تنفيذ برنامج، فيعطّل التدفق الطبيعي للتعليمات.
الاستثناءات تُرفع في Java بشكل صريح، وتُسمّى عملية رفع الاستثناء *رمي الاستثناء*.
وتُسمّى عملية التعامل مع الاستثناء *التقاط الاستثناء*.

في Java، جميع الاستثناءات أصناف فرعية من الصنف `Exception`، وهو نفسه صنف فرعي من `Throwable`.

تميّز Java بين نوعين من الاستثناءات:

1. الاستثناءات المُتحقَّق منها
2. الاستثناءات غير المُتحقَّق منها

### الاستثناءات المُتحقَّق منها

*الاستثناءات المُتحقَّق منها* هي حالات استثنائية ينبغي أن يتوقعها التطبيق ويتعافى منها.
ومن أمثلتها الاستثناء `FileNotFoundException`، الذي يحدث عندما تحاول طريقةٌ قراءة ملف غير موجود.

يُتحقَّق من هذا النوع من الاستثناءات في وقت الترجمة: ينبغي للطرق التي ترمي استثناءات مُتحقَّق منها أن تحدّد ذلك في توقيع الطريقة، ويُشترط على الكود الذي يستدعي طريقة قد ترمي استثناءً مُتحقَّقًا منه أن يتعامل معه، وإلا فلن يُترجم الكود.

جميع الاستثناءات المُتحقَّق منها أصناف فرعية من `Exception` لا تمتد من `RuntimeException`.

### الاستثناءات غير المُتحقَّق منها

*الاستثناءات غير المُتحقَّق منها* هي حالات استثنائية لا يستطيع التطبيق عادةً توقعها أو التعافي منها.
ومن أمثلتها الاستثناء `NullPointerException`، الذي يحدث عندما تتوقع طريقةٌ قيمةً غير `null` لكنها تستقبل `null`.

لا يُتحقَّق من هذا النوع من الاستثناءات في وقت الترجمة: لا يُشترط على الطرق التي ترمي استثناءات غير مُتحقَّق منها أن تحدّد ذلك في توقيع الطريقة، ولا يُشترط على الكود الذي يستدعي طريقة قد ترمي استثناءً غير مُتحقَّق منه أن يتعامل معه.

ترث جميع الاستثناءات غير المُتحقَّق منها من `RuntimeException`، وهو نفسه امتدادٌ لـ `Exception`.

## رمي الاستثناءات

يمكن لطريقة في Java أن ترمي استثناءً باستخدام عبارة `throw`.

### رمي استثناء مُتحقَّق منه

عند رمي استثناء مُتحقَّق منه من طريقة، يُشترط تحديد ذلك في توقيع الطريقة باستخدام الكلمة المفتاحية `throws`، كما يوضح المثال التالي.
وهذا يُلزم الكود الذي يستدعي الطريقة بأن يتوقع احتمال رمي استثناء وأن يتعامل معه وفقًا لذلك.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### رمي استثناء غير مُتحقَّق منه

عند رمي استثناء غير مُتحقَّق منه من طريقة، لا يُشترط تحديد ذلك في توقيع الطريقة، وإن كان ذلك مدعومًا.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## التعامل مع الاستثناءات

يتم التعامل مع الاستثناءات في Java باستخدام الكلمات المفتاحية `try` و`catch` و`finally`.

- ينبغي وضع عبارات الكود التي قد ترمي استثناءً داخل كتلة `try`.
- تتبع كتلة `try` كتلة `catch` واحدة أو أكثر تلتقط الاستثناءات المرمية داخل كتلة `try`.
- ويمكن أن تتبع كتل `catch` كتلة `finally` تُنفَّذ دائمًا بعد كتلة `try`، بغض النظر عما إذا كان قد رُمي استثناء أم لا.

يوضح المثال التالي كيف تعمل هذه الكلمات المفتاحية:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

في هذا المثال، عندما لا يُرمى أي استثناء، تُطبع المخرجات التالية:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

أما إذا رمَت عبارة `bankAccount.withdraw(amount)` استثناء `InsufficientBalanceException`، فتُطبع المخرجات التالية:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

أو إذا رمى `bankAccount.withdraw(amount)` استثناءً غير مُتحقَّق منه، فتُطبع المخرجات التالية:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## الأخطاء

تضم Java أيضًا فئة منفصلة تُسمّى *الأخطاء*، وهي مشكلات خطيرة خارجية عن التطبيق.
ومن أمثلتها الخطأ `OutOfMemoryError`، الذي يحدث عندما يحاول التطبيق استخدام ذاكرة أكثر مما هو متاح على النظام.

ومثل الاستثناءات غير المُتحقَّق منها، لا يُتحقَّق من الأخطاء في وقت الترجمة.
والفرق أنها تمثل مشكلات على مستوى النظام، وعادةً ما ترميها الآلة الافتراضية لـ Java أو البيئة بدلًا من التطبيق.
وعمومًا، لا ينبغي للتطبيقات أن تحاول التقاطها أو التعامل معها.

ترث جميع الأخطاء في Java من الصنف `Error`.
