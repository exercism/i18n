# القوائم

`LIST{T}` مجموعة مرتبة قابلة للنمو، تستند إلى مصفوفة تُستبدل بأخرى أكبر عند امتلائها.

```sather
   notes ::= #LIST{STR};
   notes.append("muddy boots");
   notes[0]                     -- "muddy boots"
   notes[0] := "clean boots";
   notes.size
   notes.is_empty
   notes.has("clean boots")
   notes.remove_index(0);
```

## مصفوفة أم قائمة؟

| | `ARRAY{T}` | `LIST{T}` |
| --- | --- | --- |
| الحجم | ثابت عند الإنشاء | يتغير |
| الإلحاق | لا | نعم |
| الإزالة | لا | نعم |
| الفهرسة | `a[i]` | `l[i]` |
| الحمل الإضافي | لا شيء | حجم، ومساحة فائضة |

استخدم `ARRAY` عندما يكون الحجم معروفًا ومستقرًا، مثل صف من الراقصين أو أسبوع من العدّات. واستخدم `LIST` عندما تصل الأشياء أو تغادر.

## التعديل في المكان مقابل الأسلوب الوظيفي

إن `append` و`remove_index` و`[i] :=` كلها تغيّر القائمة نفسها. فلا حاجة إلى إعادة الإسناد، والقائمة التي تُمرَّر إلى إجراء ليست بمنأى عن ذلك.

وهذا عكس ما تفعله `FMAP` و`FSET`، ويستحق الأمر أن تكون واضحًا بشأن النوع الذي تحمله. والقاعدة المختصرة: وجود `F` في بداية الاسم يعني الأسلوب الوظيفي، وكل ما عدا ذلك يُعدَّل في المكان.

ولتسلّم قائمة لا يستطيع أحد إفسادها، أعطِ نسخة منها:

```sather
   return notes.copy;
```

## تكلفة الإلحاق

الإلحاق رخيص في المتوسط. وعندما تمتلئ المصفوفة الداعمة، تُؤخذ مصفوفة جديدة بضعف الحجم وتُنسخ كل العناصر، لذا لا تكلف معظم عمليات الإلحاق شيئًا يُذكر، بينما تكلف إحداها نسخًا كاملًا من حين لآخر. وعلى مدى عمليات إلحاق كثيرة، يصبح المتوسط تكلفة ثابتة لكل عملية، ولهذا تُضاعَف المصفوفة بدلًا من أن تنمو بعنصر واحد في كل مرة.

أما `remove_index` فليست رخيصة: فكل ما يلي الموضع المحذوف يتحرك خطوة واحدة. والحذف المتكرر من مقدمة قائمة طويلة بطيء بطريقة يسهل ألّا تلاحظها.

## إجراءات مفيدة

| الاستدعاء | ما يفعله |
| --- | --- |
| `l.append(x)` | يضيف في النهاية |
| `l.insert_before(i, x)` | يضيف عند موضع معيّن |
| `l.remove_index(i)` | يحذف موضعًا |
| `l.has(x)` | هل هو موجود فيها؟ |
| `l.copy` | نسخة مستقلة |
| `l.str` | المحتويات، بين أقواس معقوفة |
| `l.elt!`, `l.ind!` | المرور على القيم، أو على المواضع |
