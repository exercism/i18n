# مقدمة

التحليل هو عملية تحويل النص إلى بيانات ذات معنى.
الدوال في حزمة `String` محدودة في هذا الصدد، والتعبيرات النمطية صعبة الاستخدام، لذا فإن الطريقة المألوفة في Elm للتحليل هي استخدام حزمة `elm/parser`.

لنستعرض مثالًا على كتابة محلل (لمجموعة فرعية) من لغة البرمجة [LOLCODE][lolcode].
لننظر إلى البرنامج التالي المُعلَّق عليه:

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

أولًا، لنكتب نوعًا في Elm لتمثيل الأوامر الممكنة:

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

يمكن بعد ذلك نمذجة برنامج LOLCODE لدينا على هيئة `List Command`.
لنبدأ بمحلل للسطر `HAI 1`:

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP` مبني باستخدام _خط أنابيب المحلل_.
يعني العامل `(|.)` "حلّل السلسلة النصية لكن تخلَّص من النتيجة"، ويعني `(|=)` "حلّل السلسلة النصية واحتفظ بالنتيجة".
في هذا المثال، ستستهلك `Parser.keyword "HAI"` كلمة "HAI"، لكن هذه النتيجة تُتجاهل.
ستستهلك `Parser.spaces` أي عدد من محارف ' ' و'\n' و'\r'، لكن ذلك سيُتجاهل أيضًا.
ستحلّل `Parser.int` عددًا صحيحًا، وستُمرَّر قيمة ذلك العدد الصحيح (لنقل 1) إلى `Parser.succeed Version` في الأعلى، وسينجح المحلل في إرجاع القيمة `Version 1`.

إذا فشل أيٌّ من المحللات في خط الأنابيب، فسيُرجع `Parser.DeadEnd` وسيفشل المحلل بأكمله.
ويمكن تشغيل محلل باستخدام `Parser.run`:

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

لنعالج سطر "CAN HAS STDIO?" باستخدام

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP` هو أيضًا خط أنابيب محلل، لكنه هذه المرة ينتهي بـ `Parser.symbol` المناسب لتحليل رموز مثل "?".
أما القيمة التي نريد الاحتفاظ بها (اسم الحزمة المراد استيرادها) فيحلّلها

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

بما أننا لا نعرف ما سيكون اسم الحزمة، فلا يمكننا استخدام `Parser.keyword`، لذا نستخدم بدلًا منها `Parser.chompWhile` التي ستستهلك محارف مفردة ما دامت تحقق شرطًا (هنا، أن تكون محرفًا أبجديًا رقميًا).
ثم تُجمع هذه المحارف بواسطة `Parser.getChompedString` التي تُرجع `Parser String`.
في هذه الحالة، نود توحيد أسماء الحزم، لذا نستخدم `Parser.map` لتعديل السلسلة النصية الموجودة في المحلل وجعلها بأحرف صغيرة.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

بعد ذلك، يُحلَّل `VISIBLE "HAI WORLD!"` بواسطة

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

أصبح لدينا الآن محلل لكل أمر.
بالطبع، في برنامج عام، لا يمكن التنبؤ بترتيب هذه الأوامر، لذا نبني محللًا عامًا للأوامر

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

ستجرّب `Parser.oneOf` محللًا واحدًا بالترتيب المعطى.
إذا فشل محلل، يُجرَّب التالي، أما إذا نجح، فتُرجع نتيجته دون تجربة المحللات المتبقية.
وإذا فشلت جميع المحللات، يفشل `Parser.oneOf`.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

لاحظ كيف تنتج كل محاولة فاشلة `Parser.DeadEnd` تجمعه `Parser.oneOf`.

لتحليل برنامج كامل، نحتاج إلى تحليل عدة أوامر بالتتابع باستخدام

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence` محلل قابل للتخصيص بدرجة كبيرة وله عدد من الخيارات.
تأخذ `start` و`separator` و`end` سلاسل نصية تفصل عناصر التسلسل، ولتحليل مصفوفة Elm نستخدم "[" و"," و"]".
وتوفّر `spaces` المرونة عبر أخذ محلل يتولى المسافات المحتملة بين العناصر والفواصل، ولتحليل مصفوفة Elm نستخدم `Parser.spaces`، لكننا في هذه الحالة لا نقبل أي مسافات لذا نستخدم `Parser.succeed ()` الذي ينجح فورًا دون أن يستهلك أي شيء فعليًا.
تأخذ `item` محلل العناصر، وأخيرًا تتيح لنا `trailing` تحديد ما إذا كانت الفواصل اللاحقة `Parser.Forbidden` أو `Parser.Mandatory` أو `Parser.Optional`.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

عندما تنجح المحللات، تتوقف عن استهلاك السلسلة النصية

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

لذا إذا احتجنا إلى التأكد من أننا حللنا كل شيء في السلسلة النصية، يمكننا استخدام `Parser.end`

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

أخيرًا، نحتاج أحيانًا إلى اتخاذ قرار بإفشال محلل بناءً على محتواه المحلَّل.
على سبيل المثال، إذا احتجنا إلى محلل يُفشل البرامج التي تبدأ بأمرين "HAI" متتاليين، يمكننا استخدام

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

يستطيع `Parser.andThen` أن يفحص محتوى محلل ويُرجع محللًا جديدًا بناءً على قيمته.
هنا، أفشلنا المحلل برسالة مخصصة باستخدام `Parser.problem` في إحدى الحالتين، وأرجعنا القيمة الأصلية في الأخرى.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
