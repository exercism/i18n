# ملحق التعليمات

## المهمة

نفّذ إجراءين.

- يطلق `custom_error_message message` خطأً، و`message` هو رسالة الخطأ.
- يشغّل `handle_error script` السكربت المعطى ويُرجع سلسلة نصية تصف ما حدث:

  | عندما يقوم السكربت بـ…                | ما يُرجع                 |
  | ------------------------------------- | ----------------------- |
  | يقسم على صفر                          | `"division by zero"`     |
  | يفتح ملفًا غير موجود                  | `"file does not exist"`  |
  | يستدعي إجراءً غير موجود               | `"proc does not exist"`  |
  | يطلق أي خطأ آخر                       | `"unknown error"`        |
  | ينجح                                  | `"success"`              |

## إطلاق الأخطاء

في Tcl أمران لإطلاق خطأ.

```tcl
error "something went wrong"
throw {MYAPP BADTHING} "something went wrong"
```

يحتاج `throw` إلى _رمز خطأ_ كوسيطه الأول.
رمز الخطأ قائمة تخبر المُعالج بنوع الخطأ الذي حدث، حتى يستجيب دون تحليل نص الرسالة.
محتوياته متروكة لك: `{MYAPP BADTHING}` مجرد مثال، وأي قائمة غير فارغة تفي بالغرض.
وحسب العُرف، ينتقل من العام إلى الخاص.
ويمسك المُعالج به بنمط `try ... trap` مطابق (نوضحه أدناه)، مثل `trap {MYAPP BADTHING}`، أو `trap {MYAPP}` للإمساك بكل خطأ من نوع `MYAPP`.
ويأخذ `error` رمز خطأ اختياريًا كوسيطه الثالث: `error message ?info? ?code?`.

## معالجة الأخطاء باستخدام `catch`

[`catch`][catch] يشغّل سكربتًا ويُرجع _رمز إتمام_ صحيحًا بدلًا من إطلاق الخطأ:

| الرمز | المعنى     |
| ----- | ---------- |
| 0     | `ok`       |
| 1     | `error`    |
| 2     | `return`   |
| 3     | `break`    |
| 4     | `continue` |

```tcl
if {[catch {expr {1 / 0}} result options] == 1} {
    puts "error message: $result"
    puts "error code:    [dict get $options -errorcode]"
}
```
```none
error message: divide by zero
error code:    ARITH DIVZERO {divide by zero}
```

يستقبل الوسيط الثاني الاختياري النتيجة (أو رسالة الخطأ).
ويستقبل الوسيط الثالث الاختياري _قاموس خيارات_، يحتوي على `-errorcode` و`-errorinfo` (تتبّع المكدس).

المزايا:

- إنه صغير ومرن.
- وهو قصير في الحالات البسيطة، مثل `if {[catch {open $f} fh]} {...}`.

العيوب:

- عليك أن تفحص رمز الإتمام بنفسك.
  إن `if {[catch ...] != 0} { handle error }` المكتوبة بإهمال تعامل `return` و`break` و`continue` كأخطاء أيضًا.
- الأخطاء التي لا تعالجها تُبتلع ما لم تُعد إطلاقها بنفسك.
- لا توجد وسيلة مدمجة لتشغيل كود التنظيف سواء فشل السكربت أم لا.

## معالجة الأخطاء باستخدام `try`

[`try`][try] يشغّل سكربتًا ويرسل النتيجة إلى أول مُعالج مطابق.
وهناك بند `finally` اختياري يُنفَّذ دائمًا، ما يجعلها مكانًا جيدًا لتحرير الموارد مثل قنوات الملفات.

```tcl
set fh [open $filename r]
try {
    set data [read $fh]
} on error {msg options} {
    puts "could not read $filename: $msg"
} finally {
    close $fh
}
```

المزايا:

- البنية واضحة: مُعالج واحد لكل نوع من النتائج.
- يُنفَّذ `finally` دائمًا.
- النتائج التي لا يطابقها أي مُعالج تُمرَّر إلى المستدعي دون تغيير.

العيوب:

- إنه أكثر إسهابًا بقليل من `catch` في الحالات البسيطة.

### `try ... on` مقابل `try ... trap`

هناك نوعان من المُعالج.

يطابق `on code {msgVar optionsVar}` _رمز الإتمام_: `ok` أو `error` أو `return` أو `break` أو `continue`.
كل خطأ رمز إتمامه `error`، لذا لا يستطيع `on error` التمييز بين القسمة على صفر والملف المفقود.
سيكون عليك النظر في نص الرسالة، وهذا هشّ: فالرسائل موجهة للبشر وقد تتغير بين إصدارات Tcl.

```tcl
try {
    expr {$a / $b}
} on error {msg} {
    if {[string match "*divide by zero*" $msg]} { ... }
}
```

يطابق `trap pattern {msgVar optionsVar}` _رمز الخطأ_.
يطابق المُعالج عندما يكون النمط بادئة من قائمة `-errorcode`.
وهذا يحدد نوع الخطأ بموثوقية.

```tcl
try {
    expr {$a / $b}
} trap {ARITH DIVZERO} {} {
    puts "division by zero"
} trap {} {msg} {
    puts "some other error: $msg"
}
```

النمط الفارغ، `trap {}`، يطابق أي خطأ.
تُفحص المُعالجات بالترتيب، لذا ضع المُعالج الشامل أخيرًا.

## إيجاد رمز الخطأ

أين توثيق `ARITH DIVZERO`؟
في الكود المصدري غالبًا فقط، لكن Tcl سيعرضه لك.
بعد حدوث خطأ، يحمل المتغير العام `errorCode` رمز الخطأ الأحدث:

```none
$ tclsh
% set a 1; set b 0
% expr {$a / $b}
divide by zero
% set errorInfo     ;# this is the stack trace
divide by zero
    while executing
"expr {$a / $b}"
% set errorCode     ;# this is what we're after
ARITH DIVZERO {divide by zero}
```

داخل البرنامج، احصل عليه من قاموس الخيارات:

```tcl
try {
    expr {$a / $b}
} on error {msg options} {
    puts [dict get $options -errorcode]
}
```

العنصر الأخير في رمز الخطأ غالبًا رسالة مقروءة للبشر، أو اسم الشيء الذي سبب الخطأ.
اتركه خارج نمط `trap`: استخدم النمط `{ARITH DIVZERO}`، لا `{ARITH DIVZERO {divide by zero}}`.

### بعض رموز الأخطاء الشائعة

هذا الجدول ليس كاملًا.
استخدم التقنية أعلاه لإيجاد رمز أي خطأ آخر.

| الحالة                | مثال                     | رمز الخطأ                     |
| --------------------- | ------------------------ | ----------------------------- |
| القسمة على صفر        | `expr {1 / 0}`           | `ARITH DIVZERO ...`           |
| خطأ نطاق رياضي        | `expr {sqrt(-1)}`        | `ARITH DOMAIN ...`            |
| الملف غير موجود       | `open nosuchfile r`      | `POSIX ENOENT ...`            |
| رفض الإذن             | `open /root/x w`         | `POSIX EACCES ...`            |
| أمر غير معروف         | `no::such::proc`         | `TCL LOOKUP COMMAND name`     |
| متغير غير معروف       | `set nosuchvar`          | `TCL LOOKUP VARNAME name`     |
| عدد وسائط خاطئ        | `string length a b`      | `TCL WRONGARGS`               |
| قاموس غير صالح        | `dict size {1 2 3}`      | `TCL VALUE DICTIONARY`        |
| قائمة غير صالحة       | `llength "a \{b"`        | `TCL VALUE LIST ...`          |

تستخدم رموز أخطاء `POSIX` أسماء `errno` الخاصة بنظام التشغيل، مثل `ENOENT` و`EACCES` و`EEXIST`.

## تلميح: أين يُنفَّذ السكربت

يستقبل `handle_error` سكربتًا من المستدعي.
إذا شغّلته بـ `try $script`، فسيُقيَّم في نطاق `handle_error`، لا في نطاق المستدعي.
لتقييمه حيث كُتب، استخدم [`uplevel`][uplevel]: `try {uplevel 1 $script} ...`.
