# مقدمة

في Go 1.18، أضافت لغة Go دعمًا **للأنواع العامة**.
تتيح لك الأنواع العامة كتابة دوال وهياكل بيانات تعمل مع أنواع مختلفة دون تكرار الكود.

## لماذا الأنواع العامة؟

في Go، تعمل الدوال والأنواع عادةً مع أنواع محددة، مثل `int` أو `string`.
قبل الأنواع العامة، كان لديك خياران لدعم أنواع متعددة.
أولًا، كان بإمكانك كتابة عدة دوال بأسماء مختلفة، مثل `SumInts` و`SumFloats`.
ينشئ هذا الأسلوب كودًا مكررًا يصعب صيانته.
ثانيًا، كان بإمكانك استخدام الواجهة الفارغة `any` (`interface{}`).
غير أن الواجهة الفارغة تلغي فحوصات الأنواع وقت الترجمة وتتطلب تأكيدات الأنواع وقت التشغيل.
تحل الأنواع العامة هذه المشكلة بتوفير أمان الأنواع مع تجنب تكرار الكود.

## الدوال العامة

تعرّف دالة عامة بإضافة **معاملات النوع** بين الأقواس المربعة `[...]` بعد اسم الدالة.
إليك مثالًا لدالة عامة تُرجع شريحة معكوسة:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

في هذا المثال، `T` هو معامل نوع.
يمكنك التفكير في `T` على أنه عنصر نائب لنوع حقيقي.
الكلمة المفتاحية `any` داخل الأقواس المربعة هي **قيد نوع**.
يحدد القيد للمترجم الأنواع المسموح بها للمعامل `T`.
هنا، تعني `any` أن `T` يمكن أن يكون أي نوع.

### استدعاء الدوال العامة

يمكنك استدعاء دالة عامة بتمرير النوع الفعلي بين الأقواس المربعة.
يُسمى هذا النوع الفعلي **وسيط النوع**.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

في معظم الحالات، يستطيع مترجم Go اكتشاف النوع تلقائيًا من وسائط الدالة.
تُسمى هذه الميزة **استنتاج النوع**.
مع استنتاج النوع، لا تحتاج إلى كتابة وسيط النوع بين الأقواس المربعة.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

في هذا المثال، يرى المترجم أن `words` شريحة من السلاسل النصية، فيستنتج أن `T` هو `string`.

## قيود الأنواع

يجب أن يكون لكل معامل نوع قيد.
يحدد القيد الأنواع التي يمكنك استخدامها كوسائط نوع.
ويحدد القيد أيضًا العمليات المسموح لك بتنفيذها على قيم ذلك النوع.

### قيد `any`

يسمح قيد `any` بأي نوع.
في Go، `any` اسم بديل للواجهة الفارغة `interface{}`.
لأن `any` يسمح بكل الأنواع، لا يمكن للدالة أن تنفذ إلا العمليات التي تعمل مع جميع أنواع Go.
على سبيل المثال، إذا كان لديك قيمتان من النوع `any` تحملان شريحتين، فلا يمكن مقارنتهما باستخدام `==`، لأن الشرائح لا يمكن مقارنتها باستخدام `==`.

### قيد `comparable`

توفر لغة Go قيدًا مدمجًا يُسمى `comparable`.
يسمح قيد `comparable` بأي نوع يدعم العاملين `==` و`!=`.
تشمل الأنواع القابلة للمقارنة القيم المنطقية، والأعداد، والسلاسل النصية، والمؤشرات، والقنوات، والهياكل أو المصفوفات المكوّنة من أنواع قابلة للمقارنة.

إليك مثالًا لدالة تتحقق مما إذا كانت شريحة تحتوي على عنصر محدد:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

لأن `T` يستخدم قيد `comparable`، فإن استخدام `elem == target` صالح.
إذا استبدلت `comparable` بـ`any`، فسيُصدر المترجم خطأً.

### قيود مخصصة باستخدام مجموعات الأنواع في الواجهات

بدءًا من Go 1.18، يمكن للواجهات أن تعرّف مجموعات من الأنواع بالإضافة إلى الطرق.
يمكنك استخدام الرمز العمودي `|` لسرد الأنواع المسموح بها في واجهة.

```go
type Number interface {
    int | int64 | float64
}
```

يمكنك الآن استخدام `Number` كقيد لدالة:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

لأن جميع الأنواع في `Number` تدعم العامل `*`، تسمح لغة Go بالتعبير `value * 2` داخل الدالة.

### تقريب النوع الأساسي `~`

أحيانًا تنشئ تعريفًا لنوع مخصص استنادًا إلى نوع بدائي:

```go
type MyInt int
```

لا يسمح قيد `Number` المعرّف أعلاه إلا بالأنواع `int` و`int64` و`float64` نفسها.
إذا مررت قيمة من النوع `MyInt` إلى `Double`، فسيُصدر المترجم خطأً لأن `MyInt` لا يطابق `int`.
للسماح بأي نوع يكون نوعه الأساسي `int`، أضف علامة التلدة `~` قبل النوع:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

يمكنك الآن استخدام `Double` مع قيم من النوع `MyInt`.

### قيد `cmp.Ordered`

توفر المكتبة القياسية قيد `cmp.Ordered` في [حزمة `cmp`][doc-cmp].
يسمح قيد `cmp.Ordered` بأي نوع يدعم عوامل المقارنة `<` و`<=` و`>` و`>=`.

## الأنواع العامة

يمكنك أيضًا استخدام معاملات النوع لتعريف أنواع عامة، مثل الهياكل.
إليك مثالًا لهيكل بيانات `Stack` عام:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

عندما تعرّف متغيرًا من نوع عام، يجب أن تقدم وسيط النوع بين الأقواس المربعة:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

لا يعمل استنتاج النوع إلا مع الدوال العامة.
يجب عليك دائمًا تحديد وسيط النوع عند إنشاء قيم من نوع عام.

## متى تستخدم الأنواع العامة

الأنواع العامة ميزة قوية، لكنك لا تحتاج إلى استخدامها في كل مشكلة.

استخدم الأنواع العامة في حالات مثل هذه:
- عندما تبني هياكل بيانات، مثل الأشجار أو القوائم المترابطة أو الذاكرات المؤقتة، تعمل مع أي نوع عنصر.
- عندما تكتب دوالًا مساعدة تعمل على شرائح أو خرائط من أي نوع، مثل التصفية أو الترتيب أو البحث.
- عندما تحتاج إلى التنفيذ نفسه تمامًا لعدة أنواع، وتريد أمان الأنواع وقت الترجمة.

استخدم الواجهات بدلًا من ذلك في حالات مثل هذه:
- عندما يهمك السلوك والطرق أكثر من نوع البيانات الأساسي.
  على سبيل المثال، إذا أردت قراءة بيانات من مصادر متنوعة الأنواع (ملفات، وشبكة، وطرفية) ومعالجتها، فستستخدم `func Process(src io.Reader)` بدلًا من `func Process[T](src T)`.
- عندما تتطلب أنواع مختلفة تنفيذات مختلفة للطرق لإنجاز عملها.
