# مقدمة

تكون الدالة [تكرارية ذيلية][recursion-tc] إذا كان _آخر_ ما تنفذه الدالة هو استدعاء لنفسها.

في كل مرة تُستدعى فيها أي دالة، يوضع _إطار مكدس_ يحوي متغيراتها المحلية ووسائطها فوق [مكدس استدعاء الدوال][call-stack].
وعندما تُرجع الدالة، يُزال إطار المكدس من المكدس.

تتيح الدوال التكرارية الذيلية [تحسين الاستدعاء الذيلّي][tail-call-optimization] (أو إزالة الاستدعاء الذيلّي).
وهو تحسين يسمح بإعادة استخدام آخر إطار مكدس في الاستدعاء التالي للدالة، عندما يُضمن أن الدالة السابقة لم تعد بحاجة إليه.
وهذا يخفف من مخاوف طفح مكدس استدعاء الدوال، وهي الحالة التي تكون فيها الإطارات على مكدس استدعاء الدوال كثيرة جدًا لدرجة أنه لم تبقَ ذاكرة لإنشاء إطار آخر.

## تحسين الاستدعاء الذيلّي في Elm

في حالة معينة، يستطيع مُصرِّف Elm أن يجري تلقائيًا تحسين الاستدعاء الذيلّي عند التصريف إلى JavaScript.

يمكن أن يحدث هذا التحسين في دالة تكرارية عندما تكون _آخر_ عملية في أحد الفروع هي استدعاء الدالة نفسها في تطبيق دالة بسيط.
لنلقِ نظرة على بعض الأمثلة:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

التنفيذ أعلاه ليس تكرارياً ذيلياً، لأن آخر عملية في فرع `else` هي عملية الضرب `n *`.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

التنفيذ أعلاه تكرارية ذيلي ويخضع للتحسين، لأن آخر عملية في فرع `else` هي أن `factorialHelper` تستدعي نفسها.
وهذا لن يكون ممكنًا لدالة بتوقيع النوع `Int -> Int`، وفي الممارسة العملية يتحقق تحسين الاستدعاء الذيلّي غالبًا بتعريف دوال مساعدة.
