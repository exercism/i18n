# مقدمة

ينشئ التصريح `GENERIC:` كلمةً يعتمد سلوكها على *صنف* أحد وسائطها. أما السلوك الفعلي فيأتي من *الطُرق* التي تُعرَّف باستخدام `M:`.

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

عندما تُستدعى `area`، يفحص Factor قمة المكدس، ويبحث عن الطريقة الأكثر تخصيصًا التي يطابق صنفها، ثم يشغّلها. ومع المتغيرات المحلية يمكنك استخدام `M::`:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

تتيح لك الدوال العامة إضافة تمثيلات جديدة لاحقًا دون تغيير الكود المستدعي: فقد كانت `area` تعمل أصلًا مع `square` و`circle`، وتُلتقط طريقة `rectangle` تلقائيًا في كل موضع تُستدعى فيه `area`.

## متى تكون الدالة العامة هي الخيار الصحيح

استخدم `GENERIC:` عندما:

- تكون لعملية واحدة تطبيقات *مختلفة فعلًا* لمدخلات مختلفة.
- تتوقع أن يضيف كود مستقبلي أنواعًا جديدة.
- تريد أن يفرض نظام الأنواع تعريفات خاصة بكل صنف.

وإذا كان الاختلاف مجرد تعداد صغير من التسميات، فإن `case` أبسط.

## الانضمام إلى mixin باستخدام `INSTANCE:`

إنّ mixin صنف عام *مفتوح*: يمكن لأي أحد تسجيل صنف جديد كعضو فيه. كثير من بروتوكولات Factor المدمجة (المتتاليات، والمجموعات، والتدفقات، …) مكشوفة في صورة mixin، ولذلك يمكن لسجل مخصص أن ينضم إلى الطرق الافتراضية للبروتوكول بإعلان نفسه نسخة منه:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

بعد `INSTANCE:`، تُوجَّه تلقائيًا كل طريقة افتراضية `M: shape …` إلى `my-shape`، ويقبل أي كود يطلب `shape` القيمة `my-shape`. فـ `M:` مخصّصة لإضافة طرق إلى دالة عامة، و`INSTANCE:` مخصّصة لضمّ صنف إلى mixin.

## `TYPED::`: مدخلات مُتحقَّق منها لكلمة عادية

تختار `GENERIC:`/`M:` طريقةً بحسب صنف الوسيط. وأحيانًا لا تريد الإرسال الديناميكي، بل تريد *كلمة واحدة* تُلزم أن تكون مدخلاتها من صنف معيّن. و`TYPED::` (في المفردات `typed`) هي `::` مع كتابة صنف بعد اسم كل مدخل:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

تُقرأ `n: integer` مثل المتغيرات المحلية التي تستخدمها بالفعل، مع كتابة الصنف بعد النقطتين. لا يوجد إرسال ديناميكي، تعريف واحد وسلوك واحد، لكن يُتحقَّق الآن من كل وسيط مقابل صنفه: فالتنافر مثل `"x" triple` يُرفض (*expected input value of type integer but got string*) بدلًا من أن يمرّ بصمت.

ويمكن وسم النتيجة بالطريقة نفسها. فـ `yes?` تحدّد نوع مدخلها ونتيجتها معًا:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## دوال الرياضيات وثوابتها

يعتمد هذا التمرين أيضًا على بضع كلمات من `math.constants` و`math.functions` ستلتقي بها للمرة الأولى هنا:

- `pi`: الثابت π، من `math.constants`.
- `sin ( x -- y )`، و`cos ( x -- y )`: الجيب وجيب التمام لزاوية مقيسة بالراديان.
- `e^ ( x -- y )`: `e` مرفوعًا إلى القوة `x`. (ولأي أساس تشاء، استخدم `^`.)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
