# دليل أسلوب Rexx

يصف هذا الدليل الأسلوب المقصود استخدامه مع ملفات اختبارات تمارين مسار Rexx وملفات الأمثلة.

## معيار Rexx

ينبغي أن يتوافق الكود مع مستوى لغة Rexx 5.0.

يمكن استخدام امتدادات Regina Rexx، ودوال معيار SAA للوصول إلى المكتبات الخارجية.

لا ينبغي استخدام امتدادات AREXX، ولا روتينات معالجة المخزن المؤقت في CMS.

## المنصة

بيئة اختبار التشغيل قائمة على Linux، لذلك لا يجوز استخدام سوى الأوامر المتاحة في تلك البيئة عند استدعاء تعليمة `ADDRESS`. وينبغي إبراز هذه الأوامر بوضوح في تعليقات الكود.

## الأسماء

### التعليمات

ينبغي كتابة التعليمات (الكلمات المحجوزة) **_بأحرف صغيرة_**. لذلك، المثال التالي متوافق مع توصيات دليل الأسلوب:

```rexx
do while input \= ''
  parse var input char +1 input
  say char
end
```

في حين أن كلا المثالين التاليين غير متوافقين، وبالتالي غير موصى بهما:

```rexx
/* *** Not recommended *** */
Do While input \= ''
  Parse Var input char +1 input
  Say char
End
```

و:

```rexx
/* *** Not recommended *** */
DO WHILE input \= ''
  PARSE VAR input char +1 input
  SAY char
END
```

### الدوال المدمجة (BIFs)

ينبغي كتابة الدوال المدمجة **_بأحرف كبيرة_**، كما يوضح المثال التالي:

```rexx
input = 'ABCDE'
say 'Length of input is' LENGTH(input)
say 'First letter of input is' SUBSTR(input, 1, 1)
```

### العلامات (الدوال المعرّفة من المستخدم)

ينبغي أن تُكتب أسماء العلامات بنمط **_Pascal case_**، كما هو موضح هنا:

```rexx
greeting = MyFuncSayHello()
say greeting

exit 0

MyFuncSayHello : procedure
  hello = 'Hello there!'
return hello
```

### المتغيرات

ينبغي أن يبدأ اسم المتغير بحرف **_صغير_**، لذا تكون المتغيرات ذات الكلمة الواحدة بأحرف صغيرة.

يمكن كتابة المتغيرات متعددة الكلمات إما بنمط **_camel case_** أو بنمط **_snake case_**.

والعُرف المعتمد في المسار هو استخدام _نمط camel case لمعظم المتغيرات_، وحصر نمط snake case على متغيرات الاختبار. ويمكن، اختياريًا، كتابة المتغيرات المخصّصة كثوابت بأحرف كبيرة أيضًا.

```rexx
input = 'ABCDE'
i = 0

personName = 'Alice'
test_person_description = 'Brown hair, blue eyes'

TRUE = 1
PI_CONSTANT = 3.14159
```

## القيم الحرفية

يمكن الإشارة إلى السلاسل النصية باستخدام علامات الاقتباس المفردة أو المزدوجة، **`'`** و**`"`** على الترتيب. والمثالان التاليان متكافئان:

```rexx
say "Hello, world!"

say 'Hello, world!'
```

ويمكن تضمين كل منهما داخل الآخر دون الحاجة إلى محرف هروب:

```rexx
say "Please don't do that as it's wrong."

say 'He said, "Please sir, may I have more?".'
```

ما لم تحتوِ السلاسل النصية على علامات اقتباس مضمّنة تستلزم خلط نوعي علامات الاقتباس، فالمفضّل الإشارة إلى السلاسل النصية باستخدام **_علامات الاقتباس المفردة_**.

### السلاسل النصية السداسية عشرية والثنائية

يمكن تمثيل القيم الثنائية والسداسية عشرية بإضافة **`B`** أو **`X`** على الترتيب إلى سلسلة نصية. أمثلة:

```rexx
hexvalue = "0A"X

binvalue = "00001010"B
```

يوصى بتحديد هذه القيم بـ**_علامات الاقتباس المزدوجة_**.

إلى جانب التوصية السابقة باستخدام علامات الاقتباس المفردة لتمثيل السلاسل النصية العادية، ينبغي أن يسهّل هذا العُرف تمييز السلاسل النصية الثنائية والسداسية عشرية في قاعدة الكود.

### مُنهي السطر الجديد

في كثير من اللغات المتأثّرة بـUNIX أو بلغة C، تُستخدم القيمة الحرفية **_`\n`_** كمُنهي **_للسطر الجديد_**. وهذا الاستخدام واسع الانتشار، وتتضمن عدة تمارين في هذا المسار استخدام السلاسل النصية التي تحمل هذا المُنهي والتعامل معها.

لا يدعم Rexx هذا المُنهي، ولا يدعم **_`\`_** (أو أي محرف آخر) كمحرف هروب.

المكافئ في Rexx لمحرف السطر الجديد هو قيمة سداسية عشرية (تعتمد على المنصة)؛ وعلى المنصات المشتقة من UNIX تكون:

**_`"0A"X`_**

والمكافئ في Rexx للسلسلة النصية التالية التي تحوي أسطرًا جديدة مضمّنة (باستخدام صدفة bash):

```bash
printf "I have\nthree embedded\nnewlines.\n"
```

هو:

```rexx
say 'I have' || "0A"X || 'three embedded' || "0A"X || 'newlines.' || "0A"X
```

لن تُحوّل التمارين في هذا المسار **_`\n`_** إلى **_`"0A"X`_** إلا عند الحاجة إليها في سلسلة نصية مخصّصة للعرض على الطرفية. وفي غير ذلك، ستُفسَّر سلسلة **_`\n`_** ببساطة على أنها سطر جديد منطقي.

## توصيات أسلوبية أخرى

يمكن أن تكون الإزاحة بمقدار حرفين أو ثلاثة أو أربعة من محارف المسافة، وإن كان المفضّل الإزاحة بمقدار _حرفين_ والاتساق في الإزاحة.

ينبغي أن تتحاذى تعليمة **_return_** الأخيرة في الدالة مع اسم العلامة، بحيث تحدّد نهاية تلك الدالة بوضوح، وينبغي أن _تُرجع_ قيمة دائمًا.

يمكن تمثيل عامل النفي المنطقي NOT بعدة رموز مختلفة. والرمز المفضّل في هذا المسار هو **`\`**، وللحفاظ على الاتساق مع هذا الاستخدام، ينبغي أن يكون عامل «لا يساوي» العلاقي هو **`\=`**.

تُمثَّل القيم المنطقية **`false`** و**`true`** بـ**`0`** و**`1`** على الترتيب. ولا توجد قيم حرفية معرّفة مسبقًا لهذه القيم.

تُشار إلى حالات الخطأ باستخدام قيم الإرجاع، إذ تشير السلسلة النصية الفارغة **`''`** أو القيمة **`-1`** إلى حالات الخطأ، حسب السياق.

## بنية ملف الاختبار

يكون لكل تمرين ملف اختبار واحد، يقع في الدليل الأعلى للتمرين، باسم: `<exercise>-check.rexx`

وباتباع هذا العُرف، سيحمل ملف اختبار تمرين `acronym` الاسم: `acronym-check.rexx`

يُرتَّب ملف اختبار كل تمرين بطريقة مرنة لكن محدّدة، لمساعدة المتعلمين على فهم متطلبات التمرين، ولتسهيل مهمة المساهم في تنفيذ الاختبارات أو توسيعها.

وفيما يلي جزء من ملف اختبار تمرين `acronym`:

```rexx
/* Unit Test Runner: t-rexx */
function = 'Abbreviate'
context('Checking the' function 'function')

/* Unit tests */
check('basic' function||'("Portable Network Graphics")',,
      function||'("Portable Network Graphics")',, 'to be', 'PNG')

check('lowercase words' function||'("Ruby on Rails")',,
      function||'("Ruby on Rails")',, 'to be', 'ROR')
```

ينقسم الملف إلى قسمين منطقيين، يُميّز كلًّا منهما سطر تعليق.

يُسند القسم الأول اسم **_الدالة موضع الاختبار_** (هنا الدالة `Abbreviate`) إلى المتغير `function`. وهذا الاسم وصفي لكنه اختياري، ويُشار إليه في بقية الملف في كل موضع يُطلب فيه اسم الدالة موضع الاختبار.

وفي هذا القسم أيضًا استدعاء للدالة `context`، وغرضها بيّن بذاته.

يحتوي القسم التالي على اختبارات الوحدة. وكل استدعاء للدالة `check` هو اختبار وحدة واحد. المعاملات المتوقّعة:

```rexx
check(<test description>,
      <function invocation>,
      [<actual result variable>],
      <test comparator>,
      <expected result>)
```

**\<test description>** هي السلسلة النصية التي تُصدَر عند تنفيذ الاختبار. ولجعلها وصفية قدر الإمكان، يوصى باستخدام سلسلة نصية تتكوّن من اسم الدالة موضع الاختبار والوسائط الممرَّرة إليها، كما في المثال.

**\<function invocation>** هو استدعاء الدالة الفعلي، بحيث تُمرَّر قيمة إرجاعه إلى `check` لمقارنة الاختبار.

**\<actual result variable>** هو معامل اختياري، وإذا استُخدم فهو اسم المتغير الذي يحوي القيمة المستخدمة في مقارنة الاختبار.

والسبب في استخدامه هو السماح بالتحقق من نتائج _مشتقّة من_ قيمة إرجاع الدالة موضع الاختبار بدلًا من قيمة الإرجاع نفسها. ومن الأمثلة الواضحة على ذلك أن تكون قيمة الإرجاع سلسلة نصية بحجم عدة كيلوبايت، كما هو موضح:

```rexx
expected_length = LENGTH(FUT(...))

check('...', FUT(...), expected_length, 'to be', 50)
```

يُرجى ملاحظة أنه لا يزال يتعيّن تمرير الوسيط \<function invocation>.

**\<test comparator>** هي سلسلة نصية تصف نوع المقارنة المطلوب إجراؤها. وفي معظم الحالات تكون هذه السلسلة 'to be'، وهي تطلب مقارنة من أجل التساوي. راجع توثيق إطار اختبار الوحدة لخيارات المقارنة الأخرى.

**\<expected result>** هي، كما هو بيّن، القيمة التي تُقارَن بها النتيجة الفعلية.

يمكن تعريف المتغيرات بحرية داخل ملف الاختبار (قبل استخدامها بالطبع)، واستخدامها بدلًا من القيم الحرفية كوسائط للدالة `check`.
