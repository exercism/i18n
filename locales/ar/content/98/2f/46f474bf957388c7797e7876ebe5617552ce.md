# حلقتا `while` و `until`

الحلقة بنية تحكم تسمح بتكرار تنفيذ الكود بناءً على شرط معيّن.

## حلقات `while`

حلقة `while` بنية تحكم تسمح بتكرار تنفيذ الكود بناءً على شرط معيّن.
يستمر الكود داخل حلقة `while` في التنفيذ ما دامت قيمة الشرط صحيحة.
غالبًا ما تُستخدم حلقات `while` عندما يكون عدد التكرارات غير معروف مسبقًا، ويمكن استخدامها في أي موقف تكون فيه الحلقة مطلوبة.

يُقيَّم الشرط قبل تنفيذ الكود داخل الحلقة، وهذا يعني أنه إذا كان الشرط خاطئًا فلن يُنفَّذ الكود داخل الحلقة أبدًا.

```crystal
i = 0
while i < 3
  puts i
  i += 1
end

# Output:
# 0
# 1
# 2
```

عندما تريد المرور على سلسلة نصية، يمكنك التكرار على طول السلسلة النصية.

```crystal
str = "Hello"
i = 0
while i < str.size
  puts str[i]
  i += 1
end

# Output:
# H
# e
# l
# l
# o
```

## حلقات `until`

تعمل حلقات `until` كما تعمل حلقات `while`، إلا أن الكود داخل الحلقة يظل يُنفَّذ حتى تصبح قيمة الشرط صحيحة.
وهو نفس الفرق بين `if` و `unless`.

```crystal
i = 0
until i == 3
  puts i
  i += 1
end
```

### الحلقات اللانهائية

من الأخطاء الشائعة في حلقات `while` الدخول في "حلقة لا نهائية" لا تنتهي أبدًا.
قد تنشأ الحلقة اللانهائية لأن قيمة الشرط _لا_ تُقيَّم أبدًا على أنها صحيحة أو خاطئة.
وهذا غالبًا بسبب خطأ من المبرمج؛ على سبيل المثال، نسيان زيادة متغير الحلقة.
لكن أحيانًا تكون الحلقة اللانهائية أوضح أسلوب لتطبيق منطق البرنامج.
أو يكون التكرار إلى ما لا نهاية أمرًا ضروريًا؛ فمثلًا ينتظر خادم HTTP اتصالًا واردًا، ويعالجه، ثم ينتظر الاتصال التالي.

## `break`

يمكن استخدام الكلمة المفتاحية `break` للخروج من الحلقة مبكرًا.
وهذا مفيد عندما تريد الخروج من الحلقة مبكرًا في ظروف معيّنة.

```crystal
i = 0
while i <= 3
  puts i
  i += 1
  if i == 2
    break
  end
end

# Output:
# 0
# 1
```

## `next`

يمكن استخدام الكلمة المفتاحية `next` للانتقال إلى التكرار التالي في الحلقة.
وهذا مفيد عندما تريد تخطي تكرارات معيّنة في الحلقة.

```crystal
i = 0
while i <= 3
  i += 1
  if i == 2
    next
  end
  puts i
end

# Output:
# 1
# 3
```

## الأنواع أثناء التكرار

قد يختلف نوع المتغير أثناء التكرار.
في المثال التالي، نوع `a` هو `Int32 | String` لأنه قد يكون `Int32` أو `String` في الجزء الأول من الحلقة.
لن يحمل المتغير `a` النوع `Int32 | String` إلا في الجزء الأول من الحلقة، لأنه عند بدء الحلقة يحمل `Int32`، وفي التكرار الثاني يحمل `String`.
سيُشرح نظام الأنواع المتعددة هذا بالتفصيل لاحقًا.
ولكن بما أننا متأكدون من أن الجزء الثاني من الحلقة لن يحمل إلا `String`، فإن نوع `a` في الجزء الثاني من الحلقة هو `String`.
وعند التنفيذ، لن يحمل `Int32` و `String` في الوقت نفسه أبدًا.

```crystal
i = 0
a = 4
while i < 3
  p typeof(a)
  # => Int32 | String
  a = "4"
  p typeof(a)
  # => String
  i += 1
end
```
