# بنّاءات السلاسل النصية

لا يتغيّر `STR` أبدًا. لذا لا يمكن لعامل `+` أن يضيف إليه شيئًا، بل عليه أن ينشئ سلسلة نصية جديدة كاملة تجمع محتوى الاثنين.

هذا لا مشكلة فيه مرة واحدة. أما داخل حلقة فيصبح مشكلة:

```sather
   -- don't
   script ::= "";
   loop
      script := script + lines.elt!;
   end;
```

في كل دورة تُنسخ كل ما بُني حتى الآن إلى سلسلة نصية جديدة، وتُهمل السلسلة القديمة. عشرة أسطر تعني عشر نسخ، كل واحدة أطول من التي قبلها. ومئة سطر تعني مئة نسخة. فالعمل ينمو مع *مربع* عدد الأسطر، وتتحول حلقة تبدو غير ضارة إلى الجزء البطيء في البرنامج.

## FSTR

`FSTR` سلسلة نصية *يمكن* تغييرها، أي **بنّاء سلاسل نصية**. والإضافة إليه تكتب عادةً في مساحة موجودة لديه بالفعل، لذا فإن حلقة على مئة سطر تبذل جهد ما يعادل مئة سطر بدلًا من مئة نسخة.

```sather
   script ::= #FSTR;
   loop
      script := script + lines.elt!;
   end;
   return script.str;
```

ثلاثة أمور جديرة بالملاحظة.

**`#FSTR` ينشئ بنّاءً فارغًا.** أما `#FSTR(100)` فينشئ بنّاءً بحيز محجوز مسبقًا لمئة محرف، وهو أمر يستحق العناء حين يكون الحجم معروفًا.

**يجب أن تُسند النتيجة من جديد.** `script := script + ...`، وليس `script + ...` وحدها أبدًا. عادةً تكون النتيجة هي بنّاء نفسه الذي دخل، لكنه حين ينفد حيزه يصبح بنّاءً جديدًا أكبر، وإهمال النتيجة يتركك تكتب في البنّاء القديم.

**`.str` في النهاية.** الروتين الذي يَعِد بـ `: STR` عليه أن يُرجع `STR`، و`.str` ينشئ واحدًا من البنّاء.

## ما الذي يمكن إضافته

يقبل `+` على `FSTR` سلسلة نصية أو محرفًا أو عددًا صحيحًا أو قيمة منطقية، فلا حاجة عادةً إلى التحويل أولًا:

```sather
   line ::= #FSTR;
   line := line + 1 + ". " + "Enter" + '!';   -- "1. Enter!"
```

## الأسطر الجديدة

`"\n"` داخل سلسلة نصية يعني سطرًا جديدًا: محرف واحد يُكتب بحرفين.

```sather
   script := script + "Enter" + "\n" + "Exit";
```
