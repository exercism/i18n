# حول الأساسيات

Kotlin لغة ذات أنواع ثابتة، صُمِّمت لتكون متوافقة توافقًا تامًا مع Java.

وما يميّزها عن Java أنها:

- تتمتع بصياغة أنظف وأكثر إيجازًا؛
- تدمج العديد من سمات اللغات الوظيفية؛
- وتوفر دعمًا واسعًا للقيم القابلة لأن تكون `null`.

## المتغيرات

لأن Kotlin لغة ذات أنواع ثابتة، فلا بد من _معرفة_ نوع كل قيمة في وقت الترجمة.

لكن [استنتاج الأنواع][inference] في Kotlin قوي جدًا، لذا فإن _تحديد_ النوع غالبًا أمر اختياري.

هناك طريقتان للإعلان عن متغير.

1. تُنشئ `val` متغيرًا غير قابل للتغيير، ومحاولة تغييره خطأ في وقت الترجمة.

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. تُنشئ `var` متغيرًا قابلًا للتغيير.

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

ولأن المتغيرات غير القابلة للتغيير تمنع فئة شائعة من الـ bug، يُشجَّع على استخدام `val` كلما أمكن.

كما أن حتى `var` لا تستطيع تغيير نوعها:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

لتقليل التشتيت البصري، ستُحذف الأنواع الصريحة في الغالب من هذا المنهج.
ومع ذلك، يُوصى بتحديد الأنواع على الأقل في:

- واجهات API العامة
- تواقيع الدوال
- المواضع التي تحتاج إلى توثيق

بعض الشركات والمؤسسات تطلب أمانًا صارمًا للأنواع وتمنع استنتاج الأنواع، بينما تقصره أخرى على الأنواع "البسيطة"، أو تتبنى استنتاج الأنواع بالكامل.

```kotlin
val x: Int = 42  // => 42
```

بشكل عام، يجب أن تكون أسماء المتغيرات والدوال بصيغة `camelCase`، لا `snake_case`

## الدوال

أعلن عن دالة باستخدام الكلمة المفتاحية `fun`.
وعلى عكس Java، لا يُشترط أن تكون الدوال جزءًا من صنف.

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

بعض النقاط الجديرة بالملاحظة:

- الأقواس الهلالية `()` مطلوبة بعد اسم الدالة، حتى لو لم تأخذ الدالة أي وسائط.
- تحتاج وسائط الدالة إلى تحديد النوع: لا يوجد استنتاج للأنواع (على عكس المتغيرات).
- يُحاط جسم الدالة بالأقواس المعقوفة `{ }` (لكن انظر أدناه).
- الكلمة المفتاحية `return` مطلوبة إذا كانت الدالة تُرجع قيمة.
- الفواصل المنقوطة `;` في نهاية الأسطر اختيارية، وعادة ما تُحذف.
- عوامل العمليات الحسابية `+`، `-`، `*`، `/` مشابهة لتلك الموجودة في معظم اللغات الشائعة.

لكن بالنسبة لهذه الدوال البسيطة جدًا، "أحادية التعبير"، ثمة صياغة مختصرة:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
يمكن أن يكون للدوال معاملات بقيم افتراضية. 
ستُستخدم هذه القيم إذا حُذفت عند استدعاء الدالة:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

عادة ما تُرجع الدوال في Exercism قيمة (بسبب طريقة بناء مشغّل الاختبارات).
ولاستخدام Kotlin على نطاق أوسع، قد يفيدك أن تعرف أن الدالة التي لا تُرجع قيمة يمكنها حذف نوع الإرجاع والكلمة المفتاحية `return`.

ويُقال حينها إن نوع إرجاعها هو `Unit`: وهو مكافئ لـ `void` في Java وعدة لغات أخرى.

## التعليقات

تبدأ التعليقات أحادية السطر بـ `//`، ثم يُتجاهَل ما تبقى من السطر.

أما التعليقات متعددة الأسطر فتبدأ بـ `/*` وتنتهي بـ `*/`

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

وهذا مطابق لما في Java.
