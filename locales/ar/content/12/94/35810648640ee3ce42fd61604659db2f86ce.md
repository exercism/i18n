# مقدمة

كل الأخطاء في Elixir تُنفّذ _سلوك الاستثناء_. وكما في _سلوك الوصول_، يُعرّف _سلوك الاستثناء_ دوال استدعاء راجعة يجب على الوحدة أن تنفّذها للوفاء بالعقد البرمجي لهذا السلوك. وبعد تعريف أي خطأ، تصبح له الخصائص التالية:

- يحدّد اسم الوحدة اسم الخطأ.
- تُعرّف الوحدة بنية خطأ.
- تحتوي البنية على حقل `:message`.
- يمكن استخدام الوحدة مع `raise/1` و`raise/2` لرفع الخطأ المقصود

كما يحدّد _سلوك الاستثناء_ دالتَي استدعاء راجعتين: `message/1` و`exception/1`. وإذا لم تُنفَّذ، فسيُستخدم التنفيذ الافتراضي. تُحوّل `message/1` بنية الخطأ إلى رسالة مقروءة عند استدعائها مع `raise`. وتسمح `exception/1` بإضافة سياق إضافي إلى الرسالة عند استدعائها مع `raise/2`

## تعريف استثناء

لتعريف استثناء انطلاقًا من وحدة خطأ، نستخدم الماكرو `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

## استخدام الاستثناءات

يمكن استخدام الأخطاء المُعرَّفة مثل خطأ مدمج باستخدام `raise/1` أو `raise/2`.

- يرفع `raise/1` خطأً معيّنًا باسم وحدته، أو، إذا كان الوسيط سلسلة نصية، فسيرفع `RuntimeError` وتكون السلسلة النصية هي الرسالة.
- ويرفع `raise/2` خطأً معيّنًا باسم وحدته، ويقبل وسيط سمات يُستخدم للحصول على الخطأ مع الرسالة المناسبة.
