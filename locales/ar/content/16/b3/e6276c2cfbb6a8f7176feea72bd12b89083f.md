# نبذة

نوع `Result` هو حل لغة Elm للإبلاغ عن الأخطاء والتعافي منها. وهو يشبه نوع `Maybe` إلى حد ما. الفرق أن `Nothing` في `Maybe` يعبّر عن نوع من الفشل دون أن يخبرك بشيء عن _سبب_ هذا الفشل، بينما يتضمن `Result` سياقًا يوضح سبب الفشل.

## التعريف ومتغير النوع

يُعرَّف نوع `Result` كما يلي:

```elm
type Result error value
  = Ok value
  | Err error
```

باختصار، يرمّز هذا النوع نتيجة عملية قد تنجح فتُرجع `value`، أو تفشل فتُرجع تفسيرًا للفشل (`error`).

ويُعرف هذا في مصطلحات Elm بتعريف "النوع المخصص".
تُقدَّم الأنواع المخصصة بالتفصيل في مفهوم آخر من هذا المسار، لكننا لن نحتاج إليها لفهم `Result` تحديدًا.
يمثّل `error` و`value` في `OK value` و`Error error` متغير نوع، أي أنه يمكن أن يكون أي نوع، مثل `Int` أو `Bool` أو `String`.
وعليه، فإن `Result String Int` متغير يُتوقع أن يحتوي على `Int`، وإذا وقع خطأ فسيُمثَّل بـ `String`.

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## قراءة محتوى قيمة `Result`

تتم قراءة محتوى قيمة `Result` عبر "مطابقة الأنماط".
وقد قُدّمت مطابقة الأنماط بالتفصيل أيضًا في مفهوم آخر، لذا سنركّز هنا فقط على كيفية عمل مطابقة الأنماط مع `Result`.

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

في كل مرة تستخدم فيها قيمة `Result`، سيتحقق مترجم Elm من أن الكود لديك يتعامل مع كل الاحتمالات، فلا يمكنك أبدًا أن تطابق نمط `Result` وتتعامل فقط مع الحالة التي فيها `Ok value`.
قد يبدو هذا مزعجًا في البداية، لكنه من أعظم نقاط قوة لغة Elm.
سيمنع هذا مئات الأخطاء، ويجعل إعادة هيكلة الكود الموجّهة بالمترجم تجربة لا خوف فيها ومجزية.

## التعامل مع محتوى قيمة `Result`

توجد دوال متعددة للتعامل مع أنواع `Result`، وهي عادةً أفضل من مطابقة الأنماط. يمكن استخدام `Result.map` لتحويل القيمة، و`Result.andThen` لربط الدوال التي قد تفشل ببعضها.

تُستخدم `Result.map` لتغيير قيمة `Ok`، وهي مفيدة لربط الدوال ببعضها دون الحاجة إلى القلق بشأن ما إذا كان `Result` يحتوي على خطأ أم لا. إذا كانت القيمة `Ok`، فإن `Result.map` تستدعي الدالة المربوطة (`formatAge` أدناه)، أما إذا وُجد خطأ، فلا تفعل `Result.map` شيئًا، بل تُرجع الخطأ فقط.

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

تُستخدم `Result.andThen` لتغيير قيمة `Ok`، وهي مفيدة لربط الدوال ببعضها دون الحاجة إلى القلق بشأن ما إذا كان `Result` يحتوي على خطأ أم لا. وهي تشبه `Result.map`، لكن `Result.andThen` تعمل مع دالة مربوطة (`formatSpecialBirthday` أدناه) تُرجع بدورها `Result`. تستطيع `Result.map` أن تفعل ذلك أيضًا، لكنها تنتهي بطبقة إضافية من التداخل، وهو ما يتجنبه `andThen` ببراعة.

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
