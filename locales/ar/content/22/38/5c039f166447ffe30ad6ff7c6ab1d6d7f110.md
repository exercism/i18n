# مقدمة

تتيح [مطابقة الأنماط][pattern-matching] كتابة كود تفريعي معبّر، ويجلب [التفكيك][destructuring] ربطًا أنيقًا للقيم بالمتغيرات.
ويُعدّ إتقان كليهما مفيدًا للغاية لمبرمجي Elm، وعند استخدامهما معًا يُحسّنان قابلية قراءة الكود كثيرًا.

## مطابقة الأنماط البسيطة

تشير مطابقة الأنماط إلى كود تفريعي يعتمد على شكل البيانات التي نتعامل معها.
ولذلك تتوافق طبيعيًا مع مفهوم الأنواع المخصصة، التي تعبّر عن الأشكال المتعددة التي قد تتخذها بعض البيانات.
فعلى سبيل المثال، إذا كان لدينا نوع مخصص `Color` معرّفًا بأنه إما `Blue` أو `Red`، فيمكننا كتابة دالة `toString` نطابق فيها الأنماط على اللون لإرجاع السلسلة النصية الصحيحة.

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

تعمل مطابقة الأنماط أيضًا مع الأنواع المخصصة التي ليست مجرد تعداد بسيط.
لنتأمل دالة `hello` تأخذ معاملًا من النوع `Maybe String`، يحمل إما اسم شخص أو لا شيء على الإطلاق.
عند مطابقة الأنماط، يمكننا إعطاء أسماء بحروف صغيرة للبيانات لربطها بذلك المتغير، ثم استخدامه في الطرف الأيمن من المطابقة.

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

يجب أن تكون مطابقة الأنماط شاملة، وإلا سيرفض المُصرِّف التصريف.
لكن في بعض الأحيان، لا تهمّنا بعض البيانات أو بعض فروع تعبير `case`.
في تلك الحالات، بدلًا من أن نضطر إلى البحث عن اسم متغير لنربطه وكتابة فروع لكل الحالات، يمكننا استخدام الشرطة السفلية `_` كمحرف بديل.

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## مطابقة الأنماط المتقدمة

بالإضافة إلى الأنواع المخصصة، يمكننا أيضًا مطابقة الأنماط على الأنواع التي لها قيم حرفية، مثل `Char` و`String` و`Int` و`Floats`.

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

لمطابقة أكثر من قيمة واحدة دون تداخل، هناك حيلة شائعة في Elm وهي جمع القيم المراد مطابقتها في [_الصفوف الظرفية_][ad-hoc-tuples] على النحو التالي:

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

ولأن القوائم عزيزة على المبرمجين الوظيفيين، [فيمكن مطابقة الأنماط عليها أيضًا][pattern-match-lists]، بالصيغة نفسها المستخدمة في بنائها، باستخدام العامل `::`.

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

وأخيرًا، تعمل مطابقة الأنماط حتى بشكل عودي، مما يتيح التعمق في الأنواع المعقدة والعودية.

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## التفكيك

يشبه التفكيك مطابقة الأنماط كثيرًا، من حيث إنه يتيح ربط المتغيرات بالبيانات الموجودة داخل الأنواع.
والفرق الرئيسي هو أننا نسمي تلك الآلية "تفكيكًا" عندما يكون هناك شكل واحد ممكن فقط، ونسميها "مطابقة أنماط" عندما تكون الأشكال متعددة.
وغالبًا ما نجد التفكيك في ارتباطات `let`، وفي معاملات الدوال، وبالطبع في تعبيرات `case` ممزوجًا بمطابقة الأنماط.

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

يمكن استخدام التفكيك مع الأنواع المخصصة ذات المتغير الواحد، ومع الصفوف، وكذلك مع السجلات، حيث يكون مريحًا للغاية.
ولـ[تفكيك سجل][records-pattern-matching]، يمكن للمرء استخدام أي عدد من حقوله، حقلًا واحدًا، أو اثنين، أو ...، أو كل الحقول.

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

لسوء الحظ، لا تتيح صيغة Elm التفكيك العودي للسجلات.
في مثال `Circle` السابق، لا توجد طريقة للوصول دفعة واحدة إلى `x`` and `y موضعَي مركز الدائرة.
علينا أولًا الوصول إلى `center` ثم تفكيكه للحصول على موضعَي `x` و`y`.

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

ولدينا نصيحة أخيرة!
أحيانًا نريد وصولًا سهلًا إلى الشيء ككل وإلى جزء منه في الوقت نفسه.
وهنا يمكن أن تكون [الكلمة المفتاحية `as`][as-keyword] مفيدة.
فهي تتيح إعطاء اسم مستعار للشيء ككل، مع إمكانية تفكيك محتواه في الوقت نفسه.

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
