# التعليمات

صمّمت صديقتك هيلما لعبة صغيرة عبر الإنترنت سرعان ما اكتسبت شعبية.
وهي تُدعى _HellMath_.
جذبت هذه الجماعة الصغيرة بعض الترولات الذين جعلوا اللعبة والمنتديات مزعجة إلى حد كبير.
وقد طلبت منك هيلما العمل على نظام صلاحيات جديد لفصل مثيري المشاكل.

يدعم المنتدى ثلاثة إجراءات مختلفة:

- قراءة
- كتابة
- إزالة

وهناك أربعة أنواع من الحسابات، ولكل منها صلاحيات افتراضية مختلفة:

- الضيوف: يمكنهم قراءة المنشورات.
- المستخدمون والترولات: يمكنهم قراءة المنشورات وكتابتها.
- المشرفون: يمكنهم قراءة المنشورات وكتابتها وإزالتها، فلهم جميع الصلاحيات.

لاحظت هيلما أنه لا جدوى من حظر حسابات الترول.
استراتيجيتها هي أن تمنحهم وهمًا بأن وقتهم «مُستثمَر جيدًا»، لكن منشوراتهم لا تُعرض إلا على الترولات الآخرين.
وفي أي شيء يتطلب ترتيبًا حسب الأولوية، يأتي الترولات في آخر أي تسلسل.
وعندما يدخلون لعبة، تقتصر مجموعة اللاعبين المتاحين أيضًا على الترولات الآخرين.

تُسمى هذه الممارسة [الحظر الخفي][shadow-ban].

## 1. إعداد أنواع المستخدمين والصلاحيات.

أولًا، عرّف تعداد `AccountStatus` لتمثيل أنواع الحسابات الأربعة: `troll` و`guest` و`user` و`mod`.

ثم عرّف تعداد `Action` لتمثيل أنواع الصلاحيات الثلاثة: `read` و`write` و`remove`.


## 2. عرض منشورات الترولات على الترولات فقط.

يحفظ كل منشور في المنتديات حالة `AccountStatus` الخاصة بالناشر في بياناته الوصفية.
احرص على ألا تُعرض منشورات الترولات إلا على الترولات الآخرين.

تحتاج هيلما إلى دالة `display_post` تستقبل وسيطين من نوع `AccountStatus` وتُرجع قيمة `bool`.
الوسيط الأول هو حالة الناشر، والوسيط الثاني هو حالة المشاهد.

```cpp
using namespace hellmath;
display_post(AccountStatus::troll, AccountStatus::user);
// => false
display_post(AccountStatus::mod, AccountStatus::guest);
// => true
```

## 3. التحقق من الصلاحيات لمختلف المستخدمين.

تحتاج هيلما إلى وسيلة للتحقق مما إذا كان إجراء معيّن مسموحًا به لمستخدم ما.

من فضلك نفّذ دالة `permission_check` تستقبل `Action` كوسيط أول و`AccountStatus` للتحقق منه.
ينبغي أن تُرجع قيمة `bool` وفقًا للصلاحيات المذكورة في المقدمة.

```cpp
permission_check(Action::remove, AccountStatus::guest);
// => false
permission_check(Action::write, AccountStatus::mod);
// => true
```

## 4. منح صلاحية الوصول إلى اللعبة وإقران اللاعبين.

لإبقاء اللاعبين الفعليين في اللعبة مسؤولين عن أفعالهم، تمنع _Hellmath_ المستخدمين الضيوف من الوصول.
وكما ذُكر أعلاه، تريد هيلما أن يزعج الترولاتُ الترولاتِ الآخرين.
أما الاتصالات بين بقية المستخدمين في اللعبة فغير مقيّدة.

نفّذ دالة `valid_player_combination` التي تتحقق مما إذا كان بإمكان لاعبَين الانضمام إلى اللعبة نفسها.
للدالة معاملان من نوع `AccountStatus` وتُرجع قيمة `bool`.

```cpp
valid_player_combination(AccountStatus::guest, AccountStatus::mod);
// => false
valid_player_combination(AccountStatus::troll, AccountStatus::troll);
// => true
```

## 5. بناء قائمة انتظار الأولوية.

مع النمو الهائل للعبة والمنتديات، أصبح على هيلما الآن توزيع القدرة الحاسوبية وعرض النطاق الترددي بين المستخدمين.
للتعامل مع الحالات الطارئة، تُمنح الأولوية القصوى للمشرفين.
الضيوف يقفون في الطابور خلف المستخدمين العاديين، أما الترولات فيُرتَّبون خلف الجميع.

نفّذ دالة `has_priority` التي تستقبل وسيطين من نوع `AccountStatus` وتُرجع `true`، إذا وفقط إذا كانت أولوية الحساب الأول أعلى بشكل صارم من أولوية الثاني.

```cpp
has_priority(AccountStatus::guest, AccountStatus::mod);
// => false
has_priority(AccountStatus::user, AccountStatus::troll);
// => true
```
