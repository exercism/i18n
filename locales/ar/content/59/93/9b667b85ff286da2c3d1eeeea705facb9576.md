# حول

[السجلات][records] هياكل بيانات تجمع معًا معلومات مترابطة تحت تسميات.
وهي تشبه الكائنات في JavaScript أو Java، أو structs في C أو Rust، لكن مع بعض الفروق الجوهرية.

## إنشاء السجلات

[تُنشأ][create] السجلات باستخدام الأقواس المعقوفة، وتُفصل عناصرها بفواصل.

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

يُعرَّف نوع السجل أيضًا بصيغة مشابهة، إلا أن علامة يساوي `=` تُستبدل بنقطتين `:`.

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

تكرار تعريفات الأنواع هذه أمر مُرهق، لذا فإن استخدام [الاسم المستعار للنوع][record-types] لمشاركة التعريف أسلوب شائع.

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

يزوّدنا الاسم المستعار للنوع أيضًا تلقائيًا بدالة إنشاء للسجل.
قد يكون هذا مفاجئًا أحيانًا، لأن الدوال في Elm يجب أن تبدأ بحرف صغير، لكن دوال إنشاء الأنواع تشكل استثناءً واحدًا.

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

## الوصول إلى حقول السجل

الطريقة الرئيسية [للوصول إلى قيمة حقل في نسخة سجل][access] هي استخدام الترميز النقطي مثل `firefly.creator`.
يدعم مُصرِّف Elm أيضًا دوال وصول خاصة تبدأ بنقطة `.` مثل `.creator`، وهي تعمل مع أي سجل يحتوي حقلًا بهذا الاسم.
وهذا هو الاستثناء الثاني لقاعدة أن الدوال يجب أن تبدأ بحرف صغير.
في الواقع، يجب أن تبدأ الدوال التي يعرّفها المستخدم بحرف صغير، لكن المثالين اللذين اكتشفناهما للتو يولّدهما المُصرِّف، لا المبرمج.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

يمكن أيضًا _تفكيك_ السجلات في الارتباطات باستخدام [مطابقة أنماط السجلات][pattern-matching].
يعمل التفكيك مع أي سجل له حقول بالأسماء ذات الصلة.

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

## تحديث السجلات

السجلات غير قابلة للتغيير، كما هو حال كل شيء في Elm، لذا بمجرد تعريف سجل، لا يمكن لقيم حقوله أن تتغير أبدًا.
توجد [صيغة خاصة لإنشاء نسخة من سجل موجود مع تغيير حقل واحد أو أكثر][update].
تستخدم هذه الصيغة رمز الخط العمودي `|` للتمييز بين السجل الأصلي والحقول التي ستتغير، مثل `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

## مقارنة السجلات

يستخدم Elm [المساواة البنيوية][equality]، وهذا يعني أن نسختين من السجل نفسه بقيم متطابقة تكونان متساويتين.

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

## السجلات القابلة للتوسيع

يدعم Elm أيضًا [النظام البنيوي للأنواع][structural-typing]، أي أنه إذا احتاجت دالة إلى سجل يحتوي حقلي x و y، فستعمل مع أي سجل يملك هذين الحقلين، مثل النقاط ثنائية الأبعاد، والنقاط ثلاثية الأبعاد، والمركبات الفضائية، إلخ.
تحتوي أنواع السجلات تلك على خط عمودي `|` في تعريفها، مثل `{ a | x : Float, y : Float }`، وتُسمى "السجلات القابلة للتوسيع" في مصطلحات Elm.
احذر الفرق بين خط عمودي `|` في تعريف نوع، وهو تعريف سجل قابل للتوسيع (`{ a | x : Int }`)، وخط عمودي `|` في نسخة سجل فعلية، وهو يعني أننا نحدّث بعض حقول ذلك السجل.

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
