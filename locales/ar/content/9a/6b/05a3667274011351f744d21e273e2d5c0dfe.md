# مقدمة

تتُقابل الأرقام الثنائية في النهاية الترانزستورات في وحدة المعالجة المركزية (CPU) أو الذاكرة العشوائية (RAM) مباشرةً، وتحدد ما إذا كان كل منها في حالة "تشغيل" أم "إيقاف".

التلاعب منخفض المستوى، الذي يُسمّى بشكل غير رسمي "التلاعب بالبتات"، مهم بوجه خاص في لغات الأنظمة.

عادةً ما تُخفي اللغات عالية المستوى مثل Kotlin معظم هذه التفاصيل. ومع ذلك، هناك مجموعة أساسية من العمليات على مستوى البتات [متاحة][ref-bitwise].

## عمليات إزاحة البتات

يمكن تمثيل الأنواع `Int` أو `Long`، سواء كانت موقّعة أم غير موقّعة، على هيئة متتالية من الآحاد والأصفار، والتعامل معها كتسلسل من البتات.

ومن المفاجئ ربما أن النوعين `Byte` و`Short` لا يتوافقان مع معظم عمليات البتات في Kotlin.
تستخدم كل الأمثلة أدناه أعدادًا صحيحة بطول 32 بت (`Int` أو `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

تُحرّك إزاحات البتات كل شيء إلى اليسار أو اليمين بعدد محدد من المواضع.
تسقط بعض البتات من أحد الطرفين، ويُملأ الطرف الآخر بالأصفار أو الآحاد.

- الإزاحة إلى اليسار باستخدام `shl`: حشو بالأصفار.
- الإزاحة إلى اليمين باستخدام `shr` أو `ushr`: حشو بالأصفار للأعداد الموجبة (انظر لاحقًا إلى الأعداد السالبة).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

تُضاعف كل إزاحة إلى اليسار القيمة، وتُنصّفها كل إزاحة إلى اليمين (مع احتمال الاقتطاع).
ويتّضح هذا أكثر في التمثيل العشري:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

إزاحة البتات هذه أسرع بكثير من الحساب "التقليدي"، ما يجعل هذه التقنية شائعة جدًا في البرمجة منخفضة المستوى.

مع _الأعداد الصحيحة السالبة_، علينا أن نكون أكثر حرصًا.

تُخزَّن القيم السالبة على هيئة [المتمّم الثنائي][wiki-2complement]، ما يعني أن البت الأقصى يسارًا يساوي 1.
لا مشكلة في الإزاحة إلى اليسار، لكن عند الإزاحة إلى اليمين، كيف نملأ البتات الأقصى يسارًا؟

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

يُنفّذ العامل `shr` [الإزاحة الحسابية][wiki-arithmetic]، مع الحفاظ على بت الإشارة.

يُنفّذ العامل `ushr` [الإزاحة المنطقية][wiki-logical]، بحشو بالأصفار كما لو كان العدد بدون إشارة.

## المنطق على مستوى البتات

رأينا في [مفهوم القيم المنطقية][concept-booleans] أن العوامل `&&` (و) و`||` (أو) و`!` (ليس) تُستخدم مع القيم المنطقية.

وهناك عوامل مكافئة هي `and` و`or` و`xor` ([أو الحصرية][wiki-xor]) لمقارنة البتات في عددين صحيحين، ودالة `inv` (عكس) لقلب جميع البتات.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
