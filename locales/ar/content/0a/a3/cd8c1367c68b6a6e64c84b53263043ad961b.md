# حول

## الأخطاء في `jq`

يُبلّغ `jq` عن فئتين عريضتين من الأخطاء:

1. **أخطاء وقت الترجمة**: البرنامج نفسه غير صالح، مثل أخطاء نحوية، أو إشارات إلى دوال أو متغيرات غير معرّفة، وما إلى ذلك.
   يرفض `jq` تشغيل البرنامج كليًا.

   ```sh
   $ jq -n '1 + $foo + 2'
   jq: error: $foo is not defined at <top-level>, line 1, column 5:
       1 + $foo + 2
           ^^^^
   jq: 1 compile error
   ```

2. **أخطاء وقت التشغيل**: البرنامج صالح، لكن شيئًا ما يحدث خطأ أثناء معالجة قيمة، مثل فهرسة عدد بسلسلة نصية، أو تحليل نص JSON غير صالح باستخدام `fromjson`، أو استدعاء دالة بوسائط من نوع خاطئ، وما إلى ذلك.

   ```sh
   $ echo '42' | jq '.foo'
   jq: error (at <stdin>:1): Cannot index number with "foo"
   ```

يتناول هذا المفهوم **أخطاء وقت التشغيل**: كيف نثيرها، وكيف نلتقطها، وكيف نوقفها.

عندما لا يُلتقط خطأ وقت التشغيل، يطبع `jq` رسالة إلى _الخطأ القياسي_ ويخرج بحالة `5`.

## إثارة الأخطاء: `error` و`error(message)`

يثير المرشّح [`error`][man-error] خطأً.

- `error` يثير خطأً قيمته هي قيمة **المدخل**.
- `error(message)` يثير خطأً قيمته نتيجة `message`.

```jq
"bad input" | try error catch .
# => "bad input"

42 | try error("invalid value: \(.)") catch .
# => "invalid value: 42"
```

~~~~exercism/note
يمكن أن تكون قيمة الخطأ _أي_ قيمة JSON، وليست سلسلة نصية فقط.
وإثارة أخطاء مُهيكلة تتيح لمعالج `catch` أن يتخذ قرارات بناءً على محتوى الخطأ.

```jq
try error({kind: "range", msg: "age must be non-negative"})
catch (if type == "object" then "\(.kind) error: \(.msg)" else "unexpected: \(.)" end)
# => "range error: age must be non-negative"
```
~~~~

إذا لم تُلتقط قيمة خطأ ليست سلسلة نصية، يطبعها `jq` بصيغة JSON، موسومة بـ `(not a string)`.

```sh
$ jq -n 'error({code: 42, msg: "boom"})'
jq: error (at <unknown>) (not a string): {"code":42,"msg":"boom"}
```

## التقاط الأخطاء: `try` و`catch`

يمكن التقاط الأخطاء باستخدام [`try EXP catch HANDLER`][man-try-catch].
يُنفَّذ التعبير الأول، وإذا أثار خطأً يُنفَّذ تعبير `HANDLER` **وقيمة الخطأ هي مدخله**.
وتُخرَج مخرجات المعالج كما لو كانت مخرجات التعبير الذي جُرِّب.

```jq
true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]

true | try error("some exception") catch .
# => "some exception"
```

الصيغة الأقصر `try EXP` مكافئة لـ `try EXP catch empty`: يُهمل الخطأ ولا تُنتج أي مخرجات.

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

~~~~exercism/note
الخطأ **يُجهض بقية التدفق** داخل `try`.
تُحفظ القيم التي أُنتجت بالفعل، لكن لا يُقيَّم أي شيء بعد الخطأ.

```jq
jq -n 'try (1, error("x"), 3) catch "caught: \(.)"'
# outputs:
# 1
# "caught: x"
# (3 is never produced)
```
~~~~

يستطيع المعالج أن يثير خطأً جديدًا، أو أن يعيد إثارة الخطأ الأصلي باستخدام `error` وحدها، ولأن قيمة الخطأ هي مدخل المعالج فإن هذا يمرّرها دون تغيير.

```jq
try repeat(f) catch
  if . == "break" then empty else error end
```

## كبت الأخطاء: عامل `?`

العامل [`?`][man-question-mark]، عند استخدامه بالصيغة `EXP?`، اختصار لـ `try EXP`.
وهو يحوّل تعبيرًا فاشلًا إلى تعبير لا ينتج أي مخرجات ببساطة.

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]

true | [.a?]
# => []
```

وكثيرًا ما يظهر ملحقًا بعوامل الفهرسة:

- `.foo?` هي `.["foo"]?`
- `.[]?` لا يكرّر إلا إذا كان المدخل مصفوفة أو كائنًا، ويكون فارغًا خلاف ذلك

~~~~exercism/caution
يكبت `?` **كل** خطأ، بما في ذلك أخطاء لم تتوقعها.
فعندما لا يكون `user` كائنًا، ينتج `user.name?` لا شيء بصمت، وهذا قد يخفي مشكلات في البيانات أو أخطاء كتابية في برنامجك.
فضّل `try ... catch` عندما تحتاج إلى معرفة _أن_ شيئًا ما قد فشل، أو تحقّق من المدخل صراحةً.
~~~~

## عامل البديل `//`

يتوقع المبرمجون أحيانًا أن يُنتج `a // b` القيمة `b` عندما يفشل `a`.
كان هذا صحيحًا في إصدارات `jq` القديمة، لكنه لم يعد كذلك منذ `jq` 1.6.
عامل `//` لا يكبت الأخطاء.
إنه يستبدل `b` فقط عندما لا يُنتج `a` أي قيمة، أو يُنتج `false` أو `null`؛ أما الأخطاء في `a` فتنتشر كما هي.

```sh
$ jq -n '(error("x")) // 42'
jq: error (at <unknown>): x
```

استخدم `try a catch b` إذا أردت بديلًا احتياطيًا عند الأخطاء.

## عامل البديل مع التفكيك `?//`

يجمع العامل [`?//`][man-question-mark-slash-slash] بين التفكيك ومعالجة الأخطاء.
يجرّب كل نمط ربط بدوره حتى ينجح أحدها، وتُضبط المتغيرات التي ربطتها البدائل الفاشلة على `null`.

```jq
# input:
#   [
#     {"a": 1, "b": 2, "c": {"d": 3, "e": 4}},
#     {"a": 5, "b": 6, "c": [{"d": 7, "e": 8}]}
#   ]

.[] as {$a, $b, c: {$d, $e}} ?// {$a, $b, c: [{$d, $e}]}
| {$a, $b, $d, $e}

# outputs:
# {"a": 1, "b": 2, "d": 3, "e": 4}    # first element: c is an object, first pattern matched
# {"a": 5, "b": 6, "d": 7, "e": 8}    # second element: c is an array, second pattern matched
```

هنا يتوقع النمط الأول أن يكون `c` _كائنًا_ له مفتاحان `d` و`e`، بينما يتوقع الثاني أن يكون `c` _مصفوفة_ تحتوي على كائن كهذا.
يرتبط العنصر الأول من المدخل بالنمط الأول؛ أما العنصر الثاني فيفشل مع ذلك النمط، فيُجرَّب النمط الثاني بدلًا منه.

يتيح هذا لبرنامج واحد أن يفكك مدخلات قد تأخذ أحد أشكال عدة، من دون أن تكتب صراحةً تعبيرات مثل `if type == ...` واحدًا تلو الآخر.

## إيقاف البرنامج: `halt` و`halt_error`

أحيانًا يكون الرد الصحيح على خطأ هو التوقف عن المعالجة كليًا.

- [`halt`][man-halt] يوقف برنامج `jq` فورًا دون أي مخرجات إضافية؛ وحالة الخروج تكون `0`.
- [`halt_error`][man-halt-error] يوقف البرنامج، ويطبع **مدخله** إلى _الخطأ القياسي_ كنص خام (دون أي زخرفة، ولا حتى سطر جديد)، ويخرج بالحالة المعطاة، والتي تكون `5` افتراضيًا.

```sh
$ echo '"Error: something went wrong"' | jq 'halt_error(1)'
Error: something went wrong    # printed on stderr, exit status 1
```

لاحظ أن هذين المرشّحين يوقفان البرنامج فورًا، حتى لو بقيت مدخلات أخرى لم تُقرأ بعد.

### حالات الخروج

للمرجعية، يستخدم `jq` حالات الخروج هذه:

| الحالة | المعنى                                           |
| :----: | ------------------------------------------------ |
| `0`    | النجاح                                           |
| `2`    | خطأ في الاستخدام (خيارات سطر أوامر غير صالحة)    |
| `3`    | خطأ في الترجمة                                   |
| `5`    | خطأ وقت التشغيل (أو `halt_error` بلا وسيط)        |

مع الخيار `--exit-status` / `-e`، تعكس الحالة بدلًا من ذلك آخر قيمة مُخرَجة: `0` من أجل `true` أو الأعداد، و`1` من أجل `false` أو `null`، و`4` عند عدم وجود مخرجات.

## مساعدات تنقيح الأخطاء

عند تتبع مصدر خطأ ما، تساعدك هذه المرشّحات:

- [`debug`][man-debug] يمرّر مدخله كما هو دون تغيير، لكنه يطبع `["DEBUG:", <input>]` إلى الخطأ القياسي.
  و`debug(msgs)` يطبع الرسائل `msgs` كرسائل تنقيح أيضًا.
- [`stderr`][man-stderr] يطبع مدخله، خامًا ومضغوطًا، إلى الخطأ القياسي.
- [`input_line_number`][man-input-line-number] يُخرج رقم سطر المدخل الذي يُرشَّح حاليًا، وهو أمر بالغ الأهمية عندما يحتوي ملف على نصوص JSON كثيرة ويكون أحدها تالفًا.
- [`$__loc__`][man-loc] يُخرج كائنًا بمفتاحَي `file` و`line` يصف موضع حدوثه في البرنامج، ويمكن تضمينه في رسائل الخطأ.

```jq
def checked_div($d):
  if $d == 0
  then error("\($__loc__): division by zero")
  else . / $d end;

try (10 | checked_div(0)) catch .
# => "{\"file\":\"<top-level>\",\"line\":3}: division by zero"
```
