# التعليمات

أنت تكتب الكود لنظام البيانات في مصنع لقطع السيارات.
تنتقل مكوّنات المحرك والهيكل عبر عدد من محطات التشغيل الآلي.
تُنتج كل محطة قياسات يجب دمجها ومقارنتها ومعايرتها وتطبيعها قبل أن تبدأ المرحلة التالية.
والدوال التي تنفذها هنا هي دالة واحدة لكل محطة.

~~~~exercism/note
يجب إجراء الحسابات في هذا التمرين باستخدام تعليمات SIMD، لا باستخدام العمليات العددية المفردة.
~~~~

## 1. دمج النواتج من خطَّي إنتاج

يشغّل المصنع خطَّي تجميع متوازيين.
في نهاية كل وردية، يبلّغ الخطان عن نواتجهما لأربع سلال من القطع في صورة أعداد مفردة الدقة.
تعرض لوحة تحكم المشرف الناتج المدمج لكل سلة، لذا يُجمع التقريران سلة بسلة.
يدير نظام التقارير المخازن الثلاثة جميعها، وهي دائمًا محاذية بمقدار 16 بايت.

عرّف دالة `sum_yields` تكتب، عند إعطائها النواتج لكل سلة من `line_a` و`line_b`، المجموع سلة بسلة في `result`.
الوسائط، بالترتيب، هي:

1. `line_a`: عنوان ذاكرة محاذٍ بمقدار 16 بايت ويحمل 4 أعداد عائمة بطول 32 بت
2. `line_b`: عنوان ذاكرة محاذٍ بمقدار 16 بايت ويحمل 4 أعداد عائمة بطول 32 بت
3. `result`: عنوان ذاكرة محاذٍ بمقدار 16 بايت ستكتب فيه الدالة 4 أعداد عائمة بطول 32 بت

لا تُرجع هذه الدالة أي قيمة، وإنما يُخزَّن الناتج في المخزن المؤقت الممرَّر (`result`):

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. حساب الانحراف المُقيَّس

بين العمليات، تقيس محطة أخذ العينات القطع المشغولة آليًا وتقارنها بالأبعاد المستهدفة.
تتدفق القيم المقيسة من مقياس دقيق إلى مخزن محاذٍ دائمًا بمقدار 16 بايت.
تأتي القيم المستهدفة من حزمة أمر العمل، وهي لا تضمن المحاذاة.
يُضرب الانحراف في معامل حساسية لكل محور قبل تمريره إلى فاحص التفاوتات اللاحق.
في هذه المرحلة، يقرأ الفاحص اللاحق الانحراف مباشرةً من مسجّل SIMD بدلًا من الذاكرة.

عرّف دالة `scaled_deviation` تكتب، عند إعطائها `measured` و`target` و`sensitivity`، الانحراف المُقيَّس في `result`.
الوسائط، بالترتيب، هي:

1. `measured`: عنوان ذاكرة محاذٍ بمقدار 16 بايت ويحمل عددين عائمين بطول 64 بت
2. `target`: عنوان ذاكرة يحمل عددين عائمين بطول 64 بت (المحاذاة غير مضمونة)
3. `sensitivity`: عنوان ذاكرة يحمل عددين عائمين بطول 64 بت (المحاذاة غير مضمونة)
4. `result`: عنوان ذاكرة لمخزن ستكتب فيه الدالة عددين عائمين بطول 64 بت (المحاذاة غير مضمونة)

الانحراف المُقيَّس هو `(measured - target) * sensitivity`، مسارًا بمسار.

لا تُرجع هذه الدالة أي قيمة، وإنما يُخزَّن الناتج في المخزن المؤقت الممرَّر (`result`) في صورة عددين عائمين بطول 64 بت.

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. معايرة دفعة

قبل دخول القطع إلى منطقة الفحص النهائي، تُعاد قراءات الأبعاد لدفعة من 4 قطع إلى الدقة المزدوجة وتُصحَّح لمراعاة الانزياح الحراري المعروف.

تصل القراءات الخام الأربع في صورة أعداد مفردة الدقة.
لكل صف من قراءتين، تحسب المعايرة `reference / (raw - offset)`، ثم تضرب هذا الناتج في معامل تحويل ثابت قيمته `0.5`.

لاحظ أن المرجع والإزاحة متماثلان في صفَّي الدفعة.
معامل التحويل متماثل في كل معايرة، لذا بدلًا من تمريره كوسيط، عليك تعريفه كثابت مُحزَّم بطول 16 بايت في الذاكرة.

عرّف دالة `calibrate_batch` تكتب، عند إعطائها دفعة `raw`، و`reference`، و`offset`، ومخزن `result`، القيم المعايَرة في `result`.
الوسائط، بالترتيب، هي:

1. `raw`: عنوان ذاكرة يحمل 4 أعداد عائمة بطول 32 بت (المحاذاة غير مضمونة)
2. `reference`: عنوان ذاكرة محاذٍ بمقدار 16 بايت ويحمل عددين عائمين بطول 64 بت
3. `offset`: عنوان ذاكرة محاذٍ بمقدار 16 بايت ويحمل عددين عائمين بطول 64 بت
4. `result`: عنوان ذاكرة محاذٍ بمقدار 16 بايت ستكتب فيه الدالة 4 أعداد عائمة بطول 64 بت (32 بايت إجمالًا)

يجب أن تنفّذ الدالة، لكل صف من صفَّي الدفعة، ما يلي:

1. تحويل قيمتَي الصف الخامّتين المفردتَي الدقة إلى الدقة المزدوجة.
2. طرح `offset` من الزوج المحوَّل.
3. قسمة `reference` على الناتج.
4. ضرب كل عدد عائم بطول 64 بت في معامل التحويل الثابت `0.5`، مسارًا بمسار.
5. تخزين العددين العائمين بطول 64 بت في البايتات الـ16 المقابلة من `result`.

لا تُرجع هذه الدالة أي قيمة، وإنما يُخزَّن الناتج في المخزن المؤقت الممرَّر (`result`):

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. تطبيع الدرجات على طول الخط

في نهاية الخط، لكل قطعة درجة جودة تحتاج إلى تطبيع قبل الإبلاغ عنها.
تُضرب كل درجة في معامل الكسب الخاص بها لكل قطعة، ثم تُقسم على مقياس إنتاج خاص بكل محور.
يحمل مخزن معاملات الكسب معامل كسب واحدًا لكل قطعة.

مقياس الإنتاج متماثل في الدورة كاملة ويُمرَّر في عنوان ذاكرة يحمل عددين عائمين بطول 64 بت.
تُحدَّث الدرجات **في مكانها**: المخزن نفسه الذي كان يحمل الدرجات الخام يحمل الآن الدرجات المطبَّعة.

عرّف دالة `normalize_scores` تطبّع الدرجات في مكانها، عند إعطائها مصفوفة `scores`، ومصفوفة `gains`، و`scale`، وعددًا `n`.
الوسائط، بالترتيب، هي:

1. `scores`: عنوان ذاكرة محاذٍ بمقدار 16 بايت يحمل `n` من الأعداد العائمة بطول 64 بت (يُعدَّل في مكانه)
2. `gains`: عنوان ذاكرة محاذٍ بمقدار 16 بايت يحمل `n` من الأعداد العائمة بطول 64 بت
3. `scale`: عنوان ذاكرة محاذٍ بمقدار 16 بايت يحمل عددين عائمين بطول 64 بت
4. `n`: عدد صحيح موجب زوجي بطول 64 بت (بحد أدنى `2`)، وهو عدد الدرجات المطلوب تطبيعها

ينطبق مسارا المقياس على عنصري كل زوج.
يطبّق المسار الأول المقياس على العنصر الأول من كل زوج (المسارات في المواضع الزوجية)، ويطبّق المسار الثاني المقياس على العنصر الثاني (المسارات في المواضع الفردية).
تُضرب كل درجة في معامل الكسب المقابل لها، ثم تُقسم على مسار المقياس المناسب: `score * gain / scale_lane`.

لا تُرجع هذه الدالة أي قيمة، وإنما يُخزَّن الناتج في مخزن الإدخال (`scores`)، في الموضع نفسه للدرجة `score` المقابلة التي طُبِّعت:

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
