# مقدمة

يحتفظ *مُرسِل الإشارات* على متن سفينة دورية ساحلية بسجل الرسائل. تأتي رايات الإشارة الخام مؤطَّرة بأحرف علامات؛ ولا بد من تجهيز القراءات لإرسالها عبر السلك؛ ويجري تلخيص أزواج الملاحظات وثلاثياتها فورًا. وتقوم مجموعة صغيرة من التعابير الاصطلاحية من مكتبة Factor القياسية بمعظم العمل.

## `unparse`: من القيمة إلى الكود المصدري

تُرجع [`unparse`][unparse] (في `prettyprint`) نصَّ أي قيمة بصيغة الكود المصدري:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

‏`unparse` هي عكس المُحلِّل، فالذهاب والإياب عبر `dup unparse parse` يعيد بناء القيمة. وهي الأداة المناسبة للتحويل إلى صيغة سلكية سيعيد المستقبل تحليلها، والأداة الخاطئة لإخراج يقرأه الإنسان (فالسلاسل النصية تحتفظ بعلامات الاقتباس، والمتجهات تحتفظ بـ `V{ ... }`، وهكذا).

## متغيّرات الشريحة: عروض لا نُسخ

تنسخ `head` و`tail` من `sequences` *الجزء* الذي تحتفظ به إلى تسلسل جديد. أما نظيراتهما المنتهية بـ `-slice` فتُرجع كائن `slice`، وهو صف يحمل فهرس البداية وفهرس النهاية والتسلسل الأساسي، وينفّذ [بروتوكول التسلسل][sequence-protocol] دون نسخ:

| الكلمة        | التأثير                                          |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )`: نسخ أول `n` عنصرًا        |
| `head-slice`  | `( seq n -- slice )`: عرض أول `n` عنصرًا         |
| `tail`        | `( seq n -- newseq )`: نسخ من الفهرس `n` فما بعده |
| `tail-slice`  | `( seq n -- slice )`: عرض من الفهرس `n` فما بعده |
| `head*`       | `( seq n -- newseq )`: نسخ الكل عدا آخر `n` عنصرًا |
| `head-slice*` | `( seq n -- slice )`: عرض الكل عدا آخر `n` عنصرًا |
| `tail*`       | `( seq n -- newseq )`: نسخ آخر `n` عنصرًا        |
| `tail-slice*` | `( seq n -- slice )`: عرض آخر `n` عنصرًا         |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

إن كائن `slice` *هو* تسلسل، لذا فكل ما يقبل تسلسلًا يقبل شريحة؛ فـ `length` و`first` و`each` وغيرها تعمل كلها دون نسخ. ويمكن للاختبارات التي تحتاج إلى المقارنة بسلسلة نصية حرفية أن تحوّل النوع بـ `>string`.

## `?head` و`?tail`: إزالة علامة إن وُجدت

تحمل القراءات المؤطَّرة نصًّا علاميًّا قد يكون موجودًا وقد لا يكون. و`?head` و`?tail` (في `splitting`) تحاولان إزالة بادئة أو لاحقة، فتُرجعان التسلسل (الذي قد يكون مختصرًا) *و* قيمة منطقية تخبر بما إذا وُجدت العلامة:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

وتجعل القيمة المنطقية الختامية منهما أداة مناسبة للتحقق الشرطي: اقرن `?head` بـ `if` للتفرّع حسب وجود الإطار، أو بـ `unless` لرفض أي مدخل يفتقر إلى العلامة المتوقعة.

## `<repetition>`: N من النسخ الافتراضية

‏[`<repetition>`][repetition] (في `sequences`) تسلسل افتراضي آخر لا ينسخ؛ فالصيغة `( len elt -- repetition )` تبني تسلسلًا مكوّنًا من `len` عنصرًا كلها `elt`، دون تخصيص هذا العدد من الخانات:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

ويمكن أن يكون `elt` نفسه تسلسلًا، فتكون كل نسخة هي التسلسل ذاته. ثم يَصِل `concat` النسخ بعضها ببعض من طرف إلى طرف:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

ومثل `slice`، فإن الناتج *هو* تسلسل، فتعمل عليه `length` و`each` وأخواتها مباشرة. استخدمه لحشو رمز إشارة إلى عرض ثابت، أو لإنشاء تتابع من العلامات المتكررة؛ ولا تلجأ إلى التحويل بـ `>string` (أو `>array`) إلا عند الحاجة الفعلية إلى تسلسل ملموس.

## `<clumps>`: نوافذ متراكبة افتراضية

‏[`<clumps>`][clumps] (في `grouping`) تسلسل افتراضي ثالث لا ينسخ؛ فالصيغة `( seq n -- clumps )` تعرض `seq` على هيئة تتابع من نوافذ *متراكبة* بطول `n`، كل نافذة منها شريحة:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

ويعطي تسلسل طوله `n` عددًا من النوافذ يساوي `length - n + 1`. ولأن كل نافذة شريحة، فإن قرن القراءات المتتالية لا يكلّف شيئًا من النسخ: إذ يمنحك `[ first2 ]` على كل تجميعة مكوّنة من `2` عنصرين كل زوج متتالٍ لتشتق منه النتيجة. (أما نظيره غير المتراكب، `<groups>`، فيقطّع التسلسل إلى كتل غير متقاطعة بدلًا من ذلك.)

## كلمات `cleave` متعددة المدخلات: `2bi` و`3bi` و`2tri` و`3tri`

تطبّق كلمتا `cleave` العاديتان `bi` و`tri` كتلتين برمجيتين أو ثلاثًا على مدخل *واحد*. أما المتغيّرات المسبوقة بـ `2` والمسبوقة بـ `3` فتطبّق كل كتلة برمجية على مدخلين *أو* ثلاثة:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

تتلقى كل كتلة برمجية *كل* المدخلات. استخدم هذه الكلمات عندما تعتمد أكثر من نتيجة مشتقة على الزوج نفسه (أو الثلاثي نفسه) من القيم، لا عندما تريد تطبيق العملية *نفسها* على كل مدخل على حدة (فتلك مهمة `bi@` أو `tri@`).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
