# المقدمة

توفّر الاستثناءات في Ruby، كما في لغات كثيرة، وسيلة للتعامل مع الأحداث غير المتوقعة. والتعامل السليم مع الاستثناءات مهم عندما تحاول منع برنامجك من الانهيار.

عندما يُطرح استثناء، سواء بطرحه صراحةً أو بطرح مفسّر Ruby له، يُحوّل البرنامج مسار تشغيله الطبيعي وينتهي في النهاية برسالة خطأ:

```ruby
raise ArgumentError.new("Something went wrong!")
=> Traceback (most recent call last):
.
.
ArgumentError (Something went wrong!)
```

```ruby
1/0
=> Traceback (most recent call last):
.
.
ZeroDivisionError (divided by 0)
```

وإذا أردنا إيقاف عملية الإنهاء هذه، فعلينا أن نتفاعل مع الاستثناء. وهذا ما يسمى «إنقاذ» الاستثناء:

```ruby
begin
  # ...any code that raises an exception
rescue
  puts 'Got an exception'
end
```

لن ينهار هذا البرنامج، وسيطبع "Got an exception". فبدلًا من الخروج، ينفّذ Ruby الكود الموجود في كتلة `rescue`، وهي تطبع رسالة.

وكما هو الحال في كل شيء في Ruby، فإن الاستثناءات أيضًا كائنات، وعادةً ما تحمل بيانات عن الاستثناء. وهكذا يمكننا الحصول على كائن الاستثناء:

```ruby
begin
  # ...any code that raises an exception
rescue => e
  puts "Exception class: #{ e.class.name }"
  puts "Exception Message:#{e.message}"
end
```

في Ruby يمكنك أيضًا طرح استثناءاتك الخاصة. على سبيل المثال:

```ruby
begin
  raise ArgumentError.new("Invalid argument")
rescue ArgumentError => e
  puts e.message
end
```

الاستثناء السابق هو أحد الاستثناءات المدمجة في Ruby، لكن يمكنك أيضًا تعريف استثناءات مخصصة وطرحها:

```ruby
class CustomError < StandardError
end

raise CustomError.new("Something went wrong")
```
