# مقدمة

*الطابور المزدوج النهايات* (deque) يدعم الدفع والسحب من كلا الطرفين في زمن O(1). التطبيق القياسي في Factor هو `<dlist>` (قائمة مرتبطة مزدوجة) ضمن [`dlists`][dlists]، وتوجد العمليات في [`deques`][deques].

## واجهة API للطابور المزدوج النهايات

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

تفرّغ `clear-deque` الطابور المزدوج النهايات في مكانه، وهو أمر مفيد لإعادة استخدامه دون إعادة تخصيص الذاكرة.

الدفع والسحب من الطرف نفسه يمنحك مكدسًا بنمط LIFO. أما الدفع من أحد الطرفين والسحب من الطرف الآخر فيمنحك طابورًا بنمط FIFO:

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

أما من أجل LIFO فستستخدم متجهًا (`V{ }`) مع `push`/`pop`، إذ تقلّ تكلفته لكل عملية. والجأ إلى `<dlist>` عندما تحتاج إلى زمن O(1) عند *كلا* الطرفين، وهذا هو الحال في طابور FIFO غالبًا.

## البحث بالعرض أولًا

استخدام FIFO هو ما يجعل الطوابير المزدوجة النهايات الحدود المناسبة لـ *BFS*. تبدأ بعقدة واحدة، وتدفع العقد المجاورة إلى الخلف، وتسحب المرشّحات من المقدمة، وتزيل التكرارات باستخدام مجموعة تجزئة:

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

تُزار المرشّحات الأقدم قبل الأحدث، فيزحف البحث نحو الخارج في طبقات بدءًا من نقطة البداية. وهذا ما يمنح *BFS* خاصية أقصر مسار: فأول مرة تصل فيها إلى عقدة الهدف تكون عبر مسار بأقل عدد من القفزات.

## `MEMO:`، التخزين المؤقت التلقائي

أحيانًا تكون عملية البحث التي يجريها BFS عند كل عقدة مكلفة. تمنحك مفردات [`memoize`][memoize] في Factor الصيغة `MEMO:`، وهي بديل مباشر لـ `:` يخزّن نتيجة الكلمة مؤقتًا وفقًا لمدخلاتها:

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

تشغّل كلمة `MEMO:` جسمها في أول مرة يُرى فيها كل مدخل، ثم تُرجع النتيجة المخزّنة مؤقتًا بعد ذلك؛ الواجهة نفسها، دون استدعاءات إضافية في موقع الاستدعاء، وأسرع فقط عند تكرار المدخلات.
