# التعليمات

أنت تكتب البرامج الثابتة لنظام تسجيل النتائج في جهاز ألعاب محمول قديم الطراز.
وحدة المعالجة المركزية في الجهاز متواضعة، وتُحدَّث شاشة عرض النتائج بمعدل ثابت.
ولكي تبقى الصورة سلسة، يجب أن تعمل روتينات تسجيل النتائج في عدد من الدورات يمكن التنبؤ به، بصرف النظر عما يفعله اللاعب.

لديك أربع مهام.

~~~~exercism/note
ينبغي أن يكون الكود الخاص بالمهام خاليًا من الفروع.
استخدم `cmovcc` و`setcc` والعمليات الحسابية بدلًا من القفزات الشرطية.
~~~~

## 1. إضافة مكافأة دون تجاوز حد الشاشة

تحتوي منطقة النتائج في شاشة الجهاز على مساحة لستة أرقام عشرية.
ولا يمكنها عرض أي عدد يتجاوز `999999`.
وعندما تدفع مكافأة الإجمالي الجاري إلى ما يتجاوز هذا الحد، يُثبَّت الإجمالي المعروض عند الحد الأقصى بدلًا من أن يلتف إلى الصفر.

عرّف دالة `add_bonus` تُرجع، عند إعطائها إجماليًا حاليًا ومكافأة تُضاف، الإجمالي الجديد مقيّدًا عند `999999`.
الوسائط، بالترتيب، هي:

1. `total`: إجمالي النتيجة الحالي (دائمًا بين `0` و`999999`)
2. `bonus`: المكافأة المراد إضافتها (دائمًا غير سالبة)

القيمة المُرجَعة هي `total + bonus` إذا كان هذا المجموع أقل من أو يساوي `999999`، و`999999` خلاف ذلك:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

الوسائط والقيمة المُرجَعة جميعها أعداد صحيحة موقّعة بطول 64 بت.

~~~~exercism/note
يمكنك أن تفترض أن `total + bonus` لا يتجاوز سعة عدد صحيح موقّع بطول 64 بت.
~~~~

## 2. مقارنة نتيجتين

يحتفظ الجهاز بلوحة صدارة صغيرة لأفضل نتائج اللاعب الحديثة في ملف الحفظ الخاص به.
بعد كل جلسة لعب، تُدرَج النتيجة الجديدة في لوحة الصدارة في الموضع الصحيح.
يسأل روتين الترتيب أي النتيجتين متقدّمة، وينتظر الإجابة على هيئة عدد صحيح صغير.

عرّف دالة `compare_scores` تُرجع، عند إعطائها نتيجتين:

- `+1` إذا كانت النتيجة الأولى _أعلى_
- `-1` إذا كانت النتيجة الأولى _أدنى_
- `0` إذا كانت النتيجتان _متساويتين_

مثال:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

الوسائط والقيمة المُرجَعة جميعها أعداد صحيحة موقّعة بطول 64 بت.

## 3. التحقق من نتيجة خام

يمكن للجهاز الاتصال بجهاز آخر عبر كابل الربط لتبادل النتائج بعد مباراة جماعية.
الكابل مشوّش كهربائيًا، وتتلف البايتات الواردة أحيانًا، ما ينتج قيمًا أقل بكثير من الحد الأدنى المسموح أو أعلى بكثير من الحد الأقصى المسموح.
ويقيّد المدقّق كل نتيجة واردة ضمن النطاق المسموح قبل أن يراها بقية النظام.

عرّف دالة `validate_score` تُرجع، عند إعطائها نتيجة خام والحدود المسموح بها، النتيجة مقيّدة ضمن `[min, max]`.
الوسائط، بالترتيب، هي:

1. `score`: النتيجة الخام الواردة عبر كابل الربط
2. `min`: أصغر نتيجة مسموح بها
3. `max`: أكبر نتيجة مسموح بها

القيمة المُرجَعة هي `min` إذا كان `score < min`، و`max` إذا كان `score > max`، و`score` خلاف ذلك.
يمكنك أن تفترض أن `min <= max`.

مثال:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

جميع الوسائط والقيمة المُرجَعة أعداد صحيحة موقّعة بطول 64 بت.

## 4. تتبّع أعلى نتيجتين

في نهاية كل جلسة لعب، يمسح الجهاز سجل الجلسات الأخيرة في ملف الحفظ الخاص به للعثور على أعلى نتيجتين مسجّلتين على الإطلاق.
والسجل عبارة عن مصفوفة عادية من أعداد صحيحة موقّعة بطول 64 بت في الذاكرة.
يمر المسح على المصفوفة مرة واحدة ويحتفظ بقيمتين أعلى متحركتين: الأعلى حتى الآن، والثاني في الترتيب.

لاحظ أن كلا العددين ينبغي أن يكون على الأقل `0`.
ويُتجاهل أي عدد سالب.

كُتبت أول نسخة من الدالة بقفزات شرطية متتالية.
فلكل مرشّح، يسأل الكود أين يقع (فوق الأول، بين الأول والثاني، أو لا مكان له)، ثم يزيح القيمتين الأعلى المتحركتين تبعًا لذلك، متجاهلًا أي نتيجة سالبة.

هذا يعمل.
لكن بما أن قيم الإدخال عشوائية، فإن كل قفزة شرطية تؤدي إلى أخطاء كثيرة في التنبؤ بالفروع.
ولهذا قررت إعادة كتابة الحلقة الرئيسية لتكون خالية من الفروع.

في ما يلي الدالة وقد عُلّق فيها الجزء الذي يستخدم الفروع:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

استبدل الجزء المعلّق بتنفيذ خالٍ من الفروع.
والقفزة الوحيدة المسموح بها في الكود الجديد هي التي تعود إلى بداية الحلقة لفحص عنصر جديد في المصفوفة.

لا تُرجع الدالة أي قيمة، وتأخذ نفس وسائط النسخة المتفرّعة:

1. `out`: المخزن المؤقت للإخراج الذي ستكتب فيه الدالة أعلى نتيجتين غير سالبتين بترتيب تنازلي، كأعداد صحيحة موقّعة بطول 64 بت
2. `array`: مصفوفة الإدخال من أعداد صحيحة موقّعة بطول 64 بت
3. `length`: عدد العناصر في المصفوفة، كعدد صحيح غير موقّع بطول 64 بت

~~~~exercism/note
إذا احتوت المصفوفة على قيم مكرّرة، فقد تظهر القيم المكرّرة في خانتي الإخراج كلتيهما إذا كانتا أعلى نتيجتين.
~~~~
