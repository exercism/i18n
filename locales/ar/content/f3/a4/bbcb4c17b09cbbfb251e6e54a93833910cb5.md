# نبذة

الدوال العودية هي دوال تستدعي نفسها.

تحتاج الدالة العودية إلى _حالة أساسية_ واحدة على الأقل وإلى _حالة عودية_ واحدة على الأقل.

الحالة الأساسية تُرجع قيمة دون استدعاء الدالة مرة أخرى.
أما الحالة العودية فتستدعي الدالة مرة أخرى، مع تعديل المدخل بحيث يطابق الحالة الأساسية في مرحلة ما.

في Elm، تُعرَّف الدوال العودية عادةً باستخدام مطابقة الأنماط مع تعبيرات `case`.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

يمكن أن تحتوي الدالة العودية على حالات أساسية كثيرة و/أو حالات عودية كثيرة.
على سبيل المثال، [متتالية فيبوناتشي][fibonacci] متتالية عودية لها حالتان أساسيتان:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

لاحظ أن هذا التنفيذ تحديدًا بطيء بشكل أسي، لأن أعداد فيبوناتشي المتقاربة تُحسب من الصفر في استدعاءين عوديين مستقلين.

أما عدّ عدد مرات ظهور قيمة معطاة `x` في مصفوفة فله حالتان عوديتان:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## الحلقات عبر العودية

بسبب الثبات، تُكتب الحلقات في Elm بطريقة مختلفة عن اللغات الأمرية.
على سبيل المثال، تبدو الحلقات عادةً هكذا:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

في لغة وظيفية مثل Elm، لا يمكن تغيير قيم المتغيرات.
لذلك لا بد من تنفيذ الحلقات بالعودية.

المقابل لحلقة `for` في Elm سيبدو هكذا:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

عمليًا، يتم المرور على المصفوفات وغيرها من بنى البيانات في Elm في معظم الأحيان باستخدام دوال من وحدة [`List`][module-list]، مثل `List.map` و`List.filter` و`List.foldl`.
وتُنفَّذ هذه الدوال في العمق بالعودية.

## التنفيذ اللانهائي

قد لا تُرجع الدوال العودية نتيجتها أبدًا إذا نُفِّذت بشكل خاطئ أو إذا كان عدد الاستدعاءات العودية كبيرًا جدًا.
وقد يكون هذا مشكلة لأن كل مرة تُستدعى فيها دالة، يُخزَّن في الذاكرة مرجع يحدد المكان الذي ينبغي أن تُرجع فيه بيئة التشغيل النتيجة (على [مكدس الاستدعاءات][wiki-call-stack]).
إذا استدعت الدالة العودية نفسها مرات كثيرة جدًا أو حتى بلا نهاية، فمن الممكن أن تنفد الذاكرة، ما يؤدي إلى انهيار بيئة التشغيل (وهو [خطأ تجاوز سعة المكدس][wiki-stack-overflow]).
بيئة تشغيل Elm محسّنة للعودية والموثوقية، لكن العودية اللانهائية قد تُسبب مشكلات رغم ذلك.

يمكن أن تنشأ مشكلة التنفيذ اللانهائي هذه عن:

- نسيان تنفيذ حالة أساسية.
- عدم معالجة جميع الحالات الممكنة في مطابقة الأنماط.
- عدم تعديل الوسيط بشكل صحيح عند إجراء الاستدعاء العودي، وبالتالي عدم الوصول إلى الحالة الأساسية أبدًا.
