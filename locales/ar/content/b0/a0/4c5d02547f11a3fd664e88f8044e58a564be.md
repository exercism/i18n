# نبذة

## JSON

[JSON][json] (JavaScript Object Notation) صيغة بيانات وملفات مقروءة للبشر، تُستخدم عادةً لتبادل البيانات، ولا سيما في تطبيقات الويب.
ولذلك لا عجب أن تكون له مكانة خاصة في لغة Elm.

توفّر Elm وحدتَي [`Json.Decode`][decode] و[`Json.Encode`][encode] الأساسيتين لتحليل بيانات JSON وكتابتها.
مفكّكات JSON وسيلة _للتصريح_ بنوع البيانات المتوقَّع وببنية البيانات التي ينبغي أن تُنسب إليها.
عند القدوم من لغات ذات أنواع ديناميكية، تبدو المفكّكات غالبًا مرهقة أو شديدة الصرامة من النظرة الأولى.
ومع أنها مُسهبة بالتأكيد، في Elm على الأقل، فهي أداة قيّمة لوصف توقعات البرامج من البيانات الواردة وصفًا صريحًا، وهي [لا تقل تعبيرًا عن الأنواع الديناميكية][dynamic-types-not-more-open].

لنستورد بعض الأسماء المستعارة والأنواع من الوحدات:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

استخدام `Decode.decodeString : Decoder a -> String -> Result Error a` مع مفكّك وسلسلة نصية بصيغة JSON إما أن ينجح إذا توافقت السلسلة النصية مع مواصفات المفكّك، وإما أن يفشل في غير ذلك.
لا توجد طريقة لفحص بيانات JSON الخام أثناء تعريف المفكّك، وقد يبدو ذلك غير معتاد لمن يأتي من اللغات الأمرية.

## مفكّكات أنواع البيانات الأساسية

يحتوي JSON على عدد قليل من أنواع البيانات الأساسية:

- سلسلة نصية: تُرمَّز بعلامات تنصيص مزدوجة `"hello world"`
- قيمة منطقية: إما `true` وإما `false`
- عدد: مثل `34` أو `0.12`
- العدم: غياب البيانات `null`

يرتبط كل منها بدالة في `Decode`:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

لاحظ أن `Decode.null` تتيح لك تحديد كيفية نمذجة `null` في برنامجك عبر طلب قيمة عشوائية كوسيط (ربما `()` أو `Nothing` أو أي شيء مناسب لبرنامجك).

## دمج المفكّكات

يعرّف JSON أيضًا بنيتين من بنى البيانات لتجميع أنواع البيانات الأساسية:

- مصفوفة: مجموعة من أنواع بيانات أخرى `[0, null, "none", []]`
- كائن: مجموعة من أزواج المفتاح والقيمة `{"id": 1, "is_admin": false, "more_info": {}}`

كما توفّر `Decode` دوال لفكّ ترميز هذه الأنواع:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

تتوقع كلٌّ من `Decode.list : Decoder a -> Decoder (List a)` و`Decode.dict : Decoder a -> Decoder (Dict String a)` مفكّكًا كوسيط، يُتوقع منه فكّ ترميز كل عنصر من عناصر بنية البيانات.
إذا فشل المفكّك الممرَّر كوسيط في فكّ ترميز أي عنصر من عناصر قيمة مصفوفة أو كائن، فشل المفكّك بأكمله، وهذا نمط شائع.

دمج المفكّكات البسيطة في مفكّكات أكثر تعقيدًا هو الفكرة الجوهرية لهذه التقنية.
سنقدّم عدة دوال أخرى يمكن استخدامها لبناء مفكّكات بيانات واقعية بالغة التعقيد من خلال مثال.

## GeoJSON

للتدرب على دمج المفكّكات الأساسية لتحليل بيانات JSON المعقدة، لنبنِ مفكّكات لتحليل (مجموعة فرعية من) بيانات GeoJSON.
[GeoJSON][geojson] صيغة بيانات متخصصة قائمة على JSON تُستخدم لتمثيل معالم جغرافية، مثل المواقع أو المسارات أو المناطق، محدَّدة بإحداثيات جغرافية ثنائية أو ثلاثية الأبعاد، إلى جانب خصائص أخرى.

### كائن الهندسة

كائن الهندسة في GeoJSON هو كائن يحتوي على حقل `type` بقيمة سلسلة نصية (هناك 7 قيم ممكنة للنوع) وحقل `coordinates` بإحداثيات جغرافية (مجمَّعة في بنية تعتمد على النوع).
على سبيل المثال،

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

أو

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

يمكن تمثيل كائن الهندسة في Elm بالنوع التالي

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

لفحص قيمة حقل معيّن، يمكننا استخدام `Decode.field : String -> Decoder a -> Decoder a`، الذي يفكّ ترميز قيمة مفتاح محدد في كائن.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

لتحويل القيمة التي حلّلها المفكّك بنجاح، يمكننا استخدام `Decode.map : (a -> value) -> Decoder a -> Decoder value`، أو أيًّا من نظائره، من `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` إلى `Decode.map8`.

في هذه الحالة، نريد تحديد مفكّك الإحداثيات الذي نستخدمه بناءً على القيمة في حقل `type`، وهي مهمة مثالية لـ `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` ورفاقها `Decode.succeed : a -> Decoder a` و`Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

لاحظ عند هذه النقطة أنه يمكننا استخدام `Decode.andThen` للتحقق من صحة الإحداثيات (بالتأكد من أن الإحداثيات تأتي في أزواج أو ثلاثيات، ومن أن قيم الإحداثيات منطقية جغرافيًا).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### كائن Feature

يمثّل كائن Feature في GeoJSON شيئًا محدَّدًا مكانيًا: له حقل `type` بالقيمة `"Feature"`، وحقل `geometry` بكائن هندسة أو `null`، وحقل `properties` بكائن JSON عشوائي أو `null`، وحقل `id` اختياري بقيمة سلسلة نصية أو عدد.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

أو

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

لنعالج حقل `id` أولًا.
إذا كان موجودًا، فيجب أن يستوعب السلاسل النصية أو الأعداد، لذا يمكننا إما إنشاء نوع مخصص للقيمة أو حفظه دائمًا كسلسلة نصية.

للاختيار بين مفكّكين محتملين، يمكننا استخدام `Decode.oneOf : List (Decoder a) -> Decoder a`.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

للتعبير عن أن الحقل اختياري، يمكننا استخدام التقنية نفسها

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

لكن يمكننا بدلًا من ذلك استخدام `Decode.maybe : Decoder a -> Decoder (Maybe a)`

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

لاحظ أن `decodeMaybeFeatureId` (أو أي مفكّك ملفوف بـ `Decode.maybe`) سينجح دائمًا لأنه يستطيع دائمًا الرجوع إلى `Ok Nothing`، مع أن المفكّك الذي يستخدمه قد يفشل رغم ذلك

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

بعد ذلك، لنركّز على حقل `geometry`، الذي يمكن أن يكون كائن هندسة أو `null`.
يمكننا استخدام `Decode.oneOf` مرة أخرى، لكن هناك خيار أفضل: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

لـ `Decode.maybe` و`Decode.nullable` التوقيع نفسه، لكن سلوكهما مختلف، لأن نتيجة `OK Nothing` التي يعيدها `Decode.nullable` لا تأتي إلا من قيمة JSON المحددة `null`.

أخيرًا، يمكن أن يحتوي حقل `properties` على كائن JSON عشوائي أو `null`، وهذه مهمة `Decode.value : Decoder Value`.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

لاحظ أن `Value` نوع معتم، ما يعني أنك لا تستطيع فحص محتواه بسهولة.
لاستخدامه، يمكنك إما كتابة مفكّك له وتشغيله بـ `Decode.decodeValue : Decoder a -> Value -> Result Error a`، أو إرساله إلى JavaScript مباشرة عبر `port`.

أصبحنا جاهزين لتحليل كائنات Feature:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## مُرمِّزات JSON

تتيح المرمّزات كتابة JSON صالح من قيم Elm باستخدام الدالة `Encode.encode : Int -> Value -> String`.
يحدّد الوسيط الأول مقدار المسافة البادئة في النتيجة النهائية، والوسيط الثاني هو قيمة JSON المراد كتابتها.

يمكن الحصول على `Value` إما من `Decode.value` وإما من أحد المرمّزات:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

وكذلك باستخدام `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

لنعرّف مرمّزات لمفكّكات GeoJSON المعرَّفة سابقًا

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

عمومًا، الاختبار الجيد لأزواج المفكّك والمرمّز هو التحقق من أن `elmValue |> encoder |> decoder == elmValue`.

## ماذا أيضًا؟

لم نغطِّ كل دالة في وحدات `Json`.
من الأمور التي لم نذكرها: مفكّكات لتحويل المصفوفات إلى `Array` أو الكائنات إلى `List (String, a)`، ومفكّكات للمصفوفات التي تحتوي على عنصر واحد أو أكثر، ومفكّكات لحقول محددة في كائنات JSON المتداخلة أو لعناصر محددة في المصفوفات، وكيفية فكّ ترميز البنى التكرارية، إضافة إلى المتغيرات المختلفة للنوع `Error` وكيفية عرضها.

من الحزم الأخرى كثيرة الاستخدام [`Json.Decode.Pipeline`][pipeline]، التي تقدّم أسلوبًا مريحًا للتعامل مع بنية JSON المعقدة، و[`Json.Decode.Extra`][extra]، التي توفّر المزيد من المفكّكات والمرمّزات والأدوات المساعدة.
