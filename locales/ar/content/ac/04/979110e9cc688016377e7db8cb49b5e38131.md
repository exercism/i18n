# الملكية

في Cairo، يرتبط مفهوم الملكية بـ_المتغيرات_ نفسها وليس بـ_القيم_ التي تحملها.

القيم في Cairo غير قابلة للتغيير، وهذا الثبات يضمن أنه حتى لو أشارت متغيرات كثيرة إلى القيمة نفسها، تبقى القيمة نفسها ثابتة دون تغيير.
لذلك يجب على المترجم أن يضمن استخدامها الصحيح من قِبل المبرمج.
وهذا هو معنى _ملكية_ المتغير: المالك هو الكود الذي يستطيع قراءة المتغير (والكتابة فيه إن كان قابلًا للتغيير).

## قواعد ملكية المتغيرات

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## نطاق المتغير

النطاق هو المدى داخل البرنامج الذي يكون فيه المتغير صالحًا.
لنلقِ نظرة على المثال التالي الذي يعرّف متغيرًا `x` من نوع عدد صحيح بدون إشارة، مع تعليقات توضّح أين يكون المتغير صالحًا:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

ملاحظات:

- عندما يدخل `x` في النطاق، يصبح صالحًا.
- ويبقى صالحًا حتى يخرج من النطاق، وفي هذه الحالة حتى نهاية الدالة `main()`.

## نقل القيم

يحدث النقل عندما تُمرَّر قيمة إلى دالة أخرى، فيُدمَّر المتغير الأصلي الذي كان يشير إلى القيمة (وبذلك يصبح المتغير غير مفيد)، ويُنشأ متغير جديد يحمل القيمة نفسها.

المصفوفات مثال على نوع مركّب يُنقل عند تمريره إلى دالة أخرى.
وإليك تذكيرًا سريعًا بشكل المصفوفة:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

كيف يضمن نظام الأنواع ألا يحاول برنامج Cairo الكتابة في خلية الذاكرة نفسها مرتين؟
انظر إلى الكود التالي، حيث نحاول إزالة مقدمة المصفوفة مرتين:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

في هذه الحالة، نحاول تمرير القيمة نفسها (المصفوفة الموجودة في المتغير `arr`) إلى كلا نداءَي الدالة.
هذا يعني أن الكود يحاول إزالة العنصر الأول مرتين، ما يعني محاولة الكتابة في خلية الذاكرة نفسها مرتين، وهو أمر محظور في آلة Cairo الافتراضية، ويؤدي إلى خطأ في وقت التشغيل.
لحسن الحظ، هذا الكود لا يُترجم أصلًا.
فبمجرد أن نمرّر المصفوفة إلى الدالة `foo`، يصبح المتغير `arr` غير قابل للاستخدام.
فنحصل على خطأ في وقت الترجمة يخبرنا بأننا سنحتاج إلى أن تطبّق `Array` السمة `Copy`:

## سمة `Copy`

إذا طبّق نوع ما السمة `Copy`، فإن تمريره إلى دالة لا ينقل القيمة بل ينشئ متغيرًا جديدًا يشير إلى القيمة نفسها.
وهذه عملية مجانية لأن المتغيرات تجريد من تجريدات Cairo، والقيم دائمًا غير قابلة للتغيير.

لتطبيق السمة `Copy` على نوعك، أضف التوجيه `#[derive(Copy)]` إلى تعريف النوع.
لكن Cairo لن يسمح بذلك إذا لم يكن النوع أو أي من مكوّناته يطبّق السمة `Copy`.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## إتلاف القيم

يمكن أيضًا استخدام الأنواع الخطية عبر إتلافها، ما يضمن تحرير المورد المرتبط بها بشكل صحيح.
ويتحقق ذلك بتطبيق السمة `Drop` أو اشتقاقها، وهي تشير إلى المترجم بأن النوع يمكن إتلافه بأمان بمجرد أن يتوقف عن كونه مفيدًا.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

حاليًا، يمكن اشتقاق تطبيق `Drop` لجميع الأنواع، ما عدا القواميس (`Felt252Dict`) والأنواع التي تحتوي على قواميس.
ذلك لأن القواميس يجب أن "تُضغط" عند إتلافها.
ولهذا نشتق السمة `Destruct`:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## القيم المُرجعة والنطاق

إرجاع القيم يعادل نقلها.
يوضّح المثال التالي دالة تُرجع قيمة ما:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
