# حول

[concept:csharp/resource-cleanup]() يستخدم واجهة `IDispose` ليشير إلى مستدعي الصنف بوجود موارد أو حالة برنامج تحتاج إلى تحرير أو إعادة ضبط في الوقت المناسب عندما لا يعود الكائن المعني مطلوبًا. في هذا التمرين قدّمنا بعض السكر النحوي عبر الكلمة المفتاحية `using`، وهو يجعل الكود أقل إسهابًا ويقلل من احتمال إغفال استدعاءات مهمة.

يمكن النظر إلى `using` على أنه بديل عن [`try/finally`][try-finally] في بعض حالات الاستخدام.

```csharp
File file = null;
try
{
    file = new File("myStuff.txt");
    file.Write("more stuff");
}
finally
{
    file.Dispose();
}
```

تُستبدل هذه الصياغة بالنسخة الأكثر إحكامًا والأكثر أمانًا من الأخطاء:

```csharp
using (var file = new File("myStuff.txt")
{
    file.Write("more stuff");
}
```

لاحظ أنه يمكن دمج عدة موارد بسهولة وفقًا للقواعد المعتادة للكتل ذات السطر الواحد:

```csharp
using (var file = new File("mystuff.txt")
using (var fileWriter = new StreamWriter(file)
{
     ...
}
```

في C# 8 أُدخل التغيير التالي، حيث تأتي عبارة `using` في بداية الكتلة:

```csharp
using var file = new File("myStuff.txt");
file.Write("more stuff");
```

يتيح لك هذا أن يكون لديك عدة كائنات قابلة للتحرير في الكتلة نفسها، وأن تتعامل بشكل أكثر طبيعية مع [`try/catch`][try-catch]:

```csharp
using var fileIn = new File("myStuff.txt");
using var fileOut = new File("yourStuff.txt");
try
{
    var stuff = fileIn.Read();
    fileOut.Write(stuff);
}
catch (Exception)
{
    LogStuff();
}
```

القواعد المتعلقة بكيفية استخدام الكلمة المفتاحية `using` وبأنواع الكائنات التي يمكن استخدامها معها موضحة بالتفصيل [هنا][using-statement].

## ملاحظة لمطوري Java

قد يتعرف مطورو Java على هذا باعتباره نظيرًا لآلية [_إدارة الموارد التلقائية_][automatic-resource-management] التي أُدخلت في Java 7. وهما متشابهان جدًا. ويتميز تركيب Java، الذي يعيد استخدام `try`، بأنه يدمج كتل `catch` بشكل أكثر طبيعية مما تفعل `using` في C#.

## الإصدارات

لاحظ أن النسخة الأكثر مرونة من `using`، التي لا تحتوي على كتلة تركيبية خاصة بها، أُدخلت في C# 8، لذا قد تحتاج إلى التحقق مما إذا كانت قاعدة الكود التي تعمل عليها تستخدم C# 8 أو أحدث.
