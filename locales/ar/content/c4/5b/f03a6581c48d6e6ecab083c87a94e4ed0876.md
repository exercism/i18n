# الاختبارات

نفّذ الاختبارات باستخدام:

```shell
corepack pnpm test
```

احرص على أن يتبع كودك أفضل الممارسات وأنماط البرمجة، كما يفعل المستخدمون الآخرون، وذلك باستخدام ESLint، وهي أداة تُجري تحليلًا ثابتًا على الكود.
أحيانًا توفّر لك أدوات كهذه بعض الوقت في اكتشاف الأخطاء المطبعية أو الأخطاء الساذجة في كود JavaScript:

```shell
corepack pnpm lint
```

يمكنك أيضًا تشغيل Jest في وضع "watch"، وهو سيعيد تشغيل اختباراتك تلقائيًا عند حفظ تغييرات في الكود أو في وحدة الاختبار:

```shell
corepack pnpm watch
```

## فهم تخطّي الاختبارات

تُخبر طريقة `skip` مجموعة الاختبارات بألّا تُشغّل اختبارًا معيّنًا، ويمكن استدعاء هذه الدالة أيضًا تحت الأسماء البديلة التالية: `it.skip(name, fn)` أو `xit(name, fn)` أو `xtest(name, fn)`

- لماذا تُتخطّى؟

لتمكين المستخدمين من التركيز على اختبار واحد في كل مرة، وتفعيلها واحدًا بعد الآخر مع تطوّرهم في الحل.

- كيف تُفعّلها؟

غيّر `xtest` إلى `test`.

```javascript
test('title cased phrases', () => {
  expect(Acronyms.parse('Portable Network Graphics')).toEqual('PNG');
});
```

## إنشاء أول وحدة JavaScript 2015 لك

عادةً ما تحمّل الاختبارات في هذا المسار تنفيذك عن طريق استيراده كوحدة JavaScript: `import { Bob } from './bob.js';`.
كل ما عليك فعله هو تصدير تنفيذك من الملف المُشار إليه، `bob.js`:

```javascript
export function hey(message) {}
```

يمكنك العثور على مزيد من المعلومات حول الوحدات في [توثيق Babel](https://babeljs.io/docs/learn-es2015/#modules).
ولتسهيل البدء، يوجد ملف JavaScript _هيكلي_ في المجلد.
