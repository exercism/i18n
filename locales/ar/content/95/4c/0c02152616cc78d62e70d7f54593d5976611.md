# مقدمة

يمكن للصفوف أن توسّع صفوفًا أخرى. العبارة `TUPLE: child < parent slots ;` تُعلن عن صنف تكون نسخه أيضًا نسخًا من `parent`، فتحصل على خانات الأب بالإضافة إلى خاناتها، كما تعمل دوال الوصول الخاصة بالأب عليها أيضًا، تمامًا كما لو كانت قد عُرّفت على الابن.

```factor
USING: accessors ;

TUPLE: animal name age ;
TUPLE: dog < animal breed ;

"Rex" 4 "labrador" dog boa .
! => T{ dog { name "Rex" } { age 4 } { breed "labrador" } }

"Rex" 4 "labrador" dog boa name>> .   ! => "Rex"   (inherited accessor)
```

## ترتيب خانات `boa`

تأخذ الدالة البانية `boa` الخانات بترتيب *التصريح، الأصناف الأصلية أولًا*. من أجل `dog` أعلاه:

```
dog boa ( name age breed -- dog )
```

أما الحفيد `puppy < dog ` الذي يضيف `weeks` فسيكون:

```
puppy boa ( name age breed weeks -- puppy )
```

## التسلسل الهرمي لدوال التحقق

كل تعريف `TUPLE:` يولّد دالة تحقق (`name?`). مع الوراثة تتداخل دوال التحقق، فكل سليل يحقق دوال تحقق أسلافه:

```factor
"Rex" 4 "labrador" dog boa
dup dog? .        ! => t
dup animal? .     ! => t
```

والعكس غير صحيح: أي `animal` ليس `dog` يفشل في `dog?`.

## ملاحظة لما سيأتي

الطرق العامة (`M:`، المشروحة في [`generics`][generics]) تُرسل عبر التسلسل الهرمي أيضًا، فالطريقة المعرّفة على `animal` تُنفَّذ من أجل كل سليل ما لم يكن هناك تجاوز أكثر تخصيصًا له الأولوية. سترى ذلك في `boatswains-bilge` مباشرة بعد هذا التمرين.

[generics]: https://docs.factorcode.org/content/article-generic.html
