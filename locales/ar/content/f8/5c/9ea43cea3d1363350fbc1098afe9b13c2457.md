# مقدمة

حان الوقت للوصول إلى أحد الأنماط الأساسية في C++: البرمجة كائنية التوجه (OOP).
تتمحور البرمجة كائنية التوجه حول `classes`، وهي أنواع بيانات يعرّفها المستخدم ولها مجموعتها الخاصة من الدوال المرتبطة بها.
سنبدأ بالأساسيات، ثم نتناول موضوعات أكثر تقدمًا في مواضع لاحقة من شجرة المنهج.

## الأعضاء

يمكن للأصناف أن تمتلك **متغيرات أعضاء** و**دوال أعضاء**.
ويتم الوصول إليها بواسطة عامل **اختيار الأعضاء** `.`.
وكما في حالة المتغيرات خارج `classes`، يُستحسن تهيئة متغيرات الأعضاء بقيمة عند التعريف.
وتصبح هذه القيمة عندئذٍ القيمة الافتراضية للكائنات المُنشأة حديثًا من هذا الصنف.

## التغليف وإخفاء المعلومات

توفّر الأصناف خيار تقييد الوصول إلى أعضائها.
والحالتان الأساسيتان هما `private` و`public`.
لا يمكن الوصول إلى الأعضاء `private` من خارج الصنف.
ويمكن استدعاء الأعضاء `public` بحرية.
جميع الأعضاء `private` افتراضيًا، ويجب تعليمها صراحةً حتى تصبح قابلة للاستخدام خارج الصنف.

## مثال أساسي

يمكن رؤية تعريف `class` جديد في المثال التالي.
لاحظ `;` بعد التعريف.

```cpp
class Wizard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

يمكنك الوصول إلى جميع المتغيرات من داخل الصنف.
ألقِ نظرة على `damage` داخل الدالة `cast_spell`.
لا يمكنك قراءة الأعضاء `private` أو تغييرها من خارج الصنف:

```cpp
Wizard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## البواني

تتيح البواني إمكانية إسناد قيم إلى متغيرات الأعضاء عند إنشاء الكائن.
وهي تحمل الاسم نفسه الذي يحمله `class`، وليس لها نوع إرجاع.
ويمكن للصنف أن يحتوي على عدة بواني.
وهذا مفيد إن لم تكن بحاجة دائمًا إلى ضبط جميع المتغيرات.

```cpp
class Wizard {
  public:
    Wizard(std::string new_name) {
      name = new_name;
    }
    Wizard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizard el{"Eleven"};       // deals  5 damage
Wizard vecna{"Vecna", 50}; // deals 50 damage
```

البواني موضوع كبير وفيه تفاصيل دقيقة كثيرة.
إذا لم تعرّف `constructor` صراحةً لـ `class` الخاص بك، فحينها، وحينها فقط، سيقوم المترجم بالمهمة نيابةً عنك.
وهذا ما حدث في المثال الأول أعلاه.
فقد أُنشئ الكائن _silverhand_ باستدعاء الباني الافتراضي، ولم تُمرَّر أي وسائط.
وقد ضُبطت جميع المتغيرات على القيمة المذكورة في تعريف الصنف.
ولو لم تُعطِ أي قيم في ذلك التعريف، لربما بقيت المتغيرات غير مُهيّأة، وقد يترتب على ذلك عواقب غير مقصودة.

## البُنى

جاءت البُنى من الجذور الأصلية للغة في C، وعمرها من عمر C++ نفسه.
وهي في جوهرها الشيء نفسه الذي تمثله `classes`، باستثناء واحد مهم.
افتراضيًا، كل ما في `class` هو `private`.
أما البُنى فهي `public` حتى يُحدَّد خلاف ذلك.
وعُرفًا، تُستخدم الكلمة المفتاحية `struct` غالبًا لـ **البُنى التي تحمل بيانات فقط**.
وتُفضَّل الكلمة المفتاحية `class` للكائنات التي تحتاج إلى ضمان خصائص معينة.
وقد يكون هذا الثابت هو أن قيمة `damage` في `Wizard` `class` لا يمكن أن تصبح سالبة.
فالمتغير `damage` خاص، وأي دالة تغيّر قيمة `damage` ستضمن الحفاظ على هذا الثابت.
