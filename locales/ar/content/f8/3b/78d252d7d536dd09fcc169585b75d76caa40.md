# مقدمة

عادةً ما يوزّع نظام التشغيل (OS) الذاكرة للبرنامج وفق تخطيط عام:

| العنوان | منطقة الذاكرة |
| :-----: | :--------------------- |
|  عالٍ   | المكدس                 |
|         | ...                    |
|         | الكومة                 |
|         | قسم القراءة والكتابة   |
|         | قسم الكود/القراءة فقط  |
|  منخفض  | محجوز                  |

تُنظَّم الذاكرة في مقاطع، وتُقسَّم إلى أقسام ذات أذونات مختلفة.

كل الدوال التي عرّفناها حتى الآن كانت في **القسم .text**.
يحوي هذا القسم بيانات قابلة للتنفيذ للقراءة فقط.
وتُستخدم أقسام أخرى للإعلان عن متغيرات البيانات، وقد تكون للقراءة فقط أو للقراءة والكتابة، لكنها غير قابلة للتنفيذ.

## القسم .data

تُعلَن البيانات المُهيّأة في **القسم .data**.

في NASM (المُجمِّع Netwide Assembler، وهو المُجمِّع المستخدَم في هذا المسار)، يمتلك المتغير المُهيّأ اسمًا، وتوجيهًا يحدد حجم البيانات، وقائمة قيم مفصولة بفواصل.
ويُفصَل كل عنصر من هذه عن الآخر بمسافة، ويمكن اختياريًا أن تتبع الوسم علامة `:`.

أهم التوجيهات وأحجام البيانات المرتبطة بها هي:

| التوجيه | الحجم |
| :-------: | :------ |
|    db     | 1 بايت  |
|    dw     | 2 بايت |
|    dd     | 4 بايت |
|    dq     | 8 بايت |

على سبيل المثال، يعلن هذا متغيرًا من نوع بايت باسم `space` وقيمته `10`:

```x86asm
section .data
    space db 10
```

المتغيرات المُعلنة في `section .data` قابلة للتغيير، أي أنها للقراءة والكتابة.
كما أن لها مدة تخزين _ساكنة_، أي أنها توجد طوال مدة تشغيل البرنامج.

## القسم .rodata

يشبه **القسم .rodata** القسم `section .data`.
يحتوي القسمان على بيانات مُهيّأة تُعلَن بالطريقة نفسها ولها المدة نفسها للتخزين.

الفرق الرئيسي بينهما أن البيانات في `section .rodata` غير قابلة للتغيير، أي للقراءة فقط.

~~~~exercism/note
الثوابت المُعرَّفة بـ `equ` تختلف عن تلك المُعرَّفة في `section .rodata`.

الثابت المُعرَّف بـ `equ` لا يشغل حيزًا في الذاكرة، ويستبدله المُجمِّع بقيمته مباشرة.
بل هو في الحقيقة عنصر نائب عن تلك القيمة.

في المقابل، الثوابت المُعرَّفة في `section .rodata` تُخزَّن فعلًا في الذاكرة، ولها عنوان.
~~~~

## الوصول إلى البيانات

### الوسوم والوصول غير المباشر

يجب أن يرتبط بالبيانات المُعلنة اسمٌ.
ويُسمى هذا الاسم **وسمًا**.

الوسم رمز يحمل العنوان المحدد للبيانات في الذاكرة.
**العناوين في x86-64 قيم بطول 64 بت**.

في NASM، محاولة الوصول إلى البيانات مباشرةً عبر وسمها لا تُعطيك الذاكرة المحجوزة، بل عنوانها:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

للوصول إلى محتويات عنوان في الذاكرة، من الضروري _فكّ الإشارة_ إليه.
ويُسمى هذا **الوصول غير المباشر**.

في NASM، يتم هذا باستخدام `[]`:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

لكن توجد بعض الحالات التي قد يلتبس فيها حجم الذاكرة التي فُكّت الإشارة إليها.
في هذه الحالات، يجب استخدام بادئة تحدد هذا الحجم.

هذه أهم البادئات وأحجامها في برنامج نموذجي على x86-64:

| البادئة | الحجم |
| :----- | :------ |
| byte   | 1 بايت  |
| word   | 2 بايت |
| dword  | 4 بايت |
| qword  | 8 بايت |

يمكن كتابة التحميل نفسه مع ذكر الحجم صراحةً:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

من الممارسات الجيدة استخدام بادئة دائمًا عند فك الإشارة إلى الذاكرة.

### الكتابة إلى الذاكرة

تتم الكتابة إلى الذاكرة بالطريقة نفسها، عبر فك الإشارة إلى العنوان:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

لاحظ أنه يمكنك استخدام معاملات الذاكرة في معظم التعليمات دون تحميل المحتويات في سجل أولًا.
لكن لا يمكن عادةً استخدامها في معامل المصدر ومعامل الوجهة معًا، بل في واحدٍ منهما فقط:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### تعليمة LEA

رغم أنه يمكن استخدام `mov` لتخزين عنوان متغير في سجل، فإن هناك تعليمة مخصصة لهذا الغرض تحديدًا: **lea**.

تستخدم هذه التعليمة معاملًا بصيغة الذاكرة، لكنها _لا_ تقرأ الذاكرة.
بل تحسب تعبير العنوان الفعّال وتكتب النتيجة في معامل الوجهة:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

من الأسلوب الأمثل استخدام `lea` لحساب عناوين الذاكرة وتخزينها في السجلات.

### العنونة النسبية

عند الوصول إلى مواقع الذاكرة، فإن السلوك الافتراضي في NASM هو توليد **عناوين مطلقة**، أي عناوين ذاكرة ثابتة.

لأسباب أمنية، غالبًا ما تُبنى الملفات التنفيذية كـ **PIE (ملف تنفيذي مستقل عن الموضع)**، حيث تُوضَع مناطق الذاكرة في مواقع عشوائية.
في `PIE`، لا يُعرف العنوان النهائي للمتغير وقت الربط.
لذلك يحسب الكود العناوين بدلًا من ذلك كإزاحة من القيمة في سجل خاص يُسمى `rip`، يشير إلى التعليمة التالية المطلوب تنفيذها.

ويُسمى هذا عادةً **العنونة النسبية إلى RIP**.

في NASM يمكنك طلب وصول نسبي إلى RIP باستخدام العامل `rel`:

```x86asm
mov rax, qword [rel variable]
```

يمكن أيضًا جعل العنونة النسبية الافتراضية لملف مصدري باستخدام `default rel` في أعلاه.

تُترجم جميع التمارين في هذا المسار وتُربط كـ `PIE`، لذا ينبغي استخدام `rel` لتوليد عناوين نسبية.

### الظهور

الوسوم (الدوال والبيانات) المُعرَّفة في أي قسم (مثل `.text` و`.data` و`.rodata`) تكون مرئية داخل ملف المصدر نفسه.
وإذا أُعلنت بـ `global`، تصبح مرئية لملفات المصدر الأخرى أيضًا.

وبالمقابل، تكون الوسوم المُعرَّفة في ملفات مصدر أخرى مرئية لملف المصدر الحالي إذا أُعلنت بـ `extern`.
في هذه الحالة، لا يوجد في لغة التجميع ما يدل على حجم البيانات، فيجب معرفته مسبقًا.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
