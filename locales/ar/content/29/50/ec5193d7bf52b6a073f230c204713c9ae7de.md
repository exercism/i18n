# الروتينات المرتبطة

كل ما مرّ بنا حتى الآن كان يمرّر *القيم*: أعدادًا وسلاسل نصية وكائنات. أما **الروتين المرتبط** فيتيح لك تمرير روتين نفسه، أي شيء يُستدعى لاحقًا من كود لا يعرف ما هو.

البديل في المسرح هو هذه الفكرة نفسها: يحتفظ مدير المسرح بطريقة لأداء الدور، دون أن يعرف من سيؤديه ولا ما الذي سيفعله.

## كيف تصنع واحدًا

تأخذ `bind` استدعاءً فيه فراغات، تُكتب بالشرطة السفلية `_`:

```sather
   shout(line : STR) : STR is return line.upper; end;

   ...

   part ::= bind(shout(_));
```

أصبح `part` الآن قيمة كأي قيمة أخرى. أما استدعاؤه فيحدث لاحقًا:

```sather
   part.call("who's there")      -- "WHO'S THERE"
```

## النوع

نوع الروتين المرتبط هو `ROUT`، مع أنواع الوسائط بين الأقواس المعقوفة ونوع الإرجاع بعد نقطتين:

```sather
   part : ROUT{STR}:STR := bind(shout(_));
```

اقرأ `ROUT{STR}:STR` على أنها «روتين يأخذ `STR` ويُرجع `STR`».

| المكتوب | المعنى |
| --- | --- |
| `ROUT{STR}:STR` | يأخذ `STR` ويُرجع `STR` |
| `ROUT{INT,INT}:BOOL` | يأخذ `INT` اثنين ويُرجع `BOOL` |
| `ROUT{STR}` | يأخذ `STR` ولا يُرجع شيئًا |
| `ROUT:INT` | لا يأخذ شيئًا ويُرجع `INT` |

ولأنه نوع، يمكن أن يكون وسيطًا:

```sather
   rehearse(line : STR, part : ROUT{STR}:STR) : STR is
      return part.call(line);
   end;
```

لا تعرف `rehearse` شيئًا عما تفعله `part`. وهذا هو المقصود: فيمكن أن تُسلَّم إليها `shout` أو `whisper` أو أي شيء آخر بهذا الشكل.

## ملء بعض الوسائط

ليس كل وسيط يجب أن يكون فراغًا. أي شيء مكتوب صراحةً يتحدد عند حدوث الربط:

```sather
   repeat(times : INT, line : STR) : STR is ... end;

   twice ::= bind(repeat(2, _));      -- ROUT{STR}:STR
```

لا تأخذ `twice` سوى السطر، لأن `2` محدد سلفًا. وتُحسب القيمة لحظة الربط وتُحفظ، لذا فإن تغيير المتغير الذي جاءت منه بعد ذلك لا يحدث أي فرق.

وهكذا يتحول روتين عام واحد إلى روتينات متخصصة كثيرة.

## ربط الكائن أيضًا

في روتين يخص كائنًا ما، يكون الكائن أول شيء في الاستدعاء، ويمكن تثبيته أو تركه فراغًا:

```sather
   bind(board.home_goal)      -- this board's, always
   bind(_.home_goal)          -- whichever board is handed in later
```
