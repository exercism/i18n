# مقدمة

أي بيانات في لغة التجميع ما هي إلا تسلسل من البايتات.
وهذا يعني أن أي بيانات يمكن النظر إليها بوصفها **مصفوفة** من تلك البايتات الكامنة.

## الوصول إلى عناصر المصفوفة

للوصول إلى أي قيمة في الذاكرة، من الضروري حساب **عنوانها الفعّال**.
العنوان الفعّال تعبير يمكن أن يتكوّن من:

- _عنوان أساس_، على سبيل المثال العنوان الذي يدل عليه وسم متغير.
- _سجل فهرس_ واحد، قد يُضرب في `1` أو `2` أو `4` أو `8`.
- _إزاحة_ ذات إشارة بسعة 32 بت، وهي عدد يُضاف إلى عنوان الأساس (أو يُطرح منه).

لاحظ أن هذا العنوان مُفهرس بدءًا من 0، لذا فإن عنوان الأساس، دون أي إزاحة، يشير إلى أول بايت من المتغير.
ولهذا فإن فك الإشارة إلى الذاكرة باستخدام وسم فقط دون أي إزاحة، كما فعلنا في المفاهيم السابقة، يعطي قيمة تبدأ من أول بايت فيها:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
معمارية x86-64 تعتمد [ترتيب البايتات الصغير][endianness].
وهذا يعني أن البايت الأقل أهمية في قيمة متعددة البايتات يُخزَّن عند أصغر عنوان في الذاكرة.

وبالتالي، عند الوصول إلى البايتات الفردية لقيمة متعددة البايتات، من الضروري إضافة إزاحة موجبة إلى عنوان الأساس للوصول إلى البايتات الأكثر أهمية.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

المتغير المُهيّأ المُعلن بقائمة من القيم هو مصفوفة من تلك القيم، ويكون حجم كل عنصر هو الحجم المحدد.
لكن الإزاحات تكون دائمًا بالـ**_بايتات_**، حتى عندما يكون حجم كل عنصر في المصفوفة أكبر:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

لاحظ أنه بما أن العناوين بالبايتات، فمن الممكن الوصول مباشرة إلى بايت فردي من أي عنصر في المصفوفة:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

وللسبب نفسه، من الممكن الوصول إلى أكثر من حجم عنصر واحد في تعليمة واحدة:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
لا تُجري لغة التجميع أي فحص لحدود الوصول إلى المصفوفات.
فهرس يتجاوز نهاية المصفوفة يقرأ أو يكتب في ذاكرة خارجها.
قد يؤدي هذا إلى نتائج غير صحيحة بصمت، وإلى إفساد بيانات أخرى، وإذا لم تكن الذاكرة التي جرى الوصول إليها مُعيَّنة، إلى خطأ وقت التشغيل.
المبرمج هو المسؤول عن إبقاء كل عنوان فعّال داخل حدود المصفوفة.
~~~~

## حساب حجم مصفوفة مُهيّأة

يمتلك NASM (The Netwide Assembler، وهو المُجمِّع المستخدم في هذا المسار) رمزًا خاصًا (`$`) يشير إلى الموقع الحالي في الذاكرة.
ويوفّر هذا الرمز وسيلة ملائمة لحساب الحجم الكلي في الذاكرة الذي تشغله مصفوفة:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

عند استخدامه بعد `example` مباشرة، يدل `$` على العنوان في الذاكرة الذي تمتد إليه نهاية المصفوفة.
وهذا يعني أن `$ - example` هو الفرق بين ذلك العنوان والعنوان الذي يشير إليه الوسم `example`.
وهذا بالضبط هو الحجم الكلي، بالبايتات، الذي تشغله المصفوفة التي يشير إليها `example`.

إذن، بتعريف `example_length` بهذه القيمة، أنشأنا متغيرًا بحجم 8 بايت يخزّن حجم المصفوفة، أو طولها، بالبايتات.

## القسم .bss

تُعلَن البيانات غير المُهيّأة في **القسم .bss**.
على معظم المنصات، يملأ نظام التشغيل هذه البيانات بالأصفار عند بدء البرنامج.

في NASM، يكون للمتغير غير المُهيّأ اسم، وتوجيه يحدد حجم البيانات وعدد العناصر المطلوب حجزها.
ويفصل بين كل منها والآخر مسافة.

التوجيهات الرئيسية وأحجام البيانات المرتبطة بها هي:

| التوجيه | الحجم |
| :-------: | :------ |
|   resb    | 1 بايت  |
|   resw    | 2 بايت |
|   resd    | 4 بايت |
|   resq    | 8 بايت |

على سبيل المثال، هذا يحجز مساحة غير مُهيّأة مقدارها `3` بايت في متغير باسم `example`:

```x86asm
section .bss
    example resb 3
```

وهذا يحجز مساحة غير مُهيّأة مقدارها `10` في `8` بايت (أي `80` بايت) في متغير باسم `arr`:

```x86asm
section .bss
    arr resq 10
```

المتغيرات في `section .bss` قابلة للتغيير، أي أنها تُقرأ وتُكتب.

يمكن الوصول إلى البيانات غير المُهيّأة بالطريقة نفسها التي يُوصَل بها إلى البيانات المُهيّأة، وذلك باستخدام عنوانها الفعّال.
وبالمثل، فهي أيضًا ذات مدة تخزين ساكنة ويمكن الوصول إليها من أي دالة في ملف المصدر نفسه (وإذا أُعلنت `global`، فمن ملفات مصدر أخرى أيضًا).

## الوصول إلى عناوين المصفوفة باستخدام تعليمة `lea`

كما رأينا في مفهوم سابق، تحسب تعليمة `lea` عنوان ذاكرة فعّالًا.
ويمكن استخدامها لحساب عنوان أي عنصر في مصفوفة، وفق الدلالات نفسها.

لاحظ أنه في العنونة النسبية غالبًا ما يكون من الضروري تحميل عنوان المتغير في سجل قبل تكوين عنوان أكثر تعقيدًا:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
من مزايا `lea` أنها تستخدم عمليات حساب العناوين لحساب قيمة دون الوصول فعليًا إلى الذاكرة الموجودة في ذلك العنوان.
وهذا يجعلها مفيدة لإجراء عمليات حسابية حتى عندما لا يحمل أي من السجلات عنوان ذاكرة:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
