# نبذة

عادةً ما يُخطّط نظام التشغيل (OS) الذاكرةَ لبرنامج ما في تخطيط عام:

| العنوان | منطقة الذاكرة          |
| :-----: | :--------------------- |
|  مرتفع  | المكدس                 |
|         | ...                    |
|         | الكومة                 |
|         | مقطع القراءة والكتابة  |
|         | مقطع الكود/القراءة فقط |
|  منخفض  | محجوز                  |

تُنظَّم الذاكرة على شكل مقاطع، وتتكوّن هذه المقاطع من أقسام ذات صلاحيات مختلفة.

كانت الدوال التي عرّفناها حتى الآن كلها في **القسم .text**.
يحتوي هذا القسم على بيانات قابلة للتنفيذ للقراءة فقط.
تُستخدم أقسام أخرى لتعريف متغيرات البيانات، وقد تكون للقراءة فقط أو للقراءة والكتابة، لكنها غير قابلة للتنفيذ.

## القسم .data

تُعرَّف البيانات المهيّأة في **[القسم .data][data]**.

في NASM (المُجمِّع Netwide Assembler، وهو المُجمِّع الذي يستخدمه هذا المسار)، يكون للمتغير المهيّأ اسم، وتوجيه يدل على حجم البيانات، وقائمة قيم مفصولة بفواصل.
ويفصل بين كل عنصر وآخر مسافة، ويمكن اختياريًا أن تتبع التسمية علامة `:`.

أهم التوجيهات وأحجام البيانات المرتبطة بها هي:

| التوجيه | الحجم   |
| :-----: | :------ |
|    db   | 1 بايت  |
|    dw   | 2 بايت  |
|    dd   | 4 بايت  |
|    dq   | 8 بايت  |

على سبيل المثال، يعرّف هذا متغيرًا بحجم بايت اسمه `space` وقيمته `10`:

```x86asm
section .data
    space db 10
```

المتغيرات المعرَّفة في `section .data` قابلة للتعديل، أي أنها للقراءة والكتابة.
كما أنّ لها مدة تخزين _ساكنة_، أي أنها تبقى موجودة طوال مدة تشغيل البرنامج.

## القسم .rodata

يشبه **القسم .rodata** القسم `section .data`.
يحتوي القسمان على بيانات مهيّأة تُعرَّف بالطريقة نفسها ولهما مدة التخزين نفسها.

الفرق الرئيسي بينهما أن البيانات في `section .rodata` غير قابلة للتعديل، أي للقراءة فقط.

~~~~exercism/note
الثوابت المعرَّفة بـ `equ` تختلف عن الثوابت المعرَّفة في `section .rodata`.

الثابت المعرَّف بـ `equ` لا يشغل حيزًا في الذاكرة، بل يستبدله المُجمِّع بقيمته مباشرة.
إنه في الواقع عنصر نائب لتلك القيمة.

في المقابل، الثوابت المعرَّفة في `section .rodata` تُخزَّن فعليًا في الذاكرة، ولها عنوان.
~~~~

## الوصول إلى البيانات

### التسميات والإشارة غير المباشرة

يجب أن ترتبط بالبيانات المعرَّفة اسمٌ يدل عليها.
ويُسمى هذا الاسم **تسمية**.

التسمية رمز يشفّر العنوان المحدد للبيانات في الذاكرة.
**العناوين في x86-64 قيم بطول 64 بت**.
والقيمة التي تحمل عنوانًا كهذا، سواء كانت محفوظة في سجل أو مخزَّنة في الذاكرة، هي ما تسميه اللغات عالية المستوى **[مؤشرًا][pointer]**.

في NASM، محاولة الوصول إلى البيانات مباشرةً بواسطة تسميتها لا تعطي الذاكرة المخصَّصة، بل عنوانها:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

وللوصول إلى محتويات عنوان في الذاكرة، لا بد من _إلغاء الإشارة_ إليه.
ويُسمى هذا **الإشارة غير المباشرة**.

وفي NASM، يتم ذلك باستخدام `[]`:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

لكن في بعض الحالات قد يلتبس حجم الذاكرة التي أُلغيت الإشارة إليها.
وفي تلك الحالات، يجب استخدام بادئة تحدّد هذا الحجم.

هذه أهم البادئات وأحجامها في برنامج نموذجي على x86-64:

| البادئة | الحجم   |
| :----- | :------ |
| byte   | 1 بايت  |
| word   | 2 بايت  |
| dword  | 4 بايت  |
| qword  | 8 بايت  |

ويمكن كتابة التحميل نفسه مع ذكر الحجم صراحةً:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

من الممارسات الجيدة استخدام بادئة دائمًا عند إلغاء الإشارة إلى الذاكرة.

### الكتابة إلى الذاكرة

تتم الكتابة إلى الذاكرة بالطريقة نفسها، عبر إلغاء الإشارة إلى عنوان:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

لاحظ أنه يمكنك استخدام معاملات الذاكرة في معظم التعليمات دون تحميل المحتويات في سجل أولًا.
لكن ليس من الممكن عادةً استخدامها في معامل المصدر ومعامل الوجهة معًا، بل في واحد منهما فقط:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### التعليمة LEA

مع أنه يمكن استخدام `mov` لتخزين عنوان متغير في سجل، توجد تعليمة مخصَّصة لهذا الغرض: **[lea][lea]**.

تستخدم هذه التعليمة معاملًا بصيغة الذاكرة، لكنها _لا_ تقرأ الذاكرة.
بل تحسب تعبير العنوان الفعّال وتكتب النتيجة في معامل الوجهة:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

ومن الأسلوب الأكثر شيوعًا استخدام `lea` لحساب عناوين الذاكرة وتخزينها في السجلات.

### العنونة النسبية

عند الوصول إلى مواضع الذاكرة، فإن السلوك الافتراضي في NASM هو توليد **عناوين مطلقة**، أي عناوين ذاكرة ثابتة.

ولأسباب أمنية، غالبًا ما تُبنى الملفات التنفيذية كـ **PIE (ملف تنفيذي مستقل عن الموضع)**، حيث توضع مناطق الذاكرة في مواضع عشوائية.
وفي `PIE`، لا يُعرف العنوان النهائي لمتغير وقت الربط.
لذلك يحسب الكود العناوين بدلًا من ذلك كإزاحة عن القيمة الموجودة في سجل خاص يُسمى `rip`، وهو يشير إلى التعليمة التالية المطلوب تنفيذها.

ويُسمى هذا عادةً **العنونة النسبية إلى RIP**.

في NASM يمكنك طلب وصول نسبي إلى RIP باستخدام **[عامل `rel`][rel]**:

```x86asm
mov rax, qword [rel variable]
```

ويمكن أيضًا جعل العنونة النسبية الافتراضية لملف مصدري بوضع `default rel` في أعلاه.

تُجمَّع كل تمارين هذا المسار وتُربط كـ `PIE`، لذا ينبغي استخدام `rel` لتوليد عناوين نسبية.

التخطيط العشوائي المذكور أعلاه إجراء تخفيفي يُعرف بعشوائية تخطيط فضاء العناوين.
فبجعل قاعدة كل منطقة ذاكرة غير متوقَّعة، يحرم المهاجم من العناوين الثابتة التي تعتمد عليها كثير من تقنيات الاستغلال، و`PIE` هي ما يتيح للمُحمِّل وضع تلك المناطق في أي مكان.

وبسبب ذلك، لا تقتصر العنونة المطلقة في هذا المسار على كونها غير مستحسنة، بل إنها غير قابلة للاستخدام.
فالمرجع المطلق مثل `[abs variable]` يطلب من المُجمِّع تضمين عنوان ثابت بطول 32 بت في التعليمة.
على Linux يرفض رابط `PIE` الترحيل الناتج عن ذلك، وعلى macOS لا يدعم تنسيق `macho64` العناوين المطلقة ذات 32 بت إطلاقًا، لذا يفشل تجميع الملف.

تتجنّب العنونة النسبية إلى RIP المشكلتين معًا، لأن التعليمة تشفّر إزاحة عن `rip` فقط ولا تشفّر عنوانًا ثابتًا أبدًا.
لذلك فإن الأسلوب الشائع لوضع عنوان في سجل في ظل `PIE` هو `lea` مع معامل `rel`:

```x86asm
default rel

section .data
    variable dq 7

section .text
fn:
    lea rax, [rel variable]       ; materialize the address (PIE-safe)
    mov rcx, qword [rel variable] ; load the value through a RIP-relative access
    ...
```

### إمكانية الرؤية

التسميات (الدوال والبيانات) المعرَّفة في أي قسم (مثل `.text` و`.data` و`.rodata`) تكون مرئية داخل الملف المصدري نفسه.
وإذا أُعلنت `global`، تصبح مرئية لملفات مصدرية أخرى أيضًا.

وبالمقابل، تكون التسميات المعرَّفة في ملفات مصدرية أخرى مرئية للملف المصدري الحالي إذا أُعلنت `extern`.
وفي هذه الحالة، لا يوجد في التجميع ما يدل على حجم البيانات، فيجب معرفته مسبقًا.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
