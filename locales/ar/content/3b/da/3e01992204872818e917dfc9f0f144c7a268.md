# تضمين الكود

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

تنسخ عبارة `include` كود صنف آخر إلى هذا الصنف. وهي عملية تجري وقت التصريف، بلا كلفة وقت التشغيل وبلا صلة وقت التشغيل: فلا يبقى الصنفان مرتبطين بعد ذلك.

## الجملة

```
   include CLASS  old_name -> new_name , old_name -> ;
```

تُعيد كل مدخلة تسمية عنصر واحد. أما `-> ;` من دون اسم جديد فيستبعده. وكل ما لا يُذكر يدخل من دون تغيير.

تنطبق إعادة التسمية على ما يراه *الخارج*. وتبقى الاستدعاءات بين الإجراءات المضمَّنة تعمل: فإذا استدعى `describe` الإجراء `count` وأُعيدت تسمية `count` إلى `beats`، استدعى `describe` الإجراء `beats`.

## تضمين عدة أصناف

```sather
   include WARM_UP;
   include COOL_DOWN;
```

وهذا مسموح، وهو الأسلوب الذي تحصل به Sather على ما تسمّيه اللغات الأخرى الوراثة المتعددة، من دون المتاعب المعتادة، لأن التعارض خطأ في التصريف وحلّه إعادة التسمية أو استبعاد أحدهما. ولا يُحسم شيء بترتيب أسبقية عليك حفظه.

## التضمين بـ `private`

```sather
   private include WARM_UP;
```

يجلب الكود من أجل استخدام هذا الصنف نفسه دون كشفه. مفيد عندما تريد التنفيذ لا الواجهة.

## الاثنان معًا

الشكل المعتاد لعائلة أصناف:

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

يبيّن `< $ACT` ما يستطيع الصنف فعله، ويوفّر `include ACT_BASICS` جزءًا من الكيفية. غيّر رأيك في الكيفية، فلا يتحرّك `<` من مكانه.

## لماذا يُتبع هذا الأسلوب

الصنف المجرّد لا يحتوي على كود، لذا لا يمكن أن يُورَث منه عن غير قصد، ولا وجود لصنف أعلى يتغيّر سلوكه من تحتك دون أن تشعر. إعادة الاستخدام نسخة تُؤخذ وقت التصريف، من صنف سمّيته أنت، مع تدوين كل إعادة تسمية.

الثمن هو أن إعادة الاستخدام يجب أن تُطلَب صراحةً في كل صنف. وهذه هي المقايضة: كتابة أكثر، ولا شيء ضمني.
