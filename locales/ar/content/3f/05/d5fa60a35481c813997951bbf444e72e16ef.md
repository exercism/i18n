# مقدمة

مثل كثير من اللغات الأخرى، تحتوي لغة Go على مؤشرات.
إذا كنت جديدًا على المؤشرات، فقد تبدو غامضة بعض الشيء، لكنها تصبح بسيطة جدًا بمجرد أن تعتاد عليها.
إنها جزء أساسي من Go، لذا خصّص بعض الوقت لفهمها فهمًا حقيقيًا.

قبل الخوض في التفاصيل، يجدر بك فهم الغرض من استخدام المؤشرات.
المؤشرات وسيلة لمشاركة الذاكرة مع أجزاء أخرى من برنامجنا، وهي مفيدة لسببين رئيسيين:

1. عندما نمتلك كميات كبيرة من البيانات، يكون إنشاء نسخ لتمريرها بين الدوال غير فعّال على الإطلاق.
   وبتمرير موقع الذاكرة الذي تُخزَّن فيه البيانات بدلًا من ذلك، يمكننا تقليل استهلاك برامجنا للموارد بدرجة كبيرة.
2. بتمرير المؤشرات بين الدوال، يمكننا الوصول إلى النسخة الوحيدة من البيانات وتعديلها مباشرةً، ما يعني أن أي تغييرات تُجريها إحدى الدوال تصبح مرئية فورًا لأجزاء أخرى من البرنامج عند انتهاء الدالة.

## المتغيرات والذاكرة

لنفترض أن لدينا متغيرًا عاديًا من نوع عدد صحيح اسمه `a`:

```go
var a int
```

عندما نُعلن عن متغير، يجب على Go أن تجد مكانًا في الذاكرة لتخزين قيمته.
وهذا الأمر مجرّد عنا إلى حد كبير: عندما نحتاج إلى جلب القيمة المخزّنة في ذلك الجزء من الذاكرة، يكفي أن نشير إليه باسم المتغير.

على سبيل المثال، عندما نكتب `a + 2`، فإننا في الواقع نجلب القيمة المخزّنة في الذاكرة المرتبطة بالمتغير `a` ونضيف إليها 2.

وبالمثل، عندما نحتاج إلى تغيير القيمة في الجزء الخاص بالمتغير `a` من الذاكرة، يمكننا استخدام اسم المتغير للقيام بعملية إسناد:

```go
a = 3
```

سيخزّن الجزء من الذاكرة المرتبط بالمتغير `a` القيمة `3` الآن.

## المؤشرات

بينما تتيح لنا المتغيرات الإشارة إلى القيم في الذاكرة، فإن معرفة **عنوان الذاكرة** الذي يشير إليه المتغير مفيدة في بعض الأحيان.
و**المؤشرات** تحمل عناوين الذاكرة الخاصة بتلك القيم.
تُعلن عن متغير من نوع مؤشر بوضع نجمة قبل النوع الأساسي:

```go
var p *int // 'p' contains the memory address of an integer
```

هنا نُعلن عن متغير `p` من النوع "مؤشر إلى عدد صحيح" (`*int`).
وهذا يعني أن `p` سيحمل عنوان الذاكرة الخاص بعدد صحيح.
والقيمة الصفرية للمؤشرات هي `nil`، لأن المؤشر `nil` لا يحمل أي عنوان ذاكرة.

### الحصول على مؤشر إلى متغير

لإيجاد عنوان الذاكرة الخاص بقيمة متغير، يمكننا استخدام العامل `&`.
على سبيل المثال، إذا أردنا إيجاد عنوان الذاكرة الخاص بالمتغير `a` وتخزينه في المؤشر `p`، يمكننا فعل ما يلي:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### الوصول إلى القيمة عبر مؤشر (إلغاء الإشارة)

عندما يكون لدينا مؤشر، قد نرغب في معرفة القيمة المخزّنة في عنوان الذاكرة الذي يمثله المؤشر.
ويمكننا فعل ذلك باستخدام العامل `*`:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

تُجلب العملية `*p` القيمة المخزّنة في عنوان الذاكرة المحفوظ في `p`.
وتُسمى هذه العملية غالبًا "إلغاء الإشارة".

ويمكننا أيضًا استخدام عامل إلغاء الإشارة لإسناد قيمة جديدة إلى عنوان الذاكرة الذي يشير إليه المؤشر:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

يؤدي الإسناد إلى `*pa` إلى تغيير القيمة المخزّنة في عنوان الذاكرة الذي يحمله `pa`.
وبما أن `pa` يحمل عنوان الذاكرة الخاص بالمتغير `a`، فإننا بإسناد قيمة إلى `*pa` نغيّر قيمة `a` فعليًا!

لكن انتبه: تحقّق دائمًا من أن المؤشر ليس `nil` قبل إلغاء الإشارة.
فإلغاء الإشارة إلى مؤشر `nil` سيجعل البرنامج ينهار أثناء التنفيذ!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### مؤشرات إلى البنى

حتى الآن لم نرَ سوى مؤشرات إلى قيم أولية.
ويمكننا أيضًا إنشاء مؤشرات إلى البنى:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

كان بإمكاننا أيضًا إنشاء `Person` جديدة وتخزين مؤشر إليها فورًا:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

عندما يكون لدينا مؤشر إلى بنية، لا نحتاج إلى إلغاء الإشارة قبل الوصول إلى أحد الحقول:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## الشرائح والخرائط مؤشرات أصلًا

الشرائح والخرائط أنواع خاصة لأنها تحتوي أصلًا على مؤشرات في تنفيذها الداخلي.
وهذا يعني أننا في أغلب الأحيان لا نحتاج إلى إنشاء مؤشرات لهذه الأنواع لمشاركة عنوان الذاكرة الخاص بقيمها.
تخيّل أن لدينا دالة تزيد قيمة مفتاح في خريطة:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

إذا أنشأنا خريطة واستدعينا هذه الدالة، فإن التغييرات التي أجرتها الدالة على الخريطة تبقى بعد انتهاء الدالة.
وهذا سلوك مشابه لما نحصل عليه عند استخدام مؤشر، لكن لاحظ أننا في هذا المثال لا نستخدم أي إشارة أو إلغاء إشارة ولا أيًا من صيغة المؤشرات:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

ينطبق الأمر نفسه عند تغيير عنصر موجود في شريحة.

لكن الإجراءات التي تُرجع شريحة جديدة مثل `append` حالة خاصة، وقد **لا** تعدّل الشريحة خارج الدالة.
ويرجع ذلك إلى الطريقة التي تعمل بها الشرائح داخليًا، لكننا لن نغطي هذا بالتفصيل لأنه موضوع متقدّم أكثر.
وإذا كنت فضوليًا حقًا، يمكنك قراءة المزيد عن ذلك في [Go Blog: Mechanics of 'append'][mechanics-of-append]
