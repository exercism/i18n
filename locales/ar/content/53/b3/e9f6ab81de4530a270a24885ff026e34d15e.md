# مقدمة

## المراجع `null`

إذا سبق أن استخدمت لغة برمجة أخرى (C/C++، Python، Java، Ruby، Lisp، إلخ)، فمن المرجح أنك صادفت `null` أو `nil` من قبل.
استخدام `null` أو `nil` هو الطريقة التي تشير بها هذه اللغات إلى أن متغيرًا معينًا ليس له قيمة.
غير أن هذا يجعل استخدام متغير يشير إلى `null` من دون قصد خطأً سهل الوقوع (وشائعًا).
وكما قد تتخيل، فإن محاولة استدعاء دالة غير موجودة، أو الوصول إلى قيمة غير موجودة، قد تؤدي إلى شتى أنواع الـ Bug والانهيارات.
ذهب مبتكر `null` إلى حد أنه وصفه بأنه ["خطأ المليار دولار".](https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/)

## المراجع `null`

لتجنب هذه المشكلات، لا تستخدم Rust مراجع `null`.
لكنها لا تزال بحاجة إلى طريقة آمنة للإشارة إلى أن متغيرًا معينًا ليس له قيمة.
وهنا يأتي دور `Option`.
فبدلًا من أن يكون لديك متغير بلا قيمة، يمكن لمتغيرات Rust أن تستخدم تعداد `Option`.
لهذا التعداد صيغتان: `None`، وهي المكافئة لـ `null` في Rust؛ و`Some(T)`، حيث `T` قيمة من أي نوع.

وهو يبدو هكذا:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

يمكنك أن تنظر إلى `Option` على أنه طبقة أمان بينك وبين المشكلات التي قد تسببها مراجع `null`، مع الإبقاء على فائدتها المفهومية.

## استخدام `Option`

تعيين متغير إلى `None` أمر مباشر إلى حد ما:

```rust
let nothing: Option<u32> = None;  // Variable nothing is set to None
```

لكن إن أردت أن يحمل نوع `Option` قيمة، فلا يمكنك إسناد هذه القيمة مباشرة.
فمتغير من نوع `Option` ومتغير من نوع `i32` مثلًا ليسا متكافئين.
ستحتاج إلى استخدام `Some`:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Some(-4); // This will work
let another_right_way = Some(-4); // Compiler infers that this is Option<i32>
```

ولهذا السبب أيضًا لن يعمل ما يلي:

```rust
let number = 47;
let option_number = Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

إن أردت الحصول على القيمة التي يحتويها `Some`، فستحتاج أولًا إلى التحقق من وجودها:

```rust
let mut some_words = Some("choose something to say"); // some_words set to something

match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "Here, we will choose something to say"

some_words = None; // some_words now set to None

// exactly the same match block as above
match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "I've got nothing to say"
```

إلى جانب `match`، تمتلك Rust أدوات أخرى متاحة للتحقق من القيم الموجودة داخل `Option` والوصول إليها، لكن `match` لا بد أن يكون مألوفًا لك الآن.

وبالإضافة إلى ذلك، اعتبر هذا توضيحًا لسبب استخدام Rust لـ `Option` بدلًا من مرجع `null`.
والفكرة هي أنه **_يجب_ عليك أن تتحقق** مما إذا كان متغير `Option` يساوي `Some` (وفي هذه الحالة يمكنك المضي قدمًا واستخراج القيمة الموجودة داخله واستخدامها)، أم أنه يساوي `None`.
وأي شيء غير ذلك، فلن يُترجم برنامجك؛ فالمترجم يحميك من `null`.
