# دليل الأسلوب في C

يصف هذا الدليل الأسلوب المقصود استخدامه مع ملفات الأمثلة والاختبارات الخاصة بتمارين مسار C.

القواعد الواردة في هذا الدليل تأتي إضافةً إلى تلك التي يحددها ملف [.clang-format][]، أو للتنبيه عليها.

## معيار C

ينبغي أن يتوافق الكود مع معيار C99، المعروف رسميًا باسم ISO/IEC 9899:1999.
وينبغي عدم استخدام POSIX، أو أي دوال مكتبة أو أنواع أو مراجع أخرى غير قياسية وخارجة عن التنفيذ.

## الأسماء

عمومًا، ينبغي أن تستخدم أسماء الأنواع والمتغيرات والبنى والملفات أسلوب snake case بحروف صغيرة كلها، مع استخدام الشرطات السفلية `_` للفصل بين مكوّنات الاسم.

```c
void some_foo_function(char * input_string, int input_string_length);
```

### التعدادات

ينبغي أن تكون أسماء التعداد مفردة عادةً لا جمعًا.

وينبغي أن تستخدم تسميات التعداد snake case بحروف كبيرة كلها.

```c
enum heading {
    HEADING_NORTH,
    HEADING_EAST,
    HEADING_SOUTH,
    HEADING_WEST
}
```

### الماكرو

وحدات الماكرو التي تعرّف الثوابت تُسمّى باستخدام snake case بحروف كبيرة كلها.

```c
#define CONSTANT 0x4000
```

نُقدّر استخدام snake case بحروف كبيرة لأسماء الماكرو، لكن الماكرو التي تشبه الدوال يمكن تسميتها بـ snake case بحروف صغيرة.

### الأنواع

تُفضَّل الأنواع القياسية ذات العرض الثابت (في `stdint.h`) على أنواع الأعداد الصحيحة الأساسية.

ويُفضَّل النوع `bool` (من `stdbool.h`) على `_Bool`.

وبالمثل، يُفضَّل `size_t` و`ptrdiff_t` (من `stddef.h`) لتمثيل الكميات المتعلقة بالذاكرة.

وينبغي تسمية الأنواع التي يعرّفها البرنامج باستخدام `typedef` بلاحقة `_t`.
ومع إدراكنا أن POSIX تحتفظ باللاحقة `_t`، فإن المسار لا يستخدم POSIX حاليًا.

## حرّاس التضمين

ينبغي استخدام حرّاس التضمين في جميع ملفات الترويسة.

وعمومًا، ينبغي أن تُحيط مجموعة واحدة من حرّاس التضمين بكامل محتوى الترويسة.

وينبغي أن تستخدم الحرّاس في التنفيذ المثال (`.meta/example.h`) وملف التمرين الأولي (`exercise_name.h`) أسماء ماكرو تتبع اسم التمرين.
وينبغي أن تتبع أسماء ماكرو الحرّاس القاعدة المذكورة أعلاه بشأن حالة الأحرف في الماكرو.

على سبيل المثال، بالنسبة للتمرين `hello-world`، استخدم:

```c
#ifndef HELLO_WORLD_H
#define HELLO_WORLD_H

//...

#endif
```

## المعاملات

ينبغي تسمية معاملات الدوال في كلٍّ من التصريح والتعريف لجميع الدوال.
وينطبق هذا على ملفات `.c` و`.h` كليهما.
وينبغي أن تتطابق الأسماء المستخدمة في جميع المواضع.
أي أن النموذج الأولي التالي للدالة صحيح في C، لكن الأسلوب غير صحيح لأن المعامل غير مُسمّى: `void foo(int);`.
أما النموذج الأولي الصحيح، بشرط أن تستخدم جميع التصريحات الأخرى والتعريف أيضًا اسم المعامل `bar`، فهو `void foo(int bar);`.

وحيث يكون ذلك أبسط أو أنسب، تُفضَّل المعاملات التي تتطلب تمرير الوسائط بالقيمة بدلًا من المؤشر.
لاحظ على وجه الخصوص أن هذا يشمل معاملات النوع `struct`.

وإذا لم يكن متوقعًا أن يغيّر الطالب قيم معامل من نوع المؤشر داخل تنفيذه، فينبغي أن يكون ذلك المعامل مؤهَّلًا بـ `const`.

## تخطيط ملف الاختبار

يتبع ملف الاختبار لكل تمرين تخطيطًا معينًا.
ويهدف هذا التخطيط إلى مساعدة المساهمين في تحديد أجزاء الملف، ومساعدة المتعلمين على فهم كيفية عمل الاختبارات.

ومثل معظم ملفات مصدر C، يبدأ ملف الاختبار بالتضمينات.

```c
#include "vendor/unity.h"
#include "../src/file_under_test.h"
// any other includes here
```

ثم تأتي بعد التضمينات الدالتان `setUp()` و`tearDown()`.
وحتى الآن، لا يستخدم أي تمرين هاتين الدالتين (فجسماهما فارغان)، ومع ذلك يجب أن تبقيا في مكانهما لتتمكن ملفات الاختبار من التصريف بشكل صحيح عبر جميع المنصات.

```c
void setUp(void)
{
}

void tearDown(void)
{
}
```

ثم تأتي أي دوال مساعدة تستخدمها دوال الاختبار.
وينبغي ألا تستخدم أسماء هذه الدوال المساعدة البادئة `test_`.

ثم تأتي دوال الاختبار نفسها.
وتستخدم أسماء هذه الدوال البادئة `test_`.
وفيما عدا الأولى، ينبغي أن تحتوي كل دالة اختبار على `TEST_IGNORE();` كأول عبارة فيها.
وينبغي أن يتبع أول ظهور لهذا تعليق السطر `// delete this line to run test`.

على سبيل المثال:

```c
static void test_the_first(void)
{
   test_first_foo();
}

static void test_the_second(void)
{
   TEST_IGNORE();               // delete this line to run test
   test_second_foo();
}

static void test_the_third(void)
{
   TEST_IGNORE();
   char grade = 'A';
   test_third_foo(grade);
}
```

وفي آخر الملف تأتي الدالة `main()`.
ويتبع جسم الدالة main تخطيطًا معينًا هو الآخر.
أولًا استدعاء لـ `UNITY_BEGIN()` يتبعه سطر فارغ، ثم الاختبارات.
ويتبع الاختبار الأخير سطر فارغ آخر قبل إرجاع نتيجة `UNITY_END()`.

```c
int main(void)
{
    UNITY_BEGIN();

    RUN_TEST(test_foo);
    RUN_TEST(test_bar);

    return UNITY_END();
}
```
