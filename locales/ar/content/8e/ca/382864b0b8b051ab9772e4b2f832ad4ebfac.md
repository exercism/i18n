# الاختبارات

كل تمرين يوفّر اختبارات الوحدة ووصفة بناء CMake. وأنت تقدّم التنفيذ.
كل ملف اختبار مُعدّ ليرتبط بتنفيذك لتوفير برنامج تنفيذي يعمل في الطرفية يشغّل الاختبارات. تشغيل البرنامج التنفيذي للاختبارات يطبع رسائل لكل اختبار فاشل ويُبلّغ بحالة خروج غير صفرية عندما تفشل الاختبارات.

سيكون اسم ملف الاختبار `<exercise>_test.f90`، لذا فبالنسبة لتمرين "Bob" يكون الملف الذي يحتوي على الاختبارات هو `bob_test.f90`. سيحتوي كل اختبار على تعليق يصف الاختبار ثم الاختبار الفعلي الذي يبدأ بـ `call assert_equal`، على سبيل المثال.

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

لتعطيل اختبار، ما عليك سوى تحويله إلى تعليق باستخدام `'!'`، على سبيل المثال.

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

العمل على كل تمرين هو عملية من:

* إنشاء البناء الأولي باستخدام CMake
* لكل اختبار وحدة:
 * عالج أخطاء الترجمة لتجعل الاختبار يفشل.
 * نفّذ القدر الكافي فقط لجعل الاختبار ينجح.
 * أعد هيكلة تنفيذك لتحسين قابلية القراءة وتقليل التكرار وما إلى ذلك.
 * أزل التعليق عن الاختبار التالي


## إنشاء البناء الأولي باستخدام CMake

سيأتي كل تمرين مع ملف `CMakeLists.txt` إلى جانب اختبارات الوحدة. وهو يحتوي على وصفة CMake الجاهزة التي تتولى البناء نيابة عنك. ولا يُفترض أن تحتاج إلى تعديل هذا الملف. تفترض الوصفة المقدَّمة أن تنفيذك موجود في ملف مصدري مسمّى تبعًا للتمرين.

على سبيل المثال، يتوقع تمرين "Bob" تنفيذًا في الملف `bob.f90`.

**أنشئ ملفات التنفيذ الأولية قبل تشغيل CMake.**
إذا لم يكن لديك الملف `bob.f90` عند تشغيل CMake لتمرين "Bob"، فسيولّد CMake خطأً حول عدم العثور على الملفات.
**يمكن أن تكون هذه الملفات فارغة، لكن يجب أن تكون موجودة.**

باستخدام هذه الوصفة، يستطيع CMake توليد مشروع مناسب لبيئتك عن طريق تشغيل `cmake -G` مع مولّد مناسب وموقع مجلد التمرين. سيولّد CMake نصًّا برمجيًّا للبناء مناسبًا لنظام تشغيلك. ولإبقاء تلك الملفات المولَّدة منفصلة عن الكود المصدري لتمرينك، من الشائع إنشاء مجلد باسم `build` يحتوي على ملفات البناء المولَّدة هذه، فضلًا عن الكود المُترجَم.

سيبقي هذا مجلد تمرينك مرتبًا وخاليًا من الفوضى.

**ملاحظة: في المرة الأولى التي يُستدعى فيها `cmake`، سيُنزَّل [testlib](###-Testlib) تلقائيًّا. تُعدّ `testlib` ضرورية لعمل اختبارات الوحدة.

بما أنك ستشغّل CMake لإنشاء تعليمات البناء لكل مهمة، فقد ترغب في إنشاء نص bash (Linux/MacOS) أو ملف دفعي (Windows) لهذا الأمر.

بمجرد أن ينشئ CMake بيئة البناء، يمكنك بناء الكود باستخدام الأمر المناسب لبيئتك:

* Linux مع make: `make`
* Windows مع Visual Studio: اختر Build / Build Solution من القائمة.
* Windows مع MingW: `mingw32-make.exe`
* Windows مع nMake: `nmake.exe`
* MacOS مع Xcode: اختر Build من شريط الأدوات

تظهر أدناه أمثلة على تشغيل CMake لبيئات مختلفة.

### Linux\MacOS مع Make

اسم المولّد في CMake هو `Unix Makefiles`.
بافتراض أن التمرين الحالي هو `bob` وأننا في مجلد التمرين:

```
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

يوضّح هذا المثال إنشاء ملفات فارغة للتنفيذ قبل تشغيل CMake.

ما عليك سوى كتابة make في مجلد البناء لترجمة الاختبارات. سيولّد هذا أخطاء وقت الترجمة. وبمجرد إصلاح الأخطاء، شغّل `make` مرة أخرى. وعند إصلاح كل أخطاء البناء، شغّل الاختبارات:

```
$ ctest -V
```
### Windows مع Visual Studio 2017

اسم المولّد في CMake هو `Visual Studio 15`. يدعم المولّد نفسه جميع إصدارات IDE من Visual Studio 2017: Community وProfessional وEnterprise. بافتراض أن التمرين الحالي هو `bob` وأننا في مجلد التمرين:

```
> copy nul: bob.f90
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

يوضّح هذا المثال إنشاء ملفات فارغة للتنفيذ قبل تشغيل CMake.

### Testlib

تعتمد الاختبارات على مكتبة صغيرة تُسمّى `testlib` تُنزَّل من github في المرة الأولى التي يُهيَّأ فيها البناء باستخدام cmake.

في حال فشل التنزيل، يمكن إجراء التنزيل يدويًّا، على سبيل المثال.

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/TesterMain.f90
```
