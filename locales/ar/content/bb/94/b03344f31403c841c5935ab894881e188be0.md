# نبذة


حان الوقت لنصل إلى أحد الأنماط الأساسية في C++: البرمجة كائنية التوجه (OOP). تتمحور البرمجة كائنية التوجه حول `classes`، وهي أنواع بيانات يعرّفها المستخدم، ولكل منها مجموعتها الخاصة من الدوال المرتبطة بها. سنبدأ بالأساسيات، ثم نتناول موضوعات أكثر تقدمًا في موضع أدنى من شجرة المنهج.

## الأعضاء

يمكن للأصناف أن تحتوي على **متغيرات الأعضاء** و**دوال الأعضاء**. ويتم الوصول إليها عبر عامل **اختيار الأعضاء** `.`. وكما هو الحال مع المتغيرات خارج `classes`، يُستحسن تهيئة متغيرات الأعضاء بقيمة عند التعريف. وستصبح هذه القيمة بعد ذلك القيمة الافتراضية للكائنات المنشأة حديثًا من هذا الصنف.

## التغليف وإخفاء المعلومات

تتيح الأصناف إمكانية تقييد الوصول إلى أعضائها. والحالتان الأساسيتان هما `private` و`public`. لا يمكن الوصول إلى الأعضاء `private` من خارج الصنف. ويمكن استدعاء الأعضاء `public` بحرية. جميع الأعضاء `private` بشكل افتراضي، ويجب تعليمها صراحةً حتى تصبح قابلة للاستخدام خارج الصنف.

## مثال أساسي

يمكنك أن ترى تعريف `class` جديد في المثال التالي. لاحظ وجود `;` بعد التعريف.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

يمكنك الوصول إلى جميع المتغيرات من داخل الصنف. ألقِ نظرة على `damage` داخل الدالة `cast_spell`. ولا يمكنك قراءة الأعضاء `private` أو تغييرها من خارج الصنف:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## المُنشئات

تتيح المُنشئات إمكانية إسناد قيم إلى متغيرات الأعضاء عند إنشاء الكائن. وهي تحمل الاسم نفسه الذي يحمله `class`، وليس لها نوع إرجاع. ويمكن للصنف أن يحتوي على عدة مُنشئات. ويفيد ذلك إذا لم تكن بحاجة دائمًا إلى ضبط جميع المتغيرات.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

المُنشئات موضوع واسع وفيه تفاصيل دقيقة كثيرة. إذا لم تُعرّف `constructor` صراحةً داخل `class` الخاص بك، فحينها وحدها سيقوم المُصرِّف بالمهمة نيابة عنك. وهذا ما حدث في المثال الأول أعلاه. أُنشئ الكائن _silverhand_ باستدعاء المُنشئ الافتراضي، ولم تُمرَّر أي وسائط. وقد ضُبطت جميع المتغيرات على القيمة المذكورة في تعريف الصنف. أما إذا لم تكن قد أعطيت أي قيم في ذلك التعريف، فقد تبقى المتغيرات غير مهيأة، وقد يؤدي ذلك إلى نتائج غير مقصودة.

## البُنى

جاءت البُنى من الجذور الأصلية للغة في C، وعمرها بعمر C++ نفسه. وهي في جوهرها الشيء نفسه الذي تمثله `classes`، مع استثناء واحد مهم. فبشكل افتراضي، كل شيء داخل `class` هو `private`. أما البُنى، فهي `public` حتى يُعرَّف خلاف ذلك. ومن المتعارف عليه أن الكلمة المفتاحية `struct` تُستخدم غالبًا من أجل **التراكيب التي تحتوي على بيانات فقط**. في حين تُفضَّل الكلمة المفتاحية `class` للكائنات التي تحتاج إلى ضمان خصائص معينة. وقد تكون هذه الخاصية الثابتة ألا تصبح قيمة `damage` في `class` `Wizzard` الخاص بك سالبة. فالمتغير `damage` خاص، وأي دالة تغيّر قيمته ستضمن الحفاظ على هذه الخاصية الثابتة.
