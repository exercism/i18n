# ملحق التعليمات

## عملية الإدخال والإخراج

على عكس بقية التمارين، يتطلب `grep` التفاعل مع «العالم الخارجي»: قراءة الملفات، والتعامل مع أخطاء النظام، والطباعة إلى `stdout`.

في Lean، يتم التفاعل مع النظام عادةً داخل الموناد [IO][io]، وهو يسمح بحدوث آثار جانبية في بيئة معزولة دون التأثير على الحالة النقية لمعظم الدوال الأخرى.

## قراءة الوسائط

يسمح Lean باستدعاء ملف كسكربت، إما مباشرةً كسكربت مستقل عبر `lean --run` أو باستخدام `lake`.

لمشروع Lean نقطة دخول واحدة، وهي دالة تُسمى `main`، وتأخذ `List String` يحوي جميع الوسائط الممرَّرة إليها.
ولمحاكاة تشغيل `Grep.lean` كملف تنفيذي، تُمرَّر الوسائط بالطريقة نفسها في هذا التمرين.

## قراءة الملفات

يوفر Lean [دوال][files] للتعامل مع الملفات داخل الموناد `IO.FS`.
على سبيل المثال، يمكن استخدام `IO.FS.readFile` لقراءة محتويات ملف في مسار معين، على شكل `String`.

## كتابة المخرجات

بدلًا من إرجاع قيمة، يتطلب هذا التمرين كتابة النتائج إلى المخرج القياسي أو الخطأ القياسي.
توجد [دوال][console] في Lean لهذا الغرض.

## التعامل مع أخطاء النظام

على عكس الأخطاء في `Except`، فإن استثناءات `IO` هي في الواقع استثناءات وقت التشغيل.
يمكنك استخدام `try`/`catch` للتعامل معها:

```
try
    /- 
        code that may possibly raise an exception 
    -/
catch msg =>
    /-
        code that is executed only if an exception was thrown
    -/
```
