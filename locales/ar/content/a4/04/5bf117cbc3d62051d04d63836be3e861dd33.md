# About

Elm لغة ممتعة لبناء تطبيقات ويب موثوقة.
تتميز برسائل خطأ ودّية، وأداء ممتاز، وملفات صغيرة، ولا توجد استثناءات أثناء التشغيل.

ربما يكون أشهر جزء في Elm وأكثره نسخًا هو The Elm Architecture، وهو نمط بسيط لهيكلة تطبيقات الويب، وبه تُكتب جميع تطبيقات الويب في Elm.

الفكرة الأساسية أن الكود يُبنى حول `Model` يمثّل حالة تطبيقك، وحول طريقة لتحديث النموذج عبر `update`، وطريقة لعرضه عبر `view`.

يحتوي `Model` على حالة التطبيق، أي كل البيانات التي يحتاجها التطبيق.
ويمكن أن يكون أي نوع، لكنه في أي تطبيق مفيد يكون عادةً [سجلًا][record].
إذا تخيّلت تطبيقًا بسيطًا فيه مربع نص، ونص يعرض ذلك النص معكوسًا، فسيبدو النموذج كما يلي.
يمكنك أيضًا رؤية هذا المثال في [دليل Elm][elm-guide-text-fields].

```elm
type alias Model =
  { text : String
  }
```

‏`update` دالة تُستدعى مع `Msg` عند حدوث تغيير (مثل نقر المستخدم على زر).
تأخذ `Msg` و`Model` الحالي، وتُرجع `Model` جديدًا.
ويمكن أن يكون `Msg` أي نوع، لكنه عادةً [نوع مخصص][custom-type].

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

وكما هو الحال مع كل الأنواع المخصصة، يمكن أن تتضمن متغيرات `Msg` ما تحتاجه من معلومات حرة.
في المثال أعلاه يتضمن المتغير `TextChanged` قيمة من نوع `String`.

‏`view` دالة تُرجع HTML لعرضه للمستخدم في المتصفح.
تأخذ `Model` الحالي وتُرجع `Html Msg` (النوع الذي يستخدمه Elm لتمثيل HTML).
لكل عنصر HTML (مثل `<div>`) دالة مقابلة في Elm (`Html.div`) داخل حزمة `Html`.
تأخذ كل من هذه الدوال معاملين: الأول مصفوفة سمات (من حزمتي `Html.Attributes` و`Html.Events`)، والثاني مصفوفة عناصر فرعية (دوال من حزمة `Html`).
وهناك أيضًا دالة `text` لتمثيل محتوى HTML النصي، وهي تأخذ معاملًا واحدًا من نوع سلسلة نصية، لكنها تُستخدم فيما عدا ذلك بالطريقة نفسها التي تُستخدم بها بقية الدوال والعناصر في حزمة `Html`.

يمكن لدالة `view` أن تحدد أن أحداثًا معينة، مثل النقر على زر أو تحرير نص في مربع نص، تؤدي إلى إنشاء `Msg`، يستخدمه Elm Runtime لاستدعاء دالة `update` وتعديل `Model` وتوليد HTML محدَّث.
في الكود أدناه يحدث هذا عبر `Html.Events.onInput TextChanged`.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

يتوقع `Html.Events.onInput` أن تُمرَّر إليه دالة (`String -> Msg`) سيستخدمها لإنشاء `Msg`.
وتتوقع الأحداث المختلفة دوالًا مختلفة بحسب المعلومات التي يمكنها تقديمها، فمثلًا يتوقع `Html.Events.onCheck` (لمربعات الاختيار) دالة من النوع `Bool -> Msg`، بينما يتوقع `Html.Events.onClick` قيمة `Msg` فقط.

لغة Elm نقية ووظيفية ولا يمكن تعديل أي قيمة فيها، لذلك يتولى Elm Runtime التعامل مع كل ما يتغير.
يمكنك الاطلاع على جميع [عناصر HTML][html-elements] و[سمات العناصر][element-attributes] و[أحداث HTML][html-events] المختلفة في سجل حزم Elm.

هناك 4 "مستويات" لتطبيقات الويب يمكنك كتابتها بـ Elm، تزداد قوة وتعقيدًا تدريجيًا (رغم أن Elm يبقى لغة ومنظومة بسيطة وممتعة).
وكلها معرّفة في [حزمة Browser][browser-package]:

- [sandbox][browser-sandbox]: التفاعل مع إدخال المستخدم، مثل الأزرار ومربعات الاختيار
- [element][browser-element]: التواصل مع العالم الخارجي باستخدام HTTP والتفاعل مع JavaScript
- [document][browser-document]: التحكم في `<title>` و`<body>` لصفحة ويب
- [application][browser-application]: إنشاء تطبيقات كاملة من نوع الصفحة الواحدة تتعامل مع التوجيه وتغييرات الروابط

يستخدم هذا المفهوم [sandbox][browser-sandbox] لأنه الأبسط (ولأنه sandbox، فالتعامل مع محرر Exercism على الويب أسهل نسبيًا).
يجب أن تُسمّى وحدة الدخول لبرنامج Elm بـ `Main`، وأن تُسمّى الدالة التي تنشئ التطبيق بـ `main`، كما يلي.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

لقد رأينا بالفعل دالتي `update` و`view`، ويحتاج [sandbox][browser-sandbox] إضافةً إلى ذلك إلى دالة `init` تُرجع الحالة الابتدائية للـ `Model`.
