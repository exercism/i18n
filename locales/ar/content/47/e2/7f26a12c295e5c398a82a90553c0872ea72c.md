# مقدمة

في لغة C، **بنية** هي نوع مركّب يتكوّن من حقول مختلفة، ولكل حقل نوعه وحجمه الخاص.

على سبيل المثال، يعرّف هذا نوعًا مركّبًا من ثلاثة أعداد صحيحة، اثنان بحجم 4 بايتات وواحد بحجم 8 بايتات:

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

وقد تحتوي البنية أيضًا على بنى أخرى:

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

إذا كان أحد حقول البنية مصفوفة، فإن كل البايتات المخصّصة للمصفوفة تكون جزءًا من البنية.
أما إذا كان الحقل مجرّد مؤشر إلى المصفوفة، فيجب تخزين المصفوفة في مكان آخر:

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## المحاذاة

**محاذاة** النوع هي قوة غير سالبة من قوى العدد اثنين (1، 2، 4، 8، ...) تمثّل شرطًا مفروضًا على عنوانه.
ويجب أن يقع كل كائن من ذلك النوع في عنوان يكون مضاعفًا لمحاذاته.

بالنسبة إلى نوع أولي، تكون المحاذاة عادةً مساوية لحجمه، لذا يكون لـ`int32_t` مثلًا محاذاة من 4 بايتات عادةً.
وهذا يعني أن `int32_t` يجب أن يُخصَّص عند حدود من 4 بايتات.

أما محاذاة البنية فهي أكبر محاذاة بين حقولها.
فمثلًا، البنية `struct example` المعرّفة أعلاه تكون محاذاتها 8 بايتات، لأن هذه هي محاذاة `uint64_t`.

إذا كانت محاذاة أحد حقول البنية أصغر من محاذاة البنية، فقد تُدرَج بايتات حشو بعد ذلك الحقل.
وهذا يضمن أن الحقول التالية والبنية ككل تلبّي متطلبات المحاذاة.
وعمليًا، يعني هذا أنه على الرغم من أن بايتات الحشو تلك تسهم في حجم البنية، فإنها لا تُستخدم في قيمة البنية:

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

لاحظ أن الحقل 'one_byte' في البنية المعرّفة أعلاه محاذاته 1، ويمكن وضعه في أي عنوان.
وبما أن الحقل 'four_byte' محاذاته 4، فيجب أن تحترم الحقول في البنية أيضًا حدود 4 بايتات.
وهذا يعني أنه يجب أن يكون عدد البايتات بين أي حقلين في البنية مضاعفًا للعدد 4.
وبما أن 'one_byte' يشغل بايتًا واحدًا فقط، تُدرَج 3 بايتات حشو بعده لاحترام هذا الحد.

تُجمَّع الحقول المتجاورة كلما أمكن لتقليل عدد بايتات الحشو اللازمة:

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

ويجب أن يحترم هذا التجميع أيضًا محاذاة كل حقل:

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

وهذا يعني أن تغيير ترتيب الحقول في البنية قد يؤدي أحيانًا إلى اختلاف في حجمها:

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

لاحظ أن محاذاة المصفوفة هي نفس محاذاة نوعها الأساسي:

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

ويمكن تجميع عناصر المصفوفة بالطريقة نفسها كما لو لم تكن جزءًا من مصفوفة:

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

من المهم أن تأخذ في الحسبان أي بايتات حشو محتملة عند الوصول إلى بنية في لغة التجميع.

## اصطلاح الاستدعاء

عمومًا، تُمرَّر القيم إلى الدوال وتُرجَع منها كما هو متوقّع:

- تُمرَّر الأعداد الصحيحة، بما فيها عناوين الذاكرة والتعدادات، في سجلات الأغراض العامة (GPR).
- وتُمرَّر قيم الفاصلة العائمة في سجلات `xmm`.

أما البنى فهي حالة خاصة.
وكقاعدة عامة، تشغل جميع حقول البنية مساحة متجاورة في الذاكرة، وينبغي وضعها في سجل واحد كلما أمكن:

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

إذا كانت للبنية حقول بقيم صحيحة وأيضًا حقول بقيم الفاصلة العائمة، فينبغي تصنيف كل 8 بايتات متتالية في البنية على حدة:

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

وإذا وُجدت أعداد صحيحة وقيم فاصلة عائمة في 8 بايتات واحدة، كان النوع عددًا صحيحًا ووُضعت الـ8 بايتات كاملة (بما فيها قيمة الفاصلة العائمة) في سجل أغراض عامة:

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
عند إجراء تحويل من قيمة فاصلة عائمة إلى عدد صحيح باستخدام `cvtss2si` أو `cvtsd2si`، فإن هذا يغيّر تنظيم البايتات الأساسية.

يمكنك استخدام `movd` (لقيم 32 بت) و`movq` (لقيم 64 بت) لنقل بايتات خام من سجل `xmm` إلى سجل أغراض عامة، دون تغيير تمثيل البتات.
~~~~

لكن، البنى التي يزيد حجمها على 16 بايتًا توضع عادةً في الذاكرة، بغض النظر عن نوع كل 8 بايتات:

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

عند تمرير بنية كوسيط إلى دالة، فإنها تستخدم من السجلات ما يلزم.
أما إذا وُضعت في الذاكرة، فيُستخدم المكدّس بدلًا من ذلك.

وتنطبق قواعد مشابهة على البنى المُرجَعة من دالة.
فعادةً ما تُرجَع أولًا في `rax` و`rdx` (إذا كانت قيمتها صحيحة) أو في `xmm0` و`xmm1` (إذا كانت قيمتها فاصلة عائمة).
أما إذا وُضعت في الذاكرة، فيجب على المستدعي أن يحجز لها مساحة وأن يمرّر عنوان موقع الذاكرة هذا كوسيط أول ضمني إلى الدالة (في `rdi`).
ثم تخزّن الدالة البنية في هذه المساحة وتُرجع عنوانها في `rax`.
