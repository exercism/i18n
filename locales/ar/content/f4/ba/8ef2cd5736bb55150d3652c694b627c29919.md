# الأصناف المجرّدة

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## علامة `$` جزء من الاسم

يُسمّى كل صنف مجرّد بعلامة `$` بادئة، ولا تُستخدم هذه العلامة إلا مع الأصناف المجرّدة. لذا فإن أي نوع يبدأ بـ `$` هو نوع لا يمكنك إنشاء كائن منه، وهذا واضح أينما ظهر الاسم.

## ما الذي يجوز أن يوجد فيه

توقيعات الإجراءات والمكرّرات، وتنتهي عند الفاصلة المنقوطة. لا أجساد، ولا سمات، ولا `create`. يصف الصنف المجرّد ما يمكن *أن يُطلب* من شيء ما، وليس ما يحتفظ به.

## المطابقة

```sather
class TRAPEZE < $ACT is
```

يجب أن يعرّف الصنف كل إجراء مدرج، مع أنواع وسائط ونوع إرجاع مطابقة. ويُتحقق من ذلك عند الترجمة.

قد يطابق الصنف عدة أصناف:

```sather
class TRAPEZE < $ACT, $RISKY is
```

وقد يمتد صنف مجرّد من صنف مجرّد آخر:

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## أين يحدث الإرسال

يحمل المتغير من نوع مجرّد مرجعًا إلى كائن مطابق ما. واستدعاء إجراء عليه يختار النسخة التي تنتمي إلى الصنف الحقيقي للكائن، أثناء التشغيل.

ذلك هو الموضع الوحيد الذي يقرر فيه Sather أي شيء أثناء التشغيل. أما الاستدعاء على متغير من نوع ملموس فيُحسم عند الترجمة.

## `typecase`

أحيانًا يكون النوع مهمًا حقًا. يسأل `typecase`:

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

داخل أحد الفروع، يأخذ المتغير النوع الأضيق. لا تلجأ إليه إلا نادرًا: فاستخدام `typecase` مع كل نوع من أنواع العرض غالبًا ما يكون إجراءً كان ينتمي إلى الصنف المجرّد من البداية.

## `$OB`

`$OB` هو الصنف المجرّد الذي يطابق كل كائن. وهو مفيد أحيانًا، وغالبًا ما يكون علامة على أن نوعًا قد ضاع في الطريق.

## لماذا لا نستخدم الوراثة؟

يفصل Sather بين أمرين تدمجهما معظم اللغات. تقول `<` فقط ما يمكن للصنف أن *يفعله*. أما الحصول على تنفيذ من مكان آخر فهو `include`، وهو التمرين الثاني بعده، وهو قرار منفصل.
