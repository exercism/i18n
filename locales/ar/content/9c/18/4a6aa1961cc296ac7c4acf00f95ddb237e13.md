# تضمين الكود

استخدم `circus-acts` الرمز `<` ليقول إن صنفًا *يستطيع* أن يفعل ما يصفه صنف مجرّد، لكنه لم يقل شيئًا عن الكيفية.

`include` هي النصف الآخر: فهي تأخذ الكود الفعلي من صنف آخر وتضع نسخة منه في هذا الصنف.

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

قيمة `JAZZ_ROUTINE::count` هي 8، من دون أن يذكر `JAZZ_ROUTINE` ذلك.

## هذان قراران منفصلان

معظم اللغات تدمجهما: كلمة `extends` واحدة تورّث الكود وتجعل الصنف الفرعي صالحًا للاستخدام في أي موضع يُطلب فيه الصنف الأعلى. أما في Sather فيبقى القراران منفصلين.

| ما يُكتب | ما يعنيه |
| --- | --- |
| `class A < $B` | يمكن استخدام `A` في أي موضع يُطلب فيه `$B` |
| `class A is include B` | يبدأ `A` بنسخة من كود `B` |

يمكن استخدام أحدهما دون الآخر، أو كليهما معًا. تضمين صنف **لا** يجعله نوعًا فرعيًا: فبعد `include WARM_UP`، لا يزال لا يمكن استخدام `JAZZ_ROUTINE` في موضع يُطلب فيه `WARM_UP`، ولا شيء يدّعي غير ذلك.

## إعادة التسمية

يمكن إدخال روتين مُضمَّن باسم مختلف:

```sather
   include WARM_UP count -> warm_up_count;
```

وإذا كان هناك أكثر من روتين، فتُفصل بينها بفواصل:

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## استبعاد أحدها

إعادة التسمية إلى *لا شيء* تستبعده، وهذه هي طريقة استبداله:

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

يُضمَّن `count` كالمعتاد، أما `describe` فلا، ولذلك لا يُعدّ كتابة واحدة هنا تعارضًا. ولولا `describe -> ;` لرفض المصرّف الكود: وجود روتينين بالاسم نفسه والوسائط نفسها في صنف واحد خطأ، ولن يخمّن Sather أيّهما كنت تقصد.

وهذا هو الفرق بينه وبين التجاوز في معظم اللغات: فالاستبدال يُعلن عنه صراحةً بدلًا من أن يكون ضمنيًا.
