# نبذة

[الحلقة][control] هي تسلسل من التعليمات يمكن أن يُنفَّذ أكثر من مرة، إلى أن يتحقق شرط النهاية.

في معمارية x86-64 تُنشأ الحلقة عادةً بقفزة إلى وسم سابق:

```x86asm
example_loop:
    ...
    jmp example_loop
```

لاحظ أن القفزة غير الشرطية إلى وسم سابق ستنقل التنفيذ دائمًا إلى هذا الوسم.
وهذا يعني أن الحلقة ستظل تتكرر إلى ما لا نهاية، ما لم توجد قفزة أخرى إلى خارج التسلسل المتكرر.

على سبيل المثال، هذه الحلقة لا تنتهي:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

وهذه الحلقة قد تنتهي، حسب تحقق الشرط:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## حلقات العدّ

تنتهي حلقة العدّ دائمًا تقريبًا بالطريقة نفسها: تعليمة تُحدّث عدادًا أو تقارن قيمتين، تتبعها مباشرةً قفزة شرطية تقرر ما إذا كان التنفيذ سيعيد الكرّة أم لا.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
لا حاجة إلى `cmp rsi, 0` في الكود أعلاه، لأن `sub rsi, 1` تضبط بالفعل `zero flag (ZF)` عندما تكون النتيجة `0`.

ورغم أن `cmp` هي الطريقة الأساسية لاختبار الشروط في لغة التجميع، فإن تعليمات كثيرة تُحدّث الأعلام.
على سبيل المثال، تضبط تعليمات كثيرة للحساب على الأعداد الصحيحة أو للعمليات على البتات `ZF` عندما تكون النتيجة `0`، و`SF` عندما تكون النتيجة سالبة (أي عندما تكون البتة العليا مضبوطة).

يمكنك الرجوع إلى [مرجع][reference] لمعرفة الأعلام التي تتأثر بكل تعليمة.

[reference]: https://www.felixcloutier.com/x86/
~~~~

لاحظ أن `rsi` في المثال أعلاه مفترض أن يكون أكبر من `0`.
ولو كان `0`، فإن `sub rsi, 1` ستُنقص `rsi` إلى `-1`، وهو عدد كبير جدًا غير مُوقَّع.
وسيلزمه `18,446,744,073,709,551,615` تكرارًا إضافيًا قبل أن تنتهي الحلقة أخيرًا.
كذلك، لأن طول المصفوفة `0`، فإن أي وصول إلى الذاكرة سيكون خارج الحدود.

إذا لم تكن هناك أي ضمانات بخصوص طول المصفوفة، فهناك أسلوبان شائعان.

الأول هو نقل شرط النهاية إلى بداية الحلقة، ثم وضع قفزة غير شرطية في النهاية:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

والثاني هو الاختبار مرة واحدة لمصفوفة طولها صفر قبل بداية الحلقة:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

هذا الأسلوب الثاني أكثر كفاءة عادةً من الأول، لأن عدد التفريعات في جسم الحلقة أقل.
وستتعلم المزيد عن هذا في مفهوم لاحق.

## العمليات الدقيقة

لا ينفّذ المعالج تعليمة مثل `add` أو `jnz` مباشرةً.
بل تفكّ الواجهة الأمامية للمعالج ترميز كل تعليمة أولًا إلى خطوة داخلية واحدة أو أكثر من الخطوات الأصغر، تُسمى **العمليات الدقيقة** (أو **micro-ops**).
ثم يقوم المعالج بجدولة هذه العمليات الدقيقة وتنفيذها، وغالبًا ما ينفّذ عدة منها في الدورة الواحدة وخارج ترتيبها الأصلي.

تفكّ معظم التعليمات البسيطة ترميزها إلى عملية دقيقة واحدة، بينما قد تُفكّ التعليمة الأكثر تعقيدًا إلى عدة عمليات.
ولأن العبء الحقيقي للمعالج هو تدفّق العمليات الدقيقة، فإن إنتاج عدد أقل منها للمهمة نفسها هو أحد الأسباب التي تجعل الكود أسرع.

## الدمج الكلي

كما ذُكر سابقًا، تنتهي الحلقة عادةً بنوع من القفزات الشرطية.
وهذا شائع لدرجة أن المعالجات الحديثة مُحسَّنة لهذا النمط أثناء فك الترميز.

يمكن فك ترميز تعليمة تضبط الأعلام تتبعها مباشرةً قفزة شرطية تقرأ هذه الأعلام معًا في **عملية دقيقة واحدة**، بدلًا من عملية لكل منهما.
ويُسمى هذا **الدمج الكلي**.

ويتصرف الزوج المندمج كعملية واحدة: يُحدَّث العداد ويُتخذ قرار التفريع معًا، في عملية دقيقة واحدة.
وبذلك لا يكلّف تدفق التحكم في الحلقة شيئًا تقريبًا فوق العمل الذي تقوم به الحلقة فعليًا.

وكقاعدة عامة، يندمج نوعان من الأزواج عادةً بهذه الطريقة:

- تعليمات حسابية مثل `add` أو `sub`، تتبعها مباشرةً قفزة شرطية.
- تعليمة `cmp` أو `test` أو `and`، تتبعها مباشرةً قفزة شرطية.

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

لا يحدث الدمج إلا عندما تأتي القفزة الشرطية **مباشرةً** بعد التعليمة التي تضبط الأعلام، دون أي شيء بينهما.

~~~~exercism/note
يعتمد الدمج الكلي على المعالج، وهناك بعض الاختلاف في التعليمات التي تندمج مع أي قفزة شرطية.

ومن المراجع المفيدة [البنية الدقيقة لمعالجات Intel و AMD و VIA، بقلم Agner Fog][agner-uarch].
كما يورد القسم 3.4.2.2 (التحسين من أجل الدمج الكلي) من [دليل التحسين لمعالجات Intel][intel-opt] أزواجًا قابلة للدمج في معالجات Intel.

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## الأمر `loop`

هناك بعض التعليمات التي يمكن استخدامها لإنشاء سلوك شبيه بالحلقات.
وإحداها هي [loop][loop].

وهي تأخذ قيمة واحدة هي وسم يحمل عنوان بداية الحلقة.

تستخدم التعليمة `loop` القيمة الموجودة في `rcx` كعداد، وتُنقصها بمقدار 1 في كل مرة.
وبمجرد أن تصل القيمة في `rcx` إلى الصفر، تنتهي الحلقة ويتابع التنفيذ بشكل متسلسل:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

هناك صيغتان للتعليمة `loop` تفحصان علم الصفر (`ZF`) في كل تكرار.
وإلى جانب إيقاف الحلقة بمجرد أن يصل `rcx` إلى الصفر، فإنهما تتوقفان أيضًا عندما لا يتحقق الشرط.

| تعليمة            | شرط       |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

هذه التعليمات **لا تضبط** `ZF`.
ولا بد من وجود `cmp` أو `test` أو أي تعليمة أخرى تغيّر `ZF` قبلها:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
على الرغم من سهولتها، فإن `loop` و`loope` و`loopne` أبطأ عادةً بكثير على المعالجات الحديثة من تسلسل `sub`/`jnz` أو `cmp`/`jnz` المكافئ.

ومن المراجع الجيدة حول أداء التعليمات في العديد من المعالجات المختلفة [جداول Agner][agner-tables].

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
