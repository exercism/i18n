# مقدمة

يستخدم Elixir ما يُعرف بـ_Behaviours_ في الكود لتوفير واجهات عامة مشتركة، مع تسهيل تطبيقات محدّدة لكل وحدة تطبّقها. ومن الأمثلة الشائعة على ذلك _Access Behaviour_.

توفّر _Access Behaviour_ واجهة مشتركة لاسترجاع البيانات من بنية بيانات قائمة على المفاتيح. وهي مُطبَّقة على الخرائط ومصفوفات الكلمات المفتاحية، لكن لنلقِ نظرة على استخدامها مع الخرائط لنأخذ فكرة عنها. تحدّد _Access Behaviour_ أنك حين يكون لديك خريطة، يمكنك أن تكتب بعدها _الأقواس المربعة_ ثم تستخدم المفتاح لاسترجاع القيمة المرتبطة به.

```elixir
# Suppose we have these two maps defined (note the difference in the key type)
my_map = %{key: "my value"}
your_map = %{"key" => "your value"}

# Obtain the value using the Access Behaviour
my_map[:key] == "my value"
your_map[:key] == nil
your_map["key"] == "your value"
```

إذا لم يكن المفتاح موجودًا في بنية البيانات، فستُرجع القيمة `nil`. وقد يكون هذا مصدرًا لسلوك غير مقصود، لأنه لا يرفع خطأ. لاحظ أن `nil` نفسه يطبّق Access Behaviour ويُرجع `nil` دائمًا لأي مفتاح.
