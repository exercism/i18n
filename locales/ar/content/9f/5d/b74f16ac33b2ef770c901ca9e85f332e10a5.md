# بنّاءات السلاسل النصية

`STR` غير قابل للتغيير؛ أما `FSTR` فليس كذلك. استخدم `STR` للنص المكتمل و`FSTR` للنص الذي ما زال يُجمَّع.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## أعد إسناد النتيجة دائمًا

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR` ينمو بواسطة **المضاعفة المطفأة**: عندما ينفد ما لديه من مساحة، يأخذ مصفوفة جديدة أكبر، بضعف الحجم، وينسخ إليها. إذن تكون النتيجة عادةً الكائن نفسه، وأحيانًا كائنًا آخر. كتابة `b := b + x` في كل مرة صحيحة في الحالتين، وهي الصيغة الوحيدة التي تستحق التعلّم.

## لماذا لا نستخدم `+` مع `STR` فقط؟

إن ضم عدد ثابت وصغير من القطع باستخدام `+` واضح ولا بأس به:

```sather
   return piece + " by " + composer;
```

المشكلة فقط في الحلقة، حيث لا يكون عدد عمليات الضم معروفًا عند كتابة الكود. قاعدة تقريبية: إذا كان `+` داخل `loop`، فاستخدم `FSTR`.

## إجراءات مفيدة

| الاستدعاء | ما يفعله |
| --- | --- |
| `b + x` | يضيف؛ قد يكون `x` من النوع `STR` أو `CHAR` أو `INT` أو `BOOL` … |
| `b.size` | عدد الأحرف حتى الآن |
| `b.str` | `STR` مكتمل |
| `b.clear` | يفرغه مع الاحتفاظ بالمساحة |

## متتاليات الهروب

| المكتوب | المعنى |
| --- | --- |
| `"\n"` | سطر جديد |
| `"\t"` | علامة جدولة |
| `"\""` | علامة اقتباس مزدوجة |
| `"\\"` | شرطة مائلة عكسية |
