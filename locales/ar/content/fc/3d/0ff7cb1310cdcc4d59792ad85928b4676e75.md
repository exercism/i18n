# التعليمات

وظّفتك للتو شركة Mecha Munch™، وهي شركة لأتمتة التسوق من متاجر البقالة، للعمل على تطبيق الطلبات الخاص بها.
مهمة فريقك هي بناء MVP (_[منتج أولي قابل للتطبيق بدرجة دنيا][mvp]_) يدير كل أنشطة سلة التسوق الأساسية، بما يسمح للمستخدمين بإضافة طلبات البقالة وحذفها وترتيبها.
لحسن الحظ، يتولى فريق آخر كل وظائف النقود وإتمام الشراء!

## 1. إضافة عنصر (عناصر) إلى سلة تسوق المستخدم

ينبغي أن يسمح MVP للمستخدم بإضافة عناصر إلى سلة تسوقه.
وقد يكون ذلك عنصرًا واحدًا أو عدة عناصر دفعة واحدة.
وبما أن هذا منتج أولي، تُشار إلى كمية العنصر عن طريق _التكرار_.
إذا أراد المستخدم إضافة برتقالتين، فستظهر 'Oranges' مرتين في المُدخلات القابلة للتكرار.
إذا كان العنصر موجودًا بالفعل في سلة المستخدم، فينبغي زيادة كميته في السلة بمقدار 1.
وإذا كان العنصر _جديدًا_ على السلة، فيُضاف بكمية مقدارها 1.

أنشئ الدالة `add_item(<current_cart>, <items_to_add>)` التي تأخذ قاموس سلة تسوق وأي تركيب قابل للتكرار شبيه بالقوائم من العناصر المراد إضافتها كوسائط.
وينبغي أن تُرجع قاموس سلة تسوق جديدًا/محدَّثًا للمستخدم.

```python
>>> add_item({'Banana': 3, 'Apple': 2, 'Orange': 1},
              ('Apple', 'Apple', 'Orange', 'Apple', 'Banana'))
{'Banana': 4, 'Apple': 5, 'Orange': 2}

>>> add_item({'Banana': 3, 'Apple': 2, 'Orange': 1},
              ['Banana', 'Orange', 'Blueberries', 'Banana'])
{'Banana': 5, 'Apple': 2, 'Orange': 2, 'Blueberries': 1}
```

## 2. قراءة العناصر المدرجة في تطبيق الملاحظات لدى المستخدم

أوه.
يبدو أن فريق المنتج يمارس [تضخّم الميزات][feature creep].
فهم يريدون إضافة وظائف إضافية إلى MVP.
وعلى التطبيق الآن أن ينشئ سلة تسوق من خلال قراءة العناصر من تطبيق الملاحظات الخاص بالمستخدم.
أمر مريح للمستخدمين، لكنه عمل إضافي بعض الشيء للفريق.

أنشئ الدالة `read_notes(<notes>)` التي يمكنها أن تأخذ أي تركيب قابل للتكرار شبيه بالقوائم كوسيط.
ينبغي أن تُحلّل الدالة العناصر وتنشئ سلة تسوق/قاموسًا للمستخدم.
ويُضاف كل عنصر بكمية مقدارها 1.
ثم تُرجع سلة المستخدم الجديدة.

```python
>>> read_notes(('Banana','Apple', 'Orange'))
{'Banana': 1, 'Apple': 1, 'Orange': 1}

>>> read_notes(['Blueberries', 'Pear', 'Orange', 'Banana', 'Apple'])
{'Blueberries' : 1, 'Pear' : 1, 'Orange' : 1, 'Banana' : 1, 'Apple' : 1}
```

## 3. تحديث قسم "أفكار" الوصفات

يحتوي التطبيق على قسم "أفكار" مليء بوصفات جاهزة من مطابخ متنوعة.
ويمكن للمستخدم اختيار أي وصفة من هذه الوصفات، فتُضاف كل مكوّناتها تلقائيًا إلى سلة تسوقه.
وقد طلب منك مدير المشروع إنشاء أسلوب لتحرير وصفات "الأفكار" هذه، لأن فريق المحتوى يظل يغيّر المكوّنات والكميات.

أنشئ الدالة `update_recipes(<ideas>, <recipe_updates>)` التي تأخذ قاموس "أفكار" وتركيبًا قابلًا للتكرار من تحديثات الوصفات كوسائط.
وينبغي أن تُرجع الدالة قاموس "الأفكار" الجديد/المحدَّث.

```python
>>>update_recipes(
    {'Banana Bread' : {'Banana': 1, 'Apple': 1, 'Walnuts': 1, 'Flour': 1, 'Eggs': 2, 'Butter': 1},
     'Raspberry Pie' : {'Raspberry': 1, 'Orange': 1, 'Pie Crust': 1, 'Cream Custard': 1}},
    (('Banana Bread', {'Banana': 4,  'Walnuts': 2, 'Flour': 1, 'Butter': 1, 'Milk': 2, 'Eggs': 3}),)
    )
...

{'Banana Bread': {'Banana': 4, 'Walnuts': 2, 'Flour': 1, 'Butter': 1, 'Milk': 2, 'Eggs': 3}, 
 'Raspberry Pie': {'Raspberry': 1, 'Orange': 1, 'Pie Crust': 1, 'Cream Custard': 1}}

>>> update_recipes(

    'Raspberry Pie' : {'Raspberry': 1, 'Orange': 1, 'Pie Crust': 1, 'Cream Custard': 1},
    'Pasta Primavera': {'Eggs': 1, 'Carrots': 1, 'Spinach': 2, 'Tomatoes': 3, 'Parmesan': 2, 'Milk': 1, 'Onion': 1}},
    [('Raspberry Pie', {'Raspberry': 3, 'Orange': 1, 'Pie Crust': 1, 'Cream Custard': 1, 'Whipped Cream': 2}),
```

## 4. ترتيب العناصر في سلة تسوق المستخدم

بعد أن يبدأ المستخدم سلة، يتيح له التطبيق ترتيب عناصره أبجديًا.
فذلك يسهّل العثور على الأشياء، ويساعد عند وجود أخطاء في إدخال البيانات مثل وجود 'potatoes' و'Potato' في قاعدة البيانات.

أنشئ الدالة `sort_entries(<cart>)` التي تأخذ سلة تسوق/قاموسًا كوسيط وتُرجع سلة جديدة مرتّبة أبجديًا.

```python
>>> sort_entries({'Banana': 3, 'Apple': 2, 'Orange': 1})
{'Apple': 2, 'Banana':3, 'Orange': 1}
```

## 5. إرسال سلة تسوق المستخدم إلى المتجر لتجهيز الطلب

يحتاج التطبيق إلى إرسال سلة مستخدم معيّن إلى المتجر لتجهيز الطلب.
غير أن العاملين في المتجر بحاجة إلى معرفة الممر الذي يمكن العثور على العنصر فيه، وما إذا كان يحتاج إلى تبريد.
لذلك (_وبشكل اعتباطي إلى حد ما_) يجب ترتيب "سلة التجهيز" ترتيبًا أبجديًا عكسيًا، مع دمج كميات العناصر مع معلومات الموقع والتبريد.

أنشئ الدالة `send_to_store(<cart>, <aisle_mapping>)` التي تأخذ سلة تسوق المستخدم وقاموسًا يحوي رقم ممر المتجر وقيمة `True`/`False` لما إذا كان كل عنصر يحتاج إلى تبريد.
وينبغي للدالة أن `return` "سلة تجهيز" مجمّعة تحوي (الكمية، والممر، والتبريد) لكل عنصر يطلبه العميل.
وينبغي أن تظهر العناصر بترتيب أبجدي _عكسي_.

```python
>>> send_to_store({'Banana': 3, 'Apple': 2, 'Orange': 1, 'Milk': 2},
                  {'Banana': ['Aisle 5', False], 'Apple': ['Aisle 4', False], 'Orange': ['Aisle 4', False], 'Milk': ['Aisle 2', True]})
{'Orange': [1, 'Aisle 4', False], 'Milk': [2, 'Aisle 2', True], 'Banana': [3, 'Aisle 5', False], 'Apple': [2, 'Aisle 4', False]}
```

## 6. تحديث مخزون المتجر ليعكس ما طلبه المستخدم.

لا يستطيع التطبيق أن يرسل طلبات العملاء إلى ما لا نهاية.
ففي نهاية المطاف، ستنفد من المتجر منتجات متنوعة.
لذلك يحتاج MVP لتطبيقك إلى تحديث مخزون المتجر في كل مرة يرسل فيها المستخدم طلبه إلى المتجر.
وإلا فسيطلب العملاء منتجات غير متوفرة فعليًا.

أنشئ الدالة `update_store_inventory(<fulfillment_cart>, <store_inventory>)` التي تأخذ "سلة تجهيز" ومخزون متجر.
وينبغي أن تخصم الدالة من كميات مخزون المتجر العدد "المطلوب" في "سلة التجهيز"، ثم تُرجع مخزون المتجر المحدَّث.
وحيثما ينخفض عدد أحد عناصر المتجر إلى 0، يُستبدل العدد بالرسالة 'Out of Stock'.

```python
>>> update_store_inventory({'Orange': [1, 'Aisle 4', False], 'Milk': [2, 'Aisle 2', True], 'Banana': [3, 'Aisle 5', False], 'Apple': [2, 'Aisle 4', False]},
{'Banana': [15, 'Aisle 5', False], 'Apple': [12, 'Aisle 4', False], 'Orange': [1, 'Aisle 4', False], 'Milk': [4, 'Aisle 2', True]})

{'Banana': [12, 'Aisle 5', False], 'Apple': [10, 'Aisle 4', False], 'Orange': ['Out of Stock', 'Aisle 4', False], 'Milk': [2, 'Aisle 2', True]}
```
