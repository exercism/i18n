# مقدمة

## مراجع `null`

إذا كنت قد استخدمت من قبل لغة برمجة أخرى (C/C++، Python، Java، Ruby، Lisp، وما إلى ذلك)، فمن المحتمل أنك صادفت `null` أو `nil` سابقًا.
استخدام `null` أو `nil` هو الطريقة التي تشير بها هذه اللغات إلى أن متغيرًا معيّنًا لا قيمة له.
لكن هذا يجعل استخدام متغير `null` عن غير قصد خطأً سهل الوقوع (وشائعًا).
وكما قد تتخيل، فإن محاولة استدعاء دالة غير موجودة، أو الوصول إلى قيمة غير موجودة، قد تؤدي إلى شتى أنواع الـbugs والانهيارات.
وقد ذهب مبتكر `null` إلى حد وصفه بأنه ['خطأ المليار دولار'][billion-dollar-mistake].

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## النوع `Option`

لتجنّب هذه المشكلات، يمكن لمتغيرات Cairo استخدام التعداد `Option` لتمثيل غياب القيمة بأمان.
يتكوّن هذا التعداد من صيغتين: `None`، وهي مكافئ `null` في Cairo؛ و`Some(T)`، حيث `T` قيمة من أي نوع.

وهو يبدو هكذا:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

يمكنك أن تنظر إلى `Option` كطبقة أمان بينك وبين المشكلات التي قد تسبّبها مراجع `null`، مع الاحتفاظ بفائدتها المفاهيمية في الوقت نفسه.

## استخدام `Option`

ضبط متغير على `None` أمر بسيط إلى حد كبير:

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

لكن إذا أردت أن يحمل النوع `Option` قيمة، فلا يمكنك إسناد هذه القيمة مباشرة.
فمتغير من النوع `Option` ومتغير من النوع `i32` مثلًا ليسا متكافئين.
عليك استخدام `Some`:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

وللسبب نفسه لن ينجح ما يلي:

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

للحصول على القيمة التي يحتويها `Some`، عليك أولًا التحقق من وجودها:

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

لدى Cairo أدوات أخرى غير `match` متاحة للتحقق من القيم الموجودة داخل `Option` والوصول إليها، لكن `match` ينبغي أن يكون مألوفًا لك الآن.

اعتبر هذا توضيحًا لسبب استخدام Cairo لـ `Option` بدلًا من مرجع `null`.
والنقطة الجوهرية هي أن **عليك _أن تتحقق_ بالضرورة** مما إذا كان متغير `Option` يحمل `Some` (وفي هذه الحالة يمكنك المضي قدمًا واستخراج القيمة الموجودة داخله واستخدامها)، أو `None`.
وإلا فلن يُترجم برنامجك؛ فالمترجم يحميك من `null`.
