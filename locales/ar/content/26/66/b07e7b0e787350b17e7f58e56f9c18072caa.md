# نبذة

## المحارف

ترميز المحارف هو اصطلاح محدد يُستخدم لتمثيل عناصر النص في لغة طبيعية على هيئة تسلسل من البايتات.
وقد يكون «عنصر النص» هنا أي وحدة ذات دلالة في لغة طبيعية، مثل الحروف والمسافات وعلامات الترقيم والرموز التعبيرية والكتابات التصويرية وغيرها.

يدعم NASM (The Netwide Assembler، المُجمّع المستخدم في هذا المسار) تعريف البيانات باستخدام [ASCII][ascii].

قد يصل طول ثوابت المحارف في NASM إلى 8 بايتات، ويمكن تعريفها بعلامات الاقتباس المفردة (`'`) أو المزدوجة (`"`) أو الخلفية (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

يجب تعريف المحارف الخاصة بين علامتي الاقتباس الخلفيتين وتهريبها بـ `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

كما يدعم NASM [محارف يونيكود][unicode] بترميز [UTF-8][utf8]، تُحدَّد بـ `\u` أو `\U` وبين علامتي الاقتباس الخلفيتين:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

لاحظ أنه لا يوجد دعم مدمج لأي ترميز محارف في x86-64 كنوع مستقل.
البيانات في لغة التجميع هي تسلسل من البايتات، وترك تفسير تلك البايتات كمحرف أو عدد أو أي شيء آخر للمبرمج.

على سبيل المثال، المحرف '0' في ASCII هو بايت واحد قيمته 48.
لذا، فإن تخزين 48 في بايت واحد يكافئ تمامًا تخزين المحرف '0' في ASCII:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

وللسبب نفسه، تتم معالجة المحارف بتحويل القيم في تلك البايتات مباشرةً:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## السلاسل النصية

السلسلة النصية هي تسلسل من المحارف.
وفي لغة التجميع، تُنفَّذ عادةً على هيئة مصفوفة.

يمكن تعريف سلسلة نصية في NASM بالطريقة نفسها التي يمكن بها تعريف أي مصفوفة:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

من الفروق بين السلاسل النصية والمصفوفات الأخرى أن NASM يدعم أيضًا تعريف السلاسل النصية دون فاصلة (`,`) تفصل بين القيم.
ويمكن كذلك مزج القيم مع الفواصل:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

لاحظ أنه، كما ذُكر سابقًا، المحارف مجرد بايتات (أو تسلسل من البايتات في ترميز يونيكود):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

بما أن كل محرف ASCII يشغل بايتًا واحدًا، فإن أي بايت لاحق في حجم أوسع يكون `0`.
على سبيل المثال، تعريف `'a'` ككلمة رباعية (8 بايتات) يعني أن البايت الأول هو `'a'` (`97`) والبايتات السبعة الأخرى كلها `0`.

ولهذا السبب، فإن كل ما يلي متكافئ:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
في لغة التجميع، لا تنتهي السلاسل النصية تلقائيًا بمحرف NUL في ASCII (القيمة `0`).

وعند التعامل مع لغات عالية المستوى، مثل C، تقع على عاتق المبرمج مسؤولية التأكد من إلحاق المُنهي الصحيح، إن وُجد، بنهاية السلسلة النصية.
~~~~

## تعليمات السلاسل النصية

بما أن السلاسل النصية مصفوفات، يمكنك التعامل معها بالطريقة نفسها التي تتعامل بها مع أي مصفوفة، عبر إلغاء الإشارة إلى الذاكرة صراحةً:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

إضافةً إلى ذلك، هناك بعض التعليمات لتحميل القيم ونقلها وتخزينها في تسلسلات من البايتات في الذاكرة.
وعلى الرغم من تسميتها _تعليمات السلاسل النصية_، يمكن استخدامها مع أي تسلسل من البايتات في الذاكرة، أي مع أي مصفوفة:

| التعليمة  | ما تفعله                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | تحمّل قيمة من موقع في الذاكرة يحدده `rsi` إلى `rax`                                                |
| [stos][stos] | تخزّن قيمة من `rax` في موقع في الذاكرة يحدده `rdi`                                               |
| [movs][movs] | تنسخ قيمة من موقع في الذاكرة يحدده `rsi` وتخزّنها في موقع في الذاكرة يحدده `rdi`    |
| [cmps][cmps] | تقارن القيمة في موقع في الذاكرة يحدده `rsi` بالقيمة في موقع في الذاكرة يحدده `rdi` |
| [scas][scas] | تقارن القيمة في `rax` بالقيمة في موقع في الذاكرة يحدده `rdi`                                |

لاحظ أن تلك التعليمات _لا_ تأخذ أي معامل صريح.
فمعاملاتها ضمنية.

وكقاعدة عامة:

1. عندما يكون معامل المصدر الخاص بها موقعًا في الذاكرة، يجب تخزين عنوانه في `rsi` (`s` اختصارًا لكلمة source، أي المصدر).
2. عندما يكون معامل الوجهة الخاص بها موقعًا في الذاكرة، يجب تخزين عنوانه بدلًا من ذلك في `rdi` (`d` اختصارًا لكلمة destination، أي الوجهة).
3. إذا لم يكن أحد المعاملين موقعًا في الذاكرة، فهو السجل `rax`.

لاحظ أن تلك التعليمات تلغي الإشارة إلى عناوين الذاكرة تلقائيًا وفقًا للعملية المحددة التي تنفذها.

ويمكن أن تعمل جميعها بأحجام مختلفة.
وتُلحَق بها لاحقة للدلالة على هذا الحجم:

| اللاحقة | المعنى | الحجم    |
| :----: | ------- | :------ |
|  `b`   | بايت    | 1 بايت  |
|  `w`   | كلمة    | 2 بايت |
|  `d`   | كلمة مزدوجة   | 4 بايت |
|  `q`   | كلمة رباعية   | 8 بايت |

على سبيل المثال:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

كما تُحدّث أي عنوان مستخدم بمقدار حجم العملية.
ويتم هذا التحديث وفقًا لقيمة **علم الاتجاه (DF)**:

- إذا كان `DF` مصفّرًا، فإن العناوين _تزداد_ بمقدار حجم العملية.
- وإذا كان `DF` مضبوطًا، فإن العناوين _تنقص_ بالمقدار نفسه بدلًا من ذلك.

ينص ABI الخاص بـ System V على أنه يجب تصفير علم الاتجاه عند دخول الدالة.
لذا، فإن _السلوك الافتراضي هو قراءة الذاكرة أو الكتابة فيها بترتيب تصاعدي للعناوين_.

يمكن استخدام التعليمة [cld][cld] لتصفير علم الاتجاه، بينما تُستخدم التعليمة [std][std] لضبطه:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
يتوقع المُستدعي أن يكون `DF` مصفّرًا بعد أن تُرجع أي دالة يُستدعى إليها، وفقًا لـ ABI الخاص بـ System V.
وإذا ضبطت `DF` في أي وقت، فتأكد من تصفيره قبل `ret`.
~~~~

### Lods

_تقرأ_ هذه التعليمة من موقع في الذاكرة عنوانه في `rsi` وتنسخ القيمة إلى `rax`.

ويُحدَّث العنوان في `rsi` بمقدار عدد البايتات المقروءة:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

تنسخ هذه التعليمة القيمة في `rax` و_تكتبها_ في موقع في الذاكرة عنوانه في `rdi`.

ويُحدَّث العنوان في `rdi` بمقدار عدد البايتات المكتوبة:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

_تقرأ_ هذه التعليمة من موقع في الذاكرة عنوانه في `rsi` و_تكتب_ القيمة في موقع في الذاكرة عنوانه في `rdi`.
ولا تتأثر القيمة في `rax` بهذه التعليمة.

ويُحدَّث كل من `rsi` و`rdi` بمقدار عدد البايتات المنسوخة من موقع في الذاكرة إلى الآخر:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

_تقرأ_ هذه التعليمة من موقع في الذاكرة عنوانه في `rsi` و_تقرأ_ أيضًا من موقع في الذاكرة عنوانه في `rdi`.
ثم تقارن القيمتين وتُحدّث الأعلام، وفقًا لـ `cmp`.

ويُحدَّث كل من `rsi` و`rdi` بمقدار عدد البايتات المقروءة من كلا الموقعين:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

تقارن هذه التعليمة القيمة في `rax` بالقيمة التي _تقرأها_ من موقع في الذاكرة عنوانه في `rdi`.
ثم تُحدّث الأعلام، وفقًا لـ `cmp`.

ويُحدَّث العنوان في `rdi` بمقدار عدد البايتات المقروءة:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

بخلاف ما سبق، لا تتفاعل التعليمة [rep][rep] مع الذاكرة مباشرة.
بدلًا من ذلك، يمكن إضافتها كبادئة إلى التعليمات الأخرى المذكورة، ف_تكرّر_ تلك التعليمات.

عند إضافة البادئة `rep`، تتكرر تعليمات السلاسل النصية عددًا من المرات يساوي القيمة في `rcx`.
وفي كل مرة، تُنقص القيمة في `rcx` بمقدار `1`.
لاحظ أنه يجب ضبط القيمة في `rcx` قبل استخدام التعليمة:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

بالإضافة إلى استخدام `rcx` كعداد، فإن `repe` (أو `repz`) و`repne` (أو `repnz`) توقفان التنفيذ إذا كان `zero flag (ZF)` مصفّرًا أو مضبوطًا على الترتيب:

| التعليمة      | أين يمكن إضافتها     | قد تتوقف مبكرًا        |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`، `lods`، `stos` | لا                      |
| `repe`,`repz`    | `cmps`، `scas`         | نعم، تتوقف عندما يساوي ZF القيمة 0 |
| `repne`, `repnz` | `cmps`، `scas`         | نعم، تتوقف عندما يساوي ZF القيمة 1 |

~~~~exercism/advanced
على وحدات المعالجة المركزية الحديثة، غالبًا ما يكون `rep movs` و`rep stos` خيارين سريعين عند نقل البيانات في كتل كبيرة.
أما تعليمات السلاسل النصية الأخرى، بل وحتى `movs` و`stos` عند العمل دون `rep`، فهي عادةً أبطأ من حلقة عادية.
