# Docker

تُنشَر أدوات Representer لدينا كصور Docker.

يرجى قراءة [معلومات Docker العامة الخاصة بـ Tooling](/docs/building/tooling/docker) لتتعرف على كيفية عمل هذه الصور.

## التكامل

عندما نُشغّل Representer لإنشاء تمثيل للحل، ننفّذ أمر Docker يبدو هكذا:

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-representer" \
        "${exercise_slug}" "/solution" "/output"
```

كما ترى، نمرّر ثلاث وسائط إلى صورة Docker:

1. مُعرّف التمرين
2. مسار مجلد الحل
3. مسار مجلد الإخراج

## الاصطلاحات

تستخدم جميع أدوات Representer لدينا الاصطلاحات التالية في تنفيذها:

- يقع ملف `Dockerfile` في الدليل الجذر للمستودع.
- ينبغي أن يكون مجلد العمل هو `/opt/representer`.
- نقطة الدخول هي `/opt/representer/bin/run.sh`
- يأخذ السكربت `/opt/representer/bin/run.sh` ثلاث وسائط:
  1. مُعرّف التمرين
  2. مسار مجلد الحل
  3. مسار مجلد الإخراج

لمزيد من المعلومات، انظر [الواجهة](/docs/building/tooling/test-runners/interface).

```exercism/note
ستستخدم مستودعات representer الجديدة هذه الاصطلاحات افتراضيًا.
```
