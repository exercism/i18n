# مقدمة

توفّر JavaScript كائنًا مدمجًا هو `Date` يخزّن التاريخ والوقت، ويوفّر طرقًا للتعامل معهما.

<!-- prettier-ignore -->
~~~exercism/caution
كان مبنيًّا على صنف `java.util.Date` في Java، الذي استُبدل في أوائل العقد الثاني من القرن الحادي والعشرين، لكن `Date` في JavaScript ما زال موجودًا من أجل التوافق مع الكود القديم.

ولأن التعامل مع التواريخ صعب عمومًا، ولأن معالجة المناطق الزمنية رديئة أو شبه معدومة، وُجدت مكتبات كثيرة مثل `moment.js` و`day.js` و`date-fns` و`luxon`.
لا تتوفّر أيٌّ من هذه المكتبات على Exercism.

في مشاريعك الخاصة، لا تستخدم حزمة مهجورة أو غير مُصانة مثل `moment.js`، بل اعتمد على بدائل أحدث مثل `luxon`، أو على [Temporal][mdn-temporal] الذي لم ينتشر بعد على نطاق واسع.
يركّز هذا التمرين على `Date`، الذي سيظل مهمًّا حتى نهاية عمر JavaScript.

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal
~~~

## الإنشاء

كائن `Date` هو أحد كائنات الصنف `Date`.
ويمكن إنشاؤه دون تمرير أي وسائط إلى دالة الإنشاء.
وينتج عن ذلك كائن `Date` يمثّل التاريخ والوقت الحاليين:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### الطابع الزمني Unix (عدد)

إذا مُرِّر عدد، فسيُفسَّر على أنه `timestamp`.
الطابع الزمني عدد صحيح يمثّل عدد **الميلي ثانية** التي مضت منذ **1 يناير 1970 [UTC][defn-utc]+0**.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

قد يتوقّع المرء أن يُنشئ `new Date(0)` كائن التاريخ "الأبكر"، لكن JavaScript ستحوّل التاريخ إلى منطقتك الزمنية المحلية، ما يعني أن من هم في نطاق [GMT / بتوقيت UTC+0][defn-gmt] فقط هم من سيحصلون فعليًا على قيمة [حقبة Unix][defn-unix-epoch].

### الطابع الزمني ISO 8601 (سلسلة نصية)

يمكنك تمرير قيمة سلسلة نصية تمثّل تاريخًا إلى دالة إنشاء `Date`.
الصيغة **الوحيدة** المتناسقة بين كل التطبيقات هي [النسخة المبسّطة][mdn-date-string-format] من ما يُعرف بـ[سلاسل الطوابع الزمنية ISO 8601][defn-iso8601] المعترف بها دوليًا والموحّدة.

تبدو لحظة زمنية بتوقيت [UTC][defn-gmt] هكذا:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

حيث تُجرى الاستبدالات التالية:

| Key  | Description                                 | Default |
| ---- | ------------------------------------------- | ------- |
| YYYY | The calendar year, represented in 4 digits  |         |
| MM   | The calendar month, represented in 2 digits | 01      |
| DD   | The calendar day, represented in 2 digits   | 01      |
| T    | A literal letter T, separating date & time  | T       |
| HH   | The hours in a 24-hour clock, 2 digits      | 00      |
| mm   | The minutes, 2 digits                       | 00      |
| ss   | The seconds, 2 digits                       | 00      |
| mss  | The milliseconds, 3 digits                  | 000     |
| Z    | A literal letter Z, or an offset `+/-HH:mm` |         |

الحرف `Z` حرفيًا يدلّ على UTC (بلا منطقة زمنية، وبلا توقيت صيفي).

ولأن هناك قيمًا افتراضية لمعظم المكوّنات، فحذف الأجزاء من النهاية صحيح:

```text
YYYY-MM-DD
```

وتكون القيمة الافتراضية للوقت 00:00:00.000

إذا لم ينتهِ الطابع الزمني بـ `Z`، ولم ينتهِ بـ `+HH:mm` أو `-HH:mm` (وهي إشارة إلى إزاحة المنطقة الزمنية)، فبسبب أسباب تاريخية ينطبق ما يلي:

> عند غياب إزاحة المنطقة الزمنية، تُفسَّر الصيغ التي تحوي تاريخًا فقط على أنها بتوقيت UTC، وتُفسَّر الصيغ التي تحوي تاريخًا ووقتًا على أنها بالتوقيت المحلي.
> ويعود تفسيرها على أنها بتوقيت UTC إلى خطأ تاريخي في المواصفة، لم يكن متناسقًا مع ISO 8601، لكن لم يكن ممكنًا تغييره حفاظًا على توافق الويب.
> انظر [Broken Parser – A Web Reality Issue][ref-broken-parser].

### كائن التاريخ

يمكن أيضًا استخدام كائن تاريخ موجود كوسيط لدالة الإنشاء.
فينتج عن ذلك نسخة من كائن `Date` الموجود بالتاريخ والوقت نفسيهما.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### تمرير قيم مكوّنات التاريخ والوقت كلٌّ على حدة

يمكن إنشاء كائن تاريخ يمثّل تاريخًا بتمرير ثلاثة أعداد.
ويمكن إنشاء كائن تاريخ يمثّل تاريخًا ووقتًا بتمرير 6 أعداد.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

القيمة الثانية هي `month`، وتبدأ من `0` لشهر يناير وحتى `11` لشهر ديسمبر.

## `Date.parse()`

قد تصادف إشارات إلى دالة تحليل التواريخ `Date.parse` أو مراجع لها.
ولأن لهذه الدالة ثوابت (حقائق) قليلة فقط، ولأن بقية التنفيذ غير محدّد (وبالتالي غير قياسي)، فلا ينبغي استخدامها.

## الوصول إلى مكوّنات `Date`

توجد طرق متعددة على كائنات التاريخ تُرجع مكوّنات التاريخ:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

لكل طريقة من هذه نظير `set` مقابل (مثل `setFullYear`) لتحديث القيمة.
وأي قيمة تتجاوز الحد تنتقل إلى المكوّن التالي:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

توجد نسخ بتوقيت UTC لكل الطرق التي تتجاهل المنطقة الزمنية المحلية.

## التحويل من التاريخ

تحتوي كائنات التاريخ على طريقة `getTime()` تُرجع طابع UNIX الزمني بالميلي ثانية، أي عدد الميلي ثانية منذ منتصف ليل 1 يناير 1970 بتوقيت UTC.
بالإضافة إلى ذلك، تتوفّر طريقة `toISOString()` للتحويل من كائن تاريخ إلى سلسلة نصية للطابع الزمني ISO 8601.

## مقارنة التواريخ

يمكن استخدام أكبر من (`>`) وأكبر من أو يساوي (`>=`) وكذلك أصغر من (`<`) وأصغر من أو يساوي (`<=`) مباشرة بين تاريخين أو بين تاريخ وعدد.
وهذا يعمل لأن JavaScript ستحاول تحويل التاريخ إلى قيمة أولية.
