# مقدمة

## قيم المعاملات الافتراضية

يمكن تزويد أي معامل من معاملات الدالة بقيم افتراضية من خلال إسناد قيمة إلى المعامل في قائمة المعاملات بعد تحديد النوع الخاص به. وعند تحديد قيمة افتراضية لمعامل، يمكن لمنادي الدالة أن يحذف ذلك المعامل عند استدعاء الدالة، فتُستخدم القيمة الافتراضية بدلًا منه.

```swift
func greeting(name: String = "guest", duration: Int = 2) -> String {
  "Welcome, \(name). Enjoy your \(duration) night stay."
}

greeting(name: "Bobo", duration: 7)
// Returns "Welcome, Bobo. Enjoy your 7 night stay."
greeting(duration: 3)
// Returns "Welcome, guest. Enjoy your 3 night stay."
greeting(name: "Wynona")
// Returns "Welcome, Wynona. Enjoy your 2 night stay."
greeting()
// Returns "Welcome, guest. Enjoy your 2 night stay."
```

## المعاملات المتغيّرة العدد

تتيح _المعاملات المتغيّرة العدد_ في Swift تمرير صفر أو أكثر من القيم من النوع نفسه إلى معامل واحد في الدالة. ويُشار إلى ذلك بإضافة `...` إلى تحديد النوع الخاص بالمعامل.

وستُجمَع هذه القيم تلقائيًا في مصفوفة عناصرها من النوع نفسه الذي ينتمي إليه المعامل المتغيّر العدد.

```swift
func geometricMean(_ numbers: Double...) -> Double {
  var total = 1.0
  for number in numbers {
      total *= number
  }
  return pow(total, 1.0 / Double(numbers.count))
}

geometricMean(1, 2, 3, 4, 5)
// => 2.605171084697352
```

لاحظ أن Swift تفرض قيدًا عند استخدام المعاملات المتغيّرة العدد. فإذا كانت للدالة معاملات تأتي بعد المعامل المتغيّر العدد في التعريف، فيجب أن يكون للمعامل الأول الذي يلي المعامل المتغيّر العدد _وسم وسيط_.

## معاملات الدخول والخروج

داخل جسم الدالة تُعامَل المعاملات كثوابت لا كمتغيرات؛ ومحاولة تعديل قيمة معامل تؤدي إلى خطأ في وقت التصريف. وإذا أرادت الدالة تعديل قيمة أحد معاملاتها، فيجب أن تستخدم [_معامل الدخول والخروج_][in-out-parameters] لتوضيح قابلية التعديل هذه.

لاستخدام معاملات الدخول والخروج، يجب أن يتأكد المبرمج من ثلاثة أمور:

1. يجب أن يحدد تعريف الدالة معاملات الدخول والخروج صراحةً بكتابة الكلمة المفتاحية `inout` بين `:` واسم النوع في تحديد النوع الخاص بالمعامل.
2. يجب أن تكون القيمة الممرَّرة إلى معامل الدخول والخروج معرَّفة كمتغير لا كثابت. وبالمثل، لا يمكن أن تكون قيمة حرفية.
3. يجب أن يسبق اسم المتغير علامة `&` في استدعاء الدالة، لتوضيح أنه قابل للتعديل.

وعند فعل ذلك، تُنشئ الدالة نسخة داخلية من معامل الدخول والخروج، وتعدّلها وفق ما يوجِّهه جسم الدالة، ثم تنسخ القيمة المعدَّلة مرة أخرى إلى المتغير الذي مُرِّر عند عودة الدالة.

```swift
func updateVersion(_ record: inout (version: Int, title: String)) {
  record.version += 1
}

var dbRecord = (version: 2, title: "Exercism")
updateVersion(&dbRecord)

// dbRecord is now (3, "Exercism")
```

~~~~exercism/warning
هناك قاعدتان إضافيتان يجدر الانتباه إليهما بخصوص معاملات الدخول والخروج.

1. داخل دالة لها معاملات دخول وخروج، لا يُسمح لك بالإشارة إلى المتغير الذي مُرِّر كمعامل دخول وخروج.
2. لا يمكن تمرير المتغير نفسه كعدة معاملات دخول وخروج في الدالة نفسها.
   فمثلًا، `inoutFunc(&mutVar, &mutVar)` يؤدي إلى خطأ في التصريف.
~~~~

## الدوال المتداخلة

في Swift، يمكنك تعريف [دوال داخل دوال أخرى][nested-functions]. وتُعرف هذه بـ **الدوال المتداخلة**.

وكثيرًا ما تُستخدم الدوال المتداخلة كدوال مساعدة خاصة تؤدي مهام محددة لصالح الدالة الحاوية دون إرباك النطاق الخارجي:

```swift
func makeNumber(_ number: Int) -> Int {
    func double(_ x: Int) -> Int {
        x * 2
    }

    func increment(_ x: Int) -> Int {
        x + 1
    }

    return number.isMultiple(of: 2) ? increment(double(number)) : double(number)
}

print(makeNumber(3)) // Prints 6
print(makeNumber(4)) // Prints 9
```

تتصرف الدوال المتداخلة كالدوال العادية، لكن رؤيتها مقصورة على جسم الدالة الحاوية.
