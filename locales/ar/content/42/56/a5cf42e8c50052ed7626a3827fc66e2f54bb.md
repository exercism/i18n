# مقدمة

## القيم الافتراضية للمعاملات

يمكن تزويد أيٍّ من معاملات الدالة بـ[قيم افتراضية للمعاملات][default-parameter-values] عبر إسناد قيمة إلى المعامل في قائمة المعاملات بعد تعليق النوع الخاص بالمعامل. وعند تحديد قيمة افتراضية لمعامل ما، يستطيع من يستدعي الدالة أن يحذف ذلك المعامل عند استدعاء الدالة، وستُستخدم القيمة الافتراضية بدلًا منه.

```swift
func greeting(name: String = "guest", duration: Int = 2) -> String {
  "Welcome, \(name). Enjoy your \(duration) night stay."
}

greeting(name: "Bobo", duration: 7)
// Returns "Welcome, Bobo. Enjoy your 7 night stay."
greeting(duration: 3)
// Returns "Welcome, guest. Enjoy your 3 night stay."
greeting(name: "Wynona")
// Returns "Welcome, Wynona. Enjoy your 2 night stay."
greeting()
// Returns "Welcome, guest. Enjoy your 2 night stay."
```

## المعاملات المتغيرة العدد

تسمح [المعاملات المتغيرة العدد][variadic-parameters] للدالة بقبول صفر أو أكثر من القيم من نوع محدد في معامل واحد.
وتُعرّف المعامل المتغير العدد بإضافة ثلاث نقاط (`...`) إلى تعليق النوع الخاص بالمعامل.

وداخل جسم الدالة، يجعل Swift هذه القيم متاحة على هيئة مصفوفة من النوع المحدد:

```swift
import Foundation

func geometricMean(_ numbers: Double...) -> Double {
    var total = 1.0
    for number in numbers {
        total *= number
    }
    return pow(total, 1.0 / Double(numbers.count))
}

let result = geometricMean(1, 2, 3, 4, 5)
// result is 2.605171084697352
```

~~~~exercism/note
إذا تضمنت الدالة معاملات إضافية بعد معامل متغير العدد، فالمعامل الأول بعد المعامل المتغير العدد **يجب** أن يحمل وسم وسيط صريح، حتى يعرف Swift أين تنتهي قائمة الوسائط المتغيرة العدد.
~~~~


## معاملات الدخل والخرج

داخل جسم الدالة، تُعامَل المعاملات على أنها ثوابت لا متغيرات؛ ومحاولة تعديل قيمة معامل ما ستُثير خطأً في وقت الترجمة.
وإذا أرادت الدالة تعديل قيمة معامل، فعليها استخدام [_معامل دخل وخرج_][in-out-parameters] لجعل قابلية التغيير هذه صريحة.

لاستخدام معاملات الدخل والخرج، على المبرمج أن يتأكد من ثلاثة أمور:

1. يجب أن يحدد تعريف الدالة معاملات الدخل والخرج صراحةً بكتابة الكلمة المفتاحية `inout` بين `:` واسم النوع في تعليق النوع الخاص بالمعامل.
2. يجب تعريف القيمة المُمرَّرة إلى معامل الدخل والخرج على أنها متغير لا ثابت. وبالمثل، لا يمكن أن تكون قيمة حرفية.
3. يجب أن يسبق اسم المتغير علامة `&` في استدعاء الدالة، لتحديد أنه قابل للتعديل صراحةً.

وعند القيام بذلك، ستُنشئ الدالة نسخة داخلية من معامل الدخل والخرج، وتعدّلها كما هو مطلوب في جسم الدالة، ثم تنسخ القيمة المعدّلة مرة أخرى إلى المتغير الذي مُرِّر عند رجوع الدالة.

```swift
func updateVersion(_ record: inout (version: Int, title: String)) {
  record.version += 1
}

var dbRecord = (version: 2, title: "Exercism")
updateVersion(&dbRecord)

// dbRecord is now (3, "Exercism")
```

~~~~exercism/warning
هناك قاعدتان إضافيتان ينبغي الانتباه إليهما فيما يخص معاملات الدخل والخرج.

1  داخل دالة لها معاملات دخل وخرج، لا يُسمح لك بالإشارة إلى المتغير الذي مُرِّر كمعامل دخل وخرج.
2. لا يمكن تمرير المتغير نفسه كعدة معاملات دخل وخرج في الدالة نفسها.
   فعلى سبيل المثال، يؤدي `inoutFunc(&mutVar, &mutVar)` إلى خطأ في المترجم.
~~~~

## الدوال المتداخلة

في Swift، يمكنك تعريف [دوال داخل دوال أخرى][nested-functions].
وتُعرف هذه بـ**الدوال المتداخلة**.

ويُستخدم هذا النوع من الدوال عادةً كدوال مساعدة خاصة تؤدي مهام محددة للدالة الحاوية دون إثقال النطاق الخارجي:

```swift
func makeNumber(_ number: Int) -> Int {
    func double(_ x: Int) -> Int {
        x * 2
    }

    func increment(_ x: Int) -> Int {
        x + 1
    }

    return number.isMultiple(of: 2) ? increment(double(number)) : double(number)
}

print(makeNumber(3)) // Prints 6
print(makeNumber(4)) // Prints 9
```

تتصرف الدوال المتداخلة كالدوال العادية، لكن رؤيتها مقصورة على جسم الدالة الحاوية.
