# حول

يعتمد الكود العددي على أعلام تضبطها تعليمات متنوعة ليتفرع بها استجابةً لشرط معين.
لكن القيم المحزومة تمثل لا قيمة واحدة بل قيمًا كثيرة بالتوازي.
وقد يفشل شرط واحد في أحد المسارات وينجح في مسار آخر.

ولهذا يكون كود SIMD [بلا تفرعات][branchless-code] بشكل افتراضي.

بدلًا من الاعتماد على الأعلام، تُنتج المقارنات المحزومة عادةً **قناعًا** في معامل الوجهة.
في كل مسار، تملأ المقارنة المسار كاملًا بواحدات عندما يكون صحيحًا وبأصفار عندما يكون خاطئًا.
وعند قراءته كعدد صحيح بإشارة، يكون المسار الصحيح `-1` والمسار الخاطئ `0`.

ويمكن بعد ذلك تركيب هذا القناع مع [العمليات على مستوى البتات][simd-bitwise] لتصفية مسارات محددة.

## المقارنات المحزومة

تعليمة `cmp` العددية عامة بمعنى أنها تُستخدم لضبط أعلام متنوعة في الوقت نفسه.
ويمكن بعدها لتعليمة أخرى أن تستهلك تلك الأعلام إما لتتفرع وإما لإجراء حسابات.

لكن، بما أن المقارنة المحزومة تفحص شرطًا وتحسب قناعًا في الوقت نفسه، فإنها ليست عامة.
يجب إعطاء المقارنة الشرط الدقيق الذي يجري فحصه.

وهناك طريقتان لفعل ذلك:

- تُعطى المقارنات الصحيحة الشرط كلاحقة: `eq` للمساواة، و`gt` للأكبر من.
  وتُبنى الصيغ الأخرى بتركيب نتيجة إحدى هاتين.
- تُعطى مقارنات الفاصلة العائمة الشرط مُرمَّزًا في قيمة فورية.
  وتقابل القيم المختلفة لهذه القيمة الفورية شروطًا مختلفة يجري فحصها.

وخلافًا لاستخدام لاحقة شرطية محددة في المقارنات الصحيحة، تتبع الصياغة البنية ذاتها التي رأيناها سابقًا:

- للأعداد الصحيحة، `p` + `cmp` + الشرط + الحجم (`b` أو `w` أو `d` أو `q`).
- للعوائم، `cmp` + `p` + الحجم (`s` أو `d`).
  ويُمرَّر الشرط في قيمة فورية كمعامل إضافي.

### المقارنات الصحيحة

كما ذكرنا، لا توجد مقارنات صحيحة إلا للمساواة والأكبر من:

| التعليمة                                   | الوصف                       |
|--------------------------------------------|-----------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | مساواة لكل مسار             |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | أكبر من **بإشارة** لكل مسار |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

لإنشاء مقارنة أصغر من، استخدم `gt` مع تبديل المعاملين: `a < b` == `b > a`.

لاحظ أن المقارنة **بإشارة**.
ولإجراء مقارنة بدون إشارة، اقلب البت الأعلى في كلا المعاملين.
ويمكن فعل ذلك بعملية XOR مع قناع لا يكون مضبوطًا فيه إلا البت الأعلى.

~~~~exercism/note
من الأساليب المفيدة:

1. تطبيق XOR على سجل مع نفسه لإنتاج أصفار كلها.
2. مقارنة سجل مع نفسه لإنتاج واحدات كلها.

على سبيل المثال:

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

الأصفار الكاملة والواحدات الكاملة قناعان شائعان لترميز «خطأ في كل مكان» و«صحيح في كل مكان» على التوالي.
ويمكن أيضًا استخدامهما لتمثيل القيمة المحزومة `0` أو القيمة المحزومة `-1`، وهما قيمتان حارستان شائعتان.
على سبيل المثال، قيمة NUL التي تعلّم نهاية سلسلة نصية هي `0`.
~~~~

### مقارنات الفاصلة العائمة

تستخدم المسارات ذات الفاصلة العائمة شكلًا مختلفًا: تعليمة واحدة، `cmpps` (و`cmppd` للمسارات ذات 64 بت)، مع الشرط في صورة قيمة فورية:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

يمتلك NASM أيضًا شبه عمليات تقابل القيمة الفورية الصحيحة وتسهل تذكّرها.
في كل ما يلي، يمكن أن يكون `x` في `px` هو `s` (عوائم 32 بت) أو `d` (عوائم 64 بت):

| شبه العملية | القيمة الفورية | المقارنة               |
|-------------|----------------|------------------------|
| `cmpeqpx`   | 0              | a == b                 |
| `cmpltpx`   | 1              | a <  b                 |
| `cmplepx`   | 2              | a <= b                 |
| `cmpunordpx`| 3              | a قيمة NaN أو b قيمة NaN |
| `cmpneqpx`  | 4              | a != b                 |
| `cmpnltpx`  | 5              | a >= b                 |
| `cmpnlepx`  | 6              | a >  b                 |
| `cmpordpx`  | 7              | لا a ولا b قيمة NaN    |

~~~~exercism/caution
تُقارَن قيمة NaN كغير مرتبة: فهي ليست أصغر من أي شيء ولا مساوية له ولا أكبر منه، بما في ذلك نفسها.
تُعطي المحمولات المرتبة، مثل `cmpltps`، قيمة خطأ عندما يكون أحد المعاملين قيمة NaN، بينما تُعطي المحمولات غير المرتبة قيمة صحيح.
ولهذا السبب توجد `cmpordps` و`cmpunordps`، لاختبار قيمة NaN صراحةً.
~~~~

## الاختيار بقناع

يُرمّز القناع نتيجة شرط.
ويمكن بعدها استخدامه للاختيار، مسارًا بمسار، بين مجموعتين من القيم وفقًا لذلك الشرط.
فنأخذ المسار من قيمة حيث يكون القناع صحيحًا، ومن قيمة أخرى حيث يكون خاطئًا:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

هذا النمط هو الصيغة المحزومة للاختيار بلا تفرعات.
فكل مسار يُحسب، والقناع وحده يقرر أي قيمة تبقى، دون أي `jcc` في أي مكان.

## الدمج المخصص

توجد تعليمات تُجري ذلك الاختيار نفسه مباشرةً، فتقرأ بتًا واحدًا لكل عنصر من سجل قناع.
وتُسمى تعليمات **الدمج**:

| التعليمة    | العنصر      | مصدر القناع     |
|-------------|-------------|-----------------|
| `pblendvb`  | بايت        | `xmm0` ضمني     |
| `blendvps`  | مسار 32 بت  | `xmm0` ضمني     |
| `blendvpd`  | مسار 64 بت  | `xmm0` ضمني     |

لاحظ أن التعليمة الأولى تتبع صياغة الأعداد الصحيحة، بينما تتبع الأخريان صياغة العوائم.
ومع ذلك، وبما أن هذه التعليمات تختار ببساطة بايتات خام، فيمكن استخدام أي منها مع الأعداد الصحيحة والعوائم معًا.

لكل عنصر، يحتفظ الدمج بالوجهة عندما يكون البت الأعلى لعنصر القناع المطابق صفرًا، ويأخذ المصدر عندما يكون مضبوطًا.
فلا يُفحص إلا ذلك **البت الأعلى**، وهو ما يستوفيه قناع المقارنة، لأن مساراته كلها واحدات أو كلها أصفار.
وسجل القناع دائمًا هو `xmm0`، وهو ضمني:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

ويمكن أيضًا استخدام `pblendvb` لاختيار مسارات من قناع مقارنة لأي حجم آخر.
وبما أن جميع البايتات في المسار الصحيح واحدات كلها، فإن `pblendvb` يختارها جميعًا.

~~~~exercism/note
تُضيف هذه التعليمات كلها حرف `v` بعد العملية المُنفَّذة (`blend`).
ويرمز هذا الـ `v` إلى _variable_، لأن الاختيار ليس ثابتًا، بل يعتمد على سجل.

وتوجد أيضًا صيغ بدون `v`، تختار وفقًا لقيمة فورية.
وهي تتبع النمط نفسه، فتختار المسار `i` إذا كان البت `i` في القيمة الفورية مضبوطًا.
~~~~

## العودة من قناع إلى العددية

على الرغم من قوته، يفتقر كود SIMD إلى الكثير من مرونة الكود العددي.
وفي حالات كثيرة، يلزم الانتقال من سجل محزوم عائدًا إلى عالم التعليمات العددية.

وتعمل عائلة التعليمات `movmsk` كجسر بين العالمين.
تستخرج هذه التعليمات **البت الأعلى** من كل مسار إلى سجل عام الغرض:

| التعليمة    | ما تجمعه                            | عرض النتيجة |
|-------------|-------------------------------------|-------------|
| `pmovmskb`  | البت الأعلى من كل بايت من 16 بايتًا | 16 بتًا     |
| `movmskps`  | البت الأعلى من كل كلمة مزدوجة من 4 كلمات مزدوجة | 4 بتات |
| `movmskpd`  | البت الأعلى من كل كلمة رباعية من 2 كلمتين رباعيتين | 2 بتان |

وإذا استُخدمت بعد مقارنة، فإن كل بت مضبوط يمثل مسارًا «صحيحًا» وكل بت مصفّر مسارًا «خاطئًا».
ويمكن بعد ذلك التعامل مع هذه النتيجة كالمعتاد بواسطة التعليمات العددية.
على سبيل المثال، تعدّ `popcnt` عدد المطابقات، وتجد `tzcnt` المطابقة الأولى.

وقد يكون سجل عام الغرض بعرض 32 بت أو 64 بت.

## اختبار متجه كامل

توجد أيضًا صيغة محزومة من التعليمة العددية `test`: وهي `ptest`.

وهي تشبه نظيرتها العددية في أنها تُجري عملية AND بين معاملين دون تعديلهما.
وعلى عكس `test`، تُجري `ptest` أيضًا عملية ANDN، فتنفي المعامل الأول.

وبذلك يمكن النظر إلى `ptest` على أنها نسخة غير مُدمّرة من `pand` و`pandn` تضبط الأعلام وفقًا للنتيجة.
وبالطريقة ذاتها تقريبًا التي تتبعها هاتان التعلميتان، تتعامل `ptest` مع سجل SIMD بأكمله كمسار واحد، ولذلك لا تأخذ بادئة حجم.

إذا كانت نتيجة عملية AND تساوي `0`، ضُبط `ZF`، وإذا أنتجت عملية ANDN القيمة `0`، ضُبط `CF`.
وهذا يعني أنه يمكن استخدام `ptest` لفحص كلٍّ من قناع الواحدات الكاملة وقناع الأصفار الكاملة:

1. استخدام `ptest` على سجل مع نفسه يضبط `ZF` فقط إذا كان السجل أصفارًا كلها.
   وهذا يحاكي الأسلوب العددي الشائع باستخدام `test` على سجل مع نفسه لفحص القيمة `0`.
2. استخدام `ptest` على سجل مع قناع واحدات كاملة يضبط `CF` فقط إذا كان السجل واحدات كلها.
   كما يضبط `ZF` فقط إذا كان السجل أصفارًا كلها، مما يجعل من الممكن فحص كلا القناعين في الوقت نفسه.

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

ويمكن استخدام نتيجة `ptest` للتفرع أو في تعليمات بلا تفرعات مثل `setcc` أو `cmovcc`، كالمعتاد.

## AVX وما بعده

يمنح AVX المقارنات والدمج و`ptest` صيغة ببادئة `v` على سجلات أوسع.

ويتغير شكل الدمج المتغيّر.
فلم يعد القناع هو `xmm0` الضمني، بل معاملًا رابعًا صريحًا:

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

وتغيّر امتدادات AVX-512 النموذج بعمق أكبر.

أولًا، تضيف صنفًا جديدًا من سجلات SIMD بحجم 64 بايتًا، تُسمى `zmm`.
وهي توسّع سجلات `ymm` المقابلة، بالطريقة نفسها التي توسّع بها سجلات `ymm` سجلات `xmm`.

ثانيًا، تنشئ تلك الامتدادات أيضًا صنفًا جديدًا كليًّا من **سجلات أقنعة العمليات**، من `k0` إلى `k7`، وغرضها الأساسي أن تكون أقنعةً لتعليمات SIMD.
فلم تعد المقارنات تكتب إلى المتجهات، بل إلى أحد هذه السجلات الجديدة.
ويمكن أيضًا استخدامها مباشرةً على تعليمات كثيرة كمحمولات مع قناع كتابة `{k}`، فتختار المسارات _مباشرةً_:

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

وأخيرًا، توجد تعليمات جديدة للعمل على تلك السجلات الجديدة، بما في ذلك نسخها إلى سجلات عامة الغرض.
وهذا يجعل تعليمات `movmsk` غير ضرورية، ولا يوجد دعم لتعليمات `movmsk` على سجلات `zmm`.

وقد ذُكرت هذه الامتدادات للاستيفاء التام.
وتستخدم تمارين هذا المسار التعليمي صيغ SSE.
