# نبذة

في C#، يمكن تعريف تسلسل هرمي من _الأصناف_ باستخدام _الوراثة_، وهي ما يسمح لصنف مشتق (`Car`) بأن يرث سلوك صنفه الأب (`Vehicle`) وبياناته. وإذا لم يُحدَّد صنف أب، فإن الصنف يرث من الصنف `object`.

يمكن للأصناف الأب أن توفّر وظائف للأصناف المشتقة بثلاثة أساليب:

- تعريف طريقة عادية.
- تعريف [طريقة `virtual`][virtual-keyword]، وهي مثل الطريقة العادية، لكن _يمكن_ للأصناف المشتقة تغييرها.
- تعريف [طريقة `abstract`][abstract-keyword]، وهي طريقة بلا تنفيذ، وعلى الأصناف المشتقة _تنفيذها_. والصنف الذي يحتوي على طرق `abstract` يجب أن يُوسم هو أيضًا بـ[`abstract`][abstract-classes]. ولا يمكن إنشاء نسخ من الأصناف المجرّدة.

يسمح [مُحدِّد الوصول `protected`][protected-keyword] بالوصول إلى عضو في الصنف الأب من داخل الصنف المشتق، لكنه يمنع الوصول من أصناف أخرى. وهكذا تستطيع الأصناف المشتقة الوصول إلى أعضاء الصنف الأب من النوع `public` و`protected`، لكن ليس من النوع `private`.

ويمكن للأصناف المشتقة الوصول إلى أعضاء الصنف الأب عبر [الكلمة المفتاحية `base`][base-keyword].

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

سيقوم مُنشئ الصنف المشتق [باستدعاء مُنشئ صنفه الأب تلقائيًا][constructors] _قبل_ تنفيذ منطق مُنشئه هو. ويمكن تمرير الوسائط إلى مُنشئ الصنف الأب باستخدام [الكلمة المفتاحية `base`][base-keyword-constructor]. ولأنه لا يمكن إنشاء نسخ من الأصناف المجرّدة، يمكن جعل مُنشّئاتها `protected`.

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

عندما يُشتق أكثر من صنف من صنف أساس، فإن الصنفين (أو الأصناف) الفرعيين كثيرًا ما ينفّذان نسخًا مختلفة من طريقة في الصنف الأساس. وهذا مبدأ مهم جدًا يُسمّى [تعدّد الأشكال][polymorphism]. فعلى سبيل المثال، في صيغة مختلفة عن المثال السابق، نوضّح كيف يمكن للكود الذي يستخدم `Vehicle` أن يغيّر سلوكه بحسب نوع المركبة التي أُنشئت منها نسخة.

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

لمنع وراثة صنف ما، أضف [المُحدِّد `sealed`][sealed-classes].
يحاول بعض الممارسين تجنّب الوراثة من أصناف ملموسة (كما نوقش في [هذا السؤال على Stack Overflow][pro-sealed])، ومُحدِّد _sealed_ يدعم هذا الاتجاه. ومن ناحية أخرى، يرى كثير من مطوّري C# أنها عقبة أمام الصيانة، كما نوقش في بعض التعليقات على [هذا السؤال][anti-sealed]. والنصيحة هي استخدام المُحدِّد `sealed` باعتدال حتى تكتسب ثقة في استخدامه لمتطلباتك.

تصف [المقالة][new-vs-override] التالية الكلمة المفتاحية `new` كبديل لمُحدِّد `override`. وهذا مفيد أحيانًا، ربما مع تسلسلات هرمية معقّدة للأصناف و/أو نوع من التعارض بين المكتبات.
