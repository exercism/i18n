# مقدمة

## تحسين استدعاء الذيل

في كل مرة تُستدعى فيها دالة، يُنشأ إطار مكدس جديد في الذاكرة لتخزين وسائط الدالة ومتغيراتها المحلية، ويُحرَّر هذا الإطار عند إرجاع الدالة. ولأن Gleam يستخدم استدعاءات الدوال العودية بدلًا من صيغة الحلقات، فقد يؤدي هذا إلى استهلاك قدر كبير من الذاكرة بواسطة إطارات المكدس هذه.

لتجنّب هذه المشكلة يدعم Gleam تحسين استدعاء الذيل، وهو ما يتيح للمصرّف إعادة استخدام إطار المكدس الخاص بالدالة الحالية إذا كان استدعاء دالة هو آخر ما تقوم به الدالة. وهذا يعني أن الدالة يمكنها استدعاء نفسها عددًا لا نهائيًا من المرات دون استخدام أي ذاكرة إضافية.

غالبًا ما يمكن إعادة كتابة الدوال العودية غير المحسَّنة إلى دوال محسَّنة باستدعاء الذيل باستخدام _مُراكِم_.

المُراكِم متغير يُمرَّر إلى جانب البيانات. ويُستخدم لتمرير الحالة الراهنة لتنفيذ الدالة، إلى أن نصل إلى الحالة الأساسية.

ينبغي أن يهيّئ المُراكِم كاتبُ الدالة، لا مستخدمُ الدالة. ولتحقيق ذلك عرّف دالتين: دالة عامة تأخذ البيانات اللازمة فقط كوسائط وتهيّئ المُراكِم، ودالة خاصة تأخذ المُراكِم أيضًا.

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
