# تلميحات
يُستخدم `Option` للإشارة إلى عملية حسابية قد لا يكون لها نتيجة مفيدة
(على سبيل المثال بسبب خطأ أو مُدخل غير صالح).
إذا لم تكن على دراية بـ `Option` فيمكنك قراءة [هذا الدرس التعليمي](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html).
إن `Option` هو ما يُسمى [موناد](https://en.wikipedia.org/wiki/Monad_(functional_programming))، وهو يغطي «جانبًا حسابيًا»، وفي هذه الحالة احتمال غياب القيمة.
الاستخدام السليم للمونادات قد يؤدي إلى كود موجز وأنيق
ومقروء. أما الاستخدام غير السليم فقد يؤدي بسهولة إلى العكس.
شاهد [هذا الفيديو](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) لتتعلم المزيد.
## أخطاء شائعة يجب تجنّبها
هناك بعض القواعد الإرشادية لـ `Option`:
1. إذا لم تكن بحاجة إليه فلا تستخدمه. فبدلًا من
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
الأفضل أن تكون لديك
```scala
def add1(x: Int): Int = x + 1
```
(توجد `Option.map` لتطبيق مثل هذه الدوال البسيطة،
فلا داعي لأن تُثقلها بـ `Option`).
2. لا «تفكّ» القيمة إن لم تكن بحاجة حقيقية إلى ذلك.
غالبًا ما توجد دوال مدمجة تخدم غرضك. ومن مؤشرات فك التغليف المبكر
`isDefined/isEmpty` أو مطابقة الأنماط. فبدلًا من
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
الأفضل أن تكون لديك
```scala
x map (_ + 1) getOrElse 0
```
3. يمكن استخدام المونادات داخل صيغة `for` المركّبة، وهذا أمر رائع.
يُستحسن ذلك عندما تريد «تركيب» عدة نسخ من `Option`. فبدلًا من
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
الأفضل أن تكون لديك
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
