# تشغيل الاختبارات

من الطرفية، انتقل إلى المجلد الأساسي للتمرين، ثم نفّذ الاختبارات باستخدام:

```bash
$ mix test
```

سيُنفّذ هذا ملف الاختبار الموجود في المجلد الفرعي `test`، وهو ملف ينتهي بـ `_test.exs`.

التوثيق:

* [`mix test` - أداة Elixir لتنفيذ الاختبارات](https://hexdocs.pm/mix/Mix.Tasks.Test.html)
* [`ExUnit` - مكتبة اختبارات الوحدة في Elixir](https://hexdocs.pm/ex_unit/ExUnit.html)

## الاختبارات المعلّقة

في مجموعات اختبارات التمارين التطبيقية، تم وسم جميع الاختبارات عدا الأول لكي تُتخطّى.

بعد أن ينجح أحد الاختبارات، يمكنك إلغاء تخطّي الاختبار التالي بتعليق الوسم `@tag :pending` ذي الصلة باستخدام الرمز `#`.

على سبيل المثال:

```elixir
# @tag :pending
test "shouting" do
  assert Bob.hey("WATCH OUT!") == "Whoa, chill out!"
end
```

إذا أردت تنفيذ جميع الاختبارات دفعة واحدة، يمكنك تضمين كل الاختبارات المتخطّاة باستخدام الخيار `--include` في الأمر `mix test`:

```bash
$ mix test --include pending
```

أو يمكنك تفعيل جميع الاختبارات بتعليق سطر `ExUnit.configure` في الملف `test/test_helper.exs`.

```elixir
# ExUnit.configure(exclude: :pending, trace: true)
```

## خيارات `mix test` المفيدة

* `test/<FILE>.exs:LINENUM` - ينفّذ اختبارًا واحدًا فقط، وهو الاختبار الموجود في `<FILE>.exs` والذي يقع تعريفه في السطر `LINENUM`
* `--failed` - ينفّذ فقط الاختبارات التي فشلت في المرة الأخيرة التي شُغّلت فيها
* `--max-failures` - تتوقف المجموعة عن تقييم الاختبارات عند بلوغ هذا العدد من الاختبارات الفاشلة
* `--seed 0` - يعطّل العشوائية بحيث تُنفّذ الاختبارات في ملف واحد دائمًا بالترتيب نفسه الذي عُرّفت به
