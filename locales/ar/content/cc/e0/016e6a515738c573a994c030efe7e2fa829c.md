# نبذة

ترتبط `struct` في C# ارتباطًا وثيقًا بـ `class`.
فلديها حالة وسلوك.
ويمكن أن تضم الأنواع نفسها من الأعضاء: المنشئات، والطرق، والحقول، والخصائص، وغير ذلك.

يمكن أن تكون الحقول والخصائص أنواعًا بسيطة أو `struct` أو أنواعًا مرجعية.
وتتبع `struct` القواعد نفسها المتعلقة بالنطاق وقواعد القراءة/الكتابة ومستويات الوصول التي تتبعها `class`.

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

من الأمور الرئيسية التي ينبغي تذكّرها أنه عند إسناد بنية إلى متغير أو تمريرها كمعامل، تُنسخ القيم، لذا فإن التغييرات التي تُجرى على المتغير الأصلي لن تؤثر في النسخة المنسوخة، والعكس صحيح.
وخلاصة القول إن `struct` من **أنواع القيم**.

يناقش [هذا المقال][class-or-struct] الفروق بين `struct` و`class`.
سترى من المقال أن `struct` تميل إلى أن تكون خفيفة الوزن و[غير قابلة للتغيير][structs-immutable]، رغم أن المترجم أو وقت التشغيل لا يفرضان هذه الإرشادات (افتراضيًا).

هناك بضعة أمور ستواجهها (وسيذكّرك بها المترجم):

1. لا يمكن تهيئة أعضاء `struct` في السطر نفسه.
2. لا يمكن وراثة `struct`.
3. تمتلك `struct` دائمًا منشئًا افتراضيًا حتى إذا قُدّم منشئ غير افتراضي، ولا يمكنك تقديم منشئ صريح بلا معاملات.

ونتيجةً للنقطتين 1 و3 أعلاه، لا سبيل لمطوّر `struct` إلى منع ظهور نسخ غير صالحة.

## البنى الشائعة

سترى من التوثيق أن هناك علاقة وثيقة بين الأنواع الأولية والبنى.
انظر إلى [`Int32/int`][int32] للحصول على مثال.
ومن الأمثلة الأكثر تقليدية على `struct` النوع [`TimeSpan`][time-span].

تتصرّف نسخ `TimeSpan` إلى حد كبير مثل الأعداد، مع عوامل مقارنة مثل `>` و`<` وعوامل حسابية.
ويمكنك تنفيذ هذه العوامل في `struct` الخاصة بك عند الحاجة إليها.

ومن الأمور الجديرة بالملاحظة بشأن `TimeSpan` أنها تنفّذ عددًا من الواجهات، مثل `IComparable<TimeSpan>`.
ومع أن `struct` لا يمكن اشتقاقها من `struct` أخرى، فإنها تستطيع تنفيذ الواجهات.

## التساوي

غالبًا ما يكون اختبار التساوي في `struct` أبسط بكثير من نظيره في `class`، لأنه يقارن الحقول من حيث التساوي افتراضيًا.
ولا حاجة إلى تجاوز `object.Equals()` (أو `GetHashCode()`).
وتذكّر أنه إذا كنت تعتمد على `Object.GetHashCode()`، فلا بد أن تضمن ألّا تتغير الحقول المشاركة في توليد رمز التجزئة (أي كل الحقول) أثناء استخدام مجموعة مُجزّأة.
وعمليًا، يعني هذا أن البنى المستخدمة بهذه الطريقة ينبغي أن تكون غير قابلة للتغيير.

وعلى عكس الطريقة `Equals()`، لا يوجد تنفيذ افتراضي لعاملي التساوي، `==` و`!=`.
وإذا كانت `struct` الخاصة بك بحاجة إليهما، فسيتعيّن عليك تنفيذهما.

ومن ناحية أخرى، يوضّح [هذا المقال][equality] كيف يمكن تحسين الأداء بإنشاء طريقتي `Equals()` و`GetHashCode()` المخصّصتين، كما يحدث غالبًا مع `class`.
وقد بلغ الفرق في حالة هذا التمرين نحو 20% في مقارنة غير دقيقة كثيرًا، لكنه قد يكون أقل من الواقع لأن جميع الحقول من النوع نفسه، انظر أدناه.

وهناك نقاشات على [الويب][equality-performance] حول تحسينات السرعة عندما لا تُتجاوَز الطريقة `Equals()`، إذا كانت جميع الحقول من النوع نفسه.
وقد بلغ الفرق في هذا التمرين عند تضمين حقول متباينة نحو 60%.
وهذا غير مذكور في توثيق مايكروسوفت، ما يجعله تفصيلًا تنفيذيًا غير موثّق، وينبغي الاستفادة منه بحكمة.

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
