# مقدمة

غالبًا ما يكون من المفيد تعريف أنواع مخصّصة في برامجنا.

يمكن إنشاء أنواع بدائية جديدة، لكن ذلك نادرًا ما يحدث.
والأنواع البدائية المضمّنة ليست اختيارًا عشوائيًا: فهي تطابق عن قرب الأنواع القياسية في مترجم LLVM الذي تستخدمه Julia للترجمة في الوقت المناسب.

الأكثر فائدة بكثير هو القدرة على تعريف أنواع مركّبة ذات حقول مُسمّاة.

تحتوي لغات أخرى على شيء مشابه، وتسمّيه `structs` أو `records`.
وتشير إليها وثائق Julia باسم `composite types`، مع أن صيغة اللغة تعرّفها بالكلمة المفتاحية `struct` (وهو تعارض طفيف).

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

تجدر ملاحظة بضع نقاط في المثال أعلاه:

- لم يُحدَّد أي نوع لـ `id`، لذا يفسّر المترجم هذا بأنه `id::Any`.
- يُستخدم اسم النوع كدالة بانية، كما في `Person(id, name, age)`، لإعطاء نسخة من النوع `Person`.
- يمكن الوصول إلى الحقول الفردية بالتدوين النقطي، تمامًا كما هو الحال مع الصفوف المُسمّاة.

عناصر النوع `Person` غير قابلة للتغيير، لذا لا يُسمح بإجراء تحديثات عليها.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

إذا كانت القابلية للتغيير ضرورية، فأضف `mutable` إلى التعريف.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

تتطلب الدالة البانية افتراضيًا أن تظهر الحقول بالترتيب نفسه الوارد في التعريف، وهو ما يصبح غير عملي مع الأنواع الأكثر تعقيدًا.

يتيح استخدام الماكرو `@kwdef` إمكانيتين جديدتين:

- تستخدم الدالة البانية الكلمات المفتاحية بدلًا من الموضع.
- يمكن أن تكون للحقول قيم افتراضية، ويمكن اختياريًا حذفها من الدالة البانية.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## التسلسلات الهرمية للأنواع المركّبة

حتى الآن، لم نُنشئ سوى أنواع مركّبة ملموسة.
وإذا تحقّقت، ستجد أنها جميعًا أنواع فرعية من `Any`.

عند إنشاء عدة أنواع مترابطة، غالبًا ما يكون من المنطقي أكثر تعريف تسلسل هرمي لها.
وهذا أمر سهل جدًا.

أولًا، أنشئ نوعًا مجرّدًا:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

بعد ذلك، أضف عامل `<:` في تعريف النوع لإظهار العلاقة.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

كرّر ذلك حسب الحاجة، مع تذكّر أنه لا يُسمح باشتقاق أنواع فرعية من الأنواع الملموسة.

وللحصول على تسلسل هرمي أكثر تعقيدًا، أنشئ أنواعًا فرعية مجرّدة حسب الحاجة.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

ستتضح قيمة هذا التسلسل الهرمي أكثر عندما نصل إلى مفهوم `Multiple Dispatch`، ونرى كيف تتعامل الدوال مع أنواع الوسائط.
