# مقدمة

لقد *استخدمت* بالفعل التدفقات في `channel-chatter` وتخلّصت منها في `boatswains-bilge`. هذا التمرين هو أول تدفق مخصص لك: صنف يُنفّذ [البروتوكول][stream-protocol]، بحيث يعمل عليه الكود نفسه `with-input-stream` / `read1` / `stream-read1` الذي كان يعمل على `<string-reader>`.

## المزائج: النصف الآخر من التسلسل الهرمي للأصناف

أنت تعرف بالفعل `TUPLE: child < parent …` من `dragons-descendants`: تسلسل هرمي بأب واحد تتدفق فيه الخانات إلى الأسفل. ولـ Factor طريقة *ثانية* لتوسيع مخطط الأصناف: **المزائج المفتوحة**. تُعرّف `MIXIN: m` صنفًا بلا خانات يمكن لأصناف أخرى الانضمام إليه لاحقًا عبر `INSTANCE: c m`. الانتماء هنا متعدد إلى متعدد: يمكن للصنف أن يكون نسخةً من أي عدد من المزائج.

يستخدم بروتوكول التدفقات مزيجين لتحديد أي نصف من الواجهة ينفّذه الصنف:

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

يمكن أن يكون التدفق أحد المزيجين، أو الآخر، أو كليهما. بعد ذلك تُوزّع الدوال العامة المعرّفة على `input-stream` (أو `output-stream`) الاستدعاء إلى أي صنف انضم إلى المزيج، وهكذا تصل الدوال المحيطة مثل `read1` و `stream-contents` و `with-input-stream` وغيرها إلى صنفك.

المزائج *مفتوحة*: يمكنك إضافة عضو جديد بعد تعريف المزيج، حتى في معجم مختلف. وهذا ما يميّزها عن `TUPLE: < parent`، حيث تُثبَّت العلاقة عند تعريف الصنف الابن.

## الدوال العامة للبروتوكول

تقع الدوال العامة للبروتوكول في معجم `io`:

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

تُرجع `stream-read1` البايت التالي (أو `f` عند نهاية التدفق)، بينما تكتب `stream-write1` بايتًا واحدًا. و`stream-read-unsafe` هي القراءة الدفعية المنخفضة المستوى التي توفّرها معظم تدفقات الإدخال، أما `stream-read` فمبنية فوقها وتتولّى تخصيص الذاكرة. وتخبرنا `stream-element-type` ما إذا كان التدفق يتعامل بالبايتات (`+byte+`) أم بالمحارف (`+character+`)؛ وعندما تغلّف تدفقًا آخر، فإن أبسط تنفيذ يفوّض الأمر ببساطة إلى التدفق الأساسي.

## التنظيف من `destructors`

التدفقات قابلة للتخلص منها: التدفق المخصص يرث من `disposable` وينفّذ `dispose*`. وهذا هو الإطار نفسه من `boatswains-bilge` مطبّقًا على صنف تدفق:

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

وبمجرد أن يصبح ذلك جاهزًا، تعمل جميع المُركِّبات `with-…` من `channel-chatter` على تدفقك تلقائيًا.
