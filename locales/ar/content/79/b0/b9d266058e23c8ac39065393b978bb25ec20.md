# نبذة

تُنفَّذ الذاكرة الديناميكية عبر دوال المكتبة التي يستخدمها المبرمج لتخصيص الذاكرة وتحريرها أثناء التنفيذ.
وبما أن المبرمج يتحكم في تخصيص الذاكرة وتحريرها، فإن الذاكرة الديناميكية آمنة بقدر خلوّ المبرمج من الخطأ البشري.
ولهذا السبب، تُعدّ الذاكرة الديناميكية أحد المصادر الرئيسية لأخطاء البرمجة، وهدفًا رئيسيًا لهجمات القرصنة.

تُستخدم الذاكرة الديناميكية للمتغيرات التي لا يُعرَف حجمها إلا أثناء التنفيذ.
وهذا مفيد عادةً للمصفوفات التي قد يتغيّر عدد عناصرها من تنفيذ إلى آخر.
والمصفوفات متغيّرة الطول (VLA) أسلوب آخر للتعامل مع المصفوفات التي لا يُعرَف حجم عناصرها إلا أثناء التنفيذ.
تستخدم المصفوفة متغيّرة الطول تخزينًا تلقائيًا، أي أن ذاكرتها تُدمَّر عند الخروج من الكتلة التي عُرِّفت فيها.
(لمزيد من المعلومات عن التخزين، راجع مفهوم [محدِّدات صنف التخزين](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers).)
أُدخلت المصفوفات متغيّرة الطول إلى لغة C عبر C99، لكنها أصبحت اختيارية بدءًا من C11، لذا لا يلزم أن تدعمها المترجمات التي تدعم C11 فما بعده.
وتحليل مفصّل للمصفوفات متغيّرة الطول يخرج عن نطاق هذه المقالة.

## malloc

`malloc` دالة مُعلَنة في `stdlib.h` تُستخدم لتخصيص الذاكرة الديناميكية.
إذا نجح التخصيص، تُرجع الدالة مؤشرًا يشير إلى عنوان أول بايت من الذاكرة المخصَّصة.
وإذا لم ينجح التخصيص، تُرجع `NULL`.
من الحكمة أن تتحقق من نتيجة `malloc` مقابل `NULL` وأن تتعامل مع الفشل بصورة سليمة.
المؤشر المُرجَع من النوع `pointer-to-void`، ويمكن اعتباره تقريبًا مؤشرًا "عامًّا" قابلًا للتحويل إلى النوع المحدد الذي تستخدمه الذاكرة.
لدى `malloc` معامل واحد هو حجم الذاكرة المطلوبة بالبايت.
والحجم الكلي لتخصيص مصفوفة هو حجم نوع بيانات كل عنصر مضروبًا في عدد العناصر.
ويُستخدم العامل `sizeof` عادةً للحصول على حجم نوع بيانات كل عنصر.
يوضّح المثال التالي ذلك

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

من المهم أن تتذكر أن الذاكرة المخصَّصة حديثًا بواسطة `malloc` ليست مُهيّأة، لكنها قد تحتوي على قيم عشوائية.
لاحظ أن `sizeof` لمؤشر `numbers` ليس عدد عناصر المصفوفة، ولا الحجم الكلي للذاكرة المخصَّصة.
فحجم المؤشر الذي تُرجعه `malloc` هو حجم أي مؤشر على ذلك النظام بعينه.
شُغِّل كود المثال على نظام 64 بت، فكان حجم المؤشر 8 بايتات (مضروبة في 8 بتات لكل بايت = 64 بت).
وحُوّل نوع المؤشر ضمنيًا من pointer-to-void إلى pointer-to-int.
أما كون pointer-to-int يشير إلى `int` واحد أو إلى مصفوفة من `ints` فهو أمر يستطيع المبرمج التعامل معه كما يراه مناسبًا.
على سبيل المثال

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

إذا كان سيُكتب في القيمة أو القيم قطعًا قبل قراءتها، فقد يكون استخدام `malloc` أسلوبًا فعّالًا لتخصيص الذاكرة.
لكن إذا كان هناك احتمال أن تُقرأ القيمة أو القيم قبل تهيئتها، فإن استخدام `malloc` محفوف بالمخاطر.
وثمة أسلوب أكثر أمانًا لتخصيص الذاكرة هو استخدام `calloc`، الذي يهيّئ الذاكرة المخصَّصة حديثًا إلى الصفر.

لاحظ في الأمثلة أعلاه أنه استُخدم `free(numbers)`.

## free

`free` دالة مُعلَنة في `stdlib.h` تُستخدم لتحرير الذاكرة التي خُصِّصت ديناميكيًا.
وتبقى الذاكرة المخصَّصة ديناميكيًا محجوزة في الذاكرة حتى تُحرَّر بواسطة `free`.
قد تُحرِّر بعض أنظمة التشغيل الذاكرة المخصَّصة ديناميكيًا تلقائيًا عند انتهاء البرنامج، لكن من أفضل الممارسات ألّا تعتمد على ذلك.
لدى `free` معامل واحد هو مؤشر إلى الذاكرة التي خُصِّصت ديناميكيًا.
ويرتبط استخدام `free` أو عدم استخدامه بعدّة مشكلات في الذاكرة.

#### تسرّب الذاكرة

عدم تحرير الذاكرة المخصَّصة ديناميكيًا بعد أن يبلغ المرجع إلى تلك الذاكرة نهاية عمره، أو يُتلَف بأي شكل آخر، يُسمّى تسرّب الذاكرة.
والذاكرة المتسرِّبة هي ذاكرة يحجزها النظام لكن لم يعد البرنامج قادرًا على الوصول إليها.
وقد تكون هذه مشكلة خاصة إذا خُصِّصت الذاكرة داخل حلقة، ولم تُحرَّر في نهاية الحلقة، ثم خُصِّصت مرة أخرى في بداية الحلقة.
وإذا خُصِّصت ذاكرة كافية دون تحريرها، سيفشل نداء تخصيص الذاكرة بسبب عدم تبقّي ذاكرة كافية للتخصيص.
من المهم أن تتذكر أنه على الرغم من أن الذاكرة المخصَّصة ديناميكيًا يحجزها النظام حتى تُحرَّر، فإن المؤشر المُسنَد إليها قد يكون له نطاق كتلة فقط.
فعلى سبيل المثال، في أمثلة `malloc`، تُخصَّص الذاكرة داخل `my_function`.
وستتسرّب تلك الذاكرة لو لم يُرجع المؤشر إليها ويُستخدم لضبط مؤشر `numbers` في `main`.
وهكذا، فإن تمرير مؤشر `numbers` ذلك إلى `free` يحرّر الذاكرة المخصَّصة في `my_function`.

#### الاستخدام بعد التحرير (**UAF**)

إذا جرى الوصول إلى الذاكرة بعد تحريرها، فقد تكون القيمة أو القيم أي شيء.
في المثال التالي، تُحرَّر الذاكرة التي يشير إليها `numbers` ثم يُقرأ منها في `printf`.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

يُسمّى مؤشر `numbers`، بعد تحريره، مؤشرًا معلّقًا.
وقد يشير المؤشر المعلّق إلى ذاكرة أخرى غير التي قُصد بها.
وهكذا يمكن أن يؤدي المؤشر المعلّق إلى تلف البيانات واستبدال الكود وتنفيذه بشكل عشوائي.
ويمكن استخدام مؤشر إلى ذاكرة مخصَّصة لم يُفرَّغ بضبطه على `NULL` لاختراق البرنامج.
في المثال أعلاه، لو ضُبط `numbers` على `NULL` هكذا: `numbers = NULL;` بعد تحريره، لانتهى البرنامج عند `printf` التالي، وربما أبلغ عن خطأ تجزئة عند محاولة قراءة `numbers[0]`.

#### التحرير المزدوج

إذا استُدعيت `free` مرتين على مؤشر إلى ذاكرة مخصَّصة ديناميكيًا، نتج عن ذلك سلوك غير معرَّف (**UB**).
وهذا يعني أن المترجم يمكنه التعامل معه بأي أسلوب يشاء.
والمثال التالي، عند ترجمته بمترجمَين مختلفين، قد تكون له نتيجتان مختلفتان

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

لم يولّد المترجم الأول ولا الثاني أي خطأ وقت التنفيذ عندما ضُبط `numbers` على `NULL` بين كل نداء إلى `free`، لكن ذلك ليس مضمونًا للعمل مع مترجم ثالث.
ومن المصادر الشائعة للتحرير المزدوج وجود مؤشرين يشيران إلى الذاكرة الديناميكية نفسها.
فقد يشير أحد المؤشرين إلى بداية مصفوفة في موضع ما من البرنامج، بينما يُستخدم المؤشر الآخر للتنقّل عبر المصفوفة في موضع آخر منه.
وفي مواضع مختلفة من البرنامج يُحرَّر كل مؤشر، ما يؤدي إلى تحرير مزدوج.

## calloc

`calloc` دالة مُعلَنة في `stdlib.h` تُستخدم لتخصيص الذاكرة الديناميكية وتهيئة الذاكرة المخصَّصة حديثًا إلى الصفر معًا.
إذا نجح التخصيص، تُرجع الدالة مؤشرًا يشير إلى عنوان أول بايت من الذاكرة المخصَّصة.
وإذا لم ينجح التخصيص، تُرجع `NULL`.
من الحكمة أن تتحقق من نتيجة `calloc` مقابل `NULL` وأن تتعامل مع الفشل بصورة سليمة.
المؤشر المُرجَع من النوع `pointer-to-void`، ويمكن اعتباره تقريبًا مؤشرًا "عامًّا" قابلًا للتحويل إلى النوع المحدد الذي تستخدمه الذاكرة.
لدى `calloc` معاملان.
المعامل الأول يحدد عدد العناصر المطلوب تخصيصها من نوع البيانات المحدَّد.
والمعامل الثاني يحدد حجم نوع البيانات المحدَّد المراد تخصيصه.

في المثال التالي، ينبغي أن تُظهر جميع عبارات `printf` القيمة `0` دائمًا، لأن `calloc` يضمن تصفير القيم المخصَّصة حديثًا.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` دالة مُعلَنة في `stdlib.h` تُستخدم لتوسيع ذاكرة مخصَّصة قائمة أو تقليصها.
إذا نجحت إعادة التخصيص، تُرجع الدالة مؤشرًا يشير إلى عنوان أول بايت من الذاكرة المعاد تخصيصها.
وإذا لم تنجح إعادة التخصيص، تُرجع `NULL`.
من الحكمة أن تتحقق من نتيجة `realloc` مقابل `NULL` وأن تتعامل مع الفشل بصورة سليمة.
لدى `realloc` معاملان.
المعامل الأول مؤشر إلى الذاكرة القائمة المراد إعادة تخصيصها.
والمعامل الثاني يحدد حجم الذاكرة المعاد تخصيصها بالبايت.
وتُحتفَظ بالقيم التي ضُبطت قبل توسيع الذاكرة.
من المهم أن تتذكر أن الذاكرة المضافة عند توسيع الذاكرة ليست مهيَّأة إلى الصفر، وقد تكون قيمتها أو قيمها أي شيء.
كذلك، الذاكرة التي تُزال عند تقليص الذاكرة ليست مهيَّأة أيضًا، وقد تحتفظ بالقيمة أو القيم.
يوضّح المثال التالي توسيع مصفوفة وتقليصها

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## عندما يكون الحجم المُمرَّر 0

إذا كان الحجم المُمرَّر إلى `malloc` أو `calloc` أو `relloac` هو `0`، فإن ما يحدث يعتمد على كيفية تنفيذ المترجم له.
فقد يُرجع المترجم مؤشرًا `NULL` أو مؤشرًا غير فارغ.
على سبيل المثال، عند تخصيص ذاكرة لمؤشر إلى `char`، قد يُرجع المترجم إما `NULL` أو مؤشرًا غير فارغ إلى سلسلة نصية فارغة.
ولتجنّب نتائج مختلفة باختلاف المترجمات، من الأفضل عدم التخصيص بحجم 0.
