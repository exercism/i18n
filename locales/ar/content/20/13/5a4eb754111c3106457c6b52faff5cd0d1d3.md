# مقدمة

عندما تكون لديك عدة قيم منفصلة محتملة تريد التفرّع بينها، فإن `case` (في [`combinators`][combinators]) خيار أنسب من تسلسل من `if`.

## `case`

```
case ( obj assoc -- )
```

يأخذ `case` القيمة من أعلى المكدس، ويأخذ *assoc* من البنود. كل بند بالشكل `{ value [ body ] }`. أول بند تكون قيمته مساوية (`=`) للمدخل هو الذي يُطبَّق، ويعمل جسمه بينما قيمة المدخل *مستهلكة بالفعل*. أما المدخل الأخير المكوّن من `[ body ]` فقط فهو الحالة الافتراضية: يبقى المدخل *على المكدس* عند تنفيذها.

```factor
USING: combinators ;

: name-of ( n -- s )
    {
        { 1 [ "one" ] }
        { 2 [ "two" ] }
        [ drop "many" ]
    } case ;
```

المساواة تتم باستخدام `=`، لذا يصلح أي شيء تكون المقارنة فيه متساوية كمفتاح، سواء كان عددًا أو سلسلة نصية أو رمزًا.

## `cond` للفروع المحروسة

عندما يعتمد الاختيار على *محمول* بدلًا من المساواة (مثل `x > 11`)، فإن `cond` هو الأداة المناسبة. لقد تعرّفت على `cond` في [Cars, Assemble!][cars-assemble].

## الرموز

تُعرّف `SYMBOL:` كلمة تدفع نفسها إلى المكدس، أي قيمة وسم تقيّم نفسها. أما `SYMBOLS:` فتُعرّف عدة رموز دفعة واحدة:

```factor
SYMBOLS: yes no maybe ;
```

والآن أصبح `yes` قيمة يمكن مقارنتها باستخدام `=` واستخدامها كمفتاح في `case`:

```factor
: invert ( ? -- ?' )
    { { yes [ no ] } { no [ yes ] } [ ] } case ;
```
