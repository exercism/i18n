# مقدمة

بعض الحلقات لا يمكن كتابتها على هيئة «نفّذ هذا لكل عنصر من عناصر متتالية»، بل عليك أن تستمر حتى تنقلب بعض الشروط. ومُركّب `while` في Factor هو الأداة المناسبة لذلك: عبارة quotation للشرط تقول «هل نستمر؟»، وعبارة quotation للجسم تنفّذ عمل خطوة واحدة، ويكرّر `while` ذلك حتى تُرجع العبارة الشرطية `f`.

## `while` و`until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` و`body` عبارتان من نوع quotation تعملان على مكدّس البيانات. تظل `while` تكرّر الحلقة ما دامت `pred` تترك قيمة تُعدّ صحيحة؛ أما `until` فهي العكس: تظل تكرّر الحلقة *حتى* تصبح `pred` صحيحة (أي ما دامت `pred` تترك `f`).

يمكن لقيمة حالة واحدة أن تتدفق على المكدّس بين العبارة الشرطية والجسم:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

التتبّع: العبارة الشرطية `dup 0 >` تتفقّد العدّاد الجاري؛ والجسم `dup . 1 -` يطبعه ويُنقص منه واحدًا؛ وتتوقف الحلقة بمجرد أن يبلغ العدّاد `0`. أما `drop` في النهاية فتتخلص من ذلك `0` الأخير على المكدّس.

## `while*`: أبقِ قيمة العبارة الشرطية

```
while* ( pred body -- )
```

كل ما يهمّ `while` هو ما إذا كانت عبارتها الشرطية قد تركت قيمة صحيحة، فهي تتخلص من القيمة نفسها قبل تشغيل الجسم. أما `while*` فهي *تُسلّم تلك القيمة إلى الجسم* بدلًا من ذلك. الجأ إليها كلما أراد الاختبار والجسم الشيء نفسه المحسوب حديثًا: بحث في جدول، أو مطابقة، أو رمز مُحلَّل.

هنا يشير كل اسم إلى الاسم التالي في سلسلة مترابطة. تبحث العبارة الشرطية عن الاسم الحالي؛ وما دام هناك اسم تالٍ، تُمرّر `while*` ذلك الاسم إلى الجسم، الذي يطبعه ويواصل من هناك:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

تُرجع `links at` الاسم التالي، أو `f` حالما لا يكون للاسم أي مدخل. وما دامت تُرجع اسمًا، تمنح `while*` ذلك الاسم إلى `dup .`، التي تطبعه وتتركه مفتاحًا للبحث التالي. وأول `f` يوقف الحلقة، إذ تتخلص `while*` منه، فلا يتبقى شيء.

## قيم حالة متعددة باستخدام المتغيرات المحلية

عندما تحمل الحلقة أكثر من قيمة (مصفوفة متبقية ومجموع جارٍ، مثلًا)، يصبح التلاعب بالمكدّس فوضويًا. والنمط الأنظف هو الإعلان عن *متغيرات محلية* باستخدام `::`:

```
:: word ( inputs -- outputs ) ... ;
```

داخل الجسم، يضيف `:> name!` متغيرًا محليًا قابلًا للتغيير؛ فالقراءات تستخدم `name`، والكتابات تستخدم `name!` (التي تستهلك القيمة الجديدة من المكدّس وتُسندها).

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

يغطي متغيران محليان هنا (`rest` و`running`) حالة الحلقة بأكملها: تتفقّدهما العبارة الشرطية، ويحدّثهما الجسم، وتُرجَع القيمة النهائية في النهاية.

تنزع `unclip ( seq -- rest first )` العنصر الأول من متتالية، وهو أمر مفيد عندما تريد الحلقة أن تستهلك مصفوفة عنصرًا واحدًا في كل تكرار. أما صيغة `[ rest! ] dip` فتحدّث `rest` إلى الذيل المتبقي، مع إبقاء العنصر المنزوع حديثًا على المكدّس كي يستخدمه الجسم.
