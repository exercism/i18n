# القابلية للتغيير

القابلية للتغيير خاصية لارتباط معيّن في Rust. الارتباط إما غير قابل للتغيير وإما قابل للتغيير. لا يجوز تغيير قيمة الارتباط غير القابل للتغيير، بينما يمكن تغيير قيمة الارتباط القابل للتغيير. وجميع الارتباطات غير قابلة للتغيير افتراضيًا.

## الارتباطات

الارتباط هو العلاقة بين اسم متغيّر معيّن كما يظهر في الكود المصدري ومنطقة معيّنة من الذاكرة كما تظهر أثناء التنفيذ. وبدقة أكثر، لا توجد الارتباطات إلا أثناء الترجمة: فقبل الترجمة لا تكون هناك ذاكرة مُخصَّصة فعلًا، وبعد الترجمة يتعامل كود الآلة حصرًا مع عناوين الذاكرة بدلًا من المتغيّرات المُسمّاة.

تُنشأ الارتباطات عادةً بالكلمة المفتاحية `let`. كما تُنشأ ارتباطات من معاملات الدوال وفي بعض الحالات الأخرى.

يمكن أن يكون للارتباطات خصائص متنوعة، وأهمها القابلية للتغيير. والارتباط القابل للتغيير هو الذي يجوز فيه تغيير قيمة الذاكرة المرتبطة به. وتتعقّب Rust قابلية التغيير لكل ارتباط وتفرضها بصرامة للمساعدة في ضمان صحة البرامج، إذ ترفض البرامج التي تحاول خطأً تعديل ارتباط ينبغي أن يكون غير قابل للتغيير.

## القابلية للتغيير

عمليًا، غالبًا ما تكون القابلية للتغيير بسيطة. فباستخدام الكلمة المفتاحية `mut` في تعريف الارتباط، تحصل على القدرة على تغيير القيمة.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### التخفيض من قابل للتغيير إلى غير قابل للتغيير

يمكن دائمًا تخفيض ارتباط من قابل للتغيير إلى غير قابل للتغيير. وهذه العملية شفافة.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### الترقية من غير قابل للتغيير إلى قابل للتغيير

بشكل عام، يمكن ترقية قيمة من غير قابلة للتغيير إلى قابلة للتغيير في أي وقت تُنقل فيه الملكية.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

عند `(1)`، تُنقل ملكية السلسلة النصية من `x` إلى `y`، ما يسمح لنا بترقية القيمة لتصبح قابلة للتغيير.

### القابلية للتغيير في معاملات الدوال

هناك أسلوبان مختلفان لجعل معاملات الدوال قابلة للتغيير. الأسلوب الأول، وهو الأكثر شيوعًا، يشبه التمرير بالمرجع في C:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

في هذا المثال، أُعلنت القابلية للتغيير صراحةً في ثلاثة مواضع. وتُشترط إعلانات القابلية للتغيير الثلاثة كلها لكي تعمل المراجع القابلة للتغيير.
في `(2)`، يُعلَن الارتباط `x` قابلًا للتغيير. وهذا الارتباط هو المالك للقيمة على المستوى الأعلى.
وفي `(3)`، تُستعار تلك القيمة استعارة قابلة للتغيير، لتُمرَّر إلى الدالة `increment`.
وفي `(1)`، يُنشأ ارتباط جديد قابل للتغيير باسم `n` إلى المرجع المناسب.

وهناك أسلوب آخر لقابلية تغيير المعاملات، وهو أقل شيوعًا لكنه يظل مفيدًا أحيانًا. في هذا الأسلوب، تكون القيمة مملوكة، لكن الارتباط قابل للتغيير.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

يتطلب هذا المثال إعلانات صريحة أقل لأنه في الواقع نقل للملكية مع ترقية مدمجة للقابلية للتغيير. وهو يعمل لأن `i32` نوع `Copy` ينسخ البيانات بشكل شفاف.
في `(1)` نُعلن أن `increment_internally` تقبل `i32` مملوكًا وقابلًا للتغيير باسم `n` كمعامل لها.
وفي `(2)` نُعلن أن `x` ارتباط غير قابل للتغيير بالقيمة `1`.
وفي `(3)` تُنسخ `x` إلى موضع جديد في الذاكرة. وتبقى `x` غير قابلة للتغيير، بينما `n` قابلة للتغيير.

من الممكن بالطبع دمج الصيغتين، أي إنشاء ارتباط قابل للتغيير إلى مرجع قابل للتغيير (`mut n: &mut i32` وما شابه)، لكن هذا نادرًا ما يكون هو المطلوب فعلًا.

### القابلية للتغيير بدون `let`

يمكن لعدة تراكيب في Rust (`if let`، `match`، وما شابه) أن تنشئ ارتباطات أيضًا. ويمكن أن تكون هذه الارتباطات قابلة للتغيير كذلك.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

ينتج هذا المثال أولًا `v = Some(2)`، ثم `v = None`.

## التظليل

من الممكن، وغالبًا ما يكون مألوفًا في الأسلوب، إعادة استخدام اسم متغيّر مع تحوّل قيمة معيّنة، عبر إعادة إعلانه باستدعاءات `let` متعددة. ويُعرف هذا بالتظليل.

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

لكن هذه ليست حالة من القابلية للتغيير؛ فالقيم الأصلية لا تزال موجودة من حيث المبدأ. وبالنسبة إلى الأنواع غير `Drop`، قد يختار المترجم تعديل موضع في الذاكرة بدلًا من تخصيص موضع جديد. لكنه لن يفعل ذلك أبدًا مع نوع `Drop`، أو إذا أُعيد استخدام الارتباط القديم.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
