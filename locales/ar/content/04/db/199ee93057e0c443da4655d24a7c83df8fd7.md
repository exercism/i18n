# حول

## التساوي

يمكن التحقق من أنواع Elm لمعرفة ما إذا كانت «متماثلة» باستخدام [عامل التساوي][equality-operator] `(==)`.
أما عامل عدم التساوي فهو `(/=)` (*وليس* `!=` كما في كثير من اللغات).

```elm
1 == 2
    --> False

1 /= 2
    --> True
```

يجب أن تكون كلتا القيمتين المقارنتين من النوع نفسه.
يعمل عامل التساوي على القيم الحرفية، والصفوف، والسجلات، والأنواع المخصصة.
يتحقق هذا العامل من التساوي البنيوي، أي أن القيم المتساوية لها المحتوى نفسه والبنية العميقة نفسها، بغض النظر عن تعليق النوع أو موضعها في الذاكرة.

```elm
(1, 2) == (2, 1)
    --> False

type alias MyRecord = { myInt : Int, myStrings : List String }
a : MyRecord
a = MyRecord (1 + 1) ["hello world"]

type alias MyOtherRecord = { myInt : Int, myStrings : List String }
myStrings =  (String.join " " ["hello", "world"]) :: []
b : MyOtherRecord
b = { myInt = 2, myStrings = myStrings}

a == b
    --> True
```

لاحظ أنه *لا ينبغي أبدًا* مقارنة الدوال، لأن ذلك سيجعل البرنامج يتعطل أثناء التشغيل.
لمزيد من المعلومات حول هذا القيد، انظر [هنا][equality-operator].

## المقارنات

تعمل [عوامل المقارنة][comparison-operators] `(<)` و`(<=)` و`(>)` و`(>=)` والدوال `min` و`max` و`compare` على الأنواع `comparable`.
النوع `comparable` نوع خاص يجمع كل الأنواع المدمجة القابلة للمقارنة: الأعداد، والمحارف، والسلاسل النصية، ومصفوفات الأشياء القابلة للمقارنة، والصفوف المكوّنة من أشياء قابلة للمقارنة.
تُقارن المحارف حسب [نقاط ترميز يونيكود][unicode-codepoint] الخاصة بها.

```elm
1 < 1 + 1
    --> True

'x' < 'X'
    --> False

'互' < '🙏'
    --> True
```

تُقارن الأنواع الشبيهة بالمتتاليات (السلاسل النصية والمصفوفات والصفوف) وفق [الترتيب المعجمي][lexicographic-order].
باختصار، تُقارن عناصر المتتالية اثنين اثنين بالترتيب حتى يُعثر على عنصر أصغر أو تنتهي إحدى المتتاليتين.

```elm
"abc" < "abz"
    --> True

"abc" < "abcd"
    --> True

"abc" < "b"
    --> True

min [1 , 2, 9000] [10]
    --> [1 , 2, 9000]

min (1, "hello") (3, "bye")
    --> (1, "hello")

min (1, ['a', 'b']) (1, ['A', 'B'])
    --> (1, ['A', 'B'])
```

لا يمكن مقارنة قيم الأنواع الأخرى، مثل السجلات أو الأنواع المخصصة، مباشرة.

تتطلب بعض الأنواع المدمجة أن يكون محتواها من النوع `comparable`، مثل مفاتيح `Set` أو `Dict`، لأن بنيتها تعتمد على ترتيب داخلي.
وهذا يعني أنه قد لا يمكن تخزين الأنواع المخصصة في `Set`، مع أن هناك بدائل من المجتمع: [`AnySet`][any-set] و[`AnyDict`][any-dict] و[`Sort`][sort] وغيرها.

يمكن ترتيب مصفوفات القيم من النوع `comparable` باستخدام `List.sort`، ويمكن ترتيب مصفوفات القيم التي يمكن تحويلها إلى قيم قابلة للمقارنة باستخدام `List.sortBy`.
إذا احتجت إلى ترتيب هرمي (ترتيب حسب خاصية، ثم حسم التعادل بخاصية أخرى)، يمكن استخدام الصفوف أو المصفوفات مع `List.sortBy` (من بين [بدائل][sort-by] أخرى)، لأن الصفوف والمصفوفات تُرتَّب بترتيب معجمي.


```elm
List.sort ["hi", "hello", "bye", "goodbye"]
    --> ["bye", "goodbye", "hello", "hi"]

List.sortBy String.length ["hi", "hello", "bye", "goodbye"]
    --> ["hi", "bye", "hello", "goodbye"]

-- sort by length, then alphabetically
List.sortBy (\str -> (String.length str, str)) ["hi", "mum", "hello", "sis", "bye", "dad"]
    --> ["hi", "bye", "dad", "mum", "sis", "hello"]
```

تأخذ الدالة `compare` قيمتين من النوع `comparable` وتُرجع قيمة من النوع `Order`.
النوع `Order` نوع يتحقق في عملية واحدة مما إذا كانت قيمة ما أكبر (`GT`) أو مساوية (`EQ`) أو أصغر (`LT`) من قيمة أخرى.

```elm
compare 1 2
    --> LT

compare "" ""
    --> EQ

compare [12] []
    --> GT
```

يمكن إنشاء دوال مقارنة لأي نوع واستخدامها، مثلًا، في الترتيب باستخدام `List.sortWith`:

```elm
type Color = Red | Green | Blue

compareColors : Color -> Color -> Order
compareColors a b =
  case (a, b) of
    (Red, Red) -> EQ
    (Red, _) -> LT
    (_, Red) -> GT
    (Green, Green) -> EQ
    (Green, _) -> LT
    (_, Green) -> GT
    (Blue, Blue) -> EQ

List.sortWith compareColors [Blue, Red, Green, Green, Blue]
    --> [Red, Green, Green, Blue, Blue]
```
