# نبذة

مثل كثير من اللغات الأخرى، تمتلك Go مؤشرات. وإذا كنت جديدًا على المؤشرات، فقد تبدو غامضة بعض الشيء، لكن ما إن تعتاد عليها حتى تجدها بسيطة ومباشرة. وهي جزء جوهري من Go، لذا خصّص بعض الوقت لفهمها حقًا.

قبل الخوض في التفاصيل، يجدر بنا أن نفهم الغرض من استخدام المؤشرات. فالمؤشرات وسيلة لمشاركة الذاكرة مع أجزاء أخرى من برنامجنا، وهذا مفيد لسببين رئيسيين:

1. عندما نمتلك كميات كبيرة من البيانات، يصبح إنشاء نُسخ لتمريرها بين الدوال غير فعّال إلى حد كبير. وبدلًا من ذلك، بتمرير موقع الذاكرة الذي تُخزَّن فيه البيانات، يمكننا تقليص استهلاك برامجنا للموارد بشكل كبير.
2. بتمرير المؤشرات بين الدوال، يمكننا الوصول إلى النسخة الواحدة من البيانات وتعديلها مباشرة، ما يعني أن أي تغييرات تُجريها إحدى الدوال تصبح مرئية فورًا لأجزاء أخرى من البرنامج عند انتهاء الدالة.

## المتغيرات والذاكرة

لنفترض أن لدينا متغيرًا عاديًا من نوع عدد صحيح اسمه `a`:

```go
var a int
```

عندما نُعلن عن متغير، يتعيّن على Go إيجاد مكان في الذاكرة لتخزين قيمته. وهذا الأمر مجرّد عنّا إلى حد كبير: فعندما نحتاج إلى جلب القيمة المخزّنة في ذلك الجزء من الذاكرة، يكفي أن نشير إليه باسم المتغير.

على سبيل المثال، عندما نكتب `a + 2`، فإننا في الواقع نجلب القيمة المخزّنة في الذاكرة المرتبطة بالمتغير `a` ونضيف إليها 2.

وبالمثل، عندما نحتاج إلى تغيير القيمة في الجزء الخاص بالمتغير `a` من الذاكرة، يمكننا استخدام اسم المتغير للقيام بعملية إسناد:

```go
a = 3
```

سيخزّن الجزء من الذاكرة المرتبط بـ `a` الآن القيمة `3`.

## المؤشرات

بينما تتيح لنا المتغيرات الإشارة إلى القيم في الذاكرة، فإن معرفة **عنوان الذاكرة** الذي يشير إليه المتغير مفيدة في بعض الأحيان. وتحمل **المؤشرات** عناوين الذاكرة لتلك القيم. وتُعلن عن متغير من نوع مؤشر بإضافة نجمة قبل النوع الأساسي:

```go
var p *int // 'p' contains the memory address of an integer
```

هنا نُعلن عن متغير `p` من النوع «مؤشر إلى عدد صحيح» (`*int`). وهذا يعني أن `p` سيحمل عنوان الذاكرة الخاص بعدد صحيح. القيمة الصفرية للمؤشرات هي `nil`، لأن المؤشر `nil` لا يحمل أي عنوان ذاكرة.

### الحصول على مؤشر إلى متغير

لإيجاد عنوان الذاكرة الخاص بقيمة متغير، يمكننا استخدام العامل `&`. على سبيل المثال، إذا أردنا إيجاد عنوان الذاكرة الخاص بالمتغير `a` وتخزينه في المؤشر `p`، فيمكننا فعل ما يلي:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### الوصول إلى القيمة عبر المؤشر (إلغاء الإشارة)

عندما نمتلك مؤشرًا، قد نرغب في معرفة القيمة المخزّنة في عنوان الذاكرة الذي يمثّله المؤشر. ويمكننا فعل ذلك باستخدام العامل `*`:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

تجلب العملية `*p` القيمة المخزّنة في عنوان الذاكرة المحفوظ في `p`. وغالبًا ما تُسمى هذه العملية «إلغاء الإشارة» (dereferencing).

يمكننا أيضًا استخدام عامل إلغاء الإشارة لإسناد قيمة جديدة إلى عنوان الذاكرة الذي يشير إليه المؤشر:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

يؤدي الإسناد إلى `*pa` إلى تغيير القيمة المخزّنة في عنوان الذاكرة الذي يحمله `pa`. وبما أن `pa` يحمل عنوان الذاكرة الخاص بـ `a`، فإننا بإسناد قيمة إلى `*pa` نغيّر فعليًا قيمة `a`!

لكن انتبه: تحقّق دائمًا من أن المؤشر ليس `nil` قبل إلغاء الإشارة إليه. فإلغاء الإشارة إلى مؤشر `nil` سيجعل البرنامج يتعطل وقت التشغيل!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### المؤشرات إلى البُنى

حتى الآن لم نرَ سوى مؤشرات إلى قيم بدائية. ويمكننا أيضًا إنشاء مؤشرات إلى البُنى:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

كان يمكننا أيضًا إنشاء `Person` جديد وتخزين مؤشر إليه مباشرة:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

عندما نمتلك مؤشرًا إلى بنية، لا نحتاج إلى إلغاء الإشارة قبل الوصول إلى أحد الحقول:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## الشرائح والخرائط هي مؤشرات بالفعل

الشرائح والخرائط أنواع خاصة لأنها تحتوي بالفعل على مؤشرات في تصميمها الداخلي. وهذا يعني أنه في معظم الحالات لا نحتاج إلى إنشاء مؤشرات لهذه الأنواع لمشاركة عنوان الذاكرة الخاص بقيمها. تخيّل أن لدينا دالة تزيد قيمة مفتاح في خريطة:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

إذا أنشأنا خريطة ونادينا هذه الدالة، فإن التغييرات التي أجرتها الدالة على الخريطة تبقى بعد انتهاء الدالة. وهذا سلوك مشابه لما نحصل عليه عند استخدام مؤشر، لكن لاحظ أننا في هذا المثال لا نستخدم أي إشارة أو إلغاء إشارة ولا أيًا من صيغة المؤشرات:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

وينطبق الأمر نفسه عند تغيير عنصر موجود في شريحة.

غير أن العمليات التي تُرجع شريحة جديدة مثل `append` حالة خاصة و**قد لا** تعدّل الشريحة خارج الدالة. ويعود السبب في ذلك إلى الطريقة التي تعمل بها الشرائح داخليًا، لكننا لن نخوض في تفاصيل ذلك، لأنه موضوع أكثر تقدمًا. وإذا كنت فضوليًا حقًا، يمكنك قراءة المزيد عن ذلك في [مدونة Go: آليات 'append'][mechanics-of-append]

## حساب المؤشرات

بخلاف لغات أخرى، لا تدعم Go حساب المؤشرات. وهذا يعني أنه لا يمكنك الانتقال من عنوان ذاكرة قيمة ما إلى عنوان قيمة أخرى بزيادة قيمة المؤشر. لذا فإن المقتطفات التالية غير صالحة:

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
