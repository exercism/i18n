# حول

تنفّذ مجموعات التجزئة [بروتوكول][set-protocol] [`sets`][sets] باستخدام التجزئة في الخلفية، ما يمنح إدراجًا وبحثًا وحذفًا بمتوسط O(1).
وهي قابلة للتغيير في مكانها، ما يجعلها مثالية لنمط *مجموعة العناصر المزارة* في اجتيازات الرسوم البيانية.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| الكلمة | التأثير |
|--------|---------|
| `HS{ }` | قيمة حرفية لمجموعة تجزئة فارغة (مشتركة، لذا استخدم `clone`!) |
| `>hash-set` | `( seq -- set )`: ينشئ مجموعة جديدة من متتالية (يزيل التكرارات) |
| `adjoin` | `( elt set -- )`: إدراج مدمّر |
| `in?` | `( elt set -- ? )`: اختبار العضوية |
| `delete` | `( elt set -- )`: إزالة مدمّرة |
| `cardinality` | `( set -- n )`: عدد العناصر |
| `null?` | `( set -- ? )`: صحيح عندما تكون المجموعة فارغة |
| `members` | `( set -- seq )`: يسرد كمتتالية |
| `union` | `( set1 set2 -- set )` |
| `intersect` | `( set1 set2 -- set )` |
| `diff` | `( set1 set2 -- set )` |
| `set-like` | `( set exemplar -- set' )`: يحوّل `set` قسريًا إلى صنف `exemplar` |

لبناء مجموعة من بيانات لديك بالفعل، يحوّل `>hash-set` أي متتالية في خطوة واحدة، مع تجاهل التكرارات: `{ 2 3 2 5 } >hash-set` ينتج `HS{ 2 3 5 }`. وهو النظير الجملي لبناء مجموعة عبر `adjoin` المتكرر.

ملاحظة دقيقة حول `in?` مقابل `member?` (من `sequences`): كلاهما يختبر العضوية، لكن `member?` يجري مسحًا خطيًا على متتالية، بينما `in?` يوجّه الاستدعاء إلى طريقة البروتوكول الخاصة بنوع المجموعة، وبالنسبة إلى `HS{ }` يكون ذلك بحث تجزئة. استخدم `in?` عندما تحتوي حاوية "العناصر المزارة" لديك على أكثر من عدد قليل من العناصر.

`null?` يجيب عن سؤال "هل هذه المجموعة فارغة؟" دون حساب `cardinality` الكامل، وهو الحارس الطبيعي لسؤال "هل بقي لدينا شيء لمعالجته؟". أما قائمة العمل المحفوظة كمجموعة، فإن `[ set null? ]
[ … ] until` يفرغها حتى تصبح فارغة.

## يتكامل بشكل جميل مع جداول التجزئة

`HS{ }` للإجابة عن سؤال "هل تمت زيارة `X`؟" يتكامل طبيعيًا مع `H{ }` للإجابة عن سؤال "من هم جيران `X`؟". وهذا اجتياز بحث العمق أولًا (DFS) كتابي:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

مجموعة العناصر المزارة تزيل تكرار العمل؛ والمكدس يمرر عقد الحدود (LIFO، أخيرًا يدخل أولًا يخرج، عبر `push`/`pop`)؛ وخريطة الجيران (جدول تجزئة) توفّر الرسم البياني. لا يهم ترتيب الزيارة في سؤال قابلية الوصول، ولهذا يكفي استخدام متجه كالمكدس. أما بحث العرض أولًا (BFS) حقيقي على الشكل نفسه، فيستبدل المتجه بـ[`<dlist>`][dlist] ويستخرج من المقدمة بدلًا من ذلك.
