# نبذة

المعجم هو وحدة التنظيم في Factor: مجموعة مسمّاة من تعريفات الكلمات.

```factor
USING: kernel ;
IN: greetings.formal

: hello ( name -- str ) "Greetings, " prepend ;
```

## تخطيط الملفات والمجلدات

تستخدم أسماء المعاجم النقطة `.` كفاصل. ويتبع المسار هذه النقاط:

| المعجم             | الملف                                       |
| ---                    | ---                                        |
| `greetings`            | `greetings/greetings.factor`               |
| `greetings.formal`     | `greetings/formal/formal.factor`           |
| `greetings.casual`     | `greetings/casual/casual.factor`           |

يبحث محمّل Factor عن المعاجم عبر التنقل في *جذور المعاجم*، أي جذر المشروع والمكتبة الأساسية المضمّنة، حتى يجد مجلدًا يطابق اسمه كل مقطع من مقاطع المسار. ويتكرر المقطع الأخير كاسم للملف.

## `USING:` و`IN:`

يُدرج `USING:` (إلى جانب `USE:` لمعجم واحد في كل مرة) معاجم أخرى في مسار البحث الخاص بالملف الحالي. وتُعلن `IN:` المعجمَ الذي *تنتمي إليه* الكلمات المعرَّفة في هذا الملف، فأسماؤها المؤهلة بالكامل تبدأ بذلك البادئة.

```factor
USING: kernel sequences greetings.formal ;
IN: greetings

: greet-everyone ( names -- strs )
    [ hello ] map ;
```

هنا تنتمي `greet-everyone` إلى `greetings`، وتستدعي `hello` من `greetings.formal`، وتستدعي `map` من `sequences`.

## لماذا نقسّم الحل على عدة معاجم

تتيح لك تجزئة الكود على عدة معاجم ما يلي:

- تجميع الكلمات المساعدة الصغيرة حسب مسؤوليتها، بعيدًا عن الإجراء عالي المستوى الذي يركّبها.
- إعادة استخدام هذه الكلمات المساعدة من مواضع أخرى دون جرّ الإجراء الرئيسي معها.
- قراءة كل ملف كطبقة تجريد واحدة متماسكة.

محمّل Factor سريع وكسول بما يكفي ليكون التقسيم *نزولًا* إلى معاجم أصغر غير مكلف، والاصطلاح المتبع في المكتبة القياسية هو تجزئة الكود تجزئةً مكثّفة.
