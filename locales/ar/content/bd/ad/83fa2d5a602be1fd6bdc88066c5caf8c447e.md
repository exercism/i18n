# مقدمة

## عمر المورد

يستخدم [concept:csharp/resource-cleanup]() الواجهة `IDispose` للإشارة إلى أن موارد كائن ما أو غيره من حالات البرنامج كان لا بد من تحريرها أو إعادة ضبطها عندما لا يعود الكائن مطلوبًا (وأن الاعتماد على جامع القمامة لن يحقق ذلك أو يوفر مستوى التحكم المطلوب)، وأن طريقة `IDisposable.Dispose()` كانت المكان الطبيعي لمثل هذه العمليات.

وهناك تركيب آخر، وهو كتلة `using`، يتيح من منظور المستدعي جمع إدارة عمر الموارد كلها في عبارة واحدة.

```csharp
using (var file = new File("my_secrets"))
{
    file.WriteSecret("xxxxxxx");
}
```

في المثال أعلاه، ستُحرَّر موارد نظام الملفات المرتبطة بـ `file` وتُعاد إلى نظام التشغيل عند الخروج من كتلة `using`.

ولكي يعمل هذا النمط، يجب أن يكون المتغير في عبارة `using` من نوع مرجعي يُنفّذ الواجهة `IDisposable`، وأن يُحرّر الموارد أو يُعيد ضبط حالة البرنامج في طريقة `Dispose()`.

يقدّم C# 8 تحسينًا على هذا النمط، إذ يمكن وضع عبارة `using` في بداية الكتلة.

```csharp
using var drawingResource = some_provided_or_new_object;
try
{
    drawingResource.DrawSomething();
}
catch (Exception)
{
    throw;
}
```

قد يتعرف مطورو Java على هذا بوصفه نظيرًا لآلية _إدارة الموارد التلقائية_ التي قُدّمت في Java 7.
