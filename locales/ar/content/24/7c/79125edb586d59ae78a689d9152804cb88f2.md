# نبذة

**الفاصلة العائمة** عددٌ يمكن أن يكون له جزء كسري، مثل `-1.23` أو `3.1415`.

لتمثيل عدد كهذا على هيئة تسلسل من البايتات، تستخدم x86-64 معيار [IEEE-754][ieee]. وأكثر صيغتين شيوعًا في هذا المعيار هما أعداد الفاصلة العائمة أحادية الدقة وأعداد الفاصلة العائمة مزدوجة الدقة. وتدعم x86-64 كلتيهما.

عدد الفاصلة العائمة أحادي الدقة بعرض 32 بت، بينما مزدوج الدقة بعرض 64 بت.

~~~~exercism/note
بما أن أعداد الفاصلة العائمة تقريب لمجموعة الأعداد الحقيقية كاملة، فقد تعطي العمليات عليها نتائج غير دقيقة.

للحصول على شرح معمّق، يُرجى الرجوع إلى [الملحق D][guide] من دليل الحساب العددي من Oracle بعنوان «What Every Computer Scientist Should Know About Floating-Point Arithmetic».

وتقدّم [صفحة Float Toy][toy] شرحًا بيانيًا جميلًا لكيفية تحويل بِتّات عدد الفاصلة العائمة إلى قيمة فاصلة عائمة فعلية.

## سجلات XMM

في x86-64، هناك 16 سجلًا مخصّصًا لإجراء العمليات الحسابية على الفاصلة العائمة، تُسمّى `xmm0` حتى `xmm15`.

عرض هذه السجلات 128 بت على الأقل، لكن المعالجات الحديثة تزيده إلى 256 بت أو 512 بت. ومع ذلك، في الممارسة العملية، لا تستخدم معظم أعداد الفاصلة العائمة سوى أقل 32 بت أو 64 بت، حسب الدقة المطلوبة.

## التحويل بين الأعداد

هناك عائلة من التعليمات للتحويل بين صيغ الأعداد: `cvtxx2yy`.

كلا `xx` و`yy` ليسا قيمتين حرفيتين، بل عنصرين نائبين:

- `xx` عنصر نائب لنوع معامل المصدر.
- `yy` عنصر نائب لنوع معامل الوجهة.

ويمكن أن يأخذ هذا العنصر النائب أشكالًا عديدة، منها:

| العنصر النائب | المعنى                |
| ----------- | --------------------- |
| `si`        | عدد صحيح ذو إشارة     |
| `ss`        | فاصلة عائمة 32 بت     |
| `sd`        | فاصلة عائمة 64 بت     |

على سبيل المثال:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

لاحظ أنه يمكن تحويل عدد صحيح 32 بت إلى فاصلة عائمة 64 بت أو عدد صحيح 64 بت إلى فاصلة عائمة 32 بت. وبالمثل، يمكن أيضًا تحويل فاصلة عائمة 32 بت إلى عدد صحيح 64 بت أو فاصلة عائمة 64 بت إلى عدد صحيح 32 بت. وبعبارة أخرى، لا يلزم أن يكون حجم المعاملين في `cvtxx2yy` _متساويًا_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

عندما لا يمكن التعبير عن عدد الفاصلة العائمة بدقة على هيئة عدد صحيح، تُقرّب `cvtxx2si` العدد وفقًا للتحكم في التقريب في سجل خاص يُسمّى `mxcsr`. وقد يكون هذا التقريب إلى الأقرب، أو تقريبًا لأسفل، أو تقريبًا لأعلى، أو اقتطاعًا. ولا توجد قيمة افتراضية مضمونة عند دخول الدالة.

لاحظ أن النتيجة الدقيقة لا تُقرَّب، وبالتالي لا تتأثر بالتحكم في التقريب. على سبيل المثال، ستُحوَّل `42.0` _دائمًا_ إلى `42`.

وهناك عائلة مشابهة من التعليمات بالصيغة `cvttxx2si` (بحرف `t` إضافي) تقتطع النتيجة دائمًا.

## التقريب

تقوم عائلة التعليمات `roundxx` بتحويل قيمة فاصلة عائمة في معامل المصدر إلى قيمة فاصلة عائمة مقرّبة تُخزَّن في معامل الوجهة.

هنا، `xx` عنصر نائب لنوع المعاملات، كما اعتدنا: `ss` لأعداد الفاصلة العائمة أحادية الدقة و`sd` لمزدوجة الدقة.

تأخذ هذه التعليمات عددًا ثابتًا كمعامل ثالث. ويشير هذا العدد إلى نمط التقريب:

| العدد | النمط         |
| :----- | :----------- |
| 0      | الأقرب      |
| 1      | الأدنى (لأسفل) |
| 2      | الأعلى (لأعلى)    |
| 3      | الاقتطاع     |

على سبيل المثال:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

وبما أن هذه التعليمات تنتج نتيجة دقيقة، يمكن استخدامها استعدادًا لتعليمة `cvtxx2si`.

## تعليمات الحساب

تتخذ العديد من العمليات على أعداد الفاصلة العائمة تعليمات باسم مشابه لنظيرتها الخاصة بالأعداد الصحيحة، مع إضافة العنصر النائب اللازم (`ss` أو `sd`) في النهاية. وهذه التعليمات ثنائية المعاملات، بدلالتها المعتادة، حتى تلك التي تُجري الضرب أو القسمة:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## النقل

التعليمات المستخدمة للنقل من سجل XMM إلى آخر هي `movss` أو `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

**لا** يمكن نقل قيمة فورية (عدد صحيح ثابت ذو إشارة) إلى سجل xmm مباشرة. يحتاج هذا العدد أولًا إلى النقل إلى سجل عام الاستخدام ثم تحويله باستخدام `cvtsi2xx`:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## المقارنات

هناك مجموعتان من التعليمات لإجراء مقارنة بين عددين من أعداد الفاصلة العائمة. وهما بالصيغة `comixx` و`ucomixx`، حيث `xx` إما `ss` أو `sd`. وتضبط كلتاهما أعلامًا في `rflags` كما هو معتاد، وفقًا للدلالة نفسها التي يتبعها `cmp`.

والفرق بينهما أن `ucomixx` تضبط `parity flag (PF)` إذا كانت إحدى قيمتي الفاصلة العائمة تحمل القيمة `NaN`، في حين تُطلق `comixx` استثناءً في هذه الحالة.

تجري المقارنة بين قيم الفاصلة العائمة _بدون إشارة_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## تعليمات أخرى

هناك تعليمات أخرى كثيرة للتعامل مع أعداد الفاصلة العائمة وتنفيذ عمليات شائعة. ومنها:

| التعليمة | الوصف                                      |
| :---------- | :----------------------------------------------- |
| `sqrtxx`    | يحسب الجذر التربيعي (`sqrt(x)`)                 |
| `rcpss`     | يحسب المقلوب (`1/x`)                      |
| `rsqrtss`   | يحسب مقلوب الجذر التربيعي (`1/sqrt(x)`) |
| `minxx`     | يحسب الحد الأدنى (`min(x, y)`)                   |
| `maxxx`     | يحسب الحد الأعلى (`max(x, y)`)                   |

وحيثما استُخدم العنصر النائب `xx`، يمكن أن يأخذ صيغة `ss` أو `sd`، كما اعتدنا. غير أن `rcpss` و`rsqrtss` تعملان فقط مع أعداد الفاصلة العائمة أحادية الدقة.

وهذه التعليمات كلها ثنائية المعاملات.

## اصطلاح الاستدعاء

في System V ABI، تُمرَّر أول ثمانية وسائط للفاصلة العائمة إلى الدوال بالترتيب، من `xmm0` إلى `xmm7`. وتُرجَع قيم الفاصلة العائمة من الدوال في `xmm0`، وإذا لزم الأمر في `xmm1`.

جميع سجلات `xmm` متاحة للاستخدام بحرية، ولا شيء منها محجوز للمستدعي.

## الذاكرة

يمكن تعريف قيم الفاصلة العائمة في الذاكرة وفقًا للدلالة نفسها الخاصة بالأعداد الصحيحة بالحجم نفسه. كما يسمح NASM (The Netwide Assembler، المجمّع المستخدم في هذا المسار) بالإعلان عن قيم الفاصلة العائمة بالترميز العلمي.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```

## AVX/AVX2

تُدخل امتدادات AVX/AVX2 لمعمارية x86-64 صيغًا جديدة ثلاثية المعاملات لتعليمات الفاصلة العائمة، تفصل الوجهة عن المصادر. وتأخذ بادئة `v` (من _vector_) لتمييزها عن صيغة SSE القديمة التي رأيناها أعلاه:

```x86asm
vaddss xmm0, xmm1, xmm2 ; xmm0 = xmm1 + xmm2 (32-bit floating-point)
vmulsd xmm2, xmm3, xmm4 ; xmm2 = xmm3 * xmm4 (64-bit floating-point)
```

في هذا المسار، اقتصرنا على التعليمات والسجلات حتى امتدادات SSE السابقة. وهذا كافٍ لتعليم الأساسيات ويضمن التوافق مع طائفة واسعة من وحدات المعالجة المركزية.

غير أن مُشغّل الاختبارات يدعم AVX وAVX2 دعمًا كاملًا. ولك حرية استخدامهما.
