# الأصناف غير القابلة للتغيير

```sather
immutable class BEARING is
   readonly attr degrees : INT;
   create(d : INT) : SAME is
      b : SAME;
      return b.degrees(d);
   end;
end;
```

## ما الذي يتغيّر

| | صنف عادي | صنف غير قابل للتغيير |
| --- | --- | --- |
| الإسناد | يتشارك الكائن | ينسخ القيمة |
| يمكن أن يكون `void` | نعم | لا |
| كاتب `attr` | `x.a := v` | `x := x.a(v)` |
| `new` | نعم | لا؛ `x : SAME` موجود بالفعل |

لا يمكن أن يكون الكائن غير القابل للتغيير `void`، لذا تكون `void(b)` دائمًا خطأ، ولا يمكن لأي إجراء عليه أن يفشل لعدم وجود كائن. وهذا يزيل نوعًا كاملًا من الأخطاء، على حساب أنك لن تستطيع أبدًا أن تقول "لا يوجد اتجاه بعد".

## أين تُخزَّن القيمة

تُخزَّن القيمة في موضع المتغير نفسه، داخل كائن آخر أو على المكدس، بدلًا من الوصول إليها عبر مرجع. لذا تحمل `ARRAY{BEARING}` كائنات `BEARING` نفسها، لا مؤشرات إليها، ما يجعلها أصغر حجمًا وأسرع في المرور عليها.

والتكلفة هي النسخ: فتمرير كائن كبير غير قابل للتغيير ينسخه في كل مرة. لذا من الأفضل أن تبقى هذه الكائنات صغيرة.

## إجراءات السمة

يمنحك `readonly attr degrees : INT` إجراءين:

```sather
   b.degrees          -- read: INT
   b.degrees(90)      -- answer a new BEARING with degrees changed
```

الإجراء الثاني موجود حتى مع `readonly`، لأنه لا يغيّر شيئًا، بل يبني قيمة جديدة. وهو عام مع `attr` العادي، وليس كذلك مع `private attr`.

## إجراءا `is_eq` و `str`

لا يوفّر الصنف أيًّا منهما. اكتب `is_eq` من أجل `=`، و `str` حتى يمكن طباعة الكائن وضمّه إلى السلاسل النصية:

```sather
   is_eq(other : SAME) : BOOL is return degrees = other.degrees; end;
   str : STR is return degrees.str + " degrees"; end;
```

كتابة `str` تجعل الصنف يمتثل لـ `$STR`، وهذا ما يسمح لـ `+` و `#OUT` بقبوله.

## الأصناف المدمجة

الأصناف `INT` و `BOOL` و `CHAR` و `FLTD` و `TUP` كلها أصناف غير قابلة للتغيير. ولا شيء فيها مميز: فهي مكتوبة في المكتبة بلغة Sather بالطريقة نفسها، وتتصرّف على هذا النحو للأسباب المذكورة أعلاه.
