# حول

**الدوال العودية** هي دوال تستدعي نفسها.

يجب أن تحتوي _الدالة العودية_ على _حالة أساسية_ واحدة على الأقل و_حالة عودية_ واحدة على الأقل.

**الحالة الأساسية** تُرجع قيمة دون استدعاء الدالة مرة أخرى.
**الحالة العودية** تستدعي الدالة مرة أخرى، مع تعديل المدخل بحيث يطابق الحالة الأساسية في مرحلة ما.

إليك مثالًا يحصي عناصر مصفوفة.

```jq
def count:
  if length == 0 then
    0                       # base case
  else
    1 + (.[1:] | count)     # recursive case
  end;

([] | count),           # => 0
([11, 22, 33] | count)  # => 3
```

يمكن أن تحتوي _الدالة العودية_ على _حالات أساسية_ متعددة و/أو _حالات عودية_ متعددة.
على سبيل المثال، [متتالية فيبوناتشي][wiki-fibonacci] هي متتالية عودية ذات _حالتين أساسيتين_.

```jq
def fibonacci:
  if . == 0 then
    0
  elif . == 1 then
    1
  else
    (. - 1 | fibonacci) + (. - 2 | fibonacci)
  end;

10 | fibonacci          # => 55
```

يتضمّن عدّ عدد مرات ظهور قيمة معطاة `x` في مصفوفة _حالتين عوديتين_.

```jq
def count_occurrences(x):
  if length == 0 then
    0
  elif first == x then
    1 + (.[1:] | count_occurrences(x))
  else
    (.[1:] | count_occurrences(x))
  end;

[11, 22, 33, 22, 44] | count_occurrences(22)    # => 2
```

في الممارسة العملية، غالبًا ما يتم التكرار على المصفوفات وبُنى البيانات الأخرى القابلة للتعداد باستخدام دوال مدمجة، مثل `map` و `reduce`، أو [باستخدام التدفقات][map-implementation] مثل `[.[] | select(...)]`.
خلف الكواليس، بعض الدوال المدمجة [مُنفَّذة باستخدام العَودية][walk-implementation].

## العَودية اللانهائية

قد لا تُرجع الدوال العودية نتيجتها أبدًا إذا نُفِّذت بشكل غير صحيح.
قد يمثل هذا مشكلة لأن كل مرة تُستدعى فيها دالة، يُخزَّن مرجع في الذاكرة حيث ينبغي أن تُرجع الآلة الافتراضية النتيجة (على [مكدس الاستدعاءات][wiki-call-stack]).
إذا استدعت دالة عودية نفسها بلا نهاية، فمن الممكن أن تنفد الذاكرة، مما يؤدي إلى تعطل الآلة الافتراضية بسبب [خطأ تجاوز سعة المكدس][wiki-stack-overflow].

قد تنتج مشكلة العَودية اللانهائية هذه عن:

- نسيان تنفيذ حالة أساسية.
- عدم تعريف الحالة الأساسية كأول شرط.
- عدم تعديل الوسيط بشكل صحيح عند إجراء الاستدعاء العودي، وبالتالي عدم الوصول إلى الحالة الأساسية أبدًا.

## تحسين الاستدعاء الذيلي

كما هو [موضح في ويكيبيديا][wiki-tail-call]:

> الاستدعاء الذيلي هو استدعاء روتين فرعي يتم كإجراء أخير في إجراء.
> إذا كان هدف الاستدعاء الذيلي هو الروتين الفرعي نفسه، فيقال إن الروتين الفرعي عودي ذيلي.

لنتأمل تنفيذ `fibonacci` الوارد أعلاه.
تستدعي الحالة العودية نفسها مرتين.
الإجراء الأخير الذي تحتاج الدالة إلى تنفيذه هو الجمع.
ولأن الإجراء الأخير ليس استدعاءً لنفسها، فإن تلك الدالة عودية، لكنها ليست عودية ذيلية.

تُطبّق بعض اللغات _تحسين الاستدعاء الذيلي_، بحيث يمكن للاستدعاء الذيلي إعادة استخدام إطار المكدس الحالي بدلًا من إضافة إطار جديد إلى [مكدس الاستدعاءات][wiki-call-stack].
قد يحقق ذلك فوائد في الأداء إضافة إلى الحماية من [تجاوز سعة المكدس][wiki-stack-overflow] المخيف.

تُطبّق `jq` تحسين الاستدعاء الذيلي، _لكن فقط للدوال التي لا تستقبل وسائط_.
طريقة الاستفادة من ذلك هي تعريف دالة «داخلية» لا تستقبل وسائط، تأخذ نوعًا ما من الحالة كمدخل.
يمكن للدالة الداخلية تعديل الحالة حسب الحاجة، وتمرير الحالة الجديدة إلى الاستدعاء العودي الذيلي.
تنشئ الدالة الخارجية الحالة الأولية وتمررها إلى الدالة الداخلية لبدء العَودية.

يمكن تنفيذ دالة `fibonacci` عودية ذيلية بالاحتفاظ بالمتسلسلة المحسوبة حتى الآن كجزء من الحالة.

```jq
def fibonacci:
  def _fib:
    # input: {limit: number, series: array}
    if (.series | length - 1) >= .limit then
      .series[.limit]                                   # base case
    else
      .series += [.series[-1] + .series[-2]] | _fib     # recursive case
    end;
  {limit: ., series: [0, 1]} | _fib;

10 | fibonacci          # => 55
```
