# مقدمة

تحتوي JavaScript على كائن مدمج هو `Date` يخزّن التاريخ والوقت، ويوفر طرقًا لإدارتهما.

<!-- prettier-ignore -->
~~~exercism/caution
كان مبنيًا على صنف `java.util.Date` في Java، وقد استُبدل في أوائل عقد 2010، لكن كائن `Date` في JavaScript ما زال باقيًا من أجل التوافق مع الإصدارات السابقة.

ونظرًا لصعوبة التعامل مع كائنات التاريخ عمومًا، وسوء معالجة المناطق الزمنية أو غيابها، توجد مكتبات كثيرة مثل `moment.js` و`day.js` و`date-fns` و`luxon`.
لا تتوفر أي من هذه المكتبات على Exercism.

في مشاريعك الخاصة، لا تستخدم حزمة مهملة أو غير مُصانة مثل `moment.js`، بل اعتمد على بدائل أحدث مثل `luxon`، أو على [Temporal][mdn-temporal] الذي لم ينتشر بعد على نطاق واسع.
يركّز هذا التمرين على `Date`، الذي سيظل ذا صلة حتى نهاية JavaScript.

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal
~~~

## الإنشاء

كائن `Date` هو نسخة من صنف `Date`.
يمكن إنشاؤه دون تمرير أي وسائط إلى دالة الإنشاء.
ينتج عن ذلك كائن `Date` يمثّل التاريخ والوقت الحاليين:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### الطابع الزمني Unix (عدد)

إذا مُرِّر عدد، فسيُفسَّر على أنه `timestamp`.
الطابع الزمني عدد صحيح يمثّل عدد **المللي ثانية** التي مضت منذ **1 يناير 1970 [UTC][defn-utc]+0**.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

قد يتوقع المرء أن `new Date(0)` يولّد كائن التاريخ «الأبكر»، لكن JavaScript ستحوّل التاريخ إلى منطقتك الزمنية المحلية، ما يعني أن من هم في منطقة [GMT / بتوقيت UTC+0][defn-gmt] فقط سيحصلون فعليًا على قيمة [حقبة Unix][defn-unix-epoch].

### الطابع الزمني ISO 8601 (سلسلة نصية)

يمكنك تمرير قيمة سلسلة نصية تمثّل تاريخًا إلى دالة إنشاء `Date`.
التنسيق **الوحيد** المتناسق عبر كل التطبيقات هو [النسخة المبسّطة][mdn-date-string-format] مما يُعرف دوليًا ويُعتمد معيارًا باسم [سلاسل الطوابع الزمنية بصيغة ISO 8601][defn-iso8601].

تبدو لحظة زمنية بتوقيت [UTC][defn-gmt] هكذا:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

حيث تجري الاستبدالات التالية:

| المفتاح | الوصف                                   | الافتراضي |
| ---- | --------------------------------------------- | ------- |
| YYYY | السنة الميلادية، ممثّلة بأربعة أرقام    |         |
| MM   | الشهر الميلادي، ممثّل برقمين   | 01      |
| DD   | اليوم الميلادي، ممثّل برقمين     | 01      |
| T    | حرف T حرفي، يفصل التاريخ عن الوقت |         |
| HH   | الساعات بنظام 24 ساعة، رقمان        | 00      |
| mm   | الدقائق، رقمان                         | 00      |
| ss   | الثواني، رقمان                         | 00      |
| mss  | المللي ثانية، ثلاثة أرقام                    | 000     |
| Z    | حرف Z حرفي، أو إزاحة `+/-HH:mm`   |         |

الحرف الحرفي `Z` يشير إلى UTC (بدون منطقة زمنية، وبدون توقيت صيفي).

ولأن معظم المكوّنات لها قيم افتراضية، فإن حذف أجزاء من النهاية صحيح:

```text
YYYY-MM-DD
```

القيمة الافتراضية وقت 00:00:00.000

إذا لم ينتهِ الطابع الزمني بـ `Z`، ولم ينتهِ بـ `+HH:mm` أو `-HH:mm` (مما يشير إلى إزاحة المنطقة الزمنية)، فبسبب أسباب تاريخية ينطبق ما يلي:

> عند غياب إزاحة المنطقة الزمنية، تُفسَّر الصيغ التي تحمل تاريخًا فقط على أنها بتوقيت UTC، أما الصيغ التي تحمل تاريخًا ووقتًا فتُفسَّر على أنها بالتوقيت المحلي.
> ويعود تفسيرها على أنها بتوقيت UTC إلى خطأ تاريخي في المواصفة لم يكن متوافقًا مع ISO 8601، لكن تعذّر تغييره بسبب التوافق مع الويب.
> انظر [Broken Parser – A Web Reality Issue][ref-broken-parser].

### كائن `Date`

يمكن أيضًا استخدام كائن تاريخ موجود كوسيط لدالة الإنشاء.
يؤدي هذا إلى إنشاء نسخة من كائن `Date` الموجود بالتاريخ والوقت نفسيهما.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### تمرير قيم مكوّنات التاريخ والوقت منفردة

يمكن إنشاء كائن `Date` يمثّل تاريخًا بتمرير ثلاثة أعداد.
ويمكن إنشاء كائن `Date` يمثّل تاريخًا ووقتًا بتمرير ستة أعداد.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

القيمة الثانية هي `month`، وتبدأ من `0` لشهر يناير حتى `11` لشهر ديسمبر.

## `Date.parse()`

قد تجد إشارات إلى دالة تحليل التاريخ `Date.parse`.
ولأن لهذه الدالة ثوابت قليلة فقط، ولأن بقية التنفيذ غير محدد (وبالتالي غير قياسي)، فلا ينبغي استخدامها.

## الوصول إلى مكوّنات `Date`

هناك طرق متنوعة على كائنات التاريخ تُرجع مكوّنات التاريخ:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

ولكل واحدة من هذه الطرق نظير `set` (مثل `setFullYear`) لتحديث القيمة.
أي قيمة تتجاوز الحد تنتقل إلى المكوّن التالي:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

وهناك صيغ UTC لكل الطرق التي تتجاهل المنطقة الزمنية المحلية.

## التحويل من التاريخ

لدى كائنات التاريخ طريقة `getTime()` تُرجع الطابع الزمني في Unix بالمللي ثانية، أي عدد المللي ثانية منذ منتصف ليل 1 يناير 1970 بتوقيت UTC.
إضافة إلى ذلك، تتوفر طريقة `toISOString()` للتحويل من كائن تاريخ إلى طابع زمني ISO 8601 على شكل سلسلة نصية.

## مقارنة التواريخ

يمكن استخدام أكبر من (`>`) وأكبر من أو يساوي (`>=`) وكذلك أصغر من (`<`) وأصغر من أو يساوي (`<=`) مباشرة بين تاريخين أو بين تاريخ وعدد.
ينجح هذا لأن JavaScript ستحاول تحويل التاريخ إلى قيمة أولية.
