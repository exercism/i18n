# العقود

تعبّر وسائط الروتين ونوع الإرجاع عن *نوع* ما يدخل وما يخرج. لكنها لا تستطيع أن تقول إن كان الوزن يجب أن يكون موجبًا، ولا أن أداة الاختبار لا تُبلّغ أبدًا عن سعة احتياطية أكبر من التي تملكها.

أما **العقد** فيقول هذه الأشياء في ترويسة الروتين نفسها، حيث يراها كل من يقرأه.

## pre

تحدّد `pre` ما يجب أن يكون صحيحًا عند استدعاء الروتين. وهي توضع بين نوع الإرجاع و`is`.

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

هذا مطلب على **المستدعي**: لا تستدعِ هذا بحمل سالب.

## post

تحدّد `post` ما سيكون صحيحًا عندما يُرجع الروتين. وبداخلها، `result` هي القيمة المُرجَعة.

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

هذا وعد للمستدعي. والروتين الذي يحمل الاثنين معًا صفقة: أعطني هذا، وسأعطيك ذاك.

تُجمع عدة شروط باستخدام `and`، تمامًا كما تفعل أي قيم منطقية:

```sather
      pre load >= 0 and load <= limit
```

## العقود ليست استثناءات

الاستثناء الذي يُطلق مخصّص لأمر يمكن أن يحدث. أما العقد المنقوض فيعني وجود **Bug**: فقد استدعى أحدهم الروتين على نحو خاطئ، أو أن الروتين لم يفعل ما قال إنه سيفعله.

لذلك، فإن العقد المنقوض لا يُطلق شيئًا يمكن التقاطه. وعند تشغيل فحص العقود، يتوقف البرنامج ويطبع اسم الروتين واسم الشرط المعني. وعند إيقافه، لا يُختبر الشرط أصلًا، ويمضي البرنامج قُدمًا نحو أي عبث ينتظره بعد ذلك.

ولهذا فإن العقد قضية عن الصحة وليس طريقة للتعامل مع مدخلات سيئة. فإن كانت المدخلات السيئة متوقعة، فافحصها ثم استخدم `raise`. وإن كانت المدخلات السيئة تعني أن المستدعي مخطئ، فصرّح بذلك باستخدام `pre`.

## تشغيل التحقق

يفحص Sather العقود عندما يُعطى المُصرِّف `-chk`:

```
sacomp -chk mine.sa -main MAIN -o mine
```

بدونه، ليس `pre` و`post` سوى توثيق قرأه المُصرِّف وأقرّ بأنه سليم الصياغة، لا أكثر. إن اختبارات هذا التمرين تُبنى بدون `-chk`، لذا لا يمكنها أن تكشف لك عقدًا منقوضًا؛ وإنما تتحقق من أن الروتينات تفعل الشيء الصحيح عند استخدامها على النحو الصحيح.
