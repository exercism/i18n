# مقدمة

خيوط Factor هي *روتينات تعاونية*: فهي تتشارك خيط نظام تشغيل واحد، وتتناوب تسليم التحكم لبعضها عند عمليات الإدخال/الإخراج وعند نقاط تسليم التنفيذ الصريحة، ولا تعمل في الوقت نفسه حقًا. وأي شيء تفعله *بين* عمليات التسليم يحدث كخطوة واحدة لا تنقطع. لكن إذا سلّمت عملية مركّبة (قراءة-تعديل-كتابة) التحكم في منتصفها، فقد يتسلل خيط آخر ويغيّر الوضع قبل أن تنتهي، وهذه حالة تسابق.

يغطي هذا التمرين أربع لبنات أساسية تتكرر مرارًا:

## `parallel-map`: التفرّع والدمج على متتالية

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

في [`concurrency.combinators`][combinators]. تُنشئ خيطًا لكل عنصر، وتشغّل الاقتباس، ثم تجمع النتائج في متتالية جديدة بالترتيب نفسه:

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`: بدء خيط

```
spawn ( quot name -- thread )
```

في [`threads`][threads]. يعمل الاقتباس على نحو متزامن، و`name` اسم للاستعانة به في تصحيح الأخطاء. ولا أهمية تُذكر لمقبض الخيط المُرجَع في هذا المستوى، فتجاهله باستخدام `drop`.

## الوعود: تسليم قيمة لمرة واحدة

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

في [`concurrency.promises`][promises]. الوعد صندوق بريد لمرة واحدة: خيط واحد يفي به، وخيوط أخرى تقرأ منه. وتوقف `?promise` التنفيذ حتى يُوفى بالوعد، ثم تُرجع القيمة.

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

`spawn` مع `<promise>` هو ما بُنيت عليه `parallel-map`، وتنفيذهما يدويًا مفيد عندما تؤدي كل مهمة شيئًا آخر غير «حساب عنصر واحد».

والشكل النمطي للتفرّع/الدمج على متتالية هو: أنشئ وعدًا جديدًا لكل مدخل، وأنشئ خيطًا يؤدي العمل ويستوفي الوعد بـ `fulfill`، ثم اجمع كل وعد في متتالية، واستدعِ `?promise` على كل منها لتنتظر اكتماله. وتجعل المتغيرات المحلية هذا مقروءًا: اربط الوعد باسم باستخدام `:>` داخل تعبير لامدا `[| | ]`، حتى يتمكن الاقتباس المُشغَّل من الوصول إليه:

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## الأقفال: الاستبعاد المتبادل

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

في [`concurrency.locks`][locks]. لا يمكن لأكثر من خيط واحد أن يمسك قفلًا معينًا في الوقت نفسه. وتستحوذ `with-lock` على القفل، وتشغّل الاقتباس، ثم تحرّره، حتى لو رفع الاقتباس استثناءً.

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

استخدم قفلًا كلما كانت قيمة *تُقرأ أو تُكتب من أكثر من خيط* ولم تكن العمليات عليها ذرّية بطبيعتها. وتحتاج القراءة والكتابة معًا إلى القفل: فالقراءة التي تسلّم التحكم في منتصفها قد ترى حالة ممزقة.
