# مقدمة

## الواجهة كمجموعة من الطرق

في أبسط صوره، **نوع الواجهة** هو مجموعة من توقيعات الطرق.
إليك مثالًا على تعريف واجهة يتضمن طريقتين هما `Add` و `Value`:

```go
type Counter interface {
    Add(increment int)
    Value() int
}
```

يمكن حذف أسماء المعاملات مثل `increment` من تعريف الواجهة، لكنها غالبًا ما تزيد من قابلية القراءة.

لا تحتوي أسماء الواجهات في Go على الكلمة `Interface` أو `I`.
بل غالبًا ما تنتهي بـ `er`، مثل `Reader` و `Stringer`.

## تطبيق واجهة

أي نوع يعرّف طرق الواجهة فهو يُطبّق الواجهة تلقائيًا وضمنيًا.
لا توجد كلمة مفتاحية `implements` في Go.

النوع التالي يُطبّق واجهة `Counter` التي رأيناها أعلاه.

```go
type Stats struct {
    value int
    // ...
}

func (s Stats) Add(v int) {
    s.value += v
}

func (s Stats) Value() int {
    return s.value
}

func (s Stats) SomeOtherMethod() {
    // The type can have additional methods not mentioned in the interface.
}
```

لا يهم، عند تطبيق الواجهة، ما إذا كانت الطريقة تملك مستقبل قيمة أو مستقبل مؤشر.
(راجع [مفاهيم الطرق][concept-methods] إن لم تكن متأكدًا منها.)

> يمكن لقيمة من نوع الواجهة أن تحمل أي قيمة تُطبّق تلك الطرق. ((Go Tour: Interfaces)[go-tour-interfaces])

وهذا يعني أنه يمكن الآن استخدام `Stats` في كل المواضع التي تتوقع واجهة `Counter`.

```go
func SetUpAnalytics(counter Counter) {
    // ...
}

stats := Stats{}
SetUpAnalytics(stats)
// works because Stats implements Counter
```

لأن الواجهات تُطبّق ضمنيًا، يمكن للنوع بسهولة أن يُطبّق واجهات متعددة.
كل ما يحتاجه هو أن يعرّف جميع الطرق اللازمة.

## الواجهة الفارغة

توجد في Go واجهة خاصة جدًا، هي **الواجهة الفارغة** التي لا تحتوي على أي طرق.
تُكتب الواجهة الفارغة هكذا: `interface{}`.
في Go 1.18 أو أحدث، يمكن استخدام `any` أيضًا.
وقد عُرّف كاسم مستعار.

ولأن الواجهة الفارغة لا تحتوي على طرق، فإن كل نوع يُطبّقها ضمنيًا.
وهذا مفيد لتعريف دالة يمكنها قبول أي قيمة بشكل عام.
في هذه الحالة، يستخدم معامل الدالة نوع الواجهة الفارغة.
