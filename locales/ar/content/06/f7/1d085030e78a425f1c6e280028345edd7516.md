# مقدمة إلى إعادة التوجيه

في عالم واجهة سطر الأوامر، كثيرًا ما تتفاعل البرامج مع ثلاثة تدفقات بيانات قياسية:

1. **الإدخال القياسي** (`stdin`): حيث يستقبل البرنامج مدخلاته (عادةً من لوحة المفاتيح).
1. **الإخراج القياسي** (`stdout`): حيث يرسل البرنامج مخرجاته العادية (عادةً إلى شاشة الطرفية).
1. **الخطأ القياسي** (`stderr`): حيث يرسل البرنامج رسائل الخطأ (عادةً إلى شاشة الطرفية).

تذكّر أننا قدّمنا هذه التدفقات في فصل [خطوط الأنابيب وقوائم الأوامر][pipelines].

~~~~exercism/note
يمكن اعتبار خطوط الأنابيب شكلًا من أشكال إعادة التوجيه: يُرسَل الإخراج القياسي من برنامج مباشرةً إلى الإدخال القياسي لبرنامج آخر.
لقد غطّينا خطوط الأنابيب بالفعل.
سيتناول هذا المفهوم إعادة التوجيه من الملفات وإليها.
~~~~

إعادة التوجيه في الصدفة آلية قوية تتيح لك تغيير وجهة هذه التدفقات.
فبدلًا من أن يقرأ البرنامج من لوحة المفاتيح أو يكتب إلى الشاشة، يمكنك إعادة توجيه الإدخال من ملف أو إرسال الإخراج إلى ملف.
وهذا يمنحك مرونة وتحكّمًا كبيرين في كيفية تفاعل البرامج مع البيانات.

## عوامل إعادة التوجيه الرئيسية

إليك أكثر عوامل إعادة التوجيه شيوعًا وما تفعله:

### `>` (إعادة توجيه الإخراج)

* الغرض: إعادة توجيه الإخراج القياسي (`stdout`) لأمر إلى ملف.
* السلوك:
  * إذا لم يكن الملف موجودًا، يُنشأ.
  * إذا كان الملف موجودًا، يُستبدل محتواه.
* مثال:

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
تُنفَّذ إعادة التوجيه **قبل** تنفيذ الأمر.
وهذا يعني أنك لا تستطيع إعادة التوجيه إلى الملف نفسه الذي تحتاج إلى القراءة منه.

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

في الأمر الثاني من المثال أعلاه،

1. يقتطع Bash أولًا الملف المذكور في إعادة التوجيه.
   وهذا يدمّر المحتوى السابق، تاركًا ملفًا فارغًا.
2. ثم يقرأ Bash الملف الفارغ حديثًا.
3. ثم يكتب Bash المحتوى (أي لا شيء) عائدًا إلى الملف.
~~~~

### `>>` (إعادة توجيه الإخراج بالإضافة)

* الغرض: إلحاق الإخراج القياسي (`stdout`) لأمر ما بملف.
* السلوك:
  * إذا لم يكن الملف موجودًا، يُنشأ.
  * إذا كان الملف موجودًا، يُضاف الإخراج إلى نهاية الملف.
* مثال:

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<` (إعادة توجيه الإدخال)

* الغرض: إعادة توجيه الإدخال القياسي (`stdin`) لأمر من ملف.
* السلوك: يقرأ الأمر مدخلاته من الملف المحدَّد بدلًا من لوحة المفاتيح.
* مثال:

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>` (إعادة توجيه الخطأ):

* الغرض: إعادة توجيه الخطأ القياسي (`stderr`) لأمر إلى ملف.
* السلوك: تُرسَل رسائل الخطأ إلى الملف المحدَّد بدلًا من الطرفية.
* مثال:
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

يمكنك _إلحاق_ الخطأ القياسي بملف باستخدام `2>>`.

### عمليات إعادة توجيه إضافية

هناك أيضًا عمليات إعادة توجيه يمكنها دمج كلٍّ من `stdin` و`stderr`.
راجع [الدليل][manual] للتفاصيل.

## `/dev/null`

`/dev/null` ملف خاص:

* يكون ملفًا فارغًا عندما تقرأ منه، و
* يتجاهل كل البيانات المكتوبة إليه.

يُشار إليه أحيانًا باسم "the bitbucket".
وهو مفيد لكتم الإخراج أو الأخطاء.

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## دمج عمليات إعادة التوجيه

يمكن إعطاء عدة عمليات إعادة توجيه في الوقت نفسه.

```bash
some_command < input.txt > output.txt 2> error.txt
```

يمكن نسخ إعادة توجيه.

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

عندما ترى `2>&1`، اقرأها كأنها تعني "أعِد توجيه `stderr` إلى _حيثما يشير `stdout` **حاليًا**_".
يعالج Bash تعليمات إعادة التوجيه من اليسار إلى اليمين بدقة، ما يعني أنك تستطيع القيام بما يلي:

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## واصفات الملفات

في سياق برمجة الصدفة وأنظمة التشغيل مثل Linux/Unix، واصف الملف (FD) هو عدد صحيح غير سالب يعمل كمعرّف أو مقبض لملف مفتوح أو مورد إدخال/إخراج (Input/Output).
تخيّله مثل ملصق أو رقم مرجعي يستخدمه نظام التشغيل لتتبّع الملفات المفتوحة وتدفقات البيانات.

الأرقام التي تراها على الجانب الأيسر من عمليات إعادة التوجيه هي واصفات ملفات.

تُمنح تدفقات الإدخال/الإخراج القياسية أول 3 واصفات ملفات:

* الإدخال القياسي هو واصف الملف 0
* الإخراج القياسي هو واصف الملف 1
* الخطأ القياسي هو واصف الملف 2

يمكن تعيين واصفات ملفات جديدة أو إنشاؤها باستخدام أمر `exec` وعوامل إعادة التوجيه.

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

تبدو هذه التقنية معقّدة نوعًا ما، لكنها قد تكون مفيدة جدًا في الحالات التي يُشغَّل فيها سكربتك عبر حزمة برمجيات أخرى، فيلتقط البرنامج الإخراج القياسي تلقائيًا.
يعمل أمر `bats` المستخدم لتشغيل اختبارات الوحدة لهذا المسار بهذه الطريقة: يلتقط `bats` الإخراج القياسي والخطأ القياسي للاختبار، لكن رسائل التنقيح المرسلة إلى واصف الملف 3 ستُعرض على الطرفية.
~~~~

## الخلاصة

لماذا إعادة التوجيه مفيدة؟

* حفظ الإخراج: خزّن نتائج الأمر لمراجعتها أو معالجتها لاحقًا.
* التسجيل: التقط رسائل الخطأ لأغراض التنقيح.
* الأتمتة: اربط الأوامر ببعضها، باستخدام إخراج أحدها كإدخال لآخر.
* التصفية: تخلّص من الإخراج غير المرغوب فيه.
* المعالجة بالدفعات: عالج البيانات من الملفات بدلًا من كتابتها يدويًا.
* كتابة السكربتات: تعدّ عمليات إعادة التوجيه ضرورية لكتابة سكربتات صدفة متينة.

تمنحك عمليات إعادة التوجيه في الصدفة تحكّمًا دقيقًا في كيفية تفاعل البرامج مع البيانات، ما يتيح لك بناء سير عمل معقّد وإدارة المعلومات بفعالية.
