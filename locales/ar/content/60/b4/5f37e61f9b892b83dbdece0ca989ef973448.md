# مقدمة

[الأنواع المخصصة][custom-types] في Elm تمثل عددًا ثابتًا من الحالات المسمّاة. كل قيمة تقابل واحدة فقط من الحالات المسمّاة.

يُعرَّف النوع المخصص باستخدام الكلمة المفتاحية `type` ويتطلب قواعد كتابة قليلة جدًا. وهي من أهم التقنيات في برمجة Elm، وتُستخدم لجعل القيم الممكنة في الكود تطابق تمامًا القيم الصالحة في الحياة الواقعية، مما لا يترك مجالًا لبيانات غير صالحة، ويجعل [الحالات المستحيلة مستحيلة التمثيل في الكود][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

يمكن أن ترتبط بكل حالة من حالات النوع المخصص بيانات اختياريًا، ويمكن أن تختلف أنواع البيانات من حالة إلى أخرى. إذا لم تكن لأي من الحالات بيانات مرتبطة بها، فإن الاتحاد المميز يشبه ما تشير إليه اللغات الأخرى عادةً باسم _التعداد_ (أو _enum_).

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

يمكن إنشاء قيمة لحالة محددة بالإشارة إلى اسمها (`Spring`)، عندما تكون معرّفة في نفس الوحدة، أو يتم استيرادها باستخدام صيغة `import SeasonModule exposing (Season(..))`، أو بالإشارة إلى اسمها المؤهل بالكامل (`Season.Spring`) عندما يتم استيرادها باستخدام صيغة `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

تتمتع الأنواع المخصصة، مثل كل شيء في Elm، بـ _التساوي البنيوي_، مما يعني أن قيمتين لنفس الحالة وبنفس البيانات (الاختيارية) متكافئتان.

الطريقة المفضلة للتعامل مع الأنواع المخصصة هي [مطابقة الأنماط][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
