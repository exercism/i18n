# مقدمة

يتكوّن نظام الأخطاء في Factor من ثلاثة أجزاء: `throw` للإشارة إلى خطأ، و`recover` لمعالجة خطأ، و`ERROR:` لتعريف نوعك الخاص من الأخطاء.

## `throw`

`throw` (في [`kernel`][kernel]) ترفع خطأ. يمكن أن يكون الوسيط *أي* قيمة: سلسلة نصية، أو عدد، أو صف، ويصبح هو الخطأ الذي يمكنك فحصه لاحقًا:

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw` لا تُرجع؛ ويتم تخطي بقية الكلمة الحالية.

## `recover`

`recover` (في [`continuations`][continuations]) هي آلية المحاولة والالتقاط في Factor. تأخذ كتلة *try* وكتلة *recovery*:

```
recover ( try recovery -- )
```

إذا انتهت `try` دون أن ترفع خطأ، يتم تجاهل `recovery`. وإذا رفعت `try` خطأ، يُدفع الخطأ إلى المكدس ويتم تشغيل `recovery`:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

`when` من [`kernel`][kernel] هي الرفيق الطبيعي: فهي تشغّل كتلة فقط عندما تكون قمة المكدس صحيحة منطقيًا:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:` تُعرّف صنفًا من نوع الصف *و* كلمة تُنشئ نسخة جديدة وترفعها:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

الخطأ بلا خانة ليس إلا `ERROR: name ;`؛ فاستدعاء `name` يرفع نسخة فارغة. الصفوف المعرّفة باستخدام `ERROR:` تحمل محمول الصنف `name?` يمكنك استخدامه لاختبار ما إذا كان الخطأ الملتقط من ذلك النوع.

## قراءة الخانات مرة أخرى

الخطأ الملتقط ليس إلا صفًا، لذا تأتي كل خانة من خانات `ERROR:` مع القارئ `slot>>` المولّد تلقائيًا نفسه الذي يأتي مع أي صف آخر.

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
