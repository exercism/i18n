# مقدمة

كل برنامج مكتوب بـ Factor تقريبًا هو تسلسل من الكلمات يستهلك قيمًا وينتجها على *مكدس البيانات*. وعندما تتناسق المدخلات والمخرجات بدقة، يُقرأ الكود من اليسار إلى اليمين من دون أي عناء. وعندما لا تتناسق، تلجأ إلى *كلمات إعادة الترتيب*، فيصبح الكود فوضويًا بسرعة.

يأخذك هذا التمرين في جولة عبر الحل المعتاد في Factor، ألا وهو المُركِّبات.

## كلمات إعادة الترتيب

توجد كلمات إعادة الترتيب الأكثر شيوعًا في [`kernel`][kernel]:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

لا بد أنك استخدمت `dup` و`swap` من قبل. تُنشئ `over` نسخة من العنصر *الثاني* من القمة، وهو أمر مفيد عندما يحتاج المدخل نفسه إلى تغذية عمليتين حسابيتين:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

هذا جيد لاستخدام واحد. لكن عند ربطها معًا، تصبح تسلسلات `dup` و`swap` و`over` و`rot` غير مقروءة بسرعة.

## `keep`، الحفاظ على المدخل

تستدعي الكلمة `keep` (في [`kernel`][kernel]) اقتباسًا على قمة المكدس، لكنها تترك القيمة الأصلية فوق النتيجة:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

يستبدل هذا نمطًا يتكوّن من `dup` يتبعه شيء ما ثم عملية إعادة ترتيب: في أي مكان كنت ستكتب فيه `dup something swap`، يمكنك ببساطة أن تكتب `[ something ] keep`.

## `bi`، دالتان لمدخل واحد

تطبّق الكلمة `bi` (في [`kernel`][kernel]) *اقتباسين* على القيمة نفسها، وتترك النتيجتين معًا على المكدس:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

من دون `bi` كنت ستكتب `dup sq swap neg`، وهو مقروء بما يكفي لعمليتين، لكنه شائك مع ثلاث.

## `tri` و`cleave`، دوال كثيرة لمدخل واحد

توسّع الكلمة `tri` الكلمة `bi` لتشمل ثلاثة اقتباسات:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

والكلمة `cleave` (في [`combinators`][combinators]) هي الفكرة نفسها، لكن من أجل *مصفوفة* من أي عدد من الاقتباسات:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

يؤدي الاقتباس الفارغ `[ ]` دور عنصر الهوية، وهو مفيد عندما يتعيّن أن يكون أحد المواضع في البطاقة المقطوعة هو المدخل نفسه.

## `dip` و`2dip`، العمل تحت القمة

تستدعي الكلمة `dip` (في [`kernel`][kernel]) اقتباسًا على القيم الواقعة *تحت* قمة المكدس، وتترك القمة دون مساس. وتفعل الكلمة `2dip` الشيء نفسه، لكنها تحمي القيمتين *العلويتين*:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

هنا أخفت `dip` القيمة `11`، ثم نفّذت `9 10 +`، وأعادت `11` إلى القمة. وأخفت `2dip` القيمتين `11 12`، ثم نفّذت `9 10 +` تحتهما، وأعادت بعدها `11 12`.

تُعدّ `dip` الأداة المناسبة عندما يترك ترتيب الوسائط الطبيعي قيمة «المرور» على قمة المكدس، فاستخدمها بدلًا من شطيرة `swap … swap`.

## `bi@`، العملية نفسها على قيمتين

تطبّق الكلمة `bi@` (في [`kernel`][kernel]) اقتباسًا واحدًا على قيمتين من المكدس:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*`، عمليتان مختلفتان على قيمتين

تطبّق الكلمة `bi*` (في [`kernel`][kernel]) *اقتباسين مختلفين* على قيمتي المكدس: الاقتباس الأول على القيمة الأدنى، والثاني على القمة:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

استخدم `bi@` عندما تخضع القيمتان للمعالجة نفسها، و`bi*` عندما تحتاج كل واحدة إلى معالجة خاصة بها.

## `tri*`، عمليات مختلفة على ثلاث قيم

توسّع الكلمة `tri*` (في [`combinators`][combinators]) الكلمة `bi*` لتشمل ثلاث قيم وثلاثة اقتباسات، بحيث تطبّق كل اقتباس على قيمة واحدة بالترتيب:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
