# استثناء

في العالم المثالي، يعمل كل شيء على نحو مثالي.
لكن في العالم الحقيقي، قد تسوء الأمور، وطريقة تعاملنا مع هذه المواقف مهمة لضمان أن تكون برمجياتنا متينة وموثوقة.
الاستثناءات مفهوم بالغ الأهمية في البرمجة، فهو يسمح لنا بالتعامل مع الأخطاء والمواقف غير المتوقعة بسلاسة.

رفع خطأ، إذا لم يُعالج، يوقف البرنامج ويطبع رسالة خطأ.
في معظم الحالات، لا تريد أن يتوقف برنامجك عند حدوث خطأ، بل تريد التعامل مع الخطأ ومواصلة تشغيل البرنامج.

## رفع استثناء

في Crystal، تُرفع الاستثناءات باستخدام الكلمة المفتاحية `raise`، ويمكن إما تمرير `String` أو كائن `Exception` إليها.
إذا لم يُعالج، سيتوقف البرنامج ويطبع رسالة الخطأ.

```crystal
raise "This is an error"
```

توجد عدة استثناءات مدمجة في Crystal، مثل `ArgumentError` و`IndexError` و`KeyError` و`IOError` و`SystemCallError` و`TypeError` و`ZeroDivisionError` وغيرها الكثير.
تتطلب منك تمرير رسالة إلى الاستثناء.

```crystal
raise ArgumentError.new("This is an argument error")
```

## [التعامل مع الاستثناءات][exception-handling]

لا نريد أن يتعطل برنامجنا عند رفع استثناء.
لذلك، عندما نعلم أن جزءًا من الكود عُرضة للخطأ، يمكننا تغليفه في كتلة `begin` والتقاط الاستثناء بكتلة `rescue`.
تحدد كتلة `begin` بداية الكود الذي قد يرفع استثناءً، وتتعامل كتلة `rescue` مع الاستثناء.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
end
```

يمكن أيضًا تحديد كتلة `rescue` باستخدام متغير للحصول على كائن الاستثناء.

```crystal
begin
 raise "This is an error"
rescue ex
 puts "An error occurred: #{ex.message}"
end
```

يمكن أيضًا تحديد كتلة `rescue` بنوع استثناء محدد لالتقاط ذلك الاستثناء فقط.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
end

# or

begin
 raise ArgumentError.new("This is an argument error")
rescue ex : ArgumentError
 puts "An argument error occurred: #{ex.message}"
end
```

يمكن استخدام عدة كتل `rescue` للتعامل مع أنواع مختلفة من الاستثناءات.
في المثال أدناه، ستلتقط كتلة `rescue` الأولى استثناء `ArgumentError`، وستلتقط كتلة `rescue` الثانية أي استثناء آخر.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
rescue
 puts "An error occurred!"
end
```

يمكن أن تحتوي كتلة `begin` أيضًا على كتلة `else`، تُنفَّذ إذا لم يُرفع أي استثناء.

```crystal
begin
 puts "No error occurred"
rescue
 puts "An error occurred!"
else
 puts "No error occurred"
end
```

أخيرًا، توجد كتلة `ensure` تُنفَّذ دائمًا، بغض النظر عما إذا كان قد رُفع استثناء.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
ensure
 puts "This is always executed"
end
```

## اصطلاح الطرق

بعض الطرق لها نسختان، واحدة مع `!` والأخرى بدونه.
قد يعني هذا شيئين مختلفين.
أحدهما أن الطريقة تُغيّر الكائن، والآخر أن الطريقة يمكن أن ترفع استثناءً.

لكن هناك أيضًا اصطلاح آخر حول إنهاء الطريقة بـ `?` ذُكر في مفهوم القيمة المنطقية.
بعض الطرق ترفع استثناءً افتراضيًا، لكن لديها أيضًا نسخة تنتهي بـ `?` وتُرجع `nil` بدلًا من رفع استثناء.

يكون هذا مثاليًا عندما تريد تجنب رفع خطأ.
قد يفيد هذا الأداء لأنه لا يضطر إلى إنشاء تتبّع للمكدس، وإذا أُعدّ بشكل صحيح، فقد يجعل الكود أكثر أمانًا.

## استثناءات مخصصة

يمكنك أيضًا إنشاء استثناءاتك الخاصة عبر الوراثة من الصنف [`Exception`][exception].
وبذلك، يمكنك اختياريًا تجاوز طريقة `initialize` لتعيين رسالة الاستثناء.
يمكن فعل ذلك بإسناد الرسالة إلى متغير نسخة باسم `@message`.

```crystal
class MyException < Exception
 def initialize
   @message = "This is my exception"
 end
end

raise MyException.new
```
