# نبذة

`generator` هو دالة أو تعبير يُرجع نوعًا خاصًا من [المكرّر][iterator] يُسمى [مكرّر المولّد][generator-iterator].
`Generator-iterators` [كسولة][lazy iterator]: فهي لا تخزّن `values` في الذاكرة، بل _تولّد_ قيمها عند الحاجة.

دالة المولّد تبدو مثل أي دالة أخرى، لكنها تحتوي على [تعبيرات `yield`][yield expression] واحدًا أو أكثر.
كل `yield` سيُعلّق تنفيذ الكود، ويحفظ حالة التنفيذ الحالية (_بما في ذلك كل المتغيرات المحلية وعبارات `try`_).
وعندما يستأنف المولّد عمله، يستكمل حالته من نقطة التعليق، على عكس الدوال العادية التي تُصفَّر مع كل استدعاء.


## إنشاء مولّد

تُبنى المولّدات كثيرًا مثل غيرها من دوال الحلقات أو الدوال العودية، لكنها تحتاج إلى [تعبير `yield`](#the-yield-expression)، وسنستكشفه بعمق بعد قليل.

ومن الأمثلة على ذلك دالة تُرجع _مربّعات_ الأعداد من مصفوفة أعداد معطاة.  
وكما هي مكتوبة الآن، يجب معالجة كل المدخلات قبل أن يُمكن إرجاع أي قيم:

```python
>>> def squares(list_of_numbers):
...     squares = []
...     for number in list_of_numbers:
...         squares.append(number ** 2)
...     return squares
```

يمكنك تحويل تلك الدالة إلى مولّد هكذا:

```python
>>> def squares_generator(list_of_numbers):
...     for number in list_of_numbers:
...         yield number ** 2
```

والمنطق وراء ذلك هو أنك تستخدم مولّدًا عندما لا تحتاج إلى كل القيم _دفعة واحدة_.

وهذا يوفّر الذاكرة وقوة المعالجة، لأن القيمة الوحيدة التي _تعمل عليها حاليًا_ هي التي تُحسب.


## استخدام مولّد

المولّدات (_من الناحية التقنية هي [`generator-iterator`s][generator-iterator]، انظر الملاحظة أدناه._) نوع من `iterator`، ويمكن استخدامها في أي مكان في Python حيث يُتوقع `iterator` أو `iterable`.
وهذا يشمل _الدوال_ أو _الكائنات_ التي تحتاج إلى `iterable`/`iterator` كوسيط.
وللتعمّق أكثر، انظر [كيف تصنع مكرّرًا في Python][how-to-iterator].


~~~~exercism/note

مكرّرات المولّد هي مجموعة فرعية خاصة من [المكرّرات][iterator].
`Iterators` هي الآلية أو البروتوكول الذي يتيح التكرار على _القيم القابلة للتكرار_.
مكرّرات المولّد والمكرّرات التي تُرجعها [`iterables`][iterables] الشائعة في Python تتصرف بشكل متشابه جدًا، لكن هناك بعض الفروق المهمة التي يجب ملاحظتها:

- فهي _[تُقيَّم بتكاسل][lazy evaluation]_؛ فالتكرار _أحادي الاتجاه_ ولا يوجد «رجوع» إلى قيمة سابقة.
- وهي _تُستهلك_ عند التكرار على القيم المُرجَعة؛ فلا يوجد تصفير أو حفظ في الذاكرة.
- وهي غير قابلة للترتيب ولا يمكن عكسها.
- وهي ليست أنواعًا تسلسلية، و_ليس_ لديها `indexes`. 
  فلا يمكنك الرجوع إلى قيمة سابقة أو لاحقة بالجمع أو الطرح، ولا يمكنك استخدام تدوين الأقواس المربعة (`[]`) أو التقطيع.
- ولا يمكن استخدامها مع الدالة `len()`، لأنها بلا طول.
- ويمكن أن تكون _منتهية_ أو _غير منتهية_، فكن حذرًا عند جمع كل القيم من `generator-iterator` _غير منتهٍ_!

[iterator]: https://docs.python.org/3.11/glossary.html#term-iterator
[iterables]: https://wiki.python.org/moin/Iterator
[lazy evaluation]: https://en.wikipedia.org/wiki/Lazy_evaluation
~~~~


لاستخدام المولّد `squares_generator()`:

```python
>>> squared_numbers = squares_generator([1, 2, 3, 4])

>>> for square in squared_numbers:
...     print(square)
...
1
4
9
16
```

يمكن أيضًا إنتاج القيم داخل المولّد أو الوصول إليها عبر الدالة `next()`.
تستدعي `next()` الطريقة `__next__()` في كائن المولّد، فتُقدّم أو تُقيّم كود المولّد حتى تعبير `yield` الخاص به، والذي «يولّد» أو يُرجع القيمة بعد ذلك.

```python
>>> squared_numbers = squares_generator([1, 2])

>>> next(squared_numbers)
1
>>> next(squared_numbers)
4
```

وعندما يُستهلك `generator` بالكامل ولا تبقى لديه قيم يُرجعها، فإنه يرفع خطأ `StopIteration`.

```python
>>> next(squared_numbers)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
StopIteration
```

### الفرق بين القيم القابلة للتكرار والمولّدات

المولّدات هي مجموعة فرعية خاصة من _المكرّرات_.
`Iterators` هي الآلية أو البروتوكول الذي يتيح التكرار على _القيم القابلة للتكرار_.
المولّدات والمكرّرات التي تُرجعها [`iterables`][iterables] الشائعة في Python تتصرف بشكل متشابه جدًا، لكن هناك بعض الفروق المهمة التي يجب ملاحظتها:

- المولّدات _أحادية الاتجاه_؛ فلا يوجد «رجوع» إلى قيمة سابقة.

- التكرار على المولّدات يستهلك القيم المُرجَعة؛ فلا تصفير.

- المولّدات (_لأنها تُقيَّم بتكاسل_) غير قابلة للترتيب ولا يمكن عكسها.

- المولّدات _ليس_ لديها `indexes`، لذا لا يمكنك الرجوع إلى قيمة سابقة أو لاحقة بالجمع أو الطرح.

- لا يمكن استخدام المولّدات مع الدالة `len()`.

- يمكن أن تكون المولّدات _منتهية_ أو _غير منتهية_، فكن حذرًا عند جمع كل القيم من مولّد _غير منتهٍ_.

## تعبير `yield`

[تعبير `yield`][yield expression] شبيه جدًا بتعبير `return`.

و_على عكس_ تعبير `return`، فإن `yield` يتنازل عن القيم للمستدعي عند _نقطة محددة_، فيُعلّق تقييم أو إرجاع أي قيم إضافية حتى تُطلب.

وعندما يُقيَّم `yield`، فإنه يوقف تنفيذ الدالة الحاضنة ويُرجع قيم الدالة _في تلك اللحظة من الزمن_.

ثم _تبقى الدالة في النطاق_، وعندما تُستدعى `__next__()`، يستأنف التنفيذ حتى يُصادف `yield` مرة أخرى.

~~~~exercism/note
يُحظر استخدام تعبيرات `yield` خارج الدوال.
~~~~

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1

>>> lets_try = infinite_sequence()
>>> lets_try.__next__()
0
>>> lets_try.__next__()
1
```

## لماذا المولّدات؟

المولّدات مفيدة في كثير من التطبيقات.

عند العمل مع مجموعة كبيرة، قد لا ترغب في وضع كل قيمها في `memory`.
ويمكن استخدام مولّد للعمل على بيانات أكبر قطعة تلو الأخرى، مما يوفّر الذاكرة ويحسّن الأداء.

كما أن المولّدات مفيدة جدًا عندما تكون عملية أو حسابات ما _معقدة_ أو _مكلفة_ أو _غير منتهية_:

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1
```

والآن، كلما استُدعيت `__next__()` على الكائن `infinite_sequence`، فستُرجع _العدد السابق_ + 1.
