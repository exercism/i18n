# مقدمة

تحتوي JavaScript على كائن مدمج هو `Date` يخزّن التاريخ والوقت، ويوفّر طرقًا لإدارتهما.

<!-- prettier-ignore -->
~~~exercism/caution
كان مبنيًّا على صنف `java.util.Date` في Java، الذي استُبدل في مطلع العقد 2010، لكن `Date` في JavaScript لا يزال موجودًا من أجل التوافق مع الإصدارات السابقة.

ولأنّ العمل مع التواريخ صعب عمومًا، ولأنّ التعامل مع المناطق الزمنية سيّئ أو شبه معدوم، ظهرت مكتبات كثيرة مثل `moment.js` و`day.js` و`date-fns` و`luxon`.
لا تتوفّر أي من هذه المكتبات على Exercism.

في مشاريعك الخاصة، لا تستخدم حزمة مهجورة أو غير مدعومة مثل `moment.js`، بل اعتمد على بدائل أحدث مثل `luxon`، أو على [Temporal][mdn-temporal] الذي لم ينتشر بعد على نطاق واسع.
يركّز هذا التمرين على `Date`، الذي سيبقى ذا صلة إلى نهاية JavaScript.

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal
~~~

## الإنشاء

كائن `Date` هو نسخة من صنف `Date`.
يمكن إنشاؤه دون تمرير أي وسائط إلى دالة البناء.
ينتج عن ذلك كائن `Date` يمثّل التاريخ والوقت الحاليين:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### **الطابع الزمني Unix (عدد)**

إذا مُرّر عدد، فسيُفسَّر على أنه `timestamp`.
الطابع الزمني عدد صحيح يمثّل عدد **الميلي ثانية** التي مرّت منذ **1 يناير 1970 [UTC][defn-utc]+0**.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

قد يتوقّع المرء أن `new Date(0)` ينشئ كائن التاريخ "الأقدم"، لكن JavaScript ستحوّل التاريخ إلى منطقتك الزمنية المحلية، ما يعني أن من هم في نطاق المنطقة الزمنية [GMT / UTC+0][defn-gmt] فقط هم من سيحصلون فعلًا على قيمة [حقبة Unix][defn-unix-epoch].

### **الطابع الزمني ISO 8601 (سلسلة نصية)**

يمكنك تمرير قيمة نصية تمثّل تاريخًا إلى دالة البناء `Date`.
الصيغة **الوحيدة** المتّسقة بين مختلف التطبيقات هي [النسخة المبسّطة][mdn-date-string-format] مما يُعرف بسلاسل [الطابع الزمني ISO 8601][defn-iso8601]، وهي معترف بها دوليًا وموحّدة.

تبدو لحظة زمنية معيّنة بتوقيت [UTC][defn-gmt] هكذا:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

حيث تُجرى الاستبدالات التالية:

| المفتاح | الوصف                                   | القيمة الافتراضية |
| ---- | --------------------------------------------- | ------- |
| YYYY | السنة التقويمية، بصيغة 4 أرقام    |         |
| MM   | الشهر التقويمي، بصيغة رقمين   | 01      |
| DD   | يوم الشهر التقويمي، بصيغة رقمين     | 01      |
| T    | حرف T نفسه، يفصل التاريخ عن الوقت |         |
| HH   | الساعات بنظام 24 ساعة، بصيغة رقمين        | 00      |
| mm   | الدقائق، بصيغة رقمين                         | 00      |
| ss   | الثواني، بصيغة رقمين                         | 00      |
| mss  | الميلي ثانية، بصيغة 3 أرقام                    | 000     |
| Z    | حرف Z نفسه، أو إزاحة `+/-HH:mm`   |         |

يشير الحرف `Z` نفسه إلى UTC (بدون منطقة زمنية، وبدون توقيت صيفي).

ولأنّ لمعظم المكوّنات قيمًا افتراضية، فمن الصحيح حذف أجزاء من النهاية:

```text
YYYY-MM-DD
```

القيمة الافتراضية للوقت هي 00:00:00.000

إذا لم ينتهِ الطابع الزمني بـ `Z`، ولم ينتهِ بـ `+HH:mm` أو `-HH:mm` (ما يشير إلى إزاحة المنطقة الزمنية)، فبسبب أسباب تاريخية ينطبق ما يلي:

> عندما تكون إزاحة المنطقة الزمنية غائبة، تُفسَّر الصيغ التي تتضمّن التاريخ فقط على أنها بتوقيت UTC، وتُفسَّر الصيغ التي تتضمّن التاريخ والوقت على أنها بالتوقيت المحلي.
> ويرجع تفسيرها على أنها بتوقيت UTC إلى خطأ تاريخي في المواصفة لم يكن متّسقًا مع ISO 8601، لكن تعذّر تغييره بسبب التوافق مع الويب.
> راجع [المحلّل المعطوب: مشكلة واقعية على الويب][ref-broken-parser].

### **كائن `Date`**

يمكن أيضًا استخدام كائن تاريخ موجود كوسيط لدالة البناء.
ينشئ ذلك نسخة من كائن `Date` الموجود بالتاريخ والوقت نفسيهما.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### **تمرير قيم مكوّنات التاريخ والوقت بشكل فردي**

يمكن إنشاء تاريخ يمثّل يومًا بتمرير ثلاثة أعداد.
ويمكن إنشاء تاريخ يمثّل يومًا ووقتًا بتمرير 6 أعداد.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

القيمة الثانية هي `month`، وتبدأ من `0` لشهر يناير، حتى `11` لشهر ديسمبر.

## `Date.parse()`

قد تصادف إشارات أو إحالات إلى دالة تحليل التواريخ `Date.parse`.
ولأنّ هذه الدالة لا تضمّ سوى قليل من الثوابت (الحقائق المؤكدة)، ولأنّ بقية تنفيذها غير محدّدة (وبالتالي غير قياسية)، فلا ينبغي استخدامها.

## الوصول إلى مكوّنات `Date`

هناك طرق متعددة على كائنات التاريخ تُرجع مكوّنات التاريخ:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

ولكلٍّ من هذه الطرق صيغة `set` مناظرة (مثل `setFullYear`) لتحديث القيمة.
وأي قيمة تتجاوز الحد تنتقل إلى المكوّن التالي:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

توجد صيغ بتوقيت UTC لجميع الطرق تتجاهل المنطقة الزمنية المحلية.

## التحويل من تاريخ

تمتلك كائنات التاريخ طريقة `getTime()` تُرجع الطابع الزمني UNIX بالميلي ثانية، أي عدد الميلي ثانية منذ منتصف ليل 1 يناير 1970 بتوقيت UTC.
إضافةً إلى ذلك، تتوفّر طريقة `toISOString()` للتحويل من كائن تاريخ إلى سلسلة طابع زمني بصيغة ISO 8601.

## مقارنة التواريخ

يمكن استخدام أكبر من (`>`) وأكبر من أو يساوي (`>=`) وكذلك أصغر من (`<`) وأصغر من أو يساوي (`<=`) مباشرةً بين تاريخين، أو بين تاريخ وعدد.
يعمل هذا لأنّ JavaScript ستحاول تحويل التاريخ إلى قيمة أولية.
