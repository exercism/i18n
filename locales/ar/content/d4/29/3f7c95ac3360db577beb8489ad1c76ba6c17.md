# التعليمات

أنت تبني آلة حاسبة صغيرة بالترميز البولندي المعكوس (RPN).
حالة الآلة الحاسبة هي *مكدس من القيم*، ممثَّل في صورة مصفوفة Factor، و*العملية* اقتباس يأخذ مكدسًا كهذا ويُرجع مكدسًا جديدًا.

```factor
{ 3 4 }   ! the calculator's stack: 3 is below 4
[ ... ]   ! an operation that consumes some values and pushes a result
```

## 1. تنفيذ عملية الجمع

عرّف `add-op` بحيث يسحب القيمتين العلويتين من المكدس، ويدفع مجموعهما، ويُرجع المكدس الجديد.

```factor
{ 3 4 } add-op .
! => { 7 }

{ 1 2 3 4 } add-op .
! => { 1 2 7 }
```

## 2. تنفيذ عملية الضرب

عرّف `multiply-op` على النحو نفسه لكن من أجل الضرب.

```factor
{ 3 4 } multiply-op .
! => { 12 }
```

## 3. تطبيق عملية واحدة

عرّف `apply-op` بحيث يأخذ مكدسًا وعملية (اقتباسًا) من مكدس البيانات، ويُرجع مكدس الآلة الحاسبة الجديد.

```factor
{ 3 4 } [ add-op ] apply-op .
! => { 7 }
```

## 4. تقييم برنامج

عرّف `evaluate` بحيث يأخذ مكدسًا ابتدائيًا ومصفوفة من العمليات، ويطبّق كل عملية بدورها، ويُرجع المكدس النهائي.

```factor
{ 3 4 5 } { [ add-op ] [ multiply-op ] } evaluate .
! => { 27 }
```

## 5. التقييم بالاسم

الآن أصبح البرنامج قائمة من *أسماء العوامل* (سلاسل نصية)، وتبحث الآلة الحاسبة عن كل اسم في `assoc` يربط الأسماء بالعمليات.

عرّف `evaluate-named` بحيث يأخذ مكدسًا ابتدائيًا، و`assoc` لعمليات مسمّاة، ومصفوفة من الأسماء، ويُرجع المكدس النهائي.

```factor
{ 3 4 5 } H{ { "+" [ add-op ] } { "*" [ multiply-op ] } } { "+" "*" }
evaluate-named .
! => { 27 }
```

## 6. القسمة بأمان

يجب ألا تنتج آلة حاسبة حقيقية نتائج غير صحيحة بصمت عند طلب القسمة على صفر. صنف الخطأ `zero-divisor-error` معرّف لك مسبقًا. نفّذ `divide-op` على غرار `add-op` و`multiply-op`، إلا أنه ينفّذ `throw` من أجل `zero-divisor-error` جديد عندما يكون المقسوم عليه في أعلى المكدس هو `0`.

```factor
{ 12 4 } divide-op .
! => { 3 }

{ 1 5 6 2 } divide-op .
! => { 1 5 3 }

{ 5 0 } divide-op
! throws zero-divisor-error
```
