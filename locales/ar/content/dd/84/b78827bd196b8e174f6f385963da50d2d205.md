# مقدمة

المؤشرات الذكية ميزة حديثة في C++ صُمّمت لتوفّر إدارة تلقائية للذاكرة، وتساعد على منع تسريبات الذاكرة والمؤشرات المعلّقة المرتبطة عادةً بالمؤشرات الخام.
وهي تعمل كأغلفة حول المؤشرات الخام، وتضيف وظائف إضافية مثل تحرير الذاكرة تلقائيًا عندما لا تعود هناك حاجة إلى المؤشر.

## الصيغة العامة

عادةً ما تُنفَّذ المؤشرات الذكية كقوالب أصناف في مكتبة C++ القياسية.
وأكثر المؤشرات الذكية استخدامًا هما `std::unique_ptr` و`std::shared_ptr`.

## المؤشرات الفريدة

`std::unique_ptr` مؤشر ذكي يملك الكائن ملكية حصرية.
وهو يضمن أنه في أي لحظة لا يملك المورد سوى كائن `std::unique_ptr` واحد.
وعندما يُدمَّر المؤشر `std::unique_ptr` المالك أو يُعاد ضبطه، فإنه يدمّر الكائنات ويحرّر ذاكرتها تلقائيًا.

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## مزايا `std::make_unique()`

عند إنشاء `std::unique_ptr`، يُفضَّل استخدام `std::make_unique()` بدلًا من استخدام `new` مباشرةً لتخصيص الذاكرة.
ويوفّر `std::make_unique()` عدة مزايا:
1. **أمان الاستثناءات**: يضمن `std::make_unique()` أمان الاستثناءات.
  فإذا طُرح استثناء أثناء إنشاء الكائن، حُرِّرت الذاكرة تلقائيًا، ما يمنع تسريبات الذاكرة.
2. **الوضوح**: استخدام `std::make_unique()` يجعل الكود أوضح وأكثر إيجازًا.
  فهو يلغي الحاجة إلى تحديد النوع المُخصَّص صراحةً، لأن وسائط القالب تُستنتج تلقائيًا.
3. **فرص التحسين**: تُتاح للمصرّفات فرصة تحسين `std::make_unique()` بفعالية أكبر من تخصيص الذاكرة يدويًا باستخدام `new`، وقد يؤدي ذلك إلى تحسين الأداء.
4. **تجنّب إساءة الاستخدام**: يمكن حذف المورد الأساسي عند إنشاء `std::unique_ptr` يدويًا.
  ويؤدي ذلك إلى سلوك غير معرّف عندما يحاول `std::unique_ptr` حذفه عند نهاية نطاقه.

## المؤشرات المشتركة

`std::shared_ptr` مؤشر ذكي يسمح لعدة كائنات `std::shared_ptr` بأن تتشارك ملكية المورد نفسه.
وهو يتتبّع عدد المؤشرات المشتركة التي تشير إلى المورد، ولا يحرّر الذاكرة إلا عندما يخرج آخر مؤشر مشترك يملك المورد من نطاقه أو يُعاد ضبطه.

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

في C++17 وما قبله، لا يتوفر دعم مباشر لاستخدام `std::shared_ptr` مع المصفوفات عبر `std::make_shared<T[]>`.
ومع أن تخصيص المصفوفات باستخدام `std::make_shared<T[]>` ممكن، فإن إنشاء مؤشرات مشتركة منها مباشرةً قد يؤدي إلى سلوك غير معرّف بسبب اختلافات إدارة الذاكرة بين الكائنات المفردة والمصفوفات.
بدلًا من ذلك، فكّر في استخدام `std::vector` أو دوال حذف مخصّصة لإدارة المصفوفات بالمؤشرات المشتركة بفعالية.
واحرص دائمًا على التوافق مع المصرّف وتنفيذ المكتبة القياسية لديك عند التعامل مع تخصيص المصفوفات والمؤشرات المشتركة في C++17.
~~~~

## مزايا `std::make_shared()`

على غرار `std::make_unique()`، يقدّم `std::make_shared()` مزايا مثل تحسين كفاءة الذاكرة، وأمان الاستثناءات، وقابلية القراءة.
فهو يجمع تخصيص الذاكرة لكتلة التحكم والكائن المُدار في عملية واحدة، ما يعزّز الكفاءة ويقلّل خطر تسريبات الذاكرة.
وإضافةً إلى ذلك، يبسّط الاستنتاج التلقائي لوسائط القالب الكود ويعزّز قابلية القراءة.
ويؤدي استخدام `std::make_shared()` إلى كود أنظف وأكثر أمانًا وكفاءة عند التعامل مع كائنات `std::shared_ptr` في C++.

## المؤشرات الضعيفة

`std::weak_ptr` صنف مرافق لـ `std::shared_ptr` يوفّر مرجعًا "ضعيفًا" غير مالك إلى كائن يديره مؤشر مشترك.

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

المؤشرات الضعيفة مفيدة في الحالات التي يلزم فيها كسر المراجع الدائرية لمنع تسريبات الذاكرة.
وقد صُمّم `std::weak_ptr` لمعالجة مشكلة الملكية الدائرية، المعروفة أيضًا بالمراجع الدائرية، التي قد تحدث عند استخدام `std::shared_ptr`.
وفي حالة الملكية الدائرية، يشير كائنان أو أكثر من `std::shared_ptr` إلى بعضها بعضًا، ما ينشئ دورة لا يمكن فيها حذف أي من الكائنات لأنها تحمل مراجع قوية إلى بعضها، فيؤدي ذلك إلى تسريبات الذاكرة.
ويقدّم `std::weak_ptr` حلًا لهذه المشكلة بالسماح بمراجع ضعيفة إلى الكائنات المشتركة دون أن تسهم في عدّ مراجعها.
وهذا يعني أنه يستطيع مراقبة الكائن المشترك والوصول إليه، لكنه لا يمنعه من أن يُحذف.
~~~~

## نصائح الاستخدام

استخدم المؤشرات الذكية افتراضيًا: `std::unique_ptr` للملكية الحصرية و`std::shared_ptr` للملكية المشتركة.
واحتفظ بالمؤشرات الخام للمراجع غير المالكة أو عند التعامل مع كود قديم.
وفي معظم الحالات، يكفي `std::unique_ptr` للملكية الحصرية، لأنه يقدّم إدارة خفيفة للذاكرة دون عبء عدّ المراجع.
وينبغي استخدام `std::shared_ptr` باعتدال، لأنه يضيف عبئًا وتعقيدًا ما لم تكن الملكية المشتركة ضرورية فعلًا.
أما `std::weak_ptr` فهو متخصّص في كسر التبعيات الدائرية أو مراقبة الكائنات المشتركة، لكنه ليس شائع الاستخدام.
