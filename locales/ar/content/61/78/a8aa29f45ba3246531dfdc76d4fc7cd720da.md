# القيم المنطقية

تحمل `BOOL` إحدى قيمتين، هما `true` و`false`.

```sather
   ready : BOOL is
      return true;
   end;
```

## المقارنة

| العامل | يسأل | مثال |
| --- | --- | --- |
| `=` | هل هما متساويان؟ | `age = 13` |
| `/=` | هل هما مختلفان؟ | `age /= 13` |
| `<` | أقل من | `age < 13` |
| `<=` | أقل من أو يساوي | `age <= 13` |
| `>` | أكبر من | `age > 13` |
| `>=` | أكبر من أو يساوي | `age >= 13` |

تعمل هذه العوامل على الأعداد، وتعمل `=` و`/=` على السلاسل النصية أيضًا.

## العوامل الثلاثة

| العامل | الصيغة | تكون النتيجة صحيحة عندما |
| --- | --- | --- |
| `and` | `a and b` | يكون كلاهما صحيحًا |
| `or` | `a or b` | يكون أحدهما على الأقل صحيحًا |
| `not` | `~a` | يكون `a` خطأً |

**تعمل `and` و`or` بمبدأ التقييم القصير**: فالتعبير `a and b` لا يكلف نفسه النظر إلى `b` بمجرد أن يتبين أن `a` خطأ، لأن النتيجة قد حُسمت بالفعل. وبالمثل يتوقف `a or b` إذا كان `a` صحيحًا. وهذا مهم عندما يكون الطرف الأيمن مكلفًا، أو قد يؤدي تنفيذه إلى خطأ.

## إرجاع نتيجة المقارنة مباشرة

الدالة التي تتمثل مهمتها كلها في طرح سؤال ينبغي أن تُرجع السؤال نفسه، لا أن تختار جوابًا باستخدام جملة شرطية:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

كتابة `if age >= 13 then return true else return false end` تستغرق ثلاثة أسطر لتقول ما قالته المقارنة أصلًا، وسيلاحظ ذلك كل قارئ متمرس.

## الأسبقية

`~` له أعلى أسبقية، ثم `and`، ثم `or`. إذن

```sather
~a and b or c
```

يعني `((~a) and b) or c`. الأقواس الهلالية لا تكلّف شيئًا عند كتابتها، وتستحق العناء كلما احتاج القارئ إلى تذكر هذا الترتيب لمتابعة السطر.
