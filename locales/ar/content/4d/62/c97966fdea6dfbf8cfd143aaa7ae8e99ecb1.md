# نبذة

تتعلق محدّدات صنف التخزين بكيفية تخزين المتغيرات في الذاكرة.
وهي وثيقة الصلة بمدة التخزين (التي يُشار إليها أيضًا بعمر القيمة).

## auto: صنف التخزين الافتراضي لمتغيرات نطاق الدالة أو الكتلة

بما أن المتغيرات المعرَّفة داخل كتلة أو دالة تكون `auto` افتراضيًا، فليس من الشائع استخدام المصطلح صراحةً.
وهناك سبب آخر لتفادي `auto` غالبًا، وهو أن له معنى مختلفًا في C++.
وقد تكون قواعد الأكواد التي تجمع بين C وC++ أقل إرباكًا إذا تجنّبت محدّد التخزين `auto`.
يبدأ عمر متغير `auto` عند الدخول إلى كتلته وينتهي عند الخروج منها.
ويُخصَّص لمتغير `auto` ذاكرة عند الدخول إلى كتلته، _لكن دون قيمة افتراضية_.
ويقع الاستثناء على المصفوفات متغيرة الطول (VLAs.)
فتخصيص المصفوفة متغيرة الطول يحدث حيث تُعلَن أو تُعرَّف في كتلتها، وينتهي عند الخروج من تلك الكتلة.
ويمكن تهيئة متغير `auto` بأي تعبير صالح.

## static: محدّد التخزين الذي لا يُخلط بينه وبين نوع الارتباط static

المتغير المعرَّف خارج كتلة أو دالة له نطاق الملف، وله دائمًا مدة تخزين ساكنة.
ونطاق الملف يعني أنه يمكن الوصول إليه في أي مكان في الملف.
والتخزين الساكن يعني أنه موجود من بداية تنفيذ البرنامج حتى نهايته.
وما لم يُهيَّأ صراحةً، يُهيَّأ متغير `static` بقيمته الافتراضية الصفرية.
وإذا وُسم متغير في نطاق الملف بـ `static`، فإن `static` هنا تشير إلى ارتباطه.
فالمتغير ذو نطاق الملف الموسوم بـ `static` له ارتباط داخلي، أي أنه لا يمكن الوصول إليه إلا داخل الملف.
وإذا عُرِّف متغير داخل دالة أو في كتلة داخل دالة ووُسم بـ `static`، فله مدة تخزين من نوع `static`.
وتبقى قيمة متغير `static` محفوظة بين الاستدعاءات المتتالية للدالة أو الكتلة.

في المثال التالي نرى متغيرين من نوع `static` أثناء العمل.
المتغير الأول `count` معرَّف داخل الدالة `print_stuff` ويحتفظ بقيمته بين الاستدعاءات المتتالية للدالة.
والمتغير الثاني `count` معرَّف داخل كتلة عشوائية، ويحجب (أو يُظلِّل) المتغير الأول `count` داخل كتلته.
ويحتفظ المتغير الثاني `count` بقيمته بشكل مستقل بين مرات الدخول إلى الكتلة.

```c
#include <stdio.h>

void print_stuff(void) {
    // static variable is initialized to 0
    static int count;
    count++;
    printf("function count is %d\n", count);
    {
        // static variable is initialized to 0
        static int count;
        count++;
        printf("block count is %d\n", count);
    }
}

int main() {
    // prints
    // function count is 1
    // block count is 1
    print_stuff();
    // prints
    // function count is 2
    // block count is 2    
    print_stuff();
}
```

وإذا هُيِّئ متغير `static` صراحةً، فيجب أن يكون ذلك بتعبير ثابت.
والتعبير الثابت هو تعبير يمكن حسابه في وقت الترجمة.

## extern: كيفية الوصول إلى متغير في وحدة ترجمة أخرى

تتكوّن وحدة الترجمة من ملف مصدري وأي ملف آخر يضمّه بـ `#include`.
ورغم أنه يمكن إعلان متغير له نطاق الملف وتهيئته بوصفه `extern`، فإن الكلمة المفتاحية `extern` تُستخدم عادةً للإشارة إلى متغير موجود، لا لتعريف متغير جديد.
ويجب أن يكون المتغير الذي تشير إليه `extern` ذا نطاق ملف.
والمتغير ذو نطاق الملف له دائمًا تخزين من نوع `static`.
ويجب أن يكون للمتغير في ملف مُضمَّن ارتباط خارجي حتى يتمكن الملف الذي يضمّه من الوصول إليه.

في المثال التالي نستخدم المتغير `val` المُعلَن بوصفه `extern` ليشير إلى `val` المعرَّف في نطاق ملفه.
ويُسمّى الاستخدامان معًا لـ `extern` إعلانات مرجعية، لأنهما يشيران إلى متغير معرَّف في مكان آخر.

```c
#include <stdio.h>

void set_val() {
    // this declares val which is defined elsewhere
    extern int val;
    val += 42;
    // prints val is 42
    printf("val is %d\n", val);
}

int main() {
    set_val();
    // this declares val which is defined elsewhere
    extern int val;
    val += 42;
    // prints val is 84
    printf("val is %d\n", val);
}
// this value could be defined in another source file.
// as a variable with static storage, it is initialized to zero
int val;
```

إذا أزلنا كلمتَي `extern` المفتاحيتين، فقد يطبع البرنامج شيئًا مثل

```
val is 22038
val is 42
```

ويوضح هذا الناتج أن كل إعلان لـ `val` بدون `extern` هو إعلان معرِّف ومستقل عن بقية إعلانات `val`.
وإزالة إعلانات `val` كليًا من `set_val` و`main` ستؤدي إلى خطأ في الترجمة مفاده أن `val` غير مُعلَن في `set_val` و`main`.

وإذا كان المتغير المشار إليه بـ `extern` في الملف نفسه، فيمكن أن يكون ارتباطه داخليًا أو خارجيًا.
ولن يكون لتعريف `val` بالصيغة `static int val;` أي تأثير على استخدام `val` في `set_val` أو `main`، إلا أن التعريف سيحتاج إلى نقله فوقهما حتى ينجح التصريف.
لكن لو كان `val` معرَّفًا فوق الدالتين، لما احتاجتا إلى إعلان `val` بوصفه `extern`.

المثال التالي سيعمل

```c
#include <stdio.h>

// val defining declaration before the function definitions
static int val;

void set_val() {
    val += 42;
    // prints val is 42
    printf("val is %d\n", val);
}

int main() {
    set_val();
    val += 42;
    // prints val is 84
    printf("val is %d\n", val);
}
```

ويمكن إزالة `static` من `static int val;`، فيصبح لـ `val` ارتباط خارجي، وسيظل `val` يعمل بالطريقة نفسها في `set_val` و`main`.
ولو ضمّ ملف مصدري آخر هذا الملف، فلن يستطيع استخدام `val` إلا إذا كان لـ `val` ارتباط خارجي (غير مُعلَن بوصفه `static`) وأعلن الملف الآخر `extern int val;`.

ولا يجب أن يمتلك المتغير المشار إليه بـ `extern` تخزينًا من نوع `static` فحسب، بل يجب أيضًا أن يكون له نطاق ملف.
ومن المرجح ألا يُصرَّف المثال التالي، لأن `val`، رغم كونه `static`، ليس له نطاق ملف.

```c
#include <stdio.h>

void set_val() {
    // defined with static storage, but not in file scope
    static int val;
    val += 42;
    printf("val is %d\n", val);
}

int main() {
    set_val();
    extern int val;
    printf("val is %d\n", val);
}
```

## register: كيف يمكن تسريع الوصول إلى متغير

يعبّر المتغير الموسوم بـ `register` عن رغبة المبرمج في وضع القيمة في سجل للوصول السريع إليها.
ويشبه متغير `register` متغير `auto` في أنه يجب أن يكون في نطاق دالة أو كتلة.
ولأن القيمة يُقصد بها أن توضع في سجل بدلًا من الذاكرة، فينبغي ألا يسمح المترجم بالوصول إلى عنوان المتغير، إذ لا يمكن أخذ عنوان سجل.
ومع ذلك، يمكن وضع عنوان ذاكرة نفسه في سجل.
يوضح المثال التالي ذلك

```c
#include <stdio.h>

int main() {
    int i = 42;
    register int *i_ptr = &i;
    // prints i is 42, i_ptr is 0x7ffd0c2055c4 (or some other address)
    printf("i is %d, i_ptr is %p", i, i_ptr);
}
```

register` هو في الأساس مجرد تلميح، لأن المترجمات حرة في أن تتبع هذا المحدّد أو لا تتبعه، لذا قد توضع القيمة فعليًا في سجل أو لا توضع.

## typedef: محدّد صنف التخزين الذي ليس كذلك في الحقيقة

يُوصف `typedef` بأنه محدّد صنف تخزين لأسباب نحوية فقط.
وذلك لأن محدّد صنف التخزين لا يمكن استخدامه مع محدّد صنف تخزين آخر.
لذا فإن `typedef auto int i = 42;` غير قانوني تمامًا مثل `static auto int i = 42;`.
