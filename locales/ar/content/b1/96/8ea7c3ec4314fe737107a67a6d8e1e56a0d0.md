# مقدمة

يبني هذا التمرين على ما رأيته في [Backyard Birdwatcher][backyard-birdwatcher]، إذ يقدّم الكلمات عالية الرتبة التي تأخذ *اقتباسًا*، وهو قطعة من الكود بين قوسين مربعين `[ ]`، لتوجيه العملية.

## الاقتباسات كقيم

الاقتباس ليس سوى قطعة حرفية من الكود. يمكنك تمريره كبيانات إلى كلمة أخرى:

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

هنا `[ 2 > ]` اقتباس يأخذ عددًا ويترك قيمة منطقية. ويشغّل `count` هذا الاقتباس على كل عنصر ويحصي النتائج التي تُعتبر صحيحة.

## التصفية والاستبعاد

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

يعامل `without` وسيطه الثاني كمجموعة: أي عنصر من `seq` يساوي `=` *أي* عنصر من `exclude` يُحذف. أما `sift` فهي الحالة الخاصة الخالية من الاقتباس في `reject`: فهي تحتفظ بكل عنصر عدا `f`، وهذا مفيد لتنظيف الفجوات التي تركها `map` سابق.

### الاحتفاظ بنتيجة الاختبار

يُعيد `find` العنصر المطابق. وعندما يحسب الاختبار بالفعل القيمة التي تريدها، يوفّر عليك `map-find` تمريرة ثانية: فهو يشغّل الاقتباس على كل عنصر ويُرجع أول نتيجة ليست `f` **و** العنصر الذي أنتجها.

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

يُرجع الاقتباس `f` للعناصر غير المؤهلة، والنتيجة التي تريد الاحتفاظ بها للعنصر المؤهل. وإذا لم يتأهل أي عنصر، يترك `map-find` القيمتين `f f`، تمامًا مثل `find`.

### تصفية السجلات حسب خانة

عندما تكون العناصر من نوع `tuple`، فإن الشرط عادةً يستخرج خانة عبر قارئها المولَّد تلقائيًا `slot>>` ويفحص عليها:

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## تمرير قيمة ثابتة عبر `with`

أحيانًا يحتاج الشرط إلى قيمة تكون نفسها في كل استدعاء، مثل عتبة أو مقسوم أو سلسلة نصية مستهدفة. وتدمج `with` (في [`kernel`][kernel]) تلك القيمة الثابتة داخل الاقتباس، فتحوّل اقتباسًا بوسيطين `( value elt -- ? )` إلى الاقتباس ذي الوسيط الواحد الذي تتوقعه `filter` و`count` و`map` و`each`:

```
with ( value seq quot -- seq curry )
```

كل استدعاء لكل عنصر يرى `( value elt )` على المكدس: القيمة الثابتة أولًا، والعنصر الحالي ثانيًا:

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## التطبيق والتكرار

تطبّق `map` (في [`sequences`][sequences]) اقتباسًا على كل عنصر وتُرجع مصفوفة النتائج. وتقوم `each` بالمرور نفسه لكنها تتجاهل النتائج، وهذا مفيد عندما يعمل الاقتباس من أجل آثاره الجانبية فقط. أما `2map` فتسير على *متتاليتين* بالتوازي وتدمج العناصر المتناظرة؛ وتُعد `2each` و`2reduce` نظيرتيها في الآثار الجانبية فقط وفي الطيّ على التوالي؛ و`zip` هي الاختصار لعبارة «إقرانها دون دمج»:

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

تمرّر `2reduce` مركمًا عبر المتتاليتين معًا: اقتباسها يأخذ `( accumulator elt1 elt2 -- accumulator' )`. وهنا تجمع حاصل الضرب النقطي، إذ يُضرب كل زوج وتُجمع حواصل الضرب (`1*10 + 2*20 + 3*30`):

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

`map-as` هي نظيرة `map` التي تفرض نوع متتالية الخرج: مرّر `{ }` أو `V{ }` فارغة كقالب لتتجاوز الافتراضي المأخوذ من نوع الدخل (وإلا، فعند تطبيق map على سلسلة نصية لإنتاج عناصر ليست محارف، يحدث خطأ عندما يحاول Factor حزم النتائج مجددًا في سلسلة نصية).

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

تتوقف الصيغتان ذواتا المتتاليتين عند طول الدخل الأقصر. و`zip` مكافئة لـ `[ 2array ] 2map`، أي إبقاء الأزواج بدل دمجها.

## الترتيب

تُرجع `sort` نسخة مرتبة بالترتيب الطبيعي؛ أما `sort-by` (في [`sorting`][sorting]) فترتّب حسب مفتاح مستخرج من كل عنصر:

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## التجميع

تطبّق `map-sum` (في [`sequences`][sequences]) اقتباسًا على المتتالية وتجمع النتائج في تمريرة واحدة:

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## الأصغر والأكبر

تُرجع `minimum` و`maximum` أصغر عنصر أو أكبر عنصر في متتالية مباشرةً. أما `minimum-by` و`maximum-by` (وكلها في [`sequences`][sequences]) فترجعان العنصر الذي يكون مفتاحه المستخرج الأصغر أو الأكبر:

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## كتابة كلمتك عالية الرتبة

عندما تأخذ كلمتك اقتباسًا كوسيط وقت التشغيل وتمرّره إلى `map` أو `filter` أو `each` أو نحوها، فعرّف كلمتك باستخدام `; inline`. فهذا يخبر المصرِّف بأن يضمّن كلمتك في مكان كل استدعاء، حيث يكون الاقتباس قيمة حرفية معروفة؛ وبدون ذلك، لا سبيل للمصرِّف إلى معرفة تأثير المكدس للاقتباس.

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

الكلمات المبنية من اقتباسات حرفية فقط لا تحتاج إلى `inline`، بل فقط تلك التي تمرّر اقتباسًا *واردًا*.

وإذا استدعت كلمة `inline` كهذه *نفسها*، وهي مُركِّب تعاودي، فعرّفها بـ `; inline recursive` بدلًا من ذلك. وبدون الكلمة الإضافية يتوقف المصرِّف برسالة *"The inline recursive word ... must be declared recursive"*، وهي تخبرك بالضبط بما يجب إضافته.

## جلب العنصر الثاني

بالنسبة إلى مصفوفة من عنصرين، تُرجع `second` عنصرها الثاني. وتُرجع `first` العنصر الأول. وكلتاهما في [`sequences`][sequences].

## من الأعداد إلى السلاسل النصية

تحوّل `number>string ( n -- str )` (في [`math.parser`][math.parser]) عددًا إلى صيغته النصية العشرية:

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
