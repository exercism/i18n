# الأصناف العامة

كنت تستخدم `ARRAY{STR}` و`FMAP{STR,INT}` و`FSET{STR}` منذ البداية.
لطالما احتوت الأقواس المعقوفة على نوع. الآن ستكتب صنفًا له أقواسه المعقوفة الخاصة.

## المشكلة

يحتاج مكتب المفقودات إلى صندوق يحفظ شيئًا واحدًا ويتذكر من سلّمه. صندوق لكنزة:

```sather
class JUMPER_BOX is
   attr item : JUMPER;
   ...
end;
```

ثم نفس الصنف مرة أخرى لزجاجة ماء، ومرة أخرى لهاتف.
ثلاث نسخ تختلف في كلمة واحدة.

## معامل النوع

```sather
class LOST_BOX{T} is

   attr item : T;

   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;

end; -- class LOST_BOX{T}
```

`{T}` بعد اسم الصنف هو **معامل نوع**. `T` ليس نوعًا؛ بل هو بديل عن أي نوع يُمرَّر عند استخدام الصنف. داخل الصنف، يُستخدم `T` تمامًا كما يُستخدم أي اسم نوع.

## استخدامه

مرّر النوع بين الأقواس المعقوفة:

```sather
   jumper ::= #LOST_BOX{STR}("blue jumper");
   count ::= #LOST_BOX{INT}(3);

   jumper.item      -- "blue jumper", a STR
   count.item       -- 3, an INT
```

`LOST_BOX{STR}` و`LOST_BOX{INT}` نوعان مختلفان. وضع أحدهما حيث يُراد الآخر خطأ يلتقطه المترجم، تمامًا كما لو كنت قد كتبت الصنفين يدويًا؛ وهذا ما يحدث فعليًا: يبني Sather صنفًا منفصلًا من النمط لكل نوع يُستخدم فعليًا.

لذا لا توجد كلفة لهذا وقت التشغيل، ولا فقدان لمعلومات النوع:
`jumper.item` هو فعلًا `STR`، وليس شيئًا يجب فحصه أو تحويله.

## أكثر من واحد

قد يأخذ الصنف عدة معاملات، مفصولة بفواصل. `FMAP{K,T}` هو المثال الذي تعرفه بالفعل.

```sather
class LABELLED{L,T} is
   attr label : L;
   attr item : T;
   ...
end;
```

## التسمية

حسب الاصطلاح، تُستخدم أحرف كبيرة مفردة: `T` للشيء، و`K` للمفتاح، و`E` للعنصر. وتستخدمها المكتبة في كل مكان.
