# نبذة

## التمثيل والمحارف والأعداد الصحيحة

مثل الأنواع البسيطة الأخرى (`int` و`bool` وغيرها)، للمحرف `char` نوع مرافق أو اسم مستعار، وهو في هذه الحالة `System.Char`.

هو في الواقع `struct` يحتوي على حقل من 16 بت، وهو غير قابل للتغيير افتراضيًا.

للمحرف `char` بعض دوال النسخة مثل `Equals` و`ToString` و[`CompareTo`][compare-to].

للـ `char` العرض نفسه الذي للـ [`ushort`][uint16]، لكنهما عمومًا لا يُستخدمان بالتبادل كما يحدث في بعض اللغات. يجب تحويل `ushort` صراحةً إلى `char`.

وجدير بالذكر أن `char` يمكن أن تخضع لعمليات حسابية، ونتيجة هذه العمليات عدد صحيح.

ومن الواضح أنه لا تكافؤ بين `byte` ذي 8 بتات و`char` ذي 16 بتًا.

## الاستخدام

استخدام `char` سهل عمومًا.

يمكن تعريفها كقيم حرفية بعلامات الاقتباس المفردة:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

يمكن استخراج محرف `char` واحد من سلسلة نصية بالفهرسة (بدءًا من الصفر):

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

التكرار على سلسلة نصية يُرجع محرف `char` عند كل خطوة:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

وكما هو موضّح أعلاه، يمكن تحويل `char` إلى قيمة `int` المقابلة لها.
وهذا ينطبق أيضًا (*في بعض الحالات على الأقل*) على كتابات أخرى:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

تُستخدم قيمة `Int16` الكامنة عند مقارنة المحارف:

```fsharp
'A' < 'D'
// => val it: bool = true
```

كذلك يمكن تحويل `int` إلى `char`:

```fsharp
char 77
// => val it: char = 'M'
```

تحتوي مكتبة `System.Char` على المجموعة الكاملة من [الدوال][Char-methods] المتوقّعة لأي لغة .NET، مثل التحويل إلى أحرف كبيرة/صغيرة (لكن انظر التحذيرات في القسم التالي):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

تساعد مكتبات .NET في استخراج محارف `char` من السلاسل النصية، وهنا عبر دوال `Seq`:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

توجد طرق عدة لتحويل قائمة المحارف (أو مصفوفتها) إلى سلسلة نصية، منها ما يلي:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

يمكن العثور على معلومات عامة عن `char` هنا:

- [توثيق المحارف][chars-docs]: التوثيق المرجعي للـ `char`.

غير أن `char` فيه عدد من النقاط الخشنة كما هو مفصّل أدناه. وتتعلّق هذه النقاط غالبًا بالتعارض بين معيار يونيكود الكامل من جهة، والتمثيلات التاريخية للنصوص إضافةً إلى الأداء واستهلاك الذاكرة من جهة أخرى.

## مشكلات يونيكود

عند التعامل مع السلاسل النصية، إذا كانت دوال مكتبة [`System.String`][System-string] متاحة فابحث عنها واستخدمها بدلًا من تفكيك السلسلة إلى محارف.

بعض "المحارف" النصية تتكوّن من أكثر من `char` واحد لأن معيار يونيكود يضم أكثر من 65536 نقطة ترميز. فمثلًا الإيموجي التي تظهر في بعض الاختبارات تتكوّن من `char` اثنين لأنها تضم محارف [بديلة][surrogates].

إضافةً إلى ذلك، توجد تسلسلات دمج، حيث قد يتكوّن المحرف المنقوط في بعض الحالات من `char` واحد للمحرف المجرّد و`char` آخر للعلامة التشكيلية.

وإذا اضطررت للتعامل مع محارف فردية فحاول استخدام دوال المكتبة مثل [`System.Char.IsControl`][is-control] و[`System.Char.IsDigit`][is-digit] بدلًا من إجراء مقارنات ساذجة مثل التحقق من أن محرفًا يقع بين '0' و'9'.

لاحظ على سبيل المثال أن '٢' هو الرقم العربي 2. ستُرجع `IsDigit` القيمة صحيح للنسخة العربية، لذا عليك أن تكون واضحًا، عند التحقق، بشأن نطاق المدخلات المقبول.

حتى دوال مكتبة `System.Char` قد لا تتصرّف كما تتوقّع عند التعامل مع لغات أقل شيوعًا.

إحدى الطرق الآمنة لتفكيك سلسلة نصية إلى "محارف" عرض هي استخدام [`StringInfo`][string-info] ودوال مثل [`GetNexttextElement`][get-next-text-element].
قد يكون هذا ضروريًا إذا كنت تتعامل مع العولمة/التوطين.

وهناك مسار آخر تكون فيه القيم القياسية لمحارف يونيكود مهمة (مثلًا إذا كنت تبني نظام ترميز خاصًا بك)، وهو استخدام [runes][runes]. لكن إذا كنت تعرف أن نطاق المحارف التي تتعامل معها لا يشمل المحارف البديلة أو تسلسلات دمج المحارف (مثل Latin ASCII) ومدخلاتك تم التحقق منها جيدًا، فيمكنك تجنّب ذلك.

ومرة أخرى، أفضل موقف يمكن أن تكون فيه هو أن تتمكّن من استخدام دوال مكتبة `String`.

وإذا وجدت نفسك فعلًا في الموقف غير المحسود المتمثّل في التعامل مع تفاصيل يونيكود الدقيقة، فهذا [المصدر][char-encoding-net] نقطة بداية جيدة.
