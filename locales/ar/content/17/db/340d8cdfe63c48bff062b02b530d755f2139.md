# نبذة

توفّر Common Lisp للمبرمج عدة جمل شرطية مختلفة يمكن تصنيفها حسب عدد "الفروع" التي تدعمها.

كذلك، وخلافًا لكثير من لغات البرمجة الأخرى، فإن جميع الجمل الشرطية في Common Lisp هي _تعبيرات_ وليست عبارات.
ويعني هذا أن جميع الجمل الشرطية في Lisp تُقيَّم إلى قيمة ما، ويمكن أن تحلّ محلّ معاملات محددة.

على سبيل المثال:

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## الجمل الشرطية ذات الفرع الواحد

لا تُقيّم الجملتان الشرطيتان `when` و`unless` أي كود إلا عندما يكون الاختبار المقدَّم صحيحًا أو خطأ على الترتيب، وتُقيَّمان إلى `nil` فيما عدا ذلك.

ويمكن أن يحتوي القسم الذي يلي تعبير الاختبار على أكثر من تعبير واحد.

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## الجملة الشرطية ذات الفرعين

تُقيّم الجملة الشرطية `if` التعبير الأول من جسمها عندما يكون الاختبار صحيحًا، والثاني فيما عدا ذلك.

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

لاحظ أن كلا الفرعين، فرع "ثم" وفرع "وإلا"، لا يمكن أن يحوي إلا تعبيرًا واحدًا.

## الجمل الشرطية متعددة الفروع

الجملة الشرطية "العظمى" في Lisp هي `cond`، ويمكن أن تحتوي على عدد لا نهائي من الفروع.
لكل فرع شرط اختبار وتعبير جسم محاطان بزوج إضافي من الأقواس الهلالية.
وإذا قُيّمت جميع الاختبارات إلى خطأ، فستُرجع القيمة `nil`.

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

لاحظ أنه لا حدّ لعدد التعبيرات بعد تعبير الاختبار. 


إذا أردت فقط اختبار قيمة واحدة مقابل عدد من الفروع، فيمكنك استخدام التعبير `case` الأبسط.
وإذا لم تطابق أي حالة، فستُرجع القيمة `nil`.
ويمكن استخدام كلٍّ من `t` و`otherwise` كحالة شاملة:

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

لاحظ أنه، مثل `cond`، لا حدّ لعدد التعبيرات بعد تعبير الاختبار.

## الجمل الشرطية المتخفّية

عمليتا `and` و`or` المنطقيتان في Common Lisp هما ماكروان يعملان بمبدأ الدارة القصيرة، ويمكن استخدامهما لتقليل تكرار بعض التعبيرات الشرطية.

إذا صادف ماكرو `and` قيمة خطأ واحدة، فسيُرجع `nil` فورًا، وإلا فسيُرجع آخر قيمة صحيحة:

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

يُرجع ماكرو `or` أول قيمة صحيحة يصادفها، أو `nil` إذا لم توجد أي قيمة صحيحة:

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## لقد استنفدتُ طاقتي...

كما ذُكر سابقًا، عندما لا يطابق أي فرع في عبارة `case`، ولا توجد حالة `otherwise`، فستُرجع القيمة `nil`.
غير أنه ينبغي أحيانًا اعتبار عدم مطابقة أي فرع خطأً، وهنا يأتي دور `ecase` (للمطابقة **الشاملة**).

ويُستخدم بالأسلوب نفسه تمامًا مثل `case`، لكنه يرفع خطأً بدلًا من إرجاع `nil` عندما لا يوجد تطابق.

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
