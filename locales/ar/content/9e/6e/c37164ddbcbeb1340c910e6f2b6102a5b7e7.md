# مقدمة

## المصفوفات

أي بيانات في لغة التجميع هي سلسلة من البايتات.
وهذا يعني أنه يمكن النظر إلى أي بيانات على أنها **مصفوفة** من تلك البايتات الأساسية.

### الوصول إلى العناصر في مصفوفة

للوصول إلى أي قيمة في الذاكرة، من الضروري حساب **عنوانها الفعّال**.
العنوان الفعّال هو تعبير قد يتكوّن من:

- _عنوان أساسي_، على سبيل المثال العنوان الذي يشير إليه وسم متغير.
- _سجل فهرس_ واحد، وقد يكون مضروبًا في `1` أو `2` أو `4` أو `8`.
- _إزاحة_ موقّعة بطول 32 بت، وهي عدد يُضاف إلى العنوان الأساسي (أو يُطرح منه).

لاحظ أن هذا العنوان يبدأ فهرسته من 0، لذا فإن العنوان الأساسي، دون أي إزاحة، يشير إلى أول بايت في المتغير.
ولهذا السبب، فإن إلغاء الإشارة إلى الذاكرة باستخدام وسم فقط دون أي إزاحة، كما فعلنا في المفاهيم السابقة، يعطي قيمة تبدأ من البايت الأول فيها:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
‏x86-64 يستخدم [النهاية الصغرى][endianness].
وهذا يعني أن أقل بايت أهميةً في قيمة متعددة البايتات يُخزَّن في أصغر عنوان في الذاكرة.

وبالتالي، عند الوصول إلى البايتات الفردية لقيمة متعددة البايتات، من الضروري إضافة إزاحة موجبة إلى العنوان الأساسي للوصول إلى بايتات أكثر أهمية.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

المتغير المُهيّأ المُعلَن بقائمة قيم هو مصفوفة من تلك القيم، ولكل عنصر الحجم المحدد.
ومع ذلك، فإن الإزاحات دائمًا بوحدة **_البايتات_**، حتى عندما يكون حجم كل عنصر في المصفوفة أكبر:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

لاحظ أنه بما أن العناوين بالبايتات، فمن الممكن الوصول مباشرة إلى بايت فردي لأي عنصر في المصفوفة:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

وللسبب نفسه، من الممكن الوصول إلى أكثر من حجم عنصر واحد في تعليمة واحدة:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
لا تُجري لغة التجميع أي تحقق من الحدود عند الوصول إلى المصفوفات.
الفهرس الذي يتجاوز نهاية المصفوفة يقرأ أو يكتب في ذاكرة خارجها.
قد يؤدي هذا إلى نتائج خاطئة دون أي إنذار، وإلى إتلاف بيانات أخرى، وإذا لم تكن الذاكرة التي جرى الوصول إليها مُعيَّنة، إلى خطأ وقت التشغيل.
المبرمج مسؤول عن إبقاء كل عنوان فعّال داخل المصفوفة.
~~~~

### حساب حجم مصفوفة مُهيّأة

يحتوي NASM (‏The Netwide Assembler، وهو المُجمِّع المستخدم في هذا المسار) على رمز خاص (`$`) يشير إلى الموقع الحالي في الذاكرة.
يوفر هذا الرمز أسلوبًا ملائمًا لحساب الحجم الكلي الذي تشغله مصفوفة في الذاكرة:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

عند استخدامه مباشرة بعد `example`، يحمل `$` عنوان نهاية المصفوفة في الذاكرة.
وهذا يعني أن `$ - example` هو الفرق بين ذلك العنوان والعنوان الذي يشير إليه الوسم `example`.
وهذا بالضبط هو الحجم الكلي، بالبايتات، الذي تشغله المصفوفة التي يشير إليها `example`.

إذن، بتعريف `example_length` بهذه القيمة، أنشأنا متغيرًا بحجم 8 بايتات يخزّن حجم المصفوفة، أو طولها، بالبايتات.

### القسم .bss

تُعلَن البيانات غير المُهيّأة في **القسم .bss**.
على معظم المنصات، يملأ نظام التشغيل هذه البيانات بالأصفار عند بداية البرنامج.

في NASM، يتكوّن المتغير غير المُهيّأ من اسم، وتوجيه يحدد حجم البيانات، وعدد العناصر المطلوب حجزها.
ويفصل بين كل من هذه العناصر مسافة.

التوجيهات الرئيسية وأحجام البيانات المرتبطة بها هي:

| التوجيه | الحجم    |
| :-------: | :------ |
|   resb    | 1 بايت  |
|   resw    | 2 بايت |
|   resd    | 4 بايت |
|   resq    | 8 بايت |

على سبيل المثال، هذا يحجز مساحة غير مُهيّأة بحجم `3` بايت في متغير باسم `example`:

```x86asm
section .bss
    example resb 3
```

وهذا يحجز مساحة غير مُهيّأة بحجم `10` مضروبة في `8` بايت (أي `80` بايت) في متغير باسم `arr`:

```x86asm
section .bss
    arr resq 10
```

المتغيرات في `section .bss` قابلة للتعديل، أي يمكن القراءة منها والكتابة فيها.

يمكن الوصول إلى البيانات غير المُهيّأة كما يُ accessed إلى البيانات المُهيّأة، وذلك باستخدام عنوانها الفعّال.
وبالمثل، فإنها أيضًا ذات مدة تخزين ساكنة، ويمكن الوصول إليها من أي دالة في ملف المصدر نفسه (وإذا أُعلنت `global`، فمن ملفات مصدر أخرى أيضًا).

### الوصول إلى عناوين المصفوفات باستخدام تعليمة `lea`

كما استعرضنا في مفهوم سابق، تحسب تعليمة `lea` عنوان ذاكرة فعّالًا.
ويمكن استخدامها لحساب عنوان أي عنصر في مصفوفة، وفق الدلالات نفسها.

لاحظ أنه في العنونة النسبية غالبًا ما يكون من الضروري تحميل عنوان المتغير في سجل قبل تكوين عنوان أكثر تعقيدًا:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
من مزايا `lea` أنها تستخدم حساب العناوين لاحتساب قيمة دون الوصول فعليًا إلى الذاكرة في ذلك العنوان.
وهذا يجعلها مفيدة لإجراء عمليات حسابية حتى عندما لا يحمل أي من السجلات عنوان ذاكرة:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
