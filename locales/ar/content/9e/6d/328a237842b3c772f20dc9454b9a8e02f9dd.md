# مقدمة

كما رأينا في مفهوم [`Nothingness`][concept-nothingness]، توفّر R طرقًا متعددة لتمثيل البيانات الغائبة (`NULL`) أو المجهولة (`NA`) أو غير الصالحة رياضيًا (`NaN`, `Inf`).
وبشكل عام، تحاول R استخدام هذه القيم للإشارة إلى المشكلات في مكانها، ثم تواصل التنفيذ دون رفع استثناء.

## `stop()`

بعض المشكلات أساسية إلى حد لا يسمح للبرنامج بالاستمرار. 
في هذه الحالة، استخدم `stop(msg)` لإيقاف البرنامج فورًا مع خطأ `Error` وطباعة `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

تشبه هذه الدالة `assert` في لغات أخرى، وهي غلاف مريح حول `stop()`. 
معاملاتها عدد اعتباطي من الشروط المنطقية المفصولة بفواصل، ولن يستمر البرنامج إلا إذا كانت جميعها `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

تمتلك R طرقًا متنوعة للتعامل مع الأخطاء.
وهي مستندة إلى Common Lisp وتختلف اختلافًا كبيرًا عن كثير من اللغات الشائعة.

أبسط هذه الطرق هو تغليف الكود الذي قد يسبب مشكلة داخل `try()`.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()` و`message()`

هذه استجابات لحالات غير قاتلة، على سبيل المثال:

- للتحذير من مشكلة يمكن للبرنامج أن يتعافى منها جزئيًا على الأقل.
- لإخبار المستخدم بالتقدّم المحرز في برنامج يستغرق وقتًا طويلًا.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

قد تفيد دالة `suppressWarnings()` أحيانًا داخل Exercism، لتجنّب إرباك مشغّل الاختبارات بمخرجات غير مرغوبة.
