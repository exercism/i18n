# نبذة

في Gleam، يمكن استخدام تعبير `case` لتنفيذ الكود شرطيًا. فبتعبير `case` يمكن اختبار قيمة ما مقابل نمط واحد أو أكثر من _الأنماط_. ومن أمثلة هذه الأنماط _النمط الحرفي_، وهو يطابق قيمة مقابل قيمة حرفية (مثل `1` أو `"hello"`).

تُكتب تعبيرات `case` باستخدام الكلمة المفتاحية `case`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    1 -> "One"
  }
}
```

قد يبدو هذا مشابهًا لعبارات `switch` في لغات أخرى، لكن مطابقة الأنماط تتألق حقًا حين تستخدم أنماطًا أخرى أيضًا. ومن هذه الأنماط _نمط المتغير_، الذي يتيح إسناد قيمة إلى متغير. في هذا المثال، سيُسند إلى المتغير `i` قيمة `number` إذا لم تكن `0`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i -> "Non zero"
  }
}
```

في بعض الحالات، قد ترغب في إضافة شرط إضافي إلى نمط ما. ويُعرف هذا باسم _الحارس_ (الشرط)، ويمكن إضافته باستخدام الكلمة المفتاحية `if`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
  }
}
```

لأسباب تتعلق بالأداء، لا يُسمح في الحوارس إلا بالعوامل الرياضية والمنطقية الأساسية، ولا يمكن استخدام دوال أخرى فيها.

في المثال أعلاه، لن يكون لكل مُدخل ممكن نمط مطابق له. سيكتشف المصرّف ذلك ويُصدر خطأ. ويُعرف هذا باسم _التحقق الشامل_. ولحل التحذير، عليك معالجة جميع الحالات. ولهذا يمكن استخدام _نمط التجاهل_، وهو نمط يطابق أي قيمة:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
    _ -> "Positive number"
  }
}

// No compiler error
```

تختبر تعبيرات `case` قيمة ما مقابل كل نمط من الأعلى إلى الأسفل، حتى تجد نمطًا مطابقًا وتنفّذ المنطق المرتبط بذلك النمط. ترتيب الأنماط مهم!
