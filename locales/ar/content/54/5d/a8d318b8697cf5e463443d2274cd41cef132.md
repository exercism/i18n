# مقدمة

**عدد الفاصلة العائمة** هو عدد يمكن أن يكون له جزء كسري، مثل `-1.23` أو `3.1415`.

ولتمثيل مثل هذا العدد على هيئة سلسلة من البايتات، تستخدم x86-64 معيار **IEEE-754**.
وأكثر صيغتين شيوعًا في هذا المعيار هما أعداد الفاصلة العائمة ذات الدقة المفردة وأعداد الفاصلة العائمة ذات الدقة المزدوجة.
وتدعم x86-64 كلتيهما.

يبلغ عرض عدد الفاصلة العائمة ذي الدقة المفردة 32 بت، بينما يبلغ عرض العدد ذي الدقة المزدوجة 64 بت.

## سجلات XMM

في x86-64، هناك 16 سجلًا مخصصًا لإجراء العمليات الحسابية على الفاصلة العائمة، تسمى `xmm0` إلى `xmm15`.

عرض هذه السجلات 128 بت على الأقل، لكن المعالجات الحديثة ترفع ذلك إلى 256 بت أو 512 بت.
ومع ذلك، في الواقع العملي لا تستخدم معظم أعداد الفاصلة العائمة إلا أدنى 32 بت أو 64 بت، حسب الدقة المطلوبة.

## التحويل بين الأعداد

هناك عائلة من التعليمات للتحويل بين صيغ الأعداد: `cvtxx2yy`.

‏`xx` و`yy` ليسا قيمتين حرفيتين، بل عنصرين بديلين:

- ‏`xx` عنصر بديل لنوع المُعامَل المصدر.
- ‏`yy` عنصر بديل لنوع المُعامَل الوجهة.

ويمكن أن يتخذ هذا العنصر البديل أشكالًا كثيرة، منها:

| العنصر البديل | المعنى               |
| ----------- | --------------------- |
| `si`        | عدد صحيح بإشارة        |
| `ss`        | فاصلة عائمة 32 بت |
| `sd`        | فاصلة عائمة 64 بت |

على سبيل المثال:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

لاحظ أنه يمكن تحويل عدد صحيح 32 بت إلى عدد فاصلة عائمة 64 بت، أو عدد صحيح 64 بت إلى عدد فاصلة عائمة 32 بت.
وبالمثل، يمكن أيضًا تحويل عدد فاصلة عائمة 32 بت إلى عدد صحيح 64 بت، أو عدد فاصلة عائمة 64 بت إلى عدد صحيح 32 بت.
بعبارة أخرى، لا يلزم أن يكون حجم المُعامَلين في `cvtxx2yy` _متماثلًا_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

عندما يتعذّر التعبير عن عدد الفاصلة العائمة بدقة على هيئة عدد صحيح، تقوم `cvtxx2si` بتقريب العدد وفقًا لتحكم التقريب الموجود في سجل خاص يسمى `mxcsr`.
وقد يكون هذا التقريب تقريبًا إلى الأقرب، أو إلى الأسفل، أو إلى الأعلى، أو اقتطاعًا.
ولا توجد قيمة افتراضية مضمونة عند دخول الدالة.

لاحظ أن النتيجة الدقيقة لا تُقرَّب، وبالتالي لا يتأثر بها تحكم التقريب.
على سبيل المثال، سيُحوَّل `42.0` _دائمًا_ إلى `42`.

وهناك عائلة مشابهة من التعليمات بصيغة `cvttxx2si` (بحرف `t` إضافي) تقتطع النتيجة دائمًا.

## التقريب

تُحوِّل عائلة التعليمات `roundxx` عدد الفاصلة العائمة في المُعامَل المصدر إلى عدد فاصلة عائمة مُقرَّب يُخزَّن في المُعامَل الوجهة.

وهنا، `xx` عنصر بديل لنوع المُعامَلين، كما هو معتاد: `ss` للدقة المفردة و`sd` للدقة المزدوجة.

وتأخذ هذه التعليمات عددًا ثابتًا كمُعامَل ثالث.
ويشير هذا العدد إلى نمط التقريب:

| العدد | النمط         |
| :----- | :----------- |
| 0      | الأقرب      |
| 1      | الأرضية (إلى الأسفل) |
| 2      | السقف (إلى الأعلى)    |
| 3      | الاقتطاع     |

على سبيل المثال:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

بما أن هذه التعليمات تنتج نتيجة دقيقة، فيمكن استخدامها تحضيرًا لـ `cvtxx2si`.

## تعليمات الحساب

تتخذ كثير من العمليات على أعداد الفاصلة العائمة تعليمات تشبه في أسمائها نظيراتها الخاصة بالأعداد الصحيحة، لكن مع إضافة العنصر البديل اللازم (`ss` أو `sd`) في النهاية.
وهذه التعليمات ثنائية المُعاملات، وبالدلالة المعتادة، حتى تلك التي تنفذ الضرب أو القسمة:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## النقل

التعليمات الخاصة بالنقل من سجل XMM إلى آخر هي `movss` أو `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

**لا** يمكن نقل قيمة فورية (عدد صحيح ثابت بإشارة) إلى سجل xmm مباشرة.
يجب أولًا نقل هذا العدد إلى سجل الأغراض العامة ثم تحويله باستخدام `cvtsi2xx`:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## المقارنات

هناك مجموعتان من التعليمات لإجراء مقارنة بين عددي فاصلة عائمة.
وهما على الصيغة `comixx` و`ucomixx`، حيث `xx` إما `ss` أو `sd`.
وكلتاهما تضبطان الأعلام في `rflags` كما هو معتاد، وفقًا للدلالة نفسها التي يتبعها `cmp`.

والفرق بينهما أن `ucomixx` تضبط `parity flag (PF)` إذا كان أحد عددي الفاصلة العائمة يحمل القيمة `NaN`، بينما ترفع `comixx` استثناءً في هذه الحالة.

والمقارنة بين قيم الفاصلة العائمة هي مقارنة _بلا إشارة_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## اصطلاح الاستدعاء

في System V ABI، تُمرَّر أول ثمانية وسائط من نوع الفاصلة العائمة إلى الدوال بالترتيب، من `xmm0` إلى `xmm7`.
وتُرجَع قيم الفاصلة العائمة من الدوال في `xmm0`، وعند الحاجة في `xmm1`.

جميع سجلات `xmm` متاحة للاستخدام بحرية، ولا شيء منها محجوز للمُستدعي.

## الذاكرة

يمكن تعريف قيم الفاصلة العائمة في الذاكرة وفقًا للدلالة نفسها المتبعة مع الأعداد الصحيحة بالحجم نفسه.
كما يسمح NASM (The Netwide Assembler، وهو المُجمِّع المستخدم في هذا المسار) بالإعلان عن قيم الفاصلة العائمة بالترميز العلمي.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```
