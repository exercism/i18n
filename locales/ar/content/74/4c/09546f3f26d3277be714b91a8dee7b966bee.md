# مقدمة

## التطبيق الجزئي

جميع الدوال في Elm [مُكرَّاة][currying]، وهذا يعني أنك إذا استدعيت دالة دون تمرير جميع الوسائط، فإنها تُرجع دالة جديدة.

تُسمّى نتيجة القيام بذلك [التطبيق الجزئي][partial-application] (فأنت لا تمرّر جميع الوسائط إلى الدالة، بل تطبّق بعضها تطبيقًا جزئيًا).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

التطبيق الجزئي يطبّق الوسائط دائمًا بالترتيب.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## عامل الأنبوب (`|>`)

قولنا `x |> f` هو تمامًا مثل `f x`. ومن الأمثلة الملموسة أن `"5" |> String.toInt` هو نفسه `String.toInt "5"`.

قد لا يبدو هذا مفيدًا كثيرًا في البداية، لكنه يُسمّى [عامل الأنبوب][pipe-operator] لأنه يتيح لك كتابة كود على شكل خط أنابيب.

على سبيل المثال، لنفترض أن لدينا دالة `sanitize` لتحويل مدخلات المستخدم إلى أعداد صحيحة:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

يمكننا إعادة كتابتها هكذا:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

يتجنّب هذا استخدام الأقواس، ويُظهر الدوال بالترتيب الذي تُطبَّق به (أولًا `String.trim`، ثم `String.toInt`)، مما يساعد على سهولة القراءة.

يوجد أيضًا [عامل الأنبوب المعكوس `(<|)`][reverse-pipe-operator].
قولنا `f <| x` هو تمامًا مثل `f x`.
ولا يبدو هذا مفيدًا كثيرًا للوهلة الأولى أيضًا، وهو بالتأكيد لا يُستخدم بقدر عامل الأنبوب، لكنه يساعد على تجنّب الأقواس في بعض الحالات.

## تركيب الدوال / الأسلوب الخالي من النقاط

عامل [`(>>)`][forward-composition] نوعه `(a -> b) -> (b -> c) -> (a -> c)`، وهو يُنشئ دالة من النوع `a -> c` عبر تركيب دالتين متوافقتين من النوع `a -> b ` و `b -> c`.
وهو يفعل ذلك بأخذ الناتج (من النوع `b`) من الدالة الأولى واستخدامه وسيطًا أول للدالة الثانية (التي يجب أن تكون من النوع نفسه `b`).
وستأخذ الدالة المُنشأة المدخل نفسه (من النوع `a`) الذي تأخذه الدالة الأولى، وستُرجع القيمة `c` التي تُرجعها الدالة الثانية.

ومن الأمثلة الملموسة `String.trim >> String.toInt`.
تأخذ `String.trim` سلسلة نصية كمعاملها الوحيد، فهذا ما تأخذه الدالة المُنشأة.
وتُرجع `String.toInt` قيمة `Maybe Int`، فهذا ما تُرجعه الدالة المُنشأة.
وتُرجع `String.trim` سلسلة نصية تقبلها `String.toInt` كمعامل، لذا يُترجم المثال بنجاح.

يمكننا الآن إعادة كتابة دالة `sanitize` على النحو التالي:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

لاحظ أننا لم نعد نستخدم المعامل `input` الذي تراه في المثال الأصلي، مع أن الوظيفة متطابقة.
تُسمّى هذه الطريقة في إنشاء الدوال التي لا تشير إلى معاملاتها "الأسلوب الخالي من النقاط".
وميزة هذا الأسلوب أن الكود أكثر إيجازًا، وعيبه أنه قد يكون أصعب في الفهم، خاصة للمبتدئين.

يجدر التذكير بأن جميع الدوال مُكرَّاة في Elm، لذا فإن `String.length >> max` يُترجم بنجاح.

- عامل [`(>>)`][forward-composition] نوعه `(a -> b) -> (b -> c) -> (a -> c)`.
- نوع `String.length` هو `String -> Int`، وهو الجزء `(a -> b)`، إذن `a` هو `String` و `b` هو - `Int`.
- نوع `max` هو `Int -> Int -> Int`، وهو الجزء `b -> c`.
- `b` هو `Int`، لذا يُطبَّق `max` جزئيًا، ومن ثمّ فإن `c` هو نتيجة هذا التطبيق الجزئي (`Int -> Int`).
- إذن نوع `String.length >> max` هو `String -> (Int -> Int)`.
- إذن قيمة `((String.length >> max) "123") 2` هي `3`، لأن طول `"123"` يساوي 3، وهو أكبر من 2 القادم من وسيط `Int`.

## تصميم الدوال

لتسهيل كتابة كود أنيق في Elm، ينبغي أن تجعل بنية البيانات الرئيسية آخر معامل في الدوال.
وتفعل جميع الدوال الشائعة في المكتبة القياسية ذلك، مثل `List.map` (توقيع النوع أدناه).

```elm
map : (a -> b) -> List a -> List b
```

نرى هنا أن آخر معامل لدالة `map` هو `List a` وأنها تُرجع `List b`، لذا فإن بنية البيانات الرئيسية (`List`) هي آخر معامل.

وهذا يجعل من الممكن كتابة كود أنيق على شكل خط أنابيب، كما في المثال أدناه.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

كما يجعل من المريح استخدام تركيب الدوال والأسلوب الخالي من النقاط، كبديل عن أسلوب خط الأنابيب.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

يتيح لك تركيب الدوال أيضًا اختصار هذا المثال إلى استدعاء واحد لـ `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
