# حول

التحليل هو عملية تحويل النص إلى بيانات ذات معنى. ودوال حزمة `String` محدودة في هذا الجانب، والتعبيرات النمطية صعبة الاستخدام، لذا فإن الأسلوب المألوف في Elm للتحليل هو استخدام حزمة `elm/parser`.

لنستعرض مثالًا على كتابة محلّل لمجموعة فرعية من لغة البرمجة [LOLCODE][lolcode].
لننظر إلى البرنامج التالي المشروح بالتعليقات:

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

أولًا، لنكتب نوعًا في Elm يمثّل الأوامر الممكنة:

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

يمكننا بعد ذلك تمثيل برنامج LOLCODE على هيئة `List Command`.
لنبدأ بمحلّل لسطر `HAI 1`:

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

بُني `versionP` باستخدام _خط أنابيب المحلّل_.
يعني العامل `(|.)` "حلّل السلسلة النصية ثم تخلّص من الناتج"، ويعني `(|=)` "حلّل السلسلة النصية واحتفظ بالناتج".
في هذا المثال، سيستهلك `Parser.keyword "HAI"` كلمة `HAI`، لكن هذا الناتج يُتجاهل.
وسيستهلك `Parser.spaces` أي عدد من المحارف `' '` و`'\n'` و`'\r'`، لكن ذلك سيُتجاهل أيضًا.
سيحلّل `Parser.int` عددًا صحيحًا، وستُمرَّر قيمة ذلك العدد الصحيح (لنقل 1) إلى `Parser.succeed Version` الأعلى في خط الأنابيب، وسينجح المحلّل في إرجاع القيمة `Version 1`.

إذا فشل أي محلّل من محلّلات خط الأنابيب، فسيُرجع `Parser.DeadEnd` وسيفشل المحلّل كله.
ويمكن تشغيل المحلّل باستخدام `Parser.run`:

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

لنتناول سطر "CAN HAS STDIO?" باستخدام

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP` أيضًا خط أنابيب محلّل، لكنه ينتهي هذه المرة بـ `Parser.symbol` المناسب لتحليل الرموز مثل `?`.
أما القيمة التي نريد الاحتفاظ بها (اسم الحزمة المطلوب استيرادها) فيحلّلها

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

بما أننا لا نعرف ما سيكون اسم الحزمة، فلا يمكننا استخدام `Parser.keyword`، وبدلًا من ذلك نستخدم `Parser.chompWhile` الذي سيستهلك المحارف واحدًا واحدًا ما دامت تحقّق شرطًا (هنا، أن تكون محرفًا أبجديًا رقميًا).
ثم تُجمع هذه المحارف المستهلكة بواسطة `Parser.getChompedString` الذي يُرجع `Parser String`.
وفي هذه الحالة نريد توحيد أسماء الحزم، لذا نستخدم `Parser.map` لتعديل السلسلة النصية الموجودة في المحلّل وتحويلها إلى أحرف صغيرة.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

بعد ذلك، يُحلَّل `VISIBLE "HAI WORLD!"` بواسطة

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

أصبح لدينا الآن محلّل لكل أمر.
وبالطبع، في برنامج عام لا يمكن التنبؤ بترتيب هذه الأوامر، لذا نبني محلّلًا عامًا للأوامر

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

سيجرّب `Parser.oneOf` محلّلًا واحدًا، وفق الترتيب المعطى.
فإذا فشل محلّل، يُجرَّب الذي يليه، أما إذا نجح، فيُرجَع ناتجه دون تجربة بقية المحلّلات.
وإذا فشلت جميع المحلّلات، يفشل `Parser.oneOf`.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

لاحظ كيف تُنتج كل محاولة فاشلة `Parser.DeadEnd` يجمعها `Parser.oneOf`.

ولتحليل برنامج كامل، علينا تحليل عدة أوامر بالتتابع باستخدام

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence` محلّل قابل للتخصيص بدرجة كبيرة، وله عدد من الخيارات.
تأخذ `start` و`separator` و`end` سلاسل نصية تفصل بين عناصر التسلسل؛ فتحليل مصفوفة في Elm يستخدم `[` و`,` و`]`.
ويمنح `spaces` مرونة بأن يأخذ محلّلًا يتعامل مع المسافات المحتملة بين العناصر والفواصل؛ فتحليل مصفوفة في Elm يستخدم `Parser.spaces`، لكننا هنا لا نقبل أي مسافات، لذا نستخدم `Parser.succeed ()` الذي ينجح فورًا دون أن يستهلك أي شيء فعليًا.
ويأخذ `item` محلّل العنصر، وأخيرًا يتيح لنا `trailing` أن نقرر ما إذا كانت الفواصل في النهاية `Parser.Forbidden` أو `Parser.Mandatory` أو `Parser.Optional`.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

عندما تنجح المحلّلات، تتوقف عن استهلاك السلسلة النصية

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

لذا إذا احتجنا إلى التأكد من أننا حلّلنا كل ما في السلسلة النصية، يمكننا استخدام `Parser.end`

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

أخيرًا، نحتاج أحيانًا إلى إفشال محلّل بناءً على المحتوى الذي حلّله.
على سبيل المثال، لو احتجنا إلى محلّل يُفشل البرامج التي تبدأ بأمري `HAI` متتاليين، لأمكننا استخدام

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

يستطيع `Parser.andThen` فحص محتوى المحلّل ويُرجع محلّلًا جديدًا بناءً على قيمته.
وهنا، أفشلنا المحلّل برسالة مخصّصة باستخدام `Parser.problem` في إحدى الحالتين، وأرجعنا القيمة الأصلية في الحالة الأخرى.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
