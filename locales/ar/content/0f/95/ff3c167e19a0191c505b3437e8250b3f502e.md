# نبذة

الاستثناءات شكل من أشكال معالجة الأخطاء.
سُمّيت استثناءات لأنها تظهر عادةً عند التعامل مع حدث غير متوقع.

في أي نقطة من الكود، يمكننا "raise" استثناء.
ونفعل ذلك باستخدام طريقة `raise`، بتمرير كائن إليها، وهو عادةً كائن Exception، وإن كان بإمكاننا أيضًا استخدام سلاسل نصية بسيطة.
على سبيل المثال، سترى في هياكل التمارين أننا نستخدم `RuntimeError` المدمج لنخبر Ruby بأن طريقة ما لم تُنفَّذ بعد.
يمكنك أيضًا استخدام الصيغة المختصرة `raise(ExceptionObject, params)`.
وإذا حذفت صنف الاستثناء، يُستخدم `RuntimeError` افتراضيًا.

على سبيل المثال:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

وعندما ترى Ruby هذا، تصعّد الخطأ إلى أعلى البرنامج ثم تخرج.

على سبيل المثال، إذا حاولت قسمة شيء على صفر، سترى شيئًا كهذا:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

من المهم أن تلاحظ أن الاستثناءات ينبغي أن تُستخدم في الحالات التي يقع فيها أمر استثنائي، أي خطأ يحتاج إلى معالجة خاصة.
ولا ينبغي استخدام الاستثناءات للتحكم في مسار البرنامج، لأن ذلك يُعدّ تصميمًا سيئًا، كثيرًا ما يؤدي إلى ضعف الأداء وصعوبة الصيانة.

## التسلسل الهرمي للأصناف

في Ruby تتبع الاستثناءات تسلسلًا هرميًا للأصناف، حيث يكون `Exception` هو الصنف الأساسي.
وهذه أكثر الاستثناءات المدمجة شيوعًا في Ruby:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

التقاط أخطاء صنف معيّن يعني أيضًا التقاط أخطاء أصنافه الفرعية.
ولهذا قد يكون التقاط `Exception` خطيرًا.
تستخدم Ruby الاستثناءات أيضًا للتعامل مع رسائل "الإشارات" الصادرة عن نظام التشغيل، مثل `ctrl-c`.
وهذا يعني أن التقاط `Exception` سيلتقط أيضًا "الإشارات" الصادرة عن النظام.
لذلك، ولتفادي السلوكيات غير المتوقعة، فالممارسة الشائعة لالتقاط "جميع الأخطاء" هي الالتقاط من `StandardError`.

## صيغة الالتقاط

توفّر Ruby أيضًا جمل التقاط موسّعة للحالات التي تتطلب معالجة خاصة:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

قد يفيد هذا، على سبيل المثال، عند التعامل مع إدخال وإخراج الشبكة، حيث نحتاج دائمًا إلى تذكّر إغلاق الاتصال.

يمكن لكتل التقاط في Ruby أيضًا استخدام الكلمة المفتاحية `retry`، التي تعيد تنفيذ كل ما بين begin وrescue:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
