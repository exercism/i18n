# مقدمة إلى الأنابيب وقوائم الأوامر

رأينا كيف نكتب أوامر بسيطة، حيث يأتي بعد الأمر وسائط.
الآن سنرى كيف نبني أوامر أكثر تعقيدًا بتركيب أوامر بسيطة.

## المدخلات والمخرجات

قبل أن نبدأ، مقدمة سريعة عن المدخلات والمخرجات.

للعمليات "قنوات إدخال وإخراج قياسية".

* يمكن للعملية أن تستهلك _المدخلات_ على "stdin".
* يمكن للعملية أن تُخرج _المخرجات_ على "stdout".
* يمكن للعملية أن تُخرج _مخرجات الأخطاء_ على "stderr".

الأمر `tr` مثال نقي جدًّا على ذلك.
كل ما يفعله هو قراءة النص من مدخله، وإجراء تحويلات للحروف، وطباعة النص الناتج إلى مخرجه.

سنرى المزيد عن التعامل مع قنوات "stdio" لاحقًا في المنهج.

## الأنابيب

هذه إحدى "الميزات القاتلة" في برمجة الصدفة.
تتيح لك الأنابيب إنشاء تحويلات متقدمة على تدفق من النصوص.

لإنتاج قائمة مرتبة بأسماء المستخدمين:

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

يربط رمز الأنبوب (`|`) مخرجات أمر واحد بمدخلات أمر آخر.
يقرأ `cut` مخرجات `cat`، ويقرأ `sort` مخرجات `cut`.

~~~~exercism/advanced
* افتراضيًّا، يعمل كل أمر في الأنبوب داخل صدفة فرعية منفصلة.
  (الصدفة الفرعية عملية ابنة تكون نسخة من الصدفة قيد التشغيل حاليًّا.)

* هناك تكلفة أداء لتشغيل الأنابيب.
  إذا وجدت نفسك أمام أنابيب طويلة من أوامر متشابهة، ففكّر في دمجها في أمر واحد.
  على سبيل المثال، يمكن عمومًا دمج الأنابيب التي تستخدم عدة نسخ من `grep` و`cut` و`sed` و`awk` و`tr` في أمر `awk` واحد لتحسين الكفاءة.

* حالة الخروج للأنبوب هي حالة الخروج لآخر أمر فيه.
  وهذا يعني أنه إذا فشل أمر سابق لكن نجح الأمر الأخير، فستكون حالة الخروج للأنبوب كله صفرًا.

  هناك إعداد في الصدفة يمكنه تغيير ذلك؛
  إذا كان إعداد "pipefail" مفعّلًا (عبر `set -o pipefail`)، فستكون حالة الخروج للأنبوب:
  * صفرًا إذا نجحت كل الأوامر، وإلا
  * _حالة الخروج **الأخيرة** غير الصفرية_ للأوامر في الأنبوب.
~~~~

## قوائم الأوامر

قائمة الأوامر هي تسلسل من الأنابيب تفصل بينها `;` (أو سطر جديد) أو `&&` أو `||`.

* `A; B` قائمة أوامر يُنفَّذ فيها `B` بعد اكتمال `A`.
* `A && B`، حيث يُنفَّذ `B` فقط إذا نجح `A` (خرج بحالة صفر).
* `A || B`، حيث يُنفَّذ `B` فقط إذا فشل `A` (خرج بحالة غير صفرية).

حالة الخروج لقائمة الأوامر هي حالة الخروج لآخر أمر نُفِّذ.

يمكن ربط عاملي `&&` و`||` بحيث يُنفَّذ الأمر التالي شرطيًّا بناءً على حالة الأوامر السابقة.
على سبيل المثال

```bash
A && B && C && D || E
```

* يُنفَّذ B إذا نجح A،
* يُنفَّذ C إذا نجح A وB،
* يُنفَّذ D إذا نجح A وB وC،
* يُنفَّذ E إذا فشل **أي** من A أو B أو C أو D.

~~~~exercism/caution
استخدم هذه العوامل المنطقية باعتدال.
فقد تؤدي سريعًا إلى كود غير قابل للقراءة، أو إلى منطق يصعب فهمه.

على سبيل المثال، قد تظن أن هذين المقطعين متطابقان:

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

الفرق هو: متى يُنفَّذ C؟

* في المقطع الأول (الجملة الشرطية)، لن يُنفَّذ C إلا إذا فشل A.
* في المقطع الثاني، سيُنفَّذ C إذا فشل A _أو إذا نجح A لكن فشل B_!
~~~~

### استخدامات قوائم الأوامر

إليك مثالين حيث يمكن لقوائم الأوامر أن تبسّط الكود.

#### قراءة كتل من الأسطر من ملف

لنفترض أن لديك ملف بيانات يحتوي على بيانات عن مثلثات،
ويُمثَّل المثلث بثلاثة أسطر منفصلة تحمل أضلاع المثلث.

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

يمكنك استخدام حلقة `while` يكون شرطها ثلاثة أوامر `read` منفصلة:

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

بافتراض أن `is_pythagorean` أمر يحدّد ما إذا كانت الأضلاع الثلاثة تحقق معادلة فيثاغورس، فستكون المخرجات:

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### التأكيدات

تحتوي كثير من لغات البرمجة على شكل من أشكال التأكيد حيث يُطرح استثناء إذا فشل شرط ما

```
assert(user == "Administrator", "wrong user");
```

يمكننا استخدام عامل OR في Bash لمحاكاة تلك الدالة:

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## اعتبارات الأسلوب

تصبح قوائم الأوامر الطويلة صعبة القراءة بسرعة.
ويمكن أن يساعد الاستخدام السخي للأسطر الجديدة كثيرًا.

تأمّل هذا المثال حيث تُضاف كلمة إلى مصفوفة إذا تحقق شرطان.

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

يتيح لك Bash إضافة سطر جديد بعد أنبوب أو عامل منطقي.

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

لكن قد يسهل تفويت العامل في نهاية السطر.
استخدام _متابعة السطر_ يعني أنه يمكنك وضع العامل أولًا، ما يجعل استمرار القائمة أوضح:

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
_متابعة السطر_ هي تسلسل الحرفين "شرطة مائلة عكسية" و"سطر جديد" (`\` + `\n`).
عندما يرى Bash هذا التسلسل، يُحذف ببساطة من الكود، وبذلك _يُكمل_ السطر الحالي بالسطر التالي.
احرص على ألا تضع أي مسافات بين الشرطة المائلة العكسية والسطر الجديد.
~~~~

إليك مثالًا آخر

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

أو

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
