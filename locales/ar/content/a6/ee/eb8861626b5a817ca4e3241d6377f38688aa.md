# نبذة

روبي لغة ديناميكية وذات أنواع صارمة.
في اللغات الديناميكية يُحدَّد نوع المتغير أو الكائن وقت التشغيل، وهذا يعني أنه يمكن تغيير قيمته أو نوعه حتى آخر لحظة (حين يفسّره المفسّر).
وماذا نعني بأنواع صارمة؟
بمجرد أن نعرف نوع متغير أو كائن، تكون روبي صارمة بشأن ما يمكنك فعله به، على سبيل المثال:

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**لكن**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

تذكّر أن كل شيء في روبي كائن.
حتى الأصناف هي نسخ من الصنف `Class`.

على سبيل المثال:

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

هذا يعني أننا نستطيع تعريف الأصناف بهذه الطريقة أيضًا:

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

وأخيرًا، ضع في اعتبارك أن كائن `Integer` يحمل قيمًا قد تُعرَّف على أنها رقم واحد أو أكثر من الأرقام (المتتالية)، وأن طرقه تدعم الكثير من [العوامل الحسابية][integers-docs].

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
غالبًا ما تشير الكتابة في التوثيق إلى طرق النسخ بصيغة مثل `Class#method_name`، بينما تُشار إلى الطرق على مستوى الصنف أو الوحدة بصيغة `Class::method_name`.
ويُسمى `::` _عامل تحديد النطاق_، أي الثابت أو الطريقة على مستوى الصنف أو الوحدة الذي يجري الإشارة إليه.
ستصادف هذا في توثيق روبي، وفي القوائم البريدية ومجالات الدعم الأخرى.
وستجد أننا نشير في كتاباتنا إلى طرق الأصناف والوحدات بصيغة `ClassName.method_name` أو `ModuleName.method_name` بدلًا من ذلك.
~~~~
