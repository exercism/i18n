# مقدمة

## المحارف

**ترميز المحارف** هو اصطلاح محدد يُستخدم لتمثيل عناصر النص في لغة طبيعية على هيئة تسلسل من البايتات.
وقد يكون «عنصر النص» هنا أي وحدة لها دلالة في لغة طبيعية، مثل الحروف والمسافات وعلامات الترقيم والرموز التعبيرية والرسوم الفكرية وغيرها.

يدعم NASM (The Netwide Assembler، المُجمِّع المستخدم في هذا المسار) تعريف البيانات باستخدام **ASCII**.

قد يصل طول ثوابت المحارف في NASM إلى 8 بايتات، ويمكن تعريفها باستخدام علامتَي الاقتباس المفردتين (`'`) أو المزدوجتين (`"`) أو علامتَي الاقتباس الخلفيتين (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

يجب تعريف المحارف الخاصة بين علامتَي الاقتباس الخلفيتين مع تهريبها بالشرطة المائلة العكسية `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

لاحظ أنه لا يوجد دعم مدمج لأي ترميز محارف في x86-64 كنوع مستقل.
فالبيانات في لغة التجميع تسلسل من البايتات، وترك تفسير تلك البايتات كمحرف أو عدد أو أي شيء آخر للمبرمج.

على سبيل المثال، المحرف '0' في ASCII بايت واحد قيمته 48.
لذا، فإن تخزين القيمة 48 في بايت واحد مطابق تمامًا لتخزين المحرف '0' في ASCII:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

وللسبب نفسه، تتم معالجة المحارف عبر تحويل القيم في تلك البايتات مباشرةً:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## السلاسل النصية

**السلسلة النصية** هي تسلسل من المحارف.
وفي لغة التجميع، تُنفَّذ عادةً على هيئة مصفوفة.

يمكن تعريف سلسلة نصية في NASM بالطريقة نفسها التي يمكن بها تعريف أي مصفوفة:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

من الفروق بين السلاسل النصية والمصفوفات الأخرى أن NASM يدعم أيضًا تعريف السلاسل دون فاصلة (`,`) تفصل بين القيم.
كما يمكن أيضًا مزج القيم مع الفواصل:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

لاحظ أنه، كما ذُكر سابقًا، المحارف ليست سوى بايتات (أو تسلسل من البايتات في ترميز يونيكود):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

بما أن كل محرف ASCII يشغل بايتًا واحدًا، فإن أي بايت لاحق في حجم أوسع يكون `0`.
على سبيل المثال، تعريف `'a'` على هيئة qword (8 بايتات) يعني أن البايت الأول هو `'a'` (`97`) وبقية البايتات السبعة كلها `0`.

ولهذا السبب، فإن كل ما يلي متكافئ:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
في لغة التجميع، لا تُنهى السلاسل النصية تلقائيًا بمحرف NUL في ASCII (قيمته `0`).

وعند التعامل مع اللغات عالية المستوى، مثل C، تقع على عاتق المبرمج مسؤولية التأكد من إضافة المُنهي الصحيح، إن وُجد، في نهاية السلسلة النصية.
~~~~

## تعليمات السلاسل النصية

بما أن السلاسل النصية مصفوفات، يمكنك التعامل معها بالطريقة نفسها التي تتعامل بها مع أي مصفوفة، عبر إلغاء الإشارة إلى الذاكرة صراحةً:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

إضافةً إلى ذلك، هناك بعض التعليمات لتحميل القيم ونقلها وتخزينها في تسلسلات من البايتات في الذاكرة.
وعلى الرغم من تسميتها _تعليمات السلاسل النصية_، يمكن استخدامها مع أي تسلسل من البايتات في الذاكرة، أي مع أي مصفوفة.

أهم ثلاث تعليمات للسلاسل النصية هي `lods` و`stos` و`movs`:

| التعليمة | ما تفعله                                                                                                          |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | تحمّل قيمة من موضع ذاكرة يشير إليه `rsi` إلى `rax`                                                                |
| `stos`      | تخزّن قيمة من `rax` في موضع ذاكرة يشير إليه `rdi`                                                                 |
| `movs`      | تنسخ قيمة من موضع ذاكرة يشير إليه `rsi` وتخزّنها في موضع ذاكرة يشير إليه `rdi`                                    |

لاحظ أن تلك التعليمات لا تأخذ أي معامل صريح.
فمعاملاتها ضمنية.

وكقاعدة عامة:

1. عندما يكون معامل المصدر موضع ذاكرة، ينبغي تخزين عنوانه في `rsi` (`s` للمصدر).
2. عندما يكون معامل الهدف موضع ذاكرة، ينبغي تخزين عنوانه بدلًا من ذلك في `rdi` (`d` للهدف).
3. إذا لم يكن أحد المعاملات موضع ذاكرة، فهو السجل `rax`.

لاحظ أن تلك التعليمات تلغي الإشارة إلى عناوين الذاكرة تلقائيًا وفقًا للعملية المحددة التي تؤديها.

ويمكن لجميعها العمل بأحجام مختلفة.
وتُلحَق بها لاحقة لبيان هذا الحجم:

| اللاحقة | المعنى | الحجم    |
| :----: | ------- | :------ |
|  `b`   | بايت    | 1 بايت  |
|  `w`   | كلمة    | 2 بايتات |
|  `d`   | كلمة مزدوجة   | 4 بايتات |
|  `q`   | كلمة رباعية   | 8 بايتات |

على سبيل المثال:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

كما تُحدّث أي عنوان مستخدَم بمقدار حجم العملية.
ويتم هذا التحديث وفقًا لقيمة **راية الاتجاه (DF)**:

- إذا كانت راية `DF` مُصفَّرة، تزداد العناوين بمقدار حجم العملية.
- وإذا كانت راية `DF` مضبوطة، تنقص العناوين بدلًا من ذلك بالمقدار نفسه.

ينص معيار System V ABI على وجوب تصفير راية الاتجاه عند دخول الدالة.
لذا، فإن _السلوك الافتراضي هو قراءة الذاكرة والكتابة فيها بترتيب تصاعدي للعناوين_.

يمكن استخدام التعليمة `cld` لتصفير راية الاتجاه، بينما تُستخدم التعليمة `std` لضبطها:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
يتوقع المُستدعي أن تكون راية `DF` مُصفَّرة بعد عودة أي دالة مستدعاة، وفقًا لمعيار System V ABI.
وإذا ضبطت راية `DF` في أي وقت، فتأكد من تصفيرها قبل `ret`.
~~~~

### rep

بصرف النظر عن ذلك، لا تتفاعل التعليمة **rep** مباشرةً مع الذاكرة.
بدلًا من ذلك، يمكن إضافتها بادئةً للتعليمات الأخرى المذكورة، فـ_تكرّر_ تلك التعليمات.

وعندما تُسبق بـ`rep`، تتكرر تعليمات السلاسل النصية عددًا من المرات يساوي القيمة في `rcx`.
وفي كل مرة، تنقص القيمة في `rcx` بمقدار `1`.
لاحظ أنه يجب ضبط القيمة في `rcx` قبل استخدام التعليمة:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
على وحدات المعالجة المركزية الحديثة، غالبًا ما تكون `rep movs` و`rep stos` خيارين سريعين عند نقل البيانات في كتل كبيرة.
أما تعليمات السلاسل النصية الأخرى، وحتى `movs` و`stos` عند العمل دون `rep`، فهي عادةً أبطأ من حلقة عادية.

ويمكن العثور على نظرة أكثر تعمقًا حول هذا الموضوع في [الفصل 16.9، «تعليمات السلاسل النصية»، من هذا الكتاب المرجعي][agner-optimization-guide].
