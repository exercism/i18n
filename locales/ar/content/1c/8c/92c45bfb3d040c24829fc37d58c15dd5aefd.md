# نبذة

التحويل (casting) وتحويل النوع [طريقتان مختلفتان لتغيير تعبير من نوع بيانات إلى نوع آخر][wiki-casting].

تصنّف [وثائق C#][type-testing-and-cast-operators] تحويل النوع على أنه استخدام [عامل `as`][as-operator] أو [عامل `is`][is-operator]. أما التحويل فيُعرَّف على أنه استخدام [عامل التحويل][cast-operator].

في C#، وكثيرًا ما يحدث ذلك خارج نطاق القيم العددية والتسلسلات الهرمية للأصناف، ستضطر إلى إجراء تحويل عبر استدعاء أحد أعضاء النوع "الهدف" مثل [`Int32.Parse()`][int32-parse] الذي يحوّل سلسلة نصية إلى عدد صحيح، أو عبر استدعاء عضو من النوع "المصدر" مثل `object.ToString()`. وينبغي لمطوري JavaScript واللغات الديناميكية الأخرى أن ينتبهوا إلى ذلك.

لاحظ أن [عوامل][operator-overloading] التحويل الضمني والصريح (التي نناقشها في [concept:csharp/operator-overloading]()) متاحة، ويمكنها أن تتيح تحويلات شبه حرة إلى أنواعك الخاصة.

## تحويل الأنواع الأولية: ضمنيًا

نظام الأنواع في C# أكثر صرامة إلى حد ما من نظام _C_ أو JavaScript، ونتيجة لذلك تكون عمليات التحويل أكثر تقييدًا. يحدث [التحويل الضمني][implicit-casts] بين نوعين عدديين ما دام النوع "الهدف" قادرًا على الحفاظ على مدى قيمة النوع "المصدر" وإشارتها. لاحظ في الوثائق الاستثناء المتعلق بالتحويل إلى الأعداد الحقيقية حيث قد تُفقد الدقة.

لا تدلّ أي صيغة خاصة على التحويل الضمني. على سبيل المثال:

```csharp
int myInt = 1729;
long myLong = myInt;
```

لا يوجد تحويل ضمني لتعبير عددي (أو تعبير سلسلة نصية) إلى `bool`. وتوفّر مكتبة الأصناف الأساسية (BCL) الدالة `Convert.ToBoolean()` لهذا الغرض.

يمكن تحويل تعبير من النوع `char` ضمنيًا إلى `int`. أما التحويل في الاتجاه المعاكس فيجب أن يكون صريحًا. وليست كل قيم `int` محارف utf-16 صالحة.

## تحويل الأنواع الأولية: صريحًا

حيث لا يمكن تحويل الأنواع العددية ضمنيًا، يمكنك عمومًا استخدام [عامل][cast-operator] التحويل الصريح.

وحين لا يستطيع النوع "الهدف" تمثيل القيمة الجاري تحويلها لأنه ليس واسعًا بما يكفي أو لوجود تعارض في الإشارة، فقد يُطرح استثناء تجاوز السعة في حالة الأعداد الصحيحة، أو قد يأخذ متغير النوع "الهدف" القيمة `Infinity` في حالة الأعداد `float` و`double`.

يمكن تحويل تعبير من النوع `int` صراحةً إلى `char`. وقد ينتج عن ذلك محرف `char` غير صالح.

## أمثلة على تحويل الأنواع الأولية

```csharp
int largeInt = Int32.MaxValue;
int largeNegInt = Int32.MinValue;
ushort shortUnsignedInt = ushort.MaxValue;
float largeFloat = float.MaxValue;
float smallFloat = 17.29f;

// implicit cast
int from_ushort = shortUnsignedInt;          // 65535
float from_int = largeInt;                   // -21474836E+09
int from_char = 'a';                         // 96

// explicit cast
uint from_largeInt = (uint)largeInt;         // 2147483647
uint from_neg = (uint) largeNegInt;          // 2147483648 or OverflowException is thrown (if checked)
int from_smallFloat = (int) smallFloat;      // 17
int from_largeFloat = (int) largeFloat;      // -2147483648 or OverflowException is thrown (if checked)
char from_intc = (char) 32;                  // ' '
char from_invalid_int = (char) 0xdcbf;       // invalid char - no exception thrown

// no cast available
int fromString = Int32.Parse("42");          // 42
string toString = largeInt.ToString();       // "2147483647"
int fromString_bad = Int32.Parse("forty two");     // FormatException is thrown
```

راجع هذا [المقال][checked] للاطلاع على الكلمة المفتاحية _**checked**_.

## تحويل النوع للأنواع داخل تسلسل هرمي

يمكن تحويل أي نوع ضمنيًا إلى صنفه الأساسي أو واجهته.

```csharp
IList<int> ll = new List<int>();
```

ويمكن استخدام عامل تحويل للتحويل من صنف أساسي إلى صنف مشتق.

```csharp
IList<int> ll = new List<int>();
List<int> l = (List<int>)ll;
```

إذا فشل التحويل لأن نوع التعبير الجاري تحويله غير مرتبط بالنوع المحوَّل إليه، فسيُطرح استثناء من نوع `InvalidCastException`.

والنهج الأكثر شيوعًا في تحويلات النوع هذه هو استخدام الكلمة المفتاحية [`is`][is-operator]:

```csharp
interface IFoo { int Bar(); }
class Foo : IFoo { public int Bar() { return 42; }}
Object r = new Random();
IFoo ifoo = new Foo();
Object o = new Foo();

int result = 1729;

if (ifoo is Foo foo)
{
    result = foo.Bar();
}
// result == 42

result = 1729;
if (o is Foo foo2)
{
    result = foo2.Bar();
}
// result == 42

result = 1729;
if (r is Foo foo3)
{
    result = foo3.Bar();
}
// result == 1729
```

وتؤدي الكلمة المفتاحية [`as`][as-operator] وظيفة مشابهة لدور `is`، مثل `var foo = ifoo as Foo;`. في هذا المثال سيكون `foo` مساويًا لـ `null` إذا لم يكن `ifoo` من النوع `Foo`، وإلا فسيُسند `ifoo` إليه.

## عامل التحويل المخصص

يمكن للأنواع أن تعرّف [عوامل تحويل][custom-casts] صريحة وضمنية مخصصة خاصة بها.

من أمثلة التحويلات [الصريحة][big-integer-explicit] و[الضمنية][big-integer-implicit] في BCL التحويلات من البنية `BigInteger` وإليها من وإلى أنواع عددية أخرى.

## استخدام `typeof`

إذا احتجت إلى اكتشاف النوع الدقيق لكائن ما، فقد يكون `is` متسامحًا أكثر من اللازم، لأنه سيحوّل الكائن إلى صنف أو إلى أي من أصنافه الأساسية. وفي هذه الحالة يكون الحل هو `typeof` و`Object.GetType()`.

```csharp
object o = new List<int>();

o is ICollection<int> // true
o.GetType() == typeof(ICollection<int>) // false
o is List<int> // true
o.GetType() == typeof(List<int>) // true
```
