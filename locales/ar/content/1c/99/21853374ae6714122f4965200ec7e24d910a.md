# نبذة

تُعدّ [`interfaces`][interfaces] الوسيلة الأساسية التي يُحقَّق بها [الفصل][wiki-loose-coupling] بين استخدامات صنف ما وتنفيذه. ويمنح هذا الفصل مرونة في صيانة التنفيذ، ويساعد على دعم سلوك عام آمن من حيث الأنواع.

صيغة الواجهة شبيهة بصيغة الصنف أو البنية، إلا أن الطرق والخصائص تظهر كتوقيع فقط دون تقديم أي جسم.

```csharp
public interface ILanguage
{
    string Speak();
}

public interface IItalianLanguage : ILanguage
{
    string Speak();
    string SpeakItalian();
}

public interface IScriptConverter
{
    string Version { get; set; }
    string ConvertCyrillicToLatin(string cyrillic);
}
```

يجب على الصنف أو البنية المنفِّذ أن ينفّذ كل العمليات التي تعرّفها الواجهة.

عادةً ما تقوم الواجهات بواحد أو أكثر مما يلي:

- تسمح بمعاملة عدد من الأصناف المختلفة معاملة عامة من طرف الكود الذي يستخدمها. وفي هذه الحالة تؤدي الواجهات الدور نفسه الذي يؤديه الصنف الأساس
- تكشف عن مجموعة فرعية من الوظائف لغرض معيّن (مثل [`IComparable<T>`][icomparable])، أو
- تكشف API العام لصنف ما بحيث يمكن لعدة تنفيذات أن تتواجد معًا. ومن الأمثلة على ذلك [البديل الاختباري][wiki-test-double]

```csharp
public class ItalianTraveller : IItalianLanguage
{
    public string Speak()
    {
        return "Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class ItalianTravellerV2 : IItalianLanguage
{
    public string Speak()
    {
        return "migliorata - Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class FrenchTraveller : ILanguage
{
    public string Speak()
    {
        return "Ça va?";
    }
}

public class RussianTraveller : ILanguage, IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Speak()
    {
        return "Привет мир";
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}

public class DocumentTranslator : IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Translate(string russian)
    {
        throw new NotImplementedException();
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}
```

يمكن للكود الذي يستخدم الواجهات والأصناف السابقة أن:

- يعامل جميع المتحدثين بالطريقة نفسها بغض النظر عن اللغة.
- يسمح لنظام فرعي يتولى تحويل الكتابة أن يعمل دون اكتراث بالأنواع المحددة التي يتعامل معها.
- يظل غير مدرك للتغييرات التي تطرأ على المتحدث الإيطالي، وهو أمر مريح إذا كان كود الصنف وكود المستخدم تُصونهما فرق مختلفة

تُستخدم الواجهات على نطاق واسع لدعم الاختبار لأنها تتيح [محاكاة][so-mocking-interfaces] سهلة.

راجع هذا [المقال][dt-interfaces] لمعرفة تفاصيل أنواع الأعضاء التي يمكن تضمينها في واجهة.

يمكن للواجهات أن ترث من واجهات أخرى.

أعضاء الواجهة عامة افتراضيًا.

يمكن للواجهات أن تحتوي على أنواع متداخلة، مثل القيم الحرفية `const`، و`enums`، و`delegates`، و`classes`، و`structs`. وهنا تعمل الواجهات كـ[مساحات أسماء][wiki-namespaces] بالطريقة نفسها التي تعمل بها الأصناف والبنى، والسلوك والصيغة متطابقان.

بحكم التصميم، لا تدعم لغة C# الوراثة المتعددة، لكنها تسهّل نوعًا من الوراثة المتعددة عبر الواجهات.

علاوة على ذلك، فإن مفهوم [إمكانية تنفيذ تعدد الأشكال عبر الواجهات][interface-polymorphism] هو ما تقوم عليه آلية الواجهات.

## التنفيذ الصريح للواجهات

قد تتشارك واجهتان مختلفتان أحيانًا في أسماء الطرق وتوقيعاتها. ومن أجل تقديم تنفيذ مختلف لهذه الطرق، توفر C# [التنفيذ الصريح للواجهات][explicit-implementation]. لاحظ أنه لاستخدام تنفيذ معيّن لواجهة ما، عليك تحويل التعبير الذي يشير إلى الكائن إلى تلك الواجهة. ويتحقق ذلك عن طريق الإسناد أو التحويل أو التمرير كوسيط.

```csharp
public interface IFoo
{
    void X();
}

public interface IBar
{
    void X();
}

public class Census : IFoo, IBar
{
    void IFoo.X()
    {
        Console.Write("This is from Foo");
    }

    void IBar.X()
    {
        Console.Write("This is from Bar");
    }
}

public class User
{
    public void Use()
    {
        IFoo foo = new Census();
        IBar bar = new Census();
        foo.X();
        // => "This is from Foo"
        bar.X();
        // => "This is from Bar"
    }
}
```

هناك عدد من حالات الاستخدام:

- تعارض بين المجالات (كما هو موضّح أعلاه) حيث تكون للطرق توقيعات متطابقة.
- طرق تحمل الاسم نفسه لكن أنواع الإرجاع مختلفة: إذا نفّذت أصناف التجميع الخاصة بك، فقد تجد أنك بحاجة إلى واجهة صريحة للطريقة القديمة `IEnumerable.GetEnumerator()`، إلى جانب `IEnumerable<T>.GetEnuerator()`. وقد لا تستخدم هذه الواجهة أبدًا، لكن المترجم قد يُصرّ على وجودها.
- طرق لا يوجد فيها تعارض في الأسماء بين الواجهات، لكن من المستحسن أن يستخدم الصنف المنفِّذ الاسم لغرض ذي صلة: فـ`IFormattable` لديها طريقة `ToString()` تأخذ معامل _نوع التنسيق_ إضافة إلى معامل من النوع `IFormatProvider`. وصنف مثل `FormattableString` من مكتبة الأصناف الأساسية (BCL) يمتلك هذه الواجهة لضمان إمكانية استخدامه من إجراءات تأخذ `IFormattable`، لكن نسخته الرئيسة من `ToString(IFormatProvider)` أكثر تعبيرًا حين تحذف معامل _نوع التنسيق_ لأنه غير مستخدم في التنفيذ وقد يربك مستخدمي API.

## التنفيذ الافتراضي

يعالج الإصدار 8 من C# مشكلة مزعجة تتعلق بـAPIs. فإذا أضفت طرقًا إلى واجهة لتعزيز الوظائف من أجل تنفيذات جديدة، فسيكون من الضروري تعديل كل التنفيذات القائمة للواجهة كي تتوافق مع عقد API حتى وإن لم يكن لديها سلوك خاص بالتنفيذ. وتتيح C# الآن توفير _طريقة افتراضية_ كجزء من الواجهة (وسيكون مطوّرو Java على دراية بذلك). في السابق، عندما كان يحدث تغيير كهذا، كان يوجد _إصدار 2_ من الواجهة إلى جانب الأصلية.

يُعدّ هذا [المقال][dt-interfaces] مقدمة ممتازة عن الواجهات، ويركز على _التنفيذ الافتراضي_ وغير ذلك من الابتكارات الداعمة مثل الأعضاء `static` و`private` و`virtual`.
