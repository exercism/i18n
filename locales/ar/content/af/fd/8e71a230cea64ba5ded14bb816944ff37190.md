# نبذة

تُستخدم وحدة `Time` لعرض التواريخ والأوقات بصيغة يمكن للبشر قراءتها.
ورغم أنه من الممكن تقنيًا التعامل مع الأوقات باستخدام `Time`، فإن هناك حزمًا من مجتمع Elm أنسب بكثير لهذه المهمة، مثل [`justinmimbs/date`][date] أو [`CoderDennis/elm-time-format`][elm-time-format].

## Posix

تُمثَّل الأوقات بالنوع المعتم `Posix`، الذي يغلّف وقت حقبة يونكس، أي عدد المللي ثانية التي انقضت منذ منتصف ليل 1 يناير 1970 بتوقيت UTC.
وقيمة `Posix` قيمة لا لبس فيها ولا تختلف من منطقة زمنية إلى أخرى، ولذلك فهي خيار جيد لحفظ الوقت.
وفي تطبيق Elm، تأتي أوقات `Posix` عادةً من مصادر خارجية، مثل المتصفح.

يمكن تحويل `Posix` إلى عدد من المللي ثانية والعكس باستخدام الدوال التالية:

```elm
posixToMillis : Posix -> Int
millisToPosix : Int -> Posix
```

## المناطق الزمنية

في حياتنا اليومية، لا نقرأ عادةً قيم `Posix`، بل نفضّل التوقيت المحلي، الذي يعتمد على موقعنا على الأرض وعلى قواعد التوقيت الصيفي المحلية.
وفي Elm، تُشفَّر هذه المعلومات في النوع المعتم `Zone`، الذي يوفّره المتصفح عادةً.

وهناك `Zone` خاص متاح دائمًا:

```elm
utc : Zone
```

## أوقات مقروءة للبشر

بوجود `Posix` و`Zone`، تتوفر لدينا معلومات كافية لعرض التوقيت المحلي بأي مستوى من التفصيل.
وفيما يلي قائمة بالدوال التي يمكن استخدامها لذلك:

```elm
toYear : Zone -> Posix -> Int
toMonth : Zone -> Posix -> Month
toDay : Zone -> Posix -> Int
toWeekday : Zone -> Posix -> Weekday
toHour : Zone -> Posix -> Int
toMinute : Zone -> Posix -> Int
toSecond : Zone -> Posix -> Int
toMillis : Zone -> Posix -> Int
```

ولا بد أنك لاحظت نوعين مخصصين آخرين في `Time`:

```elm
type Month = Jan | Feb | Mar | Apr | May | Jun | Jul | Aug | Sep | Oct | Nov | Dec
type Weekday = Mon | Tue | Wed | Thu | Fri | Sat | Sun
```

ويُترك للمستخدمين تحويل هذين النوعين المخصصين إلى قيم يمكن للبشر قراءتها.
