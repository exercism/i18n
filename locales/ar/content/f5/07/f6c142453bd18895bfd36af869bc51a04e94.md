# نبذة

*الكومة* مجموعة تعرف دائمًا أصغر عنصر فيها (أو أكبره) وتتيح لك إزالته بسرعة، وهي التنفيذ الطبيعي لـ *طابور الأولوية*. وتوجد الأكوام في مفردات [`heaps`][heaps].

مع `<min-heap>` تحصل على كومة فارغة يخرج منها أصغر مفتاح أولًا، ومع `<max-heap>` يُقدَّم أكبر مفتاح أولًا. كل عنصر هو *قيمة* مخزَّنة تحت *مفتاح*، والمفتاح هو الأولوية التي يرتّب Factor على أساسها:

```
<min-heap> ( -- min-heap )
<max-heap> ( -- max-heap )
heap-push  ( value key heap -- )
heap-push-all ( assoc heap -- )
```

```factor
USING: heaps ;

<min-heap>
"alice" 5 pick heap-push
"bob"   2 pick heap-push
```

الكومة *قابلة للتغيير*: تعدّلها `heap-push` و`heap-pop` في مكانها.

```
heap-peek    ( heap -- value key )
heap-pop     ( heap -- value key )
heap-pop-all ( heap -- alist )
heap-empty?  ( heap -- ? )
heap-size    ( heap -- n )
```

تقرأ `heap-peek` العنصر الأمامي دون إزالته، وتزيل `heap-pop` العنصر الأمامي وتُرجعه، وتستنزف `heap-pop-all` الكومة إلى قائمة اقتران من أزواج `{ key value }` حسب ترتيب الأولوية.

```factor
USING: assocs heaps kernel prettyprint ;

<min-heap>
"alice" 5 pick heap-push
"bob"   2 pick heap-push
"carol" 9 pick heap-push
dup heap-pop .           ! => 2 "bob"   (removed; value then key)
heap-pop-all values .    ! => { "alice" "carol" }
```

عملية الدفع تكلفتها `O(log n)` وقراءة العنصر الأمامي تكلفتها `O(1)`، لذا يبقى تكرار «خذ العنصر الأكثر إلحاحًا ثم أضف المزيد» سريعًا حتى مع طابور كبير. والتنفيذ عبارة عن كومة ثنائية مخزَّنة في مصفوفة قابلة للنمو؛ وقد يكون المفتاح أي قيمة قابلة للترتيب (أعداد، سلاسل نصية، …).
