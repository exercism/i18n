# نبذة

لفهم [`Box`][box]، من المفيد أن نفهم ما هما [المكدس والكومة][stack and heap].

المكدس منطقة من الذاكرة تعمل كمخزن مؤقت بنظام «آخر ما يدخل أول ما يخرج» (LIFO). دفع البيانات إلى المكدس سريع جدًا، وإخراجها منه سريع أيضًا. وقد تشمل البيانات متغيرات أو عناوين دوال، لكن يجب أن تكون ذات حجم ثابت معروف وقت التصريف.

أما إذا كانت البيانات ذات حجم غير معروف وقت التصريف، أو ذات حجم قد يتغير، فيجب تخصيصها على الكومة. وعملية التخصيص هذه يجب أن تجد مساحة في الكومة كبيرة بما يكفي لتخزين البيانات، ثم تكتب البيانات في الكومة، وتدفع عنوان الذاكرة الخاص بتلك البيانات إلى المكدس. وكل ذلك يستغرق وقتًا أطول بكثير من مجرد وضع البيانات على المكدس. واسترجاع البيانات من الكومة أبطأ قليلًا، لأننا نحتاج إلى المرور عبر العنوان الموجود على المكدس واتباعه إلى موضع البيانات على الكومة.

`Box` مؤشر ذكي يخصّص البيانات على الكومة. العنوان موجود على المكدس، وهو يشير إلى البيانات الموجودة على الكومة. أحد [الأسباب][reasons] لاستخدام `Box` هو وضع البيانات على الكومة عندما يكون لديك نوع لا يمكن معرفة حجمه وقت التصريف، وتريد استخدام قيمة من هذا النوع في سياق يتطلب حجمًا محددًا بدقة. ومن الاستخدامات العملية لذلك أن يكون لديك عدة بنى تريد التعامل معها بالأسلوب نفسه عبر سمة تُنفّذها جميعًا، كما في المثال أدناه.

لنفترض أن لدينا بنيتين. كل بنية تمثل شيئًا يمكن أن يكون مزعجًا. يمكننا أن نجعل كل بنية تُنفّذ سمة Annoyance هكذا

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

لنفترض الآن أننا نريد دالة تُعطينا Annoyance بناءً على وقت اليوم الذي يُمرَّر إليها. يمكننا أولًا أن نجرّب هذا، لنكتشف أنه لن يُصرَّف

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

يخبرنا المصرّف، بكل لطفه، بما يجب فعله بالضبط، وهو إرجاع كائن سمة مغلَّف في `Box`. وإذا كنت لا تعرف ما هو كائن السمة، فأبسط وصف له أنه أسلوب لإرجاع كائن محدد عبر [الإرسال الديناميكي][dynamic dispatch] من دالة يمكن أن تُرجع أي كائن يُنفّذ سمة محددة. وبما أننا نحتاج إلى الإرسال الديناميكي، يمكننا أن نجرّب مجرد وضع `dyn` قبل اسم السمة ونرى إن كان ذلك سينجح.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

أحد الأخطاء هو أن حجم `dyn Annoyance` لا يمكن معرفته وقت التصريف. وذلك لأن `annoy_me` لا تعرف ما كائن السمة المحدد الذي ستُرجعه قبل استدعائها. فالبنى التي تُنفّذ Annoyance قد تمتلك حقولًا مختلفة وأحجامًا مختلفة. ويُذكَّرنا هذا بأن أحد استخدامات `Box` هو للأنواع التي لا يمكن معرفة حجمها وقت التصريف. لذا نجرّب الآن استخدام قيمة إرجاع مغلَّفة في `Box`، ونضع القيم المُرجَعة من تعبير `match` داخل `Box`، هكذا

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

توقيع `Box` هو `Box<T>`، حيث يمثل `T` النوع المحدد المراد تغليفه، ويوضع بين الأقواس الزاوية، كما في `Box<dyn Annoyance>` أعلاه.

يمكننا استهلاك كائن السمة المغلَّف في `Box` هكذا

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

وهو ما يطبع

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

بما أن `my_annoyance` من النوع `Box<dyn Annoyance>`، فيجب فك مرجعها من `Box` باستخدام عامل فك المرجع `*`. ثم يُشار إليها بوصفها `dyn Annoyance` لتستعيرها دالة `be_annoying`.

وثمة أسلوب آخر لتنفيذ ذلك، وهو إزالة شرط أن يكون المعامل محدد الحجم. في هذه الحالة، سيُنشئ التصريف دالة منفصلة لكل شكل من أشكال Annoyance حتى يمكن إرسالها إرسالًا ساكنًا (وهي عملية تُسمى [التماثل الأحادي][monomorphization])، هكذا

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

وثمة أسلوب آخر أيضًا لتنفيذ ذلك، وهو أن تقبل دالة `be_annoying` قيمة من النوع `Box<dyn Annoyance>` وتستخدم [الإكراه على فك المرجع][deref coercion] لتجنّب فك مرجع `Box` يدويًا. سيؤدي ذلك إلى نقل ملكية كائن سمة Annoyance إلى دالة `be_annoying`. وسيخرج عن النطاق في نهاية الدالة ولن يبقى متاحًا.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
