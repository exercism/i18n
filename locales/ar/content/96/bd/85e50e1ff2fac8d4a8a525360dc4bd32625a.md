# مقدمة

في عالم مثالي، يمكننا الاعتماد على أن كل شيء مُعرَّف على نحو جيد، بقيم محددة ولا فراغات فيه.

لكن هذا يتعارض مع تجربتنا اليومية، ولذلك تمتلك كثير من لغات البرمجة طريقة لتمثيل غياب القيمة: null أو NULL، أو nil، أو None، أو nothing...

كان إدخال هذه الفكرة سهلًا (في عام 1965)، لكنه سرعان ما أدى إلى ندم.
وقد سمّاه مخترعه لاحقًا «خطأ المليار دولار».

وفي العقود الأخيرة، استكشف مصممو اللغات طرقًا كثيرة لجعل قيم null متاحة لكن آمنة (في معظمها).

تمتلك Kotlin بعض [المبادئ العامة][ref-null-safety] التي تختلف اختلافًا كبيرًا عما في Java.


- تمتلك Kotlin قيمة `null` خاصة.
- جميع الأنواع تكون _افتراضيًا_ غير قابلة لأن تكون `null`.
- يمكن _جعل_ معظم الأنواع قابلة لأن تكون `null`، لكن على المبرمج أن يطلب ذلك صراحةً.
- الدوال التي قد تفشل برفع استثناء يُرجَّح أن يكون لها نسخة تُرجع قيمة قابلة لأن تكون `null`.
- وتحاول صياغة خاصة ومقتضبة للغاية أن تجعل فحص قيم null والتعامل معها سهلًا قدر الإمكان.

## إنشاء متغيرات قابلة لأن تكون null

للأنواع القياسية عمومًا مقابل قابل لأن يكون `null`، بلاحقة `?`: على سبيل المثال `String?` بدلًا من `String`.

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## عوامل ودوال مفيدة

### عامل الاستدعاء الآمن `?.`

مع `String` غير القابل لأن يكون `null`، يمكننا الحصول على الخاصية `.length`.

أما النوع `String?` القابل لأن يكون `null` فيفشل مع الصيغة نفسها، لكن استخدام `?.length` يسمح باحتمال وجود `null`.
ونوع القيمة المُرجعة هو `Int?`.

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

وكما رأينا في السطر الأخير أعلاه، يعمل `?.` أيضًا مع الأنواع غير القابلة لأن تكون `null`.

### عامل إلفيس `?:`

وبتوسيع فكرة عامل الاستدعاء الآمن، يتيح لنا [عامل إلفيس][wiki-elvis] تمرير قيمة افتراضية تحل محل `null`.

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### عامل التأكيد على أن القيمة ليست null `!!`

باستخدام هذا العامل، يُجبَر النوع القابل لأن يكون `null` على أن يُعامَل كنوع غير قابل لذلك، عندما يثق المبرمج في ذلك.
فربما نفهم منطق البرنامج أحيانًا أفضل من مُصرِّف مفرط في الحذر؟

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

وتقع المسؤولية الآن علينا: إذا كانت `b` ما زالت `null` فسنحصل على `NullPointerException`.

### دالة `let` `?.let`

إذا كنا نمرر عنصرًا قابلًا لأن يكون `null` إلى كتلة من الكود، فيمكننا إجراء فحوص محددة لقيم null مثل `if (item != null) { do something }`.

لكن الأبسط والأكثر توافقًا مع أسلوب اللغة هو استخدام `item?.let { do something }`،
فلن يُنفَّذ `do something` إلا عندما لا تكون قيمة `item` مساوية لـ `null`.

### دوال من النوع `somethingOrNone()`

قد تفشل بعض الدوال، مثلًا عند طلب فهرس غير صالح في سلسلة نصية أو مصفوفة.

وبدلًا من رفع استثناء، يمكننا استخدام النسخة `...OrNull` من الدالة، لنحصل (في هذه الحالة) على قيمة إرجاع من النوع `Int?`.

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
