# نبذة

## التطبيق الجزئي

جميع الدوال في Elm [كاريّة][currying]، أي أنك إذا استدعيت دالة دون تمرير كل الوسائط، فإنها تُرجع دالة جديدة.

تُسمّى نتيجة هذا الفعل [التطبيق الجزئي][partial-application] (فأنت لا تمرّر كل الوسائط إلى الدالة، بل تطبّق بعضها تطبيقًا جزئيًا).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

التطبيق الجزئي يطبّق الوسائط دائمًا بالترتيب.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## عامل الأنبوب (`|>`)

قولنا `x |> f` يكافئ تمامًا `f x`. ومن الأمثلة الملموسة أن `"5" |> String.toInt` تكافئ `String.toInt "5"`.

قد لا يبدو هذا مفيدًا كثيرًا في البداية، لكنه يُسمّى [عامل الأنبوب][pipe-operator] لأنه يتيح لك كتابة كود «متسلسل» على طريقة الأنابيب.

على سبيل المثال، لنفترض أن لدينا دالة `sanitize` تحوّل مدخلات المستخدم إلى أعداد صحيحة:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

يمكننا إعادة كتابتها هكذا:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

يتجنّب هذا استخدام الأقواس الهلالية، ويعرض الدوال بالترتيب الذي تُطبَّق به (أولًا `String.trim`، ثم `String.toInt`)، ما يسهّل القراءة.

يوجد أيضًا [عامل الأنبوب المعاكس `(<|)`][reverse-pipe-operator]. وقولنا `x <| f` يكافئ تمامًا `f x`. ولا يبدو هذا مفيدًا كثيرًا للوهلة الأولى أيضًا، وهو بالتأكيد أقل استخدامًا من عامل الأنبوب، لكنه يساعد على تجنّب الأقواس الهلالية في بعض الحالات.

## تركيب الدوال / الأسلوب الخالي من النقاط

عامل [`(>>)`][forward-composition] من النوع `(a -> b) -> (b -> c) -> (a -> c)`، وينشئ دالة من النوع `a -> c` عبر تركيب دالتين متوافقتين من النوع `a -> b ` و`b -> c`.
وهو يفعل ذلك بأخذ ناتج الدالة الأولى (من النوع `b`) واستخدامه كأول وسيط للدالة الثانية (التي يجب أن تكون من النوع نفسه `b`).
الدالة المُنشأة ستأخذ المدخل نفسه (من النوع `a`) الذي تأخذه الدالة الأولى، وتُرجع أي قيمة `c` تُرجعها الدالة الثانية.

مثال ملموس على ذلك `String.trim >> String.toInt`.
تأخذ `String.trim` سلسلة نصية كمعاملها الوحيد، وهذا ما تأخذه الدالة المُنشأة.
وتُرجع `String.toInt` قيمة `Maybe Int`، وهذا ما تُرجعه الدالة المُنشأة.
وتُرجع `String.trim` قيمة `String`، وهي قيمة تقبلها `String.toInt` كمعامل، لذا يُترجم المثال بنجاح.

يمكننا الآن إعادة كتابة دالة `sanitize` على النحو التالي:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

لاحظ أننا لم نعد نستخدم معامل `input` الذي تراه في المثال الأصلي، مع أن الوظيفة نفسها متطابقة.
تُسمّى هذه الطريقة في إنشاء الدوال التي لا تشير إلى معاملاتها «الأسلوب الخالي من النقاط».
وميزة هذا الأسلوب أن الكود أكثر إيجازًا، وعيبه أنه قد يكون أصعب في الفهم، خاصة للمبتدئين.

يجدر التذكير بأن جميع الدوال في Elm كاريّة، لذا يُترجم `String.length >> max`، وينتج ما يلي:

- دالة (1) لها معامل من نوع سلسلة نصية (وهو مدخل `String.length`)
- `max` دالة لها معاملان من النوع `Int`، لكن الدالة 1 تمرّر إليها قيمة `Int` واحدة (وهي ما تُرجعه `String.length`)، لذا يُطبَّق `max` تطبيقًا جزئيًا.
- القيمة التي تُرجعها دالة `max` المطبَّقة جزئيًا هي دالة أخرى (2) تأخذ قيمة `Int`، وتُرجع أكبر القيمتين: قيمة `Int` هذه والقيمة `Int` المطبَّقة جزئيًا القادمة من `String.length`
- وبالتالي تُرجع الدالة 1 (`String -> Int`) الدالة 2 (`Int -> Int`)
- لذا تُرجع `((String.length >> max) "123") 2` القيمة `3`، لأن طول `"123"` هو 3، وهو أكبر من 2 المأخوذة من وسيط `Int`.

## تصميم الدوال

لتسهيل كتابة كود أنيق في Elm، اجعل بنية البيانات الأساسية آخر معامل في الدوال.
جميع الدوال الشائعة في المكتبة القياسية تفعل ذلك، مثل `List.map` (توقيع النوع أدناه).

```elm
map : (a -> b) -> List a -> List b
```

نرى هنا أن آخر معامل لدالة `map` هو `List a` وأنها تُرجع `List b`، لذا فبنية البيانات الأساسية (`List`) هي المعامل الأخير.

وهذا يجعل من الممكن كتابة كود متسلسل أنيق، كما في المثال أدناه.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

كما يسهّل استخدام تركيب الدوال والأسلوب الخالي من النقاط، كبديل عن التسلسل بالأنابيب.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

يتيح لك تركيب الدوال أيضًا اختصار هذا المثال إلى استدعاء واحد لـ `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
