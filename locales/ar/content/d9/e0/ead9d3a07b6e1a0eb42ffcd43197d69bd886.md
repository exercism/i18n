# نبذة

من غير المرجح أن تصادف الكثير من كود الإنتاج الذي لا يستخدم مساحات الأسماء.

مثال على الصياغة:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

مساحات الأسماء وسيلة لتجميع الكود المرتبط ولتجنب تعارض الأسماء.

وفقاً لما ورد في [الوثائق الرسمية][namespaces]، لمساحات الأسماء دوران رئيسيان:

- أولاً، يستخدم .NET مساحات الأسماء لتنظيم أصنافه العديدة
- ثانياً، يمكن أن يساعدك الإعلان عن مساحات الأسماء الخاصة بك في التحكم بنطاق أسماء الأصناف والطرق في مشاريع البرمجة الأكبر.

تستخدم مكتبة الأصناف الأساسية (BCL) مساحات الأسماء على نطاق واسع لتنظيم وظائفها.

## الإشارة إلى الأنواع داخل مساحات الأسماء

يُشار إلى الأنواع الموجودة داخل مساحات الأسماء من خارج مساحة الاسم بإضافة بادئة إلى اسم النوع باستخدام صيغة النقطة. بدلاً من ذلك، وفي أغلب الأحيان، يمكنك وضع توجيه `using` في أعلى الملف (أو داخل مساحة اسم)، ويمكن استخدام أي أنواع في مساحة الاسم المستوردة بدون البادئة. داخل مساحة الاسم نفسها، لا حاجة لتأهيل أسماء الأنواع.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

يوضح هذا [المقال][using] بوضوح الطرق التي يمكن بها استخدام توجيه `using`:

- `using`: تجنّب الحاجة إلى تأهيل الأنواع بمساحة الاسم
- `using static`: تجنّب الحاجة إلى تأهيل الأعضاء بالأنواع (مثال جيد هو `Math.Max()`).
- `using MyAlias = YourNamespace;`: استبدل اسم مساحة الاسم باسم أكثر قابلية للقراءة.

## تعارض مساحات الأسماء

يعالج .NET مشكلة وجود مساحتي اسم بالاسم نفسه في تجميعات مختلفة حيث قد يحدث تعارض في أسماء المعرّفات المؤهلة بالكامل (ربما سيناريو يتم فيه تحميل إصدارات متعددة من تجميعة). تُعالَج هذه المشكلة باستخدام [مؤهل الاسم المستعار لمساحة الاسم][namespace-alias-qualifier] و[الاسم المستعار `extern`][extern-alias].

أحد أسباب طرح هذا الموضوع المتخصص إلى حد ما هو استخدامه [عامل التشغيل `::`][dot-dot-operator]. غالباً ما سترى المؤهل `global::` مُضافاً كبادئة إلى مساحات الأسماء، خاصة في الكود المُولَّد. الغرض هنا هو تجنب تعارض محتمل مع مساحة اسم متداخلة أو اسم صنف. فبإضافة `global::` كبادئة إلى مساحة اسم， تضمن اختيار مساحة اسم من المستوى الأعلى.

## ملاحظة لمطوري Java

عند المقارنة مع `import` الخاص بـ `packages` في Java، ينبغي ملاحظة بعض الاختلافات وأوجه الشبه:

- لا يوجد مقابل في C# لاستيراد أنواع محددة.
- `using static` و `import static` متكافئان.
- في Java، لأسماء الحزم تأثير على إمكانية الوصول بين ملفات JAR. وفي C#، تكون التجميعات هي الأهم، والانتماء إلى مساحة الاسم نفسها لا يؤثر على مستوى الوصول.
- العلاقة بين مسارات نظام الملفات وأسماء الأصناف المؤهلة بالكامل في Java لا تنعكس في مساحات الأسماء في C#، مع أنه من الممارسات الجيدة، حيثما أمكن، أن تمنح ملفاً الاسم نفسه الذي يحمله الصنف الرئيسي الذي يحتوي عليه.
