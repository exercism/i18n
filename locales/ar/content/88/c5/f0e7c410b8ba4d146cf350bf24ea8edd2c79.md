# مقدمة

## الكود بدون تفرّع

يقدّم مفهوم الشروط `jcc`، وهي عائلة التعليمات الخاصة بالتفرّع بناءً على شرط. و`jcc` تنقل التنفيذ إلى نقطة أخرى في البرنامج فقط إذا تحقق شرطها.

لكن وحدات المعالجة المركزية (CPU) الحديثة سريعة وقادرة على تنفيذ تعليمات كثيرة بالتوازي. وسيكون مكلفًا للغاية إيقاف كل العمل بينما تنتظر وحدة المعالجة المركزية فحص شرط ما وقت التشغيل.

ولهذا لا تنتظر وحدة المعالجة المركزية داخليًا. بل تستخدم **متوقّع التفرّع** لتخمين نتيجة الشرط، وتبدأ في تنفيذ المسار المتوقّع _تخمينيًا_.

إذا كان التوقّع صحيحًا، يمضي التنفيذ وكأنه لا يوجد تفرّع. أما إذا كان التوقّع خاطئًا، فعلى وحدة المعالجة المركزية أن _تتخلّى عن العمل المنجز_ على المسار المتوقّع وأن تبدأ من جديد على المسار الصحيح.

ويُسمّى هذا **التوقّع الخاطئ للتفرّع**، وهو مكلف لأنه يسبّب تأخيرًا.

وعندما يصعب توقّع تفرّع ما، تتراكم هذه الأخطاء في التوقّع. وفي تلك الحالات، يُفضّل أحيانًا تجنّب التفرّع كليًا، بحيث تُنفَّذ التعليمات نفسها بصرف النظر عن الشرط. ويُسمّى الكود الذي يختار بين القيم دون `jcc` **بدون تفرّع**.

وهناك عدة طرق لكتابة الكود بحيث يتفرّع أقل، أو بحيث تكون التفرّعات الموجودة فيه أسهل في التوقّع. وعلى وجه الخصوص، توفّر x86-64 عائلتَي تعليمات شائعتَي الاستخدام لكتابة الكود بدون تفرّع.

### النقل الشرطي

تنسخ عائلة التعليمات `cmovcc` المصدر إلى الوجهة فقط إذا تحقق شرط محدّد. وإلا تُترك الوجهة دون تغيير.

وتتبع اللاحقة `cc` التسمية نفسها المستخدمة في `jcc`، بالمعنى نفسه:

| التعليمة | النقل إذا                              |
|-------------|--------------------------------------|
| `cmove`     | A == B بعد `cmp A, B`              |
| `cmovne`    | A != B بعد `cmp A, B`              |
| `cmovl`     | A < B (ذو إشارة) بعد `cmp A, B`      |
| `cmovb`     | A < B (بدون إشارة) بعد `cmp A, B`    |
| `cmovg`     | A > B (ذو إشارة) بعد `cmp A, B`      |
| `cmova`     | A > B (بدون إشارة) بعد `cmp A, B`    |

والقواعد مشابهة لقواعد `jcc`:

1. تُستخدم `l` و `g` للمقارنات ذات الإشارة، و`b` و `a` للمقارنات بدون إشارة.
2. إضافة `e` إلى اللاحقة تُشمِل المساواة.
3. إضافة `n` تنفي الشرط.
4. وهناك أيضًا صيغ تشير إلى ضبط العلم.
   فمثلًا `cmovz` و `cmovc`.

لننظر إلى القيمة المطلقة لعدد صحيح ذي إشارة موجود في `rdi`، وتُرجَع في `rax`.
عند كتابتها باستخدام `jcc`، تختار الدالة أحد مسارين:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

وعند كتابتها باستخدام `cmovcc`، تُحسب القيمتان المرشّحتان دون شرط، ثم يختار النقل الشرطي إحداهما:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

النسخة بدون تفرّع تنفّذ التعليمات نفسها دائمًا.
ولا يوجد `jcc` ليتوقّعه متوقّع التفرّع.

يجب أن تكون وجهة `cmovcc` سجلًا.
أما المصدر فيمكن أن يكون سجلًا أو موقعًا في الذاكرة، لكنه لا يمكن أن يكون قيمة فورية.

~~~~exercism/note
في الكود أعلاه، تضبط التعليمة `neg` عدة أعلام وفقًا للنتيجة، ومنها علم الإشارة (SF).
وهذا يعني أنه يمكن الاستغناء عن `cmp rdi, 0` تمامًا:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

بالنسبة إلى `rdi` الموجب، ينتج `neg` نتيجة سالبة ويكون SF == 1، لذا يستعيد `cmovs` القيمة `rdi`.
وبالنسبة إلى `rdi` المساوي صفرًا أو السالب، ينتج `neg` نتيجة غير سالبة ويكون SF == 0، فتحتفظ `rax` بالقيمة المنفية (وهي القيمة المطلقة الصحيحة).

ورغم أن `cmp` هي الطريقة الأساسية لمقارنة القيم في لغة التجميع، فإن تعليمات كثيرة تضبط الأعلام وفقًا لنتيجتها أيضًا.
والقائمة الكاملة للأعلام التي تؤثر عليها التعليمة مُدرَجة عادةً في [مرجعها][reference].
وبالنسبة إلى `neg` تحديدًا، فهي SF و ZF و CF و OF و PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

### الضبط الشرطي

تضبط عائلة التعليمات `setcc` الوجهة على `1` إذا تحقق شرط محدّد، وعلى `0` فيما عدا ذلك.
والوجهة دائمًا _بعرض 8 بت_.

وتتبع اللاحقة `cc` التسمية نفسها المستخدمة في `jcc` و `cmovcc`.
فمثلًا، تضبط `setz` الوجهة على `1` إذا كان `ZF == 1`، وعلى `0` فيما عدا ذلك.

ولأن الوجهة بعرض 8 بت، فمن الشائع أن تُتبع `setcc` بالتعليمة `movzx` عند الحاجة إلى قيمة أعرض:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

وهذه طريقة شائعة لتحويل نتيجة المقارنة إلى عدد صحيح `0` أو `1`.
