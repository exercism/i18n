# مقدمة

تشبه الشرائح في Go المصفوفات في لغات أخرى.
فهي تحمل عدة عناصر من نوع محدد (أو واجهة).

تستند الشرائح في Go إلى المصفوفات.
وللمصفوفات حجم ثابت.
أما الشريحة، في المقابل، فهي منظور مرن ومتغيّر الحجم لعناصر المصفوفة.

تُكتب الشريحة على هيئة `[]T` حيث `T` هو نوع العناصر في الشريحة:

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

يمكنك قراءة عنصر أو تعديله عند فهرس معيّن يبدأ من الصفر باستخدام الأقواس المربعة:

```go
withData[1] = 5
x := withData[1] // x is now 5
```

يمكنك إنشاء شريحة جديدة من شريحة موجودة بأخذ مجموعة متتالية من العناصر.
مرة أخرى باستخدام الأقواس المربعة، لكن مع تحديد فهرس البداية (شامل) وفهرس النهاية (غير شامل).
إذا لم تحدد فهرس البداية، فسيكون الافتراضي هو 0.
وإذا لم تحدد فهرس النهاية، فسيكون الافتراضي هو طول الشريحة.

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

يمكنك إضافة عناصر إلى شريحة باستخدام الدالة `append`.
في المثال التالي نضيف `4` و`2` إلى الشريحة `a`.

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

تُرجع `append` دائمًا شريحة جديدة، وعندما نريد فقط إضافة عناصر إلى شريحة موجودة، فمن الشائع إعادة إسنادها إلى متغيّر الشريحة الذي نمرّره كأول وسيط، كما فعلنا أعلاه.

يمكن أيضًا استخدام `append` لدمج شريحتين:

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## الفهارس في الشرائح

ينبغي دائمًا حماية التعامل مع فهارس الشرائح بطريقة ما عبر تحقق يتأكد من وجود الفهرس فعليًا.
وإغفال ذلك سيؤدي إلى انهيار التطبيق بأكمله.

## الشرائح الفارغة

الشريحة `nil` هي الشريحة الفارغة الافتراضية.
ولا عيوب فيها مقارنة بشريحة لا تحتوي على أي قيم.
فدالة `len` تعمل على الشرائح `nil`، ويمكن إضافة عناصر إليها دون تهيئتها، وهكذا.
وإذا كنت تنشئ شريحة جديدة، ففضّل `var s []int` (شريحة `nil`) على `s := []int{}` (شريحة فارغة وليست `nil`).

## الأداء

عند إنشاء شرائح ستُملأ بشكل متكرر، هناك مكسب سهل لتحسين الأداء إذا كان الحجم النهائي للشريحة معروفًا.
والأمر الأساسي هو تقليل عدد مرات تخصيص الذاكرة، وهي عملية مكلفة إلى حد ما وتحدث عندما تنمو الشريحة بما يتجاوز مساحة الذاكرة المخصصة لها.
وأأمن طريقة لذلك هي تحديد سعة `cap` للشريحة عبر `s := make([]int, 0, cap)` ثم استخدام `append` مع الشريحة كالمعتاد.
وبهذه الطريقة تُخصَّص المساحة اللازمة لعدد `cap` من العناصر فورًا بينما يكون طول الشريحة صفرًا.
وفي الواقع العملي، غالبًا ما تكون `cap` هي طول شريحة أخرى: `s := make([]int, 0, len(otherSlice))`.

## الدالة `append` ليست دالة نقية

دالة `append` في Go مُحسَّنة من أجل الأداء، ولذلك فهي لا تنسخ الشريحة المُدخلة.
وهذا يعني أن الشريحة الأصلية (المعامل الأول في `append`) قد تتغير في بعض الأحيان.
