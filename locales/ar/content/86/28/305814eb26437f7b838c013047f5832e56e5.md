# مقدمة

معرفة نوع قطعة البيانات أمر مهم غالبًا لكي يعمل الكود بسلاسة ودون أخطاء.

لدى Javascript عدة أساليب للتحقق من نوع قيمة أو كائن.

## عامل `typeof`

يُرجع عامل `typeof` نوع الطرف الخاص به.
الناتج هو سلسلة نصية تطابق اسم أحد [أنواع البيانات الأولية][primitives]، باستثناء `"null"`.
ويمكن أن يكون أيضًا `"function"` أو `"object"`.

```javascript
typeof undefined;
// => "undefined"

typeof true;
// => "boolean"

typeof 42;
// => "number"

typeof 'Hello, World!';
// => "string"

typeof function () {
  return 'Hello, World';
};
// => "function"

typeof [1, 2, 3, 4];
// => "object"

typeof { city: 'Stockholm', country: 'Sweden' };
// => "object"
```

لأسباب [تاريخية][`typeof null` is `"object"`].

## عامل `instanceof`

للتحقق من نوع كائن، يمكنك استخدام عامل `instanceof`.
وهو يُقيّم إلى `boolean` بحسب ما إذا كان الطرف الثاني مُدرجًا في [سلسلة النماذج الأولية][prototype chain] للطرف الأول.
وللتوضيح، سيُرجع `instanceof` ما إذا كان الطرف الأول نسخة من الطرف الثاني أو من إحدى أصنافه الفرعية.
يعمل `instanceof` على الكائنات فقط.

```javascript
class Beverage {
  // ...
}

// The Coffee class is a child of the Beverage class.
class Coffee extends Beverage {
  // ...
}

const java = new Coffee();

java instanceof Coffee;
// => true

java instanceof Beverage;
// => true
```

````exercism/advanced
يحتوي صنف `Array` على طريقة تُسمى `Array.isArray()` تتحقق مما إذا كان وسيطها مصفوفة.

بينما لا يعمل `instanceof Array` مع مصفوفة أُنشئت في بيئة مختلفة مثل `iframe` في صفحة ويب، فإن `Array.isArray()` يعمل.

وذلك لأن صنف Array له دالة إنشاء مختلفة في كل بيئة، ولكل `iframe` بيئته الخاصة، ما يعني أن الدالة في سلسلة النماذج الأولية ستكون مختلفة، فيفشل `instanceof Array`.
ويستطيع `Array.isArray()` تجاهل ذلك، وينبغي استخدامه دائمًا كلما أمكن.

ويمكنه أيضًا تجاوز النتائج الإيجابية الكاذبة حين لا يكون الكائن في الحقيقة مصفوفة، وإنما يحوي `Array` في سلسلة النماذج الأولية الخاصة به فقط.

```javascript
({ __proto__: Array.prototype }) instanceof Array
// => true

Array.isArray({ __proto__: Array.prototype })
// => false
```
````

## عامل `in`

يُحدد عامل `in` ما إذا كان الطرف الأول خاصية من خصائص الطرف الثاني.
وهو لا يتحقق من أن للخاصية قيمة معرَّفة.
فالخاصية المضبوطة على `undefined` سيكتشفها `in` مع ذلك.

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
    this.isDarkMatter = undefined;
  }

  coolDown() {
    this.temperature = 'warm';
  }
}

const espresso = new Coffee();

'temperature' in espresso;
// => true

'color' in espresso;
// => false

'isDarkMatter' in espresso;
// => true
```

## دالة `Object.hasOwn()`

تُرجع طريقة `Object.hasOwn()` ما إذا كان الكائن المحدد _يملك الخاصية المعطاة_ (فهي ليست موروثة ولا طريقة).

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
  }

  coolDown() {
    this.temperature = 'warm';
  }
}
const cappuccino = new Coffee();

Object.hasOwn(cappucino, 'temperature');
// => true

Object.hasOwn(cappucino, 'constructor');
// => false

Object.hasOwn(cappucino, 'coolDown');
// => false
```
