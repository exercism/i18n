# التعليمات

كلما تعلمت أكثر عن البرمجة، بدأت تفكر أن هذا قد يكون أكثر من مجرد نزوة عابرة.
بل قد توجد حتى بعض الفرص التجارية: الناس يكتبون الكود، ويريدون حفظه ومشاركته والتعاون عليه، وربما الحصول على بعض الملاحظات أيضًا.

حسنًا، لنفعلها، لنبنِ خدمة تشجّع الناس على البرمجة: هيا بنا أيها الناس، ابدأوا باستخدام `git`!
ولنسمِّها... GitHup.

تبدأ ببناء واجهة REST JSON API: مستخدمون، وطلبات سحب، وتعليقات، ويكون backend جاهزًا بسرعة.
وهذا مثال على الحمولة التي يقدّمها الخادم عندما تطلب منه قائمة التعليقات على طلب سحب:

بالطبع، سيُنجَز frontend باستخدام Elm، لكن عليك أولًا أن تفهم ما الذي تدور حوله تلك المفكّكات والمرمّزات سيئة السمعة.

```exercism/note
بعيدًا عن القصة الطريفة، فإن متطلبات هذا التمرين مأخوذة مباشرة من نقاط النهاية الخاصة بواجهة GitHub REST API لتعليقات مراجعة طلبات السحب.
حُذفت بعض الحقول من مخططات JSON من أجل التبسيط، لكن هذا أقرب ما يكون إلى تطبيقات العالم الحقيقي.
```

## 1. المعرِّف، من فضلك!

عينك الثاقبة لاحظت أن التعليقات والمستخدمين كلاهما لديه حقل `id`، وهو مكان مثالي للبدء.

عرّف `decodeId` بحيث يفكّ ترميز كائن JSON يحتوي على `id` من نوع عدد صحيح.

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. ما اسمي مرة أخرى؟

تلاحظ في المثال أعلاه أن ليس كل المستخدمين لديهم اسم.

عرّف `decodeName` بحيث يفكّ ترميز سلسلة نصية في حقل `name` إن وُجدت.
لا اسم؟ لا مشكلة، أرجِع `Nothing` ببساطة.
يجب ألا يفشل هذا المفكّك أبدًا.

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. مستخدم؟ بالكاد أعرفه!

قطعنا نصف الطريق تقريبًا في فكّ ترميز المستخدمين، فلنُنجزه.

عرّف `decodeUser` بحيث يفكّ ترميز كائن JSON لمستخدم.
احرص على استخدام `decodeId` و`decodeName` داخل `decodeUser`.

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. أنا تعليق قوي ومستقل

بعض التعليقات في مراجعة طلب سحب تكون مستقلة، ولذلك لا تحتوي على `pull_request_review_id`.
مع ذلك، تذكر المواصفات أنه في مثل هذه الحالة يجب أن يظل هناك حقل `pull_request_review_id`، لكن القيمة يجب أن تكون `null`، وهي النسخة المتواضعة من `Nothing`.

عرّف `decodePullRequestReviewId` بحيث يفكّ ترميز عدد صحيح في حقل `pull_request_review_id` إن وُجد.
إذا لم يوجد عدد صحيح، فيجب أن يوجد `null`، وإذا لم يوجد `null` فيجب أن يفشل المفكّك.

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. عمل جانبي

التالي هو حقل `side` ذو المظهر المثير للاهتمام.
في مراجعة طلب سحب، يمكنك التعليق على كود حُذف (على الجانب `Left` من الشاشة) أو على كود أُضيف (على الجانب `Right` من الشاشة).

عرّف `decodeSide` بحيث يفكّ ترميز إما `"LEFT"` أو `"RIGHT"` في حقل `side` ويطابقه مع البديل المقابل له من النوع.

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. استيقاظ الروابط

لكل تعليق مجموعة من الروابط، ويبدو أنها غير ثابتة من تعليق لآخر.

عرّف `decodeLinks` بحيث يفكّ ترميز مجموعة من عناوين URL في حقل `_links`.
قد تختلف أسماء الروابط وعددها، فاحرص على أن تأخذ ذلك في الحساب.
الروابط نفسها كائنات JSON يجب أن تحتوي دائمًا على حقل `href`.

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. نعم، تعليقات

كدنا نصل، فلنُنجزه.

عرّف `decodeComment` و`decodeComments` بحيث تفكّان ترميز كائن تعليق JSON واحد أو قائمة تعليقات على الترتيب.
احرص على استخدام جميع الدوال المعرّفة حتى الآن داخل `decodeComment`، باستثناء `decodeName`.
وبالطبع، ينبغي أن تستخدم `decodeComments` الدالة `decodeComment` أيضًا.

## 8. كل شيء يترابط

لا تزال هناك ميزة واحدة ناقصة في كل هذا: القدرة على إرسال تعليق جديد إلى الخادم.
ولهذا تحتاج إلى تحقيق عكس المفكّك، أي أن تكون قادرًا على تحويل `Comment` في Elm إلى `Value` من JSON.

عرّف `encodeComment` بحيث يُرمّز أي `Comment` صالح.
ترتيب الحقول لا يهم، ما دام المرمّز قادرًا على إنتاج قيمة يستطيع `decodeComment` فكّ ترميزها.
