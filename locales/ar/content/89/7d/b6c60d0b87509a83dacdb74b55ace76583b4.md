# نبذة

أي بيانات في لغة التجميع هي تسلسل من البايتات.
وهذا يعني أن أي بيانات يمكن النظر إليها على أنها **[مصفوفة][array]** من تلك البايتات الأساسية.

## الوصول إلى العناصر في مصفوفة

لكي تصل إلى أي قيمة في الذاكرة، من الضروري أن تحسب **عنوانها الفعّال**.
العنوان الفعّال هو تعبير قد يتكوّن من:

- _عنوان أساسي_، مثل العنوان الذي يشير إليه وسم متغير.
- _سجل فهرس_ واحد، يمكن أن يُضرب في `1` أو `2` أو `4` أو `8`.
- _إزاحة_ مُوقّعة من 32 بت، وهي عدد يُضاف إلى العنوان الأساسي (أو يُطرح منه).

لاحظ أن فهرسة هذا العنوان تبدأ من 0، لذا فإن عنوانًا أساسيًا بدون أي إزاحة يشير إلى البايت الأول من المتغير.
ولهذا فإن إلغاء الإشارة إلى الذاكرة باستخدام وسم فقط بدون أي إزاحة، كما فعلنا في المفاهيم السابقة، يُنتج قيمة تبدأ من بايتها الأول:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
يستخدم x86-64 [ترتيب البايت الصغير][endianness].
وهذا يعني أن أقل بايت أهمية في قيمة متعددة البايتات يُخزَّن في أصغر عنوان في الذاكرة.

وبالتالي، عند الوصول إلى البايتات الفردية لقيمة متعددة البايتات، من الضروري إضافة إزاحة موجبة إلى العنوان الأساسي للوصول إلى البايتات الأكثر أهمية.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

المتغير المهيّأ المُعرَّف بقائمة من القيم هو مصفوفة من تلك القيم، ولكل عنصر فيها الحجم المحدَّد.
لكن الإزاحات تكون دائمًا بالبايتات، حتى عندما يكون حجم كل عنصر في المصفوفة أكبر:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

لاحظ أنه بما أن العناوين بالبايتات، يمكنك الوصول مباشرة إلى بايت فردي في أي عنصر من عناصر المصفوفة:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

وللسبب نفسه، يمكنك الوصول إلى أكثر من حجم عنصر واحد في تعليمة واحدة:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
لا تُجري لغة التجميع أي تحقق من الحدود عند الوصول إلى المصفوفات.
الفهرس الذي يتجاوز نهاية المصفوفة يقرأ أو يكتب في ذاكرة خارجها.
قد يؤدي هذا إلى نتائج خاطئة بصمت، وإلى إفساد بيانات أخرى، وإلى خطأ في وقت التشغيل إذا كانت الذاكرة التي جرى الوصول إليها غير مُخصَّصة.
المبرمج مسؤول عن إبقاء كل عنوان فعّال داخل المصفوفة.
~~~~

## حساب حجم مصفوفة مهيّأة

يمتلك NASM (The Netwide Assembler، وهو المُجمِّع المستخدَم في هذا المسار) رمزًا خاصًا (`$`) يشير إلى الموقع الحالي في الذاكرة.
يوفر هذا الرمز طريقة ملائمة لحساب الحجم الكلي في الذاكرة الذي تشغله مصفوفة:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

عند استخدامه مباشرة بعد `example`، يحمل `$` عنوان نهاية المصفوفة في الذاكرة.
وهذا يعني أن `$ - example` هو الفرق بين ذلك العنوان والعنوان الذي يشير إليه الوسم `example`.
وهذا هو بالضبط الحجم الكلي، بالبايتات، الذي تشغله المصفوفة التي يشير إليها `example`.

إذن، بتعريف `example_length` بهذه القيمة، أنشأنا متغيرًا بحجم 8 بايتات يخزّن حجم المصفوفة، أو طولها، بالبايتات.

## قسم .bss

تُعرَّف البيانات غير المهيّأة في **[القسم .bss][bss]**.
في معظم الأنظمة الأساسية، يملأ نظام التشغيل هذه البيانات بالأصفار عند بداية البرنامج.

في NASM، المتغير غير المهيّأ له اسم، وتوجيه يحدد حجم البيانات، وعدد العناصر المطلوب حجزها.
ويفصل كل واحد منها عن الآخر بمسافة.

أهم التوجيهات وأحجام البيانات المرتبطة بها هي:

| التوجيه | الحجم    |
| :-------: | :------ |
|   resb    | 1 بايت  |
|   resw    | 2 بايت |
|   resd    | 4 بايت |
|   resq    | 8 بايت |

على سبيل المثال، هذا يحجز مساحة غير مهيّأة بمقدار `3` بايتات في متغير اسمه `example`:

```x86asm
section .bss
    example resb 3
```

وهذا يحجز مساحة غير مهيّأة بمقدار `10` مضروبة في `8` بايتات (أي `80` بايتًا) في متغير اسمه `arr`:

```x86asm
section .bss
    arr resq 10
```

المتغيرات في `section .bss` قابلة للتغيير، أي أنها للقراءة والكتابة.

يمكن الوصول إلى البيانات غير المهيّأة بالطريقة نفسها التي تصل بها إلى البيانات المهيّأة، باستخدام عنوانها الفعّال.
وبالمثل، فهي أيضًا ذات مدة تخزين ساكنة ويمكن الوصول إليها من أي دالة في ملف المصدر نفسه (وإذا عُرِّفت بـ `global`، فمن ملفات مصدر أخرى أيضًا).

## الوصول إلى عناوين المصفوفات باستخدام التعليمة `lea`

كما رأينا في مفهوم سابق، تحسب التعليمة `lea` عنوان ذاكرة فعّالًا.
ويمكن استخدامها لحساب عنوان أي عنصر في مصفوفة، وفق الدلالات نفسها.

لاحظ أن العنونة النسبية كثيرًا ما تتطلب تحميل عنوان المتغير في سجل قبل تكوين عنوان أكثر تعقيدًا:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
من مزايا `lea` أنها تستخدم حساب العناوين لحساب قيمة دون الوصول فعليًا إلى الذاكرة في ذلك العنوان.
وهذا يجعلها مفيدة لإجراء حسابات حسابية حتى عندما لا يحمل أي سجل عنوان ذاكرة:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
