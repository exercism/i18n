# مقدمة

غالبًا ما يكون من المفيد تعريف أنواع مخصصة في برامجنا.

يمكن إنشاء أنواع أولية جديدة، لكن ذلك نادرًا ما يحدث.
الأنواع الأولية المدمجة ليست خيارًا اعتباطيًا: فهي تطابق عن قرب الأنواع القياسية في مترجم LLVM الذي تستخدمه Julia للترجمة الفورية (JIT).

لكن الأكثر فائدة بكثير هو القدرة على تعريف أنواع مركبة بحقول مُسمّاة.

توجد في لغات أخرى بنى مشابهة، تُسمى `structs` أو `records`.
أما توثيق Julia فيسميها `composite types`، مع أن صياغة اللغة تعرّفها بالكلمة المفتاحية `struct` (وهو عدم توافق طفيف).

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

تجدر ملاحظة بعض النقاط في المثال أعلاه:

- لم يُحدَّد نوع لـ `id`، لذلك يفسّره المترجم على أنه `id::Any`.
  - عمليًا، من الأفضل مساعدة المترجم بتحديد نوع الحقل بنوع ملموس
- يُستخدم اسم النوع كبانية، كما في `Person(id, name, age)`، لإعطاء نسخة من النوع `Person`.
- يمكن الوصول إلى كل حقل على حدة بالترميز النقطي، تمامًا كما في الصفوف المسماة.

عناصر النوع `Person` غير قابلة للتغيير، لذا لا يُسمح بالتحديثات.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

إذا لزمت قابلية التغيير، فأضف `mutable` إلى التعريف.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

تتطلب البانية افتراضيًا أن تظهر الحقول بالترتيب نفسه الوارد في التعريف، وهو ما يصبح غير مريح مع الأنواع الأكثر تعقيدًا.

يتيح استخدام الماكرو `@kwdef` قدرتين جديدتين:

- تستخدم البانية الكلمات المفتاحية، لا الموضع.
- يمكن أن يكون للحقول قيم افتراضية، ويمكن اختياريًا حذفها من البانية.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## هرمية الأنواع المركبة

حتى الآن أنشأنا أنواعًا مركبة ملموسة فقط.
وإذا تحققت، فكلها أنواع فرعية من `Any`.

عند إنشاء عدة أنواع مترابطة، يكون من المنطقي أكثر أن نعرّف لها هرمية.
وهذا سهل جدًا.

أولًا، أنشئ نوعًا مجردًا:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

بعد ذلك، أدرج العامل `<:` في تعريف النوع، لبيان العلاقة.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

كرّر ذلك حسب الحاجة، وتذكّر أن إنشاء نوع فرعي من نوع ملموس غير مسموح به.

لهرمية أكثر تعقيدًا، أنشئ أنواعًا فرعية مجردة عند الحاجة.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

ستتضح قيمة هذه الهرمية أكثر عندما نصل إلى مفهوم `Multiple Dispatch`، ونرى كيف تتعامل الدوال مع أنواع الوسائط.
