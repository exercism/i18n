# نبذة

أسلوب Factor الوحيد لتمرير البيانات هو *مكدس البيانات*: تسحب الكلمات مُدخلاتها وتدفع مُخرجاتها. وكل تعريف لكلمة يُعلن *تأثير المكدس* الذي يوثّق هذا العقد.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

الأسماء داخل `( … -- … )` هي لصالح القارئ؛ أما ما يتحقق منه المصرّف فهو *عدد* المدخلات والمخرجات. وعدم التوافق خطأ في وقت التصريف، وهو ما يكشف فئة من الأخطاء كانت ستكون أخطاء وقت التشغيل في لغة ذات أنواع ديناميكية تفتقر إلى هذا النوع من الإعلان.

ولأن مكدس البيانات يعتمد على الموضع، فأنت بحاجة دائمًا إلى إعادة ترتيب قمّته قبل أن تعمل الكلمة التالية. وكلمات إعادة ترتيب المكدس في `kernel` تفعل ذلك بالضبط:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

وتوسّع عائلة إعادة ترتيب المكدس الكاملة هذه الكلمات بـ `-rot` (التي تُدوّر في الاتجاه الآخر)، وأبناء العم المُلحقين بـ `d` الذين يعملون على عنصر أعمق (`dupd`, `swapd`)، وأبناء العم المبدوءين بـ `2` الذين يعملون على أزواج (`2dup`, `2drop`, `2nip`)، وغيرها مثل `pick` و`tuck`. وتُقدَّم هذه الكلمات كلما احتاجت إليها التمارين اللاحقة؛ والاستعانة بعدد كبير من كلمات إعادة ترتيب المكدس دفعة واحدة علامة على أن *المتغير المحلي* (قيمة مُسمّاة) سيكون أوضح للقراءة.

بحسب العُرف، تُكتب الكلمات بأسلوب `lowercase-kebab-case`، وتنتهي الكلمات التي تفحص شرطًا بـ `?` وتُنتج قيمة منطقية (`even?`, `empty?`)، وتُكتب كلمات الضبط بالشكل `>>name` وكلمات الجلب بالشكل `name>>`، وكثيرًا ما تشترك الكلمة ونسختها المُعدِّلة في الاسم نفسه، ولا يفصل بينهما إلا السياق.
