# مقدمة

## التطبيق الجزئي وتركيب الدوال

### التطبيق الجزئي

جميع الدوال في Elm دوال كاريّة، وهذا يعني أنك إذا استدعيت دالة دون تمرير كل الوسائط، فإنها تُرجع دالة جديدة.

تُسمّى نتيجة فعل ذلك [التطبيق الجزئي][partial-application] (أنت لا تمرر كل الوسائط إلى الدالة، بل تطبّق بعضها تطبيقًا جزئيًا).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

التطبيق الجزئي يطبّق الوسائط دائمًا بالترتيب.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

### معامل الأنبوب (`|>`)

قول `x |> f` مطابق تمامًا لقول `f x`. ومن الأمثلة الملموسة أن `"5" |> String.toInt` مطابق لـ `String.toInt "5"`.

قد لا يبدو هذا مفيدًا كثيرًا في البداية، لكنه يُسمّى [معامل الأنبوب][pipe-operator] لأنه يتيح لك كتابة كود يعمل عبر الأنابيب.

على سبيل المثال، لنفترض أن لدينا دالة `sanitize` لتحويل مدخلات المستخدم إلى أعداد صحيحة:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

يمكننا إعادة كتابتها هكذا:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

يتجنّب هذا استخدام الأقواس، ويعرض الدوال بترتيب تطبيقها (أولًا `String.trim`، ثم `String.toInt`)، مما يساعد على سهولة القراءة.

هناك أيضًا [معامل الأنبوب العكسي `(<|)`][reverse-pipe-operator].
قول `f <| x` مطابق تمامًا لقول `f x`.
لا يبدو هذا مفيدًا كثيرًا للوهلة الأولى أيضًا، وهو بالتأكيد لا يُستخدم بقدر معامل الأنبوب، لكنه يساعد على تجنّب الأقواس في بعض الحالات.

### تركيب الدوال / الأسلوب الخالي من النقاط

معامل [`(>>)`][forward-composition] نوعه `(a -> b) -> (b -> c) -> (a -> c)` وينشئ دالة من النوع `a -> c` بتركيب دالتين متوافقتين من النوع `a -> b ` و`b -> c`.
يفعل ذلك بأخذ القيمة المُرجَعة (من النوع `b`) من الدالة الأولى واستخدامها وسيطًا أول للدالة الثانية (الذي يجب أن يكون من النوع نفسه `b`).
الدالة المُنشأة ستأخذ المدخل نفسه (من النوع `a`) الذي تأخذه الدالة الأولى، وستُرجع أي قيمة `c` تُرجعها الدالة الثانية.

ومن الأمثلة الملموسة `String.trim >> String.toInt`.
تأخذ `String.trim` سلسلة نصية كمعاملها الوحيد، وهذا ما تأخذه الدالة المُنشأة.
تُرجع `String.toInt` قيمة `Maybe Int`، وهذا ما تُرجعه الدالة المُنشأة.
تُرجع `String.trim` قيمة `String`، وهي ما تقبله `String.toInt` كمعامل، لذا يُترجم المثال بنجاح.

يمكننا الآن إعادة كتابة دالتنا `sanitize` على النحو التالي:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

لاحظ أننا لم نعد نستخدم المعامل `input` الذي تراه في المثال الأصلي، رغم أن الوظائف متطابقة.
تُسمّى هذه الطريقة في إنشاء الدوال التي لا تشير إلى معاملاتها «الأسلوب الخالي من النقاط».
ميزة هذا الأسلوب أن الكود أكثر إيجازًا، والعيب أنه قد يكون أصعب في الفهم، خاصة للمبتدئين.

يجدر التذكير بأن جميع الدوال في Elm كاريّة، لذا يُترجم `String.length >> max` بنجاح.

- معامل [`(>>)`][forward-composition] نوعه `(a -> b) -> (b -> c) -> (a -> c)`.
- نوع `String.length` هو `String -> Int`، وهو الجزء `(a -> b)`، لذا فإن `a` هو `String` و`b` هو `Int`.
- نوع `max` هو `Int -> Int -> Int`، وهو الجزء `b -> c`.
- `b` هو `Int`، لذا يُطبَّق `max` تطبيقًا جزئيًا، وبذلك يكون `c` هو نتيجة هذا التطبيق الجزئي (`Int -> Int`).
- إذن نوع `String.length >> max` هو `String -> (Int -> Int)`.
- لذا فإن `((String.length >> max) "123") 2` تُرجع `3`، لأن طول `"123"` هو 3، وهو أكبر من 2 القادم من وسيط `Int`.

### تصميم الدوال

لتسهيل كتابة كود أنيق في Elm، ينبغي أن تجعل بنية البيانات الرئيسية آخر معامل في الدوال.
تفعل جميع الدوال الشائعة في المكتبة القياسية ذلك، مثل `List.map` (توقيع النوع أدناه).

```elm
map : (a -> b) -> List a -> List b
```

هنا نرى أن آخر معامل لدالة `map` هو `List a` وأنها تُرجع `List b`، لذا فبنية البيانات الرئيسية (`List`) هي آخر معامل.

يتيح هذا كتابة كود أنيق يعمل عبر الأنابيب، كما في المثال التالي.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

كما يجعل من الملائم استخدام تركيب الدوال والأسلوب الخالي من النقاط، كبديل عن الأنابيب.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

يتيح لك تركيب الدوال أيضًا اختصار هذا المثال إلى استدعاء واحد لـ `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
