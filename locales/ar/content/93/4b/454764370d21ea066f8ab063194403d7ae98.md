# الأصناف غير القابلة للتغيير

`SCOREBOARD` شيء يتغيّر. الاسمان اللذان يدلّان على لوحة نتائج واحدة يريان النتيجة نفسها، لأنه لا توجد إلا لوحة واحدة وكلاهما يشير إليها.

أما الاتجاه فليس كذلك. فـ`350 degrees` لا يصير شيئًا آخر، بل هو *هو* ببساطة. الأعداد تسلك هذا المسلك، وكذلك السلاسل النصية، وكذلك يمكن أن تفعل أصناف من صنعك أنت.

## immutable

```sather
immutable class BEARING is

   readonly attr degrees : INT;

end; -- class BEARING
```

كلمتان تغيّران كل شيء. الكائن المنتمي إلى صنف غير قابل للتغيير هو **قيمة**، لا شيء يُشار إليه:

- تُنسخ عند الإسناد أو التمرير، فلا يستطيع أحد آخر تغيير ما لديك؛
- ولا يمكن أن تكون معدومة؛
- ولا يمكن إسناد قيم إلى خصائصها.

## تغيير أحدها بإنشاء آخر

بما أن `degrees := 90` غير مسموح به، فإن `attr` يقدّم شيئًا آخر: دالة تأخذ القيمة الجديدة وتُرجع **كائنًا جديدًا** يحمل التغيير.

```sather
   b ::= b.degrees(90);      -- not b.degrees := 90
```

يبقى الأصل دون مساس. هذا هو الأسلوب كله، وهكذا تُكتب `create`:

```sather
   create(d : INT) : SAME is
      b : SAME;                     -- starts with everything at nought
      return b.degrees(d);
   end;
```

لا وجود لـ`new` هنا. الكائن غير القابل للتغيير موجود دائمًا، لذا فإن `b : SAME` هو بالفعل كائن، وكل خصائصه عند قيمتها الفارغة.

لذا فإن الدالة التي «تغيّر» اتجاهًا إنما تُرجع اتجاهًا جديدًا:

```sather
   turned(by : INT) : SAME is
      return #BEARING(degrees + by);
   end;
```

## المقارنة

تُقارَن القيم بمحتواها، لا بالكائن الذي تنتمي إليه، لكن عليك أن تحدّد كيف. اكتب `is_eq`، وسيستخدم `=` هذه الدالة:

```sather
   is_eq(other : SAME) : BOOL is
      return degrees = other.degrees;
   end;
```

وبدونه، لن يُترجم استخدام `=` على اتجاهين.

## أيّهما تختار

استخدم صنفًا غير قابل للتغيير حين لا تكون للشيء هوية ولا يمكن تغيير أي شيء فيه تغييرًا معقولًا: اتجاه، أو نقطة، أو تاريخ، أو طول. واستخدم صنفًا عاديًا حين يكون الشيء شيئًا بعينه تحدث له أشياء: لوحة نتائج، أو منصة اختبار، أو ملف.

والمعيار هو: هل تعني «نفسه» «مساويًا له» أم «الشيء ذاته بعينه»؟
