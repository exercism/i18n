# حول البتات

تُقابل الأرقام الثنائية في النهاية الترانزستورات في وحدة المعالجة المركزية أو الذاكرة مباشرةً، وما إذا كان كلٌّ منها في حالة "تشغيل" أو "إيقاف".

تعد المعالجة على المستوى المنخفض، التي تُسمى عاميًّا "العبث بالبتات"، مهمة بشكل خاص في لغات الأنظمة.

عادةً ما تُخفي اللغات عالية المستوى مثل Kotlin معظم هذه التفاصيل. ومع ذلك، تتوفر مجموعة أساسية من العمليات على مستوى البتات [متاحة][ref-bitwise].

~~~~exercism/note
لرؤية مخرجات ثنائية قابلة للقراءة البشرية، تحتاج معظم الأمثلة أدناه إلى تغليفها داخل الدالة [`Integer.toBinaryString()`][web-binstring]، أو تحويلها باستخدام `toString(radix = 2)`.
 
هذا يُشتّت الانتباه بصريًّا، لذلك حُذفت معظم حالات ظهور هذه الدالة، وتُمثَّل النتائج بترميز `0b`.

[web-binstring]: https://www.baeldung.com/kotlin/int-binary-representation
~~~~

## عمليات إزاحة البتات

يمكن تمثيل الأنواع `Int` أو `Long`، بإشارة وبدون إشارة، على هيئة سلسلة نصية من الآحاد والأصفار، ومعالجتها كتتابع من البتات.

وقد يكون مفاجئًا أن النوعين `Byte` و`Short` لا يتوافقان مع معظم العمليات على مستوى البتات في Kotlin. جميع الأمثلة أدناه تستخدم أعدادًا صحيحة بسعة 32 بت (`Int` أو `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

تُحرّك إزاحات البتات كل شيء إلى اليسار أو اليمين بعدد محدد من المواضع. تسقط بعض البتات من أحد الطرفين، ويُحشى الطرف الآخر بالأصفار أو الآحاد.

- الإزاحة إلى اليسار باستخدام `shl`: حشو بالأصفار.
- الإزاحة إلى اليمين باستخدام `shr` أو `ushr`: حشو بالأصفار للأعداد الموجبة (انظر قسمًا لاحقًا للأعداد السالبة).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

كل إزاحة إلى اليسار تُضاعف القيمة، وكل إزاحة إلى اليمين تُنصّفها (مع احتمال الاقتطاع). يظهر هذا بوضوح أكبر في التمثيل العشري:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

هذا النوع من إزاحة البتات أسرع بكثير من العمليات الحسابية "الفعلية"، مما يجعل هذه التقنية شائعة جدًّا في البرمجة منخفضة المستوى.

### إزاحة الأعداد الصحيحة السالبة

مع _الأعداد الصحيحة السالبة_، نحتاج إلى مزيد من الحذر.

تُخزَّن القيم السالبة بصيغة [المتمم الثنائي][wiki-2complement]، ما يعني أن البت في أقصى اليسار يساوي 1. لا مشكلة في الإزاحة إلى اليسار، لكن عند الإزاحة إلى اليمين، كيف نحشو البتات في أقصى اليسار؟

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

يُنفّذ العامل [`shr`][ref-shr] [الإزاحة الحسابية][wiki-arithmetic]، مع الحفاظ على بت الإشارة.

يُنفّذ العامل [`ushr`][ref-ushr] [الإزاحة المنطقية][wiki-logical]، بالحشو بالأصفار كما لو كان العدد بدون إشارة.

## المنطق على مستوى البتات

رأينا في [مفهوم القيم المنطقية][concept-booleans] أن العوامل `&&` (and) و`||` (or) و`!` (not) تُستخدم مع القيم المنطقية.

توجد عوامل مكافئة هي `and` و`or` و`xor` ([أو الحصرية][wiki-xor]) لمقارنة البتات في عددين صحيحين، ودالة `inv` (الانعكاس) لقلب جميع البتات.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
