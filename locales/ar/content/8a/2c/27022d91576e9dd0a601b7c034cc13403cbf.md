# مقدمة

## الاستثناءات

كل الأخطاء في Elixir تُطبّق _سلوك الاستثناء_. وكما في _سلوك الوصول_، يحدّد _سلوك الاستثناء_ دوال استدعاء راجعة يجب على الوحدة تنفيذها لتفي بالعقد البرمجي لهذا السلوك. وبمجرد تعريف خطأ، تكون له الخصائص التالية:

- اسم الوحدة يحدّد اسم الخطأ.
- الوحدة تعرّف بنية الخطأ.
- ستحتوي البنية على حقل `:message`.
- يمكن استخدام الوحدة مع `raise/1` و`raise/2` لرفع الخطأ المقصود

يحدّد _سلوك الاستثناء_ أيضًا دالتَي استدعاء راجعتين: `message/1` و`exception/1`. وإذا لم تُنفَّذ، ستُستخدم تنفيذات افتراضية. تحوّل `message/1` بنية الخطأ إلى رسالة مقروءة عند استدعائها مع `raise`. وتتيح `exception/1` إضافة سياق إضافي إلى الرسالة عند استدعائها مع `raise/2`.

### تعريف استثناء

لتعريف استثناء انطلاقًا من وحدة خطأ، نستخدم ماكرو `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### استخدام الاستثناءات

يمكن استخدام الأخطاء المعرّفة مثل خطأ مدمج باستخدام `raise/1` أو `raise/2`.

- `raise/1` يرفع خطأً محددًا باسم وحدته، وإذا كان الوسيط سلسلة نصية، فإنه يرفع `RuntimeError` وتكون هذه السلسلة النصية هي رسالته.
- `raise/2` يرفع خطأً محددًا باسم وحدته، ويقبل وسيط سمات يُستخدم للحصول على الخطأ بالرسالة المناسبة.
