# مقدمة

## الأصناف

حان الوقت للوصول إلى أحد الأنماط الأساسية في C++: البرمجة كائنية التوجه (OOP).
تتمحور البرمجة كائنية التوجه حول `classes`، وهي أنواع بيانات يعرّفها المستخدم ولها مجموعتها الخاصة من الدوال المرتبطة بها.
سنبدأ بالأساسيات، ثم نتناول موضوعات أكثر تقدّمًا في مواضع أعمق من شجرة المنهج.

### الأعضاء

يمكن أن تحتوي الأصناف على **متغيرات الأعضاء** و**دوال الأعضاء**.
ويتم الوصول إليها عبر عامل **اختيار الأعضاء** `.`.
وكما هو الحال مع المتغيرات خارج `classes`، يُستحسن تهيئة متغيرات الأعضاء بقيمة عند التعريف.
ستصبح هذه القيمة بعد ذلك القيمة الافتراضية للكائنات المُنشأة حديثًا من هذا الصنف.

### التغليف وإخفاء المعلومات

توفّر الأصناف إمكانية تقييد الوصول إلى أعضائها.
هناك نوعان أساسيان من `access specifiers` هما `private` و `public`.
لا يمكن الوصول إلى الأعضاء `private` من خارج الصنف.
أما الأعضاء `public` فيمكن الوصول إليها بحرية.
جميع أعضاء `class` تكون `private` افتراضيًا.
ولا يكون الاستخدام الحر خارج الصنف متاحًا إلا للأعضاء المعلَّمة صراحةً بـ `public`.

### مثال أساسي

يمكن رؤية تعريف `class` في المثال التالي.
لاحظ `;` بعد التعريف:

```cpp
class Wizard {
  public:               // from here on all members are publicly accessible
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

يمكنك الوصول إلى جميع متغيرات الأعضاء من داخل الصنف.
ألقِ نظرة على `damage` داخل الدالة `cast_spell`.
ولا يمكنك قراءة الأعضاء `private` أو تغييرها من خارج الصنف:

```cpp
Wizard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

### المنشئات

تتيح المنشئات إمكانية إسناد قيم إلى متغيرات الأعضاء عند إنشاء الكائن.
وهي تحمل الاسم نفسه الذي يحمله `class` وليس لها نوع إرجاع.
ويمكن أن يحتوي الصنف على عدة منشئات.
وهذا مفيد إن لم تكن بحاجة دائمًا إلى ضبط جميع المتغيرات.
أحيانًا قد ترغب في إبقاء كل شيء على القيمة الافتراضية مع تغيير المتغير `name`.
وفي حالة ساحر مهم، قد ترغب في تغيير الضرر أيضًا، لذا تحتاج إلى اثنين من `constructors`.

```cpp
class Wizard {
  public:
    Wizard(std::string new_name) {
      name = new_name;
    }
    Wizard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizard el{"Eleven"};       // deals  5 damage
Wizard vecna{"Vecna", 50}; // deals 50 damage
```

المنشئات موضوع كبير وفيه تفاصيل دقيقة كثيرة.
إذا لم تُعرّف `constructor` لـ `class` بشكل صريح، فحينها فقط سيقوم المترجم بهذه المهمة نيابةً عنك.
وهذا ما حدث في المثال الأول أعلاه.
أُنشئ الكائن _silverhand_ باستدعاء المنشئ الافتراضي، دون تمرير أي وسائط.
تُضبط جميع المتغيرات على القيمة المذكورة في تعريف الصنف.
وإذا لم تكن قد أعطيت أي قيم في ذلك التعريف، فقد تبقى المتغيرات دون تهيئة، وقد يؤدي ذلك إلى نتائج غير مقصودة.

## البُنى

جاءت البُنى من جذور اللغة الأصلية في C، وعمرها من عمر C++ نفسها.
وهي في جوهرها الشيء نفسه الذي تعنيه `classes`، مع استثناء مهم واحد.
فكل شيء داخل `class` يكون `private` افتراضيًا.
أما البُنى فتكون `public` حتى يُحدَّد غير ذلك.
ومن المتعارف عليه أن الكلمة المفتاحية `struct` تُستخدم غالبًا لـ **بُنى البيانات فقط**.
وتُفضَّل الكلمة المفتاحية `class` للكائنات التي تحتاج إلى ضمان خصائص معيّنة.
وقد يكون أحد هذه الثوابت أن قيمة `damage` في `class` الساحر `Wizard` لا يمكن أن تصبح سالبة.
فالمتغير `damage` خاص، وأي دالة تغيّر الضرر ستضمن الحفاظ على هذا الثابت.
