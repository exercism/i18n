# ملحق التعليمات

## تخصيص الاستثناءات ورفعها

أحيانًا تحتاج في الكود إلى [تخصيص](https://docs.python.org/3/tutorial/errors.html#user-defined-exceptions) الاستثناءات و[`raise`](https://docs.python.org/3/tutorial/errors.html#raising-exceptions) بها. وعندما تفعل ذلك، يجب أن تُضمّن دائمًا **رسالة خطأ ذات معنى** توضّح مصدر الخطأ، فهذا يجعل الكود أكثر قابلية للقراءة ويساعد كثيرًا في تصحيح الكود.

يمكن إنشاء استثناءات مخصصة عبر أصناف استثناءات جديدة (اطّلع على [`classes`](https://docs.python.org/3/tutorial/classes.html#tut-classes) لمزيد من التفاصيل) تكون عادةً أصنافًا فرعية من [`Exception`](https://docs.python.org/3/library/exceptions.html#Exception).

وفي الحالات التي تعرف فيها أن مصدر الخطأ سيكون مشتقًّا من نوع استثناء معيّن، يمكنك أن تختار الوراثة من أحد [`built in error types`](https://docs.python.org/3/library/exceptions.html#base-classes) الواقعة تحت صنف _Exception_. وعند رفع الخطأ، يجب أن تُضمّن رسالة ذات معنى على أي حال.

يتطلّب هذا التمرين تحديدًا أن تُنشئ _استثناءً مخصصًا_ [لرفعه](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement)/«إطلاقه» عندما لا يكون المكدس ممتلئًا بما يكفي. ولن تنجح الاختبارات إلا إذا خصّصت استثناءً مناسبًا، ورفعت ذلك الاستثناء باستخدام `raise`، وضمّنت رسائل خطأ مناسبة.


```python
# subclassing the Exception to create a StackUnderflowError
class StackUnderflowError(Exception):
    """Exception raised when Stack is not full.
       message: explanation of the error.
    """
    def __init__(self, message):
        self.message = message

        
# raising a StackUnderflowError
raise StackUnderflowError("Insufficient number of items in stack")
```

بالإضافة إلى ذلك، يتطلّب هذا التمرين أن ترفع عدة `built-in exceptions` مع رسائل خطأ.
ولرفع `built-in exception` مع رسالة، اكتب الرسالة كوسيط لنوع `exception`:

```python
# an example when division by zero is attempted.
raise ZeroDivisionError("divide by zero")

#an example when the operation is undefined.
raise ValueError("undefined operation")
```
