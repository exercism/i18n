# مقدمة

## التعدادات

حتى الآن تعاملنا في الغالب مع الأعداد والسلاسل النصية.
لكي نمثّل العالم الحقيقي، قد نحتاج إلى عدد محدود من القيم التي يمكن للمتغير أن يأخذها.
قد ترغب في نوع مخصّص له بضع قيم متمايزة بأسماء مختلفة.
على سبيل المثال، قد تريد في مصنع ألواح التزلج أن تكون مادة اللوح محصورة في الاختيار بين القيقب أو الخيزران أو البلاستيك فقط.

يمكنك استخدام الأعداد الصحيحة لترميز تلك القيم، لكن سيتعين عليك كتابة كود إضافي للتحقق مما إذا كانت هناك قيمة غير صالحة تأتي من النظام لمادة اللوح.
من الصعب تتبّع معنى تلك [_الأرقام السحرية_][magic numbers] عبر الكود المصدري، وهي عرضة للالتباس.
يمكن استخدام `enumerations` لتشجيع كود معبّر وللحدّ من أخطاء المقارنة غير المقصودة.

## مثال على الاستخدام

المصطلح المحدد لهذا النوع من التعداد هو `scoped enumeration`.
يعرض المقطع التالي كيفية كتابة `enumeration` باسم `DeckMaterial`.
لاحظ الكلمة المفتاحية `enum class` والرمز `;` في نهاية التعريف:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
الآن، انظر إلى دالة التسعير في متجر ألواح التزلج، ولاحظ عامل تحديد النطاق (`::`) الذي يحدّد `enumerator` من داخل `enumeration`:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## النطاق

تخيّل أن لديك `enumeration` آخر لمادة العجلات:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
على الرغم من أن العجلات واللوح قد يكونان معًا من _البلاستيك_، فلا يمكن الخلط بين الاثنين.
فهما _نوعان_ مختلفان: البلاستيك في `DeckMaterial` والبلاستيك في `WheelMaterial`.
سيكون لكل `enumeration` ما يخصّه من `enumerators` في نطاقه الخاص، أي في `namespace` الخاصة به.
ولهذا السبب تُسمّى `scoped enumerations`.

## التعدادات غير المحدَّدة النطاق
قد تفكّر أنه ما دام الاسم يحتوي على `scoped`، فلا بد أن توجد أيضًا تعدادات _`unscoped`_، وأنت محق في ذلك.
أصبحت `Unscoped enumerations` أقل شيوعًا لأنها كلها تتشارك النطاق العام نفسه.
وبسبب هذا التشارك، لا يمكن أن يكون لديك `unscoped enumerations` اثنان لهما نفس `enumerators` مثل _البلاستيك_ في المثال أعلاه.

كذلك، تتحوّل `unscoped enumerations` ضمنيًا إلى أعداد صحيحة.
انظر إلى المثال التالي للحصول على نتيجة مفاجئة:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

إذا أردت تحويل `scoped enumerations` إلى أعداد صحيحة، فيمكنك استخدام `static_cast<int>`.

## عبارات `switch`

مثل اللغات الأخرى، توفّر C++ أيضًا عبارة `switch`.
عبارات `switch` طريقة أقصر لكتابة عبارات `if ... else if` الطويلة.
ولإنشاء عبارة `switch`، نبدأ باستخدام الكلمة المفتاحية `switch` متبوعة بعدد صحيح.
ثم نحدّد كل شرط باستخدام الكلمة المفتاحية `case`.
ويمكننا أيضًا تحديد حالة `default` تُنفَّذ عندما لا يتحقق أي من شروط `case` السابقة.
وينبغي أن تنتهي كل حالة بعبارة `break` (أو `return`).

```cpp
int price{0};
int adults{3};
int kids{2};

switch (int group_size{adults + kids}) {
    case 1:
        price = 50;
        break;
    case 2:
        price = 70;
        break;
    default:
        price = group_size * 30;
}
```

## السقوط المتتالي

من الأمور المهمة في بنية `switch` أن الكود يستمر في التنفيذ حتى توقفه عبارة `break` (أو `return`).
وقد يؤدي هذا إلى سلوك غير متوقع.

```cpp
int adults{1};
int kids{0};
switch (int group_size{adults + kids}) {
    case 1:
        price = 50;
    case 2:
        price = 70;
    default:
        price = group_size * 30;
}
// price will be 30!
```

أهم حالة لاستخدام ميزة التنفيذ المتواصل هذه هي عبارة تحمل عدة تسميات.
يمكن لعدة نتائج في `switch` أن تُقابل نفس الجزء من الكود المراد تنفيذه.
وبهذه الطريقة، في تطبيق حجز مثلًا، يمكن أن تكون الدالة المستدعاة لمجموعتي الحجم 2 و3 هي نفسها:
```cpp
switch (group_size) {
case 1:
    book_room();
    break;
case 2:
case 3:
    book_apartment(group_size);
    break;
default:
    book_house(group_size);
}
// book_apartment happens when group_size is 2 or 3
```
