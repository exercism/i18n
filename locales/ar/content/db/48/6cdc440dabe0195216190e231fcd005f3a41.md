# نبذة

تصف أصناف مثل `LocalDate` و`LocalDateTime` _نقطة_ في الزمن.
تحتوي حزمة `java.time` أيضًا على صنفين يصفان _مقدارًا_ من الزمن:

- [`Period`][period-docs] هو مقدار زمني قائم على التاريخ، بالسنوات والأشهر والأيام، مثل "شهران وخمسة أيام".
- [`Duration`][duration-docs] هو مقدار زمني قائم على الوقت، بالساعات والدقائق والثواني والميلي ثانية والنانو ثانية، مثل "ساعة وثلاثون دقيقة".

يهمّ هذا الفرق لأن وحدات التقويم ليس لها طول ثابت.
قد يحتوي الشهر على 28 أو 29 أو 30 أو 31 يومًا، لذا فإن "شهرًا واحدًا" ليس عددًا ثابتًا من الثواني.
يتبع `Period` التقويم، بينما يقيس `Duration` الزمن الدقيق.

| | `Period` | `Duration` |
| --- | --- | --- |
| يخزّن | السنوات والأشهر والأيام | الثواني والنانو ثانية |
| يُستخدم مع | `LocalDate`، `LocalDateTime` | `LocalTime`، `LocalDateTime`، `Instant` |

الصنفان كلاهما غير قابلين للتغيير.
تُرجع طرق مثل `plusDays()` أو `multipliedBy()` نسخة _جديدة_ وتترك الأصل دون تغيير.

## `Period`

### إنشاء فترة

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

تستخدم نتيجة `toString()` [صيغة المدة ISO-8601][iso-8601-durations]: الحرف `P` متبوعًا بعدد السنوات (`Y`) والأشهر (`M`) والأيام (`D`).
لا توجد أسابيع في `Period`: يُخزَّن `Period.ofWeeks(2)` على هيئة 14 يومًا.
ويمكن تحليل الترميز نفسه مرة أخرى باستخدام `Period.parse()`:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### إضافة فترة إلى تاريخ

تُضاف الفترة إلى تاريخ أو تُطرح منه باستخدام `plus()` و`minus()`:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

يمكن إضافة فترة إلى `LocalDateTime` بالطريقة نفسها، ويبقى وقت اليوم كما هو:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

لا يملك `Instant` تقويمًا، لذا لا يمكن إضافة سوى فترة من الأيام إليه.
أما الفترة التي تحتوي على سنوات أو أشهر فترمي استثناءً:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

تُضاف السنوات أولًا، ثم الأشهر، ثم الأيام.
وعندما تؤدي إضافة سنوات أو أشهر إلى الوصول إلى يوم غير موجود، تُنقل النتيجة إلى آخر يوم صالح في ذلك الشهر:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

يعني هذا أيضًا أن إضافة فترة ثم طرحها مرة أخرى لا تُعيد التاريخ الأصلي دائمًا:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### الفترة بين تاريخين

تُرجع `Period.between()` الفترة من تاريخ (ضمنًا) إلى تاريخ آخر (دون ضمه).
ويمكن الحصول على النتيجة نفسها عبر `LocalDate.until()`:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

يمكن الحصول على أجزاء الفترة عبر `getYears()` و`getMonths()` و`getDays()`.
هذه الأجزاء مستقلة عن بعضها: فـ `getDays()` تُرجع جزء الأيام فقط، لا العدد الإجمالي للأيام.
وتُرجع `toTotalMonths()` السنوات والأشهر مجتمعةً على هيئة عدد من الأشهر، لكن لا توجد طريقة للعدد الإجمالي للأيام، لأن ذلك يعتمد على الأشهر المعنية.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### تطبيع فترة

تحتفظ الفترة المنشأة بطريقة مصنع بوحداتها كما هي تمامًا، وتقارن `equals()` الوحدات واحدة تلو الأخرى.
أما `normalized()` فتحوّل الأشهر الفائضة إلى سنوات، لكنها تترك الأيام كما هي:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## عدّ الوحدات باستخدام `ChronoUnit`

للحصول على العدد الإجمالي لوحدة واحدة بين نقطتين في الزمن، استخدم الطريقة `between()` على أحد ثوابت [`ChronoUnit`][chronounit-docs]:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

تُحتسب الوحدات الكاملة فقط، وتكون النتيجة سالبة عندما يأتي الوسيط الثاني قبل الأول:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

وتعمل `ChronoUnit` مع الوحدات الزمنية والتواريخ والأوقات أيضًا:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### إنشاء مدة

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

في ترميز ISO-8601 يفصل الحرف `T` جزء التاريخ عن جزء الوقت.
ولا يحتوي `Duration` على جزء تاريخ، لذا تبدأ `toString()` الخاصة به دائمًا بـ `PT`.
وتعامل `Duration.ofDays()` اليوم على أنه 24 ساعة بالضبط.

ويمكن أيضًا تحليل مدة باستخدام `Duration.parse()`:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### إضافة مدة إلى وقت

تُضاف المدة إلى `LocalTime` أو `LocalDateTime` أو `Instant` أو تُطرح منه باستخدام `plus()` و`minus()`:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

يلتف `LocalTime` حول منتصف الليل، كما يوضح المثال الأخير.

ولا يحتوي `LocalDate` على وقت، لذا لا يمكن دمجه مع `Duration`:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### المدة بين وقتين

تُرجع `Duration.between()` المقدار الدقيق للزمن بين وقتين أو قيمتي تاريخ ووقت:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

لا تقبل `Duration.between()` قيمتي `LocalDate`، لأن التاريخ لا يحتوي على ثوانٍ يمكن قياسها:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

استخدم `Period.between()` أو `ChronoUnit.DAYS.between()` للتواريخ بدلًا من ذلك.

### تحويل مدة

تحوّل الطرق `toXxx()` المدة إلى مقدار _إجمالي_ من وحدة واحدة، بتقريب نحو الأسفل:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

وتقسّم الطرق `toXxxPart()` المدة إلى أجزائها، كما في الساعة:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

تتوقف `toHoursPart()` عند 23، لأن الساعات فوق ذلك تُحتسب بواسطة `toDaysPart()`.

### المقارنة والحساب باستخدام المدد

يمكن مقارنة المدد باستخدام `compareTo()`، وفحصها باستخدام `isZero()` و`isNegative()`:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

وتدعم أيضًا العمليات الحسابية، مثل `plus()` و`minus()` و`multipliedBy()` و`dividedBy()`:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` أم `Duration`؟

بالنسبة إلى `LocalDate` أو `LocalTime`، فالخيار محسوم لك: فالتاريخ لا يحتوي على وقت لقياسه، والوقت لا يحتوي على تقويم.
ويملك `LocalDateTime` كليهما، لكن دون منطقة زمنية، لذا فإن إضافة `Period.ofDays(1)` أو `Duration.ofDays(1)` إليه تعطي النتيجة نفسها.
ويظهر الفرق عند وجود مناطق زمنية.
فعندما تتقدم الساعات بسبب التوقيت الصيفي، يصبح اليوم التقويمي 23 ساعة فقط:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

إضافة `Period` مقدارها يوم واحد تحافظ على وقت اليوم، بينما إضافة `Duration` مقدارها يوم واحد تضيف 24 ساعة بالضبط.
استخدم `Period` للمقادير التي يفكر فيها الناس بمصطلحات تقويمية ("الوقت نفسه الشهر القادم")، و`Duration` للزمن المنقضي ("تذكرة الوقوف صالحة لمدة ساعتين").
