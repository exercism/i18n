# مقدمة

عندما يصادف برنامج `jq` مشكلة أثناء معالجة قيمة، مثل فهرسة عدد بسلسلة نصية، أو تحليل نص JSON غير صالح، أو استدعاء دالة بنوع خاطئ من الوسائط، فإنه يطلق **خطأ وقت تشغيل**.
وعندما يقع خطأ وقت تشغيل غير معالَج، يطبع `jq` رسالة إلى _الخطأ القياسي_ ويخرج بحالة خروج مقدارها `5`.

## إطلاق الأخطاء: `error` و`error(message)`

- يطلق `error` خطأً قيمته هي قيمة **المدخل**.
- يطلق `error(message)` خطأً قيمته هي ناتج `message`.

يمكن أن تكون قيمة الخطأ _أي_ قيمة JSON، وليست سلسلة نصية فقط.

```jq
42 | error("invalid value: \(.)")
# => "invalid value: 42"

42 | error
(not a string): 42
```

## التقاط الأخطاء: `try` و`catch`

يمكن التقاط الأخطاء باستخدام `try EXP catch HANDLER`.
يُنفَّذ التعبير الأول، وإذا أطلق خطأً يُنفَّذ التعبير `HANDLER` **ويكون مدخله قيمة الخطأ**.
ناتج `try catch` هو ناتج التعبير الذي نُفِّذ أخيرًا، سواء كان `EXP` أو `HANDLER`.

```jq
{a: 42} | try .a catch "no index a in \(.)"
# => 42

true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

true | try error("some exception") catch .
# => "some exception"
```

الصيغة الأقصر `try EXP` مكافئة لـ `try EXP catch empty`: يُهمَل الخطأ ولا ينتج أي ناتج.

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

## كتم الأخطاء: عامل `?`

عامل `?`، عند استخدامه بالصيغة `EXP?`، اختصار لـ `try EXP`.
وهو يحوّل تعبيرًا فاشلًا إلى تعبير لا ينتج شيئًا ببساطة.

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]
```

غالبًا ما يظهر هذا العامل ملحقًا بعوامل الفهرسة: `.foo?` و`.[]?`.

## إيقاف البرنامج: `halt_error` و`halt`

يوقف `halt_error` البرنامج، ويطبع مدخله إلى _الخطأ القياسي_ نصًا خامًا، ويخرج بحالة الخروج المعطاة، والتي تكون `5` افتراضيًا.
أما المرشح `halt` المرتبط به، فيوقف البرنامج بصمت بحالة خروج `0`.

```jq
"Error: something went wrong" | halt_error(1)
```
