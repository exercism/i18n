# نبذة

تُنشئ الكلمة `<dlist>` (في [`dlists`][dlists]) قائمة جديدة مزدوجة الترابط. تعيش العمليات في [`deques`][deques] وتُرسَل حسب [بروتوكول deque][deque-protocol]، بحيث تستطيع حاويات أخرى، وفي مقدمتها `<dlist>`، تنفيذها.

| الكلمة | التأثير |
|--------|---------|
| `<dlist>` | `( -- dlist )`: deque جديد فارغ |
| `push-front` | `( elt deque -- )`: إضافة إلى المقدمة |
| `push-back` | `( elt deque -- )`: إضافة إلى المؤخرة |
| `pop-front` | `( deque -- elt )`: إزالة من المقدمة |
| `pop-back` | `( deque -- elt )`: إزالة من المؤخرة |
| `peek-front` | `( deque -- elt )`: قراءة المقدمة دون إزالتها |
| `peek-back` | `( deque -- elt )`: قراءة المؤخرة دون إزالتها |
| `deque-empty?` | `( deque -- ? )`: هل الـ deque فارغ؟ |
| `dlist-length` | `( dlist -- n )`: عدد العناصر |

تُعدّل جميع عمليات الإضافة والإزالة الـ deque في مكانه، وتمرير deque إلى إجراء ثم قراءته منه مجددًا هو النمط المعتاد.

## المكدس مقابل الطابور

هناك نمطان تقليديان للإرسال:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

المتجه الذي يملك `push` و `pop` (من `mutation`) هو الخيار الصحيح عندما لا تحتاج إلا إلى ترتيب LIFO، إذ يحمل `<dlist>` عبئًا إضافيًا بسبب القائمة المترابطة. الجأ إلى `<dlist>` عندما تحتاج إلى O(1) عند *كلا* الطرفين، وهو ما يكون دائمًا تقريبًا من أجل طابور FIFO.

## نمط BFS

البحث بالعرض أولًا هو الاستخدام النموذجي لـ FIFO:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

يحمل الـ deque حدود البحث، بينما تحمل مجموعة التجزئة إزالة التكرار. استبدل `pop-front` بـ `pop-back` فيصبح النمط نفسه بحثًا بالعمق أولًا.

## `MEMO:`، التخزين المؤقت التلقائي

أحيانًا يكون الاستعلام عن كل عقدة، الذي يستدعيه BFS، مكلفًا. يوفّر Factor الكلمة [`MEMO:`][memo-decl]، وهي بديل لـ `:` يخزّن نتيجة الكلمة مؤقتًا تلقائيًا بحسب مدخلاتها:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

تنفّذ كلمة `MEMO:` جسمها في أول مرة يُرى فيها كل مدخل، ثم تُرجع النتيجة المخزّنة مؤقتًا بعد ذلك. تعيش الذاكرة المؤقتة طوال عمر الصورة؛ ولا يوجد إخلاء قائم على الوقت أو الحجم. استخدمها من أجل الدوال النقية التي تأتي مدخلاتها من مجموعة محدودة قابلة للإدارة.
