وكما ورد في [مفهوم السلاسل النصية][concept-strings]، فإن `stringr` لديها توثيق جيد، يكتبه عادةً مؤلف الحزمة أو مؤلفوها.

العديد من الدوال التي سبق أن نوقشت في مفهوم [`Strings`][concept-strings] مصمَّمة أصلًا للبحث بالتعبيرات النمطية.

لقد أبقينا مفهوم السلاسل النصية بسيطًا نسبيًا بالاكتفاء بمطابقة السلاسل النصية الحرفية، لكن يمكن استخدام أي نمط تعبير نمطي بدلًا من ذلك.

من حيث الصياغة الرسمية، يُنشأ التعبير النمطي في R باستدعاء [`regex()`][ref-regex].
وللتسهيل، تتعامل دوال `stringr` مع أي سلسلة نمطية على أنها تعبير نمطي.
في المثال أدناه، الاستدعاء الأول لـ `str_replace_all()` ليس إلا صياغة مختصرة للنسخة الثانية:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

تُعد [الورقة المرجعية السريعة][cheat-stringr] دليلًا مفيدًا: فكل الدوال التي لها وسيط `pattern` (المطبوع بالأحمر) تقبل تعبيرًا نمطيًا، وتلخّص الصفحة الثانية صياغة التعبيرات النمطية.

لاحظ أن الدالة [`regex()`][ref-regex] قد تظل مهمة إذا احتجت إلى تجاوز الإعدادات الافتراضية، مثل حساسية حالة الأحرف أو الإعدادات المحلية.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

يشتمل كثير من رموز التعبيرات النمطية على شرطة مائلة عكسية، مثل `\s` المستخدمة أعلاه.
وفي السلاسل النصية العادية في R، يجب تهريب `\` بمضاعفتها، ومن هنا `"\\s"`.

قد تتكاثر الشرطات المائلة العكسية وتصبح مربكة، لذا قد يساعد استخدام [السلاسل النصية الخام][book-raw] في الحالات المعقدة.

افتراضيًا، الصياغة المستخدمة لتعريف سلسلة نصية خام هي `r"( )"`، لكن يُسمح بفواصل أخرى.
ولأن الأقواس الهلالية `( )` والأقواس المربعة `[ ]` شائعة كلتاهما في صياغة التعبيرات النمطية (لمجموعات الالتقاط ومجموعات الخيارات)، فقد تكون الأقواس المعقوفة `{ }` خيارًا جيدًا.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## اكتشاف المطابقات

فيما يلي بعض الأسئلة، ودوال يمكن أن تساعد في الإجابة عنها.

تستخدم بعض الأمثلة [`fruit`][ref-fruit]، وهو متجه يضم 80 اسمًا من أسماء الفواكه مرفق مع `stringr` للتدريب.

_هل تحتوي سلسلة نصية على مطابقة؟_
استخدم [`str_detect()`][ref-str_detect]، أو [`str_starts()`][ref-str_starts] و`str_ends()` لتجنّب استخدام المراسي `^` و`$`.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_هل تريد إرجاع السلاسل النصية التي تحتوي على مطابقة فقط؟_
استخدم [`str_subset()`][ref-str_subset] للحصول على السلاسل النصية، و`str_which()` للحصول على الفهارس.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_كم عدد المطابقات في كل سلسلة نصية؟_
[`str_count()`][ref-str_count]

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_أين توجد المطابقة؟_
[`str_view()`][ref-str_view] للاستخدام التفاعلي، و[`str_locate()`][ref-str_locate] أو `str_locate_all()` بشكل أعم.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## الالتقاط

غالبًا ما نريد معرفة _ما_ الذي يطابق.
ويتحقق ذلك بتضمين مجموعات الالتقاط بين أقواس هلالية داخل التعبير النمطي.

يمكن الرجوع إلى عمليات الالتقاط داخل التعبير النمطي نفسه، باستخدام `\1` و`\2` وهكذا.
على سبيل المثال، إيجاد أزواج الحروف المتكررة:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

وبصياغة مشابهة، يمكن استخدام عمليات الالتقاط في سلاسل الاستبدال:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

اجمع المطابقات لمعالجتها لاحقًا باستخدام الدالة [`str_match()`][ref-str_match] للمطابقة الأولى فقط، أو `str_match_all()` لجميع المطابقات.

تميل مجموعات الالتقاط إلى إنتاج مخرجات معقدة في أي لغة.
ونهج R (_وهو أيضًا يعمل بأسلوب المتجهات كتحدٍّ إضافي_) هو توليد مصفوفة من `str_match()`، بحيث يكون لكل سلسلة نصية مُدخَلة صف واحد، ويحتوي العمود 1 على السلسلة النصية المطابقة كاملة، بينما تحتوي الأعمدة المتبقية على مجموعات الالتقاط المختلفة.

قد يكون استخدام المجموعات المسماة ميزة، إذ تصبح أسماء الأعمدة في مصفوفة النتائج.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

لم نقُل الكثير عن المصفوفات في هذا المنهج، مع أن هناك [مستندًا لمفهوم][concept-matrices-arrays] يمكنك الرجوع إليه.
ولا تنسجم المصفوفات جيدًا مع منظومة Tidyverse، رغم أنها جزء من Base R منذ زمن طويل.

بإيجاز سريع: تعامل مع المصفوفات كمتجهات ذات فهرسين، بالترتيب `[rows, cols]`.
واترك أيًّا من الفهرسين فارغًا للحصول على الصف أو العمود كاملًا.

عند الحصول على صف واحد `r` بواسطة `m[r,]` أو عمود واحد `c` بواسطة `m[, c]`، فإن القيمة المُرجَعة تُسطَّح إلى متجه افتراضيًا.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

بطبيعة الحال، تُنتج [`str_match_all()`][ref-str_match] مخرجات ذات بنية أكثر تعقيدًا:

- تكون النتيجة قائمة، بعنصر واحد لكل سلسلة نصية مُدخَلة.
- إذا كانت هناك سلسلة نصية مُدخَلة واحدة فقط، فأزل التغليف عن المخرجات بالفهرسة `[[1]]` كما هو موضح في [مفهوم القوائم][concept-lists].
- يكون كل عنصر مصفوفة، بأعمدة كما في `match()`.
- يمثل كل صف في المصفوفة عملية التقاط ناجحة.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

بطبيعة الحال، قد تفشل المطابقة.
وتكون النتيجة حينها القيمة الخاصة `NA`.
وكن مستعدًا لاختبار ذلك، كما هو موضح في [مفهوم العدم][concept-nothingness].

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
