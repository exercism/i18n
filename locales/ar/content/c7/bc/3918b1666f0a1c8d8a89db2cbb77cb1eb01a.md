# مقدمة

في Java، التحميل الزائد للطرق ميزة تسمح للصنف بأن يحتوي على أكثر من طريقة تحمل الاسم نفسه، بشرط أن تختلف قوائم معاملاتها.
وهو مرتبط بتعدد الأشكال في وقت الترجمة (أو تعدد الأشكال الساكن).
وهذا المفهوم جوهري لإنشاء طرق تؤدي مهامًا متشابهة لكن بمدخلات مختلفة.

## لماذا نستخدم التحميل الزائد للطرق؟

التحميل الزائد للطرق يزيد من قابلية قراءة البرنامج.
يمكن إعطاء طرق مختلفة الاسم نفسه لكن بمعاملات مختلفة.
وبحسب عدد المعاملات أو أنواعها، تُستدعى الطريقة المناظرة.

## كيف نُحمّل الطرق تحميلًا زائدًا؟

مفتاح التحميل الزائد للطرق هو توقيع الطريقة.
وتُعدّ الطريقتان مختلفتين إذا اختلف توقيعهما.
وهناك أسلوبان لتحميل طريقة ما تحميلًا زائدًا:

1. **اختلاف عدد المعاملات**: يمكن أن تحمل الطرق الاسم نفسه لكن بعدد مختلف من المعاملات.

   ```java
   public class Display {

       public void show(int x) {
           System.out.println("Show with int: " + x);
       }

       public void show(int x, int y) {
           System.out.println("Show with two ints: " + x + ", " + y);
       }
   }
   ```

2. **اختلاف أنواع المعاملات**: يمكن أن تحمل الطرق الاسم نفسه وعدد المعاملات نفسه لكن بأنواع مختلفة.

   ```java
   public class Display {

       public void show(int x) {
           System.out.println("Show with int: " + x);
       }

       public void show(String s) {
           System.out.println("Show with String: " + s);
       }
   }
   ```

## نقاط يجب تذكرها

- الطرق المُحمَّلة تحميلًا زائدًا يجب أن تغيّر قائمة الوسائط.
- يمكن للطرق المُحمَّلة تحميلًا زائدًا أن تغيّر نوع الإرجاع أيضًا، لكن مجرد تغيير نوع الإرجاع لا يُعدّ تحميلًا زائدًا
  للطرق.
- يمكن تحميل الطرق تحميلًا زائدًا في الصنف نفسه أو في صنف فرعي.

سنستكشف في هذا المفهوم أمثلة متنوعة وفروقًا دقيقة تخص التحميل الزائد للطرق في Java.
