# مقدمة

تستخدم [concept:csharp/resource-cleanup]() الواجهة `IDispose` للإشارة إلى أن مورد كائن ما أو حالة برنامج أخرى كان لا بد من تحريرها أو إعادة ضبطها عندما لم يعد الكائن مطلوبًا (وإلى أن الاعتماد على جامع القمامة لن يحقق ذلك أو يوفر مستوى التحكم المطلوب)، وأن طريقة `IDisposable.Dispose()` كانت المكان الطبيعي لمثل عمليات التنظيف هذه.

ثمة بنية أخرى، وهي كتلة `using`، تتيح من منظور المستدعي تجميع كل إدارة دورة حياة الموارد في عبارة واحدة.

```csharp
using (var file = new File("my_secrets"))
{
    file.WriteSecret("xxxxxxx");
}
```

في المثال أعلاه، ستُحرَّر موارد نظام الملفات المرتبطة بـ `file` وتُعاد إلى نظام التشغيل عند الخروج من كتلة `using`.

ولكي يعمل هذا النمط، يجب أن يكون المتغير في عبارة `using` من نوع مرجعي يُنفّذ الواجهة `IDisposable`، وأن يحرّر الموارد ويعيد ضبط حالة البرنامج في طريقة `Dispose()`.

يقدّم C# 8 تحسينًا على هذا النمط. إذ يمكن وضع عبارة `using` في بداية كتلة.

```csharp
using var drawingResource = some_provided_or_new_object;
try
{
    drawingResource.DrawSomething();
}
catch (Exception)
{
    throw;
}
```

قد يتعرف مطورو Java على هذا باعتباره نظيرًا لآلية _الإدارة التلقائية للموارد_ التي قُدّمت في Java 7.
