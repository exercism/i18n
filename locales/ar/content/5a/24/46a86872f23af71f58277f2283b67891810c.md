# مقدمة إلى المستندات المضمَّنة

في نصوص Bash البرمجية، يعيد «المستند المضمَّن» (أو «هيردوك») توجيه عدة أسطر من الدخل إلى أمر أو برنامج، كما لو كنت تكتبها مباشرة في الطرفية.
وهي أداة قوية لتضمين نص من عدة أسطر داخل نصوصك البرمجية دون الحاجة إلى ملفات خارجية أو معالجة معقّدة للسلاسل النصية.

## الخصائص الرئيسية والصياغة

1. المحدِّد: يبدأ المستند المضمَّن بالعامل `<<` متبوعًا بكلمة محدِّدة (يُطلق عليها غالبًا «العلامة» أو «المُنهي»).
   ويمكن أن تكون هذه الكلمة أي كلمة تختارها، لكن من الشائع استخدام شيء مثل `EOF` أو `END` أو `TEXT` للوضوح.
   ولجعل الكود أكثر قابلية للقراءة، يمكنك استخدام كلمة وصفية كمحدِّد، مثل `END_INSTALLATION_INSTRUCTIONS`.

1. المحتوى: بعد `<< DELIMITER` في البداية، تكتب المحتوى الذي تريد إعادة توجيهه.
   ويمكن أن يكون عدة أسطر من النص أو الكود أو أي شيء آخر.

1. الإنهاء: ينتهي المستند المضمَّن عندما تظهر الكلمة المحدِّدة مرة أخرى في سطر وحده، دون أي فراغات في بدايته أو نهايته.

## الصياغة الأساسية

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## كيف يعمل

* يقرأ Bash كل الأسطر الواقعة بين `<< DELIMITER` في البداية و`DELIMITER` في النهاية.
* يربط Bash هذا المحتوى بالدخل القياسي للأمر.
* يعالج الأمر هذا الدخل كما لو كان قادمًا من لوحة المفاتيح.

### المثال 1: إخراج نص بسيط

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

الإخراج:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

في هذا المثال:

* `cat` هو الأمر.
* يبدأ `<< EOF` المستند المضمَّن ويكون `EOF` هو المحدِّد.
* الأسطر الثلاثة من النص هي المحتوى.
* `EOF` في سطر وحده ينهي المستند المضمَّن.
* ثم يُخرج `cat` المحتوى الذي استقبله.

### المثال 2: الاستخدام مع wc (عدّ الكلمات)

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

الإخراج:

```plaintext
3
```

هنا، يحسب `wc -l` عدد الأسطر.
ويوفّر المستند المضمَّن الأسطر الثلاثة كدخل.

### المثال 3: تمرير بيانات إلى نص برمجي

النص البرمجي:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

استدعِ النص البرمجي من موجّه Bash تفاعلي باستخدام مستند مضمَّن:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

الإخراج:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## تنويعات وميزات متقدمة

### محتوى حرفي

ينفّذ Bash توسيع المتغيرات واستبدال الأوامر والتوسيع الحسابي داخل المستند المضمَّن.
وبهذا المعنى، تعمل المستندات المضمَّنة مثل السلاسل النصية المحاطة بعلامات اقتباس مزدوجة.

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

الإخراج:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

عندما يكون المحدِّد محاطًا بعلامات اقتباس (بعلامات فردية أو مزدوجة)، تُمنع هذه التوسيعات.
ويُؤخذ المحتوى كما هو حرفيًا.
وهذا شبيه بالسلاسل النصية المحاطة بعلامات اقتباس فردية.

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

الإخراج:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### إزالة علامات الجدولة البادئة

إذا استخدمت `<<-` (مع شرطة لاحقة) بدلًا من `<<`، فسيُزيل Bash أي _علامات جدولة_ بادئة من كل سطر من أسطر المستند المضمَّن.
وهذا مفيد لإزاحة محتوى المستند المضمَّن داخل نصك البرمجي دون التأثير على الإخراج.

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

ويُطبع الإخراج بعد إزالة كل علامات الجدولة البادئة:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

1. من الصعب تمييز الفرق بين المسافات وعلامات الجدولة.

## متى تستخدم المستندات المضمَّنة

* دخل متعدد الأسطر: عندما تحتاج إلى تمرير عدة أسطر نصية إلى أمر.
* ملفات الإعدادات: تضمين مقاطع إعداد صغيرة داخل نص برمجي.
* توليد الكود: إنشاء الكود في أثناء التنفيذ داخل نص برمجي.
* محاكاة التفاعل: محاكاة دخل المستخدم للبرامج التفاعلية.
* تجنّب الملفات الخارجية: عندما تريد تفادي إنشاء ملفات مؤقتة.

ومن الاستخدامات النموذجية توفير نص مساعدة:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## عيوب محتملة

* قد تجعل المستندات المضمَّنة الكبيرة الكود أصعب في القراءة.
  وقد يكون من الأفضل أن تنشر نصك البرمجي مع توثيقه في ملفات منفصلة.
* قد تقطع المستندات المضمَّنة تسلسل الكود.
  فقد تكون في قسم شديد التداخل من الكود حين تريد تمرير نص ما إلى برنامج.
  وقد تبدو إزاحة المستند المضمَّن غريبة مقارنة بالكود المحيط.

## النصوص المضمَّنة

مثل المستندات المضمَّنة، تُوفّر _النصوص المضمَّنة_ (أو «هيرسترنغ») دخلًا إلى أمر.
لكن بينما تُقدَّم المستندات المضمَّنة ككتلة نصية، تُقدَّم النصوص المضمَّنة كسلسلة نصية واحدة.
وتستخدم النصوص المضمَّنة الصياغة `<<< "text"`.

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

الإخراج:

```plaintext
UPPER CASE THIS STRING
```

وخلافًا للمستندات المضمَّنة، لا حاجة إلى محدِّد نهاية.

### لماذا نستخدم النصوص المضمَّنة؟

يمكن استخدام خط الأنابيب بدلًا من النص المضمَّن:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

فلماذا نستخدم النص المضمَّن؟

تأمّل الحالة التي تحصل فيها على السلسلة النصية كإخراج من عملية حسابية طويلة، وتريد تمرير النتيجة إلى أمرين منفصلين.
فباستخدام خطوط الأنابيب، عليك تنفيذ العملية الحسابية مرتين:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

والنهج الأكثر كفاءة هو التقاط إخراج العملية الحسابية (باستخدام استبدال الأوامر)، ثم استخدام النصوص المضمَّنة لتوفير الدخل للأمرين التاليين:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

وهذا تطبيق واقعي على ذلك المثال:

* التقط استجابة JSON لطلب REST API (متعدد الصفحات)،
* ثم مرّر بيانات JSON إلى برنامج jq لتحليل النتائج وإخراجها إلى ملف،
* ثم مرّر بيانات JSON إلى برنامج jq آخر لتحديد عنوان URL للطلب التالي.

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

لاحظ موضع إعادة توجيه الإخراج.
سيُلحق كل إخراج حلقة `while` بالملف `data.csv`.

## المستندات والنصوص المضمَّنة كإعادة توجيه

ولأنها مجرد أشكال من إعادة التوجيه، يمكن دمجها مع عمليات إعادة توجيه أخرى:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## الخلاصة

المستندات المضمَّنة (أو «هيردوك») طريقة مرنة ومريحة لإدارة الدخل متعدد الأسطر في نصوص Bash البرمجية.
فهي تبسّط عملية تضمين النص والبيانات مباشرة داخل نصوصك البرمجية، وتجعلها أكثر اكتفاءً بذاتها وأسهل في القراءة.

والنصوص المضمَّنة (أو «هيرسترنغ») شبيهة بالمستندات المضمَّنة، لكنها تقدّم صياغة أبسط وأكثر ديناميكية.
