# أساسيات Unison

## الحدود والدوال

الحدود والدوال هما الوحدتان الأساسيتان في كتابة برنامج بـ Unison.

«الحدّ» هو ما نسميه قيمة ثابتة. ويُعرَّف بالصيغة `name = expression`، ويمكن أن يسبقه توقيع نوع بالشكل `name : MyType`. تدعم Unison استنتاج الأنواع، لذا قد ترى توقيع النوع محذوفًا في التعريفات البسيطة.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

تبدو دوال Unison بالشكل `myFunctionName argument1 argument2 = myImplementation`؛ فهي تبدأ باسم الدالة متبوعًا بمعاملات تفصل بينها مسافات.

```
getMax a b = Nat.max a b
```

ويمكن أن تتضمن الدوال توقيع نوع اختياريًا. النوع الأخير على اليمين هو دائمًا نوع الإرجاع النهائي للدالة، ويفصل سهم الدالة `->` بين كل معامل وآخر.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

لاستدعاء دالة، استخدم اسمها متبوعًا بوسائطها مفصولة بمسافات فقط.

```
maximum = getMax 1 10
```

عند استدعاء دالة، ستحاول Unison اعتبار ما يأتي مباشرة على يمينها وسيطًا لها، وهذا قد لا يُنتج دائمًا ترتيب تقييم الدوال المطلوب.

لنفترض أننا نريد الحصول على القيمة `1` من التعبير التالي

```
shouldBe1 = getMax 1 10 - 10
```

كما هو مكتوب، يُقيَّم `shouldBe1` إلى `0` لأن ترتيب تطبيق الدوال المفهوم ضمنيًا هو `getMax 1 10`، أي `10`، ثم `10 - 10`، أي `0`.

يمكنك استخدام الأقواس لإعادة تجميع التعبير بالترتيب المطلوب للعمليات.

```
shouldBe1 = getMax 1 (10 - 10)
```

## الدوال متعددة الأسطر

تستخدم دوال Unison متعددة الأسطر الإزاحة أو كتل `let` لتحديد حدود الكود، أي «النطاق المعجمي».

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

كل ما هو على مستوى الإزاحة نفسه يتشارك النطاق نفسه، ولهذا يمكننا الإشارة إلى المتغير `newBeginning` في السطر الأخير.

## فضاءات الأسماء وجمل `use`

فضاءات الأسماء هي طريقتنا لتجميع دوال Unison وتنظيمها. يمكنك التفكير فيها كأنها أشبه بـ«المجلدات». فهي توفّر البنية والتجميع المنطقي.

ويمكنك إدخال الدوال الموجودة في فضاء أسماء إلى النطاق بجملة `use`.

لنفترض أنك تكتب دالة تستفيد من قيم `List` في Unison. أنت تعلم أنك ستحتاج دوالًا مثل `List.map` و`List.flatMap`، حيث `List` هو فضاء الأسماء و`map` و`flatMap` دالتان. ولتفادي تكرار نفسك، قد تختار إدخال كل شيء من فضاء الأسماء `List` إلى النطاق المعجمي داخل دالتك هكذا:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

سطر `use List` يزيل الالتباس في الإشارات إلى `map` و`flatMap`. يمكنك قراءة المزيد عن [جمل `use` من هنا][use-statements].

## المكتبة القياسية في Unison

تُسمّى المكتبة القياسية في Unison `base`. وإذا كنت قد اتبعت دليل البداية السريعة وأنشأت قاعدة كود محليًا، فيفترض أن المكتبة القياسية نُزّلت تلقائيًا. ويمكنك تصفّح توثيق المكتبة القياسية على الإنترنت في [Unison Share][unison-share-base].

## التعليقات والقيم التوثيقية

التعليقات في Unison ميزة غير مألوفة بعض الشيء. فعند كتابة كود Unison، يمكنك إنشاء نص في ملفك ذي الامتداد `.u` لا يُفسَّر، بالصيغة التالية:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_ومع ذلك_، لأن كود Unison يُحفظ كتجزئة لشجرة تركيبه المجرّد، لا كملفات نصية على نظام الملفات، فإن التعليقات التي هي «زينة» نصية لدالة أو حدّ معيّن في الملف لا يمكن فعليًا حفظها وإعادة عرضها للمشاركة. وإذا أردت إضافة معلومة إلى حدّك في Unison بطريقة تُخزَّن ليقرأها الآخرون ويفهموها، فيمكنك استخدام قيمة توثيقية.

التوثيق قيمة من الدرجة الأولى في لغة Unison. وهذا يعني أنه يمكن إسناد عنصر `Doc` إلى قيمة، أو تمريره كقيمة إلى دالة، أو إرجاعه كقيمة لدالة. وتُفتح عناصر القيم التوثيقية وتُغلق بقوسين معقوفين مزدوجين. وإليك كيف قد نستخدم عنصر `Doc` كتعليق.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
