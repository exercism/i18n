# Sobre

Em Gleam, uma expressão `case` pode ser usada para executar código de forma condicional. Com uma expressão case, um valor pode ser testado em relação a um ou mais _padrões_. Um exemplo desse tipo de padrão é o _padrão literal_, que compara um valor com um valor literal (por exemplo, `1` ou `"hello"`).

As expressões case escrevem-se com a palavra-chave `case`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    1 -> "One"
  }
}
```

Embora isto possa parecer-se com instruções `switch` de outras linguagens, a correspondência de padrões começa a brilhar quando também se usam outros padrões. Um desses padrões é o _padrão variável_, que permite atribuir um valor a uma variável. Neste exemplo, à variável `i` será atribuído o valor de `number` se este não for `0`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i -> "Non zero"
  }
}
```

Em alguns casos, podes querer acrescentar uma condição adicional a um padrão. Isto é conhecido como uma _guarda_ (cláusula), que pode ser acrescentada com a palavra-chave `if`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
  }
}
```

Por razões de desempenho, nas guardas só são permitidos operadores matemáticos e Boolean básicos; não podes usar outras funções nas guardas.

No exemplo acima, nem todos os valores de entrada possíveis terão um padrão correspondente. O compilador deteta isto e dá um erro. Isto é conhecido como _verificação de exaustividade_. Para resolver o aviso, tens de tratar todos os casos. Para isso, podes usar o _padrão de descarte_, que é um padrão que corresponde a qualquer valor:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
    _ -> "Positive number"
  }
}

// No compiler error
```

As expressões case testam um valor em relação a cada padrão, de cima para baixo, até encontrar um padrão correspondente e executar a lógica associada a esse padrão. A ordem dos padrões é importante!
