# Apêndice às instruções

O conjunto de testes só gera cerca de 100 nomes por predefinição.
Há cerca de 700 mil nomes válidos, por isso só tens uma pequena probabilidade de apanhar colisões.
Para além do conjunto de testes, pondera testar a tua solução para colisões de outra forma.

Este exercício continua a nossa exploração do
[sistema de tipos](https://docs.julialang.org/en/v1/manual/types/) da Julia,
desta vez com tipos mutáveis,
e dá-nos a conhecer a
[geração de números aleatórios](https://docs.julialang.org/en/v1/stdlib/Random/).

Vamos imaginar que repor o robô nas definições de fábrica é como uma cirurgia: faz alterações no sujeito, mas não o substitui.
Também podíamos ter modelado o problema de forma a que repor um robô criasse um robô novo, mas nem todos os problemas podem ser modelados apenas com estruturas de dados imutáveis (até as linguagens puramente funcionais lidam com mutabilidade dentro dos seus ambientes de execução!).

Em Julia, as funções que alteram os seus argumentos têm, por convenção, o sufixo `!`.
Por isso, o nosso método para fazer isto vai chamar-se `reset!`.

Isto é apenas uma convenção, mas quase todo o código Julia publicado segue-a, e podes vir a concordar que é bastante útil!

## Sugestões

Vais precisar de definir
um método para gerar nomes únicos,
uma estrutura para descrever robôs,
um método para repor um robô,
e um método para obter o nome de um robô.

Pode ser-te útil conceber primeiro o teu programa apenas para gerar um nome aleatório para um robô (sem te preocupares com colisões) e, mais tarde, pensar e planear um esquema que evite emitir nomes duplicados.
Ao conceberes o teu programa, pensa com cuidado em como o tempo de execução da geração de nomes muda à medida que os nomes se esgotam. Que garantias queres oferecer a quem chama?
