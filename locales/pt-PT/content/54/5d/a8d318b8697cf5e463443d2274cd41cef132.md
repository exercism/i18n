# Introdução

Um número de **vírgula flutuante** é um número que pode ter uma parte fracionária, como `-1.23` ou `3.1415`.

Para representar um número desses como uma sequência de bytes, o x86-64 usa a norma **IEEE-754**.
Os dois formatos mais comuns nesta norma são os números de vírgula flutuante de precisão simples e de precisão dupla.
O x86-64 suporta ambos.

Um número de vírgula flutuante de precisão simples tem 32 bits de largura, enquanto um de precisão dupla tem 64 bits.

## Registos XMM

No x86-64 há 16 registos dedicados à aritmética de vírgula flutuante, chamados `xmm0` a `xmm15`.

Esses registos têm pelo menos 128 bits de largura, mas os processadores recentes aumentam isso para 256 ou 512 bits.
No entanto, na prática, a maioria dos números de vírgula flutuante usa apenas os 32 ou 64 bits mais baixos, consoante a precisão pretendida.

## Conversão entre números

Há uma família de instruções para converter entre formatos de números: `cvtxx2yy`.

Tanto `xx` como `yy` não são literais, mas sim marcadores de posição:

- `xx` é um marcador de posição para o tipo do operando de origem.
- `yy` é um marcador de posição para o tipo do operando de destino.

Este marcador de posição pode assumir várias formas, entre elas:

| marcador de posição | significado           |
| ----------- | --------------------- |
| `si`        | inteiro com sinal     |
| `ss`        | vírgula flutuante de 32 bits |
| `sd`        | vírgula flutuante de 64 bits |

Por exemplo:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

Repara que é possível converter um inteiro de 32 bits num número de vírgula flutuante de 64 bits, ou um inteiro de 64 bits num número de vírgula flutuante de 32 bits.
Da mesma forma, também é possível converter um número de vírgula flutuante de 32 bits num inteiro de 64 bits, ou um número de vírgula flutuante de 64 bits num inteiro de 32 bits.
Por outras palavras, o tamanho dos dois operandos numa `cvtxx2yy` _não tem de ser o mesmo_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

Quando o número de vírgula flutuante não pode ser expresso exatamente como um inteiro, a `cvtxx2si` arredonda o número de acordo com o controlo de arredondamento de um registo especial chamado `mxcsr`.
Isso pode ser um arredondamento para o mais próximo, para baixo, para cima ou um truncamento.
Não há um comportamento predefinido garantido à entrada de uma função.

Repara que um resultado exato não é arredondado e, por isso, não é afetado pelo controlo de arredondamento.
Por exemplo, `42.0` seria _sempre_ convertido em `42`.

Há uma família de instruções semelhante, com o formato `cvttxx2si` (com um `t` extra), que trunca sempre o resultado.

## Arredondamento

A família de instruções `roundxx` converte um número de vírgula flutuante do operando de origem num número de vírgula flutuante arredondado, guardado no operando de destino.

Aqui, `xx` é um marcador de posição para o tipo dos operandos, como habitualmente: `ss` para vírgula flutuante de precisão simples e `sd` para precisão dupla.

Estas instruções recebem um número constante como terceiro operando.
Este número indica o modo de arredondamento:

| Número | Modo         |
| :----- | :----------- |
| 0      | Mais próximo |
| 1      | Para baixo (floor) |
| 2      | Para cima (ceil) |
| 3      | Truncar      |

Por exemplo:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

Como estas instruções produzem um resultado exato, podem ser usadas como preparação para uma `cvtxx2si`.

## Instruções aritméticas

Muitas operações com números de vírgula flutuante usam instruções com um nome semelhante ao do seu equivalente para inteiros, mas com o marcador de posição necessário (`ss` ou `sd`) acrescentado no fim.
Estas instruções têm dois operandos, com a semântica habitual, mesmo as que fazem multiplicação ou divisão:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## Movimento

As instruções para mover de um registo XMM para outro são `movss` ou `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

**Não** é possível mover um valor imediato (um inteiro constante com sinal) diretamente para um registo xmm.
Este número tem primeiro de ser movido para um registo de uso geral e depois convertido com `cvtsi2xx`:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## Comparações

Há dois grupos de instruções para comparar dois números de vírgula flutuante.
Têm a forma `comixx` e `ucomixx`, em que `xx` é `ss` ou `sd`.
Ambas definem flags no `rflags`, como habitualmente, seguindo a mesma semântica que o `cmp`.

A diferença entre elas é que a `ucomixx` define a `parity flag (PF)` se um dos dois números de vírgula flutuante tiver um valor `NaN`, enquanto a `comixx` gera uma exceção nesse caso.

A comparação entre valores de vírgula flutuante é _sem sinal_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## Convenção de chamada

No ABI System V, os primeiros oito argumentos de vírgula flutuante são passados às funções por ordem, de `xmm0` a `xmm7`.
Os valores de vírgula flutuante são devolvidos pelas funções em `xmm0` e, se necessário, em `xmm1`.

Todos os registos `xmm` estão livres para serem usados; nenhum deles é reservado para quem chama.

## Memória

Os valores de vírgula flutuante podem ser definidos na memória seguindo a mesma semântica que os inteiros do mesmo tamanho.
O NASM (The Netwide Assembler - o assembler usado neste percurso) também permite declarar valores de vírgula flutuante em notação científica.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```
