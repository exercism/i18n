# Sobre carateres

Este é potencialmente um tema _enorme_!
É possível escrever um livro longo sobre isto, e várias pessoas já o fizeram (procura "unicode book" na Amazon para ver alguns exemplos).

## Uma história muito breve

Lidar com carateres nos computadores era muito mais simples nas décadas anteriores, quando os programadores assumiam que o inglês era a única língua importante.
Portanto: 26 letras, maiúsculas e minúsculas, 10 algarismos, vários sinais de pontuação, mais um código (0x07) para tocar uma campainha, e tudo cabia em 7 bits: o conjunto de carateres [ASCII][wiki-ascii].

Naturalmente, as pessoas começaram a perguntar o que se passava com à, ä e Ł, depois outras pessoas começaram a perguntar sobre ऄ, ஹ e ญ, e os jovens queriam emojis 😱.
O que fazer?

Para encurtar a história, muitas pessoas inteligentes e pacientes tiveram de fazer parte de comités durante anos, a definir os detalhes do conjunto de carateres [Unicode][web-unicode] e de codificações como [UTF-8][wiki-utf-8], e muito software precisou de uma reescrita _muito_ complicada.
Além disso, foram introduzidos muitos bugs novos.

Para evitar que _tudo_ se estragasse, o design do Unicode/UTF-8 garante que os primeiros 127 códigos são idênticos ao ASCII _(até a campainha)_.

## Carateres em Kotlin

As linguagens criadas depois de cerca de 2005 têm a enorme vantagem de já existir um padrão Unicode razoavelmente estável.

O Kotlin (lançado pela primeira vez em 2011) pôde assumir que os utilizadores usariam uma variedade de línguas (humanas) e que precisariam do Unicode para as expressar.

~~~~exercism/advanced
Os [carateres][ref-char] em Kotlin são [`codepoints`][wiki-codepoint] de 16 bits (UTF-16), tal como um `char` da JVM.
Isto é suficiente para expressar a maioria dos alfabetos escritos, mas não toda a variedade de emojis.

O padrão Unicode completo usa até seis bytes (48 bits) por caráter (chamado [`grapheme`][wiki-grapheme]).

As `Strings` do Kotlin suportam este padrão completo ao usar vários codepoints por caráter, quando necessário.
Por exemplo, 😱 seria `\uD83D` e `\uDE31`.

Infelizmente, o Java não tem suporte de graphemes integrado e, por compatibilidade, o Kotlin também não.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


Os literais de caráter escrevem-se entre aspas simples e são distintos das strings escritas entre aspas duplas.
Isto é provavelmente óbvio para quem vem do mundo C/C++, mas pode confundir os programadores de Python e JavaScript.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

Converter entre `Char` e `Int` é simples:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

O compilador permite _algumas_ formas de aritmética de inteiros com `Char`s:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## Algumas funções para `Char`

Como sempre, há [demasiadas funções][ref-char-lib] para discutir aqui, por isso esta é apenas uma seleção.

- Para os alfabetos adequados, muda a caixa com [`uppercase()`][ref-uppercase] e [`lowercase()`][ref-lowercase].
- Testa a caixa com [`isUpperCase()`][ref-isuppercase] e [`isLowerCase()`][ref-islowercase].
- Testa o tipo de caráter com:
  - [`isLetter()`][ref-isletter], abrange muitos alfabetos (as categorias Lu, Ll, Lt, Lm e Lo do Unicode)
  - [`isDigit()`][ref-isdigit], no intervalo 0..9 (a categoria Nd do Unicode)
  - `isLetterOrDigit()`, combina as duas anteriores
  - [`isWhitespace()`][ref-iswhitespace], qualquer caráter de espaço em branco (as categorias Cc, Zp, Zl e Zs do Unicode)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

Além disso, as [expressões regulares][ref-regex] (que serão o tema de um Conceito mais adiante) permitem pesquisas e manipulações poderosas.

## Interconversões entre listas de `Char` e strings

Para converter uma `String` numa `List` de `Char`s, podemos usar `toList()`.

Para converter uma `List` de `Char`s numa `String`, existe a função [`joinToString()`][ref-jointostring], que recebe um separador (muitas vezes a string vazia) como argumento.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

Repara que `joinToString()` opera sobre uma List ou um Array.
Para _converter_ um único `Char` numa string de um caráter, usa `toString()`.

```kotlin
'a'.toString() // => "a"
```

Para verificar se um caráter está presente numa `String`, numa lista de `Char` ou num array, temos o `in`, que corresponde à função [`contains()`][ref-contains].

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
