# Iteradores personalizados

Tens usado iteradores desde `bird-survey`. Agora vais escrever um.

## yield

Um iterador parece uma rotina com duas diferenças: o nome termina em `!` e entrega valores com `yield` em vez de `return`.

```sather
   markers!(count : INT) : INT is
      loop
         yield 100 * 1.upto!(count);
      end;
   end;
```

O `yield` dá um valor ao ciclo que chamou o iterador e depois **espera**. Quando esse ciclo volta a passar, o iterador continua a partir do ponto imediatamente a seguir ao `yield`, com tudo exatamente como o deixou: as suas variáveis, o seu próprio ciclo, a sua posição.

É isto que um iterador é: uma rotina que pode fazer uma pausa a meio e ser retomada.

```sather
   loop
      #OUT + TRAIL::markers!(3) + " ";      -- 100 200 300
   end;
```

## Fim

Um iterador termina de uma de duas formas.

**Esgotar-se.** Quando o ciclo do próprio iterador termina, ou a rotina chega ao fim, acabou, e o ciclo que o chamou termina imediatamente.

**quit.** O `quit` termina-o ali mesmo, sem fazer `yield`.

```sather
   named!(names : ARRAY{STR}) : STR is
      loop
         name ::= names.elt!;
         if name = "" then quit; end;
         yield name;
      end;
   end;
```

Isto entrega nomes até encontrar um vazio, e para. O `quit` está para um iterador como o `return` está para uma rotina, só que não transporta nenhum valor: já não há nada para entregar.

## once

Um argumento marcado com `once` é calculado uma única vez, quando o ciclo começa, em vez de o ser a cada volta:

```sather
   markers!(once count : INT) : INT is
```

Usa-o para tudo o que não muda de volta para volta, ou seja, para a maioria dos argumentos. Os iteradores da própria biblioteca fazem-no: `upto!(once i : SAME)`.

## Iteradores sem valor

Um iterador não tem de entregar nada. O `times!` é um deles:

```sather
   steps!(once count : INT) is
      loop
         ignored ::= 1.upto!(count);
         yield;
      end;
   end;
```

Um `yield` sozinho não entrega nada e limita-se a deixar o ciclo dar mais uma volta.

## Onde fica a posição

Cada *ponto do programa* que chama um iterador mantém a sua própria posição, e é por isso que chamar o mesmo iterador duas vezes no corpo de um ciclo o percorre duas vezes. Agora já percebes porquê: as duas chamadas são duas rotinas distintas, ambas em pausa.
