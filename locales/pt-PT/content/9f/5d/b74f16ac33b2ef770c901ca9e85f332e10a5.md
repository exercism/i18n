# Construtores de strings

`STR` é imutável; `FSTR` não é. Usa `STR` para texto que está terminado e
`FSTR` para texto que ainda está a ser montado.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## Atribui sempre o resultado à variável

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR` cresce por **duplicação amortizada**: quando fica sem espaço, arranja
um novo array maior, com o dobro do tamanho, e copia para lá. Por isso, o
resultado é habitualmente o mesmo objeto e, por vezes, um objeto diferente.
Escrever `b := b + x` sempre é correto nos dois casos e é a única forma que
vale a pena aprender.

A duplicação é o que faz com que o trabalho total seja proporcional ao
comprimento e não ao seu quadrado: as cópias tornam-se mais raras à mesma
velocidade a que se tornam mais caras.

## Porque não usar apenas `+` em STR?

Concatenar um número fixo e pequeno de partes com `+` é claro e não há
problema:

```sather
   return piece + " by " + composer;
```

O problema surge apenas num ciclo, onde o número de concatenações não é
conhecido quando o código é escrito. Uma regra prática: se o `+` estiver
dentro de um `loop`, recorre a `FSTR`.

## Rotinas úteis

| Chamada | Faz |
| --- | --- |
| `b + x` | acrescenta; `x` pode ser `STR`, `CHAR`, `INT`, `BOOL` … |
| `b.size` | quantos carateres até agora |
| `b.str` | uma `STR` finalizada |
| `b.clear` | esvazia-o, mantendo o espaço |

## Sequências de escape

| Escrito | É |
| --- | --- |
| `"\n"` | uma nova linha |
| `"\t"` | um tabulador |
| `"\""` | uma aspa dupla |
| `"\\"` | uma barra invertida |
