# Números de vírgula flutuante

`FLTD` guarda um número que pode ter uma parte decimal. Um literal precisa de uma parte decimal e de um `d`:

```sather
   440.0d
   0.5d
   -2.25d
```

`FLT` é a mesma ideia com metade da precisão. Neste percurso usamos `FLTD` em todo o lado; não há razão para recorreres a `FLT`, a menos que a memória esteja escassa.

## Aritmética

| Operador | Significado |
| --- | --- |
| `+` `-` `*` | como para `INT` |
| `/` | divisão, mantendo a parte decimal |

Não existe `%` para `FLTD`.

Ambos os operandos têm de ser `FLTD`. Misturar um `INT` é um erro de compilação, não uma conversão silenciosa, o que é uma vantagem: o único sítio onde isto morde é exatamente aquele onde as pessoas se enganam.

## Conversão

```sather
   7.fltd            -- 7.0, an INT made into an FLTD
   7.5d.int          -- 7, the fraction thrown away
   7.5d.round        -- 8, to the nearest whole number
   7.5d.floor        -- 7.0, down to a whole number
   7.5d.ceiling      -- 8.0, up to a whole number
```

Converte antes de dividir, nunca depois: `n.fltd / 2.0d` mantém a metade, `(n / 2).fltd` já a perdeu.

## Rotinas úteis

```sather
   (-2.5d).abs       -- 2.5
   2.0d.sqrt         -- 1.41421
   (2.0d).max(3.0d)  -- 3.0
```

## A vírgula flutuante é uma aproximação

Um `FLTD` guarda uma aproximação muito próxima, não o valor exato. A maioria das frações decimais não pode ser guardada exatamente, tal como um terço não pode ser escrito exatamente em decimal. Por isso:

```sather
0.1d + 0.2d          -- very nearly 0.3, but not exactly
```

Duas consequências que vale a pena ter em conta:

**Não compares com `=`.** Dois cálculos que deviam dar o mesmo resultado diferem muitas vezes nos últimos algarismos. Pergunta antes se estão próximos:

```sather
   (a - b).abs < 0.0001d
```

**Somar muitos valores pequenos perde precisão.** Cada soma arredonda um pouco, e os erros acumulam-se.

Quando os valores têm de ser exatos, em particular o dinheiro, conta antes em unidades inteiras com `INT` (cêntimos em vez de euros).

## Impressão

`.str` mostra cerca de seis algarismos significativos, o que fica aquém da precisão que é realmente guardada:

```sather
   #OUT + (1.0d / 3.0d).str;      -- 0.333333
```
