# Sobre

Para compreender o [`Box`][box], é útil perceber o que são a [pilha e o heap][stack and heap].

A pilha é uma área de memória que funciona como um buffer do tipo último a entrar, primeiro a sair (LIFO). É muito rápido colocar dados na pilha e também é rápido retirá-los de lá.
Os dados podem incluir variáveis ou endereços de funções, mas têm de ter um tamanho fixo conhecido em tempo de compilação.

Se os dados tiverem um tamanho desconhecido em tempo de compilação, ou tiverem um tamanho que possa mudar, então têm de ser alocados no heap. O processo de alocação tem de encontrar
espaço no heap suficientemente grande para guardar os dados, escrever os dados no heap e colocar na pilha o endereço de memória desses dados, o que demora
significativamente mais tempo do que simplesmente colocar dados na pilha. Obter dados do heap é um pouco mais lento, porque temos de passar pelo endereço na
pilha e segui-lo até à localização dos dados no heap.

O `Box` é um ponteiro inteligente que aloca dados no heap. O endereço está na pilha e aponta para os dados no heap. Uma [razão][reasons] para usar o `Box`
é colocar dados no heap quando tens um tipo cujo tamanho não pode ser conhecido em tempo de compilação e queres usar um valor desse tipo num contexto que exige
um tamanho exato. Uma aplicação prática disso é quando tens várias structs que queres tratar da mesma forma através de um trait que todas implementam, como
no exemplo abaixo.

Digamos que temos duas structs. Cada struct representa algo que pode ser irritante. Podemos fazer com que cada struct implemente um trait Annoyance, assim

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

Agora digamos que queremos uma função que nos devolva uma Annoyance com base na hora do dia que lhe é passada. Podemos começar por tentar isto, e descobrimos que não compila

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

Com toda a sua simpatia, o compilador diz-nos exatamente o que fazer: devolver um objeto trait dentro de um `Box`. Se não sabes o que é um objeto trait,
uma forma simples de o descrever é como uma maneira de devolver um objeto específico, através de [despacho dinâmico][dynamic dispatch], a partir de uma função que pode devolver qualquer objeto
que implemente um determinado trait. Como precisamos de despacho dinâmico, podemos tentar colocar apenas um `dyn` antes do nome do trait e ver se resulta.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

Um dos erros é que o tamanho de `dyn Annoyance` não pode ser conhecido em tempo de compilação. Isto acontece porque a função `annoy_me` não sabe, antecipadamente,
que objeto trait específico vai devolver quando é chamada. Structs que implementam Annoyance podem ter campos diferentes e tamanhos diferentes. E recordamos que
uma das utilizações do `Box` é precisamente para um tipo cujo tamanho não pode ser conhecido em tempo de compilação. Por isso, agora tentamos usar um valor de retorno dentro de um `Box`, e colocamos num `Box` os valores devolvidos
pela expressão match, assim

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

A assinatura de `Box` é `Box<T>`, em que `T` representa o tipo específico a colocar dentro do `Box`, que é escrito entre os sinais de menor e maior, como em `Box<dyn Annoyance>` acima.

Podemos consumir o objeto trait dentro do `Box` assim

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

o que produz a saída

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

Como `my_annoyance` é do tipo `Box<dyn Annoyance>`, tem de ser desreferenciado do `Box` com o operador de desreferenciação `*`. É depois referenciado como um
`dyn Annoyance`, para que a função `be_annoying` o possa emprestar.

Outra forma de o implementar seria remover o requisito de que o parâmetro tenha tamanho definido. Nesse caso, a compilação criaria uma função separada
para cada variante de Annoyance, para que pudesse ser despachada estaticamente (um processo chamado [monomorfização][monomorphization]), assim

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

Ainda outra forma de o implementar seria a função `be_annoying` aceitar um `Box<dyn Annoyance>` e usar [coerção de desreferência][deref coercion] para evitar
ter de desreferenciar o `Box` manualmente. Isto transferiria a propriedade do objeto trait Annoyance para a função `be_annoying`. Sairia do
âmbito no fim da função e deixaria de estar disponível.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
