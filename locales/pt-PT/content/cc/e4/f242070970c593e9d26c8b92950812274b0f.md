# Sobre

O exercício de programação ilustra várias propriedades dos parâmetros:

- Os parâmetros [passados][passing-parameters] sem um modificador (como `out` ou `ref`) são passados por valor. Ou seja, o parâmetro pode ser usado e receber atribuições no método chamado, mas quaisquer alterações não terão efeito sobre quem faz a chamada.
- Quando uma referência a um array ou a uma instância de uma classe é um parâmetro, o método chamado pode alterar os elementos ou os campos dessa instância, e essas alterações são visíveis para quem faz a chamada. Isto aplica-se independentemente de o modificador `ref` estar presente.
- Um parâmetro com o modificador [`out`][out-parameter] devolve um valor do método chamado a quem faz a chamada. O parâmetro pode ser passado ao método chamado sem estar inicializado e, em qualquer caso, é tratado dentro do método chamado como se, à entrada, não tivesse sido inicializado. A forma mais fácil de compreender o comportamento e as regras dos modificadores de parâmetros é através de exemplos (ver abaixo) e de mensagens do compilador.

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- Os parâmetros `out` têm de receber uma atribuição dentro do método chamado.

- Um parâmetro com o modificador [`ref`][ref-parameter] passa um valor para um método chamado. Quando o método regressa, quem faz a chamada encontra nesse parâmetro as atualizações feitas pelo método chamado.

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

-`ref` parâmetros têm de ser variáveis, pois o método chamado vai operar diretamente sobre o parâmetro tal como é visto por quem faz a chamada.

- Os modificadores `out` e `ref` são obrigatórios tanto na assinatura do método chamado como no local da chamada.
- Os parâmetros `out` podem ser declarados inline no local da chamada, por exemplo: `Foo(out int importantValue);`
- Se fizeres uma chamada a um método que tem parâmetros `out` mas não estiveres interessado no valor atribuído a um ou mais deles, podes usar a variável fictícia [discard][discard] `_`, como em: `Foo(out int _);`

Todas as regras relativas aos parâmetros `ref` e `out` são impostas pelo compilador.

Também existem parâmetros [`in`][in-parameter], mas são sobretudo uma otimização de desempenho e são abordados no exercício `structs`, onde são mais relevantes.

A documentação referida acima está resumida abaixo:

- [passing-parameters][passing-parameters]: explica como os valores podem ser passados como argumentos. Repara que o tema de structs e parâmetros é abordado no exercício `structs`.
- [ref-parameter][ref-parameter]: descreve como funcionam os parâmetros `ref`.
- [out-parameter][out-parameter]: descreve como funcionam os parâmetros `out`.

Ao estudares a documentação, repara que esta usa os seguintes termos:

- parâmetro / parâmetro formal: refere-se ao parâmetro tal como é visto pelo método chamado.
- argumento: refere-se ao parâmetro tal como é visto por quem faz a chamada.

[Pode dizer-se][so-tuples-vs-out] que grande parte do valor dos parâmetros `out` desapareceu com a introdução dos `tuples` no C# 7. O exercício `tuples` mostra `tuples` a serem usados para devolver vários valores.

Embora `ref` seja fácil de usar e não tenha penalizações de desempenho, vale a pena ver como os problemas que resolve são tratados numa determinada base de código antes de o usares em grande escala. Há alternativas, como passar por valor e usar o valor da instrução de retorno do método chamado. Mais uma vez, os `tuples` podem ter um papel aqui.

Vais ver na [documentação][ref-parameter] que `out` e `ref` não podem ser usados em certas situações, mas por agora podes ignorá-las. O compilador avisa-te quando essas situações surgirem.

Repara que os `optional parameters` e os `named arguments` são abordados no exercício `method-overloading`.

Os tópicos relacionados de [`ref local`][ref-local] e [`ref return`][ref-return] são abordados noutro sítio.

## Alocação na pilha

As regras relativas aos parâmetros e aos seus modificadores são suficientemente simples para que as possas aceitar tal como são e compreender ao seu nível de abstração. No entanto, se estiveres interessado nos mecanismos subjacentes e em por que razão estas palavras-chave podem fazer diferença no desempenho, pelo menos no caso dos `struct`s, podes começar por este [_artigo da Wikipédia_][calling-conventions], notando que o C# usa `stdcall` em x86/64.

O essencial é o seguinte: no caso dos parâmetros sem modificador, o **valor** de uma variável é copiado para a pilha do programa para ficar disponível para uma rotina chamada, ao passo que, nos parâmetros `ref`, `out` e `in`, é colocado na pilha do programa um ponteiro (**referência**) para a memória que contém o valor, e os valores são atribuídos à memória apontada pela referência.
