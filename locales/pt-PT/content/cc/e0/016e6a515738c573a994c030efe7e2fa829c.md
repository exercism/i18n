# Sobre

As `struct`s de C# estão intimamente relacionadas com as `class`es.
Têm estado e comportamento.
Podem ter os mesmos tipos de membros: construtores, métodos, campos, propriedades, etc.

Os campos e as propriedades podem ser tipos simples, `struct`s ou tipos de referência.
As `struct`s obedecem às mesmas regras de âmbito, de leitura/escrita e de níveis de acesso que as `class`es.

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

Uma das principais coisas a ter em conta é que, quando uma struct é atribuída a uma variável ou passada como parâmetro, os valores são copiados, pelo que as alterações à variável original não afetam a que foi copiada, e vice-versa.
Em resumo, as `struct`s são **tipos de valor**.

Este [artigo][class-or-struct] aborda as diferenças entre `struct`s e `class`es.
Vais ver no artigo que as `struct`s tendem a ser leves e [imutáveis][structs-immutable], embora esta orientação não seja imposta (por predefinição) pelo compilador nem pelo runtime.

Há algumas coisas com que te vais deparar (e sobre as quais o compilador te vai avisar):

1. Os membros de uma `struct` não podem ser inicializados na própria declaração.
2. Uma `struct` não pode ser herdada
3. Uma `struct` tem sempre um construtor predefinido, mesmo que seja fornecido um construtor não predefinido, e não podes fornecer um construtor sem parâmetros explícito.

Como consequência dos pontos 1 e 3 acima, não há forma de o programador de uma `struct` impedir que surjam instâncias inválidas.

## Structs comuns

Vais ver na documentação que existe uma relação estreita entre os tipos primitivos e as structs.
Vê [`Int32/int`][int32], por exemplo.
Um exemplo mais convencional de uma `struct` é o tipo [`TimeSpan`][time-span].

As instâncias de `TimeSpan` comportam-se de forma muito semelhante a números, com operadores de comparação como `>` e `<` e operadores aritméticos.
Podes implementar estes operadores nas tuas próprias `struct`s quando precisares deles.

Uma coisa a ter em conta sobre `TimeSpan` é que implementa várias interfaces, por exemplo `IComparable<TimeSpan>`.
Embora as `struct`s não possam derivar de outras `struct`s, podem implementar interfaces.

## Igualdade

Testar a igualdade de `struct`s pode ser, muitas vezes, muito mais simples do que no caso das `class`es, uma vez que, por predefinição, compara simplesmente os campos quanto à igualdade.
Não é preciso substituir `object.Equals()` (nem `GetHashCode()`).
Lembra-te de que, se estiveres a contar com `Object.GetHashCode()`, tens na mesma de garantir que os campos envolvidos na geração do código hash (ou seja, todos os campos) não mudam enquanto uma coleção com hash está a ser utilizada.
Na prática, isto significa que as structs usadas desta forma devem ser imutáveis.

Ao contrário do método `Equals()`, não existe uma implementação predefinida dos operadores de igualdade, `==` e `!=`.
Se a tua `struct` precisar deles, terás de os implementar.

Por outro lado, este [artigo][equality] descreve como o desempenho pode ser otimizado criando os teus próprios métodos `Equals()` e `GetHashCode()` personalizados, como se faz frequentemente com as `class`es.
A diferença, no caso deste exercício, foi de cerca de 20% numa comparação pouco rigorosa, mas esse valor pode pecar por baixo, porque todos os campos são do mesmo tipo (vê mais abaixo).

Há discussões na [web][equality-performance] sobre melhorias de velocidade, quando o método `Equals()` não é substituído, se todos os campos forem do mesmo tipo.
A diferença neste exercício, ao incluir campos de tipos diferentes, foi de cerca de 60%.
Isto não é mencionado na documentação da Microsoft, o que faz disto um detalhe de implementação não documentado, e deve ser aproveitado com ponderação.

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
