# Docker

Os nossos analisadores são publicados como imagens Docker.

Lê a [informação geral sobre Docker nas ferramentas](/docs/building/tooling/docker) para te familiarizares com o modo como funcionam.

## Integração

Quando executamos um analisador para analisar uma solução, corremos um comando Docker com este aspeto:

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-analyzer" \
        "${exercise_slug}" "/solution" "/output"
```

Como podes ver, passamos três argumentos à imagem Docker:

1. O slug do exercício
2. O caminho para o diretório da solução
3. O caminho para o diretório de saída

## Convenções

Todos os nossos analisadores seguem as seguintes convenções na sua implementação:

- O `Dockerfile` está no diretório raiz do repositório.
- O diretório de trabalho deve ser `/opt/analyzer`.
- O entrypoint é `/opt/analyzer/bin/run.sh`
- O script `/opt/analyzer/bin/run.sh` recebe 3 argumentos:
  1. O slug do exercício
  2. O caminho para o diretório da solução
  3. O caminho para o diretório de saída

Para mais informações, consulta [A Interface](/docs/building/tooling/analyzer/interface).

```exercism/note
Os novos repositórios de analisadores usam estas convenções por predefinição.
```
