# Dicas
O `Option` usa-se para indicar um cálculo que pode não ter um resultado útil
(por exemplo, por causa de um erro ou de dados inválidos).
Se não estás familiarizado com o `Option`, podes ler [este tutorial](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html).
O `Option` é uma chamada [mónada](https://en.wikipedia.org/wiki/Monad_(functional_programming)) que abrange um «aspeto computacional», neste caso a possível ausência de um valor.
O uso correto das mónadas pode resultar em código muito conciso, mas ainda assim elegante
e legível. O uso incorreto pode facilmente resultar no contrário.
Vê [este vídeo](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) para saberes mais.
## Armadilhas comuns que deves evitar
Há algumas regras básicas para o `Option`:
1. Se não precisas dele, não o uses. Em vez de
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
é melhor ter
```scala
def add1(x: Int): Int = x + 1
```
(há o `Option.map` para aplicar funções simples como estas,
por isso não precisas de as sobrecarregar com o `Option`).
2. Não faças «unwrap» se não precisares mesmo.
Muitas vezes há funções incorporadas para o que queres. Indícios de
«unwrap» prematuro são `isDefined/isEmpty` ou a correspondência de padrões. Em vez de
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
é melhor ter
```scala
x map (_ + 1) getOrElse 0
```
3. As mónadas podem ser usadas dentro de uma for-comprehension FTW.
Isto é aconselhável quando queres «compor» várias instâncias de `Option`. Em vez de
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
é melhor ter
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
