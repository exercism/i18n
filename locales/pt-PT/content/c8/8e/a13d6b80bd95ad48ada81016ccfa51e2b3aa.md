# Noções básicas

Um programa Sather é feito de **classes** que contêm **rotinas**.

```sather
class GREETER is

   hello : STR is
      return "Hello!";
   end;

end; -- class GREETER
```

## Classes

Uma classe tem o nome em maiúsculas, com underscores entre as palavras:
`GREETER`, `STAGE_DIRECTIONS`. O nome do ficheiro corresponde habitualmente a
esse nome, em minúsculas: `stage_directions.sa`.

Todas as rotinas vivem dentro de uma classe. Não há código fora de uma.

## Rotinas

Uma rotina que produz uma resposta declara o tipo de resposta depois de dois
pontos:

```sather
   hello : STR is
      return "Hello!";
   end;
```

`STR` é o tipo para texto. Uma rotina que não recebe argumentos escreve-se e
chama-se sem parênteses.

Uma rotina pode receber argumentos, escritos entre parênteses depois do nome:

```sather
   louder(word : STR) : STR is
      return word;
   end;
```

`return` devolve uma resposta e para a rotina logo de imediato, por isso
quaisquer linhas abaixo são ignoradas.

## Chamar

De fora da classe, indica o nome da classe, depois `::`, depois a rotina:

```sather
GREETER::hello
```

De dentro da mesma classe, podes omitir o nome da classe. É esta a forma
habitual de deixar uma rotina usar outra:

```sather
   greeting_again : STR is
      return hello;
   end;
```

## Comentários

Dois traços iniciam um comentário que vai até ao fim da linha.

```sather
   -- Explain why, not what: the code already says what.
   hello : STR is
      return "Hello!";   -- a trailing comment is fine too
   end;
```

Por convenção, uma classe termina com um comentário que lhe dá o nome. As
rotinas, os ciclos e as classes fecham todos com `end;`, por isso o comentário
diz a qual deles pertence este `end;`:

```sather
end; -- class GREETER
```

## Pontos e vírgulas

As instruções terminam com um ponto e vírgula. O ponto e vírgula depois da
última instrução de uma rotina é opcional, mas escrevê-lo sempre é uma coisa
menos em que pensar.
