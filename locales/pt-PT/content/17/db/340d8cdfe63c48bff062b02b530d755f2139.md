# Sobre

O Common Lisp oferece ao programador vários condicionais diferentes, que se podem categorizar pelo número de «ramos» que suportam.

Além disso, ao contrário de muitas outras linguagens de programação, todos os condicionais no Common Lisp são _expressões_ e não instruções.
Isto significa que todos os condicionais de Lisp resultam num valor e podem ocupar o lugar de parâmetros concretos.

Por exemplo:

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## Condicionais de um único ramo

Os condicionais `when` e `unless` avaliam algum código apenas quando o teste fornecido é verdadeiro ou falso, respetivamente, resultando em `nil` caso contrário.

A secção a seguir à expressão de teste pode ter mais do que uma expressão.

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## O condicional de dois ramos

O condicional `if` avalia a primeira expressão do corpo quando o teste é verdadeiro e a segunda caso contrário.

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

Repara que tanto a cláusula then como a cláusula else só podem ser uma única expressão.

## Condicionais de vários ramos

O «super-condicional» de Lisp é o `cond`, que pode ter um número infinito de ramos.
Cada ramo tem uma condição de teste e uma expressão de corpo que são envolvidas por um par extra de parênteses.
Se todos os testes forem falsos, é devolvido `nil`.

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

Repara que não há limite para o número de expressões depois da expressão de teste.


Se só quiseres testar um valor em vários ramos, podes usar a expressão `case`, que é mais limpa.
Se nenhum dos casos corresponder, é devolvido `nil`.
Tanto o `t` como o `otherwise` podem ser usados como casos que apanham tudo:

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

Repara que, tal como no `cond`, não há limite para o número de expressões depois da expressão de teste.

## Os condicionais camuflados

As operações booleanas `and` e `or` do Common Lisp são macros de curto-circuito que podem ser usadas para reduzir a duplicação de certas expressões condicionais.

A macro `and` devolve imediatamente `nil` se encontrar um único valor falso, mas, caso contrário, devolve o último valor verdadeiro do `and`:

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

A macro `or` devolve o primeiro valor verdadeiro que encontrar ou `nil` se não houver valores verdadeiros:

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## Estou exausto...

Como já foi referido, quando nenhum dos ramos de uma instrução `case` corresponde e não existe uma cláusula `otherwise`, é devolvido `nil`.
Por vezes, no entanto, uma falha em corresponder a qualquer ramo deve ser tratada como um erro. É aqui que entra o `ecase` (para correspondência **exaustiva**).

Usa-se exatamente da mesma forma que o `case`, mas sinaliza um erro em vez de devolver `nil` quando não há correspondência.

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
