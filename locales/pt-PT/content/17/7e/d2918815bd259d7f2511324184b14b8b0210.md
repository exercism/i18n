## Roc API

Usa um valor `React` imutável. Cada operação devolve um reactor atualizado; guarda esse valor para as operações seguintes. As células são identificadas por `cell_id`; os callbacks por `callback_id`. Ambos os identificadores são strings fornecidas quando são registados. O registo e a remoção de callbacks usam ambos os identificadores para especificar a célula e o respetivo callback.

Uma função de cálculo recebe uma lista de valores de células na mesma ordem da sua lista `inputs` de identificadores de células. Devolve `Ok(value)` em caso de sucesso ou `Err(message)` com uma string que descreve uma falha, como um número de entradas incorreto ou uma divisão por zero. As suas dependências têm de já existir quando a célula de cálculo é adicionada. Tanto `add_compute` como `set_value` comunicam erros de cálculo como `ComputeFailed({ cell_id, message })`. Se um cálculo falhar durante uma atualização, não é devolvido nenhum reactor atualizado e não corre nenhum callback; o reactor original continua utilizável.

Os callbacks são funções puras do tipo `React.CellValue, React.CallbackLog -> React.CallbackLog`. Cada callback recebe o novo valor da célula e o log atual, e devolve depois um log atualizado. `set_value` recebe um registo que contém `cell_id`, `value` e o `log` inicial, e devolve tanto o reactor atualizado como o log final. Passa o log devolvido por cada callback ao callback seguinte; a ordem dos callbacks não é especificada.

`React.CallbackLog` é um alias de `Dict(Str, List(I64))`: regista os valores recebidos por cada identificador de callback. Os testes passam um log vazio a cada atualização de entrada para verificar se os callbacks correram exatamente uma vez ou não correram de todo.

Registar um callback não o chama. Remover o mesmo callback mais do que uma vez é permitido e não pode afetar os outros callbacks. Todos os callbacks de uma atualização têm de observar os valores finais e estáveis das células.
