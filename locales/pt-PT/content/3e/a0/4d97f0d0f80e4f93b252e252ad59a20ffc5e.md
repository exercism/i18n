# Dicas

## Geral

- Uma comparação empacotada escreve uma **máscara**: cada lane fica com todos os bits a um onde a condição se verifica e com todos os bits a zero onde não se verifica.
- As comparações de vírgula flutuante recebem a condição como imediato, ou podes usar as pseudo-instruções do NASM, como `cmpltps` e `cmpeqps`.
- As comparações de inteiros recebem a condição como sufixo: `pcmpgtd` para maior que com sinal, `pcmpeqd` para igualdade.
- Os blocos estão alinhados a 16 bytes, por isso `movaps` e `movdqa` são ambos seguros.

## 1. Assinalar as pontuações acima do limiar

- `a > b` é o mesmo que `not (a <= b)` (imediato 6) ou que `b < a` (imediato 1, com os operandos trocados).
- A igualdade não deve contar como estando acima do limiar.

## 2. Assinalar as pontuações perfeitas

- Isto é uma igualdade de vírgula flutuante direta com `cmpeqps`.
- Compara as pontuações com os máximos.
  Cada lane fica definido onde coincidem.

## 3. Atribuir uma classificação

- Podes definir o limiar `50.0` e os valores de classificação `1`, `2` e `3` como constantes empacotadas na memória, com quatro lanes cada.
- Podes definir duas máscaras.
  Uma para «acima do limiar», como na tarefa 1 (mas em relação à constante empacotada `50.0`).
  Outra para «pontuação perfeita» (como na tarefa 2).
- A classificação base é `1`.
  A classificação `2` deve ser selecionada para os lanes onde a máscara de «acima do limiar» está ativa.
  A classificação `3` deve ser selecionada para os lanes onde a máscara de «pontuação perfeita» está ativa.
- As pontuações perfeitas também estão acima do limiar.
  Se a máscara de «acima do limiar» for aplicada primeiro, a máscara de «pontuação perfeita» tem precedência onde for necessário.
- O `blendvps` recebe a sua máscara de `xmm0` e seleciona de acordo com o bit mais alto de cada lane.
  Nos lanes onde este bit está a um, seleciona do operando de origem.
  Nos restantes, mantém o lane que já está no operando de destino.

## 4. Contar as falhas

- Uma classificação falha quando está estritamente abaixo do limiar, ou seja, quando `threshold > rank`.
  Podes usar `pcmpgtd` com o limiar como destino e as classificações como origem.
- Para cada bloco, podes usar `movmskps` para compactar a máscara de falhas num registo de uso geral, recolhendo o bit mais alto de cada lane.
  Este registo de uso geral pode ter 32 ou 64 bits.
- Podes usar `popcnt` para contar o número de bits a um num registo de uso geral.
- Pode haver mais do que um bloco, por isso é necessário um ciclo para os percorrer e acumular um resultado.
- Cada bloco tem 16 bytes.

## 5. Passaram todos?

- «todos passaram» é representado por um resultado todo a zeros na máscara de falhas.
  Um único lane diferente de zero é um resultado falso.
- Pode haver mais do que um bloco, por isso é necessário um ciclo para os percorrer e acumular um resultado.
- Cada bloco tem 16 bytes.
- Podes usar um `ptest` de um registo com ele próprio para verificar se está tudo a zeros.
- Uma operação OR preserva os bits a um e uma operação AND preserva os bits a zero.
  Ambas podem ser usadas para acumular valores lógicos num ciclo.
- Uma flag pode ser transformada num resultado `0/1` com `setcc`.
