# Instruções

Tu, o Mestre do Mal, tens muito orgulho na qualidade dos `TreasureChest`s que se encontram nas tuas masmorras malignas por todo o mundo.
Não é fácil manter a qualidade, os teus gestores de masmorras não param de estragar a criação de tesouros, por isso decides fornecer uma API de Elm para os dobrar à tua vontade.

Há duas condições em que não cedes:
1. um `TreasureChest` deve ser protegido por uma palavra-passe segura de pelo menos 8 carateres
2. numa masmorra específica, cada `TreasureChest` deve guardar um tesouro único

Os teus gestores de masmorras vão apresentar uma lista de sugestões de palavra-passe/tesouro, e só serão criados os `TreasureChest`s adequados.

Com estes critérios, há duas formas possíveis de criar baús seguros a partir de uma lista de sugestões: 
1. remover os que têm palavras-passe inseguras e, depois, remover os que têm tesouros duplicados
2. remover os que têm tesouros duplicados e, depois, remover os que têm palavras-passe inseguras

Estas duas podem não dar os mesmos resultados (por exemplo, para `[("strong_password", GoldStatue), ("1234", GoldStatue)]`), mas tanto te faz, por isso queres deixar que os gestores de masmorras decidam.

Uma API que deixa alguma escolha aos utilizadores, mas que ainda garante propriedades do resultado final?
Parece um encaixe perfeito para a técnica do tipo fantasma!

## 1. Fornece um espaço reservado para baús do tesouro

O tipo `TreasureChest` e a função `getTreasure` que o acompanha já estão definidos, mas precisas de criar um tipo para uma sugestão de baú.

Implementa o tipo `Chest`, implementa `makeChest` e corrige as assinaturas de tipo de `secureChest` e `uniqueTreasures`.
As assinaturas de tipo de `makeChest` e `makeTreasureChest` já são fornecidas como parte dos requisitos; não as modifiques.

Um `Chest` deve guardar os mesmos dados que um `TreasureChest` e deve ter dois argumentos de tipo, um para `treasure` e um tipo fantasma de registo para `conditions`.
Repara que, como `Chest` usa um tipo fantasma, deve por isso ser opaco para impedir a sua utilização em qualquer lugar fora do módulo `TreasureFactory`.
Neste caso, não é sequer exposto.

Edita as assinaturas de tipo de `secureChest` e `uniqueTreasures` para adicionar as restrições usando registos extensíveis como tipos fantasma.
`secureChest` deve receber um `Chest` sem condições específicas e devolver um `Maybe Chest`, com a condição extra `securePassword : ()` no seu registo fantasma.
`uniqueTreasures` deve receber uma `List Chest` sem condições específicas e devolver uma `List Chest`, com a condição extra `uniqueTreasure : ()` adicionada ao registo fantasma.

~~~~exercism/note
Os testes de Elm têm acesso às funções expostas, mas não às assinaturas de tipo; por isso, é impossível que os testes verifiquem se estás a usar as assinaturas corretas.
Claro que a indicação mais forte de que tens as assinaturas corretas é conseguires compilar e executar o módulo e os testes, mas criámos uma regra do analisador que vai verificar as tuas assinaturas de tipo assim que submeteres a tua solução.
~~~~

## 2. Seleciona baús seguros

Assim que tiveres os baús prontos, precisas de escolher os seguros.

Implementa `secureChest` que só devolve uma variante `Just` para baús com uma palavra-passe de 8 ou mais carateres.
Os `Chest` que cumprem essas condições devem ter uma condição extra `securePassword : ()` adicionada ao seu tipo fantasma.

## 3. Seleciona tesouros únicos

Só os tesouros mais raros devem ser permitidos numa masmorra; até uma única cópia faz um tesouro parecer barato.

Implementa `uniqueTreasures` que recebe uma lista de `Chest` e devolve uma lista dos `Chest` que têm um tesouro único na lista de entrada.
Se um tesouro aparecer duas vezes na entrada, não deve estar na saída.
Os `Chest` de entrada não devem ter condições específicas, e os de saída devem ter a condição extra `uniqueTreasure : ()` adicionada.

## 4. Aproveita o produto final

Aproveita o melhor dos `TreasureChest`s, que vão de certeza atrair aventureiros como moscas ao mel.

Implementa `makeTreasureChest` que recebe um `Chest` que é ao mesmo tempo seguro e único e cria um `TreasureChest`.
Como `TreasureChest` é um tipo opaco, esta será a única forma de criar um; nem os gestores de masmorras mais incompetentes o conseguirão estragar.
