# Introdução

O assembly escrito à mão está cheio de repetição.
A mesma pequena sequência de instruções aparece vezes sem conta, com pouca variação, e há poucas abstrações para reduzir o código repetitivo.
Além disso, programar em assembly obriga a gerir valores sem semântica óbvia.
Não há parâmetros com nome e a maior parte dos detalhes da máquina subjacente tem de ser tratada manualmente pelo programador.

O NASM, o assembler usado pelo track, oferece algumas ferramentas que podem ajudar o programador com ambos os problemas.
Estas ferramentas atuam em _tempo de assemblagem_, antes de qualquer instrução chegar ao processador.
Orientam o assembler sobre como reescrever o texto fonte antes de este ser sequer traduzido em código máquina.

A mais importante destas ferramentas são as **macros**, que podem ser vistas como uma receita para o assembler.
São expandidas no local onde são usadas, como se o código tivesse sido escrito ali à mão.

As macros podem receber vários tokens literais como parâmetros, o que as torna reutilizáveis em contextos diferentes.
No entanto, não são funções: não há `call`, nem `ret`, nem transferência de controlo para outro ponto do código.

## Macros de uma linha

A definição mais simples dá um nome a um valor ou a uma expressão curta com `%define`:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Todas as ocorrências posteriores de `WIDTH` são substituídas por `8` antes da assemblagem.
A substituição é textual, pelo que o nome é substituído onde quer que apareça, seja num operando, seja dentro de outra definição.

~~~~exercism/note
Para _constantes_ numéricas, prefere `equ` em vez de `%define`.

Uma macro de uma linha declarada com `%define` só se expande quando é usada, e pode ser reatribuída ou deixar de estar definida.
Uma constante `equ`, por outro lado, é avaliada no ponto de definição e nunca é modificada.
~~~~

Um `%define` também pode receber parâmetros _com nome_, comportando-se como uma pequena função inline:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Coloca entre parênteses tanto o corpo inteiro como cada parâmetro.
Com `%define square(x) x*x`, a chamada `square(1+1)` expande-se para `1+1*1+1`, que é `3`.
Escrito como `%define square(x) ((x)*(x))`, a mesma chamada expande-se para `((1+1)*(1+1))`, que é `4`.
~~~~

Os nomes definidos com `%define` distinguem maiúsculas de minúsculas.
A variante `%idefine` faz com que o nome não distinga maiúsculas de minúsculas, se for essa a intenção.

As macros de uma linha são úteis para dar significado a várias partes do código.
Se usadas com cuidado, melhoram a legibilidade e reduzem a probabilidade de gralhas.
Por exemplo, um registo que tem uma finalidade dedicada dentro de uma função pode ser definido pela sua finalidade:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Macros de várias linhas

Uma sequência inteira de código, com qualquer número de linhas, é capturada com `%macro` e fechada com `%endmacro`.
Um número a seguir ao nome indica quantos argumentos a macro recebe, que podem ser zero.
Quando são passados argumentos, estes são separados por uma vírgula (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Os argumentos em macros de várias linhas não têm nome.
São referidos como `%1`, `%2`, e assim por diante, pela ordem em que são passados:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Repara que os argumentos têm de ser sintaxe válida para as operações realizadas no corpo da macro.
Aqui, tanto `mult_two eax, ecx` como `mult_two r8, r9` são aceites pelo assembler, mas `mult_two eax, cl` não seria, uma vez que `imul eax, cl` não está definido.

### Etiquetas dentro de uma macro

Uma macro que define uma etiqueta comum deixa de funcionar no momento em que é usada duas vezes, porque a etiqueta também seria definida duas vezes.
Para usar etiquetas dentro de uma macro que pode ser chamada mais do que uma vez, é necessário colocar o prefixo `%%` antes dessa etiqueta.
Isto instrui o assembler a dar a essa etiqueta um nome diferente e único em cada expansão:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Repetir em tempo de assemblagem

É possível repetir um bloco de código de uma linha com `times`.
Isto é particularmente útil ao declarar valores repetidos na memória:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Para repetir código de várias linhas, podemos usar `%rep`:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Repara que o número de repetições é indicado logo a seguir a `%rep` e que há um `%endrep` para fechar o bloco repetido.

É comum usar um contador de tempo de assemblagem dentro de um bloco `%rep`, tal como um ciclo em tempo de execução usa um contador.
Embora uma constante inteira de tempo de assemblagem possa ser declarada com `equ`, para _variáveis_ inteiras de tempo de assemblagem usamos `%assign`.
Ao contrário de `%define`, `%assign` é avaliado imediatamente para um número e pode ser reatribuído:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Depois de o pré-processador correr, o ciclo desaparece e restam quatro instruções `add`, com os valores imediatos `0`, `1`, `2` e `3` já embutidos.
Isto é o desenrolar de ciclos feito pelo assembler: sem registo contador e sem salto, apenas código linear.

## Assemblagem condicional

O pré-processador tem à disposição vários condicionais.
Selecionam entre vários caminhos diferentes, expandindo o seu corpo no próprio local, mas apenas quando a sua condição é verdadeira.

`%if` ... `%elif` ... `%else` ... `%endif` selecionam um caminho a partir de um teste numérico:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## Dividir em ficheiros

As macros são frequentemente guardadas num ficheiro próprio e trazidas para cada fonte que precisa delas com `%include`:

```x86asm
%include "patterns.mac"
```

O ficheiro indicado é inserido literalmente nesse ponto, antes da assemblagem, exatamente como se o seu conteúdo tivesse sido escrito ali.
Isto mantém as definições num único local e permite que vários ficheiros fonte as partilhem.

Se o ficheiro de macros também puder ser montado pelo assembler de forma autónoma, deve ter a extensão `.asm`.
Repara que as macros não têm ligação.
Mesmo que o ficheiro de macros seja montado pelo assembler, as suas macros só são visíveis para outro ficheiro que o inclua com `%include`.

Caso contrário, um ficheiro destinado apenas a ser incluído com `%include` pode ter qualquer extensão.
Usar `.asm` ou `.mac` é uma convenção comum.
