# Sobre

`<dlist>` (em [`dlists`][dlists]) constrói uma nova lista duplamente ligada. As operações vivem em [`deques`][deques] e despacham com base no [protocolo de deque][deque-protocol], para que outros contentores, sobretudo `<dlist>`, as possam implementar.

| palavra         | efeito                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`: deque vazio novo    |
| `push-front`    | `( elt deque -- )`: adiciona à frente |
| `push-back`     | `( elt deque -- )`: adiciona ao fim  |
| `pop-front`     | `( deque -- elt )`: remove da frente |
| `pop-back`      | `( deque -- elt )`: remove do fim  |
| `peek-front`    | `( deque -- elt )`: lê a frente sem remover |
| `peek-back`     | `( deque -- elt )`: lê o fim sem remover  |
| `deque-empty?`  | `( deque -- ? )`: o deque está vazio? |
| `dlist-length`  | `( dlist -- n )`: número de elementos |

Todas as operações push/pop alteram o deque diretamente. Passar um deque a uma rotina e voltar a lê-lo depois é o padrão normal.

## Pilha vs fila

Dois padrões de despacho convencionais:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

Um vetor com `push` e `pop` (de `mutation`) é a escolha certa quando a ordem LIFO é tudo o que precisas. O `<dlist>` acarreta o custo adicional de uma lista ligada. Recorre ao `<dlist>` quando precisas de O(1) em *ambas* as extremidades, quase sempre para uma fila FIFO.

## Padrão BFS

A procura em largura é o uso canónico de uma fila FIFO:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

O deque transporta a fronteira da procura; o conjunto de hash trata da deduplicação. Troca `pop-front` por `pop-back` e a mesma estrutura passa a ser procura em profundidade.

## `MEMO:` e a cache automática

Por vezes, a consulta por cada nó que a procura em largura faz é dispendiosa. O Factor disponibiliza [`MEMO:`][memo-decl], um substituto de `:` que guarda automaticamente em cache o resultado da palavra, indexado pelos seus parâmetros de entrada:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

Uma palavra `MEMO:` executa o seu corpo na primeira vez que cada valor de entrada é visto e devolve o resultado em cache a partir daí. A cache dura todo o tempo de vida da imagem; não há expulsão com base no tempo nem no tamanho. Usa-o em funções puras cujos valores de entrada venham de um conjunto finito e controlável.
