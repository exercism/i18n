# Introdução

Como vimos no conceito [`Nothingness`][concept-nothingness], o R tem várias formas de representar dados ausentes (`NULL`), desconhecidos (`NA`) ou matematicamente inválidos (`NaN`, `Inf`).
Em geral, o R tenta usá-las para assinalar problemas no próprio local e continuar sem lançar uma exceção.

## `stop()`

Alguns problemas são demasiado fundamentais para deixar o programa continuar. 
Nesse caso, usa `stop(msg)` para parar imediatamente o programa com um `Error` e imprimir `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

À semelhança de um `assert` noutras linguagens, esta é uma forma prática de invocar `stop()`. 
Os parâmetros são um número arbitrário de condições Boolean separadas por vírgulas, e o programa só continua se todas forem `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

O R tem várias formas de tratar erros.
Baseiam-se em Common Lisp e são bastante diferentes das de muitas linguagens populares.

A mais simples consiste em envolver o código potencialmente problemático em `try()`.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()` e `message()`

Estas são respostas a condições não fatais, por exemplo:

- Para avisar de um problema do qual o programa pode, pelo menos em parte, recuperar.
- Para informar o utilizador do progresso num programa de longa duração.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

A função `suppressWarnings()` pode, ocasionalmente, ser útil no Exercism, para evitar que resultados indesejados confundam o test runner.
