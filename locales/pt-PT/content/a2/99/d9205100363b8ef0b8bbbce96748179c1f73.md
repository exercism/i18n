# Testes

Podes correr os testes com o seguinte comando, no diretório do exercício:

```bash
dub test
```

## Passar nos testes

Começa por pôr o primeiro teste a compilar, a ligar e a passar, seguindo as [três regras do desenvolvimento orientado por testes](http://butunclebob.com/ArticleS.UncleBob.TheThreeRulesOfTdd). Cria apenas a estrutura suficiente, declarando namespaces, funções, classes, etc., para resolver os erros do compilador e fazer o teste falhar. Depois escreve apenas o código suficiente para o teste passar. Assim que o conseguires, descomenta o teste seguinte, movendo a linha abaixo para depois do teste seguinte.

```D
static if (all_tests_enabled)
```

Isto pode originar erros de compilação, porque podem ser invocadas construções novas que ainda não declaraste nem definiste. Mais uma vez, corrige os erros de compilação de forma mínima para obteres um teste a falhar, depois altera o código de forma mínima para passar o teste, refatora a tua implementação para a tornar mais legível e expressiva, e passa ao teste seguinte.

Tenta usar os recursos padrão de D em vez de escreveres à mão os teus próprios algoritmos ou recursos de baixo nível.
