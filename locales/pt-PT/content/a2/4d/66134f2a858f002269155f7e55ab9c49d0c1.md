# Introdução

A análise sintática é o processo de transformar texto em dados com significado.
As funções do pacote `String` são limitadas nesse aspeto e as expressões regulares são difíceis de usar, por isso a forma idiomática de analisar em Elm é com o pacote `elm/parser`.

Vamos ver um exemplo de como escrever um analisador para (um subconjunto da) linguagem de programação [LOLCODE][lolcode].
Considera o seguinte programa comentado:

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

Primeiro, vamos escrever um tipo de Elm para representar os comandos possíveis:

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

O nosso programa LOLCODE pode então ser modelado como uma `List Command`.
Vamos começar com um analisador para a linha `HAI 1`:

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP` é construído com um _pipeline de analisadores_.
O operador `(|.)` significa "analisar a string mas descartar o resultado" e `(|=)` significa "analisar a string e manter o resultado".
Neste exemplo, `Parser.keyword "HAI"` consome um "HAI", mas esse resultado é ignorado.
`Parser.spaces` consome qualquer número de carateres ' ', '\n' e '\r', mas isso também é ignorado.
`Parser.int` analisa um número inteiro e o valor desse inteiro (digamos 1) é passado ao `Parser.succeed Version` que está mais acima, e o analisador acaba por devolver o valor `Version 1` com sucesso.

Se algum dos analisadores do pipeline falhar, devolve um `Parser.DeadEnd` e o analisador todo falha.
Um analisador pode ser executado com `Parser.run`:

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

Vamos atacar a linha "CAN HAS STDIO?" com

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP` também é um pipeline de analisadores, mas desta vez termina com `Parser.symbol`, que é adequado para analisar símbolos como "?".
O valor que queremos manter (o nome do pacote a importar) é analisado por

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

Como não sabemos qual será o nome do pacote, não podemos usar `Parser.keyword`, por isso usamos antes `Parser.chompWhile`, que consome carateres um a um desde que satisfaçam uma condição (aqui, serem carateres alfanuméricos).
Estes carateres consumidos são depois recolhidos por `Parser.getChompedString`, que devolve um `Parser String`.
Neste caso, queremos normalizar os nomes dos pacotes, por isso usamos `Parser.map` para modificar a string contida no analisador e pô-la em minúsculas.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

A seguir, `VISIBLE "HAI WORLD!"` é analisado por

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

Temos agora um analisador para cada comando.
Claro que, num programa geral, não é possível prever a ordem destes comandos, por isso construímos um analisador de comandos genérico

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf` tenta um analisador, pela ordem dada.
Se um analisador falhar, passa-se ao seguinte, mas se tiver sucesso, o resultado é devolvido sem tentar os restantes analisadores.
Se todos os analisadores falharem, `Parser.oneOf` falha.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

Repara como cada tentativa falhada produz um `Parser.DeadEnd` que é recolhido pelo `Parser.oneOf`.

Para analisar um programa completo, precisamos de analisar vários comandos sequencialmente com

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence` é um analisador muito personalizável, com várias opções.
`start`, `separator` e `end` recebem strings que separam os itens da sequência; para analisar uma lista de Elm usaríamos "[", "," e "]".
`spaces` dá flexibilidade ao receber um analisador que trata dos eventuais espaços entre itens e separadores; para analisar uma lista de Elm usaríamos `Parser.spaces`, mas neste caso não aceitamos espaços nenhuns, por isso usamos `Parser.succeed ()`, que tem sucesso imediatamente sem consumir nada.
`item` recebe o analisador dos itens e, por fim, `trailing` permite-nos decidir se os separadores no fim são `Parser.Forbidden`, `Parser.Mandatory` ou `Parser.Optional`.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

Quando um analisador tem sucesso, deixa de consumir a string

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

Por isso, se precisarmos de garantir que analisámos tudo na string, podemos usar `Parser.end`

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

Por fim, por vezes precisamos de decidir fazer um analisador falhar consoante o conteúdo que analisou.
Por exemplo, se precisássemos de um analisador que fizesse falhar programas que começam com dois comandos "HAI" seguidos, podíamos usar

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen` pode inspecionar o conteúdo de um analisador e devolve um novo analisador consoante o seu valor.
Aqui, num dos casos fizemos o analisador falhar com uma mensagem personalizada usando `Parser.problem`, e no outro devolvemos o valor original.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
