# Sobre

## const

O modificador [`const`][constants] pode ser aplicado (e, regra geral, deve ser) a qualquer campo cujo valor seja conhecido em tempo de compilação e que não mude durante o tempo de vida do programa.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

O compilador orienta-te sobre que expressões podem ser avaliadas em tempo de compilação. São permitidas operações aritméticas simples, tal como a concatenação de strings. Isto exclui qualquer avaliação que exija o uso da heap ou da stack, pelo que todas as chamadas a métodos e referências a tipos não primitivos ficam de fora.

Há alguma discussão na internet sobre as vantagens de desempenho do `const` em relação a variáveis. No caso de uma comparação com campos de instância não `const`, pode haver uma poupança de memória significativa, mas, quando comparado com variáveis estáticas, isso é decididamente trivial. Qualquer consideração sobre o desempenho da CPU será provavelmente vista pelos teus colegas como [otimização prematura][premature-optimization].

Uma razão mais convincente para usar `const` é que melhora a capacidade de quem faz a manutenção raciocinar sobre o código. Reparar que um campo está marcado como `const` ou `readonly`, ou que uma propriedade não tem setter, permite a quem faz a manutenção excluí-lo em grande medida da sua análise. É pouco provável que seja o foco de erros. É pouco provável que cause dificuldades numa refatoração. Este [comentário no Stack Overflow][so-consts] aborda esta questão.

O modificador `const` também pode ser aplicado a valores dentro de métodos:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

Identificar um valor com `const` desta forma pode ser útil se ele for usado várias vezes no método ou se quiseres chamar a atenção para o seu significado. Não há qualquer ganho de desempenho em relação a usar literais diretamente no código.

## readonly

O modificador [`readonly`][readonly-fields] pode ser aplicado (e, regra geral, deve ser) a qualquer campo que não possa ser `const` quando o seu valor não muda durante o tempo de vida do programa e é definido por um inicializador escrito diretamente no código ou durante a instanciação (pelo construtor ou por um método chamado pelo construtor).

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

O uso do modificador `readonly` é encorajado pelas mesmas razões que se aplicam ao `const`. O hábito de restringir campos desta forma ajuda quem faz a manutenção a raciocinar sobre o código.

Repara que acrescentar o modificador `readonly` a um campo impede apenas que o valor do campo seja alterado. No caso de tipos agregados, não protege os campos nem as propriedades desse tipo. Em particular, não protege o conteúdo de arrays.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

Para garantir que todos os membros de um tipo de referência estão protegidos, os campos podem ser marcados como `readonly` e podem definir-se propriedades automáticas sem um acessor `set`.

Deves dar uma vista de olhos às [coleções só de leitura][readonly-collections] na Biblioteca de Classes Base.

Para arrays, o mais próximo que consegues chegar de uma versão só de leitura é o método [`Array.AsReadOnly<T>()`][as-read-only].
