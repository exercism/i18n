# Sobre

_"As datas e as horas são algo que ensinamos a crianças pequenas. Quão difícil pode ser?"_

Muitos programadores já cometeram esse erro, e a experiência que se segue costuma ter um efeito negativo na sua saúde e na sua felicidade.

Quem faça programação não trivial com datas e horas deve, no mínimo, estar preparado para compreender e mitigar potenciais problemas.

Este documento procura dar uma panorâmica de como a Julia trata as datas e as horas, mas será necessário consultar o [manual][Dates] para mais detalhes.
Existe também um [Wikibook][Wikibook] cujas explicações alguns leitores podem achar mais claras, e que inclui um [diagrama][type-hierarchy] útil da hierarquia de tipos.

## O módulo `Dates`

A maior parte da funcionalidade básica está em `Dates`, um módulo incluído numa instalação predefinida, mas que não faz parte da biblioteca padrão.

Para usar o módulo, há duas opções:

1. Adicionar `import Dates` e depois preceder todas as chamadas de funções com `Dates.`
2. Adicionar `using Dates`, o que traz o módulo inteiro para o espaço de nomes atual (_exceto alguns nomes problemáticos_).

```julia-repl
# option 1
julia> import Dates

julia> Dates.now()
2025-06-21T16:02:39.080

julia> now()  # wrong: need to include `Dates.` after an import
ERROR: UndefVarError: `now` not defined in `Main`


# option 2
julia> using Dates

julia> now()  # functions are now in the namespace
2025-06-21T16:03:04.161
```

O módulo `Dates` é grande e complicado, mas fornece quatro tipos principais de funcionalidade:

- `Dates.Date`, que inclui dia-mês-ano mas não a hora do dia.
- `Dates.Time`, que inclui a hora do dia, com resolução de nanossegundos, mas não a data.
- `Dates.DateTime`, que combina data e hora com resolução de milissegundos.
- `Dates.Period`, que trata de intervalos de tempo/data.

Tem em conta que um `DateTime` geralmente _não_ inclui informação de fuso horário (o Python chamaria a isto um datetime "naive").
Uma exceção é `now()`, que obtém a hora local a partir do relógio do teu sistema e pode convertê-la em UTC, se for necessário.

Outros cálculos de fuso horário precisam do pacote `TimeZones.jl`, que não faz parte de uma instalação predefinida.
Em junho de 2025, isto ainda não está disponível no Exercism, mas pode vir a ser adicionado no futuro.

Talvez as necessidades mais frequentes sejam:

- Analisar um formato de entrada adequado para construir um tipo `Dates`.
- Obter o formato numérico ou de string necessário a partir de um tipo `Dates`.
- Aplicar um deslocamento a um valor `Date`, `Time` ou `DateTime`.
- Calcular o intervalo entre dois desses valores.
- Obter a data atual (com `today()`) e/ou a hora (com `now()`).

Para reduzir a distração visual, a maior parte do código de exemplo no resto deste documento assume `using Dates` e evita incluir o nome do módulo `Dates.` nas chamadas de funções.

### Formatos de data e hora

Há muitas maneiras de escrever datas e horas, que tendem a ser específicas de cada cultura.
As datas só com números, como "7/6/23", são ambíguas, confusas e já levaram a muitos erros dispendiosos em organizações multinacionais (_o autor fala disto por amarga experiência pessoal_).

O padrão internacional está definido na [`ISO 8601`][ISO8601] e tem duas vantagens principais:

- A análise é rápida e não é ambígua.
- A ordenação é fácil, pois a data e hora pode ser tratada como texto normal e ordenada alfabeticamente.

Vimos num exemplo anterior que `Date.now()` devolvia `2025-06-21T16:03:04.161`.

Isto é composto por várias partes:

- `YYYY-MM-DD` para a parte da data.
- `hh:mm:ss` para a parte da hora.
- Opcionalmente, milissegundos (ou uma unidade ainda menor) após a vírgula decimal.

Outros formatos de string serão abordados mais à frente.

## Datas

`Dates.Date` é um tipo relativamente simples, só de datas, sem qualquer noção de horas ou de fusos horários.

```julia-repl
# constructor with year, month, day arguments
julia> date1 = Date(2025, 06, 23)
2025-06-23

# constructor with ISO 8601 string
julia> date2 = Date("2025-06-23")
2025-06-23

julia> date1 == date2
true

julia> typeof(date1)
Date
```

Existem funções de acesso para as partes individuais da data, e estas surgem em pares distinguidos pela capitalização.

```julia-repl
# lowercase returns an integer
julia> month(date1)
6

julia> typeof(month(date1))
Int64

# Propercase returns a Period type
julia> Month(date1)
6 months

julia> typeof(Month(date1))
Month

# various compound methods are also available, returning a tuple
julia> monthday(date1)
(6, 23)
```

### Funções de consulta

Existem várias [funções de consulta][query-func] com alguma compreensão do calendário.
O exemplo seguinte mostra apenas algumas.

```julia-repl
julia> date1
2025-06-23

julia> dayofweek(date1) # 1 = Monday, 7 = Sunday
1

julia> dayname(date1)
"Monday"

julia> daysinmonth(date1)
30

julia> isleapyear(date1)
false

julia> lastdayofmonth(date1)
2025-06-30
```

## Horas

`Dates.Time` é o tipo básico, só de horas.
Não tem qualquer noção de datas: as horas passam automaticamente para `Time(0, 0, 0)` à meia-noite.

O formato completo do construtor é `Time(hour, min, sec, millisec, microsec)` ou o equivalente em ISO 8601.

Todos os parâmetros são opcionais e têm `0` como valor predefinido.

```julia-repl
julia> Time(14, 57, 25, 142)
14:57:25.142

julia> Time(14, 57, 25, 142, 32)`
14:57:25.142032

julia> Time("14:57:25.142")
14:57:25.142
```

Tal como acontece com `Date`, as partes individuais estão disponíveis através de funções de acesso:

```julia-repl
julia> minute(t) # => integer
57

julia> Minute(t) # => Period
57 minutes
```

## Datas e horas

`Dates.DateTime` combina a maior parte das características dos tipos `Date` e `Time`.

É o mais versátil destas três classes, embora a resolução temporal esteja limitada a milissegundos (`Time` consegue chegar aos nanossegundos).

```julia-repl
julia> dt1 = DateTime(2025, 6, 23, 14, 57, 25, 142)
2025-06-23T14:57:25.142

# date1 and t were defined in previous examples
julia> dt2 = DateTime(date1, t)
2025-06-23T14:57:25.142
```

Os parâmetros de ano, mês e dia têm `1` como valor predefinido, e os parâmetros de hora têm todos `0` como valor predefinido.

Manter todos estes parâmetros em ordem pode ser um desafio, pelo que o formato ISO pode ser preferível.

Em alternativa, um `DateTime` pode ser construído a partir de um `Date` e um `Time`, como no exemplo acima.

## Períodos

Cada um dos componentes de data/hora tem o seu próprio tipo [`Period`][period], desde `Year` até `Nanosecond`, que representa um intervalo de tempo.
Estes são particularmente úteis para fazer aritmética.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Year(21)
21 years

julia> Second(61)
61 seconds

julia> dt1 + Year(21) - Second(61)
2046-06-23T14:56:24.142

julia> Date(2025, 07, 03) - Date(2025, 04, 25)
69 days
```

Existe também um tipo [`CompoundPeriod`][compound-period], que consegue combinar vários tipos `Period`.
Curiosamente, neste momento é preciso o nome do módulo para evitar um erro de espaço de nomes (_o que dá a sensação de ser um bug_).

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> offset = Dates.CompoundPeriod(Year(21), Second(-61))
21 years, -61 seconds

julia> dt1 + offset
2046-06-23T14:56:24.142
```

Ao subtrair datas/horas, o período é apresentado em dias (para datas) ou em nanossegundos (para horas).
Pode ser útil usar [`canonicalize`][canonicalize] para os converter num `CompoundPeriod`.

```julia-repl
julia> diff = Time(23, 14, 00) - Time(1, 23, 52)
78608000000000 nanoseconds

julia> canonicalize(diff)
21 hours, 50 minutes, 8 seconds

julia> typeof(canonicalize(diff))
Dates.CompoundPeriod
```

Ao trabalhar com tipos `Period`, a Julia tenta ser inteligente em relação a irregularidades do calendário, como a duração dos meses, arredondando conforme necessário.

```julia-repl
# February has fewer days than January
julia> Date(2025, 1, 31) + Month(1) 
2025-02-28
```

## [Arredondamento][rounding]

As funções `floor`, `ceil` e `round` devem ser familiares dos números inteiros e de vírgula flutuante, mas também funcionam com datas e horas.
Especifica o `Period` para o qual arredondar, como segundo argumento.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> floor(dt1, Minute(15))
2025-06-23T14:45:00

julia> ceil(dt1, Minute(30))
2025-06-23T15:00:00

julia> ceil(dt1, Month(1))
2025-07-01T00:00:00
```

## Representações em string

Mencionámos antes o padrão ISO 8601, que é a representação de data/hora predefinida da Julia ao formatar ou analisar strings.

Obviamente, muitos outros formatos são usados com frequência, muitas vezes de formas específicas de cada cultura.
Para lidar com eles, a Julia tem o tipo `DateFormat`, que pode ser construído a partir de uma string de formato de complexidade arbitrária.

```julia-repl
# dateformat"" string syntax
julia> dtfmt = dateformat"d/m/y"
dateformat"d/m/y"

julia> typeof(dtfmt)
DateFormat{Symbol("d/m/y"), Tuple{Dates.DatePart{'d'}, Dates.Delim{Char, 1}, Dates.DatePart{'m'}, Dates.Delim{Char, 1}, Dates.DatePart{'y'}}}

# DateFormat constructor
julia> DateFormat("d/m/y")
dateformat"d/m/y"
```

O exemplo acima é muito simples, apenas uma data no formato dia/mês/ano comum na Europa.
São mostradas duas variantes da sintaxe, mas o resultado é idêntico.

Um `DateFormat` pode depois ser usado para analisar qualquer string adequada:

```julia-repl
julia> DateTime("14/7/2023", dtfmt)
2023-07-14T00:00:00
```

Criar um `DateFormat` implica bastante sobrecarga, por isso fazer este passo apenas uma vez (como aqui com `dtfmt`) ajuda no desempenho quando se percorrem muitas strings de data/hora.

Os formatos podem ser muito mais complexos do que isto, por isso consulta o [manual][dateformat] para mais detalhes.

Quem estiver familiarizado com outras linguagens pode notar uma semelhança de família com as funções `strptime` e `strftime`, que já existem há décadas.
A versão da Julia inspira-se neste legado, mas procura ser mais concisa e flexível.

O mesmo `DateFormat` também pode ser usado para produzir uma data/hora em qualquer formato de string desejado, com a função [`Dates.format()`][format].

Infelizmente, parece haver um conflito de espaço de nomes com `format` (pelo menos na Julia 1.11.5), por isso é melhor incluir o prefixo `Dates.` mesmo depois de `using Dates`.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Dates.format(dt1, dateformat"e, u d")
"Mon, Jun 23"
```

Como está [documentado][wiki-format], `"e, u d"` dá a representação abreviada em texto para o dia da semana e o mês.

A representação em texto tem o inglês como predefinição.
Podem ser adicionadas outras línguas, embora o suporte para isto seja atualmente pouco satisfatório.
