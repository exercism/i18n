# Introdução

_"As datas e as horas são uma coisa que ensinamos a crianças pequenas. Que dificuldade pode haver nisso?"_

Muitos programadores já cometeram esse erro, e a experiência que se segue costuma ter um efeito negativo na sua saúde e na sua felicidade.

Quem faz programação não trivial com datas e horas deve, no mínimo, estar preparado para compreender e atenuar potenciais problemas.

Este documento vai tentar dar uma visão geral de como o R lida com datas e horas, mas será necessário consultar a documentação completa para mais detalhes.

Enquanto linguagem de ciência de dados, as datas e as horas têm uma importância particular no R.
Grande parte dos dados chega na forma de séries temporais: números diários de doentes durante um surto de doença, números mensais de emprego comunicados pelos governos, populações de aves numa colónia de nidificação, o PIB anual das principais economias, e mais exemplos sem fim.

_Será que isto significa que o R torna o tratamento de datas e horas simples?_

Infelizmente, não!

A funcionalidade de datas e horas do R base tem má reputação e, hoje em dia, grande parte é raramente usada.

O pacote [`lubridate`][web-lubridate] é uma grande melhoria, mas prepara-te para uma biblioteca grande e complicada, concebida para lidar com um conjunto vasto e complicado de problemas.

Originalmente independente, o `lubridate` está agora incluído na coleção `tidyverse`.
Carrega-o com `library(lubridate)` ou `library(tidyverse)`.

Recursos para te ajudar a trabalhar com o `lubridate`:

- Uma [página de referência][ref-lubridate].
- Um [cheatsheet][cheat-lubridate] em formato PDF.
- um [capítulo][book-dates-times] em R for Data Science.

## Datas e datetimes

Uma `date` é apenas um dia, sem informação de horas.

Internamente, as datas são armazenadas como o número (com sinal) de dias desde `1970-01-01`.

```R
today()
#> [1] "2026-04-22"
```

Um `datetime` combina informações de data, hora e fuso horário.

Internamente, é armazenado como o número de segundos desde o início de 1970, no fuso horário UTC.

```R
now()
#> [1] "2026-04-22 15:37:11 MST"  # mid-afternoon in Arizona
```

Talvez de forma surpreendente, o R não tem representação interna para valores apenas com horas.

## Trabalhar com valores `date` e `datetime`

Talvez as necessidades mais frequentes com datas e horas sejam:

- Interpretar um formato de entrada adequado para construir uma data ou um datetime.
- Obter o formato numérico ou de string pretendido a partir de uma data ou de um datetime.
- Aplicar um deslocamento a um valor de data ou datetime.
- Calcular o intervalo de tempo entre dois desses valores.
- Obter a data atual (com `today()`) e/ou o datetime atual (com `now()`).

### Interpretar a partir de strings

Há muitas formas de escrever datas e horas, que tendem a ser específicas de cada cultura.
As datas só com números, como "7/6/23", são ambíguas, confusas, e já deram origem a muitos erros dispendiosos em organizações multinacionais (_o autor diz isto por amarga experiência pessoal_).

O padrão internacional (a-m-d) está definido na [`ISO 8601`][wiki-ISO8601], com duas vantagens principais:

- A interpretação é rápida e não é ambígua.
- A ordenação é fácil, pois o datetime pode ser tratado como texto normal e ordenado alfabeticamente.

No entanto, a ciência de dados consiste em trabalhar com os dados que consegues encontrar, e muitas vezes não vale a pena queixar-te da forma como os outros os formatam.

O R base tem funções de conversão que recebem uma string de formato (por omissão, ISO 8601).

```R
as.Date("2026-04-22")
#> [1] "2026-04-22"
as.Date("4/22/26", format = "%m/%d/%y")
#> [1] "2026-04-22"
as.POSIXct("2026-04-22 15:30:09 MST")
#> [1] "2026-04-22 15:30:09 MST"
```

As strings de formato fazem lembrar a função `strptime()`, com décadas de existência, incluída em _muitas_ linguagens.
Os programadores familiarizados com esta sintaxe podem, opcionalmente, usar a função [`fast_strptime()`][ref-parse_dt] do lubridate.

De forma mais útil, o `lubridate` fornece uma grande variedade de [funções auxiliares][ref-parsing], com nomes que representam a ordem dos campos.
Assim que as funções sabem que valores procurar, e em que ordem, a interpretação é impressionantemente flexível.

```R
mdy("4/22/26")
#> [1] "2026-04-22"
mdy("April 22nd 26")
#> [1] "2026-04-22"
mdy("Wednesday, April 22nd 2026")
#> [1] "2026-04-22"
mdy_hm("Wednesday, April 22nd 2026, 4:14 pm")
#> [1] "2026-04-22 16:14:00 UTC"  # defaults to your OS timezone
```

### Construir a partir de valores numéricos

Nas situações em que o teu programa tem os componentes de uma data/datetime como números separados, estes podem ser reunidos com [`make_date()` ou `make_datetime()`][ref-make_datetime].

Estes são os componentes que podem ser fornecidos, mostrando a sua ordem e os seus valores por omissão:

```R
make_datetime(
  year = 1970L,
  month = 1L,
  day = 1L,
  hour = 0L,
  min = 0L,
  sec = 0,
  tz = "UTC"
)
#> [1] "1970-01-01 UTC"


make_datetime(2026, 4, 22, 17)
#> [1] "2026-04-22 17:00:00 UTC"
```

Naturalmente, `make_date()` só recebe argumentos de ano, mês e dia.

### Apresentar de forma legível para humanos

A consola do R apresenta automaticamente datas/datetimes como uma representação em string.
Normalmente, isto é prático, mas por vezes é enganador.

Internamente, as datas e os datetimes são números (mais alguns atributos), não strings.
Devolver uma data (ou datetime) quando se espera uma string vai causar problemas, por isso precisamos de saber como fazer a conversão.

Uma abordagem simples é usar [`as.character()`][ref-ascharacter] do R base, que devolve uma string no formato ISO 8601.

Há também uma função [`format_ISO8601()`][ref-iso8601] para datetimes, que tem opções para arredondar para a precisão pretendida.

```R
today() |> as.character()  # a date
#> [1] "2026-04-23"
now() |> as.character()  # a datetime
#> [1] "2026-04-23 09:07:09.779319"
now() |> format_ISO8601() # defaults to nearest second
#> [1] "2026-04-23T09:07:38"
```

Poucos não-programadores querem ver resultados em ISO 8601, por isso é essencial lidar com formatos de data e hora específicos de cada cultura.

O R base fornece a função [`format()`][ref-format], que usa strings de formato semelhantes às veneráveis funções `strftime()` incluídas em muitas outras linguagens.

```R
format(today(), "%A, %d %B %Y")
#> [1] "Thursday, 23 April 2026"
```

Essa abordagem do R base é feia, mas fiável.
Estes são alguns dos códigos mais comuns:

Código | Resultado
-- | --
%d | Número do dia do mês (5, 17, 28, etc.)
%a | Dia da semana abreviado (Mon, Tue, Wed, etc.)
%A | Dia da semana por extenso (Monday, Tuesday, etc.)
%w | Número do dia da semana (0-6, Sunday is 0)
%u | Número do dia da semana (1-7, Monday is 1)
%b | Mês abreviado (Jan, Feb, etc.)
%B | Mês por extenso (January, February, etc.)
%y | Ano com 2 algarismos (p. ex. 89)
%Y | Ano com 4 algarismos (p. ex. 1989)
%h | horas (relógio de 24 horas)
%m | minutos
%s | segundos
%z | deslocamento em relação ao UTC
%Z | Fuso horário (caráter)

O Lubridate procura oferecer uma alternativa mais amigável para humanos com a função [`stamp()`][ref-stamp], e com as mais restritas `stamp_date()` e `stamp_time()`.

Estas recebem uma string de modelo que é um exemplo do resultado pretendido, e criam uma função personalizada para gerar esse formato.

O Lubridate tenta adivinhar o formato, mas muitas vezes depara-se com ambiguidades e produz o resultado errado.
Prepara-te para fornecer strings de formato (como `"dmy"`) para desambiguar.

No Exercism, também pode ser útil especificar `locale = "C"`, para ignorar o locale do teu sistema e trabalhar em inglês (como os testes esperam).
_Os locales são complicados!_

```R
sf <- stamp("Saturday, June 27, 2026 at 14:45", locale = "C")
#> Multiple formats matched: "%A, %B %d, %Y at %H:%M"(1), "Saturday, %Om %d, %Y at %H:%M"(1), "Saturday, %B %d, %Y at %H:%M"(1), "%A, %Om %d, %Y at %H:%M"(0)
#> Using: "%A, %B %d, %Y at %H:%M"

sf(make_datetime(2023, 3, 29, 15, 0, 0))
#> [1] "Wednesday, March 29, 2023 at 15:00"
```

### Definir ou extrair componentes

O Lubridate fornece [muitas funções][ref-set-get] para obter ou definir elementos de uma data ou datetime: umas óbvias, como `year()` e `second()`, mas também outras mais especializadas, como `quarter()` e `epiweek()`.

Todas estas funções podem ser usadas para obter um valor, e a maioria também pode ser usada para definir o valor.

```R
dt <- now()
dt
#> [1] "2026-04-23 15:47:11 MST"

# get
month(dt)
#> [1] 4

# set
month(dt) <- 11
dt
#> [1] "2026-11-23 15:47:11 MST"
```

Para `wday()` (dia da semana) e `month()`, o resultado por omissão é um número inteiro, mas:

- Definir `labels = TRUE` devolve uma string de carateres abreviada correspondente ao locale atual.
- Definir também `abbr = FALSE` devolve o nome por extenso.

```R
d <- today()
d
#> [1] "2026-04-23"
wday(d)
#> [1] 5
wday(d, label = TRUE)
#> [1] Thu
#> Levels: Sun < Mon < Tue < Wed < Thu < Fri < Sat
wday(d, label = TRUE, abbr = FALSE)
#> [1] Thursday
#> Levels: Sunday < Monday < Tuesday < Wednesday < Thursday < Friday < Saturday
```

Os rótulos são `categorical variables`, que serão o tema de outro Conceito.
Os valores estão restritos aos `Levels` listados, que também mostram a ordem de ordenação.

Por omissão, a semana começa ao domingo, mas isto pode ser alterado com o argumento `week_start` (usa `1` para segunda-feira).

```R
dt <- make_datetime(2026, 4, 23)

# default behavior
wday(dt)
#> [1] 5
wday(dt, label = T)
#> [1] Thu

# set week_start to Monday
wday(dt, week_start = 1)
#> [1] 4
```

Algumas funções utilitárias devolvem valores `TRUE`/`FALSE`, como `leap_year()` e `dst()` (a hora de verão está ativa?).

Os meses têm durações diferentes, por isso `days_in_month()` dá o valor inteiro.

## Extensões de tempo

Tanto os valores `date` como os `datetime` representam um instante ao longo da linha temporal.

Como é que lidamos com conceitos como "a esta hora ontem" ou "daqui a uma semana"?

Os estudantes familiarizados com outras linguagens orientadas para a ciência podem conhecer o `datetime.timedelta` em Python ou o tipo `Period` em Julia.

Em contrapartida, o R tem nada menos do que três formas de representar extensões de tempo, com pontos fortes e limitações diferentes.
Como sempre, escolhe a que melhor se adequa ao teu contexto.

As várias extensões podem ser convertidas facilmente umas nas outras, com `as.period()`, `as_duration()` e `as.interval()`.

Os tipos de extensão podem ser verificados com `is.period()`, etc.

### Períodos

Um `period`, como `hours(3)`, pode ser usado para acrescentar 3 horas a uma hora de relógio.

Irregularidades como a hora de verão (DST) são, em grande parte, ignoradas.

Todos os períodos são o nome pluralizado de uma unidade: `years`, `weeks`, etc.

```R
d <- today()
d
#> [1] "2026-04-25"

d + weeks(2)
#> [1] "2026-05-09"

# dates are coerced to datetimes at midnight if necessary
d - hours(20)
#> [1] "2026-04-24 04:00:00 UTC"

hours(3)
#> [1] "3H 0M 0S"
```

### Durações

Uma `duration`, como `dhours(3)`, acrescenta 3 horas ao tempo físico, respeitando irregularidades como a hora de verão que fazem com que a hora de relógio se desvie do tempo físico.

Todas as durações acrescentam um prefixo `d` ao período correspondente: `dyears`, `dweeks`, etc.

```R
dhours(3)
#> [1] "10800s (~3 hours)"
```

### Intervalos

Um `interval` é uma combinação de um tempo de início e de fim, criado com a função [`interval()`][ref-interval] ou com o operador infixo `%--%`.

```R
# the next 2 lines were run about 33s apart, so now() is different
dt1 <- now()
dt2 <- now() + hours(1)

# interval(0 function)
ivl <- interval(dt1, dt2)
ivl
#> [1] 2026-04-24 16:24:54 MST--2026-04-24 17:25:27 MST

# infix operator
iv2 <- dt1 %--% dt2
iv2 == iv1
#> [1] TRUE
```

## Fusos horários

Lidar com fusos horários pode ser desafiante.
A citação abaixo é da documentação do Python, mas igualmente relevante para o R:

> "As regras de ajuste da hora em todo o mundo são mais políticas do que racionais, mudam com frequência, e não existe um padrão adequado a todas as aplicações para além do UTC."

Alguns pontos gerais sobre fusos horários:

- Um `datetime` inclui sempre um fuso horário (`tz`); uma `date` não tem em conta o fuso horário.
- Os construtores de datetime usam, em geral, [UTC][wiki-UTC] por omissão.
- A função [`now()`][ref-now] é uma exceção: obtém a tua hora local a partir do relógio do sistema, incluindo o `tz`.
  O `tz` local é usado por omissão, mas podem especificar-se outros, como `now("UTC")`.

```R
# timezone defaults to UTC
local <- ymd_hm("2026-04-25 10:32")
local
#> [1] "2026-04-25 10:32:00 UTC"

# timezone can be specified
AZ <- ymd_hm("2026-04-25 10:32", tz = "America/Phoenix")
AZ
#> [1] "2026-04-25 10:32:00 MST"

# same clocktime, different tz
local - AZ
#> Time difference of -7 hours
```

A aritmética relacionada com fusos horários é mais fiável com durações do que com períodos.
