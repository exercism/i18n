# Sobre

Os hash-sets implementam o [protocolo][set-protocol] [`sets`][sets] com hashing por baixo do capô, o que dá O(1) em média para inserir, procurar e remover.
São mutáveis no próprio local, o que os torna ideais para o padrão *conjunto de visitados* nas travessias de grafos.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| palavra       | efeito                                    |
|---------------|-------------------------------------------|
| `HS{ }`       | literal de hash-set vazio (partilhado, usa `clone`!) |
| `>hash-set`   | `( seq -- set )`: cria um conjunto novo a partir de uma sequência (remove duplicados) |
| `adjoin`      | `( elt set -- )`: inserção destrutiva     |
| `in?`         | `( elt set -- ? )`: teste de pertença     |
| `delete`      | `( elt set -- )`: remoção destrutiva      |
| `cardinality` | `( set -- n )`: número de elementos       |
| `null?`       | `( set -- ? )`: verdadeiro quando o conjunto está vazio |
| `members`     | `( set -- seq )`: enumera como sequência  |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )`: converte `set` para a classe de `exemplar` |

Para construir um conjunto a partir de dados que já tens, o `>hash-set` converte qualquer sequência num único passo, descartando os duplicados: `{ 2 3 2 5 } >hash-set` dá `HS{ 2 3 5 }`. É a alternativa em bloco a crescer um conjunto com `adjoin` repetidos.

Um pormenor subtil sobre o `in?` versus o `member?` (de `sequences`): ambos testam a pertença, mas o `member?` faz uma pesquisa linear sobre uma sequência, enquanto o `in?` encaminha para o que quer que seja o método de protocolo do tipo de conjunto. No caso do `HS{ }`, isso é uma pesquisa por hash. Usa o `in?` quando o teu contentor de «visitados» tiver mais do que um punhado de entradas.

O `null?` responde a «este conjunto está vazio?» sem calcular toda a `cardinality`; é a guarda natural para «ainda temos algo para processar?». Para uma lista de trabalho guardada como conjunto, `[ set null? ] [ … ] until` esvazia-a até ficar vazia.

## Combina bem com hashtables

O `HS{ }` para «o X já foi visitado?» combina naturalmente com o `H{ }` para «quem são os vizinhos do X?». Uma DFS de manual é só isto:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

O conjunto de visitados elimina trabalho duplicado; a pilha encadeia os nós da fronteira (LIFO através de `push`/`pop`); o mapa de vizinhos (uma hashtable) fornece o grafo. A ordem de visita não importa para uma questão de alcançabilidade, e é por isso que um vetor usado como pilha chega; uma BFS a sério sobre a mesma forma troca o vetor por uma [`<dlist>`][dlist] e passa a retirar elementos pela frente.
