# Introdução

## Carateres

Uma **codificação de carateres** é uma convenção específica usada para representar elementos de texto de uma língua natural como uma sequência de bytes.
Um "elemento de texto", aqui, pode ser qualquer unidade com significado numa língua natural, por exemplo, letras, espaços, pontuação, emojis, ideogramas, etc.

O NASM (The Netwide Assembler, o assembler usado por este track) tem suporte para a definição de dados usando **ASCII**.

As constantes de carateres em NASM podem ter até 8 bytes e ser definidas com aspas simples (`'`), aspas duplas (`"`) ou backticks (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Os carateres especiais têm de ser definidos entre backticks e escapados com `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Repara que não existe suporte incorporado para nenhuma codificação de carateres em x86-64 como um tipo distinto.
Em assembly, os dados são uma sequência de bytes, e a interpretação desses bytes como um caráter, um número ou qualquer outra coisa fica ao critério do programador.

Por exemplo, o caráter ASCII '0' é um único byte com o valor 48.
Por isso, guardar 48 num byte é exatamente o mesmo que guardar o caráter ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Pela mesma razão, a manipulação de carateres faz-se transformando diretamente os valores desses bytes:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Strings

Uma **string** é uma cadeia de carateres.
Em assembly, é normalmente implementada como um array.

É possível declarar uma string em NASM da mesma forma que se declararia qualquer array:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Uma diferença entre strings e outros arrays é que o NASM também tem suporte para declarar strings sem uma vírgula (`,`) a separar os valores.
Também é possível intercalar valores com vírgulas:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Repara que, como já foi mencionado, os carateres são apenas bytes (ou uma sequência de bytes numa codificação Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Como cada caráter ASCII ocupa um único byte, qualquer byte seguinte num tamanho maior é `0`.
Por exemplo, declarar `'a'` como um qword (8 bytes) significa que o primeiro byte é `'a'` (`97`) e os outros sete bytes são todos `0`.

Por esta razão, todos estes são equivalentes:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
Em assembly, as strings não são terminadas automaticamente por um caráter NUL ASCII (valor `0`).

Ao interagir com linguagens de nível superior, como C, é responsabilidade do programador garantir que o terminador correto, se existir, é acrescentado ao fim da string.
~~~~

## Instruções de string

Como as strings são arrays, podes trabalhar com elas da mesma forma que com qualquer array, desreferenciando explicitamente a memória:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Além disso, existem algumas instruções para carregar, mover e guardar valores em sequências de bytes na memória.
Apesar de se chamarem _instruções de string_, podem ser usadas com qualquer sequência de bytes na memória, ou seja, com qualquer array.

As três instruções de string mais importantes são `lods`, `stos` e `movs`:

| instrução | o que faz                                                                                                          |
| --------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`    | carrega um valor de uma posição de memória indicada por `rsi` para `rax`                                           |
| `stos`    | guarda um valor de `rax` numa posição de memória indicada por `rdi`                                                |
| `movs`    | copia um valor de uma posição de memória indicada por `rsi` e guarda-o numa posição de memória indicada por `rdi`  |

Repara que estas instruções _não_ recebem qualquer operando explícito.
Os seus operandos são implícitos.

Como regra geral:

1. Quando o seu operando de origem é uma posição de memória, o endereço deve ser guardado em `rsi` (`s` de source).
2. Quando o seu operando de destino é uma posição de memória, o endereço deve ser guardado, em vez disso, em `rdi` (`d` de destination).
3. Se um dos operandos não for uma posição de memória, é o registo `rax`.

Repara que estas instruções desreferenciam automaticamente os endereços de memória de acordo com a operação específica que realizam.

Todas podem operar em tamanhos diferentes.
É acrescentado um sufixo para indicar esse tamanho:

| sufixo | significado | tamanho |
| :----: | ------- | :------ |
|  `b`   | byte    | 1 byte  |
|  `w`   | word    | 2 bytes |
|  `d`   | dword   | 4 bytes |
|  `q`   | qword   | 8 bytes |

Por exemplo:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

Também atualizam qualquer endereço usado pelo tamanho da operação.
Esta atualização é feita de acordo com o valor da **direction flag (DF)**:

- Se a `DF` estiver limpa, os endereços são _aumentados_ pelo tamanho da operação.
- Se a `DF` estiver definida, os endereços são, em vez disso, _diminuídos_ na mesma quantidade.

A ABI System V estabelece que a direction flag tem de estar limpa à entrada de uma função.
Por isso, _o comportamento predefinido é que a memória seja lida/escrita por ordem crescente de endereços_.

A instrução `cld` pode ser usada para limpar a direction flag, enquanto a instrução `std` serve para a definir:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
O chamador espera que a `DF` esteja limpa depois de qualquer função chamada regressar, segundo a ABI System V.
Se alguma vez definires a `DF`, certifica-te de que a limpas antes do `ret`.
~~~~

### Rep

Além destas, a instrução **rep** não interage diretamente com a memória.
Em vez disso, pode ser acrescentada como prefixo às outras instruções mencionadas, _repetindo_ essas instruções.

Quando têm o prefixo `rep`, as instruções de string são repetidas um número de vezes igual ao valor em `rcx`.
De cada vez, o valor em `rcx` é diminuído em `1`.
Repara que o valor em `rcx` tem de ser definido antes de a instrução ser usada:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
Nos CPUs modernos, `rep movs` e `rep stos` são normalmente opções rápidas para mover dados em blocos grandes.
As outras instruções de string, e até `movs` e `stos` quando operam sem `rep`, são, no entanto, normalmente mais lentas do que um ciclo simples.

Podes encontrar uma análise mais aprofundada deste tema em [Capítulo 16.9, "Instruções de string", deste livro de referência][agner-optimization-guide].
