# Introdução

O código escalar baseia-se em sinalizadores definidos por várias instruções para ramificar em resposta a uma determinada condição.
Os valores empacotados, no entanto, representam não um, mas muitos valores em paralelo.
Uma única condição pode falhar numa via e ser verdadeira noutra.

É por isso que o código SIMD é _sem ramificações_ por predefinição.

Em vez de se basear em sinalizadores, as comparações empacotadas produzem normalmente uma **máscara** no operando de destino.
Para cada via, a comparação preenche a via inteira com uns quando é verdadeira e com zeros quando é falsa.
Interpretada como um número inteiro com sinal, uma via verdadeira é `-1` e uma via falsa é `0`.

Esta máscara pode depois ser combinada com operações bit a bit para filtrar vias específicas.

## Comparações empacotadas

Uma `cmp` escalar é genérica no sentido em que é usada para definir vários sinalizadores ao mesmo tempo.
Outra instrução pode depois consumir esses sinalizadores para ramificar ou efetuar cálculos.

No entanto, como uma comparação empacotada tanto verifica uma condição como calcula uma máscara, não é genérica.
A comparação tem de receber a condição exata que está a ser testada.

Há duas formas de o fazer:

- As comparações de números inteiros recebem a condição como sufixo: `eq` para igualdade e `gt` para maior que.
  As outras variantes são construídas compondo o resultado de uma destas.
- As comparações de vírgula flutuante recebem a condição codificada num imediato.
  Valores diferentes deste imediato correspondem a condições diferentes que estão a ser testadas.

Além do uso de um sufixo condicional específico nas comparações de números inteiros, a sintaxe segue a mesma estrutura que já vimos:

- Para números inteiros, `p` + `cmp` + condição + tamanho (`b`, `w`, `d` ou `q`).
- Para vírgula flutuante, `cmp` + `p` + tamanho (`s` ou `d`).
  A condição é passada num imediato como operando extra.

### Comparações de números inteiros

Como foi referido, só existem comparações de números inteiros para igualdade e maior que:

| instrução | descrição |
| --- | --- |
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | igualdade por via |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | maior que **com sinal**, por via |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

Para criar uma comparação menor que, usa `gt` com os operandos trocados: `a < b` == `b > a`.

Repara que a comparação é **com sinal**.
Para efetuar uma comparação sem sinal, inverte o bit mais significativo de ambos os operandos.
Isto pode ser feito com um XOR com uma máscara em que só o bit mais significativo está a um.

~~~~exercism/note
Dois idiomas úteis são:

1. Fazer XOR de um registo com ele próprio para produzir todos os bits a zero.
2. Comparar um registo com ele próprio para produzir todos os bits a um.

Por exemplo:

```x86asm
pxor xmm4, xmm4    ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

Máscaras com todos os bits a zero e com todos os bits a um são comuns para codificar «falso em todo o lado» e «verdadeiro em todo o lado», respetivamente.
Também podem ser usadas para representar `0` empacotado ou `-1` empacotado, que são valores sentinela comuns.
Por exemplo, o NUL que marca o fim de uma string é um `0`.
~~~~

### Comparações de vírgula flutuante

As vias de vírgula flutuante usam uma forma diferente: uma instrução, `cmpps` (e `cmppd` para vias de 64 bits), com a condição num imediato:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

O NASM também tem pseudo-operadores que correspondem ao imediato correto e são mais fáceis de memorizar.
Em todos os seguintes, `x` em `px` pode ser `s` (números de vírgula flutuante de 32 bits) ou `d` (números de vírgula flutuante de 64 bits):

| pseudo-operador | imediato | comparação |
| --- | --- | --- |
| `cmpeqpx` | 0 | a == b |
| `cmpltpx` | 1 | a < b |
| `cmplepx` | 2 | a <= b |
| `cmpunordpx` | 3 | a é NaN ou b é NaN |
| `cmpneqpx` | 4 | a != b |
| `cmpnltpx` | 5 | a >= b |
| `cmpnlepx` | 6 | a > b |
| `cmpordpx` | 7 | nem a nem b é NaN |

## Selecionar com uma máscara

Uma máscara codifica o resultado de uma condição.
Pode depois ser usada para escolher, via a via, entre dois conjuntos de valores de acordo com essa condição.
Escolhemos a via de um valor onde a máscara é verdadeira, e de outro onde é falsa:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

Este padrão é a forma empacotada da seleção sem ramificações.
Todas as vias são calculadas, e é a máscara que decide sozinha qual o valor que sobrevive, sem qualquer `jcc`.

## Misturas dedicadas

Há instruções que efetuam essa mesma seleção diretamente, lendo um bit por elemento a partir de um registo de máscara.
São chamadas instruções de **mistura**:

| instrução | elemento | origem da máscara |
| --- | --- | --- |
| `pblendvb` | byte | `xmm0` implícito |
| `blendvps` | via de 32 bits | `xmm0` implícito |
| `blendvpd` | via de 64 bits | `xmm0` implícito |

Repara que a primeira instrução segue a sintaxe de números inteiros, enquanto as outras duas seguem a sintaxe de vírgula flutuante.
No entanto, como estas instruções apenas selecionam bytes em bruto, qualquer uma delas pode ser usada tanto com números inteiros como com números de vírgula flutuante.

Para cada elemento, a mistura mantém o destino quando o bit mais significativo do elemento correspondente da máscara está a zero, e escolhe a origem quando está a um.
Só esse **bit mais significativo** é consultado, o que uma máscara de comparação satisfaz, pois as suas vias são todos uns ou todos zeros.
O registo de máscara é sempre `xmm0`, que é implícito:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

Também é possível usar `pblendvb` para selecionar vias a partir de uma máscara de comparação para qualquer outro tamanho.
Como todos os bytes numa via verdadeira são todos uns, `pblendvb` seleciona todos eles.

~~~~exercism/note
Estas instruções acrescentam todas um `v` após a operação realizada (`blend`).
Este `v` significa _variável_, porque a seleção não é estática: depende de um registo.

Também existem variantes sem `v`, que selecionam de acordo com um imediato.
Seguem o mesmo padrão, selecionando uma via `i` se o bit `i` do imediato estiver a um.
~~~~

## De uma máscara de volta ao escalar

Embora seja poderoso, o código SIMD não tem grande parte da flexibilidade do código escalar.
Em muitas situações, é necessário passar de um registo empacotado de volta ao mundo das instruções escalares.

A família de instruções `movmsk` serve de ponte entre os dois mundos.
Estas instruções extraem o **bit mais significativo** de cada via para um registo de uso geral:

| instrução | recolhe | largura do resultado |
| --- | --- | --- |
| `pmovmskb` | bit mais significativo de cada um de 16 bytes | 16 bits |
| `movmskps` | bit mais significativo de cada um de 4 dwords | 4 bits |
| `movmskpd` | bit mais significativo de cada um de 2 qwords | 2 bits |

Se forem usadas após uma comparação, cada bit a um representa uma via «verdadeira» e cada bit a zero, uma via «falsa».
Este resultado pode depois ser manipulado como habitualmente com instruções escalares.
Por exemplo, um `popcnt` conta o número de correspondências, e um `tzcnt` encontra a primeira.

O registo de uso geral pode ter 32 ou 64 bits de largura.

## Testar um vetor completo

Existe também uma variante empacotada da instrução escalar `test`: `ptest`.

É semelhante à sua equivalente escalar, na medida em que efetua uma operação AND entre dois operandos, sem os modificar.
Ao contrário de `test`, `ptest` também efetua uma operação ANDN, negando o primeiro operando.

Assim, `ptest` pode ser visto como uma versão não destrutiva de `pand` e `pandn` que define sinalizadores de acordo com o resultado.
De forma semelhante a estas duas instruções, `ptest` trata todo o registo SIMD como uma única via e, por isso, não recebe um prefixo de tamanho.

Se o resultado de uma operação AND for `0`, o `ZF` é definido, e se a operação ANDN resultar em `0`, é o `CF` que é definido.
Isto significa que `ptest` pode ser usado para verificar tanto uma máscara com todos os bits a um como uma máscara com todos os bits a zero:

1. Usar `ptest` num registo com ele próprio define `ZF` apenas se o registo for todo a zeros.
   Isto imita o idioma escalar comum de usar `test` num registo com ele próprio para verificar se é `0`.
2. Usar `ptest` num registo com uma máscara com todos os bits a um define `CF` apenas se o registo for todo a uns.
   Além disso, define `ZF` apenas se o registo for todo a zeros, o que permite verificar ambas as máscaras de uma só vez.

```x86asm
pxor    xmm0, xmm0   ; all zeros
pcmpeqb xmm1, xmm1   ; all ones
pcmpeqb xmm2, xmm2

ptest xmm0, xmm0     ; ZF set: a register against itself detects all zeros
ptest xmm0, xmm1     ; ZF set, CF clear: xmm0 is all zeros, not all ones
ptest xmm2, xmm1     ; CF is set only if xmm2 is all ones
```

O resultado de um `ptest` pode ser usado para ramificar ou em instruções sem ramificações, como `setcc` ou `cmovcc`, como habitualmente.
