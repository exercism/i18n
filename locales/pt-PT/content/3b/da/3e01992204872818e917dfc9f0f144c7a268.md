# Inclusão de código

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

Um `include` copia o código de outra classe para esta. É uma operação em tempo de compilação, sem custo nem relação em tempo de execução: as duas classes deixam de estar ligadas depois disso.

## A cláusula

```
   include CLASS  old_name -> new_name , old_name -> ;
```

Cada entrada renomeia uma característica. `-> ;` sem um novo nome deixa-a de fora. Tudo o que não é mencionado entra sem alterações.

A renomeação aplica-se ao que o *exterior* vê. As chamadas entre as rotinas incluídas continuam a funcionar: se `describe` chama `count` e `count` é renomeado para `beats`, `describe` chama `beats`.

## Incluir várias

```sather
   include WARM_UP;
   include COOL_DOWN;
```

é permitido, e é assim que Sather obtém aquilo a que outras linguagens chamam herança múltipla, sem os problemas habituais, porque um conflito é um erro de compilação e a solução é renomear ou deixar uma de fora. Nada é resolvido por uma ordem de precedência que tenhas de memorizar.

## private include

```sather
   private include WARM_UP;
```

traz o código para uso da própria classe, sem o expor. Útil quando queres a implementação e não a interface.

## Os dois juntos

A forma habitual para uma família de classes:

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

`< $ACT` diz o que a classe sabe fazer; `include ACT_BASICS` fornece parte do como. Se mudares de ideias sobre o como, o `<` não se move.

## Porque é que se faz assim

Uma classe abstrata não tem código, por isso não pode ser herdada por acidente, e não existe uma superclasse cujo comportamento mude debaixo dos teus pés. A reutilização é uma cópia feita em tempo de compilação, a partir de uma classe que nomeaste, com todas as renomeações escritas.

O custo é que a reutilização tem de ser pedida explicitamente em cada classe. É essa a troca: mais para escrever, nada implícito.
