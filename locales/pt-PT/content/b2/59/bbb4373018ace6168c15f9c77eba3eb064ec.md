# Introdução

## Asserções let

Quando fazemos correspondência de padrões com um valor em Gleam, temos de garantir que os padrões correspondem a todos os valores possíveis do tipo; caso contrário, o código não compila.

Esta função deve ser rejeitada, pois não trata o caso em que a lista está vazia:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Na maioria das vezes, em programas em Gleam, queremos tratar todos os casos possíveis, mas em alguns programas, como protótipos e scripts rápidos, podemos querer focar-nos apenas no caminho principal e não escrever código para os outros casos. É aqui que entra o `let assert` do Gleam.

Com as asserções let, um padrão pode corresponder apenas a alguns dos valores possíveis de um tipo e, se o padrão não corresponder a um valor, o programa rebenta. Com `let assert`, podemos escrever a função acima assim:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

As bibliotecas Gleam nunca devem usar asserções let, pois podem fazer o programa rebentar. Em vez disso, devem usar o tipo `Result` e deixar o programador da aplicação decidir como tratar os erros.
