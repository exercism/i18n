# Introdução

Alguns ciclos não podem ser escritos como "faz isto para cada elemento de uma sequência". Tens de continuar até que alguma condição mude. O combinador `while` do Factor é a ferramenta para isso: uma quotation do predicado diz "continua?", uma quotation do corpo faz o trabalho de um passo, e o `while` repete até que o predicado devolva `f`.

## `while` e `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` e `body` são ambos quotations que operam na pilha de dados. O `while` continua a repetir enquanto `pred` deixa um valor verdadeiro; o `until` é o contrário: continua a repetir *até* que `pred` se torne verdadeiro (ou seja, enquanto `pred` deixa `f`).

Um único valor de estado pode fluir na pilha entre o predicado e o corpo:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

Traço: o predicado `dup 0 >` observa o contador em execução; o corpo `dup . 1 -` imprime-o e decrementa-o; o ciclo para assim que o contador atinge `0`. O `drop` no fim descarta esse último `0` da pilha.

## `while*`: manter o valor do predicado

```
while* ( pred body -- )
```

O `while` só se interessa se o seu predicado deixou um valor verdadeiro; descarta o próprio valor antes de executar o corpo. O `while*`, em vez disso, *entrega esse valor ao corpo*. Usa-o sempre que o teste e o corpo queiram a mesma coisa acabada de calcular: uma consulta, uma correspondência, um token analisado.

Aqui, cada nome aponta para o seguinte numa cadeia. O predicado procura o nome atual; desde que haja um nome seguinte, o `while*` passa-o ao corpo, que o imprime e continua a partir daí:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at` devolve o nome seguinte, ou `f` quando um nome não tem entrada. Enquanto devolve um nome, o `while*` dá esse nome a `dup .`, que o imprime e o deixa como chave para a próxima consulta. O primeiro `f` para o ciclo; o `while*` descarta-o, por isso não sobra nada.

## Vários valores de estado com variáveis locais

Quando o ciclo transporta mais do que um valor, por exemplo uma lista restante e um total acumulado, o malabarismo com a pilha torna-se confuso. O padrão mais limpo é declarar *variáveis locais* com `::`:

```
:: word ( inputs -- outputs ) ... ;
```

Dentro do corpo, `:> name!` adiciona uma variável local mutável; as leituras usam `name`, as escritas usam `name!` (que consome o novo valor da pilha e o atribui).

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

Duas variáveis locais aqui (`rest` e `running`) cobrem todo o estado do ciclo: o predicado inspeciona-as, o corpo atualiza-as, e o valor final é devolvido no fim.

`unclip ( seq -- rest first )` retira o primeiro elemento de uma sequência; é útil quando o ciclo quer consumir uma lista um elemento por iteração. A forma `[ rest! ] dip` atualiza `rest` para a cauda restante, deixando o elemento acabado de retirar na pilha para o corpo o usar.
