# Introdução ao redirecionamento

No mundo da interface de linha de comandos, os programas interagem muitas vezes com três fluxos de dados padrão:

1. **Entrada padrão** (`stdin`): onde um programa recebe a sua entrada (normalmente a partir do teclado).
1. **Saída padrão** (`stdout`): onde um programa envia a sua saída normal (normalmente para o ecrã do terminal).
1. **Erro padrão** (`stderr`): onde um programa envia mensagens de erro (normalmente para o ecrã do terminal).

Lembra-te de que os introduzimos no capítulo [Pipelines e Listas de Comandos][pipelines].

~~~~exercism/note

O redirecionamento do shell é um mecanismo poderoso que te permite mudar o destino destes fluxos.
Em vez de um programa ler a partir do teclado ou escrever para o ecrã, podes redirecionar a entrada de um ficheiro ou enviar a saída para um ficheiro.
Isto dá-te bastante flexibilidade e controlo sobre a forma como os programas interagem com os dados.

## Principais operadores de redirecionamento

Aqui estão os operadores de redirecionamento mais comuns e o que eles fazem:

### `>` (Redirecionamento da saída)

* Objetivo: redirecionar a saída padrão (`stdout`) de um comando para um ficheiro.
* Comportamento:
  * Se o ficheiro não existir, é criado.
  * Se o ficheiro existir, o seu conteúdo é substituído.
* Exemplo:

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
O redirecionamento é feito **antes** de o comando ser executado.
Isto significa que não podes redirecionar para o mesmo ficheiro de onde precisas de ler.

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

No segundo comando do exemplo acima,

1. O Bash começa por truncar o ficheiro indicado no redirecionamento.
   Isto destrói o conteúdo anterior, deixando um ficheiro vazio.
2. Depois o Bash lê o ficheiro, agora vazio.
3. Em seguida o Bash escreve o conteúdo (ou seja, nada) de volta no ficheiro.
~~~~

### `>>` (Redirecionamento da saída para acrescentar)

* Objetivo: acrescentar a saída padrão (`stdout`) de um comando a um ficheiro.
* Comportamento:
  * Se o ficheiro não existir, é criado.
  * Se o ficheiro existir, a saída é adicionada ao fim do ficheiro.
* Exemplo:

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<` (Redirecionamento da entrada)

* Objetivo: redirecionar a entrada padrão (`stdin`) de um comando a partir de um ficheiro.
* Comportamento: o comando lê a sua entrada a partir do ficheiro indicado em vez do teclado.
* Exemplo:

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>` (Redirecionamento do erro):

* Objetivo: redirecionar o erro padrão (`stderr`) de um comando para um ficheiro.
* Comportamento: as mensagens de erro são enviadas para o ficheiro indicado em vez do terminal.
* Exemplo:
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

Podes _acrescentar_ o erro padrão a um ficheiro com `2>>`.

### Redirecionamentos adicionais

Há também redirecionamentos que conseguem fundir tanto o `stdin` como o `stderr`.
Vê o [manual][manual] para mais detalhes.

## `/dev/null`

`/dev/null` é um ficheiro especial que

* é um ficheiro vazio quando lês a partir dele, e
* descarta todos os dados que lhe são escritos.

Por vezes, é também chamado de «bitbucket».
É útil para suprimir a saída ou os erros.

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## Combinar redirecionamentos

Podem ser indicados vários redirecionamentos ao mesmo tempo.

```bash
some_command < input.txt > output.txt 2> error.txt
```

Um redirecionamento pode ser copiado.

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

Quando vês `2>&1`, lê isso como «redireciona o stderr para _aquilo para que o stdout está a apontar **neste momento**_».
O Bash processa as instruções de redirecionamento estritamente da esquerda para a direita, o que significa que podes fazer:

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## Descritores de ficheiros

No contexto da programação de shell e de sistemas operativos como o Linux/Unix, um descritor de ficheiro (FD, de file descriptor) é um número inteiro não negativo que serve de identificador ou de referência para um ficheiro aberto ou um recurso de E/S (Entrada/Saída).
Pensa nele como uma etiqueta ou um número de referência que o sistema operativo usa para acompanhar os ficheiros abertos e os fluxos de dados.

Os números que vês do lado esquerdo dos redirecionamentos são descritores de ficheiros.

Aos fluxos de E/S padrão são atribuídos os três primeiros descritores de ficheiros:

* a entrada padrão é o FD 0
* a saída padrão é o FD 1
* o erro padrão é o FD 2

É possível definir ou criar novos descritores de ficheiros com o comando `exec` e os operadores de redirecionamento.

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

Esta técnica parece bastante complicada, mas pode ser muito útil em situações em que o teu script é executado por outro pacote de software e a saída padrão é capturada automaticamente por esse software.
O comando `bats`, que é usado para correr os testes unitários desta track, funciona assim: o `bats` captura o stdout e o stderr de um teste, mas as mensagens de depuração enviadas para o FD 3 são apresentadas no terminal.
~~~~

## Em resumo

Porque é que o redirecionamento é útil?

* Guardar a saída: guardar os resultados de um comando para os reveres ou processares mais tarde.
* Registos: capturar mensagens de erro para depuração.
* Automatização: encadear comandos, usando a saída de um como entrada de outro.
* Filtragem: descartar a saída indesejada.
* Processamento em lote: processar dados a partir de ficheiros em vez de os escreveres à mão.
* Scripts: os redirecionamentos são essenciais para escrever scripts de shell robustos.

Os redirecionamentos do shell dão-te um controlo preciso sobre a forma como os programas interagem com os dados, permitindo-te construir fluxos de trabalho complexos e gerir a informação de forma eficaz.
