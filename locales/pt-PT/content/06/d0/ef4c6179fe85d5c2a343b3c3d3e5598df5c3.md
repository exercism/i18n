# Testes
Uma forma de resolveres os exercícios do Exercism é acederes ao site e usares o editor no navegador, onde podes editar e testar a tua solução.

Em alternativa, podes descarregar os exercícios para o teu computador e usar o teu próprio editor, juntamente com um conjunto de ferramentas, para criar, testar e, por fim, submeter a tua solução.

Isto implica usar a interface de linha de comandos do Exercism, ou CLI, uma aplicação que corre dentro de um terminal ou de uma janela de linha de comandos. Podes encontrar as instruções de instalação aqui: [Documentação da CLI do Exercism](https://exercism.org/docs/using/solving-exercises/working-locally).

## Abordagem de testes
O Exercism assume alguma experiência com desenvolvimento orientado a testes. Cada exercício é composto por um _`stub file`_, um _`test file`_ que contém uma série de testes já escritos e um _`test script`_ usado para executar os testes.

Resolver um exercício exige que o _`stub file`_ seja desenvolvido de forma incremental, até conter código que venha a passar em todos os testes.

Na prática, isto significa que vais editar ativamente tanto o _`stub file`_ como o _`test file`_. Repara que o _`test file`_ é editado não para alterar o código dos testes, mas para comentar os testes que falham.

Inicialmente, todos os testes menos um estarão comentados; depois, à medida que o _`stub file`_ avança para uma solução funcional, vais descomentando mais testes até que todos passem.

## Infraestrutura de testes
Não precisas de instalar software adicional, uma vez que os componentes da framework de testes vêm incluídos quando descarregas o exercício.

A framework de testes é composta por três ficheiros Rexx que, na altura dos testes, são combinados com a solução do exercício para formar a unidade de código de teste; esta é depois executada pelo _`test script`_, e os resultados dos testes são impressos no terminal.

Não edites nem apagues o _`test script`_, nem qualquer outro ficheiro da framework de testes. Se os gremlins fizerem com que isto aconteça, volta a descarregar o exercício através da CLI do Exercism, tendo o cuidado de guardar o código da tua solução.

## Executar os testes
Resolver um exercício segue estes passos:

1. Abre um terminal
2. Descarrega o exercício escolhido
3. Entra no diretório do exercício
4. Carrega o stub file e o test file no teu editor
5. Iterativamente,

    1. Executa o test script
    2. Escreve código no teu stub file (transformando-o lentamente num ficheiro de solução) e comenta / descomenta testes no teu test file

6. Quando todos os testes passarem, submete a solução ao Exercism
7. Fecha o terminal
8. Celebra o teu sucesso

Um exemplo concreto num terminal Linux, com o exercício `acronym` (assume que o espaço de trabalho do exercism é: `/home/exercism`)

Descarrega o exercício:

`exercism download --track=rexx --exercise=acronym`

Entra no diretório do exercício:

`cd /home/exercism/rexx/acronym`

De outra janela, talvez uma interface gráfica, carrega no teu editor o `acronym.rexx` e o `acronym-check.rexx`, que são, respetivamente, o stub file e o test file.

Executa o test script: `./test-acronym`

e todos os testes devem falhar:

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Comenta todos os testes menos o primeiro no ficheiro `acronym-check.rexx` e volta a executar o test script; deves obter o seguinte resultado:

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

Volta a trabalhar o `acronym.rexx` até conter código funcional e, mais tarde, a saída da execução do test script deve ser:

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

Descomenta então os outros testes, volta a executar o test script e, por fim, a saída deve ser:

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Já podes submeter a solução do teu exercício:

`exercism submit acronym.rexx`

e ganhar mais um ponto de reputação. Fecha o terminal quando terminares.

O processo para quem usa MacOS seria bastante semelhante, uma vez que é um sistema operativo derivado do UNIX.

O processo para quem usa Windows é, em geral, semelhante, mas há algumas pequenas diferenças:

- A janela _Command Prompt_ é o terminal
- As barras invertidas substituem as barras nos caminhos, por isso o diretório de trabalho pode ser:

  `cd C:\Users\MyName\exercism\rexx\acronym`

- A execução do test script é feita assim:

  `test-acronym`  ou  `test-acronym.bat`

A saída dos testes será idêntica.
