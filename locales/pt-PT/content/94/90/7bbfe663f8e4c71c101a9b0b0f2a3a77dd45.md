# Construir um test runner

O test runner é uma ferramenta essencial que permite:

- Que o site verifique automaticamente se uma iteração passa em todos os testes.
- Que os estudantes resolvam exercícios com o [editor no navegador](/docs/using/solving-exercises/using-the-online-editor) ([sem precisar de CLI](/docs/using/solving-exercises/working-locally)).

Para começares a construir um test runner, consulta o documento [Criar um test runner de raiz](/docs/building/tooling/test-runners/creating-from-scratch).

## Implementação

As ferramentas de um track são normalmente (na sua maioria) escritas na linguagem desse track.

```exercism/caution
Embora sejas livre de usar outras linguagens, cada linguagem adicional torna mais difícil manter o track ou contribuir para ele.
Por isso, recomendamos que uses a linguagem do track sempre que possível, porque torna a manutenção e a contribuição mais fáceis.
```

## Publicação

O test runner é empacotado e executado como um [contentor Docker](/docs/building/tooling/docker).
As imagens Docker do test runner são publicadas automaticamente através de um [fluxo de trabalho do GitHub Actions](https://github.com/exercism/generic-test-runner/blob/main/.github/workflows/docker.yml).

## Testes

Depois de construíres um test runner, podes usar a sua imagem Docker na configuração de CI do teu track para verificares os exercícios do track.
A principal vantagem desta abordagem é que imita melhor o ambiente de produção; por outras palavras, podes ter mais confiança de que as coisas também funcionam em produção.
Uma possível desvantagem é que pode tornar o fluxo de trabalho de CI mais lento.
Cabe-te a ti, que manténs o track, decidir qual das abordagens funciona melhor para o teu track.
