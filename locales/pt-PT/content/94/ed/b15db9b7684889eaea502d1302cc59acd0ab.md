# Introdução

O Elixir disponibiliza uma construção para resgatar erros usando `try .. rescue`

```elixir
try do
  raise RuntimeError, "error"
rescue
  e in RuntimeError -> :error
end
```

Vamos analisar esta construção:

- **Linha 1**, o bloco é declarado com `try`.
- **Linha 2**, a chamada da função que pode dar erro é colocada aqui, neste caso estamos a chamar `raise/2`.
- **Linha 4**, na secção `rescue`, fazemos correspondência de padrões com o nome do _módulo_ do erro lançado
  - no lado esquerdo de `->`:
    - `e` é associado à struct de erro.
    - `in` é uma palavra-chave.
    - `RuntimeError` é o erro que queremos resgatar.
      - Se quiséssemos resgatar todos os erros, podíamos usar `_` em vez do nome do módulo ou omitir completamente a palavra-chave `in`.
  - no lado direito:
    - as instruções a executar se o erro corresponder.

## Structs de erro

Os erros (por vezes também chamados "exceções") que resgatas desta forma são structs.
Resgatar erros em Elixir é algo que se faz muito raramente.
Normalmente, o erro resgatado é registado ou enviado para um serviço externo de monitorização e, em seguida, volta a ser lançado.
Isto significa que, normalmente, não nos preocupamos com a estrutura interna da struct de erro em concreto.

No [conceito de exceções][exercism-exceptions] vais aprender mais sobre structs de erro, incluindo como definir o teu próprio erro personalizado.
