# Instruções

Estás a escrever firmware para o sistema de pontuação de uma consola portátil retro.
O CPU da máquina é modesto e o ecrã das pontuações atualiza-se a uma taxa fixa.
Para que a imagem se mantenha fluida, as rotinas de pontuação têm de correr num número previsível de ciclos, independentemente do que o jogador esteja a fazer.

Tens quatro tarefas.

~~~~exercism/note
O código das tarefas deve ser sem ramificações.
Usa `cmovcc`, `setcc` e aritmética em vez de saltos condicionais.
~~~~

## 1. Adicionar um bónus sem transbordar o ecrã

A região de pontuação do LCD da consola tem espaço para seis algarismos decimais.
Não consegue mostrar nenhum número acima de `999999`.
Quando um bónus faria ultrapassar esse limite ao total acumulado, o total apresentado é mantido no máximo em vez de dar a volta.

Define uma função `add_bonus` que, dados um total atual e um bónus a adicionar, devolve o novo total limitado a `999999`.
Os argumentos, por ordem, são:

1. `total`: o total de pontuação atual (sempre entre `0` e `999999`)
2. `bonus`: o bónus a adicionar (sempre não negativo)

O valor devolvido é `total + bonus` se essa soma for menor ou igual a `999999`, e `999999` caso contrário:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

Tanto os argumentos como o valor devolvido são inteiros de 64 bits com sinal.

~~~~exercism/note
Podes assumir que `total + bonus` não provoca transbordo num inteiro de 64 bits com sinal.
~~~~

## 2. Comparar duas pontuações

A consola guarda no seu ficheiro de gravação uma pequena tabela de classificação com as melhores pontuações recentes do jogador.
Depois de cada partida, a nova pontuação é inserida na tabela de classificação na posição correta.
A rotina de ordenação pergunta qual das duas pontuações está à frente e espera a resposta como um pequeno inteiro.

Define uma função `compare_scores` que, dadas duas pontuações, devolve:

- `+1` se a primeira pontuação for _superior_
- `-1` se a primeira pontuação for _inferior_
- `0` se as duas pontuações forem _iguais_

Exemplo:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

Tanto os argumentos como o valor devolvido são inteiros de 64 bits com sinal.

## 3. Validar uma pontuação em bruto

A consola pode ligar-se a outra unidade através do seu cabo de ligação para partilhar pontuações depois de uma partida multijogador.
O cabo tem ruído elétrico e os bytes recebidos corrompem-se ocasionalmente, produzindo valores muito abaixo do mínimo permitido ou muito acima do máximo permitido.
O validador limita cada pontuação recebida ao intervalo permitido antes de o resto do sistema a ver.

Define uma função `validate_score` que, dada uma pontuação em bruto e os limites permitidos, devolve a pontuação limitada a `[min, max]`.
Os argumentos, por ordem, são:

1. `score`: a pontuação em bruto recebida através do cabo de ligação
2. `min`: a menor pontuação permitida
3. `max`: a maior pontuação permitida

O valor devolvido é `min` se `score < min`, `max` se `score > max`, e `score` caso contrário.
Podes assumir que `min <= max`.

Exemplo:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

Todos os argumentos e o valor devolvido são inteiros de 64 bits com sinal.

## 4. Acompanhar as duas pontuações mais altas

No final de cada sessão de jogo, a consola percorre o registo de partidas recentes no seu ficheiro de gravação para encontrar as duas pontuações mais altas alguma vez registadas.
O registo é um array simples de inteiros de 64 bits com sinal em memória.
A pesquisa percorre o array uma vez e mantém dois máximos em curso: o mais alto visto até agora e o segundo mais alto.

Nota que ambos os números devem ser pelo menos `0`.
Qualquer número negativo é ignorado.

Uma primeira versão da função foi escrita com saltos condicionais em cascata.
Para cada candidato, o código pergunta onde ele se encaixa (acima do primeiro, entre o primeiro e o segundo, ou em lado nenhum) e ajusta os máximos em curso em conformidade, descartando qualquer resultado negativo.

Isto funciona.
No entanto, como os valores de entrada são aleatórios, cada salto condicional dá origem a muitas falhas de previsão de ramificação.
É por isso que decidiste refatorar o ciclo principal para ficar sem ramificações.

Abaixo está a função com a secção com ramificações comentada:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

Substitui a secção comentada por uma implementação sem ramificações.
O único salto permitido no novo código é o que salta de volta para o início do ciclo para verificar um novo elemento do array.

A função não tem valor devolvido e recebe os mesmos argumentos que a versão com ramificações:

1. `out`: buffer de saída onde a função vai escrever as duas pontuações não negativas mais altas, por ordem decrescente, como inteiros de 64 bits com sinal
2. `array`: array de entrada de inteiros de 64 bits com sinal
3. `length`: o número de elementos do array, como inteiro sem sinal de 64 bits

~~~~exercism/note
Se o array contiver valores duplicados, os duplicados podem aparecer nas duas posições de saída se forem as duas pontuações mais altas.
~~~~
