# Sobre

As funções recursivas são funções que se chamam a si próprias.

Uma função recursiva tem de ter pelo menos um _caso base_ e pelo menos um _caso recursivo_.

Um _caso base_ devolve um valor sem voltar a chamar a função.
Um _caso recursivo_ volta a chamar a função, modificando o valor de entrada para que este acabe por corresponder ao caso base.

Em Elm, as funções recursivas são habitualmente definidas com correspondência de padrões, através de expressões `case`.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

Uma função recursiva pode ter vários casos base e/ou vários casos recursivos.
Por exemplo, [a sequência de Fibonacci][fibonacci] é uma sequência recursiva com dois casos base:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

Repara que esta implementação em particular é exponencialmente lenta, uma vez que os números de Fibonacci relacionados são calculados de raiz em duas chamadas recursivas independentes.

Contar o número de ocorrências de um determinado valor `x` numa lista tem dois casos recursivos:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## Ciclos através da recursão

Devido à imutabilidade, os ciclos em Elm escrevem-se de forma diferente das linguagens imperativas.
Por exemplo, é comum os ciclos terem este aspeto:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

Numa linguagem funcional como Elm, não é possível alterar variáveis.
Por isso, os ciclos têm de ser implementados com recursão.

O equivalente a um ciclo `for` em Elm seria assim:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

Na prática, percorrer listas e outras estruturas de dados em Elm faz-se quase sempre com funções do módulo [`List`][module-list], como `List.map`, `List.filter` e `List.foldl`.
Nos bastidores, estas funções são implementadas com recursão.

## Execução infinita

As funções recursivas, se forem implementadas incorretamente ou tiverem um número demasiado elevado de chamadas recursivas, podem nunca devolver o seu resultado.
Isto pode ser problemático porque, cada vez que uma função é chamada, é guardada em memória uma referência ao local para onde o ambiente de execução deve devolver o resultado (na [pilha de chamadas][wiki-call-stack]).
Se uma função recursiva se chamar a si própria demasiadas vezes ou mesmo infinitamente, é possível ficar sem memória, o que faz o ambiente de execução falhar (um [erro de transbordo de pilha][wiki-stack-overflow]).
O ambiente de execução do Elm está otimizado para a recursão e para a fiabilidade, mas a recursão infinita ainda pode causar problemas.

Este problema de execução infinita pode ser causado por:

- Esquecer-se de implementar um caso base.
- Não tratar todos os casos possíveis na correspondência de padrões.
- Não modificar o argumento corretamente ao fazer a chamada recursiva, nunca chegando por isso ao caso base.
