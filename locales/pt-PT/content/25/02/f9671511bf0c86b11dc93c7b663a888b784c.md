# Introdução

Em muitas linguagens orientadas a objetos, é comum estender comportamentos [criando subclasses][wiki-subclass] de uma classe progenitora, herdando métodos da classe mãe e acrescentando outros novos.
Assim obtemos uma hierarquia de objetos.

A Julia _não tem classes_, logo, por extensão, _não tem subclasses_.
Como é que herdamos e estendemos comportamentos já existentes?

Em conceitos anteriores, vimos como criar uma hierarquia de tipos e também como a Julia usa [multiple dispatch][concept-multiple-dispatch] para escolher métodos com base nos tipos dos argumentos.

A Julia tem também várias interfaces informais, que permitem que os teus tipos personalizados se liguem a comportamentos já definidos para os tipos padrão.

A melhor forma de ilustrar isto é com a interface de iteradores.

## Iteradores

Anteriormente, no programa, vimos várias formas de a Julia operar sobre cada elemento de uma coleção.

- [Ciclos][concept-loops], como `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Funções de ordem superior][concept-hof]: `map(√, [1, 4, 9])`
- [Compreensões][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Geradores][concept-comprehensions]: `(x^2 for x in 1:1e6)`, que é avaliado de forma preguiçosa.

É evidente que a Julia sabe percorrer coleções padrão item a item: vetores e intervalos nos exemplos acima, e também Sets, Dicts, etc.

Como é que acrescentamos esta capacidade às nossas próprias coleções personalizadas, sobretudo se puderem ser iteradas de forma preguiçosa como um gerador?

### Requisitos mínimos

Para criar uma sequência para iteração, precisamos de (pelo menos) duas coisas:

1. Uma forma de obter o _primeiro_ item.
2. Uma forma de obter o item _seguinte_ a partir do estado atual.

A Julia realiza estas tarefas com métodos da função `Base.iterate()`, seguindo estes passos:

1. `Base.iterate(iter)` é chamada automaticamente primeiro.
    - Se não houver nada para iterar, devolve `nothing`.
    - Caso contrário, devolve o `Tuple` do primeiro item devolvido e do primeiro estado: `(firstitem, firststate)`.
2. `Base.iterate(iter, state)` é chamada automaticamente se um item foi devolvido na iteração anterior, recebendo `firststate` como argumento `state`.
    - Se a iteração terminar, devolve `nothing`.
    - Caso contrário, devolve o `Tuple` do item seguinte e do estado seguinte: `(nextitem, nextstate)`.
3. Repete o passo 2 até à terminação.

Todos estes passos acontecem «nos bastidores»: as chamadas aos métodos e o estado são geridos internamente pelo protocolo de iteração (e o estado permanece opaco), ficando apenas o item exposto a construções de alto nível, como os ciclos.
Por outras palavras, só vemos o `item`; tudo o resto permanece numa caixa negra.

O [multiple dispatch][concept-multiple-dispatch] é central nisto.
O tipo de `iter` determina que métodos são chamados, e o número de argumentos determina se é devolvido o primeiro item ou o item seguinte.

Os métodos para os tipos padrão já estão definidos: `Vector`, `Range`, `Set`, etc. ([atualmente][ref-iterations-collections] 14 tipos no total).

Para que um `MyType` personalizado partilhe os mesmos comportamentos, precisamos primeiro de definir:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Tudo isto pode parecer confuso em abstrato, mas pode ser bastante simples.
Para ilustrar, imagina que queremos um tipo que dê as potências de um determinado inteiro `n`, até um número máximo de termos.

Primeiro, define um tipo personalizado:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Agora já podemos definir os métodos `iterate` para este tipo, mas quais são o primeiro item e o primeiro estado?

Para obter o primeiro item, alguns iteradores precisam de uma preparação complicada, mas neste caso simples reparamos que o primeiro item devolvido é apenas o número base, por isso basta verificar se o valor de `count` é maior ou igual a um.

Vejamos agora o primeiro estado, que transporta informação usada na iteração seguinte.
Cabe-te a ti decidir que informação precisas de acompanhar para o fazer, e pode ser de qualquer tipo.

Neste caso, podíamos limitar-nos a acompanhar o «índice» a que elevamos `n`, ou podemos encontrar uma opção com melhor desempenho usando a potência mais recente de `n` (isto é, o item devolvido) e o «índice» seguinte na sequência.
Estes dois números podem ser envolvidos num `Tuple` e devolvidos como o `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

Neste exemplo, o primeiro item (`p.n`) é devolvido ao ciclo e o primeiro estado `(p.n, 2)` é passado ao método `iterate(P::Powers, state)`.
Aí podemos processar o estado para produzir o item seguinte, multiplicando o item atual pelo número base e aumentando assim a sua potência em `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Se o valor do índice ainda estiver dentro de `count`, o `Tuple` é devolvido com o item `next` e o `Tuple` de estado incrementado.
Quando o valor de `index` ultrapassa `count`, devolve-se antes `nothing`, para indicar que a iteração terminou.

Talvez tenhas reparado que os métodos `iterate(p::Powers)` e `iterate(p::Powers, state)` têm corpos de função bastante semelhantes.
Na verdade, se formos espertos, esta semelhança permite uma implementação mais simples, usando apenas a versão de dois argumentos com um argumento predefinido para o estado: `Base.iterate(p::Powers, state=(1, 1))`
Com isso, já não precisaríamos do método separado de um só argumento `iterate(p::Powers)`.
Na prática, isto é algo que se faz frequentemente quando é possível.

Até agora já temos algumas funcionalidades úteis: para as primeiras 4 potências de 3, podemos percorrer os resultados num ciclo, verificar se um determinado número está nos resultados e aplicar funções de agregação como `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Métodos adicionais

Apesar deste bom começo, ainda nem tudo funciona.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Com efeito, `length(Powers(3, 4))` dá exatamente a mesma mensagem de erro.

Isto corrige-se facilmente, pois o comprimento faz parte do construtor do tipo: 4, neste caso.
Basta definir `Base.length()` para este tipo e depois já podemos usar compreensões e `collect()` na sequência.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Por uma questão de eficiência, o melhor é definir também `Base.eltype()`: o tipo dos elementos do resultado.
Isto permite que funções como `collect()` reservem antecipadamente espaço para o `Vector{Int}` de saída, em vez de fazerem repetidamente um `push!()` para um `Vector{Any}`.

Repara na sintaxe, que podes nunca ter visto antes: este método é definido no _tipo_, e não numa _instância_ do tipo.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Não é _obrigatório_ que os iteradores tenham um comprimento finito.
O uso de sequências «infinitas» é mais limitado, mas percorrê-las num ciclo pode ser útil desde que haja alguma forma de sair do ciclo com `break`.
Por exemplo, podíamos definir uma variante de `Powers` que gerasse valores menores do que um determinado limite (talvez `typemax(Int)`, para evitar o overflow dos inteiros).

## Resumo

As interfaces são bastante confusas de explicar, porque a abordagem da Julia é muito diferente da da maioria das outras linguagens.
Em particular, o nome da interface pode nunca ser mencionado na implementação, ao contrário do que acontece com [a criação de subclasses][wiki-subclass] ou com [mixins][wiki-mixins].

No entanto, na prática são surpreendentemente simples:

1. Define um tipo adequado.
2. Descobre que métodos são necessários.
3. Implementa esses métodos para o teu tipo personalizado; normalmente são apenas alguns métodos, bastante curtos e simples.
4. Deixa o [multiple dispatch][concept-multiple-dispatch] tratar do resto, automaticamente.
