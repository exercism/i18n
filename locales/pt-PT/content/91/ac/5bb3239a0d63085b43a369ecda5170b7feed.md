# Ordenação

```sather
   numbers.sort;                                  -- the natural order
   words.insertion_sort_by(bind(before(_, _)));   -- an order you supply
```

## O que a sort precisa

A `sort` exige que o tipo dos elementos tenha `is_lt`. `INT`, `STR`, `CHAR`,
`FLTD` e `INTI` têm-no todos. Uma classe tua não o tem, até escreveres um.

A `insertion_sort_by` não exige nada do tipo dos elementos: tudo o que
precisa de saber está na rotina que lhe passas.

## O que uma comparação tem de ser

A rotina tem de definir uma ordem consistente; caso contrário, o resultado
não fica definido:

- se `before(a, b)` for verdadeiro, então `before(b, a)` tem de ser falso;
- se `a` vem antes de `b` e `b` antes de `c`, então `a` vem antes de `c`;
- `before(a, a)` tem de ser falso.

É a última que costuma apanhar as pessoas. Escrever `<=` em vez de `<` diz
que uma coisa vem antes de si própria, e uma ordenação feita assim pode dar
o que quer que seja.

## Empates

Nem a `sort` nem a `insertion_sort_by` são **estáveis**: as coisas que a
comparação considera iguais podem sair em qualquer ordem e, nesta
biblioteca, saem geralmente ao contrário.

Por isso, o truque de ordenar duas vezes, primeiro por nome e depois por
pontos, à espera que as equipas com os mesmos pontos fiquem por ordem
alfabética, não funciona aqui. Nem vale a pena contar com a ordem de entrada
para coisa alguma.

Se os empates forem importantes, resolve-os **na comparação**. Faz dela uma
ordem total, para que nunca duas coisas diferentes sejam consideradas
iguais:

```sather
   shorter(a, b : STR) : BOOL is
      if a.size /= b.size then return a.size < b.size; end;
      return a < b;                  -- same length: alphabetical
   end;
```

Vale a pena fazê-lo mesmo quando pensas que não pode haver empates. Uma
comparação que responde falso nos dois sentidos deixa o resultado
indefinido, e o bug manifesta-se como uma ordem que muda sem razão visível.

## Os outros

| Chamada | O que faz |
| --- | --- |
| `a.sort` | no local, ordem natural, não estável |
| `a.insertion_sort_by(lt)` | no local, a tua ordem, estável |
| `a.is_sorted` | verificação |
| `a.is_sorted_by(lt)` | verificação segundo a tua ordem |
| `a.binary_search(e)` | procura, num array ordenado |
| `a.binary_search_by(e, lt)` | procura, segundo a tua ordem |

A `binary_search` num array não ordenado não falha: responde disparates.
A sua pré-condição diz isso mesmo, e as pré-condições não são verificadas
a menos que se dê `-chk` ao compilador.

## Custo

A ordenação por inserção faz um trabalho proporcional ao quadrado do
comprimento, o que serve para uma classificação de uma dúzia de equipas e
não serve para dez mil registos. `ARR_SORT_ALG::sort_by` é a versão
quicksort da mesma ideia, para quando o array é grande e a estabilidade não
importa.
