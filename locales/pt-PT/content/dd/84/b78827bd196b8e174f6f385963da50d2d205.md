# Introdução

Os ponteiros inteligentes são uma funcionalidade moderna do C++ concebida para proporcionar uma gestão automática de memória, ajudando a evitar as fugas de memória e os ponteiros pendentes habitualmente associados aos ponteiros brutos.
Funcionam como invólucros em torno dos ponteiros brutos, acrescentando funcionalidades extra, como a libertação automática de memória quando o ponteiro já não é necessário.

## Sintaxe geral

Os ponteiros inteligentes são normalmente implementados como templates de classe na biblioteca padrão do C++.
Os dois ponteiros inteligentes mais utilizados são `std::unique_ptr` e `std::shared_ptr`.

## Ponteiros únicos

`std::unique_ptr` é um ponteiro inteligente que detém a propriedade exclusiva do objeto.
Garante que, em qualquer momento, apenas um objeto `std::unique_ptr` é dono do recurso.
Quando o `std::unique_ptr` que detém a propriedade é destruído ou reiniciado, destrói automaticamente os objetos e liberta a memória.

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## Vantagens de `std::make_unique()`

Quando crias um `std::unique_ptr`, é preferível usar `std::make_unique()` em vez de usares diretamente `new` para alocar memória.
`std::make_unique()` oferece várias vantagens:
1. **Segurança face a exceções**: `std::make_unique()` garante segurança face a exceções.
  Se for lançada uma exceção durante a construção do objeto, a memória é libertada automaticamente, o que evita fugas de memória.
2. **Clareza**: usar `std::make_unique()` torna o código mais claro e mais conciso.
  Elimina a necessidade de especificar explicitamente o tipo que está a ser alocado, uma vez que os argumentos do template são deduzidos automaticamente.
3. **Oportunidades de otimização**: os compiladores têm a oportunidade de otimizar `std::make_unique()` de forma mais eficaz do que a alocação manual de memória com `new`, o que pode resultar num melhor desempenho.
4. **Evitar utilizações indevidas**: é possível eliminar o recurso subjacente quando o `std::unique_ptr` é construído manualmente.
  Isso daria origem a comportamento indefinido quando o `std::unique_ptr` tentasse eliminá-lo ao chegar ao fim do âmbito.

## Ponteiros partilhados

`std::shared_ptr` é um ponteiro inteligente que permite que vários objetos `std::shared_ptr` partilhem a propriedade do mesmo recurso.
Mantém o registo de quantos ponteiros partilhados estão a referenciar o recurso e só liberta a memória quando o último ponteiro partilhado que detém o recurso sai do âmbito ou é reiniciado.

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
Em C++17 e anteriores, não há suporte direto para usar `std::shared_ptr` com arrays através de `std::make_shared<T[]>`.
Embora seja possível alocar arrays com `std::make_shared<T[]>`, criar ponteiros partilhados diretamente a partir deles pode dar origem a comportamento indefinido, devido a diferenças na gestão de memória entre objetos individuais e arrays.
Em vez disso, considera usar `std::vector` ou funções de eliminação personalizadas para gerir arrays com ponteiros partilhados de forma eficaz.
Ao lidar com alocações de arrays e ponteiros partilhados em C++17, garante sempre a compatibilidade com o teu compilador e com a implementação da biblioteca padrão.
~~~~

## Vantagens de `std::make_shared()`

À semelhança de `std::make_unique()`, `std::make_shared()` oferece vantagens como uma melhor eficiência de memória, segurança face a exceções e legibilidade.
Combina a alocação de memória para o bloco de controlo e para o objeto gerido numa única operação, o que aumenta a eficiência e reduz o risco de fugas de memória.
Além disso, a dedução automática dos argumentos do template simplifica o código e melhora a legibilidade.
Usar `std::make_shared()` promove um código mais limpo, mais seguro e mais eficiente quando trabalhas com objetos `std::shared_ptr` em C++.

## Ponteiros fracos

`std::weak_ptr` é uma classe complementar de `std::shared_ptr` que fornece uma referência "fraca" sem propriedade a um objeto gerido por um ponteiro partilhado.

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

Os ponteiros fracos são úteis em cenários em que é preciso quebrar referências cíclicas para evitar fugas de memória.
`std::weak_ptr` foi concebido para resolver o problema da propriedade cíclica, também conhecida como referências circulares, que pode ocorrer ao usar `std::shared_ptr`.
Num cenário de propriedade cíclica, dois ou mais objetos `std::shared_ptr` referenciam-se mutuamente, criando um ciclo em que nenhum dos objetos pode ser eliminado, porque todos têm referências fortes uns aos outros, o que dá origem a fugas de memória.
`std::weak_ptr` resolve este problema ao permitir referências fracas a objetos partilhados sem contribuir para a sua contagem de referências.
Isto significa que consegue observar e aceder ao objeto partilhado, mas não impede que este seja eliminado.
~~~~

## Conselhos de utilização

Usa ponteiros inteligentes por predefinição: `std::unique_ptr` para propriedade exclusiva e `std::shared_ptr` para propriedade partilhada.
Reserva os ponteiros brutos para referências sem propriedade ou para interagir com código legado.
Na maioria dos casos, `std::unique_ptr` é suficiente para a propriedade exclusiva, pois oferece uma gestão de memória leve, sem a sobrecarga da contagem de referências.
`std::shared_ptr` deve ser usado com moderação, pois introduz sobrecarga e complexidade, a menos que seja mesmo necessária propriedade partilhada.
`std::weak_ptr` é especializado em quebrar dependências cíclicas ou observar objetos partilhados, mas não é usado com frequência.
