# Sobre

## Introdução

Os genéricos são uma funcionalidade da linguagem que permite reutilizar código.
Por exemplo, não deve importar que tipo de valores é que uma lista guarda para calcular o seu comprimento.
É por isso que a função `length` usa um parâmetro de tipo genérico `a` na sua assinatura de tipo.

```elm
length : List a -> Int
```

## Parâmetros em tipos

Quando um tipo é genérico em relação a outro tipo, usamos um nome em minúsculas para esse outro tipo e chamamos-lhe parâmetro de tipo.
Exemplos comuns são os tipos personalizados `List`, `Maybe` e `Result`.

```elm
-- Maybe is generic over the type a
type Maybe a
    = Nothing
    | Just a

someString : Maybe String
someString = Just "hello"

someInt : Maybe Int
someInt = Just 42
```

Uma observação importante sobre os nomes dos parâmetros de tipo é que podem ter vários carateres.
A única restrição é que têm de ser nomes em minúsculas.
Por isso, quando é útil, tendemos a dar-lhes nomes descritivos.

Um tipo pode ser genérico em relação a vários outros tipos e, por isso, ter vários parâmetros de tipo.
Nesse caso, cada tipo independente recebe um nome diferente em minúsculas.
O facto de serem independentes não impede que se tornem o mesmo tipo, apenas permite que sejam diferentes.

```elm
-- Result is generic over the types error and value
type Result error value
    = Ok value
    | Err error
```

Os aliases de tipo de registo também podem ter parâmetros de tipo, embora seja menos comum.

```elm
-- Event is generic over the type a
type alias Event a =
    { at : Time
    , data : a 
    }
```

> É por isso que o pacote `Html` define o tipo `Html msg`, com um parâmetro de tipo chamado `msg`.
> A arquitetura Elm orienta-te no sentido de criar um tipo personalizado `Msg` que descreve todas as mensagens que a tua página web pode desencadear.
> Como resultado, o teu código vai construir vistas do tipo `Html Msg`, em que `Msg` é o tipo concreto que definiste.
> Os principiantes às vezes confundem os erros que mencionam `Html msg` (minúsculas) com os erros com `Html Msg`.
> Agora já sabes!
> A diferença é que o primeiro é genérico em relação a qualquer tipo `msg`, enquanto o segundo é específico do teu tipo `Msg`.

## Parâmetros de tipo em funções

Uma vez que os tipos podem ser genéricos, as funções também podem.
Podem escrever-se funções que lidam com tipos genéricos, como a `Maybe.withDefault`.

```elm
withDefault : a -> Maybe a -> a
withDefault default maybe =
    case maybe of
      Just value -> value
      Nothing -> default
```

As funções que recebem outras funções como parâmetros chamam-se funções de ordem superior, e estas também podem ser genéricas.

```elm
map : (a -> b) -> Maybe a -> Maybe b
map function maybe =
  case maybe of
    Just value ->
      Just (function value)

    Nothing ->
      Nothing
```

Os parâmetros de tipo podem aparecer tanto nos parâmetros de entrada como na saída de uma função, e à genericidade proporcionada pelos parâmetros de tipo chama-se habitualmente **polimorfismo paramétrico**.
Isto contrasta com o polimorfismo ad hoc, também conhecido como sobrecarga de funções, em que o mesmo nome de função pode ser usado em várias implementações em que os tipos diferem.
Também contrasta com o polimorfismo de subtipos, em que os tipos podem ser definidos numa hierarquia e as funções definidas para um tipo também podem ser chamadas com argumentos dos seus subtipos.
Em Elm, o único mecanismo de genericidade disponível é o polimorfismo paramétrico.
