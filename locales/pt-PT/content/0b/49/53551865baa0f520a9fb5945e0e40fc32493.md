# Introdução

Um *sinaleiro* a bordo de uma embarcação de patrulha costeira mantém o registo de mensagens. As bandeiras de sinais em bruto chegam enquadradas com carateres marcadores. As leituras têm de ser preparadas para transmissão. Os pares e trios de observações são resumidos à medida que surgem. Alguns idiomas da biblioteca padrão do Factor fazem a maior parte do trabalho.

## `unparse`: do valor ao texto de origem

[`unparse`][unparse] (em `prettyprint`) devolve o texto de origem de qualquer valor:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` é o inverso do parser: o percurso de ida e volta `dup unparse parse` reconstrói o valor. É a ferramenta certa para serializar para um formato de transmissão que o recetor voltará a analisar, e a ferramenta errada para produzir saída legível por humanos (as strings mantêm as aspas, os vetores mantêm o seu `V{ ... }`, etc.).

## Variantes de slice: vistas, não cópias

`head` e `tail`, de `sequences`, *copiam* a parte que manténs para uma sequência nova. As suas equivalentes `-slice` devolvem um objeto `slice`, um tuplo que contém o índice inicial, o índice final e a sequência subjacente, e que implementa o [protocolo de sequência][sequence-protocol] sem copiar:

| palavra       | efeito                                              |
|---------------|-----------------------------------------------------|
| `head`        | `( seq n -- newseq )` — copia os primeiros n        |
| `head-slice`  | `( seq n -- slice )` — vista dos primeiros n        |
| `tail`        | `( seq n -- newseq )` — copia a partir do índice n  |
| `tail-slice`  | `( seq n -- slice )` — vista a partir do índice n   |
| `head*`       | `( seq n -- newseq )` — copia tudo menos os últimos n |
| `head-slice*` | `( seq n -- slice )` — vista de tudo menos os últimos n |
| `tail*`       | `( seq n -- newseq )` — copia os últimos n          |
| `tail-slice*` | `( seq n -- slice )` — vista dos últimos n          |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

Um `slice` *é* uma sequência, por isso tudo o que recebe uma sequência recebe um slice: `length`, `first`, `each` e afins funcionam todos sem copiar. Os testes que precisem de comparar com uma string literal podem converter com `>string`.

## `?head` e `?tail`: retirar um marcador, se existir

As leituras enquadradas trazem texto marcador que pode ou não estar presente. `?head` e `?tail` (em `splitting`) tentam retirar um prefixo ou sufixo, devolvendo a sequência (possivelmente encurtada) *e* um boolean que indica se o marcador foi encontrado:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

O boolean final torna-os uma escolha natural para uma guarda: combina `?head` com `if` para ramificar conforme o enquadramento estava presente ou não, ou com `unless` para rejeitar dados de entrada que não tenham o marcador esperado.

## `<repetition>`: N cópias, virtualmente

[`<repetition>`][repetition] (em `sequences`) é outra sequência virtual que não copia: `( len elt -- repetition )` constrói uma sequência de `len` elementos todos iguais a `elt`, sem alocar tantas posições:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

O `elt` pode ele próprio ser uma sequência: cada cópia é essa mesma sequência. O `concat` junta depois as cópias uma a seguir à outra:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

Tal como um `slice`, o resultado *é* uma sequência: `length`, `each` e afins funcionam diretamente sobre ele. Recorre a ele para preencher um código de sinal até uma largura fixa ou para colocar uma série de marcadores repetidos; converte com `>string` (ou `>array`) apenas quando precisares mesmo de uma sequência concreta.

## `<clumps>`: janelas sobrepostas, virtualmente

[`<clumps>`][clumps] (em `grouping`) é uma terceira sequência virtual que não copia: `( seq n -- clumps )` encara `seq` como a série de janelas de comprimento `n` *sobrepostas*, cada janela um slice:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

Uma sequência de `length` n produz `length - n + 1` janelas. Como cada janela é um slice, emparelhar leituras sucessivas não custa nenhuma cópia: `[ first2 ]` em cada clump de `2` dá-te todos os pares consecutivos a partir dos quais projetar. (O primo não sobreposto, `<groups>`, em vez disso, corta a sequência em blocos disjuntos.)

## Cleave com vários valores de entrada: `2bi`, `3bi`, `2tri`, `3tri`

As palavras de cleave simples `bi` e `tri` aplicam duas ou três quotations a *um* valor de entrada. As variantes com prefixo `2` e `3` aplicam cada quotation a *dois* ou *três* valores de entrada:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

Cada quotation recebe *todos* os valores de entrada. Usa estas palavras quando mais do que uma projeção depende do mesmo par (ou triplo) de valores, e não quando queres aplicar a *mesma* operação a cada valor de entrada separadamente (isso é `bi@` ou `tri@`).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
