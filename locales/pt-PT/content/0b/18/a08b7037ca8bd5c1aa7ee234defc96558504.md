# Sobre

Uma função é [recursiva de cauda][recursion-tc] se a _última_ coisa executada pela função for uma chamada a si própria.

Cada vez que se chama uma função, é colocado um _frame da pilha_ no topo da [pilha de chamadas de funções][call-stack], com as suas variáveis locais, os seus argumentos, etc. Quando a função devolve, o frame da pilha é removido da pilha.

As funções recursivas de cauda permitem a [otimização de chamadas de cauda][tail-call-optimization]. É uma otimização que permite reutilizar o último frame da pilha na chamada de função seguinte, porque é garantido que a função anterior já não precisa dele. Isto atenua o problema de transbordar a pilha de chamadas de funções, uma situação em que há tantos frames na pilha de chamadas que já não há memória para criar outro.

- Para conseguir recursão de cauda em Elixir, muitas vezes é preciso um acumulador, por causa das regras de imutabilidade dos dados.

  - Um acumulador é uma variável que é passada ao longo da chamada recursiva e que guarda o estado atual da função recursiva _até ao momento_, até o resultado final ser devolvido no caso base.

    ```elixir
    # Count the length of a list without an accumulator
    def count([]), do: 0
    def count([_head | tail]), do: 1 + count(tail)

    # Count the length of a list with an accumulator
    def count(list), do: do_count(list, 0)

    defp do_count([], count), do: count
    defp do_count([_head | tail], count), do: do_count(tail, count + 1)
    ```

- Quando trabalhas com listas, lembra-te de que são implementadas como listas simplesmente ligadas: acrescentar ao início é muito rápido, mas acrescentar ao fim é muito lento.

  ```elixir
  # Reverse a list with an accumulator
  def reverse(list), do: do_reverse(list, [])

  defp do_reverse([], acc), do: acc

  defp do_reverse([head | tail], acc) do
    do_reverse(tail, [head | acc])
  end
  ```
