# Acerca dos bits

Os algarismos binários correspondem, em última análise, diretamente aos transístores da tua CPU ou RAM, e ao facto de cada um estar "ligado" ou "desligado".

A manipulação de baixo nível, informalmente chamada "bit-twiddling", é especialmente importante em linguagens de sistema.

Linguagens de nível mais alto, como Kotlin, costumam abstrair a maior parte destes detalhes. No entanto, existe um conjunto básico de operações ao nível dos bits [disponível][ref-bitwise].

~~~~exercism/note

Isto distrai visualmente, por isso a maioria das ocorrências desta função foi retirada e os resultados são apresentados na notação `0b`.

## Operações de deslocamento de bits

Os tipos `Int` ou `Long`, tanto com sinal como sem sinal, podem ser representados como uma string de 1s e 0s e manipulados como uma sequência de bits.

Talvez seja surpreendente, mas os tipos `Byte` ou `Short` não são compatíveis com a maioria das operações bit a bit em Kotlin. Todos os exemplos abaixo usam inteiros de 32 bits (`Int` ou `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Os deslocamentos de bits movem tudo para a esquerda ou para a direita um número especificado de posições. Alguns bits caem de uma extremidade e a outra extremidade é preenchida com zeros ou uns.

- Deslocamento para a esquerda com `shl`: preenchimento com zeros.
- Deslocamento para a direita com `shr` ou `ushr`: preenchimento com zeros para números positivos (ver a secção seguinte para números negativos).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Cada deslocamento para a esquerda duplica o valor e cada deslocamento para a direita divide-o por dois (sujeito a truncagem). Isto é mais óbvio na representação decimal:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Este tipo de deslocamento de bits é muito mais rápido do que a aritmética "a sério", o que torna a técnica muito popular na programação de baixo nível.

### Deslocamento de bits com inteiros negativos

Com _números inteiros negativos_, temos de ser um pouco mais cuidadosos.

Os valores negativos são armazenados na forma de [complemento para dois][wiki-2complement], o que significa que o bit mais à esquerda é 1. Não há problema para um deslocamento para a esquerda, mas, ao deslocar para a direita, como preenchemos os bits mais à esquerda?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

O operador [`shr`][ref-shr] faz um [deslocamento aritmético][wiki-arithmetic], preservando o bit de sinal.

O operador [`ushr`][ref-ushr] faz um [deslocamento lógico][wiki-logical], preenchendo com zeros como se o número não tivesse sinal.

## Lógica bit a bit

Vimos no [conceito Boolean][concept-booleans] que os operadores `&&` (and), `||` (or) e `!` (not) são usados com valores Boolean.

Existem operadores equivalentes `and`, `or` e `xor` ([ou exclusivo][wiki-xor]) para comparar os bits de dois inteiros, e uma função `inv` (inversão) para inverter todos os bits.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
