# Introdução

A utilização da correspondência de padrões é dominante no código Elixir assertivo e idiomático. Deves lembrar-te de que `=/2` é descrito como um operador de correspondência e não como um operador de atribuição. Ao usar o operador de correspondência, se o padrão à esquerda corresponder ao lado direito, as variáveis à esquerda ficam ligadas e o valor do lado direito é devolvido. É lançado um `MatchError` se não houver correspondência.

```elixir
2 = 2
# => 2
# Literals can be matched if they are the same

2 = 3
# => ** (MatchError) no match of right hand side value: 3

{_, denominator} = Float.ratio(0.25)
# => {1, 4}
# the variable `denominator` is bound to the value 4
```

Lembra-te de que as correspondências acontecem do lado direito para o lado esquerdo.

No último exemplo, se não precisarmos de uma variável numa correspondência de padrões, podemos descartá-la referindo `_`. Qualquer variável que comece por `_` não é seguida pelo runtime.

## Correspondência de padrões em funções com nome

A correspondência de padrões também é uma ferramenta útil quando criamos várias cláusulas de função. A correspondência de padrões pode ser usada nos argumentos das funções, o que depois determina qual a cláusula de função a invocar, começando pelo topo do ficheiro e descendo até à primeira correspondência. As variáveis podem ser ligadas na cabeça da função e usadas no corpo da função.

```elixir
defmodule Example do
  def named_function(:a = variable_a) do
    {variable_a, 1}
  end

  def named_function(:b = variable_b) do
    {variable_b, 2}
  end
end

Example.named_function(:a)
# => {:a, 1}

Example.named_function(:b)
# => {:b, 2}

Example.named_function(:c)
# => ** (FunctionClauseError) no function clause matching in Example.named_function/1
```
