# Sobre

Em Rust, um iterador é qualquer valor que implemente o trait [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html).
Os valores de um iterador podem ser avançados manualmente chamando o método `next` no iterador.

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Muitas das [`collections`](https://doc.rust-lang.org/std/collections/index.html) de Rust implementam
[`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html),
que pode produzir um `Iterator` a partir dos valores da coleção.

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

Repara que, embora `IntoIterator::into_iter` consuma o seu tipo `self`, esse tipo não tem necessariamente de ser um valor com posse.
Assim, existem implementações de `IntoIterator` para [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2),
para [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)
e para [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1).
Estas implementações para diferentes graus de posse proporcionam uma flexibilidade útil.

Não é necessário compreender os `traits` para este conceito e teremos um exercício completo para que domines os `traits`.
Por agora, lembra-te apenas de que:

- Qualquer tipo que implemente `IntoIterator` chama-se _iterável_, porque pode ser transformado num iterador.
- Qualquer tipo que implemente `Iterator` é um iterador, que _produz_ valores e pode ser _iterado_.
- Podes obter um iterador a partir de qualquer tipo que implemente `IntoIterator` chamando o seu método `into_iter`.
- Cada iterador [implementa `IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25) e produz-se a si próprio.
- Os ciclos `for` operam sempre sobre iteradores e chamam `IntoIterator` implicitamente sobre o seu argumento de intervalo.

## `into_iter` e ciclos for

Provavelmente já estás familiarizado com ciclos for sobre um vetor:

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

Fundamentalmente, um ciclo `for` é apenas uma forma abreviada de chamar o método `into_iter` do seu argumento
e depois chamar `next()` até deixar de produzir itens. Por outras palavras, o ciclo anterior é equivalente a:

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## Os métodos `iter` e `iter_mut`

A maioria dos tipos de coleção de Rust fornece os métodos `iter` e `iter_mut`.
Para uma coleção do tipo `T`, estes dois métodos fazem, por convenção, o seguinte:

- O iterador devolvido por `iter` produz `&T` emprestado de forma imutável.
- O iterador devolvido por `iter_mut` produz `&mut T` emprestado de forma mutável.

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## A diferença entre `iter`, `iter_mut` e `into_iter`

Se `iter`, `iter_mut` e `into_iter` produzem todos iteradores, quais são as diferenças?

- O iterador devolvido por `iter` produz, por convenção, `&T` emprestado de forma imutável.
- O iterador devolvido por `iter_mut` produz, por convenção, `&mut T` emprestado de forma mutável.
- O iterador devolvido por `into_iter` pode produzir `T`, `&T` ou `&mut T`, dependendo do seu contexto.

Qual é o contexto de uma invocação de `into_iter`?
O seu tipo `self`.
Lembra-te de que existem implementações de `IntoIterator` para `Vec`, `&'a Vec` e `&'a mut Vec`.
Por isso:

- `(&v).into_iter()` é igual a `v.iter()` => devolve `&T`
- `(&mut v).into_iter()` é igual a `v.iter_mut()` => devolve `&mut T`
- `v.into_iter()` => devolve `T` e move os valores

Isto é mais claro nos ciclos for:

- `for num in &v {...}` => liga `&T`
- `for num in &mut v {...}` => liga `&mut T`
- `for num in v {...}` => liga `T` e move os valores

Muitas vezes é mais claro escrever `v.iter()` em vez de `(&v).into_iter()`.
Por isso, há razões ergonómicas para preferir `iter` e `iter_mut` a `into_iter`.

## Usar os métodos incorporados dos iteradores

Os iteradores fornecem inúmeros métodos incorporados, como `map`, `filter` e `collect`.
Estes métodos são por vezes usados com closures.

`map` usa uma closure para transformar os valores de um iterador.
`take` trunca um iterador (potencialmente infinito) para um que termina após, no máximo, o número especificado de itens.

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter` transforma o iterador num que só devolve os valores para os quais a closure é avaliada como `true`.
`count` consome o iterador, devolvendo o número de itens produzidos.

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map` transforma um iterador transformando cada item num novo iterador através da closure fornecida,
e depois achata todos os novos iteradores produzidos encadeando-os.
`collect` produz uma nova coleção,
desde que o tipo de coleção implemente [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html).

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

O [trait `Iterator`](https://doc.rust-lang.org/std/iter/trait.Iterator.html) fornece _muitas_ transformações úteis deste tipo para iteradores;
vale a pena ler a documentação e familiarizares-te com elas.

## Avaliação preguiçosa

É importante saber que os iteradores de Rust são preguiçosos:
não produzem nenhum valor até consumirmos o iterador.
Se escreveres e executares o seguinte código:

```rust
(0..5).map(|x| x * x);
```

Vais obter o seguinte erro do compilador:

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

Isto acontece porque `map` é um método adaptador que devolve outro iterador.

Para consumires um iterador, usa um ciclo `for` ou um método de iterador que produza algum valor que não seja ele próprio um iterador.

Por exemplo, `collect` é um método consumidor (a sua assinatura de função não devolve um iterador, mas sim um tipo genérico):

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
