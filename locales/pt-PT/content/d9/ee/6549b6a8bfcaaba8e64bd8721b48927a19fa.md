# Introdução aos condicionais

## Veracidade no Bash

O Bash não tem o conceito de valores Boolean.
Existem strings e números, e arrays de strings ou números.
Então, como é que os comandos condicionais lidam com verdadeiro e falso?

## Estado de saída

Os comandos produzem um _estado de saída_ quando terminam.
Um estado de saída é um número inteiro entre 0 e 255, inclusive.
O Bash considera que um estado de saída **zero** representa _sucesso_.
Qualquer outro estado de saída representa _falha_.

Isto aplica-se a todos os comandos, incluindo os comandos internos do Bash, as palavras-chave e as funções.

## O comando "if"

A sintaxe básica do comando `if` é

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

Começa com `if`; os comandos de condição são separados dos comandos de "sucesso" por `then`; e termina com `fi`.
A cláusula `else` é opcional.

Os CONDITIONAL_COMMANDS podem ser um único comando ou uma [lista de comandos][command-list].

Os CONDITIONAL_COMMANDS são executados e

* se o estado de saída for zero (sucesso), então os TRUE_COMMANDS são executados.
* se o estado de saída for diferente de zero (falha), então os FALSE_COMMANDS são executados, se estiverem presentes.

É possível criar ramos em cascata com `elif`
```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

Tem de haver um ponto e vírgula ou uma nova linha antes das palavras `then`, `elif`, `else` e `fi`.

Para sublinhar: é o **estado de saída** dos comandos condicionais que controla o fluxo.
Por exemplo, o `grep` devolve 0 se encontrar uma correspondência e 1 se não encontrar nenhuma.
A opção `-q` suprime a saída, produzindo apenas o estado de saída.

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## Os comandos "[" e "test"

Não há sintaxe especial à volta dos CONDITIONAL_COMMANDS.
Podes estar habituado a ver condicionais com este aspeto:

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

O `[` não é sintaxe especial.
É um _comando_ que avalia a expressão condicional e termina com um estado de sucesso ou de falha.
Como em todos os comandos, é **obrigatório** haver espaço entre ele e os seus argumentos.

Na verdade, o `[` é sinónimo do comando `test`.
São exatamente iguais, exceto que o último argumento do `[` _tem_ de ser `]`.

### Expressões condicionais

Dentro de `[` e `]`, escreves uma expressão condicional.
Algumas expressões condicionais típicas incluem:

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

Há muitas mais operações disponíveis; estão listadas na secção [Expressões condicionais do Bash][cond-expr] do manual.

~~~~exercism/note
Nos exemplos acima, repara que todas as variáveis estão entre aspas.
Os comandos `test` e `[` são comandos simples, em que os argumentos estão sujeitos à divisão em palavras e à expansão de nomes de ficheiros, tal como em qualquer outro comando.

Isto é importante referir porque as expressões condicionais são avaliadas de forma diferente consoante _o número de argumentos_ que forneces:

* 0 argumentos: o estado de saída é diferente de zero (falha)
* 1 argumento: o estado de saída é zero (sucesso) se o argumento não estiver vazio, e diferente de zero se estiver vazio.
* 2 argumentos: o primeiro argumento tem de ser um operador unário (como `[ -z "$name" ]`) ou um `!` (que nega o estado do teste de 1 argumento)
* e [mais][test].

Podes obter resultados inesperados se te esqueceres de usar aspas:

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## A palavra-chave "[["

A [construção condicional `[[...]]`][cond-construct] não é um _comando_, é uma **palavra-chave**.
Isto significa que, embora seja tratada como qualquer outro comando, tem regras de análise sintática especiais.
O que o `[[` tem de especial é que as variáveis expandidas dentro dele **não** estão sujeitas à divisão em palavras nem à expansão de nomes de ficheiros.
Isto significa que este comando funciona como esperas, mesmo sem aspas.

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

O `[[` suporta todas as expressões condicionais que o `test` e o `[` conseguem tratar.
Além disso, o `[[` oferece

* o operador de correspondência por expressão regular `=~`,
* os `==` e `!=` a funcionar como operador de correspondência de padrões glob,
* os `&&` e `||` como operadores lógicos (regra de análise sintática especial),
* os `<` e `>` como operadores de comparação de strings "simples" (regra de análise sintática especial: como são símbolos de redirecionamento, no `[` têm de ser escapados).

Há um consenso generalizado de que estas funcionalidades especiais oferecem tantas vantagens que o `[[` deve ser usado exclusivamente.
(Por exemplo, o [Google Shell Style Guide][goog-test].)

## O comando "case"

O [`case`][case] é outro comando de controlo de fluxo.
É como a instrução "switch" noutras linguagens.

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

O WORD é comparado com cada PATTERN.
Quando um deles corresponde, os COMMANDS são executados.

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

Cada cláusula COMMANDS tem de terminar com **dois** pontos e vírgulas, `;;`.
