# Sobre

É pouco provável que encontres muito código de produção que não faça uso de namespaces.

Um exemplo da sintaxe é:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

Os namespaces são uma forma de agrupar código relacionado e de evitar conflitos de nomes.

Segundo a [documentação oficial][namespaces], os namespaces têm dois papéis principais:

- Primeiro, o .NET usa namespaces para organizar as suas muitas classes
- Segundo, declarar os teus próprios namespaces pode ajudar-te a controlar o âmbito dos nomes de classes e métodos em projetos de programação maiores.

Os namespaces são amplamente usados pela biblioteca de classes base (BCL) para organizar a sua funcionalidade.

## Referências a tipos em namespaces

Os tipos incluídos em namespaces são referidos, fora do namespace, prefixando o nome do tipo com a sintaxe de ponto. Em alternativa, e mais habitualmente, podes colocar uma diretiva `using` no topo do ficheiro (ou dentro de um namespace) e quaisquer tipos do namespace importado podem ser usados sem o prefixo. Dentro do mesmo namespace, não é preciso qualificar os nomes dos tipos.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

Este [artigo][using] explica claramente as formas como a diretiva `using` pode ser usada:

- `using`: evita ter de qualificar os tipos com o namespace
- `using static`: evita ter de qualificar os membros com os tipos (um bom exemplo é `Math.Max()`).
- `using MyAlias = YourNamespace;`: substitui o nome do namespace por um nome mais legível.

## Conflito de namespaces

O .NET resolve o problema de dois namespaces com o mesmo nome em assemblies diferentes, onde haveria um conflito de nomes de identificadores totalmente qualificados (por exemplo, um cenário em que são carregadas várias versões de um assembly). Este problema é resolvido com o [qualificador de alias de namespace][namespace-alias-qualifier] e o [extern alias][extern-alias].

Uma das razões para abordar este tópico bastante específico é o uso do [operador `::`][dot-dot-operator]. Vais ver frequentemente o qualificador `global::` a prefixar namespaces, sobretudo em código gerado. A intenção aqui é evitar um possível conflito com algum namespace ou nome de classe aninhado. Ao prefixar um namespace com `global::`, garantes que é selecionado um namespace de nível superior.

## Nota para programadores de Java

Ao comparar com o `import` dos `packages` de Java, há algumas diferenças e semelhanças a assinalar:

- Não há equivalente em C# para importar tipos específicos.
- `using static` e `import static` são equivalentes.
- Em Java, os nomes dos pacotes têm impacto na acessibilidade entre jars. Em C#, os assemblies são fundamentais e pertencer ao mesmo namespace não afeta o nível de acesso.
- A relação entre os caminhos do sistema de ficheiros e os nomes de classe totalmente qualificados em Java não se reflete nos namespaces de C#, embora seja boa prática, sempre que possível, dar a um ficheiro o mesmo nome que a classe principal que contém.
