# Sobre

[concept:csharp/resource-cleanup]() usa a interface `IDispose` para sinalizar a quem chama uma classe que há recursos ou estado de programa que precisam de ser libertados ou repostos atempadamente, quando o objeto em questão já não é necessário. Neste exercício introduzimos um pouco de açúcar sintático, com a palavra-chave `using`, que torna o código menos verboso e reduz a probabilidade de se omitirem chamadas importantes.

Podes ver o `using` como um substituto do [`try/finally`][try-finally] em alguns casos de utilização.

```csharp
File file = null;
try
{
    file = new File("myStuff.txt");
    file.Write("more stuff");
}
finally
{
    file.Dispose();
}
```

Esta sintaxe é substituída pela versão mais compacta e à prova de erros:

```csharp
using (var file = new File("myStuff.txt")
{
    file.Write("more stuff");
}
```

Repara que é possível combinar vários recursos de forma conveniente, seguindo as regras habituais para blocos de uma só linha:

```csharp
using (var file = new File("mystuff.txt")
using (var fileWriter = new StreamWriter(file)
{
     ...
}
```

No C# 8 foi introduzida a seguinte variante, em que a instrução `using` aparece no início de um bloco:

```csharp
using var file = new File("myStuff.txt");
file.Write("more stuff");
```

Isto permite-te ter vários objetos descartáveis no mesmo bloco e lidar de forma mais natural com o [`try/catch`][try-catch]:

```csharp
using var fileIn = new File("myStuff.txt");
using var fileOut = new File("yourStuff.txt");
try
{
    var stuff = fileIn.Read();
    fileOut.Write(stuff);
}
catch (Exception)
{
    LogStuff();
}
```

As regras sobre a forma como a palavra-chave `using` pode ser usada, e com instâncias de que tipos, estão detalhadas [aqui][using-statement].

## Nota para programadores Java

Os programadores de Java talvez reconheçam isto como um equivalente do mecanismo de [_gestão automática de recursos_][automatic-resource-management] introduzido no Java 7. São muito semelhantes. A sintaxe do Java, que reutiliza o `try`, tem a vantagem de incorporar os blocos `catch` de forma mais natural do que o `using` do C#.

## Versões

Repara que a versão mais flexível do `using`, aquela em que ele não tem um bloco sintático próprio, foi introduzida no C# 8, por isso podes ter de verificar se a base de código em que estás a trabalhar usa o C# 8 ou uma versão posterior.
