# Traits

Um trait especifica um conjunto de métodos que um tipo pode implementar.
Os traits são úteis para definir métodos que devem ser partilhados entre tipos.
Quando os traits são usados com tipos genéricos, os métodos definidos podem ser chamados num tipo em particular, mas também é possível chamá-los noutro tipo de dados.
De forma abstrata, com o uso de _trait bounds_, podemos especificar que o tipo genérico tem de partilhar determinado comportamento.

> **Nota:** Os traits têm uma funcionalidade semelhante ao que noutras linguagens de programação se conhece como interfaces, com algumas diferenças.

## Definição de traits

Definir um trait ajuda a identificar a assinatura da função que compõe o conjunto de comportamentos que um tipo pode implementar para alcançar um resultado.
Estes métodos formam o comportamento de um tipo.
Se conseguirmos chamar os mesmos métodos em tipos diferentes, isso implica que os tipos envolvidos têm o mesmo comportamento.

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

Tendo em conta a definição do trait `Summary` acima, o método `summarize` é um comportamento que só pode ser chamado pelo tipo de estrutura `NewsArticle`.
Se for invocado noutras instâncias de tipo, provoca um erro de compilação.
Declarar o trait com a palavra-chave `pub` expõe o trait desta crate a outras crates que também pretendam usá-lo.
Repara também que usamos um ponto e vírgula depois de declarar as assinaturas dos métodos nos traits.

Um trait pode ser definido com um argumento genérico, o que permite que uma função receba um argumento de qualquer tipo de dados.
Isto introduz uma maior flexibilidade na assinatura da função, permitindo-lhe lidar com vários tipos de dados.
No caso do trait `Summary` abaixo, este foi reformulado para funcionar com qualquer tipo de dados, para que, quando o método `summarize` for invocado sobre eles, devolva um ByteArray.

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

Um trait pode ter mais do que um método no seu corpo; cada assinatura de método declarada é uma linha única que termina com um ponto e vírgula.

## Implementação de um trait num tipo

Depois de definires as assinaturas de função que compõem um trait, o compilador vai garantir que também é definida uma implementação para os tipos que adotam o trait.
Abaixo escrevemos uma crate de biblioteca `aggregator` de media que resume alguns dados de instâncias de `NewsArticle` e `Tweet`.
Para a estrutura `NewsArticle`, usaríamos o headline, o author e o location para devolver o valor do método `summarize` do trait `Summary`, enquanto para a estrutura `Tweet` usaríamos o username e o content, partindo do princípio de que o conteúdo do tweet tem uma limitação de 280 caracteres.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## Implementações predefinidas

Por vezes, um trait pode ser definido com uma implementação predefinida para alguns ou todos os métodos que o compõem.
Isto serve para evitar exigir uma implementação de todos os métodos em cada tipo e para melhorar a legibilidade do código.
Se um tipo em particular precisar de uma implementação especial de um método do trait, pode substituir a implementação predefinida.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## Como usar e gerir traits externos

Os traits e as implementações podem ser definidos num módulo externo e usados noutros módulos, desde que sejam devidamente importados.
Digamos que temos um trait `ShapeGeometry` com o método `boundary`, que tem de ser implementado tanto para a estrutura `Circle` como para a estrutura `Rectangle`.
Abaixo está um exemplo de como o trait e a implementação são importados, geridos e usados entre módulos.

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

A visibilidade da implementação tanto de `CircleGeometry` como de `RectangleGeometry` não precisa de ser pública, uma vez que o trait `ShapeGeometry` é tornado público e deve ser facilmente encontrado pelo compilador.

## Aliases de impl

As implementações podem receber um alias quando são importadas, usando a palavra-chave `impl`.
Isto ajuda na instanciação de uma implementação genérica para tipos concretos.
Vamos definir uma implementação trivial do trait `Two` para todos os tipos que implementam o trait `One`, somando simplesmente duas vezes o valor de `One` e devolvendo a soma.
Podemos depois expor a implementação de `Two` que funciona apenas para os tipos `u8` e `u128`.

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

A implementação genérica pode ser escrita num módulo privado e, com o uso de um alias de impl, podemos instanciar a implementação genérica destes dois tipos concretos.
O benefício de usar uma implementação genérica privada e não exposta é que evita a duplicação de código entre ficheiros.
Isto também mantém a API pública simples e limpa.
