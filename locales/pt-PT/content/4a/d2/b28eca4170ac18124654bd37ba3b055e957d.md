# Introdução

## Igualdade

Os tipos simples (strings e tipos primitivos) são normalmente testados quanto à igualdade com `==` e `!=`.

Os tipos de referência (instâncias de classes) são comparados com o método `Equals()` herdado de `Object`. Se o teu objetivo com o teste de igualdade é garantir que dois objetos são exatamente a mesma instância, basta confiar na implementação de `Object`. Caso contrário, tens de substituir `object.Equals()`.

Se sabes que todas as instâncias da tua classe são criadas num único sítio, por exemplo personagens de um jogo ou simulação, a igualdade de referência é suficiente. No entanto, é provável que sejam criadas várias instâncias da mesma entidade do mundo real (a partir de uma base de dados, por entrada do utilizador, através de um pedido web). Neste caso, os valores que identificam a entidade de forma única têm de ser testados quanto à igualdade. Por isso, `Equals()` tem de ser substituído e os membros de dados adequados da tua classe são testados quanto à igualdade.

Um método `Equals()` substituído contém testes de igualdade sobre membros de tipos simples com `==` e sobre tipos de referência com chamadas recursivas a `Equals()`.

A classe `Object` fornece os métodos adequados para comparar dois objetos e detetar se são uma e a mesma instância.

### `Object.GetHashCode()`

O método `Object.GetHashCode()` devolve um código hash sob a forma de um número inteiro de 32 bits. O código hash é usado pelas classes de _dicionário_ e de _conjunto_, como `Dictionary<T>` e `HashSet<T>`, para armazenar e obter objetos de forma eficiente.

A relação entre código hash e igualdade é a seguinte: se dois objetos forem iguais (`Equal()` devolve true), então `GetHashCode()` dos dois objetos tem de devolver o mesmo valor. Isto não se aplica no sentido inverso. Não é simétrico. O facto de dois objetos terem o mesmo código hash não significa que tenham de ser iguais. Imagina uma função de consulta que vai primeiro a um "bucket", com base no código hash, e depois extrai o item específico através do teste de igualdade.

A documentação da API da biblioteca HashCode aborda a melhor forma de gerar um código hash

Os valores usados no teste de igualdade têm de ser estáveis enquanto a coleção com hash estiver a ser usada. Se adicionares um objeto à coleção com um conjunto de valores e depois alterares esses valores, o código hash deixa de apontar para o "bucket" correto. Na prática, isto significa que o objeto deve ser imutável. Outras abordagens correm o risco de criar armadilhas para quem mantém o código.

## Conjuntos

Um conjunto é uma coleção de valores únicos. A implementação predefinida de um conjunto no .NET é a classe `HashSet<T>`, que é uma coleção que só contém valores únicos.
