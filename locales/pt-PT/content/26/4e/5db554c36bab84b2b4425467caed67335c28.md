# Sobre

Os [closures][closures] em Swift são blocos de código autónomos aos quais se podem passar parâmetros para desencadear o seu cálculo e devolver valores.
Os closures também capturam valores do ambiente onde estão inseridos e usam-nos nos seus cálculos.
Como são autónomos, podem ser passados de uns sítios para outros num programa como quaisquer outros valores, ou atribuídos a constantes e variáveis.

Os closures podem parecer muito com as funções de Swift; de facto, parecem, e por bons motivos.
As funções em Swift são casos especiais de closures, com a particularidade de terem obrigatoriamente um nome e de serem definidas com uma sintaxe ligeiramente diferente.

Embora as funções em Swift sejam, tecnicamente, closures, quando se fala de «closures» em Swift está-se a referir às [expressões de closure][closure-expressions].
As expressões de closure escrevem-se como uma lista de parâmetros seguida de um tipo de retorno e da palavra-chave `in`, seguida do corpo do closure, tudo entre um par de chavetas:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}
```

Isto define uma expressão de closure do tipo `(Double, Double) -> Double`, que pode ser executada de forma semelhante a uma função desse tipo, aplicando-a a parâmetros do tipo adequado:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}(10.0, 15.0)
// returns 12.5
```

Como não é muito prático escrever a expressão de closure completa sempre que se quer executá-la, os closures podem ser atribuídos a nomes, como qualquer outro valor em Swift.
Depois, podem ser chamados aplicando o nome aos parâmetros:

```swift
let mean = { (a: Double, b: Double) -> Double in
  (a + b) / 2.0
}

mean(13.0, 100.0)
// returns 56.5
```

Como se vê acima, os closures, tal como as funções normais, podem omitir a palavra-chave `return` se o corpo do closure for uma única expressão.

Na maioria das vezes, os closures são usados com funções de ordem superior, quer passados como parâmetros, quer devolvidos como resultado:

```swift
[11, 75, 3, 99, 53].contains(where: { (x: Int) -> Bool in x > 100 })
// returns false

["apple", "ball", "carrot"].sorted(by: { (s1: String, s2: String) -> Bool in s1.count < s2.count })
// returns ["ball", "apple", "carrot"]

func makeAdder(base: Int) -> (Int) -> Int {
  { (x: Int) -> Int in base + x }
}
```

## Inferir os tipos de closure

Quando o tipo de retorno ou os tipos dos parâmetros podem ser [inferidos a partir do contexto][inferring-closure-types], podem ser omitidos da expressão de closure.
Além disso, se os tipos dos parâmetros puderem ser omitidos, também o podem ser os parênteses à volta dos nomes dos parâmetros:

```swift
let mean: (Double, Double) -> Double = { a, b in a + b / 2.0 }

func makeAdder(base: Int) -> (Int) -> Int {
  { x in base + x }
}

["apple", "ball", "carrot"].sorted(by: { s1, s2 in s1.count < s2.count })
```

- No primeiro exemplo, o tipo pode ser inferido a partir da anotação na constante `mean`.
- No segundo, o compilador sabe, a partir da definição de `makeAdder`, que `base` é um `Int` e que a função devolvida tem de ser do tipo `(Int) -> Int`. A partir daí, consegue verificar que, se `x` for um `Int`, o closure terá o tipo `(Int) -> Int` e, por isso, podemos omitir a assinatura de tipo no closure, já que `(Int) -> Int` é a única assinatura válida que o closure pode ter.
- O terceiro exemplo é semelhante, mas o compilador precisa de obter parte da informação de tipo a partir do array com que o método está a ser usado. Sabe que o método `sorted(by:)` recebe como parâmetro um closure com dois parâmetros do mesmo tipo que os elementos da coleção que está a ser ordenada e que devolve um `Bool`, por isso o compilador consegue inferir que o tipo de retorno do closure tem de ser `Bool`. E, como o método está a ser usado com um array de String, consegue determinar que os tipos dos parâmetros `s1` e `s2` têm de ser ambos `String`.

## Limitações dos closures

Como já foi referido, as funções e os closures são muito semelhantes em Swift, mas há algumas diferenças importantes:

- Os closures não podem usar rótulos de argumento externos. Não há forma de os definir e tentar usar o nome de um parâmetro ao chamar o closure dá origem a um erro:

```swift
let add5 = { x in x + 5 }
add5(x: 10)
// Error: Extraneous argument label 'x:' in call
```

- Os parâmetros de um closure não podem ter um valor por omissão.
- Os parâmetros de um closure podem ser variádicos, mas têm de ter um nome e uma anotação de tipo.
