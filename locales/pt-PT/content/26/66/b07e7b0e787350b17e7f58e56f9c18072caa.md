# Acerca de

## Carateres

Uma [codificação de carateres][char-encoding] é uma convenção específica usada para representar elementos de texto de uma língua natural como uma sequência de bytes.
Um "elemento de texto", aqui, pode ser qualquer unidade com significado numa língua natural: por exemplo, letras, espaços, pontuação, emojis, ideogramas, etc.

O NASM (The Netwide Assembler, o assembler usado nesta track) suporta a definição de dados com [ASCII][ascii].

As constantes de carateres em NASM podem ter até 8 bytes e podem ser definidas com aspas simples (`'`), aspas duplas (`"`) ou backticks (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Os carateres especiais têm de ser definidos com backticks e escapados com `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

O NASM também suporta [carateres Unicode][unicode] em [UTF-8][utf8], especificados com `\u` ou `\U` e entre backticks:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

Repara que não existe suporte integrado para nenhuma codificação de carateres em x86-64 como um tipo distinto.
Os dados em assembly são uma sequência de bytes, e a interpretação desses bytes como um caráter, um número ou qualquer outra coisa fica a cargo do programador.

Por exemplo, o caráter ASCII '0' é um único byte com o valor 48.
Assim, armazenar 48 num byte é exatamente o mesmo que armazenar o caráter ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Pela mesma razão, manipular carateres faz-se transformando diretamente os valores desses bytes:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Strings

Uma [string][string] é uma sequência de carateres.
Em assembly, é normalmente implementada como um array.

É possível declarar uma string em NASM da mesma forma que se declararia qualquer array:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Uma diferença entre strings e outros arrays é que o NASM também suporta a declaração de strings sem uma vírgula (`,`) a separar os valores.
Também é possível intercalar valores com vírgulas:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Repara que, como já foi referido, os carateres são apenas bytes (ou uma sequência de bytes em codificação Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Como cada caráter ASCII ocupa um único byte, qualquer byte seguinte num tamanho maior é `0`.
Por exemplo, declarar `'a'` como um qword (8 bytes) significa que o primeiro byte é `'a'` (`97`) e que os outros sete bytes são todos `0`.

Por esta razão, todos os seguintes são equivalentes:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
Em assembly, as strings não são terminadas automaticamente por um caráter NUL ASCII (valor `0`).

Ao interagir com linguagens de alto nível, como C, é responsabilidade do programador garantir que o terminador correto, se existir, é acrescentado ao fim da string.
~~~~

## Instruções de string

Como as strings são arrays, podes trabalhar com elas da mesma forma que com qualquer array, desreferenciando explicitamente a memória:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Além disso, existem algumas instruções para carregar, mover e armazenar valores em sequências de bytes na memória.
Apesar de serem chamadas de _instruções de string_, podem ser usadas com qualquer sequência de bytes na memória, ou seja, com qualquer array:

| instrução    | o que faz                                                                                                         |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | carrega um valor de uma posição de memória indicada por `rsi` para `rax`                                          |
| [stos][stos] | armazena um valor de `rax` numa posição de memória indicada por `rdi`                                             |
| [movs][movs] | copia um valor de uma posição de memória indicada por `rsi` e armazena-o numa posição de memória indicada por `rdi` |
| [cmps][cmps] | compara o valor numa posição de memória indicada por `rsi` com o valor numa posição de memória indicada por `rdi` |
| [scas][scas] | compara o valor em `rax` com o valor numa posição de memória indicada por `rdi`                                   |

Repara que estas instruções _não_ recebem qualquer operando explícito.
Os seus operandos são implícitos.

Como regra geral:

1. Quando o seu operando de origem é uma posição de memória, o seu endereço deve ser guardado em `rsi` (`s` de source).
2. Quando o seu operando de destino é uma posição de memória, o seu endereço deve ser guardado em `rdi` (`d` de destination).
3. Se um dos operandos não for uma posição de memória, é o registo `rax`.

Repara que estas instruções desreferenciam automaticamente os endereços de memória de acordo com a operação específica que realizam.

Todas podem operar com tamanhos diferentes.
É acrescentado um sufixo para indicar esse tamanho:

| sufixo | significado | tamanho |
| :----: | ------- | :------ |
|  `b`   | byte    | 1 byte  |
|  `w`   | word    | 2 bytes |
|  `d`   | dword   | 4 bytes |
|  `q`   | qword   | 8 bytes |

Por exemplo:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

Atualizam também qualquer endereço usado pelo tamanho da operação.
Esta atualização é feita de acordo com o valor da **flag de direção (DF)**:

- Se a `DF` estiver a zero, os endereços são _aumentados_ pelo tamanho da operação.
- Se a `DF` estiver a um, os endereços são, em vez disso, _diminuídos_ pela mesma quantidade.

A ABI System V determina que a flag de direção tem de estar a zero à entrada da função.
Assim, _o comportamento predefinido é que a memória seja lida/escrita por ordem crescente de endereços_.

A instrução [cld][cld] pode ser usada para colocar a flag de direção a zero, enquanto a instrução [std][std] a coloca a um:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Quem chama espera que a `DF` esteja a zero depois de qualquer função chamada retornar, segundo a ABI System V.
Se alguma vez colocares a `DF` a um, certifica-te de que a colocas a zero antes do `ret`.
~~~~

### Lods

Esta instrução _lê_ de uma posição de memória cujo endereço está em `rsi` e copia o valor para `rax`.

O valor em `rsi` é atualizado pelo número de bytes lidos:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

Esta instrução copia o valor em `rax` e _escreve-o_ numa posição de memória cujo endereço está em `rdi`.

O valor em `rdi` é atualizado pelo número de bytes escritos:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

Esta instrução _lê_ de uma posição de memória cujo endereço está em `rsi` e _escreve_ o valor numa posição de memória cujo endereço está em `rdi`.
O valor em `rax` não é afetado por esta instrução.

Tanto `rsi` como `rdi` são atualizados pelo número de bytes copiados de uma posição de memória para a outra:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

Esta instrução _lê_ de uma posição de memória cujo endereço está em `rsi` e também _lê_ de uma posição de memória cujo endereço está em `rdi`.
De seguida, compara os valores e atualiza as flags, segundo o `cmp`.

Tanto `rsi` como `rdi` são atualizados pelo número de bytes lidos de ambas as posições:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

Esta instrução compara o valor em `rax` com o valor que _lê_ de uma posição de memória cujo endereço está em `rdi`.
De seguida, atualiza as flags, segundo o `cmp`.

O valor em `rdi` é atualizado pelo número de bytes lidos:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

Além destas, a instrução [rep][rep] não interage diretamente com a memória.
Em vez disso, pode ser acrescentada como prefixo às outras instruções mencionadas, _repetindo_ essas instruções.

Quando precedidas de `rep`, as instruções de string são repetidas um número de vezes igual ao valor em `rcx`.
Cada vez, o valor em `rcx` é diminuído em `1`.
Repara que o valor em `rcx` tem de ser definido antes de a instrução ser usada:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

Além de usar `rcx` como contador, `repe` (ou `repz`) e `repne` (ou `repnz`) interrompem a execução se a `zero flag (ZF)` estiver a zero ou a um, respetivamente:

| instrução        | onde pode ser acrescentada | pode parar mais cedo        |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`, `lods`, `stos` | não                     |
| `repe`,`repz`    | `cmps`, `scas`         | sim, para quando ZF é 0 |
| `repne`, `repnz` | `cmps`, `scas`         | sim, para quando ZF é 1 |

~~~~exercism/advanced
Nos processadores modernos, `rep movs` e `rep stos` são normalmente opções rápidas para mover dados em blocos grandes.
No entanto, as outras instruções de string, e até `movs` e `stos` quando operam sem `rep`, são habitualmente mais lentas do que um ciclo simples.
