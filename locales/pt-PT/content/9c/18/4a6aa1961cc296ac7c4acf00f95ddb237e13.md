# Inclusão de código

`circus-acts` usava `<` para dizer que uma classe *pode fazer* o que uma classe abstrata descreve. Não dizia nada sobre como.

O `include` é a outra metade: vai buscar o código real a outra classe e coloca uma cópia dele nesta.

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

`JAZZ_ROUTINE::count` vale 8, sem que `JAZZ_ROUTINE` alguma vez o mencione.

## São duas decisões separadas

A maioria das linguagens junta as duas coisas: um único `extends` passa o código e torna a subclasse utilizável onde se espera a superclasse. O Sather mantém-nas separadas.

| Escrito | Significa |
| --- | --- |
| `class A < $B` | um `A` pode ser usado onde se espera um `$B` |
| `class A is include B` | `A` começa com uma cópia do código de `B` |

Uma sem a outra, ou as duas. Incluir uma classe **não** a torna num subtipo: depois de `include WARM_UP`, um `JAZZ_ROUTINE` continua a não poder ser usado onde se espera um `WARM_UP`, e nada finge o contrário.

## Mudar o nome

Uma rotina incluída pode ser trazida com um nome diferente:

```sather
   include WARM_UP count -> warm_up_count;
```

Várias separam-se por vírgulas:

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## Deixar uma de fora

Renomear para *nada* deixa-a de fora, e é assim que se substitui uma rotina:

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

O `count` entra como habitualmente; o `describe` não, por isso escrever uma aqui não entra em conflito. Sem o `describe -> ;`, o compilador recusaria: duas rotinas com o mesmo nome e os mesmos argumentos numa só classe são um erro, e o Sather não vai adivinhar qual querias dizer.

É esta a diferença em relação a uma sobrescrita na maioria das linguagens: a substituição é anunciada, não subentendida.
