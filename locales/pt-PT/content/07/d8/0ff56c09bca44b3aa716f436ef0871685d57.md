# Sobre

Os `Complex numbers` não são complicados.
Só precisam de um nome menos assustador.

São tão úteis, sobretudo em engenharia e ciência, que a Julia inclui [números complexos][complex] como tipos numéricos padrão, a par dos inteiros e dos números de vírgula flutuante.

## Noções básicas

Um valor `complex` em Julia é essencialmente um par de números: normalmente, mas nem sempre, de vírgula flutuante.
Estas partes chamam-se «real» e «imaginária», por razões históricas infelizes.
Mais uma vez, o melhor é focares-te na simplicidade subjacente e não nos nomes estranhos.

Para criar números complexos a partir de dois números reais, basta acrescentar o sufixo `im` à parte imaginária.

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im

julia> typeof(z)
ComplexF64 (alias for Complex{Float64})

julia> zi = 1 + 2im
1 + 2im

julia> typeof(zi)
Complex{Int64}
```

Existem, assim, vários tipos `Complex`, derivados do tipo inteiro ou de vírgula flutuante correspondente.

Para criar um número complexo a partir de variáveis reais, a sintaxe acima não funciona.
Escrever `a + bim` confunde o analisador sintático, que passa a pensar que `bim` é o nome de uma variável (que não existe).

Escrever `b*im` é possível, mas o método preferido usa a função `complex()`.

```julia-repl
julia> a = 1.2; b = 3.4; complex(a, b)
1.2 + 3.4im
```

Podes perguntar-te: porque é `im` e não `i` ou `j`?

A maioria dos engenheiros contenta-se com `j`.
A maioria dos cientistas e matemáticos prefere a notação matemática `i` para _imaginário_, mas essa notação entra em conflito com o uso de `i` para designar _corrente_ em engenharia eletrotécnica.

O [manual][complex] afirma que «usar o i dos matemáticos ou o j dos engenheiros para esta constante global foi rejeitado, por serem nomes de variáveis de índice muito populares».

Por feliz coincidência, isto também evita longas discussões entre engenheiros e todos os outros.
Podes formar a tua própria opinião sobre se isso influenciou a decisão.

Para acederes às partes de um número complexo individualmente:

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im

julia> real(z)
1.2

julia> imag(z)
3.4
```

Qualquer das partes pode ser zero e os matemáticos podem então dizer que o número é «totalmente real» ou «totalmente imaginário».
No entanto, continua a ser um número complexo em Julia.

```julia-repl
julia> zr = 1.2 + 0im
1.2 + 0.0im

julia> typeof(zr)
ComplexF64 (alias for Complex{Float64})

julia> zi = 3.4im
0.0 + 3.4im

julia> typeof(zi)
ComplexF64 (alias for Complex{Float64})
```

Podes ter ouvido dizer que «`i` (ou `j`) é a raiz quadrada de -1».

Para já, isto significa apenas que a parte imaginária satisfaz, _por definição_, a seguinte igualdade:

```julia-repl
julia> 1im * 1im == -1
true
```

É uma ideia simples, mas conduz a consequências interessantes.

## Aritmética

Todos os `operators` matemáticos padrão e as funções elementares usados com números de vírgula flutuante e inteiros também funcionam com números complexos. Uma pequena amostra:

```julia-repl
julia> z1 = 1.5 + 2im
1.5 + 2.0im

julia> z2 = 2 + 1.5im
2.0 + 1.5im

julia> z1 + z2  # addition
3.5 + 3.5im

julia> z1 * z2  # multiplication
0.0 + 6.25im

julia> z1 / z2  # division
0.96 + 0.28im

julia> z1^2  # exponentiation
-1.75 + 6.0im

julia> 2^z1  # another exponentiation
0.5188946835878313 + 2.7804223253571183im
```

Explicar as regras da multiplicação e da divisão de números complexos está fora do âmbito deste conceito (_e é pouco provável que tenhas de fazer essas operações «à mão» com muita frequência_).

Qualquer introdução [matemática][math-complex] ou de [engenharia eletrotécnica][engineering-complex] aos números complexos aborda este tema, caso queiras aprofundá-lo.

Em alternativa, o Exercism tem um exercício de prática `Complex Numbers` onde podes implementar uma classe de números complexos com estas operações, a partir dos princípios básicos.

A divisão inteira (na maior parte dos casos) ___não___ é possível com números complexos, pelo que os operadores `//`, `÷` e `%` falham para o tipo de números complexos.
Uma exceção é usar `//` com _inteiros_ complexos para obter números racionais complexos, mas provavelmente isso raramente é útil.

## Funções

A maioria das funções matemáticas funciona com valores de entrada complexos.

No entanto, fornecer valores de entrada reais e esperar um resultado complexo normalmente não funciona.
Trata-se de uma otimização de desempenho que fará mais sentido depois de veres o conceito de Multiple Dispatch.

```julia-repl
julia> sin(1.5 + 2.0im)
3.752771340479298 + 0.25655395609048176im

julia> sqrt(-1)
ERROR: DomainError with -1.0:
sqrt was called with a negative real argument but will only return a complex result if called with a complex argument. Try sqrt(Complex(x)).

julia> sqrt(-1 + 0im)
0.0 + 1.0im
```

Existem várias funções, além de `real()` e `imag()`, com particular relevância para os números complexos.
Podes ignorar estas se não fizerem sentido para ti!

- `conj()` limita-se a inverter o sinal da parte imaginária de um número complexo (_de + para - ou vice-versa_).
    - Devido à forma como a multiplicação de números complexos funciona, isto é mais útil do que imaginas.
- `abs(<complex number>)` garante que devolve um número real sem parte imaginária.
- `abs2(<complex number>)` devolve o quadrado de `abs(<complex number>)`: mais rápido de calcular do que `abs()` e, muitas vezes, exatamente o que um cálculo precisa.
- `angle(<complex number>)` devolve o ângulo de fase em radianos.

```julia-repl
julia> z1
1.5 + 2.0im

julia> conj(z1)
1.5 - 2.0im

julia> abs(z1)
2.5

julia> abs2(z1)
6.25

julia> angle(z1)
0.9272952180016122
```
Uma explicação parcial, para quem gosta de matemática _(mais uma vez, podes ignorar)_:

- A representação `(real, imag)` de `z1` usa, na prática, coordenadas cartesianas no plano complexo.
- O mesmo número complexo pode ser representado na notação `(r, θ)`, com coordenadas polares.
- Aqui, `r` e `θ` são dados por `abs(z1)` e `angle(z1)`, respetivamente.

Eis um exemplo com algumas constantes:

```julia-repl
julia> euler = exp(1im * π)
-1.0 + 1.2246467991473532e-16im

julia> real(euler)
-1.0

julia> round(imag(euler), digits=15)  # round to 15 decimal places
0.0
```

Assim, uma expressão simples com três das constantes mais importantes da natureza, `e`, `i` (ou `j`) e `pi`, dá o resultado `-1`.
Há quem acredite que este é o resultado mais belo de toda a matemática.
Remonta a cerca de 1740.

A notação polar `(r, θ)` é tão útil que existem funções incorporadas, `cis` (abreviação de `cos(x) + isin(x)`) e `cispi` (abreviação de `cos(πx) + isin(πx)`), que ajudam a construí-la de forma mais eficiente.

A utilidade da notação polar está na elegante fórmula de Euler, `ℯ^(iθ) = cos(θ) + isin(θ) = x + iy`, em que `|x + iy| = 1`.
Com `|x + iy| = r`, obtemos a forma polar mais geral `r * ℯ^(iθ) = r * (cos(θ) + isin(θ)) = x + iy`.
Repara que a forma exponencial, em particular, é compacta e fácil de manipular.

```julia-repl
julia> exp(1im * π) ≈ cis(π) ≈ cispi(1)
true
```

A igualdade aproximada acima deve-se ao facto de as funções [`cis`][cis] e [`cispi`][cispi] poderem dar resultados numéricos mais agradáveis, sobretudo `cispi`, quando se lida com argumentos que são fatores arbitrários de π (por exemplo, radianos!).

```julia-repl
julia> cis(π)
-1.0 + 0.0im

julia> cispi(1)
-1.0 + 0.0im

julia> θ = π/2;
julia> exp(im*θ)
6.123233995736766e-17 + 1.0im

julia> cis(θ)
6.123233995736766e-17 + 1.0im

julia> cispi(θ / π)  # θ/π == 1/2
0.0 + 1.0im
```

A propósito, isto torna os números complexos muito úteis para efetuar rotações e deslocamentos radiais em 2D.

Para as rotações, o número complexo `z = x + iy` pode ser rodado um ângulo `θ` em torno da origem com uma simples multiplicação: `z * ℯ^(iθ)`.
Repara que `x` e `y` aqui são apenas as coordenadas habituais no plano cartesiano real a duas dimensões, e que um ângulo positivo resulta numa rotação no sentido *contrário ao dos ponteiros do relógio*, enquanto um ângulo negativo resulta numa rotação no sentido *dos ponteiros do relógio*.

De forma igualmente simples, um deslocamento radial `Δr` pode ser feito somando-o à magnitude `r` de um número complexo na forma polar (por exemplo, `z = r * ℯ^(iθ)` -> `z' = (r + Δr) * ℯ^(iθ)`).
Repara como a parte angular se mantém igual e só a magnitude, `r`, varia, como seria de esperar.

## Secção opcional: perguntas frequentes sobre números complexos

Podes saltar esta parte, a não ser que tenhas interesse.

### Isto não é uma coisa nova e estranha da matemática pura?

Era estranho e novo no século XVI.

500 anos depois, é central para a maior parte da engenharia e das ciências físicas.

### Porque é que alguém usaria isto?

Acontece que os números complexos são a forma mais simples de descrever tudo o que roda ou que tem propriedades ondulatórias.
Por isso, são amplamente usados em engenharia eletrotécnica, processamento de áudio, física, videojogos e navegação, para mencionar apenas algumas aplicações.

Vês coisas a rodar.
Pode ser que os números complexos não façam o mundo girar, mas são ótimos para explicar _o que acontece_ quando o mundo gira: olha para qualquer imagem de satélite de uma grande tempestade.

De forma menos óbvia, o som é ondulatório, a luz é ondulatória, os sinais de rádio são ondulatórios e até a economia do teu país é, pelo menos em parte, ondulatória.

Muito deste processamento de ondas pode ser feito com funções trigonométricas (`sin()` e `cos()`), mas isso torna-se confuso muito depressa.

As exponenciais complexas são ___muito___ mais fáceis de usar.

### Mas eu não preciso de números complexos!

Só é verdade se viveres numa caverna e andares a procurar comida.

Se estás a ler isto em qualquer tipo de ecrã, dependes totalmente de alguns avanços úteis do século XX, alcançados através do uso de números complexos.

1. __Chips semicondutores__.
    - Não fazem sentido na física clássica e só podem ser explicados (e concebidos) pela mecânica quântica (MQ).
    - Na MQ, tudo tem valores complexos, por definição. (_é tudo ondas até ao fundo_)

2. __O algoritmo da Transformada Rápida de Fourier__.
    - A FFT é uma aplicação dos números complexos e está em _tudo_ o que se relaciona com transmissão de som, processamento de áudio, fotografias e vídeo.

    - O MP3 e outros formatos de áudio usam a FFT para compressão, o que permite que caiba mais áudio num espaço de armazenamento menor.
    - A compressão JPEG e o vídeo MP4, entre muitos outros formatos de imagem e vídeo, também usam a FFT para compressão.

    - A FFT é também usada nos filtros digitais que permitem às torres de telemóvel separar o teu sinal pessoal do de todos os outros.

Por isso, provavelmente usas tecnologia que depende de cálculos com números complexos milhares de vezes por segundo.
