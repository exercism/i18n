# Introdução

## Código sem desvios

O conceito de condicionais apresenta o `jcc`, a família de instruções para desviar com base numa condição.
Um `jcc` transfere a execução para outro ponto do programa apenas se a sua condição se verificar.

No entanto, as CPUs modernas são rápidas e capazes de executar muitas instruções em paralelo.
Seria demasiado dispendioso bloquear todo o trabalho enquanto a CPU espera por uma verificação da condição em tempo de execução.

É por isso que, internamente, a CPU não espera.
Usa um **preditor de desvios** para adivinhar o resultado de uma condição e começa a executar _especulativamente_ o caminho previsto.

Se a previsão estiver correta, a execução prossegue como se não houvesse desvio.
No entanto, se a previsão estiver errada, a CPU tem de _descartar o trabalho feito_ no caminho previsto e recomeçar no caminho correto.

A isto chama-se uma **previsão de desvio incorreta**, e é dispendiosa, provocando um atraso.

Quando um desvio é difícil de prever, essas previsões incorretas acumulam-se.
Nesses casos, por vezes é preferível evitar o desvio por completo, para que as mesmas instruções sejam executadas independentemente da condição.
Ao código que escolhe entre valores sem usar um `jcc` chama-se **código sem desvios**.

Há várias formas de estruturar o código para que desvie menos vezes, ou para que os desvios que tem sejam mais previsíveis.
Em particular, o x86-64 fornece duas famílias de instruções que são habitualmente usadas para escrever código sem desvios.

### Movimentos condicionais

A família de instruções `cmovcc` copia o operando de origem para o destino apenas se uma condição específica se verificar.
Caso contrário, o destino fica inalterado.

O sufixo `cc` segue a mesma nomenclatura que em `jcc`, com o mesmo significado:

| instrução | move se                              |
|-------------|--------------------------------------|
| `cmove`     | A == B depois de `cmp A, B`              |
| `cmovne`    | A != B depois de `cmp A, B`              |
| `cmovl`     | A < B (com sinal) depois de `cmp A, B`      |
| `cmovb`     | A < B (sem sinal) depois de `cmp A, B`    |
| `cmovg`     | A > B (com sinal) depois de `cmp A, B`    |
| `cmova`     | A > B (sem sinal) depois de `cmp A, B`    |

As regras são semelhantes às de `jcc`:

1. `l` e `g` são usados para comparações com sinal, e `b` e `a`, para comparações sem sinal.
2. Acrescentar `e` a um sufixo inclui a igualdade.
3. Acrescentar `n` nega a condição.
4. Há também variantes que se referem ao facto de o sinalizador estar definido.
   Por exemplo, `cmovz` e `cmovc`.

Considera o valor absoluto de um inteiro com sinal em `rdi`, devolvido em `rax`.
Escrita com `jcc`, a função seleciona um de dois caminhos:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Escrita com `cmovcc`, ambos os valores candidatos são calculados incondicionalmente e o movimento condicional escolhe um deles:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

A versão sem desvios executa sempre as mesmas instruções.
Não há nenhum `jcc` para o preditor adivinhar.

O destino de um `cmovcc` tem de ser um registo.
A origem pode ser um registo ou uma posição de memória, mas não um valor imediato.

~~~~exercism/note
No código acima, a instrução `neg` define vários sinalizadores de acordo com o resultado, incluindo o sinalizador de sinal (SF).
Isto significa que o `cmp rdi, 0` pode ser eliminado por completo:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Para `rdi` positivo, `neg` produz um resultado negativo e SF == 1, pelo que `cmovs` restaura `rdi`.
Para `rdi` igual a zero ou negativo, `neg` produz um resultado não negativo e SF == 0, pelo que `rax` mantém o valor negado (que é o valor absoluto correto).

Embora `cmp` seja a principal forma de comparar valores em código assembly, muitas instruções também definem sinalizadores de acordo com o seu resultado.
A lista completa dos sinalizadores que uma instrução afeta costuma estar indicada na sua [referência][reference].
No caso concreto de `neg`, são o SF, o ZF, o CF, o OF e o PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

### Definição condicional

A família de instruções `setcc` define o operando de destino como `1` se uma condição específica se verificar, e como `0` caso contrário.
O destino é sempre um _operando de 8 bits_.

O sufixo `cc` segue a mesma nomenclatura que em `jcc` e `cmovcc`.
Por exemplo, o `setz` define o destino como `1` se `ZF == 1` e como `0` caso contrário.

Como o destino tem 8 bits, é comum seguir o `setcc` com um `movzx` quando é preciso um valor mais largo:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Este é um idioma comum para transformar o resultado de uma comparação num inteiro `0` ou `1`.
