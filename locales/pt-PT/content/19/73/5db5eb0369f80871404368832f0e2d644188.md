# Sobre

A esta altura do currículo, já viste muitas definições de funções.
Normalmente, eram apresentadas sem grandes comentários sobre o resultado no REPL:

```julia-repl
julia> f(x) = x^2
f (generic function with 1 method)
```

Porque é que aparece _"generic function with 1 method"_?

Suponhamos que queremos ser mais específicos quanto aos tipos dos argumentos.

```julia-repl
julia> f(x::Integer) = x^2
f (generic function with 2 methods)

julia> f(x::Real) = x^2
f (generic function with 3 methods)
```

Ou podíamos alterar o número de argumentos:

```julia-repl
julia> f(x, y) = x * y
f (generic function with 4 methods)
```

Parece que as novas definições da mesma função se chamam "métodos".
Os métodos são acrescentados a uma lista, em vez de substituírem a definição antiga.

Podemos listar os métodos facilmente:

```julia-repl
julia> methods(f)  # output edited for brevity
# 4 methods for generic function "f" from Main:
 [1] f(x, y)
 [2] f(x::Integer)
 [3] f(x::Real)
 [4] f(x)
 ```

Se chamarmos a função `f`, Julia sabe de alguma forma qual o método a usar:

```julia-repl
julia> f(2.5)  # Float64
6.25

julia> f(2)  # Int64
4

julia> f(2, 3)  # Int64, Int64
6
```

## O que é uma função?

De acordo com o [manual][function], uma função é um objeto que mapeia um tuplo de argumentos para um valor devolvido.
É uma definição próxima da que os matemáticos usam.

Normalmente pensamos nos argumentos da função em `f(2, 3)` como dois elementos separados, mas o compilador vê-os como um único [tuplo][tuple].
Isto é verdade mesmo para um único argumento (embora tenhamos de acrescentar uma vírgula para que fique mais claro):

```julia-repl
julia> typeof( (2, 3) )
Tuple{Int64, Int64}

julia> typeof( (2,) )
Tuple{Int64}
```

Vendo a função como uma caixa negra, podemos dizer que entra um tuplo e sai um valor devolvido.
Mais formalmente, o tuplo é _mapeado_ para um valor devolvido.

## Como é que as funções lidam com diferentes números e tipos de argumentos?

A isto chama-se geralmente ["polimorfismo"][polymorphism].

Tem sido um tema central na informática durante várias décadas, e têm sido adotadas abordagens diferentes.

A abordagem de Julia é invulgar, embora não seja única.

- As funções são ["genéricas"][generic], o que significa que podem ter vários métodos associados.
- As funções são apenas nomes, até lhes serem associados métodos.
- Os métodos podem ser acrescentados conforme necessário, potencialmente em grande número (o operador `+` é uma função com 161 métodos, atualmente).
- Quando uma função é chamada, Julia examina a assinatura da chamada: o número de argumentos e o tipo atual de cada um.
- É selecionado o método que corresponde mais de perto à assinatura da chamada.
  - Em geral, o número de argumentos tem de coincidir exatamente (embora o operador [splat/slurp][splat] `...` possa contornar isto em parte).
  - São preferidos os métodos cujos tipos correspondem exatamente à assinatura da chamada.
  - Se for necessário, Julia analisa os supertipos de cada argumento da assinatura da chamada para encontrar o método mais próximo e mais específico.
- O método escolhido é [`dispatched`][dispatch] com os argumentos dados e devolve um resultado.
- Se não for encontrado nenhum método adequado, é gerado um [`MethodError`][methoderror].

Repara que Julia tem tipagem dinâmica, por isso o despacho de métodos acontece em _tempo de execução_.

## Despacho múltiplo: um exemplo

A secção anterior tinha muitas palavras, por isso vamos traduzir estas ideias para código.
Para simplificar, as funções abaixo têm apenas um argumento, mas não é invulgar encontrar funções com dezenas de argumentos (por exemplo, em pacotes de gráficos ou em aprendizagem automática).

Começa por definir alguns tipos personalizados, para representar formas geométricas.

```julia-repl
julia> abstract type Shape end

julia> struct Circle <: Shape
           radius::Float64
       end

julia> struct Square <: Shape
           side::Float64
       end

julia> struct Rectangle <: Shape
           length::Float64
           width::Float64
       end
```

A seguir, podemos definir métodos para calcular a área de cada forma.
Cada um recebe um argumento, de um tipo concreto e definido pelo utilizador diferente em cada caso.

```julia-repl
julia> area(c::Circle) = π * c.radius^2
area (generic function with 1 method)

julia> area(s::Square) = s.side^2
area (generic function with 2 methods)

julia> area(r::Rectangle) = r.length * r.width
area (generic function with 3 methods)
```

Agora podemos criar algumas formas e calcular as áreas, confiando no mecanismo de despacho de Julia para usar a fórmula correta em cada caso.

```julia-repl
julia> circle = Circle(2.3)
Circle(2.3)

julia> area(circle)  # call signature Tuple{Circle}
16.619025137490002

julia> square = Square(1.6)
Square(1.6)

julia> area(square)  # call signature Tuple{Square}
2.5600000000000005

julia> rectangle = Rectangle(1.4, 2.1)
Rectangle(1.4, 2.1)

julia> area(rectangle)  # call signature Tuple{Rectangle}
2.94
```

## [Métodos paramétricos][parametric]

As assinaturas de métodos podem receber valores de tipo fictícios, de forma mais ou menos semelhante aos tipos paramétricos.

A sintaxe é peculiar, exigindo uma cláusula `where`:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T} = true
same_type (generic function with 1 method)

julia> same_type([1, 2], 3)
true

julia> same_type([1, 2], "three")
ERROR: MethodError: no method matching same_type(::Vector{Int64}, ::String)
```

O exemplo acima exige que ambos os argumentos usem o mesmo tipo `T`, seja ele qual for.

Podemos ser mais específicos impondo uma restrição a `T`:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T<:Number} = true
same_type (generic function with 2 methods)
```

Com este método, só os tipos numéricos idênticos devolvem `true`.

É possível usar várias variáveis fictícias, separadas por vírgulas na cláusula `where`.
Os dois métodos seguintes são parecidos:

```julia-repl
julia> func(v::Vector{Number}, x::Number) = true
func (generic function with 1 method)

julia> func(v::Vector{S}, x::T) where {S<:Number, T<:Number} = true
func (generic function with 2 methods)
```

Uma diferença é que os valores de tipo `S` e `T` podem ser usados no corpo da função do segundo método.
É o tipo de truque que podes não usar muitas vezes, mas que em certas circunstâncias pode poupar muitas dores de cabeça.

Por exemplo, na seguinte definição de tipo paramétrico, os campos têm de ser do mesmo tipo `T`, que está restringido a ser um subtipo de `Real`:
```julia
struct Point{T<:Real}
    x::T
    y::T
end
```
Esta definição de `Point` aceita um `x` e um `y` do mesmo tipo, ou pode aceitar um `x` e um `y` de tipos diferentes, mas nesse caso é preciso indicar um tipo de conversão explícito.
```julia-repl
julia> Point(4, 5)
 Point{Int64}(4, 5)

julia> Point(3.5, 2)
 MethodError: no method matching Point(::Float64, ::Int64)    # Output truncated for brevity

julia> Point{Float32}(3.5, 2)
 Point{Float32}(3.5f0, 2.0f0)

julia> Point{Int64}(3.5, 2) 
 InexactError: Int64(3.5)      # Output truncated for brevity
```
Embora este nível de controlo sobre os tipos possa ser desejável, também pode ser útil ter um pouco de abstração.
```julia
Point(x::T, y::S) where {T<:Real, S<:Real} = Point{promote_type(T,  S)}(x, y)
```
Este construtor externo proporciona isso ao permitir que um `Point` aceite tipos não homogéneos para `x` e `y` sem especificar explicitamente o tipo de conversão.
Os valores de tipo `T` e `S` são usados no corpo da função, em `promote_type(T, S)`, para fornecer o tipo de conversão explícito para a definição original.
```julia-repl
julia> Point(3.5, 2)
 Point{Float64}(3.5, 2.0)
```

## Comparação com outras linguagens

Como Julia examina todos os argumentos ao selecionar um método, a isto chama-se [`multiple dispatch`][multiple-dispatch].

Algumas outras linguagens permitem o despacho múltiplo, como o Common Lisp, embora raramente seja tão central para o desenho da linguagem como em Julia.

Em contrapartida, numa linguagem orientada a objetos (OO), por exemplo em Ruby, os métodos são normalmente chamados sobre uma [instância][instance].
A definição passa agora a privilegiar o primeiro argumento (com um nome como `self` ou `this` na definição), e o nome do método é acrescentado à instância depois de um ponto para o chamar:

```ruby
irb(main):004:0> "abc".sub("b", "*")
=> "a*c"
```

A isto chama-se [`single dispatch`][single-dispatch], pois só a classe da instância (da string "abc" no exemplo acima) é usada para escolher um método.

Algumas linguagens OO de tipagem estática suportam polimorfismo de métodos, que é um pouco parecido com o despacho múltiplo.
A grande diferença é que a seleção de métodos só acontece em _tempo de compilação_.

As linguagens funcionais tendem a ter apenas uma definição de função, com algum tipo de expressão Select/Case/Match para lidar com as várias possibilidades.
Escreves a tua própria lógica, normalmente com a ajuda de uma sintaxe concisa de correspondência de padrões, que Julia não tem.
Claro que Julia também faz uma forma de correspondência de padrões, mas no despacho e não dentro do corpo da função.

## Conclusão

O despacho múltiplo é muito flexível e muito eficiente em Julia, por isso é amplamente utilizado.

Como sugere o exemplo dos 161 métodos para `+`, os programadores de Julia procuram definir métodos com tipos bem específicos.
Somar dois inteiros é muito diferente de somar dois números de vírgula flutuante ao nível do bytecode, e somar um inteiro a um número de vírgula flutuante acrescenta ainda a complicação da promoção de tipos.

Quanto mais específico for o tipo, mais otimizações pode fazer o compilador: algo de importância marginal num exercício simples no Exercism, mas vital para o desempenho nas grandes simulações numéricas para as quais Julia foi concebida.

_Se sabes que valores de entrada vai receber um método, diz ao compilador!_
