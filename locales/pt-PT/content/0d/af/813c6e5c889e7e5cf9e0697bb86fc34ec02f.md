# Exceções

Algumas rotinas não conseguem responder. Quando lhe pedem um prop que não está na mesa, `count_of` não tem número para dar, e zero seria uma mentira, porque zero significa «não temos nenhum desses», não «não existe tal coisa».

Uma **exceção** é a forma de uma rotina dizer que não consegue responder.

## Lançar

`raise` abandona a rotina e entrega um valor a quem a chamou.

```sather
   count_of(props : FMAP{STR,INT}, prop : STR) : INT is
      if ~props.has_ind(prop) then
         raise "Unknown prop: " + prop;
      end;
      return props.get(prop);
   end;
```

Nada depois de um `raise` é executado. A rotina não devolve nada, por isso não há resposta para verificar nem forma de quem a chamou continuar como se houvesse.

O valor lançado é habitualmente uma string que diz o que correu mal.

## Capturar

`protect` executa um pedaço de código, preparado para que ele lance uma exceção.

```sather
   protect
      taken ::= count_of(props, prop);
      #OUT + "There are " + taken;
   when $STR then
      #OUT + "Cannot: " + exception.str;
   end;
```

Se nada for lançado, a parte a seguir ao `protect` é executada e o ramo `when` é ignorado. Se algo for lançado, o resto da parte `protect` é abandonado e o `when` correspondente é executado em vez disso.

`when $STR then` captura uma string lançada. `exception` é o valor que foi lançado, disponível dentro do ramo.

## Passar adiante

Uma rotina que não captura uma exceção não tem de fazer nada em relação a isso. A exceção viaja para fora, através de cada rotina que a chama, até que algo a capture:

```sather
   take_one(props : FMAP{STR,INT}, prop : STR) : INT is
      -- If this raises, take_one raises too. Nothing here says so.
      have ::= count_of(props, prop);
      ...
   end;
```

É essa a razão de ser das exceções. A rotina que deteta o problema e a rotina que sabe o que fazer em relação a ele normalmente não são a mesma rotina, e tudo o que está pelo meio pode ignorá-lo.
