# Instruções

A direção está a começar a aplicar princípios darwinianos ao projeto [exercise:csharp/remote-control-competition]() do carro de controlo remoto. Os programadores foram divididos em duas equipas, _Red_ e _Blue_, e têm a missão de melhorar o design de forma independente uma da outra. Não precisam de se preocupar com as decisões de design da outra equipa.

Pedem-te que dês uma vista de olhos ao código e vejas qual a melhor forma de combinar os dois esforços para fins de teste.

## 1. Encontra uma forma mais adequada de isolar o código das duas equipas

Usa `namespaces` para expressar melhor a intenção do código.

Atualmente, tipos importantes como `Motor` e `Telemetry`, para não falar do próprio `RemoteControlCar`, estão aninhados dentro de uma classe estática exterior, `<Color>RemoteControlCarTeam`. O único objetivo da classe exterior é permitir que tipos com o mesmo nome coexistam no programa. Isso expressa-se melhor com um namespace. Vais ver no próximo exercício que, para estes fins, um `namespace` tem vantagens sobre uma `static class`.

## 2. Simplifica o sistema de nomes

Embora a direção faça questão de que as equipas se chamem `RedRemoteControlCarTeam` e `BlueRemoteControlCarTeam` nas definições, os nomes são bastante pesados quando nos referimos às equipas. Encontra uma forma de usar os identificadores mais curtos `Red` e `Blue` ao construir os carros.
