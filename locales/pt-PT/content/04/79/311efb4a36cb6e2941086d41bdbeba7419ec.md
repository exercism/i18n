# Introdução

## A interface de erro

O tratamento de erros **não** é feito com exceções em Go.
Em vez disso, os erros são _valores_ normais de tipos que implementam a interface `error` incorporada.
A interface `error` é muito reduzida.
Contém apenas um método, `Error()`, que devolve a mensagem de erro como uma string.

```go
type error interface {
  Error() string
}
```

Sempre que defines uma função na qual pode ocorrer um erro durante a execução que tenha de chegar a quem a chama, tens de incluir `error` como um dos tipos de retorno.
Se a função tiver vários valores devolvidos, por convenção `error` é sempre o último.

```go
func DoSomething() (int, error) {
  // ...
}
```

## Criar e devolver um erro simples

Nem sempre tens de implementar a interface de erro tu próprio.
Para criar um erro simples, podes usar a função `errors.New()`, que faz parte do pacote `errors` da biblioteca padrão.
A única coisa que precisas de passar é a mensagem de erro como uma string, e `errors.New()` encarrega-se de criar um valor que contém a tua mensagem e implementa a interface `error`.

Se a função devolver um erro, é boa prática devolver o valor zero para todos os outros valores devolvidos:

```go
func DoSomething() (SomeStruct, int, error) {
  // ...
  return SomeStruct{}, 0, errors.New("failed to calculate result")
}
```

~~~~exercism/caution
Não deves assumir que todas as funções devolvem valores zero para os outros valores devolvidos se houver um erro.
É boa prática assumir que não é seguro usar nenhum dos outros valores devolvidos se ocorreu um erro.
As únicas exceções são os casos em que a documentação afirma claramente que os outros valores devolvidos são relevantes em caso de erro.
~~~~

Se quiseres usar um erro simples destes em vários sítios, deves declarar uma variável para o erro em vez de usares `errors.New` em linha.
Por convenção, o nome da variável deve começar por `Err` ou `err` (consoante seja exportada ou não).
Estas variáveis de erro são muitas vezes chamadas _erros sentinela_.

```go
import "errors"

var ErrNotFound = errors.New("resource was not found")

func DoSomething() error {
  // ...
  return ErrNotFound
}
```

Devolve `nil` no erro para sinalizar que não houve erros durante a execução da função:

```go
func Foo() (int, error) {
  return 10, nil
}
```

## Verificação de erros

Se chamares uma função que devolve um erro, é comum guardar o valor do erro numa variável chamada `err`.
Antes de usares o resultado propriamente dito da função, tens de verificar que não houve erro.

Para evitares aninhar o "caminho feliz" do teu código, os casos de erro devem ser tratados primeiro.
Podemos usar `==` e `!=` para comparar o erro com `nil` e sabemos que houve um erro quando `err` não é `nil`.

```go
func processUserFile() error {
	file, err := os.Open("./users.csv")
	if err != nil {
		return err
	}

	// do something with file
}
```

Na maioria das vezes, o erro é devolvido pela pilha de funções para cima, tal como mostra o exemplo acima.
Outra forma de tratar o erro pode ser registá-lo e continuar com outra operação.
É boa prática devolver o erro ou registá-lo, nunca as duas coisas.

Como a maioria das funções em Go inclui um erro como um dos valores devolvidos, vais ver e usar o padrão `if err != nil` por todo o lado no código Go.

## Tipos de erro personalizados

Se quiseres que o teu erro inclua mais informação do que apenas a string da mensagem de erro, podes criar um tipo de erro personalizado.
Como já foi referido, tudo o que implemente a interface `error` (ou seja, que tenha um método `Error() string`) pode servir de erro em Go.

Normalmente, usa-se uma struct para criar um tipo de erro personalizado.
Por convenção, os nomes dos tipos de erro personalizados devem terminar em `Error`.
Além disso, é melhor definir o método `Error() string` com um recetor ponteiro; vê este [comentário do Stackoverflow][stackoverflow-errors] para perceberes o raciocínio.
Repara que isto significa que tens de devolver um ponteiro para o teu erro personalizado; caso contrário, não conta como `error`, porque o valor não-ponteiro não fornece o método `Error() string`.

```go
type MyCustomError struct {
  message string
  details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.message, e.details)
}

func someFunction() error {
  // ...
  return &MyCustomError{
    message: "...",
    details: "...",
  }
}
```
