# Anexo às instruções

## Personalizar e lançar exceções

Por vezes, é necessário personalizar e [`raise`](https://docs.python.org/3/tutorial/errors.html#raising-exceptions) exceções no teu código. Quando o fazes, deves incluir sempre uma **mensagem de erro significativa** que indique qual é a origem do erro. Isto torna o teu código mais legível e ajuda bastante a depurar.

Podes criar exceções personalizadas através de novas classes de exceção (vê [`classes`](https://docs.python.org/3/tutorial/classes.html#tut-classes) para mais detalhes), que são, tipicamente, subclasses de [`Exception`](https://docs.python.org/3/library/exceptions.html#Exception).

Nas situações em que sabes que a origem do erro será derivada de um determinado tipo de exceção, podes optar por herdar de um dos [`built in error types`](https://docs.python.org/3/library/exceptions.html#base-classes) sob a classe _Exception_. Mesmo ao lançar o erro, deves continuar a incluir uma mensagem significativa.

Este exercício em particular pede que cries duas _exceções personalizadas_. Uma exceção a ser [lançada](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement)/"thrown" quando o teu buffer circular estiver **cheio**, e outra para quando estiver **vazio**. Os testes só passam se personalizares as exceções adequadas, as lançares com `raise` e incluíres mensagens de erro adequadas.

Para personalizar uma `built-in exception`, cria uma `class` que herde dessa exceção. Quando lanças a exceção personalizada com uma mensagem, escreve a mensagem como argumento do tipo `exception`:

```python
# subclassing the built-in BufferError to create BufferFullException
class BufferFullException(BufferError):
    """Exception raised when CircularBuffer is full.

    message: explanation of the error.

    """
    def __init__(self, message):
        self.message = message

        
# raising a BufferFullException
raise BufferFullException("Circular buffer is full")
```
