# Mutabilidade

A mutabilidade é uma propriedade de uma determinada ligação em Rust. Uma ligação é imutável ou mutável. O valor de uma ligação imutável não pode ser alterado; o valor de uma ligação mutável pode ser alterado. Por predefinição, todas as ligações são imutáveis.

## Ligações

Uma ligação é a associação entre um determinado nome de variável, tal como aparece no código-fonte, e uma determinada região de memória, tal como existe durante a execução. Em rigor, as ligações só existem durante a compilação: antes da compilação, não há memória efetivamente alocada e, depois da compilação, o código máquina lida exclusivamente com endereços de memória em vez de variáveis com nome.

Normalmente, as ligações são criadas com a palavra-chave `let`. Além disso, criam-se ligações a partir de parâmetros de função e em certas outras circunstâncias.

As ligações podem ter várias propriedades, das quais a mais importante é a mutabilidade. Uma ligação mutável é aquela em que é legal alterar o valor da memória associada. O Rust controla e impõe rigorosamente a mutabilidade de cada ligação, para ajudar a garantir que os programas estão corretos, rejeitando os programas que tentam, incorretamente, modificar uma ligação que devia ser imutável.

## Mutabilidade

Na prática, a mutabilidade é muitas vezes simples. Ao usar a palavra-chave `mut` na definição da ligação, ficas com a capacidade de alterar o valor.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### Despromover de mutável para imutável

Uma ligação pode sempre ser despromovida de mutável para imutável. Esta operação é transparente.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### Promover de imutável para mutável

Em geral, é possível promover um valor de imutável para mutável sempre que a propriedade é transferida.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

Em `(1)`, a propriedade da string é transferida de `x` para `y`, o que permite promover o valor a mutável.

### Mutabilidade nos parâmetros de função

Há duas formas diferentes de os parâmetros de função serem mutáveis. O primeiro método, mais comum, assemelha-se à passagem por referência em C:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

Neste exemplo, a mutabilidade foi anotada explicitamente em três locais. As três declarações de mutabilidade são necessárias para que as referências mutáveis funcionem.
Em `(2)`, a ligação `x` é declarada mutável. Esta ligação é a proprietária de topo do valor.
Em `(3)`, esse valor é emprestado mutavelmente, para ser passado à função `increment`.
Em `(1)`, cria-se uma nova ligação mutável `n` para a referência adequada.

Há outro estilo de mutabilidade de parâmetros, menos comum, mas ainda por vezes útil. Neste estilo, o valor é propriedade da função, mas a ligação é mutável.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

Este exemplo exige menos anotações explícitas, porque na verdade é uma transferência de propriedade com promoção de mutabilidade incorporada. Funciona porque `i32` é um tipo `Copy`, que copia os dados de forma transparente.
Em `(1)`, declaramos que `increment_internally` aceita como parâmetro um `i32` mutável de que passa a ser proprietária, com o nome `n`.
Em `(2)`, declaramos que `x` é uma ligação imutável ao valor `1`.
Em `(3)`, `x` é copiado para um novo local na memória. `x` permanece imutável. `n` é mutável.

É claro que é possível combinar as formas, criando uma ligação mutável para uma referência mutável (`mut n: &mut i32`, etc.), mas raramente é isso que se pretende na prática.

### Mutabilidade sem `let`

Várias construções em Rust (`if let`, `match`, etc.) também podem criar ligações. Estas ligações também podem ser mutáveis.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

Este exemplo produz primeiro `v = Some(2)` e depois `v = None`.

## Sombreamento

É possível, e muitas vezes idiomático, reutilizar um nome de variável à medida que um determinado valor é transformado, redeclarando-o com múltiplas invocações de `let`. A isto dá-se o nome de sombreamento.

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

No entanto, não se trata de um caso de mutabilidade; em princípio, os valores originais continuam presentes. No caso de tipos que não implementam `Drop`, o compilador pode optar por modificar um local de memória em vez de alocar um novo. Contudo, nunca o fará no caso de um tipo que implementa `Drop` ou se a ligação antiga for novamente utilizada.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
