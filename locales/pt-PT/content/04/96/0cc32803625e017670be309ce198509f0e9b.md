# Geradores de testes

A track de C# usa um [gerador de testes](https://exercism.org/docs/building/tooling/test-generators) para gerar automaticamente os testes dos exercícios de prática.
Aproveita o facto de a maioria dos exercícios definidos no [repositório problem-specifications](https://github.com/exercism/problem-specifications/) ter também um ficheiro `canonical-data.json`, que contém entradas e saídas de teste normalizadas que podem ser usadas para implementar o exercício.

## Passos

Para gerar os testes de um exercício de prática, o gerador de testes:

1. Lê os casos de teste do exercício a partir do seu ficheiro `canonical-data.json`
2. Usa o ficheiro `tests.toml` para omitir os casos de teste excluídos
3. Renderiza os casos de teste com o modelo de gerador do exercício
4. Formata o modelo renderizado com o Roslyn
5. Escreve o modelo formatado no ficheiro de teste do exercício

### Passo 1: ler o ficheiro `canonical-data.json`

O gerador de testes analisa os casos de teste do `canonical-data.json` do exercício com o [namespace System.Text.Json](https://learn.microsoft.com/en-us/dotnet/api/system.text.json).

Como alguns dados canónicos usam aninhamento, o caso de teste analisado inclui um campo `path` adicional, que contém as propriedades `description` de quaisquer elementos superiores, bem como a própria propriedade `description` do caso de teste.

### Passo 2: omitir os testes excluídos do ficheiro `tests.toml`

Cada exercício tem um ficheiro `tests.toml`, no qual podem ser excluídos ou desativados testes individuais.
O gerador de testes remove todos os casos de teste marcados como excluídos (`include = false`).

### Passo 3: renderizar os casos de teste

Os casos de teste (potencialmente transformados) são depois passados ao ficheiro `.meta/Generator.tpl`, que define como os testes devem ser renderizados com base nesses casos de teste.

### Passo 4: formatar o modelo renderizado com o Roslyn

O modelo renderizado é depois formatado com o [Roslyn](https://github.com/dotnet/roslyn).
Isto tem as seguintes vantagens:

- Os exercícios são formatados de forma consistente
- Não precisas de te preocupar muito com espaços em branco e alinhamento quando escreves modelos

### Passo 5: escrever o modelo renderizado no ficheiro de teste do exercício

Por fim, o resultado do modelo renderizado é escrito no ficheiro de teste do exercício.

## Modelos

Os modelos são renderizados com a [biblioteca Scriban](https://github.com/scriban/scriban/).

## Interface de linha de comandos

Há duas formas de executar o gerador de testes:

1. `bin/update-tests.ps1`: atualiza os testes de todos os exercícios que têm um modelo de gerador
2. `bin/update-tests.ps1 -e <slug>`: atualiza os testes do exercício especificado, se tiver um modelo de gerador
