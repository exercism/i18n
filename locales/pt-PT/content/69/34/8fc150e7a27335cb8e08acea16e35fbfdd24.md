# Introdução

**Single instruction, multiple data (SIMD)** é uma forma de paralelismo ao nível do hardware.
A mesma computação é realizada pela CPU sobre vários elementos ao mesmo tempo.

Considera, por exemplo, a soma elemento a elemento de dois arrays de quatro números de vírgula flutuante de 32 bits.
Uma implementação escalar emitiria quatro instruções `addss` separadas, uma por elemento.
Uma implementação SIMD usa uma única `addps` para fazer as quatro adições em paralelo.
Isso permite realizar quatro vezes mais trabalho por instrução.

Em assembly x86-64, as instruções SIMD são normalmente executadas com registos `xmm`.
Algumas dessas instruções operam sobre inteiros.
Outras operam sobre números de vírgula flutuante.

Esses inteiros ou números de vírgula flutuante são chamados **empacotados**.
Cada um ocupa um espaço, a que se chama **via**, dentro do mesmo registo.
As instruções SIMD operam normalmente em paralelo sobre valores na mesma posição da via nos dois operandos de origem.
O resultado de cada operação é armazenado na via que está na mesma posição no operando de destino.

Uma via não é um limite rígido.
É uma interpretação que cada instrução dá a uma sequência de bytes.
Um operando de 128 bits contém 16 bytes.
Dependendo da instrução, esses bytes podem ser interpretados como 16 vias de _1 byte_, 8 vias de _2 bytes_, 4 vias de _4 bytes_, 2 vias de _8 bytes_, ou até uma única via de _16 bytes_.

Por exemplo, a instrução `addps` soma valores de vírgula flutuante empacotados de precisão simples (4 bytes).
Para esta instrução, cada bloco de 4 bytes num operando é uma via diferente.
Num operando de 128 bits (16 bytes):

| operando     | 4.ª via | 3.ª via | 2.ª via | 1.ª via |
|:-----------:|:--------:|:--------:|:--------:|:--------:|
| origem 1    |  1.5     |  2.1     | 6.2      | 3.4      |
|    +        |  +       |  +       | +        | +        |
| origem 2    |  0.5     |  8.26    | -13.4    | 22.9     |
|    =        |  =       |  =       | =        | =        |
| resultado   |  2.0     |  10.36   | -7.2     | 26.3     |

Por outro lado, um operando de 128 bits seria interpretado como tendo 2 vias no caso de `mulpd`.
Isto porque esta instrução realiza multiplicação empacotada sobre valores de precisão dupla (8 bytes):

| operando     | 2.ª via | 1.ª via |
|:-----------:|:--------:|:--------:|
| origem 1    |  4.2     |  2.1     |
|    *        |  *       |  *       |
| origem 2    |  1.0     |  92.4    |
|    =        |  =       |  =       |
| resultado   |  4.2     |  194.04  |

Neste conceito, vamos focar-nos numa pequena seleção de instruções SIMD.
Estas operam sobre valores de vírgula flutuante empacotados usando registos `xmm`.

## Instruções SIMD de vírgula flutuante

Como regra geral, as instruções SIMD que operam sobre valores de vírgula flutuante assumem uma forma de dois operandos.
O seu nome segue uma certa estrutura:

1. A operação realizada, com o mesmo nome da sua equivalente não SIMD (também chamada _escalar_) (por exemplo, `add`, `mul`, etc.).
2. Um sufixo `p` para indicar que a instrução opera sobre dados _empacotados_, na mesma posição anteriormente ocupada por um `s` (para dados _escalares_).
3. Um sufixo para indicar o tamanho de cada via, seguindo a mesma semântica da sua equivalente não SIMD (`s` para precisão simples e `d` para precisão dupla).

O nome empacotado é, portanto, obtido a partir do nome escalar substituindo o `s` (escalar) no meio do mnemónico por um `p` (empacotado).
O nome da operação e o sufixo de tamanho permanecem inalterados:

| escalar | empacotado | significado |
|---------|---------|----------------------------------------|
| `addss` | `addps` | somar, precisão simples (vias de 32 bits) |
| `addsd` | `addpd` | somar, precisão dupla (vias de 64 bits) |
| `mulss` | `mulps` | multiplicar, precisão simples |
| `mulsd` | `mulpd` | multiplicar, precisão dupla |

### Aritmética

As instruções SIMD aritméticas seguem a regra acima.
Alguns exemplos:

```x86asm
addps xmm0, xmm1 ; xmm0 = xmm0 + xmm1 (each 32-bit float at the same position)
subpd xmm2, xmm3 ; xmm2 = xmm2 - xmm3 (each 64-bit float at the same position)
mulps xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (each 32-bit float at the same position)
divpd xmm6, xmm7 ; xmm6 = xmm6 / xmm7 (each 64-bit float at the same position)
```

### Conversão entre precisões

Existem também instruções SIMD para converter entre valores de vírgula flutuante empacotados de precisão simples e de precisão dupla.
Seguem a mesma regra de nomenclatura, com cada `s` de _escalar_ substituído por um `p` de _empacotado_:

| escalar     | empacotado     | significado |
|------------|------------|----------------------------------------------|
| `cvtss2sd` | `cvtps2pd` | converter precisão simples em precisão dupla |
| `cvtsd2ss` | `cvtpd2ps` | converter precisão dupla em precisão simples |

Estas instruções ilustram o ponto anterior de que uma via é uma interpretação, não um limite rígido.
Os operandos de origem e de destino têm tamanhos de via diferentes, pelo que têm contagens de vias diferentes.

Para `cvtps2pd`, a origem (`ps`) tem 4 vias de precisão simples.
O destino (`pd`) tem 2 vias de precisão dupla.
Apenas as 2 vias inferiores da origem são lidas.
As 2 superiores são ignoradas:

| operando              | 4.ª via | 3.ª via | 2.ª via | 1.ª via |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| origem como `ps`      | ignorada | ignorada | 2.5      | 1.5      |
| destino como `pd`     |          |          | 2.5      | 1.5      |

Para `cvtpd2ps`, a origem (`pd`) tem 2 vias de precisão dupla.
O destino (`ps`) tem 4 vias de precisão simples.
Ambas as vias da origem são convertidas e escritas nas 2 vias inferiores do destino.
As 2 vias superiores do destino são colocadas a zero:

| operando              | 4.ª via | 3.ª via | 2.ª via | 1.ª via |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| origem como `pd`      |          |          | 4.0      | 3.0      |
| destino como `ps`     | 0        | 0        | 4.0      | 3.0      |

Alguns exemplos:

```x86asm
cvtps2pd xmm0, xmm1 ; xmm0 = xmm1 as 2 doubles (low 2 lanes of xmm1 are read)
cvtpd2ps xmm0, xmm1 ; xmm0 = xmm1 as 2 floats (in low 2 lanes; upper 2 zeroed)
```

### Operandos de memória

As instruções SIMD acima foram todas mostradas com operandos registo a registo.
Também podem receber um operando de memória como origem (mas **não** como destino).

O número de bytes lidos da memória é determinado pela instrução.
Por exemplo, `addps` lê 16 bytes (4 valores de vírgula flutuante de precisão simples).
`cvtps2pd`, em contrapartida, lê apenas 8 bytes (2 valores de vírgula flutuante de precisão simples), porque é tudo o que precisa como entrada.

```x86asm
addps    xmm0, [rsi]      ; xmm0 = xmm0 + 4 floats at [rsi]
mulpd    xmm1, [rsi + 16] ; xmm1 = xmm1 * 2 doubles at [rsi + 16]
cvtps2pd xmm2, [rsi + 8]  ; xmm2 = (2 floats at [rsi + 8]) converted to 2 doubles
```

Quando o operando de memória tem 16 bytes de largura, tem de estar _alinhado a 16 bytes_.
Uma localização de memória alinhada é aquela cujo endereço é um múltiplo do tamanho da operação (16 bytes, neste caso).

Para declarar memória alinhada, podes usar a diretiva `align` na secção .data e .rodata, ou `alignb`, na secção .bss:

```x86asm
section .rodata
align 16
mem1: dd 4.0, 3.5, 2.0, -1.0

section .data
align 16
mem2: dq 6.0, 2.1

section .bss
alignb 16
mem3: resb 16

section .text
fn:
    movaps xmm0, oword [rel mem1] ; loads 4 packed 32-bit floats in xmm0
    movapd xmm1, oword [rel mem2] ; loads 2 packed 64-bit floats in xmm1
    movaps oword [rel mem3], xmm0 ; stores 4 packed 32-bit floats in mem3
    ret
```

Os operandos de memória menores que 16 bytes, como a origem de 8 bytes de `cvtps2pd`, não têm requisitos de alinhamento.

### Carregar e armazenar valores

Existem quatro instruções que copiam 128 bits de valores de vírgula flutuante empacotados.
Estas operam entre dois registos `xmm`, ou entre um registo `xmm` e uma localização de memória:

| instrução | descrição                                                                       |
|-------------|-----------------------------------------------------------------------------------|
| `movaps`    | copia dados empacotados de precisão simples de, ou para, uma localização de memória _alinhada_     |
| `movups`    | copia dados empacotados de precisão simples de, ou para, uma localização de memória _não alinhada_   |
| `movapd`    | copia dados empacotados de precisão dupla de, ou para, uma localização de memória _alinhada_    |
| `movupd`    | copia dados empacotados de precisão dupla de, ou para, uma localização de memória _não alinhada_   |

Todas estas instruções podem ser usadas para copiar valores entre dois registos `xmm`.

Se a operação envolver uma localização de memória, `movaps` e `movapd` exigem que esta esteja _alinhada_.
`movaps` e `movapd` geram uma falha se receberem um endereço desalinhado.
Funcionam também como uma verificação de segurança de que a disposição dos teus dados é aquilo que pensas que é.

Por outro lado, `movups` e `movupd` podem ser usadas com qualquer localização de memória, alinhada ou não.

O prefixo de tamanho para um valor de 16 bytes em NASM é `oword`.

## Extensões SIMD

O SIMD tem sido alvo de desenvolvimento ativo no ecossistema x86-64 durante décadas.
Cada extensão à arquitetura traz novas instruções ou novas utilizações para instruções antigas.

Em particular, as extensões AVX e AVX2 introduzem algumas alterações relevantes.

Primeiro, suporte para registos SIMD de 256 bits, chamados `ymm`.
Estes estendem os registos `xmm` correspondentes, tal como `rax` contém `eax`.

Segundo, incluem suporte para variantes de 3 operandos para a maioria das instruções que operam sobre registos `xmm` (e `ymm`).
Isto inclui não só instruções SIMD, mas também aquelas que operam sobre valores de vírgula flutuante escalares.
Essas variantes seguem a mesma notação da sua equivalente SSE, com um `v` adicionado antes:

```x86asm
vaddsd xmm0, xmm1, xmm2   ; xmm0 = xmm1 + xmm2 (scalar sum of 64-bit floats)
vmulps xmm1, xmm3, xmm4   ; xmm1 = xmm3 * xmm4 (packed multiplication of 32-bit floats)
vmovupd ymm5, yword [mem] ; this copies 32 bytes from the location at mem to ymm5
```

Terceiro, o alinhamento exigido dos operandos de memória SIMD é relaxado.
Apenas movimentos explicitamente alinhados, como `vmovaps`, exigem este alinhamento.

Neste percurso, restringimo-nos a instruções e registos até às extensões SSE anteriores.
Isto é suficiente para ensinar os fundamentos e garante compatibilidade com uma vasta gama de CPUs.

No entanto, o executor de testes suporta totalmente AVX e AVX2, e até as extensões mais recentes que fazem parte do AVX-512.
Podes usá-las à vontade.

~~~~exercism/note
É boa prática seres consistente na utilização das variantes SIMD.
Tenta não misturar variantes SSE e AVX para as mesmas instruções.

Se a tua base de código misturar essas variantes, é boa prática usar `vzeroupper` depois de terminares o teu trabalho com AVX e antes de usares SSE.
Isto quebra cadeias de dependências e evita uma paragem dispendiosa quando a CPU transita entre os estados AVX e SSE.
~~~~
