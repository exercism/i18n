# Sobre

É possível aceder a carateres individuais de uma `String` com o mesmo método de indexação que se usa com os arrays.
No entanto, os [índices][string-indices] usados nas strings _não_ são números inteiros e não podem ser usados diretamente.
Em vez disso, têm de ser calculados a partir de outro índice conhecido, como `startIndex`, que aponta para a posição do primeiro caráter numa string não vazia, recorrendo aos métodos disponíveis nas bibliotecas [`String`][string-docs] e [`NSString`][nsstring-docs] (quando o módulo `Foundation` está importado, as strings em Swift têm acesso a todas as propriedades e métodos de NSString).

Por exemplo, dada a seguinte string:

```swift
let csv = "apple,pear,peach,orange,cherry,lime,goosberry"
```

Não se pode escrever `csv[21]` para obter o "g" de "orange"; em vez disso, é preciso calcular um valor do tipo `String.Index` e fornecer esse índice.
Repara que estes índices não se destinam a ser compreendidos por humanos.
São o que se chama _índices opacos_, pois não é preciso saber o que está lá dentro.

```swift
let index = csv.index(csv.startIndex, offsetBy: 21)
csv[index]
// "g"
print(index)
// prints Index(_rawBits: 1376513)
```

Tem em atenção, no entanto, que se o deslocamento não for um índice válido, isto é, se devolver um índice antes de `startIndex` ou depois de `endIndex`, a operação vai dar erro e o programa vai abaixo.
Para evitar este problema, podes especificar um índice limite.
Isto devolve um índice opcional e devolverá nil para índices que de outra forma seriam inválidos.

```swift
let tooFar = csv.index(csv.startIndex, offsetBy: 200)
// error: Execution was interrupted, reason: EXC_BAD_INSTRUCTION (code=EXC_I386_INVOP, subcode=0x0).
let tooFarButSafe = csv.index(csv.startIndex, offsetBy: 200, limitedBy: csv.endIndex)
// nil
```

Além disso, os índices não podem ser partilhados entre strings.
Por exemplo, usar o `index` do "g" de "orange" calculado acima para indexar a string `fam = "This is my family: 👨‍👩‍👦‍👦, this is our dog: 🐶, this is our cat: 🐱!"`, ou seja, `fam[index]`, vai fazer o teu programa ir abaixo.

Há muitas razões para tudo isto, mas, no fundo, resumem-se todas a "o Unicode é complicado".

De um modo geral, se precisas de acesso aleatório a carateres individuais, provavelmente queres usar outra estrutura de dados, como `Array<Character>`.

## Alguns métodos úteis

O Swift tem os métodos `first` e `last` para obter o primeiro e o último caráter de uma string.
Estes métodos devolvem um caráter opcional, por isso, se a string estiver vazia, devolvem nil.

```swift
let str = "Hello, world!"
print(str.first) // Prints Optional("H")
print(str.last)  // Prints Optional("!")
```

Também podes usar os métodos `prefix` e `suffix` para obter uma substring de uma string.
Estes métodos recebem um número inteiro como argumento e devolvem uma substring com os primeiros ou os últimos n carateres da string.

```swift
let str = "Hello, world!"
print(str.prefix(5)) // Prints "Hello"
print(str.suffix(6)) // Prints "world!"
```

## Análise em profundidade: indexação de Unicode

~~~~exercism/advanced

O [Unicode][unicode] é um padrão para codificar texto e inclui um grande número de carateres de muitas línguas e sistemas de escrita diferentes.
É um superconjunto do ASCII, o que significa que todos os carateres ASCII também são carateres Unicode.
O Unicode é uma codificação de comprimento variável, ou seja, alguns carateres ocupam mais bytes do que outros.
E a razão pela qual isso é importante será explicada na secção seguinte.

Por isso, temos de ir a outras línguas (além do inglês) para ver o problema na prática. Vejamos o caráter "ü" da língua alemã (repara que aqui estamos a usar a variante de 2 bytes; também existe uma versão de 1 byte).
Pode parecer à primeira vista um único caráter, mas na verdade são dois carateres: "u" e "¨". Por isso, se imprimisses o comprimento da string "ü", obterias 2 em linguagens como o Python.
No entanto, enquanto utilizadores ou programadores, diríamos que é um único caráter, e o Swift concorda connosco.
Mas porque é que o Swift faz isso e o Python não?
A resposta é que o Swift usa uma representação de strings diferente da do Python.
No Python, as strings são representadas como uma sequência de bytes, o que significa que o comprimento de uma string é o número de bytes que ocupa na memória.
No Swift, as strings são representadas como uma sequência de carateres, o que significa que o comprimento de uma string é o número de carateres que contém.
Esta é uma distinção muito importante, porque significa que, no Swift, o comprimento de uma string não é necessariamente igual ao número de bytes que ocupa na memória.
É isto, por sua vez, que faz com que não possamos usar números inteiros para indexar strings.
