# Instruções

Estás a escrever código para o sistema de dados no chão de fábrica de uma fábrica de componentes automóveis.
Os componentes do motor e do chassis passam por uma série de estações de maquinagem.
Cada estação produz medições que têm de ser combinadas, comparadas, calibradas ou normalizadas antes de a etapa seguinte avançar.
As funções que implementas aqui são uma para cada estação.

~~~~exercism/note
Os cálculos deste exercício devem ser feitos com instruções SIMD, não com operações escalares.
~~~~

## 1. Combina os rendimentos de duas linhas

No chão de fábrica funcionam duas linhas de montagem paralelas.
No fim de cada turno, as duas linhas comunicam os seus rendimentos para 4 caixas de peças como números de precisão simples.
O painel do supervisor mostra o rendimento combinado por caixa, por isso os dois relatórios são somados caixa a caixa.
Os três buffers são geridos pelo sistema de relatórios e estão sempre alinhados a 16 bytes.

Define uma função `sum_yields` que, dados os rendimentos por caixa de `line_a` e `line_b`, escreve a soma caixa a caixa em `result`.
Os argumentos, por ordem, são:

1. `line_a`: endereço de memória alinhado a 16 bytes que contém 4 números de vírgula flutuante de 32 bits
2. `line_b`: endereço de memória alinhado a 16 bytes que contém 4 números de vírgula flutuante de 32 bits
3. `result`: endereço de memória alinhado a 16 bytes onde a função vai escrever 4 números de vírgula flutuante de 32 bits

Esta função não tem valor devolvido; o resultado é guardado no buffer recebido (`result`):

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. Calcula o desvio escalado

Entre operações, uma estação de amostragem mede peças maquinadas e compara-as com as dimensões pretendidas.
Os valores medidos chegam de um medidor de precisão para um buffer que está sempre alinhado a 16 bytes.
Os valores pretendidos vêm do pacote da ordem de trabalho, que não tem garantia de alinhamento.
O desvio é multiplicado por um fator de sensibilidade por eixo antes de ser passado ao verificador de tolerâncias a jusante.
Nesta etapa, o verificador a jusante lê o desvio diretamente de um registo SIMD, e não da memória.

Define uma função `scaled_deviation` que, dados `measured` e `target` e uma `sensitivity`, escreve o desvio escalado em `result`.
Os argumentos, por ordem, são:

1. `measured`: endereço de memória alinhado a 16 bytes que contém 2 números de vírgula flutuante de 64 bits
2. `target`: endereço de memória que contém 2 números de vírgula flutuante de 64 bits (sem garantia de alinhamento)
3. `sensitivity`: endereço de memória que contém 2 números de vírgula flutuante de 64 bits (sem garantia de alinhamento)
4. `result`: endereço de memória para um buffer onde a função vai escrever 2 números de vírgula flutuante de 64 bits (sem garantia de alinhamento)

O desvio escalado é `(measured - target) * sensitivity`, lane a lane.

Esta função não tem valor devolvido; o resultado é guardado no buffer recebido (`result`) como um par de números de vírgula flutuante de 64 bits.

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. Calibra um lote

Antes de as peças entrarem na baía de inspeção final, as leituras dimensionais de um lote de 4 peças são reescaladas para dupla precisão e corrigidas quanto à deriva de temperatura conhecida.

As 4 leituras em bruto chegam como números de precisão simples.
Para cada linha de 2 leituras, a calibração calcula `reference / (raw - offset)` e multiplica depois esse resultado por um fator de conversão constante de `0.5`.

Repara que a referência e o offset são iguais para as duas linhas do lote.
O fator de conversão é o mesmo em todas as calibrações; por isso, em vez de o receberes como argumento, deves declará-lo como uma constante de 16 bytes empacotada na memória.

Define uma função `calibrate_batch` que, dado um lote `raw`, uma `reference`, um `offset` e um buffer `result`, escreve os valores calibrados em `result`.
Os argumentos, por ordem, são:

1. `raw`: endereço de memória que contém 4 números de vírgula flutuante de 32 bits (sem garantia de alinhamento)
2. `reference`: endereço de memória alinhado a 16 bytes que contém 2 números de vírgula flutuante de 64 bits
3. `offset`: endereço de memória alinhado a 16 bytes que contém 2 números de vírgula flutuante de 64 bits
4. `result`: endereço de memória alinhado a 16 bytes onde a função vai escrever 4 números de vírgula flutuante de 64 bits (32 bytes no total)

A função deve, para cada uma das duas linhas do lote:

1. Converter os 2 valores em bruto de precisão simples da linha para dupla precisão.
2. Subtrair `offset` ao par convertido.
3. Dividir `reference` pelo resultado.
4. Multiplicar lane a lane cada número de vírgula flutuante de 64 bits pelo fator de conversão fixo de `0.5`.
5. Guardar os 2 números de vírgula flutuante de 64 bits nos 16 bytes correspondentes de `result`.

Esta função não tem valor devolvido; o resultado é guardado no buffer recebido (`result`):

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. Normaliza as pontuações ao longo de uma linha

No fim da linha, cada peça tem uma pontuação de qualidade que tem de ser normalizada antes de ser comunicada.
Cada pontuação é multiplicada pelo seu próprio ganho por peça e depois dividida por uma escala de produção por eixo.
O buffer dos ganhos contém um ganho por peça.

A escala de produção é a mesma para toda a execução e é passada num endereço de memória que contém dois números de vírgula flutuante de 64 bits.
As pontuações são atualizadas **no local**: o mesmo buffer que continha as pontuações em bruto passa a conter as pontuações normalizadas.

Define uma função `normalize_scores` que, dados um array `scores`, um array `gains`, uma `scale` e uma contagem `n`, normaliza as pontuações no local.
Os argumentos, por ordem, são:

1. `scores`: endereço de memória alinhado a 16 bytes que contém `n` números de vírgula flutuante de 64 bits (modificado no local)
2. `gains`: endereço de memória alinhado a 16 bytes que contém `n` números de vírgula flutuante de 64 bits
3. `scale`: endereço de memória alinhado a 16 bytes que contém 2 números de vírgula flutuante de 64 bits
4. `n`: um número inteiro positivo par de 64 bits (mínimo `2`), o número de pontuações a normalizar

As duas lanes da escala aplicam-se aos dois elementos de cada par.
A primeira lane escala o primeiro elemento de cada par (lanes em posições pares); a segunda lane escala o segundo (lanes em posições ímpares).
Cada pontuação é multiplicada pelo ganho correspondente e depois dividida pela lane de escala adequada: `score * gain / scale_lane`.

Esta função não tem valor devolvido; o resultado é guardado no buffer de entrada (`scores`), na mesma posição da `score` correspondente que foi normalizada:

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
