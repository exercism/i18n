# Dicas

## Geral

- Um contrato fica depois do tipo de retorno e antes do `is`:

  ```sather
     spare_capacity(load : INT) : INT
        pre load >= 0
     is
        ...
     end;
  ```

- Dentro de um contrato podes usar os argumentos e os atributos do objeto,
  por isso `limit` está disponível.
- Os testes são compilados sem `-chk`, por isso um contrato errado não os faz
  falhar. Escreve-os a pensar em quem os lê.

## 1. Monta um arnês

- `pre kg > 0`, no `create`.
- O corpo é o `new` do costume: define o atributo e devolve-o.

## 2. Quanto sobra?

- Duas condições unidas com `and`: `pre load >= 0 and load <= limit`.
- `post result >= 0`. Isso decorre do `pre`, e é isso que faz valer a pena
  dizê-lo: regista a razão pela qual se pode confiar na resposta.

## 3. Quão cheio está?

- `pre load >= 0` e `post result >= 0`.
- `load * 100 / limit`, por essa ordem. Dividir primeiro deitaria tudo fora,
  tal como aconteceria em `tuning-the-strings`.

## 4. É seguro?

- Nenhum `pre`: a ideia é precisamente poder perguntar sobre qualquer carga.
- O `post` reformula a pergunta: `post result = (load <= limit)`.
  Parênteses, porque o `=` está a ser usado duas vezes para coisas diferentes.
