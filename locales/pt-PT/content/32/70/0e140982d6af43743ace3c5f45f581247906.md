# Sobre

Ao escrever funções em Haskell, podemos tirar partido da [correspondência de padrões][pattern-matching]. A correspondência de padrões é uma funcionalidade muito poderosa do Haskell que te permite corresponder a construtores de dados e ligar variáveis aos valores que estão lá dentro. Como o nome sugere, o que fazemos é comparar valores com padrões e, se o valor corresponder ao padrão, podemos ligar variáveis aos valores dentro do padrão. A correspondência de padrões assenta sobretudo nestes conceitos: reconhecer valores, ligar variáveis e decompor valores.

~~~~exercism/note
A correspondência de padrões em linguagens como o Elixir é um pouco diferente da correspondência de padrões em Haskell. O Elixir, por exemplo, permite que o mesmo nome de ligação apareça várias vezes num padrão, ao passo que o Haskell não.
~~~~


Vê esta função, por exemplo:

```haskell
lucky :: Int -> String
lucky 7 = "Lucky number seven!"
lucky x = "Sorry, you're out of luck, pal!"
```

Aqui temos uma função `lucky` que recebe um `Int` e devolve uma `String`. Definimos dois padrões para a função: um que corresponde ao número `7` e outro que corresponde a qualquer outro número. O nome pode ser o que quiseres (desde que siga a convenção de nomes do Haskell), mas aqui usamos `x`. Se o número for `7`, a função devolve `"Lucky number seven!"`; caso contrário, devolve `"Sorry, you're out of luck, pal!"`. É importante notar que os padrões são verificados de cima para baixo, por isso, se tivéssemos trocado a ordem dos padrões, a função devolveria sempre `"Lucky number seven!"`.

## Padrões de listas

Um padrão muito comum é fazer correspondência com listas, tirando a cabeça e a cauda da lista. Isto deve-se à natureza das listas como listas ligadas. Vê um exemplo de uma função que devolve a cabeça e a cauda de uma lista:

```haskell
headAndTail :: [Int] -> (Int, [Int])
headAndTail [] = error "Can't call head on an empty list"
headAndTail (x:xs) = (x, xs)
```

Aqui temos dois padrões: um que corresponde a uma lista vazia e outro que corresponde a uma lista com pelo menos um elemento. Isto porque, se a lista estiver vazia, precisamos de ter um caso para isso; caso contrário, teríamos um erro em tempo de execução. Se a lista não estiver vazia, podemos fazer corresponder a cabeça da lista a `x` e a cauda da lista a `xs`. Isto faz-se com o operador `:` (cons), que serve para acrescentar um elemento à frente de uma lista. Mas, na correspondência de padrões, permite decompor uma lista na sua cabeça e na sua cauda, fazendo de certa forma o inverso.

O nome `xs` é comum para a cauda de uma lista, pois realça que se trata de uma lista. Mas, se estiveres a trabalhar com uma lista aninhada, podes usar `xss` para realçar que é uma lista de listas.

## Padrões de tuplos

Tal como com as listas, também podemos fazer correspondência de padrões com tuplos. Vê um exemplo de uma função que recebe um tuplo e devolve o primeiro e o segundo elemento:

```haskell
sumTuple :: (Int, Int) -> Int
sumTuple (x, y) = x + y
```

Aqui temos um padrão que corresponde a um tuplo com dois elementos: o primeiro elemento fica ligado a `x` e o segundo elemento fica ligado a `y`.

## Padrões com wildcard

Às vezes não nos interessa o valor de uma variável, só queremos corresponder ao padrão. É aqui que entra o padrão com wildcard, que se representa com um sublinhado `_`.

Vê um exemplo de uma função que devolve o primeiro elemento de uma lista:

```haskell
head' :: [Int] -> Int
head' [] = error "Can't call head on an empty list"
head' (x:_) = x
```

Aqui dizemos que não precisamos da cauda da lista, por isso usamos o padrão com wildcard para a ignorar.

## Padrões de tipos

Também podemos fazer correspondência de padrões com tipos, usando o construtor desse tipo. Também podemos extrair valores do tipo, como fizemos com os tuplos.

```haskell
data AccountType = Guest | User String 

greet :: AccountType -> String
greet Guest = "Welcome, guest!"
greet (User name) = "Welcome, " ++ name ++ "!"
```

No primeiro padrão fazemos correspondência com o construtor `Guest` e, no segundo padrão, fazemos correspondência com o construtor `User`, ligando o valor que está lá dentro a `name`.
