# Linting

A principal utilização do [configlet](/docs/building/configlet) é o linting: verificar se os ficheiros de configuração de um percurso estão bem estruturados, tanto a nível sintático como semântico. Os percursos mal configurados podem não sincronizar corretamente, podem parecer errados no site ou podem proporcionar uma experiência de utilizador abaixo do ideal, por isso as verificações do configlet desempenham um papel importante na manutenção da integridade do Exercism.

## Utilização

O comando `lint` pode ser usado para fazer o linting de um percurso.

```
configlet [global-options] lint [command-options]

Global options:
  -h, --help                   Show this help message and exit
      --version                Show this tool's version information and exit
  -t, --track-dir <dir>        Specify a track directory to use instead of the current directory
  -v, --verbosity <verbosity>  The verbosity of output. Allowed values: q[uiet], n[ormal], d[etailed]
```

## Regras

Estas são as regras de linting que são verificadas.

### Regra: os ficheiros obrigatórios estão presentes

O linter deve verificar se todos os ficheiros obrigatórios estão presentes. Os ficheiros que não são específicos de um exercício e que têm de estar presentes são:

- `config.json`
- `docs/ABOUT.md`
- `docs/INSTALLATION.md`
- `docs/LEARNING.md`
- `docs/RESOURCES.md`
- `docs/SNIPPET.txt`
- `docs/TESTS.md`
- `exercises/shared/.docs/help.md`
- `exercises/shared/.docs/tests.md`

Os ficheiros específicos dos exercícios de conceito que têm de estar presentes são:

- `exercises/concept/<slug>/.docs/hints.md`
- `exercises/concept/<slug>/.docs/instructions.md`
- `exercises/concept/<slug>/.docs/introduction.md`
- `exercises/concept/<slug>/.meta/config.json`

Haverá uma lista semelhante para os exercícios de prática, mas ainda não definimos a especificação para isso.

Cada conceito listado no `config.json` deve ter os seguintes ficheiros:

- `concepts/<slug>/about.md`
- `concepts/<slug>/introduction.md`
- `concepts/<slug>/links.json`

## Glossário

1. **String não vazia**: uma string que contém pelo menos um caráter que não seja um espaço em branco.
2. **String em kebab-case**: uma string que contém apenas carateres no intervalo `[a-z0-9]`, opcionalmente separados por hífenes (por exemplo, "two-fer"). Tem de corresponder à expressão regular: `^[a-z0-9]+(-[a-z0-9]+)*$`
3. **String em Title Case**: uma string não vazia que segue as [orientações do Chicago Manual of Style](https://en.wikipedia.org/wiki/Title_case#Chicago_Manual_of_Style) abaixo:
   - Escreve com maiúscula a primeira e a última palavra de títulos e subtítulos.
   - Escreve com maiúscula as palavras "principais" (nomes, pronomes, verbos, adjetivos, advérbios e algumas conjunções).
   - Escreve com minúscula as conjunções _and_, _but_, _for_, _or_ e _nor_.
   - Escreve com minúscula os artigos _the_, _a_ e _an_.
   - Escreve com minúscula as preposições, independentemente do comprimento, exceto quando são tónicas, são usadas como advérbios ou adjetivos, ou são usadas como conjunções.
   - Escreve com minúscula as palavras _to_ e _as_.
   - Escreve com minúscula a segunda parte dos nomes de espécies latinas.
4. **String em Sentence Case**: uma string não vazia que segue as [orientações](https://en.wikipedia.org/wiki/Letter_case#Sentence_case) abaixo:
   - Escreve com maiúscula a primeira palavra da frase, bem como os nomes próprios e outras palavras conforme exigido por uma regra mais específica.
5. **Padrão de `files` válido**: uma string não vazia¹ que especifica a localização de um ficheiro usado num exercício, relativa ao diretório do exercício. Um padrão pode usar um dos seguintes placeholders:

   - `%{kebab_slug}`: o slug do exercício em `kebab-case` (por exemplo, `bit-manipulation`)
   - `%{snake_slug}`: o slug do exercício em `snake_case` (por exemplo, `bit_manipulation`)
   - `%{camel_slug}`: o slug do exercício em `camelCase` (por exemplo, `bitManipulation`)
   - `%{pascal_slug}`: o slug do exercício em `PascalCase` (por exemplo, `BitManipulation`)

6. **String UUID de versão 4 única**: uma string que satisfaz todas estas condições:

   - Existe apenas uma vez no ficheiro `config.json` ao nível do percurso de um determinado percurso do Exercism
   - Não existe no ficheiro `config.json` ao nível do percurso de qualquer outro percurso do Exercism
   - Não existe em nenhum ficheiro `canonical-data.json` em https://github.com/exercism/problem-specifications
   - Não existe em mais nenhum sítio do Exercism
   - Corresponde à expressão regular:

   ```
   ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
   ```

   Por exemplo, o UUID abaixo tem a forma correta:

   ```
   d334ffe3-657e-4725-a950-290b284b6d9f
   ```

   Podes executar `configlet uuid` para gerar um UUID adequado.

7. **`tag` de analisador válida**: uma string não vazia¹ com o formato `<category>:<thing>`.
   O valor de `<category>` tem de ser um dos seguintes:

- `paradigm` (por exemplo, `paradigm:functional`)
- `technique` (por exemplo, `technique:recursion`)
- `construct` (por exemplo, `construct:bitwise-and`)
- `uses` (por exemplo, `uses:DateTime.add_seconds`)

O valor de `<thing>` tem de ser uma string não vazia¹.
