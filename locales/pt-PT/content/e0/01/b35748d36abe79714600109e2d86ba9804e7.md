# Sobre

O tipo `Result` permite que uma função devolva um único valor que indica tudo o seguinte:
- Se a operação teve sucesso ou falhou
- Em caso de sucesso, o valor resultante da operação
- Em caso de falha, o motivo da falha

Com outras linguagens de programação que não suportam algo como um tipo `Result`, é comum encontrar os seguintes padrões para atingir os objetivos acima:
- Uma função que devolve um código numérico a indicar sucesso ou o motivo da falha e que exige um parâmetro de saída para receber o valor em caso de sucesso.
- Uma função que devolve o valor em caso de sucesso ou NULL em caso de erro, e depois uma função diferente para obter o código de erro que indica o motivo da falha.

Outro mecanismo comum de tratamento de erros é a exceção, que sai abruptamente da função atual e
transfere o controlo para o primeiro processador da pilha de chamadas quando ocorre uma falha.  
Se nenhum processador "capturar" a exceção, o programa é abortado.

## Vantagens de usar o tipo `Result`

* __Segurança em tempo de compilação__: ao tornar o sucesso ou a falha de uma chamada de função explícitos no sistema de tipos, o compilador consegue garantir que o código que faz a chamada trata todos os casos de falha, evitando uma grande categoria de bugs que poderiam ocorrer com valores nulos.

* __Segurança em tempo de execução__: em vez de usar `null`, o tipo `Result` usa `Error` para representar uma falha, o que torna impossível a ocorrência de uma `NullReferenceException`.

* __Tratamento explícito de erros__: o código que chama uma função que devolve um `Result` tem de reconhecer que a
chamada pode falhar; o código que faz a chamada tem de tratar essas falhas de forma intencional.  Não há falhas silenciosas nem exceções inesperadas.

* __Fluxo de controlo previsível__: um `Result` é devolvido como qualquer outro valor; não salta para fora da pilha de chamadas como uma exceção.  Sabes sempre de onde vêm os erros e como se propagam.

* __Legibilidade e capacidade de manutenção melhoradas__: ao devolver um `Result`, a assinatura de uma função indica claramente o comportamento esperado em caso de sucesso e de falha.

## Utilização

O tipo `Result` é um tipo genérico que contém dois tipos subjacentes:
- O tipo do valor resultante numa operação bem-sucedida
- O tipo que representa o motivo da falha numa falha

O tipo `Result` é também uma [união discriminada][discriminated-union] com os seguintes casos possíveis:
* `Ok <value>` a representar um resultado bem-sucedido
* `Error <reason>` a representar uma falha

A função seguinte demonstra como criar um valor `Result`:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

Neste exemplo, o valor `Ok` é uma string (o nome indicado) e o valor `Error` é também uma string (a causa do erro, em formato legível por humanos).

## Ler o conteúdo de um valor `Result`

Considera a seguinte definição de tipo e assinatura de função:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

O código que chama a função `openFile` pode usar correspondência de padrões para tratar os casos de sucesso e de falha, como no exemplo seguinte:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
