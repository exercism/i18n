# Notas sobre parênteses

O Tcl é uma [linguagem muito simples](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm), mas a forma como o intérprete analisa o código tem alguns casos-limite desagradáveis.

## Chavetas

As chavetas em Tcl são apenas uma forma de delimitar um bloco de texto: esse texto pode ser interpretado como código ou como dados. Dentro das chavetas podem aparecer chavetas aninhadas, mas essas chavetas aninhadas têm de estar equilibradas. A página de manual do Tcl diz o seguinte:

> As chavetas aninham-se dentro da palavra: por cada chaveta de abertura adicional tem de haver uma chaveta de fecho adicional (no entanto, se uma chaveta de abertura ou de fecho dentro da palavra estiver _escapada com uma barra invertida_, não é contabilizada ao localizar a chaveta de fecho correspondente).

A redação é bastante específica: se quiseres ter um caráter de abertura ou de fecho de chaveta sem par, tens de o escapar com uma barra invertida. Por isso, não faças isto:
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "{"}]
    # ......................^ will not work
}
```
Tens de fazer isto
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "\{"}]
    # ......................^^ will work
}
```

Isto pode ser problemático devido à forma como o Tcl analisa os comentários, que é diferente da maioria das linguagens. Há mais discussão na [wiki do Tcl](https://wiki.tcl-lang.org/page/Why+can+I+not+place+unmatched+braces+in+Tcl+comments).

## Parênteses retos

Da mesma forma, como o Tcl usa parênteses retos para a [substituição de comandos](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M11), mesmo dentro de strings entre aspas duplas tens de ter cuidado ao escapar parênteses retos de abertura.

## Parênteses

Com exceção das [variáveis de array associativo](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M12), os parênteses são simplesmente carateres comuns.
