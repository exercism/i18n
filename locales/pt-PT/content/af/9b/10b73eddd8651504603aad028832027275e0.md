# Testes

Correr os testes implica executar `cmake -G` e depois usar o comando de compilação adequado à tua plataforma.
Encontras instruções detalhadas sobre como fazer isto na página [Correr os testes][cpp-tests-instructions] para C++ em exercism.org.

## Passar nos testes

Quando começas um novo exercício localmente, os ficheiros estão configurados para que apenas o primeiro teste seja executado.
Faz com que esse primeiro teste compile, ligue e passe, seguindo as [três regras do desenvolvimento orientado por testes][three-laws-of-tdd].
Cria apenas a estrutura suficiente, declarando namespaces, funções, classes, etc., para resolver os erros do compilador e fazer com que o teste falhe.
Depois, escreve apenas o código suficiente para que o teste passe.
Depois de fazeres isso, descomenta o teste seguinte movendo a linha `if defined(EXERCISM_RUN_ALL_TESTS)` para depois do teste seguinte.

Vê o exemplo abaixo do exercício Bob (ficheiro `bob_test.cpp`, linha 15):

```diff
-#if defined(EXERCISM_RUN_ALL_TESTS)
TEST_CASE("shouting")
{
    REQUIRE("Whoa, chill out!" == bob::hey("WATCH OUT!"));
}
+#if defined(EXERCISM_RUN_ALL_TESTS)
```

Mover esta linha para depois do teste seguinte pode provocar erros de compilação, porque podem passar a ser usadas construções novas que ainda não declaraste nem definiste.
Mais uma vez, corrige os erros de compilação de forma mínima para obteres um teste que falha, depois altera o código de forma mínima para o teste passar, refatora a tua implementação para melhorar a legibilidade e a expressividade e passa ao teste seguinte.

Tenta usar as funcionalidades padrão do C++17 em vez de escreveres os teus próprios algoritmos ou funcionalidades de baixo nível à mão.
