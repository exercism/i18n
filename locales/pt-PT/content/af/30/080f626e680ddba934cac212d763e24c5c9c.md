# Sobre

Para além das classes de carateres e dos quantificadores, as expressões regulares conseguem descrever a *estrutura* e o *contexto* do texto. Estas funcionalidades vivem no mesmo vocabulário [`regexp`][regexp], escrito com o literal `R/ /`.

## Agrupamento e alternância

Os parênteses curvos `( )` agrupam uma parte de um padrão, para que um quantificador ou um `|` ("isto ou aquilo") se aplique ao grupo todo. O `?` depois de um grupo torna-o opcional:

```factor
USING: regexp ;

"abab"    R/ (ab)+/ matches? .             ! => t
"cat"     R/ cat|dog/ matches? .           ! => t
"$100.50" R/ \$\d+(\.\d{2})?/ matches? .   ! => t
"$100"    R/ \$\d+(\.\d{2})?/ matches? .   ! => t   (group optional)
```

## Âncoras

```
^    ! start of the string
$    ! end of the string
\b   ! a word boundary
```

Um *limite de palavra* (`\b`) é o ponto onde um caráter de palavra (uma letra, um algarismo ou um underscore) encontra um que não é de palavra, incluindo as extremidades da string. Por isso, `\bcat\b` só corresponde a `cat` quando este aparece sozinho:

```factor
USING: regexp ;

"cat nap" R/ \bcat\b/ re-contains? .   ! => t
"scatter" R/ \bcat\b/ re-contains? .   ! => f
```

## Verificação de contexto

Uma *verificação de contexto* testa o que vem imediatamente antes ou depois de um ponto, sem que esses carateres façam parte da correspondência. Tem largura zero:

```
(?=...)    ! lookahead
(?!...)    ! negative lookahead
(?<=...)   ! lookbehind
```

```factor
USING: regexp ;

"spent $100 and $25" R/ (?<=\$)\d+/ all-matching-subseqs .
! => { "100" "25" }

"up 5% then 12%" R/ \d+(?=%)/ all-matching-subseqs .
! => { "5" "12" }
```

## Opções

Uma letra de opção a seguir ao `/` de fecho altera o padrão todo. O `i` não distingue maiúsculas de minúsculas:

```factor
USING: regexp ;

"REFUND" R/ refund/i matches? .   ! => t
```

## Transformar cada correspondência

O `map-matches` executa uma quotation sobre cada correspondência e recolhe os resultados; o `each-match` faz o mesmo apenas para efeitos secundários. Ambos passam à quotation o índice `start` e o índice `end` da correspondência, e a string completa, para que o `subseq` recupere o texto correspondido:

```
map-matches ( string regexp quot: ( start end string -- obj ) -- seq )
each-match  ( string regexp quot: ( start end string --     ) --     )
```

```factor
USING: math regexp sequences ;

"a1 b22 c333" R/ \d+/ [ subseq length ] map-matches .
! => { 1 2 3 }
```

## O que o Factor não suporta

O motor de expressões regulares do Factor não tem **extração de grupos de captura** (um grupo `( )` estrutura o padrão, mas não consegues ler de volta o texto com que correspondeu), nem **retro-referências** (`\1`), nem quantificadores **preguiçosos/não gananciosos** (`*?`, `+?`). A verificação de contexto é o substituto idiomático dos grupos de captura: corresponde à parte que queres, reconhecida pelo contexto que a rodeia.
