# Testes

Cada exercício fornece os testes unitários.
Tu escreves a implementação.
Cada ficheiro produz um executável de consola que corre os testes.
Ao correr o executável de testes, é impressa uma mensagem por cada teste que falha e é reportado um estado de saída diferente de zero quando os testes falham.

*Nota* O teu código é testado com o conjunto de testes sempre que compilas o teu projeto.
Se o teu código não passar num ou mais testes, mas for código D válido, ainda assim é compilado.

Percorrer cada exercício é um processo de:

* Correr os testes com `dub test`
  * Se optaste por não instalar o DUB, usa antes `dmd source/*.d -de -w -main -unittest` e depois corre o binário resultante.
* Para cada teste unitário:
  * Corrige os erros de compilação para que o teste falhe.
  * Implementa apenas o suficiente para o teste passar.
  * Refatora a tua implementação para melhorar a legibilidade, reduzir duplicação, etc.
  * Ativa o teste seguinte

*Nota:* O D tem suporte para testes unitários diretamente na linguagem, por isso, normalmente, os testes unitários ficam no mesmo ficheiro que a implementação.
Os testes unitários são executados antes do corpo de main e são ativados no executável final através da opção do compilador **-unittest**.

```none
$ dub test
             Generating test runner configuration 'dnd-character-test-library' for 'library' (library).

    Building dnd-character ~master: building configuration [dnd-character-test-library]
     Linking dnd-character-test-library
     Running dnd-character-test-library

```
