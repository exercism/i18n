# Introdução

O que é a programação funcional?

Para os nossos objetivos, estas são algumas características fundamentais:

- Funções puras, que mapeiam entradas para saídas de forma consistente e sem efeitos secundários.
- Dados imutáveis.
- Funções de primeira classe, que podem ser tratadas como valores como qualquer outro tipo.
- Funções de ordem superior, que recebem outras funções como argumentos ou como valores devolvidos.

No entanto, o R não é uma linguagem funcional pura (ao contrário de, por exemplo, Haskell).

Vê o R como uma linguagem pragmática, que (cada vez mais) oferece capacidades funcionais quando estas são uma forma limpa e fácil de fazer o trabalho.
Em geral, o objetivo é a análise de dados, e a programação é apenas um meio para esse fim.

## Pipes

A utilização de pipes `|>` para ligar funções é uma técnica cada vez mais comum em várias linguagens.

Em resumo:

- Um resultado à esquerda do pipe torna-se o primeiro argumento da função à direita (em que «direita» ignora quebras de linha opcionais).
- Quaisquer argumentos restantes podem ser incluídos na chamada à função.
- Em R, temos de usar o pipe para uma _chamada_ de função, não apenas para um _nome_, pelo que os parênteses são sempre obrigatórios (_isto é diferente de algumas outras linguagens_).

Alguns programadores acham útil pronunciar o pipe como «then» ao rever código: faz o passo 1, depois faz o passo 2...

O exemplo abaixo ilustra a sintaxe.

```R
library(stringr)

"Monday-25-February" |> 
  str_split("-") |>     
  unlist() |>               # [1] "Monday"   "25"       "February"
  str_sub(1, 3) |>          # [1] "Mon" "25"  "Feb"
  str_to_upper() |>         # [1] "MON" "25"  "FEB"
  str_flatten(collapse = ", ")
#> [1] "MON, 25, FEB"
```

Este tipo de pipe foi adicionado ao Base R na v4.1.0, e podes vê-lo referido como o «pipe nativo».

O editor RStudio (entre outros) usa `Ctrl-Shift-M` como atalho de teclado para adicionar um pipe com espaços adequados.

## Funções de aplicação

Vimos anteriormente que muitas funções em R são «vetorizadas»: operam sobre vetores inteiros, sem necessidade de escrever ciclos explícitos.

As funções que usam apenas funções vetorizadas são elas próprias provavelmente vetorizadas automaticamente.
Num exemplo trivial:

```R
triple <- function(x) return(3 * x)
triple(1:10)
 [1]  3  6  9 12 15 18 21 24 27 30
 ```

No entanto, funções mais complexas podem não aceitar entrada vetorial, por exemplo se contiverem ciclos ou blocos if-else.

Precisamos de uma forma mais geral de aplicar funções a vetores (semelhante a `map()` nalgumas outras linguagens).

Como o R tem uma grande variedade de estruturas de dados na linguagem base, também tem toda uma família de funções `*apply()` para operar sobre elas.
Mais tecnicamente, são frequentemente chamadas «funções de ordem superior» pelos programadores e «funcionais» pelos matemáticos, porque recebem funções como argumentos.

Por agora, considera `lapply()` e `sapply()`.

### `lapply()`

O «List-apply» foi concebido para trabalhar com entradas de listas, mas os vetores serão silenciosamente convertidos em listas quando necessário.

O resultado é uma lista, pelo que pode ser necessário desempacotá-la para obter um vetor:

```R
h <- function(size) {
    switch(size,
           "small" = 6,
           "medium" = 8,
           "large" = 10
    )
}

v <- c("small", "large", "medium")

h(v) # bad use of an unvectorized function
#> Error in switch(size, small = 6, medium = 8, large = 10) : 
#>   EXPR must be a length 1 vector

lapply(v, h)  # output is a list
#> [[1]]
#> [1] 6

#> [[2]]
#> [1] 10

#> [[3]]
#> [1] 8

lapply(v, h) |> unlist() # output is a vector
#> [1]  6 10  8
```

Os estudantes familiarizados com o [Conceito Switch][concept-switch] podem notar que podíamos, em alternativa, substituir o `switch` escalar pela função vetorizada [`recode_values()`][ref-recode_values] da biblioteca [`dplyr`][ref-dplyr].
A vetorização é boa, e o R moderno fornece várias formas de a conseguir.

```R
library(dplyr)

h <- function(size) {
  recode_values(size,
         "small" ~ 6,
         "medium" ~ 8,
         "large" ~ 10
  )
}

v <- c("small", "large", "medium")
h(v)
#> [1]  6 10  8
```

### [`sapply()`][ref-lapply]

O «Simplified-apply» faz algo semelhante ao `lapply`, mas também tenta simplificar o valor devolvido: por exemplo, um vetor com nomes em vez de uma lista.
Dependendo do contexto, pode ser necessário usar [`unname()`][ref-unname]:

```R
sapply(v, h)
 small  large medium 
     6     10      8 

sapply(v, h) |> unname()
#> [1]  6 10  8
```

## A biblioteca `purrr`

`lapply` e `sapply` são simples, familiares para a maioria dos utilizadores de R, e ainda bastante populares para vetores e listas simples.

O Base R também tem _muitas_ outras funções de aplicação.
Fornecer uma alternativa mais simples e consistente para este tipo de confusão é um dos principais objetivos do Tidyverse.

Existe agora o pacote `purrr`, que fornece várias opções adicionais como `map()`, melhorando a consistência do design e a clareza das mensagens de erro.

Menos limitado pela compatibilidade retroativa do que o Base R, este pacote aproxima significativamente o R da programação funcional moderna encontrada noutras linguagens.

Há muitas funções diversificadas no `purrr`, que não se resumem facilmente.
Os recursos que ajudam a navegar na biblioteca incluem:

- Um [sítio web][web-purrr], incluindo um guia de [primeiros passos][web-starting].
- Uma [página de referência][ref-purrr-funcs] para todas as funções.
- Uma [folha de consulta rápida][cheat-purrr] em formato PDF.
- Um guia para converter a partir do [Base R][web-from-R].

### As muitas funções map

A função [map()][ref-map] aplica uma função a cada elemento da entrada e devolve sempre uma [lista][concept-lists].

Até aqui, isto parece o [`lapply()`][ref-lapply], apenas com outro nome, e talvez com melhores mensagens de erro.

No entanto, `map()` é apenas um membro de uma _grande_ família.

Algumas perguntas a considerar ao escolher uma função:

- O que queres devolver? [`map()`][ref-map] devolve sempre uma lista, mas se quiseres um tipo específico de vetor atómico usa [`map_chr()`][ref-map_chr] para strings, [`map_int()`][ref-map_int] para inteiros, etc.
- Precisas de cada índice posicional da entrada? Coloca o prefixo `i` nos nomes das funções, como em [`imap()`][ref-imap].
- Queres processar várias entradas em paralelo? 
  - Substitui `map` por `map2` no nome, como em [`map2_dbl()`][ref-map2_dbl] para duas entradas (por exemplo, valores e pesos, para calcular uma média ponderada)
  - Substitui por `pmap` para uma lista de entradas paralelas, como em [`pmap_chr()`][ref-pmap_chr]. E sim, é possível paralelismo ao nível do hardware.
- Queres processar todos os elementos da entrada? Se não, considera [`map_if()`][ref-map_if] para aplicar um filtro de predicado (booleano), [`map_at()`][ref-map_at] para especificar critérios de índice posicional, [`head_while()`][ref-head_while] para processar a entrada até um elemento falhar um predicado.
- Os dados de entrada estão profundamente aninhados? Existem [funções][ref-plucks] para essa situação.
- Queres que o valor devolvido seja sempre do mesmo tipo que a entrada? Usa as funções [`modify()`][ref-modify] em vez de `map`, ou [`modify_tree()`][ref-modify_tree] para aplicação recursiva.

Estas funções têm os dados de entrada como primeiro argumento sempre que possível, para garantir que funcionam bem com pipes.

Além disso, o `purrr` é (deliberadamente) mais pedante do que o Base R. Se pedires algo específico, as funções devolvem _exatamente_ isso ou param com uma mensagem de erro.
Duro, mas muito eficaz a reduzir bugs difíceis de encontrar.

### Funções de redução

As funções map têm geralmente um valor devolvido com o mesmo comprimento da entrada.

Algumas outras funções _reduzem_ a dimensionalidade dos dados, por exemplo `sum()`.

```R
sum(1:100)
#> [1] 5050
```

No caso acima, convertemos um vetor de comprimento 100 num inteiro de comprimento 1.
Veremos num futuro Conceito sobre matrizes e arrays que o conceito de redução de dimensionalidade é mais geral.

A função `sum()` é incorporada (tal como muitas outras funções estatísticas).
No entanto, precisamos de uma forma de aplicar funções arbitrárias de redução de dimensionalidade a uma estrutura de dados, usando alguma função de ordem superior equivalente a `map()`.

Noutras linguagens, usam-se nomes de funções como `fold`, `foldl` e `foldr`. Em R, a função relevante é [`reduce()`][ref-reduce], que corresponde à conhecida (entre entusiastas de algoritmos) framework MapReduce.

O primeiro argumento é, como habitualmente, os dados de entrada. O segundo argumento é uma função de 2 argumentos: muitas vezes uma função anónima, mas possivelmente tão simples como um operador aritmético como `+`.

```R
# surround an infix operator with backticks, to use as a function
reduce(1:100, `+`)
#> [1] 5050  # same as sum(1:100)

# anonymous function, alternately add and subtract
reduce(1:10, \(accum, nextval) ifelse(nextval %% 2 == 0, accum + nextval, accum - nextval))
#> [1] 7
```

Importa se aplicamos a função a partir do início ou do fim da entrada?

Não com operadores [associativos][wiki-associative] como `+` ou `*`.
Claramente, `(1 + 2) + 3 == 1 + (2 + 3)`.

Em contrapartida, `-` e `/` são não associativos:

```R
(1 - 2) - 3
#> [1] -4
1 - (2 - 3)
#> [1] 2
```

Para funções em que a direção importa, existe um argumento opcional `.dir`.

```R
# default is .dir = "forward"
reduce(1:10, `-`)
#> [1] -53
reduce(1:10, `-`, .dir = "backward")
#> [1] -5
```

Tal como com `map()` e `map2()`, existe também uma função [`reduce2()`][ref-reduce] para operar sobre dois vetores de entrada em paralelo.

Em R, gostamos de trabalhar com vetores.
Imagina que, em vez de um único valor final, queres ver todos os passos intermédios.

Para isso, as funções correspondentes são [`accumulate()`][ref-accumulate] e `accumulate2()`.
A sintaxe é semelhante a `reduce()`, com alguns argumentos opcionais extra para especificar o tipo de resultado.

```R
accumulate(1:10, `+`)
#> [1]  1  3  6 10 15 21 28 36 45 55
```

Alguns tipos comuns de accumulate têm as suas próprias funções.
O Conceito [Funções de Vetores][concept-vector-functions] abordou [`cumsum()`][ref-cumsum] e `cumprod()` no Base R, e a biblioteca `dplyr` tem [`cummean()`][ref-dplyr-cum] para médias numéricas, `cumall()` e `cumany()` para vetores lógicos.

### Funções de filtragem

Frequentemente, queremos incluir (ou excluir) elementos da entrada que correspondem a um determinado predicado.

No Conceito [Filtragem de Vetores][concept-vector-filtering] vimos uma forma idiomática de fazer isto.

```R
v <- 1:3
v[v >= 2]
#> [1] 2 3
```

Isto é muito usado no R tradicional, mas encaixa mal nos pipelines funcionais modernos.

Consequentemente, o `purrr` fornece um conjunto de [funções de predicado][ref-predicates], que seguem a convenção habitual de argumentos `f(input, func, ...)` para funcionar com pipes.

Os nomes são um pouco diferentes da maioria das outras linguagens (nomes como `filter` e `drop` já significam algo completamente diferente em R).

As funções correspondentes do `purrr` incluem [`keep()`][ref-keep] e [`discard()`][ref-keep], além de várias outras.

Temos também [`every()`][ref-every], [`some()`][ref-every] e [`none()`][ref-every], para substituir `all()` e `any()` ao devolver um único valor lógico.
