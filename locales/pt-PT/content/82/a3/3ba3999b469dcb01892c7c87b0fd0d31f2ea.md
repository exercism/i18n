# Classes imutáveis

```sather
immutable class BEARING is
   readonly attr degrees : INT;
   create(d : INT) : SAME is
      b : SAME;
      return b.degrees(d);
   end;
end;
```

## O que muda

| | classe normal | classe imutável |
| --- | --- | --- |
| atribuição | partilha o objeto | copia o valor |
| pode ser void | sim | não |
| escrita de `attr` | `x.a := v` | `x := x.a(v)` |
| `new` | sim | não; `x : SAME` já existe |

Um objeto imutável não pode ser void, pelo que `void(b)` é sempre falso e nenhuma rotina sobre um objeto imutável pode falhar por falta de um objeto. Isto elimina toda uma categoria de erros, à custa de nunca se poder dizer «ainda não há bearing».

## Onde vive o valor

O valor é armazenado onde está a variável (dentro de outro objeto ou na pilha), em vez de ser acedido através de uma referência. Assim, um `ARRAY{BEARING}` contém os próprios objetos do tipo BEARING, e não ponteiros para eles, o que é mais pequeno e mais rápido de percorrer.

O custo é a cópia: passar um objeto imutável grande copia-o sempre. É melhor mantê-los pequenos.

## As rotinas de `attr`

`readonly attr degrees : INT` dá duas rotinas:

```sather
   b.degrees          -- read: INT
   b.degrees(90)      -- answer a new BEARING with degrees changed
```

A segunda existe mesmo sob `readonly`, porque não muda nada: cria um novo valor. Sob um `attr` simples, é pública; sob `private attr`, não é.

## is_eq e str

Nenhuma delas é fornecida. Escreve `is_eq` para `=`, e `str` para que o objeto possa ser impresso e concatenado com strings:

```sather
   is_eq(other : SAME) : BOOL is return degrees = other.degrees; end;
   str : STR is return degrees.str + " degrees"; end;
```

Escrever `str` faz a classe conformar-se com `$STR`, o que permite que `+` e `#OUT` a aceitem.

## As classes incorporadas

`INT`, `BOOL`, `CHAR`, `FLTD` e `TUP` são todas classes imutáveis. Não têm nada de especial: são escritas em Sather na biblioteca da mesma forma, e o seu comportamento deve-se às razões acima.
