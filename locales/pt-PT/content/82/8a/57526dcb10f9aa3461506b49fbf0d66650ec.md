# Sobre

O assembly escrito à mão está cheio de repetição.
A mesma sequência curta de instruções aparece vezes sem conta, com pouca variação, e há poucas abstrações para reduzir o código repetitivo.
Além disso, programar em assembly obriga-te a gerir valores sem semântica óbvia.
Não há parâmetros com nome e o programador tem de tratar manualmente a maioria dos detalhes da máquina subjacente.

O NASM, o assembler usado pelo track, oferece algumas ferramentas que podem ajudar o programador com ambos os problemas.
Estas ferramentas atuam _em tempo de assemblagem_, antes de qualquer instrução chegar ao processador.
Orientam o assembler sobre como reescrever o texto fonte antes de este ser traduzido para código máquina.

A mais importante destas ferramentas são as **macros**, que podes encarar como uma receita para o assembler.
São expandidas no local onde são usadas, como se o código tivesse sido escrito ali à mão.

As [macros][macro] podem receber vários tokens literais como parâmetros, o que as torna reutilizáveis em contextos diferentes.
No entanto, não são funções: não há `call`, nem `ret`, nem transferência de controlo para outro ponto do código.

## Macros de uma linha

A definição mais simples dá um nome a um valor ou a uma expressão curta com `%define`:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Todas as ocorrências posteriores de `WIDTH` são substituídas por `8` antes da assemblagem.
A substituição é textual, por isso o nome é substituído onde quer que apareça, seja num operando, seja dentro de outra definição.

~~~~exercism/note
Para _constantes_ numéricas, dá preferência a `equ` em vez de `%define`.

Uma macro de uma linha declarada com `%define` só é expandida quando é usada, e pode ser reatribuída ou deixar de estar definida.
Uma constante `equ`, por outro lado, é avaliada no ponto de definição e nunca é modificada.
~~~~

Um `%define` também pode receber parâmetros _com nome_, comportando-se como uma pequena função inline:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Põe parênteses tanto no corpo inteiro como em cada parâmetro.
Com `%define square(x) x*x`, a chamada `square(1+1)` expande para `1+1*1+1`, que é `3`.
Escrito como `%define square(x) ((x)*(x))`, a mesma chamada expande para `((1+1)*(1+1))`, que é `4`.
~~~~

Os nomes definidos com `%define` distinguem maiúsculas de minúsculas.
A variante `%idefine` faz com que o nome não distinga maiúsculas de minúsculas, caso seja desejado.

As macros de uma linha são úteis para dar significado a várias partes do código.
Se forem usadas com cuidado, isto melhora a legibilidade e reduz a probabilidade de gralhas.
Por exemplo, um registo que tem um propósito específico dentro de uma função pode ser definido pelo seu propósito:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Macros de várias linhas

Uma sequência inteira de código, com qualquer número de linhas, é capturada com `%macro` e fechada por `%endmacro`.
Um número depois do nome indica quantos argumentos a macro recebe, que podem ser zero.
Quando são passados argumentos, estes são separados por uma vírgula (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Os argumentos nas macros de várias linhas não têm nome.
São referidos como `%1`, `%2`, e por aí adiante, pela ordem em que são passados:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Repara que os argumentos têm de ser sintaxe válida para as operações realizadas no corpo da macro.
Aqui, `mult_two eax, ecx` e `mult_two r8, r9` são ambos assemblados, mas `mult_two eax, cl` não seria, pois `imul eax, cl` não está definido.

As macros também podem receber um número arbitrário de argumentos.
Isto é feito com a notação `n-*`, em que `n` é o número mínimo de argumentos:

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

Numa macro de várias linhas, `%0` representa o _número_ de argumentos da macro.
Isto é particularmente útil em macros que podem receber um número arbitrário de argumentos.

### Rótulos dentro de uma macro

Uma macro que define um rótulo comum deixa de funcionar no momento em que é usada duas vezes, porque o rótulo também ficaria definido duas vezes.
Para usar rótulos dentro de uma macro que pode ser chamada mais de uma vez, é necessário colocar `%%` antes desse rótulo.
Isto indica ao assembler que dê a esse rótulo um nome diferente e único a cada expansão:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Repetir em tempo de assemblagem

É possível repetir um bloco de código de uma linha com [`times`][times].
Isto é particularmente útil ao declarar valores repetidos na memória:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Para repetir código de várias linhas, podemos usar `%rep` em alternativa:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Repara que o número de repetições é indicado logo a seguir a `%rep` e que há um `%endrep` para fechar o bloco repetido.

É comum usar um contador de tempo de assemblagem dentro de um bloco `%rep`, tal como um ciclo em tempo de execução usa um contador.
Embora uma constante inteira de tempo de assemblagem possa ser declarada com `equ`, como já vimos, para _variáveis_ inteiras de tempo de assemblagem usamos antes `%assign`.
Ao contrário de `%define`, `%assign` é avaliado imediatamente para um número e pode ser reatribuído:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Depois de o pré-processador correr, o ciclo desaparece e restam quatro instruções `add`, com os valores imediatos `0`, `1`, `2` e `3` já embutidos.
Isto é o desenrolar do ciclo feito pelo assembler: sem registo contador e sem salto, apenas código linear.

Outra utilização comum de `%rep` é tratar argumentos numa macro que pode receber qualquer número deles.
Nesse caso, o `%rep` costuma ser combinado com `%rotate`, que roda os argumentos de uma macro, de modo que o segundo argumento passa a ser o primeiro.
Aplicações repetidas de `%rotate` fazem com que o terceiro argumento, depois o quarto, e por aí adiante, passe a ser o primeiro, garantindo que cada argumento pode ser tratado a seu tempo:

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## Assemblagem condicional

O [pré-processador][preprocessor] tem vários condicionais disponíveis.
Selecionam entre vários caminhos diferentes, expandindo o seu corpo no próprio local, mas apenas quando a sua condição é verdadeira.

`%if` ... `%elif` ... `%else` ... `%endif` selecionam um ramo a partir de um teste numérico:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef` e `%ifndef` são semelhantes, mas testam se um nome foi definido.
Por exemplo, podem ser usados para garantir que o conteúdo de um ficheiro é incluído apenas uma vez, mesmo quando o ficheiro é trazido por mais do que um ficheiro fonte:

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

Deves ter reparado que no fim de cada ficheiro `.asm` deste track há este pedaço de código:

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn` compara dois pedaços de texto para ver se coincidem exatamente.
O `__OUTPUT_FORMAT__` incorporado expande para o formato de saída atual, por isso esse código verifica se o formato de saída é `elf64`, que é o formato usado pelos sistemas Linux.
Se for, é adicionada uma nota ao ficheiro objeto a declarar as permissões que a pilha deve ter, uma medida de segurança comum.
Se não for, nada muda.

## Estruturas

Chegar a um campo de um registo na memória significa somar o deslocamento em bytes do campo a um endereço base.
Escrever esses deslocamentos como números em bruto é propenso a erros e esconde o seu significado.
[`struc`][struc] e `endstruc` dão um nome a um layout, transformando cada campo num deslocamento simbólico calculado em tempo de assemblagem.

Dentro do bloco, as diretivas de reserva `resb`, `resw`, `resd` e `resq` reservam um ou mais bytes, words, doublewords ou quadwords.
Colocar um `.` à frente de cada campo mantém o nome do campo restrito ao âmbito da estrutura:

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

Cada nome de campo passa a representar o seu deslocamento, por isso `thread.color` é `0`, `thread.tension` é `4` e `thread.name` é `12`.
O NASM também define `<struc>_size` como o total, em que `<struc>` é o nome do `struc`.
Por exemplo, aqui `thread_size` seria `4 + 8 + 16 = 28`.

Chega-se a um campo somando o seu deslocamento a um registo base, e `thread_size` é o passo de um registo para o seguinte:

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

Um `struc` descreve apenas uma forma, não aloca memória por si só.
Para criar uma instância inicializada, podes usar `istruc ... iend` depois de um rótulo.
Dentro de uma instância, `at` coloca um valor num campo com nome:

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

Repara que `thread.name` é inicializado com `"warp", 0`, que ocupa apenas 5 bytes.
Os outros 11 bytes reservados para ele no `struc` são preenchidos automaticamente com zeros pelo `iend`, que completa a instância até `thread_size` com `0`.

Um `struc` é apenas açúcar sintático para memória que também podemos declarar manualmente.
Por exemplo, o código acima é equivalente ao seguinte, em que `times 11 db 0` garante que são alocados 16 bytes no fim:

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## Dividir em ficheiros

As macros são frequentemente guardadas num ficheiro próprio e trazidas para cada ficheiro fonte que precisa delas com `%include`:

```x86asm
%include "patterns.mac"
```

O ficheiro indicado é inserido textualmente nesse ponto, antes da assemblagem, exatamente como se o seu conteúdo tivesse sido escrito ali.
Isto mantém as definições num único local e permite que vários ficheiros fonte as partilhem.

Se o ficheiro de macros puder ser assemblado de forma autónoma, deve ter a extensão `.asm`.
Repara que as macros não têm ligação.
Mesmo que o ficheiro de macros seja assemblado, as suas macros só são visíveis para outro ficheiro que o inclua com `%include`.

Caso contrário, um ficheiro que só sirva para `%include` pode ter qualquer extensão.
Usar `.asm` ou `.mac` é uma convenção comum.
