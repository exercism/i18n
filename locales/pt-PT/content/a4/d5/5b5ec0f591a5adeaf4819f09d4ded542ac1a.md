# Instruções

Este problema é modelado a partir do escalonamento estático não preemptivo de sistemas operativos de tempo real, mas também é semelhante ao Job-Shop Scheduling Problem (JSP) com apenas um recurso. Este problema assume que todas as tarefas são conhecidas estaticamente. Por outras palavras, os tempos de libertação de todas as tarefas deste problema são conhecidos no início do programa. Na prática, os tempos de libertação das tarefas não são conhecidos no início de um programa e podem ser gerados a qualquer momento através de I/O, interrupções, etc.

Dada uma lista de tarefas com parâmetros, determina um escalonamento em que as tarefas possam ser executadas sequencialmente, sem sobreposição. Como o problema é modelado a partir do escalonamento de processos de um RTOS, vamos assumir que é necessário um intervalo de tempo diferente de zero entre tarefas, também conhecido como sobrecarga de troca de contexto. Existem dois tipos diferentes de tarefas: periódicas e dinâmicas. Ambos os tipos têm um parâmetro de ID de tarefa, que é uma string usada para distinguir as diferentes tarefas da lista.

Uma **tarefa periódica** é definida como uma tarefa que é executada periodicamente. Por outras palavras, a tarefa é executada uma vez a cada T segundos, em que T é definido como o período.
Uma tarefa periódica é definida pelos seguintes parâmetros:
* Tempo de Início - instante em que começa a primeira repetição, ou instância, da tarefa
* Período - tempo entre o início das repetições da tarefa
* Tempo de Execução - tempo que cada repetição demora a correr
* Tempo de Fim - instante em que a tarefa deixa de ser escalonada

Uma **tarefa dinâmica** é definida como uma tarefa que só é executada uma vez.
Uma tarefa dinâmica é definida pelos seguintes parâmetros:
* Tempo de Libertação - primeiro instante em que a tarefa PODE ser escalonada (NÃO é o mesmo que o tempo de início)
* Tempo de Execução - tempo que a tarefa demora a correr
* Prazo-limite - instante até ao qual a tarefa tem de terminar a execução

A função a implementar tem dois parâmetros de entrada. O primeiro parâmetro de entrada é uma lista de instâncias de `RealTimeTask`. As instâncias de `RealTimeTask` são dadas como instâncias de `PeriodicRealTimeTask` ou de `DynamicRealTimeTask`, com todos os parâmetros da tarefa como inteiros. Podes usar a função integrada `isinstance()` do Python para distinguir os dois tipos de tarefas na lista. A ordem da lista é irrelevante; olha apenas para os parâmetros das tarefas. O segundo parâmetro de entrada é um único inteiro que especifica a sobrecarga de troca de contexto. A sobrecarga de troca de contexto é sempre um inteiro não negativo.

O resultado deve ser um dicionário em que as chaves são o ID da tarefa das instâncias de RealTimeTask e o valor deve ser uma lista de tuplos de dois elementos. O formato dos tuplos de dois elementos é (tempo de início, tempo de fim). As tarefas dinâmicas devem conter apenas um tuplo na lista, ao passo que as tarefas periódicas podem conter mais do que um. A ordem dos tuplos na lista não é relevante. Se não for possível criar um escalonamento válido a partir da lista de tarefas com a sobrecarga de troca de contexto indicada, lança uma exceção `NoRtosStaticScheduleProducible`. Tem em atenção que os resultados do modelo Z3 para as variáveis têm de ser convertidos em inteiros antes de serem devolvidos. Se o resultado do modelo Z3 for do tipo `IntNumRef`, podes usar o método de classe `as_long()` para o converter num inteiro.

É fornecida uma função adicional que te permite visualizar a ordem sequencial das tarefas. Também podes ativá-la para casos de teste individuais, definindo o argumento nomeado `plot` como `True` na função `check()`. É usado um gráfico de barras horizontais segmentadas para representar e rotular cada tarefa. Para utilizares esta função, é necessário ter a biblioteca Python *matplotlib* instalada. Podes encontrar os detalhes de instalação da *matplotlib* [aqui](https://matplotlib.org/stable/users/installing.html).
