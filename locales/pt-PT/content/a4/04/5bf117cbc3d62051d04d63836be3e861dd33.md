# Sobre

O Elm é uma linguagem encantadora para construir aplicações web fiáveis.
Tem mensagens de erro amigáveis, excelente desempenho, recursos pequenos e nenhuma exceção em tempo de execução.

Provavelmente, a parte mais famosa e mais amplamente copiada do Elm é o The Elm Architecture, um padrão simples para estruturar aplicações web e a forma como todas as aplicações web em Elm são escritas.

A ideia central é que o teu código gira em torno de um `Model` do estado da tua aplicação, de uma forma de o atualizar com `update` e de uma forma de o ver com `view`.

O `Model` contém o estado da aplicação: todos os dados de que a aplicação precisa.
Pode ser de qualquer tipo, mas em qualquer aplicação útil é normalmente um [registo][record].
Se imaginares uma aplicação simples com uma caixa de texto e um texto que mostra o inverso desse texto, o modelo teria o seguinte aspeto.
Também podes ver este exemplo no [Elm Guide][elm-guide-text-fields].

```elm
type alias Model =
  { text : String
  }
```

`update` é uma função que é chamada com uma `Msg` quando há uma alteração (como o utilizador clicar num botão).
Recebe a `Msg` e o `Model` atual e devolve um novo `Model`.
A `Msg` pode ser de qualquer tipo, mas normalmente é um [tipo personalizado][custom-type].

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

Tal como em todos os tipos personalizados, as variantes da `Msg` podem incluir tanta informação arbitrária quanta precisarem.
No exemplo acima, a variante `TextChanged` inclui uma `String`.

`view` é uma função que devolve HTML para mostrar ao utilizador no navegador.
Recebe o `Model` atual e devolve um `Html Msg` (o tipo que o Elm usa para representar HTML).
Cada elemento HTML (por exemplo, `<div>`) tem uma função Elm correspondente (`Html.div`), no pacote `Html`.
Cada uma destas funções recebe dois parâmetros: o primeiro é uma lista de atributos (dos pacotes `Html.Attributes` e `Html.Events`) e o segundo é uma lista de elementos filhos (funções do pacote `Html`).
Existe também uma função `text` que representa conteúdo de string em HTML, que recebe apenas um parâmetro do tipo string, mas, fora isso, é usada da mesma forma que todas as outras funções/elementos do pacote `Html`.

A função `view` pode especificar que determinados eventos, como clicar num botão ou editar texto numa caixa de texto, dão origem à criação de uma `Msg`, que o Elm Runtime vai usar para chamar a função `update`, modificar o `Model` e gerar HTML atualizado.
No código abaixo, isto acontece com `Html.Events.onInput TextChanged`.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

`Html.Events.onInput` espera receber uma função (`String -> Msg`) que vai usar para criar a `Msg`.
Eventos diferentes esperam funções diferentes, consoante a informação que conseguem fornecer; por exemplo, `Html.Events.onCheck` (para caixas de seleção) espera `Bool -> Msg` e `Html.Events.onClick` espera apenas uma `Msg`.

A linguagem Elm é pura e funcional e não é possível qualquer mutação, por isso o Elm Runtime trata de tudo o que muda.
Podes ver todos os diferentes [elementos HTML][html-elements], [atributos de elementos][element-attributes] e [eventos HTML][html-events] no registo de pacotes do Elm.

Há 4 «níveis» de aplicações web que podes escrever em Elm, que se tornam progressivamente mais poderosos e mais complicados (embora o Elm continue a ser uma linguagem e um ecossistema encantadoramente simples).
Estão todos definidos no [pacote Browser][browser-package]:

- [sandbox][browser-sandbox]: reage à entrada do utilizador, como botões e caixas de seleção
- [element][browser-element]: comunica com o mundo exterior, usando HTTP e interoperabilidade com JavaScript
- [document][browser-document]: controla o `<title>` e o `<body>` de uma página web
- [application][browser-application]: cria aplicações completas de página única que gerem o encaminhamento e as alterações de URL

Este conceito usa o [sandbox][browser-sandbox], por ser o mais simples (e, como é uma sandbox, é relativamente fácil trabalhar com o editor online do Exercism).
O módulo de entrada de um programa Elm tem de se chamar `Main`, e a função que cria a aplicação tem de se chamar `main`, como se mostra abaixo.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

Já vimos as funções `update` e `view`, e o [sandbox][browser-sandbox] exige ainda uma função `init`, para devolver o estado inicial do `Model`.
