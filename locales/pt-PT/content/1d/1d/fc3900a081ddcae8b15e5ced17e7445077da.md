# Sobre

Preparar um valor para transmissão significa três coisas ao mesmo tempo:
serializá-lo, escolher a parte certa dele e não copiar quando não é
preciso. Três expressões idiomáticas do Factor dão conta disso.

## `unparse`: do valor ao código-fonte

[`unparse`][unparse] (em `prettyprint`) devolve o texto em forma de
código-fonte de qualquer valor. É o inverso do parser: a ida e volta
`dup unparse parse` reconstrói o valor.

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

Compara com `>string` (que só funciona em sequências de carateres) e
`number>string` (só números). `unparse` é o universal, mas à custa de
produzir sintaxe do Factor (as strings entre aspas mantêm as aspas). Por
isso, é a ferramenta certa quando quem recebe vai voltar a fazer o parse
do texto, e a ferramenta errada para saída legível por humanos.

## Slices: vistas, não cópias

| palavra       | efeito                                          |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )`: copia os primeiros n     |
| `head-slice`  | `( seq n -- slice )`: vista dos primeiros n     |
| `tail`        | `( seq n -- newseq )`: copia a partir do índice n |
| `tail-slice`  | `( seq n -- slice )`: vista a partir do índice n |
| `head*`       | `( seq n -- newseq )`: copia tudo menos os últimos n |
| `head-slice*` | `( seq n -- slice )`: vista de tudo menos os últimos n |
| `tail*`       | `( seq n -- newseq )`: copia os últimos n       |
| `tail-slice*` | `( seq n -- slice )`: vista dos últimos n       |

Um `slice` é um tuple que guarda um índice inicial, um índice final e a
sequência subjacente. Implementa o [protocolo de sequências][sequence-protocol], por isso
qualquer operação de sequência funciona sobre ele. Recorre às
variantes de slice quando, de outra forma, terias de alocar só para ler;
recorre às que copiam quando precisas de manter os dados depois de a
sequência subjacente vir a mudar.

## Cleave com várias entradas: `2bi`, `3bi`, `2tri`, `3tri`

As palavras cleave simples `bi` e `tri` aplicam duas ou três
quotations a *uma* entrada na pilha. As variantes com o prefixo `2`
e o prefixo `3` aplicam cada quotation a *duas* ou *três*
entradas:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

Cada quotation recebe *todas* as entradas. Por isso, usa `2bi` quando
ambas as projeções dependem do par, e não quando queres a mesma
projeção aplicada a cada entrada em separado (isso é `bi@`).

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

Para *uma* quotation aplicada a cada entrada em separado, recorre antes
a `bi@` (duas entradas) ou `tri@` (três entradas): a mesma família,
uma forma diferente.
