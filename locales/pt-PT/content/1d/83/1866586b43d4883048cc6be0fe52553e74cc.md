# Apêndice às instruções

## Manter a contagem em Roc

É o teu wrapper que trata da contabilidade interna; o backend fornecido faz a leitura e a escrita de facto.
Não tens de abrir ficheiros nem ligações.

`Paasio(state, err)` funciona com qualquer estado de backend e qualquer tipo de erro.
O backend guarda o `state` inicial e dois callbacks:

- `read!(state, max_bytes)` devolve `{ state, result }`, com `Ok(bytes)` ou `Err(error)`.
- `write!(state, bytes)` devolve `{ state, result }`, com `Ok(bytes_written)` ou `Err(error)`.

Inicializa a zero os quatro contadores de cada wrapper.
`create`, `stats` e `get_state` não podem invocar os callbacks.
Para cada `read!` ou `write!`, chama o callback correspondente exatamente uma vez, passando os argumentos sem alterações.
Guarda o estado e o resultado devolvidos, mesmo em caso de falha, e devolve `{ io, result }`.
Transporta esse `io` atualizado para a chamada seguinte.

## Todas as tentativas contam

Mantém as estatísticas de leitura e de escrita separadas:

- Conta todas as chamadas, incluindo falhas, EOF, leituras de zero bytes e escritas vazias.
- Conta bytes apenas em caso de sucesso: o comprimento da lista devolvida nas leituras e o número indicado nas escritas.
- Uma transferência parcial continua a contar como uma única chamada: não a repitas, tal como não repetes uma operação falhada.

O backend de ficheiro real usa o basic-cli, que comunica o EOF como `Err(EndOfInput)`.
Preserva esse resultado sem alterações: conta como uma operação de leitura e zero bytes.
Um `Ok([])` é uma leitura vazia bem-sucedida, como um pedido de zero bytes; não é o sinal de EOF do basic-cli.

Conta aquilo que o backend comunica; não precisas de acompanhar as chamadas ao sistema operativo nem os buffers.
Podes confiar na contagem de bytes do backend e assumir que os contadores cabem num `U64`.

## Executar os testes

Os testes usam tanto backends em memória como um ficheiro real num diretório temporário, que é eliminado no fim.

Ao contrário da maioria dos outros exercícios, este exercício usa funções com efeitos (neste caso, baseadas na plataforma `basic-cli`).
Por isso, se quiseres correr os testes localmente, tens de usar `roc --opt=speed paasio-test.roc` em vez de `roc test` (porque atualmente a instrução `expect` não consegue testar funções com efeitos).

Qualquer erro devolvido pelo código Roc é comunicado pela plataforma, num formato diferente do habitual.
