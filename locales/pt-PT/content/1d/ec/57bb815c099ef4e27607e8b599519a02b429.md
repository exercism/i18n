# Combinação de iteradores

Um ciclo pode chamar mais de um iterador. A cada volta, pede-se-lhe o valor
seguinte uma vez, e ambos avançam em conjunto.

```sather
   loop
      first ::= violin_one.elt!;
      second ::= violin_two.elt!;
      #OUT + first + " against " + second + "\n";
   end;
```

Isto percorre os dois arrays lado a lado: o primeiro elemento com o
primeiro, o segundo com o segundo.

## A regra que surpreende toda a gente

**O ciclo termina assim que o *primeiro* dos seus iteradores se esgota.**

Não quando o último se esgota. Nem quando todos se esgotam. O primeiro.

Por isso, se o `violin_one` tiver quatro compassos e o `violin_two` tiver
dois, o ciclo acima corre **duas vezes**. Os terceiro e quarto compassos da
primeira parte nunca chegam a ser vistos, porque nessa altura a segunda
parte já não tem nada para oferecer.

Normalmente é exatamente isto que se quer, pois emparelhar coisas só faz
sentido enquanto há pares. Mas é preciso saber isto, em vez de o descobrir
por acaso.

## Contar ao mesmo tempo

Um iterador que nunca se esgota é útil precisamente por causa dessa regra.
O `up!` conta para sempre:

```sather
1.up!        -- 1, 2, 3, 4, ... and never ends
```

Sozinho, faria um ciclo infinito. Emparelhado com um que termina, numera
os valores sem nunca decidir até onde contar:

```sather
   loop
      number ::= 1.up!;
      bar ::= part.elt!;
      #OUT + "Bar " + number + ": " + bar + "\n";
   end;
```

É o `part.elt!` que termina o ciclo; o `1.up!` fornece a numeração. Nenhum
deles precisa de saber qual é o comprimento da parte.

## A ordem não importa

Pede-se a todos os iteradores uma vez por volta, por isso não faz diferença
qual deles é escrito primeiro. O que importa é que se peça exatamente uma
vez a cada um: escrever `part.elt!` duas vezes numa só volta faz com que se
obtenham dois valores em vez de um.
