# Propriedade

Em Cairo, o conceito de propriedade está associado às _variáveis_ e não aos _valores_ que elas guardam.

Em Cairo, os valores são imutáveis. Esta imutabilidade garante que, mesmo que muitas variáveis se refiram ao mesmo valor, o valor em si permanece constante e inalterado.
Por isso, o compilador tem de garantir que o programador os utiliza corretamente.
É este o significado da _propriedade_ de uma variável: o proprietário é o código que pode ler (e escrever, se for mutável) a variável.

## Regras de propriedade das variáveis

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## Âmbito das variáveis

Um âmbito é a região de um programa na qual uma variável é válida.
Vamos ver o exemplo seguinte, que declara uma variável `x` de tipo inteiro sem sinal, com comentários a assinalar onde a variável é válida:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Notas:

- Quando `x` entra em âmbito, é válida.
- Mantém-se válida até sair de âmbito, neste caso até ao fim da função `main()`.

## Mover valores

Ocorre uma movimentação quando um valor é passado a outra função, destruindo a variável original que se referia ao valor (tornando assim a variável inútil) e criando uma nova variável para guardar o mesmo valor.

Os arrays são um exemplo de um tipo complexo que é movido ao ser passado a outra função.
Eis uma pequena recordação de como é um array:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

Como é que o sistema de tipos garante que o programa em Cairo nunca tenta escrever na mesma célula de memória duas vezes?
Considera o código seguinte, em que tentamos remover a frente do array duas vezes:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

Neste caso, tentamos passar o mesmo valor (o array na variável `arr`) às duas chamadas de função.
Isto significa que o nosso código tenta remover o primeiro elemento duas vezes, o que tentaria escrever na mesma célula de memória duas vezes, algo proibido pela VM do Cairo e que origina um erro em tempo de execução.
Felizmente, este código não compila.
Assim que passamos o array à função `foo`, a variável `arr` deixa de ser utilizável.
Obtemos este erro em tempo de compilação, que nos diz que `Array` teria de implementar o trait `Copy`:

## O trait Copy

Se um tipo implementa o trait `Copy`, passá-lo a uma função não move o valor, mas cria uma nova variável que se refere ao mesmo valor.
Esta é uma operação sem custos, porque as variáveis são uma abstração do Cairo e os valores são sempre imutáveis.

Para implementares o trait `Copy` no teu tipo, adiciona a anotação `#[derive(Copy)]` à definição do tipo.
No entanto, o Cairo não o permite se o tipo, ou qualquer um dos seus componentes, não implementar o trait `Copy`.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## Destruir valores

Os tipos lineares também podem ser utilizados ao serem destruídos, o que garante que o recurso associado é corretamente libertado.
Isto consegue-se implementando ou derivando o trait `Drop`, que indica ao compilador que o tipo pode ser destruído em segurança assim que deixa de ser útil.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

De momento, a implementação de `Drop` pode ser derivada para todos os tipos, exceto para dicionários (`Felt252Dict`) e tipos que contenham dicionários.
Isto acontece porque os dicionários têm de ser "squashed" quando são destruídos.
Para isso, derivamos o trait `Destruct`:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## Valores devolvidos e âmbito

Devolver valores é equivalente a movê-los.
O exemplo abaixo mostra uma função que devolve um valor:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
