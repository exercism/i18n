# Etiquetas dos analisadores

As etiquetas dos analisadores servem para identificar _como_ uma solução foi resolvida.

Estas etiquetas podem depois ser usadas para:

- Associar uma solução a abordagens
- Associar uma solução a conceitos
- Procurar soluções com determinadas etiquetas

## Formato

Uma etiqueta é uma string formatada como: `<category>:<thing>`.

Suportamos quatro categorias diferentes, do nível mais elevado para o mais baixo:

| Categoria   | Descrição                                       | Especificidade                                   | Exemplos                              |
| ----------- | ----------------------------------------------- | ------------------------------------------------ | ------------------------------------- |
| `paradigm`  | Um [paradigma de programação][programming-paradigms] | Muito abstrato, não específico de um track  | `imperative`, `functional`            |
| `technique` | Uma técnica utilizada                            | Abstrato, a maioria não será específica de um track | `recursion`, `immutability`       |
| `construct` | Um construto da linguagem                        | Muitos não serão específicos de um track        | `bitwise-and`, `for-loop`             |
| `uses`      | Utilização específica da linguagem, como tipos ou métodos | Concreto, específico de um track        | `DateTime.add_seconds`, `IEnumerable` |

Alguns exemplos de etiquetas:

- `paradigm:functional`
- `technique:recursion`
- `construct:bitwise-and`
- `uses:DateTime.add_seconds`

## Etiquetas habitualmente usadas

Embora os tracks sejam livres de etiquetar as soluções como entenderem, recomendamos que tentes usar a lista de etiquetas habitualmente usadas abaixo sempre que possível.
Usar um conjunto comum de etiquetas permite-nos fazer coisas bem úteis, como ligar soluções entre tracks.
