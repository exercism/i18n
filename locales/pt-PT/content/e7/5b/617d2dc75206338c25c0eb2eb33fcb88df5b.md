# Introdução

## Processos

Em Elixir, todo o código corre dentro de processos.

Por predefinição, uma função é executada no mesmo processo a partir do qual foi chamada. Quando precisas de executar explicitamente uma determinada função num novo processo, usa `spawn/1`:

```elixir
spawn(fn -> 2 + 2 end)
# => #PID<0.125.0>
```

`spawn/1` cria um novo processo que executa a função de aridade 0 fornecida e devolve um _identificador de processo_ (PID). O novo processo mantém-se vivo enquanto a função estiver a executar e, depois, termina silenciosamente.

Os processos de Elixir não devem ser confundidos com processos do sistema operativo. Os processos de Elixir usam muito menos memória e CPU. Não há problema nenhum em ter aplicações Elixir que correm centenas de processos Elixir.

### Mensagens

Os processos não partilham informação diretamente entre si. Os processos _enviam e recebem mensagens_ para partilhar dados.

Podes enviar uma mensagem a qualquer processo com `send/2`. O primeiro argumento de `send/2` é o PID do destinatário; o segundo argumento é a mensagem.

Uma mensagem pode ser de qualquer tipo. Muitas vezes, é composta por átomos e tuplas. Se quiseres obter uma resposta, deves incluir o PID do remetente algures na mensagem. Podes obter o PID do processo atual com `self()`.

`send/2` não verifica se a mensagem foi recebida pelo destinatário nem se o destinatário ainda está vivo. A mensagem acaba na _caixa de correio_ do destinatário e só é lida se e quando o destinatário pedir explicitamente para _receber mensagens_.

Uma mensagem pode ser lida de uma caixa de correio com a macro `receive/1`. Aceita um bloco `do` que pode [fazer correspondência de padrões][exercism-pattern-matching] com as mensagens.

```elixir
receive do
  {:ping, sender_pid} -> send(sender_pid, :pong)
  :do_nothing -> nil
end
```

`receive/1` retira _uma mensagem_ da caixa de correio que corresponda a qualquer dos padrões indicados e executa a expressão indicada para esse padrão. Se não houver mensagens na caixa de correio, ou se nenhuma das mensagens na caixa de correio corresponder a algum dos padrões, `receive/1` fica à espera de uma.

### Ciclo de receção

Se quiseres receber mais do que uma mensagem, tens de chamar `receive/1` recursivamente. É um padrão comum implementar uma função recursiva, por exemplo com o nome `loop`, que chama `receive/1`, faz algo com a mensagem e depois se chama a si própria para esperar por mais mensagens. Se precisares de transportar algum estado de uma chamada a `receive/1` para outra, podes fazê-lo passando um argumento a essa função `loop`.

## PIDs

Os identificadores de processo são um tipo de dados próprio. Funcionam como _endereços de caixa de correio_: se tiveres o PID de um processo, podes enviar uma mensagem a esse processo. Os PIDs são normalmente criados indiretamente, como valor devolvido de funções que criam novos processos, como `spawn`.
