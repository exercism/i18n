# Funções em `jq`

Podes definir as tuas próprias **funções personalizadas** em `jq` para encapsular a lógica de que precisares.
As _funções_ comportam-se exatamente como as funções incorporadas: recebem um valor de entrada e emitem zero, um ou mais valores de saída.

## Definir uma função

Podes definir uma _função_ `jq` com a seguinte sintaxe:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- começa com a palavra-chave `def`,
- dois pontos antes do corpo da função,
- o corpo é constituído por uma única expressão,
- termina com um ponto e vírgula,
- tal como no resto da sintaxe de `jq`, podes usar espaços em branco arbitrários para facilitar a leitura.

## Onde colocar as funções

As _funções_ têm de ser definidas antes de serem usadas: isto é um erro:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Isto implica que tens de colocar as _funções_ no topo do teu código `jq`, antes da expressão «principal».

### Funções aninhadas

As _funções_ podem ser aninhadas:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Aqui, a _função_ `B` só é visível no corpo de `A`.

## Âmbito

Uma _função_ introduz um novo **âmbito** para variáveis e funções aninhadas.

## Argumentos

Os **argumentos** de uma _função_ são separados por _pontos e vírgula_, não por vírgulas.
Por exemplo, uma _função_ que recebe um número e depois soma um número e multiplica por um número:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
Os pontos e vírgula são necessários porque a vírgula já tem uma finalidade em `jq`: é um operador que junta fluxos.

Usar uma vírgula em vez de um ponto e vírgula tentará fazer duas chamadas a uma _função_ `add_mul` _de 1 argumento_, que não existe e, por isso, falhará na primeira chamada tentada:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

A vírgula em `5, 4` concatena os números 5 e 4 num fluxo.
Quando chamamos uma função com um fluxo como argumento, o `jq` chama essa função várias vezes, uma vez por cada valor do fluxo.
Este é um exemplo da «iteração implícita» inerente aos fluxos de `jq`.
`10 | add_mul(5, 4)` é equivalente ao seguinte.

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
Agora já vemos como surge o erro `add_mul/1 is not defined`.
~~~~

<!-- prettier-ignore-end -->

### Os argumentos são _expressões_

Os _argumentos_ de uma função são filtros, não valores.
Neste sentido, comportam-se como aquilo a que outras linguagens chamam callbacks:

Usando a função `add_mul` como exemplo:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

O que está aqui a acontecer?

- o argumento `adder` recebe a _expressão_ `. + 5`
  - quando a função faz `. + adder`, isso torna-se `. + . + 5`
  - que é avaliada como 25, dado que `. == 10`
- da mesma forma, o argumento `multiplier` é a expressão `. - 2`
  - que é avaliada como 8
  - e o resultado é `25 * 8 == 200`

### Argumentos como valores

Por vezes, vais querer «materializar» um _argumento_ numa variável:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Há uma sintaxe abreviada para isto:

```jq
def my_func($arg):
    other stuff ...
;
```

Tem em atenção que isto é apenas «açúcar sintático»: o nome `arg` sem `$` continua no âmbito da _função_.

<!-- prettier-ignore -->
~~~~exercism/caution
Por exemplo, escrevi algo assim para resolver um exercício:

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

e fiquei surpreendido por todos os valores do array serem iguais à chave.

Isto aconteceu porque o jq viu a função `equals` como

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

O **argumento** `code` _sobrepôs-se_ à **função** `code` definida anteriormente.
Isso significava que `(. | code)` simplesmente produz o **argumento** em vez de calcular um novo código com base no valor de entrada.
Assim, `$this_code` e `$code` eram sempre iguais.
~~~~

## Aridade

As _funções_ têm uma **aridade**, ou seja, o número de _argumentos_ que recebem.

As _funções_ podem usar o mesmo nome com _aridades_ diferentes.
A função incorporada [`range`][man-range] demonstra isto: `range/1`, `range/2` e `range/3` coexistem.

Isto pode ser útil para definir funções recursivas que transportam estado através de argumentos.
Por exemplo, `map` _poderia_ ser implementado assim:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Recursão

O `jq` faz otimização de chamadas de cauda, mas apenas para funções de aridade 0.

## Módulos

Um módulo `jq` é um ficheiro que contém apenas funções.
Os módulos são incluídos num programa jq com os comandos [`include`][man-include] ou [`import`][man-import].
