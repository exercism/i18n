# Introdução

Um [operador de comparação][comparisons] em Python (_também chamado de operador relacional_), analisa os _valores_ de dois [operandos][operand] e devolve um valor Boolean, `True` ou `False`, consoante a condição `comparison` se verifique ou não.

A tabela abaixo mostra os operadores de comparação mais comuns de Python:

| Operador | Operação                   | Descrição                                                                 |
| -------- | -------------------------- | ------------------------------------------------------------------------- |
| `>`      | "maior que"                | `a > b` é `True` se `a` for **estritamente** maior, em valor, do que `b`  |
| `<`      | "menor que"                | `a < b` é `True` se `a` for **estritamente** menor, em valor, do que `b`  |
| `==`     | "igual a"                  | `a == b` é `True` se `a` for **estritamente** igual a `b` em valor        |
| `>=`     | "maior ou igual a"         | `a >= b` é `True` se `a > b` OU se `a == b` em valor                      |
| `<=`     | "menor ou igual a"         | `a <= b` é `True` se `a < b` ou se `a == b` em valor                      |
| `!=`     | "diferente de"             | `a != b` é `True` se `a == b` for `False`                                 |
| `is`     | "identidade"               | `a is b` é `True` se, **_e só se_**, `a` e `b` forem o mesmo _objeto_     |
| `is not` | "identidade negada"        | `a is not b` é `True` se, **_e só se_**, `a` e `b` **não** forem o mesmo _objeto_ |
| `in`     | "teste de pertença"        | `a in b` é `True` se `a` for membro, subconjunto ou elemento de `b`       |
| `not in` | "teste de pertença negado" | `a not in b` é `True` se `a` não for membro, subconjunto ou elemento de `b` |

Todos têm a mesma precedência (_que é mais alta do que a das [operações Boolean][boolean operations], mas mais baixa do que a das operações aritméticas ou bit a bit_).

## Comparação entre tipos de dados diferentes

Objetos de tipos diferentes (_exceto os tipos numéricos_) nunca são considerados iguais por predefinição.
Instâncias não idênticas de uma `class` também _**não**_ são consideradas iguais, a menos que a `class` defina métodos especiais que personalizem o comportamento de comparação predefinido do `object`.

Os tipos numéricos são (em grande parte) uma exceção a esta regra de correspondência de tipos.
Um `integer` **pode** ser considerado igual a um `float` (_ou um [`octal`][octal] igual a um [`hexadecimal`][hex]_), desde que os tipos possam ser convertidos implicitamente para efeitos de comparação.

Para os outros tipos numéricos ([complex][complex numbers], [decimal][decimal numbers], [fractions][rational numbers]), os operadores de comparação estão definidos onde "fazem sentido" (_onde a conversão implícita não altera o resultado_), mas lançam um `TypeError` se os objetos subjacentes não puderem ser convertidos com exatidão para efeitos de comparação.

## Comparar a identidade de objetos

Os operadores `is` e `is not` testam a [_identidade_][object identity] de um objeto, e não o seu _valor_.
A identidade de um objeto nunca muda depois de este ser criado e pode ser obtida com a função [`id()`][id function].

`<apple> is <orange>` é avaliado como `True` se, _**e só se**_, `id(<apple>)` == `id(<orange>)`.
`<apple> is not <orange>` dá o resultado inverso.

## Comparações de pertença

Os operadores `in` e `not in` testam a _pertença_.
`<fish> in <soup>` é avaliado como `True` se `<fish>` for membro de `<soup>` (_se `<fish>` for um subconjunto de `<soup>` ou estiver contido em `<soup>`_), e como `False` caso contrário.
`<fish> not in <soup>` devolve a negação, ou o _oposto_ de `<fish> in <soup>`.

Para os tipos string e bytes, `<name> in <fullname>` é `True` _**se e só se**_ `<name>` for uma substring de `<fullname>`.
