# Iteradores personalizados

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | rotina | iterador |
| --- | --- | --- |
| nome | `foo` | `foo!` |
| devolve um valor | `return` | `yield` |
| termina | `return`, ou o fim | `quit`, ou esgotar-se |
| pode ser chamado | em qualquer lugar | apenas dentro de um `loop` |
| mantém a sua posição | não | sim |

## yield

`yield` entrega um valor e suspende a execução. Tudo é restaurado na vez seguinte: as variáveis locais, a posição nos ciclos do próprio iterador e as posições de quaisquer iteradores que ele próprio esteja a chamar.

Um `yield` dentro de ciclos aninhados retoma no mais interior, e é isso que torna simples escrever um percurso sobre algo aninhado:

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

Termina o iterador e, por consequência, o ciclo que o chama. Não transporta nenhum valor: um `quit` não é um último resultado, é o anúncio de que não existe nenhum.

Um iterador com um tipo de retorno tem de `yield` um valor de cada vez que produz um resultado; `quit` é a forma de se recusar a fazê-lo.

## once

```sather
   markers!(once count : INT) : INT is
```

Um argumento `once` é avaliado quando se entra no ciclo e é mantido. Um argumento simples é reavaliado em cada vez, o que é importante quando a expressão passada contém outra chamada a um iterador:

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

Marca os argumentos como `once`, a menos que queiras especificamente isso. É o que toda a biblioteca faz.

## self e iteradores

Um iterador pode ser chamado sobre um objeto e, nesse caso, `self` é esse objeto. O seu estado suspenso pertence ao local da chamada, não ao objeto, por isso dois ciclos que percorrem o mesmo objeto não interferem um com o outro.

## Quando escrever um

Escreve um iterador quando a resposta é uma sequência e quem chama deve decidir quanto dela quer receber. Parar cedo não tem custo e nada é construído sem ser utilizado. Já uma rotina que devolve um `ARRAY` tem de construir tudo primeiro.
