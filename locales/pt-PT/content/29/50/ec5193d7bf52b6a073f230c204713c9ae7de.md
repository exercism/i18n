# Rotinas vinculadas

Até aqui, tudo tem andado a passar *valores* de uns para os outros: números, strings, objetos. Uma **rotina vinculada** permite-te passar a própria rotina: algo que será chamado mais tarde, por código que não sabe o que é.

Um suplente é exatamente essa ideia: o diretor de cena fica com uma forma de representar o papel, sem saber quem é nem o que vai fazer.

## Criar uma

O `bind` recebe uma chamada com lacunas, escritas `_`:

```sather
   shout(line : STR) : STR is return line.upper; end;

   ...

   part ::= bind(shout(_));
```

O `part` é agora um valor como qualquer outro. A chamada faz-se mais tarde:

```sather
   part.call("who's there")      -- "WHO'S THERE"
```

## O tipo

O tipo de uma rotina vinculada é `ROUT`, com os tipos dos argumentos entre chavetas e o tipo devolvido depois de dois pontos:

```sather
   part : ROUT{STR}:STR := bind(shout(_));
```

Lê `ROUT{STR}:STR` como "uma rotina que recebe um `STR` e devolve um `STR`".

| Escrito | Significa |
| --- | --- |
| `ROUT{STR}:STR` | recebe um `STR`, devolve um `STR` |
| `ROUT{INT,INT}:BOOL` | recebe dois `INT`, devolve um `BOOL` |
| `ROUT{STR}` | recebe um `STR`, não devolve nada |
| `ROUT:INT` | não recebe nada, devolve um `INT` |

Como é um tipo, pode ser um argumento:

```sather
   rehearse(line : STR, part : ROUT{STR}:STR) : STR is
      return part.call(line);
   end;
```

O `rehearse` não faz ideia do que o `part` faz. É esse o objetivo: pode receber o `shout`, o `whisper` ou qualquer outra coisa com a mesma forma.

## Preencher alguns dos argumentos

Nem todos os argumentos têm de ser uma lacuna. Tudo o que esteja escrito fica fixo no momento em que o `bind` acontece:

```sather
   repeat(times : INT, line : STR) : STR is ... end;

   twice ::= bind(repeat(2, _));      -- ROUT{STR}:STR
```

O `twice` recebe apenas a linha, porque o `2` já está decidido. O valor é calculado no momento do `bind` e guardado, por isso alterar depois a variável de onde veio não faz diferença.

É assim que uma rotina genérica se transforma em muitas rotinas específicas.

## Vincular também o objeto

Numa rotina de um objeto, o objeto é a primeira coisa na chamada e pode ficar fixo ou ser deixado como lacuna:

```sather
   bind(board.home_goal)      -- this board's, always
   bind(_.home_goal)          -- whichever board is handed in later
```
