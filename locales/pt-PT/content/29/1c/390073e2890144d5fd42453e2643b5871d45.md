# Dicas

## Geral

A linguagem SGF tem uma definição recursiva:

```none
GameTree = "(" Sequence { GameTree } ")"
```

Ou seja, um GameTree é um pedaço de texto que começa com um `(`, seguido de algum texto chamado "Sequence" (uma lista de nós de jogo), _seguido de **zero ou mais** GameTrees filhos_, e termina com um `)`.

Talvez queiras usar expressões regulares para analisar um texto SGF.
No entanto, como os GameTrees podem estar aninhados dentro de outros GameTrees a qualquer profundidade, as expressões regulares padrão não são suficientemente poderosas para acompanhar os níveis de aninhamento.

Há algumas abordagens para resolver este exercício:

### Máquina de estados

Podes percorrer a string de entrada caráter a caráter, mantendo uma variável com a tua posição atual.
Podes acompanhar o estado atual do texto analisado com base no caráter na posição atual.
O "estado atual" pode ser algo como "a ler um nome de propriedade" ou "dentro de um valor de propriedade".
Com esta abordagem, há muitos valores que precisas de acompanhar.

### Parser

Um [parser baseado em PEG][PEG-parser] é uma ótima forma de analisar uma linguagem que tem uma gramática definida.
O [LPeg][LPeg] é um parser PEG e é uma das dependências obrigatórias do MoonScript, por isso já tens acesso a ele.
Um parser permite-te escrever regras sobre o aspeto que o texto deve ter.
Por exemplo, "um nome de propriedade é composto por letras maiúsculas" ou "um valor de propriedade está entre parênteses retos".
Depois, o parser encarrega-se do trabalho pesado de fazer corresponder o texto de entrada às tuas regras.

* [Tutorial do LPeg][tutorial] na wiki lua-users.
