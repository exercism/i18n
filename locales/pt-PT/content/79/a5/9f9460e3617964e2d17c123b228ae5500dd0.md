# Introdução

Já *usaste* streams em `channel-chatter` e descartaste-os em `boatswains-bilge`. Este exercício é o teu primeiro stream personalizado: uma classe que implementa o [protocolo][stream-protocol], para que o mesmo código `with-input-stream` / `read1` / `stream-read1` que funcionava num `<string-reader>` funcione no teu.

## Mixins: a outra metade da hierarquia de classes

Já conheces `TUPLE: child < parent …` de `dragons-descendants`: uma hierarquia de herança simples, em que os slots passam de cima para baixo. O Factor tem uma *segunda* forma de estender o grafo de classes: os **mixins abertos**. Um `MIXIN: m` declara uma classe sem slots, à qual outras classes se podem juntar mais tarde com `INSTANCE: c m`. A associação é muitos-para-muitos: uma classe pode ser instância de tantos mixins quantos quiser.

O protocolo dos streams usa dois mixins para assinalar que metade da interface uma classe implementa:

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

Um stream pode ser um, o outro, ou ambos. Os métodos genéricos de `input-stream` (ou `output-stream`) são então despachados para qualquer classe que se tenha juntado ao mixin. É assim que o `read1`, o `stream-contents`, o `with-input-stream`, etc. que tens à disposição encontram o caminho até à tua classe.

Os mixins são *abertos*: podes acrescentar um novo membro depois de o mixin ser declarado, até num vocabulário diferente. É este o contraste com `TUPLE: < parent`, em que a relação fica fixada quando a subclasse é declarada.

## Os genéricos do protocolo

Os genéricos do protocolo estão em `io`:

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

O `stream-read1` devolve o byte seguinte (ou `f` no fim do stream); o `stream-write1` escreve um. O `stream-read-unsafe` é a leitura em lote de mais baixo nível que a maioria dos streams de entrada disponibiliza; o `stream-read` é construído sobre ele e trata da alocação. O `stream-element-type` indica se o stream trabalha com bytes (`+byte+`) ou com carateres (`+character+`); quando envolves outro stream, a implementação mais simples limita-se a delegar no stream subjacente.

## A limpeza vem de `destructors`

Os streams são descartáveis: um stream personalizado estende `disposable` e implementa `dispose*`. É esse o framework de `boatswains-bilge`, aplicado a uma classe de stream:

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

Depois de isso estar pronto, todos os combinadores `with-…` de `channel-chatter` funcionam automaticamente no teu stream.
