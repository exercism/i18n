# Sobre

A memória dinâmica é implementada por funções de biblioteca que o programador usa para alocar e libertar memória em tempo de execução.
Como é o programador que controla a alocação e a libertação da memória, a memória dinâmica é tão segura quanto o programador estiver livre de erro humano.
Por esse motivo, a memória dinâmica é uma das principais fontes de bugs de programação e um dos principais alvos de ataques informáticos.

A memória dinâmica usa-se para variáveis cujo tamanho só é conhecido em tempo de execução.
Isto é habitualmente útil para arrays cujo número de elementos pode variar de uma execução para a seguinte.
Os arrays de comprimento variável (VLA) são outra forma de lidar com arrays cujo tamanho dos elementos só é conhecido em tempo de execução.
Um VLA usa armazenamento automático, o que significa que a sua memória é destruída ao sair do bloco onde foi definido.
(Para mais informações sobre armazenamento, consulta o conceito [especificadores de classe de armazenamento](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers).)
Os VLA foram introduzidos na linguagem C pelo C99, mas, a partir do C11, os VLA são opcionais, pelo que os compiladores que suportam o C11 em diante não têm de suportar VLA.
Uma análise detalhada dos arrays de comprimento variável está fora do âmbito deste artigo.

## malloc

`malloc` é uma função declarada em `stdlib.h` que serve para alocar memória dinâmica.
Se a alocação for bem-sucedida, é devolvido um ponteiro que aponta para o endereço do primeiro byte da memória alocada.
Se a alocação não for bem-sucedida, é devolvido `NULL`.
É prudente verificar se o resultado de `malloc` é `NULL` e lidar com isso de forma adequada caso falhe.
O ponteiro devolvido é do tipo `pointer-to-void`, que pode ser considerado, aproximadamente, como um ponteiro "genérico" que pode ser convertido para o tipo específico usado pela memória.
`malloc` tem um parâmetro, que é o tamanho, em bytes, da memória pretendida.
O tamanho total para alocar um array é o tamanho do tipo de dados de cada elemento multiplicado pelo número de elementos.
O operador `sizeof` é habitualmente usado para obter o tamanho do tipo de dados de cada elemento.
O exemplo seguinte demonstra isto

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

É importante lembrar que a memória recém-alocada por `malloc` não é inicializada, mas pode conter valores de lixo.
Repara que o `sizeof` do ponteiro `numbers` não é o número de elementos do array, nem a quantidade total de memória alocada.
O tamanho do ponteiro devolvido por `malloc` é o tamanho de qualquer ponteiro nesse sistema em particular.
O código do exemplo foi executado num sistema de 64 bits, pelo que o tamanho do ponteiro era 8 bytes (multiplicado por 8 bits por byte = 64 bits).
O tipo do ponteiro foi convertido implicitamente de um ponteiro para void num ponteiro para int.
Se o ponteiro para int aponta para um único `int` ou para um array de `ints`s, isso é algo que o programador pode tratar como achar adequado.
Por exemplo

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

Se os valores forem definitivamente escritos antes de serem lidos, usar `malloc` pode ser uma forma eficiente de alocar memória.
Mas, se houver a possibilidade de os valores serem lidos antes de serem inicializados, usar `malloc` é arriscado.
Uma forma mais segura de alocar memória é usar `calloc`, que inicializa a memória recém-alocada a zero.

Repara que, nos exemplos acima, foi usado `free(numbers)`.

## free

`free` é uma função declarada em `stdlib.h` que serve para libertar memória que foi alocada dinamicamente.
A memória alocada dinamicamente permanece reservada na memória até ser libertada por `free`.
Alguns sistemas operativos podem libertar automaticamente a memória alocada dinamicamente quando o programa termina, mas é boa prática não depender disso.
`free` tem um parâmetro, que é um ponteiro para a memória que foi alocada dinamicamente.
O uso, ou a ausência de uso, de `free` está associado a vários problemas de memória.

#### fuga de memória

Não libertar a memória alocada dinamicamente depois de a referência a essa memória chegar ao fim do seu tempo de vida, ou ser de outra forma destruída, é o que se chama uma fuga de memória.
A memória perdida é memória que está reservada pelo sistema mas já não está acessível ao programa.
Isto pode ser um problema particular se a memória for alocada dentro de um ciclo, não for libertada no fim do ciclo e for alocada novamente no início do ciclo.
Se for alocada memória suficiente sem a libertar, a chamada para alocar memória falhará por não restar memória suficiente para alocar.
É importante lembrar que, embora a memória alocada dinamicamente esteja reservada pelo sistema até ser libertada, o ponteiro ao qual é atribuída pode ter apenas âmbito de bloco.
Por exemplo, nos exemplos com `malloc`, a memória é alocada em `my_function`.
Essa memória ficaria perdida se o ponteiro para ela não fosse devolvido e usado para definir o ponteiro `numbers` em `main`.
Assim, passar esse ponteiro `numbers` a `free` liberta a memória alocada em `my_function`.

#### uso após libertação (**UAF**)

Se a memória for acedida depois de ser libertada, os valores podem ser quaisquer.
No exemplo seguinte, a memória apontada por `numbers` é libertada e depois é lida no `printf`.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

O ponteiro `numbers`, depois de ter sido libertado, é designado por ponteiro pendente.
Um ponteiro pendente pode referir-se a memória diferente daquela para a qual foi pensado.
Assim, um ponteiro pendente pode levar à corrupção de dados e à substituição e execução de código arbitrário.
Um ponteiro para memória alocada que não foi limpo ao ser definido como `NULL` pode ser usado para atacar o programa.
No exemplo acima, se `numbers` fosse definido como `NULL` desta forma: `numbers = NULL;`, depois de ser libertado, o `printf` seguinte resultaria na terminação do programa, reportando talvez uma falha de segmentação ao tentar ler `numbers[0]`.

#### libertação dupla

Se `free` for chamada duas vezes sobre um ponteiro para memória alocada dinamicamente, isso resulta em comportamento indefinido (**UB**).
Isto significa que o compilador pode tratá-lo de forma arbitrária, da maneira que quiser.
O exemplo seguinte, compilado com dois compiladores diferentes, pode ter dois resultados diferentes

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

O primeiro e o segundo compilador não geraram erro de execução quando `numbers` foi definido como `NULL` entre cada chamada a `free`, mas não haveria garantia de que isso funcionasse com um terceiro compilador.
Uma fonte comum de libertação dupla é ter dois ponteiros que apontam para a mesma memória alocada dinamicamente.
Um ponteiro pode apontar para o início de um array num ponto do programa, e o outro ponteiro pode ser usado para percorrer o array noutro ponto do programa.
Em pontos diferentes do programa, cada ponteiro é libertado, causando assim uma libertação dupla.

## calloc

`calloc` é uma função declarada em `stdlib.h` que serve tanto para alocar memória dinâmica como para inicializar a memória recém-alocada a zero.
Se a alocação for bem-sucedida, é devolvido um ponteiro que aponta para o endereço do primeiro byte da memória alocada.
Se a alocação não for bem-sucedida, é devolvido `NULL`.
É prudente verificar se o resultado de `calloc` é `NULL` e lidar com isso de forma adequada caso falhe.
O ponteiro devolvido é do tipo `pointer-to-void`, que pode ser considerado, aproximadamente, como um ponteiro "genérico" que pode ser convertido para o tipo específico usado pela memória.
`calloc` tem dois parâmetros.
O primeiro parâmetro indica quantos elementos do tipo de dados especificado devem ser alocados.
O segundo parâmetro indica o tamanho do tipo de dados especificado a alocar.

No exemplo seguinte, todas as instruções `printf` devem mostrar sempre `0`, uma vez que `calloc` garante que os valores recém-alocados são colocados a zero.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` é uma função declarada em `stdlib.h` que serve para expandir ou reduzir memória já alocada.
Se a realocação for bem-sucedida, é devolvido um ponteiro que aponta para o endereço do primeiro byte da memória realocada.
Se a realocação não for bem-sucedida, é devolvido `NULL`.
É prudente verificar se o resultado de `realloc` é `NULL` e lidar com isso de forma adequada caso falhe.
`realloc` tem dois parâmetros.
O primeiro parâmetro é um ponteiro para a memória existente a realocar.
O segundo parâmetro é o tamanho, em bytes, da memória realocada.
Os valores definidos antes de a memória ser expandida são mantidos.
É importante lembrar que a memória adicionada ao expandir a memória não é inicializada a zero e os seus valores podem ser quaisquer.
Além disso, a memória removida ao reduzir a memória também não é inicializada e pode conservar os valores.
O exemplo seguinte demonstra a expansão e a redução de um array

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## Quando o tamanho passado é 0

Se o tamanho passado a `malloc`, `calloc` ou `relloac` for `0`, o que acontece depende de como o compilador o implementa.
Um compilador pode devolver um ponteiro `NULL` ou um ponteiro não nulo.
Por exemplo, se alocar memória para um ponteiro para `char`, o compilador pode devolver `NULL` ou um ponteiro não nulo para uma string vazia.
Para evitar resultados diferentes com compiladores diferentes, o melhor é não alocar com um tamanho de 0.
