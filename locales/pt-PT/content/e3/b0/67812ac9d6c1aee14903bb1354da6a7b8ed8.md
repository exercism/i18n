# Sobre

A única convenção de passagem de dados do Factor é a *pilha de dados*: as palavras retiram os valores de entrada e colocam os valores de saída. Cada definição de palavra declara um *efeito de pilha* que documenta esse contrato.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

Os nomes dentro de `( … -- … )` existem para ajudar quem lê; o que o compilador verifica é o *número* de valores de entrada e de saída. Uma divergência dá um erro de compilação, o que apanha uma classe de erros que, numa linguagem de tipagem dinâmica sem este tipo de declaração, só apareceriam em tempo de execução.

Como a pilha é posicional, tens constantemente de reorganizar o seu topo antes de a palavra seguinte poder correr. As **palavras de reorganização** do `kernel` fazem exatamente isso:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

A família completa de palavras de reorganização estende estas com `-rot` (roda no sentido contrário), as primas com o sufixo `d`, que atuam um item mais fundo (`dupd`, `swapd`), as primas com o prefixo `2`, que atuam sobre pares (`2dup`, `2drop`, `2nip`), e outras como `pick` e `tuck`. São introduzidas à medida que os exercícios seguintes precisam delas; usar demasiadas palavras de reorganização de uma só vez é, normalmente, sinal de que uma *variável local* (um valor com nome) se leria melhor.

Por convenção, as palavras usam `lowercase-kebab-case`, os predicados terminam em `?` e produzem um Boolean (`even?`, `empty?`), as palavras que definem valores escrevem-se `>>name` e as que os leem `name>>`, e uma palavra e a sua variante mutável partilham muitas vezes o mesmo nome, distinguindo-se apenas pelo contexto.
