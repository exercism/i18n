# Dicas

Um uso comum de `Either` é indicar uma computação que pode resultar num erro
(se o erro em si não tiver interesse, então o tipo mais simples `Option` pode ser uma escolha melhor).
Na ausência de um erro, o resultado costuma ser um `Right` (mnemónica: o valor "certo"),
enquanto um erro é um `Left`, por exemplo um `Left[String]` que contém uma mensagem de erro.
Repara que, no Scala 2.12, `Either` é orientado à direita por omissão, por isso funciona como esperado em operações como `filter`, `map`, `flatMap` ou numa compreensão for.
Se não estás familiarizado com `Either`, podes ler [este tutorial](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html). Mas tem em atenção que este tutorial é sobre versões de Scala anteriores à 2.12. Para Scala 2.12, podes ignorar `RightProjection` sem problemas e omitir `.right`.
`Either` é aquilo a que se chama uma [mónada](https://en.wikipedia.org/wiki/Monad_(functional_programming)), que abrange um "aspeto computacional",
neste caso o tratamento de erros.
O uso correto de mónadas pode resultar em código muito conciso, mas ainda assim elegante
e legível. O uso incorreto pode facilmente resultar no contrário.
Vê [este vídeo](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) para saber mais.

## Armadilhas comuns que deves evitar

Há algumas regras básicas para `Either`:

1. Se não precisares dele, não o uses. Em vez de

```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```

é preferível:

```scala
def add1(x: Int): Int = x + 1
```

(há `Either.map` para aplicar funções simples como estas,
por isso não precisas de as sobrecarregar com `Either`).

2. Não faças "unwrap" se não precisares mesmo.
Muitas vezes há funções incorporadas para o teu objetivo. Indicadores de unwrap prematuro são `isLeft/isRight` ou correspondência de padrões. Por exemplo, em vez de

```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```

é preferível:

```scala
x fold (identity, _ + 1)
```

3. As mónadas podem ser usadas dentro de uma compreensão for, e isso é ótimo.
Isto é aconselhável quando queres "compor" várias instâncias de `Either`. Em vez de

```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```

é preferível:

```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
