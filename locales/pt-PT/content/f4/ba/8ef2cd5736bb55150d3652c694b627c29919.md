# Classes abstratas

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## O $ faz parte do nome

Todas as classes abstratas têm um `$` à frente do nome, e só as classes abstratas o
têm. Por isso, um tipo que começa por `$` é um tipo do qual não podes criar um
objeto, e isso vê-se onde quer que o nome apareça.

## O que pode estar dentro de uma

Assinaturas de rotinas e de iteradores, que terminam no ponto e vírgula. Sem
corpos, sem atributos, sem `create`. Uma classe abstrata descreve o que se pode
*pedir* a algo, nunca o que esse algo guarda.

## Conformidade

```sather
class TRAPEZE < $ACT is
```

A classe tem de definir todas as rotinas listadas, com tipos de argumento e tipo
devolvido correspondentes. Isto é verificado na compilação.

Uma classe pode estar em conformidade com várias:

```sather
class TRAPEZE < $ACT, $RISKY is
```

e as classes abstratas podem estender-se umas às outras:

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## Onde acontece o despacho

Uma variável de um tipo abstrato guarda uma referência a um objeto conforme.
Chamar uma rotina nele escolhe a versão que pertence à classe real do objeto,
em tempo de execução.

É o único sítio onde o Sather decide algo em tempo de execução. Uma chamada numa
variável de um tipo concreto é decidida na compilação.

## typecase

Por vezes, o tipo importa mesmo. O `typecase` pergunta:

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

Dentro de um braço, a variável tem o tipo mais restrito. Recorre a ele raramente:
um `typecase` sobre todos os tipos de ato costuma ser uma rotina que devia estar
na classe abstrata desde o início.

## $OB

`$OB` é a classe abstrata com que todos os objetos estão em conformidade. É
ocasionalmente útil e, na maior parte das vezes, um sinal de que um tipo se
perdeu pelo caminho.

## Porque não a herança?

O Sather separa duas coisas que a maioria das linguagens junta. O `<` diz apenas
o que uma classe pode *fazer*. Obter uma implementação de outro sítio é o
`include`, que é o segundo exercício a seguir a este, e é uma decisão separada.
