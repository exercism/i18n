# Introdução

## Notação binária

Um **inteiro** é uma abstração que representa números inteiros, como `4`, `-2`, `0` ou `64532`.

Para representar um inteiro como uma sequência de bytes, usa-se a **notação binária**.
Nesta notação, cada bit da sequência representa uma potência de dois distinta, e o valor aumenta à medida que o índice do bit cresce da direita para a esquerda.

## Números sem sinal

Se o número só puder ser não negativo, chama-se-lhe um número **sem sinal**.

Os números sem sinal são representados diretamente como a soma das potências de dois correspondentes a todos os bits definidos da sua sequência.

O intervalo de inteiros não negativos representáveis num registo vai de `0` (nenhum bit definido) a `2⁶⁴ - 1` (soma dos 64 bits todos definidos).

Alargar um número sem sinal para um tamanho maior faz-se preenchendo todos os bits superiores com `0`, para que nenhum bit novo contribua para o valor.
A isto chama-se **extensão com zeros**.

A instrução `movzx` (`z` de zero) estende com zeros um operando de origem de 8 ou 16 bits para um operando de destino maior.
Um operando de origem de 32 bits é sempre estendido com zeros para os 64 bits do operando de destino com um simples `mov`.

## Números com sinal

Se um inteiro puder assumir valores positivos ou negativos, chama-se-lhe um número **com sinal**.

Para representar números negativos, o x86-64 usa a representação em **complemento para dois**.

No complemento para dois, os números com sinal também são representados como a soma das potências de dois correspondentes aos bits definidos.
No entanto, se o bit mais significativo estiver definido, é subtraído em vez de somado aos restantes.

Como este bit corresponde a um valor superior à soma de todos os outros, na prática isto significa que um número com este bit definido é sempre negativo.
A este bit especial chama-se **bit de sinal**.

Alargar um número com sinal para um tamanho maior significa preencher cada novo bit superior com uma cópia do bit de sinal, para que o valor se mantenha.
A isto chama-se **extensão de sinal**.

A instrução `movsx` (`s` de sinal) estende com o sinal um operando de origem de 8 ou 16 bits para um operando de destino maior.
Uma variante de `movsx` chamada `movsxd` faz o mesmo de um operando de origem de 32 bits para um operando de destino de 64 bits.

A instrução `neg` pode ser usada para mudar o sinal de um número.

~~~~exercism/caution
Em assembly, não há forma de saber se uma sequência de bytes representa um número com sinal ou sem sinal.
É responsabilidade do programador dar significado a esses bytes.

O uso de comentários pode ser uma grande ajuda nesta tarefa.
~~~~

## Imediatos

Num conceito anterior, foi mencionado que um número constante, como `4` ou `-15`, pode ser usado como operando de origem em muitas instruções.
A esses números chama-se **imediatos**.

Um imediato não fica num registo nem na memória: está codificado dentro da própria instrução.
Na maioria das instruções, o espaço reservado para ele tem apenas 32 bits, independentemente do tamanho do operando de destino.

Quando o operando de destino tem 64 bits, esses 32 bits são _estendidos com o sinal_ para o preencher.
A metade superior do operando fica totalmente preenchida com cópias do bit mais significativo do imediato, pelo que só um número dentro do intervalo de um _inteiro com sinal de 32 bits_ pode ser escrito desta forma:

```x86asm
add rax, -1          ; the immediate is sign-extended, so all 64 bits of rax are affected
add rax, 2147483647  ; the largest immediate an instruction like this accepts
```

Um número fora desse intervalo não pode ser usado como imediato.
A exceção a esta regra é `mov`, que pode receber um imediato completo de 64 bits quando o operando de destino é um registo.
Se for necessário um imediato de 64 bits, usa primeiro `mov` para o carregar num registo e depois usa esse registo:

```x86asm
mov rax, 3435973837           ; this works, mov can take a 64-bit immediate
mov rdx, 18446744073709551615 ; the largest immediate mov accepts
sub rdx, rax
```

Repara que um imediato negativo e o número sem sinal com a mesma representação em bits são equivalentes e produzem exatamente o mesmo valor:

```x86asm
mov rax, -1                   ; rax = 18446744073709551615
mov rax, 18446744073709551615 ; rax = -1
```

## Soma

A soma de dois números pode ser calculada com a instrução `add`.

Existe também a instrução `inc`, de um operando, que soma `1` ao valor do seu operando:

```x86asm
inc rax ; rax = rax + 1
```

A soma de dois inteiros funciona da mesma forma para números sem sinal e com sinal.

## Subtração

A subtração de dois inteiros é feita com a instrução `sub`.

Existe também a instrução `dec`, de um operando, que subtrai `1` ao valor do seu operando:

```x86asm
dec rax ; rax = rax - 1
```

A subtração de dois inteiros também funciona da mesma forma para números sem sinal e com sinal.

## Multiplicação

Existem duas instruções diferentes para multiplicar dois números em x86-64.
Por norma, a multiplicação sem sinal usa a instrução `mul`, enquanto a multiplicação com sinal usa `imul`.

A instrução `mul` assume a seguinte forma de um operando, em que `src` é o operando de origem:

```x86asm
mul src
```

A instrução `imul` pode assumir a forma de um, dois ou três operandos:

```x86asm
imul src
imul dest, src
imul dest, src1, src2
```

### Multiplicação com um operando

Dois registos são usados implicitamente para realizar uma multiplicação na forma de um operando: `rax` e `rdx`.
Se a multiplicação envolver dois números de 64 bits, então os 64 bits inferiores do resultado ficam em `rax` e os 64 bits superiores ficam em `rdx`.

Costuma chamar-se a isto `rdx:rax`, para indicar que ambos os registos são usados em conjunto:

```x86asm
mul rcx ; rax = lower 64 bits of rax * rcx
        ; rdx = upper 64 bits of rax * rcx
```

O mesmo acontece com outros tamanhos de operandos.
Por exemplo, se estiverem a ser multiplicados dois números de 32 bits, serão usados `eax` e `edx`.

A exceção é a multiplicação entre dois bytes.

Neste caso, em vez de `dl:al`, é usado `ax`.
A parte inferior de `ax` (`al`) recebe os 8 bits inferiores do produto, enquanto a parte superior (`ah`) recebe os 8 bits superiores.

~~~~exercism/caution
Os registos usados implicitamente numa multiplicação, como `rax` e `rdx`, são sempre sobrescritos.
Se os valores desses registos forem necessários mais tarde, devem ser guardados antes da operação.
~~~~

### Multiplicação com dois operandos

A forma de dois operandos do `imul` tem um operando de destino explícito e segue a sintaxe habitual.
`rdx` não é usado.
Em vez disso, o resultado é truncado para caber no operando de destino.

```x86asm
imul r8, r9 ; r8 = lower 64 bits of r8 * r9
```

### Multiplicação com três operandos

A forma de três operandos do `imul` tem dois operandos de origem, sendo o segundo sempre um imediato (um número constante).
Ambos os operandos de origem são multiplicados e o resultado é truncado e colocado no operando de destino:

```x86asm
imul r8, r9, 100 ; r8 = lower 64 bits of r9 * 100
```

Repara que o operando de destino não é usado na multiplicação.
Apenas recebe o resultado.

### Lidar com o transbordo

Tanto a multiplicação de dois operandos como a de três operandos truncam o resultado para caber no tamanho do operando de destino.
A multiplicação de um operando preserva o intervalo completo, mas costuma ser dividida por dois registos, `rdx` e `rax`.

Por isso, por vezes é útil alargar os operandos antes da multiplicação para abrir espaço para o produto completo num único registo.
Um operando sem sinal é estendido com zeros, enquanto um com sinal é estendido com o sinal:

```x86asm
movzx eax, di ; di and si hold unsigned 16-bit numbers
movzx ecx, si
mul ecx       ; the 32-bit product fits in eax, and edx is cleared
```

## Divisão

Tal como acontece com a multiplicação, também existem duas instruções para dividir dois números.
A divisão sem sinal usa a instrução `div`, enquanto a divisão com sinal usa `idiv`.

Ambas as instruções funcionam com apenas um operando:

```x86asm
div src
idiv src
```

A divisão de 16, 32 e 64 bits usa `dx:ax`, `edx:eax` e `rdx:rax` como dividendo, respetivamente.
Nestes casos, ambos os registos atuam em conjunto para criar um valor de 2N bits, em que N é o tamanho da operação (16, 32 ou 64 bits).
Este valor é depois dividido pelo operando de origem.
O quociente é escrito em `ax`, `eax` ou `rax`, e o resto é escrito em `dx`, `edx` ou `rdx`, consoante o tamanho da operação.

A divisão entre bytes é especial: em vez de usar `dl:al`, usa-se `ax`.
Os 8 bits inferiores de `ax` (`al`) recebem o quociente da operação e os 8 bits superiores (`ah`) recebem o resto.

Repara que todos os bits do dividendo devem estar devidamente definidos antes da divisão.
Qualquer bit definido em `rdx` (ou em `ah`, no caso da divisão de 8 bits) contribui para o valor que está a ser dividido.

Na divisão sem sinal, quando o valor a dividir cabe na metade inferior, a metade superior deve ser limpa.
Qualquer instrução que limpe esses bits serve.
Por exemplo, `mov edx, 0` limpa os bits superiores na divisão de 32 bits.

Na divisão com sinal, o valor deve, em vez disso, ser estendido com o sinal.
Existem instruções que automatizam este processo: `cbw`, `cwd`, `cdq` e `cqo`.
A primeira define os bits em `ah` de acordo com o sinal de `al`.
As outras fazem a extensão de sinal de `ax` para `dx`, de `eax` para `edx` e de `rax` para `rdx`, respetivamente.

~~~~exercism/caution
Os registos usados implicitamente numa divisão, como `rax` e `rdx`, são sempre sobrescritos.
Se os valores desses registos forem necessários mais tarde, devem ser guardados antes da divisão.
~~~~
