# Sobre

## Representação, carateres e inteiros

Tal como outros tipos simples (`int`s, `bool`s, etc.), o `char` tem um tipo associado, ou alias, neste caso, `System.Char`.

Na verdade, trata-se de um `struct` com um campo de 16 bits, imutável por predefinição.

O `char` tem alguns métodos de instância como `Equals`, `ToString` e [`CompareTo`][compare-to].

O `char` tem a mesma largura que um [`ushort`][uint16], mas, ao contrário do que acontece nalgumas linguagens, não são geralmente usados de forma intercambiável. É preciso converter explicitamente um `ushort` para `char`.

A título de curiosidade, os `char`s podem ser alvo de operações aritméticas. O resultado dessas operações é um número inteiro.

Obviamente, não há equivalência entre um `byte` de 8 bits e um `char` de 16 bits.

## Utilização

Os `char`s são, em geral, fáceis de usar.

Podem ser definidos como literais com aspas simples:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

É possível obter um `char` individual de uma string com indexação (a partir de zero):

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

Iterar sobre uma string devolve um `char` em cada passo:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

Como mostrado acima, é possível converter um `char` no seu valor `int`.
Isto também funciona (*pelo menos algumas vezes*) com outros sistemas de escrita:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

O Int16 subjacente é usado ao comparar carateres:

```fsharp
'A' < 'D'
// => val it: bool = true
```

Além disso, é possível converter um `int` num `char`:

```fsharp
char 77
// => val it: char = 'M'
```

A biblioteca `System.Char` contém o conjunto completo de [métodos][Char-methods] esperados numa linguagem .NET, como as conversões para maiúsculas/minúsculas (mas vê as ressalvas na secção seguinte):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

As bibliotecas .NET ajudam a extrair `char`s de strings, neste caso os métodos de `Seq`:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

Há várias formas de converter uma lista (ou array) de carateres numa string, incluindo estas:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

Encontras informações gerais sobre `char`s aqui:

- [Documentação de Chars][chars-docs]: documentação de referência para `char`.

No entanto, os `char`s têm várias arestas por limar, como se detalha abaixo. Essas arestas relacionam-se sobretudo com a oposição entre o padrão Unicode completo, por um lado, e as representações históricas do texto, bem como o desempenho e o consumo de memória, por outro.

## Problemas com Unicode

Ao trabalhar com strings, se estiverem disponíveis métodos da biblioteca [`System.String`][System-string], deves procurá-los e usá-los em vez de dividir a string em carateres.

Alguns "carateres" textuais são compostos por mais do que um `char`, porque o padrão Unicode tem mais de 65536 pontos de código. Por exemplo, os emojis que aparecem nalguns dos testes têm 2 `char`s, pois incluem carateres [substitutos][surrogates].

Além disso, existem sequências de combinação, por exemplo, em que, nalguns casos, um caráter acentuado pode consistir num `char` para o caráter simples e noutro `char` para o acento.

Se tiveres de lidar com carateres individuais, deves tentar usar métodos de biblioteca como [`System.Char.IsControl`][is-control] e [`System.Char.IsDigit`][is-digit], em vez de fazer comparações ingénuas como verificar se um caráter está entre '0' e '9'.

Por exemplo, repara que '٢' é o algarismo árabe 2. `IsDigit` devolve true para a versão árabe, por isso, ao validar, tens de definir claramente que intervalo de entradas é aceitável.

Mesmo os métodos da biblioteca `System.Char` podem não comportar-se como esperarias quando estás a lidar com línguas mais obscuras.

Uma forma segura de dividir uma string em "carateres" de apresentação é usar [`StringInfo`][string-info] e métodos como [`GetNexttextElement`][get-next-text-element].
Isto pode ser necessário se estiveres a lidar com globalização/localização.

Outra via em que os valores escalares dos carateres Unicode são importantes (digamos que estás a criar o teu próprio sistema de codificação) é usar [runes][runes]. No entanto, se souberes que o intervalo de carateres com que lidas não inclui substitutos nem sequências de carateres combinantes (por exemplo, ASCII latino) e se a tua entrada estiver bem validada, podes evitar isto.

Mais uma vez, a melhor situação é aquela em que podes usar os métodos de biblioteca de `String`.

Se te vires mesmo na ingrata posição de lidar com os detalhes do Unicode, então [isto][char-encoding-net] é um bom ponto de partida.

## Globalização

Se trabalhas num ambiente em que lidas com várias culturas, ou em que a cultura é importante em algumas partes do código mas não noutras, tem atenção às sobrecargas de [`ToUpper`][to-upper] e [`ToLower`][to-lower] que recebem uma cultura, e de [`ToUpperInvariant`][to-upper-invariant] e [`ToLowerInvariant`][to-lower-invariant], que dão um resultado consistente independentemente da [cultura][culture-info] atual.
