# Introdução

O Gleam não usa exceções para tratar erros. Em vez disso, as funções que podem ser bem-sucedidas ou falhar devolvem o tipo genérico `Result`.

O tipo `Result` faz parte da linguagem, por isso não precisas de o definir nem de o importar. Mas se o definisses tu próprio, ficaria assim:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

A variante `Ok` é devolvida quando uma função é bem-sucedida, e a variante `Error` é devolvida quando uma função falha.

Os resultados são muito comuns em Gleam, e quem programa em Gleam usa habitualmente o [módulo `gleam/result`](https://hexdocs.pm/gleam_stdlib/gleam/result.html) para facilitar o trabalho com eles.

A função `result.map` pode ser usada para chamar uma função sobre o valor que está dentro de um resultado, se este for um `Ok`, ou para deixar passar um `Error` inalterado.

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

A função `result.try` é semelhante, mas espera-se que a função de callback devolva um resultado. Isto é útil para encadear várias funções que devolvem resultados.

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
