# Instruções

Quanto mais aprendes sobre programação, mais começas a pensar que isto pode ser mais do que uma simples moda.
Pode até haver algumas oportunidades de negócio: as pessoas escrevem código, querem guardá-lo, partilhá-lo, colaborar, talvez até receber algum feedback.

Muito bem, vamos a isso, vamos construir um serviço para incentivar as pessoas a programar: hup, hup, pessoal, comecem a usar git!
Vamos chamá-lo... GitHup.

Começas a construir uma API REST JSON: utilizadores, pull requests, comentários, e o backend fica rapidamente pronto.

Claro que o frontend vai ser feito em Elm, mas primeiro tens de perceber o que são esses famosos decoders/encoders.

```exercism/note
Piada à parte, os requisitos do exercício são retirados diretamente dos endpoints da API REST do GitHub para comentários de revisão de pull requests.
Alguns campos foram removidos dos esquemas JSON por uma questão de simplicidade, mas isto é o mais próximo que se chega de aplicações do mundo real.
```

## 1. ID, por favor!

O teu olho de águia reparou que tanto os comentários como os utilizadores têm um campo `id`, o sítio perfeito para começar.

Define `decodeId` de modo a que consiga descodificar um objeto JSON com um `id` inteiro.

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. Como é que eu me chamo mesmo?

Reparas, no exemplo acima, que nem todos os utilizadores têm um nome.

Define `decodeName` de modo a que consiga descodificar uma string no campo `name`, se esta existir.
Não há nome? Não há problema, devolve simplesmente `Nothing`.
Este descodificador nunca deve falhar.

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. Utilizador? Nem sei quem é!

Já vamos praticamente a meio da descodificação dos utilizadores, vamos acabar isto.

Define `decodeUser` de modo a que consiga descodificar um objeto JSON de utilizador.
Certifica-te de que usas `decodeId` e `decodeName` em `decodeUser`.

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. Sou um comentário forte e independente

Alguns comentários numa revisão de pull request são independentes e, por isso, não têm um `pull_request_review_id`.
No entanto, a especificação refere que, nesse caso, deve continuar a existir um campo `pull_request_review_id`, mas com o valor `null`, o `Nothing` dos pobres.

Define `decodePullRequestReviewId` de modo a que consiga descodificar um inteiro no campo `pull_request_review_id`, se este existir.
Se não houver um inteiro, deve haver um `null`; se não houver um `null`, o descodificador deve falhar.

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. Trabalho paralelo

A seguir, temos este campo `side` com um aspeto interessante.
Numa revisão de pull request, podes comentar código que foi removido (no lado `Left` do ecrã) ou código que foi acrescentado (no lado `Right` do ecrã).

Define `decodeSide` de modo a que consiga descodificar `"LEFT"` ou `"RIGHT"` no campo `side` e associá-los à variante de tipo correspondente.

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. O despertar dos links

Cada comentário tem um conjunto de links, que não parece ser consistente de comentário para comentário.

Define `decodeLinks` de modo a que consiga descodificar uma coleção de URLs no campo `_links`.
Os nomes e o número de links podem variar, certifica-te de que consegues dar conta disso.
Os próprios links são objetos JSON que devem ter sempre um campo `href`.

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. Sim, comentários

Estamos quase lá, vamos acabar isto.

Define `decodeComment` e `decodeComments` de modo a que consigam descodificar, respetivamente, um único objeto JSON de comentário ou uma lista de comentários.
Certifica-te de que usas todas as funções definidas até agora em `decodeComment`, com a exceção de `decodeName`.
Claro que `decodeComments` também deve usar `decodeComment`.

## 8. Tudo se liga

Falta ainda uma funcionalidade em tudo isto: conseguir enviar um novo comentário para o servidor.
Para isso, precisas de fazer o oposto de um descodificador, precisas de conseguir transformar um `Comment` de Elm num `Value` de JSON.

Define `encodeComment` de modo a que consiga codificar qualquer `Comment` válido.
A ordem dos campos não importa, desde que o codificador consiga produzir um valor que o `decodeComment` consiga descodificar.
