# Instalação

## Preâmbulo

Embora o Regina Rexx tenha sido amplamente portado, as instruções de instalação vão focar-se em plataformas de secretária de 64 bits com Windows, Linux ou MacOS.

## Passos de instalação

Tem em atenção que este track espera que esteja instalada a versão mais recente do [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) (a 3.9.5, à data em que este texto foi escrito). A hiperligação fornecida leva-te diretamente à secção Files, onde escolhes o ficheiro que queres descarregar.

### Windows

Uma instalação para correr nativamente no Windows (através de uma janela CMD ou PowerShell) faz-se facilmente no navegador através do botão [`Download Latest Version`](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/Regina395w64.exe/download). Basta clicar, descarregar e instalar.

Se tiveres, ou quiseres usar, ambientes de emulação de Linux como:

* [Git for Windows](https://gitforwindows.org/)
* [Cygwin](https://cygwin.com/)
* [MinGW](http://mingw.org/)

os binários do Regina nativos do Windows devem estar acessíveis, por isso podes simplesmente executá-los nesses ambientes e, para a maioria dos fins, isto é suficiente.

Há, no entanto, uma ressalva: a instrução ADDRESS não funciona corretamente (porque interage com o sistema operativo anfitrião). Para obteres os melhores resultados nestes ambientes, obtém o pacote específico do ambiente e instala-o. O site do Regina, por exemplo, disponibiliza uma [compilação específica para Cygwin](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-pc-cygwin.tgz/download) que podes instalar.

Em alternativa, se tiveres ou quiseres usar uma distribuição de Linux _real_ no Windows, como o [WSL](https://docs.microsoft.com/en-us/windows/wsl/about) ou o [Virtual Box](https://www.virtualbox.org/), segue simplesmente as instruções da secção Linux para a distribuição em causa.

### Linux

As instalações em Linux são, tipicamente, bastante simples quando se usa o gestor de pacotes do sistema. Tornam-se problemáticas, no entanto, quando os pacotes disponíveis _não_ são os mais recentes. É, infelizmente, o caso do Regina.

Uma instalação baseada em pacotes ainda é possível, obtendo manualmente o pacote mais recente. O site do [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) disponibiliza pacotes para distribuições da família Debian (inclui Ubuntu) e da família RHEL (inclui Fedora, CentOS, Rocky e Alma), entre outras.

Para a distribuição escolhida, vais precisar de descarregar dois pacotes: um pacote de biblioteca e um pacote de binários. Por exemplo, para instalar no Debian ou no Ubuntu, faz o seguinte:

```plain
sudo apt update && sudo apt -y install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx_3.9.5-2_amd64-Debian-11.deb > regina-rexx_3.9.5-2_amd64-Debian-11.deb
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3_3.9.5-2_amd64-Debian-11.deb > libregina3_3.9.5-2_amd64-Debian-11.deb
sudo apt -y install libregina3_3.9.5-2_amd64-Debian-11.deb regina-rexx_3.9.5-2_amd64-Debian-11.deb
```

E no CentOS e no RHEL 7, experimenta:
```plain
sudo yum update && sudo yum install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
sudo yum localinstall libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
```

E no Fedora, Rocky e Alma, experimenta:
```plain
sudo dnf update && sudo dnf install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
sudo dnf localinstall libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
```

Quando uma instalação baseada em pacotes não é possível, ou se revelou problemática por algum motivo, é sempre possível compilar a partir do código-fonte, com o arquivo disponível em:

```plain
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5.tar.gz > regina-rexx-3.9.5.tar.gz
```

Partindo do princípio de que as ferramentas de compilação padrão (gcc, make) estão instaladas (se não estiverem, segue as instruções aqui: [Install Development Tools](https://ostechnix.com/install-development-tools-linux/)), realiza então os seguintes passos:

```plain
tar -xzvf regina-rexx-3.9.5.tar.gz && cd regina-rexx-3.9.5
./configure
sudo make
sudo make install
```

São instaladas a biblioteca (`libregina.so`) e dois conjuntos de binários (`rexx` e `regina`) (a localização predefinida é `/usr/local/bin`).

O binário `rexx` está ligado estaticamente, por isso é autónomo e está pronto a usar.

O binário `regina` está ligado dinamicamente, pelo que requer alguma configuração para conseguir localizar a biblioteca partilhada `libregina.so` em tempo de execução. Para o fazer, segue estes passos:

```plain
# Configure shared library location
sudo su
echo /usr/local/lib64/ > /etc/ld.so.conf.d/regina-rexx-3.9.5-x86_64.conf
echo /usr/local/lib64/regina-rexx/addons > /etc/ld.so.conf.d/regina-rexx-addons-x86_64.conf
cd /usr/local/lib64
rm -f libregina.so libregina.so.3
ln -s libregina.so.3.9 libregina.so
ln -s libregina.so.3.9 libregina.so.3
ldconfig
exit

# Check symbolic link creation
ls -l /usr/local/lib64/

# Output should be similar. Note symbolic links.
-rw-r--r--. 1 root root 3887554 Dec  1 18:22 libregina.a
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so -> libregina.so.3.9
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so.3 -> libregina.so.3.9
-rwxr-xr-x. 1 root root  574104 Dec  1 18:22 libregina.so.3.9
drwxr-xr-x. 2 root root      26 Dec  1 18:22 pkgconfig
drwxr-xr-x. 4 root root      33 Dec  1 18:22 regina-rexx

# Check library path, and executable using that path
ldconfig -p | grep regina
ldd /usr/local/bin/regina

# Alternate for local user
export LD_LIBRARY_PATH=${LD_LIBRARY_PATH}:/usr/local/lib64:/usr/local/lib64/regina-rexx/addons
```

Tem em atenção que compilar a partir do código-fonte, e a configuração de sistema que isso implica, é uma tarefa que é melhor deixar aos utilizadores experientes.

### MacOS

A instalação é um processo em três passos:

* Instala o gestor de pacotes [Homebrew](https://brew.sh)
* Localiza e abre a aplicação `Terminal`
* Na linha de comandos do `Terminal`, introduz o seguinte:

   `brew install regina-rexx`

Isto _deve_ instalar a versão mais recente.

Se não o fizer, podes descarregar o pacote [Regina para MacOS](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-apple-darwin21.6.0.tgz/download) e instalá-lo manualmente.

## Após a instalação

### Verificação da instalação

Depois de concluíres a instalação, podes verificar se o [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) foi instalado com sucesso executando este comando num terminal:

```plain
rexx --version=v
```

Tanto no Windows como no Linux, aparece a seguinte saída no terminal:

```plain
3.9.5
```

que é o número de versão do intérprete.

É também instalado um segundo binário, `regina`. É idêntico ao `rexx` em todos os aspetos, exceto que se liga a uma biblioteca partilhada, e é o intérprete a usar caso queiras aceder a funções utilitárias externas. Consulta a secção [Aceder a rotinas externas](###accessing-external-routines).

Não é preciso instalar mais nenhum componente de software para começar a usar o track (partindo do princípio de que o CLI do Exercism já está instalado).

As notas de utilização abaixo dão-te uma base sobre como usar o intérprete a partir da linha de comandos.

### Utilização

Um script Rexx costuma ter a extensão _`.rexx`_, embora isso não seja obrigatório, pois o intérprete tenta executar o nome de ficheiro que lhe for passado como argumento e, se este contiver código Rexx válido, é executado com sucesso.

O comando seguinte tenta executar um ficheiro chamado `hello.rexx`:

```plain
rexx hello.rexx
```

Partindo do princípio de que o ficheiro contém o seguinte código:

```rexx
say "Hello, world!"
exit 0
```

a saída no terminal seria:

```plain
Hello, world!
```

A mesma saída no terminal apareceria se o ficheiro fosse renomeado para `hello.txt` e executado como:

```plain
rexx hello.txt
```

Vale também a pena saber que o código de um script pode ser encaminhado para o intérprete através de uma pipe, em vez de estar num ficheiro. O código anterior pode ser executado através de uma pipe da seguinte forma:

```plain
echo "say 'Hello, world' ; exit 0" | rexx
```

e funciona igualmente bem num terminal Linux ou num terminal PowerShell do Windows.

### Utilização avançada

Aos ficheiros de script podem ser passados um ou mais argumentos de linha de comandos, e estes podem devolver códigos inteiros arbitrários. No entanto, o intérprete precisa de saber que serão passados vários argumentos ao script, o que se consegue através da opção `-a`.

Por exemplo, supõe que o ficheiro `multiarg.rexx` contém o seguinte código:

```rexx
say "My name is" ARG(1) || ", your name is" ARG(2) || ", and the script return code will be" ARG(3) || "."
exit ABS(ARG(3))
```

Para garantir que os vários argumentos do script são interpretados corretamente, o script é executado da seguinte forma:

```plain
rexx -a multiarg.rexx "John" "Jill" 5
```

o que dá origem à seguinte saída no terminal:

```plain
My name is John, your name is Jill, and the script return code will be 5.
```

e o código devolvido pelo programa (acessível através de `$?` no Linux, ou de `%errorlevel%` no Windows) fica definido com o valor 5.

### Aceder a rotinas externas

O Regina suporta a utilização de rotinas residentes em bibliotecas partilhadas externas. Estão disponíveis várias no site do Regina. No entanto, a instalação dessas bibliotecas não é abordada aqui.

O Regina é distribuído com uma dessas bibliotecas, a _regutil_. Contém várias rotinas de uso geral, incluindo para matemática, manipulação de ficheiros e de sistemas de ficheiros, e tarefas de acesso ao sistema.

Não são necessários passos de instalação adicionais. No entanto, para usar estas rotinas num script, é preciso registá-las quando o intérprete é carregado. Isto não exige mais do que duas chamadas de função, e o processo é ilustrado aqui.

Um ficheiro, `access-external.rexx`, contém o seguinte código:

```rexx
/* Register external library and functions */
call RxFuncAdd 'SysLoadFuncs', 'regutil', 'SysLoadFuncs'
call SysLoadFuncs

say "Value of pi is" SysPi()
say "Square root of 25 is" SysSqrt(25)
say "Square root of 2 is" SysSqrt(2)

/* Deregister */
call SysDropFuncs

exit 0
```

Para carregar e usar estas rotinas, é necessário usar o binário `regina`, pelo que o script seria executado assim:

```plain
regina access-external.rexx
```

e aparece a seguinte saída no terminal:

```plain
Value of pi is 3.141592654
Square root of 25 is 5.000000000
Square root of 2 is 1.414213562
```

Se, em vez disso, tivesse sido usado o binário `rexx`, a saída no terminal numa plataforma Windows seria:

```plain
'SYSLOADFUNCS' is not recognized as an internal or external command,
operable program or batch file.
'SYSPI' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSDROPFUNCS' is not recognized as an internal or external command,
operable program or batch file.
```

ao passo que numa plataforma Linux a saída no terminal seria:

```plain
sh: SYSLOADFUNCS: command not found
sh: SYSPI: command not found
sh: SYSSQRT: command not found
sh: SYSSQRT: command not found
sh: SYSDROPFUNCS: command not found
```
