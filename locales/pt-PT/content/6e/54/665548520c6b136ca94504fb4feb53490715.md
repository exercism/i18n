# Introdução

Em muitas linguagens orientadas a objetos, é comum estender comportamentos [criando subclasses][wiki-subclass] de uma classe principal, herdando métodos da classe principal e acrescentando outros novos.
Assim obtemos uma hierarquia de objetos.

A Julia _não tem classes_, por isso, por extensão, _não tem subclasses_.
Como é que herdamos e estendemos comportamentos existentes?

Vimos em conceitos anteriores como criar uma hierarquia de tipos, e aprendemos também como a Julia usa o [despacho múltiplo][concept-multiple-dispatch] para escolher métodos com base nos tipos dos argumentos.

A Julia tem também várias interfaces informais, que permitem que os teus tipos personalizados se associem a comportamentos já definidos para os tipos padrão.

Isto ilustra-se mais facilmente com a interface Iterador.

## Iteradores

Anteriormente, no currículo, vimos várias formas de a Julia operar sobre cada elemento de uma coleção.

- [Ciclos][concept-loops], como `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Funções de ordem superior][concept-hof]: `map(√, [1, 4, 9])`
- [Compreensões][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Geradores][concept-comprehensions]: `(x^2 for x in 1:1e6)`, que é avaliado de forma preguiçosa.

É evidente que a Julia sabe percorrer coleções padrão elemento a elemento: vetores e intervalos nos exemplos acima, e também Sets, Dicts, etc.

Como é que acrescentamos esta capacidade às nossas próprias coleções personalizadas, sobretudo se puderem ser iteradas de forma preguiçosa, como um gerador?

### Requisitos mínimos

Para criar uma sequência que possa ser iterada, precisamos de (pelo menos) duas coisas:

1. Uma forma de obter o _primeiro_ elemento.
2. Uma forma de obter o elemento _seguinte_ a partir do estado atual.

A Julia consegue isto com métodos da função `Base.iterate()`, seguindo estes passos:

1. O `Base.iterate(iter)` é chamado automaticamente primeiro.
    - Se não houver nada para iterar, devolve `nothing`.
    - Caso contrário, devolve o `Tuple` do primeiro elemento e o primeiro estado: `(firstitem, firststate)`.
2. O `Base.iterate(iter, state)` é chamado automaticamente se um elemento tiver sido devolvido na iteração anterior, recebendo `firststate` como argumento `state`.
    - Se a iteração terminar, devolve `nothing`.
    - Caso contrário, devolve o `Tuple` do elemento seguinte e o estado seguinte: `(nextitem, nextstate)`.
3. Repete o passo 2 até terminar.

Todos estes passos acontecem nos bastidores, o que significa que as chamadas aos métodos e o estado são geridos internamente pelo protocolo de iteração (permanecendo o estado opaco), e só o elemento é exposto a construções de alto nível, como os ciclos.
Por outras palavras, só vemos o `item`; tudo o resto permanece numa caixa negra.

O [despacho múltiplo][concept-multiple-dispatch] é central neste mecanismo.
O tipo de `iter` determina que métodos são chamados, e o número de argumentos determina se é devolvido o primeiro elemento ou o seguinte.

Os métodos para os tipos padrão já estão definidos: `Vector`, `Range`, `Set`, etc. ([atualmente][ref-iterations-collections] 14 tipos no total).

Para que um `MyType` personalizado partilhe os mesmos comportamentos, temos primeiro de definir:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Tudo isto pode soar confuso em abstrato, mas pode ser bastante simples.
Para ilustrar, imagina que queremos um tipo que dê as potências de um determinado número inteiro `n`, até um máximo de elementos.

Primeiro, define um tipo personalizado:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Já podemos então definir os métodos `iterate` para este tipo, mas quais são o primeiro elemento e o primeiro estado?

Para obter o primeiro elemento, alguns iteradores precisam de uma preparação complicada, mas neste caso simples reparamos que o primeiro elemento devolvido é apenas o número base, por isso basta verificar se o valor de `count` é maior ou igual a um.

Passemos agora ao primeiro estado, que transporta informação usada na iteração seguinte.
É contigo: decides que informação precisas de acompanhar para o fazer, e pode ser de qualquer tipo.

Neste caso, podíamos limitar-nos a acompanhar o “índice” a que elevamos `n`, ou podemos encontrar uma opção mais eficiente usando a potência mais recente de `n` (ou seja, o elemento devolvido) e o “índice” seguinte da sequência.
Podemos envolver estes dois números num `Tuple` e devolvê-lo como o `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

Neste exemplo, o primeiro elemento (`p.n`) é devolvido ao ciclo e o primeiro estado `(p.n, 2)` é passado ao método `iterate(P::Powers, state)`.
Aí podemos processar o estado para produzir o elemento seguinte, multiplicando o elemento atual pelo número base e aumentando assim a sua potência em `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Se o valor do índice ainda estiver dentro de `count`, devolve-se o `Tuple` com o elemento `next` e o `Tuple` de estado incrementado.
Quando o valor de `index` ultrapassar `count`, devolve-se `nothing` em vez disso, para indicar que a iteração terminou.

Talvez tenhas reparado que os métodos `iterate(p::Powers)` e `iterate(p::Powers, state)` têm corpos de função bastante semelhantes.
De facto, com um pouco de engenho, esta semelhança permite uma implementação mais enxuta, usando apenas a versão de dois argumentos com um valor predefinido para o estado: `Base.iterate(p::Powers, state=(1, 1))`
Assim, já não precisaríamos do método separado de um só argumento `iterate(p::Powers)`.
Na prática, faz-se isto com frequência sempre que possível.

Até agora já temos alguma funcionalidade útil: para as primeiras 4 potências de 3, podemos percorrer os resultados num ciclo, verificar se um determinado número está nos resultados e aplicar funções de agregação como `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Métodos adicionais

Apesar deste bom começo, ainda nem tudo funciona.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Como esperado, `length(Powers(3, 4))` dá exatamente a mesma mensagem de erro.

Isto corrige-se facilmente, pois o comprimento faz parte do construtor do tipo: 4 neste caso.
Basta definir `Base.length()` para este tipo, e depois podemos usar compreensões e `collect()` na sequência.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Por uma questão de eficiência, é melhor definir também `Base.eltype()`: o tipo de elemento do resultado.
Isto permite que funções como `collect()` pré-aloquem espaço para o `Vector{Int}` de saída, em vez de fazerem repetidamente um `push!()` para um `Vector{Any}`.

Repara na sintaxe, que pode ser nova para ti: este método é definido no _tipo_, não numa _instância_ do tipo.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Não é _obrigatório_ que os iteradores tenham comprimento finito.
O uso de sequências “infinitas” é mais limitado, mas percorrê-las num ciclo pode ser útil desde que haja alguma forma de fazer `break` para sair do ciclo.
Por exemplo, podíamos definir uma variante de `Powers` que gerasse valores inferiores a um certo limite (talvez `typemax(Int)`, para evitar que os inteiros transbordem).

## Resumo

As interfaces são bastante confusas de explicar, porque a abordagem da Julia é muito diferente da da maioria das outras linguagens.
Em particular, o nome da interface pode nunca ser mencionado na implementação: muito ao contrário de [criar subclasses][wiki-subclass] ou de [mixins][wiki-mixins].

No entanto, na prática são surpreendentemente simples:

1. Define um tipo adequado.
2. Descobre que métodos são necessários.
3. Implementa esses métodos para o teu tipo personalizado; normalmente são só alguns métodos, curtos e simples.
4. Deixa o [despacho múltiplo][concept-multiple-dispatch] tratar do resto, automaticamente.
