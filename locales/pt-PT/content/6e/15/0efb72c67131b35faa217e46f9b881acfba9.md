# Introdução

Em JavaScript, os valores podem ser de tipos diferentes. Alterar o tipo de uma variável pode ser feito com uma _conversão de tipos_ explícita.
Além disso, o JavaScript também realiza _coerção de tipos_ (conversão de tipos implícita) quando o contexto o exige.

## Conversão de tipos

O JavaScript não tem um construto para converter para um tipo (diferente), como muitas outras linguagens, mas podes usar alguns auxiliares incorporados em vez disso.
Em particular, `Boolean`, `Number` e `String` podem ser usados como funções para converter um valor no tipo respetivo.

### Converter para Boolean (valores truthy/falsy)

Com `Boolean(value)` podes converter qualquer valor num Boolean.
Existe um conjunto fixo de valores, os chamados valores _falsy_, que são convertidos em `false`.
Os mais importantes: `false`, `0`, a string vazia, `null`, `undefined` e `NaN` são falsy.

Para todos os outros valores, `Boolean` devolve `true`.
A estes valores chamamos _truthy_.

```javascript
Boolean(-1);
// => true

Boolean(0);
// => false

Boolean(' ');
// => true

Boolean('');
// => false
```

Repara que, devido às regras descritas, `'0'`, `'false'`, `[]` e `{}` são **truthy** em JavaScript.

### Converter para número

Podes usar `Number(value)` para converter um valor num número.
Os espaços em branco no início e no fim de uma string são ignorados e uma string vazia é convertida em `0`.
Se tentares converter um valor não primitivo ou uma string que não representa um número, o resultado é `NaN` ([Not-A-Number][mdn-nan]).

```javascript
Number('  -12.34  ');
// => -12.34

Number('1,2');
// => NaN

Number('');
// => 0

Number({ num: 123 });
// => NaN
```

### Converter para string

Com `String(value)` podes converter um valor numa string.
Para valores primitivos, o resultado é o que esperarias.

```javascript
String(12.34);
// => '12.34'

String(false);
// => 'false'

String(null);
// => 'null'

String(undefined);
// => 'undefined'
```

No caso dos arrays, a função `String` aplica a conversão para string a cada elemento e junta os resultados com uma vírgula.
Também podes aplicar tu o [método `join`][mdn-join], por exemplo, para personalizares o separador.
Repara que, nestes casos, `null` e `undefined` são convertidos numa string vazia.

```javascript
String([42, null, true, 'abc']);
// => '42,,true,abc'
```

No caso dos objetos, por predefinição, `String` devolve um texto pouco útil.

```javascript
String({ key: 'value' });
// => '[object Object]'
```

## Coerção de tipos

Em certos contextos, o JavaScript converte automaticamente um valor noutro tipo de dados antes de avaliar uma instrução.
A esta conversão implícita chamamos _coerção de tipos_.

### Contexto Boolean

Quando um valor não Boolean é usado num contexto Boolean, o JavaScript aplica as mesmas regras da função `Boolean` para converter o valor implicitamente.

A coerção para Boolean ocorre habitualmente:

- na condição de um [condicional][concept-conditionals]
- no primeiro operando do [operador ternário][mdn-ternary] `?`
- no operando do operador lógico de negação `!`
- nos operandos dos operadores lógicos AND `&&` e OR `||` (o resultado da expressão é um dos operandos, não necessariamente um Boolean)

```javascript
const num = 0;
if (num) {
  // this block is NOT executed because 0 is falsy
}
```

### Contexto de string

Se o operador de adição `+` for usado com valores primitivos e um dos operandos for uma string, o outro também será coagido para string.
A lógica de conversão é a mesma da função `String`.
Depois, as duas strings são concatenadas.

```javascript
let name;
'hello ' + name;
// => 'hello undefined'
```

### Contexto numérico

Muitos operadores coagem os operandos em números (se necessário) segundo a lógica da função `Number` explicada acima.

- Operadores aritméticos: `+` (se não estiver envolvida nenhuma string), `-`, `*`, `/`, `%`, `**`
- Operadores unários de adição e de negação: `+`, `-`
- Operadores relacionais (para operandos que não sejam strings): `>`, `>=`, `<`, `<=`
- Operadores bit a bit: `|`, `&`, `^`, `~`

Consulta a [lista de operadores da MDN][mdn-operators] para mais detalhes sobre qualquer um destes operadores.

Para evitar erros, é boa prática chamar `Number` explicitamente antes de aplicar estes operadores.
