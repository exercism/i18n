# Testes

Podes usar o editor online no site do Exercism para resolveres os exercícios.
Ou podes descarregar os exercícios para o teu computador, resolvê-los localmente e depois submetê-los ao Exercism.
O resto deste documento fala sobre trabalhar localmente.

## CLI do Exercism

Vais precisar da ferramenta de linha de comandos `exercism` para descarregares e submeteres exercícios.
Consulta [a documentação do CLI do exercism][exercism-cli].

### Função wrapper para a ferramenta exercism

Um dos aspetos irritantes da ferramenta exercism predefinida é que, depois de descarregares um exercício, tens de mudar de diretório manualmente.
Esta função wrapper trata disso por ti; guarda isto no teu `~/.bashrc`.

```bash
exercism () {
    local out
    readarray -t out < <(command exercism "$@")
    printf '%s\n' "${out[@]}"
    if [[ $1 == "download" && -d "${out[-1]}" ]]; then
        cd "${out[-1]}" || return 1
    fi
}
```

Repara que isto não pode ser um _script_ de shell, tem de ser uma _função_ de shell.
Os scripts de shell são executados num processo filho e não conseguem afetar o ambiente (como o diretório de trabalho atual) da tua shell atual.

## Testar localmente

Para testar no percurso de bash, usamos o [bats][bats].

Corre os testes para o exercício hipotético "whatever" assim:

```bash
cd /path/to/your/exercise_workspace/bash/whatever
bats whatever.bats
```

Se quiseres imprimir a saída de depuração enquanto corres os testes localmente, vê [Depuração local](/docs/tracks/bash/debugging).

## Instalar o `bats-core`

Deves conseguir instalá-lo a partir do teu gestor de pacotes preferido:

### Para Mac (brew)

No macOS com o [Homebrew][homebrew], isto seria mais ou menos assim:

```
$ brew install bats-core
==> Downloading https://github.com/bats-core/bats-core/archive/v1.1.0.tar.gz
==> Downloading from https://codeload.github.com/bats-core/bats-core/tar.gz/v1.1.0
######################################################################## 100.0%
==> ./install.sh /usr/local/Cellar/bats-core/1.1.0
🍺  /usr/local/Cellar/bats-core/1.1.0: 13 files, 55KB, built in 4 seconds
```

- O pacote `bats` legado também existe no ecossistema do Homebrew.
  **_Não instales esse por engano_**: <u>instala o `bats-core`</u>.

### Para Linux

#### Fedora 30 e versões mais recentes

O `bats` está empacotado para o Fedora 30 e versões mais recentes; podes instalá-lo com

```bash
sudo dnf install bats
```

#### Outras distribuições de Linux

Para outras distribuições de Linux, a implementação do `bats` que usamos pode não estar disponível num pacote conveniente.
A melhor forma de o instalar é a partir do código-fonte.
Se quiseres instalá-lo em `/usr/local`, então

```bash
git clone https://github.com/bats-core/bats-core
cd bats-core/
sudo ./install.sh /usr/local
```

Depois disso, partindo do princípio de que `/usr/local/bin` está no teu $PATH, podes agora fazer:

```bash
$ bats
Error: Must specify at least one <test>
Usage: bats [-cr] [-f <regex>] [-j <jobs>] [-p | -t] <test>...
       bats [-h | -v]
...
```

### Para Windows (MINGW64/Cygwin)

```
$ git clone https://github.com/bats-core/bats-core.git
$ cd bats-core
$ ./install.sh $HOME
```

Nota: se estiveres a usar o já desatualizado `https://github.com/sstephenson/bats.git` e encontrares um erro como `cp: cannot create symbolic link '${HOME}/bin/bats': No such file or directory`, tens de copiar manualmente o conteúdo da pasta `bin/bats/libexec/` para `${HOME}/bin/`.

Há relatos de que [as versões mais recentes do bats não se dão bem com o bash do MinGW][mingw-issues]. Antes de correres o script de instalação, podes querer:

```
$ git checkout v1.1.0
```

## Testes ignorados

Resolver um exercício significa fazer passar todos os seus testes.
Por predefinição, só um teste (o primeiro) é executado quando corres os testes.
Isto é intencional, pois permite-te focar-te apenas em fazer passar esse teste.
Assim que passar, podes ativar o teste seguinte comentando ou removendo as

    [[ $BATS_RUN_SKIPPED == true ]] || skip

anotações que precedem os outros testes.

### Anular os testes ignorados

Para correres todos os testes, incluindo os que têm anotações `skip`, podes definir a variável de ambiente `BATS_RUN_SKIPPED` com o valor `true`.
Uma forma de a definir apenas enquanto corres o bats é:

```bash
BATS_RUN_SKIPPED=true bats exercise_name.bats
```

Pode ser conveniente usar uma função wrapper para escrever menos:

```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```

Depois, corre os testes apenas com:

```bash
bats
```

## `bats` legado

O `bats-core` resultou de um fork da [implementação original do `bats`][sstephenson-bats].
O projeto `sstephenson/bats` tinha bastantes bugs e estava abandonado.
A propriedade foi transferida em 2017: [sstephenson/bats#150 (comentário)][bats-fork].

Se tiveres o sstephenson/bats original instalado (verifica com `bats -v`; se reportar um número de versão inferior a 1.0), deves mudar para o bats-core; caso contrário, podes ver-te [a ter falhas de teste inexplicáveis][legacy-failures].
