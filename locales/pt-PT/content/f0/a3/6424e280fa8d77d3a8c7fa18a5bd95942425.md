# Sobre

## Opcionais

O Swift usa [_opcionais_][optionals] para permitir aos programadores representar a possível ausência de um valor.
Um opcional é um tipo que pode conter um valor ou ser [`nil`][nil], que representa a ausência de um valor.
Usar um opcional obriga o programa a verificar se existe um valor antes de o usar, depois de o desembrulhar.

Qualquer tipo pode tornar-se um opcional acrescentando um `?` ao fim do nome do tipo.
Assim, um inteiro opcional teria o tipo `Int?` e uma string opcional teria o tipo `String?`.
Definir constantes ou variáveis de tipo opcional e atribuir-lhes valores faz-se da mesma forma que para valores de tipos não opcionais.

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

Podes atribuir a ausência de um valor a uma variável de tipo opcional atribuindo-lhe o valor especial `nil`.
O `nil` pode ser usado com todos os tipos opcionais, mas os `nil` atribuídos a dois tipos opcionais diferentes não têm o mesmo tipo e não podem ser trocados nem sequer comparados.

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

Repara também que, embora o `nil` possa ser atribuído a qualquer tipo opcional, não pode ser atribuído a um tipo não opcional (mesmo que este não contenha, na verdade, `nil`).
E os métodos que esperam um tipo não opcional não podem receber um tipo opcional sem que este seja primeiro desembrulhado.

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## Usar opcionais

Como os tipos opcionais não são os mesmos tipos que os seus tipos base, os dois tipos não podem ser usados da mesma forma.
Por exemplo: `Int("123") + 1` dá origem a um erro de compilação: "Value of optional type 'Int?' must be unwrapped to a value of type 'Int'".
Isto acontece porque `Int("123")` devolve um tipo opcional `Int?`, e não um tipo `Int`, dado que, se a string não puder ser convertida num inteiro, o resultado será `nil`.
Para aceder ao `Int` resultante da conversão, é preciso "desembrulhá-lo" primeiro.

Em Swift, isto faz-se habitualmente com as construções `if-let` e `guard-let` para [_ligação opcional_][optional-binding], que verificam se há `nil` e seguem um caminho de código com o valor desembrulhado ligado a um nome fornecido, se existir um valor, e seguem um caminho diferente se tiver sido encontrado `nil`.

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

Vale a pena notar que a variável `safeNum` tem o tipo `Int` e não `Int?`.
No exemplo abaixo, `num` é do tipo `Int?` e `safeNum` é do tipo `Int`.

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

Esta _ligação opcional_ é importante porque desembrulha (ou "remove") o tipo opcional do valor, permitindo usá-lo como um valor não opcional.
Se apenas verificares se o valor é `nil` com uma condição, o valor continua a ser de tipo opcional:

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

A opção `guard-let` também pode ser usada nos casos em que se pretende um retorno antecipado:

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## Comparar opcionais

Repara que, mesmo que o tipo base de um par de opcionais possa ser comparado com os operadores de comparação padrão, os próprios opcionais não podem ser comparados.
Só se pode verificar se são iguais.
Dois opcionais são iguais se ambos forem `nil` ou se os valores que envolvem forem iguais dentro dos respetivos tipos base.

No entanto, pode escrever-se código para fazer uma comparação personalizada de dois valores opcionais.
Abaixo está um exemplo de uma instrução `switch` que devolve `true` apenas se ambos os valores opcionais não forem `nil` e o primeiro valor for menor que o segundo.
Para isso, usa o _padrão de opcional_ `varName?`, que só corresponde a opcionais não nulos, ligando o valor dentro do opcional ao nome `varName`.

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## Coalescência de nil

Existe outra opção para desembrulhar quando é possível usar um [valor alternativo][fallback] se `nil` estiver presente.
Isto pode ser feito com o _operador de coalescência de nil_, `??`.
Partindo do princípio de que `x` é um `Int?`, se escreveres `let y = x ?? 0`, o Swift verifica se `x` é `nil`.
Se não for, desembrulha `x` e atribui o valor desembrulhado a `y`; se `x` _for_ `nil`, atribui 0 a `y`.

Como `x ?? y` é apenas uma forma abreviada de `x != nil ? x! : y`, se `x` não for `nil`, a expressão `y` não é sequer avaliada.

Por fim, convém notar que o operador de coalescência de nil é associativo à direita, o que pode dar resultados surpreendentes a quem não estiver atento.

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

Podes ler mais sobre o operador de coalescência de nil em [Uma visita guiada ao Swift: Operador de coalescência de nil][nil-coalescing].
