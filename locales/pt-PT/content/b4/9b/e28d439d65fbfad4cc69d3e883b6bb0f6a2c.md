# Anexo às instruções

## Estruturas de dados com estado

Em linguagens funcionais, como o Lean, a maioria dos valores é imutável por conceção.
Isto significa que as atualizações são normalmente feitas produzindo um novo valor.
O valor antigo e o novo coexistem, podendo ambos ser referenciados e usados.

No entanto, há muitas situações em que um valor _com estado_ é desejado, ou até necessário.
Um valor com estado é atualizado por mutação, _substituindo_ o valor antigo em vez de criar um novo.
Após uma mutação, só o valor atualizado permanece acessível.

Repara que as mutações podem quebrar algumas garantias da linguagem.
Uma função pura tem sempre de devolver o mesmo resultado para o mesmo conjunto de valores de entrada, mas, se um valor de entrada puder mudar ao longo do tempo, a função pode devolver resultados diferentes mesmo quando é chamada com os mesmos argumentos.
Da mesma forma, se uma função puder produzir alterações externas para além de devolver um resultado, ou puder ler de fontes que não sejam os seus parâmetros, duas chamadas à mesma função podem ter resultados diferentes e, por vezes, imprevisíveis.

Para lidar com este tipo de comportamento com estado, o Lean, tal como outras linguagens funcionais, exige que as funções com efeitos sejam envolvidas num tipo especial de estrutura que as distingue das funções puras.
Estas estruturas chamam-se _mónadas_.

É importante notar que, embora todos os valores com estado vivam dentro de alguma mónada com efeitos, nem todas as mónadas representam estado mutável.
Exemplos notáveis de mónadas "puras" são `Option`, `Except` e `Id`.

Neste exercício, vais definir uma estrutura de dados com estado chamada `LinkedList`.
As instâncias desta estrutura de dados são atualizadas por mutação.

Para isso, todas as funções ficam envolvidas na mónada `ST`.
Nesta mónada, o estado mutável é o único efeito secundário e as referências mutáveis não podem escapar.
Para mais informações, podes consultar a [referência][reference].
