# Introdução aos Comandos e Argumentos

Este percurso não é sobre como usar o bash como shell interativa.
É sobre aprender a escrever programas com bash, a linguagem de programação.

Um programa bash, ou _script_, é uma sequência de comandos guardados num ficheiro.
O bash (o executável) lê o ficheiro e executa os comandos por ordem.

## O shebang

A primeira linha de um script costuma ser uma _diretiva de intérprete_, também conhecida como _hashbang_ ou _shebang_:

```bash
#!/usr/bin/env bash
```

Quando o sistema operativo executa um ficheiro não binário, lê a primeira linha.
Se a linha começar por `#!`, o kernel usa-a para determinar que intérprete deve executar o ficheiro.
O `#!` tem de estar mesmo no início do ficheiro, sem espaços nem linhas em branco antes.

Aqui, o `env` procura o executável `bash` em `PATH`.
Também podes ver a forma mais simples `#!/bin/bash`, que fixa a localização do intérprete; a forma com `env` é mais portátil.

~~~~exercism/note
Não te deixes enganar por scripts ou exemplos na Internet que usam `/bin/sh` como intérprete.
**`sh` não é `bash`!**
O bash é "compatível com sh" e consegue correr a maioria dos scripts `sh`, mas algumas funcionalidades do bash avariam ou comportam-se de forma inesperada no `sh`.
~~~~

## Comentários

Uma linha que começa por `#` é um _comentário_, e o bash ignora-a.
Um comentário também pode aparecer depois de um comando na mesma linha: tudo desde o `#` até ao fim da linha é ignorado.
Os comentários existem para quem lê o script.

## Palavras e argumentos

O Bash lê comandos da sua entrada (que é normalmente um terminal ou um ficheiro).
Cada linha de entrada que lê é tratada como um _comando_, uma instrução a ser executada.
(Existem alguns casos avançados, como comandos que abrangem várias linhas, que serão abordados mais adiante.)

O Bash divide cada comando em **palavras** delimitadas por carateres de espaço em branco (espaços e tabulações).
A primeira palavra é o nome do _comando_ a executar.
Todas as palavras restantes tornam-se _argumentos_ desse comando (opções, nomes de ficheiros, etc.).

Um comando pode ser um _builtin_ do bash, como o `echo`, ou um programa _executável_, como o `head`, o `awk` ou o `sed`.

## O comando `echo`

O `echo` imprime os seus argumentos, separados por um único espaço, e termina com uma mudança de linha:

```bash
echo flour sugar eggs
```

produz:

```text
flour sugar eggs
```

A quantidade de espaço em branco entre argumentos não importa:

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

Chamar o `echo` sem argumentos imprime uma linha em branco.

## As opções são apenas argumentos

Muitos comandos aceitam _opções_ que alteram o seu comportamento.
Para o bash, uma opção não tem nada de especial: é uma palavra como qualquer outra, separada das palavras vizinhas por espaço em branco.
É o próprio comando que decide como interpretar os seus argumentos.
Por convenção, as opções começam por `-`.

O comando `head` imprime as primeiras linhas de um ficheiro.
Dado um ficheiro `list.txt`:

```bash
head -n 2 list.txt
```

O Bash divide esta linha em quatro palavras:

| Palavra    | Função                                             |
| ---------- | -------------------------------------------------- |
| `head`     | o comando a executar                               |
| `-n`       | uma opção, que diz ao `head` para contar _linhas_  |
| `2`        | o valor da opção `-n`                              |
| `list.txt` | o ficheiro a ler                                   |

O Bash passa as três últimas palavras ao `head` sem as alterar.
É o `head` que percebe que o `-n` é seguido de um número e que a palavra restante é um ficheiro.

Como é o espaço em branco que separa as palavras, importa onde o colocas.
O `head -n 2` dá dois argumentos ao `head` (`-n` e `2`), enquanto o `head -n2` lhe dá apenas um (`-n2`).
Muitos comandos aceitam as duas formas, mas isso depende do comando.
O bash não se importa; limita-se a dividir a linha em palavras.

## Colocar argumentos entre aspas

[As aspas][Quotes] agrupam palavras num _único argumento_.
O espaço em branco dentro das aspas é preservado, e os próprios carateres de aspas não fazem parte do argumento:

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

Se um argumento, como um nome de ficheiro, contiver espaço em branco, coloca-o entre aspas:

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## Executar um script

Para executar um script, passa-o como argumento ao comando `bash`:

```bash
bash myscript
```

Usada desta forma, a linha `#!` é apenas um comentário.
Estás a dizer ao sistema operativo como executar o ficheiro.

Em alternativa, marca o ficheiro do script como executável e executa-o como qualquer outro programa:

```bash
chmod +x myscript
./myscript
```

Agora é o sistema operativo que usa a linha `#!` para determinar que intérprete usar.
