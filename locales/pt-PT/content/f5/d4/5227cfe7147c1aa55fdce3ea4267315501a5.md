# Testes

Cada exercício contém um ficheiro de testes.
Corre os testes com o programa `bats`.

```bash
bats test-hello-world.bats
```

O `bats` tem de estar instalado.
Consulta a página [Testar no percurso Bash][bash] para instruções sobre como instalar o `bats` no teu sistema.

### O bats está implementado em bash

O ficheiro do bats é um script bash, com algumas funções especiais reconhecidas pelo comando `bats`.
Vais ver alguns testes com este aspeto

```sh
jq -f some-exercise.jq <<< "{some,json,here}"
```

Essa sintaxe `<<<` é uma [Here String][here-string] do bash.
Envia a string do lado direito para a entrada padrão do programa do lado esquerdo.
É ([aproximadamente][so]) o mesmo que

```sh
echo "{some,json,here}" | jq -f some-exercise.jq
```

## Ajuda para as funções assert

Os testes usam funções da biblioteca [bats-assert][bats-assert].
Aí encontras ajuda para as várias funções `assert*`.

## Testes ignorados

Resolver um exercício significa fazer com que todos os seus testes passem.
Por omissão, só um teste (o primeiro) é executado quando corres os testes.
Isto é intencional, porque assim podes concentrar-te apenas em fazer esse teste passar.
Assim que ele passar, podes ativar o teste seguinte comentando ou removendo as

    [[ $BATS_RUN_SKIPPED == true ]] || skip

anotações que estão antes dos outros testes.

## Anular os skips

Para correr todos os testes, incluindo os que têm anotações `skip`, podes correr:

```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Pode ser prático usar uma função wrapper para escrever menos: em `bash`, podes fazer:

```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```

Depois, corre os testes apenas com:

```bash
bats
```

## Depurar em `jq`

O `jq` traz um filtro [`debug`][debug] muito útil.
Usa-o enquanto estás a desenvolver as tuas soluções para o exercício, para inspecionares os dados que estão neste momento no pipeline do jq.
Consulta a [documentação de depuração][debugging] para mais detalhes.
