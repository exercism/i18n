# Sobre

O Factor divide a E/S de fluxos em duas camadas. A camada inferior é a API de *fluxo explícito*: cada palavra recebe o fluxo como argumento. A camada superior é a API de *fluxo ambiente*: palavras curtas, de uma só linha, que atuam sobre o fluxo que estiver ligado no momento. Ambas as camadas assentam no mesmo [protocolo][stream-protocol]; as palavras da camada superior limitam-se a procurar o fluxo ambiente e a reencaminhar a chamada.

## Palavras de fluxo explícito

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents` consome tudo; `stream-lines` consome e divide nos limites de linha; `stream-readln` devolve uma linha de cada vez (ou `f` no fim do fluxo).

## Palavras de fluxo ambiente

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

Estas são as palavras de E/S do dia a dia. Procuram o fluxo de entrada ou de saída atual nas variáveis dinâmicas `input-stream` / `output-stream` e reencaminham a chamada. É por isso que redirecionar `print` para uma string é só uma questão de ligar `output-stream` durante a execução de uma quotation.

## Construtores de fluxos incluídos

| palavra           | vocabulário          | o que constrói                  |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | lê uma string literal           |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | recolhe escritas numa string    |
| `<file-reader>`   | [`io.files`][io.files]           | lê um ficheiro com uma codificação   |
| `<file-writer>`   | [`io.files`][io.files]           | escreve num ficheiro com uma codificação |

Os quatro produzem objetos descartáveis: são extensões de `disposable`, do vocabulário `destructors`, por isso os combinadores `with-…` abaixo libertam-nos ao sair.

## Ligação com âmbito

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

Cada uma abre um fluxo, liga-o como entrada ou saída ambiente para a quotation interior e liberta-o ao sair, mesmo que a quotation lance uma exceção. São os combinadores destrutores de `boatswains-bilge`, especializados para fluxos.

`with-string-writer` é uma variante especialmente elegante: constrói automaticamente um `<string-writer>` novo, executa a quotation com esse fluxo de escrita como saída ambiente e devolve a string acumulada. Todo o padrão de «capturar a saída de uma quotation» é uma única palavra.

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## Mas porquê ambiente, afinal?

A ligação às variáveis dinâmicas é o que faz `print` funcionar num programa que não sabe se está a ser executado de forma interativa, se para um ficheiro de registo, ou se para um buffer de teste capturado. Basta substituir a ligação uma vez e todas as palavras que chamam `print` passam a fazer o que é certo, sem ser preciso refazer ligações. É esta a inversão que a camada superior te oferece.

Para *implementares* um fluxo (definir uma classe tua que encaixe no protocolo), vê o conceito `streams` (lecionado em `telegraphers-tape`).
