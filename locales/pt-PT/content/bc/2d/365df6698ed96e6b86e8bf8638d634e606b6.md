# Sobre

Uma declaração `MACRO:` é uma palavra cujo *corpo* é executado em tempo de compilação. O corpo consome argumentos literais da pilha de compilação e tem de deixar uma quotation na pilha. O compilador substitui depois essa quotation pela chamada à macro, por isso o programa em tempo de execução nunca vê a macro, apenas o código que ela produziu.

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- compound )
    dup append ;
```

Se quem chama escrever `[ 1 + ] twice`, o compilador executa o corpo com `[ 1 + ]` na pilha, recebe de volta `[ 1 + 1 + ]` e insere esse resultado no lugar. Não há qualquer custo em tempo de execução: o ciclo ou combinador que a macro substituiu desapareceu.

## Os valores de entrada têm de ser literais

Porque o corpo é executado em tempo de compilação, cada valor de entrada tem de ser um *literal* no local da chamada: uma quotation `[ … ]`, um número, um array, uma string. Passar um valor não literal (um valor que só se conhece em tempo de execução) é um erro de compilação.

```factor
! works: [ 1 + ] is a literal quotation
: inc-twice ( x -- y ) [ 1 + ] twice ;

! refused: f is a literal, but the macro can't run with a non-quotation
! input where the body expects to call `append` on it
```

## Os valores de entrada estruturais determinam a estrutura da saída

As macros interessantes recebem uma *estrutura* (um array, uma sequência literal de pares) e produzem código cuja forma depende dessa estrutura. O `each-literal` deste exercício recebe uma sequência literal e uma quotation e produz uma cópia currificada e inline da quotation por cada elemento. O programa em tempo de execução é código linear, sem `each` e sem despacho por elemento, e a iteração da sequência aconteceu por completo em tempo de compilação.

## Porque é que não há problema de higiene

As macros de Lisp debatem-se com a *higiene*: uma macro que introduz um nome local pode colidir com nomes no local da chamada, o que exige `gensym` ou um sistema de higiene. O Factor não tem este problema, porque as quotations são sequências de *referências de palavras resolvidas*: cada palavra é procurada em tempo de análise, não simbolicamente em tempo de expansão. Um `dup` dentro de uma quotation construída por uma macro será sempre `kernel:dup`, independentemente dos nomes que existam no local da chamada.

O custo é este: as macros do Factor não podem introduzir novas ligações como o `defmacro` consegue. Constroem código a partir de palavras que o analisador sintático já viu. Para a maior parte da metaprogramação, isto chega.

## Formas adjacentes (não abordadas aqui)

- `MACRO::`: variante com variáveis locais de `MACRO:`, tal como `::` é a forma com variáveis locais de `:`. Útil quando o corpo faz referência aos seus valores de entrada mais do que uma vez.
- `<< … >>`: bloco de avaliação em tempo de análise. Executa Factor comum em tempo de compilação, sem o contrato de devolver uma quotation. Útil para calcular um valor que tem de existir em tempo de análise (por exemplo, um `CONSTANT:` derivado de uma consulta ao ambiente).
- `SYNTAX:`: *palavras de análise*. São outra coisa por completo: operam sobre o fluxo de tokens do analisador sintático, não sobre valores, e são executadas numa fase ainda mais inicial. Usam-se para definir novas sintaxes literais (`T{ }`, `H{ }`). Está fora do âmbito deste conceito.
- `functor:`: modelos declarativos que geram conjuntos de palavras relacionadas a partir de uma única especificação. Construídos sobre o mecanismo das macros; território de quem escreve bibliotecas.
