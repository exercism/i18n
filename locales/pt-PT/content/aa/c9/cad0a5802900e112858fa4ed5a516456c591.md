# Sobre

Apesar de os programadores de Elixir dizerem frequentemente «let it crash» e programarem para o «caminho feliz», há muitas vezes em que precisamos de apanhar o erro da chamada à função para devolver um valor específico, uma mensagem, ou libertar recursos do sistema.

- As funções que lançam erros em circunstâncias normais devem ter um `!` no fim do nome.
- As funções podem, em alternativa, devolver átomos e tuplos para indicar sucesso e falha:

  ```elixir
  Map.fetch(%{a: 1}, :a)
  # => {:ok, 1}
  Map.fetch(%{a: 1}, :b)
  # => :error

  Map.fetch!(%{a: 1}, :b)
  # => raises KeyError
  ```

## Evita antipadrões

Evita padrões de programação que usam erros para controlar o fluxo lógico. Isto é um antipadrão em Elixir.

```elixir
# Avoid using errors for control-flow.
try do
  {:ok, value} = MyModule.janky_function()
  "All good! #{value}."
rescue
  e in RuntimeError ->
    reason = e.message
    "Uh oh! #{reason}."
end

# Rather, use control-flow structures for control-flow.
case MyModule.janky_function() do
  {:ok, value} -> "All good! #{value}."
  {:error, reason} -> "Uh oh! #{reason}."
end
```
