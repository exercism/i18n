# Introdução

## Exceções

Todos os erros em Elixir implementam o _comportamento Exception_. Tal como o _comportamento Access_, o _comportamento Exception_ define funções de callback que um módulo tem de implementar para cumprir o contrato de software do comportamento. Assim que um erro é definido, tem as seguintes propriedades:

- O nome do módulo define o nome do erro.
- O módulo define uma estrutura de erro.
- A estrutura terá um campo `:message`.
- O módulo pode ser usado com `raise/1` e `raise/2` para lançar o erro pretendido

O _comportamento Exception_ também especifica dois callbacks: `message/1` e `exception/1`. Se não forem implementadas, serão usadas implementações predefinidas. `message/1` transforma a estrutura de erro numa mensagem legível quando é chamada com `raise`. `exception/1` permite adicionar contexto adicional à mensagem quando é chamada com `raise/2`

### Definir uma exceção

Para definir uma exceção a partir de um módulo de erro, usamos a macro `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### Utilizar exceções

Os erros definidos podem ser usados como um erro incorporado, utilizando `raise/1` ou `raise/2`.

- `raise/1` lança um erro específico pelo nome do módulo ou, se o argumento for uma string, lança um `RuntimeError` com a string como mensagem.
- `raise/2` lança um erro específico pelo nome do módulo e aceita um argumento de atributos que é usado para obter o erro com a mensagem apropriada.
