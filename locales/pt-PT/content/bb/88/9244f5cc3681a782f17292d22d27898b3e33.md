# Introdução

## Structs

As structs são tipos de dados personalizados que te permitem dar um nome e agrupar vários valores relacionados.

Para definir uma struct, usa a palavra-chave `struct` seguida de um nome e de chavetas que contêm os campos com os respetivos nomes e tipos:

```rust
#[derive(Drop)]
struct User {
    active: bool,
    username: ByteArray,
    email: ByteArray,
    sign_in_count: u64,
}
```

Para criar uma instância de uma `struct`, indica o nome da `struct` e usa chavetas com pares chave-valor para os campos.

```rust
let user = User {
   active: true, username: "someusername123", email: "someone@example.com", sign_in_count: 1
};
```

Usa a notação de ponto para aceder aos campos de uma instância de `struct` mutável ou para os modificar.

```rust
let mut user = User {
    active: true, username: "someusername123", email: "someone@example.com", sign_in_count: 1
};
user.email = "anotheremail@example.com";
```

## Propriedade

Os valores em Cairo são imutáveis, e essa imutabilidade garante que, mesmo que muitas variáveis se refiram ao mesmo valor, o próprio valor permanece constante e inalterado.
O _proprietário_ de uma variável é o código que pode ler (e escrever, se for mutável) essa variável.

Regras de propriedade em Cairo:

1. Cada variável em Cairo tem um proprietário.
2. Só pode haver um proprietário de cada vez.
3. Quando o proprietário sai do âmbito, a variável é destruída.

Um âmbito é a região de um programa na qual uma variável é válida.

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Quando uma variável sai do âmbito, é destruída, o que garante que o recurso associado é libertado corretamente.
Isto consegue-se implementando ou derivando o trait `Drop`, que indica ao compilador que o tipo pode ser destruído em segurança quando já não for útil.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

De momento, a implementação de `Drop` pode ser derivada para todos os tipos, exceto para dicionários (`Felt252Dict`) e para tipos que contenham dicionários.

Um valor também pode ser _movido_. Isto acontece quando um valor é passado a outra função: a variável original que se referia ao valor é destruída (ficando assim inútil) e é criada uma nova variável para conter o mesmo valor.

```rust
fn foo(num: u32) { 
    // do something with p
}

fn main() {
    let num: u32 = 10;
    foo(num);
    // ownership of `num` was moved into `foo` and is thus no longer valid in this scope
}
```

Devolver valores é equivalente a movê-los.

O exemplo abaixo mostra uma função que devolve um valor:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    // main now owns a1
    let a1 = gives_ownership();

    // a2 comes into scope
    let a2 = A {};

    // a2 is moved into takes_and_gives_back, which also moves its return value into a3
    let a3 = takes_and_gives_back(a2);
} // Here, a3 and a1 go out of scope and are dropped. a2 was moved, so nothing happens.

// Moves its return value into the function that calls it
fn gives_ownership() -> A {
    let some_a = A {};
    some_a
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A {
    some_a
}
```

Como uma variável é destruída depois de ser movida, o compilador impede-nos de a reutilizar a seguir.

```rust
#[derive(Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(p: Point) { 
    // do something with p
}

fn main() {
    let p = Point { x: 5, y: 10 };
    foo(p);
    foo(p); // compiler error: Variable was previously moved.
}
```

Neste caso, tentamos passar o mesmo valor (a struct `Point` na variável `p`) às duas chamadas de função.
Depois de passarmos a variável à função `foo` pela primeira vez, a variável já não pode ser usada.

Uma forma de resolver isto é derivar o trait `Copy` na nossa struct, o que alteraria o que acontece quando passamos uma variável `Copy` a uma função: deixaria de mover o valor e criaria uma nova variável que se refere ao mesmo valor.
Esta é uma operação gratuita, porque as variáveis são uma abstração de Cairo e os valores são sempre imutáveis.

Para implementar o trait `Copy` no teu tipo, adiciona a anotação `#[derive(Copy)]` à definição do tipo.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(p: Point) { 
    // do something with p
}

fn main() {
    let p = Point { x: 5, y: 10 };
    foo(p);
    foo(p); // this now works
}
```

## Referências e snapshots

Cairo tem duas funcionalidades para passar um valor sem o destruir ou mover, chamadas `references` e `snapshots`.

Os snapshots fornecem uma "vista" imutável de um valor num determinado momento, permitindo-te manter a propriedade de uma variável enquanto acedes ao seu estado.
Qualquer modificação à variável cria uma nova célula de memória, deixando a vista do snapshot inalterada.

Para criar um snapshot, basta colocar `@` antes da instância da variável.

```rust
// this function takes in a snapshot using `@` with the data-type
fn get_len(arr: @Array<u128>) -> u32 { // 
    arr.len()
}

fn foo(arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let mut new_arr: Array<u128> = array![1, 2, 3, 4, 5, 6, 7, 8];
    let snapshot = @new_arr; // using `@` to create a snapshot of a variable
    let len = get_len(snapshot); // pass the snapshot as argument, retaining ownership
    foo(new_arr); // `new_arr` is still valid up until here and no further
}
```

Para converter um snapshot de volta numa variável normal, podes usar o operador desnap `*`, que funciona como o oposto do operador `@`.
Só os tipos que implementam o trait `Copy` podem sofrer desnap.

```rust
fn square(n: @u32) -> u32 {
    let n = *n; // we desnap the value
    n * n
}

fn main() {
    let num: u32 = 10;
    let squared = square(@num); // we use `@` to create a snapshot
    println!("{} squared = {}", num, squared);
}
```

As referências permitem-te passar valores mutáveis a funções e recebê-los de volta implicitamente, mantendo a propriedade no contexto de quem chama.
Isto consegue-se com o modificador `ref`, desde que a variável seja declarada como mutável com a palavra-chave `mut`.

Podemos atualizar o exemplo anterior da struct `Point` para usar referências mutáveis em vez de depender do trait `Copy`, e continuaria a funcionar.

```rust
#[derive(Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(ref p: Point) { 
    // we can now update the passed values and the changes
    // will be visible in the calling context
    p.x += 1;
}

fn main() {
    let mut p = Point { x: 5, y: 10 };
    foo(ref p);
    foo(ref p); // this now works even without the Copy trait
    println!("p.x = {}", p.x); // p.x = 7 
}
```
