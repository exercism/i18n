# Apêndice às instruções

Há muitas formas de resolver este exercício, mas concebemo-lo a pensar em quem quer praticar a escrita dos seus próprios [gestores de capacidades][ability-handler-docs].

Escreve uma capacidade `Zipper` que te permite navegar por uma estrutura de dados de árvore binária.

A própria capacidade `Zipper` está definida para ti, mas vais ter de implementar o gestor que lhe permite navegar pela estrutura de dados de árvore binária que indicámos.

Dada a seguinte árvore binária, se chamarmos `Zipper.right`, `Zipper.right`, `Zipper.up` e depois `Zipper.left`, devemos ficar no nó com o valor `5`.

```
     1
   /   \
  2     4
 /     /  \
3     5    7
```

Para efeitos deste exercício, se chamares `left` ou `right` numa árvore binária que não tenha um ramo à esquerda ou à direita, podes devolver o valor do nó atual.

## Coisas para pensar

Em que medida é que um gestor de capacidades é, ele próprio, como um fecho éclair? Podes considerar a `continuation` de uma função um ponteiro para o próximo "nó" do teu programa? Podes guardar no teu gestor as chamadas anteriores à continuation, para poderes navegar "para trás" até um estado anterior?

Que outras estruturas de dados poderias percorrer desta forma? Poderias escrever um Zipper sobre JSON ou um sobre a árvore DOM do HTML?
