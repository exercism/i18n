# Anexo às instruções

## Prós e contras de `from_quote`
Este exercício define uma função `from_quote` no tipo `Time`. Isto permite escrever código como este:

```roc
time : Time
time = "00:01:23"
```

Este código chama implicitamente `Time.from_quote("00:01:23")` em tempo de compilação. Isto pode acelerar o programa, uma vez que não precisa de tratar da análise em tempo de execução, e garante que os tempos rejeitados por `from_quote` são detetados em tempo de compilação, em vez de em tempo de execução. Além disso, torna o código agradável e legível. Por exemplo, eis um dos testes deste exercício:

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

No entanto, quem leia este código pode assumir que a função `advance_time` recebe uma `Str`, quando na verdade recebe um `Time`. Isto pode originar confusão e erros. Por este motivo, podes preferir o formato um pouco mais longo mas mais explícito: `"00:00:05".Time`, que também chama `from_quote` em tempo de compilação.

Nos teus próprios programas, podes preferir usar antes `from_str`:

```roc
Time := { ... }.{
    from_str : time_str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

Também podes chamar `from_str` (ou qualquer outra função pura) em tempo de compilação, assim:

```roc
Ok(time) = Time.from_str("00:01:23")
```

Nota: colocar esta definição ao nível de topo faz com que seja executada em tempo de compilação (uma vez que a função é pura e o seu valor de entrada é conhecido em tempo de compilação). Dentro de uma função, podes usar `from_str` em tempo de execução.
