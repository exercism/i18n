# Sobre

Em muitas linguagens orientadas a objetos, é comum estender comportamentos através da [criação de subclasses][wiki-subclass] de uma classe-mãe, herdando métodos dela e acrescentando também novos.
Assim, obtemos uma hierarquia de objetos.

A Julia _não tem classes_, por isso, por extensão, _não tem subclasses_.
Como é que herdamos e estendemos comportamentos já existentes?

Nos conceitos anteriores, vimos como criar uma hierarquia de tipos e aprendemos também como a Julia usa o [despacho múltiplo][concept-multiple-dispatch] para escolher métodos com base nos tipos dos argumentos.

A Julia tem também várias [interfaces][ref-interfaces] informais, que permitem que os teus tipos personalizados se integrem em comportamentos já definidos para os tipos padrão.

Isto ilustra-se mais facilmente com a interface de iteração.

## [Iteradores][ref-iterators]

Anteriormente, no currículo, já vimos várias formas de a Julia operar sobre cada elemento de uma coleção.

- [Ciclos][concept-loops], como `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Funções de ordem superior][concept-hof]: `map(√, [1, 4, 9])`
- [Compreensões][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Geradores][concept-comprehensions]: `(x^2 for x in 1:1e6)`, que é avaliado de forma preguiçosa.

Claramente, a Julia sabe percorrer coleções padrão item a item: vetores e intervalos nos exemplos acima, e também Sets, Dicts, etc.

Como é que adicionamos esta capacidade às nossas próprias coleções personalizadas, especialmente se puderem ser iteradas de forma preguiçosa, como um gerador?

### Requisitos mínimos

Para criar uma sequência para iteração, precisamos de (pelo menos) duas coisas:

1. Uma forma de obter o _primeiro_ item.
2. Uma forma de obter o item _seguinte_ a partir do estado atual.

A Julia realiza estas tarefas com métodos da função `Base.iterate()`, através dos seguintes passos:

1. `Base.iterate(iter)` é chamado automaticamente primeiro.
    - Se não houver nada para iterar, devolve `nothing`.
    - Caso contrário, devolve o `Tuple` do primeiro item devolvido e do primeiro estado: `(firstitem, firststate)`.
2. `Base.iterate(iter, state)` é chamado automaticamente se tiver sido devolvido um item na iteração anterior, recebendo `firststate` como o seu argumento `state`.
    - Se a iteração terminar, devolve `nothing`.
    - Caso contrário, devolve o `Tuple` do item seguinte e do estado seguinte: `(nextitem, nextstate)`.
3. Repete o passo 2 até à terminação.

Todos estes passos acontecem "nos bastidores", o que significa que as chamadas aos métodos e o estado são geridos internamente pelo protocolo de iteração (mantendo-se o estado opaco), e só o item é exposto a construções de alto nível, como os ciclos.
Por outras palavras, só vemos o `item`, enquanto tudo o resto permanece numa caixa negra.

O [despacho múltiplo][concept-multiple-dispatch] é central para isto.
O tipo de `iter` determina que métodos são chamados, e o número de argumentos determina se é devolvido o primeiro item ou o seguinte.

Os métodos para os tipos padrão já estão definidos: `Vector`, `Range`, `Set`, etc. ([atualmente][ref-iterations-collections] 14 tipos no total).

Para que um `MyType` personalizado partilhe os mesmos comportamentos, temos primeiro de definir:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Tudo isto provavelmente soa confuso em abstrato, mas pode ser bastante simples.
A título de exemplo, imagina que queremos um tipo que dá as potências de um dado inteiro `n`, até um número máximo de termos.

Primeiro, define um tipo personalizado:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Já podemos definir os métodos `iterate` para este tipo, mas quais são o primeiro item e o primeiro estado?

Para obter o primeiro item, alguns iteradores precisam de uma preparação complicada, mas neste caso simples, podemos reparar que o primeiro item devolvido é apenas o número base, por isso só precisamos de verificar se o valor de `count` é maior ou igual a um.

Agora podemos considerar o primeiro estado, que transporta a informação utilizada na iteração seguinte.
Cabe-te a ti decidir que informação precisas de acompanhar para o fazer, e pode ser de qualquer tipo.

Neste caso, podemos simplesmente acompanhar o "índice" a que elevamos `n`, ou podemos encontrar uma opção mais eficiente usando a potência mais recente de `n` (ou seja, o item devolvido) e o "índice" seguinte na sequência.
Estes dois números podem ser agrupados num `Tuple` e devolvidos como o `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

Neste exemplo, o primeiro item (`p.n`) é devolvido ao ciclo e o primeiro estado `(p.n, 2)` é passado ao método `iterate(P::Powers, state)`.
Aí podemos processar o estado para produzir o item seguinte, multiplicando o item atual pelo número base, aumentando assim a sua potência em `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Se o valor do índice ainda estiver dentro de `count`, o `Tuple` é devolvido com o item `next` e o estado incrementado `(next, index + 1)`.
Quando o valor de `index` ultrapassa `count`, devolve-se `nothing`, para indicar que a iteração terminou.

Talvez tenhas reparado que os métodos `iterate(p::Powers)` e `iterate(p::Powers, state)` têm corpos de função bastante semelhantes.
De facto, se formos espertos, esta semelhança permite uma implementação mais simples, usando apenas a versão com dois argumentos e um argumento predefinido para o estado: `Base.iterate(p::Powers, state=(1, 1))`
Assim, não precisaríamos da versão separada com um único argumento `iterate(p::Powers)`.
Isto faz-se habitualmente na prática, sempre que possível.

~~~~exercism/advanced
Quando introduzimos os argumentos opcionais no conceito [Funções][concept-functions], não se disse nada sobre a implementação.

Desde então, ficámos a conhecer o despacho múltiplo, por isso agora faz mais sentido saber que a Julia converte automaticamente uma função _com_ argumentos opcionais em vários métodos _sem_ argumentos opcionais.

Definir `Base.iterate(P::Powers, state=(1, 1))` é exatamente equivalente a definir separadamente `Base.iterate(P::Powers, state)` e `Base.iterate(P::Powers)`.

[concept-functions]: https://exercism.org/tracks/julia/concepts/functions
~~~~

Até agora, já temos algumas funcionalidades úteis: para as primeiras 4 potências de 3, podemos percorrer os resultados num ciclo, verificar se um dado número está nos resultados, e aplicar funções de agregação como `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Métodos adicionais

Apesar deste bom começo, ainda não funciona tudo.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Como esperado, `length(Powers(3, 4))` dá exatamente a mesma mensagem de erro.

Isto corrige-se facilmente, pois o comprimento faz parte do construtor do tipo: 4, neste caso.
Basta definir `Base.length()` para este tipo, e depois podemos usar compreensões e `collect()` na sequência.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Por uma questão de eficiência, é melhor definir também `Base.eltype()`: o tipo dos elementos do resultado.
Isto permite que funções como `collect()` reservem antecipadamente espaço para o `Vector{Int}` de saída, em vez de fazerem repetidamente um `push!()` para um `Vector{Any}`.

Repara na sintaxe, que talvez ainda não tenhas visto: este método é definido no _tipo_, e não numa _instância_ do tipo.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Não é _obrigatório_ que os iteradores tenham comprimento finito.
A utilização de sequências "infinitas" é mais limitada, mas percorrê-las num ciclo pode ser útil, desde que haja alguma forma de `break` para sair do ciclo.
Por exemplo, podíamos definir uma variante de `Powers` que gerasse valores menores do que um certo limite (talvez `typemax(Int)`, para evitar overflow de inteiros).

## Outras interfaces

### [Indexação][ref-indexing]

A interface de iteração permite-nos pegar num tipo personalizado arbitrário e fazê-lo comportar-se como uma sequência, bastando definir alguns métodos simples.

Suponhamos que também queríamos poder indexar a sequência:

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

Podemos acrescentar este comportamento, e o [manual][ref-indexing] explica como.

No mínimo, precisamos de definir `getindex()`.

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

Também precisamos de definir:

- `firstindex()` e `lastindex()` para suportar `P[begin]` e `P[end]`.
- Variantes de `getindex()` para suportar indexação com vetores e intervalos.
- Em teoria, `setindex!()`, embora seja difícil ver o que isso significaria sequer neste exemplo.

No entanto, a esta altura estamos a fazer muito trabalho só para que o nosso iterador se pareça mais com um Vector.

### [AbstractArray][ref-abstractarray]

Pode valer a pena pensar em interfaces alternativas que ofereçam um melhor ponto de partida.

Neste caso, podíamos considerar fazer de `Powers` um subtipo de [`AbstractArray`][ref-abstractarray], o que nos dá, de graça, muito comportamento semelhante ao de um array.

Para a sequência `Powers`, o array correspondente é de inteiros, com 1 dimensão.
Por vezes vais ver isto escrito como `AbstractArray{Int, 1}`, mas os aliases `AbstractVector{Int}` para 1-D e `AbstractMatrix{Int}` para 2-D são mais comuns em código Julia mais recente.

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

Em vez de `length()`, precisamos agora de definir `size()` com um tuplo de comprimentos ao longo de cada dimensão: apenas uma dimensão, neste caso.

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

Como queremos indexar as entradas?
No [conceito de Arrays Multidimensionais][concept-multi-dimensional-arrays] introduzimos as duas abordagens principais:

- Um índice por dimensão, ou seja, `M[row, col]` para uma Matrix `M`.
- Um único índice, correspondente à disposição das entradas na memória

Estes são chamados `Cartesian` e `Linear`, respetivamente.

No exemplo temos apenas uma dimensão, por isso a indexação linear é a adequada.

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

Repara que, neste caso, não definimos `iterate()`.
A Julia fornece automaticamente uma implementação predefinida, com base na nossa definição de `getindex()`.

Ainda é possível definir a nossa própria versão de `iterate()`, e em alguns casos pode ser mais eficiente.

Usar a interface `AbstractArray` é especialmente valioso se quisermos iteração de dimensão superior.
Correndo o risco de esticar o exemplo simples até ao ponto de rutura, isto poderia significar as primeiras `m` potências dos números em `1:n`, o que definirá iterativamente um array de tamanho `(m, n)`.

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [Arredondamento][ref-rounding]

Conceitos anteriores mencionaram vários tipos de arredondamento para tipos numéricos.

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

A função [`round()`][ref-round] é mais flexível do que isto, permitindo especificar o [`RoundingMode`][ref-roundingmode] (dos 7 atualmente suportados), as casas decimais do resultado, e a base do número.

Podemos querer que as mesmas funções tratem dos nossos tipos personalizados.
Normalmente, isto significa tipos compostos, como coordenadas.

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

Como seria de esperar, existe uma interface `Rounding`, que exige, no mínimo, que definamos `round()` para o nosso tipo.

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

Como incluímos `RoundingMode` na definição, `floor()` e `ceil()` funcionam automaticamente.

Claro que somos livres de definir formas mais complicadas de arredondamento.

- Podemos querer arredondar o `Point3D` para uma distância inteira à origem, na mesma direção.
- Para ângulos, podemos querer arredondar para as 16 direções usadas pelos meteorologistas (_"vento de SSO a 15 nós"_), ou seja, múltiplos de π/8 radianos.
- Podemos querer acrescentar a capacidade de especificar `digits`, `sigdigits` ou `base`.
- Existem [opções especiais][ref-round-periods] para períodos de tempo

## Resumo

As interfaces são bastante confusas de explicar, porque a abordagem da Julia é muito diferente da da maioria das outras linguagens.
Em particular, o nome da interface pode nunca ser mencionado na implementação: muito ao contrário da [criação de subclasses][wiki-subclass] ou dos [mixins][wiki-mixins].

No entanto, na prática são surpreendentemente simples:

1. Define um tipo adequado, decidindo se a criação de subtipos é útil ou não.
2. Descobre quais os métodos necessários (a partir da [documentação][ref-interfaces]).
3. Implementa esses métodos para o teu tipo personalizado; normalmente apenas alguns métodos, bastante curtos e simples.
4. Deixa o [despacho múltiplo][concept-multiple-dispatch] tratar do resto, automaticamente.
