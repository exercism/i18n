# Para quem faz a manutenção

## Gerar testes: `bin/generate_tests.py`

Os ficheiros de teste são gerados a partir dos dados canónicos de
[exercism/problem-specifications](https://github.com/exercism/problem-specifications)
com um modelo Jinja guardado em cada exercício em `.meta/template.j2`.

```bash
bin/generate_tests.py bob            # regenerate one exercise
bin/generate_tests.py                # regenerate every exercise that has a template
bin/generate_tests.py --no-pull bob  # skip `git pull` of problem-specifications
```

O script lê o problem-specifications a partir da cache do configlet
(`~/.cache/exercism/configlet/problem-specifications`, preenchida por `bin/configlet sync`),
ou de um diretório pai chamado `problem-specifications`.
Só são gerados os casos incluídos em `.meta/tests.toml`.

Os literais de string do Fortran não podem conter escapes como `\n` e `\t`.
O filtro de modelo `escape_quote_whitespace` reescreve-os como
`" // NEWLINE // "`, `" // TAB // "` e `" // CARRIAGE_RETURN // "`,
por isso o modelo tem de declarar essas constantes (ver `exercises/practice/bob/.meta/template.j2`).

### Pré-requisitos

- CMake e compilador de Fortran a funcionar
- Python 3.12+ com `jinja2`
- git

### Fluxo de trabalho para adicionar um novo exercício

Usando o `bob` como exemplo:

- Cria um novo ramo, por exemplo `git checkout -b exercise-bob`
- Corre `bin/add-exercise bob` (precisa de `jq` e `curl`). Isto:
  - descarrega o configlet e corre `configlet create`, que adiciona o exercício ao `config.json` e sincroniza a documentação, os metadados e o `tests.toml` a partir do problem-specifications
  - ordena o `config.json` com `bin/reorder-exercises`
  - copia `exercises/shared/CMakeLists.txt` para o diretório do exercício
  - escreve uma solução esqueleto, um `.meta/example.f90` esqueleto e um `.meta/template.j2` inicial (a partir de `exercises/shared/template.j2`)

  Pede o teu nome de utilizador do GitHub a menos que passes `-a <username>`, e define a dificuldade como 1 a menos que passes `-d <difficulty>`.

- Edita o `.meta/template.j2` para que cada caso chame a função certa com os valores de entrada certos e depois gera os testes:

  ```bash
  bin/generate_tests.py bob
  ```

- Escreve uma solução funcional em `.meta/example.f90`. Substitui o ficheiro do estudante (por exemplo `bob.f90`) por um esqueleto das funções ou sub-rotinas que os testes chamam, para ajudar o estudante a começar
- Certifica-te de que todos os testes passam, correndo a compilação completa a partir da raiz do repositório:

  ```bash
  mkdir -p build && cd build
  cmake ..
  cmake --build .
  ctest -V -R bob
  ```

- Corre `bin/reorder-exercises` e `bin/configlet lint`
- Se tudo passar, abre um pull request com as tuas alterações

### Alterar `CMakeLists.txt`

Quando alterares o ficheiro do CMake, atualiza a cópia principal em `exercises/shared/` e usa `bin/update-cmake-files` para a copiar para todos os diretórios dos exercícios.
