# Introdução

Um *deque* (fila de duas extremidades) suporta push e pop em ambas as extremidades em O(1). A implementação padrão do Factor é `<dlist>` (uma lista duplamente ligada), em [`dlists`][dlists]; as operações estão em [`deques`][deques].

## A API do deque

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` esvazia o deque no próprio local, o que é útil para o reutilizar sem voltar a alocar.

Fazer push e pop na mesma extremidade dá-te uma pilha LIFO. Fazer push numa extremidade e pop na outra dá-te uma fila FIFO:

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

Para LIFO, recorrerias a um vetor (`V{ }`) com `push`/`pop`, que tem menos sobrecarga por operação. Recorre a `<dlist>` quando precisas de O(1) em *ambas* as extremidades, quase sempre para uma fila FIFO.

## Procura em largura

É o uso FIFO que faz dos deques a fronteira certa para a *BFS*. Começas com um único nó, fazes push dos vizinhos para o fim, fazes pop dos candidatos a partir do início e eliminas os duplicados com um hash-set:

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

Os candidatos mais antigos são visitados antes dos mais recentes, por isso a procura avança para fora em camadas a partir do início. É isso que confere à BFS a sua propriedade do caminho mais curto: a primeira vez que chegas a um nó objetivo é através de um caminho com o menor número de saltos.

## `MEMO:`, a cache automática

Por vezes, a consulta que a BFS faz por cada nó é dispendiosa. O vocabulário [`memoize`][memoize] do Factor dá-te o `MEMO:`, um substituto direto de `:` que guarda em cache o resultado da palavra, usando os seus parâmetros de entrada como chave:

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

Uma palavra `MEMO:` executa o corpo na primeira vez que vê um determinado valor de entrada e, a partir daí, devolve o resultado em cache. A interface é a mesma, não há chamadas extra no local da chamada, é apenas mais rápida em repetições.
