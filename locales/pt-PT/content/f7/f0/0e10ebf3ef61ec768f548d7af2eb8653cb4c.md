# Sobre

O [Elixir](https://elixir-lang.org/), lançado inicialmente em 2012, parte das funcionalidades já robustas do Erlang e leva-as mais longe, sendo ao mesmo tempo mais fácil de abordar, ler, testar e escrever para quem está a começar.

José Valim, o criador do Elixir, explica [na sua palestra de 2012](https://vimeo.com/53221562) como criou a linguagem para que as aplicações fossem:

  1. Distribuídas
  2. Tolerantes a falhas
  3. De tempo real suave
  4. De troca de código a quente (é possível introduzir código novo sem parar o servidor)

Na verdade, o Elixir compila para [bytecode](https://en.wikipedia.org/wiki/Bytecode) e corre depois na [máquina virtual BEAM do Erlang](https://codesync.global/media/robert-virding-co-creator-of-erlang-explains-the-beam/).

Não existe qualquer "custo de conversão" ao chamar Erlang, o que significa que podes executar código Erlang mesmo ao lado de código Elixir.

Como é uma linguagem funcional, no Elixir tudo é uma expressão.

O Elixir tem "documentação de primeira classe", o que significa que os comentários podem ser associados a uma função, o que torna a documentação mais fácil de consultar.

As expressões regulares também recebem tratamento de primeira classe, o que elimina o incómodo de ter de escapar caracteres dentro das strings.

A implementação de comunicação assíncrona do Elixir permite que o código seja leve e, ainda assim, suporte um elevado volume de concorrência.

Os programadores usam o Elixir para tratar milhares de pedidos e respostas *em simultâneo* num único nó de servidor.

Tem sido usado com sucesso em microsserviços que precisam de consumir e servir uma multiplicidade de APIs rapidamente.

O [framework Phoenix](https://www.phoenixframework.org/) ajuda a estruturar aplicações Elixir para a web.
