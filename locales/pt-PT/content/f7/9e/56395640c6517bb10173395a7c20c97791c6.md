# Fluxos de trabalho

O GitHub Actions usa o conceito de _fluxos de trabalho_, que são scripts executados automaticamente sempre que ocorre um evento específico (por exemplo, quando se faz push de um commit).

Cada fluxo de trabalho do GitHub Actions é definido num ficheiro `.yml` no diretório `.github/workflows`.
Para mais informações sobre os fluxos de trabalho, consulta a seguinte documentação:

- [Sintaxe dos fluxos de trabalho](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions)
- [Escolher quando o teu fluxo de trabalho é executado](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow)
- [Escolher onde o teu fluxo de trabalho é executado](https://docs.github.com/en/actions/writing-workflows/choosing-where-your-workflow-runs)
- [Escolher o que o teu fluxo de trabalho faz](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does)
- [Escrever fluxos de trabalho](https://docs.github.com/en/actions/writing-workflows)
- [Boas práticas](/docs/building/github/gha-best-practices)

## Fluxos de trabalho partilhados

Alguns fluxos de trabalho são partilhados entre repositórios.

```exercism/caution
Os fluxos de trabalho partilhados são sincronizados automaticamente (a partir do [repositório org-wide-files](https://github.com/exercism/org-wide-files/)).
Por isso, não deves alterar o conteúdo deles manualmente.
```

### Fluxos de trabalho gerais

- [Sincronizar etiquetas](/docs/building/tracks/ci/workflows/sync-labels): sincroniza as etiquetas do repositório a partir de um ficheiro

### Fluxos de trabalho específicos de um percurso

- [configlet](/docs/building/tracks/ci/workflows/configlet): verifica se os ficheiros (de configuração) do percurso estão bem estruturados, tanto a nível sintático como semântico
- [Nenhum ficheiro importante alterado](/docs/building/tracks/ci/workflows/no-important-files-changed): comenta os pull requests que provocariam a repetição dos testes das soluções existentes
- [Teste](/docs/building/tracks/new/setup-continuous-integration#h-test-workflow): verifica os exercícios do percurso

### Fluxos de trabalho específicos das ferramentas

- [Publicar](/docs/building/tracks/ci/workflows/deploy): publica a imagem Docker das ferramentas do percurso no Docker Hub e no ECR

### Fluxos de trabalho opcionais

Existem também alguns fluxos de trabalho que os percursos podem optar por usar:

- [Pausar as contribuições da comunidade](/docs/building/tracks/ci/workflows/pause-community-contributions): comenta automaticamente em issues e PRs recém-criados por utilizadores que não são membros da organização do Exercism no GitHub

## Fluxos de trabalho personalizados

Os maintainers podem adicionar livremente fluxos de trabalho personalizados aos seus repositórios.
Exemplos desses fluxos de trabalho podem ser:

- [Análise estática de scripts shell](https://github.com/exercism/configlet/blob/3baa09608c8ac327315c887608c13a68ae8ac359/.github/workflows/shellcheck.yml)
- [Comentário automático em pull requests](https://github.com/exercism/elixir/blob/b737f80cc93fcfdec6c53acb7361819834782470/.github/workflows/pr-comment.yml)
- Etc.
