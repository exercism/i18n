# Sobre

Uma função é recursiva de cauda se a _última_ coisa executada pela função for uma chamada a si própria.

Cada vez que se chama uma função, é colocado um _quadro da pilha_ com as suas variáveis locais e os seus argumentos no topo da [pilha de chamadas de funções][call-stack].
Quando uma função devolve, o quadro da pilha é retirado da pilha.

As funções recursivas de cauda permitem a [otimização de chamadas de cauda][tail-call-optimization] (ou eliminação de chamadas de cauda).
É uma otimização que permite que a chamada de função seguinte reutilize o último quadro da pilha, quando está garantido que a função anterior já não precisa dele.
Isto atenua o problema de transbordar a pilha de chamadas de funções, que é a situação em que há tantos quadros na pilha de chamadas que já não há memória para criar mais um.

## Otimização de chamadas de cauda em Elm

Em determinadas condições, o compilador de Elm consegue realizar automaticamente uma otimização de chamadas de cauda ao compilar para JavaScript.

A otimização pode acontecer numa função recursiva quando a _última_ operação de um ramo é feita através da chamada da própria função numa aplicação simples de função.
Vamos ver alguns exemplos:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

A implementação acima não é recursiva de cauda, porque a última operação do ramo `else` é uma multiplicação `n *`.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

A implementação acima é recursiva de cauda e será otimizada, porque a última operação do ramo `else` é `factorialHelper` a chamar-se a si própria.
Isto não seria possível numa função com a assinatura de tipo `Int -> Int` e, na prática, a otimização de chamadas de cauda consegue-se muitas vezes definindo funções auxiliares.

## Casos limite

Em alguns casos, o compilador não consegue otimizar as funções recursivas. Vamos ver alguns exemplos.

Embora `f x = f (x - 1)` seja recursiva de cauda, `f x = (x - 1) |> f` já não é, porque a aplicação de função `|>` é a última operação e é considerada separada de `f`.
Da mesma forma, as funções que terminam com condições booleanas, como `f x = x > 0 || f (x - 1)`, não são recursivas de cauda.

A função `f x = if f (x - 1) then 1 else 0` não é recursiva de cauda, porque a expressão dentro do `if` não é considerada um ramo.
Da mesma forma, uma chamada recursiva numa instrução `case` também não seria otimizada.

A função `f x = let y = f (x - 1) in y` não é recursiva de cauda, porque se chama a si própria numa instrução `let`, que não é considerada um ramo.
No entanto, em `f x = let g x = g (x - 1) in g x`, a função `g` é recursiva de cauda e será otimizada, mesmo estando definida numa instrução `let`.

A função `f x = if x > 0 then f (x + 1) else 1 + f x` será otimizada _parcialmente_: o ramo `then` pode ser otimizado, mas o ramo `else` não.
A otimização parcial é o melhor que se consegue em algumas situações, como percorrer estruturas em forma de árvore ou definir funções co-recursivas.
