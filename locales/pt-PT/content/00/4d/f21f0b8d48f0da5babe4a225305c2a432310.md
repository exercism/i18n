# Sobre

O [8th](https://8th-dev.com) é uma linguagem fortemente tipada, derivada do FORTH e baseada em pilha, com sintaxe RPN.

O 8th suporta as plataformas android, ios32, lin64, mac64, rpi32 e win64. O 8th permite-te usar a plataforma que preferires para escreveres e testares o teu código. Com um clique, geras os executáveis *para* qualquer plataforma suportada pelo 8th, *a partir de* qualquer plataforma que ele suporte!

O 8th inclui tudo o que precisas: suporte de GUI multiplataforma, encriptação forte, suporte de bases de dados SQLite, FFI, acesso REST, localização fácil, acesso ao hardware, suporte de JSON, um REPL e muito mais!

A segurança não é um detalhe deixado para o fim no 8th. Foi concebido desde o início para evitar os problemas de segurança de software mais comuns. Trabalhamos continuamente para o tornar ainda mais seguro.

O 8th tem um [fórum](https://8th-dev.com/forum/) e também documentação extensa, incluindo um [manual](https://8th-dev.com/manual.html) e um dicionário com hiperligações de [palavras](https://8th-dev.com/words.html) nativas e de biblioteca. [Compara](https://8th-dev.com/compare.html) o 8th com outras linguagens!


## Introdução rápida para quem usa linguagens "convencionais"

Se vens do C ou do Java, ou da maioria das linguagens mais comuns, podes achar o 8th um pouco estranho. Para te ajudar a seguir o caminho certo, aqui ficam algumas das principais diferenças entre o 8th e as linguagens "convencionais", bem como algumas dicas úteis:

* Como consequência da forma como o intérprete procura os itens, tens de declarar uma var ou uma palavra antes da sua primeira utilização. Se não o fizeres, obténs a exceção can't find ...
    
* Uma var é um contentor com nome para outros itens. Não é o nome do item a que se refere! Por isso, a var x pode conter um array, mas é errado tentar aceder a x como se ele próprio fosse um array, e fazê-lo provoca o lançamento de uma exceção
    
* Não podes declarar uma var dentro (por exemplo, local a) uma palavra; não o tentes! Podes, no entanto, usar w:@ e w:! para acederes a variáveis locais de uma palavra
    
* Tenta escrever as tuas próprias palavras de modo a que possam ser encadeadas com outras palavras. Por exemplo: as "palavras de ficheiro" fazem uma operação sobre um ficheiro e deixam o item do ficheiro na pilha (e talvez outra informação) para a palavra seguinte usar

* Mantém as tuas palavras curtas. Comenta-as. Certifica-te, sobretudo, de comentar o stack-effect, e…

* … testa cada palavra que escreves (de preferência à medida que a escreves ou pouco depois), garantindo que respeita o SED (Stack-Effect Diagram) documentado. Isto ajuda-te a escrever código sem erros. Volta a testar se alterares o SED ou o código

* Consulta as palavras help e apropos para obteres detalhes sobre a ação do SED e os efeitos secundários de qualquer palavra de que não tenhas a certeza
    
* No 8th, uma exceção é um erro fatal e faz com que a aplicação termine (este é o comportamento predefinido). Não esperes "apanhar" uma e tratá-la com eficácia
    
* Não existe um ciclo de compilação e ligação. Em vez disso, o 8th é um motor que primeiro interpreta o teu código e, se necessário, o compila em tempo de execução. Quando corre num dispositivo, o teu código é código nativo da plataforma, não bytecode a correr dentro de uma VM
