# Introdução

Em C++, as declarações estão frequentemente separadas das definições.
As declarações agrupam-se em ficheiros de cabeçalho, e as respetivas implementações ficam em ficheiros de código-fonte.
Podes pensar nos ficheiros de cabeçalho como uma API.
O ficheiro de cabeçalho diz-te _o que_ uma base de código tem para oferecer, sem entrar nos detalhes de _como_.

## Cabeçalho e código-fonte

A extensão de ficheiro mais comum para ficheiros de cabeçalho é `.h`.
Alguns projetos usam `.hpp` ou dispensam completamente a extensão.

As definições ficam num ficheiro `.cpp` à parte.
Para voltar a juntar as partes, o ficheiro de código-fonte começa por _incluir_ o respetivo ficheiro de cabeçalho.

Se quiseres escrever uma biblioteca chamada "quick_math" que oferece uma função "super_root" que queres usar com frequência, os ficheiros teriam este aspeto:

```cpp
// A file named quick_math.h
#pragma once

namespace quick_math {

double super_root(double x, int n);

}  // namespace quick_math
```

```cpp
// A file named quick_math.cpp
#include <cmath>

#include "quick_math.h"

double quick_math::super_root(double x, int n) {
    while (n) {
        x = std::sqrt(x), --n;
    }
    return x;
}
```

Se precisares de incluir um cabeçalho que só a implementação exige, a respetiva linha `#include` só é necessária no ficheiro de código-fonte.
Tudo o que está incluído no cabeçalho também está disponível no ficheiro `.cpp`, como a biblioteca `string` no exemplo abaixo.
**Atenção**: o `;` é necessário depois da declaração no ficheiro de cabeçalho, mas não depois da definição no ficheiro de código-fonte.

## Classes e cabeçalhos

As classes podem tornar-se muito complexas e a sua relação com a divisão entre cabeçalho e código-fonte pode ser confusa.
Uma organização possível é manter todos os detalhes da implementação no ficheiro de código-fonte e todas as declarações e variáveis membro no cabeçalho:

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0);
    void give_water();
    std::string get_name();
    int get_size();
    void start_next_day();
};

}  // namespace robots

#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"

robots::Flower::Flower(std::string name, int size) {
    this->name = "Robotica " + name;
    this->size = size;
}

void robots::Flower::start_next_day() {
    if (!needs_water) {
        ++size;
    }
    needs_water = true;
}

std::string robots::Flower::get_name() { return name; }

int robots::Flower::get_size() { return size; }
```

Quando o cabeçalho serve de visão geral da API, é aí que alguém procura informações como os valores predefinidos.
O valor predefinido do parâmetro `size` do construtor é, por isso, tratado no cabeçalho e não na implementação.
As definições no ficheiro de código-fonte são precedidas pelo namespace `robots` e pelo tipo de classe `Flower`.

Outra opção de organização é uma biblioteca _header only_, que não tem sequer um ficheiro `.cpp`:

```cpp
// A file named robot_flower.h
#pragma once

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0) {
        this->name = "Robotica " + name;
        this->size = size;
    }
    void give_water() { needs_water = false; }
    std::string get_name() { return name; }
    int get_size() { return size; }
    void start_next_day() {
        if (!needs_water) {
            ++size;
        }
        needs_water = true;
    }
};

}  // namespace robots
```

Os projetos podem usar combinações destas organizações e há muita discussão sobre qual será a mais adequada para cada caso de uso.

## Include guards

Deves ter reparado na linha `#pragma once` no ficheiro de cabeçalho de exemplo acima.
Isto chama-se uma include guard, e garante que o conteúdo do ficheiro é incluído apenas uma vez durante a compilação, para evitar erros.
Há outra variação, mais complexa, de uma include guard, que começa com `#ifndef` e termina com `#endif`.
Tem a mesma finalidade e a sua utilização é mostrada no exemplo da classe `Flower` acima.
