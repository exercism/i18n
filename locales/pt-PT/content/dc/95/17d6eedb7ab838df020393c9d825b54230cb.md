# Introdução

Já sabes *construir* uma quotation a partir de peças e executá-la. Uma quotation é apenas uma sequência de código, por isso as palavras de sequência que já conheces também se aplicam a ela:

```factor
USING: kernel math prettyprint quotations sequences ;

{ [ 1 ] [ 2 + ] [ 3 * ] } concat >quotation call .   ! => 9
[ 1 + ] dup append .                                 ! => [ 1 + 1 + ]
```

O `append` junta duas quotations, o `concat` achata um array delas, o `map` transforma dados em quotations e o `>quotation` torna o resultado passível de ser chamado. O `MACRO:` pega nessa mesma competência e transporta-a para o **tempo de compilação**.

## O que é uma macro

Uma definição `MACRO:` parece uma palavra normal, mas o seu corpo é executado *enquanto o teu programa está a ser compilado*, e não enquanto é executado. O corpo tem de deixar **uma quotation** na pilha. O compilador **insere depois essa quotation no local da chamada**: substitui a chamada da macro pelo código que o corpo produziu. Em tempo de execução já não resta nenhuma macro, apenas o código gerado.

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- spliced )
    dup append ;
```

Onde quer que escrevas `[ 1 + ] twice`, o compilador:

1. executa o corpo com `[ 1 + ]` na pilha,
2. `dup append` constrói a quotation `[ 1 + 1 + ]`,
3. insere o seu código, `1 + 1 +`, nesse local.

Assim, uma palavra que chama `twice` compila como se tivesses escrito `1 + 1 +` à mão:

```factor
: inc-twice ( x -- y ) [ 1 + ] twice ;

5 inc-twice .   ! => 7
```

O contraste essencial: uma palavra normal que recebe uma quotation chama-a com `call` em tempo de execução. Uma macro nunca chama nada: entrega ao compilador *código novo* para compilar no seu lugar.

## As entradas têm de ser literais

Como o corpo é executado em tempo de compilação, as entradas de uma macro têm de ser conhecidas *nessa altura*. Têm de ser **literais** no local da chamada: uma quotation `[ … ]`, um número, um array, uma string. Um valor que só existe em tempo de execução não pode ser entregue a uma macro.

```factor
! DOCTEST: SKIP — illustrative call sites, not standalone code
[ 1 + ] twice          ! ok: the quotation is a literal
[ 1 + ] 3 repeat-quot  ! ok: the quotation and the number are literals
```

## O conjunto de ferramentas

O corpo de uma macro é código normal que devolve uma quotation. As palavras que já conheceste fazem a maior parte do trabalho:

| para construir…                        | usa                  |
|----------------------------------------|----------------------|
| `[ A B ]` a partir de `[ A ]` e `[ B ]`| `append`             |
| uma quotation a partir de um array delas | `concat >quotation`|
| uma quotation por cada elemento de uma sequência | `map`, depois `concat >quotation` |

Mais duas palavras, de `sequences` e `kernel`, completam o conjunto.

**`<repetition>`** (em `sequences`) cria uma sequência de `n` cópias de um elemento. O seu efeito na pilha é `( length elt -- repetition )`: a contagem vem primeiro. O resultado é uma sequência *virtual*, por isso achata-a da forma habitual:

```factor
3 [ 1 + ] <repetition> concat >quotation .   ! => [ 1 + 1 + 1 + ]
```

**`curry`** (em `kernel`) acrescenta um valor ao início de uma quotation, produzindo uma nova quotation que empilha esse valor primeiro:

```factor
3 [ + ] curry .          ! => [ 3 + ]
{ 1 2 3 } [ . ] curry .  ! => [ { 1 2 3 } . ]
```

O `curry` é a forma de incorporar um elemento concreto numa quotation: é exatamente o que transforma `{ 10 20 30 }` e `[ + ]` em `[ 10 + ] [ 20 + ] [ 30 + ]`.

## Porque é que isto é mais simples do que parece

Nalgumas linguagens, as macros precisam de sintaxe especial de quote/unquote e de maquinaria extra para evitar colisões de nomes. O Factor não precisa de nada disso: uma quotation já é uma sequência de palavras *resolvidas*; o parser procurou cada `dup`, `+` e `append` quando leu o `[ … ]`. Assim, o corpo de uma macro é apenas a manipulação de sequências que já fazes, que por acaso devolve uma quotation.

## Um primo próximo: `$[ … ]`

Uma macro devolve uma quotation para ser inserida numa *chamada*. Quando, em vez disso, queres um *valor* simples calculado em tempo de análise, `$[ code ]` executa `code` enquanto o ficheiro está a ser lido e incorpora o resultado no código-fonte como literal:

```factor
! DOCTEST: SKIP — compile-time value, shown for contrast
USING: calendar literals ;

CONSTANT: build-time $[ now ]
```

O `$[ … ]` vem do vocabulário [`literals`][literals], que reúne as palavras para interpolar resultados de tempo de análise em literais. É mencionado por uma questão de completude. Os quatro stencils que vais escrever, `twice`, `repeat-quot`, `compose-many` e `each-literal`, são todos declarações `MACRO:`.
