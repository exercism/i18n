# Introdução

No Go 1.18, o Go passou a suportar **genéricos**.
Os genéricos permitem escrever funções e estruturas de dados que funcionam com tipos diferentes sem duplicar código.

## Porquê os genéricos?

Em Go, as funções e os tipos trabalham normalmente com tipos concretos, como `int` ou `string`.
Antes dos genéricos, tinhas duas opções para suportar vários tipos.
Primeiro, podias escrever várias funções com nomes diferentes, como `SumInts` e `SumFloats`.
Esta abordagem cria código duplicado difícil de manter.
Segundo, podias usar a interface vazia `any` (`interface{}`).
No entanto, a interface vazia elimina as verificações de tipo em tempo de compilação e obriga a fazer asserções de tipo em tempo de execução.
Os genéricos resolvem este problema ao garantir segurança de tipos e evitar código duplicado.

## Funções genéricas

Defines uma função genérica acrescentando **parâmetros de tipo** entre parênteses retos `[...]` a seguir ao nome da função.
Eis um exemplo de uma função genérica que devolve uma slice invertida:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

Neste exemplo, `T` é um parâmetro de tipo.
Podes pensar em `T` como um marcador para um tipo real.
A palavra-chave `any` dentro dos parênteses retos é uma **restrição de tipo**.
A restrição indica ao compilador que tipos são permitidos para `T`.
Aqui, `any` significa que `T` pode ser qualquer tipo.

### Chamar funções genéricas

Podes chamar uma função genérica passando o tipo concreto entre parênteses retos.
Esse tipo concreto chama-se **argumento de tipo**.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

Na maioria dos casos, o compilador de Go consegue detetar automaticamente o tipo a partir dos argumentos da função.
Esta funcionalidade chama-se **inferência de tipos**.
Com a inferência de tipos, não precisas de escrever o argumento de tipo entre parênteses retos.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

Neste exemplo, o compilador vê que `words` é uma slice de strings, por isso infere que `T` é `string`.

## Restrições de tipo

Todos os parâmetros de tipo têm de ter uma restrição.
Uma restrição especifica que tipos podes usar como argumentos de tipo.
Uma restrição também determina as operações que podes realizar sobre valores desse tipo.

### A restrição `any`

A restrição `any` permite qualquer tipo.
Em Go, `any` é um alias da interface vazia `interface{}`.
Como `any` permite todos os tipos, a função só pode realizar operações que funcionem com todos os tipos de Go.
Por exemplo, se tiveres dois valores `any` que contêm slices, não os podes comparar com `==`, porque as slices não podem ser comparadas com `==`.

### A restrição `comparable`

O Go tem uma restrição incorporada chamada `comparable`.
A restrição `comparable` permite qualquer tipo que suporte os operadores `==` e `!=`.
Os tipos comparáveis incluem Boolean, números, strings, apontadores, canais e structs ou arrays compostos por tipos comparáveis.

Eis um exemplo de uma função que verifica se uma slice contém um determinado elemento:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Como `T` usa a restrição `comparable`, usar `elem == target` é válido.
Se substituíres `comparable` por `any`, o compilador dá um erro.

### Restrições personalizadas com conjuntos de tipos em interfaces

A partir do Go 1.18, as interfaces podem definir conjuntos de tipos além de métodos.
Podes usar o caráter de barra vertical `|` para listar os tipos permitidos numa interface.

```go
type Number interface {
    int | int64 | float64
}
```

Agora já podes usar `Number` como restrição de uma função:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Como todos os tipos de `Number` suportam o operador `*`, o Go permite `value * 2` dentro da função.

### A aproximação do tipo subjacente `~`

Por vezes crias uma definição de tipo personalizada com base num tipo primitivo:

```go
type MyInt int
```

A restrição `Number` definida acima só permite exatamente os tipos `int`, `int64` e `float64`.
Se passares um valor `MyInt` a `Double`, o compilador dá um erro, porque `MyInt` não corresponde a `int`.
Para permitires qualquer tipo cujo tipo subjacente seja `int`, acrescenta um til `~` antes do tipo:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

Agora já podes usar `Double` com valores do tipo `MyInt`.

### A restrição `cmp.Ordered`

A biblioteca padrão disponibiliza a restrição `cmp.Ordered` no [pacote `cmp`][doc-cmp].
A restrição `cmp.Ordered` permite qualquer tipo que suporte os operadores de comparação `<`, `<=`, `>` e `>=`.

## Tipos genéricos

Também podes usar parâmetros de tipo para definir tipos genéricos, como structs.
Eis um exemplo de uma estrutura de dados `Stack` genérica:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Quando declaras uma variável de um tipo genérico, tens de indicar o argumento de tipo entre parênteses retos:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

A inferência de tipos só funciona com funções genéricas.
Tens sempre de especificar o argumento de tipo quando crias valores de um tipo genérico.

## Quando usar genéricos

Os genéricos são uma funcionalidade poderosa, mas não precisas de os usar em todos os problemas.

Usa genéricos nestas situações:
- Estás a construir estruturas de dados, como árvores, listas ligadas ou caches, que funcionam com qualquer tipo de elemento.
- Estás a escrever funções utilitárias que operam sobre slices ou maps de qualquer tipo, como filtrar, ordenar ou procurar.
- Precisas da mesma implementação para vários tipos e queres segurança de tipos em tempo de compilação.

Usa antes interfaces nestas situações:
- Interessa-te o comportamento e os métodos, e não o tipo de dados subjacente.
  Por exemplo, se queres ler e processar dados de origens de vários tipos (ficheiros, rede, TTY), usas `func Process(src io.Reader)` em vez de `func Process[T](src T)`.
- Tipos diferentes exigem implementações de métodos diferentes para fazer o seu trabalho.
