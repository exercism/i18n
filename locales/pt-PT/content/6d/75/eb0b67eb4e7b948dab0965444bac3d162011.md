# Introdução

Quando fazemos correspondência de padrões com um valor em Gleam, temos de garantir que os padrões correspondem a todos os valores possíveis do tipo; caso contrário, o código não compila.

Esta função deve ser rejeitada, pois não trata o caso em que a lista está vazia:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Na maioria das vezes, nos programas em Gleam queremos tratar todos os casos possíveis, mas em alguns programas, como protótipos e scripts rápidos, podemos querer concentrar-nos apenas nos casos que correm bem e não escrever código para os outros casos. É aqui que entra o `let assert` do Gleam.

Com as let assertions, um padrão pode corresponder apenas a alguns dos valores possíveis de um tipo e, se o padrão não corresponder a um valor, o programa rebenta. Com `let assert`, podemos escrever a função acima assim:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

As bibliotecas de Gleam nunca devem usar let assertions, pois podem fazer o programa rebentar. Em vez disso, devem usar o tipo `Result` e deixar que o programador da aplicação decida como tratar os erros.
