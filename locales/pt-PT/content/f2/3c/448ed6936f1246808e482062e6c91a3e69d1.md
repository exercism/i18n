# Ignorar

## Opções adicionais da linha de comandos do jq

Vais reparar que os testes usam opções extra para o `jq`.

```sh
run jq -s -R -c -f minesweeper.jq << 'END_INPUT'
```

O que são?

- `-s`

  Isto é o modo "slurp".
  Em vez de tratar a entrada como um fluxo de objetos JSON,
  toda a entrada é recolhida para um array.

  ```sh
  $ seq 5 | jq -c '.'
  1
  2
  3
  4
  5
  $ seq 5 | jq -s -c '.'
  [1,2,3,4,5]
  ```

- `-R`

  Já deves ter visto o `-r`, que produz strings "raw" (sem aspas).
  Esta opção faz o contrário.
  Cada linha da entrada é considerada uma string.

  Dois exemplos:

  ```sh
  $ seq 5 | jq -R -c .
  "1"
  "2"
  "3"
  "4"
  "5"

  $ echo 42 | jq '. * 2'      # input is a JSON number
  84
  $ echo 42 | jq -R '. * 2'   # input is a JSON string
  "4242"
  ```

Quando juntas estas duas opções, _não_ obtens um array de strings:
obtens toda a entrada como uma única string, incluindo os carateres de nova linha que terminam cada linha.

```sh
$ seq 5 | jq -s -R -c .
"1\n2\n3\n4\n5\n"
```

Lidar com isto faz parte do desafio deste exercício.
