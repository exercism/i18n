# Introdução

Todos os erros em Elixir implementam o _Exception Behaviour_. Tal como o _Access Behaviour_, o _Exception Behaviour_ define funções de callback que um módulo tem de implementar para cumprir o contrato de software que o behaviour exige. Depois de um erro estar definido, este tem as seguintes propriedades:

- O nome do módulo define o nome do erro.
- O módulo define uma estrutura de erro.
- A estrutura terá um campo `:message`.
- O módulo pode ser usado com `raise/1` e `raise/2` para lançar o erro pretendido

O _Exception Behaviour_ também especifica dois callbacks: `message/1` e `exception/1`. Se não forem implementados, serão usadas implementações predefinidas. `message/1` transforma a estrutura de erro numa mensagem legível quando é chamado com `raise`. `exception/1` permite acrescentar contexto adicional à mensagem quando é chamado com `raise/2`

## Definir uma exceção

Para definir uma exceção a partir de um módulo de erro, usamos a macro `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

## Usar exceções

Os erros definidos podem ser usados como um erro incorporado, com `raise/1` ou `raise/2`.

- `raise/1` lança um erro específico pelo nome do módulo ou, se o argumento for uma string, lança um `RuntimeError` com essa string como mensagem.
- `raise/2` lança um erro específico pelo nome do módulo e aceita um argumento de atributos, que é usado para obter o erro com a mensagem adequada.
