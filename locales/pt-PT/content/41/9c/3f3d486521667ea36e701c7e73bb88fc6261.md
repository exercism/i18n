# Introdução

`Complex numbers` não são complicados.
Só precisam de um nome menos assustador.


São tão úteis, sobretudo na engenharia e na ciência, que o Python inclui [`complex`][complex] como tipo numérico padrão, a par dos inteiros ([`int`s][ints]) e dos números de vírgula flutuante ([`float`s][floats]).


Um valor `complex` em Python é essencialmente um par de números de vírgula flutuante:

```python
>>> my_complex = 5.443+6.77j
(5.443+6.77j)
```

Estas chamam-se as partes "real" e "imaginária".
Podes ter ouvido dizer que "`i` (ou `j`) é a raiz quadrada de -1".
Para já, isto significa apenas que a parte imaginária, _por definição_, satisfaz a igualdade `1j * 1j == -1`.
É uma ideia simples, mas conduz a consequências matemáticas interessantes.

Em Python, a parte "imaginária" designa-se com `j` (_não `i`, como vês nos manuais de matemática_), e
o `j` tem de vir imediatamente a seguir a um número, para que o Python não o interprete como o nome de uma variável:


```python
>>> j
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
NameError: name 'j' is not defined

>>> 1j
1j

>>> type(1j)
<class 'complex'>
```


Há duas formas comuns de criar números complexos.

1) O construtor [`complex(real, imag)`][complex] recebe dois parâmetros `float`:

    ```python
    >>> z1 = complex(1.5, 2.0)
    >>> z1
    (1.5+2j)
    ```

    O construtor também consegue interpretar uma string que lhe passes.
    Tem a limitação curiosa de falhar se a string contiver espaços.

    ```python
    >>> complex('4+2j')
    (4+2j)
    
    >>> complex('4 + 2j')
    Traceback (most recent call last):
      File "<stdin>", line 1, in <module>
    ValueError: complex() arg is a malformed string
    ```


2) O número complexo pode ser indicado como o literal `<real part> + <complex part>j`, ou apenas `<complex part>j` se a parte real for zero:


    ```python
    >>> z2 = 2.0 + 1.5j
    >>> z2
    (2+1.5j)
    ```
    O resultado final é idêntico ao de usar o construtor `complex()`.


## Aritmética

A maior parte dos [`operators`][operators] usados com números de vírgula flutuante e inteiros também funciona com números complexos.

A divisão inteira _**não**_ é possível com números complexos, por isso os operadores `//` e `%` e a função `divmod()` falham com o tipo de número complexo.

Explicar as regras da multiplicação e da divisão de números complexos está fora do âmbito deste conceito (_e é pouco provável que tenhas de fazer essas operações "à mão" muitas vezes_).

Qualquer introdução [matemática][math-complex] ou de [engenharia eletrotécnica][engineering-complex] aos números complexos aborda estes cenários, caso queiras aprofundar o tema.

A biblioteca padrão do Python tem um módulo [`math`][math-module] cheio de funcionalidades úteis para trabalhar com números reais, e o módulo [`cmath`][cmath] é o equivalente para trabalhar com números complexos.
