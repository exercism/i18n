# Structs

As structs reúnem um conjunto fixo e heterogéneo de dados numa única unidade. Em Rust, as structs têm estas propriedades:

- Cada tipo de struct tem um nome específico.
- Cada membro de uma struct chama-se **campo**.
- Cada campo de uma struct tem um nome específico.
- A visibilidade é controlada ao nível do campo: cada campo pode ser, de forma independente, público, privado ou outra coisa[^1].

# Visão geral das structs

As structs definem-se com a palavra-chave `struct`, seguida do nome do tipo que a struct descreve.
A seguir ao nome podem vir chavetas (para uma struct normal), parênteses (para uma struct de tuplo) ou um ponto e vírgula (para uma struct unitária).

```rust
struct Item {}
```

Em seguida, acrescentam-se tipos adicionais ao corpo da struct como _campos_ da struct, cada um com o seu próprio tipo:

```rust
struct Item {
    name: String,
    weight: f32,
    worth: u32,
}
```

Por fim, podes definir métodos nas structs dentro de um bloco `impl`:

```rust
impl Item {
    // initializes and returns a new instance of our Item struct
    fn new() -> Self {
        todo!()
    }
}
```

# Variedades de structs

As structs existem em três variedades: structs com campos nomeados (structs normais), structs de tuplo e structs unitárias.

As structs são muito parecidas com **tuplos**. Na verdade, a única diferença entre structs e tuplos tem a ver com o que é anónimo. A forma geral é esta:

- As structs têm nome e têm campos nomeados:

  ```rust
  struct Foo {
      bar: Bar,
      bat: Bat,
  }
  ```

  Acede-se aos campos pelo nome:

  ```rust
  let bar = foo.bar;
  ```

- As structs de tuplo têm nome e têm campos anónimos:

  ```rust
  Foo(Bar, Bat)
  ```

  Acede-se aos campos por desestruturação ou por índice numérico:

  ```rust
  // unpacking
  let (bar, bat) = foo;
  ```

  ```rust
  // numeric index
  let bar = foo.0;
  let bat = foo.1;
  ```

- Os tuplos são anónimos e têm campos anónimos:

  ```rust
  (Bar, Bat)
  ```

  Tal como nas structs de tuplo, acede-se aos campos por desestruturação ou por índice numérico.

- As structs anónimas são, como o nome indica, anónimas, mas com campos nomeados. Podes conhecê-las de outras linguagens, como Go ou Java. Não existem em Rust; considera-se idiomático usar um tuplo em vez disso.

# Tipos de tamanho zero

As structs podem ter tantos campos quantos forem necessários, ou tão poucos. Daí decorre que é legal uma struct ter zero campos. Uma struct com zero campos chama-se **tipo de tamanho zero** e tem um tratamento especial por parte do compilador: os tipos de tamanho zero (abreviados frequentemente como **ZSTs**) nunca ocupam espaço na stack nem no heap, mesmo quando poderias esperar que ocupassem. Por exemplo, `Box<T>` não aloca memória no heap se `T` for um ZST.

Podes usar a sintaxe de struct normal ou de struct de tuplo quando escreves um ZST:

```rust
// declaration
struct Foo {}
// instantiation
let foo = Foo {}
```

```rust
// declaration
struct Foo();
// instantiation
let foo = Foo();
```

Há também uma forma abreviada para os ZSTs:

```rust
// declaration
struct Foo;
// instantiation
let foo = Foo;
```

Normalmente, quando escreves um ZST, dá-se preferência à forma abreviada, porque não podes misturar estilos: o estilo usado para declarar um ZST[^2] é o mesmo estilo necessário para o instanciar.

Depois de toda esta conversa sobre a sintaxe dos ZSTs, vamos falar sobre porque razão quererias sequer uma coisa destas. Um ZST não pode guardar dados, mas é ótimo para implementar traits.

[^1]: [Estes documentos](https://doc.rust-lang.org/reference/visibility-and-privacy.html) explicam algumas opções de visibilidade menos usadas.
[^2]: Este é um caso particular de uma regra geral: o estilo usado para declarar qualquer tipo de struct é o mesmo estilo necessário para o instanciar.
