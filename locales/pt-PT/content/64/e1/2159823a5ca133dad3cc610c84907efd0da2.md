# Introdução

Os `Complex numbers` não são complicados.
Só precisam de um nome menos alarmante.

São tão úteis, especialmente em engenharia e ciência, que o R inclui os números complexos como tipos atómicos padrão, a par de integer, double, logical, character e raw.

## Noções básicas

Um número `complex` em R é um único valor.
No entanto, na prática, pode ser visto como um par de números.
Chamam-se partes "real" e "imaginária", por razões históricas infelizes.
Mais uma vez, é melhor concentrarmo-nos na simplicidade subjacente e não nos nomes estranhos.

Para criar números complexos a partir de dois números reais, basta adicionar o sufixo `i` à parte imaginária.

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

Para criar um número complexo a partir de variáveis reais, a sintaxe acima não funciona.
Escrever `r + imi` confunde o analisador sintático, levando-o a pensar que `imi` é um nome de variável (inexistente).

Ou multiplica a parte imaginária por `1i` ou usa a função [`complex()`][ref-complex]:

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

Talvez te perguntes: porque `i` e não `j`?

A maioria dos engenheiros prefere `j`.
A maioria dos cientistas e matemáticos prefere a notação matemática `i` para _imaginário_, mas essa notação entra em conflito com o uso de `i` para significar _corrente_ em Engenharia Eletrotécnica.

O R escolheu `i`, o Python escolheu `j` e a Julia evitou a polémica ao escolher `im`.
Tem cuidado ao alternar entre linguagens de programação [CTEM][wiki-STEM].

Para aceder individualmente às partes de um número complexo:

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

Qualquer das partes pode ser zero e os matemáticos podem então falar do número ser "totalmente real" ou "totalmente imaginário".
No entanto, continua a ser um número complexo em R.

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

Talvez já tenhas ouvido que "`i` (ou `j`) é a raiz quadrada de -1".

Para já, tudo isto significa apenas que a parte imaginária _por definição_ satisfaz a seguinte igualdade:

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

É uma ideia simples, mas conduz a consequências interessantes.

## Aritmética

A maioria dos operadores usados com números de vírgula flutuante e inteiros também funciona com números complexos:

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

## Funções

A maioria das funções matemáticas funciona com valores de entrada complexos.

Existem várias funções, para além de `Re()` e `Im()`, com particular relevância para números complexos.

- `Conj()` simplesmente inverte o sinal da parte imaginária de um número complexo (_de + para - ou vice-versa_).
  - Devido à forma como a multiplicação complexa funciona, isto é mais útil do que podes pensar.
- `abs(<complex number>)` tem a garantia de devolver um número real sem parte imaginária (a sua "magnitude"), e `Mod(<complex number>)` é um sinónimo.
- `Arg(<complex number>)` devolve o ângulo de fase em radianos.

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
