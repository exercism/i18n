# Introdução

Em Ruby, tal como em muitas linguagens, as exceções são uma forma de lidar com acontecimentos inesperados. Um tratamento adequado das exceções é importante para evitar que o teu programa vá abaixo.

Quando é lançada uma exceção, seja porque a lançamos explicitamente, seja porque o intérprete de Ruby a lança, o programa desvia-se do funcionamento normal e acaba por terminar com uma mensagem de erro:

```ruby
raise ArgumentError.new("Something went wrong!")
=> Traceback (most recent call last):
.
.
ArgumentError (Something went wrong!)
```

```ruby
1/0
=> Traceback (most recent call last):
.
.
ZeroDivisionError (divided by 0)
```

Se quisermos travar este processo de encerramento, precisamos de reagir à exceção. A isto chama-se fazer rescue de uma exceção:

```ruby
begin
  # ...any code that raises an exception
rescue
  puts 'Got an exception'
end
```

Este programa não vai abaixo e imprime «Got an exception». Em vez de terminar, o Ruby executa o código do bloco rescue, que imprime uma mensagem.

Tal como tudo em Ruby, as exceções também são objetos e normalmente contêm dados sobre a exceção. É assim que podemos obter o objeto da exceção:

```ruby
begin
  # ...any code that raises an exception
rescue => e
  puts "Exception class: #{ e.class.name }"
  puts "Exception Message:#{e.message}"
end
```

Em Ruby também é possível lançar as tuas próprias exceções. Por exemplo:

```ruby
begin
  raise ArgumentError.new("Invalid argument")
rescue ArgumentError => e
  puts e.message
end
```

A exceção anterior é uma das exceções incorporadas no Ruby, mas também é possível definir exceções personalizadas e lançá-las:

```ruby
class CustomError < StandardError
end

raise CustomError.new("Something went wrong")
```
