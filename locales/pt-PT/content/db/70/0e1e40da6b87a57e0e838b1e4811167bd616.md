# Apêndice às instruções

## Dicas

Um dos principais aspetos da Programação Funcional é ter funções sem efeitos secundários, ou seja, não teres de te preocupar com os objetos ocultos que uma função alterou.  

Com a Programação Reativa, em vez de haver um component a procurar trabalho ativamente, é o trabalho que é empurrado para o component. Isto é semelhante aos callbacks, mas a um nível muito mais elevado, com abstrações mais poderosas. Muitas vezes, a Programação Reativa é usada em conjunto com a Programação Funcional.

Neste exercício, vamos usar o [RxJava](https://github.com/ReactiveX/RxJava), uma biblioteca bem conhecida de Programação Reativa com uma API de Java.

O contexto simulado deste exercício é uma aplicação que recebe duas entradas:

- as novas palavras a adivinhar, vindas de algum motor de jogo,  
- as letras escolhidas pelo jogador.  

 Essas duas entradas são implementadas com [Observables](http://reactivex.io/documentation/observable.html), através da classe [io.reactivex.Observable](http://reactivex.io/RxJava/2.x/javadoc/io/reactivex/Observable.html).
 Basicamente, podes subscrever um `Observable` para "reagir" aos valores que são produzidos algures. Por exemplo, o motor de jogo envia novas palavras quando deteta que começou um novo jogo, ou os eventos de teclado geram entradas de letras.  
 Mas muitos frameworks reativos oferecem abstrações poderosas, como o [`map`](http://reactivex.io/documentation/operators/map.html), que te permite alterar a entrada recebida, ou o [`combine`](http://reactivex.io/documentation/operators/combinelatest.html), que te permite juntar um ou mais `Observable`s.

A classe `Output` é o resultado esperado do processamento do exercício, permitindo que um front-end
apresente o estado completo do jogo sem lhe exigir qualquer forma de armazenamento, o que a torna
também funcional.  
Neste exercício, tens de encontrar uma forma de usar as duas entradas para gerar esta saída na forma de um `Observable`.
