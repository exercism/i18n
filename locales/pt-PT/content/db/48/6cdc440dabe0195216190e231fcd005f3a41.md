# Sobre

Classes como `LocalDate` e `LocalDateTime` descrevem um _ponto_ no tempo.
O pacote `java.time` também tem duas classes que descrevem uma _quantidade_ de tempo:

- [`Period`][period-docs] é uma quantidade de tempo baseada em datas, em anos, meses e dias, como "2 meses e 5 dias".
- [`Duration`][duration-docs] é uma quantidade de tempo baseada em horas, minutos, segundos, milissegundos e nanossegundos, como "1 hora e 30 minutos".

A diferença é importante porque as unidades de calendário não têm uma duração fixa.
Um mês pode ter 28, 29, 30 ou 31 dias, por isso "um mês" não corresponde a um número fixo de segundos.
`Period` segue o calendário, enquanto `Duration` mede tempo exato.

| | `Period` | `Duration` |
| --- | --- | --- |
| Armazena | anos, meses e dias | segundos e nanossegundos |
| Usado com | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

Ambas as classes são imutáveis.
Métodos como `plusDays()` ou `multipliedBy()` devolvem uma _nova_ instância e deixam a original inalterada.

## `Period`

### Criar um período

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

O resultado de `toString()` usa o [formato de duração ISO-8601][iso-8601-durations]: `P` seguido do número de anos (`Y`), meses (`M`) e dias (`D`).
Não há semanas num `Period`: `Period.ofWeeks(2)` é armazenado como 14 dias.
O mesmo formato pode ser lido com `Period.parse()`:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### Adicionar um período a uma data

Um período é adicionado ou subtraído de uma data com `plus()` e `minus()`:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

Um período pode ser adicionado a um `LocalDateTime` da mesma forma, e a hora do dia mantém-se:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

Um `Instant` não tem calendário, por isso só lhe pode ser adicionado um período de dias.
Um período com anos ou meses lança uma exceção:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

Os anos são adicionados primeiro, depois os meses e, por fim, os dias.
Quando adicionar anos ou meses cai num dia que não existe, o resultado recua para o último dia válido desse mês:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

Isto também significa que adicionar um período e voltar a subtraí-lo nem sempre devolve a data original:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### O período entre duas datas

`Period.between()` devolve o período de uma data (inclusive) até outra (exclusive).
O mesmo resultado está disponível com `LocalDate.until()`:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

As partes de um período estão disponíveis através de `getYears()`, `getMonths()` e `getDays()`.
Estas partes são independentes entre si: `getDays()` devolve apenas a parte dos dias, não o número total de dias.
`toTotalMonths()` devolve os anos e os meses combinados como um número de meses, mas não há nenhum método para o número total de dias, porque isso depende dos meses envolvidos.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### Normalizar um período

Um período criado com um método de fábrica mantém as suas unidades exatamente como foram indicadas, e `equals()` compara as unidades uma a uma.
`normalized()` converte meses em anos, mas deixa os dias como estão:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## Contar unidades com `ChronoUnit`

Para obter o número total de uma única unidade entre dois pontos no tempo, usa o método `between()` numa das constantes de [`ChronoUnit`][chronounit-docs]:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

Só são contadas unidades completas, e o resultado é negativo quando o segundo argumento é anterior ao primeiro:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit` também funciona com unidades baseadas em tempo e com valores de data e hora:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### Criar uma duração

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

Na notação ISO-8601, o `T` separa a parte da data da parte da hora.
Uma `Duration` não tem parte de data, por isso o seu `toString()` começa sempre por `PT`.
`Duration.ofDays()` considera um dia como exatamente 24 horas.

Uma duração também pode ser lida com `Duration.parse()`:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### Adicionar uma duração a uma hora

Uma duração é adicionada ou subtraída de um `LocalTime`, de um `LocalDateTime` ou de um `Instant` com `plus()` e `minus()`:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

Um `LocalTime` dá a volta à meia-noite, como mostra o último exemplo.

Um `LocalDate` não tem hora, por isso não pode ser combinado com uma `Duration`:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### A duração entre dois momentos

`Duration.between()` devolve a quantidade exata de tempo entre dois momentos ou dois valores de data e hora:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()` não aceita dois valores `LocalDate`, porque uma data não tem segundos para medir:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

Para datas, usa antes `Period.between()` ou `ChronoUnit.DAYS.between()`.

### Converter uma duração

Os métodos `toXxx()` convertem uma duração numa quantidade _total_ de uma única unidade, arredondada para baixo:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

Os métodos `toXxxPart()` dividem uma duração nas suas partes, como num relógio:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()` para em 23, porque as horas acima disso são contadas por `toDaysPart()`.

### Comparar e calcular com durações

As durações podem ser comparadas com `compareTo()` e verificadas com `isZero()` e `isNegative()`:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

Também suportam operações aritméticas, como `plus()`, `minus()`, `multipliedBy()` e `dividedBy()`:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` ou `Duration`?

Para um `LocalDate` ou um `LocalTime`, a escolha é feita por ti: uma data não tem hora para medir, e uma hora não tem calendário.
Um `LocalDateTime` tem ambos, mas não tem fuso horário, por isso adicionar `Period.ofDays(1)` ou `Duration.ofDays(1)` dá o mesmo resultado.
A diferença torna-se visível com os fusos horários.
Quando os relógios avançam para a hora de verão, um dia de calendário tem apenas 23 horas:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

Adicionar um `Period` de um dia mantém a hora do dia, enquanto adicionar uma `Duration` de um dia acrescenta exatamente 24 horas.
Usa um `Period` para quantidades que as pessoas pensam em termos de calendário ("a mesma hora no mês seguinte") e uma `Duration` para tempo decorrido ("o bilhete de estacionamento é válido durante 2 horas").
