# Números exatos

| Tipo | Guarda | Limite |
| --- | --- | --- |
| `INT` | números inteiros | exatamente 32 bits |
| `FLTD` | frações | aproximado |
| `INTI` | números inteiros | memória |
| `RAT` | frações | exato |

## INTI

```sather
   #INTI(42)
   #INTI("123456789012345678901234567890")
   a + b, a - b, a * b, a / b
   a < b, a = b
   #INTI(25).factorial
   #INTI(48).gcd(#INTI(18))       -- 6
   #INTI(2).pow(100)
   big.str
   small.int                      -- back to an INT, if it fits
```

A `/` entre dois `INTI`s é divisão inteira, descartando o resto, exatamente
como acontece com um `INT`.

O `.int` sobre um valor demasiado grande para um `INT` não assinala o
problema. Verifica primeiro se isso é relevante.

## RAT

```sather
   #RAT(1, 3)
   #RAT(6)                        -- from a whole number
   a + b, a - b, a * b, a / b
   a < b, a = b
   r.is_int                       -- is it a whole number?
   r.is_zero, r.is_pos, r.is_neg
   r.abs, r.negate
   r.floor                        -- an INTI, rounded down
   r.str
```

Um `RAT` está sempre na forma irredutível e tem sempre o sinal no numerador:
`#RAT(1, -2)` é `-1/2`. Dois `RAT`s são iguais exatamente quando representam a
mesma fração, por isso o `=` faz o que queres. É esta a diferença em relação ao
`FLTD`.

O `RAT` é construído sobre o `INTI`, por isso o numerador e o denominador
também não têm limite de tamanho. Somar muitas frações com denominadores
diferentes fá-las crescer, porque cada soma multiplica os denominadores antes
de reduzir.

O `ceiling` está declarado, mas levanta "not implemented". Usa o `floor` e
ajusta.

## Como escolher

Recorre ao `INTI` quando uma contagem pode ultrapassar os dois mil milhões:
fatoriais, potências, combinações, totais acumulados ao longo do tempo.

Recorre ao `RAT` quando as frações têm de ser exatas e os denominadores são
relativamente pequenos: quotas, probabilidades, valores de notas musicais, tudo
o que, de outro modo, acumularia erros de arredondamento.

Por omissão, não recorras a nenhum dos dois. `INT` e `FLTD` são muito mais
rápidos, e a maior parte da aritmética não precisa de mais do que isso.

Para dinheiro, nenhum dos dois é a resposta habitual: conta os cêntimos
inteiros num `INT`.
