# Prepara-te para o lançamento

Antes de estares pronto para lançar o teu percurso, certifica-te de que as seguintes tarefas estão concluídas.

## Pede o ícone do percurso

Para que seja desenhado um ícone para o site, abre uma nova issue no repositório [exercism/website-icons](https://github.com/exercism/website-icons/issues), respondendo às seguintes perguntas:

- A linguagem tem um logótipo oficial? Se sim
  - inclui uma ligação para um exemplo
  - lista os requisitos de atribuição e os direitos concedidos para a utilização desse logótipo
- A linguagem tem um logótipo não oficial? Se sim
  - explica de que formas as pessoas usam o logótipo não oficial
  - inclui uma ligação para um exemplo
  - lista os requisitos de atribuição desse logótipo

## Adiciona a documentação do percurso

Adiciona os seguintes documentos do percurso:

- `docs/ABOUT.md`: uma breve introdução à linguagem.
- `docs/INSTALLATION.md`: descreve o que o aluno precisa de instalar para poder trabalhar no percurso no seu sistema local com a CLI.
- `docs/LEARNING.md`: ligações para recursos de aprendizagem.
- `docs/RESOURCES.md`: ligações para recursos úteis.
- `docs/TESTS.md`: descreve tudo o que está relacionado com a execução dos testes no percurso.

Estes documentos ajudam o aluno a começar a trabalhar no percurso e a conhecer o percurso e a sua linguagem.
Consulta a [documentação sobre os docs](/docs/building/tracks/docs) para mais informações.

## Adiciona a documentação dos exercícios

Adiciona os seguintes documentos dos exercícios:

- `exercises/shared/.docs/help.md`: contém instruções específicas do percurso sobre como obter ajuda
- `exercises/shared/.docs/tests.md`: contém instruções específicas do percurso sobre como executar os testes

## Adiciona um excerto de código

Adiciona um excerto de código ao ficheiro `docs/SNIPPET.txt`.
Este excerto dá uma ideia visual de como é a sintaxe da linguagem.
Consulta a [documentação sobre os docs](/docs/building/tracks/docs) para mais informações.

## Atualiza os metadados

Os metadados do percurso são definidos no [ficheiro config.json](/docs/building/tracks/config-json).
As seguintes propriedades devem ser atualizadas:

- `language`: a linguagem do percurso (por exemplo, `"C#"`). O seu comprimento tem de ser <= 255
- `slug`: a linguagem do percurso como uma string em minúsculas e em kebab-case (por exemplo, `"csharp"`). O seu comprimento tem de ser <= 255
- `blurb`: uma breve descrição da linguagem. O seu comprimento tem de ser <= 400
- `online_editor`: um objeto que descreve as definições usadas no editor online:
  - `indent_style`: `"space"` ou `"tab"`
  - `indent_size`: o tamanho da indentação como um número inteiro (por exemplo, `4`)
  - `highlightjs_language`: o identificador da linguagem para o Highlight.js (consulta a [lista completa de identificadores](https://github.com/highlightjs/highlight.js/blob/main/SUPPORTED_LANGUAGES.md)). Se não houver suporte do Highlight.js, este campo pode ser omitido.
- `key_features`: as características principais da linguagem, que descrevem de forma sucinta as suas funcionalidades mais importantes. Para mais informações, consulta a [documentação sobre as características principais](/docs/building/tracks/config-json#h-key-features).
- `tags`: define as etiquetas que se aplicam a este percurso, o que permite que seja pesquisado no site. Para mais informações e para a lista de etiquetas suportadas, consulta a [documentação sobre as etiquetas](/docs/building/tracks/config-json#h-tags).
