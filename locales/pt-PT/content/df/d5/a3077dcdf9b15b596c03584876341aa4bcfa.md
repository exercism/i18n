# Introdução

Quase todos os programas em Factor são uma sequência de palavras que consomem e produzem valores na *pilha de dados*. Quando as entradas e as saídas se alinham bem, o código lê-se da esquerda para a direita sem complicações. Quando não se alinham, recorres às *palavras de reorganização*, e o código fica confuso num instante.

Este exercício guia-te pela solução habitual do Factor: os combinators.

## Palavras de reorganização

As palavras de reorganização mais comuns vivem no [`kernel`][kernel]:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

Já deves ter usado `dup` e `swap`. O `over` faz uma cópia do *segundo* elemento a contar do topo, o que dá jeito quando o mesmo valor de entrada tem de alimentar dois cálculos:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

Isso serve bem para um uso. Mas, encadeadas, as sequências de `dup`, `swap`, `over` e `rot` tornam-se rapidamente ilegíveis.

## `keep`: preservar a entrada

O `keep` (no [`kernel`][kernel]) invoca uma quotation sobre o valor no topo da pilha, mas deixa o valor original acima do resultado:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

Isto substitui o padrão de `dup` seguido de algo e depois de uma reorganização: em qualquer sítio onde escreverias `dup something swap`, basta dizer `[ something ] keep`.

## `bi`: duas funções sobre um valor de entrada

O `bi` (no [`kernel`][kernel]) aplica *duas* quotations ao mesmo valor, deixando ambos os resultados na pilha:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

Sem o `bi` escreverias `dup sq swap neg`, o que ainda é legível para duas operações, mas complicado para três.

## `tri` e `cleave`: várias funções sobre um valor de entrada

O `tri` estende o `bi` a três quotations:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

O `cleave` (no [`combinators`][combinators]) é a mesma ideia para um *array* com qualquer número de quotations:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

A quotation vazia `[ ]` funciona como a identidade, o que é útil quando uma das posições do cartão de corte deve ser o próprio valor de entrada.

## `dip` e `2dip`: operar por baixo

O `dip` (no [`kernel`][kernel]) invoca uma quotation sobre os valores *por baixo* do topo da pilha, deixando o topo intacto. O `2dip` faz o mesmo, mas protege os *dois* valores do topo:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

Aqui, o `dip` escondeu o `11`, executou `9 10 +` e voltou a pôr o `11` no topo. O `2dip` escondeu o `11 12`, executou `9 10 +` por baixo e depois restaurou o `11 12`.

O `dip` é a ferramenta certa quando a ordem natural dos argumentos deixa o valor «de passagem» no topo da pilha. Recorre a ele em vez do sanduíche `swap … swap`.

## `bi@`: a mesma operação sobre dois valores

O `bi@` (no [`kernel`][kernel]) aplica uma quotation a dois valores da pilha:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*`: operações diferentes sobre dois valores

O `bi*` (no [`kernel`][kernel]) aplica quotations *diferentes* aos dois valores da pilha: a primeira quotation ao valor de baixo, a segunda ao do topo:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

Recorre ao `bi@` quando os dois valores recebem o mesmo tratamento, e ao `bi*` quando cada um precisa do seu.

## `tri*`: operações diferentes sobre três valores

O `tri*` (no [`combinators`][combinators]) estende o `bi*` a três valores e três quotations, aplicando cada quotation a um valor, por ordem:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
