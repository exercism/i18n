# Sobre

Num conceito anterior, explorámos como um `integer` em assembly é essencialmente uma sequência de bytes interpretada de uma forma específica.

Cada bit de um inteiro pode ser usado para guardar um valor binário.
Como muitas situações envolvem informação binária, como verdadeiro ou falso, inclusão ou exclusão, ligado ou desligado, a representação binária de um inteiro de N bits oferece uma forma compacta de codificar o estado binário de N itens.
É por isso que saber manipular bits e bytes é essencial em assembly.
O conjunto de instruções x86-64 oferece uma grande variedade de instruções de manipulação de bits.

## Manipulação de bits individuais

Estas instruções atuam sobre bits individuais de um operando.

Todas recebem dois operandos; o segundo indica o índice do bit do primeiro operando sobre o qual se opera.
Todas copiam o bit selecionado para a **flag de transporte (CF)**.

| Nome  | Descrição                                                                     |
|-------|-------------------------------------------------------------------------------|
| `bt`  |copia o bit para `CF` sem modificar nenhum operando                            |
| `bts` |copia o bit para `CF` e coloca-o a 1 no operando de destino                    |
| `btr` |copia o bit para `CF` e coloca-o a 0 no operando de destino                    |
| `btc` |copia o bit para `CF` e complementa-o (inverte-o) no operando de destino       |

## Operações bit a bit

As [operações bit a bit][bitwise] são efetuadas sobre todos os bits de um operando.

Todas têm uma instrução com o mesmo nome da operação bit a bit que efetuam:

| Nome   | Descrição                                    |
|--------|----------------------------------------------|
| `and`  |1 se ambos os bits forem 1                    |
| `or`   |1 se pelo menos um dos bits for 1             |
| `xor`  |1 se os bits forem diferentes                 |
| `not`  |1 se o bit era 0; 0 se o bit era 1            |

A maioria recebe dois operandos, efetua uma operação bit a bit sobre ambos e guarda o resultado no operando de destino.
A exceção é `not`, que recebe apenas um operando de destino.

## Máscaras

Quando interpretamos um e zero como inclusão e exclusão, respetivamente, o inteiro chama-se _máscara de bits_ (ou simplesmente _máscara_).

Uma máscara de bits «esconde» os itens indesejados, porque um zero no bit `i` exclui o item `i`, enquanto um valor 1 o inclui.
Também é comum usar uma máscara de bits para incluir certos bits de um inteiro e excluir outros.

Por exemplo, seja `A` um inteiro cuja representação binária é:

| índice | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|-------|---|---|---|---|---|---|---|---|
| bits  | 1 | 0 | 0 | 1 | 0 | 1 | 0 | 1 |

Seja também `M` um inteiro cuja representação binária é:

| índice | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|-------|---|---|---|---|---|---|---|---|
| bits  | 0 | 0 | 0 | 0 | 1 | 1 | 0 | 1 |

Ambos são inteiros de `8` bits.
Neste caso, podemos dizer que `M` seleciona os bits `0`, `2` e `3` de `A`, e exclui os restantes.

As instruções bit a bit que vimos antes são úteis para manipular inteiros com máscaras.
Por exemplo:

- Para *colocar a 0* os bits de `A` que não são selecionados por `M`, faz o AND bit a bit: `A AND M`.
- Para *colocar a 1* os bits de `A` selecionados por `M`, faz o OR bit a bit: `A OR M`.

## Instrução TEST

A instrução `test` faz um AND bit a bit entre os dois operandos e define as flags de acordo com o resultado.

Se A for o primeiro operando e B, o segundo:

| flag | ativada quando                   |
|:----:|:---------------------------------|
| `CF` | é sempre limpa                   |
| `ZF` | A AND B == 0                     |
| `SF` | o bit de sinal de A AND B está a 1 |
| `OF` | é sempre limpa                   |

Esta instrução recebe dois operandos e atualiza as flags, mas **não modifica os seus operandos**.

## Operações de deslocamento

Estas instruções deslocam os bits do operando de destino um número de posições indicado pelo segundo operando.
O segundo operando tem de ser um número constante (um `immediate`) ou o registo `cl` (os `8` bits mais baixos de `rcx`).

| Nome        | Descrição                |
|-------------|--------------------------|
| `shl`/`sal` | Desloca os bits para a esquerda  |
| `shr`/`sar` | Desloca os bits para a direita |

Nota que a contagem no segundo operando é mascarada para `5` bits, ou `6` bits quando o operando de destino é de `64` bits.
Qualquer bit para além disso é efetivamente ignorado.
Isto significa que o deslocamento máximo é `31`, ou `63` com um operando de `64` bits.

### Shl / Sal

Tanto `shl` como `sal` fazem exatamente a mesma operação; um é um alias do outro.

Sempre que se faz um deslocamento para a esquerda, os bits que saem pelo fim da sequência, em número igual ao comprimento do deslocamento, são primeiro movidos para `CF` e só depois descartados.
Por outro lado, é acrescentado ao início um número de bits novos a 0 igual ao comprimento do deslocamento.

Por exemplo, considera o número `23`, representado num único byte, a ser deslocado `3` posições para a esquerda:

Antes do deslocamento (número `23`):

| índice | 7   | 6   | 5   | 4   | 3   | 2   | 1   | 0   |
|:-----:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| bits  | 0   | 0   | 0   | 1   | 0   | 1   | 1   | 1   |

Depois de deslocar `3` posições (número `184`):

| índice | 7   | 6   | 5   | 4   | 3   | 2   | 1   | 0   |
|:-----:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| bits  | 1   | 0   | 1   | 1   | 1   | 0   | 0   | 0   |

Repara que `184` é igual a `23 * 2³`.
Como cada bit de um inteiro representa uma potência de `2`, um deslocamento para a esquerda de n posições tem o efeito de multiplicar o inteiro por `2ⁿ`.

### Shr / Sar

Existem duas instruções para deslocar bits para a direita: `shr` e `sar`.

Sempre que se usa uma destas duas instruções, os bits que saem pelo início da sequência, em número igual ao comprimento do deslocamento, são primeiro movidos para `CF` e só depois descartados.
Por outro lado, é acrescentado ao fim um número de bits novos igual ao comprimento do deslocamento.

A diferença entre elas é que `shr` introduz bits `0` no início, enquanto `sar` introduz `1` se o bit mais significativo estava a 1, e `0` caso contrário.
Isto significa que `sar` preserva o sinal no deslocamento de um inteiro com sinal.

Por exemplo, considera o número `23`, representado num único byte, a ser deslocado `3` posições para a direita:

Antes do deslocamento (número `23`):

| índice | 7   | 6   | 5   | 4   | 3   | 2   | 1   | 0   |
|:-----:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| bits  | 0   | 0   | 0   | 1   | 0   | 1   | 1   | 1   |

Depois de deslocar `3` posições (número `2`):

| índice | 7   | 6   | 5   | 4   | 3   | 2   | 1   | 0   |
|:-----:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| bits  | 0   | 0   | 0   | 0   | 0   | 0   | 1   | 0   |

Como `23` não é negativo, tanto `sar` como `shr` dariam o mesmo resultado neste caso.

Por outro lado, considera o número `-42`, representado num único byte, a ser deslocado `3` posições para a direita:

Antes do deslocamento (número `-42`):

| índice | 7   | 6   | 5   | 4   | 3   | 2   | 1   | 0   |
|:-----:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| bits  | 1   | 1   | 0   | 1   | 0   | 1   | 1   | 0   |

Depois de deslocar `3` posições com shr (número `26`):

| índice | 7   | 6   | 5   | 4   | 3   | 2   | 1   | 0   |
|:-----:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| bits  | 0   | 0   | 0   | 1   | 1   | 0   | 1   | 0   |

Depois de deslocar `3` posições com sar (número `-6`):

| índice | 7   | 6   | 5   | 4   | 3   | 2   | 1   | 0   |
|:-----:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| bits  | 1   | 1   | 1   | 1   | 1   | 0   | 1   | 0   |

Repara que `2` é o quociente de `23 / 2³`.
Da mesma forma, se o número `-42` for interpretado como um valor sem sinal, seria `214`, e `214 / 2³` é igual a `26`.

Como cada bit de um inteiro representa uma potência de `2`, um deslocamento para a direita de n posições com `shr` tem o efeito de fazer uma divisão *sem sinal* por `2ⁿ`.

Repara também que `-42 / 2³` é igual a `-6` (com resto `6`).
Assim, um deslocamento para a direita de n posições com `sar` tem o efeito de fazer uma divisão *com sinal* por `2ⁿ`.

~~~~exercism/note
Ao dividir números negativos, `idiv` e `sar` podem dar resultados diferentes.
Isto acontece porque `idiv` arredonda em direção a `0`, enquanto `sar` arredonda em direção a `negative infinity`.

Na prática, isto significa que o `remainder` de uma divisão com sinal feita com `idiv` pode ser negativo.

Assim, ao dividir `-9` por `4` com `idiv`, o quociente seria `-2`.
Já ao deslocar `-9` `2` posições para a direita, o resultado seria `-3`.
~~~~

## Operações de rotação

Estas instruções deslocam os bits do operando de destino um número de posições indicado pelo segundo operando.
O segundo operando tem de ser um número constante (um `immediate`) ou o registo `cl` (os `8` bits mais baixos de `rcx`).

A diferença entre uma rotação e um deslocamento é que uma rotação não descarta nem acrescenta bits.
Os bits que seriam descartados por um deslocamento são movidos para o extremo oposto.
Assim, mantêm-se todos os bits; apenas mudam de lugar.

| Nome    | Descrição                |
|---------|--------------------------|
| `rol`   | Roda os bits para a esquerda   |
| `ror`   | Roda os bits para a direita  |

Existem variantes de ambas as instruções que usam `CF` como um bit extra na rotação:

| Nome    | Descrição                                      |
|---------|------------------------------------------------|
| `rcl`   | Roda os bits para a esquerda, incluindo o `CF` |
| `rcr`   | Roda os bits para a direita, incluindo o `CF`  |

Isto significa que um bit numa das extremidades da sequência é primeiro movido para `CF` antes de passar para a outra extremidade.
Ao mesmo tempo, o valor anterior da flag é movido para o bit que iria receber o bit que foi para a flag.
É como se `CF` fosse um bit extra para estas instruções.

Nota que a contagem no segundo operando é mascarada para `5` bits, ou `6` bits quando o operando de destino é de `64` bits.
Qualquer bit para além disso é efetivamente ignorado.
Isto significa que a rotação máxima é `31`, ou `63` com um operando de `64` bits.

## Outras instruções de manipulação de bits

Existem outras instruções úteis de manipulação de bits:

| Nome       | Descrição                                                                                            |
|------------|------------------------------------------------------------------------------------------------------|
| `popcnt`   | Conta o número de bits a 1                                                                           |
| `bsr`      | Obtém o índice do bit mais significativo que está a 1. Se nenhum bit estiver a 1, o resultado é indefinido  |
| `bsf`      | Obtém o índice do bit menos significativo que está a 1. Se nenhum bit estiver a 1, o resultado é indefinido |

Estas instruções trabalham todas com dois operandos de `16`, `32` ou `64` bits.
Não podem ser usadas com operandos de `8` bits.

## Extensões de manipulação de bits

Os CPU modernos têm três extensões mais recentes dedicadas à manipulação de bits: `LZCNT`, `BMI1` e `BMI2`.

As duas primeiras são geralmente tratadas como um par, já que `LZCNT` contribui com uma única instrução e `BMI1` contribui com a sua contraparte e mais cinco:

| Nome       | Descrição                                                                                            |
|------------|------------------------------------------------------------------------------------------------------|
| `lzcnt`    | Conta os zeros acima do bit mais significativo que está a 1. Se nenhum bit estiver a 1, o resultado é o tamanho do operando  |
| `tzcnt`    | Conta os zeros abaixo do bit menos significativo que está a 1. Se nenhum bit estiver a 1, o resultado é o tamanho do operando |
| `andn`     | AND bit a bit do segundo operando de origem com o complemento do primeiro operando de origem          |
| `bextr`    | Extrai uma sequência de bits do operando de origem, com uma posição inicial e um comprimento empacotados noutro registo  |
| `blsi`     | Isola o bit mais baixo que está a 1, colocando todos os outros a 0                                   |
| `blsmsk`   | Coloca a 1 todos os bits abaixo do bit mais baixo que está a 1, incluindo esse bit                   |
| `blsr`     | Coloca a 0 o bit mais baixo que está a 1, deixando todos os outros inalterados                       |

`BMI2` contribui com instruções que movem bits de acordo com uma máscara, juntamente com variantes dos deslocamentos e da multiplicação sem sinal que não alteram as flags:

| Nome       | Descrição                                                                                            |
|------------|------------------------------------------------------------------------------------------------------|
| `bzhi`     | Coloca a 0 todos os bits a partir de um dado índice, inclusive                                        |
| `pdep`     | Espalha os bits mais baixos da origem pelas posições selecionadas por uma máscara                     |
| `pext`     | Reúne nos bits mais baixos do destino os bits selecionados por uma máscara                            |
| `mulx`     | Multiplicação sem sinal de `rdx` pela origem, escrevendo as duas metades do produto                   |
| `rorx`     | Roda para a direita segundo um valor imediato                                                        |
| `sarx`     | Deslocamento aritmético para a direita segundo uma contagem obtida de qualquer registo                |
| `shlx`     | Deslocamento para a esquerda segundo uma contagem obtida de qualquer registo                          |
| `shrx`     | Deslocamento lógico para a direita segundo uma contagem obtida de qualquer registo                    |

`lzcnt` e `tzcnt` recebem um operando de destino e um operando de origem de `16`, `32` ou `64` bits, tal como `popcnt`, `bsr` e `bsf`.
O resto desta secção não tem forma de `16` bits: essas instruções trabalham com operandos de `32` ou `64` bits e a maioria recebe três operandos em vez de dois.
Nenhuma das instruções desta secção pode ser usada com operandos de `8` bits.

~~~~exercism/caution
A maioria das instruções desta secção provoca uma falha quando o hardware não as suporta.
No entanto, `lzcnt` e `tzcnt` são silenciosamente substituídas por `bsr` e `bsf` quando o hardware não as suporta.

O problema é que `lzcnt` e `bsr` nunca devolvem o mesmo valor.
Uma conta o número de zeros à esquerda; a outra devolve o índice do bit mais significativo que está a 1.
Se o bit mais significativo que está a 1 num operando de `64` bits estiver no índice `x`, então `bsr` devolveria `x`, enquanto `lzcnt` devolveria `63 - x`.

Além disso, tanto `bsr` como `bsf` devolvem um valor indefinido quando o operando de origem é `0`, enquanto `lzcnt` e `tzcnt` devolveriam ambas o tamanho do operando.

Certifica-te de que o hardware suporta `lzcnt` e `tzcnt` antes de as usares.
~~~~
