# Instalar Factor

O percurso de Factor usa o **Factor 0.101**. Versões anteriores não são suportadas.

Podes instalar uma versão [estável](#stable) ou [nightly](#nightly), ou [compilar a partir do código-fonte](#build-from-source).

Verifica a tua instalação com o comando `factor -e='vm-version print'`: deve imprimir `0.101` ou um valor superior.

---
### Stable

<https://factorcode.org#stable-release> disponibiliza binários estáveis na secção "Stable release".

---
### Nightly

<https://factorcode.org#development-release> disponibiliza binários nightly na secção "Development release". Estes binários são compilados a partir do git, mas só aparecem as compilações que passam.

---
### Compilar a partir do código-fonte

Se queres ter sempre a versão mais recente e até a nightly já é antiga para ti, vais precisar de um compilador moderno de C++ (GCC >=4.8 ou Clang >=3.5), do `make` e do `curl`.

Com estes requisitos simples cumpridos, podes:

1. Descarregar o script de shell `build`: [**aqui** para sistemas do tipo Unix / shells POSIX](https://raw.githubusercontent.com/factor/factor/master/build.sh) ou [**aqui** para Windows](https://raw.githubusercontent.com/factor/factor/master/build.cmd). Coloca-o no diretório onde o Factor deve ser instalado. Será criado um diretório chamado `factor` com o código.

2. Executá-lo com `./build.sh install`, ou `.\build.cmd install` no Windows. <sub>Isto vai clonar o repositório `git` do Factor, compilá-lo e descarregar uma imagem da VM do Factor a partir de <https://factorcode.org>. Este processo pode demorar entre 2 e 20 minutos, dependendo da velocidade da tua ligação e do teu processador.</sub>

3. Agora já podes executar o binário `factor` ou `factor.exe` gerado dentro do subdiretório `factor`. Experimenta `factor --help` para obteres ajuda. Também podes aceder à documentação a partir da linha de comandos, ou premindo <kbd>F1</kbd> no Listener gráfico, que abre o navegador de ajuda.

4. No futuro, usa o `build.sh` (ou o `build.cmd` no Windows) dentro do subdiretório `factor` para atualizares a partir do git e recompilares no local, e para descarregares uma nova imagem da VM, se for preciso.

A estrutura de ficheiros pode agora ter este aspeto:

```
.
├── build.sh                   <- delete if you like
└── factor
    ├── basis
    ├── boot.unix-x86.64.image
    ├── build.cmd              <- use these from now on
    ├── build.sh               <-
    ├── core
    ├── extra
    ├── factor
    ├── Factor.app
    ├── factor.image
    ├── GNUmakefile
    ├── libfactor.a
    ├── libfactor-ffi-test.so
    ├── LICENSE.txt
    ├── misc
    ├── Nmakefile
    ├── README.md
    ├── unmaintained
    ├── vm
    └── work
```

Já não precisas do script `build` do nível superior, porque a partir de agora deves usar o que descarregaste.

---

### Compilar a partir do código-fonte manualmente (não recomendado)

Clona o [repositório](https://github.com/factor/factor) e usa o `make` nessa pasta.

Se o `make` falhar com um erro sobre um alvo inexistente, experimenta `make factor` ou, se souberes ler um Makefile, procura o alvo de make da tua plataforma no `GNUmakefile`.

Se *isso* falhar, abre um issue no [factor/factor](https://github.com/factor/factor) com o erro, e os simpáticos programadores terão todo o gosto em ajudar.
