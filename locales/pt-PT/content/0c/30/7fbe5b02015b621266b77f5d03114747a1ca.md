# Introdução

O JavaScript tem um objeto incorporado, `Date`, que armazena data e hora e fornece métodos para a sua gestão.

<!-- prettier-ignore -->
~~~exercism/caution
Foi baseado na classe `java.util.Date` do Java, que foi substituída no início da década de 2010, mas, por questões de compatibilidade com versões anteriores, o `Date` do JavaScript continua a existir.

Como é difícil trabalhar com datas em geral e como o tratamento de fusos horários é mau ou inexistente, existem muitas bibliotecas, como `moment.js`, `day.js`, `date-fns` e `luxon`.
Nenhuma delas está disponível no Exercism.

Nos teus próprios projetos, não uses um pacote obsoleto ou sem manutenção como o `moment.js`. Opta antes por alternativas mais modernas, como o `luxon`, ou pelo [Temporal][mdn-temporal], que ainda não está amplamente disponível.
Este exercício incide sobre o `Date`, que continuará a ser relevante até ao fim do JavaScript.

## Criação

Um objeto `Date` é uma instância da classe `Date`.
Pode ser criado sem passar quaisquer argumentos à função construtora.
Isto resulta num objeto `Date` que representa a data e a hora atuais:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### Timestamp Unix (número)

Se for passado um número, este será interpretado como um `timestamp`.
Um timestamp é um número inteiro que representa o número de **milissegundos** decorridos desde **1 de janeiro de 1970 [UTC][defn-utc]+0**.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

Pode-se esperar que `new Date(0)` gere o objeto de data "mais antigo", mas o JavaScript converte a data para o teu fuso horário local, o que significa que só quem estiver perto do fuso horário [GMT / UTC+0][defn-gmt] obterá realmente o valor da [época Unix][defn-unix-epoch].

### Timestamp ISO 8601 (string)

Podes passar um valor de string que representa uma data ao construtor `Date`.
O **único** formato consistente entre implementações é a [versão simplificada][mdn-date-string-format] das chamadas [strings de timestamp ISO 8601][defn-iso8601], reconhecidas e normalizadas internacionalmente.

Um momento no tempo em [UTC][defn-gmt] tem este aspeto:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

Onde se aplicam as seguintes substituições:

| Chave | Descrição                                 | Predefinição |
| ---- | ------------------------------------------- | ------- |
| YYYY | O ano civil, representado com 4 algarismos  |         |
| MM   | O mês civil, representado com 2 algarismos | 01      |
| DD   | O dia civil, representado com 2 algarismos   | 01      |
| T    | A letra T literal, que separa a data da hora  | T       |
| HH   | As horas num relógio de 24 horas, 2 algarismos                        | 00      |
| mm   | Os minutos, 2 algarismos                       | 00      |
| ss   | Os segundos, 2 algarismos                       | 00      |
| mss  | Os milissegundos, 3 algarismos                  | 000     |
| Z    | A letra Z literal, ou um desvio `+/-HH:mm` |         |

A letra literal `Z` indica UTC (sem fuso horário, sem horário de verão).

Como existem valores predefinidos para a maioria dos componentes, é válido omitir partes no fim:

```text
YYYY-MM-DD
```

Assume por predefinição a hora 00:00:00.000

Se o timestamp não terminar em `Z` nem terminar com `+HH:mm` ou `-HH:mm` (que indicam um desvio de fuso horário), por razões históricas aplica-se o seguinte:

> Quando o desvio de fuso horário está ausente, as formas só com data são interpretadas como hora UTC e as formas com data e hora são interpretadas como hora local.
> A interpretação como hora UTC deve-se a um erro histórico da especificação, que não era consistente com a ISO 8601, mas que não pôde ser corrigido devido à compatibilidade com a web.
> Vê [Broken Parser – A Web Reality Issue][ref-broken-parser].

### Objeto Date

Um objeto de data existente também pode ser usado como argumento do construtor.
Isto faz uma cópia do objeto `Date` existente, com a mesma data e a mesma hora.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### Fornecer valores individuais dos componentes de data e hora

Uma data que representa apenas um dia pode ser criada passando três números.
Uma data que representa um dia e uma hora pode ser criada passando 6 números.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

O segundo valor é o `month`, que começa em `0` para janeiro e vai até `11` para dezembro.

## `Date.parse()`

Podes encontrar menções ou referências a uma função de análise de datas, `Date.parse`.
Como existem apenas alguns invariantes (verdades) para esta função e como o resto da implementação não está especificado (e, por isso, não é padrão), não deves usá-la.

## Aceder aos componentes do `Date`

Existem vários métodos nos objetos de data que devolvem os componentes da data:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

Cada um destes tem uma variante `set` correspondente (por exemplo, `setFullYear`) para atualizar o valor.
Qualquer valor que transborde passa para o componente seguinte:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

Existem variantes UTC para todos os métodos, que ignoram o fuso horário local.

## Converter a partir de uma data

Os objetos de data têm um método `getTime()` que devolve o timestamp UNIX em milissegundos, ou seja, o número de milissegundos desde a meia-noite do início de 1 de janeiro de 1970, UTC.
Além disso, está disponível um método `toISOString()` para converter um objeto de data numa string de timestamp ISO 8601.

## Comparar datas

Os operadores maior que (`>`), maior ou igual que (`>=`), menor que (`<`) e menor ou igual que (`<=`) podem ser usados diretamente entre duas datas ou entre uma data e um número.
Isto funciona porque o JavaScript tenta converter a data num primitivo.

<!-- prettier-ignore -->
~~~exercism/advanced
Ao fazer uma comparação entre duas datas ou entre uma data e um número, o JavaScript chama [`[Symbol.toPrimitive]("number")`][mdn-to-primitive], que internamente chama [`date.valueOf()`][mdn-date-value-of].
Este último é equivalente a chamar [`date.getTime()`][mdn-date-get-time].

Se não quiseres depender deste comportamento, converte primeiro num número com `getTime()`.

[mdn-to-primitive]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/Symbol.toPrimitive
[mdn-date-value-of]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/valueOf
[mdn-date-get-time]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/getTime
~~~

As datas não podem ser comparadas com igualdade (`==` e `===`), mas o resultado de `.getTime()` pode.
