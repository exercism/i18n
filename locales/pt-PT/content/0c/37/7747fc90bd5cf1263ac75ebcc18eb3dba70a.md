# Docker

Os nossos Representers são publicados como imagens Docker.

Lê as [informações gerais sobre Docker em Tooling](/docs/building/tooling/docker) para perceberes como funcionam.

## Integração

Quando executamos um Representer para criar a representação de uma solução, corremos um comando Docker com este aspeto:

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-representer" \
        "${exercise_slug}" "/solution" "/output"
```

Como podes ver, passamos três argumentos à imagem Docker:

1. O slug do exercício
2. O caminho para o diretório da solução
3. O caminho para o diretório de saída

## Convenções

Todos os nossos Representers seguem as seguintes convenções na sua implementação:

- O `Dockerfile` está no diretório raiz do repositório.
- O diretório de trabalho deve ser `/opt/representer`.
- O ponto de entrada é `/opt/representer/bin/run.sh`
- O script `/opt/representer/bin/run.sh` recebe 3 argumentos:
  1. O slug do exercício
  2. O caminho para o diretório da solução
  3. O caminho para o diretório de saída

Para mais informações, consulta [A Interface](/docs/building/tooling/test-runners/interface).

```exercism/note
Os novos repositórios de representers usam estas convenções por predefinição.
```
