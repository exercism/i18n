# Sobre

## Aplicação parcial

Todas as funções em Elm são [curried][currying], o que significa que, se chamares uma função sem passar todos os argumentos, ela devolve uma nova função.

O resultado desta operação chama-se [aplicação parcial][partial-application] (não estás a passar todos os argumentos à função, mas sim a aplicá-los parcialmente).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

A aplicação parcial aplica sempre os argumentos por ordem.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## Operador pipe (`|>`)

Dizer `x |> f` é exatamente o mesmo que `f x`. Um exemplo concreto: `"5" |> String.toInt` é o mesmo que `String.toInt "5"`.

À primeira vista, isto pode não parecer muito útil, mas chama-se [operador pipe][pipe-operator] porque te permite escrever código “encadeado”.

Por exemplo, imagina que temos uma função sanitize para transformar dados introduzidos pelo utilizador em números inteiros:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Podemos reescrevê-la assim:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Isto evita o uso de parênteses e mostra as funções pela ordem em que são aplicadas (primeiro `String.trim`, depois `String.toInt`), o que ajuda à legibilidade.

Existe também um [operador pipe inverso `(<|)`][reverse-pipe-operator].
Dizer `x <| f` é exatamente o mesmo que `f x`.
À primeira vista, também não parece muito útil, e é claramente menos usado do que o operador pipe, mas ajuda a evitar parênteses em algumas situações.

## Composição de funções / estilo point free

O operador [`(>>)`][forward-composition] tem o tipo `(a -> b) -> (b -> c) -> (a -> c)` e cria uma função do tipo `a -> c` ao compor duas funções compatíveis, uma do tipo `a -> b ` e outra do tipo `b -> c`.
Fá-lo pegando na saída (do tipo `b`) da primeira função e usando-a como primeiro argumento da segunda função (que tem de ser do mesmo tipo `b`).
A função criada recebe o mesmo valor de entrada (do tipo `a`) que a primeira função e devolve o `c` que a segunda função devolver.

Um exemplo concreto é `String.trim >> String.toInt`.
`String.trim` recebe uma string como único parâmetro, por isso é isso que a função criada recebe.
`String.toInt` devolve um `Maybe Int`, por isso é isso que a função criada devolve.
`String.trim` devolve uma `String`, que `String.toInt` aceita como parâmetro, por isso o exemplo compila.

Agora podemos reescrever a nossa função `sanitize` da seguinte forma:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Repara que já não usamos o parâmetro `input` que vês no exemplo original, embora a funcionalidade seja idêntica.
Esta forma de criar funções que não fazem referência aos seus parâmetros chama-se "Point Free Style".
A vantagem deste estilo é que o código é mais conciso; a desvantagem é que pode ser mais difícil de compreender, sobretudo para quem está a começar.

Vale a pena lembrar que, em Elm, todas as funções são curried, por isso `String.length >> max` compila e dá origem ao seguinte:

- Uma função (1) que tem um parâmetro do tipo string (o valor de entrada de `String.length`)
- `max` é uma função que tem dois parâmetros `Int`, mas a função 1 passa-lhe um único `Int` (o valor devolvido por `String.length`), por isso `max` fica parcialmente aplicada.
- O valor devolvido da função `max` parcialmente aplicada é outra função (2) que recebe um `Int` e devolve o maior entre esse `Int` e o `Int` parcialmente aplicado proveniente de `String.length`
- Logo, a função 1 (`String -> Int`) devolve a função 2 (`Int -> Int`)
- Portanto, `((String.length >> max) "123") 2` devolve `3`, porque `"123"` tem comprimento 3, que é maior do que o 2 do argumento `Int`.

## Desenho de funções

Para ser mais fácil escrever código elegante em Elm, convém colocar a estrutura de dados principal como último parâmetro das funções.
Todas as funções comuns da biblioteca padrão fazem isto, como `List.map` (assinatura de tipo abaixo).

```elm
map : (a -> b) -> List a -> List b
```

Aqui vemos que o último parâmetro da função `map` é `List a` e que devolve `List b`, por isso a estrutura de dados principal (`List`) é o último parâmetro.

Isto torna possível escrever código encadeado elegante, como o que se segue.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Também torna prático usar composição de funções e o estilo point free, como alternativa ao encadeamento.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

A composição de funções também te permite reduzir este exemplo a uma única chamada a `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
