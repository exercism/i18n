# Introdução

A Julia, como a maioria das linguagens de programação, oferece uma grande variedade de tipos de coleções.

Algumas são intrinsecamente ordenadas (incluindo os `Vectors` e os `Arrays` de dimensões superiores), por isso podemos aceder aos elementos pela posição.
Outras coleções não são ordenadas (`Sets`, `Dicts`), e os elementos têm de ser acedidos pela chave ou pelo valor.

No caso mais simples, imagina que temos um `Vector` de `Ints` e queremos ordená-lo por ordem crescente.

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

Simples!
A função `sort()` tem um nome óbvio e, aparentemente, devolve o `Vector` ordenado.

_Estou a brincar!_
A esta altura do programa, talvez suspeites (com razão) que há nuances de que precisamos de falar.

## Funções que modificam vs. funções que não modificam

Depois de correres `sort(v)`, o que é o `v`?

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

O vetor original fica inalterado.
A `sort()` é uma função ***que não modifica*** os seus argumentos e devolve uma _cópia_ do valor de entrada.

É um bom design em muitos contextos: temos uma função pura, cujo comportamento é fácil de analisar, mesmo em código paralelo e distribuído.

Por outro lado, imagina que tínhamos um array com mil milhões de strings e queríamos ordená-lo.

A ordenação é provavelmente lenta.
Além disso, temos de copiar tudo (_lento!_) e alocar memória suficiente (_vários gigabytes!_) para guardar a cópia.

Compara com este código bastante semelhante:

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

Agora, o `Vector` de entrada é ordenado no local, sem cópias, e a ordem original perde-se definitivamente.

Isto pode ser eficiente, pode ter bugs e provocar efeitos secundários inesperados, pode ser confuso para outras pessoas que usem o teu código.
_Escolhe com cuidado!_

A `sort!()` é uma «função que modifica os argumentos» e, por convenção (_muito forte_), qualquer função que modifique os seus argumentos tem um `!` acrescentado ao nome, como aviso para quem programa.

## Array de índices de ordenação

Se os elementos a ordenar forem objetos grandes, pode ser mais fácil trabalhar com o seu índice de posição.

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

Como `langs` é um vetor, cada índice é um número inteiro no intervalo `1:length(langs)`.
O resultado de `sortperm()` é uma permutação desses números inteiros, que corresponde à ordenação do vetor de entrada.
