# Instruções

Trabalhas no gabinete municipal há algum tempo e desenvolviste um conjunto de ferramentas que agilizam o teu trabalho do dia a dia, por exemplo a preencher formulários.

Agora vai chegar um novo colega e apercebeste-te de que as tuas ferramentas podiam não ser autoexplicativas. Há muitas convenções estranhas no teu gabinete, como preencher sempre os formulários com letras maiúsculas e evitar deixar campos vazios.

Decides escrever alguma documentação para que o teu novo colega possa começar logo a usar as tuas ferramentas.

## 1. Documenta o objetivo das ferramentas de formulários

Adiciona ao módulo `Form` documentação que descreva o seu objetivo. Deve dizer o seguinte:

```
A collection of loosely related functions helpful for filling out various forms at the city office.
```

## 2. Documenta o preenchimento de campos com valores em branco

Adiciona documentação e um typespec à função `Form.blanks/1`. A documentação deve dizer o seguinte:

```
Generates a string of a given length.

This string can be used to fill out a form field that is supposed to have no value.
Such fields cannot be left empty because a malicious third party could fill them out with false data.
```

O typespec deve explicar que a função aceita um único argumento, um número inteiro não negativo, e devolve uma string.

## 3. Documenta a divisão de valores em listas de letras maiúsculas

Adiciona documentação e um typespec à função `Form.letters/1`. A documentação deve dizer o seguinte:

```
Splits the string into a list of uppercase letters.

This is needed for form fields that don't offer a single input for the whole string,
but instead require splitting the string into a predefined number of single-letter inputs.
```

O typespec deve explicar que a função aceita um único argumento, uma string, e devolve uma lista de strings.

## 4. Documenta a verificação de se um valor cabe num campo com um comprimento máximo

Adiciona documentação e um typespec à função `Form.check_length/2`. A documentação deve dizer o seguinte:

```
Checks if the value has no more than the maximum allowed number of letters.

This is needed to check that the values of fields do not exceed the maximum allowed length.
It also tells you by how much the value exceeds the maximum.
```

O typespec deve explicar que a função aceita dois argumentos, uma string e um número inteiro não negativo, e devolve um de dois valores possíveis. Devolve ou o átomo `:ok` ou um tuplo de dois elementos, sendo o primeiro o átomo `:error` e o segundo um número inteiro positivo.

## 5. Documenta diferentes formatos de endereço

Por alguma razão que desconheces, o sistema interno do gabinete municipal usa duas formas diferentes de representar endereços: ou como um mapa, ou como um tuplo.

Documenta este facto definindo três tipos públicos personalizados:
- `address_map` - um mapa com as chaves `:street`, `:postal_code` e `:city`. Cada chave contém um valor do tipo string.
- `address_tuple` - um tuplo com três valores - `street`, `postal_code` e `city`. Cada valor é do tipo string. Distingue os valores dando-lhes nomes no typespec.
- `address` - pode ser um `address_map` ou um `address_tuple`.

## 6. Documenta a formatação do endereço

Adiciona documentação e um typespec à função `Form.format_address/1`. A documentação deve dizer o seguinte:

```
Formats the address as an uppercase multiline string.
```

O typespec deve explicar que a função aceita um argumento, um endereço, e devolve uma string.
