# Contratos

Os argumentos de uma rotina e o tipo do valor devolvido dizem que *tipo* de coisa entra e sai. Não podem dizer que um peso tem de ser positivo, nem que um arnês nunca reporta mais capacidade disponível do que aquela que tem.

Um **contrato** diz essas coisas, no próprio cabeçalho da rotina, onde quem o ler as vai ver.

## pre

`pre` indica o que tem de ser verdadeiro quando a rotina é chamada. Fica entre o tipo do valor devolvido e o `is`.

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

Isto é uma exigência a quem chama: não chames isto com uma carga negativa.

## post

`post` indica o que será verdadeiro quando a rotina responder. Dentro dele, `result` é o valor que está a ser devolvido.

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

Isso é uma promessa a quem chama. Uma rotina com os dois é um acordo: dá-me isto e eu dou-te aquilo.

Várias condições combinam-se com `and`, tal como quaisquer booleanos:

```sather
      pre load >= 0 and load <= limit
```

## Os contratos não são exceções

Uma exceção lançada serve para algo que pode acontecer. Um contrato violado significa um **bug**: alguém chamou a rotina de forma errada, ou a rotina não fez o que dizia.

Por isso, um contrato violado não lança nada que se possa apanhar. Quando a verificação de contratos está ativada, o programa para e imprime qual a rotina e qual a condição. Quando está desativada, a condição não é sequer testada, e o programa segue em frente para o disparate que vier a seguir.

É por isso que um contrato é uma afirmação sobre a correção e não uma forma de tratar valores de entrada inválidos. Se um valor de entrada inválido for de esperar, verifica-o e usa `raise`. Se um valor de entrada inválido significar que quem chama está errado, diz isso com `pre`.

## Ativar a verificação

Este Sather verifica os contratos quando se passa `-chk` ao compilador:

```
sacomp -chk mine.sa -main MAIN -o mine
```

Sem isso, `pre` e `post` são documentação que o compilador leu e aceitou estar bem formada, e nada mais. Os testes deste exercício são compilados sem `-chk`, por isso não podem apanhar um contrato violado por ti; verificam que as rotinas fazem a coisa certa quando são usadas corretamente.
