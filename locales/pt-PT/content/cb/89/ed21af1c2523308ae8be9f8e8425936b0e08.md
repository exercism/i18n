# Introdução

## JSON

### JSON

JSON (JavaScript Object Notation) é um formato de dados e de ficheiros legível por humanos, usado habitualmente para trocar dados, em particular em aplicações web.
Como tal, não é de estranhar que ocupe um lugar especial na linguagem Elm.

O Elm fornece os módulos centrais `Json.Decode` e `Json.Encode` para interpretar e escrever dados JSON.
Os descodificadores de JSON são uma forma de _declarar_ que tipo de dados é esperado e a que estrutura de dados os dados devem ser mapeados.

Vamos importar alguns aliases e tipos dos módulos:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Usar `Decode.decodeString : Decoder a -> String -> Result Error a` com um descodificador e uma string JSON tem sucesso se a string estiver de acordo com as especificações do descodificador, e falha caso contrário.
Não há forma de inspecionar os dados JSON em bruto quando defines o descodificador. Se vens de linguagens imperativas, isto pode parecer-te invulgar.

### Descodificadores de tipos de dados básicos

O JSON tem um pequeno número de tipos de dados fundamentais:

- String: codificada com aspas duplas `"hello world"`
- Boolean: `true` ou `false`
- Number: como `34` ou `0.12`
- Null: a ausência de dados, `null`

Cada um destes está associado a uma função de `Decode`:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Repara que `Decode.null` te deixa decidir como modelar um `null` no teu programa, exigindo um valor arbitrário como argumento (talvez `()`, `Nothing`, ou qualquer coisa adequada ao teu programa).

### Combinar descodificadores

O JSON também define duas estruturas de dados para agrupar tipos de dados fundamentais:

- Array: uma coleção de outros tipos de dados `[0, null, "none", []]`
- Object: uma coleção de pares chave-valor `{"id": 1, "is_admin": false, "more_info": {}}`

O `Decode` também oferece funções para os descodificar:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Estas funções, `Decode.list : Decoder a -> Decoder (List a)` e `Decode.dict : Decoder a -> Decoder (Dict String a)`, esperam um descodificador como argumento, que deve descodificar todos os elementos da estrutura de dados.
Se o descodificador passado como argumento falhar a descodificação de algum elemento de um array ou de um objeto, o descodificador todo falha, o que é um padrão comum.

Combinar descodificadores simples em descodificadores mais complexos é a ideia central da técnica.
Vamos apresentar mais algumas funções que podes usar para construir descodificadores de dados do mundo real arbitrariamente complexos, com a ajuda de um exemplo.

### GeoJSON

Para praticares a combinação de descodificadores básicos na interpretação de dados JSON complexos, vamos construir descodificadores para interpretar (um subconjunto de) dados GeoJSON.
O GeoJSON é um formato de dados especializado, baseado em JSON, usado para representar elementos geográficos, como localizações, percursos ou regiões, especificados com coordenadas geográficas 2D ou 3D, a par de outras propriedades.

#### Objeto de geometria

Um objeto de geometria GeoJSON é um objeto que contém um campo `type` com um valor string (há 7 valores possíveis para o tipo) e um campo `coordinates` com coordenadas geográficas (reunidas numa estrutura que depende do tipo).
Por exemplo,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

ou

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Um objeto de geometria pode ser representado em Elm com o tipo seguinte

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Para inspecionar o valor de um determinado campo, podemos usar `Decode.field : String -> Decoder a -> Decoder a`, que descodifica o valor de uma chave específica de um objeto.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Para transformar o valor interpretado com sucesso por um descodificador, podemos usar `Decode.map : (a -> value) -> Decoder a -> Decoder value`, ou qualquer dos seus irmãos, desde `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` até `Decode.map8`.

Neste caso, queremos decidir que descodificador de coordenadas usar consoante o valor do campo `type`, o que é uma tarefa ideal para `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` e os seus amigos `Decode.succeed : a -> Decoder a` e `Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

Repara, a esta altura, que podíamos usar `Decode.andThen` para validar as coordenadas (verificando se as coordenadas aparecem em pares ou trios e se os valores das coordenadas fazem sentido geográfico).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

#### Objeto de feature

Um objeto de feature GeoJSON representa algo delimitado espacialmente: tem um campo `type` com o valor `"Feature"`, um campo `geometry` com um objeto de geometria ou um `null`, um campo `properties` com um objeto JSON arbitrário ou um `null`, e um campo `id` opcional com um valor de string ou de número JSON.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

ou

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Vamos tratar primeiro do campo `id`.
Se existir, tem de acomodar strings ou números, por isso podíamos ou introduzir um tipo personalizado para o valor, ou guardá-lo sempre como uma string.

Para escolher entre dois descodificadores possíveis, podemos usar `Decode.oneOf : List (Decoder a) -> Decoder a`.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Para indicar que o campo é opcional, podíamos usar a mesma técnica

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Mas podíamos, em vez disso, usar `Decode.maybe : Decoder a -> Decoder (Maybe a)`

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Repara que `decodeMaybeFeatureId` (ou qualquer descodificador envolvido com `Decode.maybe`) tem sempre sucesso, porque pode sempre recorrer a `Ok Nothing`, embora um descodificador que o use ainda possa falhar

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

A seguir, vamos centrar-nos no campo `geometry`, que pode ser um objeto de geometria ou ser `null`.
Podíamos usar `Decode.oneOf` outra vez, mas há uma opção melhor: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` e `Decode.nullable` têm a mesma assinatura, mas o comportamento é diferente, porque o resultado `OK Nothing` de um `Decode.nullable` só pode vir do valor JSON específico `null`.

Por fim, o campo `properties` pode conter um objeto JSON arbitrário ou um `null`, o que é trabalho para `Decode.value : Decoder Value`.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Repara que `Value` é um tipo opaco, o que significa que não consegues inspecionar facilmente o seu conteúdo.
Para o usar, podes ou escrever um descodificador para ele e executá-lo com `Decode.decodeValue : Decoder a -> Value -> Result Error a`, ou enviá-lo diretamente para o JavaScript através de um port.

Estamos prontos para interpretar objetos de feature:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

### Codificadores de JSON

Os codificadores permitem escrever JSON válido a partir de valores de Elm, usando a função `Encode.encode : Int -> Value -> String`.
O primeiro argumento especifica a quantidade de indentação no resultado final, e o segundo argumento é o valor JSON a escrever.

Um `Value` pode ser obtido a partir de `Decode.value` ou produzido por um dos codificadores:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

tal como com `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Vamos definir codificadores para os descodificadores GeoJSON que definimos antes

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

Em geral, um bom teste para os teus pares descodificador-codificador é verificar se `elmValue |> encoder |> decoder == elmValue`.
