# Introdução

Na maior parte das vezes, o Factor trata a iteração através de combinadores como `each`, `map` e `count`. Às vezes, porém, a forma mais limpa de exprimir um cálculo é a **recursão**: uma palavra que se chama a si própria.

## Definir uma palavra recursiva

Uma definição `:` pode chamar-se a si própria diretamente:

```factor
: count-down ( n -- )
    dup 0 = [ drop ] [ dup . 1 - count-down ] if ;

5 count-down
! prints 5 4 3 2 1
```

## Ramificar conforme está vazio ou não

O `if-empty` (em [`sequences`][sequences]) é o caso base natural da recursão:

```
if-empty ( seq emptyquot nonemptyquot -- )
```

```factor
{ 4 0 9 } [ "empty" ] [ "got data" ] if-empty .
! => "got data"
```

O `emptyquot` é executado com a sequência (vazia) já consumida; o `nonemptyquot` é executado com a sequência ainda na pilha.

## `cond`: uma cadeia de ramos com guardas

Quando a tua recursão tem mais de dois casos, o `cond` (em [`combinators`][combinators]) mantém o código legível:

```factor
: classify ( n -- label )
    {
        { [ dup 0 < ] [ drop "negative" ] }
        { [ dup 0 = ] [ drop "zero"     ] }
        [ drop "positive" ]
    } cond ;
```

## Referências futuras com `DEFER:`

Uma definição `:` pode chamar-se a si própria diretamente, mas quando duas palavras se chamam *uma à outra*, o parser vê a primeira antes de a segunda existir. O `DEFER:` reserva um nome para que a primeira definição possa ser compilada:

```factor
DEFER: even?

: odd? ( n -- ? ) dup 0 = [ drop f ] [ 1 - even? ] if ;
: even? ( n -- ? ) dup 0 = [ drop t ] [ 1 - odd? ] if ;
```

O `DEFER:` também é útil quando uma palavra auxiliar é mais naturalmente lida *depois* da palavra que a utiliza.
