# Apêndice às instruções

## Tratamento de erros

Este exercício introduz a crate `anyhow`, que facilita o tratamento de tipos de erro arbitrários.
A intenção é garantir que, quando escreves uma aplicação, não tenhas de te preocupar com os erros
concretos que a função que chamas devolve, mas apenas fazer o que está certo ao propagá-los.

Nota: na verdade, não é muito boa prática usar `anyhow` quando se escreve uma biblioteca, como é o
caso aqui; é mais explícito e mais útil escrever o teu próprio enum `Error` quando escreves uma
biblioteca (potencialmente com a ajuda de macros auxiliares como as fornecidas pela [`thiserror`](https://crates.io/crates/thiserror)). No
entanto, estamos intencionalmente e explicitamente a fazê-lo aqui para demonstrar a utilização desta crate.

Para saberes mais sobre esta crate, consulta a sua [documentação](https://docs.rs/anyhow/1.0.32/anyhow/).

## Leitura adicional

Embora este exercício te peça para implementares apenas as funções mais básicas do `grep`,
existe na verdade um projeto para reimplementar o `grep` por completo em Rust: o [ripgrep](https://github.com/BurntSushi/ripgrep).

Se gostaste da ideia de reescrever os programas utilitários básicos em Rust, não deixes de espreitar os seguintes projetos:

- [fd](https://github.com/sharkdp/fd) - um clone do `find`
- [exa](https://github.com/ogham/exa) - um clone do `ls`
- [bat](https://github.com/sharkdp/bat) - um clone do `cat`
- [coreutils](https://github.com/uutils/coreutils) - uma reescrita dos GNU coreutils
