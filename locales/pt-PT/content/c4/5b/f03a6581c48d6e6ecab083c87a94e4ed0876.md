# Testes

Executa os testes com:

```shell
corepack pnpm test
```

Certifica-te de que o teu código segue as boas práticas e os estilos de codificação, tal como os outros utilizadores, com o ESLint, uma ferramenta que faz análise estática ao teu código.
Por vezes, ferramentas como esta poupam-te tempo a detetar gralhas ou erros disparatados no teu código JavaScript:

```shell
corepack pnpm lint
```

Também podes correr o Jest em modo «watch», que volta a executar os testes automaticamente quando guardas alterações no código ou no módulo de testes:

```shell
corepack pnpm watch
```

## Compreender os testes ignorados

O método skip diz ao conjunto de testes para não executar um teste. Esta função também pode ser usada com os nomes alternativos: `it.skip(name, fn)` ou `xit(name, fn)` ou `xtest(name, fn)`

- Porque é que são ignorados ?

Para permitir que os utilizadores se concentrem num teste de cada vez e os ativem um a um à medida que a solução evolui.

- Como é que os ativamos ?

Muda `xtest` para `test`.

```javascript
test('title cased phrases', () => {
  expect(Acronyms.parse('Portable Network Graphics')).toEqual('PNG');
});
```

## Criar o teu primeiro módulo JavaScript 2015

Normalmente, os testes neste percurso carregam a tua implementação ao importá-la como um módulo JavaScript: `import { Bob } from './bob.js';`.
Só precisas de exportar a tua implementação a partir do ficheiro referenciado, `bob.js`:

```javascript
export function hey(message) {}
```

Podes encontrar mais informações sobre módulos na [documentação do Babel](https://babeljs.io/docs/learn-es2015/#modules).
