# Sobre

[Lua](https://lua.org) é uma linguagem de scripting simples mas poderosa, eficiente, leve e incorporável. É concebida, implementada e mantida na [PUC-RIO](https://www.puc-rio.br/), no Brasil, desde 1993, pela equipa de Roberto Ierusalimschy, Waldemar Celes e Luiz Henrique de Figueiredo.

## Comentários

Os comentários de uma linha em Lua começam com `--` e os comentários de várias linhas começam com `--[[` e terminam com `]]`.
```lua
-- This is a single line comment.

--[[This is
a multiline
comment
]]
```

## Variáveis

Em Lua existem três tipos de variáveis: variáveis globais, variáveis locais e campos de tabela. Para simplificar, aqui só são explicadas as variáveis locais. Por omissão, todas as variáveis são globais, por isso temos de declarar as variáveis locais como tal com a palavra-chave `local`.
```lua
local x
```

Podes atribuir um valor a uma variável com o operador `=`.
```lua
local x = 1
```

O âmbito de uma variável `local` está limitado ao bloco onde é declarada. Um bloco pode ser o corpo de uma estrutura de controlo, o corpo de uma função, ou um ficheiro ou uma string onde a variável é declarada.
```lua
local x = 1

if x == 1 then
  local x = 2
  print(x) -- prints 2
end

print(x) -- prints 1
```

## Funções

Uma função é declarada com a palavra-chave `function` e, tal como as variáveis, é global por omissão. A definição de uma função tem um nome, uma lista de parâmetros e um corpo. A função termina quando se chega à palavra-chave `return` e devolve todos os valores listados a seguir. Sem um `return` especificado, a função devolve `nil`.

```lua
-- Defining a local function which returns "Hello " followed by 
-- the name which was given as parameter
local function say_hello(name)
  return 'Hello ' .. name
end
```

## Tabelas

As tabelas são o único mecanismo de estruturação de dados em Lua e são muito poderosas. São usadas para representar arrays, conjuntos, objetos, módulos e muito mais. Essencialmente, uma tabela em Lua é um array associativo.
```lua
-- create a table and assign its reference to tbl
local tbl = {}

-- new entry with key 'x' and value 1
tbl['x'] = 1

-- printing the value
print(tbl['x'])  --> 1

-- uninitialized table fields evaluate to nil
print(tbl['y'])  --> nil

-- there is also syntactic sugar - the following is the same as above
tbl.y = 1
print(tbl.y)    --> 1
```

Isto é apenas um pequeno vislumbre, necessário para a próxima secção. Voltamos a este tópico em detalhe mais à frente.

## Módulos

Um módulo é uma coleção de código armazenada num ficheiro de código-fonte `.lua`. Tudo o que o módulo exporta fica guardado numa tabela, e essa tabela é devolvida no fim do ficheiro. Por isso, a tabela funciona basicamente como uma espécie de espaço de nomes.
```lua
-- say-hello.lua

-- defining the table 'say' which is exported at the end
local say = {}

-- defining the function 'hello' as a table field
-- this is syntax sugar for: say.hello = function() print('Hello!') end
function say.hello()
  print('Hello!')
end

-- returning (exporting) the table 'say'
return say
```

Esse módulo pode depois ser carregado noutro ficheiro através da função `require`, que devolve a tabela.
```lua
-- lets_say_hello.lua
local say = require('say-hello')
say.hello() -- prints "Hello!"
```

Quando vemos `say.hello`, pensamos em "a função `hello` do módulo `say`". Mas, sabendo que o nosso `say-hello.lua` devolve uma tabela e olhando novamente para a secção das tabelas, reparamos que, em Lua, a expressão significa "indexar a tabela `say` usando a string `hello` como chave".  

Embora seja boa prática um módulo devolver uma tabela, é igualmente possível devolver qualquer outro tipo, como uma função.

```lua
--- say-bye.lua
local function bye()
  print('Bye!')
end

return bye
```
