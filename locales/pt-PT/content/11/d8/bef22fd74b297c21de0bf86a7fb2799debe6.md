# Instruções

És o oficial de quarto a bordo de um cúter que atravessa o Estreito de Bering. Três fontes anunciam a posição de cada bloco de gelo e de cada promontório à vista:

- A **mesa de cartas** fala em direções da bússola: `north`, `east`, `south`, `west`. Apenas uma direção, sem distância.
- O **navegador** fala em coordenadas *polares* a partir da última posição fixada do cúter: uma magnitude em milhas náuticas e uma marcação em graus, no sentido dos ponteiros do relógio a partir do norte (ou seja, `0` é north, `90` é east, `180` é south e `270` é west).
- O **vigia no topo do mastro** fala em coordenadas *relativas*: uma distância para a frente e uma de entre `ahead`, `starboard`, `behind`, `port`. As marcações relativas medem-se em relação ao *rumo atual do navio*: o capitão anuncia esse rumo na ponte antes de cada quarto.

A tua tarefa é converter as três fontes para um referencial cartesiano comum `(x, y)`, para que se possa traçar a carta. As marcações são em graus; `(0, 1)` é uma milha náutica para norte e `(1, 0)` é uma milha náutica para este.

## 1. O modelo de dados e as coordenadas cartesianas a partir das direções cardinais

Primeiro, prepara os elementos que todo o exercício partilha:

- Define três tuplos: `cardinal` (um campo, `direction`), `polar` (campos `magnitude` e `bearing`) e `relative` (campos `distance` e `bearing`).
- Declara os símbolos das direções com `SYMBOLS:`: `north`, `east`, `south`, `west`, `ahead`, `starboard`, `behind`, `port`.
- Declara uma variável dinâmica `heading` com `SYMBOL:` (a tarefa 3 usa-a).
- Declara duas palavras genéricas: `GENERIC: >cartesian ( direction -- x y )` e `GENERIC: flip ( direction -- direction' )`. Vais acrescentar os métodos delas nas tarefas seguintes.

De seguida, acrescenta o método `M: cardinal` de `>cartesian`, que devolve o vetor unitário da direção indicada.

```factor
T{ cardinal { direction north } } >cartesian . .
! => 1
! => 0
! (top of stack is `y`, just below it is `x`)
```

## 2. Coordenadas cartesianas a partir das polares

Acrescenta um método `M: polar` a `>cartesian` que converte a forma polar em `(x, y)`:

```
x = magnitude * sin(bearing-in-radians)
y = magnitude * cos(bearing-in-radians)
```

```factor
T{ polar { magnitude 10 } { bearing 90 } } >cartesian . .
! => 0   (close to zero — the cosine of π/2 isn't exactly 0 in floats)
! => 10
```

## 3. Coordenadas cartesianas a partir das relativas

Acrescenta um método `M: relative` a `>cartesian`. Mas há um senão: uma marcação relativa mede-se em relação ao *rumo atual* do navio, que não faz parte do tuplo. Lê a variável `heading` (declarada na tarefa 1) com `heading get`, soma o desvio da marcação (`ahead = 0`, `starboard = 90`, `behind = 180`, `port = 270`) e produz o ponto cartesiano. Quem chama define `heading` dentro de um bloco `with-variable`.

```factor
0 heading [
    T{ relative { distance 5 } { bearing starboard } } >cartesian
] with-variable . .
! => 0   (heading 0 is north; starboard is east; (5, 0))
! => 5
```

## 4. Inverter

Acrescenta os métodos do genérico `flip` (declarado na tarefa 1) para que devolva a direção oposta.

- Para `cardinal`: north ↔ south, east ↔ west.
- Para `polar`: soma 180° à marcação (módulo 360).
- Para `relative`: ahead ↔ behind, starboard ↔ port.

```factor
T{ cardinal { direction north } } flip .
! => T{ cardinal { direction south } }

T{ polar { magnitude 10 } { bearing 90 } } flip .
! => T{ polar { magnitude 10 } { bearing 270 } }

T{ relative { distance 5 } { bearing ahead } } flip .
! => T{ relative { distance 5 } { bearing behind } }
```

## 5. Somar marcações

Define `add-bearings ( a b -- x y )`, que converte as duas direções em coordenadas cartesianas e devolve a soma. Funciona com qualquer combinação de `cardinal`, `polar` e `relative`: é a vantagem de usar um genérico para `>cartesian`.

```factor
T{ cardinal { direction north } } T{ cardinal { direction east } } add-bearings . .
! => 1
! => 1
```
