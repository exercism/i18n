# Introdução

## Erros

Os erros acontecem. Em Elixir, embora se diga muitas vezes para "let it crash", há alturas em que precisamos de resgatar a chamada à função para um estado bom conhecido, a fim de cumprir um contrato de software. Nalgumas linguagens, os erros são usados como método de controlo de fluxo, mas em Elixir este padrão é desaconselhado. Muitas vezes, conseguimos reconhecer funções que podem lançar um erro apenas pelo nome: as funções que lançam erros têm de ter `!` no fim do nome. Isto, em comparação com funções que devolvem `{:ok, value}` ou `:error`. Repara nestes exemplos da biblioteca:

```elixir
Map.fetch(%{a: 1}, :b)
# => :error
Map.fetch!(%{a: 1}, :b)
# => raises KeyError
```

## Try/Rescue

O Elixir disponibiliza uma construção para resgatar de erros usando `try .. rescue`

```elixir
try do
  raise RuntimeError, "error"
rescue
  e in RuntimeError -> :error
end
```

Vamos analisar esta construção:

- **Linha 1**, o bloco é declarado com `try`.
- **Linha 2**, a chamada à função que pode gerar um erro é colocada aqui; neste caso, estamos a chamar `raise/2`.
- **Linha 4**, na secção `rescue`, fazemos correspondência de padrões com o nome do _módulo_ do erro lançado
  - no lado esquerdo de `->`:
    - `e` corresponde à struct de erro.
    - `in` é uma palavra-chave.
    - `RuntimeError` é o erro que queremos resgatar.
      - Se quiséssemos resgatar todos os erros, podíamos usar `_` em vez do nome do módulo ou omitir completamente a palavra-chave `in`.
  - no lado direito:
    - as instruções a executar se o erro corresponder.

### Structs de erro

Os erros (às vezes também chamados "exceções") que resgatas desta forma são structs.
Resgatar erros em Elixir é algo que se faz muito raramente.
Normalmente, o erro resgatado é registado ou enviado para um serviço de monitorização externo, e depois é relançado.
Isto significa que, normalmente, não nos preocupamos com a estrutura interna da struct de erro específica.

No [conceito de Exceções][exercism-exceptions] vais aprender mais sobre structs de erro, incluindo como definir o teu próprio erro personalizado.
