# Nil

O Crystal tem um tipo chamado [`Nil`][nil], que só pode ter um valor: `nil`.
É usado para representar a ausência de um valor e é semelhante a `null` ou `None` noutras linguagens.

Os valores Nil podem ser devolvidos por vários métodos, por exemplo [`String#[]?`][string-index], que devolve `nil` se o índice estiver fora dos limites.

```crystal
"foo"[10]? # => nil
```

O Crystal tem o que é conhecido como **verificações de referências nulas**, o que significa que, por predefinição, nenhum tipo pode ser nil.
Isto significa que não podes atribuir `nil` a uma variável, a menos que a declares explicitamente como um tipo `Nil`.
Por sua vez, isto significa que o compilador vai verificar automaticamente as referências nulas.

## Valor falso

Existem várias abordagens para lidar com valores `nil`.
`nil` é um valor [falso][truthy-falsey], tal como `false`.
Isto significa que, em instruções e noutros locais onde se espera um valor falso ou verdadeiro, será tratado da mesma forma que `false`.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Isto significa que o ramo verdadeiro não será executado se uma variável que pode ser `nil` tiver o valor `nil`.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Verificar se é nil

O Crystal tem um método que podes usar para verificar se um valor é `nil`.
Chama-se [`nil?`][nil?] e está disponível em todos os objetos.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Isto é um pouco diferente de quando usas apenas o valor numa condicional, porque nos exemplos anteriores tanto false como nil eram tratados como falsos.
Aqui, só `nil` é tratado como falso, porque se fosse false não seria nil e, por isso, seria verdadeiro.

## Operador ou

A forma mais fácil de lidar com valores `nil` é garantir que nunca chegam a ser `nil`.
O operador ou ([`||`][or]) é muito usado quando trabalhas com `Bools`, mas, se o compreenderes bem, também pode ser usado para lidar com valores `nil`.
O operador ou verifica se o primeiro valor é verdadeiro; se não for, usa o segundo valor.
Isto pode ser usado para que, se o valor for `nil`, este seja falso e, por isso, seja usado o segundo valor.

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
Esta abordagem deve ser vista como um último recurso e só deve ser usada se tiveres a **certeza** de que o valor não é nil.
Se possível, usa antes as outras abordagens.
~~~~

[`not_nil!`][not_nil] é um método que te permite dizer ao compilador que um valor não é nil e que, por isso, faz com que o tipo desse valor não possa ser nil.
Faz isso lançando uma exceção se o valor for nil.

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
