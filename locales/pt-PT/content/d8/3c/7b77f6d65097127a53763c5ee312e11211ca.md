# Introdução

## Comentários

O Common Lisp permite ao programador escrever "comentários" que são ignorados pelo computador.
Os comentários de uma só linha começam com um ou mais pontos e vírgulas (`;`) e, ocasionalmente, podes ver o seguinte:

```lisp
(code...) ; => value
```

Aqui, o comentário é usado para indicar o valor que o Common Lisp devolve depois de executar o código dessa linha.

É idiomático usar um único ponto e vírgula para um comentário curto no fim de uma linha, dois para um comentário mais longo acima de uma secção de código, três para um comentário extenso que descreve algo como uma função e quatro para um comentário do tipo cabeçalho no topo de um ficheiro de código-fonte.

## Cons

Todos os objetos do Common Lisp são "átomos" (valores únicos e indivisíveis) ou "conses" (criados pela função construtora "cons").
Um cons é composto por duas partes: o primeiro elemento e o resto dos elementos.
Por razões históricas, estas duas partes chamam-se `car` e `cdr`.
Quando estes conses são avaliados como código, o primeiro elemento (`car`) representa a função que está a ser chamada, enquanto o resto dos elementos
(`cdr`) representa os argumentos dessa função:

```lisp
(<function> <arg1> <arg2> ... <argN>)
; ^ car ^  |        ^ cdr ^
```

## Expressões

Todo o código do Common Lisp é feito de S-Expressões (Expressões Simbólicas). Chamam-se sexprs, para abreviar. Cada sexpr é um átomo ou um cons. Quando as S-Expressões são avaliadas, devolvem automaticamente um valor que toma o lugar da expressão. Quando escreves as tuas próprias funções (com `defun`), o último valor dentro do corpo do `defun` é devolvido automaticamente:

```lisp
;; Defining a new function
(defun gimme-foo () 'foo)
;; Calling the function as an S-Expression
(gimme-foo) ; => FOO
```

## Símbolos

Os símbolos em Common Lisp são valores especiais que podem apontar para outros valores ou, no caso das _keywords_, para si próprios.
Quando o Lisp avalia os símbolos, estes são substituídos pelos valores para os quais apontam:

```lisp
foo  ; => <whatever-foo-points-to>
:foo ; => :FOO
```

Repara que as keywords são indicadas por dois pontos (`:`) no início.

O quoting, ou seja, a adição de `'` antes de uma S-expressão, diz ao Lisp para não avaliar essa expressão.
Ao usar quoting com `'foo` no nosso exemplo do `defun`, evitámos que o Lisp tentasse procurar (e não encontrasse) aquilo para que `FOO` deveria apontar, devolvendo, em vez disso, o próprio valor `FOO`.
Se `FOO` não estiver definido em nenhum lugar do nosso programa:

```lisp
foo  ; => <ERROR! Lisp doesn't know what foo points to!>
'foo ; => FOO
```

Por agora, podes considerar isto apenas como uma forma de devolver símbolos a partir de uma função, mas vamos voltar ao quoting e explorar melhor as suas implicações em futuros exercícios de conceitos.
