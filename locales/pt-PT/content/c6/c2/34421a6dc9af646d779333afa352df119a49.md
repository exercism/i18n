# Tipos de string

O Cairo não tem um tipo de dados nativo para strings.
No entanto, há duas formas de representar um tipo de string: strings curtas com um único `felt252` e strings de comprimento arbitrário com `ByteArray`.

## Strings curtas

Uma string curta é formada com aspas simples, onde cada caráter que compõe a string é codificado num byte segundo o [padrão ASCII][ascii-table].

Como string ASCII, por exemplo, `'abc'` será:

- `'a'` é equivalente a `0x61`
- `'b'` é equivalente a `0x62`
- `'c'` é equivalente a `0x63`
- `'abc'` é equivalente a `0x616263`

O tipo de dados `felt252` é o que guarda strings curtas em Cairo.
Como o `felt252` contém 251 bits, uma string curta está limitada a 31 carateres (31 \* 8 = 248 bits, que é o múltiplo máximo de 8 que cabe em 251 bits).

Exemplos de declarações de strings curtas:

```rust
    let my_first_char = 'D';
    let my_first_char_in_hex = 0x44;

    let my_first_string = 'Hello world';
    let my_first_string_in_hex = 0x48656C6C6F20776F726C64;
```

### ByteArray

A estrutura ByteArray foi introduzida no Cairo 2.4.0.
As strings ByteArray escrevem-se com aspas duplas, da seguinte forma:

```rust
    let long_string: ByteArray = "this is a string which has more than 31 characters";
```

Tecnicamente, a atualização também introduziu o tipo `bytes31`, que guarda 31 bytes e cabe num felt.
A estrutura `ByteArray` representa basicamente uma string longa com um array de `bytes31` que guardam as "palavras completas" (ou seja, palavras que preenchem o felt inteiro) e um único campo felt que guarda uma "palavra incompleta" (o número de bytes que contém é indicado num campo de comprimento separado).

```rust
#[derive(Drop, Clone, PartialEq, Serde, Default)]
struct ByteArray {
    data: Array<bytes31>,
    pending_word: felt252,
    pending_word_len: usize,
}
```
