# Sobre

Uma lista de palavras-chave é uma lista de [tuplas][exercism-tuples] `{key, value}`. Há duas formas de escrever uma lista de palavras-chave:

```elixir
# concise
[month: "April", year: 2018]

# explicit
[{:month, "April"}, {:year, 2018}]
```

## As chaves têm de ser átomos

Nem todas as listas de tuplas de 2 elementos são listas de palavras-chave. As chaves têm de ser átomos:

```elixir
Keyword.keyword?([{"month", "April"}])
# => false
```

Se quiseres usar na chave caracteres que não sejam letras, números e `_`, tens de a colocar entre aspas. No entanto, isso não a transforma numa string: continua a ser um átomo.

[//]: # (elixir-formatter-disable-next-block)

```elixir
Keyword.keyword?(["day of week": "Monday"])
# => true
```

## As chaves podem repetir-se

As chaves de uma lista de palavras-chave podem repetir-se, e os [pares chave-valor estão ordenados][keyword-duplicate-keys-and-ordering]. Quando tentas obter um único valor associado a uma determinada chave, obténs o primeiro valor, e quaisquer outros valores com a mesma chave são ignorados silenciosamente.

```elixir
list = [month: "April", month: "May"]

Keyword.get_values(list, :month)
# => ["April", "May"]

Keyword.get(list, :month)
# => "April"
```

As listas de palavras-chave também suportam o [_comportamento Access_][access-behaviour].

```elixir
list[:month]
# => "April"
```

## Listas de palavras-chave como opções

As características das listas de palavras-chave fizeram delas o mecanismo predefinido para passar opções a funções em Elixir.

Quando aprendeste o `if`, viste uma sintaxe especial mais curta:

```elixir
if age >= 16, do: "beer", else: "no beer"
```

Isto pode parecer que o `if` aceita dois argumentos, mas o par `do:` e `else:` é, na verdade, um único argumento: uma lista de palavras-chave. O mesmo código poderia ser escrito assim:

[//]: # (elixir-formatter-disable-next-block)

```elixir
if age >= 16, [do: "beer", else: "no beer"]
# or
if age >= 16, [{:do, "beer"}, {:else, "no beer"}]
```

O uso de listas de palavras-chave como opções de funções é tão comum que o Elixir te permite [omitir os parênteses retos quando a lista de palavras-chave é o último argumento][keyword-call-syntax] passado a uma função.

Como as tuplas, as listas, os mapas e outros são tratados da mesma forma que as chamadas de funções na sintaxe do Elixir, esta propriedade também está disponível para eles.

```elixir
[1, 2, three: 3]
# => [1, 2, {:three, 3}]
```

## Correspondência de padrões

Para fazer correspondência de padrões com êxito numa lista de palavras-chave usando a sintaxe concisa, terias de especificar todas as chaves pela ordem correta. Isso torna a correspondência de padrões uma escolha pouco provável para trabalhar com listas de palavras-chave. Usa antes o módulo [`Keyword`][keyword] ou o [_comportamento Access_][access-behaviour].

```elixir
[month: month] = [month: "April", year: 2018]
# => ** (MatchError) no match of right hand side value: [month: "April", year: 2018]

[year: year, month: month] = [month: "April", year: 2018]
# => ** (MatchError) no match of right hand side value: [month: "April", year: 2018]
```

## Listas de palavras-chave vs mapas

|                  | Keyword list                  | Map                                 |
| ---------------- | ----------------------------- | ----------------------------------- |
| Key type         | Atoms                         | Any, can be mixed in one map        |
| Duplicate keys   | Yes                           | No                                  |
| Keys ordered     | Yes                           | No                                  |
| Access           | `list[:key]`, `Keyword.get/2` | `map.key`, `map[:key]`, `Map.get/2` |
| Access time      | Linear                        | Logarithmic                         |
| Pattern matching | Not very useful               | Useful                              |

Um tempo de acesso mais rápido, um tipo de chave flexível e uma correspondência de padrões útil fazem dos mapas a escolha predefinida na maioria dos casos.

Usa listas de palavras-chave quando não tens muitos dados, mas precisas de chaves duplicadas ou de chaves numa ordem específica.
