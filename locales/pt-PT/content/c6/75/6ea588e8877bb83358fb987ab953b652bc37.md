# Introdução

O sistema de erros do Factor tem três peças: `throw` para sinalizar um erro,
`recover` para tratar de um, e `ERROR:` para definires o teu próprio tipo de
erro.

## `throw`

`throw` (em [`kernel`][kernel]) lança um erro. O argumento pode ser
*qualquer* valor, uma string, um número ou um tuplo, e torna-se no
erro que podes inspecionar mais tarde:

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw` não devolve nada; o resto da word atual é ignorado.

## `recover`

`recover` (em [`continuations`][continuations]) é o try/catch do Factor.
Recebe uma quotation *try* e uma quotation *recovery*:

```
recover ( try recovery -- )
```

Se a `try` terminar sem lançar nada, a `recovery` é ignorada. Se a `try`
lançar um erro, o erro é colocado na pilha e a `recovery` é executada:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

O `when` de [`kernel`][kernel] é o companheiro natural: só executa uma
quotation quando o topo da pilha é verdadeiro:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:` define uma classe de tuplo *e* uma word que constrói uma
instância nova e a lança:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

Um erro sem slots é apenas `ERROR: name ;`: chamar `name` lança uma
instância vazia. Os tuplos definidos com `ERROR:` trazem um predicado
de classe `name?` que podes usar para testar se um erro capturado era
desse tipo.

## Ler os slots de volta

Um erro capturado é apenas um tuplo, por isso cada slot de `ERROR:`
vem com o mesmo leitor `slot>>` gerado automaticamente que qualquer
outro tuplo.

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
