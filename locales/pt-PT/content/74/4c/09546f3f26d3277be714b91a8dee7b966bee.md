# Introdução

## Aplicação parcial

Em Elm, todas as funções são [currificadas][currying], o que significa que, se chamares uma função sem passar todos os argumentos, ela devolve uma nova função.

O resultado disto chama-se [aplicação parcial][partial-application] (não estás a passar todos os argumentos à função, mas sim a aplicar parcialmente alguns deles).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

A aplicação parcial aplica sempre os argumentos por ordem.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## Operador de pipe (`|>`)

Escrever `x |> f` é exatamente o mesmo que escrever `f x`. Um exemplo concreto: `"5" |> String.toInt` é o mesmo que `String.toInt "5"`.

À primeira vista, isto não parece muito útil, mas chama-se [operador de pipe][pipe-operator] porque te permite escrever código encadeado.

Por exemplo, imagina que temos uma função sanitize para transformar a entrada do utilizador em números inteiros:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Podemos reescrevê-la assim:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Isto evita o uso de parênteses e mostra as funções pela ordem em que são aplicadas (primeiro `String.trim`, depois `String.toInt`), o que facilita a leitura.

Existe também um [operador de pipe inverso `(<|)`][reverse-pipe-operator].
Escrever `f <| x` é exatamente o mesmo que escrever `f x`.
À primeira vista, isto também não parece muito útil e não é de certeza tão usado como o operador de pipe, mas ajuda a evitar parênteses em algumas situações.

## Composição de funções / estilo point free

O operador [`(>>)`][forward-composition] tem o tipo `(a -> b) -> (b -> c) -> (a -> c)` e cria uma função do tipo `a -> c` compondo duas funções compatíveis, uma do tipo `a -> b `e outra do tipo `b -> c`.
Faz isto tomando a saída (do tipo `b`) da primeira função e usando-a como primeiro argumento da segunda função (que tem de ser do mesmo tipo `b`).
A função criada recebe a mesma entrada (do tipo `a`) que a primeira função e devolve o `c` que a segunda função devolver.

Um exemplo concreto é `String.trim >> String.toInt`.
`String.trim` recebe uma string como único parâmetro, por isso é isto que a função criada recebe.
`String.toInt` devolve um `Maybe Int`, por isso é isto que a função criada devolve.
`String.trim` devolve uma `String`, que `String.toInt` aceita como parâmetro, por isso o exemplo compila.

Agora podemos reescrever a nossa função `sanitize` da seguinte forma:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Repara que já não usamos o parâmetro `input` que aparece no exemplo original, embora a funcionalidade seja idêntica.
Esta forma de criar funções que não fazem referência aos seus parâmetros chama-se "estilo point free".
A vantagem deste estilo é que o código é mais conciso; a desvantagem é que pode ser mais difícil de entender, sobretudo para quem está a começar.

Vale a pena lembrar que, em Elm, todas as funções são currificadas, por isso `String.length >> max` compila.

- O operador [`(>>)`][forward-composition] tem o tipo `(a -> b) -> (b -> c) -> (a -> c)`.
- `String.length` tem o tipo `String -> Int`, que é a parte `(a -> b)`, por isso `a` é `String` e `b` é - `Int`.
- `max` tem o tipo `Int -> Int -> Int`, que é a parte `b -> c`.
- `b` é `Int`, por isso `max` é aplicada parcialmente, e `c` é o resultado dessa aplicação parcial (`Int -> Int`).
- Assim, o tipo de `String.length >> max` é `String -> (Int -> Int)`.
- Assim, `((String.length >> max) "123") 2` devolve `3`, porque `"123"` tem comprimento 3, que é maior do que o 2 do argumento `Int`.

## Conceção de funções

Para ser mais fácil escrever código elegante em Elm, deves fazer da estrutura de dados principal o último parâmetro das funções.
Todas as funções comuns da biblioteca padrão fazem isto, como `List.map` (a assinatura de tipo está abaixo).

```elm
map : (a -> b) -> List a -> List b
```

Aqui podemos ver que o último parâmetro da função `map` é `List a` e que devolve `List b`, por isso a estrutura de dados principal (`List`) é o último parâmetro.

Isto torna possível escrever código encadeado elegante, como o exemplo abaixo.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Também torna conveniente usar a composição de funções e o estilo point free, como alternativa ao encadeamento.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

A composição de funções também te permite reduzir este exemplo a uma única chamada a `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
