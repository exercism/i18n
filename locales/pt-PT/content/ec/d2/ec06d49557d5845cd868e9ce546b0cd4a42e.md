# Sobre

A entrada/saída (I/O) do Factor assenta num único [protocolo][stream-protocol] que qualquer fonte ou destino de dados pode implementar. Os fluxos incluídos — `<file-reader>`, `<file-writer>`, `<string-reader>`, `<string-writer>`, sockets de rede, arrays de bytes, ttys — são todos classes que implementam o mesmo pequeno conjunto de genéricos de [`io`][io] e estendem `disposable` de [`destructors`][destructors].

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe` é a leitura em lote de baixo nível: preenche um buffer fornecido por quem chama e devolve quantos elementos foram escritos. Os métodos públicos `stream-read` e `stream-read-partial` assentam nele e tratam da alocação. A maioria dos fluxos definidos pelo utilizador implementa `stream-read1` (quando as leituras acontecem um elemento de cada vez) ou `stream-read-unsafe` (quando as leituras podem ser feitas em lote).

`stream-element-type` devolve um de dois tokens singleton: `+byte+` para fluxos de bytes (leitores de ficheiros, sockets) e `+character+` para fluxos de carateres (leitores de strings, ttys). Um fluxo que envolve outro costuma limitar-se a delegar no fluxo subjacente.

## Aderir aos mixins

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

Uma classe pode ser uma coisa, a outra, ou ambas. Aderir ao mixin faz com que os métodos predefinidos de `input-stream` / `output-stream` sejam encaminhados para a tua classe, o mesmo padrão de mixin aberto que `set` do vocabulário `sets`.

## O framework disposable

`new-disposable ( class -- disposable )` regista uma nova instância no âmbito do destrutor atual, para que uma exceção a meio da preparação de um recurso se desenrole de forma limpa:

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose` é a palavra pública; `dispose*` é o genérico que a classe implementa. Uma subclasse que redefina `dispose*` deve limpar o seu próprio estado e depois libertar os recursos que detém:

```factor
M: my-stream dispose* underlying>> dispose ;
```

O framework garante que `dispose*` é executado no máximo uma vez por objeto; chamadas repetidas a `dispose` não fazem nada.

## Acessores com âmbito

Três combinadores configuram o "fluxo de entrada/saída atual" global usado por `print`, `read1`, etc.:

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

Cada um deles liberta o recurso ao sair, mesmo que a quotation lance uma exceção. É assim que a maior parte do código usa um fluxo personalizado, em vez de o passar por todas as chamadas.
