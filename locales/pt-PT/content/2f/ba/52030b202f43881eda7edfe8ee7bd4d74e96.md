# Introdução

## Strings

### Carateres

Uma **codificação de carateres** é uma convenção específica usada para representar elementos de texto de uma língua natural como uma sequência de bytes.
Um «elemento de texto» pode aqui ser qualquer unidade com significado numa língua natural, por exemplo, letras, espaços, pontuação, emojis, ideogramas, etc.

O NASM (The Netwide Assembler, o assembler usado neste percurso) tem suporte para a definição de dados com **ASCII**.

As constantes de carateres em NASM podem ter até 8 bytes de comprimento e podem ser definidas com aspas simples (`'`), aspas duplas (`"`) ou acentos graves (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Os carateres especiais têm de ser definidos entre acentos graves e escapados com `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Repara que não existe suporte nativo para qualquer codificação de carateres em x86-64 como um tipo distinto.
Os dados em assembly são uma sequência de bytes, e a interpretação desses bytes como um caráter, um número ou qualquer outra coisa fica a cargo do programador.

Por exemplo, o caráter ASCII '0' é um único byte com o valor 48.
Assim, guardar 48 num byte é exatamente o mesmo que guardar o caráter ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Por esta mesma razão, a manipulação de carateres faz-se transformando diretamente os valores desses bytes:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### Strings

Uma **string** é uma sequência de carateres.
Em assembly, é normalmente implementada como um array.

É possível declarar uma string em NASM da mesma forma que se declararia qualquer array:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Uma diferença entre strings e outros arrays é que o NASM também suporta a declaração de strings sem uma vírgula (`,`) a separar os valores.
Também é possível intercalar valores com vírgulas:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Repara que, como já foi mencionado, os carateres são apenas bytes (ou uma sequência de bytes numa codificação Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Como cada caráter ASCII ocupa um único byte, qualquer byte seguinte numa largura maior é `0`.
Por exemplo, declarar `'a'` como um qword (8 bytes) significa que o primeiro byte é `'a'` (`97`) e os outros sete bytes são todos `0`.

Por esta razão, todos os seguintes são equivalentes:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
Em assembly, as strings não são terminadas automaticamente por um caráter NUL ASCII (valor `0`).

Ao interagir com linguagens de nível superior, como C, é responsabilidade do programador garantir que o terminador correto, se existir, é acrescentado ao fim de uma string.
~~~~

### Instruções de string

Como as strings são arrays, podes trabalhar com elas da mesma forma que com qualquer array, desreferenciando explicitamente a memória:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Além disso, existem algumas instruções para carregar, mover e guardar valores em sequências de bytes na memória.
Apesar de se chamarem _instruções de string_, podem ser usadas com qualquer sequência de bytes na memória, ou seja, com qualquer array.

As três instruções de string mais importantes são `lods`, `stos` e `movs`:

| instrução | o que faz                                                                                                          |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | carrega um valor de um endereço de memória indicado por `rsi` para `rax`                                          |
| `stos`      | guarda um valor de `rax` num endereço de memória indicado por `rdi`                                               |
| `movs`      | copia um valor de um endereço de memória indicado por `rsi` e guarda-o num endereço de memória indicado por `rdi` |

Repara que estas instruções _não_ recebem nenhum operando explícito.
Os seus operandos são implícitos.

Como regra geral:

1. Quando o seu operando de origem é um endereço de memória, o seu endereço deve ser guardado em `rsi` (`s` de source).
2. Quando o seu operando de destino é um endereço de memória, o seu endereço deve ser guardado em `rdi` (`d` de destination).
3. Se um dos operandos não for um endereço de memória, é o registo `rax`.

Repara que estas instruções desreferenciam automaticamente os endereços de memória de acordo com a operação específica que realizam.

Todas elas podem operar em tamanhos diferentes.
É acrescentado um sufixo para indicar esse tamanho:

| sufixo | significado | tamanho |
| :----: | ------- | :------ |
|  `b`   | byte    | 1 byte  |
|  `w`   | word    | 2 bytes |
|  `d`   | dword   | 4 bytes |
|  `q`   | qword   | 8 bytes |

Por exemplo:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

Também atualizam qualquer endereço usado pelo tamanho da operação.
Esta atualização é feita de acordo com o valor do **direction flag (DF)**:

- Se o `DF` estiver limpo, os endereços são _aumentados_ pelo tamanho da operação.
- Se o `DF` estiver definido, os endereços são, em vez disso, _diminuídos_ na mesma quantidade.

A ABI System V determina que o direction flag tem de estar limpo à entrada de uma função.
Assim, _o comportamento predefinido é que a memória seja lida/escrita por ordem crescente de endereços_.

A instrução `cld` pode ser usada para limpar o direction flag, enquanto a instrução `std` o define:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Quem chama espera que o `DF` esteja limpo depois de qualquer função chamada retornar, segundo a ABI System V.
Se alguma vez definires o `DF`, certifica-te de que o limpas antes do `ret`.
~~~~

#### Rep

Para além dessas, a instrução **rep** não interage diretamente com a memória.
Em vez disso, pode ser adicionada como prefixo às outras instruções mencionadas, _repetindo_ essas instruções.

Quando precedidas de `rep`, as instruções de string são repetidas um número de vezes igual ao valor em `rcx`.
De cada vez, o valor em `rcx` é diminuído em `1`.
Repara que o valor em `rcx` tem de ser definido antes de a instrução ser usada:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
Nas CPUs modernas, `rep movs` e `rep stos` são normalmente opções rápidas para mover dados em blocos grandes.
No entanto, outras instruções de string, e até `movs` e `stos` quando operam sem `rep`, são normalmente mais lentas do que um ciclo simples.

Uma visão mais aprofundada sobre este tema pode ser encontrada no [Capítulo 16.9, «Instruções de string», deste livro de referência][agner-optimization-guide].
