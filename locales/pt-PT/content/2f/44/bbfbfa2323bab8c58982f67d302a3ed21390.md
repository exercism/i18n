# golint não satisfeito

Existe uma ferramenta muito boa chamada [`golint`](https://github.com/golang/lint) que analisa o código à procura de problemas comuns e de questões de estilo.
Corre o `golint` sobre a solução, por exemplo: `golint two_fer.go`; ele vai dar-te sugestões úteis.

É boa ideia verificar sempre o código com o `golint`.
Quando escreves software Go para produção, muitas pipelines de compilação falham automaticamente se o código não passar no `golint`.

Se quiseres receber muito mais feedback de linters de código, existe o projeto [golangci-lint](https://github.com/golangci/golangci-lint)
que te permite correr muitos linters com um único comando.
Um ficheiro de configuração do projeto pode ajustar o comportamento às necessidades do projeto.

```
> golint
%{golint}
```
