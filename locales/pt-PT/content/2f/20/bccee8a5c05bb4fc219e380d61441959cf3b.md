# Diretrizes de contribuição

Se queres participar no desenvolvimento do track Pharo, segue as instruções abaixo, que te vão ajudar a começar.

Estamos empenhados em melhorar este track e mostrar aos programadores uma forma diferente de pensar em programação! :tada:

Lê como [envolver-te num track do Exercism](https://github.com/exercism/docs/tree/master/contributing-to-language-tracks) e não deixes também de ler o [Código de Conduta do Exercism](https://exercism.io/code-of-conduct).

Aceitamos pull requests de todos os tipos. Nenhuma contribuição é demasiado pequena, sobretudo as que trazem correções e melhorias aos exercícios existentes. Tem em conta que os exercícios deste track têm de cumprir os [padrões do Exercism](https://github.com/exercism/docs/tree/master/language-tracks/exercises), mas se não tiveres a certeza de como fazer uma alteração, abre uma issue no GitHub e falamos sobre isso.

>__Nota__: A organização do Exercism decidiu [suspender as contribuições da comunidade alargada do Exercism](https://exercism.org/blog/freeing-our-maintainers). O track Pharo está excluído desta política, uma vez que a nossa comunidade é bastante pequena (por outras palavras: qualquer contribuidor do track Pharo pode continuar a criar issues e a submeter PRs).

## Pré-requisitos de conhecimento

Espera-se que já estejas [familiarizado](./docs/RESOURCES.md) com o desenvolvimento em Pharo e com a utilização do [Iceberg Git](https://github.com/pharo-vcs/iceberg).

## Preparar o ambiente de desenvolvimento

Para começar, garante que tens um ambiente de desenvolvimento do Exercism completo e os seguintes artefactos instalados:

### __Imagem Pharo e IDE__

Precisas de ter um ambiente de desenvolvimento Pharo (uma imagem Pharo a correr - a IDE) para criares os exemplos de código propriamente ditos.

1. Usa o [PharoLauncher](https://pharo.org/download) para criar uma imagem de desenvolvimento estável nova a partir da categoria `Official distributions` (à data de 05/24, a imagem estável é: Pharo 12.0 - 64bit (stable)) e inicia-a (também podes usar o [zerconf](https://get.pharo.org/), se estiveres familiarizado com ele).
2. Inicia a tua imagem para testar se tudo corre bem.

> __Nota__: Se tiveres problemas de TIMEOUT, consulta as [instruções de instalação para utilizadores](./docs/INSTALLATION.md).

### __Configurar os repositórios git__

1. Se ainda não o fizeste, faz fork de `https://exercism/pharo-smalltalk` no GitHub.
2. Para clonar o teu fork, avalia o seguinte comando no Playground da imagem Pharo a correr:
```
Metacello new
 baseline: 'Exercism';
 repository: 'github://exercism/pharo-smalltalk:main/releases/latest';
 load: 'dev'
```
Isto vai efetivamente clonar o repositório git do track Pharo e carregar o código-fonte do track Pharo para a imagem Pharo - a sua baseline de desenvolvimento. A pasta local com o repositório clonado ficará localizada em (dependendo das tuas preferências do Iceberg): `<path-to-Pharo-image>/pharo-local/iceberg/<your-id/pharo-smalltalk`.
> __Nota__: As fontes da imagem Pharo são sincronizadas e serializadas em ficheiros `*.st` localizados na subpasta `src` do diretório acima referido.

2. Outra forma de fazer o mesmo é clonar o teu fork através da CLI: `git clone https://github.com/<your id>/pharo-smalltalk` como um projeto GitHub e especificar `<your id>` como o nome do proprietário e `pharo-smalltalk` como o nome do projeto.
Depois, instala a baseline `dev` do Metacello (não a predefinida) no Iceberg, usando o menu de contexto do Metacello da imagem Pharo a correr. (por exemplo, clica com o botão direito no projeto "pharo-smalltalk" que acabaste de clonar, seleciona a segunda opção do menu do Metacello e escreve `dev`)

3. Depois de carregar o projeto para a imagem Pharo, não te esqueças de __guardar a imagem__ (opção de menu Pharo -> Save).

__Repositórios opcionais__
1. Em alternativa, podes fazer `git clone https://github.com/exercism/pharo-smalltalk` como repositório de staging onde vais gerar exercícios e recursos para registar (separadamente da programação em Pharo). Tem em conta que as alterações geradas pela ferramenta Configlet neste repositório terão de ser copiadas para o teu repositório fork local. A sugestão é usar algo como `~/development/exercism/pharo-staging` para evitar confusões (nota: pode ficar em qualquer sítio). Este repositório não é necessário; podes continuar a gerar as alterações do configlet diretamente no teu repositório fork (que está sincronizado com a tua imagem Pharo), se tiveres a certeza de que alterações incluir no commit.
2. Também podes clonar as [especificações de problemas](https://github.com/exercism/problem-specifications) do Exercism, caso queiras trabalhar em exercícios de prática de raiz. Coloca-as também numa subpasta do workspace do exercism configurado abaixo (este repositório é usado para gerar os ficheiros readme.md dos exercícios e é uma referência para os testes sugeridos).

### __Nota sobre os ramos de repositório usados__

O ramo `main` é o ramo de desenvolvimento principal, para o qual tudo é integrado. Se trabalhares nalguma alteração no código, cria um ramo de funcionalidade a partir do main e faz aí os teus commits. Quando terminares, abre um PR no GitHub para ser integrado no `main` do repositório base (Exercism/pharo-smalltalk). Este ramo costumava chamar-se `master` - __agora obsoleto__.

### __Configurar as ferramentas CLI do Exercism__

Estas ferramentas são necessárias para interagir com o projeto Exercism:
1. a [interface de linha de comandos do exercism](https://exercism.io/cli-walkthrough) e configurá-la para o diretório de desenvolvimento dos exercícios do Exercism, chamado workspace (por exemplo, `exercism configure -w ~/development/exercism`). Este pode ser o caminho para o teu repositório fork local ou para o repositório de staging (opcional).
2. o [configlet](https://github.com/exercism/configlet#usage) do Exercism, o linter/gerador para gerar metadados dos exercícios e executar validações. Para instalar o Configlet, segue as instruções na secção [Utilização no teu track](https://github.com/exercism/configlet#use-in-your-track) (ver bin/fetch-configlet).

## Trabalhar nos exercícios do Exercism

A organização do Exercism distingue entre exercícios de conceito (que explicam teoria das linguagens de programação) e exercícios de prática. Por agora, os parágrafos abaixo focam-se apenas na contribuição para exercícios de prática.

### __Visão geral__

Passos para completar um exercício:
1a. Criar um exercício de prática de raiz (a partir das especificações de problemas).
1b. Trabalhar na solução de um exercício de prática existente.
2a. Gerar os ficheiros-fonte serializados da solução do exercício para um diretório e gerar os metadados do exercício.
2b. Ajustar a baseline do projeto para incluir o exercício recém-concluído como parte do projeto.
3. Fazer commit das alterações no teu repositório fork e publicar as alterações abrindo um PR.

#### TL;DR: Guia rápido para gerar e exportar um exercício de prática
Resumindo: só precisas de gerar e exportar o exercício a partir do Pharo; executa no Playground:
```Smalltalk
"Obtain exercise from problem specification"
ExercismExerciseGenerator new generateExerciseFrom: 'path-to-problem-specifications/exercises/slug-name' asFileReference.

"Update exercise version within Pharo image  (with updated test cases) to output exercise directory (once you have solution class defined)"
ExercismGenerator new 
	exercisesDirReference: 'path-to-local-repository/exercises/practice' asFileReference;
	generateForExercise: 'slug-name'.
```
  > __Nota__: Mais detalhes nos passos abaixo. 

![Fluxo de trabalho para completar um exercício de prática](/docs/images/overview-exercism-pharo-contribution.svg)

### __1. Criar um novo exercício de prática__
*TL;DR: Todos os detalhes e a descrição da API relacionados com a geração de exercícios encontram-se no comentário de classe da classe `ExercismExerciseGenerator`.*  

__Novos exercícios a partir do repositório de problemas__
- Se quiseres começar um exercício de prática completamente novo (passo 1a.), podes usar o repositório de especificações de problemas e gerar a classe de teste para o exercício em questão, executando:
`ExercismExerciseGenerator generateFrom: <path-to-problem-specifications/exercises>` - isto vai gerar as classes de teste para todos os exercícios do repositório de especificações de problemas no pacote `ExerciseWIP`.  

  > __Nota__: Podes usar a opção de menu da imagem Pharo para fazer o mesmo (menu World -> Exercism -> Generate test cases).
- Mais concretamente, podes gerar a classe de teste de um exercício específico com: `ExercismExerciseGenerator generateExerciseFrom: '<path-to-problem-specifications/exercises/slug-name>' asFileReference`.

O resultado da instrução anterior será uma nova classe de teste `<SlugNameTest>` (uma subclasse de ExercismTest) com os métodos de teste gerados no pacote `ExerciseWIP`.

__Regenerar um exercício existente a partir do repositório de problemas__
Se quiseres regenerar os métodos de teste de um exercício existente (já definido no pacote de solução - por exemplo, `Exercise@TwoFer`), podes usar o seguinte código. Tem em conta que os outros métodos não serão alterados (por exemplo, uuid, version, etc.) 

 `ExercismExerciseGenerator new regenerateExerciseFrom: 'path-to-problem-specifications/exercises/exercise-slug' asFileReference`

__De raiz__  
Se tiveres uma ideia interessante, consulta a documentação sobre como adicionar novos exercícios.

Há um exemplo de um exercício definido pelo utilizador no projeto, vê: `DieTest`. Ao sobrepor o método customData, o gerador cria os ficheiros relevantes por ti.

Tem em conta que:
- Cada exercício tem de ser autónomo. Não faças referência a ficheiros fora do diretório do exercício. Eles não serão incluídos quando o utilizador obtém o exercício.
- Os exercícios têm de cumprir os [padrões do Exercism](https://exercism.org/docs/building/tracks/practice-exercises).
- Os exercícios devem usar apenas as bibliotecas base do Pharo.
- Cada exercício deve:
  - estar guardado num projeto de nível superior chamado `Exercism@<ExerciseName>`
  - ter um TestCase chamado `<ExerciseName>Test` (em CamelCase) e uma solução de exemplo chamada `<ExerciseName>`
  - o TestCase deve ter um comentário de classe em formato markdown que descreva o exercício. Este texto é também usado para gerar um ficheiro README.md.
- Não faças commit de ficheiros ou diretórios de configuração dentro do exercício (isto pode ser revisto para exercícios futuros; avisa-nos se se tornar um problema).
- Certifica-te de que geras um novo UUID para o exercício com `UUIDGenerator next` e coloca esse valor no método `uuid` do teste.

> __Nota__: Infelizmente, o atual gerador de UUID do Pharo não é compatível com a RFC 4122 - versão 4. Por isso, deves usar o UUID gerado pelo configlet, avaliando: `/bin/configlet uuid`

### __2. Trabalhar num exercício existente__

Embora haja muitas formas de ajudar, de longe a contribuição mais fácil e mais útil é completar uma solução para qualquer um dos exercícios atualmente "abertos".

  * Garante que a tua imagem está atualizada em relação ao main do exercism/pharo-smalltalk (e envia quaisquer alterações de volta para o teu fork)

  * Os exercícios são todos TestCases gerados automaticamente a partir do repositório de especificações de problemas acima referido. Vais encontrá-los como subclasses de ExercismTest no pacote ExercismWIP. Tem em conta que o ExercismTest regenerado pode já estar no pacote do exercício em questão, se a solução já existir. O pacote ExercismWIP é usado para os exercícios novos ou em curso que ainda não foram publicados, juntamente com a classe de solução.

  * Depois de escolheres um exercício em que queres trabalhar, cria uma issue no GitHub com o título "Convert Exercise <name>". Isto avisa os outros de que estás a trabalhar nele e também serve de base para o teu pull request posterior.

  * Cada exercício em curso já tem a descrição do problema no seu comentário de classe; tu executas os testes e aplicas TDD até chegar a uma solução (no depurador, se executares o primeiro teste isoladamente).

  * Pode ser preciso __ajustar o teste se este não for Smalltalk idiomático__ (o nosso gerador é bastante básico; no entanto, algumas correções podem ser apropriadas como PRs para o texto original das [especificações de problemas](https://github.com/exercism/problem-specifications)).

  * Atualiza os metadados do exercício no lado da classe, sobrepondo o método #exercise e preenchendo a dificuldade, os tópicos, etc. Deves também preencher algum texto de dica no separador de comentário do Test (em baixo - substituindo o texto TBD)

  * Atualiza o pacote do exemplo escolhido para `Exercise@<ExerciseName>` (ou seja, tira-o do pacote WIP) - passo 1b.
  * Cria um novo ramo no Iceberg com o nome do exercício que escolheste (podes usar a ferramenta Iceberg para isso e introduzir o número da issue de cima).
  * Antes de submeteres o teu pull request, executa todos os testes dos exercícios de Pharo e garante que __passam todos__.


### Testes

Ao nível mais básico, o Exercism é tudo sobre os testes e sobre testar com [conjuntos de testes](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md).

Os exercícios de Pharo do Exercism estão organizados em subpacotes, cada um dos quais contém um TestCase que tem de ser compatível com o [SUnit](https://en.wikipedia.org/wiki/SUnit). Esta é a biblioteca xUnit original e não são necessários frameworks adicionais de terceiros para os exercícios.

Para testar um exercício, executa-o a partir do test runner incorporado, clicando no orb de teste. O orb fica verde se os testes passarem, ou laranja ou vermelho se houver falhas ou erros, respetivamente. Em alternativa, podes executar os testes manualmente no playground, avaliando:

```smalltalk
<ExerciseName>Test suite run. "single exercise"

AllExercismTests suite run. "all exercises"
```
> __Nota:__ Se quiseres definir o teu próprio caso de teste (não gerado), podes colocá-lo no protocolo `extra` da classe de teste.
Por uma questão de consistência, usamos a ordem dos parâmetros de teste: `self assert: actual equals: expected` no método de teste.


Para testar numa imagem que não seja de desenvolvimento, deves seguir os [passos de instalação para utilizadores](./docs/INSTALLATION.md). Se
estiveres a usar essa imagem para testar baselines de desenvolvimento subsequentes, pode ser preciso eliminares os seguintes diretórios de desenvolvimento para garantir que obténs o código mais recente:
`./pharo/pharo-local/iceberg, ./pharo/pharo-local/package-cache`


### __3. Publicar um exercício concluído__

Agora que terminaste a solução e fizeste os commits no teu ramo de funcionalidade local, deves completar estes passos:  
#### Gerar o código-fonte do exercício
Isto refere-se ao passo 2a: __gerar os ficheiros de código-fonte__ da solução e da(s) classe(s) de teste.

__Gerar os ficheiros de saída para todos os exercícios__ 
- `ExercismGenerator generate` -> isto vai gerar todos os ficheiros-fonte de todos os exercícios. Vai executar o comando `generate` do configlet e também regerar o `config.json`, que lista todos os exercícios válidos. (Ou, no menu World, escolhe: "Exercism" -> "Regenerate meta data")

#### Gerar os ficheiros de saída para um exercício específico
- Para usar o diretório predefinido (`repository-root/exercises/practice`)
```
ExercismGenerator new generateForExercise: 'slug-name'
```

Quando for necessário exportar para um diretório de exercício específico:
```
ExercismGenerator new 
	exercisesDirReference: 'path-to-exercises/practice' asFileReference;
	generateForExercise: 'slug-name'
```

> __Notas__: 
  - O ExercismGenerator atualiza automaticamente o config.json principal (cria um novo, se não existir).
  - sincroniza todos os docs, metadados e caminhos de ficheiro do(s) exercício(s) especificado(s), usando o comando do configlet. Ver detalhes: [Utilizar o sync ao adicionar um novo exercício](https://github.com/exercism/configlet#using-sync-when-adding-a-new-exercise-to-a-track)

#### Atualizar a baseline do projeto Pharo-smalltalk
Passo 2b: Atualiza a baseline do projeto Pharo-smalltalk adicionando o nome do exercício à lista do método `BaselineOfExercism>>exercisePackageNames`. Isto garante que o teu exercício é carregado quando o projeto é carregado, incluindo o novo exercício, através do comando do Metacello.
  
#### Submeter um Pull Request
Passo 3: Antes de criares o PR, deves verificar se os artefactos do Exercism estão corretos, executando o comando de CLI:
`bin/configlet lint` (a automatização de CI vai executar o linting de qualquer forma, quando o PR for submetido).  
Se estiver tudo bem, podes criar o PR:
- envia o teu ramo para o teu fork e cria depois um pull request em `exercism/pharo-Smalltalk` 

> __Detalhes finais__: 

- É importante [permitir as edições dos maintainers](https://help.github.com/en/articles/allowing-changes-to-a-pull-request-branch-created-from-a-fork), para que possamos colaborar contigo no teu ramo.
-  Os pull requests devem focar-se num único exercício, numa única issue ou numa alteração conceptualmente coerente. Consulta as [diretrizes de pull request](https://github.com/exercism/docs/tree/main/building/github#guides) do Exercism para mais detalhes.
- Acompanha o teu PR e responde a quaisquer perguntas que surjam.
- Por fim, submete quaisquer ajustes e um maintainer vai integrar o teu Pull Request para que a solução final apareça no site.

## Informações adicionais para maintainers

### Estilo de código

O código neste repositório deve seguir as convenções do [Pharo with style](https://github.com/SquareBracketAssociates/Booklet-PharoWithStyle) sempre que possível. Também podes consultar o mais genérico [Smalltalk with style](http://sdmeta.gforge.inria.fr/FreeBooks/WithStyle/SmalltalkWithStyle.pdf).

Deves também usar o formatador de código incorporado (meta-t FO no editor) quando crias exercícios, bem como as críticas de código.

### Alterações disruptivas

Se planeias fazer alterações significativas ou disruptivas, abre uma issue para podermos discuti-las antes de integrar. Se esta discussão for relevante para mais do que apenas o track Pharo, abre também uma issue em [exercism/discussions](https://github.com/exercism/discussions/issues).
