# Introdução

Tal como muitas outras linguagens, o Go tem ponteiros.
Se és novo no que toca a ponteiros, podem parecer um pouco misteriosos, mas assim que te habituares a eles vão parecer-te bastante simples.
São uma parte crucial do Go, por isso dedica algum tempo a compreendê-los bem.

Antes de entrar nos detalhes, vale a pena perceber para que servem os ponteiros.
Os ponteiros são uma forma de partilhar memória com outras partes do nosso programa, o que é útil por duas grandes razões:

1. Quando temos grandes quantidades de dados, fazer cópias para passar entre funções é muito ineficiente.
   Ao passar em vez disso a localização de memória onde os dados estão guardados, conseguimos reduzir drasticamente o consumo de recursos dos nossos programas.
2. Ao passar ponteiros entre funções, conseguimos aceder e modificar diretamente a única cópia dos dados, o que significa que quaisquer alterações feitas por uma função ficam imediatamente visíveis para as outras partes do programa quando a função termina.

## Variáveis e memória

Digamos que temos uma variável inteira normal `a`:

```go
var a int
```

Quando declaramos uma variável, o Go tem de encontrar um lugar na memória para guardar o seu valor.
Isto está em grande parte abstraído de nós: quando precisamos de obter o valor guardado nesse pedaço de memória, basta-nos usar o nome da variável.

Por exemplo, quando escrevemos `a + 2`, estamos efetivamente a obter o valor guardado na memória associada à variável `a` e a somar-lhe 2.

Do mesmo modo, quando precisamos de alterar o valor no pedaço de memória de `a`, podemos usar o nome da variável para fazer uma atribuição:

```go
a = 3
```

O pedaço de memória associado a `a` passa agora a guardar o valor `3`.

## Ponteiros

Embora as variáveis nos permitam referir valores na memória, por vezes é útil saber o **endereço de memória** para o qual a variável aponta. Os **ponteiros** guardam os endereços de memória desses valores.
Declaras uma variável com um tipo ponteiro ao colocar um asterisco antes do tipo subjacente:

```go
var p *int // 'p' contains the memory address of an integer
```

Aqui declaramos uma variável `p` do tipo "ponteiro para int" (`*int`).
Isto significa que `p` vai guardar o endereço de memória de um inteiro.
O valor zero dos ponteiros é `nil`, porque um ponteiro `nil` não guarda nenhum endereço de memória.

### Obter um ponteiro para uma variável

Para encontrar o endereço de memória do valor de uma variável, podemos usar o operador `&`.
Por exemplo, se quisermos encontrar e guardar o endereço de memória da variável `a` no ponteiro `p`, podemos fazer o seguinte:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Aceder ao valor através de um ponteiro (desreferenciação)

Quando temos um ponteiro, podemos querer saber o valor guardado no endereço de memória que o ponteiro representa.
Podemos fazê-lo com o operador `*`:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

A operação `*p` obtém o valor guardado no endereço de memória que está em `p`.
A esta operação dá-se muitas vezes o nome de "desreferenciação".

Também podemos usar o operador de desreferenciação para atribuir um novo valor ao endereço de memória referenciado pelo ponteiro:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

Atribuir a `*pa` altera o valor guardado no endereço de memória que `pa` contém.
Como `pa` contém o endereço de memória de `a`, ao atribuir a `*pa` estamos efetivamente a alterar o valor de `a`!

Um aviso, no entanto: verifica sempre se um ponteiro não é `nil` antes de o desreferenciares.
Desreferenciar um ponteiro `nil` faz o programa rebentar em tempo de execução!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Ponteiros para structs

Até agora só vimos ponteiros para valores primitivos.
Também podemos criar ponteiros para structs:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

Também podíamos ter criado um novo `Person` e guardado logo um ponteiro para ele:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Quando temos um ponteiro para uma struct, não precisamos de desreferenciar o ponteiro antes de aceder a um dos campos:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## Slices e mapas já são ponteiros

Os slices e os mapas são tipos especiais porque já têm ponteiros na sua implementação.
Isto significa que, na maioria das vezes, não precisamos de criar ponteiros para estes tipos para partilhar o endereço de memória dos seus valores.
Imagina que temos uma função que incrementa o valor de uma chave num mapa:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Se criarmos um mapa e chamarmos esta função, as alterações que a função fez ao mapa mantêm-se depois de a função terminar.
É um comportamento semelhante ao que teríamos se usássemos um ponteiro, mas repara que neste exemplo não estamos a usar qualquer referência/desreferenciação nem qualquer outra sintaxe de ponteiros:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

O mesmo se aplica quando alteramos um elemento já existente num slice.

No entanto, as ações que devolvem um novo slice, como `append`, são um caso especial e **podem não** modificar o slice fora da função.
Isto deve-se à forma como os slices funcionam internamente, mas não vamos abordar isto em detalhe neste exercício, porque é um tópico mais avançado.
Se estiveres mesmo curioso, podes ler mais sobre isto em [Go Blog: Mechanics of 'append'][mechanics-of-append]
