# Introdução

Os literais são valores fixos usados diretamente no código.
Não precisam de qualquer cálculo em tempo de execução.
Surgem em várias formas para representar diferentes tipos de dados de forma eficiente.
Os literais mais frequentes são de natureza numérica, mas também existem operadores literais para tipos de data, hora e string.
Um conceito posterior mostrará como se podem usar operadores literais definidos pelo utilizador.

## Literais numéricos

Os literais numéricos incluem representações decimais, octais, hexadecimais e binárias.
Estas bases já foram abordadas no [conceito de números][numbers-concept].

Todas as representações como `23`, `0x50f7ba11` e `0xba5eba11` são entendidas pelo compilador como `int`.
O tipo `int` geral tem sinal e ([dependendo do compilador e do sistema][in-depth-integers]) tem frequentemente um intervalo de `-2'147'483'648` a `2'147'483'647`.
Isto é suficiente na maioria das vezes e não precisas de te preocupar com o tipo específico.

Alguns casos de uso exigem intervalos maiores ou programas com uma ocupação de memória muito reduzida.
Para sermos explícitos, podemos indicar diretamente tipos inteiros específicos com o literal numérico.

Quando não são precisos números negativos, mas se pretende o intervalo adicional, usam-se os sufixos `u` ou `U` para inteiros _sem sinal_.
Para intervalos maiores, podem usar-se `L` ou mesmo `LL` para os tipos long e long long.

~~~~exercism/caution
O uso de `l` minúsculo é permitido, mas confunde-se facilmente com o número `1` e, por isso, é desaconselhado.
~~~~

```cpp
auto net_worth_christian_grey{2'500'000'000U}; // out of range for 32-bit integers
auto net_worth_carlisle_cullen{46'000'000'000LL}; // int and uint are not enough
```

Os números de vírgula flutuante resolvem-se habitualmente em `double` durante a compilação.
Este é um bom comportamento predefinido, e os casos de uso com o tipo `float`, mais estreito, são menos frequentes do que no exemplo dos inteiros sem sinal acima.

~~~~exercism/advanced
O [padrão C++23][cpp23-literals] introduz um controlo mais fino com literais como `f128` ou `F16`.
Alguns compiladores permitem os seus próprios literais.
O GCC permite o uso de `d` como literal, mas isso não está previsto no padrão e pode prejudicar a compatibilidade entre plataformas.

[cpp23-literals]: https://en.cppreference.com/w/cpp/language/floating_literal

~~~~

```cpp
auto light_year_in_m{9.46073e+15f}; // well in the range of float
auto earth_to_edge_comoving_distance_in_nm{4.32355e+32}; // needs double type for magnitude
auto eulers_number{2.718281828459045}; // needs double type for precision
```

## Literais de caráter e de string

Outros conceitos já usaram literais de caráter com aspas simples, como `'}'` ou `'@'`.

Em C++, `char` está limitado aos primeiros 128 [códigos de caráter ASCII][ascii-code].
Para usar vários carateres ASCII ou carateres ASCII estendidos como `‰`, ou mesmo carateres Unicode como `麗` e `ẞ`, são precisos outros tipos.
Em conceitos anteriores, os literais de string foram introduzidos com _aspas duplas_: `"一体どういう意味ですか。C++です"`.
O tipo real desta frase japonesa é `const char (&)[46]`, uma string ao estilo C.

O uso de literais de string não está ativado por predefinição.
Para usar o literal _string_ `""s` ou o literal _string-view_ `""sv`, é preciso especificar a sua utilização através do espaço de nomes correspondente:

```cpp
#include <string>
#include <string_view>

using namespace std::literals;

auto green_light{"무궁화 꽃 이 피었 습니다"};
// green_light type is const char (&)[36]
auto umbrella{"달고나"s};
// umbrella type is std::basic_string<char>, the same as std::string
auto il_nam{"보는 것이 하는 것보다 더 재미있을 수가 없지"sv};
// il_nam type is std::basic_string_view<char>
```

Um _string_view_ pode ser visto como uma referência a uma string constante.
