# Introdução

Antes de a classe `Promise` existir, só havia uma forma de lidar com código assíncrono: o _padrão de callback_.

Um callback é uma função que é passada como argumento a outra função e que será chamada assim que alguma ação nessa outra função terminar. Um padrão comum para essas funções de callback é aceitarem um `"error"` como primeiro parâmetro (vê o exemplo abaixo).

```javascript
function callback(error, arg2, arg3) {}
```

E que relação tem isto com o código assíncrono?

Historicamente, os callbacks têm sido usados para nos permitir fazer algum trabalho depois de uma tarefa assíncrona terminar, e sem bloquear o programa todo.

```javascript
fetchProduct(productId, function (error, data) {
  if (error) {
    // Handle the error
  } else {
    // Do some work
  }
});
```

No exemplo acima, a função `fetchProduct` (que é assíncrona) recebe um callback como segundo argumento, que decide o que fazer quando os dados do produto tiverem sido obtidos.
