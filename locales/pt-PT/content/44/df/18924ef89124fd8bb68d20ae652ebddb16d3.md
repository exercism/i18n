# Rotinas vinculadas

```sather
   part : ROUT{STR}:STR := bind(shout(_));
   part.call("who's there");
```

## bind

O `bind` recebe uma chamada na qual qualquer parte pode ser substituída por `_`. Tudo o que não é `_` é avaliado **agora** e mantido; cada `_` passa a ser um argumento da rotina vinculada, pela ordem em que está escrito.

```sather
   bind(repeat(2, _))         -- ROUT{STR}:STR
   bind(repeat(_, "Ha"))      -- ROUT{INT}:STR
   bind(repeat(_, _))         -- ROUT{INT,STR}:STR
```

## Os tipos

| Tipo | Recebe | Devolve |
| --- | --- | --- |
| `ROUT:INT` | nada | `INT` |
| `ROUT{STR}` | uma `STR` | nada |
| `ROUT{STR}:STR` | uma `STR` | uma `STR` |
| `ROUT{INT,INT}:BOOL` | dois `INT` | `BOOL` |

`ITER{...}` é a mesma ideia para um iterador.

## call

O `call` fornece os restantes argumentos. Uma rotina vinculada que não devolve nada é chamada da mesma forma, como instrução.

## O bind fica à direita de uma atribuição

Um `bind` pode ser declarado numa variável ou passado como argumento:

```sather
   part ::= bind(shout(_));                -- yes
   part : ROUT{STR}:STR := bind(shout(_)); -- yes
   rehearse("line", bind(shout(_)));       -- yes
```

mas não pode ir diretamente para um `return`:

```sather
   return bind(shout(_));                  -- does not parse
```

Coloca-o numa variável e devolve essa variável. A mensagem de erro aponta para o `bind` e menciona underscores, o que não é óbvio a partir da própria linha.

## Onde são usadas

A biblioteca usa-as sempre que é preciso fornecer comportamento:

```sather
   names.sort_by(bind(shorter(_, _)));
   scores.count_if(bind(over(10, _)));
   scores.find_if(bind(is_even(_)));
```

A ordenação é o caso mais claro: o `sort_by` sabe ordenar e não sabe nada sobre a tua noção de ordem, e a rotina vinculada é onde as duas coisas se encontram.

## Uma limitação neste compilador

O Sather 1.2 não implementa rotinas vinculadas **com despacho**, ou seja, vincular uma rotina a uma variável de um tipo abstrato. O compilador diz isso claramente:

```
Dispatched bound routines are not implemented yet
```

Vincula a um tipo concreto, ou a uma classe, e está tudo bem. É por isso que o próprio sistema de testes do percurso escreve as suas verificações de exceções à mão, em vez de usar uma rotina vinculada.

## Rotinas vinculadas ou classes abstratas?

Ambas permitem que quem chama forneça comportamento.

Uma rotina vinculada é uma única rotina, não precisa de classe e escreve-se onde é usada. Uma classe abstrata transporta várias rotinas e algum estado, e vale a pena a cerimónia quando aquilo que se fornece tem mais do que uma parte.

Uma rotina para entregar: vincula-a. Um colaborador com várias: escreve uma classe.
