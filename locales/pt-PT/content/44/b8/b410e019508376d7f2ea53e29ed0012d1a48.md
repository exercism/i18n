# Sobre

Uma declaração `GENERIC:` introduz uma palavra cujo comportamento
depende da classe de um dos seus argumentos. O comportamento concreto
é fornecido por *métodos* (`M:`) dirigidos a classes específicas.

```factor
GENERIC: stringify ( obj -- str )
M: integer stringify number>string ;
M: string  stringify ;
M: f       stringify drop "(none)" ;
```

Quando `stringify` é chamado, o Factor inspeciona o topo da pilha,
procura o método mais específico cuja classe corresponde e executa-o.
Se nenhum método corresponder, é lançado um erro.

## Classe de despacho

Por omissão, o despacho é feito no argumento do topo (o primeiro
parâmetro de entrada declarado no efeito de pilha). Para despacho
com vários argumentos, vê `HOOK:` e `MATH:`, que fazem o despacho no
segundo argumento ou na promoção numérica, respetivamente.

## Adicionar métodos a um genérico

Podes estender um genérico em qualquer altura, mesmo a partir de um
vocabulário diferente, desde que consigas fazer `USE:` tanto do
genérico como da classe:

```factor
USING: math ;
M: ratio  area drop 0 ;     ! adds an `area` method for ratios
```

## Métodos em classes incorporadas

Os genéricos funcionam igualmente bem em classes incorporadas
(`integer`, `string`, `array`, `f`, `t`) como em tuplas definidas
pelo utilizador. Os métodos em `f` e `t` são particularmente úteis
para predicados ao estilo de "is-set?", que têm predefinições
naturais.

## Quando um genérico é a escolha certa

Usa `GENERIC:` quando:

- Uma única operação tem implementações *genuinamente diferentes*
  para valores de entrada distintos (e não apenas um `case` sobre
  etiquetas).
- Esperas que outro código acrescente novos tipos mais tarde.
- Queres que o sistema de tipos garanta que a operação está
  definida para todas as classes relevantes. O Factor pode
  indicar-te os métodos que faltam.

Se a variação for uma enumeração pequena e fixa de etiquetas, um
`case` é mais simples.
