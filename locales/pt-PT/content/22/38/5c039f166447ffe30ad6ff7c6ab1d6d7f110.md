# Introdução

O [pattern matching][pattern-matching] permite escrever código com ramificações expressivas, e a [desestruturação][destructuring] traz uma ligação elegante de valores a variáveis.
Ambos são extremamente úteis de dominar enquanto programadores de Elm e, quando usados em conjunto, melhoram bastante a legibilidade do código.

## Pattern matching simples

O pattern matching designa código com ramificações que depende da forma dos dados manipulados.
Por isso, encaixa naturalmente no conceito de tipos personalizados, que expressam as várias formas que alguns dados podem assumir.
Dado um tipo personalizado `Color` definido, por exemplo, como sendo `Blue` ou `Red`, podemos escrever uma função `toString` que faz pattern matching sobre a cor para devolver a string correta.

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

O pattern matching também funciona com tipos personalizados que não são simples enumerações.
Vamos considerar uma função `hello`, que recebe como parâmetro um `Maybe String`, contendo o nome de uma pessoa ou nada de todo.
Ao fazer pattern matching, podemos dar nomes em minúsculas aos dados, para os ligar a essa variável e poder usá-la no lado direito do case.

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

O pattern matching tem de ser exaustivo, caso contrário o compilador recusa-se a compilar.
Mas, por vezes, não nos importamos com alguns dados nem com alguns ramos de uma expressão case.
Nesses casos, em vez de termos de encontrar um nome de variável para ligar e de ter ramos para todos os casos, podemos usar o underscore `_` como caráter universal.

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## Pattern matching avançado

Além dos tipos personalizados, também podemos fazer pattern matching sobre tipos que têm literais, como `Char`, `String`, `Int` e `Floats`.

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

Para fazer pattern matching sobre mais de um valor sem os aninhar, um truque comum em Elm é combinar os valores a comparar em [_tuplos ad hoc_][ad-hoc-tuples], assim:

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

E, como as listas são queridas dos programadores funcionais, [também se pode fazer pattern matching sobre elas][pattern-match-lists], com a mesma sintaxe que se usa para as construir, recorrendo ao operador `::`.

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

Por fim, o pattern matching funciona até de forma recursiva, o que permite mergulhar fundo em tipos complexos e recursivos.

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## Desestruturação

A desestruturação é muito semelhante ao pattern matching, no sentido em que permite ligar variáveis a dados dentro de tipos.
A principal diferença é que chamamos a esse mecanismo "desestruturação" quando só há uma forma possível, e chamamos-lhe pattern matching quando há várias formas.
A desestruturação aparece frequentemente em ligações `let`, em argumentos de funções e, claro, em expressões case, misturada com pattern matching.

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

A desestruturação pode ser usada com tipos personalizados de uma só variante, com tuplos e também com registos, onde é muito conveniente.
Para [desestruturar um registo][records-pattern-matching], podemos usar qualquer número dos seus campos: um, dois, ..., ou todos os campos.

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

Infelizmente, a sintaxe do Elm não permite a desestruturação recursiva de registos.
No exemplo anterior do `Circle`, não há forma de aceder às posições `x`` and `y do centro do círculo de uma só vez.
Temos primeiro de aceder ao `center` e só depois desestruturá-lo para obter as suas posições `x` e `y`.

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

E temos uma última dica!
Por vezes, queremos ter acesso fácil tanto a uma coisa como um todo como a uma parte dela.
É aqui que a [palavra-chave `as`][as-keyword] pode ser útil.
Permite dar um nome alternativo a uma coisa como um todo, continuando a ser possível desestruturar o seu conteúdo.

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
