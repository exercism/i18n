# Acerca de

Um ficheiro é um fluxo com um nome no disco. O vocabulário [`io.files`][io.files]
oferece duas formas de trabalhar com um: palavras de conveniência para o ficheiro
inteiro, que leem ou escrevem tudo numa única chamada, e abridores de fluxo (os
combinadores `with-…`) para ler ou escrever de forma incremental. Ambos assentam
no mesmo [protocolo de fluxos][stream-protocol] que os fluxos em memória do
conceito `io-streams`: um `<file-reader>` e um `<string-reader>` respondem às
mesmas palavras.

Todas as palavras de ficheiro recebem uma **codificação**, o esquema que mapeia
bytes em carateres e vice-versa. Para texto, é quase sempre [`utf8`][utf8] de
`io.encodings.utf8`; o trabalho com dados binários usa `latin1` ou uma
codificação `<byte-array>`.

## Leitura do ficheiro inteiro

```
file-contents   ( path encoding -- str )
file-lines      ( path encoding -- seq )
```

`file-contents` devolve o ficheiro inteiro como uma string. `file-lines` devolve
as suas linhas como um array, com os terminadores de linha removidos. É útil
quando cada linha é um registo.

```factor
USING: io.encodings.utf8 io.files ;

"forecast.txt" utf8 file-contents   ! => "sunny\ncloudy\n"
"forecast.txt" utf8 file-lines      ! => { "sunny" "cloudy" }
```

## Escrita do ficheiro inteiro

```
set-file-contents   ( str path encoding -- )
set-file-lines      ( seq path encoding -- )
```

Ambas **substituem** o ficheiro, criando-o se este não existir.
`set-file-contents` escreve uma string tal como está; `set-file-lines` escreve
cada elemento de uma sequência na sua própria linha, acrescentando as quebras de
linha.

```factor
{ "sunny" "cloudy" } "forecast.txt" utf8 set-file-lines
! forecast.txt now holds "sunny\ncloudy\n"
```

## Fluxos com âmbito

Quando queres acrescentar a um ficheiro, ou ler e escrever peça a peça, abre-o
com um combinador `with-…` e usa as palavras do fluxo ambiente dentro da
quotation:

```
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
with-file-appender   ( path encoding quot -- )
```

```factor
USING: io io.encodings.utf8 io.files ;

"log.txt" utf8 [ "another line" print ] with-file-appender
```

`with-file-writer` trunca o ficheiro primeiro; `with-file-appender` mantém o
conteúdo existente e escreve a seguir a ele. Cada um é um âmbito destrutor: o
handle do ficheiro é fechado quando a quotation termina, mesmo que lance um erro.
É a mesma garantia que os combinadores `boatswains-bilge` proporcionam, aqui
especializada para ficheiros.

## Ficheiro inteiro ou âmbito?

Recorre a `file-contents` / `file-lines` / `set-file-contents` /
`set-file-lines` quando o ficheiro é suficientemente pequeno para caber na
memória e queres o todo de uma só vez. Recorre aos abridores `with-…` quando
precisas de acrescentar, de transmitir um ficheiro grande linha a linha com
`readln`, ou de intercalar leituras e escritas. Em qualquer situação em que
guardar o ficheiro inteiro na memória seria um desperdício ou estaria errado.
