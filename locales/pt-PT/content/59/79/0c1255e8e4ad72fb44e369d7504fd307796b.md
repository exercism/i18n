# Anexo às instruções

## Prós e contras de `from_quote`

A função `Card.from_quote` analisa uma string e transforma-a num `Card`.
Isto permite escrever código como este:

```roc
card : Card
card = "Q"
```

Este código chama implicitamente `Card.from_quote("Q")` em tempo de compilação.
Executar código em tempo de compilação com esta abordagem (ou com outros métodos descritos abaixo) pode acelerar o programa, uma vez que não é preciso tratar a análise e a validação dos dados em tempo de execução.
Além disso, garante que os dados inválidos (como um formato de data incorreto) são rejeitados em tempo de compilação, em vez de em tempo de execução, o que torna a tua aplicação mais robusta.
Por último, torna o código agradável e legível.
Por exemplo, este é um dos testes deste exercício:

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

No entanto, quem lê este código pode assumir que a função `simulate_game` recebe um registo com dois `List(Str)`, quando na verdade é um registo com dois `List(Card)`.
Isto pode dar origem a confusão e erros.
Por isso, podes preferir o formato um pouco mais longo mas mais explícito: `"Q".Card`, que também chama `from_quote` em tempo de compilação.

Nos teus próprios programas, podes preferir usar `from_str`:

```roc
Card := { ... }.{
    from_str : Str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

Também podes chamar `from_str` (ou qualquer outra função pura) em tempo de compilação, assim:

```roc
Ok(card) = Card.from_str("Q")
```

Nota: colocar esta definição ao nível superior faz com que seja executada em tempo de compilação (uma vez que a função é pura e o seu parâmetro de entrada é conhecido em tempo de compilação).
Dentro de uma função, podes usar `from_str` em tempo de execução.
