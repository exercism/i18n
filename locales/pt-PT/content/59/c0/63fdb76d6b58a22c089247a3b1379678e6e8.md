# Acerca de

As threads do Factor são *corrotinas cooperativas* numa única thread do sistema operativo. Uma thread é executada até ceder explicitamente ou realizar operações de entrada/saída bloqueantes; nesse momento, o escalonador escolhe outra thread executável. Duas implicações:

- Tudo o que está entre cedências é efetivamente atómico.
- O verdadeiro paralelismo multinúcleo exige sair do vocabulário padrão `threads` (por exemplo, `concurrency.distributed` para arquiteturas multiprocesso).

As primitivas padrão de concorrência organizam-se em camadas:

| Vocabulário                       | Fornece                               |
|-----------------------------|----------------------------------------|
| [`threads`][threads]                   | `spawn`, `yield`, identidade da thread      |
| [`concurrency.promises`][concurrency.promises]      | `<promise>`, `fulfill`, `?promise`     |
| [`concurrency.locks`][concurrency.locks]         | `<lock>`, `with-lock`                  |
| [`concurrency.combinators`][concurrency.combinators]   | `parallel-map`, `parallel-each`        |
| [`concurrency.semaphores`][concurrency.semaphores]    | `<semaphore>`, `acquire`, `release`    |
| [`concurrency.mailboxes`][concurrency.mailboxes]     | caixas de entrada por thread, `send`, `receive`  |
| [`concurrency.channels`][concurrency.channels]      | identificadores de rendezvous, `to`, `from`       |

```factor
USING: concurrency.combinators concurrency.locks
concurrency.promises kernel sequences threads ;

! parallel-map: fork-join, in order
{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }

! spawn + promise: hand-rolled fork-join
<promise> [
    [ "hello, world" swap fulfill ] curry "greeter" spawn drop
] keep ?promise .   ! => "hello, world"

! <lock> + with-lock: protect a shared mutable slot
<lock> :> guard
guard [ "do thing under lock" drop ] with-lock
```

`parallel-map` é a API de alto nível e aquilo a que o Factor idiomático recorre primeiro. O trio `spawn` / `<promise>` / `?promise` é aquilo a partir do qual `parallel-map` é construído, o que dá jeito quando a forma da iteração não encaixa em map (por exemplo, criar workers que comunicam de volta através de outros canais).

Os bloqueios protegem o *estado mutável partilhado*, tipicamente um campo de um tuplo ou uma tabela de hash que mais do que uma thread lê ou escreve. Considera que tanto as leituras como as escritas precisam do bloqueio se houver qualquer atualização composta não atómica; faltar um bloqueio em qualquer dos lados é a receita clássica para uma leitura rasgada.
