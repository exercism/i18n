# Dicas

## Geral

- Espreita o [Guia de Elm][elm-guide], que tem um bom exemplo prático semelhante.

## 1. Define os tipos Model e Msg da aplicação e escreve a função init

- O `Model` contém o estado da aplicação: todos os dados de que a aplicação precisa.
- Deve ser um [record][record].
- Esta aplicação só precisa de uma `String` para guardar o texto na caixa de texto (os testes exigem que se chame `content`).

- O tipo `Msg` define as mensagens que são passadas à função `update`, para desencadear alterações específicas no modelo.
- Deve ser um [custom type][custom-type].
- Esta aplicação só precisa de uma alteração ao modelo: atualizar o modelo quando o texto na caixa de texto muda.

- A função `init` deve limitar-se a devolver um `Model` com um valor predefinido sensato (os testes exigem uma string vazia).

## 2. Escreve a função update

- Em qualquer aplicação útil, a função update usa um `case` para fazer correspondência de padrões sobre o parâmetro `Msg`.
- Em cada ramo do `case`, extrai a informação de que precisa do parâmetro `Msg` e devolve um `Model` atualizado.
- O `Model` deve ser um record, e normalmente usa-se a [sintaxe de atualização de records][record-update-syntax].

## 3. Escreve a função view

- A função `view` deve devolver uma `div` para o elemento raiz.
- O primeiro filho deve ser um `input`, com um atributo `value` para o texto atual e um atributo/evento `onInput` com a variante relevante de `Msg`.
- O segundo filho deve ser outra `div` com um filho `text` que indique se o texto é um palíndromo ou não.

## 4. Escreve a função main

- A função main deve limitar-se a chamar [`Browser.sandbox`][browser-sandbox].
- `Browser.sandbox` exige um argumento do tipo [record][record] com as funções `init`, `update` e `view`.
