# Testes

Os testes de um projeto Elm ficam no subdiretório `tests/` desse projeto.
O conjunto de testes de cada exercício pode ser executado a partir do diretório raiz desse exercício.

```bash
$ cd ~/exercism/elm/hello-world
$ elm-test
```

## Vigia as alterações

Volta a executar os testes automaticamente sempre que guardas alterações:

```bash
$ elm-test --watch
```

## Fluxo de desenvolvimento orientado por testes

Na maioria dos exercícios, os testes já estão escritos no ficheiro `tests/Tests.elm`.
O teu objetivo é fazê-los passar, escrevendo o código necessário
no ficheiro `src/<exercise>.elm`.
Concentra-te no primeiro teste que falha, corrige-o,
depois remove ou comenta o próximo fragmento `skip <|` no ficheiro de testes e repete
até todos os testes passarem.

## Não sabes como avançar?

O teu primeiro objetivo é conseguir compilar o código, mesmo que ele tenha `Debug.todo`.
Se sentires que não sabes como fazer algo,
muitas vezes é útil extrair essa parte para uma função própria ainda por implementar.

```elm
complexOperationOnMultipleStrings : List String -> List String
complexOperationOnMultipleStrings allStrings =
    List.map complexOperation allStrings


complexOperation : String -> String
complexOperation input =
    Debug.todo "Extracted operation into its own function"
```

Acrescentar uma anotação de tipo a esta função extraída
ajuda-te a pensar e ajuda o compilador a dar-te melhores mensagens de erro.

## Limpar o teu código

Considera correr o [`elm-format`](https://github.com/avh4/elm-format) no teu código antes de o submeteres
e até configurá-lo no teu editor de texto para formatar automaticamente ao guardar.
