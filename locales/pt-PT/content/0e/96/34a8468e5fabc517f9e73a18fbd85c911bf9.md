# Sobre

Um [ciclo `for`][for-statement] permite executar código repetidamente num ciclo até que uma condição se cumpra.

```csharp
for (int i = 0; i < 5; i++)
{
    System.Console.Write(i);
}

// => 01234
```

Um ciclo `for` é composto por quatro partes:

1. O inicializador: executado uma vez antes de entrar no ciclo. Normalmente serve para definir variáveis usadas dentro do ciclo.
2. A condição: executada antes de cada iteração do ciclo. O ciclo continua a ser executado enquanto esta for `true`.
3. O iterador: executado depois de cada iteração do ciclo. Normalmente serve para modificar (muitas vezes: incrementar/decrementar) as variáveis do ciclo.
4. O corpo: o código que é executado em cada iteração do ciclo.

## Ciclos `for` vs `foreach`

Em geral, os [concept:csharp/foreach-loops]() são preferíveis aos ciclos `for` pelas seguintes razões:

- Um ciclo `foreach` garante que itera sobre _todos_ os valores. Com um ciclo `for`, é fácil deixar escapar elementos, por exemplo devido a um erro de mais um ou menos um.
- Um ciclo `foreach` é mais _declarativo_: o teu código comunica _o que_ queres fazer, em vez de um ciclo `for` que comunica _como_ o queres fazer.
- Um ciclo `foreach` é à prova de erros, enquanto que com os ciclos `for` é fácil cometer um erro de mais um ou menos um.
- Um ciclo `foreach` funciona com todos os tipos de coleções, incluindo aqueles que não suportam o uso de um indexador para aceder aos elementos.

Para garantir que um ciclo `foreach` itera sobre _todos_ os valores, o compilador não permite alterar uma coleção dentro de um ciclo `foreach`:

```csharp
char[] vowels = new [] { 'a', 'e', 'i', 'o', 'u' };

foreach (char vowel in vowels)
{
    // This would result in a compiler error
    // vowel = 'Y';
}
```

Um ciclo `for` tem algumas vantagens em relação a um ciclo `foreach`:

- Podes começar ou parar no índice que quiseres.
- Podes usar qualquer condição de terminação (Boolean) que queiras.
- Podes saltar elementos personalizando o incremento da variável do ciclo.
- Podes processar coleções de trás para a frente, contando de forma decrescente.
- Podes usar ciclos `for` em cenários que não envolvem coleções.
