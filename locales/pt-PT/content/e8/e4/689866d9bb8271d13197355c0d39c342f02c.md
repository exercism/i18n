# Introdução

Por vezes, um pedaço de estado tem de ser partilhado entre várias palavras sem ter de ser passado pelos respetivos efeitos de pilha de cada vez. As *variáveis dinâmicas* do Factor, declaradas com `SYMBOL:`, dão a cada palavra acesso a um valor guardado num espaço de nomes.

## `SYMBOL:` e `SYMBOLS:`

`SYMBOL: name` declara uma variável. `SYMBOLS: a b c ;` declara várias de uma só vez:

```factor
USING: namespaces ;

SYMBOLS: counter total ;
```

## Definir e obter

`set-global` e `get-global` (no [`namespaces`][namespaces]) operam sobre o espaço de nomes global:

```
set-global    ( value variable -- )
get-global    ( variable -- value )
change-global ( variable quot: ( old -- new ) -- )
```

```factor
0 counter set-global
counter get-global .         ! => 0
counter [ 10 + ] change-global
counter get-global .         ! => 10
```

Para estado ao nível do módulo, são as variantes `-global` que precisas.

## Ligações de âmbito com `with-variable`

Uma variável dinâmica também suporta uma segunda variante, *com âmbito*. `set` / `get` / `change` (sem o sufixo `-global`) leem e escrevem no âmbito dinâmico *atual*, e `with-variable` (no [`namespaces`][namespaces]) cria um âmbito novo durante a execução de uma quotation:

```
with-variable ( value variable quot -- )
set           ( value variable -- )
get           ( variable -- value )
change        ( variable quot: ( old -- new ) -- )
```

A variável fica ligada a `value` enquanto `quot` está a correr; assim que este termina, a ligação desaparece. Isto permite que um chamador exterior «injete» um valor que o código interior consegue ler sem o passar por todas as assinaturas de pilha.

```factor
SYMBOL: greeting

"Hello" greeting [
    greeting get .                ! => "Hello"
    "Howdy" greeting set
    greeting get .                ! => "Howdy"
    greeting [ "!" append ] change
    greeting get .                ! => "Howdy!"
] with-variable

greeting get-global .    ! => f   (the scoped binding is gone)
```

Este exercício usa a variante global do início ao fim, mas reconhecer a família paralela `set`/`get`/`change` é útil quando lês código de outras pessoas.

## Vetores mutáveis

Como as variáveis dinâmicas guardam uma referência, podes manter uma coleção *mutável* dentro de uma delas e atualizá-la no próprio local:

```factor
SYMBOL: history

V{ } clone history set-global
"first event" history get-global push
"second event" history get-global push
history get-global .
! => V{ "first event" "second event" }
```

`V{ … }` é um vetor literal. Faz sempre `clone` de um literal `V{ }` antes de o guardares: os literais são partilhados entre chamadas.

## `find`: primeira correspondência

`find` (em [`sequences`][sequences]) devolve o primeiro elemento para o qual um predicado é verdadeiro, juntamente com o seu índice:

```
find ( seq quot -- index elt/f )
```

Se nada corresponder, ambos os valores são `f`. Descartar o índice com `nip` e usar `unless*` é a combinação habitual de «valor predefinido se faltar».

## `reject`: descartar as correspondências

`reject` (também em [`sequences`][sequences]) é o oposto de `filter`: devolve os elementos que *não passam* no predicado.
