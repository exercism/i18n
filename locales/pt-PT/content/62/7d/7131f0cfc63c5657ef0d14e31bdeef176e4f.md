# Introdução

## SIMD: bit a bit

Existem variantes empacotadas para a maioria das operações bit a bit escalares.
Seguem a mesma sintaxe geral das operações inteiras SIMD, mas não têm sufixo de tamanho:

| instrução | descrição                              |
|-------------|-----------------------------------|
| `pand`      | AND bit a bit de dois valores de 128 bits |
| `por`       | OR bit a bit de dois valores de 128 bits  |
| `pxor`      | XOR bit a bit de dois valores de 128 bits |

Repara que não existe um `NOT` empacotado.
No entanto, existe uma operação ANDN, que complementa (inverte todos os bits) o operando de **destino** e calcula depois o AND entre os dois operandos.
Podes pensar nela como um NOT combinado com um AND:

| instrução | descrição                                                     |
|-------------|-----------------------------------------------------------------|
| `pandn`     | AND bit a bit do destino **complementado** com a origem |

Repara que uma operação bit a bit combina bits na mesma posição em dois operandos diferentes, por isso as fronteiras das vias não podem alterar o resultado.
É por isso que estas instruções não têm sufixo de tamanho: o registo comporta-se como uma única via de 128 bits:

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
Todas as instruções deste conceito calculam bits, mas não definem nenhuma flag.
Um conceito posterior abordará as condicionais com valores empacotados.
~~~~

### Deslocamentos por via

Os deslocamentos, ao contrário das operações bit a bit puras, movem mesmo bits entre posições, por isso precisam de um tamanho de via para definir uma fronteira.
Dentro de cada via comportam-se como as suas equivalentes escalares, e os bits nunca passam de uma via para a vizinha:

| instrução               | descrição                         |
|---------------------------|-------------------------------------|
| `psllw`, `pslld`, `psllq` | deslocamento lógico para a esquerda, por via        |
| `psrlw`, `psrld`, `psrlq` | deslocamento lógico para a direita, por via       |
| `psraw`, `psrad`          | deslocamento aritmético para a direita, por via    |

Repara que estas instruções seguem a sintaxe das operações inteiras empacotadas, incluindo um sufixo de tamanho.
Não existe deslocamento por via de bytes, apenas de word, dword e, com exceção do deslocamento aritmético para a direita, de qword.

Uma diferença entre os deslocamentos empacotados e as suas equivalentes escalares está no nome da operação:

- Em vez de `shl` e `shr`, temos `sll` e `srl`, de **s**hift **l**eft (**r**ight) **l**ogical.
- Em vez de `sar`, temos `sra`, de **s**hift **r**ight **a**rithmetic.

Embora o nome seja diferente, a operação é a mesma:

- Um deslocamento lógico para a direita preenche os bits mais significativos com zeros.
  É equivalente a uma divisão sem sinal por uma potência de dois.
- Um deslocamento aritmético para a direita preenche os bits mais significativos com o valor do bit de sinal.
  É equivalente a uma divisão com sinal por uma potência de dois, com arredondamento para menos infinito.
- Um deslocamento para a esquerda preenche sempre com zeros (é por isso que não é preciso um deslocamento aritmético para a esquerda).

A contagem do deslocamento é a mesma para todas as vias.
Pode ser um valor imediato, ou os 64 bits de ordem inferior de um registo `xmm`:

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
Uma contagem de deslocamento maior do que a largura da via não dá a volta como a família escalar `shl`/`shr`.
Produz simplesmente zero (ou todos os bits de sinal, no caso do deslocamento aritmético para a direita).
~~~~

### Operações bit a bit com números de vírgula flutuante

Cada instrução bit a bit tem também gémeas com nomes de vírgula flutuante, seguindo a mesma sintaxe que já vimos para as operações empacotadas de vírgula flutuante:

| nome inteiro | nomes de vírgula flutuante          |
|--------------|----------------------|
| `pand`       | `andps`, `andpd`     |
| `pandn`      | `andnps`, `andnpd`   |
| `por`        | `orps`, `orpd`       |
| `pxor`       | `xorps`, `xorpd`     |

Como as operações bit a bit atuam sobre bits, na prática as operações inteiras e de vírgula flutuante calculam o mesmo resultado.
Os nomes diferentes existem por duas razões:

1. Documentar a intenção, tal como preferiríamos `movdqa`, `movaps` ou `movapd` consoante a natureza dos bytes que estão a ser copiados.
2. As operações inteiras e de vírgula flutuante têm muitas vezes domínios de execução diferentes.
   As operações dentro do mesmo domínio de execução conseguem normalmente ser sequenciadas mais depressa.

Não existe nenhuma operação de deslocamento para valores de vírgula flutuante.

### Representação em bits de números de vírgula flutuante

Um número de vírgula flutuante IEEE tem uma representação em bits muito diferente da de um número inteiro.

Num número inteiro sem sinal, cada bit tem um significado uniforme: representa uma potência de dois correspondente ao índice do bit.
O número inteiro é a soma das potências de dois correspondentes aos bits ativos.
É por isso que deslocar os bits pode multiplicar ou dividir o número por uma potência de dois: estamos apenas a alterar o índice de cada bit ativo.

Num número inteiro com sinal, a maioria dos bits é interpretada da mesma forma que num número inteiro sem sinal.
No entanto, o bit mais significativo é especial.
Se estiver ativo, em vez de ser somado aos restantes, temos de subtrair a potência de dois correspondente, o que dá um número negativo.
Na prática, para mudar o sinal de um número, precisaríamos conceptualmente de dois passos: inverter todos os bits (um `not`) e depois somar 1 ao resultado (um `inc`).

Os bits dos números de vírgula flutuante não têm um significado uniforme e precisam de ser interpretados de formas muito diferentes consoante a sua posição:

| campo    | índices (32 bits) | índices (64 bits) |
|----------|------------------|------------------|
| sinal     | 31               | 63               |
| expoente | 30-23            | 62-52            |
| fração | 22-0             | 51-0             |

O número resultante é calculado por `(-1)^sign * 1.fraction * 2^(exponent - bias)`.
O viés depende da precisão:

| tamanho   | viés |
|--------|------|
| 32 bits | 127  |
| 64 bits | 1023 |

Em ambos os formatos, o sinal do número é determinado exclusivamente pelo bit de sinal.
Mudar o sinal de um número de vírgula flutuante consegue-se apenas invertendo este bit (uma operação XOR).
Obter o valor absoluto consegue-se apenas colocando-o a zero (um AND em que o bit é colocado a zero):

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

Repara que, nesta representação em bits, deslocar bits não tem um resultado previsível e uniforme.
A fração pode «transbordar» para o expoente e o expoente para o sinal.

No entanto, às vezes é conveniente isolar as diferentes partes da representação para operar sobre elas.

Por exemplo, os bits do expoente devem ser primeiro interpretados como um número sem sinal, antes de lhes subtrairmos o viés.
Isto significa que podemos produzir um número inteiro de 32 ou 64 bits cuja representação em bits subjacente corresponde a uma potência de dois no formato de vírgula flutuante correspondente.
Depois, essa representação em bits em bruto pode ser usada para multiplicar ou dividir outro número de vírgula flutuante.

Por exemplo:

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

Inversamente, poderíamos extrair os expoentes de números de vírgula flutuante empacotados fazendo um AND com uma máscara em que os bits do expoente estão ativos e todos os outros estão a zero.
Combinado com um deslocamento e uma subtração, isto produz o expoente sem viés de cada via como número inteiro com sinal:

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
Operar sobre os bits em bruto de números de vírgula flutuante, embora seja útil em algumas situações, deve ser feito com cuidado.
Somar ou subtrair ao campo do expoente só é seguro se não houver overflow nem underflow e se o número de entrada for normal.
Além disso, somar um `x` válido ao campo do expoente de `0.0` dá `2^(x - bias)`, e não `0.0 * 2^x`.
~~~~
