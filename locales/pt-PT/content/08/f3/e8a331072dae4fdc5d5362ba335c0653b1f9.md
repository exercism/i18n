# Testes

Executa os testes com:

```bash
$ wrenc exercise-name.spec.wren
```

Por exemplo, para `hello-world`:

```bash
$ wrenc hello-world.spec.wren
```


## Perceber os testes ignorados

O método `skip` indica ao conjunto de testes para não executar um teste em particular.

- Porque é que são ignorados?

Para que te possas concentrar num teste de cada vez e os ativares um a um à medida que evoluís a solução.

- Como os ativar?

Um teste ignorado:

```js
// this test will be skipped and not run
skip.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

Basta alterar `skip.test` para `do.test`.

```js
// now the test will be run normally
do.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

## Criar o teu primeiro módulo Wren

Os testes deste percurso carregam a tua implementação importando-a como um módulo Wren:
`import "./bob" for Bob`. Não há nenhuma sintaxe especial para exportar a tua
implementação. Basta dar à tua classe o nome `Bob` para corresponder às instruções de
importação `for Bob`, e tudo deverá funcionar sem complicações.

```javascript
class Bob {
  static hey(message) {
    // Your solution to the exercise goes here
  }
}
```

Podes encontrar mais informações sobre módulos na
[documentação da modularidade do Wren][modularity].
Para ser mais fácil começar, existe um ficheiro Wren _esqueleto_ no
diretório de cada exercício.

[modularity]: https://wren.io/modularity.html
