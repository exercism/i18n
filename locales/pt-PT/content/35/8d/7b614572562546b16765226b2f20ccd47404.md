# usar especificação

[comment]: # (Este aviso é apresentado quando a solução não tem uma especificação de tipo)

Inclui [especificações de tipo](https://elixir-lang.org/getting-started/typespecs-and-behaviours.html#types-and-specs) (`@spec`) para comunicar o contrato entre os parâmetros de entrada e a saída de uma função.

- O Elixir é uma linguagem de tipagem dinâmica, o que significa que as verificações de tipo só ocorrem em tempo de execução. O uso de especificações de tipo permite que linters e ferramentas de análise estática como o [`Dialyxir`](https://hexdocs.pm/dialyxir/readme.html) (baseado no [`Dialyzer`](http://erlang.org/doc/man/dialyzer.html) do Erlang) avaliem o código à procura de comportamentos não intencionais.
- Podes encontrar uma [lista completa](https://hexdocs.pm/elixir/typespecs.html#basic-types) de todos os tipos incorporados na [documentação da linguagem](https://hexdocs.pm/elixir/typespecs.html#content)
- os tipos podem ser especificados com ou sem parênteses: `atom()` vs `atom`
  - o estilo do Exercism para Elixir é especificar sem parênteses.

```elixir
# Example 1
@spec add_one(int) :: int
def add_one(n) when is_integer(n) do
  n + 1
end

# Example 2
@spec hello(String.t) :: String.t
def hello(what \\ "world") when is_binary(what) do
  "Hello, #{what}"
end
```
