# Introdução

O conceito [`Basics`][basics] apresentou duas formas de definir uma função.

A mais geral, a forma multilinha:

```julia
function muladd(x, y, z)
    x * y + z
end
```

A forma de "atribuição", ou de "linha única", para definições curtas:
```julia
muladd(x, y, z) = x * y + z
```

Numa terceira forma, ainda mais curta, é possível criar sem nome uma função curta, de uso único:

```julia-repl
julia> map(x -> 2x, 1:3)
4-element Vector{Int64}:
 2
 4
 6

julia> map((x, y) -> x * y, 1:3, 4:6)
3-element Vector{Int64}:
  4
 10
 18
```

Neste caso, `x -> 2x` é uma "função anónima".
É o equivalente ao que outras linguagens chamam "função lambda".

Repara que vários argumentos precisam de parênteses, como em `(x, y) -> x * y`.

As funções anónimas são comuns no código Julia, sobretudo quando combinadas com funções de ordem superior como `map()` e `filter()` (que serão abordadas com mais detalhe num conceito mais adiante).

```julia-repl
julia> map(x -> x^4, [1, 2, 3])
3-element Vector{Int64}:
  1
 16
 81
```

## Argumentos de funções

Até agora, no programa, só vimos funções com um número exato de argumentos, que exigem que as chamadas à função forneçam todos eles, pela ordem correta.
Isso seria limitativo e inconveniente, por isso há várias outras opções.

### Argumentos opcionais

Tal como muitas linguagens, Julia permite que as definições de funções indiquem valores predefinidos para argumentos individuais.

A chamada à função pode então indicar um valor para esse argumento, ou omiti-lo e contar com o valor predefinido.

```julia-repl
julia> f(x, y=10) = x * y
f (generic function with 2 methods)

julia> f(2, 3)
6

julia> f(2)
20
```

Todos os argumentos _sem_ valores predefinidos têm de vir antes de qualquer argumento _com_ valores predefinidos, o que significa que `f(x=2, y)` seria inválido.

### Argumentos nomeados

Todos os exemplos até agora usam `positional arguments`, em que os valores indicados numa chamada à função têm de corresponder à ordem dos argumentos correspondentes na definição da função.

Tal como muitas linguagens, Julia também permite `keyword arguments`.
As chamadas à função têm de indicar o nome do argumento, mas vários argumentos nomeados podem depois ser indicados por qualquer ordem.

Uma característica distintiva de Julia é que os argumentos nomeados (se existirem) na definição da função têm de ser precedidos de um ponto e vírgula `;`, para os separar de quaisquer argumentos posicionais.
Uma chamada à função pode usar `;` ou `,` entre o último argumento posicional e o primeiro argumento nomeado.

```julia-repl
julia> b(x; y) = x + y
b (generic function with 1 method)

julia> b(2, y=3)
5

# keyword is required when calling
julia> b(2, 3)
ERROR: MethodError: no method matching b(::Int64, ::Int64)
The function `b` exists, but no method is defined for this combination of argument types.
```

Os valores predefinidos podem ser indicados opcionalmente, exatamente como nos argumentos posicionais.

É comum acabarmos com uma sintaxe como `myarg=myarg` numa chamada à função, quando uma variável com o mesmo nome do parâmetro foi calculada previamente.
Nesta situação, é permitida uma sintaxe abreviada:

```julia-repl
julia> width = 4.0
4.0

julia> height = √ width
2.0

julia> area(; width, height) = width * height
area (generic function with 1 method)

# repetition
julia> area(; width=width, height=height)
8.0

# shorthand form
julia> area(; width, height)
8.0
```

### Splat e slurp

Estes são os nomes padrão de um aspeto útil da sintaxe de Julia, caso tenhas curiosidade.
Ambos se referem ao operador `...`.

#### Splat

O splatting usa-se nas _chamadas_ a funções, para expandir coleções em valores individuais exigidos pela função.

Talvez seja mais fácil demonstrar do que explicar:

```julia-repl
julia> fxyz(x, y, z) = x * y * z
fxyz (generic function with 1 method)

julia> xyz = [2, 3, 4]
3-element Vector{Int64}:
 2
 3
 4

# Using the vector directly in a function call is invalid
julia> fxyz(xyz)
ERROR: MethodError: no method matching fxyz(::Vector{Int64})
The function `fxyz` exists, but no method is defined for this combination of argument types.

# splatting converts the vector to 3 numbers, used as positional arguments
julia> fxyz(xyz...)
24
```

Algumas "chamadas a funções" estão escondidas por açúcar sintático, por isso o splatting também pode ser usado de formas menos óbvias.

Por exemplo, a atribuição múltipla usa internamente uma função construtora de tuplos:

```julia-repl
julia> first, rest... = [1, 2, 3, 4]
4-element Vector{Int64}:
 1
 2
 3
 4

julia> first
1

julia> rest
3-element Vector{Int64}:
 2
 3
 4
```

Também é possível fornecer argumentos nomeados com splatting, normalmente através de um `named tuple`.
Um `Dict` também funciona, mas as chaves têm de ser símbolos (as strings não funcionam).

```julia-repl
# function with 3 keyword arguments
julia> fabc(; a, b, c) = a + b + c
fabc (generic function with 1 method)

# named tuple
julia> abc_nt = (a=2, b=3, c=4)
(a = 2, b = 3, c = 4)

# there are no positional arguments, so need to use ; before kw argument
julia> fabc(;abc_nt...)
9

# Dict
julia> abc_dict = Dict(:a=>2, :b=>3, :c=>4)
Dict{Symbol, Int64} with 3 entries:
  :a => 2
  :b => 3
  :c => 4

julia> fabc(;abc_dict...)
9
```

#### Slurp

O slurping usa-se na _definição_ de funções, para empacotar um número arbitrário de valores individuais numa coleção.

```julia-repl
julia> f_more(i, j, more...) = i + j + sum(more)
f_more (generic function with 1 method)

julia> f_more(1, 3, 5, 7, 9, 11)
36
```

O nome do argumento que recebe o slurp (neste caso, `more`) não é relevante.
O tipo desta variável é escolhido pelo compilador, mas, no caso dos argumentos posicionais, é provavelmente `tuple` ou algo semelhante.

Também é possível fazer slurp de argumentos nomeados, obtendo um `Dict` (ou algo semelhante).

```julia-repl
julia> f_kwslurp(x, y; switches...) = :mult in keys(switches) ? x * y : x + y
f_kwslurp (generic function with 1 method)

julia> f_kwslurp(5, 6; mult=true)
30

julia> f_kwslurp(5, 6)
11
```

Na chamada pode usar-se qualquer argumento nomeado.
É a definição da função que decide a que argumentos nomeados responder e quais ignorar.
