# Introdução

A maioria das palavras de sequência que já viste devolve sequências *novas* e deixa as entradas intactas: `suffix`, `reverse`, `map`, e por aí fora. Mas os arrays e os vetores também suportam **mutação no local**, e ambos aparecem quando queres registar estado que muda ao longo do tempo.

## Duas variedades de sequência mutável

- **Arrays** (`{ … }`) têm um comprimento fixo. `<array> ( n elt --
  array )` (em [`arrays`][arrays]) constrói um array novo de comprimento
  `n` preenchido com cópias de `elt`.
- **Vetores** (`V{ … }`) crescem e encolhem. Usa `V{ } clone` para criar um
  vetor vazio novo; `<vector> ( n -- vector )` (em
  [`vectors`][vectors]) pré-aloca capacidade para `n` elementos.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## Alterar uma fenda

Estas duas funcionam com qualquer dos dois tipos de sequência, e ambas esperam a sequência depois do índice:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

O `set-nth` atribui; o `change-nth` aplica uma quotation ao elemento na posição `n`.
Ambas estas palavras de [`sequences`][sequences] não devolvem nada para a pilha; o efeito é a própria mutação.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## Crescer e encolher

Estas três só fazem sentido em vetores, uma vez que os arrays não podem mudar de comprimento:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## De vetor para array

Quando construíste um vetor e queres devolver um array de comprimento fixo, o `>array ( seq -- array )` (em [`arrays`][arrays]) devolve um array novo com os mesmos elementos:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`: guardar uma cópia instantânea

A mutação modifica a sequência no local. Se quem chama te entrega uma sequência e estás prestes a alterá-la, o `clone` (em [`kernel`][kernel]) dá-te uma cópia nova e independente, para que a perspetiva de quem chamou não mude debaixo dos pés:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

A mesma precaução aplica-se a `V{ }` e a outros literais vazios. Nalgumas linguagens, `[]` ou `vec![]` aloca um contentor novo sempre que a expressão é avaliada. Em Factor, o literal `V{ }` escrito no teu código é *um* único objeto, partilhado por todos os locais de chamada que o mencionam. Se fizeres `push` diretamente para `V{ }`, a chamada seguinte vê os restos. O `V{ } clone` cria a cópia nova que quase sempre queres.
