# Introdução

Uma declaração `GENERIC:` cria uma palavra cujo comportamento depende da *classe* de um dos seus argumentos. O comportamento concreto vem dos *métodos*, definidos com `M:`.

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

Quando se chama `area`, o Factor examina o topo da pilha, procura o método mais específico cuja classe corresponde e executa-o. Com variáveis locais, podes usar `M::`:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

Os genéricos permitem-te acrescentar novas representações mais tarde sem alterar o código que chama: `area` já funcionava para `square` e `circle`, e o método `rectangle` é reconhecido automaticamente onde quer que se chame `area`.

## Quando um genérico é a escolha certa

Recorre a `GENERIC:` quando:

- Uma única operação tem implementações *genuinamente diferentes* para valores de entrada distintos.
- Esperas que código futuro acrescente novos tipos.
- Queres que o sistema de tipos imponha definições por classe.

Se a variação for apenas uma pequena enumeração de etiquetas, um `case` é mais simples.

## Juntar um mixin com `INSTANCE:`

Um *mixin* é uma classe genérica que está *aberta*: qualquer pessoa pode registar uma nova classe como membro. Muitos dos protocolos incorporados do Factor (sequências, conjuntos, streams, …) são expostos como mixins, pelo que um tuplo personalizado pode adotar os métodos predefinidos do protocolo, bastando declarar-se como instância:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

Depois de `INSTANCE:`, todos os métodos predefinidos `M: shape …` fazem automaticamente o despacho com base em `my-shape`, e qualquer código que peça um `shape` aceita um `my-shape`. O `M:` serve para acrescentar métodos a um genérico; o `INSTANCE:` serve para juntar uma classe a um mixin.

## `TYPED::`: parâmetros de entrada verificados para uma palavra simples

`GENERIC:`/`M:` escolhem um método com base na classe de um argumento. Às vezes não queres despacho, apenas *uma* palavra que exija que os seus parâmetros de entrada sejam de uma determinada classe. O `TYPED::` (no vocabulário `typed`) é o `::` com uma classe escrita a seguir ao nome de cada parâmetro de entrada:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

`n: integer` lê-se como as variáveis locais que já usas, com a classe escrita depois dos dois pontos. Não há despacho (uma definição, um comportamento), mas cada argumento é agora verificado em relação à sua classe. Uma incompatibilidade como `"x" triple` é rejeitada (*expected input value of type integer but got string*), em vez de passar silenciosamente.

A saída pode ser anotada da mesma forma. O `yes?` define o tipo tanto do seu parâmetro de entrada como do seu resultado:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## Funções e constantes matemáticas

Este exercício também se apoia em algumas palavras de `math.constants` e `math.functions` que vais encontrar aqui pela primeira vez:

- `pi`: a constante π, de `math.constants`.
- `sin ( x -- y )`, `cos ( x -- y )`: seno e cosseno de um ângulo em radianos.
- `e^ ( x -- y )`: `e` elevado a `x`. (Para uma base arbitrária, usa `^`.)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
