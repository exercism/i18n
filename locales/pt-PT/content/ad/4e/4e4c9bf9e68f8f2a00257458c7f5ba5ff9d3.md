# Introdução

## Enumerações

Até agora, trabalhámos sobretudo com números e strings.
Para modelar o mundo real, podemos querer um número limitado de valores que uma variável pode assumir.
Podemos querer um tipo dedicado com alguns valores distintos, com nomes distintos.
Por exemplo, numa fábrica de skates, o material do deck pode ser uma escolha entre apenas maple, bamboo ou plastic.

Poderias usar números inteiros para codificar esses valores, mas terias de escrever código extra para verificar se o sistema está a fornecer um valor inválido para o material.
O significado desses [_números mágicos_][magic numbers] é difícil de seguir ao longo do código-fonte e são fáceis de confundir.
Podemos usar `enumerations` para promover código expressivo e restringir comparações acidentais.

## Exemplo de utilização

O termo específico para este tipo de enumeração é `scoped enumeration`.
O excerto abaixo mostra como escrever uma `enumeration` `DeckMaterial`.
Repara na palavra-chave `enum class` e no `;` no fim da definição:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
Agora, repara numa função de preços da loja de skates e nota o operador de resolução de âmbito (`::`) que especifica um `enumerator` da `enumeration`:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## Âmbito

Imagina que tens uma segunda `enumeration` para o material das rodas:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
Embora as rodas e o deck possam ser ambos feitos de _plastic_, os dois não se podem confundir.
São _tipos_ diferentes: `DeckMaterial` plastic e `WheelMaterial` plastic.
Cada `enumeration` tem os seus `enumerators` no seu próprio âmbito, o seu próprio `namespace`.
É por isso que se chamam `scoped enumerations`.

## Enumerações sem âmbito

Podes estar a pensar que, havendo o nome `scoped`, também existirão enumerações `unscoped`. E tens razão.
`Unscoped enumerations` estão a tornar-se menos populares porque partilham todos o mesmo namespace global.
Por causa dessa partilha, não poderias ter duas `unscoped enumerations` com os mesmos `enumerators`, como _plastic_ no exemplo acima.

Além disso, `unscoped enumerations` convertem-se implicitamente em números inteiros.
Repara no exemplo abaixo, que dá um resultado surpreendente:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

Se quiseres converter `scoped enumerations` em números inteiros, podes usar `static_cast<int>`.
