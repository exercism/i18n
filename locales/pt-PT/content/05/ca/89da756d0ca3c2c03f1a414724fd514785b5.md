# Testes

Cada exercício vem com um conjunto de testes unitários e tudo o que é necessário para os compilar e correr.
A implementação é contigo.

## Correr os testes

Abre um terminal na pasta do exercício e corre:

```
make
```

Isto compila a tua solução e os testes e, de seguida, corre os testes.
Volta a correr o comando sempre que alterares a tua solução.

Se tiveres a [Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally), podes usar antes este comando, que também corre o `make`:

```
exercism test
```

Para removeres os ficheiros criados pela compilação, corre `make clean`.

### Sem make

Se não tiveres `make` (no Windows, por exemplo), podes compilar e correr os testes diretamente.
Para o exercício "Bob":

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

Depois, corre os testes no Linux ou no macOS:

```
./run_tests
```

Ou no Windows:

```
.\run_tests
```

## Trabalhar num exercício

Os ficheiros de cada exercício têm o nome do exercício.
Para o exercício "Bob":

| Ficheiro         | Conteúdo                                                          |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90`        | um esqueleto da solução, pronto para completares                  |
| `bob_test.f90`   | os testes                                                         |
| `TesterMain.f90` | a biblioteca de testes                                            |
| `Makefile`       | instruções para o `make`                                          |
| `CMakeLists.txt` | instruções para o [CMake](#using-cmake-instead), que é opcional    |

Só precisas de editar o ficheiro da solução.

Trabalhar cada exercício é um processo que consiste em repetir estes passos até todos os testes passarem:

- Corrige os erros de compilação e, depois, corre os testes para ver quais falham.
- Implementa apenas o suficiente para fazer passar o próximo teste que falha.
- Refatoriza a tua implementação para melhorar a legibilidade, reduzir a duplicação, etc.
- Corre os testes outra vez e passa ao próximo teste que falha.

É impressa uma mensagem por cada teste que falha, seguida de um resumo.
Se algum teste falhar, o `make` termina com um erro.

Cada teste tem um comentário que descreve o teste e, a seguir, o teste propriamente dito, que começa por `call assert_equal`, por exemplo.

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Para desativar um teste, basta comentá-lo com um `'!'`, por exemplo.

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## Usar o CMake em alternativa

Não precisas do CMake, mas pode ser útil se trabalhares num IDE como o Visual Studio ou o Xcode, ou se usares um compilador diferente do GFortran.

A pasta do exercício tem de manter o nome original, porque o CMake usa-o para encontrar os ficheiros de código-fonte.
Começa na pasta do exercício:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

Depois de alterares a tua solução, só são precisos os dois últimos comandos.

**Nota:** Corre sempre o `cmake` numa pasta separada, como `build`.
Correr `cmake .` na pasta do exercício substitui o `Makefile` que vem com o exercício.

O CMake escolhe um gerador adequado ao teu sistema.
Para escolheres outro, usa a opção `-G`, por exemplo, `cmake -G Xcode ..`.
Corre `cmake --help` para veres a lista dos geradores que podes usar.
Com o Visual Studio ou o Xcode, corre os testes com `ctest -V -C Debug`.

Se a tua pasta do exercício não tiver um `Makefile`, foi descarregada antes de estes ficheiros terem sido adicionados aos exercícios.
Mesmo assim, podes usar o CMake.
