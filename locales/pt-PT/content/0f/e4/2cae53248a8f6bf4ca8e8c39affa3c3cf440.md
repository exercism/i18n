# Introdução

Os tipos simples (strings e primitivos) são normalmente comparados quanto à igualdade com `==` e `!=`.

Os tipos de referência (instâncias de classes) são comparados com o método `Equals()` herdado de `Object`. Se o teu objetivo com o teste de igualdade é garantir que dois objetos são exatamente a mesma instância, basta confiar na implementação de `Object`. Caso contrário, tens de substituir `object.Equals()`.

Se sabes que todas as instâncias da tua classe são criadas num único lugar, por exemplo, personagens de um jogo ou de uma simulação, a igualdade de referência é suficiente. No entanto, é provável que sejam criadas várias instâncias da mesma entidade do mundo real (a partir de uma base de dados, através de dados introduzidos pelo utilizador, através de um pedido web). Neste caso, os valores que identificam a entidade de forma única têm de ser comparados quanto à igualdade. Por isso, o método `Equals()` tem de ser substituído e os membros de dados adequados da tua classe são comparados quanto à igualdade.

Um método `Equals()` substituído contém testes de igualdade sobre membros de tipos simples com `==` e sobre tipos de referência com chamadas recursivas a `Equals()`.

A classe `Object` disponibiliza os métodos adequados para comparar dois objetos e detetar se são uma única e mesma instância.

## `Object.GetHashCode()`

O método `Object.GetHashCode()` devolve um código de hash sob a forma de um número inteiro de 32 bits. O código de hash é usado pelas classes _dicionário_ e _conjunto_, como `Dictionary<T>` e `HashSet<T>`, para armazenar e obter objetos de forma eficiente.

A relação entre o código de hash e a igualdade é a seguinte: se dois objetos são iguais (`Equal()` devolve true), então `GetHashCode()` tem de devolver o mesmo valor para os dois objetos. Isto não se aplica na direção inversa. Não é simétrico. O facto de dois objetos terem o mesmo código de hash não significa que tenham de ser iguais. Imagina uma função de pesquisa que primeiro vai a um "bucket" com base no código de hash e depois escolhe o item em particular através do teste de igualdade.

A documentação da API da biblioteca HashCode explica a melhor forma de gerar um código de hash.

Os valores usados no teste de igualdade têm de ser estáveis enquanto a coleção com hash estiver a ser usada. Se adicionares um objeto à coleção com um conjunto de valores e depois alterares esses valores, o código de hash deixa de apontar para o "bucket" correto. Na prática, isto significa que o objeto deve ser imutável. Outras abordagens correm o risco de criar armadilhas para quem faz a manutenção.
