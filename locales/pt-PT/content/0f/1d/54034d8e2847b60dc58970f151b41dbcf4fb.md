# Anexo às instruções

## Notas sobre a implementação de `smallest` e `largest`:

Ambas as funções têm de receber dois argumentos nomeados:
- `max_factor`: int
- `min_factor`: int, por omissão 0

O valor devolvido por ambas tem de ser um `tuple -- (value, factors)`, em que `value` é o próprio palíndromo e `factors` é um `iterable` que contém os dois fatores do palíndromo, por ordem arbitrária.


## Mensagens de exceção

Por vezes, é necessário [lançar uma exceção](https://docs.python.org/3/tutorial/errors.html#raising-exceptions). Quando o fazes, deves incluir sempre uma **mensagem de erro significativa** que indique qual é a origem do erro. Isto torna o teu código mais legível e ajuda imenso a depurar. Nas situações em que sabes que a origem do erro é de um determinado tipo, podes optar por lançar um dos [tipos de erro incorporados](https://docs.python.org/3/library/exceptions.html#base-classes), mas deves continuar a incluir uma mensagem significativa.

Este exercício em particular exige que uses a [instrução raise](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement) para "lançar" um `ValueError` quando a função `largest()` ou `smallest()` recebe um par de fatores que não estão no intervalo correto. Os testes só passam se tanto fizeres `raise` da `exception` como incluíres uma mensagem com ela.

Para lançar um `ValueError` com uma mensagem, escreve a mensagem como argumento do tipo `exception`:

```python
# if the max_factor is less than the min_factor
raise ValueError("min must be <= max")
```
