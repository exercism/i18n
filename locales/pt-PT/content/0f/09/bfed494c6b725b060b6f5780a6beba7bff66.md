# Introdução a pipelines e listas de comandos

Já viste como escrever comandos simples, em que a um comando se seguem os seus argumentos.
Agora vamos ver como criar comandos mais complexos compondo comandos simples.

## Entrada e saída

Antes de começar, uma breve introdução à entrada e à saída.

Os processos têm "canais de E/S padrão".

* Um processo pode consumir _entrada_ no "stdin".
* Um processo pode emitir _saída_ no "stdout".
* Um processo pode emitir _saída de erro_ no "stderr".

O comando `tr` é um exemplo muito puro disto.
Tudo o que faz é ler texto da sua entrada, efetuar transliterações de carateres e imprimir o texto resultante na sua saída.

Vamos ver mais sobre a manipulação dos canais "stdio" mais à frente no programa.

## Pipelines

Esta é uma das "funcionalidades de eleição" da programação em shell.
Os pipelines permitem-te criar transformações sofisticadas sobre um fluxo de texto.

Para produzir uma lista de utilizadores ordenada:

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

O símbolo de pipe (`|`) liga a saída de um comando à entrada de outro.
O `cut` lê a saída do `cat`, e o `sort` lê a saída do `cut`.

~~~~exercism/advanced
* Por predefinição, cada comando de um pipeline corre numa subshell separada.
  (Uma subshell é um processo filho que é uma cópia da shell em execução.)

* Executar pipelines tem um custo de desempenho.
  Se tiveres pipelines longos de comandos semelhantes, considera combiná-los num único comando.
  Por exemplo, pipelines que usam várias instâncias de `grep`, `cut`, `sed`, `awk` e `tr` podem geralmente ser combinados num único comando `awk`, por uma questão de eficiência.

* O estado de saída de um pipeline é o estado de saída do último comando do pipeline.
  Isto significa que, se um comando anterior falhou mas o último comando teve sucesso, o estado de saída do pipeline inteiro é zero.

  Existe uma configuração da shell que pode alterar isto;
  se a configuração "pipefail" estiver ativada (com `set -o pipefail`), o estado de saída do pipeline será:
  * zero se todos os comandos tiverem sucesso, caso contrário
  * o _**último** estado de saída não nulo_ dos comandos do pipeline.
~~~~

## Listas de comandos

Uma lista de comandos é uma sequência de pipelines separados por `;` (ou uma nova linha), `&&` ou `||`.

* `A; B` é uma lista de comandos em que `B` é executado depois de `A` terminar.
* `A && B`, em que `B` só é executado se `A` tiver sucesso (sair com estado zero).
* `A || B`, em que `B` só é executado se `A` falhar (sair com estado não nulo).

O estado de saída de uma lista de comandos é o estado de saída do último comando executado.

Os operadores `&&` e `||` podem ser encadeados, de forma que o comando seguinte seja executado condicionalmente com base no estado dos comandos anteriores.
Por exemplo

```bash
A && B && C && D || E
```

* B é executado se A tiver sucesso,
* C é executado se A e B tiverem sucesso,
* D é executado se A e B e C tiverem sucesso,
* E é executado se **qualquer um** de A, B, C ou D falhar.

~~~~exercism/caution
Usa estes operadores lógicos com moderação.
Podem rapidamente dar origem a código ilegível, ou a lógica difícil de compreender.

Por exemplo, podes pensar que estes são iguais:

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

A diferença é esta: quando é que C é executado?

* No primeiro excerto (a condicional), C só é executado se A falhar.
* No segundo excerto, C é executado se A falhar _ou se A tiver sucesso mas B falhar_!
~~~~

### Utilizações das listas de comandos

Eis alguns exemplos em que as listas de comandos podem simplificar o código.

#### Ler blocos de linhas de um ficheiro

Suponhamos que tens um ficheiro de dados com informação sobre triângulos, e que cada triângulo é representado por três linhas separadas com os lados do triângulo.

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

Podes usar um ciclo while em que a condição é composta por três comandos read separados:

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

Partindo do princípio de que `is_pythagorean` é um comando que determina se os três lados satisfazem a equação de Pitágoras, a saída seria:

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### Asserções

Muitas linguagens de programação têm uma forma de asserção em que é lançada uma exceção se uma condição falhar

```
assert(user == "Administrator", "wrong user");
```

Podemos usar um operador OR no Bash para simular esse comportamento:

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## Considerações de estilo

As listas de comandos longas tornam-se difíceis de ler muito depressa.
O uso generoso de novas linhas pode ajudar bastante.

Considera este exemplo em que uma palavra é adicionada a um array se duas condições se verificarem.

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

O Bash permite-te adicionar uma nova linha depois de um pipe ou de um operador lógico.

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

No entanto, o operador pode passar facilmente despercebido no fim da linha.
Usar uma _continuação de linha_ permite-te colocar o operador em primeiro lugar, o que deixa mais óbvio que a lista continua:

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
Uma _continuação de linha_ é a sequência de dois carateres "barra invertida" e "nova linha" (`\` + `\n`).
Quando o Bash vê essa sequência, esta é simplesmente removida do código, _continuando_ assim a linha atual com a linha seguinte.
Tem cuidado para não deixar espaços entre a barra invertida e a nova linha.
~~~~

Eis outro exemplo

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

ou

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
