# Sobre

As exceções são uma forma de tratamento de erros.
Chamam-se exceções porque aparecem normalmente quando estamos perante um evento inesperado.

Em qualquer ponto do nosso código, podemos lançar uma exceção.
Fazemo-lo com o método `raise`, passando um objeto, normalmente um objeto Exception, embora também possamos usar strings básicas.
Por exemplo, vais ver nos esqueletos dos exercícios que usamos o `RuntimeError` incorporado para dizer ao Ruby que um método ainda não foi implementado.
Também podes usar a sintaxe abreviada `raise(ExceptionObject, params)`.
Se a classe da exceção for omitida, é usado o `RuntimeError` por predefinição.

Por exemplo:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

Quando o Ruby se depara com isto, propaga o erro até ao topo do programa e depois termina.

Por exemplo, se tentares dividir algo por zero, vais ver algo assim:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

É importante notar que as exceções devem ser usadas em casos em que acontece algo excecional, um erro que precisa de tratamento especial.
As exceções não devem ser usadas para o fluxo de controlo de um programa, pois isso é considerado má conceção e leva muitas vezes a um mau desempenho e a dificuldades de manutenção.

## Hierarquia de classes

No Ruby, as exceções seguem uma hierarquia de classes em que `Exception` é a classe base.
Estas são as exceções incorporadas do Ruby mais comuns:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

Apanhar erros de uma classe específica também apanha os erros das suas subclasses.
É por isso que apanhar a partir de `Exception` pode ser perigoso.
O Ruby também usa exceções para tratar mensagens dos «sinais» do sistema operativo, por exemplo `ctrl-c`.
Isto significa que apanhar a partir de `Exception` também captura esses «sinais» do sistema.
Por isso, para evitar comportamentos inesperados, a prática comum para capturar «todos os erros» é apanhar a partir de `StandardError`.

## Sintaxe do rescue
O Ruby também disponibiliza cláusulas rescue alargadas para situações que exigem um tratamento especial:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

Isto pode ser útil, por exemplo, quando trabalhas com IO de rede, em que precisas sempre de te lembrar de fechar uma ligação.

Os blocos rescue do Ruby também podem usar a palavra-chave `retry`, que volta a executar tudo o que está entre o begin e o rescue:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
