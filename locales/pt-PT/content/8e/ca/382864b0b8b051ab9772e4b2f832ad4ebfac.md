# Testes

Cada exercício traz os testes unitários e uma receita de compilação do CMake. A implementação é contigo.
Cada ficheiro de teste destina-se a ser ligado à tua implementação, de forma a produzir um executável de consola que corre os testes. Ao executar o executável de testes, é impressa uma mensagem por cada teste que falha e é devolvido um código de saída diferente de zero quando os testes falham.

O ficheiro de testes tem o nome `<exercise>_test.f90`, portanto, para o exercício "Bob", o ficheiro que contém os testes é `bob_test.f90`. Cada teste tem um comentário que o descreve e, a seguir, o teste propriamente dito, que começa com `call assert_equal`, por exemplo.

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Para desativar um teste, basta comentá-lo com um `'!'`, por exemplo.

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Trabalhar em cada exercício é um processo que passa por:

* Criar a compilação inicial com o CMake
* Para cada teste unitário:
 * Resolver os erros de compilação, para que o teste falhe.
 * Implementar apenas o suficiente para que o teste passe.
 * Refatorar a tua implementação para melhorar a legibilidade, reduzir a duplicação, etc.
 * Descomentar o teste seguinte


## Criar a compilação inicial com o CMake

Cada exercício traz um ficheiro `CMakeLists.txt` juntamente com os testes unitários. Contém a receita de CMake já pronta que trata da compilação por ti. Não deves precisar de editar este ficheiro. A receita fornecida assume que a tua implementação está num ficheiro de código com o nome do exercício.

Por exemplo, o exercício "Bob" espera uma implementação no ficheiro `bob.f90`.

**Cria os ficheiros da tua implementação inicial antes de correres o CMake.**
Se não tiveres o ficheiro `bob.f90` quando correres o CMake para o exercício "Bob", o CMake vai gerar um erro a dizer que não encontrou os ficheiros.
**Estes ficheiros podem estar vazios, mas têm de existir.**

Com esta receita, o CMake consegue gerar um projeto adequado ao teu ambiente, executando `cmake -G` com um gerador adequado e a localização do diretório do exercício. O CMake vai gerar um script de compilação apropriado para o teu sistema operativo. Para manteres esses ficheiros gerados separados do código do exercício, é comum criar um diretório chamado `build` para guardar esses ficheiros de compilação gerados, bem como o código compilado.

Assim, a pasta do teu exercício mantém-se arrumada e sem desordem.

**Nota: Da primeira vez que chamares o `cmake`, a [testlib](###-Testlib) é descarregada automaticamente. A `testlib` é necessária para que os testes unitários funcionem.

Como vais correr o CMake para criar as instruções de compilação de cada exercício, podes querer criar um script bash (Linux/MacOS) ou um ficheiro batch (Windows) para este comando.

Depois de o CMake criar o ambiente de compilação, podes compilar o teu código com o comando adequado ao teu ambiente:

* Linux com make: `make`
* Windows com o Visual Studio: seleciona Build / Build Solution no menu.
* Windows com MingW: `mingw32-make.exe`
* Windows com nMake: `nmake.exe`
* MacOS com o Xcode: seleciona Build na barra de ferramentas

Abaixo tens exemplos de como correr o CMake em diferentes ambientes.

### Linux\MacOS com Make

O nome do gerador para o CMake é `Unix Makefiles`.
Assumindo que o exercício atual é `bob` e que estamos na pasta do exercício:

```
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

Este exemplo mostra a criação de ficheiros vazios para a implementação antes de correr o CMake.

Basta escrever make no diretório de compilação para compilar os testes. Isto deve gerar erros de compilação. Depois de corrigires os erros, corre `make` novamente. Quando todos os erros de compilação estiverem corrigidos, corre os testes:

```
$ ctest -V
```
### Windows com o Visual Studio 2017

O nome do gerador para o CMake é `Visual Studio 15`. O mesmo gerador suporta todas as edições IDE do Visual Studio 2017: Community, Professional e Enterprise. Assumindo que o exercício atual é `bob` e que estamos na pasta do exercício:

```
> copy nul: bob.f90
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

Este exemplo mostra a criação de ficheiros vazios para a implementação antes de correr o CMake.

### Testlib

Os testes dependem de uma pequena biblioteca chamada `testlib`, que é descarregada do github na primeira vez que a compilação é configurada com o cmake.

Caso a descarga falhe, esta pode ser feita manualmente, por exemplo:

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/TesterMain.f90
```
