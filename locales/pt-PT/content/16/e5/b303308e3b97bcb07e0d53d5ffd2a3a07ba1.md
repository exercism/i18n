# Sobre

A Julia, tal como a maioria das linguagens de programação, oferece uma grande variedade de tipos de coleção.

Alguns são intrinsecamente ordenados (incluindo os `Vectors` e os `Arrays` multidimensionais), por isso podemos aceder aos elementos pela sua posição.
Outras coleções não têm ordem (`Sets`, `Dicts`), e os elementos têm de ser acedidos pela chave ou pelo valor.

No caso mais simples, suponhamos que temos um `Vector` de `Ints` e o queremos [ordenar][ref-sorting] por ordem crescente.

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

Simples!
A função [`sort()`][ref-sort] tem um nome óbvio e, aparentemente, devolve o `Vector` ordenado.

_Estava só a brincar!_
A esta altura do currículo, suspeitas talvez (e com razão) que há nuances de que precisamos de falar.

## Funções modificadoras vs. não modificadoras

Depois de correr `sort(v)`, o que é `v`?

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

O vetor original fica inalterado.
A `sort()` é uma função ***não modificadora*** que devolve uma _cópia_ do valor de entrada.

Em muitos contextos, isto é um bom design: temos uma [função pura][wiki-pure-func] cujo comportamento é fácil de analisar, mesmo em código paralelo e distribuído.

Por outro lado, suponhamos que tínhamos um array de mil milhões de strings e o queríamos ordenar.

A ordenação é provavelmente lenta (falaremos disso mais adiante).
Além disso, temos de copiar tudo (_lento!_) e alocar memória suficiente (_vários gigabytes!_) para guardar a cópia.

Compara com este código bastante semelhante:

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

Agora o `Vector` de entrada é ordenado no próprio local, sem cópias, e a ordem original perde-se para sempre.

Isto pode ser eficiente, pode ter erros e provocar [efeitos secundários][wiki-side-effect] inesperados, ou pode ser confuso para outras pessoas que usem o teu código.
_Escolhe com cuidado!_

A [`sort!()`][ref-sort!] é uma [função modificadora][ref-mutating-func] e, por convenção (_muito forte_), qualquer função que modifique os seus argumentos tem um `!` acrescentado ao nome, como aviso aos programadores.

## Ordenar por que critério?

Ordenar valores `Int64` é relativamente simples: até as crianças pequenas percebem que 2 é maior do que 1 e menor do que 3.

Outros tipos podem ser mais complicados, mas, em geral, `x < y` se `isless(x, y) == true`.
A Julia fornece implementações de `isless()` para a maioria dos tipos padrão, e podes definir [métodos][concept-multiple-dispatch] equivalentes para comparar os teus [tipos personalizados][concept-composite-types].

Por exemplo, os carateres Unicode (para as letras europeias, as maiúsculas ficam antes das minúsculas):

```julia-repl
julia> j = collect("Julia")
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)

julia> sort(j)
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0false069 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
```

Também podemos aplicar uma função arbitrária aos elementos antes de ordenar, como [`abs`][ref-abs] para ignorar o sinal ou [`uppercase`][ref-uppercase] para uma ordenação que não distingue maiúsculas de minúsculas:

```julia-repl
julia> nums = [3, -2, -4, 1]
4-element Vector{Int64}:
  3
 -2
 -4
  1

julia> sort(nums)
4-element Vector{Int64}:
 -4
 -2
  1
  3

julia> sort(nums, by=abs)
4-element Vector{Int64}:
  1
 -2
  3
 -4

# j is from "Julia", as previously

julia> sort(j, by=uppercase)
5-element Vector{Char}:
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)

julia> vecs = [[1, 3], [4, 2], [3, 4], [2, 1]];

julia> sort(vecs)  # by default sorts by the first element of the (2-element) vectors
4-element Vector{Vector{Int64}}:
 [1, 3]
 [2, 1]
 [3, 4]
 [4, 2]

julia> sort(vecs, by=last)
4-element Vector{Vector{Int64}}:
 [2, 1]
 [4, 2]
 [1, 3]
 [3, 4]
```

Para [arrays multidimensionais][concept-mda], podemos especificar a palavra-chave `dims` para controlar a direção da ordenação.

```julia-repl
# create a matrix of integers in random order
julia> A = reshape(Random.shuffle(1:9), (3, 3))
3×3 Matrix{Int64}:
 8  4  9
 6  7  5
 2  1  3

julia> sort(A, dims=1)  # sort rows
3×3 Matrix{Int64}:
 2  1  3
 6  4  5
 8  7  9

julia> sort(A, dims=2)  # sort columns
3×3 Matrix{Int64}:
 4  8  9
 5  6  7
 1  2  3
```

## Ordenar com um array de índices

Se os elementos a ordenar forem objetos grandes, pode ser mais fácil trabalhar com o seu índice posicional.

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

Como `langs` é um Vector, cada índice é um número inteiro no [intervalo][concept-range] `1:length(langs)`.
O resultado da chamada a [sortperm()][ref-sortperm] sobre um Vector é uma [permutação][wiki-permutation] desses inteiros, que corresponde à ordenação do Vector de entrada.

## Ordenação parcial

O teu programa precisa de ordenar todos os dados de entrada?
Nos casos em que só os primeiros ou os últimos elementos interessam, pode ser bastante mais rápido fazer uma [ordenação parcial][wiki-partial-sort].

A Julia fornece as funções [`partialsort()`][ref-partialsort] e [`partialsort!()`][ref-partialsort!], que garantem que o elemento ou intervalo de elementos indicado fica correto, mas não dão garantias quanto ao resto dos dados.

O segundo argumento pode ser um número inteiro ou um intervalo, que representa o índice ou os índices dos dados ordenados:

```julia-repl
julia> vsq = [9, 4, 16, 1];  # would be [1, 4, 9, 16] after a full sort

julia> partialsort(vsq, 4)
16

julia> partialsort(vsq, 2:3)
2-element view(::Vector{Int64}, 2:3) with eltype Int64:
 4
 9
```

## Algoritmos de ordenação

Ordenar `[3, 2, 4, 1]` é um desafio fácil, tanto para uma pessoa como para um computador.

Se os dados de entrada forem _muito_ maiores, qual é a melhor forma de os ordenar?

Isto obriga-nos a definir o que é "melhor"!

- O tempo médio mais rápido?
- O melhor caso ou o pior caso? Ou um ponto intermédio, como o tempo no percentil 90?
- A utilização mínima de memória?
- Uma ordenação aproximada ou parcial, que seja "suficientemente boa" para a aplicação em questão?

E, além disso, quais são os dados de entrada?
Podem ser essencialmente aleatórios, mas os casos especiais incluem arrays já ordenados, ordenados pela ordem inversa, ou com muitos elementos repetidos.
Nas mesmas situações, algoritmos diferentes comportam-se de formas muito diferentes.

Criar algoritmos de ordenação novos e melhores é simultaneamente fascinante do ponto de vista intelectual (_para certo tipo de personalidade_) e valioso do ponto de vista comercial: _uma combinação poderosa!_

Por conseguinte, existe uma vasta literatura sobre este tema, que continua a crescer de forma constante.

Na maioria dos casos, a Julia tenta escolher um algoritmo predefinido razoável, embora os programadores possam [indicar uma preferência][ref-algorithms] se for necessário.

O próximo exemplo é ridículo, mas ilustra a sintaxe:

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v, alg=InsertionSort)
4-element Vector{Int64}:
 1
 2
 3
 4
```
