# Acerca de

O tipo `Result` é a solução da linguagem Elm para reportar e recuperar de erros. É um pouco semelhante ao tipo `Maybe`, mas enquanto o `Nothing` do `Maybe` codifica algum tipo de falha, não te diz nada sobre o _porquê_ de ter falhado. O `Result` inclui um contexto sobre a razão pela qual algo falhou.

## Definição e variável de tipo

O tipo `Result` é definido da seguinte forma:

```elm
type Result error value
  = Ok value
  | Err error
```

Em resumo, este tipo codifica o resultado de uma operação que pode ter sucesso e devolver um `value` ou falhar e devolver uma explicação para a falha (`error`).

Isto é conhecido como uma definição de "tipo personalizado" na terminologia de Elm.
Os tipos personalizados são introduzidos em detalhe noutro conceito desta track, mas não vamos precisar disso para compreender especificamente o `Result`.
O `error` e o `value` em `OK value` e `Error error` representam uma variável de tipo, o que significa que pode ser qualquer tipo, como `Int`, `Bool` ou `String`.
Assim, um `Result String Int` é uma variável que se espera conter um `Int`, e se houver um erro este será representado como uma `String`.

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## Leitura do conteúdo de um valor `Result`

A leitura do conteúdo de um valor `Result` faz-se através de "pattern matching".
O pattern matching também é introduzido em mais detalhe noutro conceito, por isso vamos apenas focar-nos em como funciona o pattern matching num `Result`.

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

Sempre que usas um valor `Result`, o compilador de Elm verifica que o teu código trata todas as possibilidades, por isso nunca podes fazer pattern matching a um `Result` e tratar apenas o caso em que existe um `Ok value`.
Isto pode parecer irritante ao início, mas é uma das maiores forças da linguagem Elm.
Isto evita centenas de bugs e torna a refatoração guiada pelo compilador uma experiência destemida e recompensadora.

## Manipulação do conteúdo de um valor `Result`

Existem várias funções para trabalhar com tipos `Result`, que são normalmente preferíveis ao pattern matching. O `Result.map` pode ser usado para mapear o valor, e o `Result.andThen` pode ser usado para encadear funções que podem falhar.

O Result.map é usado para alterar o valor Ok e é útil para encadear funções sem ter de te preocupar se o Result contém um erro ou não. Se o valor for Ok, o Result.map chama a função encadeada (`formatAge` abaixo), mas se houver um erro, o Result.map não faz nada e devolve apenas o erro.

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

O Result.andThen é usado para alterar o valor Ok e é útil para encadear funções sem ter de te preocupar se o Result contém um erro ou não. É semelhante ao Result.map, mas o Result.andThen funciona com uma função encadeada (`formatSpecialBirthday` abaixo) que também devolve um Result. O `Result.map` também consegue fazer isto, mas acaba por criar uma camada extra de aninhamento, que o `andThen` evita habilmente.

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
