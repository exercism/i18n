# Introdução aos ciclos

O Bash tem duas formas de fazer ciclos:

* Repetir alguns comandos _para cada item de uma lista de itens_,
* Repetir alguns comandos _enquanto uma condição for verdadeira (ou falsa)_.

## Ciclos `for`

Para iterar sobre uma lista de itens, usamos o ciclo `for`.

```bash
for varname in words; do COMMANDS; done
```

`words` é expandido através da divisão de palavras e da expansão de nomes de ficheiros (que aprendemos no [conceito de citação][quoting]).
Cada palavra é atribuída, por sua vez, à `varname`, e os COMMANDS são executados.

Aqui estão alguns exemplos que mostram quando o ciclo `for` pode ser útil

* Executar alguns comandos num grupo de ficheiros.

    ```bash
    # source all the bash library files in the current directory
    for file in ./*.bash; do
        source "$file"
    done
    ```

* Executar um comando para cada um dos parâmetros de um script ou função.

    ```bash
    for arg in "$@"; do
        echo "argument: ${arg}"
    done
    ```

* Executar um comando para cada palavra separada por espaços em branco na saída de um comando.

    ```bash
    for i in $(seq 10); do
        echo "${i} squared is $((i * i))"
    done
    ```

    Mais à frente veremos alguns avisos sobre este estilo.

### Ciclo `for` aritmético

O Bash tem, de facto, um ciclo aritmético.
Isto vai parecer algo familiar a quem conhece outras linguagens de programação.

```bash
for ((INITIALIZATION; CONDITION; INCREMENT)); do COMMANDS; done
```

Os parênteses duplos no Bash representam um contexto aritmético (veremos mais sobre a aritmética do Bash num conceito posterior).
O exemplo acima com o `seq` pode ser escrito assim

```bash
for ((i = 1; i <= 10; i++)); do
    echo "${i} squared is $((i * i))"
done
```

### Quando não usar o `for`

[Não leias linhas com o `for`][bashfaq1].

Este é um antipadrão que vais ver com frequência: iterar sobre a saída do `cat`.

```bash
for line in $(cat some.file); do 
    do_something_with "$line"
done
```

Isto está errado por dois motivos.

1. A substituição de comandos não está entre aspas, por isso está sujeita à divisão de palavras.
   Por omissão, a divisão de palavras separa por _espaços em branco_, não apenas por novas linhas.
   Este ciclo `for` está a iterar sobre as **palavras** do ficheiro, e não sobre as linhas.
2. A substituição de comandos não está entre aspas, por isso está sujeita à expansão de nomes de ficheiros.
   Cada palavra do ficheiro será comparada como um padrão glob.

Como aprendemos no [conceito de citação][quoting], a divisão de palavras pode ser controlada com a variável `IFS`, e a expansão de nomes de ficheiros pode ser desativada.
Mas esta solução tende a ser frágil.
O `for` é o método errado para iterar sobre as linhas de um ficheiro.
A forma idiomática de ler um ficheiro é com um ciclo `while`.

## Ciclos `while`

Usa o `while` para repetir uma sequência de comandos _enquanto_ uma condição for verdadeira.

```bash
while CONDITION_COMMANDS; do COMMANDS; done
```

Tal como acontece com o `if` (como aprendemos no [conceito de condicionais][conditionals]), não há sintaxe especial para CONDITION_COMMANDS.
O estado de saída da lista de comandos determina "true" ou "false".

## Controlar os ciclos

O comando `break` salta para fora do ciclo.
O controlo retoma no comando que se segue ao terminador `done` do ciclo.

O comando `continue` salta para a iteração seguinte do ciclo.

## Ler as linhas de um ficheiro

Como foi referido, um ciclo `while` é a forma idiomática de ler um ficheiro.

```bash
while IFS= read -r line; do
    do_something_with "$line"
done < some.file
```

* O conteúdo do ficheiro é fornecido ao ciclo através do redirecionamento `<`.
* O comando `read` devolve "true" se conseguir ler uma linha completa da sua entrada.
  Quando a entrada é consumida, ou se a última linha terminar sem uma nova linha final, o `read` devolve "false".
  * A forma _realmente_ idiomática de ler as linhas de um ficheiro, mesmo que a última linha não termine com uma nova linha, é

    ```bash
    while IFS= read -r line || [[ -n "$line" ]]; do ...
    ```

* A opção `-r` diz ao `read` para não substituir sequências de barras invertidas: uma barra invertida é apenas um caráter normal.
* `IFS=` atribui a string vazia ao IFS apenas durante a execução do comando `read`.
  Isto desativa temporariamente a divisão de palavras, para que quaisquer espaços em branco no início ou no fim da linha de texto que chega sejam preservados.

## `until`

O construtor `until` repete uma sequência de comandos enquanto uma condição for **falsa**.
O ciclo repete _até_ a condição se tornar verdadeira.

```bash
until CONDITION_COMMANDS; do COMMANDS; done
```

É raro usar o `until`.
É mais comum usar um ciclo "while not".

```bash
while ! CONDITION_COMANDS; do ...
```

## Ciclos infinitos

Por vezes queres fazer um ciclo sem fim.
Aqui estão duas formas de o fazer.

1. um ciclo `while` com uma condição cujo estado de saída é sempre de sucesso

    ```bash
    while true; do ...
    ```

2.  um ciclo `for` aritmético com expressões vazias

    ```bash
    for ((;;)); do ...
    ```

## Do-While

Não existe um construtor do-while explícito, mas podes obter o mesmo efeito:

```bash
while true; do
    COMMANDS

    if END_CONDITION; then
        break
    fi
done
```
