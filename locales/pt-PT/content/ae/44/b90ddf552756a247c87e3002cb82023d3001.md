# Listas

Um `ARRAY` é fixo. É criado com um determinado tamanho e mantém esse
tamanho: não há forma de lhe acrescentar nem de lhe remover elementos.

O caderno de um detetive não é assim. As pistas aparecem uma a uma e são
riscadas quando são descartadas. Para isso, queres uma **lista**.

```sather
   notes ::= #LIST{STR};
   notes.append("muddy boots");
   notes.append("broken window");
   notes.size                   -- 2
```

`LIST{T}` guarda valores do tipo `T` por ordem, tal como um array, e cresce
e encolhe conforme lhe pedires.

## Muda no próprio local

`append` altera a lista sobre a qual é chamado e não devolve nada:

```sather
   notes.append("muddy boots");        -- yes
   notes := notes.append("muddy boots");   -- no: append answers nothing
```

Isto é diferente de `FMAP` e `FSET`, em que todas as alterações tinham de
ser atribuídas de novo. Uma `LIST` é um objeto comum, como um `SCOREBOARD`:
entrega-a a uma rotina e a rotina pode alterar a tua.

## Ler e escrever

Parênteses retos, a contar do zero, exatamente como num array:

```sather
   notes[0]                     -- "muddy boots"
   notes[1] := "smashed window";
   notes.size                   -- how many
   notes.is_empty               -- true when there are none
```

## Remover

`remove_index` retira uma posição e tudo o que vem depois sobe uma casa:

```sather
   notes.remove_index(0);       -- the first clue is struck out
```

Por isso, as posições não são permanentes. A posição de uma pista muda
quando se remove uma anterior, o que vale a pena ter em conta antes de
guardar uma.

## Percorrer a lista

`elt!` funciona, tal como num array:

```sather
   loop
      #OUT + notes.elt! + "\n";
   end;
```

## As chavetas

`LIST{STR}` é uma lista de strings, `LIST{INT}` uma lista de números. É uma
classe genérica, exatamente como a que escreveste em `lost-property`. E
agora já consegues ler a da própria biblioteca da mesma forma.
