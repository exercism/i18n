# Tipos de dados genéricos

Os genéricos em Cairo permitem escrever código reutilizável que funciona com vários tipos, evitando a duplicação e facilitando a manutenção.

Podes usar genéricos com funções, structs, enums, traits e métodos.

## Funções genéricas

Uma função genérica funciona com tipos diferentes sem precisar de implementações separadas.

Por exemplo:

```rust
fn largest_list<T>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Aqui, `T` é um marcador de posição para qualquer tipo.

No entanto, Cairo exige limites de traits para garantir que o tipo genérico cumpre requisitos específicos.

Se for preciso que `T` seja droppable, podemos atualizar a assinatura:

```rust
fn largest_list<T, impl TDrop: Drop<T>>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Os limites de traits, como `Drop` ou `PartialOrd`, impõem restrições aos genéricos para operações específicas.

## Restrições anónimas

Se uma implementação de trait não for usada diretamente numa função, podes escrever restrições anónimas com `+`:

```rust
fn smallest_element<T, +PartialOrd<T>, +Drop<T>, +Copy<T>>(list: @Array<T>) -> T {
    let mut smallest = *list[0];
    let mut index = 1;

    while index < list.len() {
        if *list[index] < smallest {
            smallest = *list[index];
        }
        index += 1;
    };

    smallest
}
```

Assim evitas nomear traits como `TPartialOrd`, o que reduz a verbosidade.

## Structs com genéricos

Os genéricos em structs permitem que os campos sejam flexíveis.

Por exemplo:

```rust
#[derive(Drop)]
struct Wallet<T> {
    balance: T,
}

let w = Wallet { balance: 42 };
```

Se uma struct precisar de vários tipos genéricos, basta acrescentar mais marcadores de posição:

```rust
#[derive(Drop)]
struct Wallet<T, U> {
    balance: T,
    address: U,
}

let w = Wallet { balance: 42, address: '0xabc' };
```

## Enums com genéricos

Os enums também podem conter tipos de dados genéricos.

Por exemplo:

```rust
enum Option<T> {
    Some: T,
    None,
}
```

O enum `Option<T>` pode representar um valor opcional de qualquer tipo.

De forma semelhante, `Result<T, E>` permite definir tipos de sucesso e de falha:

```rust
enum Result<T, E> {
    Ok: T,
    Err: E,
}
```

## Métodos genéricos

Os métodos também podem usar genéricos.

Por exemplo:

```rust
#[derive(Copy, Drop)]
struct Wallet<T> {
    balance: T,
}

trait WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T;
}

impl WalletImpl<T, +Copy<T>> of WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T {
        *self.balance
    }
}

let w = Wallet { balance: 50 };
assert!(w.balance() == 50);
```

Também podes definir métodos para tipos genéricos específicos, como `Wallet<u128>`:

```rust
trait WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128);
}

impl WalletReceiveImpl of WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128) {
        self.balance += value;
    }
}

let mut w = Wallet { balance: 50 };
w.receive(100);
assert!(w.balance() == 150);
```

## Misturar tipos genéricos

Os genéricos conseguem lidar com combinações complexas.

Por exemplo, combinar duas instâncias de `Wallet` de tipos diferentes:

```rust
trait WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2>;
}

impl WalletMixImpl<T1, +Drop<T1>, U1, +Drop<U1>> of WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2> {
        Wallet { balance: self.balance, address: other.address }
    }
}

let w1 = Wallet { balance: true, address: 10 };
let w2 = Wallet { balance: 32, address: 100 };
let w3 = w1.mixup(w2);

assert!(w3.balance);
assert!(w3.address == 100);
```

Ao acrescentar restrições `+Drop`, o compilador garante o tratamento correto dos recursos.

Os genéricos são poderosos, mas exigem uma gestão cuidadosa das restrições.

Usa-os para escrever código reutilizável, independente do tipo e conciso.
