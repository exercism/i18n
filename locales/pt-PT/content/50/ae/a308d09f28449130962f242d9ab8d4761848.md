# Sobre

As variáveis locais não substituem o código de pilha; vivem lado a lado com ele. Recorre a elas quando:

- O mesmo valor de entrada é referenciado mais do que uma vez.
- A ordem natural das operações não corresponde à ordem da pilha.
- Estás dentro de uma palavra de ordem superior que entrega à lambda vários valores de uma só vez (o `( key value -- newkey newvalue )` de `assoc-map`).

```factor
USING: locals ;

! Two references to ratio: stack-shuffled vs. local.
: average  ( a b -- avg ) + 2 / ;
:: average ( a b -- avg ) a b + 2 / ;        ! same effect
```

`[let code :> name code :> name ... body ]` introduz ligações locais dentro de uma quotation ou no listener, onde `:>` de outra forma não teria âmbito lexical onde se ligar:

```factor
[let 5 :> x 10 :> y x y + ] .   ! => 15
```

O sufixo de mutação `:>` permite-te reatribuir uma variável local, o que é útil em ciclos de estilo imperativo:

```factor
:: collatz ( n -- count )
    n :> current!
    0 :> count!
    [ current 1 = ] [
        current odd?
        [ current 3 * 1 + current! ]
        [ current 2 / current! ] if
        count 1 + count!
    ] until
    count ;
```
