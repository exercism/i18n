# Sobre

O Swift tem muitos tipos diferentes, mas cada um deles enquadra-se numa de duas classificações: _tipos de valor_ e _tipos de referência_. No Swift, [as structs são tipos de valor][structs-are-value-types] e as [classes são tipos de referência][classes-are-reference-types].

A principal diferença entre tipos de valor e tipos de referência está no que acontece quando atribuis um tipo de valor a uma variável ou constante, ou quando o passas para uma função: o que é atribuído ou passado é, na verdade, uma cópia do valor, e não esse valor em particular. Se modificares uma cópia de uma struct, as outras cópias não são afetadas. Com os tipos de referência, o que é atribuído ou passado é uma referência ao valor, pelo que dois nomes diferentes podem referir-se à mesma instância de uma classe. Isto pode levar à modificação da instância original quando lhe acedes através de um nome diferente.

Assim, com a struct e a classe que definem uma personagem de um jogo e as suas estatísticas, podemos ver o que acontece quando estes elementos são copiados e alterados.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

Repara como alterar as propriedades de `charB` afetou as de `charA`, uma vez que ambos os nomes se referem à mesma instância. Repara também que, no caso das estatísticas das duas personagens, os tipos de valor dentro de um tipo de referência acabam por mudar dentro desse tipo de referência. Isto não é, no entanto, uma violação do comportamento dos tipos de valor, porque `charA.stats` é a mesma instância de `CharacterStats` que `charB.stats`, já que `charA` e `charB` se referem à mesma instância da classe `GameCharacter`. Como podemos ver, as cópias desses tipos de valor não se afetam umas às outras.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

É por isso que as structs exigem a palavra-chave `mutating` antes dos métodos que alteram o estado das propriedades da struct. Alterar a propriedade de uma struct cria, na verdade, uma nova cópia da struct com o novo valor definido para essa propriedade, e a nova cópia substitui a antiga. É um indicador visual de que esta cópia e substituição pode acontecer para valores desse tipo.

Isto tem como efeito secundário que qualquer instância de struct cujas propriedades variáveis mudem, quer por chamada de funções mutating, quer por atribuição direta, _tem_ de ser atribuída a variáveis, e não a constantes. Caso contrário, o compilador gera um erro:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

Os valores iniciais podem continuar a ser criados e acedidos, mas não podem mudar. Esta restrição não se aplica às classes. Se atribuíres uma instância de uma classe a um nome com `let`, o que a constante guarda é a referência à instância, e é essa referência que não pode mudar, não a instância em si. Assim, a instância em si pode mudar, mas a referência não pode passar a apontar para outra instância.

Um resumo do que pode ser alterado com structs e classes definidas com `let` ou `var` é o seguinte:

|         | **struct**                                                                                | **class**                                                                                 |
| ------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **let** | _Não podes_ atribuir uma nova struct ao nome.</br>_Não podes_ modificar nenhuma propriedade da struct. | _Não podes_ atribuir uma nova classe ao nome.</br>_Podes_ modificar as propriedades mutáveis da classe. |
| **var** | _Podes_ atribuir uma nova struct ao nome.</br>_Podes_ modificar as propriedades mutáveis da struct. | _Podes_ atribuir uma nova classe ao nome.</br>_Podes_ modificar as propriedades mutáveis da classe. |

## Identidade

Como dois nomes diferentes podem conter uma referência à mesma instância de uma classe, às vezes é útil verificar se é esse o caso. O Swift usa o operador `===` (_idêntico_) para testar isto (e a sua negação, `!==`).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

Uma vez que dois nomes nunca podem referir-se à mesma instância de uma struct, estes operadores de identidade não estão definidos para as structs.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

Repara que identidade não é o mesmo que igualdade. Segundo muitas definições, `char1` e `char3` seriam considerados iguais, pois todas as suas propriedades têm os mesmos valores, mas não partilham a mesma identidade. A identidade está disponível automaticamente para todas as classes em Swift, mas os programadores costumam ter de escrever os seus próprios operadores de igualdade para determinar se duas instâncias de uma struct ou classe são _iguais_. Fazer isto está além do âmbito deste exercício.
