# Introdução

Como explorado no conceito [`Nothingness`][concept-nothingness], o R tem várias formas de representar dados que estão ausentes (`NULL`), desconhecidos (`NA`) ou matematicamente inválidos (`NaN`, `Inf`).
Em geral, o R tenta usá-los para assinalar problemas no próprio local e continuar sem lançar uma exceção.

## `stop()`

Alguns problemas são demasiado fundamentais para deixar o programa continuar.
Nesse caso, usa `stop(msg)` para interromper imediatamente o programa com um `Error` e imprimir `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

À semelhança de um `assert` noutras linguagens, trata-se de um invólucro prático para `stop()`.
Os parâmetros são um número arbitrário de condições booleanas separadas por vírgulas, e o programa só continua se forem todas `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `warning()` e `message()`

Estas são respostas a condições não fatais, por exemplo:

- Para avisar de um problema do qual o programa pode recuperar, pelo menos em parte.
- Para informar o utilizador do progresso num programa de longa duração.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

A função `suppressWarnings()` pode ser ocasionalmente útil no Exercism, para evitar confundir o test runner com saída indesejada.
