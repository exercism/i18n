# Sobre

Qualquer dado em assembly é uma sequência de bytes.
Isto significa que qualquer dado pode ser visto como um **[array][array]** desses bytes subjacentes.

## Aceder a elementos de um array

Para aceder a qualquer valor na memória, é necessário calcular o seu **endereço efetivo**.
Um endereço efetivo é uma expressão que pode ser composta por:

- um _endereço base_, por exemplo, o indicado pelo rótulo de uma variável.
- um _registo de índice_, possivelmente escalado por `1`, `2`, `4` ou `8`.
- um _deslocamento_ com sinal de 32 bits, que é um número a somar (ou subtrair) ao endereço base.

Repara que este endereço é _indexado a partir de 0_, pelo que um endereço base, sem qualquer deslocamento, aponta para o primeiro byte de uma variável.
É por isso que desreferenciar a memória usando apenas um rótulo, sem qualquer deslocamento, como temos vindo a fazer em conceitos anteriores, produz um valor que começa no seu primeiro byte:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
O x86-64 é [little endian][endianness].
Isto significa que o byte menos significativo de um valor com vários bytes é armazenado no endereço de memória mais baixo.

Consequentemente, ao aceder aos bytes individuais de um valor com vários bytes, é necessário somar um deslocamento positivo ao endereço base para alcançar os bytes mais significativos.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

Uma variável inicializada declarada com uma lista de valores é um array desses valores, tendo cada elemento o tamanho especificado.
No entanto, os deslocamentos são sempre em _bytes_, mesmo quando cada elemento do array tem um tamanho maior:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

Repara que, como os endereços são em bytes, é possível aceder diretamente a um byte individual de qualquer elemento de um array:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

Pela mesma razão, é possível aceder a mais do que o tamanho de um elemento numa única instrução:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
A assembly não faz qualquer verificação de limites nos acessos a arrays.
Um índice para além do fim de um array lê ou escreve memória fora dele.
Isto pode levar a resultados silenciosamente incorretos, à corrupção de outros dados e, se a memória acedida não estiver mapeada, a uma falha em tempo de execução.
Cabe ao programador garantir que todos os endereços efetivos se mantêm dentro do array.
~~~~

## Calcular o tamanho de um array inicializado

O NASM (The Netwide Assembler - o assembler usado neste percurso) tem um símbolo especial (`$`) que indica a localização atual na memória.
Este símbolo oferece uma forma prática de calcular o tamanho total em memória ocupado por um array:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

Quando usado imediatamente a seguir a `example`, o `$` tem o endereço de memória do fim do array.
Isto significa que `$ - example` é a diferença entre esse endereço e o apontado pelo rótulo `example`.
Este é exatamente o tamanho total, em bytes, ocupado pelo array apontado por `example`.

Assim, ao definir `example_length` com este valor, criámos uma variável de 8 bytes que guarda o tamanho, ou comprimento, do array, em bytes.

## A secção .bss

Os dados não inicializados são declarados na **[secção .bss][bss]**.
Na maioria das plataformas, estes dados são preenchidos com zeros pelo sistema operativo no início do programa.

Em NASM, uma variável não inicializada tem um nome, uma diretiva que indica o tamanho dos dados e o número de elementos a reservar.
Cada um destes elementos é separado dos outros por um espaço.

As principais diretivas e os respetivos tamanhos de dados são:

| diretiva | tamanho |
| :-------: | :------ |
|   resb    | 1 byte  |
|   resw    | 2 bytes |
|   resd    | 4 bytes |
|   resq    | 8 bytes |

Por exemplo, isto reserva espaço não inicializado para `3` bytes numa variável chamada `example`:

```x86asm
section .bss
    example resb 3
```

E isto reserva espaço não inicializado para `10` vezes `8` bytes (ou seja, `80` bytes) numa variável chamada `arr`:

```x86asm
section .bss
    arr resq 10
```

As variáveis em `section .bss` são mutáveis, ou seja, permitem leitura e escrita.

Os dados não inicializados podem ser acedidos da mesma forma que os dados inicializados, através do seu endereço efetivo.
Da mesma forma, têm também duração de armazenamento estática e são acessíveis a partir de qualquer função no mesmo ficheiro de código-fonte (e, se declarados `global`, também noutros ficheiros de código-fonte).

## Aceder a endereços de arrays com a instrução Lea

Como foi explorado num conceito anterior, a instrução `lea` calcula um endereço de memória efetivo.
Pode ser usada para calcular o endereço de qualquer elemento de um array, seguindo a mesma semântica.

Repara que, no endereçamento relativo, é frequentemente necessário carregar o endereço da variável para um registo antes de formar um endereço mais complexo:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
Uma das vantagens de `lea` é que esta usa aritmética de cálculo de endereços para calcular um valor sem aceder efetivamente à memória desse endereço.
Isto torna-a útil para fazer cálculos aritméticos mesmo quando nenhum dos registos contém um endereço de memória:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
