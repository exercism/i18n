# Sobre

Em C#, um tuplo é uma estrutura de dados que organiza dados, contendo dois ou mais campos de qualquer tipo.

Normalmente, cria-se um tuplo colocando duas ou mais expressões separadas por vírgulas dentro de um par de parênteses.

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

Como qualquer outra expressão, um tuplo pode ser utilizado de várias formas: em [atribuições][tuple-assignment], para inicializar um campo ou uma variável, como [valor devolvido][tuple-return-values] de um método ou passado como parâmetro. É possível testar a sua [igualdade][tuple-equality]. A igualdade de tuplos é ilustrada em detalhe no exercício `pattern-matching-tuples`, mas, por uma questão de completude, é apresentado um exemplo no código abaixo.

Os campos são extraídos com a sintaxe de ponto. Por omissão, o primeiro campo é `Item1`, o segundo `Item2`, e assim por diante. Os nomes não predefinidos são abordados mais abaixo, em _Nomes_.

Um tuplo pode ser usado como parâmetro genérico, por exemplo `IList<(bool, string)>`.

Além disso, os tuplos suportam a "desconstrução", que abordamos mais abaixo, e podem ser usados em correspondência de padrões, tema que é tratado num exercício posterior.

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

Esta [introdução][tuples] mostra como definir e utilizar tuplos.

## Nomes

Os nomes de campo `Item1`, etc. não tornam o código legível. Existem 3 formas de dar nomes aos campos: a) na declaração do tipo, b) na expressão que o cria, c) através de [inicializadores de projeção de tuplos][tuple-projection-initializers] (não ilustrado aqui).

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

Não tentes ser demasiado engenhoso com o mecanismo de nomenclatura. Na verdade, não passa de açúcar sintático. Por exemplo, não podes alterar os nomes de um tuplo quando lhe atribuis o valor de outro tuplo.

## Desconstrução

Por vezes, é útil pegar num tuplo e atribuir os campos a várias variáveis, inicializando-as quando for adequado. Este mecanismo chama-se [desconstrução][tuple-deconstruction]. (Também pode ser aplicado aos teus próprios objetos. Vê [aqui][udt-deconstruction]).

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## Atribuição de campos

É possível atribuir valores a cada um dos campos de um tuplo individualmente. No entanto, dada a tendência do C# para a imutabilidade, este tipo de utilização não é comum. Muitas vezes, os tuplos são usados como se fossem imutáveis, o que, evidentemente, não são.

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## Contexto

Os tuplos de que estamos a falar não devem ser confundidos com [`System.Tuple`][system-tuple], que provavelmente só se encontra em bases de código legado.

A situação torna-se um pouco mais confusa no que diz respeito a `System.ValueTuple`. A [documentação][system-value-tuple] da última sobrecarga de [`System.ValueTuple`][system-value-tuple] afirma que "os tipos de tuplo de valor fornecem a implementação de runtime que suporta os tuplos em C#". Por "tipos de tuplo de valor", referem-se aqui às sobrecargas genéricas de `System.ValueTuple`. Por "tuplos", referem-se àquilo que nos tem ocupado neste exercício. Com efeito, estão a dizer que `System.ValueTuple` é um detalhe de implementação dos tuplos. É pouco provável que isto interesse muito à maioria das pessoas, na maior parte do tempo. Infelizmente, grande parte da documentação sobre "tuplos", incluindo a da própria Microsoft, está generosamente salpicada de referências a `System.ValueTuple`. Provavelmente, não há problema em passar por cima dessas referências.

## Outras utilizações e limitações

A correspondência de padrões é uma utilização particularmente produtiva dos tuplos. É abordada num exercício posterior.

Os tuplos permitem também alguns floreados estilísticos menores:

- Atribuição múltipla (sobretudo em construtores), por exemplo `(this.field1, this.field2) = (arg1, arg2);`
- Trocar ou reciclar valores, por exemplo `(a, b) = (b, a);`
- Utilização em vez de um `struct` numa lista
- Utilização como chave de um dicionário ou como conteúdo de um conjunto.
- Utilização em LINQ. (LINQ é abordado em exercícios posteriores).

A documentação descreve os tuplos como um mecanismo leve, e é essa a chave para os usar com sucesso. Usar um tuplo em vez de uma classe ou de um struct pode levar a uma repetição fastidiosa dos tipos dos seus campos e, possivelmente, dos seus nomes. Isto aplica-se especialmente à sua utilização como argumento de um método ou como argumento genérico em coleções.

O melhor é usar truques como a atribuição múltipla e a troca de valores com bom senso.

As operações relacionais que não sejam de igualdade e desigualdade não são suportadas.

Repara que os tuplos foram introduzidos na linguagem relativamente há pouco tempo (C# 7), por isso, se os queres usar, certifica-te de que a tua base de código usa a [versão][language-version] 7 ou superior da linguagem.
