# Introdução

O módulo `Time` serve para mostrar datas e horas legíveis para humanos.
Embora seja tecnicamente possível manipular tempos com `Time`, há pacotes da comunidade Elm muito mais adequados a essa tarefa, como [`justinmimbs/date`][date] ou [`CoderDennis/elm-time-format`][elm-time-format].

## Posix

Os tempos são representados pelo tipo opaco `Posix`, que encapsula o tempo de época Unix, o número de milissegundos decorridos desde 1 de janeiro de 1970 à meia-noite UTC.
Um `Posix` é um valor não ambíguo que não varia entre fusos horários, sendo por isso uma boa escolha para guardar o tempo.
Numa aplicação Elm, os tempos `Posix` são normalmente fornecidos por fontes externas, como o navegador.

É possível transformar um `Posix` num número de milissegundos e vice-versa com as seguintes funções:

```elm
posixToMillis : Posix -> Int
millisToPosix : Int -> Posix
```

## Fusos horários

No nosso dia a dia, nós, humanos, normalmente não lemos `Posix` e preferimos a hora local, que depende da nossa localização na Terra e das regras locais de hora de verão.
Em Elm, esta informação está codificada no tipo opaco `Zone`, normalmente fornecido pelo navegador.

Há uma `Zone` especial que está sempre acessível:

```elm
utc : Zone
```

## Horas legíveis

Com um `Posix` e uma `Zone`, temos informação suficiente para mostrar a hora local em qualquer nível de detalhe.
Eis uma lista das funções que se podem usar para isso:

```elm
toYear : Zone -> Posix -> Int
toMonth : Zone -> Posix -> Month
toDay : Zone -> Posix -> Int
toWeekday : Zone -> Posix -> Weekday
toHour : Zone -> Posix -> Int
toMinute : Zone -> Posix -> Int
toSecond : Zone -> Posix -> Int
toMillis : Zone -> Posix -> Int
```

Já terás reparado em mais dois tipos personalizados do `Time`:

```elm
type Month = Jan | Feb | Mar | Apr | May | Jun | Jul | Aug | Sep | Oct | Nov | Dec
type Weekday = Mon | Tue | Wed | Thu | Fri | Sat | Sun
```

Cabe aos utilizadores converter estes tipos personalizados em valores legíveis para humanos.
