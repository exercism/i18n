# Sobre

Como foi explorado no conceito [`Nothingness`][concept-nothingness], o R tem várias formas de representar dados que estão ausentes ([`NULL`][ref-null]), desconhecidos ([`NA`][ref-na]) ou matematicamente inválidos ([`NaN`][ref-finite], [`Inf`][ref-finite]).
Em geral, o R tenta usar estes valores para assinalar problemas no local, e continua sem lançar uma exceção.

## `stop()`

Alguns problemas são demasiado fundamentais para deixar o programa continuar.
Neste caso, usa [`stop(msg)`][ref-stop] para parar imediatamente o programa com um `Error` e imprimir `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Tal como um [`assert`][wiki-assert] noutras linguagens, [`stopifnot()`][ref-stopifnot] é uma forma prática de usar `stop()`.
Os argumentos são um número arbitrário de condições Boolean, separadas por vírgulas, e o programa só continua se todas forem `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

O R tem várias formas de lidar com erros.
Baseiam-se no Common Lisp e diferem bastante das de muitas linguagens populares.

A mais simples é envolver o código potencialmente problemático em [`try()`][ref-try].

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning] e [`message()`][ref-message]

Estas são respostas a condições não fatais, por exemplo:

- Para avisar de um problema do qual o programa se pode, pelo menos em parte, recuperar.
- Para informar o utilizador do progresso num programa de longa duração.

Uma diferença entre elas é que os avisos ficam em cache e são (por predefinição) apresentados quando a função termina, mas as mensagens são apresentadas imediatamente.
Há muitas formas de alterar o comportamento predefinido, que vão além do âmbito desta página.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

A função [`suppressWarnings()`][ref-warning] pode ser ocasionalmente útil no Exercism, para evitar confundir o executor de testes com saída indesejada.

## Gestores de condições

O R tem uma forma alternativa de lidar com estados de erro, mais próxima do espírito da abordagem do Java e de linguagens relacionadas.

Os detalhes vão além do âmbito deste conceito, mas quem estiver interessado pode consultar [`tryCatch`][ref-conditions] e [`withCallingHandlers`][ref-conditions].
