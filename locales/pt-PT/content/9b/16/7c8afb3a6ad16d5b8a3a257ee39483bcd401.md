# Sobre

`TUPLE: child < parent extra-slots ;` declara uma classe cujas instâncias são também instâncias de `parent`. A procura de slots percorre a hierarquia: um objeto do tipo `child` tem todos os slots que a classe mãe declarou, mais os seus próprios, por essa ordem.

```factor
TUPLE: vessel name tonnage ;
TUPLE: cargo-vessel < vessel capacity ;
TUPLE: tanker < cargo-vessel fuel-type ;
```

## Ordem dos argumentos do `boa`

O construtor `boa`, gerado automaticamente, recebe os slots pela ordem de declaração, *primeiro os da classe mãe*. Para o `tanker` acima:

```
tanker boa ( name tonnage capacity fuel-type -- tanker )
```

A ordem dos slots é fixada pela cadeia de herança. Não há forma de intercalar slots da classe mãe com os da classe filha, e reordenar os slots de uma classe mãe quebra o `boa` de todos os descendentes.

## Hierarquia de predicados

Cada declaração `TUPLE:` gera um predicado de classe (`name?`). Com herança, os predicados aninham-se:

```factor
"Esso" 50000 100000 "diesel" tanker boa .

! all three predicates fire
dup tanker?        .   ! => t
dup cargo-vessel?  .   ! => t
dup vessel?        .   ! => t
```

`instance?` (do [`classes`][classes]) faz a mesma pergunta com a classe como argumento na pilha, em vez de a ter incorporada no nome de uma palavra. Ou seja, `obj tanker instance?` é o mesmo que `obj tanker?`:

```factor
USING: classes ;

"Esso" 50000 100000 "diesel" tanker boa
dup vessel instance? .   ! => t
```

Como a classe é agora um valor, o mesmo local de chamada pode testar contra a classe que lhe for entregue, o que um predicado `name?` fixo não consegue fazer.

A relação transitiva `is-a` é também o que o despacho de métodos `M:` percorre: um método definido em `vessel` aplica-se a todos os `cargo-vessel` e a todos os `tanker`, a menos que se aplique primeiro uma redefinição mais específica. Esse lado da história está em [`generics`][generics].

## Herança dos accessors

As palavras accessor (`slot>>`, `>>slot`, `change-slot`) vêm de [`accessors`][accessors] e não estão presas à classe para que foram geradas: qualquer tuple que *tenha* o slot pode usá-las.

```factor
USING: accessors ;

"Esso" 50000 100000 "diesel" tanker boa
[ 1 + ] change-tonnage tonnage>> .   ! => 50001
```

`change-tonnage` foi gerada para `vessel`, mas funciona num `tanker` porque cada `tanker` é também um `vessel`.

## O que isto não é

- **Mixins** (`MIXIN:` / `INSTANCE:`): uma classe pode aderir a vários mixins; a relação é muitos-para-muitos e serve sobretudo para despacho genérico sobre um protocolo comum. O conceito de streams apresenta-os em contexto.
- **Classes de predicado** (`PREDICATE:`): recortam uma subclasse de uma classe existente através de um predicado avaliado em tempo de execução. É uma funcionalidade separada do Factor; não é abordada aqui.
