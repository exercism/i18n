# Sobre

O Ruby é uma linguagem dinâmica e de tipagem forte.
Nas linguagens dinâmicas, o tipo de uma variável ou de um objeto é resolvido em tempo de execução, o que significa que o valor ou o tipo pode ser alterado até ao último momento (quando é analisado pelo intérprete).
E o que queremos dizer com tipagem forte?
Assim que sabemos o tipo de uma variável ou de um objeto, o Ruby é rigoroso quanto ao que podes fazer com ele, por exemplo:

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**Mas**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

Lembra-te de que, em Ruby, tudo é um objeto.
Até as classes são instâncias da classe `Class`.

Por exemplo:

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

Isto significa que também podemos definir classes assim:

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

Por fim, tem em conta que o objeto `Integer` contém valores que podem ser definidos como um ou mais algarismos (consecutivos) e que os seus métodos suportam muitos dos [operadores matemáticos][integers-docs].

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
Na documentação, é comum os métodos de instância serem referidos com uma sintaxe como `Class#method_name`, enquanto os métodos ao nível da classe ou do módulo são referidos como `Class::method_name`.
O `::` chama-se _operador de resolução de âmbito_ e serve para referir a constante ou o método ao nível da classe ou do módulo.
Vais encontrar isto na documentação do Ruby, em listas de discussão e noutras áreas de apoio.
Vais ver que, nos nossos textos, referimos métodos de classe e de módulo como `ClassName.method_name` ou `ModuleName.method_name`, em vez disso.
~~~~
