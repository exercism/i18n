# Introdução

## Comparações

O Python suporta os seguintes operadores de comparação básicos:

| Operador | Operação                   | Descrição                                                                 |
| -------- | -------------------------- | ------------------------------------------------------------------------- |
| `>`      | "maior que"                | `a > b` é `True` se `a` for **estritamente** maior, em valor, do que `b`  |
| `<`      | "menor que"                | `a < b` é `True` se `a` for **estritamente** menor, em valor, do que `b`  |
| `==`     | "igual a"                  | `a == b` é `True` se `a` for **estritamente** igual a `b` em valor        |
| `>=`     | "maior ou igual a"         | `a >= b` é `True` se `a > b` OU `a == b` em valor                         |
| `<=`     | "menor ou igual a"         | `a <= b` é `True` se `a < b` ou `a == b` em valor                         |
| `!=`     | "diferente de"             | `a != b` é `True` se `a == b` for `False`                                 |
| `is`     | "identidade"               | `a is b` é `True` **_se e somente se_** `a` e `b` forem o mesmo _objeto_  |
| `is not` | "identidade negada"        | `a is not b` é `True` se `a` e `b` **não** forem o mesmo _objeto_         |
| `in`     | "teste de pertença"        | `a in b` é `True` se `a` for membro, subconjunto ou elemento de `b`       |
| `not in` | "teste de pertença negado" | `a not in b` é `True` se `a` não for membro, subconjunto ou elemento de `b` |

Todos têm a mesma prioridade (_que é superior à das [operações Boolean][boolean operations], mas inferior à das operações aritméticas ou bit a bit_).

## Comparação entre tipos de dados diferentes

Os objetos de tipos diferentes (_exceto os tipos numéricos_) nunca são considerados iguais por predefinição.
Instâncias não idênticas de uma `class` também _**não**_ serão consideradas iguais, a menos que a `class` defina métodos especiais de [comparação avançada][rich comparisons] que personalizem o comportamento de comparação predefinido do `object`.
A personalização através de `rich comparisons` será abordada num exercício seguinte.
Para mais detalhes (muitos) sobre este tema, consulta [Comparações de valores][value comparisons] na documentação do Python.

Os tipos numéricos são (na sua maioria) uma exceção a esta regra de correspondência de tipos.
Um `integer` **pode** ser considerado igual a um `float` (_ou um [`octal`][octal] igual a um [`hexadecimal`][hex]_), desde que os tipos possam ser convertidos implicitamente para efeitos de comparação.

Para os outros tipos numéricos da biblioteca padrão do Python ([complexos][complex numbers], [decimais][decimal numbers], [frações][rational numbers]), os operadores de comparação estão definidos onde "fazem sentido" (_onde a conversão implícita não altera o resultado_), mas lançam um `TypeError` se os objetos subjacentes não puderem ser convertidos com exatidão para efeitos de comparação.
Para mais informações sobre as regras que o Python usa para a _conversão numérica_, consulta [conversões aritméticas][arithmetic conversions] na documentação do Python.

```python
>>> import fractions

# A string cannot be converted to an int.
>>> 17 == '17'
False

# An int can be converted to float for comparison.
>>> 17 == 17.0
True

# The fraction 6/3 can be converted to the int 2
# The int 2 can be converted to 0b10 in binary.
>>> 6/3 == 0b10
True

# An int can be converted to a complex number with a 0 imaginary part.
>>> 17 == complex(17)
True

# The fraction 2/5 can be converted to the float 0.4
>>> 0.4 == 2/5
True

>>> complex(2/5, 1/2) == complex(0.4, 0.5)
True
```

Qualquer comparação ordenada de um número com um tipo `NaN` (_not a number_) é `False`.
Um efeito secundário confuso da definição de `NaN` do Python é que `NaN` nunca é considerado igual a `NaN`.

```python
>>> x = float('NaN')

>>> 3 < x
False

>>> x < 3
False

# NaN never compares equal to NaN
>>> x == x
False
```

## Comparar strings

Ao contrário dos números, as strings (`str`) são comparadas [_lexicograficamente_][lexographic order], usando os respetivos pontos de código Unicode (_o resultado de passar cada ponto de código da `str` à função incorporada [`ord()`][ord], que devolve um `int`_).
Se todos os pontos de código de ambas as strings coincidirem e estiverem _**pela mesma ordem**_, as duas strings são consideradas iguais.
Esta comparação é feita aos pares: primeiro com primeiro, segundo com segundo, etc.
No Python 3.x, `str` e `bytes` não podem ser diretamente coagidos ou comparados.

```python
>>> 'Python' > 'Rust'
False

>>> 'Python' > 'JavaScript'
True

# Examples with Mandarin.
# hello < goodbye
>>> '你好' < '再见'
True

# ord() of first characters
>>> ord('你'), ord('再')
(20320, 20877)

# ord() of second characters
>>> ord('好'), ord('见')
(22909, 35265)

# And with Korean words.
# Pretty < beautiful.
>>> '예쁜' < '아름다운'
False

>>> ord('예'), ord('아')
(50696, 50500)
```

## Encadeamento de comparações

Os operadores de comparação podem ser encadeados _arbitrariamente_, ou seja, podem ser usados em qualquer combinação e com qualquer extensão.
Repara que a avaliação de uma expressão ocorre de `left` para `right`.

Por exemplo, `x < y <= z` é equivalente a `x < y` `and` `y <= z`, exceto que `y` é avaliado **apenas uma vez**.
Em ambos os casos, `z` _não_ é avaliado **de todo** quando se verifica que `x < y` é `False`.
A isto chama-se frequentemente `short-circuit evaluation`: a avaliação termina se o valor de verdade da expressão já tiver sido determinado.

O `Short circuiting` é suportado por vários operadores boolean, por funções e também pelo encadeamento de comparações em Python.
Ao contrário de muitas outras linguagens de programação, incluindo `C`, `C++`, `C#` e `Java`, as expressões encadeadas como `a < b < c` em Python têm uma [interpretação matemática][three way boolean comparison] e uma precedência convencionais.

```python
>>> x = 2
>>> y = 5
>>> z = 10

>>> x < y < z
True

>>> x < y > z
False

>>> x > y < z
False
```

## Comparar a identidade de objetos

Os operadores `is` e `is not` testam a [_identidade_][object identity] de um objeto, em oposição ao seu _valor_.
A identidade de um objeto nunca muda após a sua criação e pode ser obtida com a função [`id()`][id function].

`<apple> is <orange>` é `True` _**se e somente se**_ `id(<apple>)` == `id(<orange>)`.
`<apple> is not <orange>` devolve o inverso.

Devido ao seu estatuto de singleton, `None` e `NotImplemented` devem ser sempre comparados com itens usando `is` e `is not`.
Consulta a documentação de referência do Python sobre [comparações de valores][value comparisons none] e o [PEP8][pep8 programming recommendations] para mais detalhes sobre esta convenção.

```python
>>> my_fav_numbers = [1, 2, 3]

>>> your_fav_numbers = my_fav_numbers

>>> my_fav_numbers is your_fav_numbers
True

# The returned id will differ by system and python version.
>>> id(my_fav_numbers)
4517478208

# your_fav_numbers is only an alias pointing to the original my_fav_numbers object.
# Assigning a new name does not create a new object.
>>> id(your_fav_numbers)
4517478208


>>> my_fav_numbers is not your_fav_numbers
False

>>> my_fav_numbers is not None
True

>>> my_fav_numbers is NotImplemented
False
```

## Comparações de pertença

Os operadores `in` e `not in` testam a _pertença_.
`<fish> in <soup>` é `True` se `<fish>` for um membro de `<soup>` (_se `<fish>` for um subconjunto de `<soup>` ou estiver contido em `<soup>`_), e é `False` caso contrário.
`<fish> not in <soup>` devolve a negação, ou o _oposto de_ `<fish> in <soup>`.

Para os tipos string e bytes, `<name> in <fullname>` é `True` _**se e somente se**_ `<name>` for uma substring de `<fullname>`.

```python
# A set of lucky numbers.
>>> lucky_numbers = {11, 22, 33}
>>> 22 in lucky_numbers
True

>>> 44 in lucky_numbers
False

# A dictionary of employee information.
>>> employee = {'name': 'John Doe', 
                'id': 67826, 'age': 33, 
                'title': 'ceo'}

# Checking for the membership of certain keys.
>>> 'age' in employee
True

>>> 33 in employee
False

>>> 'lastname' not in employee
True

# Checking for substring membership
>>> name = 'Super Batman'
>>> 'Bat' in name
True

>>> 'Batwoman' in name
False
```
