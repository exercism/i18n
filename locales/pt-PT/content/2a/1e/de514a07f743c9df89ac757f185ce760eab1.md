# Sobre

Os recursos que guardam estado do sistema operativo (handles de ficheiro, sockets, bloqueios) precisam de uma limpeza *garantida*, mesmo quando uma exceção desenrola a pilha. O vocabulário [`destructors`][destructors] do Factor fornece um pequeno framework para isso, e a maioria dos recursos incorporados (`<file-reader>`, `<file-writer>`, sockets, …) já se liga a ele.

## A classe e o genérico

Para aderir ao mecanismo, uma classe estende `disposable` e implementa `dispose*`:

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )` aloca o tuplo *e* regista-o no âmbito de destruidores atual, pelo que uma exceção entre a alocação e o ponto seguro seguinte não pode deixar escapar o recurso. O framework garante que `dispose*` corre **no máximo uma vez** por objeto: chamadas repetidas a `dispose` não fazem nada.

## Quem chama de fora usa `dispose`

| palavra              | efeito                                        |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )`: liberta o recurso; pode ser chamada duas vezes    |
| `with-disposal`   | `( disposable quot -- )`: abre um âmbito para um recurso |
| `with-destructors`| `( quot -- )`: abre um âmbito de registo         |
| `&dispose`        | `( obj -- obj )`: liberta na saída normal *ou* na saída por falha |
| `|dispose`        | `( obj -- obj )`: liberta apenas se o âmbito desenrolar |

`with-disposal` é a forma para um único recurso. Para mais do que um recurso, abre um âmbito `with-destructors` e regista cada aquisição com `&dispose` (queres sempre libertá-lo) ou `|dispose` (liberta apenas em caso de falha; o caminho de sucesso mantém-no).

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## A `cleanup` é a primitiva básica

Para um try/finally pontual, sem registo, [`cleanup`][cleanup] (do `continuations`) é a palavra de nível mais baixo:

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` é estritamente mais poderosa (o registo pode crescer em tempo de execução), mas `cleanup` é a escolha natural quando o par aquisição/libertação é fixo e local.
