# Classes genéricas

Usas `ARRAY{STR}`, `FMAP{STR,INT}` e `FSET{STR}` desde o início.
As chavetas sempre contiveram um tipo. Agora escreves uma classe com
chavetas próprias.

## O problema

O serviço de objetos perdidos precisa de uma caixa que guarda uma coisa e se
lembra de quem a entregou. Uma caixa para uma camisola:

```sather
class JUMPER_BOX is
   attr item : JUMPER;
   ...
end;
```

e depois a mesma classe outra vez para uma garrafa de água, e outra vez para
um telemóvel. Três cópias que diferem numa palavra.

## O parâmetro de tipo

```sather
class LOST_BOX{T} is

   attr item : T;

   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;

end; -- class LOST_BOX{T}
```

`{T}` depois do nome da classe é um **parâmetro de tipo**. `T` não é um
tipo: é um substituto do tipo que for fornecido quando a classe é usada.
Dentro da classe, `T` usa-se exatamente como se usaria qualquer nome de tipo.

## Como usar

Fornece o tipo entre chavetas:

```sather
   jumper ::= #LOST_BOX{STR}("blue jumper");
   count ::= #LOST_BOX{INT}(3);

   jumper.item      -- "blue jumper", a STR
   count.item       -- 3, an INT
```

`LOST_BOX{STR}` e `LOST_BOX{INT}` são dois tipos diferentes. Usar um onde se
esperava o outro é um erro que o compilador apanha, exatamente como se
tivesses escrito as duas classes à mão. E, com efeito, é isso que acontece:
o Sather constrói uma classe separada a partir do padrão para cada tipo
realmente usado.

Por isso, isto não tem qualquer custo em tempo de execução, nem perda de
informação de tipo: `jumper.item` é mesmo um `STR`, e não algo que tenha de
ser verificado ou convertido.

## Mais do que um

Uma classe pode ter vários parâmetros, separados por vírgulas. `FMAP{K,T}` é o
exemplo que já conheces.

```sather
class LABELLED{L,T} is
   attr label : L;
   attr item : T;
   ...
end;
```

## Nomes

Letras maiúsculas isoladas, por convenção: `T` para uma coisa, `K` para uma
chave, `E` para um elemento. A biblioteca usa-as em todo o lado.
