# Introdução

Este exercício parte do que viste no [Backyard Birdwatcher][backyard-birdwatcher] e introduz as palavras de ordem superior que recebem uma *quotation*, um pedaço de código entre parênteses retos `[ ]`, para conduzir a operação.

## Quotations como valores

Uma quotation é apenas um pedaço de código literal. Podes passá-la como dados a outra palavra:

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

Aqui, `[ 2 > ]` é uma quotation que recebe um número e deixa um Boolean. O `count` executa-a em cada elemento e conta os resultados verdadeiros.

## Filtrar e rejeitar

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

O `without` trata o seu segundo argumento como um conjunto: qualquer elemento de `seq` que seja `=` a *qualquer* elemento de `exclude` é descartado. O `sift` é o caso especial de `reject` sem quotation: mantém todos os elementos exceto `f`, o que é útil para limpar as lacunas que um `map` anterior deixou para trás.

### Guardar o resultado do teste

O `find` devolve o *elemento* correspondente. Quando o teste já *calcula* o valor que queres, o `map-find` poupa-te uma segunda passagem: executa a quotation em cada elemento e devolve o primeiro resultado que não seja `f` **e** o elemento que o produziu.

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

A quotation devolve `f` para os elementos que não se qualificam e o resultado que queres guardar para aquele que se qualifica. Se nenhum se qualificar, o `map-find` deixa `f f`, tal como o `find`.

### Filtrar registos por um slot

Quando os elementos são *tuples*, o predicado costuma projetar um slot através do leitor gerado automaticamente `slot>>` e testar sobre esse valor:

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## Passar um valor fixo com `with`

Por vezes, o predicado precisa de um valor que é igual em todas as chamadas: um limite, um divisor, uma string de destino. O `with` (em [`kernel`][kernel]) incorpora esse valor fixo na quotation, transformando uma quotation de dois argumentos `( value elt -- ? )` na quotation de um argumento que o `filter`, o `count`, o `map` e o `each` esperam:

```
with ( value seq quot -- seq curry )
```

Cada chamada por elemento vê `( value elt )` na pilha: primeiro o valor fixo, depois o elemento atual:

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## Mapear e iterar

O `map` (em [`sequences`][sequences]) aplica uma quotation a cada elemento e devolve o array de resultados. O `each` faz a mesma passagem mas descarta os resultados, o que é útil quando a quotation corre apenas pelos seus efeitos secundários. O `2map` percorre *duas* sequências ao mesmo ritmo e combina os elementos correspondentes; o `2each` e o `2reduce` são os seus primos de efeitos secundários e de acumulação; o `zip` é a forma abreviada de "emparelhar sem combinar":

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

O `2reduce` encadeia um acumulador pelas duas sequências em simultâneo: a sua quotation recebe `( accumulator elt1 elt2 -- accumulator' )`. Aqui acumula um produto escalar: cada par é multiplicado e os produtos são somados (`1*10 + 2*20 + 3*30`):

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

O `map-as` é o primo do `map` que força o tipo da sequência de saída: passa um `{ }` ou `V{ }` vazio como exemplar para substituir o tipo predefinido da entrada (caso contrário, mapear uma string para não carateres dá erro quando o Factor tenta voltar a empacotar os resultados numa string).

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

Ambas as formas de duas sequências param no comprimento da entrada mais curta. O `zip` é o mesmo que `[ 2array ] 2map`: mantém os pares em vez de os colapsar.

## Ordenação

O `sort` devolve uma cópia ordenada por ordem natural; o `sort-by` (em [`sorting`][sorting]) ordena por uma chave extraída de cada elemento:

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## Agregação

O `map-sum` (em [`sequences`][sequences]) mapeia uma quotation pela sequência e soma os resultados numa única passagem:

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## Mínimo e máximo

O `minimum` e o `maximum` devolvem diretamente o menor ou o maior elemento de uma sequência. O `minimum-by` e o `maximum-by` (todos em [`sequences`][sequences]) devolvem o elemento cuja chave extraída é a menor ou a maior:

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## Escrever a tua própria palavra de ordem superior

Quando a *tua* palavra recebe uma quotation como argumento em tempo de execução e a encaminha para o `map`, o `filter`, o `each`, etc., declara a tua palavra com `; inline`. Isso diz ao compilador para embutir a tua palavra em cada local de chamada, onde a quotation é um literal conhecido. Sem isso, o compilador não tem forma de saber o efeito de pilha da quotation.

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

As palavras construídas apenas com quotations literais não precisam de `inline`, só aquelas que deixam passar uma quotation *de entrada*.

Se uma dessas palavras `inline` se chamar a *si própria*, um combinador recursivo, declara-a antes como `; inline recursive`. Sem essa palavra extra, o compilador para com *"The inline recursive word ... must be declared recursive"*, o que te diz exatamente o que acrescentar.

## Extrair o segundo elemento

Para um array de 2 elementos, o `second` devolve o seu segundo elemento. O `first` devolve o primeiro. Ambos estão em [`sequences`][sequences].

## Números para strings

O `number>string ( n -- str )` (em [`math.parser`][math.parser]) transforma um número na sua forma de string decimal:

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
