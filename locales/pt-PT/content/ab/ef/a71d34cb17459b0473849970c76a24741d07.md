# Sobre

`String` e `&str` são duas formas fundamentais de trabalhar com dados textuais em Rust.
Conhecer as suas características e a forma como funcionam em conjunto é muito útil.
Este documento explica de que forma se sobrepõem e apresenta alguns conselhos básicos.
`String` é um vetor de bytes `u8` com posse.
`String` é mutável.
`&str` é uma referência emprestada a um slice de String.
`&str` é imutável.

A pronúncia correta de `&str` é "ref string".
`String` é uma representação, potencialmente mutável, de uma sequência de pontos de código Unicode, codificada em UTF-8.

`&str` é uma vista só de leitura de uma sequência UTF-8 bem formada.
Como é uma referência, é `Copy` e pode ser partilhada.

`String` e `&str` em Rust não podem ser indexados como poderias fazer noutras linguagens.
Por exemplo, isto não funciona:

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

Isto deriva das seguintes propriedades:

- As strings são UTF-8, cuja primitiva não é um byte, mas sim um ponto de código Unicode: `char`.
- Os pontos de código Unicode ocupam até 4 bytes, mas são codificados com largura variável.
- Por isso, é impossível calcular a posição do `n`-ésimo ponto de código sem iterar sobre os carateres codificados de facto, porque, depois do primeiro caráter, a posição do caráter seguinte depende da largura dos anteriores.
- Por este motivo, os autores da biblioteca padrão de Rust optaram por não implementar o trait `Index` para strings: embora indexar um array de bytes demore um tempo constante, indexar uma string pode demorar bastante tempo. Isto viola o princípio da menor surpresa.

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## Converter uma `String` numa `&str`

`String` implementa `Deref<Target=str>`.
Este trait tem um tratamento especial por parte do compilador: significa que qualquer referência a uma `String` pode ser automaticamente e de forma transparente convertida num `&str`.
Isto implica o seguinte:

- Qualquer código que espere, por exemplo, um argumento `&str` pode, em vez disso, aceitar um `&String`.
- Qualquer método implementado para `&str` também pode ser chamado numa `String`.

(Se, de forma genérica, quiséssemos poder receber qualquer forma de referência a um `str`, poderíamos ter um argumento do tipo `impl AsRef<str>`, mas, tipicamente, é comum escrever os argumentos como `&str`.)

## Converter uma `&str` numa `String`

Há muitas formas de criar uma `String` a partir de uma `&str`:

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

Todas as formas acima exigem alocar memória para a `String` (no heap).
É por isso que `&str` está disponível em no_std, mas `String` não.

(A crate [heapless](https://crates.io/crates/heapless) é frequentemente utilizada quando se
manipulam strings em no_std.)

## Usar String e `&str` em structs

Esta secção aborda quando usar `String` ou `&str` para campos de structs.
Vais ver frequentemente structs definidas com `String` em vez de `&str` para os valores dos campos.

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

Ao usar `String`, a struct detém os dados.
Isto torna o código mais fácil de ler e de ensinar a principiantes.
Mas também significa que vão ocorrer alocações no heap para cada campo.
`&str` empresta dados textuais, pelo que tem um melhor desempenho, à custa de a tua struct ter de definir parâmetros de tempo de vida.
O [tutorial da crate csv][csv-tutorial] demonstra e explica estas ideias de forma bastante prática e clara.

## Notas de desempenho

As `String` são alocadas no heap, pelo que podem ser mais dispendiosas de usar.
As `&str` são referências partilhadas, pelo que não exigem realocações frequentes.
