# Sobre o básico

Kotlin é uma linguagem de tipagem estática, concebida para ser totalmente interoperável com Java.

Ao contrário do Java, o Kotlin:

- tem uma sintaxe mais limpa e mais concisa;
- incorpora muitas funcionalidades das linguagens funcionais;
- tem um grande suporte para valores que podem ser nulos.

## Variáveis

Como o Kotlin é uma linguagem de tipagem estática, é necessário _saber_ o tipo de cada valor em tempo de compilação.

No entanto, a [inferência de tipos][inference] do Kotlin é muito poderosa, por isso _especificar_ o tipo é muitas vezes opcional.

Há duas formas de declarar uma variável.

1. `val` cria uma variável imutável, e tentar alterá-la é um erro de compilação.

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. `var` cria uma variável mutável.

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

Como as variáveis imutáveis eliminam uma classe comum de bugs, incentiva-se o uso de `val` sempre que possível.

Além disso, nem sequer uma `var` pode mudar de tipo:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

Para reduzir a distração visual, os tipos explícitos serão, na sua maioria, omitidos deste plano de estudos.
Ainda assim, recomenda-se que especifiques os tipos pelo menos para:

- APIs públicas
- assinaturas de funções
- onde seja necessária documentação

Algumas empresas e organizações exigem uma segurança de tipos estrita e não permitem a inferência de tipos, enquanto outras a restringem a tipos «simples», ou adotam a inferência de tipos por completo.

```kotlin
val x: Int = 42  // => 42
```

Em geral, os nomes de variáveis e funções devem estar em `camelCase`, não em `snake_case`.

## Funções

Declara uma função com a palavra-chave `fun`.
Ao contrário do Java, as funções não têm de fazer parte de uma classe.

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

Alguns pontos a ter em atenção:

- Os parênteses `()` são necessários depois do nome da função, mesmo que a função não receba argumentos.
- Os argumentos das funções têm de especificar o tipo: não há inferência de tipos (ao contrário do que acontece com as variáveis).
- O corpo da função fica entre chavetas `{ }` (mas vê mais abaixo).
- A palavra-chave `return` é obrigatória se a função devolver um valor.
- Os pontos e vírgulas `;` no fim das linhas são opcionais e, normalmente, são omitidos.
- Os operadores aritméticos `+`, `-`, `*`, `/` são semelhantes aos da maioria das linguagens mais populares.

No entanto, para estas funções muito simples, de «expressão única», existe uma sintaxe abreviada:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
As funções podem ter parâmetros com valores predefinidos.
Esses valores são usados quando são omitidos no local onde a função é invocada:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

As funções no Exercism devolvem, normalmente, um valor (por causa da forma como o executor de testes está estruturado).
Para usares o Kotlin de forma mais ampla, pode ser útil saberes que uma função que não devolve nenhum valor pode omitir o tipo de retorno e a palavra-chave `return`.

Diz-se, então, que tem um tipo de retorno `Unit`: equivalente a `void` em Java e em várias outras linguagens.

## Comentários

Os comentários de uma linha começam com `//` e o resto da linha é ignorado.

Os comentários de várias linhas começam com `/*` e terminam com `*/`.

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

Isto é igual ao Java.
