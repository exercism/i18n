# Sobre

## Booleanos em Julia

Os valores verdadeiro ou falso são representados pelo tipo `Bool`.
Contém apenas dois valores: `true` e `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

Ao contrário de várias outras linguagens, a Julia não tem deliberadamente o conceito de «truthiness», e só as expressões que são avaliadas como `true` ou `false` serão tratadas como um `Bool`.

Concretamente, arrays ou strings vazios *não* serão interpretados como `false`.
Tem de haver um teste adequado, como `isempty()`, se quiseres um tratamento especial para valores vazios.

## Operadores booleanos

Há três [operadores booleanos][boolean-operators] em Julia.

`&&` é o «e» booleano.
Resulta em `true` se as expressões em *ambos* os lados de `&&` forem `true`.

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||` é o «ou» booleano.
Resulta em `true` se uma expressão em *qualquer* dos lados de `||` for `true`.

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!` é o «não» booleano.
Troca (inverte) os valores `true` e `false`.

```julia-repl
julia> !true
false

julia> !false
true
```

Operadores semelhantes serão conceptualmente familiares para quem usa muitas outras linguagens, embora a sintaxe exata possa variar entre linguagens.

## Precedência de operadores

Em expressões mais complexas, pode ser útil saber que `&&` tem uma [precedência][operator-precedence] ligeiramente superior a `||` *(tal como `*` é aplicado antes de `+` em expressões aritméticas)*.

Confiar nisto pode ser confuso e propenso a erros.
Para maior clareza, usa parênteses para deixar a tua intenção clara.

## Avaliação de curto-circuito

A expressão `true || x` depende do valor de `x`, ou o compilador pode ignorar `x`?

A Julia avalia expressões booleanas da esquerda para a direita e para quando tem um resultado inequívoco.

Por exemplo, `true || x` tem de ser `true`, independentemente de `x`, por isso `x` não é avaliado.
Da mesma forma, `false && y` é `false`, sem necessidade de avaliar `y`.

Inversamente, `true && x` é `true` *apenas se* `x` for `true`, por isso `x` tem de ser avaliado.

Da mesma forma, se encadearmos vários operadores:

```julia-repl
julia> true && false && something_else
false
```

Como `true && false` tem de ser `false`, o `something_else` não é importante e é ignorado pelo compilador.

Neste caso, `something_else` não existia como variável, mas incluí-lo neste contexto não deu erro *(testa isto no REPL se tiveres dúvidas)*.

Este tipo de avaliação de curto-circuito é frequentemente usado por programadores de Julia como um atalho para detetar problemas de execução e casos-limite:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

Por exemplo, o `do_something` pode ser um `return` antecipado da função se `all_ok` for `false`, ou atribuir um valor predefinido a uma variável antes de continuar.

Isto é um ligeiro abuso da sintaxe booleana, mas pode ser muito conveniente.

## Como funcionam os booleanos internamente

Se um booleano for incluído numa expressão *aritmética*, `true` é interpretado como `1` e `false` como `0`, refletindo a forma como são armazenados.

Se estás habituado a linguagens de mais baixo nível (C e semelhantes), *por favor*, evita usar isto com frequência.
Vai reduzir a legibilidade do código e tornar a depuração mais difícil.

Por vezes, podes ver os valores numéricos usados como uma forma rápida de contar quantas coisas são `true`.

```julia-repl
julia> true + false + true
2
```
