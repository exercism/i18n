# Noções básicas de Unison

## Termos e funções

Os termos e as funções são as unidades básicas da escrita de um programa em Unison.

Um "termo" é aquilo a que chamamos um valor estático. Define-se com `name = expression`, opcionalmente precedido por uma assinatura de tipo com a forma `name : MyType`. O Unison suporta inferência de tipos, por isso é possível que a assinatura de tipo seja omitida em definições simples.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

As funções em Unison têm a forma `myFunctionName argument1 argument2 = myImplementation`; começam com o nome da função, seguido de argumentos separados por espaços.

```
getMax a b = Nat.max a b
```

As funções podem incluir opcionalmente uma assinatura de tipo. O último tipo à direita é sempre o tipo devolvido final da função, e cada argumento é separado pela seta de função `->`.

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Para chamares uma função, usa o nome dela seguido dos argumentos, separados apenas por espaços.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Ao chamar uma função, o Unison tenta tratar tudo o que vem imediatamente à direita como seu argumento, o que nem sempre produz a ordem desejada de avaliação da função.

Digamos que queremos obter o valor `1` da seguinte expressão

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Tal como está escrito, `shouldBe1` é avaliado como `0`, porque a ordem implícita de aplicação da função é `getMax 1 10`, que dá `10`, e depois `10 - 10`, que dá `0`.

Podes usar parênteses para reagrupar a expressão na ordem de operações desejada.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Expressões de observação

O Unison oferece uma forma de avaliar código rapidamente, chamada "expressão de observação". Uma expressão de observação começa com o símbolo `>` e é seguida da expressão a avaliar. As expressões de observação podem ser escritas em qualquer ficheiro com a extensão `.u`. Quando guardares o ficheiro, deves ver o resultado da avaliação da expressão na consola do Unison Codebase Manager (UCM). Sempre que possível, nestes documentos, tentamos mostrar uma expressão com o resultado esperado depois de a avaliar numa expressão de observação.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Funções multilinha

As funções multilinha do Unison usam indentação ou blocos `let` para delimitar o código, ou seja, o "âmbito léxico".

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Tudo o que está no mesmo nível de indentação partilha o mesmo âmbito, e é por isso que podemos referir a variável `newBeginning` na última linha.

## Namespaces e instruções `use`

Os namespaces são a forma como agrupamos e organizamos as funções do Unison. Podes pensar neles como algo análogo a "diretórios". Proporcionam estrutura e agrupamento lógico.

Podes trazer as funções de um namespace para o âmbito com uma instrução `use`.

Imagina que estás a escrever uma função que recorre a valores `List` do Unison. Sabes que vais precisar de funções como `List.map` e `List.flatMap`, em que `List` é o namespace e `map` e `flatMap` são funções. Para evitares repetições, podes optar por trazer tudo do namespace `List` para o âmbito léxico da tua função, assim:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

A linha `use List` desambigua as referências a `map` e `flatMap`. Podes ler mais sobre as [instruções `use` aqui][use-statements].

## A biblioteca padrão do Unison

A biblioteca padrão do Unison chama-se `base`. Se seguiste o guia de início rápido e tens uma base de código criada localmente, a biblioteca padrão deve ter sido descarregada automaticamente. Podes consultar a documentação da biblioteca padrão online em [Unison Share][unison-share-base].

## Comentários e literais de documentação

Os comentários em Unison são uma funcionalidade um pouco invulgar. Quando escreves código Unison, podes criar texto no teu ficheiro com extensão `.u` que não é interpretado, com a seguinte sintaxe:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_No entanto_, como o código Unison é guardado como um hash da sua árvore de sintaxe abstrata, e não como ficheiros de texto no sistema de ficheiros, os comentários que são "decorações" textuais de uma determinada função ou termo Unison no ficheiro não podem, na verdade, ser guardados e renderizados de novo para partilha. Se quiseres acrescentar informação ao teu termo Unison de uma forma que fique guardada para outros lerem e compreenderem, podes usar um literal de documentação.

A documentação é um valor de primeira classe na linguagem de programação Unison. Isso significa que um elemento `Doc` pode ser atribuído a um valor, passado como valor para uma função, ou devolvido como valor de uma função. Os elementos de literal de documentação abrem e fecham com chavetas duplas. Eis como podemos usar o elemento `Doc` como comentário.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
