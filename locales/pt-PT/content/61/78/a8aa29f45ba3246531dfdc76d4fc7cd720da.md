# Boolean

`BOOL` guarda um de dois valores: `true` e `false`.

```sather
   ready : BOOL is
      return true;
   end;
```

## Comparação

| Operador | Pergunta | Exemplo |
| --- | --- | --- |
| `=` | é igual? | `age = 13` |
| `/=` | é diferente? | `age /= 13` |
| `<` | menor que | `age < 13` |
| `<=` | menor ou igual | `age <= 13` |
| `>` | maior que | `age > 13` |
| `>=` | maior ou igual | `age >= 13` |

Estes operadores funcionam com números, e o `=` e o `/=` também funcionam com strings.

## Os três operadores

| Operador | Escrito | É verdadeiro quando |
| --- | --- | --- |
| and | `a and b` | ambos são verdadeiros |
| or | `a or b` | pelo menos um é verdadeiro |
| not | `~a` | `a` é falso |

O `and` e o `or` usam avaliação de curto-circuito: assim que o `a` se revela falso, o `a and b` não se dá ao trabalho de olhar para o `b`, porque a resposta já está decidida. Do mesmo modo, o `a or b` fica por aí se o `a` for verdadeiro. Isso é importante quando o lado direito é caro de calcular, ou daria problemas se chegasse a ser executado.

## Devolver uma comparação diretamente

Uma rotina cujo único trabalho é fazer uma pergunta deve devolver a pergunta, e não escolher uma resposta com um condicional:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

Escrever `if age >= 13 then return true else return false end` ocupa três linhas para dizer o que a comparação já dizia, e qualquer leitor com experiência vai reparar nisso.

## Precedência

O `~` tem a maior precedência, depois o `and` e por fim o `or`. Por isso,

```sather
~a and b or c
```

significa `((~a) and b) or c`. Os parênteses não custam nada a escrever e valem a pena sempre que, sem eles, o leitor tivesse de se lembrar dessa ordem para acompanhar a linha.
