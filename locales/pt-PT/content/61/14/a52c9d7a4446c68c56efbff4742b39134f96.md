# Introdução

As expressões regulares são uma forma extremamente versátil de fazer _correspondência de padrões_ em strings, recorrendo a uma Linguagem Específica de Domínio (DSL) concebida para esse fim.

Muitas capacidades de regex estão incorporadas no R base, e podes encontrar exemplos em código mais antigo.

Para código novo, é _vivamente_ recomendado usar a biblioteca [`stringr`][web-stringr].

Como referido no [Conceito de Strings][concept-strings], o `stringr` tem boa documentação, normalmente escrita pelo(s) autor(es) do pacote.

- Um [site de referência][web-stringr]
- Um [guia rápido][cheat-stringr].
- Um [capítulo sobre strings][book-strings] e um [capítulo sobre regex][book-regex] em "R for Data Science".

Muitas das funções já abordadas no Conceito [`Strings`][concept-strings] foram concebidas para fazer pesquisas com regex por predefinição.

Mantivemos o Conceito de Strings relativamente simples, fazendo correspondência apenas com literais de string, mas qualquer padrão de regex pode ser usado em alternativa.

Formalmente, cria-se uma regex em R chamando [`regex()`][ref-regex].
Por conveniência, as funções do `stringr` tratam qualquer string de padrão como uma regex.
No exemplo abaixo, o primeiro `str_replace_all()` é açúcar sintático para a segunda versão:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

O [guia rápido][cheat-stringr] é uma referência útil: todas as funções com um argumento `pattern` (impresso a vermelho) aceitam uma regex, e a página 2 resume a sintaxe de regex.

Repara que a função [`regex()`][ref-regex] pode continuar a ser importante se precisares de substituir os valores predefinidos, como a distinção entre maiúsculas e minúsculas ou o locale.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

Muitos códigos de regex incluem uma barra invertida, como o `\s` usado acima.
Em strings normais de R, `\` tem de ser escapado duplicando-o, daí `"\\s"`.

As barras invertidas podem multiplicar-se e tornar-se confusas, por isso pode ajudar usar [strings raw][book-raw] em casos complexos.

Por predefinição, a sintaxe para definir uma raw string é `r"( )"`, mas são permitidos outros delimitadores.
Como os parênteses `( )` e os parênteses retos `[ ]` são ambos comuns na sintaxe de regex (para grupos de captura e grupos de opções), as chavetas `{ }` podem ser uma boa escolha.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## Detetar correspondências

Aqui estão algumas perguntas e algumas funções que podem ajudar a respondê-las.

Alguns exemplos usam `fruit`, um vetor de 80 nomes de frutas incluído no `stringr` para praticar.

_Uma string contém uma correspondência?_
`str_detect()`, ou `str_starts()` e `str_ends()` para evitar usar as âncoras `^` ou `$`.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_Devolver apenas strings que contenham uma correspondência?_
Usa `str_subset()` para obteres as strings e `str_which()` para obteres os índices.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_Quantas correspondências em cada string?_
Usa `str_count()`.

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_Onde está a correspondência?_
`str_view()` para uso interativo, `str_locate()` ou `str_locate_all()` de forma mais geral.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## Capturas

Habitualmente, queremos saber _o que_ corresponde.
Isto consegue-se incluindo grupos de captura entre parênteses dentro da regex.

É possível referir novamente as capturas dentro da mesma regex, usando `\1`, `\2`, etc.
Por exemplo, encontrar pares de letras repetidos:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

Com uma sintaxe semelhante, as capturas podem ser usadas em strings de substituição:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

Recolhe as correspondências para processamento posterior com a função `str_match()`, para apenas a primeira correspondência, ou `str_match_all()`, para todas as correspondências.

Os grupos de captura tendem a produzir resultados complicados em qualquer linguagem.
A abordagem do R (_que também é vetorizada, como desafio adicional_) passa por gerar uma matriz a partir de `str_match()`, com uma linha por string de entrada, a coluna 1 com a string correspondida completa e as restantes colunas com os vários grupos de captura.

Usar grupos com nome pode ser uma vantagem, uma vez que se tornam os nomes das colunas na matriz de resultados.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

Não falámos muito sobre matrizes neste programa, embora exista um [documento do conceito][concept-matrices-arrays] que podes consultar.
As matrizes não se dão bem com o ecossistema Tidyverse, apesar de fazerem parte do R base há muito tempo.

Em resumo: trata as matrizes como vetores com 2 índices, pela ordem `[rows, cols]`.
Deixa qualquer um dos índices em branco para obteres a linha ou a coluna completa.

Quando obténs uma única linha `r` com `m[r,]` ou uma única coluna `c` com `m[,c]`, o valor devolvido é achatado para um vetor por predefinição.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

Inevitavelmente, `str_match_all()` produz resultados com ainda mais estrutura:

- O resultado é uma lista, com um elemento por cada string de entrada.
- Se houver apenas uma string de entrada, usa `unlist` no resultado com a indexação `[[1]]`, como descrito no [Conceito de Listas][concept-lists].
- Cada elemento é uma matriz, com as colunas tal como em `match()`.
- Cada linha da matriz é uma captura bem-sucedida.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

Claro que as correspondências podem falhar.
O resultado será então o valor especial `NA`.
Prepara-te para testar isto, como descrito no [Conceito de Nada][concept-nothingness].

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
