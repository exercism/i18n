# Testes

Podes executar os exercícios de Odin dentro do diretório do teu projeto do Exercism, mudando para o diretório do exercício e executando `odin test .`.

```sh
cd "$(exercism workspace)"/odin/leap
odin test .
```

## Ativar as verificações da linguagem

Enquanto estás a testar, o Odin pode fazer "vet" ao teu código: pode procurar coisas como importações e variáveis não utilizadas.

Executa os teus testes com

```sh
odin test . -vet
```

Para ainda mais verificações, acrescenta a opção `-strict-style`.

## Desenvolvimento orientado por testes (TDD)

O `odin test` executa cada procedimento que tem o atributo `@(test)`.

No conjunto de testes, vais reparar que cada procedimento de teste tem este atributo.
Isto significa que, quando iniciares os testes, cada procedimento de teste vai ser executado.

O Exercism promove geralmente o [desenvolvimento orientado por testes][tdd], em que:

- inicialmente, todos os testes exceto o primeiro estão configurados para serem ignorados;
- escreves apenas o código suficiente para passar no primeiro teste;
- depois, ativas o teste seguinte e escreves apenas o código suficiente para que passe;
- repetes até o teu código passar em todos os testes.

Nós (os mantenedores) não encontrámos uma forma programática elegante de executar um subconjunto dos testes.
O ficheiro de teste tornou-se simplesmente demasiado difícil de gerir.
Para desenvolveres com TDD, podes editar o ficheiro de teste para simplesmente comentar os testes que ainda não estás pronto para executar e descomentá-los um a um à medida que escreves a tua solução.
