# Introdução

## Valores predefinidos dos parâmetros

É possível fornecer [valores predefinidos][default-parameter-values] para qualquer um dos parâmetros de uma função, atribuindo um valor ao parâmetro na lista de parâmetros, a seguir à anotação de tipo do parâmetro. Quando um valor predefinido é especificado, quem chama a função pode omitir esse parâmetro ao chamar a função, e o valor predefinido é usado em vez disso.

```swift
func greeting(name: String = "guest", duration: Int = 2) -> String {
  "Welcome, \(name). Enjoy your \(duration) night stay."
}

greeting(name: "Bobo", duration: 7)
// Returns "Welcome, Bobo. Enjoy your 7 night stay."
greeting(duration: 3)
// Returns "Welcome, guest. Enjoy your 3 night stay."
greeting(name: "Wynona")
// Returns "Welcome, Wynona. Enjoy your 2 night stay."
greeting()
// Returns "Welcome, guest. Enjoy your 2 night stay."
```

## Parâmetros variádicos

Os [_parâmetros variádicos_][variadic-parameters] em Swift permitem que se passem zero ou mais valores do mesmo tipo para um único parâmetro de uma função. Isto é indicado acrescentando `...` à anotação de tipo do parâmetro.

Estes valores são automaticamente agrupados num array cujos elementos são do mesmo tipo que o tipo do parâmetro variádico.

```swift
func geometricMean(_ numbers: Double...) -> Double {
  var total = 1.0
  for number in numbers {
      total *= number
  }
  return pow(total, 1.0 / Double(numbers.count))
}

geometricMean(1, 2, 3, 4, 5)
// => 2.605171084697352
```

Repara que, ao usar parâmetros variádicos, o Swift tem uma limitação.
Se uma função tiver parâmetros que, na definição, vêm depois do parâmetro variádico, é _obrigatório_ que o primeiro parâmetro a seguir ao parâmetro variádico tenha uma etiqueta de argumento.

## Parâmetros in-out

Dentro do corpo de uma função, os parâmetros são tratados como constantes, não como variáveis; tentar modificar o valor de um parâmetro dá origem a um erro de compilação.
Se uma função quiser modificar o valor de um parâmetro, tem de usar um [_parâmetro in-out_][in-out-parameters] para tornar essa mutabilidade explícita.

Para usar parâmetros in-out, quem programa tem de garantir três coisas:

1. A definição da função tem de marcar explicitamente os parâmetros in-out, escrevendo a palavra-chave `inout` entre o `:` e o nome do tipo na anotação de tipo do parâmetro.
2. O valor passado ao parâmetro in-out tem de ser declarado como uma variável, não como uma constante. Da mesma forma, não pode ser um literal.
3. O nome da variável tem de ser precedido de um `&` na chamada à função, marcando-o explicitamente como modificável.

Quando isto é feito, a função faz uma cópia interna do parâmetro in-out, modifica-a conforme indicado no corpo da função e, quando a função termina, copia o valor modificado de volta para a variável que foi passada.

```swift
func updateVersion(_ record: inout (version: Int, title: String)) {
  record.version += 1
}

var dbRecord = (version: 2, title: "Exercism")
updateVersion(&dbRecord)

// dbRecord is now (3, "Exercism")
```

~~~~exercism/warning
Há mais algumas regras a ter em conta em relação aos parâmetros in-out.

1  Dentro de uma função com parâmetros in-out, não podes fazer referência à variável que foi passada como parâmetro in-out.
2. A mesma variável não pode ser passada como vários parâmetros in-out na mesma função.
   Por exemplo, `inoutFunc(&mutVar, &mutVar)` dá origem a um erro do compilador.
~~~~

## Funções aninhadas

Em Swift, podes definir [funções dentro de outras funções][nested-functions].
A estas chama-se **funções aninhadas**.

As funções aninhadas são usadas habitualmente como auxiliares privados que desempenham tarefas específicas para a função que as contém, sem sobrecarregar o âmbito exterior:

```swift
func makeNumber(_ number: Int) -> Int {
    func double(_ x: Int) -> Int {
        x * 2
    }

    func increment(_ x: Int) -> Int {
        x + 1
    }

    return number.isMultiple(of: 2) ? increment(double(number)) : double(number)
}

print(makeNumber(3)) // Prints 6
print(makeNumber(4)) // Prints 9
```

As funções aninhadas comportam-se como funções normais, mas a sua visibilidade está restringida ao corpo da função que as contém.
