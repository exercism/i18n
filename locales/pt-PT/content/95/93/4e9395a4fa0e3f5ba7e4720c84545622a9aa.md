# Instruções

A direção está a começar a aplicar princípios darwinianos a um projeto de carro telecomandado.
Os programadores foram divididos em duas equipas, _Red_ e _Blue_, e têm como tarefa melhorar o design de forma independente uma da outra.
Não precisam de se preocupar com as decisões de design da outra equipa.
Pediu-se-te que dês uma vista de olhos ao código e vejas qual a melhor forma de combinar os esforços das duas equipas para efeitos de teste.

## 1. Encontra uma forma mais adequada de isolar o código das duas equipas

Usa módulos para expressar melhor a intenção do código.

Neste momento, tipos importantes como `Motor` e `Telemetry`, para não falar do próprio `RemoteControlCar`, têm como prefixo a cor da equipa correspondente, `<Color>RemoteControlCarTeam`.
O único propósito do prefixo é permitir que tipos com o mesmo nome coexistam no programa.
Isso expressa-se melhor com um módulo.
Vais ver que, para estes efeitos, um módulo tem vantagens em relação a colocar prefixos nos tipos.

## 2. Simplifica o sistema de nomes

A direção exige que as equipas se chamem "Red Remote Control Car Team" e "Blue Remote Control Car Team" nas definições, e que estes nomes longos sejam usados até no próprio código.
No entanto, os nomes são bastante pesados quando se faz referência às equipas.

Encontra uma forma de usar os identificadores mais curtos "Red" e "Blue" dentro do módulo no qual vais construir os carros.
