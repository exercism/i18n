# Dicas

## Geral

- `movapd` e `movaps` só devem ser usados quando se sabe que um operando de memória está alinhado.
  Podem ser usados em segurança quando ambos os operandos são registos `xmm`.
- Os endereços de memória são passados como valores inteiros.
  Os primeiros seis argumentos inteiros são passados a uma função em `rdi`, `rsi`, `rdx`, `rcx`, `r8` e `r9`, respetivamente.

## 1. Combina os rendimentos de duas linhas

- A adição empacotada para números de vírgula flutuante de 32 bits é `addps`.
- Os três argumentos de ponteiro estão garantidamente alinhados a 16 bytes, por isso a variante de movimentação alinhada, `movaps`, é a adequada.

## 2. Calcula o desvio escalado

- A subtração empacotada para números de vírgula flutuante de 64 bits é `subpd`.
- A multiplicação empacotada para números de vírgula flutuante de 64 bits é `mulpd`.
- `measured` está alinhado e `target` não, por isso precisam de variantes de carregamento diferentes.

## 3. Calibra um lote

- Tanto `reference` como `offset` estão alinhados, `raw` não, por isso precisam de variantes de carregamento diferentes.
- Tanto `reference` como `offset` são necessários para ambas as linhas.
- As instruções de dois operandos costumam sobrescrever o seu operando de destino.
- Para converter os 2 números de vírgula flutuante superiores de `raw` em números de vírgula flutuante de 64 bits, usa `cvtps2pd` com um operando de memória deslocado 8 bytes em relação ao ponteiro `raw`.
- O fator de conversão deve ser armazenado em memória como 2 números de vírgula flutuante de 64 bits (ambos iguais a `0.5`).
- O resultado ocupa 32 bytes (4 números de vírgula flutuante de 64 bits): os primeiros 16 bytes em `[result]`, os 16 seguintes em `[result + 16]`.

## 4. Normaliza as pontuações ao longo de uma linha

- As instruções de dois operandos costumam sobrescrever o seu operando de destino.
- A memória não pode ser o operando de destino das instruções aritméticas empacotadas.
- Para cada `score` de vírgula flutuante de 64 bits no array `scores` (primeiro argumento), existe um `gain` equivalente no array `gains` (segundo argumento).
  Cada `score` vai operar com o `gain` na mesma posição.
- O terceiro argumento é um `scale` fixo com 2 números de vírgula flutuante de 64 bits empacotados.
- Para cada par `score` e `gain`, a função calcula `score * gain / scale_lane`.
  A primeira lane em `scale` escala o primeiro elemento de cada par (lanes em posições pares), a segunda lane escala o segundo (lanes em posições ímpares).
- A pontuação normalizada é guardada diretamente no array `scores`, na mesma posição do `score` de entrada.
- O número de elementos em `scores` e `gains` é igual e corresponde ao valor de `n` (o quarto argumento).
- Deves usar um ciclo para processar todos os pares de elementos, avançando 16 bytes (2 elementos) em cada iteração.
