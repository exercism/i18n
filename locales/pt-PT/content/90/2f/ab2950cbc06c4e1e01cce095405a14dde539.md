# Contratos

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| Cláusula | Diz | Culpa de quem, se for violada |
| --- | --- | --- |
| `pre` | o que tem de se verificar à entrada | de quem chama |
| `post` | o que se verifica ao devolver | da rotina |

Ambos recebem um `BOOL`, e ambos podem usar os argumentos da rotina e os
atributos do objeto. O `post` também pode usar `result`, o valor que está a
ser devolvido.

## assert

Dentro do corpo de uma rotina, `assert` afirma algo que tem de ser verdadeiro
nesse ponto:

```sather
      assert load <= limit;
```

É verificado com a mesma opção que os outros.

## Invariantes de classe

Uma classe pode afirmar algo verdadeiro para todos os seus objetos entre
chamadas:

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

É verificado à entrada e à saída de todas as rotinas públicas, quando a
verificação está ativa.

## Como ativar

| Opção | Verifica |
| --- | --- |
| `-chk` | tudo: pre, post, assert, invariant, limites, aritmética |
| `-chk_no` | nada |

Repara que `-chk_pre` sozinho *não* ativa a verificação de pré-condições
neste compilador; o que funciona é `-chk`. Uma violação imprime a rotina e a
linha do código-fonte e para o programa. Não é uma exceção, e o `protect`
não a captura.

O habitual é desenvolver e testar com `-chk` e distribuir sem ela, para que
as verificações não custem nada no programa distribuído. Isso só compensa se
os testes exercitarem mesmo os caminhos.

## O que faz um bom contrato

Diz o que a rotina precisa, não como funciona:

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

Um `post` que repete o corpo não ensina nada a ninguém:

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## Herança

Um subtipo pode enfraquecer um `pre` e reforçar um `post`, aceitar mais e
prometer mais, mas nunca o contrário, senão o código escrito para o supertipo
deixaria de funcionar. É essa a regra que os contratos existem para tornar
verificável.
