# secção sobre comentários

O Go tem [ótimas diretrizes](https://golang.org/doc/effective_go.html) sobre como escrever comentários. Existe um formato padrão que podes usar nos comentários de documentação, e que a ferramenta `godoc` consegue depois transformar automaticamente em documentação elegante.

O comentário do pacote deve começar com a palavra `Package`, seguida do nome do pacote, assim:

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

Nas funções, métodos, constantes e variáveis de pacote exportados, o comentário deve começar pelo nome e continuar com uma expressão verbal:

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

A wiki [CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences) especifica ainda que os comentários de documentação devem ser frases completas, terminadas com um ponto final.

Para além de otimizar a legibilidade, seguir estas recomendações melhora o aspeto do teu código nas [ferramentas de documentação do Go](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/), como o [godoc.org](http://godoc.org), o `godoc` e o `go doc`.

Reserva um momento para ler a secção sobre comentários de documentação no guia de estilo oficial, o [Effective Go](https://golang.org/doc/effective_go.html), e perceberes o raciocínio por trás destas escolhas.
