# Apêndice às instruções

## Vantagens e desvantagens de `from_quote`

Este exercício define uma função `from_quote` no tipo `DateOfBirth`. Isso torna possível escrever código como este:

```roc
birthdate : DateOfBirth
birthdate = "2019-01-20"
```

Este código chama implicitamente `DateOfBirth.from_quote("2019-01-20")` em tempo de compilação. Isto pode acelerar o programa, uma vez que não é preciso fazer a análise sintática em tempo de execução, e garante que as datas rejeitadas por `from_quote` são detetadas em tempo de compilação, em vez de em tempo de execução. Além disso, torna o código agradável e legível. Por exemplo, aqui está um dos testes deste exercício:

```roc
# multiple birthdates with one shared birthday
expect {
	shared_birthday(["1966-07-29", "1977-02-12", "2001-07-29", "1980-11-10"])
}
```

No entanto, quem leia este código pode pensar que a função `shared_birthday` recebe uma `List(Str)`, quando na verdade recebe uma `List(DateOfBirth)`. Isto pode dar origem a confusão e a erros. Por este motivo, podes preferir o formato um pouco mais longo mas mais explícito: `"2019-01-20".DateOfBirth`, que também chama `from_quote` em tempo de compilação.

Nos teus próprios programas, podes preferir fornecer um construtor prático, como este:

```roc
DateOfBirth := { year : I64, month : U8, day : U8 }.{
    from_ymd : I64, U8, U8 -> Try(DateOfBirth, [InvalidMonth, InvalidDay])
    from_ymd = |year, month, day| ...
}
```

Também podes chamar este construtor em tempo de compilação, assim:

```roc
Ok(birthdate) = DateOfBirth.from_ymd(2019, 1, 20)
```

Nota: colocar esta definição ao nível de topo faz com que seja executada em tempo de compilação (uma vez que a função é pura e os parâmetros de entrada são conhecidos em tempo de compilação). Dentro de uma função, podes usar o mesmo construtor em tempo de execução.
