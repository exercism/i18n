# シェルの基礎入門

## シェル

_シェル_とは、コマンドを入力してオペレーティングシステムとやり取りするためのプログラムです。
シェルにはグラフィカルなものもあります。マウスやトラックパッドで操作するデスクトップ環境も、シェルの一種です。
ここではコマンドラインインターフェースに焦点を当てます。コマンドを入力すると、その結果が（たいていは）ターミナルに出力されます。

コマンドラインのシェルには、さまざまな種類があります。
Windowsには**cmd**と**powershell**があります。
MacやLinuxには「Unixシェル」があり、こちらも多くの種類があります。
Macのデフォルトシェルは**zsh**です。
**csh**はCに似た構文を持つ古いシェルです。
**bash**は、とくにLinuxでよく使われる人気のシェルのひとつです。

もっとも初期のシェルのひとつが、Bourneシェルの**sh**です。
やがてこのシェルは、Unix系のシステムすべてに用意されるよう[標準化][posix]されました。
多くのシェルがBourneシェルをベースにしており、対話的な機能やプログラミング機能を追加していることがよくあります。

**Bash**はBourneシェルをベースにしています。
だから「**B**ourne-**a**gain **sh**ell」と呼ばれるのです。
多くのLinuxシステムでデフォルトのシェルになっています。
Bashには、対話的なシェルとして快適に使えるようにしてくれる機能がたくさんあります。たとえば：

* 自由にカスタマイズできるプロンプト
* 履歴からコマンドを呼び出して編集する機能
* 実行中のプロセスを操作する機能
* 入力を減らせるエイリアス
* などなど

このトラックは、bashを対話的なシェルとして使う方法を扱うものではありません。
bashを使ってプログラムを書くことを学ぶためのものです。
問題を解くときは_ひたすら_bashを使うことに重点を置きます。とはいえ、外部のツールを呼び出すことに制限はありません。

## Bashの基礎：コマンドと引数

Bashは、入力（通常はターミナルかファイル）からコマンドを読み取ります。
読み取った入力の各行は、_コマンド_として扱われます。つまり、実行すべき指示です。
（複数行にまたがるコマンドなど、いくつか高度なケースがありますが、それについては後で説明します。）

Bashは各行を、空白文字（スペースとタブ）で区切られた**単語**に分割します。
行の最初の単語が、実行する_コマンド_の名前です。
残りの単語はすべて、そのコマンドへの_引数_になります（オプション、ファイル名など）。

~~~~exercism/note
以下の例では、実際に実行できる対話的なコマンドをいくつか紹介します。

* `#`は_コメント_の始まりです。
  コメントに続く単語はシェルには無視されます。コメントは読むためだけのものです。
* `$`はシェルのプロンプトを表します。
  コマンドをコピーするときは、プロンプトは含めないでください。
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm`は、与えられたファイルを削除するアプリケーションです。
`*`は[glob][glob]文字で、現在のディレクトリにあるすべてのファイルに一致する「ワイルドカード」パターンです。
globについては、また後で詳しく説明します。

`a`と`b`の間にはスペースがいくつかあり、`b`と`c`の間には1つしかないことに気づきましたか？
引数の間の空白の量は関係ありません！
たとえば：

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo`は、引数を標準出力（ここではターミナル）に出力するコマンドです。
Bashはこのコマンドを5つの単語に分割し、4つの引数で`echo`コマンドを呼び出します。
2つ目の例にある余分なスペースは何の違いも生みません。
`echo`は、もともと単語の間にどれだけスペースがあったのかを知りません。

余分な空白をそのまま保ちたければ、その文を1つの引数として渡す必要があります。
これは[クォート][Quotes]を使えばできます：

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

クォートは、その中にあるものをすべて_1つの引数_にまとめます。
この引数は、その特定のスペース文字を含めた`This    is    a    test.`です。
クォート自体は引数の一部ではないことに注意してください。bashは、その1つの引数を`echo`に渡す前にクォートを取り除きます。

引数は、コマンド名からも、互いからも、空白で区切られます。
これは覚えておくことが大切です。
たとえば、次の例は間違いです：

```bash
$ [-f file]
bash: [-f: command not found
```

これは`file`という名前のファイルが存在するかどうかを調べるつもりで書いたものです。
`[`と`]`のまわりの空白は関係ないと考えるのも無理はありませんが、`[`は実はコマンドであり、最後の引数が`]`であることを必要とします。
（`[`コマンドについては、後でもっと詳しく扱います。）
したがって、`[`と`-f`、`]`と`file`はそれぞれ区切らなければなりません。
そうしないと、bashは`[-f`という名前のコマンドを、`file]`という1つの引数で実行しようとしていると解釈します。
正しいコマンドは、すべての引数を空白で区切ります：

```bash
$ [ -f file ]
```

（この挙動に戸惑う人をよく見かけます。`[...]`は「単なる構文」でスペースは省けると思ってしまうのです。`[`はコマンドであり、空白は必要なのです。）

ファイル名に空白やその他の特殊文字が含まれる場合も、クォートする必要があります：

```bash
$ [ -f "my file" ]
```

## コマンドの種類

Bashはいくつかの異なる種類のコマンドを理解します。エイリアス、関数、組み込みコマンド、キーワード、実行ファイルです。
これらはすべて_コマンド_であり、どれもとてもよく似た振る舞いをします。

デフォルトでは、エイリアスは対話的なシェルでのみ有効で、シェルスクリプトでは無効です。
ここでは扱いません。

### 関数

関数はシェルのコマンドを含み、小さなスクリプトによく似た働きをします。引数を受け取ったり、ローカル変数を作ったりもできます。
関数を呼び出すと、その中のコマンドが実行されます。
関数については、後で詳しく扱います。

### 組み込みコマンド

Bashには、`cd`（ディレクトリの移動）、`echo`（出力の書き込み）など、基本的なコマンドが組み込まれています。
これらは、あらかじめ用意された関数のようなものだと考えることができます。

### キーワード

キーワードは組み込みコマンドに似ていますが、主な違いは、キーワードが実際にはbashの構文であり、特別な規則で解析される点です。
たとえば、`[`はbashの組み込みコマンドで、`[[`はbashのキーワードです。どちらもさまざまな条件を調べるために使われます。
ただし、`[[`キーワードにはいくつか追加の機能があります。
たとえば、正規表現のテストを行う`=~`演算子が使えます。

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

文字列比較演算子の`<`と`>`も、キーワードがコードを異なる方法で解析する例です。
`[[...]]`の中では、これらの演算子に特別な注意は必要ありません。

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

しかし`[...]`の中では、シェルがこれらをリダイレクト演算子として解析しないよう、クォートするかエスケープしなければなりません。

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### 実行ファイル

bashが実行できる最後の種類のコマンドは_実行ファイル_です。
これらは、コンピューターのファイルシステム上にある実行可能なファイル（プログラム）で、実行できます。
（実行ファイルは_外部コマンド_や_アプリケーション_と呼ばれることもあります。）
実行ファイルは、通常は名前だけを入力して呼び出します。ファイルへの完全なパスは、たいてい必要ありません。
これは、bashがあらかじめ定義された変数を使って一般的な実行ファイルの場所を見つけられるようにしているからです。
この変数を`PATH`と呼びます。
コロンで区切られたディレクトリ名の集まりです（例：`/usr/bin:/bin`）。
ファイルパスを付けずにコマンド（例：`myprogram`や`ls`）が指定され、それがエイリアス、関数、組み込みコマンド、キーワードのいずれでもない場合、bashは`PATH`にあるディレクトリを順に探します。
ディレクトリは左から右へ順に調べられ、指定された名前の実行ファイルが含まれているかどうかが確認されます。

実行ファイルが既知のパスの外にある場合は、その実行ファイルのファイルパスを指定する必要があります。
カレントディレクトリにある`myprogram`という実行ファイルなら`./myprogram`、`/opt/somedirectory`ディレクトリにあるなら`/opt/somedirectory/myprogram`を使います。

ヒント：`type`コマンドを使うと、そのコマンドの詳細を調べられます：

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## スクリプト

_スクリプト_とは、ファイルに保存された一連のコマンドです。
Bashはファイルを読み、コマンドを順番に処理します。
現在のコマンドが終わって初めて、次のコマンドに進みます。
例外は、コマンドが非同期（バックグラウンド）で実行するよう指定されている場合です。
このケースについては、まだあまり気にしないでください。仕組みは後で学びます。

このガイドに出てくるコマンドラインの例は、どれもスクリプトでも使えます。

スクリプトを作るのは簡単です。
まず新しいファイルを作り、最初の行にこれを書きます：

```bash
#!/bin/bash
```

この行は_インタプリター指示子_と呼ばれます（_ハッシュバン_や**_シバン_**とも呼ばれます）。
この行は、そのファイルがコマンドの実行ファイルとして使われるとき、`/bin/bash`をインタプリターとして使うことを指定します。
OSのカーネルが_非バイナリのファイル_を実行するとき、そのファイルの最初の行を読み取ります。
その行が`#!`で始まっていれば、カーネルはその行を使って、ファイルを引き渡す先のインタプリターを決めます。
（これ以外にも有効な方法があります。後述をご覧ください。）
`#!`はファイルの先頭そのものになければならず、その前にスペースや空行があってはいけません。
スクリプトのコマンドは、この行より下に別々の行として書きます。

ヒント：`#!/bin/bash`の代わりに、次のように書くこともできます

```bash
#!/usr/bin/env bash
```

`env`は、最初の引数で指定された名前の実行ファイル（この場合は「bash」）を`$PATH`から探します。
この手法の詳しい説明や、普通の`#!/bin/bash`との違いについては、[StackOverflowのこちらの質問][env bash]をご覧ください。

インターネット上で`/bin/sh`をインタプリターとして使っているスクリプトや例に、どうか惑わされないでください。
**`sh`は`bash`ではありません！**
Bash自体は「sh互換」のシェルで、ほとんどの`sh`スクリプトを実行でき、同じ構文の多くを引き継いでいます。
しかし、その逆は成り立ちません。bashの一部の機能は、`sh`では壊れたり予期しない動作を引き起こしたりします。
実際のところ、単一の`sh`シェルというものは存在しません。
POSIX-sh構文をサポートするシェルの実装は数多くあります。
OSによっては、`sh`を実行しても、実際にはbashやash、dash、あるいは別のシェルが動いていることがあります。

スクリプトファイルを作ったら、次のようにして実行できます：

```bash
$ bash myscript
```

この例では、_コマンド_`bash`を実行し、_引数_として渡したスクリプトを読むように指示しています。
この方法で実行すると、`#!`の行は単なる_コメント_になります。

別の方法として、スクリプトに実行権限を与えることもできます。
この方法なら、bashを手動で呼び出す代わりに、他の実行ファイルと同じようにスクリプトを実行できます：

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

この方法でコマンドを実行すると、オペレーティングシステム（OS）が`#!`の行を使って、スクリプトを実行するインタプリターを決めます。
