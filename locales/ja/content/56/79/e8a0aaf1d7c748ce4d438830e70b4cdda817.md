# インストール

このトラックでは、WebAssemblyのランタイムを提供するために、全体を通して[Node.js][web-nodejs]に依存しています。つまり、お使いのコンピューターでJavaScriptを実行するときは、すべて[Node.js][web-nodejs]を使うことを前提としています。

## トラックの要件

多くのマシンには[Node.js][web-nodejs]が最初からインストールされているか、以前に、あるいは依存関係としてインストールされている場合があります。そこで、何をするにしても、まずすでにインストールされているかどうかを確認しましょう。

1. _ターミナル_（`Terminal`、`cmd`、`Powershell`、`bash`、…）を開きます
1. `node -v`を実行します

[Node.js][web-nodejs]がインストールされていれば、バージョンが表示されます。このバージョンを書き留めておきましょう。[Node.js][web-nodejs]がインストールされて_いない_場合は、エラーが出力されます。たいていは、`'node' is not recognised`のような内容です。

## Node.js

### Node.jsがすでにインストールされている場合

[Node.jsのウェブサイト][web-nodejs]を開きます。すると、_2つ_のバージョンが表示されます（OSが判別された場合。判別されないときは、先にOSを選択してください）。`node -v`のバージョンがどちらかと一致していれば、問題ありません。一致しない場合は、Node.js LTSを使うことをおすすめします。アップグレードでシステムの何かが壊れるのが心配なら、すべて問題ないものとしてそのまま進めてもかまいません。ただし、予期しないことが起きたときにサポートを提供できない場合があります。

### Node.jsがインストールされていない場合

[Node.js][web-nodejs]をインストールする方法は、いくつかあります。

- [インストーラーまたはバイナリ][web-nodejs-download]を使う
- [パッケージマネージャー][web-nodejs-package]を使う

どちらの方法もWindows、macOS、Linuxに対応しています。どうすればよいかわからない場合は、インストーラーを使うのがいちばん簡単です。

- **LTS**バージョンを使うことをおすすめします。[Node.js][web-nodejs]のウェブサイトでも、_recommended_（ほとんどのユーザーにおすすめ）と表示されています。
- ウェブページやインストーラー中の手順に従って、[Node.js][web-nodejs]をインストールします。

## インストールのテスト

インストーラーでの作業が終わったあと、パッケージマネージャーでの作業が完了したあと、またはバイナリをコピーして手順どおりに進めたあとは、すべてうまくいったかどうかをテストしておくとよいでしょう。

1. _ターミナル_（`Terminal`、`cmd`、`Powershell`、`bash`、…）を開きます
1. `node -v`を実行します

表示されるバージョンは、ウェブサイトに載っているものと一致しているはずです。

**注意**: _新しく_ターミナルウィンドウを開くことが重要です。すでに開いているターミナルウィンドウは、インストールが完了したあとに更新されていない可能性があります。つまり、開いているターミナルは、新しいプログラムがインストールされたことを認識していないのです。

> _**ヘルプ**_: `'node' is not recognised`
>
> 公式のインストーラーを使った場合、`PATH`は自動的に設定されているはずです。ただし、シェルがグローバルにインストールされたモジュールを見つけられない場合や、Node.jsをソースからビルドした場合は、`npm`のバイナリを含めるように`PATH`を更新してください。
>
> macOSとLinuxでは、次の行を`~/.bash_profile`または`~/.zshrc`のどちらかに追加するとよいでしょう。
>
> ```shell
> export PATH=/usr/local/share/npm/bin:$PATH
> ```
>
> Windowsでは、スタートメニューを開いて"environment variables"を検索します。`PATH`の項目を編集し、ここに`npm`のバイナリへのパスを_追加_する必要があります。たいていは、`C:\Program Files\nodejs`にあります。`File Explorer`でこの場所を開くと、`node.exe`、`npm.bat`、`npx.bat`が見つかるはずです。
>
> 開いているターミナルをすべて閉じて、新しいターミナルを開きます。

## 演習の要件

お使いのOS用のExercism CLIをダウンロードするには、[こちらの手順][cli-walkthrough]に従ってください。

CLIのセットアップと設定が完了したら、最初の演習`hello-world`をダウンロードしましょう。

```shell
exercism download --exercise=hello-world --track=wasm
```

各演習では、テストを実行するためにいくつかのツールが必要です。それらは、各演習のディレクトリで次のコマンドを実行してインストールできます。

```shell
npm install
```

> _**ヘルプ**_: `'<package>' is missing / cannot be found`
>
> 演習を_アップグレード_したあとにこれが表示されたなら、npm 7へようこそ。`node_modules`と`package-lock.json`を削除して、コマンドをもう一度実行すると解決します。

ディスク容量が気になり、別のツールをインストールしてもよいなら、[pnpm](https://pnpm.io/)を見てみましょう。pnpmは、各パッケージの各バージョンがディスク上に1つしかインストールされないようにします。この場合は、`npm install`の代わりに`pnpm install`を実行すれば、すべて期待どおりに動くはずです。

> **でも、npmとは何で、なぜこれでうまくいくのでしょうか？**
>
> JavaScriptトラックを完了するのにこの情報は必要ありませんが、いま何が起きたのかをぜひ理解したいという方は、次の段落が参考になります。
>
> これは、`npm`がNode.jsに同梱されているパッケージマネージャーであり、Node.jsは上記の手順でインストールされているからです。`npm`コマンドは`package.json`ファイルを探します。このファイルは_各_演習フォルダーにあります。このファイルには上記の`"dependencies"`がリストされており、`npm`がそれらをダウンロードして`node_modules`フォルダーに配置します。
>
> `package.json`内のスクリプトは、ローカルの`node_modules`フォルダーにあるバイナリを使用します。テストの実行に使われるのはまさにこれらのスクリプトで、`exercise`の説明に記載されています。
