# はじめに

Gleamの`Iterator`は、すべての値が同じ型である、順序づけられた値の集まりという点で配列に似ています。配列との違いは、遅延評価であることです。つまり、すべての値を一度にメモリに保持するのではなく、必要になったときに値を計算します。

これは、非常に大きな、あるいは無限の長さのシーケンスを扱うときに役立ちます。すべてを一度に保持するだけのメモリの空きがない場合でも、そうしたシーケンスを扱えるようになるからです。

`gleam/iterator`モジュールは、`Iterator`型と、イテレーターを扱うための関数を定義しています。

配列向けの関数の多くは、イテレーターにも用意されています。たとえば`map`、`filter`、`take`などです。これらの関数はイテレーターを返すので、イテレーターが消費されるまで実際には何の処理も行いません。

```gleam
let iter = 
  [1, 2, 3, 4, 5, 6]
  |> iterator.from_list
  |> iterator.filter(fn(x) { x > 2 })
  |> iterator.take(2)

// No work has been done yet as the iterator has not been consumed

// Consume the iterator and collect the values into a list
iterator.to_list(iter)
// -> [3, 4]
```

`unfold`関数を使うと、繰り返し呼び出されてシーケンスの次の値を生成する関数から、イテレーターを作ることができます。

ここでは、`unfold`関数を使ってフィボナッチ数列を生成するイテレーターを作っています。

```gleam 
iterator.unfold(#(0, 1), fn(pair) {
  let x = pair.0 + pair.1
  iterator.Next(element: x, accumulator: #(pair.1, x))
})
|> iterator.take(6)
|> iterator.to_list
// -> [1, 2, 3, 5, 8, 13]
```

このシーケンスは無限なので、値を配列にまとめる前に、`take`関数を使って有限にしています。無限のイテレーターに対して`to_list`を呼び出すと、プログラムはメモリを使い果たしてクラッシュするまで動き続けます。
