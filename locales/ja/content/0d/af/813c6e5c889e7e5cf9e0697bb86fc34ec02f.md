# 例外

ルーチンによっては、答えを返せないものもあります。テーブルに載っていないプロパティを求められても、`count_of`が返せる数値はありません。ここで0を返すのは嘘をつくことになります。0は「そういうものは1つもない」という意味であって、「そんなものは存在しない」という意味ではないからです。

**例外**は、ルーチンが答えられないことを伝える手段です。

## 例外を投げる

`raise`はルーチンを中断し、呼び出した相手に値を渡します。

```sather
   count_of(props : FMAP{STR,INT}, prop : STR) : INT is
      if ~props.has_ind(prop) then
         raise "Unknown prop: " + prop;
      end;
      return props.get(prop);
   end;
```

`raise`より後の処理は実行されません。ルーチンは戻らないので、確認すべき答えはなく、答えがあったかのように呼び出し元が処理を続けることもできません。

投げられる値は、通常、何が問題だったかを伝える文字列です。

## 例外を捕まえる

`protect`は、例外が投げられることを想定しながら、あるコードを実行します。

```sather
   protect
      taken ::= count_of(props, prop);
      #OUT + "There are " + taken;
   when $STR then
      #OUT + "Cannot: " + exception.str;
   end;
```

何も投げられなければ、`protect`に続く部分が実行され、`when`の枝は飛ばされます。何かが投げられると、`protect`の部分の残りは中断され、代わりに一致する`when`が実行されます。

`when $STR then`は、投げられた文字列を捕まえます。`exception`は投げられた値で、枝の中から参照できます。

## そのまま通り抜ける

例外を捕まえないルーチンは、例外について何かをする必要はありません。例外は外へ向かって、すべての呼び出し元を通り抜けながら、何かが捕まえるまで伝わっていきます。

```sather
   take_one(props : FMAP{STR,INT}, prop : STR) : INT is
      -- If this raises, take_one raises too. Nothing here says so.
      have ::= count_of(props, prop);
      ...
   end;
```

これが例外の要点です。問題に気づくルーチンと、それをどう扱えばよいかを知っているルーチンは、たいてい同じルーチンではありません。その間にあるものはすべて、例外を無視できます。
