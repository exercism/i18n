# 概要

多くのオブジェクト指向言語では、親クラスを[サブクラス化][wiki-subclass]して振る舞いを拡張するのが一般的です。親からメソッドを継承しつつ、新しいメソッドも追加します。こうしてオブジェクトの階層ができあがります。

Juliaには_クラスがありません_。したがって、_サブクラスもありません_。では、既存の振る舞いをどのように継承し、拡張すればよいのでしょうか？

これまでの概念で、型の階層を作る方法を学びました。また、Juliaが引数の型に基づいてメソッドを選ぶために[多重ディスパッチ][concept-multiple-dispatch]をどのように使うかも学びました。

Juliaにはいくつかの非公式な[インターフェース][ref-interfaces]もあり、これを使うと自作の型を、標準の型にすでに定義されている振る舞いに組み込むことができます。

これはイテレーターインターフェースで説明するのが一番わかりやすいでしょう。

## [イテレーター][ref-iterators]

これまでのシラバスで、Juliaがコレクションの各要素を操作するいくつかの方法を見てきました。

- [ループ][concept-loops]：`for item in items...`のように書きます
- [ブロードキャスト][concept-vector-operations]：`[1, 2, 3] .- 0.5`
- [高階関数][concept-hof]：`map(√, [1, 4, 9])`
- [内包表記][concept-comprehensions]：`[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [ジェネレーター][concept-comprehensions]：`(x^2 for x in 1:1e6)`。これは遅延評価されます。

明らかに、Juliaは標準のコレクションを要素ごとにたどる方法を知っています。上の例ではベクトルと範囲、そのほかSetやDictなども同様です。

では、自作のコレクションにこの機能をどうやって追加すればよいのでしょうか。特に、ジェネレーターのように遅延評価で反復できるようにしたい場合はどうでしょう？

### 最小限の要件

反復できるシーケンスを作るには、（少なくとも）2つのものが必要です。

1. _最初の_要素を取得する方法。
2. 現在の状態から_次の_要素を取得する方法。

Juliaはこれらのタスクを、`Base.iterate()`関数のメソッドによって次の手順で実現します。

1. まず`Base.iterate(iter)`が自動的に呼び出されます。
    - 反復するものが何もなければ、`nothing`を返します。
    - そうでなければ、最初に返される要素と最初の状態の`Tuple`を返します：`(firstitem, firststate)`。
2. 前の反復で要素が返されていれば、`Base.iterate(iter, state)`が自動的に呼び出され、`firststate`を`state`引数として受け取ります。
    - 反復が終了するなら、`nothing`を返します。
    - そうでなければ、次の要素と次の状態の`Tuple`を返します：`(nextitem, nextstate)`。
3. 終了するまで手順2を繰り返します。

これらの手順はすべて「舞台裏」で行われます。つまり、メソッドの呼び出しと状態は反復プロトコルによって内部的に管理され（状態は中身が見えないまま）、ループのような高水準の構文には要素だけが公開されます。
言い換えれば、私たちが見るのは`item`だけで、それ以外はすべてブラックボックスの中にあります。

これを支える中心にあるのが[多重ディスパッチ][concept-multiple-dispatch]です。
`iter`の型がどのメソッドが呼ばれるかを決め、引数の数が最初の要素を返すか次の要素を返すかを決めます。

標準の型に対するメソッドはすでに定義されています：`Vector`、`Range`、`Set`など（[現在][ref-iterations-collections]全部で14の型）。

自作の`MyType`に同じ振る舞いを共有させるには、まず次のものを定義する必要があります。
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

抽象的に聞くと、これらはすべて難しく感じられるかもしれませんが、実際にはとても簡単です。
例として、与えられた整数`n`の累乗を、最大の個数まで生成する型がほしいとしましょう。

まず、自作の型を定義します。

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

これでこの型の`iterate`メソッドを定義できますが、最初の要素と最初の状態とは何でしょうか？

最初の要素を取得するために、複雑な準備が必要なイテレーターもあります。しかし、このおもちゃの例では、最初に返される要素は単に底そのものだとわかるので、`count`の値が1以上かどうかを確認するだけで済みます。

次に、最初の状態を考えます。これは次の反復で使われる情報を持っています。
そのためにどんな情報を追跡する必要があるかは自分で決められ、どのような型でもかまいません。

この場合は、`n`を累乗する「インデックス」を追跡するだけでもかまいませんし、より性能のよい方法として、`n`の直前の累乗（つまり返された要素）と、シーケンス内の次の「インデックス」を使うこともできます。
この2つの数値を`Tuple`にまとめて`state`として返します。

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

この例では、最初の要素（`p.n`）がループに返され、最初の状態`(p.n, 2)`が`iterate(P::Powers, state)`メソッドに渡されます。
そこで状態を処理し、現在の要素に底を掛けることで次の要素を生成し、累乗を`1`だけ増やします。

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

`index`の値がまだ`count`の範囲内であれば、`next`の要素と、インクリメントされた`(next, index + 1)`状態が`Tuple`として返されます。
`index`の値が`count`を超えると、代わりに`nothing`が返され、反復が終了したことを示します。

お気づきかもしれませんが、`iterate(p::Powers)`と`iterate(p::Powers, state)`のメソッドは、関数の中身がかなり似ています。
実は、うまくやれば、この類似性を利用して、状態にデフォルト引数を持つ2引数のバージョンだけを使う、すっきりした実装にできます：`Base.iterate(p::Powers, state=(1, 1))`
これなら、別に用意していた1引数の`iterate(p::Powers)`は不要になります。
可能なときは、実際によくこうします。

~~~~exercism/advanced
[関数][concept-functions]の概念で省略可能な引数を紹介したとき、実装については何も触れませんでした。

その後、多重ディスパッチを学んだので、Juliaが_省略可能な引数を持つ_関数を、自動的に_省略可能な引数を持たない_複数のメソッドへ変換することを知っておくと、より納得できるでしょう。

`Base.iterate(P::Powers, state=(1, 1))`を定義することは、`Base.iterate(P::Powers, state)`と`Base.iterate(P::Powers)`の両方を別々に定義することとまったく同じです。

[concept-functions]: https://exercism.org/tracks/julia/concepts/functions
~~~~

ここまでで、すでにいくつか便利な機能があります。3の最初の4つの累乗について、結果をループでたどり、ある数値が結果に含まれているか確認し、`sum()`のような集約関数を適用できます。

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 追加のメソッド

よいスタートですが、まだすべてが動くわけではありません。

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

案の定、`length(Powers(3, 4))`もまったく同じエラーメッセージを出します。

これは簡単に直せます。長さは型のコンストラクターの一部で、この場合は4です。
この型に対して`Base.length()`を定義するだけで、そのシーケンスに内包表記や`collect()`を使えるようになります。

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

効率のために、`Base.eltype()`も定義するのが最善です。これは結果の要素の型です。
これにより、`collect()`のような関数が、`Vector{Any}`に何度も`push!()`する代わりに、出力用の`Vector{Int}`の領域をあらかじめ確保できるようになります。

これまで見たことのないかもしれない構文に注目してください。このメソッドは型の_インスタンス_ではなく、_型そのもの_に対して定義されています。

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

イテレーターは有限の長さを_持たなければならない_わけではありません。
「無限」シーケンスの用途はもっと限られますが、ループから`break`で抜け出す方法があるかぎり、それをループでたどるのは役に立つことがあります。
たとえば、ある上限（整数のオーバーフローを避けるなら`typemax(Int)`など）より小さい値を生成する`Powers`の変種を定義できます。

## そのほかのインターフェース

### [インデックス付け][ref-indexing]

イテレーターインターフェースを使えば、いくつかの簡単なメソッドを定義するだけで、任意の自作の型をシーケンスのように振る舞わせることができます。

さらに、そのシーケンスにインデックスでアクセスできるようにしたいとしましょう。

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

この振る舞いを追加できます。その方法は[マニュアル][ref-indexing]で説明されています。

最低限、`getindex()`を定義する必要があります。

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

さらに、次のものも定義する必要があります。

- `P[begin]`と`P[end]`をサポートするための`firstindex()`と`lastindex()`。
- ベクトルや範囲によるインデックス付けをサポートするための`getindex()`の変種。
- 理論上は`setindex!()`ですが、この例でそれが何を意味するのかはなかなか想像できません。

しかし、ここまで来ると、イテレーターをベクトルに似せるためだけにかなりの作業をしていることになります。

### [AbstractArray][ref-abstractarray]

よりよい出発点を与えてくれる別のインターフェースを検討する価値があるかもしれません。

この場合は、`Powers`を[`AbstractArray`][ref-abstractarray]のサブタイプにすることを検討できます。そうすると、配列らしい振る舞いを多くただで手に入れられます。

`Powers`シーケンスに対応する配列は、1次元の整数の配列です。
`AbstractArray{Int, 1}`と書かれているのをときどき見かけますが、新しいJuliaのコードでは1次元用の`AbstractVector{Int}`、2次元用の`AbstractMatrix{Int}`という別名のほうがよく使われます。

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

`length()`ではなく、各次元に沿った長さのタプルを返す`size()`を定義する必要があります。この場合は1次元だけです。

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

では、要素にどのようにインデックスを付けたいでしょうか？
[多次元配列の概念][concept-multi-dimensional-arrays]で、2つの主な方法を紹介しました。

- 次元ごとに1つのインデックスを使う方法。行列`M`なら`M[row, col]`です。
- メモリ上の要素の並びに対応する、単一のインデックスを使う方法。

これらはそれぞれ`Cartesian`と`Linear`と呼ばれます。

この例では1次元だけなので、線形インデックスが適切です。

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

この場合、`iterate()`は定義していないことに注意してください。
Juliaが、`getindex()`の定義に基づいて、デフォルトの実装を自動的に提供してくれます。

独自の`iterate()`を定義することもまだ可能で、場合によってはそのほうが効率的なこともあります。

より高次元の反復をしたい場合、`AbstractArray`インターフェースの使用は特に価値があります。
このおもちゃの例を壊れるまで引き伸ばすリスクを承知で言えば、これは`1:n`の数値の最初の`m`個の累乗を意味し、サイズ`(m, n)`の配列を反復的に定義することになります。

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [丸め][ref-rounding]

これまでの概念で、数値型に対するさまざまな丸めについて触れてきました。

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

[`round()`][ref-round]関数はこれよりも柔軟で、[`RoundingMode`][ref-roundingmode]（現在サポートされている7つのうちの1つ）、出力の小数点以下の桁数、基数を指定できます。

同じ関数で自作の型も扱えるようにしたいことがあります。よくあるのは座標のような複合型です。

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

当然のことながら、`Rounding`インターフェースがあり、最低限、自分の型に対して`round()`を定義する必要があります。

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

定義に`RoundingMode`を含めているので、`floor()`と`ceil()`は自動的に動きます。

もちろん、もっと複雑な丸めを自由に定義できます。

- `Point3D`を、原点から同じ方向のまま整数距離に丸めたいかもしれません。
- 角度では、天気予報士が使う16方位（_「南南西の風15ノット」_）に丸めたいかもしれません。これはπ/8ラジアンの倍数を意味します。
- `digits`、`sigdigits`、`base`を指定できるようにしたいかもしれません。
- 期間には[特別なオプション][ref-round-periods]があります

## まとめ

インターフェースの説明はかなりやっかいです。Juliaのアプローチがほとんどの他の言語と大きく異なるからです。
特に、実装の中でインターフェースの名前が一度も出てこないこともあります。[サブクラス化][wiki-subclass]や[ミックスイン][wiki-mixins]とは大違いです。

しかし、実際には驚くほど簡単です。

1. 適切な型を定義し、サブタイピングが役に立つかどうかを決めます。
2. （[ドキュメント][ref-interfaces]から）どのメソッドが必要かを調べます。
3. それらのメソッドを自作の型に対して実装します。ふつうはほんのいくつかのメソッドで、ごく短く簡単です。
4. あとは[多重ディスパッチ][concept-multiple-dispatch]が自動的に引き受けてくれます。
