# 概要

FactorのI/Oは、単一の[プロトコル][stream-protocol]の上に成り立っています。このプロトコルは、どんなデータソースやデータの出力先でも実装できます。同梱されているストリーム、つまり`<file-reader>`、`<file-writer>`、`<string-reader>`、`<string-writer>`、ネットワークソケット、バイト配列、ttyはどれもクラスで、[`io`][io]にある同じいくつかのジェネリックを実装し、[`destructors`][destructors]の`disposable`を継承しています。

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe`は低レベルの一括読み取りです。呼び出し側が用意したバッファーを埋め、何個の要素が書き込まれたかを返します。公開されている`stream-read`と`stream-read-partial`は、これを土台にしていて、メモリの確保を処理します。ユーザーが定義するストリームの多くは、`stream-read1`（読み取りが1要素ずつ行われる場合）か`stream-read-unsafe`（読み取りを一括で行える場合）のどちらかを実装します。

`stream-element-type`は、2つのシングルトントークンのうちの一方を返します。バイトストリーム（ファイルリーダー、ソケット）なら`+byte+`、文字ストリーム（文字列リーダー、tty）なら`+character+`です。ラッパーストリームは通常、その下にあるストリームにそのまま処理を委譲するだけです。

## ミックスインに加える

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

クラスは、どちらか一方にも、両方にもなれます。ミックスインに加えると、`input-stream`/`output-stream`のデフォルトメソッドが自分のクラスにディスパッチされるようになります。これは、`sets`ボキャブラリの`set`と同じオープンミックスインのパターンです。

## disposableのフレームワーク

`new-disposable ( class -- disposable )`は、新しいインスタンスを現在のデストラクタースコープに登録します。こうすることで、リソースの準備の途中で例外が起きてもきれいに巻き戻ります。

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose`は公開されているワードです。`dispose*`はクラスが実装するジェネリックです。サブクラスで`dispose*`をオーバーライドするときは、自分自身の状態を片付けてから、自分が持っているリソースを破棄します。

```factor
M: my-stream dispose* underlying>> dispose ;
```

フレームワークは、`dispose*`が1つのオブジェクトにつき多くても1回しか実行されないことを保証しています。`dispose`を何度呼んでも何も起こりません。

## スコープ付きアクセサ

3つのコンビネータが、`print`や`read1`などで使われるグローバルな「現在の入力ストリーム/出力ストリーム」を設定します。

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

それぞれが、終了時にリソースを破棄します。クォートが例外を投げた場合でもそうです。ほとんどのコードは、呼び出しのたびにストリームを引き回すのではなく、この方法でカスタムストリームを使います。
