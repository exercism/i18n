# 説明

この演習では、`x86-64`アセンブリ言語にヒントを得た小さな言語の構文と実行モデルを定義します。

目標は、制約された環境の中でコードがどのように書かれ、解析され、実行されるかを定式化することです。

## 実行モデル

アセンブリのコードは、特別な構文の中に書きます。

```lean
let program := assemble!(
    -- assembly code here
)
```

この構文は、アセンブリのコードを実行して値を返す関数を模した**プログラム**を生成しなければなりません。
このプログラムは、次の構文で呼び出します。ここで`a`、`b`、`c`などは引数です。

```lean
let result := program(a, b, c, ...)
```

引数と戻り値はすべて_64ビットの符号付き整数_です。
引数は最大_6個_までです。

## レジスタ

戻り値とすべての引数は**レジスタ**で渡されます。
この言語では、次のレジスタを扱えるようにします。

| レジスタ | 役割         |
|----------|--------------|
| `rdi`    | 1番目の引数  |
| `rsi`    | 2番目の引数  |
| `rdx`    | 3番目の引数  |
| `rcx`    | 4番目の引数  |
| `r8`     | 5番目の引数  |
| `r9`     | 6番目の引数  |
| `rax`    | 戻り値       |

レジスタの初期値は`0`です。ただし、関数に引数を渡すために使われる場合は除きます。

たとえば次のプログラムでは、`rdi`が`10`、`rsi`が`-20`で初期化され、それ以外のレジスタはすべて`0`です。

```lean
program(10, -20)
```

プログラムの戻り値は常に`rax`に格納されます。

~~~~exercism/note
レジスタ名は_大文字と小文字を区別しません_。
つまり、`rax`、`RAX`、`rAx`はすべて同じレジスタを指します。
~~~~

## アセンブリのコード

アセンブリのコードの各行は、次の2つの形式のいずれかです。

- **ラベル**は、一部の命令が使うプログラム内の特定の位置を示します。
- **命令**は、プログラムが実行する操作を表します。

何らかの命令で変更されない限り、プログラムの実行の流れは上から順に進みます。
つまり、ある行の実行が完全に終わってから、その次の行が実行されます。

### ラベル

ラベルは次の構文で書きます。

```lean
<label>:
```

ラベルはどのレジスタの値も変えません。命令から使えるようにコード内の特定の位置を示す以外に、プログラムに影響を与えることはありません。

~~~~exercism/note
ラベルは_大文字と小文字を区別します_。
つまり、`Start`、`start`、`sTart`はすべて異なるラベルです。
~~~~

### 2オペランド命令

ほとんどの命令は次の構文で書きます。

```lean
<opcode> <destination>, <source>
```

`opcode`は実行する操作を表し、`destination`と`source`のオペランドの値を使います。
操作の結果は`destination`オペランドに格納されます。

たとえば`add`命令は、`destination`と`source`のオペランドの値を足し、その結果を`destination`オペランドに格納します。

`destination`オペランドは_常に_レジスタですが、`source`オペランドはレジスタまたはリテラルの数値です。

プログラムが扱えるようにする命令は次のとおりです。

| オペコード | 実行される操作                        |
|------------|---------------------------------------|
| `mov`  | destination := source                 |
| `add`  | destination := destination + source   |
| `sub`  | destination := destination - source   |
| `mul`  | destination := destination * source   |
| `div`  | destination := destination / source   |
| `xor`  | destination := destination ^^^ source |
| `and`  | destination := destination &&& source |
| `or`   | destination := destination \|\|\| source |
| `shl`  | destination := destination <<< source |
| `shr`  | destination := destination >>> source |

これらに加えて、2オペランドの`cmp`命令も扱えるようにします。

この命令はどのレジスタも変更しません。代わりに`destination`と`source`のオペランドを比較し、プログラムの内部状態を次の3つのいずれかに設定します。

- `destination` > `source`のとき、_より大きい_
- `destination` == `source`のとき、_等しい_
- `destination` < `source`のとき、_より小さい_

この状態を内部的にどう保持するかは自由です。

### 1オペランド命令

プログラムの流れを変え、実行をコードの別の位置に移す命令があります。
これらは_ジャンプ_命令と呼ばれます。

いずれもオペランドを1つだけ取ります。これはジャンプ先、つまり実行を続けるコード上の位置を示すラベルです。

```lean
<opcode> <label>
```

`jmp`命令は_常に_、対象のラベルへジャンプします。

その他のジャンプ命令は、プログラムの内部状態が特定の値に設定されているときだけジャンプします。
そのため、通常は`cmp`命令の後に続きます。

プログラムが扱えるようにするジャンプ命令は次のとおりです。

| 命令        | 実行される操作                                     |
|-------------|----------------------------------------------------|
| `jmp`       | 無条件ジャンプ。常にジャンプします                  |
| `je`        | 内部状態が_等しい_ときにジャンプします              |
| `jl`        | 内部状態が_より小さい_ときにジャンプします          |
| `jg`        | 内部状態が_より大きい_ときにジャンプします          |

~~~~exercism/note
命令のオペコードは、2オペランドでも1オペランドでも、_大文字と小文字を区別しません_。
つまり、`add`、`ADD`、`aDd`はすべて同じ命令を指します。
~~~~
