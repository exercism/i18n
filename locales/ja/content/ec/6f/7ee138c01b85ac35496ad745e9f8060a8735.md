# ジェネレーター

Clojureトラックでは、[テストジェネレーター](https://exercism.org/docs/building/tooling/test-generators)を使ってプラクティス演習のテストを自動生成しています。
これは、[problem-specificationsリポジトリ](https://github.com/exercism/problem-specifications/)で定義されているほとんどの演習に`canonical-data.json`ファイルが付属していることを利用しています。このファイルには、演習を実装するために使える標準化されたテストの入力と出力が含まれています。

## 手順

プラクティス演習のテストを生成するために、テストジェネレーターは次の処理を行います。

1. 演習の`canonical-data.json`ファイルからテストケースを読み込む
2. `tests.toml`ファイルを使って、除外されたテストケースを省略する
3. テストケースを変換する（任意）
4. 演習のジェネレーターテンプレートを使ってテストケースをレンダリングする
5. レンダリングされたテンプレートを[cljfmt](https://github.com/weavejester/cljfmt)でフォーマットする
6. フォーマットされたテンプレートを演習のテストファイルに書き込む

### ステップ1：`canonical-data.json`ファイルを読み込む

テストジェネレーターは、[clojure/data.jsonライブラリ](https://github.com/clojure/data.json)を使って、演習の`canonical-data.json`からテストケースを解析します。

カノニカルデータには入れ子になっているものもあるため、解析されたテストケースには、親要素の`description`プロパティと、そのテストケース自身の`description`プロパティを含む`path`フィールドが追加されます。

注：キーはキーワードとして解析されます。

### ステップ2：`tests.toml`ファイルから除外されたテストを省略する

各演習には`tests.toml`ファイルがあり、個々のテストを除外したり無効にしたりできます。
テストジェネレーターは、除外済み（`include = false`）とマークされたテストケースを削除します。

### ステップ3：テストケースを変換する（任意）

演習によっては、データをレンダリングする前に少し調整が必要な場合があります。
たとえば、説明をより簡潔にしたい場合があります。

テストケースを調整するには、`<slug>-generator`名前空間を持つ`.meta/generator.clj`ファイルを定義します。
テストケースを変換する方法は2つあります。

- テストケースを更新する
- テストケースを追加・削除する

#### テストケースを更新する

個々のテストケースを更新するには、次の関数を定義します。

```clojure
(defn update-test-case
  "Update a test case"
  [test-case]
  ;; function body
)
```

##### 例

次の例では、`:path`の値の最後の要素だけを残して他をすべて削除します（説明を短くしています）。

```clojure
(ns difference-of-squares-generator)

(defn update-test-case [test-case]
  (update test-case :path #(take-last 1 %)))
```

#### テストケースを追加・削除する

テストケースを追加または削除するには、次の関数を定義します。

```clojure
(defn add-remove-test-cases
  "Add/remove test case(s)"
  [test-cases]
  ;; function body
)
```

```exercism/note
_両方_の関数を定義した場合、`add-remove-test-cases`が先に呼ばれ、`update-test-case`が次に呼ばれます。
```

### ステップ4：テストケースをレンダリングする

（変換された可能性のある）テストケースは、`.meta/generator.tpl`ファイルに渡されます。このファイルは、それらのテストケースに基づいてテストをどのようにレンダリングするかを定義します。

### ステップ5：レンダリングされたテンプレートをcljfmtでフォーマットする

次に、レンダリングされたテンプレートが[cljfmt](https://github.com/weavejester/cljfmt)でフォーマットされます。
これには次のようなメリットがあります。

- 演習のフォーマットが統一される
- テンプレートを書くときに、空白や位置揃えをあまり気にする必要がない

### ステップ6：レンダリングされたテンプレートを演習のテストファイルに書き込む

最後に、レンダリングされたテンプレートの出力が演習のテストファイルに書き込まれます。

## テンプレート

テンプレートは[hbsライブラリ](https://github.com/sunng87/hbs)を使ってレンダリングされます。このライブラリはhandlebars構文をサポートしています（[handlebars.java](https://github.com/jknack/handlebars.java/)を使用）。

## コマンドラインインターフェース

テストジェネレーターの実行方法は2つあります。

1. `bin/generate-tests`：ジェネレーターテンプレートを持つすべての演習のテストを生成する
2. `bin/generate-tests <slug>`：指定した演習がジェネレーターテンプレートを持つ場合、その演習のテストを生成する
