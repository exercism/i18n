# 概要

[Single instruction, multiple data (SIMD)][SIMD]は、ハードウェアレベルでの並列処理の一種です。同じ計算を、CPUが複数の要素に対して同時に実行します。

たとえば、32ビットの浮動小数点数4つからなる配列を2つ、要素ごとに足し合わせることを考えてみましょう。スカラー実装では、要素ごとに`addss`命令を4つ別々に発行します。SIMD実装では、`addps`を1つ使って4つの加算をまとめて並列に行います。つまり、1命令あたり4倍の仕事をこなせるわけです。

x86-64アセンブリでは、SIMD命令は通常`xmm`レジスタを使って実行されます。そうした命令のうち、整数を扱うものもあれば、浮動小数点数を扱うものもあります。

そうした整数や浮動小数点数は、**パック**されていると呼ばれます。それぞれは、同じレジスタ内の**レーン**と呼ばれる区画を占めます。SIMD命令は通常、2つのソースオペランドの同じレーン位置にある値を並列に処理します。各演算の結果は、デスティネーションオペランドの同じ位置のレーンに格納されます。

レーンは固定的な限界ではありません。命令ごとに、バイトの並びに与えられる解釈にすぎません。128ビットのオペランドには16バイトが入っています。命令によって、それらのバイトは16個の_1バイト_レーン、8個の_2バイト_レーン、4個の_4バイト_レーン、2個の_8バイト_レーン、あるいは1個の_16バイト_レーンとして解釈できます。

たとえば、`addps`命令は、パックされた単精度（4バイト）の浮動小数点数を加算します。この命令では、オペランド内の4バイトのかたまり1つ1つが別々のレーンになります。128ビット幅（16バイト）のオペランドでは、次のようになります。

| オペランド  | 4番目のレーン | 3番目のレーン | 2番目のレーン | 1番目のレーン |
|:-----------:|:--------:|:--------:|:--------:|:--------:|
| ソース1     |  1.5     |  2.1     | 6.2      | 3.4      |
|    +        |  +       |  +       | +        | +        |
| ソース2     |  0.5     |  8.26    | -13.4    | 22.9     |
|    =        |  =       |  =       | =        | =        |
| 結果        |  2.0     |  10.36   | -7.2     | 26.3     |

一方、`mulpd`の場合、128ビットのオペランドは2つのレーンを持つものとして解釈されます。この命令は、倍精度（8バイト）の値に対してパック乗算を行うからです。

| オペランド  | 2番目のレーン | 1番目のレーン |
|:-----------:|:--------:|:--------:|
| ソース1     |  4.2     |  2.1     |
|    *        |  *       |  *       |
| ソース2     |  1.0     |  92.4    |
|    =        |  =       |  =       |
| 結果        |  4.2     |  194.04  |

この概念では、SIMD命令の中からごく一部を取り上げます。それらは`xmm`レジスタを使って、パックされた浮動小数点数の値を操作します。

## 浮動小数点のSIMD命令

おおよその目安として、浮動小数点数を扱うSIMD命令は2オペランド形式をとります。その名前は、次のような構造に従っています。

1. 実行される演算。SIMDではない（_スカラー_とも呼ばれる）対応命令と同じ名前です（例：`add`、`mul`など）。
2. その命令が_パック_されたデータを扱うことを示す接尾辞`p`。_スカラー_データを表す`s`が以前置かれていたのと同じ位置に付きます。
3. 各レーンのサイズを示す接尾辞。SIMDではない対応命令と同じ意味を持ちます（`s`は単精度、`d`は倍精度）。

したがって、パック版の名前は、スカラー版の名前のニーモニック中央にある`s`（スカラー）を`p`（パック）に置き換えることで得られます。演算名とサイズの接尾辞は変わりません。

| スカラー | パック  | 意味                                |
|---------|---------|----------------------------------------|
| `addss` | `addps` | 加算、単精度（32ビットのレーン）   |
| `addsd` | `addpd` | 加算、倍精度（64ビットのレーン）   |
| `mulss` | `mulps` | 乗算、単精度             |
| `mulsd` | `mulpd` | 乗算、倍精度             |

### 算術演算

算術のSIMD命令も、上記の規則に従います。いくつか例を示します。

```x86asm
addps xmm0, xmm1 ; xmm0 = xmm0 + xmm1 (each 32-bit float at the same position)
subpd xmm2, xmm3 ; xmm2 = xmm2 - xmm3 (each 64-bit float at the same position)
mulps xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (each 32-bit float at the same position)
divpd xmm6, xmm7 ; xmm6 = xmm6 / xmm7 (each 64-bit float at the same position)
```

### 精度間の変換

パックされた単精度の浮動小数点数と、パックされた倍精度の浮動小数点数とを相互に変換するSIMD命令もあります。これらも同じ命名規則に従い、_スカラー_を表す`s`が_パック_を表す`p`に置き換わります。

| スカラー    | パック      | 意味                                      |
|------------|------------|----------------------------------------------|
| `cvtss2sd` | `cvtps2pd` | 単精度を倍精度に変換 |
| `cvtsd2ss` | `cvtpd2ps` | 倍精度を単精度に変換 |

これらの命令は、レーンは固定的な限界ではなく解釈である、という先ほどの話をよく示しています。ソースオペランドとデスティネーションオペランドではレーンのサイズが異なるため、レーンの個数も異なります。

`cvtps2pd`では、ソース（`ps`）は4つの単精度レーンを持ちます。デスティネーション（`pd`）は2つの倍精度レーンを持ちます。読み取られるのは、ソースの下位2つのレーンだけです。上位2つは無視されます。

| オペランド              | 4番目のレーン | 3番目のレーン | 2番目のレーン | 1番目のレーン |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| `ps`としてのソース       | 無視  | 無視  | 2.5      | 1.5      |
| `pd`としてのデスティネーション  |          |          | 2.5      | 1.5      |

`cvtpd2ps`では、ソース（`pd`）は2つの倍精度レーンを持ちます。デスティネーション（`ps`）は4つの単精度レーンを持ちます。ソースの2つのレーンはどちらも変換され、デスティネーションの下位2つのレーンに書き込まれます。デスティネーションの上位2つのレーンには0が設定されます。

| オペランド              | 4番目のレーン | 3番目のレーン | 2番目のレーン | 1番目のレーン |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| `pd`としてのソース       |          |          | 4.0      | 3.0      |
| `ps`としてのデスティネーション  | 0        | 0        | 4.0      | 3.0      |

いくつか例を示します。

```x86asm
cvtps2pd xmm0, xmm1 ; xmm0 = xmm1 as 2 doubles (low 2 lanes of xmm1 are read)
cvtpd2ps xmm0, xmm1 ; xmm0 = xmm1 as 2 floats (in low 2 lanes; upper 2 zeroed)
```

### メモリオペランド

ここまでに示したSIMD命令は、いずれもレジスタ間オペランドを使っていました。ソースとしてメモリオペランドを取ることもできます（ただし、デスティネーションに取ることは**できません**）。

メモリから読み取られるバイト数は、命令によって決まります。たとえば`addps`は16バイト（単精度の浮動小数点数4つ）を読み取ります。これに対して`cvtps2pd`が読み取るのは8バイト（単精度の浮動小数点数2つ）だけです。必要な入力がそれだけだからです。

```x86asm
addps    xmm0, [rsi]      ; xmm0 = xmm0 + 4 floats at [rsi]
mulpd    xmm1, [rsi + 16] ; xmm1 = xmm1 * 2 doubles at [rsi + 16]
cvtps2pd xmm2, [rsi + 8]  ; xmm2 = (2 floats at [rsi + 8]) converted to 2 doubles
```

メモリオペランドが16バイト幅の場合、その位置は_16バイトに整列_していなければなりません。整列されたメモリ位置とは、アドレスが演算のサイズ（この場合は16バイト）の倍数になっている場所のことです。

整列されたメモリを宣言するには、.dataセクションと.rodataセクションでは`align`ディレクティブを、.bssセクションでは`alignb`を使います。

```x86asm
section .rodata
align 16
mem1: dd 4.0, 3.5, 2.0, -1.0

section .data
align 16
mem2: dq 6.0, 2.1

section .bss
alignb 16
mem3: resb 16

section .text
fn:
    movaps xmm0, oword [rel mem1] ; loads 4 packed 32-bit floats in xmm0
    movapd xmm1, oword [rel mem2] ; loads 2 packed 64-bit floats in xmm1
    movaps oword [rel mem3], xmm0 ; stores 4 packed 32-bit floats in mem3
    ret
```

16バイトより小さいメモリオペランド、たとえば`cvtps2pd`の8バイトのソースには、整列の要件はありません。

### 値のロードとストア

パックされた浮動小数点数の128ビットをコピーする命令が4つあります。これらは2つの`xmm`レジスタ間、または1つの`xmm`レジスタとメモリ位置の間で動作します。

| 命令 | 説明                                                                       |
|-------------|-----------------------------------------------------------------------------------|
| `movaps`    | _整列された_メモリ位置との間で、パックされた単精度データをコピーします     |
| `movups`    | _整列されていない_メモリ位置との間で、パックされた単精度データをコピーします   |
| `movapd`    | _整列された_メモリ位置との間で、パックされた倍精度データをコピーします    |
| `movupd`    | _整列されていない_メモリ位置との間で、パックされた倍精度データをコピーします   |

これらの命令はすべて、2つの`xmm`レジスタ間で値をコピーするのに使えます。

演算にメモリ位置が関わる場合、`movaps`と`movapd`はその位置が_整列_されていることを要求します。`movaps`と`movapd`は、整列されていないアドレスが渡されるとフォールトを発生させます。これは、データの配置が思い描いたとおりになっているかを確かめる安全チェックも兼ねています。

一方、`movups`と`movupd`は、整列されているかどうかに関係なく、どんなメモリ位置でも使えます。

NASMで16バイトの値を表すサイズプレフィックスは`oword`です。

## SIMD拡張

x86-64のエコシステムでは、何十年にもわたってSIMDが活発に開発されてきました。アーキテクチャに拡張が加わるたびに、新しい命令や、既存の命令の新しい使い方が登場します。

とくに、[AVXとAVX2][AVX]という拡張は、いくつかの重要な変更をもたらします。

1つ目は、`ymm`と呼ばれる256ビットのSIMDレジスタのサポートです。`ymm`レジスタは対応する`xmm`レジスタを拡張したもので、ちょうど`rax`が`eax`を含んでいるのと同じ関係です。

2つ目は、`xmm`（および`ymm`）レジスタを扱うほとんどの命令に、3オペランドの変種が用意されたことです。対象はSIMD命令だけでなく、スカラーの浮動小数点数を扱う命令にも及びます。これらの変種は、対応するSSE版と同じ表記に、先頭へ`v`を付けたものになります。

```x86asm
vaddsd xmm0, xmm1, xmm2   ; xmm0 = xmm1 + xmm2 (scalar sum of 64-bit floats)
vmulps xmm1, xmm3, xmm4   ; xmm1 = xmm3 * xmm4 (packed multiplication of 32-bit floats)
vmovupd ymm5, yword [mem] ; this copies 32 bytes from the location at mem to ymm5
```

3つ目は、SIMDのメモリオペランドに求められる整列が緩和されたことです。`vmovaps`のような、明示的に整列を指定するムーブだけが、この整列を必要とします。

このトラックでは、扱う命令とレジスタを、先に述べたSSE拡張の範囲に限定しています。基礎を教えるには十分で、幅広いCPUとの互換性も確保できます。

ただし、テストランナーはAVXとAVX2、さらにはAVX-512に含まれる新しい拡張まで完全にサポートしています。自由に使ってみてください。

~~~~exercism/note
SIMDの変種を使うときは、一貫性を保つのがよい習慣です。同じ命令に対してSSEとAVXの変種を混ぜないようにしましょう。

コードベースでそうした変種を混在させる場合は、AVXを使った作業を終え、SSEを使う前に`vzeroupper`を使うのがよい習慣です。これは依存関係の連鎖を断ち切り、CPUがAVXとSSEの状態を行き来するときの高コストなストールを避けられます。
~~~~
