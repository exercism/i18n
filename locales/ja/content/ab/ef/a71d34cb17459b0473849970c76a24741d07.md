# 概要

`String`と`&str`は、Rustでテキストデータを扱うための2つの基本的な方法です。
それぞれの特徴と、互いにどう組み合わせて動くのかを知っておくと、とても役に立ちます。
このドキュメントでは、両者がどう重なり合うかを説明し、いくつかの基本的なアドバイスを紹介します。
`String`は、`u8`バイトのベクターを所有する型です。
`String`はミュータブルです。
`&str`は、文字列スライスへの借用参照です。
`&str`はイミュータブルです。

`&str`の正しい読み方は「ref string」です。
`String`は、Unicodeコードポイントの並びをUTF-8でエンコードして表した、ミュータブルになり得る表現です。

`&str`は、整形式のUTF-8シーケンスへの読み取り専用のビューです。
参照なので、`Copy`であり、共有できます。

Rustでは、`String`と`&str`は、他の言語のようにインデックスで要素にアクセスすることはできません。
たとえば、次のコードは動作しません：

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

これは、次の性質に由来します：

- 文字列はUTF-8であり、その基本単位はバイトではなく、Unicodeコードポイントの`char`です。
- Unicodeコードポイントは最大4バイト幅ですが、可変幅でエンコードされます。
- そのため、実際にエンコードされた文字を反復処理しない限り、`n`番目のコードポイントの位置を計算することはできません。最初の文字より後では、次の文字の位置が、それまでの文字の幅によって決まるからです。
- そのため、Rustの標準ライブラリの作者たちは、文字列に`Index`トレイトを実装しないことを選びました。バイト配列へのインデックスアクセスは定数時間で済みますが、文字列へのインデックスアクセスには非常に長い時間がかかる可能性があります。これは「驚き最小の原則」に反します。

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## `String`から`&str`への変換

`String`は`Deref<Target=str>`を実装しています。
このトレイトにはコンパイラによる特別扱いがあり、`String`への参照は自動的かつ透過的に`&str`へ型強制できます。
これは次のことを意味します：

- たとえば`&str`引数を期待するコードは、代わりに`&String`を受け取ることができます。
- `&str`に実装されたメソッドは、`String`に対しても呼び出せます。

（汎用的に`str`へのあらゆる形の参照を受け取れるようにしたいなら、引数の型を`impl AsRef<str>`にすることもできますが、通常は引数を`&str`と型付けするのが一般的です。）

## `&str`から`String`への変換

`&str`から`String`を作る方法はたくさんあります：

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

上記の方法はすべて、`String`用のメモリを（ヒープ上に）確保する必要があります。
そのため、`no_std`では`&str`は使えますが、`String`は使えません。

（[heapless](https://crates.io/crates/heapless)クレートは、`no_std`で文字列を操作するときによく使われます。）

## 構造体内で`String`と`&str`を使う

このセクションでは、構造体のフィールドに`String`と`&str`のどちらを使うべきかを説明します。
フィールドの値に`&str`ではなく`String`を使って構造体を定義する例をよく見かけます。

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

`String`を使うと、構造体がデータを所有します。
これにより、コードは読みやすくなり、初心者にも教えやすくなります。
ただし、フィールドごとにヒープ確保が発生するという意味でもあります。
`&str`はテキストデータを借用するので、構造体でライフタイムパラメーターを定義する必要がある代わりに、よりよいパフォーマンスを発揮します。
[csvクレートのチュートリアル][csv-tutorial]では、これらの考え方を実践的に示し、とてもうまく説明しています。

## パフォーマンスに関するメモ

`String`はヒープに確保されるため、使うのにコストがかかることがあります。
`&str`は共有参照なので、頻繁な再確保は必要ありません。
