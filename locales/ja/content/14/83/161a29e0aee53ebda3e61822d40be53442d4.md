# はじめに

`MACRO:`宣言は`:`と似ていますが、本体は*コンパイル時*に実行され、クォーテーションを返さなければなりません。コンパイラーは、返されたそのクォーテーションをマクロの呼び出しの代わりに差し込みます。本体は普通のFactorのコードなので、結果のクォーテーションを作るのは、単に単語のシーケンスを操作するだけです。

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- compound )
    dup append ;

: shout-twice ( name -- ) [ " ahoy!" append print ] twice ;
! At compile time, the call site is replaced with
! [ " ahoy!" append print " ahoy!" append print ].
```

マクロへの入力は、*呼び出し地点でのリテラル*です。リテラルでない値を渡すと、コンパイラーは特化を拒否します。マクロの本体がその値を必要とするのは、実行時ではなくコンパイル時だからです。

よく似たものに、`<< … >>`のパース時評価ブロックがあります。こちらは、クォーテーションを返すという約束なしに、コンパイル時に任意のFactorのコードを実行します。どちらもFactorの[`macros`][macros]の仕組みに含まれます。

[macros]: https://docs.factorcode.org/content/vocab-macros.html
