# 概要

Factorは、ストリーム入出力を2つの層に分けています。下の層は、明示ストリームAPIです。すべてのワードがストリームを引数として受け取ります。上の層は、暗黙ストリームAPIです。現在バインドされているストリームに作用する、短く1行のワードです。どちらの層も同じ[プロトコル][stream-protocol]の上に成り立っています。上の層のワードは、暗黙ストリームを調べて呼び出しを転送しているだけです。

## 明示ストリームのワード

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents`はすべてを読み出します。`stream-lines`はすべてを読み出し、行の境界で分割します。`stream-readln`は一度に1行を返します（ストリームの終端では`f`を返します）。

## 暗黙ストリームのワード

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

これらは日常的に使う入出力のワードです。動的変数`input-stream`と`output-stream`から現在の入力ストリームまたは出力ストリームを調べ、呼び出しを転送します。そのため、`print`の出力先を文字列に変えるには、クォーテーションの実行中だけ`output-stream`をバインドすれば済みます。

## 組み込みのストリームコンストラクター

| ワード              | 語彙                | 生成するもの                  |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | リテラル文字列を読み出す          |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | 書き込みを文字列に集める   |
| `<file-reader>`   | [`io.files`][io.files]           | エンコーディングを指定してファイルを読み出す   |
| `<file-writer>`   | [`io.files`][io.files]           | エンコーディングを指定してファイルに書き出す  |

これら4つはすべて、破棄が必要なオブジェクトを生成します。`destructors`の`disposable`を継承しているため、後述の`with-…`コンビネーターが終了時にそれらを解放します。

## スコープ付きバインディング

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

それぞれがストリームを開き、内側のクォーテーションのための暗黙の入力または出力としてバインドし、終了時に破棄します。クォーテーションが例外を投げた場合でも同様です。これらは`boatswains-bilge`のデストラクターコンビネーターをストリーム用に特化したものです。

`with-string-writer`は特にすっきりした書き方です。新しい`<string-writer>`を自動的に作り、そのライターを暗黙の出力としてクォーテーションを実行し、集められた文字列を返します。「クォーテーションの出力をキャプチャする」というパターン全体が、1つのワードで完結します。

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## なぜ暗黙ストリームを使うのか

動的変数のバインディングのおかげで、`print`は、対話的に実行されているのか、ログファイルに出力されているのか、それともキャプチャされたテストバッファーに出力されているのかを知らないプログラムでも正しく動作します。バインディングを一度差し替えるだけで、`print`を呼ぶすべてのワードが正しく動作します。配線をやり直す必要はありません。これが、上の層がもたらしてくれる発想の逆転です。

ストリームを実装する方法、つまりプロトコルに組み込まれる独自のクラスを定義する方法については、`streams`の概念（`telegraphers-tape`で扱います）を参照してください。
