# 説明

この演習では、工場の従業員向けのバッジを出力するコードを書きます。
従業員にはID、名前、部署名があります。
従業員のバッジのラベルは、次のようにフォーマットされています：`"[id] - name - DEPARTMENT"`。

## 1. 従業員のバッジを出力する

`print_name_badge`関数を実装します。ID、名前、部署を入力として受け取り、部署名を大文字にしたバッジのラベルを返すようにします。

```R
print_name_badge(67, "Katherine Williams", "Strategic Communication")
# => "[67] - Katherine Williams - STRATEGIC COMMUNICATION"
```

## 2. 新入従業員のバッジを出力する

コンピューターシステムのちょっとした不具合で、新入従業員が工場で働き始めた時点では、まだIDを持っていないことがあります。
バッジは必須なので、IDのプレフィックスなしの一時的なバッジが発行されます。

`print_name_badge`関数を拡張します。IDがないときは、IDなしのバッジを出力するようにします。

```R
print_name_badge(NA, "Robert Johnson", "Procurement")
# => "Robert Johnson - PROCUREMENT"
```

## 3. オーナーのバッジを出力する

工場のオーナーでさえ、いつでもバッジを身につけなければなりません。
ただし、オーナーには部署がありませんし、これからもできません。オーナーはすべての部署の上に立つ存在だからです。
この場合、ラベルには部署名の代わりに`"OWNER"`を出力します。

`print_name_badge`関数を拡張します。部署が`NULL`のときは、そのバッジは会社のオーナーのものだとみなします。

```R
print_name_badge(204, "Rachel Miller", NULL)
# => "[204] - Rachel Miller - OWNER"
```

オーナーが新入従業員でもある場合があることに注意してください。

```R
print_name_badge(NA, "Rachel Miller", NULL)
# => "Rachel Miller - OWNER"
```

## 4. IDのない従業員の給与の合計を計算する

IDがどれだけうまく発行されているかの、おおよその指標として、IDのない従業員の給与の合計を見たいとします。
この値が大きいということは、大勢が待たされているか、問題がベテランの従業員にも及んでいるかのどちらかです。どちらも良くありません。

`salaries_no_id`関数を実装します。IDのベクターと、それに対応する給与のベクターを受け取り、まだIDのない人たちの給与の合計を返します。
どちらのベクターも長さは同じです。

```R
ids <- c(204, NA, 210, 352, NA, 263)
salaries <- c(23, 21, 47, 35, 17, 101) * 1000
salaries_no_id(ids, salaries)
# => 38,000
```
