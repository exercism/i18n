# 説明

オーストラリアにある「Doctor Data」という会社で、初出勤の日を迎えます。この会社は情報の復元を専門としています。
C++と[フォン・ノイマン探査機][van-neumann-probes]の知識を武器に、面接は見事に突破しました。
テストファイルをたくさん見てきたので、新しい上司は、会社が最近復元したいくつかのテストコードから、対応するソースファイルとヘッダーファイルを再現するよう求めています。

この演習では、失われたファイルを再現します。
現時点では、ファイルの中身は使いものにならないゴミデータです。

~~~~exercism/note
この概念演習の進め方は、Exercismの練習演習の構成とよく似ています。
演習の導入テキストは、仕様の一部にすぎません。
テストファイルこそが、問題を解くための確実な道しるべです。
C++のコンパイルの仕組み上、テストが必要とするすべてのクラス、関数、列挙型を、最小限のものでも実装し終えるまで、テスト結果がWebインターフェースに表示されないことがあります。
コンパイルエラーが出ても、すべてのタスクとテストに対応し終えれば消えることがあります。
~~~~

タスクは4つあり、いずれもヘッダーファイルとソースファイルにある失われたコードの復元に関係しています。

## 1. まずは手がかりを探し出しましょう

テストファイルから復元された2行に目を向けます。

```cpp
heaven::Vessel bob{"Robert Johansson", 1};
heaven::Vessel will{"Riker", 2, star_map::System::BetaHydri};
```

鋭い目ですぐに`heaven`という名前空間に気づきます。
`Vessel`というクラスが存在することもわかります。
コンストラクターは、どうやら2つか3つの引数で呼び出せるようです。
最初の引数は`string`型のようで、2つ目は数値です。
`Vessel`クラスは、3つ目の引数でも初期化できます。
3つ目の引数は、`star_map`名前空間から来ています。
それは`System`型の列挙子です。
列挙型の1つ、`BetaHydri`まで手に入りました。

見つけた情報をもとに、ソースファイルとヘッダーファイルを用意しましょう。
必要な名前空間は2つ、`heaven`と`star_map`です。
`heaven`名前空間には`Vessel`クラスがあり、2つか3つの引数で呼び出せます。
`System`列挙型は`star_map`名前空間に置き、`BetaHydri`という列挙子を持たせます。
他の列挙子にも目を光らせて、`System`列挙型をそのつど更新できるようにしましょう。

## 2. さらに詳しい情報を探しましょう

テストからさらに多くの行が見つかります。

```cpp
heaven::Vessel bob{"Robert Johansson", 1};
REQUIRE(bob.current_system == star_map::System::Sol);
REQUIRE(bob.generation == 1);
heaven::Vessel bob5 = bob.replicate("Mario");
REQUIRE(bob5.current_system == star_map::System::Sol);
REQUIRE(bob5.generation == 2);
```

新たに見つかったテストの行から、`Vessel`クラスのもう1つのメンバー関数`replicate`が明らかになります。
この関数は文字列を受け取り、別の`Vessel`インスタンスを返します。
前のタスクから、コンストラクターの3つ目の引数のデフォルト値の見当がつきます。
`Vessel`クラスの2つの公開メンバー変数と、`replicate`メンバー関数の仕様もわかります。

ヘッダーファイルとソースファイルに、`replicate`関数と公開メンバー変数`current_system`、`generation`を追加しましょう。

## 3. 内部の仕組みをのぞいてみましょう

復元されたテストファイルに、さらに興味深い行が見つかります。

```cpp
heaven::Vessel bob6{"Homer", 3, star_map::System::EpsilonEridani};
REQUIRE(bob6.busters == 0);
bob6.make_buster();
REQUIRE(bob6.busters == 1);
bool success = bob6.shoot_buster();
REQUIRE(success);
REQUIRE(bob6.busters == 0);
success = bob6.shoot_buster();
REQUIRE_FALSE(success);
```

どうやら`Vessel`クラスには`busters`というメンバー変数があり、2つのクラスメンバー関数`make_buster`と`shoot_buster`で変更できるようです。
他の情報が出てくるまでは、`make_buster`関数は`void`を返すと推測しておきます。
`shoot_buster`の戻り値に対するテストがあるので、この関数は`bool`を返すと仮定します。

`Vessel`クラスに2つの関数とメンバー変数を追加しましょう。
他の`System`列挙子も探し続けましょう。

## 4. 全体像を完成させましょう

テストファイルをひととおり見ても、まだ解明されていないコードの部分は2か所だけです。

```cpp
heaven::Vessel bob1{"Bob", 1, star_map::System::AlphaCentauri};
heaven::Vessel marv{"Marvin", 2, star_map::System::DeltaEridani};
heaven::Vessel milo{"Milo", 3, star_map::System::DeltaEridani};
heaven::Vessel howie{"Howard", 4, star_map::System::Omicron2Eridani};

REQUIRE("Bob" == heaven::get_older_bob(bob1, marv));
REQUIRE(heaven::in_the_same_system(marv, milo));
REQUIRE_FALSE(heaven::in_the_same_system(marv, howie));
```

2つの関数が見えますが、これらはインスタンスから呼び出されていないので、`Vessel`クラスのメンバーではありません。
`get_older_bob`は2つの`Vessel`インスタンスを比較し、`string`を返します。
`in_the_same_system`は2つの`Vessel`インスタンスを比較し、`bool`を返します。

上で復元した行から、まだ足りない最後の関数を実装しましょう。
