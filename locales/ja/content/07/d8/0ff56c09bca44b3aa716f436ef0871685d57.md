# 詳細

`Complex numbers`は、決して複雑ではありません。
ただ、もっと穏やかな名前を付けてあげればよかっただけのことです。

複素数はエンジニアリングや科学の分野でとても役に立つため、Juliaでは[複素数][complex]が整数や浮動小数点数と並ぶ標準の数値型として用意されています。

## 基本

Juliaの`complex`型の値は、本質的には2つの数値のペアです。多くの場合は浮動小数点数ですが、いつもそうとは限りません。
これらは「実部」と「虚部」と呼ばれますが、これは不幸な歴史的経緯によるものです。
ここでも、奇妙な名前にとらわれず、その根底にあるシンプルさに目を向けるのがよいでしょう。

2つの実数から複素数を作るには、虚部に接尾辞`im`を付けるだけです。

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im

julia> typeof(z)
ComplexF64 (alias for Complex{Float64})

julia> zi = 1 + 2im
1 + 2im

julia> typeof(zi)
Complex{Int64}
```

このように、対応する整数型や浮動小数点型から派生した、さまざまな`Complex`型が存在します。

実数の変数から複素数を作るときは、上の書き方ではうまくいきません。
`a + bim`と書くと、パーサーは`bim`という（存在しない）変数名だと勘違いしてしまいます。

`b*im`と書くこともできますが、推奨される方法は`complex()`関数を使うものです。

```julia-repl
julia> a = 1.2; b = 3.4; complex(a, b)
1.2 + 3.4im
```

なぜ`i`や`j`ではなく`im`なのか、不思議に思うかもしれません。

多くのエンジニアは`j`で満足しています。
多くの科学者や数学者は、_虚数_を意味する数学の記法`i`を好みますが、電気工学では`i`は_電流_を意味するため、その記法は衝突してしまいます。

[マニュアル][complex]には、「数学者の`i`やエンジニアの`j`をこのグローバル定数に使うことは、どちらもインデックス変数の名前としてあまりに一般的であるため、却下されました」と書かれています。

幸運な偶然ですが、これによってエンジニアとそれ以外の人たちとの長い議論も避けられます。
これが決定に影響したかどうかは、自由に判断してみてください。

複素数の各部分を個別に取り出すには、次のようにします。

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im

julia> real(z)
1.2

julia> imag(z)
3.4
```

どちらの部分もゼロになることがあり、数学者はそのような数を「完全に実数」や「完全に虚数」と呼ぶことがあります。
ただし、Juliaではそれも複素数です。

```julia-repl
julia> zr = 1.2 + 0im
1.2 + 0.0im

julia> typeof(zr)
ComplexF64 (alias for Complex{Float64})

julia> zi = 3.4im
0.0 + 3.4im

julia> typeof(zi)
ComplexF64 (alias for Complex{Float64})
```

「`i`（または`j`）は-1の平方根である」と聞いたことがあるかもしれません。

今のところ、これが意味するのは、虚部が_定義により_次の等式を満たすということだけです。

```julia-repl
julia> 1im * 1im == -1
true
```

単純な考え方ですが、興味深い結果を生み出します。

## 演算

浮動小数点数や整数で使う標準的な数学の`operators`や初等関数は、複素数でもそのまま使えます。ほんの一例を挙げます。

```julia-repl
julia> z1 = 1.5 + 2im
1.5 + 2.0im

julia> z2 = 2 + 1.5im
2.0 + 1.5im

julia> z1 + z2  # addition
3.5 + 3.5im

julia> z1 * z2  # multiplication
0.0 + 6.25im

julia> z1 / z2  # division
0.96 + 0.28im

julia> z1^2  # exponentiation
-1.75 + 6.0im

julia> 2^z1  # another exponentiation
0.5188946835878313 + 2.7804223253571183im
```

複素数の掛け算と割り算の規則を説明することは、この概念の範囲外です（_そして、そうした演算を「手作業で」行う必要は、めったにないでしょう_）。

複素数についてさらに深く掘り下げたければ、[数学][math-complex]や[電気工学][engineering-complex]の入門書がこの内容を扱っています。

別の方法として、Exercismには`Complex Numbers`の実践演習があり、これらの演算を持つ複素数クラスを基本原理から実装できます。

複素数では整数の割り算が（ほとんど）___できません___。そのため、`//`、`÷`、`%`の各演算子は複素数型ではエラーになります。
例外として、複素_整数_に`//`を使うと複素有理数が得られますが、これはおそらくあまり役に立ちません。

## 関数

ほとんどの数学関数は複素数を入力として受け付けます。

ただし、実数を入力して複素数の出力を期待しても、通常はうまくいきません。
これはパフォーマンスのための最適化で、多重ディスパッチの概念を見たあとであれば、より納得できるはずです。

```julia-repl
julia> sin(1.5 + 2.0im)
3.752771340479298 + 0.25655395609048176im

julia> sqrt(-1)
ERROR: DomainError with -1.0:
sqrt was called with a negative real argument but will only return a complex result if called with a complex argument. Try sqrt(Complex(x)).

julia> sqrt(-1 + 0im)
0.0 + 1.0im
```

`real()`と`imag()`のほかにも、複素数に特に関係の深いいくつかの関数があります。
よくわからない場合は、読み飛ばしてください！

- `conj()`は、複素数の虚部の符号を反転させるだけです（_+から-へ、またはその逆_）。
    - 複素数の掛け算の仕組みのおかげで、これは思っている以上に役に立ちます。
- `abs(<complex number>)`は、虚部のない実数を返すことが保証されています。
- `abs2(<complex number>)`は`abs(<complex number>)`の2乗を返します。`abs()`より計算が速く、実際の計算で必要になることもよくあります。
- `angle(<complex number>)`は位相角をラジアンで返します。

```julia-repl
julia> z1
1.5 + 2.0im

julia> conj(z1)
1.5 - 2.0im

julia> abs(z1)
2.5

julia> abs2(z1)
6.25

julia> angle(z1)
0.9272952180016122
```
数学に興味のある方向けの、部分的な説明です（_繰り返しますが、読み飛ばしてかまいません_）。

- `z1`の`(real, imag)`表現は、実質的に複素平面上の直交座標を使っています。
- 同じ複素数は、極座標を使った`(r, θ)`の記法でも表せます。
- ここで、`r`と`θ`はそれぞれ`abs(z1)`と`angle(z1)`で与えられます。

いくつかの定数を使った例を見てみましょう。

```julia-repl
julia> euler = exp(1im * π)
-1.0 + 1.2246467991473532e-16im

julia> real(euler)
-1.0

julia> round(imag(euler), digits=15)  # round to 15 decimal places
0.0
```

このように、自然界で最も重要な定数のうち3つ、`e`、`i`（または`j`）、`pi`を使ったシンプルな式が、`-1`という結果を生み出します。
数学全体の中で最も美しい結果だと信じている人もいます。
その起源は1740年頃にさかのぼります。

極座標の`(r, θ)`記法はとても便利なので、`cis`（`cos(x) + isin(x)`の略）と`cispi`（`cos(πx) + isin(πx)`の略）という組み込み関数があり、より効率的に構成するのに役立ちます。

極座標記法の有用性は、オイラーの美しい公式`ℯ^(iθ) = cos(θ) + isin(θ) = x + iy`に表れています。ここで`|x + iy| = 1`です。
`|x + iy| = r`とすると、より一般的な極形式`r * ℯ^(iθ) = r * (cos(θ) + isin(θ)) = x + iy`が得られます。
特に指数形式は簡潔で、扱いやすいことに注目してください。

```julia-repl
julia> exp(1im * π) ≈ cis(π) ≈ cispi(1)
true
```

上の近似等号を使ったのは、[`cis`][cis]と[`cispi`][cispi]という関数が、よりきれいな数値結果を返せるためです。特に`cispi`は、引数がπの任意の倍数（つまりラジアンですね！）の場合に力を発揮します。

```julia-repl
julia> cis(π)
-1.0 + 0.0im

julia> cispi(1)
-1.0 + 0.0im

julia> θ = π/2;
julia> exp(im*θ)
6.123233995736766e-17 + 1.0im

julia> cis(θ)
6.123233995736766e-17 + 1.0im

julia> cispi(θ / π)  # θ/π == 1/2
0.0 + 1.0im
```

ちなみに、このおかげで複素数は、2Dでの回転や半径方向の移動を行うのに非常に役立ちます。

回転の場合、複素数`z = x + iy`は、原点を中心に角度`θ`だけ、単純な掛け算`z * ℯ^(iθ)`で回転できます。
ここでの`x`と`y`は、実数の2次元直交平面上のごく普通の座標にすぎません。正の角度は*反時計回り*の回転に、負の角度は*時計回り*の回転になります。

同様に簡単に、半径方向の移動`Δr`は、極形式の複素数の大きさ`r`に加えることで実現できます（例：`z = r * ℯ^(iθ)` -> `z' = (r + Δr) * ℯ^(iθ)`）。
角度の部分は変わらず、期待どおり大きさ`r`だけが変化していることに注目してください。

## おまけ：複素数のよくある質問

興味がなければ、この部分は読み飛ばしてかまいません。

### これは奇妙な、新しい純粋数学の話ではないのでしょうか？

16世紀には、確かに奇妙で新しい話でした。

500年後の今では、エンジニアリングと理学のほとんどの中核をなしています。

### なぜこれを使うのでしょうか？

実は、複素数は、回転するものや波のような性質を持つものを記述するための最もシンプルな方法です。
そのため、電気工学、音声処理、物理学、コンピューターゲーム、ナビゲーションなど、ほんの一部を挙げただけでも、広く使われています。

回転するものは、身の回りに見つかります。
複素数は世界を動かしてはくれませんが、世界が回ることで_何が起こるか_を説明するのには最適です。大きな嵐の衛星画像を見てみてください。

もっとわかりにくいところでは、音は波的であり、光も波的であり、無線信号も波的です。そして、母国の経済でさえ、少なくとも一部は波のようなものです。

こうした波の処理の多くは三角関数（`sin()`と`cos()`）で行えますが、すぐにごちゃごちゃしてしまいます。

複素指数関数を使うほうが___ずっと___扱いやすいのです。

### でも、複素数なんて必要ありません！

それが当てはまるのは、洞窟に住んで食料を採集して生きている場合だけです。

何らかの画面でこれを読んでいるのなら、20世紀に複素数の活用によってもたらされた、いくつかの有用な進歩に完全に依存していることになります。

1. __半導体チップ__。
    - これは古典物理学では説明がつかず、量子力学（QM）によってのみ説明（および設計）できます。
    - 量子力学では、あらゆるものが定義上複素数値です（_どこまでも波の話なのです_）。

2. __高速フーリエ変換アルゴリズム__。
    - FFTは複素数の応用例で、音の伝送、音声処理、写真、動画に関わる_あらゆるもの_に登場します。

    - MP3などの音声形式は圧縮にFFTを使い、より少ない容量により多くの音声を収められるようにしています。
    - JPEG圧縮やMP4動画をはじめ、他にも多くの画像・動画形式が圧縮にFFTを使っています。

    - FFTは、携帯電話の基地局が個々の携帯電話の信号を他のすべての信号から分離できるようにするデジタルフィルターにも使われています。

つまり、おそらく1秒間に何千回も複素数計算に依存する技術を使っているのです。
