# 概要

[`IDisposable`][idisposable]インターフェースはリソースのクリーンアップの中心となるもので、C#では2つの重要な役割を持っています。

- 実装クラスを使う人に対して、そのクラスがもう不要になったことを（[`Dispose()`][dispose]メソッドを呼んで）知らせる責任があることを示します。そうすれば、クラスはアンマネージドリソースを解放したり、必要に応じて内部状態をリセットしたりできます。これは、後始末のすべてを（主にメモリの解放を）[ガベージコレクター][garbage-collector]に任せるという通常のやり方とは対照的です。
- コンパイラーとランタイムと連携して、`IDisposable`インターフェースは`resource-lifetime`演習で説明する[`using`文][using-statement]を支えています。

`Dispose()`が、何らかの汎用的なクリーンアップルーチンの中でインターフェースを通して呼ばれることもありえますが、まれです。

`IDisposable`は、[`System.IO.Stream`][stream]や[`System.IO.TextReader`][text-reader]のように、オペレーティングシステムの（アンマネージド）リソースをラップするライブラリクラスで最もよく出会います。（`Stream`と`TextReader`は別の演習で扱います。）

```csharp
public class TextHandler : IDispoable
{
    private TextReader reader = new TextReader(...);

    public void Dispose()
    {
        reader.Dispose();
    }
}
```

使っているクラスが`IDispoable`インターフェースを実装しているなら、そのインスタンスが不要になったときに`Dispose()`が確実に呼ばれるようにしなければなりません（[`catch`と`finally`][try-catch-finally]節を使います）。あるクラスが`IDisposable`を実装するメンバーを持っているなら、そのクラス自身も`IDisposable`を実装する必要があるでしょう。そうすれば、`IDisposble`を実装するメンバーを破棄するために`Dispose()`を呼べます。

```csharp
public class Activity : IDisposable
{
    private MyResource myResource;

    public Activity()
    {
        myResource = new MyResource();
    }

    public void Perform()
    {
        try
        {
            myResource.BeUseful();
        }
        catch (Exception)
        {
            myResource.Dispose();
        }
    }

    public void Dispose()
    {
        myResource.Dispose();
    }
}
```

`IDisposable`インターフェースは、アンマネージドリソースがまったく絡んでいなくても役に立つことがあります。たとえば、長く生きるオブジェクトがあり、そのオブジェクトに短命なオブジェクトたちが自分自身を登録し、不要になったら登録を解除する必要があるとします。短命なオブジェクトのほうで`IDisposable`を実装すれば、そのクラスを使う開発者に、短命なオブジェクトの寿命の終わりに`Dispose()`を呼ぶ必要があることを知らせられます。

## Disposeパターン

ドキュメントの中に、[dispose pattern][dispose-pattern]への言及を見かけるでしょう。_Disposeパターン_には、クラスの[ファイナライザー][finalizer]から`Dispose()`を呼ぶことや、基底クラスにあるリソースの破棄が正しく処理されるようにすることが含まれます。_Disposeパターン_は後の演習で扱います。

_Disposeパターン_は、主にアンマネージドリソースに関係するものです。[P/Invokeの仕組み][native-interoperability]と`extern`メソッドを使っているなら、Disposeパターンをいつ、どのように実装すべきかを理解する必要があります。ほとんどのC#開発者は、こうした形でアンマネージドリソースを直接扱うことはほとんどありません。
