# はじめに

## SIMD: ビット演算

ほとんどのスカラーのビット演算には、パック版があります。
パック版はSIMD整数演算と同じ一般的な構文に従いますが、サイズ接尾辞がありません。

| 命令 | 説明 |
|-------------|-----------------------------------|
| `pand`      | 2つの128ビット値のビット単位AND |
| `por`       | 2つの128ビット値のビット単位OR  |
| `pxor`      | 2つの128ビット値のビット単位XOR |

パック版の`NOT`は存在しないことに注意してください。
ただし、ANDN演算があり、これは**転送先**オペランドを補数化（すべてのビットを反転）してから、両方のオペランド間のANDを計算します。
NOTとANDを組み合わせたものと考えることができます。

| 命令 | 説明 |
|-------------|-----------------------------------------------------------------|
| `pandn`     | 補数化された**転送先**とソースのビット単位AND |

ビット演算は2つの異なるオペランドの同じ位置にあるビットを組み合わせるため、レーンの境界が結果を変えることはありません。
これが、これらの命令にサイズ接尾辞がない理由です。レジスターは1つの128ビットレーンとして振る舞います。

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
このコンセプトのすべての命令はビットを計算しますが、フラグは設定しません。
パック値を使った条件分岐は、後のコンセプトで扱います。
~~~~

### レーンごとのシフト

シフトは、純粋なビット演算とは違い、実際にビットを位置をまたいで移動させるため、境界を定めるレーンサイズが必要です。
各レーン内ではスカラー版と同じように振る舞い、ビットがあるレーンから隣のレーンへ移動することはありません。

| 命令               | 説明                         |
|---------------------------|-------------------------------------|
| `psllw`, `pslld`, `psllq` | レーンごとの論理左シフト        |
| `psrlw`, `psrld`, `psrlq` | レーンごとの論理右シフト       |
| `psraw`, `psrad`          | レーンごとの算術右シフト    |

これらの命令は、サイズ接尾辞を含め、パック整数演算の構文に従うことに注意してください。
バイトレーンのシフトはなく、ワード、ダブルワード、そして算術右シフトを除いてクワッドワードだけです。

パックシフトとスカラー版の違いの1つは、演算名にあります。

- `shl`と`shr`の代わりに、`sll`と`srl`があります。これは**s**hift **l**eft（**r**ight）**l**ogicalの略です。
- `sar`の代わりに、`sra`があります。これは**s**hift **r**ight **a**rithmeticの略です。

名前は違いますが、演算は同じです。

- 論理右シフトは、最上位ビットを0で埋めます。
  これは2の累乗による符号なし除算に相当します。
- 算術右シフトは、最上位ビットを符号ビットの値で埋めます。
  これは2の累乗による符号付き除算に相当し、負の無限大へ丸められます。
- 左シフトは常に0で埋めます（これが算術左シフトが不要な理由です）。

シフト量はどのレーンでも同じです。
即値か、`xmm`レジスターの下位64ビットを指定できます。

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
レーン幅より大きいシフト量は、スカラー版の`shl`/`shr`ファミリーのようにラップアラウンドしません。
単に0になります（算術右シフトの場合はすべての符号ビットになります）。
~~~~

### 浮動小数点のビット演算

各ビット演算命令には、浮動小数点用の名前を持つ双子の命令もあり、パック浮動小数点演算で見てきたのと同じ構文に従います。

| 整数名 | 浮動小数点名          |
|--------------|----------------------|
| `pand`       | `andps`, `andpd`     |
| `pandn`      | `andnps`, `andnpd`   |
| `por`        | `orps`, `orpd`       |
| `pxor`       | `xorps`, `xorpd`     |

ビット演算はビットを対象とするため、実際には整数演算と浮動小数点演算は同じ結果を計算します。
名前が違うのには2つの理由があります。

1. 意図を記録するためです。コピーするバイトの性質に応じて`movdqa`、`movaps`、`movapd`を使い分けるのと同じです。
2. 整数演算と浮動小数点演算は、しばしば異なる実行ドメインを持ちます。
   同じ実行ドメイン内の演算は、たいていより速く連続して実行できます。

浮動小数点値にはシフト演算がありません。

### 浮動小数点のビット表現

IEEE浮動小数点数のビット表現は、整数とは大きく異なります。

符号なし整数では、各ビットは一様な意味を持ちます。ビットは、そのビットのインデックスに対応する2の累乗を表します。
整数は、セットされたビットに対応する2の累乗の合計です。
ビットをシフトすると数を2の累乗で掛けたり割ったりできるのはそのためで、セットされた各ビットのインデックスを変えているだけです。

符号付き整数では、ほとんどのビットは符号なし整数と同じように解釈されます。
ただし、最上位ビットは特別です。
これがセットされている場合、他のビットに足すのではなく、対応する2の累乗を引く必要があり、その結果は負の数になります。
実際には、数の符号を変えるには、概念的には2つの手順が必要です。すべてのビットを反転し（`not`）、その結果に1を足します（`inc`）。

浮動小数点数のビットは一様な意味を持たず、その位置に応じてまったく異なる解釈が必要です。

| フィールド    | インデックス（32ビット） | インデックス（64ビット） |
|----------|------------------|------------------|
| 符号部     | 31               | 63               |
| 指数部 | 30-23            | 62-52            |
| 仮数部 | 22-0             | 51-0             |

得られる数は`(-1)^sign * 1.fraction * 2^(exponent - bias)`で計算されます。
バイアスは精度によって異なります。

| サイズ   | バイアス |
|--------|------|
| 32ビット | 127  |
| 64ビット | 1023 |

どちらの形式でも、数の符号はもっぱら符号ビットによって決まります。
浮動小数点数の符号を変えるには、このビットを反転するだけです（XOR演算）。
絶対値を得るには、このビットをクリアするだけです（ビットをクリアするAND）。

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

このビット表現では、ビットをシフトしても予測可能で一様な結果にはならないことに注意してください。
仮数部が指数部へ「こぼれ出」し、指数部が符号部へこぼれ出ることがあります。

ただし、表現の各部分を分離して操作すると便利なこともあります。

たとえば、指数部のビットは、バイアスを引く前に、まず符号なしの数として解釈する必要があります。
つまり、その基礎となるビット表現が対応する浮動小数点形式のある2の累乗に対応する、32ビットまたは64ビットの整数を作り出せます。
そして、この生のビット表現を使って、別の浮動小数点数を掛けたり割ったりできます。

たとえば、次のようになります。

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

逆に、指数ビットがセットされ他のすべてのビットがクリアされたマスクでANDを行うことで、パック浮動小数点数の指数を抽出できます。
シフトと減算を組み合わせると、各レーンのバイアスを取り除いた指数を符号付き整数として得られます。

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
浮動小数点数の生のビットを操作することは、状況によっては便利ですが、慎重に行うべきです。
指数部に足したり引いたりするのが安全なのは、オーバーフローやアンダーフローがなく、入力された数が正規数である場合だけです。
また、`0.0`の指数部に有効な`x`を足すと、`0.0 * 2^x`ではなく`2^(x - bias)`になります。
~~~~
