# 抽象クラス

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## `$`は名前の一部です

抽象クラスの名前には、必ず先頭に`$`を付けます。`$`が付くのは抽象クラスだけです。つまり、`$`で始まる型からはオブジェクトを作れません。これは、その名前が現れるところならどこでも見て取れます。

## 中に書けるもの

ルーチンとイテレーターのシグネチャを、セミコロンで終わる形で書きます。本体は書けません。属性も`create`も書けません。抽象クラスが表すのは、あるものに*尋ねられる*ことだけであり、それが何を保持しているかではありません。

## 適合

```sather
class TRAPEZE < $ACT is
```

クラスは、挙げられているすべてのルーチンを、引数の型と戻り値の型を一致させて定義しなければなりません。これはコンパイル時に検査されます。

クラスは複数の型に適合できます。

```sather
class TRAPEZE < $ACT, $RISKY is
```

また、抽象クラスどうしが互いを拡張できます。

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## ディスパッチが行われる場所

抽象型の変数は、適合する何らかのオブジェクトへの参照を保持します。その変数に対してルーチンを呼び出すと、実行時に、そのオブジェクトの実際のクラスに属するバージョンが選ばれます。

Satherが実行時に何かを決めるのは、ここだけです。具象型の変数への呼び出しは、コンパイル時に確定します。

## typecase

ときに、種類が本当に問題になることがあります。そんなときは`typecase`で尋ねます。

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

分岐の内側では、変数はより狭い型を持ちます。これを使うのはまれにしましょう。あらゆる種類のactに対して`typecase`を書くのは、たいてい、そもそも抽象クラスに置くべきだったルーチンです。

## $OB

`$OB`は、すべてのオブジェクトが適合する抽象クラスです。ときどき役に立ちますが、たいていは、途中で型を見失ったというサインです。

## なぜ継承ではないのか？

ほとんどの言語が一つにまとめている2つのことを、Satherは分けています。`<`が言うのは、クラスが*できる*ことだけです。別の場所から実装を得るのは`include`で、これは次の次の演習にあたり、別の判断です。
