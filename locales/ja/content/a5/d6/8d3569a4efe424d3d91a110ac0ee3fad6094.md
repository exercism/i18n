# はじめに

これまでに見てきたシーケンスのワードは、ほとんどが*新しい*シーケンスを返し、入力には手を付けません。`suffix`、`reverse`、`map`などがそうです。しかし、配列とベクターは**その場で書き換えること**にも対応していて、時間とともに変化する状態を記録したいときには、どちらも登場します。

## 変更可能なシーケンスの2つの種類

- **配列**（`{ … }`）は長さが固定です。`<array> ( n elt -- array )`（[`arrays`][arrays]にあります）は、長さ`n`の新しい配列を作り、`elt`のコピーで埋めます。
- **ベクター**（`V{ … }`）は伸び縮みします。新しい空のベクターには`V{ } clone`を使います。`<vector> ( n -- vector )`（[`vectors`][vectors]にあります）は、`n`個の要素分の容量をあらかじめ確保します。

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## スロットを変更する

この2つはどちらの種類のシーケンスにも使えます。どちらも、インデックスのあとにシーケンスを取ります。

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth`は代入し、`change-nth`は位置`n`の要素にクォーテーションを適用します。これらの[`sequences`][sequences]のワードはどちらもスタックに何も返しません。変更そのものが効果です。

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## 伸ばす・縮める

配列は長さを変えられないので、この3つはベクターでしか意味を持ちません。

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## ベクター → 配列

ベクターを組み立てて、それを長さが固定の配列として返したいときは、`>array ( seq -- array )`（[`arrays`][arrays]にあります）を使うと、同じ要素を持つ新しい配列が返ります。

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`でスナップショットを残す

変更はシーケンスをその場で書き換えます。呼び出し元からシーケンスを受け取り、これからそれを変更しようとしているなら、`clone`（[`kernel`][kernel]にあります）を使うと独立した新しいコピーが手に入るので、呼び出し元が見ている内容がその人の知らないうちに変わることはありません。

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

同じ注意は`V{ }`やその他の空のリテラルにも当てはまります。言語によっては、`[]`や`vec![]`が式を評価するたびに新しいコンテナを確保します。Factorでは、ソースに書いたリテラル`V{ }`は*1つ*のオブジェクトで、それを書いたすべての呼び出し元で共有されます。`V{ }`に直接`push`すると、次の呼び出しでは前回の残りが見えてしまいます。ほとんどの場合にほしい新しいコピーは、`V{ } clone`で作れます。
