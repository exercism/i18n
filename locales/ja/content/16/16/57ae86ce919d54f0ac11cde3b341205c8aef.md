# 説明の追記

## Nodeプロセス

ほかの演習とは違い、`grep.js`はテストファイル`grep.spec.js`の中に_読み込まれません_。その代わり、実行ファイルであるかのように使われます。それを可能にするために、`grep.js`ファイルにはshebangと、それが何をするものかを説明するコメントが用意されています。

```javascript
#!/usr/bin/env node

// The above line is a shebang. On Unix-like operating systems, or environments,
// this will allow the script to be run by node, and thus turn this JavaScript
// file into an executable. In other words, to execute this file, you may run
// the following from your terminal:
//
// ./grep.js args
//
// If you do not have a Unix-like operating system or environment, for example
// Windows without WSL, you can use the following inside a window terminal,
// such as cmd.exe:
//
// node grep.js args
//
// Read more about shebangs here: https://en.wikipedia.org/wiki/Shebang_(Unix)
```

テストは新しいnodeの_プロセス_を起動し、`grep.js`を実行します。

## 引数を読み取る

_プロセス_の起動時に渡された引数を取得するには、`process.argv`を使います。

## ファイルを読み込む

関数`readLines`が用意されています。これを使うためにファイルパスを変換する必要はありません。`readlines`関数は、カレントディレクトリを基準にパスを_解決_します。`grep.js`のプロセスでは、このカレントディレクトリは演習のディレクトリに設定されています。

## 出力を書き込む

出力を書き込むには、次のものを使います。

- `console.log`は標準出力ストリームに書き込みます。
- `console.error`は標準エラーストリームに書き込みます。

テストは、標準エラーストリームに何も書き込まれなければ実行を成功（resolved）と見なし、標準エラーストリームに何か書き込まれれば成功しなかった（rejected）と見なします。
