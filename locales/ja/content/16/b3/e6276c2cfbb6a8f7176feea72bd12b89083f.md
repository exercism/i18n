# 概要

`Result`型は、エラーの報告とエラーの回復に対するElm言語の解決策です。`Maybe`型と少し似ていますが、`Maybe`の`Nothing`はある種の失敗を表すだけで、*なぜ*失敗したのかについては何も教えてくれません。`Result`には、なぜ失敗したのかという文脈が含まれています。

## 定義と型変数

`Result`型は次のように定義されています。

```elm
type Result error value
  = Ok value
  | Err error
```

ひとことで言えば、この型は、成功して`value`を返すか、失敗してその理由（`error`）を返すか、どちらかになる操作の結果を表します。

これはElmの用語では「カスタム型」の定義と呼ばれます。
カスタム型については、このトラックの別の概念で詳しく紹介しますが、`Result`を理解するうえでは必要ありません。
`OK value`と`Error error`の`error`と`value`は型変数を表していて、`Int`や`Bool`、`String`など、どんな型でもかまいません。
したがって、`Result String Int`は`Int`が入っていることが期待される値で、エラーがある場合はそれが`String`として表されます。

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## Result値の中身を読む

`Result`値の中身を読むには「パターンマッチング」を使います。
パターンマッチングも別の概念で詳しく紹介するので、ここでは`Result`のパターンマッチングがどう機能するかにだけ注目します。

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

`Result`値を使うたびに、Elmコンパイラーが、コードがあらゆる可能性を処理しているかどうかを確認します。そのため、`Result`をパターンマッチングして`Ok value`の場合だけを処理する、ということはできません。
これは最初は面倒に思えるかもしれませんが、Elm言語の最大の強みの1つです。
何百ものバグを防いでくれますし、コンパイラーに導かれたリファクタリングは、恐れることなく、やりがいのある体験になります。

## Result値の中身を操作する

`Result`型を扱うための関数はいろいろあり、たいていはパターンマッチングよりも好んで使われます。`Result.map`を使うと値に関数を適用でき、`Result.andThen`を使うと失敗する可能性のある関数をつなげられます。

Result.mapはOkの値を変えるのに使い、Resultがエラーを含むかどうかを気にせずに関数をつなげられるので便利です。値がOkなら、Result.mapはつなげた関数（下の`formatAge`）を呼び出しますが、エラーがあればResult.mapは何もせず、そのエラーをそのまま返します。

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

Result.andThenはOkの値を変えるのに使い、Resultがエラーを含むかどうかを気にせずに関数をつなげられるので便利です。Result.mapと似ていますが、Result.andThenは、やはりResultを返すつなげた関数（下の`formatSpecialBirthday`）と組み合わせて使います。`Result.map`でも同じことはできますが、入れ子が1層余分に増えてしまいます。`andThen`はそこをうまく避けてくれます。

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
