# マップとセット

配列は、値を番号の付いた位置に保持します。しかし、ラベルとして役に立つものが番号とは限りません。

## マップ

**マップ**は、各**キー**を**ターゲット**と組にします。キーで調べると、マップはそこにしまっておいたものを返してくれます。

`FMAP{K,T}`は、型`K`のキーから型`T`のターゲットへのマップです。動物の名前とその生息地を組にしたガイドは、`FMAP{STR,STR}`になります。

```sather
   guide ::= #FMAP{STR,STR};
   guide := guide.insert("emu", "grassland");
   guide.get("emu")               -- "grassland"
```

## 戻り値は必ず代入し直す

真ん中の行をもう一度見てみましょう。`insert`は、追加した組を含むマップを返します。その戻り値は必ず受け取っておく必要があります。

```sather
   guide := guide.insert("emu", "grassland");     -- yes
   guide.insert("emu", "grassland");              -- no: the answer is lost
```

これは`FSTR`と同じルールで、理由も同じです。戻り値はたいてい、渡したマップそのものがその場で変更されたものです。ときには、マップに空きがなくなったときに、より大きなマップになることもあります。どちらなのかは区別できないので、**戻り値を使い、古い名前は使わないようにしましょう。** `insert`より前の名前を使い続けると、内容が古くなっていたり、そもそも使えるマップを指していなかったりすることがあります。

つまり、ルーチンに渡したマップも、そのルーチンから影響を受けないとは言えません。元のマップをそのまま残しておきたい場合は、コンセプトページの`copy`を参照してください。

## キーはあるかどうか

`has_ind`は、あるキーがマップに入っているかどうかを調べます。この名前は「has index」の略で、ここでのindexは、これらのマップがキーと呼んでいるものを指します。

```sather
   guide.has_ind("emu")           -- true
   guide.has_ind("moa")           -- false
```

存在しないキーを求めても、**エラーは出ません**。`get`はその型の空の値を返します。`INT`なら0、`STR`なら`void`です。これが原因で、後になって、別の場所で問題が起きます。なので、取り出す前に存在を確認しましょう。

```sather
   if guide.has_ind(animal) then
      return guide.get(animal);
   else
      return "Unknown";
   end;
```

## セット

**セット**は、重複も順序もない値の集まりです。`FSET{T}`は、型`T`の値のセットです。

```sather
   seen ::= #FSET{STR};
   seen := seen.insert("emu");
   seen := seen.insert("emu");    -- already there; nothing changes
   seen.size                      -- 1
   seen.has("emu")                -- true
```

同じものを2回挿入しても、残るのは1つです。これがセットの目的です。それぞれが何回現れたかを忘れて、ただ集めておくために使います。

セットに対する`insert`も、マップとまったく同じように、以後使うべきセットを返します。そのため、毎回代入し直してください。

## 要素数

`.size`はどちらにも使えます。マップがいくつの組を持つか、セットにいくつの値が入っているかを調べられます。
