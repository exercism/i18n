# Rexxスタイルガイド

このガイドでは、Rexxトラックの演習のテストファイルとサンプルファイルで使うことを想定したスタイルについて説明します。

## Rexx標準

コードはRexx Language level 5.0に準拠している必要があります。

Regina Rexxの拡張機能や、外部ライブラリにアクセスするためのSAA標準関数を使ってもかまいません。

AREXXの拡張機能や、CMSのバッファ操作ルーチンは使わないでください。

## プラットフォーム

実行時のテスト環境はLinuxベースなので、`ADDRESS`命令の呼び出しには、その環境で利用できるコマンドだけを使えます。これらはコードのコメント内ではっきりと目立たせるようにしてください。

## 名前

### 命令

命令（予約語）は**_小文字_**で書きます。したがって、次のコードはこのスタイルガイドの推奨に準拠しています：

```rexx
do while input \= ''
  parse var input char +1 input
  say char
end
```

一方、次のどちらも準拠していないため、推奨されません：

```rexx
/* *** Not recommended *** */
Do While input \= ''
  Parse Var input char +1 input
  Say char
End
```

および：

```rexx
/* *** Not recommended *** */
DO WHILE input \= ''
  PARSE VAR input char +1 input
  SAY char
END
```

### 組み込み関数（BIF）

BIFは**_大文字_**で書きます。次に例を示します：

```rexx
input = 'ABCDE'
say 'Length of input is' LENGTH(input)
say 'First letter of input is' SUBSTR(input, 1, 1)
```

### ラベル（ユーザー定義関数）

ラベル名は**_パスカルケース_**で書きます。次に例を示します：

```rexx
greeting = MyFuncSayHello()
say greeting

exit 0

MyFuncSayHello : procedure
  hello = 'Hello there!'
return hello
```

### 変数

変数名は**_小文字_**の英字で始めます。そのため、1語の変数名は小文字になります。

複数語の変数名は、**_キャメルケース_**または**_スネークケース_**で表せます。

このトラックでは、_ほとんどの変数にキャメルケースを使い_、テスト用の変数にはスネークケースを取っておくという規約を採用しています。定数として使う変数は、任意で大文字にしてもかまいません。

```rexx
input = 'ABCDE'
i = 0

personName = 'Alice'
test_person_description = 'Brown hair, blue eyes'

TRUE = 1
PI_CONSTANT = 3.14159
```

## リテラル

文字列は、シングルクォート**`'`**またはダブルクォート**`"`**で囲んで表せます。次の2つは同じ意味です：

```rexx
say "Hello, world!"

say 'Hello, world!'
```

どちらも、エスケープ文字を使わずにもう一方の中に埋め込めます：

```rexx
say "Please don't do that as it's wrong."

say 'He said, "Please sir, may I have more?".'
```

文字列の中にクォートが埋め込まれていて、クォートを混在させる必要がある場合を除き、文字列は**_シングルクォート_**で囲むことをおすすめします。

### 16進数と2進数の文字列

2進数と16進数の値は、それぞれ文字列の末尾に**`B`**または**`X`**を付けることで表せます。例：

```rexx
hexvalue = "0A"X

binvalue = "00001010"B
```

このような値は**_ダブルクォート_**で囲むことをおすすめします。

先ほどの、ふつうの文字列はシングルクォートで表すという推奨と合わせて、この規約はコードの中で2進数や16進数の文字列を見分けやすくします。

### 改行ターミネーター

多くのUNIX系言語やCの影響を受けた言語では、リテラル**_`\n`_**が**_改行_**のターミネーターとして使われます。この使い方は広く普及しており、このトラックのいくつかの演習では、このターミネーターを含む文字列の使用と操作を行います。

Rexxはこのターミネーターをサポートしておらず、**_`\`_**（およびその他の文字）をエスケープ文字としてもサポートしていません。

改行文字に相当するRexxでの表現は、プラットフォームに依存する16進数の値です。UNIX系のプラットフォームでは次のようになります：

**_`"0A"X`_**

次の、改行が埋め込まれた文字列（bashシェルを使用）に相当するRexxの式は次のとおりです：

```bash
printf "I have\nthree embedded\nnewlines.\n"
```

```rexx
say 'I have' || "0A"X || 'three embedded' || "0A"X || 'newlines.' || "0A"X
```

このトラックの演習では、ターミナルでの表示を目的とした文字列で必要な場合にのみ、**_`\n`_**を**_`"0A"X`_**に変換します。それ以外の場合、**_`\n`_**という文字列は単に論理的な改行として解釈されます。

## その他のスタイル上の推奨

インデントには2文字、3文字、4文字のスペースを使ってかまいませんが、_2文字_のインデントと、インデントの一貫性が好まれます。

関数内の最後の**_`return`_**命令は、ラベル名と揃えて書き、その関数の終わりをはっきり示すようにします。また、_必ず_値を返すようにします。

真偽値のNOT演算子はいくつかの異なる記号で表せます。このトラックで推奨する記号は**`\`**で、この使い方との一貫性を保つため、関係演算子の「等しくない」も**`\=`**とします。

真偽値の**`false`**と**`true`**は、それぞれ**`0`**と**`1`**で表します。これらの値にはあらかじめ定義されたリテラルはありません。

エラー状態は戻り値で示し、空文字列**`''`**または**`-1`**が、状況に応じてエラー状態を表します。

## テストファイルのレイアウト

演習には、演習の最上位ディレクトリに置かれた`<exercise>-check.rexx`という名前のテストファイルが1つあります。

この規約に従うと、`acronym`演習のテストファイルは`acronym-check.rexx`という名前になります。

各演習のテストファイルは、学習者が演習の要件を理解しやすくし、貢献者がテストを実装または拡張する作業をしやすくするために、緩やかですが一定の決まった形式で書かれています。

次は`acronym`演習のテストファイルの一部です：

```rexx
/* Unit Test Runner: t-rexx */
function = 'Abbreviate'
context('Checking the' function 'function')

/* Unit tests */
check('basic' function||'("Portable Network Graphics")',,
      function||'("Portable Network Graphics")',, 'to be', 'PNG')

check('lowercase words' function||'("Ruby on Rails")',,
      function||'("Ruby on Rails")',, 'to be', 'ROR')
```

このファイルは2つの論理的なセクションに分かれており、それぞれがコメント行で示されています。

最初のセクションでは、**_テスト対象の関数_**の名前（ここでは`Abbreviate`関数）を`function`変数に代入します。この変数名は説明的ですが任意のもので、ファイルの残りの部分でテスト対象の関数の名前が必要なところではどこでも参照されます。

このセクションには`context`関数の呼び出しもあり、その目的は明らかです。

次のセクションには単体テストが入っています。`check`関数の呼び出し1つ1つが1つの単体テストです。期待される引数は次のとおりです：

```rexx
check(<test description>,
      <function invocation>,
      [<actual result variable>],
      <test comparator>,
      <expected result>)
```

**\<test description>**は、テストを実行したときに出力される文字列です。できるだけ説明的にするため、例のように、テスト対象の関数の名前とそれに渡す引数を組み合わせた文字列を使うことをおすすめします。

**\<function invocation>**は、実際の関数の呼び出しで、その戻り値を比較のために`check`に渡します。

**\<actual result variable>**は省略可能な引数で、使う場合は、テストの比較に使う値を入れた変数の名前です。

これを使う理由は、テスト対象の関数の戻り値そのものではなく、戻り値から_導き出された_結果を確認できるようにするためです。わかりやすい例は、次のように戻り値が数KBの文字列になる場合です：

```rexx
expected_length = LENGTH(FUT(...))

check('...', FUT(...), expected_length, 'to be', 50)
```

\<function invocation>引数はそれでも渡す必要があることに注意してください。

**\<test comparator>**は、実行する比較の種類を表す文字列です。ほとんどの場合、これは等しいかどうかの比較を要求する文字列'to be'になります。その他の比較オプションについては、単体テストフレームワークのドキュメントを参照してください。

**\<expected result>**は、言うまでもなく、実際の結果と比較される値です。

テストファイルの中では、変数を自由に宣言し（もちろん使う前に）、リテラルの代わりに`check`の引数として使えます。
