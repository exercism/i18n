# Unisonの基本

## 項と関数

項と関数は、Unisonのプログラムを書くうえでの基本単位です。

「項」とは、静的な値のことです。`name = expression`という形で定義し、必要に応じてその前に`name : MyType`という形式の型シグネチャを付けます。Unisonは型推論をサポートしているため、単純な定義では型シグネチャが省略されることもあります。

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unisonの関数は`myFunctionName argument1 argument2 = myImplementation`のような形をしていて、関数名のあとにスペースで区切った引数が続きます。

```
getMax a b = Nat.max a b
```

関数には、必要に応じて型シグネチャを書くこともできます。右端の型は常にその関数の最終的な戻り値の型で、それぞれの引数は関数の矢印`->`で区切られます。

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

関数を呼び出すには、関数名のあとに、スペースだけで区切った引数を続けます。

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

関数を呼び出すとき、Unisonはすぐ右にあるものを引数として扱おうとします。そのため、思いどおりの順序で関数が評価されないことがあります。

次の式から値`1`を取り出したいとします。

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

このまま書くと、`shouldBe1`は`0`と評価されます。暗黙の関数適用の順序が`getMax 1 10`、つまり`10`で、そのあと`10 - 10`で`0`になるからです。

括弧（`()`）を使うと、式をまとめ直して、意図した順序で計算させることができます。

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## ウォッチ式

Unisonには、コードを手早く評価する方法として「ウォッチ式」があります。ウォッチ式は`>`記号で始まり、そのあとに評価したい式を書きます。ウォッチ式は、拡張子が`.u`のファイルならどれにでも書けます。ファイルを保存すると、Unison Codebase Manager（UCM）のコンソールに、式が評価された結果が表示されます。このドキュメントでは、可能なかぎり、ウォッチ式で評価したあとの式とその期待される出力をあわせて示します。

```
> helloThere
  ⧩
  "Hello, World!"
```

## 複数行の関数

Unisonの複数行関数では、インデントまたは`let`ブロックを使ってコードの範囲、いわゆる「字句スコープ」を指定します。

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

同じインデントのレベルにあるものはすべて同じスコープを共有します。だからこそ、最後の行で変数`newBeginning`を参照できるのです。

## 名前空間と`use`文

名前空間は、Unisonの関数をグループ化して整理するための仕組みです。「ディレクトリ」のようなものだと考えてください。構造と論理的なまとまりを与えてくれます。

`use`文を使うと、名前空間にある関数をスコープに持ち込めます。

Unisonの`List`の値を使う関数を書いているとします。`List.map`や`List.flatMap`のような関数が必要になることはわかっています。ここで`List`は名前空間で、`map`と`flatMap`は関数です。同じことを何度も書かずに済むように、関数の中で`List`名前空間のすべてを次のように字句スコープに持ち込めます。

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List`の行が、`map`と`flatMap`への参照を明確にします。[`use`文についてはこちら][use-statements]で詳しく読めます。

## Unisonの標準ライブラリ

Unisonの標準ライブラリは`base`と呼ばれています。クイックスタートガイドに沿ってローカルにコードベースを作成していれば、標準ライブラリは自動的にダウンロードされているはずです。標準ライブラリのドキュメントは、オンラインの[Unison Share][unison-share-base]で見ることができます。

## コメントとドキュメントリテラル

Unisonのコメントは、少し変わった機能です。Unisonのコードを書くとき、`.u`の拡張子が付いたファイルの中に、解釈されないテキストを次の構文で書けます。

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_ただし_、Unisonのコードは、ファイルシステム上のテキストベースのファイルとしてではなく、抽象構文木のハッシュとして保存されます。そのため、ファイル内の特定のUnisonの関数や項をテキストベースで「飾り付ける」コメントは、保存して共有時に再表示する、ということが実質できません。Unisonの項に、他の人が読んで理解できる形で保存される情報を追加したい場合は、ドキュメントリテラルを使えます。

Unisonというプログラミング言語では、ドキュメントは第一級の値です。つまり、`Doc`要素は値に代入でき、関数に値として渡せ、関数の値として返すこともできます。ドキュメントリテラルの要素は、二重の波括弧（`{{}}`）で開いて閉じます。`Doc`要素をコメントとして使う例を挙げます。

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
