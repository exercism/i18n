# 文字列ビルダー

`STR`はイミュータブルですが、`FSTR`は違います。完成したテキストには`STR`を、まだ組み立てている途中のテキストには`FSTR`を使います。

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## 結果は必ず代入し直しましょう

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR`は**償却つきの倍々方式**で大きくなります。スペースが足りなくなると、新しい、より大きな配列を用意し（サイズは2倍）、そこにコピーします。つまり、結果はたいてい同じオブジェクトですが、ときには別のオブジェクトになります。毎回`b := b + x`と書くのが、どちらの場合でも正しく、覚える価値のある唯一の書き方です。

倍々にすることが、全体の手間を長さの2乗ではなく長さに比例させる理由です。コピーの費用が上がるのと同じ速さで、コピーの回数は減っていきます。

## なぜ`STR`に`+`をそのまま使わないのでしょうか？

決まった数の、わずかな断片を`+`でつなぐのは、わかりやすくて問題ありません：

```sather
   return piece + " by " + composer;
```

問題になるのはループの中だけです。コードを書く時点で、つなぐ回数がわからないからです。おおまかな目安として、`+`が`loop`の中にあるなら、`FSTR`の出番です。

## 便利なルーチン

| 呼び出し | 動作 |
| --- | --- |
| `b + x` | 追加します。`x`は`STR`、`CHAR`、`INT`、`BOOL`など |
| `b.size` | これまでに何文字あるか |
| `b.str` | 完成した`STR` |
| `b.clear` | 中身を空にし、領域はそのまま残します |

## エスケープ

| 書き方 | 意味 |
| --- | --- |
| `"\n"` | 改行 |
| `"\t"` | タブ |
| `"\""` | 二重引用符 |
| `"\\"` | バックスラッシュ |
