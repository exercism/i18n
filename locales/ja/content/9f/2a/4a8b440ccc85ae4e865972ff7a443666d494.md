# はじめに

## 浮動小数点数

**浮動小数点数**とは、`-1.23`や`3.1415`のように小数部を持てる数値です。

そのような数値をバイト列として表すために、x86-64では**IEEE-754**規格を使用します。
この規格で最も一般的な2つの形式は、単精度浮動小数点数と倍精度浮動小数点数です。
x86-64は両方をサポートしています。

単精度浮動小数点数は32ビット幅で、倍精度は64ビット幅です。

### XMMレジスタ

x86-64には、浮動小数点演算を行うための専用レジスタが16個あり、`xmm0`から`xmm15`という名前が付いています。

これらのレジスタは少なくとも128ビット幅ですが、最近のプロセッサーではこれが256ビットや512ビットに拡張されています。
ただし、実際には、ほとんどの浮動小数点数は、必要な精度に応じて、最下位の32ビットまたは64ビットしか使いません。

### 数値間の変換

数値形式を変換するための命令群があります：`cvtxx2yy`。

`xx`と`yy`はどちらもリテラルではなく、プレースホルダーです：

- `xx`はソースオペランドの型を表すプレースホルダーです。
- `yy`はデスティネーションオペランドの型を表すプレースホルダーです。

このプレースホルダーは多くの形を取ることができ、その一部は次のとおりです：

| プレースホルダー | 意味               |
| ----------- | --------------------- |
| `si`        | 符号付き整数        |
| `ss`        | 32ビット浮動小数点数 |
| `sd`        | 64ビット浮動小数点数 |

例えば：

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

32ビット整数を64ビット浮動小数点数に変換したり、64ビット整数を32ビット浮動小数点数に変換したりできることに注意してください。
同様に、32ビット浮動小数点数を64ビット整数に変換したり、64ビット浮動小数点数を32ビット整数に変換したりすることもできます。
言い換えれば、`cvtxx2yy`の両オペランドのサイズは_同じである必要はありません_：

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

浮動小数点数を整数として正確に表せない場合、`cvtxx2si`は`mxcsr`と呼ばれる特殊なレジスタの丸め制御に従って数値を丸めます。
これは、最近接への丸め、切り下げ、切り上げ、切り捨てのいずれかです。
関数に入った時点で、保証されたデフォルトはありません。

正確な結果は丸められず、したがって丸め制御の影響を受けないことに注意してください。
たとえば、`42.0`は_常に_`42`に変換されます。

結果を常に切り捨てる、`cvttxx2si`という形式（余分な`t`が付く）の同様の命令群があります。

### 丸め

`roundxx`命令群は、ソースオペランドの浮動小数点数を、デスティネーションオペランドに格納される丸められた浮動小数点数に変換します。

ここで、`xx`はいつものようにオペランドの型を表すプレースホルダーです。単精度なら`ss`、倍精度浮動小数点数なら`sd`です。

これらの命令は、第3オペランドとして定数を受け取ります。
この数値は丸めモードを示します：

| 数値 | モード         |
| :----- | :----------- |
| 0      | 最近接      |
| 1      | 負の無限大方向（切り下げ） |
| 2      | 正の無限大方向（切り上げ） |
| 3      | 0方向（切り捨て）     |

例えば：

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

これらの命令は正確な結果を生成するため、`cvtxx2si`の前準備として使用できます。

### 算術命令

浮動小数点数を使う多くの演算では、整数用の同等の命令と似た名前の命令を、末尾に必要なプレースホルダー（`ss`または`sd`）を付けて使います。
これらの命令は、乗算や除算を行うものも含め、通常のセマンティクスで2オペランドです：

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

### 移動

XMMレジスタから別のXMMレジスタへ移動する命令は、`movss`または`movsd`です：

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

即値（定数の符号付き整数）をXMMレジスタに直接移動することは**できません**。
この数値はまず汎用レジスタに移動し、次に`cvtsi2xx`を使って変換する必要があります：

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

### 比較

2つの浮動小数点数を比較する命令には2つのグループがあります。
それらは`comixx`と`ucomixx`という形式を取り、`xx`は`ss`または`sd`のどちらかです。
どちらも通常どおり`rflags`のフラグを設定し、`cmp`と同じセマンティクスに従います。

両者の違いは、2つの浮動小数点数の一方が`NaN`値を持つ場合、`ucomixx`は`parity flag (PF)`を設定するのに対し、`comixx`はこの場合に例外を発生させることです。

浮動小数点値の比較は_符号なし_です：

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

### 呼び出し規約

System V ABIでは、最初の8つの浮動小数点引数は、`xmm0`から`xmm7`の順に関数へ渡されます。
浮動小数点値は、関数から`xmm0`で返され、必要に応じて`xmm1`でも返されます。

すべての`xmm`レジスタは自由に使用でき、呼び出し元のために予約されているものはありません。

### メモリ

浮動小数点値は、同じサイズの整数と同じセマンティクスでメモリ内に定義できます。
NASM（The Netwide Assembler、このトラックで使われているアセンブラー）では、浮動小数点値を指数表記で宣言することもできます。

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```
