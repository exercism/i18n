# 自分で作るイテレーター

`bird-survey`からイテレーターを使ってきました。今度は、自分で書いてみましょう。

## yield

イテレーターはルーチンとよく似ていますが、違う点が2つあります。名前が`!`で終わること、そして値を`return`ではなく`yield`で渡すことです。

```sather
   markers!(count : INT) : INT is
      loop
         yield 100 * 1.upto!(count);
      end;
   end;
```

`yield`は、そのイテレーターを呼び出したループに値を1つ渡し、そこで**待ちます**。呼び出し元のループが再び回ってくると、イテレーターは`yield`の直後から処理を再開します。変数も、自分自身のループも、今いる位置も、すべて去ったときのままです。

これがイテレーターの正体です。途中で一時停止して、そこから再開できるルーチンなのです。

```sather
   loop
      #OUT + TRAIL::markers!(3) + " ";      -- 100 200 300
   end;
```

## 終わり方

イテレーターの終わり方には2通りあります。

**使い切ったとき。** イテレーター自身のループが終わるか、ルーチンの末尾に達すると、そこで終了です。呼び出し元のループも、その場で終わります。

**`quit`。** `quit`は、値を渡すことなく、その場でイテレーターを終わらせます。

```sather
   named!(names : ARRAY{STR}) : STR is
      loop
         name ::= names.elt!;
         if name = "" then quit; end;
         yield name;
      end;
   end;
```

これは、空の名前が出てくるまで名前を渡し続け、そこで止まります。`quit`は、ルーチンにとっての`return`と同じ役割をイテレーターで果たしますが、値を伴わない点が違います。渡すものはもう何も残っていないからです。

## once

`once`を付けた引数は、ループが回るたびではなく、ループの開始時に一度だけ計算されます。

```sather
   markers!(once count : INT) : INT is
```

ループが回っても変わらないものには、これを使います。ほとんどの引数がそうですね。ライブラリに用意されているイテレーターも同じです。`upto!(once i : SAME)`。

## 値を渡さないイテレーター

イテレーターは、何も渡さなくてもかまいません。`times!`がその例です。

```sather
   steps!(once count : INT) is
      loop
         ignored ::= 1.upto!(count);
         yield;
      end;
   end;
```

`yield`だけを書くと何も渡さず、ただループを1回分進めるだけです。

## 位置はどこにあるのか

イテレーターを呼び出す*プログラム上の場所*ごとに、それぞれ独自の位置を保ちます。同じイテレーターを1つのループ本体から2回呼ぶと、2回分進んでしまうのはそのためです。理由がわかったはずです。2つの呼び出しは、それぞれ別の、一時停止したルーチンなのです。
