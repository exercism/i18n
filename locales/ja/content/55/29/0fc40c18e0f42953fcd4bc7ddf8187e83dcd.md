# 概要

## 表現・文字・整数

`int`や`bool`などの他の単純型と同じように、`char`にも対になる型（別名の型）があります。ここでは`System.Char`です。

これは実際には16ビットのフィールドを持つ`struct`で、デフォルトではイミュータブルです。

`char`には、`Equals`、`ToString`、[`CompareTo`][compare-to]などのインスタンスメソッドがあります。

`char`は[`ushort`][uint16]と同じ幅ですが、一部の言語のように一般的に互換的に使われることはありません。`ushort`は明示的に`char`へキャストする必要があります。

ちなみに、`char`は算術演算の対象になります。これらの演算の結果は整数になります。

当然ながら、8ビットの`byte`と16ビットの`char`は同じものではありません。

## 使い方

`char`は一般に扱いやすい型です。

シングルクォートを使ったリテラルとして定義できます。

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

文字列から（0から始まる）インデックスを使って、個々の`char`を取り出すことができます。

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

文字列を繰り返し処理すると、各ステップで`char`が返ります。

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

上で見たように、`char`はその`int`値にキャストできます。
これは他の文字体系でも（*少なくとも時には*）うまくいきます。

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

文字を比較するときには、基になるInt16が使われます。

```fsharp
'A' < 'D'
// => val it: bool = true
```

また、`int`は`char`にキャストできます。

```fsharp
char 77
// => val it: char = 'M'
```

`System.Char`ライブラリには、大文字・小文字変換など、.NET言語に期待される[メソッド][Char-methods]一式がそろっています（ただし、次のセクションの注意点も参照してください）。

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

.NETのライブラリは、文字列から`char`を取り出すのにも役立ちます。ここでは`Seq`のメソッドを使っています。

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

文字のリスト（または配列）を文字列に変換する方法はいろいろあります。たとえば次のようなものです。

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

`char`に関する一般的な情報はこちらにあります。

- [Charsのドキュメント][chars-docs]: `char`のリファレンスドキュメントです。

ただし、`char`には以下で詳しく述べるように、いくつか扱いにくい点があります。これらの扱いにくい点は、主に、完全なUnicode標準と、歴史的なテキスト表現やパフォーマンス・メモリ使用量との対立に関係しています。

## Unicodeの問題点

文字列を扱うときは、[`System.String`][System-string]のライブラリメソッドが利用できるなら、文字列を文字に分解するのではなく、それらのメソッドを探して使うようにしましょう。

テキスト上の「文字」の中には、Unicode標準が65536を超えるコードポイントを持つため、複数の`char`でできているものがあります。たとえば、いくつかのテストに出てくる絵文字は、[サロゲート][surrogates]文字で構成されているため、2つの`char`からなります。

さらに、結合シーケンスというものもあります。たとえば、アクセント付きの文字が、基本の文字を表す`char`1つと、アクセントを表す別の`char`1つで構成されることがあります。

個々の文字を扱わなければならない場合は、ある文字が'0'と'9'の間にあるかどうかを調べるような素朴な比較をするのではなく、[`System.Char.IsControl`][is-control]や[`System.Char.IsDigit`][is-digit]などのライブラリメソッドを使うようにしましょう。

たとえば、'٢'はアラビア語の数字の2であることに注意してください。`IsDigit`はアラビア語版に対してもtrueを返すので、検証するときには、どの範囲の入力を許容するのかを明確にする必要があります。

あまり知られていない言語を扱っているときには、`System.Char`のライブラリメソッドでさえ、期待どおりに動作しないことがあります。

文字列を表示上の「文字」に安全に分解する方法の1つは、[`StringInfo`][string-info]と[`GetNexttextElement`][get-next-text-element]などのメソッドを使うことです。
グローバリゼーションやローカライゼーションを扱う場合には、これが必要になることがあります。

Unicode文字のスカラー値が重要になる別の場面（たとえば、独自のエンコード方式を作る場合）では、[runes][runes]を使うという手があります。ただし、扱う文字の範囲にサロゲートや結合文字シーケンスが含まれないとわかっていて（例：ラテン文字のASCII）、入力が十分に検証されているなら、これを避けられます。

繰り返しになりますが、`String`のライブラリメソッドを使えるのがいちばんよい状況です。

Unicodeの細かい話を扱うという厄介な立場に立たされたときは、[こちら][char-encoding-net]がよい出発点になります。

## グローバリゼーション

複数のカルチャを扱う環境で作業していたり、コードの一部ではカルチャが重要だが他の部分では重要でないという場合には、カルチャを受け取る[`ToUpper`][to-upper]と[`ToLower`][to-lower]のオーバーロード、そして現在の[カルチャ][culture-info]に関係なく一貫した結果を返す[`ToUpperInvariant`][to-upper-invariant]と[`ToLowerInvariant`][to-lower-invariant]に注意してください。
