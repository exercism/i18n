# 概要

Gleamでは、`case`式を使って条件に応じてコードを実行できます。`case`式を使うと、ある値を1つ以上の_パターン_と照らし合わせて検査できます。そうしたパターンの1つが_リテラルパターン_で、値をリテラル値（たとえば`1`や`"hello"`）と照合するパターンです。

`case`式は、`case`キーワードを使って書きます。

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    1 -> "One"
  }
}
```

他の言語の`switch`文と似ているように見えるかもしれませんが、パターンマッチングの真価は、ほかのパターンも組み合わせたときに発揮されます。その1つが_変数パターン_で、これを使うと値を変数に割り当てられます。次の例では、`number`が`0`でなければ、変数`i`に`number`の値が割り当てられます。

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i -> "Non zero"
  }
}
```

パターンにさらに条件を追加したい場合もあります。これは_ガード_（ガード節）と呼ばれ、`if`キーワードを使って追加できます。

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
  }
}
```

パフォーマンス上の理由から、ガードで使えるのは基本的な算術演算子と真偽値演算子だけで、ほかの関数は使えません。

上の例では、取りうる入力のすべてに一致するパターンがあるわけではありません。コンパイラーがこれを検出し、エラーを出力します。これを_網羅性チェック_と呼びます。この警告を解消するには、すべてのケースに対応する必要があります。そこで使えるのが_ワイルドカードパターン_で、これはどの値にも一致するパターンです。

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
    _ -> "Positive number"
  }
}

// No compiler error
```

`case`式は、上から順に値を各パターンと照合し、一致するパターンが見つかると、そのパターンに対応する処理を実行します。パターンの順番は重要です！
