# 概要

`Maybe`型は、Elm言語で省略可能な値を扱うための解決策です。
そのため、Elmの数多くのコア関数の型シグネチャに登場しており、これを理解することは欠かせません。

## 定義と型変数

`Maybe`型は次のように定義されています。

```elm
type Maybe a = Nothing | Just a
```

これはElmの用語で「カスタム型」定義と呼ばれます。
カスタム型については、このトラックの別の概念で詳しく紹介されますが、`Maybe`そのものを理解するのに必要ではありません。
`Maybe a`と`Just a`の`a`は型変数を表し、`Int`、`Bool`、`String`など、どんな型でもよいという意味です。
つまり、`Maybe String`は`String`を省略可能で保持する変数で、`Maybe Int`は`Int`を省略可能で保持します。

```elm
name : Maybe String
name = Just "Matthieu"

age : Maybe Int
age = Just 29
```

`Maybe`の型定義にある縦棒`|`は「または」を意味します。
この型の値は、`Nothing`であるか、型`a`の何かを持つ`Just`であるかの、どちらかであることを示しています。
では、名前と年齢がその人によって入力されなかったとすると、次のようになります。

```elm
name : Maybe String
name = Nothing

age : Maybe Int
age = Nothing
```

## Maybe値の中身を読む

`Maybe`値の中身を読むには「パターンマッチング」を行います。
パターンマッチングも別の概念で詳しく紹介されるので、ここでは`Maybe`のパターンマッチングがどのように働くかに絞って見ていきます。

```elm
-- This function returns "Hello, <name>!" if the name was provided.
-- Otherwise, it just says "Hello, World!".
sayHello : Maybe String -> String
sayHello maybeName =
    case maybeName of
        Nothing -> "Hello, World!"
        Just someName -> "Hello, " ++ someName ++ "!"

sayHello (Just "Matthieu")
    --> "Hello, Matthieu!"

sayHello Nothing
    --> "Hello, World!"
```

`Maybe`値を使うたびに、Elmコンパイラーはコードがすべての可能性を扱っているかをチェックします。そのため、`Maybe`をパターンマッチングして`Just someValue`の場合だけを扱う、ということはできません。
これは最初は面倒に感じるかもしれませんが、Elm言語の最大の強みの一つです。
これにより何百ものバグを防ぐことができ、コンパイラーに導かれたリファクタリングは、恐れることなく、やりがいのあるものになります。

## Maybeを操作するその他の関数

`Maybe`型を操作するための便利な関数も、`Maybe`モジュールに数多く用意されています。

```elm
sayHelloAgain : Maybe String -> String
sayHelloAgain name = "Hello, " ++ Maybe.withDefault "World" name ++ "!"

capitalizeName : Maybe String -> Maybe String
capitalizeName name = Maybe.map String.toUpper name

capitalizeName matthieu
    --> Just "MATTHIEU"

capitalizeName anon
    --> Nothing
```
