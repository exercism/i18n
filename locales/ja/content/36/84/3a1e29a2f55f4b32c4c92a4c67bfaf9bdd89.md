# 概要

## 部分適用

Elmのすべての関数は[カリー化][currying]されています。つまり、すべての引数を渡さずに関数を呼び出すと、新しい関数が返ります。

この結果を[部分適用][partial-application]と呼びます（関数にすべての引数を渡すのではなく、一部の引数だけを部分的に適用しているのです）。

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

部分適用では、常に引数が順番に適用されます。

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## パイプ演算子（`|>`）

`x |> f`は`f x`とまったく同じです。具体的な例では、`"5" |> String.toInt`は`String.toInt "5"`と同じです。

一見するとそれほど役に立つようには思えませんが、「パイプライン」のようなコードを書けるようにしてくれるので、これは[パイプ演算子][pipe-operator]と呼ばれます。

たとえば、ユーザーの入力を整数に変換する`sanitize`関数があるとします。

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

これは次のように書き換えられます。

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

これにより括弧（`()`）を使わずに済み、関数が適用される順番（最初に`String.trim`、次に`String.toInt`）どおりに関数が並ぶので、読みやすくなります。

[逆パイプ演算子`(<|)`][reverse-pipe-operator]もあります。`x <| f`は`f x`とまったく同じです。これも一見するとあまり役に立つようには見えませんし、パイプ演算子ほど使われることはありませんが、状況によっては括弧を避けるのに役立ちます。

## 関数合成とポイントフリースタイル

[`(>>)`][forward-composition]演算子は`(a -> b) -> (b -> c) -> (a -> c)`という型を持ち、`a -> b `と`b -> c`という型の互換性のある2つの関数を合成して、`a -> c`という型の関数を作ります。これは、1つ目の関数の出力（型は`b`）を取り、それを2つ目の関数（同じく型`b`でなければなりません）の最初の引数として使うことで行います。作られる関数は、1つ目の関数と同じ入力（型は`a`）を受け取り、2つ目の関数が返す`c`をそのまま返します。

具体的な例は`String.trim >> String.toInt`です。`String.trim`は文字列を唯一の仮引数として受け取るので、作られる関数もそれを受け取ります。`String.toInt`は`Maybe Int`を返すので、作られる関数もそれを返します。`String.trim`は`String`を返し、それを`String.toInt`が仮引数として受け取れるので、この例はコンパイルできます。

ここで、`sanitize`関数を次のように書き換えられます。

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

元の例で見られる`input`仮引数を使っていないことに注目してください。機能はまったく同じですが。このように、仮引数に一切言及せずに関数を作る書き方を「ポイントフリースタイル」と呼びます。このスタイルの利点はコードがより簡潔になることで、欠点は、とくに初心者にとって理解しづらくなることがあります。

Elmではすべての関数がカリー化されていることを覚えておくとよいでしょう。そのため`String.length >> max`はコンパイルでき、次のようになります。

- 文字列の仮引数（`String.length`への入力）を持つ関数（1）
- `max`は2つの`Int`を仮引数に持つ関数ですが、関数1はそれに1つの`Int`（`String.length`の戻り値）を渡すので、`max`は部分適用されます。
- 部分適用された`max`関数の戻り値は、`Int`を受け取り、この`Int`と`String.length`から部分適用された`Int`のうち大きい方を返す、別の関数（2）です。
- したがって、関数1（`String -> Int`）は関数2（`Int -> Int`）を返します。
- つまり`((String.length >> max) "123") 2`は`3`を返します。`"123"`の長さは3で、`Int`の引数である2より大きいからです。

## 関数の設計

Elmでエレガントなコードを書きやすくするには、主要なデータ構造を関数の最後の仮引数にするとよいでしょう。標準ライブラリにある一般的な関数は、`List.map`（型シグネチャーは下記）のように、すべてこのようにしています。

```elm
map : (a -> b) -> List a -> List b
```

ここでは、`map`関数の最後の仮引数が`List a`で、`List b`を返すことがわかります。つまり、主要なデータ構造である`List`が最後の仮引数になっています。

これにより、次のようなエレガントなパイプラインコードを書けるようになります。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

また、パイプラインの代わりに、関数合成とポイントフリースタイルを使うのも便利になります。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

関数合成を使えば、この例を`List.map`の1回の呼び出しにまとめることもできます。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
