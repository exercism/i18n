# テスト

各演習には、単体テストとCMakeのビルドレシピが用意されています。実装を書くのは皆さんです。
各テストファイルは、皆さんの実装とリンクして、テストを実行するコンソール実行ファイルを作ることを想定しています。テスト実行ファイルを実行すると、失敗したテストごとにメッセージが表示され、テストが失敗したときには非ゼロの終了ステータスが報告されます。

テストファイルの名前は`<exercise>_test.f90`になります。たとえば演習「Bob」なら、テストが入っているファイルは`bob_test.f90`です。各テストには、そのテストの説明を書いたコメントがあり、そのあとに`call assert_equal`で始まる実際のテストが続きます。たとえば次のとおりです。

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

テストを無効にするには、`'!'`でコメントアウトするだけです。たとえば次のとおりです。

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

各演習を進める流れは、次のとおりです。

* CMakeで最初のビルドを作成する
* 各単体テストごとに、次のことを行う
 * テストが失敗するように、コンパイルエラーを解消する
 * テストが通るのに必要な分だけ実装する
 * 読みやすさを高めたり、重複を減らしたりするために、実装をリファクタリングする
 * 次のテストのコメントを解除する


## CMakeで最初のビルドを作成する

各演習には、単体テストと一緒に`CMakeLists.txt`ファイルが付いてきます。このファイルには、ビルドを処理してくれる定型のCMakeレシピが入っています。このファイルを編集する必要はないはずです。用意されたレシピは、実装が演習名と同じ名前のソースファイルにあることを前提としています。

たとえば、演習「Bob」では`bob.f90`ファイルに実装があることを想定しています。

**CMakeを実行する前に、最初の実装ファイルを作成してください。**
演習「Bob」でCMakeを実行するときに`bob.f90`ファイルがないと、CMakeはファイルが見つからないというエラーを出します。
**これらのファイルは空でもかまいませんが、存在している必要があります。**

このレシピを使うと、適切なジェネレーターと演習のディレクトリの場所を指定して`cmake -G`を実行することで、CMakeが環境に合ったプロジェクトを生成できます。CMakeは、お使いのオペレーティングシステムに適したビルドスクリプトを生成します。生成されたファイルを演習のソースコードと分けておくために、生成されたビルドファイルとコンパイル済みのコードを入れる`build`というディレクトリを作るのが一般的です。

こうすると、演習のフォルダーをすっきりと整理された状態に保てます。

**Note: `cmake`を初めて呼び出すときは、[testlib](###-Testlib)が自動的にダウンロードされます。単体テストを動かすには`testlib`が必要です。

各課題のためにビルド手順を作るのにCMakeを実行することになるので、このコマンド用にbashスクリプト（Linux/MacOS）やバッチファイル（Windows）を作っておくとよいでしょう。

CMakeがビルド環境を作成したら、環境に合ったコマンドでコードをビルドできます。

* Linuxでmakeの場合：`make`
* WindowsでVisual Studioの場合：メニューからBuild / Build Solutionを選択します。
* WindowsでMingWの場合：`mingw32-make.exe`
* WindowsでnMakeの場合：`nmake.exe`
* MacOSでXcodeの場合：ツールバーからBuildを選択します。

さまざまな環境でCMakeを実行する例を以下に示します。

### Linux\MacOSでMakeを使う場合

CMakeのジェネレーター名は`Unix Makefiles`です。
現在の演習が`bob`で、演習のフォルダーにいるとします。

```
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

この例では、CMakeを実行する前に実装用の空ファイルを作成しています。

ビルドディレクトリでmakeと入力するだけで、テストがコンパイルされます。ここでコンパイル時のエラーが出るはずです。エラーを直したら、もう一度`make`を実行します。ビルドのエラーがすべて解消したら、テストを実行します。

```
$ ctest -V
```
### WindowsでVisual Studio 2017を使う場合

CMakeのジェネレーター名は`Visual Studio 15`です。このジェネレーターは、Visual Studio 2017のすべてのIDEエディション（Community、Professional、Enterprise）をサポートしています。現在の演習が`bob`で、演習のフォルダーにいるとします。

```
> copy nul: bob.f90
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

この例では、CMakeを実行する前に実装用の空ファイルを作成しています。

### Testlib

テストは、cmakeでビルドを最初に設定するときにgithubからダウンロードされる`testlib`という小さなライブラリに依存しています。

ダウンロードが失敗した場合は、手動でダウンロードすることもできます。たとえば次のとおりです。

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/TesterMain.f90
```
