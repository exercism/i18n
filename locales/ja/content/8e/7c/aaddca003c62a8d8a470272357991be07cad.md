# Cスタイルガイド

このガイドでは、Cトラックの演習のサンプル実装ファイルとテストファイルで使うことを想定したスタイルについて説明します。

このガイドに書かれているルールは、[.clang-format][]ファイルで定められているルールに追加するもの、またはそれらを明確にするためのものです。

## C標準

コードは、より正式にはISO/IEC 9899:1999として知られるC99標準に準拠させます。
POSIX、またはそれ以外の非標準のライブラリ関数や型など、実装の外部にあるものを参照するものは使用しません。

## 名前

一般的に、型や変数、構造体、ファイルの名前にはスネークケースを使い、すべて小文字で書きます。名前の要素はアンダースコア`_`で区切ります。

```c
void some_foo_function(char * input_string, int input_string_length);
```

### 列挙型

列挙型の名前は、通常は複数形ではなく単数形にします。

列挙子は、すべて大文字のスネークケースで書きます。

```c
enum heading {
    HEADING_NORTH,
    HEADING_EAST,
    HEADING_SOUTH,
    HEADING_WEST
}
```

### マクロ

定数を定義するマクロは、すべて大文字のスネークケースで名前を付けます。

```c
#define CONSTANT 0x4000
```

マクロ名に大文字のスネークケースを使うと好ましいですが、関数に似たマクロには小文字のスネークケースで名前を付けてもかまいません。

### 型

基本の整数型よりも、標準の固定幅型（`stdint.h`）を優先します。

`_Bool`よりも、型`bool`（`stdbool.h`）を優先します。

同様に、メモリに関わる量を表すときは`size_t`と`ptrdiff_t`（`stddef.h`）を優先します。

プログラムが`typedef`で定義する型の名前には、`_t`という接尾辞を付けます。
POSIXが`_t`という接尾辞を予約していることは承知していますが、現在このトラックではPOSIXを使っていません。

## インクルードガード

インクルードガードは、すべてのヘッダーファイルで使います。

通常は、ヘッダーの内容全体を1組のインクルードガードで囲みます。

サンプル実装（`.meta/example.h`）と演習のスタブ（`exercise_name.h`）のガードには、演習名に合わせたマクロ名を使います。
ガードのマクロ名は、マクロの大文字・小文字に関する上記のルールに従います。

たとえば、演習`hello-world`では、次のようにします。

```c
#ifndef HELLO_WORLD_H
#define HELLO_WORLD_H

//...

#endif
```

## 仮引数

関数の仮引数には、すべての関数で宣言と定義の両方で名前を付けます。
これは`.c`ファイルと`.h`ファイルの両方に当てはまります。
使う名前は、どの箇所でも一致させます。
つまり、次の関数プロトタイプはCとしては有効ですが、仮引数に名前がないため、このスタイルは正しくありません。`void foo(int);`
ほかのすべての宣言と定義でも仮引数名`bar`を使う場合、正しいプロトタイプは`void foo(int bar);`です。

よりシンプル、またはより適切な場合は、ポインタではなく値で引数を渡す仮引数を優先します。
特に、これには`struct`型の仮引数も含まれることに注意してください。

学習者が自分の実装の中でポインタ型の仮引数の値を変更する必要がない場合は、その仮引数に`const`を付けます。

## テストファイルのレイアウト

各演習のテストファイルは、決まったレイアウトに従います。
このレイアウトは、コントリビューターがファイルの各部分を見分けやすくすることと、学習者がテストの仕組みを理解しやすくすることを目的としています。

ほとんどのCのソースファイルと同じように、テストファイルはインクルードから始まります。

```c
#include "vendor/unity.h"
#include "../src/file_under_test.h"
// any other includes here
```

インクルードの次に、`setUp()`と`tearDown()`の関数が来ます。
現時点では、これらを使っている演習はありません（関数の中身は空です）が、すべてのプラットフォームでテストファイルが正しくコンパイルされるように、これらはそのまま残しておく必要があります。

```c
void setUp(void)
{
}

void tearDown(void)
{
}
```

次に、テスト関数から使われるヘルパー関数があれば置きます。
こうしたヘルパー関数の名前には、`test_`という接頭辞を付けません。

その次が、テスト関数そのものです。
これらの関数の名前には、`test_`という接頭辞を付けます。
最初のテスト関数を除き、各テスト関数の最初の文は`TEST_IGNORE();`にします。
最初にこれが出てきたときは、その後ろに`// delete this line to run test`という行コメントを付けます。

たとえば、次のようになります。

```c
static void test_the_first(void)
{
   test_first_foo();
}

static void test_the_second(void)
{
   TEST_IGNORE();               // delete this line to run test
   test_second_foo();
}

static void test_the_third(void)
{
   TEST_IGNORE();
   char grade = 'A';
   test_third_foo(grade);
}
```

ファイルの最後は`main()`関数です。
mainの関数本体も、決まったレイアウトに従います。
まず`UNITY_BEGIN()`の呼び出しがあり、その後に空行を挟んで、テストが続きます。
最後のテストの後にもう1行空行を挟んでから、`UNITY_END()`の結果を返します。

```c
int main(void)
{
    UNITY_BEGIN();

    RUN_TEST(test_foo);
    RUN_TEST(test_bar);

    return UNITY_END();
}
```
