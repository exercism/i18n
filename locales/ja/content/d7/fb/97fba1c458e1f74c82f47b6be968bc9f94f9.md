# はじめに

ほとんどのスカラーなビット単位演算には、パック版があります。
SIMD整数演算と同じ一般的な構文に従いますが、サイズ接尾辞はありません。

| 命令 | 説明 |
|-------------|-----------------------------------|
| `pand`      | 2つの128ビット値のビット単位AND |
| `por`       | 2つの128ビット値のビット単位OR  |
| `pxor`      | 2つの128ビット値のビット単位XOR |

パック版の`NOT`は存在しません。
ただし、ANDN命令があり、これは**デスティネーション**オペランドを補数（すべてのビットを反転）にしてから、両方のオペランドのANDを計算します。
NOTとANDを組み合わせたものと考えるとよいでしょう。

| 命令 | 説明 |
|-------------|-----------------------------------------------------------------|
| `pandn`     | **補数化された**デスティネーションとソースのビット単位AND |

ビット単位の演算は、2つの異なるオペランドの同じ位置にあるビットを組み合わせます。そのため、レーン境界が結果を変えることはありません。
だからこそ、これらの命令にはサイズ接尾辞がなく、レジスタは1つの128ビットレーンとして振る舞います。

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
このコンセプトのどの命令も、ビットを計算しますが、フラグは設定しません。
パック値を使った条件分岐については、後のコンセプトで扱います。
~~~~

## レーンごとのシフト

シフトは、純粋なビット単位演算とは違い、ビットを実際に異なる位置へ移動させます。そのため、境界を決めるためのレーンサイズが必要です。
各レーンの中ではスカラーの対応命令と同じように振る舞い、ビットが隣のレーンへ移動することはありません。

| 命令               | 説明                         |
|---------------------------|-------------------------------------|
| `psllw`、`pslld`、`psllq` | レーンごとの論理左シフト        |
| `psrlw`、`psrld`、`psrlq` | レーンごとの論理右シフト       |
| `psraw`、`psrad`          | レーンごとの算術右シフト    |

これらの命令は、パック整数演算の構文に従い、サイズ接尾辞も付きます。
バイト幅のレーンのシフトはなく、ワード、dword、そして算術右シフトを例外としてqwordのみです。

パックシフトとスカラー版の違いのひとつは、演算の名前です。

- `shl`と`shr`の代わりに、`sll`と`srl`があります。これは**s**hift **l**eft（**r**ight）**l**ogicalの略です。
- `sar`の代わりに、`sra`があります。これは**s**hift **r**ight **a**rithmeticの略です。

名前は違いますが、演算自体は同じです。

- 論理右シフトは、最上位ビットを0で埋めます。
  これは、2のべき乗による符号なし除算と同じ結果になります。
- 算術右シフトは、最上位ビットを符号ビットの値で埋めます。
  これは、負の無限大方向に丸める、2のべき乗による符号付き除算と同じ結果になります。
- 左シフトは常に0で埋めます（算術左シフトが不要なのはこのためです）。

シフト量はすべてのレーンで同じです。
即値か、`xmm`レジスタの下位64ビットを指定できます。

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
レーン幅より大きいシフト量は、スカラーの`shl`/`shr`系のように巡回しません。
単に0になります（算術右シフトの場合は、すべての符号ビットになります）。
~~~~

## 浮動小数点数のビット単位演算

各ビット単位命令には、浮動小数点向けの名前を持つ対になる命令もあり、パック浮動小数点演算で見てきたのと同じ構文に従います。

| 整数命令名 | 浮動小数点命令名          |
|--------------|----------------------|
| `pand`       | `andps`、`andpd`     |
| `pandn`      | `andnps`、`andnpd`   |
| `por`        | `orps`、`orpd`       |
| `pxor`       | `xorps`、`xorpd`     |

ビット単位演算はビットに対して作用するので、実際には整数演算と浮動小数点演算は同じ結果を計算します。
名前が違うのには、2つの理由があります。

1. 意図を文書化するためです。コピーするバイトの性質に応じて`movdqa`、`movaps`、`movapd`を使い分けるのと同じ考え方です。
2. 整数演算と浮動小数点演算は、しばしば異なる実行ドメインを持ちます。
   同じ実行ドメイン内の演算は、通常より速く連続実行できます。

浮動小数点値にはシフト演算がありません。

## 浮動小数点数のビット表現

IEEE浮動小数点数は、整数とは大きく異なるビット表現を持ちます。

符号なし整数では、各ビットの意味は一様です。ビットは、その位置（インデックス）に対応する2のべき乗を表します。
整数は、1になっているビットに対応する2のべき乗の合計です。
ビットをシフトすると数値を2のべき乗で掛けたり割ったりできるのはこのためです。それぞれの1のビットの位置を変えているだけなのです。

符号付き整数では、ほとんどのビットは符号なし整数と同じように解釈されます。
ただし、最上位ビットは特別です。
このビットが1の場合、他のビットに足すのではなく、対応する2のべき乗を引くことになり、結果は負の数になります。
実際に数の符号を変えるには、概念的には2つの手順が必要です。すべてのビットを反転し（`not`）、その結果に1を足す（`inc`）のです。

浮動小数点数のビットは一様な意味を持たず、位置に応じてまったく異なる解釈が必要です。

| フィールド    | 位置（32ビット） | 位置（64ビット） |
|----------|------------------|------------------|
| 符号     | 31               | 63               |
| 指数 | 30-23            | 62-52            |
| 仮数 | 22-0             | 51-0             |

結果の数値は`(-1)^sign * 1.fraction * 2^(exponent - bias)`で計算されます。
バイアスは精度によって変わります。

| サイズ   | バイアス |
|--------|------|
| 32ビット | 127  |
| 64ビット | 1023 |

どちらの形式でも、数値の符号は符号ビットだけで決まります。
浮動小数点数の符号を変えるには、このビットを反転するだけです（XOR演算）。
絶対値を得るには、このビットをクリアするだけです（そのビットを0にするAND）。

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

このビット表現では、ビットをシフトしても予測可能で一様な結果にはなりません。
仮数が指数へ、指数が符号へと「こぼれ出す」ことがあります。

しかし、表現の各部分を分離して操作すると便利なこともあります。

たとえば、指数のビットは、バイアスを引く前に、まず符号なしの数値として解釈する必要があります。
つまり、対応する浮動小数点形式のある2のべき乗に対応するビット表現を持つ、32ビットまたは64ビットの整数を作れるということです。
そして、この生のビット表現を使って、別の浮動小数点数を掛けたり割ったりできます。

たとえば、次のようになります。

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

逆に、指数ビットを1、それ以外を0にしたマスクとのANDを取ることで、パック浮動小数点数の指数を取り出せます。
シフトと減算を組み合わせれば、各レーンのバイアスを除いた指数を符号付き整数として得られます。

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
浮動小数点数の生のビットを操作することは、状況によっては便利ですが、注意して行うべきです。
指数フィールドに加算や減算をするのは、オーバーフローやアンダーフローがなく、入力が正規化数である場合にのみ安全です。
また、`0.0`の指数フィールドに有効な`x`を足すと、`0.0 * 2^x`ではなく`2^(x - bias)`になります。
~~~~
