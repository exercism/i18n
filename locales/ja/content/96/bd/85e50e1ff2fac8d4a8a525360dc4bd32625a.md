# はじめに

理想的な世界では、すべてがきちんと定義され、具体的な値が入っていて抜けがないはずです。

これは日常の経験とは食い違います。そのため、多くのプログラミング言語には、値がないことを表す方法があります。nullやNULL、nil、None、nothingなどです。

これは導入するのは簡単でした（1965年のことです）が、すぐに後悔につながりました。
発明者は後に、これを「10億ドルの過ち」と呼びました。

ここ数十年、言語の設計者たちは、nullを利用できるようにしつつ（ほとんどは）安全にする、多くの方法を模索してきました。

Kotlinには、Javaとは大きく異なる[一般原則][ref-null-safety]がいくつかあります。


- Kotlinには特別な`null`値があります。
- すべての型は、_既定で_ null非許容です。
- ほとんどの型は_あとから_ null許容にできますが、プログラマーが明示的にそう指定しなければなりません。
- 例外で失敗する可能性のある関数には、null許容の戻り値を持つ別バージョンが用意されていることがよくあります。
- 特別な、きわめて簡潔な構文によって、nullかどうかの確認とnullへの対応をできるだけ簡単にしようとしています。

## null許容変数を作る

標準的な型には、ふつう`?`を付けたnull許容版があります。たとえば`String`の代わりに`String?`です。

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## 便利な演算子と関数

### 安全呼び出し演算子`?.`

null非許容の`String`では、`.length`プロパティを取得できます。

null許容の`String?`では同じ構文は失敗しますが、`?.length`を使えば`null`の可能性に対応できます。
戻り値の型は`Int?`です。

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

上の最後の行で見たように、`?.`はnull非許容の型でも使えます。

### エルビス演算子`?:`

安全呼び出し演算子の考え方を広げたのが[エルビス演算子][wiki-elvis]で、`null`の代わりになる既定値を指定できます。

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### 非nullアサーション演算子`!!`

この演算子を使うと、プログラマーが確信しているとき、null許容の型を強制的にnull非許容として扱えます。
ときには、慎重すぎるコンパイラーよりも、プログラムのロジックをよく理解していることもあるのではないでしょうか？

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

あとは自己責任です。`b`がまだ`null`なら、`NullPointerException`が発生します。

### let関数`?.let`

null許容の値をコードのブロックに渡すなら、`if (item != null) { do something }`のように個別にnullチェックをすることもできます。

`item?.let { do something }`を使うほうが、より簡単でより慣用的です。
`do something`は、`item`がnullでないときだけ実行されます。

### `somethingOrNone()`型の関数

一部の関数は失敗することがあります。たとえば、文字列や配列で無効なインデックスを指定したときです。

例外を投げる代わりに、関数の`...OrNull`版を使って、（この場合は）`Int?`の戻り値を得ることもできます。

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
