# 概要

## オプショナル

Swiftでは、値が存在しない可能性を表すために[_オプショナル_][optionals]を使います。
オプショナルは、値を保持するか、値の不在を表す[`nil`][nil]であるかのどちらかになる型です。
オプショナルを使うには、値が存在するかどうかを確認し、アンラップしてから使う必要があります。

型名の末尾に`?`を付けると、どんな型でもオプショナルにできます。
たとえば、整数のオプショナルは`Int?`型、文字列のオプショナルは`String?`型になります。
オプショナル型の定数や変数を定義して値を代入する方法は、非オプショナル型の値の場合と同じです。

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

オプショナル型の変数に値の不在を表すには、特別な値`nil`を代入します。
`nil`はすべてのオプショナル型で使えますが、異なる2つのオプショナル型に代入された`nil`は同じ型ではなく、互換性がなく、比較することもできません。

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

また、`nil`はどんなオプショナル型にも代入できますが、非オプショナル型には代入できません（実際に`nil`を保持していない場合でも同じです）。
そして、非オプショナル型を期待するメソッドには、先にアンラップしなければオプショナル型を渡せません。

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## オプショナルの使い方

オプショナル型は基になる型と同じ型ではないため、この2つの型を同じようには使えません。
たとえば、`Int("123") + 1`と書くと、コンパイラエラー"Value of optional type 'Int?' must be unwrapped to a value of type 'Int'"になります。
これは、文字列を整数に変換できない場合に結果が`nil`になるため、`Int("123")`が`Int`型ではなくオプショナルの`Int?`型を返すからです。
変換で得られる`Int`にアクセスするには、まず「アンラップ」する必要があります。

Swiftでは、[_オプショナルバインディング_][optional-binding]の`if-let`構文や`guard-let`構文を使ってこれを行うのが一般的です。
これらの構文は`nil`かどうかを確認し、値が存在すればアンラップした値を指定した名前に束縛して一方のコードパスを実行し、`nil`だった場合はもう一方のコードパスを実行します。

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

`safeNum`変数は`Int?`ではなく`Int`型である点に注目してください。
次の例では、`num`は`Int?`型、`safeNum`は`Int`型です。

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

この_オプショナルバインディング_は重要です。
値からオプショナル型をアンラップ（「取り除く」）して、非オプショナルな値として使えるようにするからです。
単に値が`nil`かどうかの条件チェックだけを行うと、値は依然としてオプショナル型のままです。

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

早期リターンを行いたい場合には、`guard-let`を使うこともできます。

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## オプショナルの比較

2つのオプショナルの基になる型が標準の比較演算子で比較できたとしても、オプショナル自体は比較できません。
できるのは、等しいかどうかの確認だけです。
2つのオプショナルは、どちらも`nil`であるか、ラップしている値が基になる型で等しい場合に等しいとみなされます。

ただし、2つのオプショナル値を独自に比較するコードを書くことはできます。
以下は、両方のオプショナル値が非nilで、かつ最初の値が2番目の値より小さい場合にのみ`true`を返す`switch`文の例です。
これを実現するために、_オプショナルパターン_`varName?`を使います。
これは非nilのオプショナルにのみマッチし、オプショナル内の値を`varName`という名前に束縛します。

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## nil合体演算子

`nil`の場合に[フォールバック値][fallback]を使える、もうひとつのアンラップ方法があります。
これは_nil合体演算子_`??`を使うと行えます。
`x`が`Int?`であるとします。
`let y = x ?? 0`と書くと、Swiftはxが`nil`かどうかを確認します。
`nil`でなければ、`x`をアンラップしてその値を`y`に代入し、`x`が_nil_の場合は`y`に0を代入します。

`x ?? y`は`x != nil ? x! : y`を簡単に書いたものにすぎず、`x`がnilでなければ、式`y`はまったく評価されません。

最後に、nil合体演算子は右結合であるため、知らない人には意外な結果をもたらすことがある点に注意してください。

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

nil合体演算子についてさらに詳しくは、[Swiftツアー: nil合体演算子][nil-coalescing]を参照してください。
