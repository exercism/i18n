# インストラクションの補足

## Pythonでのこの演習の構成

月の第5曜日がある場合のために、追加の週指定子（`fifth`）を用意しました。  
その月に第5曜日がなければ、例外を送出してください。

## 例外のカスタマイズと送出

コードの中で例外を[カスタマイズ](https://docs.python.org/3/tutorial/errors.html#user-defined-exceptions)したり[`raise`](https://docs.python.org/3/tutorial/errors.html#raising-exceptions)したりする必要があることがあります。その際は、エラーの原因が何であるかを示す**意味のあるエラーメッセージ**を必ず含めてください。そうすることでコードが読みやすくなり、デバッグも格段にしやすくなります。

カスタム例外は、新しい例外クラスを作ることで作成できます（詳しくは[`classes`](https://docs.python.org/3/tutorial/classes.html#tut-classes)を参照してください）。こうしたクラスは通常、[`Exception`](https://docs.python.org/3/library/exceptions.html#Exception)のサブクラスです。

エラーの原因が特定の例外型から派生したものであるとわかっている場合は、_Exception_クラスの下にある[`built in error types`](https://docs.python.org/3/library/exceptions.html#base-classes)のいずれかを継承することもできます。エラーを送出するときも、意味のあるメッセージを含めてください。

この演習では、`meetup()`関数に無効な曜日名と数の組み合わせが渡されたときに[送出](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement)（"throw"）される_カスタム例外_を作成する必要があります。テストが通るのは、適切な例外をカスタマイズしてその例外を`raise`し、適切なエラーメッセージを含めた場合だけです。

`built-in exception`をカスタマイズするには、その例外を継承した`class`を作成します。メッセージ付きでカスタム例外を送出するときは、そのメッセージを`exception`型の引数として書きます。

```python
# subclassing the built-in ValueError to create MeetupDayException
class MeetupDayException(ValueError):
    """Exception raised when the Meetup weekday and count do not result in a valid date.

    message: explanation of the error.

    """
    def __init__(self, message):
        self.message = message

        
# raising a MeetupDayException
raise MeetupDayException("That day does not exist.")
```
