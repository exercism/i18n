# Docker

アナライザーはDockerイメージとしてデプロイされています。

これらがどのように動作するのかを知るために、[ツールのDockerに関する一般的な情報](/docs/building/tooling/docker)に目を通してください。

## 連携

解答を解析するためにアナライザーを実行するときは、次のようなDockerコマンドを実行します。

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-analyzer" \
        "${exercise_slug}" "/solution" "/output"
```

Dockerイメージには3つの引数を渡しているのがわかります。

1. 演習のスラッグ
2. 解答のディレクトリのパス
3. 出力ディレクトリのパス

## 規約

すべてのアナライザーは、実装において次の規約に従います。

- `Dockerfile`はリポジトリのルートディレクトリにあります。
- 作業ディレクトリは`/opt/analyzer`にします。
- エントリーポイントは`/opt/analyzer/bin/run.sh`です。
- `/opt/analyzer/bin/run.sh`スクリプトは3つの引数を受け取ります。
  1. 演習のスラッグ
  2. 解答のディレクトリのパス
  3. 出力ディレクトリのパス

詳しくは[インターフェース](/docs/building/tooling/analyzer/interface)を参照してください。

```exercism/note
新しいアナライザーのリポジトリは、デフォルトでこれらの規約を使用します。
```
