# 条件文について

## Bashにおける真偽

Bashには真偽値という概念がありません。
あるのは文字列と数値、そして文字列や数値の配列です。
では、条件を扱うコマンドは、どのようにして真と偽を判断するのでしょうか。

## 終了ステータス

コマンドは終了するときに_終了ステータス_を返します。
終了ステータスは0以上255以下の整数です。
Bashは**ゼロ**の終了ステータスを_成功_とみなします。
それ以外の終了ステータスは_失敗_を表します。

これは、bashの組み込みコマンド、キーワード、関数を含む、すべてのコマンドに当てはまります。

## `if`コマンド

`if`コマンドの基本的な構文は次のとおりです。

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

`if`で始まり、条件のコマンドと「成功」時のコマンドは`then`で区切られ、`fi`で終わります。
`else`節は省略できます。

CONDITIONAL_COMMANDSは、単一のコマンドでも、[コマンドのリスト][command-list]でもかまいません。

CONDITIONAL_COMMANDSが実行され、次のようになります。

* 終了ステータスがゼロ（成功）なら、TRUE_COMMANDSが実行されます。
* 終了ステータスが非ゼロ（失敗）なら、FALSE_COMMANDSがあれば実行されます。

`elif`を使うと、分岐を連ねることができます。

```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

`then`、`elif`、`else`、`fi`の前には、セミコロンか改行が必要です。

強調しておくと、流れを制御するのは条件コマンドの**終了ステータス**です。
たとえば、`grep`は一致が見つかれば0を、見つからなければ1を返します。
`-q`オプションは出力を抑え、終了ステータスだけを返します。

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## `[`と`test`コマンド

CONDITIONAL_COMMANDSの周りに特別な構文はありません。
次のようなif文に見覚えがあるかもしれません。

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

`[`は特別な構文ではありません。
条件式を評価し、成功か失敗のステータスで終了する_コマンド_です。
すべてのコマンドと同様に、これと引数の間には空白が**必要**です。

`[`は実際には`test`コマンドの別名です。
まったく同じものですが、`[`の最後の引数は`]`で_なければなりません_。

### 条件式

`[`と`]`の間には、条件式を書きます。
よくある条件式には、次のようなものがあります。

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

利用できる演算はもっとたくさんあり、マニュアルの[Bashの条件式][cond-expr]の節に一覧があります。

~~~~exercism/note
上の例では、すべての変数が引用符で囲まれていることに注目してください。
`test`と`[`は普通のコマンドで、引数は他のコマンドと同じように単語分割とファイル名展開の対象になります。

これが重要なのは、条件式が、与える_引数の数_によって異なる評価を受けるからです。

* 引数が0個：終了ステータスは非ゼロ（失敗）
* 引数が1個：引数が空でなければ終了ステータスはゼロ（成功）、空なら非ゼロ。
* 引数が2個：最初の引数は単項演算子（`[ -z "$name" ]`など）か、`!`（引数1個のテストのステータスを反転させる）でなければなりません。
* さらに[詳しくはこちら][test]。

引用符を忘れると、予期しない結果になることがあります。

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## `[[`キーワード

[`[[...]]`という条件構文][cond-construct]は_コマンド_ではなく、**キーワード**です。
つまり、他のコマンドと同じように扱われますが、特別な構文解析のルールがあります。
`[[`の特別な点は、その中で展開される変数が、単語分割やファイル名展開の対象に**ならない**ことです。
そのため、このコマンドは引用符を付けなくても、期待どおりに動作します。

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

`[[`は、`test`と`[`が扱えるすべての条件式をサポートします。
さらに、`[[`には次のものがあります。

* `=~`という正規表現マッチングの演算子
* `==`と`!=`がグロブパターンのマッチング演算子として働く
* `&&`と`||`が論理演算子として働く（特別な構文解析ルール）
* `<`と`>`が「そのままの」文字列比較演算子として働く（特別な構文解析ルール：これらはリダイレクト記号なので、`[`ではエスケープしなければなりません）

これらの特別な機能は非常に便利なので、`[[`だけを使うべきだという考えが広く支持されています。
（たとえば、[Google Shell Style Guide][goog-test]を参照してください。）

## `case`コマンド

[`case`][case]も制御フローのコマンドです。
他の言語の「switch」文のようなものです。

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

WORDは、それぞれのPATTERNと照合されます。
どれかが一致すると、そのCOMMANDSが実行されます。

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

各COMMANDS節は、**2つ**のセミコロン`;;`で終わらなければなりません。
