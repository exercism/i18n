# 概要

**浮動小数点数**とは、`-1.23`や`3.1415`のように、小数部分を持てる数値のことです。

このような数値をバイト列として表すために、x86-64では[IEEE-754][ieee]規格を使います。
この規格で最もよく使われる形式は、単精度浮動小数点数と倍精度浮動小数点数です。
x86-64はその両方をサポートしています。

単精度浮動小数点数は32ビット幅で、倍精度は64ビット幅です。

~~~~exercism/note
浮動小数点数は実数全体の近似でしかないため、これを使った演算は正確でない結果になることがあります。

詳しい説明については、OracleのNumerical Computation Guide「What Every Computer Scientist Should Know About Floating-Point Arithmetic」の[付録D][guide]を参照してください。

[Float Toyのページ][toy]では、浮動小数点数のビットが実際の浮動小数点値にどう変換されるかを、図解付きでわかりやすく説明しています。

[guide]: https://docs.oracle.com/cd/E19957-01/806-3568/ncg_goldberg.html

~~~~

## XMMレジスタ

x86-64には、浮動小数点演算を行うための専用レジスタが16個あり、`xmm0`から`xmm15`という名前が付いています。

これらのレジスタは少なくとも128ビット幅ですが、最近のプロセッサーでは256ビットや512ビットに拡張されています。
ただし実際には、必要な精度に応じて、ほとんどの浮動小数点数は下位の32ビットか64ビットしか使いません。

## 数値間の変換

数値の形式を変換するための命令群があります。
それが`cvtxx2yy`です。

`xx`と`yy`はどちらもリテラルではなく、プレースホルダーです。

- `xx`は変換元のオペランドの型を表すプレースホルダーです。
- `yy`は変換先のオペランドの型を表すプレースホルダーです。

このプレースホルダーにはさまざまな形があり、その一部を次に示します。

| プレースホルダー | 意味                  |
| ----------- | --------------------- |
| `si`        | 符号付き整数          |
| `ss`        | 32ビット浮動小数点数  |
| `sd`        | 64ビット浮動小数点数  |

例えば、次のとおりです。

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

32ビット整数を64ビット浮動小数点数に、あるいは64ビット整数を32ビット浮動小数点数に変換できることに注意してください。
同じように、32ビット浮動小数点数を64ビット整数に、64ビット浮動小数点数を32ビット整数に変換することもできます。
つまり、`cvtxx2yy`の2つのオペランドは_同じサイズである必要はありません_。

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

浮動小数点数を整数として正確に表せない場合、`cvtxx2si`は`mxcsr`という特別なレジスタの丸め制御に従って数値を丸めます。
丸め方には、最近接への丸め、切り捨て、切り上げ、ゼロ方向への切り捨てがあります。
関数に入った時点でのデフォルト値は保証されていません。

正確な結果は丸められず、したがって丸め制御の影響も受けないことに注意してください。
例えば、`42.0`は_常に_`42`に変換されます。

似た命令群に`cvttxx2si`（`t`が1つ多い）という形式のものがあり、こちらは常に結果を切り捨てます。

## 丸め

`roundxx`命令群は、変換元のオペランドにある浮動小数点数を丸めた浮動小数点数に変換し、変換先のオペランドに格納します。

ここでも`xx`はオペランドの型を表すプレースホルダーで、`ss`は単精度、`sd`は倍精度の浮動小数点数を意味します。

これらの命令は3番目のオペランドとして定数を取ります。
この数値が丸めモードを指定します。

| 数値 | モード       |
| :----- | :----------- |
| 0      | 最近接       |
| 1      | 切り捨て（下方向） |
| 2      | 切り上げ（上方向） |
| 3      | ゼロ方向への切り捨て |

例えば、次のとおりです。

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

これらの命令は正確な結果を返すので、`cvtxx2si`の前準備として使うことができます。

## 算術命令

浮動小数点数に対する多くの演算には、整数向けの同等の命令とよく似た名前で、末尾に必要なプレースホルダー（`ss`か`sd`）を付けた命令を使います。
掛け算や割り算を行うものも含め、これらの命令は通常の意味論を持つ2オペランド命令です。

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## 移動

XMMレジスタから別のレジスタへ移動する命令は`movss`と`movsd`です。

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

即値（定数の符号付き整数）をxmmレジスタへ直接移動することは**できません**。
この数値はまず汎用レジスタへ移動し、その後`cvtsi2xx`で変換する必要があります。

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## 比較

2つの浮動小数点数を比較する命令には2つのグループがあります。
形式は`comixx`と`ucomixx`で、`xx`は`ss`か`sd`のどちらかです。
どちらも`cmp`と同じ意味論に従い、通常どおり`rflags`のフラグを設定します。

両者の違いは、2つの浮動小数点数の一方が`NaN`値の場合に`ucomixx`は`parity flag (PF)`を設定するのに対し、`comixx`は例外を発生させる点です。

浮動小数点値の比較は_符号なし_で行われます。

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## その他の命令

浮動小数点数を扱う命令はほかにもたくさんあり、よく使われる演算を実装しています。
その一部を次に示します。

| 命令 | 説明                                      |
| :---------- | :----------------------------------------------- |
| `sqrtxx`    | 平方根（`sqrt(x)`）を計算します                 |
| `rcpss`     | 逆数（`1/x`）を計算します                      |
| `rsqrtss`   | 平方根の逆数（`1/sqrt(x)`）を計算します |
| `minxx`     | 最小値（`min(x, y)`）を計算します                   |
| `maxxx`     | 最大値（`max(x, y)`）を計算します                   |

`xx`プレースホルダーが使われる場合、通常どおり`ss`か`sd`の形を取ることができます。
ただし、`rcpss`と`rsqrtss`は単精度浮動小数点数でしか動作しません。

これらの命令はすべて2オペランドです。

## 呼び出し規約

System V ABIでは、最初の8つの浮動小数点引数が`xmm0`から`xmm7`の順に関数へ渡されます。
浮動小数点値は`xmm0`、必要なら`xmm1`で関数から返されます。

すべての`xmm`レジスタは自由に使うことができ、呼び出し側のために予約されているものはありません。

## メモリ

浮動小数点値は、同じサイズの整数と同じ意味論でメモリ上に定義できます。
NASM（The Netwide Assembler、このトラックで使われているアセンブラー）では、浮動小数点値を指数表記で宣言することもできます。

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```

## AVX/AVX2

x86-64アーキテクチャのAVX/AVX2拡張では、浮動小数点命令に新しい3オペランド形式が導入され、変換先と変換元が分かれました。
これらは、上で見てきた従来のSSE形式と区別するために、`v`（_vector_の頭文字）という接頭辞を付けます。

```x86asm
vaddss xmm0, xmm1, xmm2 ; xmm0 = xmm1 + xmm2 (32-bit floating-point)
vmulsd xmm2, xmm3, xmm4 ; xmm2 = xmm3 * xmm4 (64-bit floating-point)
```

このトラックでは、命令とレジスタを従来のSSE拡張までに限定しています。
これは基礎を教えるのに十分で、幅広いCPUとの互換性も確保できます。

ただし、テストランナーはAVXとAVX2を完全にサポートしています。
自由に使ってかまいません。
