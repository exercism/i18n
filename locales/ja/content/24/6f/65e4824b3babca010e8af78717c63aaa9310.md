# テスト


## テストの実行

テストを実行するには、演習のディレクトリで次のコマンドを実行します。

```bash
stack test
```

ファイルを保存するたびにテストを実行するには、代わりにこちらのコマンドを実行します。

```bash
stack test --file-watch
```

### このようなエラーメッセージが表示されたら…

```
No .cabal file found in directory
```

おそらく古いバージョンのstackを使っているので、アップグレードする必要があります。

### そうでなければ、このようなエラーメッセージが表示されたら…

```
No compiler found, expected minor version match with...
Try running "stack setup" to install the correct GHC...
```

表示されたとおりに実行すれば、正しいバージョンのコンパイラーがダウンロードされてインストールされます。

```bash
stack setup
```

## 演習を解く

演習の解答は、Haskellのモジュールです。モジュールの名前は、テストスイートの*import文*で定義されています。通常はその先頭にあります。

```haskell
import Test.Hspec        (Spec, describe, it, shouldBe)
import Test.Hspec.Runner (configFailFast, defaultConfig, hspecWith)

import ModuleName (someFunc)

main :: IO ()
main ...
```

この例では、テストファイルの4行目で`ModuleName`というモジュールをインポートしています。このモジュールは`someFunc`という関数をエクスポートしています。つまり、`ModuleName.hs`というファイルを作成する必要があります。内容は次のようになります。

```haskell
module ModuleName (someFunc) where

someFunc :: ...
someFunc ...
```

`src/`には、この名前のファイルがすでに用意されています。これを解答の出発点として使えます。

ただし、この*スタブ*は始めるためのものだという点に留意してください。変えたほうがよいと思うなら、遠慮なく丸ごと書き換えてください。

### パッケージを使う

よりエレガントな解答を書くためにパッケージを使いたい場合は、まず`package.yaml`にある解答の依存関係にパッケージを追加します。

```yaml
library:
  exposed-modules: ModuleName
  source-dirs: src
  dependencies:
    - foo
    - bar
```

ローカルで作業している間は、好きなパッケージを自由に使えます。ただし、オンラインのテストランナーが使えるパッケージは限られています。利用できるパッケージは次のとおりです。

- GHCに最初からインストールされているもの（特に`base`、`containers`、`array`、`time`、`mtl`、`deepseq`、`exceptions`、`bytestring`）
- テストランナー用にビルド済みのもの。一覧は[haskell-test-runner/pre-compiled/package.yaml](https://github.com/exercism/haskell-test-runner/blob/main/pre-compiled/package.yaml)にあります。

利用できないパッケージを使った解答を提出すると、テストランナーはインターネットに接続できないため、次のようなエラーを出します。

```text
Cabal file info not found for unavailable-package-1.0@..., updating
Selected mirror https://hackage.haskell.org/
Downloading root
HttpExceptionRequest Request {
  host                 = "hackage.haskell.org"
  ...
}
 (ConnectionFailure ...)
```

### *GHCi*を実行する

GHCiで解答を試してみたいときは、次のコマンドを実行するだけです。

```bash
stack ghci
```

## HLint（任意）

解答に対して`hlint`を実行して、見落としている点がないか確認することを強くおすすめします。

```bash
hlint ModuleName.hs
```

`hlint`の提案をすべて受け入れる必要はありませんが、ふつうは美しく慣用的なHaskellコードの書き方を学ぶ助けになります。
