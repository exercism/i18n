# ヒアドキュメント入門

Bashスクリプトでは、ヒアドキュメント（here document、またはheredoc）は、複数行の入力を、まるでターミナルに直接入力しているかのように、コマンドやプログラムへリダイレクトします。
外部ファイルや複雑な文字列操作を必要とせず、スクリプト内に複数行のテキストを埋め込める強力なツールです。

## 主な特徴と構文

1. 区切り文字：ヒアドキュメントは`<<`演算子で始まり、その後に区切りとなる単語（しばしば「マーカー」や「終端」と呼ばれます）が続きます。
   この区切り文字には好きな単語を使えますが、わかりやすさのために`EOF`、`END`、`TEXT`などを使うのが一般的です。
   コードをより読みやすくするには、`END_INSTALLATION_INSTRUCTIONS`のように、内容を表す説明的な単語を区切り文字に使うこともできます。

1. 内容：最初の`<< DELIMITER`のあとに、リダイレクトしたい内容を書きます。
   これは複数行のテキストでも、コードでも、その他の何でもかまいません。

1. 終了：区切り文字の単語が、前後に空白のない1行として再び現れると、ヒアドキュメントは終わります。

## 基本的な構文

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## 仕組み

* Bashは、始まりの`<< DELIMITER`と終わりの`DELIMITER`の間にあるすべての行を読み取ります。
* Bashは、この内容をコマンドの標準入力に接続します。
* コマンドは、この入力をキーボードから入力されたものであるかのように処理します。

### 例1：シンプルなテキスト出力

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

出力：

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

この例では：

* `cat`がコマンドです。
* `<< EOF`が、`EOF`を区切り文字としてヒアドキュメントを開始します。
* 3行のテキストが内容です。
* `EOF`だけの行がヒアドキュメントを終了します。
* その後、`cat`が受け取った内容を出力します。

### 例2：`wc`（単語数）と組み合わせる

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

出力：

```plaintext
3
```

ここでは、`wc -l`が行数を数えます。
ヒアドキュメントが3行を入力として渡します。

### 例3：スクリプトにデータを渡す

スクリプト：

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

対話的なbashプロンプトから、ヒアドキュメントを使ってスクリプトを呼び出します：

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

出力：

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## さまざまな書き方と高度な機能

### リテラルな内容

Bashはヒアドキュメント内で、変数展開、コマンド置換、算術展開を行います。
この意味で、ヒアドキュメントは二重引用符で囲んだ文字列のように振る舞います。

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

出力：

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

区切り文字を引用符で囲む（一重引用符または二重引用符を使う）と、これらの展開は行われなくなります。
内容はそのままの文字として扱われます。
これは一重引用符で囲んだ文字列のようなものです。

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

出力：

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### 先頭のタブを取り除く

`<<`の代わりに`<<-`（末尾にハイフンを付ける）を使うと、Bashはヒアドキュメントの各行の先頭にある_タブ文字_をすべて取り除きます。
これは、出力に影響を与えずに、スクリプト内でヒアドキュメントの内容をインデントするのに便利です。

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

先頭のタブをすべて取り除いた状態で出力されます：

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
著者はこの使い方をすすめていません。
スクリプトの読みやすさは改善できますが、

1. タブ文字を誤って空白に置き換えてしまいがちです（エディターが自動で行うこともあります）。
1. 空白とタブの違いに気づくのが難しいです。
~~~~

## ヒアドキュメントをいつ使うか

* 複数行の入力：コマンドに複数行のテキストを渡したいとき。
* 設定ファイル：小さな設定の断片をスクリプトに埋め込むとき。
* コードの生成：スクリプトの中でその場でコードを作るとき。
* 対話のスクリプト化：対話型プログラムへのユーザー入力をシミュレートするとき。
* 外部ファイルの回避：一時ファイルを作りたくないとき。

よくある使い方としては、ヘルプテキストを表示する場合が挙げられます：

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## 考えられるデメリット

* 大きなドキュメントを埋め込むと、コードが読みにくくなることがあります。
  スクリプトと別のファイルにドキュメントを用意して配布するほうがよい場合もあります。
* ヒアドキュメントはコードの流れを途切れさせることがあります。
  深く入れ子になったコードの途中で、プログラムにテキストを渡したくなることがあるでしょう。
  ヒアドキュメントのインデントは、周囲のコードと比べて見た目がちぐはぐに感じられることがあります。

## ヒアストリング

ヒアドキュメントと同じく、_ヒアストリング_（here string、またはherestrings）はコマンドに入力を渡します。
ただし、ヒアドキュメントがテキストのブロックとして渡されるのに対し、ヒアストリングは1つの文字列として渡されます。
ヒアストリングは`<<< "text"`という構文を使います。

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

出力：

```plaintext
UPPER CASE THIS STRING
```

ヒアドキュメントと違い、終わりの区切り文字は必要ありません。

### なぜヒアストリングを使うのか？

ヒアストリングの代わりにパイプラインを使うこともできます：

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

では、なぜヒアストリングを使うのでしょうか？

長時間かかる計算の出力として文字列を受け取り、その結果を2つの別々のコマンドに渡したい場合を考えてみましょう。
パイプラインを使うと、計算を2回実行しなければなりません：

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

より効率的な方法は、計算の出力を（コマンド置換を使って）取り込み、ヒアストリングで後続の2つのコマンドに入力を渡すことです：

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

この例の実用的な応用を紹介します：

* ページネーションされたREST APIのクエリへのJSONレスポンスを取得し、
* そのJSONデータを`jq`プログラムに渡して結果を解析させ、ファイルに出力し、その後、
* 同じJSONデータを別の`jq`プログラムに渡して、次のクエリのURLを求めます。

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

出力リダイレクトの位置に注目してください。
`while`ループからのすべての出力が、ファイル`data.csv`に追記されます。

## リダイレクトとしてのヒアドキュメントとヒアストリング

これらは単なるリダイレクトの一種なので、他のリダイレクト操作と組み合わせることができます：

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## まとめ

ヒアドキュメントは、Bashスクリプトで複数行の入力を扱うための柔軟で便利な方法です。
テキストやデータをスクリプトに直接埋め込む手間を減らし、スクリプトをより自己完結的に、そして読みやすくします。

ヒアストリングはヒアドキュメントに似ていますが、よりシンプルで動的な構文を提供します。
