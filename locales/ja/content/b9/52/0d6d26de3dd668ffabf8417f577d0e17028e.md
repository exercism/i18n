## General

`SimpleLinkedList`構造体を`Vec`のラッパーとして実装しないでください。代わりに、ノードをヒープに割り当てます。

たとえば、次のように実装できます。

```
pub struct SimpleLinkedList<T> {
    head: Option<Box<Node<T>>>,
}
```

`head`フィールドは、この連結リストの最初の要素（Node）を指します。

この実装では、次のフィールドを持つ`Node`構造体も必要です。

```
struct Node<T> {
    data: T,
    next: Option<Box<Node<T>>>,
}
```

`data`には保存するデータが入り、`next`は次のノード（存在すれば）またはNoneを指します。

## なぜ`Option<Box<Node<T>>>`であって、`Option<Node<T>>`ではないのでしょうか？

自分で試してみましょう。すると、次のエラーが出ます。

```
| struct Node<T>
| ^^^^^^^^^^^^^^ recursive type has infinite size
...
|     next: Option<Node<T>>,
|     --------------------- recursive without indirection
```

問題は、コンパイル時に`next`のサイズがわかっていなければならないことです。
`next`は再帰的（「ノードがノードを持ち、そのノードがまたノードを持ち…」）なので、コンパイラーはどれだけのメモリーを確保すべきかわかりません。
これに対して、[Box](https://doc.rust-lang.org/std/boxed/)はサイズが決まっているヒープへのポインターです。
