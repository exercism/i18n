# 概要

関数が*最後*に実行するのがその関数自身の呼び出しであるとき、その関数は[末尾再帰][recursion-tc]です。

関数が呼び出されるたびに、ローカル変数や引数などを含む*スタックフレーム*が[関数呼び出しスタック][call-stack]の先頭に積まれます。関数が戻ると、そのスタックフレームはスタックから取り除かれます。

末尾再帰の関数は、[末尾呼び出し最適化][tail-call-optimization]を可能にします。これは、直前の関数がもうそのスタックフレームを必要としないことが保証されているため、次の関数呼び出しで最後のスタックフレームを再利用できるようにする最適化です。これにより、関数呼び出しスタックがあふれる問題を軽減できます。あふれるとは、関数呼び出しスタック上のフレームが多すぎて、新しいフレームを作るためのメモリが残っていない状態のことです。

- Elixirで末尾再帰を実現するには、データが不変であるというルールのため、アキュムレーターが必要になることがよくあります。

  - アキュムレーターは、再帰呼び出しに引き継がれていく変数です。基底ケースで最終的な結果が返されるまで、*ここまで*の再帰関数の状態を保ちます。

    ```elixir
    # Count the length of a list without an accumulator
    def count([]), do: 0
    def count([_head | tail]), do: 1 + count(tail)

    # Count the length of a list with an accumulator
    def count(list), do: do_count(list, 0)

    defp do_count([], count), do: count
    defp do_count([_head | tail], count), do: do_count(tail, count + 1)
    ```

- 配列を扱うときは、配列が単方向連結リストとして実装されていることを覚えておきましょう。先頭への追加はとても速いですが、末尾への追加はとても遅いです。

  ```elixir
  # Reverse a list with an accumulator
  def reverse(list), do: do_reverse(list, [])

  defp do_reverse([], acc), do: acc

  defp do_reverse([head | tail], acc) do
    do_reverse(tail, [head | acc])
  end
  ```
