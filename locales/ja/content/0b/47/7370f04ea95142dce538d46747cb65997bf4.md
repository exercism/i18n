# はじめに

条件分岐のコンセプトでは、条件に基づいて分岐する命令ファミリーである`jcc`を紹介します。`jcc`は、条件が満たされたときだけ、プログラム内の別の地点に実行を移します。

しかし、現代のCPUは高速で、多くの命令を並列に実行できます。実行時に条件をチェックするあいだCPUが待ち、その間すべての作業を止めてしまうのは、コストがかかりすぎます。

そのため、CPUは内部的には待ちません。**分岐予測器**を使って条件の結果を推測し、予測した経路を_投機的に_実行し始めます。

予測が当たれば、分岐がなかったかのように実行が進みます。しかし、予測が外れると、CPUは_予測した経路で行った作業を破棄して_、正しい経路でやり直さなければなりません。

これは**分岐予測ミス**と呼ばれ、遅延を招くためコストがかかります。

分岐の予測が難しいときは、こうした予測ミスが積み重なります。そうした場合は、分岐を完全になくして、条件に関係なく同じ命令が実行されるようにしたほうがよいこともあります。`jcc`を使わずに値を選ぶコードは、**ブランチレス**と呼ばれます。

コードを、分岐が起こる回数が少なくなるように、あるいは実際にある分岐がより予測しやすくなるように組み立てる方法は、いくつかあります。とくにx86-64には、ブランチレスなコードを書くためによく使われる2つの命令ファミリーがあります。

## 条件付き移動

`cmovcc`という命令ファミリーは、特定の条件が満たされたときだけ、ソースオペランドをデスティネーションにコピーします。そうでなければ、デスティネーションは変更されません。

`cc`という接尾辞は、`jcc`と同じ命名規則に従い、意味も同じです：

| 命令 | 移動する条件 |
|-------------|--------------------------------------|
| `cmove`     | `cmp A, B`の後でA == B              |
| `cmovne`    | `cmp A, B`の後でA != B              |
| `cmovl`     | `cmp A, B`の後でA < B（符号付き）     |
| `cmovb`     | `cmp A, B`の後でA < B（符号なし）     |
| `cmovg`     | `cmp A, B`の後でA > B（符号付き）     |
| `cmova`     | `cmp A, B`の後でA > B（符号なし）     |

規則は`jcc`と似ています：

1. `l`と`g`は符号付きの比較に、`b`と`a`は符号なしの比較に使います。
2. 接尾辞に`e`を付けると、等しい場合も含まれます。
3. 接尾辞に`n`を付けると、条件が否定されます。
4. フラグがセットされているかどうかを参照する変種もあります。
   たとえば`cmovz`や`cmovc`です。

`rdi`にある符号付き整数の絶対値を計算し、`rax`で返すことを考えてみましょう。`jcc`で書くと、関数は2つの経路のうち一方を選びます：

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

`cmovcc`で書くと、2つの候補値がどちらも無条件に計算され、条件付き移動がそのうち一方を選びます：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

ブランチレス版は、常に同じ命令を実行します。予測器が推測すべき`jcc`はありません。

`cmovcc`のデスティネーションはレジスタでなければなりません。ソースはレジスタかメモリの位置であってよく、即値は使えません。

~~~~exercism/note
上のコードでは、`neg`命令が結果に応じていくつかのフラグを設定します。その中には符号フラグ（SF）も含まれます。つまり、`cmp rdi, 0`は完全に省略できます：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

`rdi`が正のとき、`neg`は負の結果を生成するのでSF == 1になり、`cmovs`が`rdi`を復元します。`rdi`が0か負のとき、`neg`は非負の結果を生成するのでSF == 0になり、`rax`は否定された値（これが正しい絶対値です）をそのまま保ちます。

アセンブリコードで値を比較する主な方法は`cmp`ですが、多くの命令も結果に応じてフラグを設定します。ある命令が影響を与えるフラグの完全な一覧は、通常その[リファレンス][reference]に記載されています。`neg`の場合は、SF、ZF、CF、OF、PFです。

[reference]: https://www.felixcloutier.com/x86/
~~~~

## 条件付きセット

`setcc`という命令ファミリーは、特定の条件が満たされたときはデスティネーションオペランドを`1`に、そうでないときは`0`に設定します。デスティネーションは常に_8ビットのオペランド_です。

`cc`という接尾辞は、`jcc`や`cmovcc`と同じ命名規則に従います。たとえば`setz`は、`ZF == 1`のときはデスティネーションを`1`に、そうでないときは`0`に設定します。

デスティネーションは8ビットなので、より幅の広い値が必要なときは、`setcc`の後に`movzx`を続けるのが一般的です：

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

これは、比較の結果を整数の`0`か`1`に変換するためのよく知られたイディオムです。
