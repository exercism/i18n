# はじめに

沿岸警備艇に乗り組む*信号手*は、メッセージログを管理します。生の信号旗は、マーカー文字で囲まれた形で届きます。読み取った値は、通信回線に流せる形に変換しなければなりません。また、観測値のペアやトリプルは、その場で要約されます。Factorの標準ライブラリーにあるいくつかのイディオムが、作業の大半を担ってくれます。

## `unparse`：値からソースへ

[`unparse`][unparse]（`prettyprint`にあります）は、どんな値でもそのソース形式のテキストを返します：

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse`はパーサーの逆のはたらきをします。`dup unparse parse`という往復で、元の値が復元されます。受信側が再びパースする通信形式へシリアライズするにはうってつけですが、人間が読むための出力には向きません（文字列は引用符が付いたまま、ベクターは`V{ ... }`のまま、など）。

## スライスの派生形：ビューでありコピーではない

`sequences`の`head`と`tail`は、残す部分を*コピー*して新しいシーケンスにします。これに対応する`-slice`版は、`slice`オブジェクトを返します。これは開始インデックス、終了インデックス、元のシーケンスを保持するタプルで、コピーせずに[sequence protocol][sequence-protocol]を実装しています：

| ワード          | 効果                                          |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )` 最初のn個をコピー           |
| `head-slice`  | `( seq n -- slice )` 最初のn個のビュー           |
| `tail`        | `( seq n -- newseq )` インデックスn以降をコピー   |
| `tail-slice`  | `( seq n -- slice )` インデックスn以降のビュー      |
| `head*`       | `( seq n -- newseq )` 最後のn個以外をコピー    |
| `head-slice*` | `( seq n -- slice )` 最後のn個以外のビュー    |
| `tail*`       | `( seq n -- newseq )` 最後のn個をコピー            |
| `tail-slice*` | `( seq n -- slice )` 最後のn個のビュー            |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

`slice`はシーケンス*そのもの*なので、シーケンスを受け取るものはスライスも受け取ります。`length`や`first`、`each`などは、コピーなしでそのまま動きます。リテラル文字列と比較したいテストでは、`>string`で変換できます。

## `?head`と`?tail`：マーカーがあれば取り除く

枠で囲まれた読み取り値には、あるかもしれないしないかもしれないマーカー文字列が付いています。`?head`と`?tail`（`splitting`にあります）は、接頭辞や接尾辞を取り除こうとし、短くなった（かもしれない）シーケンス*と*、マーカーが見つかったかどうかを示す真偽値を返します：

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

末尾の真偽値のおかげで、ガードとしてぴったりです。`?head`を`if`と組み合わせれば、枠が存在したかどうかで分岐できますし、`unless`と組み合わせれば、期待するマーカーがない入力をはじけます。

## `<repetition>`：N個のコピーを仮想的に

[`<repetition>`][repetition]（`sequences`にあります）も、コピーしない仮想シーケンスです。`( len elt -- repetition )`は、すべて`elt`である`len`個の要素からなるシーケンスを、その数のスロットを確保することなく構築します：

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

`elt`自体をシーケンスにすることもできます。その場合、各コピーは同じシーケンスです。あとは`concat`が、コピー同士を端から端までつなぎます：

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

`slice`と同様、結果はシーケンス*そのもの*です。`length`や`each`などが直接使えます。信号コードを決まった幅まで埋めたり、同じマーカーを連続して並べたりするときに使います。実際に具体的なシーケンスが必要なときだけ、`>string`（または`>array`）で変換しましょう。

## `<clumps>`：重なり合うウィンドウを仮想的に

[`<clumps>`][clumps]（`grouping`にあります）は3つ目のコピーしない仮想シーケンスです。`( seq n -- clumps )`は、`seq`を、その上を*重なり合いながら*進む長さ`n`のウィンドウの連なりとしてとらえます。各ウィンドウはスライスです：

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

長さ`length`のシーケンスからは、`length - n + 1`個のウィンドウが得られます。各ウィンドウがスライスなので、連続する読み取り値のペアを作るのにコピーは不要です。各`2`-clumpに`[ first2 ]`を適用すれば、射影の元になる連続ペアがすべて手に入ります。（重ならずに分割するいとこの`<groups>`は、シーケンスを互いに素なブロックに切り分けます。）

## 複数入力のcleave：`2bi`、`3bi`、`2tri`、`3tri`

ふつうのcleaveワードである`bi`と`tri`は、*1つ*の入力に2つまたは3つのクオテーションを適用します。`2`や`3`が付いた版は、各クオテーションを*2つ*または*3つ*の入力に適用します：

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

どのクオテーションも、*すべての*入力を受け取ります。同じペア（またはトリプル）の値から複数の射影を計算したいときに使います。*同じ*操作を各入力に別々に適用したいときではありません（それは`bi@`や`tri@`です）。

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
