# はじめに

ここでは、_言語_のほうを **AWK** と呼び、AWKプログラムを解釈する_実行ファイル_のほうを **`awk`** または **`gawk`** と呼ぶことにします。

## パターンとアクション

AWKプログラムは、**パターンとアクションの組**で構成されます。

```awk
pattern1 { action1 }
pattern2 { action2 }
...
```

**パターン**には、入力を照合するための正規表現を指定できます。結果が真偽値になる任意の式を指定することもできます。

**アクション**は1つ以上のAWKコマンドです。囲む波括弧は省略できません。

パターンの結果が_真_であれば、対応するアクションが実行されます。

## レコードとフィールド

AWKは、入力を一連の**レコード**として解析します。各レコードは、0個以上の**フィールド**に分割されます。

デフォルトの動作は次のとおりです。

- 入力は、改行を「レコード区切り文字」としてレコードに分割されます。つまり、_行_がそれぞれ1つのレコードになります。
- レコードは、空白を「フィールド区切り文字」としてフィールドに分割されます。つまり、_単語_がそれぞれ1つのフィールドになります。

## パターンとアクション（続き）

パターンは省略できます。その場合、アクションは_すべての入力レコード_に対して実行されます。

アクションも省略できます。その場合、デフォルトのアクションとして現在のレコードが出力されます。

### 特別なパターン

よく使われる特別なパターンが2つあります。

- `BEGIN`は、入力が消費される前に、対応するアクションを実行します。
- `END`は、すべての入力が消費されたあとに、対応するアクションを実行します。

## フィールド変数

フィールドを参照するときは、`$1`、`$2`、`$3`のように書きます。

現在のレコードは`$0`です。

ほかによく使われる組み込み変数も紹介します。

### 入力の解析を制御する組み込み変数

- `RS`は入力のレコード区切り文字です。前述のとおり、デフォルト値は改行です。
- `FS`は入力のフィールド区切り文字です。

これらの変数は、`BEGIN`のアクションブロックで設定することがよくあります。

### 情報を伝える組み込み変数

これらの変数は、プログラムの実行中にAWKによって自動的に設定されます。

- `NF`には、現在のレコードのフィールド数が入ります。
  - 最後のフィールドの値を得るには、`$NF`を使います。
- `NR`には、現在のレコード番号が入ります。
  - 複数の入力ファイルを処理しているとき、`NR`にはこれまでに処理したレコードの総数が入ります。
- `FNR`には、現在の入力ファイルにおけるレコード番号が入ります。
  - `NR`と`FNR`の違いを説明するために、よく使われるAWKのイディオムを紹介します。
    ```awk
    NR == FNR {action}
    ```
    これは「累積のレコード番号が、現在のファイルのレコード番号と等しいなら」という意味です。これが真になるのは、_最初の入力ファイル_のレコードだけです。

## 真偽の考え方

AWKは、C言語と同じ真偽の考え方を使います。

- 数値の`0`は偽です。
- それ以外の数値はすべて真です。

AWKはテキスト処理言語なので、この真偽の考え方は文字列にも広がります。

- 空文字列`""`は偽です。
- 空でない文字列はすべて真です。

## コメント

コメントは`#`で始まり、行の終わりまで続きます。

## 例

Unix系のシステムでは、`/etc/passwd`にユーザーの情報が含まれています。各ユーザーはそれぞれ別の行に書かれ、フィールドはコロンで区切られています。

ユーザー名を一覧表示するには、次のようにします。

```sh
awk '
    BEGIN { FS = ":" }
    { print $1 }
' /etc/passwd
```

`{print $1}`というアクションにはパターンがないので、すべてのレコードに対して実行されることに注目してください。

出力を、ログインシェルとしてbashを使うユーザーだけに絞りたい場合は、次のようにします。

```sh
awk '
    BEGIN { FS = ":" }
    $7 == "/bin/bash" { print $1 }
' /etc/passwd
```
