# はじめに

## 部分適用

Elmのすべての関数は[カリー化][currying]されています。つまり、すべての引数を渡さずに関数を呼び出すと、新しい関数が返ります。

こうした結果を[部分適用][partial-application]と呼びます（関数にすべての引数を渡しているのではなく、一部の引数だけを部分的に適用しているのです）。

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

部分適用では、いつも引数が順番どおりに適用されます。

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## パイプ演算子（`|>`）

`x |> f`と書くのは、`f x`とまったく同じです。具体的な例では、`"5" |> String.toInt`は`String.toInt "5"`と同じです。

これは一見するとあまり役に立たないように思えますが、パイプラインのようにコードを書けるようにしてくれるので、[パイプ演算子][pipe-operator]と呼ばれています。

たとえば、ユーザーの入力を整数に変換する`sanitize`関数があるとします。

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

これは次のように書き換えられます。

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

こうすると括弧（`()`）を使わずに済み、関数が適用される順番（最初に`String.trim`、次に`String.toInt`）がそのまま見えるので、読みやすくなります。

逆向きの[逆パイプ演算子`(<|)`][reverse-pipe-operator]もあります。
`f <| x`と書くのは、`f x`とまったく同じです。
これも一見するとあまり役に立たないように思えますし、パイプ演算子ほど使われることはありませんが、状況によっては括弧を避けるのに役立ちます。

## 関数合成／ポイントフリースタイル

[`(>>)`][forward-composition]演算子は`(a -> b) -> (b -> c) -> (a -> c)`という型を持ち、型`a -> b `と`b -> c`という互換性のある2つの関数を合成して、型`a -> c`の関数を作ります。
これは、1つ目の関数の出力（型`b`）を取り出し、それを2つ目の関数（同じ型`b`である必要があります）の最初の引数として使うことで行います。
作られた関数は、1つ目の関数と同じ入力（型`a`）を受け取り、2つ目の関数が返す`c`をそのまま返します。

具体的な例が`String.trim >> String.toInt`です。
`String.trim`は文字列を唯一の仮引数に取るので、作られる関数もそれを受け取ります。
`String.toInt`は`Maybe Int`を返すので、作られる関数もそれを返します。
`String.trim`は`String`を返し、それを`String.toInt`が仮引数として受け取れるので、この例はコンパイルできます。

これで、`sanitize`関数を次のように書き換えられます。

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

元の例にあった`input`という仮引数をもう使っていないことに注目してください。機能はまったく同じですが。
このように、仮引数を参照せずに関数を作る書き方を「ポイントフリースタイル」と呼びます。
このスタイルの利点はコードがより簡潔になることで、欠点は、特に初心者にとっては理解しづらくなることがある点です。

Elmではすべての関数がカリー化されているので、`String.length >> max`もコンパイルできることを覚えておくとよいでしょう。

- [`(>>)`][forward-composition]演算子は`(a -> b) -> (b -> c) -> (a -> c)`という型を持ちます。
- `String.length`は`String -> Int`という型で、これが`(a -> b)`の部分にあたるので、`a`は`String`、`b`は - `Int`です。
- `max`は`Int -> Int -> Int`という型で、これが`b -> c`の部分にあたります。
- `b`は`Int`なので、`max`は部分的に適用され、`c`はこの部分適用の結果（`Int -> Int`）になります。
- したがって、`String.length >> max`の型は`String -> (Int -> Int)`です。
- したがって、`((String.length >> max) "123") 2`は`3`を返します。`"123"`の長さは3で、これは`Int`引数の2より大きいからです。

## 関数の設計

Elmでエレガントなコードを書きやすくするには、主となるデータ構造を関数の最後の仮引数にするとよいでしょう。
標準ライブラリのよく使う関数はすべてこのようにしています。たとえば`List.map`です（型シグネチャは下記）。

```elm
map : (a -> b) -> List a -> List b
```

ここでは、`map`関数の最後の仮引数が`List a`で、戻り値が`List b`であることがわかります。つまり、主となるデータ構造（`List`）が最後の仮引数になっています。

これにより、次のようなエレガントなパイプライン風のコードを書けるようになります。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

また、パイプラインの代わりに関数合成やポイントフリースタイルを使うのも便利になります。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

関数合成を使えば、この例を`List.map`の1回の呼び出しにまとめることもできます。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
