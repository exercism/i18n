# Nil

Crystalには[`Nil`][nil]という型があり、値は`nil`の1つだけです。
これは値が存在しないことを表すために使われ、他の言語の`null`や`None`に似ています。

`nil`はさまざまなメソッドの戻り値として返ることがあります。たとえば[`String#[]?`][string-index]は、インデックスが範囲外のときに`nil`を返します。

```crystal
"foo"[10]? # => nil
```

Crystalには**null参照チェック**と呼ばれる仕組みがあります。これは、すべての型がデフォルトで`nil`を許容しないという意味です。
つまり、変数を明示的に`Nil`型として宣言しない限り、その変数に`nil`を代入することはできません。
そのため、コンパイラーがnull参照を自動的にチェックしてくれます。

## 偽とみなされる値

`nil`値の扱い方には、いくつかの方法があります。
`nil`は[偽とみなされる値][truthy-falsey]で、`false`も同じです。
つまり、偽とみなされる値や真とみなされる値が期待される文やその他の場所では、`false`と同じように扱われます。

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

つまり、`nil`になりうる変数の値が`nil`のときは、真とみなされる側の分岐は実行されません。

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## `nil`かどうかを確認する

Crystalには、値が`nil`かどうかを確認するためのメソッドがあります。
[`nil?`][nil?]といい、すべてのオブジェクトで利用できます。

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

これは、`if`文でそのまま値を使う場合とは少し異なります。というのも、先ほどの例では`false`と`nil`のどちらも偽として扱われていました。
ここでは`nil`だけが偽として扱われます。値が`false`だったなら`nil`ではないので、真になっていたはずだからです。

## or演算子

`nil`値を扱うもっとも簡単な方法は、そもそも`nil`にならないようにすることです。
or演算子（[`||`][or]）は`Bools`を扱うときによく使われますが、正しく理解すれば`nil`値の扱いにも使えます。
or演算子は、最初の値が真かどうかを調べ、そうでなければ2番目の値を使います。
これを使えば、値が`nil`の場合は偽となるので、2番目の値が使われるようにできます。

```crystal
"foo"[10]? || "bar" # => "bar"
```
