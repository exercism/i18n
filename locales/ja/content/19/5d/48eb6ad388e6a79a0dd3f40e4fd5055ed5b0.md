# はじめに

## null参照

これまでに別のプログラミング言語（C/C++、Python、Java、Ruby、Lispなど）を使ったことがあれば、`null`や`nil`に出会ったことがあるでしょう。
これらの言語では、`null`や`nil`を使って、特定の変数に値がないことを示します。
しかしそのせいで、`null`の変数をうっかり使ってしまうという、簡単で（しかもよくある）間違いを犯しやすくなります。
ご想像のとおり、存在しない関数を呼び出そうとしたり、存在しない値にアクセスしようとしたりすると、さまざまなバグやクラッシュにつながります。
`null`の生みの親は、それを自ら['10億ドルの過ち'][billion-dollar-mistake]と呼んだほどです。

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## `Option`型

こうした問題を避けるために、Cairoの変数では`Option`列挙型を使って、値がないことを安全に表せます。
この列挙型には2つのバリアントがあります。Cairoにおけるnull相当の`None`と、任意の型の値`T`をとる`Some(T)`です。

次のようになっています：

```rust
enum Option<T> {
    None,
    Some(T),
}
```

`Option`は、null参照が引き起こしかねない問題から守ってくれる安全の層のようなものだと考えるとよいでしょう。それでいて、null参照の概念としての有用さはそのまま残っています。

## `Option`の使い方

変数に`None`を設定するのは、わりと簡単です：

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

しかし、`Option`型に値を持たせたい場合は、その値を直接代入することはできません。
`Option`型の変数と、たとえば`i32`型の変数は同じものではありません。
`Some`を使う必要があります：

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

同じ理由で、次のコードも動きません：

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

`Some`が持つ値を取り出すには、まずその値が存在するかどうかを確認する必要があります：

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

Cairoには、`Option`に含まれる値を確認したり取り出したりするために、`match`以外にも使えるツールがあります。ただし、`match`にはもう慣れているはずです。

これは、Cairoがnull参照ではなく`Option`を使う理由を示す例だと考えてください。
要点はこうです。`Option`の変数が`Some`なのか（その場合は、中に含まれる値を取り出して使ってかまいません）、それとも`None`なのかを、**必ず確認しなければなりません**。
そうしないと、プログラムはコンパイルされません。コンパイラーが`null`から守ってくれます。
