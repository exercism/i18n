# 概要

Elixirでは、すべてのコードはプロセスの中で実行されます。Elixirのプロセスには、次のような特徴があります。

- システムのプロセスとは混同しないでください。
- 軽量です。
- 特定の用途があります。次のようなことができます。
  - [グローバルな状態を保つ][getting-started-processes-state]
  - [障害を封じ込める][getting-started-processes-links]
  - 並行・非同期のコードを可能にする

_何百_ものプロセスを動かすElixirアプリは珍しくありませんが、特にそれがライブラリであれば、新しいプロセスを明示的に一切作らないアプリも普通にあります。

## プロセスの作成

デフォルトでは、関数はそれを呼び出したのと同じプロセスの中で実行されます。ある関数を新しいプロセスで明示的に実行したいときは、`spawn`を使います。

- [`spawn/1`][kernel-spawn-1]は、そのまま実行する関数を引数に取ります。

  ```elixir
  spawn(fn -> 2 + 2 end)
  # => #PID<0.125.0>
  ```

- [`spawn/3`][kernel-spawn-3]は、実行する関数を、モジュール名、関数名（アトム）、その関数に渡す引数のリストで指定します。

  ```elixir
  spawn(String, :split, ["hello there", " "])
  # => #PID<0.113.0>
  ```

  - この3つのデータの組は、_MFA_（_Module、Function、Arguments_）と呼ばれることがよくあります。

- プロセスは、その関数の実行が終わるとすぐに終了します。

- プロセスがまだ_生きている_（実行中である）かどうかは、[`Process.alive?/1`][process-alive]で確認できます。

  ```elixir
  pid = spawn(fn -> 2 + 2 end)
  Process.alive?(pid)
  # => false
  ```

## メッセージ

プロセス同士が直接情報を共有することはありません。プロセスはデータを共有するために_メッセージを送り_ます。この並行処理のパターンは、[アクターモデル][wiki-actor-model]と呼ばれます。

- プロセスにメッセージを送るには、[`send/2`][kernel-send]を使います。

  ```elixir
  send(pid, :hello)
  ```

  - メッセージは、送られた順に受信側の_メールボックス_に届きます。
  - `send`は、メッセージが受信されたかどうかも、受信側がまだ生きているかどうかも確認しません。

- メッセージはどのような型でもかまいません。
- 現在のプロセスに送られたメッセージは、[`receive/1`][kernel-receive]で受け取ることができます。

  - メッセージに対してパターンマッチを行う必要があります。
  - `receive`は、指定したいずれかのパターンに一致するメッセージがプロセスのメールボックスに入るまで待ちます。
    - デフォルトでは無期限に待ちますが、`after`ブロックを使ってタイムアウトを指定できます。
  - 読み取られたメッセージはプロセスのメールボックスから取り除かれます。読み取られていないメッセージは、そのまま無期限に残ります。
    - 読み取られていないメッセージがたまってメモリ不足にならないよう、`receive/1`には必ずすべてに一致する`_`節を書いてください。

  ```elixir
  receive do
    {:ping, sender_pid} -> send(sender_pid, :pong)
    _ -> nil
  after
    5000 ->
      {:error, "No message in 5 seconds"}
  end
  ```

## 受信ループ

複数のメッセージを受け取りたいときは、`receive/1`を再帰的に呼び出す必要があります。`receive/1`を呼び出し、メッセージに対して何らかの処理を行い、さらにメッセージを待つために自分自身を呼び出す再帰関数（たとえば`loop`という名前の関数）を実装するのは、よくあるパターンです。ある`receive/1`の呼び出しから次の呼び出しへ状態を持ち越したいときは、その`loop`関数に引数を渡すことで実現できます。

```elixir
def loop(state) do
  receive do
    :increment_by_one ->
      loop(state + 1)

    {:report_state, sender_pid} ->
      send(sender_pid, state)
      loop(state)

    :stop ->
      nil

    _ ->
      loop(state)
  end
end
```

実際には、この方法を直接使うことはほとんどありません。Elixirには、[`Agent`モジュール][agent]や[`GenServer`ビヘイビア][genserver]など、どちらも受信ループの上に成り立つ並行処理の抽象化が用意されています。ただし、これらの抽象化を効率よく使いこなすには、基本をしっかり理解しておくことが欠かせません。
