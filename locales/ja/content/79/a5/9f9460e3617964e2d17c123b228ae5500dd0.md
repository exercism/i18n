# はじめに

`channel-chatter`ではすでにストリームを*使い*、`boatswains-bilge`ではその始末をしました。この演習では、初めて自分でストリームを作ります。[プロトコル][stream-protocol]を実装したクラスを作るので、`<string-reader>`で動いていた`with-input-stream`、`read1`、`stream-read1`のコードが、そのまま自分のクラスでも動きます。

## ミックスイン：クラス階層のもう半分

`dragons-descendants`で`TUPLE: child < parent …`をすでに学びました。これは、スロットが親から子へと流れていく単一親の階層です。Factorには、クラスグラフを拡張する*もうひとつ*の方法があります。**オープンミックスイン**です。`MIXIN: m`はスロットを持たないクラスを宣言し、他のクラスは後から`INSTANCE: c m`でそこに参加できます。所属は多対多で、ひとつのクラスは好きなだけ多くのミックスインのインスタンスになれます。

ストリームのプロトコルでは、2つのミックスインを使って、クラスがインターフェースのどちら側を実装しているかを示します。

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

ストリームは、どちらか一方でも、両方でもかまいません。`input-stream`（または`output-stream`）のジェネリックメソッドは、そのミックスインに参加した任意のクラスへディスパッチされます。周囲からそのまま使える`read1`、`stream-contents`、`with-input-stream`などが自分のクラスにたどり着くのは、こういう仕組みです。

ミックスインは*オープン*です。ミックスインを宣言したあとでも、たとえ別のボキャブラリーであっても、新しいメンバーを追加できます。これが`TUPLE: < parent`との違いです。こちらは子クラスを宣言した時点で関係が固定されます。

## プロトコルのジェネリック

プロトコルのジェネリックは`io`にあります。

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

`stream-read1`は次のバイトを返します（ストリームの終端では`f`）。`stream-write1`は1バイトを書き込みます。`stream-read-unsafe`は、ほとんどの入力ストリームが提供する低レベルの一括読み込みです。`stream-read`はその上に作られていて、メモリの割り当てを扱います。`stream-element-type`は、そのストリームがバイト（`+byte+`）を扱うのか文字（`+character+`）を扱うのかを表します。別のストリームをラップする場合、いちばん簡単な実装は、その下にあるストリームにそのまま委譲するだけです。

## 後始末は`destructors`から

ストリームはディスポーザブルです。自作のストリームは`disposable`を継承し、`dispose*`を実装します。これは`boatswains-bilge`で扱ったフレームワークを、ストリームのクラスに当てはめたものです。

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

これさえ整えば、`channel-chatter`で出てきた`with-…`系のコンビネーターが、自分のストリームでも自動的に動きます。
