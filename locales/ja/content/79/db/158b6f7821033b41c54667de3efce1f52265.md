# 概要

`Complex numbers`は複雑ではありません。
ただ、もっと穏やかな名前を付けてあげればいいだけです。

複素数は、特に工学や科学の分野でとても役に立ちます。そのためRでは、integer、double、logical、character、rawと並ぶ標準の[原子型][ref-atomic]のひとつとして、[複素数][web-complex]が用意されています。

## 基本

Rの`complex`は、1つの値です。
しかし実際には、2つの数値のペアとして考えることができます。
この2つは、残念な歴史的経緯から「実部」と「虚部」と呼ばれています。
ここでも、奇妙な名前にとらわれず、その根底にあるシンプルさに目を向けるのがよいでしょう。

2つの実数から複素数を作るには、虚部に接尾辞`i`を付けるだけです。

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

実数の変数から複素数を作るには、上のような書き方ではうまくいきません。
`r + imi`と書くと、パーサーは`imi`を（存在しない）変数名だと解釈してしまいます。

虚部に`1i`を掛けるか、[`complex()`][ref-complex]関数を使います。

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

なぜ`j`ではなく`i`なのか、不思議に思うかもしれません。

エンジニアの多くは`j`を好みます。
科学者や数学者の多くは、_虚数_を表す数学の記法である`i`を好みますが、その記法は電気工学で_電流_を意味する`i`の使い方と衝突します。

Rは`i`を、Pythonは`j`を選び、Juliaは`im`を選んでこの論争を回避しました。
[STEM][wiki-STEM]分野のプログラミング言語を行き来するときは注意してください。

複素数の各部分を個別に取り出すには、次のようにします。

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

どちらの部分も0になることがあり、数学者はそうした数を「完全に実数」「完全に虚数」と呼ぶことがあります。
しかし、Rではそれでも複素数です。

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

「`i`（または`j`）は-1の平方根だ」と聞いたことがあるかもしれません。

今のところ、これが意味するのは、虚部が_定義により_次の等式を満たすということだけです。

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

単純な考え方ですが、興味深い結果につながります。

## 算術

小数や整数で使う[`operators`][ref-operators]のほとんどは、複素数でも使えます。

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

複素数の掛け算と割り算の規則をここで説明するのは、この概念の範囲外です（_そして、そうした演算を「手作業で」行うことは、めったにないでしょう_）。

この話題を深く掘り下げたいなら、複素数に関する[数学][web-math-complex]や[電気工学][web-engineering-complex]の入門書のどれでも、この点が説明されています。

また、Exercismには[`Complex Numbers`][exercise-complex-numbers]という実践的な演習があり、そこではこれらの演算を持つ複素数クラスを基本原理から実装できます。

複素数では整数除算は一般に___できません___。そのため、`%/%`と`%%`演算子は複素数型では失敗します。

## 関数

ほとんどの数学関数は複素数の入力で動作します。

ただし、実数の入力を渡して複素数の出力を期待しても、通常はうまくいきません。

```r
sqrt(z1)
#> [1] 1.414214+0.707107i

sqrt(-1)  # fails!
#> Warning in sqrt(-1) : NaNs produced
#> [1] NaN

sqrt(-1 + 0i)  # succeeds with complex input
#> [1] 0+1i

sin(z1)
#> [1] 3.752771+0.256554i
```

`Re()`と`Im()`のほかにも、複素数に特に関係の深いいくつかの関数があります。
意味がよくわからなければ、ここは飛ばしてしまってください！

- `Conj()`は、複素数の虚部の符号を反転させるだけです（_+から-へ、またはその逆_）。
  - 複素数の掛け算の仕組みのおかげで、これは思っている以上に役に立ちます。
- `abs(<complex number>)`は、虚部のない実数（その「大きさ」）を必ず返します。`Mod(<complex number>)`はその同義語です。
- `Arg(<complex number>)`は、位相角をラジアンで返します。

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```

数学に興味がある方のための、部分的な説明です（_繰り返しますが、読み飛ばしてかまいません_）。

- `z1`の`(real, imag)`表現は、実質的に複素平面上のデカルト座標を使っています。
- 同じ複素数は、極座標を使った`(r, θ)`の表記で表すこともできます。
- ここで、`r`と`θ`はそれぞれ`abs(z1)`と`Arg(z1)`で与えられます。

いくつかの定数を使った例を見てみましょう。

```r
 euler <- exp(1i * pi)

euler
#> [1] -1+0i
```

つまり、自然界で最も重要な3つの定数`e`、`i`（または`j`）、`pi`を使った単純な式が、`-1`という結果を生み出します。
これは数学全体で最も美しい結果だと信じている人もいます。
その起源は1740年ごろにさかのぼります。

### なぜ使う人がいるのでしょうか？

実は、複素数は、回転するものや波のような性質を持つものを記述する最もシンプルな方法です。
そのため、電気工学、音声処理、物理学、コンピューターゲーム、ナビゲーションなど、ほんの一部を挙げただけでも幅広く使われています。

回転するものは目に見えます。
複素数が世界を回しているわけではありませんが、世界が回ることで_何が起きるのか_を説明するのは得意です。大きな嵐の衛星写真をどれか見てみてください。

もっとわかりにくい例では、音は波であり、光も波であり、無線信号も波です。
そして、母国の経済でさえ、少なくとも部分的には波の性質を持っています。

こうした波の処理の多くは三角関数（`sin()`と`cos()`）でも行えますが、あっという間に煩雑になってしまいます。

複素指数関数を使うほうが___ずっと___扱いやすくなります。

### でも、複素数は必要ないのでは？

それが当てはまるのは、洞窟に住んで食べ物を採集して暮らしている場合だけです。

何らかの画面でこれを読んでいるなら、複素数を活用して生まれた20世紀の有用な進歩に、完全に依存していることになります。

__半導体チップ__。

- これらは古典物理学では説明がつかず、量子力学（QM）によってのみ説明（および設計）できます。
- 量子力学では、定義上、すべてが複素数値です（_どこまでも波形です_）。

__高速フーリエ変換アルゴリズム__。

- FFTは複素数の応用例で、音声の伝送、音声処理、写真、動画に関わる_あらゆるもの_に使われています。

- MP3などの音声フォーマットは圧縮にFFTを使い、より小さな記憶領域により多くの音声を収められるようにしています。
- JPEG圧縮やMP4動画をはじめ、他にも多くの画像・動画フォーマットが圧縮にFFTを使っています。

- FFTは、携帯電話の基地局が各自の携帯電話の信号を他の人たちの信号から分離するためのデジタルフィルターにも使われています。

つまり、1秒間に何千回も複素数計算に頼る技術を、おそらく使っていることになります。
