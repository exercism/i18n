# 概要

動的メモリは、プログラマーが実行時にメモリを確保したり解放したりするために使うライブラリ関数によって実現されます。
メモリの確保と解放をプログラマー自身が制御するため、動的メモリの安全性は、プログラマーがヒューマンエラーを起こさないかどうかにかかっています。
そのため、動的メモリはプログラミングのバグの主要な原因の一つであり、ハッキング攻撃の主要な標的でもあります。

動的メモリは、実行時にしかサイズがわからない変数に使われます。
これは、実行するたびに要素数が変わりうる配列でよく役立ちます。
可変長配列（VLA）は、要素のサイズが実行時にしかわからない配列を扱うもう一つの方法です。
VLAは自動記憶域を使うので、定義したブロックを抜けるとそのメモリは破棄されます。
（記憶域について詳しくは、[記憶域クラス指定子](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers)の概念を参照してください。）
VLAはC99でC言語に導入されましたが、C11以降はVLAは任意となったため、C11以降に対応するコンパイラーはVLAをサポートしなくてもよいことになっています。
可変長配列の詳細な分析は、この記事の範囲外です。

## malloc

`malloc`は`stdlib.h`で宣言されている関数で、動的メモリを確保するために使います。
確保に成功すると、確保したメモリの先頭バイトのアドレスを指すポインターが返されます。
確保に失敗すると、`NULL`が返されます。
`malloc`の結果が`NULL`でないか確認し、失敗した場合は適切に対処するのが賢明です。
返されるポインターの型は`pointer-to-void`で、これはおおまかに「汎用」ポインターと考えることができ、そのメモリで使う具体的な型に変換できます。
`malloc`の仮引数は一つで、確保したいメモリのサイズをバイト単位で指定します。
配列を確保するための合計サイズは、各要素のデータ型のサイズに要素数を掛けたものです。
各要素のデータ型のサイズを得るには、`sizeof`演算子をよく使います。
次の例はこれを示しています。

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

`malloc`で新しく確保したメモリは初期化されておらず、ゴミの値が入っている可能性があることを覚えておくことが大切です。
`numbers`ポインターの`sizeof`は、配列の要素数でも、確保したメモリの合計量でもないことに注意してください。
`malloc`が返すポインターのサイズは、そのシステムにおけるポインター一般のサイズです。
例のコードは64ビットシステムで実行されたので、ポインターのサイズは8バイトでした（1バイトにつき8ビットを掛けると64ビットになります）。
ポインターの型はpointer-to-voidからpointer-to-intへ暗黙的に変換されました。
pointer-to-intが単一の`int`を指すのか、`ints`の配列を指すのかは、プログラマーが適切だと思うように扱えます。
たとえば、次のようにします。

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

読み出す前に必ず値が書き込まれるのであれば、`malloc`を使うのは効率的なメモリ確保の方法になり得ます。
しかし、初期化される前に値が読み出される可能性があるなら、`malloc`の使用は危険です。
より安全なメモリ確保の方法は`calloc`を使うことで、これは新しく確保したメモリを0で初期化します。

上の例で`free(numbers)`が使われていることに注意してください。

## free

`free`は`stdlib.h`で宣言されている関数で、動的に確保したメモリを解放するために使います。
動的に確保したメモリは、`free`で解放されるまでメモリ上に確保されたままになります。
プログラムの終了時に動的に確保したメモリを自動的に解放するオペレーティングシステムもありますが、それに依存しないのがよい習慣です。
`free`の仮引数は一つで、動的に確保されたメモリへのポインターです。
`free`を使うか使わないかは、いくつかのメモリの問題と関係しています。

#### メモリリーク

動的に確保したメモリへの参照がその寿命の終わりに達したり、別の理由で破棄されたりしたあとに、そのメモリを解放しないことをメモリリークと呼びます。
リークしたメモリは、システムによって確保されたまま、プログラムからはもうアクセスできないメモリです。
ループの中でメモリを確保し、ループの終わりに解放せず、ループの先頭でまた確保する場合、これは特に問題になります。
解放されないまま十分な量のメモリが確保されると、確保に使えるメモリが足りなくなり、メモリ確保の呼び出しは失敗します。
動的に確保したメモリは解放されるまでシステムに確保されたままですが、それを代入したポインターはブロックスコープしか持たないことがある、ということを覚えておくことが大切です。
たとえば、`malloc`の例では、メモリは`my_function`の中で確保されています。
そのメモリへのポインターが返されて`main`の`numbers`ポインターの設定に使われなければ、そのメモリはリークしてしまいます。
こうして、その`numbers`ポインターを`free`に渡すことで、`my_function`で確保したメモリが解放されます。

#### 解放後の使用（**UAF**）

メモリを解放したあとにアクセスすると、その値は何であってもおかしくありません。
次の例では、`numbers`が指すメモリが解放されたあと、`printf`の中で読み出されています。

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

解放されたあとの`numbers`ポインターは、ダングリングポインターと呼ばれます。
ダングリングポインターは、本来意図したメモリとは別のメモリを指すことがあります。
そのため、ダングリングポインターはデータの破壊や、任意のコードの差し替えと実行につながる可能性があります。
`NULL`を設定してクリアしていない、確保済みメモリへのポインターは、プログラムをハッキングするために使われる可能性があります。
上の例で、解放後に`numbers = NULL;`のように`numbers`へ`NULL`を設定していれば、続く`printf`はプログラムの終了を引き起こし、`numbers[0]`を読み出そうとしたときにセグメンテーション違反を報告するかもしれません。

#### 二重解放

動的に確保したメモリへのポインターに対して`free`を二回呼び出すと、未定義動作（**UB**）になります。
これは、コンパイラーが好きなように任意に扱えるという意味です。
次の例を二つの異なるコンパイラーでコンパイルすると、二通りの異なる結果になり得ます。

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

一つ目と二つ目のコンパイラーでは、`free`の各呼び出しの間に`numbers`に`NULL`を設定すれば実行時エラーは発生しませんでしたが、三つ目のコンパイラーで同じように動作する保証はありません。
二重解放のよくある原因は、同じ動的に確保したメモリを指す二つのポインターを持ってしまうことです。
一方のポインターがプログラムのある場所で配列の先頭を指し、もう一方のポインターが別の場所で配列を順にたどるために使われることがあります。
プログラムの別々の場所でそれぞれのポインターが解放され、その結果として二重解放が起きます。

## calloc

`calloc`は`stdlib.h`で宣言されている関数で、動的メモリの確保と、新しく確保したメモリを0で初期化することの両方に使います。
確保に成功すると、確保したメモリの先頭バイトのアドレスを指すポインターが返されます。
確保に失敗すると、`NULL`が返されます。
`calloc`の結果が`NULL`でないか確認し、失敗した場合は適切に対処するのが賢明です。
返されるポインターの型は`pointer-to-void`で、これはおおまかに「汎用」ポインターと考えることができ、そのメモリで使う具体的な型に変換できます。
`calloc`の仮引数は二つあります。
一つ目の仮引数は、指定したデータ型をいくつ確保するかを指定します。
二つ目の仮引数は、確保する指定したデータ型のサイズを指定します。

次の例では、`calloc`が新しく確保した値を必ず0にするので、すべての`printf`文は常に`0`を表示するはずです。

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc`は`stdlib.h`で宣言されている関数で、すでに確保したメモリを拡張または縮小するために使います。
再確保に成功すると、再確保したメモリの先頭バイトのアドレスを指すポインターが返されます。
再確保に失敗すると、`NULL`が返されます。
`realloc`の結果が`NULL`でないか確認し、失敗した場合は適切に対処するのが賢明です。
`realloc`の仮引数は二つあります。
一つ目の仮引数は、再確保する既存のメモリへのポインターです。
二つ目の仮引数は、再確保するメモリのサイズをバイト単位で指定します。
メモリを拡張する前に設定された値は保持されます。
メモリを拡張したときに追加されるメモリは0で初期化されず、その値は何であってもおかしくないことを覚えておくことが大切です。
また、メモリを縮小したときに取り除かれるメモリも初期化されず、値を保持している可能性があります。
次の例は、配列の拡張と縮小を示しています。

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## 渡すサイズが0のとき

`malloc`、`calloc`、または`relloac`に渡すサイズが`0`の場合、どうなるかはコンパイラーがそれをどう実装しているかによります。
コンパイラーは`NULL`ポインターを返すことも、非NULLのポインターを返すこともあります。
たとえば、`char`へのポインターのためにメモリを確保する場合、コンパイラーは`NULL`を返すことも、空文字列への非NULLのポインターを返すこともあります。
コンパイラーによって結果が異なるのを避けるには、サイズ0で確保しないのが一番です。
