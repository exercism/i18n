## ごく簡単な歴史

コンピューターで文字を扱うのは、何十年も前にはもっとずっと簡単でした。当時のプログラマーは、英語だけが重要な言語だと考えていたからです。
つまり、大文字と小文字のアルファベット26文字、数字10文字、いくつかの句読点、それにベルを鳴らすためのコード（0x07）で、すべてが7ビットに収まりました。それがASCII文字セットです。

当然のことながら、àやä、Łはどうするのかという声が上がり、次にはऄやஹ、ญはどうなのかという声が上がり、若い人たちは絵文字😱を求めるようになりました。
どうすればよいのでしょうか？

手短に言えば、多くの賢く辛抱強い人たちが何年も委員会に参加し、Unicode文字セットやUTF-8などのエンコーディングの細部を詰めていきました。そして、多くのソフトウェアが_非常_に複雑な書き直しを必要としました。
さらに、たくさんの新しいバグも生まれました。

_すべて_が壊れるのを防ぐため、Unicode/UTF-8の設計では、最初の127個のコードがASCIIと同一になるようにしています（_ベルのコードまで_）。

## Juliaの文字

2005年頃以降に設計された言語には、妥当に安定したUnicode標準がすでに存在していたという大きな利点があります。

Julia（最初の公開は2012年）は、文字、文字列、変数名や関数名、数学演算子など、あらゆるものがUnicodeであると仮定できました。

マニュアルを引用すると、「Julia makes dealing with plain ASCII text simple and efficient, and handling Unicode is as simple and efficient as possible」となります。
「as possible」という部分に注目してください。これがこの記述の重要な点です。

***文字リテラルはシングルクォートで書き、ダブルクォートで書く文字列とは区別されます。***

C/C++の世界の人には当たり前ですが、PythonやJavascriptのプログラマーには戸惑うところかもしれません。

```julia-repl
julia> a = 'a'  # Roman alphabet
'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)

julia> typeof(a)
Char

julia> jha = 'झ'  # Devanagari alphabet
'झ': Unicode U+091D (category Lo: Letter, other)

julia> typeof(jha)
Char

julia> '❤'  # heart emoji
'❤': Unicode U+2764 (category So: Symbol, other)
```

例からわかるように、型は`Char`で、Juliaは文字のカテゴリについても詳しい情報を持っています。

よく見ると、これらの文字は4桁の16進数で表せるようです。
文字セット全体となると、最大6桁の16進数が必要になります。

これらの数は「コードポイント」と呼ばれ、現在はU+0000からU+10FFFFまでの範囲にあります。
REPLでは表示されますが、コードの中では`codepoints()`を使って取得します。

`Char`と`Int`の変換は簡単です。

```julia-repl
julia> Int('a')
97

julia> Char(97)
'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
```

コンパイラーは、`Char`に対する_一部の_整数演算を許しています。

```julia-repl
julia> 'b' - 'a'  # interval, in alphabetic order
1

julia> 'b' + 'a'
ERROR: MethodError: no method matching +(::Char, ::Char)

julia> 'a' + 5
'f': ASCII/Unicode U+0066 (category Ll: Letter, lowercase)

julia> 'f' + ('A' - 'a')  # same as `uppercase('f')`
'F': ASCII/Unicode U+0046 (category Lu: Letter, uppercase)
```

## 文字のための関数

文字列を扱う関数の多くは、`Char`の入力にも対応しています。

- 対応する文字体系であれば、`uppercase()`と`lowercase()`で大文字小文字を変換できます。
- 大文字小文字の判定には`isuppercase()`と`islowercase()`を使います。
- 文字の種類の判定には次の関数を使います。
  - `isletter()`は多くの文字体系をカバーします
  - `isdigit()`は厳密に0〜9かどうかを判定します
  - `isnumeric()`は`isdigit`より広く、¾やヨーロッパ以外のさまざまな文字体系でも`true`になります
  - `isxdigit()`は16進数の数字を判定します
  - `isascii()`はUnicode以前の文字を判定します
  - `ispunct()`は句読点を判定します
  - `isspace()`はあらゆる空白文字を判定します
  - `isprint()`は印字可能な文字を判定します（逆は`iscntrl()`です）

```julia
islowercase('A')  # false
uppercase('γ')  # 'Γ': Unicode U+0393 (category Lu: Letter, uppercase)
ispunct('@')  # true
isdigit('A')  # false
isxdigit('A')  # true
```

## CharのベクターとStringの相互変換

StringからCharのベクターへは、`collect()`を使います。

CharのベクターからStringへは、`String()`コンストラクターがあります。

```julia-repl
julia> s = "abcde"
"abcde"

julia> cv = collect(s)
5-element Vector{Char}:
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'b': ASCII/Unicode U+0062 (category Ll: Letter, lowercase)
 'c': ASCII/Unicode U+0063 (category Ll: Letter, lowercase)
 'd': ASCII/Unicode U+0064 (category Ll: Letter, lowercase)
 'e': ASCII/Unicode U+0065 (category Ll: Letter, lowercase)

julia> String(cv)
"abcde"
```

これはASCIIだけでなく、あらゆる文字で機能します。

```julia-repl
julia> collect("❤,😱")
3-element Vector{Char}:
 '❤': Unicode U+2764 (category So: Symbol, other)
 ',': ASCII/Unicode U+002C (category Po: Punctuation, other)
 '😱': Unicode U+1F631 (category So: Symbol, other)
```

`String()`コンストラクターはVectorに対して働くことに注意してください。
1文字の`Char`を1文字の文字列に_キャスト_するには、小文字の`s`の`string()`という関数を使います。

```julia-repl
julia> string('a')
"a"
```

## メモリー上での格納

ここまでに出てきた話はどれも比較的簡単に思えるので、本当に心配することはほとんどないのでしょうか？

残念ながら、それは楽観的すぎます！

1つの複雑さは、コードポイントごとに「最大」6桁の16進数が必要だという点から来ています。
つまり、UTF-8でエンコードすると、文字によってメモリー上で必要な容量が異なるのです。

1バイトで格納できるのは（符号なしで）255まで、つまり16進数2桁分です。そのためUTF-8では、`Char`を格納するのに可変のバイト数（1〜4）を使います。
これらは「コードユニット」と呼ばれ、`ncodeunits()`関数はある文字に必要な数を返します。

```julia-repl
julia> codepoint(jha)  # jha 'झ' is defined in an earlier example
0x0000091d

julia> ncodeunits(jha)
3

julia> ncodeunits('a')  # ASCII character
1

julia> ncodeunits('😱')  # emoji
4
```

また、画面に表示できるものすべてが、それぞれ固有のコードポイントを持つわけではありません。
見た目が異なる文字の中には、他の文字から派生したものとみなされるものがあり、Unicodeでは親となる文字と修飾子の組み合わせとして扱われます。
