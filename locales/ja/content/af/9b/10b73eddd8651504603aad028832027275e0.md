# テスト

テストの実行には、`cmake -G`を実行してから、お使いのプラットフォームに合ったビルドコマンドを使います。この方法の詳しい手順は、exercism.orgのC++向けの[Running the Tests][cpp-tests-instructions]ページにあります。

## テストに合格する

新しい演習をローカルで始めると、最初のテストだけが実行されるようにファイルが設定されています。まず、[テスト駆動開発の3つのルール][three-laws-of-tdd]に従って、最初のテストをコンパイルしてリンクし、合格させましょう。名前空間、関数、クラスなどを宣言して、コンパイラのエラーを解消し、テストが失敗する状態になるだけの最小限の構造を作ります。次に、テストに合格するだけの最小限のコードを書きます。それができたら、`if defined(EXERCISM_RUN_ALL_TESTS)`の行を次のテストの後ろに移動して、次のテストのコメントを解除します。

Bobの演習の例（ファイル`bob_test.cpp`、15行目）を見てみましょう。

```diff
-#if defined(EXERCISM_RUN_ALL_TESTS)
TEST_CASE("shouting")
{
    REQUIRE("Whoa, chill out!" == bob::hey("WATCH OUT!"));
}
+#if defined(EXERCISM_RUN_ALL_TESTS)
```

この行を次のテストの後ろに移動すると、まだ宣言も定義もしていない新しい構文が呼び出されて、コンパイルエラーになることがあります。ここでも、まずコンパイルエラーを最小限に修正してテストを失敗させ、次にコードを最小限に変更してテストに合格させます。そして、読みやすさと表現力を高めるために実装をリファクタリングし、次のテストに進みます。

独自の低レベルなアルゴリズムや機能を自分で書くよりも、標準のC++17の機能を使うようにしましょう。
