# はじめに

関数型プログラミングとは何でしょうか？

ここでは、いくつかの重要な特徴を挙げます。

- 純粋関数。入力から出力へ、副作用なしに一貫して対応付けます。
- 不変データ。
- 第一級関数。他の型と同じように値として扱えます。
- 高階関数。他の関数を引数として、または戻り値として受け取ります。

ただし、Rは純粋な関数型言語ではありません（たとえばHaskellとは対照的です）。

Rは実用的な言語と捉えましょう。（ますます）関数型の機能を提供し、それが仕事を片付けるためのクリーンで簡単な手段となる場面で役立ちます。
一般に、目標はデータ分析であり、プログラミングはそのための手段にすぎません。

## パイプ

関数をつなぐパイプ`|>`の使用は、いくつかの言語でますます一般的になっている手法です。

簡単に言うと、次のとおりです。

- パイプの左側の結果が、右側の関数の最初の引数になります（ここで「右側」とは任意の改行を無視したものを指します）。
- 残りの引数は関数呼び出しに含めることができます。
- Rでは、関数の_名前_だけでなく関数_呼び出し_にパイプする必要があるため、常に括弧（`()`）が必要です（_これは他の言語とは異なります_）。

コードを読むときに、パイプを「次に」と読むとわかりやすいと感じるプログラマーもいます。ステップ1をして、次にステップ2をする、という具合です。

次の例は、この構文を示しています。

```R
library(stringr)

"Monday-25-February" |> 
  str_split("-") |>     
  unlist() |>               # [1] "Monday"   "25"       "February"
  str_sub(1, 3) |>          # [1] "Mon" "25"  "Feb"
  str_to_upper() |>         # [1] "MON" "25"  "FEB"
  str_flatten(collapse = ", ")
#> [1] "MON, 25, FEB"
```

このタイプのパイプはv4.1.0でBase Rに追加されました。「ネイティブパイプ」と呼ばれることもあります。

RStudioのエディターなどでは、`Ctrl-Shift-M`が、適切なスペース付きでパイプを追加するキーボードショートカットとして使われています。

## apply系の関数

以前見たように、Rの多くの関数は「ベクトル化」されています。明示的なループを書かなくても、ベクトル全体に作用します。

ベクトル化された関数だけを使っている関数は、それ自体も自動的にベクトル化される可能性が高いです。
簡単な例を見てみましょう。

```R
triple <- function(x) return(3 * x)
triple(1:10)
 [1]  3  6  9 12 15 18 21 24 27 30
 ```

しかし、より複雑な関数はベクトル入力を受け付けないことがあります。たとえば、ループやif-elseブロックを含む場合です。

ベクトルに関数を適用する、より一般的な方法が必要です（他の言語の`map()`に似ています）。

Rの基本言語には多様で豊富なデータ構造があるため、それらを操作する`*apply()`関数のファミリーも存在します。
より専門的には、これらは関数を引数として受け取るため、プログラマーは「高階関数」、数学者は「汎関数」と呼ぶことがよくあります。

ここでは、`lapply()`と`sapply()`を見てみましょう。

### `lapply()`

「List-apply」はリストの入力に対して動作するよう設計されていますが、必要に応じてベクトルは暗黙のうちにリストに変換されます。

出力はリストなので、ベクトルを得るには展開が必要になることがあります。

```R
h <- function(size) {
    switch(size,
           "small" = 6,
           "medium" = 8,
           "large" = 10
    )
}

v <- c("small", "large", "medium")

h(v) # bad use of an unvectorized function
#> Error in switch(size, small = 6, medium = 8, large = 10) : 
#>   EXPR must be a length 1 vector

lapply(v, h)  # output is a list
#> [[1]]
#> [1] 6

#> [[2]]
#> [1] 10

#> [[3]]
#> [1] 8

lapply(v, h) |> unlist() # output is a vector
#> [1]  6 10  8
```

[Switchのコンセプト][concept-switch]に親しんでいる方は、スカラーの`switch`を、[`dplyr`][ref-dplyr]ライブラリのベクトル化された[`recode_values()`][ref-recode_values]に置き換えることもできると気づくかもしれません。
ベクトル化は良いことであり、現代のRはそれを実現する複数の方法を提供しています。

```R
library(dplyr)

h <- function(size) {
  recode_values(size,
         "small" ~ 6,
         "medium" ~ 8,
         "large" ~ 10
  )
}

v <- c("small", "large", "medium")
h(v)
#> [1]  6 10  8
```

### [`sapply()`][ref-lapply]

「Simplified-apply」は`lapply`と似たことをしますが、戻り値の簡略化も試みます。たとえば、リストではなく名前付きベクトルを返します。
状況によっては、[`unname()`][ref-unname]を使う必要があるかもしれません。

```R
sapply(v, h)
 small  large medium 
     6     10      8 

sapply(v, h) |> unname()
#> [1]  6 10  8
```

## `purrr`ライブラリ

`lapply`と`sapply`はシンプルで、ほとんどのRユーザーにとって親しみやすく、ベクトルや単純なリストに対して今でもかなり人気があります。

Base Rには、他にも_たくさん_のapply系関数があります。
この種の混乱に対して、よりシンプルで一貫性のある代替を提供することが、Tidyverseの重要な目標です。

現在では`purrr`パッケージがあり、`map()`のようないくつかの追加オプションを提供しつつ、設計の一貫性とエラーメッセージの明瞭さを向上させています。

このパッケージは、base Rよりも後方互換性に縛られていないため、他の言語に見られる現代的な関数型プログラミングにRを大きく近づけます。

`purrr`には多様で多くの関数があり、簡単にはまとめられません。
ライブラリを理解するのに役立つリソースには、次のようなものがあります。

- [ウェブサイト][web-purrr]。ここには[はじめかた][web-starting]ガイドもあります。
- すべての関数の[リファレンスページ][ref-purrr-funcs]。
- PDF形式の[チートシート][cheat-purrr]。
- [Base R][web-from-R]からの変換ガイド。

### さまざまなmap系関数

[map()][ref-map]関数は、入力の各要素に関数を適用し、常に[リスト][concept-lists]を返します。

ここまでは、名前が変わっただけで、おそらくエラーメッセージが良くなっただけの[`lapply()`][ref-lapply]のように聞こえます。

しかし、`map()`は_大きな_ファミリーの一員にすぎません。

関数を選ぶときに考えるといい質問がいくつかあります。

- 何を返したいですか？　[`map()`][ref-map]は常にリストを返しますが、特定の型の原子ベクトルが欲しい場合は、文字列には[`map_chr()`][ref-map_chr]、整数には[`map_int()`][ref-map_int]などを使います。
- 入力の各位置インデックスが必要ですか？　[`imap()`][ref-imap]のように、関数名の前に`i`を付けます。
- 複数の入力を並行して処理したいですか？
  - 名前の`map`を`map2`に置き換えます。2つの入力（たとえば値と重みで加重平均を計算する）に対する[`map2_dbl()`][ref-map2_dbl]のように。
  - 並行する入力のリストには`pmap`に置き換えます。[`pmap_chr()`][ref-pmap_chr]のように。そう、ハードウェアレベルの並列処理も可能です。
- 入力のすべての要素を処理したいですか？　そうでない場合は、述語（真偽値）フィルターを適用する[`map_if()`][ref-map_if]、位置インデックスの条件を指定する[`map_at()`][ref-map_at]、要素が述語を満たさなくなるまで入力を処理する[`head_while()`][ref-head_while]を検討します。
- 入力データが深く入れ子になっていますか？　そのような状況に対応する[関数][ref-plucks]があります。
- 戻り値を常に入力と同じ型にしたいですか？　`map`の代わりに[`modify()`][ref-modify]関数を、再帰的な適用には[`modify_tree()`][ref-modify_tree]を使います。

これらの関数は、パイプとうまく連携するように、可能な限り入力データを最初の引数に取ります。

また、`purrr`は（意図的に）Base Rよりも細かく厳格です。何か特定のものを要求すれば、関数は_まさに_それを返すか、エラーメッセージを出して停止します。
厳しいですが、見つけにくいバグを減らすのにはとても効果的です。

### reduce系の関数

map系の関数は、一般に入力と同じ長さの戻り値を持ちます。

他の関数の中には、データの次元を_減らす_ものがあります。たとえば`sum()`です。

```R
sum(1:100)
#> [1] 5050
```

上の例では、長さ100のベクトルを長さ1の整数に変換しています。
行列と配列に関する今後のコンセプトで、次元の削減という考え方がより一般的であることを見ていきます。

`sum()`関数は組み込みです（他の多くの統計関数も同様です）。
しかし、`map()`に相当する何らかの高階関数を使って、任意の次元削減関数をデータ構造全体に適用する方法が必要です。

他のいくつかの言語では、`fold`、`foldl`、`foldr`といった関数名が使われます。Rでは、該当する関数は[`reduce()`][ref-reduce]で、（アルゴリズム好きには）よく知られたMapReduceフレームワークに対応します。

最初の引数は、いつもどおり入力データです。2番目の引数は2引数の関数で、多くの場合匿名関数ですが、`+`のような算術演算子程度にシンプルなこともあります。

```R
# surround an infix operator with backticks, to use as a function
reduce(1:100, `+`)
#> [1] 5050  # same as sum(1:100)

# anonymous function, alternately add and subtract
reduce(1:10, \(accum, nextval) ifelse(nextval %% 2 == 0, accum + nextval, accum - nextval))
#> [1] 7
```

関数を入力の先頭から適用するか末尾から適用するかは、重要でしょうか？

`+`や`*`のような[結合的][wiki-associative]な演算子では重要ではありません。
明らかに、`(1 + 2) + 3 == 1 + (2 + 3)`です。

対照的に、`-`と`/`は結合的ではありません。

```R
(1 - 2) - 3
#> [1] -4
1 - (2 - 3)
#> [1] 2
```

方向が重要な関数には、省略可能な`.dir`引数があります。

```R
# default is .dir = "forward"
reduce(1:10, `-`)
#> [1] -53
reduce(1:10, `-`, .dir = "backward")
#> [1] -5
```

`map()`や`map2()`と同様に、2つの入力ベクトルを並行して操作する[`reduce2()`][ref-reduce]関数もあります。

Rでは、ベクトルを扱うのが好みです。最終的な単一の値ではなく、途中のすべてのステップを見たいとします。

そのためには、対応する関数として[`accumulate()`][ref-accumulate]と`accumulate2()`があります。
構文は`reduce()`に似ていますが、出力型を指定するための追加の省略可能な引数がいくつかあります。

```R
accumulate(1:10, `+`)
#> [1]  1  3  6 10 15 21 28 36 45 55
```

よくあるaccumulateの種類には、それぞれ専用の関数があります。
[ベクトル関数][concept-vector-functions]のコンセプトでは、Base Rの[`cumsum()`][ref-cumsum]と`cumprod()`を扱いました。また、`dplyr`ライブラリには、数値の平均のための[`cummean()`][ref-dplyr-cum]、論理ベクトルのための`cumall()`と`cumany()`があります。

### フィルター関数

よくあるのは、何らかの述語に一致する入力の要素を含めたい（または除外したい）場合です。

[ベクトルのフィルタリング][concept-vector-filtering]のコンセプトで、これを行う1つの定型的な方法を見ました。

```R
v <- 1:3
v[v >= 2]
#> [1] 2 3
```

これは伝統的なRでよく使われますが、現代的な関数型のパイプラインにはあまりなじみません。

そのため、`purrr`は[述語関数][ref-predicates]のセットを提供しています。これらはパイプと連携するために、`f(input, func, ...)`という通常の引数の慣習に従います。

名前は他のほとんどの言語とは少し異なります（`filter`や`drop`のような名前は、Rではすでにまったく別の意味を持っています）。

対応する`purrr`の関数には、[`keep()`][ref-keep]と[`discard()`][ref-keep]、その他いくつかがあります。

また、単一の論理値を返す`all()`や`any()`の代わりに、[`every()`][ref-every]、[`some()`][ref-every]、[`none()`][ref-every]があります。
