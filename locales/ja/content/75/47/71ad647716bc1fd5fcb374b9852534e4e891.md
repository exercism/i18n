# テスト

各演習にはユニットテストが用意されています。
実装を書くのは皆さん自身です。
テストのファイルはそれぞれ、テストを実行するコンソール用の実行ファイルを生成します。
テストの実行ファイルを動かすと、失敗したテストごとにメッセージが表示され、テストが失敗したときは終了ステータスが0以外になります。

*注意* プロジェクトをビルドするたびに、コードはテストスイートで検証されます。
1つ以上のテストに通らなくても、有効なDのコードであればコンパイルは通ります。

各演習を進める流れは、次のとおりです。

* `dub test`でテストを実行します
  * DUBをインストールしない場合は、代わりに`dmd source/*.d -de -w -main -unittest`を使い、そのあと生成されたバイナリを実行します。
* それぞれのユニットテストごとに、次のことを行います。
  * コンパイルエラーを解消して、まずテストを失敗させます。
  * テストに通るだけの最小限の実装を書きます。
  * 読みやすさを高めたり重複を減らしたりするために、実装をリファクタリングします。
  * 次のテストを有効にします

*注意:* Dには言語自体にユニットテストの仕組みがあるので、通常ユニットテストは実装と同じファイルに置きます。
ユニットテストは`main`の本体より前に実行され、最終的な実行ファイルでは**-unittest**コンパイラスイッチで有効になります。

## ユニットテストの出力を読み取る

すべてのテストが成功すると、テストの出力は次のようになります。

```none
$ dub test
             Generating test runner configuration 'dnd-character-test-library' for 'library' (library).
    Starting Performing "unittest" build using dmd for x86_64.
    Building dnd-character ~master: building configuration [dnd-character-test-library]
     Linking dnd-character-test-library
     Running dnd-character-test-library
1 modules passed unittests
```
