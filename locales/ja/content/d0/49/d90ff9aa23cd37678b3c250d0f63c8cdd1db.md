# 概要

プログラマーは完璧なソフトウェアを書こうとしますが、たいていは失敗します。

物事は思わぬ形でうまくいかなくなるもので、それに対処できる必要があります。

言語設計者の中には、できるだけ早くエラーを検出し、デバッグに役立つ情報メッセージとともに実行を終了させることを優先すべきだと考える人もいます。

データサイエンス向けの言語は、よりきめ細やかなアプローチを取る傾向があります。中には即座に終了させる必要があるほど深刻なエラーもありますが、多くの場合、問題を後で対処するものとして示しておき、実行を続けるほうがよいのです。

[Nothingness][nothingness]コンセプトで、Juliaが問題のある値のためにさまざまなプレースホルダーを用意していることを見ました。[`missing`][nothing]、[`NaN`][NaN]、`Inf`です。これらが特定の状況でプログラムを終了させるよりもよいアプローチかどうかは、プログラマーの判断次第です。

詳細に入る前に、用語についてひと言。「エラー」と「例外」という言葉は、Juliaのドキュメントではほぼ同じ意味で扱われています。以下の内容も、同じくらい一貫性がないかもしれません。

## 標準のエラー型

シラバスのこの時点まで来れば、Juliaからのエラーメッセージをたくさん見てきたはずです。たとえば次のとおりです。

```julia-repl
julia> Int(3.14)
ERROR: InexactError: Int64(3.14)
```

小数を整数にキャストすると精度が失われるため、`InexactError`が発生します。

`InexactError`は型のひとつで、Juliaに標準で組み込まれているいくつかの型（[現在は25種類][errors]）のうちのひとつです。これらはすべて`Exception`のサブタイプです。

```julia-repl
julia> supertype(InexactError)
Exception
```

## `throw()`

標準のエラー型の中には、自分のコードで生成すると役に立つものもあります。

すべての具象型と同様、これらのエラーにはコンストラクターがあります。引数はさまざまなので、使いたいものについては[ドキュメント][errors]を確認してください。

```julia-repl
julia> DomainError(42, "out of range")
DomainError(42, "out of range")
```

エラーを使うには、コンストラクターを[`throw()`][throw]関数で包みます。

```julia-repl
julia> throw(DomainError(42, "out of range"))
ERROR: DomainError with 42:
out of range
```

## `error()`

手っ取り早く済ませたいときは、[`error()`][error]関数が便利です。引数として文字列（または文字列の構成要素）を取ります。

```julia-repl
julia> happy = false;
julia> happy || error("😞 something went wrong")
ERROR: 😞 something went wrong
```

## カスタムエラー

新しいエラー型を作るのは、原理的にはとても簡単です。`Exception`のサブタイプをもうひとつ追加するだけです。

```julia-repl
julia> struct MyError <: Exception end

julia> throw(MyError)
ERROR: MyError
```

ただし、上の例にはフィールドがなく、コンストラクターも引数を取りません。そのため、エラーメッセージを制御できません。メッセージ用のフィールドを追加できます。

```julia-repl
julia> struct AnotherError <: Exception
           msg::String
       end

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError("Wrong!")
```

単にコンストラクターを表示するだけでは、まだ十分ではありません。先ほど`DomainError`を投げた例と比べてみましょう。

カスタムエラーを組み込みエラーと同じように扱ってもらうには、[`showerror()`][showerror]メソッドを追加する必要があります。

```julia-repl
julia> Base.showerror(io::IO, e::AnotherError) =
           print(io, "AnotherError: ", e.msg)

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError: Wrong!
```

このあまり文書化されていない機能は、本質的に、自作のエラー型をJuliaの標準的なエラー処理システムに組み込むものです。

## アサーション

アサーションの基本的な考え方は、「この命題は真であるはずで、偽なら大きな声で文句を言う」というものです。これが役に立つのは主にデバッグ中で、本番コードではアサーションが失敗してはいけないからです。

[Types][types]コンセプトで、たとえば関数の戻り値の型を確認するために、型アサーションを追加できることを見ました。

```julia-repl
julia> 42::Number
42

julia> "two"::Number
ERROR: TypeError: in typeassert, expected Number, got a value of type String
```

より一般的には、[`@assert`][assert]マクロを使うと、真偽値に評価される任意の式をテストできます。

```julia-repl
julia> n = 22;
julia> @assert isodd(n) "n must be odd"
ERROR: AssertionError: n must be odd
```

## `try`...`catch`

中には避けようのない致命的なエラーもありますが、多くの場合、プログラムがうまく復帰することを期待します。

デフォルトでは、エラーは現在の関数を直ちに終了させ、そのエラー（および付随する情報メッセージ）は呼び出し元の関数に渡されます。

これはコールスタックをさかのぼって続き、最終的に最上位のコードがエラーメッセージを出して終了します。

どの段階でも、エラーを処理しようとする[`try...catch`][try-catch]ブロックでエラーを捕まえることができます。

```julia-repl
julia> n = -1;
julia> try
           log_n = log(n)
       catch problem
           if problem isa DomainError # number out of range
               # See next section for more on @warn and @info
               @warn "you may have supplied a negative real number: $n"
               @info "trying with complex argument"
               log_n = log(Complex(n))  # fallback calculation

           elseif problem isa MethodError # no idea what n is
               @error "please supply a valid argument"
 
           else
              rethrow() # the error could be anything else
           end
      end
┌ Warning: you may have supplied a negative real number: -1
└ @ Main REPL[3]:5
[ Info: trying with complex argument
0.0 + 3.141592653589793im  # success
```

上の例では、`log(n)`は`n`が正の実数値か、任意の複素数値であることを必要とします。`try ... catch`は負の実数値による問題を受け止め、数学的表記で正しい複素数の答え`iπ`を返します。

たとえば文字列を引数として渡した場合、ユーザーに修正を求める以外に復帰する方法はありません。

最後の受け皿として、`DomainError`でも`MethodError`でもないものすべてに対して[`rethrow()`][rethrow]を追加しました。

さらに、省略可能な節もあります。

- [`else`][else]。`try`節が成功したときに実行されます。
- [`finally`][finally]。`try`の成否にかかわらず、外部リソースの後片付けに使えます。ファイルを閉じる、データベース接続を切断するなどです。

**注:** `try...catch`が必要な場合もありますが、使いすぎは避けてください。代わりに`if...else`ブロックを使えるなら、例外を捕まえるよりもはるかに性能がよくなります。

## ログ

上で説明した`error()`関数を、[`@error`][error_macro]マクロと混同しないでください。

この関数は例外を生成し、捕まえられない限りコールスタックをさかのぼって渡されます。

`@error`マクロは、対応する[`@debug`][debug_macro]、[`@info`][info_macro]、[`@warn`][warn_macro]とともに、[`Logging`][logging]モジュールの一部であり、プログラムの流れを変えずに情報メッセージを生成するためのものです。

出力はデフォルトでターミナルに送られ（重要度に応じて色分けされます）が、実際のアプリケーションでは他にも多くの可能性があります。

```julia-repl
julia> @warn "Something looks not quite right"
┌ Warning: Something looks not quite right
└ @ Main REPL[55]:1

julia> @error "Panic!"
┌ Error: Panic!
└ @ Main REPL[56]:1
```

`try...catch`のところにある前の例も参照してください。
