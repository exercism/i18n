# はじめに

**ループ**とは、終了条件を満たすまで、何度も実行される可能性のある命令の並びのことです。

x86-64では、ループは通常、直前のラベルへのジャンプで作ります。

```x86asm
example_loop:
    ...
    jmp example_loop
```

なお、直前のラベルへの無条件ジャンプは、必ずそのラベルに実行を移します。
つまり、繰り返す範囲の外へ抜ける別のジャンプがない限り、そのループは永遠に繰り返されます。

たとえば、次のループは終わりません。

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

そして、次のループは、条件が満たされるかどうかによって終わることもあります。

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## カウントループ

カウントループの終わり方は、ほとんどいつも同じです。カウンターを更新するか、2つの値を比較する命令があり、そのすぐ後に、もう一度繰り返すかどうかを決める条件付きジャンプが続きます。

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
上のコードでは`cmp rsi, 0`は必要ありません。`sub rsi, 1`が、結果が`0`のときにすでに`zero flag (ZF)`を設定するからです。

アセンブリで条件を判定する主な方法は`cmp`ですが、多くの命令がフラグを更新します。
たとえば、多くの整数演算命令やビット演算命令は、結果が`0`のときは`ZF`を、結果が負のとき（つまり最上位ビットが1のとき）は`SF`を更新します。

どの命令がどのフラグに影響するかは、[リファレンス][reference]で確認できます。

[reference]: https://www.felixcloutier.com/x86/
~~~~

上の例では、`rsi`は`0`より大きいと仮定していることに注意してください。
もし`0`だった場合、`sub rsi, 1`によって`rsi`は`-1`になり、これは符号なしでは非常に大きな数になります。
ループがようやく終わるまでに、あと`18,446,744,073,709,551,615`回の繰り返しが必要になります。
また、配列の長さが`0`なので、どのようなメモリアクセスも範囲外になります。

配列の長さについて何も保証がない場合は、よく使われる方法が2つあります。

1つ目は、終了条件をループの先頭に移し、最後に無条件ジャンプを置く方法です。

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

2つ目は、ループの先頭で、長さが0の配列かどうかを一度だけ判定する方法です。

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

この2つ目の方法は、ループ本体の分岐が少ないため、通常は1つ目より効率的です。
これについては、今後のコンセプトで詳しく学びます。

~~~~exercism/advanced
状況によっては、現代のCPUは2つの異なる命令を1つの操作にまとめることができます。
この最適化は**マクロフュージョン**と呼ばれます。

`sub`や`add`など多くの算術命令、そして`cmp`や`test`は、直後に続く条件付きジャンプとよく融合します。
つまり、`cmp rax, rdx`のような命令の直後に条件付きジャンプが続く場合、CPUはそれを通常1つの操作として扱えます。

マクロフュージョンはCPUに依存し、どの命令がどの条件付きジャンプと融合するかには多少の違いがあります。

役に立つ資料として、[The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]があります。
[Intel optimization reference manual][intel-opt]のセクション3.4.2.2（Optimizing for Macrofusion）にも、Intel CPUで融合可能なペアが載っています。

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
