# Nil

Crystalには[`Nil`][nil]という型があり、値は`nil`の1つだけです。
値が存在しないことを表すために使われ、ほかの言語の`null`や`None`に似ています。

`nil`はさまざまなメソッドから返されることがあります。たとえば[`String#[]?`][string-index]は、インデックスが範囲外の場合に`nil`を返します。

```crystal
"foo"[10]? # => nil
```

Crystalには**NULL参照チェック**と呼ばれる仕組みがあり、デフォルトではどの型も`nil`になりません。
つまり、明示的に`Nil`型として宣言しない限り、変数に`nil`を代入することはできません。
これは、コンパイラーがnull参照を自動的にチェックしてくれるということでもあります。

## Falsey value

`nil`の値を扱うには、いくつかの方法があります。
`nil`はfalseyな値で、`false`も同じです。
つまり、falseyまたはtruthyな値が期待される文やその他の場所では、`false`と同じように扱われます。

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

つまり、`nil`になりうる変数の値が`nil`の場合、truthy側の分岐は実行されません。

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Check for nil

Crystalには、値が`nil`かどうかを確認するためのメソッドがあります。
[`nil?`][nil?]というメソッドで、すべてのオブジェクトで使えます。

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

値をそのまま`if`文で使う場合とは、少し違います。先ほどの例では、`false`も`nil`も偽として扱われていました。
ここでは`nil`だけがfalseyとして扱われます。値が`false`だったとしても`nil`ではないので、`nil?`はfalseを返し、つまりtruthyとみなされるからです。

## Or operator

`nil`を扱うもっとも簡単な方法は、そもそも`nil`にならないようにすることです。
or演算子（[`||`][or]）は、`Bools`を扱うときによく使われますが、正しく理解すれば`nil`の扱いにも使えます。
or演算子は、1つ目の値がtruthyかどうかを調べ、そうでなければ2つ目の値を使います。
これを使うと、値が`nil`ならfalseyなので、2つ目の値が使われるようにできます。

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
この方法は最後の手段と考えるべきで、値が`nil`でないと**確信**できる場合にだけ使ってください。
可能であれば、ほかの方法を使ってください。
~~~~

[`not_nil!`][not_nil]は、値が`nil`ではないとコンパイラーに伝えるためのメソッドで、これによりその値の型は`nil`になりえない型になります。
値が`nil`の場合は例外を発生させることで、これを実現します。

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
