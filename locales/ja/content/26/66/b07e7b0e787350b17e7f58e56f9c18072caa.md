# 概要

## 文字

[文字エンコーディング][char-encoding]とは、自然言語のテキストの要素をバイト列として表現するための、特定の取り決めのことです。
ここでいう「テキストの要素」とは、自然言語において意味を持つ任意の単位を指します。たとえば、文字、空白、句読点、絵文字、表意文字などです。

NASM（The Netwide Assembler。このトラックで使われているアセンブラーです）は、[ASCII][ascii]を使ったデータの定義に対応しています。

NASMの文字定数は最大8バイトで、シングルクォート（`'`）、ダブルクォート（`"`）、またはバッククォート（`` ` ``）を使って定義できます。

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

特殊文字はバッククォートで定義し、`\`でエスケープする必要があります。

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASMは、[UTF-8][utf8]の[Unicode文字][unicode]にも対応しており、`\u`または`\U`をバッククォート内で指定します。

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

x86-64では、どの文字エンコーディングも独立した型としては標準でサポートされていないことに注意してください。
アセンブリにおけるデータはバイト列であり、そのバイト列を文字、数値、その他何として解釈するかは、プログラマーに委ねられます。

たとえば、ASCII文字の'0'は値48の1バイトです。
つまり、48を1バイトに格納することは、ASCII文字の'0'を格納することとまったく同じです。

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

同じ理由から、文字の操作は、こうしたバイトの値を直接変換することで行います。

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## 文字列

[文字列][string]とは、文字の並びです。
アセンブリでは、通常は配列として実装されます。

NASMでは、他の配列を宣言するのと同じようにして文字列を宣言できます。

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

文字列と他の配列の違いのひとつに、NASMでは値をカンマ（`,`）で区切らずに文字列を宣言できるという点があります。
カンマで区切って値を並べることもできます。

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

すでに述べたように、文字はただのバイト（Unicodeエンコーディングではバイト列）であることに注意してください。

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

各ASCII文字は1バイトを占めるため、それより大きなサイズで見たときの後続のバイトは`0`になります。
たとえば、`'a'`をqword（8バイト）として宣言すると、最初のバイトが`'a'`（`97`）で、残りの7バイトはすべて`0`になります。

このため、次はすべて同じ意味になります。

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
アセンブリでは、文字列はASCIIのNUL文字（値`0`）で自動的に終端されるわけではありません。

Cのような高水準言語とやり取りする場合、必要に応じて正しい終端文字を文字列の末尾に付けるのはプログラマーの責任です。
~~~~

## 文字列命令

文字列は配列なので、メモリを明示的に逆参照することで、他の配列と同じように扱えます。

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

さらに、メモリ上のバイト列に対して値を読み込み、移動、格納するための命令がいくつかあります。
これらは_文字列命令_と呼ばれますが、メモリ上の任意のバイト列、つまり任意の配列に対して使えます。

| 命令         | 動作                                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | `rsi`が示すメモリ位置から`rax`に値を読み込む                                                                      |
| [stos][stos] | `rax`の値を`rdi`が示すメモリ位置に格納する                                                                        |
| [movs][movs] | `rsi`が示すメモリ位置から値をコピーし、`rdi`が示すメモリ位置に格納する                                            |
| [cmps][cmps] | `rsi`が示すメモリ位置の値と`rdi`が示すメモリ位置の値を比較する                                                    |
| [scas][scas] | `rax`の値と`rdi`が示すメモリ位置の値を比較する                                                                    |

これらの命令は、明示的なオペランドを_取りません_。
オペランドは暗黙的です。

おおよその目安として、次のとおりです。

1. ソースオペランドがメモリ位置の場合、そのアドレスは`rsi`に格納します（`s`はsourceのs）。
2. デスティネーションオペランドがメモリ位置の場合、そのアドレスは代わりに`rdi`に格納します（`d`はdestinationのd）。
3. オペランドの一方がメモリ位置でない場合、それは`rax`レジスタです。

これらの命令は、実行する具体的な操作に応じて、メモリアドレスを自動的に逆参照することに注意してください。

これらはすべて、異なるサイズで動作できます。
サイズを示すために接尾辞が付きます。

| 接尾辞 | 意味       | サイズ   |
| :----: | ---------- | :------- |
|  `b`   | バイト     | 1バイト  |
|  `w`   | ワード     | 2バイト  |
|  `d`   | ダブルワード | 4バイト  |
|  `q`   | クアッドワード | 8バイト  |

たとえば、次のとおりです。

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

また、これらの命令は、使ったアドレスを操作のサイズだけ更新します。
この更新は、**方向フラグ（DF）**の値に従って行われます。

- `DF`がクリアされている場合、アドレスは操作のサイズだけ_増加_します。
- `DF`がセットされている場合、代わりにアドレスは同じ分だけ_減少_します。

System V ABIでは、関数に入った時点で方向フラグをクリアしていなければならないと定められています。
つまり、_メモリは既定でアドレスの昇順に読み書きされます_。

[cld][cld]命令を使うと方向フラグをクリアでき、[std][std]命令を使うとセットできます。

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
System V ABIに従い、呼び出し側は、呼び出した関数が戻ったあとに`DF`がクリアされていることを期待します。
`DF`をセットした場合は、必ず`ret`の前にクリアしてください。
~~~~

### Lods

この命令は、`rsi`にアドレスがあるメモリ位置から_読み込み_、その値を`rax`にコピーします。

`rsi`の値は、読み込んだバイト数だけ更新されます。

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

この命令は、`rax`の値をコピーし、`rdi`にアドレスがあるメモリ位置に_書き込み_ます。

`rdi`の値は、書き込んだバイト数だけ更新されます。

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

この命令は、`rsi`にアドレスがあるメモリ位置から_読み込み_、その値を`rdi`にアドレスがあるメモリ位置に_書き込み_ます。
`rax`の値はこの命令の影響を受けません。

`rsi`と`rdi`はどちらも、一方のメモリ位置からもう一方へコピーしたバイト数だけ更新されます。

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

この命令は、`rsi`にアドレスがあるメモリ位置から_読み込み_、`rdi`にアドレスがあるメモリ位置からも_読み込み_ます。
そして値を比較し、`cmp`と同じようにフラグを更新します。

`rsi`と`rdi`はどちらも、両方の位置から読み込んだバイト数だけ更新されます。

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

この命令は、`rax`の値と、`rdi`にアドレスがあるメモリ位置から_読み込んだ_値を比較します。
そして`cmp`と同じようにフラグを更新します。

`rdi`の値は、読み込んだバイト数だけ更新されます。

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

これらとは別に、[rep][rep]命令はメモリと直接やり取りしません。
代わりに、先に挙げた他の命令の前に接頭辞として付けられ、その命令を_繰り返し_ます。

`rep`を付けると、文字列命令は`rcx`の値と同じ回数だけ繰り返されます。
繰り返すたびに、`rcx`の値は`1`ずつ減ります。
命令を使う前に`rcx`の値を設定しておく必要があることに注意してください。

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

`rcx`をカウンターとして使うほかにも、`repe`（または`repz`）と`repne`（または`repnz`）は、`zero flag (ZF)`がそれぞれクリアまたはセットされていると、実行を停止します。

| 命令             | 付けられる場所         | 早期に停止するか        |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`、`lods`、`stos` | いいえ                  |
| `repe`、`repz`   | `cmps`、`scas`         | はい、ZFが0になると停止します |
| `repne`、`repnz` | `cmps`、`scas`         | はい、ZFが1になると停止します |

~~~~exercism/advanced
現代のCPUでは、`rep movs`と`rep stos`は、大きなブロックでデータを移動するときにたいてい高速な選択肢です。
しかし、他の文字列命令や、`rep`なしで動かす`movs`や`stos`は、たいていは素のループより遅くなります。

この話題についてより詳しくは、[こちらの参考書の第16.9章「文字列命令」][agner-optimization-guide]を参照してください。
