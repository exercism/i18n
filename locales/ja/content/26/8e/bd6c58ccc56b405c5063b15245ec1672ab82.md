# 概要

Go 1.18で、Goは**ジェネリクス**をサポートしました。
ジェネリクスを使うと、コードを重複させることなく、さまざまな型で動作する関数やデータ構造を書くことができます。

## なぜジェネリクスが必要なのでしょうか？

Goでは、関数や型は通常、`int`や`string`といった特定の型で動作します。
ジェネリクスが登場する前は、複数の型を扱う方法が2つありました。
1つ目は、`SumInts`や`SumFloats`のように、名前の異なる複数の関数を書く方法です。
この方法では、メンテナンスが難しい重複したコードが生まれてしまいます。
2つ目は、空のインターフェース`any`（`interface{}`）を使う方法です。
しかし、空のインターフェースではコンパイル時の型チェックがなくなり、実行時に型アサーションが必要になります。
ジェネリクスは、コードの重複を避けながら型の安全性を提供することで、この問題を解決します。

## ジェネリック関数

ジェネリック関数を定義するには、関数名のあとに角括弧（`[...]`）で**型パラメーター**を追加します。
次は、スライスを逆順にして返すジェネリック関数の例です：

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

この例では、`T`が型パラメーターです。
`T`は実際の型のプレースホルダーだと考えることができます。
角括弧の中の`any`キーワードは**型制約**です。
型制約は、`T`にどの型を許可するかをコンパイラーに伝えます。
ここでは`any`なので、`T`はどんな型でもよいという意味になります。

### ジェネリック関数の呼び出し

ジェネリック関数は、角括弧の中に実際の型を渡して呼び出すことができます。
この実際の型は**型引数**と呼ばれます。

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

ほとんどの場合、Goのコンパイラーは関数の引数から型を自動的に判別できます。
この機能は**型推論**と呼ばれます。
型推論を使えば、角括弧の中に型引数を書く必要はありません。

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

この例では、コンパイラーは`words`が文字列のスライスであることを認識し、`T`が`string`であると推論します。

## 型制約

すべての型パラメーターには制約が必要です。
制約は、どの型を型引数として使えるかを指定します。
また、制約は、その型の値に対して行える操作も決めます。

### `any`制約

`any`制約は、どんな型でも許可します。
Goでは、`any`は空のインターフェース`interface{}`のエイリアスです。
`any`はすべての型を許可するので、関数が行えるのは、すべてのGoの型で通用する操作だけです。
たとえば、スライスを保持する2つの`any`値があったとしても、スライスは`==`で比較できないため、`==`で比較することはできません。

### `comparable`制約

Goには`comparable`という組み込みの制約があります。
`comparable`制約は、`==`と`!=`の演算子をサポートする型を許可します。
比較可能な型には、真偽値、数値、文字列、ポインター、チャネル、そして比較可能な型でできた構造体や配列が含まれます。

次は、スライスに特定の要素が含まれているかを調べる関数の例です：

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

`T`は`comparable`制約を使っているので、`elem == target`は有効です。
`comparable`を`any`に置き換えると、コンパイラーはエラーを報告します。

### インターフェースの型セットを使ったカスタム制約

Go 1.18から、インターフェースはメソッドに加えて、型の集合も定義できるようになりました。
インターフェースで許可する型を並べるには、パイプ文字`|`を使います。

```go
type Number interface {
    int | int64 | float64
}
```

これで、`Number`を関数の制約として使えるようになります：

```go
func Double[T Number](value T) T {
    return value * 2
}
```

`Number`のすべての型が`*`演算子をサポートしているので、Goは関数内で`value * 2`を許可します。

### 基底型の近似`~`

基本型をもとに独自の型を定義することがあります：

```go
type MyInt int
```

上で定義した`Number`制約が許可するのは、`int`、`int64`、`float64`という正確な型だけです。
`MyInt`の値を`Double`に渡すと、`MyInt`は`int`と一致しないため、コンパイラーはエラーを出します。
基底型が`int`であるどんな型も許可するには、型の前にチルダ`~`を追加します：

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

これで、`MyInt`型の値にも`Double`を使えます。

### `cmp.Ordered`制約

標準ライブラリは、[`cmp`パッケージ][doc-cmp]で`cmp.Ordered`制約を提供しています。
`cmp.Ordered`制約は、比較演算子`<`、`<=`、`>`、`>=`をサポートする型を許可します。

## ジェネリック型

型パラメーターは、構造体などのジェネリック型を定義するのにも使えます。
次は、ジェネリックな`Stack`データ構造の例です：

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

ジェネリック型の変数を宣言するときは、角括弧の中に型引数を指定する必要があります：

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

型推論が働くのはジェネリック関数だけです。
ジェネリック型の値を作るときは、常に型引数を指定する必要があります。

## ジェネリクスをいつ使うか

ジェネリクスは強力な機能ですが、すべての問題に使う必要はありません。

次のような場合には、ジェネリクスを使います：
- ツリー、連結リスト、キャッシュなど、どんな要素の型でも動作するデータ構造を作っている場合。
- フィルタリング、ソート、検索など、任意の型のスライスやマップを操作するユーティリティ関数を書いている場合。
- 複数の型に対してまったく同じ実装が必要で、コンパイル時の型安全性を求めている場合。

次のような場合には、代わりにインターフェースを使います：
- 基底のデータ型よりも、振る舞いやメソッドを重視する場合。
  たとえば、さまざまな種類のソース（ファイル、ネットワーク、TTY）からデータを読み取って処理したいなら、`func Process[T](src T)`ではなく`func Process(src io.Reader)`を使います。
- 型ごとに異なるメソッドの実装が必要な場合。
