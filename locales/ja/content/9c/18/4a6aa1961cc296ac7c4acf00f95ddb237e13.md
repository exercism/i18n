# コードの取り込み

`circus-acts`は、あるクラスが抽象クラスの示すことを*できる*と伝えるために`<`を使いました。やり方については何も言っていません。

`include`は、その残りの半分です。別のクラスから実際のコードを取り出し、そのコピーをこのクラスに置きます。

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

`JAZZ_ROUTINE`がどこにも書いていないのに、`JAZZ_ROUTINE::count`は8になります。

## 2つの別々の決定

ほとんどの言語では、この2つは一緒になっています。`extends`ひとつで、コードをそのまま引き継ぎ、しかもスーパークラスが使えるところならどこでもサブクラスが使えるようにします。Satherは、この2つを分けています。

| 書き方 | 意味 |
| --- | --- |
| `class A < $B` | `$B`が求められるところならどこでも`A`を使える |
| `class A is include B` | `A`は`B`のコードのコピーから始まる |

どちらか一方だけでも、両方でもかまいません。クラスを取り込んでも、そのクラスがサブタイプになるわけでは**ありません**。`include WARM_UP`のあとでも、`JAZZ_ROUTINE`は`WARM_UP`が求められるところでは使えませんし、そう見せかけることもありません。

## 名前の変更

取り込んだルーチンは、別の名前で持ち込むこともできます。

```sather
   include WARM_UP count -> warm_up_count;
```

複数あるときは、コンマで区切ります。

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## 1つを外す

*何もない*ものに名前を変えると、そのルーチンは取り込まれません。これが置き換えの方法です。

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

`count`はいつもどおり取り込まれますが、`describe`は取り込まれないので、ここに書いても衝突にはなりません。`describe -> ;`がなければ、コンパイラーは受け付けません。同じ名前と同じ引数を持つルーチンが1つのクラスに2つあるのはエラーで、Satherがどちらを意図したかを推測してくれることはありません。

これが、ほとんどの言語のオーバーライドとの違いです。置き換えは暗黙ではなく、明示的に告げられるのです。
