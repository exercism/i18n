# 解説

[ループ][control]とは、終了条件を満たすまで、何度も実行される可能性のある一連の命令のことです。

x86-64では、ループは通常、前のラベルへのジャンプで作られます。

```x86asm
example_loop:
    ...
    jmp example_loop
```

前のラベルへの無条件ジャンプは、常に実行をそのラベルへ移すことに注意してください。つまり、繰り返される範囲の外側への別のジャンプがない限り、ループは永遠に繰り返され続けます。

たとえば、次のループは終わりません。

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

一方、次のループは、条件が満たされるかどうかによって終わる可能性があります。

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## カウントループ

カウントループは、ほとんどの場合、同じ形で終わります。カウンターを更新するか2つの値を比較する命令の直後に、もう一度繰り返すかどうかを決める条件付きジャンプが続くのです。

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
上のコードでは`cmp rsi, 0`は必要ありません。`sub rsi, 1`が、結果が`0`のときにすでに`zero flag (ZF)`を設定するからです。

アセンブリで条件を判定する主な方法は`cmp`ですが、多くの命令はフラグを更新します。たとえば、多くの整数演算命令やビット演算命令は、結果が`0`のときは`ZF`を、結果が負のとき（つまり最上位ビットが立っているとき）は`SF`を更新します。

どのフラグが各命令の影響を受けるかは、[リファレンス][reference]で確認できます。

[reference]: https://www.felixcloutier.com/x86/
~~~~

上の例では、`rsi`は`0`より大きいと仮定されていることに注意してください。もし`0`だった場合、`sub rsi, 1`は`rsi`を`-1`にします。これは符号なしの数としては非常に大きな値です。ループがようやく終わるまでには、さらに`18,446,744,073,709,551,615`回の繰り返しが必要になります。また、配列の長さが`0`なので、どのメモリアクセスも範囲外になってしまいます。

配列の長さについて何も保証がない場合、よく使われる方法が2つあります。

1つ目は、終了条件をループの先頭に移し、末尾に無条件ジャンプを置く方法です。

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

2つ目は、ループの先頭で、長さが0の配列かどうかを一度だけ判定する方法です。

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

この2つ目の方法は、通常、1つ目より効率的です。ループ本体の分岐が少ないからです。これについては、今後別の概念で詳しく学びます。

## マイクロオペレーション

プロセッサーは、`add`や`jnz`のような命令をそのまま実行するわけではありません。まずCPUのフロントエンドが各命令を、1つ以上のより小さな内部ステップに_デコード_します。これを**マイクロオペレーション**（**マイクロオペ**）と呼びます。そしてプロセッサーは、これらのマイクロオペをスケジューリングして実行します。多くの場合、1サイクルに複数、しかも元の順序とは異なる順序で実行されます。

ほとんどの単純な命令は1つのマイクロオペにデコードされ、より複雑な命令は複数にデコードされることがあります。プロセッサーの実際の処理負荷はマイクロオペの流れなので、同じ処理でより少ないマイクロオペを生み出すことは、コードを速くする方法の1つです。

## マクロフュージョン

すでに触れたように、ループは通常、何らかの条件付きジャンプで終わります。これは非常によくあるパターンなので、最新のプロセッサーはデコード時にこのパターンに最適化されています。

フラグを設定する命令の直後に、そのフラグを読む条件付きジャンプが続く場合、それらはそれぞれ1つずつではなく、まとめて**1つ**のマイクロオペにデコードできます。これを**マクロフュージョン**と呼びます。

融合されたペアは1つの操作として振る舞います。カウンターの更新と分岐の判断が、1つのマイクロオペの中で一緒に行われるのです。すると、ループの制御フローは、ループ本来の処理にほとんど負担をかけません。

おおよその目安として、次の2種類のペアが通常このように融合します。

- `add`や`sub`のような算術命令の直後に、条件付きジャンプが続くもの。
- `cmp`、`test`、`and`の直後に、条件付きジャンプが続くもの。

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

融合が起こるのは、条件付きジャンプがフラグ設定命令の**すぐ直後**に、間に何も挟まずに来る場合だけです。

~~~~exercism/note
マクロフュージョンはCPUに依存し、どの命令がどの条件付きジャンプと融合するかには、ある程度の違いがあります。

参考になるのは、[The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]です。[Intel optimization reference manual][intel-opt]のセクション3.4.2.2（Optimizing for Macrofusion）にも、Intel CPUで融合可能なペアが載っています。

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## `loop`命令

ループのような動作を作るために使える命令がいくつかあります。その1つが[loop][loop]です。

その唯一のオペランドは、ループの先頭のアドレスを持つラベルです。

`loop`命令は`rcx`の値をカウンターとして使い、繰り返すたびに1ずつ減らします。`rcx`の値がゼロになると、ループは終了し、実行は順番に続きます。

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

`loop`命令には、繰り返しごとにゼロフラグ（`ZF`）を確認する2つの派生形があります。これらは、`rcx`がゼロになった時点でループを止めるだけでなく、条件が満たされて_いない_ときにも止まります。

| 命令       | 条件 |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

これらの命令は`ZF`を**設定しません**。その前に、`ZF`を変更する`cmp`や`test`、あるいは別の命令が必要です。

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
便利ではありますが、`loop`、`loope`、`loopne`は、最新のプロセッサーでは、同等の`sub`/`jnz`や`cmp`/`jnz`の並びよりも通常ずっと遅くなります。

さまざまなCPUにおける命令の性能については、[Agner's tables][agner-tables]が参考になります。

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
~~~~
