## Roc API

イミュータブルな`React`の値を使います。各操作は更新されたリアクターを返すので、その値を以降の操作でも使います。セルは`cell_id`で、コールバックは`callback_id`で識別します。どちらの識別子も、登録するときに渡す文字列です。コールバックの登録と削除では、どちらの識別子も渡して、対象のセルとそのコールバックを指定します。

計算関数は、`inputs`のセル識別子のリストと同じ順序で並んだセルの値のリストを受け取ります。成功したときは`Ok(value)`を返し、失敗したときは`Err(message)`を返します。この`message`には、入力の個数が正しくない、0で割った、といった失敗の内容を説明する文字列が入ります。計算セルを追加する時点で、その依存先はすでに存在していなければなりません。`add_compute`と`set_value`はどちらも、計算のエラーを`ComputeFailed({ cell_id, message })`として報告します。更新の途中で計算が失敗した場合は、更新されたリアクターは返されず、コールバックも実行されません。元のリアクターはそのまま使えます。

コールバックは`React.CellValue, React.CallbackLog -> React.CallbackLog`という型の純粋関数です。各コールバックはセルの新しい値と現在のログを受け取り、更新されたログを返します。`set_value`は`cell_id`、`value`、初期の`log`を含むレコードを受け取り、更新されたリアクターと最終的なログの両方を返します。各コールバックが返したログは、次のコールバックに渡します。コールバックの順序は決まっていません。

`React.CallbackLog`は`Dict(Str, List(I64))`の別名で、コールバックの識別子ごとに受け取った値が記録されます。テストでは、各入力の更新に空のログを渡して、コールバックがちょうど1回実行されたか、まったく実行されなかったかを確認します。

コールバックを登録しても、そのコールバックは呼び出されません。同じコールバックを2回以上削除してもかまいませんし、他のコールバックに影響を与えてはいけません。1回の更新に関わるすべてのコールバックは、最終的に確定したセルの値を見る必要があります。
