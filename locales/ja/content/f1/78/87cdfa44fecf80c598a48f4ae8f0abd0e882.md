# Unisonの基本

## 項と関数

項と関数は、Unisonのプログラムを書くうえでの基本単位です。

「項」とは、静的な値のことです。定義は`name = expression`の形で書き、必要に応じて`name : MyType`という形式の型シグネチャーを前に付けます。Unisonは型推論に対応しているので、単純な定義では型シグネチャーが省略されていることもあります。

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unisonの関数は`myFunctionName argument1 argument2 = myImplementation`のような形をしていて、関数名のあとにスペースで区切った引数が続きます。

```
getMax a b = Nat.max a b
```

関数にも、必要に応じて型シグネチャーを付けられます。右端にある最後の型が、常にその関数の最終的な戻り値の型で、それぞれの引数は関数の矢印`->`で区切ります。

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

関数を呼び出すには、関数名のあとに、スペースだけで区切った引数を続けます。

```
maximum = getMax 1 10
```

関数を呼び出すとき、Unisonはすぐ右にあるものをその引数として扱おうとします。そのため、意図した順序で関数が評価されないことがあります。

次の式から値`1`を得たいとしましょう。

```
shouldBe1 = getMax 1 10 - 10
```

このまま書くと、`shouldBe1`は`0`に評価されます。暗黙の関数適用の順序が`getMax 1 10`、つまり`10`になり、そのあと`10 - 10`で`0`になるからです。

括弧（`()`）を使うと、式をまとめ直して、意図した演算の順序にできます。

```
shouldBe1 = getMax 1 (10 - 10)
```

## 複数行の関数

Unisonの複数行関数では、インデントまたは`let`ブロックを使ってコードの境界、いわゆる「字句スコープ」を指定します。

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

同じインデントレベルにあるものは同じスコープを共有します。だからこそ、最後の行で変数`newBeginning`を参照できるのです。

## 名前空間と`use`文

名前空間は、Unisonの関数をグループ化して整理するための仕組みです。ディレクトリのようなものだと考えてみてください。名前空間は、構造と論理的なまとまりを与えてくれます。

`use`文を使うと、名前空間にある関数をスコープに取り込めます。

Unisonの`List`の値を使う関数を書いているとしましょう。`List.map`や`List.flatMap`のような関数が必要になることはわかっています。ここで`List`は名前空間で、`map`と`flatMap`は関数です。同じことを繰り返さないために、次のようにして`List`名前空間のすべてを関数の字句スコープに取り込むこともできます。

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List`の行が、`map`と`flatMap`への参照を明確にします。`use`文について詳しくは、[こちら][use-statements]を読んでください。

## Unisonの標準ライブラリ

Unisonの標準ライブラリは`base`と呼ばれます。クイックスタートガイドに沿ってローカルにコードベースを作成していれば、標準ライブラリは自動的にダウンロードされているはずです。標準ライブラリのドキュメントは、[Unison Share][unison-share-base]でオンラインで閲覧できます。

## コメントとドキュメントリテラル

Unisonのコメントは、少し変わった機能です。Unisonのコードを書くとき、拡張子`.u`のファイルに、次の構文で解釈されないテキストを書くことができます。

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_ただし_、Unisonのコードはテキストベースのファイルとしてではなく、抽象構文木のハッシュとして保存されます。そのため、ファイル内にある特定のUnisonの関数や項をテキストで「装飾」するコメントは、保存して共有時に再表示することが実質できません。Unisonの項に、他の人が読んで理解できる形で保存される情報を追加したい場合は、ドキュメントリテラルを使います。

ドキュメントは、Unisonプログラミング言語では第一級の値です。つまり、`Doc`の要素は変数に代入したり、値として関数に渡したり、関数の値として返したりできます。ドキュメントリテラルの要素は、二重の波括弧で開いて閉じます。`Doc`の要素をコメントとして使う例を見てみましょう。

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
