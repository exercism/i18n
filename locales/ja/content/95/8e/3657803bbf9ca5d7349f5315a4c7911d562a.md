# はじめに

Goでは、`for`とインデックスを使って`slice`を繰り返し処理することもできますし、`range`を使うこともできます。`range`を使えば、`map`を繰り返し処理することもできます。

それぞれの繰り返しでは、インデックスかキーと、そのインデックスかキーにある要素のコピーの、2つの値が返されます。

## `slice`を繰り返し処理する

とても簡単です。`slice`の繰り返しは、期待どおりの順序で進みます。

```go
xi := []int{10, 20, 30}
for i, x := range xi {
  fmt.Println(i, x)
}
// outputs:
// 0, 10
// 1, 20
// 2, 30
```

## `map`を繰り返し処理する

`map`を繰り返し処理すると、新たな問題が生じます。順序がランダムになるのです。

```go
hash := map[int]int{9: 10, 99: 20, 999: 30}
for k, v := range hash {
  fmt.Println(k, v)
}
// outputs, for example:
// 99 20
// 999 30
// 9 10
```

~~~~exercism/note
上の出力は正しくないように見えるかもしれません。`map`の宣言にある最初のキーと値のペア`9 10`が、最後ではなく最初に出力されると期待するのが自然だからです。
しかし、`map`は本質的に順序を持ちません。最初や最後のキーと値のペアというものはないのです。
そのため、`map`の要素を繰り返し処理するとき、どの要素がどの順序でたどられるかはランダムで、決まったパターンには従いません。
つまり、上の出力は起こりえますが、自分で実行したときに得られる結果とは異なるかもしれません。
詳しくは、[Go Language Spec: range clause](https://go.dev/ref/spec#RangeClause)を参照してください。
~~~~

## キーや値を省略した繰り返し

Goでは、使われていない変数があるとビルド時にエラーになります。
最初の例のように、値だけが必要なこともあります。

```go
xi := []int{10, 20, 30}
for i, x := range xi {
  fmt.Println(x)
}
// Go build failed: i declared but not used
```

`i`を`_`に置き換えると、その値を使わないことをコンパイラーに伝えられます。

```go
xi := []int{10, 20, 30}
for _, x := range xi {
  fmt.Println(x)
}
// outputs:
// 10
// 20
// 30
```

インデックスだけを出力したい場合は、`x`を`_`に置き換えるか、宣言そのものを省略します。

```go
xi := []int{10, 20, 30}
// for i, _ := range xi {
for i := range xi {
  fmt.Println(i)
}
// outputs:
// 0
// 1
// 2
```

## 型を定義する

型定義では、新しい名前付きの型を作ります。その型は、たとえ基底型が同じであっても、他のどの型とも異なる別個の型です。

```go
type File []bool
```

ここでの`File`は、チェスボードの縦1列を指します。この列には、ふつうAからHのラベルが付いています。
この列のマスはそれぞれ、そこにコマが置かれているかどうかを示す真偽値で表されます。
`File`が定義できたので、今度はこれを他の定義の中で使えます。

```go
type Chessboard map[string]File

board := Chessboard{
    "A": File{true, false, true},
    "B": File{false, true, false},
}
```

`Chessboard`は、ファイルの識別子を`File`の値に対応付けます。
それぞれの`File`は、チェスの1つのファイルにあるマスを表す真偽値の`slice`です。
こうした型定義がないと、`board`は`map[string][]bool`になってしまい、何を表しているのかが分かりにくくなります。
