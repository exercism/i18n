# はじめに

Goでは、文字列を変更することはできません。
ループの中で`+`を使って文字列を連結すると、頻繁にメモリ確保が行われ、データが何度もコピーされてしまいます。
[`strings`パッケージ](https://pkg.go.dev/strings)には[`Builder`](https://pkg.go.dev/strings#Builder)があり、文字列を効率よく組み立てることで、メモリのオーバーヘッドを最小限に抑えられます。

## 文字列を組み立てる

`strings.Builder`のゼロ値は、明示的な初期化やメモリ確保をしなくても、すぐにそのまま使えます。
ビルダーに新しいデータを追加するには、専用の書き込み用メソッドを使います。
どの書き込みメソッドも、Goの標準インターフェースを満たすためにエラー値を返しますが、常に`nil`であることが保証されているため、ふだんのコードでは無視するのが一般的です。

よく使うメソッドは次のとおりです。

- `WriteString(s string) (int, error)`: バッファーに文字列を追加します。
- `WriteRune(r rune) (int, error)`: runeをUTF-8でエンコードした内容を追加します。
- `WriteByte(c byte) error`: 1バイトを追加します。

```go
var sb strings.Builder

sb.WriteString("Hello")
var r rune = ' '
sb.WriteRune(r)
var b byte = '.'
sb.WriteByte(b)
```

## 文字列の取り出しとリセット

テキストを組み立て終えたら、`String()`メソッドを呼び出すことで、たまった内容をGoの標準的な文字列として取り出せます。
`String()`の呼び出しはとても低コストです。蓄積されたデータをコピーせずに、内部のバイトスライスをそのまま文字列として返すからです。

同じビルダーのインスタンスを再利用して新しい文字列を組み立てたい場合（たとえばループの中など）は、`Reset()`メソッドを呼び出します。
これにより内部のバッファーが空になり、内部では確保済みのメモリ容量を保ったまま、新しく文字列を作り始められます。

```go
var sb strings.Builder

sb.WriteString("Task One")
fmt.Println(sb.String()) // Output: Task One

// Clear the buffer for resource reuse
sb.Reset()

sb.WriteString("Task Two")
fmt.Println(sb.String()) // Output: Task Two
```
