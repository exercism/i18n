# 概要

Gleamはエラー処理に例外を使いません。その代わり、成功も失敗もあり得る関数は、汎用的な`Result`型を返します。

`Result`型は言語に組み込まれているので、自分で定義したりインポートしたりする必要はありません。ただ、自分で定義するとしたら次のようになります。

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

`Ok`バリアントは関数が成功したときに返され、`Error`バリアントは関数が失敗したときに返されます。

Gleamでは`Result`を扱う機会が非常に多く、Gleamプログラマーはそれらを扱いやすくするために[`gleam/result`モジュール](https://hexdocs.pm/gleam_stdlib/gleam/result.html)をよく使います。

`result.map`関数を使うと、`Result`の中の値が`Ok`であればその値に対して関数を呼び出せます。`Error`であれば、そのまま通します。

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

`result.try`関数も似ていますが、コールバック関数は`Result`を返すことが期待されます。これは、`Result`を返す複数の関数をつなげるときに便利です。

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
