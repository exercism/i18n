# はじめに

値がプログラムの外へ出るとき、つまりネットワークへ流れたり、ログファイルへ書き出されたり、ソケットを越えていったりするとき、その値は*テキスト*でなければなりません。値を送信できる形に整えるとき、Factorで繰り返し登場する定番の書き方が3つあります。シリアライザーの`unparse`、コピーせずにシーケンスを参照するスライス系のバリアント、そして複数の入力を取るcleaveコンビネーターです。

```factor
USING: combinators kernel prettyprint sequences strings ;

123 unparse .                          ! => "123"
"NS-1024" 2 head-slice >string .       ! => "NS"
1 2 [ + ] [ - ] 2bi . .
! => -1
! => 3
```

`unparse`はFactorのパーサーの逆で、`dup unparse parse`とすると元の値に戻ります。`head-slice`は、`head`のように新しいシーケンスを確保するのではなく、*ビュー*（`slice`オブジェクト）を返します。ある範囲をちょっと見たいだけのときに便利です。`2bi`、`3bi`、`2tri`、`3tri`は、cleaveファミリーをスタックの2つまたは3つの入力へと広げます。
