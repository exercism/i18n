# ワークフローのヒント

## Unisonコードを書いて評価する

Unisonのコードは、`.u`という拡張子のファイルに書きます。Unisonのコードを書くために使うことから、こうしたファイルを「scratch」ファイルと呼びますが、その内容を最終的に保存するのはUnison Codebase Manager（UCM）です。これらのファイルはこれまで通りExercism CLIで提出しますが、Unisonコードの「source of truth」はUCMだと考えられます。

UnisonにはREPL（対話的にコードを読み込んで評価し、結果を表示する仕組み）はありませんが、「watch expressions」を使えばUnisonの式を手早く評価できます。`.u`拡張子のファイルで、行の先頭に`>`を書き、その右側に式を入力します。

```
> myFunction 42 "hi"
```

ファイルを保存すると、UCMが式を評価した結果を表示します。演習の実装のトラブルシューティングに役立ててください。

Exercismでのより詳しいワークフローについては、Exercismの問題を実装してテストする様子を収めた[ウォークスルー動画][walk-through-vid]があります。

```exercism/caution
このウォークスルー動画は、古いバージョンのUnisonのワークフローを紹介しています。新しいプロジェクトのワークフローについては、[こちら](https://exercism.org/docs/tracks/unison/tests)を参照してください。
```

## コードベースの構成

Unisonのコードベースは「名前空間」で構成されています。名前空間は、ファイルシステムのディレクトリに少し似ていますが、ファイルではなく、Unisonの型と関数を格納します。名前空間のパスは、ドット`.`で区切ります。たとえば、`base`名前空間にある`Text`名前空間は、`base.Text`で参照できます。

取り組む演習ごとに名前空間を作成し、そこへ`cd`することをおすすめします。

## インポート

Unisonでインポートを管理・指定するための構文は、`use`構文です。たとえば`use base.data.List`と書くと、`base.data.List`名前空間にあるすべての関数がスコープに入ります。これは、`List`に対して`map`のような関数を使うときに、`Optional.map`のような他の`map`関数と区別する必要がある場合に便利です。名前空間のあとに、スコープに入れたい関数をスペースで区切って並べれば、特定の関数だけをインポートすることもできます。たとえば、`use base.data.List tails head flatMap`のように書きます。

`use`構文は、ファイルのトップレベルでも関数の中でも使ってインポートを指定できます。`use`節は字句スコープの規則に従うため、より深く入れ子になったインポートが、そうでないインポートより優先されます。

## 標準ライブラリ

Unisonの標準ライブラリは`base`と呼ばれます。新しいUnisonコードベースには、デフォルトでダウンロードされています。実装で使える関数は、Unisonコードのオンラインリポジトリである[Unison share][unison-share]、[ローカルのコードベースUI][local-codebase-ui]、またはUnison Codebase Manager（UCM）での検索から眺めることができます。検索については、このあと説明します。

## Unison Codebase Manager（UCM）の操作

UCMで`help`と入力すると、UCMのコマンドの完全な一覧を確認できますが、ここではいくつかのヒントと慣習を紹介します。

UCMでは`find`コマンドで名前や名前空間のプレフィックスから用語を検索できますが、`find`はコードベースの_型に基づく_検索にも対応しています。型シグネチャで関数を検索するには、`find`のあとにスペースとコロンを続けて入力します。たとえば、`find : [a] -> [[a]]`のように書きます。

名前空間の内容は`ls`コマンドで一覧できます。たとえば、`ls base.data.List`や`ls .exercism.helloWorld`のように使います。UCMの多くのコマンドは、相対的な名前空間パスの引数と、完全修飾の名前空間の引数のどちらも受け付けます。完全修飾のパスは、コードベースの「ルート」を表す`.`で始まります。

UCM内を移動するには、CLIの`cd`コマンドを使います。存在しない名前空間へ`cd`すると、その名前空間が_作成_されます。1つ上の名前空間へ移動するには、`cd ..`を使います。

## トラブルシューティング

__テストを読み込もうとすると、UCMが演習の実装を見つけられません。__

テストを読み込む前に、テキストエディタでスタブファイルを保存し、コードベースの用語を`update`しておいてください。

__名前の衝突が起きています。`tests`という名前の用語を2つ持つことはできません。__

異なる名前空間であれば、同じ名前の用語を2つ持つことができます。Exercismの演習を進めるときは、演習ごとに別の名前空間を作成し、テストやスタブが他と混ざらないようにすることをおすすめします。

__ローカルではテストが通るのに、テストランナーでは通りません。__

ご迷惑をおかけしてすみません！　まず、インポートが標準ライブラリの`base`と、テスト対象の`scratch`ファイルで定義されている関数以外を参照していないか確認してください。その場合は、ExercismのSlackの`#track-unison`で知らせるか、[Unisonトラックのリポジトリ][unison-track-repo]にissueを立てて教えてください。

__何か問題があれば、ぜひ教えてください！　🙂__
