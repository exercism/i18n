# はじめに

Elmの[カスタム型][custom-types]は、あらかじめ決まった数の名前付きケースを表すものです。それぞれの値は、必ずそのうちの1つのケースに対応します。

カスタム型は`type`キーワードで定義でき、必要な構文はごくわずかです。カスタム型はElmプログラミングで最も重要なテクニックの1つで、コード上で取りうる値と、現実世界で有効な値をぴったり一致させるために使います。こうすることで不正なデータが入り込む余地がなくなり、[不可能な状態をコードで表現できないようにできます][impossible-states]。

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

カスタム型の各ケースには、必要に応じてデータをひも付けられます。また、ケースごとに異なる型のデータを持たせることもできます。どのケースにもデータがひも付いていない場合、その判別共用体は、他の言語で一般に_列挙型_（_enum_）と呼ばれているものに似ています。

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

特定のケースの値を作るには、その名前（`Spring`）を参照します。これは、そのケースが同じモジュール内で定義されている場合か、`import SeasonModule exposing (Season(..))`のような構文でインポートされている場合に使えます。`import SeasonModule exposing (Season)`のような構文でインポートした場合は、完全修飾名（`Season.Spring`）で参照します。

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

カスタム型は、Elmの他のすべてと同様に_構造的等価性_を持ちます。つまり、同じケースで同じ（省略可能な）データを持つ2つの値は等価です。

カスタム型を扱うのに好ましい方法は、[パターンマッチ][pattern-matching]です。

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
