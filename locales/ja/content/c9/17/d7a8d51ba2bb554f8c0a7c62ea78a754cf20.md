# リスト

`LIST{T}`は、伸縮できる順序付きのコレクションです。内部では配列で支えられており、いっぱいになると、より大きな配列に置き換えられます。

```sather
   notes ::= #LIST{STR};
   notes.append("muddy boots");
   notes[0]                     -- "muddy boots"
   notes[0] := "clean boots";
   notes.size
   notes.is_empty
   notes.has("clean boots")
   notes.remove_index(0);
```

## 配列かリストか？

|  | `ARRAY{T}` | `LIST{T}` |
| --- | --- | --- |
| サイズ | 作成時に固定 | 変化する |
| `append` | なし | あり |
| `remove` | なし | あり |
| インデックス | `a[i]` | `l[i]` |
| オーバーヘッド | なし | サイズの分と予備の領域 |

サイズが決まっていて、その後も変わらないときは、`ARRAY`を使います。たとえば、一列に並んだダンサーや、1週間分のカウントです。反対に、要素が増えたり減ったりするときは、`LIST`を使います。

## 関数的ではなく、その場で変更する

`append`、`remove_index`、`[i] :=` は、いずれもリストそのものを変更します。結果を代入し直す必要はありません。また、ルーチンに渡したリストも、変更されずに済むとは限りません。

これは`FMAP`や`FSET`とは正反対の性質です。自分がどちらを扱っているのか、はっきりさせておく価値があります。目安は、名前の先頭に`F`が付いていれば関数的、そうでなければその場で変更する、というものです。

誰にも壊されないリストを渡したいときは、コピーを渡します。

```sather
   return notes.copy;
```

## 追加のコスト

追加は、平均すると低コストです。内部の配列がいっぱいになると、2倍のサイズの新しい配列が用意され、すべての要素がコピーされます。つまり、ほとんどの追加はほとんどコストがかかりませんが、ときどきコピーのコストがかかります。追加を何度も繰り返すと、1回あたりのコストは一定に平均化されます。だからこそ、毎回1つずつ増やすのではなく、倍々に増やしているのです。

`remove_index`は低コストとは言えません。削除した位置より後ろの要素が、すべて1つずつ手前にずれます。長いリストの先頭から何度も削除すると遅くなりますが、その遅さには気づきにくいものです。

## 便利なルーチン

| 呼び出し | 動作 |
| --- | --- |
| `l.append(x)` | 末尾に追加します |
| `l.insert_before(i, x)` | 指定した位置に挿入します |
| `l.remove_index(i)` | 指定した位置の要素を取り除きます |
| `l.has(x)` | 含まれているかどうかを調べます |
| `l.copy` | 独立したコピーを作ります |
| `l.str` | 波括弧で囲んだ内容を返します |
| `l.elt!`, `l.ind!` | 値、あるいは位置を順にたどります |
