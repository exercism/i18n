# カスタムイテレーター

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | ルーチン | イテレーター |
| --- | --- | --- |
| 名前 | `foo` | `foo!` |
| 値を返す | `return` | `yield` |
| 終わり方 | `return`、または最後まで到達したとき | `quit`、または最後まで進み切ったとき |
| 呼び出せる場所 | どこからでも | `loop`の中だけ |
| 位置を保つ | いいえ | はい |

## yield

`yield`は値を渡して、そこで一時停止します。次に制御が戻ってきたときには、すべてが元通りになります。ローカル変数、そのイテレーター自身のループの位置、そしてそのイテレーターがさらに呼び出しているイテレーターの位置です。

入れ子になったループの中にある`yield`は、いちばん内側のループから再開します。だからこそ、入れ子になった構造をたどる処理を素直に書けるのです。

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

イテレーターを終わらせ、ひいてはそれを呼び出しているループも終わらせます。値は持ちません。`quit`は最後の結果ではなく、これ以上結果がないという知らせなのです。

戻り値の型を持つイテレーターは、何かをyieldするたびに必ず値を`yield`しなければなりません。`quit`は、値を出さずに終えるための方法です。

## once

```sather
   markers!(once count : INT) : INT is
```

`once`が付いた引数は、ループに入るときに一度だけ評価され、その値が保持されます。何も付けない引数は呼び出しのたびに評価し直されます。これは、渡す式の中に別のイテレーターの呼び出しが含まれているときに重要になります。

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

特にそうしたいのでなければ、引数には`once`を付けましょう。ライブラリ全体がそうしています。

## selfとイテレーター

イテレーターはオブジェクトに対して呼び出すことができ、そのとき`self`はそのオブジェクトを指します。一時停止した状態は、オブジェクトではなく呼び出し側に属します。そのため、同じオブジェクトをたどる2つのループが干渉し合うことはありません。

## いつ書くべきか

答えが一連の値の並びで、そのうちどこまで受け取るかを呼び出し側に決めさせたいときは、イテレーターを書きましょう。途中で止めてもコストはかかりませんし、使わないものは作られません。`ARRAY`を返すルーチンでは、まず全体を組み立てなければならないのです。
