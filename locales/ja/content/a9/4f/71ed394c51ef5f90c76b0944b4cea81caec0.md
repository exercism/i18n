# はじめに

`switch()`関数は、長い`if`...`else if`の連続を簡潔に置き換えることができます。切り替えの対象になる変数はたいてい文字列で、その場合はセレクターから引用符を省略できます。

```R
star <- function(type) {
  switch(type,
    M = , # will "fall through" if no value given
    K = "red dwarf",
    G = "Earth-like",
    "bigger star" # only correct for O,B,A,F
  )
}

> star("M")
[1] "red dwarf"
```

上の例の`M`のように、値が空のままの場合にだけ、次の選択肢にフォールスルーする点に注意してください。他の言語のように`break`文を書く必要はありません。

`character`型を対象に切り替える場合、ここで示したように、最後の値がデフォルトになります。整数型の場合、デフォルトは指定できません。

## `dplyr`の関数

base Rの`switch`はかなり限定的で、1つの入力に対して完全一致でしか照合できません。1993年にRが最初にリリースされた当時は妥当に思えましたが、現代の使い方には改善が必要です。

~~~~exercism/note
[`Conditionals`][concept-conditionals]のコンセプトで触れたように、`tidyverse`のパッケージ群は、後方互換性に影響を与えずにbase Rの機能を補完する（ときには置き換える）ために設計されています。

コードの先頭に、`library(dplyr)`（`dplyr`パッケージのみ）または`library(tidyverse)`（コレクション全体）を追加すると、`dplyr`パッケージをスコープに読み込むことができます。

~~~~

`dplyr`ライブラリには、`switch`に関連する2つの追加関数があります。

### `recode_values`と`replace_values`関数

これら2つの関数はよく似ていて、古い値から新しい値への、`switch`に似た対応付けをベクトル化して行えます。

両者の主な違いは、`recode_values()`がまったく新しいベクトルを作るのに対し、`replace_values()`は既存のベクトルの一部を更新できる点です。

照合はやはり完全一致ですが、次の点が異なります。

- 左側の選択肢はベクトルにでき、いずれかの要素が一致すれば入力は一致したとみなされます。
- 左側の選択肢と右側の結果は、`=`ではなくチルダ`~`で結びます。
- どの場合でもデフォルトを指定できます。

```R
library(dplyr)

x <- c("a", "b", "a", "d", "b", NA, "c", "e", "z")
recode_values(
  x,
  "a" ~ 1,
  "b" ~ 2,
  "c" ~ 3,
  c("d", "e") ~ 4, # either "d' or "e" will match
  NA ~ 0,          # matches missing values
  default = 100   # note the different syntax for the default
)
#> [1]   1   2   1   4   2   0   3   4 100
```

### `case_when`関数

`case_when`は`case_match`の構文をさらに一歩進め、`~`の左側に任意の論理式を書けるようにします。

入力のベクトル（下の例では`x`）は引数として渡すのではなく、あらかじめ定義されている必要があるだけです。

```R
x <- 1:10
case_when(
  x < 3 ~ "low",
  between(x, 3, 5) ~ "mid",
  between(x, 6, 8) ~ "high",
  .default = "what?"
)
#>  [1] "low"   "low"   "mid"   "mid"   "mid"   "high"  "high"  "high"  "what?" "what?"
```

`between()`関数も`dplyr`の一部です。
