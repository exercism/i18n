# 概要

Elixirのドキュメントは：

- 第一級の存在です。
- [**Markdown**][markdown]で書きます。
- 特別なモジュール属性を使って追加します。
- 複数行の文字列には、通常ヒアドキュメント構文を使います。

ドキュメントに使うモジュール属性：

- `@moduledoc`：モジュールを説明します。モジュールの最初の行に書きます。
- `@doc`：関数を説明します。関数の定義と型仕様のすぐ上に書きます。
- `@typedoc`：カスタム型を説明します。型の定義のすぐ上に書きます。

```elixir
defmodule String do
  @moduledoc """
  Strings in Elixir are UTF-8 encoded binaries.
  """

  @typedoc """
  A UTF-8 encoded binary.
  """
  @type t :: binary

  @doc """
  Converts all characters in the given string to uppercase according to `mode`.

  ## Examples

      iex> String.upcase("abcd")
      "ABCD"

      iex> String.upcase("olá")
      "OLÁ"
  """
  def upcase(string, mode \\ :default)
end
```

## [ドキュメントとコードコメントの違い][documentation-vs-comments]

Elixirは、ドキュメントとコードコメントを別々の概念として扱います。

ドキュメントは、公開APIの利用者との間で交わす明示的な契約です（同僚や未来の自分も利用者に含まれます）。利用者がソースコードを読めるとは限らないので、ドキュメントでコードの使い方を説明します。

コードコメントは、ソースコードを読むエンジニアに向けたものです。メモを残したり、実装の詳細を説明したり、改善の余地を示したりするのに役立ちます。

ドキュメントはコードの公開APIを説明するものなので、プライベート関数に`@doc`属性を付けようとすると、コンパイル警告が出ます。プライベート関数の説明には、代わりにコードコメントを使います。

```
warning: defp do_check_length/2 is private, @doc attribute is always discarded for private functions/macros/types
  lib/form.ex:33: Form.do_check_length/2
```

## ドキュメントを読む

Elixirプロジェクトのドキュメントにアクセスする方法は、たくさんあります。

### `hexdocs.pm`と`ExDoc`

[`hex.pm`][hex-pm]は、ElixirとErlangのパッケージリポジトリです。`hex.pm`に公開されたパッケージは、ドキュメントも自動的に[`hexdocs.pm`][hexdocs-pm]に公開されます。そこでは、お気に入りのElixirライブラリのドキュメントはもちろん、[Elixirの公式ドキュメント][official-documentation]も見つかります。

`hex.pm`にパッケージを公開しなくても、Elixirの公式ドキュメントと同じ見た目のドキュメントサイトを自分のプロジェクト用に生成できます。そのためのツールが[`ExDoc`][ex-doc]です。`ExDoc`は、ローカルのファイルシステムから閲覧できるHTMLファイルを生成します。

`ExDoc`を最高の結果で使うために、[ドキュメントを書くための公式の推奨事項][writing-documentation-recommendations]に従いましょう。

### IExの`h`ヘルパー

標準ライブラリやインストール済みのライブラリ、そして自分のElixirプロジェクトのドキュメントに、自分のコンピューターから直接アクセスできます。

コンピューターにElixirがインストールされていれば、`iex`コマンドを実行して[対話モード][getting-started-iex]で使えます（現在のmixプロジェクトのソースを読み込みたい場合は`iex -S mix`です）。

`iex`では、[`h`][iex-h]に続けてスペースとモジュール名または関数名を入力すると、そのドキュメントを読めます。

[//]: # (elixir-formatter-disable-next-block)

```elixir
iex()> h String.upcase/1
# def upcase(string, mode \\ :default)
#
# Converts all characters in the given string to uppercase according to mode.
# (...)
```

モジュール名や関数名を途中まで入力してからTabキーを押すと、オートコンプリートで利用できるモジュールや関数を見つけられます。

### 最近のIDE

Elixirをサポートする最近のIDEの多くは、ドキュメントや型仕様を解析して、便利なポップアップで表示できます。たとえば[Visual Studio Code][vsc-documentation]や[Elixirプラグインを入れたIntellij][intellij-elixir-documentation]などです。

## 内部モジュールと関数

モジュールや関数を内部での利用だけを目的とする場合は、`@moduledoc false`または`@doc false`を付けます。それらのモジュールと関数は、生成されるドキュメントに含まれません。ただし、これでプライベートになるわけではありません。呼び出したりインポートしたりすることはできます。この問題への対処法については、[内部モジュールと関数を隠す方法についての公式ドキュメント][hiding-internal-modules-and-functions]を確認してください。
