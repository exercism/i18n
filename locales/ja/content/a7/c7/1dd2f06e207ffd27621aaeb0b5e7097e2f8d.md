# 指示の補足

## Rocでの銀行口座

Rocのコードでは、並行処理や共有状態はプラットフォームに任せ、私たちはビジネスロジックに集中するのが一般的です。そのため、この演習では`BankAccount.roc`の口座操作を実装するだけでよく、並行処理を気にする必要はありません。口座は閉じた状態から始まり、開き直すと残高はリセットされます。入金と出金は正の値でなければなりません。

## 任意のサーバーデモ

同梱の`bank-account-demo.roc`は、この実装を小さなWebサービスでどう使えるかを示しています。エディターで読むことはできますが、テストとは独立しており、解答の一部ではありません。

デモを実行するには、ご自身のマシンに[Rocをインストール](https://www.roc-lang.org/install/)し、[Exercism CLI](https://exercism.org/cli-walkthrough)を導入したうえで、ターミナルで次のコマンドを実行します。

```sh
exercism download --exercise=bank-account --track=roc
```

次に、`BankAccount.roc`を実装し、次のコマンドでテストします（CLIが表示するダウンロード先が下のパスと異なる場合は、その場所に合わせて変更してください）。

```sh
cd ~/Exercism/roc/bank-account
roc test bank-account-test.roc
```

すべてのテストが通ったら、次のコマンドでデモサーバーを起動できます。

```sh
roc bank-account-demo.roc
```

このサーバーは[basic-webserverプラットフォーム](https://github.com/roc-lang/basic-webserver)と、その組み込みのSQLiteサポートを利用しています（Rocは初回実行時にプラットフォームをダウンロードします）。別途データベースサーバーを用意する必要はありません。サーバーは`http://127.0.0.1:8000`で待ち受け、カレントディレクトリに`bank-account-demo.db`を作成します（別のデータベースファイルを使うには`DB_PATH`を設定してください）。サーバーはCtrl-Cで停止します。データは再起動しても保持されます。

別のターミナルから、`curl`でWebサービスを呼び出せます（Windowsでは、PowerShellの`curl`エイリアスを避けるため、常に`curl.exe`を使ってください）。たとえば、口座#123を開き、50を入金し、10を出金して、残高を確認するには次のようにします。

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/open
curl -X POST http://127.0.0.1:8000/accounts/123/deposit/50
curl -X POST http://127.0.0.1:8000/accounts/123/withdraw/10
curl http://127.0.0.1:8000/accounts/123/balance
```

残高は`40`です。口座IDと金額は符号なし整数でなければなりません。更新が成功すると`OK`を返し、失敗すると口座の実装からのエラーを返します。口座#123を閉じるには次のようにします。

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/close
```

Linux/macOSで並行リクエストを試すには、新しい口座IDを使い、8つのクライアントから100件の入金を送ります。

```sh
curl -X POST http://127.0.0.1:8000/accounts/456/open
seq 100 | xargs -P 8 -I '{}' curl --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1
curl http://127.0.0.1:8000/accounts/456/balance
```

Windowsでは、並列の例に[PowerShell 7以降](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows)を使ってください。

```powershell
curl.exe -X POST http://127.0.0.1:8000/accounts/456/open
1..100 | ForEach-Object -Parallel { curl.exe --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1 } -ThrottleLimit 8
curl.exe http://127.0.0.1:8000/accounts/456/balance
```

入金はすべて成功し、残高は`100`になるはずです。

## デモが並行処理を扱う方法

各リクエストは口座を読み取り、実装したRocの関数を呼び出し、その結果をSQLiteの`Immediate`トランザクション内で保存します。失敗した操作はロールバックされ、口座は変更されません。SQLiteは同時に1つの書き込みしか許さないため、並行するリクエストが互いの更新を上書きすることはありません（異なる口座間でも同様です）。

注意：この演習では`U64`を使いますが、デモでは残高をSQLiteの整数として保存するため、`I64`の最大値（`9223372036854775807`）を超える更新は拒否されます。

独立した計算を並行して実行する例については、[Parallel Letter Frequencyの演習](https://exercism.org/tracks/roc/exercises/parallel-letter-frequency)を試してみてください。
