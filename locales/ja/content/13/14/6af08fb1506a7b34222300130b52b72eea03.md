# 説明

プログラミングについて学べば学ぶほど、これはただの一時的な流行ではないかもしれないと思うようになります。ビジネスのチャンスだってあるかもしれません。人がコードを書き、それを保存し、共有し、共同作業をし、さらにはフィードバックまで欲しがるのですから。

よし、やりましょう。人がコードを書くのを後押しするサービスを作りましょう。さあ、みなさん、gitを使い始めましょう！　名前は……GitHupにしましょう。

まずはREST JSON APIの構築に取りかかります。ユーザー、プルリクエスト、コメント、バックエンドはあっという間に完成します。サーバーにプルリクエストのコメント一覧を要求したときに返されるペイロードの例を次に示します。

もちろん、フロントエンドはElmで作りますが、その前に、あの厄介なデコーダー／エンコーダーとは一体何なのかを理解する必要があります。

```exercism/note
ジョーク交じりの話はさておき、この演習の要件はGitHubのREST APIにおけるプルリクエストレビューコメントのエンドポイントからそのまま取られています。
簡単にするために一部のフィールドはJSONスキーマから削除されていますが、これ以上ないほど実際のアプリケーションに近い内容です。
```

## 1. IDをください！

鋭い目で見れば、コメントにもユーザーにも`id`フィールドがあることに気づくはずです。始めるのにうってつけですね。

`decodeId`を定義して、整数の`id`を持つJSONオブジェクトをデコードできるようにしましょう。

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. 名前は何でしたっけ？

上の例を見ると、すべてのユーザーが名前を持っているわけではないことに気づきます。

`decodeName`を定義して、`name`フィールドに文字列があればそれをデコードできるようにしましょう。
名前がない？　問題ありません。単に`Nothing`を返すだけです。
このデコーダーは決して失敗しないはずです。

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. ユーザー？　そんな人、知りませんよ！

ユーザーのデコードはほぼ半分まで来ました。仕上げてしまいましょう。

`decodeUser`を定義して、JSONのユーザーオブジェクトをデコードできるようにしましょう。
`decodeUser`の中で`decodeId`と`decodeName`を使うようにしましょう。

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. 私はたくましく自立したコメント

プルリクエストのレビューでは、単独で存在するコメントもあり、そのようなコメントには`pull_request_review_id`がありません。
しかし、仕様によれば、そのような場合でも`pull_request_review_id`フィールドは存在し、値は`null`（貧乏人の`Nothing`）であるべきです。

`decodePullRequestReviewId`を定義して、`pull_request_review_id`フィールドに整数があればそれをデコードできるようにしましょう。
整数がなければ`null`があるはずで、`null`がなければデコーダーは失敗するべきです。

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. サイドビジネス

次は、いかにも面白そうな`side`フィールドです。
プルリクエストのレビューでは、削除されたコード（画面の`Left`側）にも、追加されたコード（画面の`Right`側）にもコメントできます。

`decodeSide`を定義して、`side`フィールドの`"LEFT"`または`"RIGHT"`をデコードし、対応する型のバリアントにマッチさせましょう。

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. リンクの目覚め

各コメントにはリンクの集合がありますが、コメントによって一貫していないようです。

`decodeLinks`を定義して、`_links`フィールドにあるURLの集合をデコードできるようにしましょう。
リンクの名前も数も変わりうるので、それに対応できるようにしましょう。
リンク自体はJSONオブジェクトで、常に`href`フィールドを持つはずです。

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. はい、コメント！

もう少しです。仕上げましょう。

`decodeComment`と`decodeComments`を定義して、それぞれ単一のJSONコメントオブジェクトとコメントのリストをデコードできるようにしましょう。
`decodeComment`では、`decodeName`を除いて、これまでに定義したすべての関数を使うようにしましょう。
もちろん、`decodeComments`でも`decodeComment`を使います。

## 8. すべてがつながる

これまでのところで、まだ1つ足りない機能があります。サーバーに新しいコメントを送信できるようにすることです。
そのためには、デコーダーの逆を実現する必要があります。Elmの`Comment`をJSONの`Value`に変換できるようにするのです。

`encodeComment`を定義して、任意の有効な`Comment`をエンコードできるようにしましょう。
フィールドの順序は問いません。`decodeComment`がデコードできる値をエンコーダーが生成できればよいのです。
