# ヘルプ

## テストを実行する

Factorトラックでは、**Factor 0.101**を使います。[インストール](https://exercism.org/docs/tracks/factor/installation)を済ませたら、この演習のディレクトリで次を実行します。

```
factor -roots=. -run=exercism-tools <exercise>
```

たとえば、`hello-world`の場合は次のようになります。

```
factor -roots=. -run=exercism-tools hello-world
```

各演習には、テスト実行を担う小さな`exercism-tools`ボキャブラリが同梱されています。テストがすべて通ると、ランナーはステータス0で終了します。テストが1つでも失敗すると、0以外のステータスと診断出力を返して終了します。

### スキップされるテスト

既定では、最初のテストだけが実行されます。その仕組みは、テストファイルにある`STOP-HERE`の行です。この行は解析時に、Factorの字句解析器にそれより下をすべて無視するよう指示するので、ランナーには上のテストだけが見えます。最初のテストが通ったら、次の2つの方法でテストを有効にできます。

- **`STOP-HERE`の行を削除する**と、残りのテストをすべて一度に有効にできます。
- **`STOP-HERE`の行をさらに下へ移動する**と、テストを1つずつ、またはタスクを1つずつ有効にできます。コンセプト演習ではテストが`TASK:`マーカーごとにまとめられているので、`STOP-HERE`を次の`TASK:`の直前に移動するのが自然な進め方です。

すべてのテストが通れば、その演習は解けたことになります。

## 解答を提出する

演習のディレクトリで次を実行します。

```
exercism submit <exercise>/<exercise>.factor
```

たとえば、次のようになります。

```
exercism submit hello-world/hello-world.factor
```

演習の`.meta/config.json`に複数の解答ファイルがリストされている場合（コンセプト演習の中には、解答を補助的なサブボキャブラリに分けているものがあります）は、編集したファイルをすべて`exercism submit`に渡します。

## 未完成の解答を提出する

テストが失敗していても解答は提出できます。そうすると、ほかの人がその演習にどう取り組んだかを見たり、ここまでに書けたものについてメンターのフィードバックを求めたりできます。

## さらに助けを求める

- [ExercismフォーラムのFactorカテゴリ](https://forum.exercism.org/c/programming/factor/)は、トラック固有の質問やフィードバックに最適な場所です。
- [Exercism Discord](https://exercism.org/r/discord)には、一般的な助けと個々のトラックの両方のチャンネルがあります。
- Factorの公式ドキュメントは検索できて、内容も網羅的です。取っかかりとして良いのは次の2つです。
  - [The Factor handbook](https://docs.factorcode.org/content/article-handbook.html)は、リファレンス形式でボキャブラリごとに整理されています。
  - [The Factor cookbook](https://docs.factorcode.org/content/article-cookbook.html)は、トピックごとにまとまった短くて慣用的な例です。
- Andrea Ferrettiの[Factor tutorial](https://andreaferretti.github.io/factor-tutorial/)は、言語と開発環境への、手早くて親しみやすい入門です。
