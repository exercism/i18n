# 条件分岐入門

## Bashにおける真偽の扱い

Bashには真偽値という概念がありません。
あるのは文字列と数値、そして文字列や数値の配列です。
では、条件分岐のコマンドは`true`と`false`をどのように扱うのでしょうか？

## 終了ステータス

コマンドは、終了するときに_終了ステータス_を返します。
終了ステータスは、0以上255以下の整数です。
Bashは、**0**の終了ステータスを_成功_とみなします。
それ以外の終了ステータスは_失敗_を表します。

これは、bashの組み込みコマンド、キーワード、関数など、すべてのコマンドに当てはまります。

## `if`コマンド

`if`コマンドの基本構文は次のとおりです。

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

`if`で始まり、条件コマンドは`then`によって「成功」時のコマンドと区切られ、`fi`で終わります。
`else`節は省略できます。

CONDITIONAL_COMMANDSは、単一のコマンドでも、[コマンドのリスト][command-list]でもかまいません。

CONDITIONAL_COMMANDSが実行され、その終了ステータスに応じて次のようになります。

* 終了ステータスが0（成功）なら、TRUE_COMMANDSが実行されます。
* 終了ステータスが0以外（失敗）なら、FALSE_COMMANDSがあればそれが実行されます。

`elif`を使うと、分岐を連ねることができます。

```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

`then`、`elif`、`else`、`fi`の前には、セミコロンか改行が必要です。

強調しておくと、流れを制御するのは、条件コマンドの**終了ステータス**です。
たとえば、`grep`は一致が見つかれば0を、見つからなければ1を返します。
`-q`オプションを付けると出力が抑えられ、終了ステータスだけが返ります。

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## `[`と`test`コマンド

CONDITIONAL_COMMANDSのまわりに特別な構文はありません。
次のような`if`文に見覚えがあるかもしれません。

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

`[`は特別な構文ではありません。
これは、条件式を評価し、成功か失敗のステータスで終了する_コマンド_です。
すべてのコマンドと同様、これと引数の間には空白が**必要**です。

`[`は実際には`test`コマンドの別名です。
`[`の最後の引数が`]`で_なければならない_ことを除けば、両者はまったく同じです。

### 条件式

`[`と`]`のあいだには、条件式を書きます。
代表的な条件式には、次のようなものがあります。

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

他にも多くの演算が用意されています。それらはマニュアルの[Bashの条件式][cond-expr]のセクションに載っています。

~~~~exercism/note
上の例では、すべての変数が引用符で囲まれていることに注目してください。
`test`と`[`コマンドはただのコマンドで、その引数は他のコマンドと同じように単語分割やファイル名展開の対象になります。

これが重要だとわざわざ言うのは、条件式の評価が、与える_引数の数_によって変わるからです。

* 引数0個：終了ステータスは0以外（失敗）です。
* 引数1個：引数が空でなければ終了ステータスは0（成功）、空なら0以外です。
* 引数2個：最初の引数は単項演算子（`[ -z "$name" ]`など）か、`!`（引数1個のテストのステータスを否定する）でなければなりません。
* そして、[さらに多くのケース][test]があります。

引用符を忘れると、予期しない結果になることがあります。

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## `[[`キーワード

[`[[...]]`という条件構文][cond-construct]は_コマンド_ではなく、**キーワード**です。
つまり、他のコマンドと同じように扱われますが、特別な構文解析のルールがあります。
`[[`の特別な点は、その中で展開される変数が、単語分割やファイル名展開の対象に**ならない**ことです。
そのため、このコマンドは、引用符を付けなくても期待どおりに動作します。

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

`[[`は、`test`と`[`が扱えるすべての条件式をサポートします。
さらに、`[[`には次のものがあります。

* `=~`という正規表現マッチングの演算子
* `==`と`!=`がグロブパターンマッチングの演算子として働く
* `&&`と`||`が論理演算子として使える（特別な構文解析のルール）
* `<`と`>`が「引用符なしの」文字列比較の演算子として使える（特別な構文解析のルール。これらはリダイレクト記号なので、`[`ではエスケープしなければなりません）

これらの特別な機能は非常に大きな利点をもたらすため、`[[`だけを使うべきだという考えが広く支持されています。
（たとえば、[Google Shell Style Guide][goog-test]などです。）

## `case`コマンド

[`case`][case]も、もうひとつの制御フローのコマンドです。
他の言語の「switch」文のようなものです。

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

WORDは、それぞれのPATTERNと照合されます。
一致するものが見つかると、そのCOMMANDSが実行されます。

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

各COMMANDS節は、**2つ**のセミコロン`;;`で終わらなければなりません。
