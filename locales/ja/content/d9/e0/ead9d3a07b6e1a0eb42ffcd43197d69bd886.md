# 概要

名前空間を使っていない実務のコードに出会うことは、ほとんどないでしょう。

構文の例は、次のとおりです。

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

名前空間は、関連するコードをまとめ、名前の衝突を避けるための仕組みです。

[公式ドキュメント][namespaces]によると、名前空間には主に2つの役割があります。

- 1つ目は、.NETが数多くのクラスを整理するために名前空間を利用することです。
- 2つ目は、自分で名前空間を宣言することで、規模の大きなプログラミングプロジェクトでもクラス名やメソッド名のスコープを制御しやすくなることです。

基底クラスライブラリ（BCL）も、その機能を整理するために名前空間を広く利用しています。

## 名前空間内の型を参照する

名前空間に含まれる型を、その名前空間の外から参照するときは、型名の前にドット記法で名前空間を付けます。別の方法として、というよりは通常は、ファイルの先頭（または名前空間の中）に`using`ディレクティブを置けば、インポートした名前空間にある型を接頭辞なしで使えます。同じ名前空間の中であれば、型名を修飾する必要はありません。

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

こちらの[記事][using]では、`using`ディレクティブの使い方が分かりやすく説明されています。

- `using`: 型を名前空間で修飾しなくて済むようにします。
- `using static`: メンバーを型で修飾しなくて済むようにします（よい例が`Math.Max()`です）。
- `using MyAlias = YourNamespace;`: 名前空間名を、より読みやすい名前に置き換えます。

## 名前空間の衝突

.NETでは、別々のアセンブリに同じ名前の名前空間があり、完全修飾された識別子名が衝突してしまうという問題に対処しています（たとえば、あるアセンブリの複数のバージョンが読み込まれるような状況です）。この問題は、[名前空間エイリアス修飾子][namespace-alias-qualifier]と[externエイリアス][extern-alias]で解決します。

このかなりニッチな話題を取り上げる理由の1つは、[`::`演算子][dot-dot-operator]を使うからです。特に生成されたコードでは、名前空間の前に`global::`という修飾子が付いているのをよく見かけます。これは、入れ子になった名前空間やクラス名との潜在的な衝突を避けるためのものです。名前空間の前に`global::`を付けると、トップレベルの名前空間が選ばれることが保証されます。

## Java開発者に向けた補足

Javaの`packages`に対する`import`と比べると、いくつかの違いと共通点があります。

- C#には、特定の型だけをインポートする仕組みに相当するものはありません。
- `using static`と`import static`は同じはたらきをします。
- Javaでは、パッケージ名がjar間のアクセス可能性に影響します。C#ではアセンブリが何より重要で、同じ名前空間に属しているかどうかはアクセスレベルに影響しません。
- Javaにおけるファイルシステムのパスと完全修飾クラス名の関係は、C#の名前空間には反映されません。ただし、ファイルに、その中に含まれる主要なクラスと同じ名前を付けておくのは、可能な範囲で行うとよい習慣です。
