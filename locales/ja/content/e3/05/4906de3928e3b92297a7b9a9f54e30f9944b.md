# ヒント
`Either`のよくある使い方は、エラーになる可能性のある計算を表すことです（実際のエラー内容が重要でなければ、よりシンプルな`Option`型のほうが良い選択かもしれません）。
エラーがない場合、結果は通常`Right`です（覚え方：「正しい（right）」の値）。一方、エラーは`Left`で、たとえばエラーメッセージを含む`Left[String]`のようになります。
Scala 2.12では`Either`はデフォルトで右寄りなので、`filter`や`map`、`flatMap`といった操作やfor内包表記で期待どおりに動作します。
`Either`に馴染みがない場合は、[こちらのチュートリアル](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html)を読んでみてください。ただし、このチュートリアルは2.12より前のScalaを対象としている点に注意してください。Scala 2.12では、`RightProjection`は無視してよく、`.right`も省略できます。
`Either`はいわゆる[モナド](https://en.wikipedia.org/wiki/Monad_(functional_programming))で、「計算の側面」、ここではエラー処理を担います。
モナドを適切に使うと、簡潔でありながらエレガントで読みやすいコードになります。使い方を誤ると、あっという間に正反対の結果になります。
詳しくは[こちらの動画](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA)を見てみましょう。
## 避けたいよくある落とし穴
`Either`にはいくつかの経験則があります。
1. 必要がないなら使わないこと。次のような

```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```

ではなく、

```scala
def add1(x: Int): Int = x + 1
```

としたほうがよいでしょう。
（このような単純な関数を適用する`Either.map`があるので、`Either`でコードを煩雑にする必要はありません。）
2. 本当に必要でなければ「アンラップ」しないこと。
目的に合った組み込み関数が用意されていることがよくあります。早すぎるアンラップの兆候は、`isLeft/isRight`やパターンマッチングです。たとえば、次のような

```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```

ではなく、

```scala
x fold (identity, _ + 1)
```

としたほうがよいでしょう。
3. モナドはfor内包表記の中でも使えて、とても便利です。
これは、複数の`Either`を「合成」したいときにおすすめです。次のような

```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```

ではなく、

```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```

としたほうがよいでしょう。
