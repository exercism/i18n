# イテレーターの組み合わせ

ループからは、複数のイテレーターを呼び出せます。それぞれが1回の繰り返しにつき1つずつ次の値を求められ、イテレーターどうしは一緒に進んでいきます。

```sather
   loop
      first ::= violin_one.elt!;
      second ::= violin_two.elt!;
      #OUT + first + " against " + second + "\n";
   end;
```

これで2つの配列を並べて進められます。最初の要素と最初の要素、2番目と2番目、というように。

## みんなが驚くルール

**ループは、イテレーターの*最初の*ものが尽きた時点で終わります。**

最後のものが尽きたときではありません。すべてが尽きたときでもありません。最初です。

ですから、`violin_one`に4小節、`violin_two`に2小節が入っていると、上のループは**2回**しか回りません。最初のパートの3小節目と4小節目は決して見られません。その時点で、2番目のパートには差し出せるものが何も残っていないからです。

これはたいてい、まさに望んだとおりの動きです。ペアを作ることに意味があるのは、ペアが存在する間だけですから。ただし、これは自分で発見するものではなく、あらかじめ知っておくべきことです。

## 数えながら進む

決して尽きないイテレーターが役に立つのは、まさにこのルールのおかげです。`up!`は永遠に数え続けます。

```sather
1.up!        -- 1, 2, 3, 4, ... and never ends
```

単体で使えば、永遠にループし続けます。終わりのあるものと組にすると、どこまで数えるかを決めることなく、値に番号を振ってくれます。

```sather
   loop
      number ::= 1.up!;
      bar ::= part.elt!;
      #OUT + "Bar " + number + ": " + bar + "\n";
   end;
```

`part.elt!`がループを終わらせ、`1.up!`が番号を振ります。どちらも、パートがどれだけ長いかを知る必要はありません。

## 順番は関係ありません

イテレーターはどれも1回の繰り返しにつき1回ずつ求められるので、どちらを先に書いても違いはありません。大事なのは、それぞれがきっかり1回だけ求められることです。1回の繰り返しの中で`part.elt!`を2回書くと、1つのはずが2つの値を取ってしまいます。
