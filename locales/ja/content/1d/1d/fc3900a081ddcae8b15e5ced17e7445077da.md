# 概要

値を送り出すための準備には、3つのことが同時に含まれます。値をシリアライズすること、その中から必要な部分を取り出すこと、そしてコピーが必要ないときにはコピーしないことです。Factorの3つのイディオムが、この3つをカバーします。

## `unparse`：値からソースへ

[`unparse`][unparse]（`prettyprint`の中にあります）は、どんな値でもそのソース形式のテキストにして返します。パーサーとは逆の働きをします。`dup unparse parse`と往復させれば、元の値が復元されます。

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

`>string`（文字の並びにしか使えません）や`number>string`（数値専用です）と比べてみましょう。`unparse`はどんな値にも使える万能なものです。ただし代償として、出力はFactorの構文のままになります（文字列は引用符が付いたままです）。受け取った側がそのテキストをパースし直すならこれが適切な道具で、人間が読むための出力には向きません。

## スライス：ビューであり、コピーではない

| 単語          | 効果                                            |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`：先頭のn個をコピー          |
| `head-slice`  | `( seq n -- slice )`：先頭のn個のビュー           |
| `tail`        | `( seq n -- newseq )`：インデックスn以降をコピー  |
| `tail-slice`  | `( seq n -- slice )`：インデックスn以降のビュー   |
| `head*`       | `( seq n -- newseq )`：最後のn個以外をコピー      |
| `head-slice*` | `( seq n -- slice )`：最後のn個以外のビュー       |
| `tail*`       | `( seq n -- newseq )`：最後のn個をコピー          |
| `tail-slice*` | `( seq n -- slice )`：最後のn個のビュー           |

`slice`は、開始インデックス、終了インデックス、元になったシーケンスを持つタプルです。[シーケンスプロトコル][sequence-protocol]を実装しているので、どんなシーケンス操作もそのまま使えます。読むだけなのに新しく領域を確保したくないときはスライスのほうを、元のシーケンスが変わってもデータを保持しておきたいときはコピーするほうを選びましょう。

## 複数入力のcleave：`2bi`、`3bi`、`2tri`、`3tri`

ふつうのcleaveの言葉`bi`と`tri`は、スタック上の*1つ*の入力に2つか3つのクォーテーションを適用します。`2`が付くものと`3`が付くものは、各クォーテーションを*2つ*または*3つ*の入力に適用します。

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

それぞれのクォーテーションは入力の*すべて*を受け取ります。つまり、2つの結果がどちらもそのペアに依存するときに`2bi`を使うのであって、同じ結果をそれぞれの入力に別々に適用したいときではありません（そちらは`bi@`です）。

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

*1つ*のクォーテーションをそれぞれの入力に別々に適用したいときは、`bi@`（入力2つ）か`tri@`（入力3つ）を使います。同じ仲間ですが、形が違います。
