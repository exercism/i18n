# 概要

C#では、_継承_を使って_クラス_の階層を定義できます。継承を使うと、派生クラス（`Car`）が親クラス（`Vehicle`）の振る舞いとデータを引き継ぐことができます。親クラスを指定しなければ、そのクラスは`object`クラスを継承します。

親クラスは、次の3つの方法で派生クラスに機能を提供できます。

- 通常のメソッドを定義する。
- [`virtual`メソッド][virtual-keyword]を定義する。これは通常のメソッドと同じですが、派生クラスが_変更できる_ものです。
- [`abstract`メソッド][abstract-keyword]を定義する。これは実装を持たないメソッドで、派生クラスが_必ず_実装しなければなりません。`abstract`メソッドを持つクラスは、それ自体も[`abstract`][abstract-classes]としてマークする必要があります。抽象クラスはインスタンス化できません。

[`protected`アクセス修飾子][protected-keyword]を使うと、親クラスのメンバーに派生クラスからアクセスできますが、他のクラスからのアクセスはできません。つまり、派生クラスは親クラスの`public`メンバーと`protected`メンバーにはアクセスできますが、`private`メンバーにはアクセスできません。

派生クラスは、[`base`キーワード][base-keyword]を使って親クラスのメンバーにアクセスできます。

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

派生クラスのコンストラクターは、自分のコンストラクターの処理を実行する_前に_、[親クラスのコンストラクターを自動的に呼び出します][constructors]。親クラスのコンストラクターには、[`base`キーワード][base-keyword-constructor]を使って引数を渡せます。抽象クラスはインスタンス化できないため、そのコンストラクターは`protected`にできます。

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

1つの基底クラスから複数のクラスを派生させると、それら2つ（あるいはそれ以上）のサブクラスが、基底クラスのメソッドをそれぞれ違う形で実装することがよくあります。これは[ポリモーフィズム][polymorphism]と呼ばれる、とても重要な原則です。たとえば、上の例を少し変えた次のコードでは、`Vehicle`を使うコードが、インスタンス化された乗り物の種類に応じて振る舞いを変える様子を示しています。

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

クラスを継承されないようにするには、[`sealed`修飾子][sealed-classes]を付けます。実践者の中には、具象クラスからの継承を避けようとする人もいて（[こちらのStack Overflowの質問][pro-sealed]で議論されています）、_sealed_修飾子はこの考え方を後押しします。一方で、多くのC#開発者は、[こちらの質問][anti-sealed]のコメントで議論されているように、sealed修飾子を保守の妨げになると考えています。アドバイスとしては、自分の要件に合っていると確信が持てるまでは、sealed修飾子を控えめに使うのがよいでしょう。

次の[記事][new-vs-override]では、`override`修飾子の代わりになるものとして`new`が説明されています。これは、入り組んだクラス階層や、ライブラリ同士の何らかの衝突などで、ときどき役に立ちます。
