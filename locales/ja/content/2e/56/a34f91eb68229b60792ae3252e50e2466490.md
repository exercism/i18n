# 例外

```sather
   raise "Unknown prop: " + prop;
```

```sather
   protect
      ...
   when $STR then
      #OUT + exception.str;
   end;
```

## raise

`raise`はどんなオブジェクトでも受け取ります。`STR`を投げるのがもっとも単純なケースで、この演習でもそれを使います。自分で定義したクラスなら、どの`prop`が、いくつ必要だったのかといった情報をより多く運べますが、その分、定義する場所を用意しなければなりません。

例外は、`protect`が捕まえるまで、呼び出し元を通って外側へ伝わっていきます。どこにも捕まえられなければ、プログラムは停止し、その例外を出力します。

Satherは、ルーチンがどの例外を投げる可能性があるかを記録しませんし、呼び出し元にそれを処理させることもありません。ルーチンの型を見ても、失敗しうることは何もわかりません。

## protect

```sather
   protect
      body
   when $STR then
      ...
   when SOME_CLASS then
      ...
   end;
```

`when`節は上から順に試され、投げられた値と型が一致した最初のものが実行されます。`exception`はその値を指し、スコープに入るのは`when`節の内側だけです。

一致する`when`節がない`protect`は捕まえません。例外は、`protect`がなかったかのように、そのまま外側へ伝わっていきます。

## どこで捕まえるか

実際に何か対処できる場所で捕まえましょう。例外を飲み込んで、でっち上げの値のまま先に進んでしまう`protect`は、はっきりわかる失敗を、気づきにくい誤った答えに変えてしまいます。そうなると、かえって悪いのです。

```sather
   -- almost always wrong
   protect
      return risky;
   when $STR then
      return 0;
   end;
```

## 例外か、契約か

どちらも、何かがうまくいかないことに関わりますが、対象とする場面は正反対です。

**例外**は、本当に起こりうることで、呼び出し元が防ごうにも防げなかったものを扱います。たとえば、テーブルにない`prop`や、そこにないファイルです。

**契約**は次の演習で扱うものですが、決して起こってはいけないこと、たとえば呼び出し元が負の重さを渡してしまうような場合を扱い、呼び出し元にバグがあるという宣言になります。契約は求められたときにだけチェックされ、破られると、捕まえられる例外を投げるのではなく、プログラムを停止させます。

おおまかに言えば、注意深い呼び出し元でも出くわしてしまうなら、例外を投げます。出くわすこと自体が呼び出し元の誤りを意味するなら、契約にします。
