# 概要

Rustでは、[`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html)トレイトを実装するあらゆる値がイテレーターです。イテレーターの値は、そのイテレーターの`next`メソッドを呼び出すことで手動で進めることができます。

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Rustの[`collections`](https://doc.rust-lang.org/std/collections/index.html)の多くは[`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html)を実装しており、コレクションの値から`Iterator`を生成できます。

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

`IntoIterator::into_iter`は`self`の型を消費しますが、その型が必ずしも所有された値である必要はない点に注意してください。そのため、[`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2)、[`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)、[`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1)に対する`IntoIterator`の実装が存在します。所有権の度合いが異なるこれらの実装が、便利な柔軟性をもたらしてくれます。

この概念を理解するのに`traits`の知識は必要ありません。`traits`をマスターするための演習はまるごと用意されています。今は、次のことだけ覚えておいてください。

- `IntoIterator`を実装する型は、イテレーターに変換できるため、_イテラブル_と呼ばれます。
- `Iterator`を実装する型はイテレーターであり、値を_生成_し、_繰り返し処理_できるものです。
- `IntoIterator`を実装する型からは、その`into_iter`メソッドを呼び出すことでイテレーターを取得できます。
- すべてのイテレーターは[`IntoIterator`を実装](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25)しており、自身を生成します。
- `for`ループは常にイテレーターを対象に動作し、渡された値に対して暗黙的に`IntoIterator`を呼び出します。

## `into_iter`と`for`ループ

ベクターを対象にした`for`ループなら、きっと馴染みがあるでしょう。

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

根本的に、`for`ループは、対象の`into_iter`メソッドを呼び出し、値が生成されなくなるまで`next()`を呼び出し続けるための省略記法にすぎません。言い換えると、先ほどのループは次のように展開されます。

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## `iter`と`iter_mut`メソッド

Rustのほとんどのコレクション型には、`iter`と`iter_mut`メソッドが用意されています。型`T`のコレクションに対して、この2つのメソッドは慣習的に次のように動作します。

- `iter`が返すイテレーターは、不変借用した`&T`を生成します。
- `iter_mut`が返すイテレーターは、可変借用した`&mut T`を生成します。

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## `iter`と`iter_mut`と`into_iter`の違い

`iter`と`iter_mut`と`into_iter`がどれもイテレーターを生成するのなら、違いは何でしょうか？

- `iter`が返すイテレーターは、慣習的に不変借用した`&T`を生成します。
- `iter_mut`が返すイテレーターは、慣習的に可変借用した`&mut T`を生成します。
- `into_iter`が返すイテレーターは、状況に応じて`T`、`&T`、`&mut T`のいずれかを生成します。

`into_iter`の呼び出しにおける「状況」とは何でしょうか？　それは`self`の型です。`Vec`、`&'a Vec`、`&'a mut Vec`に対する`IntoIterator`の実装があることを思い出してください。したがって、次のようになります。

- `(&v).into_iter()`は`v.iter()`と同じ => `&T`を返します
- `(&mut v).into_iter()`は`v.iter_mut()`と同じ => `&mut T`を返します
- `v.into_iter()` => `T`を返し、値をムーブします

これは`for`ループで見ると最もはっきりします。

- `for num in &v {...}` => `&T`を束縛します
- `for num in &mut v {...}` => `&mut T`を束縛します
- `for num in v {...}` => `T`を束縛し、値をムーブします

`(&v).into_iter()`と書くよりも`v.iter()`と書くほうが、たいていの場合わかりやすいものです。そのため、`into_iter`よりも`iter`と`iter_mut`が好まれるのには、使い勝手の面での理由があります。

## イテレーターの組み込みメソッドを使う

イテレーターには、`map`、`filter`、`collect`など、数多くの組み込みメソッドが用意されています。これらのメソッドは、クロージャーと組み合わせて使われることもあります。

`map`はクロージャーを使って、イテレーターの値を変換します。`take`は（無限かもしれない）イテレーターを、指定した個数の値を生成したら終了するイテレーターに切り詰めます。

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter`は、クロージャーが`true`と評価される値だけを返すイテレーターに変換します。`count`はイテレーターを消費し、生成された値の個数を返します。

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map`は、与えられたクロージャーによって各要素を新しいイテレーターに変換し、生成されたすべての新しいイテレーターをつなげて平坦化することで、イテレーターを変換します。`collect`は、コレクションの型が[`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html)を実装していれば、新しいコレクションを生成します。

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

[`Iterator`トレイト](https://doc.rust-lang.org/std/iter/trait.Iterator.html)には、このような便利なイテレーター変換が_数多く_用意されています。ドキュメントを読んで、使い方に慣れておく価値があります。

## 遅延評価

Rustのイテレーターは遅延評価であることを知っておくのが重要です。イテレーターを消費するまで、値は何も生成されません。次のコードを書いて実行するとします。

```rust
(0..5).map(|x| x * x);
```

次のコンパイラーエラーが出ます。

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

これは、`map`が別のイテレーターを返すアダプターメソッドだからです。

イテレーターを消費するには、`for`ループを使うか、それ自体はイテレーターではない値を生成するイテレーターメソッドを使います。

たとえば、`collect`は消費メソッドです（その関数シグネチャーはイテレーターではなくジェネリック型を返します）。

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
