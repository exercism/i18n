# 概要

## 複合型

プログラムの中で独自の型を定義できると、便利なことがよくあります。

新しいプリミティブ型を作ることもできますが、実際にそうすることはほとんどありません。
組み込みの[プリミティブ型][primitive]は、場当たり的に選ばれたものではありません。JuliaがJITコンパイルに使っているLLVMコンパイラーの標準の型と、ほぼそのまま対応しています。

それよりもはるかに役立つのが、名前の付いたフィールドを持つ[複合型][composite-types]を定義する機能です。

他の言語にも似た仕組みがあり、`structs`や`records`と呼ばれています。
Juliaのドキュメントではこれを`composite types`と呼んでいますが、言語の構文では`struct`キーワードで定義します（ここには少しずれがあります）。

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

上の例では、いくつか注目したい点があります。

- `id`には型が指定されていないので、コンパイラーはこれを`id::Any`として扱います。
  - **注意**：実際には、フィールドの型を具体的な型で指定して、コンパイラーに手がかりを与えるのがよいでしょう。
  - パラメーターを使うという別の選択肢については、[今後のコンセプト][parametric]で説明します。
- 型の名前はコンストラクターとして使われ、`Person(id, name, age)`のように書くと、`Person`型のインスタンスが得られます。
- 個々のフィールドには、[名前付きタプル][named-tuple]と同じように、ドット記法でアクセスできます。

`Person`型の項目はイミュータブルなので、更新はできません。

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

変更可能にする必要がある場合は、定義に`mutable`を付けます。

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

コンストラクターは、既定ではフィールドを定義と同じ順番で並べる必要があり、型が複雑になると不便になってきます。

`@kwdef`マクロを使うと、新たに2つのことができるようになります。

- コンストラクターが、位置ではなくキーワードを使うようになります。
- フィールドに既定値を設定でき、省略可能にすればコンストラクターから省くこともできます。

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## 複合型の階層

ここまでは、具体的な複合型だけを作ってきました。
確認してみると、どれも`Any`のサブタイプです。

関連する複数の型を作る場合は、それらの階層を定義したほうがよさそうです。
これはとても簡単にできます。

まず、抽象型を作ります。

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

次に、型定義に`<:`演算子を入れて、関係を示します。

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

必要に応じて繰り返しますが、具体的な型をサブタイプにすることはできない点に注意してください。

より複雑な階層が必要な場合は、必要に応じて抽象的なサブタイプを作ります。

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

このような階層の価値は、`Multiple Dispatch`のコンセプトに進み、関数が引数の型をどう扱うかを見ると、よりはっきりわかります。


## 内部コンストラクター

このコンセプトの冒頭で、型の名前がコンストラクターとして使われ、その型の項目を作れることを見ました。

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)
```

ここで、`Person()`は`outer constructor`と呼ばれます。
フィールドの型は型定義との互換性が確認され、必要ならエラーが発生します。

_型_だけでなく、渡される_値_にも制約をかけたい場合はどうすればよいでしょう？

その場合は、型定義の中に`inner constructor`を含めて、適切なチェックを行うことができます。

たとえば、`(x, y)`の座標を受け取ることを想定した抽象型`AbstractPoint`があり、`y > x`という制約を付けたサブタイプが欲しいとします。

```julia-repl
julia> abstract type AbstractPoint end;

julia> struct Point <: AbstractPoint
           x::Integer
           y::Integer
       end;

julia> struct ConstrainedPoint <: AbstractPoint
           x::Integer
           y::Integer
           
           ConstrainedPoint(x, y) =
               y > x ? new(x, y) : @error("require y > x")
       end;
       
julia> Point(3, 2)
Point(3, 2)

julia> ConstrainedPoint(3, 2)
Error: require y > x

julia> ConstrainedPoint(3, 5)
ConstrainedPoint(3, 5)
```

`new()`関数は内部コンストラクターの中で_だけ_使うことができ、入力が妥当だと判断されれば、目的の項目を返します。

不正な入力に対しては、例のようにエラーメッセージを出して止めることもできます。
あるいは、`nothing`や`missing`のようなプレースホルダーを使うほうがよいかもしれません。
これらについて詳しくは、[`Nothingness`][nothingness]のコンセプトを見てください。
