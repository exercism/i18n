# テスト

Factorトラックでは、**Factor 0.101**を使用します。各演習には、`STOP-HERE`と`TASK:`という解析用のワードとテストランナーを定義した`exercism-tools`ボキャブラリが同梱されています。演習のディレクトリで、次のコマンドを実行します：

```
factor -roots=. -run=exercism-tools <exercise>
```

たとえば、`hello-world`演習の場合は次のようになります：

```
factor -roots=. -run=exercism-tools hello-world
```

テストランナーは、すべてのテストが通ればステータス0で終了し、テストが1つでも失敗すると、診断出力とともに0以外のステータスで終了します。

## スキップされるテスト

演習を解くというのは、その演習のすべてのテストを通すということです。
既定では、テストを実行すると、（最初の）1つのテストだけが実行されます。
これは意図的な仕組みで、その1つのテストを通すことに集中できるようになっています。

その仕組みが、テストファイルにある`STOP-HERE`の行です。解析の時点で、それより下をすべて無視するようFactorに伝えるので、テストランナーには上のテストだけが見えます。最初のテストが通ったら、2つの方法でさらにテストを有効にできます：

- **`STOP-HERE`の行を削除する**と、残りのテストをまとめて有効にできます。
- **`STOP-HERE`の行をさらに下へ移動する**と、テストを1つずつ、またはタスクを1つずつ有効にできます。コンセプト演習では、テストは`TASK:`マーカーの下にまとめられています。`STOP-HERE`を次の`TASK:`の直前に移動するのが自然な進め方です。

すべてのテストを有効にして、実装がそれらをすべて通すようになったら、演習を解けたことになります！
