# 指示の補足

## `from_quote`による時間リテラル

`Time.from_quote`関数は、`"HH:MM:SS"`という形式の文字列を`Time`にパースします。
これにより、次のようなコードを書くことができます。

```roc
time : Time
time = "00:01:23"
```

このコードは、コンパイル時に暗黙的に`Time.from_quote("00:01:23")`を呼び出します。
この方法（および後述する他の方法）でコンパイル時にコードを実行すると、実行時にパースやデータの検証を行う必要がないため、プログラムを高速化できる可能性があります。
さらに、無効なデータ（たとえば誤った日付の形式）は実行時ではなくコンパイル時に拒否されるので、アプリはより堅牢になります。
最後に、コードが読みやすくなります。
たとえば、この演習にあるテストの1つを見てみましょう。

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

ただし、このコードを読んだ人は、`advance_time`関数が`Time`ではなく`Str`を受け取るのだと誤解するかもしれません。
これは混乱やエラーのもとになります。
そのため、少し長くなりますがより明確な`"00:00:05".Time`という書き方のほうが好ましいかもしれません。こちらもコンパイル時に`from_quote`を呼び出します。

自分のプログラムでは、代わりに`from_str`を使うほうがよいかもしれません。

```roc
Time := { ... }.{
    from_str : Str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

また、次のように、コンパイル時に`from_str`（または他の純粋な関数）を呼び出すこともできます。

```roc
Ok(time) = Time.from_str("00:01:23")
```

補足：この定義をトップレベルに置くと、コンパイル時に実行されます（関数が純粋で、その入力がコンパイル時にわかっているためです）。
関数の中では、実行時に`from_str`を使えます。
