# 概要

[メソッドのオーバーロード][method-overloading]はJavaの重要な概念で、同じ名前のメソッドを、それぞれ仮引数リストが異なっていれば複数持てるようにします。
この機能はJavaのオブジェクト指向プログラミングの基礎をなすもので、型や入力の数が違っても同じような操作を行えるようにします。
メソッドのオーバーロードを使うと、似た処理を行うメソッドに同じ名前を付けられるので、コードの可読性と整理がよくなります。
ここで押さえておきたいのは、オーバーロードが決まるのはメソッドのシグネチャによるという点です。シグネチャには、メソッド名と仮引数リストが含まれます。

## 要点

- **シグネチャが重要**: 戻り値の型はメソッドのシグネチャには含まれないので、戻り値の型だけを変えてもオーバーロードにはなりません。
- **仮引数の違い**: オーバーロードするメソッドは、仮引数の数か型が違っていなければなりません。
- **用途**: オーバーロードは、さまざまな型の入力でメソッドをより直感的に使えるようにするためによく使われます。

## メソッドのオーバーロードの例

数の足し算ができる`Calculator`クラスを考えてみましょう。
オーバーロードを使うと、型の異なる足し算を用意できます。

```java
public class Calculator {

    public int add(int a, int b) {
        return a + b;
    }

    public double add(double a, double b) {
        return a + b;
    }

    public int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

## ベストプラクティス

- **わかりやすさ**: オーバーロードしたメソッドは、コードがより直感的になるように使います。
  - オーバーロードしたメソッドの動作は、互いに関連していて一貫しているべきです。
- **曖昧さを避ける**: オーバーロードした各メソッドの目的をはっきりさせ、仮引数リストの違いが混乱を招かない程度に十分なものであることを確認しましょう。
- **ドキュメント**: オーバーロードしたメソッドの各バージョンをきちんと文書化しましょう。
  - 明確なドキュメントがあると、他のエンジニアが各メソッドの目的と使い方を理解しやすくなります。
- **戻り値の型を揃える**: オーバーロードしたメソッドでは戻り値の型を変えることもできますが、混乱を避けるため、可能な限り揃えておくのが一般的によい習慣です。
- **オーバーロードを控えめに**: メソッドのオーバーロードを使いすぎないようにしましょう。
  - 過度なオーバーロードは、コードを読みにくく、保守しにくくします。

## まとめ

メソッドのオーバーロードはJavaの強力な機能で、正しく使えばコードの可読性と柔軟性を大きく高めてくれます。
メソッドをより多用途に、さまざまな状況に適応できるものにし、Javaプログラムをよりモジュール化して保守しやすくします。
