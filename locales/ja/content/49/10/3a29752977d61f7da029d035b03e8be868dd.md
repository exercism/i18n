# はじめに

## 例外

Javaプログラミング言語は、エラーやその他の例外的な出来事を扱うために_例外_を使います。

### 例外とは

例外とは、プログラムの実行中に発生し、命令の通常の流れを妨げる出来事です。
Javaでは例外は明示的に発生させ、その行為を_例外をスローする_と呼びます。
例外を処理する行為を_例外をキャッチする_と呼びます。

Javaでは、すべての例外は`Exception`クラスのサブクラスであり、`Exception`クラス自体は`Throwable`のサブクラスです。

Javaでは、例外を2つの種類に分けています：

1. チェック例外
2. 非チェック例外

#### チェック例外

_チェック例外_は、アプリケーションが予期し、回復すべき例外的な状況です。
チェック例外の例として、メソッドが存在しないファイルを読み取ろうとしたときに発生する`FileNotFoundException`があります。

この種類の例外はコンパイル時にチェックされます。チェック例外をスローするメソッドは、メソッドシグネチャでそのことを指定する必要があり、チェック例外をスローする可能性があるメソッドを呼び出すコードは、それを処理する必要があります。そうしないと、コードはコンパイルされません。

すべてのチェック例外は、`RuntimeException`を継承していない`Exception`のサブクラスです。

#### 非チェック例外

_非チェック例外_は、アプリケーションが通常予期できず、回復もできない例外的な状況です。
非チェック例外の例として、`null`ではない値を期待しているメソッドが`null`を受け取ったときに発生する`NullPointerException`があります。

この種類の例外はコンパイル時にチェックされません。非チェック例外をスローするメソッドは、メソッドシグネチャでそのことを指定する必要はなく、非チェック例外をスローする可能性があるメソッドを呼び出すコードも、それを処理する必要はありません。

すべての非チェック例外は`RuntimeException`を継承しており、`RuntimeException`自体は`Exception`を拡張したものです。

### 例外をスローする

Javaのメソッドは、`throw`文を使って例外をスローできます。

#### チェック例外をスローする

メソッドからチェック例外をスローする場合は、以下の例のように、`throws`キーワードを使ってメソッドシグネチャでそのことを指定する必要があります。
これにより、呼び出し側のコードは、例外がスローされる可能性を予期し、適切に処理しなければならなくなります。

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

#### 非チェック例外をスローする

メソッドから非チェック例外をスローする場合、メソッドシグネチャでそのことを指定する必要はありません。ただし、指定することは可能です。

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

### 例外を処理する

Javaで例外を処理するには、`try`、`catch`、`finally`キーワードを使います。

- 例外をスローする可能性があるコードの文は、`try`ブロックで囲む必要があります。
- `try`ブロックの後には、`try`ブロック内でスローされた例外をキャッチする1つ以上の`catch`ブロックが続きます。
- `catch`ブロックの後には、例外がスローされたかどうかに関係なく、`try`ブロックの後に必ず実行される`finally`ブロックを置くこともできます。

次の例は、これらのキーワードがどのように機能するかを示しています。

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

この例で、例外がスローされない場合は、次のように出力されます：

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

ただし、`bankAccount.withdraw(amount)`文が`InsufficientBalanceException`をスローした場合は、次のように出力されます：

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

または、`bankAccount.withdraw(amount)`によって非チェック例外がスローされた場合は、次のように出力されます：

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

### エラー

Javaには、_エラー_と呼ばれる別のカテゴリもあります。これは、アプリケーションの外部にある深刻な問題です。
エラーの例として、アプリケーションがシステムで利用可能なメモリよりも多くのメモリを使おうとしたときに発生する`OutOfMemoryError`があります。

非チェック例外と同様に、エラーはコンパイル時にチェックされません。
違いは、エラーがシステムレベルの問題を表しており、通常はアプリケーションではなく、Java仮想マシンや環境によってスローされることです。
アプリケーションは通常、それらをキャッチしたり処理したりしようとすべきではありません。

Javaのすべてのエラーは、`Error`クラスを継承しています。
