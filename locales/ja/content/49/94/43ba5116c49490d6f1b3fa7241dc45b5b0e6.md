# はじめに

スカラーコードは、ある条件に応じて分岐するために、さまざまな命令が設定するフラグに頼っています。
一方、パックド値は1つではなく、多数の値を並列に表します。
1つの条件が、あるレーンでは成り立たず、別のレーンでは成り立つことがあります。

こうした理由から、SIMDコードはデフォルトで_分岐なし_になっています。

フラグに頼る代わりに、パックド比較は通常、デスティネーションオペランドに**マスク**を生成します。
各レーンについて、比較は、真ならそのレーン全体を1で埋め、偽なら0で埋めます。
符号付き整数として読むと、真のレーンは`-1`、偽のレーンは`0`です。

このマスクは、ビット単位の演算と組み合わせて、特定のレーンを絞り込むのに使えます。

## パックド比較

スカラーの`cmp`は、同時にさまざまなフラグを設定するために使われるという意味で汎用的です。
そのフラグを別の命令が消費して、分岐したり計算を行ったりできます。

しかし、パックド比較は条件を調べると同時にマスクを計算するため、汎用的ではありません。
比較には、テストする条件を正確に指定しなければなりません。

これには2つの方法があります。

- 整数比較では、条件を接尾辞として与えます。等値なら`eq`、より大きいなら`gt`です。
  その他の変種は、これらいずれかの結果を組み合わせて作ります。
- 浮動小数点比較では、条件を即値にエンコードして与えます。
  この即値の値が異なると、テストされる条件も異なります。

整数比較で特定の条件接尾辞を使う点を除けば、構文はすでに見てきたのと同じ構造に従います。

- 整数の場合、`p` + `cmp` + 条件 + サイズ（`b`・`w`・`d`・`q`）。
- 浮動小数点の場合、`cmp` + `p` + サイズ（`s`・`d`）。
  条件は追加のオペランドとして即値で渡します。

### 整数比較

前述のとおり、整数比較には等値とより大きいの2つしかありません。

| 命令 | 説明 |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | レーンごとの等値 |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | レーンごとの**符号付き**「より大きい」 |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

より小さい比較を作るには、オペランドを入れ替えて`gt`を使います。`a < b` == `b > a`です。

この比較は**符号付き**であることに注意してください。
符号なしの比較を行うには、両方のオペランドの最上位ビットを反転します。
これは、最上位ビットだけを立てたマスクとの`XOR`で行えます。

~~~~exercism/note
よく使うイディオムが2つあります。

1. レジスタ自身と`XOR`を取って、すべて0を作る。
2. レジスタ自身と比較して、すべて1を作る。

たとえば、次のように書きます。

```x86asm
pxor xmm4, xmm4    ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

すべて0とすべて1は、それぞれ「どこでも偽」と「どこでも真」をエンコードするのによく使われるマスクです。
これらは、よく使われる番兵値であるパックド`0`やパックド`-1`を表すのにも使えます。
たとえば、文字列の終わりを示すNULは`0`です。
~~~~

### 浮動小数点比較

浮動小数点のレーンは形が異なります。命令は`cmpps`（64ビットのレーンでは`cmppd`）の1つだけで、条件は即値として渡します。

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASMには、正しい即値に対応し、より覚えやすい擬似命令もあります。
以下ではすべて、`px`の`x`は`s`（32ビット浮動小数点）または`d`（64ビット浮動小数点）です。

| 擬似命令 	 | 即値 | 比較             |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | aまたはbがNaN   |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | aもbもNaNでない |

## マスクを使った選択

マスクは条件の結果をエンコードしたものです。
これを使うと、その条件に従って、2組の値のどちらかをレーンごとに選べます。
マスクが真のところでは一方の値からレーンを取り、偽のところではもう一方から取ります。

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

このパターンは、分岐なしの選択をパックドにした形です。
すべてのレーンが計算され、どの値が残るかを決めるのはマスクだけです。どこにも`jcc`は現れません。

## 専用のブレンド命令

同じ選択を直接行う命令があり、マスクレジスタから要素ごとに1ビットを読み取ります。
これらは**ブレンド**命令と呼ばれます。

| 命令 | 要素     | マスクの取得元     |
|-------------|-------------|-----------------|
| `pblendvb`  | バイト        | 暗黙の`xmm0` |
| `blendvps`  | 32ビットレーン | 暗黙の`xmm0` |
| `blendvpd`  | 64ビットレーン | 暗黙の`xmm0` |

1つ目の命令は整数の構文に従い、残りの2つは浮動小数点の構文に従うことに注意してください。
ただし、これらの命令は生のバイトを選択するだけなので、どれも整数と浮動小数点の両方に使えます。

各要素について、ブレンドは、対応するマスク要素の最上位ビットがクリアならデスティネーションを保持し、セットされていればソースを取ります。
参照されるのはその**最上位ビット**だけです。比較のマスクはレーンがすべて1かすべて0なので、この条件を満たします。
マスクレジスタは常に`xmm0`で、これは暗黙です。

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

また、`pblendvb`を使えば、他の任意のサイズについても、比較のマスクからレーンを選べます。
真のレーンではすべてのバイトが1なので、`pblendvb`はそれらすべてを選択します。

~~~~exercism/note
これらの命令はどれも、行う演算（`blend`）のあとに`v`を付けます。
この`v`は_可変_を意味します。選択が静的ではなく、レジスタに依存するからです。

`v`のない変種もあり、こちらは即値に従って選択します。
同じパターンに従い、即値のビット`i`がセットされていればレーン`i`を選びます。
~~~~

## マスクからスカラーへ戻す

強力ではありますが、SIMDコードにはスカラーコードほどの柔軟性がありません。
多くの場面で、パックドレジスタからスカラー命令の世界へ戻る必要があります。

`movmsk`命令ファミリーは、この2つの世界をつなぐ橋渡しの役割を果たします。
これらの命令は、各レーンの**最上位ビット**を汎用レジスタに取り出します。

| 命令 | 集める対象                     | 結果の幅 |
|-------------|-----------------------------|--------------|
| `pmovmskb`  | 16バイトそれぞれの最上位ビット | 16ビット      |
| `movmskps`  | 4つのdwordそれぞれの最上位ビット | 4ビット       |
| `movmskpd`  | 2つのqwordそれぞれの最上位ビット | 2ビット       |

比較のあとで使うと、セットされた各ビットが「真」のレーンを、クリアされた各ビットが「偽」のレーンを表します。
この結果は、通常どおりスカラー命令で操作できます。
たとえば、`popcnt`は一致の数を数え、`tzcnt`は最初の一致を見つけます。

汎用レジスタは32ビット幅でも64ビット幅でもかまいません。

## ベクトル全体をテストする

スカラーの`test`命令には、パックド版の`ptest`もあります。

これは、2つのオペランド間で`AND`演算を行い、オペランドを変更しないという点で、スカラーの対応する命令と似ています。
`test`と違い、`ptest`は`ANDN`演算も行い、1つ目のオペランドを反転します。

したがって、`ptest`は、結果に応じてフラグを設定する、`pand`と`pandn`の非破壊版と考えることができます。
これら2つの命令とほぼ同じように、`ptest`はSIMDレジスタ全体を1つのレーンとして扱うため、サイズ接頭辞を付けません。

`AND`演算の結果が`0`なら`ZF`がセットされ、`ANDN`演算の結果が`0`なら`CF`がセットされます。
つまり、`ptest`を使えば、すべて1のマスクとすべて0のマスクの両方を調べられます。

1. レジスタに対して`ptest`をそのレジスタ自身と使うと、レジスタがすべて0のときだけ`ZF`がセットされます。
   これは、`0`かどうかを調べるためにレジスタを自身と`test`する、よくあるスカラーのイディオムを再現しています。
2. レジスタに対して`ptest`をすべて1のマスクと使うと、レジスタがすべて1のときだけ`CF`がセットされます。
   また、レジスタがすべて0のときだけ`ZF`もセットされるので、両方のマスクを一度に調べられます。

```x86asm
pxor    xmm0, xmm0   ; all zeros
pcmpeqb xmm1, xmm1   ; all ones
pcmpeqb xmm2, xmm2

ptest xmm0, xmm0     ; ZF set: a register against itself detects all zeros
ptest xmm0, xmm1     ; ZF set, CF clear: xmm0 is all zeros, not all ones
ptest xmm2, xmm1     ; CF is set only if xmm2 is all ones
```

`ptest`の結果は、通常どおり、分岐に使ったり、`setcc`や`cmovcc`のような分岐なし命令に使ったりできます。
