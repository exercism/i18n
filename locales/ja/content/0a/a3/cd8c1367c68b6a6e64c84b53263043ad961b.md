# 概要

## `jq`のエラー

`jq`が報告するエラーは、大きく2つに分かれます。

1. **コンパイル時エラー**：プログラム自体が不正なものです。構文エラー、未定義の関数や変数への参照などが該当します。`jq`はプログラムの実行を完全に拒否します。

   ```sh
   $ jq -n '1 + $foo + 2'
   jq: error: $foo is not defined at <top-level>, line 1, column 5:
       1 + $foo + 2
           ^^^^
   jq: 1 compile error
   ```

2. **実行時エラー**：プログラムは正しいものの、値を処理している最中に何かがうまくいかないものです。数値に文字列でインデックスしようとする、`fromjson`で不正なJSONテキストを解析する、間違った型の引数で関数を呼び出す、などが該当します。

   ```sh
   $ echo '42' | jq '.foo'
   jq: error (at <stdin>:1): Cannot index number with "foo"
   ```

この概念で扱うのは**実行時エラー**です。エラーを発生させる方法、捕まえる方法、そして止める方法を見ていきます。

捕まえられなかった実行時エラーがあると、`jq`は_標準エラー出力_にメッセージを出力し、ステータス`5`で終了します。

## エラーを発生させる：`error`と`error(message)`

[`error`][man-error]フィルターはエラーを発生させます。

- `error`は、**入力**値を値とするエラーを発生させます。
- `error(message)`は、`message`の結果を値とするエラーを発生させます。

```jq
"bad input" | try error catch .
# => "bad input"

42 | try error("invalid value: \(.)") catch .
# => "invalid value: 42"
```

~~~~exercism/note
エラーの値は文字列に限らず、_どのような_JSON値でもかまいません。構造化されたエラーを発生させれば、`catch`ハンドラーがエラーの内容に基づいて判断できるようになります。

```jq
try error({kind: "range", msg: "age must be non-negative"})
catch (if type == "object" then "\(.kind) error: \(.msg)" else "unexpected: \(.)" end)
# => "range error: age must be non-negative"
```
~~~~

文字列以外のエラー値が捕まえられなかった場合、`jq`はそれをJSONとして出力し、`(not a string)`という印を付けます。

```sh
$ jq -n 'error({code: 42, msg: "boom"})'
jq: error (at <unknown>) (not a string): {"code":42,"msg":"boom"}
```

## エラーを捕まえる：`try`と`catch`

エラーは[`try EXP catch HANDLER`][man-try-catch]で捕まえられます。最初の式が実行され、そこでエラーが発生すると、**エラー値を入力として**`HANDLER`式が実行されます。ハンドラーの出力は、tryした式の出力だったかのように出力されます。

```jq
true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]

true | try error("some exception") catch .
# => "some exception"
```

短い形式の`try EXP`は`try EXP catch empty`と同じです。エラーは捨てられ、何も出力されません。

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

~~~~exercism/note
エラーは`try`の中で**ストリームの残りを中断**します。すでに生成された値はそのまま残りますが、エラーより後の部分は評価されません。

```jq
jq -n 'try (1, error("x"), 3) catch "caught: \(.)"'
# outputs:
# 1
# "caught: x"
# (3 is never produced)
```
~~~~

ハンドラーは、新しいエラーを発生させることも、元のエラーを`error`でそのまま発生し直すこともできます。エラー値はハンドラーの入力なので、これでエラーがそのまま伝播します。

```jq
try repeat(f) catch
  if . == "break" then empty else error end
```

## エラーを抑える：`?`演算子

`EXP?`として使う[`?`演算子][man-question-mark]は、`try EXP`の省略形です。失敗する式を、単に何も出力しない式に変えます。

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]

true | [.a?]
# => []
```

インデックス演算子に付けて使われることがよくあります。

- `.foo?`は`.["foo"]?`
- `.[]?`は、入力が配列かオブジェクトのときだけ繰り返し、それ以外では空になります

~~~~exercism/caution
`?`は、予期していなかったものも含め、**あらゆる**エラーを抑え込みます。`user`がオブジェクトでないとき、`user.name?`は何も出力せずに終わるので、データの問題やプログラムの打ち間違いを隠してしまうことがあります。何かが失敗した_こと_を知る必要があるときは、`try ... catch`を使うか、入力を明示的に検証しましょう。
~~~~

## 代替演算子`//`

`a // b`は、`a`が失敗したときに`b`を出力するものと期待するプログラマーもいるかもしれません。これは古いバージョンの`jq`では正しかったのですが、`jq`1.6以降は違います。`//`演算子はエラーを抑えません。`a`が値を出力しない、`false`、または`null`のときにだけ`b`で置き換え、`a`のエラーはそのまま伝播します。

```sh
$ jq -n '(error("x")) // 42'
jq: error (at <unknown>): x
```

エラーに対するフォールバックがほしいときは、`try a catch b`を使います。

## 分割代入の代替演算子`?//`

[`?//`演算子][man-question-mark-slash-slash]は、分割代入とエラー処理を組み合わせます。バインドのパターンを順に試し、うまくいくまで続けます。失敗した代替のパターンでバインドされた変数は`null`になります。

```jq
# input:
#   [
#     {"a": 1, "b": 2, "c": {"d": 3, "e": 4}},
#     {"a": 5, "b": 6, "c": [{"d": 7, "e": 8}]}
#   ]

.[] as {$a, $b, c: {$d, $e}} ?// {$a, $b, c: [{$d, $e}]}
| {$a, $b, $d, $e}

# outputs:
# {"a": 1, "b": 2, "d": 3, "e": 4}    # first element: c is an object, first pattern matched
# {"a": 5, "b": 6, "d": 7, "e": 8}    # second element: c is an array, second pattern matched
```

ここでは、最初のパターンは`c`が`d`と`e`というキーを持つ_オブジェクト_であることを期待し、2つ目のパターンは`c`がそのようなオブジェクトを含む_配列_であることを期待しています。最初の入力要素は最初のパターンにバインドされます。2つ目の要素はそのパターンに失敗するので、代わりに2つ目のパターンが試されます。

こうすると、いくつかの形のどれかを取る入力を、`if type == ...`のような明示的な連鎖を書かなくても、1つのプログラムで分割代入できます。

## プログラムを停止する：`halt`と`halt_error`

エラーへの適切な対応が、処理を完全に止めることである場合もあります。

- [`halt`][man-halt]は`jq`プログラムを即座に停止し、それ以上何も出力しません。終了ステータスは`0`です。
- [`halt_error`][man-halt-error]はプログラムを停止し、**入力**を生のテキストとして（装飾なし、改行すら付けずに）_標準エラー出力_に出力し、指定したステータスで終了します。デフォルトは`5`です。

```sh
$ echo '"Error: something went wrong"' | jq 'halt_error(1)'
Error: something went wrong    # printed on stderr, exit status 1
```

これらのフィルターは、読むべき入力がまだ残っていても、プログラムを即座に停止することに注意しましょう。

### 終了ステータス

参考までに、`jq`は次の終了ステータスを使います。

| ステータス | 意味                                          |
| :----: | ------------------------------------------------ |
| `0`    | 成功                                          |
| `2`    | 使い方のエラー（コマンドラインオプションの誤り）           |
| `3`    | コンパイルエラー                                    |
| `5`    | 実行時エラー（または引数なしの`halt_error`） |

`--exit-status` / `-e`オプションを付けると、ステータスは代わりに最後の出力値を反映します。`true`か数値なら`0`、`false`か`null`なら`1`、出力がなければ`4`です。

## デバッグの助けになるもの

エラーの出どころを突き止めたいときは、次のフィルターが役立ちます。

- [`debug`][man-debug]は入力をそのまま通しますが、`["DEBUG:", <input>]`を標準エラー出力に出力します。`debug(msgs)`は`msgs`もデバッグメッセージとして出力します。
- [`stderr`][man-stderr]は入力を生のままコンパクトに標準エラー出力へ出力します。
- [`input_line_number`][man-input-line-number]は、今フィルターしている入力の行番号を出力します。ファイルに多数のJSONテキストが含まれていて、そのうちの1つが壊れているときに重宝します。
- [`$__loc__`][man-loc]は、プログラムのどこに現れるかを示す`file`と`line`キーを持つオブジェクトを出力します。これはエラーメッセージに埋め込むことができます。

```jq
def checked_div($d):
  if $d == 0
  then error("\($__loc__): division by zero")
  else . / $d end;

try (10 | checked_div(0)) catch .
# => "{\"file\":\"<top-level>\",\"line\":3}: division by zero"
```
