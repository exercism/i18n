# 説明

Grand Marqueeは初日の夜を迎え、スタッフ全員が一斉に働いています。
観客はどの扉からもなだれ込み、いくつもの売り場の窓口が同じチケットロールから売り、プレミア上映は満席に近づいています。そして映写室では、リールを回し続けなければなりません。

スタッフが共有するものはすべて、あるメモリアドレスに置かれています。テストは複数のスレッドから同時にあなたの関数を呼び出します。
値を読み、変更し、書き戻すという手順を別々に行うと、この負荷の下では更新が失われてしまいます。そのため、どの関数も更新をアトミックに行う必要があります。

この演習で共有する値は、すべて64ビットの符号付き整数です。

タスクは5つあります。

~~~~exercism/note
この演習での更新は、_アトミック_な命令で行う必要があります。
テストはあなたの関数を並行して実行し、更新が失われていないかを確認します。そのため、アトミックでない読み取り・変更・書き込みは、テストに失敗する可能性が非常に高いです。
~~~~

## 1. 入場者数を数える

扉は開いていて、どの扉にも案内係がいてチケットをもいでいます。
通されたグループは、1つの共有された入場者数の集計に数えられます。どの扉でも同時に数えているので、館内の人数はそれでも正しく出なければなりません。

`admit_group`関数を実装して、グループの人数をアトミックに集計へ加えます。

この関数は、次の順番で引数を取ります。

- `admissions`: 共有された入場者数の集計のメモリアドレスで、64ビットの符号付き整数です。
- `group_size`: グループの人数で、64ビットの符号付き整数です。常に`0`より大きい値になります。

```c
admissions = 120, group_size = 4
// admissions is now 124
```

テストは、複数の扉から同時にグループを入場させます。
最終的な集計は、通したすべてのグループの合計と同じでなければなりません。

この関数に戻り値はありません。
集計はその場で更新してください。

## 2. リールを交換する

映写機に取り付けられるリールは1つだけです。
次のリールを取り付け、今のリールを取り外すのは、1つの動作でなければなりません。映写技師が2人同時に機械の前にいると、別々の手順では、同じリールを2人に渡してしまったり、床に落としてしまったりするかもしれません。

`change_reel`関数を実装して、次のリールをアトミックに取り付け、それまで取り付けられていたリールを返します。

この関数は、次の順番で引数を取ります。

- `mounted`: 取り付けられているリールの識別子のメモリアドレスで、64ビットの符号付き整数です。
- `next_reel`: 取り付けるリールの識別子で、64ビットの符号付き整数です。

```c
mounted = 7, next_reel = 9
// => 7, and mounted is now 9
```

この関数は、それまで取り付けられていたリールの識別子を、64ビットの符号付き整数として返します。
テストでは、複数のスレッドが同じマウントを通して同時にリールを交換し、渡したリールがそれぞれちょうど1回ずつ返ってくることを確認します。

## 3. チケットを売る

どの窓口も、1つの共有された販売枚数から売っています。
扉のときのように数を足すだけでは、ここでは足りません。それぞれの販売は、自分に割り当てられた番号も知る必要があります。
2つの販売が同じ番号を共有してはいけませんし、混雑が終わったあと、数は売れたチケットの枚数とぴったり同じでなければなりません。

`sell_ticket`関数を実装して、数にアトミックに1を足し、たった今売れたチケットの番号を返します。
チケット番号は、この販売の_後_の数です。数が`41`だったとき、この販売はチケット`42`になります。

この関数は、次の引数を取ります。

- `tickets_sold`: 共有された販売枚数のメモリアドレスで、64ビットの符号付き整数です。

```c
tickets_sold = 0
// => 1, and tickets_sold is now 1

tickets_sold = 41
// => 42, and tickets_sold is now 42
```

この関数は、チケット番号を64ビットの符号付き整数として返します。
テストでは、複数の窓口から同時に販売します。返される番号はすべて異なっていなければなりませんし、最終的な数は販売回数と同じでなければなりません。

## 4. プレミア上映を満席にする

プレミア上映には決まった数の座席があり、どの窓口もその席を売っています。
販売は、席がまだ残っている間だけ通すことができ、上映は絶対に売り越してはいけません。どの窓口も同じ瞬間に最後の1席を奪い合うときでさえ、です。
数を確認してから足すという2つの別々の手順には、その間に隙間が生まれます。そのため、確認と更新は一緒に成功するか、一緒に失敗するかのどちらかでなければなりません。

`claim_seat`関数を実装して、席がまだ空いているときに、次の席をアトミックに確保します。
席を確保できたときは、その席の番号を返します。番号は、この確保の後の、確保済みの席の数です。
上映が満席のときは`0`を返し、数は変えません。

この関数は、次の順番で引数を取ります。

- `seats_taken`: すでに確保された席の数のメモリアドレスで、64ビットの符号付き整数です。`capacity`を超えることはありません。
- `capacity`: 上映の座席数で、64ビットの符号付き整数です。常に`0`より大きい値になります。

```c
seats_taken = 0, capacity = 150
// => 1, and seats_taken is now 1

seats_taken = 82, capacity = 150
// => 83, and seats_taken is now 83

seats_taken = 149, capacity = 150
// => 150, and seats_taken is now 150

seats_taken = 150, capacity = 150
// => 0, and seats_taken stays 150
```

この関数は、席の番号を、上映が満席のときは`0`を、64ビットの符号付き整数として返します。

## 5. 映写室に気を配る

映写室に入れるのは1人だけです。
メモリ上の1つのワードが、使用中かどうかを表します。`0`なら空き、`1`なら使用中です。
スタッフは一晩中やって来て、それぞれに中でやることがあります。記録帳に署名する、映写機にフィルムを通す、リールを片付ける、などです。
どんな用事であっても、映写室のルールは同じです。それを守らせるのがあなたの仕事です。1人が中に入れるのは、その用事を始めてから終えるまで、一度に1人だけです。

`visit_booth`関数を実装します。この関数は次のことを行います。

1. 映写室が空くまで待ちます。
2. 映写室を確保します。
3. 訪問者の用事を実行します。
4. 用事が終わったあと、戻る前に映写室を再び開けます。

映写室がほかの人に使われている間は、`pause`で行儀よく待ちます。

この関数は、次の順番で引数を取ります。

- `booth`: 使用中の状態を表すワードのメモリアドレスで、`0`か`1`のどちらかの64ビットの符号付き整数です。
- `task`: 訪問者の用事で、引数を取らず、戻り値もない関数です。

テストでは、映写室と共有の記録帳を確認する用事を実行します。
つまり、映写室は用事の間ずっと使用中でなければなりません。また、どの訪問もその用事をちょうど1回だけ実行しなければなりません。さらに、複数の訪問者が同時に来ても、記録帳は正確でなければなりません。

~~~~exercism/caution
訪問者の用事は、呼び出し規約に従うごく普通の関数です。

- caller-savedレジスタはどれでも上書きされる可能性があります。そのため、用事のあとにもまだ必要になるものは、呼び出しが触れない場所に取っておいてください。
- また、呼び出しの時点でスタックが16バイト境界に整列していることを前提としています。

どちらのルールに違反しても、チェックの失敗ではなくクラッシュとして現れることがあります。
~~~~
