# 説明

Juliaは、ほとんどのプログラミング言語と同じように、さまざまなコレクション型を提供しています。

なかには、`Vectors`や多次元の`Arrays`のように、もともと順序をもつものもあり、そうしたものでは要素に位置でアクセスできます。
順序をもたないコレクション（`Sets`、`Dicts`）もあり、その場合は要素にキーや値を使ってアクセスします。

もっとも単純な場合として、`Ints`の`Vector`があり、それを昇順に[並べ替え][ref-sorting]たいとしましょう。

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

簡単ですね！
[`sort()`][ref-sort]という関数は、名前のとおりで、並べ替えた`Vector`を返すように見えます。

_冗談です！_
シラバスのこの段階まで来ると、（正しくも）ここには検討すべきニュアンスがあるとお気づきかもしれません。

## 破壊的な関数と非破壊的な関数

`sort(v)`を実行したあと、`v`はどうなっているでしょうか？

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

元のVectorは変わっていません。
`sort()`は、入力をコピーして返す***非破壊的***な関数です。

これは多くの場面でよい設計です。振る舞いを容易に推論できる[純粋関数][wiki-pure-func]であり、並列・分散コードであっても同じことがいえます。

一方で、10億個の文字列からなる配列を並べ替えたいとします。

並べ替えにはおそらく時間がかかります（これについては後で説明します）。
さらに、すべてをコピーし（_これも遅い！_）、そのコピーを保存するのに十分なメモリ（_数ギガバイト！_）を確保する必要があります。

よく似たこちらのコードと比べてみましょう。

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

今度は、入力の`Vector`がコピーされずにその場で並べ替えられ、元の順序は永久に失われます。

これは効率的なこともありますが、バグを生んで予期しない[副作用][wiki-side-effect]を引き起こしたり、あなたのコードを使うほかの人を混乱させたりもします。
_よく選んでくださいね！_

[`sort!()`][ref-sort!]は[破壊的な関数][ref-mutating-func]です。（_非常に強い_）慣習として、入力を変更する関数は、プログラマーへの警告として名前に`!`を付けます。

## 何を基準に並べ替えるか？

`Int64`の値を並べ替えるのは比較的簡単です。2が1より大きく3より小さいことは、小さな子どもでもわかります。

ほかの型はもっと複雑かもしれませんが、一般に`isless(x, y) == true`ならば`x < y`です。
Juliaはほとんどの標準型に対して`isless()`を実装しており、[独自の型][concept-composite-types]を比較するための同様の[メソッド][concept-multiple-dispatch]を自分で定義することもできます。

たとえば、Unicode文字の場合です（ヨーロッパの文字では、大文字は小文字より前に並びます）。

```julia-repl
julia> j = collect("Julia")
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)

julia> sort(j)
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0false069 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
```

並べ替える前の要素に任意の関数を適用することもできます。たとえば、符号を無視する[`abs`][ref-abs]や、大文字と小文字を区別せずに並べ替える[`uppercase`][ref-uppercase]です。

```julia-repl
julia> nums = [3, -2, -4, 1]
4-element Vector{Int64}:
  3
 -2
 -4
  1

julia> sort(nums)
4-element Vector{Int64}:
 -4
 -2
  1
  3

julia> sort(nums, by=abs)
4-element Vector{Int64}:
  1
 -2
  3
 -4

# j is from "Julia", as previously

julia> sort(j, by=uppercase)
5-element Vector{Char}:
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)

julia> vecs = [[1, 3], [4, 2], [3, 4], [2, 1]];

julia> sort(vecs)  # by default sorts by the first element of the (2-element) vectors
4-element Vector{Vector{Int64}}:
 [1, 3]
 [2, 1]
 [3, 4]
 [4, 2]

julia> sort(vecs, by=last)
4-element Vector{Vector{Int64}}:
 [2, 1]
 [4, 2]
 [1, 3]
 [3, 4]
```

[多次元配列][concept-mda]では、`dims`キーワードを指定して並べ替える方向を制御できます。

```julia-repl
# create a matrix of integers in random order
julia> A = reshape(Random.shuffle(1:9), (3, 3))
3×3 Matrix{Int64}:
 8  4  9
 6  7  5
 2  1  3

julia> sort(A, dims=1)  # sort rows
3×3 Matrix{Int64}:
 2  1  3
 6  4  5
 8  7  9

julia> sort(A, dims=2)  # sort columns
3×3 Matrix{Int64}:
 4  8  9
 5  6  7
 1  2  3
```

## インデックスの配列で並べ替える

並べ替える要素が大きなオブジェクトの場合、位置を表すインデックスを扱うほうが簡単なことがあります。

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

`langs`はVectorなので、各インデックスは[範囲][concept-range]`1:length(langs)`の整数です。
Vectorに対して[sortperm()][ref-sortperm]を呼び出した結果は、これらの整数の[順列][wiki-permutation]で、入力Vectorを並べ替えたものに対応します。

## 部分的な並べ替え

プログラムは、入力をすべて並べ替える必要がありますか？
最初のいくつか、あるいは最後のいくつかの要素だけが重要であれば、[部分的な並べ替え][wiki-partial-sort]のほうがずっと速いことがあります。

Juliaには、[`partialsort()`][ref-partialsort]と[`partialsort!()`][ref-partialsort!]という関数があります。これらは指定した要素や要素の範囲が正しいことを保証しますが、入力の残りの部分については何も保証しません。

2番目の引数には、整数または範囲を指定でき、並べ替えたあとの入力のインデックスを表します。

```julia-repl
julia> vsq = [9, 4, 16, 1];  # would be [1, 4, 9, 16] after a full sort

julia> partialsort(vsq, 4)
16

julia> partialsort(vsq, 2:3)
2-element view(::Vector{Int64}, 2:3) with eltype Int64:
 4
 9
```

## 並べ替えアルゴリズム

`[3, 2, 4, 1]`を並べ替えるのは、人にとってもコンピューターにとっても簡単な課題です。

入力が_ずっと_大きくなったら、並べ替える最善の方法は何でしょうか？

ここで「最善」とは何かを定義せざるを得なくなります！

- 平均時間がもっとも短いこと？
- 最良の場合、それとも最悪の場合の時間？　あるいは90パーセンタイルの時間のような中間の基準？
- メモリ使用量が最小であること？
- 今の用途に「十分」な、近似的または部分的な並べ替え？

また、入力はどんなものでしょうか？
ほとんどランダムかもしれませんが、特別な場合として、すでに並べ替えられている配列、逆順に並んでいる配列、同じ要素がたくさんある配列などがあります。
こうした状況では、アルゴリズムによって動作が大きく変わります。

新しくよりよい並べ替えアルゴリズムを設計することは、知的に魅力的で（_ある種の性格の人には_）、商業的にも価値があります。_強力な組み合わせですね！_

そのため、この分野には膨大な文献があり、今も着実に増え続けています。

Juliaはほとんどの場合、妥当なデフォルトのアルゴリズムを選ぼうとしますが、必要であればプログラマーが[好みのアルゴリズムを指定][ref-algorithms]することもできます。

次のおもちゃのような例はばかげていますが、構文の説明にはなります。

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v, alg=InsertionSort)
4-element Vector{Int64}:
 1
 2
 3
 4
```
