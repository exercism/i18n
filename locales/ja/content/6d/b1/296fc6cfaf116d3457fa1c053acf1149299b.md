# はじめに

他の多くの言語と同じように、C++には_ポインター_があります。
_参照_と_ポインター_が似ていることはすでに知っていると思いますが、ポインターはコンピューターの内部動作にもう一歩近づいたものだと考えてください。
_ポインター_は、オブジェクトのアドレスを保持する変数です。
オブジェクトを直接操作するために使われ、C++で動的メモリの割り当てや効率的なデータ操作を可能にします。

_ポインター_に初めて触れると、少し不思議に感じるかもしれませんが、慣れてしまえばとても簡単です。

C++にとって欠かせない要素なので、時間をかけてしっかり理解しましょう。
この概念で扱う最小限のものは、_ダムポインター_や_生ポインター_とも呼ばれます。
モダンC++には_スマートポインター_もありますが、基本の型はまったく賢くなく、すべての作業を手動でこなす必要があります。

詳細に入る前に、まずは_ポインター_の用途を理解しておく価値があります。
_ポインター_は、オブジェクトのアドレスをプログラムの他の部分と共有する方法です。これには大きく2つの理由があり、とても便利です：

1. _参照_と同じように、ポインターはコピーを避け、プログラムのリソース消費を抑えるのに役立ちます。
1. _参照_と違って、ポインターは別のオブジェクトに再代入できます。
1. またポインターはヌル値を指すことができ、現在どのオブジェクトも指していないことを示せます。

## 一般的な構文

C++でポインターを宣言するときは、ポインターが指すデータ型を指定し、その後にアスタリスク（`*`）とポインターの名前を書きます。
ポインターは宣言しただけでは自動的に初期化されません。
明示的に代入しない限り、ポインターは通常は不定の値を持ち、これはよく「ゴミアドレス」と呼ばれます。
一部のコンパイラーではポインターが`nullptr`に初期化されることもありますが、すべてのコンパイラーで保証されている動作ではないため、それに頼らないことが大切です。
思わぬ問題を避けるため、生ポインターは明示的に初期化し、使う前にヌルでないことを確認するのがよい習慣です。

```cpp
int* ptr{nullptr}; // Declares a pointer and makes sure it is not invalid
```

変数のアドレスをポインターに代入するには、アドレス演算子（`&`）を使います。
ポインターの参照外しは、_間接演算子_（`*`）を使って行います。

```cpp
std::string opponent{"Solomon Lane"};
// 'ethan' points to the address of the string opponent
std::string* ethan{&opponent};
// Instead of ethan's, the opponent's name address is given to the passPort
std::string passportName{*ethan};
```

注意：_参照_は単なるエイリアスのようにそのまま使えましたが、参照外しは明示的に行う必要があります。

## ポインター演算

_ポインター演算_を使うと、ポインターに対して算術演算を行えます。これは配列を扱うときに特に便利です。
ポインターに整数を足すと、そのポインターは別の要素を指すようになります。

```cpp
// Stargate Coordinate Code
int gateCode[] = {462, 753, 218, 611, 977};
// 'ptr' points to the first element of 'gateCode'
int* ptr{&gateCode[0]};
// Accesses the third Stargate address through pointer arithmetic
int dialedAddress{*(ptr + 2)};
// Chevron encoded! Dialing Stargate address:
openStarGate(dialedAddress);
```

~~~~exercism/caution
C++のポインター演算は、慎重に扱わないと簡単に__未定義動作__を引き起こします。
未定義動作は、予期しないプログラムの動作、クラッシュ、さらにはセキュリティ上の脆弱性という形で現れることがあります。
未定義動作の結果として悪名高い例が、1996年の[アリアン5ロケットの爆発][ariane-flight-v88]です。これは、64ビットの浮動小数点数を16ビットの符号付き整数に変換したことでソフトウェア例外が発生し、壊滅的な失敗につながりました。

[ariane-flight-v88]: https://en.wikipedia.org/wiki/Ariane_flight_V88

## メンバー変数へのアクセス

C++では、`->`演算子を使って、オブジェクトへのポインターを経由してそのメンバーにアクセスします。
これは、ポインターが指すオブジェクトのメンバーへのアクセスを簡略化する省略記法です。
たとえば、`ptr`がメンバー変数`x`を持つオブジェクトへのポインターである場合、`(*ptr).x`を使う代わりに、`ptr->x`を直接使えます。
この演算子は、オブジェクトへのポインターを扱うときのコードの読みやすさを高め、記述を簡潔にします。

ここで簡単な例を見てみましょう。メンバー変数`superpower`を持つ_構造体_`Superhero`を使います。
main関数は、`Superhero`オブジェクトへのポインター`dianaPrince`を作成します（ワンダーウーマンを表しています）。
`->`演算子を使ってメンバー変数`superpower`にアクセスし、ワンダーウーマンの象徴である"Lasso of Truth"を表しています。

```cpp
struct Superhero {
    std::string superpower;
};
Superhero wonder_woman{};
Superhero* dianaPrince = &wonder_woman;
dianaPrince->superpower = "Lasso of Truth";
// Using the -> operator to access member variable superpower:
std::cout << "Wonder Woman, possesses the mighty " << dianaPrince->superpower;
// Memory cleanup:
delete dianaPrince;
```

## ポインターと参照の違い

ポインターと参照はどちらも、オブジェクトへの間接的なアクセスを可能にしますが、できることと安全性の面で違いがあります。
ポインターは、指す対象のオブジェクトを変更できる柔軟性があり、ヌルを代入することもできます。
ただし、この柔軟性には、ヌルポインターの参照外しやダングリングポインターの生成といったリスクが伴います。
一方、参照はヌルになることがなく、生成時に必ず有効なオブジェクトに束縛されるため、こうしたリスクを避けられます。
参照のほうが安全なので、ポインターが提供する追加の機能が必要な場合を除いて、ポインターより参照を選ぶべきです。
