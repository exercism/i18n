# はじめに

このシラバスの時点では、Rが命令型言語としてよく使われ、ますます関数型言語として（特に[`purrr`][ref-purrr]や[`dplyr`][ref-dplyr]ライブラリとともに）使われるのを見てきたはずです。

ここでRが主にオブジェクト指向であると言うと、懐疑的な反応を招くかもしれません。

奇妙なことに、これは本当です。
内部的には、Rはクラス、継承、ポリモーフィズム、そしてオブジェクト指向プログラマーに典型的な考え方を使って実装されています。

しかし、JavaやRuby（明示的にオブジェクト指向）あるいはPython（ある意味では半ば暗黙のオブジェクト指向）に慣れている人なら、Rのアプローチは…_なじみがない_と感じるでしょう。

まず、複数のクラス設計があります。一般的に使われるものがおそらく3つ（S3、S4、R6）あり、そのほかにも主に理論上の関心によるさまざまなものがあります。

詳細な議論は[Advanced R, 2e][book-advanced-r]の第12章から第16章にあります。
この2019年の本は、主にRの内部を理解し保守したい人を対象としているため、オブジェクト指向は必須です。

よりエンドユーザー向けの教科書はさまざまです。

- The Art of R Programming（2011年、紙媒体のみ）には、当時重要だったS3と（より簡単に）S4を扱うオブジェクト指向の章があります。_「S3クラスはかなり寄せ集めの構造をしている」_というコメントは、今でも驚くほど当てはまります。
- R in Action（第3版、2022年）では、オブジェクト指向は終盤の「上級プログラミング」の章で3ページだけ扱われています。
- [R for Data Science, 2e][book-r-data-sci]（2023年、紙媒体版は548ページ）では、オブジェクト指向についてまったく触れられていません。

この概念では、最も単純で、最も一般的で、Exercismタイプの問題に最も関連するS3クラスに焦点を当てます。
Rトラックの練習用の演習のなかには、S3クラスの作成を必須とするものもあれば、任意だが控えめに推奨するものもあります。

## S3クラス

これらは古くからあります。S3という名前は、S言語（Rの商業的な前身）のバージョン3で導入されたことを意味するだけです。

S3クラスも非常に単純です。通常は、少なくとも1つの追加属性を持つ[リスト][concept-lists]です。

[Advanced R][book-s3]からの引用です。_「S3は非公式で場当たり的ですが、そのミニマリズムにはある種のエレガンスがあります。どの部分を取り除いても、まだ有用なオブジェクト指向システムとして成り立つことはできません。」_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

つまり、[`class(obj)`][ref-class]に代入すると、`obj`に属性が1つ追加されるだけです。この場合は、`pt2d`を`point2d`クラスのインスタンスとして識別します。

作成手順は[`structure()`][ref-structure]と組み合わせることもできます。

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

結果として得られるインスタンスは概念上同一ですが、Rがそれを確認する方法はまだ実装されていません。

### 総称メソッド

他の言語のオブジェクト指向に慣れている人なら、_「クラスは何かをするべきではないのでしょうか？」_と不思議に思うかもしれません。

`point2d`インスタンスで利用できるメソッドを確認すると、（基になる`list`とは対照的に）今のところ何もないことがわかります。

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

ほとんどのオブジェクト指向言語では、メソッドはクラス定義の内部で定義されます。
少数の言語（特にRuby）では、後からクラスメソッドを追加したり変更したりできます。

S3クラスは大きく異なります。
クラスにメソッドを追加するのではなく、総称メソッドにクラスを追加します。

Rコンソールで対話的に作業する人は、総称メソッドをいつも使っていますが、たいていはどのように実装されているか考えていません。

非常によくある例は`print()`です。ただし、関数名を入力することはほとんどありません。
コンソールプロンプトで値`x`を単独で入力するのは、`print(x)`の糖衣構文にすぎません。

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

すでに`pt2d`を表示できます。
`print()`は`point2d`クラスについて何も知りませんが、さまざまなオブジェクトを扱うための常識的なデフォルトを備えています。

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

これはかなり冗長なので、点を簡潔に整形表示する方法が欲しくなるかもしれません。

簡単です。`print.point2d()`という関数を追加するだけです。
名前は`methodname.classname`の形式である必要があります。そうすることで、ディスパッチャーが何を探すべきかわかります。

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

次に、新しい総称メソッドを作りたいとします。たとえば、`y`座標の符号を反転する`flipvert()`です。

これも簡単です。

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

これによりディスパッチャーが作成されます。ここで`x`はS3クラスを持つオブジェクトで、`...`はメソッド定義が必要とする追加の引数（[関数の概念][concept-functions]で説明されている「ドット引数」）を処理します。

その後、`point2d`用のメソッドを定義して使うことができます。

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

これでRは、点を反転する方法と結果を表示する方法を理解しました。

これを拡張して、3Dや極座標などのクラスを作成し、それぞれにメソッドを定義することもできます。

エンドユーザーから見ると、`flipvert(x, ...)`だけがあり、Rが入力クラスを判別して適切な基盤実装を使うことを信頼できます。

~~~~exercism/caution
`verb.class`形式の関数名は、ユーザーにもRパーサーにもS3メソッドのように見えます。
ほかの文脈で似た命名を使うのは避けてください。

確かに、base Rはときどきこのルールに違反しています。
これは（S3よりもさらに古い関数のための）不幸な歴史的経緯と見なすべきであり、後方互換性のために維持しなければなりません。
~~~~

### 継承

オブジェクト指向の愛好家は、継承、サブクラス化、ミックスインなどについて、教科書の章をいくつも長々と書けます。

Rでは、`class`属性に複数の名前を指定できるだけです。つまり、単一の文字列ではなく、より長い文字列のベクトルです。

例を無理に広げて破綻させる恐れがありますが、総称的な`point`クラスを作り、それを`point2d`、`point3d`などにサブクラス化したいとします。

その場合、`point2d`の定義では単に`class = c("point2d", "point")`を使います。具体的なクラスと親クラス（複数の場合もあります）です。

すると、`print()`などの総称メソッドは、`print.point2d()`、`print.point()`、そして（おそらく）`print.default()`を順に検索し、ディスパッチャーが見つけた最初の実装を使います。

### 安全性

多くのオブジェクト指向言語（Java、C#など）では、クラス内のデータのカプセル化を利用して、慎重なコンパイル時のチェックを行い、型安全性を強制します。

S3では、意味が通らなくても、ほとんど好きなことができる点に注意してください（エラーメッセージが出るとしても、後になってからです）。

["Advanced R"][book-s3]（第2版、13.3節）からの引用です。

> _ほかのオブジェクト指向言語を使ったことがあると、これは気持ち悪く感じるかもしれませんが、実際にはこの柔軟性が問題を引き起こすことはほとんどありません。Rは自分で自分の足を撃つのを止めてはくれませんが、銃口を足先に向けて引き金を引かなければ、問題は起きません。_

まあ、_いいでしょう？_
Rは、探索的なデータサイエンスや統計、特にインタラクティブに作業するときに優れています。
誰も、高度にセキュアな企業金融システムを書くためにRを使うべきだと言っているわけではありません！
