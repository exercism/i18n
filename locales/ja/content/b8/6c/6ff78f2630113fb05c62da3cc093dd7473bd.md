# 概要

多くのプログラムでは、現実世界の出来事をシミュレーションするために（見かけ上の）ランダムな値が必要になります。

よくある身近な例を挙げます。

- コイン投げ：`"H"`か`"T"`のいずれかになるランダムな値。
- サイコロを振ること：1から6までのランダムな整数。
- トランプの山をシャッフルすること：カードのリストをランダムに並べ替えたもの。

コンピューターで真にランダムな値を生成するのは[驚くほど難しい技術的課題][web-truly-random]なので、こうした結果は「疑似ランダム」と呼ばれることがあります。

***重要***：この概念では、暗号学的に安全な乱数を扱い*ません*。これははるかに難しい課題です。

ただし、Rは統計パッケージから派生した言語で、シミュレーションによく使われるため、ランダムな値を生成する方法が豊富に用意されています。
その結果は、モデリングやシミュレーション、ゲームなど、ほとんどの用途には十分な品質です。

## [復元抽出と非復元抽出][yt-sampling-with-replacement]

3つの赤い玉と4つの緑の玉が入った袋から、ランダムに1つの玉を取り出すところを想像してみましょう。
2つ目の玉を取り出すには、2通りの方法があります。

1. 取り出した玉を袋に戻し、よく振ってからもう1つ取り出す。玉の数は元と同じ（7つ）で、*赤と緑の比率も変わりません*。
2. 取り出した玉をテーブルに置いてから、2つ目を取り出す。袋の中の玉は6つだけになり、*赤と緑の比率は最初に取り出した玉の色によって変わります*。

シナリオ1は復元抽出、シナリオ2は非復元抽出で、*結果は異なります*。

## `sample`による離散値

限られた数の離散値から選ぶには、[`sample()`][ref-sample]を復元抽出でも非復元抽出でも使えます。
これは整数や文字列などに便利です。

```R
sample(1:10, 5) # no repeats by default
#> [1] 8 3 4 2 6

sample(1:10, 5, replace = TRUE) # repeats are OK
#> [1] 10 10  7 10  9

languages <- c("Fortran", "R", "Python", "Julia")
sample(languages, 1)
#> [1] "Python"

sample(c("H", "T"), 5, replace = TRUE) # coin flips
#> [1] "T" "T" "H" "H" "H"

sample(c(TRUE, FALSE), 5, replace = TRUE) # alternative coin flips
#> [1] FALSE  TRUE FALSE  TRUE  TRUE
```

サンプリングはデータパイプラインによく合います。
例えば、ランダムな英数字の文字列を生成するには、次のようにします。

```R
library(stringr)

c(letters, LETTERS, 0:9) |> sample(50) |> str_flatten()
#> [1] "5tX71jhbM9zUmKrpENBQyGYaZdJPVAx06leSF2s8gcfw3OviIH"
```

また、サンプリングはベクトルや範囲に限られません。
別の概念で見るように、[リスト][concept-lists]、[行列][concept-matrices-arrays]、[データフレーム][concept-dataframes]もすべて有効な入力です。
*まさにRに期待するとおりの挙動です*。

## シャッフル

他の多くの言語には、シーケンスをシャッフルする専用の関数があります。たとえば、Pythonの`random.shuffle()`、Juliaの`shuffle()`、Matlabの`randperm()`などです。

Rにはシャッフル関数がありません。
*なぜでしょうか？*

これを理解するには、[`sample`][ref-sample]関数をもう一度見てみましょう。

完全な形は`sample(x, size, replace = FALSE, prob = NULL)`で、`x`は（通常）サンプリング元のシーケンス、`size`は選ぶ要素の数です。

`replace`についてはすでに説明しました。デフォルトは非復元抽出です。
今は`prob`は無視してください。これは`x`の各要素に異なる重みを付けられるようにするものです。

`size`を省略して`x`だけを渡すと、どうなるでしょうか？

```R
x <- letters[1:6]
x
#> [1] "a" "b" "c" "d" "e" "f"
sample(x)
#> [1] "e" "a" "f" "b" "c" "d"
```

典型的なRのスタイルで、パターンは「ベクトルを入れてベクトルを出す」で、`size`のデフォルトは`length(x)`です。

Rは主に統計学者によって、統計学者のために書かれています。「`x`のすべての要素を非復元抽出でサンプリングする」とは、「`x`をシャッフルする」をより技術的に言い換えただけだと、彼らは理解しているのです。

*だからこそ*、`shuffle`関数はありません。`sample`がすでに必要なことを正確に行ってくれるからです！

## 分布を扱う

ここまでの例では、すべての結果が同じ確率で起こる場合を説明しました。
たとえば、`sample(1:100)`は1から100までのどの整数も同じ確率で返します。

これは[`uniform`][web-uniform]分布と呼ばれます。

現実世界の多くの状況は、これよりはるかに複雑です。
そのため、統計学者たちは「現実世界」の結果を数学的に記述するために、多種多様な[`distributions`][wiki-probability-distribution]を生み出しました。

ベースRは、聞いたこともないほど多くの分布をサポートしており、その他の分布はオープンソースパッケージで利用できます。

このドキュメントの残りでは、最も一般的な分布のいくつかだけを説明します。

## 浮動小数点数

### 一様分布

浮動小数点数の[等確率の分布][wiki-uniform]には、[`runif()`][ref-runif]を使います（「**r**andom-**unif**orm」に注目してください。そして、「run if」と読んでしまう自然な、しかし*間違った*傾向に抗いましょう）。
`min`と`max`はどちらも指定できますが、デフォルトはそれぞれ0と1です。

```R
runif(5)  # generate 5 values
#> [1] 0.3038506 0.3527959 0.3319309 0.4846354 0.4386279

# generate 5 non-negative values <= 100.0
runif(5, max = 100)
#> [1] 79.70762 51.62232 52.85281 71.08571 63.94380
```

### 正規分布／ガウス分布

「釣り鐘型」の曲線とも呼ばれ、測定値のばらつきを表す非常によく使われる方法です。

たとえば、勤務先の工場が、どれも同じはずのボルトを10,000本購入したとします。
そのボルトを扱えるように工場のロボットを設定したいと考え、100本をサンプルとして重さを量ったところ、平均（[`mean`][ref-mean]）の重さが4.731gでした。
これは、ボルトすべてが正確に4.731gであることを意味する可能性は極めて低いです。
おそらく、値は4.627から4.794gの範囲にありながら、4.731gの周辺に集まっていることがわかるでしょう。

これが[`normal distribution`][wiki-normal-distribution]（「ガウス分布」とも呼ばれ、数学者カール・フリードリヒ・ガウスに由来します）で、確率は平均でピークになり、両側に対称的に裾を引きます（だから「釣り鐘型」なのです）。

これをソフトウェアでシミュレーションするには、曲線の広がりを指定する方法が必要です（*一般に、高価なボルトは安価なボルトよりも平均の周辺に密集します*）。
慣例として、これは[`standard deviation`][wiki-standard-deviation]で行います。値が小さいと鋭く狭い曲線になり、大きいと低く広い曲線になります。

数学者はギリシャ文字が大好きなので、平均を表す`μ`（「ミュー」）や、標準偏差（または`sd`）を表す`σ`（「シグマ」）をよく目にします。
したがって、「95%の値がμの2σ以内にある」とか「ヒッグス粒子が5シグマの信頼度で検出された」といった記述を目にしたら、それは標準偏差に関係する話です。

<!-- これについては[`Statistics`][statistics]の概念で詳しく説明する予定です。 -->

この分布に従うランダムな値を生成するために、Rには[`rnorm()`][ref-rnorm]関数があります。

「random normal」の略で、デフォルトは`mean`が0、`sd`が1です。

```R
rnorm(5)
#> [1]  0.36965357  0.07489948 -0.83827224 -0.83126506 -0.59895825

# Simulating our bolts example
rnorm(5, mean = 4.731, sd = 0.2)
#> [1] 4.564521 4.613237 4.419512 4.772196 4.839102
```

数値を見ただけでは、生の出力が一様分布よりも平均の近くに集まっていることを見て取るのは難しいです。
疑わしい場合は、1000個以上生成してプロットすると、よりはっきりわかります。
ローカルにRStudio（または同様のもの）をインストールしていない学習者は、[rdrr.io][web-rdrr]や[WebR ggplot2 Playground][web-ggplot]のようなオンラインR実行環境を使えます。

`hist(rnorm(10000), breaks = 40)`というコードを実行すると、基本的なパターンがわかりますが、最も美しい表示ではありません。
乱数はビンに分けられ、縦軸は各ビンに入った結果の数です。

~~~~exercism/advanced

## 離散分布

### 二項分布

コインを（*イカサマなしで*）投げると、表と裏が出る確率は同じです。どちらも確率は`p = 0.5`です。

コインを20回投げたら、表は何回出るでしょうか？
0回のこともあれば20回のこともありますが、統計の訓練を受けていない人でも「*だいたい10回*」と推測するでしょう。

1回のコイン投げで表が0回または1回になる確率の比は`1:1`です。

2回のコイン投げでは、表が0回、1回、2回の確率の比は`1:2:1`、3回では`1:3:3:1`です。

このような比は[「二項係数」][wiki-binom-coeff]と呼ばれます。
これらは[パスカルの三角形][wiki-pascal-triangle]を形づくり、Rを含む多くのExercismのトラックには、それに基づく[演習][practice-pascal]があります。

代わりに特定の結果の確率を求めたい場合は、Rに[`dbinom()`][ref-rbinom]関数があります（これは[確率密度][wiki-pdf]を計算します）。
20回のコイン投げで表が10回出る確率はほぼ18%です。

```R
# Probability of exactly 10 heads in 20 flips, fair coin
dbinom(10, size = 20, prob = 0.5)
#> [1] 0.1761971
```

イカサマも可能で、表の出る確率を`p = 0.6`に上げると、表が10回出る確率は*下がります*。

```R
# Probability of exactly 10 heads in 20 flips, biased coin
dbinom(10, size = 20, prob = 0.6)
#> [1] 0.1171416
```

この場合、20回のコイン投げで表が10回より多く出る可能性が高くなります。
明らかに、すべての起こりうる結果、つまり[二項分布][wiki-binomial]に注目する必要があります。

Rには、二項分布に従うランダムな値を生成する[`rbinom()`][ref-rbinom]関数があります。
返す値の個数`n`、試行回数`size`（コイン投げの回数など）、1回の事象の確率`prob`（1回のコイン投げで表が出る確率など）を指定します。

コイン投げをシミュレーションするには、正規分布のときと同様に、グラフ出力を表示できる環境でこのコードを実行します。

```R
# fair coin
hist(rbinom(n = 10000, size = 20, prob = 0.5))

# biased coin
hist(rbinom(n = 10000, size = 20, prob = 0.6))
```

得られるグラフから、表の最も出やすい回数がそれぞれ「約10回」と「約12回」であることがわかります。

20回のコイン投げでは、結果は明らかに離散的で、ヒストグラムには大きな段差がありますが、「釣り鐘型」にいくらか近づきます。

フェアなコインを使って結果に対称性を持たせ、何百万回ものコイン投げをシミュレーションすれば、二項分布は（*連続的な*）正規分布のますます良い近似になります。

### ポアソン分布

直径1mより大きい隕石は、毎年どれくらい地球に衝突するでしょうか？

地球上のどこにでも、自然のバックグラウンド放射線が（低いながら）存在します。
[ガイガーカウンター][wiki-geiger]の電源を入れたとき、放射線の粒子を検出して1秒間に何回のクリック音が聞こえるでしょうか？

これらの例に共通する特徴は次のとおりです。

- 事象は互いに*独立*しています。
- ある区間で事象が起こる確率は一定です。
- 離散的な事象を数えています。
- カウントに*理論上の*上限はありません（ただし、測定には実際上の制約があるかもしれません）。

ある区間で0回、1回、2回…の事象が起こる確率は、[ポアソン分布][wiki-poisson]を形づくります。

ポアソン分布の鍵となるパラメータは、選んだ区間での事象の[平均][ref-mean]（平均値）の回数で、通常はギリシャ文字のλ（「ラムダ」）で表されます。

直径1メートル以上の、地球に衝突する隕石の頻度は、文献では「数か月ごと」と記述されています。

例として`lambda = 4`とし、[`rpois()`][ref-rpois]で分布がどのようになるか見てみましょう。

```R
hist(rpois(n = 10000, lambda = 4))
```

今度のヒストグラムは大きく非対称で、衝突回数2にピークがあり、10以上というゼロでないカウントを示す長い裾を引いています。

## シード

ここまで説明したすべてのランダム関数は、実行するたびに異なる結果を返すことを目指しています。
結局のところ、それらは*ランダム*なのです！

この挙動は、毎回異なる[乱数シード][wiki-seed]を生成することに依存しています。

デバッグの目的では、[`set.seed(n)`][ref-set-seed]関数を使うと役立つことがあります。ここで`n`は選んだ整数です。
毎回同じシードを設定すると、コードは実行するたびに同じランダム値のセットを返すようになります。

```R
sample(1:5) #> [1] 5 1 2 4 3
sample(1:5) #> [1] 2 5 4 1 3
sample(1:5) #> [1] 4 2 5 1 3

set.seed(100); sample(1:5) #> [1] 2 3 5 4 1
set.seed(100); sample(1:5) #> [1] 2 3 5 4 1
set.seed(100); sample(1:5) #> [1] 2 3 5 4 1
```

上級者向けに、`set.seed()`では使用するRNG（*乱数生成器*）の種類も指定できます。

どうやらデフォルトは`"Mersenne-Twister"`のようです。変更を試みる前に、それが何を意味するか十分に理解しておいてください。
この概念の著者たちは、RNGについてこれ以上の助言は持ち合わせていません。
