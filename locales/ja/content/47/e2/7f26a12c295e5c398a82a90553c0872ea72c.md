# はじめに

C言語では、**構造体**とは、異なるフィールドから成る複合型です。各フィールドはそれぞれ独自の型とサイズを持ちます。

たとえば、次のコードは、4バイトの整数が2つ、8バイトの整数が1つ、合計3つの整数から成る型を定義します。

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

構造体は、ほかの構造体を含むこともできます。

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

構造体のフィールドの1つが配列である場合、その配列に割り当てられたすべてのバイトは構造体の一部です。しかし、フィールドが配列へのポインタにすぎない場合、その配列は別の場所に格納しなければなりません。

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## アラインメント

型の**アラインメント**とは、そのアドレスに対する要件を表す、負でない2のべき乗（1、2、4、8、…）です。その型のすべてのオブジェクトは、アラインメントの倍数となるアドレスに配置されなければなりません。

プリミティブ型では、アラインメントは通常そのサイズと同じです。たとえば、`int32_t`のアラインメントは通常4バイトです。つまり、`int32_t`は4バイトの境界に割り当てられなければなりません。

一方、構造体のアラインメントは、そのフィールドの中で最大のアラインメントです。たとえば、上で定義した`struct example`のアラインメントは8バイトになります。これは`uint64_t`のアラインメントだからです。

構造体のあるフィールドのアラインメントが、構造体のアラインメントより小さい場合、そのフィールドの後ろにパディングバイトが挿入されることがあります。これにより、後続のフィールドと構造体全体がアラインメントの要件を満たすようになります。実際には、これらのパディングバイトは構造体のサイズには寄与しますが、構造体の値には使われないということです。

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

上で定義した構造体では、フィールド'one_byte'のアラインメントは1で、どのアドレスにも配置できます。フィールド'four_byte'のアラインメントは4なので、構造体内のフィールドも4バイトの境界を守らなければなりません。つまり、構造体内の任意の2つのフィールドの間には、4の倍数のバイト数がなければなりません。'one_byte'は1バイトしか占めないので、この境界を守るために、その後に3バイトのパディングが挿入されます。

隣り合うフィールドは、必要なパディングバイトの数を最小限に抑えるため、可能な限りまとめられます。

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

このまとめ方は、各フィールドのアラインメントも守らなければなりません。

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

つまり、構造体内のフィールドの順序を変えると、サイズが変わることがあります。

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

配列のアラインメントは、その要素の型のアラインメントと同じであることに注意してください。

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

配列の要素は、配列の一部でない場合と同じようにまとめることができます。

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

アセンブリで構造体にアクセスするときは、考えられるパディングバイトをすべて考慮に入れることが重要です。

## 呼び出し規約

一般に、値が関数に渡され、また関数から返されるときは、当然予想される方法で扱われます。

- メモリアドレスや列挙型を含む整数値は、汎用レジスタ（GPR）で渡されます。
- 浮動小数点値は`xmm`レジスタで渡されます。

ただし、構造体は特別なケースです。経験則として、構造体内のすべてのフィールドはメモリ上で隣接した領域を占め、可能な限り1つのレジスタにまとめて配置されます。

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

構造体に整数値のフィールドと浮動小数点値のフィールドの両方がある場合、構造体内の連続する8バイトごとに個別に分類します。

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

整数と浮動小数点値が同じ8バイト内にある場合、その型は整数とみなされ、8バイト全体（浮動小数点値を含む）がGPRに配置されます。

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
`cvtss2si`や`cvtsd2si`を使って浮動小数点から整数へ変換すると、元のバイトの並びが変わります。

`movd`（32ビット値の場合）と`movq`（64ビット値の場合）を使うと、ビット表現を変えずに、`xmm`レジスタから生のバイトをGPRへ移動できます。
~~~~

ただし、サイズが16バイトを超える構造体は、各8バイトの型に関係なく、通常はメモリに配置されます。

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

構造体を関数の引数として渡すときは、必要な数のレジスタが使われます。メモリに配置される場合は、代わりにスタックが使われます。

関数から返される構造体にも、同様の規則が当てはまります。通常、整数値であれば`rax`と`rdx`に、浮動小数点値であれば`xmm0`と`xmm1`に、まず返されます。ただし、メモリに配置される場合は、呼び出し側がそのための領域を確保し、このメモリ位置のアドレスを、関数への暗黙の最初の引数として（`rdi`で）渡さなければなりません。関数はその領域に構造体を格納し、そのアドレスを`rax`で返します。
