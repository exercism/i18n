# 説明

新聞工場の新しい品質管理責任者であるElenaは、製造室を監視する小さなソフトウェアを書いてほしいと頼んできました。

## 1. 独自のエラーを定義する

`ERROR:`パースワードを使って、エラータプルクラス`machine-error`を定義します。スロットは必要ありません。

```factor
machine-error   ! throws a fresh machine-error
```

## 2. 湿度をチェックする

`check-humidity`を定義します。これはスタックから湿度の測定値を取り出し、その値が厳密に`70`より大きいとき、文字列`"humidity too high"`を`throw`します。それ以外の場合は何も返しません。

```factor
50 check-humidity   ! returns nothing
80 check-humidity   ! throws "humidity too high"
```

## 3. 温度をチェックする

`check-temperature`を定義します。これは温度の測定値を取り出し、その値が厳密に`500`より大きいとき、文字列`"temperature too high"`を`throw`します。それ以外の場合は何も返しません。

```factor
400 check-temperature   ! returns nothing
600 check-temperature   ! throws "temperature too high"
```

## 4. 機械を監視する

`monitor`を定義し、スタックから湿度と温度を取り出して、両方のチェックを実行します。どちらかのチェックが`throw`したら、代わりに`monitor`が新しい`machine-error`を`throw`します。両方とも通れば、`monitor`は何も返しません。

```factor
50 400 monitor   ! returns nothing
80 400 monitor   ! throws a machine-error
50 600 monitor   ! throws a machine-error
```

## 5. 測定値のバッチを監視する

`monitor-batch`を定義し、`{ humidity temperature }`の測定値の配列を受け取って、そのうち何件が失敗するか（つまり、何件が`monitor`に`throw`させるか）を返します。

```factor
{ { 50 400 } { 80 400 } { 50 600 } { 60 200 } } monitor-batch .
! => 2
```
