# 概要

ハッシュセットは、内部でハッシュ化を行って[`sets`][sets]の[プロトコル][set-protocol]を実装しており、挿入・検索・削除を平均O(1)で行えます。その場で書き換えられるため、グラフ探索における*訪問済み集合*パターンに最適です。

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| word          | effect                                    |
|---------------|-------------------------------------------|
| `HS{ }`       | 空のハッシュセットリテラル（共有されるので、`clone`してください！） |
| `>hash-set`   | `( seq -- set )`、シーケンスから新しい集合を作る（重複は取り除かれる） |
| `adjoin`      | `( elt set -- )`、破壊的な挿入     |
| `in?`         | `( elt set -- ? )`、要素の判定           |
| `delete`      | `( elt set -- )`、破壊的な削除     |
| `cardinality` | `( set -- n )`、要素数       |
| `null?`       | `( set -- ? )`、集合が空のとき`t` |
| `members`     | `( set -- seq )`、シーケンスとして列挙  |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )`、`set`を`exemplar`のクラスに変換 |

すでにあるデータから集合を作るには、`>hash-set`を使えば、どんなシーケンスでも一度に変換でき、重複は取り除かれます。`{ 2 3 2 5 } >hash-set`とすると、`HS{ 2 3 5 }`が得られます。`adjoin`を繰り返して集合を育てるのに対する、まとめて処理する版です。

`in?`と`member?`（`sequences`のワード）の違いは、少し紛らわしいところです。どちらも要素が含まれるかを調べますが、`member?`はシーケンスを先頭から順に走査するのに対し、`in?`はその集合型のプロトコルメソッドに処理を委ねます。`HS{ }`の場合、それはハッシュによる検索です。「訪問済み」を保持するコンテナの要素が、片手で数えられる程度を超えたら、`in?`を使いましょう。

`null?`は、`cardinality`をすべて計算しなくても「この集合は空か？」を答えてくれます。「まだ処理するものは残っているか？」を判定する自然なガードです。作業リストを集合として持っているなら、`[ set null? ] [ … ] until`で空になるまで処理し尽くせます。

## ハッシュテーブルとの相性

「Xは訪問済みか？」を`HS{ }`で、「Xの隣接ノードはどれか？」を`H{ }`で持つと、自然に組み合わせられます。教科書どおりの深さ優先探索（DFS）は、次のようになります。

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

訪問済み集合は重複した処理を省き、スタックは次に調べる候補となるノードをつないでいきます（`push`/`pop`によるLIFO）。隣接ノードのマップ（ハッシュテーブル）がグラフを提供します。到達可能性を調べるだけなら訪問の順序は関係ないので、スタックとしてベクターを使うだけで十分です。同じ形の本格的な幅優先探索（BFS）では、ベクターを[`<dlist>`][dlist]に置き換えて、代わりに先頭から取り出します。
