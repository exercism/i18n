# 指示

あなたは沿岸貨物船でボースンを務めています。ビルジ、つまり船体で最も低い区画には廃水がたまります。そして毎シフト、ビルジ用の装備を開けて動かし、最後は片づけなければなりません。ポンプ作業の途中で何が起ころうと、装備は*必ず*元の収納状態に戻らなければなりません。

テストからは、新品のポンプを取得するための`<test-pump>`が与えられます。各ポンプには`opened>>`というスロットがあり、開いている間は`t`、処分が済むと`f`になります。

## 1. ビルジを排水する

`drain-bilge`を定義し、ポンプを1つ解放します。同じポンプに対して`drain-bilge`を2回呼び出しても問題ありません。そのあたりはフレームワークが処理してくれます。

```factor
<test-pump> dup drain-bilge opened>> .   ! => f
```

## 2. ポンプアウトのルーチン

`pump-out`を定義します。ポンプとクォーテーションを受け取り、クォーテーションが使えるようにポンプをスタックに積み、そのあとでポンプを解放します。*クォーテーションが例外を投げた場合でも*、必ず解放します。

```factor
<test-pump> [ drop ] pump-out   ! pump released
```

## 3. シフト全体のルーチン

`shift-routine`を定義します。2つのポンプとクォーテーションを受け取り、デストラクタースコープを開き、*両方*のポンプを無条件解放として登録してから、クォーテーションを呼び出します。クォーテーションが正常に終わっても例外を投げても、どちらのポンプも解放されます。

クォーテーションは、スタックに積まれた2つのポンプを入力として受け取ります。

```factor
<test-pump> <test-pump> [ 2drop ] shift-routine
! both pumps released
```

## 4. 危険なポンプアウト

ポンプを借りているだけ、ということもあります。何か問題が起きたときだけ処分したいのであり、そうでなければ次のシフトのために開けたままにしておく必要があります。`risky-pump-out`を定義します。ポンプとクォーテーションを受け取り、ポンプを**失敗時のみ**の解放として登録し、ポンプをスタックに積んだ状態でクォーテーションを呼び出します。

クォーテーションが成功すれば、ポンプは開いたままです。クォーテーションが例外を投げた場合は、ポンプが解放され、例外はそのまま伝わります。

```factor
<test-pump> [ drop ] risky-pump-out                ! stays open
<test-pump> [ drop "boom" throw ] risky-pump-out   ! pump released, throws
```

## 5. 自作の使い捨てリソース：バルブ

道具一式の仕上げに、まったく新しい使い捨てリソースである`valve`を加えましょう。タプルはあらかじめ宣言されています。

```factor
TUPLE: valve < disposable is-open ;
```

- `<valve> ( -- valve )`を定義して、`new-disposable`で新しいバルブを生成し、`is-open`を`t`に設定します。
- `M: valve dispose*`を実装して、`is-open`を`f`に切り替えます。

```factor
<valve> is-open>> .                ! => t
<valve> dup dispose is-open>> .    ! => f
```
