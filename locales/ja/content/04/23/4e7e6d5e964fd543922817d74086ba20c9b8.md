# 可変性

可変性は、Rustにおける個々の束縛が持つ性質です。束縛は、不変か可変のどちらかです。不変の束縛では値を変更できませんが、可変の束縛では変更できます。すべての束縛は、デフォルトで不変です。

## 束縛

束縛とは、ソースコードに書かれた変数名と、実行時に存在するメモリ上の領域とを結びつけるものです。厳密に言えば、束縛が存在するのはコンパイル時だけです。コンパイル前にはメモリは実際には確保されておらず、コンパイル後には、機械語は名前付きの変数ではなくメモリアドレスだけを扱います。

束縛は通常、`let`キーワードで作成します。また、関数の引数やその他の特定の状況でも束縛は作成されます。

束縛にはさまざまな性質がありますが、その中で最も重要なのが可変性です。可変の束縛とは、束縛されているメモリの値を変更することが許されている束縛のことです。Rustは、プログラムの正しさを保つために、各束縛の可変性を厳密に追跡して強制します。不変であるべき束縛を誤って変更しようとするプログラムを拒否するのです。

## 可変性

実際には、可変性は多くの場合シンプルです。束縛の定義で`mut`キーワードを使えば、値を変更できるようになります。

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### 可変から不変への降格

束縛はいつでも、可変から不変へ降格できます。この操作は透過的です。

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### 不変から可変への昇格

一般に、所有権が移動するときはいつでも、値を不変から可変へ昇格できます。

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

`(1)`の時点で、文字列の所有権が`x`から`y`へ移動するため、値を可変に昇格できます。

### 関数の引数における可変性

関数の引数を可変にする方法は2つあります。1つ目はより一般的な方法で、Cの参照渡しに似ています。

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

この例では、可変性が3か所で明示的に注釈されています。可変参照を機能させるには、この3つの可変性の宣言がすべて必要です。
`(2)`では、束縛`x`が可変として宣言されています。この束縛は、値の最上位の所有者です。
`(3)`では、その値が可変で借用され、`increment`関数に渡されます。
`(1)`では、対応する参照に対して、新しい可変の束縛`n`が作成されます。

引数の可変性には別のスタイルもあり、こちらはあまり一般的ではありませんが、それでもときに役立ちます。このスタイルでは、値は所有されますが、束縛は可変です。

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

この例では明示的な注釈が少なくて済みます。実際には、可変性の昇格が組み込まれた所有権の移動だからです。これが機能するのは、`i32`がデータを透過的にコピーする`Copy`型だからです。
`(1)`では、`increment_internally`が`n`という名前の可変で所有された`i32`を引数として受け取ると宣言しています。
`(2)`では、`x`を値`1`への不変の束縛として宣言しています。
`(3)`では、`x`がメモリ上の新しい場所にコピーされます。`x`は不変のままで、`n`は可変です。

もちろん、これらの形式を組み合わせて、可変参照への可変の束縛（`mut n: &mut i32`など）を作ることもできますが、実際に望まれることはほとんどありません。

### `let`を使わない可変性

Rustのいくつかの構文（`if let`、`match`など）でも束縛を作成できます。これらの束縛も可変にできます。

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

この例では、まず`v = Some(2)`、次に`v = None`が出力されます。

## シャドーイング

値を変換していくにあたって、複数の`let`で再宣言して同じ変数名を使い回すことができます。これはよく行われる書き方でもあり、シャドーイングと呼ばれます。

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

ただし、これは可変性の話ではありません。元の値は原則としてそのまま残っています。`Drop`を実装していない型であれば、コンパイラーは新しいメモリを確保する代わりに、既存のメモリの場所を書き換えることを選ぶ場合があります。ただし、`Drop`型の場合や、古い束縛が再び使われる場合には、決してそうはしません。

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
