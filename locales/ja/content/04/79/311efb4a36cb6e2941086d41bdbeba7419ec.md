# はじめに

## `error`インターフェース

Goでは、エラー処理は例外で行うのでは**ありません**。
そうではなく、エラーは、組み込みの`error`インターフェースを実装した型の、ごく普通の_値_です。
`error`インターフェースはごく最小限で、エラーメッセージを文字列として返す`Error()`メソッドを1つだけ持ちます。

```go
type error interface {
  Error() string
}
```

実行中にエラーが起こり、それが呼び出し元まで届く必要がある関数を定義するときは、戻り値の型の1つに`error`を含める必要があります。
関数が複数の戻り値を持つ場合、慣習として`error`は常に最後に置きます。

```go
func DoSomething() (int, error) {
  // ...
}
```

## シンプルなエラーの作成と返却

エラーインターフェースをいつも自分で実装する必要はありません。
シンプルなエラーを作るには、標準ライブラリの`errors`パッケージにある`errors.New()`関数を使えます。
渡す必要があるのは、エラーメッセージを文字列として1つだけです。`errors.New()`が、そのメッセージを含み`error`インターフェースを実装する値を作ってくれます。

関数がエラーを返す場合は、他の戻り値にはゼロ値を返すのが良い習慣です。

```go
func DoSomething() (SomeStruct, int, error) {
  // ...
  return SomeStruct{}, 0, errors.New("failed to calculate result")
}
```

~~~~exercism/caution
エラーがある場合に、すべての関数が他の戻り値にゼロ値を返すと決めつけてはいけません。
エラーが発生したときは、他の戻り値はどれも安全に使えないと考えるのが最善です。
唯一の例外は、エラーの場合でも他の戻り値が意味を持つとドキュメントに明確に書かれている場合です。
~~~~

このようなシンプルなエラーを複数の場所で使いたい場合は、`errors.New`をその場で書くのではなく、エラー用の変数を宣言しましょう。
慣習として、変数の名前は`Err`か`err`で始めます（エクスポートされるかどうかで使い分けます）。
こうしたエラー変数は、よく_センチネルエラー_と呼ばれます。

```go
import "errors"

var ErrNotFound = errors.New("resource was not found")

func DoSomething() error {
  // ...
  return ErrNotFound
}
```

関数の実行中にエラーがなかったことを示すには、エラーに`nil`を返します。

```go
func Foo() (int, error) {
  return 10, nil
}
```

## エラーのチェック

エラーを返す関数を呼び出すときは、エラーの値を`err`という変数に格納するのが一般的です。
関数の実際の結果を使う前に、エラーがなかったことを確認する必要があります。

コードの「ハッピーパス」が入れ子になるのを避けるために、エラーのケースを先に処理しましょう。
`==`と`!=`を使ってエラーと`nil`を比較でき、`err`が`nil`でなければエラーがあったとわかります。

```go
func processUserFile() error {
	file, err := os.Open("./users.csv")
	if err != nil {
		return err
	}

	// do something with file
}
```

ほとんどの場合、上の例のように、エラーは関数のスタックを上へたどって返されます。
別の対処法としては、エラーをログに記録し、そのまま別の処理を続けることもできます。
エラーは返すかログに記録するかのどちらかにするのが良い習慣で、両方はしません。

Goのほとんどの関数は戻り値の1つにエラーを含むため、Goのコードでは`if err != nil`というパターンをあちこちで見かけ、また使うことになります。

## 独自のエラー型

エラーに、エラーメッセージの文字列だけでなくもっと多くの情報を含めたい場合は、独自のエラー型を作れます。
前述のとおり、Goでは`error`インターフェースを実装するもの（つまり`Error() string`メソッドを持つもの）はすべてエラーとして扱えます。

独自のエラー型を作るには、通常は構造体を使います。
慣習として、独自のエラー型の名前は`Error`で終わらせます。
また、`Error() string`メソッドはポインターレセプターで定義するのが最善です。その理由については、こちらの[Stackoverflowのコメント][stackoverflow-errors]を参照してください。
これはつまり、独自のエラーへのポインターを返す必要があるということです。そうでなければ`error`として扱われません。ポインタではない値は`Error() string`メソッドを持たないからです。

```go
type MyCustomError struct {
  message string
  details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.message, e.details)
}

func someFunction() error {
  // ...
  return &MyCustomError{
    message: "...",
    details: "...",
  }
}
```
