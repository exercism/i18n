# 無視

## jqの追加のコマンドラインオプション

テストでは、`jq`に追加のオプションが付いていることに気づくでしょう。

```sh
run jq -s -R -c -f minesweeper.jq << 'END_INPUT'
```

それぞれどんな意味があるのでしょうか？

- `-s`

  「slurp」モードです。
  入力をJSONオブジェクトのストリームとして扱う代わりに、
  入力全体をひとつの配列にまとめて取り込みます。

  ```sh
  $ seq 5 | jq -c '.'
  1
  2
  3
  4
  5
  $ seq 5 | jq -s -c '.'
  [1,2,3,4,5]
  ```

- `-R`

  文字列を引用符なしで「生の」まま出力する`-r`は、もう見たことがあるかもしれません。
  `-R`はその反対です。
  入力の各行が、それぞれ文字列として扱われます。

  2つの例を見てみましょう。

  ```sh
  $ seq 5 | jq -R -c .
  "1"
  "2"
  "3"
  "4"
  "5"

  $ echo 42 | jq '. * 2'      # input is a JSON number
  84
  $ echo 42 | jq -R '. * 2'   # input is a JSON string
  "4242"
  ```

この2つのオプションを組み合わせても、文字列の配列には_なりません_。
行末の改行も含めて、入力全体がひとつの文字列として渡されます。

```sh
$ seq 5 | jq -s -R -c .
"1\n2\n3\n4\n5\n"
```

これをどう扱うかも、この演習のやりがいの1つです。
