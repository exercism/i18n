# はじめに

アセンブリでは、あらゆるデータはバイトの並びです。
つまり、どんなデータも、その土台となるバイトの**配列**として見ることができます。

## 配列の要素にアクセスする

メモリ上の値を参照するには、その**実効アドレス**を計算する必要があります。
実効アドレスは、次のものを組み合わせた式です。

- _ベースアドレス_。たとえば、変数のラベルが示すアドレスです。
- _インデックスレジスタ_を1つ。`1`、`2`、`4`、`8`でスケーリングできます。
- 符号付き32ビットの_ディスプレースメント_。ベースアドレスに加算（または減算）する数値です。

このアドレスは_0始まり_であることに注意してください。そのため、オフセットを一切付けないベースアドレスは、変数の先頭のバイトを指します。
以前の概念でやってきたように、オフセットを付けずにラベルだけでメモリを参照すると、その先頭のバイトから始まる値が得られるのは、このためです。

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64は[リトルエンディアン][endianness]です。
つまり、複数バイトの値では、最下位のバイトが最も小さいメモリアドレスに格納されます。

したがって、複数バイトの値を1バイトずつ参照するときは、より上位のバイトにたどり着くために、ベースアドレスに正のオフセットを足す必要があります。

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

値のリストで宣言した初期化済みの変数は、それらの値の配列です。各要素のサイズは、指定したとおりになります。
ただし、配列の各要素がそれより大きなサイズでも、オフセットは常に**_バイト_**単位です。

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

アドレスはバイト単位なので、配列のどの要素でも、その1バイトを直接参照できることに注意してください。

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

同じ理由から、1つの命令で要素のサイズを超える範囲を参照することもできます。

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
アセンブリは、配列へのアクセスに境界チェックを行いません。
配列の末尾を超えたインデックスは、配列の外のメモリを読み書きします。
その結果、気づかないうちに誤った結果になったり、ほかのデータが壊れたり、参照したメモリがマップされていなければ実行時フォールトになったりします。
すべての実効アドレスを配列の範囲内に保つのは、プログラマーの責任です。
~~~~

## 初期化済みの配列のサイズを計算する

NASM（The Netwide Assembler。このトラックで使うアセンブラーです）には、メモリ上の現在位置を表す特別な記号（`$`）があります。
この記号を使うと、配列がメモリ上で占める合計サイズを簡単に計算できます。

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

`example`のすぐ後ろで使うと、`$`は配列の終端のメモリアドレスを表します。
つまり、`$ - example`は、そのアドレスとラベル`example`が指すアドレスとの差です。
これが、`example`が指す配列が占める合計サイズ（バイト単位）そのものです。

この値で`example_length`を定義すると、配列のサイズ（長さ）をバイト単位で保持する8バイトの変数ができます。

## `.bss`セクション

未初期化のデータは、**`.bss`セクション**で宣言します。
ほとんどのプラットフォームでは、プログラムの開始時にOSがこのデータを0で埋めます。

NASMでは、未初期化の変数は、名前、データサイズを表すディレクティブ、確保する要素数で構成されます。
これらはそれぞれ、スペースで区切ります。

主なディレクティブと、それに対応するデータサイズは次のとおりです。

| ディレクティブ | サイズ    |
| :-------: | :------ |
|   resb    | 1バイト  |
|   resw    | 2バイト |
|   resd    | 4バイト |
|   resq    | 8バイト |

たとえば、次のコードは`example`という名前の変数に`3`バイト分の未初期化領域を確保します。

```x86asm
section .bss
    example resb 3
```

そして、次のコードは`arr`という名前の変数に`10`×`8`バイト（つまり`80`バイト）の未初期化領域を確保します。

```x86asm
section .bss
    arr resq 10
```

`section .bss`の変数は可変です。つまり、読み書きできます。

未初期化のデータも、初期化済みのデータと同じように、実効アドレスを使って参照できます。
同様に、静的記憶域期間を持ち、同じソースファイル内のどの関数からもアクセスできます（`global`宣言されていれば、ほかのソースファイルからもアクセスできます）。

## `lea`命令で配列のアドレスを扱う

以前の概念で見たように、`lea`命令は実効メモリアドレスを計算します。
同じ意味論で、配列のどの要素のアドレスも計算できます。

相対アドレス指定では、より複雑なアドレスを組み立てる前に、変数のアドレスをレジスタに読み込む必要がよくあることに注意してください。

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea`の利点の1つは、アドレス計算の仕組みを使って値を計算し、そのアドレスのメモリには実際にはアクセスしないことです。
そのため、どのレジスタにもメモリアドレスが入っていないときでも、計算に使えて便利です。

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
