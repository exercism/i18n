# はじめに

## ループ

**ループ**とは、終了条件を満たすまで、繰り返し実行される可能性のある一連の命令のことです。

x86-64では、ループは通常、前のラベルへのジャンプで作ります。

```x86asm
example_loop:
    ...
    jmp example_loop
```

前のラベルへの無条件ジャンプは、常にそのラベルへ実行を移すことに注意してください。つまり、繰り返す範囲の外側へジャンプする命令が別にない限り、ループは永遠に繰り返されます。

たとえば、次のループは終わりません。

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

そして、次のループは、条件を満たすかどうかによって終わることもあります。

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### カウントループ

カウントループは、ほとんどいつも同じように終わります。カウンターを更新するか2つの値を比較する命令のすぐあとに、もう一度繰り返すかどうかを決める条件付きジャンプが続くのです。

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
上のコードでは、`sub rsi, 1`が結果`0`のときにすでに`zero flag (ZF)`を設定するので、`cmp rsi, 0`は必要ありません。

アセンブリで条件を判定する主な方法は`cmp`ですが、多くの命令がフラグを更新します。たとえば、多くの整数演算やビット演算の命令は、結果が`0`のときに`ZF`を、結果が負のとき（つまり最上位ビットが立っているとき）に`SF`を更新します。

各命令がどのフラグに影響するかは、[リファレンス][reference]で確認できます。

[reference]: https://www.felixcloutier.com/x86/
~~~~

上の例では、`rsi`は`0`より大きいと仮定していることに注意してください。もし`0`だったら、`sub rsi, 1`によって`rsi`は`-1`になり、符号なしではこれは非常に大きな数になります。ループがようやく終わるまでには、さらに`18,446,744,073,709,551,615`回繰り返すことになります。また、配列の長さが`0`なので、どのメモリアクセスも範囲外になります。

配列の長さが保証されていない場合は、よく使われる方法が2つあります。

1つ目は、終了条件をループの先頭に移し、最後に無条件ジャンプを置く方法です。

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

2つ目は、ループの先頭で、長さが0の配列かどうかを一度だけ確認する方法です。

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

この2つ目の方法は、ループ本体の分岐が少ないため、通常は1つ目より効率的です。これについては、今後の概念で詳しく学びます。

~~~~exercism/advanced
状況によっては、現代のCPUは2つの異なる命令を1つの操作にまとめることができます。この最適化は**マクロフュージョン**と呼ばれます。

`sub`や`add`のような多くの算術命令、そして`cmp`や`test`は、直後に続く条件付きジャンプとよく融合します。つまり、`cmp rax, rdx`のような命令の直後に条件付きジャンプが続く場合、CPUは通常それを1つの操作として扱えます。

マクロフュージョンはCPUに依存し、どの命令がどの条件付きジャンプと融合するかには多少の違いがあります。

参考になるのは、[The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]です。[Intel optimization reference manual][intel-opt]のセクション3.4.2.2（Optimizing for Macrofusion）にも、Intel CPUで融合できるペアが一覧になっています。

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
