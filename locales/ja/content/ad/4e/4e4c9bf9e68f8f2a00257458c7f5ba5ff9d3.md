# はじめに

## 列挙型

ここまでは、主に数値と文字列を扱ってきました。
現実世界をモデル化するには、変数がとりうる値を限られた数だけにしたいことがあります。
それぞれに名前の付いた、いくつかの異なる値だけを持つ専用の型が欲しくなるかもしれません。
たとえばスケートボードの工場では、デッキの素材をmaple、bamboo、plasticの3つだけから選ぶようにしたいでしょう。

整数を使ってこれらの値を表すこともできますが、素材として無効な値がシステムから渡されていないかを確認する追加のコードが必要になります。
こうした[_マジックナンバー_][magic numbers]の意味はソースコードを追いかけても分かりにくく、取り違えも起こりがちです。
`enumerations`を使うと、意図が伝わりやすいコードを書きやすくなり、意図しない比較のミスを防げます。

## 使用例

この種の列挙型を指す専門用語は`scoped enumeration`です。
次のコードは、`DeckMaterial`という`enumeration`を書く方法を示しています。
`enum class`というキーワードと、定義の最後にある`;`に注目してください。

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
では、スケートショップの価格計算の関数を見てみましょう。`enumeration`の中の`enumerator`を指定しているスコープ解決演算子（`::`）に注目してください。

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## スコープ

ホイールの素材を表す2つ目の`enumeration`があるとします。

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
ホイールもデッキも_plastic_で作ることができますが、この2つを混同することはありません。
これらは別の_型_です。`DeckMaterial`のplasticと`WheelMaterial`のplasticです。
それぞれの`enumeration`は、自身の`enumerators`を独自のスコープ、つまり独自の`namespace`の中に持ちます。
これが、`scoped enumerations`と呼ばれる理由です。

## スコープのない列挙型
`scoped`という名前があるなら`unscoped`な列挙型もあるのでは、と思うかもしれません。そのとおりです。
`Unscoped enumerations`は、すべてが同じグローバル名前空間を共有するため、あまり使われなくなってきています。
共有しているせいで、上の例の_plastic_のように同じ`enumerators`を持つ2つの`unscoped enumerations`を定義することはできません。

また、`unscoped enumerations`は暗黙的に整数に変換されます。
次の例を見ると、意外な結果が分かります。

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

`scoped enumerations`を整数に変換したいときは、`static_cast<int>`を使います。
