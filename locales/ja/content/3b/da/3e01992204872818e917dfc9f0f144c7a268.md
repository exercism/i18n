# コードの取り込み

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

`include`は、別のクラスのコードをこのクラスにコピーします。コンパイル時の操作で、実行時のコストも、実行時の関係もありません。取り込んだあと、2つのクラスはつながっていません。

## 節

```
   include CLASS  old_name -> new_name , old_name -> ;
```

それぞれの項目が、1つの機能の名前を変えます。新しい名前を書かない`-> ;`は、その機能を省きます。書かなかったものは、そのままの形で取り込まれます。

名前の変更は、*外側*から見えるものに適用されます。取り込まれたルーチン同士の呼び出しは、そのまま機能します。`describe`が`count`を呼び出していて、`count`の名前を`beats`に変えた場合、`describe`は`beats`を呼び出します。

## 複数を取り込む

```sather
   include WARM_UP;
   include COOL_DOWN;
```

これは認められています。他の言語が多重継承と呼ぶものを、Satherはこの方法で実現します。しかも、よくある厄介ごとは付いてきません。名前の衝突はコンパイルエラーになり、直し方は名前を変えるか、片方を省くかのどちらかだからです。覚えなければならない優先順位で解決されることは何もありません。

## private include

```sather
   private include WARM_UP;
```

そのクラス自身が使うためにコードを取り込みますが、外部には公開しません。実装は欲しいけれどインターフェースは要らない、というときに役立ちます。

## 2つを組み合わせる

クラスのグループでよく使われる形は、次のとおりです。

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

`< $ACT`は、そのクラスが何をできるかを示します。`include ACT_BASICS`は、そのやり方の一部を提供します。やり方について考えが変わっても、`<`は動きません。

## なぜこのようにするのか

抽象クラスにはコードがないので、うっかり継承してしまうことはありません。また、自分の足元で振る舞いが変わるスーパークラスというものもありません。再利用は、コンパイル時に、自分で名前を指定したクラスから取るコピーです。名前の変更はすべて書き留められます。

その代わり、再利用はクラスごとに明示的に求めなければなりません。これがトレードオフです。書く量は増えますが、暗黙のものは何もありません。
