# はじめに

Goのスライスは、他の言語のリストや配列に似ています。スライスは、特定の型（またはインターフェース）の要素を複数保持します。

Goのスライスは配列を基にしています。配列はサイズが固定です。一方、スライスはサイズが動的で、配列の要素を柔軟に見渡せるビューです。

スライスは`[]T`のように書きます。ここで`T`は、スライスの要素の型です。

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

0から始まるインデックスを指定して、角括弧の記法で要素を取得したり設定したりできます:

```go
withData[1] = 5
x := withData[1] // x is now 5
```

範囲を指定して要素を取り出すことで、既存のスライスから新しいスライスを作れます。ここでも角括弧の記法を使いますが、開始インデックス（その値を含む）と終了インデックス（その値を含まない）の両方を指定します。開始インデックスを指定しなければ、0が使われます。終了インデックスを指定しなければ、スライスの長さが使われます。

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

`append`関数を使って、スライスに要素を追加できます。次の例では、`a`スライスに`4`と`2`を追加しています。

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append`は常に新しいスライスを返します。すでにあるスライスに要素を追加したいだけのときは、上でそうしたように、最初の引数として渡したスライスの変数に代入し直すのが一般的です。

`append`は、2つのスライスをまとめるのにも使えます:

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## スライスのインデックス

スライスのインデックスを扱うときは、そのインデックスが実際に存在するかを確認するチェックで、必ず何らかの形で保護しましょう。そうしないと、アプリケーション全体がクラッシュします。

## 空のスライス

`nil`スライスは、デフォルトの空のスライスです。値が1つも入っていないスライスと比べても、デメリットはありません。`len`関数は`nil`スライスでも動作しますし、初期化しなくても要素を追加できます。新しくスライスを作る場合は、`s := []int{}`（空の、`nil`ではないスライス）よりも、`var s []int`（`nil`スライス）のほうがおすすめです。

## パフォーマンス

繰り返し処理で要素を追加していくスライスを作る場合、そのスライスが最終的にどのくらいのサイズになるかがわかっていれば、パフォーマンスを手軽に改善できるポイントがあります。鍵となるのは、メモリを確保する回数を最小限にすることです。メモリの確保はかなりコストがかかり、スライスが確保済みのメモリ領域を超えて大きくなると発生します。最も確実な方法は、`s := make([]int, 0, cap)`のようにしてスライスに容量`cap`を指定し、あとはいつもどおり`append`で要素を追加していくことです。こうすると、スライスの長さが0のまま、`cap`個分の要素のための領域がすぐに確保されます。実際には、`cap`には別のスライスの長さを指定することがよくあります: `s := make([]int, 0, len(otherSlice))`。

## `append`は純粋な関数ではありません

Goの`append`関数はパフォーマンスのために最適化されており、そのため入力のスライスのコピーを作りません。つまり、元のスライス（`append`の1番目の引数）が変更されることがあります。
