# はじめに

_「日付と時刻なんて、小さな子どもに教えるようなものだ。そんなに難しいはずがない」_

多くのプログラマーがその過ちを犯してきました。そして、その後に経験することは、彼らの健康と幸福に悪い影響を与えがちです。

日付と時刻を扱う、簡単ではないプログラミングに取り組むなら、少なくとも、起こりうる問題を理解し、軽減する備えをしておくべきです。

このドキュメントでは、Juliaが日付と時刻をどのように扱うかの概要を説明します。さらに詳しい情報については、[マニュアル][Dates]を参照する必要があります。説明がよりわかりやすいと感じる読者もいるでしょう[Wikibook][Wikibook]もあり、型階層の役立つ[図][type-hierarchy]も含まれています。

## `Dates`モジュール

基本的な機能のほとんどは`Dates`にあります。これはデフォルトのインストールに含まれているモジュールですが、標準ライブラリの一部ではありません。

モジュールを使うには、2つの方法があります。

1. `import Dates`を追加し、すべての関数呼び出しの前に`Dates.`を付けます。
2. `using Dates`を追加します。これでモジュール全体が現在の名前空間に読み込まれます（_一部の問題のある名前を除く_）。

```julia-repl
# option 1
julia> import Dates

julia> Dates.now()
2025-06-21T16:02:39.080

julia> now()  # wrong: need to include `Dates.` after an import
ERROR: UndefVarError: `now` not defined in `Main`


# option 2
julia> using Dates

julia> now()  # functions are now in the namespace
2025-06-21T16:03:04.161
```

`Dates`モジュールは大きく複雑ですが、主に4種類の機能を提供します。

- `Dates.Date`：日・月・年を含みますが、時刻は含みません。
- `Dates.Time`：時刻を含みますが、日付は含みません。
- `Dates.DateTime`：日付と時刻を組み合わせたものです。
- `Dates.Period`：時間や日付の間隔を扱います。

`DateTime`は通常、タイムゾーンの情報を含まないことに注意してください（Pythonではこれを「naive」なdatetimeと呼びます）。例外の1つは`now()`で、これはシステムクロックからローカル時刻を取得し、必要ならこれをUTCに変換できます。

おそらくもっともよくあるニーズは次のようなものでしょう。

- 適切な入力形式を解析して`Dates`型を構築する。
- `Dates`型から必要な数値や文字列の形式を取得する。
- `Date`、`Time`、`DateTime`の値にオフセットを適用する。
- 2つの値の間の間隔を計算する。
- 現在の日付（`today()`）や時刻（`now()`）を取得する。

~~~~exercism/note
視覚的な煩雑さを減らすため、このドキュメントの残りのサンプルコードのほとんどは`using Dates`を前提とし、関数呼び出しにモジュール名`Dates.`を付けないようにしています。
~~~~

### 日付と時刻の形式

日付と時刻の書き方には多くの種類があり、しばしば文化的に固有のものです。「7/6/23」のような数字だけの日付は曖昧で紛らわしく、多国籍企業に多くの高くつく間違いをもたらしてきました（_これは著者の苦い経験からの言葉です_）。

国際標準は`ISO 8601`で定義されており、主に2つの利点があります。

- 解析が速く、曖昧さがありません。
- 日時を通常のテキストとして扱えるので、辞書順に並べ替えるのが簡単です。

先ほどの例で、`Date.now()`が`2025-06-21T16:03:04.161`を返すのを見ました。

これはさまざまな部分から組み立てられています。

- `YYYY-MM-DD`：日付の部分。
- `hh:mm:ss`：時刻の部分。
- 任意で、小数点以下のミリ秒（またはさらに小さい単位）。

他の文字列形式については、後のセクションで説明します。

## 日付

`Dates.Date`は比較的単純な日付のみの型で、時刻やタイムゾーンは扱いません。

```julia-repl
# constructor with year, month, day arguments
julia> date1 = Date(2025, 06, 23)
2025-06-23

# constructor with ISO 8601 string
julia> date2 = Date("2025-06-23")
2025-06-23

julia> date1 == date2
true

julia> typeof(date1)
Date
```

日付の各部分を取得するアクセサ関数があり、これらは大文字・小文字で区別されたペアになっています。

```julia-repl
# lowercase returns an integer
julia> month(date1)
6

julia> typeof(month(date1))
Int64

# Propercase returns a Period type
julia> Month(date1)
6 months

julia> typeof(Month(date1))
Month
```

### クエリ関数

カレンダーをある程度理解したさまざまな関数があります。次の例では、ほんの一部を紹介します。

```julia-repl
julia> date1
2025-06-23

julia> dayofweek(date1) # 1 = Monday, 7 = Sunday
1

julia> dayname(date1)
"Monday"

julia> daysinmonth(date1)
30

julia> isleapyear(date1)
false

julia> lastdayofmonth(date1)
2025-06-30
```

## 時刻

`Dates.Time`は基本的な時刻のみの型です。日付は扱いません。時刻は真夜中になると自動的に`Time(0, 0, 0)`に戻ります。

コンストラクタの完全な形式は`Time(hour, min, sec, millisec, microsec)`、またはISO 8601に相当する形式です。

すべてのパラメータは省略可能で、デフォルトは`0`になります。

```julia-repl
julia> Time(14, 57, 25, 142)
14:57:25.142

julia> Time("14:57:25.142")
14:57:25.142

julia> Time(14, 57, 25, 142, 32)
14:57:25.142032
```

`Date`と同様に、各部分はアクセサ関数で取得できます。

```julia-repl
julia> minute(t) # => integer
57

julia> Minute(t) # => Period
57 minutes
```

## 日時

`Dates.DateTime`は`Date`型と`Time`型のほとんどの機能を組み合わせたものです。

```julia-repl
julia> dt1 = DateTime(2025, 6, 23, 14, 57, 25, 142)
2025-06-23T14:57:25.142

# date1 and t were defined in previous examples
julia> dt2 = DateTime(date1, t)
2025-06-23T14:57:25.142
```

年、月、日のパラメータのデフォルトは`1`、時刻のパラメータはすべてデフォルトで`0`です。

これらのパラメータをすべて正しく覚えておくのは大変なので、入力にはISO形式を使うほうがよいでしょう。

あるいは、上の例のように、`Date`と`Time`から`DateTime`を構築することもできます。

## 期間

日付・時刻の各要素には、`Year`から`Nanosecond`まで、それぞれ独自の`Period`型があり、時間の間隔を表します。これらは特に計算に役立ちます。

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Year(21)
21 years

julia> Second(61)
61 seconds

julia> dt1 + Year(21) - Second(61)
2046-06-23T14:56:24.142

julia> Date(2025, 07, 03) - Date(2025, 04, 25)
69 days
```

`Period`型を扱うとき、Juliaは月の長さのようなカレンダーの不規則性を賢く処理しようとし、必要に応じて丸めます。

```julia-repl
# February has fewer days than January
julia> Date(2025, 1, 31) + Month(1) 
2025-02-28
```

## 文字列表現

先ほどISO 8601標準に触れました。これは、文字列をフォーマットまたは解析するときのJuliaのデフォルトの日時表現です。

もちろん、他にも多くの形式が頻繁に使われており、しばしば文化的に固有のものです。これらを扱うために、Juliaには`DateFormat`型があり、任意の複雑さのフォーマット文字列から構築できます。

```julia-repl
# dateformat"" string syntax
julia> dtfmt = dateformat"d/m/y"
dateformat"d/m/y"

julia> typeof(dtfmt)
DateFormat{Symbol("d/m/y"), Tuple{Dates.DatePart{'d'}, Dates.Delim{Char, 1}, Dates.DatePart{'m'}, Dates.Delim{Char, 1}, Dates.DatePart{'y'}}}

# DateFormat constructor
julia> DateFormat("d/m/y")
dateformat"d/m/y"
```

上の例は非常に単純で、ヨーロッパで一般的な日/月/年の形式の日付にすぎません。2つの構文のバリエーションを示していますが、結果は同じです。

`DateFormat`は、適切な文字列を解析するのに使えます。

```julia-repl
julia> DateTime("14/7/2023", dtfmt)
2023-07-14T00:00:00
```

`DateFormat`の作成にはかなりのオーバーヘッドがかかるので、この手順を一度だけ行うこと（ここでの`dtfmt`のように）は、多くの日時文字列をループ処理する際のパフォーマンスに役立ちます。

フォーマットはこれよりはるかに複雑にできるので、詳細は[マニュアル][dateformat]を参照してください。

同じ`DateFormat`は、[`Dates.format()`][format]関数を使って、日時を任意の文字列形式で出力するのにも使えます。

残念ながら、`format`とは名前空間の競合があるようです（少なくともJulia 1.11.5の時点では）。そのため、`using Dates`の後でも`Dates.`の接頭辞を付けるのが最善です。

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Dates.format(dt1, dateformat"e, u d")
"Mon, Jun 23"
```

[ドキュメント][wiki-format]にあるように、`"e, u d"`は曜日と月の省略されたテキスト表現を与えます。

テキスト表現のデフォルトは英語です。他の言語も追加できますが、現時点ではそのサポートは十分とはいえません。
