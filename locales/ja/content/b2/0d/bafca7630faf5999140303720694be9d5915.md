# 概要

[`switch()`][ref-switch]関数は、長く連なる`if`や`else if`の条件判定を簡潔に置き換えられます。
`switch`の対象となる変数はほとんどの場合文字列で、その場合、セレクターの引用符は省略できます。

```R
star <- function(type) {
  switch(type,
    M = , # will "fall through" if no value given
    K = "red dwarf",
    G = "Earth-like",
    "bigger star" # only correct for O,B,A,F
  )
}

> star("M")
[1] "red dwarf"
```

上の例の`M`のように、値を空にしたときにだけ、そのオプションはフォールスルーします。
他の言語のように`break`文を書く必要はありません。

最後の値は、ここでのようにデフォルトにするか、すべての条件を網羅したい場合にはエラーを投げる[`stop()`][ref-stop]にできます。
整数を対象にした`switch`は少し異なり、その場合のデフォルトは常に`NULL`です（これについては[「Nothingness」概念][concept-nothingness]で扱います）。

## `dplyr`の関数

base Rの`switch`はかなり限定的で、1つの入力に対する完全一致しか行いません。
1993年にRが最初にリリースされた当時は妥当でしたが、現代の使い方には改善が必要です。

~~~~exercism/note
[`Conditionals`][concept-conditionals]の概念でも触れたように、[`tidyverse`][web-tidyverse]のパッケージ群は、後方互換性を損なわずにbase Rの機能を補完する（ときには置き換える）ために設計されています。

tidyverseのパッケージには、優れた現代的なドキュメントもそろっているので、以下のリンクをたどるとより詳しい情報が得られます。

[`dplyr`][ref-dplyr]パッケージは、コードの先頭に`library(dplyr)`（単体のパッケージを使う場合）か`library(tidyverse)`（コレクション全体を使う場合）を追加すると利用できるようになります。

`dplyr`ライブラリには、`switch`に関連する2つの追加関数があります。

#### [`recode_values`][ref-recode_values]関数と[`replace_values`][ref-recode_values]関数

この2つのよく似た関数を使うと、`switch`のようなベクトル化された、古い値から新しい値への対応づけができます。

両者の主な違いは、`recode_values()`がまったく新しいベクトルを作るのに対し、`replace_values()`は既存のベクトルの一部だけを更新できる点です。

照合は依然として完全一致ですが、次の点が異なります。

- 左側のオプションにはベクトルを書くこともでき、いずれかの要素が一致すれば入力が一致したとみなされます。
- 左側のオプションと右側の結果は、`=`ではなくチルダ`~`で結びます。
- 欠損値`NA`も明示的に照合できます（これについては[「Nothingness」概念][concept-nothingness]で扱います）。
- どの場合にもデフォルトを指定できます。

```R
library(dplyr)

x <- c("a", "b", "a", "d", "b", NA, "c", "e", "z")
recode_values(
  x,
  "a" ~ 1,
  "b" ~ 2,
  "c" ~ 3,
  c("d", "e") ~ 4, # either "d' or "e" will match
  NA ~ 0,          # matches missing values
  default = 100   # note the different syntax for the default
)
#> [1]   1   2   1   4   2   0   3   4 100
```

~~~~exercism/note
オンラインでは、ベクトル化された`switch`として`case_match()`関数を使うというアドバイスを見かけるかもしれません。

この関数は`dplyr`バージョン1.2.0（2026年2月）で非推奨になりました。
これを使おうとすると警告メッセージが表示され、代わりに`recode_values()`を使うよう促されます。
~~~~

### The [`case_when`][ref-case_when]関数

[`case_when`][ref-case_when]は、`case_match`の構文をさらに一歩進め、`~`の左側に任意の論理式を書けるようにします。

入力のベクトル（下の例では`x`）は引数として渡すのではなく、あらかじめ定義しておくだけです。

```R
x <- 1:10
case_when(
  x < 3 ~ "low",
  between(x, 3, 5) ~ "mid",
  between(x, 6, 8) ~ "high",
  .default = "what?"
)
#>  [1] "low"   "low"   "mid"   "mid"   "mid"   "high"  "high"  "high"  "what?" "what?"
```

[`between()`][ref-between]関数も`dplyr`の一部です。

[文字列の関数][concept-strings]はすでに扱いましたし、[正規表現][concept-regex]は後の概念で扱います。
これらは`case_when`ととても相性がいいです。

```R
library(stringr)

tracks <- "R C Python C# Elixir C++ Odin" |> str_split_1(" ")
tracks
#> [1] "R"      "C"      "Python" "C#"     "Elixir" "C++"    "Odin"  

case_when(
  str_starts(tracks, "C") ~ "C-like",
  str_starts(tracks, "[AEIOU]") ~ "vowel",
  .default = "other"
)
#> [1] "other"  "C-like" "other"  "C-like" "vowel"  "C-like" "vowel"
```
