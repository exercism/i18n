# 構造体

構造体は、固定された異なる型のデータを1つの単位にまとめます。Rustの構造体には、次のような性質があります。

- すべての構造体の型には、それぞれ名前があります。
- 構造体の各要素は**フィールド**と呼ばれます。
- 構造体の各フィールドには、それぞれ名前があります。
- 可視性はフィールド単位で管理されます。各フィールドは、それぞれ独立して公開、非公開、その他に設定できます[^1]。

# 構造体の概要

構造体は、`struct`キーワードを使って定義し、そのあとに構造体が表す型の名前を書きます。
名前のあとには、通常の構造体なら波括弧（`{}`）、タプル構造体なら括弧（`()`）、ユニット構造体ならセミコロンを続けます。

```rust
struct Item {}
```

次に、その他の型を構造体の本体に構造体の_フィールド_として取り込みます。各フィールドはそれぞれ自分の型を持ちます。

```rust
struct Item {
    name: String,
    weight: f32,
    worth: u32,
}
```

最後に、`impl`ブロックの中にメソッドを定義できます。

```rust
impl Item {
    // initializes and returns a new instance of our Item struct
    fn new() -> Self {
        todo!()
    }
}
```

# 構造体の種類

構造体には3種類あります。名前付きフィールドを持つ構造体（通常の構造体）、タプル構造体、ユニット構造体です。

構造体は**タプル**とよく似ています。実際、構造体とタプルの違いは、何が匿名かという点だけです。大まかな形は次のとおりです。

- 構造体は名前を持ち、フィールドにも名前があります。

  ```rust
  struct Foo {
      bar: Bar,
      bat: Bat,
  }
  ```

  フィールドには名前でアクセスします。

  ```rust
  let bar = foo.bar;
  ```

- タプル構造体は名前を持ち、フィールドは匿名です。

  ```rust
  Foo(Bar, Bat)
  ```

  フィールドには分割代入か数値インデックスでアクセスします。

  ```rust
  // unpacking
  let (bar, bat) = foo;
  ```

  ```rust
  // numeric index
  let bar = foo.0;
  let bat = foo.1;
  ```

- タプルは匿名で、フィールドも匿名です。

  ```rust
  (Bar, Bat)
  ```

  タプル構造体と同じく、フィールドには分割代入か数値インデックスでアクセスします。

- 匿名構造体は、その名のとおり匿名ですが、フィールドには名前があります。GoやJavaなど他の言語で見たことがあるかもしれません。Rustには存在せず、代わりにタプルを使うのが慣用的です。

# ゼロサイズ型

構造体は、必要なだけいくつでも、あるいは少しだけでもフィールドを持てます。つまり、フィールドが0個の構造体も合法です。フィールドが0個の構造体は**ゼロサイズ型**と呼ばれ、コンパイラーによって特別に扱われます。ゼロサイズ型（よく**ZST**と略されます）は、消費すると思われる場面でも、スタックやヒープの領域を一切消費しません。たとえば、`T`がZSTであれば、`Box<T>`はヒープメモリを一切割り当てません。

ZSTを書くときは、通常の構造体かタプル構造体の構文を使えます。

```rust
// declaration
struct Foo {}
// instantiation
let foo = Foo {}
```

```rust
// declaration
struct Foo();
// instantiation
let foo = Foo();
```

ZSTには省略記法もあります。

```rust
// declaration
struct Foo;
// instantiation
let foo = Foo;
```

通常、ZSTを書くときは省略記法が好まれます。スタイルは混ぜられないからです。ZSTを宣言するのに使ったスタイル[^2]が、そのままインスタンス化に必要なスタイルになります。

ZSTの構文についてここまで見てきたので、なぜそんなものが必要になるのかを考えてみましょう。ZSTはデータを一切保存できませんが、トレイトを実装するのには最適です。

---

[^1]: [こちらのドキュメント](https://doc.rust-lang.org/reference/visibility-and-privacy.html)では、あまり使われない可視性のオプションが説明されています。
[^2]: これは一般的なルールの一例です。どんな構造体の型を宣言するのに使ったスタイルであっても、インスタンス化には同じスタイルが必要です。
