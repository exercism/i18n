# テスト

  ## 概要

  1. `<myFileName>.u`ファイルに変更を加えます
  2. `<myFileName>.u`ファイルを保存します
  3. ファイルの型チェックが通ったら、UCMの`add`または`update`コマンドを実行します
    * ファイルの型チェックが通らない場合は、コンパイルが通るまで`<myFileName>.u`ファイルのコードを修正します。変更したあとは、忘れずに関数を`update`しましょう！
  4. UCMのCLIで`load <myFileName>.test.u`コマンドを実行して、テストをスコープに入れて実行します

  ## 順を追って見てみましょう

  コマンドラインでExercismの演習に取り組んでいるときは、たいてい、その演習の名前が付いたディレクトリで解答を実装することになります。たとえば、演習が`hello-world`なら、コマンドラインから`~/exercism/unison/hello-world`に`cd`してから、`ucm`を開きます。実装の変更は`hello.u`ファイルで行い、実装に満足できたら、Unison codebase manager CLI（UCM）で`add`または`update`コマンドを入力して、ファイルでの作業をコードベースに取り込みます。

  各演習のテストが入っているファイルには、`.test.u`という接尾辞が付いています。UCMの`load`コマンドを使って、テストをスコープに入れて実行しましょう。`load`コマンドは、引数としてファイルパスを取ります。hello worldの演習では、次のようになります。

  ```
  .> load hello.test.u
  ```

  UCMから、スコープに入った定義についてのメッセージと、何より大切な、テストを実行した結果が表示されます。

  ```

    ⍟ These new definitions are ok to `add`:

      hello.test : Test.Test
      tests      : [Result]

  Now evaluating any watch expressions (lines starting with
  `>`)... Ctrl+C cancels.


    6 | test> tests = runAll [hello.test]

    🚫 FAILED
  ```

  テストが最初は通らなかったとしましょう。`myExercise.u`ファイルの編集に戻って、保存すれば`update`できます。

  ```
  I found and typechecked these definitions in ~/Exercism/unison/hello-world/hello.u. If you do an
  `add` or `update`, here's how your codebase would change:

    ⍟ These names already exist. You can `update` them to your new definition:

      hello : Text

  .> update

  ⍟ I've updated these names to your new definition:

    hello : Text
  ```

  次に、テストをもう一度`load`して、何か変わったかどうか確かめてみましょう。

  ```
  .> load hello.test.u
    Now evaluating any watch expressions (lines starting with `>`)... Ctrl+C cancels.


    6 | test> tests = runAll [hello.test]

    ✅ Passed : Passed 1 tests.
  ```
