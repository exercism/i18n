# 概要

[`switch`文][switch_statement]は式を評価し、その値に一致する最初の`case`を実行します。
長い`if ... else if`の連鎖に比べて、しばしばすっきりと書ける代替手段です。

## 基本的な使い方

```go
operatingSystem := "windows"

switch operatingSystem {
case "windows":
    // do something if the operating system is windows
case "linux":
    // do something if the operating system is linux
case "macos":
    // do something if the operating system is macos
default:
    // do something if the operating system is none of the above
}
```

複数の値は、カンマで区切って1つの`case`にまとめられます。
式がいずれかの値と等しければ、その`case`が一致します：

```go
switch operatingSystem {
case "windows", "linux":
    // do something if the operating system is windows or linux
case "macos":
    // do something if the operating system is macos
default:
    // do something if the operating system is none of the above
}
```

## 式のない`switch`

`switch`の後ろの式は、まるごと省略することもできます。
その場合、各`case`には真偽値の式を書き、最初に`true`と評価されたものが実行されます。

```go
age := 21

switch {
case age > 20 && age < 30:
    // do something if age is between 20 and 30
case age == 10:
    // do something if age is equal to 10
default:
    // do something else for every other case
}
```

## 初期化文

`if`と同じように、`switch`も式の前に短い初期化文を書くことができます。
そこで宣言した変数のスコープは、`switch`ブロックの中だけです：

```go
switch v := getValue(); {
case v < 0:
    // do something if v is less than 0
case v == 0:
    // do something if v is 0
default:
    // do something else for every other case
}
// v will not be accessible here
```

## `fallthrough`

`fallthrough`は、次の`case`の式が一致するかどうかに関わらず、その本体を実行させます。
これは`case`の本体の最後の文でなければならず、また実行する次の`case`が存在する必要があります。

`fallthrough`は、隣り合う`case`同士を互いに依存させるため、慣用的なGoではあまり使われません。
その結果、各`case`を単独で考えるのが難しくなり、`switch`全体が読みにくくなります。
複数の`case`を同じ動作にしたいときは、カンマでまとめるほうが分かりやすくなります。
それ以外の理由で複数の`case`に共通のロジックがある場合は、その共通部分をヘルパー関数として切り出すことを検討しましょう。

```go
s := "hello"

switch s {
case "hello":
    fmt.Println("hello")
    fallthrough
case "world":
    fmt.Println("world") // also runs, even though s != "world"
}
// Output:
// hello
// world
```
