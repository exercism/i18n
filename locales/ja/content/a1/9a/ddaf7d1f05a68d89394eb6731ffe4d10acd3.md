# はじめに

*デック*（両端キュー）は、両端でのプッシュとポップをO(1)で行えます。Factorの標準実装は、[`dlists`][dlists]にある`<dlist>`（双方向連結リスト）です。操作は[`deques`][deques]にあります。

## デックのAPI

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque`はデックをその場で空にします。再確保せずに使い回したいときに便利です。

同じ端でプッシュとポップを行えば、LIFOのスタックになります。一方の端でプッシュし、もう一方の端でポップすれば、FIFOのキューになります。

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

LIFOなら、`push`と`pop`を備えたベクター（`V{ }`）を使う手があります。1回あたりのオーバーヘッドが小さくて済みます。`<dlist>`を選ぶのは、*両方*の端でO(1)が必要なとき、つまりほとんどはFIFOキューの場合です。

## 幅優先探索

デックをFIFOとして使うことで、幅優先探索のフロンティアにぴったりの構造になります。まず1つのノードから始め、隣接ノードを後ろにプッシュし、候補を前からポップし、ハッシュセットで重複を除きます。

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

古い候補のほうが新しい候補より先に訪問されるため、探索は開始点から層状に外側へ広がっていきます。これが幅優先探索に最短経路の性質を与えます。ゴールのノードに初めてたどり着くとき、その経路は最小ホップ数になっているのです。

## `MEMO:`：自動キャッシュ

幅優先探索がノードごとに呼び出す検索が、高コストになることがあります。Factorの[`memoize`][memoize]ボキャブラリーには`MEMO:`が用意されています。これは`:`の代わりにそのまま使えるもので、ワードの結果をその入力に基づいてキャッシュします。

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

`MEMO:`のワードは、それぞれの入力が初めて現れたときに本体を実行し、それ以降はキャッシュした結果を返します。インターフェースは同じままで、呼び出し側に余計な呼び出しは必要なく、繰り返し使うときに速くなるだけです。
