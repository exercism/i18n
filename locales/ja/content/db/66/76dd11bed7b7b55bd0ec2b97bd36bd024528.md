# 正確な数値

| 型 | 保持する内容 | 上限 |
| --- | --- | --- |
| `INT` | 整数 | ちょうど32ビット |
| `FLTD` | 小数 | 近似値 |
| `INTI` | 整数 | メモリーの許す限り |
| `RAT` | 分数 | 正確 |

## INTI

```sather
   #INTI(42)
   #INTI("123456789012345678901234567890")
   a + b, a - b, a * b, a / b
   a < b, a = b
   #INTI(25).factorial
   #INTI(48).gcd(#INTI(18))       -- 6
   #INTI(2).pow(100)
   big.str
   small.int                      -- back to an INT, if it fits
```

2つの`INTI`に対する`/`は整数除算で、余りは切り捨てられます。`INT`の場合とまったく同じです。

`INT`に収まらない大きさの値に`.int`を使っても、問題は報告されません。それが重要なら、先に確認しておきましょう。

## RAT

```sather
   #RAT(1, 3)
   #RAT(6)                        -- from a whole number
   a + b, a - b, a * b, a / b
   a < b, a = b
   r.is_int                       -- is it a whole number?
   r.is_zero, r.is_pos, r.is_neg
   r.abs, r.negate
   r.floor                        -- an INTI, rounded down
   r.str
```

`RAT`は常に約分された形で、符号は常に分子に付きます。`#RAT(1, -2)`は`-1/2`です。2つの`RAT`は、まったく同じ分数であるときにだけ等しくなります。つまり`=`は期待どおりに動きます。これが`FLTD`との決定的な違いです。

`RAT`は`INTI`の上に作られているので、分子と分母にも大きさの制限はありません。分母の異なる分数をたくさん足すと、どんどん大きくなります。それぞれの足し算で、約分する前に分母どうしを掛け合わせるからです。

`ceiling`は宣言されていますが、"not implemented"を送出します。`floor`を使って調整しましょう。

## どちらを選ぶか

数え上げる数が20億を超える可能性があるときは`INTI`を使いましょう。階乗、累乗、組み合わせ、長期間にわたる累計などです。

分数が正確でなければならず、分母がそれほど大きくないときは`RAT`を使いましょう。取り分、確率、音符の長さなど、そうしないと丸め誤差が積み重なってしまうもの全般です。

とくに理由がなければ、どちらも使う必要はありません。`INT`と`FLTD`のほうがはるかに速く、ほとんどの計算にはそれで十分です。

お金の計算では、どちらも通常の答えではありません。セントを整数として`INT`で数えましょう。
