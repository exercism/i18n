# 指示の補足

## 実装

始める前に、テストケースを通過できるコードの書き方を理解しておきましょう。詳しくは、こちらの[チュートリアル]を参照してください。

Javaの演習のほとんどには、複数のテストケースが含まれています。
これらのテストケースは、[テスト駆動開発（TDD）][tdd]と呼ばれる、役に立つプロセスを支えるように構成されています。
TDDでは、プログラマーが複雑な機能を一度にまとめて作るのではなく、少しずつ組み立てられるようにするための、決まったサイクルを繰り返します。
そのサイクルは、次のように説明できます。

1. 今のコードに足りていない、望ましい機能の一部を表すテストを追加します。
2. テストを実行して、今追加したテストが失敗することを確認します。
3. 次の状態になるまで、既存のコードを更新します：
   - これまでのテストがすべて通り続けること。
   - 新しいテストも通ること。
4. すべてのテストが通り続けることを確認しながら、コードを[整理][refactoring]します。
   通常は、変数の名前の変更、重複したロジックの削除、不要になったログの削除などを行います。
5. 望ましい機能をすべて実装し終えるまで、ステップ1に戻ります！

このトラックのテストファイルには、解答が有効と見なされるために通すべきテストが_すべて_含まれています。
これは、テストを1つずつ書いていくという、上で説明したサイクルとは、すぐには両立しないように思えます。
しかし、テストを書くために使っているツールである[JUnit][junit]には、すでに書いたテストを一時的にスキップするための[@Disabled][junit-disabled]という[アノテーション][java-annotation]があります。
このアノテーションを使うことで、お届けするテストファイルが次のルールを満たすようにしています：

- どのテストファイルでも、最初のテストはデフォルトで_スキップされません_。
- どのテストファイルでも、最初のテスト以外はすべてデフォルトで_スキップされます_。

これにより、少し変更した次のステップで、TDDのサイクルをシミュレートできます：

1. テストを実行して、現時点で失敗するテストが_多くても1つ_であることを確認します。
2. スキップされていないテストがすべて通るまで、既存のコードを更新します。
3. スキップされていないテストがすべて通り続けることを確認しながら、コードを整理します。
4. テストファイルの中で一番上の`@Disabled`アノテーションを削除します。
5. スキップされるテストがなくなり、すべてのテストが通るまで、ステップ1に戻ります！
