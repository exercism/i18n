# はじめに

メモリは通常、オペレーティングシステム（OS）によって、プログラムのために次のような一般的なレイアウトでマッピングされます。

| アドレス | メモリ領域 |
| :-----: | :--------------------- |
|  高アドレス   | スタック                  |
|         | ...                    |
|         | ヒープ                   |
|         | 読み書き可能セグメント |
|         | コード／読み取り専用セグメント |
|  低アドレス   | 予約済み               |

セグメントに分けられたメモリは、それぞれ異なる権限を持つセクションで構成されています。

これまで定義してきた関数は、すべて**`.text`セクション**にありました。
このセクションには、読み取り専用の実行可能データが入っています。
ほかのセクションはデータ変数の宣言に使われます。読み取り専用のことも読み書き可能なこともありますが、実行可能ではありません。

## `.data`セクション

初期化されたデータは、**`.data`セクション**に宣言します。

NASM（The Netwide Assembler、このトラックで使うアセンブラー）では、初期化された変数は、名前、データサイズを示すディレクティブ、そしてカンマで区切られた値のリストを持ちます。
これらの要素はそれぞれスペースで区切られ、ラベルの後ろには任意で`:`を付けられます。

主なディレクティブと対応するデータサイズは次のとおりです。

| ディレクティブ | サイズ    |
| :-------: | :------ |
|    db     | 1バイト  |
|    dw     | 2バイト |
|    dd     | 4バイト |
|    dq     | 8バイト |

たとえば、これは`space`という名前のバイト変数を値`10`で宣言します。

```x86asm
section .data
    space db 10
```

`section .data`で宣言した変数は可変、つまり読み書き可能です。
また、_静的_な記憶域期間を持ち、プログラムの実行中ずっと存在します。

## `.rodata`セクション

**`.rodata`セクション**は`section .data`と似ています。
どちらのセクションも初期化されたデータを含み、宣言のしかたも記憶域期間も同じです。

両者の主な違いは、`section .rodata`のデータが不変、つまり読み取り専用であることです。

~~~~exercism/note
`equ`で定義した定数は、`section .rodata`で定義したものとは異なります。

`equ`で定義した定数はメモリ上に場所を取りません。アセンブラーによって、その値に直接置き換えられます。
実際、その値のプレースホルダーなのです。

一方、`section .rodata`で定義した定数は実際にメモリに格納され、アドレスを持ちます。
~~~~

## データへのアクセス

### ラベルと間接参照

宣言したデータには、必ず名前を付ける必要があります。
この名前を**ラベル**と呼びます。

ラベルは、メモリ上にあるデータの具体的なアドレスを表すシンボルです。
**x86-64のアドレスは64ビットの値です**。

NASMでラベルを使ってデータに直接アクセスしようとしても、得られるのは確保されたメモリそのものではなく、そのアドレスです。

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

メモリアドレスの内容にアクセスするには、そのアドレスを_逆参照_する必要があります。
これを**間接参照**と呼びます。

NASMでは、`[]`でこれを行います。

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

ただし、逆参照するメモリのサイズが曖昧になることもあります。
そのような場合は、サイズを指定するプレフィックスを使う必要があります。

一般的なx86-64プログラムでよく使う重要なプレフィックスとそのサイズは次のとおりです。

| プレフィックス | サイズ    |
| :----- | :------ |
| byte   | 1バイト  |
| word   | 2バイト |
| dword  | 4バイト |
| qword  | 8バイト |

同じ読み込みは、サイズを明示して書くこともできます。

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

メモリを逆参照するときは、常にプレフィックスを付けるのがよい習慣です。

### メモリへの書き込み

メモリへの書き込みも、アドレスを逆参照するという同じ方法で行います。

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

ほとんどの命令では、内容を先にレジスタに読み込まなくてもメモリオペランドを使えます。
ただし、通常はソースオペランドと宛先オペランドの両方には使えず、どちらか一方だけに使えます。

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### `lea`命令

`mov`でも変数のアドレスをレジスタに格納できますが、この目的専用の命令があります。それが**`lea`**です。

この命令はメモリ形式のオペランドを使いますが、メモリを読み取ることは_ありません_。
代わりに、実効アドレスの式を計算し、その結果を宛先オペランドに書き込みます。

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

メモリアドレスを計算してレジスタに格納するときは、`lea`を使うほうが自然です。

### 相対アドレス指定

メモリ位置にアクセスするとき、NASMの既定の動作は**絶対アドレス**、つまり固定されたメモリアドレスを生成することです。

セキュリティ上の理由から、実行ファイルは**PIE（位置独立実行ファイル）**としてビルドされることがよくあります。この場合、メモリ領域はランダムな位置に配置されます。
`PIE`では、変数の最終的なアドレスはリンク時に決まりません。
そのため、コードは`rip`という特別なレジスタの値を基準に、そこからのオフセットとしてアドレスを計算します。`rip`は次に実行する命令を指します。

これを通常、**RIP相対アドレス指定**と呼びます。

NASMでは、`rel`演算子を使うとRIP相対のアクセスを指定できます。

```x86asm
mov rax, qword [rel variable]
```

ソースファイルの先頭で`default rel`と書けば、相対アドレス指定を既定にすることもできます。

このトラックの演習はすべて`PIE`としてコンパイル・リンクされるので、相対アドレスを生成するには`rel`を使いましょう。

### 可視性

どのセクション（`.text`、`.data`、`.rodata`など）で定義されたラベル（関数やデータ）も、同じソースファイル内から参照できます。
`global`を付けて宣言すれば、ほかのソースファイルからも参照できます。

逆に、ほかのソースファイルで定義されたラベルは、`extern`を付けて宣言すれば、現在のソースファイルから参照できます。
この場合、アセンブリにはデータサイズの情報がないため、あらかじめ把握しておく必要があります。

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
