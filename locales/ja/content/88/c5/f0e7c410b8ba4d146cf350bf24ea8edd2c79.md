# はじめに

## 分岐なしコード

条件分岐のコンセプトでは、条件に基づいて分岐する命令ファミリーである`jcc`を紹介します。
`jcc`は、その条件が満たされたときにだけ、プログラムの別の地点へ実行を移します。

しかし、現代のCPUは高速で、多くの命令を並列に実行できます。
CPUが条件の実行時チェックを待つ間、すべての処理を止めてしまうのは、コストがかかりすぎます。

そのため、CPUは内部で待ったりはしません。
**分岐予測器**を使って条件の結果を推測し、予測した経路を_投機的に_実行し始めます。

予測が正しければ、分岐がなかったかのように実行が続きます。
しかし、予測が外れると、CPUは予測した経路で行った処理を_破棄_し、正しい経路でやり直さなければなりません。

これは**分岐予測ミス**と呼ばれ、遅延を引き起こすため、コストがかかります。

分岐の予測が難しいときは、そうした予測ミスが積み重なります。
そのような場合は、分岐を完全に避けて、条件に関係なく同じ命令が実行されるようにしたほうがよいことがあります。
`jcc`を使わずに値の選択を行うコードを**分岐なし**と呼びます。

コードが分岐する頻度を減らすように、あるいは実際にある分岐をより予測しやすくするように、コードを組み立てる方法はいくつかあります。
特に、x86-64には、分岐なしコードを書くためによく使われる2つの命令ファミリーがあります。

### 条件付き移動

`cmovcc`という命令ファミリーは、特定の条件が満たされたときにだけ、ソースオペランドをデスティネーションにコピーします。
そうでなければ、デスティネーションは変更されません。

`cc`の接尾辞は`jcc`と同じ命名規則に従い、意味も同じです：

| 命令 | 移動する条件 |
|-------------|--------------------------------------|
| `cmove`     | `cmp A, B`の実行後、A == B |
| `cmovne`    | `cmp A, B`の実行後、A != B |
| `cmovl`     | `cmp A, B`の実行後、A < B（符号付き） |
| `cmovb`     | `cmp A, B`の実行後、A < B（符号なし） |
| `cmovg`     | `cmp A, B`の実行後、A > B（符号付き） |
| `cmova`     | `cmp A, B`の実行後、A > B（符号なし） |

規則は`jcc`と同様です：

1. `l`と`g`は符号付きの比較に使い、`b`と`a`は符号なしの比較に使います。
2. 接尾辞に`e`を付けると、等号が含まれます。
3. `n`を付けると、条件が反転します。
4. フラグがセットされていることを参照する変種もあります。
   たとえば、`cmovz`や`cmovc`です。

`rdi`に入った符号付き整数の絶対値を計算し、`rax`で返すことを考えましょう。
`jcc`で書くと、この関数は2つの経路のうち1つを選びます：

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

`cmovcc`で書くと、2つの候補値が無条件に計算され、条件付き移動がそのうちの1つを選びます：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

分岐なしのバージョンは、常に同じ命令を実行します。
予測器が推測する`jcc`はありません。

`cmovcc`のデスティネーションはレジスタでなければなりません。
ソースはレジスタかメモリ位置にできますが、即値にはできません。

~~~~exercism/note
上のコードでは、`neg`命令は結果に応じていくつかのフラグを設定します。その中には符号フラグ（SF）も含まれます。
つまり、`cmp rdi, 0`は完全に省くことができます：

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

正の`rdi`では、`neg`は負の結果を生み、SF == 1となるので、`cmovs`が`rdi`を復元します。
`rdi`が0か負の場合、`neg`は非負の結果を生み、SF == 0となるので、`rax`は反転された値（これが正しい絶対値です）を保ちます。

`cmp`はアセンブリコードで値を比較する主な方法ですが、多くの命令も結果に応じてフラグを設定します。
命令が影響するフラグの完全な一覧は、通常その[リファレンス][reference]に記載されています。
`neg`の場合は、SF、ZF、CF、OF、PFです。

[reference]: https://www.felixcloutier.com/x86/
~~~~

### 条件付きセット

`setcc`という命令ファミリーは、特定の条件が満たされたときにデスティネーションオペランドを`1`に設定し、そうでなければ`0`に設定します。
デスティネーションは常に_8ビットのオペランド_です。

`cc`の接尾辞は`jcc`や`cmovcc`と同じ命名規則に従います。
たとえば、`setz`は`ZF == 1`のときにデスティネーションを`1`に、そうでなければ`0`に設定します。

デスティネーションが8ビットなので、より幅の広い値が必要なときは、`setcc`のあとに`movzx`を続けるのが一般的です：

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

これは、比較の結果を整数の`0`か`1`に変換する、よく使われるイディオムです。
