# 説明

先日のセキュリティレビューを受けて、組織のアーカイブ済みログファイルを整理するよう依頼されました。

## 1. 文字化けしたログ行を特定する

アーカイブ内のログ行のうち、現在の標準に準拠していないものがどれくらいあるのか、だいたいの見当をつけておく必要があります。ログ行が有効かどうかは、簡単なテストで見分けられると考えています。有効とみなされるには、行が次のいずれかの文字列で始まっている必要があります。

- [DEBUG]
- [INFO]
- [WARNING]
- [ERROR]

`valid_line?/1`関数を実装して、ログ行が有効であれば`true`を返すようにしてください。

```elixir
LogParser.valid_line?("[ERROR] Network Failure")
# => true

LogParser.valid_line?("Network Failure")
# => false
```

## 2. ログ行を分割する

ログ解析プロジェクトを始めてまもなく、あるアプリケーションのログが他のアプリケーションのように行に分割されていないことに気づきます。このプロジェクトでは、本来なら別々の行になるはずのものが1行にまとまってしまい、`<--->`や`<*~*~>`のような風変わりな矢印でつながれています。

実際、最初の文字が`<`、最後の文字が`>`で、その間に`~`、`*`、`=`、`-`を任意に組み合わせた文字列は、このプロジェクトのログの区切り文字として使えます。

1行を受け取って文字列の配列を返す`split_line/1`関数を実装してください。

```elixir
LogParser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
# => ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. ログから不要なテキストを削除する

ログの上流処理のどこかが、"end-of-line"というテキストとそれに続く行番号（間に空白を挟まず）を、ログ全体に散りばめていることに気づきました。

`remove_artifacts/1`関数を実装してください。文字列を受け取り、"end-of-line"というテキスト（大文字小文字を区別しない）の出現箇所をすべて取り除いて、きれいなログ行を返します。

"end-of-line"のテキストを含まない行は、そのまま返してください。

"end-of-line"の文字列を取り除くだけです。空白を調整する必要はありません。

```elixir
LogParser.remove_artifacts("[WARNING] end-of-line23033 Network Failure end-of-line27")
# => "[WARNING]  Network Failure "
```

## 4. ユーザー名で行にタグを付ける

ログ行の中には、ユーザーに言及する文が含まれているものがあることに気づきました。そうした文には必ず`"User"`という文字列が含まれ、そのあとに1つ以上の空白文字、そしてユーザー名が続きます。そこで、そのような行にタグを付けることにします。

ログ行を処理する`tag_with_user_name/1`関数を実装してください。

- 文字列`"User"`を含まない行は、そのまま変更しません。
- 文字列`"User"`を含む行は、行の先頭に`[USER]`とユーザー名を付けます。

```elixir
LogParser.tag_with_user_name("[INFO] User Alice created a new project")
# => "[USER] Alice [INFO] User Alice created a new project"
```

次のことを前提としてかまいません。

- `"User"`という文字列の出現箇所には、必ず1つ以上の空白文字とユーザー名が続きます。
- 各行に`"User"`という文字列は多くても1回しか出現しません。
- ユーザー名は、空ではなく空白文字を含まない文字列です。
