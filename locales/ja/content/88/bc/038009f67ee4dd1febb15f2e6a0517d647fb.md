# ソート

ものを順番に並べることはよくあるので、ライブラリが代わりにやってくれます。

```sather
   scores : ARRAY{INT} := |3, 1, 2|;
   scores.sort;              -- 1, 2, 3
```

`sort`は、自分自身を比較する方法をすでに知っているものなら何にでも使えます。数値と文字列がそうで、どちらも`is_lt`を持っているからです。

## 自分のルールでソートする

並び順のほとんどは、組み込みのものではありません。ネットボールの順位表は、アルファベット順でも名前の長さ順でもありません。勝ち点順で、勝ち点が並んでいるチームについては得失点差順です。`ARRAY`がそれを推測するすべはありません。

そこで、順序を、束縛したルーチンとして渡します。

```sather
   before(a, b : STR) : BOOL is
      return a.size < b.size;
   end;

   ...

   words.insertion_sort_by(bind(before(_, _)));
```

`insertion_sort_by`は`ROUT{T,T}:BOOL`を受け取ります。これは、ソートする2つの値を受け取り、1つ目が2つ目より前に来るべきかどうかを答えるルーチンです。このルーチンを必要なだけ呼び出し、その答えが示す順序に配列を並べ替えます。

これが`understudy`の役割でした。ライブラリはソートのしかたは知っていますが、どんな順序で並べたいのかについては何も知りません。その2つが出会うのが、束縛したルーチンです。

## 比較の書き方

このルーチンは、**第1引数が先に来るときに`true`を返します**。

```sather
   -- shortest first
   return a.size < b.size;

   -- longest first: turn it round
   return a.size > b.size;
```

ルールが複数の部分からなる場合は、重要な部分から順に扱います。

```sather
   higher(a, b : TEAM) : BOOL is
      if a.points /= b.points then
         return a.points > b.points;      -- more points comes first
      end;
      return a.difference > b.difference; -- level: better difference wins
   end;
```

最初の`if`は、勝ち点が異なるときは必ず決着をつけます。勝ち点が等しいときにだけ、2行目がものを言います。タイブレーカーを先に書いてしまうと、勝ち点がまったく意味を持たなくなってしまいます。

## ソートは配列を変更します

`insertion_sort_by`は配列そのものを並べ替え、何も返しません。

```sather
   teams.insertion_sort_by(bind(higher(_, _)));   -- teams is now sorted
```

元の順序が重要な場合は、コピーをソートします。

```sather
   ranked ::= teams.copy;
   ranked.insertion_sort_by(bind(higher(_, _)));
   return ranked;
```
