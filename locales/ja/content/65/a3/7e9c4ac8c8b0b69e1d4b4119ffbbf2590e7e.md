# はじめに

Gleamでは、`case`式を使うと、条件に応じてコードを実行できます。`case`式を使うと、ある値を1つ以上の_パターン_と照合できます。そうしたパターンの例が_リテラルパターン_で、これは値をリテラル値（たとえば`1`や`"hello"`）と照合します。

`case`式は、`case`キーワードを使って書きます。

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    1 -> "One"
  }
}
```

これは他の言語の`switch`文に似ているように見えるかもしれませんが、パターンマッチングの真価は、他のパターンもあわせて使うときに発揮されます。そうしたパターンの1つが_変数パターン_で、これを使うと値を変数に代入できます。この例では、`number`が`0`でなければ、変数`i`に`number`の値が代入されます。

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i -> "Non zero"
  }
}
```

場合によっては、パターンに条件を追加したいことがあります。これは_ガード_（節）と呼ばれ、`if`キーワードを使って追加できます。

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
  }
}
```

パフォーマンス上の理由から、ガードで使えるのは基本的な算術演算子と真偽値演算子だけです。他の関数をガードの中で使うことはできません。

上の例では、起こりうるすべての入力に一致するパターンがあるわけではありません。コンパイラーがこれを検出し、エラーを出力します。これは_網羅性チェック_と呼ばれます。この警告を解消するには、すべてのケースに対処する必要があります。そのために使えるのが_破棄パターン_で、これはどんな値にも一致するパターンです。

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
    _ -> "Positive number"
  }
}

// No compiler error
```

`case`式は、一致するパターンを見つけてそのパターンに対応する処理を実行するまで、値を上から順に各パターンと照合していきます。パターンの順番は重要です！
