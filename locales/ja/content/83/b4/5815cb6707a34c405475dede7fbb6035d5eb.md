# 概要

スカラーコードは、各種命令が設定するフラグに頼って、ある条件に応じて分岐します。
一方、パックされた値は、1つではなく多数の値を並列に表します。
1つの条件が、あるレーンでは成立せず、別のレーンでは成立することがあります。

これが、SIMDコードがデフォルトで[ブランチレス][branchless-code]である理由です。

フラグに頼る代わりに、パック比較は通常、デスティネーションオペランドに**マスク**を生成します。
各レーンについて、比較は、条件が真ならレーン全体を1で埋め、偽なら0で埋めます。
符号付き整数として読むと、真のレーンは`-1`、偽のレーンは`0`です。

このマスクは、[ビット演算][simd-bitwise]と組み合わせて、特定のレーンをフィルタリングできます。

## パック比較

スカラーの`cmp`は、同時にさまざまなフラグを設定するために使われるという意味では汎用的です。
その後、別の命令がそれらのフラグを消費して、分岐したり計算を実行したりできます。

しかし、パック比較は条件の確認とマスクの計算を同時に行うため、汎用的ではありません。
比較には、テストする条件を正確に指定する必要があります。

これには2つの方法があります。

- 整数比較では、条件をサフィックスとして指定します。等価には`eq`、より大きいには`gt`です。
  その他の変種は、これらのいずれかの結果を組み合わせて作ります。
- 浮動小数点比較では、条件をイミディエートにエンコードして指定します。
  このイミディエートの値が異なれば、テストされる条件も異なります。

整数比較で特定の条件サフィックスを使う点を除けば、構文はすでに見てきたのと同じ構造に従います。

- 整数の場合、`p` + `cmp` + 条件 + サイズ（`b`、`w`、`d`、`q`）です。
- 浮動小数点の場合、`cmp` + `p` + サイズ（`s`、`d`）です。
  条件は追加のオペランドとしてイミディエートで渡します。

### 整数比較

前述のとおり、整数比較には等価とより大きいの2種類しかありません。

| 命令                                       | 説明                             |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | レーンごとの等価                 |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | レーンごとの**符号付き**より大きい |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

より小さい比較を作るには、オペランドを入れ替えて`gt`を使います。`a < b` == `b > a`です。

この比較は**符号付き**であることに注意してください。
符号なし比較を行うには、両方のオペランドの最上位ビットを反転します。
これは、最上位ビットだけがセットされたマスクとのXORで行えます。

~~~~exercism/note
便利なイディオムが2つあります。

1. レジスタ自身とのXORで、すべて0を作ります。
2. レジスタ自身との比較で、すべて1を作ります。

たとえば、次のとおりです。

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

すべて0とすべて1は、それぞれ「どこも偽」と「どこも真」をエンコードする、よくあるマスクです。
これらは、パックされた`0`やパックされた`-1`を表すのにも使えます。これらはよくあるセンチネル値です。
たとえば、文字列の終わりを示すNULは`0`です。
~~~~

### 浮動小数点比較

浮動小数点のレーンは形が異なります。命令は`cmpps`（64ビットレーンの場合は`cmppd`）の1つだけで、条件をイミディエートとして渡します。

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASMには、正しいイミディエートに対応し、より覚えやすい疑似命令もあります。
以下ではすべて、`px`の`x`は`s`（32ビット浮動小数点数）または`d`（64ビット浮動小数点数）です。

| 疑似命令     | イミディエート | 比較                   |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | aがNaN、またはbがNaN   |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | aもbもNaNではない      |

~~~~exercism/caution
NaNは順序なしとして比較されます。NaNは、自分自身を含め、何に対してもより小さい、等しい、より大きいのいずれでもありません。
`cmpltps`のような順序付き述語は、どちらかのオペランドがNaNのとき偽になり、順序なし述語は真になります。
`cmpordps`と`cmpunordps`が存在するのは、NaNを明示的にテストするためです。
~~~~

## マスクによる選択

マスクは条件の結果をエンコードします。
そして、その条件に従って、2組の値のどちらかをレーンごとに選ぶのに使えます。
マスクが真のところでは一方の値から、偽のところではもう一方の値からレーンを取ります。

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

このパターンは、ブランチレス選択のパック形式です。
すべてのレーンが計算され、どの値が生き残るかはマスクだけが決めます。`jcc`はどこにも現れません。

## 専用のブレンド命令

同じ選択を直接行う命令があり、マスクレジスタから要素ごとに1ビットを読み取ります。
これらは**ブレンド**命令と呼ばれます。

| 命令        | 要素        | マスクの取得元   |
|-------------|-------------|-----------------|
| `pblendvb`  | バイト      | 暗黙の`xmm0`    |
| `blendvps`  | 32ビットレーン | 暗黙の`xmm0` |
| `blendvpd`  | 64ビットレーン | 暗黙の`xmm0` |

最初の命令は整数の構文に従い、残りの2つは浮動小数点の構文に従うことに注意してください。
ただし、これらの命令は生のバイトを選択するだけなので、どれも整数と浮動小数点の両方に使えます。

各要素について、ブレンドは、対応するマスク要素の最上位ビットがクリアならデスティネーションを保持し、セットされていればソースを取ります。
参照されるのはその**最上位ビット**だけです。比較マスクはこれを満たします。なぜなら、そのレーンはすべて1かすべて0だからです。
マスクレジスタは常に`xmm0`で、これは暗黙です。

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

`pblendvb`を使って、他の任意のサイズの比較マスクからレーンを選択することもできます。
真のレーンではすべてのバイトがすべて1なので、`pblendvb`はそれらをすべて選択します。

~~~~exercism/note
これらの命令はすべて、実行する演算（`blend`）のあとに`v`を付けます。
この`v`は_variable_を表します。選択が固定ではなく、レジスタに依存するからです。

`v`の付かない変種もあり、それらはイミディエートに従って選択します。
同じパターンに従い、イミディエートのビット`i`がセットされていればレーン`i`を選択します。
~~~~

## マスクからスカラーへ戻す

SIMDコードは強力ですが、スカラーコードの柔軟性の多くを欠いています。
多くの状況で、パックレジスタからスカラー命令の世界へ戻る必要があります。

`movmsk`命令ファミリーは、この2つの世界の橋渡しをします。
これらの命令は、各レーンの**最上位ビット**を汎用レジスタに取り出します。

| 命令        | 取り出すもの                     | 結果の幅 |
|-------------|-----------------------------|--------------|
| `pmovmskb`  | 16バイトそれぞれの最上位ビット | 16ビット      |
| `movmskps`  | 4つのdwordそれぞれの最上位ビット | 4ビット       |
| `movmskpd`  | 2つのqwordそれぞれの最上位ビット | 2ビット       |

比較のあとに使うと、セットされた各ビットは「真」のレーンを、クリアされた各ビットは「偽」のレーンを表します。
この結果は、通常どおりスカラー命令で操作できます。
たとえば、`popcnt`は一致の数を数え、`tzcnt`は最初の一致を見つけます。

汎用レジスタは32ビット幅でも64ビット幅でもかまいません。

## ベクトル全体をテストする

スカラー命令`test`には、パック版の`ptest`もあります。

2つのオペランドの間でAND演算を行い、それらを変更しないという点で、スカラーの`test`と似ています。
`test`と違い、`ptest`はANDN演算も行い、第1オペランドを反転します。

したがって、`ptest`は、結果に応じてフラグを設定する、非破壊版の`pand`と`pandn`と考えることができます。
この2つの命令とほぼ同じように、`ptest`はSIMDレジスタ全体を1つのレーンとして扱うため、サイズプレフィックスを取りません。

AND演算の結果が`0`なら`ZF`がセットされ、ANDN演算の結果が`0`なら`CF`がセットされます。
つまり、`ptest`はすべて1のマスクとすべて0のマスクの両方を確認するのに使えます。

1. レジスタに対して自身で`ptest`を使うと、レジスタがすべて0のときだけ`ZF`がセットされます。
   これは、レジスタが`0`かどうかを確認するために自身で`test`を使う、よくあるスカラーのイディオムを模倣しています。
2. レジスタにすべて1のマスクを付けて`ptest`を使うと、レジスタがすべて1のときだけ`CF`がセットされます。
   また、レジスタがすべて0のときだけ`ZF`がセットされるので、両方のマスクを一度に確認できます。

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

`ptest`の結果は、いつもどおり、分岐に使ったり、`setcc`や`cmovcc`のようなブランチレス命令に使ったりできます。

## AVXとその先

AVXは、比較、ブレンド、`ptest`に、より幅の広いレジスタ上で`v`を付けた形式を与えます。

可変ブレンドは形が変わります。
マスクは暗黙の`xmm0`ではなく、明示的な第4オペランドになります。

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

AVX-512拡張は、このモデルをさらに大きく変えます。

第一に、`zmm`と呼ばれる64バイトのSIMDレジスタの新しいクラスを追加します。
これらは、`ymm`レジスタが`xmm`レジスタを拡張するのと同じように、対応する`ymm`レジスタを拡張します。

第二に、これらの拡張は、**オプマスクレジスタ**というまったく新しいクラスも作ります。`k0`から`k7`まであり、その主な目的はSIMD命令のマスクとして機能することです。
比較はもはやベクターではなく、これらの新しいレジスタの1つに書き込みます。
また、多くの命令で`{k}`ライトマスクを付けた述語として直接使え、レーンを_直接_選択できます。

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

最後に、これらの新しいレジスタを操作する新しい命令があり、汎用レジスタへのコピーも含まれます。
これにより`movmsk`命令は不要になり、`zmm`レジスタでは`movmsk`命令がサポートされていません。

これらの拡張は、網羅性のために言及しています。
このトラックの演習ではSSE形式を使います。
