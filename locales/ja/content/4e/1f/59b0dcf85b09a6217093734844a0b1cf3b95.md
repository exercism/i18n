# 説明

ここでの課題は、Smart Game Format（SGF）の文字列を解析し、対局を表すツリー構造のデータを返すことです。

SGF文字列はノードのツリーを表します。ツリー全体は括弧（`()`）で囲まれます。ツリーの各ノードはセミコロン`;`で示され、そのあとにプロパティが続きます。プロパティは、大文字の識別子（例：`AB`）と、それに続く角括弧（`[]`）で囲まれた1つ以上の値から構成されます。

たとえば、文字列`(;FF[4]C[root])`は、ルートノードが1つだけのツリーを表します。このノードには2つのプロパティがあります。
- プロパティ`FF`、値は`4`
- プロパティ`C`、値は`root`

**バリエーション（ツリーと分岐）**
SGFはツリーを入れ子にすることで、対局のバリエーションを表現できます。1つのツリーは複数の子ツリーを持つことができ、それらも括弧で囲まれます。
たとえば、`(;A[B](;C[D])(;E[F]))`は、プロパティ`A`を持つルートノードを表し、このノードには2つの子の枝があります。
1. プロパティ`C`、値`D`を持つノード
2. プロパティ`E`、値`F`を持つノード

**書式とエスケープ**
角括弧の中の値には、エスケープされた文字を含めることができます。バックスラッシュ`\`のあとに任意の文字が続く場合、それはその文字そのものを表します（例：`\]`は文字としての`]`に解析します）。また、改行の前にバックスラッシュがある場合は行の継続を意味するので、値から取り除きます。それ以外の値の中の改行はそのまま保持します。

**エラーの扱い**
無効なSGF文字列に対しては、エラーを投げる必要があります。無効なSGFの例を次に示します。
- ツリーが括弧（`()`）で始まっていない。
- ノードがセミコロン`;`で始まっていない。
- プロパティの識別子が、すべて大文字の英字になっていない。
- 角括弧が欠けている、または括弧の対応が取れていない。

### データ構造

解析用の関数は、ツリーを表すデータを返すようにします。よくあるのは、各ツリーを2つのフィールドを持つオブジェクトとして表す方法です。
- `properties`: キーがプロパティの識別子（文字列）、値が文字列の配列であるオブジェクト（または`Map`）です。プロパティは複数の値を持てるためです。
- `children`: 子ツリーを格納する配列です。


例：

入力：`(;FF[4]C[root])`
出力：`{
  properties: {
    FF: ['4'],
    C: ['root']
  },
  children: []
}`

入力：`(;A[B](;C[D])(;E[F]))`
出力：`{
  properties: {
    A: ['B']
  },
  children: [
    {
      properties: {
        C: ['D']
      },
      children: []
    },
    {
      properties: {
        E: ['F']
      },
      children: []
    }
  ]
}`
