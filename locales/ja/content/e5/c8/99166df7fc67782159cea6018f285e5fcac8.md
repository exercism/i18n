# 概要

リンケージとは、コード内のどこから識別子にアクセスできるかを表します。
ブロックスコープ、関数スコープ、関数プロトタイプスコープをもつ値には、リンケージがありません。
つまり、スコープの外からアクセスすることはできません。
スコープの詳細については、[スコープの概念](../scope/introduction.md#Introduction)を参照してください。

## 外部リンケージ

ファイルスコープをもつ識別子は、デフォルトで外部リンケージをもちます。
外部リンケージをもつ識別子は、プログラム内のどのファイルからでも呼び出すことができます。

## 内部リンケージ

ファイルスコープをもつ識別子は、`static`指定子を使うことで内部リンケージをもたせることができます。
内部リンケージをもつ識別子は、そのファイル内でしか使えません。

たとえば

```c
int public_count = 0; // file scope, external linkage by default
static int private_count = 0;  // file scope, internal linkage 

// file scope, internal linkage
static void some_function()
{
    // code snipped
}

// file scope, external linkage by default
int main()
{
    // code snipped
}
```

静的リンケージと、静的記憶域期間を混同しないようにしましょう。
静的記憶域期間の詳細については、[記憶域期間の概念](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#static-the-storage-specifier-not-to-be-confused-with-the-static-linkage-type)を参照してください。

値（関数ではなく）がヘッダーで宣言されているものの、ソースファイル内で初期化された値をもつ`static`なファイルスコープの識別子として定義されている場合、その初期化された値には、ソースファイルの外からアクセスできません。
コンパイル、リンク、実行はエラーなく通るかもしれませんが、値が`extern`で宣言されていても、その値はその識別子のゼロ値になります。
（`extern`の詳細については、[`extern`の概念](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#extern-how-to-access-a-variable-in-another-translation-unit)を参照してください。）
ソースファイル内で`static`とマークされたファイルスコープの識別子は、そのヘッダーファイルで宣言すべきではありません。
