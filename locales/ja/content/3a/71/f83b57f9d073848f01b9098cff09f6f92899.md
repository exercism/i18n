# はじめに

ポンプ、バルブ、ホース。オペレーティングシステムのリソース（開いているファイルやネットワーク接続など）を握るものは、使い終わったら*解放*しなければなりません。Factorの[`destructors`][destructors]ボキャブラリは、こうしたリソースをフレームワークで包み、コードの途中でエラーが起きても確実に後片付けが行われるようにします。

## クラスと総称関数

クラスは、`disposable`を継承し、`dispose*`総称関数を実装することで、このフレームワークに加わります。

```factor
USING: accessors destructors kernel ;

TUPLE: pump < disposable opened ;

: <pump> ( -- pump )
    pump new-disposable t >>opened ;

M: pump dispose* f >>opened drop ;
```

`new-disposable ( class -- obj )`はタプルを確保し、*同時に*フレームワークへ登録します。確保してから次の安全な地点までの間に例外が起きても、リソースが漏れることはありません。フレームワークは、`dispose*`がオブジェクトごとに**最大1回**だけ実行されることを保証します。`dispose`を何度呼んでも何も起こりません。

## 呼び出し側は`dispose`を使います

```
dispose          ( obj -- )                ! release; safe to call twice
with-disposal    ( disposable quot -- )    ! scope one resource
with-destructors ( quot -- )               ! open a registry scope
&dispose         ( obj -- obj )            ! dispose on normal *or* failure exit
|dispose         ( obj -- obj )            ! dispose only if the scope unwinds
```

`with-disposal`はリソース1つ用の形です。内側のクォーテーションのために`disposable`を積み、終了時に解放します。

```factor
USING: destructors io ;

<pump> [
    "pumping" print
] with-disposal
! pump released on the way out — even if `print` had thrown
```

リソースが2つ以上あるときは、`with-destructors`のスコープを開き、リソースを確保するたびに登録します。`&dispose`（アンパサンド）は「成功しても失敗しても、終了時に必ず解放する」という意味です。`|dispose`（パイプ）は「失敗したときに**だけ**解放する」という意味で、成功したときは所有権を引き継ぐ呼び出し側にリソースを渡したい、という場合に便利です。

```factor
[
    <pump> &dispose
    <pump> &dispose
    ! ... use the pumps ...
] with-destructors
! both pumps released
```

レジストリを使わずにtry/finallyだけを行うなら、[`cleanup`][cleanup]（`continuations`にあります）がより低レベルな基本操作です。ただし、現代のFactorで慣用的なのは`with-destructors`です。
