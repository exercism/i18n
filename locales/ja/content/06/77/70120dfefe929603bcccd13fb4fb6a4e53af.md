# はじめに

正規表現は、そのために設計されたドメイン固有言語（DSL）を使って文字列を_パターンマッチ_する、非常に汎用性の高い方法です。

正規表現の機能の多くはBase Rに組み込まれており、古いコードでその例を見かけることもあるでしょう。

新しいコードでは、[`stringr`][web-stringr]ライブラリを使うことを_強く_おすすめします。

[Stringsの概念][concept-strings]で触れたとおり、`stringr`には、たいていはパッケージの作者によって書かれた、よく整ったドキュメントがあります。

- [リファレンスサイト][web-stringr]
- [チートシート][cheat-stringr]
- 「R for Data Science」の[文字列の章][book-strings]と[正規表現の章][book-regex]

[`Strings`][concept-strings]の概念ですでに説明した関数の多くは、標準で正規表現検索に対応するように作られています。

Stringsの概念では、文字列リテラルのマッチングだけを扱って比較的シンプルに保ちましたが、代わりにどんな正規表現パターンでも使えます。

正式には、Rで正規表現を作るには[`regex()`][ref-regex]を呼び出します。
利便性のため、`stringr`の関数はどんなパターン文字列も正規表現として扱います。
次の例では、1つ目の`str_replace_all()`は2つ目の書き方の糖衣構文です。

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[チートシート][cheat-stringr]は役に立つガイドです。`pattern`引数を持つ関数（赤で印刷されています）はすべて正規表現を受け付け、2ページ目に正規表現の構文がまとめられています。

大文字と小文字の区別やロケールなど、デフォルトを上書きしたい場合には、[`regex()`][ref-regex]関数が依然として重要になることに注意してください。

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

正規表現のコードには、上で使った`\s`のように、バックスラッシュを含むものが多くあります。
通常のRの文字列では、`\`は2つ重ねてエスケープする必要があるため、`"\\s"`と書きます。

バックスラッシュは増えすぎて混乱しがちなので、複雑な場合には[生の文字列][book-raw]を使うとよいでしょう。

デフォルトでは、生の文字列を定義する構文は`r"( )"`ですが、他の区切り文字も使えます。
正規表現の構文では、丸括弧`( )`と角括弧`[ ]`（キャプチャグループとオプショングループに使います）がどちらもよく登場するため、波括弧`{ }`が良い選択かもしれません。

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## マッチの検出

ここでは、いくつかの疑問と、その答えを出すのに役立つ関数を紹介します。

一部の例では、`stringr`に練習用として付属している、80個の果物の名前からなるベクトル`fruit`を使います。

_文字列にマッチは含まれているか？_
`str_detect()`を使います。`^`や`$`のアンカーを使わずに済ませたいなら、`str_starts()`や`str_ends()`を使います。

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_マッチを含む文字列だけを返すには？_
文字列を取得するには`str_subset()`、インデックスを取得するには`str_which()`を使います。

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_各文字列にマッチはいくつあるか？_
`str_count()`を使います。

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_マッチはどこにあるか？_
対話的に使うなら`str_view()`、より一般的には`str_locate()`や`str_locate_all()`を使います。

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## キャプチャ

よくあるのは、_何に_マッチしたのかを知りたい場合です。
これは、正規表現の中の括弧でキャプチャグループを囲むことで実現できます。

同じ正規表現の中で`\1`、`\2`などを使ってキャプチャを後方参照することもできます。
たとえば、同じ文字のペアが繰り返されているものを探すには、次のようにします。

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

よく似た構文で、置換文字列の中でもキャプチャを使えます。

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

後で処理するためにマッチを集めるには、最初のマッチだけなら`str_match()`関数、すべてのマッチなら`str_match_all()`を使います。

キャプチャグループは、どの言語でも複雑な出力になりがちです。
Rでのやり方（_おまけの難しさとして、ベクトル化もされています_）は、`str_match()`から行列を生成するものです。入力文字列ごとに1行、1列目にマッチした文字列全体、残りの列にそれぞれのキャプチャグループが入ります。

名前付きグループを使うと、結果の行列の列名になるので便利です。

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

~~~~exercism/note
このシラバスでは行列についてあまり触れていませんが、参照できる[概念ドキュメント][concept-matrices-arrays]があります。
行列は、長い間Base Rの一部でありながら、Tidyverseのエコシステムとはあまり相性がよくありません。

手短にまとめると、行列は2つのインデックスを持つベクトルのように扱い、順序は`[rows, cols]`です。
どちらかのインデックスを空にすると、行全体または列全体を取得できます。

`m[r,]`で1つの行`r`を、`m[,c]`で1つの列`c`を取得すると、返される値はデフォルトではベクトルに平坦化されます。

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```
~~~~

当然ながら、`str_match_all()`の出力はさらに構造が複雑になります。

- 結果はリストで、入力文字列ごとに1つの要素を持ちます。
- 入力文字列が1つだけの場合は、[Listsの概念][concept-lists]で説明したように、`[[1]]`のインデックス指定で出力をunlistします。
- 各要素は行列で、列は`match()`の場合と同じです。
- 行列の各行が、成功したキャプチャです。

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

もちろん、マッチは失敗することもあります。
その場合の結果は特別な値`NA`になります。
[Nothingnessの概念][concept-nothingness]で説明したように、これに備えてテストできるようにしておきましょう。

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
