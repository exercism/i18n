# テスト
Exercismの演習を解く方法のひとつは、Webサイトにアクセスし、ブラウザー内のエディターで解答を編集してテストするというものです。

もうひとつの方法は、演習を自分のコンピューターにダウンロードし、好きなエディターと一連のツールを使って、解答を作成し、テストし、最後に提出するというものです。

この方法では、Exercismのコマンドラインインターフェース（CLI）を使います。これはターミナル、つまりコマンドラインウィンドウの中で動くアプリケーションです。インストール方法はこちらにあります：[Exercism CLIのドキュメント](https://exercism.org/docs/using/solving-exercises/working-locally)。

## テストの進め方
Exercismでは、テスト駆動開発の経験がある程度あることを前提としています。各演習は、_`stub file`_、あらかじめ書かれた一連のテストを含む_`test file`_、そしてテストを実行するための_`test script`_で構成されています。

演習を解くには、_`stub file`_を少しずつ育てていき、最終的にすべてのテストに通るコードに仕上げていく必要があります。

実際には、_`stub file`_と_`test file`_の両方を頻繁に編集することになります。ここで_`test file`_を編集するのはテストコードを変えるためではなく、失敗するテストをコメントアウトするためです。

最初は1つを除くすべてのテストがコメントアウトされています。そこから_`stub file`_を動く解答へと近づけていくにつれて、コメントアウトを解除するテストを増やし、最終的にすべてのテストが通るようにします。

## テスト環境
テストフレームワークの構成要素は演習のダウンロードに含まれているので、追加のソフトウェアをインストールする必要はありません。

テストフレームワークは3つのRexxファイルで構成されています。テスト時にこれらが演習の解答と組み合わされてテストコードの単位をつくり、それが_`test script`_によって実行され、テスト結果がターミナルに表示されます。

_`test script`_やその他のテストフレームワークのファイルは、編集したり削除したりしないでください。もし何かの拍子にそうなってしまった場合は、解答のコードを保存したうえで、Exercism CLIを使って演習をダウンロードし直してください。

## テストを実行する
演習を解く手順は次のとおりです。

1. ターミナルを開きます
2. 選んだ演習をダウンロードします
3. 演習のディレクトリに移動します
4. スタブファイルとテストファイルをエディターに読み込みます
5. 次のことを繰り返します

    1. テストスクリプトを実行します
    2. スタブファイルにコードを書き（少しずつ解答ファイルに変わっていきます）、テストファイルのテストをコメントアウトしたり、コメントアウトを解除したりします

6. すべてのテストに通ったら、解答をExercismに提出します
7. ターミナルを閉じます
8. 自分の成功を祝いましょう

`acronym`演習を使った、Linuxのターミナルでの具体的な例です（exercismのワークスペースは`/home/exercism`にあるとします）

演習をダウンロードします：

`exercism download --track=rexx --exercise=acronym`

演習のディレクトリに移動します：

`cd /home/exercism/rexx/acronym`

別のウィンドウ（GUIでもかまいません）で、`acronym.rexx`と`acronym-check.rexx`を、それぞれスタブファイルとテストファイルとしてエディターに読み込みます。

テストスクリプトを実行します：`./test-acronym`

すると、すべてのテストが失敗するはずです：

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

`acronym-check.rexx`ファイルで最初のテスト以外をすべてコメントアウトし、テストスクリプトをもう一度実行します。すると、次のような出力になるはずです：

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

`acronym.rexx`を、動くコードになるまで書き直します。やがて、テストスクリプトを実行したときの出力は次のようになるはずです：

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

続けて、残りのテストのコメントアウトを解除し、テストスクリプトをもう一度実行します。最終的な出力は次のようになるはずです：

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

これで、演習の解答を提出できます：

`exercism submit acronym.rexx`

またレピュテーションポイントを獲得できます。終わったらターミナルを閉じましょう。

MacOSを使っている場合も、UNIXを起源とするオペレーティングシステムなので、ほぼ同じ手順になります。

Windowsを使っている場合もだいたい同じですが、いくつか細かい違いがあります。

- ターミナルにあたるのは_Command Prompt_ウィンドウです
- パスではスラッシュの代わりにバックスラッシュを使うので、作業ディレクトリは次のようになります

  `cd C:\Users\MyName\exercism\rexx\acronym`

- テストスクリプトの実行方法は次のとおりです

  `test-acronym`、または`test-acronym.bat`

テストの出力は同じになります。
