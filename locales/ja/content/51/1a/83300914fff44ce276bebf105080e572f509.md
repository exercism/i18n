# `match`の基本

`match`式を使うと、ある値を一連のパターンと簡単に比較し、マッチしたパターンに応じてコードを実行できます。パターンは、リテラル値、変数名、ワイルドカードなど、さまざまな要素から成り立っています。

```rust
#[derive(Drop)]
enum Color {
    Red,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red => println!("The color is Red"),
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Yellow;
    print_color_type(color); // prints "The color is Yellow"
}
```

複数行のコードを扱うには、`match`のアームを波括弧（`{}`）で囲みます。

```rust
fn specified_color(color: Color) -> felt252 {
    let mut response: felt252 = '';

    match color {
        Color::Red => {
            response = 'You passed in Red';
        },
        Color::Yellow => {
            response = 'You passed in Yellow';
        },
        Color::Green => {
            response = 'You passed in Green';
        },
    }

    response
}
```

`match`式には、パターンにマッチした値に束縛する機能もあります。これにより、列挙型のバリアントに関連付けられた値を取り出せます。

```rust
#[derive(Drop, Debug)]
enum ColorType {
    Light,
    Dark,
}

#[derive(Drop)]
enum Color {
    Red: ColorType,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red(state) => {
            println!("The color is Red");
            println!("The Color Type is {:?}", state);
        },
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Red(ColorType::Dark);
    print_color_type(color);
}
```

`Color`列挙型の`Red`バリアントを拡張して、関連する列挙型を持たせています。`match`式の助けを借りて、関連付けられた値である`state`を取り出せます。これは単なる変数名で、そのあとのアームのコードで使うことができます。

## `Option`列挙型のマッチング

組み込みの`Option`列挙型も、`match`式で扱えます。

`Option<u8>`を引数に取る関数を設計してみましょう。与えられた引数に値があれば、その値に1を足します。なければ、何も操作せずに`None`を返します。

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
        Option::None => Option::None,
    }
}

fn main() {
    let three: Option<u8> = Option::Some(3);
    let four: Option<u8> = add_one(three);
    let none = add_one(Option::None);

    println!("{three:?}"); // prints "Option::Some(3)"
    println!("{four:?}"); // prints "Option::Some(4)"
    println!("{none:?}"); // prints "Option::None(())"
}
```

> 注: `{:?}`は特別な書式指定構文で、`println!`マクロに渡された引数をデバッグ形式で出力できます。
> 詳しくは[The Cairo Book][debugging]を参照してください。

`match`制御フローを使う利点の1つは、その網羅性です。アームのパターンは、_すべて_の可能性をカバーしなければなりません。`None`の場合を処理していない、先ほどの例のバージョンを見てみましょう。

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
    }
     // this code does not compile, as we forgot to handle the `None` case
}
```

## `_`ワイルドカードによるすべてにマッチするパターン

列挙型を使うと、いくつかの特定の値に対してだけ特別な処理を行い、それ以外のすべての値に対しては1つのデフォルトの処理を行うことができます。そのためには、`match`式の最後のアームとして、パターンに`_`を使った新しいアームを追加します。`_`パターンは、どんな値にもマッチし、その値に束縛しない特別なパターンです。

`is_red`関数は引数を受け取り、色が`Red`なら`true`を、それ以外の色なら`false`を返します。

```rust
fn is_red(color: Color) -> bool {
    match color {
        Color::Red => true,
        _ => false,
    }
}
```

## `|`演算子によるパターンマッチング

Cairoの`match`制御フロー構文を使うと、`|`（_or_）演算子で1つの値を複数のパターンとマッチングできます。これによりコードを簡潔にできます。

たとえば、`Color`列挙型を使って、`Red`または`Green`の色に対して`true`を、それ以外の色に対して`false`を返す関数を書きたいとします。

```rust
fn is_red_or_green(color: Color) -> bool {
    match color {
        Color::Red | Color::Green => true,
        _ => false,
    }
}
```

## `felt252`と整数変数によるパターンマッチング

`felt252`や整数変数を一連の値とマッチングすることも可能です。ただし、いくつかの制約があります。

- 単一の`felt252`に収まる整数だけをサポートします（つまり、`u256`はサポートされません）。
- 0が最初のアームでなければなりません。
- 各アームは、他のアームと連続した、連番のセグメントに従わなければなりません。

6面サイコロを振るゲームを実装してみましょう。このサイコロを振ると、0から5の数値が得られます。0、1、2が出たら勝ちです。3ならもう一度振れます。それ以外の値なら負けです。

```rust
fn toss(value: u8) {
    match value {
        0 | 1 | 2 => println!("you won!"),
        3 => println!("you can roll again!"),
        _ => println!("you lost...")
    }
}

fn main() {
    toss(2); // prints "you won!".
    toss(3); // prints "you can roll again!".
    toss(5); // prints "you lost...".
}
```

## タプルのマッチング

タプルも一連のパターンとマッチングできます。これらのパターンも、タプルと同じように書きます。

```rust
#[derive(Drop)]
enum DayType {
    Week,
    Weekend,
    Holiday
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn vending_machine_accept(c: (DayType, Coin)) -> bool {
    match c {
        (DayType::Week, _) => true, // accepts all coins during week day
        (_, Coin::Dime) | (_, Coin::Quarter) => true, // accepts only Dime or Quarter coin for all specified days
        (_, _) => false, // returns false for other instances
    }
}
```

最後のアームでは、任意の曜日と色の組み合わせにマッチさせるのに`(_, _)`を使っても、単に`_`ワイルドカードを使ってもかまいません。機能的に同じだからです。
