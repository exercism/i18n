# はじめに

正規表現は、文字列を_パターンマッチ_するための非常に汎用性の高い方法で、そのために設計されたドメイン固有言語（DSL）を使います。

正規表現の機能の多くはBase Rに組み込まれており、古いコードでその例を見かけることがあります。

新しいコードでは、[`stringr`][web-stringr]ライブラリを使うことを_強く_おすすめします。

[Stringsのコンセプト][concept-strings]で触れたように、`stringr`には優れたドキュメントがあり、たいていはパッケージの作者自身によって書かれています。

[`Strings`][concept-strings]のコンセプトですでに取り上げた関数の多くは、標準で正規表現検索向けに設計されています。

Stringsのコンセプトでは、文字列リテラルにだけマッチするようにして、比較的シンプルに保ちましたが、代わりにどんな正規表現パターンでも使えます。

正式には、Rで正規表現は[`regex()`][ref-regex]を呼び出して作成します。
利便性のため、`stringr`の関数はどんなパターン文字列も正規表現として扱います。
次の例では、1つ目の`str_replace_all()`が2つ目の書き方の糖衣構文になっています：

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[チートシート][cheat-stringr]は役に立つガイドです。`pattern`引数を持つ関数（赤色で印刷されています）はすべて正規表現を受け付け、2ページ目には正規表現の構文がまとめられています。

大文字と小文字の区別やロケールなど、デフォルトを上書きする必要がある場合には、[`regex()`][ref-regex]関数がやはり重要になることを覚えておきましょう。

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

正規表現のコードには、上で使った`\s`のようにバックスラッシュを含むものが多くあります。
通常のRの文字列では、`\`は2つ重ねてエスケープする必要があるため、`"\\s"`と書きます。

バックスラッシュはどんどん増えて混乱しやすいので、複雑な場合は[生の文字列][book-raw]を使うとよいでしょう。

デフォルトでは、生の文字列を定義する構文は`r"( )"`ですが、他の区切り文字も使えます。
正規表現の構文では丸括弧`( )`も角括弧`[ ]`もよく使われるため（キャプチャグループとオプショングループ）、波括弧`{ }`を選ぶとよいかもしれません。

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## マッチの検出

ここでは、いくつかの疑問と、その答えを導くのに役立つ関数を紹介します。

いくつかの例では、練習用に`stringr`に含まれている、80個の果物名からなるベクトル`fruit`を使います。

_文字列にマッチが含まれているか？_
`str_detect()`を使います。`^`や`$`のアンカーを使うのを避けたい場合は、`str_starts()`や`str_ends()`を使います。

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_マッチを含む文字列だけを返すには？_
文字列を取得するには`str_subset()`、インデックスを取得するには`str_which()`を使います。

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_各文字列にマッチはいくつあるか？_
`str_count()`を使います。

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_マッチはどこにあるか？_
対話的に使うなら`str_view()`、より一般的には`str_locate()`や`str_locate_all()`を使います。

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## キャプチャ

多くの場合、何がマッチしたのかを知りたくなります。
これは、正規表現の中に丸括弧でキャプチャグループを書くことで実現できます。

同じ正規表現の中で`\1`や`\2`などを使ってキャプチャを後方参照することもできます。
たとえば、繰り返し現れる文字のペアを見つけるには次のようにします：

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

よく似た構文で、キャプチャは置換文字列の中でも使えます：

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

後で処理するためにマッチを集めるには、最初のマッチだけなら`str_match()`関数、すべてのマッチなら`str_match_all()`を使います。

キャプチャグループは、どの言語でも複雑な出力になりがちです。
Rでのアプローチ（_さらに、追加の課題としてベクトル化もされています_）は、`str_match()`から行列を生成するというものです。入力文字列ごとに1行、1列目にはマッチした文字列全体、残りの列にはそれぞれのキャプチャグループが入ります。

名前付きグループを使うと、結果の行列の列名になるという利点があります。

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

このシラバスでは行列についてあまり説明していませんが、参照できる[コンセプトのドキュメント][concept-matrices-arrays]があります。
行列は、長いあいだBase Rの一部でありながら、Tidyverseのエコシステムとはあまり相性がよくありません。

手短にまとめると、行列は2つのインデックスを持つベクトルのように扱い、順序は`[rows, cols]`です。
どちらかのインデックスを空にすると、その行や列全体を取得できます。

`m[r,]`で単一の行`r`を、`m[,c]`で単一の列`c`を取得すると、返される値はデフォルトではベクトルに平坦化されます。

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

当然ながら、`str_match_all()`の出力はさらに複雑な構造になります：

- 結果はリストで、入力文字列ごとに1つの要素を持ちます。
- 入力文字列が1つだけの場合は、[Listsのコンセプト][concept-lists]で説明されている`[[1]]`のインデックスで出力をunlistします。
- 各要素は行列で、列は`match()`の場合と同じです。
- 行列の各行は、成功した1つのキャプチャです。

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

もちろん、マッチは失敗することもあります。
その場合、結果は特別な値`NA`になります。
[Nothingnessのコンセプト][concept-nothingness]で説明されているように、これに備えてテストできるようにしておきましょう。

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
