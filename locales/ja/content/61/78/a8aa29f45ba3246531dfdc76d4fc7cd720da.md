# 真偽値

`BOOL`は、`true`と`false`という2つの値のどちらかを保持します。

```sather
   ready : BOOL is
      return true;
   end;
```

## 比較

| 演算子 | 問いかけること | 例 |
| --- | --- | --- |
| `=` | 同じ？ | `age = 13` |
| `/=` | 違う？ | `age /= 13` |
| `<` | より小さい | `age < 13` |
| `<=` | 以下 | `age <= 13` |
| `>` | より大きい | `age > 13` |
| `>=` | 以上 | `age >= 13` |

これらは数値に対して使えます。`=`と`/=`は文字列にも使えます。

## 3つの演算子

| 演算子 | 書き方 | 真になるのは |
| --- | --- | --- |
| and | `a and b` | 両方が真のとき |
| or | `a or b` | 少なくとも一方が真のとき |
| not | `~a` | `a`が偽のとき |

`and`と`or`は**短絡評価**を行います。`a`が偽だとわかった時点で、`a and b`は`b`を見に行きません。答えはすでに決まっているからです。同じように、`a or b`も`a`が真ならそこで止まります。右側の式の評価にコストがかかるときや、実行するとおかしなことになるときには、この性質が重要になります。

## 比較をそのまま返す

問いかけること自体が役目であるルーチンは、条件分岐で答えを選ぶのではなく、その問いかけの結果をそのまま返すべきです。

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

`if age >= 13 then return true else return false end`と書くのは、比較がすでに言っていることを3行かけて言い直しているだけで、経験ある読み手なら誰でも気づきます。

## 優先順位

`~`が最も強く結びつき、次に`and`、その次に`or`です。つまり

```sather
~a and b or c
```

は`((~a) and b) or c`という意味になります。括弧（`()`）を書くのに手間はかかりません。読み手がその順序を思い出さないと行を追えない、という状況では、括弧を書く価値があります。
