# はじめに

手書きのアセンブリは、繰り返しだらけです。同じ短い命令の並びが、ほとんど変化もなく何度も現れますが、定型コードを減らしてくれる抽象化はほとんどありません。それだけでなく、アセンブリでコードを書くときは、意味のはっきりしない値を自分で管理しなければなりません。名前の付いた仮引数はなく、土台となる仕組みの細かな部分のほとんどは、プログラマーが手作業で扱う必要があります。

トラックで使われているアセンブラーであるNASMには、この2つの問題の解決に役立つツールがいくつか用意されています。これらのツールは、まだ命令がプロセッサーに届く前、つまり_アセンブル時_に動きます。ソーステキストが機械語に翻訳される前に、それをどう書き換えるべきかをアセンブラーに指示するのです。

こうしたツールの中で最も重要なのが**マクロ**で、アセンブラーにとってのレシピのようなものだと考えられます。マクロは使われた場所で展開され、まるでそこに手書きでコードを書いたかのように扱われます。

マクロは、いくつかのリテラルトークンを仮引数として受け取ることができ、さまざまな場面で再利用できます。ただし、マクロは関数ではありません。`call`も`ret`もなく、コード内の別の場所へ制御を移すこともありません。

## 1行マクロ

最も単純な定義は、`%define`を使って値や短い式に名前を付けるものです。

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

それ以降に現れる`WIDTH`はすべて、アセンブル前に`8`へ置き換えられます。この置き換えはテキストとして行われるので、オペランドの中でも、別の定義の中でも、その名前が現れる場所はどこでも置き換えられます。

~~~~exercism/note
数値の_定数_には、`%define`よりも`equ`を使うのがおすすめです。

`%define`で宣言した1行マクロは、使われたときにだけ展開され、再定義したり未定義にしたりできます。一方、`equ`の定数は定義した時点で評価され、あとから変更されることはありません。
~~~~

`%define`では、_名前付きの_仮引数を取ることもでき、小さなインライン関数のように振る舞います。

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
マクロ本体と各仮引数の両方を、括弧で囲んでください。`%define square(x) x*x`の場合、`square(1+1)`という呼び出しは`1+1*1+1`に展開され、これは`3`になります。`%define square(x) ((x)*(x))`と書けば、同じ呼び出しは`((1+1)*(1+1))`に展開され、これは`4`になります。
~~~~

`%define`で定義した名前は、大文字と小文字を区別します。必要であれば、`%idefine`という書き方を使うと、名前の大文字と小文字を区別しないようにできます。

1行マクロは、コードのさまざまな部分に意味を持たせるのに役立ちます。注意して使えば、読みやすさが上がり、打ち間違いの可能性も減ります。たとえば、関数の中で専用の役割を持つレジスターは、その役割を表す名前で定義するとよいでしょう。

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## 複数行マクロ

何行にもわたるコードの並びは、`%macro`でとらえ、`%endmacro`で閉じます。名前のあとの数字は、そのマクロが受け取る引数の数を表し、0にすることもできます。引数を渡すときは、カンマ（`,`）で区切ります。

```x86asm
%macro example_macro 0
...
%endmacro
```

複数行マクロの引数には名前がありません。渡された順に、`%1`、`%2`…として参照します。

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

引数は、マクロ本体で行われる操作に対して有効な構文でなければならない点に注意してください。ここでは`mult_two eax, ecx`と`mult_two r8, r9`はどちらもアセンブルできますが、`mult_two eax, cl`はアセンブルできません。`imul eax, cl`が定義されていないからです。

### マクロ内のラベル

普通のラベルを定義するマクロは、2回使われた時点で壊れてしまいます。ラベルも2回定義されることになるからです。複数回呼ばれる可能性のあるマクロの中でラベルを使うには、そのラベルに`%%`を付ける必要があります。こうすると、展開のたびに異なる一意な名前をそのラベルに付けるよう、アセンブラーに指示できます。

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## アセンブル時の繰り返し

`times`を使えば、1行のコードを繰り返すことができます。これは、メモリー内で同じ値を繰り返し宣言するときに特に便利です。

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

複数行のコードを繰り返すときは、代わりに`%rep`を使います。

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

繰り返しの回数は`%rep`のすぐあとに指定し、繰り返すブロックは`%endrep`で閉じる点に注意してください。

`%rep`ブロックの中では、実行時のループがカウンターを使うのと同じように、アセンブル時のカウンターを使うことがよくあります。アセンブル時の整数定数は`equ`で宣言できますが、アセンブル時の整数_変数_には、代わりに`%assign`を使います。`%define`と違って、`%assign`はすぐに数値として評価され、再代入もできます。

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

プリプロセッサーが動いたあとには、ループは消え、4つの`add`命令だけが残ります。即値`0`、`1`、`2`、`3`はそのまま埋め込まれています。これはアセンブラーが行うループ展開で、カウンター用のレジスターも分岐もなく、ただまっすぐに並んだコードだけになります。

## 条件付きアセンブル

プリプロセッサーには、さまざまな条件付きの仕組みが用意されています。これらは複数の異なる経路から1つを選び、条件が真のときにだけ、その本体をその場に展開します。

`%if` ... `%elif` ... `%else` ... `%endif`は、数値のテストに基づいて分岐を選びます。

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## ファイルに分割する

マクロは、専用のファイルにまとめておき、必要なソースそれぞれに`%include`で取り込むことがよくあります。

```x86asm
%include "patterns.mac"
```

指定したファイルは、アセンブル前にその場所へそのまま挿入されます。まるでその内容をそこに直接書いたかのようです。こうすると、定義を1か所にまとめたまま、複数のソースファイルで共有できます。

マクロファイルを単体でアセンブルする可能性があるなら、拡張子は`.asm`にしておきましょう。マクロにはリンケージがない点に注意してください。マクロファイルをアセンブルしても、そのマクロは、`%include`した別のファイルからしか見えません。

そうでなければ、`%include`されるだけのファイルは、拡張子が何であってもかまいません。`.asm`と`.mac`のどちらかを使うのが、よくある慣習です。
