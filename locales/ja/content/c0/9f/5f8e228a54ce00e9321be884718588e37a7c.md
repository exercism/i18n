# 指示

ラジコンカーのプロジェクトは続いています。テレメトリシステムの帯域はひっ迫しているため、テレメトリデータをやり取りするためのメッセージプロトコルを実装することになりました。

データはバッファ（バイト配列）で送信されます。整数を送るときは、以下で説明するプロトコルを使うことで、バッファのサイズを小さくできます。

それぞれの値は、できるだけ小さい整数型で表現します（`byte`と`sbyte`型は、節約できる量がごくわずかなので含まれていません）：

| 下限                       | 上限                      | 型       |
| -------------------------- | ------------------------- | -------- |
| 4_294_967_296              | 9_223_372_036_854_775_807 | `long`   |
| 2_147_483_648              | 4_294_967_295             | `uint`   |
| 65_536                     | 2_147_483_647             | `int`    |
| 0                          | 65_535                    | `ushort` |
| -32_768                    | -1                        | `short`  |
| -2_147_483_648             | -32_769                   | `int`    |
| -9_223_372_036_854_775_808 | -2_147_483_649            | `long`   |

値は、割り当てられた型に応じたバイト数に変換します。バッファ全体は、バッファ内の追加バイト数を示す1バイト（_プレフィックスバイト_）と、そのあとに続く整数を保持するバイト列（_ペイロードバイト_）で構成されます。

型によっては、同じバイト数を使うものもあります（たとえば`uint`型と`int`型）。通常なら、どちらも同じ_プレフィックスバイト_になりますが、それではデコードがややこしくなってしまいます。そこで、このプロトコルにはちょっとした工夫があります。符号付きの型では、_プレフィックスバイト_の値は`256`からバッファ内の追加バイト数を引いた値になります。

通信で送信されるのは、プレフィックスバイトと、そのプレフィックスが示す数の後続バイトだけです。内部的には、送信ルーチンも受信ルーチンも、（必要に応じて末尾にゼロを付けた）9バイトのバッファを使います。

## 1. 送信できるように整数値をエンコードする

メソッドに渡された値をバッファにエンコードする、静的メソッド`TelemetryBuffer.ToBuffer()`を実装してください。

```csharp
// Type: ushort, bytes: 2, signed: no, prefix byte: 2
TelemetryBuffer.ToBuffer(5)
// => {0x2, 0x5, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0 };

// Type: int, bytes: 4, signed: yes, prefix byte: 256 - 4
TelemetryBuffer.ToBuffer(Int32.MaxValue)
// => {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 };
```

## 2. 受信したバッファをデコードする

受信したバッファをデコードし、その値を`long`の形で返す、静的メソッド`TelemetryBuffer.FromBuffer()`を実装してください。

```csharp
TelemetryBuffer.FromBuffer(new byte[] {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 })
// => 2147483647
```

プレフィックスバイトが想定外の値だった場合は、`0`を返します。
