# はじめに

[`Nothingness`][concept-nothingness]の概念で見たように、Rには、存在しないデータ（`NULL`）、不明なデータ（`NA`）、数学的に無効なデータ（`NaN`、`Inf`）を表すさまざまな方法があります。
一般に、Rはこれらを使って問題をその場で知らせ、例外を発生させずに処理を続けようとします。

## `stop()`

なかには、プログラムを続行させるには根本的すぎる問題もあります。
そのような場合は、`stop(msg)`を使って`Error`とともにプログラムを直ちに停止し、`msg`を表示します。

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

他の言語の`assert`に似ていて、`stop()`の便利なラッパーです。
カンマで区切った任意の数の真偽値の条件を渡すことができ、それらがすべて`TRUE`のときだけプログラムが続行します。

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

Rには、エラーを扱うためのさまざまな方法があります。
それらはCommon Lispを基にしており、多くの一般的な言語とは大きく異なります。

もっとも簡単なのは、問題が起きそうなコードを`try()`で包む方法です。

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()` と `message()`

これらは致命的ではない状況への対応で、たとえば次のようなときに使います。

- プログラムが少なくとも部分的には復帰できるような問題を警告するとき。
- 長時間実行されるプログラムの進捗をユーザーに知らせるとき。

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

`suppressWarnings()`関数は、Exercismの中でもときどき役に立ちます。不要な出力でテストランナーを混乱させないようにできるからです。
