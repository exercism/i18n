# 概要

`<dlist>`（[`dlists`][dlists]にあります）は、新しい双方向連結リストを作ります。操作は[`deques`][deques]にあり、[両端キューのプロトコル][deque-protocol]でディスパッチするので、ほかのコンテナ（主に`<dlist>`）もこれらの操作を実装できます。

| ワード            | 効果                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`：新しい空の両端キュー  |
| `push-front`    | `( elt deque -- )`：先頭に追加します |
| `push-back`     | `( elt deque -- )`：末尾に追加します  |
| `pop-front`     | `( deque -- elt )`：先頭から取り除きます |
| `pop-back`      | `( deque -- elt )`：末尾から取り除きます  |
| `peek-front`    | `( deque -- elt )`：取り除かずに先頭を読みます |
| `peek-back`     | `( deque -- elt )`：取り除かずに末尾を読みます  |
| `deque-empty?`  | `( deque -- ? )`：両端キューは空ですか？ |
| `dlist-length`  | `( dlist -- n )`：要素数 |

push/popの操作はすべて、その場で両端キューを書き換えます。両端キューをルーチンに渡し、あとでまた読み取るのが普通の使い方です。

## スタックとキュー

よく使われるディスパッチのパターンは2つあります。

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

LIFOの順序さえあればよいなら、`mutation`の`push`と`pop`を備えたベクターが適しています。`<dlist>`には連結リストのオーバーヘッドがあるからです。*両端*でO(1)が必要なときに`<dlist>`を選びます。これはほとんどの場合、FIFOキューが目的です。

## 幅優先探索のパターン

幅優先探索は、FIFOの代表的な使い方です。

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

両端キューが探索のフロンティアを担い、ハッシュセットが重複排除を担います。`pop-front`を`pop-back`に置き換えると、同じ形が深さ優先になります。

## `MEMO:`：自動キャッシュ

BFSがノードごとに行う検索が高コストになることがあります。Factorには[`MEMO:`][memo-decl]があり、これは`:`の代わりに使えて、ワードの結果をその入力にひもづけて自動でキャッシュします。

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

`MEMO:`ワードは、ある入力に初めて出会ったときに本体を実行し、それ以降はキャッシュした結果を返します。キャッシュはイメージが存続する間だけ保持され、時間やサイズに基づく破棄はありません。入力が有限で扱いやすい集合に収まる純粋関数に使います。
