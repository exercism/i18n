# はじめに

「シーケンスの各要素に対してこれを実行する」という形では書けないループもあります。条件が切り替わるまで動かし続けなければならないケースです。Factorの`while`コンビネーターがそのための道具です。述語クオーテーションが「続ける？」を判断し、本体クオーテーションが1ステップ分の処理を行い、`while`は述語が`f`を返すまで繰り返します。

## `while`と`until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred`と`body`はどちらもデータスタックを操作するクオーテーションです。`while`は`pred`が真とみなせる値を残す間、ループを続けます。`until`はその逆で、`pred`が真になる*まで*ループを続けます（つまり、`pred`が`f`を残す間です）。

状態を1つだけ、述語と本体の間でスタックに載せて受け渡すこともできます。

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

動作を追ってみましょう。述語`dup 0 >`は実行中のカウンターをのぞき見ます。本体`dup . 1 -`はそれを表示してデクリメントします。ループはカウンターが`0`に達すると止まります。末尾の`drop`は、その最後の`0`をスタックから捨てます。

## `while*`：述語の値を受け取る

```
while* ( pred body -- )
```

`while`は、述語が真の値を残したかどうかしか気にしません。本体を実行する前に、その値そのものは捨ててしまいます。それに対して`while*`は、*その値を本体に渡します*。テストと本体が同じ計算結果を必要とする場面、たとえば検索、マッチ、パース済みのトークンなどで使うとよいでしょう。

ここでは、各名前がチェーンの中で次の名前を指しています。述語が現在の名前を検索し、次の名前がある限り、`while*`はそれを本体に渡します。本体はその名前を表示して、そこから処理を続けます。

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at`は次の名前を返します。名前に対応する項目がなければ`f`を返します。名前が返されている間、`while*`はその名前を`dup .`に渡します。`dup .`はそれを表示し、次の検索のキーとしてスタックに残します。最初の`f`でループが止まります。`while*`はそれを捨てるので、余分なものは何も残りません。

## ローカル変数で複数の状態を扱う

ループが複数の値（たとえば、残りのリストと累計）を扱うようになると、スタックの操作が煩雑になります。最もすっきりしたパターンは、`::`で*ローカル変数*を宣言することです。

```
:: word ( inputs -- outputs ) ... ;
```

本体の中では、`:> name!`が書き換え可能なローカル変数を追加します。読み取りには`name`を使い、書き込みには`name!`を使います（`name!`はスタックから新しい値を取り出して代入します）。

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

ここでは2つのローカル変数（`rest`と`running`）がループ全体の状態を担っています。述語がそれらを調べ、本体がそれらを更新し、最後に最終的な値が戻り値として返されます。

`unclip ( seq -- rest first )`はシーケンスの最初の要素を取り出します。ループが1回の繰り返しごとにリストを1要素ずつ消費したいときに便利です。`[ rest! ] dip`という形は、`rest`を残りの部分に更新しつつ、取り出したばかりの要素を本体が使えるようにスタックに残します。
