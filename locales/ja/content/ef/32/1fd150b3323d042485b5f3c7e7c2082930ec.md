# はじめに

Factorのスレッドは*協調的コルーチン*です。1つのOSスレッドを共有し、入出力のときや明示的にyieldする箇所で互いに制御を渡し合い、本当に同時に動くことはありません。yieldの*間*に行う処理は、1つの途切れないステップとして実行されます。しかし、複合的な操作（読み取り・変更・書き込み）の途中でyieldが起きると、別のスレッドが割り込んで、処理が終わる前に状態を変えてしまうことがあります。これが競合状態です。

この演習では、何度も出てくる4つの基本要素を扱います。

## `parallel-map`：シーケンスに対するfork/join

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

[`concurrency.combinators`][combinators]にあります。要素ごとに1つのスレッドを起動し、そのクォーテーションを実行して、結果を同じ順序の新しいシーケンスにまとめます。

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`：スレッドを開始する

```
spawn ( quot name -- thread )
```

[`threads`][threads]にあります。クォーテーションは並行に実行されます。`name`はデバッグ用のラベルです。返ってくるスレッドのハンドルは、この段階ではほとんど気にする必要がありません。`drop`しておきましょう。

## プロミス：一度きりの値の受け渡し

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

[`concurrency.promises`][promises]にあります。プロミスは一度きりのメールボックスです。1つのスレッドが値を入れ、ほかのスレッドがそれを読み取ります。`?promise`は、プロミスに値が入れられるまでブロックし、そのあと値を返します。

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

`spawn`と`<promise>`は、`parallel-map`の土台になっている仕組みです。それぞれのタスクが「要素を1つ計算する」以外のことをする場合は、これらを自分で組み立てると役立ちます。

シーケンスに対する典型的なfan-out/joinの形は、次のとおりです。入力ごとに新しいプロミスを作り、実際の処理を行ってそのプロミスを`fulfill`するスレッドを起動し、すべてのプロミスを1つのシーケンスにまとめ、最後に各プロミスを`?promise`して完了を待ちます。Localsを使うと、これを読みやすく書けます。`[| | ]`ラムダの中で`:>`を使ってプロミスに名前を付けると、起動したクォーテーションがそのプロミスをクロージャとして取り込めるようになります。

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## ロック：相互排他

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

[`concurrency.locks`][locks]にあります。あるロックを同時に持てるスレッドは1つだけです。`with-lock`はロックを取得してクォーテーションを実行し、クォーテーションが例外を投げた場合でも、最後にロックを解放します。

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

ある値を*複数のスレッドから読み書きする*場合で、その値に対する操作がもともとアトミックでないときは、ロックを使ってください。読み取りにも書き込みにもロックが必要です。読み取りの途中でyieldが起きると、中途半端な状態が見えてしまうことがあります。
