# デバッグ

多くのプログラミング言語とは異なり、WebAssemblyのコードはコンソールのようなグローバルリソースに自動的にアクセスできません。そうした機能は、代わりにインポートとして用意する必要があります。

`console.log`のような機能や、そのほかいくつかの便利な機能を提供するために、ExercismのWebAssemblyトラックでは、すべての演習で使える関数の標準ライブラリを公開しています。

これらの関数は、WebAssemblyモジュールの先頭でインポートする必要があり、その後、WebAssemblyのコードの中から呼び出すことができます。

`log_mem_*`の関数は、WebAssemblyモジュールの線形メモリにアクセスできることを前提としています。デフォルトでは、これはプライベートな状態です。そのため、アクセスできるようにするには、線形メモリをエクスポート名`mem`でエクスポートする必要があります。次のように書きます。

```wasm
(memory (export "mem") 1)
```

# ローカル変数とグローバル変数のログ出力

WebAssemblyのプリミティブ型それぞれについて、ログ出力用の関数を用意しています。グローバル変数やローカル変数のログ出力に便利です。

## log_i32_s - 32ビット符号付き整数をコンソールにログ出力する

```wasm
(module
  (import "console" "log_i32_s" (func $log_i32_s (param i32)))
  (func $main
    ;; logs -1
    (call $log_i32_s (i32.const -1))
  )
)
```

# 線形メモリからのログ出力

WebAssemblyの線形メモリは、バイト単位でアドレス指定できる値の配列です。これは、WebAssemblyプログラムにとっての仮想メモリに相当するものです。

線形メモリ内の一定範囲のアドレスを、特定の型の静的配列として解釈するためのログ出力用関数を用意しています。これはJavaScriptのTypedArrayに似た働きをします。長さのパラメータはバイト数ではなく、その関数に対応する型の要素が連続する個数で表されます。

**これらの関数が動作するには、WebAssemblyモジュールが線形メモリを宣言し、名前付きエクスポート`"mem"`でエクスポートする必要があります。**

```wasm
(memory (export "mem") 1)
```

## log_mem_as_utf8 - UTF8文字の並びをコンソールにログ出力する

```wasm
(module
  (import "console" "log_mem_as_utf8" (func $log_mem_as_utf8 (param $byteOffset i32) (param $length i32)))
  (memory (export "mem") 1)
  (data (i32.const 64) "Goodbye, Mars!")
  (func $main
    ;; Logs "Goodbye, Mars!" to console
    (call $log_mem_as_utf8 (i32.const 64) (i32.const 14))
  )
)
```

## log_mem_as_i8 - 符号付き8ビット整数の並びをコンソールにログ出力する

```wasm
(module
  (import "console" "log_mem_as_i8" (func $log_mem_as_i8 (param $byteOffset i32) (param $length i32)))
  (memory (export "mem") 1)
  (func $main
    (memory.fill (i32.const 128) (i32.const -42) (i32.const 10))
    ;; Logs an array of 10x -42 to console
    (call $log_mem_as_u8 (i32.const 128) (i32.const 10))
  )
)
```
