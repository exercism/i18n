# 概要

Factorのスレッドは、単一のOSスレッド上で動く*協調的コルーチン*です。スレッドは、明示的に`yield`するか、ブロッキングI/Oを行うまで実行を続けます。その時点で、スケジューラーが実行可能な別のスレッドを選びます。これには2つの意味があります。

- `yield`と`yield`の間で行われる処理は、事実上アトミックになります。
- 真のマルチコア並列処理には、標準の`threads`ボキャブラリの外に出る必要があります（たとえば、マルチプロセス設計のための`concurrency.distributed`など）。

標準の並行処理プリミティブは、層状になっています。

| ボキャブラリ                       | 提供するもの                               |
|-----------------------------|----------------------------------------|
| [`threads`][threads]                   | `spawn`、`yield`、スレッドの識別情報      |
| [`concurrency.promises`][concurrency.promises]      | `<promise>`、`fulfill`、`?promise`     |
| [`concurrency.locks`][concurrency.locks]         | `<lock>`、`with-lock`                  |
| [`concurrency.combinators`][concurrency.combinators]   | `parallel-map`、`parallel-each`        |
| [`concurrency.semaphores`][concurrency.semaphores]    | `<semaphore>`、`acquire`、`release`    |
| [`concurrency.mailboxes`][concurrency.mailboxes]     | スレッドごとの受信トレイ、`send`、`receive`  |
| [`concurrency.channels`][concurrency.channels]      | ランデブーハンドル、`to`、`from`       |

```factor
USING: concurrency.combinators concurrency.locks
concurrency.promises kernel sequences threads ;

! parallel-map: fork-join, in order
{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }

! spawn + promise: hand-rolled fork-join
<promise> [
    [ "hello, world" swap fulfill ] curry "greeter" spawn drop
] keep ?promise .   ! => "hello, world"

! <lock> + with-lock: protect a shared mutable slot
<lock> :> guard
guard [ "do thing under lock" drop ] with-lock
```

`parallel-map`は高レベルなAPIで、慣用的なFactorコードがまず最初に使うものです。`spawn`/`<promise>`/`?promise`の3つは、`parallel-map`の土台になっている組み合わせです。反復の形がmapに合わないとき（たとえば、別のチャネルを通じて結果を返すワーカーを起動する場合）に便利です。

ロックが保護するのは*共有された可変状態*です。典型的には、複数のスレッドが読み書きするタプルのスロットやハッシュテーブルです。アトミックでない複合的な更新がある場合は、読み込みも書き込みもロックが必要だと考えてください。どちらか片方でロックを忘れると、更新途中の値を読み取ってしまう典型的な原因になります。
