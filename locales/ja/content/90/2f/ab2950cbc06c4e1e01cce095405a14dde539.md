# 契約

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| 節 | 何を述べるか | 破られたときの責任の所在 |
| --- | --- | --- |
| `pre` | 呼び出し時に成り立っていなければならないこと | 呼び出し側 |
| `post` | 戻ったときに成り立つこと | ルーチン側 |

どちらも`BOOL`を取り、どちらもルーチンの引数とオブジェクトの属性を使うことができます。`post`はさらに、返される値である`result`も使うことができます。

## assert

ルーチンの本体の中で、`assert`はその時点で成り立っていなければならないことを述べます。

```sather
      assert load <= limit;
```

これは他のものと同じスイッチで検査されます。

## クラスの不変条件

クラスは、呼び出しと呼び出しの間、そのクラスのすべてのオブジェクトについて成り立つことを述べることができます。

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

検査が有効なとき、すべての公開ルーチンへの入り口と出口で検査されます。

## 有効にする

| フラグ | 検査する内容 |
| --- | --- |
| `-chk` | すべて: pre、post、assert、不変条件、境界、算術 |
| `-chk_no` | 何も検査しない |

なお、このコンパイラーでは`-chk_pre`だけでは事前条件の検査は有効に*なりません*。機能するのは`-chk`です。違反があると、ルーチンとソース行が出力され、プログラムは停止します。これは例外ではないので、`protect`では捕捉できません。

ふつうは、`-chk`を付けて開発とテストを行い、出荷時には外します。こうすると、出荷するプログラムでは検査のコストがかかりません。ただし、テストが実際にその経路を通ってこそ、このやり方は報われます。

## よい契約とは

ルーチンが何を必要としているかを書き、どう動くかは書きません。

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

本体をそのまま繰り返す`post`は、何も教えてくれません。

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## 継承

サブタイプは`pre`を弱め、`post`を強めることができます。より多くを受け入れ、より多くを約束するわけです。しかし逆はできません。そうすると、スーパータイプに対して書かれたコードが壊れてしまいます。契約とは、この規則を検査可能にするために存在します。
