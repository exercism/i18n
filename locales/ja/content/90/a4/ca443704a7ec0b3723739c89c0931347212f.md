# コメントに関するセクション

Goには、コメントの書き方に関する[優れたガイドライン](https://golang.org/doc/effective_go.html)があります。ドキュメントコメントには標準的な書式があり、それに従って書くと、`godoc`ツールが自動的に美しいドキュメントに変換してくれます。

パッケージコメントは、`Package`という語のあとにパッケージ名を続けて始めます。次のようになります。

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

エクスポートされた関数、メソッド、定数、パッケージ変数については、コメントは名前から始め、そのあとに動詞句を続けます。

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

[CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences)のWikiではさらに、ドキュメントコメントは完全な文にし、ピリオドで終えるべきだと述べられています。

読みやすさを良くするだけでなく、この推奨に従うと、[Goのドキュメンテーションツール](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/)（[godoc.org](http://godoc.org)、`godoc`、`go doc`など）でコードがどう表示されるかも良くなります。

公式スタイルガイドの[Effective Go](https://golang.org/doc/effective_go.html)にあるドキュメントコメントのセクションを少し読んで、こうした選択の背景にある理由を確認してみましょう。
