# Unisonの基本

## 項と関数

項と関数は、Unisonのプログラムを書くための基本単位です。

「項」とは、静的な値のことです。項は`name = expression`の形で定義し、任意で`name : MyType`という形の型シグネチャを前に付けることもできます。Unisonは型推論をサポートしているので、単純な定義では型シグネチャが省略されていることもあります。

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unisonの関数は`myFunctionName argument1 argument2 = myImplementation`のような形をしていて、関数名のあとにスペースで区切った引数が続きます。

```
getMax a b = Nat.max a b
```

関数には、任意で型シグネチャを付けられます。右端の型が常にその関数の最終的な戻り値の型で、それぞれの引数は関数の矢印`->`で区切られます。

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

関数を呼び出すには、関数名のあとに、スペースだけで区切った引数を書きます。

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

関数を呼び出すとき、Unisonはすぐ右にあるものを引数として扱おうとします。そのため、関数が思いどおりの順序で評価されないことがあります。

次の式から値`1`を得たいとしましょう。

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

このように書くと、`shouldBe1`は`0`と評価されます。暗黙の関数適用の順序が`getMax 1 10`、つまり`10`で、そのあとに`10 - 10`、つまり`0`になるからです。

括弧（`()`）を使うと、式をまとめ直して、思いどおりの演算順序にできます。

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## ウォッチ式

Unisonには、コードをすばやく評価するための「ウォッチ式」と呼ばれる仕組みがあります。ウォッチ式は`>`記号で始まり、そのあとに評価したい式を書きます。ウォッチ式は、拡張子が`.u`のファイルならどこにでも書けます。ファイルを保存すると、Unison Codebase Manager（UCM）のコンソールに、その式が何と評価されるかが表示されます。このドキュメントでは、可能なかぎり、ウォッチ式で評価したあとの式と、その期待される出力をあわせて示すようにします。

```
> helloThere
  ⧩
  "Hello, World!"
```

## 複数行の関数

Unisonの複数行関数では、インデントまたは`let`ブロックを使ってコードの境界、いわゆる「字句スコープ」を指定します。

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

同じインデントのレベルにあるものはすべて同じスコープを共有します。だからこそ、最後の行で変数`newBeginning`を参照できるのです。

## 名前空間と`use`文

名前空間は、Unisonの関数をグループ化して整理するための仕組みです。「ディレクトリ」のようなものだと考えてください。名前空間は、構造と論理的なまとまりを与えてくれます。

`use`文を使うと、名前空間にある関数をスコープに取り込めます。

Unisonの`List`値を使う関数を書いているとしましょう。`List.map`や`List.flatMap`のような関数が必要になることはわかっています。ここで`List`は名前空間で、`map`と`flatMap`は関数です。同じことを繰り返さなくて済むように、次のようにして`List`名前空間のすべてを関数の字句スコープに取り込むとよいでしょう。

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List`の行が、`map`と`flatMap`への参照を曖昧さなく解決します。[`use`文についてはこちら][use-statements]で詳しく読めます。

## Unisonの標準ライブラリ

Unisonの標準ライブラリは`base`と呼ばれています。クイックスタートガイドに沿ってローカルにコードベースを作成していれば、標準ライブラリは自動的にダウンロードされているはずです。標準ライブラリのドキュメントは、[Unison Share][unison-share-base]でオンラインで閲覧できます。

## コメントとドキュメンテーションリテラル

Unisonのコメントは、少し変わった機能です。Unisonのコードを書くとき、`.u`の拡張子が付いたファイルに、解釈されないテキストを次の構文で書けます。

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_ただし_、Unisonのコードは、ファイルシステム上のテキストベースのファイルとしてではなく、抽象構文木のハッシュとして保存されます。そのため、ファイル内のUnisonの関数や項をテキストベースで「装飾」するコメントは、保存して共有のために再表示する、ということが実質できません。ほかの人が読んで理解できる形で保存されるように、Unisonの項に情報を付け加えたい場合は、ドキュメンテーションリテラルを使えます。

ドキュメンテーションは、Unisonプログラミング言語では第一級の値です。つまり、`Doc`要素は値に代入したり、関数に値として渡したり、関数の値として返したりできます。ドキュメンテーションリテラルの要素は、二重の波括弧（`{}`）で囲みます。`Doc`要素をコメントとして使うと、次のようになります。

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
