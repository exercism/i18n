# 概要

C#の`struct`は、`class`と密接に関係しています。
状態と振る舞いを持ちます。
コンストラクター、メソッド、フィールド、プロパティなど、`class`と同じ種類のメンバーを持てます。

フィールドとプロパティは、単純型、`struct`、参照型のいずれかです。
`struct`は、スコープ、読み書きの規則、アクセスレベルについて、`class`と同じ規則に従います。

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

覚えておきたい重要な点の一つは、ある`struct`を変数に代入したり引数として渡したりすると、値がコピーされるということです。そのため、元の変数を変更してもコピーには影響せず、その逆も同じです。
まとめると、`struct`は**値型**です。

この[記事][class-or-struct]では、`struct`と`class`の違いについて説明しています。
この記事を読むと、`struct`は軽量で[不変][structs-immutable]であることが多いとわかりますが、この指針はコンパイラーやランタイムによって（既定では）強制されません。

いくつか、直面すること（そしてコンパイラーが教えてくれること）があります。

1. `struct`のメンバーはインラインで初期化できません。
2. `struct`は継承できません。
3. `struct`には、既定以外のコンストラクターを用意した場合でも常に既定のコンストラクターがあり、明示的な引数なしコンストラクターを用意することはできません。

以上の1と3の結果として、`struct`のエンジニアは、無効なインスタンスが生成されるのを防ぐ方法がありません。

## よく使われる構造体

ドキュメントを見ると、プリミティブ型と`struct`の間には密接な関係があることがわかります。
例として[`Int32/int`][int32]を見てください。
より一般的な`struct`の例としては、[`TimeSpan`][time-span]型があります。

`TimeSpan`のインスタンスは、`>`や`<`のような比較演算子や算術演算子を備えた数値とよく似た振る舞いをします。
これらの演算子は、必要であれば自分の`struct`にも実装できます。

`TimeSpan`について注目すべき点は、`IComparable<TimeSpan>`など、いくつものインターフェースを実装していることです。
`struct`は他の`struct`から派生させることはできませんが、インターフェースは実装できます。

## 等価性

`struct`の等値判定は、既定では単純にフィールドを比較するだけなので、`class`の等値判定よりもはるかに簡単なことがよくあります。
`object.Equals()`（や`GetHashCode()`）をオーバーライドする必要はありません。
`Object.GetHashCode()`に頼っている場合でも、ハッシュコードの生成に関わるフィールド（つまりすべてのフィールド）が、ハッシュを使うコレクションの使用中に変化しないようにする必要があることを覚えておいてください。
事実上、このように使う`struct`は不変であるべきだということです。

メソッド`Equals()`とは対照的に、等値演算子である`==`と`!=`には既定の実装がありません。
自分の`struct`でそれらが必要なら、自分で実装しなければなりません。

一方、この[記事][equality]では、`class`でよく行われるように独自の`Equals()`と`GetHashCode()`メソッドを作成することで、パフォーマンスを最適化できる方法が説明されています。
この演習の場合の差は、あまり厳密ではない比較で約20%でしたが、すべてのフィールドが同じ型なので、これは低めかもしれません。詳しくは後述します。

すべてのフィールドが同じ型であれば、`Equals()`メソッドをオーバーライドしない方が速度が向上する、という議論が[ウェブ][equality-performance]にあります。
この演習で、異なる型のフィールドを含めた場合の差は約60%でした。
これはMicrosoftのドキュメントには記載されていないので、未文書化の実装の詳細ということになります。利用する際は慎重にすべきです。

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
