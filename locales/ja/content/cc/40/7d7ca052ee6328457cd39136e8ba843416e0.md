# はじめに

バイナリデータを扱うのは難しいことがあるため、Gleamには`BitArray`型と、バイナリデータを構築したりパターンマッチしたりするための構文が用意されています。

ビット配列のリテラルは`<<>>`構文を使って定義します。ビット配列のリテラルを定義するときは、セグメント単位で書きます。各セグメントは値と注釈からなり、`:`で区切ります。注釈はその値をエンコードするのに何ビット使うかを指定するもので、完全に省略することもでき、その場合は8ビットの整数値が既定値になります。

```gleam
// This defines a bit array with three segments of a single bit each
<<0:1, 1:1, 0:1>>

// This defines a bit array with three segments of 8 bits each
<<0, 1, 0>>
```

型を`:1`と指定するのは、`:size(1)`と書く省略記法です。ビット数が変数から得られる場合は、長い方の構文を使う必要があります。

```gleam
let segment_size = 1
<<0:size(segment_size), 1:size(segment_size), 0:size(segment_size)>>
```

## 2進数

2進数の整数リテラルを書くときは、リテラルの先頭に`0b`を付けることで、そのまま2進表記で書くことができます。テストやプログラムの中で出力されるときには、10進数として表示されることに注意しましょう。

```gleam
<<0b1011:4>> == <<11:4>>
// -> True
```

## 切り捨て

セグメントの値がそのセグメントの型の容量を超えると、左から切り捨てられます。

```gleam
<<0b1011:3>> == <<0b0011:3>>
// -> True
```

## 先頭への追加と末尾への追加

ビット配列の構文を使えば、既存のビット配列の先頭にも末尾にも追加できます。既存のビット配列には`:bits`注釈を付ける必要があります。

```gleam
let value = <<0b110:3, 0b001:3>>
let new_value = <<0b011:3, value:bits, 0b000:3>>
// -> <<120, 8:size(4)>>
```

## 連結

この構文を使うと、変数に入ったビット配列同士を連結できます。サイズが変数の2つのビット配列を連結するときは、`:bits`注釈を付ける必要があります。

```gleam
let first = <<0b110:3>>
let second = <<0b001:3>>
let concatenated = <<first:bits, second:bits>>
// -> <<49:size(6)>>
```

## パターンマッチ

パターンマッチを使って、ビット配列から値を取り出すこともできます。取り出したい各断片について、そのビット数を知っておく必要がありますが、1つだけ例外があります。`:bits`注釈を使えば、サイズがわからないビット配列にパターンマッチできますが、これは最後の断片にしか使えません。

```gleam
let assert <<value:4, rest:bits>> = <<0b01101001:8>>
value == 0b0110
// -> true
```

## ビット配列を調べる

~~~~exercism/note
ビット配列は、作成したときの形式とは違う形式で出力されることがあります。これはビット配列を学ぶときにしばしば混乱の原因になります。
~~~~

既定では、ビット配列は8ビット（1バイト）の断片として表示されます。たとえ違うサイズの断片で作成してもです。

```gleam
<<2011:11>>
// -> <<251, 3:size(3)>>
```

表示可能なUTF-8エンコード文字列を表すビット配列を作ると、`io.debug`のような関数によって文字列として表示されることがあります。これは、Gleamが内部的に文字列を表現する方法の実装上の都合によるものです。

```gleam
<<>>
// -> ""

<<65, 66, 67>>
// -> "ABC"
```
