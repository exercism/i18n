# 概要

この演習では、仮引数に関するいくつかの性質を説明します。

- 修飾子（`out`や`ref`など）を付けずに[渡された][passing-parameters]仮引数は、値渡しになります。つまり、その仮引数は呼び出されたメソッド内で使ったり代入したりできますが、変更は呼び出し元に何の影響も与えません。
- 配列への参照やクラスのインスタンスが仮引数である場合、そのインスタンスの要素やフィールドは呼び出されたメソッドから変更でき、変更は呼び出し元にも見えます。これは`ref`修飾子の有無にかかわらず当てはまります。
- [`out`][out-parameter]修飾子を付けた仮引数は、呼び出されたメソッドから呼び出し元へ値を返します。この仮引数は、初期化せずに呼び出されたメソッドへ渡すことができ、いずれにしても呼び出されたメソッド内では、入った時点で初期化されていなかったものとして扱われます。仮引数の修飾子に関する振る舞いとルールは、例（下記参照）とコンパイラーのメッセージを通して理解するのがいちばん簡単です。

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- `out`仮引数は、呼び出されたメソッド内で必ず代入する必要があります。

- [`ref`][ref-parameter]修飾子を付けた仮引数は、呼び出されたメソッドへ値を渡します。メソッドから戻ると、呼び出し元はその仮引数に、呼び出されたメソッドが加えた更新を確認できます。

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

-`ref`仮引数は変数でなければなりません。呼び出されたメソッドは、呼び出し元から見えるその仮引数を直接操作するからです。

- `out`と`ref`の修飾子は、呼び出されたメソッドのシグネチャーと呼び出し箇所の両方で必要です。
- `out`仮引数は、呼び出し箇所でインラインでも宣言できます。たとえば`Foo(out int importantValue);`のように書きます。
- `out`仮引数を持つメソッドを呼び出すものの、そのうち1つ以上に代入される値に関心がない場合は、[破棄][discard]のダミー変数`_`を使えます。たとえば`Foo(out int _);`のように書きます。

`ref`と`out`仮引数に関するすべてのルールは、コンパイラーによって適用されます。

`in`仮引数も存在しますが、これは主にパフォーマンスのための最適化であり、いちばん関係の深い`structs`演習で扱います。

上でリンクしたドキュメントの内容は、以下にまとめます。

- [仮引数][passing-parameters]: 値を実引数として渡す方法を説明しています。構造体と仮引数の話題は`structs`演習で扱うことに注意してください。
- [`ref`仮引数][ref-parameter]: `ref`仮引数の仕組みを説明しています。
- [`out`仮引数][out-parameter]: `out`仮引数の仕組みを説明しています。

ドキュメントを読むときは、次の用語が使われていることに注意してください。

- 仮引数 / 仮パラメーター: 呼び出されたメソッドから見た仮引数を指します。
- 実引数: 呼び出し元から見た仮引数を指します。

[議論の余地はありますが][so-tuples-vs-out]、`out`仮引数の価値の多くは、C# 7で`tuples`が導入されたことでなくなったと言えます。`tuples`演習では、複数の値を返すために`tuples`を使う例を示します。

`ref`は使いやすく、パフォーマンス上のペナルティーもありませんが、広く使う前に、それが解決しようとする問題を特定のコードベースでどう扱っているかを確認する価値があります。値渡しにして、呼び出されたメソッドのreturn文が返す値を使う、といった方法もあります。ここでも`tuples`が役に立ちます。

[ドキュメント][ref-parameter]を見ると、`out`と`ref`が使えない状況もあることがわかりますが、今は気にしなくてかまいません。そうした状況になれば、コンパイラーが知らせてくれます。

`optional parameters`と`named arguments`は`method-overloading`演習で扱うことに注意してください。

関連する話題である[`ref local`][ref-local]と[`ref return`][ref-return]は、別の場所で扱っています。

## スタックの割り当て

仮引数とその修飾子に関するルールはとてもわかりやすいので、そのまま受け取り、その抽象度のまま理解できます。ただし、背後にある仕組みや、少なくとも`struct`の場合にこれらのキーワードがなぜパフォーマンスの違いを生むのかに興味があれば、この[_Wikipediaの記事_][calling-conventions]から始めるのがよいでしょう。C#はx86/64で`stdcall`を使う点に注意してください。

要点はこうです。修飾子のない仮引数の場合は、変数の**値**がプログラムのスタックにコピーされ、呼び出されたルーチンから使えるようになります。一方、`ref`、`out`、`in`の仮引数の場合は、値を保持するメモリーへのポインター（**参照**）がプログラムのスタックに置かれ、値はその参照が指すメモリーに代入されます。
