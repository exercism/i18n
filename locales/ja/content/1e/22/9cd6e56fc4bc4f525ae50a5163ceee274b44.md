# 説明

ここでの課題は、固定ウィンドウ方式のレートリミッターを作ることです。

1つのサーバーが、1つ以上のクライアントと接続している状況を想像してみましょう。
クライアントがリクエストを送ると、サーバーは何らかの処理を行い、レスポンスを返します。
しかし、処理には時間がかかります。
クライアントがあまりに多くのリクエストを短時間に送ると、サーバーは処理しきれなくなってしまいます。すると、すべてが遅くなったり、失敗したりします。

レートリミッターは、そのクライアントがどれくらいの頻度でリクエストを送っているかに基づいて、リクエストを許可するか拒否するかを決める小さなコンポーネントです。
戦略にはいくつか種類がありますが、この演習では固定ウィンドウ方式のレートリミッターを実装します。

固定ウィンドウ方式のレート制限では、時間を同じ長さのウィンドウに区切り（たとえば10秒ごと）、クライアントごとに、各ウィンドウ内で一定数までのリクエストを許可します。
ウィンドウがリセットされると、次のウィンドウに向けて許可数が回復します。
クライアントはそれぞれ別々に追跡されるので、同じ期間中でも別のクライアントはリクエストを送ることができます。

たとえば、クライアントごとに10秒あたり2リクエストに制限するよう設定されたレートリミッターを考えてみましょう。
あるクライアントがリクエストを送ったとします。

- これが最初のリクエストなので、許可されます。
- 最初のリクエストから10秒以内に送られた2つ目のリクエストも、許可されます。
- ただし、そのあとのリクエストは、最初のリクエストから少なくとも10秒が経過する_まで_拒否されます。
- 2人目のクライアントが、最初のクライアントの最初のリクエストから10秒以内に自分の最初のリクエストを送った場合、最初のクライアントが2つ目のリクエストを送ったかどうかに関係_なく_、そのリクエストも許可されます。
