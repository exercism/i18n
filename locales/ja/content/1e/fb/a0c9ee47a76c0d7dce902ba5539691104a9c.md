# はじめに

## 2進表記

**整数**とは、`4`、`-2`、`0`、`64532` のような数を表す抽象概念です。

整数をバイトの並びとして表すには、**2進表記**を使います。
この表記では、並びの中の各ビットがそれぞれ異なる2のべき乗を表し、ビットのインデックスが右から左へ増えるにつれて値が大きくなります。

## 符号なし数

その数が負の値にならない場合、**符号なし**数と呼びます。

符号なし数は、その並びの中でセットされているすべてのビットに対応する2のべき乗の和として、直接表されます。

レジスタで表せる非負整数の範囲は、`0`（どのビットもセットされていない状態）から `2⁶⁴ - 1`（64ビットすべてがセットされた状態の和）までです。

符号なし数をより大きなサイズに拡張するには、上位ビットをすべて`0`で埋めます。これにより、新しいビットは値に影響を与えません。
これを**ゼロ拡張**と呼びます。

命令`movzx`（`z`はゼロの意味）は、8ビットまたは16ビットのソースオペランドを、より大きなデスティネーションオペランドにゼロ拡張します。
32ビットのソースオペランドは、単純な`mov`によって、常にデスティネーションオペランドの64ビットすべてにゼロ拡張されます。

## 符号付き数

整数が正または負の値をとりうる場合、その数を**符号付き**数と呼びます。

負の数を表すために、x86-64では**2の補数**表現を使います。

2の補数では、符号付き数も、セットされたビットに対応する2のべき乗の和として表されます。
ただし、最上位ビットがセットされている場合は、そのビットは他のビットに加算されるのではなく、減算されます。

このビットは他のすべてのビットの和よりも大きな値に対応するため、実際には、このビットがセットされた数は常に負になります。
この特別なビットを**符号ビット**と呼びます。

符号付き数をより大きなサイズに拡張するには、新しく増える上位ビットをすべて符号ビットのコピーで埋め、値が保たれるようにします。
これを**符号拡張**と呼びます。

命令`movsx`（`s`は符号の意味）は、8ビットまたは16ビットのソースオペランドを、より大きなデスティネーションオペランドに符号拡張します。
`movsx`の変種である`movsxd`は、32ビットのソースオペランドから64ビットのデスティネーションオペランドに対して同じことを行います。

`neg`命令を使うと、数の符号を変えることができます。

~~~~exercism/caution
アセンブリでは、バイトの並びが符号付き数と符号なし数のどちらを表しているかを判別する方法はありません。
それらのバイトに意味を与えるのはプログラマーの責任です。

コメントを使うと、この作業がとても助けになります。
~~~~

## 即値

以前の概念で、`4`や`-15`のような定数を、多くの命令のソースオペランドとして使えると説明しました。
これらの数を**即値**と呼びます。

即値はレジスタやメモリに保持されず、命令自体の中にエンコードされます。
ほとんどの命令では、デスティネーションオペランドがどれほど大きくても、即値用に確保される領域は32ビット幅しかありません。

デスティネーションオペランドが64ビット幅の場合、それらの32ビットは、それを埋めるために_符号拡張_されます。
オペランドの上半分は、即値の最上位ビットのコピーで完全に埋められます。そのため、この方法で書けるのは、_32ビット符号付き整数_の範囲の数だけです。

```x86asm
add rax, -1          ; the immediate is sign-extended, so all 64 bits of rax are affected
add rax, 2147483647  ; the largest immediate an instruction like this accepts
```

その範囲外の数は、即値として使うことはできません。
この規則の例外は`mov`です。`mov`は、デスティネーションオペランドがレジスタの場合、完全な64ビットの即値を受け取ることができます。
64ビットの即値が必要な場合は、まず`mov`を使ってそれをレジスタに読み込み、次にそのレジスタを使います。

```x86asm
mov rax, 3435973837           ; this works, mov can take a 64-bit immediate
mov rdx, 18446744073709551615 ; the largest immediate mov accepts
sub rdx, rax
```

負の即値と、同じビット表現を持つ符号なし数は等価であり、まったく同じ値にアセンブルされることに注意してください。

```x86asm
mov rax, -1                   ; rax = 18446744073709551615
mov rax, 18446744073709551615 ; rax = -1
```

## 加算

2つの数の加算は、`add`命令を使って計算できます。

また、1オペランド命令の`inc`があり、オペランドの値に`1`を加えます。

```x86asm
inc rax ; rax = rax + 1
```

2つの整数の和は、符号なし数でも符号付き数でも同じように動作します。

## 減算

2つの整数の減算は、`sub`命令を使って行います。

また、1オペランド命令の`dec`があり、オペランドの値から`1`を引きます。

```x86asm
dec rax ; rax = rax - 1
```

2つの整数の減算も、符号なし数と符号付き数の両方で同じように動作します。

## 乗算

x86-64で2つの数の乗算を行うための命令は2つあります。
原則として、符号なしの乗算には`mul`命令を使い、符号付きの乗算には`imul`を使います。

`mul`命令は次の1オペランド形式をとります。ここで`src`はソースオペランドです。

```x86asm
mul src
```

`imul`命令は、1オペランド、2オペランド、または3オペランドの形式をとることができます。

```x86asm
imul src
imul dest, src
imul dest, src1, src2
```

### 1オペランドの乗算

1オペランド形式の乗算では、2つのレジスタ`rax`と`rdx`が暗黙的に使われます。
乗算が2つの64ビット数の場合、結果の下位64ビットは`rax`に、上位64ビットは`rdx`に入ります。

これは通常`rdx:rax`と呼ばれ、2つのレジスタが連携して使われることを示します。

```x86asm
mul rcx ; rax = lower 64 bits of rax * rcx
        ; rdx = upper 64 bits of rax * rcx
```

他のオペランドサイズでも同じことが起こります。
たとえば、2つの32ビット数を乗算する場合は、`eax`と`edx`が使われます。

例外は、2つのバイト同士の乗算です。

この場合、`dl:al`の代わりに`ax`が使われます。
`ax`の下位部分（`al`）には積の下位8ビットが入り、上位部分（`ah`）には上位8ビットが入ります。

~~~~exercism/caution
乗算で暗黙的に使われるレジスタ（`rax`や`rdx`など）は、常に上書きされます。
これらのレジスタの値が後で必要になる場合は、演算の前に保存しておく必要があります。
~~~~

### 2オペランドの乗算

`imul`の2オペランド形式には、明示的なデスティネーションオペランドがあり、通常の構文に従います。
`rdx`は使われません。
代わりに、結果はデスティネーションオペランドに収まるように切り捨てられます。

```x86asm
imul r8, r9 ; r8 = lower 64 bits of r8 * r9
```

### 3オペランドの乗算

`imul`の3オペランド形式には2つのソースオペランドがあり、2番目のソースオペランドは常に即値（定数）です。
両方のソースオペランドが乗算され、結果は切り捨てられてデスティネーションオペランドに格納されます。

```x86asm
imul r8, r9, 100 ; r8 = lower 64 bits of r9 * 100
```

デスティネーションオペランドは乗算には使われないことに注意してください。
単に結果を受け取るだけです。

### オーバーフローの扱い

2オペランド乗算と3オペランド乗算はどちらも、結果をデスティネーションオペランドのサイズに収まるように切り捨てます。
1オペランド乗算は完全な範囲を保持しますが、通常は2つのレジスタ`rdx`と`rax`に分割されます。

そのため、乗算の前にオペランドを拡張し、積全体を1つのレジスタに収められるようにすると便利なことがあります。
符号なしオペランドはゼロ拡張され、符号付きオペランドは符号拡張されます。

```x86asm
movzx eax, di ; di and si hold unsigned 16-bit numbers
movzx ecx, si
mul ecx       ; the 32-bit product fits in eax, and edx is cleared
```

## 除算

乗算の場合と同様に、2つの数の除算を行う命令も2つあります。
符号なしの除算には`div`命令を使い、符号付きの除算には`idiv`を使います。

どちらの命令も、1つのオペランドだけで動作します。

```x86asm
div src
idiv src
```

16ビット、32ビット、64ビットの除算では、それぞれ`dx:ax`、`edx:eax`、`rdx:rax`を被除数として使います。
これらの場合、2つのレジスタが連携して2Nビットの値を作ります。ここでNは演算のサイズ（16ビット、32ビット、64ビット）です。
この値がソースオペランドで除算されます。
商は演算のサイズに応じて`ax`、`eax`、`rax`に書き込まれ、余りは`dx`、`edx`、`rdx`に書き込まれます。

バイト同士の除算は特別です。`dl:al`を使う代わりに、`ax`を使います。
`ax`の下位8ビット（`al`）には演算の商が入り、上位8ビット（`ah`）には余りが入ります。

除算の前に、被除数のすべてのビットを適切に設定しておく必要があることに注意してください。
`rdx`（8ビット除算の場合は`ah`）にセットされているビットは、除算される値に寄与します。

符号なし除算では、除算される値が下半分に収まる場合、上半分をクリアする必要があります。
それらのビットをクリアする命令ならどれでもかまいません。
たとえば、`mov edx, 0`は32ビット除算で上位ビットをクリアします。

符号付き除算では、代わりに値を符号拡張する必要があります。
この処理を自動化する命令があります。`cbw`、`cwd`、`cdq`、`cqo`です。
最初の命令は、`al`の符号に応じて`ah`のビットを設定します。
残りの命令は、それぞれ`ax`から`dx`へ、`eax`から`edx`へ、`rax`から`rdx`へ符号拡張を行います。

~~~~exercism/caution
除算で暗黙的に使われるレジスタ（`rax`や`rdx`など）は、常に上書きされます。
これらのレジスタの値が後で必要になる場合は、除算の前に保存しておく必要があります。
~~~~
