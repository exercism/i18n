# 概要

`GENERIC:`宣言で導入されるワードは、引数のどれか1つのクラスによって振る舞いが変わります。具体的な振る舞いは、特定のクラスを対象とする*メソッド*（`M:`）が提供します。

```factor
GENERIC: stringify ( obj -- str )
M: integer stringify number>string ;
M: string  stringify ;
M: f       stringify drop "(none)" ;
```

`stringify`が呼ばれると、Factorはスタックの一番上を調べ、クラスが一致する最も具体的なメソッドを探して、それを実行します。一致するメソッドがなければ、エラーが投げられます。

## ディスパッチの対象クラス

既定では、ディスパッチは一番上の引数（スタック効果で宣言された最初の入力）に対して行われます。複数の引数によるディスパッチについては、`HOOK:`と`MATH:`を参照してください。これらはそれぞれ、2番目の引数と数値の昇格を基準にディスパッチします。

## ジェネリックにメソッドを追加する

ジェネリックはいつでも拡張できます。別のボキャブラリーからでも、`USE:`でジェネリックとクラスの両方を読み込めれば問題ありません。

```factor
USING: math ;
M: ratio  area drop 0 ;     ! adds an `area` method for ratios
```

## 組み込みクラスのメソッド

ジェネリックは、ユーザー定義のタプルだけでなく、組み込みクラス（`integer`、`string`、`array`、`f`、`t`）でも同じように機能します。特に`f`と`t`のメソッドは、自然な既定値をもつ「設定されているか？」といった述語に役立ちます。

## ジェネリックが適切なのはどんなときか

次のような場合は`GENERIC:`の出番です。

- 1つの操作が、入力によって*本当に異なる*実装をもつ場合（単にラベルで`case`するだけではない場合）。
- あとから別のコードによって新しい型が追加されることが見込まれる場合。
- 操作が関係するすべてのクラスに対して定義されていることを、型システムに強制してほしい場合。Factorは足りないメソッドを一覧にしてくれます。

違いが、ラベルの小さく固定された列挙で表せる程度なら、`case`のほうがシンプルです。
