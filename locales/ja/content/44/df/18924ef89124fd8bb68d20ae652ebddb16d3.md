# 束縛ルーチン

```sather
   part : ROUT{STR}:STR := bind(shout(_));
   part.call("who's there");
```

## bind

`bind`は、任意の部分を`_`で置き換えられる呼び出しを受け取ります。`_`以外の部分はすべて**その場で**評価され、そのまま保持されます。`_`はそれぞれ、書かれた順に束縛ルーチンの引数になります。

```sather
   bind(repeat(2, _))         -- ROUT{STR}:STR
   bind(repeat(_, "Ha"))      -- ROUT{INT}:STR
   bind(repeat(_, _))         -- ROUT{INT,STR}:STR
```

## 型

| 型 | 受け取るもの | 返すもの |
| --- | --- | --- |
| `ROUT:INT` | なし | `INT` |
| `ROUT{STR}` | `STR`を1つ | なし |
| `ROUT{STR}:STR` | `STR`を1つ | `STR`を1つ |
| `ROUT{INT,INT}:BOOL` | `INT`を2つ | `BOOL` |

`ITER{...}`は、イテレーターについて同じことを表します。

## call

`call`は残りの引数を渡します。何も返さない束縛ルーチンも、文として同じように呼び出します。

## bindは代入の右側に置きます

`bind`は変数に宣言することも、引数として渡すこともできます。

```sather
   part ::= bind(shout(_));                -- yes
   part : ROUT{STR}:STR := bind(shout(_)); -- yes
   rehearse("line", bind(shout(_)));       -- yes
```

ただし、`return`に直接書くことはできません。

```sather
   return bind(shout(_));                  -- does not parse
```

いったん変数に入れてから、それを返します。エラーメッセージは`bind`を指し、アンダースコアのことに触れますが、その行を見ただけではすぐにはわかりません。

## どこで使われているか

ライブラリーは、動作を渡す必要があるところでこれを使います。

```sather
   names.sort_by(bind(shorter(_, _)));
   scores.count_if(bind(over(10, _)));
   scores.find_if(bind(is_even(_)));
```

並べ替えが最もわかりやすい例です。`sort_by`は並べ替えの方法を知っていますが、あなたの考える順序については何も知りません。その2つをつなぐのが束縛ルーチンです。

## このコンパイラーでの制限

Sather 1.2は、**ディスパッチされた**束縛ルーチン、つまり抽象型の変数に対してルーチンを束縛することを実装していません。コンパイラーははっきりそう言います。

```
Dispatched bound routines are not implemented yet
```

具象型、またはクラスに対して束縛すれば、問題ありません。このトラックのテストハーネスが、束縛ルーチンを使わずに例外チェックを手書きしているのはこのためです。

## 束縛ルーチンか、抽象クラスか？

どちらも、呼び出す側が動作を渡せるようにします。

束縛ルーチンは1つのルーチンで、クラスを必要とせず、使う場所にそのまま書けます。抽象クラスは複数のルーチンといくつかの状態を持ち、渡すものに複数の要素がある場合には、その手間をかける価値があります。

渡したいものがルーチン1つなら、それを束縛しましょう。複数の役割を担う相手なら、クラスを書きましょう。
