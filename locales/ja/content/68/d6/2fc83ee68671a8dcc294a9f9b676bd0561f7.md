# トレイト

トレイトは、ある型が実装できるメソッドのまとまりを定義します。
トレイトは、複数の型の間で共有したいメソッドを定義するのに役立ちます。
トレイトをジェネリック型と組み合わせて使うと、定義したメソッドは特定の型に対して呼び出せるだけでなく、他のデータ型に対しても呼び出せるようになります。
抽象的に言えば、_トレイト境界_を使うことで、そのジェネリック型が特定の振る舞いを共有していなければならないと指定できます。

> **注:** トレイトは、他のプログラミング言語でインターフェースとして知られているものと似た機能を備えていますが、いくつか違いがあります。

## トレイトの定義

トレイトを定義すると、ある型が結果を得るために実装できる一連の振る舞いを構成する関数シグネチャをはっきりさせることができます。
これらのメソッドが、その型の振る舞いを形づくります。
同じメソッドを異なる型に対して呼び出せるなら、それらの型は同じ振る舞いを持っていることになります。

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

上の`Summary`トレイトの定義を見ると、`summarize`メソッドは`NewsArticle`構造体の型からしか呼び出せない振る舞いです。
他の型のインスタンスで呼び出すと、コンパイルエラーになります。
`pub`キーワードを付けてトレイトを宣言すると、このクレートのトレイトが、同じトレイトを利用しようとしている他のクレートにも公開されます。
また、トレイトの中でメソッドのシグネチャを宣言したあとには、セミコロンを付けることにも注目してください。

トレイトはジェネリック引数を取って定義することもでき、そうすると関数は任意のデータ型の引数を受け取れるようになります。
これにより関数シグネチャに柔軟性が生まれ、さまざまなデータ型を扱えるようになります。
下の`Summary`トレイトの場合、あらゆるデータ型で動作するように設計し直されており、それらの型で`summarize`メソッドを呼び出すとByteArrayが返ります。

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

トレイトの本体には、複数のメソッドを書くことができます。宣言するメソッドのシグネチャはそれぞれ1行で、セミコロンで終わります。

## 型へのトレイトの実装

トレイトを構成する関数シグネチャを定義すると、コンパイラーは、そのトレイトを採用する型に対して実装もきちんと定義されていることを要求します。
以下では、`NewsArticle`と`Tweet`のインスタンスからデータを要約する、メディア向けの`aggregator`ライブラリクレートを書きました。
`NewsArticle`構造体では、見出し、著者、場所を使って`Summary`トレイトの`summarize`メソッドの戻り値を返し、`Tweet`構造体では、ツイートの内容が280文字までという前提で、ユーザー名と内容を使います。

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## デフォルト実装

トレイトは、それを構成するメソッドの一部または全部にデフォルト実装を用意して定義することがあります。
これは、すべての型ですべてのメソッドを実装しなければならない状況を避け、コードを読みやすくするためです。
特定の型でトレイトのメソッドに特別な実装が必要な場合は、デフォルト実装を上書きできます。

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## 外部トレイトの利用と管理

トレイトと実装は外部のモジュールで定義し、適切にインポートしさえすれば、他のモジュールで使うことができます。
`boundary`メソッドを持つ`ShapeGeometry`トレイトがあり、それが`Circle`と`Rectangle`の両方の構造体に実装されなければならないとしましょう。
以下は、トレイトと実装をモジュールをまたいでインポートし、管理し、使う方法の例です。

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

`ShapeGeometry`トレイトは公開されていてコンパイラーが簡単に見つけられるはずなので、`CircleGeometry`と`RectangleGeometry`の実装の可視性を公開にする必要はありません。

## `impl`エイリアス

実装は、インポートするときに`impl`キーワードを使って別名を付けられます。
これは、ジェネリックな実装を具体的な型に対してインスタンス化するときに役立ちます。
`One`トレイトを実装するすべての型に対して、`One`の値を2回足してその和を返すだけの、トレイト`Two`の簡単な実装を定義してみましょう。
その後、`u8`型と`u128`型だけで動作する`Two`の実装を公開できます。

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

ジェネリックな実装は非公開のモジュールに書き、`impl`エイリアスを使うことで、この2つの具体的な型に対するジェネリック実装をインスタンス化できます。
非公開で外部に露出していないジェネリック実装を使う利点は、ファイルをまたいだコードの重複を防げることです。
また、公開APIをシンプルできれいに保つことにもつながります。
