# 概要

[concept:csharp/resource-cleanup]()では、`IDispose`インターフェースを使って、対象のオブジェクトが不要になった時点で、リソースやプログラムの状態を速やかに解放またはリセットする必要があることを、クラスの呼び出し元に知らせます。この演習では、`using`キーワードによるシンタックスシュガーを導入しました。これによりコードはより簡潔になり、重要な呼び出しを書き忘れる可能性も低くなります。

`using`は、一部のユースケースでは[`try/finally`][try-finally]を置き換えるものと見なせます。

```csharp
File file = null;
try
{
    file = new File("myStuff.txt");
    file.Write("more stuff");
}
finally
{
    file.Dispose();
}
```

この構文は、よりコンパクトで間違いの起きにくい次の形に置き換わります。

```csharp
using (var file = new File("myStuff.txt")
{
    file.Write("more stuff");
}
```

なお、複数のリソースは、単一行ブロックの標準的なルールに従って、そのまま組み合わせることができます。

```csharp
using (var file = new File("mystuff.txt")
using (var fileWriter = new StreamWriter(file)
{
     ...
}
```

C# 8では、`using`文をブロックの先頭に置く、次のような書き方も導入されました。

```csharp
using var file = new File("myStuff.txt");
file.Write("more stuff");
```

これにより、同じブロック内に複数の破棄可能なオブジェクトを置けるようになり、[`try/catch`][try-catch]もより自然に扱えます。

```csharp
using var fileIn = new File("myStuff.txt");
using var fileOut = new File("yourStuff.txt");
try
{
    var stuff = fileIn.Read();
    fileOut.Write(stuff);
}
catch (Exception)
{
    LogStuff();
}
```

`using`キーワードをどのように使えるか、どのような型のインスタンスに対して使えるかといったルールの詳細は、[こちら][using-statement]に書かれています。

## Java開発者の方へ

Java開発者なら、これをJava 7で導入された[_自動リソース管理_][automatic-resource-management]の仕組みに似たものだと気づくかもしれません。両者はよく似ています。`try`を再利用したJavaの構文は、C#の`using`よりも`catch`ブロックを自然に組み込めるという利点があります。

## バージョン

専用の構文ブロックを持たない、より柔軟な`using`はC# 8で導入されたため、作業しているコードベースがC# 8以降を使っているか確認する必要があるかもしれません。
