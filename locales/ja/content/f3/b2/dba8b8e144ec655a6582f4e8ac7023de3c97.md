# 説明

レトロな携帯ゲーム機のスコアリングシステム用のファームウェアを書いています。
この機械のCPUは非力で、スコアボードのディスプレイは決まった周期で更新されます。
画面を滑らかに保つには、プレイヤーが何をしていても、スコア計算のルーチンが予測可能なサイクル数で実行される必要があります。

タスクは4つあります。

~~~~exercism/note
タスクのコードは分岐なしにします。
条件ジャンプの代わりに、`cmovcc`、`setcc`、そして算術演算を使います。
~~~~

## 1. ディスプレイをあふれさせずにボーナスを加える

携帯ゲーム機のLCDのスコア領域は、10進数で6桁まで表示できます。
`999999`を超える数値は表示できません。
ボーナスによって現在の合計がこの上限を超えてしまうときは、合計は折り返さず、表示上は最大値に保たれます。

現在の合計と加算するボーナスを受け取り、`999999`にクランプした新しい合計を返す関数`add_bonus`を定義します。
入力は、順に次のとおりです。

1. `total`：現在のスコアの合計（常に`0`から`999999`の間）
2. `bonus`：加算するボーナス（常に0以上）

戻り値は、合計が`999999`以下なら`total + bonus`、それ以外は`999999`です。

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

入力と戻り値はどちらも64ビットの符号付き整数です。

~~~~exercism/note
`total + bonus`が64ビットの符号付き整数をオーバーフローしないと仮定してかまいません。
~~~~

## 2. 2つのスコアを比較する

携帯ゲーム機は、プレイヤーの最近のベストスコアを小さなリーダーボードとしてセーブファイルに保存しています。
プレイのたびに、新しいスコアが正しい位置に挿入されます。
並べ替えルーチンは、2つのスコアのどちらが上位かを尋ね、その答えを小さな整数として受け取ります。

2つのスコアを受け取り、次の値を返す関数`compare_scores`を定義します。

- 最初のスコアのほうが_大きい_場合は`+1`
- 最初のスコアのほうが_小さい_場合は`-1`
- 2つのスコアが_等しい_場合は`0`

例：

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

入力と戻り値はどちらも64ビットの符号付き整数です。

## 3. 生のスコアを検証する

携帯ゲーム機は、対戦後にスコアを共有するため、通信ケーブルで別の本体に接続できます。
このケーブルは電気的なノイズが多く、受信するバイトがときどき壊れて、許容される最小値をはるかに下回ったり、最大値をはるかに上回ったりする値になります。
検証用の処理は、システムの他の部分が受け取る前に、受信した各スコアを許容範囲内にクランプします。

生のスコアと許容範囲の境界を受け取り、`[min, max]`にクランプしたスコアを返す関数`validate_score`を定義します。
入力は、順に次のとおりです。

1. `score`：通信ケーブル経由で受信した生のスコア
2. `min`：許容される最小のスコア
3. `max`：許容される最大のスコア

戻り値は、`score < min`なら`min`、`score > max`なら`max`、それ以外は`score`です。
`min <= max`と仮定してかまいません。

例：

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

すべての入力と戻り値は64ビットの符号付き整数です。

## 4. 上位2つのスコアを追跡する

プレイのたびに、携帯ゲーム機はセーブファイル内の最近のプレイ履歴を走査して、これまでに記録された上位2つのスコアを探します。
この履歴は、メモリ上にある64ビットの符号付き整数の単純な配列です。
走査では配列を一度だけたどり、2つの最大値、つまりこれまでに見た中で最も大きい値と2番目に大きい値を保持します。

どちらの値も`0`以上である必要があります。
負の数は無視されます。

この関数の最初のバージョンは、連続する条件ジャンプを使って書かれていました。
各候補値について、コードはそれがどこに入るか（1番目の上か、1番目と2番目の間か、どこにも入らないか）を調べ、それに応じて実行中の最大値をずらし、負の結果は捨てていました。

これは正しく動きます。
しかし、入力値はランダムなので、条件ジャンプのたびに分岐予測ミスが多く発生します。
そこで、メインループを分岐なしに書き直すことにしました。

以下は、分岐のある部分をコメントアウトした関数です。

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

コメントアウトされた部分を、分岐のない実装に置き換えます。
新しいコードで許可されるジャンプは、配列の新しい要素を調べるためにループの先頭に戻るものだけです。

この関数は戻り値を持たず、分岐のあるバージョンと同じ入力を取ります。

1. `out`：上位2つの非負のスコアを降順で64ビットの符号付き整数として書き込む出力バッファ
2. `array`：64ビットの符号付き整数の入力配列
3. `length`：配列の要素数を表す64ビットの符号なし整数

~~~~exercism/note
配列に同じ値が複数含まれている場合、それらが上位2つのスコアであれば、両方の出力スロットに同じ値が現れることがあります。
~~~~
