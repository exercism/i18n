# 概要

再帰関数とは、自分自身を呼び出す関数のことです。

再帰関数には、少なくとも1つの_基底ケース_と、少なくとも1つの_再帰ケース_が必要です。

_基底ケース_は、その関数を再び呼び出さずに値を返します。
_再帰ケース_は、いずれ基底ケースに一致するよう入力を変えながら、その関数を再び呼び出します。

Elmでは、再帰関数は通常、`case`式を使ったパターンマッチで定義します。

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

再帰関数は、基底ケースをいくつも持つことも、再帰ケースをいくつも持つこともできます。
たとえば、[フィボナッチ数列][fibonacci]は2つの基底ケースを持つ再帰的な数列です。

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

ただし、この実装は指数関数的に遅いことに注意してください。関連するフィボナッチ数が、2つの独立した再帰呼び出しの中で毎回ゼロから計算されるためです。

ある値`x`が配列の中に現れる回数を数える場合、再帰ケースが2つあります。

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## 再帰によるループ

不変性のため、Elmのループは命令型言語とは書き方が異なります。
たとえば、命令型言語のループはふつう次のようになります。

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

Elmのような関数型言語では、変数を書き換えることはできません。
そのため、ループは再帰で実装する必要があります。

Elmで`for`ループに相当するものは、次のようになります。

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

実際には、Elmで配列やその他のデータ構造を繰り返し処理するときは、[`List`][module-list]モジュールの`List.map`、`List.filter`、`List.foldl`といった関数を使うことがほとんどです。
これらの関数は、内部では再帰を使って実装されています。

## 無限の実行

再帰関数は、実装が間違っていたり、再帰呼び出しの回数が多すぎたりすると、結果を返せないことがあります。
これは問題になり得ます。関数が呼び出されるたびに、ランタイムが結果を戻すべき場所（[コールスタック][wiki-call-stack]）への参照がメモリに保存されるためです。
再帰関数が自分自身を呼び出しすぎたり、無限に呼び出したりすると、メモリを使い果たしてランタイムがクラッシュすることがあります（[スタックオーバーフローエラー][wiki-stack-overflow]）。
Elmのランタイムは、再帰と信頼性のために最適化されていますが、無限再帰が問題を引き起こすことはあります。

この無限の実行という問題は、次のようなことが原因で起こります。

- 基底ケースの実装を忘れる。
- パターンマッチですべてのケースを処理していない。
- 再帰呼び出しのときに引数を適切に変えておらず、そのため基底ケースに決してたどり着かない。
