# はじめに

## コメント

Common Lispでは、コンピューターに無視される「コメント」を書くことができます。1行コメントは1つ以上のセミコロン（`;`）で始まります。ときには、次のような書き方も見かけます：

```lisp
(code...) ; => value
```

これは、その行のコードを実行したあとにCommon Lispが返す値をコメントで示しているものです。

行末の短いコメントにはセミコロンを1つ、コードのまとまりの上に置くやや長いコメントには2つ、関数などの説明を書く長いコメントには3つ、ソースファイルの先頭に置くヘッダーのようなコメントには4つ使うのが慣習です。

## コンス

Common Lispのすべてのオブジェクトは、「アトム」（単一で分割できない値）か「コンス」（構成する関数`cons`によって作られる）のどちらかです。
コンスは、最初の要素と残りの要素という2つの部分からできています。
歴史的な理由から、この2つの部分は`car`と`cdr`と呼ばれています。
こうしたコンスがコードとして評価されるとき、最初の要素（`car`）が呼び出される関数を表し、残りの要素（`cdr`）がその関数への引数を表します：

```lisp
(<function> <arg1> <arg2> ... <argN>)
; ^ car ^  |        ^ cdr ^
```

## 式

Common LispのコードはすべてS式（Symbolic Expression）でできています。これは略してsexprと呼ばれます。すべてのsexprは、アトムかコンスのどちらかです。S式は評価されると、自動的に何らかの値を返し、その値が式の代わりになります。`defun`を使って自分の関数を書くときは、`defun`の本体の最後の値が自動的に返されます：

```lisp
;; Defining a new function
(defun gimme-foo () 'foo)
;; Calling the function as an S-Expression
(gimme-foo) ; => FOO
```

## シンボル

Common Lispにおけるシンボルは特別な値で、他の値を指すこともあれば、_キーワード_の場合は自分自身を指すこともあります。
シンボルがLispによって評価されると、そのシンボルが指す値に置き換えられます：

```lisp
foo  ; => <whatever-foo-points-to>
:foo ; => :FOO
```

キーワードは先頭のコロン（`:`）で表されることに注意してください。

クォートとは、S式の前に`'`を付けることです。これにより、Lispにその式を評価しないように伝えます。
`defun`の例で`'foo`をクォートしたことで、Lispが`FOO`の指す先を探そうとする（そして見つけられない）のを避け、代わりに`FOO`という値そのものを返しました。
`FOO`がプログラムのどこにも定義されていなければ、次のようになります：

```lisp
foo  ; => <ERROR! Lisp doesn't know what foo points to!>
'foo ; => FOO
```

今のところは、関数からシンボルを返す方法だと考えておけば大丈夫です。クォートについては、今後のコンセプト演習で改めて取り上げ、その意味をさらに掘り下げていきます。
