# 概要

`TUPLE: child < parent extra-slots ;`は、そのインスタンスが`parent`のインスタンスでもあるクラスを宣言します。スロットの検索は階層をたどります。`child`は、親が宣言したすべてのスロットと、それに続く自分のスロットを、その順序で持ちます。

```factor
TUPLE: vessel name tonnage ;
TUPLE: cargo-vessel < vessel capacity ;
TUPLE: tanker < cargo-vessel fuel-type ;
```

## `boa`の引数の順序

自動生成される`boa`コンストラクターは、宣言された順序でスロットを受け取ります。*親が先*です。上の`tanker`の場合、次のようになります。

```
tanker boa ( name tonnage capacity fuel-type -- tanker )
```

スロットの順序は継承の連鎖によって決まります。親と子のスロットを交互に並べる方法はありませんし、親のスロットの順序を変えると、すべての子孫の`boa`にとって互換性を壊す変更になります。

## 述語の階層

`TUPLE:`の宣言は、どれもクラスの述語（`name?`）を生成します。継承があると、述語は入れ子になります。

```factor
"Esso" 50000 100000 "diesel" tanker boa .

! all three predicates fire
dup tanker?        .   ! => t
dup cargo-vessel?  .   ! => t
dup vessel?        .   ! => t
```

`instance?`（[`classes`][classes]より）は、同じ問いを、ワード名に埋め込む代わりにクラスをスタック引数として渡して尋ねます。`obj tanker instance?`は`obj tanker?`と同じです。

```factor
USING: classes ;

"Esso" 50000 100000 "diesel" tanker boa
dup vessel instance? .   ! => t
```

クラスが値になったので、同じ呼び出し箇所で、渡されたどんなクラスに対してもテストできます。固定された`name?`述語にはできないことです。

推移的な`is-a`関係は、`M:`のメソッドディスパッチがたどる関係でもあります。`vessel`に定義されたメソッドは、より具体的なオーバーライドが先に働かない限り、すべての`cargo-vessel`とすべての`tanker`に適用されます。その話のもう一方の側面は、[`generics`][generics]で扱っています。

## アクセサの継承

アクセサワード（`slot>>`、`>>slot`、`change-slot`）は[`accessors`][accessors]から来ていて、生成元のクラスには縛られていません。そのスロットを*持っている*タプルなら、どれでも使えます。

```factor
USING: accessors ;

"Esso" 50000 100000 "diesel" tanker boa
[ 1 + ] change-tonnage tonnage>> .   ! => 50001
```

`change-tonnage`は`vessel`のために生成されましたが、すべての`tanker`は`vessel`なので、`tanker`でも動きます。

## ここで扱わないもの

- **ミックスイン**（`MIXIN:` / `INSTANCE:`）: クラスは多くのミックスインに加わることができます。関係は多対多で、主に共有されたプロトコルに対するジェネリックディスパッチに使われます。ストリームの概念で、文脈の中で紹介します。
- **述語クラス**（`PREDICATE:`）: 実行時の述語によって、既存のクラスからサブクラスを切り出します。Factorの別の機能で、ここでは扱いません。
