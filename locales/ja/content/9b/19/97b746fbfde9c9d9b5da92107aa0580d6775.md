# 概要

メモリは通常、オペレーティングシステム（OS）によって、プログラムのために次のような大まかなレイアウトでマッピングされます。

| アドレス | メモリ領域 |
| :-----: | :--------------------- |
|  高位   | スタック |
|         | ... |
|         | ヒープ |
|         | 読み書き可能セグメント |
|         | コード／読み取り専用セグメント |
|  低位   | 予約済み |

セグメントに分かれたメモリは、さらに、それぞれ異なる権限を持つセクションに整理されています。

これまで定義してきた関数は、すべて**セクション .text**にありました。
このセクションには、読み取り専用の実行可能データが入っています。
ほかのセクションはデータ変数を宣言するために使われます。データ変数は読み取り専用の場合も読み書き可能な場合もありますが、実行可能ではありません。

## セクション .data

初期化されたデータは、**[セクション .data][data]**で宣言します。

NASM（The Netwide Assembler、このトラックで使われているアセンブラー）では、初期化された変数は、名前、データサイズを示すディレクティブ、そしてカンマで区切られた値のリストを持ちます。
それぞれはスペースで区切られ、ラベルの後ろには任意で`:`を付けられます。

主なディレクティブと、それに対応するデータサイズは次のとおりです。

| ディレクティブ | サイズ    |
| :-------: | :------ |
|    db     | 1バイト  |
|    dw     | 2バイト |
|    dd     | 4バイト |
|    dq     | 8バイト |

たとえば、次のコードは`space`という名前のバイト変数を、値`10`で宣言します。

```x86asm
section .data
    space db 10
```

`section .data`で宣言された変数は可変です。つまり、読み書きができます。
また、_静的_な記憶域期間を持ちます。これは、プログラムの実行中ずっと存在し続けることを意味します。

## セクション .rodata

**セクション .rodata**は、`section .data`と似ています。
どちらのセクションも初期化されたデータを含み、そのデータは同じ方法で宣言され、同じ記憶域期間を持ちます。

両者の主な違いは、`section .rodata`のデータが不変、つまり読み取り専用であることです。

~~~~exercism/note
`equ`で定義された定数は、`section .rodata`で定義されたものとは異なります。

`equ`で定義された定数はメモリ上に領域を占めず、アセンブラーによってその値に直接置き換えられます。
実際には、その値のプレースホルダーです。

一方、`section .rodata`で定義された定数は、実際にメモリに格納され、アドレスを持ちます。
~~~~

## データへのアクセス

### ラベルと間接参照

宣言されたデータには、必ず名前を関連付ける必要があります。
この名前を**ラベル**と呼びます。

ラベルは、メモリ内のデータの特定のアドレスを表すシンボルです。
**x86-64のアドレスは64ビットの値です**。
このようなアドレスを保持する値は、レジスタに置かれていてもメモリに格納されていても、高水準言語では**[ポインタ][pointer]**と呼ばれます。

NASMでは、ラベルを使ってデータに直接アクセスしようとしても、確保されたメモリそのものではなく、そのアドレスが得られます。

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

メモリアドレスの内容にアクセスするには、そのアドレスを_逆参照_する必要があります。
これを**間接参照**と呼びます。

NASMでは、これは`[]`で行います。

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

ただし、逆参照するメモリのサイズが曖昧になる場合があります。
そのような場合は、サイズを指定するプレフィックスを使う必要があります。

一般的なx86-64プログラムで最も重要なプレフィックスと、そのサイズは次のとおりです。

| プレフィックス | サイズ    |
| :----- | :------ |
| byte   | 1バイト  |
| word   | 2バイト |
| dword  | 4バイト |
| qword  | 8バイト |

同じロードを、サイズを明示して書くこともできます。

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

メモリを逆参照するときは、常にプレフィックスを付けるのが良い習慣です。

### メモリへの書き込み

メモリへの書き込みも同じように、アドレスを逆参照して行います。

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

ほとんどの命令では、内容を先にレジスタへ読み込まなくても、メモリオペランドを使えることに注意してください。
ただし、通常は、ソースオペランドとデスティネーションオペランドの両方に使うことはできず、どちらか一方だけに使えます。

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### LEA命令

`mov`を使って変数のアドレスをレジスタに格納することもできますが、この目的専用の命令があります。それが**[lea][lea]**です。

この命令はメモリ形式のオペランドを使いますが、メモリを読み取ることは_ありません_。
代わりに、実効アドレスの式を計算し、その結果をデスティネーションオペランドに書き込みます。

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

メモリアドレスを計算してレジスタに格納するには、`lea`を使うのがより慣用的です。

### 相対アドレス指定

メモリ位置にアクセスするとき、NASMのデフォルトの動作は**絶対アドレス**、つまり固定されたメモリアドレスを生成することです。

セキュリティ上の理由から、実行ファイルは**PIE（位置独立実行形式）**としてビルドされることがよくあります。この場合、メモリ領域はランダムな位置に配置されます。
`PIE`では、変数の最終的なアドレスはリンク時に確定しません。
そのため、コードは代わりに、`rip`と呼ばれる特別なレジスタの値からのオフセットとしてアドレスを計算します。このレジスタは、次に実行される命令を指します。

これは通常、**RIP相対アドレス指定**と呼ばれます。

NASMでは、**[rel演算子][rel]**を使ってRIP相対アクセスを要求できます。

```x86asm
mov rax, qword [rel variable]
```

ソースファイルの先頭で`default rel`と書けば、相対アドレス指定をデフォルトにすることもできます。

このトラックのすべての演習は`PIE`としてコンパイル・リンクされるので、相対アドレスを生成するには`rel`を使う必要があります。

前述のランダムな配置は、アドレス空間配置のランダム化として知られる緩和策です。
各メモリ領域のベースを予測不能にすることで、多くの攻撃手法が依存している固定アドレスを攻撃者に与えません。そして、ローダーがこれらの領域をどこにでも配置できるようにするのが`PIE`です。

このため、このトラックでは絶対アドレス指定は推奨されないどころか、使うことすらできません。
`[abs variable]`のような絶対参照は、固定の32ビットアドレスを命令に埋め込むようアセンブラーに要求します。
Linuxでは、`PIE`リンカーがこれによって生じる再配置を拒否します。また、macOSでは`macho64`形式が32ビットの絶対アドレスをまったくサポートしていないため、ファイルのアセンブルに失敗します。

RIP相対アドレス指定は、どちらの問題も回避します。命令がエンコードするのは`rip`からのオフセットだけで、固定アドレスは決して含まないからです。
したがって、`PIE`でアドレスをレジスタに格納する慣用的な方法は、`rel`オペランドを付けた`lea`です。

```x86asm
default rel

section .data
    variable dq 7

section .text
fn:
    lea rax, [rel variable]       ; materialize the address (PIE-safe)
    mov rcx, qword [rel variable] ; load the value through a RIP-relative access
    ...
```

### 可視性

どのセクション（`.text`、`.data`、`.rodata`など）で定義されたラベル（関数やデータ）も、同じソースファイル内から参照できます。
`global`として宣言すれば、ほかのソースファイルからも参照できます。

逆に、ほかのソースファイルで定義されたラベルは、`extern`として宣言されていれば、現在のソースファイルから参照できます。
この場合、アセンブリにはデータサイズを示す情報がないため、あらかじめ把握しておく必要があります。

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
