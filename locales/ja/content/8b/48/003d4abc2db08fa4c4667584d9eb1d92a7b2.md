# はじめに

2進数の各桁は、最終的にはCPUやRAMのトランジスタに直接対応しています。各トランジスタが「オン」なのか「オフ」なのか、ということです。

低レベルな操作は、くだけた言い方では「ビットいじり」とも呼ばれ、システムプログラミング言語では特に重要です。

Juliaのような高水準言語では、こうした詳細のほとんどはたいてい抽象化されています。とはいえ、ビット単位の操作は言語そのものにひととおり用意されています。

***注意：*** REPLで人が読める形の2進数の出力を見るには、以下の例のほとんどを`bitstring()`関数で包む必要があります。これは見た目に煩わしいので、この関数の出現箇所はほとんど取り除いてあります。

## ビットシフト演算

整数型は、符号付きでも符号なしでも、1と0の並びとして表すことができます。

```julia-repl
julia> bitstring(UInt8(5))
"00000101"
```

ビットシフトは、指定した桁数だけ全体を左または右に動かすだけです。`UInt`型では、一方の端からビットがこぼれ落ち、もう一方の端は0で埋められます：

```julia-repl
julia> ux::UInt8 = 5
5

julia> bitstring(ux)
"00000101"

julia> ux << 2 # left by 2
"00010100"

julia> ux >> 1 # right by 1
"00000010"
```

左シフトするたびに値は2倍になり、右シフトするたびに値は半分になります（切り捨てが起こります）。これは10進数で表すと、よりはっきりわかります：

```julia-repl
julia> 3 << 2
12

julia> 24 >> 3
3
```

こうしたビットシフトは「正統な」算術よりもはるかに速いため、低レベルのコードを書くときにはとてもよく使われる手法です。

符号付き整数では、もう少し注意が必要です。

左シフトは比較的単純です：

```julia-repl
julia> sx = Int8(5)
5

julia> sx # positive integer
"00000101"

julia> sx << 2
"00010100"

julia> -sx # negative integer
"11111011"

julia> -sx << 2
"11101100"
```

このように、正の符号付き整数の左シフトは、符号なし整数の場合と同じです。

負の値は[2の補数][2complement]の形で格納されるので、いちばん左のビットは1になります。左シフトなら問題ありませんが、右シフトのときは、いちばん左のビットをどう埋めればよいのでしょうか？

```julia-repl
julia> sx >> 2 # simple for positive values!
"00000001"

julia> -sx # negative integer
"11111011"

julia> -sx >> 2 # pad with repeated sign bit
"11111110"

julia> -sx >>> 2 # pad with 0
"00111110"
```

`>>`演算子は算術シフトを行い、符号ビットを保ちます。

`>>>`演算子は論理シフトを行い、その数が符号なしであるかのように0で埋めます。

## ビット単位の論理演算

以前の概念で、演算子`&&`（and）、`||`（or）、`!`（not）が真偽値に対して使われることを見ました。

2つの整数のビットを比較するための、それぞれに対応する演算子`&`（ビット単位のand）、`|`（ビット単位のor）、`~`（チルダ、ビット単位のnot）があります。

```julia-repl
julia> 0b1011 & 0b0010 # bit is 1 in both numbers
"00000010"

julia> 0b1011 | 0b0010 # bit is 1 in at least one number
"00001011"

julia> ~0b1011 # flip all bits
"11110100"

julia> xor(0b1011, 0b0010) # bit is 1 in exactly one number, not both
"00001001"
```

ここでの`xor()`は排他的論理和で、関数として使います。

[2complement]: https://en.wikipedia.org/wiki/Two%27s_complement
