# 説明

先日のセキュリティレビューを受けて、組織にアーカイブされたログファイルを整理することになりました。

## 1. 不正なログ行を特定する

アーカイブ内のログ行のうち、現在の基準に準拠していないものがどれくらいあるのか、おおよそ把握しておきたいところです。あるログ行が有効かどうかは、簡単なテストで判定できるはずだと考えています。
有効と見なされるには、行が次のいずれかの文字列で始まっている必要があります：

- `[DEBUG]`
- `[INFO]`
- `[WARNING]`
- `[ERROR]`

`is_valid_line`関数を実装して、そのログ行が有効であれば`True`を返すようにします。

```gleam
log_parser.valid_line("[ERROR] Network Failure")
// -> True

log_parser.valid_line("Network Failure")
// -> False
```

## 2. ログ行を分割する

ログ解析プロジェクトを始めて間もなく、あるアプリケーションのログが他のもののように行に分割されていないことに気づきます。このプロジェクトでは、本来別々の行であるべきものが1行にまとまっており、`<--->`や`<*~*~>`のような変わった矢印でつながっています。

実際、最初の文字が`<`、最後の文字が`>`で、その間に次の文字`~`、`*`、`=`、`-`が0個以上ある文字列は、このプロジェクトのログで区切り文字として使えます。

`split_line`関数を実装して、1行を受け取り、文字列の配列を返すようにします。

```gleam
log_parser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
// -> ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. 行にユーザー名のタグを付ける

ログ行の中には、ユーザーを指す文が含まれているものがあることに気づきました。
これらの文には必ず、文字列`"User"`のあとに1つ以上の空白文字が続き、そのあとにユーザー名が来ます。
そこで、そのような行にタグを付けることにします。

ログ行を処理する`tag_with_user_name`関数を実装します：

- 文字列`"User"`を含まない行はそのままにします。
- 文字列`"User"`を含む行には、`[USER]`とそれに続くユーザー名を行の先頭に付けます。

```gleam
log_parser.tag_with_user_name("[INFO] User Alice created a new project")
// -> "[USER] Alice [INFO] User Alice created a new project"
```

次のように仮定してかまいません：

- 文字列`"User"`の各出現箇所には、1つ以上の空白文字とユーザー名が続きます。
- 各行には、文字列`"User"`が最大1回だけ出現します。
- ユーザー名は、空白文字を含まない空でない文字列です。
