# 概要

## はじめに

ジェネリクスは、コードの再利用を可能にする言語機能です。
たとえば、配列の長さを計算するのに、その配列がどんな型の要素を保持しているかは問題になりません。
だからこそ、`length`関数は型シグネチャの中でジェネリックな型パラメータ`a`を使っています。

```elm
length : List a -> Int
```

## 型におけるパラメータ

型が別の型に対してジェネリックであるとき、その別の型には小文字の名前を使い、それを型パラメータと呼びます。
よくある例は、`List`、`Maybe`、`Result`といったカスタム型です。

```elm
-- Maybe is generic over the type a
type Maybe a
    = Nothing
    | Just a

someString : Maybe String
someString = Just "hello"

someInt : Maybe Int
someInt = Just 42
```

型パラメータの名前について重要なのは、複数の文字からなっていてもよいという点です。
唯一の制約は、小文字の名前でなければならないことです。
そのため、役に立つときには、説明的な名前を付けることが多いです。

型は複数の別の型に対してジェネリックになれるので、複数の型パラメータを持てます。
その場合、独立したそれぞれの型に、異なる小文字の名前を付けます。
独立しているからといって、同じ型になれないわけではありません。単に、異なる型になれるというだけです。

```elm
-- Result is generic over the types error and value
type Result error value
    = Ok value
    | Err error
```

レコードの型エイリアスも型パラメータを持てますが、あまり一般的ではありません。

```elm
-- Event is generic over the type a
type alias Event a =
    { at : Time
    , data : a 
    }
```

> これが、`Html`パッケージが`Html msg`という型を定義し、`msg`という名前の型パラメータを1つ持たせている理由です。
> Elmアーキテクチャは、ウェブページが引き起こせるすべてのメッセージを表すカスタム型`Msg`を作る方向へ導いてくれます。
> その結果、書くコードは`Html Msg`という型のビューを作ることになります。ここで`Msg`は自分で定義した具体的な型です。
> 初心者は、`Html msg`（小文字）に言及したエラーと、`Html Msg`に関するエラーを混同しがちです。
> これで納得ですね！
> 違いは、前者が任意の`msg`型に対してジェネリックであるのに対し、後者は自分の`Msg`型に固有であるという点です。

## 関数の型パラメータ

型がジェネリックになれるのですから、関数もジェネリックになれます。
ジェネリックな型を扱う関数を書くことができ、たとえば`Maybe.withDefault`があります。

```elm
withDefault : a -> Maybe a -> a
withDefault default maybe =
    case maybe of
      Just value -> value
      Nothing -> default
```

他の関数を仮引数として受け取る関数は高階関数と呼ばれ、これらもジェネリックになれます。

```elm
map : (a -> b) -> Maybe a -> Maybe b
map function maybe =
  case maybe of
    Just value ->
      Just (function value)

    Nothing ->
      Nothing
```

型パラメータは、関数の入力にも出力にも現れることができます。そして、型パラメータによって型がジェネリックになれることを、ふつう**パラメトリック多相**と呼びます。
これは、関数オーバーロードとも呼ばれるアドホック多相と対照的です。アドホック多相では、型が異なる複数の実装に同じ関数名を使えます。
また、サブタイプ多相とも対照的です。サブタイプ多相では、型を階層の中で定義でき、ある型に定義された関数をそのサブタイプの入力で呼び出すこともできます。
Elmで利用できる唯一のジェネリクスの仕組みは、パラメトリック多相です。
