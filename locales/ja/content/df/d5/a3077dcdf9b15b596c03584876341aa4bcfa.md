# はじめに

ほとんどすべてのFactorプログラムは、*データスタック*上の値を消費したり生成したりする単語の並びです。入力と出力がきれいに揃っていれば、コードは左から右へすんなり読めます。そうでなければ、*シャッフルワード*の出番です。そしてコードはあっという間に騒がしくなります。

この演習では、Factorの標準的な解決策であるコンビネーターを順を追って見ていきます。

## シャッフルワード

よく使うシャッフルワードは[`kernel`][kernel]にあります。

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

`dup`と`swap`はもう使ったことがあるでしょう。`over`は上から*2番目*の要素のコピーを作ります。同じ入力から2つの計算に渡したいときに便利です。

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

1回の使用なら問題ありません。しかし、`dup`や`swap`、`over`、`rot`を続けざまに並べると、すぐに読みづらくなります。

## `keep`：入力を保つ

`keep`（[`kernel`][kernel]にあります）は、スタックの一番上に対してクォーテーションを呼び出しますが、元の値を結果の上に残します。

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

これは、`dup`のあとに何かを挟んでから並べ替えるというパターンを置き換えます。`dup something swap`と書くところを、`[ something ] keep`と書くだけで済みます。

## `bi`：1つの入力に2つの関数

`bi`（[`kernel`][kernel]にあります）は、*2つ*のクォーテーションを同じ値に適用し、どちらの結果もスタックに残します。

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

`bi`がなければ、`dup sq swap neg`と書くことになります。2つの操作ならまだ読めますが、3つになると厄介です。

## `tri`と`cleave`：1つの入力に多くの関数

`tri`は`bi`を3つのクォーテーションに拡張します。

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

`cleave`（[`combinators`][combinators]にあります）は、同じ考え方を、任意の数のクォーテーションからなる*配列*に適用したものです。

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

空のクォーテーション`[ ]`は恒等としての役割を果たします。カードを切ったときのスロットの1つが、入力そのものになる場合に便利です。

## `dip`と`2dip`：下側を操作する

`dip`（[`kernel`][kernel]にあります）は、スタックの一番上の*下側*にある値に対してクォーテーションを呼び出し、一番上はそのままにします。`2dip`も同じことをしますが、上から*2つ*の値を保護します。

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

ここでは`dip`が`11`を隠し、`9 10 +`を実行して、`11`を再び一番上に戻しました。`2dip`は`11 12`を隠し、その下で`9 10 +`を実行してから、`11 12`を元に戻しました。

自然な引数の順番だと「そのまま通す」値がスタックの一番上に来てしまうとき、`dip`が適切な道具です。`swap … swap`というサンドイッチの代わりに、これを使ってください。

## `bi@`：2つの値に同じ操作

`bi@`（[`kernel`][kernel]にあります）は、1つのクォーテーションを2つのスタック値に適用します。

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*`：2つの値に異なる操作

`bi*`（[`kernel`][kernel]にあります）は、*異なる*クォーテーションを2つのスタック値に適用します。1つ目のクォーテーションは下側の値に、2つ目は一番上の値に適用します。

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

どちらの値も同じ扱いをするときは`bi@`、それぞれに別の扱いが必要なときは`bi*`を使います。

## `tri*`：3つの値に異なる操作

`tri*`（[`combinators`][combinators]にあります）は、`bi*`を3つの値と3つのクォーテーションに拡張し、各クォーテーションを順番に1つの値へ適用します。

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```

[combinators]: https://docs.factorcode.org/content/vocab-combinators.html
