# ヒント

## 全般

- 解答ファイルは、マクロを呼び出す別のファイルに読み込まれます。
  各マクロの名前と引数の順序は、タスクで示されたとおりに正確に保ってください。そうしないと、ファイルをアセンブルできません。
- マクロの引数はトークンで、本体のどこに現れても`%1`、`%2`、`%3`として置き換えられます。
  それぞれの展開が有効な命令になるのであれば、引数はレジスターでも、アドレス式でも、リテラルでもかまいません。
- 各マクロは、何を書き込むかだけでなく、どのレジスターを変更せずに残すかについてもチェックされます。
  各タスクの破壊に関する注記を読み、許可されているレジスターだけを変更してください。

## 1. フォーマット定数に名前を付ける

- 1行の`%define`は値に名前を付けるので、残りのコードは裸の数値の代わりにその名前を読むことができます。
  固定の数値には`equ`が同じことをし、定数にはこちらがふつうの選択です。
- バイト定数は、16進数（`0x20`）でも文字リテラル（`' '`）でも書けます。
  どちらも同じ値にアセンブルされます。

## 2. `fill_run`マクロを書く

- `rcx`には読みやすい名前`COUNTER`を付けるとよいでしょう。
- `fill_run`は3つの引数を取る複数行マクロです。
  複数行マクロは`%macro ... %endmacro`で定義します。
- `fill_run`の第1引数は、64ビット汎用レジスターに入ったメモリーアドレスです。
  第2引数はカウントで、64ビット汎用レジスターでも即値でも渡せます。
  第3引数は書き込むバイトで、即値です。
  これらの仕様を踏まえて、マクロ内のコードを組み立てましょう。
- `fill_run`が変更してよいレジスターは`COUNTER`だけです。
- マクロ内のループには、ふつう`%%`を先頭に付けたラベルが必要です。
  この接頭辞がないと、マクロが呼び出されるたびに同じラベルが作られてしまい、マクロを2回以上呼び出すとエラーの原因になります。

## 3. `lay_columns`マクロを書く

- `lay_columns`は2つの引数を取る複数行マクロです。
  複数行マクロは`%macro ... %endmacro`で定義します。
- `lay_columns`の引数はどちらも64ビット汎用レジスターで渡されます。
  第1引数はメモリーアドレス、第2引数は整数です。
  これらの仕様を踏まえて、マクロ内のコードを組み立てましょう。
- `lay_columns`が変更してよいレジスターは、引数として渡された2つだけです。
- マクロが書き込まなければならないオフセットの数は、アセンブル時に決まっています。
  コードを繰り返すには`%rep ... %endrep`を使えます。
- オフセットの計算は`offset[i] = margin + i * COLUMN_STRIDE`で行います。
  `margin`はマクロの第2引数です。
  `i`はループカウンターで、`%assign`変数として定義できます。

## 4. `set_header`マクロを書く

- `set_header`は2つの引数を取る複数行マクロです。
  複数行マクロは`%macro ... %endmacro`で定義します。
- `set_header`の第1引数は、実効メモリーアドレスを表す式です。
  これは、`1`、`2`、`4`、`8`のいずれかでスケールされたインデックスレジスターと足し合わせられるベースレジスターと、即値を取ります。
  つまり、`rdi`をそのまま書いても、`rdi+rax*4+2`と書いても有効です。
- `set_header`の第2引数は即値で、値は`0`、`1`、`2`のいずれかです。
- `set_header`はどのレジスターも一切変更してはいけません。
- 第2引数に応じて、アセンブル時に条件付きで1バイトを宛先アドレスへコピーするとよいでしょう。
  値が`0`なら`PLAIN`を、`1`なら`RULED`を、`2`なら`BOXED`をコピーします。
