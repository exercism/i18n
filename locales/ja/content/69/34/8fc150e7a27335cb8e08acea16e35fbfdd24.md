# はじめに

**単一命令複数データ（SIMD）** は、ハードウェアレベルの並列性の一種です。
同じ計算を、CPUが複数の要素に対して同時に実行します。

たとえば、4つの32ビット浮動小数点数からなる2つの配列を要素ごとに足し合わせることを考えてみましょう。
スカラー実装では、要素ごとに4つの`addss`命令を別々に発行します。
SIMD実装では、1つの`addps`で4つの加算をすべて並列に行います。
これにより、1命令あたり4倍の処理ができることになります。

x86-64アセンブリでは、SIMD命令は通常`xmm`レジスタを使って実行されます。
これらの命令のなかには、整数を扱うものもあります。
浮動小数点数を扱うものもあります。

これらの整数や浮動小数点数は、**パック**と呼ばれます。
それぞれが同じレジスタ内の**レーン**と呼ばれる場所を占めます。
SIMD命令は通常、2つのソースオペランドの同じレーン位置にある値を並列に操作します。
各演算の結果は、デスティネーションオペランドの同じ位置のレーンに格納されます。

レーンは固定された限界ではありません。
各命令がバイト列に対して与える解釈です。
128ビットのオペランドには16バイトが含まれます。
命令によって、これらのバイトは16個の_1バイト_レーン、8個の_2バイト_レーン、4個の_4バイト_レーン、2個の_8バイト_レーン、あるいは1個の_16バイト_レーンとして解釈できます。

たとえば、`addps`命令はパックされた単精度（4バイト）の浮動小数点数を加算します。
この命令では、オペランド内の4バイトごとのまとまりがそれぞれ異なるレーンになります。
128ビット幅（16バイト）のオペランドでは、次のようになります。

| オペランド | 4番目のレーン | 3番目のレーン | 2番目のレーン | 1番目のレーン |
|:-----------:|:--------:|:--------:|:--------:|:--------:|
| ソース1 | 1.5 | 2.1 | 6.2 | 3.4 |
|    +        |  +       |  +       | +        | +        |
| ソース2 | 0.5 | 8.26 | -13.4 | 22.9 |
|    =        |  =       |  =       | =        | =        |
| 結果 | 2.0 | 10.36 | -7.2 | 26.3 |

一方、`mulpd`の場合、128ビットのオペランドは2つのレーンを持つものとして解釈されます。
これは、この命令が倍精度（8バイト）の値に対してパック乗算を行うためです。

| オペランド | 2番目のレーン | 1番目のレーン |
|:-----------:|:--------:|:--------:|
| ソース1 | 4.2 | 2.1 |
|    *        |  *       |  *       |
| ソース2 | 1.0 | 92.4 |
|    =        |  =       |  =       |
| 結果 | 4.2 | 194.04 |

このコンセプトでは、SIMD命令のなかからいくつかを取り上げます。
これらは`xmm`レジスタを使って、パックされた浮動小数点数を操作します。

## 浮動小数点のSIMD命令

おおまかに言うと、浮動小数点数を操作するSIMD命令は2オペランド形式をとります。
その名前は、次のような構造に従います。

1. 実行する操作。非SIMD（_スカラー_とも呼ばれます）の対応する命令と同じ名前です（例：`add`、`mul`など）。
2. `p`という接尾辞。命令が_パック_データを操作することを示し、以前は（_スカラー_データを表す）`s`があった同じ位置に付きます。
3. 各レーンのサイズを示す接尾辞。非SIMDの対応する命令と同じ意味を持ちます（単精度なら`s`、倍精度なら`d`）。

したがって、パック版の名前は、スカラー版の名前のニーモニック中央にある`s`（スカラー）を`p`（パック）に置き換えることで得られます。
操作名とサイズの接尾辞は変わりません。

| スカラー | パック | 意味 |
|---------|---------|----------------------------------------|
| `addss` | `addps` | 加算、単精度（32ビットレーン） |
| `addsd` | `addpd` | 加算、倍精度（64ビットレーン） |
| `mulss` | `mulps` | 乗算、単精度 |
| `mulsd` | `mulpd` | 乗算、倍精度 |

### 算術演算

算術SIMD命令は、上記の規則に従います。
いくつかの例を見てみましょう。

```x86asm
addps xmm0, xmm1 ; xmm0 = xmm0 + xmm1 (each 32-bit float at the same position)
subpd xmm2, xmm3 ; xmm2 = xmm2 - xmm3 (each 64-bit float at the same position)
mulps xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (each 32-bit float at the same position)
divpd xmm6, xmm7 ; xmm6 = xmm6 / xmm7 (each 64-bit float at the same position)
```

### 精度間の変換

パックされた単精度とパックされた倍精度の浮動小数点数の間で変換を行うSIMD命令もあります。
これらも同じ命名規則に従い、_スカラー_を表す`s`が_パック_を表す`p`に置き換わります。

| スカラー | パック | 意味 |
|------------|------------|----------------------------------------------|
| `cvtss2sd` | `cvtps2pd` | 単精度から倍精度への変換 |
| `cvtsd2ss` | `cvtpd2ps` | 倍精度から単精度への変換 |

これらの命令は、レーンは解釈であって固定された限界ではない、という先ほどのポイントをよく示しています。
ソースオペランドとデスティネーションオペランドではレーンのサイズが異なるため、レーンの数も異なります。

`cvtps2pd`の場合、ソース（`ps`）は4つの単精度レーンを持ちます。
デスティネーション（`pd`）は2つの倍精度レーンを持ちます。
ソースの下位2レーンだけが読み込まれます。
上位2レーンは無視されます。

| オペランド | 4番目のレーン | 3番目のレーン | 2番目のレーン | 1番目のレーン |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| `ps`としてのソース | 無視 | 無視 | 2.5 | 1.5 |
| `pd`としてのデスティネーション |          |          | 2.5 | 1.5 |

`cvtpd2ps`の場合、ソース（`pd`）は2つの倍精度レーンを持ちます。
デスティネーション（`ps`）は4つの単精度レーンを持ちます。
ソースの両方のレーンが変換され、デスティネーションの下位2レーンに書き込まれます。
デスティネーションの上位2レーンは0に設定されます。

| オペランド | 4番目のレーン | 3番目のレーン | 2番目のレーン | 1番目のレーン |
|:--------------------:|:--------:|:--------:|:--------:|:--------:|
| `pd`としてのソース |          |          | 4.0 | 3.0 |
| `ps`としてのデスティネーション | 0 | 0 | 4.0 | 3.0 |

いくつかの例を見てみましょう。

```x86asm
cvtps2pd xmm0, xmm1 ; xmm0 = xmm1 as 2 doubles (low 2 lanes of xmm1 are read)
cvtpd2ps xmm0, xmm1 ; xmm0 = xmm1 as 2 floats (in low 2 lanes; upper 2 zeroed)
```

### メモリオペランド

上記のSIMD命令は、すべてレジスタ間オペランドで示してきました。
ソースとしてメモリオペランドを取ることもできますが、デスティネーションには**できません**。

メモリから読み込まれるバイト数は、命令によって決まります。
たとえば、`addps`は16バイト（単精度浮動小数点数4個）を読み込みます。
一方、`cvtps2pd`は8バイト（単精度浮動小数点数2個）だけを読み込みます。それだけの入力があれば十分だからです。

```x86asm
addps    xmm0, [rsi]      ; xmm0 = xmm0 + 4 floats at [rsi]
mulpd    xmm1, [rsi + 16] ; xmm1 = xmm1 * 2 doubles at [rsi + 16]
cvtps2pd xmm2, [rsi + 8]  ; xmm2 = (2 floats at [rsi + 8]) converted to 2 doubles
```

メモリオペランドが16バイト幅の場合、_16バイトに整列_している必要があります。
整列されたメモリ位置とは、そのアドレスが操作のサイズ（この場合は16バイト）の倍数である場所のことです。

整列されたメモリを宣言するには、.dataセクションと.rodataセクションでは`align`ディレクティブを、.bssセクションでは`alignb`を使うことができます。

```x86asm
section .rodata
align 16
mem1: dd 4.0, 3.5, 2.0, -1.0

section .data
align 16
mem2: dq 6.0, 2.1

section .bss
alignb 16
mem3: resb 16

section .text
fn:
    movaps xmm0, oword [rel mem1] ; loads 4 packed 32-bit floats in xmm0
    movapd xmm1, oword [rel mem2] ; loads 2 packed 64-bit floats in xmm1
    movaps oword [rel mem3], xmm0 ; stores 4 packed 32-bit floats in mem3
    ret
```

`cvtps2pd`の8バイトのソースのように、16バイトより小さいメモリオペランドには整列の要件はありません。

### 値のロードとストア

パックされた浮動小数点数128ビットをコピーする命令が4つあります。
これらは2つの`xmm`レジスタ間、または1つの`xmm`レジスタとメモリ位置の間で動作します。

| 命令 | 説明 |
|-------------|-----------------------------------------------------------------------------------|
| `movaps`    | パックされた単精度データを、_整列された_メモリ位置との間でコピーします |
| `movups`    | パックされた単精度データを、_整列されていない_メモリ位置との間でコピーします |
| `movapd`    | パックされた倍精度データを、_整列された_メモリ位置との間でコピーします |
| `movupd`    | パックされた倍精度データを、_整列されていない_メモリ位置との間でコピーします |

これらの命令はすべて、2つの`xmm`レジスタ間で値をコピーするのに使えます。

操作にメモリ位置が関わる場合、`movaps`と`movapd`はそれが_整列_されていることを要求します。
`movaps`と`movapd`は、整列されていないアドレスを渡されるとフォールトを発生させます。
これらは、データの配置が想定どおりであるかを確認する安全チェックの役割も果たします。

一方、`movups`と`movupd`は、整列されているかどうかに関わらず、どのメモリ位置でも使えます。

NASMで16バイトの値に付けるサイズプレフィックスは`oword`です。

## SIMD拡張

SIMDは、何十年にもわたってx86-64エコシステムで活発に開発されてきた対象です。
アーキテクチャへの拡張はそれぞれ、新しい命令や、古い命令の新しい使い方をもたらします。

とくに、AVXとAVX2という拡張は、いくつかの重要な変更をもたらします。

第一に、`ymm`と呼ばれる256ビットSIMDレジスタのサポートです。
これらは、`rax`が`eax`を含むのと同じように、対応する`xmm`レジスタを拡張したものです。

第二に、`xmm`（および`ymm`）レジスタを操作するほとんどの命令で、3オペランド版がサポートされます。
これにはSIMD命令だけでなく、スカラー浮動小数点数を操作する命令も含まれます。
これらの版は、SSE版と同じ表記に、先頭に`v`を付けたものになります。

```x86asm
vaddsd xmm0, xmm1, xmm2   ; xmm0 = xmm1 + xmm2 (scalar sum of 64-bit floats)
vmulps xmm1, xmm3, xmm4   ; xmm1 = xmm3 * xmm4 (packed multiplication of 32-bit floats)
vmovupd ymm5, yword [mem] ; this copies 32 bytes from the location at mem to ymm5
```

第三に、SIMDメモリオペランドに求められる整列の要件が緩和されます。
`vmovaps`のような、明示的に整列されたムーブだけが、この整列を必要とします。

このトラックでは、以前のSSE拡張までの命令とレジスタに限定しています。
これは基礎を教えるのに十分で、幅広いCPUとの互換性を確保できます。

ただし、テストランナーはAVXとAVX2、さらにはAVX-512に含まれる新しい拡張まで完全にサポートしています。
自由に使ってかまいません。

~~~~exercism/note
SIMDの派生を使うときは、一貫性を保つのがよい習慣です。
同じ命令に対してSSEとAVXの派生を混ぜないようにしましょう。

コードベースでこれらの派生を混在させる場合は、AVXを使った作業を終えたあと、SSEを使う前に`vzeroupper`を使うのがよい習慣です。
これにより依存関係の連鎖が切れ、CPUがAVXとSSEの状態間を移行するときの高コストなストールを避けられます。
~~~~
