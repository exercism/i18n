# 概要

`String`の個々の文字には、配列で使われるのと同じサブスクリプトの方法でアクセスできます。
しかし、文字列で使う[インデックス][string-indices]は_整数ではなく_、そのまま直接扱うことはできません。
代わりに、`startIndex`のような、何か他のわかっているインデックスをもとに計算する必要があります。`startIndex`は、空でない文字列の最初の文字の位置を指します。計算には、[`String`][string-docs]と[`NSString`][nsstring-docs]のライブラリで利用できるメソッドを使います（`Foundation`モジュールをインポートすると、Swiftの文字列はNSStringのすべてのプロパティとメソッドを利用できるようになります）。

たとえば、次の文字列を考えてみましょう。

```swift
let csv = "apple,pear,peach,orange,cherry,lime,goosberry"
```

「orange」の「g」を取り出すために`csv[21]`と書くことはできません。代わりに、`String.Index`型の値を計算し、そのインデックスを渡す必要があります。
これらのインデックスは、それ自体を人間が読むためのものではないことに注意してください。
これらは_不透明なインデックス_と呼ばれるもので、中に何が入っているかを人間が知る必要はありません。

```swift
let index = csv.index(csv.startIndex, offsetBy: 21)
csv[index]
// "g"
print(index)
// prints Index(_rawBits: 1376513)
```

ただし、オフセットが有効なインデックスでない場合、つまり`startIndex`より前や`endIndex`より後のインデックスを返す場合、この操作はエラーになり、プログラムがクラッシュします。
この問題を防ぐには、制限するインデックスを指定します。
これはオプショナルのインデックスを返し、それ以外の無効なインデックスに対してはnilを返します。

```swift
let tooFar = csv.index(csv.startIndex, offsetBy: 200)
// error: Execution was interrupted, reason: EXC_BAD_INSTRUCTION (code=EXC_I386_INVOP, subcode=0x0).
let tooFarButSafe = csv.index(csv.startIndex, offsetBy: 200, limitedBy: csv.endIndex)
// nil
```

さらに、インデックスは文字列間で共有できません。
たとえば、上で計算した「orange」の「g」の`index`を使って文字列`fam = "This is my family: 👨‍👩‍👦‍👦, this is our dog: 🐶, this is our cat: 🐱!"`、つまり`fam[index]`にインデックスでアクセスすると、プログラムがクラッシュします。

これにはいろいろな理由がありますが、突き詰めれば「Unicodeは厄介」ということになります。

一般的に、個々の文字にランダムアクセスする必要があるなら、`Array<Character>`のような別のデータ構造を使うのがよいでしょう。

## 便利なメソッド

Swiftには、文字列の最初と最後の文字を取得する`first`と`last`というメソッドがあります。
これらのメソッドはオプショナルの文字を返すので、文字列が空の場合はnilを返します。

```swift
let str = "Hello, world!"
print(str.first) // Prints Optional("H")
print(str.last)  // Prints Optional("!")
```

`prefix`と`suffix`メソッドを使って、文字列の部分文字列を取得することもできます。
これらのメソッドは整数を引数に取り、文字列の最初または最後のn文字を含む部分文字列を返します。

```swift
let str = "Hello, world!"
print(str.prefix(5)) // Prints "Hello"
print(str.suffix(6)) // Prints "world!"
```

## 深掘り：Unicodeのインデックス

~~~~exercism/advanced

[Unicode][unicode]はテキストを符号化するための規格で、さまざまな言語や文字体系のたくさんの文字を含んでいます。
ASCIIの上位集合なので、すべてのASCII文字はUnicode文字でもあります。
Unicodeは可変長の符号化方式で、文字によって使うバイト数が異なります。
なぜそれが重要なのかは、次の節で説明します。

そこで、この問題を実際に見るために、英語以外の言語に目を向けてみましょう。ドイツ語の文字「ü」を取り上げます（ここでは2バイトのほうを使っていますが、1バイトの版もあります）。
一見すると1文字に見えますが、実際には「u」と「¨」の2文字です。なので「ü」という文字列の長さを表示すると、Pythonのような言語では2になります。
しかし、ユーザーやプログラマーとしてはこれを1文字と考えるでしょうし、Swiftも実際にそう考えます。
では、なぜSwiftはそうしてPythonはそうしないのでしょうか？
答えは、SwiftがPythonとは異なる文字列の表現を使っているからです。
Pythonでは、文字列はバイトの並びとして表されるので、文字列の長さはメモリ上で占めるバイト数になります。
Swiftでは、文字列は文字の並びとして表されるので、文字列の長さは含まれる文字数になります。
これはとても重要な違いです。というのも、Swiftでは文字列の長さは、メモリ上で占めるバイト数と同じとは限らないからです。
そしてこれが、整数で文字列のインデックスを指定できない理由です。
~~~~
