# はじめに

## タプル

Elixirでは、タプルはデータをまとめるデータ構造のひとつで、どんな型の要素でも決まった個数だけ保持できます。ただし、それぞれの要素に名前はありません。タプルは、メモリからの読み取りが多い処理でよく使われます。要素への読み取りアクセスが定数時間で済むからです。一方、要素を動的に追加したり削除したりする場面では、ふつう使いません。既存のタプルを変更するのではなく新しいタプルを作ることになり、そのぶんメモリを前もって確保しなければならないからです。

実際には、タプルは波括弧（`{}`）を使って作ります。タプルの要素には、`elem/2`関数と0から始まるインデックスを使って個別にアクセスできます。

```elixir
empty_tuple = {}
one_element_tuple = {1}
multiple_element_tuple = {1, :a, "hello"}

elem(multiple_element_tuple, 2)
# => "hello"
```

### まとまった情報としてのタプル

タプルは、まとまった情報を表すのによく使われます。

```elixir
Float.ratio(0.25)
# => {1, 4} indicating the numerator and denominator of the fraction ¼
```

## パターンマッチング

パターンマッチングは、断定的で慣用的なElixirのコードで中心的に使われます。`=/2`は代入演算子ではなくマッチ演算子と呼ばれているのを覚えているでしょうか。マッチ演算子を使うとき、左辺のパターンが右辺とマッチすれば、左辺の変数が束縛され、右辺の値が返ります。マッチしなければ、`MatchError`が発生します。

```elixir
2 = 2
# => 2
# Literals can be matched if they are the same

2 = 3
# => ** (MatchError) no match of right hand side value: 3

{_, denominator} = Float.ratio(0.25)
# => {1, 4}
# the variable `denominator` is bound to the value 4
```

マッチは右辺から左辺へと行われることを覚えておきましょう。

最後の例で、パターンマッチに変数が必要ない場合は、`_`を参照して捨てることができます。`_`で始まる変数は、ランタイムには追跡されません。

### 名前付き関数でのパターンマッチング

パターンマッチングは、複数の関数節を作るときにも役立つ道具です。関数の引数に対してパターンマッチングを使うと、どの関数節を呼び出すかが決まります。ファイルの先頭から順に見ていき、最初にマッチした節が選ばれます。変数は関数ヘッドで束縛し、関数本体で使えます。

```elixir
defmodule Example do
  def named_function(:a = variable_a) do
    {variable_a, 1}
  end

  def named_function(:b = variable_b) do
    {variable_b, 2}
  end
end

Example.named_function(:a)
# => {:a, 1}

Example.named_function(:b)
# => {:b, 2}

Example.named_function(:c)
# => ** (FunctionClauseError) no function clause matching in Example.named_function/1
```
