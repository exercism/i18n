# 説明

自動車部品工場の現場で動くデータシステムのコードを書いていきます。
エンジンやシャシーの部品は、いくつもの加工ステーションを通っていきます。
各ステーションは測定値を出力し、次の工程に進む前に、それを足し合わせたり、比べたり、校正したり、正規化したりする必要があります。
ここで実装する関数は、ステーションごとに1つずつです。

~~~~exercism/note
この演習の計算には、スカラー演算ではなくSIMD命令を使います。
~~~~

## 1. 2つのラインの歩留まりを合計する

工場の現場では、2本の組立ラインが並行して動いています。
各シフトの終わりに、両方のラインが4つの部品ビンごとの歩留まりを単精度の数値で報告します。
監督者のダッシュボードにはビンごとの合計歩留まりが表示されるので、2つのレポートをビン単位で足し合わせます。
3つのバッファーはすべてレポートシステムが管理していて、常に16バイト境界に整列しています。

`line_a`と`line_b`のビンごとの歩留まりを受け取り、ビンごとの合計を`result`に書き込む関数`sum_yields`を定義します。
引数は、順に次のとおりです。

1. `line_a`: 4つの32ビット浮動小数点数を保持する、16バイト境界に整列したメモリアドレス
2. `line_b`: 4つの32ビット浮動小数点数を保持する、16バイト境界に整列したメモリアドレス
3. `result`: 関数が4つの32ビット浮動小数点数を書き込む、16バイト境界に整列したメモリアドレス

この関数は戻り値を返しません。その代わり、結果は渡されたバッファー（`result`）に格納されます。

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. スケーリングした偏差を計算する

工程と工程の間で、サンプリングステーションが加工済みの部品を測定し、目標寸法と比べます。
測定値は精密ゲージから、常に16バイト境界に整列したバッファーに流れ込みます。
目標値は作業指示パケットから来ますが、こちらは整列が保証されていません。
偏差は、下流の公差チェッカーに渡される前に、軸ごとの感度係数を掛けられます。
この段階では、下流のチェッカーは偏差をメモリからではなくSIMDレジスタから直接読み取ります。

`measured`と`target`、そして`sensitivity`を受け取り、スケーリングした偏差を`result`に書き込む関数`scaled_deviation`を定義します。
引数は、順に次のとおりです。

1. `measured`: 2つの64ビット浮動小数点数を保持する、16バイト境界に整列したメモリアドレス
2. `target`: 2つの64ビット浮動小数点数を保持するメモリアドレス（整列は保証されていません）
3. `sensitivity`: 2つの64ビット浮動小数点数を保持するメモリアドレス（整列は保証されていません）
4. `result`: 関数が2つの64ビット浮動小数点数を書き込むバッファー用のメモリアドレス（整列は保証されていません）

スケーリングした偏差は、レーンごとに`(measured - target) * sensitivity`です。

この関数は戻り値を返しません。その代わり、結果は渡されたバッファー（`result`）に、2つの64ビット浮動小数点数として格納されます。

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. バッチを校正する

部品が最終検査ベイに入る前に、4つの部品からなるバッチの寸法測定値が倍精度にスケールし直され、既知の温度ドリフトが補正されます。

4つの生の測定値は単精度の数値として届きます。
測定値2つを1行として、校正では`reference / (raw - offset)`を計算し、その結果に一定の変換係数`0.5`を掛けます。

基準値とオフセットは、バッチの両方の行で同じであることに注意してください。
変換係数はどの校正でも同じなので、引数として受け取るのではなく、メモリ上にパックされた16バイトの定数として宣言します。

生のバッチ`raw`、`reference`、`offset`、そして`result`バッファーを受け取り、校正した値を`result`に書き込む関数`calibrate_batch`を定義します。
引数は、順に次のとおりです。

1. `raw`: 4つの32ビット浮動小数点数を保持するメモリアドレス（整列は保証されていません）
2. `reference`: 2つの64ビット浮動小数点数を保持する、16バイト境界に整列したメモリアドレス
3. `offset`: 2つの64ビット浮動小数点数を保持する、16バイト境界に整列したメモリアドレス
4. `result`: 関数が4つの64ビット浮動小数点数（合計32バイト）を書き込む、16バイト境界に整列したメモリアドレス

この関数は、バッチの2つの行それぞれについて、次の処理を行います。

1. その行の2つの単精度の生の値を倍精度に変換します。
2. 変換したペアから`offset`を引きます。
3. `reference`をその結果で割ります。
4. 各64ビット浮動小数点数に、固定の変換係数`0.5`をレーンごとに掛けます。
5. 2つの64ビット浮動小数点数を、`result`の対応する16バイトに格納します。

この関数は戻り値を返しません。その代わり、結果は渡されたバッファー（`result`）に格納されます。

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. ライン上のスコアを正規化する

ラインの終わりでは、どの部品にも品質スコアがあり、報告される前に正規化する必要があります。
各スコアは部品ごとのゲインを掛けられ、次に軸ごとの生産スケールで割られます。
ゲインバッファーには、部品ごとに1つのゲインが入っています。

生産スケールは実行全体を通して同じで、2つの64ビット浮動小数点数を保持するメモリアドレスとして渡されます。
スコアは**その場で**更新されます。生のスコアが入っていたのと同じバッファーに、正規化したスコアが入ります。

`scores`配列、`gains`配列、`scale`、そして個数`n`を受け取り、スコアをその場で正規化する関数`normalize_scores`を定義します。
引数は、順に次のとおりです。

1. `scores`: `n`個の64ビット浮動小数点数を保持する、16バイト境界に整列したメモリアドレス（その場で変更されます）
2. `gains`: `n`個の64ビット浮動小数点数を保持する、16バイト境界に整列したメモリアドレス
3. `scale`: 2つの64ビット浮動小数点数を保持する、16バイト境界に整列したメモリアドレス
4. `n`: 正規化するスコアの個数で、64ビットの正の偶数（最小値は`2`）

スケールの2つのレーンは、各ペアの2つの要素にそれぞれ適用されます。
1つ目のレーンは各ペアの1つ目の要素（偶数位置のレーン）をスケーリングし、2つ目のレーンは2つ目の要素（奇数位置のレーン）をスケーリングします。
各スコアは対応するゲインを掛けられ、次に適切なスケールのレーンで割られます。つまり`score * gain / scale_lane`です。

この関数は戻り値を返しません。その代わり、結果は入力バッファー（`scores`）の、正規化された対応する`score`と同じ位置に格納されます。

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
