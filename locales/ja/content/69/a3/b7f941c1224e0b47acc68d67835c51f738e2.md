# コードを書く

コードは`src/lib.rs`に書きます。
演習には`src/lib.rs`にスタブファイルが用意されていて、これから書く必要のあるコードのシグネチャを確認できます。

ほとんどの演習では、コードはすべて`src/lib.rs`というファイルに書くのがよいでしょう。
解答を複数のファイルに分けたい場合は、Rustの本の[モジュールの章][chapter-modules]を参照してください。

[chapter-modules]: https://doc.rust-lang.org/book/ch07-02-defining-modules-to-control-scope-and-privacy.html

## テストを実行する

テストを実行するには、次のコマンドを実行するだけです。

```bash
$ cargo test
```

デフォルトでは、最初のテストだけが有効になっています。
次のテストに合格する準備ができたら、次のテストからignoreフラグ（`#[ignore]`）を外します。
好みに応じて、すべてのテストから一度にフラグを外してもかまいません。

テストに合格するために、できるだけ少ないコードを書いてかまいません。
テストの失敗が、次に何を書くべきかを教えてくれます。

Rustはコンパイル時にすべてのコードをチェックするので、必要なコードを書くまでテストがコンパイルできないことがあります。
`ignore`されたテストもコンパイル時にチェックされます。
コンパイルできないテストは、各行の先頭に`//`を付けて[コメントアウト][comments]できます。
そして、そのテストに取り組む準備ができたら、コメントを外します。
Rustには`todo!()`という特別なマクロもあり、未完成のコードパスに使うとプログラムをコンパイルできるようにできます。

[comments]: https://doc.rust-lang.org/book/ch03-04-comments.html

## ライブラリを使う

ほとんどの演習は、外部ライブラリを使わずに解けるはずです。
それでも、演習のディレクトリで`cargo add crate-name`を実行すれば、ライブラリ（Rustコミュニティでは**クレート**と呼びます）を追加できます。

ウェブサイト上の自動テストが対応しているのは、あらかじめ決められたクレートのセットだけです。その一覧は[こちら][local-registry]の`[dependencies]`セクションにあります。
特定のクレートのサポートを追加してほしい場合は、気軽にissueやpull requestを送ってください。

[local-registry]: https://github.com/exercism/rust-test-runner/blob/main/local-registry/Cargo.toml
