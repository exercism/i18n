# はじめに

## リテラルのパターンマッチング

`if/else`式でも条件分岐を実行できますが、Haskellにはもっと強力な方法があります。それが[パターンマッチング][pattern-matching]です。
パターンマッチングを使うと、1つの値を1つ以上の_パターン_と照合できます。
そのようなパターンの例が_定数パターン_で、これは値を定数（たとえば`1`や`"hello"`）と照合します。

関数を定義するときは、パターンごとに別々の関数本体を定義できます。
こうすると、シンプルで読みやすい、きれいなコードになります。
数値、文字、リスト、タプルなど、あらゆるデータ型に対してパターンマッチングできます。

たとえば、整数（`Int`）を受け取り、それを_0_に_1_だけ近づける単純な関数は、次のように書けます：

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero 1 = 0
```

パターンマッチングは、他のパターン、たとえば_変数パターン_と組み合わせると真価を発揮します：

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero n = n - 1
```

上の例では、_0_以外のすべての入力を同じように扱うため、負の数に対しては誤った結果を返します。
これは、_ガード_と呼ばれる条件付きパターンを使えば解決できます。ガードは`|`記号で表します：

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
```

上の例では、すべての可能な入力に一致するパターンがあるわけではありません。
コンパイラーがこれを検出し、警告を出力します。
これはHaskellのとても便利な機能で、実行時エラーを避けるためにすべての可能な経路が網羅されていることを確認するのに役立ちます。
これは_網羅性チェック_と呼ばれます。
警告を解消するには、すべてのケースを処理する必要があります。
_ガード_の中では、残りのすべてのパターンを受け止めるために、`True`の糖衣構文として`otherwise`という式を使えます。

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
    | otherwise = 0
```

パターンマッチングでは、値が上から下へ順に各パターンと照合され、一致するパターンが見つかると、そのパターンに対応するロジックが実行されます。
**パターンの順番は重要です！**
