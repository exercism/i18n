# はじめに

## プロセス

Elixirでは、すべてのコードはプロセスの中で実行されます。

デフォルトでは、関数は呼び出されたプロセスと同じプロセスで実行されます。ある関数を新しいプロセスで明示的に実行したいときは、`spawn/1`を使います。

```elixir
spawn(fn -> 2 + 2 end)
# => #PID<0.125.0>
```

`spawn/1`は、与えられた0引数の関数を実行する新しいプロセスを作り、_プロセス識別子_（PID）を返します。新しいプロセスは、その関数が実行されている間は生き続け、その後は静かに終了します。

Elixirのプロセスは、オペレーティングシステムのプロセスと混同しないでください。Elixirのプロセスは、はるかに少ないメモリとCPUしか使いません。何百ものElixirプロセスを動かすElixirアプリケーションがあっても、まったく問題ありません。

### メッセージ

プロセス同士は、情報を直接共有することはありません。データを共有するために、プロセスは_メッセージを送受信_します。

`send/2`を使えば、どんなプロセスにもメッセージを送ることができます。`send/2`の最初の引数は受信者のPIDで、2番目の引数がメッセージです。

メッセージはどんな型でもかまいません。多くの場合、アトムとタプルでできています。返事を受け取りたいときは、メッセージのどこかに送信者のPIDを含めておきます。現在のプロセスのPIDは`self()`で取得できます。

`send/2`は、メッセージが受信者に届いたかどうかも、受信者がまだ生きているかどうかも確認しません。メッセージは受信者の_メールボックス_に入り、受信者が明示的に_メッセージを受信_しようとしたときにだけ読み出されます。

メッセージは、`receive/1`マクロを使ってメールボックスから読み出すことができます。`receive/1`は、メッセージを[パターンマッチ][exercism-pattern-matching]できる`do`ブロックを受け取ります。

```elixir
receive do
  {:ping, sender_pid} -> send(sender_pid, :pong)
  :do_nothing -> nil
end
```

`receive/1`は、与えられたパターンのいずれかにマッチするメッセージを_1つ_メールボックスから取り出し、そのパターンに対応する式を実行します。メールボックスにメッセージがない場合、またはどのメッセージもどのパターンにもマッチしない場合、`receive/1`はメッセージを待ちます。

### 受信ループ

複数のメッセージを受け取りたいときは、`receive/1`を再帰的に呼び出す必要があります。たとえば`loop`という名前の再帰関数を実装し、それが`receive/1`を呼び出し、メッセージに対して何か処理をしてから、さらにメッセージを待つために自分自身を呼び出す、というのはよくあるパターンです。`receive/1`の呼び出しから次の呼び出しへ状態を持ち越したいときは、その`loop`関数に引数を渡すことで実現できます。

## PID

プロセス識別子は、それ自体が1つのデータ型です。これは_メールボックスのアドレス_として機能します。プロセスのPIDがわかれば、そのプロセスにメッセージを送ることができます。PIDは通常、`spawn`のように新しいプロセスを作る関数の戻り値として、間接的に生成されます。
