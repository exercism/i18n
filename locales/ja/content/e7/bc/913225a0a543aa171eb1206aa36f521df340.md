# テストジェネレーター

テストジェネレーターを使うと、トラックはテストを自分で書かなくても、テストを自動的に生成できます。それぞれのテストジェネレーターは、演習の`canonical data`から読み取ります。ここにはテストの名前、入力、出力が定義されています。Exercismのテストスイートへの取り組みについては、[こちら](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md)で詳しく読めます。

テストを自動で生成すれば、テストを作成するときの人為的なミスをなくせます。テストは、そのcanonical dataと正確に一致しているべきです。テストの生成は、テストを最新の状態に保つのもずっと楽にしてくれます。canonical dataが変わると、そのテストのジェネレーターを実行したときに、テストも自動的に更新されます。

canonical dataファイルの例は[こちら](https://github.com/exercism/problem-specifications/blob/master/exercises/bob/canonical-data.json)にあります。

## よく使う用語

canonical dataやジェネレーターのコードを読んでいると、よく使う用語がたくさん出てきます。このリストが、それぞれ何を表しているのかを整理する助けになればと思います。

* canonical data：テストスイート全体を表します。
* canonical data case：1つのテストケースを表したものです。
* 説明：テストの名前です。
* プロパティ：テストを実行するときに呼び出されるメソッドです。
* 入力：テストケースへの入力です。
* 期待値：テストケースを実行したときに期待される値です。

## シンプルなジェネレーターを追加する

テストジェネレーターの追加は簡単です。`generators`フォルダーにある`Generators.fs`ファイルに、演習の名前（PascalCase）を付けたクラスを追加し、`GeneratorExercise`抽象クラスを継承するだけです。

シンプルなジェネレーターの例としては、Bob演習があります。ソースコードは以下にありますが、リポジトリの[こちら](https://github.com/exercism/fsharp/blob/master/generators/Generators.fs#L174)でも見られます。

```fsharp
type Bob() =
    inherit GeneratorExercise()
```

これは完全に動作するジェネレーターで、ほかに書くコードはありません。ただ、これがシンプルなのは、テストスイートとプログラムそのものが比較的単純だからです。

## 複雑なジェネレーターを追加する

多くのジェネレーターでは、`GeneratorExercise`クラスのデフォルトの動作で十分です。ただ、より_複雑な_ジェネレーターでは、その仮想メソッドを1つ以上オーバーライドできます。

### メソッド: RenderInput

テストメソッドの入力をレンダリングします。

#### 例

`Gigasecond`ジェネレーターは、入力の値を、括弧（`()`）で囲んだ`DateTime`の値としてレンダリングします。

```fsharp
override __.RenderInput (_, _, value) =
    DateTime.Parse(string value, CultureInfo.InvariantCulture)
    |> DateTime.renderParenthesized
```

`key`フィールドを使えば、特定の入力フィールドだけ出力をカスタマイズできることに注目してください。`Yacht`ジェネレーターはこうしています。

```fsharp
override __.RenderInput (canonicalDataCase, key, value) =
    match key with
    | "category" -> Obj.renderEnum "Category" value
    | _ -> base.RenderInput (canonicalDataCase, key, value)
```

### メソッド: RenderExpected

テストメソッドの期待値をレンダリングします。

#### 例

`Connect`ジェネレーターは、期待値を`Option<T>`の値としてレンダリングします。

```fsharp
override __.RenderExpected (canonicalDataCase, key, value) =
    match string value with
    | "O" -> "(Some White)"
    | "X" -> "(Some Black)"
    | _   -> "None"
```

### メソッド: RenderSut

テスト対象のシステム（System Under Test、SUT）をレンダリングします。これは、期待値と照らし合わせて検証される実際の値です。

#### 例

`RunLengthEncoding`ジェネレーターには、入力をエンコードしてからデコードすると同じ値になることを検証するテストケースがあります。`RenderSut`メソッドは、存在しない`consistency`関数への1回の呼び出しになるはずのものを、`encode |> decode`の呼び出しの連鎖に変換するためにオーバーライドされています。

```fsharp
override this.RenderSut canonicalDataCase =
    match canonicalDataCase.Property with
    | "consistency" ->
        let parameters = this.RenderSutParameters canonicalDataCase |> String.concat " "
        sprintf "%s |> encode |> decode" parameters
    | _ ->
        base.RenderSut canonicalDataCase
```

### メソッド: RenderArrange

テストメソッドの準備部分をレンダリングします。この部分では、SUTが作られます。

デフォルトの動作で通常は十分です。これを変更したくなるのは、ごく特別な状況だけです。

注: このメソッドは`string list`を返します。それぞれの`string`は、テストファイルにレンダリングされた1行に対応します。

### メソッド: RenderAssert

テストメソッドのアサート部分をレンダリングします。この部分では、SUTを期待値と照らし合わせて検証するアサーションが行われます。

デフォルトの動作で通常は十分です。これを変更したくなるのは、ごく特別な状況だけです。

注: このメソッドは`string list`を返します。それぞれの`string`は、テストファイルにレンダリングされた1行に対応します。

### メソッド: RenderSetup

追加のユーティリティメソッドやセットアップメソッドをレンダリングします。テストメソッドで使えるヘルパーメソッドを定義するのに使えます。

セットアップのコードは、セットアップメソッドをテストメソッドで使えるようにするために、テストメソッドの_前に_追加されます。

注: このメソッドは`string list`を返します。それぞれの`string`は、テストファイルにレンダリングされた1行に対応します。

#### 例

`Zipper`ジェネレーターは、面倒な定型コードを減らすためにテストメソッドで使われるヘルパーメソッドを2つ追加します。

```fsharp
override __.RenderSetup _ =
    [ "let subTree value left right = Some (tree value left right)"
      "let leaf value = subTree value None None" ]
    |> String.concat "\n"
```

### メソッド: RenderValue

1つの値をレンダリングします（これは入力パラメーター、期待値、SUTのレンダリングに使われます）。

### 例

`ComplexNumbers`ジェネレーターは、値の型に応じて異なる値をレンダリングします。

```fsharp
override __.PropertiesWithIdentifier canonicalDataCase =
    match canonicalDataCase.Expected.Type with
    | JTokenType.Array -> ["sut"]
    | _ -> base.PropertiesWithIdentifier canonicalDataCase
```

### メソッド: MapCanonicalDataCase

canonical data caseをマップします。プロパティを追加したり削除したりしたいときに便利です。

デフォルトの動作で通常は十分です。これを変更したくなるのは、ごく特別な状況だけです。

#### 例

`ScaleGenerator`ジェネレーターは、canonical data caseのマッピングを使って、欠けているプロパティを`null`値として追加します（こうすると後の処理が楽になります）。

```fsharp
override __.MapCanonicalDataCase canonicalDataCase =
    let input = canonicalDataCase.Input
    match Map.tryFind "intervals" input with
    | Some _ -> canonicalDataCase
    | None   -> { canonicalDataCase with Input = Map.add "intervals" null input }
```

### メソッド: PropertiesUsedAsSutParameter

どのプロパティをSUTのパラメーターとして使うかを指定します。

デフォルトの動作で通常は十分です。これを変更したくなるのは、ごく特別な状況だけです。

#### 例

`RailFenceCipher`は、SUTのパラメーターとして使うプロパティを明示的に定義して、渡される順序を変えています。

```fsharp
override __.PropertiesUsedAsSutParameter _ = ["rails"; "msg"]
```

### メソッド: PropertiesWithIdentifier

どのプロパティに識別子を割り当てるかを指定します。プロパティがこのリストにあると、その値は別の行で、それ自身の識別子に割り当てられます。

#### 例

`Transpose`ジェネレーターは、すべてのプロパティに識別子を使うことを選んでいます。

```fsharp
override this.PropertiesWithIdentifier canonicalDataCase = this.Properties canonicalDataCase
```

### メソッド: IdentifierTypeAnnotation

場合によっては、識別子に明示的な型を付けたいことがあります。よくあるのは、値が空のリストのときです。そのような場合、FsUnitがアサーションを正しく実行するには型注釈が必要です。

#### 例

`Minesweeper`ジェネレーターは、空の値に`string list`の型注釈を追加します。

```fsharp
override __.IdentifierTypeAnnotation (_, _, value) =
    match Seq.isEmpty value with
    | true  -> Some "string list"
    | false -> None
```

### メソッド: AdditionalNamespaces

テストファイルで開く追加の名前空間のリストを返します。

#### 例

`Gigasecond`ジェネレーターは`DateTime`のインスタンスを扱うので、その名前空間を追加の名前空間のリストに加えます。

```fsharp
override __.AdditionalNamespaces = [typeof<DateTime>.Namespace]
```

### メソッド: AssertTemplate

使うアサートテンプレートです。アサートテンプレートの完全なリストは`generators/Templates/_Assert*.liquid`にあります。

#### 例

`RationalNumbers`ジェネレーターは、`"AssertEqualWithin"`テンプレートを使って、倍精度浮動小数点数が特定の許容誤差で等しいかを確認できるようにしています。

```fsharp
override __.AssertTemplate canonicalDataCase =
    match canonicalDataCase.Expected.Type with
    | JTokenType.Float -> "AssertEqualWithin"
    | _ -> base.AssertTemplate(canonicalDataCase)
```

### メソッド: TestFileFormat

テストファイルの形式です。モジュールかクラスのどちらかです。

デフォルトの動作でほぼ常に十分です。これを変更したくなるのは、ごくまれな場合だけです。

#### 例

`Grep`ジェネレーターは、セットアップメソッドとティアダウンメソッドを使えるようにするために、自身をテストクラスとして定義しています。

```fsharp
override __.TestFileFormat = TestFileFormat.Class
```

### メソッド: TestMethodName

テストメソッドの名前を指定します。

デフォルトの動作で通常は十分です。これを変更したくなるのは、ごく特別な状況だけです。

#### 例

`Zipper`ジェネレーターは、テストメソッド名を少し整理します。

```fsharp
override __.RenderTestMethodName canonicalDataCase =
    let testMethodName = base.RenderTestMethodName canonicalDataCase
    testMethodName.Replace("Set_", "Set ")
```

### メソッド: UseFullMethodName

使うテストメソッド名が完全なパスを使うべきかどうかを示します。つまり、入れ子になったテストケースでは、テストメソッド名の前に親の説明が付きます。

デフォルトの動作で通常は十分です。これを変更したくなるのは、そうしないと同じ名前のテストメソッドが複数できてしまう場合だけです。

#### メソッド: Signature

`KindergartenGarden`ジェネレーターは、テストメソッド名の衝突を防ぐために完全なメソッド名を使っています。

```fsharp
override __.UseFullMethodName _ = true
```

### メソッド: SkipTestMethod

テストメソッドに`Skip = true`プロパティを付けるべきかどうかを示します。

デフォルトの動作でほぼ常に十分です。これを変更したくなるのは、ごくまれな場合だけです。

#### メソッド: Signature

`Markdown`演習はリファクタリングの演習なので、そのテストはすべてすでに正しい状態にあるはずです。そのため、どのテストメソッドにも`Skip`プロパティを付けません。

```fsharp
override __.SkipTestMethod (_, _) = false
```

## 既存のファイルを更新する

既存の演習がcanonical dataと一致していないこともあります。その場合は、canonical dataに合わせて演習のスタブや解答例を更新してかまいません。

また、既存のジェネレーターやテストスイートに問題を見つけたら、更新したいジェネレーターを開いて変更を加え、ジェネレーターを実行するだけです。

## ジェネレーターを実行する

このリポジトリは[.NET Core 2.x](https://www.microsoft.com/net/core)向けに書かれています。ジェネレーターを実行するには、generatorsディレクトリーで次のコマンドを実行するだけです。

`dotnet run`

このコマンドは、定義されているすべての演習のジェネレーターを取得し、各演習のテストケースをすべて生成します。すべての演習はリフレクションで取得しているので、新しいテストを追加すると、ジェネレーターの実行時にそのテストも自動的に含まれます。

1つのジェネレーターだけを実行したい場合は、次のコマンドを実行します。

`dotnet run -e <exercise>`

ジェネレーターを実行したら、その演習のテストファイルを開くと、生成された出力を確認できます。例として、Bob演習のテストスイートは次の場所にあります。

`exercises/bob/BobTests.fs`

## ジェネレーターを提出する

ジェネレーターの出力に満足したら、ぜひプルリクエストを送ってください。ぜひ、ジェネレーター、更新したテストスイート、そのほか変更した関連ファイルを一緒に含めてください。
