# `jq`の関数

`jq`では、必要なロジックをひとまとめにするために、独自の**カスタム関数**を定義できます。_関数_は組み込み関数とまったく同じように動作し、入力を受け取って、0個、1個、またはそれ以上の出力を返します。

## 関数の定義

`jq`の_関数_は、次の構文で定義します。

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- `def`キーワードで始まり、
- 関数本体の前にコロンを置き、
- 本体は1つの式で構成され、
- セミコロンで終わります。
- `jq`の他の構文と同じように、読みやすさのために自由に空白を入れられます。

## 関数を書く場所

_関数_は、使う前に定義しておく必要があります。次のコードはエラーになります。

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

つまり、_関数_は`jq`のコードの先頭、つまり「メイン」の式より前に置く必要があります。

### 入れ子の関数

_関数_は入れ子にできます。

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

ここでは、`B`という_関数_は`A`の本体の中でだけ参照できます。

## スコープ

_関数_は、変数と入れ子の関数のために新しい**スコープ**を導入します。

## 引数

_関数_の**引数**は、カンマではなく_セミコロン_で区切ります。
たとえば、数値を受け取ってから、ある数値を足して別の数値を掛ける_関数_は、次のようになります。

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
セミコロンが必要なのは、カンマにはすでに`jq`での役割があるからです。それは、ストリームを結合する演算子です。

セミコロンの代わりにカンマを使うと、引数を1つ取る`add_mul`関数を2回呼び出そうとします。そのような関数は存在しないため、最初の呼び出しで失敗します。

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

`5, 4`のカンマは、数値5と4を1つのストリームに連結します。
ストリームを引数として関数を呼び出すと、`jq`はストリーム内の各値に対して1回ずつ、その関数を複数回呼び出します。
これは、`jq`のストリームに備わっている「暗黙の繰り返し」の一例です。
`10 | add_mul(5, 4)`は、次のコードと同じです。

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
これで、`add_mul/1 is not defined`というエラーがどうして出るのかがわかります。
~~~~

### 引数は_式_

関数の_引数_は値ではなく、フィルターです。
この意味では、他の言語でコールバックと呼ばれるものと同じように働きます。

`add_mul`関数を例に見てみましょう。

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

ここで何が起きているのでしょうか？

- `adder`引数には、_式_`. + 5`が入ります。
  - 関数が`. + adder`を実行すると、それは`. + . + 5`になります。
  - `. == 10`なので、これは25と評価されます。
- 同様に、`multiplier`引数は式`. - 2`です。
  - これは8と評価され、
  - その結果は`25 * 8 == 200`になります。

### 引数を値として扱う

_引数_を変数として「実体化」したいこともあるでしょう。

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

これには省略記法があります。

```jq
def my_func($arg):
    other stuff ...
;
```

これは単なる「糖衣構文」であることに注意してください。`$`の付いていない`arg`という名前も、_関数_のスコープ内に残っています。

<!-- prettier-ignore -->
~~~~exercism/caution
たとえば、私はある演習を解くために、次のようなコードを書きました。

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

すると、配列のすべての値がキーと等しくなってしまい、驚きました。

これは、jqが`equals`関数を次のように解釈したために起こりました。

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

**引数**`code`が、それ以前に定義された**関数**`code`を_上書き_しました。
そのため、`(. | code)`は入力値から新しいコードを計算するのではなく、単に**引数**を出力してしまいます。
こうして、`$this_code`と`$code`は常に同じ値になっていました。
~~~~

## アリティ

_関数_には**アリティ**、つまり受け取る_引数_の個数があります。

_関数_は、同じ名前を異なる_アリティ_で使うことができます。
組み込みの[`range`][man-range]関数がその例で、`range/1`、`range/2`、`range/3`がすべて共存しています。

これは、引数を介して状態を引き継ぐ再帰関数を定義するときに便利です。
たとえば、`map`は次のように実装することも_できます_。

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## 再帰

`jq`は末尾呼び出し最適化を行いますが、それはアリティが0の関数だけです。

## モジュール

`jq`のモジュールは、関数だけを含むファイルです。
モジュールは、[`include`][man-include]または[`import`][man-import]コマンドでjqのプログラムに読み込みます。
