コードベースの公開インターフェースは、慎重に検討する必要があります。公開する関数が増えるほど、長期的なメンテナンスコストが増え、リファクタリングも難しくなるからです。

Exercismの演習では、公開インターフェースはテストスイートによって決まります。
テストされている関数は、公開されている必要があります。
それ以外の関数はすべて非公開にしましょう。同じ名前でもアリティが異なる関数も含みます。

```elixir
# you defined the following public function

%{actual}

# make it private like this

%{expected}
```
デフォルト引数を使うと、関数のアリティが変わる点に注意してください。

ライブラリを書くときは、モジュール間で使うために関数を公開しなければならないことがよくあります。
そうした関数をドキュメントから隠すには、ライブラリの作者は関数定義の前に`@doc false`を付けます。モジュール全体を隠したい場合は、`@moduledoc false`を使います。
