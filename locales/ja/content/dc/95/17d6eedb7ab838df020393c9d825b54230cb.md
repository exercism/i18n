# はじめに

クオーテーションを部品から*組み立てて*実行する方法は、もう知っていますね。クオーテーションはコードの並びにすぎないので、知っているシーケンスのワードがそのまま使えます。

```factor
USING: kernel math prettyprint quotations sequences ;

{ [ 1 ] [ 2 + ] [ 3 * ] } concat >quotation call .   ! => 9
[ 1 + ] dup append .                                 ! => [ 1 + 1 + ]
```

`append`は2つのクオーテーションを連結し、`concat`はそれらの配列を平坦化し、`map`はデータをクオーテーションに変換し、`>quotation`は結果を呼び出し可能にします。`MACRO:`は、まさにその技術を取って**コンパイル時**へと移します。

## マクロとは

`MACRO:`の定義は普通のワードに見えますが、その本体はプログラムが実行されるときではなく、*コンパイルされているとき*に実行されます。本体はスタックに**1つのクオーテーション**を残さなければなりません。するとコンパイラーが**そのクオーテーションを呼び出し箇所に展開します**。マクロの呼び出しが、本体が生成したコードに置き換わるのです。実行時にはマクロはもう残っておらず、生成されたコードだけが存在します。

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- spliced )
    dup append ;
```

`[ 1 + ] twice`と書いた場所では、コンパイラーが次のことをします。

1. スタックに`[ 1 + ]`を置いて本体を実行します。
2. `dup append`がクオーテーション`[ 1 + 1 + ]`を組み立てます。
3. そのコード`1 + 1 +`をその場所に展開します。

つまり、`twice`を呼び出すワードは、`1 + 1 +`を手で書いたかのようにコンパイルされます。

```factor
: inc-twice ( x -- y ) [ 1 + ] twice ;

5 inc-twice .   ! => 7
```

重要な対比はここです。クオーテーションを受け取る普通のワードは、実行時にそれを`call`します。マクロは何も呼び出しません。代わりにコンパイラーに*新しいコード*を渡し、その場所でコンパイルさせます。

## 入力はリテラルでなければなりません

本体はコンパイル時に実行されるので、マクロの入力は*その時点*でわかっていなければなりません。呼び出し箇所では**リテラル**である必要があります。つまり`[ … ]`のクオーテーション、数値、配列、文字列です。実行時にしか存在しない値は、マクロに渡せません。

```factor
! DOCTEST: SKIP — illustrative call sites, not standalone code
[ 1 + ] twice          ! ok: the quotation is a literal
[ 1 + ] 3 repeat-quot  ! ok: the quotation and the number are literals
```

## 道具箱

マクロの本体は、クオーテーションを返す普通のコードです。すでに見てきたワードがほとんどをこなしてくれます。

| 組み立てたいもの…                      | 使うもの              |
|----------------------------------------|----------------------|
| `[ A ]`と`[ B ]`から`[ A B ]`を作る    | `append`             |
| それらの配列から1つのクオーテーション   | `concat >quotation`  |
| シーケンスの要素ごとに1つのクオーテーション | `map`、次に`concat >quotation` |

`sequences`と`kernel`から、あと2つのワードがこの道具箱を完成させます。

**`<repetition>`**（`sequences`にあります）は、1つの要素の`n`個のコピーからなるシーケンスを作ります。スタック効果は`( length elt -- repetition )`で、個数が先に来ます。結果は*仮想*シーケンスなので、いつもどおり平坦化します。

```factor
3 [ 1 + ] <repetition> concat >quotation .   ! => [ 1 + 1 + 1 + ]
```

**`curry`**（`kernel`にあります）は、クオーテーションの先頭に値を付け加え、その値を最初にプッシュする新しいクオーテーションを作ります。

```factor
3 [ + ] curry .          ! => [ 3 + ]
{ 1 2 3 } [ . ] curry .  ! => [ { 1 2 3 } . ]
```

`curry`を使うと、特定の要素をクオーテーションに焼き込めます。まさに`{ 10 20 30 }`と`[ + ]`を`[ 10 + ] [ 20 + ] [ 30 + ]`に変えるものです。

## 思ったより簡単な理由

言語によっては、マクロに特別なクオートやアンクオートの構文、そして名前の衝突を避けるための追加の仕組みが必要です。Factorにはどれも要りません。クオーテーションはすでに*解決済み*のワードの並びだからです。パーサーは`[ … ]`を読むときに、`dup`、`+`、`append`のそれぞれを解決しています。つまりマクロの本体は、いつも行っているシーケンス操作そのもので、それがたまたまクオーテーションを返すだけなのです。

## よく似た仲間：`$[ … ]`

マクロは、*呼び出し*に展開されるクオーテーションを返します。代わりに、解析時に計算される普通の*値*が欲しいときは、`$[ code ]`がファイルを読み込んでいる間に`code`を実行し、その結果をリテラルとしてソースに折り込みます。

```factor
! DOCTEST: SKIP — compile-time value, shown for contrast
USING: calendar literals ;

CONSTANT: build-time $[ now ]
```

`$[ … ]`は、解析時の結果をリテラルに埋め込むためのワードを集めた[`literals`][literals]ボキャブラリにあります。ここでは網羅のために触れておきます。これから書く4つのステンシル、`twice`、`repeat-quot`、`compose-many`、`each-literal`は、どれも`MACRO:`の宣言です。

[macros]: https://docs.factorcode.org/content/vocab-macros.html
[literals]: https://docs.factorcode.org/content/article-literals.html
