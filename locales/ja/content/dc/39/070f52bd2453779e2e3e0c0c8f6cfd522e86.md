# はじめに

Go 1.18で、Goは**ジェネリクス**のサポートを追加しました。ジェネリクスを使うと、コードを重複させずに、さまざまな型で動作する関数やデータ構造を書けます。

## なぜジェネリクスが必要なのでしょうか？

Goでは、関数や型は通常、`int`や`string`といった特定の型で動作します。ジェネリクス以前は、複数の型に対応する方法が2つありました。1つ目は、`SumInts`や`SumFloats`のように、名前の異なる複数の関数を書く方法です。この方法では、メンテナンスが難しい重複したコードが生まれます。2つ目は、空のインターフェース`any`（`interface{}`）を使う方法です。しかし、空のインターフェースを使うとコンパイル時の型チェックがなくなり、実行時に型アサーションが必要になります。ジェネリクスは、コードの重複を避けながら型安全を提供することで、この問題を解決します。

## ジェネリック関数

ジェネリック関数は、関数名のあとに角括弧（`[...]`）で**型パラメーター**を書いて定義します。次は、逆順にしたスライスを返すジェネリック関数の例です。

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

この例では、`T`が型パラメーターです。`T`は実際の型のプレースホルダーだと考えるとよいでしょう。角括弧の中の`any`キーワードは**型制約**です。型制約は、`T`にどの型を許可するかをコンパイラーに伝えます。ここでの`any`は、`T`がどの型でもよいことを意味します。

### ジェネリック関数の呼び出し

ジェネリック関数は、角括弧の中に実際の型を渡して呼び出せます。この実際の型を**型引数**と呼びます。

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

ほとんどの場合、Goコンパイラーは関数の引数から型を自動で検出できます。この機能を**型推論**と呼びます。型推論を使えば、角括弧の中に型引数を書く必要はありません。

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

この例では、コンパイラーは`words`が文字列のスライスであることがわかるので、`T`は`string`だと推論します。

## 型制約

すべての型パラメーターには制約が必要です。制約は、どの型を型引数として使えるかを指定します。また制約は、その型の値に対して実行できる操作を決めます。

### `any`制約

`any`制約はどの型も許可します。Goでは、`any`は空のインターフェース`interface{}`の別名です。`any`はあらゆる型を許可するので、関数が実行できるのは、すべてのGoの型で通用する操作だけです。たとえば、スライスを保持する2つの`any`値があったとして、スライスは`==`で比較できないため、それらを`==`で比較することはできません。

### `comparable`制約

Goには`comparable`という組み込みの制約があります。`comparable`制約は、`==`と`!=`の演算子をサポートする型を許可します。比較可能な型には、真偽値、数値、文字列、ポインター、チャネル、そして比較可能な型で構成された構造体や配列が含まれます。

次は、スライスに特定の要素が含まれているかを調べる関数の例です。

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

`T`が`comparable`制約を使っているので、`elem == target`は有効です。`comparable`を`any`に置き換えると、コンパイラーがエラーを報告します。

### インターフェースの型集合を使った独自の制約

Go 1.18以降、インターフェースはメソッドに加えて型の集合も定義できます。パイプ文字`|`を使って、インターフェース内に許可する型を並べられます。

```go
type Number interface {
    int | int64 | float64
}
```

これで、`Number`を関数の制約として使えます。

```go
func Double[T Number](value T) T {
    return value * 2
}
```

`Number`に含まれるすべての型が`*`演算子をサポートしているので、Goは関数の中で`value * 2`を許可します。

### 基底型の近似 `~`

プリミティブ型をもとに、独自の型定義を作ることがあります。

```go
type MyInt int
```

上で定義した`Number`制約は、`int`、`int64`、`float64`という正確な型だけを許可します。`MyInt`の値を`Double`に渡すと、`MyInt`は`int`と一致しないため、コンパイラーはエラーを出します。基底型が`int`であるあらゆる型を許可するには、型の前にチルダ`~`を付けます。

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

これで、`MyInt`型の値でも`Double`を使えます。

### `cmp.Ordered`制約

標準ライブラリーは、[`cmp`パッケージ][doc-cmp]で`cmp.Ordered`制約を提供しています。`cmp.Ordered`制約は、比較演算子`<`、`<=`、`>`、`>=`をサポートする型を許可します。

## ジェネリック型

型パラメーターを使って、構造体などのジェネリック型を定義することもできます。次は、ジェネリックな`Stack`データ構造の例です。

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

ジェネリック型の変数を宣言するときは、角括弧の中に型引数を指定する必要があります。

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

型推論が機能するのはジェネリック関数だけです。ジェネリック型の値を作るときは、必ず型引数を指定しなければなりません。

## ジェネリクスを使う場面

ジェネリクスは強力な機能ですが、すべての問題に使う必要はありません。

次のような場面ではジェネリクスを使いましょう。
- 木構造、連結リスト、キャッシュなど、どの要素型でも動作するデータ構造を作っている。
- フィルタリング、並べ替え、検索など、任意の型のスライスやマップを操作するユーティリティ関数を書いている。
- 複数の型に対してまったく同じ実装が必要で、コンパイル時の型安全がほしい。

次のような場面では、代わりにインターフェースを使いましょう。
- 基底のデータ型よりも、振る舞いやメソッドを重視している。
  たとえば、さまざまな種類のソース（ファイル、ネットワーク、TTY）からデータを読み込んで処理したいなら、`func Process[T](src T)`ではなく`func Process(src io.Reader)`を使います。
- 型ごとに異なるメソッドの実装が必要になる。
