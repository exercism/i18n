# はじめに

C++では、宣言と定義はしばしば分けて書かれます。
宣言はヘッダーファイルと呼ばれるファイルにまとめられ、対応する実装はソースファイルに置かれます。
ヘッダーファイルはAPIのようなものだと考えることができます。
ヘッダーファイルを見れば、コードベースが_何_を提供しているかがわかりますが、_どのように_実装されているかの詳細には立ち入りません。

## ヘッダーとソース

ヘッダーファイルで最も一般的な拡張子は`.h`です。
プロジェクトによっては`.hpp`を使ったり、拡張子をまったく付けなかったりします。

定義は別の`.cpp`ファイルに書かれます。
各部分をつなぎ合わせるために、ソースファイルは対応するヘッダーファイルを_インクルード_することから始まります。

`quick_math`というライブラリを書き、その中でよく使いたい`super_root`という関数を提供したい場合、ファイルは次のようになります。

```cpp
// A file named quick_math.h
#pragma once

namespace quick_math {

double super_root(double x, int n);

}  // namespace quick_math
```

```cpp
// A file named quick_math.cpp
#include <cmath>

#include "quick_math.h"

double quick_math::super_root(double x, int n) {
    while (n) {
        x = std::sqrt(x), --n;
    }
    return x;
}
```

実装でのみ必要なヘッダーをインクルードする場合、対応する`#include`行はソースファイルにだけ書けばよいです。
ヘッダーでインクルードされたものはすべて、下の例の`string`ライブラリのように、`.cpp`ファイルでも利用できます。
**注意**：ヘッダーファイルでは宣言のあとに`;`が必要ですが、ソースファイルでは定義のあとに必要ありません。

## クラスとヘッダー

クラスは非常に複雑になることがあり、ヘッダーとソースの分割との関係は混乱しやすいかもしれません。
考えられる構成の1つは、実装の詳細をすべてソースファイルに置き、宣言とメンバー変数をすべてヘッダーに置くことです。

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0);
    void give_water();
    std::string get_name();
    int get_size();
    void start_next_day();
};

}  // namespace robots

#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"

robots::Flower::Flower(std::string name, int size) {
    this->name = "Robotica " + name;
    this->size = size;
}

void robots::Flower::start_next_day() {
    if (!needs_water) {
        ++size;
    }
    needs_water = true;
}

std::string robots::Flower::get_name() { return name; }

int robots::Flower::get_size() { return size; }
```

ヘッダーがAPIの概要として使われる場合、デフォルト値のような情報を探す場所はそこになります。
そのため、コンストラクターの`size`仮引数のデフォルト値は、実装ではなくヘッダーで扱われます。
ソースファイル内の定義には、名前空間`robots`とクラス型`Flower`が先頭に付きます。

もう1つの構成として、`.cpp`ファイルをまったく持たない_ヘッダーのみ_のライブラリもあります。

```cpp
// A file named robot_flower.h
#pragma once

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0) {
        this->name = "Robotica " + name;
        this->size = size;
    }
    void give_water() { needs_water = false; }
    std::string get_name() { return name; }
    int get_size() { return size; }
    void start_next_day() {
        if (!needs_water) {
            ++size;
        }
        needs_water = true;
    }
};

}  // namespace robots
```

プロジェクトではこれらの構成を組み合わせて使うこともあり、それぞれの用途に何が最適かについては多くの議論があります。

## インクルードガード

上のヘッダーファイルの例で、`#pragma once`の行に気づいたかもしれません。
これはインクルードガードと呼ばれ、コンパイル中にファイルの内容が一度だけインクルードされるようにして、エラーを防ぎます。
インクルードガードには、`#ifndef`で始まり`#endif`で終わる、より複雑な別の書き方もあります。
これも同じ目的を持ち、その使い方は上の`Flower`クラスの例で示されています。
