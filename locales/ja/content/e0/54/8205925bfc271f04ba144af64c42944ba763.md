# 括弧に関する注意点

Tclは[とてもシンプルな言語](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm)ですが、インタプリターがコードを解析する方法には、厄介なエッジケースがいくつかあります。

## 波括弧

Tclの波括弧（`{}`）は、テキストのまとまりをクォートするための仕組みにすぎません。そのテキストはコードとしてもデータとしても解釈されます。波括弧の中には、入れ子になった波括弧を書くこともできますが、それらの波括弧の対応は取れていなければなりません。Tclのマニュアルページには、次のように書かれています。

> 波括弧は単語の中で入れ子になります。開き波括弧が1つ増えるごとに、対応する閉じ波括弧も1つ必要です（ただし、単語の中の開き波括弧または閉じ波括弧が_バックスラッシュでエスケープされている_場合は、対応する閉じ波括弧を探すときに数えられません）。

ここの表現は非常に厳密です。対応の取れていない開き波括弧や閉じ波括弧の文字を使いたい場合は、バックスラッシュでエスケープしなければなりません。なので、次のようにしてはいけません。
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "{"}]
    # ......................^ will not work
}
```
次のようにする必要があります
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "\{"}]
    # ......................^^ will work
}
```

これは、Tclのコメントの解析方法がほとんどの言語と異なるため、問題になることがあります。詳しい議論は[Tcl wiki](https://wiki.tcl-lang.org/page/Why+can+I+not+place+unmatched+braces+in+Tcl+comments)にあります。

## 角括弧

同様に、Tclでは角括弧（`[]`）を[コマンド置換](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M11)に使うため、二重引用符で囲んだ文字列の中であっても、開き角括弧のエスケープには注意が必要です。

## 丸括弧

[連想配列の変数](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M12)を除けば、丸括弧（`()`）は単なる普通の文字です。
