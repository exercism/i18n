# 概要

`Result`型を使うと、関数が次のことをすべて示す1つの値を返せるようになります。
- その操作が成功したか失敗したか
- 成功した場合は、その操作の結果の値
- 失敗した場合は、失敗した理由

`Result`型のような仕組みをサポートしていない他のプログラミング言語では、上に挙げた目的を達成するために、次のようなパターンがよく見られます。
- 成功したか失敗の理由かを示す数値コードを返し、成功したときの値を受け取るための出力パラメーターを必要とする関数。
- 成功したときは値を返し、エラーのときはNULLを返し、その後、別の関数で失敗の理由を示すエラーコードを取得する。

もう1つよくあるエラー処理の仕組みが例外です。例外は、失敗が起きたときに現在の関数から突然抜け出し、コールスタック内で最初のハンドラーに制御を移します。
どのハンドラーにも「捕捉」されなければ、プログラムは異常終了します。

## `Result`型を使うメリット

* __コンパイル時の安全性__: 関数呼び出しの成功か失敗かを型システム上で明示することで、コンパイラーは呼び出し側のコードがあらゆる失敗ケースを処理していることを保証でき、nullにまつわる多くのバグを防げます。

* __実行時の安全性__: `null`を使う代わりに、`Result`型は失敗を表すのに`Error`を使うので、`NullReferenceException`が発生することはあり得ません。

* __明示的なエラー処理__: `Result`を返す関数を呼び出すコードは、その呼び出しが失敗し得ることを認めなければなりません。呼び出し側のコードは、そうした失敗を意図的に処理する必要があります。無言の失敗はなく、不意の例外もありません。

* __予測しやすい制御フロー__: `Result`は他の値と同じように返されます。例外のようにコールスタックから飛び出すことはありません。エラーがどこで生まれ、どう伝わるかをいつでも把握できます。

* __可読性と保守性の向上__: `Result`を返すことで、関数のシグネチャは成功時と失敗時に期待される動作を明確に示します。

## 使い方

`Result`型は、2つの基底の型を持つジェネリック型です。
- 操作が成功したときの結果の値の型
- 失敗したときの理由を表す型

`Result`型はまた、次のような場合を持つ[判別共用体][discriminated-union]です。
* 成功した結果を表す`Ok <value>`
* 失敗を表す`Error <reason>`

次の関数は、`Result`の値を作る方法を示しています。

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

この例では、`Ok`の値は文字列（与えられた名前）で、`Error`の値も文字列（人間が読める形でのエラーの原因）です。


`openFile`関数を呼び出すコードは、次の例のようにパターンマッチングを使って成功と失敗のケースを処理できます。

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
