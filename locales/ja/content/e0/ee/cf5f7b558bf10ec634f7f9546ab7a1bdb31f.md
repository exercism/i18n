# はじめに

## メソッドの集まりとしてのインターフェース

最も単純な形では、**インターフェース型**はメソッドのシグネチャの集まりです。
次は、`Add`と`Value`という2つのメソッドを含むインターフェース定義の例です。

```go
type Counter interface {
    Add(increment int)
    Value() int
}
```

`increment`のような仮引数の名前は、インターフェース定義から省略できますが、書いておくと読みやすくなることがよくあります。

Goのインターフェース名には、`Interface`や`I`という語は含めません。
その代わり、`Reader`や`Stringer`のように、`er`で終わることがよくあります。

## インターフェースを実装する

インターフェースのメソッドを定義している型は、自動的に、暗黙のうちにそのインターフェースを「実装」します。
Goには`implements`というキーワードはありません。

次の型は、上で見た`Counter`インターフェースを実装しています。

```go
type Stats struct {
    value int
    // ...
}

func (s Stats) Add(v int) {
    s.value += v
}

func (s Stats) Value() int {
    return s.value
}

func (s Stats) SomeOtherMethod() {
    // The type can have additional methods not mentioned in the interface.
}
```

インターフェースを実装するうえでは、メソッドが値レシーバーを持つかポインターレシーバーを持つかは関係ありません。
（これらについて自信がなければ、[メソッドのコンセプト][concept-methods]をもう一度見てみましょう。）

> インターフェース型の値には、それらのメソッドを実装している任意の値を入れることができます。 [^1]

つまり`Stats`は、`Counter`インターフェースを期待するすべての場所で使えるようになりました。

```go
func SetUpAnalytics(counter Counter) {
    // ...
}

stats := Stats{}
SetUpAnalytics(stats)
// works because Stats implements Counter
```

インターフェースは暗黙のうちに実装されるので、1つの型が複数のインターフェースを簡単に実装できます。
必要なメソッドがすべて定義されていればよいのです。

## 空のインターフェース

Goには、とても特別なインターフェース型が1つあります。メソッドを1つも持たない**空のインターフェース**型です。
空のインターフェースは`interface{}`のように書きます。
`any`は`interface{}`のエイリアスで、よりよく使われます。

空のインターフェースにはメソッドがないので、どの型も暗黙のうちにこれを実装しています。
これは、あらゆる値を汎用的に受け取る関数を定義するのに役立ちます。
その場合、関数の仮引数に空のインターフェース型を使います。
