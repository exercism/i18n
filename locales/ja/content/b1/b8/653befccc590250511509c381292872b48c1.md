# はじめに

関数が自分自身を呼び出すとき、その関数は**再帰的**であるといいます。

関数呼び出しとループの大きな違いの一つは、関数を呼び出すと戻り先アドレスがスタックにプッシュされる点です。
つまり、再帰関数は通常、同等のループよりも多くのスタック領域を必要とします。

その結果、自分自身を呼び出し続ける関数は、やがてスタック領域を使い果たしてしまうことがあります。
これを**スタックオーバーフロー**といいます。

そのため、すべての再帰関数には少なくとも1つのベースケースが必要です。ベースケースとは、関数が自分自身を呼び出さずに戻る場合のことです。
再帰呼び出しは、最終的に必ずベースケースに到達しなければなりません。

たとえば、階乗関数`n! = n * (n - 1) * ... * 1`は、`1`をベースケースとして再帰的に定義できます。

```x86asm
factorial:
    ; the argument `n` is passed on `rdi`
    ; the factorial will be returned on `rax`

    cmp rdi, 1
    jle .base_case     ; base case -> if rdi <= 1, return 1

    push rdi           ; save n
    dec rdi            ; rdi = n - 1
    call factorial     ; recursive call, rax = (n - 1)!
    pop rdi            ; restore n
    imul rax, rdi      ; rax = n * (n - 1)! = n!
    ret
.base_case:
    mov rax, 1
    ret
```

`factorial`は、再帰する前に`push rdi`を、再帰した後に`pop rdi`を行う必要があることに注意してください。
これは、再帰呼び出しから戻ったあとに`n * (n-1)!`を計算するために、依然として`n`が必要だからです。

また、呼び出し先保存レジスタを使ってもこの問題は解決しないことにも注意してください。

再帰関数は自分自身を呼び出す可能性のある呼び出し元ですが、同時に何か他の関数から見た呼び出し先でもあります。
つまり、その関数は呼び出し先保存レジスタを使う前にその値を保存し、使い終わったあとに復元しなければなりません。
これは通常、以前のコンセプトで見たように、`push`/`pop`の組み合わせで行います。

再帰関数の各フレームは、ベースケースを除いて、それぞれが自分のローカル変数を保存する必要のある呼び出し元でもあるため、この`push`/`pop`の組み合わせはフレームごとに繰り返さなければなりません。
レジスタを使わずに変数を直接スタックに保存したとしても、フレームごとに同じ`8`バイトのコストがかかります。

つまり、再帰呼び出しのたびに、`call`がプッシュする戻り先アドレスの分として`8`バイト、さらに保存が必要なローカル変数ごとに`8`バイトがスタックに加わります。
関数はベースケースに到達するまで、フレームごとにこれらのバイトをスタックに加え続けます。
そしてベースケースに到達して初めて、逆の順序で巻き戻しが始まります。各再帰呼び出しは、必要なだけ`pop`を行い、そのあと`ret`します。

たとえば、`factorial`を引数`10`で呼び出すと、`1`というベースケースに到達するまでに9回自分自身を呼び出します。
その時点で、これまでの各フレームについて`n`（`8`バイト）と戻り先アドレス（`8`バイト）を保存するために、`144`バイトが使われていたことになります。

## 末尾呼び出し

関数が別の関数を呼び出したあと、戻るまでの間に何も処理を行わない場合があります。

たとえば、次の例を見てみましょう。

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    call times_three
    ret
```

関数`triple_of_square`は、次のことを行います。

- 渡された引数（`rdi`に入っています）をそれ自身と掛け合わせて、その2乗を求めます。
- 次に`times_three`を呼び出します。この関数は、渡された引数を3倍した値を返します。

その結果、`triple_of_square`は`3*x²`を返します。ここで`x`は、`rdi`で渡された引数です。

`triple_of_square`では、`times_three`を呼び出したあとに何も処理を行わず、単に戻るだけであることに注意してください。
このような場合、関数は`call`を使う代わりに、`jmp`を使って呼び出した関数に実行を移すことがあります。

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    jmp times_three
```

これを**末尾呼び出し**といいます。

末尾呼び出しの主な利点は、`call`の余分なコストを避けられることです。
`call`は戻り先アドレスをスタックにプッシュするので、その地点に制御を戻すには、対応する`ret`が必要です。

末尾呼び出しはその両方を省きます。プッシュすべき戻り先アドレスはなく、対応させる余分な`ret`もありません。あるのは、呼び出された関数自身の`ret`だけです。

## 末尾再帰

末尾呼び出しは、戻るまでに何度も自分自身を呼び出す可能性のある再帰関数で特に役立ちます。

ただし、すべての再帰呼び出しがそのまま末尾呼び出しに変換できるわけではありません。
`jmp`は呼び出された関数に制御を移すため、呼び出し元は末尾呼び出しのあとに何も処理を行えません。

たとえば、先ほどの`factorial`関数は末尾再帰では**ありません**。
再帰呼び出しのあと、`imul rax, rdi`を使って結果と現在の`n`を掛け合わせる必要がまだ残っています。

このような場合、途中の計算結果を集めて最後に返すアキュムレーターを使えることがあります。
たとえば、ほとんどの処理を行う`factorial_helper`を定義し、`factorial`がアキュムレーターを用意して`factorial_helper`に制御を移すことができます。

```x86asm
factorial_helper:
    ; the argument `n` is passed on `rdi`
    ; `rax` is used as an accumulator and will be returned at the end

    cmp rdi, 1
    jle .base_case

    imul rax, rdi        ; we accumulate the partial result on `rax`
    dec rdi              ; rdi = n - 1
    jmp factorial_helper ; tail call to accumulate (n - 1)!
.base_case:
    ret                  ; returns the factorial already accumulated on `rax`

factorial:
    mov rax, 1           ; initial value for the accumulator
    jmp factorial_helper ; tail call
```

再帰呼び出しのあとに何も処理を行わないので、`rdi`を保存する必要もなくなります。
`call`も`push rdi`もないため、再帰の各繰り返しでスタックに加わるのは`0`バイトです。追加のスタック領域は使われません。
このバージョンなら、スタックをオーバーフローさせることなく、どんなに大きな`n`でも扱えます。
効率がよく、しかも安全です。

場合によっては、関数の順序を工夫することで、ヘルパーへの`jmp`さえも避けられます。
たとえば、`factorial`と`triple_of_square`は次のように書き換えられます。

```x86asm
factorial:
    mov rax, 1
factorial_helper:
    cmp rdi, 1
    jle .base_case

    imul rax, rdi
    dec rdi
    jmp factorial_helper
.base_case:
    ret

triple_of_square:
    imul rdi, rdi
times_three:
    imul rax, rdi, 3
    ret
```

上のコードでは、`factorial`の実行はそのまま`factorial_helper`に流れ込みます。
`triple_of_square`と`times_three`も同じです。
どちらの場合も実行はそのまま順に続き、末尾の関数は「メイン」関数の中にある単なるローカルラベルにすぎないように見えます。

実際には、ローカルラベルと関数の間に本質的な違いはありません。
x86-64アセンブリはどちらも特別扱いしません。どちらも、`section .text`のような実行可能なコードが入ったセクション内のアドレスにすぎません。

このように、末尾再帰関数は、再帰呼び出しが先頭にジャンプして戻るループと本質的に同じものと考えることができます。ベースケースは、そのループを終わらせる条件です。
