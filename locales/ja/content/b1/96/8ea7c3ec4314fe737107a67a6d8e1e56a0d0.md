# はじめに

この演習は、[裏庭のバードウォッチャー][backyard-birdwatcher]で見た内容を土台に、*クォーテーション*、つまり括弧（`[ ]`）で囲まれたコードの断片を取って操作を動かす高階ワードを紹介します。

## 値としてのクォーテーション

クォーテーションは、単なるコードのリテラルです。データとして別のワードに渡すことができます。

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

ここで`[ 2 > ]`は、数値を取り、真偽値を残すクォーテーションです。`count`はそれを各要素に対して実行し、真とみなされた結果を数えます。

## 絞り込みと除外

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

`without`は、2番目の引数を集合として扱います。`seq`の要素のうち、`exclude`の*どの*要素と`=`であっても、それは取り除かれます。`sift`は`reject`のクォーテーションなしの特殊ケースで、`f`以外のすべての要素を残します。以前の`map`が残した隙間を取り除くのに便利です。

### 検査の結果を残す

`find`は、一致した*要素*を返します。検査がすでに*求めている値そのもの*を計算しているときは、`map-find`を使えばもう一度走査せずに済みます。各要素に対してクォーテーションを実行し、最初の`f`以外の結果と、それを生み出した要素の**両方**を返します。

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

そのクォーテーションは、条件を満たさない要素には`f`を返し、満たす要素には残したい結果を返します。何も条件を満たさなければ、`map-find`は`find`と同じく`f f`を残します。

### スロットでレコードを絞り込む

要素が*タプル*のときは、述語はたいてい、自動生成された読み取り用ワード`slot>>`でスロットを取り出し、それに対して検査します。

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## `with`で固定値を引き回す

述語が、呼び出しのたびに同じ値であるものを必要とすることがあります。しきい値、除数、対象の文字列などです。`with`（[`kernel`][kernel]にあります）は、その固定値をクォーテーションに組み込み、2引数のクォーテーション`( value elt -- ? )`を、`filter`、`count`、`map`、`each`が期待する1引数のクォーテーションに変えます。

```
with ( value seq quot -- seq curry )
```

各要素ごとの呼び出しでは、スタックに`( value elt )`が見えます。固定値が先、現在の要素が後です。

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## マッピングと繰り返し

`map`（[`sequences`][sequences]にあります）は、クォーテーションを各要素に適用し、結果の配列を返します。`each`も同じようにたどりますが、結果は捨てます。クォーテーションが副作用のためだけに実行されるときに便利です。`2map`は*2つ*のシーケンスを同期してたどり、対応する要素同士を組み合わせます。`2each`と`2reduce`はその副作用専用版と畳み込み版です。`zip`は「組み合わせずにペアにする」の略記です。

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

`2reduce`は、アキュムレーターを両方のシーケンスに同時に引き回します。そのクォーテーションは`( accumulator elt1 elt2 -- accumulator' )`を取ります。ここでは内積を計算しています。各ペアを掛けて、その積を合計します（`1*10 + 2*20 + 3*30`）。

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

`map-as`は`map`のいとこで、出力するシーケンスの型を強制します。見本となる値として空の`{ }`または`V{ }`を渡すと、入力の型にもとづく既定を上書きできます（そうしないと、文字列を文字以外にマッピングしたとき、Factorが結果を文字列に詰め戻そうとしてエラーになります）。

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

2つのシーケンスを取る形はどちらも、短いほうの長さで止まります。`zip`は`[ 2array ] 2map`と同じで、ペアを畳み込むのではなくペアのまま残します。

## 並べ替え

`sort`は、自然な順序で並べ替えたコピーを返します。`sort-by`（[`sorting`][sorting]にあります）は、各要素から取り出したキーで並べ替えます。

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## 集計

`map-sum`（[`sequences`][sequences]にあります）は、クォーテーションをシーケンス全体にマッピングし、結果を一度の走査で合計します。

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## 最小値と最大値

`minimum`と`maximum`は、シーケンスの最小または最大の要素をそのまま返します。`minimum-by`と`maximum-by`（いずれも[`sequences`][sequences]にあります）は、取り出したキーが最小または最大になる要素を返します。

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## 自分だけの高階ワードを書く

*あなたの*ワードがクォーテーションを実行時の引数として受け取り、それを`map`や`filter`、`each`などに渡すときは、そのワードを`; inline`で宣言します。そうするとコンパイラーに、呼び出し地点ごとにそのワードをインライン展開するよう伝えます。そこではクォーテーションが既知のリテラルです。これがないと、コンパイラーはクォーテーションのスタック効果を知る手立てがありません。

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

リテラルのクォーテーションだけから作られたワードには`inline`は必要ありません。*外から来る*クォーテーションを渡すワードだけです。

そうした`inline`ワードが*自分自身*を呼び出す場合（再帰的なコンビネーター）、代わりに`; inline recursive`で宣言します。余分なワードがないと、コンパイラーは*"The inline recursive word ... must be declared recursive"*というエラーで止まります。これは、何を追加すればよいかを正確に教えてくれます。

## 2番目の要素を取り出す

2要素の配列では、`second`がその2番目の要素を返します。`first`は最初の要素を返します。どちらも[`sequences`][sequences]にあります。

## 数値から文字列へ

`number>string ( n -- str )`（[`math.parser`][math.parser]にあります）は、数値を10進数の文字列の形に変えます。

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
