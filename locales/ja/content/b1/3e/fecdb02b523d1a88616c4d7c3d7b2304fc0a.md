# はじめに

バイナリデータを扱うことはどの言語においても重要な概念であり、Elixirにはバイナリデータを書いたり、マッチさせたり、構築したりするためのエレガントな構文が用意されています。

Elixirでは、バイナリデータはビットストリング型と呼ばれます。バイナリデータ_型_（一般的なバイナリデータと混同しないでください）はビットストリングの特定の形式で、これについては後の演習で説明します。

ビットストリングリテラルは、ビットストリングの特殊形式`<<>>`を使って定義します。ビットストリングリテラルを定義するときは、セグメントごとに定義します。各セグメントは値と型を持ち、`::`演算子で区切られます。型は、その値をエンコードするのに何ビット使うかを指定します。型は完全に省略でき、その場合は8ビット整数値がデフォルトになります。

```elixir
# This defines a bitstring with three segments of a single bit each
<<0::1, 1::1, 0::1>>
```

型を`::1`と指定するのは、`::size(1)`と書く省略形です。ビットサイズが変数から得られる場合は、長い方の構文を使う必要があります。

## バイナリ

二進整数リテラルを書くときは、リテラルの前に`0b`を付けることで、2進数表記で直接書くことができます。なお、テスト結果として出力されたりiexで使ったりするときは、いずれにせよ10進数として表示されます。

```elixir
<<0b1011::4>> == <<11::4>>
# => true
```

## 切り捨て

セグメントの値がそのセグメントの型の容量を超えると、左から切り捨てられます。

```elixir
<<0b1011::3>> == <<0b0011::3>>
# => true
```

## 先頭への追加と末尾への追加

特殊形式を使うと、既存のビットストリングの先頭にも末尾にも追加できます。既存のビットストリングのサイズが不明な場合は、`::bitstring`型を使う必要があります。

```elixir
value = <<0b110::3, 0b001::3>>
new_value = <<0b011::3, value::bitstring, 0b000::3>>
# => <<120, 8::size(4)>>
```

## 連結

変数に格納したビットストリングは、特殊形式を使って連結できます。サイズが不明な2つのビットストリングを連結するときは、`::bitstring`型を使う必要があります。

```elixir
first = <<0b110::3>>
second = <<0b001::3>>
concatenated = <<first::bitstring, second::bitstring>>
# => <<49::size(6)>>
```

## パターンマッチング

パターンマッチングを使って、特殊形式から値を取り出すこともできます。ただし1つだけ例外があります。取り出したい各断片のビット数を知っておく必要があります。`::bitstring`型を使うと、サイズが不明なビットストリングに対してもパターンマッチングできますが、これが使えるのは最後の断片だけです。

```elixir
<<value::4, rest::bitstring>> = <<0b01101001::8>>
value == 0b0110
# => true
```

## ビットストリングを検査する

~~~~exercism/note
ビットストリングは、（テストランナーやiexによって）作成時に使った形式とは異なる形式で出力されることがあります。これは、ビットストリングを学ぶときにしばしば混乱の原因になります。
~~~~

デフォルトでは、異なるサイズの断片で作成したとしても、ビットストリングは8ビット（1バイト）の断片で表示されます。

```elixir
<<2011::11>>
# => <<251, 3::size(3)>>
```

出力可能なUTF-8エンコードされた文字列を表すビットストリングを作成すると、それは文字列として表示されます。

```elixir
<<>>
# => ""

<<65, 66, 67>>
# => "ABC"
```
