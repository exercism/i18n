## スクリプトの使い方

テストを生成するには、[problem-specifications][problem-specifications]リポジトリのローカルコピーが必要です。
演習に正しくアクセスするため、スクリプトは`python`ディレクトリのルートから実行してください。

使い方を確認するには、`bin/generate_tests.py --help`を実行してください。


## テストテンプレート

テストテンプレートは[Jinja2]構文をサポートしており、正規データから次のコンテキスト変数を利用できます：
- `exercise`: ハイフン付きの演習名（例：`two-fer`）
- `version`: 正規データのバージョン（例：`1.2.0`）
- `cases`: ケースオブジェクトのリスト、または`cases`リストのリスト。作業中の演習の正確な構造については、`canonical-data.json`を参照してください。
- `has_error_case`: エラーの送出を期待するテストケースがあるかどうかを示します（例：`False`）
- `additional_cases`: `cases`と同様の構造ですが、演習の`.meta/additional_tests.json`ファイルが存在する場合は、そこから値が設定されます（例については、`exercises/word-count/.meta/additional_tests.json`を参照してください）

さらに、利便性のために次のテンプレートフィルターが追加されています：
- `to_snake`: 文字列をsnake_caseに変換します（例：`{{ "CamelCaseString" | to_snake }}` -> `camel_case_string`）
- `camel_case`: 文字列をCamelCaseに変換します（例：`{{ "snake_case_string" | camel_case }}` -> `SnakeCaseString` ）
- `error_case`: テストケースがエラーの送出を期待しているかどうかを確認します（例：`{% for case in cases%}{% if case is error_case}`）
- `regex_replace`: 正規表現による文字列の置換です（例：`{{ "abc123" | regex_replace("\\d", "D") }}` -> `abcDDD`）


### 規約

- 繰り返しの多いテンプレート構造で汎用的に使えるマクロは、`config/generator_macros.j2`で定義されています。
  - 次のようにしてインポートできます：
  `{%- import "generator_macros.j2" as macros with context -%}`
- すべてのテストテンプレートは`{{ macros.footer() }}`で終わるようにしてください。
- Pythonのクラス名はすべてCamelCaseにします（例：`TwoFer`）。
  - `{{ "two-fer" | camel_case }}`を使って変換します。
- Pythonのモジュール名と関数名はすべてsnake_caseにします（例：`high_scores`、`personal_best`）。
  - `{{ "personalBest" | to_snake }}`を使って変換します。
- トラック固有のテストは、オプションファイル`.meta/additional_tests.json`で定義します。このファイルで定義するJSONオブジェクトは、`cases`という単一のキーを持ち、その構造は`canonical-data.json`の`cases`と同じにします。
- トラック固有のテストは、テストファイル内で正規データのテストの後に配置します。
- トラック固有のテストは、テストファイル内で次のコメントを付けて示します：
```
# Additional tests for this track
```


### レイアウト

ほとんどのテンプレートは、次のような形になります：

```Jinja2
{%- import "generator_macros.j2" as macros with context -%}
{{ macros.header() }}

class {{ exercise | camel_case }}Test(unittest.TestCase):
    {% for case in cases -%}
    def test_{{ case["description"] | to_snake }}(self):
        value = {{ case["input"]["value"] }}
        expected = {{ case["expected"] }}
        self.assertEqual({{ case["property"] }}(value), expected)

    {% endfor %}

{{ macros.footer() }}
```


### インポートの上書き

`macros.header()`でインポートされる名前は、インポートする別名のリストを追加することで上書きできます（例：`clock`）：

```Jinja2
{{ macros.header(["Clock"])}}
```


### プロパティの無視

まれに、このトラックではテストされないプロパティを除外する必要があるかもしれません。`header`マクロは`ignore`引数も受け取ります（例：`high-scores`）：

```Jinja2
{{ macros.header(ignore=["scores"]) }}
```

## テンプレートを作成する

1. 実装する演習の`.meta/template.j2`を作成し、エディターで開きます。
2. テンプレートファイルに[レイアウトの例](#Layout)をコピー＆ペーストして保存します。
3. 有効なテストコードが生成されるまで、テンプレートファイルに適切な変更を加えます。入力名とケースの構造については、演習の`canonical-data.json`を参照してください。
    - 標準的なセクションを書き直さなくて済むよう、[利用可能なマクロ](../config/generator_macros.j2)を使ってください。
    - 既存の演習のテンプレートを実装する場合、既存のテストファイルと構造を完全に一致させる必要はありませんが、違いを最小限に抑えると、関係者全員にとってプルリクエストのレビューがずっとスムーズになります。
