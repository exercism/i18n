# テスト

各演習には、単体テスト一式と、それをビルドして実行するために必要なものがすべて用意されています。
実装は自分で用意します。

## テストを実行する

演習のフォルダーでターミナルを開き、次のコマンドを実行します。

```
make
```

これは自分の解答とテストをコンパイルし、そのあとテストを実行します。
解答を変更するたびに、もう一度実行してください。

[Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally)があれば、代わりに次のコマンドも使えます。こちらは`make`も実行します：

```
exercism test
```

ビルドで作成されたファイルを削除するには、`make clean`を実行します。

### makeがない場合

`make`がない場合（たとえばWindows）は、テストを直接コンパイルして実行できます。
演習「Bob」の場合：

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

LinuxやmacOSでテストを実行するには：

```
./run_tests
```

Windowsの場合：

```
.\run_tests
```

## 演習の進め方

各演習のファイルは、演習名にちなんだ名前になっています。
演習「Bob」の場合：

| ファイル | 内容 |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90` | 解答のひな形（あとは完成させるだけです） |
| `bob_test.f90` | テスト |
| `TesterMain.f90` | テストライブラリ |
| `Makefile` | `make`のための指示 |
| `CMakeLists.txt` | 省略可能な[CMake](#using-cmake-instead)のための指示 |

編集が必要なのは解答ファイルだけです。

各演習は、すべてのテストに通るまで、次の手順を繰り返して進めます。

- コンパイルエラーを修正してから、テストを実行し、どのテストが失敗するかを確認します。
- 次に失敗しているテストに通るだけの最小限の実装をします。
- 読みやすさを高め、重複を減らすなど、実装をリファクタリングします。
- もう一度テストを実行し、次に失敗しているテストへ進みます。

失敗したテストごとにメッセージが表示され、最後にまとめが表示されます。
テストが1つでも失敗すると、`make`はエラーで終了します。

各テストにはそのテストを説明するコメントがあり、そのあとに`call assert_equal`で始まる実際のテストが続きます。例：

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

テストを無効にするには、`'!'`でコメントアウトするだけです。例：

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## 代わりにCMakeを使う

CMakeは必須ではありませんが、Visual StudioやXcodeなどのIDEを使う場合や、GFortran以外のコンパイラを使う場合には便利です。

演習のフォルダーは元の名前のままにしておく必要があります。CMakeがその名前を使ってソースファイルを探すからです。
演習のフォルダーで次のコマンドを実行します。

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

解答を変更したあとは、最後の2つのコマンドだけを実行すればOKです。

**注意：**`cmake`は必ず`build`などの別のフォルダーから実行してください。
演習のフォルダーで`cmake .`を実行すると、演習に付属している`Makefile`が置き換えられてしまいます。

CMakeは環境に合ったジェネレーターを選びます。
別のジェネレーターを使うには、`-G`オプションを指定します（例：`cmake -G Xcode ..`）。
使えるジェネレーターの一覧は`cmake --help`で確認できます。
Visual StudioやXcodeを使う場合は、`ctest -V -C Debug`でテストを実行します。

演習のフォルダーに`Makefile`がない場合、その演習はこれらのファイルが追加される前にダウンロードされたものです。
その場合でもCMakeは使えます。
