# はじめに

抽象構文木（AST）は、*クォートされた式*とも呼ばれ、コードをデータとして表現する方法です。

ASTの各ノードは、3つの要素からなるタプルです。

```elixir
# AST representation of:
# 2 + 3
{:+, [], [2, 3]}
```

1つ目の要素はアトムで、演算を表します。2つ目の要素はキーワードリストで、メタデータです。3つ目の要素は引数のリストで、その中にはほかのノードが入ります。整数、アトム、文字列などのリテラル値は、3つの要素からなるタプルではなく、ASTの中ではそのままの形で表されます。

## コードをASTに変換する

ElixirのコードをASTに変換したり、ASTをコードに戻したりする機能は、標準ライブラリに含まれています。ASTを扱う関数は、`Code`モジュール（たとえば、コードを含む文字列をASTに変換する）と`Macro`モジュール（たとえば、ASTをたどったり文字列に変換したりする）にあります。

標準ライブラリの関数はどれも、ASTを指す名前として「quoted」（クォートされた式の略）を使っている点に注意してください。

コードをASTに変換するための特殊形式は、`quote`と呼ばれます。これはコードブロックを受け取り、そのASTを返します。

```elixir
quote do
  2 + 3 - 1
end

# => {:-, [], [
#      {:+, [], [2, 3]},
#      1
#    ]}
```

## 用途

コードをASTとして表現できることは、Elixirのメタプログラミングの核心です。*マクロ*は、Elixirのコードを生み出すElixirコードを書くための仕組みで、ASTを出力として返すことで動作します。

ASTのもう1つの用途は、静的コード解析です。たとえばExercism自身のツールであるAnalyzerがそうで、解答にコメントを残してくれる小さなボットとして、すでに見覚えがあるかもしれません。
