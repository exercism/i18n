# はじめに

クォーテーションが周囲の値を*覚えておく*必要があるとき、Factorは2つの道具を使います。`curry`というワードと、`'[ ]`という*fry*構文です。他の言語では、これを*クロージャ*と呼びます。

## `curry`で値を1つ取り込む

`curry`は（[`kernel`][kernel]にあります）値とクォーテーションを受け取り、その値を組み込んだ新しいクォーテーションを返します。

```
curry ( value quot -- newquot )
```

```factor
3 [ + ] curry .
! => [ 3 + ]

10 3 [ + ] curry call .
! => 13
```

2つの値を取り込むには、`curry`を2回適用します。

```factor
2 3 [ + + ] curry curry .
! => [ 2 3 + + ]
```

## `compose`で2つのクォーテーションをつなぐ

`compose`は（[`kernel`][kernel]にあります）2つのクォーテーションを1つにつなぎます。

```
compose ( quot1 quot2 -- quot )
```

```factor
[ 1 + ] [ 2 * ] compose .
! => [ 1 + 2 * ]

5 [ 1 + ] [ 2 * ] compose call .
! => 12
```

## fryクォーテーションで複数の値を取り込む

取り込む値が3つ以上になると、`curry`をつなげた呼び出しは読みにくくなります。*fry*では、`'[ … ]`と1つ以上の`_`プレースホルダーを使います。各`_`は、データスタックから取り出した値で、順番に置き換えられます。

```factor
2 3 '[ _ _ + + ] .
! => [ 2 3 + + ]
```

`curry`もfryも、クロージャが作られた瞬間にスタックから値を*消費*します。上の行はスタックに何も残さず、`[ + + ] curry curry`をそのまま置き換えるものです。

プレースホルダーは、スタックの下から上の順に取り出した値で、左から右へ埋められます。`2 3 '[ _ _ ]`は`[ 2 3 ]`になり、`[ 3 2 ]`にはなりません。

fryは入れ子になったクォーテーションの*中にまで*届きます。そのおかげで、取り込んだ値を好きな場所に正確に置けます。

```factor
2 '[ [ _ > ] filter ] { 1 2 3 4 5 } swap call( s -- s ) .
! => { 3 4 5 }
```

`_`は内側の`[ … ]`の中にありますが、fryはそこにもちゃんと値を埋めます。

## スタック効果を宣言した`call`

しまっておいたクォーテーションを実際に実行するときは、`call`にスタック効果を宣言しておくと、コンパイラーが型チェックを行えます。

```factor
{ 3 4 5 } [ first2 + ] call( p -- n ) .
! => 7

{ 3 4 5 } [ first ] call( p -- n ) .
! => 3
```

## ベクトル演算

[`math.vectors`][math.vectors]ボキャブラリーは、同じ長さの2つのシーケンスを要素ごとに組み合わせます。`v+`と`v*`は足し算と掛け算を、`vmax`と`vmin`は各要素の大きい方と小さい方をそれぞれ残します。どれも2要素の配列を返します。

```factor
{ 1 1 } { 3 4 } v+ .    ! => { 4 5 }
{ 2 5 } { 3 -1 } v* .   ! => { 6 -5 }
{ 1 9 } { 4 4 } vmax .  ! => { 4 9 }
{ 1 9 } { 4 4 } vmin .  ! => { 1 4 }
```
