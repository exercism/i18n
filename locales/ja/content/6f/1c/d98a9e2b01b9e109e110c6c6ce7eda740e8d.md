# 浮動小数点数

`FLTD`は、小数部をもつことのある数値を保持します。リテラルを書くには、小数点と`d`が必要です。

```sather
   440.0d
   0.5d
   -2.25d
```

`FLT`は同じ考え方で、精度が半分です。このトラックでは`FLTD`を一貫して使います。メモリが厳しいとき以外に`FLT`に手を伸ばす理由はありません。

## 演算

| 演算子 | 意味 |
| --- | --- |
| `+` `-` `*` | `INT`の場合と同じ |
| `/` | 除算。小数部をそのまま保持します |

`FLTD`には`%`がありません。

両方のオペランドは`FLTD`でなければなりません。`INT`を混ぜるとコンパイルエラーになります。黙って変換されることはありません。これはむしろ利点です。これが問題になるのは、まさに間違いが起きやすい場面だけだからです。

## 変換

```sather
   7.fltd            -- 7.0, an INT made into an FLTD
   7.5d.int          -- 7, the fraction thrown away
   7.5d.round        -- 8, to the nearest whole number
   7.5d.floor        -- 7.0, down to a whole number
   7.5d.ceiling      -- 8.0, up to a whole number
```

変換は割り算の前にしましょう。後からでは遅すぎます。`n.fltd / 2.0d`は小数部を保ちますが、`(n / 2).fltd`ではすでに失われています。

## 便利なルーチン

```sather
   (-2.5d).abs       -- 2.5
   2.0d.sqrt         -- 1.41421
   (2.0d).max(3.0d)  -- 3.0
```

## 浮動小数点数は近似値です

`FLTD`が保持しているのは、正確な値ではなく、ごく近い近似値です。ほとんどの小数は正確に表せません。3分の1を小数で正確に書き表せないのと同じです。ですから、次のようになります。

```sather
0.1d + 0.2d          -- very nearly 0.3, but not exactly
```

覚えておきたい結果が2つあります。

**`=`で比較してはいけません。** 同じ答えになるはずの2つの計算でも、最後の数桁が違うことがよくあります。代わりに、値が近いかどうかを確認しましょう。

```sather
   (a - b).abs < 0.0001d
```

**小さな値をたくさん足すと精度が落ちます。** 足すたびに少しずつ丸められ、誤差が積み重なっていきます。

値が正確でなければならないとき、とくにお金を扱うときは、`INT`で整数の単位に数えましょう（ドルではなくセントで）。

## 出力

`.str`は有効数字を6桁ほどしか表示しません。実際に保持している精度には足りません。

```sather
   #OUT + (1.0d / 3.0d).str;      -- 0.333333
```
