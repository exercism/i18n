# 解説

[`Nothingness`][concept-nothingness]の概念で見たように、Rには、存在しないデータ（[`NULL`][ref-null]）、不明なデータ（[`NA`][ref-na]）、数学的に無効なデータ（[`NaN`][ref-finite]、[`Inf`][ref-finite]）を表すさまざまな方法があります。
一般にRは、これらの値を使ってその場で問題を示そうとし、例外を発生させずに処理を続けます。

## `stop()`

問題によっては、プログラムを続行させられないほど根本的なものもあります。
そのような場合は、[`stop(msg)`][ref-stop]を使って`Error`とともにプログラムを直ちに停止し、`msg`を出力します。

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

他の言語の[`assert`][wiki-assert]に似ていて、[`stopifnot()`][ref-stopifnot]は`stop()`の便利なラッパーです。
引数には、カンマで区切った任意の数の真偽値の条件を指定し、すべてが`TRUE`の場合にのみプログラムが続行されます。

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

Rには、エラーを扱うためのさまざまな方法があります。
これらはCommon Lispに基づいており、多くの一般的な言語とは大きく異なります。

最も簡単なのは、問題が起きそうなコードを[`try()`][ref-try]で包む方法です。

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning]と[`message()`][ref-message]

これらは致命的ではない条件に対する応答で、たとえば次のような場合に使います。

- プログラムが少なくとも部分的に回復できる問題を警告する場合。
- 長時間実行されるプログラムの進捗をユーザーに知らせる場合。

両者の違いの一つは、警告はキャッシュされ、（デフォルトでは）関数が戻ったときに出力されるのに対し、メッセージはすぐに出力されることです。
デフォルトの動作を変える方法はたくさんありますが、ここで扱う範囲を超えています。

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

[`suppressWarnings()`][ref-warning]関数は、Exercismの中で、不要な出力でテストランナーを混乱させないために、ときどき役立つことがあります。
