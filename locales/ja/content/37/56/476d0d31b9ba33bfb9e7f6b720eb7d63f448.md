# はじめに

プログラミングでは、予期しない状況でプログラムがクラッシュしたり予測できない動作をしたりしないよう、エラーをうまく扱うことが欠かせません。
Cairoには、エラー処理のための主な仕組みが2つあります。

1. `panic`による**回復不可能なエラー**。これはプログラムを即座に停止します。
2. `Result`による**回復可能なエラー**。これはプログラムがエラーに対処し、対応できるようにします。

## `panic`による回復不可能なエラー

プログラムがこれ以上続行できないほど深刻なエラーに遭遇することがあります。
Cairoでは、そうしたときに`panic`関数を使って実行を即座に停止します。
これは、範囲外のインデックスにアクセスしようとするエラーのように、まともな形でプログラムを続けることが不可能な場合に役立ちます。
`panic`関数は、エラーの理由を説明する`ByteArray`のメッセージを受け取ります。

たとえば、Cairoでは次のようになります。

```rust
fn main() {
    let data = array![1, 2];
    panic("An unrecoverable error has occurred!");
}
```

この例は、強制的なpanicを起こし、メッセージとともにプログラムを即座に停止します。

### `assert!`マクロ

`assert!`マクロは、コードの中で特定の条件を強制するのに便利なツールです。
`assert!`の条件が`false`と評価されると、プログラムは`ByteArray`のエラーメッセージとともにpanicします。
これは、開発中に前提を検証したり、値が特定の条件を満たしていることを確かめたりするのによく使われます。

たとえば、次のようになります。

```rust
fn main() {
    let x = 5;
    assert!(x > 0, "x must be greater than zero");
}
```

`x`が0より大きくない場合、プログラムは`"x must be greater than zero"`というメッセージとともにpanicします。`assert!`は、エラー処理のコードを自分で書かなくても、不変条件や事前条件をチェックするのに役立ちます。

## `Result`による回復可能なエラー

すべてのエラーがプログラムを停止させる必要はありません。
穏やかに扱えるものもあり、プログラムはそのまま続けられます。
Cairoの`Result`列挙型は、こうした回復可能なエラーを表し、2つのバリアントを持ちます。

- `Result::Ok`は成功を表します。
- `Result::Err`はエラーを表します。

`Result`を使うと、関数は成功の値かエラーのどちらかを返すことができ、呼び出し側の関数が次に何をするかを決められます。

```rust
fn divide(a: u32, b: u32) -> Result<u32, ByteArray> {
    if b == 0 {
        Result::Err("Error: Division by zero")
    } else {
        Result::Ok(a / b)
    }
}
```

この例では、`b`が0ならエラーが返され、そうでなければ割り算の結果が返されます。
