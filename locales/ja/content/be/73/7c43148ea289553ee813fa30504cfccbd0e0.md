# 詳細

他の多くの言語と同じように、Goにもポインターがあります。
ポインターに初めて触れると、少し不思議なものに感じるかもしれませんが、慣れてしまえばとても素直な仕組みです。
ポインターはGoの重要な要素なので、時間をかけてしっかり理解しておきましょう。

詳しい話に入る前に、ポインターが何のためにあるのかを知っておきましょう。
ポインターは、プログラムの別の場所とメモリーを共有するための仕組みです。これが役に立つのは、大きく分けて次の2つの理由からです。

1. 大量のデータを扱うとき、関数の間でコピーを渡すのはとても非効率です。
   代わりに、データが保存されているメモリーの位置を渡せば、プログラムのリソース消費を大幅に減らせます。
2. 関数の間でポインターを渡せば、データの1つのコピーに直接アクセスして変更できます。
   つまり、ある関数でした変更は、その関数が終わった時点でプログラムの他の部分からすぐに見えるということです。

## 変数とメモリー

ふつうの整数の変数`a`があるとしましょう。

```go
var a int
```

変数を宣言すると、Goはその値を保存する場所をメモリーの中に探します。
このあたりの仕組みは、ほとんど意識しなくても済みます。そのメモリーに保存された値を取り出したいときは、変数名を指定するだけでよいのです。

たとえば、`a + 2`と書くと、変数`a`に対応するメモリーに保存された値を取り出して、それに2を足していることになります。

同じように、`a`のメモリーに入っている値を変えたいときは、変数名を使って代入します。

```go
a = 3
```

これで、`a`に対応するメモリーには値`3`が保存されます。

## ポインター

変数を使うとメモリー上の値を参照できますが、その変数が指している**メモリーアドレス**を知りたいこともあります。
**ポインター**は、そうした値のメモリーアドレスを保持します。
ポインター型の変数を宣言するには、元の型の前にアスタリスクを付けます。

```go
var p *int // 'p' contains the memory address of an integer
```

ここでは、「intへのポインター」型（`*int`）の変数`p`を宣言しています。
つまり、`p`には整数のメモリーアドレスが入るということです。
ポインターのゼロ値は`nil`です。`nil`のポインターはメモリーアドレスを何も持っていないからです。

### 変数へのポインターを取得する

変数の値のメモリーアドレスを調べるには、`&`演算子を使います。
たとえば、変数`a`のメモリーアドレスを調べてポインター`p`に保存したいときは、次のように書きます。

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### ポインター経由で値にアクセスする（参照外し）

ポインターがあれば、そのポインターが表すメモリーアドレスに保存されている値を知りたくなることがあります。
それには`*`演算子を使います。

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p`という操作は、`p`に保存されたメモリーアドレスにある値を取り出します。
この操作はよく「参照外し」と呼ばれます。

参照外し演算子を使うと、ポインターが参照しているメモリーアドレスに新しい値を代入することもできます。

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa`に代入すると、`pa`が保持しているメモリーアドレスに保存された値が変わります。
`pa`は`a`のメモリーアドレスを保持しているので、`*pa`に代入することは、つまり`a`の値を変えていることになります。

ただし、1つ注意点があります。参照を外す前に、ポインターが`nil`でないことを必ず確認してください。
`nil`のポインターの参照を外すと、実行時にプログラムがクラッシュしてしまいます。

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### 構造体へのポインター

ここまでは、プリミティブな値へのポインターしか見てきませんでした。
構造体のポインターも作れます。

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

新しい`Person`を作って、そのポインターをすぐに保存することもできます。

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

構造体へのポインターがあるときは、フィールドにアクセスする前に参照を外す必要はありません。

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## スライスとマップはすでにポインターです

スライスとマップは、実装の中にすでにポインターを持っている特別な型です。
そのため、これらの型の値のメモリーアドレスを共有するために、わざわざポインターを作る必要はほとんどありません。
マップのあるキーの値を1増やす関数を考えてみましょう。

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

マップを作ってこの関数を呼び出すと、関数がマップに加えた変更は、関数が終わったあともそのまま残ります。
これはポインターを使ったときとよく似た動作ですが、この例では参照や参照外しなど、ポインターの構文を一切使っていないことに注目してください。

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

スライス内の既存の要素を変更するときも同じです。

ただし、`append`のように新しいスライスを返す操作は特別で、関数の外側のスライスを**変更しない**ことがあります。
これはスライスの内部の仕組みによるものですが、少し高度な話題なので、ここでは詳しくは扱いません。
もっと知りたい場合は、[Go Blog: Mechanics of 'append'][mechanics-of-append]で詳しく読めます。

## ポインター演算

他の言語と違い、Goはポインター演算をサポートしていません。
つまり、ポインターの値を増やして、ある値のメモリーアドレスから別の値のアドレスに移動することはできません。
そのため、次のようなコードは書けません。

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
