# 説明の補足

## `from_quote`の長所と短所

この演習では、`Card`型に`from_quote`関数を定義します。これにより、次のようなコードを書くことができます。

```roc
card : Card
card = "Q"
```

このコードは、コンパイル時に暗黙的に`Card.from_quote("Q")`を呼び出します。実行時にパース処理をする必要がないため、プログラムを高速化できる可能性があります。また、`from_quote`に拒否されたカードは、実行時ではなくコンパイル時に検出されます。さらに、コードが読みやすくなります。たとえば、この演習のテストの一つを見てみましょう。

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

しかし、このコードを読んだ人は、`simulate_game`関数が2つの`List(Str)`を含むレコードを受け取ると勘違いするかもしれません。実際には、2つの`List(Card)`を含むレコードです。これは混乱やエラーの原因になりえます。そのため、少し長くなりますがより明示的な`"Q".Card`という書き方を好むかもしれません。これもコンパイル時に`from_quote`を呼び出します。

自分のプログラムでは、代わりに`from_str`を使うほうがよいかもしれません。

```roc
Card := { ... }.{
    from_str : card_str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

次のように、コンパイル時に`from_str`（または他の任意の純粋関数）を呼び出すこともできます。

```roc
Ok(card) = Card.from_str("Q")
```

注：この定義をトップレベルに置くと、コンパイル時に実行されます（関数が純粋で、入力がコンパイル時にわかっているためです）。関数の中では、実行時に`from_str`を使うことができます。
