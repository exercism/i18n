# 指示の補足

## 実装

Goのエラーやパニックに慣れていない場合は、まず[これらのトピックに関するドキュメント](https://blog.golang.org/defer-panic-and-recover)を読んで背景を理解することをお勧めします。

この演習では、関数`Use(opener ResourceOpener, input string) error`を定義する必要があります。この関数は、リソースを開き、結果のリソースに対して`Frob(input)`を呼び出し、その後（すべての場合において）そのリソースを閉じます。
関数はエラーとパニックを適切に処理する必要があります。

`ResourceOpener opener`は、リソースを「開く」ために直接`opener()`を呼び出すことができる関数です。
これは、[Goの慣用的な方法](https://blog.golang.org/error-handling-and-go)で`Resource`とエラー値を返します：

`Resource`、`ResourceOpener`、`FrobError`、`TransientError`の定義については、[common.go](./common.go)ファイルを参照してください。
解答は、[common.go](./common.go)と[error_handling_test.go](./error_handling_test.go)と同じパッケージ「erratum」に定義します。
これにより、それらの型を解答で使用できるようになります。

`Use`関数内でエラーが発生する可能性がある箇所がいくつかあります：

- 最初の引数としてUseに渡された`ResourceOpener`関数を呼び出すと、`TransientError`型のエラーで失敗することがあります。その場合は、リソースを開く試行を続けてください。
  それ以外の種類のエラーであれば、`Use`関数からそのエラーを返してください。

- `ResourceOpener`関数から返された`Resource`に対して`Frob`関数を呼び出すと、`FrobError`（または別の種類のエラー）で**パニック**する可能性があります。
  本当に`FrobError`である場合は、リソースの`Defrob`関数を呼び出す必要があります。その際、_パニックした`FrobError`の`.defrobTag`変数を`Defrob`関数への入力として使います_。
  いずれの場合も、`Use`はエラーを返す必要があります。

- _また注意してください_：`Resource`が正常に開かれた場合は、何があっても（エラーが発生した場合でも）その`Close`関数を正確に一度だけ呼び出すようにしてください。

特定のエラー型のテストは、[型アサーション](https://golang.org/ref/spec#Type_assertions)で行うことができます。
また、パニックからの回復時にエラー情報を返す便利な方法として、[名前付き戻り値](https://blog.golang.org/defer-panic-and-recover)を参照する必要があるかもしれません。
