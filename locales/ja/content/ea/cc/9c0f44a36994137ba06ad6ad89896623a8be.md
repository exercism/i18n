# 説明

食料品の買い物を自動化する会社Mecha Munch™に、注文アプリの開発メンバーとして加わることになりました。
チームの任務は、ショッピングカートの基本的な操作をすべて管理するMVP（_[実用最小限の製品][mvp]_）を作ることです。ユーザーが食料品の注文を追加・削除・並べ替えできるようにします。
ありがたいことに、お金と会計の処理は別のチームが担当してくれています！

## 1. ユーザーのショッピングカートに商品を追加する

このMVPでは、ユーザーが自分のショッピングカートに商品を追加できるようにします。
追加するのは1つの商品でも、一度に複数の商品でもかまいません。
MVPなので、商品の数量は_繰り返し_で表します。
ユーザーがオレンジを2つ追加したい場合、入力のイテラブルに'オレンジ'が2回現れます。
その商品がすでにカートに入っている場合は、カートの数量を1増やします。
その商品がカートにとって_新しい_ものであれば、数量1で追加します。

引数にカートの辞書と、追加する商品のイテラブルを取る関数`add_items!(<cart>, <items>)`を作成します。
更新後のユーザーのショッピングカートの辞書を返します。

```julia-repl
julia> additems!(Dict("Banana" => 3, "Apple" => 2, "Orange" => 1),
                 ("Apple", "Apple", "Orange", "Apple", "Banana"))
Dict{String, Int64} with 3 entries:
  "Apple"  => 5
  "Orange" => 2
  "Banana" => 4

julia> additems!(Dict("Banana" => 3, "Apple" => 2, "Orange" => 1),
                 ["Banana", "Orange", "Blueberries", "Banana"])
Dict{String, Int64} with 4 entries:
  "Blueberries" => 1
  "Apple"       => 2
  "Orange"      => 2
  "Banana"      => 5
```

## 2. レシピの「アイデア」セクションを更新する

ユーザーはこれらのレシピから好きなものを1つ選ぶと、その材料がすべて自動的にショッピングカートに追加されます。
プロジェクトマネージャーから、この「アイデア」レシピを編集する方法を作るよう頼まれました。コンテンツチームが材料や数量を頻繁に変更しているためです。

引数に「アイデア」の辞書と、レシピ更新の辞書を取る関数`update_recipes!(<ideas>, <updates>)`を作成します。

## 3. ユーザーのショッピングカートを店舗に送って発送準備をする

アプリは、ユーザーのカートを店舗に送って発送準備を依頼する必要があります。
ただし、店舗のスタッフは、商品がどこにあるかを一意の通路コードで知る必要があります。
「発送用カート」は、スタッフが効率よく作業できるよう、商品の通路コード順に並べ替える必要があります。

引数にユーザーのショッピングカートと、店舗の通路番号を持つ辞書を取る関数`send_to_store(<cart>, <aislecodes>)`を作成します。
この関数は、お客様が注文する各商品について`aislecode => quantity`のペアを持つ、統合された「発送用カート」を返します。
商品は通路コードの順に並びます。

```julia-repl
julia> cart = Dict("Orange" => 1, "Milk" => 2, "Banana" => 3, "Apple" => 2, "Chocolate" => 2);

julia> aislecodes = Dict("Orange" => 2.4, "Milk" => 3.3, "Banana" => 2.6, "Apple" => 2.2, "Chocolate" => 5.7);

julia> send_to_store(cart, aislecodes)
5-element Vector{Pair{Float64, Int64}}:
 2.2 => 2
 2.4 => 1
 2.6 => 3
 3.3 => 2
 5.7 => 2
```

## 4. ユーザーの注文を反映して店舗の在庫を更新する

アプリがお客様の注文をいつまでも受け付けるわけにはいきません。
いずれ店舗のさまざまな商品は在庫切れになります。
そのため、MVPのアプリは、ユーザーが注文を店舗に送るたびに店舗の在庫を更新する必要があります。
そうしないと、お客様が実際には在庫のない商品を注文してしまいます。

引数に`cart`と`inventory`を取る関数`update_store_inventory!(<inventory>, <cart>)`を作成します。
この関数は、店舗の在庫数から「カート」で「注文された」数だけ減らし、在庫切れ（つまり`0`になった）商品の辞書を返します。

```julia-repl
julia> inventory = Dict("Banana" => 15, "Apple" => 12, "Orange" => 1, "Milk" => 4);

julia> cart = Dict("Orange" => 1, "Milk" => 2, "Banana" => 3, "Apple" => 2);

julia> update_store_inventory!(inventory, cart)
Dict{String, Int64} with 1 entry:
  "Orange" => 0

julia> inventory
Dict{String, Int64} with 4 entries:
  "Milk"   => 2
  "Apple"  => 10
  "Orange" => 0
  "Banana" => 12
```

## 5. 在庫切れの商品を再発注する

在庫の更新だけでなく、アプリは在庫の補充も手伝えます。
MVPは、お客様の注文後に在庫切れになった商品のミニ発注を準備できるようにします。
こうすることで、大きな発注を出すのが簡単になります。
さらに、在庫リストにない期間限定のプロモーション商品があることもあります。
こうした商品がプロモーション期間の終了前に売り切れたなら、人気が証明されたわけなので、在庫リストに追加できます。

引数に`outofstock`と`stock`を取る`reorder!(<outofstock>, <stock>)`を作成します。
`stock`の辞書には、標準的な在庫商品とその再発注数量が入っています。
`outofstock`の辞書は`update_store_inventory!`の結果、つまり数量が0になった商品の辞書です。
`outofstock`の数量は、`stock`の数量を反映するように更新して返します。
また、`outofstock`にあって`stock`にない商品は、デフォルトの数量`100`で`stock`に追加します。

```julia-repl
julia> inventory = Dict("Banana" => 15, "Apple" => 12, "Orange" => 1, "Milk" => 4, "Chocolate" => 2);

julia> cart = Dict("Orange" => 1, "Milk" => 2, "Banana" => 3, "Apple" => 2, "Chocolate" => 2);

julia> stock = Dict("Banana" => 150, "Apple" => 120, "Orange" => 120, "Milk" => 45);

julia> outofstock = update_store_inventory!(inventory, cart)
Dict{String, Int64} with 1 entry:
  "Orange"    => 0
  "Chocolate" => 0

julia> reorder!(outofstock, stock)
Dict{String, Int64} with 1 entry:
  "Orange"    => 120
  "Chocolate" => 100

julia> stock 
Dict{String, Int64} with 5 entries:
  "Milk"      => 45
  "Apple"     => 120
  "Chocolate" => 100
  "Orange"    => 120
  "Banana"    => 150
```
