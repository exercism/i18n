# ジェネリックなデータ型

Cairoのジェネリクスを使うと、さまざまな型で動作する再利用可能なコードを書けるようになり、重複を避けて保守性を高めることができます。

ジェネリクスは、関数、構造体、列挙型、トレイト、メソッドで使うことができます。

## ジェネリック関数

ジェネリック関数は、別々の実装を用意しなくても、異なる型を扱うことができます。

たとえば、次のとおりです。

```rust
fn largest_list<T>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

ここで、`T`は任意の型のプレースホルダーです。

ただし、Cairoでは、ジェネリック型が特定の要件を満たすことを保証するために、トレイト境界が必要です。

`T`をドロップ可能にする必要がある場合は、シグネチャを次のように更新できます。

```rust
fn largest_list<T, impl TDrop: Drop<T>>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

`Drop`や`PartialOrd`のようなトレイト境界は、特定の操作のためにジェネリクスに制約を追加します。

## 無名の制約

トレイトの実装が関数内で直接使われない場合は、`+`を使って無名の制約を書くことができます。

```rust
fn smallest_element<T, +PartialOrd<T>, +Drop<T>, +Copy<T>>(list: @Array<T>) -> T {
    let mut smallest = *list[0];
    let mut index = 1;

    while index < list.len() {
        if *list[index] < smallest {
            smallest = *list[index];
        }
        index += 1;
    };

    smallest
}
```

これにより、`TPartialOrd`のようなトレイトに名前を付ける必要がなくなり、記述が簡潔になります。

## ジェネリクスを持つ構造体

構造体でジェネリクスを使うと、フィールドを柔軟にできます。

たとえば、次のとおりです。

```rust
#[derive(Drop)]
struct Wallet<T> {
    balance: T,
}

let w = Wallet { balance: 42 };
```

構造体で複数のジェネリック型が必要な場合は、プレースホルダーをさらに追加するだけです。

```rust
#[derive(Drop)]
struct Wallet<T, U> {
    balance: T,
    address: U,
}

let w = Wallet { balance: 42, address: '0xabc' };
```

## ジェネリクスを持つ列挙型

列挙型もジェネリックなデータ型を保持できます。

たとえば、次のとおりです。

```rust
enum Option<T> {
    Some: T,
    None,
}
```

`Option<T>`という列挙型は、任意の型のオプション値を表すことができます。

同様に、`Result<T, E>`では、成功時と失敗時の型を定義できます。

```rust
enum Result<T, E> {
    Ok: T,
    Err: E,
}
```

## ジェネリックメソッド

メソッドでもジェネリクスを使うことができます。

たとえば、次のとおりです。

```rust
#[derive(Copy, Drop)]
struct Wallet<T> {
    balance: T,
}

trait WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T;
}

impl WalletImpl<T, +Copy<T>> of WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T {
        *self.balance
    }
}

let w = Wallet { balance: 50 };
assert!(w.balance() == 50);
```

`Wallet<u128>`のような特定のジェネリック型に対してメソッドを定義することもできます。

```rust
trait WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128);
}

impl WalletReceiveImpl of WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128) {
        self.balance += value;
    }
}

let mut w = Wallet { balance: 50 };
w.receive(100);
assert!(w.balance() == 150);
```

## ジェネリック型の組み合わせ

ジェネリクスは複雑な組み合わせも扱うことができます。

たとえば、異なる型の2つの`Wallet`インスタンスを組み合わせる場合は、次のようになります。

```rust
trait WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2>;
}

impl WalletMixImpl<T1, +Drop<T1>, U1, +Drop<U1>> of WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2> {
        Wallet { balance: self.balance, address: other.address }
    }
}

let w1 = Wallet { balance: true, address: 10 };
let w2 = Wallet { balance: 32, address: 100 };
let w3 = w1.mixup(w2);

assert!(w3.balance);
assert!(w3.address == 100);
```

`+Drop`制約を追加すると、コンパイラーがリソースの適切な処理を保証します。

ジェネリクスは強力ですが、制約を慎重に管理する必要があります。

再利用可能で、型に依存せず、簡潔なコードを書くために使いましょう。
