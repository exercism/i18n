# はじめに

[concept:csharp/resource-cleanup]()では、`IDispose`インターフェースを使って、あるオブジェクトが不要になったときに、そのオブジェクトのリソースやその他のプログラムの状態を解放またはリセットする必要があること（そして、ガベージコレクターに任せるだけではそれを実現できず、必要なレベルの制御も得られないこと）、そして、そうした後片付けには`IDisposable.Dispose()`メソッドが自然な場所であることを示します。

もうひとつ、`using`ブロックという構文があります。これは、呼び出す側から見ると、リソースのライフタイム管理をすべて1つの文にまとめることができるようにします。

```csharp
using (var file = new File("my_secrets"))
{
    file.WriteSecret("xxxxxxx");
}
```

上の例では、`file`に紐づくファイルシステムのリソースは、`using`ブロックを抜けたときにオペレーティングシステムに返されます。

このパターンが機能するには、`using`文の変数が`IDisposable`インターフェースを実装した参照型である必要があり、その`Dispose()`メソッドの中でリソースを解放するか、プログラムの状態をリセットしなければなりません。

C# 8では、このパターンがさらに洗練されました。`using`文をブロックの先頭に置けるようになりました。

```csharp
using var drawingResource = some_provided_or_new_object;
try
{
    drawingResource.DrawSomething();
}
catch (Exception)
{
    throw;
}
```

Javaのエンジニアなら、Java 7で導入された_自動リソース管理_の仕組みに似ていると気づくかもしれません。
