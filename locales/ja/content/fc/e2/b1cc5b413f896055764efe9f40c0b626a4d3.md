# マップとセット

| 型 | 保持するもの | 探す手がかり |
| --- | --- | --- |
| `ARRAY{T}` | 順序どおりの値 | 位置 |
| `FMAP{K,T}` | キーと値のペア | キー |
| `FSET{T}` | 重複のない値 | 含まれるかどうか |

## FMAP

```sather
   m ::= #FMAP{STR,INT};
   m := m.insert("emu", 2);
   m.get("emu")          -- 2
   m.has_ind("emu")      -- true
   m.size                -- 1
   m := m.delete("emu");
```

`m["emu"]`は、マップを読む方法では**ありません**。`FMAP`にそのようなルーチンはなく、この行はコンパイルできません。使うのは`get`です。

### 存在しないキー

存在しないキーに対して`get`を呼ぶと、文句を言うのではなく、その型の空の値が返ります。`0`、`false`、あるいはvoidです。voidの`STR`は、作られた時点では失敗しません。失敗するのは、その後、最後に使われる場所です。まず`has_ind`で確認するのが、身につける価値のある習慣です。

## FSET

```sather
   s ::= #FSET{STR};
   s := s.insert("emu");
   s.has("emu")          -- true
   s.size                -- 1
   s := s.delete("emu");
```

セットは組み合わせられます：

```sather
   a.union(b)            -- in either
   a.intersect(b)        -- in both
   a.difference(b)       -- in a but not b
   a.is_subset(b)
```

## 代入し直すこと、そしてコピー

`insert`と`delete`は、これ以降使うべきコンテナを返します。ふつうは同じオブジェクトがその場で変更されて返りますが、大きくなる必要があるときは、より大きな新しいオブジェクトになります。つまり、こうです：

```sather
   m := m.insert(k, v);     -- always
```

そして、その後で信頼できるのは、左辺の名前だけです。`insert`の前に取った、同じマップを指す別の名前は、古くなっているかもしれません。

独立したコピーを保つには、まずコピーを取ります：

```sather
   n ::= m.copy.insert(k, v);      -- m is unchanged
```

ただし、注意点がひとつあります。まだ何も挿入したことのないマップは**void**で、voidのマップに対する`copy`は失敗します。`insert`、`get`、`has_ind`、`size`はどれもvoidのマップを扱えます。`#FMAP{K,T}`はvoidであり、そこに挿入することが、マップが最初に生まれる方法だからです。ただ、`copy`だけは扱えません。

`HMAP`と`HSET`は、必ずその場で変更されるだけのバージョンです。大きなものを組み立てるときは速いですが、学習中の既定としては間違った選択です。

## 中身をたどる

| イテレーター | 得られるもの |
| --- | --- |
| `m.ind!` | 各キー |
| `m.target!` | 各値 |
| `m.pair!` | キーと値をひと組ずつ |
| `s.elt!` | セットの各値 |

マップにもセットにも順序はありません。2回実行すると、たどる順序が変わるかもしれません。ですから、どちらが先に来るかに依存するものは決して書かないでください。

```sather
   loop
      #OUT + guide.ind! + "\n";
   end;
```
