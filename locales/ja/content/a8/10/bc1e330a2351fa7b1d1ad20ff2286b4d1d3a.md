# はじめに

前のコンセプトでは、パックド浮動小数点値を紹介しました。これは、複数の数値を1つの`xmm`レジスタに格納し、レーンごとに並列して操作するものです。
同じ`xmm`レジスタは、パックド_整数_も保持できます。

## 構文

SIMD浮動小数点モデルのほとんどは、パックド整数にもそのまま当てはまります。

- 128ビットレジスタはレーンに分割されます
- 命令は、同じ位置にあるレーンを並列して操作します
- メモリオペランドは、同じ16バイトのアラインメント規則に従います

ただし、構文は少し異なります。

1. 命令が_パックド_データを操作することを示す_接頭辞_`p`。
2. 実行される操作。非SIMD（_スカラー_とも呼ばれます）の対応する操作と同じ名前です（例: `add`、`mul`など）。
3. 各レーンのサイズを示す接尾辞。

パックド整数には4つのレーンサイズがあり、それぞれに独自の接尾辞があります。

| レーン幅 | バイト数 | 128ビット内のレーン数 | 接尾辞 |
|------------|-------|-------------------|--------|
| バイト       | 1     | 16                | b      |
| ワード       | 2     | 8                 | w      |
| ダブルワード      | 4     | 4                 | d      |
| クアッドワード      | 8     | 2                 | q      |

たとえば、次のようになります。

| 命令 | 意味                              |
|-------------|--------------------------------------|
| `paddb`     | パックド`add`、8ビットレーン（16レーン） |
| `paddw`     | パックド`add`、16ビットレーン（8レーン） |
| `paddd`     | パックド`add`、32ビットレーン（4レーン） |
| `paddq`     | パックド`add`、64ビットレーン（2レーン） |

一部の命令は、あるサイズのレーンを入力として受け取り、別のサイズを出力します。
これらは同じ一般的な規則に従いますが、サイズ接尾辞を_2つ_持ちます。
1つ目は入力レーンのサイズ、2つ目は出力レーンのサイズを示します。

| 命令  | 意味                                           |
|--------------|---------------------------------------------------|
| `pmovsxwd`   | パックド`movsx`、16ビットレーンから32ビットレーンへ |
| `pmuldq`     | パックド`mul`、32ビットレーンから64ビットレーンへ   |

## メモリ移動

整数名を持つ2つの命令は、`xmm`レジスタとメモリの間で128ビットをコピーします。

| 命令 | 説明                                             |
|-------------|---------------------------------------------------------|
| `movdqa`    | _アラインメントされた_場所との間でパックド整数をコピーします   |
| `movdqu`    | _アラインメントされていない_場所との間でパックド整数をコピーします |

これらは`movaps`と`movups`のように動作します。`movdqa`はアラインメントされていないアドレスでフォールトしますが、`movdqu`はどのようなアドレスも受け付けます。
4つとも、128ビットを解釈せずにコピーします。
整数名のペアは、要件ではなく慣習として整数データとともに使われます。

~~~~exercism/note
ここでの`dq`は`double-qword`、つまり128ビット（16バイト）を表します。
~~~~

## 加算/減算

加算と減算は、命名規則に従います。

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

符号付きと符号なしの別形式はありません。
2の補数では、加算と減算は、レーンを符号付きとして読むか符号なしとして読むかに関係なく同じビットを生成するため、1つの命令で両方を扱えます。
解釈は、スカラーの`add`と`sub`の場合とまったく同じく、読む側に任されます。

これらの命令は、スカラーの対応命令と同様、オーバーフロー時に**ラップアラウンド**します。
8ビットレーンは値を256を法として保持するため、`paddb`で`200 + 100`を計算すると`300 - 256 = 44`になり、収まらないビットは切り捨てられます。

これらの余分なビットは、次のレーンに繰り越されないことに注意してください。
各レーンは、同じレジスタを共有していても、他のレーンとは別々に操作されます。

## 飽和加算/減算

整数SIMDには、浮動小数点SIMDにはない操作が追加されています。それは**飽和**加算と減算で、ラップアラウンドの代わりに_飽和_させます。
レーンの範囲を超える結果は、そのレーンが保持できる最大値になり、範囲を下回る結果は最小値になります。

飽和形式では、サイズ接尾辞の前に`s`（符号付き）または`us`（符号なし）を挿入します。

| 命令 | 意味                                    |
|-------------|--------------------------------------------|
| `paddsb`    | `add`、飽和、符号付き8ビットレーン      |
| `paddusb`   | `add`、飽和、符号なし8ビットレーン    |
| `psubsw`    | `sub`、飽和、符号付き16ビットレーン     |
| `psubusw`   | `sub`、飽和、符号なし16ビットレーン   |

飽和の範囲は、対応するサイズと符号の有無に対して整数が表現できる全範囲です。
バイトの場合、次のようになります。

- 符号なしバイトは`[0, 255]`に飽和します。`paddusb`で`200 + 100`を計算すると`255`になり、`psubusb`で`5 - 10`を計算すると`0`になります。
- 符号付きバイトは`[-128, 127]`に飽和します。`paddsb`で`100 + 50`を計算すると`127`になります。

飽和は、ピクセルのチャンネルやオーディオサンプルのように、レーンが範囲の限られた値を保持する場合に重要になります。
ラップアラウンドでは明るすぎるピクセルが暗くなってしまいますが、飽和させれば最大の明るさを保つことができ、これが望ましい結果です。

~~~~exercism/note
飽和加算と飽和減算は、バイトとワードのレーンにのみ存在し、ダブルワードやクアッドワードには存在しません。
~~~~

## 乗算

2つのNビット値を乗算すると2Nビットの積が得られますが、出力先のレーンはNビット幅しかありません。
SIMD演算では、積のどちらの半分を保持するか、つまり下位Nビットか上位Nビットかを指定することで、これを解決します。

16ビットレーンの場合、3つの命令が使われます。

| 命令 | 意味                                                       |
|-------------|---------------------------------------------------------------|
| `pmullw`    | `mul`、16ビットレーン、各積の下位16ビットを保持     |
| `pmulhw`    | `mul`、16ビットレーン、上位16ビットを保持、符号付きオペランド   |
| `pmulhuw`   | `mul`、16ビットレーン、上位16ビットを保持、符号なしオペランド |

積の下位16ビットは、オペランドを符号付きとして読むか符号なしとして読むかに関係なく同じであるため、`pmullw`は1つだけです。

一方、上位16ビットは、結果の符号の有無によって異なります。
そのため、上位半分の乗算には、符号付き乗算と符号なし乗算の別形式があります。

1. `pmulhw`：符号付き乗算用。
2. `pmulhuw`：余分な`u`が付き、符号なし乗算用。

構文に注意してください。

1. `p`：パックド整数を表します。
2. 実行される操作`mul`。
3. `h`：結果の上位（「high」）ビットが選択されることを示します。
4. 結果を符号なしとして解釈する必要がある場合の省略可能な`u`（つまり、符号拡張されません）。
5. 最後に、サイズ接尾辞`w`：ワード（16ビット）操作であることを示します。

ワードのパックド乗算は、上記の規則に正確に従います。
ダブルワード（32ビット）乗算もこの規則に従いますが、下位半分を選択する変種しかありません。`pmulld`です。

上位ビットを選択するダブルワード乗算の変種はありません。
ただし、乗算を_拡張_し、_偶数番目_のレーン（つまり、位置0と2のレーン）の完全な64ビット積を格納する変種があります。

| 命令 | 意味                                                                          |
|-------------|----------------------------------------------------------------------------------|
| `pmuludq`   | 偶数番目の32ビット要素を符号なしで乗算し、2つの完全な64ビット積にする |
| `pmuldq`    | 偶数番目の32ビット要素を符号付きで乗算し、2つの完全な64ビット積にする   |

構文では`dq`を使い、符号なし乗算の場合はその前に`u`が付くことがあります。
これは、これらの命令が`dword`レーンを入力として受け取り、`qword`レーンを出力するためです。

## 除算

パックド整数の除算はありません。
それが必要なコードは、値を浮動小数点に変換し、除算してから元に戻します。

## 整数の拡張

`movsx`と`movzx`には、パックド版があります。
これらは、入力と出力でレーンサイズが異なる命令について前述したのと同じ構文に従います。

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

レーン数は、より大きい方（出力側）の幅によって決まることに注意してください。
命令は、ソースの下位部分からその数のレーンを読み取ります。
これは、単精度と倍精度の浮動小数点数の間のパックド`cvt`命令ですでに見たのと同じ意味論です。

## 整数と浮動小数点数の変換

32ビット符号付き整数と浮動小数点レーンの間で変換する命令があります。
これらは`cvt`と`cvtt`命令の通常の構文に従いますが、`si`の代わりにパックド整数は`dq`で表されます。

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
パックド整数を表すために`pi`を使う命令は、レガシーの`mmx`レジスタに書き込み、x86-64では事実上非推奨です。
`xmm`レジスタを使う`dq`形式を優先してください。
~~~~

浮動小数点数と整数の間のスカラー変換について述べたのと同じ注意点がここでも当てはまります。
浮動小数点数は、MXCSRと呼ばれる特別なレジスタに従って丸められ、関数に入った時点でそのモードを仮定することはできません。
常に結果を切り捨てる`cvtt`変種（余分な`t`が付く）があります。

変換前にパックド浮動小数点値を既知の状態にするために、`round`を使うこともできます。
丸め制御値はスカラーの`round`と同じで、構文もパックド浮動小数点値の場合と同じです。

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
