# はじめに

## メソッドの集まりとしてのインターフェース

最も単純な形では、**インターフェース型**はメソッドのシグネチャの集まりです。
次は、`Add`と`Value`という2つのメソッドを含むインターフェース定義の例です。

```go
type Counter interface {
    Add(increment int)
    Value() int
}
```

`increment`のような仮引数名は、インターフェース定義から省略できますが、可読性が上がることがよくあります。

Goのインターフェース名に、`Interface`や`I`という語は含まれません。
その代わり、`Reader`や`Stringer`のように`er`で終わることがよくあります。

## インターフェースを実装する

インターフェースのメソッドを定義している型は、自動的に、暗黙的にそのインターフェースを「実装」します。
Goには`implements`というキーワードはありません。

次の型は、上で見た`Counter`インターフェースを実装しています。

```go
type Stats struct {
    value int
    // ...
}

func (s Stats) Add(v int) {
    s.value += v
}

func (s Stats) Value() int {
    return s.value
}

func (s Stats) SomeOtherMethod() {
    // The type can have additional methods not mentioned in the interface.
}
```

インターフェースを実装するうえでは、メソッドのレシーバーが値レシーバーかポインタレシーバーかは関係ありません。
（これらについて不安があれば、[メソッドの概念][concept-methods]をもう一度見てください。）

> インターフェース型の値は、それらのメソッドを実装する任意の値を保持できます。 ((Go Tour: Interfaces)[go-tour-interfaces])

つまり、`Stats`は、`Counter`インターフェースを期待するあらゆる場所で使えるようになりました。

```go
func SetUpAnalytics(counter Counter) {
    // ...
}

stats := Stats{}
SetUpAnalytics(stats)
// works because Stats implements Counter
```

インターフェースは暗黙的に実装されるので、1つの型が複数のインターフェースを簡単に実装できます。
必要なメソッドがすべて定義されていればよいだけです。

## 空のインターフェース

Goには、とても特別なインターフェース型が1つあります。メソッドを1つも持たない**空のインターフェース**型です。
空のインターフェースは、`interface{}`のように書きます。
Go 1.18以降では、`any`も使えます。
これはエイリアスとして定義されました。

空のインターフェースにはメソッドがないので、すべての型が暗黙的にこれを実装しています。
これは、あらゆる値を汎用的に受け取れる関数を定義するのに役立ちます。
その場合、関数の仮引数には空のインターフェース型を使います。
