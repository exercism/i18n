# 説明

友人のLinusは、都市と都市の間で貨物列車を運転する機関士です。列車の扱いは得意ですが、物流やコンピューターの扱いは得意ではありません。Linusは、列車の情報を整理し、ルートデータの間違いを直すのを、プログラミングで手伝ってほしいと考えています。

~~~~exercism/note
この演習は、スライスやインデックス、さまざまな`Dict`のメソッドを使えば簡単に解けます。ただし、以下の各タスクを解くときは、パッキング（つまりslurping）、アンパッキング（つまりsplatting）、そして多重代入を練習してほしいと思います。
~~~~

## 1. すべての貨車のベクトルを作成する

Linusは、各貨車の識別子（ID）を記録してきましたが、システムがいつどれだけの数の貨車を処理することになるのか、いつも確信が持てません。このデータを1つの`Vector`にまとめておけば、残りの物流プログラムはずっと扱いやすくなります。

任意の数の貨車IDを受け取る関数`get_vector_of_wagons(args...)`を実装してください。
各IDは正の整数です。
関数は、与えられたIDを1つの`Vector`として`return`するようにします。

```julia-repl
julia> get_vector_of_wagons(1, 7, 12, 3, 14, 8, 5)
7-element Vector{Int64}:
  1
  7
 12
  3
 14
  8
  5
```

## 2. 貨車のベクトルを修正する

ここまでで、データと、それが物流プログラムでどのように使われるかが、なんとなく見えてきたのではないでしょうか。
IDシステムでは、機関車には常に**1**のIDが割り当てられ、列車の残りの貨車には**1**より大きいランダムなIDが割り当てられます。

Linusは列車に新しい貨車を2つ連結する必要がありましたが、システムを更新するのを忘れてしまいました！　今、列車の`Vector`にある最初の2つの貨車を末尾に移動しないと、すべての順序が狂ってしまいます。

さらに面倒なことに、Linusは、行方不明の貨車IDが含まれているらしい2つ目の`Vector`をたった今見つけました。
覚えているのは、新しい貨車を移動したあと、この2つ目の`Vector`のIDを、指定された機関車のすぐ後ろに置くべきだということだけです。

Linusは、間違いを直してデータを統合してくれると、とても喜びます。

2つの貨車IDの`Vector`を受け取る関数`fix_vector_of_wagons(each_wagons_id, missing_wagons)`を実装してください。
1つ目の`Vector`の最初の2つの要素を末尾に移動し、2つ目の`Vector`の値を機関車ID（**1**）の後ろ（_右側_）に挿入します。
関数は、変更後の`Vector`を`return`します。

```julia-repl
julia> fix_vector_of_wagons([2, 5, 1, 7, 4, 12, 6, 3, 13], [3, 17, 6, 15])
13-element Vector{Int64}:
  1
  3
 17
  6
 15
  7
  4
 12
  6
  3
 13
  2
  5
```

## 3. 不足している停車駅を追加する

すべての貨車データが正しくなったので、Linusは、システムの経路情報を更新してほしいと考えています。
輸送ルートでは、列車は貨物を積み下ろしするために、いくつかの駅に停車することがあります。
それぞれの旅で、こうした中間の配送地点の数は異なることがあります。
Linusは、不足している、あるいは追加の配送情報で、システムの経路`Dict`を更新してほしいと考えています。

経路の`Dict`と、そのあとに続く可変個の`stop_number => city`ペアを受け取る関数`add_missing_stops(route, stops...)`を実装してください。
関数は、追加されたすべての停車駅を順番どおりに格納した`Vectors`を値に持つ`key`を追加した、経路`Dict`を返します。

```julia-repl
julia> add_missing_stops(Dict("from" => "New York", "to" => "Miami"), :stop_1 => "Washington, DC", :stop_2 => "Charlotte", :stop_3 => "Atlanta", :stop_4 => "Jacksonville")
Dict{String, Any} with 3 entries:
  "stops" => ["Washington, DC", "Charlotte", "Atlanta", "Jacksonville"]
  "to"    => "Miami"
  "from"  => "New York"
```

## 4. 経路情報を拡張する

Linusは経路プログラムに取り組む中で、一部のルートで重要な詳細が欠けていることに気づきました。
初期の経路情報は`Dict`として構成されており、Linusは、足りないものをその`Dict`に追加して更新してほしいと考えています。
システム内の各ルートで必要な詳細は少しずつ異なるため、Linusは汎用的な解決策を強く望んでいます。

関数`extend_route_information(route; more_route_information...)`を実装してください。
この関数は、列車のルートが結ぶ出発地と目的地の都市を含む`Dict`と、列車の速度・長さ・温度といった経路の詳細を含む可変個のキーワード引数を受け取ります。
関数は、すべての経路情報をまとめた`Dict`を返します。

```julia-repl
julia> extend_route_information(Dict("from" => "Berlin", "to" => "Hamburg"); length = "100", speed = "50")
Dict{Any, String} with 4 entries:
  :speed  => "50"
  "to"    => "Hamburg"
  "from"  => "Berlin"
  :length => "100"


julia> extend_route_information(Dict("from" => "Paris", "to" => "London"), length = "15", temperature = "20", timeOfArrival = "10:30")
Dict{Any, String} with 5 entries:
  :temperature   => "20"
  :timeOfArrival => "10:30"
  "to"           => "London"
  "from"         => "Paris"
  :length        => "15"
```
