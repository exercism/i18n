# 概要

Swiftには多くの異なる型がありますが、それらはすべて_値型_と_参照型_という2つの分類のどちらかに属します。Swiftでは、[構造体は値型][structs-are-value-types]であり、[クラスは参照型][classes-are-reference-types]です。

値型と参照型の主な違いは、値型を変数や定数に代入したり、関数に渡したりするとき、代入・渡されるのはその値そのものではなく、値のコピーであるという点です。構造体のコピーを1つ変更しても、他のコピーには影響しません。参照型の場合は、代入・渡されるのはその値への参照なので、2つの異なる名前が同じクラスのインスタンスを指すことがあります。そのため、別の名前でアクセスしたときに元のインスタンスが変更されてしまうことがあります。

では、ゲームのキャラクターとそのゲーム上のステータスを定義する構造体とクラスを例に、これらの項目をコピーして変更するとどうなるかを見てみましょう。

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

`charB`のプロパティを変更すると`charA`のプロパティにも影響が出ていることに注目してください。どちらの名前も同じインスタンスを指しているからです。また、2人のキャラクターのステータスでは、参照型の中にある値型が、その参照型の中で変化することにも注目してください。ただし、これは値型の振る舞いに反するものではありません。`charA`と`charB`は`GameCharacter`クラスの同じインスタンスを指しているので、`charA.stats`は`charB.stats`と同じ`CharacterStats`のインスタンスだからです。たとえば、次のように、これらの値型のコピーが互いに影響し合うことはありません。

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

構造体のプロパティの状態を変更するメソッドの前に`mutating`キーワードが必要なのは、このためです。構造体のプロパティを変更すると、実際にはそのプロパティに新しい値が設定された構造体の新しいコピーが作られ、新しいコピーが古いコピーを置き換えます。これは、その型の値でこうしたコピーと置き換えが起こりうることを示す目に見える印です。

この副作用として、可変プロパティが変化する構造体のインスタンスは、mutatingな関数の呼び出しであれ直接代入であれ、定数ではなく変数に代入_しなければなりません_。そうしないと、コンパイラエラーが発生します。

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

初期値は作成もアクセスもできますが、変更することはできません。この制限はクラスには当てはまりません。`let`を使ってクラスのインスタンスを名前に代入した場合、定数が保持するのはそのインスタンスへの参照であり、変更できないのは参照であって、インスタンスそのものではありません。つまり、インスタンス自体は変更できますが、参照を別のインスタンスを指すように変更することはできません。

`let`や`var`で定義された構造体とクラスで何を変更できるかをまとめると、次のとおりです。

|         | **struct**                                                                                  | **class**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _Cannot_ assign a new struct to the name.</br>_Cannot_ modify any properties of the struct. | _Cannot_ assign a new class to the name.</br>_Can_ modify mutable properties of the class. |
| **var** | _Can_ assign a new struct to the name.</br>_Can_ modify mutable properties of the struct.   | _Can_ assign a new class to the name.</br>_Can_ modify mutable properties of the class.    |

## 同一性

2つの異なる名前が同じクラスのインスタンスへの参照を保持することがあるため、そうなっているかどうかを調べられると便利なことがあります。Swiftでは、これを調べるために`===`という_同一性_演算子を使います（その否定の`!==`もあります）。

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

2つの名前が同じ構造体のインスタンスを指すことはないため、これらの同一性演算子は構造体には定義されていません。

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

同一性は等値性と同じではないことに注意してください。多くの定義では、`char1`と`char3`はすべてのプロパティが同じ値を持つため等しいとみなされますが、同じ同一性を共有しているわけではありません。同一性はSwiftのすべてのクラスで自動的に利用できますが、構造体やクラスの2つのインスタンスが_等しい_かどうかを判定するには、通常、エンジニアが自分で等値演算子を書く必要があります。これを行うことは、この演習の範囲を超えています。
