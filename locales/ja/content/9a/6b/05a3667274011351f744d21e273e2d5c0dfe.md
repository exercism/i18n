# はじめに

2進数の各桁は、最終的にはCPUやRAMの中のトランジスタが「オン」か「オフ」かという状態に直接対応しています。

口語で「bit-twiddling」と呼ばれる低レベルな操作は、特にシステム言語で重要です。

Kotlinのような高水準言語では、こうした細かい部分のほとんどが通常は抽象化されています。
ただし、基本的なビット演算は[利用できます][ref-bitwise]。

## ビットシフト演算

符号付きでも符号なしでも、`Int`や`Long`型は1と0の文字列として表現でき、ビットの並びとして操作できます。

意外に思えるかもしれませんが、Kotlinでは`Byte`や`Short`型はほとんどのビット演算に対応していません。
以下の例はすべて32ビット整数（`Int`または`UInt`）を使います。

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

ビットシフトは、指定した桁数だけすべてのビットを左または右に動かすだけです。
片方の端からあふれたビットは消え、もう片方の端は0か1で埋められます。

- `shl`による左シフト：0で埋めます。
- `shr`または`ushr`による右シフト：正の数では0で埋めます（負の数については後述）。

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

左シフトするたびに値は2倍になり、右シフトするたびに値は半分になります（切り捨てが起こります）。
これは10進数で表すとよりはっきりわかります。

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

このようなビットシフトは「本来の」算術よりもずっと速いため、低レベルなプログラミングでとてもよく使われます。

_負の整数_を扱うときは、もう少し注意が必要です。

負の値は[2の補数][wiki-2complement]の形で保存されるので、最上位ビットは1になります。
左シフトでは問題ありませんが、右シフトでは最上位ビットをどう埋めればよいのでしょうか？

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

`shr`演算子は[算術シフト][wiki-arithmetic]を行い、符号ビットを保ちます。

`ushr`演算子は[論理シフト][wiki-logical]を行い、その数が符号なしであるかのように0で埋めます。

## ビット論理演算

[Booleansの概念][concept-booleans]では、`&&`（and）、`||`（or）、`!`（not）の各演算子を真偽値に対して使うことを学びました。

2つの整数のビットを比較するための、`and`、`or`、`xor`（[排他的論理和][wiki-xor]）という対応する演算子と、すべてのビットを反転させる`inv`（反転）関数があります。

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
