# Docker

テストランナーは、Dockerイメージとしてデプロイされています。

これらの仕組みを理解するために、まずは[ToolingのDockerに関する一般的な情報](/docs/building/tooling/docker)を読んでください。

## 統合

解答をテストするためにテストランナーを実行するときは、次のようなDockerコマンドを実行します：

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-test-runner" \
        "${exercise_slug}" "/solution" "/output"
```

Dockerイメージには3つの引数を渡していることがわかります。

1. 演習のスラッグ
2. 解答のディレクトリのパス
3. 出力ディレクトリのパス

## 規約

すべてのテストランナーは、実装で次の規約に従っています。

- `Dockerfile`はリポジトリのルートディレクトリにあります。
- 作業ディレクトリは`/opt/test-runner`にします。
- エントリーポイントは`/opt/test-runner/bin/run.sh`です。
- `/opt/test-runner/bin/run.sh`スクリプトは3つの引数を受け取ります。
  1. 演習のスラッグ
  2. 解答のディレクトリのパス
  3. 出力ディレクトリのパス

詳しくは[インターフェース](/docs/building/tooling/test-runners/interface)を参照してください。

```exercism/note
新しいテストランナーのリポジトリは、デフォルトでこの規約に従います。
```
