# はじめに

Javaプログラミング言語では、エラーやその他の例外的な出来事を扱うために_例外_を使います。

## 例外とは

例外とは、プログラムの実行中に起こり、命令の通常の流れを妨げる出来事のことです。
Javaでは例外は明示的に発生させます。例外を発生させることを_例外をスローする_といいます。
例外を処理することを_例外をキャッチする_といいます。

Javaでは、すべての例外は`Exception`クラスのサブクラスで、`Exception`クラス自体は`Throwable`のサブクラスです。

Javaは例外を2つの種類に分けています：

1. チェック例外
2. 非チェック例外

### チェック例外

_チェック例外_とは、アプリケーションが事前に予期して復帰できるようにすべき例外的な状況です。
チェック例外の例としては`FileNotFoundException`があり、存在しないファイルをメソッドが読み込もうとしたときに発生します。

この種類の例外はコンパイル時にチェックされます。チェック例外をスローするメソッドは、そのことをメソッドシグネチャに明記する必要があり、チェック例外をスローする可能性のあるメソッドを呼び出すコードは、それを処理しなければコンパイルできません。

チェック例外はすべて、`RuntimeException`を継承していない`Exception`のサブクラスです。

### 非チェック例外

_非チェック例外_とは、通常、アプリケーションが予期することも復帰することもできない例外的な状況です。
非チェック例外の例としては`NullPointerException`があり、null以外の値を期待しているメソッドが`null`を受け取ったときに発生します。

この種類の例外はコンパイル時にチェックされません。非チェック例外をスローするメソッドは、そのことをメソッドシグネチャに明記する必要がなく、非チェック例外をスローする可能性のあるメソッドを呼び出すコードも、それを処理する必要はありません。

非チェック例外はすべて`RuntimeException`を継承しており、`RuntimeException`自体は`Exception`を拡張したものです。

## 例外をスローする

Javaのメソッドは、`throw`文を使って例外をスローできます。

### チェック例外をスローする

メソッドからチェック例外をスローするときは、次の例のように、`throws`キーワードを使ってそのことをメソッドシグネチャに明記する必要があります。
これにより、呼び出す側のコードは、例外がスローされる可能性をあらかじめ考慮して、それに応じて処理することが求められます。

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### 非チェック例外をスローする

メソッドから非チェック例外をスローするときは、そのことをメソッドシグネチャに明記する必要はありません。ただし、明記することは可能です。

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## 例外を処理する

Javaで例外を処理するには、`try`、`catch`、`finally`のキーワードを使います。

- 例外をスローする可能性のあるコードの文は、`try`ブロックで囲みます。
- `try`ブロックの後には、`try`ブロックでスローされた例外をキャッチする1つ以上の`catch`ブロックが続きます。
- `catch`ブロックの後には、必要に応じて`finally`ブロックを置くことができます。`finally`ブロックは、例外がスローされたかどうかに関係なく、`try`ブロックの後に必ず実行されます。

次の例は、これらのキーワードがどのように働くかを示しています：

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

この例で、例外がスローされなかった場合は、次のように出力されます：

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

ただし、`bankAccount.withdraw(amount)`の文が`InsufficientBalanceException`をスローした場合は、次のように出力されます：

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

あるいは、`bankAccount.withdraw(amount)`によって非チェック例外がスローされた場合は、次のように出力されます：

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## エラー

Javaには、_エラー_と呼ばれる別のカテゴリーもあります。これは、アプリケーションの外部にある深刻な問題です。
エラーの例としては`OutOfMemoryError`があり、システムで利用できる以上のメモリを使おうとしたときに発生します。

非チェック例外と同様、エラーもコンパイル時にチェックされません。
違いは、エラーがシステムレベルの問題を表しており、通常はアプリケーションではなくJava仮想マシンや環境によってスローされる点です。
アプリケーションは通常、エラーをキャッチしたり処理したりしようとすべきではありません。

Javaのすべてのエラーは`Error`クラスを継承しています。
