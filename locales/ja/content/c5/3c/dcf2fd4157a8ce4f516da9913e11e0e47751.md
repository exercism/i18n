# Null許容性について

理想的な世界なら、すべてがきちんと定義され、具体的な値があって隙間もない、と信じていられるはずです。

しかし、現実の経験はそうはいきません。そのため、多くのプログラミング言語には、値が存在しないことを表す手段があります。nullやNULL、nil、None、nothingなどです。

これは（1965年当時）導入するのは簡単でしたが、すぐに後悔を生むことになりました。
考案者は後に、これを["Billion Dollar Mistake"][web-mistake]と呼んでいます。

ここ数十年の間に、言語の設計者たちは、nullを使えるようにしつつ（ほとんどは）安全にするための、さまざまな方法を模索してきました。

Kotlinにはいくつかの[一般的な原則][ref-null-safety]があり、それらは[Javaとは大きく異なります][ref-java2kotlin]。
_この違いのため、KotlinにはJavaとの相互運用に対処するための特別な機能がありますが、詳細はこの概念の範囲を超えます。_

- Kotlinには特別な`null`値があります。
- すべての型は_既定で_非nullです（つまり`null`にはできません）。
- すべての型は_null許容_にできますが、そのためには明示的に指定する必要があります。
- 例外で失敗する可能性のある関数には、null許容の戻り値を持つ版が用意されていることがよくあります。
- nullかどうかを調べて対応する作業をできるだけ簡単にするために、特別で簡潔な構文が用意されています。

## null許容の変数を作る

型は、`?`を後ろに付けることで[null許容][ref-nullable-type]にできます（例：`String`の代わりに`String?`）。

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## 便利な演算子と関数

### [安全呼び出し演算子][ref-safe-call]`?.`

非nullの`String`では、`.length`プロパティを取得できます。

null許容の`String?`で同じ構文を使うとエラーになりますが、`?.length`を使えば`null`の可能性に対応できます。
戻り値の型は`Int?`です。

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

上の最後の行で見たように、`?.`は非nullの型でも機能します。

### [エルビス演算子][ref-elvis]`?:`

安全呼び出し演算子の考え方を広げたのが[エルビス演算子][wiki-elvis]で、`null`の代わりに使う既定の値を指定できます。

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### [非nullアサーション演算子][ref-not-null]`!!`

この演算子を使うと、プログラマーが確信しているときに、null許容の型を強制的に非nullとして扱えます。
ときに、慎重すぎるコンパイラーより、プログラムの論理をよく理解していることもあるのではないでしょうか？

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

あとは自分の責任です。もし`b`がまだ`null`なら、`NullPointerException`が発生します。

### [let関数][ref-let]`?.let`

null許容の項目をコードのブロックに渡す場合、`if (item != null) { do something }`のように個別にnullチェックをすることもできます。

`item?.let { do something }`を使うほうが、より簡潔で慣用的です。
`do something`は、`item`がnullでないときにだけ実行されます。

### `somethingOrNone()`型の関数

関数の中には、たとえば文字列や配列で無効なインデックスを指定したときに失敗するものがあります。

例外をスローする代わりに、その関数の[`...OrNull`版][ref-elem-at-or-null]を使えば、（この場合は）`Int?`の戻り値を得られます。

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
