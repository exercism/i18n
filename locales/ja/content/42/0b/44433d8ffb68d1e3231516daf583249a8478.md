# 概要

リテラルとは、コードに直接書く固定値のことです。
実行時に計算する必要はありません。
さまざまな種類のデータを効率よく表すために、いろいろな形があります。
もっともよく使われるのは数値のリテラルですが、日付・時刻・文字列型のためのリテラル演算子もあります。
ユーザー定義のリテラル演算子をどう使うかは、後の概念で紹介します。

## 数値リテラル

数値リテラルには、10進数、8進数、16進数、2進数の表現があります。
これらの基本は、[数値の概念][numbers-concept]ですでに扱いました。

`23`、`0x50f7ba11`、`0xba5eba11`のような表現は、コンパイラーにはどれも`int`として解釈されます。
一般的な`int`型は符号付きで、（[コンパイラーとシステムによりますが][in-depth-integers]）範囲は多くの場合`-2'147'483'648`から`2'147'483'647`です。
ほとんどの場合これで十分なので、具体的な型を気にする必要はありません。

用途によっては、より広い範囲や、プログラムのごく小さなメモリ使用量が求められます。
型を明示するには、数値リテラルで特定の整数型を直接指定します。

負の数が必要ないけれど範囲を広げたいときは、`u`または`U`の接尾辞を付けて_符号なし_整数にします。
さらに広い範囲には、`L`、あるいは`LL`を`long`型や`long long`型に使えます。

~~~~exercism/caution
小文字の`l`を使うことも認められていますが、数値の`1`と見間違えやすいため、おすすめしません。
~~~~

```cpp
auto net_worth_christian_grey{2'500'000'000U}; // out of range for 32-bit integers
auto net_worth_carlisle_cullen{46'000'000'000LL}; // int and uint are not enough
```

浮動小数点数は、コンパイル時にたいてい`double`になります。
これはよい既定の動作で、より狭い`float`型を使う場面は、上の符号なしの例よりも少ないです。

```cpp
auto light_year_in_m{9.46073e+15f}; // well in the range of float
auto earth_to_edge_comoving_distance_in_nm{4.32355e+32}; // needs double type for magnitude
auto eulers_number{2.718281828459045}; // needs double type for precision
```

## 文字リテラルと文字列リテラル

これまでの概念でも、`'}'`や`'@'`のような、シングルクォートで囲んだ文字リテラルを使ってきました。

C++の`char`は、最初の128個の[ASCII文字コード][ascii-code]までしか扱えません。
複数のASCII文字や、`‰`のような拡張ASCII文字、あるいは`麗`や`ẞ`のようなUnicode文字を使うには、別の型が必要です。
前の概念では、文字列リテラルを_ダブルクォート_で導入しました：`"一体どういう意味ですか。C++です"`。
この日本語のフレーズの実際の型は`const char (&)[46]`で、Cスタイルの文字列です。

文字列リテラルは、既定では有効になっていません。
_string_リテラルの`""s`や_string-view_リテラルの`""sv`を使うには、関連する名前空間を指定して、使うことを明示する必要があります。

```cpp
#include <string>
#include <string_view>

using namespace std::literals;

auto green_light{"무궁화 꽃 이 피었 습니다"};
// green_light type is const char (&)[36]
auto umbrella{"달고나"s};
// umbrella type is std::basic_string<char>, the same as std::string
auto il_nam{"보는 것이 하는 것보다 더 재미있을 수가 없지"sv};
// il_nam type is std::basic_string_view<char>
```

_string_view_は、const文字列への参照と考えることができます。
