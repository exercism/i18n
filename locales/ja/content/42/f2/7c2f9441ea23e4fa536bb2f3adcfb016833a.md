# はじめに

## レコード

[レコード][records]は、関連する情報をラベル付きでまとめたデータ構造です。
JavaScriptやJavaのオブジェクト、CやRustの構造体に似ていますが、いくつか重要な違いがあります。

### レコードの作成

レコードは波括弧（`{}`）で[作成し][create]、要素はカンマで区切ります。

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

レコードの型も似た構文で定義しますが、等号`=`の代わりにコロン`:`を使います。

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

この型定義を毎回繰り返すのは面倒なので、定義を共有するために[型エイリアス][record-types]を使うのが一般的な書き方です。

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

型エイリアスは、そのレコードのコンストラクター関数も自動的に用意してくれます。
Elmの関数は小文字で始めなければならないので、これはときに意外に思えますが、型コンストラクターはその例外の1つです。

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

### レコードのフィールドへのアクセス

レコードのインスタンスが持つフィールドの値に[アクセスする][access]には、`firefly.creator`のようなドット記法を使うのが基本です。
Elmコンパイラーは、`.`で始まる特別なアクセサー関数もサポートしています。たとえば`.creator`は、その名前のフィールドを持つどんなレコードにも使えます。
これが、関数は小文字で始めなければならないというルールの2つ目の例外です。
実際のところ、ユーザーが定義する関数は小文字で始めなければなりませんが、いま見た2つの例はプログラマーではなくコンパイラーが生成するものです。

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

レコードは、[レコードのパターンマッチング][pattern-matching]を使って束縛の中で_分解_することもできます。
分解は、該当する名前のフィールドを持つレコードなら何でも機能します。

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

### レコードの更新

Elmのすべての値がそうであるように、レコードは不変です。一度定義したレコードのフィールドの値を後から変えることはできません。
既存のレコードのコピーを作り、1つ以上のフィールドを変更する[特別な構文][update]があります。
この構文では、パイプ記号`|`を使って、元のレコードと変更するフィールドを区別します。たとえば`{ oldRecord | field1 = newValue }`のようになります。

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

### レコードの比較

Elmは[構造的等価性][equality]を採用しているので、同じレコードの2つのインスタンスは、値がまったく同じであれば等しいとみなされます。

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

### 拡張可能レコード

Elmは[構造的型付け][structural-typing]もサポートしています。つまり、xとyというフィールドを持つレコードを要求する関数は、それらのフィールドを持つレコードなら何でも受け付けます。2Dの点、3Dの点、宇宙船などです。
このようなレコード型は、`{ a | x : Float, y : Float }`のように定義にパイプ`|`が含まれ、Elmの用語では「拡張可能レコード」と呼ばれます。
型定義の中のパイプ`|`（拡張可能レコードの定義、`{ a | x : Int }`）と、実際のレコードのインスタンスの中のパイプ`|`（そのレコードの一部のフィールドを更新するという意味）は、まったく違うものなので注意してください。

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
