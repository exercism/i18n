# ヒント

## 全体

- `movapd`と`movaps`は、メモリオペランドがアラインメントされているとわかっている場合にだけ使います。両方のオペランドが`xmm`レジスタであれば、安全に使えます。
- メモリアドレスは整数値として渡されます。最初の6つの整数引数は、それぞれ`rdi`、`rsi`、`rdx`、`rcx`、`r8`、`r9`で関数に渡されます。

## 1. 2つのラインの生産量を合算する

- 32ビット浮動小数点数のパック加算は`addps`です。
- 3つのポインタ引数はすべて16バイトにアラインメントされていることが保証されているので、アラインメント前提の移動命令である`movaps`が適切です。

## 2. スケーリングされた偏差を計算する

- 64ビット浮動小数点数のパック減算は`subpd`です。
- 64ビット浮動小数点数のパック乗算は`mulpd`です。
- `measured`はアラインメントされていますが、`target`はされていないので、それぞれ別の読み込み命令を使う必要があります。

## 3. バッチを較正する

- `reference`と`offset`はどちらもアラインメントされていますが、`raw`はされていないので、それぞれ別の読み込み命令を使う必要があります。
- `reference`と`offset`は、どちらの行にも必要です。
- 2オペランド命令は通常、デスティネーションオペランドを上書きします。
- `raw`の上位2つのfloatをdoubleに変換するには、rawポインタから8バイトオフセットしたメモリオペランドを指定して`cvtps2pd`を使います。
- 変換係数は、2つの64ビット浮動小数点数（どちらも`0.5`）としてメモリに格納します。
- 結果は32バイト（4つの64ビット浮動小数点数）にまたがります。最初の16バイトが`[result]`、次の16バイトが`[result + 16]`です。

## 4. ラインに沿ってスコアを正規化する

- 2オペランド命令は通常、デスティネーションオペランドを上書きします。
- 算術パック命令では、メモリをデスティネーションオペランドにすることはできません。
- `scores`配列（第1引数）の各64ビット浮動小数点数`score`には、`gains`配列（第2引数）に対応する`gain`があります。各`score`は、同じ位置にある`gain`と演算されます。
- 第3引数は、2つのパックされた64ビット浮動小数点数を持つ固定の`scale`です。
- `score`と`gain`の各ペアについて、関数は`score * gain / scale_lane`を計算します。`scale`の最初のレーンは各ペアの最初の要素（偶数位置のレーン）をスケーリングし、2番目のレーンは2番目の要素（奇数位置のレーン）をスケーリングします。
- 正規化されたスコアは、入力の`score`と同じ位置で、`scores`配列にその場で格納されます。
- `scores`と`gains`の要素数は同じで、`n`（第4引数）の値に等しくなります。
- すべての要素のペアを処理するにはループを使い、各繰り返しで16バイト（2要素）ずつ進めます。
