# ヒント

## 全般

SGF言語には、再帰的な定義があります。

```none
GameTree = "(" Sequence { GameTree } ")"
```

つまり、GameTreeとは、`(`で始まり、その後に「Sequence」と呼ばれるテキスト（ゲームノードのリスト）が続き、_その後に**0個以上**の子GameTreeが続き_、`)`で終わるテキストのことです。

SGFのテキストを解析するのに、正規表現を使いたくなるかもしれません。
しかし、ゲームツリーは他のゲームツリーの中にいくらでも深く入れ子にできるため、標準的な正規表現では入れ子の深さを追いかけるだけの力がありません。

この演習を解くには、いくつか方法があります。

### ステートマシン

入力文字列を1文字ずつ走査しながら、現在位置を保持する変数を管理する方法があります。
現在の位置にある文字をもとに、解析中のテキストがどの状態にあるかを追いかけることができます。
「現在の状態」とは、たとえば「プロパティ名を読み取っている」「プロパティ値の中にいる」といったものです。
この方法では、追いかける必要のある値がたくさんあります。

### パーサー

文法がきちんと定義されている言語を解析するには、[PEGベースのパーサー][PEG-parser]がとても良い方法です。
[LPeg][LPeg]はPEGパーサーであり、MoonScriptの必須依存関係の1つなので、すでに利用できます。
パーサーを使えば、テキストがどんな形であるべきかを表すルールを書くことができます。
たとえば「プロパティ名はすべて大文字」「プロパティ値は角括弧で囲む」といったルールです。
あとはパーサーが、入力テキストをルールに照らして照合する面倒な作業を引き受けてくれます。
