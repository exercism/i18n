# テスト

Exercismのプロジェクトディレクトリ内にあるGoの演習は、演習ディレクトリに移動して`go test`を実行すると走らせることができます。

```bash
cd exercism/project/directory/go/leap
go test
```

## データ競合検出器を使ったテスト

`go test`の実行に加えて、一部の演習は[データ競合検出器](https://go.dev/doc/articles/race_detector)のフラグを付けて実行する必要があります。これは、解答がデータ競合のバグを持ち込んでいないかを確認するためのものです。
該当する演習では、データ競合検出器のフラグ`-race`を付けてテストを実行するよう促す案内があります。
データ競合を確認するには、`go test -race`を実行します。
例えば、次のようになります。

```bash
cd exercism/project/directory/go/bank-account
go test -race
```

## ベンチマークの実行

ほとんどの演習にはベンチマークが含まれており、解答に加えた変更がパフォーマンスにどう影響するかを調べるのに使えます。
演習のベンチマークを実行するには、演習ディレクトリの中で`go test -v --bench . --benchmem`というコマンドを使います。

次の出力を見てみましょう。

```text
BenchmarkReverse-16       403594              2537 ns/op             176 B/op         34 allocs/op
```

これは、ベンチマークが正確に計測されるまでに403594回の繰り返しを要したことを意味します。
平均速度は1ループあたり2537 nsでした。
1回の操作あたり34回のメモリ割り当てが行われ、平均で176バイトでした。

## テスト可能な例

[Exampleテスト](https://blog.golang.org/examples)は一部の演習で使われ、通常の演習テストと一緒に実行されます。
これらの例は、演習のAPIを文書化し検証するために使われ、演習で期待されるAPIが何かを判断するのに役立ちます。

## Go fmt

解答を提出する前に、コードに対して[`go fmt`](http://blog.golang.org/go-fmt-your-code)を実行してください。

## ヒントとコツ

### 演習のコードを書く

各演習のREADME.mdには概要が書かれていますが、Goのテストプログラムは非常に具体的です。
テストプログラムを開いてざっと目を通しましょう。カンニングのように思えるかもしれませんが、それでも構わずやってみてください。
役立つコメントやテストデータ、そしてテスト関数の名前を探してみましょう。
何も書く前に`go test`を実行してみて、エラーメッセージからどこから始めればよいかヒントが得られないか見てみましょう。

最初の目標は、テストに失敗してもよいので、とにかくコンパイルが通る状態にすることです。
そのためには、関数を「スタブ」にする必要があります。
つまり、必ず戻さなければならないものを除いて、本体は空のままにします。
コンパイルを通すためだけに、`return 0`や`return ""`など、何でもよいので書きます。
関数のシグネチャを把握するために、テストプログラムに戻ってより詳しく読まなければならないこともあります。
必要な関数シグネチャをすべて把握すると、テストプログラムは0が間違った答えだと文句を言うようになります。
ここから関数の本体を埋めていきましょう。

### 修正する

テストは多くの場合、最初のエラーで止まります。
そのエラーを直し、エラーがなくなるまで繰り返します。
`go test`には便利なオプションがあります。
`go test -v`はより詳細な出力を出します。`go test -run <regexp>`は、名前が`<regexp>`に一致するテストだけを実行します。

パニックは大量の出力を出します。
最初は怖く思えるかもしれませんが、勇気を出しましょう。
パニック出力の一番上にあるパニックメッセージを見てください。
そこにおおよその問題の説明が書かれています。
次に、残りの部分を読み、自分のコードへの最初の言及を探します。
多くの場合、そこが問題箇所を直接示してくれます。

並行プログラムの問題を見つけるには、`go test -race`を試してみましょう。

### コードをきれいにする

もう一度言いましょう、`go fmt`を実行しましょう。
[Golint](https://github.com/golang/lint)は、`go fmt`では見つけられないコードのスタイル上の問題を教えてくれます。
`go vet`も見てみるとよいでしょう。これはコードの潜在的な問題について警告してくれます。
[コードレビューでよくあるコメント](https://code.google.com/p/go-wiki/wiki/CodeReviewComments)を読んで、参考にしましょう。
並行処理を扱う演習では、テストに通っていても`go test -race`を試してみましょう。
ベンチマークのパフォーマンスのために最適化する場合でも、読みやすさを忘れないようにしましょう。
最適化によって、簡潔で読みやすい解答を見つけられることもありますが、パフォーマンスを追い求めるあまり読みやすさを犠牲にしたくなる誘惑もあります。

### ボーナステスト

いくつかの演習には、`go test`だけでは実行されないボーナステストがあります。
通常の演習に加えてボーナス演習を解く場合は、`go test -tags bonus`、またはテストプログラムのドキュメントに記載されている同様のコマンドを入力する必要があります。
