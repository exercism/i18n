# 概要

ユーザー定義の例外とは、コードの中で定義するクラスのうち、`System.Exception`から派生したもののことです。クラスの継承に関するすべてのルールに従いますが、それに加えて、コンパイラーと言語ランタイムはそのようなクラスを特別に扱います。そのおかげで、`exceptions`演習で説明したように、通常の制御フローの外側でもそのインスタンスをスローしたりキャッチしたりできます。ユーザー定義の例外は、ランタイムやMicrosoft Base Class Libraryの例外と同じように、あらゆる場面で使えます。

この特別な扱いは、`Exception`から派生したクラスにだけ当てはまります。ほかの型のインスタンスはスローできません。

ユーザー定義の例外は、メッセージやその他の関連データといった追加情報を運び、例外をキャッチする側で利用できるようにするためによく使われます。こうした情報は、ログに記録したり、ユーザーに伝えたり、再試行の処理に使ったりできます。`System.Exception`には、メッセージと「内部」例外を保持するための便利なデータメンバーと、適切なコンストラクターが用意されています。

慣例として、例外のクラス名は「Exception」で終わります。たとえば`MyTerribleException`です。

ユーザー定義の例外でサードパーティの例外をラップして拡張するのはよく見られるパターンですが、一般的なアドバイスとしては、この用途以外で自分のコードの中で使いすぎないほうがよいとされています。アンチパターンと見なされているからです。ただし、この考え方には異論もあり、その議論の両論はこちらの[Stack Exchangeの投稿][se-exceptions]で確認できます。

こちらの[記事][create-user-defined-exceptions]は、ユーザー定義の例外を学ぶのによい入門記事です。

.NETチームは、[例外の作成とスロー][exceptions-guidance]に関するガイダンスの中で、ユーザー定義の例外にはいくつかの[便利なコンストラクター][convenience-constructors]を用意することを勧めています。ほとんどの用途では、以下に示す組み合わせが適切です。

```csharp
public class IncompleteExerciseException : System.Exception
{
    public IncompleteExerciseException() : base() { }
    public IncompleteExerciseException(string message) : base(message) { }
    public IncompleteExerciseException(string message, System.Exception inner) : base(message, inner) { }
}
```
