# 概要

OSの状態を保持するリソース（ファイルハンドル、ソケット、ロックなど）は、*保証された*後始末が必要です。例外によってスタックが巻き戻されるときも同じです。Factorの[`destructors`][destructors]ボキャブラリはそのための小さなフレームワークを提供しており、ほとんどの組み込みリソース（`<file-reader>`、`<file-writer>`、ソケットなど）はすでにこれに対応しています。

## クラスとジェネリックワード

クラスは`disposable`を継承し、`dispose*`を実装することで仲間に加わります。

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )`はタプルを割り当て、*さらに*現在のデストラクタースコープに登録します。そのため、割り当てから次の安全な地点までの間に例外が起きても、リソースが漏れることはありません。このフレームワークは、`dispose*`が1つのオブジェクトにつき**最大1回**しか実行されないことを保証します。`dispose`を繰り返し呼んでも何も起こりません。

## 利用側は`dispose`を使う

| ワード            | 動作                                          |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )`：解放します。2回呼んでも安全です |
| `with-disposal`   | `( disposable quot -- )`：1つのリソースをスコープで囲みます |
| `with-destructors`| `( quot -- )`：レジストリのスコープを開きます |
| `&dispose`        | `( obj -- obj )`：正常終了*または*失敗終了のときに解放します |
| `|dispose`        | `( obj -- obj )`：スコープが巻き戻されるときだけ解放します |

`with-disposal`はリソースが1つの場合の書き方です。リソースが複数あるときは、`with-destructors`のスコープを開き、取得するリソースをそれぞれ`&dispose`（常に解放したいとき）または`|dispose`（失敗したときだけ解放したいとき）で登録します。`|dispose`では、成功したときはリソースをそのまま保持します。

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup`は基本のプリミティブ

レジストリを使わず、その場かぎりのtry/finallyを行いたいときは、`continuations`にある[`cleanup`][cleanup]がより低レベルのワードです。

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors`のほうが明確に強力です（レジストリは実行時に増やせます）。ただし、取得と解放の組み合わせが固定されていて局所的であれば、`cleanup`のほうが自然な選択です。
