# ヒント

## 全般

- ポインターの構文に注意しましょう。`*`（間接参照演算子）と`->`（ポインターを介したメンバーアクセス）を使います。
- 無効なメモリにアクセスしないよう、必要な箇所ではヌルポインター（`nullptr`）を確認しましょう。
- コードが未完成でもテストは実行できます。大まかな構造があれば、テスト結果を確認できます。
- テストで使われるすべての関数は、ヘッダーファイルで宣言する必要があります。
- プログラムがクラッシュしたり、予期しない動作をしたりするときは、ヌルポインターの間接参照が原因であることがよくあります。`nullptr`を正しく扱えているか、もう一度確認しましょう。
- ポインター演算を使うときは、センサー配列の範囲内に収まるようにしましょう。配列の容量を超えると、メモリの問題につながることがあります。

## 1. センサーの接続を確認する（`connection_check`）

- このタスクは主に、ポインターがヌルかどうかを確認することです。
- ポインターが有効かどうかを確認するには、比較演算子`!=`を使います。
- ポインターを正しく確認できているかわからないときは、`nullptr`が何を表すか（有効なメモリアドレスが存在しないこと）を考えてみましょう。

## 2. センサーの活動を数える（`activity_counter`）

- センサーの配列を繰り返し処理する必要があります。C++では、配列はその先頭要素へのポインターとして扱うことができます。
- インデックス`i`のセンサーにアクセスするには、ポインター演算（`sensor_array + i`）を使います。
- `->`演算子は、ポインターを介して構造体のメンバーにアクセスするために使います。

### 例

```cpp
int sum = (sensor_array + i)->activity; // Access activity using pointer arithmetic
```

## 3. アラームの制御（`alarm_control`）

- まず、センサーにアクセスする前に、ポインターがヌルかどうかを確認します。
- `pillar_men_sensor`構造体の`activity`メンバーにアクセスするには、`->`演算子を使います。
- センサーの活動レベルが`0`のときにどうなるべきかをよく考えましょう。アラームを作動させるべきでしょうか？

## 4. `uv_alarm`関数でデータの異常を確認する

- `uv_light_heuristic`関数に、センサーのデータ配列へのポインターを渡すには、`&`演算子を使います。
- センサーのデータにアクセスする前に、ヌルポインターを正しく確認しましょう。
- アラームを作動させるべきか判断するには、`uv_light_heuristic`の結果とセンサーの`activity`の値を比較します。
