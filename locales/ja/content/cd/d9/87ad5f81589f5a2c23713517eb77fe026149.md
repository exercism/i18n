# イテレーターの組み合わせ

複数のイテレーターで、1つのループを共有することができます。それぞれは1周につき1度だけ進みます。

```sather
   loop
      a ::= xs.elt!;
      b ::= ys.elt!;
      ...
   end;
```

## 終了

イテレーターの**どれか1つ**が値を返せなくなった瞬間に、ループは終わります。残りのイテレーターは進められず、ループ本体の残りの部分も実行されません。

つまり、2つの配列を同時に走査すると、たどれるのは`min(xs.size, ys.size)`周分だけです。長いほうを最後までたどるには、代わりに位置を走査してインデックスで参照し、短いほうの配列は自分で範囲を超えないよう見張ります。

## 呼び出し箇所ごとに別々の走査

イテレーターの位置は、オブジェクトではなく、それが書かれている*プログラム上の場所*に属します。つまり、次のようになります。

```sather
   loop
      #OUT + xs.elt! + xs.elt!;      -- two walks, each advancing separately
   end;
```

これは2つの独立した走査から、1周につき2つの異なる要素を取り出します。値を取り出すのは1度だけにして、その値を取っておきましょう。

## 終わりのないイテレーター

| イテレーター | 取り出せる値 |
| --- | --- |
| `n.up!` | `n`、`n+1`、`n+2`、…と永遠に続く |
| `n.upto!(m)` | `n` … `m`を取り出して、そこで終わる |

終わりのないイテレーターは、どこかで終わるもの、あるいは`break!`や`until!`と組み合わせる必要があります。単独では永遠に繰り返します。

`1.up!`をコレクションの走査と組み合わせるのは、要素に番号を振る定番の書き方です。見た瞬間にそれとわかるようになっておきましょう。

## これが独立した概念で、ほかの概念の一部ではない理由

*最初の*イテレーターが尽きた時点で終わるループは、プログラムを明らかに壊すのではなく、気づきにくい形で間違ったものにしてしまう可能性が最も高い、ただ1つのルールです。クラッシュはせず、ただ早く止まってしまうからです。これを、イテレーターを紹介する演習や、イテレーターを書く演習に折り込んでしまうと、ほかにも新しいことがある状態でこのルールに出会うことになります。
