# はじめに

Elixirでは、すべてのコードはプロセスの中で実行されます。

デフォルトでは、関数は呼び出し元と同じプロセスで実行されます。特定の関数を新しいプロセスで明示的に実行したいときは、`spawn/1`を使います。

```elixir
spawn(fn -> 2 + 2 end)
# => #PID<0.125.0>
```

`spawn/1`は、与えられた引数を取らない関数を実行する新しいプロセスを作成し、_プロセス識別子_（PID）を返します。新しいプロセスは、その関数が実行されている間は生き続け、その後は静かに終了します。

Elixirのプロセスを、オペレーティングシステムのプロセスと混同しないでください。Elixirのプロセスは、メモリとCPUの使用量がはるかに少なくなっています。何百ものElixirプロセスを動かすアプリケーションがあっても、まったく問題ありません。

## メッセージ

プロセス同士は、直接情報を共有しません。データを共有するために、プロセスは_メッセージを送受信_します。

`send/2`を使うと、任意のプロセスにメッセージを送ることができます。`send/2`の第1引数は宛先のPIDで、第2引数はメッセージです。

メッセージはどんな型でもかまいません。多くの場合、アトムとタプルで構成されます。応答を受け取りたい場合は、メッセージのどこかに送信者のPIDを含めておきましょう。現在のプロセスのPIDは、`self()`で取得できます。

`send/2`は、メッセージが宛先に届いたかどうかや、宛先のプロセスがまだ生きているかどうかを確認しません。メッセージは宛先の_メールボックス_に入り、宛先が明示的に_メッセージを受信_しようとしたときにだけ読み出されます。

`receive/1`マクロを使うと、メールボックスからメッセージを読み出せます。`receive/1`は、メッセージを[パターンマッチ][exercism-pattern-matching]できる`do`ブロックを受け取ります。

```elixir
receive do
  {:ping, sender_pid} -> send(sender_pid, :pong)
  :do_nothing -> nil
end
```

`receive/1`は、指定されたパターンのいずれかに一致するメッセージをメールボックスから_1つ_取り出し、そのパターンに対応する式を実行します。メールボックスにメッセージがない場合、またはどのメッセージもどのパターンにも一致しない場合、`receive/1`はメッセージを1つ待ちます。

## 受信ループ

複数のメッセージを受信したい場合は、`receive/1`を再帰的に呼び出す必要があります。たとえば`loop`という名前の再帰関数を実装するのはよくあるパターンです。この関数は`receive/1`を呼び出し、メッセージに対して何か処理を行ってから、さらにメッセージを待つために自分自身を呼び出します。ある`receive/1`の呼び出しから次の呼び出しへ状態を引き継ぐ必要がある場合は、その`loop`関数に引数を渡すことで実現できます。

[exercism-pattern-matching]: https://exercism.org/tracks/elixir/concepts/pattern-matching
