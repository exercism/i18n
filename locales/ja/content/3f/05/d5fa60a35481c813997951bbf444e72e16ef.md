# はじめに

Goには、他の多くのプログラミング言語と同じように、ポインタがあります。
ポインタが初めてだと、少し不思議に感じるかもしれませんが、慣れてしまえばとても分かりやすいものです。
ポインタはGoのとても重要な要素なので、じっくり時間をかけて理解しましょう。

詳しい話に入る前に、ポインタが何のためにあるのかを理解しておく価値があります。
ポインタは、プログラムの別の部分とメモリを共有するための仕組みで、次の2つの大きな理由から役に立ちます。

1. 大量のデータを扱うとき、関数の間で受け渡すためにコピーを作るのはとても非効率です。
   代わりに、データが保存されているメモリ上の位置を渡せば、プログラムが使うリソースを劇的に減らせます。
2. 関数の間でポインタを渡せば、1つだけあるデータに直接アクセスして書き換えられます。つまり、ある関数でした変更は、その関数が終わった時点でプログラムの他の部分からすぐに見えるようになります。

## 変数とメモリ

普通の整数の変数`a`があるとしましょう。

```go
var a int
```

変数を宣言すると、Goはその値を保存するための場所をメモリの中に見つける必要があります。
この部分はほとんど意識しなくて済みます。そのメモリに保存された値を取り出したいときは、変数名を書くだけで参照できます。

たとえば`a + 2`と書くと、変数`a`に対応するメモリに保存された値を取り出し、それに2を足していることになります。

同じように、`a`のメモリに入っている値を変えたいときは、変数名を使って代入できます。

```go
a = 3
```

これで、`a`に対応するメモリには値`3`が保存されます。

## ポインタ

変数を使えばメモリ上の値を参照できますが、その変数が指している**メモリアドレス**を知りたいときもあります。
**ポインタ**は、そうした値のメモリアドレスを保持します。
ポインタ型の変数を宣言するには、元になる型の前にアスタリスクを付けます。

```go
var p *int // 'p' contains the memory address of an integer
```

ここでは「intへのポインタ」型（`*int`）の変数`p`を宣言しています。
つまり`p`は、ある整数のメモリアドレスを保持します。
ポインタのゼロ値は`nil`です。`nil`ポインタはどのメモリアドレスも保持していないからです。

### 変数へのポインタを取得する

変数の値のメモリアドレスを調べるには、`&`演算子を使います。
たとえば、変数`a`のメモリアドレスを調べてポインタ`p`に保存したいときは、次のように書きます。

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### ポインタ経由で値にアクセスする（逆参照）

ポインタがあるとき、そのポインタが表すメモリアドレスに保存されている値を知りたいことがあります。
それは`*`演算子でできます。

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p`という操作は、`p`に保存されているメモリアドレスにある値を取り出します。
この操作はよく「逆参照」と呼ばれます。

逆参照演算子を使って、ポインタが参照するメモリアドレスに新しい値を代入することもできます。

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa`に代入すると、`pa`が保持しているメモリアドレスに保存されている値が変わります。
`pa`は`a`のメモリアドレスを保持しているので、`*pa`に代入することは、つまり`a`の値を変えていることになります！

ただし注意が必要です。逆参照する前に、必ずポインタが`nil`でないかを確認してください。
`nil`ポインタを逆参照すると、実行時にプログラムがクラッシュします！

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### 構造体へのポインタ

ここまでは、基本的な値へのポインタだけを見てきました。
構造体へのポインタも作れます。

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

新しい`Person`を作ると同時に、それへのポインタを保存することもできます。

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

構造体へのポインタがあるとき、フィールドにアクセスする前にポインタを逆参照する必要はありません。

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## スライスとマップはすでにポインタ

スライスとマップは、その実装にすでにポインタが含まれている特別な型です。
つまり、たいていの場合、これらの型の値のメモリアドレスを共有するためにポインタを作る必要はありません。
マップのあるキーの値を増やす関数を考えてみましょう。

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

マップを作ってこの関数を呼び出すと、関数がマップに加えた変更は、関数が終わったあとも残ります。
これはポインタを使ったときと似た動作ですが、この例では参照や逆参照といったポインタの構文をまったく使っていないことに注目してください。

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

スライスの既存の要素を変えるときも同じです。

ただし、`append`のように新しいスライスを返す操作は特別で、関数の外にあるスライスを**変更しないことがあります**。
これはスライスの内部の仕組みによるものですが、より発展的な話題なのでここでは詳しく扱いません。
もっと詳しく知りたい場合は、[Go Blog: Mechanics of 'append'][mechanics-of-append]で読むことができます。

[mechanics-of-append]: https://go.dev/blog/slices
