# リンティング

[configlet](/docs/building/configlet)の主な用途はリンティングです。トラックの設定ファイルが、構文的にも意味的にも正しく構成されているかを確認します。設定が間違っているトラックは、正しく同期されなかったり、ウェブサイトでの表示がおかしくなったり、ユーザー体験が最適でなくなったりする可能性があります。そのため、configletのチェック機能は、Exercismの整合性を保つうえで重要な役割を果たします。

## 使い方

`lint`コマンドを使うと、トラックをリントできます。

```
configlet [global-options] lint [command-options]

Global options:
  -h, --help                   Show this help message and exit
      --version                Show this tool's version information and exit
  -t, --track-dir <dir>        Specify a track directory to use instead of the current directory
  -v, --verbosity <verbosity>  The verbosity of output. Allowed values: q[uiet], n[ormal], d[etailed]
```

## ルール

以下は、チェックされるリンティングルールです。

### ルール: 必須ファイルが存在する

リンターは、必須ファイルがすべて存在するかどうかをチェックする必要があります。演習に固有でない、存在しなければならないファイルは次のとおりです。

- `config.json`
- `docs/ABOUT.md`
- `docs/INSTALLATION.md`
- `docs/LEARNING.md`
- `docs/RESOURCES.md`
- `docs/SNIPPET.txt`
- `docs/TESTS.md`
- `exercises/shared/.docs/help.md`
- `exercises/shared/.docs/tests.md`

コンセプト演習に固有で、存在しなければならないファイルは次のとおりです。

- `exercises/concept/<slug>/.docs/hints.md`
- `exercises/concept/<slug>/.docs/instructions.md`
- `exercises/concept/<slug>/.docs/introduction.md`
- `exercises/concept/<slug>/.meta/config.json`

プラクティス演習についても同様のリストがありますが、その仕様はまだ定義されていません。

`config.json`にリストされている各コンセプトには、次のファイルが必要です。

- `concepts/<slug>/about.md`
- `concepts/<slug>/introduction.md`
- `concepts/<slug>/links.json`

## 用語集

1. **空でない文字列**: 少なくとも1つの空白以外の文字を含む文字列。
2. **kebab-case文字列**: `[a-z0-9]`の範囲の文字のみを含み、任意でダッシュで区切られる文字列（例: "two-fer"）。次の正規表現に一致しなければなりません: `^[a-z0-9]+(-[a-z0-9]+)*$`
3. **Title Case文字列**: 以下の[Chicago Manual of Styleのガイドライン](https://en.wikipedia.org/wiki/Title_case#Chicago_Manual_of_Style)に従う空でない文字列:
   - タイトルとサブタイトルの最初と最後の単語を大文字で始めます。
   - 「主要な」単語（名詞、代名詞、動詞、形容詞、副詞、および一部の接続詞）を大文字で始めます。
   - 接続詞 _and_、_but_、_for_、_or_、_nor_ は小文字にします。
   - 冠詞 _the_、_a_、_an_ は小文字にします。
   - 前置詞は、長さにかかわらず小文字にします。ただし、強調されている場合、副詞的または形容詞的に使われている場合、あるいは接続詞として使われている場合を除きます。
   - 単語 _to_ と _as_ は小文字にします。
   - ラテン語の種名の2番目の部分は小文字にします。
4. **Sentence Case文字列**: 以下の[ガイドライン](https://en.wikipedia.org/wiki/Letter_case#Sentence_case)に従う空でない文字列:
   - 文の最初の単語、および固有名詞や、より具体的なルールで求められるその他の単語を大文字で始めます。
5. **有効な`files`パターン**: 演習で使用されるファイルの位置を、その演習のディレクトリからの相対パスで指定する、空でない文字列¹。パターンでは、次のプレースホルダーのいずれかを使用できます:

   - `%{kebab_slug}`: `kebab-case`の演習slug（例: `bit-manipulation`）
   - `%{snake_slug}`: `snake_case`の演習slug（例: `bit_manipulation`）
   - `%{camel_slug}`: `camelCase`の演習slug（例: `bitManipulation`）
   - `%{pascal_slug}`: `PascalCase`の演習slug（例: `BitManipulation`）

6. **一意なバージョン4のUUID文字列**: 次の条件をすべて満たす文字列:

   - 特定のExercismトラックのトラックレベルの`config.json`ファイルに1回だけ存在します
   - 他のどのExercismトラックのトラックレベルの`config.json`ファイルにも存在しません
   - https://github.com/exercism/problem-specifications のどの`canonical-data.json`ファイルにも存在しません
   - Exercismの他のどこにも存在しません
   - 次の正規表現に一致します:

   ```
   ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
   ```

   たとえば、以下のUUIDは正しい形式です:

   ```
   d334ffe3-657e-4725-a950-290b284b6d9f
   ```

   適切なUUIDを生成するには、`configlet uuid`を実行します。

7. **有効なアナライザーの`tag`**: `<category>:<thing>`という形式の空でない文字列¹。
   `<category>`の値は、次のいずれかでなければなりません:

- `paradigm`（例: `paradigm:functional`）
- `technique`（例: `technique:recursion`）
- `construct`（例: `construct:bitwise-and`）
- `uses`（例: `uses:DateTime.add_seconds`）

`<thing>`の値は、空でない文字列¹でなければなりません。
