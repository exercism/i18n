# 手順

この演習の舞台はバレンタインデーです。パートナーと一緒に何か楽しいことをしようと計画しています。パートナーはたくさんのアイデアを持っていて、どれに取り組むかを決めるために、それぞれのアイデアを評価してほしいと頼んできました。

パートナーが提案したアイデアは次のとおりです。

- ボードゲームで遊ぶ
- のんびり過ごす
- 映画を見る
- レストランに行く
- 散歩する

バレンタインデーのアクティビティを選ぶための6つのタスクがあります。

## 1. 承認を定義する

パートナーが提案する各アイデアに対して、yes、no、maybeの3つのうちのどれかで答えます。

これらの選択肢を表すカスタム型`Approval`を、次の3つのケースで定義します。`Yes`、`No`、`Maybe`です。

## 2. 料理を定義する

パートナーはレストランの候補を2つ選びました。1つは韓国料理、もう1つはトルコ料理です。

これらの料理を表すカスタム型`Cuisine`を、次の2つのケースで定義します。`Korean`と`Turkish`です。

## 3. 映画のジャンルを定義する

選べる映画は膨大にあるので、絞り込むために、パートナーはジャンルも挙げています。

次のジャンルをケースとして表すカスタム型`Genre`を定義します。`Crime`、`Horror`、`Romance`、`Thriller`です。

## 4. アクティビティを定義する

先ほども触れましたが、パートナーは5つの異なるアクティビティを考えました。ボードゲームで遊ぶ、のんびり過ごす、映画を見る、レストランに行く、散歩するの5つです。

これらのアクティビティを表すカスタム型`Activity`を定義します。

- `BoardGame`：関連するデータはありません。
- `Chill`：関連するデータはありません。
- `Movie`：関連データとして`Genre`を持ちます。
- `Restaurant`：関連データとして`Cuisine`を持ちます。
- `Walk`：歩く距離をキロメートルで表す`Int`を関連データとして持ちます。

## 5. アクティビティを評価する

最後に、パートナーのアイデアを評価する準備ができました。それぞれのアイデアに対して、次のように感じています。

- ボードゲームで遊ぶ：no。
- のんびり過ごす：no。
- 映画を見る：ロマンス映画ならyes、それ以外はno。
- レストランに行く：韓国料理ならyes、トルコ料理ならmaybe。
- 散歩する：歩く距離が11キロメートルより長ければyes、6キロメートルより長ければmaybe、それ以外はno。

`Activity`の値を受け取り、上記の気持ちに基づいて`Approval`を返す`rate_activity`という関数を実装します。

```gleam
rate_activity(Restaurant(Turkish))
// -> Maybe
```
