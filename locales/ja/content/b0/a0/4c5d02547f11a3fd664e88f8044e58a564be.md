# 概要

## JSON

[JSON][json]（JavaScript Object Notation）は、人間が読めるデータ形式でありファイル形式で、データの交換、とりわけウェブアプリケーションでよく使われます。そのため、Elm言語において特別な位置を占めているのも不思議ではありません。

Elmは、JSONデータをパースして書き出すためのコアモジュール[`Json.Decode`][decode]と[`Json.Encode`][encode]を提供しています。JSONデコーダーは、どんな型のデータが期待されているか、そのデータをどのデータ構造に対応付けるべきかを_宣言_する方法です。

動的型付け言語から来た人にとって、デコーダーは面倒に感じられたり、一見すると堅苦しく見えたりすることがよくあります。確かに冗長ではありますが、少なくともElmにおいては、プログラムが受け取るデータに何を期待しているかを明示的に記述するための貴重な道具であり、[動的型よりも表現力が劣るわけではありません][dynamic-types-not-more-open]。

モジュールからいくつかのエイリアスと型をインポートしましょう。

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

`Decode.decodeString : Decoder a -> String -> Result Error a`をデコーダーとJSON文字列に使うと、文字列がデコーダーの仕様に適合していれば成功し、そうでなければ失敗します。デコーダーを定義するときに生のJSONデータを覗く方法はなく、これは命令型言語から来た人には珍しく感じられるかもしれません。

## 基本的なデータ型のデコーダー

JSONには、少数のコアなデータ型があります。

- 文字列: `"hello world"`のように、二重引用符で囲んで表します
- 真偽値: `true`か`false`のいずれかです
- 数値: `34`や`0.12`などです
- Null: データが存在しないこと、つまり`null`です

これらのそれぞれに、対応する`Decode`関数があります。

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

`Decode.null`は、引数として任意の値を要求することで、プログラム内で`null`をどうモデル化するかを自分で決められるようにしている点に注目してください（`()`、`Nothing`、あるいはプログラムに合った何かでも構いません）。

## デコーダーを組み合わせる

JSONは、コアなデータ型をまとめるための2つのデータ構造も定義しています。

- 配列: 他のデータ型をまとめたもの`[0, null, "none", []]`
- オブジェクト: キーと値のペアをまとめたもの`{"id": 1, "is_admin": false, "more_info": {}}`

`Decode`にも、これらをデコードするための関数が用意されています。

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

これらの関数`Decode.list : Decoder a -> Decoder (List a)`と`Decode.dict : Decoder a -> Decoder (Dict String a)`は、それぞれ引数としてデコーダーを取り、そのデコーダーがデータ構造の要素ひとつひとつをデコードすることが期待されています。引数のデコーダーが配列やオブジェクトの値の要素をひとつでもデコードできなければ、デコーダー全体が失敗します。これはよくあるパターンです。

単純なデコーダーを組み合わせて、より複雑なものにするのが、この手法の核心です。ここからは例を通して、現実世界のどんなに複雑なデータでもデコードできるデコーダーを組み立てるために使える、さらにいくつかの関数を紹介します。

## GeoJSON

基本的なデコーダーを組み合わせて複雑なJSONデータをパースする練習として、GeoJSONデータ（の一部）をパースするデコーダーを作ってみましょう。[GeoJSON][geojson]は、場所・経路・地域といった地理的な特徴を表すために使われる、JSONを基にした専用のデータ形式です。2次元または3次元の地理座標と、その他のプロパティで指定します。

### ジオメトリオブジェクト

GeoJSONのジオメトリオブジェクトは、文字列値を持つ`type`フィールド（取りうる値は7種類あります）と、地理座標を持つ`coordinates`フィールド（その構造は`type`によって変わります）を含むオブジェクトです。たとえば、次のようになります。

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

あるいは

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

ジオメトリオブジェクトは、Elmでは次のような型で表せます。

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

あるフィールドの値を調べるには、`Decode.field : String -> Decoder a -> Decoder a`を使います。これはオブジェクトの特定のキーの値をデコードします。

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

デコーダーが正常にパースした値を変換するには、`Decode.map : (a -> value) -> Decoder a -> Decoder value`や、その仲間たち（`Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value`から`Decode.map8`まで）を使えます。

ここでは、`type`フィールドの値に応じてどの座標デコーダーを使うかを決めたいわけですが、これは`Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b`と、その仲間である`Decode.succeed : a -> Decoder a`、`Decode.fail : String -> Decoder a`の出番です。

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

ここで、`Decode.andThen`を使って座標を検証できることにも触れておきます（座標が2つ組や3つ組になっているか、座標の値が地理的に妥当かを確認できます）。

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### フィーチャーオブジェクト

GeoJSONのフィーチャーオブジェクトは、空間的に区切られた何かを表します。`"Feature"`という値を持つ`type`フィールド、ジオメトリオブジェクトまたは`null`を持つ`geometry`フィールド、任意のJSONオブジェクトまたは`null`を持つ`properties`フィールド、そして省略可能な`id`フィールド（JSONの文字列または数値）を持ちます。

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

あるいは

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

まずは`id`フィールドから見ていきましょう。これが存在する場合、文字列か数値のどちらかを受け入れる必要があるので、値用のカスタム型を導入するか、常に文字列として保存するかのどちらかになります。

2つの候補となるデコーダーのどちらを使うか選ぶには、`Decode.oneOf : List (Decoder a) -> Decoder a`を使えます。

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

フィールドが省略可能であることを表すには、同じ手法を使えます。

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

しかし、代わりに`Decode.maybe : Decoder a -> Decoder (Maybe a)`を使うこともできます。

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

`decodeMaybeFeatureId`（あるいは`Decode.maybe`で包んだ任意のデコーダー）は、常に`Ok Nothing`にフォールバックできるため必ず成功します。ただし、それを使うデコーダー自体は失敗する可能性があります。

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

次に`geometry`フィールドに注目しましょう。これはジオメトリオブジェクトか`null`のどちらかです。ここでも`Decode.oneOf`を使えますが、もっと良い選択肢があります。`Decode.nullable : Decoder a -> Decoder (Maybe a)`です。

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe`と`Decode.nullable`は同じシグネチャーを持ちますが、動作は異なります。`Decode.nullable`の`OK Nothing`という結果は、JSONの特定の値`null`からのみ生じるからです。

最後に、`properties`フィールドは任意のJSONオブジェクトか`null`を含むことができ、これには`Decode.value : Decoder Value`がうってつけです。

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

`Value`は不透明な型なので、その中身を簡単に調べることはできません。これを使うには、そのためのデコーダーを書いて`Decode.decodeValue : Decoder a -> Value -> Result Error a`で実行するか、ポートを通じて直接JavaScriptに送るかのどちらかです。

これでフィーチャーオブジェクトをパースする準備ができました。

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## JSONエンコーダー

エンコーダーを使うと、`Encode.encode : Int -> Value -> String`関数を使ってElmの値から有効なJSONを書き出せます。最初の引数は最終結果のインデントの量を指定し、2番目の引数は書き出すJSONの値です。

`Value`は、`Decode.value`から得るか、いずれかのエンコーダーで生成するかのどちらかです。

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

また、`Encode.object : List ( String, Value ) -> Value`でも書けます。

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

先ほど定義したGeoJSONのデコーダーに対応するエンコーダーを定義しましょう。

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

一般に、デコーダーとエンコーダーのペアの良いテストは、`elmValue |> encoder |> decoder == elmValue`が成り立つかを確認することです。

## ほかには？

`Json`モジュールのすべての関数を網羅したわけではありません。取り上げなかったものには、配列を`Array`に、オブジェクトを`List (String, a)`に変換するデコーダー、1つ以上の要素を持つ配列のためのデコーダー、入れ子になったJSONオブジェクトの特定のフィールドや配列の特定の要素を取り出すデコーダー、再帰的な構造をデコードする方法、そして`Error`のさまざまな種類とその表示方法などがあります。

よく使われる他のパッケージには、複雑なJSON構造を扱うための便利な流れを導入する[`Json.Decode.Pipeline`][pipeline]や、より多くのデコーダー・エンコーダー・ヘルパーを提供する[`Json.Decode.Extra`][extra]があります。
