# 正確な数値

すでに見てきた数値型のうち、2つは何かを犠牲にしています。

`INT`はちょうど32ビットなので、約マイナス20億から20億までの数値しか保持できません。その範囲を超えると、静かにラップしてしまいます。エラーは出ず、ただ答えが間違っているだけです。

`FLTD`は小数を保持できますが、あくまで近似的です。`0.1d + 0.2d`は`0.3`にごく近いものの、正確に等しくなるわけではありません。

こうした正確さが問題になる作業のために、ライブラリにはそれぞれ専用の型が用意されています。

## INTI：大きさを問わない整数

`INTI`は、メモリの許す限り大きさに制限なく整数を保持できます。

```sather
   #INTI(2).pow(100)
   -- 1267650600228229401496703205376
```

`INT`ではこれを保持できません。`FLTD`なら近い値は持てますが、末尾の20桁が失われてしまいます。

`INT`から作ることもできますし、そもそも`INT`として書くには大きすぎる数値なら、文字列から作ることもできます。

```sather
   #INTI(42)
   #INTI("123456789012345678901234567890")
```

あとは`+`、`-`、`*`、`/`、そして比較が通常どおり使え、`.str`で全桁を取り出せます。

一団が並ぶ順列の数を数えるのは、これが欲しくなる典型的な理由です。ダンサーが12人なら479001600通りで、これは`INT`に収まりますが、13人だと6227020800通りとなり、収まりません。

```sather
   #INTI(20).factorial
   -- 2432902008176640000
```

## RAT：正確な分数

`RAT`は、一方の整数を他方の整数で割った形のまま保持します。

```sather
   #RAT(1, 3)          -- 1/3, exactly
   #RAT(1, 2) + #RAT(1, 3)
   -- 5/6
```

小数に変換されることがないので、丸めは一切起こりません。

```sather
   #RAT(1, 10) + #RAT(2, 10) = #RAT(3, 10)      -- true
   0.1d + 0.2d = 0.3d                            -- not to be relied on
```

`RAT`は自動的に約分されます。`#RAT(2, 4)`は`1/2`で、`1/2`と表示されます。割り切れて整数になるものは整数として表示され、`#RAT(6, 3)`は`2`と表示されます。

## 代償

どちらも組み込み型より遅く、どちらもメモリを確保します。`INT`と`FLTD`は単一のマシン命令ですが、`INTI`と`RAT`はソフトウェアで計算を行うオブジェクトです。

正確さが求められる場面ではこれらを使い、それ以外の場面では通常の型を使いましょう。
