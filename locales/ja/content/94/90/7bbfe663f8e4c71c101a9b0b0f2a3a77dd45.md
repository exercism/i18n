# テストランナーをビルドする

テストランナーは、次のことを可能にする欠かせないツールです。

- サイトが、イテレーションがすべてのテストに合格するかどうかを自動で検証できるようにします。
- 学習者が、[ブラウザ内エディター](/docs/using/solving-exercises/using-the-online-editor)を使って演習を解けるようにします（[CLIは不要](/docs/using/solving-exercises/working-locally)）。

テストランナーの構築を始めるには、[テストランナーをゼロから作る](/docs/building/tooling/test-runners/creating-from-scratch)のドキュメントを参照してください。

## 実装

トラックのツールは、たいてい（ほとんどは）そのトラックの言語で書かれています。

```exercism/caution
他の言語を使うこともできますが、言語が増えるほど、そのトラックをメンテナンスしたりコントリビュートしたりするのが難しくなります。
そのため、できるだけそのトラックの言語を使うことをおすすめします。メンテナンスやコントリビュートがしやすくなるからです。
```

## デプロイ

テストランナーは、[Dockerコンテナ](/docs/building/tooling/docker)としてパッケージ化して実行します。
テストランナーのDockerイメージは、[GitHub Actionsのワークフロー](https://github.com/exercism/generic-test-runner/blob/main/.github/workflows/docker.yml)を使って自動的にデプロイされます。

## テスト

テストランナーをビルドしたら、そのDockerイメージをトラックのCIの設定に組み込んで、トラックの演習を検証できます。
この方法の主な利点は、本番環境の構成をより忠実に再現できることです。つまり、本番環境でも動作するという確信を持ちやすくなります。
一方、CIのワークフローが遅くなる可能性があります。
自分のトラックにとってどの方法が最適かは、メンテナーが決めてください。
