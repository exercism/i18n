# はじめに

`Types`のコンセプトでは、次のことを学びました。

- Juliaの型は階層構造になっています。
- それぞれの型にはスーパータイプがあります。
- `Any`は階層の最上位にあり、それ自身が自分のスーパータイプです。
- 型はサブタイプを_持つこともあり_、そうした型は`abstract types`と呼ばれます。
- サブタイプを持たない型（木構造の葉ノード）は`concrete types`と呼ばれます。
- `Char`や`Int64`のように、分割できない型は`primitive types`と呼ばれます。

この抽象型と具象型という単純なパターンに当てはまるのは、`primitive`型だけです。
`Vector`はコレクションであり、それぞれが独自の型を持つ要素に分けることができます。

```julia-repl
julia> isprimitivetype(Int)
true

julia> isprimitivetype(Vector)
false
```

_何のコレクションなのでしょうか？_

それぞれのベクター（または集合）は、ある共通した型を持つ要素の集まりです。その型は、波括弧（`{ }`）の中に_パラメーター_として指定することもできますし、省略して型推論に任せることもできます。

```julia-repl
julia> v = [1, 2, 3]
3-element Vector{Int64}:
 1
 2
 3

julia> v8 = Vector{Int8}([2, 4, 6])
3-element Vector{Int8}:
 2
 4
 6
```

こうした`parametric types`は`generic programming`の一種であり、多くのモダンな言語にもおおよそ同じような仕組みがあります。ただし、細かい点では多くの違いがあります。

## パラメトリックな複合型

複合型を、さまざまなフィールドの型に対応できるほど柔軟（ジェネリック）にしたいことがあります。

これは、定義の中でダミーの型を使うことで実現できます。その型は通常`T`と呼ばれます。

```julia-repl
julia> struct Point{T}
               x::T
               y::T
       end

# high definition version

julia> real_point = Point(7.3, 4.2)
Point{Float64}(7.3, 4.2)

julia> typeof(real_point)
Point{Float64}

# low definition version

julia> int8point = Point{Int8}(17, 23)
Point{Int8}(17, 23)

julia> typeof(int8point)
Point{Int8}

julia> Point(Int8(17), Int8(23))
Point{Int8}(17, 23)
```

もちろん、この方法はフィールドにコレクションを持つ場合にも使えます。

```julia-repl
julia> struct Record{T}
           data::Vector{T}
           comment::String
       end

julia> rec = Record{Float64}([1.3, 5.2], "some data")
Record{Float64}([1.3, 5.2], "some data")

julia> rec.data
2-element Vector{Float64}:
 1.3
 5.2

julia> rec2 = Record{Int32}([3, 5], "more data")
Record{Int32}(Int32[3, 5], "more data")

julia> rec2.data
2-element Vector{Int32}:
 3
 5
```
