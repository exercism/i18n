# ジェネレーター

`generator`とは、[イテレーター][iterator]という特殊な種類の、[`generator iterator`][generator-iterator]と呼ばれるものを返す関数または式です。
`Generator-iterator`は[遅延評価][lazy iterator]です。`values`をメモリに保存せず、必要になったときに値を_生成_します。

ジェネレーター関数は他の関数と見た目は同じですが、1つ以上の[`yield`式][yield expression]を含みます。
各`yield`はコードの実行を中断し、現在の実行状態（_すべてのローカル変数とtry文を含む_）を保存します。
ジェネレーターが再開すると、中断したところから状態を引き継ぎます。通常の関数が呼び出しのたびにリセットされるのとは違います。


## ジェネレーターを作る

ジェネレーターは他のループ関数や再帰関数とほとんど同じように作りますが、[`yield`式](#the-yield-expression)が必要です。これについては後ほど詳しく見ていきます。

たとえば、与えられた数値のリストから_平方_を返す関数を考えてみましょう。
現在の書き方では、値を返す前にすべての入力を処理しなければなりません。

```python
>>> def squares(list_of_numbers):
...     squares = []
...     for number in list_of_numbers:
...         squares.append(number ** 2)
...     return squares
```

この関数は、次のようにしてジェネレーターに変換できます。

```python
>>> def squares_generator(list_of_numbers):
...     for number in list_of_numbers:
...         yield number ** 2
```

これを書くのは、すべての値を_一度に_生成する必要がないときにジェネレーターを使うためです。
_現在処理している_値だけを計算するので、メモリと処理能力を節約できます。


## ジェネレーターを使う

ジェネレーターは、Pythonのほとんどの`iterables`の代わりに使えます。
これには、引数として`iterable`/`iterator`を必要とする_関数_や_オブジェクト_も含まれます。

`squares_generator()`ジェネレーターを使うには、次のようにします。

```python
>>> squared_numbers = squares_generator([1, 2, 3, 4])

>>> for square in squared_numbers:
...     print(square)
...
1
4
9
16
```

`generator`内の値は、`next()`関数を使っても生成・取得できます。
`next()`はジェネレーターイテレーターオブジェクトの`__next__()`メソッドを呼び出し、コードをその`yield`式まで「進めて」評価します。すると`yield`式が値を「生成」、つまり返します。

```python
>>> squared_numbers = squares_generator([1, 2])

>>> next(squared_numbers)
1
>>> next(squared_numbers)
4
```

`generator-iterator`を完全に消費して返す値がなくなると、`StopIteration`エラーを送出します。

```python
>>> next(squared_numbers)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
StopIteration
```


~~~~exercism/note

ジェネレーターイテレーターは、[イテレーター][iterator]の特別な部分集合です。
`Iterators`は、_イテラブル_をループするための仕組み、つまりプロトコルです。
ジェネレーターイテレーターと、一般的なPythonの[`iterables`][iterables]が返すイテレーターは非常によく似た動作をしますが、いくつか重要な違いがあります。

- _[遅延評価][lazy evaluation]_されます。繰り返しは_一方通行_で、前の値に「戻る」ことはできません。
- 返された値を繰り返すと_消費_されます。リセットやメモリへの保存は行われません。
- 並べ替えることはできず、逆順にすることもできません。
- シーケンス型ではなく、`indexes`を_持ちません_。
  足し算や引き算で前後の値にアクセスすることはできず、角括弧（`[]`）記法やスライスも使えません。
- 長さがないため、`len()`関数と一緒には使えません。
- _有限_の場合も_無限_の場合もあります。_無限_の`generator-iterator`からすべての値を集めるときは注意してください！

~~~~


## `yield`式

[`yield`式][yield expression]は`return`式と非常によく似ています。
`return`式とは_異なり_、`yield`は_特定の時点_で呼び出し元に値を渡し、追加の値は求められるまでその評価と返却を中断します。
`yield`が評価されると、それを囲む関数の実行を一時停止し、_その時点での_関数の値を返します。
その後、関数は_スコープに残り_、`__next__()`が呼ばれると、再び`yield`に到達するまで実行が再開されます。


~~~~exercism/note
`yield`式を関数の外で使うことはできません。
~~~~

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1

>>> lets_try = infinite_sequence()
>>> lets_try.__next__()
0
>>> lets_try.__next__()
1
```


## なぜジェネレーターを作るのか？

ジェネレーターは多くの場面で役立ちます。

大量になる可能性のある値の集まりを扱うとき、それらをすべてメモリに置きたくないことがあります。
ジェネレーターを使えば、大きなデータを少しずつ処理でき、メモリを節約しパフォーマンスを向上させられます。

ジェネレーターは、処理や計算が_複雑_、_高コスト_、あるいは_無限_である場合にもとても役立ちます。

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1
```

これで、`infinite_sequence`オブジェクトに対して`__next__()`が呼ばれるたびに、_直前の数値_ + 1を返します。
