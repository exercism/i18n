# 所有権

Cairoでは、所有権という考え方は、変数が保持する_値_ではなく、_変数_そのものに結びついています。

Cairoの値は不変です。この不変性のおかげで、たとえ多くの変数が同じ値を参照していても、値そのものは一定のままで、書き換えられることはありません。
そのため、コンパイラーは、プログラマーがこれらを正しく使うことを保証しなければなりません。
これが変数の_所有権_の意味です。所有者とは、その変数を読み取る（可変であれば書き込む）ことができるコードのことです。

## 変数の所有権のルール

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## 変数のスコープ

スコープとは、プログラムの中で変数が有効な範囲のことです。
次の例を見てみましょう。符号なし整数型の変数`x`を宣言し、コメントでその変数が有効な範囲を示しています。

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

補足：

- `x`がスコープに入ると、有効になります。
- スコープから外れるまで、この場合は`main()`関数の終わりまで有効なままです。

## 値の移動

値が別の関数に渡されると、移動が起こります。値が渡されると、その値を参照していた元の変数は破棄され（したがってその変数は使えなくなり）、同じ値を保持する新しい変数が作られます。

配列は、別の関数に渡すと移動される複合型の一例です。
配列がどんなものだったか、簡単に思い出してみましょう。

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

型システムは、Cairoのプログラムが同じメモリセルに二度書き込もうとしないことを、どうやって保証するのでしょうか？
次のコードを見てください。ここでは、配列の先頭を二度取り除こうとしています。

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

この場合、同じ値（`arr`変数の配列）を両方の関数呼び出しに渡そうとしています。
つまり、コードは最初の要素を二度取り除こうとしており、同じメモリセルに二度書き込むことになります。これはCairo VMで禁止されており、実行時エラーにつながります。
ありがたいことに、このコードは実際にはコンパイルできません。
配列を`foo`関数に渡した時点で、変数`arr`はもう使えません。
すると、`Array`が`Copy`トレイトを実装する必要がある、というコンパイル時エラーが出ます。

## `Copy`トレイト

ある型が`Copy`トレイトを実装していると、その型を関数に渡しても値は移動せず、同じ値を参照する新しい変数が作られます。
変数はCairoの抽象化であり、値は常に不変なので、これはコストのかからない操作です。

自分の型に`Copy`トレイトを実装するには、型定義に`#[derive(Copy)]`アノテーションを追加します。
ただし、その型やその構成要素のどれかが`Copy`トレイトを実装していない場合、Cairoはこれを許可しません。

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## 値の破棄

線形型は、破棄されることでも活用できます。これにより、関連するリソースが正しく解放されることが保証されます。
これは、`Drop`トレイトを実装または導出することで実現します。これにより、その型が不要になった時点で安全に破棄できることをコンパイラーに伝えます。

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

現時点では、`Drop`の実装は、辞書（`Felt252Dict`）と辞書を含む型を除くすべての型で導出できます。
これは、辞書が破棄されるときに"squash"されなければならないからです。
そのために、`Destruct`トレイトを導出します。

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## 戻り値とスコープ

値を返すことは、値を移動することと同じです。
次の例は、ある値を返す関数の例です。

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
