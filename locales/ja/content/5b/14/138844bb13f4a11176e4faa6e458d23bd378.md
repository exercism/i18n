# ヒント

## 1. `weigh-crate`

- `sequences`の単語1つでできます。

## 2. `weigh-all`

- `parallel-map`（[`concurrency.combinators`][combinators]内）は`map`と同じ形をしています。1つのクレートを1つの重量に変換するクォーテーションを渡します。

## 3. `<crane>`

- `crane`タプル（スロットは`lock`と`tonnage`）は、演習ファイルですでに宣言されています。
- ロックのスロットには`<lock>`（[`concurrency.locks`][locks]内）を、開始時のトン数には`0`を使います。`boa`はスタック上の値から、スロットの順にタプルを構築します。

## 4. `hoist-crate`

- `with-lock ( lock quot -- )`は、ロックを保持したままクォーテーションを実行します。クォーテーションはクレーンの`tonnage`を読み、`weight`を加え、その結果を書き戻す必要があります。`change-tonnage`（`TUPLE:`が自動生成します）は、この読み取り・変更・書き込みの手順を1つの単語で正確に行います。
- ローカル変数を使うと読みやすくなります。`:: hoist-crate ( weight crane -- )`と書けば、ロックの本体の中で`weight`と`crane`を参照できます。

## 5. `crane-tonnage`

- 読み取り側にもロックが必要です。そうすれば、進行中の書き込みを中途半端な状態で観測してしまうことがありません。

## 6. `load-cargo`

- クレートごとに`<promise>`を作り、そのクレートの重量を量って持ち上げ、プロミスを`fulfill`するスレッドを`spawn`します。`fulfill`する値は何でもよく、目印になる値で十分です。プロミスは完了を知らせるためだけに使われるからです。
- スレッドを生成しながら、プロミスをシーケンスに集めます（ローカル変数を使うとすっきり書けます。ラムダを渡した`map`もよく合います）。
- すべてのスレッドを生成したら、プロミスのシーケンスを順に見て、それぞれに`?promise`を呼びます。`?promise`はそのスレッドが終わるまでブロックするので、最後の1つが戻るころには、すべての持ち上げが完了しています。
