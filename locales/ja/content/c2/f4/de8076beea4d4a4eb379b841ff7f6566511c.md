# 評判

評判は、Exercismのエコシステムの中で「信頼」を獲得するための仕組みです。

評判は、その人がExercismにどれだけ貢献してきたかを示す指標です。プラットフォームへの貢献（ソフトウェアや演習、ドキュメントの作成など）と、コミュニティへの貢献（メンタリングなど）の両方が含まれます。

評判を「消費」したり「使用」したりすることはできません。ただし、一定の評判のしきい値に達すると、新しい特権や貢献の方法を利用できるようになります。簡単に言えば、その人の評判が高いほど、Exercismはその人をより信頼できるとみなし、より多くの権限を渡す、ということです。評判は、その人がExercismにどれだけ貢献してきたかを誰でも見られる形で示す指標でもあります。

## 目的

評判システムの目的は、次のとおりです。

1. 学習者とメンターの間の、成長につながるやり取りを最大化する
2. メンターが貢献したいという意欲を最大化する

## 評判の獲得

評判は、さまざまな方法で獲得できます。

| 行動                              | 評判       |
| --------------------------------- | ---------- |
| 解答のメンタリングを成功させる    | 5          |
| 解答を公開する                    | 1〜3       |
| 演習を作成する                    | 20         |
| 演習を更新する                    | 10         |
| コンセプトを作成する              | 10         |
| コンセプトを更新する              | 5          |
| プルリクエストを作成する          | 3〜100     |
| プルリクエストをレビューする      | 1〜20      |
| プルリクエストをマージする        | 1〜5       |

### 解答のメンタリングに成功したとき

メンタリングに成功した解答（ディスカッションが終了したもの）1件につき、評判が`5`付与されます。

### 解答を公開したとき

公開された解答1件につき、演習の難易度に応じて評判が付与されます。

| ラベル   | 評判       |
| -------- | ---------- |
| `easy`   | 1          |
| `medium` | 2          |
| `hard`   | 3          |

### 演習を作成したとき

作成者として名前が載っている演習1件につき、評判が`20`付与されます。

### 演習を更新したとき

コントリビューターとして名前が載っている演習1件につき、評判が`10`付与されます。

### コンセプトを作成したとき

作成者として名前が載っているコンセプト1件につき、評判が`10`付与されます。

### コンセプトを更新したとき

コントリビューターとして名前が載っているコンセプト1件につき、評判が`5`付与されます。

### プルリクエストを作成したとき

デフォルトでは、ユーザーが作成したプルリクエストがマージされたときに、評判が`12`付与されます。

プルリクエストの内容に応じて、メンテナーは次のいずれかのラベルをプルリクエストに付けることで、評判を増やしたり減らしたりできます。

| ラベル          | 評判       | 例                                                                                                                                                                                                                                                                                                                                                                  |
| --------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x:rep/tiny`    | 3          | <ul><li>1か所の誤字やリンクの修正</li><li>空行の削除や改行の追加</li><li>1つのコードコメントの変更または追加</li></ul>                                                                                                                                                                                                                                             |
| `x:rep/small`   | 5          | <ul><li>1つのテストケース、タスク、例の修正</li><li>1つのファイル内の複数の誤字やリンクの修正</li><li>ファイルに数行を追加して内容を明確にする</li></ul>                                                                                                                                                                                                             |
| `x:rep/medium`  | 12         | <ul><li>演習をproblem-specificationsと同期する（編集を含む）</li><li>1つ以上のテストケースを新規に追加する</li><li>演習内の複数のファイルを改善する</li><li>演習のメンターノートを新規に追加する</li><li>テストランナー・アナライザー・リプレゼンターの小さなバグを修正する</li><li>1つの演習に対するアナライザーのコメントを追加する</li></ul> |
| `x:rep/large`   | 30         | <ul><li>新しいコンセプト演習またはプラクティス演習を追加する</li><li>新しいコンセプトのドキュメントを追加する</li><li>既存のコンセプトや演習を大幅に書き直す</li><li>新しいCIスクリプトやその他の自動化を追加する</li></ul>                                                                                                                                            |
| `x:rep/massive` | 100        | <ul><li>テストランナー、アナライザー、リプレゼンター、ジェネレーターを新規に作成する</li><li>これらのツールを大規模にリファクタリングする</li><li>主要なドキュメントを新規に作成する（コントリビューションガイドやテストガイドなど）</li></ul>                                                                                                                       |

上記の例は、どのラベルをいつ適用するかの大まかな目安として使えますが、メンテナーは自分の判断で自由に決められます。

- 推定所要時間は、_メンテナー_がそのプルリクエストにかける平均時間と解釈してください。
- 複数のラベルが指定された場合は、評判の値が最も高いラベルが、付与される評判を決めます。
- プルリクエストがまだオープンの場合、評判は（まだ）付与されません。
- プルリクエストがマージされることなくクローズされた場合、評判は付与されません。

_後方互換性のために、付与される評判の決定に`x:size`ラベルを使うこともサポートしています。_

### プルリクエストをレビューしたとき

ユーザーがレビューした、マージ済みまたはクローズ済みのプルリクエスト1件につき、評判が`5`付与されます。

- プルリクエストがまだオープンの場合、評判は（まだ）付与されません。
- レビューの評判は、1つのプルリクエストにつきユーザー1人に対して1回だけ付与されます。
- プルリクエストを作成したユーザーは、自分のプルリクエストをレビューしても評判は付与_されません_。

- プルリクエストのレビューで付与される評判は、次のいずれかのラベルがそのプルリクエストに付くと変わります。

  | ラベル          | 評判       |
  | --------------- | ---------- |
  | `x:rep/tiny`    | 1          |
  | `x:rep/small`   | 2          |
  | `x:rep/medium`  | 5          |
  | `x:rep/large`   | 10         |
  | `x:rep/massive` | 20         |

  プルリクエストの作成者とレビュアーで、異なる評判の「サイズ」を使うことは_できません_。
  どちらも同じ`x:rep`ラベルに基づきます。

  複数のラベルが指定された場合は、評判の値が最も高いラベルが、付与される評判を決めます。

  _後方互換性のために、付与される評判の決定に`x:size`ラベルを使うこともサポートしています。_

### プルリクエストをマージしたとき

ユーザーがマージしたプルリクエスト1件につき、評判が`1`付与されます。

- プルリクエストがまだオープンの場合、評判は（まだ）付与されません。
- プルリクエストがマージされることなくクローズされた場合、評判は付与されません。
- プルリクエストを作成したユーザーは、自分のプルリクエストをマージしても評判は付与_されません_。
- プルリクエストにレビューが1件もない場合は、代わりに評判が`5`付与されます。

### イシューを作成したとき

プルリクエストと同様、イシューを作成したときは、デフォルトでは**評判は付与されません**。
プルリクエストとは違い、評判が付与されるのはlargeまたはmassiveのイシューだけです。

イシューの内容に応じて、メンテナーは次のいずれかのラベルをイシューに付けることで、評判を付与するかどうかを決められます。

| ラベル          | 評判       | 例                                                   |
| --------------- | ---------- | ---------------------------------------------------- |
| `x:rep/large`   | 30         | <ul><li>コンセプト演習を細部まで作り込む</li></ul>   |
| `x:rep/massive` | 100        | <ul><li>トラックのカリキュラムを設計する</li></ul>   |

上記の例は、どのラベルをいつ適用するかの大まかな目安になりますが、メンテナーは自分の判断で自由に決められます。

- 評判は、その_メンテナー_がイシューの作成にかける労力の大きさを反映しているべきです。

- 複数のラベルが指定された場合は、評判の値が最も高いラベルが、付与される評判を決めます。
