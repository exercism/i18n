# はじめに

## AST

抽象構文木（AST）は、_クォート式_とも呼ばれ、コードをデータとして表現する方法です。

ASTの各ノードは3要素のタプルです。

```elixir
# AST representation of:
# 2 + 3
{:+, [], [2, 3]}
```

最初の要素はアトムで、演算を表します。2番目の要素はキーワードリストで、メタデータです。3番目の要素は引数の配列で、他のノードを含みます。整数、アトム、文字列などのリテラル値は、3要素のタプルではなく、AST内ではそのままの値として表現されます。

### コードをASTに変換する

ElixirコードをASTに変換したり、ASTをコードに戻したりすることは、標準ライブラリの一部です。ASTを扱う関数は、`Code`モジュール（例：コードを含む文字列をASTに変換する）と`Macro`モジュール（例：ASTを走査したり、文字列に変換したりする）にあります。

標準ライブラリの関数はすべて、ASTを指す名前として「quoted」を使っていることに注意してください（_クォート式_の略です）。

コードをASTに変換する特殊形式は`quote`と呼ばれます。これはコードブロックを受け取り、そのASTを返します。

```elixir
quote do
  2 + 3 - 1
end

# => {:-, [], [
#      {:+, [], [2, 3]},
#      1
#    ]}
```

### ユースケース

コードをASTとして表現できることは、Elixirのメタプログラミングの核心です。_マクロ_は、Elixirコードを生成するElixirコードを書く方法であり、ASTを出力として返すことで機能します。

ASTのもう1つのユースケースは静的コード解析です。たとえば、Exercism独自のツールであるAnalyzerは、解答にコメントを残す小さなボットとして、すでに知っているかもしれません。
