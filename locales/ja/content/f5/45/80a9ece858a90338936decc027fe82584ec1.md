# ジェネリッククラス

```sather
class LOST_BOX{T} is
   attr item : T;
   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;
end;
```

## 型パラメーターとは

`T`は、使う場所で指定される型を表します。Satherでは、コンパイル時に、実際に使われた組み合わせごとに別々のクラスが作られます。つまり、

- `LOST_BOX{STR}`と`LOST_BOX{INT}`は無関係な型です。
- 実行時のチェックも、ボクシングも、変換もありません。
- クラス内のエラーは、それを使う型ごとに現れます。

これはC++のテンプレートやRustのジェネリクスと同じ考え方です。型が消去されて実体がすべてオブジェクトになるJavaのジェネリクスとは、そこが違います。

## 制約付きパラメーター

制約のない`T`にできるのは、代入し、渡し、返すことだけです。`T`について、それ以外のことは何もわかっていないからです。`T`のルーチンを呼び出したいときは、何に適合していなければならないかを指定します。

```sather
class LOST_BOX{T < $STR} is
   describe : STR is return "a box holding " + item.str; end;
end;
```

`T < $STR`は、`T`が`$STR`に適合していることを要求します。その代わり、`item.str`を呼び出せるようになります。制約のない`T`ではできないことは、制約を使えばできるようになります。

制約がないと、`item.str`はコンパイルできません。しかもエラーメッセージが指すのは、それを使った行ではなく、ジェネリッククラスの中の行です。

## ジェネリックなルーチン？

そんなものはありません。型パラメーターを取れるのはクラスだけです。複数の型に対して動作する必要のあるルーチンは、ジェネリッククラスの中に置くか、`$STR`のような抽象型を取るかのどちらかです。

## どちらを選ぶか

| | ジェネリッククラス | 抽象クラス |
| --- | --- | --- |
| 決まる時点 | コンパイル時 | 実行時 |
| 保持する型 | インスタンスごとに1つの型 | 適合する任意の型 |
| コスト | なし | ディスパッチ1回 |

`ARRAY{$ACT}`はその両方を使っています。要素の型はジェネリックで、その要素が何になれるかは抽象です。

全体を通して同じ型を使い、そのクラスを使う側がその型を把握しているなら、ジェネリッククラスを選びましょう。1つのコレクションの中に複数の型を共存させたいなら、抽象クラスを選びましょう。
