# ヒント

`Option`は、役に立つ結果が得られないかもしれない計算（たとえばエラーや不正な入力が原因の場合）を表すために使います。

`Option`に馴染みがない場合は、[このチュートリアル](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html)を読んでみてください。

`Option`は、いわゆる[Monad](https://en.wikipedia.org/wiki/Monad_(functional_programming))であり、「計算の側面」、この場合は値が存在しない可能性を扱います。

モナドを適切に使うと、とても簡潔でありながらエレガントで読みやすいコードになります。使い方を誤ると、あっという間に正反対の結果になってしまいます。詳しく知りたい場合は[この動画](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA)を見てみましょう。

## 避けておきたいよくある落とし穴

`Option`には、いくつかの経験則があります。

1. 必要ないなら使わない。次のように書くのではなく

```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```

次のようにしましょう

```scala
def add1(x: Int): Int = x + 1
```

（このような単純な関数を適用するための`Option.map`があるので、わざわざ`Option`でコードを煩雑にする必要はありません。）

2. 本当に必要でないなら「アンラップ」しない。多くの場合、目的に合った組み込み関数があります。早まったアンラップの兆候は、`isDefined/isEmpty`やパターンマッチです。次のように書くのではなく

```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```

次のようにしましょう

```scala
x map (_ + 1) getOrElse 0
```

3. モナドは、`for`内包表記の中で使うのが一番です。これは、複数の`Option`インスタンスを「合成」したいときに適しています。次のように書くのではなく

```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```

次のようにしましょう

```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
