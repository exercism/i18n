# パイプラインとコマンドリスト入門

これまで、コマンドのあとに引数を続けて書く、シンプルなコマンドの書き方を見てきました。
ここからは、シンプルなコマンドを組み合わせて、もっと複雑なコマンドを作る方法を見ていきましょう。

## 入力と出力

始める前に、入力と出力について簡単に紹介します。

プロセスには「標準入出力チャンネル」があります。

* プロセスは「stdin」から_入力_を受け取ることができます。
* プロセスは「stdout」に_出力_を書き出すことができます。
* プロセスは「stderr」に_エラー出力_を書き出すことができます。

`tr`コマンドは、そのとても純粋な例です。
入力からテキストを読み取り、文字を変換して、その結果のテキストを出力に書き出すだけです。

「stdio」チャンネルの操作については、シラバスの後半で詳しく見ていきます。

## パイプライン

これは、シェルプログラミングの「キラー機能」のひとつです。
パイプラインを使うと、テキストの流れに高度な変換を加えられます。

ユーザーの一覧をソートして表示するには、次のようにします。

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

パイプ記号（`|`）は、あるコマンドの出力を別のコマンドの入力につなぎます。
`cut`は`cat`の出力を読み取り、`sort`は`cut`の出力を読み取ります。

~~~~exercism/advanced
* デフォルトでは、パイプラインの各コマンドはそれぞれ別のサブシェルで実行されます。
  （サブシェルとは、現在実行中のシェルのコピーである子プロセスのことです。）

* パイプラインの実行には、パフォーマンスのコストがかかります。
  似たようなコマンドをつないだ長いパイプラインがある場合は、それらを1つのコマンドにまとめることを検討しましょう。
  たとえば、`grep`、`cut`、`sed`、`awk`、`tr`を複数使っているパイプラインは、たいてい1つの`awk`コマンドにまとめると効率的です。

* パイプラインの終了ステータスは、パイプラインの最後のコマンドの終了ステータスです。
  つまり、途中のコマンドが失敗しても、最後のコマンドが成功していれば、パイプライン全体の終了ステータスは0になります。

  これを変更できるシェルの設定があります。
  「pipefail」設定を有効にすると（`set -o pipefail`）、パイプラインの終了ステータスは次のようになります。
  * すべてのコマンドが成功した場合は0、そうでなければ
  * パイプライン内のコマンドの_**最後の**ゼロ以外の終了ステータス_
~~~~

## コマンドリスト

コマンドリストは、`;`（または改行）、`&&`、`||`で区切られたパイプラインの並びです。

* `A; B`は、`A`の完了後に`B`が実行されるコマンドリストです。
* `A && B`では、`A`が成功した場合（終了ステータスが0の場合）にだけ`B`が実行されます。
* `A || B`では、`A`が失敗した場合（終了ステータスが0以外の場合）にだけ`B`が実行されます。

コマンドリストの終了ステータスは、最後に実行されたコマンドの終了ステータスです。

`&&`と`||`の演算子はつなげることができ、前のコマンドのステータスに応じて次のコマンドを条件付きで実行できます。
たとえば次のようになります。

```bash
A && B && C && D || E
```

* Aが成功するとBが実行されます。
* AとBが成功するとCが実行されます。
* AとBとCが成功するとDが実行されます。
* A、B、C、Dの**いずれか**が失敗するとEが実行されます。

~~~~exercism/caution
これらの論理演算子は、控えめに使いましょう。
あっという間に読みにくいコードや、理解しづらいロジックにつながります。

たとえば、次の2つは同じだと思うかもしれません。

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

違いは、Cがいつ実行されるかです。

* 最初の例（`if`文）では、CはAが失敗したときにだけ実行されます。
* 2つ目の例では、Aが失敗したとき、_またはAが成功してもBが失敗したとき_にCが実行されます！
~~~~

### コマンドリストの活用法

コマンドリストでコードをシンプルにできる例を、いくつか紹介します。

#### ファイルから複数行のかたまりを読み込む

三角形のデータが入ったデータファイルがあり、1つの三角形が、その辺の長さを表す3つの別々の行で表現されているとします。

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

`while`ループの条件に、3つの別々の`read`コマンドを使うことができます。

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

`is_pythagorean`が、3つの辺がピタゴラスの定理を満たすかどうかを判定するコマンドだとすると、出力は次のようになります。

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### アサーション

多くのプログラミング言語には、ある条件が満たされなかったときに例外を投げる、アサーションという仕組みがあります。

```
assert(user == "Administrator", "wrong user");
```

Bashでは、OR演算子を使ってこの機能を模倣できます。

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## スタイル上の注意点

長いコマンドリストは、すぐに読みにくくなります。
改行を積極的に使うと、ぐっと読みやすくなります。

次の例は、2つの条件が満たされたときに配列に単語を追加するものです。

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

Bashでは、パイプや論理演算子の後で改行できます。

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

ただし、行の末尾にある演算子は見落としやすいものです。
_行の継続_を使うと演算子を先頭に置けるので、リストがまだ続いていることがよりわかりやすくなります。

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
_行の継続_とは、「バックスラッシュ」と「改行」という2文字の並び（`\` + `\n`）のことです。
Bashがこの並びを見つけると、それはコードから単純に取り除かれ、現在の行が次の行へと_継続_されます。
バックスラッシュと改行の間にスペースを入れないように注意してください。
~~~~

もうひとつ例を紹介します。

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

または

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
