# 概要

C#における中心的なオブジェクト指向の仕組みが、_クラス_です。クラスは、データ（[_フィールド_][fields]）と振る舞い（[_メソッド_][methods]）を組み合わせたものです。クラスのフィールドとメソッドは、_メンバー_と呼ばれます。

メンバーへのアクセスは、アクセス修飾子によって制限できます。最もよく使われるのは、次の2つです。

- [`public`][public]: どのコードからもアクセスできます（制限なし）。
- [`private`][private]: 同じクラス内のコードからしかアクセスできません。

すべてのメンバーにアクセス修飾子を指定するのが通例です。アクセス修飾子を指定しない場合、既定では`private`になります。

関連するデータと振る舞いをまとめ、メンバーへのアクセスを制限する、この仕組みは[カプセル化][encapsulation]と呼ばれます。これはオブジェクト指向の中核となる概念の1つです。

ある時点におけるオブジェクトのフィールドの値の組み合わせは、そのオブジェクトの[状態][object-state]と呼ばれます。

クラスは、そのクラスのインスタンスを作るためのテンプレートだと考えることができます。[クラスのインスタンスを作る][creating-objects]には（これは_オブジェクト_とも呼ばれます）、[`new`キーワード][new]を使います。

```csharp
class Car
{
}

// Create two car instances
var myCar = new Car();
var yourCar = new Car();
```

[フィールド][fields]には型があり、クラス内のどこにでも定義できます。パブリックフィールドは[PascalCase][pascal-case]で、プライベートフィールドは[camelCase][camel-case]で定義し、先頭にアンダースコア`_`を付けます。

```csharp
class Car
{
    // Accessible by anyone
    public int Weight;

    // Only accessible by code in this class
    private string _color;
}
```

フィールドには、任意で初期値を代入できます。フィールドに初期値を指定し_ない_場合、その型の[既定値][default-values]が設定されます。インスタンスのフィールドの値には、ドット記法でアクセスして更新できます。

```csharp
class Car
{
    // Will be set to specified value
    public int Weight = 2500;

    // Will be set to default value (0)
    public int Year;
}

var newCar = new Car();
newCar.Weight; // => 2500
newCar.Year;   // => 0

// Update value of the field
newCar.Year = 2018;
```

プライベートフィールドは通常、メソッドを呼び出した副作用として更新されます。そのようなメソッドは通常、値を返しません。その場合、戻り値の型は[`void`][void]にします。

```csharp
class CarImporter
{
    private int _carsImported;

    public void ImportCars(int numberOfCars)
    {
        // Update private field
        _carsImported = _carsImported + numberOfCars;
    }
}
```

なお、C#のクラスではパブリックフィールドを使うのは通例ではありません。プライベートフィールドを使うか、以降の演習で説明する別の種類のメンバーを使います。

クラス内では、[`this`キーワード][this]は現在のクラスを指します。これは、仮引数がフィールドと同じ名前を持つ場合に特に役立ちます。

```csharp
class CarImporter
{
    private int carsImported;

    public void SetImportedCars(int carsImported)
    {
        // Update private field from public method
        this.carsImported = carsImported;
    }
}
```

クラスとメソッドの構造は、フィールドやメソッドといったプログラムの要素の可視性を制限し、よく知られた[グローバル状態の問題][so-global-state-problem]を避けるための自然な方法を提供します。パブリックなフィールドやメソッド、その他のメンバーを、クラスの外のコードから見えるようにするには、オブジェクト名で修飾する必要があります。`object.field`や`object.method()`のように書きます（静的メンバーの場合はクラス名）。メソッド内で宣言された変数と仮引数は、そのメソッド内からしか見えません。

この仕組みで気を付けるべき点は、フィールド名と、メソッド内の変数や仮引数の名前が同じだと、メソッド内のコードではフィールド名が無視されてしまうことです。これが意図した動作とは限りません。一般的には、可能な限りこれを避けるべきですが、コンストラクターではよくあるパターンです。フィールドと変数の名前を同じにするのが適切な場合は、メソッド内でフィールド名を`this`キーワードで修飾します。

こうした[アクセス修飾子][access-modifiers]を使うと、可視性をさらに制限できます。
