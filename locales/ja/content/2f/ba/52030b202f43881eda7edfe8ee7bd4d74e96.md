# はじめに

## 文字列

### 文字

**文字エンコーディング**とは、自然言語のテキストの要素をバイト列として表現するための、特定の取り決めです。
ここでいう「テキストの要素」とは、自然言語で意味を持つ任意の単位のことで、たとえば文字、空白、句読点、絵文字、表意文字などです。

NASM（Netwide Assembler。このトラックで使うアセンブラーです）は、**ASCII**を使ってデータを定義するためのサポートを備えています。

NASMの文字定数は最大8バイトで、シングルクォート（`'`）、ダブルクォート（`"`）、バッククォート（`` ` ``）のいずれかを使って定義できます：

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

特殊文字はバッククォートで定義し、`\`でエスケープする必要があります：

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

x86-64では、文字エンコーディングを独立した型として扱うための組み込みのサポートはないことに注意してください。
アセンブリにおけるデータとはバイト列であり、そのバイト列を文字、数値、その他何として解釈するかは、プログラマーに委ねられます。

たとえば、ASCII文字の'0'は、値48の1バイトです。
つまり、48を1バイトに格納することは、ASCII文字の'0'を格納することとまったく同じです：

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

同じ理由から、文字を操作するには、そのバイトの値を直接変換します：

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### 文字列

**文字列**とは、文字の並びです。
アセンブリでは、通常は配列として実装されます。

NASMでは、他の配列と同じ方法で文字列を宣言できます：

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

文字列と他の配列の違いのひとつは、NASMでは値をカンマ（`,`）で区切らずに文字列を宣言できることです。
カンマを混ぜて値を並べることもできます：

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

すでに述べたとおり、文字は単なるバイト（Unicodeエンコーディングではバイト列）であることに注意してください：

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

ASCII文字はそれぞれ1バイトなので、より大きなサイズで見たときの後続のバイトはすべて`0`になります。
たとえば、`'a'`をqword（8バイト）として宣言すると、最初のバイトが`'a'`（`97`）で、残りの7バイトはすべて`0`になります。

このため、次のものはすべて等価です：

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
アセンブリでは、文字列はASCIIのNUL文字（値`0`）で自動的に終端されるわけではありません。

Cなどの高級言語とやり取りするときは、文字列の末尾に正しい終端文字（必要な場合）を付ける責任はプログラマーにあります。
~~~~

### 文字列命令

文字列は配列なので、メモリを明示的にデリファレンスすれば、他の配列とまったく同じように扱えます：

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

さらに、メモリ上のバイト列に対して値を読み込み、移動、格納するための命令がいくつかあります。
_文字列命令_と呼ばれていますが、メモリ上の任意のバイト列、つまり任意の配列に対して使えます。

もっとも重要な文字列命令は`lods`、`stos`、`movs`の3つです：

| 命令 | 動作                                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | `rsi`が示すメモリ位置から`rax`に値を読み込みます                                                |
| `stos`      | `rax`の値を`rdi`が示すメモリ位置に格納します                                               |
| `movs`      | `rsi`が示すメモリ位置から値をコピーし、`rdi`が示すメモリ位置に格納します    |

これらの命令は明示的なオペランドを_取りません_。
オペランドは暗黙です。

おおまかな指針として：

1. ソースオペランドがメモリ位置の場合、そのアドレスは`rsi`に格納します（`s`はsourceの`s`）。
2. デスティネーションオペランドがメモリ位置の場合、そのアドレスは`rdi`に格納します（`d`はdestinationの`d`）。
3. オペランドの一方がメモリ位置でない場合、それは`rax`レジスタです。

これらの命令は、それぞれが行う操作に応じて、メモリアドレスを自動的にデリファレンスすることに注意してください。

いずれも異なるサイズで動作できます。
そのサイズを示すために接尾辞が付きます：

| 接尾辞 | 意味 | サイズ    |
| :----: | ------- | :------ |
|  `b`   | バイト    | 1バイト  |
|  `w`   | ワード    | 2バイト |
|  `d`   | ダブルワード   | 4バイト |
|  `q`   | クアッドワード   | 8バイト |

たとえば：

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

また、使用したアドレスを操作のサイズだけ更新します。
この更新は、**方向フラグ（DF）**の値に従って行われます：

- `DF`がクリアされている場合、アドレスは操作のサイズだけ_増加_します。
- `DF`がセットされている場合、アドレスは代わりに同じ量だけ_減少_します。

System V ABIでは、関数に入った時点で方向フラグをクリアしておくことが定められています。
つまり、_メモリはアドレスの昇順で読み書きされるのが既定の動作です_。

`cld`命令を使うと方向フラグをクリアでき、`std`命令を使うとセットできます：

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
System V ABIに従い、呼び出し側は、呼び出した関数が戻ったときに`DF`がクリアされていることを前提としています。
`DF`をセットした場合は、必ず`ret`の前にクリアしてください。
~~~~

#### Rep

これらとは別に、**rep**命令はメモリと直接やり取りしません。
代わりに、先ほど挙げた他の命令の接頭辞として付けることができ、その命令を_繰り返し_ます。

`rep`を付けると、文字列命令は`rcx`の値と同じ回数だけ繰り返されます。
繰り返すたびに、`rcx`の値は`1`ずつ減ります。
命令を使う前に`rcx`の値を設定しておく必要があることに注意してください：

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
現代のCPUでは、大きなブロックのデータを移動するとき、`rep movs`と`rep stos`はたいてい高速な選択肢です。
しかし、他の文字列命令や、`rep`を付けずに使う`movs`や`stos`は、通常は単純なループよりも遅くなります。

この話題をより詳しく知りたい場合は、こちらの参考書の[第16.9章「String instructions」][agner-optimization-guide]を参照してください。
