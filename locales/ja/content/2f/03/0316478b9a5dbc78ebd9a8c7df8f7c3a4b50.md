# 概要

- Ponyは静的型付け言語です。つまり、プログラムで扱うデータの型を、あらかじめ定義しておかなければなりません。変数`x`を整数だとPonyに伝えたら、そこに文字列を代入することはできません。
- Ponyの型システムこそが、Ponyの保証を成り立たせています。
  - プログラムはコンパイルさえ通れば、クラッシュしません。
  - 未処理の例外が起きることはありません。
  - `null`というものが存在しないので、プログラムが`null`を参照解除しようとすることもありません。
  - データ競合が起きることはありません。
  - デッドロックが起きることはありません。
  - コードのケイパビリティセキュリティは常に保たれます（サプライチェーン攻撃からの保護）。
- Ponyでは型をキャストできません。型の変更はすべて、新しい型のインスタンスを生成する関数を通して行う必要があります。
- Ponyの型システムは他のほとんどの言語とは大きく異なるので、小さな単位に分けて見ていきましょう。

## プリミティブ

- プリミティブは、Ponyでコードをまとめる最も単純な単位です。
  - 関数のためのコンテナ、つまり名前空間のようなものだと考えてください。
  - フィールドは持ちません（フィールドにはクラスを使います）。
  - `primitive`キーワードで定義します。

## 関数

- 関数は`fun`キーワードで定義します。
  - 関数は`primitive`の中に置く必要があります（`class`や`actor`の中にも置けますが、これらは後で扱います）。
  - 関数には、渡ってくる入力と戻り値を持たせられます。どちらにも型を付ける必要があります。
  - 戻り値の型を定義したら、関数はその型の値を必ず返さなければなりません。PonyにはNullという概念がありません。

```pony
primitive Greeter
  // A Function that takes a String, and returns a different String
  fun hello(name: String): String =>
    "Hello " + name + "!"
```

## コメント

コメントを使うと、メモや備忘を残したり、ソースコードからコードを一時的に外したりできます。上ですでに見たとおり、1行コメントには`//`を使います。複数行コメントにはC言語スタイルの`/*`と`*/`を使います。

## 変数

- 変数は必ず小文字で始まります。
  - 変数の宣言には`var`を使います（`let`と`embed`は後で扱います）。
  - Ponyが変数の型を判断できれば、自動で型を決めてくれます。
  - 変数の型はコンパイル時にチェックされ、決して変わりません。
  - Ponyを始めたばかりのときは、型を明示的に書くのがおすすめです。

```pony
var name: "Bob"
var bettername: String = "Bobby"
```
