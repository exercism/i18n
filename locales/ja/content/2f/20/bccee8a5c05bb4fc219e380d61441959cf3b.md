# コントリビューションガイドライン

Pharoトラックの開発に参加したい場合は、始めるための助けになる以下の手順に従ってください。

このトラックをよりよくして、プログラミングについての違った考え方をエンジニアに示していきたいと思っています！ :tada:

[Exercismのトラックに参加する方法](https://github.com/exercism/docs/tree/master/contributing-to-language-tracks)を読んでください。また、[Exercismの行動規範](https://exercism.io/code-of-conduct)も必ず読んでください。

あらゆる種類のプルリクエストを歓迎します。どんなに小さなコントリビューションでも歓迎します。特に、既存の演習の修正や改善はありがたいです。なお、このトラックの演習は[Exercism全体の標準](https://github.com/exercism/docs/tree/master/language-tracks/exercises)に準拠している必要があります。ただし、変更の仕方に迷ったら、GitHubでissueを作成してください。そこで相談しましょう。

>__Note__: Exercismは[Exercism全体でのコミュニティコントリビューションを一時停止する](https://exercism.org/blog/freeing-our-maintainers)ことを決定しました。Pharoトラックはコミュニティが比較的小さいため、この方針から除外されています（つまり、Pharoトラックのコントリビューターは誰でもこれまでどおりissueを作成し、PRを送信できます）。

## 知識の前提条件

Pharoでの開発と、[Iceberg Git](https://github.com/pharo-vcs/iceberg)の使い方に[慣れている](./docs/RESOURCES.md)ことを前提としています。

## 開発環境のセットアップ

まず、Exercismの開発環境が整っていて、以下のものがインストールされていることを確認してください。

### __PharoイメージとIDE__

実際のコード例を作成するには、Pharoの開発環境（起動中のPharoイメージ、すなわちIDE）が必要です。

1. [PharoLauncher](https://pharo.org/download)を使って、`Official distributions`カテゴリから新しい安定版の開発イメージを作成し（05/24時点の安定版イメージはPharo 12.0 - 64bit (stable)です）、起動します（[zerconf](https://get.pharo.org/)に慣れていればそちらも使えます）。
2. イメージを起動して、すべてが問題なく動作することを確認します。

> __Note__: TIMEOUTの問題が発生した場合は、[ユーザー向けインストール手順](./docs/INSTALLATION.md)を参照してください。

### __Gitリポジトリのセットアップ__

1. まだ行っていない場合は、GitHubで`https://exercism/pharo-smalltalk`をフォークします。
2. 自分のフォークをcloneするには、起動中のPharoイメージのPlaygroundで次のコマンドを実行します。
```
Metacello new
 baseline: 'Exercism';
 repository: 'github://exercism/pharo-smalltalk:main/releases/latest';
 load: 'dev'
```
これでPharoトラックのGitリポジトリがcloneされ、Pharoトラックのソースコードが開発用ベースラインとしてPharoイメージに読み込まれます。cloneしたリポジトリのローカルフォルダーは（Icebergの設定に応じて）次の場所に作成されます：`<path-to-Pharo-image>/pharo-local/iceberg/<your-id/pharo-smalltalk`。
> __Note__: Pharoイメージのソースは、前述のディレクトリの`src`サブフォルダーにある`*.st`ファイルに同期され、シリアライズされます。

2. 別の方法として、CLIで自分のフォークをcloneすることもできます：`git clone https://github.com/<your id>/pharo-smalltalk`をGitHubプロジェクトとして実行し、`<your id>`をオーナー名、`pharo-smalltalk`をプロジェクト名に指定します。
次に、起動中のPharoイメージのMetacelloコンテキストメニューを使って、IcebergにMetacelloベースライン`dev`（デフォルトではありません）をインストールします（たとえば、cloneしたばかりの"pharo-smalltalk"プロジェクトを右クリックし、Metacelloメニューの2番目のオプションを選んで`dev`と入力します）。

3. プロジェクトをPharoイメージに読み込んだら、忘れずにイメージの変更を__保存__してください（メニューのPharo -> Save）。

__任意のリポジトリ__
1. 別の方法として、`git clone https://github.com/exercism/pharo-smalltalk`をステージングリポジトリとしてcloneし、そこにチェックインする演習とアセットを生成することもできます（Pharoでのコーディングとは別に行います）。このリポジトリでConfigletツールが生成した変更は、ローカルのフォークリポジトリにコピーする必要がある点に注意してください。混乱を避けるために、`~/development/exercism/pharo-staging`のようなパスを使うことをおすすめします（この場所はどこでもかまいません）。このリポジトリは必須ではありません。コミットに含める変更を確信できるなら、フォークしたリポジトリ（Pharoイメージと同期しています）で直接Configletの変更を生成できます。
2. ゼロから実践演習に取り組みたい場合は、Exercismの[problem specifications](https://github.com/exercism/problem-specifications)もcloneできます。これも下で設定するexercismワークスペースのサブディレクトリに置きます（このリポジトリは演習のreadme.mdファイルを生成するために使われ、推奨されるテストへの参照でもあります）。

### __使用するリポジトリブランチについて__

`main`ブランチは主要な開発ブランチで、すべてがここにマージされます。コードの変更に取り組む場合は、mainからfeatureブランチを作成し、そこに変更をコミットします。完了したら、GitHubでPRを作成し、ベースリポジトリ（Exercism/pharo-smalltalk）の`main`にマージしてもらいます。このブランチは以前`master`と呼ばれていましたが、__現在は非推奨です__。

### __Exercism CLIツールのセットアップ__

これらのツールは、Exercismプロジェクトとやり取りするために必要です。
1. [exercismコマンドラインインターフェース](https://exercism.io/cli-walkthrough)をインストールし、Exercismの演習開発用のディレクトリ（ワークスペース）を設定します（例：`exercism configure -w ~/development/exercism`）。これはローカルのフォークリポジトリへのパスでも、（任意で）ステージングリポジトリへのパスでもかまいません。
2. 演習のメタデータを生成し、検証を実行するためのExercismの[configlet](https://github.com/exercism/configlet#usage)リンター／ジェネレーターです。Configletのインストール方法は、[トラックでの使用](https://github.com/exercism/configlet#use-in-your-track)の段落の手順に従ってください（bin/fetch-configletを参照）。

## Exercismの演習に取り組む

Exercismでは、概念演習（プログラミング言語の理論を説明するもの）と実践演習を区別しています。以下の段落では、当面は実践演習へのコントリビューションだけに焦点を当てます。

### __概要__

演習を完成させるまでの手順：
1a. 実践演習をゼロから作成します（problem specificationsから）。
1b. 既存の実践演習の解答に取り組みます。
2a. 演習の解答のシリアライズされたソースファイルをディレクトリに生成し、演習のメタデータを生成します。
2b. 新しく完成した演習をプロジェクトの一部として含めるように、プロジェクトのベースラインを調整します。
3. リポジトリのフォークに変更をコミットし、PRを作成して変更を公開します。

#### TLDR: 実践演習を生成・エクスポートする簡単ガイド
要するに、Pharoから演習を生成・エクスポートするだけです。Playgroundで次を実行します。
```Smalltalk
"Obtain exercise from problem specification"
ExercismExerciseGenerator new generateExerciseFrom: 'path-to-problem-specifications/exercises/slug-name' asFileReference.

"Update exercise version within Pharo image  (with updated test cases) to output exercise directory (once you have solution class defined)"
ExercismGenerator new 
	exercisesDirReference: 'path-to-local-repository/exercises/practice' asFileReference;
	generateForExercise: 'slug-name'.
```
  > __Note__: 詳細は以下の手順にあります。 

![実践演習を完成させるまでのワークフロー](/docs/images/overview-exercism-pharo-contribution.svg)

### __1. 新しい実践演習を作成する__
*TLDR: 演習の生成に関する詳細とAPIの説明はすべて、`ExercismExerciseGenerator`クラスのクラスコメントにあります。*  

__problemリポジトリから新しい演習を作成する__
- まったく新しい実践演習を始めたい場合（ステップ1a.）は、problem specificationリポジトリを使って、対象の演習のテストクラスを次のコマンドで生成できます：
`ExercismExerciseGenerator generateFrom: <path-to-problem-specifications/exercises>`。これにより、problem specificationsリポジトリにあるすべての演習のテストクラスが`ExerciseWIP`パッケージに生成されます。  

  > __Note__: Pharoイメージのメニュー項目からも同じことができます（World menu -> Exercism -> Generate test cases）。
- より具体的には、次のようにして特定の演習のテストクラスを生成できます：`ExercismExerciseGenerator generateExerciseFrom: '<path-to-problem-specifications/exercises/slug-name>' asFileReference`。

上の文を実行すると、`ExerciseWIP`パッケージに、生成されたテストメソッドを持つ新しい`<SlugNameTest>`テストクラス（ExercismTestのサブクラス）が作成されます。

__problemリポジトリから既存の演習を再生成する__
既存の演習（すでに解答パッケージで定義されているもの、たとえば`Exercise@TwoFer`）のテストメソッドを再生成したい場合は、次のコードを使います。他のメソッド（uuid、versionなど）は変更されない点に注意してください。 

 `ExercismExerciseGenerator new regenerateExerciseFrom: 'path-to-problem-specifications/exercises/exercise-slug' asFileReference`

__ゼロから作成する__  
面白いアイデアがあれば、新しい演習の追加に関するドキュメントを参照してください。

プロジェクトには、ユーザー定義の演習の例があります。`DieTest`を参照してください。customDataメソッドをオーバーライドすると、ジェネレーターが関連するファイルを作成します。

注意点：
- 各演習は独立している必要があります。演習ディレクトリの外にあるファイルを参照しないでください。ユーザーが演習を取得しても、それらは含まれません。
- 演習は[Exercism全体の標準](https://exercism.org/docs/building/tracks/practice-exercises)に準拠している必要があります。
- 演習ではPharoのコアライブラリだけを使うようにします。
- 各演習は次のようになっている必要があります。
  - `Exercism@<ExerciseName>`という名前の最上位プロジェクトに格納されている
  - `<ExerciseName>Test`（CamelCase）という名前のTestCaseと、`<ExerciseName>`という名前の解答例がある
  - TestCaseには、演習を説明するMarkdown形式のクラスコメントがある。このテキストはREADME.mdファイルの生成にも使われます。
- 演習の中に設定ファイルやディレクトリをコミットしないでください（これは今後の演習で見直される可能性があります。問題になったら知らせてください）。
- `UUIDGenerator next`を使って演習の新しいUUIDを生成し、その値をテストの`uuid`メソッドに設定してください。

> __Note__: 現在のPharoのUUIDジェネレーターは、残念ながらRFC 4122のバージョン4に準拠していません。そのため、configletで生成したUUIDを次のようにして使ってください：`/bin/configlet uuid`

### __2. 既存の演習に取り組む__

手助けの方法はたくさんありますが、いちばん簡単で役に立つコントリビューションは、現在「募集中」の演習の解答を完成させることです。

  * イメージがexercism/pharo-smalltalkのmainに追いついていることを確認します（変更はフォークにプッシュし直します）。

  * 演習はすべて、前述のproblem-specificationsリポジトリから自動生成されたTestCaseです。それらはExercismWIPパッケージ内のExercismTestのサブクラスとして見つかります。解答がすでに存在する場合、再生成されたExercismTestが対象の演習パッケージにすでにあるかもしれません。ExercismWIPパッケージは、解答クラスと並んでまだデプロイされていない、新しい演習や作業中の演習に使われます。

  * 取り組みたい演習を選んだら、GitHubで「Convert Exercise <name>」と指定してIssueを作成します。これで他の人に取り組み中であることが伝わり、あとでプルリクエストを作る際の基礎にもなります。

  * 各WIP演習には、すでにクラスコメントに問題の説明があります。テストを実行し、解答をTDDで書きます（最初のテストを単独で実行する場合はデバッガーの中で行います）。

  * テストがSmalltalkらしくない場合は、__テストを調整する必要があるかもしれません__（ジェネレーターはかなり基本的なものです。とはいえ、修正のいくつかは上流の[problem-specification](https://github.com/exercism/problem-specifications)のテキストへのPRとして適切かもしれません）。

  * 演習のクラス側で#exerciseメソッドをオーバーライドし、難易度やトピックなどを入力して、演習のメタデータを更新します。Test commentタブ（下部）にもヒントのテキストを入力してください（TBDというテキストを置き換えます）。

  * 選んだ解答例のパッケージを`Exercise@<ExerciseName>`に更新します（つまり、WIPパッケージから移動します）。ステップ1bです。
  * Icebergで、選んだ演習の名前で新しいブランチを作成します（このためにIcebergツールを使い、上で作ったissue番号を入力します）。
  * プルリクエストを送信する前に、Pharoの演習のすべてのテストを実行し、それらが__すべて通る__ことを確認します。

### テスト

もっとも基本的なレベルでは、Exercismはテストと、[テストスイート](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md)を使ったテストが中心です。

PharoのExercism演習はサブパッケージに分かれており、それぞれに[SUunit](https://en.wikipedia.org/wiki/SUnit)と互換性がなければならないTestCaseが含まれています。これはオリジナルのxUnitライブラリで、演習用の追加のサードパーティフレームワークは必要ありません。

演習をテストするには、組み込みのテストランナーでtest orbをクリックして実行します。テストが成功するとorbは緑になり、失敗やエラーがあるとそれぞれオレンジまたは赤になります。あるいは、Playgroundで次のように評価して手動でテストを実行することもできます。

```smalltalk
<ExerciseName>Test suite run. "single exercise"

AllExercismTests suite run. "all exercises"
```
> __Note:__ 独自の（生成されていない）テストケースを定義したい場合は、テストクラスの`extra`プロトコルに置けます。
一貫性のため、テストメソッドでは`self assert: actual equals: expected`というテストパラメーターの順序を使います。

開発用ではないイメージでテストする場合は、[ユーザー向けインストール手順](./docs/INSTALLATION.md)に従ってください。そのイメージを使って以降の開発ベースラインをテストする場合は、最新のコードを取得するために次の開発用ディレクトリを削除する必要があるかもしれません：
`./pharo/pharo-local/iceberg, ./pharo/pharo-local/package-cache`

### __3. 完成した演習を公開する__

解答ができて、ローカルのfeatureブランチにコミットしたら、次の手順を行います。  
#### 演習のソースコードを生成する
これはステップ2aを指します。解答とテストクラスの__ソースコードを生成__します。

__すべての演習の出力ソースを生成する__ 
- `ExercismGenerator generate` -> すべての演習のソースファイルが生成されます。configletの`generate`コマンドが実行され、有効なすべての演習を一覧にした`config.json`も再生成されます（またはWorldメニューで"Exercism" -> "Regenerate meta data"を選びます）。

#### 特定の演習の出力ソースを生成する
- デフォルトのディレクトリ（`repository-root/exercises/practice`）を使う場合
```
ExercismGenerator new generateForExercise: 'slug-name'
```

特定の演習ディレクトリにエクスポートする必要がある場合：
```
ExercismGenerator new 
	exercisesDirReference: 'path-to-exercises/practice' asFileReference;
	generateForExercise: 'slug-name'
```

> __Notes__: 
  - ExercismGeneratorはmainのconfig.jsonを自動的に更新します（存在しない場合は新規作成します）。
  - configletコマンドを使って、指定した演習のすべてのドキュメント、メタデータ、ファイルパスを同期します。詳細はこちら：[新しい演習を追加するときのsyncの使用](https://github.com/exercism/configlet#using-sync-when-adding-a-new-exercise-to-a-track)

####  Pharo-smalltalkプロジェクトのベースラインを更新する
ステップ2b：`BaselineOfExercism>>exercisePackageNames`メソッドのリストに演習名を追加して、Pharo-smalltalkプロジェクトのベースラインを更新します。これにより、Metacelloコマンドで新しい演習を含めてプロジェクトを読み込むときに、演習が確実に読み込まれます。
  
#### プルリクエストを送信する
ステップ3：PRを作成する前に、CLIコマンドを実行してExercismの成果物が正しいか確認します：
`bin/configlet lint`（PRを送信すると、いずれにせよCIが自動でリンティングを実行します）。  
すべて問題なければ、PRを作成できます。
- ブランチをフォークにプッシュし、`exercism/pharo-Smalltalk`でプルリクエストを作成します。

> __Final details__: 

- ブランチで一緒に作業できるよう、[メンテナーの編集を有効にする](https://help.github.com/en/articles/allowing-changes-to-a-pull-request-branch-created-from-a-fork)ことが重要です。
-  プルリクエストは、1つの演習、issue、または概念的にまとまりのある変更に焦点を当てるようにします。詳しくはExercismの[プルリクエストガイドライン](https://github.com/exercism/docs/tree/main/building/github#guides)を参照してください。
- 自分のPRを追い、その後の質問に答えます。
- 最後に調整を送信すると、メンテナーがプルリクエストをマージし、最終的な解答がサイトに表示されます。

## メンテナー向けの追加情報

### コーディングスタイル

このリポジトリのコードは、可能な限り[Pharo with style](https://github.com/SquareBracketAssociates/Booklet-PharoWithStyle)の規約に従うようにします。より一般的な[Smalltalk with style](http://sdmeta.gforge.inria.fr/FreeBooks/WithStyle/SmalltalkWithStyle.pdf)も参考にできます。

演習を作成するときは、組み込みのコードフォーマッター（エディターでmeta-t FO）やコード批評も活用してください。

### 破壊的な変更

大きな変更や破壊的な変更を予定している場合は、マージする前に話し合えるようissueを作成してください。この議論がPharoトラックだけでなく関係する場合は、[exercism/discussions](https://github.com/exercism/discussions/issues)にもissueを作成してください。
