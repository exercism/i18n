# はじめに

プログラムで独自の型を定義できると、便利なことがよくあります。

新しいプリミティブ型を定義することもできますが、実際にそうすることはほとんどありません。
組み込みのプリミティブ型は、適当に選ばれたわけではありません。JuliaがJITコンパイルに使うLLVMコンパイラーの標準の型と、ほぼ一致しています。

もっと便利なのは、名前の付いたフィールドを持つ複合型を定義できることです。

他の言語にもよく似たものがあり、`structs`や`records`と呼ばれています。
Juliaのドキュメントではこれを`composite types`と呼んでいますが、言語の構文では`struct`キーワードを使って定義します（少し食い違っていますね）。

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

上の例では、いくつか注目すべき点があります。

- `id`には型が指定されていないので、コンパイラーはこれを`id::Any`と解釈します。
- 型名はコンストラクターとして使われ、`Person(id, name, age)`のように書くと、型`Person`のインスタンスが得られます。
- 個々のフィールドには、名前付きタプルと同じように、ドット記法でアクセスできます。

`Person`型の値はイミュータブルなので、更新はできません。

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

ミュータブルにする必要がある場合は、定義に`mutable`を付けます。

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

コンストラクターは既定では、定義と同じ順序でフィールドを並べる必要があります。型が複雑になると、これは不便になってきます。

`@kwdef`マクロを使うと、次の2つのことができるようになります。

- コンストラクターが使うのは、位置ではなくキーワードです。
- フィールドに既定値を設定でき、コンストラクターから省略することもできます。

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## 複合型の階層

ここまでは、具象の複合型しか作っていません。
確認すると、どれも`Any`のサブタイプです。

関連する複数の型を作るときは、それらの階層を定義するほうがたいてい理にかなっています。
これはとても簡単にできます。

まず、抽象型を作ります。

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

次に、型定義に`<:`演算子を入れて、関係を示します。

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

必要に応じて繰り返しますが、具象型をサブタイプにすることはできない点に注意してください。

もっと複雑な階層が必要なら、必要に応じて抽象サブタイプを作ります。

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

このような階層のありがたみは、`Multiple Dispatch`のコンセプトに進み、関数が引数の型をどう扱うかを見ると、もっとはっきりしてきます。
