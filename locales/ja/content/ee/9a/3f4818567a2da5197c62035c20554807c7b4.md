# インストール

このトラックでは、JavaScriptを動かすための実行環境として、最初から最後まで[Node.js][web-nodejs]を使います。つまり、お使いのコンピューターでJavaScriptを実行するときは、常に[Node.js][web-nodejs]を使うことを前提としています。

## トラックの要件

多くのマシンには[Node.js][web-nodejs]があらかじめインストールされていたり、以前にインストールされていたり、何かの依存関係として入っていたりします。
ですから、何をするにしても、まずインストールされているかどうかを確認しましょう。

1. _ターミナル_（`Terminal`、`cmd`、`Powershell`、`bash`、...）を開きます
1. `node -v`

[Node.js][web-nodejs]がインストールされていれば、バージョンが表示されます。
このバージョンはメモしておきましょう。
[Node.js][web-nodejs]がインストールされていなければ、エラーが表示されます。
たいていは、`'node' is not recognised`のような内容です。

## Node.js

### Node.jsがすでにインストールされている場合

[Node.jsのウェブサイト][web-nodejs]にアクセスしてみましょう。
すると、_2つ_のバージョンが表示されます（OSが自動的に判別された場合。そうでなければ、まずOSを選択してください）。
`node -v`で表示されたバージョンがそのどちらかと一致していれば、そのままで大丈夫です。
一致していない場合は、Node.js LTSを使うことをおすすめします。
アップグレードでシステムの何かが壊れてしまうのが心配な場合は、すべて問題ないものとしてそのまま進めてもかまいません。
ただし、予期しないことが起きたときにサポートできない場合があります。

### Node.jsがインストールされていない場合

[Node.js][web-nodejs]をインストールする方法はいくつかあります。

- [インストーラーまたはバイナリ][web-nodejs-download]を使う
- [パッケージマネージャー][web-nodejs-package]を使う

どちらの方法もWindows、macOS、Linuxに対応しています。どれを選べばよいかわからない場合は、インストーラーを使うのがいちばん簡単です。

- **LTS**バージョンの使用をおすすめします。[Node.js][web-nodejs]のウェブサイトでも、_ほとんどのユーザーに推奨_として示されています。
- ウェブページの手順、またはインストーラー中の指示に従って、[Node.js][web-nodejs]をインストールしましょう。

## インストールの確認

インストーラーが完了したあと、パッケージマネージャーでの作業が終わったあと、あるいはバイナリをコピーして手順どおりに進めたあとは、すべてうまくいっているか確認しておきましょう。

1. _ターミナル_（`Terminal`、`cmd`、`Powershell`、`bash`、...）を開きます
1. `node -v`

表示されるバージョンは、ウェブサイトに載っているものと一致しているはずです。

> [!NOTE]
> _新しい_ターミナルウィンドウを開くことが大切です。
> すでに開いているターミナルウィンドウは、インストールが完了したあとに更新されていない可能性があります。
> つまり、開いたままのターミナルは、新しいプログラムがインストールされたことを認識していません。

> [!IMPORTANT] > _**ヘルプ**_: `'node' is not recognised`
>
> 公式のインストーラーを使った場合は、`PATH`は自動的に設定されているはずです。ただし、シェルがグローバルにインストールされたモジュールを見つけられない場合や、Node.jsをソースからビルドした場合は、`npm`のバイナリを含めるように`PATH`を更新してください。
>
> macOSとLinuxでは、次の内容を`~/.bash_profile`または`~/.zshrc`に追加すれば設定できます。
>
> ```shell
> export PATH=/usr/local/share/npm/bin:$PATH
> ```
>
> Windowsでは、スタートメニューを開いて「environment variables」を検索します。
> `PATH`の項目を編集して、ここに`npm`バイナリへのパスを_追加_する必要があります。
> 通常、これらは`C:\Program Files\nodejs`にあります。
> ここを`File Explorer`で開くと、`node.exe`、`npm.bat`、`npx.bat`が見つかるはずです。
>
> 開いているターミナルをすべて閉じて、新しいターミナルを開いてください。

## corepackを有効にする

このトラックに対応した、バージョン管理されたパッケージマネージャーを使うには、`corepack`を一度だけ有効にする必要があります。

```shell
corepack enable pnpm
```

## 演習の要件

お使いのOS用のExercism CLIをダウンロードするには、[こちらの手順][cli-walkthrough]に従ってください。

CLIのセットアップと設定が終わったら、最初の演習`hello-world`をダウンロードしましょう。

```shell
exercism download --exercise=hello-world --track=javascript
```

次に、各演習でテストを実行するためのツールが必要になります。
それらは、各演習のディレクトリで次のコマンドを実行するとインストールできます。

```shell
corepack pnpm install
```

このトラックはpnpmに切り替わったので、ディスク容量を気にする必要はありません。
[pnpm](https://pnpm.io/)を見てみましょう。各パッケージの各バージョンが、ディスク上にひとつしかインストールされないようにしてくれます。

> **でも、corepackとは何で、なぜこれでうまくいくのでしょうか？**
>
> JavaScriptトラックを進めるのにこの情報は必要ありませんが、いま何が起きたのかを知りたいという方は、次の段落を読んでみてください。
>
> これは、`corepack`がNode.jsに同梱されているツールだからです。上記の手順でインストールされたNode.jsに付属しています。
> これはパッケージマネージャー`pnpm`をインストールできます。システムの設定も行います。
> `corepack`コマンドは、`package.json`ファイルを探します。このファイルは_各_演習フォルダーにあります。
> そして、`packageManager`を確認し、それが`pnpm`と一致すれば、そのまま処理を続けます。必要であれば、先に`pnpm`をアップグレードします。
> このファイルには、上に挙げた`"dependencies"`も記載されていて、それらは`pnpm`によってダウンロードされ、ローカルのキャッシュに置かれます。
>
> `package.json`内のスクリプトは、ローカルキャッシュにあるバイナリを使います。テストの実行に使われるのはこれらのスクリプトで、`exercise`の説明に記載されています。
