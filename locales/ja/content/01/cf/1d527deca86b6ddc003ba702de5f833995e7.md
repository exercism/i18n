# 詳細

ほとんどのスカラーのビット演算には、パックド版があります。これらは[SIMD整数演算][simd-integers]と同じ一般的な構文に従いますが、サイズ接尾辞がありません。

| 命令 | 説明 |
|-------------|-----------------------------------|
| `pand`      | 2つの128ビット値のビット単位AND |
| `por`       | 2つの128ビット値のビット単位OR  |
| `pxor`      | 2つの128ビット値のビット単位XOR |

パックドの`NOT`は存在しないことに注意してください。ただし、ANDN演算があり、これは**デスティネーション**オペランドを補数化（すべてのビットを反転）してから、両方のオペランド間のANDを計算します。NOTとANDを組み合わせたものと考えることができます。

| 命令 | 説明 |
|-------------|-----------------------------------------------------------------|
| `pandn`     | **補数化された**デスティネーションとソースのビット単位AND |

ビット演算は、2つの異なるオペランドの同じ位置にあるビットを組み合わせるため、レーンの境界が結果を変えることはありません。だからこそ、これらの命令にはサイズ接尾辞がなく、レジスターは単一の128ビットレーンとして振る舞います。

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
この概念のすべての命令はビットを計算しますが、フラグは設定しません。パックド値を使った条件分岐については、後の概念で扱います。
~~~~

## レーンごとのシフト

シフトは、純粋なビット演算とは異なり、ビットを実際に位置をまたいで移動させるため、境界を決めるためのレーンサイズが必要です。各レーン内ではスカラーの対応する演算と同じように振る舞い、ビットが隣のレーンに渡ることはありません。

| 命令               | 説明                         |
|---------------------------|-------------------------------------|
| `psllw`、`pslld`、`psllq` | レーンごとの論理左シフト        |
| `psrlw`、`psrld`、`psrlq` | レーンごとの論理右シフト       |
| `psraw`、`psrad`          | レーンごとの算術右シフト    |

これらの命令は、サイズ接尾辞を含め、パックド整数演算の構文に従います。バイトレーンのシフトはありません。あるのはワード、ドワード、そして算術右シフトを除いたクワッドワードだけです。

パックドシフトとスカラーの対応する演算の違いの1つは、演算の名前です。

- `shl`と`shr`の代わりに、`sll`と`srl`があります。これは**s**hift **l**eft（**r**ight）**l**ogicalの頭文字です。
- `sar`の代わりに、`sra`があります。これは**s**hift **r**ight **a**rithmeticの頭文字です。

名前は違いますが、演算は同じです。

- 論理右シフトは、最上位ビットを0で埋めます。これは、2の累乗による符号なし除算に相当します。
- 算術右シフトは、最上位ビットを符号ビットの値で埋めます。これは、負の無限大に向かって丸める、2の累乗による符号付き除算に相当します。
- 左シフトは常に0で埋めます（算術左シフトが不要なのはこのためです）。

シフト量はすべてのレーンで同じです。即値か、`xmm`レジスターの下位64ビットを指定できます。

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
レーン幅より大きいシフト量は、スカラーの`shl`/`shr`ファミリーのようにラップアラウンドしません。単純に0（算術右シフトの場合は符号ビットで埋まった値）になります。
~~~~

## 浮動小数点のビット演算

各ビット演算には、浮動小数点向けの名前を持つ双子の命令もあり、パックド浮動小数点演算で見てきたのと同じ構文に従います。

| 整数の名前 | 浮動小数点の名前          |
|--------------|----------------------|
| `pand`       | `andps`、`andpd`     |
| `pandn`      | `andnps`、`andnpd`   |
| `por`        | `orps`、`orpd`       |
| `pxor`       | `xorps`、`xorpd`     |

ビット演算はビットに対して作用するため、実際には整数演算と浮動小数点演算は同じ結果を計算します。名前が異なるのには2つの理由があります。

1. 意図を明示するためです。コピーするバイトの性質に応じて`movdqa`、`movaps`、`movapd`を使い分けるのと同じです。
2. 整数演算と浮動小数点演算は、多くの場合、実行ドメインが異なります。同じ実行ドメイン内の演算は、たいていより速く並べることができます。

浮動小数点値向けのシフト演算はありません。

## 浮動小数点数のビット表現

[IEEE 754][ieee-754]の浮動小数点数は、整数とは大きく異なるビット表現を持ちます。

符号なし整数では、各ビットは一様な意味を持ちます。つまり、ビットのインデックスに対応する2の累乗を表します。整数は、セットされたビットに対応する2の累乗の合計です。ビットをシフトすると数値を2の累乗で掛けたり割ったりできるのはこのためです。セットされた各ビットのインデックスを変えているだけなのです。

符号付き整数では、ほとんどのビットは符号なし整数と同じように解釈されます。ただし、最上位ビットは特別です。これがセットされている場合は、他のビットに加算するのではなく、対応する2の累乗を減算する必要があり、その結果は負の数になります。実際には、数値の符号を変えるには、概念的には2つのステップが必要です。すべてのビットを反転し（`not`）、その結果に1を加算します（`inc`）。

浮動小数点数のビットは一様な意味を持たず、その位置に応じてまったく異なる解釈が必要です。

| フィールド    | インデックス（32ビット） | インデックス（64ビット） |
|----------|------------------|------------------|
| 符号     | 31               | 63               |
| 指数 | 30-23            | 62-52            |
| 仮数 | 22-0             | 51-0             |

得られる数値は`(-1)^sign * 1.fraction * 2^(exponent - bias)`で計算されます。バイアスは精度によって異なります。

| サイズ   | バイアス |
|--------|------|
| 32ビット | 127  |
| 64ビット | 1023 |

どちらの形式でも、数値の符号は符号ビットだけで決まります。浮動小数点数の符号を変えるには、このビットを反転するだけです（XOR演算）。絶対値を得るには、このビットをクリアするだけです（そのビットをクリアするANDです）。

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

このビット表現では、ビットをシフトしても予測可能で一様な結果にはならないことに注意してください。仮数が指数へ、指数が符号へ「あふれ出す」ことがあります。

ただし、表現の各部分を分離して操作すると便利なこともあります。

たとえば、指数のビットは、バイアスを引く前に、まず符号なしの数値として解釈する必要があります。つまり、その基になるビット表現が、対応する浮動小数点形式のある2の累乗に対応するような、32ビットまたは64ビットの整数を作り出せます。そして、この生のビット表現を使って、別の浮動小数点数を掛けたり割ったりできます。

たとえば、次のようになります。

```x86asm
mov eax, 210       ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23        ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax     ; we move the raw bits to xmm0
mulss xmm1, xmm0   ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

逆に、指数ビットがセットされ他がすべてクリアされたマスクでANDを行うことで、パックド浮動小数点数の指数を取り出せます。シフトと減算を組み合わせると、各レーンのバイアスを除いた指数が符号付き整数として得られます。

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
浮動小数点数の生のビットを操作することは、状況によっては役立ちますが、慎重に行うべきです。上の式は**正規**数だけを表しています。指数フィールドがすべて0の場合はゼロと非正規数を、すべて1の場合は無限大とNaNを表します。指数フィールドへの加算や減算が安全なのは、オーバーフローやアンダーフローがなく、入力値が正規数である場合だけです。また、`0.0`の指数フィールドに有効な`x`を加算すると、結果は`0.0 * 2^x`ではなく`2^(x - bias)`になります。
~~~~

## AVX以降

AVXでは、ここにあるすべての命令に、より広いレジスター上で`v`が付いた3オペランド形式が用意され、動作は変わりません。

```x86asm
vpand  ymm0, ymm1, ymm2 ; ymm0 = ymm1 AND ymm2, 256 bits
vxorps ymm3, ymm4, ymm5 ; ymm3 = ymm4 XOR ymm5, 256 bits
vpsrad ymm6, ymm7, 2    ; eight 32-bit lanes shifted right arithmetically
```

AVX2では、サイズ接尾辞の前に`v`を付けた可変シフトも導入されています。これはシフト量のベクターを取り、対応するレーンのシフト量に従ってシフトします。

```x86asm
vpsllvd ymm0, ymm1, ymm2  ; each 32-bit lane shifted left by its own count
vpsravd ymm3, ymm4, ymm5  ; each 32-bit lane shifted right arithmetically by its own count
```

AVX-512は、SSEが残した2つのギャップを埋めます。

- `vpsraq`がついに64ビットの算術右シフトを提供します。
- `vpternlogd`と`vpternlogq`は、**任意の**3入力ビット演算関数を1つの命令で計算します。8ビットの即値は真理値表そのものです。即値のビット`i`が、入力の組み合わせ`i`に対する出力になります。3つのオペランドに対する`pand`/`pandn`/`por`/`pxor`の連鎖はすべて、単一の`vpternlog`にまとめられます。

これらの拡張機能は、網羅性のために触れています。このトラックの演習では、SSE形式を使います。
