# 概要

[SIMD][SIMD]の概念では、パックされた浮動小数点数が登場しました。複数の数値が1つの`xmm`レジスタに格納され、レーンごとに並列して演算されます。
同じ`xmm`レジスタには、パックされた_整数_を格納することもできます。

## 構文

SIMDの浮動小数点モデルのほとんどは、そのままパック整数にも当てはまります。

- 128ビットのレジスタは、レーンに分割されます
- 命令は、同じ位置にあるレーンに対して並列に作用します
- メモリーオペランドも、同じ16バイトのアラインメント規則に従います

ただし、構文は少し異なります。

1. 命令が_パック_されたデータを対象とすることを示す、_接頭辞_の`p`。
2. 実行される演算。名前はSIMDではない方（_スカラー_とも呼ばれます）と同じです（例：`add`、`mul`など）。
3. 各レーンのサイズを示す接尾辞。

パック整数のレーンサイズは4つあり、それぞれに専用の接尾辞があります。

| レーン幅 | バイト数 | 128ビット内のレーン数 | 接尾辞 |
|------------|-------|-------------------|--------|
| バイト       | 1     | 16                | b      |
| ワード       | 2     | 8                 | w      |
| ダブルワード       | 4     | 4                 | d      |
| クアッドワード       | 8     | 2                 | q      |

たとえば、次のようになります。

| 命令 | 意味                              |
|-------------|--------------------------------------|
| `paddb`     | パック`add`、8ビットのレーン（16レーン） |
| `paddw`     | パック`add`、16ビットのレーン（8レーン） |
| `paddd`     | パック`add`、32ビットのレーン（4レーン） |
| `paddq`     | パック`add`、64ビットのレーン（2レーン） |

あるサイズのレーンを入力に取り、別のサイズを出力する命令もあります。
そうした命令も同じ一般的な規則に従いますが、サイズの接尾辞を_2つ_付けます。
1つ目が入力レーンのサイズを、2つ目が出力レーンのサイズを示します。

| 命令  | 意味                                           |
|--------------|---------------------------------------------------|
| `pmovsxwd`   | パック`movsx`、16ビットのレーンから32ビットのレーンへ |
| `pmuldq`     | パック`mul`、32ビットのレーンから64ビットのレーンへ   |

## メモリーの移動

整数の名前を持つ2つの命令が、`xmm`レジスタとメモリーの間で128ビットをコピーします。

| 命令 | 説明                                             |
|-------------|---------------------------------------------------------|
| `movdqa`    | パック整数を_アラインメント_された場所との間でコピーします   |
| `movdqu`    | パック整数を_アラインメント_されていない場所との間でコピーします |

これらの命令は`movaps`と`movups`と同じように動作します。`movdqa`はアラインメントの合っていないアドレスでフォールトを起こしますが、`movdqu`はどのようなアドレスでも受け付けます。
4つとも、128ビットを解釈せずにそのままコピーします。
整数の名前を持つ2つは、慣習として整数データと一緒に使われるだけで、必須ではありません。

~~~~exercism/note
ここでの`dq`は`double-qword`、つまり128ビット（16バイト）のことです。
~~~~

## 加算と減算

加算と減算は、命名規則に従います。

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

符号付きと符号なしで別々の形式はありません。
2の補数表現では、レーンを符号付きとして読んでも符号なしとして読んでも、加算と減算は同じビットを生み出すため、1つの命令で両方をまかなえます。
その解釈は読者に委ねられます。スカラーの`add`と`sub`の場合とまったく同じです。

これらの命令は、スカラーの対応命令と同じく、オーバーフロー時に**ラップアラウンド**します。
8ビットのレーンは値を256を法として保持するので、`paddb`で`200 + 100`を計算すると`300 - 256 = 44`となり、収まらないビットは捨てられます。

余分なビットが隣のレーンに繰り上がることはない点に注意してください。
同じレジスタを共有していても、各レーンは互いに独立して演算されます。

## 飽和加算と飽和減算

整数SIMDには、浮動小数点SIMDにはない演算が加わります。[飽和][saturation]加算と減算です。これはラップアラウンドする代わりに値を_クランプ_します。
レーンの範囲を上回る結果は、そのレーンが保持できる最大値になり、範囲を下回る結果は最小値になります。

飽和形式では、サイズの接尾辞の前に`s`（符号付き）または`us`（符号なし）を挿入します。

| 命令 | 意味                                    |
|-------------|--------------------------------------------|
| `paddsb`    | `add`、飽和、符号付き8ビットのレーン      |
| `paddusb`   | `add`、飽和、符号なし8ビットのレーン    |
| `psubsw`    | `sub`、飽和、符号付き16ビットのレーン     |
| `psubusw`   | `sub`、飽和、符号なし16ビットのレーン     |

クランプの範囲は、対応するサイズと符号の整数が表現できる範囲全体です。
バイトの場合：

- 符号なしバイトは`[0, 255]`にクランプされます。`paddusb`で`200 + 100`は`255`になり、`psubusb`で`5 - 10`は`0`になります。
- 符号付きバイトは`[-128, 127]`にクランプされます。`paddsb`で`100 + 50`は`127`になります。

飽和が重要になるのは、レーンがピクセルのチャンネルや音声サンプルのように、上限と下限のある量を保持する場合です。
ラップアラウンドでは明るすぎるピクセルが暗くなってしまいますが、クランプなら最大の明るさのまま保たれ、これが望ましい結果です。

~~~~exercism/note
飽和加算と飽和減算は、バイトとワードのレーンにだけ存在し、ダブルワードやクアッドワードにはありません。
~~~~

## 乗算

2つのNビットの値を掛けると2Nビットの積が得られますが、格納先のレーンはNビットの幅しかありません。
SIMDの演算では、積のどちらの半分を保持するかを指定してこれを解決します。下位Nビットか、上位Nビットのどちらかです。

16ビットのレーンでは、3つの命令を使います。

| 命令 | 意味                                                       |
|-------------|---------------------------------------------------------------|
| `pmullw`    | `mul`、16ビットのレーン、各積の下位16ビットを保持     |
| `pmulhw`    | `mul`、16ビットのレーン、上位16ビットを保持、符号付きオペランド   |
| `pmulhuw`   | `mul`、16ビットのレーン、上位16ビットを保持、符号なしオペランド   |

積の下位16ビットは、オペランドを符号付きとして読んでも符号なしとして読んでも同じなので、`pmullw`は1つだけです。

一方、上位16ビットは、結果が符号付きか符号なしかによって変わります。
そのため、上位半分を求める乗算には、符号付き乗算用と符号なし乗算用の別々の形式があります。

1. `pmulhw`：符号付きの乗算用です。
2. `pmulhuw`：`u`が1つ余分に付き、符号なしの乗算用です。

構文に注目してください。

1. パック整数を表す`p`。
2. 実行される演算`mul`。
3. 結果の上位（"high"）ビットを選んでいることを示す`h`。
4. 結果を符号なしとして解釈する場合（つまり符号拡張されない場合）に付く、省略可能な`u`。
5. 最後に、ワード（16ビット）演算であることを示すサイズの接尾辞`w`。

ワードのパック乗算は、上の規則にそのまま従います。
ダブルワード（32ビット）の乗算もこの規則に従いますが、下位半分を選ぶ形式しかありません。`pmulld`です。

ダブルワードの乗算には、上位ビットを選ぶ形式はありません。
ただし、乗算を_拡張_して、_偶数番目_のレーン（つまり位置0と2のレーン）の完全な64ビットの積を格納する形式ならあります。

| 命令 | 意味                                                                          |
|-------------|----------------------------------------------------------------------------------|
| `pmuludq`   | 偶数番目の32ビット要素を符号なしで乗算し、完全な64ビットの積を2つ作ります |
| `pmuldq`    | 偶数番目の32ビット要素を符号付きで乗算し、完全な64ビットの積を2つ作ります   |

構文では`dq`を使い、符号なし乗算の場合はその前に`u`が付くことがあります。
これは、これらの命令が`dword`のレーンを入力として受け取り、`qword`のレーンを出力するためです。

## 除算

パック整数の除算はありません。
除算が必要なコードは、値を浮動小数点数に変換してから除算し、再び元に戻します。

## 整数の拡張

`movsx`と`movzx`には、パック版の相当する命令があります。
入力のレーンサイズが出力と異なる命令について述べたのと同じ構文に従います。

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

レーンの数は、大きい方（出力側）の幅で決まる点に注意してください。
命令は、その数だけのレーンを入力の下位部分から読み取ります。
これは、単精度と倍精度の浮動小数点数の間のパック`cvt`命令ですでに見たのと同じ意味論です。

## 整数と浮動小数点数の変換

32ビットの符号付き整数と浮動小数点数のレーンとの間で変換する命令があります。
`cvt`と`cvtt`命令の通常の構文に従いますが、パック整数は`si`の代わりに`dq`で表します。

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
パック整数を表すのに`pi`を使う命令は、レガシーな`mmx`レジスタに書き込み、x86-64では事実上非推奨です。
`xmm`レジスタを使う`dq`形式のほうを使ってください。
~~~~

浮動小数点数と整数の間のスカラー変換について述べた注意は、ここでも同じように当てはまります。
浮動小数点数は、MXCSRと呼ばれる特別なレジスタに従って丸められます。このモードは、関数に入った時点で分かっていると決めつけることはできません。
結果を常に切り捨てる`cvtt`形式（`t`が1つ余分に付きます）もあります。

変換の前に、`round`を使ってパック浮動小数点数の値を既知の状態にしておくこともできます。
丸めの制御値はスカラーの`round`と同じで、パック浮動小数点数の場合も構文は同じです。

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
