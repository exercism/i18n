# はじめに

多くのプログラミング言語には、`null`や`none`のように、存在しない値を表す仕組みがあります。Rは大量の（しばしば乱雑な）データを扱えるように設計されているため、何もないことを表す形が複数用意されています。

全体的な狙いは、欠損している値や疑わしい値に出会った時点で印を付け、例外を発生させずに処理を続けることです。

## NULL

値が本当に存在しない場合は、`NULL`で表します。これはおそらく、CやPythonのやり方に最も近いものです。

```R
v <- c() # zero-length vector
v
#> NULL
is.null(v)
#> [1] TRUE
```

多くの場面では、`NULL`の値は単純に無視されます。

```R
c(2, 3, NULL, 5)
#> [1] 2 3 5
```

## NA

値は存在するものの、それが何なのかわからない状況では、`NA`を使います。たとえば、道路を走る車を数えているとき、人間の観測者が病気で休んだり、自動センサーが故障したりすることがありますが、交通は流れ続けます。

```R
v <- c(1, 2, NA, 4, 5)
v
#> [1]  1  2 NA 4  5
is.na(v) # test for data gaps
#> [1] FALSE FALSE  TRUE FALSE FALSE
```

つまり`NA`はプレースホルダーで、これをどう扱うべきかを人間が判断する必要があると警告してくれます。

## NaN

「Not a Number」の略である`NaN`は、数値が期待される場面で計算上の問題が起きたことを示します。

```R
n <- c(0, 2, 4)
d <- c(0, 1, 2)
n / d
#> [1] NaN   2   2  # 0/0 is mathematically undefined
is.nan(n / d)
#> [1]  TRUE FALSE FALSE
```

これが「無効な」計算の唯一の結果というわけではありません。ゼロで割ると、分子が0でなければ、エラーを発生させずに`Inf`または`-Inf`が返ります。

```R
1 / 0
#> [1] Inf
```

## 空のベクトル

意外かもしれませんが、Rには空かどうかを確認する標準的な方法がありません。

空のベクトルを生成することさえ、それほど自明ではありません。前のセクションで見たように、引数なしの`c()`はベクトルではなく`NULL`を返します。

```R
is.vector(c())
#> [1] FALSE
```

`logical()`や`integer()`のような関数は、希望する長さを指定する引数を取り、その長さは0にできます。

```R
z <- logical(0)
is.vector(z)
#> [1] TRUE
length(z)
#> [1] 0
```

[ベクトルの概念][concept-vectors]で説明されているように、ベクトルを生成してからすべての要素を削除することもできます。こうすると、適切な型の長さ0のベクトルができます。

```R
v <- 5
v[-1]  # delete the first element
#> numeric(0)
```

[concept-vectors]: https://exercism.org/tracks/r/concepts/vectors
