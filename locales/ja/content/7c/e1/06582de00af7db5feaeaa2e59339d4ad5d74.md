# はじめに

`if/else`式を使って条件付きのロジックを実行できますが、Haskellにはもっと強力な方法があります。それが[パターンマッチング][pattern-matching]です。パターンマッチングを使うと、ある値を1つ以上の_パターン_と照合してテストできます。そうしたパターンの例が_定数パターン_で、これは値を定数（`1`や`"hello"`など）と照合します。

関数を定義するときは、パターンごとに異なる関数本体を定義できます。こうすると、シンプルで読みやすい、すっきりしたコードになります。パターンマッチングは、数値、文字、配列、タプルなど、どんなデータ型に対しても行えます。

たとえば、整数（`Int`）を受け取って_0_に_1_だけ近づける、ささいな関数は次のように書けます。

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero 1 = 0
```

パターンマッチングの真価は、他のパターンと組み合わせたときに発揮されます。たとえば_変数パターン_です。

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero n = n - 1
```

上の例では、_0_以外のすべての入力が同じように扱われるため、負の数に対しては正しくない結果になります。
これは、`|`記号で表される_ガード_と呼ばれる条件付きパターンを使えば解決できます。

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
```

上の例では、すべての入力に対応するパターンがあるわけではありません。
コンパイラーはこれを検出して警告を出力します。
これはHaskellのとても便利な機能で、実行時エラーを避けるためにすべての経路が網羅されているかを確認するのに役立ちます。
これは_網羅性チェック_と呼ばれます。
警告を解決するには、すべてのケースを処理する必要があります。
_ガード_の中では、残りのすべてのパターンを受け止めるために、`True`の糖衣構文として`otherwise`という式を使えます。

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
    | otherwise = 0
```

パターンマッチングは、上から下へ順に値を各パターンと照合し、一致するパターンを見つけると、そのパターンに対応する処理を実行します。
**パターンの順序は重要です！**
