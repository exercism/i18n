# はじめに

## JSON

JSON（JavaScript Object Notation）は、人間が読めるデータおよびファイル形式で、データの交換、とりわけWebアプリケーションでよく使われます。
そのため、Elm言語の中で特別な位置を占めているのも不思議ではありません。

Elmには、JSONデータを解析したり書き出したりするためのコアモジュール`Json.Decode`と`Json.Encode`が用意されています。
JSONデコーダーは、どのような型のデータを期待するのか、そのデータをどのデータ構造に対応させるのかを_宣言_する方法です。

モジュールからいくつかのエイリアスと型をインポートしましょう。

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

`Decode.decodeString : Decoder a -> String -> Result Error a`をデコーダーとJSON文字列と一緒に使うと、文字列がデコーダーの仕様に適合していれば成功し、そうでなければ失敗します。
デコーダーを定義するときに生のJSONデータを調べる方法はありません。これは命令型言語から来た人には珍しく感じられるかもしれません。

## 基本的なデータ型のデコーダー

JSONには、少数のコアなデータ型があります。

- 文字列: 二重引用符で表します `"hello world"`
- 真偽値: `true`か`false`のいずれか
- 数値: `34`や`0.12`など
- Null: データが存在しないことを示す`null`

これらのそれぞれに、`Decode`の関数が対応しています。

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

`Decode.null`を使うと、引数として任意の値（`()`や`Nothing`、その他プログラムに適したものなど）を要求することで、プログラム内で`null`をどう表現するかを自分で決められることに注意してください。

## デコーダーを組み合わせる

JSONには、コアなデータ型をまとめるための2つのデータ構造も定義されています。

- 配列: 他のデータ型を集めたもの `[0, null, "none", []]`
- オブジェクト: キーと値のペアを集めたもの `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode`には、これらをデコードする関数も用意されています。

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

これらの関数`Decode.list : Decoder a -> Decoder (List a)`と`Decode.dict : Decoder a -> Decoder (Dict String a)`はそれぞれ、引数としてデコーダーを取ります。そのデコーダーは、データ構造の要素を1つひとつデコードすることが期待されます。
引数のデコーダーが配列やオブジェクトの値のいずれかの要素のデコードに失敗すると、デコーダー全体が失敗します。これはよくあるパターンです。

単純なデコーダーを組み合わせて、より複雑なデコーダーを作ることが、このテクニックの中心となる考え方です。
ここからは、実例を通して、現実世界のどんなに複雑なデータでもデコードできるデコーダーを組み立てるために使える、さらにいくつかの関数を紹介します。

## GeoJSON

複雑なJSONデータを解析するために基本のデコーダーを組み合わせる練習として、GeoJSONデータ（の一部）を解析するデコーダーを作ってみましょう。
GeoJSONは、JSONをベースにした専用のデータ形式で、場所や経路、領域といった地理的な特徴を表すために使われます。これらの特徴は、2次元または3次元の地理座標と、その他のプロパティで指定されます。

### ジオメトリオブジェクト

GeoJSONのジオメトリオブジェクトは、文字列の値を持つ`type`フィールド（取りうる値は7種類あります）と、地理座標を持つ`coordinates`フィールド（座標はtypeに応じた構造でまとめられます）を含むオブジェクトです。
たとえば、次のようになります。

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

または

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

ジオメトリオブジェクトは、Elmでは次の型で表せます。

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

あるフィールドの値を取り出すには、`Decode.field : String -> Decoder a -> Decoder a`を使えます。これはオブジェクトの特定のキーの値をデコードします。

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

デコーダーが正常に解析した値を変換するには、`Decode.map : (a -> value) -> Decoder a -> Decoder value`を使えます。あるいはその兄弟たち、`Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value`から`Decode.map8`までのいずれかです。

ここでは、`type`フィールドの値に応じて、どの座標デコーダーを使うかを決めたいところです。これは`Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b`と、その仲間である`Decode.succeed : a -> Decoder a`、`Decode.fail : String -> Decoder a`の出番です。

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

ここで、`Decode.andThen`を使って座標を検証することもできることに触れておきます（座標が2つ組や3つ組になっているか、座標の値が地理的に妥当かを確認できます）。

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### フィーチャーオブジェクト

GeoJSONのフィーチャーオブジェクトは、空間的に区切られた何かを表します。`"Feature"`という値を持つ`type`フィールド、ジオメトリオブジェクトまたは`null`を持つ`geometry`フィールド、任意のJSONオブジェクトまたは`null`を持つ`properties`フィールド、そして省略可能でJSONの文字列または数値の値を持つ`id`フィールドがあります。

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

または

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

まず`id`フィールドから見ていきましょう。
このフィールドが存在する場合は、文字列か数値のどちらも受け入れる必要があります。そこで、値用のカスタム型を導入するか、常に文字列として保存するかのどちらかができます。

2つのデコーダーのどちらかを選ぶには、`Decode.oneOf : List (Decoder a) -> Decoder a`を使えます。

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

フィールドが省略可能であることを表すには、同じテクニックを使えます。

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

ただし、代わりに`Decode.maybe : Decoder a -> Decoder (Maybe a)`を使えます。

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

`decodeMaybeFeatureId`（あるいは`Decode.maybe`で包んだ任意のデコーダー）は、常に`Ok Nothing`へフォールバックできるため必ず成功することに注意してください。ただし、これを使うデコーダーが失敗する可能性はあります。

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

次に、`geometry`フィールドに注目しましょう。このフィールドはジオメトリオブジェクトか`null`のどちらかです。
ここでも`Decode.oneOf`を使えますが、もっと良い選択肢があります。`Decode.nullable : Decoder a -> Decoder (Maybe a)`です。

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe`と`Decode.nullable`は同じシグネチャを持ちますが、動作は異なります。`Decode.nullable`の`OK Nothing`という結果は、JSONの特定の値`null`からのみ生じるからです。

最後に、`properties`フィールドは任意のJSONオブジェクトまたは`null`を含むことができ、これには`Decode.value : Decoder Value`が適しています。

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

`Value`は不透明な型なので、その中身を簡単に調べることはできません。
これを使うには、そのためのデコーダーを書いて`Decode.decodeValue : Decoder a -> Value -> Result Error a`で実行するか、ポートを通してJavaScriptに直接送るかのどちらかです。

これでフィーチャーオブジェクトを解析する準備が整いました。

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## JSONエンコーダー

エンコーダーを使うと、`Encode.encode : Int -> Value -> String`関数でElmの値から有効なJSONを書き出せます。
最初の引数は最終結果のインデントの量を指定し、2番目の引数は書き出すJSONの値です。

`Value`は、`Decode.value`から得るか、いずれかのエンコーダーから生成できます。

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

また、`Encode.object : List ( String, Value ) -> Value`でも同様です。

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

先ほど定義したGeoJSONのデコーダーに対応するエンコーダーを定義しましょう。

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

一般に、デコーダーとエンコーダーのペアの良いテストは、`elmValue |> encoder |> decoder == elmValue`であることを確認することです。
