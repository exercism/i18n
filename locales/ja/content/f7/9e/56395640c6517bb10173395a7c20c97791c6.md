# ワークフロー

GitHub Actionsでは、_ワークフロー_という概念を使います。ワークフローとは、特定のイベント（たとえばコミットのプッシュ）が起きたときに自動で実行されるスクリプトです。

GitHub Actionsの各ワークフローは、`.github/workflows`ディレクトリにある`.yml`ファイルで定義します。
ワークフローについて詳しくは、次のドキュメントを参照してください。

- [ワークフローの構文](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions)
- [ワークフローを実行するタイミングを選ぶ](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow)
- [ワークフローを実行する場所を選ぶ](https://docs.github.com/en/actions/writing-workflows/choosing-where-your-workflow-runs)
- [ワークフローで行うことを選ぶ](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does)
- [ワークフローの作成](https://docs.github.com/en/actions/writing-workflows)
- [ベストプラクティス](/docs/building/github/gha-best-practices)

## 共有ワークフロー

一部のワークフローは、複数のリポジトリで共有されています。

```exercism/caution
共有ワークフローは（[org-wide-filesリポジトリ](https://github.com/exercism/org-wide-files/)から）自動的に同期されます。
そのため、その中身を手動で変更しないでください。
```

### 一般的なワークフロー

- [ラベルの同期](/docs/building/tracks/ci/workflows/sync-labels)：リポジトリのラベルをファイルから同期します

### トラック固有のワークフロー

- [configlet](/docs/building/tracks/ci/workflows/configlet)：トラックの（設定）ファイルが、構文的にも意味的にも正しく構造化されているかをチェックします
- [重要なファイルが変更されていないか](/docs/building/tracks/ci/workflows/no-important-files-changed)：既存の解答の再テストにつながるプルリクエストにコメントします
- [Test](/docs/building/tracks/new/setup-continuous-integration#h-test-workflow)：トラックの演習を検証します

### ツール固有のワークフロー

- [Deploy](/docs/building/tracks/ci/workflows/deploy)：トラックのツールのDockerイメージをDocker HubとECRにデプロイします

### オプションのワークフロー

トラックが任意で導入できるワークフローもあります。

- [コミュニティからのコントリビューションの一時停止](/docs/building/tracks/ci/workflows/pause-community-contributions)：ExercismのGitHub組織のメンバーではないユーザーが作成した新しいissueやPRに自動でコメントします

## カスタムワークフロー

メンテナーは、自分のリポジトリにカスタムワークフローを自由に追加できます。
たとえば、次のようなものがあります。

- [シェルスクリプトのリント](https://github.com/exercism/configlet/blob/3baa09608c8ac327315c887608c13a68ae8ac359/.github/workflows/shellcheck.yml)
- [プルリクエストへの自動コメント](https://github.com/exercism/elixir/blob/b737f80cc93fcfdec6c53acb7361819834782470/.github/workflows/pr-comment.yml)
- など
