# 概要

## 比較演算子

Rには、他の多くの言語と同じ演算子がそろっています。

```R
1 == 2 # FALSE
1 != 2 # TRUE
1 < 2 # TRUE
1 > 2 # FALSE
1 <= 2 # TRUE
1 >= 2 # FALSE
```

## 分岐

if-then-elseの基本的な形は次のとおりです。

```R
if (x > 10) {
    y <- "big"
} else if (x > 2) {
    y <- "medium"
} else {
    y <- "tiny"
}
```

この場合、条件を囲む丸括弧（`( )`）と、本体を囲む波括弧（`{ }`）の両方が必要です。

単純な`if`文は短く書けます。

```R
if (x == 0) return("success")
```

## 条件式でベクトルを使う

この先の[`vector-filtering`][concept-vector-filtering]コンセプトを見据えておきましょう。括弧（`()`）の中の条件式は、単一の`TRUE`/`FALSE`に評価される必要があります。

比較にベクトルを含めると、たいていは真偽値のベクトルが返るので、[`all()`][ref-all]（すべての値がTRUEか？）や[`any()`][ref-any]（少なくとも1つの値がTRUEか？）のような集約関数で包む必要があります。

```R
numbers <- c(4,5,7,9,10,11)
numbers %% 3 == 0 # gives vector of booleans
#> [1] FALSE FALSE FALSE  TRUE FALSE FALSE

# use any() to get a single TRUE/FALSE
if (any(numbers %% 3 == 0)) print("1 or more numbers are divisible by 3")
#> [1] "1 or more numbers are divisible by 3"
```

## [`ifelse`][ref-ifelse]関数

結果がtrueかfalseのどちらかにしかならないのであれば、代わりのif-elseの形が役立つことがあります。

```R
y <- ifelse(x > 8, "big", "small")

# Don't mix result types:
z <- ifelse(x > 100, 100, "small") # numeric or string result? Expect problems!
```

`ifelse()`はちょうど3つの入力を取ります。

1. 真偽値の条件
2. `TRUE`のときの値
3. `FALSE`のときの値。

ベクトルを入力してもよく、その場合はベクトルが出力されます。
この場合、どちらの分岐も同じ型のデータ（数値、文字列、論理値など）になるようにしてください。
これについては、[`vector-functions`][concept-vector-functions]コンセプトで扱います。

2つの結果（上の例では`"big", "small"`）は、それぞれ単一の値にしてください。
残念ながら、ここにより長いベクトルを渡すと、警告メッセージも出ないまま、Rが紛らわしく予想外の動作をすることがあります。

### 背景

R言語のメンテナーは、できるだけ破壊的変更を避けるという方針を取っています。
これは、[CRAN][web-cran]にある膨大な数のサードパーティパッケージを維持するのに役立ちますが、base Rを現代的なプログラミングの考え方で更新する余地を狭めています。

近年、Rの機能を拡張し、ときに置き換えるパッケージがいくつか公開されています。これらは、元々のRの設計の長所と短所について何十年にもわたる経験に基づいています。

これらのパッケージは、[`tidyverse`][web-tidyverse]というコレクションを構成しています。
これらは2023年にExercismのテストランナーに追加され、演習で使えるようになりました。

Rトラックは、tidyverseが追加されるより数年早くからあるので、多くのコミュニティの解答がベース言語にこだわっていることに気づくかもしれません。

### [`dplyr`][ref-dplyr]パッケージ

`dplyr`は、主にデータフレームを操作するためのものです（コースの後半で扱います）。

コードの先頭に`library(dplyr)`と書くか、コレクション全体を追加する`library(tidyverse)`を使います。
名前のマスクに関する警告メッセージが表示されることがありますが、めったに問題にはなりません。

今回のコンセプトでは、[`if_else`][ref-if_else]関数が注目に値します。
これは、base Rの[`ifelse`][ref-ifelse]とほとんど同じです。

```R
library(dplyr) # warnings not shown

x <- 10
if_else(x > 8, "big", "small")
#> [1] "big"
```

主な違いは、`if_else`が4番目の入力をオプションで取れることです。これは、Rで[`NA`][ref-na]として表される[欠損][concept-nothingness]値のためです。

```R
xs <- c(3, NA, 10, NA, 4)  # a 5-element vector
xs
#> [1]  3 NA 10 NA  4
if_else(xs > 8, "big", "small", "missing")
#> [1] "small"   "missing" "big"     "missing" "small" 

# contrast:
ifelse(xs > 8, "big", "small")
#> [1] "small" NA      "big"   NA      "small"
```

また、`if_else`のほうが古い`ifelse`よりエラーメッセージがはるかに親切だと感じるかもしれません。

`dplyr`ライブラリを読み込むと、[`between()`][ref-between]関数も使えるようになります。

Rでは比較をつなげて書くことができないので、`1 <= x <= 5`と書くとエラーメッセージが出ます。
`dplyr`を読み込んでいれば、`between(x, 1, 5)`は`x >= 1 & x <= 5`と同じで、より読みやすいかもしれません。
下限も上限も、その値を含みます。
