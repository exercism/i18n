## <a name="virtual-environments"></a>仮想環境

Pythonの仮想環境は、軽量なランタイムとパッケージの分離を提供します。
特定の環境ディレクトリの中にインストールしたPythonパッケージをまとめておくことで、プロジェクトを整理するのに役立ちます。
環境ごとに、Pythonランタイムの異なるバージョンと、プロジェクトやライブラリの依存関係を一緒に保持できます。
これは、あるプロジェクトのためにライブラリをアップグレードしたことで別のプロジェクトの依存関係が「壊れる」ことによるバグや非互換性を避けるのに役立ちます。

現在、多くの*仮想環境*や*仮想環境に似た*ツールが使われており、仮想環境の代わりに[インラインスクリプトメタデータ][PEP723]、[開発コンテナー][dev containers]、[Docker][docker]を使おうという動きが高まっています。
さまざまな戦略を試して、自分の開発スタイルやプロジェクトのニーズに合うものを見つけることが大切です。
ここで紹介する戦略が万能だったり、唯一の選択肢だったりすると考えないでください。
ここで取り上げていないツールのより一般的な概要については、[Bas Nijholtによるこのブログ記事][bas nihholt]をチェックして、好奇心を持ち続けてください。


ここでは、3つの主要な*仮想環境*ツールを取り上げます。Python標準ライブラリの[`venv`][venv]、サードパーティの[`conda env`][condaenv]（[`conda`][conda]パッケージマネージャーと、_通常は_Anaconda Pythonディストリビューションを使います）、そしてサードパーティの`pip` + `venv`の代替である[`uv`][uv]です。
どれも、使い方もインストールもかなり簡単です。

さらに、[`PyEnv`][pyenv]、[`Poetry`][poetry]、[virtualenvwrapper][virtualenvwrapper]は、同じマシン上で複数のバージョンのPythonと複数のPython環境を管理するのに役立つツールです。

### <a name="creating-a-virtual-environment-with-venv"></a>`venv`で仮想環境を作成する

`venv`を使って仮想環境を作成するには、環境を保存したいディレクトリに`cd`します。
これは、プロジェクトのコードとは**別の**ディレクトリであるべきで、ソース管理に**チェックインしない**ディレクトリにします。
次に、この特定の**環境**を保存したいフォルダーの名前を付けて`venv`コマンドを実行します。
一般的な慣習では、そのフォルダーを`<project-name-here>_venv`と呼びます。

**Windows**

```powershell
PS C:\Users\foobar> py -m venv {name_of_virtualenv}
```
仮想環境を有効化するには、次のコマンドを実行します。

```powershell
PS> .\{name_of_virtual_env}\Scripts\activate.bat
(venv) PS> _
```

<br>

**Linux/MacOS**

```bash
$ python3 -m venv {name_of_virtualenv}
created virtual environment ... in 8568ms
```

仮想環境を有効化するには、次のコマンドを実行します。

```bash
$ source {name_of_virtual_env}/bin/activate
(venv) $ _
```

`venv`を有効化すると、環境の「内側」でパッケージをインストールするための`pip`コマンドを実行できます。
インストールされたパッケージは、`venv`のPythonのバージョンに関連付けられ、`{name_of_virtual_env}/Lib`の中に配置されます。

仮想環境の_無効化_は、`activate`と同じディレクトリにある`deactivate`スクリプトを呼び出すことで行えます。

<br>

### <a name="creating-a-virtual-environment-using-conda"></a>`conda`を使って仮想環境を作成する

*最新の`conda`バージョンは[miniconda][miniconda]からインストールできます。*
この[`conda`チートシート][conda-cheatsheet]はとても役立ちます。 [`conda`ドキュメント][conda-docs]も同様です。

もともとは「科学的なPython」として人気のある[`Anaconda distribution`][anaconda]のためのPythonパッケージマネージャーとして作られた`conda`は、後に一般化され拡張されました。
Conda環境は`venv`に似ていますが、大きな違いは、condaはPythonに加えて多くのプログラミング言語の仮想環境を作成し、パッケージをインストールできることです。

Condaがサポートする言語には、`R`、`JavaScript`、`Ruby`、`Fortran`、`C/C++`、`Scala`、`Java`などがあります。
condaとvenvのコマンドの比較については、condaの[コマンドリファレンス][conda command ref]を参照してください。

<br>

### <a name="uv">UV

uvでプロジェクトを扱う: [uv][uv-docs]

`uv`は、[Rust][rust programming language]で書かれた[Astral][astral]製の、Pythonのパッケージおよびプロジェクト管理ツールです。
`pip`、`venv`、`poetry`、その他のPythonのパッケージ／依存関係管理ツールを置き換えるために設計されました。
`Conda`や`Mamba`とは違い、uvはPythonだけに特化しています。ただしuvは、Fortranなど他の言語で書かれたPython拡張モジュールのビルドには対応しています。
Astralはまた、人気のある[Ruff][ruff]リンターと、Pythonの型ヒントのための静的型チェッカー[TY][ty]の開発元でもあり、どちらもRustで書かれています。


ここで詳しく説明するよりも、インストールとセットアップについては[UVドキュメント][uv documentation]が最良の情報源です。

### <a name="virtual-environment-wrapper">仮想環境ラッパー

ドキュメントと背景: [virtualenvwrapper][virtualenvwrapper]。

`virtualenvwrapper`パッケージは`venv`の上で動作し、すべての仮想環境を1か所で管理します。
`lsvirtualenv`（_環境を一覧表示する_）や`mkvirtualenv`（_環境を作成する_）のようなLinux風のコマンドで、環境の作成、コピー、削除、切り替えができます。
また、拡張機能を使って追加の管理ツールを追加することもできます。
[このチュートリアル][venv wrapper tutorial]を使って、ツールの独自の拡張機能を作成することもできます。

<br>

### <a name="pyenv"></a>PyEnv

`pyenv`は、人気のある`rbenv`／`ruby-build`ツールをPython用に改変したPythonフォークです。
本質的には、グローバルおよびユーザーごとの両方の単位でPythonのバージョンを設定できるようにする、スクリプトとシムの集合です。
一つのことをうまくこなす、単一目的で控えめなツールというUnixの伝統に従おうとしています。

`pyenv`と`pyenv`のドキュメントは[GitHub][pyenv on github]にあります。

### <a name="visual-studio-code"></a>Visual Studio Code

[Visual Studio Code（VS Code）][vscode]は、Microsoftが作った無料のコードエディターです。
[仮想環境／conda環境][virtual environments in vscode]と、[`docker`][docker in vscode]（_[dockerプラグイン][vs code docker plugin]経由_）の両方をしっかりサポートしており、[テスト][python testing in vscode]、[リンティング][linting python in vscode]、[フォーマット][formatting python in vscode]、[Web開発][python web dev in vscode]のためのさまざまなプラグインで拡張できます。

#### <a name="python-for-vs-code"></a>VS Code用のPython

_拡張機能ID: ms-python.python_

![VS CodeのPython拡張機能のヘッダー](https://raw.githubusercontent.com/exercism/python/main/docs/img/VSCode-EXT-Python-Header.png)

[MicrosoftのPython拡張機能][MS Python extension]は、VS Code向けのMicrosoft公式Python拡張機能で、インストールを強くおすすめします。
環境管理、テスト管理、リンティング、デバッグなど、幅広い機能を備えています。
[最新リリース][vs code python latest release]の時点では、MS Python拡張機能をインストールすると、[pylance][vs code pylance]（_Pythonコードのリンティングと検証のための人気パッケージ_）と、[jupyter][vs code jupyter]（_Jupyter Notebookを扱うため_）もダウンロードされます。

- セットアップのチュートリアルは[こちら][python extension setup tutorial]にあり、[設定リファレンス][vs code python settings reference]もとても役立ちます。
- Pythonのバージョンの設定や仮想環境の扱い方については、[こちら][virtual environments in vscode]をご覧ください。
- VS Codeでunittestとpytestを設定して扱う方法については、[こちら][python testing in vscode]をご覧ください。

### <a name="pycharm"></a>PyCharm

[PyCharm][pycharm download]は、[JetBrains][jetbrains]が作った`IDE`（_統合開発環境_）です。
Pythonのために作られており、プロの間で人気があります。
VS Codeと同様に、有料・無料のさまざまなプラグイン、テーマ、フォーマッターで拡張できます。
有料版では、[Django開発][pycharm django dev]、[Docker開発][pycharm docker]、[データベース連携][pycharm database tools]もサポートしています。

- Pythonのバージョンの設定方法については、[Pythonインタープリターの設定][pycharm interpreter config]と[仮想環境の設定][pycharm config venv]にあります。

<details>
    <summary>PyCharmとPytest</summary>

  - PyCharmでpytestを設定する手順は[こちら][pycharm pytest docs]にあります。
  - PyCharmはデフォルトで`unittest`を使うので、PyCharmで使っている環境に`pytest`をインストールし（_上記のインタープリターと環境のドキュメントを参照_）、PyCharmにその場所を指定する必要があります。
  - GUIから直接[テストを実行する][pycharm gui running tests]のはとても簡単ですが、好みに合わせて設定できるよう、基になる[pytestパラメーター](TESTS.md#extra-arguments)をよく確認するのを忘れないでください。
  - PyCharmでテストを実行しデバッグするための一般的なドキュメントは[こちら][pycharm run tests]にあります。

</details>

- 追加のデバッグツールとガイダンスは[こちら][pycharm debugging tools]にあります。
  -  **警告**:  `pytest`の`coverage`プラグインはPyCharmのデバッガーを壊します。
     詳しくは[実行／デバッグ構成: pytest][pycharm debug configuration]を参照してください。

### <a name="spyder-ide">Spyder IDE

[Spyder][spyder-ide]は、科学コミュニティ向けに作られた、クロスプラットフォームの無料かつオープンソースのPython IDEです。
通常はAnacondaのPythonディストリビューションに含まれていますが、[単体でインストール][spyder standalone installers]して、どのバージョンのPythonでも使えます。
最大限の柔軟性を確保し、パッケージの競合が起きないようにするために、単体でのインストールをおすすめします。

Spyderは`venv`と`conda`の環境を完全にサポートしています。
統合された[IPython][ipython]対話型ターミナル、対話型デバッガー、エディター内でのグラフ作成とデータ探索のための豊富なサポートを備えています。
追加のコード補完とリンティングは[kite][kite]によって提供されます。
[Jupyter Notebook][spyder notebook plugin]や[テストツール][spyder unittest plugin]との連携は、コミュニティが開発したプラグインによって提供されます。
Spyder APIを使って、[独自のプラグイン][writing spyder plugins]を書くこともできます。

### <a name="vim"></a>Vim

[Vim][vimdotorg]は、Unix標準の`vi`テキストエディターの無料の「改良版」です。
さまざまなオペレーティングシステムやLinux／Unix系で利用できます。
優れた[インストールとセットアップのガイド][vim setup at real python]がReal Pythonにあり、便利なチートシートが[vimsheet][vim cheat sheet]、[glump][glump vim cheatsheet]、[rtorr][rtorr vim cheat sheet]にあります。


`vim`でPythonコードを編集するのは自分には合わないと判断したとしても、基本的なコマンドのセットに慣れておくことをおすすめします。
`vim`や`vi`は、LinuxやUnixのディストリビューションで「基本」または「デフォルト」のテキストエディターであることが多く、そうしたシステムでは`git`のコミットメッセージ（_ほかにもいろいろありますが_）のデフォルトエディターです。
*nixシステムで、`vi`しか使えない状態で設定ファイルを編集しなければならなくなる可能性は十分にあります。ですから、[vimを終了する][how do I quit vim]方法を知っておくことは、（_少なくとも_）良い自己防衛になります。

<br>
