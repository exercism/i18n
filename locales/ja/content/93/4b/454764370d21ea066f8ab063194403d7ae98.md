# イミュータブルクラス

`SCOREBOARD`は変化するものです。1つのスコアボードに2つの名前を付けると、どちらも同じスコアを見ることになります。ボードは1つだけで、どちらの名前もそれを指しているからです。

方位はそうではありません。`350 degrees`は別の何かになるのではなく、ただ*そこにある*だけです。数値も文字列もそうであり、自分で作ったクラスも同じようにできます。

## イミュータブル

```sather
immutable class BEARING is

   readonly attr degrees : INT;

end; -- class BEARING
```

2つの単語がすべてを変えます。イミュータブルクラスのオブジェクトは**値**であり、何かを指しているものではありません。

- 代入や受け渡しのときにコピーされるので、ほかの誰かがあなたの値を変えることはできません。
- voidになることはありません。
- 属性に代入することもできません。

## 新しいものを作って変更する

`degrees := 90`は許されないので、`attr`は別のものを与えてくれます。新しい値を受け取り、それを変更した**新しいオブジェクト**を返すルーチンです。

```sather
   b ::= b.degrees(90);      -- not b.degrees := 90
```

元のオブジェクトはそのままです。これがこの書き方のすべてであり、`create`もこのとおりに書きます。

```sather
   create(d : INT) : SAME is
      b : SAME;                     -- starts with everything at nought
      return b.degrees(d);
   end;
```

ここに`new`はありません。イミュータブルオブジェクトは常に存在するので、`b : SAME`はすでに1つのオブジェクトであり、すべての属性は空の値になっています。

したがって、方位を「変更する」ルーチンは、新しい方位を返します。

```sather
   turned(by : INT) : SAME is
      return #BEARING(degrees + by);
   end;
```

## 比較

値は、どのオブジェクトであるかではなく、何を保持しているかで比較されます。ただし、その方法は自分で示さなければなりません。`is_eq`を書けば、`=`がそれを使うようになります。

```sather
   is_eq(other : SAME) : BOOL is
      return degrees = other.degrees;
   end;
```

これがなければ、2つの方位に対する`=`はコンパイルできません。

## どちらを選ぶか

そのものが同一性を持たず、そのどの部分も理にかなった形では変化しないときは、イミュータブルクラスを使いましょう。方位、点、日付、長さなどです。逆に、そのものが特定の1つのもので、そこにいろいろな出来事が起こる場合は、通常のクラスを使いましょう。スコアボード、ハーネス、ファイルなどです。

判断の基準は、「同じ」が「等しい」という意味なのか、「まったく同一のもの」という意味なのかです。
