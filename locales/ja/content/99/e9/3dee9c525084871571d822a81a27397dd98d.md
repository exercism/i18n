# 説明

海賊が、隠れ入り江の海図をたどるルートを計画しています。海図は入り江の名前をキーにしたハッシュテーブルで、それぞれの値は、その入り江から直接たどり着ける入り江の配列です。

## 1. 潮のキューを空にする

`tide-queue`を定義します。項目の配列を受け取り、それぞれを（順番に）新しい両端キューにプッシュし、そのあとすべてポップして、元の順序を保った配列に戻します。これがFIFOの形です。後ろにプッシュし、前からポップします。

```factor
{ "alpha" "bravo" "charlie" } tide-queue .
! => { "alpha" "bravo" "charlie" }
```

## 2. 到達できる入り江

`coves-reachable`を定義します。開始地点の入り江と海図を受け取り、`start`から到達できるすべての入り江のハッシュセットを返します。`start`自身も含みます。

```factor
"Skull Bay" H{
    { "Skull Bay"   { "Hidden Cove" } }
    { "Hidden Cove" { "Reef Point"  } }
    { "Reef Point"  { } }
} coves-reachable .
! => HS{ "Skull Bay" "Hidden Cove" "Reef Point" }
```

BFSのフロンティアには`<dlist>`を、訪問済み集合には`HS{ }`を使います。

## 3. ホップ数

`hop-count`を定義します。開始地点の入り江、目的の入り江、海図を受け取り、それらの間の最小ホップ数を返します。目的の入り江に到達できない場合は`f`を返します。

```factor
"Skull Bay" "Hidden Cove"
H{
    { "Skull Bay"   { "Hidden Cove" } }
    { "Hidden Cove" { } }
} hop-count .
! => 1
```

両端キューには、それぞれの入り江を、開始地点からの距離と組にして持たせます（2要素の配列でかまいません）。

## 4. 金貨の数

スタブでは`gold-count`が`:`で宣言されています。これを`MEMO:`（`:`ではありません）に変えて、各入り江の結果が一度だけ計算されてキャッシュされるようにします。入り江の金貨は、この演習が用意している`gold-distribution`定数から調べます。分布にない入り江の金貨は0です。

```factor
"Smuggler's Hollow" gold-count .   ! => 200
"Davy Jones' Locker" gold-count .  ! => 0
```

## 5. 宝物のルート

`treasure-route`を定義します。開始地点の入り江と海図を受け取り、到達できる入り江のうち、金貨が最も多いものを返します。タスク2の`coves-reachable`と、タスク4の`gold-count`を使います。

```factor
"Skull Bay" some-chart treasure-route .
! => "Smuggler's Hollow"   (the richest reachable cove)
```

メモ化された`gold-count`なら、同じ入り江を何度も調べてもコストはかかりません。アルゴリズムの複数の部分が同じ入り江を参照するときに便利です。
