# テスト

YAMLScriptで書かれたExercismの演習の解答をテストするのは、とても簡単です。実行も簡単で、理解も簡単です。

演習のディレクトリで`make test`を実行するだけです。

最初に`make test`を実行したときは、テストを解くコードをまだ書いていないので、すべてのテストが失敗します。

通常の演習の進め方は、まず`make test`を実行し、それから一度に1つのテストに集中して、そのテストに合格するコードを書いていくというものです。すべてのテストに合格したら、完了です！

おまけとして、`make test`を実行すると、正しいバージョンの`ys` YAMLScriptインタプリター（現在の演習で必要なもの）が正しい場所（`/path/to/exercism/yamlscript/.local/`）にインストールされていることも確認されます。つまり、始める前に`ys`をインストールしておく必要すらありません！


## 演習ディレクトリの構成

`the-great-exercise`という演習に取り組んでいるとすると、`exercism download --exercise=the-great-exercise --track=yamlscript`を実行すると、`/path/to/exercism/yamlscript/the-great-exercise`というディレクトリが作成されます。

このディレクトリの中では、テストファイルは`the-great-exercise-test.ys`、解答プログラムのファイルは`the-great-exercise.ys`という名前になります。また、演習の説明が書かれた`README.md`と、行き詰まったときに役立つ情報が書かれた`HELP.md`もあります。

`make`用のファイルは`Makefile`と`GNUmakefile`の2つです。これは、システムにインストールされているかもしれない別の`make`コマンドではなく、GNU `make`でテストを実行することを（npi）確実にするためのものです。本物は`GNUmakefile`で、GNU `make`は常に`Makefile`よりこちらを優先します。他の`make`コマンドは`Makefile`を使いますが、これはGNU `make`を使うように促すメッセージとともにエラーになるはずです！


## テストファイルの中身

YAMLScriptのテストは、もちろんYAMLScriptで書きます！　YAMLScriptはYAMLで、YAMLはデータですから、テストは基本的にただのデータです。

簡単なテストファイルの例を挙げます。実はこれは`acronym`の演習の最初の3つのテストです。:-)

```yaml
#!/usr/bin/env ys-0

use ys::taptest: :all
load: 'acronym.ys'

test::
- name: Basic
  code: abbreviate('Portable Network Graphics')
  want: PNG

- name: Lowercase words
  code: abbreviate('Ruby on Rails')
  want: ROR

- name: Punctuation
  code: abbreviate('First In, First Out')
  want: FIFO

done: 3
```

1行目はシバン行で、`prove`コマンド（Makefileから実行されます）に対して、`prove`のデフォルトである`perl`の代わりに、YAMLScriptの`ys`インタプリターでテストを実行するよう指示します。

2行目は`use`文で、YAMLScriptの`ys::taptest`という[TAP](https://testanything.org)テストライブラリを読み込みます。

> 注: TAPはテストスクリプトとテストハーネスの間のシンプルなテキストベースのインターフェースで、`prove`はPerlでTAPテストを実行するための標準的なハーネスです。Perlはどこにでもあるので、多くの言語（YAMLScriptを含む）のテストスイートにとって、TAPと`prove`を使うのはとても良い選択になります。

`use`文で`acronym.ys`の解答プログラムを読み込むことで、このテストファイルがテストする対象が用意されます。

テストはすべて、`test`キーの下のYAMLシーケンスに入っています。

最後の行の`done:`は必須で、すべてのテストが実際に実行されたことをテストハーネスに伝えます。数値（省略可能）は、実行されると想定していたテストの数です。

各テスト（`test`キーの下）は、次のキーと値のペアを持つマッピングです。

* `name:` - `prove -v`で表示されるテストのラベルです。
* `code:` - 実行するYAMLScriptのコードです。
  このコードは、取り組んでいる解答プログラムの何らかの関数を呼び出します。
* `what:` - エラーの発生を期待するテストでは、値は`error`です。
  通常のテストでは、このペアはありません。
* `want:` - テストで期待される結果です。
  これはYAMLの値で、文字列、数値、真偽値、シーケンス、マッピングのいずれかです。
  `what:`が`error`の場合、この値は期待されるエラーメッセージです。
* `SKIP:` - そのテストの実行をスキップするには、これを`true`にします。
* `ONLY:` - そのテストだけを実行するには、これを`true`にします。
  `ONLY:`のテストが複数ある場合は、そのすべてが実行されます。

これで、Exercismの演習をYAMLScriptでテスト駆動開発するために知っておくべきことは、すべてのはずです！

`ys::taptest`ライブラリには、もっと複雑なテストを書くために使える他の機能もありますが、Exercismのテストはすでに用意されています。`ys::taptest`ライブラリについてもっと知りたい場合は、[ドキュメント](
https://yamlscript.org/doc/ys-taptest)を参照してください。
