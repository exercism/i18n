# はじめに

他の多くの言語と同じように、Goにもポインタがあります。
ポインタに初めて触れると、少し不思議に感じるかもしれません。でも、慣れてしまえばとてもシンプルです。
ポインタはGoの非常に重要な要素なので、時間をかけてしっかり理解しましょう。

詳細に入る前に、ポインタの使い道を理解しておきましょう。
ポインタは、プログラムの他の部分とメモリを共有する方法であり、主に2つの理由で役立ちます：

1. 大量のデータがあるとき、関数間で渡すためにコピーを作るのは非常に非効率です。
   代わりに、データが保存されているメモリの位置を渡すことで、プログラムのリソース消費量を劇的に減らせます。
2. 関数間でポインタを渡すと、データの単一のコピーに直接アクセスして変更できます。つまり、ある関数で行われた変更は、その関数が終了した時点で、プログラムの他の部分からすぐに参照できるようになります。

## 変数とメモリ

ここで、通常の整数変数`a`があるとしましょう：

```go
var a int
```

変数を宣言すると、Goはその値を保存するためのメモリ上の場所を見つける必要があります。
この仕組みはほとんど私たちから抽象化されています。そのメモリに保存されている値を取得したいときは、変数名で参照するだけで済みます。

たとえば、`a + 2`と書くと、変数`a`に対応するメモリに保存された値を取り出し、それに2を足していることになります。

同様に、`a`のメモリに入っている値を変更したいときは、変数名を使って代入できます：

```go
a = 3
```

`a`に対応するメモリには、今度は値`3`が保存されます。

## ポインタ

変数を使うとメモリ内の値を参照できますが、その変数が指している**メモリアドレス**を知りたいときもあります。**ポインタ**は、そうした値のメモリアドレスを保持します。
ポインタ型の変数を宣言するには、基底型の前にアスタリスクを付けます：

```go
var p *int // 'p' contains the memory address of an integer
```

ここでは、型が「`int`へのポインタ」（`*int`）である変数`p`を宣言しています。
これは、`p`が整数のメモリアドレスを保持することを意味します。
ポインタのゼロ値は`nil`です。`nil`ポインタはメモリアドレスを何も保持しないからです。

### 変数へのポインタを取得する

変数の値のメモリアドレスを見つけるには、`&`演算子を使います。
たとえば、変数`a`のメモリアドレスを見つけてポインタ`p`に保存したい場合は、次のようにします：

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### ポインタ経由で値にアクセスする（デリファレンス）

ポインタがあるとき、そのポインタが表すメモリアドレスに保存されている値を知りたいことがあります。
それには`*`演算子を使います：

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p`という操作は、`p`に保存されたメモリアドレスにある値を取り出します。
この操作はよく「デリファレンス」と呼ばれます。

デリファレンス演算子を使って、ポインタが参照するメモリアドレスに新しい値を代入することもできます：

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa`へ代入すると、`pa`が保持するメモリアドレスに保存されている値が変わります。
`pa`は`a`のメモリアドレスを保持しているので、`*pa`へ代入することは、実質的に`a`の値を変更していることになります！

ただし、注意点があります。デリファレンスする前に、ポインタが`nil`でないことを必ず確認しましょう。
`nil`ポインタをデリファレンスすると、実行時にプログラムがクラッシュします！

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### 構造体へのポインタ

ここまでは、プリミティブ値へのポインタだけを見てきました。
構造体へのポインタも作成できます：

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

新しい`Person`を作成し、それへのポインタをすぐに保存することもできます：

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

構造体へのポインタがある場合、フィールドにアクセスする前にポインタをデリファレンスする必要はありません：

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## スライスとマップはすでにポインタ

スライスとマップは、その実装にすでにポインタが含まれている特殊な型です。
そのため、これらの型では、値のメモリアドレスを共有するためにポインタを作成しなくてよいことがほとんどです。
マップ内のキーの値をインクリメントする関数を考えてみましょう：

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

マップを作成してこの関数を呼び出すと、関数がマップに加えた変更は、関数の終了後も保持されます。
これはポインタを使った場合と似た動作ですが、この例では参照やデリファレンスなど、ポインタの構文を一切使っていないことに注目してください：

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

スライス内の既存の要素を変更する場合も同じです。

ただし、`append`のように新しいスライスを返す操作は特殊で、関数の外側のスライスを**変更しない**ことがあります。
これはスライスの内部動作によるものですが、より高度な話題なので、この演習では詳しく扱いません。
もっと知りたい場合は、[Go Blog: Mechanics of 'append'][mechanics-of-append]で詳しく読めます。

[mechanics-of-append]: https://go.dev/blog/slices
