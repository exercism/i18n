# 概念と概念演習へのコントリビュート

[概念演習][product-concept]は、あるプログラミング言語で1つの概念を教えることを目的としています。
明確な学習目標を持ち、学習者が不要なコードを覚えなくて済むよう、十分な定型コードを用意する必要があります。
関連する概念には、その概念演習とは独立した独自のドキュメントがあります。
概念には、ほかの概念を前提条件として持ち、前提となる概念の概念演習を完了するまでロックされるものがあります。
概念演習の難易度は、トラックが進んでも上がらないようにします。
概念演習は、前提となる概念に慣れているエンジニアなら誰でも5〜10分で解けるようにします。

概念演習とは何かがわかったところで、その実装方法と、関連する概念について詳しく見ていきましょう。
参考までに、概念演習と概念の詳細な仕様は、Exercismの[docsリポジトリ][docs-repo]で確認できます。
このドキュメントは、概念演習をコントリビュートする方法を、便利なステップバイステップのガイドとして提供するために、多くの情報源から情報をまとめたものです。

## 2. 学習目標を定める

概念演習が何を教えようとしているのか、どこまでが範囲外なのかを把握することが大切です。そこで、最初のファイルを作りましょう。`exercises/concept/<story-name>/.meta/design.md`です。
概念演習は使うストーリーにちなんで命名されるので、まだその名前はわかりません。そこで、今は`story-name`のままにしておき、あとで置き換えます。
[`design.md`の仕様][design-spec]によると、このドキュメントには、演習全体の目標、複数の学習目標、スコープ外の事項、その演習でアンロックされる関連する概念、そして演習を完了するために必要な概念の前提条件を定義します。
[真偽値の概念演習の`design.md`][design-bool]を、出発点となるテンプレートとして使えます。

## 3. 演習用の概念のイントロダクションを書く

学習目標が固まったら、学習者が演習を解けるように、概念を十分に説明するイントロダクションを書く番です。
ファイル`exercises/concept/<story-name>/.docs/introduction.md`を作成します。
このファイルの詳しい内容は、[その仕様][exercise-intro-spec]で説明されています。
[真偽値の概念演習の`introduction.md`][intro-bool]を、出発点となるテンプレートとして使えます。

ここで提供する情報は、学習者が自力で演習の解答を導き出せる程度に、概念を紹介するにとどめます。
学習者がオンラインで検索しやすいよう、適切な専門用語を使います。
リンクはできるだけ避け、その場で簡潔に説明します。
コードの文法は、コードブロックで紹介します。

## 4. 演習用のストーリーを探す

各概念演習は、ストーリーまたはテーマに基づいている必要があります。
Exercismは世界中で使われているため、できるだけ多くの人に受け入れられるものにするよう心がけています。
まずは、[ドキュメントにまとめられたストーリーの一覧][stories]にある既存のストーリーを再利用するのがよいでしょう。
新しいストーリーを作りたい場合は、プルリクエストで@exercism/leadershipに遠慮なくメンションしてください。
ここで、`exercises/concept/<story-name>/`ディレクトリを、自分のストーリーに合わせて名前を変えます。

## 5. 演習の指示を書く

ストーリーが決まったら、学習者が行うタスクを列挙した、正確な指示を書く必要があります。
ストーリーと指示はどちらも、`exercises/concept/<story-name>/.docs/instructions.md`ドキュメントに書きます。
[そのドキュメントの仕様][instructions-spec]で説明されているとおり、各タスクには見出しレベル2のMarkdownタイトル（`## 1. Do X`）を付け、そのあとに説明とコードの使用例を続けます。
[真偽値の概念演習の`instructions.md`][instructions-bool]を、出発点となるテンプレートとして使えます。

`instructions.md`に加えて、`hints.md`ファイルも必要です。
今取り組んでいるタスクに応じて適切なヒントが表示されるよう、指示ファイルと同じ見出しレベル2のタイトル（`## 1. Do X`）を含めます。
すべてのタスクに当てはまるヒント用に、`## General`セクションを設けることもできます。
ヒントで解答を直接書いてはいけません。
また、ヒントをクリックする人は、その演習にすでに戸惑ったり、圧倒されたり、いら立ったりしているかもしれないことに気をつけてください。
このドキュメントについての詳しい情報は[その仕様][hints-spec]にあり、[真偽値の概念演習の`hints.md`][hints-bool]を、出発点となるテンプレートとして使えます。

## 6. 設計を検証するためのドラフトプルリクエストを開く

ここで、概念演習のドラフトプルリクエストを開くのにちょうどよいタイミングです。
必要な残りのファイルに進む前に、演習を評価し、必要であれば作り直すのに十分な材料がそろっています。
ドキュメントが足りないためにCIの自動チェックが失敗しても心配いりません。それらはあとで作ります。

## 7. コードを書く

まずは演習を解くつもりでコードを書き、あとで仕様に沿うようにファイルを移動します。
最初に、[`template/`][template]ディレクトリの中身を、`exercises/concept/<story-name>/`ディレクトリにコピーしましょう。
すると、次のファイルができます。

```txt
elm.json           # elm project configuration file
src/Exercise.elm   # code for the exercise
tests/Tests.elm    # tests for the exercise
```

次に、`Exercise.elm`を、ストーリー名のPascalCaseに合わせて名前を変更します。
たとえば、`annalyns-infiltration`は`AnnalynsInfiltration.elm`になります。
そのソースファイルの中に、先ほど書いた`instructions.md`で説明した関数をすべて書いていきます。

演習を実装したら、`tests/Tests.elm`ファイルの中身を更新し、`instructions.md`のタスクの順番に自然に沿った関連テストを入れます。
概念演習のテストでは、**`Fuzz`を使わないでください**。`Debug.log`を使ってコードをデバッグする機能とうまくかみ合わないためです。
代わりに、いくつかのコーナーケースと一般的なケースの単体テストを含めてください。
概念演習のテストでは、**`test`または`describe`関数呼び出しの直下で`let`式を使わないでください**。[elmのテストランナーがまだこれをサポートしていない](https://github.com/exercism/elm-test-runner/issues/30)ためです。

演習とテストの両方ができて、問題なく動くようになったら、次のことを行います。

- `src/<ExerciseSlug>.elm`を`.meta/Exemplar.elm`にコピーします。この実装は、演習のリファレンスとなる「模範解答」の実装として、トラックのテストを実行するときに使われます。
- `src/<ExerciseSlug>.elm`の中の実装をすべて削除し、学習者が演習を始められるスターターファイルだけを残します。

## 8. 概念のドキュメントを書く

`exercises/concept/<story-name>`演習に関連する概念用に、`concepts/<concept>/`ディレクトリを作成します。
その新しいフォルダーの中に、2つのMarkdownドキュメント[`introduction.md`][concept-intro-spec]と[`about.md`][concept-about-spec]、そして1つの[`links.json`][concept-links-spec]ファイルを作成します（それぞれのリンクは仕様に飛びます）。

`introduction.md`の概念ファイルには、学習者が関連する概念演習を完了していない間、概念ページに表示される紹介を書きます。
関連する演習を始めたときに何を学ぶのかを、よく見渡せるようにするものです。
対照的に、`about.md`の概念ファイルには、学習者が関連する概念演習を完了したあとにだけ概念ページに表示される、概念のまとめを書きます。
そのため、内容はすでに書いた`exercises/concept/<story-name>/.docs/introduction.md`ファイルと似ていますが、同じではありません。
概念ファイル`introduction.md`については、演習のイントロダクションのドキュメントから始めて、その本質だけに絞り込むことをおすすめします。
そして`about.md`のドキュメントについては、演習のイントロダクションから始めて、その概念に関する関連情報がすべてそのページにそろうように補完します。
`links.json`には、概念についての追加情報が得られる役立つリンクをまとめます。
公式ドキュメントや優れたチュートリアルなどです。
これらのリンクは、概念のabout.mdファイル内にある、より文脈に沿ったリンクを置き換えるものではありません。学習者にとっての、全体を見渡せる手早い参照先を提供するものです。
リンクには任意でicon_urlフィールドを付けられます。これは、リンクが表示されるときのアイコンをカスタマイズするために使います。指定しない場合、アイコンはfaviconが既定になります。
利用できるアイコンは[github.com/exercism/website-icons/tree/main/exercises][icons]で確認できます。

## 9. 各種設定ファイルを完成させる

コードとドキュメントができたので、あとはこのプルリクエストを完成させるための、いくつかの設定ファイルを残すだけです。

- [`concepts/<concept>/.meta/config.json`][concept-config-json]: 自分をauthorに、レビューしてくれる可能性のある人をcontributorsにし、blurb（短い説明）を追加します。
- [`exercises/concept/<story-name>/.meta/config.json`][exercise-config-json]: authors（自分）、contributors、blurbなどの情報が含まれます。リンクされた仕様を参照してください。
- `config.json`: トラックの`config.json`ファイルに、[概念のエントリー][track-config-json-concept]と[概念演習のエントリー][track-config-json-concept-exercise]を追加します。概念演習のstatusキーには"wip"または"beta"を使います。UUIDは、Exercismが提供する[configletの実行ファイル][configlet]で生成できます。
