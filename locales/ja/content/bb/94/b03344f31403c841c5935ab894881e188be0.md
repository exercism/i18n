# 概要

いよいよ、C++の核心的なパラダイムの1つであるオブジェクト指向プログラミング（OOP）に取り組みましょう。
OOPは`classes`を中心に成り立っています。`classes`とは、関連する関数をひとまとまりに持つ、ユーザーが定義するデータ型のことです。
まずは基本から始め、シラバスのツリーを下っていく中で、より発展的なトピックを扱っていきます。

## メンバー

クラスは**メンバー変数**と**メンバー関数**を持つことができます。
これらには、**メンバー選択**演算子`.`でアクセスします。
`classes`の外にある変数と同じように、メンバー変数は宣言と同時に値を初期化しておくのがおすすめです。
この値は、そのクラスから新しく作られるオブジェクトの既定値になります。

## カプセル化と情報隠蔽

クラスには、メンバーへのアクセスを制限する仕組みがあります。
基本となるのは`private`と`public`の2つです。
`private`なメンバーは、クラスの外からはアクセスできません。
`public`なメンバーは、自由に呼び出せます。
すべてのメンバーは既定で`private`なので、クラスの外から使うには明示的に指定する必要があります。

## 基本的な例

新しい`class`の定義は、次の例のようになります。
定義の後ろにある`;`に注目してください。

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

クラスの内側からは、すべての変数にアクセスできます。
`cast_spell`関数の中の`damage`を見てみましょう。
クラスの外からは、`private`なメンバーを読み取ることも変更することもできません。

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## コンストラクター

コンストラクターを使えば、オブジェクトを作るときにメンバー変数へ値を代入できます。
コンストラクターは`class`と同じ名前で、戻り値の型を持ちません。
1つのクラスに複数のコンストラクターを持たせることができます。
すべての変数をいつも設定する必要があるわけではないときに便利です。

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

コンストラクターは奥が深く、多くのニュアンスがあります。
`class`に対して`constructor`を明示的に定義しない場合に限り、コンパイラーがその役割を果たしてくれます。
これは、上の最初の例で起きています。
_silverhand_オブジェクトは、引数を渡さずに既定のコンストラクターを呼び出すことで作られています。
すべての変数は、クラスの定義に書かれた値に設定されます。
もしその定義で値を何も指定していなければ、変数は未初期化のままになり、思わぬ結果を招くおそれがあります。

## 構造体

構造体は、この言語の元となったC言語に由来するもので、C++そのものと同じくらい古くからあります。
構造体は、1つ重要な例外を除けば、`classes`と実質的に同じものです。
既定では、`class`の中のすべては`private`です。
一方、構造体は別途指定しない限り`public`です。
慣習的に、`struct`キーワードは**データだけの構造体**によく使われます。
特定の性質を保証する必要があるオブジェクトには、`class`キーワードのほうが好まれます。
そうした不変条件の例としては、`Wizzard` `class`の`damage`が負にならないこと、などが挙げられます。
`damage`変数は`private`なので、damageを変更する関数はどれも、この不変条件が保たれるようにするはずです。
