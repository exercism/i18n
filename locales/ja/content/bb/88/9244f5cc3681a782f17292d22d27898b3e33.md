# はじめに

## 構造体

構造体とは、複数の関連する値をひとまとめにして名前を付けられる、独自のデータ型です。

構造体を定義するには、`struct`キーワードに続けて名前を書き、波括弧の中に各フィールドの名前と型を書きます。

```rust
#[derive(Drop)]
struct User {
    active: bool,
    username: ByteArray,
    email: ByteArray,
    sign_in_count: u64,
}
```

`struct`のインスタンスを作るには、`struct`の名前を指定し、波括弧の中にフィールドのキーと値のペアを書きます。

```rust
let user = User {
   active: true, username: "someusername123", email: "someone@example.com", sign_in_count: 1
};
```

可変の`struct`インスタンスのフィールドにアクセスしたり変更したりするには、ドット記法を使います。

```rust
let mut user = User {
    active: true, username: "someusername123", email: "someone@example.com", sign_in_count: 1
};
user.email = "anotheremail@example.com";
```

## 所有権

Cairoの値は不変であり、この不変性によって、たとえ多くの変数が同じ値を参照していても、値そのものは変わらず、書き換えられないことが保証されます。
変数の_所有者_とは、その変数を読み取れる（可変であれば書き込める）コードのことです。

Cairoにおける所有権のルールは次のとおりです。

1. Cairoのすべての変数には所有者がいます。
2. 所有者は同時に1つだけです。
3. 所有者がスコープから外れると、その変数は破棄されます。

スコープとは、プログラムの中で変数が有効な範囲のことです。

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

変数がスコープから外れると破棄され、それによって関連するリソースが正しく解放されることが保証されます。
これは`Drop`トレイトを実装または導出することで実現します。`Drop`トレイトは、その型が不要になったときに安全に破棄できることをコンパイラーに伝えます。

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

現時点では、辞書（`Felt252Dict`）と辞書を含む型を除き、すべての型で`Drop`の実装を導出できます。

値は_ムーブ_されることもあります。これは、値が別の関数に渡されたときに起こり、その値を参照していた元の変数は破棄され（その結果、その変数は使えなくなり）、同じ値を保持する新しい変数が作られます。

```rust
fn foo(num: u32) { 
    // do something with p
}

fn main() {
    let num: u32 = 10;
    foo(num);
    // ownership of `num` was moved into `foo` and is thus no longer valid in this scope
}
```

値を返すことは、その値をムーブすることと同じです。

次の例は、ある値を返す関数の例です。

```rust
#[derive(Drop)]
struct A {}

fn main() {
    // main now owns a1
    let a1 = gives_ownership();

    // a2 comes into scope
    let a2 = A {};

    // a2 is moved into takes_and_gives_back, which also moves its return value into a3
    let a3 = takes_and_gives_back(a2);
} // Here, a3 and a1 go out of scope and are dropped. a2 was moved, so nothing happens.

// Moves its return value into the function that calls it
fn gives_ownership() -> A {
    let some_a = A {};
    some_a
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A {
    some_a
}
```

変数はムーブされたあとに破棄されるため、コンパイラーはその後の再利用を許しません。

```rust
#[derive(Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(p: Point) { 
    // do something with p
}

fn main() {
    let p = Point { x: 5, y: 10 };
    foo(p);
    foo(p); // compiler error: Variable was previously moved.
}
```

この場合、同じ値（`p`変数に入っている`Point`構造体）を両方の関数呼び出しに渡そうとしています。
一度`foo`関数に変数を渡してしまうと、その変数はもう使えません。

これを解決する方法の1つは、構造体で`Copy`トレイトを導出することです。`Copy`を実装した変数を関数に渡すと動作が変わり、値はムーブされず、同じ値を参照する新しい変数が作られます。
変数はCairoの抽象化であり、値は常に不変なので、この操作にコストはかかりません。

型に`Copy`トレイトを実装するには、型定義に`#[derive(Copy)]`アノテーションを追加します。

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(p: Point) { 
    // do something with p
}

fn main() {
    let p = Point { x: 5, y: 10 };
    foo(p);
    foo(p); // this now works
}
```

## 参照とスナップショット

Cairoには、値を破棄したりムーブしたりせずに渡すための2つの機能があり、`references`と`snapshots`と呼ばれます。

スナップショットは、ある時点での値の不変の「ビュー」を提供し、変数の状態にアクセスしながらその所有権を保持できます。
変数を変更すると新しいメモリセルが作られ、スナップショットのビューは変わりません。

スナップショットを作るには、変数インスタンスの前に`@`を付けるだけです。

```rust
// this function takes in a snapshot using `@` with the data-type
fn get_len(arr: @Array<u128>) -> u32 { // 
    arr.len()
}

fn foo(arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let mut new_arr: Array<u128> = array![1, 2, 3, 4, 5, 6, 7, 8];
    let snapshot = @new_arr; // using `@` to create a snapshot of a variable
    let len = get_len(snapshot); // pass the snapshot as argument, retaining ownership
    foo(new_arr); // `new_arr` is still valid up until here and no further
}
```

スナップショットを通常の変数に戻すには、desnap演算子`*`を使います。これは`@`演算子の逆の働きをします。
desnapできるのは、`Copy`トレイトを実装している型だけです。

```rust
fn square(n: @u32) -> u32 {
    let n = *n; // we desnap the value
    n * n
}

fn main() {
    let num: u32 = 10;
    let squared = square(@num); // we use `@` to create a snapshot
    println!("{} squared = {}", num, squared);
}
```

参照を使うと、可変の値を関数に渡して暗黙的に返してもらいながら、呼び出し側のコンテキストで所有権を保持できます。
これは`ref`修飾子を使って実現できます。ただし、その変数が`mut`キーワードで可変として宣言されている必要があります。

先ほどの`Point`の例を、`Copy`トレイトに頼る代わりに可変の参照を使うように書き換えても、同じように動きます。

```rust
#[derive(Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(ref p: Point) { 
    // we can now update the passed values and the changes
    // will be visible in the calling context
    p.x += 1;
}

fn main() {
    let mut p = Point { x: 5, y: 10 };
    foo(ref p);
    foo(ref p); // this now works even without the Copy trait
    println!("p.x = {}", p.x); // p.x = 7 
}
```
