# 説明

この演習では、ログファイルの解析を扱います。

最近のセキュリティレビューを受けて、組織にアーカイブされているログファイルを整理するよう依頼されました。

メソッドに渡される文字列はすべて、nullではなく、先頭と末尾に空白がないことが保証されています。

## 1. 規格に合わないログ行を特定する

アーカイブ内のログ行のうち、現在の規格に準拠していないものがどれくらいあるのか、おおよそを把握する必要があります。シンプルなテストで、あるログ行が有効かどうかを判定できると考えました。有効と見なされるには、行が次のいずれかの文字列で始まっている必要があります。

- [TRC]
- [DBG]
- [INF]
- [WRN]
- [ERR]
- [FTL]

`LogParser.IsValidLine()`メソッドを実装し、文字列が有効でなければ`false`を、そうでなければ`true`を返すようにしましょう。

```csharp
var lp = new LogParser();
lp.IsValidLine("[ERR] A good error here");
// => true
lp.IsValidLine("Any old [ERR] text");
// => false
lp.IsValidLine("[BOB] Any old text");
// => false
```

## 2. ログ行を分割する

組織に新しいチームが加わりました。そのチームのログファイルでは、「フィールド」の区切りに変わった記号を使っていることがわかりました。コロンの":"のような常識的な区切りではなく、"<--->"や"<=>"のような文字列を使っているのです（そのほうが見た目が良いからです）。実際、最初の文字が"<"で最後の文字が">"であり、その間に"^"、"\*"、"="、"-"の文字が任意に組み合わさっていれば、どんな文字列でも構いません。

`LogParser.SplitLogLine()`メソッドを実装します。このメソッドは1行を受け取り、それぞれが1つのフィールドを含む文字列の配列を返します。

```csharp
var lp = new LogParser();
lp.SplitLogLine("Section 1<===>Section 2<^-^>Section 3");
// => {"Section 1", "Section 2", "Section 3"}
```

## 3. 引用符で囲まれたパスワードを含む行の数を数える

チームは、引用符で囲まれたテキストに現れるパスワードを把握して、手作業で調査できるようにする必要があります。

手作業がどの程度の規模になりそうかの目安を示すために、`LogParser.CountQuotedPasswords()`メソッドを実装します。

リテラル文字列"password"が引用符で囲まれているログ行を特定します。この文字列は、大文字と小文字がどのように組み合わされていても構いません。"password"の前後、引用符の内側に別の内容が入っている可能性も考慮する必要があります。

この処理に渡される行は、タスク1で定義したとおりに有効な場合もあれば、そうでない場合もあります。どちらの場合も同じように処理します。

```csharp
string lines =
    "[INF] passWord " + Environment.NewLine + // contains 'password' but not surrounded by quotation marks
    "\"passWord\"" + Environment.NewLine + // count this one
    "[INF] User saw error message \"Unexpected Error\" on page load." + Environment.NewLine + //does not contain 'password'
    "[INF] \"The secret password was added by the user\""; // count this one

var lp = new LogParser();
lp.CountQuotedPasswords(lines);
// => 2
```

## 4. ログから余分な文字列を取り除く

ログの上流処理のどこかで、テキスト"end-of-line"の直後に行番号が（間に空白を挟まずに）続く文字列が、ログ全体に散らばってしまっていることに気づきました。

`LogParser.RemoveEndOfLineText()`メソッドを実装します。このメソッドは文字列を受け取り、end-of-lineのテキストを取り除いて「きれいな」文字列を返します。

end-of-lineのテキストを含まない行は、そのまま返します。

end-of-lineの文字列だけを取り除きます。空白の調整は行いません。

```csharp
var lp = new LogParser();
lp.RemoveEndOfLineText("[INF] end-of-line23033 Network Failure end-of-line27");
// => "[INF]  Network Failure "
```

## 5. 極端に弱いパスワードを含む行を一覧にして、犯人を罰せるようにする

ファイルからパスワードを削除する前に、パスワードがテキスト"password"で始まるものをすべて一覧にしておく必要があります。

`LogParser.ListLinesWithPasswords()`メソッドを実装し、問題のあるパスワードを出力して、その後に完全な行を続けます。

引用符で囲まれたパスワードを含む行はすでに削除されており、行が有効かどうか（タスク1の定義による）に関係なく処理します。

問題のあるパスワードを含む行は、"<password>: "を先頭に付けて返します。

問題のあるパスワードを含まない行は、"--------: "を先頭に付けて返します。

```csharp
var lp = new LogParser();
lp.ListLinesWithPasswords(new string[] {"my passwordsecret is great"});
// => "passwordsecret: my passwordsecret is great"
lp.ListLinesWithPasswords(new string[] {"my password secret"});
// => {"--------: my password secret"}

```
