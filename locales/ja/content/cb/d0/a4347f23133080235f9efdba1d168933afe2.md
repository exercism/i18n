# テスト

テストを実行するには、次のコマンドを使います。

```shell
$ busted
```

`busted`のインストールについては、[Luaをローカルにインストールする][install]を参照してください。

[install]: https://exercism.org/docs/tracks/lua/installation

## ユニットテストのデバッグ

このガイドでは、[VSCode](https://code.visualstudio.com/)に[Busted](https://github.com/lunarmodules/busted)テストフレームワークと[Local Lua Debugger](https://marketplace.visualstudio.com/items?itemName=tomblind.local-lua-debugger-vscode)を設定する方法を紹介します。これにより、テストスペックとテスト対象のファイルの両方にブレークポイントを設定できるようになり、[テスト駆動開発](https://en.wikipedia.org/wiki/Test-driven_development)のワークフローをすんなり進められます。これは唯一の方法というわけではありません。ほかにも動く方法はたくさんありますが、この方法なら少なくともすぐに動かせるようになります（注: これはWindows 10とUbuntu 20.04でテスト済みで、動作します）。

難しい用語の話はこのくらいにして、始めましょう。

> これらの部分は、あくまでプロセスを説明するためのものなので、読み飛ばしてもかまいません。

**VSCode**で、ほかの**Lua**デバッガー拡張機能をすべて削除するか無効にして、[Local Lua Debugger](https://marketplace.visualstudio.com/items?itemName=tomblind.local-lua-debugger-vscode)をインストールします。次に、[カスタム起動構成](https://code.visualstudio.com/docs/editor/debugging#_launch-configurations)を次のように作成します:

```json
{
	"name": "Busted",
	"type": "lua-local",
	"request": "launch",
	"program": {
		"command": "busted"
	},
	"cwd": "${workspaceFolder}/${relativeFileDirname}",
	"args": ["${file}"],
	"integratedTerminal": true
}
```

**注:** `integratedTerminal`プロパティを使うと、`Property integratedTerminal is not allowed`という警告が出ますが、これは無視してかまいません。

> `cwd`プロパティは、現在の作業ディレクトリを指定します。これはパスの解決に重要です。既定では、**Exercism**は各演習を、トラック名のフォルダーの下にあるそれぞれのフォルダーにインストールします。**Lua**の場合は次のようになります:
>
> ```
> └── Exercism/
>     ├── lua/
>     │   ├── armstrong-numbers
>     │   ├── bank-account
>     │   ├── binarysearch
>     │   └── etc...
>     └── python/
>         └── etc...
> ```
>
> そこで、`/lua`フォルダーから次のように**VSCode**を開くとします:
>
> > `C:\users\<username>\Exercism\lua> code .`
> >
> > または
> >
> > `/home/<username>/exercism/lua> code .`
>
> **VSCode**は、ワークスペース内の各演習をそれぞれのフォルダーに表示します。つまり、起動構成で現在の作業ディレクトリ`cwd`を、演習ごとのフォルダーに変更する必要があります。これは、[VSCodeの変数](https://code.visualstudio.com/docs/editor/variables-reference#_settings-command-variables-and-input-variables)である`${workspaceFolder}`と`${relativeFileDirname}`を組み合わせて行います。
>
> `args`プロパティには、**Busted**に渡す引数を指定します。ここでは、現在開いているファイルを参照する変数`${file}`を使っています。

次に、取り組んでいる演習のテストファイル（名前は`<exercise_name>_spec.lua`）の先頭に、次の3行を追加します:

```lua
if os.getenv("LOCAL_LUA_DEBUGGER_VSCODE") == "1" then
  require("lldebugger").start()
end
```

これで、デバッガーを使ってテストを実行したいときは、テストファイルを開き、左側の`Run and Debug`（Ctrl+Shift+D）サイドバーから、作成した起動構成を実行します。テストファイルにフォーカスがあると、起動構成がそのテストを実行し、ブレークポイントで停止して、下部の統合ターミナルの`DEBUG CONSOLE`タブに出力を表示します。

コーディングを楽しみましょう！
