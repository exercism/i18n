# 契約

ルーチンの引数と戻り値の型は、どんな*種類*の値が入って出てくるかを示します。しかし、重さが正の値でなければならないことや、ハーネスが実際の余剰容量より多く報告しないことは、示せません。

**契約**は、そうした事柄をルーチン自身のヘッダーに書きます。そこは、読む人なら誰でも目にする場所です。

## pre

`pre`は、ルーチンが呼び出されるときに成り立っていなければならないことを示します。書く場所は、戻り値の型と`is`の間です。

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

これは**呼び出し側**への要求です。負の`load`でこのルーチンを呼び出してはいけません。

## post

`post`は、ルーチンが答えを返すときに成り立つことを示します。その中で、`result`は戻される値を表します。

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

これは呼び出し側への約束です。両方を備えたルーチンは取引です。これを渡してくれれば、あれを返します、というわけです。

複数の条件は、真偽値と同じように、`and`でつなぎます。

```sather
      pre load >= 0 and load <= limit
```

## 契約は例外ではありません

発生させる例外は、起こりうることに対するものです。破られた契約は**バグ**を意味します。誰かがルーチンを間違って呼び出したか、ルーチンが宣言どおりのことをしなかったかです。

ですから、破られた契約は捕まえられるものを発生させません。契約チェックを有効にすると、プログラムは停止し、どのルーチンのどの条件かを出力します。無効にすると、その条件は検査すらされず、プログラムはそのまま、後に続くどんな無意味な処理へも進んでいきます。

だからこそ、契約は不正な入力の扱い方ではなく、正しさについての表明なのです。不正な入力が想定されるなら、検査して`raise`します。不正な入力が呼び出し側の誤りを意味するなら、`pre`でそう示します。

## チェックを有効にする

このSatherは、コンパイラーに`-chk`を渡すと契約をチェックします。

```
sacomp -chk mine.sa -main MAIN -o mine
```

それがなければ、`pre`と`post`は、コンパイラーが読んで、書式が正しいと確認しただけのドキュメントであり、それ以上のものではありません。この演習のテストは`-chk`なしでビルドされるので、破られた契約を代わりに見つけてはくれません。テストが確認するのは、正しく使ったときにルーチンが期待どおりに動くことです。
