# はじめに

## JSON

### JSON

JSON（JavaScript Object Notation）は、人間が読めるデータ形式でありファイル形式でもあり、データのやり取り、とくにWebアプリケーションでのデータ交換によく使われます。それだけに、Elmという言語の中でJSONが特別な位置を占めているのも不思議ではありません。

Elmには、JSONデータを解析したり書き出したりするためのコアモジュールとして`Json.Decode`と`Json.Encode`が用意されています。JSONデコーダーは、どんな型のデータを期待するのか、そのデータをどのデータ構造に対応させるのかを_宣言_する方法です。

これらのモジュールから、いくつかのエイリアスと型をインポートしてみましょう。

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

`Decode.decodeString : Decoder a -> String -> Result Error a`をデコーダーとJSON文字列と一緒に使うと、その文字列がデコーダーの仕様に合っていれば成功し、そうでなければ失敗します。デコーダーを定義するときに生のJSONデータを調べる方法はありません。命令型言語に慣れていると、これは少し不思議に感じられるかもしれません。

### 基本的なデータ型のデコーダー

JSONの基本データ型はごくわずかです。

- 文字列：二重引用符で囲んで表します `"hello world"`
- 真偽値：`true`か`false`のどちらかです
- 数値：`34`や`0.12`のような値です
- Null：データがないことを表す`null`です

これらのそれぞれに、対応する`Decode`関数があります。

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

`Decode.null`を使うと、`null`をプログラムの中でどう扱うかを自分で決められます。引数に任意の値を渡す仕組みになっているので、`()`や`Nothing`など、プログラムに合ったものを選べます。

### デコーダーを組み合わせる

JSONにはまた、基本データ型をまとめるためのデータ構造が2つあります。

- 配列：ほかのデータ型を集めたもの `[0, null, "none", []]`
- オブジェクト：キーと値のペアを集めたもの `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode`にも、これらをデコードする関数が用意されています。

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

これらの関数、`Decode.list : Decoder a -> Decoder (List a)`と`Decode.dict : Decoder a -> Decoder (Dict String a)`は、どちらも引数にデコーダーを取ります。そのデコーダーは、データ構造の要素をひとつずつデコードする役割を担います。配列やオブジェクトの中に、引数のデコーダーでデコードできない要素が1つでもあると、デコーダー全体が失敗します。これはよく使われるパターンです。

単純なデコーダーを組み合わせて、より複雑なデコーダーを作るのが、この技法の中心となる考え方です。ここからは例を交えながら、現実世界の複雑なデータを自在にデコードできるデコーダーを組み立てるための関数を、いくつか紹介していきます。

### GeoJSON

基本的なデコーダーを組み合わせて複雑なJSONデータを解析する練習として、GeoJSONのデータを（一部だけ）解析するデコーダーを作ってみましょう。GeoJSONは、地理的な特徴を表すために使われる、JSONをベースにした専用のデータ形式です。地点や経路、領域といったものを、2次元または3次元の地理座標とその他のプロパティで表現します。

#### ジオメトリオブジェクト

GeoJSONのジオメトリオブジェクトは、文字列の値を持つ`type`フィールド（`type`の値は7種類あります）と、地理座標を持つ`coordinates`フィールド（座標のまとめ方は`type`によって変わります）を含むオブジェクトです。たとえば、次のようになります。

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

あるいは

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

ジオメトリオブジェクトは、Elmでは次のような型で表せます。

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

あるフィールドの値を取り出すには、`Decode.field : String -> Decoder a -> Decoder a`が使えます。これは、オブジェクトの特定のキーの値をデコードするものです。

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

デコーダーが無事に解析した値を変換するには、`Decode.map : (a -> value) -> Decoder a -> Decoder value`や、その仲間たち、`Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value`から`Decode.map8`までを使えます。

ここでは、`type`フィールドの値に応じて、どの座標デコーダーを使うかを決めたいところです。これは`Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b`と、その仲間である`Decode.succeed : a -> Decoder a`、`Decode.fail : String -> Decoder a`の出番です。

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

ここで、`Decode.andThen`を使えば座標を検証できることにも触れておきます。座標が2つ組や3つ組になっているか、座標の値が地理的に妥当かを確かめられるのです。

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

#### フィーチャーオブジェクト

GeoJSONのフィーチャーオブジェクトは、空間的に区切られた何かを表します。`"Feature"`という値を持つ`type`フィールド、ジオメトリオブジェクトまたは`null`を持つ`geometry`フィールド、任意のJSONオブジェクトまたは`null`を持つ`properties`フィールド、そして省略可能な`id`フィールド（JSONの文字列または数値）を持ちます。

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

あるいは

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

まず`id`フィールドから取り組みましょう。このフィールドがある場合、文字列か数値のどちらかを受け入れる必要があります。そこで、値用に独自の型を用意するか、いつも文字列として保存するかのどちらかが考えられます。

2つの候補のデコーダーから1つを選ぶには、`Decode.oneOf : List (Decoder a) -> Decoder a`が使えます。

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

このフィールドが省略可能であることを表すには、同じ技法が使えます。

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

ただし、代わりに`Decode.maybe : Decoder a -> Decoder (Maybe a)`を使うこともできます。

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

`decodeMaybeFeatureId`（あるいは`Decode.maybe`で包んだ任意のデコーダー）は、いつでも`Ok Nothing`にフォールバックできるため、必ず成功します。ただし、これを使う側のデコーダーは失敗する可能性があります。

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

次に`geometry`フィールドに注目しましょう。このフィールドは、ジオメトリオブジェクトか`null`のどちらかです。ここでも`Decode.oneOf`が使えますが、もっと良い選択肢があります。`Decode.nullable : Decoder a -> Decoder (Maybe a)`です。

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe`と`Decode.nullable`は同じシグネチャですが、動作は異なります。`Decode.nullable`の`OK Nothing`という結果は、JSONの値が`null`のときだけ返されるからです。

最後に、`properties`フィールドは任意のJSONオブジェクトか`null`を含められます。これには`Decode.value : Decoder Value`が向いています。

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

`Value`は不透明な型なので、その中身を簡単に調べることはできません。使うには、そのためのデコーダーを書いて`Decode.decodeValue : Decoder a -> Value -> Result Error a`で実行するか、ポートを通して直接JavaScriptに送るかのどちらかです。

これでフィーチャーオブジェクトを解析する準備ができました。

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

### JSONエンコーダー

エンコーダーを使うと、Elmの値から`Encode.encode : Int -> Value -> String`関数で正しいJSONを書き出せます。最初の引数は出力のインデント量を指定し、2番目の引数は書き出すJSONの値です。

`Value`は、`Decode.value`から得るか、いずれかのエンコーダーで作るかのどちらかです。

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

`Encode.object : List ( String, Value ) -> Value`を使っても同様です。

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

先ほど定義したGeoJSONのデコーダーに対応するエンコーダーを定義してみましょう。

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

一般に、デコーダーとエンコーダーの組み合わせが正しいかどうかは、`elmValue |> encoder |> decoder == elmValue`が成り立つかどうかで確かめられます。
