# 概要

[レコード][records]は、関連する情報をラベル付きでまとめたデータ構造です。JavaScriptやJavaのオブジェクト、CやRustの構造体に似ていますが、いくつか重要な違いがあります。

## レコードを作成する

レコードは波括弧（`{}`）で[作成][create]し、要素はカンマで区切ります。

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

レコードの型も似た構文で定義しますが、等号`=`の代わりにコロン`:`を使います。

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

この型定義を毎回繰り返すのは面倒なので、定義を共有するために[型エイリアス][record-types]を使うのがよくある書き方です。

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

型エイリアスは、そのレコードのコンストラクター関数も自動的に用意してくれます。Elmでは関数名を小文字で始めなければならないため、これは時に意外に思えますが、型コンストラクターはその例外の一つです。

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

## レコードのフィールドにアクセスする

[レコードのインスタンスのフィールド値にアクセスする][access]主な方法は、`firefly.creator`のようなドット記法を使うことです。
Elmのコンパイラーは、`.`で始まる特別なアクセサー関数もサポートしています。たとえば`.creator`は、その名前のフィールドを持つどんなレコードにも使えます。
これが、関数名は小文字で始めなければならないというルールの2つ目の例外です。
実際には、ユーザーが定義する関数は小文字で始めなければなりませんが、今見た2つの例はプログラマーではなくコンパイラーが生成するものです。

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

レコードは、[レコードのパターンマッチング][pattern-matching]を使って束縛の中で_分解_することもできます。分解は、該当する名前のフィールドを持つどんなレコードにも使えます。

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

## レコードを更新する

Elmのすべての値と同じく、レコードはイミュータブルです。そのため、一度定義したレコードのフィールド値は決して変わりません。
[既存のレコードのコピーを作り、1つ以上のフィールドを変更する特別な構文][update]があります。
この構文では、パイプ記号`|`を使って元のレコードと変更するフィールドを区別します。たとえば`{ oldRecord | field1 = newValue }`のように書きます。

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

## レコードを比較する

Elmは[構造的等価性][equality]を使います。つまり、同じ値を持つ同じレコードの2つのインスタンスは等しいと見なされます。

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

## 拡張可能なレコード

Elmは[構造的型付け][structural-typing]もサポートしています。これは、xとyフィールドを持つレコードを必要とする関数が、それらのフィールドを持つどんなレコードでも動くという意味です。たとえば2次元の点、3次元の点、宇宙船などです。
こうしたレコードの型は、定義にパイプ`|`を持ち、たとえば`{ a | x : Float, y : Float }`のようになります。Elmの用語ではこれを「拡張可能なレコード」と呼びます。
型定義の中のパイプ`|`（拡張可能なレコードの定義、`{ a | x : Int }`）と、実際のレコードのインスタンスの中のパイプ`|`（そのレコードのいくつかのフィールドを更新するという意味です）の違いに注意してください。

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
