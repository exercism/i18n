# はじめに

Elixirは、バイナリデータを扱うためのエレガントな構文を提供しています。これまで[ビット列][exercism-bitstrings]を扱うために用意された`<<>>`という特殊形式で見てきたとおりです。

バイナリ型は、ビット列型を特殊化したものです。ビット列は任意の長さ（任意の数の[ビット][wiki-bit]）にできますが、バイナリはビット数を8で割り切れる場合のものです。つまり、バイナリを扱うときは、[バイト][wiki-byte]（8ビット）という単位で考えることがよくあります。1バイトは`0`から`255`までの整数値を表せます。バイトの値は[16進数][wiki-hexadecimal]で扱うのが一般的で、`0x00 - 0xFF`のように表します。

バイナリリテラルは、ビット列の特殊形式`<<>>`を使って定義します。バイナリリテラルを定義するときは、整数リテラルと文字列リテラルを使えます。255より大きい整数値はオーバーフローし、その整数の最後の8ビットだけが使われます。デフォルトでは、その値に`::binary`モディファイアが適用されます。バイナリは`<>/2`演算子で連結できます。

```elixir
<<255>> == <<0xFF>>
# Overflowing bits are truncated
<<256>> == <<0>>
<<2, 4, 6, 8, 10, 12, 14, 16>> == <<0x02, 0x04, 0x06, 0x08, 0x0A, 0x0C, 0x0E, 0x10>>
```

*ヌルバイト*は`<<0>>`の別名です。

## バイナリデータのパターンマッチング

[パターンマッチング][exercism-pattern-matching]はバイナリにも拡張されており、配列の場合と同じように、バイナリデータの一部をパターンマッチできます。

```elixir
# Ignore the first 8 bytes, match and bind the remaining to `body`
<<_::binary-size(8), body::binary>>
```

他の種類のパターンマッチングと同じく、これを関数シグネチャで使い、複数の関数節から選ぶときにマッチさせることができます。
