# はじめに

多くのオブジェクト指向言語では、親クラスを[サブクラス化][wiki-subclass]して振る舞いを拡張するのが一般的です。親からメソッドを引き継ぎながら、新しいメソッドも追加します。
こうしてオブジェクトの階層ができあがります。

Juliaには_クラスがありません_。したがって、_サブクラスもありません_。
では、既存の振る舞いをどうやって継承し、拡張するのでしょうか？

これまでの概念では、型の階層を作る方法を学びました。また、Juliaが[多重ディスパッチ][concept-multiple-dispatch]を使って、引数の型に基づいてメソッドを選ぶ仕組みも見てきました。

Juliaには、いくつかの非公式なインターフェースもあり、自作の型を、標準の型ですでに定義されている振る舞いに組み込むことができます。

これはイテレーターインターフェースで説明するのがいちばんわかりやすいでしょう。

## イテレーター

これまでのシラバスで、Juliaがコレクションの各要素を操作するいくつかの方法を見てきました。

- [ループ][concept-loops]：たとえば`for item in items...`
- [ブロードキャスト][concept-vector-operations]：`[1, 2, 3] .- 0.5`
- [高階関数][concept-hof]：`map(√, [1, 4, 9])`
- [内包表記][concept-comprehensions]：`[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [ジェネレーター][concept-comprehensions]：`(x^2 for x in 1:1e6)`。これは遅延評価されます。

このように、Juliaは標準のコレクションを要素ごとにたどる方法をちゃんと知っています。上の例のベクトルや範囲のほか、SetやDictなども同様です。

では、自作のコレクションにこの機能をどうやって追加するのでしょうか？　とくに、ジェネレーターのように遅延評価で繰り返せる場合はどうでしょう。

### 最低限の要件

繰り返しの対象となるシーケンスを作るには、（少なくとも）2つのものが必要です。

1. _最初_の要素を取得する方法。
2. 現在の状態から_次の_要素を取得する方法。

Juliaは、`Base.iterate()`関数のメソッドを使って、次の手順でこれらのタスクを実現します。

1. まず`Base.iterate(iter)`が自動的に呼び出されます。
    - 繰り返すものがない場合は、`nothing`を返します。
    - それ以外の場合は、最初に返す要素と最初の状態の`Tuple`、つまり`(firstitem, firststate)`を返します。
2. 前回の繰り返しで要素が返された場合、`Base.iterate(iter, state)`が自動的に呼び出され、`firststate`を`state`引数として受け取ります。
    - 繰り返しが終了する場合は、`nothing`を返します。
    - それ以外の場合は、次の要素と次の状態の`Tuple`、つまり`(nextitem, nextstate)`を返します。
3. 終了するまで手順2を繰り返します。

これらの手順はすべて「内部で」行われます。つまり、メソッドの呼び出しと状態は繰り返しのプロトコルによって内部的に管理され（状態は非公開のまま保たれ）、ループのような高レベルの構文には要素だけが公開されます。
言い換えれば、見えるのは常に`item`だけで、それ以外はすべてブラックボックスの中にとどまります。

この仕組みの中心にあるのが[多重ディスパッチ][concept-multiple-dispatch]です。
`iter`の型がどのメソッドが呼ばれるかを決め、引数の数が、最初の要素と次の要素のどちらが返されるかを決めます。

標準の型のメソッドはすでに定義されています：`Vector`、`Range`、`Set`など（[現在][ref-iterations-collections]は全部で14種類）。

自作の`MyType`に同じ振る舞いを持たせるには、まず次のものを定義する必要があります。
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

抽象的に聞くと、どれもややこしく思えるかもしれませんが、実際にはとてもシンプルです。
たとえば、与えられた整数`n`の累乗を、最大の個数まで返す型が欲しいとしましょう。

まず、自作の型を定義します。

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

これでこの型の`iterate`メソッドを定義できますが、最初の要素と最初の状態とは何でしょうか？

最初の要素を得るには、複雑な準備が必要なイテレーターもありますが、このおもちゃの例では、最初に返される要素はただの基数だとわかるので、`count`の値が1以上かどうかを確認するだけで済みます。

次に、最初の状態について考えます。これは、次の繰り返しで使われる情報を運びます。
そのためにどんな情報を記録しておく必要があるかは、自分で決めることができます。型は何でもかまいません。

この場合は、`n`を累乗する「指数」だけを記録してもよいですし、もっと性能のよい方法として、`n`の最新の累乗（つまり返された要素）と、シーケンス内の次の「指数」を使うこともできます。
この2つの数値は`Tuple`にまとめて、`state`として返すことができます。

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

この例では、最初の要素（`p.n`）がループに返され、最初の状態`(p.n, 2)`が`iterate(P::Powers, state)`メソッドに渡されます。
そこで状態を処理して、現在の要素に基数を掛けることで次の要素を作り、累乗を`1`増やします。

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

`index`の値がまだ`count`の範囲内であれば、`next`の要素とインクリメントされた状態の`Tuple`が返されます。
`index`の値が`count`を超えると、代わりに`nothing`が返され、繰り返しが終了したことを示します。

お気づきかもしれませんが、`iterate(p::Powers)`と`iterate(p::Powers, state)`のメソッドは、関数の中身がかなりよく似ています。
実際、うまくやれば、この類似性のおかげで、状態にデフォルト引数を持つ2引数のバージョンだけを使い、すっきり実装できます：`Base.iterate(p::Powers, state=(1, 1))`
そうすれば、1引数の`iterate(p::Powers)`を別に用意する必要はありません。
これは可能なときに実際よく行われる手法です。

ここまでで、すでにいくつか便利な機能が手に入っています。3の最初の4つの累乗について、結果をループでたどり、ある数値が結果に含まれるかを確認し、`sum()`のような集約関数を適用できます。

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 追加のメソッド

よい滑り出しですが、まだすべてが動くわけではありません。

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

案の定、`length(Powers(3, 4))`もまったく同じエラーメッセージを出します。

これは簡単に直せます。長さは型のコンストラクターの一部であり、この場合は4だからです。
この型に対して`Base.length()`を定義するだけで、シーケンスに内包表記や`collect()`を使えるようになります。

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

効率を考えると、`Base.eltype()`、すなわち結果の要素の型も定義するのがよいでしょう。
こうすると、`collect()`のような関数が、`Vector{Any}`に何度も`push!()`する代わりに、出力用の`Vector{Int}`の領域をあらかじめ確保できます。

見たことのないかもしれない構文に注目してください。このメソッドは型の_インスタンス_ではなく、_型そのもの_に対して定義されます。

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

イテレーターは、長さが有限であることを_必須_としません。
「無限」シーケンスの用途は限られますが、ループから`break`で抜け出す方法があるかぎり、それらをループでたどるのは役に立つことがあります。
たとえば、ある上限（整数のオーバーフローを避けるなら`typemax(Int)`など）より小さい値を生成する`Powers`の変種を定義できます。

## まとめ

インターフェースは、説明するのがなかなか難しいものです。Juliaのアプローチが他のほとんどの言語とあまりに違うからです。
とくに、実装の中でインターフェースの名前が一度も登場しないこともあります。これは[サブクラス化][wiki-subclass]や[ミックスイン][wiki-mixins]とは大きく異なります。

しかし、実際に使ってみると驚くほどシンプルです。

1. 適切な型を定義します。
2. どのメソッドが必要かを調べます。
3. 自作の型に対してそれらのメソッドを実装します。たいていはほんの数個のメソッドで、ごく短くシンプルです。
4. あとは[多重ディスパッチ][concept-multiple-dispatch]が自動的に処理してくれます。
