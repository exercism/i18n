# 概要

## const

[`const`][constants]修飾子は、コンパイル時に値がわかっており、かつプログラムの実行中に変化しないフィールドになら、どのフィールドにも適用できます（そして、たいていは適用すべきです）。

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

どんな式がコンパイル時に評価できるかは、コンパイラーが教えてくれます。単純な算術演算は許可され、文字列の連結も同様です。ただし、ヒープやスタックを使う必要がある評価は除外されるので、メソッド呼び出しやプリミティブ型以外への参照は使えません。

`const`が変数よりも性能面で有利だという議論が、ウェブ上にはいくつかあります。インスタンスの非`const`フィールドと比べる場合は、メモリを目に見えて節約できることがありますが、静的変数と比べると、それは明らかに取るに足らないものです。CPUの性能を云々するのは、同僚の目には[早すぎる最適化][premature-optimization]と映るでしょう。

`const`を使うもっと説得力のある理由は、コードを保守する人がコードを読み解きやすくなることです。あるフィールドに`const`や`readonly`が付いている、あるいはプロパティにセッターがない、と一目見れば、保守する人はその部分を解析からほぼ除外できます。そこがバグのもとになることはまずありません。リファクタリングで難しい問題になることもまずありません。この点については、こちらの[Stack Overflowのコメント][so-consts]が触れています。

`const`修飾子は、メソッド内の値にも適用できます。

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

このように`const`で値を定義しておくと、その値がメソッド内で何度も使われる場合や、その意味を際立たせたい場合に役立ちます。リテラルを直接書く場合と比べて、性能が上がるわけではありません。

## readonly

[`readonly`][readonly-fields]修飾子は、`const`にできないフィールドのうち、値がプログラムの実行中に変化せず、インライン初期化子か、インスタンス化のとき（コンストラクター、またはコンストラクターから呼ばれるメソッド）に設定されるものになら、どのフィールドにも適用できます（そして、たいていは適用すべきです）。

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

`readonly`修飾子の使用が推奨される理由は、`const`と同じです。このようにフィールドを制約する習慣は、コードを保守する人がコードを読み解く助けになります。

フィールドに`readonly`修飾子を付けても、防げるのはそのフィールドの値が変わることだけです。集約型の場合は、その型のフィールドやプロパティまでは保護されません。とくに、配列の中身は保護されません。

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

参照型のすべてのメンバーを保護したい場合は、フィールドを`readonly`にし、自動プロパティを`set`アクセサーなしで定義します。

Base Class Libraryの[読み取り専用コレクション][readonly-collections]も調べてみましょう。

配列については、読み取り専用に最も近いものは[`Array.AsReadOnly<T>()`][as-read-only]メソッドです。
