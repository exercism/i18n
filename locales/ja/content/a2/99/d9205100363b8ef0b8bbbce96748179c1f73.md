# テスト

演習のディレクトリで次のコマンドを実行すると、テストを実行できます。

```bash
dub test
```

## テストに合格するには

[テスト駆動開発の3つのルール](http://butunclebob.com/ArticleS.UncleBob.TheThreeRulesOfTdd)に従って、まずは最初のテストがコンパイル・リンクされて通るようにしましょう。コンパイラのエラーが解消され、テストが失敗する状態になるまで、名前空間、関数、クラスなどを宣言して、必要最小限の構造を作ります。次に、テストが通るだけの最小限のコードを書きます。ここまでできたら、次の行を次のテストの後ろに移動して、次のテストのコメントを外します。

```D
static if (all_tests_enabled)
```

まだ宣言や定義をしていない新しい構文が呼び出されるため、コンパイルエラーになるかもしれません。ここでも、テストが失敗する状態になるまでコンパイルエラーを最小限に修正し、次にテストが通るようにコードを最小限だけ変えます。そして、読みやすさと表現力を高めるために実装をリファクタリングしたら、次のテストに進みます。

独自の低レベルなアルゴリズムや仕組みを手で書くよりも、Dの標準ライブラリの機能を使うようにしてみましょう。
