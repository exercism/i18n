# はじめに

## 文字

**文字エンコーディング**とは、自然言語のテキストの要素をバイト列として表現するための、特定の取り決めです。
ここでいう「テキストの要素」とは、自然言語で意味を持つ任意の単位を指します。たとえば、文字、空白、句読点、絵文字、表意文字などです。

NASM（Netwide Assembler、このトラックで使われているアセンブラー）は、**ASCII**を使ったデータの定義をサポートしています。

NASMの文字定数は最大8バイト長で、一重引用符（`'`）、二重引用符（`"`）、またはバッククォート（`` ` ``）を使って定義できます。

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

特殊文字はバッククォートで定義し、`\`でエスケープする必要があります。

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

x86-64には、いかなる文字エンコーディングも独立した型として組み込みでサポートされていないことに注意してください。
アセンブリのデータはバイト列であり、そのバイトを文字、数値、その他何として解釈するかは、プログラマーに委ねられます。

たとえば、ASCII文字の'0'は値48の1バイトです。
したがって、48を1バイトに格納することは、ASCII文字の'0'を格納することとまったく同じです。

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

同じ理由で、文字の操作は、それらのバイトの値を直接変換することによって行います。

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## 文字列

**文字列**とは、文字の並びです。
アセンブリでは、通常、配列として実装されます。

NASMでは、他の配列を宣言するのと同じ方法で文字列を宣言できます。

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

文字列と他の配列の違いの1つは、NASMでは値の区切りにカンマ（`,`）を使わずに文字列を宣言できることです。
また、値をカンマで区切りながら混在させることもできます。

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

すでに述べたように、文字は単なるバイト（Unicodeエンコーディングではバイト列）であることに注意してください。

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

ASCII文字はそれぞれ1バイトなので、より広いサイズで宣言した場合、後続のバイトはすべて`0`になります。
たとえば、`'a'`をqword（8バイト）として宣言すると、最初のバイトは`'a'`（`97`）で、残りの7バイトはすべて`0`です。

このため、以下はすべて等価です。

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
アセンブリでは、文字列はASCIIのNUL文字（値`0`）で自動的に終端されません。

Cなどの高水準言語とやり取りする場合、文字列の末尾に正しい終端文字（必要な場合）を追加するのはプログラマーの責任です。
~~~~

## 文字列命令

文字列は配列なので、メモリを明示的に逆参照することで、他の配列と同じように扱えます。

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

さらに、メモリ内のバイト列に対して値をロード、移動、ストアするための命令がいくつかあります。
これらは_文字列命令_と呼ばれますが、メモリ内の任意のバイト列、つまり任意の配列で使用できます。

最も重要な文字列命令は、`lods`、`stos`、`movs`の3つです。

| 命令 | 動作 |
| --- | --- |
| `lods` | `rsi`で示されるメモリ位置から`rax`に値をロードします |
| `stos` | `rax`から`rdi`で示されるメモリ位置に値をストアします |
| `movs` | `rsi`で示されるメモリ位置から値をコピーし、`rdi`で示されるメモリ位置にストアします |

これらの命令は明示的なオペランドを_取りません_。
オペランドは暗黙的です。

おおよその規則として：

1. ソースオペランドがメモリ位置の場合、そのアドレスは`rsi`に格納します（`s`はsourceの意味）。
2. 宛先オペランドがメモリ位置の場合、そのアドレスは代わりに`rdi`に格納します（`d`はdestinationの意味）。
3. オペランドの1つがメモリ位置でない場合、それは`rax`レジスターです。

これらの命令は、実行する特定の操作に応じて、メモリアドレスを自動的に逆参照することに注意してください。

これらはすべて、異なるサイズで動作できます。
このサイズを示すために接尾辞が付けられます。

| 接尾辞 | 意味 | サイズ |
| :----: | ------- | :------ |
|  `b`   | バイト    | 1バイト  |
|  `w`   | ワード    | 2バイト |
|  `d`   | ダブルワード   | 4バイト |
|  `q`   | クアッドワード   | 8バイト |

例：

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

また、使用されたアドレスを操作のサイズだけ更新します。
この更新は**方向フラグ（DF）**の値に従って行われます。

- `DF`がクリアされている場合、アドレスは操作のサイズだけ_増加_します。
- `DF`がセットされている場合、アドレスは代わりに同じ量だけ_減少_します。

System V ABIでは、関数に入った時点で方向フラグをクリアしなければならないと定められています。
したがって、_デフォルトの動作では、メモリはアドレスの昇順で読み書きされます_。

命令`cld`は方向フラグをクリアするために使用でき、命令`std`は方向フラグをセットするために使用できます。

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
呼び出し元は、System V ABIに従い、呼び出された関数が戻った後に`DF`がクリアされていることを期待します。
`DF`をセットした場合は、必ず`ret`の前にクリアしてください。
~~~~

### Rep

これらとは別に、**rep**命令はメモリと直接やり取りしません。
代わりに、前述の他の命令に接頭辞として追加して、それらの命令を_繰り返す_ことができます。

`rep`を接頭辞として付けると、文字列命令は`rcx`の値と同じ回数だけ繰り返されます。
そのたびに、`rcx`の値は`1`ずつ減らされます。
`rcx`の値は命令を使用する前に設定しておく必要があることに注意してください。

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
現代のCPUでは、大きなブロックでデータを移動する場合、`rep movs`と`rep stos`は通常高速な選択肢です。
しかし、他の文字列命令や、`rep`なしで動作する`movs`や`stos`でさえ、通常は単純なループより遅いです。
