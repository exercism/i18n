# はじめに

プログラムで独自の型を定義できると、便利なことがよくあります。

新しいプリミティブ型を作ることも可能ですが、ほとんど行われません。
組み込みのプリミティブ型は、恣意的に選ばれたものではありません。JuliaがJITコンパイルに使うLLVMコンパイラーの標準型と密接に対応しています。

もっと便利なのは、名前付きフィールドを持つ複合型を定義できることです。

他の言語にも似た仕組みがあり、`structs`や`records`と呼ばれています。
Juliaのドキュメントでは`composite types`と呼んでいますが、（少し食い違いがありますが）言語の構文では`struct`キーワードを使って定義します。

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

上の例では、いくつか注目すべき点があります。

- `id`の型が指定されていないため、コンパイラーはこれを`id::Any`と解釈します。
  - 実際には、フィールドの型を具象型で指定してコンパイラーを助けるのが最善です。
- 型名はコンストラクターとして使われ、`Person(id, name, age)`のように書くと、型`Person`のインスタンスを作成します。
- 個々のフィールドには、名前付きタプルと同じようにドット記法でアクセスできます。

型`Person`の値はイミュータブルなので、更新できません。

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

可変性が必要な場合は、定義に`mutable`を追加します。

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

コンストラクターは、デフォルトでは定義と同じ順序でフィールドを並べる必要があり、複雑な型では不便になります。

`@kwdef`マクロを使うと、2つの新しい機能が使えるようになります。

- コンストラクターが位置ではなくキーワードを使うようになります。
- フィールドにデフォルト値を設定でき、コンストラクターで省略することもできます。

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## 複合型の階層

ここまでは、具象複合型だけを作成してきました。
確認すると、すべて`Any`のサブタイプです。

複数の関連する型を作成するときは、それらの階層を定義する方が理にかなっていることが多いでしょう。
これはとても簡単にできます。

まず、抽象型を作成します。

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

次に、型定義に`<:`演算子を含めて、関係を示します。

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

必要に応じて繰り返しますが、具象型のサブタイプ化はできないことに注意してください。

より複雑な階層が必要な場合は、必要に応じて抽象サブタイプを作成します。

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

このような階層の価値は、`Multiple Dispatch`の概念まで進み、関数が引数の型をどのように扱うかを見ると、より明確になるでしょう。
