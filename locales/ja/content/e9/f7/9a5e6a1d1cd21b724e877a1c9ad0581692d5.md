# 説明

貨物船で無線通信士をしています。信号は雑音だらけの回線を通して届きます。船の機械の音、天候による空電、ときどき混ざる外国語の通信。それらに紛れて、本来聞き取りたいモールス信号が流れてきます。メッセージを捉えるには、回線の信号を*テープ*装置に通します。この装置は、有効なモールス符号（`.`、`-`、および文字と文字の区切りとなる空白）以外をすべて取り除いてくれます。

ここでの課題は、このテープをFactorのカスタム入力ストリームとして組み立てることです。

## 1. テープを定義する

`disposable`を継承し、基になる入力ストリームを保持するスロット`wire`を1つ持つ`tape`タプルを定義しましょう。

```factor
TUPLE: tape < disposable wire ;
```

次に、コンストラクター`<tape> ( wire -- tape )`を書きましょう。デストラクターの仕組みがテープを登録できるよう、`new`ではなく`new-disposable`を使い（`new`ではありません）、基になるストリームは`wire`スロットに保存しましょう。

## 2. input-streamミックスインを組み込む

`tape`を`input-stream`として宣言しましょう。

```factor
INSTANCE: tape input-stream
```

こうすると、プロトコルの既定のコンビネーターが、定義したクラスにディスパッチされるようになります。

## 3. モールス符号を1つ読み取る

`M: tape stream-read1 ( tape -- elt/f )`を実装しましょう。基になるwireからバイトを読み取り、`CHAR: .`、`CHAR: -`、`CHAR: \s`（空白）のいずれかに当たるまで進めます。そのバイトを返します。wireが`f`（ストリームの終端）を返したら、こちらも`f`を返します。テープの役割はそこで終わりです。

```factor
"x.y -ab cz" <string-reader> <tape>
[ stream-read1 ] [ stream-read1 ] [ stream-read1 ] tri
! => CHAR: . CHAR: - CHAR: \s
```

## 4. 要素の型を委譲する

`M: tape stream-element-type ( tape -- type )`を実装し、wireに委譲しましょう。テープは、読み取る要素の種類を変えません。

## 5. 後片付けをする

`M: tape dispose* ( tape -- )`を実装しましょう。フレームワークは、`dispose`が呼ばれるたびに、定義したメソッドをちょうど1回呼び出します。あとは基になるwireを破棄するだけです。

この5つの部品がそろえば、テープは通常の入力ストリームとして機能します。`with-input-stream`や`stream-read`をはじめ、ほかのプロトコルのワードはすべて、定義したメソッドに自動的にディスパッチされます。
