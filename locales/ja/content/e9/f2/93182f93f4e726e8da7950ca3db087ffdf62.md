# ユニオン型

Crystalでは、変数が複数の型を持つことができます。これを[ユニオン型][union-type]と呼びます。Crystalでは、コンパイラーがユニオン型を推論するのが一般的です。

~~~~exercism/note
ユニオン型は、複数の型からできていても、実行時には1つの型です。つまり、`String`と`Int32`からなるユニオン型が、同時にその両方になることはありません。その代わり、`String`か`Int32`のどちらかになります。
~~~~

ユニオン型は、型をパイプ（`|`）で区切って宣言します。多くの場合、括弧（`()`）で囲みますが、必須ではありません。もっともよく見るユニオン型は、`T`を型とすると`(T | Nil)`で、これは`Nil`を返す可能性があるメソッドに現れます。これは、その変数が**nil可能**であるとも言われます。

```crystal
foo : String = "Hello"
foo = nil # Error: type must be String, not (String | Nil)

foo : (String | Nil) = "Hello"
foo = nil
```

型は2つに限らず、いくつでも組み合わせられます。

```crystal
foo : (String | Int32 | Nil | Float64) = "Hello"
foo = 1
foo = nil
foo = 1.0
```

## `typeof`と`Object#class`の違い

変数の型を調べる方法は2つあります。[`typeof`][typeof]を使うか、[`Object#class`][Object#class]を使うかです。違いは、`typeof`がコンパイル時に変数の型を返すのに対し、`Object#class`は実行時に型を返すことです。つまり、たとえば変数がユニオン型かどうかを調べたいとき、`Object#class`ではそれがわかりません。実行時に返るのは1つの型だけだからです。

```crystal
foo = 0 == 0 ? "a" : 1
typeof(foo) # => (String | Int32)
foo.class # => String
```

## ユニオン型の操作

ユニオン型は実行時には1つの型なので、通常の操作はすべて使えます。ただし、コンパイル時にはコンパイラーがどの型なのかを知っている必要があります。そのため、型ごとの操作を使いたいときは、その型のどれか1つにしかなり得ないようにコードを書く必要があります。

```crystal
foo : (String | Int32) = "Hello"
foo.downcase # Error: undefined method 'downcase' for (String | Int32)
```

Crystalには、ユニオン型のための特別なメソッドがあります。`is_a?`メソッドです。これは型を引数に取り、真偽値を返します。`nil?`メソッドは`is_a?(Nil)`の省略形です。`is_a?`メソッドを制御式の中で使うと、コンパイラーにその型であることを伝えられ、その型であることが保証されます。また、`else`の分岐では、その型ではないことが保証されます。

```crystal
foo : (String | Int32) = "Hello"
if foo.is_a?(String)
  typeof(foo)  # => String
  foo.downcase # => "hello"
end
```

この`is_a?`は、引数に1つの型だけでなくユニオン型を取ることもできます。`&&`と組み合わせて複数の型を指定することもできます。

~~~~exercism/note
`is_a?`メソッドを制御式と組み合わせて使う場合、そのレシーバーをインスタンス変数やクラス変数にすることはできません。その場合は、まずローカル変数に代入する必要があります。
~~~~

## `as`

ユニオン型を1つの型にする方法の1つは、特定の型のときだけその分岐に入るようにすることです。もう1つの方法は、[`as`][as]メソッドを使うことです。これは実行時にチェックすることで、ユニオン型を1つの型にします。型が期待したものでなければ、例外が発生します。

```crystal
foo : String | Int32 = "Hello"
foo.as(String).downcase # => "hello"

foo.as(Int32) # Error: can't cast String to Int32
```

~~~~exercism/caution
この方法は、型が期待したものであると確信しているとき、またはそうでないときに例外を発生させたいときだけのものです。

不適切な使い方をすると、予期しない動作につながることがあります。
~~~~

## `as?`

[`as?`][as?]は`as`とよく似た働きをしますが、型が期待したものでないときに例外を発生させる代わりに`nil`を返します。つまり、期待した型と`Nil`のユニオン型を返します。

```crystal
foo : (String | Int32) = "Hello"
foo.as?(String).downcase # => "hello"

foo.as?(Int32) # => nil
```

## nil可能の省略形

nil可能とは、変数が何らかの型か`Nil`のどちらかになり得るという意味です。これは`(T | Nil)`と書けます。ただし、nil可能な型は比較的よく登場するので、省略形が用意されています。`T?`です。

```crystal
# This:
foo : (String | Nil) = "Hello"
foo = nil

# Is the same as:
foo : String? = "Hello"
foo = nil
```
