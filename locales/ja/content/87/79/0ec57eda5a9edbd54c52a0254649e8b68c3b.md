# 指示の補足

## `from_quote`の長所と短所
この演習では、`Time`型に`from_quote`関数を定義します。これにより、次のようなコードを書くことができます。

```roc
time : Time
time = "00:01:23"
```

このコードは、コンパイル時に暗黙的に`Time.from_quote("00:01:23")`を呼び出します。実行時にパース処理を行う必要がないためプログラムを高速化できる可能性があり、また`from_quote`が拒否する時間は実行時ではなくコンパイル時に検出されます。さらに、コードが読みやすくなります。たとえば、この演習にあるテストの1つを見てみましょう。

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

ただし、このコードを読んだ人は、`advance_time`関数が`Time`ではなく`Str`を受け取るのだと誤解するかもしれません。これは混乱やエラーのもとになります。そのため、少し長くなりますがより明確な`"00:00:05".Time`という書き方のほうが好ましいかもしれません。こちらもコンパイル時に`from_quote`を呼び出します。

自分のプログラムでは、代わりに`from_str`を使うほうがよいかもしれません。

```roc
Time := { ... }.{
    from_str : time_str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

また、次のように、コンパイル時に`from_str`（または他の純粋な関数）を呼び出すこともできます。

```roc
Ok(time) = Time.from_str("00:01:23")
```

補足：この定義をトップレベルに置くと、コンパイル時に実行されます（関数が純粋で、その入力がコンパイル時にわかっているためです）。関数の中では、実行時に`from_str`を使えます。
