# はじめに

ほとんどの場合、Factorでは`each`や`map`、`count`といったコンビネーターを通して繰り返しを扱います。しかし、計算をいちばんきれいに書き表せるのが**再帰**、つまり自分自身を呼び出すワードであることもあります。

## 再帰的なワードを定義する

`:`定義は自分自身を直接呼び出せます:

```factor
: count-down ( n -- )
    dup 0 = [ drop ] [ dup . 1 - count-down ] if ;

5 count-down
! prints 5 4 3 2 1
```

## 空かどうかで分岐する

[`sequences`][sequences]内の`if-empty`は、再帰の自然な基底ケースです:

```
if-empty ( seq emptyquot nonemptyquot -- )
```

```factor
{ 4 0 9 } [ "empty" ] [ "got data" ] if-empty .
! => "got data"
```

`emptyquot`は、（空の）シーケンスがすでに消費された状態で実行されます。`nonemptyquot`は、シーケンスがまだスタックにある状態で実行されます。

## `cond`：ガード付きの分岐の連鎖

再帰のケースが3つ以上あるときは、[`combinators`][combinators]内の`cond`を使うと、コードを読みやすく保てます:

```factor
: classify ( n -- label )
    {
        { [ dup 0 < ] [ drop "negative" ] }
        { [ dup 0 = ] [ drop "zero"     ] }
        [ drop "positive" ]
    } cond ;
```

## `DEFER:`による前方参照

`:`定義は自分自身を直接呼び出せますが、2つのワードが*互いを*呼び出す場合、パーサーは2つ目のワードが存在する前に1つ目を見てしまいます。`DEFER:`は名前を確保し、最初の定義をコンパイルできるようにします:

```factor
DEFER: even?

: odd? ( n -- ? ) dup 0 = [ drop f ] [ 1 - even? ] if ;
: even? ( n -- ? ) dup 0 = [ drop t ] [ 1 - odd? ] if ;
```

`DEFER:`は、ヘルパーワードがそれを使うワードの*後*に読むほうが自然な場合にも便利です。
