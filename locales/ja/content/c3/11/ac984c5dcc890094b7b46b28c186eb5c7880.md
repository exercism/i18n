# 説明

友人のLeticiaは、地下鉄の駅にある遺失物取扱所で働いています。

見つかった品物はすべて、その日の品物リストに新しいエントリーとして追加されます。
月末になると、引き取り手のない品物は、見つかった日付が記された箱の保管場所に移されます。
これらはすべて紙で管理されているので、ときどき手に負えなくなってしまいます！

Leticiaは、これらの作業の一部を自動化するのを手伝ってほしいと頼んできました。

~~~~exercism/note
このコンセプトで登場する命令は次のとおりです：

| 命令   | 説明                                               |
|---------------|-----------------------------------------------------------|
| push a        | aをスタックにプッシュし、`rsp`をaのサイズだけ減らします  |
| pop a         | aをスタックからポップし、`rsp`をaのサイズだけ増やします  |
~~~~

## 1. 各品物のエントリーを作成する

まず最初に、すべての品物を整理して、もっと簡単に探せるようにする必要があります。
各品物は、保管庫の中で、ID、説明、見つかった日付、そして可変個のカテゴリーによって識別されます。

戻り値を持たず、あるメモリ位置に品物の新しいエントリーを挿入する関数`create_item_entry`を定義しましょう。
この関数は任意の数の仮引数を取ることができ、そのうち最初の6つは常に次のとおりです：

1. エントリーを保存するメモリ上の位置のアドレス。
2. 品物のID（64ビット符号なし整数）。
3. 品物の説明を表す文字列のアドレス。
4. 品物が見つかった日（64ビット符号なし整数）。
5. 品物が見つかった月（64ビット符号なし整数）。
6. 品物のカテゴリー数（64ビット符号なし整数）。

それ以降の仮引数はそれぞれ、カテゴリーの1つを表す文字列のアドレスです。

値は、与えられたメモリ位置に、引数と同じ順序で保存します：ID、説明、日、月、カテゴリー数、そして各カテゴリーを順番に。

## 2. 月ごとの品物リスト用の領域を確保する

これほど多くの異なるリストから品物を探すのは面倒です。
そこで、すべてを月ごとに1つのリストにまとめることにします。
このリストは配列として実装します。

配列用のメモリ領域を確保し、そのメモリ位置のアドレスを返す関数`create_monthly_list`を定義しましょう。
次のものを仮引数として取ります：

1. 配列の容量（バイト単位、64ビット符号なし整数）。
2. アロケーター関数。

アロケーター関数は、確保するメモリのサイズ（バイト単位）に対応する64ビット符号なし整数を仮引数として取り、確保した領域のアドレスを返します。

確保された領域の値は_未定義_なので、その領域のすべてのバイトをクリアする必要があります。つまり、値を`0`に設定します。

## 3. 月ごとのリストに品物を挿入する

毎日、見つかった品物はすべて月ごとのリストに挿入します。

戻り値を持たず、次のものを仮引数として取る関数`insert_found_item`を定義しましょう：

1. 月ごとのリストがあるメモリ上の領域のアドレス。
2. リストにすでに保存されている現在のエントリー数（64ビット符号なし整数）。
3. リストに追加する新しいエントリー。

新しいエントリーは常にリストに収まり、リストの各エントリーは120バイトの領域を占めると考えてかまいません。

## 4. 品物を出力する

特定のエントリーを探すのは、Leticiaがそれを画面に出力して見ることができれば、ずっと簡単になります。

次のものを仮引数として取る関数`print_item`を定義しましょう：

1. 導入用のASCII NUL終端文字列を保存できるバッファのアドレス。
2. 月ごとのリストがあるメモリ上の領域のアドレス。
3. 出力する品物に対応する、配列内のエントリーのインデックス（64ビット符号なし整数）。
4. 出力関数。

この関数は戻り値を持たず、次の引数で出力関数を呼び出す必要があります：

1. 導入用の文字列が保存されているメモリ位置のアドレス。文字列が渡されない場合は`0`（64ビット整数）。
2. 出力する品物に対応する、配列内のエントリーのインデックス（64ビット符号なし整数）。
3. 品物のID（64ビット符号なし整数）。
4. 品物の説明を表す文字列のアドレス。
5. 品物が見つかった日（64ビット符号なし整数）。
6. 品物が見つかった月（64ビット符号なし整数）。
7. 品物のカテゴリー数（64ビット符号なし整数）。
8. 最初のカテゴリー文字列のアドレス。

導入用の文字列は省略可能です。
この文字列を出力関数で使う場合は、NUL終端（`0`で終わる）である必要があり、NUL終端文字を含めて最大50文字でなければなりません。
そうでない場合は、代わりに値`0`を出力関数に渡します。

リストの各品物は120バイトの領域を占めると考えてかまいません。
