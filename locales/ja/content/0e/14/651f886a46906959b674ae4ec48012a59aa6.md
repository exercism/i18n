# テスト

Elmプロジェクトのテストは、そのプロジェクトの`tests/`サブディレクトリにあります。各演習のテストスイートは、その演習のルートディレクトリから実行できます。

```bash
$ cd ~/exercism/elm/hello-world
$ elm-test
```

## 変更を監視する

変更を保存すると、テストが自動的に再実行されます：

```bash
$ elm-test --watch
```

## テスト駆動開発の流れ

ほとんどの演習では、テストは`tests/Tests.elm`ファイルにすでに書かれています。`src/<exercise>.elm`ファイルに必要なコードを書いて、テストに通るようにすることが目標です。まず最初に失敗するテストに注目して、それを修正します。次に、テストファイルにある次の`skip <|`の部分を削除するかコメントアウトして、すべてのテストが通るまで繰り返します。

## 行き詰まったら

まずは、`Debug.todo`が入っていてもいいので、コードがコンパイルできる状態を目指しましょう。何かをどうやればいいかわからないときは、その部分を未実装の関数として切り出すとよいことがよくあります。

```elm
complexOperationOnMultipleStrings : List String -> List String
complexOperationOnMultipleStrings allStrings =
    List.map complexOperation allStrings


complexOperation : String -> String
complexOperation input =
    Debug.todo "Extracted operation into its own function"
```

切り出した関数に型注釈を付けると、考えを整理しやすくなるだけでなく、コンパイラーがより良いエラーメッセージを出してくれるようにもなります。

## コードを整える

コードを提出する前に、[`elm-format`](https://github.com/avh4/elm-format)を実行してみることを検討しましょう。テキストエディターで保存時に自動フォーマットするように設定するのもよいでしょう。
