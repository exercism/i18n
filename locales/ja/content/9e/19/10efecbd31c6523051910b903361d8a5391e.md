# はじめに

関数型プログラミングとは何でしょうか？

ここでは、その主な特徴をいくつか挙げます。

- 純粋関数：入力を出力へと一貫して対応付け、副作用を持ちません。
- 不変のデータ。
- 第一級関数：ほかの型と同じように、値として扱えます。
- 高階関数：ほかの関数を引数として受け取ったり、戻り値として返したりします。

ただし、Rは純粋な関数型言語ではありません（たとえばHaskellとは異なります）。

Rは実用本位の言語だと考えてください。作業をきれいに簡単に片付ける手段として、関数型の機能が（ますます）用意されています。
一般に、目的はデータ分析であり、プログラミングはそのための手段にすぎません。

## パイプ

関数をつなぐためにパイプ`|>`を使う手法は、いくつかの言語でますます一般的になっています。

要点は次のとおりです。

- パイプの左側の結果が、右側の関数の最初の引数になります（ここでの「右側」は、任意の改行を無視します）。
- 残りの引数は、関数呼び出しに含めることができます。
- Rでは、関数の_名前_だけでなく関数_呼び出し_にパイプしなければならないため、常に括弧（`()`）が必要です（_これはほかの言語とは異なります_）。

コードを読むときに、パイプを「then」と読むとわかりやすいと感じるプログラマーもいます。ステップ1を実行し、THEN（次に）ステップ2を実行する、という具合です。

次の例は、この構文を示しています。

```R
library(stringr)

"Monday-25-February" |> 
  str_split("-") |>     
  unlist() |>               # [1] "Monday"   "25"       "February"
  str_sub(1, 3) |>          # [1] "Mon" "25"  "Feb"
  str_to_upper() |>         # [1] "MON" "25"  "FEB"
  str_flatten(collapse = ", ")
#> [1] "MON, 25, FEB"
```

このタイプのパイプは、R 4.1.0でBase Rに追加されました。「ネイティブパイプ」と呼ばれることもあります。

RStudioのエディター（ほかのエディターも同様）では、`Ctrl-Shift-M`というキーボードショートカットで、適切なスペースを入れたパイプを追加できます。

## apply関数

以前見たように、Rの多くの関数は「ベクトル化」されています。明示的にループを書かなくても、ベクトル全体にわたって処理を行います。

ベクトル化された関数だけを使っている関数も、それ自体が自動的にベクトル化される可能性が高いです。
簡単な例を見てみましょう。

```R
triple <- function(x) return(3 * x)
triple(1:10)
 [1]  3  6  9 12 15 18 21 24 27 30
 ```

しかし、より複雑な関数は、たとえばループや`if-else`ブロックを含んでいると、ベクトルを入力として受け取れないことがあります。

ベクトルに関数を適用する、より一般的な方法が必要です（ほかの言語の`map()`に似ています）。

Rの基本言語には多様なデータ構造が用意されているため、それらを操作する`*apply()`関数の一族も存在します。
より専門的には、関数を引数として受け取ることから、プログラマーはこれらを「高階関数」、数学者は「汎関数」と呼ぶことがよくあります。

ここでは、`lapply()`と`sapply()`を見てみましょう。

### `lapply()`

「List-apply」はリストの入力を対象に設計されていますが、必要に応じてベクトルは黙ってリストに変換されます。

出力はリストなので、ベクトルにするには展開が必要になる場合があります。

```R
h <- function(size) {
    switch(size,
           "small" = 6,
           "medium" = 8,
           "large" = 10
    )
}

v <- c("small", "large", "medium")

h(v) # bad use of an unvectorized function
#> Error in switch(size, small = 6, medium = 8, large = 10) : 
#>   EXPR must be a length 1 vector

lapply(v, h)  # output is a list
#> [[1]]
#> [1] 6

#> [[2]]
#> [1] 10

#> [[3]]
#> [1] 8

lapply(v, h) |> unlist() # output is a vector
#> [1]  6 10  8
```

[Switchの概念][concept-switch]に馴染みのある学習者は、スカラーの`switch`を、[`dplyr`][ref-dplyr]ライブラリーのベクトル化された[`recode_values()`][ref-recode_values]に置き換えることもできると気づくかもしれません。
ベクトル化はよいことであり、現代のRにはそれを実現する方法がいくつも用意されています。

```R
library(dplyr)

h <- function(size) {
  recode_values(size,
         "small" ~ 6,
         "medium" ~ 8,
         "large" ~ 10
  )
}

v <- c("small", "large", "medium")
h(v)
#> [1]  6 10  8
```

### [`sapply()`][ref-lapply]

「Simplified-apply」は`lapply`と同様のことをしますが、戻り値の簡略化も試みます。たとえば、リストの代わりに名前付きベクトルを返します。
状況によっては、[`unname()`][ref-unname]を使う必要があるかもしれません。

```R
sapply(v, h)
 small  large medium 
     6     10      8 

sapply(v, h) |> unname()
#> [1]  6 10  8
```

## `purrr`ライブラリー

`lapply`と`sapply`はシンプルで、ほとんどのRユーザーにとって馴染み深く、ベクトルや単純なリストには今でもよく使われています。

Base Rには、ほかにも_たくさん_のapply関数があります。
こうした混乱に対して、よりシンプルで一貫性のある代替手段を提供することが、Tidyverseの主要な目標です。

現在では`purrr`パッケージがあり、`map()`のようないくつかの追加の選択肢を提供するとともに、設計の一貫性とエラーメッセージのわかりやすさを高めています。

Base Rよりも後方互換性の制約が少ないため、このパッケージは、ほかの言語に見られる現代的な関数型プログラミングにRを大きく近づけます。

`purrr`には多種多様な関数があり、簡単にはまとめられません。
このライブラリーを使いこなすための資料には、次のようなものがあります。

- [ウェブサイト][web-purrr]（[入門][web-starting]ガイドを含む）。
- すべての関数の[リファレンスページ][ref-purrr-funcs]。
- PDF形式の[チートシート][cheat-purrr]。
- [Base R][web-from-R]からの移行ガイド。

### さまざまなmap関数

[map()][ref-map]関数は、入力の各要素に関数を適用し、常に[リスト][concept-lists]を返します。

ここまでは、名前が変わっただけの、おそらくエラーメッセージがより親切な[`lapply()`][ref-lapply]のように思えるかもしれません。

しかし、`map()`は_大きな_一族の一員にすぎません。

関数を選ぶときに考えるとよい問いをいくつか挙げます。

- 何を返したいですか？　[`map()`][ref-map]は常にリストを返しますが、特定の型のアトミックベクトルがほしい場合は、文字列なら[`map_chr()`][ref-map_chr]、整数なら[`map_int()`][ref-map_int]などを使います。
- 入力の各位置のインデックスが必要ですか？　その場合は、[`imap()`][ref-imap]のように、関数名の前に`i`を付けます。
- 複数の入力を並行して処理したいですか？
  - 名前の`map`を`map2`に置き換えます。たとえば、2つの入力（値と重みなど。加重平均を計算するときに使います）には[`map2_dbl()`][ref-map2_dbl]を使います。
  - 並列な入力のリストには`pmap`に置き換えます。たとえば[`pmap_chr()`][ref-pmap_chr]です。もちろん、ハードウェアレベルの並列処理も可能です。
- 入力のすべての要素を処理したいですか？　そうでない場合は、述語（真偽値）によるフィルターを適用する[`map_if()`][ref-map_if]、位置のインデックスで条件を指定する[`map_at()`][ref-map_at]、要素が述語を満たさなくなるまで入力を処理する[`head_while()`][ref-head_while]を検討しましょう。
- 入力データが深く入れ子になっていますか？　そういう場合のための[関数][ref-plucks]があります。
- 戻り値が常に入力と同じ型であってほしいですか？　その場合は`map`の代わりに[`modify()`][ref-modify]関数を、再帰的に適用するなら[`modify_tree()`][ref-modify_tree]を使います。

これらの関数は、パイプとうまく組み合わせられるように、可能な限り入力データを最初の引数に取ります。

また、`purrr`は（意図的に）Base Rよりも細かいところまでうるさくできています。特定のものを求めた場合、関数は_まさに_それを返すか、エラーメッセージを出して停止します。
厳しいですが、見つけにくいバグを減らすのにはとても効果的です。

### reduce関数

map関数は一般に、入力と同じ長さの戻り値を返します。

ほかの関数の中には、`sum()`のように、データの次元を_減らす_ものもあります。

```R
sum(1:100)
#> [1] 5050
```

上の例では、長さ100のベクトルを長さ1の整数に変換しています。
行列と配列に関する今後の概念で、次元を減らすという考え方がより一般的なものであることを見ていきます。

`sum()`関数は組み込みです（ほかの多くの統計関数も同様です）。
しかし、`map()`に相当する高階関数を使って、任意の次元削減関数をデータ構造全体に適用する方法が必要です。

ほかのいくつかの言語では、`fold`、`foldl`、`foldr`といった関数名が使われます。Rでは、該当する関数は[`reduce()`][ref-reduce]で、（アルゴリズム好きには）よく知られたMapReduceフレームワークに対応します。

最初の引数は、いつもどおり入力データです。2番目の引数は2つの引数を取る関数で、多くの場合無名関数ですが、`+`のような算術演算子と同じくらい単純なこともあります。

```R
# surround an infix operator with backticks, to use as a function
reduce(1:100, `+`)
#> [1] 5050  # same as sum(1:100)

# anonymous function, alternately add and subtract
reduce(1:10, \(accum, nextval) ifelse(nextval %% 2 == 0, accum + nextval, accum - nextval))
#> [1] 7
```

入力の先頭から関数を適用するか、末尾から適用するかは、結果に影響するのでしょうか？

`+`や`*`のような[結合的][wiki-associative]な演算子では影響しません。
明らかに、`(1 + 2) + 3 == 1 + (2 + 3)`です。

これに対して、`-`と`/`は結合的ではありません。

```R
(1 - 2) - 3
#> [1] -4
1 - (2 - 3)
#> [1] 2
```

方向が問題になる関数には、省略可能な`.dir`引数があります。

```R
# default is .dir = "forward"
reduce(1:10, `-`)
#> [1] -53
reduce(1:10, `-`, .dir = "backward")
#> [1] -5
```

`map()`や`map2()`と同様に、2つの入力ベクトルを並行して操作する[`reduce2()`][ref-reduce]関数もあります。

Rでは、ベクトルを扱うのが好まれます。
最終的な値が1つだけ得られるのではなく、途中のすべてのステップを見たいとします。

そのためには、[`accumulate()`][ref-accumulate]と`accumulate2()`という関数があります。
構文は`reduce()`と似ていますが、出力の型を指定するための省略可能な引数がいくつか追加されています。

```R
accumulate(1:10, `+`)
#> [1]  1  3  6 10 15 21 28 36 45 55
 ```

よく使われるaccumulateの種類には、それぞれ専用の関数があります。
[ベクトル関数][concept-vector-functions]の概念では、Base Rの[`cumsum()`][ref-cumsum]と`cumprod()`を扱いました。また、`dplyr`ライブラリーには、数値の平均を求める[`cummean()`][ref-dplyr-cum]、論理ベクトル用の`cumall()`と`cumany()`があります。

### フィルター関数

多くの場合、ある述語に一致する入力の要素を含めたい（または除外したい）ことがあります。

[ベクトルのフィルタリング][concept-vector-filtering]の概念では、そのための慣用的な方法を1つ見ました。

```R
v <- 1:3
v[v >= 2]
#> [1] 2 3
```

これは伝統的なRではよく使われますが、現代的な関数型のパイプラインにはあまりなじみません。

そのため、`purrr`には[述語関数][ref-predicates]が一式用意されており、パイプと組み合わせられるように、`f(input, func, ...)`という通常の引数の慣習に従っています。

名前はほかのほとんどの言語とは少し異なります（`filter`や`drop`のような名前は、Rではすでにまったく別の意味を持っています）。

対応する`purrr`の関数には、[`keep()`][ref-keep]と[`discard()`][ref-keep]のほか、いくつかあります。

また、単一の論理値を返す`all()`や`any()`の代わりに、[`every()`][ref-every]、[`some()`][ref-every]、[`none()`][ref-every]があります。
