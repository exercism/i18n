# はじめに

## 配列

アセンブリでは、あらゆるデータはバイトの並びです。
つまり、あらゆるデータは、それを構成するバイトの**配列**として見ることができます。

### 配列の要素にアクセスする

メモリ内の任意の値にアクセスするには、その**実効アドレス**を計算する必要があります。
実効アドレスは、次の要素で構成されることがある式です。

- _ベースアドレス_。たとえば、変数のラベルで示されるアドレスです。
- 1つの_インデックスレジスタ_。`1`、`2`、`4`、`8`のいずれかでスケーリングされることがあります。
- 符号付き32ビットの_ディスプレースメント_。ベースアドレスに加算される（または減算される）数値です。

このアドレスは_0から始まるインデックス_なので、オフセットなしのベースアドレスは変数の最初のバイトを指すことに注意してください。
これが、以前のコンセプトで行ってきたように、オフセットなしのラベルだけでメモリを参照すると、最初のバイトから始まる値が得られる理由です。

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64は[リトルエンディアン][endianness]です。
これは、複数バイトの値の最下位バイトが最も小さいメモリアドレスに格納されることを意味します。

したがって、複数バイトの値の個々のバイトにアクセスする場合、より上位のバイトに到達するには、ベースアドレスに正のオフセットを加える必要があります。

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

値のリストで宣言された初期化済み変数は、それらの値の配列であり、各要素は指定されたサイズを持ちます。
ただし、オフセットは常に**_バイト_**単位です。配列の各要素がより大きいサイズであっても変わりません。

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

アドレスはバイト単位であるため、配列内の任意の要素について、個々のバイトに直接アクセスできることに注意してください。

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

同じ理由で、1つの命令で要素のサイズを超えてアクセスすることも可能です。

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
アセンブリは配列アクセスに対して境界チェックを行いません。
配列の末尾を超えたインデックスは、配列の外側のメモリを読み書きします。
これにより、気付かないうちに誤った結果になったり、他のデータが破壊されたり、アクセスしたメモリがマップされていない場合は実行時障害が発生したりする可能性があります。
プログラマーは、すべての実効アドレスを配列内に収める責任があります。
~~~~

### 初期化済み配列のサイズを計算する

NASM（The Netwide Assembler、このトラックで使用されるアセンブラ）には、メモリ内の現在位置を示す特別なシンボル（`$`）があります。
このシンボルを使うと、配列がメモリ上で占める合計サイズを簡単に計算できます。

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

`example`の直後に使うと、`$`は配列の終端のメモリアドレスを表します。
つまり、`$ - example`は、そのアドレスとラベル`example`が指すアドレスとの差です。
これはまさに、`example`が指す配列が占める合計サイズ（バイト単位）です。

したがって、この値で`example_length`を定義すると、配列のサイズ（長さ）をバイト単位で格納する8バイトの変数を作成したことになります。

### `.bss`セクション

未初期化データは、**`.bss`セクション**で宣言します。
ほとんどのプラットフォームでは、このデータはプログラムの開始時にOSによって0で埋められます。

NASMでは、未初期化変数は、名前、データサイズを示すディレクティブ、予約する要素数を持ちます。
これらはそれぞれスペースで区切られます。

主なディレクティブと対応するデータサイズは次のとおりです。

| ディレクティブ | サイズ |
| :-------: | :------ |
|   resb    | 1バイト  |
|   resw    | 2バイト |
|   resd    | 4バイト |
|   resq    | 8バイト |

たとえば、これは`example`という名前の変数に`3`バイトの未初期化領域を予約します。

```x86asm
section .bss
    example resb 3
```

また、これは`arr`という名前の変数に`10`×`8`バイト（つまり`80`バイト）の未初期化領域を予約します。

```x86asm
section .bss
    arr resq 10
```

`section .bss`内の変数は可変です。つまり、読み書き可能です。

未初期化データにも、実効アドレスを使うことで、初期化済みデータと同じ方法でアクセスできます。
同様に、これらは静的記憶域期間を持ち、同じソースファイル内の任意の関数からアクセスできます（また、`global`で宣言されていれば、他のソースファイルからもアクセスできます）。

### `lea`命令で配列のアドレスにアクセスする

以前のコンセプトで扱ったように、`lea`命令は実効メモリアドレスを計算します。
同じ意味論に従って、配列内の任意の要素のアドレスを計算するのに使えます。

相対アドレス指定では、より複雑なアドレスを形成する前に、変数のアドレスをレジスタに読み込む必要がよくあることに注意してください。

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea`の利点の1つは、そのアドレスのメモリに実際にアクセスすることなく、アドレス計算用の演算を使って値を計算できることです。
これにより、どのレジスタもメモリアドレスを保持していない場合でも、算術計算を行うのに役立ちます。

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
