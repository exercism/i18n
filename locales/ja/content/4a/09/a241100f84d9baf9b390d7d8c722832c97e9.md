# Travisからの移行

こちらは`.travis.yml`の例です（`elm`トラックから抜粋したものです）：

```yml
sudo: false
language: node_js
node_js:
  - lts/*
script:
  - bin/fetch-configlet
  - bin/configlet lint
  - bin/build.sh
```

これを手早くGitHub Actionsに移行するには、次の手順で進めます：

## テンプレート変数を決める

| 変数                        | 値                                   |
| --------------------------- | ------------------------------------ |
| `<track>`                   | `elm`                                |
| `<image-name>`              | `ubuntu-latest`                      |
| `<action to setup tooling>` | `actions/setup-node@v1`              |
| `<install dependencies>`    | `npm ci` (happens inside `build.sh`) |
| `<code-extensions>`         | `.elm`                               |

> セットアップ用のアクションは[この検索](https://github.com/actions/?q=setup+node&type=&language=)で見つけました。
> イメージ名は[Travisのデフォルトディストリビューション](https://blog.travis-ci.com/2019-04-15-xenial-default-build-environment)を見て決めました。

## 手順を決める

- `bin/fetch-configlet`：[`configlet.yml`][workflow-template-configlet-yml]ワークフローを使うなら、もう必要ありません
- `bin/configlet lint`：[`configlet.yml`][workflow-template-configlet-yml]ワークフローを使うなら、もう必要ありません
- `bin/build.sh`：すべてをこなす単一のスクリプト

## 「スクリプト」を準備する

このトラックでは`bin`フォルダーを使うので、`bin`フォルダーの中に次のファイルを作成します：

```bash
# bin/pr
bin/build.sh
```

```bash
# bin/pr-check
echo "No checks yet"
```

```bash
# bin/ci
bin/build.sh
```

```bash
# bin/ci-check
echo "No checks yet"
```

これらを_別々の_バイナリとして作っておくと、あとで最適化しやすくなります。今の時点で何かをインライン化する必要はありません。

## テンプレートを埋める

こちらが[`workflows/ci.yml`][workflow-template-ci-yml]の差分です。

```diff

  #
- # Replace <track> with the track name
- # Replace <image-name> with an image to run the jobs on
- # Replace <action to setup tooling> with a github action to setup tooling on the image
- # Replace <install dependencies> with a cli command to install the dependencies
- # Replace <code-extensions> with file extensions that should trigger the workflow
- #
- # Find Github Actions to setup tooling here:
- # - https://github.com/actions/?q=setup&type=&language=
- # - https://github.com/actions/starter-workflows/tree/main/ci

- #

- # - scripts/ci-check
- # - scripts/ci
+ # - bin/ci-check
+ # - bin/ci

- name: <track> / main
+ name: elm / main

  on:
    push:
      branches: [main]
    workflow_dispatch:

  jobs:
    precheck:
-     runs-on: <image-name>
+     runs-on: ubuntu-latest

      steps:
        - uses: actions/checkout@v2
-       - name: Use <setup tooling>
-         uses: <action to setup tooling>
+       - name: Use Node LTS
+         uses: actions/setup-node@v1
          with:
-           # here, use the LTS/stable version of the track's tooling

        - name: Install project dependencies

    ci:
-     runs-on: <image-name>
+     runs-on: ubuntu-latest

      strategy:
        matrix:
-         # here, add all SUPPORTED versions only
-         # version: [10.x, 12.x, 14.x]
+         version: [10.x, 12.x, 14.x]

      steps:
        - uses: actions/checkout@v2
-       - name: Use <setup tooling> ${{ matrix.version }}
-         uses: <action to setup tooling>
+       - name: Use Node ${{ matrix.version }}
+         uses: actions/setup-node@v1
          with:
-           # below: see how to inject the version
-           # node-version: ${{ matrix.version }}
+           node-version: ${{ matrix.version }}

        - name: Install project dependencies
-         run: <install dependencies>
+         run: npm ci

-       - name: Run exercism/<track> ci (runs tests) for all exercises
```

[`workflows/pr.yml`][workflow-template-pr-ci-yml]も同じ変更ですが、変更された各ファイルを引数として`pr-check`と`pr`スクリプトに渡すbash-fuの部分だけは大きく異なります：

```diff
# # .github/workflows/pr.yml

# # ...

-       - name: Run exercism/<track> ci pre-check (stub files, config integrity) for changed exercises
+       - name: Run exercism/elm ci pre-check (stub files, config integrity) for changed exercises
          run: |
            PULL_REQUEST_URL=$(jq -r ".pull_request.url" "$GITHUB_EVENT_PATH")
            curl --url $"${PULL_REQUEST_URL}/files" --header 'authorization: Bearer ${{ secrets.GITHUB_TOKEN }}' | \
-             jq -c '.[] | select(.status == "added" or .status == "modified") | select(.filename | match("\\.(<code-extensions>|md|json)$")) | .filename' | \
+             jq -c '.[] | select(.status == "added" or .status == "modified") | select(.filename | match("\\.(elm|md|json)$")) | .filename' | \
-             xargs -r scripts/pr-check
+             xargs -r bin/pr-check

  # ...
```

## これで動くはずです

これだけでGitHub Actionsへの移行は完了します。あとはスクリプトを最適化していけます。

1. `build.sh`から、一度だけ実行すればよい手順を取り除き、`ci-check.sh`と`pre-check.sh`ファイルに切り出します（ヒント：`lint.sh`を作り、両方の「スクリプト」から呼び出すこともできます）
2. `pr.sh`と`pr-check.sh`には、入力引数を使ってチェック対象のファイルや演習を判断する最適化を加えます。
3. チェックをさらに追加します
4. チェックをローカルで実行する方法と、それぞれのチェックが何を達成しようとしているのかをドキュメントに書き加えます。
