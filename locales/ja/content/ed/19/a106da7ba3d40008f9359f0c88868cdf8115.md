# 概要

Gleamで値のパターンマッチングをするときは、パターンがその型の取りうるすべての値にマッチするようにしなければなりません。そうでないと、コードはコンパイルされません。

次の関数は、配列が空の場合を処理していないため、コンパイルできません。

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Gleamのプログラムでは、ほとんどの場合、考えられるすべてのケースを処理したいはずです。しかし、プロトタイプやちょっとしたスクリプトなどでは、正常系だけに注目し、それ以外のケースのコードは書かないこともあるでしょう。そこで登場するのが、Gleamの`let assert`です。

letアサーションを使うと、パターンをその型の取りうる値の一部にだけマッチさせることができ、値がパターンにマッチしなければ、プログラムはクラッシュします。`let assert`を使えば、上の関数は次のように書けます。

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleamのライブラリでは、letアサーションを決して使うべきではありません。プログラムがクラッシュするおそれがあるからです。代わりに`Result`型を使い、エラーの扱いはアプリケーションのエンジニアに任せるべきです。
