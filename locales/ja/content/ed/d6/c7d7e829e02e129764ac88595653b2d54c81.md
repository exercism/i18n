# 説明の補足

## Odin向けの説明

### 二分木におけるZipper

上の説明では、Zipperをローズツリー（1つのノードに複数の子）で説明していますが、Zipperの考え方はどんな木にも、さらにはリストにも当てはめることができます。
この演習では二分木（各ノードが2つの子を持つ）を使うので、子の数を動的に管理する方法ではなく、Zipperの操作そのものに集中できます。

説明に挙げた操作は、二分木に合わせて次のように更新されています。

| 操作            | 説明                                                                       |
| --------------- | -------------------------------------------------------------------------- |
|`zip_from_tree`  | 木からZipperを取り出します。フォーカスノードは根ノードです。                |
|`zip_to_tree`    | Zipperから木を取り出します。                                               |
| `zip_value`     | フォーカスノードの値を取得します。                                         |
| `zip_left`      | フォーカスノードの左の子にフォーカスを移し、新しいZipperを返します。        |
| `zip_right`     | フォーカスノードの右の子にフォーカスを移し、新しいZipperを返します。        |
| `zip_up`        | フォーカスノードの親ノードにフォーカスを移し、新しいZipperを返します。      |
| `zip_set_value` | フォーカスノードの値を設定し、新しいZipperを返します。                     |
| `zip_set_left`  | フォーカスノードの左部分木を設定し、新しいZipperを返します。                |
| `zip_set_right` | フォーカスノードの右部分木を設定し、新しいZipperを返します。                |

### メモリ管理

Odinでは、メモリを自分で管理する必要があります。
演習を簡単にしてZipperの操作に集中できるよう、木のノードと経路に割り当てられたメモリは、アリーナアロケーターによって自動的に管理されます。
メモリが必要なときは`new(Node)`と`new(Step)`で確保するだけでかまいません。木を操作し終えると、テストがアリーナの`free_all()`を自動的に呼び出します。
これは、Odinで定期的に動く処理（ゲームループや一連のリクエストとレスポンスなど）のメモリ確保を扱うときの、慣用的な方法です。

Odinのアロケーター、とくにアリーナアロケーターについてもっと知りたい場合は、次のドキュメントが参考になるでしょう。[The Allocator chapter in the Odin Overview][allocators-overview]、[Understand the Temporary Allocator; Understand arenas by Karl Zylinski][allocators-zylinksi]、[Linear/Arena Allocators by gingerBill][allocators-gingerbill]。
