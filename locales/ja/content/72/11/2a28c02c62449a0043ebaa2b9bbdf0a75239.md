# はじめに

## `rflags`レジスター

`rflags`という特別なレジスターがあります。
このレジスターの各ビットは、さまざまな条件を表すフラグのように機能します。

その一部を以下に示します。

| 名前 | 記号 | ビット |
| :------- | :----: | :-: |
| キャリー |   CF   |  0  |
| ゼロ |   ZF   |  6  |
| 符号 |   SF   |  7  |
| オーバーフロー |   OF   | 11  |

## 比較命令

`rflags`のフラグは、_直接_変更されることはありません。
代わりに、さまざまな命令によって設定されます。

たとえば`ZF`は、演算やビット演算の結果がゼロになったときに設定されます。

条件を調べるためによく使われる命令の1つが`cmp`です。
`cmp`は2つのオペランドを受け取り、フラグを更新しますが、**オペランド自体は変更しません**。

### `cmp`命令

`cmp`命令は、第1オペランドから第2オペランドを引き、その結果に応じてフラグを設定します。

Aを第1オペランド、Bを第2オペランドとすると：

| フラグ | 設定される条件 |
| :--: | :----------------------------- |
|  CF  | A < B（符号なし）               |
|  ZF  | A == B                         |
|  SF  | A < B（符号あり、オーバーフローなし）    |
|  OF  | 符号ありの減算でオーバーフローが発生 |

## 分岐

x86-64では、コードは原則として上から下へと順番に実行されます。

しかし、この動作を変える必要がある場面は数多くあります。
たとえば、ある条件に応じて別の命令群を実行したい場合です。

高水準言語では、通常`if...else`のような抽象的な構文を使ってこれを実現します。
しかし、x86-64にはそのような構文はありません。

その代わりに、x86-64には、実行をコードの別の位置へ移す命令が用意されています。
これを`branching`と呼びます。

~~~~exercism/note
これまでに、そうした命令を2つ見てきました。`call`と`ret`です。

関数が呼び出されると、実行は呼び出し元から呼び出された関数へ移ります。
そして、戻るときには、実行は呼び出し元へ戻ります。

`ret`が見つからない場合、実行はある関数から次の関数へとそのまま流れていきます。
これはときに、コードの流れを最適化するために利用できます。
~~~~

### 無条件ジャンプ

**jmp**命令は、プログラムの実行をコードの別の位置へ無条件に移します。
その唯一のオペランドはラベルで、実行が続く位置のアドレスを持ちます。

たとえば、次の関数を見てみましょう。

```x86asm
fn:
    mov rax, 5
    jmp end

    add rax, 10
end:
    ret
```

`fn`が呼び出されると、実行は`mov rax, 5`から始まります。
これにより、その時点で`rax`の値が5になります。

次の命令は`jmp end`で、実行をラベル`end`へ移します。

`end`の次にある命令は`ret`で、実行を呼び出し元の関数へ戻します。

`add rax, 10`は`jmp end`の後、`end`の前に位置しているため、決して実行されないことに注目してください。
`fn`が戻るときの`rax`の値は5です。

### 条件付きジャンプ

**jcc**命令群は、特定の条件が満たされたときにだけ、プログラムの実行を別の位置へ移します。
そうでない場合は、実行はそのまま順番に続きます。

それぞれの条件は、`rflags`内の1つまたは複数のフラグに対応します。
`jcc`のいくつかの変種はフラグがセットされていることを調べ、別の変種はフラグがクリアされていることを調べます。

`jcc`の`cc`はそのままの文字ではなく、調べるフラグに対応する特定の接尾辞を指します。

接尾辞はたくさんあり、その多くは別の接尾辞と同じ条件を調べます。
そのうちのいくつかはフラグを直接参照し、特定のフラグがセットされていればラベルへジャンプします。

| 接尾辞 | ジャンプする条件 |
| :----: | :------: |
|   z    | ZF == 1  |
|   c    | CF == 1  |
|   s    | SF == 1  |
|   o    | OF == 1  |

ほかの多くは、`cmp`命令における意味を表すように選ばれています。
たとえば：

| 命令 | 接尾辞 | ジャンプする条件         |
| ----------- | :----: | :--------------- |
| cmp A, B    |   e    | A == B           |
| cmp A, B    |   l    | A < B（符号あり）   |
| cmp A, B    |   b    | A < B（符号なし） |
| cmp A, B    |   g    | A > B（符号あり）   |
| cmp A, B    |   a    | A > B（符号なし） |

`l`、`b`、`g`、`a`の後に`e`を付けると、条件に等号を含めることができます。

```x86asm
cmp rcx, r8
jge two      ; this jumps to 'two' if rcx is greater than, or equal to, r8 in a signed comparison
jbe two      ; this jumps to 'two' if rcx is lesser than, or equal to, r8 in an unsigned comparison
```

すべての接尾辞には、反対の動作を調べる変種があります。
構文は同じですが、接尾辞の前に`n`が付きます。

たとえば`jnz`は、`ZF`がセットされて**いない**ときにジャンプします。
同様に`jnae`は、AがB以上では**ない**ときにジャンプします（AとBは符号なし整数として解釈されます）。

~~~~exercism/note
同じ条件に対する別名になっている接尾辞もあります。
たとえば`jz`（接尾辞`z`、`ZF`に対応）と`je`（接尾辞`e`、等しいことに対応）は、どちらも`ZF`がセットされているときにジャンプします。
これは、`cmp`では減算の結果がゼロになるとき、つまり2つのオペランドが等しいときに`ZF`がセットされるためです。

一方、ほかの接尾辞は複数のフラグの組み合わせを調べるため、単一のフラグの接尾辞で直接置き換えることはできません。

比較の意味をよりよく表す接尾辞を選ぶようにしましょう。
~~~~

## ローカルラベル

ラベルはソースファイル全体から見えるもので、関数にローカルなものではありません。
そのため、同じラベル名を再利用することはできません。

ローカルラベルの動作を模倣するために、NASMには、先頭にピリオド（`.`）を付けて宣言するラベル用の特別な記法があります。
この記法で定義されるラベルには、直前のピリオドの付いていないラベルの名前が暗黙的に含まれます。

```x86asm
section .text
fn1:
    ...
.example: ; this is fn1.example
    ...
    ret

fn2:
    ...
.example: ; this is fn2.example
    ...
    ret
```

コードのどこからでも、完全なラベル名を使ってこのラベルへジャンプすることは可能です。たとえば`jmp fn1.example`のように書きます。

ただし、ピリオドから始まる部分だけを使ったジャンプは、外側の関数の_内側_にあるラベルに対して行われます。
たとえば`.example`は、その関数に対してローカルであるかのように振る舞います。

```x86asm
section .text
fn1:
    ...
.example:
    ...
    jmp .example ; this jumps to fn1.example

fn2:
    ...
.example:
    ...
    jmp .example ; this jumps to fn2.example
```
