# 概要

`Option`型は、標準ライブラリが提供する列挙型です。存在しないかもしれない値を表すのに役立ちます。`null`や`nil`と同じように聞こえるかもしれませんが、実際はまったく違い、特別なものです。

`Option<T>`は他の型を包み込み、`Some(T)`と`None`という2つのバリアントを持ちます。

たとえば、`Option<u32>`は`u32`型を包み込みます。

## 使い方

### `Option<T>`の中の`T`を使う

`Option`の中に存在するかもしれない値を使うには、よく使われる書き方がいくつかあります。

- `if let Some(t) = optional { ... }`.

    `if let`という書き方を使うと、`Option<T>`から値を取り出して変数`t`に束縛できます。これにより、そのブロックスコープの中で値を直接使えます。

- `match optional { Some(t) => {...}, None => {...}}`

    `match`演算子を使えば、`None`の場合も含めて、1つの文または式で値を取り出して処理できます。`if`と`else`を連ねた文の代わりになります。`match`を使うと、コードの一部が読みやすくなることがあります。
- `optional.map(|t| ...)`
   `Option::map`は、与えられた関数によって`Option`をその場で更新します。新しい型になることもあります。

   **注意**: 値が存在する場合は、その中の値に対して処理を行います。束縛は`Option<U>`になり、ここで与えられたクロージャは`FnOnce(T) -> U`です。
- `optional.unwrap()`.
   `Option<T>`をアンラップすると`T`を取り出せますが、`T`が存在しない場合はパニックします。場合によっては手っ取り早い方法です。

   **重要**: アンラップは、短期的には開発を楽にしたり、テストコードで役立ったりしますが、実行時パニックの可能性を生み出します。できるだけ避けるべきです。

- `optional.expect("Unexpected None found! Aborting program.)`.
   `Option<T>`の`expect`メソッドは`unwrap()`とよく似ていますが、`None`の場合、与えられたメッセージとともにパニックします。

## 例

`Option<u32>`に値が存在する場合：

```rust
let has_something: Option<u32> = Some(100);
assert_eq!(has_something.unwrap(), 100);
```

`Option<u32>`に値が*存在しない*場合：

```rust
let has_nothing: Option<u32> = None;
assert_eq!(has_nothing, None);
```
