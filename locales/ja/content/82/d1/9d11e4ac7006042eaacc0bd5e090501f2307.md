# 概要

**再帰関数**とは、自分自身を呼び出す関数です。

_再帰関数_には、少なくとも1つの_基底ケース_と、少なくとも1つの_再帰ケース_が必要です。

**基底ケース**は、関数を再度呼び出すことなく値を返します。
**再帰ケース**は、いずれ基底ケースに一致するように入力を変更しながら、関数を再度呼び出します。

配列の要素を数える例を見てみましょう。

```jq
def count:
  if length == 0 then
    0                       # base case
  else
    1 + (.[1:] | count)     # recursive case
  end;

([] | count),           # => 0
([11, 22, 33] | count)  # => 3
```

_再帰関数_には、複数の_基底ケース_や複数の_再帰ケース_を持たせることができます。
たとえば、[フィボナッチ数列][wiki-fibonacci]は、2つの_基底ケース_をもつ再帰的な数列です。

```jq
def fibonacci:
  if . == 0 then
    0
  elif . == 1 then
    1
  else
    (. - 1 | fibonacci) + (. - 2 | fibonacci)
  end;

10 | fibonacci          # => 55
```

ある値`x`が配列の中に何回出現するかを数えるには、2つの_再帰ケース_があります。

```jq
def count_occurrences(x):
  if length == 0 then
    0
  elif first == x then
    1 + (.[1:] | count_occurrences(x))
  else
    (.[1:] | count_occurrences(x))
  end;

[11, 22, 33, 22, 44] | count_occurrences(22)    # => 2
```

実際には、配列やその他の列挙可能なデータ構造を繰り返し処理するときは、`map`や`reduce`のような組み込み関数を使うか、`[.[] | select(...)]`のように[ストリームを使う][map-implementation]ことがほとんどです。
内部的には、一部の組み込み関数は[再帰を使って実装されています][walk-implementation]。

## 無限再帰

再帰関数は、実装を誤ると、結果をいつまでも返さないことがあります。
これは問題になり得ます。関数が呼び出されるたびに、仮想マシンが結果を返すべき場所（[コールスタック][wiki-call-stack]）への参照がメモリに保存されるからです。
再帰関数が無限に自分自身を呼び出すと、メモリを使い果たし、[スタックオーバーフローエラー][wiki-stack-overflow]で仮想マシンがクラッシュする可能性があります。

この無限再帰の問題は、次のような原因で起こります。

- 基底ケースの実装を忘れている。
- 基底ケースを最初の条件節として定義していない。
- 再帰呼び出しのときに引数を正しく変更しておらず、そのために基底ケースに到達しない。

## 末尾呼び出しの最適化

[Wikipediaで説明されている][wiki-tail-call]とおりです。

> 末尾呼び出しとは、手続きの最後の動作として行われるサブルーチン呼び出しのことです。
> 末尾呼び出しの対象が同じサブルーチンである場合、そのサブルーチンは末尾再帰であると言われます。

上で実装した`fibonacci`の実装を考えてみましょう。
その再帰ケースは、自分自身を2回呼び出します。
関数が最後に行わなければならない動作は、足し算です。
最後の動作が自分自身への呼び出しではないため、この関数は再帰的ではありますが、末尾再帰ではありません。

一部の言語では_末尾呼び出しの最適化_が実装されており、末尾呼び出しは[コールスタック][wiki-call-stack]に新しいフレームを追加することなく、現在のスタックフレームを再利用できます。
これには、厄介な[スタックオーバーフロー][wiki-stack-overflow]を防げるだけでなく、パフォーマンス上の利点もあります。

`jq`にも末尾呼び出しの最適化は実装されていますが、_それは0アリティの関数に限られます_。
これを活用する方法は、何らかの状態を入力として受け取る「内側の」0アリティ関数を定義することです。
内側の関数は、必要に応じて状態を変更し、新しい状態を末尾再帰呼び出しに渡すことができます。
外側の関数は初期状態を作り、それを内側の関数に渡して再帰を開始します。

末尾再帰の`fibonacci`関数は、それまでに計算した数列を状態の一部として保持することで実装できます。

```jq
def fibonacci:
  def _fib:
    # input: {limit: number, series: array}
    if (.series | length - 1) >= .limit then
      .series[.limit]                                   # base case
    else
      .series += [.series[-1] + .series[-2]] | _fib     # recursive case
    end;
  {limit: ., series: [0, 1]} | _fib;

10 | fibonacci          # => 55
```
