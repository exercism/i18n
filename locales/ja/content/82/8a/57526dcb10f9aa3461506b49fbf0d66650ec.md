# 概要

手書きのアセンブリは、繰り返しだらけです。
同じ短い命令の並びが、ほとんど変化もなく何度も何度も現れます。そして、定型コードを減らしてくれる抽象化はほとんどありません。
それだけではありません。アセンブリでコードを書くときは、意味のわかりにくい値の管理も自分で行わなければなりません。
名前の付いた仮引数もありませんし、土台となる仕組みの細かな部分は、ほとんどすべてプログラマーが手作業で扱わなければなりません。

このトラックで使われているアセンブラーであるNASMには、この2つの問題の解決に役立つ道具がいくつか用意されています。
これらの道具は、どんな命令もプロセッサーに届く前、つまり_アセンブル時_に動きます。
そして、ソーステキストが機械語に翻訳される前に、それをどう書き換えるかをアセンブラーに指示します。

これらの道具のうち、もっとも重要なのが**マクロ**です。マクロは、アセンブラーにとってのレシピのようなものだと考えてください。
マクロは、使われたその場所で、まるでそこに手書きでコードを書いたかのように展開されます。

[マクロ][macro]は、複数のリテラルトークンを仮引数として受け取ることができ、さまざまな場面で再利用できます。
ただし、マクロは関数ではありません。`call`も`ret`もなく、コードの別の場所へ制御を移すこともありません。

## 単一行マクロ

もっとも単純な定義は、`%define`を使って値や短い式に名前を付けるものです。

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

それ以降に現れる`WIDTH`は、アセンブル前にすべて`8`に置き換えられます。
この置き換えはテキストレベルで行われるので、その名前は、オペランドの中でも、別の定義の中でも、現れる場所すべてで置き換えられます。

~~~~exercism/note
数値の_定数_には、`%define`ではなく`equ`を使いましょう。

`%define`で宣言した単一行マクロは、使われたときにだけ展開され、再定義したり未定義にしたりできます。
一方、`equ`の定数は定義した時点で評価され、あとから変更されることはありません。
~~~~

`%define`は、_名前を付けた_仮引数を受け取ることもでき、小さなインライン関数のようにふるまいます。

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
本体全体と、それぞれの仮引数とを、どちらも括弧（`()`）で囲みます。
`%define square(x) x*x`だと、`square(1+1)`という呼び出しは`1+1*1+1`に展開され、これは`3`です。
`%define square(x) ((x)*(x))`と書けば、同じ呼び出しは`((1+1)*(1+1))`に展開され、これは`4`になります。
~~~~

`%define`で定義した名前は、大文字と小文字を区別します。
大文字と小文字を区別したくないときは、`%idefine`を使うと名前の大文字と小文字が区別されなくなります。

単一行マクロは、コードのいろいろな部分に意味を与えるのに役立ちます。
注意して使えば、読みやすさが上がり、打ち間違いも減ります。
たとえば、関数の中で特定の役割を持つレジスターには、その役割にちなんだ名前を付けて定義できます。

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## 複数行マクロ

何行にもわたるコードのまとまりは、`%macro`で囲み、`%endmacro`で閉じます。
名前のあとの数字は、そのマクロが受け取る引数の数を表します。0にすることもできます。
引数を渡すときは、カンマ（`,`）で区切ります。

```x86asm
%macro example_macro 0
...
%endmacro
```

複数行マクロでは、引数に名前を付けることはできません。
引数は、渡された順に`%1`、`%2`、…という名前で参照します。

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

引数は、マクロの本体で行う操作にとって正しい構文でなければならない点に注意してください。
ここでは`mult_two eax, ecx`も`mult_two r8, r9`もアセンブルできますが、`mult_two eax, cl`はアセンブルできません。`imul eax, cl`が定義されていないからです。

マクロは、任意の数の引数を受け取ることもできます。
これには`n-*`という記法を使います。ここで`n`は、必要な引数の最小の数です。

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

複数行マクロでは、`%0`がそのマクロの引数の_数_を表します。
これは、任意の数の引数を取る可能性のあるマクロで特に役立ちます。

### マクロ内のラベル

普通のラベルを定義するマクロは、2回使ったとたんに壊れてしまいます。ラベルも2回定義されることになるからです。
複数回呼ばれる可能性のあるマクロの中でラベルを使うには、そのラベルの先頭に`%%`を付けます。
こうすると、アセンブラーは展開のたびに、このラベルに毎回異なる一意な名前を付けます。

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## アセンブル時の繰り返し

[`times`][times]を使うと、1行のコードブロックを繰り返すことができます。
これは、メモリー上に同じ値を繰り返し宣言するとき特に役立ちます。

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

複数行のコードを繰り返すときは、代わりに`%rep`を使います。

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

繰り返しの回数は`%rep`のすぐあとに指定し、繰り返すブロックを閉じるには`%endrep`を使う点に注意してください。

実行時のループがカウンターを使うのと同じように、`%rep`ブロックの中でアセンブル時のカウンターを使うことがよくあります。
すでに見たように、アセンブル時の整数定数は`equ`で宣言できますが、アセンブル時の整数_変数_には、代わりに`%assign`を使います。
`%define`と違って、`%assign`はその場で数値として評価され、再代入もできます。

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

プリプロセッサーが動いたあとにはループは消え、4つの`add`命令だけが残ります。即値`0`、`1`、`2`、`3`はそのまま埋め込まれています。
これはアセンブラーが行うループ展開です。カウンター用のレジスターも分岐もなく、ただ一直線のコードが並ぶだけです。

`%rep`のもうひとつのよくある使い方は、任意の数の引数を取るマクロで、その引数を処理することです。
その場合は、`%rep`を`%rotate`と組み合わせるのが普通です。`%rotate`は、マクロの引数を回転させて、2番目の引数を1番目にします。
`%rotate`を繰り返し適用すると、3番目、4番目、…の引数が順に1番目になるので、どの引数も順番に処理できます。

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## 条件付きアセンブル

[プリプロセッサー][preprocessor]には、いろいろな条件分岐が用意されています。
これらは複数の異なる経路からひとつを選び、その本体をその場で展開しますが、それは条件が成り立つときに限られます。

`%if` … `%elif` … `%else` … `%endif`は、数値のテストによって分岐を選びます。

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef`と`%ifndef`も似ていますが、こちらは名前が定義されているかどうかを調べます。
たとえば、あるファイルが複数のソースから読み込まれる場合でも、その中身が1回だけ取り込まれるようにするのに使えます。

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

このトラックのすべての`.asm`ファイルの末尾に、次のコードがあることにお気づきかもしれません。

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn`は、2つのテキストが完全に一致するかどうかを比べます。
組み込みの`__OUTPUT_FORMAT__`は、現在の出力フォーマットに展開されます。つまりこのコードは、出力フォーマットが`elf64`かどうかを調べています。これはLinuxシステムで使われるフォーマットです。
そうであれば、スタックが持つべき権限を宣言するノートがオブジェクトファイルに追加されます。これはよく使われる安全対策です。
そうでなければ、何も変わりません。

## 構造体

メモリー上のレコードのフィールドにアクセスするには、基準となるアドレスに、そのフィールドのバイトオフセットを足します。
そうしたオフセットを生の数値として書くと、間違えやすく、意味も見えなくなってしまいます。
代わりに[`struc`][struc]と`endstruc`でレイアウトに名前を付けると、各フィールドが、アセンブル時に計算されるシンボリックなオフセットになります。

ブロックの中では、予約用ディレクティブ`resb`、`resw`、`resd`、`resq`が、1つ以上のバイト、ワード、ダブルワード、クワッドワードを確保します。
各フィールドの先頭に`.`を付けると、その名前のスコープを構造体の中だけに限定できます。

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

これで各フィールド名がそのオフセットを表すようになります。`thread.color`は`0`、`thread.tension`は`4`、`thread.name`は`12`です。
NASMはさらに、`<struc>_size`を全体のサイズとして定義します。ここで`<struc>`は`struc`の名前です。
たとえばここでは、`thread_size`は`4 + 8 + 16 = 28`になります。

フィールドにアクセスするには、基準となるレジスターにそのオフセットを足します。また`thread_size`は、あるレコードから次のレコードまでの間隔になります。

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

`struc`は形を記述するだけで、それ自体はメモリーを確保しません。
初期値を持つインスタンスを作るには、何らかのラベルのあとに`istruc ... iend`を使います。
インスタンスの中では、`at`が名前付きのフィールドに値を置きます。

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

`thread.name`は`"warp", 0`で初期化され、これが使うのはたった5バイトである点に注意してください。
`struc`で確保された残りの11バイトは、`iend`によって自動的に0で埋められます。`iend`は、インスタンスを`0`で`thread_size`まで埋めるからです。

`struc`は、手作業でも宣言できるメモリーのための、単なるシンタックスシュガーです。
たとえば、上のコードは次のコードと等価です。ここでは`times 11 db 0`が、末尾に16バイトが確保されるようにしています。

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## ファイルへの分割

マクロは多くの場合、専用のファイルにまとめておき、必要なソースごとに`%include`で読み込みます。

```x86asm
%include "patterns.mac"
```

指定したファイルは、アセンブル前にその場所へそのまま挿入されます。まるでその内容をそこに直接打ち込んだかのようです。
こうすると、定義を1か所にまとめたまま、複数のソースファイルで共有できます。

マクロファイルを単体でアセンブルする可能性があるなら、拡張子は`.asm`にしましょう。
マクロにはリンケージがない点に注意してください。
マクロファイルをアセンブルしても、そのマクロは、それを`%include`する別のファイルからしか見えません。

そうでなければ、`%include`専用のファイルはどんな拡張子でもかまいません。
`.asm`か`.mac`のどちらかを使うのが、よくある慣習です。
