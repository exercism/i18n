# イミュータブルクラス

```sather
immutable class BEARING is
   readonly attr degrees : INT;
   create(d : INT) : SAME is
      b : SAME;
      return b.degrees(d);
   end;
end;
```

## 変わる点

| | 通常のクラス | イミュータブルクラス |
| --- | --- | --- |
| 代入 | オブジェクトを共有する | 値をコピーする |
| voidになれるか | なれる | なれない |
| `attr`の書き込み | `x.a := v` | `x := x.a(v)` |
| `new` | 使える | 使えない。`x : SAME`はすでに存在する |

イミュータブルオブジェクトはvoidになれないため、`void(b)`は常にfalseとなり、そのオブジェクトのルーチンが「対象となるオブジェクトがない」という理由で失敗することはありません。これは、ある種の間違いをまとめて取り除いてくれますが、その代償として「まだBEARINGがない」とは表せなくなります。

## 値はどこにあるのか

値は、参照をたどってたどり着くのではなく、変数があるその場所、つまり別のオブジェクトの内部やスタックの上に格納されます。そのため`ARRAY{BEARING}`は、BEARINGへのポインターではなくBEARINGそのものを保持します。こちらはデータが小さく、たどるのも速くなります。

コストはコピーです。大きなイミュータブルオブジェクトを渡すと、そのたびにコピーが発生します。小さく保つのが一番です。

## 属性ルーチン

`readonly attr degrees : INT`は2つのルーチンを生成します。

```sather
   b.degrees          -- read: INT
   b.degrees(90)      -- answer a new BEARING with degrees changed
```

2つ目は`readonly`の下でも存在します。何も変更しないからです。新しい値を組み立てるだけです。ふつうの`attr`では公開されますが、`private attr`では公開されません。

## is_eq と str

どちらも用意されていません。`=`のために`is_eq`を、そしてオブジェクトを出力したり文字列に連結したりできるようにするために`str`を書きます。

```sather
   is_eq(other : SAME) : BOOL is return degrees = other.degrees; end;
   str : STR is return degrees.str + " degrees"; end;
```

`str`を書くと、そのクラスは`$STR`に適合します。これによって`+`や`#OUT`がそのクラスを受け取れるようになります。

## 組み込みクラス

`INT`、`BOOL`、`CHAR`、`FLTD`、`TUP`はどれもイミュータブルクラスです。特別なところは何もありません。ライブラリーの中で同じようにSatherで書かれており、先に挙げた理由のとおりに振る舞います。
