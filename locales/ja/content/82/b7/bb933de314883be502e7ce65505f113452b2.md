# 説明

この演習では、6つの重大度レベルを持つログメッセージを処理します。

それぞれのログ行は、`"[<LVL>]: <MESSAGE>"`という形式の文字列です。

ログレベルは以下のとおりです：

| レベル     | LVL   |
| --------- | ----- |
| `Trace`   | `TRC` |
| `Debug`   | `DBG` |
| `Info`    | `INF` |
| `Warning` | `WRN` |
| `Error`   | `ERR` |
| `Fatal`   | `FTL` |

## 1. ログレベルを解析する

上で定義したログレベルに対応する6つの要素を持つ`LogLevel`列挙型を定義します。
次に、ログメッセージを入力として受け取り、そのレベルの列挙型メンバーを返す`parse_log_level`関数を定義します。

```python
parse_log_level("[INF]: File deleted")
#=> LogLevel.Info
```

## 2. 未知のログレベルに対応する

残念ながら、_未知の_重大度を持つログメッセージがときどき現れることがあります。関数`parse_log_level`でこうした「謎の」ログメッセージをうまく処理できるようにするには、`LogLevel`列挙型に`Unknown`メンバーを追加し、未知のログレベルを解析したときにそれを返すようにします：

```python
parse_log_level("[XYZ]: Overly specific, out of context message")
#=> LogLevel.Unknown
```

## 3. ログメッセージを短い形式に変換する

ログ行のログレベルは、かなり冗長です。ログメッセージを保存するために必要なディスク容量を減らすため、`"[<CODE_LEVEL>]:<MESSAGE>"`という短い形式が定義されています。

ログレベルのコードは、次のように単純に対応しています：

| レベル     | コード |
| --------- | ---- |
| `Trace`   | `0`  |
| `Debug`   | `1`  |
| `Info`    | `4`  |
| `Warning` | `5`  |
| `Error`   | `6`  |
| `Fatal`   | `7`  |
| `Unknown` | `42` |

2つの入力を受け取る`convert_to_short_log()`関数を定義します：

1. ログレベル：送信されるログのログレベル。例：`LogLevel.Error`。
2. ログメッセージ：`str`型のメッセージ。

```python
convert_to_short_log(LogLevel.Error, "Stack overflow")
# => "6:Stack overflow"
```

## 4. エイリアスを作成する

どうやらユーザーは、`LogLevel.Warning`ではなく`LogLevel.Warn`のログを作成したようです。`LogLevel.Warning`の`alias`を作成し、関数`get_warn_alias`で新しいエイリアスメンバーを返すようにします。

これは、ファイルの先頭ですでに定義されている同じ列挙型クラス`LogLevel`で行えます。どちらのLogLevelも、同じ値`"WRN"`を指している必要があります。

```python
get_warn_alias()
#=> LogLevel.Warn

get_warn_alias() == LogLevel.Warning
#=> True
```

## 5. すべてのメンバー名と値

関数`get_members()`を定義します。

この関数は、列挙型`LogLevel`のすべてのメンバーを含む`(name, value)`というタプルの配列を返す必要があります。

```python
get_members()
#=> [('Trace', 'TRC'), ('Debug', 'DBG'), ('Info', 'INF'), ('Warning', 'WRN'),
# ('Error', 'ERR'), ('Fatal', 'FTL'), ('Unknown', 'UKN')]
```
