# はじめに

## リソースの生存期間

[concept:csharp/resource-cleanup]()では、`IDispose`インターフェースを使って、オブジェクトのリソースやその他のプログラムの状態を、そのオブジェクトが不要になったときに解放またはリセットする必要があること（そして、ガベージコレクターに頼ってもこれを実現できず、必要なレベルの制御も得られないこと）を伝えます。そして、そうしたクリーンアップ処理を行うのに自然な場所が`IDisposable.Dispose()`メソッドです。

これとは別に、`using`ブロックという構文があります。これは、呼び出し側から見ると、リソースの生存期間の管理をすべて1つの文にまとめることを可能にします。

```csharp
using (var file = new File("my_secrets"))
{
    file.WriteSecret("xxxxxxx");
}
```

上の例では、`file`に関連付けられたファイルシステムのリソースは、`using`ブロックを抜けるときにオペレーティングシステムに返却されます。

このパターンが機能するには、using文の変数が`IDisposable`インターフェースを実装する参照型であり、その`Dispose()`メソッドでリソースの解放やプログラム状態のリセットを行わなければなりません。

C# 8では、このパターンがさらに改良されました。using文をブロックの先頭に置けるようになったのです。

```csharp
using var drawingResource = some_provided_or_new_object;
try
{
    drawingResource.DrawSomething();
}
catch (Exception)
{
    throw;
}
```

Javaの開発者なら、これはJava 7で導入された_自動リソース管理_の仕組みに似ていると気づくかもしれません。
