# 概要

ここまでの学習で、Rを命令型言語としてよく使い、そして関数型言語としてもますます使うようになってきたはずです（特に[`purrr`][ref-purrr]や[`dplyr`][ref-dplyr]のようなライブラリを使うときは）。

ここで、Rは本来オブジェクト指向だと聞くと、少し疑わしく思うかもしれません。

不思議なことに、これは本当のことです。
Rの内部は、クラス、継承、ポリモーフィズム、そしてOOPプログラマーによくある考え方を使って実装されています。

しかし、JavaやRuby（明確にOOP）やすでにPython（ある意味では半ば暗黙のOOP）に慣れている人にとって、Rのやり方は…_なじみのないもの_に映ります。

まず、クラスの設計が複数あります。よく使われるものが3つ（S3、S4、R6）あり、そのほか主に理論上の興味から存在するものもいろいろあります。

詳しい解説は[Advanced R, 2e][book-advanced-r]の第12章から第16章にあります。
この2019年の本は、主にRの内部を理解して保守したい人向けなので、OOPは欠かせません。

よりエンドユーザー向けの教科書になると、扱いはさまざまです。

- The Art of R Programming（2011年、紙媒体のみ）にはOOPの章があり、当時重要だったS3と（より簡単に）S4を扱っています。
  _「S3クラスはかなり寄せ集めの構造をしている」_という指摘は、今でも驚くほど当たっています。
- R in Action（第3版、2022年）では、OOPは終盤の「高度なプログラミング」の章で3ページだけ触れられています。
- [R for Data Science, 2e][book-r-data-sci]（2023年、紙媒体では548ページ）では、OOPには一切触れられていません。

このコンセプトでは、S3クラスに焦点を当てます。S3クラスはもっともシンプルでもっともよく使われ、Exercism向けの問題にもっとも関係が深いものです。
Rトラックの演習には、S3クラスの作成が必須のものもあれば、任意だけれど軽く推奨されているものもあります。

## S3クラス

これらは古い仕組みです。S3という名前は、単にS言語（Rの商業的な前身）のバージョン3で導入されたことを意味します。

S3クラスもとてもシンプルです。ふつうは、少なくとも1つの追加属性を持つ[リスト][concept-lists]です。

[Advanced R][book-s3]からの引用です。_「S3は非公式で場当たり的ですが、そのミニマリズムにはある種のエレガンスがあります。どの部分を取り除いても、役に立つOOシステムではいられません。」_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

つまり、[`class(obj)`][ref-class]に代入すると、`obj`に属性が1つ追加されるだけです。この場合は、pt2dがpoint2dクラスのインスタンスだと示す属性です。

この作成手順は、[`structure()`][ref-structure]と組み合わせることもできます。

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

できあがったインスタンスは概念的には同じですが、それをRが確認する方法はまだ実装していません。

### ジェネリックメソッド

ほかの言語のOOPに慣れている人なら、_「クラスは何かをするものではないのか？」_と不思議に思うかもしれません。

`point2d`のインスタンスで使えるメソッドを調べてみると、（元になっている`list`とは違って）今のところ何もないことがわかります。

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

ほとんどのOOP言語では、メソッドはクラス定義の中に書きます。
いくつかの言語（特にRuby）では、あとからクラスのメソッドを追加したり変更したりできます。

S3クラスは大きく違います。
クラスにメソッドを追加するのではなく、ジェネリックメソッドにクラスを追加します。

Rのコンソールで対話的に作業する人は、その実装を意識することなく、いつもジェネリックメソッドを使っています。

とてもよくある例が`print()`です。とはいえ、関数名を打ち込むことはほとんどありません。
コンソールのプロンプトで値`x`をそのまま入力するのは、`print(x)`のシンタックスシュガーにすぎません。

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

`pt2d`はすでに表示できます。
`print()`は`point2d`クラスについて何も知りませんが、さまざまなオブジェクトを扱える妥当なデフォルトを備えています。

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

これではかなり冗長なので、点を簡潔に整形して表示する方法が欲しくなります。

簡単です。`print.point2d()`という名前の関数を追加するだけです。
名前は`methodname.classname`の形にする必要があります。そうすれば、ディスパッチャーが何を探せばよいかわかります。

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

では、新しいジェネリックメソッドを作りたいとしましょう。たとえば、`y`座標の符号を反転させる`flipvert()`です。

これも簡単です。

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

これでディスパッチャーができます。`x`はS3クラスを持つオブジェクトで、`...`はメソッド定義が必要とする追加の引数（[関数のコンセプト][concept-functions]で説明する「ドット引数」）を扱います。

あとは`point2d`用のメソッドを定義して使うだけです。

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

これでRは、点を反転させる方法と、その結果を表示する方法を理解しました。

3Dや極座標などのクラスを作り、それぞれにメソッドを定義して、これを広げていくこともできます。

エンドユーザーから見ると`flipvert(x, ...)`があるだけです。入力のクラスを判断して適切な実装を使うところは、Rに任せられます。

~~~~exercism/caution
`verb.class`という形の関数名は、ユーザーにもRのパーサーにもS3のメソッドに見えます。
ほかの場面で似た命名をするのは避けてください。

もちろん、base Rがこのルールを破っていることもあります。
これは（S3よりもさらに古い関数のための）不幸な歴史的経緯と考えるべきもので、後方互換性のために残さなければなりません。
~~~~

### 継承

OOP好きなら、継承、サブクラス化、ミックスインなどについて、教科書の章をいくつも長々と書けるでしょう。

Rでは、`class`属性に複数の名前を渡せるだけです。1つの文字列ではなく、より長い文字列のベクトルです。

この例を限界まで押し広げることを承知で、汎用的な`point`クラスを作り、それを`point2d`や`point3d`などにサブクラス化したいとしましょう。

すると`point2d`の定義は、`class = c("point2d", "point")`を使うだけです。個別のクラスと親クラス（複数のこともあります）です。

`print()`のようなジェネリックメソッドは、`print.point2d()`、`print.point()`、そして（おそらく）`print.default()`を順に探し、ディスパッチャーが見つけた最初の実装を使います。

### 安全性

多くのOOP言語（Java、C#など）は、クラス内でのデータのカプセル化を利用して、コンパイル時に慎重なチェックを行い、型安全性を強制します。

S3では、意味が通らなくても、ほぼ好きなことができる点に注意してください（エラーメッセージが出るとしても、それは後になってからです）。

[Advanced R][book-s3]（第2版、13.3節）からの引用です。

> _ほかのOO言語を使ったことがあるなら、これには落ち着かない気持ちになるかもしれません。でも実際には、この柔軟さが問題になることはほとんどありません。Rは自分の足を撃つのを止めてくれませんが、銃を足の指に向けて引き金を引かなければ、問題は起きません。_

まあ、_それでいいのでしょう。_
Rは、探索的なデータサイエンスや統計、とくに対話的に作業するときに優れています。
Rで厳重なセキュリティが求められる企業の財務システムを書けと言っているわけではありません。
