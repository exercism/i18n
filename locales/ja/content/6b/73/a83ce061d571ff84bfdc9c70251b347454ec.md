# 概要

技術的には、[`Higher Order Function`][HOFunc]とは、次のうち少なくとも1つを行う関数にすぎません。

- 引数の1つとして関数を受け取る。
- 戻り値として関数を返す。

関数型プログラミングの世界では、使われ方はもっと狭いのが普通です。
この用語は通常、渡された関数をコレクションの要素に適用する`filter`、`map`、`reduce`などの関数を指します。

## コレクションに対する操作

シラバスのこの時点までに、Vectorのような反復可能なコレクションのすべての要素に操作を適用する方法をいくつか見てきました。

- [ループ][loops]を使う（デジタルコンピューティングの黎明期から、ほとんどのプログラミング言語がそうしてきたように）。
- [内包表記][comprehensions]を使う（Python流）。
- [ブロードキャスト][broadcasting]を使う（Juliaならではの構文ですが、R、Matlab、NumPyから多大な影響を受けています）。

このコンセプトでは、高階関数に焦点を当てます（HaskellやF#など、関数型言語に親しんだ人にはおなじみでしょう）。

そのほかに考えられる方法としては、次のようなものがあります。

- 再帰（ML系の言語のように）。
  - Juliaでも可能ですが、末尾呼び出し最適化がないため、スタックオーバーフローの危険があります。
- マクロによるメタプログラミング（伝統的にLispの機能）。
  - 高度なJuliaプログラミングでは広く使われていますが、ほとんどの場合_注意して使ってください_。
  - ほかの方法のほうが書きやすく、デバッグもはるかに簡単でしょう。

## フィルタリング

[`filter()`][filter]関数は、真偽値を返す関数を渡してコレクションに適用します。
`true`を返す要素だけが戻り値に含まれ、その戻り値は入力と同じ_基本_型になります（後述）。

```julia-repl
julia> filter(iseven, 1:6)
3-element Vector{Int64}:
 2
 4
 6

# String is a collection of Chars, so String in -> String out
julia> filter(!isascii, "Hrōðgār")
"ōðā"

# tuple input -> tuple output
julia> filter(iseven, (1, 2, 3, 4, 5))
(2, 4)
```

多次元配列の場合、`filter`は入力の次元を平坦化してVectorを返します。これは、出力の型が入力の型と一致するというルールの_主な例外_です。

```julia-repl
julia> m
2×3 Matrix{Int64}:
 1  2  3
 4  5  6

julia> filter(isodd, m)
3-element Vector{Int64}:
 1
 5
 3
```

上の例では組み込み関数を使っていますが、このような場面では[無名関数][anonymous]の使用が非常によくあります。

```julia-repl
julia> filter(x -> x % 3 == 0, 1:20)
6-element Vector{Int64}:
  3
  6
  9
 12
 15
 18
```

このコンセプトの多くの関数と同様に、破壊的なバージョンである[`filter!()`][filter-bang]もあります。

## マッピング

[`map()`][map]関数は、関数を各要素に適用してコレクションを変換します。
単純なケースでは、出力の形が入力と一致し、[ブロードキャスト][broadcasting]と似ていることがあります。

```julia-repl
julia> map(√, [1, 4, 9])
3-element Vector{Float64}:
 1.0
 2.0
 3.0

julia> map(x -> x^2 + 1, 1:4)
4-element Vector{Int64}:
  2
  5
 10
 17

julia> m
2×3 Matrix{Int64}:
 1  2  3
 4  5  6

julia> map(√, m)
2×3 Matrix{Float64}:
 1.0  1.41421  1.73205
 2.0  2.23607  2.44949
```

`map()`は複数のコレクションに対しても要素ごとに作用します。

```julia-repl
julia> map(*, [1, 2], [3, 4])
2-element Vector{Int64}:
 3
 8
```

概念的には、これは複数の入力コレクションに[`zip()`][zip]を実行し、その中間結果の各要素に`map()`を適用するのと同じだと考えることができます。
_これはあくまで大まかなたとえであり、実装について何も示唆するものではありません！_

`zip()`と同様に、形の合わないコレクションは、最も小さいものの次元に切り詰められます。

渡された関数の副作用だけが必要な場合もあります。たとえばデータベースへの書き込みや、配列への`push!`などです。
そういうときは高階関数[`foreach()`][foreach]が使えます。これは常に[`nothing`][nothingness]を返します。

大きなコレクションでは、`map()`のコストが高くなることがあります。
並列計算はこのコンセプトの範囲外ですが、[`Distributed.pmap()`][pmap]というものがあり、計算をワーカーのプールに分散できることを知っておくと役立つかもしれません。
`Distributed`パッケージは、Exercismのテストランナーで_利用できます_。

## 畳み込み

[`reduce()`][reduce]関数は、2引数の関数をコレクションに適用し、次元を削減します。

抽象的には混乱するかもしれませんが、コレクションを受け取って単一の値を返す`sum()`や`prod()`のような関数を考えてみましょう。

```julia-repl
julia> sum(1:4) # add
10

julia> prod(1:4) # multiply
24
```

_これらの専用関数は高度に最適化されているので、使えるときは必ず使うべきです。_
ほかの例には`maximum()`や`minimum()`、論理関数の`all()`と`any()`、そして多くの統計関数があります。

_説明のために_、より汎用的な`reduce()`で同じ機能を実装したものを考えてみましょう（中置演算子の`+`と`*`も、内部的には実際に関数であることを思い出してください）。

```julia-repl
julia> reduce(+, 1:4) # add
10

julia> reduce(*, 1:4) # multiply
24
```

`sum()`やほかの集約関数と同様に、`reduce()`はオプションのキーワード引数`dims`を取ることができ、畳み込む[次元][multidim]を指定します。

```julia-repl
julia> m
2×3 Matrix{Int64}:
 1  2  3
 4  5  6

julia> reduce(+, m; dims=1)
1×3 Matrix{Int64}:
 5  7  9
```

これらは簡単な例です。足し算と掛け算はどちらも可換（`1+2 == 2+1`）で結合的（`(1+2)+3 == 1+(2+3)`）だからです。

これは決して一般的ではありません！
引き算や割り算のようなごく普通の演算でさえ、結合的ではありません。

さらに、浮動小数点の誤差が大きなコレクション全体で蓄積されるという問題もあります。そのため、左から右へのreduceと右から左へのreduceでは、わずかに異なる結果になることがあります。

Juliaの`reduce`関数の方向は実装依存で、保証されていません。

方向を明示的に制御するには、[`foldl()`][foldl]と[`foldr()`][foldr]という関数があります。それぞれ名目上は「左」と「右」から始まります（Vectorの場合は、実際には上と下です）。

```julia-repl
julia> foldl(-, 1:3) # (1 - 2) - 3
-4

julia> foldr(-, 1:3) # 1 - (2 - 3)
2
```

これらは1次元として扱えるコレクションを対象としており、スカラーの結果を返すことに注意してください。
`dims`引数は`foldl`と`foldr`ではサポートされておらず、`reduce`でのみ使えます。

並列計算では順序どおりでない計算が普通になるため、reduce関数の使い方はより繊細になります（ただし、これはこのコンセプトの範囲外です）。

## MapReduce

`map`操作と`reduce`を組み合わせることは、さまざまなプログラミングの分野で非常によく行われます。

`map`を順に実行し、そのあと中間のコレクションに対して`reduce`を実行することもできます。
しかし、これはよくても非効率で、コレクションが大きくなるにつれてスケールが非常に悪くなります。

代わりに、組み合わせた[`mapreduce()`][mapreduce]関数を使うことが_強く_推奨されます。
これは、mapとreduceの操作を交互に行う、はるかに高性能なアルゴリズムを実装できます。

最初の引数はmapに使う関数で、2番目の引数はreduceの演算子です。

```julia-repl
julia> mapreduce(x -> x^2 + 1, +, 1:3)
17

# equivalent to (2 + 5 + 10)
julia> sum(map(x -> x^2 + 1, 1:3))
17
```

MapReduceの操作は、ビッグデータシステム（Hadoop、Sparkなど）で特に人気があります。任意の長さで未知のストリームを、メモリ使用量を爆発させることなくリアルタイムで処理できるからです。

予想どおり、Juliaには方向が重要な場面のための[`mapfoldl()`][mapfoldl]と[`mapfoldr()`][mapfoldr]関数もあります。
