# 概要

Goのスライスは、他の言語の配列に似ています。
特定の型（またはインターフェース）の要素をいくつかまとめて保持します。

Goのスライスは配列を基にしています。
配列はサイズが固定です。
一方、スライスは動的にサイズが変わり、配列の要素を柔軟に見渡せるビューです。

スライスは`[]T`のように書きます。ここで`T`は、スライスに入る要素の型です。

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

角括弧（`[]`）を使うと、0から始まる指定したインデックスの要素を取得したり、値を設定したりできます。

```go
withData[1] = 5
x := withData[1] // x is now 5
```

既存のスライスから要素の範囲を取り出すと、新しいスライスを作れます。
ここでも角括弧を使いますが、開始位置（その位置を含む）と終了位置（その位置を含まない）の両方を指定します。
開始位置を省略すると、0になります。
終了位置を省略すると、スライスの長さになります。

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

`append`関数を使うと、スライスに要素を追加できます。
次の例では、`a`スライスに`4`と`2`を追加しています。

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append`は常に新しいスライスを返します。既存のスライスに要素を追加したいだけのときは、上の例のように、最初の入力として渡したスライス変数にそのまま代入し直すのが一般的です。

`append`は2つのスライスをまとめるのにも使えます。

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## スライスのインデックス

スライスのインデックスを扱うときは、そのインデックスが実際に存在するかを確認するなどして、必ず何らかの形で保護するようにしましょう。
そうしないと、アプリケーション全体がクラッシュしてしまいます。

## 空のスライス

`nil`スライスは、デフォルトの空のスライスです。
値がまったく入っていないスライスと比べても、デメリットはありません。
`len`関数は`nil`スライスでも動きますし、初期化しなくても要素を追加できます。
新しいスライスを作るときは、`s := []int{}`（空の、`nil`でないスライス）よりも`var s []int`（`nil`スライス）を選びましょう。

## パフォーマンス

スライスを作って要素を繰り返し追加していく場合、最終的なサイズがわかっていれば、手軽にパフォーマンスを改善できるポイントがあります。
カギは、メモリを確保する回数をできるだけ減らすことです。メモリの確保はそれなりにコストが高く、スライスが確保済みのメモリ領域を超えて大きくなると発生します。
最も安全な方法は、`s := make([]int, 0, cap)`のようにスライスの容量`cap`を指定しておき、あとはいつもどおり`append`で追加していくやり方です。
こうすると、スライスの長さは0のまま、`cap`個分の領域がすぐに確保されます。
実際には、`cap`には別のスライスの長さを使うことがよくあります。`s := make([]int, 0, len(otherSlice))`のように書きます。

## `append`は純粋関数ではありません

Goの`append`関数はパフォーマンスのために最適化されているので、入力のスライスをコピーしません。
そのため、もとのスライス（`append`に渡した1番目の入力）が変更されることがあります。
