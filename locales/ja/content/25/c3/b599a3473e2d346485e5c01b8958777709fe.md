# クォートの紹介

bashを始めたばかりの人が何度も耳にするアドバイスがあります。

> 変数をクォートしましょう！

なぜでしょうか？

変数（`$name`など）を展開するときは、ほとんどの場合、その変数の_値_を1つの文字列（または数値）として扱いたいはずです。値が予期せず2つ以上の別々の文字列として扱われてほしくはありません。

## クォート

クォートは、あるテキストを1つの単語として扱うための主要な仕組みです。クォートには主に2つの種類があります。

### ダブルクォート

ダブルクォートの中では、パラメータ展開、算術展開、コマンド置換ができます。

```bash
echo "This is bash version $BASH_VERSION"
```

ダブルクォートで囲んだ文字列の中にダブルクォートそのものを含めたいときは、その前にバックスラッシュを付けます。

```bash
echo "She said \"Let me teach you about bash.\""
```

### シングルクォート

シングルクォートの中では、どのような展開も_行われません_。

```bash
echo 'This is bash version $BASH_VERSION'
# ...^..................................^
# prints exactly: This is bash version $BASH_VERSION
```

シングルクォートで囲んだ文字列の中にシングルクォートを入れることは_できません_。

## クォートの重要性

`echo $name`の一体何が問題なのでしょうか？

シェルがコードを1行解析するとき、[いくつかの展開][expansions]を順番に実行します。最後の方にある2つの展開が_単語分割_と_ファイル名展開_です。

### 単語分割

パラメータ展開、コマンド置換、算術展開の結果のうち、_ダブルクォートの中で行われなかったもの_は「単語分割」の対象になります。シェルは展開後の結果を、`$IFS`の値に含まれる文字の並びで分割します。デフォルトでは、スペース、タブ、改行です。

シェルのループを使うと、実際の動きを確認できます。

```bash
sentence="The quick brown fox jumps."
i=0
for word in "$sentence"; do echo "$((++i)) $word"; done
# ..........^.........^
```
出力は次のとおりです。
```none
1 The quick brown fox jumps.
```

クォートを外すと、次のようになります。

```bash
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
出力は次のとおりです。
```none
1 The
2 quick
3 brown
4 fox
5 jumps.
```

`$IFS`の値を変えるとどうなるかも見てみましょう。

```bash
csv="first,second,third"
IFS=","
for word in $csv; do echo "$word"; done
```
出力は次のとおりです。
```none
first
second
third
```

#### 単語分割を無効にする

単語分割を無効にする1つの方法は、`$IFS`を空文字列に設定することです。

```bash
sentence="The quick brown fox jumps."
IFS=    # or explicitly, IFS=""
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
出力は次のとおりです。
```none
1 The quick brown fox jumps.
```

ただし、ファイル名展開も同時に無効にしない限り、変数をクォートせずに置いておくことはおすすめしません。その方法は後ほど見ていきます。

### ファイル名展開

「Glob」パターンは、一連のファイルに一致させる簡潔なパターンを表すために使われます。たとえば、ディレクトリ内のすべてのMarkdownファイルを`*.md`で一致させられます。[Globパターン][glob]は、Unixが発明されたときから存在しています。

Globのワイルドカード文字は次のとおりです。

* `*`は、任意の文字の0回以上の繰り返しに一致します。
* `?`は、任意の文字1つにちょうど一致します。
* `[...]`は、角括弧の中に並べた文字の集合のうち、ちょうど1つの文字に一致します。

   ~~~~exercism/advanced
   <details><summary>
   文字集合にはたくさんの細かい決まりがあります。
   ここをクリックすると表示されます。
   </summary>

    * `[abc]`は、`a`、`b`、`c`のいずれか1つの文字にちょうど一致します。
        * 閉じ角括弧そのものを式に含めたいときは、開き角括弧の直後（省略可能な`^`の後）の最初の文字にします。
            * `[][]`は、閉じ角括弧か開き角括弧のどちらかに一致する文字集合です。
            * または、バックスラッシュでエスケープします: `[[\]]`
    * `[x-y]`は、`x`から`y`までの_範囲_にある1つの文字にちょうど一致します。
        * 文字集合にハイフンそのものを含めたいときは、開き角括弧の直後（省略可能な`^`の後）の最初の文字か、閉じ角括弧の直前の最後の文字にする必要があります。
            * `[-xy]`と`[xy-]`はどちらも、`-`、`x`、`y`のいずれか1つの文字にちょうど一致します。
            * または、バックスラッシュでエスケープします: `[x\-y]`
        * 複数の範囲を指定することもできます。たとえば`[0-9A-Fa-f]`は16進数の数字に一致します。
    * `[^abc]`は、`a`、`b`、`c`の**いずれでもない**1つの文字にちょうど一致します。
    * `[^x-y]`は、`x`から`y`までの範囲に**ない**1つの文字にちょうど一致します。
    * `[[:character_class:]]`は、指定した「character_class」に含まれる1つの文字に一致します。
        * 利用できる文字クラスは次のとおりです。 
            * `lower` -- 小文字
            * `upper` -- 大文字
            * `alpha` -- 英字
            * `digit` -- 数字
            * `alnum` -- 英字と数字
            * `space` -- 空白文字
            * `blank` -- 水平方向の空白文字（スペースとタブ）
            * `xdigit` -- 16進数の数字
            * `word` -- 識別子に使える文字（英字、数字、アンダースコア）
            * `punct` -- 句読点
            * `cntrl` -- 制御文字
            * `graph` -- 「目に見える」文字
            * `print` -- 目に見える文字とスペース
        * これらは組み合わせることができます。
            * `[[:alpha:]]`クラスは`[[:lower:][:upper:]]`から構成されます。
            * `[[:alnum:]]`クラスは`[[:alpha:][:digit:]]`から構成されます。
            * `[[:word:]]`クラスは`[[:alnum:]_]`から構成されます。
            * アンダースコア（8進数で137）は`[[:word:]]`と`[[:punct:]]`の両方です。
            * `[[:graph:]]`クラスは`[[:alnum:][:punct:]]`から構成されます。
            * `[[:print:]]`クラスは`[[:graph:] ]`から構成されます。これはスペース（8進数で040）だけで、他の空白文字は含みません。
   </details>   
   ~~~~

#### ファイルのリストを反復処理する

`for`ループを使うと、ファイルのリストを反復処理できます。

```bash
for file in *.csv; do
    do_something_with "$file"
done
```

変数`"$file"`がクォートされている点に注目してください。Globパターンは、名前にスペースを含むファイルを返すことがあります。`do_something_with`コマンドが引数をちょうど1つ、つまりファイル名だけを受け取るように、変数をクォートする必要があります。

#### Globパターンは正規表現ではない

Globパターンは正規表現では**ありません**。

* ちょうど1つの文字に一致させる
   * 正規表現 `.`
   * Glob `?`
* 0個以上の文字に一致させる
   * 正規表現 `.*`
   * Glob `*`
        * Globパターンの`.*`は、「最初の文字がドットそのもので、その後に任意の文字が0個以上続くファイル名に一致させる」という意味です。
* 1個以上の文字に一致させる
   * 正規表現 `.+`
   * Glob `?*`
* 正規表現の文字集合とGlobの文字集合は同じように動作します。

#### クォートとファイル名展開

ファイル名展開を抑止したい場面があります。ユーザー入力の処理はその1つです。次のコードを見てみましょう。

```bash
read -p "Enter something: " user_input
echo $user_input
```

ユーザーがアスタリスク（`*`）を入力したら、何が出力されるでしょうか？　カレントディレクトリにあるファイルの一覧です。これはおそらく意図した動作ではないでしょう。

もう1つの例は、パターンを期待するプログラムに、パターンを引数として渡す場合です。`tr`プログラムはテキスト操作によく使われます。変数の値を小文字にするには、次のようにします。

```bash
var="My Puppet"
echo "$var" | tr '[:upper:]' '[:lower:]'
```
出力は次のとおりです。
```none
my puppet
```

よくある間違いは、`tr`の引数をクォートし忘れることです: `tr [:upper:] [:lower:]`

~~~~exercism/caution
なぜそれが問題なのでしょうか？ 
クォートされていないGlobパターンは、一致するファイルの一覧に展開されます。
スクリプトを使っている人のカレントディレクトリに、`p`、`u`、`w`という名前のファイルがあるとします。

```bash
touch p u w
var="My Puppet"
echo "$var" | tr [:upper:] [:lower:]
```

これはエラーになります！

クォートされていない`[:upper:]`パターンは、`:`、`u`、`p`、`e`、`r`のいずれかに一致します。クォートされていない`[:lower:]`パターンは、`:`、`l`、`o`、`w`、`e`、`r`のいずれかに一致します。Bashは最初のパターンに対してファイル`p`と`u`、2番目のパターンに対してファイル`w`を一致させ、`tr`は次のように呼び出されます。

```bash
echo "$var" | tr p u w
```

そしてこれは、`tr`にとって間違った引数の数です。
~~~~

#### ファイル名展開を無効にする

[`set`][set]コマンドを使ってファイル名展開を無効にできます。

```bash
echo *      # prints a list of files
set -f      # disable filename expansion
echo *      # prints a literal asterisk
set +f      # enable filename expansion
```

#### ファイル名展開を制御する

組み込みの[`shopt`][shopt]コマンドには、ファイル名展開の動作を制御する設定がいくつかあります。興味深いものをいくつか挙げます。

* `shopt -s nocaseglob` -- 大文字と小文字を区別せずに一致させます
* `shopt -s extglob` -- 拡張パターンを有効にします
* `shopt -s nullglob` -- 一致するファイルがない場合、パターンを何もない状態に置き換えます。
   デフォルトの動作では、パターンをそのままリテラル文字列として残します。
