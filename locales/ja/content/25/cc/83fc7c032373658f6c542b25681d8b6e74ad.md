# 指示の補足

## `from_quote`を使った誕生日リテラル

`DateOfBirth.from_quote`関数は、`"YYYY-MM-DD"`という形式の文字列を`DateOfBirth`にパースします。これにより、次のようなコードを書くことができます。

```roc
birthdate : DateOfBirth
birthdate = "2019-01-20"
```

このコードは、コンパイル時に`DateOfBirth.from_quote("2019-01-20")`を暗黙的に呼び出します。この方法（および後述するほかの方法）でコンパイル時にコードを実行すると、実行時にパースやデータの検証を行う必要がないため、プログラムを高速化できる可能性があります。さらに、無効なデータ（日付の形式が正しくない場合など）は、実行時ではなくコンパイル時に拒否されるので、アプリの堅牢性も高まります。そして、コードも読みやすくなります。たとえば、この演習のテストの1つを見てみましょう。

```roc
# multiple birthdates with one shared birthday
expect {
	shared_birthday(["1966-07-29", "1977-02-12", "2001-07-29", "1980-11-10"])
}
```

ただし、このコードを読んだ人は、`shared_birthday`関数が`List(Str)`を受け取ると思うかもしれません。実際には`List(DateOfBirth)`を受け取ります。これは混乱やエラーのもとになります。そのため、少し長くなりますが、より明示的な`"2019-01-20".DateOfBirth`という書き方のほうがよいかもしれません。この書き方も、コンパイル時に`from_quote`を呼び出します。

自分のプログラムでは、次のような便利なコンストラクターを用意するとよいでしょう。

```roc
DateOfBirth := { year : I64, month : U8, day : U8 }.{
    from_ymd : I64, U8, U8 -> Try(DateOfBirth, [InvalidMonth, InvalidDay])
    from_ymd = |year, month, day| ...
}
```

このコンストラクターも、次のようにコンパイル時に呼び出すことができます。

```roc
Ok(birthdate) = DateOfBirth.from_ymd(2019, 1, 20)
```

注：この定義をトップレベルに置くと、コンパイル時に実行されます（関数が純粋で、入力がコンパイル時にわかっているためです）。関数の中では、同じコンストラクターを実行時に使うこともできます。
