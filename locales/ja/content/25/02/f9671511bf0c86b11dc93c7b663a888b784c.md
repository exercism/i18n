# はじめに

多くのオブジェクト指向言語では、親クラスを[継承してサブクラスを作る][wiki-subclass]ことで振る舞いを拡張し、親からメソッドを受け継ぎながら新しいメソッドも追加するのが一般的です。
こうしてオブジェクトの階層ができあがります。

Juliaには_クラスがありません_。したがって、_サブクラスもありません_。
では、どのようにして既存の振る舞いを継承し、拡張するのでしょうか？

これまでの概念で、型の階層をどう作るかを学び、またJuliaが[多重ディスパッチ][concept-multiple-dispatch]を使って引数の型に応じてメソッドを選ぶ仕組みも見てきました。

Juliaにはさらに、いくつかの非公式なインターフェースがあります。これを使うと、標準の型にすでに定義されている振る舞いに、自作の型を組み込むことができます。

これを一番わかりやすく示すのが、イテレーターのインターフェースです。

## イテレーター

これまでのシラバスで、Juliaがコレクションの各要素を操作するいくつかの方法を見てきました。

- [ループ][concept-loops]: `for item in items...` など
- [ブロードキャスト][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [高階関数][concept-hof]: `map(√, [1, 4, 9])`
- [内包表記][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [ジェネレーター][concept-comprehensions]: `(x^2 for x in 1:1e6)`。これは遅延評価されます。

明らかに、Juliaは標準のコレクションを要素ごとにたどる方法を知っています。上の例ではベクトルと範囲を使いましたが、SetやDictなども同様です。

では、この能力を自作のコレクションに加えるにはどうすればよいでしょうか。特に、ジェネレーターのように遅延評価できるコレクションの場合はどうでしょう。

### 最低限の要件

反復できるシーケンスを作るには、（少なくとも）2つのものが必要です。

1. _最初_の要素を取得する方法。
2. 現在の状態から_次の_要素を取得する方法。

Juliaは、`Base.iterate()`関数のメソッドを使ってこれらの作業を実現します。手順は次のとおりです。

1. まず`Base.iterate(iter)`が自動的に呼ばれます。
    - 反復するものが何もなければ、`nothing`を返します。
    - そうでなければ、最初に返す要素と最初の状態の`Tuple`、つまり`(firstitem, firststate)`を返します。
2. 前の反復で要素が返されていれば、`Base.iterate(iter, state)`が自動的に呼ばれ、`firststate`が`state`引数として渡されます。
    - 反復が終了するなら、`nothing`を返します。
    - そうでなければ、次の要素と次の状態の`Tuple`、つまり`(nextitem, nextstate)`を返します。
3. 終了するまで手順2を繰り返します。

これらの手順はすべて「舞台裏」で行われます。つまり、メソッド呼び出しと状態は反復プロトコルによって内部的に管理され（状態は非公開のまま）、ループのような高レベルの構文には要素だけが公開されます。
言い換えると、`item`だけが見え、それ以外はすべてブラックボックスの中にあります。

ここで中心となるのが[多重ディスパッチ][concept-multiple-dispatch]です。
`iter`の型がどのメソッドを呼ぶかを決め、引数の数が最初の要素を返すか次の要素を返すかを決めます。

標準の型のメソッドはすでに定義されています。`Vector`、`Range`、`Set`などです（[現在][ref-iterations-collections]は全部で14の型があります）。

自作の`MyType`に同じ振る舞いを持たせるには、まず次のものを定義する必要があります。
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

抽象的には難しそうに聞こえますが、実際にはとてもシンプルにできます。
例として、与えられた整数`n`の累乗を、最大個数まで生成する型を考えてみましょう。

まず、自作の型を定義します。

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

この型の`iterate`メソッドを定義できますが、最初の要素と最初の状態は何でしょうか？

最初の要素を得るには複雑な準備が必要なイテレーターもありますが、このおもちゃの例では、最初に返される要素はそのまま基数だとわかるので、`count`の値が1以上かどうかを確認するだけで済みます。

次に最初の状態を考えます。これは次の反復で使う情報を運びます。
どんな情報を追跡する必要があるかは自分で決めてよく、型も自由です。

この場合、`n`を累乗する「インデックス」を追跡するだけでもよいですし、より効率的な方法として、`n`の最新の累乗（つまり返された要素）と、シーケンス内の次の「インデックス」を使うこともできます。
この2つの数値は`Tuple`にまとめて`state`として返せます。

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

この例では、最初の要素（`p.n`）がループに返され、最初の状態`(p.n, 2)`が`iterate(P::Powers, state)`メソッドに渡されます。
そこで状態を処理し、現在の要素に基数を掛けて次の要素を作ります。これで指数が`1`増えます。

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

インデックスの値がまだ`count`の範囲内なら、`next`要素と増加した状態の`Tuple`が返されます。
`index`の値が`count`を超えると、代わりに`nothing`が返され、反復が終了したことを示します。

`iterate(p::Powers)`と`iterate(p::Powers, state)`のメソッドがかなり似た本体を持っていることにお気づきかもしれません。
実は、うまくやればこの類似性を利用して、2引数のバージョンだけを使い、状態にデフォルト引数を与えることで実装をすっきりさせられます。`Base.iterate(p::Powers, state=(1, 1))`
そうすれば、1引数の`iterate(p::Powers)`を別に用意する必要はありません。
実際によくできるときにはこう書かれます。

ここまでで、すでにいくつか便利な機能が使えます。たとえば3の最初の4つの累乗について、結果をループで回したり、ある数値が結果に含まれるか調べたり、`sum()`のような集約関数を適用したりできます。

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 追加のメソッド

よい出発点ではありますが、まだすべてが動くわけではありません。

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

確かに、`length(Powers(3, 4))`もまったく同じエラーメッセージを返します。

これは簡単に直せます。長さは型のコンストラクターの一部だからです（この場合は4）。
この型に対して`Base.length()`を定義するだけで、シーケンスに内包表記や`collect()`を使えるようになります。

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

効率のために、`Base.eltype()`も定義するのが最善です。これは結果の要素の型です。
これにより、`collect()`のような関数が、`Vector{Any}`に繰り返し`push!()`する代わりに、出力用の`Vector{Int}`の領域をあらかじめ確保できます。

見たことのないかもしれない構文に注意してください。このメソッドは型の_インスタンス_ではなく、_型_に対して定義されています。

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

イテレーターは有限の長さを_持たなければならない_わけではありません。
「無限」シーケンスの用途は限られますが、ループから`break`で抜け出す方法があるかぎり、それらをループで回すのは役立つことがあります。
たとえば、ある上限（整数のオーバーフローを避けるために`typemax(Int)`など）より小さい値を生成する`Powers`の変種を定義できます。

## まとめ

Juliaのアプローチは他のほとんどの言語と大きく異なるため、インターフェースの説明はとても混乱しやすいものです。
特に、インターフェースの名前が実装の中で一度も触れられないこともあります。[サブクラス化][wiki-subclass]や[ミックスイン][wiki-mixins]とは大違いです。

しかし、実際には驚くほどシンプルです。

1. 適切な型を定義します。
2. どのメソッドが必要かを調べます。
3. 自作の型に対してそのメソッドを実装します。ふつうはほんのいくつかのメソッドで、どれも短くシンプルです。
4. あとは[多重ディスパッチ][concept-multiple-dispatch]が自動的に残りを処理します。
