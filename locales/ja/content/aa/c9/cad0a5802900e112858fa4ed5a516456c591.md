# 概要

Elixirのプログラマーはよく「let it crash」と言い、「happy path」を前提としたコードを書きますが、特定の値やメッセージを返したり、システムのリソースを解放したりするために、関数呼び出しをrescueしなければならない場面もよくあります。

- 通常の状況でエラーを発生させる関数は、名前の末尾に`!`を付けるべきです。
- また、関数は成功と失敗を示すために、アトムやタプルを返すこともあります。

  ```elixir
  Map.fetch(%{a: 1}, :a)
  # => {:ok, 1}
  Map.fetch(%{a: 1}, :b)
  # => :error

  Map.fetch!(%{a: 1}, :b)
  # => raises KeyError
  ```

## アンチパターンを避けましょう

エラーを使って論理の流れを制御するプログラミングパターンは避けましょう。これはElixirではアンチパターンです。

```elixir
# Avoid using errors for control-flow.
try do
  {:ok, value} = MyModule.janky_function()
  "All good! #{value}."
rescue
  e in RuntimeError ->
    reason = e.message
    "Uh oh! #{reason}."
end

# Rather, use control-flow structures for control-flow.
case MyModule.janky_function() do
  {:ok, value} -> "All good! #{value}."
  {:error, reason} -> "Uh oh! #{reason}."
end
```
