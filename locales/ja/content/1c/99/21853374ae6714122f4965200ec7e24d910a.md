# 概要

[`interfaces`][interfaces]は、クラスの使われ方をその実装から[切り離す][wiki-loose-coupling]ための主な手段です。この切り離しによって、実装の保守に柔軟性が生まれ、型安全な汎用的な振る舞いを支えやすくなります。

インターフェースの構文は、クラスや構造体のものとよく似ていますが、メソッドとプロパティはシグネチャーとしてのみ現れ、本体は書かれません。

```csharp
public interface ILanguage
{
    string Speak();
}

public interface IItalianLanguage : ILanguage
{
    string Speak();
    string SpeakItalian();
}

public interface IScriptConverter
{
    string Version { get; set; }
    string ConvertCyrillicToLatin(string cyrillic);
}
```

インターフェースを実装するクラスや構造体は、そのインターフェースで定義されたすべての操作を実装しなければなりません。

インターフェースは、一般的に次のいずれか、あるいは複数の役割を担います。

- 多数の異なるクラスを、利用する側のコードから汎用的に扱えるようにします。この場合、インターフェースは基底クラスと同じ役割を果たします。
- 特定の目的のために、機能の一部だけを公開します（例: [`IComparable<T>`][icomparable]）。
- 複数の実装が共存できるように、クラスの公開APIを公開します。その一例が[テストダブル][wiki-test-double]です。

```csharp
public class ItalianTraveller : IItalianLanguage
{
    public string Speak()
    {
        return "Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class ItalianTravellerV2 : IItalianLanguage
{
    public string Speak()
    {
        return "migliorata - Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class FrenchTraveller : ILanguage
{
    public string Speak()
    {
        return "Ça va?";
    }
}

public class RussianTraveller : ILanguage, IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Speak()
    {
        return "Привет мир";
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}

public class DocumentTranslator : IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Translate(string russian)
    {
        throw new NotImplementedException();
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}
```

上記のインターフェースとクラスを利用するコードでは、次のことができます。

- 言語にかかわらず、すべての話し手を同じように扱えます。
- 文字変換を扱うサブシステムが、扱う具体的な型を気にせずに動作できます。
- イタリア語の話し手に対する変更を知らずに済みます。これは、クラスのコードと利用する側のコードを別々のチームが保守している場合に便利です。

インターフェースは、[モック化][so-mocking-interfaces]を簡単にできるため、テストを支えるためによく使われます。

インターフェースにどのような種類のメンバーを含められるかについては、こちらの[記事][dt-interfaces]を参照してください。

インターフェースは、他のインターフェースを継承できます。

インターフェースのメンバーは、既定でpublicです。

インターフェースには、`const`リテラル、`enums`、`delegates`、`classes`、`structs`などの入れ子の型を含めることができます。この場合、インターフェースはクラスや構造体と同じように[名前空間][wiki-namespaces]として機能し、動作と構文は同一です。

C#は設計上、多重継承をサポートしていませんが、インターフェースを通じて一種の多重継承を可能にしています。

さらに、[インターフェースを通じてポリモーフィズムを実装できる][interface-polymorphism]という考え方が、インターフェースの仕組みを支えています。

## 明示的なインターフェースの実装

メソッド名とシグネチャーが2つの異なるインターフェースで共有されることがあります。これらのメソッドに別々の実装を用意するために、C#では[インターフェースの明示的な実装][explicit-implementation]が提供されています。なお、インターフェースの特定の実装を使うには、そのオブジェクトを参照する式をそのインターフェースに変換する必要があります。代入、キャスト、あるいは引数として渡すことでこれを行えます。

```csharp
public interface IFoo
{
    void X();
}

public interface IBar
{
    void X();
}

public class Census : IFoo, IBar
{
    void IFoo.X()
    {
        Console.Write("This is from Foo");
    }

    void IBar.X()
    {
        Console.Write("This is from Bar");
    }
}

public class User
{
    public void Use()
    {
        IFoo foo = new Census();
        IBar bar = new Census();
        foo.X();
        // => "This is from Foo"
        bar.X();
        // => "This is from Bar"
    }
}
```

いくつかのユースケースがあります。

- （上記のように）メソッドのシグネチャーが同一である領域の衝突。
- 名前は同じでも戻り値の型が異なるメソッド: 独自のコレクションクラスを実装する場合、従来の`IEnumerable.GetEnumerator()`に対して、`IEnumerable<T>.GetEnuerator()`と並んで明示的なインターフェースが必要になることがあります。そのインターフェースを実際に使うことはないかもしれませんが、コンパイラーが要求してきます。
- インターフェース間で名前の衝突はないものの、実装するクラスがその名前を関連する別の目的で使いたいメソッド: `IFormattable`には`ToString()`メソッドがあり、これは`IFormatProvider`型のパラメーターと同様に_フォーマット型_のパラメーターを取ります。Base Class Library（BCL）の`FormattableString`のようなクラスは、`IFormattable`を取るルーチンから使えるようにするためにこのインターフェースを持っていますが、`ToString(IFormatProvider)`の主要なバージョンでは_フォーマット型_のパラメーターを省略するほうが表現豊かです。それは実装で使われず、APIの利用者を混乱させるからです。

## 既定の実装

C#のバージョン8は、APIにまつわる厄介な問題に対処しています。新しい実装のために機能を強化するメソッドをインターフェースに追加すると、既存のインターフェースの実装はすべて、実装固有の動作を持たないにもかかわらず、APIの契約に適合するように修正する必要がありました。C#では現在、インターフェースの一部として_既定のメソッド_を提供できるようになっています（Javaの開発者には馴染み深いでしょう）。以前は、このような変更が起きると、元のインターフェースと並んで_バージョン2_のインターフェースが存在していました。
