# 概要

_「日付と時刻なんて、小さな子どもにも教えるものだ。そんなに難しいはずがない」_

多くのプログラマーがこの過ちを犯してきました。そして、その後に味わう体験は、健康や幸福に悪い影響を与えがちです。

日付や時刻を扱う、それなりに本格的なプログラミングに取り組む人なら、少なくとも問題を理解し、その影響を抑える心構えを持っておくべきです。

このドキュメントでは、Juliaが日付と時刻をどのように扱うかの概要を説明します。ただし、詳しい内容については[マニュアル][Dates]を参照する必要があります。
[Wikibook][Wikibook]もあり、こちらのほうが説明が分かりやすいと感じる読者もいるでしょう。型の階層を表した便利な[図][type-hierarchy]も含まれています。

## `Dates`モジュール

基本的な機能のほとんどは、`Dates`というモジュールに含まれています。このモジュールはデフォルトのインストールに含まれていますが、標準ライブラリの一部ではありません。

このモジュールを使う方法は2つあります：

1. `import Dates`を追加し、すべての関数呼び出しの前に`Dates.`を付けます。
2. `using Dates`を追加します。これにより、モジュール全体が現在の名前空間に取り込まれます（ただし、一部の問題のある名前を除きます）。

```julia-repl
# option 1
julia> import Dates

julia> Dates.now()
2025-06-21T16:02:39.080

julia> now()  # wrong: need to include `Dates.` after an import
ERROR: UndefVarError: `now` not defined in `Main`


# option 2
julia> using Dates

julia> now()  # functions are now in the namespace
2025-06-21T16:03:04.161
```

`Dates`モジュールは大きくて複雑ですが、主に4つの機能を提供します：

- `Dates.Date`：日・月・年を含みますが、時刻は含みません。
- `Dates.Time`：時刻をナノ秒の精度で含みますが、日付は含みません。
- `Dates.DateTime`：日付と時刻をミリ秒の精度で組み合わせたものです。
- `Dates.Period`：時間や日付の間隔を扱います。

`DateTime`は通常、タイムゾーンの情報を_含みません_（Pythonではこれを「naive」なdatetimeと呼びます）。
例外の1つは`now()`です。これはシステムクロックから現地時刻を取得し、必要に応じてUTCに変換できます。

その他のタイムゾーンの計算には、`TimeZones.jl`パッケージが必要です。これはデフォルトのインストールには含まれていません。
2025年6月時点では、これはExercism内では利用できませんが、将来追加されるかもしれません。

おそらく最もよくあるニーズは次のとおりです：

- 適切な入力形式を解析して`Dates`型を構築する。
- `Dates`型から必要な数値または文字列の形式を取得する。
- `Date`、`Time`、`DateTime`の値にオフセットを適用する。
- 2つの値の間の間隔を計算する。
- 現在の日付（`today()`）や時刻（`now()`）を取得する。

~~~~exercism/note
見た目の煩雑さを減らすため、このドキュメントの残りの部分にあるサンプルコードのほとんどは、`using Dates`を前提としており、関数呼び出しにモジュール名`Dates.`を付けません。
~~~~

### 日付と時刻の形式

日付や時刻の書き方には多くの方法があり、文化によって異なる傾向があります。
"7/6/23"のような数字だけの日付は曖昧で紛らわしく、多国籍企業で多くの高くつく間違いを引き起こしてきました（_著者は苦い実体験からこう述べています_）。

国際規格は[`ISO 8601`][ISO8601]で定義されており、主な利点が2つあります：

- 解析が速く、曖昧さがありません。
- 日時を通常のテキストとして扱い、アルファベット順に並べ替えられるため、ソートが簡単です。

前の例で、`Date.now()`が`2025-06-21T16:03:04.161`を返すのを見ました。

これはさまざまな部分から構成されています：

- 日付部分は`YYYY-MM-DD`。
- 時刻部分は`hh:mm:ss`。
- 省略可能で、小数点以下にミリ秒（またはさらに小さな単位）を付けます。

その他の文字列形式については、後のセクションで説明します。

## Dates

`Dates.Date`は比較的シンプルな日付だけの型で、時刻やタイムゾーンは扱いません。

```julia-repl
# constructor with year, month, day arguments
julia> date1 = Date(2025, 06, 23)
2025-06-23

# constructor with ISO 8601 string
julia> date2 = Date("2025-06-23")
2025-06-23

julia> date1 == date2
true

julia> typeof(date1)
Date
```

日付の各部分を取得するアクセサ関数があり、これらは大文字と小文字で区別されるペアになっています。

```julia-repl
# lowercase returns an integer
julia> month(date1)
6

julia> typeof(month(date1))
Int64

# Propercase returns a Period type
julia> Month(date1)
6 months

julia> typeof(Month(date1))
Month

# various compound methods are also available, returning a tuple
julia> monthday(date1)
(6, 23)
```

### クエリ関数

カレンダーをある程度理解した[クエリ関数][query-func]がいろいろと用意されています。
次の例では、その一部だけを紹介します。

```julia-repl
julia> date1
2025-06-23

julia> dayofweek(date1) # 1 = Monday, 7 = Sunday
1

julia> dayname(date1)
"Monday"

julia> daysinmonth(date1)
30

julia> isleapyear(date1)
false

julia> lastdayofmonth(date1)
2025-06-30
```

## Times

`Dates.Time`は基本的な時刻だけの型です。
日付は扱いません。時刻は真夜中になると自動的に`Time(0, 0, 0)`に戻ります。

完全なコンストラクタの形式は`Time(hour, min, sec, millisec, microsec)`、またはそれに相当するISO 8601の形式です。

すべてのパラメータは省略可能で、デフォルトは`0`です。

```julia-repl
julia> Time(14, 57, 25, 142)
14:57:25.142

julia> Time(14, 57, 25, 142, 32)`
14:57:25.142032

julia> Time("14:57:25.142")
14:57:25.142
```

`Date`と同様に、各部分はアクセサ関数で取得できます：

```julia-repl
julia> minute(t) # => integer
57

julia> Minute(t) # => Period
57 minutes
```

## DateTimes

`Dates.DateTime`は、`Date`型と`Time`型の機能のほとんどを組み合わせたものです。

これら3つのクラスの中で最も汎用性が高いですが、時刻の分解能はミリ秒までに限られます（`Time`はナノ秒まで扱えます）。

```julia-repl
julia> dt1 = DateTime(2025, 6, 23, 14, 57, 25, 142)
2025-06-23T14:57:25.142

# date1 and t were defined in previous examples
julia> dt2 = DateTime(date1, t)
2025-06-23T14:57:25.142
```

年・月・日のパラメータのデフォルトは`1`で、時刻のパラメータはすべてデフォルトが`0`です。

これらのパラメータをすべて正しく把握するのは大変なので、ISO形式のほうが好ましいかもしれません。

あるいは、上の例のように、`Date`と`Time`から`DateTime`を構築することもできます。

## Periods

日付・時刻の各要素には、それぞれ独自の[`Period`][period]型があり、`Year`から`Nanosecond`まで、時間の間隔を表します。
これらは特に計算に役立ちます。

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Year(21)
21 years

julia> Second(61)
61 seconds

julia> dt1 + Year(21) - Second(61)
2046-06-23T14:56:24.142

julia> Date(2025, 07, 03) - Date(2025, 04, 25)
69 days
```

複数の`Period`型を組み合わせられる[`CompoundPeriod`][compound-period]型もあります。
奇妙なことに、現時点では名前空間のエラーを避けるためにモジュール名を付ける必要があります（_これはバグのように思えます_）。

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> offset = Dates.CompoundPeriod(Year(21), Second(-61))
21 years, -61 seconds

julia> dt1 + offset
2046-06-23T14:56:24.142
```

日付や時刻を引くと、間隔は（日付なら）日単位、または（時刻なら）ナノ秒単位で表されます。
これらを`CompoundPeriod`に[`canonicalize`][canonicalize]すると役立つかもしれません。

```julia-repl
julia> diff = Time(23, 14, 00) - Time(1, 23, 52)
78608000000000 nanoseconds

julia> canonicalize(diff)
21 hours, 50 minutes, 8 seconds

julia> typeof(canonicalize(diff))
Dates.CompoundPeriod
```

`Period`型を扱うとき、Juliaは月の長さのようなカレンダーの不規則さをうまく処理しようとし、必要に応じて丸めます。

```julia-repl
# February has fewer days than January
julia> Date(2025, 1, 31) + Month(1) 
2025-02-28
```

## [丸め][rounding]

`floor`、`ceil`、`round`という関数は、整数や小数でおなじみかもしれませんが、日付や時刻でも使えます。
丸める単位の`Period`を第2引数に指定します。

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> floor(dt1, Minute(15))
2025-06-23T14:45:00

julia> ceil(dt1, Minute(30))
2025-06-23T15:00:00

julia> ceil(dt1, Month(1))
2025-07-01T00:00:00
```

## 文字列での表現

先ほどISO 8601規格に触れましたが、これはJuliaが文字列をフォーマットしたり解析したりするときの、日付・時刻のデフォルトの表現です。

言うまでもなく、他にも多くの形式がよく使われており、しばしば文化に固有のものです。
これらを扱うために、Juliaには`DateFormat`型があり、任意の複雑さのフォーマット文字列から構築できます。

```julia-repl
# dateformat"" string syntax
julia> dtfmt = dateformat"d/m/y"
dateformat"d/m/y"

julia> typeof(dtfmt)
DateFormat{Symbol("d/m/y"), Tuple{Dates.DatePart{'d'}, Dates.Delim{Char, 1}, Dates.DatePart{'m'}, Dates.Delim{Char, 1}, Dates.DatePart{'y'}}}

# DateFormat constructor
julia> DateFormat("d/m/y")
dateformat"d/m/y"
```

上の例はごくシンプルで、ヨーロッパでよく使われる日/月/年の形式の日付にすぎません。
2つの構文のバリエーションを示しましたが、結果は同じです。

そうすると、`DateFormat`は適切な文字列の解析に使えます：

```julia-repl
julia> DateTime("14/7/2023", dtfmt)
2023-07-14T00:00:00
```

`DateFormat`の作成には大きなオーバーヘッドがかかるため、多くの日付・時刻文字列をループ処理するときは、このステップを（ここでの`dtfmt`のように）1回だけ行うとパフォーマンスに役立ちます。

フォーマットはこれよりはるかに複雑にできるので、詳細は[マニュアル][dateformat]を参照してください。

他の言語に慣れている人なら、何十年も前からある`strptime`や`strftime`関数との類似に気づくかもしれません。
Julia版はこの遺産から借りていますが、より簡潔で柔軟であることを目指しています。

同じ`DateFormat`は、[`Dates.format()`][format]関数を使って、日付・時刻を任意の文字列形式で出力するのにも使えます。

残念ながら、`format`とは名前空間が衝突するようです（少なくともJulia 1.11.5時点では）。そのため、`using Dates`の後でも`Dates.`の接頭辞を付けるのがよいでしょう。

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Dates.format(dt1, dateformat"e, u d")
"Mon, Jun 23"
```

[ドキュメント][wiki-format]にあるように、`"e, u d"`は曜日と月の省略されたテキスト表現になります。

テキスト表現のデフォルトは英語です。
他の言語も追加できますが、現時点ではそのサポートはあまり十分とは言えません。
