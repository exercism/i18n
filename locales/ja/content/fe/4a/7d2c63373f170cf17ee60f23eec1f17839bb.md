# はじめに

## 部分適用と関数合成

### 部分適用

Elmのすべての関数は[カリー化][currying]されています。つまり、すべての引数を渡さずに関数を呼び出すと、新しい関数が返ります。

この結果は[部分適用][partial-application]と呼ばれます（関数にすべての引数を渡しているのではなく、その一部だけを適用しているのです）。

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

部分適用では、引数は常に順番に適用されます。

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

### パイプ演算子（`|>`）

`x |> f`と書くのは、`f x`とまったく同じです。具体例を挙げると、`"5" |> String.toInt`は`String.toInt "5"`と同じです。

最初はあまり役に立たないように思えるかもしれませんが、これは[パイプ演算子][pipe-operator]と呼ばれ、「パイプライン」のようなコードを書けるようにしてくれます。

たとえば、ユーザーの入力を整数に変換するsanitize関数があるとします。

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

これは次のように書き換えられます。

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

こうすると括弧（`()`）を使わずに済み、関数が適用される順番（最初に`String.trim`、次に`String.toInt`）がそのまま見えるので、読みやすくなります。

[逆パイプ演算子`(<|)`][reverse-pipe-operator]もあります。
`f <| x`と書くのは、`f x`とまったく同じです。
これも一見するとあまり役に立たなさそうで、パイプ演算子ほど使われることはありませんが、状況によっては括弧を避けるのに役立ちます。

### 関数合成 / ポイントフリースタイル

[`(>>)`][forward-composition]演算子は`(a -> b) -> (b -> c) -> (a -> c)`という型を持ち、型が`a -> b `と`b -> c`の2つの互換性のある関数を合成して、型が`a -> c`の関数を作ります。
これは、最初の関数の出力（型`b`）を受け取り、それを2番目の関数（同じ型`b`でなければなりません）の最初の引数として使うことで行います。
作られる関数は、最初の関数と同じ入力（型`a`）を受け取り、2番目の関数が返す`c`をそのまま返します。

具体例は`String.trim >> String.toInt`です。
`String.trim`は文字列を唯一の入力として受け取るので、作られる関数もそれを受け取ります。
`String.toInt`は`Maybe Int`を返すので、作られる関数もそれを返します。
`String.trim`は`String`を返し、それを`String.toInt`が入力として受け取れるので、この例はコンパイルが通ります。

これで、`sanitize`関数を次のように書き換えられます。

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

元の例にある`input`という入力を使わなくなっていることに注目してください。ただし機能はまったく同じです。
このように、自分の入力に一切言及せずに関数を作る書き方は、「ポイントフリースタイル」と呼ばれます。
このスタイルの利点はコードがより簡潔になることで、欠点は、特に初心者にとっては理解しにくくなることがあります。

Elmではすべての関数がカリー化されているので、`String.length >> max`がコンパイルできることを覚えておくとよいでしょう。

- [`(>>)`][forward-composition]演算子は`(a -> b) -> (b -> c) -> (a -> c)`という型を持ちます。
- `String.length`の型は`String -> Int`で、これが`(a -> b)`の部分にあたります。つまり`a`は`String`、`b`は`Int`です。
- `max`の型は`Int -> Int -> Int`で、これが`b -> c`の部分にあたります。
- `b`は`Int`なので、`max`は部分適用され、`c`はその部分適用の結果（`Int -> Int`）になります。
- したがって、`String.length >> max`の型は`String -> (Int -> Int)`になります。
- つまり、`((String.length >> max) "123") 2`は`3`を返します。`"123"`の長さは3で、`Int`の引数である2より大きいからです。

### 関数の設計

Elmでエレガントなコードを書きやすくするには、主要なデータ構造を関数の最後の入力にするようにします。
標準ライブラリにある一般的な関数は、`List.map`（型シグネチャは下記）のように、すべてこのようにしています。

```elm
map : (a -> b) -> List a -> List b
```

ここでは、`map`関数の最後の入力が`List a`で、`List b`を返しているので、主要なデータ構造（`List`）が最後の入力になっていることがわかります。

これにより、次のようなエレガントなパイプラインコードが書けるようになります。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

また、パイプラインの代わりに、関数合成やポイントフリースタイルを使うのも便利になります。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

関数合成を使えば、この例を`List.map`の1回の呼び出しにまとめることもできます。

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
