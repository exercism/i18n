# 概要

シラバスのここまでで、関数定義はもうたくさん見てきたはずです。たいていは、REPLでの出力についてあまり説明もなく示されていたでしょう。

```julia-repl
julia> f(x) = x^2
f (generic function with 1 method)
```

なぜ_「generic function with 1 method」_なのでしょうか？

引数の型について、もっと具体的に指定したいとします。

```julia-repl
julia> f(x::Integer) = x^2
f (generic function with 2 methods)

julia> f(x::Real) = x^2
f (generic function with 3 methods)
```

あるいは、引数の数を変えることもできます。

```julia-repl
julia> f(x, y) = x * y
f (generic function with 4 methods)
```

同じ関数を新しく定義したものは「メソッド」と呼ばれるようです。メソッドは、古い定義を上書きするのではなく、リストに追加されていきます。

メソッドの一覧は簡単に表示できます。

```julia-repl
julia> methods(f)  # output edited for brevity
# 4 methods for generic function "f" from Main:
 [1] f(x, y)
 [2] f(x::Integer)
 [3] f(x::Real)
 [4] f(x)
 ```

関数`f`を呼び出すと、Juliaはどのメソッドを使うべきかを、どういうわけかわかっています。

```julia-repl
julia> f(2.5)  # Float64
6.25

julia> f(2)  # Int64
4

julia> f(2, 3)  # Int64, Int64
6
```

## 関数とは？

[マニュアル][function]によると、関数とは引数のタプルを戻り値に対応させるオブジェクトです。これは数学者が使う定義に近いものです。

普段は、`f(2, 3)`の引数を2つの別々のものと考えますが、コンパイラーはそれらを1つの[タプル][tuple]として見ています。これは引数が1つの場合でも同じです（ただし、それを明確にするにはカンマを付ける必要があります）。

```julia-repl
julia> typeof( (2, 3) )
Tuple{Int64, Int64}

julia> typeof( (2,) )
Tuple{Int64}
```

関数をブラックボックスとして見ると、タプルが入って戻り値が出てくると言えます。もっと正式には、タプルが戻り値に_対応づけられる_のです。

## 関数は引数の数や型の違いをどう扱うのか？

これは通常[「ポリモーフィズム」][polymorphism]と呼ばれます。

これはコンピューターサイエンスで何十年にもわたる大きなテーマであり、さまざまなアプローチが採用されてきました。

Juliaのアプローチは独特ですが、唯一無二というわけではありません。

- 関数は[「ジェネリック」][generic]です。つまり、複数のメソッドを関連付けることができます。
- 関数は、メソッドが関連付けられるまでは、単なる名前です。
- メソッドは必要に応じて追加でき、場合によっては大量になることもあります（`+`演算子は現在161個のメソッドを持つ関数です）。
- 関数が呼び出されると、Juliaは呼び出しシグネチャ、つまり引数の数とそれぞれの現在の型を調べます。
- 呼び出しシグネチャに最もよく一致するメソッドが選ばれます。
  - 一般に、引数の数は正確に一致している必要があります（ただし、[スプラット/スラープ][splat]演算子`...`を使えば、これを部分的に回避できます）。
  - 呼び出しシグネチャと型が完全に一致するメソッドが優先されます。
  - 必要に応じて、Juliaは呼び出しシグネチャの各引数のスーパータイプを調べ、最もよく一致する、最も具体的なメソッドを探します。
- 選ばれたメソッドは、与えられた引数で[`dispatched`][dispatch]され、結果を返します。
- 適切なメソッドが見つからない場合は、[`MethodError`][methoderror]が発生します。

Juliaは動的型付けであるため、メソッドのディスパッチは_実行時_に行われることに注意してください。

## 多重ディスパッチ：例

前のセクションは言葉が多かったので、これらのアイデアをコードに置き換えてみましょう。簡単にするため、以下の関数は引数を1つだけにしていますが、何十もの引数を持つ関数（たとえばプロット用のパッケージや機械学習など）も珍しくありません。

まず、図形を表すカスタム型を定義するところから始めましょう。

```julia-repl
julia> abstract type Shape end

julia> struct Circle <: Shape
           radius::Float64
       end

julia> struct Square <: Shape
           side::Float64
       end

julia> struct Rectangle <: Shape
           length::Float64
           width::Float64
       end
```

次に、それぞれの図形の面積を計算するメソッドを定義できます。どのメソッドも引数を1つ取り、その引数はそれぞれ異なる、ユーザー定義の具象型です。

```julia-repl
julia> area(c::Circle) = π * c.radius^2
area (generic function with 1 method)

julia> area(s::Square) = s.side^2
area (generic function with 2 methods)

julia> area(r::Rectangle) = r.length * r.width
area (generic function with 3 methods)
```

これで、いくつか図形を作成して面積を計算できます。Juliaのディスパッチ機構が、それぞれに正しい公式を使ってくれます。

```julia-repl
julia> circle = Circle(2.3)
Circle(2.3)

julia> area(circle)  # call signature Tuple{Circle}
16.619025137490002

julia> square = Square(1.6)
Square(1.6)

julia> area(square)  # call signature Tuple{Square}
2.5600000000000005

julia> rectangle = Rectangle(1.4, 2.1)
Rectangle(1.4, 2.1)

julia> area(rectangle)  # call signature Tuple{Rectangle}
2.94
```

## [パラメトリックメソッド][parametric]

メソッドのシグネチャは、パラメトリック型とほぼ同じように、ダミーの型値を受け取ることができます。

構文は独特で、`where`節が必要です。

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T} = true
same_type (generic function with 1 method)

julia> same_type([1, 2], 3)
true

julia> same_type([1, 2], "three")
ERROR: MethodError: no method matching same_type(::Vector{Int64}, ::String)
```

上の例では、2つの引数が同じ型`T`（どんな型でもかまいません）を使う必要があります。

`T`に制約を付けることで、より具体的にできます。

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T<:Number} = true
same_type (generic function with 2 methods)
```

このメソッドでは、同じ数値型のときだけ`true`が返ります。

`where`節にカンマで区切って、複数のダミー変数を指定することもできます。次の2つのメソッドは似て見えます。

```julia-repl
julia> func(v::Vector{Number}, x::Number) = true
func (generic function with 1 method)

julia> func(v::Vector{S}, x::T) where {S<:Number, T<:Number} = true
func (generic function with 2 methods)
```

1つの違いは、2つ目のメソッドでは、関数本体の中で型値`S`と`T`を使えることです。こうしたテクニックはあまり使わないかもしれませんが、状況によっては手間を大幅に省いてくれます。

たとえば、次のパラメトリック型の定義では、フィールドは同じ型`T`である必要があり、`T`は`Real`のサブタイプに制約されています。

```julia
struct Point{T<:Real}
    x::T
    y::T
end
```

この`Point`の定義は、同じ型の`x`と`y`を受け付けます。あるいは、異なる型の`x`と`y`も受け付けますが、その場合は明示的な変換型を指定する必要があります。

```julia-repl
julia> Point(4, 5)
 Point{Int64}(4, 5)

julia> Point(3.5, 2)
 MethodError: no method matching Point(::Float64, ::Int64)    # Output truncated for brevity

julia> Point{Float32}(3.5, 2)
 Point{Float32}(3.5f0, 2.0f0)

julia> Point{Int64}(3.5, 2) 
 InexactError: Int64(3.5)      # Output truncated for brevity
```

このレベルの型の制御が望ましいこともありますが、少し抽象化できると便利なこともあります。

```julia
Point(x::T, y::S) where {T<:Real, S<:Real} = Point{promote_type(T,  S)}(x, y)
```

この外部コンストラクタは、変換型を明示的に指定しなくても、`Point`が`x`と`y`に異なる型を受け付けられるようにすることで、これを実現します。型値`T`と`S`は、関数本体の`promote_type(T, S)`の中で使われ、元の定義に明示的な変換型を提供します。

```julia-repl
julia> Point(3.5, 2)
 Point{Float64}(3.5, 2.0)
```

## 他の言語との比較

Juliaはメソッドを選ぶときにすべての引数を調べるため、これは[`multiple dispatch`][multiple-dispatch]と呼ばれます。

Common Lispなど、多重ディスパッチを許可する言語もいくつかありますが、Juliaほど言語設計の中心になっていることはめったにありません。

対照的に、オブジェクト指向（OO）言語（たとえばRuby）では、メソッドは通常[インスタンス][instance]に対して呼び出されます。定義の上では第1引数が特別扱いされ（定義内では`self`や`this`といった名前が付きます）、メソッド名をインスタンスにドットでつないで呼び出します。

```ruby
irb(main):004:0> "abc".sub("b", "*")
=> "a*c"
```

これは[`single dispatch`][single-dispatch]と呼ばれます。メソッドの選択に使われるのは、インスタンスのクラス（上の例では文字列"abc"のクラス）だけだからです。

静的型付けのOO言語の中には、メソッドのポリモーフィズムをサポートしているものもあります。これは多重ディスパッチと少し似ています。大きな違いは、メソッドの選択が_コンパイル時_にしか行われないことです。

関数型言語は、関数の定義を1つしか持たないことが多く、さまざまなケースに対応するためにSelect/Case/Matchのような式を使います。ロジックは自分で書くことになり、通常は簡潔なパターンマッチ構文が助けになりますが、Juliaにはその構文がありません。もちろん、Juliaにもパターンマッチの一種はありますが、それは関数本体の中ではなく、ディスパッチのときに行われます。

## まとめ

多重ディスパッチはJuliaでは非常に柔軟で高性能なため、広く使われています。

`+`に161個のメソッドがある例が示すように、Juliaのプログラマーは、型を狭く限定したメソッドを定義することを目指します。バイトコードのレベルでは、2つの整数を足すことと2つの浮動小数点数を足すことはまったく異なります。さらに、整数と浮動小数点数を足すと、型昇格という余計な複雑さが加わります。

型が具体的であればあるほど、コンパイラーが行える最適化は増えます。Exercismの簡単な演習ではささいなことですが、Juliaが想定している大規模な数値シミュレーションのパフォーマンスには欠かせません。

_メソッドがどんな入力を受け取るのかわかっているなら、ぜひコンパイラーに教えてあげてください！_
