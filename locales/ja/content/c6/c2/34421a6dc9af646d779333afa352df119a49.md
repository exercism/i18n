# 文字列の型

Cairoには、文字列のためのネイティブなデータ型はありません。
ただし、文字列の型を表現する方法は2つあります。1つの`felt252`を使う短い文字列と、`ByteArray`を使う任意の長さの文字列です。

## 短い文字列

短い文字列はシングルクォートで作られ、文字列を構成する各文字は[ASCII標準][ascii-table]に従って1バイトでエンコードされます。

たとえば、ASCII文字列として、`'abc'`は次のようになります。

- `'a'`は`0x61`に相当します
- `'b'`は`0x62`に相当します
- `'c'`は`0x63`に相当します
- `'abc'`は`0x616263`に相当します

Cairoでは、`felt252`データ型が短い文字列を保持します。
`felt252`は251ビットを含むため、短い文字列は31文字に制限されます（31 \* 8 = 248ビットで、これは251ビットに収まる8の最大の倍数です）。

短い文字列の宣言の例：

```rust
    let my_first_char = 'D';
    let my_first_char_in_hex = 0x44;

    let my_first_string = 'Hello world';
    let my_first_string_in_hex = 0x48656C6C6F20776F726C64;
```

### ByteArray

ByteArray構造体は、Cairo 2.4.0で導入されました。
ByteArrayの文字列は、次のようにダブルクォートで書きます。

```rust
    let long_string: ByteArray = "this is a string which has more than 31 characters";
```

技術的には、このアップデートでは`bytes31`型も導入されました。これは31バイトを保持し、1つのfeltに収まります。
`ByteArray`構造体は、基本的に、felt全体を埋めるワードである「完全なワード」を保持する`bytes31`の配列と、「不完全なワード」を保持する1つのfeltフィールドを使って長い文字列を表現します（その中のバイト数は、別の長さフィールドで指定されます）。

```rust
#[derive(Drop, Clone, PartialEq, Serde, Default)]
struct ByteArray {
    data: Array<bytes31>,
    pending_word: felt252,
    pending_word_len: usize,
}
```

[ascii-table]: https://www.asciitable.com/
