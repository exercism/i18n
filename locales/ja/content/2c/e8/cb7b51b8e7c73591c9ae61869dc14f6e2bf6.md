# はじめに

Juliaは、できるだけ多くのコードをJITコンパイルできる関数の中に書くことを推奨しています。また、小さな関数をたくさん作ることは、設計上、性能が良くなるようになっています。

その結果、小さくて単純な関数がたくさん残りがちで、それらを組み合わせて複雑なタスクを実行する必要があります。

わかりやすい方法の1つは、関数呼び出しを入れ子にすることです。
次の例はかなり作為的ですが、要点をよく表しています。

```julia-repl
julia> first.(titlecase.(reverse.(["my", "test", "strings"])))
3-element Vector{Char}:
 'Y': ASCII/Unicode U+0059 (category Lu: Letter, uppercase)
 'T': ASCII/Unicode U+0054 (category Lu: Letter, uppercase)
 'S': ASCII/Unicode U+0053 (category Lu: Letter, uppercase)
```

この方法の欠点は、入れ子が深くなるにつれて可読性が急速に下がることです。

よりシンプルで柔軟な方法が必要です。

## 合成

これは数学者に愛用されている手法で、Juliaは数学の構文をそのまま取り入れています。

任意の数の関数を、`∘`演算子（`\circ`と入力してからTabキー）で[`composed`][comp]できます。
結果は1つの関数として使えます。

```julia-repl
julia> compfunc = first ∘ titlecase ∘ reverse
first ∘ titlecase ∘ reverse
julia> compfunc.(["my", "test", "strings"])
3-element Vector{Char}:
 'Y': ASCII/Unicode U+0059 (category Lu: Letter, uppercase)
 'T': ASCII/Unicode U+0054 (category Lu: Letter, uppercase)
 'S': ASCII/Unicode U+0053 (category Lu: Letter, uppercase)
# alternative syntax, giving the same result
julia> (first ∘ titlecase ∘ reverse).(["my", "test", "strings"])
```

注意すべき点がいくつかあります：

- 元になる関数は、入れ子にするときと同じ順序で並び、右から左の順に実行されます。
- 合成するときはブロードキャストを使いにくいですが、合成した関数を呼び出すときには適用できます。

## パイプライン処理

別の方法は、*数学者*ではなく*プログラマー*のアプローチと言えるかもしれません。

[`Pipelines`][comp]はUnixシェルスクリプトで長く使われており、近年では主流のプログラミング言語でも人気になりました（F#がその採用を先駆けたと言われることもあります）。

基本的な考え方は、何らかのデータから始めて、それを一連の関数に通して結果を得るというものです。

パイプ演算子は`|>`です（F#や最近のRと同じです）。ただしJuliaにはブロードキャスト版の`.|>`もあります。

```julia-repl
julia> ["my", "test", "strings"] .|> reverse .|> titlecase .|> first
3-element Vector{Char}:
 'Y': ASCII/Unicode U+0059 (category Lu: Letter, uppercase)
 'T': ASCII/Unicode U+0054 (category Lu: Letter, uppercase)
 'S': ASCII/Unicode U+0053 (category Lu: Letter, uppercase)
```

実行は厳密に左から右へ進み、各関数の出力は矢印の方向に流れて、次の関数の入力になります。

## 制限、回避策、その他の選択肢

合成とパイプライン処理の説明に使った関数がすべて*単一*の引数を取るのは、偶然ではありません。

純粋関数型言語の中には、*最初*の引数を関数にパイプしつつ、他の引数も渡せるものがあります。

対照的に、Juliaのパイプラインでは関数の*名前*（または同等のもの）だけを求め、追加の引数は取りません。

これには重要な技術的理由があります（[`currying`][currying]が言語設計の標準的な一部ではないことに関係しています）。
カリー化を理解していない*多くの*人は、この制限が不注意による見落としではなく、将来のJuliaのバージョンでも変わる見込みが低いことを、ただ受け入れてください。

### 回避策

必要な処理をしてくれる単一引数の関数が必要です。
幸いなことに、Juliaで新しい関数を定義するのは簡単です。

最も簡単なのは、[`anonymous function`][anonymous-function]を使うことです。
たとえば、入力の文字列が1つあり、それをアンダースコアで分割したいとします：

```julia-repl
julia> "my_test_strings" |> (s -> split(s, '_'))
3-element Vector{SubString{String}}:
 "my"
 "test"
 "strings"
```

そのベクトルは、これまでと同じように他の関数へパイプできます。

この場合、無名関数を括弧（`()`）で囲むのは省略できますが、より一般的には曖昧さを減らすのに役立つ方法です。

同様に、プログラムの早い段階で名前付き関数を作り、必要に応じて再利用することもできます。

[currying]: https://en.wikipedia.org/wiki/Currying
