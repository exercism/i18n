# はじめに

## SIMD：整数

前の概念では、パックされた浮動小数点値、つまり複数の数値を1つの`xmm`レジスタに保持し、レーンごとに並列で操作する方法を紹介しました。
同じ`xmm`レジスタは、パックされた_整数_を保持することもできます。

### 構文

SIMD浮動小数点モデルのほとんどは、パックされた整数にもそのまま当てはまります。

- 128ビットのレジスタはレーンに分割されます
- 命令は、同じ位置にあるレーンに対して並列に作用します
- メモリオペランドは、同じ16バイトのアラインメント規則に従います

ただし、構文は少し異なります。

1. 命令が_パックされた_データを操作することを示す_接頭辞_`p`。
2. 実行される演算。非SIMD（_スカラー_とも呼ばれます）の対応する演算と同じ名前です（例：`add`、`mul`など）。
3. 各レーンのサイズを示す接尾辞。

パックされた整数には4つのレーンサイズがあり、それぞれに独自の接尾辞があります。

| レーン幅 | バイト数 | 128ビット内のレーン数 | 接尾辞 |
|------------|-------|-------------------|--------|
| バイト       | 1     | 16                | b      |
| ワード       | 2     | 8                 | w      |
| ダブルワード      | 4     | 4                 | d      |
| クアッドワード      | 8     | 2                 | q      |

たとえば、次のようになります。

| 命令 | 意味                              |
|-------------|--------------------------------------|
| `paddb`     | パックされた`add`、8ビットレーン（16レーン） |
| `paddw`     | パックされた`add`、16ビットレーン（8レーン） |
| `paddd`     | パックされた`add`、32ビットレーン（4レーン） |
| `paddq`     | パックされた`add`、64ビットレーン（2レーン） |

一部の命令は、あるサイズのレーンを入力として受け取り、別のサイズを出力とします。
それらは同じ一般的な規則に従いますが、サイズ接尾辞が_2つ_付きます。
最初の接尾辞は入力レーンのサイズを示し、2番目は出力レーンのサイズを示します。

| 命令  | 意味                                           |
|--------------|---------------------------------------------------|
| `pmovsxwd`   | パックされた`movsx`、16ビットレーンから32ビットレーンへ |
| `pmuldq`     | パックされた`mul`、32ビットレーンから64ビットレーンへ   |

### メモリの移動

2つの整数名の命令は、`xmm`レジスタとメモリの間で128ビットをコピーします。

| 命令 | 説明                                             |
|-------------|---------------------------------------------------------|
| `movdqa`    | _アラインメントされた_場所との間でパックされた整数をコピーします   |
| `movdqu`    | _アラインメントされていない_場所との間でパックされた整数をコピーします |

これらは`movaps`と`movups`と同様に動作します。`movdqa`はアラインメントされていないアドレスでフォールトしますが、`movdqu`はどのアドレスも受け付けます。
4つとも、128ビットを解釈せずにコピーします。
整数名のペアは、要件ではなく慣例として整数データと一緒に使われます。

~~~~exercism/note
ここで`dq`は`double-qword`、つまり128ビット（16バイト）を表します。
~~~~

### 加算と減算

加算と減算は命名規則に従います。

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

符号付きと符号なしの別形式はありません。
2の補数では、レーンを符号付きとして読むか符号なしとして読むかに関係なく、加算と減算は同じビットを生成するため、1つの命令で両方をまかなえます。
解釈は、スカラーの`add`と`sub`の場合とまったく同じで、使う側が決めます。

これらの命令は、スカラーの対応命令と同様に、オーバーフロー時に**ラップアラウンド**します。
8ビットレーンは値を256を法として保持するため、`paddb`で`200 + 100`を計算すると`300 - 256 = 44`となり、収まらないビットは切り捨てられます。

これらの余分なビットは次のレーンに繰り越されないことに注意してください。
各レーンは、同じレジスタを共有していても、他のレーンとは別々に操作されます。

### 飽和加算と減算

整数SIMDには、浮動小数点SIMDにはない演算が加わります。**飽和**加算と減算で、ラップアラウンドする代わりに_クランプ_します。
レーンの範囲を超える結果は、そのレーンが保持できる最大値になり、範囲を下回る結果は最小値になります。

飽和形式では、サイズ接尾辞の前に`s`（符号付き）または`us`（符号なし）を挿入します。

| 命令 | 意味                                    |
|-------------|--------------------------------------------|
| `paddsb`    | `add`、飽和、符号付き8ビットレーン      |
| `paddusb`   | `add`、飽和、符号なし8ビットレーン    |
| `psubsw`    | `sub`、飽和、符号付き16ビットレーン     |
| `psubusw`   | `sub`、飽和、符号なし16ビットレーン   |

クランプ範囲は、対応するサイズと符号属性を持つ整数の表現可能な全範囲です。
バイトの場合：

- 符号なしバイトは`[0, 255]`にクランプされます。`paddusb`で`200 + 100`を計算すると`255`になり、`psubusb`で`5 - 10`を計算すると`0`になります。
- 符号付きバイトは`[-128, 127]`にクランプされます。`paddsb`で`100 + 50`を計算すると`127`になります。

飽和は、ピクセルのチャンネルや音声サンプルのように、レーンが有限の量を保持する場合に重要です。
ラップアラウンドでは明るすぎるピクセルが暗くなってしまいますが、クランプなら最大の明るさを保てます。これが望ましい結果です。

~~~~exercism/note
飽和加算と減算はバイトとワードのレーンにのみ存在し、ダブルワードやクアッドワードにはありません。
~~~~

### 乗算

2つのNビット値を乗算すると2Nビットの積が生成されることがありますが、宛先レーンの幅はNビットしかありません。
SIMD演算では、積のどちらの半分を保持するか、つまり下位Nビットか上位Nビットかを指定することでこれを解決します。

16ビットレーンの場合、3つの命令を使います。

| 命令 | 意味                                                       |
|-------------|---------------------------------------------------------------|
| `pmullw`    | `mul`、16ビットレーン、各積の下位16ビットを保持     |
| `pmulhw`    | `mul`、16ビットレーン、上位16ビットを保持、符号付きオペランド   |
| `pmulhuw`   | `mul`、16ビットレーン、上位16ビットを保持、符号なしオペランド |

積の下位16ビットは、オペランドを符号付きとして読んでも符号なしとして読んでも同じなので、`pmullw`は1つだけです。

ただし、上位16ビットは結果の符号属性によって異なります。
そのため、上位半分の乗算には符号付き乗算と符号なし乗算の別形式があります。

1. `pmulhw`：符号付き乗算用。
2. `pmulhuw`：余分な`u`が付き、符号なし乗算用。

構文に注意してください。

1. パックされた整数を表す`p`。
2. 実行される演算`mul`。
3. 結果の上位（"high"）ビットが選択されることを示す`h`。
4. 結果を符号なしとして解釈する場合の任意の`u`（つまり、符号拡張されません）。
5. 最後に、ワード（16ビット）演算であることを示すサイズ接尾辞`w`。

ワードのパック乗算は上記の規則に正確に従います。
ダブルワード（32ビット）乗算もこの規則に従いますが、下位半分を選択する変種しかありません。`pmulld`です。

上位ビットを選択するダブルワード乗算の変種はありません。
ただし、乗算を_拡張_し、_偶数インデックス_のレーン（つまり位置0と2のレーン）の完全な64ビット積を格納する変種があります。

| 命令 | 意味                                                                          |
|-------------|----------------------------------------------------------------------------------|
| `pmuludq`   | 偶数インデックスの32ビット要素を符号なしで乗算し、2つの完全な64ビット積にする |
| `pmuldq`    | 偶数インデックスの32ビット要素を符号付きで乗算し、2つの完全な64ビット積にする   |

構文では`dq`が使われ、符号なし乗算の場合はその前に`u`が付くことがあります。
これは、命令が`dword`レーンを入力として受け取り、`qword`レーンを出力するためです。

### 除算

パック整数の除算はありません。
必要なコードは、値を浮動小数点に変換して除算し、元に戻します。

### 整数の拡張

`movsx`と`movzx`にはパック版があります。
これらは、出力とは異なるレーンサイズの入力を取る命令について説明したのと同じ構文に従います。

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

レーン数は、より大きい方（出力）の幅によって決まることに注意してください。
命令は、ソースの下位部分からその数のレーンを読み取ります。
これは、単精度と倍精度の浮動小数点間のパック`cvt`命令ですでに見たのと同じ意味論です。

### 整数と浮動小数点の変換

32ビット符号付き整数と浮動小数点レーンの間で変換する命令があります。
これらは`cvt`および`cvtt`命令の通常の構文に従いますが、`si`の代わりに、パックされた整数は`dq`で表されます。

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
パックされた整数を表すために`pi`を使う命令は、レガシーな`mmx`レジスタに書き込み、x86-64では事実上非推奨です。
`xmm`レジスタを使う`dq`形式を優先してください。
~~~~

浮動小数点数と整数の間のスカラー変換について述べた同じ注意点がここでも当てはまります。
浮動小数点数はMXCSRと呼ばれる特別なレジスタに従って丸められ、そのモードは関数に入った時点で仮定できません。
結果を常に切り捨てる`cvtt`変種（余分な`t`が付きます）があります。

変換前にパックされた浮動小数点値を既知の状態にするために、`round`を使うこともできます。
丸め制御値はスカラーの`round`と同じで、構文もパックされた浮動小数点値の場合と同じです。

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
