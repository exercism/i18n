# Tests

Ejecutar los tests implica ejecutar `cmake -G` y después usar el comando de compilación adecuado para tu plataforma.
Puedes encontrar instrucciones detalladas sobre cómo hacerlo en la página [Ejecutar los tests][cpp-tests-instructions] para C++ en exercism.org.

## Superar los tests

Cuando empiezas un ejercicio nuevo en local, los archivos están configurados para que solo se realice el primer test.
Haz que ese primer test compile, enlace y pase siguiendo las [tres reglas del desarrollo guiado por tests][three-laws-of-tdd].
Crea la estructura justa declarando espacios de nombres, funciones, clases, etc., para resolver los posibles errores del compilador y conseguir que el test falle.
Después, escribe el código justo para conseguir que el test pase.
Cuando lo hayas hecho, descomenta el siguiente test moviendo la línea `if defined(EXERCISM_RUN_ALL_TESTS)` más allá del siguiente test.

Mira el ejemplo de abajo del ejercicio Bob (archivo `bob_test.cpp`, línea 15):

```diff
-#if defined(EXERCISM_RUN_ALL_TESTS)
TEST_CASE("shouting")
{
    REQUIRE("Whoa, chill out!" == bob::hey("WATCH OUT!"));
}
+#if defined(EXERCISM_RUN_ALL_TESTS)
```

Mover esta línea más allá del siguiente test puede provocar errores de compilación, ya que pueden aparecer construcciones nuevas que aún no has declarado ni definido.
Una vez más, corrige los errores de compilación de forma mínima para conseguir un test que falle; después, cambia el código de forma mínima para que el test pase, refactoriza tu implementación para mejorar la legibilidad y la expresividad, y luego pasa al siguiente test.

Intenta usar las utilidades estándar de C++17 en lugar de escribir tus propios algoritmos o utilidades de bajo nivel a mano.
