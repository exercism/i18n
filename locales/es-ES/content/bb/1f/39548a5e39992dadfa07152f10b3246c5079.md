# Introducción

Los `Complex numbers` no son complicados.
Solo necesitan un nombre menos alarmante.

Son tan útiles, sobre todo en ingeniería y ciencia, que R incluye los números complejos como tipos atómicos estándar junto con integer, double, logical, character y raw.

## Conceptos básicos

Un número `complex` en R es un único valor.
Sin embargo, en la práctica se puede pensar en él como un par de números.
Se denominan la parte «real» y la parte «imaginaria», por desafortunadas razones históricas.
De nuevo, lo mejor es fijarse en la sencillez que hay debajo y no en los nombres extraños.

Para crear números complejos a partir de dos números reales, basta con añadir el sufijo `i` a la parte imaginaria.

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

Para crear un número complejo a partir de variables reales, la sintaxis anterior no funciona.
Escribir `r + imi` confunde al analizador sintáctico, que cree que `imi` es el nombre de una variable (inexistente).

Puedes multiplicar la parte imaginaria por `1i` o usar la función [`complex()`][ref-complex]:

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

Quizá te preguntes por qué `i` y no `j`.

La mayoría de los ingenieros prefiere `j`.
La mayoría de los científicos y matemáticos prefiere la notación matemática `i` para _imaginario_, pero esa notación entra en conflicto con el uso de `i` para referirse a la _corriente_ en ingeniería eléctrica.

R eligió `i`, Python eligió `j` y Julia evitó la polémica eligiendo `im`.
Ten cuidado cuando cambies entre lenguajes de programación [STEM][wiki-STEM].

Para acceder a cada parte de un número complejo por separado:

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

Cualquiera de las dos partes puede ser cero, y los matemáticos entonces pueden hablar de un número «totalmente real» o «totalmente imaginario».
Sin embargo, sigue siendo un número complejo en R.

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

Puede que hayas oído que «`i` (o `j`) es la raíz cuadrada de -1».

Por ahora, todo esto significa que la parte imaginaria, _por definición_, cumple la siguiente igualdad:

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

Es una idea sencilla, pero conduce a consecuencias interesantes.

## Aritmética

La mayoría de los operadores que se usan con números decimales y enteros también funcionan con números complejos:

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

## Funciones

La mayoría de las funciones matemáticas funcionan con entradas complejas.

Hay varias funciones, además de `Re()` e `Im()`, especialmente relevantes para los números complejos.

- `Conj()` simplemente cambia el signo de la parte imaginaria de un número complejo (_de + a - o viceversa_).
  - Por cómo funciona la multiplicación de números complejos, esto es más útil de lo que crees.
- Se garantiza que `abs(<complex number>)` devuelve un número real sin parte imaginaria (su «magnitud»), y `Mod(<complex number>)` es un sinónimo.
- `Arg(<complex number>)` devuelve el ángulo de fase en radianes.

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
