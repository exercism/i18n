# Introducción a la redirección

En el mundo de la interfaz de línea de comandos, los programas suelen interactuar con tres flujos de datos estándar:

1. **Entrada estándar** (`stdin`): donde un programa recibe su entrada (normalmente desde el teclado).
1. **Salida estándar** (`stdout`): donde un programa envía su salida normal (normalmente a la pantalla del terminal).
1. **Error estándar** (`stderr`): donde un programa envía los mensajes de error (normalmente a la pantalla del terminal).

Recuerda que ya los presentamos en el capítulo [Tuberías y listas de comandos][pipelines].

~~~~exercism/note
Las tuberías pueden considerarse una forma de redirección: la salida estándar de un programa se envía directamente a la entrada estándar de otro.
Ya hemos tratado las tuberías.

~~~~

La redirección del shell es un mecanismo potente que te permite cambiar el destino de estos flujos.
En lugar de que un programa lea del teclado o escriba en la pantalla, puedes redirigir la entrada desde un fichero o enviar la salida a un fichero.
Esto te da una flexibilidad y un control considerables sobre cómo interactúan los programas con los datos.

## Operadores de redirección principales

Estos son los operadores de redirección más comunes y lo que hacen:

### `>` (redirección de salida)

* Propósito: redirigir la salida estándar (`stdout`) de un comando a un fichero.
* Comportamiento:
  * Si el fichero no existe, se crea.
  * Si el fichero existe, su contenido se sobrescribe.
* Ejemplo:

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
La redirección se realiza **antes** de que se ejecute el comando.
Esto significa que no puedes redirigir al mismo fichero del que necesitas leer.

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

En el segundo comando del ejemplo anterior,

1. Bash primero trunca el fichero indicado en la redirección.
   Esto destruye el contenido anterior y deja un fichero vacío.
2. Luego bash lee el fichero recién vaciado.
3. Y después bash escribe el contenido (es decir, nada) de vuelta al fichero.
~~~~

### `>>` (redirección de salida para añadir)

* Propósito: añadir la salida estándar (`stdout`) de un comando al final de un fichero.
* Comportamiento:
  * Si el fichero no existe, se crea.
  * Si el fichero existe, la salida se añade al final del fichero.
* Ejemplo:

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<` (redirección de entrada)

* Propósito: redirigir la entrada estándar (`stdin`) de un comando desde un fichero.
* Comportamiento: el comando lee su entrada del fichero indicado en lugar del teclado.
* Ejemplo:

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>` (redirección de errores):

* Propósito: redirigir el error estándar (`stderr`) de un comando a un fichero.
* Comportamiento: los mensajes de error se envían al fichero indicado en lugar del terminal.
* Ejemplo:
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

Puedes _añadir_ el error estándar al final de un fichero con `2>>`.

### Redirecciones adicionales

También hay redirecciones que pueden combinar tanto `stdin` como `stderr`.
Consulta el [manual][manual] para más detalles.

## `/dev/null`

`/dev/null` es un fichero especial que

* está vacío cuando lees de él, y
* descarta todos los datos que se le escriben.

A veces se le llama «el bitbucket».
Es útil para suprimir la salida o los errores.

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## Combinar redirecciones

Se pueden indicar varias redirecciones a la vez.

```bash
some_command < input.txt > output.txt 2> error.txt
```

Una redirección se puede copiar.

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

Cuando veas `2>&1`, léelo como «redirige stderr a _donde sea que stdout esté apuntando **en ese momento**_».
Bash procesa las instrucciones de redirección estrictamente de izquierda a derecha, lo que significa que puedes hacer:

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## Descriptores de fichero

En el contexto de la programación del shell y de sistemas operativos como Linux/Unix, un descriptor de fichero (FD) es un número entero no negativo que sirve como identificador o referencia de un fichero abierto o de un recurso de E/S (entrada/salida).
Piénsalo como una etiqueta o un número de referencia que el sistema operativo usa para llevar la cuenta de los ficheros abiertos y los flujos de datos.

Los números que ves a la izquierda de las redirecciones son descriptores de fichero.

A los flujos de E/S estándar se les asignan los 3 primeros descriptores de fichero:

* la entrada estándar es el FD 0
* la salida estándar es el FD 1
* el error estándar es el FD 2

Se pueden establecer o crear nuevos descriptores de fichero con el comando `exec` y los operadores de redirección.

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

Esta técnica parece bastante enrevesada, pero puede ser muy útil en situaciones en las que tu script lo ejecuta otro paquete de software y la salida estándar la captura automáticamente ese software.
El comando `bats`, que se usa para ejecutar las pruebas unitarias de este track, funciona así: `bats` captura el stdout y el stderr de una prueba, pero los mensajes de depuración enviados al FD 3 se muestran en el terminal.
~~~~

## En resumen

¿Por qué es útil la redirección?

* Guardar la salida: almacenar los resultados de un comando para revisarlos o procesarlos después.
* Registro: capturar los mensajes de error para la depuración.
* Automatización: encadenar comandos, usando la salida de uno como la entrada de otro.
* Filtrado: descartar la salida que no quieres.
* Procesamiento por lotes: procesar datos desde ficheros en lugar de escribirlos a mano.
* Scripts: las redirecciones son esenciales para escribir scripts de shell robustos.

Las redirecciones del shell te dan un control muy preciso sobre cómo interactúan los programas con los datos, lo que te permite crear flujos de trabajo complejos y gestionar la información de forma eficaz.
