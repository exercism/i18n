# Pruebas

Una forma de resolver los ejercicios de Exercism es entrar en el sitio web y usar el editor del navegador, donde puedes editar y probar tu solución.

Como alternativa, puedes descargar los ejercicios en tu ordenador y usar tu propio editor, junto con un conjunto de herramientas, para crear, probar y, por último, enviar tu solución.

Esto implica usar la interfaz de línea de comandos de Exercism, o CLI, una aplicación que se ejecuta dentro de un terminal o una ventana de línea de comandos. Las instrucciones de instalación se encuentran aquí: [Documentación de la CLI de Exercism](https://exercism.org/docs/using/solving-exercises/working-locally).

## Enfoque de las pruebas
Exercism da por supuesto que tienes cierta experiencia con el desarrollo guiado por pruebas. Cada ejercicio consta de un _`stub file`_, un _`test file`_ que contiene una serie de pruebas ya escritas y un _`test script`_ que se usa para ejecutar las pruebas.

Resolver un ejercicio requiere desarrollar el _`stub file`_ de forma incremental hasta que contenga código que acabe pasando todas las pruebas.

En la práctica, esto significa que tanto el _`stub file`_ como el _`test file`_ se editarán continuamente. Ten en cuenta que el _`test file`_ se edita no para modificar el código de pruebas, sino para comentar las pruebas que fallan.

Al principio, estarán comentadas todas las pruebas menos una; después, a medida que el _`stub file`_ avance hacia una solución funcional, se irán descomentando más pruebas hasta que todas se ejecuten correctamente.

## Infraestructura de pruebas
No es necesario instalar ningún software adicional, ya que los componentes del framework de pruebas se incluyen en la descarga del ejercicio.

El framework de pruebas consta de tres ficheros Rexx que, a la hora de probar, se combinan con la solución del ejercicio para formar la unidad de código de pruebas, que después ejecuta el _`test script`_, y los resultados de las pruebas se imprimen en el terminal.

No edites ni borres el _`test script`_ ni ningún otro fichero del framework de pruebas. Si algún gremlin provoca que esto ocurra, vuelve a descargar el ejercicio con la CLI de Exercism, procurando guardar cualquier código de solución.

## Ejecutar las pruebas
La resolución de un ejercicio se desarrolla así:

1. Abre un terminal
2. Descarga el ejercicio seleccionado
3. Entra en el directorio del ejercicio
4. Carga el fichero stub y el fichero de pruebas en tu editor
5. De forma iterativa,

    1. Ejecuta el script de pruebas
    2. Escribe código en tu fichero stub (convirtiéndolo poco a poco en un fichero de solución) y comenta o descomenta pruebas en tu fichero de pruebas

6. Cuando pasen todas las pruebas, envía la solución a Exercism
7. Cierra el terminal
8. Celebra tu éxito

Un ejemplo concreto en un terminal Linux con el ejercicio `acronym` (supongamos que el espacio de trabajo de Exercism es: `/home/exercism`)

Descarga el ejercicio:

`exercism download --track=rexx --exercise=acronym`

Entra en el directorio del ejercicio:

`cd /home/exercism/rexx/acronym`

Desde otra ventana, quizá una interfaz gráfica, carga `acronym.rexx` y `acronym-check.rexx`, el fichero stub y el fichero de pruebas respectivamente, en tu editor.

Ejecuta el script de pruebas: `./test-acronym`

y todas las pruebas deberían fallar:

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Comenta todas las pruebas menos la primera en el fichero `acronym-check.rexx` y vuelve a ejecutar el script de pruebas; el resultado debería ser el siguiente:

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

Retoca `acronym.rexx` hasta que contenga código que funcione, y la salida de ejecutar el script de pruebas debería acabar siendo:

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

Continúa descomentando las demás pruebas, vuelve a ejecutar el script de pruebas y, al final, la salida debería ser:

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Ya puedes enviar la solución de tu ejercicio:

`exercism submit acronym.rexx`

y ganar otro punto de reputación. Cierra el terminal cuando termines.

El proceso para un usuario de MacOS sería bastante similar, ya que es un sistema operativo derivado de UNIX.

El proceso para los usuarios de Windows es, a grandes rasgos, similar, pero hay algunas diferencias menores:

- La ventana del _Command Prompt_ es el terminal
- Las barras invertidas sustituyen a las barras normales en las rutas, así que el directorio de trabajo podría ser:

  `cd C:\Users\MyName\exercism\rexx\acronym`

- La ejecución del script de pruebas se hace así:

  `test-acronym`  o  `test-acronym.bat`

La salida de las pruebas será idéntica.
