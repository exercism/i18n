# Introducción

En Julia se usan principalmente tres tipos de condicionales:

- Expresiones `if`
- El operador ternario
- La evaluación de cortocircuito

## Expresiones `if`

Las expresiones `if` en Julia son similares a las que se ven en otros lenguajes:

```julia-repl
julia> function say_if_positive(n)
           if n > 0
               println("n is positive!")
           else
               println("n is not positive!")
           end
       end
say_if_positive (generic function with 1 method)

julia> say_if_positive(10)
n is positive!

julia> say_if_positive(-10)
n is not positive!
```

Si la expresión booleana que sigue al `if` se evalúa como `true`, se ejecuta el primer bloque de código y se omite el segundo.
Si la expresión booleana que sigue al `if` se evalúa como `false`, se omite el primer bloque de código y se ejecuta el segundo.
El programa continúa ejecutándose en la primera línea de código que hay después de la palabra clave `end`.

~~~~exercism/note
En Julia, la palabra clave `end` marca el final de todas las expresiones de bloque.
Esta sintaxis no es específica de las expresiones `if` ni de las definiciones de función.
~~~~

En los casos en que el segundo bloque de código sea simplemente otra expresión `if`, `elseif` nos permite evitar anidar expresiones `if` dentro del bloque:

```julia-repl
julia> function dessert(fruit)
           if fruit == "apple"
               return "Apple Crumble"
           elseif fruit == "lemon"
               return "Lemon Meringue Pie"
           else
               return "Fruit Salad"
           end
       end
dessert (generic function with 1 method)

julia> dessert("apple")
"Apple Crumble"

julia> dessert("lemon")
"Lemon Meringue Pie"

julia> dessert("peach")
"Fruit Salad"
```

Si una expresión `if` solo necesita ejecutar código para uno de los casos, no hace falta escribir la rama `else`.

## Operador ternario

Las instrucciones `if-else` sencillas también se pueden escribir con el operador ternario `a ? b : c`.
Si `a` es verdadero, se evaluará `b`.
En caso contrario, se evalúa `c`.

Por ejemplo, la siguiente función

```julia-repl
julia> function diagnose(heartrate)
           if heartrate > 100
               println("Elevated heart rate.")
           else
               println("Nominal heart rate or dead.")
           end
       end
diagnose (generic function with 1 method)
```

también se puede escribir así

```julia-repl
julia> diagnose(heartrate) = heartrate > 100 ? println("Elevated heart rate.") : println("Nominal heart rate or dead.")
diagnose (generic function with 1 method)
```

Esto es especialmente útil si quieres asignar un valor distinto a una variable en función de una condición.
`x = a ? b : c` asignará `b` a `x` si `a` es `true` y, en caso contrario, asignará `c` a `x`.
Por ejemplo:

```julia-repl
julia> function patient_status(heartrate)
           status = heartrate > 0 ? "alive" : "dead"

           println("The patient is ", status)
       end

julia> patient_status(100)
The patient is alive

julia> patient_status(0)
The patient is dead
```

## Evaluación de cortocircuito

Si se encadenan varias expresiones booleanas con los operadores `&&` y `||`, Julia solo evaluará la menor cantidad de expresiones que sea necesaria para determinar el valor de toda la cadena.

Por ejemplo, considera la cadena de expresiones `n > 0 && k > 10`.
Si `n` es igual a `5`, la primera parte de la cadena, `n > 0`, es `true` y es necesario evaluar la segunda expresión, `k > 10`, para determinar si toda la expresión es `true`.
Sin embargo, si `n` es igual a `-5`, sabemos que la cadena en su conjunto **no puede** ser `true`, porque su primera expresión es `false`.

Si consideramos `n > 0 || k > 10` en su lugar, ocurre lo contrario.
Si `n` es igual a `5`, la primera parte de la cadena, `n > 0`, es `true` y sabemos que toda la cadena será `true` independientemente de la segunda expresión.
Sin embargo, si `n` es igual a `-5`, es necesario evaluar la segunda expresión.

Este comportamiento se puede usar para escribir instrucciones `if` muy cortas:

```julia
if a
    b
end
```

equivale a

```julia
a && b
```

La última expresión de una cadena de `&&` y `||` no tiene por qué ser una expresión booleana.
A menudo verás que esta funcionalidad se usa para generar errores o devoluciones tempranas.
Por ejemplo, usando la función `dessert(fruit)` de antes:

```julia-repl
julia> function whats_for_dessert(fruit, allergic_to)
           fruit == allergic_to && return "I can't eat that, guess I'll not have dessert tonight!"

           return dessert(fruit)
       end
whats_for_dinner (generic function with 1 method)

julia> whats_for_dinner("apple", "peach")
"Apple Crumble"

julia> whats_for_dinner("apple", "apple")
"I can't eat that, guess I'll not have dessert tonight!"
```
