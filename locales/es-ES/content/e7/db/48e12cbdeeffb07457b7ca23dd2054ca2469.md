# Introducción

En C++, las declaraciones suelen estar separadas de las definiciones.
Las declaraciones se agrupan en los llamados ficheros de cabecera, y las implementaciones correspondientes se colocan en ficheros fuente.
Puedes pensar en los ficheros de cabecera como en una API.
El fichero de cabecera te dirá _qué_ tiene que ofrecer un código base sin entrar en los detalles de _cómo_.

## Fichero de cabecera y fichero fuente

La extensión de fichero más habitual para los ficheros de cabecera es `.h`.
Algunos proyectos usan `.hpp` o prescinden por completo de la extensión.

Las definiciones se encuentran en un fichero `.cpp` aparte.
Para volver a unir las partes, el fichero fuente empieza _incluyendo_ el fichero de cabecera correspondiente.

Si quieres escribir una biblioteca llamada «quick_math» que ofrece una función «super_root» que quieres usar a menudo, los ficheros tendrían este aspecto:

```cpp
// A file named quick_math.h
#pragma once
namespace quick_math {
    double super_root(double x, int n);
}
```

```cpp
// A file named quick_math.cpp
#include "quick_math.h"
#include <cmath>
double quick_math::super_root(double x, int n) {
    while(n) { x = std::sqrt(x), --n;}
    return x;
}
```

Si necesitas incluir una cabecera que solo requiere la implementación, la línea `#include` correspondiente solo hace falta en el fichero fuente.
Todo lo que se incluye en la cabecera también está disponible en el fichero `.cpp`, como la biblioteca `string` del ejemplo siguiente.
**Atención**: el `;` hace falta después de la declaración en el fichero de cabecera, pero no después de la definición en el fichero fuente.

~~~~exercism/note

Tienes que consultar el fichero `*_test.cpp` para ver los nombres y los espacios de nombres de las funciones que se esperan, y así poder resolver el ejercicio.

## Clases y ficheros de cabecera

Las clases pueden volverse muy complejas, y su relación con la división entre cabecera y fuente puede resultar confusa.
Una posible organización es mantener todos los detalles de implementación en el fichero fuente y todas las declaraciones y variables miembro en la cabecera:

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0);
            void give_water();
            std::string get_name();
            int get_size();
            void start_next_day();
    };
}
#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"
robots::Flower::Flower(std::string name, int size) {this->name = "Robotica " + name; this->size = size;}
void robots::Flower::start_next_day() {if (!needs_water) ++size; needs_water = true;}
std::string robots::Flower::get_name() {return name;}
int robots::Flower::get_size() {return size;}
```

Cuando la cabecera se usa como vista general de la API, es ahí donde una persona buscaría información como los valores por defecto.
El valor por defecto del parámetro `size` del constructor se gestiona, por tanto, en la cabecera y no en la implementación.
Las definiciones del fichero fuente llevan como prefijo el espacio de nombres `robots` y el tipo de clase `Flower`.

Otra opción de organización es una biblioteca _solo cabecera_, que no tiene ningún fichero `.cpp`:

```cpp
// A file named robot_flower.h
#pragma once
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0) {this->name = "Robotica " + name; this->size = size;}
            void give_water() {needs_water = false;}
            std::string get_name() {return name;}
            int get_size() {return size;}
            void start_next_day() {if (!needs_water) ++size; needs_water = true;}
    };
}
```

Los proyectos pueden usar combinaciones de estas organizaciones, y hay mucho debate sobre cuál puede encajar mejor en cada caso de uso.

## Guardas de inclusión

Es posible que te hayas fijado en la línea `#pragma once` del fichero de cabecera de ejemplo de arriba.
Esto se llama guarda de inclusión y garantiza que el contenido del fichero se incluya solo una vez durante la compilación, para evitar errores.
Existe otra variante más compleja de guarda de inclusión que empieza por `#ifndef` y termina en `#endif`.
Cumple la misma función y su uso se muestra en el ejemplo de la clase `Flower` de arriba.
