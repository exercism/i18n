# Anexo a las instrucciones

## Concurrencia frente a paralelismo

Go admite la concurrencia mediante «[goroutines](https://golangbot.com/goroutines/)», que se inician con la palabra clave `go`.
Es una forma sencilla, ligera y elegante de proporcionar soporte para la concurrencia, y una de las mayores fortalezas del lenguaje.

Es posible que hayas notado que, aunque este ejercicio se llama _frecuencia de letras en paralelo_, el término «paralelo» no se usa muy a menudo en Go.
Los Gophers prefieren usar el término **concurrente** para describir la gestión de varias goroutines independientes (los «procesos» o «hilos» en el contexto de otros lenguajes).
Aunque estos términos suelen usarse indistintamente, a los Gophers les gusta ser técnicamente precisos y usan «concurrente» cuando hablan de las ejecuciones aparentemente simultáneas de las goroutines.

Aunque podemos planificar que nuestros programas se ejecuten en paralelo y, por momentos, puede parecer que lo hacen, sin un conocimiento estricto del contexto de ejecución de nuestro código lo único que podemos garantizar es que los procesos se ejecutarán de forma concurrente.
En otras palabras, puede que se estén ejecutando de forma secuencial más rápido de lo que somos capaces de distinguir, pero no estrictamente de forma simultánea.

Para saber más, echa un vistazo a la entrada de The Go Blog: [Concurrency is not parallelism](https://blog.golang.org/concurrency-is-not-parallelism).

## Recursos sobre concurrencia

Si es la primera vez que trabajas con las funcionalidades de concurrencia de Go, aquí tienes algunos recursos para empezar.
Te recomendamos que les eches un vistazo antes de empezar este ejercicio:

- [Concurrency in the Golang Book](https://www.golang-book.com/books/intro/10)
- [A Tour of Go's concurrency section](https://tour.golang.org/concurrency/1)
- [DigitalOcean Golang Tutorial: How To Run Multiple Functions Concurrently in Go](https://www.digitalocean.com/community/tutorials/how-to-run-multiple-functions-concurrently-in-go)
- [Synchronizing Go Routines with Channels and WaitGroups](https://dev.to/sophiedebenedetto/synchronizing-go-routines-with-channels-and-waitgroups-3ke2)
- [Buffered Channels and Worker Pools](https://golangbot.com/buffered-channels-worker-pools/)

Si quieres profundizar de verdad, puedes probar el libro [Concurrency in Go](http://shop.oreilly.com/product/0636920046189.do) de [@kat-co](https://github.com/kat-co).

## Pruebas

En este ejercicio, las pruebas unitarias no pueden determinar si has escrito una buena solución concurrente.
En su lugar, lo mejor es resolver este ejercicio [en local][cli] y ejecutar los benchmarks con `go test -bench .`.
Si la solución es buena, deberías ver que la versión concurrente muestra un número menor de nanosegundos por operación (`ns/op`) que la versión secuencial.

[cli]: https://exercism.org/docs/using/solving-exercises/working-locally
