# Introducción

## Igualdad

Los tipos simples (string y primitivos) normalmente se comparan por igualdad con `==` y `!=`.

Los tipos de referencia (instancias de clases) se comparan con el método `Equals()`, heredado de `Object`. Si tu objetivo con la prueba de igualdad es asegurarte de que dos objetos son exactamente la misma instancia, basta con confiar en la implementación de `Object`. Si no es así, tendrás que sobrescribir `object.Equals()`.

Si sabes que todas las instancias de tu clase se crean en un solo lugar, por ejemplo, los personajes de un juego o una simulación, la igualdad de referencia es suficiente. Sin embargo, es probable que se creen varias instancias de la misma entidad del mundo real (desde una base de datos, a partir de la entrada del usuario o mediante una petición web). En ese caso, hay que comprobar la igualdad de los valores que identifican de forma única a la entidad. Por lo tanto, hay que sobrescribir `Equals()` y comprobar la igualdad de los miembros de datos apropiados de tu clase.

Un método `Equals()` sobrescrito contendrá comprobaciones de igualdad sobre miembros de tipos simples mediante `==` y sobre tipos de referencia mediante llamadas recursivas a `Equals()`.

La clase `Object` proporciona los métodos adecuados para comparar dos objetos y detectar si son una misma instancia.

### `Object.GetHashCode()`

El método `Object.GetHashCode()` devuelve un código hash en forma de entero de 32 bits. El código hash lo usan las clases _diccionario_ y _conjunto_, como `Dictionary<T>` y `HashSet<T>`, para almacenar y recuperar objetos de forma eficiente.

La relación entre el código hash y la igualdad es que si dos objetos son iguales (`Equal()` devuelve true), entonces `GetHashCode()` debe devolver el mismo valor para ambos. Esto no se cumple en la dirección contraria. No es simétrico. El hecho de que dos objetos tengan el mismo código hash no significa que tengan que ser iguales. Imagina una función de búsqueda que primero va a un «cubo» basándose en el código hash y luego selecciona el elemento concreto mediante la prueba de igualdad.

La documentación de la API de la biblioteca HashCode explica cuál es la mejor forma de generar un código hash.

Los valores usados en la prueba de igualdad deben ser estables mientras se use la colección con hash. Si añades un objeto a la colección con un conjunto de valores y luego cambias esos valores, el código hash ya no apuntará al «cubo» correcto. En la práctica, esto significa que el objeto debería ser inmutable. Otros enfoques corren el riesgo de crear sorpresas desagradables para quienes mantienen el código.

## Conjuntos

Un conjunto es una colección de valores únicos. La implementación predeterminada de .NET para un conjunto es la clase `HashSet<T>`, que es una colección que solo contiene valores únicos.
