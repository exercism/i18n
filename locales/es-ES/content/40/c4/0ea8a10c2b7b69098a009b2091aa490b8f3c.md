# Introducción

Un [operador de comparación][comparisons] en Python (también llamado operador relacional de Python) examina los _valores_ de dos [operandos][operand] y devuelve un valor booleano `True` o `False` en función de si se cumple o no la condición `comparison`.

La tabla siguiente muestra los operadores de comparación más habituales en Python:

| Operador | Operación                  | Descripción                                                               |
| -------- | -------------------------- | ------------------------------------------------------------------------- |
| `>`      | «mayor que»                | `a > b` es `True` si el valor de `a` es **estrictamente** mayor que el de `b`        |
| `<`      | «menor que»                | `a < b` es `True` si el valor de `a` es **estrictamente** menor que el de `b`           |
| `==`     | «igual a»                  | `a == b` es `True` si `a` es **estrictamente** igual a `b` en valor           |
| `>=`     | «mayor o igual que»        | `a >= b` es `True` si `a > b` O `a == b` en valor                        |
| `<=`     | «menor o igual que»        | `a <= b` es `True` si `a < b` o `a == b` en valor                        |
| `!=`     | «distinto de»              | `a != b` es `True` si `a == b` es `False`                                 |
| `is`     | «identidad»                | `a is b` es `True` si **_y solo si_** `a` y `b` son el mismo _objeto_ |
| `is not` | «identidad negada»         | `a is not b` es `True` si  **_y solo si_** `a` y `b` **no** son el mismo _objeto_       |
| `in`     | «prueba de contención»     | `a in b` es `True` si `a` es miembro, subconjunto o elemento de `b`            |
| `not in` | «prueba de contención negada» | `a not in b` es `True` si `a` no es miembro, subconjunto ni elemento de `b`  |

Todos tienen la misma prioridad (que es mayor que la de las [operaciones booleanas][boolean operations], pero menor que la de las operaciones aritméticas o a nivel de bits).

## Comparación entre distintos tipos de datos

Los objetos de tipos distintos (excepto los tipos numéricos) nunca se consideran iguales al compararlos de forma predeterminada.
Las instancias no idénticas de una `class` tampoco se considerarán iguales al compararlas, a menos que la `class` defina métodos especiales que personalicen el comportamiento de comparación predeterminado de `object`.

Los tipos numéricos son (en su mayoría) una excepción a esta regla de coincidencia de tipos.
Un `integer` **puede** considerarse igual a un `float` (o un [`octal`][octal] igual a un [`hexadecimal`][hex]), siempre que los tipos se puedan convertir implícitamente para compararlos.

Para los demás tipos numéricos ([complex][complex numbers], [decimal][decimal numbers], [fractions][rational numbers]), los operadores de comparación se definen donde «tienen sentido» (donde la conversión implícita no cambia el resultado), pero lanzan un `TypeError` si los objetos subyacentes no se pueden convertir con exactitud para compararlos.

## Comparación de la identidad de objetos

Los operadores `is` y `is not` comprueban la [_identidad_][object identity] de un objeto, en contraposición a su _valor_.
La identidad de un objeto nunca cambia después de su creación y se puede obtener con la función [`id()`][id function].

`<apple> is <orange>` se evalúa como `True` si **_y solo si_** `id(<apple>)` == `id(<orange>)`.
`<apple> is not <orange>` da el resultado inverso.

## Comparaciones de pertenencia

Los operadores `in` y `not in` comprueban la _pertenencia_.
`<fish> in <soup>` se evalúa como `True` si `<fish>` es miembro de `<soup>` (si `<fish>` es un subconjunto de `<soup>` o está contenido en `<soup>`), y se evalúa como `False` en caso contrario.
`<fish> not in <soup>` devuelve la negación, o lo _contrario de_ `<fish> in <soup>`.

Para los tipos string y bytes, `<name> in <fullname>` es `True` **_si y solo si_** `<name>` es una subcadena de `<fullname>`.
