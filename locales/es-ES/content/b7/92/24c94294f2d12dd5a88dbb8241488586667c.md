# Apéndice de instrucciones

## Implementación

Para este ejercicio tendrás que usar el polimorfismo de parámetros de Odin (más conocido como genéricos). Si no has visto antes esta funcionalidad, aquí tienes un repaso rápido para empezar.

El polimorfismo de parámetros es una funcionalidad de los lenguajes de programación que permite a los programadores ser menos específicos (más genéricos, de ahí el nombre) sobre los tipos que usan en su código sin dejar de mantener la seguridad de tipos.
Obviamente, esto solo tiene sentido en lenguajes fuertemente tipados como Odin.

Empecemos con un ejemplo.
Supongamos que quieres incrementar todos los elementos de un array en un valor fijo, un problema bastante sencillo.

```odin
incr_array_int :: proc(a: []int, by: int) -> []int {

    new_array := make([]int, len(a))
    for i := 0; i < len(a); i+= 1 {
        new_array[i] = a[i] + by
    }
    return new_array
}
```

¿Y si ahora necesitas la misma funcionalidad para números de coma flotante?

```odin
incr_array_f64 :: proc(a: []f64, by: f64) -> []f64 {

    new_array := make([]f64, len(a))
    for i := 0; i < len(a); i+= 1 {
        new_array[i] = a[i] + by
    }
    return new_array
}
```

¿Y luego para enteros sin signo, números de coma flotante de 32 bits, y así sucesivamente?

En poco tiempo acabas con un montón de procedimientos que hacen exactamente lo mismo pero con tipos diferentes.
Si alguna vez necesitas actualizar la lógica, tendrás que asegurarte de hacerlo en todas las variantes, lo que puede convertirse en una gran carga de mantenimiento.
La otra molestia es que tienes que dar un nombre distinto a cada procedimiento, ya que Odin no admite la sobrecarga implícita de procedimientos (todavía podrías usar la sobrecarga explícita, pero esa es una historia para otro ejercicio).

Odin, al ser un lenguaje práctico, ofrece una solución con el polimorfismo de parámetros.
Siempre que el compilador pueda deducir el tipo de un parámetro en tiempo de compilación, puedes darle un nombre genérico, como `T`.
Reescribamos el procedimiento anterior:

```odin
incr_array :: proc(a: []$T, by: T) -> []T {

    new_array := make([]T, len(a))
    for i := 0; i < len(a); i+= 1 {
        new_array[i] = a[i] + by
    }
    return new_array
}
```

Fíjate en que hemos sustituido todas las anotaciones de tipo (`int` o `f64`) por `T` y en que la primera aparición de `T` va precedida de un signo de dólar (`$T`).
El tipo `$T` le dice al compilador de Odin que el nombre `T` es un nombre genérico para el tipo, que se sustituirá por el nombre real durante la compilación.
Y, como el compilador ya conoce el tipo genérico `T`, las apariciones siguientes de ese mismo tipo solo tienen que ir marcadas con el nombre de tipo elegido (`T`).

Ahora puedes escribir código como:

```Odin
a_int := incr_array([]int{1, 2, 3}, 10)
a_f64 := incr_array([]f64{1.0, 2.0, 3.0}, 10.0)
```

En la primera instrucción, el compilador de Odin identificará el tipo del primer parámetro (`[]int`) con el tipo del parámetro genérico (`[]$T`), deducirá que `T = int` y compilará una versión con todas las apariciones siguientes de `T` sustituidas por `int` (equivalente a la versión especializada `incr_array_int()` de arriba).
Si omitieras el signo de dólar en la definición del primer parámetro, el compilador habría buscado en el paquete actual y en la lista de importaciones un tipo llamado `T` y lo más probable es que devolviera un error de compilación `Error: Undeclared name: T`.

La segunda instrucción funciona exactamente igual que la primera, pero con el compilador identificando `T` como `f64`.

Se suele dar a los tipos genéricos nombres de una sola letra (`T` y `E` son los más habituales).

Ahora ya deberías saber lo suficiente sobre el polimorfismo de parámetros, también conocido como tipos genéricos, para enfrentarte al ejercicio List Operations.
