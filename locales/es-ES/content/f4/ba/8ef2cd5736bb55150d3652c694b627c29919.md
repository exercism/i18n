# Clases abstractas

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## El $ forma parte del nombre

Toda clase abstracta se nombra con un `$` delante, y solo las clases
abstractas lo llevan. Así que un tipo que empieza por `$` es uno del que
no puedes crear un objeto, y eso se ve allá donde aparezca el nombre.

## Qué puede ir dentro de una

Firmas de rutinas e iteradores, que terminan en punto y coma. Ni cuerpos,
ni atributos, ni `create`. Una clase abstracta describe lo que se puede
*pedir* a algo, nunca lo que contiene.

## Conformidad

```sather
class TRAPEZE < $ACT is
```

La clase debe definir todas las rutinas enumeradas, con tipos de argumento
y tipo devuelto coincidentes. Se comprueba al compilar.

Una clase puede conformar con varias:

```sather
class TRAPEZE < $ACT, $RISKY is
```

y las clases abstractas pueden extenderse entre sí:

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## Dónde ocurre el despacho

Una variable de un tipo abstracto contiene una referencia a algún objeto
que conforma con él. Llamar a una rutina sobre ella elige la versión que
pertenece a la clase real del objeto, en tiempo de ejecución.

Ese es el único lugar donde Sather decide algo en tiempo de ejecución. Una
llamada sobre una variable de un tipo concreto se resuelve al compilar.

## typecase

A veces el tipo concreto sí que importa. `typecase` pregunta:

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

Dentro de una rama, la variable tiene el tipo más específico. Recurre a él
con poca frecuencia: un `typecase` sobre todos los tipos de acto suele ser
una rutina que debería haber estado en la clase abstracta desde el
principio.

## $OB

`$OB` es la clase abstracta con la que conforma todo objeto. Es útil en
contadas ocasiones y, las más de las veces, es señal de que se ha perdido
un tipo por el camino.

## ¿Por qué no herencia?

Sather separa dos cosas que la mayoría de los lenguajes une. `<` dice solo
lo que una clase puede *hacer*. Obtener una implementación de otro sitio es
`include`, que es el segundo ejercicio que viene, y es una decisión aparte.
