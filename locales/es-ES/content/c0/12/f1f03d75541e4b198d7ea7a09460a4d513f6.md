# Acerca de

`<dlist>` (en [`dlists`][dlists]) construye una lista doblemente enlazada nueva. Las operaciones viven en [`deques`][deques] y se despachan según el [protocolo de deque][deque-protocol], de modo que otros contenedores, principalmente `<dlist>`, pueden implementarlas.

| palabra        | efecto                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`: deque nuevo y vacío |
| `push-front`    | `( elt deque -- )`: añade al frente |
| `push-back`     | `( elt deque -- )`: añade al final  |
| `pop-front`     | `( deque -- elt )`: elimina del frente |
| `pop-back`      | `( deque -- elt )`: elimina del final  |
| `peek-front`    | `( deque -- elt )`: lee el frente sin eliminarlo |
| `peek-back`     | `( deque -- elt )`: lee el final sin eliminarlo  |
| `deque-empty?`  | `( deque -- ? )`: ¿está vacío el deque? |
| `dlist-length`  | `( dlist -- n )`: número de elementos |

Todas las operaciones push/pop mutan el deque in situ: pasar un deque a una rutina y volver a leerlo después es el patrón habitual.

## Pila frente a cola

Dos patrones de despacho convencionales:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

Un vector con `push` y `pop` (de `mutation`) es la elección correcta cuando el orden LIFO es todo lo que necesitas: `<dlist>` arrastra la sobrecarga de una lista enlazada. Recurre a `<dlist>` cuando necesites O(1) en *ambos* extremos, casi siempre para una cola FIFO.

## Patrón de búsqueda en anchura

La búsqueda en anchura (BFS) es el uso canónico de una cola FIFO:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

El deque transporta la frontera de la búsqueda; el hash-set se encarga de la deduplicación. Cambia `pop-front` por `pop-back` y la misma forma se convierte en búsqueda en profundidad.

## `MEMO:`, almacenamiento automático en caché

A veces, la consulta por nodo que realiza la búsqueda en anchura es costosa. Factor proporciona [`MEMO:`][memo-decl], un sustituto de `:` que almacena en caché automáticamente el resultado de la palabra, indexado por sus entradas:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

Una palabra `MEMO:` ejecuta su cuerpo la primera vez que se ve cada entrada y, a partir de ahí, devuelve el resultado almacenado en caché. La caché vive mientras dure la imagen; no hay expulsión por tiempo ni por tamaño. Úsala con funciones puras cuyas entradas provengan de un conjunto finito y manejable.
