# Introducción

El ensamblador escrito a mano está lleno de repeticiones.
La misma secuencia corta de instrucciones aparece una y otra vez, con pocas variaciones, y hay pocas abstracciones para reducir el código repetitivo.
Además, programar en ensamblador exige gestionar valores sin una semántica evidente.
No hay parámetros con nombre y el programador debe gestionar a mano la mayoría de los detalles de la maquinaria subyacente.

NASM, el ensamblador que usa el track, ofrece algunas herramientas que pueden ayudar al programador con ambos problemas.
Estas herramientas se ejecutan en _tiempo de ensamblado_, antes de que ninguna instrucción llegue al procesador.
Guían al ensamblador sobre cómo reescribir el texto fuente antes incluso de que se traduzca a código máquina.

Las más importantes de estas herramientas son las **macros**, que pueden concebirse como una receta para el ensamblador.
Se expanden en el lugar donde se usan, como si el código se hubiera escrito allí a mano.

Las macros pueden recibir una serie de tokens literales como parámetros, lo que las hace reutilizables en distintos contextos.
Sin embargo, no son funciones: no hay `call`, ni `ret`, ni transferencia de control a otro punto del código.

## Macros de una sola línea

La definición más sencilla da un nombre a un valor o a una expresión corta con `%define`:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Toda aparición posterior de `WIDTH` se sustituye por `8` antes del ensamblado.
La sustitución es textual, así que el nombre se reemplaza allí donde aparezca, ya sea en un operando o dentro de otra definición.

~~~~exercism/note
Para las _constantes_ numéricas, es preferible usar `equ` en lugar de `%define`.

Una macro de una sola línea declarada con `%define` solo se expande cuando se usa, y puede reasignarse o dejarse sin definir.
Una constante `equ`, en cambio, se evalúa en el punto de definición y nunca se modifica.
~~~~

Un `%define` también puede recibir parámetros _con nombre_, comportándose como una pequeña función en línea:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Encierra entre paréntesis tanto el cuerpo completo como cada parámetro.
Con `%define square(x) x*x`, la llamada `square(1+1)` se expande a `1+1*1+1`, que es `3`.
Escrito como `%define square(x) ((x)*(x))`, la misma llamada se expande a `((1+1)*(1+1))`, que es `4`.
~~~~

Los nombres definidos con `%define` distinguen entre mayúsculas y minúsculas.
La variante `%idefine` hace que el nombre no distinga entre mayúsculas y minúsculas, si se desea.

Las macros de una sola línea son útiles para dar significado a diversas partes del código.
Si se usan con cuidado, mejoran la legibilidad y reducen la posibilidad de errores tipográficos.
Por ejemplo, un registro que tiene un propósito concreto dentro de una función puede definirse por su propósito:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Macros de varias líneas

Toda una secuencia de código, con cualquier número de líneas, se captura con `%macro` y se cierra con `%endmacro`.
Un número después del nombre indica cuántos argumentos recibe la macro, que pueden ser cero.
Cuando se pasan argumentos, se separan por una coma (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Los argumentos de las macros de varias líneas no tienen nombre.
Se referencian como `%1`, `%2`, etc., en el orden en que se pasan:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Ten en cuenta que los argumentos deben ser sintaxis válida para las operaciones que se realizan en el cuerpo de la macro.
Aquí `mult_two eax, ecx` y `mult_two r8, r9` se ensamblan ambos, pero `mult_two eax, cl` no lo haría, ya que `imul eax, cl` no está definido.

### Etiquetas dentro de una macro

Una macro que define una etiqueta normal se rompe en el momento en que se usa dos veces, porque entonces la etiqueta también quedaría definida dos veces.
Para usar etiquetas dentro de una macro que puede llamarse más de una vez, es necesario anteponer `%%` a dicha etiqueta.
Esto indica al ensamblador que dé a esta etiqueta un nombre distinto y único en cada expansión:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Repetir en tiempo de ensamblado

Es posible repetir un bloque de código de una línea usando `times`.
Esto es especialmente útil al declarar valores repetidos en memoria:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Para repetir código de varias líneas, podemos usar `%rep`:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Ten en cuenta que el número de repeticiones se especifica justo después de `%rep` y que hay un `%endrep` para cerrar el bloque repetido.

Es habitual usar un contador en tiempo de ensamblado dentro de un bloque `%rep`, igual que un bucle en tiempo de ejecución usa un contador.
Aunque una constante entera en tiempo de ensamblado puede declararse con `equ`, para las _variables_ enteras en tiempo de ensamblado usamos `%assign`.
A diferencia de `%define`, `%assign` se evalúa inmediatamente a un número y puede reasignarse:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Después de que se ejecute el preprocesador, el bucle desaparece y quedan cuatro instrucciones `add`, con los valores inmediatos `0`, `1`, `2` y `3` integrados.
Esto es el desenrollado de bucles que hace el ensamblador: sin registro contador y sin salto, solo código lineal.

## Ensamblado condicional

El preprocesador dispone de varios condicionales.
Seleccionan entre varias rutas distintas y expanden su cuerpo en el lugar, pero solo cuando su condición se cumple.

`%if` ... `%elif` ... `%else` ... `%endif` seleccionan una rama a partir de una prueba numérica:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## Dividir en ficheros

A menudo las macros se guardan en un fichero propio y se incorporan a cada fuente que las necesita con `%include`:

```x86asm
%include "patterns.mac"
```

El fichero indicado se inserta literalmente en ese punto, antes del ensamblado, exactamente como si su contenido se hubiera escrito allí.
Esto mantiene las definiciones en un solo lugar y permite que varios ficheros fuente las compartan.

Si el fichero de macros puede ensamblarse por sí solo, debería tener la extensión de fichero `.asm`.
Ten en cuenta que las macros no tienen enlazado.
Aunque el fichero de macros se ensamble, sus macros solo son visibles para otro fichero que lo incluya con `%include`.

De lo contrario, un fichero destinado solo a `%include` puede tener cualquier extensión de fichero.
Usar `.asm` o `.mac` es una convención habitual.
