# Instrucciones

El trabajo en el proyecto del coche teledirigido continúa. El ancho de banda del sistema de telemetría escasea y se te ha pedido que implementes un protocolo de mensajes para comunicar los datos de telemetría.

Los datos se transmiten en un búfer (una matriz de bytes). Cuando se envían números enteros, el tamaño del búfer se reduce empleando el protocolo que se describe a continuación.

Cada valor debe representarse en el tipo entero más pequeño posible (los tipos `byte` y `sbyte` no se incluyen, ya que el ahorro sería insignificante):

| De                         | A                         | Tipo     |
| -------------------------- | ------------------------- | -------- |
| 4_294_967_296              | 9_223_372_036_854_775_807 | `long`   |
| 2_147_483_648              | 4_294_967_295             | `uint`   |
| 65_536                     | 2_147_483_647             | `int`    |
| 0                          | 65_535                    | `ushort` |
| -32_768                    | -1                        | `short`  |
| -2_147_483_648             | -32_769                   | `int`    |
| -9_223_372_036_854_775_808 | -2_147_483_649            | `long`   |

El valor debe convertirse al número de bytes adecuado para el tipo que se le asigne. El búfer completo consta de un byte que indica el número de bytes adicionales que hay en el búfer (_byte de prefijo_) seguido de los bytes que contienen el número entero (_bytes de carga útil_).

Algunos de los tipos usan el mismo número de bytes (por ejemplo, los tipos `uint` e `int`). Normalmente, tendrían el mismo _byte de prefijo_, pero eso haría que la decodificación fuera problemática. Para contrarrestarlo, el protocolo introduce un pequeño truco: en los tipos con signo, el valor de su _byte de prefijo_ es `256` menos el número de bytes adicionales que hay en el búfer.

En la comunicación solo se enviarán el byte de prefijo y el número de bytes siguientes indicado por el prefijo. De forma interna, tanto las rutinas de envío como las de recepción usan un búfer de 9 bytes (con ceros finales, según sea necesario).

## 1. Codifica un valor entero listo para enviar

Implementa el método estático `TelemetryBuffer.ToBuffer()` para codificar un búfer tomando el parámetro que se pasa al método.

```csharp
// Type: ushort, bytes: 2, signed: no, prefix byte: 2
TelemetryBuffer.ToBuffer(5)
// => {0x2, 0x5, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0 };

// Type: int, bytes: 4, signed: yes, prefix byte: 256 - 4
TelemetryBuffer.ToBuffer(Int32.MaxValue)
// => {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 };
```

## 2. Decodifica un búfer recibido

Implementa el método estático `TelemetryBuffer.FromBuffer()` para decodificar el búfer recibido y devolver el valor en forma de `long`.

```csharp
TelemetryBuffer.FromBuffer(new byte[] {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 })
// => 2147483647
```

Si el byte de prefijo tiene un valor inesperado, debe devolverse `0`.
