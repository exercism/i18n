# Instrucciones

Es la noche del estreno en el Grand Marquee y todo el personal trabaja a la vez.
El público entra en tropel por todas las puertas, varias taquillas venden del mismo rollo de entradas, el estreno está a punto de agotar las localidades y, arriba, en la cabina de proyección, los rollos no pueden dejar de girar.

Todo lo que comparte el personal vive en una dirección de memoria, y los tests llaman a tus funciones desde varios hilos a la vez.
Un valor que se lee, se modifica y se vuelve a escribir en pasos separados perderá actualizaciones con esa carga, así que cada función debe hacer su actualización de forma atómica.

Todos los valores compartidos de este ejercicio son enteros con signo de 64 bits.

Tienes cinco tareas.

~~~~exercism/note
Las actualizaciones de este ejercicio deben realizarse con instrucciones _atómicas_.
Los tests ejecutan tus funciones de forma concurrente y comprueban que no se pierda ninguna actualización, así que una lectura-modificación-escritura no atómica tiene muchas probabilidades de fallarlos.
~~~~

## 1. Cuenta las admisiones

Las puertas están abiertas y en cada una de ellas un acomodador está rasgando entradas.
Cada grupo que pasa se cuenta en un recuento de admisiones compartido y, con todas las puertas contando a la vez, el recuento de la sala debe cuadrar igualmente.

Implementa la función `admit_group`, que suma de forma atómica el tamaño de un grupo al recuento.

Esta función toma como argumentos, en este orden:

- `admissions`: dirección de memoria del recuento de admisiones compartido, un entero con signo de 64 bits.
- `group_size`: el número de personas del grupo, un entero con signo de 64 bits, siempre mayor que `0`.

```c
admissions = 120, group_size = 4
// admissions is now 124
```

Los tests admiten grupos por varias puertas a la vez.
El recuento final debe ser igual a la suma de todos los grupos que han pasado.

Esta función no devuelve ningún valor.
El recuento debe actualizarse in situ.

## 2. Cambia el rollo

El proyector monta exactamente un rollo.
Montar el siguiente rollo y sacar el actual debe ser un solo movimiento: con dos proyeccionistas en la máquina, dos pasos separados podrían dar el mismo rollo a los dos, o tirar uno al suelo.

Implementa la función `change_reel`, que monta de forma atómica el siguiente rollo y devuelve el que estaba montado.

Esta función toma como argumentos, en este orden:

- `mounted`: dirección de memoria del identificador del rollo montado, un entero con signo de 64 bits.
- `next_reel`: el identificador del rollo que hay que montar, un entero con signo de 64 bits.

```c
mounted = 7, next_reel = 9
// => 7, and mounted is now 9
```

Esta función devuelve el identificador del rollo que estaba montado antes, como un entero con signo de 64 bits.
Los tests hacen que varios hilos intercambien rollos por el mismo soporte a la vez y comprueban que cada rollo que entra vuelve a salir exactamente una vez.

## 3. Vende una entrada

Cada taquilla vende a partir de un recuento compartido de entradas vendidas.
Sumar a un recuento, como hacen las puertas, no basta aquí: cada venta también debe conocer el número que le ha tocado.
Ninguna venta puede compartir número con otra y, tras el aluvión, el recuento debe ser exactamente igual al número de entradas vendidas.

Implementa la función `sell_ticket`, que suma de forma atómica uno al recuento y devuelve el número de la entrada que se acaba de vender.
El número de entrada es el recuento _después_ de esta venta: cuando el recuento era `41`, esta venta es la entrada `42`.

Esta función toma como argumento:

- `tickets_sold`: dirección de memoria del recuento compartido de entradas vendidas, un entero con signo de 64 bits.

```c
tickets_sold = 0
// => 1, and tickets_sold is now 1

tickets_sold = 41
// => 42, and tickets_sold is now 42
```

Esta función devuelve el número de entrada como un entero con signo de 64 bits.
Los tests venden desde varias taquillas a la vez: cada número devuelto debe ser distinto y el recuento final debe ser igual al número de ventas.

## 4. Llena el estreno

El estreno tiene un número fijo de butacas y todas las taquillas están vendiendo para él.
Una venta solo puede realizarse mientras quede una butaca y la sesión nunca debe sobrevenderse, ni siquiera cuando todas las taquillas se lanzan a por la última butaca en el mismo instante.
Comprobar el recuento y luego sumarle uno en dos pasos separados deja una ventana de tiempo entre medias, así que la comprobación y la actualización deben tener éxito o fallar juntas.

Implementa la función `claim_seat`, que reserva de forma atómica la siguiente butaca cuando todavía queda alguna libre.
Cuando se reserva una butaca, la función devuelve el número de la butaca, que es el recuento de butacas ocupadas después de esta reserva.
Cuando la sesión está agotada, devuelve `0` y deja el recuento sin cambios.

Esta función toma como argumentos, en este orden:

- `seats_taken`: dirección de memoria del recuento de butacas ya ocupadas, un entero con signo de 64 bits, nunca superior a `capacity`.
- `capacity`: el número de butacas de la sesión, un entero con signo de 64 bits, siempre mayor que `0`.

```c
seats_taken = 0, capacity = 150
// => 1, and seats_taken is now 1

seats_taken = 82, capacity = 150
// => 83, and seats_taken is now 83

seats_taken = 149, capacity = 150
// => 150, and seats_taken is now 150

seats_taken = 150, capacity = 150
// => 0, and seats_taken stays 150
```

Esta función devuelve el número de butaca o `0` cuando la sesión está agotada, como un entero con signo de 64 bits.

## 5. Cuida la cabina

En la cabina de proyección solo cabe una persona.
Una palabra en memoria indica si está ocupada: `0` si está libre, `1` si está ocupada.
El personal pasa por allí toda la noche, cada uno con una tarea que hacer dentro: firmar el libro de registro, enhebrar el proyector, archivar un rollo.
Sea cual sea la tarea, la regla de la cabina es siempre la misma, y hacerla cumplir es cosa tuya: una sola persona dentro a la vez, desde el principio de su tarea hasta el final.

Implementa la función `visit_booth`, que:

1. espera hasta que la cabina esté libre;
2. ocupa la cabina;
3. ejecuta la tarea del visitante;
4. vuelve a liberar la cabina después de la tarea y antes de regresar.

Mientras otra persona ocupa la cabina, debe esperar amablemente con `pause`.

Esta función toma como argumentos, en este orden:

- `booth`: dirección de memoria de la palabra de ocupación, un entero con signo de 64 bits que es `0` o `1`.
- `task`: la tarea del visitante, una función que no toma parámetros y no devuelve ningún valor.

Ten en cuenta que los tests ejecutan tareas que miran la cabina y un libro de registro compartido.
Esto significa que la cabina debe estar ocupada durante toda la tarea, que cada visita debe ejecutar su tarea exactamente una vez y que, con varios visitantes a la vez, el libro de registro debe quedar exacto.

~~~~exercism/caution
La tarea del visitante es una función normal que sigue la convención de llamada:

- puede sobrescribir cualquier registro guardado por el llamador, así que deberías guardar todo lo que sigas necesitando después de la tarea en un sitio que la llamada no pueda tocar;
- también espera que la pila esté alineada a 16 bytes en el momento de la llamada.

El incumplimiento de cualquiera de las dos reglas puede manifestarse como un crash en lugar de una comprobación fallida.
~~~~
