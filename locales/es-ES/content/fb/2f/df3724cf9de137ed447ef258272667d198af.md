La interfaz pública de una base de código debe elegirse con cuidado, ya que cada función pública aumenta los costes de mantenimiento a largo plazo y dificulta la refactorización.

En todos los ejercicios de Exercism, la interfaz pública la define el conjunto de pruebas.
Si se está probando una función, esta debe ser pública.
Todas las demás funciones deben ser privadas, incluidas las funciones con el mismo nombre pero distinta aridad.

```elixir
# you defined the following public function

%{actual}

# make it private like this

%{expected}
```
Ten en cuenta que los argumentos por defecto modifican la aridad de una función.

Al escribir una biblioteca, a menudo es necesario hacer públicas ciertas funciones para poder usarlas entre módulos.
Para ocultar esas funciones de la documentación, quienes escriben bibliotecas añaden `@doc false` antes de las definiciones de las funciones, o `@moduledoc false` para ocultar el módulo entero.
