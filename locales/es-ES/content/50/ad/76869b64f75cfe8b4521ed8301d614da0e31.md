# Introducción

Como se vio en el concepto [`Nothingness`][concept-nothingness], R tiene varias formas de representar datos ausentes (`NULL`), desconocidos (`NA`) o matemáticamente no válidos (`NaN`, `Inf`).
Por lo general, R intentará usarlas para señalar los problemas in situ y continuar sin lanzar una excepción.

## `stop()`

Algunos problemas son demasiado fundamentales como para dejar que el programa continúe.
En ese caso, usa `stop(msg)` para detener el programa inmediatamente con un `Error` e imprimir `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Similar a `assert` en otros lenguajes, es un envoltorio práctico para `stop()`.
Los parámetros son un número arbitrario de condiciones booleanas separadas por comas, y el programa solo continuará si todas son `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `warning()` y `message()`

Estas son respuestas a condiciones que no son fatales, por ejemplo:

- Para advertir de un problema del que el programa podría recuperarse al menos en parte.
- Para informar al usuario del progreso de un programa de larga duración.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

La función `suppressWarnings()` puede resultar útil en ocasiones dentro de Exercism, para no confundir al ejecutor de pruebas con salidas no deseadas.
