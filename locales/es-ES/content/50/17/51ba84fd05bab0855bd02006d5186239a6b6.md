# Acerca de

Swift tiene muchos tipos diferentes, pero cada uno de ellos pertenece a una de estas dos clasificaciones: _tipos de valor_ y _tipos de referencia_. En Swift, [los structs son tipos de valor][structs-are-value-types] y [las classes son tipos de referencia][classes-are-reference-types].

La principal diferencia entre los tipos de valor y los tipos de referencia es que, cuando se asigna un tipo de valor a una variable o constante, o cuando se pasa a una función, lo que se asigna o se pasa es en realidad una copia del valor, no ese valor concreto. Modificar una copia de un struct no afecta a las demás copias. Con los tipos de referencia, lo que se asigna o se pasa es una referencia a ese valor, por lo que dos nombres diferentes pueden referirse a la misma instancia de una class. Esto puede provocar que se modifique la instancia original cuando se accede a ella con otro nombre.

Así, dado el struct y la class que definen un personaje de un juego y sus estadísticas, podemos ver qué ocurre cuando se copian y se modifican estos elementos.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

Fíjate en cómo cambiar las propiedades de `charB` afectó a las de `charA`, ya que ambos nombres se refieren a la misma instancia. Fíjate también en que, con las estadísticas de los dos personajes, los tipos de valor que están dentro de un tipo de referencia cambian dentro de los tipos de referencia. Sin embargo, esto no es una violación del comportamiento de los tipos de valor, porque `charA.stats` es la misma instancia de `CharacterStats` que `charB.stats`, ya que `charA` y `charB` se refieren a la misma instancia de la class `GameCharacter`. Como podemos ver, las copias de esos tipos de valor no se afectan entre sí, por ejemplo.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

Por eso los structs requieren la palabra clave `mutating` delante de los métodos que alteran el estado de las propiedades del struct. Cambiar una propiedad de un struct crea en realidad una nueva copia del struct con el nuevo valor establecido para esa propiedad, y la nueva copia sustituye a la anterior. Es un indicador visual de que esta copia y sustitución pueden ocurrir con valores de ese tipo.

Esto tiene el efecto secundario de que cualquier instancia de un struct cuyas propiedades variables cambien, ya sea llamando a funciones mutating o mediante asignación directa, _debe_ asignarse a variables, no a constantes. De lo contrario, se generará un error de compilación:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

Los valores iniciales se pueden crear y consultar igualmente, pero no se permite cambiarlos. Esta restricción no se aplica a las classes. Si se asigna una instancia de una class a un nombre con `let`, lo que la constante contiene es la referencia a la instancia y, por tanto, lo que no puede cambiar es esa referencia, no la instancia en sí. Así pues, la instancia en sí puede cambiar, pero la referencia no puede cambiar para apuntar a otra instancia.

Un resumen de lo que se puede cambiar en structs y classes definidos con `let` o `var` es el siguiente

|         | **struct**                                                                                  | **class**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _No_ se puede asignar un nuevo struct al nombre.</br>_No_ se puede modificar ninguna propiedad del struct. | _No_ se puede asignar una nueva class al nombre.</br>_Sí_ se pueden modificar las propiedades mutables de la class. |
| **var** | _Sí_ se puede asignar un nuevo struct al nombre.</br>_Sí_ se pueden modificar las propiedades mutables del struct.   | _Sí_ se puede asignar una nueva class al nombre.</br>_Sí_ se pueden modificar las propiedades mutables de la class.    |

## Identidad

Como dos nombres diferentes pueden contener una referencia a la misma instancia de una class, a veces resulta útil comprobar si este es el caso. Swift usa el operador _idéntico_ `===` para comprobarlo (junto con su negación, `!==`).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

Como no hay dos nombres que puedan referirse a la misma instancia de un struct, estos operadores de identidad no están definidos para los structs.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

Ten en cuenta que la identidad no es lo mismo que la igualdad. Según muchas definiciones, `char1` y `char3` se considerarían iguales, ya que todas sus propiedades tienen los mismos valores, pero no comparten la misma identidad. La identidad está disponible automáticamente para todas las classes de Swift, pero los desarrolladores normalmente necesitan escribir sus propios operadores de igualdad para determinar si dos instancias de un struct o de una class son _iguales_. Hacer esto queda fuera del alcance de este ejercicio.
