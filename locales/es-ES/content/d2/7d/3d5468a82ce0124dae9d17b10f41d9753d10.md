# Introducción

## Módulos

El código de Gleam se organiza en módulos, y cada archivo es un módulo de Gleam.

Hasta ahora hemos escrito funciones con la sintaxis `pub fn`, que define una función que está disponible públicamente para otros módulos. Las funciones definidas con `fn` son privadas del módulo en el que se definen y no pueden usarlas otros módulos.

```gleam
// This function is public
pub fn add(x, y) {
  x + y
}

// This function is private
fn subtract(x, y) {
  x - y
}
```

Los módulos de Gleam tienen nombres, y el nombre se basa en su ruta de archivo dentro del directorio `src` o `test`.

Por ejemplo, un módulo definido en `src\geometry\rectangle.gleam` (en Windows) o `src/geometry/rectangle.gleam` (en sistemas operativos tipo UNIX) se llamaría `geometry/rectangle`.

## Importar funciones de otros módulos

Para acceder a funciones definidas en otros módulos se usan las importaciones.
Todas las funciones de ese módulo que este expone se hacen accesibles al importar ese módulo.
Pero la forma de acceder a ellas varía según cómo se importe el módulo.

Las importaciones cualificadas son las predeterminadas, y para acceder a una función dentro de ese módulo (por ejemplo, la función `map` del módulo `gleam/list`) hay que anteponer el nombre del módulo (`list.map`).

```gleam
// Import the int module
import gleam/int

pub fn run(x: Int) -> String {
  // Use the to_string function from the int module
  int.to_string(x)
}
```

De forma predeterminada, el nombre que se usa para referirse al módulo es la última parte del nombre del módulo, en este caso `int`, pero se puede cambiar usando la palabra clave `as`.

```gleam
// Import the int module and refer to it as i
import gleam/int as i

pub fn run(x: Int) -> String {
  i.to_string(x)
}
```

Las importaciones sin cualificar permiten acceder directamente a las funciones expuestas de ese módulo, sin tener que anteponer el nombre del módulo.

```gleam
// Import the to_string function from the int module
import gleam/int.{to_string}

pub fn run(x: Int) -> String {
  to_string(x)
}
```

Se prefieren las importaciones cualificadas porque dejan más claro al lector de dónde procede una función y porque evitan colisiones de nombres.


## Biblioteca estándar

Gleam tiene una biblioteca estándar amplia y bien documentada. La documentación está disponible en línea en [hexdocs.pm/gleam_stdlib][docs]. Guarda este enlace en algún sitio, ¡lo usarás mucho!

La mayoría de los tipos de datos integrados tienen un módulo correspondiente que ofrece funciones para trabajar con ese tipo de datos; por ejemplo, está el módulo `gleam/int` para números enteros, el módulo `gleam/string` para strings, el módulo `gleam/list` para arrays, etcétera.

[docs]: https://hexdocs.pm/gleam_stdlib/
