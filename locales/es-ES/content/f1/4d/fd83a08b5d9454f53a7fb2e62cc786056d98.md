# Pistas

## General

- Declara los cuatro símbolos cardinales y los cuatro símbolos de
  rumbo relativo con una sola línea `SYMBOLS:`:
  `SYMBOLS: north east south west ahead starboard behind port ;`
- Cada tupla se declara con `TUPLE: <class> <slot1> <slot2> ;`.
- Una línea `GENERIC:` declara la palabra; cada línea `M:` añade un
  método para una clase. Usa `M::` si quieres variables locales con
  nombre en el cuerpo del método.

## 1. `>cartesian` para cardinal

- Un `case` pequeño sobre los cuatro símbolos de dirección es suficiente.
- `{ north [ 0 1 ] }`: el cuerpo solo apila los dos valores; el test
  espera que `x` quede por debajo de `y` en la pila.

## 2. `>cartesian` para polar

- Convierte los grados a radianes: `bearing pi * 180 /`.
- `sin` y `cos` están en `math.functions`.
- Apila `magnitude * sin(rad)` y después `magnitude * cos(rad)`.

## 3. `>cartesian` para relative

- Declara una variable dinámica: `SYMBOL: heading`.
- Léela en tu método con `heading get`.
- Asigna a `ahead/starboard/behind/port` un desplazamiento
  `0/90/180/270` con un `case` y luego suma el heading. A partir de
  ahí es la misma conversión polar que en la tarea 2. Considera
  extraer una función auxiliar
  `: deg>cartesian ( magnitude bearing -- x y ) ... ;`.

## 4. `flip`

- `change-direction` sobre un `cardinal` y `change-bearing` sobre un
  `polar` o un `relative` construyen una tupla nueva con una ranura
  modificada y dejan intacto el resto:
  `[ <transformation-quotation> ] change-bearing`.
- Para la rotación de `polar`: `[ 180 + 360 mod ] change-bearing`.

## 5. `add-bearings`

- Llama a `>cartesian` con cada entrada y luego suma las componentes x
  y las componentes y. Las variables locales hacen que esto se lea
  mejor:
  ```factor
  :: add-bearings ( a b -- x y )
      a >cartesian :> ay :> ax
      b >cartesian :> by :> bx
      ax bx +
      ay by + ;
  ```
