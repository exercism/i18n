# Introducción

Una función es **recursiva** cuando se llama a sí misma.

Una diferencia clave entre una llamada a función y un bucle es que llamar a una función apila en la pila la dirección de retorno.
Esto significa que una función recursiva normalmente exige más espacio de pila que un bucle equivalente.

Como consecuencia, una función que se llama a sí misma repetidamente puede acabar agotando todo el espacio de pila.
Esto se denomina **desbordamiento de pila**.

Por eso, toda función recursiva debe tener al menos un caso base, que es una situación en la que la función devuelve sin llamarse a sí misma.
Toda llamada recursiva debe acabar alcanzando un caso base.

Por ejemplo, la función factorial `n! = n * (n - 1) * ... * 1` puede definirse de forma recursiva con `1` como caso base:

```x86asm
factorial:
    ; the argument `n` is passed on `rdi`
    ; the factorial will be returned on `rax`

    cmp rdi, 1
    jle .base_case     ; base case -> if rdi <= 1, return 1

    push rdi           ; save n
    dec rdi            ; rdi = n - 1
    call factorial     ; recursive call, rax = (n - 1)!
    pop rdi            ; restore n
    imul rax, rdi      ; rax = n * (n - 1)! = n!
    ret
.base_case:
    mov rax, 1
    ret
```

Ten en cuenta que `factorial` debe hacer `push rdi` antes de la llamada recursiva y `pop rdi` después.
Esto se debe a que todavía necesita `n` cuando la llamada recursiva devuelve, para calcular `n * (n-1)!`.

Fíjate también en que usar un registro guardado por la función llamada no resolvería este problema.

Aunque una función recursiva es un posible llamador de sí misma, también es la función llamada por alguna otra función.
Eso significa que la función también debe preservar los registros guardados por la función llamada antes de usarlos, y restaurar su valor después de usarlos.
Esto se suele hacer con una secuencia de `push`/`pop`, como hemos visto en un concepto anterior.

Como cada marco de una función recursiva, a excepción del caso base, también es un llamador que necesita preservar sus propias variables locales, esta secuencia de `push`/`pop` debe repetirse para cada marco.
Incluso almacenar la variable directamente en la pila, sin usar registros, seguiría costando los mismos `8` bytes por marco.

Esto significa que cada llamada recursiva añade `8` bytes a la pila por la dirección de retorno que apila `call`, más `8` bytes por cada variable local que necesita guardar.
La función seguirá añadiendo esos bytes a la pila en cada marco hasta que alcance su caso base.
Solo entonces empieza a desenrollarse en orden inverso, y cada llamada recursiva usa tantos `pop` como necesite y después un `ret`.

Por ejemplo, si se llamara a `factorial` con el argumento `10`, se llamaría a sí misma nueve veces antes de alcanzar el caso base de `1`.
En ese punto, se habrían usado `144` bytes para almacenar `n` (`8` bytes) y la dirección de retorno (`8` bytes) de cada marco anterior.

## Llamada de cola

En algunas situaciones, una función no realiza más trabajo después de llamar a otra y antes de devolver.

Considera, por ejemplo:

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    call times_three
    ret
```

La función `triple_of_square`:

- multiplica el argumento que recibe (en `rdi`) por sí mismo, obteniendo su cuadrado;
- después llama a `times_three`, que devuelve el triple del argumento que se le pasa.

Como resultado, `triple_of_square` devuelve `3*x²`, donde `x` es su argumento, que se pasa en `rdi`.

Fíjate en que no se hace ningún trabajo en `triple_of_square` después de llamar a `times_three`; la función simplemente devuelve.
En una situación así, en lugar de usar `call`, una función podría usar `jmp` y transferir la ejecución a la función llamada:

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    jmp times_three
```

Esto se denomina una **llamada de cola**.

La principal ventaja de una llamada de cola es evitar el coste adicional de `call`.
Un `call` apila una dirección de retorno en la pila, y para que el control vuelva a ese punto debe haber un `ret` correspondiente.

Una llamada de cola se salta ambos: no hay dirección de retorno que apilar ni `ret` adicional que emparejar, solo el `ret` de la propia función llamada.

## Recursión de cola

Una llamada de cola es especialmente útil para funciones recursivas que pueden llamarse a sí mismas muchas veces antes de devolver.

Sin embargo, no toda llamada recursiva puede traducirse directamente en una llamada de cola.
Como un `jmp` transfiere el control a la función llamada, el llamador no puede realizar más trabajo después de la llamada de cola.

Por ejemplo, la función `factorial` anterior **no** es recursiva de cola.
Después de la llamada recursiva, todavía necesita multiplicar el resultado por el valor actual de `n`, usando `imul rax, rdi`.

En situaciones así, a veces es posible usar un acumulador que recoja los cálculos parciales y se devuelva al final.
Por ejemplo, podemos definir un `factorial_helper` que haga la mayor parte del trabajo y luego `factorial` inicializa un acumulador y transfiere el control a `factorial_helper`:

```x86asm
factorial_helper:
    ; the argument `n` is passed on `rdi`
    ; `rax` is used as an accumulator and will be returned at the end

    cmp rdi, 1
    jle .base_case

    imul rax, rdi        ; we accumulate the partial result on `rax`
    dec rdi              ; rdi = n - 1
    jmp factorial_helper ; tail call to accumulate (n - 1)!
.base_case:
    ret                  ; returns the factorial already accumulated on `rax`

factorial:
    mov rax, 1           ; initial value for the accumulator
    jmp factorial_helper ; tail call
```

Como no se hace más trabajo después de la llamada recursiva, tampoco necesitamos guardar `rdi`.
No hay `call` ni `push rdi`, así que cada iteración recursiva añade `0` bytes a la pila: no se usa espacio de pila adicional.
Esta versión puede manejar valores de `n` arbitrariamente grandes sin desbordar la pila.
Es a la vez más eficiente y más segura.

En algunos casos, manipulando el orden de las funciones, incluso se puede evitar el `jmp` a la función auxiliar.
Por ejemplo, `factorial` y `triple_of_square` pueden reescribirse de esta manera:

```x86asm
factorial:
    mov rax, 1
factorial_helper:
    cmp rdi, 1
    jle .base_case

    imul rax, rdi
    dec rdi
    jmp factorial_helper
.base_case:
    ret

triple_of_square:
    imul rdi, rdi
times_three:
    imul rax, rdi, 3
    ret
```

En el fragmento anterior, la ejecución de `factorial` pasa directamente a `factorial_helper`.
Lo mismo ocurre con `triple_of_square` y `times_three`.
En ambos casos, la ejecución continúa secuencialmente y parece que la función de cola es solo una etiqueta local dentro de la función «principal».

En realidad, no hay ninguna diferencia esencial entre cualquier etiqueta local y una función.
El ensamblador x86-64 no da un trato especial a ninguna de ellas; solo son direcciones en una sección con código ejecutable, como `section .text`.

De esta forma, una función recursiva de cola puede considerarse esencialmente lo mismo que un bucle en el que la llamada recursiva salta de nuevo al principio, y el caso base es la condición que termina el bucle.
