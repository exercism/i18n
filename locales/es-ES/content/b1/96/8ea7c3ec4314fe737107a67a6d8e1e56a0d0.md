# Introducción

Este ejercicio se basa en lo que viste en [Observador de aves del jardín][backyard-birdwatcher] al presentar las palabras de orden superior que reciben una *quotation* (un fragmento de código entre corchetes (`[ ]`)) para dirigir la operación.

## Las quotations como valores

Una quotation no es más que un fragmento literal de código. Puedes pasarla como dato a otra palabra:

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

Aquí `[ 2 > ]` es una quotation que recibe un número y deja un Boolean. `count` la ejecuta en cada elemento y cuenta los resultados verdaderos.

## Filtrar y rechazar

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

`without` trata su segundo argumento como un conjunto: cualquier elemento de `seq` que sea `=` a *cualquier* elemento de `exclude` se descarta. `sift` es el caso especial de `reject` sin quotation: conserva todos los elementos excepto `f`, lo que resulta útil para limpiar los huecos que dejó un `map` anterior.

### Conservar el resultado de la prueba

`find` devuelve el *elemento* que coincide. Cuando la prueba ya *calcula* el valor que realmente quieres, `map-find` te ahorra una segunda pasada: ejecuta la quotation sobre cada elemento y devuelve el primer resultado distinto de `f` **y** el elemento que lo produjo.

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

La quotation devuelve `f` para los elementos que no cumplen la condición y el resultado que quieres conservar para el que sí la cumple. Si ninguno la cumple, `map-find` deja `f f`, igual que `find`.

### Filtrar registros por una ranura

Cuando los elementos son *tuplas*, el predicado suele proyectar una ranura mediante su lector autogenerado `slot>>` y comprueba sobre ella:

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## Propagar un valor fijo con `with`

A veces el predicado necesita un valor que sea el mismo en cada llamada: un umbral, un divisor, un string de destino. `with` (de [`kernel`][kernel]) incorpora ese valor fijo a la quotation y convierte una quotation de dos argumentos, `( value elt -- ? )`, en la quotation de un argumento que esperan `filter`, `count`, `map` y `each`:

```
with ( value seq quot -- seq curry )
```

Cada llamada por elemento ve `( value elt )` en la pila: primero el valor fijo, después el elemento actual:

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## Mapear e iterar

`map` (de [`sequences`][sequences]) aplica una quotation a cada elemento y devuelve el array de resultados. `each` hace el mismo recorrido, pero descarta los resultados; resulta útil cuando la quotation se ejecuta únicamente por sus efectos secundarios. `2map` recorre *dos* secuencias al unísono y combina los elementos correspondientes; `2each` y `2reduce` son sus primos de solo efectos secundarios y de plegado; `zip` es la forma abreviada de «emparejarlos sin combinarlos»:

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

`2reduce` pasa un acumulador por ambas secuencias a la vez; su quotation recibe `( accumulator elt1 elt2 -- accumulator' )`. Aquí acumula un producto escalar: cada par se multiplica y los productos se suman (`1*10 + 2*20 + 3*30`):

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

`map-as` es el primo de `map` que fuerza el tipo de la secuencia de salida: pasa un `{ }` o un `V{ }` vacíos como ejemplar para anular el valor predeterminado del tipo de entrada (de lo contrario, mapear un string a elementos que no son caracteres da error cuando Factor intenta volver a empaquetar los resultados en un string).

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

Ambas formas con dos secuencias se detienen en la longitud de la entrada más corta. `zip` equivale a `[ 2array ] 2map`: conserva los pares en lugar de colapsarlos.

## Ordenar

`sort` devuelve una copia ordenada en orden natural; `sort-by` (de [`sorting`][sorting]) ordena por una clave extraída de cada elemento:

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## Agregar

`map-sum` (de [`sequences`][sequences]) mapea una quotation a lo largo de la secuencia y suma los resultados en una sola pasada:

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## Mínimo y máximo

`minimum` y `maximum` devuelven directamente el elemento más pequeño o más grande de una secuencia. `minimum-by` y `maximum-by` (todas ellas en [`sequences`][sequences]) devuelven el elemento cuya clave extraída es la más pequeña o la más grande:

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## Escribir tu propia palabra de orden superior

Cuando *tu* palabra recibe una quotation como argumento en tiempo de ejecución y la reenvía a `map`, `filter`, `each`, etc., declara tu palabra con `; inline`. Eso le indica al compilador que inserte tu palabra en línea en cada punto de llamada, donde la quotation es un literal conocido; sin eso, el compilador no tiene forma de conocer el efecto de pila de la quotation.

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

Las palabras construidas solo a partir de quotations literales no necesitan `inline`, solo aquellas que hacen pasar una quotation *entrante*.

Si una palabra `inline` de este tipo llega a llamarse *a sí misma* (un combinador recursivo), declárala `; inline recursive` en su lugar. Sin esa palabra adicional, el compilador se detiene con «The inline recursive word ... must be declared recursive», que te dice exactamente qué añadir.

## Obtener el segundo elemento

En un array de 2 elementos, `second` devuelve su segundo elemento. `first` devuelve el primero. Ambas están en [`sequences`][sequences].

## De números a strings

`number>string ( n -- str )` (de [`math.parser`][math.parser]) convierte un número en su forma de string decimal:

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
