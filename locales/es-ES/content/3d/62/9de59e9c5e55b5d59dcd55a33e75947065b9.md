# Iteradores personalizados

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | rutina | iterador |
| --- | --- | --- |
| nombre | `foo` | `foo!` |
| devuelve un valor | `return` | `yield` |
| termina | `return`, o el final | `quit`, o agotarse |
| se puede llamar | en cualquier parte | solo dentro de un `loop` |
| mantiene su posición | no | sí |

## yield

`yield` entrega un valor y suspende la ejecución. Todo se restaura en la
siguiente vuelta: las variables locales, la posición en los bucles del propio
iterador y las posiciones de los iteradores a los que él mismo está llamando.

Un `yield` dentro de bucles anidados se reanuda en el más interno, que es lo
que hace que escribir un recorrido por algo anidado resulte sencillo:

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

Pone fin al iterador y, por tanto, al bucle que lo está llamando. No lleva
ningún valor: un `quit` no es un último resultado, es el anuncio de que no hay
ninguno.

Un iterador con tipo devuelto tiene que devolver un valor en cada `yield`;
`quit` es su forma de no hacerlo.

## once

```sather
   markers!(once count : INT) : INT is
```

Un parámetro `once` se evalúa cuando se entra en el bucle y se conserva. Un
parámetro normal se reevalúa en cada vuelta, lo cual importa cuando la expresión
que se le pasa contiene otra llamada a un iterador:

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

Marca los parámetros como `once` a menos que quieras eso en concreto. Toda la
biblioteca lo hace.

## self y los iteradores

Un iterador se puede llamar sobre un objeto y, en ese caso, `self` es ese
objeto. Su estado en pausa pertenece al punto de llamada, no al objeto, así que
dos bucles que recorren el mismo objeto no interfieren entre sí.

## Cuándo escribir uno

Escribe un iterador cuando la respuesta sea una secuencia y quien llama deba
decidir cuánta parte de ella tomar. Parar antes no cuesta nada y no se
construye nada que no se vaya a usar, mientras que una rutina que devuelve un
`ARRAY` tiene que construir todo entero primero.
