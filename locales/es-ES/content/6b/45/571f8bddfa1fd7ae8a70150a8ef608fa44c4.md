# Introducción

Los especificadores de clase de almacenamiento tienen que ver con cómo se guardan las variables en la memoria.
Están estrechamente relacionados con la duración de almacenamiento (también conocida como tiempo de vida) de un valor.

## auto: la clase de almacenamiento predeterminada para variables en el scope de función o de bloque

Como las variables definidas dentro de un bloque o una función son `auto` de forma predeterminada, no es habitual usar el término de forma explícita.
El tiempo de vida de una variable `auto` empieza cuando se entra en su bloque y termina cuando se sale de él.
Cuando se entra en su bloque, se asigna memoria para una variable `auto`, _pero sin ningún valor predeterminado_.

## static: el especificador de almacenamiento que no hay que confundir con el tipo de enlace static

Si una variable se define fuera de un bloque o una función y está marcada con `static`, ese `static` se refiere a su enlace, lo que significa que solo se puede acceder a ella dentro del fichero.
Si una variable se define dentro de una función o en un bloque dentro de una función y está marcada como `static`, tiene duración de almacenamiento `static`.
El valor de la variable `static` persiste entre llamadas a la función o al bloque.

## extern: cómo acceder a una variable de otra unidad de traducción

Una unidad de traducción consta de un fichero fuente y cualquier otro fichero que este incluya mediante `#include`.
Aunque una variable con scope de fichero se puede declarar e inicializar como `extern`, la palabra clave `extern` se suele usar para referirse a una variable existente, no para definir una nueva.
La variable a la que se refiere `extern` debe tener scope de fichero.
Una variable con scope de fichero siempre tiene almacenamiento `static`.
Una variable que está en un fichero incluido debe tener enlace externo para que el fichero que la incluye pueda acceder a ella.

## register: cómo acelerar el acceso a una variable, si es posible

Una variable marcada como `register` expresa el deseo del programador de que el valor se coloque en un registro para poder acceder a él rápidamente.
Una variable `register` es como una variable `auto` en el sentido de que debe estar en el scope de una función o de un bloque.
Dado que el valor se pretende colocar en un registro en lugar de en la memoria, el compilador debería impedir el acceso a la dirección de la variable, ya que no se puede obtener la dirección de un registro.
Sin embargo, una dirección de memoria sí se puede colocar en un registro.
`register` es, esencialmente, una sugerencia, ya que puede que el valor se coloque realmente en un registro o puede que no.

## typedef: el especificador de clase de almacenamiento que en realidad no lo es

`typedef` se describe como un especificador de clase de almacenamiento solo por razones sintácticas.
Esto se debe a que un especificador de clase de almacenamiento no se puede usar junto con otro especificador de clase de almacenamiento.
Así, `typedef auto int i = 42;` es tan ilegal como `static auto int i = 42;`.
