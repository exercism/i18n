# Introducción

## Enumeraciones

Hasta ahora hemos trabajado sobre todo con números y strings.
Para modelar el mundo real, puede que queramos un número limitado de valores que una variable pueda tomar.
Es posible que quieras un tipo específico con unos pocos valores distintos y con nombres distintos.
Por ejemplo, en una fábrica de monopatines, que el material de la tabla sea una elección entre solo arce, bambú o plástico.

Podrías usar números enteros para codificar esos valores, pero tendrías que usar código adicional para comprobar si el sistema devuelve un valor no válido para el material.
El significado de esos [_números mágicos_][magic numbers] es difícil de rastrear por el código fuente y son propensos a confusiones.
Las `enumerations` se pueden usar para fomentar un código expresivo y para restringir errores de comparación involuntarios.

## Ejemplo de uso

El término específico para este tipo de enumeración es `scoped enumeration`.
El siguiente fragmento muestra cómo escribir una `enumeration` `DeckMaterial`.
Fíjate en la palabra clave `enum class` y en el `;` al final de la definición:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
Ahora, fíjate en una función de precios de la tienda de monopatines y toma nota del operador de resolución de scope (`::`), que especifica un `enumerator` de la `enumeration`:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## El scope

Imagina que tienes una segunda `enumeration` para el material de las ruedas:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
Aunque tanto las ruedas como la tabla pueden estar hechas de _plastic_, las dos no se pueden confundir.
Son _tipos_ diferentes: `DeckMaterial` plastic y `WheelMaterial` plastic.
Cada `enumeration` tendrá sus `enumerators` en su propio scope, su propio `namespace`.
Esta es la razón por la que se llaman `scoped enumerations`.

## Enumeraciones sin scope
Puede que estés pensando que, si existe el nombre `scoped`, también habrá enumeraciones `unscoped`, y tienes razón.
Las `unscoped enumerations` son cada vez menos populares porque todas comparten el mismo espacio de nombres global.
Debido a ese uso compartido, no podrías tener dos `unscoped enumerations` con los mismos `enumerators`, como _plastic_ en el ejemplo anterior.

Además, las `Unscoped enumerations` se convierten implícitamente en números enteros.
Fíjate en el ejemplo siguiente, con un resultado sorprendente:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

Si quieres convertir `scoped enumerations` en números enteros, puedes usar `static_cast<int>`.
