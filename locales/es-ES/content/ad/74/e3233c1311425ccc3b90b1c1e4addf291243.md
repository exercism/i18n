# Introducción

## Bucles

Un **bucle** es una secuencia de instrucciones que se ejecuta potencialmente más de una vez, hasta que se cumple una condición de fin.

En x86-64, un bucle se suele crear con un salto a una etiqueta anterior:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Ten en cuenta que un salto incondicional a una etiqueta anterior siempre transferirá la ejecución a esa etiqueta.
Esto significa que el bucle se repetirá para siempre, a menos que haya otro salto hacia fuera de la secuencia repetida.

Por ejemplo, este bucle no termina:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Y este bucle puede terminar, en función de si se cumple la condición:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### Bucles de recuento

Un bucle de recuento casi siempre termina de la misma forma: una instrucción que actualiza un contador o compara dos valores, seguida inmediatamente de un salto condicional que decide si se vuelve a repetir.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0` no es necesario en el código anterior porque `sub rsi, 1` ya establece la `zero flag (ZF)` cuando el resultado es `0`.

Aunque `cmp` es la forma principal de comprobar condiciones en ensamblador, muchas instrucciones actualizan las banderas.
Por ejemplo, muchas instrucciones aritméticas de enteros o de bits actualizan `ZF` cuando el resultado es `0`, y `SF` cuando el resultado es negativo (es decir, cuando el bit más significativo está activado).

Puedes consultar una [referencia][reference] para ver qué banderas afecta cada instrucción.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Ten en cuenta que, en el ejemplo anterior, se supone que `rsi` es mayor que `0`.
Si fuera `0`, `sub rsi, 1` reduciría `rsi` a `-1`, que es un número sin signo muy grande.
Harían falta `18,446,744,073,709,551,615` iteraciones más para que el bucle terminara por fin.
Además, como la longitud del array es `0`, cualquier acceso a memoria quedaría fuera de los límites.

Si no hay garantías sobre la longitud de un array, hay dos enfoques habituales.

El primero es trasladar la condición de fin al principio del bucle y poner un salto incondicional al final:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

El segundo es comprobar una vez si el array tiene longitud cero antes de empezar el bucle:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Este segundo enfoque suele ser más eficiente que el primero, porque hay menos bifurcaciones en el cuerpo del bucle.
Aprenderás más sobre esto en un concepto posterior.

~~~~exercism/advanced
En algunas situaciones, las CPU modernas son capaces de fusionar dos instrucciones distintas en una sola operación.
Esta optimización se llama **macrofusion**.

Muchas instrucciones aritméticas como `sub` y `add`, así como `cmp` y `test`, se fusionan habitualmente con el salto condicional que las sigue inmediatamente.
Esto significa que la CPU normalmente puede tratar una instrucción como `cmp rax, rdx` seguida inmediatamente de un salto condicional como una sola operación.

La macrofusion depende de la CPU y hay cierta variación en qué instrucciones se fusionan con qué salto condicional.

Una referencia útil es [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
La sección 3.4.2.2 (Optimizing for Macrofusion) del [Intel optimization reference manual][intel-opt] también enumera los pares fusionables para las CPU Intel.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
