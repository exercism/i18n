# Pruebas

Puedes ejecutar los ejercicios de Odin que hay en el directorio de tu proyecto de Exercism cambiando al directorio del ejercicio y ejecutando `odin test .`.

```sh
cd "$(exercism workspace)"/odin/leap
odin test .
```

## Activar las comprobaciones del lenguaje

Mientras haces pruebas, Odin puede hacer un «vet» de tu código: puede buscar cosas como importaciones y variables sin usar.

Ejecuta tus pruebas con

```sh
odin test . -vet
```

Para obtener aún más comprobaciones, añade la opción `-strict-style`.

## Desarrollo guiado por pruebas (TDD)

`odin test` ejecuta cada procedimiento que tiene el atributo `@(test)`.

En el conjunto de pruebas, verás que cada procedimiento de prueba tiene este atributo.
Esto significa que, cuando lanzas las pruebas, se ejecuta cada procedimiento de prueba.

Exercism suele promover el [desarrollo guiado por pruebas][tdd], en el que:

- al principio, todas las pruebas excepto la primera están configuradas para omitirse;
- escribes solo el código suficiente para pasar la primera prueba;
- después habilitas la siguiente prueba y escribes solo el código suficiente para hacerla pasar;
- repites hasta que tu código pase todas las pruebas.

Nosotros (quienes mantenemos el track) no encontramos una forma programática elegante de ejecutar un subconjunto de las pruebas.
El archivo de pruebas simplemente se volvió demasiado inmanejable.
Para desarrollar con TDD, puedes editar el archivo de pruebas y simplemente comentar las pruebas que aún no estés listo para ejecutar, e ir descomentándolas una a una a medida que escribes tu solución.
