## Closures finales

Swift ofrece otra variación de su sintaxis a la hora de trabajar con closures, conocida como [closures finales][trailing-closures]. Los closures finales surgen cuando el último parámetro de la lista de parámetros de una función tiene un tipo de función. En este caso, si se pasa un closure, el closure puede escribirse _después_ del paréntesis de cierre y se omite la etiqueta del argumento. Ten en cuenta que si la función tiene un solo parámetro, los paréntesis pueden omitirse por completo.

```swift
func fetchURL(_ urlString: String,
              uponReceipt handleResult: (String) -> ()
             )  -> () {
  if let url = URL(string: urlString), let htmlString = fetch(url) {
    handleResult(htmlString)
  }
}

fetchURL("https://www.swift.org") { print($0) }
// prints the fetched html string

["apple", "ball", "carrot"].sorted { $0.count < $1.count }
```

## Varios closures finales

Aunque las versiones anteriores de Swift solo admitían el uso de un único closure final, a partir de la versión 5.2.4 Swift admite varios closures finales.

Si una función tiene más de un closure al final de su lista de parámetros, puede usarse la sintaxis de closures finales para sacarlos todos fuera de los paréntesis. Sin embargo, solo se omite la etiqueta del primer argumento; el resto debe llevar etiqueta:

```swift
func fetchURL(_ urlString: String,
              uponReceipt handleResult: (String) -> (),
              onFailure handleFailure: () -> ()
             )  -> () {
  if let url = URL(string: urlString), let htmlString = fetch(url) {
    handleResult(htmlString)
  } else {
    handleFailure()
  }
}

fetchURL("https://www.swift.org") {
  print($0)
} onFailure: {
  print("Error: https://www.swift.org could not be fetched")
}
// prints the fetched html string on successful fetch or prints error message on failure
```
