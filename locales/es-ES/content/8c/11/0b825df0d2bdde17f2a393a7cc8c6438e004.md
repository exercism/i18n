# Introducción a los comandos y argumentos

Este track no trata sobre cómo usar bash como shell interactivo.
Se trata de aprender a escribir programas con bash, el lenguaje de programación.

Un programa de bash, o _script_, es una secuencia de comandos almacenada en un fichero.
bash (el ejecutable) lee el fichero y ejecuta los comandos en orden.

## El shebang

La primera línea de un script suele ser una _directiva de intérprete_, también conocida como _hashbang_ o _shebang_:

```bash
#!/usr/bin/env bash
```

Cuando el sistema operativo ejecuta un fichero no binario, lee la primera línea.
Si la línea empieza por `#!`, el kernel la usa para determinar qué intérprete debe ejecutar el fichero.
El `#!` debe estar al principio mismo del fichero, sin espacios ni líneas en blanco antes.

Aquí, `env` busca en `PATH` el ejecutable `bash`.
También puedes ver el más simple `#!/bin/bash`, que fija directamente la ubicación del intérprete; la forma con `env` es más portable.

~~~~exercism/note
No te dejes engañar por los scripts o ejemplos de Internet que usan `/bin/sh` como intérprete.
**¡`sh` no es `bash`!**
Bash es «compatible con sh» y puede ejecutar la mayoría de los scripts `sh`, pero algunas funcionalidades de bash fallan o se comportan de forma inesperada en `sh`.
~~~~

## Comentarios

Una línea que empieza por `#` es un _comentario_, y bash lo ignora.
Un comentario también puede seguir a un comando en la misma línea: todo lo que va desde el `#` hasta el final de la línea se ignora.
Los comentarios están pensados para las personas que leen el script.

## Palabras y argumentos

Bash lee comandos de su entrada (que normalmente es un terminal o un fichero).
Cada línea de entrada que lee se trata como un _comando_: una instrucción que hay que llevar a cabo.
(Hay algunos casos avanzados, como los comandos que abarcan varias líneas, que veremos más adelante.)

Bash divide cada comando en **palabras** delimitadas por caracteres de espacio en blanco (espacios y tabulaciones).
La primera palabra es el nombre del _comando_ que se va a ejecutar.
Todas las palabras restantes se convierten en _argumentos_ de ese comando (opciones, nombres de fichero, etc.).

Un comando puede ser un _comando integrado_ de bash, como `echo`, o un programa _ejecutable_, como `head`, `awk` o `sed`.

## El comando `echo`

`echo` imprime sus argumentos, separados por un solo espacio, y termina con un salto de línea:

```bash
echo flour sugar eggs
```

produce:

```text
flour sugar eggs
```

La cantidad de espacio en blanco entre argumentos no importa:

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

Llamar a `echo` sin ningún argumento imprime una línea en blanco.

## Las opciones son argumentos

Muchos comandos aceptan _opciones_ que cambian su comportamiento.
Para bash, una opción no tiene nada de especial: es una palabra como cualquier otra, separada de las de al lado por espacio en blanco.
El propio comando decide cómo interpretar sus argumentos.
Por convención, las opciones empiezan por `-`.

El comando `head` imprime las primeras líneas de un fichero.
Dado un fichero `list.txt`:

```bash
head -n 2 list.txt
```

Bash divide esta línea en cuatro palabras:

| Palabra    | Función                                              |
| ---------- | ---------------------------------------------------- |
| `head`     | el comando que hay que ejecutar                      |
| `-n`       | una opción que indica a `head` que cuente _líneas_   |
| `2`        | el valor de la opción `-n`                           |
| `list.txt` | el fichero que hay que leer                          |

Bash pasa las tres últimas palabras a `head` sin cambios.
Es `head` el que entiende que `-n` va seguido de un número y que la palabra restante es un fichero.

Como el espacio en blanco es lo que separa las palabras, importa dónde lo pongas.
`head -n 2` le pasa a `head` dos argumentos (`-n` y `2`), mientras que `head -n2` le pasa uno (`-n2`).
Muchos comandos aceptan las dos formas, pero eso depende del comando.
A bash le da igual; solo divide la línea en palabras.

## Entrecomillar argumentos

Las [comillas][Quotes] agrupan palabras en un _único argumento_.
El espacio en blanco dentro de las comillas se conserva, y los propios caracteres de comillas no forman parte del argumento:

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

Si un argumento, como el nombre de un fichero, contiene espacio en blanco, entrecomíllalo:

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## Ejecutar un script

Para ejecutar un script, pásalo como argumento al comando `bash`:

```bash
bash myscript
```

Usada así, la línea `#!` es solo un comentario.
Le estás diciendo al sistema operativo cómo ejecutar el fichero.

Como alternativa, marca el fichero del script como ejecutable y ejecútalo como cualquier otro programa:

```bash
chmod +x myscript
./myscript
```

Ahora el sistema operativo usa la línea `#!` para determinar qué intérprete debe usar.
