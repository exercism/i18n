# Anexo a las instrucciones

## El proceso de E/S

A diferencia de otros ejercicios, `grep` requiere interactuar con el «mundo externo»: leer ficheros, gestionar errores del sistema e imprimir en `stdout`.

En Lean, la interacción con el sistema suele hacerse en la mónada [IO][io], que permite que ocurran efectos secundarios en un entorno contenido sin afectar al estado puro de la mayoría de las demás funciones.

## Lectura de argumentos

Lean permite que se llame a un fichero como script, ya sea directamente como script independiente mediante `lean --run` o con el uso de `lake`.

Un proyecto Lean tiene un único punto de entrada, una función llamada `main`, que recibe un `List String` con todos los argumentos que se le pasan. Para simular la ejecución de `Grep.lean` como un ejecutable, en este ejercicio los argumentos se pasan de la misma forma.

## Lectura de ficheros

Lean ofrece [funciones][files] para manipular ficheros en la mónada `IO.FS`. Por ejemplo, `IO.FS.readFile` puede usarse para leer el contenido de un fichero de una ruta dada como un `String`.

## Escritura de la salida

En lugar de devolver un valor, este ejercicio requiere que los resultados se escriban en la salida estándar o en la salida de error. Lean tiene [funciones][console] para este fin.

## Gestión de errores del sistema

A diferencia de los errores en `Except`, las excepciones de `IO` son realmente excepciones en tiempo de ejecución. Puedes usar `try`/`catch` para gestionarlas:

```
try
    /- 
        code that may possibly raise an exception 
    -/
catch msg =>
    /-
        code that is executed only if an exception was thrown
    -/
```
