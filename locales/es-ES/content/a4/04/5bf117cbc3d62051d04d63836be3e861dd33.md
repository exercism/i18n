# Acerca de

Elm es un lenguaje encantador para crear aplicaciones web fiables.
Tiene mensajes de error amables, un rendimiento excelente, recursos ligeros y ninguna excepción en tiempo de ejecución.

Probablemente la parte más famosa y más copiada de Elm sea The Elm Architecture, que es un patrón sencillo para estructurar aplicaciones web y es como se escriben todas las aplicaciones web en Elm.

La idea central es que tu código se construye en torno a un `Model` del estado de tu aplicación, una forma de `update` tu modelo y una forma de `view` tu modelo.

El `Model` contiene el estado de la aplicación: todos los datos que esta necesita.
Puede ser de cualquier tipo, pero en cualquier aplicación útil suele ser un [record][record].
Si imaginas una aplicación sencilla con un cuadro de texto y un texto que muestra ese texto al revés, el modelo sería como el siguiente.
También puedes ver este ejemplo en la [Elm Guide][elm-guide-text-fields].

```elm
type alias Model =
  { text : String
  }
```

`update` es una función a la que se llama con un `Msg` cuando hay un cambio (como que el usuario pulse un botón).
Recibe el `Msg` y el `Model` actual, y devuelve un nuevo `Model`.
El `Msg` puede ser de cualquier tipo, pero normalmente es un [custom type][custom-type].

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

Como ocurre con todos los custom types, las variantes del `Msg` pueden incluir toda la información arbitraria que necesiten.
En el ejemplo anterior, la variante `TextChanged` incluye un `String`.

`view` es una función que devuelve el HTML que se muestra al usuario en el navegador.
Recibe el `Model` actual y devuelve un `Html Msg` (el tipo que usa Elm para representar HTML).
Cada elemento HTML (por ejemplo, `<div>`) tiene una función de Elm correspondiente (`Html.div`) en el paquete `Html`.
Cada una de estas funciones recibe dos parámetros: el primero es un array de atributos (de los paquetes `Html.Attributes` y `Html.Events`) y el segundo es un array de elementos hijos (funciones del paquete `Html`).
También hay una función `text` que representa contenido de texto HTML, la cual solo recibe un parámetro de tipo string, pero por lo demás se usa igual que todas las demás funciones y elementos del paquete `Html`.

La función `view` puede indicar que ciertos eventos, como hacer clic en un botón o editar el texto de un cuadro de texto, provoquen la creación de un `Msg`, que Elm Runtime usará para llamar a la función `update`, modificar el `Model` y generar el HTML actualizado.
En el código siguiente esto ocurre con `Html.Events.onInput TextChanged`.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

`Html.Events.onInput` espera que se le pase una función (`String -> Msg`) que usará para crear el `Msg`.
Los distintos eventos esperan distintas funciones en función de la información que pueden proporcionar, así que, por ejemplo, `Html.Events.onCheck` (para casillas de verificación) espera `Bool -> Msg` y `Html.Events.onClick` solo espera un `Msg`.

El lenguaje Elm es puro y funcional y no es posible la mutación, así que Elm Runtime se encarga de todo lo que cambia.
Puedes ver todos los distintos [elementos HTML][html-elements], [atributos de elementos][element-attributes] y [eventos HTML][html-events] en el registro de paquetes de Elm.

Hay 4 «niveles» de aplicaciones web que puedes escribir en Elm, que son cada vez más potentes y más complicados (aunque Elm sigue siendo un lenguaje y un ecosistema encantadoramente sencillos).
Todos ellos están definidos en el [paquete Browser][browser-package]:

- [sandbox][browser-sandbox]: reacciona a la entrada del usuario, como botones y casillas de verificación
- [element][browser-element]: habla con el mundo exterior, mediante HTTP e interoperabilidad con JavaScript
- [document][browser-document]: controla el `<title>` y el `<body>` de una página web
- [application][browser-application]: crea aplicaciones de página única completas que gestionan el enrutado y los cambios de URL

Este concepto usa [sandbox][browser-sandbox], ya que es el más sencillo (y, puesto que es un sandbox, resulta relativamente fácil trabajar con el editor en línea de Exercism).
El módulo de entrada de un programa en Elm debe llamarse `Main`, y la función que crea la aplicación debe llamarse `main`, como se muestra a continuación.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

Ya hemos visto las funciones `update` y `view`, y [sandbox][browser-sandbox] requiere además una función `init` que devuelva el estado inicial del `Model`.
