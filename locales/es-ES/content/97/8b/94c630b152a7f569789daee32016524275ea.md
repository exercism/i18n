# Introducción

En C++, las declaraciones suelen estar separadas de las definiciones.
Las declaraciones se agrupan en los llamados ficheros de cabecera, y las implementaciones correspondientes se colocan en ficheros de código fuente.
Puedes pensar en los ficheros de cabecera como una API.
El fichero de cabecera te dice _qué_ ofrece una base de código sin entrar en los detalles de _cómo_.

## Ficheros de cabecera y de código fuente

La extensión de fichero más común para los ficheros de cabecera es `.h`.
Algunos proyectos usan `.hpp` o prescinden por completo de la extensión.

Las definiciones se encuentran en un fichero `.cpp` aparte.
Para reunir las partes, el fichero de código fuente empieza _incluyendo_ el fichero de cabecera correspondiente.

Si quieres escribir una biblioteca llamada «quick_math» que ofrezca una función «super_root» que quieras usar a menudo, los ficheros tendrían este aspecto:

```cpp
// A file named quick_math.h
#pragma once

namespace quick_math {

double super_root(double x, int n);

}  // namespace quick_math
```

```cpp
// A file named quick_math.cpp
#include <cmath>

#include "quick_math.h"

double quick_math::super_root(double x, int n) {
    while (n) {
        x = std::sqrt(x), --n;
    }
    return x;
}
```

Si necesitas incluir un fichero de cabecera que solo requiere la implementación, la línea `#include` correspondiente solo hace falta en el fichero de código fuente.
Todo lo que se incluye en el fichero de cabecera también está disponible en el fichero `.cpp`, como la biblioteca `string` del ejemplo siguiente.
**Atención**: el `;` es necesario después de la declaración en el fichero de cabecera, pero no después de la definición en el fichero de código fuente.

~~~~exercism/note
Muchos ejercicios de C++ en Exercism empiezan con dos ficheros casi vacíos: uno de cabecera y otro de código fuente.
Tienes que consultar el fichero `*_test.cpp` para ver los nombres y los espacios de nombres de las funciones esperadas y poder resolver el ejercicio.

## Clases y ficheros de cabecera

Las clases pueden volverse muy complejas, y su relación con la división entre cabecera y código fuente puede resultar confusa.
Una distribución posible consiste en mantener todos los detalles de implementación en el fichero de código fuente y todas las declaraciones y variables miembro en el fichero de cabecera:

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0);
    void give_water();
    std::string get_name();
    int get_size();
    void start_next_day();
};

}  // namespace robots

#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"

robots::Flower::Flower(std::string name, int size) {
    this->name = "Robotica " + name;
    this->size = size;
}

void robots::Flower::start_next_day() {
    if (!needs_water) {
        ++size;
    }
    needs_water = true;
}

std::string robots::Flower::get_name() { return name; }

int robots::Flower::get_size() { return size; }
```

Cuando el fichero de cabecera se usa como resumen de la API, es ahí donde uno buscaría información como los valores por defecto.
El valor por defecto del parámetro `size` del constructor se gestiona, por tanto, en el fichero de cabecera y no en la implementación.
Las definiciones del fichero de código fuente llevan delante el espacio de nombres `robots` y el tipo de clase `Flower`.

Otra opción de distribución es una biblioteca _solo de cabecera_, que no tiene ningún fichero `.cpp`:

```cpp
// A file named robot_flower.h
#pragma once

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0) {
        this->name = "Robotica " + name;
        this->size = size;
    }
    void give_water() { needs_water = false; }
    std::string get_name() { return name; }
    int get_size() { return size; }
    void start_next_day() {
        if (!needs_water) {
            ++size;
        }
        needs_water = true;
    }
};

}  // namespace robots
```

Los proyectos pueden usar combinaciones de estas distribuciones, y hay mucho debate sobre cuál puede encajar mejor en cada caso de uso.

## Guardas de inclusión

Es posible que hayas visto la línea `#pragma once` en el fichero de cabecera del ejemplo anterior.
Esto se llama guarda de inclusión, y garantiza que el contenido del fichero se incluya una sola vez durante la compilación para evitar errores.
Existe otra variante más compleja de guarda de inclusión que empieza por `#ifndef` y termina con `#endif`.
Cumple la misma función y su uso se muestra en el ejemplo de la clase `Flower` de arriba.
