# Acerca de

Preparar un valor para transmitirlo implica tres cosas a la vez:
serializarlo, seleccionar la parte adecuada y no copiar cuando no
hace falta. Tres construcciones idiomáticas de Factor cubren ese
terreno.

## `unparse`: de valor a código fuente

[`unparse`][unparse] (en `prettyprint`) devuelve el texto en forma
de código fuente de cualquier valor. Es lo contrario del analizador
sintáctico: el ida y vuelta `dup unparse parse` reconstruye el valor.

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

Compáralo con `>string` (que solo funciona con secuencias de
caracteres) y `number>string` (solo con números). `unparse` es el
universal, a costa de producir sintaxis de Factor (los string
entrecomillados conservan sus comillas), así que es la herramienta
adecuada cuando quien recibe el texto va a volver a analizarlo, y la
herramienta equivocada para una salida legible para las personas.

## Slices: vistas, no copias

| palabra       | efecto                                          |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )`: copia los primeros n     |
| `head-slice`  | `( seq n -- slice )`: vista de los primeros n   |
| `tail`        | `( seq n -- newseq )`: copia a partir del índice n |
| `tail-slice`  | `( seq n -- slice )`: vista a partir del índice n |
| `head*`       | `( seq n -- newseq )`: copia todo menos los últimos n |
| `head-slice*` | `( seq n -- slice )`: vista de todo menos los últimos n |
| `tail*`       | `( seq n -- newseq )`: copia los últimos n      |
| `tail-slice*` | `( seq n -- slice )`: vista de los últimos n    |

Un `slice` es una tupla que contiene un índice inicial, un índice
final y la secuencia subyacente. Implementa el [protocolo de
secuencias][sequence-protocol], así que cualquier operación de
secuencia funciona con él. Recurre a las variantes de `slice` cuando,
de otro modo, solo reservarías memoria para leer; recurre a las que
copian cuando necesites conservar los datos aunque la secuencia
subyacente cambie.

## Cleave con varias entradas: `2bi`, `3bi`, `2tri`, `3tri`

Las palabras `cleave` simples, `bi` y `tri`, aplican dos o tres
quotations a *una* entrada de la pila. Las variantes con prefijo `2`
y `3` aplican cada quotation a *dos* o *tres* entradas:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

Cada quotation recibe *todas* las entradas, así que usa `2bi` cuando
las dos proyecciones dependan del par, no cuando quieras aplicar la
misma proyección a cada entrada por separado (eso es `bi@`).

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

Para aplicar *una* sola quotation a cada entrada por separado, usa
`bi@` (dos entradas) o `tri@` (tres entradas): la misma familia, otra
forma.
