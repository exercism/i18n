# Combinación de iteradores

Un bucle puede llamar a más de un iterador. A cada uno se le pide su siguiente valor
una vez por turno, y avanzan juntos.

```sather
   loop
      first ::= violin_one.elt!;
      second ::= violin_two.elt!;
      #OUT + first + " against " + second + "\n";
   end;
```

Eso recorre ambos arrays a la par: el primer elemento con el primer elemento,
el segundo con el segundo.

## La regla que sorprende a todo el mundo

**El bucle termina en cuanto se agota el *primero* de sus iteradores.**

No cuando se agota el último. Ni cuando se han agotado todos. El primero.

Así que si `violin_one` contiene cuatro compases y `violin_two` contiene dos, el bucle
de arriba se ejecuta **dos veces**. Los compases tercero y cuarto de la primera parte nunca
llegan a mirarse, porque para entonces la segunda parte ya no tiene nada que ofrecer.

Normalmente eso es justo lo que se quiere, porque emparejar cosas solo tiene sentido
mientras haya parejas, pero hay que saberlo de antemano en lugar de descubrirlo.

## Contar a la par

Un iterador que nunca se agota es útil precisamente por esa regla.
`up!` cuenta para siempre:

```sather
1.up!        -- 1, 2, 3, 4, ... and never ends
```

Por sí solo, crearía un bucle infinito. Emparejado con uno que sí termina, numera
los valores sin decidir nunca hasta dónde contar:

```sather
   loop
      number ::= 1.up!;
      bar ::= part.elt!;
      #OUT + "Bar " + number + ": " + bar + "\n";
   end;
```

`part.elt!` termina el bucle; `1.up!` aporta la numeración. Ninguno de los dos tiene que
saber cuánto dura la parte.

## El orden no importa

A todos los iteradores se les pide una vez por turno, así que da igual cuál
se escriba primero. Lo que importa es que a cada uno se le pida exactamente una vez: escribir
`part.elt!` dos veces en un mismo turno obtiene dos valores en lugar de uno.
