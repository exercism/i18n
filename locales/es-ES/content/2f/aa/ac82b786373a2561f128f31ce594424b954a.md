# Introducción

A menudo resulta útil definir tipos personalizados en nuestros programas.

Crear nuevos tipos primitivos es posible, pero rara vez se hace.
Los tipos primitivos integrados no son una elección arbitraria: se corresponden estrechamente con los tipos estándar del compilador LLVM que Julia usa para la compilación JIT.

Mucho más útil es la capacidad de definir tipos compuestos, con campos con nombre.

Otros lenguajes tienen algo similar, y los llaman `structs` o `records`.
La documentación de Julia se refiere a ellos como `composite types`, aunque (con una ligera discrepancia) la sintaxis del lenguaje los define con la palabra clave `struct`.

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

Vale la pena señalar algunos puntos en el ejemplo anterior:

- No se especifica ningún tipo para `id`, por lo que el compilador lo interpreta como `id::Any`.
- El nombre del tipo se usa como constructor, como en `Person(id, name, age)`, para dar una instancia del tipo `Person`.
- Se puede acceder a cada campo individual con notación de punto, igual que con las tuplas con nombre.

Los elementos de tipo `Person` son inmutables, así que no se permiten actualizaciones.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

Si es necesaria la mutabilidad, añade `mutable` a la definición.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

El constructor, por defecto, requiere que los campos aparezcan en el mismo orden que en la definición, lo que resulta incómodo para tipos más complicados.

Usar la macro `@kwdef` permite dos capacidades nuevas:

- El constructor usa palabras clave, no posiciones.
- Los campos pueden tener valores predeterminados y, opcionalmente, se pueden omitir del constructor.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## Jerarquías de tipos compuestos

Hasta ahora, solo hemos creado tipos compuestos concretos.
Si lo compruebas, todos son subtipos de `Any`.

Al crear varios tipos relacionados, probablemente tenga más sentido definir una jerarquía para ellos.
Esto se hace con mucha facilidad.

Primero, crea un tipo abstracto:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

A continuación, incluye un operador `<:` en una definición de tipo para mostrar la relación.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

Repite según sea necesario, recordando que no se permite el subtipado de tipos concretos.

Para una jerarquía más compleja, crea subtipos abstractos según sea necesario.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

El valor de una jerarquía así quedará más claro cuando lleguemos al concepto `Multiple Dispatch` y veamos cómo las funciones manejan los tipos de los argumentos.
