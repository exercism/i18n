# Guía de contribución

Si quieres participar en el desarrollo del track de Pharo, sigue las instrucciones que aparecen a continuación; te ayudarán a empezar.

¡Nos encanta mejorar este track y mostrar a los desarrolladores otra forma de pensar sobre la programación! :tada:

Lee cómo [participar en un track de Exercism](https://github.com/exercism/docs/tree/master/contributing-to-language-tracks) y asegúrate también de leer el [Código de Conducta de Exercism](https://exercism.io/code-of-conduct).

Aceptamos pull requests de todo tipo. Ninguna contribución es demasiado pequeña, sobre todo las que aportan correcciones y mejoras a ejercicios existentes. Ten en cuenta que los ejercicios de este track deben cumplir los [estándares comunes de Exercism](https://github.com/exercism/docs/tree/master/language-tracks/exercises), pero si no tienes claro cómo hacer un cambio, abre una issue en GitHub y lo comentamos.

>__Nota__: La organización de Exercism ha decidido [pausar las contribuciones de la comunidad en general a Exercism](https://exercism.org/blog/freeing-our-maintainers). El track de Pharo queda excluido de esta política, ya que nuestra comunidad es bastante pequeña (en otras palabras: cualquier colaborador del track de Pharo puede seguir creando issues y enviando PRs).

## Conocimientos previos

Se da por hecho que ya estás [familiarizado](./docs/RESOURCES.md) con el desarrollo en Pharo y con su uso de [Iceberg Git](https://github.com/pharo-vcs/iceberg).

## Configuración del entorno de desarrollo

Para empezar, asegúrate de tener un entorno de desarrollo completo de Exercism y de tener instalados los siguientes elementos:

### __Imagen de Pharo y IDE__

Necesitas un entorno de desarrollo de Pharo (una imagen de Pharo en ejecución, el IDE) para crear los ejemplos de código reales.

1. Usa [PharoLauncher](https://pharo.org/download) para crear una imagen de desarrollo estable y nueva a partir de la categoría `Official distributions` (a fecha de 05/24, la imagen estable es: Pharo 12.0 - 64bit (stable)) y lánzala (también puedes usar [zerconf](https://get.pharo.org/) si estás familiarizado con él).
2. Lanza tu imagen para comprobar que todo funciona correctamente.

> __Nota__: Si tienes algún problema de TIMEOUT, consulta las [instrucciones de instalación para usuarios](./docs/INSTALLATION.md).

### __Configuración de los repositorios de git__

1. Si no lo has hecho antes, haz un fork de `https://exercism/pharo-smalltalk` en GitHub.
2. Para clonar tu fork, evalúa el siguiente comando en el Playground de la imagen de Pharo en ejecución:
```
Metacello new
 baseline: 'Exercism';
 repository: 'github://exercism/pharo-smalltalk:main/releases/latest';
 load: 'dev'
```
Esto clonará el repositorio git del track de Pharo y cargará el código fuente del track en la imagen de Pharo, su baseline de desarrollo. La carpeta local con el repositorio clonado se encontrará en (según tus preferencias de Iceberg): `<path-to-Pharo-image>/pharo-local/iceberg/<your-id/pharo-smalltalk`.
> __Nota__: Las fuentes de la imagen de Pharo se sincronizan y serializan en archivos `*.st` ubicados en la subcarpeta `src` del directorio mencionado.

2. Otra forma de hacer lo mismo es clonar tu fork mediante la línea de comandos: `git clone https://github.com/<your id>/pharo-smalltalk` como proyecto de GitHub e indicar `<your id>` como nombre del propietario y `pharo-smalltalk` como nombre del proyecto.
A continuación, instala la baseline `dev` de Metacello (no la predeterminada) en Iceberg usando el menú contextual de Metacello de la imagen de Pharo en ejecución (por ejemplo, haz clic con el botón derecho en el proyecto «pharo-smalltalk» que acabas de clonar, selecciona la segunda opción del menú de Metacello y escribe `dev`).

3. Después de cargar el proyecto en la imagen de Pharo, no olvides __guardar la imagen__ con los cambios (elemento de menú Pharo -> Save).

__Repositorios opcionales__
1. Como alternativa, puedes hacer `git clone https://github.com/exercism/pharo-smalltalk` como repositorio de preparación en el que generarás ejercicios y recursos para subirlos (de forma independiente a la programación en Pharo). Ten en cuenta que los cambios que genere la herramienta Configlet en este repositorio tendrás que copiarlos a tu repositorio fork local. Se sugiere usar algo como `~/development/exercism/pharo-staging` para evitar confusiones (nota: puede estar en cualquier sitio). Este repositorio no es necesario; puedes seguir generando los cambios de configlet directamente en tu repositorio fork (que está sincronizado con tu imagen de Pharo), si tienes claro qué cambios incluir en el commit.
2. También puedes clonar las [especificaciones de problemas](https://github.com/exercism/problem-specifications) de Exercism, por si quieres trabajar en ejercicios de práctica desde cero. Colócalo también en un subdirectorio del espacio de trabajo de exercism que se configura más abajo (este repositorio se usa para generar los archivos readme.md de los ejercicios y sirve de referencia para las pruebas sugeridas).

### __Nota sobre las ramas del repositorio utilizadas__

La rama `main` es la rama principal de desarrollo, en la que se fusiona todo. Si trabajas en algún cambio de código, crea una rama de funcionalidad a partir de main y confirma allí tus cambios. Cuando termines, abre una PR en GitHub para fusionarla en `main` del repositorio base (Exercism/pharo-smalltalk). Esta rama antes se llamaba `master`, __ahora obsoleta__.

### __Configuración de las herramientas de línea de comandos de Exercism__

Estas herramientas son necesarias para interactuar con el proyecto Exercism:
1. la [interfaz de línea de comandos de exercism](https://exercism.io/cli-walkthrough), configurada con el directorio de desarrollo de ejercicios de Exercism llamado workspace (por ejemplo, `exercism configure -w ~/development/exercism`). Puede ser la ruta a tu repositorio fork local o (opcionalmente) al repositorio de preparación.
2. el linter/generador [configlet](https://github.com/exercism/configlet#usage) de Exercism, para generar los metadatos de los ejercicios y ejecutar las validaciones. Para instalar Configlet, sigue las instrucciones del apartado [Cómo usarlo en tu track](https://github.com/exercism/configlet#use-in-your-track) (consulta bin/fetch-configlet).

## Trabajar en los ejercicios de Exercism

La organización de Exercism distingue entre ejercicios de concepto (que explican teoría de lenguajes de programación) y ejercicios de práctica. Los siguientes apartados se centran, por ahora, solo en la contribución de ejercicios de práctica.

### __Descripción general__

Pasos para completar un ejercicio:
1a. Crear un ejercicio de práctica desde cero (a partir de las especificaciones de problemas).
1b. Trabajar en la solución de un ejercicio de práctica existente.
2a. Generar en un directorio los archivos de código serializados de la solución del ejercicio y generar los metadatos del ejercicio.
2b. Ajustar la baseline del proyecto para incluir el ejercicio recién completado como parte del proyecto.
3. Confirmar los cambios en tu repositorio fork y publicarlos abriendo una PR.

#### TLDR: Guía rápida para generar y exportar un ejercicio de práctica
En resumen: todo lo que necesitas es generar y exportar el ejercicio desde Pharo; ejecuta esto en el Playground:
```Smalltalk
"Obtain exercise from problem specification"
ExercismExerciseGenerator new generateExerciseFrom: 'path-to-problem-specifications/exercises/slug-name' asFileReference.

"Update exercise version within Pharo image  (with updated test cases) to output exercise directory (once you have solution class defined)"
ExercismGenerator new 
	exercisesDirReference: 'path-to-local-repository/exercises/practice' asFileReference;
	generateForExercise: 'slug-name'.
```
  > __Nota__: Encontrarás más detalles en los pasos siguientes.

![Flujo de trabajo para completar un ejercicio de práctica](/docs/images/overview-exercism-pharo-contribution.svg)

### __1. Crear un nuevo ejercicio de práctica__
*TLDR: Todos los detalles y la descripción de la API relacionados con la generación de ejercicios están en el comentario de clase de la clase `ExercismExerciseGenerator`.*  

__Ejercicios nuevos a partir del repositorio de problemas__
- Si quieres empezar un ejercicio de práctica completamente nuevo (paso 1a.), puedes usar el repositorio de especificaciones de problemas y generar la clase de pruebas del ejercicio en cuestión ejecutando:
`ExercismExerciseGenerator generateFrom: <path-to-problem-specifications/exercises>`, lo que generará las clases de pruebas de todos los ejercicios del repositorio de especificaciones de problemas en el paquete `ExerciseWIP`.  

  > __Nota__: Puedes usar el elemento de menú de la imagen de Pharo para conseguir lo mismo (menú World -> Exercism -> Generate test cases).
- Más concretamente, puedes generar la clase de pruebas de un ejercicio concreto con: `ExercismExerciseGenerator generateExerciseFrom: '<path-to-problem-specifications/exercises/slug-name>' asFileReference`.

El resultado de la instrucción anterior será una nueva clase de pruebas `<SlugNameTest>` (una subclase de ExercismTest) con los métodos de prueba generados en el paquete `ExerciseWIP`.

__Regenerar un ejercicio existente a partir del repositorio de problemas__
Si quieres regenerar los métodos de prueba de un ejercicio existente (ya definido en el paquete de la solución, por ejemplo `Exercise@TwoFer`), puedes usar el siguiente código. Ten en cuenta que los demás métodos no se tocarán (por ejemplo, uuid, version, etc.)

 `ExercismExerciseGenerator new regenerateExerciseFrom: 'path-to-problem-specifications/exercises/exercise-slug' asFileReference`

__Desde cero__  
Si tienes una idea interesante, consulta la documentación sobre cómo añadir nuevos ejercicios.

En el proyecto hay un ejemplo de ejercicio definido por el usuario, consulta `DieTest`. Si sobrescribes el método customData, el generador creará los archivos correspondientes por ti.

Ten en cuenta que:
- Cada ejercicio debe ser independiente. No hagas referencia a archivos que estén fuera del directorio del ejercicio, porque no se incluirán cuando el usuario descargue el ejercicio.
- Los ejercicios deben cumplir los [estándares comunes de Exercism](https://exercism.org/docs/building/tracks/practice-exercises).
- Los ejercicios solo deben usar las bibliotecas principales de Pharo.
- Cada ejercicio debe:
  - estar almacenado en un proyecto de nivel superior llamado `Exercism@<ExerciseName>`
  - tener un TestCase llamado `<ExerciseName>Test` (en CamelCase) y una solución de ejemplo llamada `<ExerciseName>`
  - el TestCase debe tener un comentario de clase en formato markdown que describa el ejercicio. Este texto también se usa para generar un archivo README.md.
- No hagas commit de archivos de configuración ni directorios dentro del ejercicio (esto puede revisarse para futuros ejercicios; avísanos si se convierte en un problema).
- Asegúrate de generar un nuevo UUID para el ejercicio con `UUIDGenerator next` y de colocar ese valor en el método `uuid` de la prueba.

> __Nota__: Lamentablemente, el generador de UUID actual de Pharo no cumple la RFC 4122, versión 4. Por lo tanto, el UUID que se use debe ser el generado por configlet, ejecutando: `/bin/configlet uuid`

### __2. Trabajar en un ejercicio existente__

Aunque hay muchas formas de ayudar, de lejos la contribución más fácil y útil es completar la solución de cualquiera de los ejercicios que están «abiertos» en este momento.

  * Asegúrate de que tu imagen esté actualizada con la rama main de exercism/pharo-smalltalk (y sube cualquier cambio a tu fork).

  * Los ejercicios son todos TestCases generados automáticamente a partir del repositorio de especificaciones de problemas mencionado antes. Los encontrarás como subclases de ExercismTest en el paquete ExercismWIP. Ten en cuenta que un ExercismTest regenerado puede que ya esté en el paquete del ejercicio en cuestión, si la solución ya estaba lista. El paquete ExercismWIP se usa para los ejercicios nuevos o en curso que todavía no se han desplegado junto con la clase de la solución.

  * Cuando hayas elegido un ejercicio en el que quieras trabajar, crea una issue en GitHub indicando «Convert Exercise <name>». Así los demás sabrán que estás trabajando en él y también te servirá de base para tu pull request posterior.

  * Cada ejercicio en curso ya tiene la descripción del problema en su comentario de clase; ejecuta sus pruebas y desarrolla una solución con TDD (en el depurador si ejecutas la primera prueba por sí sola).

  * Puede que tengas que __ajustar la prueba si no es Smalltalk idiomático__ (nuestro generador es bastante básico; dicho esto, algunas correcciones podrían ser apropiadas como PRs al texto de las [especificaciones de problemas](https://github.com/exercism/problem-specifications) originales).

  * Actualiza los metadatos del ejercicio en el lado de clase del ejercicio sobrescribiendo el método #exercise y rellenando la dificultad, los temas, etc. También deberías rellenar algo de texto de pista en la pestaña de comentario de la prueba (en la parte inferior, sustituyendo el texto TBD).

  * Actualiza el paquete del ejemplo elegido a `Exercise@<ExerciseName>` (es decir, sácalo del paquete WIP): paso 1b.
  * Crea una rama nueva en Iceberg con el nombre del ejercicio que hayas elegido (puedes usar la herramienta Iceberg para esto e introducir el número de issue de antes).
  * Antes de enviar tu pull request, ejecuta todas las pruebas de los ejercicios de Pharo y asegúrate de que __todas pasan__.

### Pruebas

En esencia, Exercism gira en torno a las pruebas y a probar con [suites de pruebas](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md).

Los ejercicios de exercism en Pharo están organizados en subpaquetes, cada uno de los cuales contiene un TestCase que debe ser compatible con [SUunit](https://en.wikipedia.org/wiki/SUnit). Esta es la biblioteca xUnit original y no se necesitan frameworks de terceros adicionales para los ejercicios.

Para probar un ejercicio, ejecútalo desde el ejecutor de pruebas integrado haciendo clic en el orbe de prueba. El orbe se pondrá verde si las pruebas se completan con éxito, o naranja o rojo si hay fallos o errores, respectivamente. Como alternativa, puedes ejecutar las pruebas manualmente en el playground evaluando:

```smalltalk
<ExerciseName>Test suite run. "single exercise"

AllExercismTests suite run. "all exercises"
```
> __Nota:__ Si quieres definir tu propio caso de prueba (no generado), puedes ponerlo en el protocolo `extra` de la clase de prueba.
Por coherencia, usamos este orden de parámetros en los métodos de prueba: `self assert: actual equals: expected`.

Para probar en una imagen que no sea de desarrollo, debes seguir los [pasos de instalación para usuarios](./docs/INSTALLATION.md). Si
usas esa imagen para probar baselines de desarrollo posteriores, puede que tengas que eliminar los siguientes directorios de desarrollo para asegurarte de obtener el código más reciente:
`./pharo/pharo-local/iceberg, ./pharo/pharo-local/package-cache`

### __3. Publicar un ejercicio completado__

Ahora que ya has terminado la solución y has hecho commit en tu rama de funcionalidad local, deberías completar estos pasos:  
#### Generar el código fuente del ejercicio
Esto se refiere al paso 2a: __generar los archivos de código fuente__ de la solución y de la clase o clases de prueba.

__Generar los códigos fuente de salida de todos los ejercicios__ 
- `ExercismGenerator generate` -> esto generará todos los archivos de código fuente de todos los ejercicios. Ejecutará el comando `generate` de configlet y también regenerará `config.json`, que lista todos los ejercicios válidos. (O en el menú World elige: «Exercism» -> «Regenerate meta data»)

#### Generar los códigos fuente de salida de un ejercicio concreto
- Para usar el directorio predeterminado (`repository-root/exercises/practice`):
```
ExercismGenerator new generateForExercise: 'slug-name'
```

Cuando necesites exportar a un directorio de ejercicio concreto:
```
ExercismGenerator new 
	exercisesDirReference: 'path-to-exercises/practice' asFileReference;
	generateForExercise: 'slug-name'
```

> __Notas__: 
  - ExercismGenerator actualizará el archivo config.json principal automáticamente (lo creará si no existe).
  - sincronizará todos los documentos, metadatos y rutas de archivo del ejercicio o ejercicios indicados usando el comando configlet. Consulta los detalles: [Cómo usar sync al añadir un nuevo ejercicio](https://github.com/exercism/configlet#using-sync-when-adding-a-new-exercise-to-a-track)

#### Actualizar la baseline del proyecto Pharo-smalltalk
Paso 2b: actualiza la baseline del proyecto Pharo-smalltalk añadiendo el nombre del ejercicio a la lista del método `BaselineOfExercism>>exercisePackageNames`. Así te asegurarás de que tu ejercicio se cargue cuando el proyecto se cargue, incluyendo el nuevo ejercicio, mediante el comando de Metacello.
  
#### Enviar una pull request
Paso 3: antes de crear la PR, comprueba que los artefactos de Exercism son correctos ejecutando este comando de la línea de comandos:
`bin/configlet lint` (la automatización de CI ejecutará el linting de todos modos cuando se envíe la PR).  
Si todo está bien, ya puedes crear la PR:
- sube tu rama a tu fork y crea una pull request en `exercism/pharo-Smalltalk` 

> __Detalles finales__: 

- Es importante [permitir que los maintainers editen](https://help.github.com/en/articles/allowing-changes-to-a-pull-request-branch-created-from-a-fork) tu rama, para que podamos colaborar contigo en ella.
-  Las pull requests deben centrarse en un solo ejercicio, issue o cambio conceptualmente coherente. Consulta las [directrices de pull requests](https://github.com/exercism/docs/tree/main/building/github#guides) de Exercism para más detalles.
- Sigue tu PR y responde a cualquier pregunta que surja.
- Por último, envía los ajustes que hagan falta y un maintainer fusionará tu pull request para que la solución final aparezca en el sitio.

## Información adicional para maintainers

### Estilo de código

El código de este repositorio debe seguir las convenciones de [Pharo with style](https://github.com/SquareBracketAssociates/Booklet-PharoWithStyle) siempre que sea posible. También puedes consultar el más genérico [Smalltalk with style](http://sdmeta.gforge.inria.fr/FreeBooks/WithStyle/SmalltalkWithStyle.pdf).

También deberías usar el formateador de código integrado (meta-t FO en el editor) cuando crees ejercicios, así como las críticas de código.

### Cambios importantes

Si tienes previsto hacer cambios importantes o que rompan la compatibilidad, abre una issue para que podamos comentarlo antes de fusionarla. Si el tema afecta a algo más que al track de Pharo, abre también una issue en [exercism/discussions](https://github.com/exercism/discussions/issues).
