# Introduction

## Strings

### Characters

Una **codificación de caracteres** es una convención específica que se usa para representar elementos de texto de un lenguaje natural como una secuencia de bytes.
Un «elemento de texto» aquí puede ser cualquier unidad que tenga significado en un lenguaje natural, por ejemplo, letras, espacios, signos de puntuación, emojis, ideogramas, etc.

NASM (The Netwide Assembler, el ensamblador que usa esta pista) tiene soporte para definir datos usando **ASCII**.

Las constantes de caracteres en NASM pueden tener hasta 8 bytes de longitud y pueden definirse con comillas simples (`'`), comillas dobles (`"`) o comillas invertidas (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Los caracteres especiales deben definirse entre comillas invertidas y escaparse con `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Ten en cuenta que x86-64 no tiene soporte integrado para ninguna codificación de caracteres como tipo distinto.
Los datos en ensamblador son una secuencia de bytes, y la interpretación de esos bytes como un carácter, un número o cualquier otra cosa queda a cargo del programador.

Por ejemplo, el carácter ASCII '0' es un único byte con el valor 48.
Así que almacenar 48 en un byte es exactamente lo mismo que almacenar el carácter ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Por esta misma razón, para manipular caracteres se transforman directamente los valores de esos bytes:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### Strings

Una **cadena de caracteres** es una secuencia de caracteres.
En ensamblador, normalmente se implementa como un array.

Es posible declarar un string en NASM de la misma forma en que se declararía cualquier array:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Una diferencia entre los strings y otros arrays es que NASM también permite declarar strings sin una coma (`,`) que separe los valores.
También es posible intercalar valores con comas:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Ten en cuenta que, como ya se ha mencionado, los caracteres son solo bytes (o una secuencia de bytes en la codificación Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Como cada carácter ASCII ocupa un único byte, cualquier byte posterior en un tamaño mayor es `0`.
Por ejemplo, declarar `'a'` como un qword (8 bytes) significa que el primer byte es `'a'` (`97`) y los otros siete bytes son todos `0`.

Por esta razón, todos estos son equivalentes:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
En ensamblador, los strings no terminan automáticamente con un carácter NUL de ASCII (valor `0`).

Al interactuar con lenguajes de más alto nivel, como C, es responsabilidad del programador asegurarse de que se añada el terminador correcto, si lo hay, al final de un string.
~~~~

### Instrucciones de string

Como los strings son arrays, puedes trabajar con ellos de la misma forma que con cualquier array, desreferenciando la memoria explícitamente:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Además de eso, hay algunas instrucciones para cargar, mover y almacenar valores en secuencias de bytes en memoria.
Aunque se las llama _instrucciones de string_, se pueden usar con cualquier secuencia de bytes en memoria, es decir, con cualquier array.

Las tres instrucciones de string más importantes son `lods`, `stos` y `movs`:

| instrucción | qué hace                                                                                                          |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | carga un valor desde una posición de memoria indicada por `rsi` en `rax`                                          |
| `stos`      | almacena un valor de `rax` en una posición de memoria indicada por `rdi`                                          |
| `movs`      | copia un valor desde una posición de memoria indicada por `rsi` y lo almacena en una posición de memoria indicada por `rdi` |

Ten en cuenta que esas instrucciones _no_ aceptan ningún operando explícito.
Sus operandos son implícitos.

Como regla general:

1. Cuando su operando de origen es una posición de memoria, su dirección debe almacenarse en `rsi` (`s` de *source*, origen).
2. Cuando su operando de destino es una posición de memoria, su dirección debe almacenarse en `rdi` (`d` de *destination*, destino).
3. Si uno de los operandos no es una posición de memoria, se trata del registro `rax`.

Ten en cuenta que esas instrucciones desreferencian automáticamente las direcciones de memoria según la operación concreta que realizan.

Todas ellas pueden operar con distintos tamaños.
Se añade un sufijo para indicar ese tamaño:

| sufijo | significado | tamaño  |
| :----: | ----------- | :------ |
|  `b`   | byte        | 1 byte  |
|  `w`   | word        | 2 bytes |
|  `d`   | dword       | 4 bytes |
|  `q`   | qword       | 8 bytes |

Por ejemplo:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

También actualizan cualquier dirección usada según el tamaño de la operación.
Esta actualización se hace según el valor del **indicador de dirección (DF)**:

- Si el `DF` está desactivado, las direcciones se _incrementan_ en el tamaño de la operación.
- Si el `DF` está activado, las direcciones en cambio se _decrementan_ en la misma cantidad.

La ABI de System V establece que el indicador de dirección debe estar desactivado al entrar en una función.
Por lo tanto, _el comportamiento predeterminado es que la memoria se lea o escriba en orden ascendente de direcciones_.

La instrucción `cld` puede usarse para desactivar el indicador de dirección, mientras que la instrucción `std`, para activarlo:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Quien llama espera que el `DF` esté desactivado después de que retorne cualquier función llamada, según la ABI de System V.
Si en algún momento activas el `DF`, asegúrate de desactivarlo antes de `ret`.
~~~~

#### Rep

Aparte de esas, la instrucción **rep** no interactúa directamente con la memoria.
En su lugar, puede añadirse como prefijo a las otras instrucciones mencionadas, _repitiendo_ esas instrucciones.

Cuando se les añade el prefijo `rep`, las instrucciones de string se repiten un número de veces igual al valor de `rcx`.
Cada vez, el valor de `rcx` se decrementa en `1`.
Ten en cuenta que el valor de `rcx` debe establecerse antes de usar la instrucción:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
En las CPU modernas, `rep movs` y `rep stos` suelen ser opciones rápidas al mover datos en bloques grandes.
Sin embargo, otras instrucciones de string, e incluso `movs` y `stos` cuando operan sin `rep`, suelen ser más lentas que un bucle simple.

Puedes encontrar una visión más detallada de este tema en [el capítulo 16.9, «String instructions», de este libro de referencia][agner-optimization-guide].
