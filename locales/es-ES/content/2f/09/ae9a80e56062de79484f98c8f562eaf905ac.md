# Acerca de

La construcción orientada a objetos principal en C# es la _clase_, que es una combinación de datos ([_campos_][fields]) y comportamiento ([_métodos_][methods]). Los campos y métodos de una clase se conocen como sus _miembros_.

Se puede restringir el acceso a los miembros mediante modificadores de acceso, siendo los dos más comunes:

- [`public`][public]: se puede acceder al miembro desde cualquier código (sin restricciones).
- [`private`][private]: solo se puede acceder al miembro desde código de la misma clase.

Es habitual especificar un modificador de acceso para todos los miembros. Si no se especifica ningún modificador de acceso, se usará `private` de forma predeterminada.

Esta agrupación de datos y comportamiento relacionados, junto con la restricción del acceso a los miembros, se conoce como [encapsulación][encapsulation], uno de los conceptos fundamentales de la orientación a objetos.

La combinación de los valores de los campos de un objeto en un momento dado se conoce como el [estado][object-state] del objeto.

Puedes pensar en una clase como una plantilla para crear instancias de esa clase. Para [crear una instancia de una clase][creating-objects] (también conocida como _objeto_), se usa la [palabra clave `new`][new]:

```csharp
class Car
{
}

// Create two car instances
var myCar = new Car();
var yourCar = new Car();
```

Los [campos][fields] tienen un tipo y se pueden definir en cualquier parte de una clase.
Los campos públicos se definen en [PascalCase][pascal-case] y los campos privados se definen en [camelCase][camel-case] y llevan un guion bajo `_` como prefijo:

```csharp
class Car
{
    // Accessible by anyone
    public int Weight;

    // Only accessible by code in this class
    private string _color;
}
```

Opcionalmente, se puede asignar un valor inicial a un campo. Si un campo _no_ especifica un valor inicial, se establecerá a su [valor predeterminado][default-values] del tipo. Se puede acceder a los valores de los campos de una instancia y actualizarlos usando la notación de punto.

```csharp
class Car
{
    // Will be set to specified value
    public int Weight = 2500;

    // Will be set to default value (0)
    public int Year;
}

var newCar = new Car();
newCar.Weight; // => 2500
newCar.Year;   // => 0

// Update value of the field
newCar.Year = 2018;
```

Los campos privados se suelen actualizar como efecto secundario de llamar a un método. Estos métodos normalmente no devuelven ningún valor, en cuyo caso el tipo devuelto debe ser [`void`][void]:

```csharp
class CarImporter
{
    private int _carsImported;

    public void ImportCars(int numberOfCars)
    {
        // Update private field
        _carsImported = _carsImported + numberOfCars;
    }
}
```

Ten en cuenta que no es habitual usar campos públicos en las clases de C#. O bien se usan campos privados, o bien otros tipos de miembros que se tratarán en ejercicios posteriores.

Dentro de una clase, la [palabra clave `this`][this] hace referencia a la clase actual. Esto es especialmente útil si un parámetro tiene el mismo nombre que un campo:

```csharp
class CarImporter
{
    private int carsImported;

    public void SetImportedCars(int carsImported)
    {
        // Update private field from public method
        this.carsImported = carsImported;
    }
}
```

La estructura de clases y métodos proporciona una forma natural de limitar la visibilidad de elementos del programa como campos y métodos, y de evitar el conocido [problema del estado global][so-global-state-problem]. Los campos, métodos y otros miembros públicos tienen que ir cualificados con el nombre del objeto, `object.field` o `object.method()`, (el nombre de la clase en el caso de los estáticos) para que el código fuera de la clase los vea. Las variables y parámetros declarados dentro de un método solo se pueden ver dentro de ese método.

Un detalle con el que hay que tener cuidado con este enfoque es que, si el nombre de un campo y el nombre de una variable o parámetro de un método son iguales, el código dentro del método ignorará el nombre del campo, lo cual puede que no sea lo que quieres. En general, deberías evitarlo siempre que sea posible, aunque es un patrón habitual en los constructores. Si es apropiado que el nombre del campo y el de la variable sean iguales, cualifica el nombre del campo con la palabra clave `this` dentro del método.

Estos [modificadores de acceso][access-modifiers] se pueden usar para limitar aún más la visibilidad.
