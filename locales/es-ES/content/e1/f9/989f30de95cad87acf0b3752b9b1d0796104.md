# Acerca de

El concepto [condicionales][conditionals-concept] presenta `jcc`, la familia de instrucciones para bifurcar según una condición.
Una `jcc` transfiere la ejecución a otro punto del programa solo si se cumple su condición.

Sin embargo, las CPU modernas son rápidas y capaces de ejecutar muchas instrucciones en paralelo.
Sería demasiado costoso detener todo el trabajo mientras la CPU espera una comprobación de la condición en tiempo de ejecución.

Por eso, internamente, la CPU no espera.
Usa un [predictor de bifurcaciones][branch-predictor] para adivinar el resultado de una condición y empieza a ejecutar _especulativamente_ la ruta prevista.

Si la predicción es correcta, la ejecución continúa como si no hubiera bifurcación.
Sin embargo, si la predicción es errónea, la CPU debe _descartar el trabajo realizado_ en la ruta prevista y reiniciar la ejecución en la correcta.

Esto se denomina **predicción incorrecta de bifurcación** y resulta caro, ya que conlleva un retraso.

Cuando una bifurcación es difícil de predecir, esas predicciones incorrectas se acumulan.
En esos casos, a veces es preferible evitar la bifurcación por completo, de modo que se ejecuten las mismas instrucciones independientemente de la condición.
El código que elige entre valores sin una `jcc` se denomina **código sin bifurcaciones**.

Hay varias formas de estructurar el código para que se bifurque con menos frecuencia, o para que las bifurcaciones que tenga sean más predecibles.
En particular, x86-64 ofrece dos familias de instrucciones que se suelen usar para escribir código sin bifurcaciones.

## Movimientos condicionales

La familia de instrucciones [cmovcc][cmov] copia el operando de origen en el destino solo si se cumple una condición concreta.
De lo contrario, el destino se deja sin cambios.

El sufijo `cc` sigue la misma nomenclatura que en `jcc`, con el mismo significado:

| instrucción | mueve si                                     |
|-------------|----------------------------------------------|
| `cmove`     | A == B después de `cmp A, B`                 |
| `cmovne`    | A != B después de `cmp A, B`                 |
| `cmovl`     | A < B (con signo) después de `cmp A, B`      |
| `cmovb`     | A < B (sin signo) después de `cmp A, B`      |
| `cmovg`     | A > B (con signo) después de `cmp A, B`      |
| `cmova`     | A > B (sin signo) después de `cmp A, B`      |

Las reglas son similares a las de `jcc`:

1. `l` y `g` se usan para comparaciones con signo; `b` y `a` se usan para comparaciones sin signo.
2. Añadir `e` a un sufijo incluye la igualdad.
3. Añadir `n` niega la condición.
4. También hay variantes que se refieren a si una bandera está activada.
   Por ejemplo, `cmovz` y `cmovc`.

Considera el valor absoluto de un entero con signo en `rdi`, devuelto en `rax`.
Escrita con `jcc`, la función elige una de dos rutas:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Escrita con `cmovcc`, se calculan incondicionalmente ambos valores candidatos y el movimiento condicional elige uno:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; if rdi >= 0, rax = rdi
                       ; otherwise rax stays = -rdi
    ; now rax = abs(rdi)
    ret
```

La versión sin bifurcaciones ejecuta siempre las mismas instrucciones.
No hay ninguna `jcc` que el predictor pueda adivinar.

El destino de una `cmovcc` debe ser un registro.
El origen puede ser un registro o una posición de memoria, pero no un inmediato.

~~~~exercism/note
En el código anterior, la instrucción `neg` activa varias banderas según el resultado, incluida la bandera de signo (SF).
Esto significa que el `cmp rdi, 0` se puede omitir por completo:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF = 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Para un `rdi` positivo, `neg` produce un resultado negativo y SF = 1, así que `cmovs` restaura `rdi`.
Para un `rdi` cero o negativo, `neg` produce un resultado no negativo y SF = 0, así que `rax` conserva el valor negado (que es el valor absoluto correcto).

Aunque `cmp` es la forma principal de comparar valores en código ensamblador, muchas instrucciones también activan banderas según su resultado.
La lista completa de banderas que afecta una instrucción suele aparecer en su [referencia][reference].
En el caso concreto de `neg`, son SF, ZF, CF, OF y PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

## Asignación condicional

La familia de instrucciones [setcc][set] asigna el valor `1` al operando de destino si se cumple una condición concreta, y el valor `0` en caso contrario.
El destino es siempre un _operando de 8 bits_.

El sufijo `cc` sigue la misma nomenclatura que en `jcc` y `cmovcc`.
Por ejemplo, `setz` asigna el valor `1` al destino si `ZF == 1`, y el valor `0` en caso contrario.

Como el destino es de 8 bits, es habitual que `setcc` vaya seguida de un `movzx` cuando se necesita un valor más ancho:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Esto es una construcción habitual para convertir el resultado de una comparación en un entero `0` o `1`.

## Cuándo usar código sin bifurcaciones

El código sin bifurcaciones no siempre es más rápido que el código con bifurcaciones.
Cuando una bifurcación es muy predecible, el predictor acierta casi siempre y una `jcc` no cuesta prácticamente nada.
El código sin bifurcaciones que sustituye a esa bifurcación es más lento, porque siempre ejecuta ambos cálculos candidatos.

Un contador de bucle es el ejemplo canónico.
Considera una función que suma `rsi` enteros de 64 bits a partir de `rdi`:

```x86asm
sum_array:
    xor rax, rax
.loop:
    add rax, [rdi]
    add rdi, 8
    dec rsi
    jnz .loop          ; taken on every iteration except the last
    ret
```

Este es exactamente el tipo de patrón que los predictores de bifurcaciones manejan bien, así que la bifurcación sale prácticamente gratis sin importar cuántos elementos procese `sum_array`.

El código sin bifurcaciones merece la pena cuando la bifurcación es difícil de predecir, o cuando se requiere un tiempo de ejecución constante independientemente de las entradas.
