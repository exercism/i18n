# Generadores de tests

El track de C# usa un [generador de tests](https://exercism.org/docs/building/tooling/test-generators) para autogenerar los tests de los ejercicios de práctica.
Se basa en que la mayoría de los ejercicios definidos en el [repositorio problem-specifications](https://github.com/exercism/problem-specifications/) también tienen un archivo `canonical-data.json`, que contiene entradas y salidas de test estandarizadas que se pueden usar para implementar el ejercicio.

## Pasos

Para generar los tests de un ejercicio de práctica, el generador de tests:

1. Lee los casos de test del ejercicio desde su archivo `canonical-data.json`
2. Usa el archivo `tests.toml` para omitir y excluir casos de test
3. Renderiza los casos de test usando la plantilla del generador del ejercicio
4. Formatea la plantilla renderizada usando Roslyn
5. Escribe la plantilla formateada en el archivo de tests del ejercicio

### Paso 1: leer el archivo `canonical-data.json`

El generador de tests analiza los casos de test del `canonical-data.json` del ejercicio usando el [espacio de nombres System.Text.Json](https://learn.microsoft.com/en-us/dotnet/api/system.text.json).

Como algunos datos canónicos usan anidamiento, el caso de test analizado incluye un campo `path` adicional que contiene las propiedades `description` de los elementos padre, así como la propiedad `description` del propio caso de test.

### Paso 2: omitir los tests excluidos del archivo `tests.toml`

Cada ejercicio tiene un archivo `tests.toml`, en el que se pueden excluir o deshabilitar tests individuales.
El generador de tests eliminará los casos de test que estén marcados como excluidos (`include = false`).

### Paso 3: renderizar los casos de test

Los casos de test (posiblemente transformados) se pasan entonces al archivo `.meta/Generator.tpl`, que define cómo deben renderizarse los tests a partir de esos casos de test.

### Paso 4: formatear la plantilla renderizada usando Roslyn

La plantilla renderizada se formatea entonces usando [Roslyn](https://github.com/dotnet/roslyn).
Esto tiene las siguientes ventajas:

- Los ejercicios tienen un formato consistente
- No tienes que preocuparte demasiado por los espacios en blanco y la alineación al escribir plantillas

### Paso 5: escribir la plantilla renderizada en el archivo de tests del ejercicio

Por último, la salida de la plantilla renderizada se escribe en el archivo de tests del ejercicio.

## Plantillas

Las plantillas se renderizan usando la [biblioteca Scriban](https://github.com/scriban/scriban/).

## Interfaz de línea de comandos

Hay dos formas de ejecutar el generador de tests:

1. `bin/update-tests.ps1`: actualiza los tests de todos los ejercicios que tengan una plantilla de generador
2. `bin/update-tests.ps1 -e <slug>`: actualiza los tests del ejercicio especificado, si tiene una plantilla de generador
