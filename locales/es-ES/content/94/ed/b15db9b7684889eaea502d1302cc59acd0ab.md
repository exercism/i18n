# Introducción

Elixir proporciona una construcción para rescatar errores usando `try .. rescue`

```elixir
try do
  raise RuntimeError, "error"
rescue
  e in RuntimeError -> :error
end
```

Vamos a examinar esta construcción:

- **Línea 1**, el bloque se declara con `try`.
- **Línea 2**, la llamada a función que puede dar error se coloca aquí; en este caso, estamos llamando a `raise/2`.
- **Línea 4**, en la sección `rescue`, hacemos coincidencia de patrones con el nombre del _módulo_ del error lanzado
  - en el lado izquierdo de `->`:
    - `e` se empareja con el struct de error.
    - `in` es una palabra clave.
    - `RuntimeError` es el error que queremos rescatar.
      - Si quisiéramos rescatar de todos los errores, podríamos usar `_` en lugar del nombre del módulo u omitir la palabra clave `in` por completo.
  - en el lado derecho:
    - las instrucciones que se ejecutarán si el error coincide.

## Structs de error

Los errores (a veces también llamados «excepciones») que rescatas de esta forma son structs.
Rescatar errores en Elixir es algo que se hace muy rara vez.
Normalmente, el error rescatado se registra o se envía a un servicio de monitorización externo, y luego se vuelve a lanzar.
Esto significa que normalmente no nos importa la estructura interna del struct de error concreto.

En el [concepto de excepciones][exercism-exceptions] aprenderás más sobre los structs de error, incluyendo cómo definir tu propio error personalizado.
