# Crear el ejecutor de pruebas

El ejecutor de pruebas es una herramienta esencial que permite:

- Que el sitio web compruebe automáticamente si una iteración pasa todas las pruebas.
- Que los estudiantes resuelvan ejercicios con el [editor del navegador](/docs/using/solving-exercises/using-the-online-editor) ([sin necesidad de usar la CLI](/docs/using/solving-exercises/working-locally)).

Para empezar a crear un ejecutor de pruebas, consulta el documento [Crear un ejecutor de pruebas desde cero](/docs/building/tooling/test-runners/creating-from-scratch).

## Implementación

Las herramientas de un track suelen estar escritas (en su mayor parte) en el lenguaje del track.

```exercism/caution
Aunque eres libre de usar otros lenguajes, cada lenguaje adicional hará más difícil mantener el track o contribuir a él.
Por eso recomendamos usar el lenguaje del track siempre que sea posible, porque hace que mantenerlo o contribuir a él resulte más fácil.
```

## Despliegue

El ejecutor de pruebas se empaqueta y se ejecuta como un [contenedor Docker](/docs/building/tooling/docker).
Las imágenes Docker de los ejecutores de pruebas se despliegan automáticamente mediante un [flujo de trabajo de GitHub Actions](https://github.com/exercism/generic-test-runner/blob/main/.github/workflows/docker.yml).

## Pruebas

Una vez que hayas creado un ejecutor de pruebas, puedes usar su imagen Docker en la configuración de CI de tu track para verificar los ejercicios del track.
El principal beneficio de este enfoque es que imita mejor el entorno de producción; en otras palabras, puedes tener más confianza en que todo también funciona en producción.
Una posible desventaja es que puede ralentizar el flujo de trabajo de CI.
La decisión de qué enfoque funciona mejor para tu track es tuya, como mantenedor.
