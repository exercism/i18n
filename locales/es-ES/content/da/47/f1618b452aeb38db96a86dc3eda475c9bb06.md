# Instalación

## Preámbulo

Aunque Regina Rexx se ha portado ampliamente, estas instrucciones de instalación se centran en plataformas de escritorio de 64 bits con Windows, Linux o MacOS.

## Pasos de instalación

Ten en cuenta que este track espera que se instale la última versión de [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) (la 3.9.5, en el momento de escribir esto). El enlace te lleva directamente a la sección Files, donde eliges el archivo que quieres descargar.

### Windows

Una instalación para ejecutar de forma nativa en Windows (mediante una ventana de CMD o Powershell) se realiza fácilmente en el navegador con el botón [`Download Latest Version`](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/Regina395w64.exe/download). Solo tienes que hacer clic, descargar e instalar.

Si tienes, o quieres usar, entornos de emulación de Linux como:

* [Git for Windows](https://gitforwindows.org/)
* [Cygwin](https://cygwin.com/)
* [MinGW](http://mingw.org/)

los binarios nativos de Regina para Windows deberían ser accesibles, así que puedes ejecutarlos directamente en estos entornos y, para la mayoría de los propósitos, es suficiente.

Sin embargo, hay una salvedad: la instrucción ADDRESS no funciona correctamente (porque interactúa con el sistema operativo anfitrión). Para obtener los mejores resultados en estos entornos, consigue el paquete específico del entorno e instálalo. La web de Regina, por ejemplo, aloja una compilación [específica para Cygwin](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-pc-cygwin.tgz/download) que puedes instalar.

Como alternativa, si tienes o quieres usar una distribución de Linux _real_ en Windows, como [WSL](https://docs.microsoft.com/en-us/windows/wsl/about) o [Virtual Box](https://www.virtualbox.org/), solo tienes que seguir las instrucciones de la sección de Linux correspondientes a tu distribución.

### Linux

Las instalaciones en Linux suelen ser bastante sencillas cuando se usa el gestor de paquetes del sistema. Sin embargo, se complican cuando los paquetes disponibles _no_ son los últimos. Lamentablemente, es el caso de Regina.

Aun así, es posible hacer una instalación basada en paquetes si obtienes manualmente el último paquete. La web de [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) aloja paquetes para distribuciones de la familia Debian (incluye Ubuntu) y de la familia RHEL (incluye Fedora, CentOS, Rocky y Alma), entre otras.

Para la distribución que elijas, tendrás que descargar dos paquetes: un paquete de biblioteca y un paquete de binarios. Por ejemplo, para instalar en Debian o Ubuntu, haz lo siguiente:

```plain
sudo apt update && sudo apt -y install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx_3.9.5-2_amd64-Debian-11.deb > regina-rexx_3.9.5-2_amd64-Debian-11.deb
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3_3.9.5-2_amd64-Debian-11.deb > libregina3_3.9.5-2_amd64-Debian-11.deb
sudo apt -y install libregina3_3.9.5-2_amd64-Debian-11.deb regina-rexx_3.9.5-2_amd64-Debian-11.deb
```

Y en CentOS y RHEL 7, prueba:
```plain
sudo yum update && sudo yum install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
sudo yum localinstall libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
```

Y en Fedora, Rocky y Alma, prueba:
```plain
sudo dnf update && sudo dnf install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
sudo dnf localinstall libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
```

Cuando una instalación basada en paquetes no es posible, o ha resultado problemática, siempre puedes compilar desde el código fuente; el archivo se obtiene con:

```plain
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5.tar.gz > regina-rexx-3.9.5.tar.gz
```

Suponiendo que tienes instaladas las herramientas de compilación estándar (gcc, make) (si no es así, sigue las instrucciones que encontrarás aquí: [Install Development Tools](https://ostechnix.com/install-development-tools-linux/)), realiza los siguientes pasos:

```plain
tar -xzvf regina-rexx-3.9.5.tar.gz && cd regina-rexx-3.9.5
./configure
sudo make
sudo make install
```

Se instalan la biblioteca (`libregina.so`) y dos conjuntos de binarios (`rexx` y `regina`) (la ubicación predeterminada es `/usr/local/bin`).

El binario `rexx` está enlazado estáticamente, por lo que es autónomo y se puede usar directamente.

El binario `regina` está enlazado dinámicamente, así que necesita algo de configuración para poder localizar la biblioteca compartida `libregina.so` en tiempo de ejecución. Para ello, sigue estos pasos:

```plain
# Configure shared library location
sudo su
echo /usr/local/lib64/ > /etc/ld.so.conf.d/regina-rexx-3.9.5-x86_64.conf
echo /usr/local/lib64/regina-rexx/addons > /etc/ld.so.conf.d/regina-rexx-addons-x86_64.conf
cd /usr/local/lib64
rm -f libregina.so libregina.so.3
ln -s libregina.so.3.9 libregina.so
ln -s libregina.so.3.9 libregina.so.3
ldconfig
exit

# Check symbolic link creation
ls -l /usr/local/lib64/

# Output should be similar. Note symbolic links.
-rw-r--r--. 1 root root 3887554 Dec  1 18:22 libregina.a
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so -> libregina.so.3.9
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so.3 -> libregina.so.3.9
-rwxr-xr-x. 1 root root  574104 Dec  1 18:22 libregina.so.3.9
drwxr-xr-x. 2 root root      26 Dec  1 18:22 pkgconfig
drwxr-xr-x. 4 root root      33 Dec  1 18:22 regina-rexx

# Check library path, and executable using that path
ldconfig -p | grep regina
ldd /usr/local/bin/regina

# Alternate for local user
export LD_LIBRARY_PATH=${LD_LIBRARY_PATH}:/usr/local/lib64:/usr/local/lib64/regina-rexx/addons
```

Ten en cuenta que compilar desde el código fuente, junto con la configuración del sistema que conlleva, es una tarea que es mejor dejar en manos de usuarios con experiencia.

### MacOS

La instalación consta de tres pasos:

* Instala el gestor de paquetes [Homebrew](https://brew.sh)
* Localiza y abre la aplicación `Terminal`
* Desde la línea de comandos de `Terminal`, escribe lo siguiente:

   `brew install regina-rexx`

Esto _debería_ instalar la última versión.

Si no lo hace, puedes descargar el paquete [Regina for MacOS](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-apple-darwin21.6.0.tgz/download) e instalarlo manualmente.

## Después de la instalación

### Comprobación de la instalación

Una vez completada la instalación, puedes comprobar si [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) se instaló correctamente ejecutando este comando en un terminal:

```plain
rexx --version=v
```

Tanto en Windows como en Linux, verás la siguiente salida en el terminal:

```plain
3.9.5
```

que es el número de versión del intérprete.

Se instala también un segundo binario, `regina`. Es idéntico a `rexx` en todos los aspectos, salvo que se enlaza con una biblioteca compartida, y es el intérprete que debes usar si quieres acceder a funciones de utilidad externas. Consulta la sección [Acceder a rutinas externas](###accessing-external-routines).

No hace falta instalar ningún otro componente de software para empezar a usar el track (suponiendo que ya tengas instalada la CLI de Exercism).

Las notas de uso que verás a continuación te darán una base básica para usar el intérprete desde la línea de comandos.

### Uso

Un script de Rexx suele tener la extensión _`.rexx`_, aunque no es obligatorio, ya que el intérprete intentará ejecutar el nombre de archivo que se le pase como argumento y, si contiene código Rexx válido, se ejecutará correctamente.

El siguiente comando intentará ejecutar un archivo llamado `hello.rexx`:

```plain
rexx hello.rexx
```

Suponiendo que el archivo contenga el siguiente código:

```rexx
say "Hello, world!"
exit 0
```

la salida en el terminal sería:

```plain
Hello, world!
```

La misma salida aparecería si el archivo se renombrara a `hello.txt` y se ejecutara así:

```plain
rexx hello.txt
```

También merece la pena saber que el código del script se puede pasar al intérprete por una tubería, en lugar de estar guardado en un archivo. El código anterior se puede ejecutar por una tubería así:

```plain
echo "say 'Hello, world' ; exit 0" | rexx
```

y funciona igual de bien tanto desde un terminal de Linux como desde uno de Windows Powershell.

### Uso avanzado

A los archivos de script se les puede pasar uno o más argumentos de línea de comandos, y pueden devolver códigos de retorno numéricos enteros arbitrarios. Sin embargo, el intérprete necesita saber que se van a pasar varios argumentos al script, algo que se consigue con la opción `-a`.

Por ejemplo, supón que el archivo `multiarg.rexx` contiene el siguiente código:

```rexx
say "My name is" ARG(1) || ", your name is" ARG(2) || ", and the script return code will be" ARG(3) || "."
exit ABS(ARG(3))
```

Para que los múltiples argumentos del script se interpreten correctamente, el script se ejecuta así:

```plain
rexx -a multiarg.rexx "John" "Jill" 5
```

lo que produce la siguiente salida en el terminal:

```plain
My name is John, your name is Jill, and the script return code will be 5.
```

y el código de retorno del programa (accesible mediante `$?` en Linux o `%errorlevel%` en Windows) se establece en un valor de 5.

### Acceder a rutinas externas

Regina permite usar rutinas que residen en bibliotecas compartidas externas. Hay varias disponibles en la web de Regina. Sin embargo, aquí no se explica cómo instalar esas bibliotecas.

Regina sí incluye una biblioteca de este tipo, _regutil_. Contiene varias rutinas de propósito general, entre ellas para matemáticas, manipulación de archivos y sistemas de archivos, y tareas de acceso al sistema.

No se necesita ningún paso de instalación adicional. Sin embargo, para usar estas rutinas en un script es necesario registrarlas cuando se carga el intérprete. Esto no requiere más que dos llamadas a funciones, y el proceso se ilustra aquí.

Un archivo, `access-external.rexx`, contiene el siguiente código:

```rexx
/* Register external library and functions */
call RxFuncAdd 'SysLoadFuncs', 'regutil', 'SysLoadFuncs'
call SysLoadFuncs

say "Value of pi is" SysPi()
say "Square root of 25 is" SysSqrt(25)
say "Square root of 2 is" SysSqrt(2)

/* Deregister */
call SysDropFuncs

exit 0
```

Para cargar y usar estas rutinas hay que utilizar el binario `regina`, así que el script se ejecutaría así:

```plain
regina access-external.rexx
```

y aparece la siguiente salida en el terminal:

```plain
Value of pi is 3.141592654
Square root of 25 is 5.000000000
Square root of 2 is 1.414213562
```

Si, en cambio, se hubiera usado el binario `rexx`, la salida en el terminal en Windows sería:

```plain
'SYSLOADFUNCS' is not recognized as an internal or external command,
operable program or batch file.
'SYSPI' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSDROPFUNCS' is not recognized as an internal or external command,
operable program or batch file.
```

mientras que en Linux la salida sería:

```plain
sh: SYSLOADFUNCS: command not found
sh: SYSPI: command not found
sh: SYSSQRT: command not found
sh: SYSSQRT: command not found
sh: SYSDROPFUNCS: command not found
```
