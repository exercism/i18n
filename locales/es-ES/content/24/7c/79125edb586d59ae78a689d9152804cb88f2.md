# Acerca de

Un **número de coma flotante** es un número que puede tener parte fraccionaria, como `-1.23` o `3.1415`.

Para representar un número así como una secuencia de bytes, x86-64 utiliza el estándar [IEEE-754][ieee].
Los dos formatos más comunes de este estándar son los números de coma flotante de precisión simple y de doble precisión.
x86-64 admite ambos.

Un número de coma flotante de precisión simple ocupa 32 bits, mientras que uno de doble precisión ocupa 64 bits.

## Registros XMM

En x86-64 hay 16 registros dedicados a hacer aritmética de coma flotante, llamados `xmm0` a `xmm15`.

Esos registros tienen al menos 128 bits de ancho, pero los procesadores recientes los amplían a 256 o 512 bits.
Sin embargo, en la práctica, la mayoría de los números de coma flotante solo usan los 32 o 64 bits más bajos, según la precisión deseada.

## Conversión entre números

Existe una familia de instrucciones para convertir entre formatos numéricos: `cvtxx2yy`.

Tanto `xx` como `yy` no son literales, sino marcadores de posición:

- `xx` es un marcador de posición para el tipo del operando de origen.
- `yy` es un marcador de posición para el tipo del operando de destino.

Este marcador de posición puede tomar muchas formas, entre ellas:

| marcador de posición | significado                  |
| ----------- | --------------------- |
| `si`        | entero con signo        |
| `ss`        | coma flotante de 32 bits |
| `sd`        | coma flotante de 64 bits |

Por ejemplo:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

Ten en cuenta que es posible convertir un entero de 32 bits en un número de coma flotante de 64 bits, o un entero de 64 bits en un número de coma flotante de 32 bits.
Del mismo modo, también es posible convertir un número de coma flotante de 32 bits en un entero de 64 bits, o un número de coma flotante de 64 bits en un entero de 32 bits.
En otras palabras, el tamaño de ambos operandos en un `cvtxx2yy` _no tiene por qué ser el mismo_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

Cuando el número de coma flotante no se puede expresar exactamente como un entero, `cvtxx2si` redondea el número según el control de redondeo de un registro especial llamado `mxcsr`.
Este puede ser un redondeo al más cercano, hacia abajo, hacia arriba o un truncamiento.
No hay un valor predeterminado garantizado al entrar en una función.

Ten en cuenta que un resultado exacto no se redondea y, por tanto, no le afecta el control de redondeo.
Por ejemplo, `42.0` _siempre_ se convertiría en `42`.

Existe una familia similar de instrucciones con el formato `cvttxx2si` (con una `t` adicional) que siempre trunca el resultado.

## Redondeo

La familia de instrucciones `roundxx` convierte un número de coma flotante del operando de origen en un número de coma flotante redondeado que se guarda en el operando de destino.

Aquí, `xx` es un marcador de posición para el tipo de los operandos, como siempre: `ss` para los de precisión simple y `sd` para los de doble precisión.

Estas instrucciones toman un número constante como tercer operando.
Ese número indica el modo de redondeo:

| Número | Modo         |
| :----- | :----------- |
| 0      | Al más cercano      |
| 1      | Hacia abajo (suelo) |
| 2      | Hacia arriba (techo)    |
| 3      | Truncar     |

Por ejemplo:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

Como estas instrucciones producen un resultado exacto, se pueden usar como preparación para un `cvtxx2si`.

## Instrucciones aritméticas

Muchas operaciones con números de coma flotante usan instrucciones con un nombre similar al de su equivalente para enteros, pero añadiendo al final el marcador de posición necesario (`ss` o `sd`).
Estas instrucciones tienen dos operandos, con la semántica habitual, incluso las que realizan multiplicaciones o divisiones:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## Movimiento

Las instrucciones para mover de un registro XMM a otro son `movss` o `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

**No** es posible mover un valor inmediato (un entero con signo constante) directamente a un registro xmm.
Ese número primero hay que moverlo a un registro de propósito general y luego convertirlo con `cvtsi2xx`:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## Comparaciones

Hay dos grupos de instrucciones para comparar dos números de coma flotante.
Tienen la forma `comixx` y `ucomixx`, donde `xx` es `ss` o `sd`.
Ambos establecen banderas en `rflags` como de costumbre, siguiendo la misma semántica que `cmp`.

La diferencia entre ellos es que `ucomixx` establece la `parity flag (PF)` si uno de los dos números de coma flotante tiene un valor `NaN`, mientras que `comixx` lanza una excepción en ese caso.

La comparación entre valores de coma flotante es _sin signo_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## Otras instrucciones

Hay muchas más instrucciones para trabajar con números de coma flotante, que implementan operaciones comunes.
Algunas de ellas son:

| Instrucción | Descripción                                      |
| :---------- | :----------------------------------------------- |
| `sqrtxx`    | Calcula la raíz cuadrada (`sqrt(x)`)                 |
| `rcpss`     | Calcula el recíproco (`1/x`)                      |
| `rsqrtss`   | Calcula el recíproco de la raíz cuadrada (`1/sqrt(x)`) |
| `minxx`     | Calcula el mínimo (`min(x, y)`)                   |
| `maxxx`     | Calcula el máximo (`max(x, y)`)                   |

Cuando se usa un marcador de posición `xx`, este puede tomar la forma `ss` o `sd`, como siempre.
Sin embargo, `rcpss` y `rsqrtss` solo funcionan con números de coma flotante de precisión simple.

Todas estas instrucciones tienen dos operandos.

## Convención de llamada

En la ABI de System V, los ocho primeros argumentos de coma flotante se pasan a las funciones en orden, de `xmm0` a `xmm7`.
Los valores de coma flotante se devuelven de las funciones en `xmm0` y, si es necesario, en `xmm1`.

Todos los registros `xmm` están disponibles libremente, ninguno está reservado para el llamador.

## Memoria

Los valores de coma flotante se pueden definir en memoria siguiendo la misma semántica que los enteros del mismo tamaño.
NASM (The Netwide Assembler, el ensamblador que usa este track) también permite declarar valores de coma flotante en notación científica.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```

## AVX/AVX2

Las extensiones AVX/AVX2 de la arquitectura x86-64 introducen nuevas formas de tres operandos para las instrucciones de coma flotante, que separan el destino de los orígenes.
Llevan el prefijo `v` (de _vector_) para diferenciarlas de la forma SSE heredada que hemos visto antes:

```x86asm
vaddss xmm0, xmm1, xmm2 ; xmm0 = xmm1 + xmm2 (32-bit floating-point)
vmulsd xmm2, xmm3, xmm4 ; xmm2 = xmm3 * xmm4 (64-bit floating-point)
```

En este track nos hemos limitado a las instrucciones y registros hasta las extensiones SSE anteriores.
Esto es suficiente para enseñar los fundamentos y garantiza la compatibilidad con una amplia gama de CPU.

Sin embargo, el ejecutor de pruebas admite AVX y AVX2 por completo.
Eres libre de usarlas.
