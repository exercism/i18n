# Acerca de

## Representación, caracteres y enteros

Como otros tipos simples (`int`s, `bool`s, etc.), el `char` tiene un tipo acompañante o alias; en este caso, `System.Char`.

De hecho, es un `struct` con un campo de 16 bits y es inmutable por defecto.

`char` tiene algunos métodos de instancia como `Equals`, `ToString` y [`CompareTo`][compare-to].

`char` tiene la misma anchura que un [`ushort`][uint16], pero por lo general no se usan indistintamente como en otros lenguajes. Un `ushort` tiene que convertirse explícitamente a `char`.

Por si sirve de algo, los `char` pueden ser objeto de operaciones aritméticas. El resultado de estas operaciones es un número entero.

Obviamente, no existe equivalencia entre un `byte` de 8 bits y un `char` de 16 bits.

## Uso

Los `char` son, por lo general, fáciles de usar.

Se pueden definir como literales con comillas simples:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

Se puede obtener un `char` individual de una cadena con indexación (empezando en cero):

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

Al iterar sobre una cadena se obtiene un `char` en cada paso:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

Como se muestra arriba, se puede convertir un `char` a su valor `int`.
Esto también funciona (*al menos algunas veces*) con otros sistemas de escritura:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

Al comparar caracteres se usa el Int16 subyacente:

```fsharp
'A' < 'D'
// => val it: bool = true
```

Además, un `int` se puede convertir a `char`:

```fsharp
char 77
// => val it: char = 'M'
```

La biblioteca `System.Char` contiene el conjunto completo de [métodos][Char-methods] que se esperan en un lenguaje .NET, como las conversiones a mayúsculas y minúsculas (pero consulta las advertencias de la siguiente sección):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

Las bibliotecas de .NET ayudan a extraer `char` de las cadenas; en este caso, con métodos de `Seq`:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

Hay varias formas de convertir una lista (o un array) de caracteres en una cadena; entre ellas:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

Puedes encontrar información general sobre los `char` aquí:

- [Documentación de Chars][chars-docs]: documentación de referencia de `char`.

Sin embargo, los `char` tienen varias asperezas, como se detalla a continuación. Estas asperezas se deben sobre todo a la contraposición entre el estándar Unicode completo, por un lado, y las representaciones históricas del texto, así como el rendimiento y el uso de memoria, por otro.

## Problemas con Unicode

Cuando trabajes con cadenas, si dispones de los métodos de la biblioteca [`System.String`][System-string], búscalos y úsalos en lugar de descomponer la cadena en caracteres.

Algunos «caracteres» textuales constan de más de un `char` porque el estándar Unicode tiene más de 65536 puntos de código. Por ejemplo, los emojis que aparecen en algunas de las pruebas tienen 2 `char`, ya que están formados por caracteres [subrogados][surrogates].

Además, existen secuencias combinadas; por ejemplo, en algunos casos un carácter acentuado puede constar de un `char` para el carácter base y otro `char` para el acento.

Si tienes que trabajar con caracteres individuales, intenta usar métodos de biblioteca como [`System.Char.IsControl`][is-control] o [`System.Char.IsDigit`][is-digit] en lugar de hacer comparaciones ingenuas, como comprobar que un carácter está entre '0' y '9'.

Por ejemplo, fíjate en que '٢' es el dígito árabe 2. `IsDigit` devolverá true para la versión árabe, así que, por ejemplo, al validar tienes que tener claro qué rango de entradas es aceptable.

Incluso los métodos de la biblioteca `System.Char` pueden no comportarse como esperas cuando trabajas con idiomas menos comunes.

Una forma segura de dividir una cadena en «caracteres» de visualización es usar [`StringInfo`][string-info] y métodos como [`GetNexttextElement`][get-next-text-element].
Esto puede ser necesario si trabajas con globalización o localización.

Otra opción, útil cuando los valores escalares de los caracteres Unicode son importantes (por ejemplo, si estás creando tu propio sistema de codificación), es usar [runes][runes]. Sin embargo, si sabes que el rango de caracteres con el que trabajas no incluye subrogados ni secuencias de caracteres combinados (p. ej., ASCII latino) y tu entrada está bien validada, puedes prescindir de esto.

Una vez más, lo mejor es poder usar los métodos de biblioteca de `String`.

Si acabas encontrándote en la poco envidiable situación de tener que lidiar con los detalles más minuciosos de Unicode, [esto][char-encoding-net] es un buen punto de partida.

## Globalización

Si trabajas en un entorno en el que manejas varias referencias culturales, o en el que la cultura es importante en algunas partes del código pero no en otras, ten en cuenta las sobrecargas de [`ToUpper`][to-upper] y [`ToLower`][to-lower] que aceptan una cultura, y [`ToUpperInvariant`][to-upper-invariant] y [`ToLowerInvariant`][to-lower-invariant], que ofrecen un resultado coherente independientemente de la [cultura][culture-info] actual.
