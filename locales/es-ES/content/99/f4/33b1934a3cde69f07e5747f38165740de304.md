# Introducción

Los literales son valores fijos que se usan directamente en el código.
No necesitan ningún cálculo durante la ejecución.
Adoptan distintas formas para representar de manera eficiente diferentes tipos de datos.
Los literales más frecuentes son de naturaleza numérica, pero también existen operadores literales para tipos de fecha, hora y string.
Un concepto posterior mostrará cómo se pueden usar operadores literales definidos por el usuario.

## Literales numéricos

Los literales numéricos incluyen representaciones decimales, octales, hexadecimales y binarias.
Estos fundamentos ya se trataron en el [concepto de números][numbers-concept].

El compilador interpreta como `int` todas las representaciones como `23`, `0x50f7ba11` y `0xba5eba11`.
El tipo `int` general tiene signo y ([según el compilador y el sistema][in-depth-integers]), a menudo tiene un rango de `-2'147'483'648` a `2'147'483'647`.
Esto es suficiente la mayoría de las veces y no necesitas preocuparte por el tipo concreto.

Algunos casos de uso exigen rangos más amplios o que los programas ocupen muy poca memoria.
Para ser explícito, se puede indicar directamente un tipo entero concreto con el literal numérico.

Cuando no se necesitan números negativos, pero se desea el rango adicional, se usan los sufijos `u` o `U` para enteros _sin signo_.
Para rangos mayores se pueden usar `L` o incluso `LL` para los tipos long y long long.

~~~~exercism/caution
Se permite el uso de la `l` minúscula, pero se confunde fácilmente con el número `1`, por lo que no se recomienda.
~~~~

```cpp
auto net_worth_christian_grey{2'500'000'000U}; // out of range for 32-bit integers
auto net_worth_carlisle_cullen{46'000'000'000LL}; // int and uint are not enough
```

Los números de coma flotante normalmente se resuelven como `double` durante la compilación.
Este es un buen caso por defecto, y los casos de uso con el tipo `float`, más estrecho, son menos frecuentes que el ejemplo anterior con enteros sin signo.

~~~~exercism/advanced
El [estándar C++23][cpp23-literals] introduce un control más preciso con literales como `f128` o `F16`.
Algunos compiladores permiten sus propios literales.
GCC permite el uso de `d` como literal, pero esto no está previsto en el estándar y puede dificultar la compatibilidad entre plataformas.

[cpp23-literals]: https://en.cppreference.com/w/cpp/language/floating_literal

~~~~

```cpp
auto light_year_in_m{9.46073e+15f}; // well in the range of float
auto earth_to_edge_comoving_distance_in_nm{4.32355e+32}; // needs double type for magnitude
auto eulers_number{2.718281828459045}; // needs double type for precision
```

## Literales de carácter y de string

Otros conceptos ya usaban literales de carácter entre comillas simples, como `'}'` o `'@'`.

En C++, `char` se limita a los primeros 128 [códigos de carácter ascii][ascii-code].
Para usar varios caracteres ascii o caracteres ascii extendidos como `‰`, o incluso caracteres unicode como `麗` y `ẞ`, se necesitan otros tipos.
En un concepto anterior se introdujeron los literales de string con _comillas dobles_: `"一体どういう意味ですか。C++です"`.
El tipo real de esta frase en japonés es `const char (&)[46]`, un string al estilo de C.

El uso de los literales de string no está activado por defecto.
Para usar el literal de _string_ `""s` o el literal de _string-view_ `""sv`, el usuario tiene que especificar su uso mediante el espacio de nombres correspondiente:

```cpp
#include <string>
#include <string_view>

using namespace std::literals;

auto green_light{"무궁화 꽃 이 피었 습니다"};
// green_light type is const char (&)[36]
auto umbrella{"달고나"s};
// umbrella type is std::basic_string<char>, the same as std::string
auto il_nam{"보는 것이 하는 것보다 더 재미있을 수가 없지"sv};
// il_nam type is std::basic_string_view<char>
```

Un _string_view_ se puede ver como una referencia a un string constante.
