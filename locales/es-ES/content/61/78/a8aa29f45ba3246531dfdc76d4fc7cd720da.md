# Booleans

`BOOL` almacena uno de dos valores, `true` y `false`.

```sather
   ready : BOOL is
      return true;
   end;
```

## Comparación

| Operador | Pregunta | Ejemplo |
| --- | --- | --- |
| `=` | ¿iguales? | `age = 13` |
| `/=` | ¿distintos? | `age /= 13` |
| `<` | menor que | `age < 13` |
| `<=` | menor o igual que | `age <= 13` |
| `>` | mayor que | `age > 13` |
| `>=` | mayor o igual que | `age >= 13` |

Estos operadores funcionan con números, y `=` y `/=` también funcionan con strings.

## Los tres operadores

| Operador | Se escribe | Es verdadero cuando |
| --- | --- | --- |
| and | `a and b` | ambos son verdaderos |
| or | `a or b` | al menos uno es verdadero |
| not | `~a` | `a` es falso |

`and` y `or` tienen **evaluación de cortocircuito**: `a and b` no se molesta en
mirar `b` en cuanto `a` resulta ser falso, porque la respuesta ya está decidida.
Del mismo modo, `a or b` se detiene si `a` es verdadero. Eso importa cuando el
lado derecho es costoso o daría error si se ejecutara.

## Devolver una comparación directamente

Una rutina cuyo único trabajo es hacer una pregunta debería devolver la pregunta,
no elegir una respuesta con un condicional:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

Escribir `if age >= 13 then return true else return false end` ocupa tres líneas
para decir lo mismo que ya decía la comparación, y cualquier lector con
experiencia se dará cuenta.

## Precedencia

`~` tiene la precedencia más alta, luego `and` y luego `or`. Así que

```sather
~a and b or c
```

significa `((~a) and b) or c`. Los paréntesis (`()`) no cuestan nada de escribir y
merecen la pena siempre que, de otro modo, el lector tuviera que recordar ese
orden para seguir la línea.
