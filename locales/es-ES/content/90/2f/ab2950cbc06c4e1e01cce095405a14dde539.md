# Contratos

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| Cláusula | Indica | De quién es la culpa si se incumple |
| --- | --- | --- |
| `pre` | qué debe cumplirse al entrar | de quien llama |
| `post` | qué se cumple al devolver | de la rutina |

Ambas reciben un `BOOL`, y ambas pueden usar los argumentos de la rutina y los
atributos del objeto. `post` también puede usar `result`, el valor que se
devuelve.

## assert

Dentro del cuerpo de una rutina, `assert` afirma algo que debe ser cierto en
ese punto:

```sather
      assert load <= limit;
```

Se comprueba bajo la misma opción que las demás.

## Invariantes de clase

Una clase puede afirmar algo que es cierto de cada uno de sus objetos entre
llamadas:

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

Se comprueba al entrar y al salir de cada rutina pública, cuando la
comprobación está activada.

## Cómo activarlo

| Opción | Qué comprueba |
| --- | --- |
| `-chk` | todo: pre, post, assert, invariant, límites y aritmética |
| `-chk_no` | nada |

Ten en cuenta que `-chk_pre` por sí solo *no* activa la comprobación de
precondiciones en este compilador; lo que funciona es `-chk`. Una infracción
imprime la rutina y la línea de código fuente y detiene el programa. No es una
excepción, y `protect` no la capturará.

Lo habitual es desarrollar y probar con `-chk` y distribuir sin él, de modo que
las comprobaciones no cuesten nada en el programa distribuido. Eso solo
compensa si los tests ejercitan de verdad los distintos caminos.

## Qué hace que un contrato sea bueno

Di qué necesita la rutina, no cómo funciona:

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

Un `post` que repite el cuerpo no le enseña nada a nadie:

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## Herencia

Un subtipo puede debilitar un `pre` y reforzar un `post` (aceptar más, prometer
más), pero nunca lo contrario, o el código escrito para el supertipo se
rompería. Esa es la regla que los contratos sirven para comprobar.
