# Contratos

Los argumentos y el tipo devuelto de una rutina dicen qué *tipo* de cosa entra
y sale. No pueden decir que un peso deba ser positivo, ni que un arnés de
pruebas informe nunca de más capacidad disponible de la que tiene.

Un **contrato** dice esas cosas, en la propia cabecera de la rutina, donde
cualquiera que la lea las verá.

## pre

`pre` indica qué debe cumplirse cuando se llama a la rutina. Va entre el tipo
devuelto y el `is`.

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

Eso es una exigencia para **quien llama**: no llames a esta rutina con una carga
negativa.

## post

`post` indica qué se cumplirá cuando la rutina responda. Dentro de él, `result`
es el valor que se devuelve.

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

Eso es una promesa a quien llama. Una rutina que tiene ambos es un trato: dame
esto y yo te daré aquello.

Varias condiciones se unen con `and`, igual que cualquier Boolean:

```sather
      pre load >= 0 and load <= limit
```

## Los contratos no son excepciones

Una excepción lanzada sirve para algo que puede ocurrir. Un contrato incumplido
significa un **bug**: alguien llamó mal a la rutina, o la rutina no hizo lo que
decía.

Así que un contrato incumplido no lanza algo que se pueda capturar. Cuando la
comprobación de contratos está activada, el programa se detiene e imprime qué
rutina y qué condición. Cuando está desactivada, la condición ni siquiera se
comprueba, y el programa continúa hacia cualquier desatino que venga después.

Por eso un contrato es una afirmación sobre la corrección y no una forma de
gestionar entradas incorrectas. Si se espera una entrada incorrecta, compruébala
y usa `raise`. Si una entrada incorrecta significa que quien llama se ha
equivocado, dilo con `pre`.

## Activar la comprobación

Este Sather comprueba los contratos cuando se le pasa `-chk` al compilador:

```
sacomp -chk mine.sa -main MAIN -o mine
```

Sin él, `pre` y `post` son documentación que el compilador ha leído y ha
aceptado que está bien formada, y nada más. Las pruebas de este ejercicio se
compilan sin `-chk`, así que no pueden detectar por ti un contrato incumplido;
lo que comprueban es que las rutinas hacen lo correcto cuando se usan bien.
