# Prepárate para recibir contribuciones de código abierto de desconocidos

En este punto ya deberías ser capaz de aceptar contribuciones de desconocidos.
Escribe algo de documentación sobre cómo contribuir para ayudar a los desconocidos a contribuir.

## Incidencias

Si hay ejercicios que quieres incluir en el track pero que aún no has implementado, abre una incidencia para cada ejercicio.
Por lo general, recomendamos abrir incidencias para las tareas para las que aceptarías contribuciones.

Tenemos una sección especial en el sitio web que lista _tareas_, que son incidencias con una o más etiquetas especiales.
Que tus incidencias aparezcan listadas en el sitio web es una excelente forma de conseguir más contribuciones.
Para obtener más información sobre cómo hacer que tus incidencias aparezcan en el sitio web, consulta la [documentación sobre las tareas](/docs/building/product/tasks).

## Otras cosas a tener en cuenta

- ¿Existe una guía de estilo para tu lenguaje de programación?
- ¿Se fomentan o se exigen estos estilos?
- ¿Hay alguna convención que debamos adoptar en este track por coherencia?
- ¿Podemos exigirlas?
- ¿Existe un linter? ¿Hay muchos? ¿Deberíamos usar alguno?
- ¿Existe una convención común para los nombres de fichero? Si no, ¿cuál debería ser nuestra convención?

Puede que valga la pena abrir incidencias aparte para las cosas que quieras abordar.
