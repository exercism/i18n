# Tipos de string

Cairo no tiene un tipo de dato nativo para los strings.
Sin embargo, hay dos maneras de representar un string: los strings cortos con un único `felt252` y los strings de longitud arbitraria con `ByteArray`.

## Strings cortos

Un string corto se forma con comillas simples, donde cada carácter que compone el string se codifica en un byte siguiendo el [estándar ASCII][ascii-table].

Como string ASCII, por ejemplo, `'abc'` sería:

- `'a'` equivale a `0x61`
- `'b'` equivale a `0x62`
- `'c'` equivale a `0x63`
- `'abc'` equivale a `0x616263`

En Cairo, el tipo de dato `felt252` es el que almacena los strings cortos.
Como `felt252` contiene 251 bits, un string corto está limitado a 31 caracteres (31 \* 8 = 248 bits, que es el múltiplo de 8 más grande que cabe en 251 bits).

Ejemplos de declaraciones de strings cortos:

```rust
    let my_first_char = 'D';
    let my_first_char_in_hex = 0x44;

    let my_first_string = 'Hello world';
    let my_first_string_in_hex = 0x48656C6C6F20776F726C64;
```

### ByteArray

La estructura ByteArray se introdujo en Cairo 2.4.0.
Los strings de tipo ByteArray se escriben entre comillas dobles de la siguiente manera:

```rust
    let long_string: ByteArray = "this is a string which has more than 31 characters";
```

Técnicamente, la actualización también introdujo el tipo `bytes31`, que contiene 31 bytes y cabe en un felt.
La estructura `ByteArray` representa básicamente un string largo usando un array de `bytes31` que contienen las «palabras completas» (es decir, palabras que llenan todo el felt) y un único campo felt que contiene una «palabra incompleta» (el número de bytes que hay en ella se especifica en un campo de longitud aparte).

```rust
#[derive(Drop, Clone, PartialEq, Serde, Default)]
struct ByteArray {
    data: Array<bytes31>,
    pending_word: felt252,
    pending_word_len: usize,
}
```
