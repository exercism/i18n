# Introducción

## Errores

Los errores ocurren. En Elixir, aunque a menudo se dice que hay que «dejar que falle», hay ocasiones en las que necesitamos rescatar la llamada a la función hasta un estado conocido y válido para cumplir con un contrato de software. En algunos lenguajes, los errores se usan como método de flujo de control, pero en Elixir este patrón está desaconsejado. A menudo podemos reconocer las funciones que pueden lanzar un error solo por su nombre: las funciones que lanzan errores llevan un `!` al final de su nombre. Esto contrasta con las funciones que devuelven `{:ok, value}` o `:error`. Mira estos ejemplos de la biblioteca:

```elixir
Map.fetch(%{a: 1}, :b)
# => :error
Map.fetch!(%{a: 1}, :b)
# => raises KeyError
```

## Try/Rescue

Elixir proporciona una construcción para rescatar de errores usando `try .. rescue`.

```elixir
try do
  raise RuntimeError, "error"
rescue
  e in RuntimeError -> :error
end
```

Vamos a examinar esta construcción:

- **Línea 1**, el bloque se declara con `try`.
- **Línea 2**, aquí se coloca la llamada a la función que puede dar error; en este caso, estamos llamando a `raise/2`.
- **Línea 4**, en la sección `rescue`, hacemos coincidencia de patrones con el nombre del _módulo_ del error lanzado
  - a la izquierda de `->`:
    - `e` se asigna a la struct del error.
    - `in` es una palabra clave.
    - `RuntimeError` es el error que queremos rescatar.
      - Si quisiéramos rescatar de todos los errores, podríamos usar `_` en lugar del nombre del módulo u omitir la palabra clave `in` por completo.
  - a la derecha:
    - las instrucciones que se ejecutan si el error coincide.

### Structs de error

Los errores (a los que a veces también se llama «excepciones») que rescatas de esta forma son structs.
En Elixir, rescatar errores se hace muy rara vez.
Normalmente, el error rescatado se registra o se envía a un servicio de monitorización externo, y luego se vuelve a lanzar.
Esto significa que normalmente no nos importa la estructura interna del struct de error concreto.

En el [concepto de excepciones][exercism-exceptions] aprenderás más sobre los structs de error, incluido cómo definir tu propio error personalizado.
