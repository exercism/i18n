# Nil

Crystal tiene un tipo llamado [`Nil`][nil], que solo puede tener un valor: `nil`.
Se utiliza para representar la ausencia de un valor y es similar a `null` o `None` en otros lenguajes.

Los valores nil pueden devolverlos varios métodos; por ejemplo, [`String#[]?`][string-index], que devuelve `nil` si el índice está fuera de los límites.

```crystal
"foo"[10]? # => nil
```

Crystal tiene lo que se conoce como **COMPROBACIONES DE REFERENCIAS NULAS**, lo que significa que, por defecto, ningún tipo puede ser nil.
Esto quiere decir que no puedes asignar `nil` a una variable a menos que la declares explícitamente como de tipo `Nil`.
A su vez, esto significa que el compilador comprobará automáticamente las referencias nulas.

## Valor falsy

Se pueden adoptar varios enfoques para manejar los valores nil.
`nil` es un [valor falsy][truthy-falsey], igual que `false`.
Esto significa que, en las instrucciones y en otros lugares donde se espera un valor falsy o truthy, se tratará igual que `false`.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Esto significa que no se tomará la rama truthy si una variable que puede ser nil tiene el valor `nil`.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Comprobar si es nil

Crystal tiene un método que se puede usar para comprobar si un valor es `nil`.
Se llama [`nil?`][nil?] y está disponible en todos los objetos.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Esto es un poco distinto cuando se usa el valor directamente en un condicional, ya que en los ejemplos anteriores tanto `false` como `nil` se trataban como falsos.
Aquí solo `nil` se trata como falsy, ya que si el valor fuera `false` no sería nil y, por tanto, sería truthy.

## Operador or

La forma más sencilla de manejar los valores nil es asegurarse de que nunca lleguen a ser `nil` en primer lugar.
El operador or ([`||`][or]) se usa a menudo cuando se trabaja con `Bools`, pero, si se entiende bien, también sirve para trabajar con valores nil.
El operador or comprueba si el primer valor es truthy; si no lo es, se usa el segundo valor.
Esto se puede usar para conseguir que, si el valor es `nil`, sea falsy y, por tanto, se use el segundo valor.

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
Este enfoque debe considerarse un último recurso y solo debe usarse si estás **seguro** de que el valor no es nil.
Si es posible, usa mejor los otros enfoques.
~~~~

[`not_nil!`][not_nil] es un método que te permite indicar al compilador que un valor no es nil y, por tanto, hacer que el tipo que contiene no pueda ser nil.
Lo hace lanzando una excepción si el valor es nil.

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
