# Acerca de lo básico

Kotlin es un lenguaje de tipado estático, diseñado para ser totalmente interoperable con Java.

A diferencia de Java, Kotlin:

- tiene una sintaxis más limpia y concisa;
- incorpora muchas funcionalidades de los lenguajes funcionales;
- tiene un amplio soporte para valores anulables.

## Variables

Como Kotlin tiene tipado estático, es necesario _conocer_ el tipo de cada valor en tiempo de compilación.

Sin embargo, la [inferencia de tipos][inference] de Kotlin es muy potente, por lo que _especificar_ el tipo suele ser opcional.

Hay dos formas de declarar una variable.

1. `val` crea una variable inmutable, e intentar cambiarla es un error en tiempo de compilación.

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. `var` crea una variable mutable.

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

Como las variables inmutables eliminan una clase común de errores, se recomienda usar `val` siempre que sea posible.

Además, ni siquiera un `var` puede cambiar de tipo:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

Para reducir la distracción visual, en este temario los tipos explícitos se omitirán en su mayoría.
No obstante, se recomienda especificar los tipos al menos para:

- las API públicas
- las firmas de funciones
- donde se necesite documentación

Algunas empresas y organizaciones exigen una seguridad de tipos estricta y no permiten la inferencia de tipos, mientras que otras la restringen a tipos «simples» o la adoptan por completo.

```kotlin
val x: Int = 42  // => 42
```

En general, los nombres de las variables y las funciones deben estar en `camelCase`, no en `snake_case`

## Funciones

Declara una función con la palabra clave `fun`.
A diferencia de Java, las funciones no tienen que formar parte de una clase.

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

Algunos puntos a tener en cuenta:

- Después del nombre de la función se necesitan paréntesis `()`, aunque la función no reciba argumentos.
- Los argumentos de una función deben especificar el tipo: no hay inferencia de tipos (a diferencia de las variables).
- El cuerpo de la función va encerrado entre llaves `{ }` (aunque lo veremos más abajo).
- La palabra clave `return` es obligatoria si se devuelve un valor.
- Los puntos y coma `;` al final de las líneas son opcionales y normalmente se omiten.
- Los operadores aritméticos `+`, `-`, `*`, `/` son similares a los de la mayoría de los lenguajes más comunes.

No obstante, para estas funciones tan simples, de «expresión única», existe una sintaxis abreviada:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
Las funciones pueden tener parámetros con valores predeterminados.
Estos valores se usarán si se omiten en el lugar donde se llama a la función:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

Las funciones en Exercism normalmente devuelven un valor (debido a cómo está estructurado el ejecutor de pruebas).
Para usar Kotlin en un contexto más amplio, puede ser útil saber que una función que no devuelve ningún valor puede omitir el tipo de retorno y la palabra clave `return`.

En ese caso se dice que tiene un tipo de retorno `Unit`: equivalente a `void` en Java y varios otros lenguajes.

## Comentarios

Los comentarios de una sola línea empiezan por `//` y el resto de la línea se ignora.

Los comentarios de varias líneas empiezan por `/*` y terminan con `*/`

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

Esto es igual que en Java.
