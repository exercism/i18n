# Acerca de

La única convención de Factor para pasar datos es la *pila de datos*: las palabras extraen sus entradas y apilan sus salidas. Toda definición de palabra declara un *efecto de pila* que documenta ese contrato.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

Los nombres que aparecen dentro de `( … -- … )` son para comodidad de quien lee; lo que comprueba el compilador es el *número* de entradas y salidas. Un desajuste es un error en tiempo de compilación, lo que atrapa toda una clase de bugs que serían errores en tiempo de ejecución en un lenguaje de tipado dinámico sin este tipo de declaración.

Como la pila es posicional, necesitas reordenar constantemente su parte superior antes de que pueda ejecutarse la siguiente palabra. Las **palabras de reordenación** de `kernel` hacen exactamente eso:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

La familia completa de palabras de reordenación amplía estas con `-rot` (que gira en el otro sentido), las primas con sufijo `d` que actúan un elemento más abajo (`dupd`, `swapd`), las primas con prefijo `2` que actúan sobre pares (`2dup`, `2drop`, `2nip`) y otras como `pick` y `tuck`. Se van presentando a medida que las necesitan los ejercicios posteriores; echar mano de demasiadas palabras de reordenación a la vez suele ser señal de que un *local* (un valor con nombre) se leería mejor.

Por convención, las palabras usan `lowercase-kebab-case`, los predicados terminan en `?` y producen un Boolean (`even?`, `empty?`), los setters se escriben `>>name` y los getters `name>>`, y una palabra y su variante mutadora comparten a menudo el nombre, y solo el contexto las distingue.
