# Pistas
Un uso habitual de `Either` es indicar un cálculo que posiblemente dé lugar a un error
(si el error en sí no te interesa, quizá sea mejor opción el tipo `Option`, más sencillo).
Cuando no hay ningún error, el resultado suele ser un `Right` (regla mnemotécnica: el valor «right»),
mientras que un error es un `Left`; por ejemplo, un `Left[String]` que contiene un mensaje de error.
Ten en cuenta que, en Scala 2.12, `Either` está sesgado hacia la derecha de forma predeterminada, así que funciona como se espera en operaciones como `filter`, `map`, `flatMap` o en una for-comprehension.
Si no conoces `Either`, puedes leer [este tutorial](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html). Pero ten en cuenta que este tutorial trata de versiones de Scala anteriores a la 2.12. Para Scala 2.12 puedes ignorar `RightProjection` sin problema y omitir `.right`.
`Either` es lo que se conoce como una [mónada](https://en.wikipedia.org/wiki/Monad_(functional_programming)) que abarca un «aspecto computacional»,
en este caso el manejo de errores.
El uso correcto de las mónadas puede dar lugar a un código muy conciso pero elegante
y legible. Un uso incorrecto puede dar lugar fácilmente a lo contrario.
Ve [este vídeo](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) para aprender más.
## Errores comunes que debes evitar
Hay unas cuantas reglas generales para `Either`:
1. Si no lo necesitas, no lo uses. En lugar de
```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```
es mejor tener
```scala
def add1(x: Int): Int = x + 1
```
(existe `Either.map` para aplicar ese tipo de funciones tan sencillas,
así que no hace falta que las sobrecargues con `Either`).
2. No hagas «unwrap» si no lo necesitas de verdad.
A menudo existen funciones integradas para lo que buscas. Los indicios de un
«unwrap» prematuro son `isLeft/isRight` o la coincidencia de patrones. Por ejemplo, en lugar de
```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```
es mejor tener
```scala
x fold (identity, _ + 1)
```
3. Las mónadas se pueden usar dentro de una for-comprehension. ¡Es lo mejor!
Esto es recomendable cuando quieres «componer» varias instancias de `Either`. En lugar de
```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```
es mejor tener
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
