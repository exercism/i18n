# Introducción

## Código sin saltos

El concepto de los condicionales presenta `jcc`, la familia de instrucciones para saltar en función de una condición.
Un `jcc` transfiere la ejecución a otro punto del programa solo si se cumple su condición.

Sin embargo, las CPU modernas son rápidas y capaces de ejecutar muchas instrucciones en paralelo.
Sería demasiado costoso detener todo el trabajo mientras la CPU espera una comprobación en tiempo de ejecución de una condición.

Por eso, internamente, la CPU no espera.
Utiliza un **predictor de saltos** para predecir el resultado de una condición y empieza a ejecutar _especulativamente_ la ruta prevista.

Si la predicción es correcta, la ejecución continúa como si no hubiera salto.
Sin embargo, si la predicción es incorrecta, la CPU debe _descartar el trabajo realizado_ en la ruta prevista y reiniciar en la ruta correcta.

Esto se llama **error de predicción de salto** y es costoso, ya que conlleva un retraso.

Cuando un salto es difícil de predecir, esos errores de predicción se acumulan.
En esos casos, a veces es preferible evitar el salto por completo, de modo que se ejecuten las mismas instrucciones independientemente de la condición.
El código que selecciona entre valores sin un `jcc` se denomina **código sin saltos**.

Hay varias formas de estructurar el código para que salte con menos frecuencia, o para que los saltos que sí tiene sean más predecibles.
En particular, x86-64 proporciona dos familias de instrucciones que se usan habitualmente para escribir código sin saltos.

### Movimientos condicionales

La familia de instrucciones `cmovcc` copia el operando origen en el destino solo si se cumple una condición específica.
En caso contrario, el destino se deja sin cambios.

El sufijo `cc` sigue la misma nomenclatura que en `jcc`, con el mismo significado:

| instrucción | mover si                              |
|-------------|--------------------------------------|
| `cmove`     | A == B después de `cmp A, B`              |
| `cmovne`    | A != B después de `cmp A, B`              |
| `cmovl`     | A < B (con signo) después de `cmp A, B`      |
| `cmovb`     | A < B (sin signo) después de `cmp A, B`    |
| `cmovg`     | A > B (con signo) después de `cmp A, B`    |
| `cmova`     | A > B (sin signo) después de `cmp A, B`    |

Las reglas son similares a las de `jcc`:

1. `l` y `g` se usan para comparaciones con signo, y `b` y `a`, para comparaciones sin signo.
2. Añadir `e` a un sufijo incluye la igualdad.
3. Añadir `n` niega la condición.
4. También hay variantes que hacen referencia a que la bandera está activada.
   Por ejemplo, `cmovz` y `cmovc`.

Considera el valor absoluto de un entero con signo en `rdi`, devuelto en `rax`.
Escrita con `jcc`, la función selecciona una de dos rutas:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Escrita con `cmovcc`, ambos valores candidatos se calculan incondicionalmente y el movimiento condicional elige uno:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

La versión sin saltos siempre ejecuta las mismas instrucciones.
No hay ningún `jcc` que el predictor tenga que predecir.

El destino de un `cmovcc` debe ser un registro.
El origen puede ser un registro o una ubicación de memoria, pero no un inmediato.

~~~~exercism/note
En el código anterior, la instrucción `neg` establece varias banderas según el resultado, incluida la bandera de signo (SF).
Esto significa que `cmp rdi, 0` se puede eliminar por completo:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Para valores positivos de `rdi`, `neg` produce un resultado negativo y SF == 1, por lo que `cmovs` restaura `rdi`.
Para valores de `rdi` cero o negativos, `neg` produce un resultado no negativo y SF == 0, por lo que `rax` conserva el valor negado (que es el valor absoluto correcto).

Aunque `cmp` es la forma principal de comparar valores en código ensamblador, muchas instrucciones también establecen banderas según su resultado.
La lista completa de banderas que afecta una instrucción suele aparecer en su [referencia][reference].
Para `neg` en concreto, son SF, ZF, CF, OF y PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

### Asignación condicional

La familia de instrucciones `setcc` establece el operando destino en `1` si se cumple una condición específica, y en `0` en caso contrario.
El destino es siempre un _operando de 8 bits_.

El sufijo `cc` sigue la misma nomenclatura que en `jcc` y `cmovcc`.
Por ejemplo, `setz` establece el destino en `1` si `ZF == 1` y en `0` en caso contrario.

Como el destino es de 8 bits, es habitual que `setcc` vaya seguido de un `movzx` cuando se necesita un valor más ancho:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Este es un modismo habitual para convertir el resultado de una comparación en un entero `0` o `1`.
