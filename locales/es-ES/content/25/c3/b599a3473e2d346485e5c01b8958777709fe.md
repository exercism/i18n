# Introducción al entrecomillado

Un consejo que los programadores noveles de bash escucharán una y otra vez:

> ¡Entrecomilla tus variables!

¿Por qué?

Cuando expandes una variable (como `$name`), casi siempre quieres usar el _valor_ de la variable como un único string (o número).
No quieres que el valor se trate inesperadamente como dos o más strings separados.

## Entrecomillado

El entrecomillado es el mecanismo principal para asegurar que un fragmento de texto se trate como una sola palabra.
Hay dos tipos principales de comillas.

### Comillas dobles

Las comillas dobles permiten la expansión de parámetros, la expansión aritmética y la sustitución de comandos dentro de ellas.

```bash
echo "This is bash version $BASH_VERSION"
```

Puedes incluir una comilla doble literal dentro de un string entrecomillado con comillas dobles si la precedes con una barra invertida.

```bash
echo "She said \"Let me teach you about bash.\""
```

### Comillas simples

Las comillas simples _no permiten_ ninguna expansión dentro de ellas.

```bash
echo 'This is bash version $BASH_VERSION'
# ...^..................................^
# prints exactly: This is bash version $BASH_VERSION
```

No es _posible_ incrustar una comilla simple dentro de un string entrecomillado con comillas simples.

## La importancia del entrecomillado

¿Qué tiene de malo `echo $name`, exactamente?

Cuando el shell analiza una línea de código, realiza [varios tipos de expansiones][expansions], en orden.
Dos de las últimas expansiones son la _división de palabras_ y la _expansión de nombres de archivo_.

### División de palabras

Cualquier resultado de la expansión de parámetros, la sustitución de comandos o la expansión aritmética _que no haya tenido lugar dentro de comillas dobles_ es candidato a la «división de palabras».
El shell toma el resultado expandido y lo divide por cualquier secuencia de caracteres presente en el valor de `$IFS`.
De forma predeterminada, se trata del espacio, el tabulador y el salto de línea.

Podemos verlo en acción con un bucle del shell:

```bash
sentence="The quick brown fox jumps."
i=0
for word in "$sentence"; do echo "$((++i)) $word"; done
# ..........^.........^
```
da como resultado
```none
1 The quick brown fox jumps.
```

Pero sin entrecomillar:

```bash
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
da como resultado
```none
1 The
2 quick
3 brown
4 fox
5 jumps.
```

Vamos a verlo con un valor distinto de `$IFS`:

```bash
csv="first,second,third"
IFS=","
for word in $csv; do echo "$word"; done
```
da como resultado
```none
first
second
third
```

#### Desactivar la división de palabras

Una técnica para desactivar la división de palabras es asignar a `$IFS` un string vacío

```bash
sentence="The quick brown fox jumps."
IFS=    # or explicitly, IFS=""
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
da como resultado
```none
1 The quick brown fox jumps.
```

No obstante, no se recomienda dejar las variables sin entrecomillar a menos que también desactives la expansión de nombres de archivo.
Veremos cómo hacerlo más abajo.

### Expansión de nombres de archivo

Los patrones «glob» se usan para expresar de forma concisa un patrón que coincida con un conjunto de archivos.
Por ejemplo, puedes hacer coincidir todos los archivos Markdown de un directorio con `*.md`.
Los [patrones glob][glob] existen desde la invención de Unix.

Los caracteres comodín de glob son:

* `*` coincide con cero o más caracteres cualesquiera,
* `?` coincide exactamente con un carácter cualquiera,
* `[...]` coincide exactamente con un carácter del conjunto de caracteres indicado entre los corchetes.

   ~~~~exercism/advanced
   <details><summary>
   Hay muchos detalles sobre los conjuntos de caracteres.
   Haz clic aquí para mostrarlos.
   </summary>

    * `[abc]` coincide exactamente con un carácter que sea una `a`, una `b` o una `c`.
        * para incluir un corchete de cierre literal en la expresión, haz que sea el primer carácter después del corchete de apertura (después de un `^` opcional)
            * `[][]` es un conjunto de caracteres que coincide tanto con un corchete de cierre como con uno de apertura.
            * o escápalo con una barra invertida: `[[\]]`
    * `[x-y]` coincide exactamente con un carácter que esté en el _rango_ de `x` a `y`
        * para incluir un guion literal en un conjunto de caracteres, debe ser el primer carácter después del corchete de apertura (después de un `^` opcional) o el último carácter antes del corchete de cierre.
            * `[-xy]` o `[xy-]` coinciden cada uno exactamente con un carácter que sea `-`, `x` o `y`
            * o escápalo con una barra invertida: `[x\-y]`
        * se pueden especificar varios rangos; por ejemplo, `[0-9A-Fa-f]` coincide con un dígito hexadecimal
    * `[^abc]` coincide exactamente con un carácter que **NO** sea una `a`, una `b` ni una `c`,
    * `[^x-y]` coincide exactamente con un carácter que **NO** esté en el rango de `x` a `y`
    * `[[:character_class:]]` coincide con un carácter que pertenezca a la «character_class» indicada
        * las clases de caracteres disponibles son: 
            * `lower` -- letras minúsculas
            * `upper` -- letras mayúsculas
            * `alpha` -- letras
            * `digit` -- dígitos
            * `alnum` -- letras y dígitos
            * `space` -- espacios en blanco
            * `blank` -- espacio en blanco horizontal (espacio y tabulador)
            * `xdigit` -- dígitos hexadecimales
            * `word` -- caracteres permitidos en un identificador (letras, números, guion bajo)
            * `punct` -- puntuación
            * `cntrl` -- caracteres de control
            * `graph` -- caracteres «visibles»
            * `print` -- caracteres visibles más el espacio
        * se pueden combinar:
            * la clase `[[:alpha:]]` consta de `[[:lower:][:upper:]]`
            * la clase `[[:alnum:]]` consta de `[[:alpha:][:digit:]]`
            * la clase `[[:word:]]` consta de `[[:alnum:]_]`
            * el guion bajo (octal 137) es tanto `[[:word:]]` como `[[:punct:]]`
            * la clase `[[:graph:]]` consta de `[[:alnum:][:punct:]]`
            * la clase `[[:print:]]` consta de `[[:graph:] ]` -- solo el espacio (octal 040), no cualquier otro espacio en blanco.

#### Iterar sobre una lista de archivos

Puedes iterar sobre una lista de archivos con un bucle `for`

```bash
for file in *.csv; do
    do_something_with "$file"
done
```

Fíjate en que la variable `"$file"` está entrecomillada.
El patrón glob puede devolver archivos cuyo nombre contenga espacios.
Necesitamos entrecomillar la variable para que el comando `do_something_with` reciba exactamente un argumento, el nombre del archivo.

#### Los patrones glob no son expresiones regulares

Los patrones glob **no son** expresiones regulares.

* coincidir exactamente con un carácter
   * regex `.`
   * glob `?`
* coincidir con cero o más caracteres
   * regex `.*`
   * glob `*`
        * el patrón glob `.*` significa «coincidir con un nombre de archivo en el que el primer carácter sea un punto literal seguido de cero o más caracteres cualesquiera».
* coincidir con uno o más caracteres
   * regex `.+`
   * glob `?*`
* los conjuntos de caracteres de regex y los de glob funcionan igual.

#### Entrecomillado y expansión de nombres de archivo

Hay ocasiones en las que quieres suprimir la expansión de nombres de archivo.
Procesar la entrada del usuario es una de ellas.
Fíjate en este fragmento de código

```bash
read -p "Enter something: " user_input
echo $user_input
```

Si el usuario introduce un asterisco (`*`), ¿qué se mostrará? 
La lista de archivos del directorio actual.
Probablemente eso no sea lo que quieres hacer.

Otro ejemplo es pasar patrones como argumentos a programas que esperan patrones.
El programa `tr` se usa a menudo para manipular texto. Para convertir a minúsculas el valor de una variable, puedes hacer esto

```bash
var="My Puppet"
echo "$var" | tr '[:upper:]' '[:lower:]'
```
da como resultado
```none
my puppet
```

Un error habitual es olvidar entrecomillar los argumentos de `tr`: `tr [:upper:] [:lower:]`

~~~~exercism/caution
¿Por qué es un problema? 
Los patrones glob sin entrecomillar se expandirán a la lista de archivos que coincidan.
Supón que la persona que usa tu script tiene archivos llamados `p`, `u` y `w` en el directorio actual:

```bash
touch p u w
var="My Puppet"
echo "$var" | tr [:upper:] [:lower:]
```

¡Esto da lugar a un error!

El patrón `[:upper:]` sin entrecomillar coincide con cualquiera de estos caracteres: `:`, `u`, `p`, `e` o `r`.
El patrón `[:lower:]` sin entrecomillar coincide con cualquiera de estos caracteres: `:`, `l`, `o`, `w`, `e` o `r`.
Bash hace coincidir los archivos `p` y `u` con el primer patrón, y el archivo `w` con el segundo, y `tr` se invoca así

```bash
echo "$var" | tr p u w
```

Y ese no es el número correcto de argumentos para `tr`.
~~~~

#### Desactivar la expansión de nombres de archivo

Puedes usar el comando [`set`][set] para desactivar la expansión de nombres de archivo.

```bash
echo *      # prints a list of files
set -f      # disable filename expansion
echo *      # prints a literal asterisk
set +f      # enable filename expansion
```

#### Controlar la expansión de nombres de archivo

Hay varias opciones del comando integrado [`shopt`][shopt] que controlan cómo funciona la expansión de nombres de archivo.
Un par de opciones interesantes son:

* `shopt -s nocaseglob` -- realiza coincidencias sin distinguir mayúsculas de minúsculas
* `shopt -s extglob` -- activa los patrones extendidos
* `shopt -s nullglob` -- si ningún archivo coincide, sustituye el patrón por nada.
   El comportamiento predeterminado es dejar el patrón tal cual, como un string literal.
