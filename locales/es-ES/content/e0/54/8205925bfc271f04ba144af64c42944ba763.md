# Notas sobre llaves, corchetes y paréntesis

Tcl es un [lenguaje muy sencillo](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm),
pero la forma en que el intérprete analiza el código tiene un par de casos límite
complicados.

## Las llaves

Las llaves en Tcl son simplemente una forma de entrecomillar un bloque de texto: ese
texto puede interpretarse como código o como datos. Dentro de las llaves pueden aparecer
llaves anidadas, pero las llaves anidadas deben estar balanceadas. La página de manual de
Tcl dice lo siguiente:

> Las llaves se anidan dentro de la palabra: por cada llave de apertura adicional debe
> haber una llave de cierre adicional (no obstante, si una llave de apertura o de cierre
> dentro de la palabra está _entrecomillada con una barra invertida_, no se cuenta a la
> hora de localizar la llave de cierre correspondiente).

La redacción es bastante concreta: si quieres tener un carácter de llave de apertura o de
cierre sin su pareja, debe ir entrecomillado con una barra invertida. Así que no hagas
esto:
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "{"}]
    # ......................^ will not work
}
```
Debes hacer esto
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "\{"}]
    # ......................^^ will work
}
```

Esto puede ser problemático por la forma en que Tcl analiza los comentarios, que es
distinta de la de la mayoría de los lenguajes. Hay más información al respecto en la [wiki
de Tcl](https://wiki.tcl-lang.org/page/Why+can+I+not+place+unmatched+braces+in+Tcl+comments).

## Los corchetes

Del mismo modo, dado que Tcl usa los corchetes para la [sustitución de
comandos](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M11), incluso dentro de cadenas
entrecomilladas con comillas dobles, hay que tener cuidado al escapar los corchetes de
apertura.

## Los paréntesis

Salvo en el caso de las [variables de array
asociativo](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M12), los paréntesis son simplemente
caracteres normales.
