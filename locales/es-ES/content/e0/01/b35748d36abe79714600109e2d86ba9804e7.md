# Acerca de

El tipo `Result` permite que una función devuelva un único valor que indique todas estas cosas:
- Si la operación se ha realizado correctamente o ha fallado
- En caso de éxito, el valor resultante de la operación
- En caso de fallo, el motivo del fallo

En otros lenguajes de programación que no admiten algo parecido a un tipo `Result`, es habitual encontrar los siguientes patrones para lograr los objetivos mencionados:
- Una función que devuelve un código numérico que indica el éxito o el motivo del fallo y que requiere un parámetro de salida para recibir el valor en caso de éxito.
- Una función que devuelve el valor en caso de éxito o NULL en caso de error, y luego otra función distinta para obtener el código de error que indica el motivo del fallo.

Otro mecanismo habitual para gestionar errores es la excepción, que sale bruscamente de la función actual y
transfiere el control al primer manejador de la pila de llamadas cuando se produce un fallo.  
Si ningún manejador «captura» la excepción, el programa se aborta.

## Ventajas de usar el tipo `Result`

* __Seguridad en tiempo de compilación__: al hacer explícitos en el sistema de tipos el éxito o el fallo de una llamada a una función, el compilador puede garantizar que el código que llama controle todos los casos de fallo, lo que evita toda una categoría de bugs que podrían producirse con valores null.

* __Seguridad en tiempo de ejecución__: en lugar de usar `null`, el tipo `Result` usa `Error` para representar un fallo, lo que hace imposible que se produzca una `NullReferenceException`.

* __Gestión explícita de errores__: el código que llama a una función que devuelve un `Result` debe reconocer que la
llamada puede fallar; el código que llama debe gestionar esos fallos de forma intencionada.  No hay fallos silenciosos ni excepciones inesperadas.

* __Flujo de control predecible__: un `Result` se devuelve como cualquier otro valor; no salta fuera de la pila de llamadas como una excepción.  Siempre sabes de dónde vienen los errores y cómo se propagan.

* __Mejor legibilidad y mantenibilidad__: al devolver un `Result`, la firma de una función indica con claridad el comportamiento esperado en caso de éxito y en caso de fallo.

## Uso

El tipo `Result` es un tipo genérico que contiene dos tipos subyacentes:
- El tipo del valor resultante en una operación correcta
- El tipo que representa el motivo del fallo en caso de fallo

El tipo `Result` es también una [unión discriminada][discriminated-union] con los siguientes casos posibles:
* `Ok <value>`, que representa un resultado correcto
* `Error <reason>`, que representa un fallo

La siguiente función muestra cómo crear un valor `Result`:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

En este ejemplo, el valor `Ok` es un string (el nombre dado) y el valor `Error` también es un string (la causa del error, en formato legible para las personas).

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

El código que llama a la función `openFile` puede usar la coincidencia de patrones para gestionar los casos de éxito y de fallo, como en el siguiente ejemplo:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
