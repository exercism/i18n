## Longitudes no enteras

El ejercicio base prueba la identificación de triángulos cuyos lados son todos números enteros. Sin embargo, algunos triángulos no se pueden representar con números enteros puros. Un ejemplo sencillo es un triángulo con un ángulo de 90 grados entre dos lados iguales de longitud 1. Su tercer lado tiene una longitud de raíz cuadrada de 2, que es un número irracional (es decir, que no se puede escribir como un número entero ni como una fracción).

Sería tedioso reescribir las funciones de análisis para manejar tanto los casos de números enteros como los de coma flotante, y especialmente tedioso hacerlo para todos los tipos de enteros y de coma flotante posibles: dadas las variantes con signo y sin signo de 8, 16, 32, 64 y 128 bits, ¡eso serían 10 reimplementaciones del mismo código fundamental, incluso antes de considerar los números de coma flotante!

Hay una forma mejor: los [genéricos](https://doc.rust-lang.org/stable/book/ch10-00-generics.html). Si reescribes tu Triangle como `Triangle<T>`, puedes escribir tu código una sola vez y delegar en el compilador el trabajo de generar todas esas especializaciones. Ten en cuenta que, para usar operaciones matemáticas, tendrás que restringir tu tipo genérico a los tipos que admitan esas operaciones mediante rasgos.

Hay algunos tests adicionales que puedes ejecutar y que prueban tu implementación con números de coma flotante. Para activarlos, ejecuta tus tests con el flag de características `generic`, así:

```bash
cargo test --features generic
```
