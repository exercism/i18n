# Introducción

La mayoría de las palabras para secuencias que has visto devuelven *nuevas* secuencias y dejan intactas sus entradas: `suffix`, `reverse`, `map`, etc. Pero los arrays y los vectores también admiten **mutación in situ**, y ambos aparecen cuando quieres registrar un estado que cambia con el tiempo.

## Dos variantes de secuencia mutable

- **Los arrays** (`{ … }`) tienen una longitud fija. `<array> ( n elt -- array )` (en [`arrays`][arrays]) construye un array nuevo de longitud `n` lleno de copias de `elt`.
- **Los vectores** (`V{ … }`) crecen y se encogen. Usa `V{ } clone` para crear uno nuevo y vacío; `<vector> ( n -- vector )` (en [`vectors`][vectors]) preasigna capacidad para `n` elementos.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## Cambiar una posición

Estas dos funcionan con cualquiera de los dos tipos de secuencia: ambas esperan la secuencia después del índice:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth` asigna; `change-nth` aplica una quotation al elemento en la posición `n`. Las dos son palabras de [`sequences`][sequences] y no devuelven nada en la pila: la mutación es el efecto.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## Crecer y encoger

Estas tres solo tienen sentido en vectores, ya que los arrays no pueden cambiar de longitud:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## Vector → array

Cuando has construido un vector y quieres devolver un array de longitud fija, `>array ( seq -- array )` (en [`arrays`][arrays]) devuelve un array nuevo con los mismos elementos:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`: guardar una instantánea

La mutación modifica la secuencia in situ. Si quien llama te pasa una secuencia y estás a punto de cambiarla, `clone` (en [`kernel`][kernel]) te da una copia nueva e independiente para que la visión de quien llama no cambie bajo sus pies:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

La misma precaución se aplica a `V{ }` y a otros literales vacíos. En algunos lenguajes, `[]` o `vec![]` reservan un contenedor nuevo cada vez que se evalúa la expresión. En Factor, el literal `V{ }` escrito en tu código fuente es *un solo* objeto, compartido por cada punto del código que lo menciona. Si haces `push` directamente sobre `V{ }`, la siguiente llamada verá los restos. `V{ } clone` crea la copia nueva que casi siempre quieres.
