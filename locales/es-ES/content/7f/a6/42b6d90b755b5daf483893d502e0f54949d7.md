# Introducción a los fundamentos del shell

## Shells

Un _shell_ es un programa que te permite introducir comandos para interactuar con el sistema operativo.
Los shells pueden ser gráficos; el entorno de escritorio que usas con el ratón o el panel táctil es un shell.
Nos centraremos en las interfaces de línea de comandos, en las que escribes comandos y los resultados se imprimen (normalmente) en tu terminal.

Existen muchos shells de línea de comandos diferentes.
Windows ofrece **cmd** y **powershell**.
Mac y Linux ofrecen «shells de Unix», de los que hay muchos.
El shell predeterminado de Mac es **zsh**.
**csh** es un shell heredado con una sintaxis similar a la de C.
**bash** es uno de los shells más populares, sobre todo en Linux.

Uno de los primeros shells es el shell de Bourne, **sh**.
Con el tiempo, este shell se [estandarizó][posix] para incluirse en todos los sistemas tipo Unix.
Muchos shells se basan en el shell de Bourne y a menudo aportan funcionalidades adicionales de interacción o de programación.

**Bash** se basa en el shell de Bourne.
Por eso se llama «**B**ourne-**a**gain **sh**ell».
Es el shell predeterminado en muchos sistemas Linux.
Bash ofrece muchas facilidades que lo convierten en un shell interactivo agradable, entre ellas:

* un indicador totalmente personalizable,
* la capacidad de recuperar y modificar comandos del historial,
* la capacidad de manipular procesos en ejecución,
* alias que reducen lo que hay que teclear,
* y mucho más.

Este track no trata sobre cómo usar bash como shell interactivo.
Trata sobre aprender a escribir programas con bash.
El énfasis estará en usar _solo_ bash para resolver problemas, aunque no hay restricciones para llamar a herramientas externas.

## Fundamentos de bash: comandos y argumentos

Bash lee comandos de su entrada (que normalmente es un terminal o un fichero).
Cada línea de entrada que lee se trata como un _comando_: una instrucción que hay que llevar a cabo.
(Hay algunos casos avanzados, como los comandos que abarcan varias líneas, que veremos más adelante.)

Bash divide cada línea en **palabras** delimitadas por un espacio en blanco (espacios y tabulaciones).
La primera palabra de la línea es el nombre del _comando_ que se va a ejecutar.
Todas las palabras restantes se convierten en _argumentos_ de ese comando (opciones, nombres de fichero, etc.).

~~~~exercism/note
En los ejemplos siguientes te mostramos algunos comandos interactivos que puedes ejecutar.

* El carácter `#` inicia un _comentario_.
  El shell ignora todas las palabras que siguen al comentario; el comentario solo es para leerlo.
* El carácter `$` indica el indicador del shell. 
  Si copias el comando, no incluyas el indicador.
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm` es una aplicación que elimina los ficheros que se le pasan.
`*` es un carácter [glob][glob], un patrón «comodín» que coincide con todos los ficheros del directorio actual.
Hablaremos más sobre los globs más adelante.

¿Te has fijado en que hay varios espacios entre `a` y `b`, y solo uno entre `b` y `c`?
¡La cantidad de espacio en blanco entre argumentos no importa!
Por ejemplo:

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo` es un comando que imprime sus argumentos en la salida estándar (que en nuestro caso es el terminal).
Bash divide el comando en cinco palabras e invoca el comando `echo` con cuatro argumentos.
Los espacios adicionales del segundo ejemplo no suponen ninguna diferencia.
`echo` no sabe cuántos espacios había originalmente entre las palabras.

Si queremos conservar el espacio en blanco adicional, tenemos que pasar la frase como un único argumento.
Podemos hacerlo usando [comillas][Quotes]:

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

Las comillas agrupan todo lo que hay dentro de ellas en un _único argumento_.
El argumento es `This    is    a    test.`, incluidos esos caracteres de espacio concretos.
Ten en cuenta que las comillas no forman parte del argumento: bash las elimina antes de pasar ese único argumento a `echo`.

Los argumentos se separan del nombre del comando y entre sí mediante un espacio en blanco.
Es importante recordarlo.
Por ejemplo, lo siguiente es incorrecto:

```bash
$ [-f file]
bash: [-f: command not found
```

La intención es comprobar si existe un fichero llamado `file`.
Es razonable suponer que el espacio en blanco alrededor de `[` y `]` da igual, pero `[` es en realidad un comando y exige que su último argumento sea `]`.
(Veremos el comando `[` con más detalle más adelante.)
Por lo tanto, debemos separar `[` de `-f` y `]` de `file`.
De lo contrario, bash pensará que estamos intentando ejecutar un comando llamado `[-f` con un único argumento `file]`.
El comando correcto separa todos los argumentos con espacio en blanco:

```bash
$ [ -f file ]
```

(Vemos a mucha gente confundida por este comportamiento; creen que `[...]` es «solo sintaxis» y que pueden omitir los espacios; `[` es un comando y el espacio en blanco es obligatorio.)

Si el nombre de nuestro fichero contiene espacios en blanco u otros caracteres especiales, también hay que entrecomillarlo:

```bash
$ [ -f "my file" ]
```

## Tipos de comandos

Bash entiende varios tipos distintos de comandos: alias, funciones, comandos integrados, palabras clave y ejecutables.
Todos ellos son _comandos_ y todos actúan de forma muy similar.

De forma predeterminada, los alias solo están habilitados en los shells interactivos, no en los scripts de shell.
No los trataremos aquí.

### Funciones

Una función contiene comandos de shell y se comporta de forma muy parecida a un script pequeño; incluso puede recibir argumentos y crear variables locales.
Cuando se llama a una función, se ejecutan los comandos que contiene.
Las funciones se tratarán en profundidad más adelante.

### Comandos integrados

Bash tiene algunos comandos básicos integrados, como `cd` (cambiar de directorio), `echo` (escribir salida), etc.
Se pueden concebir como funciones que ya vienen incluidas.

### Palabras clave

Las palabras clave son como los comandos integrados, con la diferencia principal de que en realidad son sintaxis de bash y pueden analizarse con reglas especiales.
Por ejemplo, `[` es un comando integrado de bash, mientras que `[[` es una palabra clave de bash; ambos se usan para comprobar diversas condiciones.
Pero la palabra clave `[[` tiene algunas funcionalidades adicionales.
Por ejemplo, proporciona el operador `=~`, que realiza comprobaciones con expresiones regulares.

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

Los operadores de comparación de cadenas `<` y `>` son otro ejemplo de cómo las palabras clave analizan el código de forma distinta.
Dentro de `[[...]]`, estos operadores no necesitan ningún cuidado especial.

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

Pero dentro de `[...]` debes entrecomillarlos o escaparlos para evitar que el shell los analice como operadores de redirección.

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### Ejecutables

El último tipo de comando que puede ejecutar bash es un _ejecutable_.
Son ficheros ejecutables (programas) del sistema de ficheros de tu ordenador que puedes ejecutar.
(A los ejecutables también se los puede llamar _comandos externos_ o _aplicaciones_.)
Normalmente, para invocar un ejecutable basta con escribir su nombre; por lo general no hace falta la ruta completa del fichero.
Esto es posible porque bash usa una variable predefinida que le ayuda a encontrar la ubicación de los ficheros ejecutables habituales.
Esta variable se llama `PATH`.
Es un conjunto de nombres de directorio separados por dos puntos (por ejemplo, `/usr/bin:/bin`). 
Cuando se especifica un comando (por ejemplo, `myprogram` o `ls`) sin una ruta de fichero (y no es un alias, una función, un comando integrado ni una palabra clave), bash busca en los directorios de `PATH`.
Los directorios se buscan en orden, de izquierda a derecha, para ver si contienen un ejecutable con el nombre dado.

Si el ejecutable está fuera de una ruta conocida, habrá que especificar su ruta de fichero.
Para el ejecutable `myprogram` del directorio actual, usa `./myprogram`; si está en el directorio `/opt/somedirectory`, usa `/opt/somedirectory/myprogram`.

Consejo: el comando `type` sirve para obtener detalles sobre el comando:

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## Scripts

Un _script_ es una secuencia de comandos almacenada en un fichero.
Bash lee el fichero y procesa los comandos en orden.
Pasa al siguiente comando solo cuando ha terminado el actual.
La excepción es cuando se ha especificado que un comando se ejecute de forma asíncrona (en segundo plano).
No te preocupes demasiado por este caso todavía; ya veremos cómo funciona más adelante.

Cualquier ejemplo de línea de comandos de esta guía también se puede usar en un script.

Crear un script es fácil.
Empieza creando un fichero nuevo y pon esto en la primera línea:

```bash
#!/bin/bash
```

Esta línea se llama _directiva de intérprete_ (también se la llama _hashbang_ o **_shebang_**).
Especifica que hay que usar `/bin/bash` como intérprete cuando el fichero se usa como ejecutable en un comando.
Cuando el kernel del sistema operativo ejecuta un _fichero no binario_, lee la primera línea del fichero.
Si la línea empieza por `#!`, el kernel la usa para determinar a qué intérprete pasar el fichero.
(También hay otras formas válidas de hacerlo; consulta más abajo.)
El `#!` debe estar al principio mismo del fichero, sin espacios ni líneas en blanco antes.
Los comandos de nuestro script aparecerán en líneas separadas por debajo de esta.

Consejo: en lugar de `#!/bin/bash`, puedes usar

```bash
#!/usr/bin/env bash
```

`env` busca en `$PATH` el ejecutable indicado por su primer argumento (en este caso, «bash»).
Para una explicación más detallada de esta técnica y de en qué se diferencia del simple `#!/bin/bash`, consulta [esta pregunta en StackOverflow][env bash].

No te dejes engañar por los scripts o ejemplos de Internet que usan `/bin/sh` como intérprete.
**¡`sh` no es `bash`!**
Bash en sí es un shell «compatible con sh», lo que significa que puede ejecutar la mayoría de los scripts `sh` y comparte buena parte de su sintaxis.
Sin embargo, lo contrario no es cierto; algunas funcionalidades de bash fallan o provocan un comportamiento inesperado en `sh`.
De hecho, no existe un único shell `sh`.
Hay muchas implementaciones de shell que admiten la sintaxis de POSIX sh.
Según tu sistema operativo, cuando ejecutas `sh` puede que en realidad estés ejecutando bash, ash, dash u otro shell.

Una vez creado el fichero del script, se puede ejecutar así:

```bash
$ bash myscript
```

En este ejemplo, ejecutamos el _comando_ `bash` y le decimos que lea el script que le hemos pasado como _argumento_.
Cuando lo hacemos así, la línea `#!` es solo un _comentario_.

Como alternativa, podemos dar a nuestros scripts permisos de ejecución.
Con este método podemos ejecutar el script como cualquier otro ejecutable en lugar de llamar a bash manualmente:

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

Cuando ejecutamos el comando de esta forma, el sistema operativo usa la línea `#!` para determinar qué intérprete debe usar para ejecutar tu script.
