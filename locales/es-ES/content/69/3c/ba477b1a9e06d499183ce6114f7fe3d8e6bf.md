# Acerca de

Se puede acceder a los caracteres individuales de un `String` con el mismo método de subíndice que se usa con los arrays.
Sin embargo, los [índices][string-indices] que se usan con los strings _no_ son números enteros y no se puede trabajar con ellos directamente.
En su lugar, hay que calcularlos a partir de otro índice conocido, como `startIndex`, que apunta a la posición del primer carácter de un string no vacío, usando los métodos disponibles en las bibliotecas [`String`][string-docs] y [`NSString`][nsstring-docs] (cuando se importa el módulo `Foundation`, los strings de Swift tienen acceso a todas las propiedades y métodos de NSString).

Por ejemplo, dado el siguiente string:

```swift
let csv = "apple,pear,peach,orange,cherry,lime,goosberry"
```

No se puede escribir `csv[21]` para obtener la «g» de «orange»; en su lugar hay que calcular un valor de tipo `String.Index` y proporcionar ese índice.
Ten en cuenta que estos índices no están pensados para que los consuman los humanos por sí solos.
Son lo que se conoce como _índices opacos_, ya que los humanos no necesitan saber qué hay dentro de ellos.

```swift
let index = csv.index(csv.startIndex, offsetBy: 21)
csv[index]
// "g"
print(index)
// prints Index(_rawBits: 1376513)
```

Ten en cuenta, sin embargo, que si el desplazamiento no es un índice válido, es decir, si devolviera el índice anterior a `startIndex` o posterior a `endIndex`, la operación generará un error y el programa se bloqueará.
Para evitar este problema, se puede especificar un índice límite.
Este devuelve un índice opcional y valdrá nil para índices que de otro modo no serían válidos.

```swift
let tooFar = csv.index(csv.startIndex, offsetBy: 200)
// error: Execution was interrupted, reason: EXC_BAD_INSTRUCTION (code=EXC_I386_INVOP, subcode=0x0).
let tooFarButSafe = csv.index(csv.startIndex, offsetBy: 200, limitedBy: csv.endIndex)
// nil
```

Además, los índices no se pueden compartir entre strings.
Por ejemplo, si usas el `index` de la «g» de «orange» calculado antes para indexar el string `fam = "This is my family: 👨‍👩‍👦‍👦, this is our dog: 🐶, this is our cat: 🐱!"`, es decir, `fam[index]`, el programa se bloqueará.

Hay muchas razones para todo esto, pero básicamente todas se reducen a que «Unicode es complicado».

En términos generales, si necesitas acceso aleatorio a caracteres individuales, probablemente te convenga usar otra estructura de datos, como `Array<Character>`.

## Algunos métodos útiles

Swift tiene los métodos `first` y `last` para obtener el primer y el último carácter de un string.
Estos métodos devuelven un carácter opcional, así que si el string está vacío, devolverán nil.

```swift
let str = "Hello, world!"
print(str.first) // Prints Optional("H")
print(str.last)  // Prints Optional("!")
```

También puedes usar los métodos `prefix` y `suffix` para obtener una subcadena de un string.
Estos métodos toman un número entero como argumento y devuelven una subcadena que contiene los primeros o los últimos n caracteres del string.

```swift
let str = "Hello, world!"
print(str.prefix(5)) // Prints "Hello"
print(str.suffix(6)) // Prints "world!"
```

## En profundidad: indexación de Unicode

~~~~exercism/advanced

[Unicode][unicode] es un estándar para codificar texto, e incluye una gran cantidad de caracteres de muchos idiomas y sistemas de escritura distintos.
Es un superconjunto de ASCII, lo que significa que todos los caracteres ASCII son también caracteres Unicode.
Unicode es una codificación de longitud variable, lo que significa que algunos caracteres ocupan más bytes que otros.
Y por qué eso importa se explicará en la siguiente sección.

Así que tenemos que ir a otros idiomas (distintos del inglés) para ver el problema de verdad; tomemos el carácter «ü» del alemán (fíjate en que aquí estamos usando la variante de 2 bytes, también existe una versión de 1 byte).
A primera vista puede parecer un solo carácter, pero en realidad son dos caracteres: «u» y «¨», así que si imprimieras la longitud del string «ü» sería 2 en lenguajes como Python.
Sin embargo, como usuario o como programador diríamos que es un solo carácter, y Swift está de acuerdo con nosotros.
Pero ¿por qué lo hace Swift y Python no?
La respuesta es que Swift usa una representación de los strings distinta de la de Python.
En Python, los strings se representan como una secuencia de bytes, lo que significa que la longitud de un string es el número de bytes que ocupa en memoria.
En Swift, los strings se representan como una secuencia de caracteres, lo que significa que la longitud de un string es el número de caracteres que contiene.
Esta distinción es muy importante, porque significa que en Swift la longitud de un string no es necesariamente igual al número de bytes que ocupa en memoria.
Esto, a su vez, es lo que hace que no podamos usar números enteros para indexar strings.
