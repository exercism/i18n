## Opcionales

Swift utiliza [_opcionales_][optionals] para que los programadores puedan representar la posible ausencia de un valor.
Un opcional es un tipo que puede contener un valor o ser [`nil`][nil], que representa la ausencia de un valor.
Usar un opcional requiere que el programa compruebe si existe realmente un valor antes de usarlo tras desenvolverlo.

Cualquier tipo puede convertirse en un opcional añadiendo un `?` al final del nombre del tipo.
Así, un entero opcional tendría el tipo `Int?` y un string opcional tendría el tipo `String?`.
Definir constantes o variables de tipo opcional y asignarles valores se hace igual que con los valores de tipos no opcionales.

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

Puedes asignar la ausencia de un valor a una variable de tipo opcional asignándole el valor especial `nil`.
`nil` puede usarse con todos los tipos opcionales, pero los `nil` asignados a dos tipos opcionales diferentes no tienen el mismo tipo, y no se pueden intercambiar ni siquiera comparar.

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

Ten en cuenta también que, aunque `nil` puede asignarse a cualquier tipo opcional, no puede asignarse a un tipo no opcional (aunque en realidad no contenga `nil`).
Y a los métodos que esperan un tipo no opcional no se les puede pasar un tipo opcional sin desenvolverlo primero.

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## Cómo usar los opcionales

Como los tipos opcionales no son los mismos tipos que sus tipos base, ambos tipos no pueden usarse de la misma manera.
Por ejemplo: `Int("123") + 1` da lugar a un error del compilador: «Value of optional type 'Int?' must be unwrapped to a value of type 'Int'».
Esto se debe a que `Int("123")` devuelve un tipo `Int?` opcional, no un tipo `Int`, ya que si el string no puede convertirse a un entero, el resultado será `nil`.
Para acceder al `Int` de la conversión, primero hay que «desenvolverlo».

En Swift, esto se hace habitualmente con las construcciones `if-let` y `guard-let` para el [_enlace opcional_][optional-binding], que comprueban si hay `nil` y siguen un camino de código con el valor desenvuelto enlazado a un nombre dado si existe un valor, y siguen un camino de código distinto si se encontró `nil`.

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

Merece la pena señalar que la variable `safeNum` tiene el tipo `Int` y no `Int?`.
En el ejemplo siguiente, `num` es de tipo `Int?` y `safeNum` es de tipo `Int`.

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

Este _enlace opcional_ es importante porque desenvuelve (o «elimina») el tipo opcional del valor, lo que permite usarlo como un valor no opcional.
Si solo hicieras una comprobación condicional de si el valor es `nil`, el valor seguiría siendo de tipo opcional:

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

La opción `guard-let` también puede usarse en los casos en los que se desea un retorno anticipado:

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## Comparación de opcionales

Ten en cuenta que, aunque el tipo base de un par de opcionales se puede comparar con los operadores de comparación estándar, los propios opcionales no se pueden comparar.
Solo se puede comprobar si son iguales.
Dos opcionales son iguales si ambos son `nil` o si los valores que envuelven son iguales dentro de sus tipos base.

No obstante, se puede escribir código para realizar una comparación personalizada de dos valores opcionales.
A continuación se muestra un ejemplo de una instrucción `switch` que devolverá `true` solo si ambos valores opcionales no son nil y el primer valor es menor que el segundo.
Para ello, usa el _patrón opcional_ `varName?`, que solo coincide con opcionales que no son nil, enlazando el valor dentro del opcional al nombre `varName`.

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## Coalescencia de nil

Existe otra opción para desenvolver, que consiste en usar un [valor de reserva][fallback] si hay `nil`.
Esto puede hacerse con el _operador de coalescencia de nil_, `??`. Suponiendo que `x` es un `Int?`, si escribes `let y = x ?? 0`, Swift comprobará si x es `nil`.
Si no lo es, desenvolverá `x` y asignará el valor desenvuelto a `y`; y si `x` _es_ `nil`, asignará 0 a `y`.

Como `x ?? y` es simplemente una forma abreviada de `x != nil ? x! : y`, si `x` no es nil, la expresión `y` no se evalúa en absoluto.

Por último, hay que señalar que el operador de coalescencia de nil es asociativo por la derecha, lo que puede dar lugar a resultados sorprendentes para quien no lo sabe.

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

Puedes leer más sobre el operador de coalescencia de nil en [A Tour of Swift: Nil-Coalescing Operator][nil-coalescing].
