# Ejecutar los tests

Desde la terminal, cambia al directorio base del ejercicio y ejecuta los tests con:

```bash
$ mix test
```

Esto ejecutará el fichero de test que se encuentra en la subcarpeta `test`, un fichero que termina en `_test.exs`

Documentación:

* [`mix test`, la herramienta de Elixir para ejecutar tests](https://hexdocs.pm/mix/Mix.Tasks.Test.html)
* [`ExUnit`, la biblioteca de tests unitarios de Elixir](https://hexdocs.pm/ex_unit/ExUnit.html)

## Tests pendientes

En las suites de tests de los ejercicios de práctica, todos los tests menos el primero están etiquetados para omitirse.

Cuando consigas que un test pase, puedes dejar de omitir el siguiente comentando el `@tag :pending` correspondiente con el símbolo `#`.

Por ejemplo:

```elixir
# @tag :pending
test "shouting" do
  assert Bob.hey("WATCH OUT!") == "Whoa, chill out!"
end
```

Si quieres ejecutar todos los tests a la vez, puedes incluir todos los tests omitidos usando la opción `--include` en el comando `mix test`:

```bash
$ mix test --include pending
```

O puedes habilitar todos los tests comentando la línea `ExUnit.configure` del fichero `test/test_helper.exs`.

```elixir
# ExUnit.configure(exclude: :pending, trace: true)
```

## Opciones útiles de `mix test`

* `test/<FILE>.exs:LINENUM`: ejecuta solo un test, el test de `<FILE>.exs` cuya definición está en la línea `LINENUM`
* `--failed`: ejecuta solo los tests que fallaron la última vez que se ejecutaron
* `--max-failures`: la suite deja de evaluar tests cuando se alcanza este número de
tests fallidos
* `--seed 0`: desactiva la aleatoriedad, de modo que los tests de un mismo fichero siempre se ejecuten en el mismo orden en que se definieron
