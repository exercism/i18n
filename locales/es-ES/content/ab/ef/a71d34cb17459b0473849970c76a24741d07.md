# Acerca de

`String` y `&str` son dos formas fundamentales de trabajar con datos textuales en Rust. Conocer sus características y cómo funcionan juntas resulta muy útil. Este documento analiza en qué se solapan y ofrece algunos consejos básicos.
`String` es un vector de bytes `u8` con propiedad.
`String` es mutable.
`&str` es una referencia prestada a un slice de String.
`&str` es inmutable.

La pronunciación correcta de `&str` es «ref string».
`String` es una representación, potencialmente mutable, de una secuencia de puntos de código Unicode codificada en UTF-8.

`&str` es una vista de solo lectura de una secuencia UTF-8 bien formada.
Como es una referencia, es `Copy` y se puede compartir.

En Rust, no se puede acceder por índice a `String` y `&str` como quizá harías en otros lenguajes.
Por ejemplo, esto no funciona:

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

Esto se debe a las siguientes propiedades:

- Los strings son UTF-8, cuya unidad primitiva no es un byte, sino un punto de código Unicode: `char`.
- Los puntos de código Unicode ocupan hasta 4 bytes, pero se codifican con un ancho variable.
- Por lo tanto, es imposible calcular la posición del `n`-ésimo punto de código sin iterar sobre los caracteres codificados reales, porque a partir del primer carácter, la posición del siguiente depende de cuán anchos hayan sido los anteriores.
- Por este motivo, los autores de la biblioteca estándar de Rust decidieron no implementar el trait `Index` para los strings: si bien indexar un array de bytes lleva un tiempo constante, indexar un string puede llevar bastante tiempo. Esto viola el principio de la mínima sorpresa.

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## Convertir un `String` en un `&str`

`String` implementa `Deref<Target=str>`.
Este trait tiene cierto tratamiento especial por parte del compilador: significa que cualquier referencia a un `String` puede convertirse automática y transparentemente en un `&str`.
Esto implica lo siguiente:

- Cualquier código que espere, por ejemplo, un argumento `&str` también puede aceptar un `&String`.
- Cualquier método implementado para `&str` también se puede llamar sobre un `String`.

(Si se quisiera aceptar de forma genérica cualquier tipo de referencia a un `str`, se podría usar un argumento de tipo `impl AsRef<str>`, pero lo habitual es tipar los argumentos como `&str`).

## Convertir un `&str` en un `String`

Hay muchas formas de crear un `String` a partir de un `&str`:

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

Todas las formas anteriores requieren reservar memoria para el `String` (en el heap).
Por eso `&str` está disponible en no_std pero `String` no.

(El crate [heapless](https://crates.io/crates/heapless) se usa a menudo para manipular
strings en no_std).

## Usar String y `&str` en structs

Esta sección analiza cuándo usar `String` o `&str` en los campos de una struct.
A menudo verás structs definidas con `String` en lugar de `&str` para los valores de sus campos.

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

Al usar `String`, la struct es dueña de los datos.
Esto hace que el código sea más fácil de leer y de enseñar para principiantes.
Pero también significa que se harán reservas en el heap para cada campo.
`&str` toma prestados los datos textuales, por lo que rinde mejor, a cambio de que tu struct tenga que definir parámetros de tiempo de vida.
El [tutorial del crate csv][csv-tutorial] demuestra y explica estas ideas de forma muy práctica.

## Notas sobre el rendimiento

Los `String` se asignan en el heap, por lo que pueden resultar más costosos de usar.
Los `&str` son una referencia compartida, así que no requieren reasignaciones frecuentes.
