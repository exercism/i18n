# Acerca de los caracteres

¡Este tema puede llegar a ser _enorme_!
Es posible escribir un libro muy largo sobre él, y varias personas lo han hecho (busca «unicode book» en Amazon para ver algunos ejemplos).

## Una historia muy breve

Manejar caracteres en los ordenadores era mucho más sencillo en décadas pasadas, cuando quienes programaban daban por hecho que el inglés era el único idioma importante.
Así que: 26 letras, mayúsculas y minúsculas, 10 dígitos, varios signos de puntuación y un código (0x07) para hacer sonar una campana, y todo cabía en 7 bits: el conjunto de caracteres [ASCII][wiki-ascii].

Como es natural, la gente empezó a preguntar qué pasaba con à, ä y Ł, luego otras personas empezaron a preguntar por ऄ, ஹ y ญ, y los más jóvenes querían emojis 😱.
¿Qué se podía hacer?

Para abreviar una larga historia, muchas personas inteligentes y pacientes tuvieron que formar parte de comités durante años, trabajando en los detalles del conjunto de caracteres [Unicode][web-unicode] y de codificaciones como [UTF-8][wiki-utf-8], y mucho software necesitó una reescritura _muy_ complicada.
Además, se introdujeron muchos bugs nuevos.

Para evitar que _todo_ se rompiera, el diseño de Unicode/UTF-8 garantiza que los primeros 127 códigos sean idénticos a ASCII _(incluso la campana)_.

## Los caracteres en Kotlin

Los lenguajes diseñados a partir de 2005 aproximadamente tienen la enorme ventaja de que ya existía un estándar Unicode razonablemente estable.

Kotlin (publicado por primera vez en 2011) pudo dar por hecho que sus usuarios usarían una variedad de idiomas (humanos) y que necesitarían Unicode para expresarlos.

~~~~exercism/advanced
Los [caracteres][ref-char] en Kotlin son [`codepoints`][wiki-codepoint] de 16 bits (UTF-16), igual que un `char` de la JVM.
Esto basta para expresar la mayoría de los alfabetos escritos, pero no toda la gama de emojis.

El estándar Unicode completo usa hasta seis bytes (48 bits) por carácter (lo que se denomina [`grapheme`][wiki-grapheme]).

Los `Strings` de Kotlin admiten este estándar completo usando varios codepoints por carácter, cuando es necesario.
Por ejemplo, 😱 sería `\uD83D` y `\uDE31`.

Lamentablemente, Java no tiene soporte de graphemes integrado y, por compatibilidad, Kotlin tampoco.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


Los literales de carácter se escriben entre comillas simples y son distintos de los strings escritos entre comillas dobles.
Probablemente esto sea evidente para quien viene del mundo de C/C++, pero puede resultar confuso para quienes programan en Python y JavaScript.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

Convertir entre `Char` e `Int` es sencillo:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

El compilador permite _algunas_ formas de aritmética de enteros con `Char`s:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## Algunas funciones para `Char`

Como siempre, hay [demasiadas funciones][ref-char-lib] para tratarlas aquí, así que esto es solo una selección.

- En los alfabetos adecuados, cambia entre mayúsculas y minúsculas con [`uppercase()`][ref-uppercase] y [`lowercase()`][ref-lowercase].
- Comprueba el uso de mayúsculas y minúsculas con [`isUpperCase()`][ref-isuppercase] y [`isLowerCase()`][ref-islowercase].
- Comprueba el tipo de carácter con:
  - [`isLetter()`][ref-isletter], abarca muchos alfabetos (las categorías Lu, Ll, Lt, Lm y Lo de unicode)
  - [`isDigit()`][ref-isdigit], en el rango 0..9 (la categoría Nd de unicode)
  - `isLetterOrDigit()`, combina las dos anteriores
  - [`isWhitespace()`][ref-iswhitespace], cualquier carácter de espacio en blanco (las categorías Cc, Zp, Zl y Zs de unicode)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

Además, las [expresiones regulares][ref-regex] (que serán el tema de un concepto posterior) permiten búsquedas y manipulaciones potentes.

## Conversiones entre listas de Char y strings

Para convertir un `String` en una `List` de `Char`s, podemos usar `toList()`.

Para convertir una `List` de `Char`s en un `String`, existe la función [`joinToString()`][ref-jointostring], que recibe un separador (a menudo el string vacío) como argumento.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

Ten en cuenta que `joinToString()` opera sobre una List o un Array.
Para _forzar_ la conversión de un único `Char` a un string de 1 carácter, usa `toString()`.

```kotlin
'a'.toString() // => "a"
```

Para comprobar si un carácter está presente en un `String`, o en una lista o un array de `Char`, tenemos `in`, que se corresponde con la función [`contains()`][ref-contains].

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
