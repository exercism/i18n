# Constructores de strings

`STR` es inmutable; `FSTR` no lo es. Usa `STR` para el texto ya terminado y `FSTR` para el texto que todavía se está construyendo.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## No olvides reasignar el resultado

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR` crece mediante **duplicación amortizada**: cuando se queda sin espacio, toma un array nuevo y más grande, el doble de tamaño, y copia en él. Así que el resultado suele ser el mismo objeto y, de vez en cuando, uno distinto. Escribir `b := b + x` cada vez es correcto en ambos casos, y es la única forma que vale la pena aprender.

La duplicación es lo que hace que el trabajo total sea proporcional a la longitud en lugar de a su cuadrado: las copias se vuelven más escasas con la misma rapidez con la que se vuelven más costosas.

## ¿Por qué no usar simplemente `+` con STR?

Unir un número fijo y pequeño de piezas con `+` es claro y está bien:

```sather
   return piece + " by " + composer;
```

El problema aparece solo en un bucle, donde el número de uniones no se conoce cuando se escribe el código. Una regla aproximada: si el `+` está dentro de un `loop`, echa mano de `FSTR`.

## Rutinas útiles

| Llamada | Hace |
| --- | --- |
| `b + x` | añade al final; `x` puede ser `STR`, `CHAR`, `INT`, `BOOL` … |
| `b.size` | cuántos caracteres lleva hasta ahora |
| `b.str` | un `STR` terminado |
| `b.clear` | lo vacía, conservando el espacio |

## Secuencias de escape

| Escrito | Es |
| --- | --- |
| `"\n"` | una línea nueva |
| `"\t"` | un tabulador |
| `"\""` | una comilla doble |
| `"\\"` | una barra invertida |
