# Iteradores personalizados

Has estado usando iteradores desde `bird-survey`. Ahora vas a escribir uno.

## yield

Un iterador se parece a una rutina con dos diferencias: su nombre termina en `!`, y entrega valores con `yield` en lugar de con `return`.

```sather
   markers!(count : INT) : INT is
      loop
         yield 100 * 1.upto!(count);
      end;
   end;
```

`yield` entrega un valor al bucle que llamó al iterador y luego **espera**. Cuando ese bucle vuelve a dar la vuelta, el iterador continúa justo después del `yield`, con todo exactamente como lo dejó: sus variables, su propio bucle, su posición.

Eso es un iterador: una rutina que puede pausarse en mitad y reanudarse.

```sather
   loop
      #OUT + TRAIL::markers!(3) + " ";      -- 100 200 300
   end;
```

## Finalización

Un iterador termina de una de estas dos maneras.

**Agotarse.** Cuando el propio bucle del iterador termina, o la rutina llega a su final, se acabó, y el bucle que lo llamó termina de inmediato.

**quit.** `quit` lo termina ahí mismo, sin entregar nada.

```sather
   named!(names : ARRAY{STR}) : STR is
      loop
         name ::= names.elt!;
         if name = "" then quit; end;
         yield name;
      end;
   end;
```

Entrega nombres hasta que se encuentra con uno vacío, y se detiene. `quit` es para un iterador lo que `return` es para una rutina, salvo que no lleva ningún valor: ya no queda nada que entregar.

## once

Un argumento marcado como `once` se calcula una sola vez, cuando empieza el bucle, en lugar de en cada vuelta:

```sather
   markers!(once count : INT) : INT is
```

Úsalo para cualquier cosa que no cambie entre vueltas, lo cual se aplica a la mayoría de los argumentos. Los propios iteradores de la biblioteca lo hacen: `upto!(once i : SAME)`.

## Iteradores sin valor

Un iterador no tiene por qué entregar nada. `times!` es uno:

```sather
   steps!(once count : INT) is
      loop
         ignored ::= 1.upto!(count);
         yield;
      end;
   end;
```

Un `yield` a secas no entrega nada y simplemente deja que el bucle dé una vuelta.

## Dónde vive la posición

Cada *lugar del programa* que llama a un iterador mantiene su propia posición, y por eso llamar dos veces al mismo iterador dentro del cuerpo de un bucle lo recorre dos veces. Ahora ya ves por qué: las dos llamadas son dos rutinas pausadas distintas.
