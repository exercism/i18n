# Instalación

Este track se apoya en [Node.js][web-nodejs] en todo momento para ofrecer un entorno de ejecución para JavaScript.
Esto significa que damos por sentado que toda la ejecución de JavaScript en tu ordenador se hará con [Node.js][web-nodejs].

## Requisitos del track

Muchos ordenadores vienen con [Node.js][web-nodejs] preinstalado, o puede que se haya instalado antes, o como dependencia.
Así que, antes de hacer nada, conviene comprobar si ya está instalado:

1. Abre un _terminal_ (`Terminal`, `cmd`, `Powershell`, `bash`, ...)
1. `node -v`

Si [Node.js][web-nodejs] está instalado, se mostrará una versión.
Anota esa versión.
Si [Node.js][web-nodejs] _no_ está instalado, se mostrará un error.
Normalmente, algo parecido a `'node' is not recognised`.

## Node.js

### Si Node.js ya está preinstalado

Ve a [la web de Node.js][web-nodejs].
Te mostrará _dos_ versiones (si detecta tu sistema operativo; si no, selecciona primero el tuyo).
Si tu versión de `node -v` coincide con una de ellas, todo en orden.
Si no coincide, te recomendamos que uses Node.js LTS.
Si te preocupa que actualizar pueda romper algo en tu sistema, puedes continuar como si todo fuera bien;
puede que no podamos ofrecerte soporte cuando ocurra algo inesperado.

### Si Node.js no está instalado

Hay un par de formas de instalar [Node.js][web-nodejs]:

- con un [instalador o binario][web-nodejs-download]
- con un [gestor de paquetes][web-nodejs-package]

Ambas opciones son compatibles con Windows, macOS y Linux. Si no sabes qué hacer, lo más fácil es usar un instalador.

- Te recomendamos usar la versión **LTS**. También aparece indicada como _recomendada_ en la web de [Node.js][web-nodejs] «para la mayoría de los usuarios».
- Sigue las instrucciones de la página web o del instalador, e instala [Node.js][web-nodejs].

## Probar la instalación

Cuando el instalador haya terminado, o el gestor de paquetes haya finalizado, o se haya copiado el binario y se hayan seguido las instrucciones, es buena idea probar que todo esté bien.

1. Abre un _terminal_ (`Terminal`, `cmd`, `Powershell`, `bash`, ...)
1. `node -v`

La versión debería coincidir con la de la web.

> [!NOTE]
> Es importante abrir una ventana de terminal _nueva_.
> Puede que las ventanas de terminal que ya estén abiertas no se hayan actualizado al terminar la instalación.
> Esto significa que los terminales abiertos no saben que se ha instalado un programa nuevo.

> [!IMPORTANT] > _**Ayuda**_: `'node' is not recognised`
>
> Si has usado el instalador oficial, tu `PATH` debería haberse configurado automáticamente, pero si tu shell tiene problemas para localizar tus módulos instalados globalmente, o si compilas Node.js desde el código fuente, actualiza tu `PATH` para incluir los binarios de `npm`.
>
> En macOS y Linux puedes hacerlo añadiendo lo siguiente a `~/.bash_profile` o a `~/.zshrc`:
>
> ```shell
> export PATH=/usr/local/share/npm/bin:$PATH
> ```
>
> En Windows, abre el menú de inicio y busca «environment variables».
> Tendrás que editar la entrada `PATH` y _añadir_ aquí la ruta a los binarios de `npm`.
> Normalmente, se encuentran en `C:\Program Files\nodejs`.
> Si navegas hasta ahí con el `File Explorer`, deberías encontrar `node.exe`, `npm.bat` y `npx.bat`.
>
> Cierra cualquier terminal abierto y abre uno nuevo.

## Habilitar corepack

Para usar un gestor de paquetes versionado compatible con este track, hay que habilitar `corepack` una vez:

```shell
corepack enable pnpm
```

## Requisitos de los ejercicios

Sigue [estas instrucciones][cli-walkthrough] para descargar la CLI de Exercism para tu sistema operativo.

Una vez configurada la CLI, descarga el primer ejercicio, `hello-world`:

```shell
exercism download --exercise=hello-world --track=javascript
```

Cada ejercicio necesita después algunas herramientas para ejecutar los tests.
Se pueden instalar ejecutando este comando dentro del directorio de cada ejercicio:

```shell
corepack pnpm install
```

Como este track ha cambiado a pnpm, no deberías preocuparte por el espacio en disco.
Echa un vistazo a [pnpm](https://pnpm.io/), que garantiza que solo se instale una copia de cada versión de paquete en el disco.

> **Pero ¿qué es corepack y por qué funciona esto?**
>
> No necesitas esta información para completar el track de JavaScript, pero si tienes ganas de entender qué acaba de pasar, los siguientes párrafos son para ti:
>
> Esto funciona porque `corepack` es una herramienta que viene incluida con Node.js, que se ha instalado siguiendo los pasos anteriores.
> Puede instalar el gestor de paquetes `pnpm`. Configura el sistema.
> El comando `corepack` busca un archivo `package.json`, que está presente en _cada_ carpeta de ejercicio.
> Después comprueba `packageManager`, que coincide con `pnpm`, así que puede continuar. Si es necesario, primero actualizará `pnpm`.
> Este archivo también lista las `"dependencies"` de arriba, que `pnpm` descarga y coloca en una caché local.
>
> Los scripts de `package.json` usan los binarios de la caché local, y son estos scripts los que se usan para ejecutar los tests, como se indica en la descripción del `exercise`.
