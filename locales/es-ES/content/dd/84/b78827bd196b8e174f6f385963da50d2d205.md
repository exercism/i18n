# Introducción

Los punteros inteligentes son una funcionalidad moderna de C++ diseñada para proporcionar una gestión automática de la memoria, lo que ayuda a prevenir las fugas de memoria y los punteros colgantes que suelen asociarse a los punteros sin procesar.
Actúan como envoltorios alrededor de los punteros sin procesar, añadiendo funcionalidad adicional, como la liberación automática de memoria cuando el puntero ya no es necesario.

## Sintaxis general

Los punteros inteligentes se implementan normalmente como plantillas de clase en la biblioteca estándar de C++.
Los dos punteros inteligentes que más se usan son `std::unique_ptr` y `std::shared_ptr`.

## Punteros únicos

`std::unique_ptr` es un puntero inteligente que posee el objeto en exclusiva.
Garantiza que, en cualquier momento, solo un objeto `std::unique_ptr` posea el recurso.
Cuando el `std::unique_ptr` propietario se destruye o se restablece, destruye automáticamente los objetos y libera su memoria.

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## Ventajas de `std::make_unique()`

Al crear un `std::unique_ptr`, es preferible usar `std::make_unique()` en lugar de usar `new` directamente para asignar memoria.
`std::make_unique()` ofrece varias ventajas:
1. **Seguridad frente a excepciones**: `std::make_unique()` garantiza la seguridad frente a excepciones.
  Si se lanza una excepción durante la construcción del objeto, la memoria se liberará automáticamente, lo que evita fugas de memoria.
2. **Claridad**: usar `std::make_unique()` hace que el código sea más claro y conciso.
  Elimina la necesidad de especificar explícitamente el tipo que se asigna, ya que los argumentos de plantilla se deducen automáticamente.
3. **Oportunidades de optimización**: los compiladores tienen la oportunidad de optimizar `std::make_unique()` de forma más eficaz que si se asigna memoria manualmente con `new`, lo que puede dar lugar a un mejor rendimiento.
4. **Evitar un uso incorrecto**: es posible eliminar el recurso subyacente cuando el `std::unique_ptr` se construye manualmente.
  Eso daría lugar a un comportamiento indefinido cuando el `std::unique_ptr` intente eliminarlo al final de su scope.

## Punteros compartidos

`std::shared_ptr` es un puntero inteligente que permite que varios objetos `std::shared_ptr` compartan la propiedad del mismo recurso.
Lleva la cuenta de cuántos punteros compartidos hacen referencia al recurso y libera la memoria solo cuando el último puntero compartido que posee el recurso sale del scope o se restablece.

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
En C++17 y versiones anteriores, no se admite directamente usar `std::shared_ptr` con arrays mediante `std::make_shared<T[]>`.
Aunque es posible asignar arrays con `std::make_shared<T[]>`, crear punteros compartidos directamente a partir de ellos puede dar lugar a un comportamiento indefinido debido a las diferencias en la gestión de memoria entre objetos individuales y arrays.
En su lugar, considera usar `std::vector` o funciones de eliminación personalizadas para gestionar arrays con punteros compartidos de forma eficaz.
Asegúrate siempre de la compatibilidad con tu compilador y tu implementación de la biblioteca estándar cuando trabajes con asignaciones de arrays y punteros compartidos en C++17.
~~~~

## Ventajas de `std::make_shared()`

Al igual que `std::make_unique()`, `std::make_shared()` ofrece beneficios como una mayor eficiencia de memoria, seguridad frente a excepciones y legibilidad.
Combina la asignación de memoria del bloque de control y del objeto gestionado en una sola operación, lo que mejora la eficiencia y reduce el riesgo de fugas de memoria.
Además, la deducción automática de los argumentos de plantilla simplifica el código y mejora la legibilidad.
Usar `std::make_shared()` favorece un código más limpio, seguro y eficiente cuando se trabaja con objetos `std::shared_ptr` en C++.

## Punteros débiles

`std::weak_ptr` es una clase complementaria de `std::shared_ptr` que proporciona una referencia «débil» no propietaria a un objeto gestionado por un puntero compartido.

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

Los punteros débiles son útiles en escenarios en los que hay que romper referencias cíclicas para evitar fugas de memoria.
`std::weak_ptr` se diseñó para resolver el problema de la propiedad cíclica, también conocida como referencias circulares, que puede aparecer al usar `std::shared_ptr`.
En un escenario de propiedad cíclica, dos o más objetos `std::shared_ptr` se referencian entre sí, creando un ciclo en el que ninguno de los objetos puede eliminarse porque tienen referencias fuertes entre ellos, lo que provoca fugas de memoria.
`std::weak_ptr` ofrece una solución a este problema al permitir referencias débiles a objetos compartidos sin contribuir a su recuento de referencias.
Esto significa que puede observar y acceder al objeto compartido, pero no impide que se elimine.
~~~~

## Consejos de uso

Usa los punteros inteligentes de forma predeterminada: `std::unique_ptr` para la propiedad exclusiva y `std::shared_ptr` para la propiedad compartida.
Reserva los punteros sin procesar para referencias no propietarias o cuando interactúes con código heredado.
En la mayoría de los casos, `std::unique_ptr` basta para la propiedad exclusiva, ya que ofrece una gestión de memoria ligera sin el coste adicional del recuento de referencias.
`std::shared_ptr` debería usarse con moderación, ya que introduce coste adicional y complejidad a menos que se necesite una propiedad compartida real.
`std::weak_ptr` está especializado en romper dependencias cíclicas u observar objetos compartidos, pero no se usa con frecuencia.
