# Acerca de

La memoria dinámica se implementa mediante funciones de biblioteca que el programador usa para asignar y liberar memoria en tiempo de ejecución.
Como el programador controla la asignación y la liberación de memoria, la memoria dinámica es tan segura como lo sea el programador a la hora de evitar errores humanos.
Por ese motivo, la memoria dinámica es una de las principales fuentes de bugs de programación y uno de los principales objetivos de los ataques de hacking.

La memoria dinámica se usa para variables cuyo tamaño solo se conoce en tiempo de ejecución.
Esto suele ser útil para arrays cuyo número de elementos puede variar de una ejecución a otra.
Los arrays de longitud variable (VLA) son otra forma de manejar arrays cuyo tamaño de elemento solo se conoce en tiempo de ejecución.
Un VLA usa almacenamiento automático, lo que significa que su memoria se destruye al salir del bloque en el que se define.
(Para saber más sobre el almacenamiento, consulta el concepto [especificadores de clase de almacenamiento](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers).)
Los VLA se incorporaron al lenguaje C con C99, pero a partir de C11 los VLA son opcionales, así que los compiladores que admiten C11 y versiones posteriores no tienen por qué admitir los VLA.
Un análisis detallado de los arrays de longitud variable queda fuera del alcance de este artículo.

## malloc

`malloc` es una función declarada en `stdlib.h` que se usa para asignar memoria dinámica.
Si la asignación se realiza correctamente, se devuelve un puntero que apunta a la dirección del primer byte de la memoria asignada.
Si la asignación no se realiza correctamente, se devuelve `NULL`.
Es prudente comprobar si el resultado de `malloc` es `NULL` y gestionarlo con elegancia si falla.
El puntero devuelto es de tipo `pointer-to-void`, que puede considerarse a grandes rasgos como un puntero «genérico» que se puede convertir al tipo específico que usa la memoria.
`malloc` tiene un parámetro, que es el tamaño en bytes de la memoria que se desea.
El tamaño total para asignar un array es el tamaño del tipo de dato de cada elemento multiplicado por el número de elementos.
El operador `sizeof` se usa habitualmente para obtener el tamaño del tipo de dato de cada elemento.
El siguiente ejemplo lo demuestra

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

Es importante recordar que la memoria recién asignada por `malloc` no se inicializa, sino que puede contener valores basura.
Ten en cuenta que el `sizeof` del puntero `numbers` no es el número de elementos del array ni la cantidad total de memoria asignada.
El tamaño del puntero devuelto por `malloc` es el tamaño de cualquier puntero en ese sistema concreto.
El código del ejemplo se ejecutó en un sistema de 64 bits, así que el tamaño del puntero era de 8 bytes (multiplicado por 8 bits por byte = 64 bits).
El tipo del puntero se convirtió implícitamente de pointer-to-void a pointer-to-int.
Que el pointer-to-int apunte a un solo `int` o a un array de `ints` es algo que el programador puede gestionar como considere oportuno.
Por ejemplo

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

Si con seguridad se van a escribir los valores antes de leerlos, usar `malloc` puede ser una forma eficiente de asignar memoria.
Pero si existe la posibilidad de que los valores se lean antes de inicializarlos, usar `malloc` es arriesgado.
Una forma más segura de asignar memoria es usar `calloc`, que inicializa a cero la memoria recién asignada.

Fíjate en que en los ejemplos anteriores se usó `free(numbers)`.

## free

`free` es una función declarada en `stdlib.h` que se usa para liberar memoria que se ha asignado dinámicamente.
La memoria asignada dinámicamente sigue reservada hasta que `free` la libera.
Algunos sistemas operativos pueden liberar automáticamente la memoria asignada dinámicamente cuando el programa termina, pero lo recomendable es no depender de ello.
`free` tiene un parámetro, que es un puntero a la memoria que se asignó dinámicamente.
El uso o la falta de uso de `free` se asocia con varios problemas de memoria.

#### fuga de memoria

No liberar la memoria asignada dinámicamente después de que la referencia a esa memoria llegue al final de su vida útil, o se destruya de otro modo, se conoce como fuga de memoria.
La memoria fugada es memoria que el sistema tiene reservada pero a la que el programa ya no puede acceder.
Esto puede ser un problema especialmente grave si se asigna memoria dentro de un bucle, no se libera al final del bucle y se vuelve a asignar al principio de este.
Si se asigna suficiente memoria sin liberarla, la llamada para asignar memoria fallará porque no quedará memoria suficiente disponible.
Es importante recordar que, aunque el sistema mantenga reservada la memoria asignada dinámicamente hasta que se libere, el puntero al que se asigna puede tener solo scope de bloque.
Por ejemplo, en los ejemplos de `malloc`, la memoria se asigna en `my_function`.
Se produciría una fuga de esa memoria si el puntero a ella no se devolviera y se usara para asignar el puntero `numbers` en `main`.
Por tanto, pasar ese puntero `numbers` a `free` libera la memoria asignada en `my_function`.

#### uso después de liberar (**UAF**)

Si se accede a la memoria después de liberarla, los valores pueden ser cualquier cosa.
En el siguiente ejemplo, se libera la memoria a la que apunta `numbers` y después se lee en `printf`.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

El puntero `numbers`, una vez liberado, se conoce como puntero colgante.
Un puntero colgante puede apuntar a una memoria distinta de la que se pretendía.
Por tanto, un puntero colgante puede provocar corrupción de datos y la sustitución y ejecución de código arbitrario.
Un puntero a memoria asignada que no se ha limpiado asignándole `NULL` se puede usar para hackear el programa.
En el ejemplo anterior, si se hubiera asignado `NULL` a `numbers` así: `numbers = NULL;` después de liberarlo, el `printf` siguiente provocaría la finalización del programa, quizá informando de un fallo de segmentación al intentar leer `numbers[0]`.

#### doble liberación

Si se llama a `free` dos veces sobre un puntero a memoria asignada dinámicamente, se produce un comportamiento indefinido (**UB**).
Esto significa que el compilador puede gestionarlo de forma arbitraria como quiera.
El siguiente ejemplo, compilado con dos compiladores distintos, puede tener dos resultados diferentes

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

El primer y el segundo compilador no generaron ningún error en tiempo de ejecución cuando se asignó `NULL` a `numbers` entre cada llamada a `free`, pero no hay garantía de que eso funcione con un tercer compilador.
Una causa habitual de la doble liberación es tener dos punteros que apuntan a la misma memoria asignada dinámicamente.
Un puntero puede apuntar al principio de un array en un punto del programa, y el otro puntero puede usarse para recorrer el array en otro punto del programa.
En distintos puntos del programa se libera cada puntero, lo que provoca una doble liberación.

## calloc

`calloc` es una función declarada en `stdlib.h` que se usa tanto para asignar memoria dinámica como para inicializar a cero la memoria recién asignada.
Si la asignación se realiza correctamente, se devuelve un puntero que apunta a la dirección del primer byte de la memoria asignada.
Si la asignación no se realiza correctamente, se devuelve `NULL`.
Es prudente comprobar si el resultado de `calloc` es `NULL` y gestionarlo con elegancia si falla.
El puntero devuelto es de tipo `pointer-to-void`, que puede considerarse a grandes rasgos como un puntero «genérico» que se puede convertir al tipo específico que usa la memoria.
`calloc` tiene dos parámetros.
El primer parámetro indica cuántos elementos del tipo de dato especificado se van a asignar.
El segundo parámetro indica el tamaño del tipo de dato especificado que se va a asignar.

En el siguiente ejemplo, todas las instrucciones `printf` deberían mostrar siempre `0`, ya que `calloc` garantiza poner a cero los valores recién asignados.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` es una función declarada en `stdlib.h` que se usa para ampliar o reducir memoria ya asignada.
Si la reasignación se realiza correctamente, se devuelve un puntero que apunta a la dirección del primer byte de la memoria reasignada.
Si la reasignación no se realiza correctamente, se devuelve `NULL`.
Es prudente comprobar si el resultado de `realloc` es `NULL` y gestionarlo con elegancia si falla.
`realloc` tiene dos parámetros.
El primer parámetro es un puntero a la memoria existente que se va a reasignar.
El segundo parámetro indica el tamaño en bytes de la memoria reasignada.
Los valores que se asignaron antes de ampliar la memoria se conservan.
Es importante recordar que la memoria que se añade al ampliar no se inicializa a cero y sus valores pueden ser cualquier cosa.
Además, la memoria que se elimina al reducir tampoco se inicializa y podría conservar los valores.
El siguiente ejemplo muestra cómo ampliar y reducir un array

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## Cuando el tamaño pasado es 0

Si el tamaño que se pasa a `malloc`, `calloc` o `relloac` es `0`, lo que ocurre depende de cómo lo implemente el compilador.
Un compilador puede devolver un puntero `NULL` o un puntero no nulo.
Por ejemplo, si se asigna memoria para un puntero a `char`, el compilador puede devolver `NULL` o un puntero no nulo a un string vacío.
Para evitar resultados distintos con compiladores distintos, lo mejor es no asignar con un tamaño de 0.
