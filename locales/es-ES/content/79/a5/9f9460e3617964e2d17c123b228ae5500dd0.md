# Introducción

Ya *has usado* streams en `channel-chatter` y te has deshecho de ellos en `boatswains-bilge`. Este ejercicio es tu primer stream personalizado: una clase que implementa el [protocolo][stream-protocol] para que el mismo código `with-input-stream` / `read1` / `stream-read1` que funcionaba con un `<string-reader>` funcione con el tuyo.

## Mixins: la otra mitad de la jerarquía de clases

Ya conoces `TUPLE: child < parent …` de `dragons-descendants`, una jerarquía de un solo padre en la que los slots descienden. Factor tiene una *segunda* forma de extender el grafo de clases: los **mixins abiertos**. Un `MIXIN: m` declara una clase sin slots a la que otras clases pueden unirse a posteriori con `INSTANCE: c m`. La pertenencia es de muchos a muchos: una clase puede ser instancia de tantos mixins como quiera.

El protocolo de streams usa dos mixins para marcar qué mitad de la interfaz implementa una clase:

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

Un stream puede ser uno, el otro o ambos. Los métodos genéricos de `input-stream` (o `output-stream`) despachan entonces a cualquier clase que se haya unido al mixin: así es como el `read1`, `stream-contents`, `with-input-stream`, etc. del entorno encuentran el camino hasta tu clase.

Los mixins son *abiertos*: puedes añadir un nuevo miembro después de que se declare el mixin, incluso en un vocabulario diferente. Ese es el contraste con `TUPLE: < parent`, donde la relación queda fijada cuando se declara la clase hija.

## Los genéricos del protocolo

Los genéricos del protocolo viven en `io`:

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

`stream-read1` devuelve el siguiente byte (o `f` al llegar al final del stream); `stream-write1` escribe uno. `stream-read-unsafe` es la lectura por lotes de más bajo nivel que proporcionan la mayoría de los streams de entrada; `stream-read` se construye sobre ella y se encarga de la asignación. `stream-element-type` indica si el stream trabaja con bytes (`+byte+`) o con caracteres (`+character+`); cuando envuelves otro stream, la implementación más sencilla simplemente delega en el stream subyacente.

## La limpieza viene de `destructors`

Los streams son desechables: un stream personalizado extiende `disposable` e implementa `dispose*`. Ese es el framework de `boatswains-bilge`, aplicado a una clase de stream:

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

Una vez que eso está en su sitio, todos los combinadores `with-…` de `channel-chatter` funcionan en tu stream automáticamente.
