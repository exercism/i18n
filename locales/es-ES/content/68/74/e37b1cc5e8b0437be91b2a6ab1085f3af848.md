# Acerca de

[concept:csharp/resource-cleanup]() usa la interfaz `IDispose` para indicar a quienes llaman a una clase que hay recursos o estado del programa que deben liberarse o restablecerse a su debido tiempo cuando el objeto en cuestión ya no es necesario. En este ejercicio hemos introducido algo de azúcar sintáctico, con la palabra clave `using`, que hace que el código sea menos verboso y menos probable que se omitan llamadas importantes.

El `using` puede considerarse un sustituto de [`try/finally`][try-finally] en algunos casos de uso.

```csharp
File file = null;
try
{
    file = new File("myStuff.txt");
    file.Write("more stuff");
}
finally
{
    file.Dispose();
}
```

Esta sintaxis se sustituye por esta otra, más compacta e infalible:

```csharp
using (var file = new File("myStuff.txt")
{
    file.Write("more stuff");
}
```

Ten en cuenta que se pueden combinar varios recursos cómodamente siguiendo las reglas habituales para bloques de una sola línea:

```csharp
using (var file = new File("mystuff.txt")
using (var fileWriter = new StreamWriter(file)
{
     ...
}
```

En C# 8 se introdujo la siguiente variante, en la que la instrucción `using` aparece al principio de un bloque:

```csharp
using var file = new File("myStuff.txt");
file.Write("more stuff");
```

Esto te permite tener varios objetos desechables en el mismo bloque y gestionar de forma más natural [`try/catch`][try-catch]:

```csharp
using var fileIn = new File("myStuff.txt");
using var fileOut = new File("yourStuff.txt");
try
{
    var stuff = fileIn.Read();
    fileOut.Write(stuff);
}
catch (Exception)
{
    LogStuff();
}
```

Las reglas sobre cómo se puede usar la palabra clave `using` y con instancias de qué tipos se detallan [aquí][using-statement].

## Nota para desarrolladores de Java

Es posible que los desarrolladores de Java reconozcan esto como un análogo del mecanismo de [_gestión automática de recursos_][automatic-resource-management] introducido en Java 7. Son muy similares. La sintaxis de Java, que reutiliza `try`, tiene la ventaja de incorporar los bloques `catch` de forma más natural que el `using` de C#.

## Versiones

Ten en cuenta que la versión más flexible de `using`, en la que no tiene su propio bloque sintáctico, se introdujo en C# 8, así que puede que necesites comprobar si la base de código en la que trabajas usa C# 8 o una versión posterior.
