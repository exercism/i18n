# Rasgos

Un rasgo especifica un conjunto de métodos que un tipo puede implementar.
Los rasgos son útiles para definir métodos que deben compartirse entre tipos.
Cuando se usan rasgos con tipos genéricos, los métodos definidos se pueden llamar en un tipo concreto, pero también es posible llamarlos en otro tipo de dato.
De forma abstracta, con el uso de _límites de rasgo_, podemos especificar que el tipo genérico debe compartir cierto comportamiento.

> **Nota:** Los rasgos tienen una característica similar a lo que en otros lenguajes de programación se conoce como interfaces, con algunas diferencias.

## Definición de un rasgo

Definir un rasgo ayuda a identificar la signatura de función que compondrá el conjunto de comportamientos que un tipo puede implementar para lograr un resultado.
Estos métodos forman el comportamiento de un tipo.
Si podemos llamar a los mismos métodos en tipos distintos, eso implica que los tipos implicados tienen el mismo comportamiento.

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

Según la definición del rasgo `Summary` anterior, el método `summarize` es un comportamiento que solo se puede llamar desde el tipo struct `NewsArticle`.
Si se invoca en instancias de otro tipo, lanza un error de compilación.
Declarar el rasgo con la palabra clave `pub` expone el rasgo de este crate a otros crates que también quieran usarlo.
Fíjate también en que usamos un punto y coma después de declarar las signaturas de los métodos en los rasgos.

Un rasgo se puede definir con un argumento genérico, lo que permite que una función acepte un argumento de cualquier tipo de dato.
Esto aporta flexibilidad a la signatura de la función y le permite manejar distintos tipos de datos.
En el caso del rasgo `Summary` de abajo, se ha rediseñado para funcionar con cualquier tipo de dato, de modo que cuando se invoca el método `summarize` sobre ellos, devuelve un ByteArray.

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

Un rasgo puede tener más de un método en su cuerpo; cada signatura de método declarada es una sola línea que termina con punto y coma.

## Implementación de un rasgo en un tipo

Después de definir las signaturas de función que componen un rasgo, el compilador exigirá que se defina también una implementación para los tipos que adoptan el rasgo.
Abajo hemos escrito un crate de biblioteca `aggregator` de medios de comunicación que resume algunos datos de instancias de `NewsArticle` y `Tweet`.
Para el struct `NewsArticle`, usaríamos el titular, el autor y la ubicación para devolver el valor del método `summarize` del rasgo `Summary`; mientras que para el struct `Tweet` usaríamos el nombre de usuario y el contenido, suponiendo que el contenido del tuit tiene un límite de 280 caracteres.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## Implementaciones por defecto

A veces, un rasgo se puede definir con una implementación por defecto para algunos o todos los métodos que lo componen.
Así se evita tener que implementar todos los métodos en cada tipo y se mejora la legibilidad del código.
Si un tipo concreto necesita una implementación especial de un método del rasgo, puede sobrescribir la implementación por defecto.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## Cómo usar y gestionar rasgos externos

Los rasgos y las implementaciones se pueden definir en un módulo externo y usarse en otros módulos, siempre que se importen correctamente.
Supongamos que tenemos un rasgo `ShapeGeometry` con el método `boundary`, que debe implementarse tanto para el struct `Circle` como para el struct `Rectangle`.
Abajo tienes un ejemplo de cómo se importan, gestionan y usan el rasgo y la implementación entre módulos.

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

La visibilidad de las implementaciones `CircleGeometry` y `RectangleGeometry` no necesita ser pública, ya que el rasgo `ShapeGeometry` es público y el compilador debería encontrarlo sin problema.

## Alias de impl

Se pueden crear alias de las implementaciones al importarlas, usando la palabra clave `impl`.
Esto ayuda a la hora de instanciar una implementación genérica para tipos concretos.
Vamos a definir una implementación trivial del rasgo `Two` para todos los tipos que implementan el rasgo `One`, simplemente sumando dos veces el valor de `One` y devolviendo la suma.
Después podemos exponer la implementación de `Two` que solo funciona para los tipos `u8` y `u128`.

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

La implementación genérica se puede escribir en un módulo privado y, con el uso del alias de impl, podemos instanciar la implementación genérica de estos dos tipos concretos.
La ventaja de usar una implementación genérica privada y no expuesta es que evita la duplicación de código entre archivos.
Además, mantiene la API pública sencilla y limpia.
