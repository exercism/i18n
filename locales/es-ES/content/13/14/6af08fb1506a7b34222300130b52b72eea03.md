# Instrucciones

Cuanto más aprendes sobre programación, más empiezas a pensar que esto podría ser algo más que una moda pasajera.
Incluso puede que haya oportunidades de negocio: la gente escribe código, quiere guardarlo, compartirlo, colaborar y hasta recibir comentarios.

Vale, vamos a ello, construyamos un servicio que anime a la gente a programar: ¡hup, hup, gente, empezad a usar git!
Vamos a llamarlo... GitHup.

Te pones a construir una API REST JSON: usuarios, pull requests, comentarios; el backend se hace en un momento.
Aquí tienes un ejemplo del payload que sirve el servidor cuando le pides el array de comentarios de un pull request:

```json
[

      "id": 101,

      "site_admin": false
    },
    "body": "Great stuff!",
    "side": "RIGHT",
    "_links": {
      "self": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
      },
      "html": {
        "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1"
```

Por supuesto, el frontend se hará en Elm, pero primero tienes que averiguar de qué van esos famosos decodificadores y codificadores.

```exercism/note
Aparte de la historia humorística, los requisitos del ejercicio están tomados directamente de los endpoints de la API REST de GitHub para los comentarios de revisión de pull requests.
Se han eliminado algunos campos de los esquemas JSON para simplificar, pero esto es lo más parecido a una aplicación del mundo real que te vas a encontrar.
```

## 1. ¡Tu ID, por favor!

Tu ojo de halcón se ha dado cuenta de que tanto los comentarios como los usuarios tienen un campo `id`; un sitio perfecto para empezar.

Define `decodeId` para que pueda decodificar un objeto JSON con un `id` entero.

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. ¿Cómo me llamo ya?

Te has fijado en que, en el ejemplo de arriba, no todos los usuarios tienen un nombre.

Define `decodeName` para que pueda decodificar un string en el campo `name` si lo hay.
¿Que no hay nombre? No pasa nada, simplemente devuelve `Nothing`.
Este decodificador no debe fallar nunca.

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. ¿Usuario? ¡Apenas lo conozco!

Ya llevamos medio camino en lo que a decodificar usuarios se refiere, vamos a terminarlo.

Define `decodeUser` para que pueda decodificar un objeto JSON de usuario.
Asegúrate de usar `decodeId` y `decodeName` dentro de `decodeUser`.

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. Soy un comentario fuerte e independiente

Algunos comentarios de una revisión de pull request son independientes y, por lo tanto, no tienen un `pull_request_review_id`.
Sin embargo, la especificación indica que, en ese caso, debe seguir habiendo un campo `pull_request_review_id`, pero su valor debe ser `null`, el `Nothing` de los pobres.

Define `decodePullRequestReviewId` para que pueda decodificar un entero en el campo `pull_request_review_id` si lo hay.
Si no hay un entero, debe haber un `null`; si no hay un `null`, el decodificador debe fallar.

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. Un trabajillo extra

Ahora le toca a este interesante campo `side`.
En una revisión de pull request puedes comentar el código que se ha eliminado (en el lado `Left` de la pantalla) o el código que se ha añadido (en el lado `Right` de la pantalla).

Define `decodeSide` para que pueda decodificar `"LEFT"` o `"RIGHT"` en el campo `side` y asociarlo con su variante de tipo correspondiente.

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. El despertar de los enlaces

Cada comentario tiene un conjunto de enlaces, que no parece ser consistente entre comentarios.

Define `decodeLinks` para que pueda decodificar una colección de URLs en el campo `_links`.
Los nombres y el número de enlaces pueden variar; asegúrate de tenerlo en cuenta.
Los enlaces son en sí objetos JSON que siempre deben tener un campo `href`.

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. Sí, comentarios

Ya casi está, vamos a terminarlo.

Define `decodeComment` y `decodeComments` para que puedan decodificar un único objeto de comentario JSON o un array de comentarios, respectivamente.
Asegúrate de usar en `decodeComment` todas las funciones definidas hasta ahora, con la excepción de `decodeName`.
Por supuesto, `decodeComments` también debe usar `decodeComment`.

## 8. Todo encaja

Todavía falta una funcionalidad más: poder enviar un comentario nuevo al servidor.
Para ello necesitas lo contrario de un decodificador, ser capaz de transformar un `Comment` de Elm en un `Value` JSON.

Define `encodeComment` para que pueda codificar cualquier `Comment` válido.
El orden de los campos da igual, siempre que el codificador pueda producir un valor que `decodeComment` sea capaz de decodificar.
