# Fundamentos de Unison

## Términos y funciones

Los términos y las funciones son las unidades básicas para escribir un programa en Unison.

Un «término» es lo que llamamos un valor estático. Se define con `name = expression`, opcionalmente precedido por una firma de tipo con la forma `name : MyType`. Unison admite la inferencia de tipos, así que es posible que veas la firma de tipo omitida en definiciones sencillas.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Las funciones de Unison tienen el aspecto de `myFunctionName argument1 argument2 = myImplementation`; empiezan por el nombre de la función seguido de argumentos separados por espacios.

```
getMax a b = Nat.max a b
```

Las funciones pueden incluir opcionalmente una firma de tipo. El último tipo de la derecha es siempre el tipo devuelto final de la función, y cada argumento está separado por la flecha de función `->`.

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Para llamar a una función, usa su nombre seguido de sus argumentos separados únicamente por espacios.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Al llamar a una función, Unison intentará tratar como su argumento lo que venga inmediatamente a la derecha, lo que no siempre dará lugar al orden de evaluación de funciones deseado.

Supongamos que queremos obtener el valor `1` de la siguiente expresión:

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Tal y como está escrita, `shouldBe1` se evalúa como `0` porque el orden implícito de aplicación de funciones es `getMax 1 10`, que es `10`, y después `10 - 10`, que es `0`.

Puedes usar paréntesis para reagrupar la expresión en el orden de operaciones deseado.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Watch expressions

Unison ofrece una forma de evaluar código rápidamente llamada «watch expression». Una watch expression empieza por el símbolo `>` y va seguida de la expresión que se quiere evaluar. Las watch expressions pueden escribirse en cualquier fichero con extensión `.u`. Al guardar el fichero, deberías ver a qué se evalúa la expresión en la consola de Unison Codebase Manager (UCM). Cuando sea posible, en esta documentación intentaremos mostrar una expresión con su salida esperada tras evaluarla en una watch expression.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Funciones de varias líneas

Las funciones de varias líneas de Unison usan la sangría o bloques `let` para especificar los límites del código, también conocidos como «scope léxico».

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Todo lo que está al mismo nivel de sangría comparte el mismo scope, y por eso podemos hacer referencia a la variable `newBeginning` en la última línea.

## Espacios de nombres e instrucciones `use`

Los espacios de nombres son la forma en que agrupamos y organizamos las funciones de Unison. Puedes pensar en ellos como algo análogo a los «directorios». Aportan estructura y agrupación lógica.

Puedes traer las funciones de un espacio de nombres a tu scope con una instrucción `use`.

Supongamos que estás escribiendo una función que usa valores `List` de Unison. Sabes que necesitarás funciones como `List.map` y `List.flatMap`, donde `List` es el espacio de nombres y `map` y `flatMap` son funciones. Para no repetirte, puedes optar por traer todo lo del espacio de nombres `List` al scope léxico de tu función de esta forma:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

La línea `use List` desambigua las referencias a `map` y `flatMap`. Puedes leer más sobre [las instrucciones `use` aquí][use-statements].

## La biblioteca estándar de Unison

La biblioteca estándar de Unison se llama `base`. Si has seguido la guía de inicio rápido y tienes una base de código creada localmente, la biblioteca estándar debería haberse descargado automáticamente. Puedes consultar la documentación de la biblioteca estándar en línea en [Unison Share][unison-share-base].

## Comentarios y literales de documentación

Los comentarios en Unison son una característica un tanto inusual. Cuando escribes código de Unison, puedes crear en tu fichero con extensión `.u` texto que no se interpreta, con la siguiente sintaxis:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

*Sin embargo*, como el código de Unison se guarda como un hash de su árbol de sintaxis abstracta y no como ficheros de texto en el sistema de archivos, los comentarios que son «decoraciones» basadas en texto de una función o un término de Unison del fichero no pueden realmente guardarse y volver a mostrarse para compartirlos. Si quieres añadir información a tu término de Unison de forma que se almacene para que otras personas puedan leerla y entenderla, puedes usar un literal de documentación.

La documentación es un valor de primera clase en el lenguaje de programación Unison. Eso significa que un elemento `Doc` puede asignarse a un valor, pasarse como valor a una función o devolverse como valor de una función. Los elementos de literal de documentación se abren y se cierran con llaves dobles. Así podríamos usar el elemento `Doc` a modo de comentario.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
