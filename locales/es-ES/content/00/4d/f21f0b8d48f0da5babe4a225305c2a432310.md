# Acerca de

[8th](https://8th-dev.com) es un lenguaje de tipado fuerte, derivado de FORTH y basado en la pila, con sintaxis RPN.

8th es compatible con las plataformas android, ios32, lin64, mac64, rpi32 y win64. 8th te permite usar tu plataforma preferida para escribir y probar tu código. Con un solo clic, generas los ejecutables *para* cualquier plataforma que 8th admita, *desde* cualquier plataforma que admita.

8th incluye todo lo que necesitas: compatibilidad con interfaces gráficas multiplataforma, cifrado fuerte, soporte para bases de datos SQLite, FFI, acceso REST, localización sencilla, acceso al hardware, soporte para JSON, un REPL y mucho más.

En 8th, la seguridad no se deja para después. Se diseñó desde el principio para evitar los problemas de seguridad de software más comunes. Trabajamos continuamente para hacerlo aún más seguro.

8th tiene un [foro](https://8th-dev.com/forum/) y también una extensa documentación que incluye un [manual](https://8th-dev.com/manual.html) y un diccionario con hipervínculos de [palabras](https://8th-dev.com/words.html) del núcleo y de la biblioteca. ¡[Compara](https://8th-dev.com/compare.html) 8th con otros lenguajes!


## Introducción rápida para usuarios de lenguajes «convencionales»

Si vienes de C o de Java, o de la mayoría de los lenguajes más comunes, puede que 8th te resulte un poco desconcertante. Para ayudarte a empezar con buen pie, aquí tienes algunas de las principales diferencias entre 8th y «lo convencional», además de algunos consejos útiles:

* Como consecuencia de la forma en que el intérprete busca los elementos, debes declarar un var o una palabra antes de usarlos por primera vez. Si no lo haces, se producirá la excepción can’t find ...

* Un var es un contenedor con nombre para otros elementos. No es el nombre del elemento al que se refiere. Así, var x puede contener un array, pero es un error intentar acceder a x como si fuera un array en sí mismo, y hacerlo provocará que se lance una excepción.

* No puedes declarar un var dentro de una palabra (es decir, como local de ella), ¡no lo intentes! Sin embargo, puedes usar w:@ y w:! para acceder a variables locales de la palabra.

* Intenta escribir tus propias palabras de modo que se puedan encadenar con otras palabras. Por ejemplo: las «palabras de fichero» realizan alguna operación sobre un fichero y dejan el elemento de fichero en la pila (y quizá otra información) para que la siguiente palabra trabaje con él.

* Mantén tus palabras cortas. Coméntalas. Asegúrate, sobre todo, de comentar el efecto sobre la pila, y…

* … prueba cada palabra que escribas (preferiblemente mientras la escribes o poco después), asegurándote de que se ajusta a su SED (Stack-Effect Diagram) documentado. Esto te ayudará a escribir código sin bugs. Vuelve a probarla si cambias el SED o el código.

* Consulta las palabras help y apropos para obtener detalles sobre la acción según el SED y los efectos secundarios de cualquier palabra de la que no estés seguro.

* En 8th, una excepción es un error fatal y hará que la aplicación se cierre (este es el comportamiento predeterminado). No esperes poder «capturarla» y gestionarla de forma efectiva.

* No hay ciclo de compilación y enlazado. En su lugar, 8th es un motor que primero interpreta tu código y, si es necesario, lo compila en tiempo de ejecución. Cuando se ejecuta en un dispositivo, tu código es código nativo para la plataforma, no bytecode que se ejecuta dentro de una máquina virtual.
