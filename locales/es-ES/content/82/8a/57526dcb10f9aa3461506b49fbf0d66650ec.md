# Acerca de

El ensamblador escrito a mano está lleno de repeticiones.
La misma secuencia corta de instrucciones aparece una y otra vez, con pocas variaciones, y hay pocas abstracciones para reducir el código repetitivo.
Además, programar en ensamblador exige gestionar valores sin una semántica evidente.
No hay parámetros con nombre y el programador debe gestionar a mano la mayoría de los detalles de la maquinaria subyacente.

NASM, el ensamblador que usa el track, ofrece algunas herramientas que pueden ayudar al programador con ambos problemas.
Estas herramientas se ejecutan en _tiempo de ensamblado_, antes de que ninguna instrucción llegue al procesador.
Guían al ensamblador sobre cómo reescribir el texto fuente antes incluso de que se traduzca a código máquina.

La más importante de estas herramientas son las **macros**, que pueden entenderse como una receta para el ensamblador.
Se expanden en el lugar donde se usan, como si el código se hubiera escrito allí a mano.

[Las macros][macro] pueden tomar varios tokens literales como parámetros, lo que las hace reutilizables en distintos contextos.
Sin embargo, no son funciones: no hay `call`, ni `ret`, ni transferencia de control a otro punto del código.

## Macros de una línea

La definición más sencilla da un nombre a un valor o a una expresión corta con `%define`:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Cada aparición posterior de `WIDTH` se sustituye por `8` antes del ensamblado.
La sustitución es textual, así que el nombre se reemplaza allí donde aparezca, ya sea en un operando o dentro de otra definición.

~~~~exercism/note
Para _constantes_ numéricas, es preferible usar `equ` en lugar de `%define`.

Una macro de una línea declarada con `%define` solo se expande cuando se usa, y puede reasignarse o dejarse sin definir.
Una constante `equ`, en cambio, se evalúa en el punto de definición y nunca se modifica.
~~~~

Un `%define` también puede tomar parámetros _con nombre_, comportándose como una pequeña función en línea:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Encierra entre paréntesis tanto el cuerpo completo como cada parámetro.
Con `%define square(x) x*x`, la llamada `square(1+1)` se expande a `1+1*1+1`, que es `3`.
Escrito como `%define square(x) ((x)*(x))`, la misma llamada se expande a `((1+1)*(1+1))`, que es `4`.
~~~~

Los nombres definidos con `%define` distinguen entre mayúsculas y minúsculas.
La variante `%idefine` hace que el nombre no distinga entre mayúsculas y minúsculas, si así se desea.

Las macros de una línea son útiles para dar significado a distintas partes del código.
Si se usan con cuidado, mejoran la legibilidad y reducen la probabilidad de errores tipográficos.
Por ejemplo, un registro con un propósito concreto dentro de una función puede definirse según su propósito:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Macros de varias líneas

Toda una secuencia de código, con cualquier número de líneas, se captura con `%macro` y se cierra con `%endmacro`.
Un número después del nombre indica cuántos argumentos toma la macro, que pueden ser cero.
Cuando se pasan argumentos, se separan con una coma (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Los argumentos de las macros de varias líneas no tienen nombre.
Se referencian como `%1`, `%2`, etc., en el orden en que se pasan:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Ten en cuenta que los argumentos deben ser sintaxis válida para las operaciones que se realizan en el cuerpo de la macro.
Aquí `mult_two eax, ecx` y `mult_two r8, r9` se ensamblan ambos, pero `mult_two eax, cl` no, ya que `imul eax, cl` no está definido.

Las macros también pueden tomar un número arbitrario de argumentos.
Esto se hace con la notación `n-*`, donde `n` es el número mínimo de argumentos:

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

En una macro de varias líneas, `%0` denota el _número_ de argumentos de la macro.
Esto es especialmente útil en macros que pueden tomar un número arbitrario de argumentos.

### Etiquetas dentro de una macro

Una macro que define una etiqueta normal se rompe en cuanto se usa dos veces, porque entonces la etiqueta también quedaría definida dos veces.
Para usar etiquetas dentro de una macro que puede llamarse más de una vez, es necesario anteponer `%%` a dicha etiqueta.
Esto le indica al ensamblador que dé a esta etiqueta un nombre distinto y único en cada expansión:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Repetición en tiempo de ensamblado

Es posible repetir un bloque de código de una línea con [`times`][times].
Esto es especialmente útil al declarar valores repetidos en memoria:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Para repetir código de varias líneas, podemos usar `%rep` en su lugar:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Ten en cuenta que el número de repeticiones se especifica justo después de `%rep` y que hay un `%endrep` para cerrar el bloque repetido.

Es habitual usar un contador de tiempo de ensamblado dentro de un bloque `%rep`, igual que un bucle en tiempo de ejecución usa un contador.
Aunque una constante entera de tiempo de ensamblado puede declararse con `equ`, como ya hemos visto, para _variables_ enteras de tiempo de ensamblado usamos `%assign` en su lugar.
A diferencia de `%define`, `%assign` se evalúa de inmediato a un número y puede reasignarse:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Después de que se ejecute el preprocesador, el bucle desaparece y quedan cuatro instrucciones `add`, con los valores inmediatos `0`, `1`, `2` y `3` incorporados.
Esto es desenrollado de bucles hecho por el ensamblador: sin registro contador y sin salto, solo código lineal.

Otro uso habitual de `%rep` es gestionar los argumentos de una macro que puede tomar cualquier número de ellos.
En ese caso, `%rep` suele combinarse con `%rotate`, que rota los argumentos de una macro, de modo que el segundo argumento pasa a ser el primero.
Aplicaciones repetidas de `%rotate` hacen que el tercer argumento, luego el cuarto, etc., pasen a ser el primero, lo que garantiza que cada argumento pueda tratarse por turno:

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## Ensamblado condicional

El [preprocesador][preprocessor] dispone de varios condicionales.
Seleccionan entre varios caminos distintos, expandiendo su cuerpo en el mismo lugar, pero solo cuando su condición se cumple.

`%if` ... `%elif` ... `%else` ... `%endif` seleccionan una rama a partir de una comprobación numérica:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef` y `%ifndef` son similares, pero comprueban si un nombre se ha definido.
Por ejemplo, pueden usarse para asegurar que el contenido de un archivo se incluya solo una vez, incluso cuando más de un archivo fuente lo incorpora:

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

Es posible que hayas notado que al final de cada archivo `.asm` de este track hay este fragmento de código:

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn` compara dos fragmentos de texto en busca de una coincidencia exacta.
El elemento integrado `__OUTPUT_FORMAT__` se expande al formato de salida actual, de modo que ese código comprueba si el formato de salida es `elf64`, que es el formato que usan los sistemas Linux.
Si lo es, se añade una nota al archivo objeto que declara los permisos que debe tener la pila, una medida de seguridad habitual.
Si no lo es, nada cambia.

## Estructuras

Acceder a un campo de un registro en memoria significa sumar el desplazamiento en bytes del campo a una dirección base.
Escribir esos desplazamientos como números sin más es propenso a errores y oculta su significado.
[`struc`][struc] y `endstruc` nombran en su lugar una disposición, convirtiendo cada campo en un desplazamiento simbólico calculado en tiempo de ensamblado.

Dentro del bloque, las directivas de reserva `resb`, `resw`, `resd` y `resq` reservan uno o más bytes, palabras, palabras dobles o palabras cuádruples.
Poner un `.` delante de cada campo mantiene su nombre limitado al ámbito de la estructura:

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

Cada nombre de campo representa ahora su desplazamiento, así que `thread.color` es `0`, `thread.tension` es `4` y `thread.name` es `12`.
NASM también define `<struc>_size` como el total, donde `<struc>` es el nombre de la `struc`.
Por ejemplo, aquí `thread_size` sería `4 + 8 + 16 = 28`.

Se accede a un campo sumando su desplazamiento a un registro base, y `thread_size` es el paso de un registro al siguiente:

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

Una `struc` solo describe una forma, no reserva memoria por sí sola.
Para crear una instancia inicializada, puedes usar `istruc ... iend` después de alguna etiqueta.
Dentro de una instancia, `at` coloca un valor en un campo con nombre:

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

Ten en cuenta que `thread.name` se inicializa con `"warp", 0`, que ocupa solo 5 bytes.
Los otros 11 bytes reservados para él en la `struc` se rellenan automáticamente con ceros por `iend`, que completa la instancia hasta `thread_size` con `0`.

Una `struc` no es más que azúcar sintáctico para memoria que también podemos declarar a mano.
Por ejemplo, el código anterior equivale al siguiente, donde `times 11 db 0` garantiza que se reserven 16 bytes al final:

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## Dividir en archivos

A menudo las macros se guardan en un archivo propio y se incorporan a cada fuente que las necesita con `%include`:

```x86asm
%include "patterns.mac"
```

El archivo indicado se inserta tal cual en ese punto, antes del ensamblado, exactamente como si su contenido se hubiera escrito allí mismo.
Esto mantiene las definiciones en un solo lugar y permite que varios archivos fuente las compartan.

Si el archivo de macros puede ensamblarse por sí solo, debería tener la extensión de archivo `.asm`.
Ten en cuenta que las macros no tienen enlace.
Aunque el archivo de macros se ensamble, sus macros solo son visibles para otro archivo que lo incluya con `%include`.

En caso contrario, un archivo que solo se use con `%include` puede tener cualquier extensión.
Usar `.asm` o `.mac` es una convención habitual.
