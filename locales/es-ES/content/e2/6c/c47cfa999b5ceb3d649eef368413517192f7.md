# Acerca de los bits

Los dígitos binarios se corresponden en última instancia con los transistores de tu CPU o tu RAM, y con si cada uno está «encendido» o «apagado».

La manipulación de bajo nivel, llamada informalmente «bit-twiddling», es especialmente importante en los lenguajes de sistema.

Los lenguajes de más alto nivel, como Kotlin, suelen abstraer la mayor parte de estos detalles.
Sin embargo, hay disponible una serie básica de [operaciones a nivel de bits][ref-bitwise].

~~~~exercism/note
Para ver una salida binaria legible para las personas, casi todos los ejemplos siguientes deben envolverse en una función [`Integer.toBinaryString()`][web-binstring], o convertirse con `toString(radix = 2)`.
 
Esto distrae visualmente, así que se han eliminado la mayoría de las apariciones de esta función y los resultados se representan con la notación `0b`.

## Operaciones de desplazamiento de bits

Los tipos `Int` o `Long`, tanto con signo como sin signo, pueden representarse como un string de unos y ceros, y manipularse como una secuencia de bits.

Quizá sorprenda que los tipos `Byte` o `Short` no sean compatibles con la mayoría de las operaciones bit a bit en Kotlin.
Todos los ejemplos siguientes usan enteros de 32 bits (`Int` o `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Los desplazamientos de bits mueven todo a la izquierda o a la derecha un número de posiciones determinado.
Algunos bits se pierden por un extremo y el otro extremo se rellena con ceros o unos.

- Desplazamiento a la izquierda con `shl`: relleno con ceros.
- Desplazamiento a la derecha con `shr` o `ushr`: relleno con ceros para números positivos (consulta la sección posterior para los números negativos).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Cada desplazamiento a la izquierda duplica el valor, y cada desplazamiento a la derecha lo divide por la mitad (sujeto a truncamiento).
Esto se ve más claro en representación decimal:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Este tipo de desplazamientos de bits es mucho más rápido que la aritmética «convencional», lo que hace que la técnica sea muy popular en la programación de bajo nivel.

### Desplazamiento de bits con números enteros negativos

Con los _números enteros negativos_, debemos tener un poco más de cuidado.

Los valores negativos se almacenan en forma de [complemento a dos][wiki-2complement], lo que significa que el bit más a la izquierda es 1.
No hay problema para un desplazamiento a la izquierda, pero al desplazar a la derecha, ¿cómo rellenamos los bits más a la izquierda?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

El operador [`shr`][ref-shr] realiza un [desplazamiento aritmético][wiki-arithmetic], que conserva el bit de signo.

El operador [`ushr`][ref-ushr] realiza un [desplazamiento lógico][wiki-logical], rellenando con ceros como si el número no tuviera signo.

## Lógica bit a bit

Vimos en el [concepto de Boolean][concept-booleans] que los operadores `&&` (and), `||` (or) y `!` (not) se usan con valores Boolean.

Existen operadores equivalentes `and`, `or` y `xor` ([or exclusivo][wiki-xor]) para comparar los bits de dos enteros, y una función `inv` (inversión) para invertir todos los bits.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
