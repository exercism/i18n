# Anexo de las instrucciones

El conjunto de pruebas solo genera unos 100 nombres de forma predeterminada.
Hay unos 700 000 nombres válidos, así que solo te dará una pequeña probabilidad de que se produzcan colisiones.
Plantéate comprobar tu solución en busca de colisiones de alguna otra forma, además del conjunto de pruebas.

Este ejercicio continúa nuestra exploración del
[sistema de tipos](https://docs.julialang.org/en/v1/manual/types/) de Julia,
esta vez con tipos mutables,
y nos introduce en la
[generación de números aleatorios](https://docs.julialang.org/en/v1/stdlib/Random/).

Imaginemos que restablecer el robot a los ajustes de fábrica es como una cirugía: introduce cambios en el sujeto, pero no lo sustituye.
También podríamos haber modelado el problema de forma que restablecer un robot creara un robot nuevo, pero no todos los problemas pueden modelarse únicamente con estructuras de datos inmutables (¡incluso los lenguajes puramente funcionales lidian con la mutabilidad dentro de sus entornos de ejecución!).

En Julia, las funciones que mutan sus argumentos llevan por convención un sufijo `!`.
Así que nuestro método para hacer esto se llamará `reset!`.

Esto es solo una convención, pero casi todo el código de Julia publicado la sigue, y puede que llegues a estar de acuerdo en que resulta muy útil.

## Pistas

Tendrás que definir
un método para generar nombres únicos,
una estructura para describir robots,
un método para restablecer un robot,
y un método para obtener el nombre de un robot.

Puede que te resulte útil diseñar tu programa primero para que simplemente genere un nombre aleatorio para un robot (sin preocuparte por las colisiones) y, después, pensar y diseñar un esquema que evite emitir nombres duplicados.
En tu diseño, reflexiona sobre cómo cambia el tiempo de ejecución de la generación de nombres a medida que se agotan los nombres. ¿Qué garantías quieres ofrecer a quien llama?
