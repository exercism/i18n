# Instrucciones

Estás trabajando en un sistema para simplificar el proceso de inicio de sesión en la red de tu organización. Las tareas se centran en la parte de autenticación. El sistema utiliza el reconocimiento facial para demostrar la identidad.

En todos los casos se garantiza que el parámetro del color de ojos no es nulo.

## 1. Asegúrate de que los rasgos faciales coinciden

Implementa `Authenticator.AreSameFace()` para comprobar que dos caras coinciden.

Añade rutinas de igualdad para la clase `FacialFeatures`.

```csharp
Authenticator.AreSameFace(new FacialFeatures("green", 0.9m), new FacialFeatures("green", 0.9m);
// => true
Authenticator.AreSameFace(new FacialFeatures("blue", 0.9m), new FacialFeatures("green", 0.9m);
// => false
```

## 2. Autentica al administrador del sistema

A pesar de tus protestas, el administrador del sistema insiste en tener una identidad integrada durante las pruebas de aceptación para que siempre se pueda autenticar.

El correo electrónico del administrador es admin@exerc.ism. Tiene los ojos verdes y un filtrum con una anchura de 0,9.

Añade rutinas de igualdad para la clase `Identity`.

Implementa el método `Authenticator.IsAdmin()` para comprobar que la identidad que se pasa coincide con la del administrador.

```csharp
var authenticator = new Authenticator();
authenticator.IsAdmin(new Identity("admin@exerc.ism", new FacialFeatures("green", 0.9m)));
// => true
authenticator.IsAdmin(new Identity("admin@thecompetition.com", new FacialFeatures("green", 0.9m)));
// => false
```

## 3. Registra nuevas identidades

Implementa el método `Authenticator.Register()`, que almacena una identidad en el propio autenticador de forma que las llamadas a `IsRegistered()` devuelvan `true` para esta identidad; en caso contrario, `IsRegistered()` devuelve `false`.

Para detectar intentos duplicados de registrar una identidad, si la identidad ya se ha registrado, `Authenticator.Register()` devuelve `false`; en caso contrario, `true`.

```csharp
var authenticator = new Authenticator();
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.IsRegistered(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => false
```

## 4. Evita que se autentiquen identidades no válidas

Implementa el método `Authenticator.IsRegistered()` y asegúrate de que devuelve false cuando no se ha registrado ninguna identidad.

```csharp
var authenticator = new Authenticator();
authenticator.IsRegistered(new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.8m)));
// => false
```

## 5. Añade diagnósticos para detectar múltiples intentos de autenticación

Se ha informado de un error por el cual el método `Authenticator.IsRegistered()` se llama varias veces seguidas para la misma identidad. Crees que hay algún tipo de problema de «rebote» en el que se envía el mismo registro varias veces. Tu tarea es añadir una rutina de diagnóstico, `Authenticator.AreSameObject()`, para respaldar cualquier prueba que se lleve a cabo. La rutina compara dos objetos y devuelve `true` si son exactamente la misma instancia; en caso contrario, `false`.

```csharp
var identityA = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityB = identityA;
Authenticator.AreSameObject(identityA, identityB);
// => true

var identityC = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityD = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
Authenticator.AreSameObject(identityC, identityD);
// => false
```
