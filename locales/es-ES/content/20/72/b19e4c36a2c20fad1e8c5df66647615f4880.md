# Introducción

Hay bucles que no se pueden escribir como «haz esto para cada elemento de una secuencia»: tienes que seguir adelante hasta que alguna condición cambie. El combinador `while` de Factor es la herramienta para eso: una quotation de predicado dice «¿sigo?», una quotation de cuerpo hace el trabajo de un paso, y `while` repite hasta que el predicado devuelve `f`.

## `while` y `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` y `body` son ambas quotations que operan sobre la pila de datos. `while` sigue iterando mientras `pred` deja un valor verdadero; `until` es lo contrario: sigue iterando *hasta* que `pred` se vuelve verdadero (es decir, mientras `pred` deja `f`).

Un único valor de estado puede fluir por la pila entre el predicado y el cuerpo:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

Traza: el predicado `dup 0 >` echa un vistazo al contador actual; el cuerpo `dup . 1 -` lo imprime y lo decrementa; el bucle se detiene en cuanto el contador llega a `0`. El `drop` final descarta ese último `0` de la pila.

## `while*`: conserva el valor del predicado

```
while* ( pred body -- )
```

A `while` solo le importa si su predicado dejó un valor verdadero: descarta el valor en sí antes de ejecutar el cuerpo. `while*`, en cambio, *le pasa ese valor al cuerpo*. Recurre a él siempre que el test y el cuerpo quieran lo mismo recién calculado: una búsqueda, una coincidencia, un token ya analizado.

Aquí cada nombre apunta al siguiente de una cadena. El predicado busca el nombre actual; mientras haya un nombre siguiente, `while*` se lo pasa al cuerpo, que lo imprime y continúa desde ahí:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at` devuelve el nombre siguiente, o `f` cuando un nombre ya no tiene entrada. Mientras devuelva un nombre, `while*` se lo da a `dup .`, que lo imprime y lo deja como clave para la siguiente búsqueda. El primer `f` detiene el bucle: `while*` lo descarta, así que no queda nada pendiente.

## Varios valores de estado con variables locales

Cuando el bucle arrastra más de un valor (por ejemplo, una secuencia que queda y un total acumulado), hacer malabares con la pila se vuelve engorroso. El patrón más limpio es declarar *variables locales* con `::`:

```
:: word ( inputs -- outputs ) ... ;
```

Dentro del cuerpo, `:> name!` añade una variable local mutable; las lecturas usan `name` y las escrituras usan `name!` (que consume el nuevo valor de la pila y lo asigna).

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

Aquí, dos variables locales (`rest` y `running`) cubren todo el estado del bucle: el predicado las inspecciona, el cuerpo las actualiza y el valor final se devuelve al terminar.

`unclip ( seq -- rest first )` extrae el primer elemento de una secuencia, algo muy útil cuando el bucle quiere consumir una secuencia elemento a elemento. La forma `[ rest! ] dip` actualiza `rest` con la cola restante y deja el elemento recién extraído en la pila para que lo use el cuerpo.
