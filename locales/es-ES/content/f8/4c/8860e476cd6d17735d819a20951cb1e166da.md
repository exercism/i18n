## Boolean en Julia

Los valores true o false se representan con el tipo `Bool`.
Contiene solo dos valores: `true` y `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

A diferencia de otros lenguajes, Julia deliberadamente no tiene concepto de «truthiness», y solo las expresiones que evalúan a `true` o `false` se tratarán como un `Bool`.

En concreto, los arrays o strings vacíos *no* se interpretarán como `false`.
Debe haber una prueba adecuada, como `isempty()`, si quieres un manejo especial para valores vacíos.

## Operadores Boolean

Hay tres [operadores Boolean][boolean-operators] en Julia.

`&&` es el «y» Boolean.
Evalúa a `true` si las expresiones a *ambos* lados de `&&` son `true`.

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||` es el «o» Boolean.
Evalúa a `true` si una expresión a *cualquiera* de los lados de `||` es `true`.

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!` es el «no» Boolean.
Intercambia (invierte) los valores `true` y `false`.

```julia-repl
julia> !true
false

julia> !false
true
```

Operadores similares resultarán conceptualmente familiares para usuarios de muchos otros lenguajes, aunque la sintaxis precisa puede variar entre lenguajes.

## Precedencia de operadores

En expresiones más complejas, puede ser útil saber que `&&` tiene una [precedencia][operator-precedence] ligeramente mayor que `||` *(de la misma manera que `*` se aplica antes que `+` en expresiones aritméticas)*.

Confiar en esto puede ser confuso y propenso a errores.
Para mayor claridad, usa paréntesis para dejar clara tu intención.

## Evaluación de cortocircuito

¿La expresión `true || x` depende del valor de `x`, o puede el compilador ignorar `x`?

Julia evalúa las expresiones Boolean de izquierda a derecha, y se detiene cuando tiene un resultado inequívoco.

Por ejemplo, `true || x` debe ser `true`, independientemente de `x`, así que `x` no se evalúa.
De manera similar, `false && y` es `false`, sin necesidad de evaluar `y`.

A la inversa, `true && x` es `true` *solo si* `x` es `true`, así que `x` debe evaluarse.

De manera similar, si encadenamos varios operadores:

```julia-repl
julia> true && false && something_else
false
```

Como `true && false` debe ser `false`, el `something_else` no es importante y el compilador lo ignora.

En este caso, `something_else` no existía como variable, pero incluirla en este contexto no dio error *(pruébalo en el REPL si lo dudas)*.

Esta evaluación de cortocircuito se usa con bastante frecuencia por programadores de Julia como un atajo para detectar problemas en tiempo de ejecución y casos límite:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

Por ejemplo, `do_something` podría ser un `return` anticipado de la función si `all_ok` es `false`, o asignar un valor por defecto a una variable antes de continuar.

Esto es un ligero abuso de la sintaxis Boolean, pero puede ser muy conveniente.

## Cómo funcionan los Bool internamente

Si un Bool se incluye en una expresión *aritmética*, `true` se interpreta como `1` y `false` como `0`, lo que refleja cómo se almacenan.

Si estás acostumbrado a lenguajes de más bajo nivel (C y similares), *por favor* evita usar esto con frecuencia.
Reducirá la legibilidad del código y dificultará la depuración.

A veces puedes ver los valores numéricos usados como una forma rápida de contar cuántas cosas son `true`.

```julia-repl
julia> true + false + true
2
```
