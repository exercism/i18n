# Apéndice de instrucciones

## Implementación

Antes de empezar, asegúrate de que sabes escribir código que pueda superar los casos de prueba.
Para más contexto, echa un vistazo a este [tutorial].

La mayoría de los ejercicios de Java incluyen varios casos de prueba.
Estos casos están estructurados para facilitar un proceso muy útil conocido como [desarrollo guiado por pruebas (TDD)][tdd].
El TDD consiste en repetir un ciclo estructurado que ayuda a los desarrolladores a construir funcionalidad compleja poco a poco en lugar de hacerlo todo de una vez.
Ese ciclo se puede describir así:

1. Añade una prueba que describa una parte de la funcionalidad deseada que tu código todavía no tiene.
2. Ejecuta las pruebas para comprobar que esta prueba recién añadida falla.
3. Actualiza tu código actual hasta que:
   - Todas las pruebas antiguas sigan pasando;
   - La nueva prueba también pase.
4. [Limpia][refactoring] tu código y asegúrate de que todas las pruebas sigan pasando.
   Normalmente esto implica cambiar el nombre de las variables, eliminar fragmentos de lógica duplicados, quitar los registros sobrantes, etc.
5. Vuelve al paso 1 hasta que hayas implementado toda la funcionalidad deseada.

Los archivos de prueba de este track contienen _todas_ las pruebas que tu solución debe superar para considerarse válida.
A primera vista, eso no parece compatible con el ciclo descrito antes, en el que las pruebas se escriben de una en una.
Sin embargo, la herramienta que usamos para escribir nuestras pruebas, [JUnit][junit],
ofrece una [anotación][java-annotation] [@Disabled][junit-disabled] que se puede usar para omitir temporalmente una prueba ya escrita.
Con esta anotación, nos aseguramos de que los archivos de prueba que te entregamos cumplan las siguientes reglas:

- La primera prueba de cualquier archivo de prueba _no_ se omite de forma predeterminada.
- Todas las pruebas excepto la primera de cualquier archivo de prueba _se omiten_ de forma predeterminada.

Esto te permite simular el ciclo del TDD siguiendo estos pasos ligeramente modificados:

1. Ejecuta las pruebas para comprobar que, como máximo, falla _una_ prueba.
2. Actualiza tu código actual hasta que pasen todas las pruebas no omitidas.
3. Limpia tu código y asegúrate de que todas las pruebas no omitidas sigan pasando.
4. Elimina la anotación `@Disabled` que está más arriba en el archivo de prueba.
5. Vuelve al paso 1 hasta que no quede ninguna prueba omitida y todas pasen.

[junit]: https://junit.org/junit5/
[junit-disabled]: https://junit.org/junit5/docs/current/api/org.junit.jupiter.api/org/junit/jupiter/api/Disabled.html
