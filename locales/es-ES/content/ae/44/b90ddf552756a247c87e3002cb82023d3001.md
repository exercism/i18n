# Listas

Un `ARRAY` es fijo. Se crea con un tamaño y se queda con ese tamaño: no se
le pueden añadir elementos ni quitarle ninguno.

El cuaderno de un detective no funciona así. Las pistas aparecen de una en una y
se tachan cuando se descartan. Para eso quieres una **lista**.

```sather
   notes ::= #LIST{STR};
   notes.append("muddy boots");
   notes.append("broken window");
   notes.size                   -- 2
```

`LIST{T}` contiene valores de tipo `T` en orden, como un array, y crece y
se encoge cuando se lo pides.

## Cambia en el lugar

`append` cambia la lista sobre la que se llama y no devuelve nada:

```sather
   notes.append("muddy boots");        -- yes
   notes := notes.append("muddy boots");   -- no: append answers nothing
```

Esto es diferente de `FMAP` y `FSET`, donde cada cambio tenía que
volver a asignarse. Un `LIST` es un objeto normal, como un `SCOREBOARD`: se lo
pasas a una rutina y la rutina puede cambiar el tuyo.

## Lectura y escritura

Corchetes, contando desde cero, exactamente igual que para un array:

```sather
   notes[0]                     -- "muddy boots"
   notes[1] := "smashed window";
   notes.size                   -- how many
   notes.is_empty               -- true when there are none
```

## Eliminar

`remove_index` saca una posición y todo lo que hay después se desplaza una posición hacia arriba:

```sather
   notes.remove_index(0);       -- the first clue is struck out
```

Así que las posiciones no son permanentes. La posición de una pista cambia cuando se elimina
una anterior, algo que conviene recordar antes de guardar una posición.

## Recorrerla

`elt!` funciona, igual que en un array:

```sather
   loop
      #OUT + notes.elt! + "\n";
   end;
```

## Las llaves

`LIST{STR}` es una lista de strings, `LIST{INT}` una lista de números. Es una
clase genérica, exactamente como la que escribiste en `lost-property`. Y ahora
puedes leer la de la biblioteca de la misma manera.
