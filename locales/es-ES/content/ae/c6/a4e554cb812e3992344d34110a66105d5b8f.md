# Introducción a los bucles

Bash tiene dos formas de crear bucles:

* Repetir unos comandos _para cada elemento de una lista de elementos_,
* Repetir unos comandos _mientras alguna condición es verdadera (o falsa)_.

## Bucles `for`

Para iterar sobre una lista de elementos, usamos el bucle `for`.

```bash
for varname in words; do COMMANDS; done
```

`words` se expande mediante la división de palabras y la expansión de nombres de fichero (que vimos en el [concepto de entrecomillado][quoting]).
Cada palabra se asigna a `varname` por turno, y se ejecutan los COMMANDS.

Aquí tienes algunos ejemplos que muestran cuándo puede resultar útil el bucle `for`

* Ejecutar unos comandos sobre un grupo de ficheros.

    ```bash
    # source all the bash library files in the current directory
    for file in ./*.bash; do
        source "$file"
    done
    ```

* Ejecutar algún comando sobre cada uno de los parámetros de un script o una función.

    ```bash
    for arg in "$@"; do
        echo "argument: ${arg}"
    done
    ```

* Ejecutar algún comando para cada palabra separada por espacios en blanco en la salida de un comando.

    ```bash
    for i in $(seq 10); do
        echo "${i} squared is $((i * i))"
    done
    ```

    Más adelante veremos algunas advertencias sobre este estilo.

### Bucle `for` aritmético

Bash sí que tiene un bucle aritmético.
Resultará algo familiar para quienes conozcan otros lenguajes de programación.

```bash
for ((INITIALIZATION; CONDITION; INCREMENT)); do COMMANDS; done
```

Los paréntesis dobles en Bash representan un contexto aritmético (veremos más sobre la aritmética de Bash en un concepto posterior).
El ejemplo anterior con `seq` se puede escribir así

```bash
for ((i = 1; i <= 10; i++)); do
    echo "${i} squared is $((i * i))"
done
```

### Cuándo no usar `for`

[No leas líneas con `for`][bashfaq1].

Este es un antipatrón que verás a menudo: iterar sobre la salida de `cat`.

```bash
for line in $(cat some.file); do 
    do_something_with "$line"
done
```

Esto está mal por dos motivos.

1. La sustitución de comandos no está entrecomillada, así que está sujeta a la división de palabras.
   La división de palabras, por defecto, divide por _espacios en blanco_, no solo por saltos de línea.
   Este bucle `for` itera sobre las **palabras** del fichero, no sobre las líneas.
2. La sustitución de comandos no está entrecomillada, así que está sujeta a la expansión de nombres de fichero.
   Cada palabra del fichero se comparará con un patrón glob.

Como vimos en el [concepto de entrecomillado][quoting], la división de palabras se puede controlar con la variable `IFS`, y la expansión de nombres de fichero se puede desactivar.
Pero suele ser una solución frágil.
`for` no es el método adecuado para iterar sobre las líneas de un fichero.
La forma idiomática de leer un fichero es con un bucle `while`.

## Bucles `while`

Usa `while` para repetir una secuencia de comandos _mientras_ se cumple alguna condición.

```bash
while CONDITION_COMMANDS; do COMMANDS; done
```

Al igual que con `if` (como vimos en el [concepto de condicionales][conditionals], no hay una sintaxis especial para CONDITION_COMMANDS.
El estado de salida de la lista de comandos determinará si es «verdadero» o «falso».

## Controlar los bucles

El comando `break` sale del bucle.
El control se reanuda con el comando que sigue al terminador `done` del bucle.

El comando `continue` salta a la siguiente iteración del bucle.

## Leer las líneas de un fichero

Como ya se ha mencionado, un bucle `while` es la forma idiomática de leer un fichero.

```bash
while IFS= read -r line; do
    do_something_with "$line"
done < some.file
```

* El contenido del fichero se proporciona como entrada al bucle con la redirección `<`.
* El comando `read` devuelve «verdadero» si puede leer una línea completa de su entrada.
  Cuando se agota la entrada, o si la última línea termina sin un salto de línea final, `read` devuelve «falso».
  * La forma _realmente_ idiomática de leer las líneas de un fichero, incluso si la última línea no termina en un salto de línea, es

    ```bash
    while IFS= read -r line || [[ -n "$line" ]]; do ...
    ```

* La opción `-r` indica a `read` que no sustituya secuencias con barra invertida: una barra invertida es un carácter normal.
* `IFS=` asigna la cadena vacía a IFS solo mientras dura el comando read.
  Esto desactiva temporalmente la división de palabras para que se conserve cualquier espacio en blanco al principio o al final de la línea de texto entrante.

## Until

La construcción `until` repite una secuencia de comandos mientras alguna condición es **falsa**.
El bucle se repite _hasta que_ la condición se vuelve verdadera.

```bash
until CONDITION_COMMANDS; do COMMANDS; done
```

Es raro usar `until`.
Es más habitual usar un bucle «while not».

```bash
while ! CONDITION_COMANDS; do ...
```

## Bucles infinitos

A veces quieres que un bucle se repita para siempre.
Aquí tienes dos formas de hacerlo.

1. un bucle `while` con una condición que siempre tiene un estado de salida de éxito

    ```bash
    while true; do ...
    ```

2.  un bucle `for` aritmético con expresiones vacías

    ```bash
    for ((;;)); do ...
    ```

## Do-While

No existe una construcción do-while explícita, pero puedes conseguir el mismo efecto:

```bash
while true; do
    COMMANDS

    if END_CONDITION; then
        break
    fi
done
```
