# Pistas

## General

- `movapd` y `movaps` solo deben usarse cuando se sabe que un operando de memoria está alineado.
  Se pueden usar sin problemas cuando ambos operandos son registros `xmm`.
- Las direcciones de memoria se pasan como valores enteros.
  Los seis primeros argumentos enteros se pasan a una función en `rdi`, `rsi`, `rdx`, `rcx`, `r8` y `r9`, respectivamente.

## 1. Combina los rendimientos de dos líneas

- La suma empaquetada para números de coma flotante de 32 bits es `addps`.
- Se garantiza que los tres argumentos de puntero están alineados a 16 bytes, así que la variante de movimiento alineada, `movaps`, es la adecuada.

## 2. Calcula la desviación escalada

- La resta empaquetada para números de coma flotante de 64 bits es `subpd`.
- La multiplicación empaquetada para números de coma flotante de 64 bits es `mulpd`.
- `measured` está alineado y `target` no, así que necesitan variantes de carga distintas.

## 3. Calibra un lote

- Tanto `reference` como `offset` están alineados, `raw` no, así que necesitan variantes de carga distintas.
- Tanto `reference` como `offset` se necesitan para ambas filas.
- Las instrucciones de dos operandos normalmente sobrescriben su operando de destino.
- Para convertir los 2 números de coma flotante superiores de `raw` a dobles, usa `cvtps2pd` con un operando de memoria desplazado 8 bytes respecto al puntero `raw`.
- El factor de conversión debe guardarse en memoria como 2 números de coma flotante de 64 bits (ambos iguales a `0.5`).
- El resultado ocupa 32 bytes (4 números de coma flotante de 64 bits): los primeros 16 bytes en `[result]`, los siguientes 16 en `[result + 16]`.

## 4. Normaliza las puntuaciones a lo largo de una línea

- Las instrucciones de dos operandos normalmente sobrescriben su operando de destino.
- La memoria no puede ser el operando de destino de las instrucciones aritméticas empaquetadas.
- Por cada `score` de coma flotante de 64 bits en el array `scores` (primer argumento), hay un `gain` equivalente en el array `gains` (segundo argumento).
  Cada `score` operará con el `gain` que ocupa la misma posición.
- El tercer argumento es un `scale` fijo con 2 números de coma flotante de 64 bits empaquetados.
- Por cada par `score` y `gain`, la función calcula `score * gain / scale_lane`.
  El primer carril de `scale` escala el primer elemento de cada par (los carriles en posiciones pares) y el segundo carril escala el segundo (los carriles en posiciones impares).
- La puntuación normalizada se guarda en el mismo sitio del array `scores`, en la misma posición que su `score` de entrada.
- El número de elementos de `scores` y `gains` es el mismo e igual al valor de `n` (el cuarto argumento).
- Debes usar un bucle para procesar todos los pares de elementos, avanzando 16 bytes (2 elementos) en cada iteración.
