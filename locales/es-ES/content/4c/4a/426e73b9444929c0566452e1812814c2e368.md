# no uses condicionales anidados

Intenta reescribir los condicionales para evitar anidamientos profundos, ya que pueden dar lugar a código más difícil de seguir. Fíjate en estos dos fragmentos de código:

```csharp
void PrintName(Person p)
{
    if (p != null)
    {
        if (p.Name != null)
        {
            if (p.Age >= 21)
            {
                Console.WriteLine(p.Name);
            }
        }
    }
}
```

Compáralo con el siguiente código:

```csharp
void PrintName(Person p)
{
  if (p == null || p.Name == null || p.Age < 21)
  {
      return;
  }

  Console.WriteLine(p.Name);
}
```

El segundo ejemplo tiene una estructura muy concreta: todos los caminos que tienen que ver con errores se resuelven en bloques con sangría, mientras que el «happy path» siempre queda alineado a la izquierda. Esto hace que la lectura sea muy sencilla, ya que se ve rápidamente cuál es el camino más habitual y libre de errores a través del código.
