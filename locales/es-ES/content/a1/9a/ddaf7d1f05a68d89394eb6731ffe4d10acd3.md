# Introducción

Un *deque* (cola de doble extremo) admite push y pop en ambos
extremos en O(1). La implementación estándar de Factor es `<dlist>` (una
lista doblemente enlazada) de [`dlists`][dlists]; las operaciones están
en [`deques`][deques].

## La API de deque

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` vacía el deque in situ, lo que resulta útil para reutilizarlo
sin volver a asignar memoria.

Hacer push y pop en el mismo extremo te da una pila LIFO. Hacer push en un
extremo y pop en el otro te da una cola FIFO:

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

Para LIFO, recurrirías a un vector (`V{ }`) con `push`/`pop`,
que tiene menos sobrecarga por operación. Recurre a `<dlist>` cuando
necesites O(1) en *ambos* extremos, casi siempre para una cola FIFO.

## Búsqueda en anchura

El uso FIFO es lo que convierte a los deque en la frontera adecuada para el *BFS*.
Empiezas con un único nodo, haces push de los vecinos al final, haces pop de los
candidatos del principio y eliminas los duplicados con un conjunto hash:

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

Los candidatos más antiguos se visitan antes que los más recientes, así que la
búsqueda avanza hacia fuera por capas desde el inicio. Eso es lo que le da al BFS
su propiedad de camino más corto: la primera vez que alcanzas un nodo objetivo
es mediante un camino con el mínimo número de saltos.

## `MEMO:`: almacenamiento en caché automático

A veces, la consulta por nodo que hace el BFS es costosa. El vocabulario
[`memoize`][memoize] de Factor te ofrece `MEMO:`, un reemplazo directo de `:`
que almacena en caché el resultado de la palabra usando sus entradas como clave:

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

Una palabra `MEMO:` ejecuta su cuerpo la primera vez que se ve cada entrada
y, a partir de ahí, devuelve el resultado almacenado en caché: la misma interfaz,
sin llamadas adicionales en el punto de llamada, solo más rápida en las repeticiones.
