# Rutinas vinculadas

```sather
   part : ROUT{STR}:STR := bind(shout(_));
   part.call("who's there");
```

## `bind`

`bind` recibe una llamada en la que cualquier parte puede sustituirse por `_`. Todo lo que no es un `_` se evalúa **ahora** y se conserva; cada `_` se convierte en un argumento de la rutina vinculada, en el orden en que se escribe.

```sather
   bind(repeat(2, _))         -- ROUT{STR}:STR
   bind(repeat(_, "Ha"))      -- ROUT{INT}:STR
   bind(repeat(_, _))         -- ROUT{INT,STR}:STR
```

## Los tipos

| Tipo | Recibe | Devuelve |
| --- | --- | --- |
| `ROUT:INT` | nada | `INT` |
| `ROUT{STR}` | un `STR` | nada |
| `ROUT{STR}:STR` | un `STR` | un `STR` |
| `ROUT{INT,INT}:BOOL` | dos `INT` | `BOOL` |

`ITER{...}` es la misma idea para un iterador.

## `call`

`call` aporta los argumentos restantes. Una rutina vinculada que no devuelve nada se llama igual, como una instrucción.

## `bind` va a la derecha de una asignación

Un `bind` puede declararse en una variable, o pasarse como argumento:

```sather
   part ::= bind(shout(_));                -- yes
   part : ROUT{STR}:STR := bind(shout(_)); -- yes
   rehearse("line", bind(shout(_)));       -- yes
```

pero no puede ir directamente en un `return`:

```sather
   return bind(shout(_));                  -- does not parse
```

Guárdalo en una variable y devuélvela. El mensaje de error apunta al `bind` y menciona guiones bajos, algo que no resulta obvio a partir de la propia línea.

## Dónde se usan

La biblioteca las acepta allí donde hay que aportar un comportamiento:

```sather
   names.sort_by(bind(shorter(_, _)));
   scores.count_if(bind(over(10, _)));
   scores.find_if(bind(is_even(_)));
```

Ordenar es el caso más claro: `sort_by` sabe ordenar y no sabe nada de tu idea de orden, y la rutina vinculada es el punto donde se encuentran ambas.

## Una limitación de este compilador

Sather 1.2 no implementa las rutinas vinculadas **despachadas**: vincular una rutina a una variable de un tipo abstracto. El compilador lo dice sin rodeos:

```
Dispatched bound routines are not implemented yet
```

Vincula a un tipo concreto, o a una clase, y todo irá bien. Por eso el arnés de pruebas del propio track escribe a mano sus comprobaciones de excepciones en lugar de usar una rutina vinculada.

## ¿Rutinas vinculadas o clases abstractas?

Ambas permiten que quien llama aporte un comportamiento.

Una rutina vinculada es una sola rutina, no necesita ninguna clase y se escribe donde se usa. Una clase abstracta conlleva varias rutinas y algo de estado, y el ceremonial está justificado cuando lo que se aporta tiene más de una parte.

Una sola rutina que ceder: vincúlala. Un colaborador con varias: escribe una clase.
