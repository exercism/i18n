# Anexo a las instrucciones

## Mensajes de excepción

A veces es necesario [lanzar una excepción][raise-an-exception]. Cuando lo hagas, deberías incluir siempre un **mensaje de error significativo** que indique cuál es el origen del error. Esto hace que tu código sea más legible y ayuda mucho a la hora de depurar. En situaciones en las que sepas que el origen del error va a ser de un tipo determinado, puedes optar por lanzar uno de los [tipos de error integrados][built-in-errors], pero aun así deberías incluir un mensaje significativo.

Este ejercicio en concreto requiere que uses la [instrucción raise][raise-statement] para «lanzar» un `ValueError` si la pregunta que se pasa a `answer()` está mal formada o no es válida, o si contiene una operación desconocida. Las pruebas solo pasarán si lanzas la `exception` con `raise` e incluyes un mensaje con ella.
**Ten en cuenta**: el mensaje necesario es distinto para cada escenario, aunque se lance el mismo _tipo de error_.
Revisa las pruebas con atención.

Para lanzar un [`ValueError`][value-error] con un mensaje, escribe el mensaje como argumento del tipo `exception`:


```python
# if the question contains an unknown operation.
raise ValueError("unknown operation")

# if the question is malformed or invalid.
raise ValueError("syntax error")
```

Para _gestionar_ un error lanzado dentro de un bloque de código concreto, se puede usar un [try-except][handling-exceptions].
Los bloques `try-except` «envuelven» el código que podría causar un error, y asocian todas las excepciones a un único error, a varios errores u otros fragmentos de código con los que resolver el problema:


```python
while len(equation) > 1:
        try:
           # The questionable/error-prone code goes here,in an indented block
           # It can contain statements, loops, if-else blocks, or other executable code.
           x_value, operation, y_value, *rest = equation
           ...
           ...

        except:
            # Code for what to do when an error gets thrown in the code above.
            # This could be one error, or more complicated logging, error checking and messaging.
            raise ValueError("syntax error")
```
