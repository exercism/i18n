# Introducción

En Go 1.18, Go añadió compatibilidad con los **genéricos**.
Los genéricos te permiten escribir funciones y estructuras de datos que funcionan con distintos tipos sin duplicar código.

## ¿Por qué usar genéricos?

En Go, las funciones y los tipos normalmente trabajan con tipos concretos, como `int` o `string`.
Antes de los genéricos tenías dos opciones para admitir varios tipos.
En primer lugar, podías escribir varias funciones con nombres distintos, como `SumInts` y `SumFloats`.
Este enfoque genera código duplicado que es difícil de mantener.
En segundo lugar, podías usar la interfaz vacía `any` (`interface{}`).
Sin embargo, la interfaz vacía elimina las comprobaciones de tipos en tiempo de compilación y exige aserciones de tipo en tiempo de ejecución.
Los genéricos resuelven este problema porque aportan seguridad de tipos y, al mismo tiempo, evitan el código duplicado.

## Funciones genéricas

Para definir una función genérica, añades **parámetros de tipo** entre corchetes (`[...]`) después del nombre de la función.
Este es un ejemplo de una función genérica que devuelve un slice invertido:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

En este ejemplo, `T` es un parámetro de tipo.
Puedes pensar en `T` como un marcador de posición para un tipo real.
La palabra clave `any` dentro de los corchetes es una **restricción de tipo**.
La restricción indica al compilador qué tipos están permitidos para `T`.
Aquí, `any` significa que `T` puede ser cualquier tipo.

### Llamar a funciones genéricas

Puedes llamar a una función genérica pasando el tipo real entre corchetes.
Ese tipo real se denomina **argumento de tipo**.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

En la mayoría de los casos, el compilador de Go puede detectar el tipo automáticamente a partir de los argumentos de la función.
Esta funcionalidad se llama **inferencia de tipos**.
Con la inferencia de tipos, no necesitas escribir el argumento de tipo entre corchetes.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

En este ejemplo, el compilador ve que `words` es un slice de strings, así que infiere que `T` es `string`.

## Restricciones de tipo

Todo parámetro de tipo debe tener una restricción.
Una restricción especifica qué tipos puedes usar como argumentos de tipo.
Además, la restricción determina qué operaciones puedes realizar sobre los valores de ese tipo.

### La restricción `any`

La restricción `any` permite cualquier tipo.
En Go, `any` es un alias de la interfaz vacía `interface{}`.
Como `any` permite todos los tipos, la función solo puede realizar operaciones que funcionen con todos los tipos de Go.
Por ejemplo, si tienes dos valores `any` que contienen slices, no se pueden comparar con `==`, ya que los slices no se pueden comparar usando `==`.

### La restricción `comparable`

Go incluye una restricción integrada llamada `comparable`.
La restricción `comparable` permite cualquier tipo que admita los operadores `==` y `!=`.
Entre los tipos comparables están los booleanos, los números, los strings, los punteros, los canales y los structs o arrays formados por tipos comparables.

Este es un ejemplo de una función que comprueba si un slice contiene un elemento concreto:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Como `T` usa la restricción `comparable`, usar `elem == target` es válido.
Si sustituyes `comparable` por `any`, el compilador mostrará un error.

### Restricciones personalizadas mediante conjuntos de tipos en interfaces

A partir de Go 1.18, las interfaces pueden definir conjuntos de tipos además de métodos.
Puedes usar el carácter de barra vertical `|` para enumerar los tipos permitidos en una interfaz.

```go
type Number interface {
    int | int64 | float64
}
```

Ahora puedes usar `Number` como restricción de una función:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Como todos los tipos de `Number` admiten el operador `*`, Go permite `value * 2` dentro de la función.

### La aproximación del tipo subyacente `~`

A veces creas una definición de tipo personalizada a partir de un tipo primitivo:

```go
type MyInt int
```

La restricción `Number` definida arriba solo permite los tipos exactos `int`, `int64` y `float64`.
Si pasas un valor de tipo `MyInt` a `Double`, el compilador da un error porque `MyInt` no coincide con `int`.
Para permitir cualquier tipo cuyo tipo subyacente sea `int`, añade una tilde `~` delante del tipo:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

Ahora puedes usar `Double` con valores de tipo `MyInt`.

### La restricción `cmp.Ordered`

La biblioteca estándar proporciona la restricción `cmp.Ordered` en el paquete [`cmp`][doc-cmp].
La restricción `cmp.Ordered` permite cualquier tipo que admita los operadores de comparación `<`, `<=`, `>` y `>=`.

## Tipos genéricos

También puedes usar parámetros de tipo para definir tipos genéricos, como los structs.
Este es un ejemplo de una estructura de datos `Stack` genérica:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Cuando declaras una variable de un tipo genérico, debes indicar el argumento de tipo entre corchetes:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

La inferencia de tipos solo funciona con funciones genéricas.
Siempre debes especificar el argumento de tipo cuando creas valores de un tipo genérico.

## Cuándo usar genéricos

Los genéricos son una funcionalidad potente, pero no necesitas usarlos para todos los problemas.

Usa genéricos en situaciones como estas:
- Estás creando estructuras de datos, como árboles, listas enlazadas o cachés, que funcionan con cualquier tipo de elemento.
- Estás escribiendo funciones de utilidad que operan sobre slices o mapas de cualquier tipo, como filtrar, ordenar o buscar.
- Necesitas exactamente la misma implementación para varios tipos y quieres seguridad de tipos en tiempo de compilación.

En cambio, usa interfaces en situaciones como estas:
- Te importan el comportamiento y los métodos, más que el tipo de dato subyacente.
  Por ejemplo, si quieres leer y procesar datos de fuentes de distintos tipos (ficheros, red, TTY), usarías `func Process(src io.Reader)` en lugar de `func Process[T](src T)`.
- Tipos distintos necesitan implementaciones de métodos distintas para hacer su trabajo.
