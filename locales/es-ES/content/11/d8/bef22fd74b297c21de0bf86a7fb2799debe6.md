# Instrucciones

Eres el oficial de guardia a bordo de un cúter que atraviesa el estrecho de Bering. Tres fuentes anuncian la posición de cada témpano y cada promontorio a la vista:

- La **mesa de cartas** habla en direcciones de la brújula: `north`, `east`, `south`, `west`. Solo un rumbo, sin distancia.
- El **navegante** habla en coordenadas *polares* desde la última situación del cúter: una magnitud en millas náuticas y una demora en grados en sentido horario desde el norte (así, `0` es north, `90` es east, `180` es south y `270` es west).
- El **vigía de la cofa** habla en coordenadas *relativas*: una distancia hacia delante y uno de estos valores: `ahead`, `starboard`, `behind`, `port`. Las demoras relativas se miden respecto al *rumbo actual del buque*: el capitán anuncia ese rumbo en el puente antes de cada guardia.

Tu trabajo es convertir las tres a un mismo sistema cartesiano `(x, y)` para poder trazar la carta. Las demoras están en grados; `(0, 1)` es una milla náutica hacia el norte y `(1, 0)`, una milla náutica hacia el este.

## 1. El modelo de datos y el cartesiano para los cardinales

Primero define las piezas que comparte todo el ejercicio:

- Define tres tuplas: `cardinal` (un campo, `direction`), `polar` (campos `magnitude` y `bearing`) y `relative` (campos `distance` y `bearing`).
- Declara los símbolos del rumbo con `SYMBOLS:`: `north`, `east`, `south`, `west`, `ahead`, `starboard`, `behind`, `port`.
- Declara una variable dinámica `heading` con `SYMBOL:` (la tarea 3 la usa).
- Declara dos palabras genéricas: `GENERIC: >cartesian ( direction -- x y )` y `GENERIC: flip ( direction -- direction' )`. Añadirás sus métodos en las siguientes tareas.

A continuación, añade el método `M: cardinal` de `>cartesian`, que devuelve el vector unitario de la dirección indicada.

```factor
T{ cardinal { direction north } } >cartesian . .
! => 1
! => 0
! (top of stack is `y`, just below it is `x`)
```

## 2. El cartesiano para las polares

Añade un método `M: polar` a `>cartesian` que convierta la forma polar a `(x, y)`:

```
x = magnitude * sin(bearing-in-radians)
y = magnitude * cos(bearing-in-radians)
```

```factor
T{ polar { magnitude 10 } { bearing 90 } } >cartesian . .
! => 0   (close to zero — the cosine of π/2 isn't exactly 0 in floats)
! => 10
```

## 3. El cartesiano para las relativas

Añade un método `M: relative` a `>cartesian`. El detalle está en que una demora relativa se mide respecto al *rumbo actual del buque*, que no forma parte de la tupla. Lee la variable `heading` (declarada en la tarea 1) con `heading get`, suma el desfase de la demora (`ahead = 0`, `starboard = 90`, `behind = 180`, `port = 270`) y produce el punto cartesiano. Quien llama establece `heading` dentro de un bloque `with-variable`.

```factor
0 heading [
    T{ relative { distance 5 } { bearing starboard } } >cartesian
] with-variable . .
! => 0   (heading 0 is north; starboard is east; (5, 0))
! => 5
```

## 4. Invertir

Añade los métodos del genérico `flip` (declarado en la tarea 1) para que devuelva la dirección opuesta.

- Para `cardinal`: north ↔ south, east ↔ west.
- Para `polar`: suma 180° a la demora (módulo 360).
- Para `relative`: ahead ↔ behind, starboard ↔ port.

```factor
T{ cardinal { direction north } } flip .
! => T{ cardinal { direction south } }

T{ polar { magnitude 10 } { bearing 90 } } flip .
! => T{ polar { magnitude 10 } { bearing 270 } }

T{ relative { distance 5 } { bearing ahead } } flip .
! => T{ relative { distance 5 } { bearing behind } }
```

## 5. Sumar demoras

Define `add-bearings ( a b -- x y )`, que convierte ambas direcciones a cartesianas y devuelve su suma. Funciona con cualquier combinación de `cardinal`, `polar` y `relative`: esa es la ventaja de usar un genérico para `>cartesian`.

```factor
T{ cardinal { direction north } } T{ cardinal { direction east } } add-bearings . .
! => 1
! => 1
```
