# Introducción

## Excepciones

Todos los errores de Elixir implementan el _Exception Behaviour_. Igual que el _Access Behaviour_, el _Exception Behaviour_ define funciones de callback que un módulo debe implementar para cumplir el contrato de software del behaviour. Una vez que se define un error, este tiene las siguientes propiedades:

- El nombre del módulo define el nombre del error.
- El módulo define un struct de error.
- El struct tendrá un campo `:message`.
- El módulo se puede usar con `raise/1` y `raise/2` para lanzar el error deseado

El _Exception Behaviour_ también especifica dos callbacks: `message/1` y `exception/1`. Si no se implementan, se usarán las implementaciones por defecto. `message/1` transforma el struct de error en un mensaje legible cuando se llama con `raise`. `exception/1` permite añadir contexto adicional al mensaje cuando se llama con `raise/2`

### Definir una excepción

Para definir una excepción a partir de un módulo de error, usamos la macro `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### Usar las excepciones

Los errores definidos se pueden usar como un error integrado, con `raise/1` o `raise/2`.

- `raise/1` lanza un error concreto por el nombre de su módulo o, si el argumento es un string, lanzará un `RuntimeError` con el string como mensaje.
- `raise/2` lanza un error concreto por el nombre de su módulo y acepta un argumento de atributos que se usa para obtener el error con el mensaje adecuado.
