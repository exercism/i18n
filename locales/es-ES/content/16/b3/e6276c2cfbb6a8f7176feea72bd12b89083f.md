# Acerca de

El tipo `Result` es la solución que ofrece el lenguaje Elm para notificar errores y recuperarse de ellos. Se parece bastante al tipo `Maybe`, pero mientras que el `Nothing` de `Maybe` codifica algún tipo de fallo, no te dice nada sobre _por qué_ ha fallado. `Result` incluye un contexto sobre por qué ha fallado algo.

## Definición y variable de tipo

El tipo `Result` se define del siguiente modo:

```elm
type Result error value
  = Ok value
  | Err error
```

En pocas palabras, este tipo codifica el resultado de una operación que o bien tiene éxito y devuelve un `value`, o bien falla y devuelve una explicación del fallo (`error`).

Esto se conoce como una definición de «tipo personalizado» en la terminología de Elm.
Los tipos personalizados se presentan con detalle en otro concepto de este track, pero no los necesitamos para entender `Result` en concreto.
El `error` y el `value` de `OK value` y `Error error` representan una variable de tipo, lo que significa que puede ser cualquier tipo, como `Int`, `Bool` o `String`.
Por lo tanto, un `Result String Int` es una variable de la que se espera que contenga un `Int` y, si hay un error, este se representará como un `String`.

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## Cómo leer el contenido de un valor Result

El contenido de un valor `Result` se lee mediante la «coincidencia de patrones».
La coincidencia de patrones también se presenta con más detalle en otro concepto, así que aquí nos centramos solo en cómo funciona la coincidencia de patrones con un `Result`.

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

Siempre que usas un valor `Result`, el compilador de Elm comprueba que tu código contemple todas las posibilidades, de modo que nunca puedes aplicar coincidencia de patrones a un `Result` y ocuparte solo del caso en el que hay un `Ok value`.
Puede parecer molesto al principio, pero es una de las mayores fortalezas del lenguaje Elm.
Esto evita cientos de bugs y hace que la refactorización guiada por el compilador sea una experiencia sin miedo y gratificante.

## Cómo manipular el contenido de un valor Result

Hay varias funciones para trabajar con tipos `Result`, que suelen ser preferibles a la coincidencia de patrones. `Result.map` sirve para transformar el valor, y `Result.andThen` sirve para encadenar funciones que pueden fallar.

Result.map se usa para cambiar el valor Ok y resulta útil para encadenar funciones sin tener que preocuparte de si el Result contiene un error o no. Si el valor es Ok, Result.map llama a la función encadenada (`formatAge`, más abajo), pero si hay un error, Result.map no hace nada y se limita a devolver el error.

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

Result.andThen se usa para cambiar el valor Ok y resulta útil para encadenar funciones sin tener que preocuparte de si el Result contiene un error o no. Es similar a Result.map, pero Result.andThen trabaja con una función encadenada (`formatSpecialBirthday`, más abajo) que también devuelve un Result. `Result.map` también puede hacerlo, pero acaba generando una capa extra de anidamiento, que `andThen` evita con ingenio.

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
