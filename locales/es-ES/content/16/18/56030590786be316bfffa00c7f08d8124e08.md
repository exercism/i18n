# Anexo de instrucciones

## Palabras

Define dos tuplas envoltorio que extienden `disposable` (de
`destructors`) y que almacenan el flujo subyacente junto con los
contadores enteros `bytes` y `ops`:

- `metered-input < disposable` con las ranuras `stream`, `bytes` y `ops`.
- `metered-output < disposable` con las ranuras `stream`, `bytes` y `ops`.

Construye cada una con `new-disposable` (en lugar de `new`) para que el
envoltorio se registre en el framework de destructores.

- `<metered-input> ( stream -- m )`: envuelve un flujo de entrada.
- `<metered-output> ( stream -- m )`: envuelve un flujo de salida.

Declara cada tupla como instancia del mixin de flujo correspondiente:

```
INSTANCE: metered-input  input-stream
INSTANCE: metered-output output-stream
```

A continuación, proporciona métodos `M:` que deleguen en el flujo
subyacente mientras actualizan los contadores:

- Para `metered-input`: [`stream-read1`][stream-read1],
  [`stream-read-unsafe`][stream-read-unsafe],
  [`stream-element-type`][stream-element-type] (delegación) y
  [`dispose*`][dispose*].
- Para `metered-output`: [`stream-write1`][stream-write1],
  [`stream-write`][stream-write], [`stream-flush`][stream-flush]
  (delegación) y [`dispose*`][dispose*].

Cada lectura o escritura correcta debe sumar a `bytes>>` el número de
bytes transferidos e incrementar `ops>>` en uno. Una lectura que llegue
al final del fichero sigue contando como una operación, pero transfiere
cero bytes. `dispose*` debe pasar directamente al flujo subyacente.
