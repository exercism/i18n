# Introducción

En otras partes del temario hemos visto varios tipos de datos con características diferentes.

- Los vectores atómicos son unidimensionales y homogéneos en cuanto a tipo.
- Las listas son unidimensionales y sus elementos pueden ser de tipos heterogéneos.
- Las matrices y los arrays son multidimensionales y homogéneos.

En este concepto veremos formas de almacenar datos multidimensionales y heterogéneos.
En la práctica, _la mayoría_ de los datos del mundo real son así, de modo que ahora llegamos al núcleo de cómo se usa R (en su mayor parte) en la práctica.

## Variantes de dataframe

A lo largo de las décadas, R ha añadido varios tipos de datos para manejar datos tabulares.

Este temario se centrará principalmente en los tibbles, pero es útil conocer las alternativas.

### El `data.frame`

En el R base, un `data.frame` es una `list` de `vectors` de la misma longitud.
Se puede concebir como una tabla rectangular de datos en la que cada columna es homogénea, pero cada fila puede contener (y normalmente contiene) tipos de datos diferentes.

Un ejemplo para ilustrarlo:

```R
# create the column vectors
languages <- c("Fortran", "R", "Python", "Julia")
created <- c(1957, 1993, 1991, 2012)
has.syllabus <- c(FALSE, TRUE, TRUE, TRUE)

# join columns to create the dataframe
df <- data.frame(languages, created, has.syllabus)
df
#>   languages created has.syllabus
#> 1   Fortran    1957        FALSE
#> 2         R    1993         TRUE
#> 3    Python    1991         TRUE
#> 4     Julia    2012         TRUE
 ```

 Tenemos una columna de strings, una columna de números y una columna de booleanos.
 Cuando se amplía la escala, es una forma intuitiva de representar muchas colecciones de datos del mundo real.

### El `tibble`

El diseño de `data.frame` es _antiguo_.

La experiencia de varias décadas, junto con los cambios en la forma de usar R, llevaron a un rediseño que creó una alternativa modernizada en el Tidyverse: los tibbles.

En comparación con el R base, los tibbles tienen:

- Valores predeterminados distintos, para reducir problemas habituales.
- Menos disposición a forzar la conversión de tipos de datos durante la entrada.
- Mensajes de error más numerosos y más claros.
- Formatos de visualización distintos y, por lo general, mejores.

En resumen, un `tibble` pretende «_hacer menos y quejarse más_», algo que también se describe como «_perezoso y gruñón_».

Los tipos suelen ser intercambiables: cualquier función que acepte un `data.frame` también aceptará un `tibble`, y _vice versa_.

Las conversiones entre los tipos son sencillas, con `as_tibble(df)` y `as.data.frame(tbl)`.

Para el trabajo nuevo, usar tibbles probablemente te ayudará a crear código más robusto.
Sin embargo, el código y los datos heredados abundan en el mundo de R, así que es probable que el `data.frame` siga siendo habitual durante mucho tiempo.

```R
# column vectors are same as for data.frame
library(tibble)
tbl <- tibble(languages, created, has.syllabus)
tbl
  # A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 R            1993 TRUE        
#> 3 Python       1991 TRUE        
#> 4 Julia        2012 TRUE      
```

Fíjate en el formato de impresión predeterminado: la línea de comentario con las dimensiones se imprime automáticamente y también se muestran los tipos de las columnas.

## Trabajar con tibbles

Los tibbles son una parte fundamental del Tidyverse, así que añádelos con `library(tibble)` o con `library(tidyverse)`.

### Crear un tibble

De la forma más sencilla, podemos usar la función `tibble()` para unir vectores columna, igual que con `data.frame()`.
En una sección anterior se mostró un ejemplo de esto.

Si te resulta más cómodo introducir los valores por filas, la función correspondiente es `tribble()`.

En la práctica, hay decenas de formas de crear tibbles, ya que son el formato de salida predeterminado de una amplia variedad de funciones del Tidyverse.

## Manipular un tibble

En el concepto de Programación funcional se habló de la librería `purrr` para manipular vectores y listas (estructuras de datos unidimensionales).

Para los dataframes (ya sean tradicionales o tibbles), la librería que corresponde usar es `dplyr`.

### Subconjuntos

Los dataframes, incluidos los tibbles, se pueden tratar como listas de vectores columna, así que la indexación de listas recupera una columna concreta.

```R
tbl
# A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 R            1993 TRUE        
#> 3 Python       1991 TRUE        
#> 4 Julia        2012 TRUE    

tbl$created
#> [1] 1957 1993 1991 2012
```

También se puede indexar un dataframe con indexación al estilo de las matrices.

```R
tbl[c(2, 4), 1:2]
  # A tibble: 2 × 2
#>   languages created
#>   <chr>       <dbl>
#> 1 R            1993
#> 2 Julia        2012
```

En el R moderno con el ecosistema Tidyverse, las funciones de `dplyr` suelen ser más flexibles y cómodas, y serán el centro de atención durante el resto de este concepto.

### Operaciones por columnas

Obtén una sola columna con `pull()`, indicando el nombre o el número secuencial (los números negativos cuentan de derecha a izquierda).

```R
tbl |> pull(created)
#> [1] 1957 1993 1991 2012
```

Este es el mismo resultado que `tbl$created`, pero usando una función que encaja bien en un pipeline.

Para obtener varias columnas, la función adecuada es `select()`, que es muy versátil.
Obtén (o descarta) columnas según las propiedades de su nombre o su tipo.

```R
# Range with position and/or name
tbl |> select(1:created)
  # A tibble: 4 × 2
#>   languages created
#>   <chr>       <dbl>
#> 1 Fortran      1957
#> 2 R            1993
#> 3 Python       1991
#> 4 Julia        2012      

# Use type of column
tbl |> select(where(is.numeric))
  # A tibble: 4 × 1
#>   created
#>     <dbl>
#> 1    1957
#> 2    1993
#> 3    1991
#> 4    2012
```

Se permiten varios criterios, usando los operadores booleanos `&`, `|` y `!` (y, o, no).

Tanto poder parece un poco absurdo con nuestro dataframe de juguete de lenguajes.
Por suerte, el tibble `starwars` está incluido en `dplyr`, lo que nos da algo más grande con lo que practicar.

```R
# pick a subset of columns
starwars |> 
  select(name | ends_with("color")) |> 
  head(5)
  # A tibble: 5 × 4
#>   name           hair_color skin_color  eye_color
#>   <chr>          <chr>      <chr>       <chr>    
#> 1 Luke Skywalker blond      fair        blue     
#> 2 C-3PO          NA         gold        yellow   
#> 3 R2-D2          NA         white, blue red      
#> 4 Darth Vader    none       white       yellow   
#> 5 Leia Organa    brown      light       brown    
```

### Operaciones por filas

Obtén las filas que cumplen ciertos criterios con `filter()`, o exclúyelas con `filter_out()`.

```R
starwars |> 
  select(name:mass) |> 
  filter(between(height, 150, 165) & !is.na(mass))
  # A tibble: 4 × 3
#>   name               height  mass
#>   <chr>               <int> <dbl>
#> 1 Leia Organa           150    49
#> 2 Beru Whitesun Lars    165    75
#> 3 Nien Nunb             160    68
#> 4 Ben Quadinaros        163    65
```

Los criterios de filtrado pueden ser arbitrariamente complejos, pero siempre se basan en el _contenido_ de las filas.

Si se conocen los _números_ de fila, podemos usar varias funciones `slice()`.

```R
starwars |> 
  select(name | homeworld) |> 
  slice(20:25)
  # A tibble: 6 × 2
#>   name             homeworld
#>   <chr>            <chr>    
#> 1 Palpatine        Naboo    
#> 2 Boba Fett        Kamino   
#> 3 IG-88            NA       
#> 4 Bossk            Trandosha
#> 5 Lando Calrissian Socorro  
#> 6 Lobot            Bespin   
```

## Modificar un tibble

Primera advertencia: el comportamiento predeterminado de _copiar al modificar_ hace que el tibble original normalmente no cambie.

La mayoría de las modificaciones se aplican por columnas.

Los nombres de las columnas se pueden cambiar con `rename(newname = oldname)`, o con `rename_with()` para aplicar una función.
Fíjate en la sintaxis dentro de `rename()`.
El _contenido_ de la columna `oldname` se _vincula_ al nombre `newname`, de ahí el orden.

El orden de las columnas se puede cambiar con `relocate()`.
Las columnas especificadas se mueven de forma predeterminada a la posición o posiciones más a la izquierda, pero se puede usar un argumento `.before` o `.after` para un posicionamiento más preciso.

```R
sw <- starwars |> select(name:species) |> slice(1:4)
sw
  # A tibble: 4 × 11
#>   name           height  mass hair_color skin_color  eye_color birth_year sex   gender    homeworld species
#>   <chr>           <int> <dbl> <chr>      <chr>       <chr>          <dbl> <chr> <chr>     <chr>     <chr>  
#> 1 Luke Skywalker    172    77 blond      fair        blue            19   male  masculine Tatooine  Human  
#> 2 C-3PO             167    75 NA         gold        yellow         112   none  masculine Tatooine  Droid  
#> 3 R2-D2              96    32 NA         white, blue red             33   none  masculine Naboo     Droid  
#> 4 Darth Vader       202   136 none       white       yellow          41.9 male  masculine Tatooine  Human  

sw |> relocate(c(species, homeworld), .after = name)
  # A tibble: 4 × 11
#>   name           species homeworld height  mass hair_color skin_color  eye_color birth_year sex   gender   
#>   <chr>          <chr>   <chr>      <int> <dbl> <chr>      <chr>       <chr>          <dbl> <chr> <chr>    
#> 1 Luke Skywalker Human   Tatooine     172    77 blond      fair        blue            19   male  masculine
#> 2 C-3PO          Droid   Tatooine     167    75 NA         gold        yellow         112   none  masculine
#> 3 R2-D2          Droid   Naboo         96    32 NA         white, blue red             33   none  masculine
#> 4 Darth Vader    Human   Tatooine     202   136 none       white       yellow          41.9 male  masculine
```

Para cambios más grandes, `mutate()` te permite:

- Crear columnas nuevas que son funciones de columnas existentes.
- Reemplazar una columna existente, creando una columna nueva con el mismo nombre.
- Eliminar una columna, asignando a su valor `NULL`.

Está claro que `mutate()` es potente, puede resultar confuso y es un motivo para estar muy agradecido por el _copiar al modificar_.

No hay ninguna razón evidente para interesarse por el índice de masa corporal de los personajes de Star Wars, pero por si acaso:

```R
starwars |> 
  select(c(name, species, height, mass)) |> 
  mutate(BMI = mass / (height / 100)^2) |> 
  head(4)
  # A tibble: 4 × 5
#>   name           species height  mass   BMI
#>   <chr>          <chr>    <int> <dbl> <dbl>
#> 1 Luke Skywalker Human      172    77  26.0
#> 2 C-3PO          Droid      167    75  26.9
#> 3 R2-D2          Droid       96    32  34.7
#> 4 Darth Vader    Human      202   136  33.3
```

Las **operaciones por filas** son menos habituales para modificar un solo tibble (la combinación de varios tibbles se tratará en un concepto posterior).

Una excepción: `arrange()` ordena las filas según los valores de una o varias columnas.

```R
tbl
#>       A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 R            1993 TRUE        
#> 3 Python       1991 TRUE        
#> 4 Julia        2012 TRUE  

tbl |> arrange(languages)
#>       A tibble: 4 × 3
#>   languages created has.syllabus
#>   <chr>       <dbl> <lgl>       
#> 1 Fortran      1957 FALSE       
#> 2 Julia        2012 TRUE        
#> 3 Python       1991 TRUE        
#> 4 R            1993 TRUE     
```
