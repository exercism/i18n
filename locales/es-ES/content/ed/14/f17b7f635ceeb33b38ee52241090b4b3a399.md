# Acerca de

Para entender [`Box`][box], es útil entender qué son la [pila y el montículo][stack and heap].

La pila es un área de memoria que funciona como un búfer último en entrar, primero en salir (LIFO). Es muy rápido apilar datos en la pila, y también es rápido desapilarlos.
Los datos pueden incluir variables o direcciones de funciones, pero deben tener un tamaño fijo conocido en tiempo de compilación.

Si los datos tienen un tamaño desconocido en tiempo de compilación o un tamaño que puede cambiar, hay que asignarlos en el montículo. El proceso de asignación debe buscar
espacio suficiente en el montículo para almacenar los datos, escribir los datos en el montículo y apilar en la pila la dirección de memoria de esos datos, todo lo cual lleva
bastante más tiempo que simplemente poner los datos en la pila. Recuperar datos del montículo es un poco más lento, porque hay que pasar por la dirección de la
pila y seguirla hasta la ubicación de los datos en el montículo.

`Box` es un puntero inteligente que asigna datos en el montículo. La dirección está en la pila y apunta a los datos del montículo. Una [razón][reasons] para usar `Box`
es poner datos en el montículo cuando tienes un tipo cuyo tamaño no puede conocerse en tiempo de compilación y quieres usar un valor de ese tipo en un contexto que exige
un tamaño exacto. Un uso práctico de esto es cuando tienes varias structs que quieres manejar de la misma forma mediante un trait que todas implementan, como
en el ejemplo siguiente.

Supongamos que tenemos dos structs. Cada struct representa algo que puede resultar molesto. Podemos hacer que cada struct implemente un trait Annoyance así:

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

Ahora supongamos que queremos una función que nos devuelva una Annoyance basada en la hora del día que se le pase. Podemos probar primero esto, que descubrimos que no compila

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

El compilador, en toda su amabilidad, nos dice exactamente qué hacer: devolver un objeto trait en un `Box`. Si no sabes qué es un objeto trait,
una forma sencilla de describirlo es como una manera de devolver un objeto concreto mediante [despacho dinámico][dynamic dispatch] desde una función que podría devolver cualquier objeto
que implemente un trait determinado. Como necesitamos despacho dinámico, podemos probar a poner un `dyn` delante del nombre del trait y ver si nos lo acepta.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

Uno de los errores es que el tamaño de `dyn Annoyance` no puede conocerse en tiempo de compilación. Esto se debe a que `annoy_me` no sabe qué objeto trait concreto
va a devolver antes de que se la llame. Cada struct que implementa Annoyance podría tener campos distintos y ser de distinto tamaño. Y se nos recuerda que
uno de los usos de `Box` es para un tipo cuyo tamaño no puede conocerse en tiempo de compilación. Así que ahora probamos a usar un valor devuelto dentro de un `Box`, y envolvemos en un `Box` los valores devueltos
por la expresión `match`, así:

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

La firma de `Box` es `Box<T>`, donde `T` representa el tipo concreto que se va a empaquetar en el `Box`, colocado entre los corchetes angulares, como en `Box<dyn Annoyance>` de arriba.

Podemos consumir el objeto trait en un `Box` así:

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

que imprime

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

Como `my_annoyance` es de tipo `Box<dyn Annoyance>`, hay que desreferenciarlo desde el `Box` con el operador de desreferencia `*`. Después se referencia como un
`dyn Annoyance` para que la función `be_annoying` lo tome prestado.

Otra forma de implementarlo sería eliminar el requisito de que el parámetro tenga un tamaño conocido. En ese caso, la compilación crearía una función distinta
para cada variante de Annoyance, para poder despacharla de forma estática (un proceso llamado [monomorfización][monomorphization]), así:

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

Y todavía otra forma de implementarlo sería que la función `be_annoying` aceptara un `Box<dyn Annoyance>` y usara la [coerción de deref][deref coercion] para no
tener que desreferenciar el `Box` manualmente. Esto transferiría la propiedad del objeto trait Annoyance a la función `be_annoying`. Quedaría fuera del
scope al final de la función y ya no estaría disponible.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
