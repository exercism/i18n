# Acerca de

Cuando hacemos coincidencia de patrones sobre un valor en Gleam, tenemos que asegurarnos de que los patrones coinciden con todos los valores posibles del tipo; de lo contrario, el código no compilará.

Esta función debería rechazarse, ya que no contempla el caso en el que el array está vacío:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

La mayoría de las veces, en los programas de Gleam queremos contemplar todos los casos posibles, pero en algunos programas, como prototipos y scripts rápidos, puede que solo queramos centrarnos en el camino feliz y no escribir código para los demás casos. Aquí es donde entra en juego `let assert` de Gleam.

Con las aserciones con `let`, un patrón puede coincidir solo con algunos de los valores posibles de un tipo, y si el patrón no coincide con un valor, el programa fallará. Usando `let assert` podemos escribir la función anterior así:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Las bibliotecas de Gleam nunca deberían usar aserciones con `let`, ya que pueden hacer que el programa falle; en su lugar, deberían usar el tipo `Result` y dejar que el desarrollador de la aplicación decida cómo gestionar los errores.
