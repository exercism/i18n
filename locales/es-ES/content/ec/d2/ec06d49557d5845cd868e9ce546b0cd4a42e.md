# Acerca de

La E/S de Factor se construye sobre un único [protocolo][stream-protocol] que cualquier fuente o destino de datos puede implementar. Los streams incluidos, `<file-reader>`, `<file-writer>`, `<string-reader>`, `<string-writer>`, los sockets de red, los arrays de bytes y las ttys, son todas clases que implementan el mismo puñado de genéricos de [`io`][io] y extienden `disposable` de [`destructors`][destructors].

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe` es la lectura por lotes de bajo nivel: llena un búfer que proporciona quien llama y devuelve cuántos elementos se escribieron. Los públicos `stream-read` y `stream-read-partial` se construyen sobre él y se encargan de la asignación de memoria. La mayoría de los streams definidos por el usuario implementan `stream-read1` (cuando las lecturas se hacen de un elemento a la vez) o `stream-read-unsafe` (cuando las lecturas se pueden agrupar por lotes).

`stream-element-type` devuelve uno de dos tokens singleton: `+byte+` para los streams de bytes (lectores de ficheros, sockets) y `+character+` para los streams de caracteres (lectores de strings, ttys). Un stream envoltorio normalmente solo delega en el stream subyacente.

## Unirse a los mixins

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

Una clase puede ser uno, el otro o ambos. Unirse al mixin hace que los métodos predeterminados de `input-stream` / `output-stream` se despachen a tu clase, el mismo patrón de mixin abierto que `set` del vocabulario `sets`.

## El framework disposable

`new-disposable ( class -- disposable )` registra una instancia nueva en el scope actual del destructor para que una excepción en mitad de la configuración de recursos se desenrolle limpiamente:

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose` es la palabra pública; `dispose*` es el genérico que implementa la clase. Una sobrescritura de `dispose*` en una subclase debería limpiar su propio estado y después liberar los recursos que posea:

```factor
M: my-stream dispose* underlying>> dispose ;
```

El framework garantiza que `dispose*` se ejecuta como máximo una vez por objeto: las llamadas repetidas a `dispose` no hacen nada.

## Accesores con scope

Tres combinadores configuran el «stream de entrada/salida actual» global que usan `print`, `read1`, etc.:

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

Cada uno libera el recurso al salir, aunque la quotation lance una excepción. Son la forma en que la mayoría del código usa un stream personalizado en lugar de pasarlo por todas las llamadas.
