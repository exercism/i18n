# Anexo a las instrucciones

## Mensajes de excepción

A veces es necesario [lanzar una excepción](https://docs.python.org/3/tutorial/errors.html#raising-exceptions). Cuando lo hagas, siempre debes incluir un **mensaje de error significativo** para indicar cuál es el origen del error. Esto hace que tu código sea más legible y ayuda mucho a la hora de depurar. En situaciones en las que sabes que el origen del error será de un tipo concreto, puedes optar por lanzar uno de los [tipos de error integrados](https://docs.python.org/3/library/exceptions.html#base-classes), pero aun así debes incluir un mensaje significativo.

Este ejercicio en concreto requiere que uses la [instrucción raise](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement) para «lanzar» `ValueErrors` si al constructor `Queen` se le pasan números negativos, o números que no sean una fila o una columna válidas. Las pruebas solo pasarán si haces tanto el `raise` de la `exception` como si incluyes un mensaje con ella. También debes hacer `raise` de un `ValueError` si las dos reinas que se pasan al método `can_attack()` están en la misma casilla.

Para lanzar un `ValueError` con un mensaje, escribe el mensaje como argumento del tipo `exception`:

```python
# if the row parameter is negative
raise ValueError("row not positive")

# if the row parameter is not on the defined board
raise ValueError("row not on board")

# if the column parameter is negative
raise ValueError("column not positive")

# if the column parameter is not on the defined board
raise ValueError("column not on board")

# if both the queens are on the same location
raise ValueError("Invalid queen position: both queens in the same square")
```
