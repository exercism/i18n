# Introducción

Recibirás una solución ejemplar de cada ejercicio que resuelvas en Exercism.
En el track de Julia, esas soluciones suelen contener [docstrings](https://en.wikipedia.org/wiki/Docstring).
Después de resolver este ejercicio, sabrás cómo se estructuran los docstrings, cómo escribirlos y cómo acceder a ellos desde el REPL.

~~~~exercism/note
No es obligatorio que escribas docstrings para tus funciones mientras resuelves ejercicios en el track de Julia si no quieres.
~~~~

## Sintaxis

Cualquier string justo antes de cualquier tipo de objeto de Julia, por ejemplo una función o un tipo, se interpretará como un docstring que documenta ese objeto.
Por ejemplo:

```julia
"Tell a joke."
joke() = ...
```

Los docstrings en Julia se formatean con [Markdown](https://en.wikipedia.org/wiki/Markdown).
Esto permite usar elementos como la indentación, los bloques de código o el texto en negrita dentro de los docstrings.

~~~~exercism/note
Puedes encontrar una lista de las funcionalidades de Markdown compatibles en la [documentación de la biblioteca estándar de Markdown](https://docs.julialang.org/en/v1/stdlib/Markdown/).
~~~~

Un docstring más complejo puede tener este aspecto:

````julia
"""
    mean(x, y)

Compute the mean value of `x` and `y`.
"""
mean(x, y) = (x + y) / 2
````

El manual de Julia contiene algunas convenciones que conviene seguir:

> - Muestra siempre la signatura de una función al principio de la documentación, con una indentación de cuatro espacios para que se imprima como código de Julia.
> - Incluye una única frase de una línea que describa qué hace la función o qué representa el objeto, después del bloque de signatura simplificada.
>    Si hace falta, añade más detalles en un segundo párrafo, después de una línea en blanco.
>    Cuando documentes funciones, esa frase de una línea debe usar la forma imperativa («haz esto», «devuelve aquello») en lugar de la tercera persona (no escribas «Devuelve la longitud...»).
>    Debe terminar con un punto.
> - No te repitas.
>    Como el nombre de la función lo da la signatura, no hace falta empezar la documentación con «La función `mean`...»: ve directo al grano.
> - Usa comillas invertidas para identificar código y ecuaciones.
> - Coloca los caracteres `"""` de inicio y de fin en líneas propias.

~~~~exercism/note
La lista anterior solo cubre las convenciones que puedes necesitar o encontrar en el contexto de Exercism.
Puedes encontrar una lista completa y sin abreviar en el [manual de Julia](https://docs.julialang.org/en/v1/manual/documentation/).
Las demás convenciones para documentar conceptos de Julia más avanzados se presentarán junto con el concepto en ejercicios posteriores.
~~~~

## Acceder a los docstrings

Puedes buscar docstrings en el REPL escribiendo `?` seguido del nombre de la función o del objeto, por ejemplo:

```julia-repl
help?> println
search: println printstyled print sprint isprint

  println([io::IO], xs...)


  Print (using print) xs followed by a newline. If io is not supplied, prints to stdout.

  Examples
  ==========

  julia> println("Hello, world")
  Hello, world

  julia> io = IOBuffer();

  julia> println(io, "Hello, world")

  julia> String(take!(io))
  "Hello, world\n"
```

Esto también se puede usar como una búsqueda básica, por ejemplo si no estás seguro de la escritura exacta de una función:

```julia-repl
help?> printline
search:

Couldn't find printline
Perhaps you meant println, pipeline, @inline or print
  No documentation found.

  Binding printline does not exist.
```
