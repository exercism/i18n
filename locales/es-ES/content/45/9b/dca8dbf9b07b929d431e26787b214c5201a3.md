# Pruebas

El track de Factor usa **Factor 0.101**. Cada ejercicio viene con un vocabulario `exercism-tools` incluido que define las palabras de análisis sintáctico `STOP-HERE` y `TASK:`, además de un ejecutor de pruebas. Desde el directorio del ejercicio, ejecuta:

```
factor -roots=. -run=exercism-tools <exercise>
```

Por ejemplo, para el ejercicio `hello-world`:

```
factor -roots=. -run=exercism-tools hello-world
```

El ejecutor termina con estado 0 cuando pasan todas las pruebas y con un estado distinto de cero, junto con información de diagnóstico, cuando falla alguna prueba.

## Pruebas omitidas

Resolver un ejercicio significa conseguir que todas sus pruebas pasen.
De forma predeterminada, cuando ejecutas las pruebas solo se ejecuta una (la primera).
Esto es intencionado, ya que te permite centrarte únicamente en hacer que esa prueba pase.

El mecanismo es la línea `STOP-HERE` del fichero de pruebas: en el momento del análisis, le indica a Factor que ignore todo lo que hay debajo, de modo que el ejecutor solo ve las pruebas que están por encima. Cuando pase tu primera prueba, puedes habilitar más pruebas de dos maneras:

- **Elimina la línea `STOP-HERE`** para habilitar de una vez todas las pruebas restantes.
- **Mueve la línea `STOP-HERE` más abajo** para habilitar las pruebas de una en una, o una tarea cada vez. Los ejercicios de concepto agrupan las pruebas bajo marcadores `TASK:`; mover `STOP-HERE` justo antes del siguiente `TASK:` es un paso natural.

Cuando hayas habilitado todas las pruebas y tu implementación las haga pasar todas, ¡habrás resuelto el ejercicio!
