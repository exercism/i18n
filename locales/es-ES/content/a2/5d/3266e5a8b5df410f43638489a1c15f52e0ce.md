# Tests

Cada ejercicio contiene un archivo de tests.
Ejecuta los tests con el programa `bats`.
```bash
bats test-hello-world.bats
```

Tendrás que instalar `bats`.
Consulta la página [Testing on the Bash track][bash] para obtener instrucciones sobre cómo instalar `bats` en tu sistema.

### bats está implementado en bash

El archivo de bats es un script de bash, con algunas funciones especiales que reconoce el comando `bats`.
Verás algunos tests con este aspecto:
```sh
gawk -f some-exercise.awk <<< "some,input,here"
```
Esa sintaxis `<<<` es un [Here String][here-string] de bash.
Envía el string de la derecha a la entrada estándar del programa de la izquierda.
Es ([aproximadamente][so]) lo mismo que
```sh
echo "some,input,here" | gawk -f some-exercise.awk
```

## Ayuda para las funciones assert

Los tests usan funciones de la biblioteca [bats-assert][bats-assert].
Allí encontrarás ayuda para las distintas funciones `assert*`.

## Tests omitidos

Resolver un ejercicio significa hacer que todos sus tests pasen.
De forma predeterminada, cuando ejecutas los tests solo se ejecuta un test (el primero).
Esto es intencionado, ya que te permite centrarte únicamente en hacer que ese test pase.
Cuando pase, puedes habilitar el siguiente test comentando o eliminando las

    [[ $BATS_RUN_SKIPPED == true ]] || skip

anotaciones que preceden a los demás tests.

## Anular las omisiones

Para ejecutar todos los tests, incluidos los que tienen anotaciones `skip`, puedes ejecutar:
```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Puede resultar cómodo usar una función envoltorio para escribir menos: en `bash` puedes hacer lo siguiente:
```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```
Después, ejecuta los tests simplemente con:
```bash
bats
```

## Salida de depuración

```exercism/caution
Esto funciona en local con `bats`, pero **no** en el editor en línea de Exercism.
```

Al ejecutar los tests, `bats` captura tanto stdout como stderr para compararlos con la salida esperada.
Si imprimes mensajes de depuración en stdout o stderr, se incluirán en la salida capturada y pueden hacer que el test falle.

Para imprimir información de depuración sin afectar a los resultados de los tests, `bats` proporciona el descriptor de archivo **3** para este fin.
Todo lo que se imprima en el archivo `/dev/fd/3` se mostrará durante la ejecución de los tests, pero no se incluirá en la salida capturada que se usa para las afirmaciones.

Ejemplo:

```awk
BEGIN {
    # This debug message will not interfere with test output comparison
    print "a debug message" > "/dev/fd/3"

    # Normal program output (this is what your tests will see and compare)
    print "Hello, World!"
}
```

Ejemplo de ejecución:

```none
$ bats test-hello-world.bats
test-hello-world.bats
 ✓ Say Hi!
a debug message

1 test, 0 failures
```

Esto te permite ver una salida de depuración útil sin afectar a los tests.

Ocultar los detalles en una función puede mejorar la legibilidad si la usas en varios lugares de tu código:

```awk
BEGIN {
    debug("starting ...")
}

# do stuff here ...

END {
    debug("... finished")
}

function debug(msg) {print msg > "/dev/fd/3"}
```
