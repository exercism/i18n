# Acerca de

## const

El modificador [`const`][constants] se puede aplicar (y, por lo general, se debería) a cualquier campo cuyo valor se conozca en tiempo de compilación y no cambie durante la vida del programa.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

El compilador te guiará sobre qué expresiones se pueden evaluar en tiempo de compilación. Se permiten las operaciones aritméticas simples, así como la concatenación de strings. Esto excluye cualquier evaluación que requiera el uso del montón o de la pila, por lo que no se dispone de llamadas a métodos ni de referencias a tipos no primitivos.

Hay cierto debate en la web sobre las ventajas de rendimiento de `const` frente a las variables. En el caso de una comparación con campos de instancia que no son `const`, podría haber un ahorro de memoria apreciable, pero en comparación con las variables estáticas, resulta francamente trivial. Cualquier consideración sobre el rendimiento de la CPU probablemente será vista por tus colegas como una [optimización prematura][premature-optimization].

Una razón más convincente para usar `const` es que mejora la capacidad de razonar sobre el código de quien lo mantiene. Ver de un vistazo que un campo está marcado como `const` o `readonly`, o que una propiedad no tiene descriptor de acceso `set`, permite a quien lo mantiene descartarlo en gran medida de su análisis. Es poco probable que sea el origen de errores. Es poco probable que plantee dificultades en un ejercicio de refactorización. Este [comentario de Stack Overflow][so-consts] aborda esta cuestión.

El modificador `const` también se puede aplicar a valores dentro de métodos:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

Identificar un valor con `const` de esta forma puede ser útil si se usa varias veces en el método o si quieres llamar la atención sobre su significado. No hay ninguna mejora de rendimiento frente a usar literales en línea.

## readonly

El modificador [`readonly`][readonly-fields] se puede aplicar (y, por lo general, se debería) a cualquier campo que no se pueda declarar como `const`, siempre que su valor no cambie durante la vida del programa y se establezca mediante un inicializador en línea o durante la instanciación (por el constructor o por un método al que llame el constructor).

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

Se recomienda el uso del modificador `readonly` por las mismas razones que se aplican a `const`. La práctica de restringir los campos de esta forma ayuda a quienes mantienen el código a razonar sobre él.

Ten en cuenta que añadir el modificador `readonly` a un campo solo impide que cambie el valor del campo. En el caso de los tipos agregados, no protege los campos ni las propiedades de ese tipo. En particular, no protege el contenido de los arrays.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

Para garantizar que todos los miembros de un tipo de referencia estén protegidos, los campos se pueden marcar como `readonly` y se pueden definir propiedades automáticas sin un descriptor de acceso `set`.

Deberías examinar las [colecciones de solo lectura][readonly-collections] de la Biblioteca de clases base.

Para los arrays, lo más parecido a una versión de solo lectura es el método [`Array.AsReadOnly<T>()`][as-read-only].
