# Introducción

Los [tipos personalizados][custom-types] de Elm representan un número fijo de casos con nombre. Cada valor se corresponde con exactamente uno de los casos con nombre.

Los tipos personalizados se definen con la palabra clave `type` y requieren muy poca sintaxis. Son una de las técnicas más importantes de la programación en Elm, y se usan para hacer que los valores posibles en el código coincidan exactamente con los valores válidos en la vida real, lo que no deja lugar a datos inválidos y hace que los [estados imposibles sean imposibles de representar en el código][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Cada caso de un tipo personalizado puede tener datos asociados, y casos distintos pueden tener distintos tipos de datos. Si ninguno de los casos tiene datos asociados, la unión discriminada es similar a lo que en otros lenguajes se suele llamar una _enumeración_ (o _enum_).

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Se puede crear un valor para un caso concreto refiriéndose a su nombre (`Spring`), cuando está definido en el mismo módulo o se importa con la sintaxis `import SeasonModule exposing (Season(..))`, o bien refiriéndose a su nombre completo (`Season.Spring`) cuando se importa con la sintaxis `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Los tipos personalizados, como todo en Elm, tienen _igualdad estructural_, lo que significa que dos valores del mismo caso y con los mismos datos (opcionales) son equivalentes.

La forma preferida de trabajar con tipos personalizados es la [coincidencia de patrones][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
