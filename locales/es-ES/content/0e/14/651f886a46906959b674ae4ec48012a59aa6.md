# Tests

Los tests de un proyecto de Elm están en el subdirectorio `tests/` de ese proyecto.
El conjunto de tests de cada ejercicio se puede ejecutar desde el directorio raíz de ese ejercicio.

```bash
$ cd ~/exercism/elm/hello-world
$ elm-test
```

## Vigila los cambios

Vuelve a ejecutar los tests automáticamente cuando guardes los cambios:

```bash
$ elm-test --watch
```

## Flujo de desarrollo guiado por tests

En la mayoría de los ejercicios, los tests ya están escritos en el archivo `tests/Tests.elm`.
Tu objetivo es hacer que pasen escribiendo el código necesario
en el archivo `src/<exercise>.elm`.
Céntrate en el primer test que falle, arréglalo,
luego elimina o comenta el siguiente fragmento `skip <|` en el archivo de tests y repite
hasta que pasen todos los tests.

## ¿Atascado?

Tu primer objetivo es conseguir que tu código compile, incluso con `Debug.todo` dentro.
Si sientes que no sabes cómo hacer algo,
a menudo es útil extraer esa parte a su propia función sin implementar.

```elm
complexOperationOnMultipleStrings : List String -> List String
complexOperationOnMultipleStrings allStrings =
    List.map complexOperation allStrings


complexOperation : String -> String
complexOperation input =
    Debug.todo "Extracted operation into its own function"
```

Añadir una anotación de tipo a esta función extraída
te ayudará a pensar y también ayudará al compilador a darte mejores mensajes de error.

## Limpiar tu código

Plantéate ejecutar [`elm-format`](https://github.com/avh4/elm-format) en tu código antes de enviarlo
e incluso configurarlo en tu editor de texto para que se formatee automáticamente al guardar.
