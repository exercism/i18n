# Introducción

El enlazado describe desde dónde se puede acceder a un identificador en el código.
Los valores con scope de bloque, de función o de prototipo de función no tienen enlazado.
Esto significa que no se puede acceder a ellos desde fuera de su scope.
Para obtener más información sobre el scope, consulta el [concepto de scope](../scope/introduction.md#Introduction).

## Enlazado externo

Los identificadores con scope de fichero tienen enlazado externo por defecto.
Se puede llamar a un identificador con enlazado externo desde cualquier fichero del programa.

## Enlazado interno

Se puede hacer que un identificador con scope de fichero tenga enlazado interno usando el especificador `static`.
Un identificador con enlazado interno solo se puede usar dentro de su fichero.

Por ejemplo

```c
int public_count = 0; // file scope, external linkage by default
static int private_count = 0;  // file scope, internal linkage 

// file scope, internal linkage
static void some_function()
{
    // code snipped
}

// file scope, external linkage by default
int main()
{
    // code snipped
}
```

El enlazado estático no debe confundirse con la duración de almacenamiento estática.
Para obtener más información sobre la duración de almacenamiento estática, consulta el [concepto de duración de almacenamiento](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#static-the-storage-specifier-not-to-be-confused-with-the-static-linkage-type).
