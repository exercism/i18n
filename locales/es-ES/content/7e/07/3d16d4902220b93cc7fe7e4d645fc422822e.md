# Acerca de

_«Las fechas y las horas son algo que enseñamos a niños pequeños. ¿Qué dificultad puede tener?»_

Muchos programadores han cometido ese error, y la experiencia posterior suele tener un efecto negativo en su salud y su felicidad.

Cualquiera que haga programación no trivial con fechas y horas debería estar al menos preparado para entender y mitigar los posibles problemas.

En este documento intentaremos dar una visión general de cómo Julia gestiona las fechas y las horas, pero será necesario consultar el [manual][Dates] para más detalles.
También hay un [Wikilibro][Wikibook] cuyas explicaciones pueden resultar más claras para algunos lectores, e incluye un útil [diagrama][type-hierarchy] de la jerarquía de tipos.

## El módulo `Dates`

La mayor parte de la funcionalidad básica está en `Dates`, un módulo que se incluye en una instalación predeterminada pero que no forma parte de la biblioteca estándar.

Para usar el módulo, hay dos opciones:

1. Añadir `import Dates` y, después, preceder todas las llamadas a funciones con `Dates.`
2. Añadir `using Dates`, lo que trae todo el módulo al espacio de nombres actual (_excepto unos pocos nombres problemáticos_).

```julia-repl
# option 1
julia> import Dates

julia> Dates.now()
2025-06-21T16:02:39.080

julia> now()  # wrong: need to include `Dates.` after an import
ERROR: UndefVarError: `now` not defined in `Main`


# option 2
julia> using Dates

julia> now()  # functions are now in the namespace
2025-06-21T16:03:04.161
```

El módulo `Dates` es grande y complicado, pero proporciona cuatro tipos principales de funcionalidad:

- `Dates.Date`, que incluye día, mes y año, pero no la hora del día.
- `Dates.Time`, que incluye la hora del día, con resolución de nanosegundos, pero no la fecha.
- `Dates.DateTime`, que combina fecha y hora con resolución de milisegundos.
- `Dates.Period`, que gestiona intervalos de tiempo y fecha.

Ten en cuenta que un `DateTime` generalmente _no_ incluye información de zona horaria (en Python esto se llamaría un datetime «naive»).
Una excepción es `now()`, que obtiene la hora local del reloj del sistema y puede convertirla a UTC si es necesario.

Otros cálculos de zonas horarias necesitan el paquete `TimeZones.jl`, que no forma parte de una instalación predeterminada.
A fecha de junio de 2025, esto no está disponible en Exercism, pero podría añadirse en el futuro.

Quizá las necesidades más frecuentes sean:

- Analizar algún formato de entrada adecuado para construir un tipo de `Dates`.
- Obtener el formato numérico o de string requerido a partir de un tipo de `Dates`.
- Aplicar un desplazamiento a un valor `Date`, `Time` o `DateTime`.
- Calcular el intervalo entre dos de esos valores.
- Obtener la fecha actual (con `today()`) y/o la hora (con `now()`).

~~~~exercism/note
Para reducir las distracciones visuales, la mayoría del código de ejemplo del resto de este documento da por supuesto `using Dates` y evita incluir el nombre del módulo `Dates.` en las llamadas a funciones.
~~~~

### Formatos de fecha y hora

Hay muchas formas de escribir fechas y horas, que tienden a ser específicas de cada cultura.
Las fechas compuestas solo por números, como «7/6/23», son ambiguas, confusas y han provocado muchos errores costosos en organizaciones multinacionales (_el autor lo dice por amarga experiencia personal_).

El estándar internacional se define en [`ISO 8601`][ISO8601], con dos ventajas principales:

- El análisis es rápido e inequívoco.
- Ordenar es fácil, ya que la fecha y la hora pueden tratarse como texto normal y ordenarse alfabéticamente.

Vimos en un ejemplo anterior que `Date.now()` devolvía `2025-06-21T16:03:04.161`.

Se compone de varias partes:

- `YYYY-MM-DD` para la parte de la fecha.
- `hh:mm:ss` para la parte de la hora.
- Opcionalmente, milisegundos (o una unidad aún más pequeña) después del separador decimal.

Otros formatos de string se tratarán en una sección posterior.

## Dates

`Dates.Date` es un tipo relativamente simple que solo representa fechas, sin noción de horas ni de zonas horarias.

```julia-repl
# constructor with year, month, day arguments
julia> date1 = Date(2025, 06, 23)
2025-06-23

# constructor with ISO 8601 string
julia> date2 = Date("2025-06-23")
2025-06-23

julia> date1 == date2
true

julia> typeof(date1)
Date
```

Existen funciones de acceso para las distintas partes de la fecha, y vienen en pares que se distinguen por el uso de mayúsculas y minúsculas.

```julia-repl
# lowercase returns an integer
julia> month(date1)
6

julia> typeof(month(date1))
Int64

# Propercase returns a Period type
julia> Month(date1)
6 months

julia> typeof(Month(date1))
Month

# various compound methods are also available, returning a tuple
julia> monthday(date1)
(6, 23)
```

### Funciones de consulta

Hay diversas [funciones de consulta][query-func] con cierto conocimiento del calendario.
El siguiente ejemplo muestra solo algunas.

```julia-repl
julia> date1
2025-06-23

julia> dayofweek(date1) # 1 = Monday, 7 = Sunday
1

julia> dayname(date1)
"Monday"

julia> daysinmonth(date1)
30

julia> isleapyear(date1)
false

julia> lastdayofmonth(date1)
2025-06-30
```

## Times

`Dates.Time` es el tipo básico que solo representa horas.
No tiene noción de fechas: las horas pasan automáticamente a `Time(0, 0, 0)` a medianoche.

El formato completo del constructor es `Time(hour, min, sec, millisec, microsec)` o su equivalente en ISO 8601.

Todos los parámetros son opcionales y su valor predeterminado es `0`.

```julia-repl
julia> Time(14, 57, 25, 142)
14:57:25.142

julia> Time(14, 57, 25, 142, 32)`
14:57:25.142032

julia> Time("14:57:25.142")
14:57:25.142
```

Al igual que con `Date`, las distintas partes están disponibles mediante funciones de acceso:

```julia-repl
julia> minute(t) # => integer
57

julia> Minute(t) # => Period
57 minutes
```

## DateTimes

`Dates.DateTime` combina la mayoría de las características de los tipos `Date` y `Time`.

Es el más versátil de estos tres tipos, aunque su resolución temporal se limita a los milisegundos (`Time` puede llegar a los nanosegundos).

```julia-repl
julia> dt1 = DateTime(2025, 6, 23, 14, 57, 25, 142)
2025-06-23T14:57:25.142

# date1 and t were defined in previous examples
julia> dt2 = DateTime(date1, t)
2025-06-23T14:57:25.142
```

Los parámetros de año, mes y día tienen como valor predeterminado `1`, y los parámetros de hora tienen todos como valor predeterminado `0`.

Mantener el orden de todos estos parámetros puede ser todo un reto, así que el formato ISO puede ser preferible.

Como alternativa, un `DateTime` puede construirse a partir de un `Date` y un `Time`, como en el ejemplo anterior.

## Periods

Cada uno de los componentes de fecha y hora tiene su propio tipo [`Period`][period], desde `Year` hasta `Nanosecond`, que representa un intervalo de tiempo.
Estos resultan especialmente útiles para la aritmética.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Year(21)
21 years

julia> Second(61)
61 seconds

julia> dt1 + Year(21) - Second(61)
2046-06-23T14:56:24.142

julia> Date(2025, 07, 03) - Date(2025, 04, 25)
69 days
```

También existe un tipo [`CompoundPeriod`][compound-period], que puede combinar varios tipos `Period`.
Curiosamente, actualmente necesita el nombre del módulo para evitar un error de espacio de nombres (_lo que parece un bug_).

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> offset = Dates.CompoundPeriod(Year(21), Second(-61))
21 years, -61 seconds

julia> dt1 + offset
2046-06-23T14:56:24.142
```

Al restar fechas u horas, el periodo se dará en días (para las fechas) o en nanosegundos (para las horas).
Puede resultar útil usar [`canonicalize`][canonicalize] para convertirlos en un `CompoundPeriod`.

```julia-repl
julia> diff = Time(23, 14, 00) - Time(1, 23, 52)
78608000000000 nanoseconds

julia> canonicalize(diff)
21 hours, 50 minutes, 8 seconds

julia> typeof(canonicalize(diff))
Dates.CompoundPeriod
```

Cuando se trabaja con tipos `Period`, Julia intenta ser inteligente con las irregularidades del calendario, como la duración de los meses, redondeando cuando es necesario.

```julia-repl
# February has fewer days than January
julia> Date(2025, 1, 31) + Month(1) 
2025-02-28
```

## [Redondeo][rounding]

Las funciones `floor`, `ceil` y `round` te resultarán familiares por los números enteros y decimales, pero también funcionan con fechas y horas.
Especifica el `Period` al que redondear como segundo argumento.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> floor(dt1, Minute(15))
2025-06-23T14:45:00

julia> ceil(dt1, Minute(30))
2025-06-23T15:00:00

julia> ceil(dt1, Month(1))
2025-07-01T00:00:00
```

## Representaciones de string

Antes hemos mencionado el estándar ISO 8601, que es la representación de fecha y hora predeterminada de Julia al formatear o analizar strings.

Obviamente, hay muchos otros formatos de uso frecuente, a menudo con particularidades culturales.
Para gestionarlos, Julia dispone del tipo `DateFormat`, que puede construirse a partir de un string de formato de complejidad arbitraria.

```julia-repl
# dateformat"" string syntax
julia> dtfmt = dateformat"d/m/y"
dateformat"d/m/y"

julia> typeof(dtfmt)
DateFormat{Symbol("d/m/y"), Tuple{Dates.DatePart{'d'}, Dates.Delim{Char, 1}, Dates.DatePart{'m'}, Dates.Delim{Char, 1}, Dates.DatePart{'y'}}}

# DateFormat constructor
julia> DateFormat("d/m/y")
dateformat"d/m/y"
```

El ejemplo anterior es muy simple: solo una fecha en el formato día/mes/año habitual en Europa.
Se muestran dos variantes de la sintaxis, pero el resultado es idéntico.

Después, un `DateFormat` puede usarse al analizar cualquier string adecuado:

```julia-repl
julia> DateTime("14/7/2023", dtfmt)
2023-07-14T00:00:00
```

Crear un `DateFormat` implica una sobrecarga considerable, así que hacerlo una sola vez (como aquí con `dtfmt`) ayuda al rendimiento cuando se itera sobre muchos strings de fecha y hora.

Los formatos pueden ser mucho más complejos que esto, así que consulta el [manual][dateformat] para más detalles.

Quien conozca otros lenguajes quizá note un parecido de familia con las funciones `strptime` y `strftime`, que existen desde hace décadas.
La versión de Julia se inspira en ese legado, pero aspira a ser más concisa y flexible.

El mismo `DateFormat` también puede usarse para generar una fecha u hora en cualquier formato de string deseado, mediante la función [`Dates.format()`][format].

Por desgracia, parece haber un conflicto de espacio de nombres con `format` (al menos en Julia 1.11.5), así que lo mejor es incluir el prefijo `Dates.` incluso después de `using Dates`.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Dates.format(dt1, dateformat"e, u d")
"Mon, Jun 23"
```

Como se [documenta][wiki-format], `"e, u d"` da la representación de texto abreviada del día de la semana y del mes.

La representación de texto es en inglés de forma predeterminada.
Se pueden añadir otros idiomas, aunque actualmente el soporte para ello es deficiente.
