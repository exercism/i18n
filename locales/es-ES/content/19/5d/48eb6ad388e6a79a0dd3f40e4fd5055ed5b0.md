# Introducción

## Referencias nulas

Si alguna vez has usado otro lenguaje de programación (C/C++, Python, Java, Ruby, Lisp, etc.), es probable que ya te hayas encontrado antes con `null` o `nil`.
El uso de `null` o `nil` es la forma en que estos lenguajes indican que una variable concreta no tiene valor.
Sin embargo, esto hace que usar por accidente una variable `null` sea un error fácil (y frecuente) de cometer.
Como puedes imaginar, intentar llamar a una función que no existe, o acceder a un valor que no existe, puede provocar todo tipo de bugs y bloqueos.
El creador de `null` llegó incluso a llamarlo su «[error de mil millones de dólares][billion-dollar-mistake]».

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## El tipo `Option`

Para evitar estos problemas, las variables de Cairo pueden usar la enumeración `Option` para representar de forma segura la ausencia de un valor.
Esta enumeración tiene dos variantes: `None`, el equivalente a null en Cairo; y `Some(T)`, donde `T` es un valor de cualquier tipo.

Se ve así:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

Puedes pensar en `Option` como una capa de seguridad entre tú y los problemas que pueden causar las referencias nulas, sin dejar de conservar su utilidad conceptual.

## Cómo usar `Option`

Asignar `None` a una variable es bastante sencillo:

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

Sin embargo, si quieres que el tipo `Option` contenga un valor, no puedes asignar ese valor directamente.
Una variable de tipo `Option` y, por ejemplo, una variable de tipo `i32` no son equivalentes.
Tienes que usar `Some`:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

Por la misma razón, lo siguiente no funcionará:

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

Para obtener el valor que contiene `Some`, primero tienes que comprobar que existe:

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

Cairo tiene otras herramientas aparte de `match` para comprobar y acceder a los valores contenidos en `Option`, pero a estas alturas `match` ya debería resultarte familiar.

Considera esto una demostración de por qué Cairo usa `Option` en lugar de una referencia nula.
La clave es que **es _obligatorio_ que compruebes** si la variable `Option` es `Some` (en cuyo caso puedes extraer y usar el valor que contiene) o `None`.
De lo contrario, tu programa no compilará; el compilador te protege de `null`.
