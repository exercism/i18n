# Introducción

Casi todos los programas en Factor son una secuencia de palabras que consumen y producen valores en la *pila de datos*. Cuando las entradas y las salidas encajan bien, el código se lee de izquierda a derecha sin complicaciones. Cuando no encajan, recurres a las *palabras de reordenación*, y el código se vuelve ruidoso enseguida.

Este ejercicio te guía por la solución estándar de Factor: los combinadores.

## Palabras de reordenación

Las palabras de reordenación más comunes viven en [`kernel`][kernel]:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

Ya habrás usado `dup` y `swap`. `over` hace una copia del *segundo* elemento desde arriba, algo muy útil cuando la misma entrada debe alimentar dos cálculos:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

Eso está bien para un solo uso. Pero encadenadas, las secuencias de `dup`, `swap`, `over`, `rot` se vuelven ilegibles enseguida.

## `keep`: conservar la entrada

`keep` (en [`kernel`][kernel]) llama a una *quotation* sobre la parte superior de la pila, pero deja el valor original por encima del resultado:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

Eso sustituye al patrón de `dup` seguido de algo y luego una reordenación: allí donde escribirías `dup something swap`, puedes limitarte a escribir `[ something ] keep`.

## `bi`: dos funciones sobre una misma entrada

`bi` (en [`kernel`][kernel]) aplica *dos* quotations al mismo valor y deja ambos resultados en la pila:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

Sin `bi` escribirías `dup sq swap neg`, legible para dos operaciones, pero complicado para tres.

## `tri` y `cleave`: muchas funciones sobre una misma entrada

`tri` amplía `bi` a tres quotations:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

`cleave` (en [`combinators`][combinators]) es la misma idea para un *array* con cualquier número de quotations:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

La quotation vacía `[ ]` actúa como la identidad, algo útil cuando una de las posiciones del corte debe ser la propia entrada.

## `dip` y `2dip`: operar por debajo

`dip` (en [`kernel`][kernel]) llama a una quotation sobre los valores que están *debajo* de la parte superior de la pila y deja intacta esa parte superior. `2dip` hace lo mismo, pero protege los *dos* valores superiores:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

Aquí `dip` ocultó `11`, ejecutó `9 10 +` y volvió a poner `11` arriba. `2dip` ocultó `11 12`, ejecutó `9 10 +` por debajo y luego restauró `11 12`.

`dip` es la herramienta adecuada cuando el orden natural de los argumentos deja el valor «de paso» en la parte superior de la pila. Recurre a ella en lugar del sándwich `swap … swap`.

## `bi@`: la misma operación sobre dos valores

`bi@` (en [`kernel`][kernel]) aplica una quotation a dos valores de la pila:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*`: operaciones distintas sobre dos valores

`bi*` (en [`kernel`][kernel]) aplica quotations *distintas* a los dos valores de la pila: la primera quotation al valor inferior y la segunda al superior:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

Recurre a `bi@` cuando ambos valores reciben el mismo tratamiento, y a `bi*` cuando cada uno necesita el suyo.

## `tri*`: operaciones distintas sobre tres valores

`tri*` (en [`combinators`][combinators]) amplía `bi*` a tres valores y tres quotations, aplicando cada quotation a un valor en orden:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
