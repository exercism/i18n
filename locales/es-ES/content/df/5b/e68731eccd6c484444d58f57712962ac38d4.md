# Preparación para el lanzamiento

Antes de que estés listo para lanzar tu track, asegúrate de que se hayan completado las siguientes tareas.

## Solicita el icono del track

Para que se diseñe un icono para el sitio, abre una nueva incidencia en el repositorio [exercism/website-icons](https://github.com/exercism/website-icons/issues), respondiendo a las siguientes preguntas:

- ¿El lenguaje tiene un logotipo oficial? Si es así:
  - incluye un enlace a un ejemplo
  - enumera los requisitos de atribución y los derechos concedidos para el uso de ese logotipo
- ¿El lenguaje tiene un logotipo no oficial? Si es así:
  - explica las formas en que la gente usa el logotipo no oficial
  - incluye un enlace a un ejemplo
  - enumera los requisitos de atribución de ese logotipo

## Añade la documentación del track

Añade los siguientes documentos del track:

- `docs/ABOUT.md`: una breve introducción al lenguaje.
- `docs/INSTALLATION.md`: describe lo que el estudiante necesita instalar para poder trabajar en el track en su sistema local usando la CLI.
- `docs/LEARNING.md`: enlaces a recursos de aprendizaje.
- `docs/RESOURCES.md`: enlaces a recursos útiles.
- `docs/TESTS.md`: describe todo lo relacionado con la ejecución de las pruebas en el track.

Estos documentos ayudarán al estudiante a empezar con el track, así como a conocer el track y su lenguaje.
Consulta la [documentación de docs](/docs/building/tracks/docs) para obtener más información.

## Añade la documentación de los ejercicios

Añade los siguientes documentos de los ejercicios:

- `exercises/shared/.docs/help.md`: contiene instrucciones específicas del track sobre cómo obtener ayuda
- `exercises/shared/.docs/tests.md`: contiene instrucciones específicas del track sobre cómo ejecutar las pruebas

## Añade un fragmento de código

Añade un fragmento de código al archivo `docs/SNIPPET.txt`.
Este fragmento da una impresión visual de cómo es la sintaxis del lenguaje.
Consulta la [documentación de docs](/docs/building/tracks/docs) para obtener más información.

## Actualiza los metadatos

Los metadatos del track se definen en el [archivo config.json](/docs/building/tracks/config-json).
Se deben actualizar las siguientes propiedades:

- `language`: el lenguaje del track (p. ej. `"C#"`). Su longitud debe ser <= 255
- `slug`: el lenguaje del track como una cadena en minúsculas y en kebab-case (p. ej. `"csharp"`). Su longitud debe ser <= 255
- `blurb`: una descripción breve del lenguaje. Su longitud debe ser <= 400
- `online_editor`: un objeto que describe la configuración usada para el editor online:
  - `indent_style`: `"space"` o `"tab"`
  - `indent_size`: el tamaño de la indentación como número entero (p. ej. `4`)
  - `highlightjs_language`: el identificador de lenguaje para Highlight.js (consulta la [lista completa de identificadores](https://github.com/highlightjs/highlight.js/blob/main/SUPPORTED_LANGUAGES.md)). Si no hay soporte de Highlight.js, se puede omitir este campo.
- `key_features`: las características clave del lenguaje, que describen de forma concisa sus características más importantes. Para obtener más información, consulta la [documentación de características clave](/docs/building/tracks/config-json#h-key-features).
- `tags`: define las etiquetas que se aplican a este track, lo que permite que se busque en el sitio web. Para obtener más información y ver la lista de etiquetas compatibles, consulta la [documentación de etiquetas](/docs/building/tracks/config-json#h-tags).
