# Acerca de

Clases como `LocalDate` y `LocalDateTime` describen un _punto_ en el tiempo.
El paquete `java.time` también tiene dos clases que describen una _cantidad_ de tiempo:

- [`Period`][period-docs] es una cantidad de tiempo basada en fechas, en años, meses y días, como «2 meses y 5 días».
- [`Duration`][duration-docs] es una cantidad de tiempo basada en horas, minutos, segundos, milisegundos y nanosegundos, como «1 hora y 30 minutos».

La diferencia importa porque las unidades del calendario no tienen una duración fija.
Un mes puede tener 28, 29, 30 o 31 días, así que «un mes» no es un número fijo de segundos.
Un `Period` sigue el calendario, mientras que un `Duration` mide tiempo exacto.

| | `Period` | `Duration` |
| --- | --- | --- |
| Almacena | años, meses y días | segundos y nanosegundos |
| Se usa con | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

Ambas clases son inmutables.
Métodos como `plusDays()` o `multipliedBy()` devuelven una _nueva_ instancia y dejan la original sin cambios.

## `Period`

### Crear un periodo

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

El resultado de `toString()` usa el [formato de duración ISO-8601][iso-8601-durations]: `P` seguido del número de años (`Y`), meses (`M`) y días (`D`).
En un `Period` no hay semanas: `Period.ofWeeks(2)` se almacena como 14 días.
Esa misma notación se puede volver a analizar con `Period.parse()`:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### Sumar un periodo a una fecha

Un periodo se suma o se resta a una fecha con `plus()` y `minus()`:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

Un periodo se puede sumar a un `LocalDateTime` de la misma manera, y la hora del día se mantiene igual:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

Un `Instant` no tiene calendario, así que solo se le puede sumar un periodo de días.
Un periodo con años o meses lanza una excepción:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

Primero se suman los años, después los meses y por último los días.
Cuando al sumar años o meses se cae en un día que no existe, el resultado se retrocede al último día válido de ese mes:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

Esto también significa que sumar un periodo y restarlo después no siempre devuelve la fecha original:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### El periodo entre dos fechas

`Period.between()` devuelve el periodo desde una fecha (incluida) hasta otra (excluida).
El mismo resultado está disponible como `LocalDate.until()`:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

Las partes de un periodo están disponibles mediante `getYears()`, `getMonths()` y `getDays()`.
Estas partes son independientes entre sí: `getDays()` devuelve solo la parte de días, no el número total de días.
`toTotalMonths()` devuelve los años y los meses combinados como un número de meses, pero no hay ningún método para el número total de días, porque eso depende de los meses que intervengan.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### Normalizar un periodo

Un periodo creado con un método de fábrica conserva sus unidades exactamente como se indican, y `equals()` compara las unidades una por una.
`normalized()` convierte los meses en años cuando se completan, pero deja los días intactos:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## Contar unidades con `ChronoUnit`

Para obtener el número total de una sola unidad entre dos puntos en el tiempo, usa el método `between()` de una de las constantes de [`ChronoUnit`][chronounit-docs]:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

Solo se cuentan las unidades completas, y el resultado es negativo cuando el segundo argumento es anterior al primero:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit` también funciona con unidades basadas en tiempo y con fechas y horas:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### Crear una duración

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

En la notación ISO-8601, la `T` separa la parte de fecha de la parte de hora.
Un `Duration` no tiene parte de fecha, así que su `toString()` siempre empieza por `PT`.
`Duration.ofDays()` trata un día como exactamente 24 horas.

Una duración también se puede analizar con `Duration.parse()`:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### Sumar una duración a una hora

Una duración se suma o se resta a un `LocalTime`, un `LocalDateTime` o un `Instant` con `plus()` y `minus()`:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

Un `LocalTime` da la vuelta a medianoche, como muestra el último ejemplo.

Un `LocalDate` no tiene hora, así que no se puede combinar con una `Duration`:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### La duración entre dos horas

`Duration.between()` devuelve la cantidad exacta de tiempo entre dos horas o dos fechas y horas:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()` no acepta dos valores `LocalDate`, porque una fecha no tiene segundos que medir:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

Para las fechas, usa mejor `Period.between()` o `ChronoUnit.DAYS.between()`.

### Convertir una duración

Los métodos `toXxx()` convierten una duración en una cantidad _total_ de una sola unidad, redondeada hacia abajo:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

Los métodos `toXxxPart()` dividen una duración en sus partes, como en un reloj:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()` se detiene en 23, porque las horas por encima de eso las cuenta `toDaysPart()`.

### Comparar y calcular con duraciones

Las duraciones se pueden comparar con `compareTo()` y comprobar con `isZero()` e `isNegative()`:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

También admiten operaciones aritméticas, como `plus()`, `minus()`, `multipliedBy()` y `dividedBy()`:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## ¿`Period` o `Duration`?

Para un `LocalDate` o un `LocalTime`, la elección ya está hecha: una fecha no tiene tiempo que medir y una hora no tiene calendario.
Un `LocalDateTime` tiene ambas cosas, pero no zona horaria, así que sumarle `Period.ofDays(1)` o `Duration.ofDays(1)` da el mismo resultado.
La diferencia se hace visible con las zonas horarias.
Cuando los relojes se adelantan por el horario de verano, un día de calendario solo dura 23 horas:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

Sumar un `Period` de un día mantiene la hora del día, mientras que sumar un `Duration` de un día añade exactamente 24 horas.
Usa un `Period` para las cantidades que la gente piensa en términos de calendario («la misma hora el mes que viene») y un `Duration` para el tiempo transcurrido («el ticket de aparcamiento es válido durante 2 horas»).
