# Acerca de

A estas alturas del temario, ya has visto R usarse a menudo como lenguaje imperativo y, cada vez más, como lenguaje funcional (sobre todo con las bibliotecas [`purrr`][ref-purrr] y [`dplyr`][ref-dplyr]).

Sugerir ahora que R es principalmente orientado a objetos puede provocar cierto escepticismo.

Por extraño que parezca, es una afirmación cierta.
A nivel interno, R está implementado usando clases, herencia, polimorfismo y ese tipo de actitudes típicas de los programadores de POO.

Sin embargo, quien esté familiarizado con Java o Ruby (POO explícita) o incluso con Python (POO semioculta, en algunos aspectos) encontrará el enfoque de R... _poco familiar_.

Para empezar, hay varios diseños de clases: quizá tres de uso común (S3, S4, R6) y otros varios de interés principalmente teórico.

Puedes encontrar un análisis exhaustivo en [Advanced R, 2e][book-advanced-r], capítulos 12-16.
Este libro de 2019 está dirigido en gran medida a quienes quieren entender y mantener el funcionamiento interno de R, por lo que la POO es esencial.

Los manuales más orientados al usuario final varían.

- The Art of R Programming (2011, solo en papel) tiene un capítulo sobre POO que abarca S3 y (más brevemente) S4, que eran importantes en aquel momento.
  El comentario de que _«las clases S3 tienen una estructura bastante improvisada»_ sigue siendo llamativamente cierto.
- R in Action (3e, 2022) relega la POO a 3 páginas en un capítulo sobre Advanced Programming, cerca del final.
- [R for Data Science, 2e][book-r-data-sci] (2023, con 548 páginas en la edición impresa) no menciona la POO en absoluto.

Este concepto se centrará en las clases S3, que son las más sencillas, las más comunes y las más relevantes para problemas del tipo que encontrarás en Exercism.
Algunos de los ejercicios de práctica de la pista de R te piden crear una clase S3; en otros es opcional, aunque se te anima amablemente a hacerlo.

## Clases S3

Son antiguas: el nombre S3 solo significa que se introdujeron en la versión 3 del lenguaje S (un precursor comercial de R).

Una clase S3 también es muy sencilla: normalmente, un [array][concept-lists] con al menos un atributo adicional.

Citando [Advanced R][book-s3]: _«S3 es informal y ad hoc, pero hay cierta elegancia en su minimalismo: no puedes quitarle ninguna parte y seguir teniendo un sistema de POO útil»._

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

Así que hacer una asignación a [`class(obj)`][ref-class] solo añade un atributo a `obj`, en este caso identificando pt2d como una instancia de la clase point2d.

Los pasos de creación se pueden combinar con [`structure()`][ref-structure]:

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

Aunque las instancias resultantes son en teoría idénticas, todavía no hemos implementado una forma de que R lo confirme.

### Métodos genéricos

Quien conozca la POO en otros lenguajes quizá se pregunte: _«¿no se supone que las clases pueden HACER cosas?»_

Podemos consultar los métodos disponibles para las instancias de `point2d` y descubrir que (a diferencia del `list` subyacente) actualmente no hay ninguno.

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

En la mayoría de los lenguajes con POO, los métodos se definen dentro de la definición de la clase.
Algunos lenguajes (en particular Ruby) te permiten añadir y modificar métodos de clase más adelante.

Las clases S3 son muy distintas.
En lugar de añadir métodos a una clase, añadimos la clase a un método genérico.

Cualquiera que trabaje de forma interactiva en la consola de R usa métodos genéricos continuamente, normalmente sin pensar en cómo están implementados.

Un ejemplo muy común es `print()`, aunque rara vez escribas el nombre de la función.
Escribir un valor `x` por sí solo en la consola no es más que azúcar sintáctico para `print(x)`.

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

Ya podemos imprimir `pt2d`.
Aunque `print()` no sabe nada de la clase `point2d`, tiene unos valores predeterminados razonables para manejar una amplia variedad de objetos.

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

Eso es bastante verboso, y quizá queramos una forma de imprimir el punto de manera concisa y legible.

Fácil: basta con añadir una función llamada `print.point2d()`.
El nombre debe tener la forma `methodname.classname`, para que el despachador sepa qué buscar.

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

Ahora supongamos que queremos crear un nuevo método genérico, por ejemplo `flipvert()`, para invertir el signo de la coordenada `y`.

De nuevo, es fácil:

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

Esto crea un despachador, donde `x` es nuestro objeto con una clase S3 y `...` se encarga de los argumentos adicionales que puedan necesitar las definiciones de los métodos («dot args», como se describe en el [concepto de funciones][concept-functions]).

Entonces podemos definir el método para `point2d` y usarlo.

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

Ahora R sabe cómo invertir nuestro punto y cómo mostrar el resultado.

Podríamos ampliar esto creando clases para 3D, para coordenadas polares, etc., y luego definir métodos para cada una.

Desde la perspectiva del usuario final, solo existe `flipvert(x, ...)`, y podemos confiar en que R determine la clase de la entrada y use la implementación subyacente adecuada.

~~~~exercism/caution
Los nombres de funciones con el formato `verb.class` parecen métodos S3, tanto para los usuarios como para el analizador sintáctico de R.
Procura evitar usar nombres similares en otros contextos.

Es cierto que R base a veces incumple esta regla.
Deberíamos considerarlo un desafortunado accidente histórico (para funciones incluso más antiguas que S3), que debe conservarse por retrocompatibilidad.
~~~~

### Herencia

A los entusiastas de la POO les sobra material para escribir varios capítulos largos de manual sobre herencia, creación de subclases, mixins y todo lo demás.

R simplemente te permite dar varios nombres al atributo `class`: un vector de strings más largo, en lugar de un único string.

A riesgo de forzar el ejemplo hasta el límite, supongamos que hubiéramos creado una clase genérica `point` y quisiéramos derivar de ella las subclases `point2d`, `point3d`, etc.

Entonces la definición de `point2d` simplemente usa `class = c("point2d", "point")`: la clase específica y la clase (o clases) padre.

Los métodos genéricos como `print()` buscarán entonces en secuencia `print.point2d()`, `print.point()` y (probablemente) `print.default()`, usando la primera implementación que encuentre el despachador.

### Seguridad

Muchos lenguajes con POO (Java, C#, etc.) aprovechan la encapsulación de datos dentro de las clases para hacer comprobaciones cuidadosas en tiempo de compilación e imponer la seguridad de tipos.

Ten en cuenta que S3 te permite hacer prácticamente lo que quieras, aunque no tenga ningún sentido (si aparece algún mensaje de error, será más tarde).

Citando [«Advanced R»][book-s3] (2e, sección 13.3):

> _Si has usado otros lenguajes de POO, esto puede provocarte cierto malestar, pero en la práctica esta flexibilidad causa pocos problemas. R no te impide pegarte un tiro en el pie, pero mientras no apuntes la pistola a los dedos de los pies y aprietes el gatillo, no tendrás ningún problema._

Bueno, _¿vale?_
R es excelente para la ciencia de datos exploratoria y la estadística, a menudo cuando se trabaja de forma interactiva.
¡Nadie está sugiriendo que lo uses para escribir sistemas de finanzas corporativas altamente seguros!
