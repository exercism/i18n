# Instalar Factor

La track de Factor usa **Factor 0.101**. Las versiones anteriores no son compatibles.

Puedes instalar una compilación [estable](#stable) o [nocturna](#nightly), o [compilar desde el código fuente](#build-from-source).

Verifica tu instalación ejecutando `factor -e='vm-version print'`; debería imprimir `0.101` o una versión superior.

---
### Estable

<https://factorcode.org#stable-release> proporciona binarios estables en la sección «Stable release».

---
### Nocturna

<https://factorcode.org#development-release> proporciona binarios nocturnos en la sección «Development release». Estos binarios se compilan desde git, pero solo se muestran las compilaciones que pasan.

---
### Compilar desde el código fuente

Si quieres estar a la última y hasta la compilación nocturna se te queda corta, necesitarás un compilador de C++ moderno (GCC >=4.8 o Clang >=3.5), `make` y `curl`.

Cumpliendo esos sencillos requisitos, puedes:

1. Descargar el script de shell `build`: [**aquí** para sistemas tipo Unix / shells POSIX](https://raw.githubusercontent.com/factor/factor/master/build.sh) o [**aquí** para Windows](https://raw.githubusercontent.com/factor/factor/master/build.cmd). Colócalo en el directorio en el que deba instalarse Factor. Se creará un directorio llamado `factor` que contendrá el código fuente.

2. Ejecutarlo con `./build.sh install`, o `.\build.cmd install` en Windows. <sub>Esto clonará el repositorio `git` de Factor, lo compilará y descargará una imagen de la VM de Factor desde <https://factorcode.org>. Este proceso puede tardar entre 2 y 20 minutos, según tu conexión y la velocidad de tu procesador.</sub>

3. Ya puedes ejecutar el binario `factor` o `factor.exe` generado dentro del subdirectorio `factor`. Prueba `factor --help` para obtener ayuda. También puedes acceder a la documentación desde la línea de comandos o pulsando <kbd>F1</kbd> en el Listener gráfico, lo que abrirá el navegador de ayuda.

4. En adelante, usa `build.sh` o (`build.cmd` en Windows) dentro del subdirectorio `factor` para hacer un pull desde git y recompilar en el mismo directorio, y descargar una nueva imagen de la VM si es necesario.

La estructura de archivos podría tener ahora este aspecto:

```
.
├── build.sh                   <- delete if you like
└── factor
    ├── basis
    ├── boot.unix-x86.64.image
    ├── build.cmd              <- use these from now on
    ├── build.sh               <-
    ├── core
    ├── extra
    ├── factor
    ├── Factor.app
    ├── factor.image
    ├── GNUmakefile
    ├── libfactor.a
    ├── libfactor-ffi-test.so
    ├── LICENSE.txt
    ├── misc
    ├── Nmakefile
    ├── README.md
    ├── unmaintained
    ├── vm
    └── work
```

Ya no necesitas el script `build` de nivel superior, ya que en adelante deberías usar el que has descargado.

---

### Compilar manualmente desde el código fuente (no recomendado)

Clona el [repositorio](https://github.com/factor/factor) y usa `make` en esa carpeta.

Si `make` falla con un error sobre un objetivo inexistente, prueba con `make factor` o, si sabes leer un Makefile, busca el objetivo de make para tu plataforma en `GNUmakefile`.

Si *eso* también falla, abre un issue en [factor/factor](https://github.com/factor/factor) con el error; los amables desarrolladores estarán encantados de ayudarte.
