# Acerca de

Los `struct` de C# están muy relacionados con las `class`.
Tienen estado y comportamiento.
Pueden tener los mismos tipos de miembros: constructores, métodos, campos, propiedades, etc.

Los campos y las propiedades pueden ser tipos simples, `struct` o tipos de referencia.
Los `struct` siguen las mismas reglas sobre scope, reglas de lectura/escritura y niveles de acceso que las `class`.

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

Una de las cosas principales que hay que recordar es que cuando se asigna un struct a una variable o se pasa como parámetro, los valores se copian, de modo que los cambios en la variable original no afectarán a la copiada, y viceversa.
En resumen, los `struct` son **tipos de valor**.

Este [artículo][class-or-struct] analiza las diferencias entre los `struct` y las `class`.
Verás en el artículo que los `struct` tienden a ser ligeros e [inmutables][structs-immutable], aunque el compilador o el runtime no aplican esta recomendación (de forma predeterminada).

Hay un par de cosas con las que te toparás (y sobre las que el compilador te llamará la atención):

1. Los miembros de un `struct` no se pueden inicializar en línea.
2. Un `struct` no se puede heredar
3. Un `struct` siempre tiene un constructor predeterminado, aunque se proporcione uno distinto del predeterminado, y no puedes proporcionar un constructor sin parámetros explícito.

Como consecuencia de los puntos 1 y 3 anteriores, no hay forma de que quien desarrolla un `struct` impida que existan instancias no válidas.

## Structs comunes

En la documentación verás que existe una relación estrecha entre los tipos primitivos y los structs.
Consulta [`Int32/int`][int32] como ejemplo.
Un ejemplo más convencional de `struct` es el tipo [`TimeSpan`][time-span].

Las instancias de `TimeSpan` se comportan de forma muy parecida a los números, con operadores de comparación como `>` y `<` y operadores aritméticos.
Puedes implementar estos operadores para tus propios `struct` cuando los necesites.

Algo que conviene tener en cuenta sobre `TimeSpan` es que implementa varias interfaces, por ejemplo `IComparable<TimeSpan>`.
Aunque los `struct` no pueden derivar de otros `struct`, sí pueden implementar interfaces.

## Igualdad

Comprobar la igualdad de los `struct` a menudo puede ser mucho más sencillo que en las `class`, ya que de forma predeterminada simplemente compara los campos por igualdad.
No es necesario sobrescribir `object.Equals()` (ni `GetHashCode()`).
Recuerda que si dependes de `Object.GetHashCode()`, debes asegurarte igualmente de que los campos que intervienen en la generación del código hash (es decir, todos los campos) no cambien mientras se usa una colección con hash.
En la práctica, esto significa que los structs usados de este modo deberían ser inmutables.

A diferencia del método `Equals()`, no existe una implementación predeterminada de los operadores de igualdad `==` y `!=`.
Si tu `struct` los necesita, tendrás que implementarlos.

Por otro lado, este [artículo][equality] describe cómo se puede optimizar el rendimiento creando tus propios métodos `Equals()` y `GetHashCode()` personalizados, como se hace a menudo con las `class`.
En el caso de este ejercicio, la diferencia fue de alrededor del 20 % en una comparación poco rigurosa, pero puede quedarse corta porque todos los campos son del mismo tipo; consulta más abajo.

Hay debates en la [web][equality-performance] sobre mejoras de velocidad cuando no se sobrescribe el método `Equals()`, si todos los campos son del mismo tipo.
En este ejercicio, la diferencia al incluir campos dispares fue de alrededor del 60 %.
Esto no se menciona en la documentación de Microsoft, por lo que constituye un detalle de implementación no documentado, y conviene aprovecharlo con criterio.

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
