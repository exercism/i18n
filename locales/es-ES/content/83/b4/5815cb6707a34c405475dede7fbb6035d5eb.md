# Acerca de

El código escalar se apoya en las banderas que establecen diversas instrucciones para bifurcar en respuesta a una determinada condición.
Los valores empaquetados, sin embargo, no representan un único valor, sino muchos en paralelo.
Una misma condición puede fallar para una posición y cumplirse para otra.

Por eso el código SIMD es [sin bifurcaciones][branchless-code] de forma predeterminada.

En lugar de depender de las banderas, las comparaciones empaquetadas por lo general escriben una **máscara** en el operando de destino.
Para cada posición, la comparación llena toda la posición con unos cuando se cumple y con ceros cuando no.
Si se lee como un entero con signo, una posición verdadera es `-1` y una posición falsa es `0`.

Esta máscara se puede combinar después con [operaciones a nivel de bit][simd-bitwise] para filtrar posiciones concretas.

## Comparaciones empaquetadas

Un `cmp` escalar es genérico en el sentido de que se usa para establecer varias banderas a la vez.
Otra instrucción puede después consumir esas banderas para bifurcar o para hacer cálculos.

Sin embargo, como una comparación empaquetada comprueba una condición y calcula una máscara al mismo tiempo, no es genérica.
Hay que darle a la comparación la condición exacta que se está comprobando.

Hay dos formas de hacerlo:

- A las comparaciones de enteros se les da la condición como sufijo: `eq` para la igualdad y `gt` para mayor que.
  Otras variantes se construyen combinando el resultado de una de ellas.
- A las comparaciones de coma flotante se les da la condición codificada en un inmediato.
  Distintos valores de este inmediato corresponden a distintas condiciones que se comprueban.

Aparte del uso de un sufijo condicional concreto en las comparaciones de enteros, la sintaxis sigue la misma estructura que ya hemos visto:

- Para los enteros, `p` + `cmp` + condición + tamaño (`b`, `w`, `d` o `q`).
- Para los flotantes, `cmp` + `p` + tamaño (`s` o `d`).
  La condición se pasa en un inmediato como operando adicional.

### Comparaciones de enteros

Como se ha dicho, solo hay comparaciones de enteros para la igualdad y para mayor que:

| instrucción                                | descripción                      |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | igualdad por posición            |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | mayor que **con signo** por posición |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

Para crear una comparación de menor que, usa `gt` con los operandos intercambiados: `a < b` == `b > a`.

Ten en cuenta que la comparación es **con signo**.
Para hacer una comparación sin signo, invierte el bit más alto de ambos operandos.
Esto se puede hacer con un XOR con una máscara en la que solo esté a uno el bit más alto.

~~~~exercism/note
Dos trucos prácticos son:

1. Hacer un XOR de un registro consigo mismo para producir todo ceros.
2. Comparar un registro consigo mismo para producir todo unos.

Por ejemplo:

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

Los todo ceros y los todo unos son máscaras habituales para codificar «falso en todas partes» y «verdadero en todas partes», respectivamente.
También se pueden usar para representar `0` empaquetado o `-1` empaquetado, que son valores centinela habituales.
Por ejemplo, el NUL que marca el final de un string es un `0`.
~~~~

### Comparaciones de coma flotante

Las posiciones de coma flotante usan una forma distinta: una sola instrucción, `cmpps` (y `cmppd` para las posiciones de 64 bits), con la condición como inmediato:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM también tiene pseudooperaciones que se corresponden con el inmediato correcto y son más fáciles de recordar.
En todo lo que sigue, la `x` de `px` puede ser `s` (flotantes de 32 bits) o `d` (flotantes de 64 bits):

| pseudooperación | inmediato | comparación            |
|-----------------|-----------|------------------------|
| `cmpeqpx`       | 0         | a == b                 |
| `cmpltpx`       | 1         | a <  b                 |
| `cmplepx`       | 2         | a <= b                 |
| `cmpunordpx`    | 3         | a es NaN o b es NaN    |
| `cmpneqpx`      | 4         | a != b                 |
| `cmpnltpx`      | 5         | a >= b                 |
| `cmpnlepx`      | 6         | a >  b                 |
| `cmpordpx`      | 7         | ni a ni b es NaN       |

~~~~exercism/caution
NaN se compara como no ordenado: no es menor que, ni igual a, ni mayor que nada, ni siquiera que sí mismo.
Los predicados ordenados, como `cmpltps`, dan falso cuando cualquiera de los operandos es NaN, mientras que los predicados no ordenados dan verdadero.
Por eso existen `cmpordps` y `cmpunordps`, para comprobar explícitamente si hay NaN.
~~~~

## Seleccionar con una máscara

Una máscara codifica el resultado de una condición.
Se puede usar después para elegir, posición a posición, entre dos conjuntos de valores según esa condición.
Tomamos la posición de un valor donde la máscara es verdadera y de otro donde es falsa:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

Este patrón es la forma empaquetada de la selección sin bifurcaciones.
Se calcula cada posición y la máscara por sí sola decide qué valor sobrevive, sin ningún `jcc`.

## Mezclas específicas

Hay instrucciones que realizan esa misma selección directamente, leyendo un bit por elemento de un registro de máscara.
Se llaman instrucciones de **mezcla**:

| instrucción | elemento         | origen de la máscara |
|-------------|------------------|----------------------|
| `pblendvb`  | byte             | `xmm0` implícito     |
| `blendvps`  | posición de 32 bits | `xmm0` implícito  |
| `blendvpd`  | posición de 64 bits | `xmm0` implícito  |

Fíjate en que la primera instrucción sigue la sintaxis de enteros, mientras que las otras dos siguen la sintaxis de flotantes.
Sin embargo, como estas instrucciones simplemente seleccionan bytes en bruto, cualquiera de ellas se puede usar tanto con enteros como con flotantes.

Para cada elemento, la mezcla conserva el destino cuando el bit más alto del elemento correspondiente de la máscara está a cero, y toma el origen cuando está a uno.
Solo se consulta ese **bit más alto**, lo cual cumple una máscara de comparación, ya que sus posiciones son todo unos o todo ceros.
El registro de máscara es siempre `xmm0`, que es implícito:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

También es posible usar `pblendvb` para seleccionar posiciones a partir de una máscara de comparación de cualquier otro tamaño.
Como todos los bytes de una posición verdadera son todo unos, `pblendvb` los selecciona todos.

~~~~exercism/note
Todas estas instrucciones añaden una `v` después de la operación que realizan (`blend`).
Esta `v` significa _variable_, porque la selección no es estática: depende de un registro.

También hay variantes sin `v`, que seleccionan según un inmediato.
Siguen el mismo patrón: seleccionan la posición `i` si el bit `i` del inmediato está a uno.
~~~~

## De una máscara de vuelta a un escalar

Aunque es potente, el código SIMD carece de buena parte de la flexibilidad del código escalar.
En muchas situaciones es necesario pasar de un registro empaquetado al mundo de las instrucciones escalares.

La familia de instrucciones `movmsk` sirve de puente entre los dos mundos.
Estas instrucciones extraen el **bit más alto** de cada posición y lo llevan a un registro de propósito general:

| instrucción | recoge                                | ancho del resultado |
|-------------|---------------------------------------|---------------------|
| `pmovmskb`  | el bit más alto de cada uno de los 16 bytes | 16 bits       |
| `movmskps`  | el bit más alto de cada uno de los 4 dwords | 4 bits       |
| `movmskpd`  | el bit más alto de cada uno de los 2 qwords | 2 bits       |

Si se usa después de una comparación, cada bit a uno representa una posición «verdadera» y cada bit a cero, una posición «falsa».
Este resultado se puede manipular después como de costumbre con instrucciones escalares.
Por ejemplo, un `popcnt` cuenta el número de coincidencias y `tzcnt` encuentra la primera.

El registro de propósito general puede ser de 32 o de 64 bits de ancho.

## Comprobar un vector entero

También hay una variante empaquetada de la instrucción escalar `test`: `ptest`.

Se parece a su equivalente escalar en que realiza una operación AND entre dos operandos sin modificarlos.
A diferencia de `test`, `ptest` también realiza una operación ANDN, que niega el primer operando.

Así, `ptest` se puede ver como una versión no destructiva de `pand` y `pandn` que establece las banderas según el resultado.
De forma muy parecida a esas dos instrucciones, `ptest` trata todo el registro SIMD como una única posición y por eso no lleva prefijo de tamaño.

Si el resultado de la operación AND es `0`, se activa `ZF`, y si la operación ANDN da `0`, la que se activa es `CF`.
Esto significa que `ptest` sirve para comprobar tanto una máscara todo unos como una máscara todo ceros:

1. Usar `ptest` sobre un registro consigo mismo activa `ZF` solo si el registro es todo ceros.
   Esto imita el truco escalar habitual de usar `test` sobre un registro consigo mismo para comprobar si es `0`.
2. Usar `ptest` sobre un registro con una máscara todo unos activa `CF` solo si el registro es todo unos.
   Además, activa `ZF` solo si el registro es todo ceros, lo que permite comprobar ambas máscaras a la vez.

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

El resultado de un `ptest` se puede usar para bifurcar o en instrucciones sin bifurcaciones como `setcc` o `cmovcc`, como de costumbre.

## AVX y más allá

AVX da a las comparaciones, las mezclas y `ptest` una forma con prefijo `v` sobre registros más anchos.

La mezcla variable cambia de forma.
La máscara ya no es el `xmm0` implícito, sino un cuarto operando explícito:

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

Las extensiones AVX-512 cambian el modelo de forma más profunda.

En primer lugar, añaden una nueva clase de registros SIMD de 64 bytes, llamados `zmm`.
Amplían los `ymm` correspondientes, del mismo modo que los registros `ymm` amplían los registros `xmm`.

En segundo lugar, esas extensiones también crean toda una nueva clase de **registros de máscara de operación**, `k0` a `k7`, cuyo propósito principal es servir de máscaras para las instrucciones SIMD.
Las comparaciones ya no escriben en vectores, sino en uno de estos nuevos registros.
También se pueden usar directamente en muchas instrucciones como predicados con una máscara de escritura `{k}`, seleccionando posiciones _directamente_:

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

Por último, hay nuevas instrucciones para operar con esos nuevos registros, incluida la de copiarlos a registros de propósito general.
Esto hace innecesarias las instrucciones `movmsk`, y no hay soporte para instrucciones `movmsk` sobre registros `zmm`.

Estas extensiones se mencionan por completitud.
Los ejercicios de este track usan las formas SSE.
