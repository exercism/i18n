# Acerca de

`reduce` es el plegado general de Factor: recorre una secuencia,
pasando un acumulador a través de una quotation binaria que toma
el acumulador actual y el siguiente elemento y produce el nuevo
acumulador.

```
reduce ( seq init quot: ( prev elt -- next ) -- result )
```

```factor
USING: math sequences ;

{ 1 2 3 4 } 0 [ + ] reduce .         ! => 10
{ 1 2 3 4 } 1 [ * ] reduce .         ! => 24
```

Una semilla personalizada permite que `reduce` exprese plegados
que `sum` o `product` no pueden. Por ejemplo, el valor más grande
de una secuencia con un valor predeterminado si todos los
elementos pierden:

```factor
USING: math.order ;

{ 3 1 -4 5 -2 } 0 [ max ] reduce .   ! => 5
{ -3 -1 -4 }    0 [ max ] reduce .   ! => 0
```

La semilla `0` participa en la comparación, así que una secuencia
totalmente negativa sigue produciendo `0` en lugar de su valor
más pequeño.

## `produce`: el despliegue

El dual de `reduce` es `produce` (en [`sequences`][sequences]):
donde `reduce` *consume* una secuencia, `produce` *genera*
una. Una quotation de predicado comprueba el estado actual;
mientras devuelve un valor verdadero, una quotation de cuerpo
produce el siguiente elemento.

```
produce ( pred quot -- seq )
```

Usados juntos, `reduce` y `produce` forman el par
plegado/desplegado de Factor.

## Reducciones acumulativas

La familia de reducciones acumulativas de
[`math.statistics`][math.statistics] devuelve una secuencia de la
misma longitud que la entrada, donde cada elemento es la
reducción sobre el prefijo hasta esa posición inclusive:

| palabra       | operación acumulada |
|---------------|-------------------|
| `cum-sum`     | total acumulado      |
| `cum-product` | producto acumulado    |
| `cum-min`     | mínimo acumulado    |
| `cum-max`     | máximo acumulado    |

```factor
USING: math.statistics ;

{ 3 1 4 1 5 9 2 6 } cum-sum .         ! => { 3 4 8 9 14 23 25 31 }
{ 3 1 4 1 5 9 2 6 } cum-min .         ! => { 3 1 1 1 1 1 1 1 }
{ 3 1 4 1 5 9 2 6 } cum-max .         ! => { 3 3 4 4 5 9 9 9 }
```

Las reducciones acumulativas son útiles cuando quieres inspeccionar
*cómo* ha evolucionado una cantidad a lo largo de la secuencia,
no solo su valor final. Encadenarlas también es útil: la salida
de una reducción acumulativa es a su vez una secuencia, lista
para alimentar a otra.

[sequences]: https://docs.factorcode.org/content/vocab-sequences.html
