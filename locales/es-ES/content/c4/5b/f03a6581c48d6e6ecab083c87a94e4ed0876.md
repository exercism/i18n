# Tests

Ejecuta los tests con:

```shell
corepack pnpm test
```

Asegúrate de que tu código sigue las buenas prácticas y los estilos de código, como hacen otros usuarios, con ESLint, una herramienta que realiza un análisis estático de tu código.
A veces, herramientas como esta te ahorran tiempo detectando errores tipográficos o fallos tontos en tu código JavaScript:

```shell
corepack pnpm lint
```

También puedes ejecutar Jest en modo «watch», que volverá a ejecutar tus tests automáticamente cuando guardes cambios en el código o en el módulo de tests:

```shell
corepack pnpm watch
```

## Cómo funcionan los tests omitidos

El método skip indica al conjunto de tests que no ejecute un test; esta función también se puede usar con los alias: `it.skip(name, fn)` o `xit(name, fn)` o `xtest(name, fn)`

- ¿Por qué se omiten?

Para que los usuarios puedan concentrarse en un test a la vez e ir habilitándolos uno a uno a medida que hacen evolucionar la solución.

- ¿Cómo habilitarlos?

Cambia `xtest` por `test`.

```javascript
test('title cased phrases', () => {
  expect(Acronyms.parse('Portable Network Graphics')).toEqual('PNG');
});
```

## Cómo crear tu primer módulo de JavaScript 2015

Normalmente, los tests de este track cargan tu implementación importándola como un módulo de JavaScript: `import { Bob } from './bob.js';`.
Solo tienes que exportar tu implementación desde el fichero al que se hace referencia, `bob.js`:

```javascript
export function hey(message) {}
```

Puedes encontrar más información sobre los módulos en la [documentación de Babel](https://babeljs.io/docs/learn-es2015/#modules).
Para que te resulte más fácil empezar, hay un fichero JavaScript _esqueleto_ en el directorio.
