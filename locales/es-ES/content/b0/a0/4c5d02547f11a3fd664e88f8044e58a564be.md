# Acerca de

## JSON

[JSON][json] (JavaScript Object Notation) es un formato de datos y de archivos legible por humanos que se suele usar para intercambiar datos, en particular en aplicaciones web.
Como era de esperar, ocupa un lugar especial en el lenguaje Elm.

Elm incluye los módulos principales [`Json.Decode`][decode] y [`Json.Encode`][encode] para analizar y escribir datos JSON.
Los decodificadores de JSON son una forma de _declarar_ qué tipo de datos se espera y a qué estructura de datos deben asignarse.

Si vienes de lenguajes de tipado dinámico, los decodificadores suelen parecer engorrosos o, a primera vista, demasiado rígidos.
Aunque sin duda son verbosos, al menos en Elm, son una herramienta valiosa para describir de forma explícita qué espera un programa de los datos que recibe, y [no son menos expresivos que los tipos dinámicos][dynamic-types-not-more-open].

Vamos a importar algunos alias y tipos de los módulos:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Si usas `Decode.decodeString : Decoder a -> String -> Result Error a` con un decodificador y una cadena JSON, la operación tendrá éxito si la cadena cumple las especificaciones del decodificador, o fallará en caso contrario.
Al definir el decodificador no hay forma de inspeccionar los datos JSON sin procesar, algo que puede resultar chocante si vienes de lenguajes imperativos.

## Decodificadores de tipos de datos básicos

JSON tiene un número reducido de tipos de datos básicos:

- String: se escribe entre comillas dobles `"hello world"`
- Boolean: `true` o `false`
- Number: como `34` o `0.12`
- Null: la ausencia de datos, `null`

Cada uno de ellos tiene asociada una función de `Decode`:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Fíjate en que `Decode.null` te permite decidir cómo modelar un `null` en tu programa, ya que requiere un valor arbitrario como argumento (quizá `()`, `Nothing` o cualquier cosa que le venga bien a tu programa).

## Combinar decodificadores

JSON también define dos estructuras de datos para agrupar tipos de datos básicos:

- Array: una colección de otros tipos de datos `[0, null, "none", []]`
- Object: una colección de pares clave-valor `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` también ofrece funciones para decodificarlas:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Estas funciones, `Decode.list : Decoder a -> Decoder (List a)` y `Decode.dict : Decoder a -> Decoder (Dict String a)`, esperan un decodificador como argumento, que a su vez debe decodificar cada uno de los elementos de la estructura de datos.
Si el decodificador pasado como argumento no consigue decodificar algún elemento de un array o de un objeto, el decodificador entero falla, algo que es un patrón habitual.

Combinar decodificadores simples para formar otros más complejos es la idea central de esta técnica.
A continuación, y con la ayuda de un ejemplo, presentaremos varias funciones más con las que construir decodificadores de datos del mundo real tan complejos como haga falta.

## GeoJSON

Para practicar cómo se combinan decodificadores básicos y así analizar datos JSON complejos, vamos a construir decodificadores para analizar (un subconjunto de) datos GeoJSON.
[GeoJSON][geojson] es un formato de datos especializado basado en JSON que se usa para representar elementos geográficos, como ubicaciones, trazados o regiones, definidos mediante coordenadas geográficas 2D o 3D junto con otras propiedades.

### Objeto Geometry

Un objeto Geometry de GeoJSON es un objeto que contiene un campo `type` con un valor de tipo string (hay 7 valores posibles para el tipo) y un campo `coordinates` con coordenadas geográficas (agrupadas en una estructura que depende del tipo).
Por ejemplo,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

o

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Un objeto Geometry se podría representar en Elm con el siguiente tipo

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Para consultar el valor de un campo concreto, podemos usar `Decode.field : String -> Decoder a -> Decoder a`, que decodifica el valor de una clave específica de un objeto.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Para transformar el valor que ha analizado correctamente un decodificador, podemos usar `Decode.map : (a -> value) -> Decoder a -> Decoder value`, o cualquiera de sus hermanas, desde `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` hasta `Decode.map8`.

En este caso, queremos decidir qué decodificador de coordenadas usar en función del valor del campo `type`, lo cual es el trabajo perfecto para `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` y sus compañeras `Decode.succeed : a -> Decoder a` y `Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

Fíjate en que, llegados a este punto, podríamos usar `Decode.andThen` para validar las coordenadas (comprobar que vienen en pares o tríos y que sus valores tienen sentido geográfico).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### Objeto Feature

Un objeto Feature de GeoJSON representa algo delimitado espacialmente: tiene un campo `type` con el valor `"Feature"`, un campo `geometry` con un objeto Geometry o un `null`, un campo `properties` con un objeto JSON arbitrario o un `null`, y un campo `id` opcional con un valor string o numérico de JSON.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

o

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Vamos a abordar primero el campo `id`.
Si existe, debe admitir strings o números, así que podríamos o bien crear un tipo personalizado para el valor, o bien guardarlo siempre como string.

Para elegir entre dos decodificadores posibles, podemos usar `Decode.oneOf : List (Decoder a) -> Decoder a`.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Para expresar que el campo es opcional, podríamos usar la misma técnica

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Pero también podríamos usar `Decode.maybe : Decoder a -> Decoder (Maybe a)`

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Fíjate en que `decodeMaybeFeatureId` (o cualquier decodificador envuelto con `Decode.maybe`) siempre tendrá éxito, ya que siempre puede recurrir a `Ok Nothing`, aunque un decodificador que lo use podría fallar igualmente

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

A continuación, vamos a centrarnos en el campo `geometry`, que puede ser un objeto Geometry o ser `null`.
Podríamos volver a usar `Decode.oneOf`, pero hay una opción mejor: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` y `Decode.nullable` tienen la misma signatura, pero su comportamiento es distinto, ya que el resultado `OK Nothing` de un `Decode.nullable` solo provendrá del valor JSON concreto `null`.

Por último, el campo `properties` puede contener un objeto JSON arbitrario o un `null`, lo cual es trabajo para `Decode.value : Decoder Value`.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Fíjate en que `Value` es un tipo opaco, lo que significa que no puedes inspeccionar su contenido con facilidad.
Para usarlo, puedes escribir un decodificador para él y ejecutarlo con `Decode.decodeValue : Decoder a -> Value -> Result Error a`, o enviarlo directamente a JavaScript mediante un port.

Ya estamos listos para analizar objetos Feature:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## Codificadores JSON

Los codificadores permiten escribir JSON válido a partir de valores de Elm usando la función `Encode.encode : Int -> Value -> String`.
El primer argumento especifica la cantidad de indentación del resultado final, y el segundo es el valor JSON que se va a escribir.

Un `Value` se puede obtener de `Decode.value` o producir a partir de uno de los codificadores:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

además de con `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Vamos a definir codificadores para los decodificadores de GeoJSON que hemos definido antes

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

En general, una buena prueba para tus parejas decodificador-codificador es comprobar que `elmValue |> encoder |> decoder == elmValue`.

## ¿Qué más?

No hemos cubierto todas y cada una de las funciones de los módulos `Json`.
Entre las cosas que no hemos mencionado están: decodificadores para convertir arrays en `Array` o objetos en `List (String, a)`, decodificadores para arrays con uno o más elementos, decodificadores para campos concretos de objetos JSON anidados o elementos concretos de arrays, cómo decodificar estructuras recursivas, así como las distintas variantes de `Error` y cómo mostrarlas.

Otros paquetes que se usan con frecuencia son [`Json.Decode.Pipeline`][pipeline], que introduce un flujo cómodo para estructuras JSON complejas, y [`Json.Decode.Extra`][extra], que ofrece más decodificadores, codificadores y utilidades.
