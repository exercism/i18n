# Anexo a las instrucciones

## Mensajes de excepción

A veces es necesario [lanzar una excepción](https://docs.python.org/3/tutorial/errors.html#raising-exceptions). Cuando lo hagas, siempre deberías incluir un **mensaje de error significativo** que indique cuál es el origen del error. Esto hace que tu código sea más legible y ayuda muchísimo a la hora de depurar. Cuando sepas que el origen del error va a ser de un tipo concreto, puedes optar por lanzar uno de los [tipos de error integrados](https://docs.python.org/3/library/exceptions.html#base-classes), pero aun así deberías incluir un mensaje significativo.

Este ejercicio en concreto requiere que uses la [instrucción `raise`](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement) para «lanzar» un `ValueError` cuando tu función `largest_product()` reciba una entrada no válida. Los tests solo pasarán si usas `raise` con la `exception` y además incluyes un mensaje con ella. ¡No dudes en reutilizar tu código del ejercicio `series`!

```python
# span of numbers is longer than number series
raise ValueError("span must not exceed string length")

# span of number is negative
raise ValueError("span must not be negative")

# series includes non-number input
raise ValueError("digits input must only contain digits")
```
