# Tests

Cada ejercicio incluye un conjunto de tests unitarios y todo lo necesario para compilarlos y ejecutarlos.
Tú te encargas de la implementación.

## Ejecutar los tests

Abre un terminal en la carpeta del ejercicio y ejecuta:

```
make
```

Esto compila tu solución y los tests, y después ejecuta los tests.
Vuelve a ejecutarlo cada vez que cambies tu solución.

Si tienes la [CLI de Exercism](https://exercism.org/docs/using/solving-exercises/working-locally), puedes usar este comando en su lugar, que además ejecuta `make`:

```
exercism test
```

Para eliminar los ficheros creados por la compilación, ejecuta `make clean`.

### Sin make

Si no tienes `make` (en Windows, por ejemplo), puedes compilar y ejecutar los tests directamente.
Para el ejercicio «Bob»:

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

A continuación, ejecuta los tests en Linux o macOS:

```
./run_tests
```

O en Windows:

```
.\run_tests
```

## Trabajar en un ejercicio

Los ficheros de cada ejercicio llevan su nombre.
Para el ejercicio «Bob»:

| Fichero | Contenido |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90` | una plantilla de la solución, lista para que la completes |
| `bob_test.f90` | los tests |
| `TesterMain.f90` | la biblioteca de tests |
| `Makefile` | instrucciones para `make` |
| `CMakeLists.txt` | instrucciones para [CMake](#using-cmake-instead), que es opcional |

Solo tienes que editar el fichero de la solución.

Trabajar cada ejercicio es un proceso que consiste en repetir estos pasos hasta que pasen todos los tests:

- Corregir los errores de compilación y, a continuación, ejecutar los tests para ver cuáles fallan.
- Implementar lo justo para que pase el siguiente test que falla.
- Refactorizar tu implementación para mejorar la legibilidad, reducir la duplicación, etc.
- Ejecutar los tests de nuevo y pasar al siguiente test que falla.

Se imprime un mensaje por cada test que falla, seguido de un resumen.
Si algún test falla, `make` termina con un error.

Cada test tiene un comentario que lo describe y, a continuación, el test propiamente dicho, que empieza por `call assert_equal`. Por ejemplo:

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Para desactivar un test, basta con comentarlo con un `'!'`. Por ejemplo:

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## Usar CMake en su lugar

No necesitas CMake, pero puede resultarte útil si trabajas en un IDE como Visual Studio o Xcode, o si usas un compilador distinto de GFortran.

La carpeta del ejercicio debe conservar su nombre original, porque CMake lo usa para encontrar los ficheros de código fuente.
Empieza en la carpeta del ejercicio:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

Después de cambiar tu solución, solo hacen falta los dos últimos comandos.

**Nota:** ejecuta siempre `cmake` desde una carpeta aparte, como `build`.
Ejecutar `cmake .` en la carpeta del ejercicio sustituye el `Makefile` que viene con el ejercicio.

CMake elige un generador adecuado para tu sistema.
Para elegir otro, usa la opción `-G`. Por ejemplo, `cmake -G Xcode ..`.
Ejecuta `cmake --help` para ver la lista de generadores que puedes usar.
Con Visual Studio o Xcode, ejecuta los tests con `ctest -V -C Debug`.

Si tu carpeta de ejercicio no contiene un `Makefile`, es que se descargó antes de que estos ficheros se añadieran a los ejercicios.
Aun así, puedes usar CMake.
