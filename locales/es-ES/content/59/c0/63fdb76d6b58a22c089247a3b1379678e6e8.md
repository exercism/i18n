# Acerca de

Los hilos de Factor son *corrutinas cooperativas* sobre un único hilo del sistema operativo.
Un hilo se ejecuta hasta que cede el control explícitamente o realiza una operación de E/S
bloqueante, momento en el que el planificador elige otro hilo listo para ejecutarse. Esto
tiene dos implicaciones:

- Todo lo que ocurre entre dos cesiones del control es, en la práctica, atómico.
- El verdadero paralelismo multinúcleo requiere salir del vocabulario estándar
  `threads` (por ejemplo, `concurrency.distributed` para diseños multiproceso).

Las primitivas de concurrencia estándar están organizadas en capas:

| Vocabulario                 | Proporciona                            |
|-----------------------------|----------------------------------------|
| [`threads`][threads]                   | `spawn`, `yield`, identidad del hilo      |
| [`concurrency.promises`][concurrency.promises]      | `<promise>`, `fulfill`, `?promise`     |
| [`concurrency.locks`][concurrency.locks]         | `<lock>`, `with-lock`                  |
| [`concurrency.combinators`][concurrency.combinators]   | `parallel-map`, `parallel-each`        |
| [`concurrency.semaphores`][concurrency.semaphores]    | `<semaphore>`, `acquire`, `release`    |
| [`concurrency.mailboxes`][concurrency.mailboxes]     | buzones por hilo, `send`, `receive`  |
| [`concurrency.channels`][concurrency.channels]      | manejadores de encuentro, `to`, `from`       |

```factor
USING: concurrency.combinators concurrency.locks
concurrency.promises kernel sequences threads ;

! parallel-map: fork-join, in order
{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }

! spawn + promise: hand-rolled fork-join
<promise> [
    [ "hello, world" swap fulfill ] curry "greeter" spawn drop
] keep ?promise .   ! => "hello, world"

! <lock> + with-lock: protect a shared mutable slot
<lock> :> guard
guard [ "do thing under lock" drop ] with-lock
```

`parallel-map` es la API de alto nivel y a lo que recurre primero el Factor idiomático.
La terna `spawn` / `<promise>` / `?promise` es la base sobre la que se construye
`parallel-map`, y resulta muy útil cuando la forma de la iteración no encaja con map
(por ejemplo, cuando se lanzan workers que se comunican de vuelta a través de otros
canales).

Los bloqueos protegen el *estado mutable compartido*, normalmente una ranura de una
tupla o una tabla hash a la que más de un hilo lee o escribe. Trata tanto las lecturas
como las escrituras como operaciones que necesitan el bloqueo si existe alguna
actualización compuesta no atómica; olvidar el bloqueo en cualquiera de los dos lados es
la receta clásica para una lectura inconsistente.
