# Introducción

Las tuplas pueden extender otras tuplas. `TUPLE: child < parent slots ;`
declara una clase cuyas instancias también son instancias de `parent`:
además de sus propias ranuras tienen las del padre, y los accesores del
padre también funcionan con ellas, como si se hubieran definido en la
clase hija.

```factor
USING: accessors ;

TUPLE: animal name age ;
TUPLE: dog < animal breed ;

"Rex" 4 "labrador" dog boa .
! => T{ dog { name "Rex" } { age 4 } { breed "labrador" } }

"Rex" 4 "labrador" dog boa name>> .   ! => "Rex"   (inherited accessor)
```

## Orden de las ranuras en `boa`

El constructor `boa` recibe las ranuras en *orden de declaración, primero
los padres*. Para el `dog` de arriba:

```
dog boa ( name age breed -- dog )
```

Un nieto `puppy < dog ` que añadiera `weeks` sería:

```
puppy boa ( name age breed weeks -- puppy )
```

## Jerarquía de predicados

Toda declaración `TUPLE:` genera un predicado (`name?`).
Con la herencia, los predicados se anidan, de modo que todo descendiente
cumple los predicados de sus antepasados:

```factor
"Rex" 4 "labrador" dog boa
dup dog? .        ! => t
dup animal? .     ! => t
```

Lo contrario no es cierto: un `animal` que no es un `dog` no cumple
`dog?`.

## Nota para más adelante

Los métodos genéricos (`M:`, que se enseñan en [`generics`][generics])
también despachan por la jerarquía: un método definido en `animal` se
activa para todos los descendientes, salvo que una sobrescritura más
específica tenga prioridad. Lo verás en `boatswains-bilge` justo
después de este ejercicio.

[generics]: https://docs.factorcode.org/content/article-generic.html
