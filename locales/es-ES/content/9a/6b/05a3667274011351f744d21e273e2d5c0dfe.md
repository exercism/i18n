# Introducción

Los dígitos binarios se corresponden en última instancia con los transistores de tu CPU o tu RAM, y con si cada uno está «encendido» o «apagado».

La manipulación de bajo nivel, conocida informalmente como «bit-twiddling», es especialmente importante en los lenguajes de sistemas.

Los lenguajes de más alto nivel, como Kotlin, suelen abstraer la mayor parte de este detalle. Sin embargo, se dispone de un conjunto básico de [operaciones bit a bit][ref-bitwise].

## Operaciones de desplazamiento de bits

Los tipos `Int` o `Long`, con signo o sin signo, se pueden representar como una cadena de unos y ceros y manipular como una secuencia de bits.

Quizá resulte sorprendente que los tipos `Byte` o `Short` no sean compatibles con la mayoría de las operaciones bit a bit en Kotlin. Todos los ejemplos siguientes usan enteros de 32 bits (`Int` o `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Los desplazamientos de bits simplemente mueven todo a la izquierda o a la derecha un número determinado de posiciones. Algunos bits se pierden por un extremo y el otro extremo se rellena con ceros o unos.

- Desplazamiento a la izquierda con `shl`: relleno con ceros.
- Desplazamiento a la derecha con `shr` o `ushr`: relleno con ceros para los números positivos (más adelante veremos los negativos).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Cada desplazamiento a la izquierda duplica el valor, y cada desplazamiento a la derecha lo reduce a la mitad (con posible truncamiento). Esto se ve más claro en la representación decimal:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Este tipo de desplazamientos de bits es mucho más rápido que la aritmética «propiamente dicha», lo que hace que la técnica sea muy popular en la programación de bajo nivel.

Con los _enteros negativos_ tenemos que ir con más cuidado.

Los valores negativos se almacenan en forma de [complemento a dos][wiki-2complement], lo que significa que el bit más a la izquierda es 1. No hay problema para un desplazamiento a la izquierda, pero al desplazar a la derecha, ¿cómo rellenamos los bits de la izquierda?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

El operador `shr` realiza un [desplazamiento aritmético][wiki-arithmetic], que conserva el bit de signo.

El operador `ushr` realiza un [desplazamiento lógico][wiki-logical], que rellena con ceros como si el número no tuviera signo.

## Lógica bit a bit

Vimos en el [concepto de booleanos][concept-booleans] que los operadores `&&` (and), `||` (or) y `!` (not) se usan con valores booleanos.

Existen operadores equivalentes `and`, `or` y `xor` ([o exclusivo][wiki-xor]) para comparar los bits de dos enteros, y una función `inv` (inversión) para invertir todos los bits.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
