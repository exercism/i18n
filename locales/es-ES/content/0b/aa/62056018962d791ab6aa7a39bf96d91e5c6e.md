# marcador de posición

## Nuevos conceptos de AWK

Este es el primer ejercicio en el que la solución no es un script «main».
El objetivo es escribir una biblioteca de funciones para incluirla en otros programas awk.
Hay varios conceptos nuevos e interesantes que ver en este ejercicio.

Las siguientes secciones, etiquetadas con «(gawk)», son extensiones específicas de GNU awk.

### Lectura desde un fichero

En este ejercicio, leerás datos de un fichero, no del flujo de entrada principal. 
Lee sobre [`getline`][getline] en el manual de GNU awk,
en particular, las formas `Getline/File` y `Getline/Variable/File`.

### Más sobre los arrays

Un array bidimensional podría ser una forma de implementar esta solución.
GNU awk tiene dos formas de representarlo:

* [arrays multidimensionales][multi]
* [arrays de arrays][a-of-a] <sup><sup>(gawk)</sup></sup>

### Ficheros de inclusión <sup><sup>(gawk)</sup></sup>

Fíjate en la directiva [`@include`][d-include] del fichero de test.  
Esto indica a gawk que lea y evalúe el fichero indicado.

### Espacios de nombres <sup><sup>(gawk)</sup></sup>

Todas las variables de awk son globales (excepto los parámetros de función, que son locales a la función).
Existe una alta probabilidad de colisiones de nombres, sobre todo cuando se incluyen bibliotecas de terceros. 
Los [espacios de nombres][namespaces] son una forma de dividir dónde se almacenan las variables.
Fíjate en la directiva [`@namespace`][d-namespace] de los ficheros del ejercicio.

El espacio de nombres predeterminado se llama «awk». 
Tener un espacio de nombres predeterminado permite al programador llamar a una función integrada de awk desde dentro de una función en otro espacio de nombres.

### Cómo se pasan los parámetros de función

Los parámetros de tipo array se pasan **por referencia**.
Los cambios realizados en el array dentro de la función son visibles para quien la llama.

Los parámetros que no son arrays se pasan **por valor**.

Para los parámetros _sin tipo_, depende de lo que la función haga con ellos:
- si la función lo inicializa como un array, se convierte en un parámetro pasado por referencia,
- si la función lo inicializa como un valor escalar (un número o un string), entonces no es una referencia.

Todos los detalles están en el manual, en [Pasar argumentos de función por valor o por referencia][pass-by].

#### Variables locales

Las variables con scope de función (locales) se pueden crear usando parámetros «por valor».
No es un error pasar a una función menos valores que el número de parámetros enumerados;
los parámetros sobrantes están «sin tipo» hasta que se usan.
Están disponibles para asignarles valores escalares dentro de la función que no se almacenan en el espacio de nombres global.

- Si asignas un valor escalar a un parámetro, ese es local a la función.
- Si asignas un escalar a una variable que **no** figure en la lista de parámetros, esa variable es global.

Por convención, en la firma de la función los parámetros esperados aparecen primero, seguidos de un espacio en blanco y, después, los parámetros locales.
Un ejemplo:

```awk
function add(a, b,    total) {
    # here, `typeof(total)` is "untyped"
    total = a + b
    # now, `typeof(total)` is "number"
    return total
}

BEGIN {
    sum = add(5, 10)
    print sum             # 15
    print typeof(total)   # untyped, meaning "total" is unused in this scope
}
```
