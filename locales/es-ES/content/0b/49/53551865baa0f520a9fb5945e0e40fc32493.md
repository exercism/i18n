# Introducción

Un *señalero* a bordo de un buque de patrulla costera mantiene el
registro de mensajes. Las banderas de señales en bruto llegan
enmarcadas con caracteres marcadores; las lecturas hay que
prepararlas para el cable; los pares y las ternas de observaciones
se resumen sobre la marcha. Un puñado de expresiones idiomáticas
de la biblioteca estándar de Factor hacen casi todo el trabajo.

## `unparse`: de un valor a su código fuente

[`unparse`][unparse] (en `prettyprint`) devuelve el texto en forma
de código fuente de cualquier valor:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` es la operación inversa del analizador: el recorrido de
ida y vuelta `dup unparse parse` reconstruye el valor. Es la
herramienta adecuada para serializar a un formato de cable que el
receptor volverá a analizar, y la herramienta equivocada para una
salida legible para las personas (los strings conservan sus
comillas, los vectores conservan su `V{ ... }`, etc.).

## Variantes slice: vistas, no copias

`head` y `tail`, de `sequences`, *copian* la parte que conservas en
una secuencia nueva. Sus equivalentes `-slice` devuelven un objeto
`slice` (una tupla que contiene el índice inicial, el índice final
y la secuencia subyacente) que implementa el [protocolo de
secuencias][sequence-protocol] sin copiar nada:

| palabra       | efecto                                            |
|---------------|---------------------------------------------------|
| `head`        | `( seq n -- newseq )`: copia los primeros n        |
| `head-slice`  | `( seq n -- slice )`: vista de los primeros n      |
| `tail`        | `( seq n -- newseq )`: copia desde el índice n en adelante |
| `tail-slice`  | `( seq n -- slice )`: vista desde el índice n en adelante |
| `head*`       | `( seq n -- newseq )`: copia todos menos los últimos n |
| `head-slice*` | `( seq n -- slice )`: vista de todos menos los últimos n |
| `tail*`       | `( seq n -- newseq )`: copia los últimos n         |
| `tail-slice*` | `( seq n -- slice )`: vista de los últimos n       |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

Un `slice` *es* una secuencia, así que todo lo que acepta una
secuencia acepta un slice: `length`, `first`, `each` y demás
funcionan sin copiar nada. Las pruebas que necesiten comparar con
un string literal pueden convertir el slice con `>string`.

## `?head` y `?tail`: quitar un marcador si está presente

Las lecturas enmarcadas llevan texto marcador que puede estar o no.
`?head` y `?tail` (en `splitting`) intentan quitar un prefijo o un
sufijo, y devuelven la secuencia (posiblemente acortada) *y* un
Boolean que indica si se encontró el marcador:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

El Boolean final los convierte en un recurso natural para una
guarda: empareja `?head` con `if` para ramificar según si el marco
estaba presente, o con `unless` para rechazar la entrada a la que
le falta el marcador esperado.

## `<repetition>`: N copias, de forma virtual

[`<repetition>`][repetition] (en `sequences`) es otra secuencia
virtual que no copia: `( len elt -- repetition )` construye una
secuencia de `len` elementos que son todos `elt`, sin reservar
tantas posiciones en memoria:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

El propio `elt` puede ser una secuencia: cada copia es esa misma
secuencia. Después, `concat` une las copias una tras otra:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

Igual que un slice, el resultado *es* una secuencia: `length`,
`each` y compañía funcionan directamente sobre él. Recurre a ella
para rellenar un código de señal hasta un ancho fijo o para
generar una serie de marcadores repetidos; conviértela con `>string`
(o `>array`) solo cuando necesites de verdad una secuencia concreta.

## `<clumps>`: ventanas solapadas, de forma virtual

[`<clumps>`][clumps] (en `grouping`) es una tercera secuencia
virtual que no copia: `( seq n -- clumps )` ve `seq` como la serie
de ventanas de longitud `n` *solapadas* sobre ella, cada ventana un
slice:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

Una secuencia de longitud n produce `length - n + 1` ventanas. Como
cada ventana es un slice, emparejar lecturas sucesivas no cuesta
ninguna copia: `[ first2 ]` sobre cada clump de `2` te da todos los
pares consecutivos desde los que proyectar. (Su primo no solapado,
`<groups>`, en cambio trocea la secuencia en bloques disjuntos.)

## Cleave con varias entradas: `2bi`, `3bi`, `2tri`, `3tri`

Las palabras cleave simples `bi` y `tri` aplican dos o tres
quotations a *una* entrada. Las variantes con prefijo `2` y `3`
aplican cada quotation a *dos* o *tres* entradas:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

Cada quotation recibe *todas* las entradas. Úsalas cuando más de una
proyección dependa del mismo par (o la misma terna) de valores, no
cuando quieras aplicar la *misma* operación a cada entrada por
separado (eso es `bi@` o `tri@`).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
