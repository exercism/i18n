# Introducción

El concepto de condicionales presenta `jcc`, la familia de instrucciones para bifurcar en función de una condición.
Una `jcc` transfiere la ejecución a otro punto del programa solo si se cumple su condición.

Sin embargo, las CPU modernas son rápidas y capaces de ejecutar muchas instrucciones en paralelo.
Sería demasiado costoso detener todo el trabajo mientras la CPU espera una comprobación de una condición en tiempo de ejecución.

Por eso, internamente, la CPU no espera.
Usa un **predictor de bifurcaciones** para adivinar el resultado de una condición y empieza a ejecutar _de forma especulativa_ la ruta predicha.

Si la predicción es correcta, la ejecución continúa como si no hubiera bifurcación.
Sin embargo, si la predicción es errónea, la CPU debe _descartar el trabajo realizado_ en la ruta predicha y reiniciar en la correcta.

Esto se llama **predicción errónea de bifurcación** y es costoso, ya que provoca un retraso.

Cuando una bifurcación es difícil de predecir, esas predicciones erróneas se acumulan.
En esos casos, a veces es preferible evitar la bifurcación por completo, de modo que se ejecuten las mismas instrucciones independientemente de la condición.
El código que selecciona entre valores sin una `jcc` se denomina **sin bifurcaciones**.

Hay varias formas de estructurar el código para que bifurque con menos frecuencia, o para que las bifurcaciones que tenga sean más predecibles.
En particular, x86-64 proporciona dos familias de instrucciones que se usan habitualmente para escribir código sin bifurcaciones.

## Movimientos condicionales

La familia de instrucciones `cmovcc` copia el operando origen en el destino solo si se cumple una condición concreta.
En caso contrario, el destino se deja sin cambios.

El sufijo `cc` sigue la misma nomenclatura que en `jcc`, con el mismo significado:

| instrucción | mover si                             |
|-------------|--------------------------------------|
| `cmove`     | A == B tras `cmp A, B`               |
| `cmovne`    | A != B tras `cmp A, B`               |
| `cmovl`     | A < B (con signo) tras `cmp A, B`    |
| `cmovb`     | A < B (sin signo) tras `cmp A, B`    |
| `cmovg`     | A > B (con signo) tras `cmp A, B`    |
| `cmova`     | A > B (sin signo) tras `cmp A, B`    |

Las reglas son similares a las de `jcc`:

1. `l` y `g` se usan para las comparaciones con signo, y `b` y `a`, para las que no tienen signo.
2. Añadir `e` a un sufijo incluye la igualdad.
3. Añadir `n` niega la condición.
4. También hay variantes que se refieren a que la bandera está activada.
   Por ejemplo, `cmovz` y `cmovc`.

Considera el valor absoluto de un entero con signo en `rdi`, devuelto en `rax`.
Escrita con `jcc`, la función selecciona una de dos rutas:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Escrita con `cmovcc`, ambos valores candidatos se calculan de forma incondicional y el movimiento condicional elige uno:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

La versión sin bifurcaciones ejecuta siempre las mismas instrucciones.
No hay ninguna `jcc` que el predictor pueda adivinar.

El destino de una `cmovcc` debe ser un registro.
El origen puede ser un registro o una posición de memoria, pero no un valor inmediato.

~~~~exercism/note
En el código anterior, la instrucción `neg` establece varias banderas en función del resultado, incluida la bandera de signo (SF).
Esto significa que el `cmp rdi, 0` se puede eliminar por completo:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Para valores de `rdi` positivos, `neg` produce un resultado negativo y SF == 1, así que `cmovs` restaura `rdi`.
Para `rdi` igual a cero o negativo, `neg` produce un resultado no negativo y SF == 0, así que `rax` conserva el valor negado (que es el valor absoluto correcto).

Aunque `cmp` es la forma principal de comparar valores en el código ensamblador, muchas instrucciones también establecen banderas en función de su resultado.
La lista completa de banderas que afecta una instrucción suele aparecer en su [referencia][reference].
En el caso concreto de `neg`, son SF, ZF, CF, OF y PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

## Establecimiento condicional

La familia de instrucciones `setcc` establece el operando destino a `1` si se cumple una condición concreta, y a `0` en caso contrario.
El destino es siempre un _operando de 8 bits_.

El sufijo `cc` sigue la misma nomenclatura que en `jcc` y `cmovcc`.
Por ejemplo, `setz` establece el destino a `1` si `ZF == 1` y a `0` en caso contrario.

Como el destino es de 8 bits, es habitual que `setcc` vaya seguido de un `movzx` cuando se necesita un valor más ancho:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Este es un modismo habitual para convertir el resultado de una comparación en un entero `0` o `1`.
