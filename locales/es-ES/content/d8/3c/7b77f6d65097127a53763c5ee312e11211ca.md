# Introducción

## Comentarios

Common Lisp permite al programador escribir «comentarios» que el ordenador ignora.
Los comentarios de una sola línea empiezan con uno o varios puntos y coma (`;`) y, de vez en cuando, puede que veas lo siguiente:

```lisp
(code...) ; => value
```

donde el comentario se usa para indicar qué valor devuelve Common Lisp tras ejecutar el código de esa línea.

Es idiomático usar un solo punto y coma para un comentario corto al final de una línea, dos para un comentario más largo encima de una sección de código, tres para un comentario largo que describe algo como una función y cuatro para un comentario como una cabecera al principio de un fichero fuente.

## Cons

Todos los objetos de Common Lisp son o bien «átomos» (valores únicos e indivisibles) o bien «conses» (creados por la función de construcción «cons»).
Un cons se compone de dos partes: el primer elemento y el resto de los elementos.
Por razones históricas, estas dos partes se llaman `car` y `cdr`.
Cuando estos conses se evalúan como código, el primer elemento (`car`) representa la función que se llama, mientras que el resto de los elementos
(`cdr`) representan los argumentos de esa función:

```lisp
(<function> <arg1> <arg2> ... <argN>)
; ^ car ^  |        ^ cdr ^
```

## Expresiones

Todo el código de Common Lisp está hecho de S-Expressions (expresiones simbólicas). Para abreviar, se llaman sexprs. Cada sexpr es un átomo o un cons. Cuando se evalúan las S-Expressions, devuelven automáticamente algún valor que ocupa el lugar de la expresión. Cuando escribes tus propias funciones (con `defun`), el último valor dentro del cuerpo del `defun` se devuelve automáticamente:

```lisp
;; Defining a new function
(defun gimme-foo () 'foo)
;; Calling the function as an S-Expression
(gimme-foo) ; => FOO
```

## Símbolos

Los símbolos en Common Lisp son valores especiales que pueden apuntar a otros valores o, en el caso de las _keywords_, a sí mismos.
Cuando Lisp evalúa los símbolos, estos se sustituyen por los valores a los que apuntan:

```lisp
foo  ; => <whatever-foo-points-to>
:foo ; => :FOO
```

Ten en cuenta que las keywords se indican con dos puntos (`:`) al principio.

El quoting (añadir `'` delante de una S-expression) le indica a Lisp que no evalúe esa expresión.
Al hacer quoting de `'foo` en nuestro ejemplo de `defun`, evitamos que Lisp intentara buscar (y no encontrara) aquello a lo que se suponía que apuntaba `FOO` y, en su lugar, devolvimos el propio valor `FOO`.
Si `FOO` no se ha definido en ningún sitio de nuestro programa:

```lisp
foo  ; => <ERROR! Lisp doesn't know what foo points to!>
'foo ; => FOO
```

Por ahora, puedes considerar esto simplemente como una forma de devolver símbolos desde una función, pero volveremos sobre el quoting y exploraremos más a fondo sus implicaciones en futuros ejercicios de concepto.
