# Acerca de

Una función es [recursiva de cola][recursion-tc] si lo _último_ que ejecuta la función es una llamada a sí misma.

Cada vez que se llama a una función, se coloca un _marco de pila_ con sus variables locales y sus argumentos en la parte superior de [la pila de llamadas][call-stack].
Cuando una función termina, el marco de pila se elimina de la pila.

Las funciones recursivas de cola permiten la [optimización de llamadas de cola][tail-call-optimization] (o eliminación de llamadas de cola).
Es una optimización que permite reutilizar el último marco de pila en la siguiente llamada a una función cuando se garantiza que la función anterior ya no lo necesita.
Esto mitiga el problema de desbordar la pila de llamadas, que es la situación en la que hay tantos marcos en la pila de llamadas que ya no queda memoria para crear otro.

## La optimización de llamadas de cola en Elm

Bajo ciertas condiciones, el compilador de Elm es capaz de realizar automáticamente una optimización de llamadas de cola cuando compila a JavaScript.

La optimización puede producirse en una función recursiva cuando la _última_ operación de una rama consiste en llamar a la propia función en una aplicación de función simple.
Veamos algunos ejemplos:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

La implementación anterior no es recursiva de cola, porque la última operación de la rama `else` es una multiplicación `n *`.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

La implementación anterior sí es recursiva de cola y se optimizará, porque la última operación de la rama `else` es `factorialHelper` llamándose a sí misma.
Esto no sería posible con una función cuya firma de tipo sea `Int -> Int`, y, en la práctica, la optimización de llamadas de cola se suele lograr definiendo funciones auxiliares.

## Casos límite

En algunos casos, el compilador no es capaz de optimizar las funciones recursivas. Veamos algunos ejemplos.

Mientras que `f x = f (x - 1)` es recursiva de cola, `f x = (x - 1) |> f` no lo es, porque la aplicación de función `|>` es la última operación y se considera independiente de `f`.
Del mismo modo, las funciones que terminan con condiciones booleanas `f x = x > 0 || f (x - 1)` no son recursivas de cola.

La función `f x = if f (x - 1) then 1 else 0` no es recursiva de cola, porque la expresión del `if` no se considera una rama.
Del mismo modo, una llamada recursiva en una instrucción `case` tampoco se optimizaría.

La función `f x = let y = f (x - 1) in y` no es recursiva de cola porque se llama a sí misma en una instrucción `let`, que no se considera una rama.
Sin embargo, en `f x = let g x = g (x - 1) in g x` la función `g` es recursiva de cola y se optimizará aunque esté definida en una instrucción `let`.

La función `f x = if x > 0 then f (x + 1) else 1 + f x` se optimizará _parcialmente_: la rama `then` se puede optimizar, pero la rama `else` no.
La optimización parcial es lo mejor que se puede conseguir en algunas situaciones, como recorrer estructuras en forma de árbol o definir funciones correcursivas.
