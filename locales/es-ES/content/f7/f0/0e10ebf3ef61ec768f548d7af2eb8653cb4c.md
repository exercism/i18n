# Acerca de

[Elixir](https://elixir-lang.org/), publicado inicialmente en 2012, amplía las ya sólidas características de Erlang y, además, resulta más fácil de abordar, leer, probar y escribir para quienes se inician en la programación.

José Valim, el creador de Elixir, explica [en su charla de 2012](https://vimeo.com/53221562) cómo diseñó el lenguaje para que las aplicaciones fueran:

  1. Distribuidas
  2. Tolerantes a fallos
  3. De tiempo real suave
  4. De intercambio de código en caliente (permite introducir código nuevo sin detener el servidor)

En realidad, Elixir se compila a [bytecode](https://en.wikipedia.org/wiki/Bytecode) y después se ejecuta en la [máquina virtual Erlang BEAM](https://codesync.global/media/robert-virding-co-creator-of-erlang-explains-the-beam/).

No hay ningún «coste de conversión» por llamar a Erlang, lo que significa que puedes ejecutar código Erlang justo al lado de código Elixir.

Al ser un lenguaje funcional, todo en Elixir es una expresión.

Elixir tiene «documentación de primera clase», lo que significa que los comentarios se pueden asociar a una función, lo que hace que sea más fácil de consultar.

Las expresiones regulares también reciben un tratamiento de primera clase, lo que elimina el incómodo escapado dentro de los strings.

La implementación de comunicación asíncrona de Elixir permite que el código sea ligero y, aun así, incorpore una concurrencia de gran volumen.

Los programadores usan Elixir para gestionar miles de peticiones y respuestas *de forma concurrente* en un único nodo de servidor.

Se ha utilizado con éxito en microservicios que necesitan consumir y servir multitud de APIs rápidamente.

El [framework Phoenix](https://www.phoenixframework.org/) ayuda a estructurar aplicaciones Elixir para la web.
