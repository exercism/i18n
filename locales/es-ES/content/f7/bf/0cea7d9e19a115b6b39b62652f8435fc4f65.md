# Introducción

## Tipos personalizados

Los [tipos personalizados][custom-types] de Elm representan un número fijo de casos con nombre. Cada valor se corresponde con exactamente uno de esos casos con nombre.

Un tipo personalizado se define con la palabra clave `type` y requiere muy poca sintaxis. Son una de las técnicas más importantes de la programación en Elm y se usan para que los valores posibles en el código coincidan exactamente con los valores válidos de la vida real, lo que no deja cabida a datos inválidos y hace que [los estados imposibles no se puedan representar en el código][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Cada caso de un tipo personalizado puede tener datos asociados de forma opcional, y distintos casos pueden tener distintos tipos de datos. Si ninguno de los casos tiene datos asociados, la unión discriminada se parece a lo que en otros lenguajes se suele llamar una _enumeración_ (o _enum_).

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Puedes crear un valor para un caso concreto refiriéndote a su nombre (`Spring`) cuando este está definido en el mismo módulo o se importa con la sintaxis `import SeasonModule exposing (Season(..))`, o bien refiriéndote a su nombre totalmente cualificado (`Season.Spring`) cuando se importa con la sintaxis `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Los tipos personalizados, al igual que todo en Elm, tienen _igualdad estructural_, lo que significa que dos valores del mismo caso y con los mismos datos (opcionales) son equivalentes.

La forma preferida de trabajar con tipos personalizados es la [coincidencia de patrones][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
