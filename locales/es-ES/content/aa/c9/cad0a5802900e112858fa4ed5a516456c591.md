# Acerca de

Aunque los programadores de Elixir suelen decir [«deja que falle»][let-it-crash] y programan para el [«camino feliz»][happy-path], hay ocasiones en las que necesitamos rescatar la llamada a la función para devolver un valor concreto o un mensaje, o para liberar recursos del sistema.

- Las funciones que lanzan errores en circunstancias normales deben tener `!` al final de su nombre.
- Las funciones pueden, como alternativa, devolver átomos y tuplas para indicar éxito y fallo:

  ```elixir
  Map.fetch(%{a: 1}, :a)
  # => {:ok, 1}
  Map.fetch(%{a: 1}, :b)
  # => :error

  Map.fetch!(%{a: 1}, :b)
  # => raises KeyError
  ```

## Evita los antipatrones

Evita los patrones de programación que usan errores para controlar el flujo lógico. Esto es un antipatrón en Elixir.

```elixir
# Avoid using errors for control-flow.
try do
  {:ok, value} = MyModule.janky_function()
  "All good! #{value}."
rescue
  e in RuntimeError ->
    reason = e.message
    "Uh oh! #{reason}."
end

# Rather, use control-flow structures for control-flow.
case MyModule.janky_function() do
  {:ok, value} -> "All good! #{value}."
  {:error, reason} -> "Uh oh! #{reason}."
end
```
