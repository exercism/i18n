# Acerca de

En C#, una tupla es una estructura de datos que organiza datos y que contiene dos o más campos de cualquier tipo.

Una tupla se crea normalmente colocando dos o más expresiones separadas por comas dentro de un par de paréntesis.

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

Como cualquier otra expresión, una tupla se puede usar de diversas formas: en las [asignaciones][tuple-assignment], para inicializar un campo o una variable, como [valor devuelto][tuple-return-values] de un método o pasada como parámetro. También se pueden comprobar por [igualdad][tuple-equality]. La igualdad de tuplas se ilustra por completo en el ejercicio `pattern-matching-tuples`, pero a continuación se incluye un ejemplo para mayor completitud.

Los campos se extraen mediante la sintaxis de punto. De forma predeterminada, el primer campo es `Item1`, el segundo es `Item2`, etc. Los nombres no predeterminados se explican más abajo, en _Nombres_.

Una tupla se puede usar como parámetro genérico, p. ej. `IList<(bool, string)>`

Además, las tuplas admiten la «deconstrucción», que se explica más abajo, y se pueden usar en la coincidencia de patrones, que se trata en un ejercicio posterior.

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

Esta [introducción][tuples] muestra cómo definir y usar tuplas.

## Nombres

Los nombres de campo `Item1`, etc. no hacen que el código sea legible. Hay tres formas de dar nombre a los campos: a) en la declaración del tipo, b) en la expresión que lo crea o c) mediante los [inicializadores de proyección de tuplas][tuple-projection-initializers] (no se ilustran aquí).

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

No intentes ser demasiado ingenioso con el mecanismo de nombres. En realidad no es más que azúcar sintáctico. Por ejemplo, no puedes cambiar los nombres de una tupla cuando le asignas el contenido de otra tupla.

## Deconstrucción

A veces resulta útil tomar una tupla y asignar sus campos a varias variables, inicializándolas cuando corresponda. Este mecanismo se llama [deconstrucción][tuple-deconstruction]. (También se puede aplicar a tus propios objetos. Consulta [aquí][udt-deconstruction]).

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## Asignación de campos

Se puede asignar un valor a los campos de una tupla de forma individual. Sin embargo, dada la tendencia de C# hacia la inmutabilidad, este tipo de uso no está muy extendido. A menudo se usan las tuplas como si fueran inmutables, cosa que por supuesto no son.

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## Antecedentes

Las tuplas de las que hablamos no deben confundirse con [`System.Tuple`][system-tuple], que probablemente solo se encuentre en bases de código heredado.

La situación es un poco más confusa cuando se trata de `System.ValueTuple`. La [documentación][system-value-tuple] de la última sobrecarga de [`System.ValueTuple`][system-value-tuple] afirma que «The value tuple types provide the runtime implementation that supports tuples in C#». Con «tipos de tupla de valor» se refieren aquí a las sobrecargas genéricas de `System.ValueTuple`. Con «tuplas» se refieren a las cosas que nos han ocupado en este ejercicio. En efecto, están diciendo que `System.ValueTuple` es un detalle de implementación de las tuplas. Es poco probable que esto interese mucho, la mayor parte del tiempo, a la mayoría de la gente. Por desgracia, gran parte de la documentación sobre «tuplas», incluida la de la propia Microsoft, está salpicada de referencias a `System.ValueTuple`. Probablemente no pasa nada por pasar por alto esas referencias.

## Otros usos y limitaciones

La coincidencia de patrones es un uso especialmente productivo para las tuplas. Se trata en un ejercicio posterior.

Las tuplas permiten algunos otros pequeños toques estilísticos:

- Asignación múltiple (sobre todo en constructores), p. ej. `(this.field1, this.field2) = (arg1, arg2);`
- Intercambiar o reciclar valores, p. ej. `(a, b) = (b, a);`
- Usarlas en lugar de un `struct` en una lista
- Usarlas como clave de diccionario o como contenido de un conjunto.
- Usarlas en LINQ. (LINQ se trata en ejercicios posteriores).

La documentación describe las tuplas como un mecanismo ligero, y esa es la clave de su uso correcto. Usar una tupla en lugar de una clase o un struct puede dar lugar a una tediosa repetición de los tipos de sus campos y, posiblemente, de sus nombres. Esto se aplica sobre todo a su uso como argumento de método o como argumento genérico en colecciones.

Lo mejor es recurrir a trucos como la asignación múltiple y el intercambio con criterio.

No se admiten operaciones relacionales distintas de la igualdad y la desigualdad.

Ten en cuenta que las tuplas se introdujeron en el lenguaje hace relativamente poco (C# 7), así que si quieres usarlas debes asegurarte de que tu base de código usa la [versión][language-version] 7 o posterior del lenguaje.
