# Introducción

Las excepciones en Ruby, como en muchos lenguajes, proporcionan una forma de lidiar con eventos inesperados. Manejar bien las excepciones es importante cuando intentas evitar que tu programa se bloquee.

Cuando se lanza una excepción, ya sea lanzándola explícitamente o porque la lance el intérprete de Ruby, el programa interrumpe su funcionamiento normal y acaba saliendo con un mensaje de error:

```ruby
raise ArgumentError.new("Something went wrong!")
=> Traceback (most recent call last):
.
.
ArgumentError (Something went wrong!)
```

```ruby
1/0
=> Traceback (most recent call last):
.
.
ZeroDivisionError (divided by 0)
```

Si queremos detener este proceso de cierre, tenemos que reaccionar ante la excepción. Esto se llama «rescatar» una excepción:

```ruby
begin
  # ...any code that raises an exception
rescue
  puts 'Got an exception'
end
```

Este programa no se bloqueará y mostrará «Got an exception». En lugar de salir, Ruby ejecuta el código del bloque rescue, que imprime un mensaje.

Al igual que todo en Ruby, las excepciones también son objetos y normalmente contienen datos sobre la excepción. Así podemos obtener el objeto de la excepción:

```ruby
begin
  # ...any code that raises an exception
rescue => e
  puts "Exception class: #{ e.class.name }"
  puts "Exception Message:#{e.message}"
end
```

En Ruby también es posible lanzar tus propias excepciones. Por ejemplo:

```ruby
begin
  raise ArgumentError.new("Invalid argument")
rescue ArgumentError => e
  puts e.message
end
```

La excepción anterior es una de las excepciones integradas de Ruby, pero también es posible definir excepciones personalizadas y lanzarlas:

```ruby
class CustomError < StandardError
end

raise CustomError.new("Something went wrong")
```
