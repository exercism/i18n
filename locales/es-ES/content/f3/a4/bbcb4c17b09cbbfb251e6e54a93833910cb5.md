# Acerca de

Las funciones recursivas son funciones que se llaman a sí mismas.

Una función recursiva debe tener al menos un _caso base_ y al menos un _caso recursivo_.

Un _caso base_ devuelve un valor sin volver a llamar a la función.
Un _caso recursivo_ vuelve a llamar a la función, modificando la entrada para que en algún momento coincida con el caso base.

En Elm, las funciones recursivas se suelen definir mediante coincidencia de patrones con expresiones `case`.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

Una función recursiva puede tener muchos casos base, muchos casos recursivos o ambos.
Por ejemplo, [la sucesión de Fibonacci][fibonacci] es una sucesión recursiva con dos casos base:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

Ten en cuenta que esta implementación en concreto es exponencialmente lenta, ya que los números de Fibonacci relacionados se calculan desde cero en dos llamadas recursivas independientes.

Contar el número de apariciones de un valor dado `x` en un array tiene dos casos recursivos:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## Bucles mediante recursión

Debido a la inmutabilidad, los bucles en Elm se escriben de forma distinta a como se escriben en los lenguajes imperativos.
Por ejemplo, los bucles suelen tener este aspecto:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

En un lenguaje funcional como Elm, no es posible mutar variables.
Por lo tanto, los bucles tienen que implementarse con recursión.

El equivalente de un bucle `for` en Elm tendría este aspecto:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

En la práctica, iterar sobre arrays y otras estructuras de datos en Elm se hace casi siempre con funciones del módulo [`List`][module-list], como `List.map`, `List.filter` y `List.foldl`.
Por dentro, estas funciones están implementadas con recursión.

## Ejecución infinita

Las funciones recursivas, si se implementan de forma incorrecta o si el número de llamadas recursivas es demasiado grande, pueden no devolver nunca su resultado.
Esto puede ser problemático porque cada vez que se llama a una función se guarda en memoria una referencia al lugar al que el entorno de ejecución debe devolver el resultado (en la [pila de llamadas][wiki-call-stack]).
Si una función recursiva se llama a sí misma demasiadas veces o incluso de forma infinita, es posible que se agote la memoria y que el entorno de ejecución se bloquee (un [error de desbordamiento de pila][wiki-stack-overflow]).
El entorno de ejecución de Elm está optimizado para la recursión y la fiabilidad, pero la recursión infinita todavía puede causar problemas.

Este problema de ejecución infinita puede deberse a:

- Olvidar implementar un caso base.
- No gestionar todos los casos posibles en la coincidencia de patrones.
- No modificar bien el argumento al hacer la llamada recursiva y, por tanto, no alcanzar nunca el caso base.
