# Instrucciones

Estás escribiendo el firmware del sistema de puntuación de una consola portátil retro.
La CPU de la máquina es modesta y la pantalla del marcador se actualiza a una frecuencia fija.
Para que la imagen se mantenga fluida, las rutinas de puntuación deben ejecutarse en un número predecible de ciclos, independientemente de lo que esté haciendo el jugador.

Tienes cuatro tareas.

~~~~exercism/note
El código de las tareas debe carecer de bifurcaciones.
Usa `cmovcc`, `setcc` y aritmética en lugar de saltos condicionales.
~~~~

## 1. Añade una bonificación sin desbordar la pantalla

La zona de puntuación de la pantalla LCD de la consola tiene espacio para seis dígitos decimales.
No puede mostrar ningún número superior a `999999`.
Cuando una bonificación haría que el total acumulado superara ese límite, el total mostrado se mantiene en el máximo en lugar de dar la vuelta.

Define una función `add_bonus` que, dados un total actual y una bonificación que sumar, devuelva el nuevo total limitado a `999999`.
Los argumentos, en orden, son:

1. `total`: el total de puntuación actual (siempre entre `0` y `999999`)
2. `bonus`: la bonificación que hay que sumar (siempre no negativa)

El valor devuelto es `total + bonus` si esa suma es menor o igual que `999999`, y `999999` en caso contrario:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

Tanto los argumentos como el valor devuelto son números enteros de 64 bits con signo.

~~~~exercism/note
Puedes suponer que `total + bonus` no desborda un número entero de 64 bits con signo.
~~~~

## 2. Compara dos puntuaciones

La consola guarda una pequeña tabla de clasificación con las mejores puntuaciones recientes del jugador en su archivo de guardado.
Después de cada partida, la nueva puntuación se inserta en la tabla de clasificación en la posición correcta.
La rutina de ordenación pregunta cuál de las dos puntuaciones va por delante y espera la respuesta como un número entero pequeño.

Define una función `compare_scores` que, dadas dos puntuaciones, devuelva:

- `+1` si la primera puntuación es _mayor_
- `-1` si la primera puntuación es _menor_
- `0` si las dos puntuaciones son _iguales_

Ejemplo:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

Tanto los argumentos como el valor devuelto son números enteros de 64 bits con signo.

## 3. Valida una puntuación sin procesar

La consola puede conectarse a otra unidad mediante su cable de enlace para compartir puntuaciones después de una partida multijugador.
El cable tiene ruido eléctrico y los bytes entrantes se corrompen de vez en cuando, lo que produce valores muy por debajo del mínimo legal o muy por encima del máximo legal.
El validador limita cada puntuación entrante al rango legal antes de que el resto del sistema la vea.

Define una función `validate_score` que, dada una puntuación sin procesar y los límites legales, devuelva la puntuación limitada a `[min, max]`.
Los argumentos, en orden, son:

1. `score`: la puntuación sin procesar recibida por el cable de enlace
2. `min`: la puntuación más pequeña permitida
3. `max`: la puntuación más grande permitida

El valor devuelto es `min` si `score < min`, `max` si `score > max`, y `score` en caso contrario.
Puedes suponer que `min <= max`.

Ejemplo:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

Todos los argumentos y el valor devuelto son números enteros de 64 bits con signo.

## 4. Registra las dos puntuaciones más altas

Al final de cada sesión de juego, la consola recorre el registro de partidas recientes de su archivo de guardado para encontrar las dos puntuaciones más altas registradas.
El registro es un array simple de números enteros de 64 bits con signo en memoria.
El recorrido pasa una vez por el array y mantiene dos máximos: el más alto visto hasta ahora y el segundo más alto.

Ten en cuenta que ambos números deben ser al menos `0`.
Cualquier número negativo se ignora.

Una primera versión de la función se escribió con saltos condicionales en cascada.
Para cada candidato, el código pregunta dónde encaja (por encima del primero, entre el primero y el segundo, o en ningún sitio) y desplaza los máximos en consecuencia, descartando cualquier resultado negativo.

Esto funciona.
Sin embargo, como los valores de entrada son aleatorios, cada salto condicional provoca muchos errores de predicción de bifurcaciones.
Por eso has decidido refactorizar el bucle principal para que no tenga bifurcaciones.

A continuación tienes la función con la sección de bifurcaciones comentada:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

Sustituye la sección comentada por una implementación sin bifurcaciones.
El único salto permitido en el código nuevo es el que vuelve al inicio del bucle para comprobar un nuevo elemento del array.

La función no devuelve ningún valor y recibe los mismos argumentos que la versión con bifurcaciones:

1. `out`: búfer de salida donde la función escribirá las dos puntuaciones no negativas más altas en orden descendente, como números enteros de 64 bits con signo
2. `array`: array de entrada de números enteros de 64 bits con signo
3. `length`: el número de elementos del array, como número entero de 64 bits sin signo

~~~~exercism/note
Si el array contiene valores duplicados, los duplicados pueden aparecer en las dos posiciones de salida si son las dos puntuaciones más altas.
~~~~
