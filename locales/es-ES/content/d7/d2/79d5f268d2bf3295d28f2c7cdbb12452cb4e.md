# Introducción

## Formato de strings

En C#/.NET hay dos mecanismos principales para dar formato a los strings: el uso de `String.Format()` y la interpolación de strings.

### Formato compuesto

`String.Format()` recibe un string (al que la documentación llama _formato compuesto_) formado por texto fijo y marcadores de posición (que la documentación llama elementos de formato), y un número variable de argumentos. El valor devuelto resuelve cada elemento de formato usando el argumento correspondiente y combina los valores resueltos con el texto fijo.

```csharp
string.Format("I had {0} bitcoins on {1}, the day I forgot my password.", 55.5, new DateTime(2010, 2, 25));
// => "I had 55.5 bitcoins on 2/25/2010 00:00:00, the day I forgot my password." - US settings
```

Técnicamente, este mecanismo se conoce como _formato compuesto_.

### Interpolación de strings

Los strings interpolados van precedidos de un `$` e incluyen expresiones que se evalúan en tiempo de ejecución entre llaves. El elemento de formato tiene la siguiente sintaxis: `$"{<interpolationExpression>}"`. Eliminan la necesidad de una lista de argumentos aparte. El resultado es funcionalmente equivalente al mecanismo de `String.Format()`.

```csharp
var loadsOf = 55.5;
var thatDay = new DateTime(2010, 2, 25);
$"I had {loadsOf} bitcoins on {thatDay}, the day I forgot my password."
// => "I had 55.5 bitcoins on 2/25/2010 00:00:00, the day I forgot my password." - US settings
```

### Elementos de formato

El texto entre llaves, que en el formato compuesto son marcadores de posición y, en la interpolación de strings, expresiones interpoladas, se conoce como _elemento de formato_.

Un elemento de formato puede constar de hasta 3 partes. La primera es la expresión o el marcador de posición del argumento, obligatoria, como se ve en el código de ejemplo anterior. Además, hay una alineación opcional (que se introduce con una coma, «,») y un _string de formato_ opcional (que se introduce con dos puntos, «:»).

`{<interpolationExpression>[,<alignment>][:<formatString>]}`

La _alineación_ especifica la longitud del «campo» en el que se coloca el texto, rellenado con espacios a la izquierda si la alineación es positiva o a la derecha si es negativa.

El _string de formato_ especifica la forma del texto de salida, como si deben incluirse separadores de miles en un número o si solo debe mostrarse la parte de la fecha de un objeto `DateTime`.

El siguiente código ilustra cómo mostrar la parte de la fecha de un objeto `DateTime` y un número de coma flotante en notación exponencial.

```csharp
var loadsOf = 55.5;
var thatDay = new DateTime(2010, 2, 25);
$"I had {loadsOf:E} bitcoins on {thatDay:d}, the day I forgot my password."
// => I had 5.550000E+001 bitcoins on 02/25/2010, the day I forgot my password. - US settings

string.Format(
    "I had {0:E} bitcoins on {1:d}, the day I forgot my password.",
    loadsOf, thatDay)
// => I had 5.550000E+001 bitcoins on 02/25/2010, the day I forgot my password. - US settings
```

Existen formatos tanto estándar como personalizados, para números y para fechas. No hay una diferencia esencial entre los formatos _personalizados_ y los _estándar_, salvo que tienes la oportunidad de componer strings de formato personalizados a partir de letras de formato.

### Cultura

Cada hilo tiene una cultura predeterminada, `Thread.CurrentThread.CurrentCulture`, encapsulada en una instancia de `CultureInfo`. La cultura del hilo determina cómo se formatean las fechas y los números en función de variaciones regionales, como la diferencia en el formato de fecha convencional entre el _DD/MM/YYYY_ del Reino Unido y el _MM/DD/YYYY_ de Estados Unidos.

`CultureInfo` implementa la interfaz `IFormatProvider`, que puede pasarse a determinadas sobrecargas de `String.Format()`. Esto puede usarse para anular la cultura del hilo.

## Strings textuales

Los strings textuales permiten strings de varias líneas. Se introducen con una @.

```csharp
string str = @"
See no wretched
quotes everywhere
";
```
