# Introducción

Los tipos simples (strings y primitivos) se suelen comparar por igualdad con `==` y `!=`.

Los tipos de referencia (instancias de clases) se comparan con el método `Equals()` heredado de `Object`. Si tu objetivo con la prueba de igualdad es asegurarte de que dos objetos son exactamente la misma instancia, basta con confiar en la implementación de `Object`. Si no es así, tienes que sobrescribir `object.Equals()`.

Si sabes que todas las instancias de tu clase se crean en un solo sitio, por ejemplo los personajes de un juego o una simulación, la igualdad de referencias es suficiente. Sin embargo, es probable que se creen varias instancias de la misma entidad del mundo real (desde una base de datos, a partir de la entrada del usuario, mediante una petición web). En ese caso, hay que comprobar la igualdad de los valores que identifican la entidad de forma única. Por lo tanto, hay que sobrescribir `Equals()` y comprobar la igualdad de los miembros de datos adecuados de tu clase.

Un método `Equals()` sobrescrito contendrá pruebas de igualdad sobre miembros de tipos simples usando `==` y sobre tipos de referencia con llamadas recursivas a `Equals()`.

La clase `Object` proporciona los métodos adecuados para comparar dos objetos y detectar si son una y la misma instancia.

## `Object.GetHashCode()`

El método `Object.GetHashCode()` devuelve un código hash en forma de entero de 32 bits. Las clases de _diccionario_ y _conjunto_, como `Dictionary<T>` y `HashSet<T>`, usan el código hash para almacenar y recuperar objetos de forma eficiente.

La relación entre el código hash y la igualdad es que, si dos objetos son iguales (`Equal()` devuelve true), `GetHashCode()` debe devolver el mismo valor para ambos. Esto no se cumple en la dirección contraria. No es simétrico. Que dos objetos tengan el mismo código hash no significa que tengan que ser iguales. Imagina una función de búsqueda que primero va a un «cubo» basándose en el código hash y luego selecciona el elemento concreto mediante la prueba de igualdad.

La documentación de la API de la biblioteca HashCode explica cuál es la mejor forma de generar un código hash

Los valores que se usan en la prueba de igualdad deben ser estables mientras se esté usando la colección con hash. Si añades un objeto a la colección con un conjunto de valores y luego cambias esos valores, el código hash ya no apuntará al «cubo» correcto. En la práctica, esto significa que el objeto debería ser inmutable. Otros enfoques corren el riesgo de crear sorpresas desagradables para quienes mantienen el código.
