# Acerca de

Las excepciones son una forma de gestionar errores.
Se llaman excepciones porque normalmente aparecen cuando surge algún evento inesperado.

En cualquier punto de nuestro código podemos «lanzar» una excepción.
Lo hacemos con el método `raise`, al que le pasamos un objeto, normalmente un objeto Exception, aunque también podemos usar strings básicos.
Por ejemplo, verás en los esqueletos de los ejercicios que usamos el `RuntimeError` integrado para indicarle a Ruby que un método no se ha implementado.
También puedes usar la sintaxis abreviada de `raise(ExceptionObject, params)`.
Si se omite la clase de la excepción, se usa `RuntimeError` por defecto.

Por ejemplo:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

Cuando Ruby se encuentra con esto, propaga el error hasta lo más alto del programa y después finaliza.

Por ejemplo, si intentas dividir algo entre cero, verás algo como esto:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

Es importante señalar que las excepciones deben usarse en los casos en los que ocurre algo excepcional, un error que necesita un tratamiento especial.
Las excepciones no deben usarse para controlar el flujo de un programa, ya que eso se considera un mal diseño, que a menudo da lugar a un rendimiento y un mantenimiento deficientes.

## Jerarquía de clases

En Ruby, las excepciones siguen una jerarquía de clases en la que `Exception` es la clase base.
Estas son las excepciones integradas más comunes de Ruby:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

Capturar los errores de una clase concreta también captura los errores de sus clases hijas.
Por eso puede ser peligroso capturar `Exception`.
Ruby también usa las excepciones para gestionar los mensajes que el sistema operativo envía mediante «señales», por ejemplo `ctrl-c`.
Esto significa que capturar `Exception` también capturará estas «señales» del sistema.
Así que, para evitar comportamientos inesperados, la práctica habitual para capturar «todos los errores» es capturar `StandardError`.

## Sintaxis de captura
Ruby también ofrece cláusulas de captura ampliadas para situaciones que requieren un tratamiento especial:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

Esto puede ser útil, por ejemplo, cuando se trabaja con E/S de red, donde siempre hay que acordarse de cerrar una conexión.

Los bloques de captura de Ruby también pueden usar la palabra clave `retry`, que vuelve a ejecutar todo lo que hay entre begin y rescue:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
