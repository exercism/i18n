# Acerca de

Los hash-sets implementan el [protocolo][set-protocol] [`sets`][sets] recurriendo internamente al hash, lo que da O(1) de media al insertar, consultar y eliminar. Son mutables in situ, lo que los hace ideales para el patrón del *conjunto de visitados* en los recorridos de grafos.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| palabra       | efecto                                    |
|---------------|-------------------------------------------|
| `HS{ }`       | literal de hash-set vacío (compartido, ¡clónalo con `clone`!) |
| `>hash-set`   | `( seq -- set )` — crea un conjunto nuevo a partir de una secuencia (elimina duplicados) |
| `adjoin`      | `( elt set -- )` — inserta de forma destructiva |
| `in?`         | `( elt set -- ? )` — pertenencia          |
| `delete`      | `( elt set -- )` — elimina de forma destructiva |
| `cardinality` | `( set -- n )` — número de elementos      |
| `null?`       | `( set -- ? )` — verdadero cuando el conjunto está vacío |
| `members`     | `( set -- seq )` — enumera como secuencia |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )` — convierte `set` a la clase de `exemplar` |

Para construir un conjunto a partir de datos que ya tienes, `>hash-set` convierte cualquier secuencia en un solo paso y descarta los duplicados: `{ 2 3 2 5 } >hash-set` da `HS{ 2 3 5 }`. Es la alternativa masiva a ir creciendo el conjunto con `adjoin` repetidos.

Un matiz sutil sobre `in?` frente a `member?` (de `sequences`): ambos comprueban la pertenencia, pero `member?` hace un recorrido lineal por la secuencia, mientras que `in?` delega en el método de protocolo del tipo de conjunto que corresponda: en el caso de `HS{ }`, una búsqueda en un hash. Usa `in?` cuando tu contenedor de «visitados» tenga más de un puñado de elementos.

`null?` responde a «¿está vacío este conjunto?» sin calcular todo el `cardinality`: es la guarda natural para preguntar «¿nos queda algo por procesar?». Para una lista de trabajo guardada como conjunto, `[ set null? ] [ … ] until` la consume hasta vaciarla.

## Se lleva bien con las tablas hash

`HS{ }` para responder «¿se ha visitado X?» combina de forma natural con `H{ }` para responder «¿quiénes son los vecinos de X?». Un DFS de manual es simplemente:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

El conjunto de visitados evita trabajo duplicado; la pila va enlazando los nodos de la frontera (LIFO mediante `push`/`pop`); el mapa de vecinos (una tabla hash) proporciona el grafo. El orden de visita no importa cuando la pregunta es de alcanzabilidad, y por eso basta con usar un vector como pila: un BFS real con la misma estructura cambia el vector por una [`<dlist>`][dlist] y va sacando elementos por delante.
