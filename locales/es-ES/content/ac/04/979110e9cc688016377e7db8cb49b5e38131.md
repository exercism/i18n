# Propiedad

En Cairo, el concepto de propiedad está ligado a las _variables_ y no a los _valores_ que estas contienen.

Los valores en Cairo son inmutables; esta inmutabilidad garantiza que, aunque muchas variables hagan referencia al mismo valor, el valor en sí permanezca constante y sin alteraciones.
Por eso, el compilador debe garantizar que el programador los use correctamente.
Este es el significado de la _propiedad_ de una variable: el propietario es el código que puede leer la variable (y escribir en ella si es mutable).

## Reglas de propiedad de las variables

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## El scope de las variables

Un scope es el rango dentro de un programa en el que una variable es válida.
Vamos a ver el siguiente ejemplo, que declara una variable `x` de tipo entero sin signo, con comentarios que indican dónde es válida la variable:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Notas:

- Cuando `x` entra en el scope, es válida.
- Sigue siendo válida hasta que sale del scope, en este caso hasta el final de la función `main()`.

## Mover valores

Un movimiento se produce cuando un valor se pasa a otra función: se destruye la variable original que hacía referencia al valor (lo que deja la variable inservible) y se crea una nueva variable que contiene ese mismo valor.

Los arrays son un ejemplo de un tipo complejo que se mueve al pasarlo a otra función.
Aquí tienes un breve recordatorio de cómo es un array:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

¿Cómo garantiza el sistema de tipos que un programa de Cairo nunca intente escribir dos veces en la misma celda de memoria?
Fíjate en el siguiente código, en el que intentamos eliminar el primer elemento del array dos veces:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

En este caso, intentamos pasar el mismo valor (el array de la variable `arr`) a las dos llamadas a función.
Esto significa que nuestro código intenta eliminar el primer elemento dos veces, lo que supondría escribir dos veces en la misma celda de memoria, algo que la VM de Cairo prohíbe y que provoca un error en tiempo de ejecución.
Por suerte, este código no llega a compilarse.
Una vez que hemos pasado el array a la función `foo`, la variable `arr` ya no se puede usar.
Obtenemos este error de compilación, que nos dice que necesitaríamos que `Array` implementara el trait `Copy`:

## El trait Copy

Si un tipo implementa el trait `Copy`, pasarlo a una función no mueve el valor, sino que crea una nueva variable que hace referencia a ese mismo valor.
Es una operación gratuita, porque las variables son una abstracción de Cairo y los valores siempre son inmutables.

Para implementar el trait `Copy` en tu tipo, añade la anotación `#[derive(Copy)]` a la definición del tipo.
Sin embargo, Cairo no lo permitirá si el tipo, o cualquiera de sus componentes, no implementa el trait `Copy`.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## Destruir valores

Los tipos lineales también se pueden aprovechar destruyéndolos, lo que garantiza que el recurso asociado se libere correctamente.
Esto se consigue implementando o derivando el trait `Drop`, que indica al compilador que el tipo se puede destruir de forma segura cuando ya no es útil.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

Por el momento, la implementación de `Drop` se puede derivar para todos los tipos, salvo para los diccionarios (`Felt252Dict`) y los tipos que contienen diccionarios.
Esto se debe a que los diccionarios deben «aplanarse» cuando se destruyen.
Para ello, derivamos el trait `Destruct`:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## Valores devueltos y scope

Devolver valores equivale a moverlos.
El siguiente ejemplo muestra una función que devuelve algún valor:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
