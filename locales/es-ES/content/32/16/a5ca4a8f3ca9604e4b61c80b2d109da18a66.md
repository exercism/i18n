# Pistas

## General

- Un contrato va después del tipo devuelto y antes del `is`:

  ```sather
     spare_capacity(load : INT) : INT
        pre load >= 0
     is
        ...
     end;
  ```

- Dentro de un contrato puedes usar los argumentos y los atributos del objeto,
  así que `limit` está disponible.
- Las pruebas se compilan sin `-chk`, así que un contrato incorrecto no hará que
  fallen. Escríbelos pensando en quien los lea.

## 1. Monta un arnés

- `pre kg > 0`, en `create`.
- El cuerpo es el `new` de siempre: asigna el atributo y devuélvelo.

## 2. ¿Cuánta capacidad sobra?

- Dos condiciones unidas con `and`: `pre load >= 0 and load <= limit`.
- `post result >= 0`. Eso se deduce del `pre`, que es lo que hace que merezca la
  pena decirlo: deja constancia de por qué se puede confiar en la respuesta.

## 3. ¿Cómo de lleno está?

- `pre load >= 0` y `post result >= 0`.
- `load * 100 / limit`, en ese orden. Si divides antes, lo desechas todo, igual
  que pasaría en `tuning-the-strings`.

## 4. ¿Es seguro?

- Ningún `pre`: lo importante es que se puede preguntar por cualquier carga.
- El `post` reformula la pregunta: `post result = (load <= limit)`.
  Paréntesis, porque `=` se usa dos veces para cosas distintas.
