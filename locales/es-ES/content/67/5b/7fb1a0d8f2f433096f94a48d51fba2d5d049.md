# Debug

YS tiene una función `DBG` integrada que puede resultarte útil para depurar el
código de tu solución.
Toma cualquier número de argumentos y los imprime en la consola a través de stderr.
Devuelve el último argumento, así que puedes usarlo en línea en tu código.


Puedes usar el operador en línea `.>`, que es un atajo para `.DBG()`.

Aquí tienes un ejemplo de archivo de código:

```yaml
# file: program.ys

!YS-v0

defn do-it(nums):
  x =: 5

  DBG: -'my vars' x nums

  nums: .map(\(_ * x)).>
        .reverse().>
        .map(str).>
        .join(' - ')

say: do-it(3 .. 5)
```

Cuando ejecutes este código con `ys`, verás el siguiente resultado:

```txt
>>>
"my vars"
5
(3 4 5)
<<<
>>>(15 20 25)<<<
>>>(25 20 15)<<<
>>>("25" "20" "15")<<<
25 - 20 - 15
```


## Compilación

Otra forma habitual de averiguar un problema es mirar el código de Clojure al
que se compila tu código de YS.

Puedes hacerlo ejecutando el intérprete de línea de comandos `ys` con la opción `-c`.

Así se ve el archivo `program.ys` anterior cuando se compila:

```clojure
$ ys -c program.ys
(defn do-it [nums]
 (let [x 5]
  (DBG "my vars" x nums)
  (join
   (DBG
    (+map
     (DBG (reverse (DBG (+map nums (fn [& [_1]] (mul+ _1 x))))))
     str))
   " - ")))
(say (do-it (rng 3 5)))
```

Puedes ver claramente cómo el operador `.>` se compiló a la llamada a la función `DBG`.
