# Acerca de

Es poco probable que te encuentres con mucho código de producción que no haga uso de los espacios de nombres.

Un ejemplo de la sintaxis es:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

Los espacios de nombres son una forma de agrupar código relacionado y de evitar colisiones de nombres.

Según la [documentación oficial][namespaces], los espacios de nombres tienen dos cometidos principales:

- En primer lugar, .NET usa los espacios de nombres para organizar sus muchas clases.
- En segundo lugar, declarar tus propios espacios de nombres puede ayudarte a controlar el scope de los nombres de clases y métodos en proyectos de programación más grandes.

La biblioteca de clases base (BCL) usa ampliamente los espacios de nombres para organizar su funcionalidad.

## Referencias a tipos en espacios de nombres

Se hace referencia a los tipos incluidos en espacios de nombres desde fuera del espacio de nombres anteponiendo al nombre del tipo la sintaxis de punto. Como alternativa, y más habitual, puedes colocar una directiva `using` al principio del archivo (o dentro de un espacio de nombres) y cualquier tipo del espacio de nombres importado se puede usar sin el prefijo. Dentro del mismo espacio de nombres no es necesario calificar los nombres de los tipos.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

Este [artículo][using] explica claramente las formas en que se puede usar la directiva `using`:

- `using`: evita tener que calificar los tipos con el espacio de nombres.
- `using static`: evita tener que calificar los miembros con los tipos (un buen ejemplo es `Math.Max()`).
- `using MyAlias = YourNamespace;`: sustituye el nombre del espacio de nombres por un nombre más legible.

## Colisión de espacios de nombres

.NET aborda el problema de dos espacios de nombres con el mismo nombre en distintos ensamblados, donde se produciría una colisión de nombres de identificadores totalmente calificados (quizás un escenario en el que se cargan varias versiones de un ensamblado). Este problema se aborda con el [calificador de alias de espacio de nombres][namespace-alias-qualifier] y el [alias externo][extern-alias].

Una razón para mencionar este tema bastante específico es su uso del [operador `::`][dot-dot-operator]. A menudo verás el calificador `global::` delante de espacios de nombres, sobre todo en código generado. La intención aquí es evitar una posible colisión con algún espacio de nombres o nombre de clase anidado. Al anteponer `global::` a un espacio de nombres, te aseguras de que se seleccione un espacio de nombres de nivel superior.

## Nota para desarrolladores de Java

Al comparar con el `import` de los `packages` de Java, conviene señalar algunas diferencias y similitudes:

- No hay equivalente en C# a importar tipos específicos.
- `using static` e `import static` son equivalentes.
- En Java, los nombres de paquete influyen en la accesibilidad entre archivos JAR. En C#, los ensamblados son lo fundamental y pertenecer al mismo espacio de nombres no afecta al nivel de acceso.
- La relación entre las rutas del sistema de archivos y los nombres de clase totalmente calificados en Java no se refleja en los espacios de nombres de C#, aunque es buena práctica, cuando sea posible, dar a un archivo el mismo nombre que la clase principal que contiene.
