# Introducción a los condicionales

## Veracidad en Bash

Bash no tiene el concepto de valores booleanos.
Hay strings y números, y arrays de strings o números.
Entonces, ¿cómo se enfrentan los comandos condicionales a lo verdadero y lo falso?

## El estado de salida

Los comandos producen un _estado de salida_ cuando terminan.
Un estado de salida es un número entero entre 0 y 255, ambos incluidos.
Bash considera que un estado de salida **cero** representa el _éxito_.
Cualquier otro estado de salida representa un _fallo_.

Esto se aplica a todos los comandos, incluidos los comandos integrados de bash, las palabras clave y las funciones.

## El comando «if»

La sintaxis básica del comando `if` es

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

Empieza por `if`; los comandos de condición se separan de los comandos de «éxito» mediante `then`; y termina con `fi`.
La cláusula `else` es opcional.

CONDITIONAL_COMMANDS puede ser un solo comando o puede ser una [lista de comandos][command-list].

Se ejecutan los CONDITIONAL_COMMANDS y:

* si el estado de salida es cero (éxito), se ejecutan los TRUE_COMMANDS.
* si el estado de salida no es cero (fallo), se ejecutan los FALSE_COMMANDS, si están presentes.

Se pueden dar ramas en cascada con `elif`

```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

Tiene que haber un punto y coma o un salto de línea antes de las palabras `then`, `elif`, `else` y `fi`.

Para recalcarlo: es el **estado de salida** de los comandos condicionales lo que controla el flujo.
Por ejemplo, `grep` devuelve 0 si encuentra una coincidencia, y 1 si no la encuentra.
La opción `-q` suprime la salida y solo produce el estado de salida.

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## Los comandos «[» y «test»

No hay ninguna sintaxis especial en torno a los CONDITIONAL_COMMANDS.
Puede que estés acostumbrado a ver instrucciones if con este aspecto:

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

`[` no es una sintaxis especial.
Es un _comando_ que evalúa la expresión condicional y termina con un estado de éxito o de fallo.
Como en todos los comandos, se **requiere** espacio en blanco entre él y sus argumentos.

En realidad, `[` es un sinónimo del comando `test`.
Son exactamente lo mismo, salvo que el último argumento de `[` _tiene_ que ser `]`.

### Expresiones condicionales

Dentro de `[` y `]`, escribes una expresión condicional.
Algunas expresiones condicionales típicas son:

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

Hay muchas más operaciones disponibles; aparecen en la sección [Expresiones condicionales de Bash][cond-expr] del manual.

~~~~exercism/note
En los ejemplos anteriores, fíjate en que todas las variables están entre comillas.
Los comandos `test` y `[` son comandos normales, en los que los argumentos están sujetos a la división de palabras y a la expansión de nombres de fichero como en cualquier otro comando.

Es importante señalarlo porque las expresiones condicionales se evalúan de forma distinta según _cuántos argumentos_ proporciones:

* 0 argumentos: el estado de salida no es cero (fallo)
* 1 argumento: el estado de salida es cero (éxito) si el argumento no está vacío, y distinto de cero si está vacío.
* 2 argumentos: el primer argumento tiene que ser un operador unario (como `[ -z "$name" ]`) o un `!` (que niega el estado de la prueba de 1 argumento)
* y [más][test].

Puedes obtener resultados inesperados si olvidas poner las comillas:

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## La palabra clave «[[»

La [construcción condicional `[[...]]`][cond-construct] no es un _comando_, es una **palabra clave**.
Esto significa que, aunque se maneja como cualquier otro comando, tiene reglas de análisis sintáctico especiales.
Lo especial de `[[` es que las variables que se expanden dentro de él **no** están sujetas a la división de palabras ni a la expansión de nombres de fichero.
Eso significa que este comando se comporta como esperas, incluso sin comillas.

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

`[[` admite todas las expresiones condicionales que pueden manejar `test` y `[`.
Además, `[[` ofrece

* el operador de coincidencia de expresiones regulares `=~`,
* `==` y `!=`, que funcionan como operadores de coincidencia de patrones glob,
* `&&` y `||` como operadores lógicos (regla de análisis sintáctico especial),
* `<` y `>` como operadores de comparación de strings «desnudos» (regla de análisis sintáctico especial: como son símbolos de redirección, en `[` tienen que ir escapados).

Se considera ampliamente que estas características especiales ofrecen tantas ventajas que debería usarse `[[` de forma exclusiva.
(Por ejemplo, la [guía de estilo de shell de Google][goog-test].)

## El comando «case»

[`case`][case] es otro comando de control de flujo.
Es como una instrucción «switch» en otros lenguajes.

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

La WORD se compara con cada PATTERN.
Cuando uno coincide, se ejecutan los COMMANDS.

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

Cada cláusula COMMANDS tiene que terminar con **dos** puntos y comas, `;;`.
