# Acerca de

Un *heap* es una colección que siempre conoce su elemento más pequeño (o más grande) y te permite eliminarlo rápidamente: es la implementación natural de una *cola de prioridad*. Los heaps viven en el vocabulario [`heaps`][heaps].

`<min-heap>` construye un heap vacío cuya clave más pequeña sale primero; `<max-heap>` devuelve primero la más grande. Cada elemento es un *valor* almacenado bajo una *clave*, y la clave es la prioridad por la que Factor ordena:

```
<min-heap> ( -- min-heap )
<max-heap> ( -- max-heap )
heap-push  ( value key heap -- )
heap-push-all ( assoc heap -- )
```

```factor
USING: heaps ;

<min-heap>
"alice" 5 pick heap-push
"bob"   2 pick heap-push
```

Un heap es *mutable*: `heap-push` y `heap-pop` lo modifican en el propio heap.

```
heap-peek    ( heap -- value key )
heap-pop     ( heap -- value key )
heap-pop-all ( heap -- alist )
heap-empty?  ( heap -- ? )
heap-size    ( heap -- n )
```

`heap-peek` lee el elemento frontal sin eliminarlo; `heap-pop` lo elimina y lo devuelve; `heap-pop-all` vacía el heap en una lista de asociaciones de pares `{ key value }` en orden de prioridad.

```factor
USING: assocs heaps kernel prettyprint ;

<min-heap>
"alice" 5 pick heap-push
"bob"   2 pick heap-push
"carol" 9 pick heap-push
dup heap-pop .           ! => 2 "bob"   (removed; value then key)
heap-pop-all values .    ! => { "alice" "carol" }
```

Insertar es `O(log n)` y leer el elemento frontal es `O(1)`, así que repetir «toma el elemento más urgente y luego añade más» sigue siendo rápido incluso con una cola grande. La implementación es un heap binario almacenado en un array ampliable; la clave puede ser cualquier valor ordenable (números, strings, …).

[heaps]: https://docs.factorcode.org/content/vocab-heaps.html
