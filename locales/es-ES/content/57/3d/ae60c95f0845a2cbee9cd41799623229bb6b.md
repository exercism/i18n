# Introducción

Una declaración `GENERIC:` crea una palabra cuyo comportamiento depende
de la *clase* de uno de sus argumentos. El comportamiento concreto procede
de los *métodos*, definidos con `M:`.

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

Cuando se llama a `area`, Factor inspecciona la parte superior de la pila,
busca el método más específico cuya clase coincida y lo ejecuta. Con
variables locales puedes usar `M::`:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

Los genéricos te permiten añadir nuevas representaciones más adelante sin
cambiar el código que llama: `area` ya funcionaba para `square` y `circle`,
y el método de `rectangle` se detecta automáticamente allí donde se llama
a `area`.

## Cuándo un genérico es la elección adecuada

Recurre a `GENERIC:` cuando:

- Una misma operación tiene implementaciones *realmente distintas*
  para entradas diferentes.
- Esperas que código futuro añada tipos nuevos.
- Quieres que el sistema de tipos imponga definiciones por clase.

Si la variación no es más que una pequeña enumeración de etiquetas, un
`case` es más sencillo.

## Unirse a un mixin con `INSTANCE:`

Un *mixin* es una clase genérica que está *abierta*: cualquiera puede
registrar una clase nueva como miembro. Muchos de los protocolos
integrados de Factor (secuencias, conjuntos, flujos, …) se exponen como
mixins, de modo que una tupla personalizada puede acogerse a los métodos
predeterminados del protocolo declarándose como instancia:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

Después de `INSTANCE:`, todos los métodos predeterminados `M: shape …`
despachan automáticamente sobre `my-shape`, y cualquier código que pida
una `shape` acepta una `my-shape`. `M:` sirve para añadir métodos a un
genérico; `INSTANCE:` sirve para unir una clase a un mixin.

## `TYPED::`: entradas comprobadas para una palabra normal

`GENERIC:`/`M:` eligen un método según la clase de un argumento. A veces
no quieres despacho, sino *una* palabra que exija que sus entradas sean de
una clase determinada. `TYPED::` (en el vocabulario `typed`) es `::` con
una clase escrita después de cada nombre de entrada:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

`n: integer` se lee como las variables locales que ya usas, con la clase
escrita después de los dos puntos. No hay despacho (una definición, un
comportamiento), pero ahora cada argumento se comprueba contra su clase:
un desajuste como `"x" triple` se rechaza
(*expected input value of type integer but got string*) en lugar de colarse
silenciosamente.

La salida se puede anotar de la misma forma. `yes?` declara el tipo tanto
de su entrada como de su resultado:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## Funciones y constantes matemáticas

Este ejercicio también se apoya en algunas palabras de `math.constants`
y `math.functions` que conocerás aquí por primera vez:

- `pi`: la constante π, de `math.constants`.
- `sin ( x -- y )`, `cos ( x -- y )`: seno y coseno de un ángulo en
  radianes.
- `e^ ( x -- y )`: `e` elevado a la potencia `x`. (Para una base
  arbitraria, usa `^`.)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
