# ভূমিকা

Factor-এ আপনি ওয়ার্ডগুলোকে শুধু একটির পর একটি লিখেই জোড়া লাগান; আপনি যে ক্রমে সেগুলো লেখেন, *সেই ক্রমেই* সেগুলো যুক্ত হয়। (প্রোগ্রামাররা এটাকে *ফাংশন কম্পোজিশন* বলে।) একটি ওয়ার্ডের বডি নিজেই একগুচ্ছ ওয়ার্ডের একটি সিকোয়েন্স: প্রতিটি ওয়ার্ড স্ট্যাক থেকে কিছু মান নিয়ে নিজের ফলাফল পুশ করে, আর পরের ওয়ার্ডটি ঠিক যেখান থেকে আগেরটি থেমেছিল সেখান থেকেই শুরু করে। তাই

```factor
! DOCTEST: SKIP   (cleanupname is hypothetical here — the exercise's job)
: firstletter ( name -- letter ) cleanupname first 1string ;
```

লিখলেই সেটা *আসলে* `cleanupname`, `first` এবং `1string`-এর কম্পোজিশন।

এই অনুশীলনীতে **কোয়োটেশন**-ও পরিচয় করিয়ে দেওয়া হয়েছে: কোডের এমন একটি টুকরো, যা আপনি একটি মান হিসেবে রেখে পরে চালাতে পারেন, সঙ্গে সঙ্গে চালানোর বদলে।

## কোয়োটেশন

একটি কোয়োটেশন হলো তৃতীয় বন্ধনীর ভেতরে মোড়া কোডের একটি টুকরো। লেখার সময় এটি চলে না; বরং স্ট্যাকে একটি মান হিসেবে বসে থাকে:

```factor
[ 2 * ] .       ! => [ 2 * ]
```

`call` একটি কোয়োটেশন চালায়:

```factor
3 [ 2 * ] call .    ! => 6
```

আপনি কোয়োটেশন লেখেন তখন, যখন কোডকে ডেটা হিসেবে পাঠাতে হয়: হয় পরে চালানোর জন্য, নয়তো কোনো *কম্বিনেটর*-এর কাছে পাঠানোর জন্য। কম্বিনেটর হলো এমন একটি ওয়ার্ড, যা ইনপুট হিসেবে একটি কোয়োটেশন নেয়।

## `compose`

`compose ( quot1 quot2 -- combined )` দুটি কোয়োটেশনকে জোড়া লাগিয়ে একটি বানায়, আর লেখার ক্রমেই সেগুলো চালায়:

```factor
[ 2 * ] [ 1 + ] compose .    ! => [ 2 * 1 + ]
```

সাধারণত দেখবেন, `:` ... `;` দিয়ে একটি ছোট ওয়ার্ড ডিফাইন করলে সেটা `compose`-এর চেয়ে ভালো পড়া যায়; তবে তাৎক্ষণিকভাবে কোয়োটেশন বানাতে হলে `compose` কাজে লাগে। যখন গড়ে তোলার উপকরণগুলো আগে থেকেই কোয়োটেশন নয়, তখন [`quotations`][quotations] থেকে আসা `>quotation ( seq -- quot )` মান ও ওয়ার্ড-রেফারেন্সের একটি সিকোয়েন্সকে কল করার মতো কোয়োটেশনে বদলে দেয়:

```factor
USING: quotations sequences ;

{ [ 1 ] [ 2 + ] [ 3 * ] } concat >quotation call .   ! => 9
```

## একটি কোয়োটেশন দুটি ইনপুটে প্রয়োগ করা

`bi@ ( x y quot -- ... )` কোয়োটেশনটি `x`-এর ওপর চালায়, তারপর আবার `y`-এর ওপরও, আর দুটি ফলাফলই স্ট্যাকে রেখে দেয়:

```factor
3 4 [ 2 * ] bi@ .s
! => 6
! => 8
```

এই অনুশীলনীর `couple` টাস্কটি দুটি নাম নেয়; প্রতিটির ওপর `initial` প্রয়োগ করার স্বাভাবিক উপায় হলো `bi@`।

## কয়েকটি স্ট্রিং ওয়ার্ড

এই অনুশীলনীর জন্য দরকার কয়েকটি ছোট স্ট্রিং ওয়ার্ড, যা তিনটি ভোকাবুলারি থেকে নেওয়া: [`sequences`][sequences], [`ascii`][ascii] এবং [`strings`][strings]:

- `replace ( seq old new -- new-seq )` (`splitting`-এ): সাবস্ট্রিং বদলে দেওয়া।
- `[ blank? ] trim` (`sequences`-এ `trim`, `ascii`-এ `blank?`): শুরু ও শেষের হোয়াইটস্পেস বাদ দেয়।
- `1string ( char -- str )` (`strings`-এ): একটি ক্যারেক্টারকে স্ট্রিং হিসেবে মোড়ায়।
- `>upper ( str -- upper )` (`ascii`-এ): একটি স্ট্রিংকে বড় হাতের অক্ষরে বদলায়।
- `append ( s1 s2 -- s )` (`sequences`-এ): দুটি স্ট্রিং জোড়া লাগায়।
- `prepend ( s1 s2 -- s )` (`sequences`-এ): `s2` তারপর `s1` জোড়া লাগায় (`append`-এর ইনপুট দুটো উল্টো ক্রমে দেওয়া)।
- `glue ( s1 s2 sep -- s )` (`sequences`-এ): মাঝখানে একটি সেপারেটর দিয়ে দুটি স্ট্রিং জোড়া লাগায়।
- `surround ( seq pre post -- new )` (`sequences`-এ): একটি প্রিফিক্স ও একটি সাফিক্স দিয়ে স্ট্রিং মোড়ায়।

ইউনিকোড ক্যারেক্টার একটি স্ট্রিংয়ের ভেতরে `\u{XXXX}` আকারে লেখা যায়, যেখানে `XXXX` হলো হেক্সে লেখা কোডপয়েন্ট। এই অনুশীলনীতে হৃদয়চিহ্ন `\u{2764}` (❤) দেখা যায়।

## ফরম্যাট করা আউটপুট

যখন `append`/`glue`/`surround` যথেষ্ট প্রকাশভঙ্গি দিতে পারে না, তখন [`formatting`][formatting] printf-ধাঁচের `sprintf` দেয়:

```
sprintf ( inputs... format-string -- str )
```

`%s` একটি স্ট্রিং বসায়, `%d` একটি ইন্টিজার, `%f` একটি ফ্লোট; ঐচ্ছিক উইডথ, প্রিসিশন ও প্যাডিং মডিফায়ার `%` আর টাইপ অক্ষরের মাঝখানে আসে:

```factor
USING: formatting ;

"Alice" "Bob" "%s & %s" sprintf .   ! => "Alice & Bob"
3.14159 "%.2f" sprintf .             ! => "3.14"
42 "%05d" sprintf .                  ! => "00042"
```

সংখ্যা ও স্ট্রিংয়ের মধ্যে দুইমুখী রূপান্তরের জন্য [`math.parser`][math.parser]-এ আছে `number>string` ও `string>number`:

```factor
USING: math.parser ;

42 number>string .       ! => "42"
"3.14" string>number .   ! => 3.14
```
