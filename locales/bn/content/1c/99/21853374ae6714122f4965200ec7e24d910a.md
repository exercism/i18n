# সম্পর্কে

[`interfaces`][interfaces] হলো একটি ক্লাসের ব্যবহারকে তার ইমপ্লিমেন্টেশন থেকে [ডিকাপলিং][wiki-loose-coupling] করার প্রধান উপায়। এই ডিকাপলিং ইমপ্লিমেন্টেশন রক্ষণাবেক্ষণে নমনীয়তা আনে এবং টাইপ-সেফ জেনেরিক বিহেভিয়ার সমর্থনে সাহায্য করে।

একটি ইন্টারফেসের সিনট্যাক্স ক্লাস বা স্ট্রাক্টের সিনট্যাক্সের মতোই, শুধু পার্থক্য এই যে এখানে মেথড ও প্রপার্টি শুধু সিগনেচার হিসেবে থাকে, কোনো বডি দেওয়া হয় না।

```csharp
public interface ILanguage
{
    string Speak();
}

public interface IItalianLanguage : ILanguage
{
    string Speak();
    string SpeakItalian();
}

public interface IScriptConverter
{
    string Version { get; set; }
    string ConvertCyrillicToLatin(string cyrillic);
}
```

ইন্টারফেসটি যে ক্লাস বা স্ট্রাক্ট ইমপ্লিমেন্ট করে, তাকে ইন্টারফেসে ডিফাইন করা সব অপারেশন ইমপ্লিমেন্ট করতে হবে।

ইন্টারফেস সাধারণত নিচের এক বা একাধিক কাজ করে:

- ব্যবহারকারী কোডকে একাধিক ভিন্ন ক্লাসকে জেনেরিকভাবে ব্যবহার করার সুযোগ দেয়। এক্ষেত্রে ইন্টারফেস একটি বেস ক্লাসের মতোই ভূমিকা পালন করে
- কোনো নির্দিষ্ট উদ্দেশ্যে ফাংশনালিটির একটি উপসেট প্রকাশ করে (যেমন [`IComparable<T>`][icomparable]) অথবা
- একটি ক্লাসের পাবলিক API প্রকাশ করে, যাতে একাধিক ইমপ্লিমেন্টেশন পাশাপাশি থাকতে পারে। এর একটি উদাহরণ হলো [টেস্ট ডাবল][wiki-test-double]

```csharp
public class ItalianTraveller : IItalianLanguage
{
    public string Speak()
    {
        return "Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class ItalianTravellerV2 : IItalianLanguage
{
    public string Speak()
    {
        return "migliorata - Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class FrenchTraveller : ILanguage
{
    public string Speak()
    {
        return "Ça va?";
    }
}

public class RussianTraveller : ILanguage, IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Speak()
    {
        return "Привет мир";
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}

public class DocumentTranslator : IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Translate(string russian)
    {
        throw new NotImplementedException();
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}
```

উপরের ইন্টারফেস ও ক্লাসগুলো ব্যবহার করা কোড যা করতে পারে:

- ভাষা নির্বিশেষে সব স্পিকারকে একইভাবে ব্যবহার করতে পারে।
- স্ক্রিপ্ট কনভার্সন সামলানো কোনো সাবসিস্টেমকে, সে কোন নির্দিষ্ট টাইপ নিয়ে কাজ করছে তা গ্রাহ্য না করেই চলতে দেয়।
- ইতালিয়ান স্পিকারে করা পরিবর্তন সম্পর্কে উদাসীন থাকতে পারে, যা সুবিধাজনক যদি ক্লাসের কোড ও ব্যবহারকারীর কোড ভিন্ন ভিন্ন টিম রক্ষণাবেক্ষণ করে

টেস্টিং সমর্থন করতে ইন্টারফেস ব্যাপকভাবে ব্যবহৃত হয়, কারণ এগুলো সহজে [মকিং][so-mocking-interfaces] করার সুযোগ দেয়।

একটি ইন্টারফেসে কী কী ধরনের মেম্বার রাখা যায় তার বিস্তারিত জানতে এই [লেখাটি][dt-interfaces] দেখুন।

ইন্টারফেস অন্য ইন্টারফেস থেকে ইনহেরিট করতে পারে।

ইন্টারফেসের মেম্বারগুলো ডিফল্টভাবে পাবলিক থাকে।

ইন্টারফেসে নেস্টেড টাইপ থাকতে পারে, যেমন `const` লিটারেল, `enums`, `delegates`, `classes` ও `structs`. এখানে ইন্টারফেসগুলোও ক্লাস ও স্ট্রাক্টের মতোই [নেইমস্পেস][wiki-namespaces] হিসেবে কাজ করে, আর বিহেভিয়ার ও সিনট্যাক্স একেবারে অভিন্ন।

ডিজাইনের দিক থেকেই C# মাল্টিপল ইনহেরিটেন্স সমর্থন করে না, তবে ইন্টারফেসের মাধ্যমে এক ধরনের মাল্টিপল ইনহেরিটেন্স সম্ভব করে তোলে।

তাছাড়া, [ইন্টারফেসের মাধ্যমে পলিমরফিজম প্রয়োগ করা যায়][interface-polymorphism] এই ধারণাটিই ইন্টারফেস ব্যবস্থার মূল ভিত্তি।

## এক্সপ্লিসিট ইন্টারফেস ইমপ্লিমেন্টেশন

কখনও কখনও দুটি ভিন্ন ইন্টারফেসে একই মেথডের নাম ও সিগনেচার থাকতে পারে।
এই মেথডগুলোর আলাদা ইমপ্লিমেন্টেশন দেওয়ার জন্য C# [ইন্টারফেসের এক্সপ্লিসিট ইমপ্লিমেন্টেশন][explicit-implementation] সুবিধা দেয়। মনে রাখবেন, একটি ইন্টারফেসের কোনো নির্দিষ্ট ইমপ্লিমেন্টেশন ব্যবহার করতে হলে অবজেক্টটিকে রেফারেন্স করা এক্সপ্রেশনটিকে সেই ইন্টারফেসে কনভার্ট করতে হবে। অ্যাসাইনমেন্ট, কাস্টিং বা প্যারামিটার হিসেবে পাস করার মাধ্যমে এটা করা যায়।

```csharp
public interface IFoo
{
    void X();
}

public interface IBar
{
    void X();
}

public class Census : IFoo, IBar
{
    void IFoo.X()
    {
        Console.Write("This is from Foo");
    }

    void IBar.X()
    {
        Console.Write("This is from Bar");
    }
}

public class User
{
    public void Use()
    {
        IFoo foo = new Census();
        IBar bar = new Census();
        foo.X();
        // => "This is from Foo"
        bar.X();
        // => "This is from Bar"
    }
}
```

এর বেশ কয়েকটি ব্যবহারের ক্ষেত্র আছে:

- ডোমেইনের সংঘর্ষ (উপরের উদাহরণে যেমন), যেখানে মেথডগুলোর সিগনেচার হুবহু এক।
- একই নাম কিন্তু ভিন্ন রিটার্ন টাইপের মেথড: নিজের কালেকশন ক্লাস বানালে দেখবেন পুরোনো `IEnumerable.GetEnumerator()`-এর জন্য `IEnumerable<T>.GetEnuerator()`-এর পাশাপাশি একটি এক্সপ্লিসিট ইন্টারফেস দরকার হতে পারে। আপনি হয়তো ওই ইন্টারফেস কখনোই ব্যবহার করবেন না, কিন্তু কম্পাইলার তা জোর করে চাইতে পারে।
- যেসব মেথডের ক্ষেত্রে ইন্টারফেসগুলোর মধ্যে নামের কোনো সংঘর্ষ নেই, কিন্তু ইমপ্লিমেন্ট করা ক্লাসের জন্য সম্পর্কিত কোনো কাজে সেই নামটি ব্যবহার করা বাঞ্ছনীয়: `IFormattable`-এ একটি `ToString()` মেথড আছে, যা একটি _format type_ প্যারামিটার এবং `IFormatProvider` টাইপের একটি প্যারামিটার নেয়। Base Class Library (BCL)-এর `FormattableString`-এর মতো ক্লাসে ওই ইন্টারফেসটি থাকে যাতে `IFormattable` নেয় এমন রুটিন থেকে এটি ব্যবহার করা যায়, কিন্তু এর মূল `ToString(IFormatProvider)` সংস্করণ থেকে _format type_ প্যারামিটারটি বাদ দেওয়াই বেশি অর্থবহ, কারণ ইমপ্লিমেন্টেশনে এটি ব্যবহৃত হয় না এবং এতে API ব্যবহারকারীরা বিভ্রান্ত হতেন।

## ডিফল্ট ইমপ্লিমেন্টেশন

C#-এর ৮ নম্বর সংস্করণ API-সংক্রান্ত একটি পুরোনো সমস্যার সমাধান করে। নতুন ইমপ্লিমেন্টেশনের জন্য ফাংশনালিটি বাড়াতে আপনি যদি একটি ইন্টারফেসে মেথড যোগ করেন, তবে ইন্টারফেসটির সব বিদ্যমান ইমপ্লিমেন্টেশন বদলাতে হয় যাতে সেগুলো API-চুক্তি মেনে চলে, যদিও তাদের নিজস্ব কোনো বিশেষ বিহেভিয়ার নেই। এখন C# ইন্টারফেসের অংশ হিসেবে একটি _default method_ রাখার সুযোগ দেয় (Java ডেভেলপারদের কাছে এটি চেনা)। আগে এমন পরিবর্তন হলে ইন্টারফেসটির একটি _version 2_ মূলটির পাশাপাশি থাকত।

এই [লেখাটি][dt-interfaces] ইন্টারফেস নিয়ে একটি দুর্দান্ত প্রাইমার, যা _default implementation_ এবং `static`, `private` ও `virtual` মেম্বারের মতো অন্যান্য সহায়ক নতুন সংযোজন নিয়ে আলোচনা করে।
