# সম্পর্কে

কমন লিস্প প্রোগ্রামারকে কয়েকটি ভিন্ন কন্ডিশনাল দেয়, যেগুলোকে তারা কতগুলো "শাখা" সমর্থন করে সেই সংখ্যা অনুযায়ী ভাগ করা যায়।

এছাড়াও, অন্য অনেক প্রোগ্রামিং ভাষার মতো নয়, Common Lisp-এ সব কন্ডিশনালই স্টেটমেন্ট নয়, _এক্সপ্রেশন_।

এর মানে, Lisp-এর সব কন্ডিশনালের ফলাফলই একটি মান, এবং এগুলোকে সরাসরি প্যারামিটার হিসেবে বসানো যায়।

একটি উদাহরণ:

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## এক শাখার কন্ডিশনাল

`when` আর `unless` কন্ডিশনাল কেবল তখনই কিছু কোড মূল্যায়ন করে, যখন দেওয়া টেস্টটি যথাক্রমে ট্রু বা ফলস হয়, নাহলে এর ফলাফল হয় `nil`।

টেস্ট এক্সপ্রেশনের পরের অংশে একাধিক এক্সপ্রেশন থাকতে পারে।

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## দুই শাখার কন্ডিশনাল

`if` কন্ডিশনাল টেস্ট ট্রু হলে বডির প্রথম এক্সপ্রেশনটি মূল্যায়ন করে, আর নাহলে দ্বিতীয়টি।

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

মনে রাখবেন, then আর else দুটি ক্লজই কেবল একটি করে এক্সপ্রেশন হতে পারে।

## বহু শাখার কন্ডিশনাল

Lisp-এর "সুপার-কন্ডিশনাল" হলো `cond`, যাতে অসংখ্য শাখা থাকতে পারে।
প্রতিটি শাখায় একটি টেস্ট শর্ত আর একটি বডি এক্সপ্রেশন থাকে, যেগুলোকে একটি অতিরিক্ত বন্ধনী জোড়া দিয়ে ঘেরা হয়।
সব টেস্ট যদি ফলস হয়, তাহলে `nil` রিটার্ন করা হয়।

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

মনে রাখবেন, টেস্ট এক্সপ্রেশনের পরে এক্সপ্রেশনের সংখ্যার কোনো সীমা নেই।


আপনি যদি কেবল একটি মানকে কয়েকটি শাখার সাথে মিলিয়ে দেখতে চান, তাহলে আরও পরিচ্ছন্ন `case` এক্সপ্রেশনটি ব্যবহার করতে পারেন।
কোনো কেস না মিললে `nil` রিটার্ন করা হয়।
`t` আর `otherwise` দুটোই সব কিছু ধরে ফেলার কেস হিসেবে ব্যবহার করা যায়:

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

মনে রাখবেন, `cond`-এর মতোই টেস্ট এক্সপ্রেশনের পরে এক্সপ্রেশনের সংখ্যার কোনো সীমা নেই।

## ছদ্মবেশী কন্ডিশনাল

Common Lisp-এ বুলিয়ান `and` আর `or` অপারেশনগুলো শর্ট-সার্কিটিং ম্যাক্রো, যেগুলো দিয়ে কিছু কিছু কন্ডিশনাল এক্সপ্রেশনের পুনরাবৃত্তি কমানো যায়।

`and` ম্যাক্রো একটি মাত্র ফলস মান পেলেই সঙ্গে সঙ্গে `nil` রিটার্ন করে, নাহলে `and`-এর শেষ ট্রু মানটি রিটার্ন করে:

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

`or` ম্যাক্রো তার সামনে পড়া প্রথম ট্রু মানটি রিটার্ন করে, আর কোনো ট্রু মান না থাকলে `nil` রিটার্ন করে:

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## আমি তো ক্লান্ত...

আগেই বলা হয়েছে, `case` স্টেটমেন্টের কোনো শাখাই না মিললে এবং `otherwise` ক্লজ না থাকলে `nil` রিটার্ন করা হয়।
তবে মাঝে মাঝে কোনো শাখার সাথে না মেলাকে একটি এরর হিসেবে ধরা উচিত। এখানেই আসে `ecase` (**exhaustive** মেলানোর জন্য)।

এটি `case`-এর মতোই ব্যবহার করা হয়, তবে কোনো মিল না পেলে `nil` রিটার্ন করার বদলে একটি এরর সিগন্যাল করে।

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
