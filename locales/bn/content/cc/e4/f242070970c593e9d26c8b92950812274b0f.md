# পরিচিতি

প্রোগ্রামিং অনুশীলনীটি প্যারামিটারগুলোর বেশ কিছু বৈশিষ্ট্য তুলে ধরে:

- মডিফায়ার (যেমন `out` বা `ref`) ছাড়া [পাস করা][passing-parameters] প্যারামিটার মান হিসেবে পাস হয়। অর্থাৎ, কল করা মেথডে প্যারামিটারটি ব্যবহার করা যায় এবং তাতে অ্যাসাইন করা যায়, কিন্তু কোনো পরিবর্তনই কলারের ওপর কোনো প্রভাব ফেলে না।
- কোনো অ্যারে বা ক্লাসের ইনস্ট্যান্সের রেফারেন্স যখন প্যারামিটার হিসেবে আসে, তখন কল করা মেথড সেই ইনস্ট্যান্সের এলিমেন্ট/ফিল্ডগুলো পরিবর্তন করতে পারে এবং কলার সেই পরিবর্তনগুলো দেখতে পায়। `ref` মডিফায়ার আছে কি নেই, তাতে এখানে কোনো পার্থক্য হয় না।
- [`out`][out-parameter] মডিফায়ারযুক্ত একটি প্যারামিটার কল করা মেথড থেকে কলারের কাছে একটি মান ফিরিয়ে আনে। প্যারামিটারটি ইনিশিয়ালাইজ না করেই কল করা মেথডে পাস করা যায়, আর যেভাবেই হোক, মেথডের ভেতরে এটিকে এমনভাবে দেখা হয় যেন ভেতরে ঢোঁয়ার সময় এটি ইনিশিয়ালাইজ করা ছিল না। প্যারামিটার মডিফায়ার সংক্রান্ত আচরণ ও নিয়মগুলো সবচেয়ে সহজে বোঝা যায় উদাহরণ (নিচে দেখুন) আর কম্পাইলারের মেসেজের মাধ্যমে।

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- কল করা মেথডের ভেতরে `out` প্যারামিটারে অবশ্যই অ্যাসাইন করতে হবে।

- [`ref`][ref-parameter] মডিফায়ারযুক্ত একটি প্যারামিটার একটি মান কল করা মেথডের ভেতরে পাঠায়। মেথডটি রিটার্ন করলে কলার দেখতে পাবে, কল করা মেথড ওই প্যারামিটারে যা যা পরিবর্তন করেছে তা সবই সেখানে আছে।

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

-`ref` প্যারামিটার অবশ্যই ভ্যারিয়েবল হতে হবে, কারণ কল করা মেথড কলারের দেখা প্যারামিটারটির ওপরই সরাসরি কাজ করবে।

- `out` আর `ref` মডিফায়ার দুটোই দরকার, কল করা মেথডের সিগনেচারে এবং কল সাইটে।
- `out` প্যারামিটার কল সাইটেই ইনলাইন ডিক্লেয়ার করা যায়, যেমন: `Foo(out int importantValue);`
- আপনি যদি এমন কোনো মেথড কল করেন যেটিতে `out` প্যারামিটার আছে, কিন্তু তার এক বা একাধিকটিতে অ্যাসাইন করা মান নিয়ে আপনার আগ্রহ নেই, তাহলে [discard][discard] ডামি ভ্যারিয়েবল `_` ব্যবহার করতে পারেন, যেমন: `Foo(out int _);`

`ref` আর `out` প্যারামিটার সংক্রান্ত সব নিয়মই কম্পাইলার কার্যকর করে।

[`in`][in-parameter] প্যারামিটারও আছে, তবে সেগুলো মূলত পারফরম্যান্স অপ্টিমাইজেশনের জন্য, আর এদের নিয়ে আলোচনা করা হয়েছে `structs` অনুশীলনীতে, যেখানে এরা সবচেয়ে প্রাসঙ্গিক।

উপরে লিংক করা ডকুমেন্টেশনটির সারসংক্ষেপ নিচে দেওয়া হলো:

- [প্যারামিটার পাস করা][passing-parameters]: ব্যাখ্যা করে কীভাবে মান আর্গুমেন্ট হিসেবে পাস করা যায়। মনে রাখবেন, স্ট্রাক্ট + প্যারামিটার নিয়ে আলোচনা আছে `structs` অনুশীলনীতে।
- [ref প্যারামিটার][ref-parameter]: ব্যাখ্যা করে `ref` প্যারামিটার কীভাবে কাজ করে।
- [out প্যারামিটার][out-parameter]: ব্যাখ্যা করে `out` প্যারামিটার কীভাবে কাজ করে।

ডকুমেন্টেশনটি পড়ার সময় মনে রাখবেন, এতে নিচের পরিভাষাগুলো ব্যবহার করা হয়েছে:

- প্যারামিটার / ফরমাল প্যারামিটার: কল করা মেথড যে প্যারামিটারটি দেখে, সেটিকেই বোঝায়।
- আর্গুমেন্ট: কলার যে প্যারামিটারটি দেখে, সেটিকেই বোঝায়।

[তর্কসাপেক্ষে][so-tuples-vs-out] C# 7-এ `tuples` আসার পর `out` প্যারামিটারের অনেক উপযোগিতাই আর নেই। `tuples` অনুশীলনীতে দেখানো হয়েছে কীভাবে `tuples` দিয়ে একাধিক মান রিটার্ন করা যায়।

`ref` ব্যবহার করা সহজ আর এতে পারফরম্যান্সের কোনো ক্ষতিও নেই, তবুও ব্যাপকভাবে ব্যবহার করার আগে দেখে নেওয়া ভালো, নির্দিষ্ট কোনো কোড বেসে যে সমস্যাগুলোর সমাধানে এটি ব্যবহার করা হয় সেগুলো সেখানে কীভাবে মোকাবেলা করা হয়েছে। বিকল্প পথও আছে, যেমন মান হিসেবে পাস করা আর কল করা মেথডের রিটার্ন স্টেটমেন্ট থেকে মানটি নিয়ে নেওয়া। এখানেও `tuples` ভূমিকা রাখতে পারে।

[ডকুমেন্টেশন][ref-parameter] থেকে দেখতে পাবেন, কিছু কিছু পরিস্থিতিতে `out` আর `ref` ব্যবহার করা যায় না, তবে আপাতত সেগুলো এড়িয়ে যেতে পারেন। এমন পরিস্থিতি দেখা দিলে কম্পাইলার আপনাকে জানিয়ে দেবে।

মনে রাখবেন, `optional parameters` আর `named arguments` নিয়ে আলোচনা আছে `method-overloading` অনুশীলনীতে।

[`ref local`][ref-local] আর [`ref return`][ref-return] সংক্রান্ত বিষয়গুলো নিয়ে আলোচনা আছে অন্যত্র।

## স্ট্যাক অ্যালোকেশন

প্যারামিটার আর তাদের মডিফায়ার সংক্রান্ত নিয়মগুলো যথেষ্ট সহজ, তাই এগুলোকে যেমন আছে তেমনভাবেই মেনে নিয়ে তাদের বিমূর্ততার স্তরেই বুঝে নিতে পারেন। তবে অন্তর্নিহিত কার্যপ্রণালী নিয়ে, আর কেন এই কিওয়ার্ডগুলো পারফরম্যান্সে পার্থক্য গড়ে দিতে পারে, অন্তত `struct`-এর ক্ষেত্রে, যদি আপনার আগ্রহ থাকে, তাহলে শুরু করতে পারেন এই [_উইকিপিডিয়া নিবন্ধটি_][calling-conventions] দিয়ে; মনে রাখবেন, x86/64-এ C# `stdcall` ব্যবহার করে।

মূল কথা হলো, মডিফায়ারহীন প্যারামিটারের ক্ষেত্রে একটি ভ্যারিয়েবলের **মান** প্রোগ্রামের স্ট্যাকে কপি করা হয়, যাতে কল করা রুটিন সেটি পায়; অন্যদিকে `ref`, `out` আর `in` প্যারামিটারের ক্ষেত্রে মানটি যে মেমরিতে আছে তার একটি পয়েন্টার (**রেফারেন্স**) প্রোগ্রামের স্ট্যাকে রাখা হয়, আর মান অ্যাসাইন করা হয় রেফারেন্সটি যে মেমরির দিকে দেখাচ্ছে সেখানে।
