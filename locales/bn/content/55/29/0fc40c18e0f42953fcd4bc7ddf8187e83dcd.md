# পরিচিতি

## উপস্থাপন, ক্যারেক্টার আর ইন্টিজার

অন্য সাধারণ টাইপগুলোর (`int`, `bool` ইত্যাদি) মতোই `char`-এরও একটি সঙ্গী বা অ্যালিয়াস টাইপ আছে, এক্ষেত্রে সেটি `System.Char`।

আসলে এটি একটি `struct`, যার একটি ১৬ বিটের ফিল্ড আছে, এবং ডিফল্টভাবে এটি ইমিউটেবল।

`char`-এর `Equals`, `ToString` আর [`CompareTo`][compare-to]-এর মতো কিছু ইনস্ট্যান্স মেথড আছে।

`char`-এর প্রস্থ [`ushort`][uint16]-এর সমান, কিন্তু কিছু ভাষায় যেভাবে হয়, সেভাবে সাধারণত এদের একে অন্যের বদলে ব্যবহার করা হয় না। `ushort`-কে স্পষ্টভাবে একটি `char`-এ কাস্ট করতে হয়।

যাই হোক, `char`-এর উপর গাণিতিক অপারেশন চালানো যায়। এসব অপারেশনের ফল হয় একটি ইন্টিজার।

স্পষ্টতই, ৮ বিটের একটি `byte` আর ১৬ বিটের `char`-এর মধ্যে কোনো সমতা নেই।

## ব্যবহার

`char` ব্যবহার করা সাধারণত সহজ।

এগুলো একক উদ্ধৃতি চিহ্ন দিয়ে লিটারাল হিসেবে ডিফাইন করা যায়:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

একটি স্ট্রিং থেকে (শূন্য-ভিত্তিক) ইনডেক্সিং দিয়ে একটি আলাদা `char` পাওয়া যায়:

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

একটি স্ট্রিংয়ের উপর ইটারেশন করলে প্রতিটি ধাপে একটি `char` রিটার্ন হয়:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

উপরে দেখানো হয়েছে, একটি `char`-কে তার `int` মানে কাস্ট করা যায়।
অন্য লিপির ক্ষেত্রেও এটি কাজ করে (*অন্তত কিছু ক্ষেত্রে*):

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

ক্যারেক্টার তুলনা করার সময় অন্তর্নিহিত Int16 ব্যবহার করা হয়:

```fsharp
'A' < 'D'
// => val it: bool = true
```

এছাড়া, একটি `int`-কে `char`-এ কাস্ট করা যায়:

```fsharp
char 77
// => val it: char = 'M'
```

`System.Char` লাইব্রেরিতে একটি .NET ভাষার কাছে যেসব [মেথড][Char-methods] প্রত্যাশিত, তার পুরো সেটটাই আছে, যেমন আপার/লোয়ার কনভার্সন (তবে পরের অংশের সতর্কতাগুলো দেখুন):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

স্ট্রিং থেকে `char` বের করতে .NET লাইব্রেরিগুলো সাহায্য করে, এক্ষেত্রে `Seq` মেথডগুলো:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

ক্যারেক্টারের একটি তালিকা (বা অ্যারে) স্ট্রিং-এ রূপান্তর করার নানা উপায় আছে, তার মধ্যে আছে:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

`char` সম্পর্কে সাধারণ তথ্য এখানে পাওয়া যাবে:

- [Chars ডকুমেন্টেশন][chars-docs]: `char`-এর রেফারেন্স ডকুমেন্টেশন।

তবে, `char`-এর বেশ কিছু খুঁত আছে, যা নিচে বিস্তারিত বলা হয়েছে। এসব খুঁত মূলত একদিকে পূর্ণ ইউনিকোড স্ট্যান্ডার্ড আর অন্যদিকে টেক্সটের ঐতিহাসিক উপস্থাপন, পারফরম্যান্স ও মেমরি ব্যবহারের মধ্যে দ্বন্দ্ব থেকে আসে।

## ইউনিকোডের সমস্যা

স্ট্রিং নিয়ে কাজ করার সময়, যদি [`System.String`][System-string] লাইব্রেরির মেথডগুলো পাওয়া যায়, তাহলে স্ট্রিংকে ক্যারেক্টারে ভেঙে ফেলার বদলে সেগুলো খুঁজে বের করে ব্যবহার করা উচিত।

টেক্সটের কিছু "ক্যারেক্টার" একাধিক `char` দিয়ে তৈরি, কারণ ইউনিকোড স্ট্যান্ডার্ডে ৬৫৫৩৬-এর বেশি কোড পয়েন্ট আছে। যেমন, কিছু টেস্টে যে ইমোজিগুলো দেখা যায় সেগুলোতে ২টি `char` থাকে, কারণ এগুলো [সারোগেট][surrogates] ক্যারেক্টার দিয়ে গঠিত।

এছাড়াও, কম্বাইনিং সিকোয়েন্স আছে, যেমন কিছু ক্ষেত্রে একটি অ্যাকসেন্টেড ক্যারেক্টার আসতে পারে সাধারণ ক্যারেক্টারের জন্য একটি `char` আর অ্যাকসেন্টের জন্য আরেকটি `char` দিয়ে।

যদি আপনাকে আলাদা আলাদা ক্যারেক্টার নিয়ে কাজ করতে হয়, তাহলে একটি ক্যারেক্টার '0' আর '9'-এর মধ্যে আছে কি না তা যাচাই করার মতো অপরিণত তুলনার বদলে [`System.Char.IsControl`][is-control], [`System.Char.IsDigit`][is-digit]-এর মতো লাইব্রেরি মেথড ব্যবহার করার চেষ্টা করা উচিত।

উদাহরণস্বরূপ, খেয়াল করুন '٢' হলো আরবি সংখ্যা ২। `IsDigit` আরবি সংস্করণের জন্য ট্রু রিটার্ন করবে, তাই যাচাই করার সময় কোন ধরনের ইনপুট গ্রহণযোগ্য তা আপনার স্পষ্ট থাকা দরকার।

এমনকি `System.Char` লাইব্রেরির মেথডগুলোও হয়তো আপনার প্রত্যাশামতো কাজ করবে না, যখন আপনি আরও অপ্রচলিত ভাষা নিয়ে কাজ করেন।

স্ট্রিংকে নিরাপদে প্রদর্শনযোগ্য "ক্যারেক্টারে" ভাঙার একটি উপায় হলো [`StringInfo`][string-info] আর [`GetNexttextElement`][get-next-text-element]-এর মতো মেথড ব্যবহার করা।
গ্লোবালাইজেশন/লোকালাইজেশন নিয়ে কাজ করলে এটি প্রয়োজন হতে পারে।

ইউনিকোড ক্যারেক্টারের স্কেলার মান গুরুত্বপূর্ণ হয় এমন আরেকটি ক্ষেত্রে (ধরুন আপনি নিজের এনকোডিং সিস্টেম বানাচ্ছেন) [runes][runes] ব্যবহার করা যায়। তবে, আপনি যদি জানেন আপনার কাজ করা ক্যারেক্টারের পরিসরে সারোগেট বা কম্বাইনিং ক্যারেক্টার সিকোয়েন্স নেই (যেমন Latin ASCII) এবং আপনার ইনপুট ভালোভাবে যাচাই করা, তাহলে এটি এড়িয়ে যেতে পারেন।

আবারও, সবচেয়ে ভালো অবস্থান হলো সেটাই, যেখানে আপনি `String`-এর লাইব্রেরি মেথড ব্যবহার করতে পারেন।

ইউনিকোডের সূক্ষ্মাতিসূক্ষ্ম বিষয় নিয়ে কাজ করার মতো অনভিপ্রেত অবস্থায় পড়লে, [এটি][char-encoding-net] ভালো একটি সূচনা বিন্দু।

## গ্লোবালাইজেশন

আপনি যদি এমন পরিবেশে কাজ করেন যেখানে একাধিক কালচার নিয়ে কাজ করতে হয়, বা কোডের কিছু অংশে কালচার গুরুত্বপূর্ণ কিন্তু অন্য অংশে নয়, তাহলে [`ToUpper`][to-upper] আর [`ToLower`][to-lower]-এর ওভারলোডগুলো সম্পর্কে সচেতন থাকুন, যেগুলো একটি কালচার নেয়, আর [`ToUpperInvariant`][to-upper-invariant] ও [`ToLowerInvariant`][to-lower-invariant], যেগুলো বর্তমান [কালচার][culture-info] নির্বিশেষে একটি সামঞ্জস্যপূর্ণ ফল দেবে।
