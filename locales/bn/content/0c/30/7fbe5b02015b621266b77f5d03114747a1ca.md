# ভূমিকা

JavaScript-এ একটি বিল্ট-ইন অবজেক্ট `Date` আছে, যা তারিখ ও সময় সংরক্ষণ করে এবং সেগুলো পরিচালনার জন্য মেথড সরবরাহ করে।

<!-- prettier-ignore -->
~~~exercism/caution
এটি Java-এর `java.util.Date` ক্লাসের উপর ভিত্তি করে তৈরি হয়েছিল, যা ২০১০-এর দশকের গোড়ার দিকে প্রতিস্থাপিত হয়েছিল, কিন্তু পুরোনো কোডের সাথে সামঞ্জস্য রাখতে JavaScript-এর `Date` এখনও টিকে আছে।

সাধারণভাবে ডেট নিয়ে কাজ করা বেশ কঠিন, আর টাইমজোন হ্যান্ডলিং বেশ দুর্বল বা একেবারেই অনুপস্থিত, তাই `moment.js`, `day.js`, `date-fns` এবং `luxon`-এর মতো অনেক লাইব্রেরি তৈরি হয়েছে।
এর কোনোটিই Exercism-এ পাওয়া যায় না।

নিজের প্রজেক্টে `moment.js`-এর মতো পুরোনো হয়ে যাওয়া বা রক্ষণাবেক্ষণহীন প্যাকেজ ব্যবহার করবেন না; বরং `luxon`-এর মতো আরও আধুনিক বিকল্প, কিংবা এখনও তেমন প্রচলিত নয় এমন [Temporal][mdn-temporal] ব্যবহার করুন।
এই অনুশীলনীতে মূলত `Date` নিয়েই আলোচনা করা হয়েছে, যা JavaScript-এর শেষ দিন পর্যন্ত প্রাসঙ্গিক থাকবে।

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal

## তৈরি করা

একটি `Date` অবজেক্ট হলো `Date` ক্লাসের একটি ইনস্ট্যান্স।
কনস্ট্রাক্টর ফাংশনে কোনো আর্গুমেন্ট না দিয়েও এটি তৈরি করা যায়।
এতে এমন একটি `Date` অবজেক্ট তৈরি হয়, যা বর্তমান তারিখ ও সময় প্রকাশ করে:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### ইউনিক্স টাইমস্ট্যাম্প (সংখ্যা)

যদি কোনো সংখ্যা দেওয়া হয়, তাহলে সেটিকে একটি `timestamp` হিসেবে ধরা হবে।
টাইমস্ট্যাম্প হলো একটি ইন্টিজার সংখ্যা, যা **১ জানুয়ারি ১৯৭০ [UTC][defn-utc]+0** থেকে এখন পর্যন্ত অতিক্রান্ত **মিলিসেকেন্ড**-এর সংখ্যা বোঝায়।

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

কেউ হয়তো ভাবতে পারেন `new Date(0)` সবচেয়ে "প্রাচীনতম" ডেট অবজেক্ট তৈরি করবে, কিন্তু JavaScript তারিখটিকে আপনার স্থানীয় টাইমজোনে রূপান্তর করে, ফলে যাঁরা [GMT / UTC+0][defn-gmt] টাইমজোনে আছেন, কেবল তাঁরাই আসলে [ইউনিক্স এপক][defn-unix-epoch] মানটি পাবেন।

### ISO 8601 টাইমস্ট্যাম্প (স্ট্রিং)

`Date` কনস্ট্রাক্টরে তারিখ বোঝায় এমন একটি স্ট্রিং মান দিতে পারেন।
সব ইমপ্লিমেন্টেশনে একই রকম আচরণ করে **একমাত্র** ফরম্যাটটি হলো আন্তর্জাতিকভাবে স্বীকৃত ও প্রমিত তথাকথিত [ISO 8601 টাইমস্ট্যাম্প স্ট্রিং][defn-iso8601]-এর [সরলীকৃত রূপ][mdn-date-string-format]।

[UTC][defn-gmt] সময়ে একটি মুহূর্ত দেখতে এমন হয়:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

এখানে নিচের প্রতিস্থাপনগুলো ঘটে:

| চিহ্ন | বিবরণ                                              | ডিফল্ট |
| ---- | --------------------------------------------------- | ------- |
| YYYY | ক্যালেন্ডার বছর, ৪ সংখ্যায় প্রকাশ করা               |         |
| MM   | ক্যালেন্ডার মাস, ২ সংখ্যায় প্রকাশ করা               | 01      |
| DD   | ক্যালেন্ডার দিন, ২ সংখ্যায় প্রকাশ করা                | 01      |
| T    | একটি আক্ষরিক অক্ষর T, যা তারিখ ও সময় আলাদা করে       | T       |
| HH   | ২৪-ঘণ্টার ঘড়িতে ঘণ্টা, ২ সংখ্যায়                    | 00      |
| mm   | মিনিট, ২ সংখ্যায়                                    | 00      |
| ss   | সেকেন্ড, ২ সংখ্যায়                                  | 00      |
| mss  | মিলিসেকেন্ড, ৩ সংখ্যায়                              | 000     |
| Z    | একটি আক্ষরিক অক্ষর Z, অথবা একটি অফসেট `+/-HH:mm`     |         |

আক্ষরিক অক্ষর `Z` বোঝায় UTC (কোনো টাইমজোন নেই, ডে লাইট সেভিংস নেই)।

বেশিরভাগ কম্পোনেন্টের জন্যই ডিফল্ট মান আছে, তাই শেষের কিছু অংশ বাদ দেওয়াও বৈধ:

```text
YYYY-MM-DD
```

এক্ষেত্রে ডিফল্টভাবে সময় ধরা হয় 00:00:00.000।

যদি টাইমস্ট্যাম্পের শেষে `Z` না থাকে, আর শেষে `+HH:mm` বা `-HH:mm` (যা টাইমজোন অফসেট বোঝায়) না থাকে, তাহলে ঐতিহাসিক কারণবশত নিচের কথাটি প্রযোজ্য:

> টাইমজোন অফসেট না থাকলে, শুধু তারিখের ফরমগুলো UTC সময় হিসেবে এবং তারিখ-সময়ের ফরমগুলো স্থানীয় সময় হিসেবে ধরা হয়।
> UTC সময় হিসেবে ধরা হওয়াটা একটি ঐতিহাসিক স্পেক ভুলের কারণে ঘটে, যা ISO 8601-এর সাথে সঙ্গতিপূর্ণ ছিল না, কিন্তু ওয়েব সামঞ্জস্যের কারণে বদলানো যায়নি।
> দেখুন [Broken Parser – A Web Reality Issue][ref-broken-parser]।

### ডেট অবজেক্ট

আগে থেকে থাকা একটি ডেট অবজেক্টও কনস্ট্রাক্টরের আর্গুমেন্ট হিসেবে ব্যবহার করা যায়।
এতে একই তারিখ ও সময় নিয়ে বিদ্যমান `Date` অবজেক্টের একটি কপি তৈরি হয়।

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### আলাদা আলাদা তারিখ ও সময়ের কম্পোনেন্টের মান দেওয়া

শুধু তারিখ বোঝাতে চাইলে তিনটি সংখ্যা দিয়ে ডেট তৈরি করা যায়।
তারিখ ও সময় দুটোই বোঝাতে চাইলে ৬টি সংখ্যা দিয়ে ডেট তৈরি করা যায়।

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

দ্বিতীয় মানটি হলো `month`, যা জানুয়ারির জন্য `0` থেকে শুরু হয়ে ডিসেম্বরের জন্য `11` পর্যন্ত যায়।

## `Date.parse()`

আপনি হয়তো `Date.parse` নামে একটি তারিখ পার্স করার ফাংশনের উল্লেখ বা রেফারেন্স দেখতে পাবেন।
এই ফাংশনের জন্য মাত্র কয়েকটি ইনভ্যারিয়েন্ট (সত্য) নির্ধারিত, আর বাকি ইমপ্লিমেন্টেশন অনির্দিষ্ট (তাই অপ্রমিত), কাজেই এটি ব্যবহার করা উচিত নয়।

## `Date`-এর কম্পোনেন্ট অ্যাক্সেস করা

ডেট অবজেক্টে বিভিন্ন মেথড আছে, যেগুলো তারিখের নানা কম্পোনেন্ট রিটার্ন করে:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

মান হালনাগাদ করার জন্য এগুলোর প্রতিটিরই সংশ্লিষ্ট `set` ভ্যারিয়েন্ট আছে (যেমন `setFullYear`)।
কোনো মান সীমা ছাড়িয়ে গেলে তা পরের কম্পোনেন্টে গড়িয়ে যায়:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

সব মেথডেরই UTC ভ্যারিয়েন্ট আছে, যেগুলো স্থানীয় টাইমজোন উপেক্ষা করে।

## ডেট থেকে রূপান্তর

ডেট অবজেক্টে `getTime()` নামে একটি মেথড আছে, যা মিলিসেকেন্ডে ইউনিক্স টাইমস্ট্যাম্প রিটার্ন করে, অর্থাৎ ১ জানুয়ারি ১৯৭০, UTC-এর শুরুতে থাকা মধ্যরাত থেকে অতিক্রান্ত মিলিসেকেন্ডের সংখ্যা।
এছাড়া ডেট অবজেক্ট থেকে ISO 8601 টাইমস্ট্যাম্প স্ট্রিং-এ রূপান্তর করার জন্য `toISOString()` মেথড আছে।

## ডেট তুলনা করা

বড় (`>`) ও বড় বা সমান (`>=`), এবং ছোট (`<`) ও ছোট বা সমান (`<=`) অপারেটর দুটি ডেটের মধ্যে, কিংবা একটি ডেট আর একটি সংখ্যার মধ্যে সরাসরি ব্যবহার করা যায়।
এটি কাজ করে কারণ JavaScript ডেটকে একটি প্রিমিটিভে রূপান্তর করার চেষ্টা করে।

<!-- prettier-ignore -->
~~~exercism/advanced
দুটি ডেটের মধ্যে, বা একটি ডেট আর একটি সংখ্যার মধ্যে তুলনা করার সময় JavaScript [`[Symbol.toPrimitive]("number")`][mdn-to-primitive] কল করে, যা ভেতরে ভেতরে [`date.valueOf()`][mdn-date-value-of] কল করে।
পরেরটি [`date.getTime()`][mdn-date-get-time] কল করার সমান।

আপনি যদি এই আচরণের উপর নির্ভর করতে না চান, তাহলে প্রথমে `getTime()` দিয়ে সংখ্যায় রূপান্তর করে নিন।

[mdn-to-primitive]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/Symbol.toPrimitive
[mdn-date-value-of]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/valueOf
[mdn-date-get-time]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/getTime
~~~

সমানতা (`==` এবং `===`) দিয়ে ডেট তুলনা করা যায় না, তবে `.getTime()`-এর ফলাফল দিয়ে যায়।
