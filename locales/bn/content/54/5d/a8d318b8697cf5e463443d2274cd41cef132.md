# ভূমিকা

একটি **ফ্লোটিং-পয়েন্ট** হলো এমন একটি সংখ্যা, যার একটি ভগ্নাংশ অংশ থাকতে পারে, যেমন `-1.23` বা `3.1415`।

এমন একটি সংখ্যাকে বাইটের একটি সিকোয়েন্স হিসেবে প্রকাশ করার জন্য x86-64 **IEEE-754** স্ট্যান্ডার্ড ব্যবহার করে।
এই স্ট্যান্ডার্ডের সবচেয়ে কমন দুটি ফরম্যাট হলো সিঙ্গেল-প্রিসিশন ফ্লোটিং-পয়েন্ট এবং ডাবল-প্রিসিশন ফ্লোটিং-পয়েন্ট সংখ্যা।
x86-64 দুটিই সাপোর্ট করে।

একটি সিঙ্গেল-প্রিসিশন ফ্লোটিং-পয়েন্ট সংখ্যা ৩২-বিট চওড়া, আর একটি ডাবল-প্রিসিশন ৬৪-বিট চওড়া।

## XMM রেজিস্টার

x86-64-এ ফ্লোটিং-পয়েন্ট অ্যারিথমেটিক করার জন্য ১৬টি ডেডিকেটেড রেজিস্টার আছে, যাদের নাম `xmm0` থেকে `xmm15`।

এই রেজিস্টারগুলো অন্তত ১২৮-বিট চওড়া, তবে সাম্প্রতিক প্রসেসরগুলো এটি বাড়িয়ে ২৫৬-বিট বা ৫১২-বিট করেছে।
তবে বাস্তবে, কাঙ্ক্ষিত প্রিসিশনের উপর নির্ভর করে বেশিরভাগ ফ্লোটিং-পয়েন্ট সংখ্যা কেবল সবচেয়ে নিচের ৩২-বিট বা ৬৪-বিট ব্যবহার করে।

## সংখ্যার মধ্যে রূপান্তর

সংখ্যার ফরম্যাটের মধ্যে রূপান্তর করার জন্য ইনস্ট্রাকশনের একটি পরিবার আছে: `cvtxx2yy`।

`xx` এবং `yy` দুটিই লিটারাল নয়, বরং প্লেসহোল্ডার:

- `xx` হলো সোর্স অপারেন্ডের টাইপের একটি প্লেসহোল্ডার।
- `yy` হলো ডেস্টিনেশন অপারেন্ডের টাইপের একটি প্লেসহোল্ডার।

এই প্লেসহোল্ডার অনেক রূপ নিতে পারে, যার মধ্যে আছে:

| প্লেসহোল্ডার | অর্থ               |
| ----------- | --------------------- |
| `si`        | সাইনড ইন্টিজার        |
| `ss`        | ৩২-বিট ফ্লোটিং-পয়েন্ট |
| `sd`        | ৬৪-বিট ফ্লোটিং-পয়েন্ট |

যেমন:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

লক্ষ্য করুন, একটি ৩২-বিট ইন্টিজারকে ৬৪-বিট ফ্লোটিং-পয়েন্টে বা একটি ৬৪-বিট ইন্টিজারকে ৩২-বিট ফ্লোটিং-পয়েন্টে রূপান্তর করা সম্ভব।
একইভাবে, একটি ৩২-বিট ফ্লোটিং-পয়েন্টকে ৬৪-বিট ইন্টিজারে বা একটি ৬৪-বিট ফ্লোটিং-পয়েন্টকে ৩২-বিট ইন্টিজারে রূপান্তর করাও সম্ভব।
অর্থাৎ, একটি `cvtxx2yy`-তে দুই অপারেন্ডের আকার _একই হতে হবে না_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

যখন ফ্লোটিং-পয়েন্ট সংখ্যাটিকে ঠিকঠাক একটি ইন্টিজার হিসেবে প্রকাশ করা যায় না, তখন `cvtxx2si` `mxcsr` নামের একটি বিশেষ রেজিস্টারের রাউন্ডিং কন্ট্রোল অনুযায়ী সংখ্যাটিকে রাউন্ড করে।
এটি হতে পারে নিকটতমে রাউন্ড, নিচের দিকে রাউন্ড, উপরের দিকে রাউন্ড বা ট্রাঙ্কেট।
ফাংশনে ঢোকার সময় কোনো নিশ্চিত ডিফল্ট থাকে না।

লক্ষ্য করুন, একটি নির্ভুল ফলাফল রাউন্ড করা হয় না এবং তাই রাউন্ডিং কন্ট্রোল দ্বারা প্রভাবিতও হয় না।
যেমন, `42.0` _সবসময়_ `42`-তে রূপান্তরিত হবে।

একই ধরনের আরেকটি ইনস্ট্রাকশন পরিবার আছে `cvttxx2si` ফরম্যাটে (একটি অতিরিক্ত `t` সহ), যা সবসময় ফলাফলকে ট্রাঙ্কেট করে।

## রাউন্ড

`roundxx` ইনস্ট্রাকশন পরিবার সোর্স অপারেন্ডের একটি ফ্লোটিং-পয়েন্টকে ডেস্টিনেশন অপারেন্ডে সংরক্ষিত একটি রাউন্ড করা ফ্লোটিং-পয়েন্টে রূপান্তর করে।

এখানে, যথারীতি `xx` হলো অপারেন্ডের টাইপের একটি প্লেসহোল্ডার: সিঙ্গেল-প্রিসিশনের জন্য `ss` এবং ডাবল-প্রিসিশন ফ্লোটের জন্য `sd`।

এই ইনস্ট্রাকশনগুলো তৃতীয় অপারেন্ড হিসেবে একটি ধ্রুবক সংখ্যা নেয়।
এই সংখ্যাটি রাউন্ডিং মোড নির্দেশ করে:

| সংখ্যা | মোড         |
| :----- | :----------- |
| 0      | নিকটতম      |
| 1      | ফ্লোর (নিচের দিকে) |
| 2      | সিল (উপরের দিকে)    |
| 3      | ট্রাঙ্কেট     |

যেমন:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

যেহেতু এই ইনস্ট্রাকশনগুলো একটি নির্ভুল ফলাফল তৈরি করে, তাই এগুলো একটি `cvtxx2si`-এর প্রস্তুতিতে ব্যবহার করা যায়।

## অ্যারিথমেটিক ইনস্ট্রাকশন

ফ্লোটিং-পয়েন্ট সংখ্যা নিয়ে অনেক অপারেশন ইন্টিজারের সমতুল্য অপারেশনের মতোই নামের ইনস্ট্রাকশন নেয়, তবে শেষে প্রয়োজনীয় প্লেসহোল্ডার (`ss` বা `sd`) যোগ করে।
এই ইনস্ট্রাকশনগুলো দুই-অপারেন্ডবিশিষ্ট, স্বাভাবিক সেমান্টিক্সসহ, এমনকি যেগুলো গুণ বা ভাগ করে সেগুলোও:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## মুভ

একটি XMM রেজিস্টার থেকে অন্যটিতে মুভ করার ইনস্ট্রাকশনগুলো হলো `movss` বা `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

একটি ইমিডিয়েটকে (একটি ধ্রুবক সাইনড ইন্টিজার) সরাসরি একটি xmm রেজিস্টারে মুভ করা **সম্ভব নয়**।
এই সংখ্যাটিকে প্রথমে একটি জেনারেল-পারপাস রেজিস্টারে মুভ করতে হবে, তারপর `cvtsi2xx` দিয়ে রূপান্তর করতে হবে:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## তুলনা

দুইটি ফ্লোটিং-পয়েন্ট সংখ্যার মধ্যে তুলনা করার জন্য দুইটি গ্রুপের ইনস্ট্রাকশন আছে।
এগুলোর রূপ `comixx` এবং `ucomixx`, যেখানে `xx` হয় `ss` বা `sd`।
দুটিই যথারীতি `rflags`-এ ফ্ল্যাগ সেট করে, `cmp`-এর মতো একই সেমান্টিক্স অনুসরণ করে।

এদের মধ্যে পার্থক্য হলো, দুইটি ফ্লোটিং-পয়েন্ট সংখ্যার একটির `NaN` মান থাকলে `ucomixx` `parity flag (PF)` সেট করে, অন্যদিকে `comixx` এই ক্ষেত্রে একটি এক্সেপশন তোলে।

ফ্লোটিং-পয়েন্ট মানের মধ্যে তুলনা _আনসাইনড_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## কলিং কনভেনশন

System V ABI-তে, প্রথম আটটি ফ্লোটিং-পয়েন্ট আর্গুমেন্ট ক্রমানুযায়ী, `xmm0` থেকে `xmm7` পর্যন্ত, ফাংশনে পাস করা হয়।
ফ্লোটিং-পয়েন্ট মান ফাংশন থেকে `xmm0`-এ এবং প্রয়োজনে `xmm1`-এ রিটার্ন করা হয়।

সব `xmm` রেজিস্টার অবাধে ব্যবহার করা যায়, এর কোনোটিই কলারের জন্য সংরক্ষিত নয়।

## মেমরি

একই আকারের ইন্টিজারের মতো একই সেমান্টিক্স অনুসরণ করে ফ্লোটিং-পয়েন্ট মান মেমরিতে ডিফাইন করা যায়।
NASM (The Netwide Assembler, এই ট্র্যাকের ব্যবহৃত অ্যাসেম্বলার) সায়েন্টিফিক নোটেশনে ফ্লোটিং-পয়েন্ট মান ঘোষণা করার সুযোগও দেয়।

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```
