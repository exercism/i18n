# পরিচিতি

*রেগুলার এক্সপ্রেশন* (রেজেক্স) হলো ছোট একটি প্যাটার্ন, যা বলে দেয় কোনো টেক্সট দেখতে কেমন হওয়া উচিত। Factor-এর রেজেক্স টুলগুলো থাকে [`regexp`][regexp] ভোকাবুলারিতে, আর প্যাটার্ন লেখা হয় `R/ ` আর `/` চিহ্নের মাঝে।

প্যাটার্নের বেশিরভাগ ক্যারেক্টার নিজেদের মতোই থাকে। কয়েকটি বিশেষ অংশ বোঝায় ক্যারেক্টারের *ধরন*, কিংবা কতগুলো থাকবে সেটি:

```
\d        ! any digit 0–9
\s        ! any whitespace; \S means any non-whitespace
[A-Z]     ! any one capital letter
.         ! any single character

{4}       ! exactly 4 times       +   ! one or more
{2,5}     ! 2 to 5 times          *   ! zero or more
?         ! optional (0 or 1)
```

তাহলে `R/ [A-Z]{2}-\d{4}/` মানে হলো "দুটি বড় হাতের অক্ষর, একটি ড্যাশ, চারটি অঙ্ক"।

`matches?` পরীক্ষা করে দেখে, একটি *পুরো* স্ট্রিং প্যাটার্নের সাথে মেলে কি না:

```
matches? ( string regexp -- ? )
```

```factor
USING: regexp ;

"NS-1024" R/ [A-Z]{2}-\d{4}/ matches? .   ! => t
"NS-10"   R/ [A-Z]{2}-\d{4}/ matches? .   ! => f
```

আরও কিছু শব্দ স্ট্রিংয়ের *ভেতরে* খোঁজ করে: `all-matching-subseqs` প্রতিটি ম্যাচ রিটার্ন করে, `count-matches` সেগুলো গুনে দেয়, `re-contains?` জানায় আদৌ কোনো ম্যাচ আছে কি না, আর `re-replace` প্রতিটি ম্যাচের জায়গায় নতুন টেক্সট বসিয়ে দেয়:

```
all-matching-subseqs ( string regexp -- seq )
count-matches        ( string regexp -- n )
re-contains?         ( string regexp -- ? )
re-replace           ( string regexp replacement -- result )
```

```factor
USING: regexp ;

"seen NS-1024 then AB-0007" R/ [A-Z]{2}-\d{4}/ all-matching-subseqs .
! => { "NS-1024" "AB-0007" }

"user=alice pass=hunter2" R/ pass=\S+/ "pass=****" re-replace .
! => "user=alice pass=****"
```
