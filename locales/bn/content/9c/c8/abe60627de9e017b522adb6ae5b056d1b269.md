# সম্পর্কে

একটি [লুপ][control] হলো ইনস্ট্রাকশনের এমন একটি ধারা, যা শেষ হওয়ার একটি শর্ত পূরণ হওয়া পর্যন্ত সম্ভাব্য একাধিকবার চালানো হয়।

x86-64-এ একটি লুপ সাধারণত আগের একটি লেবেলে জাম্প দিয়ে তৈরি করা হয়:

```x86asm
example_loop:
    ...
    jmp example_loop
```

মনে রাখবেন, আগের কোনো লেবেলে একটি আনকন্ডিশনাল জাম্প সবসময়ই এক্সিকিউশনকে ওই লেবেলে নিয়ে যায়।
এর মানে হলো, বারবার চলতে থাকা এই ধারার বাইরে অন্য কোনো জাম্প না থাকলে লুপটি চিরকাল বারবার চলতেই থাকবে।

উদাহরণস্বরূপ, এই লুপটি শেষ হয় না:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

আর শর্ত পূরণের উপর নির্ভর করে এই লুপটি শেষ হতে পারে:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## কাউন্টিং লুপ

একটি কাউন্টিং লুপ প্রায় সবসময়ই একইভাবে শেষ হয়: একটি ইনস্ট্রাকশন যা কোনো কাউন্টার হালনাগাদ করে বা দুটি মান তুলনা করে, তার ঠিক পরেই থাকে একটি শর্তসাপেক্ষ জাম্প, যা সিদ্ধান্ত নেয় আবার একবার ঘুরবে কি না।

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
উপরের কোডে `cmp rsi, 0` দরকার নেই, কারণ ফলাফল `0` হলে `sub rsi, 1` ইতিমধ্যেই `zero flag (ZF)` সেট করে দেয়।

অ্যাসেম্বলিতে শর্ত পরীক্ষা করার মূল উপায় `cmp` হলেও, অনেক ইনস্ট্রাকশনই ফ্ল্যাগ হালনাগাদ করে।
যেমন, অনেক পূর্ণসংখ্যার পাটিগণিত বা বিটওয়াইজ ইনস্ট্রাকশন ফলাফল `0` হলে `ZF` এবং ফলাফল ঋণাত্মক হলে (অর্থাৎ উপরের বিটটি সেট থাকলে) `SF` হালনাগাদ করে।

কোন ইনস্ট্রাকশন কোন ফ্ল্যাগে প্রভাব ফেলে, তা দেখতে আপনি একটি [রেফারেন্স][reference] দেখে নিতে পারেন।

[reference]: https://www.felixcloutier.com/x86/
~~~~

মনে রাখবেন, উপরের উদাহরণে ধরে নেওয়া হয়েছে `rsi` `0`-এর চেয়ে বড়।
যদি এটি `0` হতো, তবে `sub rsi, 1` `rsi`-কে `-1`-এ নামিয়ে আনত, যা একটি অত্যন্ত বড় আনসাইনড সংখ্যা।
লুপটি অবশেষে শেষ হওয়ার আগে আরও `18,446,744,073,709,551,615` বার ইটারেশন লাগত।
এছাড়া, অ্যারের দৈর্ঘ্য `0` হওয়ায় যেকোনো মেমরি অ্যাক্সেসই সীমার বাইরে চলে যেত।

অ্যারের দৈর্ঘ্য নিয়ে কোনো নিশ্চয়তা না থাকলে সাধারণত দুটি পদ্ধতি অবলম্বন করা হয়।

প্রথমটি হলো শেষ হওয়ার শর্তটি লুপের শুরুতে নিয়ে আসা, আর শেষে একটি আনকন্ডিশনাল জাম্প রাখা:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

দ্বিতীয়টি হলো লুপ শুরু করার আগে অ্যারেটি শূন্য-দৈর্ঘ্যের কি না তা একবার পরীক্ষা করে নেওয়া:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

এই দ্বিতীয় পদ্ধতিটি সাধারণত প্রথমটির চেয়ে বেশি কার্যকর, কারণ লুপ বডিতে ব্রাঞ্চের সংখ্যা কম থাকে।
এ বিষয়ে আপনি ভবিষ্যতের একটি কনসেপ্টে আরও জানতে পারবেন।

## মাইক্রো-অপ

একটি প্রসেসর `add` বা `jnz`-এর মতো কোনও ইনস্ট্রাকশন সরাসরি চালায় না।
CPU-এর ফ্রন্ট-এন্ড প্রথমে প্রতিটি ইনস্ট্রাকশনকে _ডিকোড_ করে এক বা একাধিক ছোট অভ্যন্তরীণ ধাপে ভাগ করে, যাদের বলা হয় **মাইক্রো-অপারেশন** (বা **মাইক্রো-অপ**)।
এরপর প্রসেসর এই মাইক্রো-অপগুলো শিডিউল করে ও চালায়, প্রায়ই প্রতি সাইকেলে একাধিক এবং তাদের মূল ক্রম না মেনেই।

বেশিরভাগ সরল ইনস্ট্রাকশন একটি মাত্র মাইক্রো-অপে ডিকোড হয়, আর জটিলতর ইনস্ট্রাকশন একাধিক মাইক্রো-অপে ডিকোড হতে পারে।
যেহেতু প্রসেসরের আসল কাজের চাপ হলো মাইক্রো-অপের ধারা, তাই একই কাজের জন্য কম মাইক্রো-অপ তৈরি করা কোড দ্রুত হওয়ার একটি উপায়।

## ম্যাক্রোফিউশন

আগেই বলা হয়েছে, একটি লুপ সাধারণত কোনো এক ধরনের শর্তসাপেক্ষ জাম্প দিয়ে শেষ হয়।
এটি এতটাই সাধারণ যে আধুনিক প্রসেসরগুলো ডিকোডিংয়ের সময় এই প্যাটার্নের জন্য অপ্টিমাইজ করা থাকে।

ফ্ল্যাগ সেট করা একটি ইনস্ট্রাকশনের ঠিক পরেই যদি সেই ফ্ল্যাগ পড়ে এমন একটি শর্তসাপেক্ষ জাম্প আসে, তবে দুটিকে আলাদা আলাদা না করে একসাথে একটি **একক** মাইক্রো-অপে ডিকোড করা যায়।
একে বলা হয় **ম্যাক্রোফিউশন**।

ফিউজ হওয়া জোড়াটি একটি অপারেশনের মতোই আচরণ করে: কাউন্টার হালনাগাদ আর ব্রাঞ্চের সিদ্ধান্ত একসাথে, একটি মাত্র মাইক্রো-অপে হয়ে যায়।
তখন লুপের কন্ট্রোল ফ্লো লুপটি যে আসল কাজ করে তার উপরে প্রায় কোনো খরচই যোগ করে না।

সাধারণ নিয়ম হিসেবে, দুই ধরনের জোড়া এভাবে ফিউজ হয়:

- `add` বা `sub`-এর মতো পাটিগণিতের ইনস্ট্রাকশন, তার ঠিক পরেই একটি শর্তসাপেক্ষ জাম্প।
- একটি `cmp`, `test` বা `and`, তার ঠিক পরেই একটি শর্তসাপেক্ষ জাম্প।

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

ফিউশন কেবল তখনই ঘটে যখন শর্তসাপেক্ষ জাম্পটি ফ্ল্যাগ সেট করা ইনস্ট্রাকশনের **ঠিক পরে** আসে, মাঝে কিছু না থাকে।

~~~~exercism/note
ম্যাক্রোফিউশন CPU-এর উপর নির্ভর করে, আর কোন ইনস্ট্রাকশন কোন শর্তসাপেক্ষ জাম্পের সাথে ফিউজ হয় তা নিয়েও কিছুটা ভিন্নতা আছে।

একটি কাজের রেফারেন্স হলো [Intel, AMD ও VIA CPU-এর মাইক্রোআর্কিটেকচার, Agner Fog-এর লেখা][agner-uarch]।
[Intel অপ্টিমাইজেশন রেফারেন্স ম্যানুয়াল][intel-opt]-এর 3.4.2.2 নম্বর অনুচ্ছেদে (Optimizing for Macrofusion) Intel CPU-গুলোর জন্য ফিউজযোগ্য জোড়ার তালিকাও দেওয়া আছে।

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## `loop` ইনস্ট্রাকশন

কিছু ইনস্ট্রাকশন আছে যা দিয়ে লুপের মতো আচরণ তৈরি করা যায়।
তার মধ্যে একটি হলো [লুপ][loop]।

এর একমাত্র অপারেন্ড হলো একটি লেবেল, যাতে লুপের শুরুর অ্যাড্রেস থাকে।

`loop` ইনস্ট্রাকশন `rcx`-এর মানকে একটি কাউন্টার হিসেবে ব্যবহার করে এবং প্রতিবার সেটি ১ করে কমায়।
`rcx`-এর মান শূন্যে পৌঁছে গেলে লুপটি শেষ হয় এবং এক্সিকিউশন ক্রমানুসারে চলতে থাকে:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

`loop` ইনস্ট্রাকশনের দুটি ভ্যারিয়েন্ট আছে, যারা প্রতি ইটারেশনে শূন্য ফ্ল্যাগ (`ZF`) পরীক্ষা করে।
`rcx` শূন্যে পৌঁছে গেলে লুপ থামানোর পাশাপাশি, শর্তটি _না_ মেটা হলেও এরা লুপ থামিয়ে দেয়।

| ইনস্ট্রাকশন       | শর্ত |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

এসব ইনস্ট্রাকশন `ZF` **সেট করে না**।
এদের আগে অবশ্যই একটি `cmp`, `test`, বা অন্য কোনো ইনস্ট্রাকশন থাকতে হবে যা `ZF` বদলায়:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
সুবিধাজনক হলেও, আধুনিক প্রসেসরে `loop`, `loope`, এবং `loopne` সাধারণত সমতুল্য `sub`/`jnz` বা `cmp`/`jnz` ধারার চেয়ে অনেক ধীর।

অনেক ভিন্ন CPU-তে ইনস্ট্রাকশনের পারফরম্যান্স নিয়ে একটি ভালো রেফারেন্স হলো [Agner-এর টেবিলগুলো][agner-tables]।

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
~~~~
