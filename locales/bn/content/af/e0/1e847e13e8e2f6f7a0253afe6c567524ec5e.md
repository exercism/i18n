# সম্পর্কে

প্রপার্টির প্রধানত দুটি ধরন আছে:

1. অটো-ইমপ্লিমেন্টেড প্রপার্টি, যেখানে `get` ও `set` অ্যাকসেসরের কোনো বডি থাকে না। এগুলো স্পষ্টভাবে ইনিশিয়ালাইজ করা হতে পারে, আবার নাও হতে পারে। যেমন:
   ```csharp
   public int MyProperty {get; set;} = 42;
   ```
2. সেগুলো, যেখানে অ্যাকসেসরগুলো এক্সপ্রেশন ইভ্যালুয়েট করে এবং স্টেটমেন্ট চালায়। কোডটি একটি ব্যাকিং ফিল্ড রিটার্ন করা বা অ্যাসাইন করার মতো সহজও হতে পারে। যেমন:
   ```csharp
   private int myField;
   public int MyProperty
   {
     get { return myField; }
     set { myField = value; }
   }
   ```

প্রপার্টি ও মেথডের আচরণ ও ক্ষমতার মধ্যে যথেষ্ট মিল রয়েছে।
অটো-ইমপ্লিমেন্টেড প্রপার্টি না হলে, প্রপার্টিতে ক্লাসের স্কোপের মধ্যে থাকতে পারে এমন যেকোনো স্টেটমেন্ট বা এক্সপ্রেশন থাকতে পারে। একটি কমন ক্ষেত্রে এগুলোকে প্রায়ই একটি ব্যাকিং ফিল্ড মোড়ানোর কাজ হিসেবে বর্ণনা করা হয়।
যদিও বেশিরভাগ সময়ই কোনো নির্দিষ্ট ক্ষেত্রে আচরণটি প্রপার্টি হিসেবে লিখবেন না মেথড হিসেবে, তা স্পষ্ট থাকে, তবু অনেক সময়ই এটি কোডারের বিচারবিবেচনার বিষয় হয়ে দাঁড়ায়, বিশেষত অ্যাকসেসরের ভেতরে কতটা কোড চালানো উচিত তা নিয়ে। একটি `set` অ্যাকসেসরে ভ্যালিডেশন এবং একটি `get` অ্যাকসেসরে সাধারণ হিসাব বা ফরম্যাটিং সাধারণত দেখা যায়:

```csharp
private float fraction;
public float Percentage
{
  get { return fraction * 100; }
  set
  {
    if (value < 0 || value > 100)
    {
      throw new ArgumentException("Percentage must be between 0 and 100");
    }
    fraction = value / 100;
  }
}
```

অন্য ক্লাস মেম্বারগুলোর মতোই প্রপার্টিরও অ্যাকসেস লেভেল থাকতে পারে।
বেশিরভাগ ক্ষেত্রেই প্রপার্টির অ্যাকসেস লেভেল নন-প্রাইভেট হয়, যা তার মূল উদ্দেশ্যের সঙ্গে সঙ্গতিপূর্ণ। কখনও কখনও একটি অ্যাকসেসরের অ্যাকসেস লেভেল প্রপার্টির চেয়ে আলাদা হয়। `TareWeight`-এর ক্ষেত্রে বরং কৃত্রিম "নিরাপত্তা" বাধ্যবাধকতার মধ্যে একটি পাবলিক প্রপার্টির সঙ্গে প্রাইভেট গেটার রাখার সুযোগ ছিল। এর অর্থ হলো, ক্লাসের বাইরের কোড প্রপার্টিটির মান সেট করতে পারে, কিন্তু কেবল ক্লাসের ভেতরের কোডই এটি পড়তে (get করতে) পারে।

```csharp
public int ConfidentialValueUsedInternally {private get; set; }
```

নন-পাবলিক `set` অ্যাকসেসরও সমর্থিত, তবে আরও কমন ক্ষেত্র হলো যেখানে `set` অ্যাকসেসরটি সম্পূর্ণ বাদ দেওয়া যায়। এর কারণ হতে পারে, প্রপার্টিটির মান ক্লাসের কনস্ট্রাক্টরে সেট করা হয়।

```csharp
class MyClass
{
  public MyClass( int importantValue)
  {
    ConstructedValue = importantValue;
  }
  public int ConstructedValue {get;}
}
```

এই অনুশীলনীতে প্রপার্টির মৌলিক ব্যবহার নিয়ে আলোচনা করা হয়েছে। আরও উন্নত বিষয় আপনি অন্য অনুশীলনীগুলোতে পাবেন:

- এক্সপ্রেশন-বডিড প্রপার্টি, `get` অ্যাকসেসর ও `set` অ্যাকসেসর (এক্সপ্রেশন-বডিড মেম্বারে আলোচিত)
- ইন্টারফেসের প্রপার্টি (ইন্টারফেসে আলোচিত)
- অ্যাবস্ট্রাক্ট ক্লাসের প্রপার্টি/অ্যাবস্ট্রাক্ট প্রপার্টি (ইনহেরিট্যান্সে আলোচিত)
- প্রপার্টির সঙ্গে `readonly` কিওয়ার্ডের ব্যবহার (ইমিউটেবিলিটিতে আলোচিত)
- স্ট্যাটিক প্রপার্টি (স্ট্যাটিকসে আলোচিত)
- ইনডেক্সার (ইনডেক্সারে আলোচিত)
