## স্ক্রিপ্টের ব্যবহার

টেস্ট জেনারেশনের জন্য [problem-specifications][problem-specifications] রিপোজিটরির একটি লোকাল কপি দরকার। অনুশীলনীগুলো সঠিকভাবে অ্যাক্সেস করার জন্য স্ক্রিপ্টটি রুট `python` ডিরেক্টরি থেকে রান করা উচিত।

ব্যবহারের তথ্যের জন্য `bin/generate_tests.py --help` চালান।


## টেস্ট টেমপ্লেট

টেস্ট টেমপ্লেট [Jinja2] সিনট্যাক্স সমর্থন করে এবং ক্যানোনিকাল ডেটা থেকে নিচের কনটেক্সট ভ্যারিয়েবলগুলো পাওয়া যায়:
- `exercise`: অনুশীলনীর হাইফেনযুক্ত নাম (যেমন: `two-fer`)
- `version`: ক্যানোনিকাল ডেটার ভার্সন (যেমন: `1.2.0`)
- `cases`: কেস অবজেক্টের একটি তালিকা বা `cases` তালিকার একটি তালিকা। আপনি যে অনুশীলনী নিয়ে কাজ করছেন তার সঠিক স্ট্রাকচারের জন্য `canonical-data.json` দেখুন
- `has_error_case`: কোনো টেস্ট কেস এরর থ্রো হওয়ার আশা করে কি না তা নির্দেশ করে (যেমন: `False`)
- `additional_cases`: `cases`-এর মতোই স্ট্রাকচার, তবে অনুশীলনীর `.meta/additional_tests.json` ফাইল থাকলে সেখান থেকে পূরণ করা হয় (উদাহরণের জন্য `exercises/word-count/.meta/additional_tests.json` দেখুন)

এছাড়া সুবিধার জন্য নিচের টেমপ্লেট ফিল্টারগুলো যোগ করা হয়েছে:
- `to_snake`: একটি স্ট্রিংকে snake_case-এ রূপান্তর করে (যেমন: `{{ "CamelCaseString" | to_snake }}` -> `camel_case_string`)
- `camel_case`: একটি স্ট্রিংকে CamelCase-এ রূপান্তর করে (যেমন: `{{ "snake_case_string" | camel_case }}` -> `SnakeCaseString` )
- `error_case`: কোনো টেস্ট কেস এরর থ্রো হওয়ার আশা করে কি না তা যাচাই করে (যেমন: `{% for case in cases%}{% if case is error_case}`)
- `regex_replace`: রেজেক্স স্ট্রিং প্রতিস্থাপন (যেমন: `{{ "abc123" | regex_replace("\\d", "D") }}` -> `abcDDD`)


### কনভেনশন

- অনেকবার ব্যবহৃত টেমপ্লেট স্ট্রাকচারের জন্য সাধারণ ব্যবহারের ম্যাক্রো `config/generator_macros.j2`-এ ডিফাইন করা আছে।
  - এগুলো নিচেরভাবে ইমপোর্ট করা যায়:
  `{%- import "generator_macros.j2" as macros with context -%}`
- সব টেস্ট টেমপ্লেট `{{ macros.footer() }}` দিয়ে শেষ হওয়া উচিত।
- সব Python ক্লাসের নাম CamelCase-এ হওয়া উচিত (যেমন: `TwoFer`)।
  - `{{ "two-fer" | camel_case }}` দিয়ে রূপান্তর করুন
- সব Python মডিউল ও ফাংশনের নাম snake_case-এ হওয়া উচিত
(যেমন: `high_scores`, `personal_best`)।
  - `{{ "personalBest" | to_snake }}` দিয়ে রূপান্তর করুন
- ট্র্যাক-নির্দিষ্ট টেস্ট অপশন ফাইল `.meta/additional_tests.json`-এ ডিফাইন করা হয়। এই ফাইলে ডিফাইন করা JSON অবজেক্টে একটিমাত্র কী (key) থাকবে, `cases`, যার স্ট্রাকচার `canonical-data.json`-এর `cases`-এর মতোই।
- ট্র্যাক-নির্দিষ্ট টেস্ট টেস্ট ফাইলে ক্যানোনিকাল টেস্টের পরে রাখা উচিত।
- ট্র্যাক-নির্দিষ্ট টেস্ট টেস্ট ফাইলে নিচের কমেন্ট দিয়ে চিহ্নিত করা উচিত:
```
# Additional tests for this track
```


### লেআউট

বেশিরভাগ টেমপ্লেট দেখতে অনেকটা এমন হবে:

```Jinja2
{%- import "generator_macros.j2" as macros with context -%}
{{ macros.header() }}

class {{ exercise | camel_case }}Test(unittest.TestCase):
    {% for case in cases -%}
    def test_{{ case["description"] | to_snake }}(self):
        value = {{ case["input"]["value"] }}
        expected = {{ case["expected"] }}
        self.assertEqual({{ case["property"] }}(value), expected)

    {% endfor %}

{{ macros.footer() }}
```


### ইমপোর্ট ওভাররাইড করা

`macros.header()`-এ ইমপোর্ট করা নামগুলো ইমপোর্ট করার জন্য বিকল্প নামের একটি তালিকা যোগ করে ওভাররাইড করা যায় (যেমন: `clock`):

```Jinja2
{{ macros.header(["Clock"])}}
```


### প্রপার্টি উপেক্ষা করা

বিরল ক্ষেত্রে, এই ট্র্যাকে যে প্রপার্টিগুলো টেস্ট করা হয় না সেগুলো ফিল্টার করে বাদ দেওয়ার প্রয়োজন হতে পারে। `header` ম্যাক্রো একটি `ignore` আর্গুমেন্টও নেয় (যেমন: `high-scores`):

```Jinja2
{{ macros.header(ignore=["scores"]) }}
```

## টেমপ্লেট তৈরি করা

1. আপনি যে অনুশীলনীটি ইমপ্লিমেন্ট করছেন তার জন্য `.meta/template.j2` তৈরি করুন এবং এডিটরে খুলুন।
2. টেমপ্লেট ফাইলে [উদাহরণ লেআউট](#Layout) কপি-পেস্ট করুন এবং সেভ করুন।
3. টেমপ্লেট ফাইলে উপযুক্ত পরিবর্তন করুন যতক্ষণ না এটি বৈধ টেস্ট কোড তৈরি করে; ইনপুটের নাম ও কেস স্ট্রাকচারের জন্য অনুশীলনীর `canonical-data.json` দেখুন।
    - স্ট্যান্ডার্ডাইজড অংশগুলো আবার লেখা এড়াতে [উপলব্ধ ম্যাক্রো](../config/generator_macros.j2) ব্যবহার করুন।
    - যদি আপনি কোনো বিদ্যমান অনুশীলনীর জন্য টেমপ্লেট ইমপ্লিমেন্ট করেন, তাহলে বিদ্যমান টেস্ট ফাইলের স্ট্রাকচার হুবহু মেলানো বাধ্যতামূলক নয়, তবে পার্থক্য যত কম রাখবেন ততই সবার জন্য PR রিভিউ অনেক সহজ হবে।
