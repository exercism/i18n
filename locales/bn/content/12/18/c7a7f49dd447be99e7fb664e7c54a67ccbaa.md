# কন্ডিশনাল

একটি **কন্ডিশনাল** কোনো একটি বিষয় সত্য কি না, তার উপর নির্ভর করে দুই ধরনের কাজের মধ্যে একটি বেছে নেয়।

```sather
   verdict(score : INT) : STR is
      if score >= 5 then
         return "Recalled";
      else
         return "Thank you";
      end;
   end;
```

এটি পড়ার নিয়ম: প্রথমে `if`, তারপর এমন একটি প্রশ্ন যার উত্তর `true` বা `false`, তারপর `then`। উত্তর সত্য হলে `then`-এর পরের লাইনগুলো চলে, আর উত্তর মিথ্যা হলে `else`-এর পরের লাইনগুলো চলে। `end;` পুরোটা শেষ করে।

## দুইয়ের বেশি পথ

`elsif` আরও একটি প্রশ্ন যোগ করে, যা কেবল তার উপরের প্রশ্নগুলোর উত্তর মিথ্যা এলে জিজ্ঞাসা করা হয়।

```sather
   verdict(score : INT) : STR is
      if score >= 8 then
         return "Cast";
      elsif score >= 5 then
         return "Recalled";
      else
         return "Thank you";
      end;
   end;
```

ক্রমটা গুরুত্বপূর্ণ। `9` স্কোরটি প্রথম প্রশ্নেই ধরা পড়ে এবং দ্বিতীয় প্রশ্ন পর্যন্ত কখনো পৌঁছায় না, যদিও `9 >= 5`-ও সত্য। শর্তগুলো ভুল ক্রমে লেখাই সাধারণত এই ভুলটা করার কারণ।

এর বানান `elsif`, `elseif` নয়, আবার `else if`-ও নয়।

## `else` বাদ দেওয়া

সেই ক্ষেত্রে করার মতো কিছু না থাকলে `else` বাদ দেওয়া যায়।

```sather
   if late then
      apologise;
   end;
```

যে রুটিনকে অবশ্যই কিছু রিটার্ন করতে হয়, তার প্রতিটি পথেই রিটার্ন থাকা দরকার, তাই এই অনুশীলনীতে প্রতিটি `if` তার `else` ধরে রাখে।
