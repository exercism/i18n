# ভূমিকা

আদর্শ জগতে আমরা ধরে নিতে পারতাম সবকিছুই সুন্দরভাবে সংজ্ঞায়িত, নির্দিষ্ট মান আছে এবং কোনো ফাঁক নেই।

এটি আমাদের দৈনন্দিন অভিজ্ঞতার সাথে সাংঘর্ষিক, তাই অনেক প্রোগ্রামিং ভাষায় মানের অনুপস্থিতি বোঝানোর একটি উপায় আছে: null বা NULL, nil, None, nothing...

এটি চালু করা সহজ ছিল (১৯৬৫ সালে), কিন্তু শীঘ্রই অনুশোচনার জন্ম দেয়। উদ্ভাবক পরে একে তাঁর "বিলিয়ন ডলারের ভুল" বলে অভিহিত করেন।

সাম্প্রতিক কয়েক দশকে ভাষা-ডিজাইনাররা নানা উপায় খুঁজেছেন, যাতে null ব্যবহার করা যায় কিন্তু (বেশিরভাগ ক্ষেত্রে) নিরাপদ থাকে।

Kotlin-এর কয়েকটি [সাধারণ নীতি][ref-null-safety] আছে, যা Java থেকে উল্লেখযোগ্যভাবে আলাদা।


- Kotlin-এ একটি বিশেষ `null` মান আছে।
- সব টাইপ _ডিফল্টভাবে_ নন-নালেবল।
- বেশিরভাগ টাইপকে নালেবল _করা_ যায়, তবে প্রোগ্রামারকে তা স্পষ্টভাবে বলতে হয়।
- যে ফাংশনগুলো এক্সেপশন নিয়ে ব্যর্থ হতে পারে, তাদের সাধারণত নালেবল রিটার্ন ভ্যালুসহ একটি ভ্যারিয়েন্ট থাকে।
- বিশেষ, অত্যন্ত সংক্ষিপ্ত সিনট্যাক্স null পরীক্ষা করা এবং তার প্রতি সাড়া দেওয়া যতটা সম্ভব সহজ করার চেষ্টা করে।

## নালেবল ভ্যারিয়েবল তৈরি করা

সাধারণ টাইপগুলোর সাধারণত একটি নালেবল সমতুল্য রূপ থাকে, যার শেষে `?` যোগ হয়: যেমন `String`-এর বদলে `String?`।

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## কাজের অপারেটর ও ফাংশন

### সেফ কল অপারেটর `?.`

একটি নন-নালেবল `String` থেকে আমরা `.length` প্রোপার্টি পেতে পারি।

একই সিনট্যাক্স নালেবল `String?`-এর ক্ষেত্রে ব্যর্থ হয়, কিন্তু `?.length` ব্যবহার করলে `null` হওয়ার সম্ভাবনা সামলানো যায়। রিটার্ন টাইপ হয় `Int?`।

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

উপরের শেষ লাইনে যেমন দেখলাম, `?.` নন-নালেবল টাইপের সাথেও কাজ করে।

### এলভিস অপারেটর `?:`

সেফ-কল অপারেটরের ধারণাটি বাড়িয়ে, [এলভিস অপারেটর][wiki-elvis] আমাদের `null`-এর বদলে বসিয়ে দেওয়ার জন্য একটি ডিফল্ট মান সরবরাহ করার সুযোগ দেয়।

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### নট-নাল অ্যাসারশন অপারেটর `!!`

এই অপারেটর দিয়ে, প্রোগ্রামার নিশ্চিত হলে একটি নালেবল টাইপকে জোর করে নন-নাল হিসেবে ধরা হয়। হয়তো আমরা কখনো কখনো অতিরিক্ত সতর্ক কম্পাইলারের চেয়ে প্রোগ্রামের লজিক ভালো বুঝি?

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

এখন দায়িত্ব আমাদের কাঁধে: যদি `b` তখনও `null` থাকে, তাহলে আমরা একটি `NullPointerException` পাই।

### let ফাংশন `?.let`

কোনো কোডের ব্লকে একটি নালেবল এলিমেন্ট পাঠাতে হলে আমরা নির্দিষ্টভাবে null পরীক্ষা করতে পারি: `if (item != null) { do something }`।

`item?.let { do something }` ব্যবহার করা আরও সহজ ও বেশি স্বাভাবিক। `do something` কেবল তখনই চলে যখন `item` null নয়।

### `somethingOrNone()` ধরনের ফাংশন

কিছু ফাংশন ব্যর্থ হতে পারে, যেমন স্ট্রিং বা অ্যারেতে একটি অবৈধ ইনডেক্স চাওয়ার সময়।

এক্সেপশন ছোড়ার বদলে আমরা ফাংশনের `...OrNull` ভ্যারিয়েন্ট ব্যবহার করতে পারি, যাতে (এই ক্ষেত্রে) একটি `Int?` রিটার্ন ভ্যালু পাওয়া যায়।

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
