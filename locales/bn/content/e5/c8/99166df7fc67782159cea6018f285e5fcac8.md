# সম্পর্কে

লিংকেজ বর্ণনা করে কোডের কোন জায়গা থেকে একটি আইডেন্টিফায়ার অ্যাক্সেস করা যায়।
ব্লক, ফাংশন বা ফাংশন প্রোটোটাইপ স্কোপযুক্ত মানের কোনো লিংকেজ থাকে না।
এর মানে হলো, তাদের নিজেদের স্কোপের বাইরে থেকে সেগুলো অ্যাক্সেস করা যায় না।
স্কোপ সম্পর্কে আরও জানতে [স্কোপ ধারণা](../scope/introduction.md#Introduction) দেখুন।

## এক্সটার্নাল লিংকেজ

ফাইল স্কোপযুক্ত আইডেন্টিফায়ারের ডিফল্টভাবে এক্সটার্নাল লিংকেজ থাকে।
এক্সটার্নাল লিংকেজযুক্ত একটি আইডেন্টিফায়ার প্রোগ্রামের যেকোনো ফাইল থেকে কল করা যায়।

## ইন্টার্নাল লিংকেজ

`static` স্পেসিফায়ার ব্যবহার করে ফাইল স্কোপযুক্ত একটি আইডেন্টিফায়ারকে ইন্টার্নাল লিংকেজ দেওয়া যায়।
ইন্টার্নাল লিংকেজযুক্ত একটি আইডেন্টিফায়ার কেবল তার নিজের ফাইলের ভেতরেই ব্যবহার করা যায়।

যেমন

```c
int public_count = 0; // file scope, external linkage by default
static int private_count = 0;  // file scope, internal linkage 

// file scope, internal linkage
static void some_function()
{
    // code snipped
}

// file scope, external linkage by default
int main()
{
    // code snipped
}
```

স্ট্যাটিক লিংকেজকে স্ট্যাটিক স্টোরেজ ডিউরেশনের সাথে গুলিয়ে ফেলা উচিত নয়।
স্ট্যাটিক স্টোরেজ ডিউরেশন সম্পর্কে আরও জানতে [স্টোরেজ ডিউরেশন ধারণা](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#static-the-storage-specifier-not-to-be-confused-with-the-static-linkage-type) দেখুন।

যদি কোনো মান (ফাংশনের বিপরীতে) একটি হেডারে ডিক্লেয়ার করা হয়, কিন্তু সোর্স ফাইলে ইনিশিয়ালাইজ করা মানসহ একটি `static` ফাইল স্কোপযুক্ত আইডেন্টিফায়ার হিসেবে ডিফাইন করা হয়, তাহলে তার ইনিশিয়ালাইজ করা মানটি তার সোর্স ফাইলের বাইরে থেকে অ্যাক্সেস করা যাবে না।
এটি হয়তো কোনো এরর ছাড়াই কম্পাইল, লিংক ও রান হতে পারে, কিন্তু মানটি ওই আইডেন্টিফায়ারের জন্য শূন্য মান হবে, এমনকি মানটি `extern` দিয়ে ডিক্লেয়ার করা হলেও।
(`extern` সম্পর্কে আরও জানতে [extern ধারণা](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#extern-how-to-access-a-variable-in-another-translation-unit) দেখুন।)
সোর্স ফাইলে `static` হিসেবে চিহ্নিত ফাইল স্কোপযুক্ত একটি আইডেন্টিফায়ার তার হেডার ফাইলে ডিক্লেয়ার করা উচিত নয়।
