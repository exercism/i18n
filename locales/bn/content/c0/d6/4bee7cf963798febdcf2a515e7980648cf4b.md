# ভূমিকা

হাতে লেখা অ্যাসেম্বলি পুনরাবৃত্তিতে ভরা।
একই ছোট ইনস্ট্রাকশনের ধারা বারবার দেখা যায়, সামান্য ভিন্নতাসহ, এবং বয়লারপ্লেট কমানোর জন্য খুব কম অ্যাবস্ট্রাকশন আছে।
শুধু তা-ই নয়, অ্যাসেম্বলিতে কোডিং করার সময় স্পষ্ট অর্থহীন মানগুলো পরিচালনা করতে হয়।
এখানে কোনো নামযুক্ত প্যারামিটার নেই এবং অন্তর্নিহিত মেশিনারির বেশিরভাগ বিবরণ প্রোগ্রামারকে নিজ হাতে সামলাতে হয়।

NASM, ট্র্যাকের ব্যবহৃত অ্যাসেম্বলার, কিছু টুল অফার করে যা প্রোগ্রামারকে উভয় সমস্যায় সাহায্য করতে পারে।
এই টুলগুলো _অ্যাসেম্বল টাইমে_ চলে, কোনো ইনস্ট্রাকশন প্রসেসরে পৌঁছানোর আগে।
এগুলো অ্যাসেম্বলারকে নির্দেশ দেয় কীভাবে সোর্স টেক্সট পুনর্লিখন করতে হয়, এমনকি এটি মেশিন কোডে রূপান্তরিত হওয়ার আগেই।

এই টুলগুলোর মধ্যে সবচেয়ে গুরুত্বপূর্ণ হলো **ম্যাক্রো**, যেগুলোকে অ্যাসেম্বলারের জন্য একটি রেসিপি হিসেবে ভাবা যায়।
এগুলো যেখানে ব্যবহার করা হয় সেখানেই এক্সপ্যান্ড করা হয়, যেন কোডটি সেখানে হাতে লেখা হয়েছে।

ম্যাক্রো প্যারামিটার হিসেবে একাধিক লিটারেল টোকেন নিতে পারে, যা তাদের বিভিন্ন প্রসঙ্গে পুনরায় ব্যবহারযোগ্য করে তোলে।
তবে, এগুলো ফাংশন নয়: কোনো `call` নেই, কোনো `ret` নেই, কোডের অন্য কোনো বিন্দুতে কন্ট্রোল ট্রান্সফার নেই।

## একক-লাইন ম্যাক্রো

সরলতম ডেফিনিশন `%define` দিয়ে একটি মান বা ছোট এক্সপ্রেশনকে একটি নাম দেয়:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

অ্যাসেম্বলির আগে `WIDTH`-এর পরবর্তী প্রতিটি উপস্থিতি `8` দিয়ে প্রতিস্থাপিত হয়।
প্রতিস্থাপনটি টেক্সটুয়াল, তাই নামটি যেখানেই আসুক না কেন, তা একটি অপারেন্ডে হোক বা অন্য ডেফিনিশনের ভিতরে, সর্বত্র প্রতিস্থাপিত হয়।

~~~~exercism/note
সাংখ্যিক _কনস্ট্যান্টের_ জন্য, `%define`-এর পরিবর্তে `equ` ব্যবহার করা ভালো।

`%define` দিয়ে ঘোষিত একটি একক-লাইন ম্যাক্রো শুধু ব্যবহার করার সময়ই এক্সপ্যান্ড হয়, এবং পুনরায় অ্যাসাইন করা বা undefined করা যেতে পারে।
অন্যদিকে, একটি `equ` কনস্ট্যান্ট ডেফিনিশনের সময়ই মূল্যায়িত হয় এবং কখনো পরিবর্তিত হয় না।
~~~~

একটি `%define` _নামযুক্ত_ প্যারামিটারও নিতে পারে, যা একটি ছোট ইনলাইন ফাংশনের মতো আচরণ করে:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
পুরো বডি এবং প্রতিটি প্যারামিটারকে বন্ধনীতে মুড়ে দিন।
`%define square(x) x*x` দিয়ে, `square(1+1)` কলটি `1+1*1+1`-এ এক্সপ্যান্ড হয়, যা `3`।
`%define square(x) ((x)*(x))` হিসেবে লেখা হলে, একই কলটি `((1+1)*(1+1))`-এ এক্সপ্যান্ড হয়, যা `4`।
~~~~

`%define` দিয়ে ডিফাইন করা নামগুলো কেস সেনসিটিভ।
ভ্যারিয়েন্ট `%idefine` নামটিকে কেস ইনসেনসিটিভ করে, যদি তা চাওয়া হয়।

একক-লাইন ম্যাক্রো কোডের বিভিন্ন অংশে অর্থ দিতে উপযোগী।
সাবধানে ব্যবহার করলে, এটি পাঠযোগ্যতা বাড়ায় এবং টাইপোর সম্ভাবনা কমায়।
উদাহরণস্বরূপ, একটি রেজিস্টার যার একটি ফাংশনের ভিতরে নির্দিষ্ট উদ্দেশ্য আছে, তা তার উদ্দেশ্য দিয়ে ডিফাইন করা যেতে পারে:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## মাল্টি-লাইন ম্যাক্রো

যেকোনো সংখ্যক লাইনের সম্পূর্ণ কোড সিকোয়েন্স `%macro` দিয়ে ধরা হয়, যা `%endmacro` দিয়ে বন্ধ করা হয়।
নামের পরে একটি সংখ্যা নির্দেশ করে ম্যাক্রোটি কতগুলো আর্গুমেন্ট নেয়, যা শূন্যও হতে পারে।
আর্গুমেন্ট পাস করা হলে, সেগুলো একটি কমা (`,`) দিয়ে পৃথক করা হয়:

```x86asm
%macro example_macro 0
...
%endmacro
```

মাল্টি-লাইন ম্যাক্রোতে আর্গুমেন্টের নাম থাকে না।
এগুলো `%1`, `%2`, ইত্যাদি হিসেবে উল্লেখ করা হয়, যে ক্রমে সেগুলো পাস করা হয় সেই ক্রমে:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

লক্ষ্য করুন যে আর্গুমেন্টগুলো ম্যাক্রোর বডিতে সম্পাদিত অপারেশনগুলোর জন্য বৈধ সিনট্যাক্স হতে হবে।
এখানে `mult_two eax, ecx` এবং `mult_two r8, r9` উভয়ই অ্যাসেম্বল হয়, কিন্তু `mult_two eax, cl` হবে না, কারণ `imul eax, cl` ডিফাইন করা নেই।

### ম্যাক্রোর ভিতরে লেবেল

একটি ম্যাক্রো যা একটি সাধারণ লেবেল ডিফাইন করে, সেটি দুইবার ব্যবহার করা হলে ভেঙে পড়ে, কারণ তখন লেবেলটিও দুইবার ডিফাইন হবে।
এমন একটি ম্যাক্রোর ভিতরে লেবেল ব্যবহার করতে যা একাধিকবার কল করা হতে পারে, সেই লেবেলের আগে `%%` প্রিফিক্স করা প্রয়োজন।
এটি অ্যাসেম্বলারকে নির্দেশ দেয় প্রতিটি এক্সপ্যানশনে এই লেবেলকে একটি ভিন্ন, অনন্য নাম দিতে:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## অ্যাসেম্বল টাইমে পুনরাবৃত্তি

`times` ব্যবহার করে এক-লাইনের কোড ব্লক পুনরাবৃত্তি করা সম্ভব।
এটি বিশেষভাবে উপযোগী যখন মেমরিতে পুনরাবৃত্ত মান ঘোষণা করা হয়:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

মাল্টি-লাইন কোড পুনরাবৃত্তির জন্য, আমরা পরিবর্তে `%rep` ব্যবহার করতে পারি:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

লক্ষ্য করুন যে পুনরাবৃত্তির সংখ্যা `%rep`-এর ঠিক পরেই নির্দিষ্ট করা হয় এবং পুনরাবৃত্ত ব্লক বন্ধ করতে একটি `%endrep` থাকে।

`%rep` ব্লকের ভিতরে একটি অ্যাসেম্বল-টাইম কাউন্টার ব্যবহার করা সাধারণ ব্যাপার, যেমন একটি রান-টাইম লুপ একটি কাউন্টার ব্যবহার করে।
যদিও একটি অ্যাসেম্বল-টাইম ইন্টিজার কনস্ট্যান্ট `equ` দিয়ে ঘোষণা করা যায়, অ্যাসেম্বল-টাইম ইন্টিজার _ভ্যারিয়েবলের_ জন্য আমরা পরিবর্তে `%assign` ব্যবহার করি।
`%define`-এর বিপরীতে, `%assign` তাৎক্ষণিকভাবে একটি সংখ্যায় মূল্যায়িত হয় এবং পুনরায় অ্যাসাইন করা যায়:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

প্রিপ্রসেসর চলার পরে, লুপটি চলে যায় এবং চারটি `add` ইনস্ট্রাকশন অবশিষ্ট থাকে, যেখানে `0`, `1`, `2`, এবং `3` ইমিডিয়েটগুলো বেক করা থাকে।
এটি অ্যাসেম্বলার দ্বারা করা লুপ আনরোলিং: কোনো কাউন্টার রেজিস্টার নেই এবং কোনো ব্রাঞ্চ নেই, শুধু সোজা-লাইন কোড।

## শর্তসাপেক্ষ অ্যাসেম্বলি

প্রিপ্রসেসরের জন্য বিভিন্ন কন্ডিশনাল উপলব্ধ।
এগুলো বিভিন্ন পাথের মধ্যে নির্বাচন করে, তাদের বডি ইন-প্লেস এক্সপ্যান্ড করে, কিন্তু শুধু যখন তাদের শর্ত সত্য হয়।

`%if` ... `%elif` ... `%else` ... `%endif` একটি সাংখ্যিক পরীক্ষা থেকে একটি ব্রাঞ্চ নির্বাচন করে:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## ফাইলে বিভক্ত করা

ম্যাক্রোগুলো প্রায়ই তাদের নিজস্ব একটি ফাইলে রাখা হয় এবং `%include` দিয়ে প্রতিটি সোর্সে টেনে আনা হয় যার সেগুলো প্রয়োজন:

```x86asm
%include "patterns.mac"
```

নামযুক্ত ফাইলটি অ্যাসেম্বলির আগে সেই বিন্দুতে হুবহু সন্নিবেশিত হয়, ঠিক যেন তার বিষয়বস্তু সেখানে টাইপ করা হয়েছে।
এটি ডেফিনিশনগুলোকে এক স্থানে রাখে এবং 여러 সোর্স ফাইলকে সেগুলো শেয়ার করতে দেয়।

যদি ম্যাক্রো ফাইলটি স্ট্যান্ডঅ্যালোন হিসেবে অ্যাসেম্বল করা হতে পারে, তাহলে এতে `.asm` ফাইল এক্সটেনশন থাকা উচিত।
লক্ষ্য করুন যে ম্যাক্রোগুলোর কোনো লিংকেজ নেই।
এমনকি যদি ম্যাক্রো ফাইলটি অ্যাসেম্বল করা হয়, তার ম্যাক্রোগুলো শুধু অন্য একটি ফাইলের কাছে দৃশ্যমান যে এটি `%include` করে।

অন্যথায়, একটি শুধুমাত্র `%include`-এর যেকোনো ফাইল এক্সটেনশন থাকতে পারে।
`.asm` বা `.mac` যেকোনোটির ব্যবহার একটি কমন কনভেনশন।
