# সম্পর্কে

`<dlist>` ([`dlists`][dlists]-এ) একটি নতুন ডাবলি-লিংকড লিস্ট তৈরি করে। অপারেশনগুলো থাকে [`deques`][deques]-এ এবং [ডেক প্রোটোকল][deque-protocol]-এর ওপর ডিসপ্যাচ করে, তাই অন্য কন্টেইনারগুলোও, বিশেষত `<dlist>`, সেগুলো ইমপ্লিমেন্ট করতে পারে।

| ওয়ার্ড         | প্রভাব                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`, নতুন খালি ডেক  |
| `push-front`    | `( elt deque -- )`, সামনের দিকে যোগ করে |
| `push-back`     | `( elt deque -- )`, পেছনের দিকে যোগ করে  |
| `pop-front`     | `( deque -- elt )`, সামনের দিক থেকে সরিয়ে ফেলে |
| `pop-back`      | `( deque -- elt )`, পেছনের দিক থেকে সরিয়ে ফেলে  |
| `peek-front`    | `( deque -- elt )`, সরিয়ে না ফেলেই সামনের দিকের মান পড়ে |
| `peek-back`     | `( deque -- elt )`, সরিয়ে না ফেলেই পেছনের দিকের মান পড়ে  |
| `deque-empty?`  | `( deque -- ? )`, ডেকটি কি খালি? |
| `dlist-length`  | `( dlist -- n )`, এলিমেন্টের সংখ্যা |

সব push/pop অপারেশন ডেকটিকে জায়গায় থাকতেই পরিবর্তন করে। একটি রুটিনে ডেক পাঠিয়ে পরে আবার তা থেকে পড়া খুব স্বাভাবিক প্যাটার্ন।

## স্ট্যাক বনাম কিউ

দুটি প্রচলিত ডিসপ্যাচ প্যাটার্ন:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

শুধু LIFO ক্রমই দরকার হলে `mutation` থেকে আসা `push` ও `pop`-সহ একটি ভেক্টরই সঠিক পছন্দ, কারণ `<dlist>`-এর সঙ্গে লিংকড-লিস্টের ওভারহেড থাকে। *দুই* প্রান্তেই O(1) দরকার হলে `<dlist>`-এর দিকে এগিয়ে যান, যা প্রায় সবসময়ই FIFO কিউয়ের ক্ষেত্রে দরকার হয়।

## BFS প্যাটার্ন

ব্রেডথ-ফার্স্ট সার্চ হলো FIFO-র ক্লাসিক ব্যবহার:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

ডেকটি সার্চের ফ্রন্টিয়ার বহন করে; হ্যাশ-সেটটি ডিডুপ্লিকেশন সামলায়। `pop-front`-এর বদলে `pop-back` বসালে একই আকারই ডেপথ-ফার্স্ট হয়ে যায়।

## `MEMO:` দিয়ে স্বয়ংক্রিয় ক্যাশিং

কখনও কখনও BFS যে নোড-ভিত্তিক লুকআপ ডাকে, তা ব্যয়বহুল হয়। Factor `:`-এর একটি বিকল্প [`MEMO:`][memo-decl] দেয়, যা ওয়ার্ডের ফলাফল তার ইনপুটের ভিত্তিতে স্বয়ংক্রিয়ভাবে ক্যাশ করে:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

একটি `MEMO:` ওয়ার্ড প্রতিটি ইনপুট প্রথমবার দেখার সময়ই তার বডি চালায় এবং এরপর ক্যাশ করা ফলাফল রিটার্ন করে। ক্যাশটি ইমেজের আয়ুষ্কাল পর্যন্ত থাকে; সময় বা আকারভিত্তিক কোনো এভিকশন নেই। যেসব পিউর ফাংশনের ইনপুট একটি সীমিত, সামলানো-সহজ সেট থেকে আসে, তাদের জন্য এটি ব্যবহার করুন।
