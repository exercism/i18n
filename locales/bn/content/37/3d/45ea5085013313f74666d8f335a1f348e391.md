# পরিচিতি

আমাদের প্রোগ্রামে কাস্টম টাইপ ডিফাইন করা প্রায়ই কাজে লাগে।

নতুন প্রিমিটিভ টাইপ তৈরি করা সম্ভব, তবে তা খুব কমই করা হয়।
বিল্ট-ইন প্রিমিটিভ টাইপগুলো কোনো ইচ্ছেমতো নেওয়া সিদ্ধান্ত নয়: JIT কম্পাইলেশনের জন্য Julia যে LLVM কম্পাইলার ব্যবহার করে, তার স্ট্যান্ডার্ড টাইপগুলোর সাথে এগুলো খুব কাছাকাছি মেলে।

আরও অনেক বেশি কাজে লাগে নেইমড ফিল্ডসহ কম্পোজিট টাইপ ডিফাইন করার সুবিধা।

অন্য ভাষাতেও এরকম কিছু আছে, যেগুলোকে `structs` বা `records` বলা হয়।
Julia-র ডকুমেন্টেশনে এগুলোকে `composite types` বলা হয়, যদিও (একটু অমিল রেখেই) ভাষার সিনট্যাক্সে এগুলো `struct` কিওয়ার্ড দিয়ে ডিফাইন করা হয়।

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

উপরের উদাহরণে কয়েকটি বিষয় লক্ষ করার মতো:

- `id`-এর জন্য কোনো টাইপ নির্দিষ্ট করা নেই, তাই কম্পাইলার এটিকে `id::Any` হিসেবে ধরে নেয়।
- `Person` টাইপের একটি ইনস্ট্যান্স পেতে টাইপের নামটিই কনস্ট্রাক্টর হিসেবে ব্যবহৃত হয়, যেমন `Person(id, name, age)`।
- আলাদা আলাদা ফিল্ড ডট নোটেশন দিয়ে অ্যাক্সেস করা যায়, ঠিক নেইমড টাপলের মতোই।

`Person` টাইপের আইটেমগুলো ইমিউটেবল, তাই আপডেট করা যায় না।

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

যদি মিউটেবিলিটি দরকার হয়, তাহলে ডেফিনিশনে `mutable` যোগ করুন।

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

ডিফল্টভাবে কনস্ট্রাক্টর চায় ফিল্ডগুলো ডেফিনিশনের মতো একই ক্রমে থাকুক, যা আরও জটিল টাইপের ক্ষেত্রে অসুবিধাজনক হয়ে দাঁড়ায়।

`@kwdef` ম্যাক্রো ব্যবহার করলে দুটি নতুন সুবিধা পাওয়া যায়:

- কনস্ট্রাক্টর পজিশন নয়, কিওয়ার্ড ব্যবহার করে।
- ফিল্ডগুলোর ডিফল্ট মান থাকতে পারে, আর চাইলে সেগুলো কনস্ট্রাক্টর থেকে বাদও দেওয়া যায়।

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## কম্পোজিট টাইপ হায়ারার্কি

এখন পর্যন্ত আমরা শুধু কংক্রিট কম্পোজিট টাইপ তৈরি করেছি।
খেয়াল করলে দেখবেন, সবগুলোই `Any`-এর সাবটাইপ।

একসাথে সম্পর্কিত একাধিক টাইপ তৈরি করার সময়, সম্ভবত সেগুলোর জন্য একটি হায়ারার্কি ডিফাইন করাই বেশি যুক্তিসঙ্গত।
এটা খুব সহজেই করা যায়।

প্রথমে একটি অ্যাবস্ট্রাক্ট টাইপ তৈরি করুন:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

এরপর, সম্পর্কটা বোঝাতে টাইপ ডেফিনিশনে একটি `<:` অপারেটর যোগ করুন।

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

যতবার দরকার ততবারই পুনরাবৃত্তি করুন, তবে মনে রাখবেন কংক্রিট টাইপের সাবটাইপিং অনুমোদিত নয়।

আরও জটিল হায়ারার্কির জন্য, দরকার অনুযায়ী অ্যাবস্ট্রাক্ট সাবটাইপ তৈরি করুন।

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

এমন হায়ারার্কির সুবিধা আরও স্পষ্ট হবে যখন আমরা `Multiple Dispatch` কনসেপ্টে পৌঁছাব, আর দেখব কীভাবে ফাংশনগুলো আর্গুমেন্ট টাইপ সামলায়।
