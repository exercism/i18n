# পরিচিতি

ফাংশনের সঙ্গে পরিচয় হয়েছিল আগের [মৌলিক বিষয়][concept-basics] ধারণা পাতায়, এ রকম উদাহরণ দিয়ে:

```R
squareit <- function(x) {
    x * x
}

squareit(3)
#> [1] 9

# shorter form
squareit_short <- function(x) x ^ 2
```

`squareit`-এর ডেফিনিশনটি একটু ভালো করে দেখলে এর বিভিন্ন অংশ চিহ্নিত করা যায়:

- ফাংশনটি একটি ফরমাল আর্গুমেন্ট `x` নেয়।
- এর একটি ফাংশন বডি থাকে, যা সাধারণত ব্রেস `{ }`-এর মধ্যে লেখা হয়।
- ফাংশন অবজেক্টটি তৈরি হওয়ার পর এটি একটি ভ্যারিয়েবল `squareit`-এ অ্যাসাইন করা হয়।

R-এ একটি ফাংশন ফার্স্ট ক্লাস অবজেক্ট, সংখ্যা আর স্ট্রিং-এর মতোই। তাই `squareit <- function...` আসলে একটি অ্যাসাইনমেন্ট, সিনট্যাক্সের দিক থেকে যা `x <- 42`-এর মতোই।

## আর্গুমেন্ট

Python বা Julia-র মতো অন্য স্ক্রিপ্টিং ভাষার বিপরীতে R পজিশনাল আর্গুমেন্ট আর কিওয়ার্ড আর্গুমেন্টের মধ্যে স্পষ্ট কোনো পার্থক্য করে না।

ফাংশন কলের সময় মান পাস করা যায় দুইভাবে: পজিশন অনুযায়ী, বা নাম ধরে। অনেক আর্গুমেন্টওয়ালা জটিল ফাংশনের ক্ষেত্রে নাম ধরে পাস করা সুবিধাজনক, কারণ তখন আর্গুমেন্টগুলোর ক্রম মনে রাখতে হয় না।

```R
f <- function(x, y) x / y

# call positionally
f(4, 2)
#> [1] 2

# call by name
f(y = 2, x = 4)
#> [1] 2
```

### অপশনাল আর্গুমেন্ট

ফাংশন ডেফিনিশনে ডিফল্ট আর্গুমেন্ট মান দেওয়া যায়, তবে সেগুলোকে ডিফল্টহীন সব আর্গুমেন্টের পরে বসাতে হবে।

এরপর আমরা চাইলে ডিফল্ট মানটি গ্রহণ করতে পারি, আবার সেটি বদলে দিতে পারি।

```R
g <- function(x, y = 2) x / y

# default y value
g(6)
#> [1] 3

# explicit y value
g(6, 3)
#> [1] 2
```

### বাড়তি আর্গুমেন্ট

যত খুশি বাড়তি আর্গুমেন্ট নিতে চাইলে ডেফিনিশনে একটি `...` (ইলিপসিস) ব্যবহার করুন। ফাংশন কলে দেওয়া বাড়তি মানগুলো চাইলে একটি ভেক্টরে রূপান্তর করা যায়, তবে এই "ডট আর্গ"গুলো (*অন্য অনেক ভাষায় যাদের "ভ্যারআর্গস" বলা হয়*) ব্যবহারের বিকল্প একটি উপায় জানতে পড়তে থাকুন।

```R
var_f <- function(x, y, ...) {
  print(c(...))
}

var_f(2, 3, "opt1", "opt2")
#> [1] "opt1" "opt2"
```

## ফাংশন এনভায়রনমেন্ট

আগে আমরা বলেছিলাম, ফরমাল আর্গুমেন্ট আর বডি, দুটিই একটি ফাংশনের উপাদান।

আসলে এর একটি তৃতীয় উপাদানও আছে: *এনভায়রনমেন্ট*, যেখানে ফাংশনটি ডিফাইন করা হয়।

নেস্টেড ফাংশনের উদাহরণ দিয়ে এটি বোঝা যায়:

```R
outer_func <- function(x) {
  inner_func <- function(y) {
    x * y
  }
  
  inner_func(3)
}

outer_func(5)
#> [1] 15
```

ফাংশন কলটি `x = 5` বাইরের ফাংশনে পাঠায়, আর এই মানটি ওই ফাংশন বডির ভেতরে ব্যবহারযোগ্য থাকে।

ভেতরের ফাংশনটি বাইরের ফাংশন বডিরই *একটি অংশ*, আর তাই এর `x`-এর মানে হাত আছে। অন্যভাবে বললে, `x = 5` আছে ভেতরের ফাংশনের *এনভায়রনমেন্টে*।

প্রযুক্তিগতভাবে একে বলা হয় [ক্লোজার][wiki-closure]।

ডট আর্গের ক্ষেত্রে এনভায়রনমেন্ট বিশেষভাবে গুরুত্বপূর্ণ, কারণ এভাবে দেওয়া যেকোনো মান ফাংশন বডির ভেতরের ফাংশন কলগুলোতে পাস করা যায়। ডট আর্গগুলোর মানে কী, তা বাইরের ফাংশনকে জানতেও হয় না, ভাবতেও হয় না।

```R
f_var <- function(x, ...) {
  sum(x, ...)
}

x <- c(1, 2, NA, 6)

# for sum(), na.rm defaults to FALSE
f_var(x)
#> [1] NA

# pass through the na.rm value
f_var(x, na.rm = TRUE)
#> [1] 9
```

এই কৌশলটি টাইডিভার্সের লাইব্রেরিগুলো, যেমন [`stringr`][ref-stringr], ব্যাপকভাবে ব্যবহার করে। `stringr`-এর অনেক ফাংশনই আসলে `stringi` আর বেস R-এর লো-লেভেল ফাংশনের চারপাশে একটি ব্যবহারবান্ধব র্যাপার।

`str_*()` ফাংশনগুলোতে দেওয়া বাড়তি আর্গুমেন্ট কেবল ওই নিচু স্তরের ফাংশনগুলোতেই পাস হয়ে যায়।

## রিটার্ন ভ্যালু হিসেবে ফাংশন

একটি বাইরের ফাংশন তার ভেতরে আরেকটি ফাংশন ডিফাইন করতে পারে (নামযুক্ত, বা নিচে বর্ণিত অ্যানোনিমাস) এবং সেটিকেই রিটার্ন ভ্যালু হিসেবে ব্যবহার করতে পারে।

যে ফাংশনটি রিটার্ন হয়, তার সঙ্গে তার ডিফাইন করার এনভায়রনমেন্টটিও থাকে।

```R
times_y <- function(x) {
  # anonymous function - see next section
  \(y) x * y
}

f <- times_y(3)
class(f)
#> [1] "function"

f(4)
#> [1] 12
```

## অ্যানোনিমাস ফাংশন

ফাংশন ডিফাইন করার সময় আমরা সাধারণত ফলাফল ফাংশন অবজেক্টটিকে একটি ভ্যারিয়েবলের সঙ্গে বেঁধে রাখি:

```R
x <- 2

# function definition captures x from the environment
doubleit_short <- function(y) x * y
```

এতে স্ক্রিপ্টের পরের অংশে ফাংশনটি ব্যবহার করা সহজ হয়, তবে এভাবে বেঁধে রাখা বাধ্যতামূলক নয়। ছোট, একবারই ব্যবহারের ফাংশন ঠিক ওই জায়গাতেই কাজে লাগতে পারে। নামের সঙ্গে বাঁধা না থাকলে একে বলা হয় *অ্যানোনিমাস ফাংশন*।

অ্যানোনিমাস ফাংশনের ব্যবহার এতটাই সাধারণ যে (*R v4.1.0 থেকে*) এগুলো ডিফাইন করার একটি সংক্ষিপ্ত সিনট্যাক্স আছে: `function` শব্দটির বদলে ব্যাকস্ল্যাশ `\` লিখুন।

এর একটি উদাহরণ আগের অংশে, রিটার্ন ভ্যালু নিয়ে আলোচনায় ছিল।

## কপি অন মডিফাই

R-এ ভেক্টরের আলাদা আলাদা এলিমেন্টে অ্যাসাইন করা যায়। যদি কোনো ভেক্টর ফাংশনের আর্গুমেন্ট হিসেবে পাঠিয়ে ফাংশন বডির ভেতরে সেটি বদলে তারপর রিটার্ন করি, তাহলে আমরা একটি বদলে যাওয়া ভেক্টর পাই।

কিন্তু আসল ভেক্টরটির কী হলো?

```R
f <- function(vec) {
  vec[1] <- 42
  vec
}

vals <- c(1, 3, 4)

# f() returns a modified vector
f(vals)
#> [1] 42  3  4  

# the original vector is unchanged.
vals
#> [1] 1 3 4
```

R হলো ডেটা সায়েন্সের জন্য তৈরি একটি ভাষা। এই ডেটা সংগ্রহ করতে সময়, পরিশ্রম আর অনেক সময় চোখ কপালে ওঠানো পরিমাণ অর্থও লাগতে পারে: *তাই ডেটা নষ্ট না করা খুব জরুরি!*

সাধারণ নীতি (কয়েকটি ব্যতিক্রম ছাড়া) হলো *কপি অন মডিফাই*। যদি কোনো অবজেক্ট (যেমন একটি ভেক্টর) এমনভাবে বদলানো হয় যা পরে সমস্যা ডেকে আনতে পারে, তাহলে R একটি *বদলে যাওয়া কপি* ফেরত দেয় আর আসলটি অপরিবর্তিত রেখে দেয়।

বড় ডেটা স্ট্রাকচার কপি করা কম্পিউটেশনের দিক থেকে খরচসাপেক্ষ হতে পারে, তবে বিকল্পটি যদি ডেটা নষ্ট হওয়া হয়, তাহলে সাধারণত এটাই কম ক্ষতিকর।
