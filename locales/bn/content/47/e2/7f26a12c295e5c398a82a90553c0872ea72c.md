# পরিচিতি

C ভাষায় একটি **struct** হলো একটি যৌগিক টাইপ, যা বিভিন্ন ফিল্ড দিয়ে গঠিত। প্রতিটি ফিল্ডের নিজস্ব টাইপ ও আকার থাকে।

উদাহরণস্বরূপ, এটি তিনটি ইন্টিজার দিয়ে গঠিত একটি টাইপ সংজ্ঞায়িত করে, যার দুটি ৪ বাইটের আর একটি ৮ বাইটের:

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

একটি struct-এর ভেতরে অন্য struct-ও থাকতে পারে:

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

struct-এর কোনো একটি ফিল্ড যদি অ্যারে হয়, তাহলে ওই অ্যারের জন্য বরাদ্দ করা সব বাইটই struct-এর অংশ। কিন্তু ফিল্ডটি যদি শুধুই অ্যারেটির প্রতি একটি পয়েন্টার হয়, তাহলে অ্যারেটি অন্য কোথাও সংরক্ষণ করতে হবে:

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## অ্যালাইনমেন্ট

একটি টাইপের **অ্যালাইনমেন্ট** হলো দুইয়ের একটি অ-ঋণাত্মক ঘাত (১, ২, ৪, ৮, ...), যা ওই টাইপের অ্যাড্রেসের উপর একটি শর্ত আরোপ করে। ওই টাইপের প্রতিটি অবজেক্টকে এমন একটি অ্যাড্রেসে থাকতে হবে, যা তার অ্যালাইনমেন্টের গুণিতক।

প্রিমিটিভ টাইপের ক্ষেত্রে অ্যালাইনমেন্ট সাধারণত তার আকারের সমান হয়, তাই উদাহরণস্বরূপ `int32_t`-এর অ্যালাইনমেন্ট সাধারণত ৪ বাইট। এর মানে হলো `int32_t`-কে ৪ বাইটের সীমানায় বরাদ্দ করতে হবে।

তবে struct-এর অ্যালাইনমেন্ট হলো তার যেকোনো ফিল্ডের সর্বোচ্চ অ্যালাইনমেন্ট। তাই, উদাহরণস্বরূপ, উপরে সংজ্ঞায়িত `struct example`-এর অ্যালাইনমেন্ট হবে ৮ বাইট, কারণ এটিই `uint64_t`-এর অ্যালাইনমেন্ট।

struct-এর কোনো ফিল্ডের অ্যালাইনমেন্ট যদি struct-এর অ্যালাইনমেন্টের চেয়ে ছোট হয়, তাহলে ওই ফিল্ডের পরে প্যাডিং বাইট যোগ করা হতে পারে। এতে পরের ফিল্ডগুলো এবং সামগ্রিকভাবে struct-টি অ্যালাইনমেন্টের শর্ত পূরণ করে। বাস্তবে এর মানে হলো, ওই প্যাডিং বাইটগুলো struct-এর আকারে যোগ হলেও struct-এর মানে ব্যবহৃত হয় না:

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

লক্ষ করুন, উপরে সংজ্ঞায়িত struct-টিতে 'one_byte' ফিল্ডের অ্যালাইনমেন্ট ১ এবং এটি যেকোনো অ্যাড্রেসে রাখা যায়। যেহেতু 'four_byte' ফিল্ডের অ্যালাইনমেন্ট ৪, তাই struct-এর ফিল্ডগুলোকেও ৪ বাইটের সীমানা মানতে হবে। এর মানে হলো, struct-এর যেকোনো দুটি ফিল্ডের মধ্যে বাইটসংখ্যা ৪-এর গুণিতক হতে হবে। যেহেতু 'one_byte' মাত্র ১ বাইট জুড়ে থাকে, তাই এই সীমানা মানতে এর পরে ৩টি প্যাডিং বাইট যোগ করা হয়।

প্রয়োজনীয় প্যাডিং বাইটের সংখ্যা কমাতে সম্ভব হলে পাশাপাশি ফিল্ডগুলোকে দলবদ্ধ করা হয়:

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

এই দলবদ্ধকরণে প্রতিটি ফিল্ডের অ্যালাইনমেন্টও মানতে হবে:

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

এর মানে হলো, struct-এ ফিল্ডের ক্রম বদলালে কখনো কখনো তার আকারেও পার্থক্য আসতে পারে:

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

লক্ষ করুন, একটি অ্যারের অ্যালাইনমেন্ট তার অন্তর্নিহিত টাইপের অ্যালাইনমেন্টের সমান:

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

অ্যারের এলিমেন্টগুলোকে এমনভাবে দলবদ্ধ করা যায়, যেন তারা অ্যারের অংশই নয়:

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

অ্যাসেম্বলিতে কোনো struct অ্যাক্সেস করার সময় সম্ভাব্য সব প্যাডিং বাইট হিসাবের মধ্যে রাখা জরুরি।

## কলিং কনভেনশন

সাধারণভাবে, ফাংশনে মান পাঠানো ও ফাংশন থেকে মান ফেরানো প্রত্যাশামাফিকভাবেই ঘটে:

- মেমরি অ্যাড্রেস ও এনামসহ ইন্টিজার মানগুলো জেনারেল-পারপাস রেজিস্টারে (GPR) পাঠানো হয়।
- ফ্লোটিং-পয়েন্ট মানগুলো `xmm` রেজিস্টারে পাঠানো হয়।

তবে struct একটি বিশেষ ক্ষেত্র। সাধারণ নিয়ম হিসেবে, struct-এর সব ফিল্ড মেমরিতে পাশাপাশি জায়গা দখল করে এবং সম্ভব হলে তাদের একটিমাত্র রেজিস্টারে রাখা উচিত:

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

struct-এর কিছু ফিল্ডে ইন্টিজার মান আর কিছু ফিল্ডে ফ্লোটিং-পয়েন্ট মান থাকলে struct-এর প্রতিটি পরপর ৮ বাইট আলাদা করে শ্রেণিবদ্ধ করতে হবে:

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

ইন্টিজার ও ফ্লোটিং-পয়েন্ট মান একই ৮ বাইটে পড়লে টাইপটি ইন্টিজার ধরা হয় এবং পুরো ৮ বাইট (ফ্লোটিং-পয়েন্ট মানসহ) একটি GPR-এ রাখা হয়:

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
`cvtss2si` বা `cvtsd2si` ব্যবহার করে ফ্লোটিং-পয়েন্ট থেকে ইন্টিজারে রূপান্তর করলে অন্তর্নিহিত বাইটের বিন্যাস বদলে যায়।

বিট উপস্থাপনা না বদলেই একটি `xmm` রেজিস্টার থেকে একটি GPR-এ কাঁচা বাইট সরাতে `movd` (৩২-বিট মানের জন্য) ও `movq` (৬৪-বিট মানের জন্য) ব্যবহার করতে পারেন।
~~~~

তবে ১৬ বাইটের বেশি আকারের struct সাধারণত মেমরিতে রাখা হয়, প্রতিটি ৮ বাইটের টাইপ যা-ই হোক:

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

কোনো struct ফাংশনে আর্গুমেন্ট হিসেবে পাঠালে যত রেজিস্টার দরকার তত রেজিস্টার ব্যবহার করে। এটি মেমরিতে রাখা হলে বদলে স্ট্যাক ব্যবহার করা হয়।

কোনো ফাংশন থেকে ফেরত আসা struct-এর ক্ষেত্রেও একই ধরনের নিয়ম প্রযোজ্য। এগুলো সাধারণত প্রথমে `rax` ও `rdx`-এ ফেরত আসে (ইন্টিজার মান হলে) বা `xmm0` ও `xmm1`-এ (ফ্লোটিং-পয়েন্ট মান হলে)। তবে মেমরিতে রাখা হলে কলকারীকে এর জন্য জায়গা সংরক্ষণ করতে হয় এবং ফাংশনের কাছে অন্তর্নিহিত প্রথম আর্গুমেন্ট হিসেবে এই মেমরি অবস্থানের অ্যাড্রেসটি পাঠাতে হয় (`rdi`-তে)। এরপর ফাংশন ওই জায়গায় struct-টি সংরক্ষণ করে এবং `rax`-এ তার অ্যাড্রেস ফেরত দেয়।
