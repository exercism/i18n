# ভূমিকা

Factor-এর এরর সিস্টেমে তিনটি অংশ আছে: এরর সংকেত দিতে `throw`, একটি হ্যান্ডেল করতে `recover`, আর নিজের ধরনের এরর ডিফাইন করতে `ERROR:`।

## `throw`

[`kernel`][kernel]-এ থাকা `throw` একটি এরর তৈরি করে। আর্গুমেন্টটি *যেকোনো* মান হতে পারে, একটি স্ট্রিং, একটি সংখ্যা বা একটি টাপল, আর এটিই পরে আপনি যে এররটি পরীক্ষা করতে পারবেন সেটি হয়ে যায়:

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw` রিটার্ন করে না; বর্তমান ওয়ার্ডের বাকি অংশটুকু বাদ পড়ে যায়।

## `recover`

[`continuations`][continuations]-এ থাকা `recover` হলো Factor-এর try/catch। এটি একটি *try* কোয়োটেশন আর একটি *recovery* কোয়োটেশন নেয়:

```
recover ( try recovery -- )
```

`try` যদি কোনো এরর থ্রো না করে শেষ হয়, তবে `recovery` উপেক্ষিত হয়। `try` যদি এরর থ্রো করে, তবে এররটি স্ট্যাকে পুশ করা হয় আর `recovery` রান করা হয়:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

[`kernel`][kernel]-এর `when` হলো এর স্বাভাবিক সঙ্গী: স্ট্যাকের উপরের মানটি ট্রুথি হলে তবেই এটি একটি কোয়োটেশন রান করে:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:` একটি টাপল ক্লাস *আর* এমন একটি ওয়ার্ড ডিফাইন করে যা নতুন একটি ইনস্ট্যান্স তৈরি করে সেটি থ্রো করে:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

স্লটবিহীন একটি এরর কেবল `ERROR: name ;`, এখানে `name` কল করলে একটি খালি ইনস্ট্যান্স থ্রো হয়। `ERROR:` দিয়ে ডিফাইন করা টাপলের সাথে একটি ক্লাস প্রেডিকেট `name?` থাকে, যা দিয়ে ধরা পড়া এররটি ওই টাইপের কি না তা পরীক্ষা করতে পারেন।

## স্লট থেকে মান আবার বের করা

ধরা পড়া একটি এরর কেবল একটি টাপল, তাই `ERROR:`-এর প্রতিটি স্লটের সাথে অন্য যেকোনো টাপলের মতোই স্বয়ংক্রিয়ভাবে তৈরি একই `slot>>` রিডার থাকে।

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
