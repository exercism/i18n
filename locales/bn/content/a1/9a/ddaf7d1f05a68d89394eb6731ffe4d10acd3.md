# ভূমিকা

একটি *ডেক* (ডাবল-এন্ডেড কিউ) উভয় প্রান্তে O(1) সময়ে পুশ ও পপ সমর্থন করে। Factor-এর স্ট্যান্ডার্ড ইমপ্লিমেন্টেশন হলো [`dlists`][dlists]-এ থাকা `<dlist>` (একটি ডাবলি-লিংকড লিস্ট); আর অপারেশনগুলো থাকে [`deques`][deques]-এ।

## ডেকের API

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` ডেকটি জায়গাতেই খালি করে দেয়, যা আবার মেমরি বরাদ্দ না করে পুনর্ব্যবহারের জন্য কাজে লাগে।

একই প্রান্তে পুশ ও পপ করলে পাওয়া যায় LIFO স্ট্যাক। এক প্রান্তে পুশ করে অন্য প্রান্তে পপ করলে পাওয়া যায় FIFO কিউ:

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

LIFO-র জন্য হাত বাড়াবেন একটি ভেক্টরের দিকে (`V{ }`), যেটিতে `push`/`pop` আছে এবং প্রতি অপারেশনে ওভারহেড কম। আর যখন *উভয়* প্রান্তেই O(1) দরকার, তখন `<dlist>`-এর দিকে হাত বাড়ান; এমনটা প্রায় সবসময়ই দরকার হয় একটি FIFO কিউ-র জন্য।

## ব্রেডথ-ফার্স্ট সার্চ

এই FIFO ব্যবহারই ডেককে *BFS*-এর জন্য উপযুক্ত ফ্রন্টিয়ার করে তোলে। আপনি শুরু করেন একটি মাত্র নোড দিয়ে, প্রতিবেশীদের পুশ করেন পেছনে, সামনের দিক থেকে প্রার্থীদের পপ করেন, আর হ্যাশ-সেট দিয়ে ডিডাপ করেন:

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

পুরোনো প্রার্থীদের দেখা হয় নতুনদের আগে, তাই সার্চ শুরু থেকেই স্তরে স্তরে বাইয়ের দিকে ছড়িয়ে পড়ে। এটাই BFS-কে তার সংক্ষিপ্ততম-পথের ধর্ম দেয়: কোনো লক্ষ্য নোডে আপনি প্রথম যে পথে পৌঁছান, সেটি ন্যূনতম হপের পথ।

## `MEMO:` দিয়ে স্বয়ংক্রিয় ক্যাশিং

কখনও কখনও BFS যে প্রতি-নোড লুকআপ করে, সেটি ব্যয়বহুল হয়। Factor-এর [`memoize`][memoize] ভোকাব আপনাকে দেয় `MEMO:`, যা `:`-এর জায়গায় সরাসরি বসিয়ে দেওয়া যায় এবং ইনপুটের ভিত্তিতে ওয়ার্ডের ফলাফল ক্যাশ করে রাখে:

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

একটি `MEMO:` ওয়ার্ড প্রতিটি ইনপুট প্রথমবার দেখার সময় তার বডি চালায়, আর এরপর ক্যাশ করা ফলাফল রিটার্ন করে। ইন্টারফেস একই, কল করা জায়গায় বাড়তি কোনো কল নেই, শুধু বারবার ব্যবহারে দ্রুততর।
