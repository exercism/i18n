# পরিচিতি

## অপশনাল

Swift [_অপশনাল_][optionals] ব্যবহার করে প্রোগ্রামারদের একটি মানের সম্ভাব্য অনুপস্থিতি প্রকাশ করার সুযোগ দেয়।
অপশনাল এমন একটি টাইপ, যা হয় একটি মান ধারণ করতে পারে, নয়তো [`nil`][nil] হতে পারে, যা একটি মানের অনুপস্থিতিকে বোঝায়।
একটি অপশনাল ব্যবহার করার আগে প্রোগ্রামকে যাচাই করতে হয় যে সত্যিই কোনো মান আছে কি না, এবং আনর‍্যাপ করার পরই সেটি ব্যবহার করা যায়।

যেকোনো টাইপের নামের শেষে একটি `?` যোগ করে সেটিকে অপশনাল বানানো যায়।
তাই একটি অপশনাল ইন্টিজারের টাইপ হবে `Int?` এবং একটি অপশনাল স্ট্রিংয়ের টাইপ হবে `String?`।
অপশনাল টাইপের কনস্ট্যান্ট বা ভ্যারিয়েবল ডিফাইন করা এবং সেগুলোতে মান অ্যাসাইন করাও নন-অপশনাল টাইপের মানের মতোই করা হয়।

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

অপশনাল টাইপের একটি ভ্যারিয়েবলে বিশেষ মান `nil` অ্যাসাইন করে আপনি মানের অনুপস্থিতি বোঝাতে পারেন।
`nil` সব অপশনাল টাইপের সাথেই ব্যবহার করা যায়, তবে দুইটি ভিন্ন অপশনাল টাইপে অ্যাসাইন করা `nil`-এর টাইপ এক নয়, তাই সেগুলো একটির বদলে আরেকটি ব্যবহার করা যায় না, এমনকি তুলনাও করা যায় না।

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

লক্ষণীয়, `nil` যেকোনো অপশনাল টাইপে অ্যাসাইন করা গেলেও নন-অপশনাল টাইপে অ্যাসাইন করা যায় না (এমনকি যদি সেটি সত্যিই `nil` ধারণ না করে)।
আর যে মেথড একটি নন-অপশনাল টাইপ আশা করে, তাকে আগে আনর‍্যাপ না করে কোনো অপশনাল টাইপ পাঠানো যায় না।

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## অপশনাল ব্যবহার

যেহেতু অপশনাল টাইপ আর তাদের বেস টাইপ এক নয়, তাই দুটি টাইপকে একইভাবে ব্যবহার করা যায় না।
উদাহরণস্বরূপ: `Int("123") + 1` লিখলে কম্পাইলার এরর আসে "Value of optional type 'Int?' must be unwrapped to a value of type 'Int'"।
এর কারণ, `Int("123")` রিটার্ন করে একটি অপশনাল `Int?` টাইপ, `Int` টাইপ নয়, কারণ স্ট্রিংটি যদি ইন্টিজারে রূপান্তর করা না যায়, তাহলে ফলাফল হবে `nil`।
রূপান্তরের ফলে পাওয়া `Int`-এ পৌঁছাতে হলে প্রথমে সেটি "আনর‍্যাপ" করতে হয়।

Swift-এ এটি সবচেয়ে বেশি করা হয় [_অপশনাল বাইন্ডিং_][optional-binding]-এর জন্য `if-let` এবং `guard-let` গঠন দিয়ে, যা `nil` আছে কি না তা যাচাই করে এবং মান থাকলে আনর‍্যাপ করা মানটি দেওয়া একটি নামের সাথে বাইন্ড করে একটি কোড পথ নেয়, আর `nil` পাওয়া গেলে অন্য একটি কোড পথ নেয়।

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

লক্ষণীয়, `safeNum` ভ্যারিয়েবলের টাইপ `Int`, `Int?` নয়।
নিচের উদাহরণে `num`-এর টাইপ `Int?` এবং `safeNum`-এর টাইপ `Int`।

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

এই _অপশনাল বাইন্ডিং_ গুরুত্বপূর্ণ, কারণ এটি মান থেকে অপশনাল টাইপটি আনর‍্যাপ করে (অর্থাৎ "সরিয়ে দেয়"), ফলে মানটিকে নন-অপশনাল মান হিসেবে ব্যবহার করা যায়।
আপনি যদি শুধু শর্ত যাচাই করে দেখেন মানটি `nil` কি না, তাহলে মানটির টাইপ তখনও অপশনালই থেকে যায়:

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

যেসব ক্ষেত্রে আগেই রিটার্ন করে বেরিয়ে যেতে চান, সেখানে `guard-let`-ও ব্যবহার করা যায়:

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## অপশনাল তুলনা করা

লক্ষ্য করুন, এক জোড়া অপশনালের বেস টাইপকে স্ট্যান্ডার্ড তুলনা অপারেটর দিয়ে তুলনা করা গেলেও অপশনালগুলো নিজেদের মধ্যে তুলনা করা যায় না।
কেবল তাদের সমতা যাচাই করা যায়।
দুটি অপশনাল সমান হয় যদি দুটিই `nil` হয়, অথবা তারা যে মানগুলো ধারণ করে সেগুলো তাদের বেস টাইপের মধ্যে সমান হয়।

তবে দুইটি অপশনাল মানের কাস্টম তুলনা করার কোড লেখা যায়।
নিচে একটি `switch` স্টেটমেন্টের উদাহরণ দেওয়া হলো, যা কেবল তখনই `true` রিটার্ন করবে যদি দুটি অপশনাল মানই nil না হয় এবং প্রথম মানটি দ্বিতীয়টির চেয়ে ছোট হয়।
এটি করতে গিয়ে স্টেটমেন্টটি _অপশনাল প্যাটার্ন_ `varName?` ব্যবহার করে, যা কেবল nil নয় এমন অপশনালের সাথে মেলে এবং অপশনালের ভেতরের মানটি `varName` নামের সাথে বাইন্ড করে।

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## নিল কোলেসিং

আনর‍্যাপ করার আরেকটি উপায় আছে, যেখানে `nil` থাকলে একটি [ফলব্যাক মান][fallback] ব্যবহার করা যায়।
এটি করা হয় _নিল কোলেসিং অপারেটর_ `??` দিয়ে।
ধরে নিন `x` একটি `Int?`; কেউ যদি `let y = x ?? 0` লেখেন, তাহলে Swift যাচাই করবে x কি `nil`।
যদি না হয়, তাহলে এটি `x` আনর‍্যাপ করে আনর‍্যাপ করা মানটি `y`-তে অ্যাসাইন করবে, আর `x` যদি _সত্যিই_ `nil` হয়, তাহলে `y`-তে 0 অ্যাসাইন করবে।

যেহেতু `x ?? y` আসলে `x != nil ? x! : y`-এর সংক্ষিপ্ত রূপ, তাই `x` যদি nil না হয়, তাহলে `y` এক্সপ্রেশনটি একেবারেই মূল্যায়ন করা হয় না।

সবশেষে লক্ষণীয়, নিল কোলেসিং অপারেটরটি ডান-অ্যাসোসিয়েটিভ, যা না জানা থাকলে চমকে দেওয়ার মতো ফলাফল দিতে পারে।

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```
