# ভূমিকা

আগের অনুশীলনীতে আমরা দেখেছি, Go-তে কমেন্ট লেখার দুটি উপায় আছে: এক লাইনের কমেন্ট, যেগুলোর শুরুতে `//` থাকে, আর মাল্টিলাইন কমেন্ট ব্লক, যেগুলো `/*` ও `*/` দিয়ে ঘেরা হয়।

## ডকুমেন্টেশন কমেন্ট

Go-তে কোড ডকুমেন্ট করার ক্ষেত্রে কমেন্টের গুরুত্বপূর্ণ ভূমিকা আছে।
`godoc` কমান্ড এগুলো ব্যবহার করে; এই কমেন্ট থেকে সে Go প্যাকেজের ডকুমেন্টেশন তৈরি করে।
একটি ডকুমেন্টেশন কমেন্ট হওয়া উচিত একটি সম্পূর্ণ বাক্য, যা যেই জিনিসের বর্ণনা দেওয়া হচ্ছে তার নাম দিয়ে শুরু হয় এবং একটি পূর্ণচ্ছেদ দিয়ে শেষ হয়।

কমেন্ট প্যাকেজের আগে থাকা উচিত, সেইসাথে এক্সপোর্টেড আইডেন্টিফায়ারের আগেও, যেমন এক্সপোর্টেড ফাংশন, মেথড, প্যাকেজ ভ্যারিয়েবল, কনস্ট্যান্ট আর স্ট্রাক্ট; এগুলোর বিষয়ে আপনি পরের অনুশীলনীগুলোতে আরও শিখবেন।

প্যাকেজ-লেভেলের একটি ভ্যারিয়েবল দেখতে এমন হতে পারে:

```go
// TemperatureCelsius represents a certain temperature in degrees Celsius.
var TemperatureCelsius float64
```

## প্যাকেজ কমেন্ট

প্যাকেজ কমেন্ট সরাসরি প্যাকেজ ক্লজের (`package x`) আগে লেখা উচিত এবং শুরু হওয়া উচিত `Package x ...` দিয়ে, এভাবে:

```go
// Package kelvin provides tools to convert
// temperatures to and from Kelvin.
package kelvin
```

## ফাংশন কমেন্ট

একটি ফাংশন কমেন্ট সরাসরি ফাংশন ডিক্লারেশনের আগে লেখা উচিত।
এটি হওয়া উচিত একটি সম্পূর্ণ বাক্য, যা ফাংশনের নাম দিয়ে শুরু হয়।
যেমন, `Calculate` ফাংশনের একটি এক্সপোর্টেড কমেন্টের রূপ হবে `Calculate  ...` এর মতো।
এটিতে আরও ব্যাখ্যা থাকা উচিত ফাংশনটি কী কী আর্গুমেন্ট নেয়, সেগুলো দিয়ে কী করে, আর তার রিটার্ন ভ্যালুগুলোর মানে কী, এবং শেষে একটি পূর্ণচ্ছেদ থাকবে):

```go
// CelsiusFreezingTemp returns an integer value equal to the temperature at which water freezes in degrees Celsius.
func CelsiusFreezingTemp() int {
	return 0
}
```
