# নির্দেশনা

প্রোগ্রামিং সম্পর্কে যত বেশি শিখবেন, তত বেশি মনে হতে শুরু করবে যে এটা হয়তো নিছক ক্ষণিকের ঝোঁক নয়।
এমনকি এতে ব্যবসার সুযোগও থাকতে পারে: মানুষ কোড লেখে, তারা সেটা সংরক্ষণ করতে চায়, শেয়ার করতে চায়, একসাথে কাজ করতে চায়, এমনকি হয়তো কিছু মতামতও পেতে চায়।

আচ্ছা, চলুন করে ফেলি, কোড লিখতে মানুষকে উৎসাহ দিতে একটি সার্ভিস বানাই: হুপ, হুপ, সবাই, git ব্যবহার শুরু করুন!
এর নাম দিই... GitHup।

আপনি একটি REST JSON API বানানো শুরু করলেন: ইউজার, পুল রিকোয়েস্ট, কমেন্ট, backend-টা দ্রুতই হয়ে গেল।
আপনি যখন সার্ভারের কাছে একটি পুল রিকোয়েস্টের কমেন্টের অ্যারে চান, তখন সার্ভার যে পেলোড পাঠায় তার একটি উদাহরণ এখানে:

অবশ্যই, frontend বানানো হবে Elm দিয়ে, তবে আগে আপনাকে বুঝে নিতে হবে সেই কুখ্যাত ডিকোডার/এনকোডারগুলো আসলে কী।

```exercism/note
রসিকতার গল্পটা বাদ দিলে, এই অনুশীলনীর প্রয়োজনীয়তাগুলো সরাসরি GitHub-এর REST API এন্ডপয়েন্ট থেকে নেওয়া, যা পুল রিকোয়েস্ট রিভিউ কমেন্টের জন্য।
সরল রাখার জন্য JSON স্কিমা থেকে কিছু ফিল্ড বাদ দেওয়া হয়েছে, তবে বাস্তব-জগতের অ্যাপ্লিকেশনের সঙ্গে এর চেয়ে বেশি কাছাকাছি আর হওয়া সম্ভব নয়।
```

## 1. ID, দয়া করে!

আপনার তীক্ষ্ণ দৃষ্টিতে ধরা পড়েছে যে কমেন্ট আর ইউজার, দুটোরই একটি `id` ফিল্ড আছে, শুরু করার জন্য এটি একদম উপযুক্ত জায়গা।

`decodeId` ডিফাইন করুন যাতে এটি এমন একটি JSON অবজেক্ট ডিকোড করতে পারে, যেখানে `id` একটি ইন্টিজার।

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. আমার নামটা আবার কী?

উপরের উদাহরণে আপনি খেয়াল করবেন, সব ইউজারের নাম থাকে না।

`decodeName` ডিফাইন করুন যাতে এটি `name` ফিল্ডে থাকা একটি স্ট্রিং ডিকোড করতে পারে, যদি সেখানে স্ট্রিং থাকে।
নাম নেই? কোনো সমস্যা নেই, শুধু `Nothing` রিটার্ন করুন।
এই ডিকোডার কখনও ব্যর্থ হওয়া উচিত নয়।

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. ইউজার? আমি তো ওকে চিনিই না!

ইউজার ডিকোড করার কাজে আমরা প্রায় অর্ধেক পথ পেরিয়ে এসেছি, চলুন শেষ করে ফেলি।

`decodeUser` ডিফাইন করুন যাতে এটি একটি JSON ইউজার অবজেক্ট ডিকোড করতে পারে।
`decodeUser`-এর ভেতরে অবশ্যই `decodeId` আর `decodeName` ব্যবহার করবেন।

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. আমি এক শক্তিশালী, স্বাধীন কমেন্ট

পুল রিভিউয়ের কিছু কমেন্ট স্বতন্ত্র, তাই তাদের `pull_request_review_id` থাকে না।
তবে স্পেসিফিকেশনে বলা আছে, এমন ক্ষেত্রেও একটি `pull_request_review_id` ফিল্ড থাকা উচিত, কিন্তু তার মান হবে `null`, অর্থাৎ গরিবের `Nothing`।

`decodePullRequestReviewId` ডিফাইন করুন যাতে এটি `pull_request_review_id` ফিল্ডে如果一个 ইন্টিজার থাকে, সেটি ডিকোড করতে পারে।
যদি কোনো ইন্টিজার না থাকে, তাহলে সেখানে একটি `null` থাকা উচিত; আর যদি `null` না থাকে, তাহলে ডিকোডার ব্যর্থ হওয়া উচিত।

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. সাইড হাসল

এরপরেই আছে এই মজার দেখতে `side` ফিল্ডটি।
একটি পুল রিভিউতে আপনি কোডের যেসব অংশ মুছে ফেলা হয়েছে (স্ক্রিনের `Left` দিকে) বা যেসব অংশ যোগ করা হয়েছে (স্ক্রিনের `Right` দিকে), সেগুলোতে কমেন্ট করতে পারেন।

`decodeSide` ডিফাইন করুন যাতে এটি `side` ফিল্ডে `"LEFT"` অথবা `"RIGHT"` ডিকোড করে সেটিকে তার সংশ্লিষ্ট টাইপ ভ্যারিয়েন্টের সঙ্গে মিলিয়ে দিতে পারে।

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. লিংকস অ্যাওয়েকেনিং

প্রতিটি কমেন্টের একগুচ্ছ লিংক থাকে, যেগুলো সব কমেন্টে একরকম মনে হয় না।

`decodeLinks` ডিফাইন করুন যাতে এটি `_links` ফিল্ডে থাকা একগুচ্ছ URL ডিকোড করতে পারে।
লিংকের নাম আর সংখ্যা বদলে যেতে পারে, তাই সেটা সামলানোর ব্যবস্থা করবেন।
লিংকগুলো নিজেরা JSON অবজেক্ট, যেগুলোতে সবসময় একটি `href` ফিল্ড থাকা উচিত।

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. হ্যাঁ, কমেন্ট

প্রায় পৌঁছে গেছি, চলুন শেষ করে ফেলি।

`decodeComment` আর `decodeComments` ডিফাইন করুন, যাতে তারা যথাক্রমে একটি একক JSON কমেন্ট অবজেক্ট বা কমেন্টের একটি অ্যারে ডিকোড করতে পারে।
`decodeName` বাদে এতক্ষণে ডিফাইন করা সব ফাংশনই `decodeComment`-এ ব্যবহার করবেন।
অবশ্যই, `decodeComments`-ও `decodeComment` ব্যবহার করবে।

## 8. সব একসূত্রে গাঁথা

এই সবকিছুতেই আরও একটি ফিচার বাকি: সার্ভারে একটি নতুন কমেন্ট পাঠানোর ক্ষমতা।
এর জন্য আপনাকে ডিকোডারের ঠিক উল্টোটা করতে হবে, একটি Elm `Comment`-কে একটি JSON `Value`-তে রূপান্তর করার ক্ষমতা আপনার থাকতে হবে।

`encodeComment` ডিফাইন করুন যাতে এটি যেকোনো বৈধ `Comment` এনকোড করতে পারে।
ফিল্ডগুলোর ক্রম গুরুত্বপূর্ণ নয়, যতক্ষণ এনকোডার এমন একটি মান তৈরি করতে পারে যা `decodeComment` ডিকোড করতে পারে।
