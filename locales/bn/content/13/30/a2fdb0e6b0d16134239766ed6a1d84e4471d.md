# পরিচিতি

Gleam এরর হ্যান্ডলিংয়ের জন্য এক্সেপশন ব্যবহার করে না। এর বদলে যেসব ফাংশন সফল হতে পারে বা ব্যর্থ হতে পারে, তারা জেনেরিক `Result` টাইপ রিটার্ন করে।

`Result` টাইপটি ভাষার মধ্যেই বিল্ট-ইন, তাই এটি ডিফাইন বা ইমপোর্ট করার দরকার নেই। তবে আপনি যদি নিজে এটি ডিফাইন করতেন, তাহলে সেটি দেখতে এমন হতো:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

কোনো ফাংশন সফল হলে `Ok` ভ্যারিয়েন্ট রিটার্ন করা হয়, আর কোনো ফাংশন ব্যর্থ হলে `Error` ভ্যারিয়েন্ট রিটার্ন করা হয়।

Gleam-এ রেজাল্ট খুবই কমন, আর Gleam প্রোগ্রামাররা সেগুলো নিয়ে কাজ করা সহজ করতে সাধারণত [`gleam/result` মডিউল](https://hexdocs.pm/gleam_stdlib/gleam/result.html) ব্যবহার করেন।

`result.map` ফাংশনটি ব্যবহার করে রেজাল্ট `Ok` হলে তার ভেতরের মানের ওপর একটি ফাংশন কল করা যায়, আর `Error` হলে সেটি অপরিবর্তিত অবস্থায় পাস করিয়ে দেওয়া যায়।

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

`result.try` ফাংশনটিও একই রকম, তবে এখানে কলব্যাক ফাংশনের কাছ থেকে একটি রেজাল্ট রিটার্ন করার প্রত্যাশা করা হয়। রেজাল্ট রিটার্ন করে এমন একাধিক ফাংশন একসাথে চেইন করতে এটি দারুণ কাজে লাগে।

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
