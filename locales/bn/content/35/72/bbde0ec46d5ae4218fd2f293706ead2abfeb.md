# লুপ

একটি **লুপ** একই কাজ বারবার করে।

```sather
   loop
      ...
   end;
```

একা এই লুপ কখনোই থামে না, তাই এর ভিতরের কোনো কিছু দিয়ে এটিকে শেষ করতে হয়।

## গণনা রাখার একটি জায়গা

লুপের প্রায় সবসময়ই এমন একটি মান দরকার যা চলার পথে বদলে যায়। এটিই একটি **ভ্যারিয়েবল**, আর `::=` দিয়ে একটি তৈরি করা হয়:

```sather
   total ::= 0;
```

ভ্যারিয়েবলটির নাম `total`, এটি `0` দিয়ে শুরু হয়, আর `0` দেখে Sather বুঝে নেয় যে এটি একটি `INT` ধারণ করে। এরপর `:=` দিয়ে নতুন একটি মান বসানো হয়:

```sather
   total := total + 5;
```

এটি ডান থেকে বামে পড়ুন: `total` এখন যা আছে তা নিন, ৫ যোগ করুন, আর উত্তরটি আবার `total`-এর মধ্যে বসান।

এভাবে তৈরি একটি ভ্যারিয়েবল রুটিনের শেষ পর্যন্ত টিকে থাকে।

## until!

`until!` একটি প্রশ্ন নেয়। লুপ প্রতিবার ঘোরার সময় সেই প্রশ্নটি করা হয়, আর উত্তরটি ট্রু হলে লুপ ঠিক তখনই থেমে যায়।

```sather
   sum_to(last : INT) : INT is
      total ::= 0;
      n ::= 1;
      loop
         until!(n > last);
         total := total + n;
         n := n + 1;
      end;
      return total;
   end;
```

`n` গণনা করে ১, ২, ৩ ... আর প্রথমবার `n` যখন `last`-এর বেশি হয় তখনই লুপ শেষ হয়। `n := n + 1` না থাকলে প্রশ্নটির উত্তর কখনো বদলাত না, আর লুপ অনন্তকাল চলতেই থাকত।

`until!` প্রথম লাইনেই থাকতে হবে না। প্রশ্নটি যেখানে অর্থবহ হয় সেখানে এটি রাখুন: উপরে রাখলে লুপ একবারও নাও চলতে পারে; নিচে রাখলে লুপ অন্তত একবার চলবে।

`!` নামেরই একটি অংশ। Sather নিজের কিছু কিছু জিনিস এভাবে চিহ্নিত করে; এই চিহ্নের অর্থ কী, তা পরে আসবে।

## break!

`break!` কোনো প্রশ্ন ছাড়াই লুপটি সঙ্গে সঙ্গে শেষ করে দেয়। কাজের মাঝখানে থামার কারণ দেখা দিলে এটি দরকার হয়।

```sather
   loop
      if too_far then break!; end;
      ...
   end;
```

`until!` আর `break!` কেবল একটি `loop`-এর ভিতরেই অর্থ বহন করে। দুটির কোনোটিই একা ব্যবহার করা যায় না।
