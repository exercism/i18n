# লিন্টিং

[configlet](/docs/building/configlet)-এর প্রধান কাজ হলো লিন্টিং: কোনো ট্র্যাকের কনফিগারেশন ফাইল সঠিকভাবে গঠিত কি না তা যাচাই করা, সিনট্যাক্স ও সিম্যান্টিক্স উভয় দিক থেকেই। ভুলভাবে কনফিগার করা ট্র্যাক ঠিকভাবে সিঙ্ক নাও হতে পারে, ওয়েবসাইটে ভুল দেখাতে পারে, বা ইউজার এক্সপেরিয়েন্সকে দুর্বল করে তুলতে পারে। তাই Exercism-এর অখণ্ডতা রক্ষায় configlet-এর গার্ডগুলো গুরুত্বপূর্ণ ভূমিকা পালন করে।

## ব্যবহার

`lint` কমান্ডটি দিয়ে একটি ট্র্যাক লিন্ট করা যায়।

```
configlet [global-options] lint [command-options]

Global options:
  -h, --help                   Show this help message and exit
      --version                Show this tool's version information and exit
  -t, --track-dir <dir>        Specify a track directory to use instead of the current directory
  -v, --verbosity <verbosity>  The verbosity of output. Allowed values: q[uiet], n[ormal], d[etailed]
```

## নিয়ম

নিচে যেসব লিন্টিং নিয়ম যাচাই করা হয় সেগুলো দেওয়া হলো।

### নিয়ম: আবশ্যক ফাইলগুলো উপস্থিত আছে

লিন্টারের যাচাই করা উচিত সব আবশ্যক ফাইল উপস্থিত আছে কি না। অনুশীলনী-নির্দিষ্ট নয়, এমন যে ফাইলগুলো অবশ্যই থাকতে হবে সেগুলো হলো:

- `config.json`
- `docs/ABOUT.md`
- `docs/INSTALLATION.md`
- `docs/LEARNING.md`
- `docs/RESOURCES.md`
- `docs/SNIPPET.txt`
- `docs/TESTS.md`
- `exercises/shared/.docs/help.md`
- `exercises/shared/.docs/tests.md`

কনসেপ্ট অনুশীলনী-নির্দিষ্ট যে ফাইলগুলো অবশ্যই থাকতে হবে সেগুলো হলো:

- `exercises/concept/<slug>/.docs/hints.md`
- `exercises/concept/<slug>/.docs/instructions.md`
- `exercises/concept/<slug>/.docs/introduction.md`
- `exercises/concept/<slug>/.meta/config.json`

প্র্যাকটিস অনুশীলনীর জন্যও অনুরূপ একটি তালিকা থাকবে, তবে তার স্পেক আমরা এখনো ঠিক করিনি।

`config.json`-এ তালিকাভুক্ত প্রতিটি কনসেপ্টের নিচের ফাইলগুলো থাকা উচিত:

- `concepts/<slug>/about.md`
- `concepts/<slug>/introduction.md`
- `concepts/<slug>/links.json`

## শব্দকোষ

1. **নন-ব্ল্যাংক স্ট্রিং**: এমন একটি স্ট্রিং, যাতে অন্তত একটি নন-হোয়াইটস্পেস ক্যারেক্টার আছে।
2. **কেবাব-কেস স্ট্রিং**: এমন একটি স্ট্রিং, যাতে কেবল `[a-z0-9]` রেঞ্জের ক্যারেক্টার থাকে, যা ঐচ্ছিকভাবে ড্যাশ দিয়ে আলাদা করা থাকে (যেমন "two-fer")। এটি অবশ্যই নিচের রেগুলার এক্সপ্রেশনের সাথে মিলতে হবে: `^[a-z0-9]+(-[a-z0-9]+)*$`
3. **টাইটেল কেস স্ট্রিং**: একটি নন-ব্ল্যাংক স্ট্রিং, যা [Chicago Manual of Style-এর নিচের নির্দেশিকা](https://en.wikipedia.org/wiki/Title_case#Chicago_Manual_of_Style) মেনে চলে:
   - শিরোনাম ও উপশিরোনামের প্রথম ও শেষ শব্দ বড় হাতের অক্ষরে লিখুন।
   - "গুরুত্বপূর্ণ" শব্দ (বিশেষ্য, সর্বনাম, ক্রিয়া, বিশেষণ, ক্রিয়া-বিশেষণ, এবং কিছু সংযোজক) বড় হাতের অক্ষরে লিখুন।
   - সংযোজক _and_, _but_, _for_, _or_ ও _nor_ ছোট হাতের অক্ষরে লিখুন।
   - আর্টিকেল _the_, _a_ ও _an_ ছোট হাতের অক্ষরে লিখুন।
   - পদান্বয়ী অব্যয় দৈর্ঘ্য নির্বিশেষে ছোট হাতের অক্ষরে লিখুন, তবে সেগুলোতে জোর দেওয়া হলে, সেগুলো ক্রিয়া-বিশেষণ বা বিশেষণ হিসেবে ব্যবহৃত হলে, কিংবা সংযোজক হিসেবে ব্যবহৃত হলে নয়।
   - _to_ ও _as_ শব্দ দুটি ছোট হাতের অক্ষরে লিখুন।
   - ল্যাটিন প্রজাতির নামের দ্বিতীয় অংশ ছোট হাতের অক্ষরে লিখুন।
4. **সেন্টেন্স কেস স্ট্রিং**: একটি নন-ব্ল্যাংক স্ট্রিং, যা [নিচের নির্দেশিকা](https://en.wikipedia.org/wiki/Letter_case#Sentence_case) মেনে চলে:
   - বাক্যের প্রথম শব্দ, সেইসাথে নামবাচক বিশেষ্য এবং আরও নির্দিষ্ট কোনো নিয়ম অনুযায়ী যেসব শব্দে প্রয়োজন, সেগুলো বড় হাতের অক্ষরে লিখুন।
5. **বৈধ `files` প্যাটার্ন**: একটি নন-ব্ল্যাংক স্ট্রিং¹, যা অনুশীলনীর ডিরেক্টরির সাপেক্ষে অনুশীলনীতে ব্যবহৃত একটি ফাইলের অবস্থান নির্দেশ করে। একটি প্যাটার্নে নিচের প্লেসহোল্ডারগুলোর একটি ব্যবহার করা যেতে পারে:

   - `%{kebab_slug}`: `kebab-case` অনুশীলনীর স্লাগ (যেমন `bit-manipulation`)
   - `%{snake_slug}`: `snake_case` অনুশীলনীর স্লাগ (যেমন `bit_manipulation`)
   - `%{camel_slug}`: `camelCase` অনুশীলনীর স্লাগ (যেমন `bitManipulation`)
   - `%{pascal_slug}`: `PascalCase` অনুশীলনীর স্লাগ (যেমন `BitManipulation`)

6. **অনন্য version 4 UUID স্ট্রিং**: এমন একটি স্ট্রিং, যা নিচের সব শর্ত পূরণ করে:

   - এটি একটি নির্দিষ্ট Exercism ট্র্যাকের ট্র্যাক-লেভেল `config.json` ফাইলে কেবল একবারই থাকে
   - অন্য কোনো Exercism ট্র্যাকের ট্র্যাক-লেভেল `config.json` ফাইলে এটি থাকে না
   - https://github.com/exercism/problem-specifications-এর কোনো `canonical-data.json` ফাইলে এটি থাকে না
   - Exercism-এর আর কোথাও এটি থাকে না
   - এটি নিচের রেগুলার এক্সপ্রেশনের সাথে মেলে:

   ```
   ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
   ```

   উদাহরণস্বরূপ, নিচের UUID-টির সঠিক রূপ রয়েছে:

   ```
   d334ffe3-657e-4725-a950-290b284b6d9f
   ```

   যথাযথ একটি UUID তৈরি করতে আপনি `configlet uuid` চালাতে পারেন।

7. **বৈধ অ্যানালাইজার `tag`**: একটি নন-ব্ল্যাংক স্ট্রিং¹, যা `<category>:<thing>` আকারে থাকে। `<category>`-এর মান অবশ্যই নিচের একটি হতে হবে:

- `paradigm` (যেমন `paradigm:functional`)
- `technique` (যেমন `technique:recursion`)
- `construct` (যেমন `construct:bitwise-and`)
- `uses` (যেমন `uses:DateTime.add_seconds`)

`<thing>`-এর মান অবশ্যই একটি নন-ব্ল্যাংক স্ট্রিং¹ হতে হবে।
