# নির্দেশনা

আপনার বন্ধু হেলমা একটি ছোট অনলাইন গেম বানিয়েছিলেন, যা দ্রুত জনপ্রিয়তা পায়।
এর নাম _HellMath_।
ছোট্ট এই কমিউনিটিতে কিছু ট্রল ভিড় করে, যারা গেম আর ফোরামকে বেশ অপ্রীতিকর করে তোলে।
ঝামেলাকারীদের আলাদা করার জন্য হেলমা আপনাকে একটি নতুন পারমিশন সিস্টেম নিয়ে কাজ করতে অনুরোধ করেছেন।

ফোরাম তিনটি আলাদা অ্যাকশন সমর্থন করে:

- Read
- Write
- Remove

চার ধরনের অ্যাকাউন্ট আছে, প্রতিটির ডিফল্ট পারমিশন আলাদা:

- গেস্ট: পোস্ট পড়তে পারে।
- ইউজার ও ট্রল: পোস্ট পড়তে ও লিখতে পারে।
- মডারেটর: পোস্ট পড়তে, লিখতে ও মুছে ফেলতে পারে, তাদের সব পারমিশন থাকে।

হেলমা লক্ষ্য করেছেন যে ট্রল অ্যাকাউন্ট ব্যান করা কোনো কাজে আসে না।
তার কৌশল হলো তাদের এই ভ্রম দেওয়া যে তাদের সময় "ভালোভাবে বিনিয়োগ" হয়েছে, কিন্তু তাদের পোস্ট কেবল অন্য ট্রলদেরই দেখানো হয়।
অগ্রাধিকার নির্ধারণের প্রয়োজন হয় এমন যেকোনো ক্ষেত্রে, ট্রলরা যেকোনো ক্রমে সবার শেষে থাকে।
তারা যখন কোনো গেমে ঢোকে, তখন পাওয়া যাওয়া প্লেয়ারদের তালিকাও কেবল অন্য ট্রলদের মধ্যে সীমাবদ্ধ থাকে।

এই পদ্ধতিটিকে বলা হয় [শ্যাডো-ব্যানিং][shadow-ban]।

## 1. ইউজার টাইপ ও পারমিশন সেট আপ করুন।

প্রথমে, চারটি অ্যাকাউন্ট টাইপ বোঝাতে একটি `AccountStatus` এনামারেশন ডিফাইন করুন: `troll`, `guest`, `user`, এবং `mod`।

এরপর, তিনটি পারমিশন টাইপ বোঝাতে একটি `Action` এনামারেশন ডিফাইন করুন: `read`, `write`, এবং `remove`।


## 2. ট্রলদের কেবল অন্য ট্রলদের কাছেই দেখান।

ফোরামের প্রতিটি পোস্ট তার মেটাডেটায় পোস্টকারীর `AccountStatus` সংরক্ষণ করে।
নিশ্চিত করুন যে ট্রলদের পোস্ট কেবল অন্য ট্রলদেরই দেখানো হয়।

হেলমার একটি `display_post` ফাংশন দরকার, যা `AccountStatus` টাইপের দুটি আর্গুমেন্ট নেয় এবং একটি `bool` রিটার্ন করে।
প্রথম আর্গুমেন্টটি পোস্টকারীর স্ট্যাটাস, দ্বিতীয়টি দর্শকের স্ট্যাটাস।

```cpp
using namespace hellmath;
display_post(AccountStatus::troll, AccountStatus::user);
// => false
display_post(AccountStatus::mod, AccountStatus::guest);
// => true
```

## 3. বিভিন্ন ইউজারের পারমিশন যাচাই করুন।

কোনো নির্দিষ্ট অ্যাকশন একটি ইউজারের জন্য অনুমোদিত কি না, তা যাচাই করার একটি উপায় হেলমার দরকার।

অনুগ্রহ করে একটি `permission_check` ফাংশন ইমপ্লিমেন্ট করুন, যা প্রথম আর্গুমেন্ট হিসেবে একটি `Action` নেয় এবং যাচাই করার জন্য একটি `AccountStatus` নেয়।
ভূমিকায় তালিকাভুক্ত পারমিশন অনুযায়ী এটি একটি `bool` রিটার্ন করবে।

```cpp
permission_check(Action::remove, AccountStatus::guest);
// => false
permission_check(Action::write, AccountStatus::mod);
// => true
```

## 4. গেমের অ্যাক্সেস দিন এবং প্লেয়ারদের জোড়া মেলান।

গেমের প্রকৃত প্লেয়ারদের তাদের কাজের জবাবদিহির মধ্যে রাখতে, _Hellmath_ গেস্ট ইউজারদের অ্যাক্সেস দেয় না।
উপরে বলা হয়েছে, হেলমা চান ট্রলরা অন্য ট্রলদের ট্রল করুক।
অন্য ইউজারদের মধ্যে গেম সংযোগে কোনো বিধিনিষেধ নেই।

`valid_player_combination` ফাংশনটি ইমপ্লিমেন্ট করুন, যা যাচাই করে দুজন প্লেয়ার একই গেমে যোগ দিতে পারে কি না।
ফাংশনটির `AccountStatus` টাইপের দুটি প্যারামিটার আছে এবং এটি একটি `bool` রিটার্ন করে।

```cpp
valid_player_combination(AccountStatus::guest, AccountStatus::mod);
// => false
valid_player_combination(AccountStatus::troll, AccountStatus::troll);
// => true
```

## 5. অগ্রাধিকারভিত্তিক কিউ তৈরি করুন।

গেম ও ফোরামের বিশাল প্রসারের সাথে, হেলমাকে এখন ইউজারদের মধ্যে কম্পিউটিং পাওয়ার আর ব্যান্ডউইথ ভাগ করে দিতে হয়।
জরুরি পরিস্থিতি সামলাতে মডারেটরদের সর্বোচ্চ অগ্রাধিকার দেওয়া হয়।
গেস্টরা সাধারণ ইউজারদের পেছনে কিউতে থাকে, আর ট্রলরা সবার পেছনে চলে যায়।

`has_priority` ফাংশনটি ইমপ্লিমেন্ট করুন, যা দুটি `AccountStatus` আর্গুমেন্ট নেয় এবং `true` রিটার্ন করে যদি এবং কেবল যদি প্রথম অ্যাকাউন্টের অগ্রাধিকার দ্বিতীয়টির চেয়ে কঠোরভাবে বেশি হয়।

```cpp
has_priority(AccountStatus::guest, AccountStatus::mod);
// => false
has_priority(AccountStatus::user, AccountStatus::troll);
// => true
```
