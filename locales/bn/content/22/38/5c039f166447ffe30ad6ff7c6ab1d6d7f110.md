# পরিচিতি

[প্যাটার্ন ম্যাচিং][pattern-matching] দিয়ে প্রকাশভরা শাখাযুক্ত কোড লেখা যায়, আর [ডিস্ট্রাকচারিং][destructuring] মানগুলোকে ভ্যারিয়েবলের সঙ্গে সুন্দরভাবে বেঁধে রাখার সুযোগ দেয়।
এলম প্রোগ্রামার হিসেবে দুটোই আয়ত্ত করা অত্যন্ত কাজের, আর একসঙ্গে ব্যবহার করলে কোডের পাঠযোগ্যতা অনেক বেড়ে যায়।

## সরল প্যাটার্ন ম্যাচিং

প্যাটার্ন ম্যাচিং মানে হলো, যে ডেটা নিয়ে কাজ করা হচ্ছে তার গঠন অনুযায়ী কোডকে শাখায় ভাগ করা।
তাই এটি স্বভাবতই কাস্টম টাইপের ধারণার সঙ্গে মানিয়ে যায়, কারণ কাস্টম টাইপই বলে দেয় কোনো ডেটা কোন কোন আকার নিতে পারে।
যেমন ধরা যাক, `Color` নামের একটি কাস্টম টাইপ আছে, যাকে `Blue` অথবা `Red` হিসেবে ডিফাইন করা হয়েছে। এখন আমরা একটি `toString` ফাংশন লিখতে পারি, যেখানে কালারের উপর প্যাটার্ন ম্যাচিং করে সঠিক স্ট্রিংটি রিটার্ন করা হয়।

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

সরল এনুমারেশন নয়, এমন কাস্টম টাইপেও প্যাটার্ন ম্যাচিং কাজ করে।
চলুন একটি `hello` ফাংশন দেখি, যার প্যারামিটার একটি `Maybe String`, যেটি হয় কোনো ব্যক্তির নাম ধরে রাখে, নয়তো কিছুই না।
প্যাটার্ন ম্যাচিং করার সময় আমরা ডেটাকে ছোট হাতের অক্ষরের নাম দিয়ে সেই ভ্যারিয়েবলের সঙ্গে বেঁধে রাখতে পারি, আর তারপর ম্যাচের ডান দিকে সেটি ব্যবহার করতে পারি।

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

প্যাটার্ন ম্যাচিং অবশ্যই এক্সহসটিভ হতে হবে, নইলে কম্পাইলার কম্পাইল করতে অস্বীকার করবে।
কিন্তু অনেক সময় কিছু ডেটা বা একটি case এক্সপ্রেশনের কিছু শাখা নিয়ে আমাদের মাথাব্যথা থাকে না।
সেসব ক্ষেত্রে, বাঁধার জন্য একটি ভ্যারিয়েবল নাম খুঁজে বের করতে হয় না, সব কেসের জন্য আলাদা শাখা লিখতেও হয় না; বরং আমরা আন্ডারস্কোর ওয়াইল্ডকার্ড `_` ব্যবহার করতে পারি।

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## অ্যাডভান্সড প্যাটার্ন ম্যাচিং

কাস্টম টাইপ ছাড়াও, যেসব টাইপের লিটারাল আছে, যেমন `Char`, `String`, `Int` আর `Floats`, সেগুলোতেও প্যাটার্ন ম্যাচিং করা যায়।

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

নেস্ট না করেই একাধিক মান ম্যাচ করতে এলমে একটি কমন কৌশল হলো, যে মানগুলো ম্যাচ করতে হবে সেগুলোকে [_অ্যাড হক টাপল_-এ][ad-hoc-tuples] এভাবে একসঙ্গে জুড়ে দেওয়া:

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

আর যেহেতু লিস্ট ফাংশনাল প্রোগ্রামারদের খুব প্রিয়, তাই [সেগুলোতেও প্যাটার্ন ম্যাচিং করা যায়][pattern-match-lists], ঠিক যে সিনট্যাক্স দিয়ে সেগুলো তৈরি করা হয় সেটিই ব্যবহার করে, `::` অপারেটর দিয়ে।

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

সবশেষে, প্যাটার্ন ম্যাচিং রিকার্সিভভাবেও কাজ করে, যা জটিল ও রিকার্সিভ টাইপের গভীরে যাওয়ার সুযোগ দেয়।

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## ডিস্ট্রাকচারিং

টাইপের ভেতরের ডেটার সঙ্গে ভ্যারিয়েবল বেঁধে রাখার সুযোগ দেয়, এই অর্থে ডিস্ট্রাকচারিং প্যাটার্ন ম্যাচিংয়ের সঙ্গে খুবই মিল।
মূল পার্থক্য হলো, যখন কেবল একটি আকার সম্ভব তখন আমরা এই পদ্ধতিটিকে "ডিস্ট্রাকচারিং" বলি, আর একাধিক আকার থাকলে বলি প্যাটার্ন ম্যাচিং।
ডিস্ট্রাকচারিং প্রায়ই `let` বাইন্ডিংয়ে, ফাংশনের আর্গুমেন্টে, এবং অবশ্যই case এক্সপ্রেশনে প্যাটার্ন ম্যাচিংয়ের সঙ্গে মিশে থাকে।

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

ডিস্ট্রাকচারিং একক ভ্যারিয়েন্টের কাস্টম টাইপ, টাপল, আর রেকর্ডেও ব্যবহার করা যায়, যেখানে এটি খুবই সুবিধাজনক।
[একটি রেকর্ড ডিস্ট্রাকচার করতে][records-pattern-matching] চাইলে তার যত খুশি ফিল্ড ব্যবহার করা যায়, একটি, দুটি, ..., কিংবা সব ফিল্ড।

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

দুর্ভাগ্যক্রমে, এলম সিনট্যাক্সে রেকর্ডের রিকার্সিভ ডিস্ট্রাকচারিং করা যায় না।
আগের `Circle` উদাহরণে, এক ধাপেই বৃত্তের কেন্দ্রের `x`` and `y`center`center`x`x`y`y` অবস্থান বের করতে হবে।

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

আর আমাদের হাতে শেষ একটি টিপ আছে!
মাঝে মাঝে আমরা চাই, কোনো জিনিসের সম্পূর্ণ অংশ এবং তার একটি টুকরো, দুটোতেই সহজে পৌঁছাতে পারি।
এখানেই [`as` কিওয়ার্ড][as-keyword] কাজে লাগতে পারে।
এটি কোনো জিনিসের সম্পূর্ণটাকে একটি অ্যালিয়াস নাম দিতে দেয়, আর একইসঙ্গে তার ভেতরের অংশ ডিস্ট্রাকচারও করতে দেয়।

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
