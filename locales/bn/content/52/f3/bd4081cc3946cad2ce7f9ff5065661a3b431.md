# পরিচিতি

Factor স্ট্রিম I/O-কে দুটি স্তরে ভাগ করে। নিচের স্তরটি হলো *এক্সপ্লিসিট-স্ট্রিম* API: প্রতিটি ওয়ার্ড স্ট্রিমটিকে একটি আর্গুমেন্ট হিসেবে নেয়। ওপরের স্তরটি হলো *অ্যাম্বিয়েন্ট-স্ট্রিম* API: ছোট, এক লাইনের ওয়ার্ড, যেগুলো এই মুহূর্তে যে স্ট্রিমটি বাইন্ড করা আছে তার ওপর কাজ করে। দুটি স্তরই একই [প্রোটোকল][stream-protocol]-এর ওপর দাঁড়িয়ে আছে, ওপরের স্তরের ওয়ার্ডগুলো শুধু অ্যাম্বিয়েন্ট স্ট্রিমটি খুঁজে নিয়ে কলটি ফরওয়ার্ড করে।

## এক্সপ্লিসিট-স্ট্রিম ওয়ার্ড

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents` সবটুকু পড়ে নেয়; `stream-lines` সবটুকু পড়ে নিয়ে লাইনের সীমানায় ভাগ করে; `stream-readln` একবারে একটি লাইন রিটার্ন করে (অথবা স্ট্রিমের শেষে `f`)।

## অ্যাম্বিয়েন্ট-স্ট্রিম ওয়ার্ড

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

এগুলোই প্রতিদিনের কাজে ব্যবহৃত I/O ওয়ার্ড। এগুলো ডাইনামিক ভ্যারিয়েবল `input-stream` / `output-stream` থেকে বর্তমান ইনপুট বা আউটপুট স্ট্রিম খুঁজে নিয়ে কলটি ফরওয়ার্ড করে। সেজন্যই `print`-কে একটি স্ট্রিংয়ে রিডাইরেক্ট করা মানে শুধু একটি কোটেশনের সময়কালের জন্য `output-stream` বাইন্ড করা।

## সাথে দেওয়া স্ট্রিম কনস্ট্রাক্টর

| ওয়ার্ড              | ভোকাবুলারি                | এটি যা তৈরি করে                  |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | একটি লিটারাল স্ট্রিং পড়ে          |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | লেখাগুলো একটি স্ট্রিংয়ে জমা করে   |
| `<file-reader>`   | [`io.files`][io.files]           | একটি এনকোডিং দিয়ে ফাইল পড়ে   |
| `<file-writer>`   | [`io.files`][io.files]           | একটি এনকোডিং দিয়ে ফাইল লেখে  |

চারটিই ডিসপোজেবল তৈরি করে: এগুলো `destructors`-এর `disposable` এক্সটেন্ড করে, তাই নিচের `with-…` কম্বিনেটরগুলো বেরোনোর সময় সেগুলো রিলিজ করে।

## স্কোপড বাইন্ডিং

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

প্রতিটির কাজ হলো একটি স্ট্রিম খোলা, ভেতরের কোটেশনের জন্য সেটিকে অ্যাম্বিয়েন্ট ইনপুট বা আউটপুট হিসেবে বাইন্ড করা, আর বেরোনোর সময় সেটি ডিসপোজ করা, কোটেশনটি থ্রো করলেও। এগুলো `boatswains-bilge`-এর ডেসট্রাক্টর কম্বিনেটর, স্ট্রিমের জন্য বিশেষায়িত।

`with-string-writer` একটি বিশেষভাবে পরিচ্ছন্ন ধরন: এটি নিজে থেকেই একটি নতুন `<string-writer>` তৈরি করে, সেই রাইটারটিকে অ্যাম্বিয়েন্ট আউটপুট ধরে কোটেশনটি রান করে, আর জমে যাওয়া স্ট্রিংটি রিটার্ন করে। "একটি কোটেশনের আউটপুট ধরে রাখা" প্যাটার্নটা পুরোটাই মাত্র একটি ওয়ার্ড।

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## তাহলে অ্যাম্বিয়েন্ট কেন?

ডাইনামিক-ভ্যারিয়েবল বাইন্ডিংয়ের কারণেই `print` এমন একটি প্রোগ্রামেও কাজ করে যেটি জানে না তাকে ইন্টারঅ্যাকটিভভাবে রান করা হচ্ছে, একটি লগ ফাইলে পাঠানো হচ্ছে, নাকি ধরে রাখা একটি টেস্ট বাফারে। বাইন্ডিংটা একবার বদলে দিলেই `print` কল করা প্রতিটি ওয়ার্ড ঠিকঠাক কাজ করে, কোনো তার বদলাতে হয় না। ওপরের স্তরটি আপনাকে যে উল্টো ব্যবস্থাটি দেয়, সেটা এটাই।

একটি স্ট্রিম *ইমপ্লিমেন্ট* করার জন্য, অর্থাৎ প্রোটোকলের সাথে যুক্ত হয় এমন নিজের ক্লাস ডিফাইন করার জন্য, `streams` কনসেপ্টটি দেখুন (যেটি শেখানো হয় `telegraphers-tape`-এ)।
