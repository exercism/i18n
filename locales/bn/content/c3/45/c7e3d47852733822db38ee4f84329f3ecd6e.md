# পরিচিতি

বেশিরভাগ সময় Factor, `each`, `map` আর `count`-এর মতো কম্বিনেটরের মাধ্যমে ইটারেশন সামলায়। তবে মাঝে মাঝে কোনো গণনা প্রকাশ করার সবচেয়ে পরিষ্কার উপায় হলো **রিকার্সন**, অর্থাৎ এমন একটি ওয়ার্ড যা নিজেকে কল করে।

## একটি রিকার্সিভ ওয়ার্ড ডিফাইন করা

একটি `:` ডেফিনিশন সরাসরিই নিজেকে কল করতে পারে:

```factor
: count-down ( n -- )
    dup 0 = [ drop ] [ dup . 1 - count-down ] if ;

5 count-down
! prints 5 4 3 2 1
```

## খালি কি না, সেই অনুযায়ী ব্রাঞ্চিং

`if-empty` ([`sequences`][sequences]-এ আছে) হলো রিকার্সনের স্বাভাবিক বেস কেস:

```
if-empty ( seq emptyquot nonemptyquot -- )
```

```factor
{ 4 0 9 } [ "empty" ] [ "got data" ] if-empty .
! => "got data"
```

`emptyquot` চলে তখন, যখন (খালি) সিকোয়েন্সটি আগেই ব্যবহৃত হয়ে গেছে; আর `nonemptyquot` চলে সিকোয়েন্সটি তখনও স্ট্যাকে থাকা অবস্থায়।

## `cond`: শর্তযুক্ত ব্রাঞ্চের একটি চেইন

যখন আপনার রিকার্সনে দুইয়ের বেশি কেস থাকে, তখন `cond` ([`combinators`][combinators]-এ আছে) কোডটি পাঠযোগ্য রাখে:

```factor
: classify ( n -- label )
    {
        { [ dup 0 < ] [ drop "negative" ] }
        { [ dup 0 = ] [ drop "zero"     ] }
        [ drop "positive" ]
    } cond ;
```

## `DEFER:` দিয়ে ফরওয়ার্ড রেফারেন্স

একটি `:` ডেফিনিশন সরাসরিই নিজেকে কল করতে পারে, কিন্তু যখন দুটি ওয়ার্ড *পরস্পরকে* কল করে, তখন পার্সার দ্বিতীয়টি তৈরি হওয়ার আগেই প্রথমটি দেখে ফেলে। `DEFER:` একটি নাম সংরক্ষিত রাখে, যাতে প্রথম ডেফিনিশনটি কম্পাইল হতে পারে:

```factor
DEFER: even?

: odd? ( n -- ? ) dup 0 = [ drop f ] [ 1 - even? ] if ;
: even? ( n -- ? ) dup 0 = [ drop t ] [ 1 - odd? ] if ;
```

`DEFER:` তখনও কাজে লাগে, যখন কোনো সহায়ক ওয়ার্ডকে সেটি ব্যবহারকারী ওয়ার্ডের *পরে* পড়াই বেশি স্বাভাবিক মনে হয়।
