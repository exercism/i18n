# ভূমিকা

অন্যান্য অনেক ভাষার মতো Go-তেও পয়েন্টার আছে।
পয়েন্টার যদি আপনার কাছে নতুন হয়, তবে প্রথমে এগুলো একটু রহস্যময় লাগতে পারে, কিন্তু একবার অভ্যস্ত হয়ে গেলে এগুলো বেশ সহজ।
এগুলো Go-র একটি অত্যন্ত গুরুত্বপূর্ণ অংশ, তাই এগুলো সত্যিকারের বুঝে নেওয়ার জন্য একটু সময় নিন।

বিস্তারিত আলোচনায় যাওয়ার আগে পয়েন্টারের ব্যবহারটা বোঝা ভালো।
পয়েন্টার হলো আমাদের প্রোগ্রামের অন্য অংশের সাথে মেমরি শেয়ার করার একটি উপায়, যা দুটি প্রধান কারণে কাজে লাগে:

1. যখন আমাদের কাছে প্রচুর পরিমাণে ডেটা থাকে, তখন ফাংশনের মধ্যে কপি করে পাঠানো খুবই অদক্ষ।
   তার বদলে ডেটা যেখানে সংরক্ষিত থাকে সেই মেমরি লোকেশনটি পাঠিয়ে দিলে, আমরা আমাদের প্রোগ্রামের রিসোর্স-ফুটপ্রিন্ট অনেকটাই কমিয়ে আনতে পারি।
2. ফাংশনের মধ্যে পয়েন্টার পাঠালে, আমরা ডেটার ওই একটিমাত্র কপি সরাসরি অ্যাক্সেস ও পরিবর্তন করতে পারি, অর্থাৎ একটি ফাংশন যে পরিবর্তনই করুক, ফাংশনটি শেষ হওয়ামাত্র প্রোগ্রামের অন্য অংশগুলো তা সাথে সাথে দেখতে পায়।

## ভ্যারিয়েবল ও মেমরি

ধরুন আমাদের একটি সাধারণ ইন্টিজার ভ্যারিয়েবল `a` আছে:

```go
var a int
```

যখন আমরা একটি ভ্যারিয়েবল ডিক্লেয়ার করি, তখন তার মান সংরক্ষণ করার জন্য Go-কে মেমরিতে একটি জায়গা খুঁজে বের করতে হয়।
এই কাজটি মূলত আমাদের কাছ থেকে আড়াল করা থাকে; ওই মেমরি টুকরোতে রাখা মানটি আনতে হলে আমরা শুধু ভ্যারিয়েবলের নাম ধরে তা ব্যবহার করতে পারি।

যেমন, আমরা যখন `a + 2` লিখি, তখন আসলে ভ্যারিয়েবল `a`-এর সাথে সম্পর্কিত মেমরিতে রাখা মানটি এনে তার সাথে ২ যোগ করছি।

একইভাবে, `a`-এর মেমরির টুকরোটিতে থাকা মান বদলাতে হলে, আমরা ভ্যারিয়েবলের নাম ব্যবহার করেই একটি অ্যাসাইনমেন্ট করতে পারি:

```go
a = 3
```

`a`-এর সাথে সম্পর্কিত মেমরি টুকরোতে এখন `3` মানটি সংরক্ষিত থাকবে।

## পয়েন্টার

ভ্যারিয়েবল আমাদের মেমরিতে থাকা মান বোঝার সুযোগ দিলেও, মাঝে মাঝে ভ্যারিয়েবলটি যে **মেমরি অ্যাড্রেস** নির্দেশ করছে সেটি জানা কাজে লাগে।
**পয়েন্টার** সেই মানগুলোর মেমরি অ্যাড্রেস ধরে রাখে।
আপনি মূল টাইপের আগে একটি অ্যাস্টেরিস্ক বসিয়ে একটি ভ্যারিয়েবল পয়েন্টার টাইপে ডিক্লেয়ার করেন:

```go
var p *int // 'p' contains the memory address of an integer
```

এখানে আমরা "pointer to int" (`*int`) টাইপের একটি ভ্যারিয়েবল `p` ডিক্লেয়ার করছি।
এর অর্থ, `p` একটি ইন্টিজারের মেমরি অ্যাড্রেস ধরে রাখবে।
পয়েন্টারের জিরো ভ্যালু হলো `nil`, কারণ একটি `nil` পয়েন্টার কোনো মেমরি অ্যাড্রেস ধরে রাখে না।

### একটি ভ্যারিয়েবলের পয়েন্টার পাওয়া

একটি ভ্যারিয়েবলের মানের মেমরি অ্যাড্রেস বের করতে আমরা `&` অপারেটরটি ব্যবহার করতে পারি।
যেমন, আমরা যদি ভ্যারিয়েবল `a`-এর মেমরি অ্যাড্রেস খুঁজে পয়েন্টার `p`-তে সংরক্ষণ করতে চাই, তবে এভাবে করতে পারি:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### পয়েন্টারের মাধ্যমে মান অ্যাক্সেস করা (ডিরেফারেন্সিং)

পয়েন্টার থাকলে, পয়েন্টারটি যে মেমরি অ্যাড্রেস নির্দেশ করছে সেখানে রাখা মানটি জানতে ইচ্ছে হতে পারে।
এটি আমরা `*` অপারেটর দিয়ে করতে পারি:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p` অপারেশনটি `p`-তে রাখা মেমরি অ্যাড্রেসে সংরক্ষিত মানটি এনে দেয়।
এই অপারেশনটিকে প্রায়ই "ডিরেফারেন্সিং" বলা হয়।

পয়েন্টারটি যে মেমরি অ্যাড্রেস নির্দেশ করে সেখানে নতুন একটি মান অ্যাসাইন করতেও আমরা ডিরেফারেন্স অপারেটর ব্যবহার করতে পারি:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa`-তে অ্যাসাইন করলে `pa`-তে রাখা মেমরি অ্যাড্রেসে সংরক্ষিত মানটি বদলে যাবে।
যেহেতু `pa`-তে `a`-এর মেমরি অ্যাড্রেস আছে, তাই `*pa`-তে অ্যাসাইন করলে আমরা আসলে `a`-এর মানই বদলে দিচ্ছি!

তবে একটি সতর্কতার কথা: ডিরেফারেন্স করার আগে সবসময় দেখে নিন পয়েন্টারটি `nil` কি না।
একটি `nil` পয়েন্টার ডিরেফারেন্স করলে রানটাইমে প্রোগ্রামটি ক্র্যাশ করবে!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### স্ট্রাক্টের পয়েন্টার

এখন পর্যন্ত আমরা শুধু প্রিমিটিভ মানের পয়েন্টার দেখেছি।
আমরা স্ট্রাক্টের জন্যও পয়েন্টার তৈরি করতে পারি:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

আমরা একটি নতুন `Person` তৈরি করে সাথে সাথেই তার একটি পয়েন্টার সংরক্ষণ করতেও পারতাম:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

স্ট্রাক্টের পয়েন্টার থাকলে, কোনো একটি ফিল্ড অ্যাক্সেস করার আগে পয়েন্টারটি ডিরেফারেন্স করার দরকার পড়ে না:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## স্লাইস ও ম্যাপ আসলে পয়েন্টার

স্লাইস ও ম্যাপ বিশেষ টাইপ, কারণ এদের বাস্তবায়নেই পয়েন্টার থাকে।
এর মানে, বেশিরভাগ ক্ষেত্রেই এই টাইপগুলোর মানের মেমরি অ্যাড্রেস শেয়ার করার জন্য আমাদের আলাদা পয়েন্টার তৈরি করার দরকার হয় না।
ধরুন আমাদের একটি ফাংশন আছে যা একটি ম্যাপের একটি কী (key)-এর মান বাড়ায়:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

আমরা যদি একটি ম্যাপ তৈরি করে এই ফাংশনটি কল করি, তবে ফাংশনটি ম্যাপে যে পরিবর্তন করেছে তা ফাংশন শেষ হওয়ার পরেও টিকে থাকে।
পয়েন্টার ব্যবহার করলেও আমরা প্রায় একই রকম আচরণ পাই, তবে লক্ষ্য করুন এই উদাহরণে আমরা কোনো রেফারেন্সিং/ডিরেফারেন্সিং বা পয়েন্টারের কোনো সিনট্যাক্স ব্যবহার করছি না:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

স্লাইসে থাকা কোনো বিদ্যমান এলিমেন্ট বদলানোর ক্ষেত্রেও একই কথা প্রযোজ্য।

তবে `append`-এর মতো নতুন স্লাইস রিটার্ন করে এমন কাজগুলো একটি বিশেষ ক্ষেত্র এবং ফাংশনের বাইরে থাকা স্লাইসটি **নাও** পরিবর্তন করতে পারে।
এর কারণ স্লাইস ভেতরে ভেতরে যেভাবে কাজ করে, কিন্তু এটি আরও অ্যাডভান্সড একটি বিষয়, তাই আমরা এখানে বিস্তারিত আলোচনা করব না।
আপনার যদি সত্যিই কৌতূহল থাকে, তবে [Go Blog: Mechanics of 'append'][mechanics-of-append] পড়ে এ বিষয়ে আরও জানতে পারেন।
