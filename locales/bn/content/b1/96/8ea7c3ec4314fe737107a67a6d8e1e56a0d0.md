# পরিচিতি

এই অনুশীলনীটি আপনি [ব্যাকইয়ার্ড বার্ডওয়াচার][backyard-birdwatcher] অনুশীলনীতে যা দেখেছিলেন তার উপরেই গড়ে উঠেছে। এখানে পরিচয় ঘটবে সেই হায়ার-অর্ডার ওয়ার্ডগুলোর সাথে, যেগুলো একটি *কোটেশন* নেয়, মানে `[ ]` বন্ধনীর ভেতরে থাকা কোডের একটি টুকরো, যা দিয়ে কাজটি চালানো হয়।

## মান হিসেবে কোটেশন

একটি কোটেশন আসলে কোডের একটি আক্ষরিক টুকরো। আপনি এটিকে ডেটা হিসেবে অন্য একটি ওয়ার্ডে পাস করতে পারেন:

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

এখানে `[ 2 > ]` হলো একটি কোটেশন, যা একটি সংখ্যা নেয় এবং একটি বুলিয়ান রেখে যায়। `count` এটিকে প্রতিটি এলিমেন্টের উপর চালায় এবং ট্রুথি ফলাফলগুলো গুনে রাখে।

## ফিল্টারিং ও রিজেক্ট করা

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

`without` তার দ্বিতীয় আর্গুমেন্টটিকে একটি সেট হিসেবে ধরে: `seq`-এর যে কোনো এলিমেন্ট যদি `exclude`-এর *যেকোনো* এলিমেন্টের সাথে `=` হয়, সেটি বাদ পড়ে। `sift` হলো `reject`-এর কোটেশন-ছাড়া বিশেষ রূপ: এটি `f` ছাড়া বাকি সব এলিমেন্ট রেখে দেয়, যা আগের কোনো `map` রেখে যাওয়া ফাঁকগুলো পরিষ্কার করার জন্য সুবিধাজনক।

### টেস্টের ফলাফল ধরে রাখা

`find` মিলে যাওয়া *এলিমেন্টটি* ফিরিয়ে দেয়। যখন টেস্টটি আসলে আপনার কাঙ্ক্ষিত মানটিই *গণনা করে*, তখন `map-find` আপনাকে দ্বিতীয় বার পুরো কাজ করতে বাঁচায়: এটি কোটেশনটি প্রতিটি এলিমেন্টের উপর চালায় এবং প্রথম যে ফলাফলটি `f` নয় সেটি **এবং** যে এলিমেন্টটি সেটি তৈরি করেছে তা ফিরিয়ে দেয়।

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

যেসব এলিমেন্ট শর্ত পূরণ করে না, তাদের জন্য কোটেশনটি `f` ফিরিয়ে দেয়, আর যে একটি পূরণ করে তার জন্য আপনার ধরে রাখতে চাওয়া ফলাফলটি দেয়। যদি কোনো এলিমেন্টই শর্ত পূরণ না করে, তাহলে `map-find` ঠিক `find`-এর মতোই `f f` রেখে যায়।

### স্লট দিয়ে রেকর্ড ফিল্টার করা

যখন এলিমেন্টগুলো *টাপল*, তখন প্রেডিকেট সাধারণত তার স্বয়ংক্রিয়ভাবে তৈরি রিডার `slot>>` দিয়ে একটি স্লট বের করে সেটির উপর টেস্ট চালায়:

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## `with` দিয়ে একটি নির্দিষ্ট মান থ্রেড করা

কখনো কখনো প্রেডিকেটের এমন একটি মান দরকার হয় যা প্রতিটি কলে একই থাকে, যেমন একটি থ্রেশহোল্ড, একটি ভাজক বা একটি টার্গেট স্ট্রিং। [`kernel`][kernel]-এ থাকা `with` সেই নির্দিষ্ট মানটি কোটেশনের ভেতরে বসিয়ে দেয়, ফলে `( value elt -- ? )` এই দুই-আর্গুমেন্টের কোটেশনটি `filter`, `count`, `map` আর `each` যে এক-আর্গুমেন্টের কোটেশন আশা করে সেটিতে পরিণত হয়:

```
with ( value seq quot -- seq curry )
```

প্রতিটি এলিমেন্টভিত্তিক কলে স্ট্যাকে `( value elt )` দেখা যায়, অর্থাৎ আগে নির্দিষ্ট মান আর পরে বর্তমান এলিমেন্ট:

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## ম্যাপিং ও ইটারেশন

`map` ([`sequences`][sequences]-এ) প্রতিটি এলিমেন্টে একটি কোটেশন প্রয়োগ করে এবং ফলাফলগুলোর অ্যারে ফিরিয়ে দেয়। `each` একইভাবে হেঁটে যায় কিন্তু ফলাফলগুলো ফেলে দেয়, যা তখন কাজে লাগে যখন কোটেশনটি কেবল পার্শ্ব-প্রতিক্রিয়ার জন্যই চলে। `2map` *দুটি* সিকোয়েন্স একসাথে তাল মিলিয়ে হাঁটে এবং সম্পর্কিত এলিমেন্টগুলোকে মিলিয়ে দেয়; `2each` ও `2reduce` হলো যথাক্রমে তার কেবল-পার্শ্ব-প্রতিক্রিয়া আর ফোল্ডিং সংস্করণ; `zip` হলো 'মিলিয়ে না দিয়ে জোড়া বানানো'-র সংক্ষিপ্ত রূপ:

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

`2reduce` একটি অ্যাকুমুলেটরকে একসাথে দুটি সিকোয়েন্সের মধ্য দিয়ে থ্রেড করে, আর তার কোটেশনটি নেয় `( accumulator elt1 elt2 -- accumulator' )`। এখানে এটি একটি ডট প্রোডাক্ট জমা করে: প্রতিটি জোড়া গুণ হয়, এবং গুণফলগুলো যোগ করা হয় (`1*10 + 2*20 + 3*30`):

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

`map-as` হলো `map`-এর সঙ্গী, যা আউটপুট সিকোয়েন্সের টাইপ জোর করে নির্দিষ্ট করে দেয়। ইনপুট-টাইপের ডিফল্টটি বাতিল করতে এক্সেমপ্লার হিসেবে একটি খালি `{ }` বা `V{ }` পাস করুন। নাহলে একটি স্ট্রিংকে নন-ক্যারেক্টারে ম্যাপ করলে এরর হয়, কারণ Factor ফলাফলগুলোকে আবার একটি স্ট্রিংয়ে গুঁজে ফেলতে চেষ্টা করে।

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

দুটি সিকোয়েন্স নেওয়া দুই রূপই ছোট ইনপুটটির দৈর্ঘ্যে গিয়ে থেমে যায়। `zip` আসলে `[ 2array ] 2map`-এরই সমান, অর্থাৎ জোড়া মিলিয়ে দেওয়ার বদলে জোড়া ধরে রাখে।

## সর্টিং

`sort` স্বাভাবিক ক্রমে সাজানো একটি কপি ফিরিয়ে দেয়; `sort-by` ([`sorting`][sorting]-এ) প্রতিটি এলিমেন্ট থেকে বের করা একটি কী (key) অনুযায়ী সাজায়:

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## অ্যাগ্রিগেট করা

`map-sum` ([`sequences`][sequences]-এ) একটি কোটেশনকে পুরো সিকোয়েন্সজুড়ে ম্যাপ করে এবং এক পাসেই ফলাফলগুলো যোগ করে:

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## মিনিমাম ও ম্যাক্সিমাম

`minimum` ও `maximum` সরাসরি একটি সিকোয়েন্সের সবচেয়ে ছোট বা সবচেয়ে বড় এলিমেন্ট ফিরিয়ে দেয়। `minimum-by` ও `maximum-by` (সবগুলোই [`sequences`][sequences]-এ) সেই এলিমেন্টটি ফিরিয়ে দেয় যার বের করা কী (key) সবচেয়ে ছোট বা সবচেয়ে বড়:

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## নিজের হায়ার-অর্ডার ওয়ার্ড লেখা

যখন *আপনার* ওয়ার্ডটি রানটাইম আর্গুমেন্ট হিসেবে একটি কোটেশন নেয় এবং সেটিকে `map`, `filter`, `each` ইত্যাদিতে ফরওয়ার্ড করে, তখন আপনার ওয়ার্ডটি `; inline` দিয়ে ডিক্লেয়ার করুন। এতে কম্পাইলার প্রতিটি কল সাইটে আপনার ওয়ার্ডটি ইনলাইন করে, যেখানে কোটেশনটি একটি জানা লিটারাল। এটি ছাড়া কম্পাইলারের কাছে কোটেশনটির স্ট্যাক ইফেক্ট জানার কোনো উপায় থাকে না।

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

শুধু লিটারাল কোটেশন দিয়ে তৈরি ওয়ার্ডগুলোর `inline` দরকার হয় না, শুধু যেগুলো *বাইরে থেকে আসা* একটি কোটেশনকে ভেতরে পাঠায় সেগুলোরই দরকার।

যদি এমন কোনো `inline` ওয়ার্ড কখনো *নিজেকেই* কল করে, অর্থাৎ একটি রিকার্সিভ কম্বিনেটর হয়, তাহলে বদলে সেটিকে `; inline recursive` দিয়ে ডিক্লেয়ার করুন। বাড়তি ওয়ার্ডটি না থাকলে কম্পাইলার *"The inline recursive word ... must be declared recursive"* বার্তা দিয়ে থেমে যায়, যা আপনাকে ঠিক কী যোগ করতে হবে তা বলে দেয়।

## দ্বিতীয় এলিমেন্ট বের করা

দুই এলিমেন্টের একটি অ্যারের জন্য `second` তার দ্বিতীয় এলিমেন্টটি ফিরিয়ে দেয়। `first` ফিরিয়ে দেয় প্রথমটি। দুটোই [`sequences`][sequences]-এ আছে।

## সংখ্যা থেকে স্ট্রিং

`number>string ( n -- str )` ([`math.parser`][math.parser]-এ) একটি সংখ্যাকে তার দশমিক-স্ট্রিং রূপে বদলে দেয়:

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
