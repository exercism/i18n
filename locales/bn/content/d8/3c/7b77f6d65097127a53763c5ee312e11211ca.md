# ভূমিকা

## কমেন্ট

Common Lisp প্রোগ্রামারকে "কমেন্ট" লেখার সুযোগ দেয়, যা কম্পিউটার উপেক্ষা করে।
একক-লাইনের কমেন্ট এক বা একাধিক সেমিকোলন (`;`) দিয়ে শুরু হয়, আর মাঝেমধ্যে আপনি নিচের মতো কিছু দেখতে পাবেন:

```lisp
(code...) ; => value
```

এখানে কমেন্টটি বোঝাতে ব্যবহার করা হয়, ওই লাইনের কোড রান করার পর Common Lisp কী মান রিটার্ন করে।

লাইনের শেষে ছোট কমেন্টের জন্য একটি সেমিকোলন, কোডের একটি অংশের উপরে আরও বড় কমেন্টের জন্য দুটি, ফাংশনের মতো কিছু বর্ণনা করা লম্বা কমেন্টের জন্য তিনটি, আর সোর্স ফাইলের উপরে হেডারের মতো কমেন্টের জন্য চারটি ব্যবহার করাই প্রচলিত রীতি।

## কনস

Common Lisp-এর সব অবজেক্ট হয় "অ্যাটম" (একক, অবিভাজ্য মান), নয়তো "কনস" ("cons" নামের কনস্ট্রাক্ট ফাংশন দিয়ে তৈরি)।
একটি কনস দুইটি অংশ নিয়ে গঠিত: প্রথম এলিমেন্ট এবং বাকি এলিমেন্টগুলো।
ঐতিহাসিক কারণে এই দুই অংশকে `car` ও `cdr` বলা হয়।
এই কনসগুলো যখন কোড হিসেবে ইভ্যালুয়েট করা হয়, তখন প্রথম এলিমেন্টটি (`car`) কল করা ফাংশনটিকে বোঝায়, আর বাকি এলিমেন্টগুলো (`cdr`) ওই ফাংশনের আর্গুমেন্ট বোঝায়:

```lisp
(<function> <arg1> <arg2> ... <argN>)
; ^ car ^  |        ^ cdr ^
```

## এক্সপ্রেশন

Common Lisp-এর সব কোড S-এক্সপ্রেশন (Symbolic Expressions) দিয়ে তৈরি। সংক্ষেপে এগুলোকে sexprs বলা হয়। প্রতিটি sexpr হয় একটি অ্যাটম, নয়তো একটি কনস। S-এক্সপ্রেশন ইভ্যালুয়েট হলে সেগুলো স্বয়ংক্রিয়ভাবে কিছু মান রিটার্ন করে, যা ওই এক্সপ্রেশনের জায়গা নেয়। নিজের ফাংশন লেখার সময় (`defun` ব্যবহার করে), `defun`-এর বডির ভেতরের শেষ মানটি স্বয়ংক্রিয়ভাবে রিটার্ন হয়:

```lisp
;; Defining a new function
(defun gimme-foo () 'foo)
;; Calling the function as an S-Expression
(gimme-foo) ; => FOO
```

## সিম্বল

Common Lisp-এ সিম্বল হলো বিশেষ ধরনের মান, যা অন্য মানের দিকে নির্দেশ করতে পারে, কিংবা _কিওয়ার্ড_-এর ক্ষেত্রে নিজের দিকে।
লিস্প যখন সিম্বল ইভ্যালুয়েট করে, তখন সেগুলো যে মানের দিকে নির্দেশ করে, তা দিয়ে প্রতিস্থাপিত হয়:

```lisp
foo  ; => <whatever-foo-points-to>
:foo ; => :FOO
```

মনে রাখবেন, কিওয়ার্ড বোঝানো হয় শুরুর কোলন (`:`) দিয়ে।

কোটিং, অর্থাৎ S-এক্সপ্রেশনের আগে `'` যোগ করা, লিস্পকে ওই এক্সপ্রেশনটি ইভ্যালুয়েট না করতে বলে।
আমাদের `defun` উদাহরণে `'foo` কোট করার মাধ্যমে আমরা লিস্পকে `FOO` যে দিকে নির্দেশ করার কথা ছিল, তা খুঁজতে (এবং খুঁজে না পেতে) বাধা দিয়েছি, বরং `FOO` মানটি নিজেই রিটার্ন করেছি।
আমাদের প্রোগ্রামে যদি কোথাও `FOO` ডিফাইন করা না থাকে:

```lisp
foo  ; => <ERROR! Lisp doesn't know what foo points to!>
'foo ; => FOO
```

আপাতত আপনি এটিকে কেবল একটি ফাংশন থেকে সিম্বল রিটার্ন করার একটি উপায় হিসেবে ভাবতে পারেন, তবে আমরা কোটিং নিয়ে আবার ফিরে আসব এবং ভবিষ্যতের কনসেপ্ট অনুশীলনীতে এর আরও নানা দিক নিয়ে আলোচনা করব।
