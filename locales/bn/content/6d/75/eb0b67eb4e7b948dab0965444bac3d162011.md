# পরিচিতি

Gleam-এ কোনো মানের উপর প্যাটার্ন ম্যাচিং করার সময় আমাদের নিশ্চিত করতে হয় যে প্যাটার্নগুলো টাইপটির প্রতিটি সম্ভাব্য মানের সাথে মেলে, নইলে কোডটি কম্পাইল হবে না।

এই ফাংশনটি প্রত্যাখ্যাত হওয়া উচিত, কারণ এটি অ্যারেটি খালি থাকার কেসটি হ্যান্ডেল করেনি:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Gleam প্রোগ্রামে বেশিরভাগ সময় আমরা প্রতিটি সম্ভাব্য কেস হ্যান্ডেল করতে চাই, কিন্তু কিছু প্রোগ্রামে, যেমন প্রোটোটাইপ বা দ্রুত লেখা স্ক্রিপ্টে, আমরা হয়তো কেবল হ্যাপি পাথটির দিকে মনোযোগ দিতে চাই এবং বাকি কেসগুলোর জন্য কোড লিখতে না চাই। এখানেই Gleam-এর `let assert` কাজে আসে।

লেট অ্যাসারশনের সাহায্যে একটি প্যাটার্ন একটি টাইপের কেবল কিছু সম্ভাব্য মানের সাথে মিলতে পারে, আর প্যাটার্নটি কোনো মানের সাথে না মিললে প্রোগ্রামটি ক্র্যাশ করবে। `let assert` ব্যবহার করে আমরা উপরের ফাংশনটি এভাবে লিখতে পারি:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam লাইব্রেরিতে কখনোই লেট অ্যাসারশন ব্যবহার করা উচিত নয়, কারণ এগুলো প্রোগ্রাম ক্র্যাশ করাতে পারে। বরং এগুলোর উচিত `Result` টাইপ ব্যবহার করা এবং কোনো এরর কীভাবে হ্যান্ডেল করবেন তা অ্যাপ্লিকেশন ডেভেলপারের সিদ্ধান্তে ছেড়ে দেওয়া।
