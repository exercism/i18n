# পরিচিতি

## ফ্যান্টম টাইপ

Elm-এর টাইপগুলো জেনেরিক টাইপ সমর্থন করে, যা সাধারণত একটি ইন্টারফেসে নমনীয়তা বাড়ায়।
যেমন, `Maybe a` টাইপটি যেকোনো টাইপের একটি মান ধারণ করতে পারে।

```elm
type Maybe a = Nothing | Just a
```

লক্ষ্য করুন, উপরের উদাহরণে টাইপ প্যারামিটার `a` সমান চিহ্ন `=`-এর দুই দিকেই ব্যবহৃত হয়েছে।
আমরা বলি যে `a` টাইপ ডেফিনিশনের ভেতরের কিছু ডেটার সাথে বাঁধা।

### ফ্যান্টম টাইপ কৌশল

তবে কিছু ক্ষেত্রে টাইপ প্যারামিটারটি কেবল সমীকরণের বাম দিকেই দেখা যায়।

```elm
type Distance unit = Distance Float
```

উপরের `Distance`-এর ডেফিনিশনে `unit` একটি ফ্রি টাইপ প্যারামিটার, এটি টাইপের ভেতরের কোনো ডেটার সাথে বাঁধা নয়।
আমরা এই টাইপকে **ফ্যান্টম টাইপ**-ও বলতে পারি।

কম্পাইল টাইমে সীমাবদ্ধতা প্রয়োগ করতে চাইলে এটি আশ্চর্যজনকভাবে কাজে লাগে।
যেমন, আমরা নিশ্চিত করতে চাই যেন কেবল একই ইউনিটের দূরত্বই যোগ করি।

```elm
-- Distance is an opaque type, since the module does not expose its variants.
-- This means that users may only use the functions meter, foot and add to manipulate distances.
module Distance exposing (Distance, Meter, Foot, meter, foot, add)

-- The Distance type has a phantom type 'unit'.
type Distance unit = Distance Float

-- We define two types that will be used in place
-- of the phantom type 'unit' in our constructor functions.
type Meter = Meter
type Foot = Foot

-- Constructor for Meter
meter : Distance Meter
meter = Distance 1.0

-- Constructor for Foot
foot : Distance Foot
foot = Distance 0.3048

-- The add function cannot take two parameters of different types.
-- So we cannot add meters and feet by mistake.
add : Distance unit -> Distance unit -> Distance unit
add (Distance d1) (Distance d2) = Distance (d1 + d2)
```

ওই মডিউলের বাইরের কোড `Distance` টাইপের ভেতরের কিছু অ্যাক্সেস করতে পারে না।
ব্যবহারকারীরা দুটি `Distance Meter` যোগ করতে পারেন, কিন্তু একটি `Distance Meter` এবং একটি `Distance Foot` একসাথে যোগ করতে পারেন না।

```elm
import Distance exposing (Distance)

-- Compiles
twoMeters = Distance.add Distance.meter Distance.meter

-- Does not compile
errDist = Distance.add Distance.meter Distance.foot
```

### ফ্যান্টম টাইপ হিসেবে এক্সটেনসিবল রেকর্ড

কোন টাইপ ফ্যান্টম হতে পারে তা নিয়ে কোনো নিষেধাজ্ঞা নেই, রেকর্ড টাইপও ব্যবহার করা যায়।
ফ্যান্টম টাইপ হিসেবে ব্যবহার করলে রেকর্ডগুলো জটিল সীমাবদ্ধতা প্রকাশ করতে পারে, যা ফাংশনের মধ্য দিয়ে রূপান্তরিত হতে পারে।

চলুন `Distance` মডিউলের ভেতরে `LegoBlock` নামে একটি নতুন দূরত্বের ইউনিট যোগ করি।
নিয়ন্ত্রিত বস্তু হওয়ায় ভৌত ব্লকের সবসময় দুটি বৈশিষ্ট্য থাকে: তাদের দূরত্ব ভগ্নাংশহীন এবং ঋণাত্মক নয়।

```elm
type LegoBlock = LegoBlock

fourStuds : Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
fourStuds = Distance 4.0
```

`nonFractional` আর `nonNegative` এমন একটি রেকর্ডের ফিল্ড, যা টাইপ আর্গুমেন্টের বাইরে কোথাও নেই, তাই এদের `()` টাইপ দেওয়াই মানানসই, যাকে **ইউনিট টাইপ** বলা হয় এবং যা কেবল নিজের উপস্থিতি ছাড়া আর কোনো তথ্য ধারণ করে না।

ইচ্ছেমতো `LegoBlock` দূরত্ব পাওয়া অবশ্যই সম্ভব, যেমন দূরত্বের পার্থক্য বা অনুপাত হিসাব করার পরে।

```elm
negativeStud : Distance { properties | unit: LegoBlock, nonFractional : () }
negativeStud = Distance -1.0

threeFiddyStud : Distance { properties | unit: LegoBlock, nonNegative : () }
threeFiddyStud = Distance 3.50

crazyStud : Distance { properties | unit: LegoBlock }
crazyStud = Distance -13.37
```

উপরের সব মানই বৈধ এবং কম্পাইল হবে, তবে `fourStuds`-এর মতো মানগুলো আমাদের কাছে বিশেষ আগ্রহের, কারণ এদের মধ্যে `nonFractional` আর `nonNegative` দুটি বৈশিষ্ট্যই আছে, আর এগুলো এমন ভৌত ব্লক বোঝায় যেগুলো একসাথে মেলানো যায়:

```elm
combineLegoBlocks
  :  Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
  -> Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
  -> Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
combineLegoBlocks = add
```

চলুন কিছু ফাংশন যোগ করি, যাতে ব্যবহারকারীরা `LegoBlock` দূরত্ব তৈরি ও পরিমার্জন করতে পারেন।

```elm
newLegoBlock : Float -> Distance { properties | unit: LegoBlock }
newLegoBlock dist = Distance dist

floorDistance : Distance properties -> Distance { properties | nonFractional : () }
floorDistance (Distance dist) = Distance (toFloat (floor dist))

ceilingDistance : Distance properties -> Distance { properties | nonFractional : () }
ceilingDistance (Distance dist) = Distance (toFloat (ceiling dist))

absDistance : Distance properties -> Distance { properties | nonNegative : () }
absDistance (Distance dist) = Distance (abs dist)
```

লক্ষ্য করুন, `floorDistance`, `ceilingDistance` আর `absDistance` `LegoBlock` ছাড়াও অন্য ইউনিট সামলাতে পারে, এবং সাধারণভাবে ইনপুটের বৈশিষ্ট্য নিয়ে কোনো অনুমান করে না, এরা কেবল নিশ্চিত করে যে আউটপুটে একটি নির্দিষ্ট বৈশিষ্ট্য থাকবে, সেটি `nonFractional` হোক বা `nonNegative`।

চলুন কিছু ফলাফল দেখি।

```elm
import Distance exposing (Distance)

-- Compiles
distance1 = combineLegoBlocks fourStuds fourStuds

-- Does not compile
distance2 = combineLegoBlocks fourStuds threeFiddyStud

-- Compiles
distance3 = combineLegoBlocks fourStuds (floorDistance threeFiddyStud)

-- Does not compile
distance4 = combineLegoBlocks fourStuds negativeStud

-- Compiles
distance5 = combineLegoBlocks fourStuds (absDistance negativeStud)

-- Does not compile
distance6 = combineLegoBlocks fourStuds crazyStud

-- Compiles
distance7 = combineLegoBlocks fourStuds (floorDistance (absDistance crazyStud))

-- Compiles
distance8 = combineLegoBlocks fourStuds (ceilingDistance (absDistance crazyStud))
```

সাধারণভাবে `floorDistance` আর `ceilingDistance` ভিন্ন ফলাফল দেয়, কিন্তু একই নিশ্চয়তা দেয়।
এটাই ফ্যান্টম টাইপ কৌশলের শক্তি: ব্যবহারকারীদের শক্তিশালী নিশ্চয়তা বজায় রেখেই নমনীয় বিকল্প দেওয়া।
