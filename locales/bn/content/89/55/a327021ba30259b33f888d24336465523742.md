# নির্দেশনা সংযোজন

## `from_quote`-এর সুবিধা ও অসুবিধা

`Card.from_quote` ফাংশনটি একটি স্ট্রিং পার্স করে একটি `Card`-এ রূপান্তর করে। এর ফলে এই ধরনের কোড লেখা সম্ভব হয়:

```roc
card : Card
card = "Q"
```

এই কোডটি কম্পাইল টাইমে অন্তর্নিহিতভাবে `Card.from_quote("Q")` কল করে। এতে প্রোগ্রামের গতি বাড়তে পারে, কারণ রানটাইমে পার্সিং সামলাতে হয় না, আর এটাও নিশ্চিত হয় যে `from_quote`-এর প্রত্যাখ্যান করা কার্ডগুলো রানটাইমের বদলে কম্পাইল টাইমেই ধরা পড়ে। তাছাড়া, এতে কোড সুন্দর ও পড়ার উপযোগী হয়। উদাহরণস্বরূপ, এই অনুশীলনীর একটি টেস্ট দেখুন:

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

তবে এই কোড পড়ে কেউ ধরে নিতে পারেন যে `simulate_game` ফাংশনটি দুটি `List(Str)` ধারণ করা একটি রেকর্ড নেয়, অথচ আসলে সেটি দুটি `List(Card)` ধারণ করা একটি রেকর্ড। এতে বিভ্রান্তি ও ভুল হতে পারে। তাই আপনি হয়তো একটু দীর্ঘ কিন্তু আরও স্পষ্ট ফরম্যাটটি পছন্দ করবেন: `"Q".Card`, যা কম্পাইল টাইমেই `from_quote` কল করে।

আপনার নিজের প্রোগ্রামে আপনি বরং `from_str` ব্যবহার করতে চাইতে পারেন:

```roc
Card := { ... }.{
    from_str : Str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

এছাড়াও আপনি কম্পাইল টাইমে `from_str` (বা অন্য যেকোনো পিওর ফাংশন) কল করতে পারেন, এভাবে:

```roc
Ok(card) = Card.from_str("Q")
```

লক্ষ্য করুন: এই ডেফিনিশনটি টপ লেভেলে রাখলে সেটি কম্পাইল টাইমে রান হয় (কারণ ফাংশনটি পিওর এবং তার ইনপুট কম্পাইল টাইমেই জানা থাকে)। কোনো ফাংশনের ভিতরে আপনি রানটাইমে `from_str` ব্যবহার করতে পারেন।
