# পরিচিতি

C#-এ টাপল হলো একটি ডেটা স্ট্রাকচার, যা ডেটা সাজিয়ে রাখে এবং যেকোনো টাইপের দুটি বা তার বেশি ফিল্ড ধারণ করে।

সাধারণত দুই বা তার বেশি এক্সপ্রেশন কমা দিয়ে আলাদা করে বন্ধনীর ভেতরে বসিয়ে টাপল তৈরি করা হয়।

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

অন্য যেকোনো এক্সপ্রেশনের মতোই টাপল নানা ভাবে ব্যবহার করা যায়: [অ্যাসাইনমেন্টে][tuple-assignment], কোনো ফিল্ড বা ভ্যারিয়েবল ইনিশিয়ালাইজ করতে, মেথড থেকে [রিটার্ন ভ্যালু][tuple-return-values] হিসেবে, কিংবা প্যারামিটার হিসেবে পাঠিয়ে। এগুলোর [সমতা][tuple-equality] পরীক্ষা করা যায়। টাপলের সমতা `pattern-matching-tuples` অনুশীলনীতে বিস্তারিত দেখানো হয়েছে, তবে সম্পূর্ণতার খাতিরে নিচের কোডে একটি উদাহরণ দেওয়া হলো।

ডট সিনট্যাক্স ব্যবহার করে ফিল্ডগুলো বের করা হয়। ডিফল্টভাবে প্রথম ফিল্ডটি `Item1`, দ্বিতীয়টি `Item2`, এভাবে চলতে থাকে। ডিফল্ট ছাড়া অন্য নাম নিয়ে নিচে _নামকরণ_ অংশে আলোচনা করা হয়েছে।

টাপলকে জেনেরিক প্যারামিটার হিসেবেও ব্যবহার করা যায়, যেমন `IList<(bool, string)>`

এছাড়া টাপল "ডিকনস্ট্রাকশন" সমর্থন করে, যা নিয়ে নিচে আলোচনা করা হয়েছে, এবং প্যাটার্ন ম্যাচিংয়েও ব্যবহার করা যায়, যা পরের একটি অনুশীলনীতে আলোচনা করা হয়েছে।

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

এই [ভূমিকা][tuples] অংশে টাপল কীভাবে ডিফাইন ও ব্যবহার করতে হয় তা দেখানো হয়েছে।

## নামকরণ

`Item1` ইত্যাদি ফিল্ডের নাম দিয়ে কোড সহজপাঠ্য হয় না। ফিল্ডগুলোর নাম দেওয়ার ৩টি উপায় আছে: ক) টাইপ ডিক্লারেশনে, খ) যে এক্সপ্রেশনটি টাপলটি তৈরি করে তার মধ্যে, গ) [টাপল প্রজেকশন ইনিশিয়ালাইজার][tuple-projection-initializers]-এর মাধ্যমে (এখানে দেখানো হয়নি)।

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

নামকরণের কৌশল নিয়ে বেশি চালাকি করার চেষ্টা করবেন না। এটা আসলে শুধুই সিনট্যাকটিক সুগার। উদাহরণস্বরূপ, অন্য একটি টাপল থেকে অ্যাসাইন করার সময় আপনি টাপলের নামগুলো বদলাতে পারেন না।

## ডিকনস্ট্রাকশন

কখনো কখনো একটি টাপল নিয়ে তার ফিল্ডগুলো একাধিক ভ্যারিয়েবলে অ্যাসাইন করা এবং দরকার হলে সেগুলো ইনিশিয়ালাইজ করা সুবিধাজনক। এই কৌশলটিকে [ডিকনস্ট্রাকশন][tuple-deconstruction] বলা হয়। (এটি নিজের অবজেক্টেও প্রয়োগ করা যায়। দেখুন [এখানে][udt-deconstruction])।

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## ফিল্ড অ্যাসাইনমেন্ট

টাপলের ফিল্ডগুলো আলাদা আলাদাভাবে অ্যাসাইন করা যায়। তবে C#-এ অপরিবর্তনীয়তার দিকে ঝোঁক বাড়ায় এ ধরনের ব্যবহার খুব একটা দেখা যায় না। টাপলকে প্রায়ই অপরিবর্তনীয় ভেবে ব্যবহার করা হয়, যদিও সেগুলো আসলে তা নয়।

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## পটভূমি

আমরা যে টাপল নিয়ে আলোচনা করছি, সেটিকে [`System.Tuple`][system-tuple]-এর সাথে গুলিয়ে ফেলা উচিত নয়, যা সম্ভবত কেবল লিগ্যাসি কোডবেসেই পাওয়া যাবে।

`System.ValueTuple`-এর ক্ষেত্রে বিষয়টি আরেকটু বেশি বিভ্রান্তিকর। [`System.ValueTuple`][system-value-tuple]-এর শেষ ওভারলোডের [ডকুমেন্টেশন][system-value-tuple]-এ বলা হয়েছে, "The value tuple types provide the runtime implementation that supports tuples in C# "। এখানে "value tuple types" বলতে তারা `System.ValueTuple`-এর জেনেরিক ওভারলোডগুলোকে বোঝাচ্ছে। আর "tuples" বলতে বোঝাচ্ছে সেই জিনিসগুলোকে, যা নিয়েই এই অনুশীলনীতে আমরা আলোচনা করেছি। মূলত তারা বলছে, `System.ValueTuple` হলো টাপলের একটি ইমপ্লিমেন্টেশন ডিটেইল। বেশিরভাগ মানুষের কাছে বেশিরভাগ সময়ে এটা খুব একটা আগ্রহের বিষয় হওয়ার কথা নয়। দুর্ভাগ্যবশত "tuples" নিয়ে লেখা অনেক ডকুমেন্টেশনেই, মাইক্রোসফটের নিজের ডকুমেন্টেশনসহ, `System.ValueTuple`-এর উল্লেখ ছড়িয়ে আছে। এ ধরনের উল্লেখ এড়িয়ে যাওয়াই বোধহয় নিরাপদ।

## অন্যান্য ব্যবহার ও সীমাবদ্ধতা

প্যাটার্ন ম্যাচিং টাপলের একটি বিশেষভাবে ফলপ্রসূ ব্যবহার। এটি পরের একটি অনুশীলনীতে আলোচনা করা হয়েছে।

টাপল আরও কিছু ছোটখাটো স্টাইলিশ ব্যবহারের সুযোগ দেয়:

- একাধিক অ্যাসাইনমেন্ট (বিশেষত কনস্ট্রাক্টরে), যেমন `(this.field1, this.field2) = (arg1, arg2);`
- মান অদলবদল বা পুনর্ব্যবহার, যেমন `(a, b) = (b, a);`
- অ্যারেতে `struct`-এর বদলে ব্যবহার
- ডিকশনারির কী (key) হিসেবে বা সেটের উপাদান হিসেবে ব্যবহার
- LINQ-এ ব্যবহার। (LINQ নিয়ে পরের অনুশীলনীগুলোতে আলোচনা করা হয়েছে)।

ডকুমেন্টেশনে টাপলকে হালকা ওজনের একটি ব্যবস্থা হিসেবে বর্ণনা করা হয়েছে, আর সফলভাবে ব্যবহারের চাবিকাঠি এটাই। ক্লাস বা struct-এর বদলে টাপল ব্যবহার করলে তার ফিল্ডের টাইপ এবং সম্ভবত নামগুলো বিরক্তিকরভাবে বারবার লিখতে হতে পারে। বিশেষত মেথডের আর্গুমেন্ট হিসেবে বা কালেকশনের জেনেরিক আর্গুমেন্ট হিসেবে এটি প্রযোজ্য।

একাধিক অ্যাসাইনমেন্ট আর অদলবদলের মতো কৌশলগুলো বিচার-বুদ্ধি খাটিয়ে ব্যবহার করাই ভালো।

সমতা ও অসমতা ছাড়া অন্য রিলেশনাল অপারেশন সমর্থিত নয়।

মনে রাখবেন, টাপল ভাষাটিতে তুলনামূলকভাবে সম্প্রতি (C# 7) যুক্ত হয়েছে, তাই আপনি যদি এগুলো ব্যবহার করতে চান, তাহলে নিশ্চিত হয়ে নিন যে আপনার কোডবেস ভাষার [ভার্সন][language-version] 7 বা তার পরেরটি ব্যবহার করছে।
