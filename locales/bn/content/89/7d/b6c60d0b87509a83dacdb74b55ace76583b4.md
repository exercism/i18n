# সম্পর্কে

অ্যাসেম্বলিতে যেকোনো ডেটাই বাইটের একটি ক্রম।
এর মানে হলো, যেকোনো ডেটাকেই ওই অন্তর্নিহিত বাইটগুলোর একটি **[অ্যারে][array]** হিসেবে দেখা যায়।

## অ্যারের এলিমেন্ট অ্যাক্সেস করা

মেমরিতে যেকোনো মান অ্যাক্সেস করতে হলে তার **ইফেক্টিভ অ্যাড্রেস** হিসাব করা প্রয়োজন।
একটি ইফেক্টিভ অ্যাড্রেস হলো এমন একটি এক্সপ্রেশন, যা নিম্নলিখিত অংশগুলো নিয়ে গঠিত হতে পারে:

- একটি _বেস অ্যাড্রেস_, যেমন ধরা যাক কোনো ভ্যারিয়েবলের লেবেল দিয়ে নির্দেশিত অ্যাড্রেস।
- একটি _ইন্ডেক্স রেজিস্টার_, যাকে সম্ভবত `1`, `2`, `4` বা `8` দিয়ে স্কেল করা হয়।
- একটি সাইনড ৩২-বিট _ডিসপ্লেসমেন্ট_, যা হলো এমন একটি সংখ্যা, যেটি বেস অ্যাড্রেসের সাথে যোগ করা হয় (বা বিয়োগ করা হয়)।

লক্ষ্য করুন, এই অ্যাড্রেস _০-ইনডেক্সড_, তাই কোনো অফসেট ছাড়া একটি বেস অ্যাড্রেস কোনো ভ্যারিয়েবলের প্রথম বাইটকে নির্দেশ করে।
এই কারণেই কোনো অফসেট ছাড়া শুধু একটি লেবেল দিয়ে মেমরি ডিরেফারেন্স করলে, যেমনটি আগের কনসেপ্টগুলোতে করা হয়েছে, প্রথম বাইট থেকে শুরু হওয়া একটি মান পাওয়া যায়:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 হলো [লিটল এন্ডিয়ান][endianness]।
এর মানে হলো, একটি মাল্টিবাইট মানের সবচেয়ে কম তাৎপর্যপূর্ণ বাইটটি সবচেয়ে ছোট মেমরি অ্যাড্রেসে সংরক্ষিত থাকে।

ফলে, একটি মাল্টিবাইট মানের আলাদা আলাদা বাইট অ্যাক্সেস করার সময়, আরও তাৎপর্যপূর্ণ বাইটে পৌঁছাতে বেস অ্যাড্রেসের সাথে একটি ধনাত্মক অফসেট যোগ করতে হয়।

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

মানের একটি তালিকা দিয়ে ডিক্লেয়ার করা একটি ইনিশিয়ালাইজড ভ্যারিয়েবল হলো সেই মানগুলোরই একটি অ্যারে, যেখানে প্রতিটি এলিমেন্টের আকার নির্দিষ্ট করা থাকে।
তবে অফসেট সবসময় _বাইটে_ হিসাব করা হয়, এমনকি অ্যারের প্রতিটি এলিমেন্টের আকার বড় হলেও:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

লক্ষ্য করুন, যেহেতু অ্যাড্রেস বাইটে হিসাব করা হয়, তাই অ্যারের যেকোনো এলিমেন্টের একটি আলাদা বাইট সরাসরি অ্যাক্সেস করা সম্ভব:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

একই কারণে, একটি এলিমেন্টের আকারের চেয়ে বেশি ডেটাও একটি একক ইন্সট্রাকশনে অ্যাক্সেস করা সম্ভব:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
অ্যাসেম্বলি অ্যারে অ্যাক্সেসে কোনো বাউন্ড চেক করে না।
অ্যারের শেষের পরে থাকা কোনো ইন্ডেক্স তার বাইরের মেমরি পড়ে বা লেখে।
এর ফলে নীরবে ভুল ফলাফল আসতে পারে, অন্য ডেটা নষ্ট হতে পারে এবং অ্যাক্সেস করা মেমরি ম্যাপ করা না থাকলে রানটাইম ফল্ট হতে পারে।
প্রতিটি ইফেক্টিভ অ্যাড্রেস অ্যারের ভেতরে রাখার দায়িত্ব প্রোগ্রামারের।
~~~~

## একটি ইনিশিয়ালাইজড অ্যারের আকার হিসাব করা

NASM (The Netwide Assembler, এই ট্র্যাকের ব্যবহৃত অ্যাসেম্বলার) এর একটি বিশেষ চিহ্ন (`$`) আছে, যা মেমরিতে বর্তমান অবস্থান নির্দেশ করে।
এই চিহ্নটি অ্যারের দখল করা মোট মেমরি আকার হিসাব করার একটি সুবিধাজনক উপায় দেয়:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

`example`-এর ঠিক পরে ব্যবহার করলে, `$`-এর মধ্যে অ্যারের শেষের মেমরি অ্যাড্রেস থাকে।
এর মানে হলো, `$ - example` হলো ওই অ্যাড্রেস আর `example` লেবেল দ্বারা নির্দেশিত অ্যাড্রেসের মধ্যে পার্থক্য।
এটাই হলো `example` দ্বারা নির্দেশিত অ্যারের দখল করা মোট আকার, বাইটে।

তাই এই মান দিয়ে `example_length` ডিফাইন করে আমরা একটি ৮-বাইটের ভ্যারিয়েবল তৈরি করেছি, যা অ্যারের আকার, বা দৈর্ঘ্য, বাইটে সংরক্ষণ করে।

## .bss সেকশন

আনইনিশিয়ালাইজড ডেটা **[.bss সেকশনে][bss]** ডিক্লেয়ার করা হয়।
বেশিরভাগ প্ল্যাটফর্মে, প্রোগ্রামের শুরুতে OS এই ডেটা শূন্য দিয়ে পূর্ণ করে।

NASM-এ একটি আনইনিশিয়ালাইজড ভ্যারিয়েবলের থাকে একটি নাম, ডেটার আকার নির্দেশ করে এমন একটি ডিরেক্টিভ এবং সংরক্ষণের জন্য এলিমেন্টের সংখ্যা।
এগুলোর প্রত্যেকটি অন্যটি থেকে একটি স্পেস দিয়ে আলাদা করা হয়।

প্রধান ডিরেক্টিভগুলো এবং তাদের সংশ্লিষ্ট ডেটা আকার:

| ডিরেক্টিভ | আকার    |
| :-------: | :------ |
|   resb    | ১ বাইট  |
|   resw    | ২ বাইট |
|   resd    | ৪ বাইট |
|   resq    | ৮ বাইট |

যেমন, এটি `example` নামের একটি ভ্যারিয়েবলে `3` বাইটের জন্য আনইনিশিয়ালাইজড জায়গা সংরক্ষণ করে:

```x86asm
section .bss
    example resb 3
```

আর এটি `arr` নামের একটি ভ্যারিয়েবলে `10` গুণ `8` বাইট (অর্থাৎ `80` বাইট) আনইনিশিয়ালাইজড জায়গা সংরক্ষণ করে:

```x86asm
section .bss
    arr resq 10
```

`section .bss`-এর ভ্যারিয়েবলগুলো মিউটেবল, অর্থাৎ এগুলো পড়া ও লেখা যায়।

আনইনিশিয়ালাইজড ডেটা ইনিশিয়ালাইজড ডেটার মতোই তার ইফেক্টিভ অ্যাড্রেস ব্যবহার করে অ্যাক্সেস করা যায়।
একইভাবে, এগুলোরও স্ট্যাটিক স্টোরেজ ডিউরেশন থাকে এবং একই সোর্স ফাইলের যেকোনো ফাংশন থেকে অ্যাক্সেস করা যায় (আর `global` হিসেবে ডিক্লেয়ার করা থাকলে অন্য সোর্স ফাইল থেকেও)।

## lea ইন্সট্রাকশন দিয়ে অ্যারের অ্যাড্রেস অ্যাক্সেস করা

আগের একটি কনসেপ্টে আলোচনা করা হয়েছে, `lea` ইন্সট্রাকশন একটি ইফেক্টিভ মেমরি অ্যাড্রেস হিসাব করে।
একই সেমান্টিক্স মেনে এটি অ্যারের যেকোনো এলিমেন্টের অ্যাড্রেস হিসাব করতে ব্যবহার করা যায়।

লক্ষ্য করুন, রিলেটিভ অ্যাড্রেসিংয়ে আরও জটিল অ্যাড্রেস তৈরি করার আগে প্রায়ই ভ্যারিয়েবলের অ্যাড্রেস একটি রেজিস্টারে লোড করা প্রয়োজন হয়:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea` ইন্সট্রাকশনের একটি সুবিধা হলো, এটি ওই অ্যাড্রেসের মেমরি সত্যিকারের অ্যাক্সেস না করেই একটি মান হিসাব করতে অ্যাড্রেস-হিসাবের পাটিগণিত ব্যবহার করে।
এই কারণে কোনো রেজিস্টারে মেমরি অ্যাড্রেস না থাকলেও পাটিগণিতের হিসাব করতে এটি কাজে লাগে:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
