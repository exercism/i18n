## একটি প্রমিসের লাইফসাইকেল

একটি `Promise`-এর তিনটি স্টেট থাকে:

1. পেন্ডিং
2. ফুলফিল্ড
3. রিজেক্টেড

তৈরি হওয়ার সময় একটি প্রমিস পেন্ডিং অবস্থায় থাকে।
ভবিষ্যতে কোনো এক সময়ে এটি _রিজলভ_ বা _রিজেক্ট_ হতে পারে।
একবার কোনো প্রমিস রিজলভ বা রিজেক্ট হয়ে গেলে, তা আর কখনোই রিজলভ বা রিজেক্ট হতে পারে না, আর তার স্টেটও বদলাতে পারে না।

অন্যভাবে বললে:

1. পেন্ডিং থাকার সময়, একটি প্রমিস:
   - ফুলফিল্ড বা রিজেক্টেড, এই দুটি স্টেটের যেকোনোটিতে রূপান্তরিত হতে পারে।
2. ফুলফিল্ড থাকার সময়, একটি প্রমিস:
   - অন্য কোনো স্টেটে রূপান্তরিত হতে পারবে না।
   - একটি মান থাকতে হবে, যা বদলাবে না।
3. রিজেক্টেড থাকার সময়, একটি প্রমিস:
   - অন্য কোনো স্টেটে রূপান্তরিত হতে পারবে না।
   - একটি কারণ থাকতে হবে, যা বদলাবে না।

## একটি প্রমিস রিজলভ করা

একটি প্রমিস বিভিন্নভাবে রিজলভ করা যায়:

```javascript
// Creates a promise that is immediately resolved
Promise.resolve(value);

// Creates a promise that is immediately resolved
new Promise((resolve) => {
  resolve(value);
});

// Chaining a promise leads to a resolved promise
somePromise.then(() => {
  // ...
  return value;
});
```

উপরের উদাহরণগুলোতে `value` _যেকোনো কিছু_ হতে পারে, যার মধ্যে আছে একটি এরর, `undefined`, `null` বা আরেকটি প্রমিস।
সাধারণত আপনি এমন একটি মান দিয়ে রিজলভ করতে চান, যেটি এরর নয়।

## একটি প্রমিস রিজেক্ট করা

একটি প্রমিস বিভিন্নভাবে রিজেক্ট করা যায়:

```javascript
// Creates a promise that is immediately rejected
Promise.reject(reason)

// Creates a promise that is immediately rejected
new Promise((_, reject) {
  reject(reason)
})

// Chaining a promise with an error leads to a rejected promise
somePromise.then(() => {
  // ...
  throw reason
})
```

উপরের উদাহরণগুলোতে `reason` _যেকোনো কিছু_ হতে পারে, যার মধ্যে আছে একটি এরর, `undefined` বা `null`।
সাধারণত আপনি একটি এরর দিয়ে রিজেক্ট করতে চান।

## একটি প্রমিস চেইন করা

কোনো প্রমিস রিজলভ বা রিজেক্ট হওয়ার পর, ভবিষ্যতের একটি অ্যাকশন দিয়ে সেটিকে _চালিয়ে যাওয়া_ যায়।

- `promise` রিজলভ হলে [`promise.then()`][promise-then] কল হয়
- `promise` রিজেক্ট হলে [`promise.catch()`][promise-catch] কল হয়
- `promise` রিজলভ বা রিজেক্ট, যেকোনোটি হলে [`promise.finally()`][promise-finally] কল হয়

### **then**

প্রতিটি প্রমিসই "thenable"।
এর মানে হলো, একটি `then` ফাংশন আছে, যা আসল প্রমিস রিজলভ হওয়ার পর এক্সিকিউট হয়।
`promise.then(onResolved)` দিলে, `onResolved` কলব্যাকটি আসল প্রমিস যে মান দিয়ে রিজলভ হয়েছিল সেটি পায়।
এটি সবসময় একটি _নতুন_ "চেইনড" প্রমিস রিটার্ন করে।

`then` থেকে একটি `value` রিটার্ন করলে "চেইনড" প্রমিসটি রিজলভ হয়।
`then`-এ একটি `reason` থ্রো করলে "চেইনড" প্রমিসটি রিজেক্ট হয়।

```javascript
const promise1 = new Promise(function (resolve, reject) {
  setTimeout(() => {
    resolve('Success!');
  }, 1000);
});

const promise2 = promise1.then(function (value) {
  console.log(value);
  // expected output: "Success!"

  return true;
});
```

এটি প্রায় ১০০০ ms পর `"Success!"` লগ করবে।
`promise1`-এর স্টেট ও মান হবে `resolved` এবং `"Success!"`।
`promise2`-এর স্টেট ও মান হবে `resolved` এবং `true`।

একটি দ্বিতীয় আর্গুমেন্টও আছে, যা আসল প্রমিস রিজেক্ট হলে চলে।
`promise.then(onResolved, onRejected)` দিলে, `onResolved` কলব্যাকটি আসল প্রমিস যে মান দিয়ে রিজলভ হয়েছিল সেটি পায়, অথবা `onRejected` কলব্যাকটি প্রমিস যে কারণে রিজেক্ট হয়েছিল সেটি পায়।

```javascript
const promise1 = new Promise(function (resolve, reject) {
  setTimeout(() => {
    resolve('Success!');
  }, 1000);

  if (Math.random() < 0.5) {
    reject('Nope!');
  }
});

function log(value) {
  console.log(value);
  return true;
}

function shout(reason) {
  console.error(reason.toUpperCase());
  return false;
}

const promise2 = promise1.then(log, shout);
```

- প্রায় অর্ধেক ক্ষেত্রে, এটি প্রায় ১০০০ ms পর `"Success!"` লগ করবে।
  - `promise1`-এর স্টেট ও মান হবে `resolved` এবং `"Success!"`।
  - `promise2`-এর স্টেট ও মান হবে `resolved` এবং `true`।
- প্রায় অর্ধেক ক্ষেত্রে, এটি সাথে সাথে `"NOPE!"` লগ করবে।
  - `promise1`-এর স্টেট ও মান হবে `rejected` এবং `Nope!`।
  - `promise2`-এর স্টেট ও মান হবে `resolved` এবং `false`।

এটা বোঝা জরুরি যে লাইফসাইকেলের নিয়মের কারণে, যখন এটি `reject` করে, তখন প্রায় ১০০০ms পর আসা `resolve`-টি চুপচাপ উপেক্ষা করা হয়, কারণ একবার রিজেক্ট বা রিজলভ হয়ে গেলে ভেতরের স্টেট আর বদলাতে পারে না।
এটাও বোঝা জরুরি যে একটি প্রমিস থেকে মান রিটার্ন করলে সেটি রিজলভ হয়, আর কোনো মান থ্রো করলে সেটি রিজেক্ট হয়।
`promise1` রিজলভ হলে এবং একটি চেইনড `onResolved` থাকলে: `then(onResolved)`, তখন সেই পরবর্তীটি একটি নতুন প্রমিস, যা রিজলভ বা রিজেক্ট হতে পারে।
`promise1` রিজেক্ট হলে কিন্তু একটি চেইনড `onRejected` থাকলে: `then(, onRejected)`, তখন সেই পরবর্তীটি একটি নতুন প্রমিস, যা রিজলভ বা রিজেক্ট হতে পারে।

### **catch**

কখনো কখনো আপনি এরর ধরে রাখতে চান এবং শুধু তখনই এগিয়ে যেতে চান, যখন আসল প্রমিস `reject` করে।
`promise.catch(onCatch)` দিলে, `onCatch` কলব্যাকটি আসল প্রমিস যে কারণে রিজেক্ট হয়েছিল সেটি পায়।
এটি সবসময় একটি _নতুন_ "চেইনড" প্রমিস রিটার্ন করে।

`catch` থেকে একটি `value` রিটার্ন করলে "চেইনড" প্রমিসটি রিজলভ হয়।
`catch`-এ একটি `reason` থ্রো করলে "চেইনড" প্রমিসটি রিজেক্ট হয়।

```javascript
const promise1 = new Promise(function (resolve, reject) {
  setTimeout(() => {
    resolve('Success!');
  }, 1000);

  if (Math.random() < 0.5) {
    reject('Nope!');
  }
});

function log(value) {
  console.log(value);
  return 'done';
}

function recover(reason) {
  console.error(reason.toUpperCase());
  return 42;
}

const promise2 = promise1.catch(recover).then(log);
```

প্রায় অর্ধেক ক্ষেত্রে, এটি প্রায় ১০০০ ms পর `"Success!"` লগ করবে।
বাকি অর্ধেক ক্ষেত্রে, এটি সাথে সাথে `42` লগ করবে।

- `promise1` রিজলভ হলে, `catch` বাদ পড়ে এবং এটি `then`-এ পৌঁছায়, আর মানটি লগ করে।
  - `promise1`-এর স্টেট ও মান হবে `resolved` এবং `"Success!"`।
  - `promise2`-এর স্টেট ও মান হবে `resolved` এবং `"done"`;
- `promise1` রিজেক্ট হলে, `catch` এক্সিকিউট হয়, যা _একটি মান রিটার্ন করে_, ফলে চেইনটি এখন `resolved`, এবং এটি `then`-এ পৌঁছায়, আর মানটি লগ করে।
  - `promise1`-এর স্টেট ও মান হবে `rejected` এবং `"Nope!"`।
  - `promise2`-এর স্টেট ও মান হবে `resolved` এবং `"done"`;

### **finally**

কখনো কখনো আপনি একটি প্রমিস সেটল হওয়ার পর কোড এক্সিকিউট করতে চান, প্রমিসটি রিজলভ করুক বা রিজেক্ট করুক।
`promise.finally(onSettled)` দিলে, `onSettled` কলব্যাকটি কিছুই পায় না।
এটি সবসময় একটি _নতুন_ "চেইনড" প্রমিস রিটার্ন করে।

`finally` থেকে একটি `value` রিটার্ন করলে আসল প্রমিসের স্টেটাস ও মান কপি হয়, `value`-টি উপেক্ষা করে।
`finally`-এ একটি `reason` থ্রো করলে "চেইনড" প্রমিসটি রিজেক্ট হয়, আর আসল প্রমিসের যেকোনো স্টেটাস ও মান বা কারণ মুছে যায়।

## উদাহরণ

বিভিন্ন মেথড একসাথে:

```javascript
const myPromise = new Promise(function (resolve, reject) {
  const sampleData = [2, 4, 6, 8];
  const randomNumber = Math.round(Math.random() * 5);

  if (sampleData[randomNumber]) {
    resolve(sampleData[randomNumber]);
  } else {
    reject('Sampling did not result in a sample');
  }
});

const finalPromise = myPromise
  .then(function (sampled) {
    // If the random number was 0, 1, 2, or 3, this will be
    // reached and the number 2, 4, 6, or 8 will be logged.
    console.log(`Sampled data: ${sampled}`);
    return 'yay';
  })
  .catch(function (reason) {
    // If the random number was 4 or 5, this will be reached and
    // reason will be "An error occurred". The entire chain will
    // then reject with an Error with the reason as message.
    throw new Error(reason);
  })
  .finally(function () {
    // This will always log after either the sampled data is
    // logged or the error is raised.
    console.log('Promise completed');
  });
```

- যে ক্ষেত্রে `randomNumber` হলো `0-3`:
  - `myPromise` মান `2, 4, 6, or 8` দিয়ে রিজলভ হবে
  - `finalPromise` মান `'yay'` দিয়ে রিজলভ হবে
  - দুটি লগ থাকবে:
    - `Sampled data: ...`
    - `Promise completed`
- যে ক্ষেত্রে `randomNumber` হলো `4-5`:
  - `myPromise` কারণ `'Sampling did not result in a sample'` দিয়ে রিজেক্ট হবে
  - `finalPromise` কারণ `Error('Sampling did not result in a sample')` দিয়ে রিজেক্ট হবে
  - একটি লগ থাকবে:
    - `Promise completed`
    - _কিছু এনভায়রনমেন্টে_ এটি একটি `"uncaught rejected promise: Error('Sampling did not result in a sample')"` লগ তৈরি করবে

উপরের উদাহরণে দেখা যাচ্ছে, `reject` একটি স্ট্রিং দিয়েও কাজ করে, এবং একটি প্রমিস `Error` দিয়েও রিজেক্ট হতে পারে।
