# ভূমিকা

## রিসোর্সের লাইফটাইম

[concept:csharp/resource-cleanup]() `IDispose` ইন্টারফেস ব্যবহার করে বোঝায় যে, কোনো অবজেক্টের রিসোর্স বা প্রোগ্রামের অন্য কোনো স্টেট তখন ছেড়ে দিতে বা রিসেট করতে হয়, যখন ওই অবজেক্টটির আর দরকার থাকে না (আর গার্বেজ কলেক্টরের উপর ভরসা করে এটা করা যাবে না, বা প্রয়োজনীয় মাত্রার নিয়ন্ত্রণও পাওয়া যাবে না), এবং এই ধরনের পরিষ্কার করার কাজের স্বাভাবিক জায়গা হলো `IDisposable.Dispose()` মেথড।

আরেকটি কনস্ট্রাক্ট আছে, `using` ব্লক, যার সাহায্যে কলারের দৃষ্টিকোণ থেকে রিসোর্স লাইফটাইমের পুরো ব্যবস্থাপনা একটি স্টেটমেন্টে একত্র করা যায়।

```csharp
using (var file = new File("my_secrets"))
{
    file.WriteSecret("xxxxxxx");
}
```

উপরের উদাহরণে `file`-এর সাথে জড়িত ফাইল সিস্টেম রিসোর্সগুলো `using` ব্লক থেকে বেরিয়ে গেলেই অপারেটিং সিস্টেমে ফিরিয়ে দেওয়া হবে।

এই প্যাটার্নটি কাজ করতে হলে using স্টেটমেন্টের ভ্যারিয়েবলটি অবশ্যই এমন একটি রেফারেন্স টাইপ হতে হবে, যা `IDisposable` ইন্টারফেস ইমপ্লিমেন্ট করে, আর তার `Dispose()` মেথডে রিসোর্স ছেড়ে দিতে হবে বা প্রোগ্রামের স্টেট রিসেট করতে হবে।

C# 8 এই প্যাটার্নে আরেকটি পরিমার্জন নিয়ে আসে। using স্টেটমেন্ট একটি ব্লকের শুরুতে বসানো যেতে পারে।

```csharp
using var drawingResource = some_provided_or_new_object;
try
{
    drawingResource.DrawSomething();
}
catch (Exception)
{
    throw;
}
```

Java ডেভেলপাররা এটাকে Java 7-এ আসা _automatic resource management_ মেকানিজমের সমতুল্য কিছু হিসেবে চিনতে পারবেন।
