# সম্পর্কে

ভোকাবুলারি হলো Factor-এ সংগঠনের একক: ওয়ার্ড ডেফিনিশনের একটি নামযুক্ত সংগ্রহ।

```factor
USING: kernel ;
IN: greetings.formal

: hello ( name -- str ) "Greetings, " prepend ;
```

## ফাইল ও ডিরেক্টরির বিন্যাস

ভোকাবুলারির নামে `.` সেপারেটর হিসেবে ব্যবহৃত হয়। পাথটি ডটগুলো অনুসরণ করে:

| ভোকাবুলারি            | ফাইল                                        |
| ---                    | ---                                        |
| `greetings`            | `greetings/greetings.factor`               |
| `greetings.formal`     | `greetings/formal/formal.factor`           |
| `greetings.casual`     | `greetings/casual/casual.factor`           |

Factor-এর লোডার *ভোকাব রুট* ধরে ঘুরে ভোকাবুলারিগুলো খুঁজে বের করে, অর্থাৎ প্রজেক্ট রুট আর সঙ্গে দেওয়া বেসিস লাইব্রেরি, যতক্ষণ না প্রতিটি পাথ সেগমেন্টের সঙ্গে মেলে এমন একটি ডিরেক্টরি পাওয়া যায়। শেষ সেগমেন্টটিই ফাইলনেম হিসেবে পুনরাবৃত্ত হয়।

## `USING:` ও `IN:`

`USING:` (একবারে একটি ভোকাবের জন্য `USE:`) অন্য ভোকাবুলারিগুলোকে বর্তমান ফাইলের সার্চ পাথে নিয়ে আসে। `IN:` ঘোষণা করে, এই ফাইলে ডিফাইন করা ওয়ার্ডগুলো কোন ভোকাবুলারির *অন্তর্ভুক্ত*; তাদের ফুলি-কোয়ালিফাইড নাম শুরু হয় সেই প্রিফিক্স দিয়ে।

```factor
USING: kernel sequences greetings.formal ;
IN: greetings

: greet-everyone ( names -- strs )
    [ hello ] map ;
```

এখানে `greet-everyone` আছে `greetings` ভোকাবুলারিতে, `greetings.formal` থেকে `hello` কল করে, আর `sequences` থেকে `map` কল করে।

## কেন একটি সমাধানকে বিভিন্ন ভোকাবে ভাগ করবেন

কোডকে নানা ভোকাবুলারিতে ভাগ করলে আপনি:

- ছোট হেল্পার ওয়ার্ডগুলোকে দায়িত্ব অনুযায়ী দলবদ্ধ করতে পারেন, যে উচ্চস্তরের রুটিন সেগুলোকে জোড়া লাগায় তা থেকে আলাদা রেখে।
- মূল রুটিনকে টেনে না এনেই অন্য জায়গা থেকে হেল্পারগুলো আবার ব্যবহার করতে পারেন।
- প্রতিটি ফাইলকে অ্যাবস্ট্রাকশনের একটি সুসংগত স্তর হিসেবে পড়তে পারেন।

Factor-এর লোডার যথেষ্ট দ্রুত আর অলস, তাই আরও ছোট ভোকাবে *ভাগ করে নামানো* সস্তা; স্ট্যান্ডার্ড লাইব্রেরির কনভেনশন হলো নির্দ্বিধায় ফ্যাক্টর করা।
