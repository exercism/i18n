# ভূমিকা

## পরিভাষা

আপনি ইতিমধ্যে কয়েকটি কনসেপ্টে C++ ফাংশন ব্যবহার করেছেন এবং লিখেছেন।
এখন একটু টেকনিক্যাল হওয়ার সময়।
নিচের কোড স্নিপেটে সহজে রেফারেন্স করার জন্য সবচেয়ে কমন পরিভাষাগুলো দেখানো হয়েছে।
যেহেতু C++ হোয়াইটস্পেস উপেক্ষা করে, তাই প্রতিটি এলিমেন্টকে একটি করে আলাদা লাইনে রাখতে ফরম্যাটিং বদলানো হয়েছে।

```cpp
// Function declaration:
bool                                              // Return type
admin_detected(string user, string password)      // Type signature
;                                                 // Don't forget the ';' for the declaration

// Function definition:
bool                                              // Return type
admin_detected                                    // Function name
(string user, string password)                    // Parameter list
{ return user == "admin" && password == "1234"; } // Function body
```
~~~~exercism/advanced
ডিক্লারেশন কম্পাইলারের কাছে একধরনের নোটের মতো কাজ করে, যে এই নাম, রিটার্ন টাইপ ও প্যারামিটার লিস্টের একটি ফাংশন আছে।
ডেফিনিশন না থাকলে কোড কাজ করবে না।
ডিক্লারেশন অপশনাল, ফাংশনটি তার ডেফিনিশনের আগে ব্যবহার করলে এগুলো দরকার হয়।
ডিক্লারেশন সাইক্লিক রেফারেন্সের মতো সমস্যা সমাধান করতে পারে, আর ইন্টারফেসকে ইমপ্লিমেন্টেশন থেকে আলাদা করতেও ব্যবহার করা যায়।
~~~~

## const কোয়ালিফায়ার

কখনও কখনও আপনি নিশ্চিত করতে চান যে কোনো মান ইনিশিয়ালাইজ হওয়ার পর আর বদলানো যাবে না।
C++ কনস্ট্যান্টের কোয়ালিফায়ার হিসেবে `const` কিওয়ার্ডটি ব্যবহার করে।

```cpp
const int number_of_dragon_balls{7};
number_of_dragon_balls--; // compilation error
```

~~~~exercism/note
কনস্ট্যান্ট প্রায়ই _UPPER_SNAKE_CASE_-এ লেখা দেখবেন।
অন্য কোনো কনভেনশন না থাকলে এই কেসিং ম্যাক্রোর জন্য সংরক্ষিত রাখার পরামর্শ দেওয়া হয়।
~~~~

সেট হওয়ার পর কোনো কনস্ট্যান্ট ভ্যারিয়েবল বদলাতে চেষ্টা করলে আপনার কোড কম্পাইল হবে না।
এটি অনিচ্ছাকৃত পরিবর্তন এড়াতে সাহায্য করে, আর একইসাথে কম্পাইলারের জন্য অপটিমাইজেশনের সুযোগও খুলে দেয়।
আর মানুষ হিসেবে কোড নিয়ে চিন্তা করাও সহজ হয়, যদি আপনি জানেন যে নির্দিষ্ট কিছু অংশ প্রভাবিত হবে না।

ফাংশন প্যারামিটারের কোয়ালিফায়ার হিসেবেও `const` ব্যবহার করা যায়।

```cpp
string guess_number(const int& secret, const int& guess) {
    if (secret < guess) return "lower.";
    if (secret > guess) return "higher.";
    return "exact!";
}
```

ফাংশনে `const` রেফারেন্স পাস করলে আপনি নিশ্চিত থাকতে পারেন যে সেটি অপরিবর্তিত থাকবে।
যেসব অবজেক্ট কপি করা খরচসাপেক্ষ হতে পারে, যেমন বড় স্ট্রিং, তাদের জন্য প্রায়ই `const` রেফারেন্স দেখা যায়।
`const` কোয়ালিফায়ারের তৃতীয় ব্যবহার হলো এমন মেম্বার ফাংশন, যেগুলো ক্লাসের ইনস্ট্যান্স বদলায় না।

```cpp
class Stubborn {
    public:
    Stubborn(string reply) {
        response = reply;
    }
    string answer(const string& question) const {
        if (question.length() == 0) { return ""; }
        return response;
    }
    private:
    string response{};
};
```

`Stubborn`-এর মেম্বার ফাংশন `answer` প্যারামিটার হিসেবে একটি `const string&` রেফারেন্স ব্যবহার করে।
এতে ফাংশনে পাস করা মূল অবজেক্ট থেকে কপি করার কাজটি এড়ানো যায়।

## ফাংশন ওভারলোডিং

প্যারামিটার লিস্ট আলাদা হলে একাধিক ফাংশনের একই নাম থাকতে পারে।
এটাকে ফাংশন ওভারলোডিং বলা হয়, এবং সাধারণত তখনই করা হয় যখন এই ফাংশনগুলো প্রায় একই রকম কাজ করে।

রিটার্ন টাইপ ছাড়া ফাংশন হেডারটাই হলো ফাংশনের __টাইপ সিগনেচার__।
টাইপ সিগনেচারে পরিবর্তন হলে নতুন একটি ফাংশন তৈরি হয়।

`play_sound` উদাহরণটিতে ভিন্ন ভিন্ন পরিস্থিতি সামলাতে ছয়টি আলাদা ওভারলোড আছে:

```cpp
// different argument types:
void play_sound(char note);         // C, D, E, ..., B
void play_sound(string solfege);    // do, re, mi, ..., ti
void play_sound(int jianpu);        // 1, 2, 3, ..., 7

// different number of arguments:
void play_sound(string solfege, double duration);

// different qualifiers:
void play_sound(vector<string>& solfege);
void play_sound(const vector<string>& solfege);
```

~~~~exercism/advanced
টাইপ সিগনেচার নির্ধারিত হয় ফাংশনের নাম, প্যারামিটারের সংখ্যা, তাদের টাইপ এবং তাদের কোয়ালিফায়ার দিয়ে (তবে তাদের নাম দিয়ে নয়)।
রিটার্ন টাইপ স্পষ্টভাবেই টাইপ সিগনেচারের অংশ নয়, আর শুধু রিটার্ন টাইপে আলাদা এমন দুটি ফাংশন থাকলে আপনি কম্পাইলেশন এরর পাবেন।
কম্পাইলার অভিযোগ করবে, কারণ দুটির মধ্যে কোনটি ব্যবহার করা উচিত তা স্পষ্ট নয়।
~~~~

## ডিফল্ট আর্গুমেন্ট

কিছু ফাংশন অনেক বড় হয়ে যেতে পারে, আর তার অনেক কলেই হয়তো বেশিরভাগ প্যারামিটারের জন্য একই মান ব্যবহৃত হয়।
ডিফল্ট আর্গুমেন্ট দিয়ে সেই কলগুলোর পুনরাবৃত্তি এড়ানো যায়।

```cpp
void record_new_horse_birth(string name, int weight, string color="brown-ish", string dam="Alruccaba", string sire="Poseidon");

record_new_horse_birth("Urban Sea", 130); // color will be brown, dam "Alruccabam", sire "Poseidon"
record_new_horse_birth("Highclere", 175, "off-white", "Fall Aspen");   // sire will be "Poseidon"
```

ফাংশন ডিক্লারেশন প্রায়ই ডেফিনিশনের আগে পড়া হয়, তাই ডিফল্ট আর্গুমেন্ট সেট করার জন্য এটাই ভালো জায়গা।
কোনো একটি প্যারামিটারের ডিফল্ট ডিক্লারেশন থাকলে তার ডানদিকের সব প্যারামিটারেও ডিফল্ট ডিক্লারেশন থাকতে হবে।
কখনও কখনও জটিল ফাংশন ওভারলোডগুলোকে ডিফল্ট আর্গুমেন্টসহ কম সংখ্যক ফাংশনে রিফ্যাক্টর করা যায়, যা রক্ষণাবেক্ষণযোগ্যতা বাড়ায়।
