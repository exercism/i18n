# পরিচিতি

পাম্প, ভালভ, নল, অপারেটিং সিস্টেমের রিসোর্স (খোলা ফাইল, নেটওয়ার্ক সংযোগ) ধরে রাখে এমন যেকোনো কিছুই, কাজ শেষ হলে *রিলিজ* করতে হয়। Factor-এর [`destructors`][destructors] ভোকাব এগুলোকে এমন একটি ফ্রেমওয়ার্কে মুড়ে দেয় যা ক্লিনআপের নিশ্চয়তা দেয়, এমনকি কোনো এরর আপনার কোডের মাঝপথে বাধা দিলেও।

## ক্লাস ও জেনেরিক

একটি ক্লাস `disposable` এক্সটেন্ড করে এবং `dispose*` জেনেরিক ইমপ্লিমেন্ট করে ফ্রেমওয়ার্কে যুক্ত হয়:

```factor
USING: accessors destructors kernel ;

TUPLE: pump < disposable opened ;

: <pump> ( -- pump )
    pump new-disposable t >>opened ;

M: pump dispose* f >>opened drop ;
```

`new-disposable ( class -- obj )` টাপলটি অ্যালোকেট করে *এবং* ফ্রেমওয়ার্কে রেজিস্টার করে। অ্যালোকেশন আর পরবর্তী নিরাপদ পয়েন্টের মধ্যে কোনো এক্সেপশন ঘটলেও রিসোর্সটি লিক হতে পারে না। ফ্রেমওয়ার্ক নিশ্চিত করে যে প্রতি অবজেক্টে `dispose*` **সর্বোচ্চ একবার** চলে। বারবার `dispose` কল করলে কিছুই হয় না।

## পাবলিক কলাররা `dispose` ব্যবহার করে

```
dispose          ( obj -- )                ! release; safe to call twice
with-disposal    ( disposable quot -- )    ! scope one resource
with-destructors ( quot -- )               ! open a registry scope
&dispose         ( obj -- obj )            ! dispose on normal *or* failure exit
|dispose         ( obj -- obj )            ! dispose only if the scope unwinds
```

`with-disposal` হলো একক-রিসোর্স রূপ: এটি ভেতরের কোটেশনের জন্য ডিসপোজেবলটি পুশ করে এবং বেরোনোর সময় সেটি রিলিজ করে।

```factor
USING: destructors io ;

<pump> [
    "pumping" print
] with-disposal
! pump released on the way out — even if `print` had thrown
```

একাধিক রিসোর্সের জন্য একটি `with-destructors` স্কোপ খুলুন এবং প্রতিটি অ্যাকুইজিশন রেজিস্টার করুন। `&dispose` (অ্যাম্পারস্যান্ড) মানে "বেরোনোর সময় সবসময় ডিসপোজ করুন, সফল হোক বা ব্যর্থ।" `|dispose` (পাইপ) মানে "**শুধু** ব্যর্থ হলেই ডিসপোজ", যা কাজে লাগে যখন সফল পথে রিসোর্সটি এমন একজন কলারকে হস্তান্তর করা হয় যে তার মালিকানা নেবে।

```factor
[
    <pump> &dispose
    <pump> &dispose
    ! ... use the pumps ...
] with-destructors
! both pumps released
```

রেজিস্ট্রি ছাড়া শুধু try/finally-এর জন্য [`cleanup`][cleanup] (`continuations`-এ) হলো নিম্নস্তরের প্রিমিটিভ, তবে আধুনিক Factor-এ রীতিসম্মত উপায় `with-destructors`।
