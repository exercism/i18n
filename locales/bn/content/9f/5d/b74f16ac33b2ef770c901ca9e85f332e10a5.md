# স্ট্রিং বিল্ডার

`STR` ইমিউটেবল, `FSTR` নয়। যে লেখা শেষ হয়ে গেছে তার জন্য `STR` ব্যবহার করুন, আর যে লেখা এখনো জোড়া হচ্ছে তার জন্য `FSTR`.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## ফলাফলটি সবসময় আবার অ্যাসাইন করুন

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR` বাড়ে **অ্যামোর্টাইজড ডাবলিং**-এর মাধ্যমে: জায়গা ফুরিয়ে গেলে এটি নতুন ও বড় একটি অ্যারে নেয়, আকারে দ্বিগুণ, এবং সেখানে কপি করে। তাই ফলাফল সাধারণত একই অবজেক্ট হয়, মাঝে মাঝে ভিন্ন একটি। প্রতিবার `b := b + x` লেখা দুই ক্ষেত্রেই সঠিক, আর শেখার যোগ্য একমাত্র রূপও এটাই।

ডাবলিং-এর জন্যই মোট কাজ দৈর্ঘ্যের বর্গের বদলে দৈর্ঘ্যের সমানুপাতিক হয়: কপিগুলো যত দ্রুত আরও ব্যয়বহুল হয়, ঠিক তত দ্রুত কম ঘন ঘনও হয়।

## কেন `STR`-এর ওপর শুধু `+` ব্যবহার করব না?

নির্দিষ্ট, অল্প কিছু টুকরো `+` দিয়ে জোড়া দিলে তা স্পষ্ট ও ঠিকই থাকে:

```sather
   return piece + " by " + composer;
```

সমস্যা কেবল লুপের ক্ষেত্রে, যেখানে কোড লেখার সময় কতবার জোড়া লাগবে তা জানা থাকে না। একটি মোটামুটি নিয়ম: `+` যদি `loop`-এর ভেতরে থাকে, তাহলে `FSTR` ব্যবহার করুন।

## দরকারি রুটিন

| কল | কী করে |
| --- | --- |
| `b + x` | যোগ করে; `x` হতে পারে `STR`, `CHAR`, `INT`, `BOOL` … |
| `b.size` | এখন পর্যন্ত কতগুলো ক্যারেক্টার |
| `b.str` | সম্পূর্ণ হওয়া একটি `STR` |
| `b.clear` | এটিকে খালি করে, জায়গাটা রেখে দেয় |

## এস্কেপ

| লেখা হয় | অর্থ |
| --- | --- |
| `"\n"` | একটি নতুন লাইন |
| `"\t"` | একটি ট্যাব |
| `"\""` | একটি ডাবল কোট |
| `"\\"` | একটি ব্যাকস্ল্যাশ |
