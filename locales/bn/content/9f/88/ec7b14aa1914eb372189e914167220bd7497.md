# কাস্টম ইটারেটর

`bird-survey` থেকেই আপনি ইটারেটর ব্যবহার করে আসছেন। এখন আপনি নিজেই একটি লিখবেন।

## yield

একটি ইটারেটর দেখতে একটি রুটিনের মতো, তবে এতে দুটি পার্থক্য আছে: এর নাম `!` দিয়ে শেষ হয়, আর এটি `return`-এর বদলে `yield` দিয়ে মান হস্তান্তর করে।

```sather
   markers!(count : INT) : INT is
      loop
         yield 100 * 1.upto!(count);
      end;
   end;
```

`yield` ইটারেটরটিকে যে লুপটি কল করেছিল, সেটিকে একটি মান দেয়, তারপর **অপেক্ষা করে**। সেই লুপটি আবার ঘুরে এলে ইটারেটরটি `yield`-এর ঠিক পর থেকে আবার চলতে থাকে, সবকিছুই ঠিক যেমনটি সে রেখে গিয়েছিল: তার ভ্যারিয়েবল, তার নিজের লুপ, তার অবস্থান।

ইটারেটর আসলে এটাই: এমন একটি রুটিন, যা মাঝপথে থেমে যেতে পারে এবং আবার চালু হতে পারে।

```sather
   loop
      #OUT + TRAIL::markers!(3) + " ";      -- 100 200 300
   end;
```

## সমাপ্তি

একটি ইটারেটর দুটি উপায়ের যেকোনো একটিতে শেষ হয়।

**ফুরিয়ে যাওয়া।** যখন ইটারেটরের নিজের লুপ শেষ হয়, বা রুটিনটি তার শেষে পৌঁছায়, তখন সেটি শেষ হয়ে যায়; আর যে লুপটি এটিকে কল করেছিল, সেটিও সঙ্গে সঙ্গে শেষ হয়।

**quit.** `quit` yield না করেই তখনই এটি শেষ করে দেয়।

```sather
   named!(names : ARRAY{STR}) : STR is
      loop
         name ::= names.elt!;
         if name = "" then quit; end;
         yield name;
      end;
   end;
```

এটি একটি খালি নামের দেখা পাওয়া পর্যন্ত নাম yield করে, তারপর থেমে যায়। রুটিনের কাছে `return` যা, ইটারেটরের কাছে `quit` তা-ই, শুধু এটি কোনো মান বহন করে না; হস্তান্তর করার মতো কিছু আর বাকি থাকে না।

## once

`once` দিয়ে চিহ্নিত একটি আর্গুমেন্ট লুপ শুরু হওয়ার সময় একবারই নির্ণয় করা হয়, প্রতিবার নয়:

```sather
   markers!(once count : INT) : INT is
```

যে জিনিস প্রতিবার পরিবর্তিত হয় না, তার জন্য এটি ব্যবহার করুন; বেশিরভাগ আর্গুমেন্টই এমন। লাইব্রেরির নিজস্ব ইটারেটরগুলোও এটি করে: `upto!(once i : SAME)`।

## মান ছাড়া ইটারেটর

একটি ইটারেটরকে কিছু yield করতে হয় না। `times!` এমনই একটি:

```sather
   steps!(once count : INT) is
      loop
         ignored ::= 1.upto!(count);
         yield;
      end;
   end;
```

খালি `yield` কিছুই হস্তান্তর করে না, কেবল লুপটিকে ঘুরতে দেয়।

## অবস্থান কোথায় থাকে

প্রোগ্রামের *প্রতিটি জায়গা* যা একটি ইটারেটর কল করে, নিজের অবস্থান নিজেই রাখে, তাই একই লুপ বডিতে একই ইটারেটর দুবার কল করলে সেটি দুবার ঘুরে যায়। এখন আপনি বুঝতে পারবেন কেন: দুটি কল আসলে দুটি আলাদা থেমে থাকা রুটিন।
