# পরিচিতি

[`Nothingness`][concept-nothingness] কনসেপ্টে যেমনটি দেখা গেছে, অনুপস্থিত ([`NULL`][ref-null]), অজানা ([`NA`][ref-na]) বা গাণিতিকভাবে অবৈধ ([`NaN`][ref-finite], [`Inf`][ref-finite]) ডেটা উপস্থাপনের জন্য R-এর হাতে নানা উপায় আছে।
সাধারণভাবে, R এই ধরনের মান দিয়ে সমস্যাগুলো জায়গাতেই চিহ্নিত করার চেষ্টা করে এবং কোনো এক্সেপশন না তুলেই চলতে থাকে।

## `stop()`

কিছু সমস্যা এতটাই মৌলিক যে প্রোগ্রামকে আর চলতে দেওয়া যায় না।
এক্ষেত্রে, [`stop(msg)`][ref-stop] ব্যবহার করে একটি `Error` দিয়ে প্রোগ্রামটি সঙ্গে সঙ্গে থামান এবং `msg` প্রিন্ট করুন।

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

অন্য ভাষার [`assert`][wiki-assert]-এর মতোই, [`stopifnot()`][ref-stopifnot] হলো `stop()`-এর জন্য একটি সুবিধাজনক র‍্যাপার।
এর আর্গুমেন্ট হলো কমা দিয়ে আলাদা করা যেকোনো সংখ্যক বুলিয়ান শর্ত, এবং সেগুলোর সবগুলো `TRUE` হলেই কেবল প্রোগ্রামটি চলবে।

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

এরর সামলানোর নানা উপায় R-এর আছে।
এগুলো Common Lisp-ভিত্তিক এবং বহুল জনপ্রিয় অনেক ভাষার থেকে যথেষ্ট আলাদা।

সবচেয়ে সহজ উপায় হলো সম্ভাব্য সমস্যাযুক্ত কোড [`try()`][ref-try]-এর ভেতরে মুড়ে ফেলা।

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning] এবং [`message()`][ref-message]

এগুলো মারণাত্মক নয় এমন অবস্থার প্রতিক্রিয়া, যেমন:

- যে সমস্যা থেকে প্রোগ্রামটি অন্তত আংশিকভাবে সেরে উঠতে পারে, তা নিয়ে সতর্ক করা।
- দীর্ঘ সময় ধরে চলা প্রোগ্রামের অগ্রগতি ব্যবহারকারীকে জানানো।

এদের মধ্যে একটি পার্থক্য হলো, ওয়ার্নিংগুলো ক্যাশে জমা থাকে এবং ডিফল্টভাবে ফাংশনটি রিটার্ন করলে তা আউটপুটে আসে, অথচ মেসেজগুলো সঙ্গে সঙ্গে আউটপুটে আসে।
ডিফল্ট আচরণ বদলানোর অনেক উপায় আছে, যা এখানে আমাদের আলোচনার পরিধির বাইরে।

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

[`suppressWarnings()`][ref-warning] ফাংশনটি মাঝেমধ্যে Exercism-এর ভেতরে কাজে লাগতে পারে, যাতে অবাঞ্ছিত আউটপুট দিয়ে test runner-কে বিভ্রান্ত করা না হয়।

## শর্ত হ্যান্ডলার

এরর পরিস্থিতি সামলানোর আরেকটি উপায় R-এর আছে, যা ভাবধারায় Java ও সংশ্লিষ্ট ভাষাগুলোর পদ্ধতির আরও কাছাকাছি।

এই কনসেপ্টে বিস্তারিত আলোচনা আমাদের পরিধির বাইরে, তবে আগ্রহী যে কেউ [`tryCatch`][ref-conditions] এবং [`withCallingHandlers`][ref-conditions] দেখে নিতে পারেন।

Advanced R-এর [৮.৪ নম্বর বিভাগে][book-handling] ভালো একটি আলোচনা আছে।
