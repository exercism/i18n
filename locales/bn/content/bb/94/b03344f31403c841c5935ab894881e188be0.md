# সম্পর্কে


এখন সময় এসেছে C++-এর অন্যতম মূল প্যারাডাইম অবজেক্ট-ওরিয়েন্টেড প্রোগ্রামিং (OOP) নিয়ে আলোচনার। OOP-এর কেন্দ্রে আছে `classes`, অর্থাৎ ব্যবহারকারীর নিজের তৈরি ডেটা টাইপ, যাদের নিজস্ব সম্পর্কিত ফাংশনের একটি সেট থাকে। আমরা মৌলিক বিষয়গুলো দিয়ে শুরু করব এবং সিলেবাসের গাছের আরও নিচে গিয়ে আরও অগ্রসর বিষয়গুলো নিয়ে আলোচনা করব।

## মেম্বার

ক্লাসে **মেম্বার ভ্যারিয়েবল** এবং **মেম্বার ফাংশন** থাকতে পারে।
এগুলোতে অ্যাক্সেস করা হয় **মেম্বার সিলেকশন** অপারেটর `.` দিয়ে।
`classes`-এর বাইরের ভ্যারিয়েবলের মতোই, ডিক্লারেশনের সময় মেম্বার ভ্যারিয়েবল একটি মান দিয়ে ইনিশিয়ালাইজ করা বাঞ্ছনীয়।
এই মানটি তখন এই ক্লাস থেকে নতুন তৈরি অবজেক্টের জন্য ডিফল্ট হয়ে যাবে।

## এনক্যাপসুলেশন ও ইনফরমেশন হাইডিং

ক্লাস তাদের মেম্বারে অ্যাক্সেস সীমাবদ্ধ করার সুযোগ দেয়।
দুটি মৌলিক ক্ষেত্র হলো `private` এবং `public`।
`private` মেম্বার ক্লাসের বাইরে থেকে অ্যাক্সেসযোগ্য নয়।
`public` মেম্বার অবাধে কল করা যায়।
ডিফল্টভাবে সব মেম্বারই `private`, আর ক্লাসের বাইরে ব্যবহারযোগ্য হতে হলে সেগুলোকে স্পষ্টভাবে চিহ্নিত করতে হয়।

## একটি মৌলিক উদাহরণ

নিচের উদাহরণে একটি নতুন `class` ডিফাইন করা দেখা যায়।
ডিফাইনের পরে `;`-টি লক্ষ্য করুন।

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

আপনি ক্লাসের ভেতর থেকে সব ভ্যারিয়েবল অ্যাক্সেস করতে পারেন।
`cast_spell` ফাংশনের ভেতরের `damage`-টি একবার দেখুন।
ক্লাসের বাইরে থেকে `private` মেম্বার পড়া বা পরিবর্তন করা যায় না:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## কনস্ট্রাক্টর

অবজেক্ট তৈরির সময় কনস্ট্রাক্টর মেম্বার ভ্যারিয়েবলে মান অ্যাসাইন করার সুযোগ দেয়।
তাদের নাম `class`-এর মতোই হয় এবং কোনো রিটার্ন টাইপ থাকে না।
একটি ক্লাসে একাধিক কনস্ট্রাক্টর থাকতে পারে।
সব ভ্যারিয়েবল সবসময় সেট করার দরকার না হলে এটি কাজে আসে।

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

কনস্ট্রাক্টর একটি বড় বিষয় এবং এর অনেক সূক্ষ্ম দিক আছে।
আপনার `class`-এর জন্য যদি আপনি স্পষ্টভাবে একটি `constructor` ডিফাইন না করেন, তাহলে, কেবল তখনই, কম্পাইলার আপনার হয়ে কাজটি করে দেবে।
উপরের প্রথম উদাহরণে এটিই ঘটেছে।
_سilverhand_ অবজেক্টটি ডিফল্ট কনস্ট্রাক্টর কল করে তৈরি হয়, কোনো আর্গুমেন্ট পাস করা হয়নি।
সব ভ্যারিয়েবল ক্লাসের ডিফিনেশনে যেই মান বলা ছিল সেটিতেই সেট হয়ে যায়।
ওই ডিফিনেশনে যদি আপনি কোনো মান না দিতেন, তাহলে ভ্যারিয়েবলগুলো আনইনিশিয়ালাইজড থেকে যেতে পারত, যার অনাকাঙ্ক্ষিত পরিণতি হতে পারত।

## স্ট্রাক্ট

স্ট্রাক্ট এসেছে ভাষার মূল C শিকড় থেকে এবং C++-এর মতোই পুরনো।
একটি গুরুত্বপূর্ণ ব্যতিক্রম ছাড়া এগুলো কার্যত `classes`-এর মতোই একই জিনিস।
ডিফল্টভাবে একটি `class`-এর সবকিছুই `private`।
অন্যদিকে স্ট্রাক্ট অন্যভাবে ডিফাইন না করা পর্যন্ত `public` থাকে।
প্রচলিতভাবে `struct` কিওয়ার্ডটি প্রায়ই **শুধু ডেটার স্ট্রাকচার**-এর জন্য ব্যবহৃত হয়।
নির্দিষ্ট কিছু বৈশিষ্ট্য নিশ্চিত করতে হয় এমন অবজেক্টের জন্য `class` কিওয়ার্ডটি বেশি পছন্দ করা হয়।
এমন একটি ইনভ্যারিয়েন্ট হতে পারে যে আপনার `Wizzard` `class`-এর `damage` ঋণাত্মক হতে পারবে না।
`damage` ভ্যারিয়েবলটি প্রাইভেট, আর যে-কোনো ফাংশন damage পরিবর্তন করে সেটি ইনভ্যারিয়েন্ট অক্ষুণ্ন রাখা নিশ্চিত করবে।
