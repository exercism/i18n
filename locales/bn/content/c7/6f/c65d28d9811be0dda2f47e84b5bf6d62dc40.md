# ভূমিকা

[concept:csharp/resource-cleanup]()-এ `IDispose` ইন্টারফেস ব্যবহার করে বোঝানো হয় যে, কোনো অবজেক্টের রিসোর্স বা প্রোগ্রামের অন্য কোনো অবস্থা অবজেক্টটির আর প্রয়োজন না থাকলে ছেড়ে দিতে বা রিসেট করতে হয় (এবং গার্বেজ কলেক্টরের ওপর ভরসা করলে সেটি হবে না, কিংবা প্রয়োজনীয় মাত্রার নিয়ন্ত্রণও মিলবে না), আর এ ধরনের পরিষ্কারের কাজের স্বাভাবিক জায়গা ছিল `IDisposable.Dispose()` মেথড।

আরেকটি কনস্ট্রাক্টও আছে, `using` ব্লক, যার ফলে কল করা পক্ষের দৃষ্টিতে রিসোর্সের লাইফটাইম ব্যবস্থাপনার পুরোটাই একটি স্টেটমেন্টে এসে জড়ো হয়।

```csharp
using (var file = new File("my_secrets"))
{
    file.WriteSecret("xxxxxxx");
}
```

উপরের উদাহরণে `file`-এর সঙ্গে যুক্ত ফাইল সিস্টেমের রিসোর্সগুলো `using` ব্লক থেকে বেরিয়ে গেলে অপারেটিং সিস্টেমকে ফিরিয়ে দেওয়া হবে।

প্যাটার্নটি কাজ করতে হলে using স্টেটমেন্টের ভ্যারিয়েবলটিকে অবশ্যই এমন একটি রেফারেন্স টাইপ হতে হবে যা `IDisposable` ইন্টারফেস ইমপ্লিমেন্ট করে, আর তার `Dispose()` মেথডে রিসোর্স ছেড়ে দিতে বা প্রোগ্রামের অবস্থা রিসেট করতে হবে।

C# 8 এই প্যাটার্নে একটি উন্নতি এনেছে। using স্টেটমেন্ট ব্লকের শুরুতে বসানো যায়।

```csharp
using var drawingResource = some_provided_or_new_object;
try
{
    drawingResource.DrawSomething();
}
catch (Exception)
{
    throw;
}
```

জাভা ডেভেলপাররা এটিকে Java 7-এ চালু হওয়া _অটোমেটিক রিসোর্স ম্যানেজমেন্ট_ ব্যবস্থার সমতুল্য বলে চিনতে পারবেন।
