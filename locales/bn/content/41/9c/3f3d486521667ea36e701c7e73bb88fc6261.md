# পরিচিতি

`Complex numbers` জটিল নয়।
এদের শুধু একটি কম ভয়ংকর নাম দরকার।


এগুলো এতটাই কাজের, বিশেষ করে ইঞ্জিনিয়ারিং ও বিজ্ঞানের ক্ষেত্রে, যে Python ইন্টিজার ([`int`s][ints]) ও ফ্লোট ([`float`s][floats]) সংখ্যার পাশাপাশি [`complex`][complex] নামের একটি স্ট্যান্ডার্ড সংখ্যাসূচক টাইপও যোগ করেছে।


Python-এ একটি `complex` মান আসলে দুটি ফ্লোট সংখ্যার এক জোড়া:

```python
>>> my_complex = 5.443+6.77j
(5.443+6.77j)
```

এদের "বাস্তব" ও "কাল্পনিক" অংশ বলা হয়।
আপনি হয়তো শুনেছেন যে "`i` (অথবা `j`) হলো -১-এর বর্গমূল"।
আপাতত এর অর্থ এইটুকুই, কাল্পনিক অংশটি _সংজ্ঞা অনুযায়ী_ `1j * 1j == -1` সমতাটি মেনে চলে।
এটি সহজ একটি ধারণা, তবে এর থেকে মজার গাণিতিক পরিণতি আসে।

Python-এ "কাল্পনিক" অংশটি `j` দিয়ে চিহ্নিত করা হয় (_গণিতের পাঠ্যবইয়ে যেমন `i` দেখতে পান, তা নয়_), আর Python যাতে এটিকে একটি ভ্যারিয়েবলের নাম হিসেবে না দেখে, সেজন্য `j` অবশ্যই একটি সংখ্যার ঠিক পরে বসতে হয়:


```python
>>> j
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
NameError: name 'j' is not defined

>>> 1j
1j

>>> type(1j)
<class 'complex'>
```


কমপ্লেক্স সংখ্যা তৈরি করার দুটি কমন উপায় আছে।

১) [`complex(real, imag)`][complex] কনস্ট্রাক্টরটি দুটি `float` প্যারামিটার নেয়:

    ```python
    >>> z1 = complex(1.5, 2.0)
    >>> z1
    (1.5+2j)
    ```

    কনস্ট্রাক্টরটি স্ট্রিং ইনপুটও পার্স করতে পারে।
    এর একটি অদ্ভুত সীমাবদ্ধতা আছে, স্ট্রিংয়ে স্পেস থাকলে এটি ব্যর্থ হয়।

    ```python
    >>> complex('4+2j')
    (4+2j)
    
    >>> complex('4 + 2j')
    Traceback (most recent call last):
      File "<stdin>", line 1, in <module>
    ValueError: complex() arg is a malformed string
    ```


২) কমপ্লেক্স সংখ্যাটি `<real part> + <complex part>j` লিটারেল আকারে লেখা যায়, অথবা বাস্তব অংশ শূন্য হলে শুধু `<complex part>j`:


    ```python
    >>> z2 = 2.0 + 1.5j
    >>> z2
    (2+1.5j)
    ```
    শেষ ফলাফল `complex()` কনস্ট্রাক্টর ব্যবহার করার মতোই অভিন্ন।


## পাটিগণিত

ফ্লোট ও ইন্টিজারের সঙ্গে ব্যবহৃত বেশিরভাগ [`operators`][operators] কমপ্লেক্স সংখ্যার ক্ষেত্রেও কাজ করে।

কমপ্লেক্স সংখ্যার উপর ইন্টিজার ডিভিশন করা _**যায় না**_, তাই `//` ও `%` অপারেটর এবং `divmod()` ফাংশন কমপ্লেক্স সংখ্যার টাইপের জন্য ব্যর্থ হবে।

কমপ্লেক্স সংখ্যার গুণ ও ভাগের নিয়ম ব্যাখ্যা করা এই কনসেপ্টের আওতার বাইরে (_আর এসব কাজ আপনাকে খুব একটা "নিজ হাতে" করতে হবে, এমন সম্ভাবনা কম_)।

বিষয়টি নিয়ে আরও গভীরে যেতে চাইলে কমপ্লেক্স সংখ্যার যেকোনো [গাণিতিক][math-complex] বা [ইলেকট্রিক্যাল ইঞ্জিনিয়ারিং][engineering-complex] ভূমিকা এই পরিস্থিতিগুলো নিয়ে আলোচনা করবে।

Python-এর স্ট্যান্ডার্ড লাইব্রেরিতে [`math`][math-module] মডিউলটি বাস্তব সংখ্যা নিয়ে কাজ করার দরকারি সব সুবিধায় ভরা, আর [`cmath`][cmath] মডিউলটি কমপ্লেক্স সংখ্যা নিয়ে কাজ করার জন্য তার সমতুল্য।
