# স্ট্রাক্ট

স্ট্রাক্ট নির্দিষ্ট এবং ভিন্ন ভিন্ন ধরনের ডেটাকে একটি একক ইউনিটে একত্র করে। Rust-এ স্ট্রাক্টের নিচের বৈশিষ্ট্যগুলো থাকে:

- প্রতিটি স্ট্রাক্ট টাইপের একটি নির্দিষ্ট নাম থাকে।
- স্ট্রাক্টের প্রতিটি সদস্যকে **ফিল্ড** বলা হয়।
- স্ট্রাক্টের প্রতিটি ফিল্ডের একটি নির্দিষ্ট নাম থাকে।
- ভিজিবিলিটি নির্ধারিত হয় ফিল্ডের স্তরে: প্রতিটি ফিল্ড স্বতন্ত্রভাবে পাবলিক, প্রাইভেট বা অন্য কিছু[^1] হতে পারে।

# স্ট্রাক্টের সংক্ষিপ্ত বিবরণ

স্ট্রাক্ট ডিফাইন করা হয় `struct` কিওয়ার্ড দিয়ে, তারপর লেখা হয় যে টাইপকে স্ট্রাক্টটি বর্ণনা করে তার নাম।
এরপর নামের পরে থাকতে পারে দ্বিতীয় বন্ধনী (সাধারণ স্ট্রাক্টের জন্য), প্রথম বন্ধনী (টুপল স্ট্রাক্টের জন্য), অথবা একটি সেমিকোলন (ইউনিট স্ট্রাক্টের জন্য)।

```rust
struct Item {}
```

এরপর আরও টাইপ স্ট্রাক্টের বডিতে স্ট্রাক্টের _ফিল্ড_ হিসেবে যুক্ত হয়, প্রতিটির নিজস্ব টাইপ থাকে:

```rust
struct Item {
    name: String,
    weight: f32,
    worth: u32,
}
```

সবশেষে, স্ট্রাক্টের উপর মেথড ডিফাইন করা যায় একটি `impl` ব্লকের ভিতরে:

```rust
impl Item {
    // initializes and returns a new instance of our Item struct
    fn new() -> Self {
        todo!()
    }
}
```

# স্ট্রাক্টের ধরন

স্ট্রাক্ট তিন ধরনের হয়: নামযুক্ত ফিল্ডের স্ট্রাক্ট (সাধারণ স্ট্রাক্ট), টুপল স্ট্রাক্ট, এবং ইউনিট স্ট্রাক্ট।

স্ট্রাক্ট অনেকটা **টুপল**-এর মতো। আসলে স্ট্রাক্ট আর টুপলের মধ্যে একমাত্র পার্থক্যটা হলো কোনটা নামহীন তা নিয়ে। সাধারণ রূপটা এরকম:

- স্ট্রাক্টের নাম থাকে এবং তার ফিল্ডগুলোরও নাম থাকে:

  ```rust
  struct Foo {
      bar: Bar,
      bat: Bat,
  }
  ```

  ফিল্ড অ্যাক্সেস করা হয় নাম দিয়ে:

  ```rust
  let bar = foo.bar;
  ```

- টুপল স্ট্রাক্টের নাম থাকে, কিন্তু তার ফিল্ডগুলো নামহীন:

  ```rust
  Foo(Bar, Bat)
  ```

  ফিল্ড অ্যাক্সেস করা হয় আনপ্যাকিং করে অথবা সংখ্যাসূচক ইনডেক্স দিয়ে:

  ```rust
  // unpacking
  let (bar, bat) = foo;
  ```

  ```rust
  // numeric index
  let bar = foo.0;
  let bat = foo.1;
  ```

- টুপল নামহীন এবং তার ফিল্ডগুলোও নামহীন:

  ```rust
  (Bar, Bat)
  ```

  টুপল স্ট্রাক্টের মতোই, ফিল্ড অ্যাক্সেস করা হয় আনপ্যাকিং করে অথবা সংখ্যাসূচক ইনডেক্স দিয়ে।

- অ্যানোনিমাস স্ট্রাক্ট নাম থেকেই বোঝা যায় নামহীন, তবে তার ফিল্ডগুলোর নাম থাকে। Go বা Java-র মতো অন্য ভাষা থেকে এগুলো আপনার পরিচিত লাগতে পারে। Rust-এ এগুলো নেই; এর বদলে টুপল ব্যবহার করাই রীতিসম্মত বলে ধরা হয়।

# জিরো-সাইজড টাইপ

স্ট্রাক্টে যত খুশি বা যত কম প্রয়োজন ততগুলো ফিল্ড থাকতে পারে। তার মানে হলো, একটি স্ট্রাক্টের শূন্যটি ফিল্ড থাকাও বৈধ। শূন্য ফিল্ডের স্ট্রাক্টকে বলা হয় **জিরো-সাইজড টাইপ**, এবং কম্পাইলার এদের নিয়ে কিছু বিশেষ ব্যবস্থা নেয়: জিরো-সাইজড টাইপ (প্রায়ই সংক্ষেপে **ZSTs**) কখনো স্ট্যাক বা হিপ জায়গা নেয় না, এমনকি যখন আপনি ভাববেন নেওয়া উচিত তখনও। উদাহরণস্বরূপ, `T` যদি একটি ZST হয়, তাহলে `Box<T>` কোনো হিপ মেমরি অ্যালোকেট করে না।

ZST লেখার সময় আপনি সাধারণ বা টুপল স্ট্রাক্টের সিনট্যাক্স ব্যবহার করতে পারেন:

```rust
// declaration
struct Foo {}
// instantiation
let foo = Foo {}
```

```rust
// declaration
struct Foo();
// instantiation
let foo = Foo();
```

ZST-এর জন্য একটি সংক্ষিপ্ত রূপও আছে:

```rust
// declaration
struct Foo;
// instantiation
let foo = Foo;
```

সাধারণত ZST লেখার সময় সংক্ষিপ্ত রূপটাই পছন্দ করা হয়, কারণ এখানে মিশিয়ে ব্যবহার করা যায় না: যে স্টাইল দিয়ে একটি ZST[^2] ডিক্লেয়ার করা হয়, ঠিক সেই স্টাইল দিয়েই সেটি ইনস্ট্যানশিয়েট করতে হয়।

ZST-এর সিনট্যাক্স নিয়ে এত আলোচনার পর, চলুন দেখা যাক কেন এমন কিছু কখনো দরকার হতে পারে। একটি ZST কোনো ডেটা সংরক্ষণ করতে পারে না, কিন্তু ট্রেইট ইমপ্লিমেন্ট করার জন্য এটি দারুণ।

[^1]: [এই ডকুমেন্টে](https://doc.rust-lang.org/reference/visibility-and-privacy.html) কম ব্যবহৃত কিছু ভিজিবিলিটি অপশন ব্যাখ্যা করা হয়েছে।
[^2]: এটি একটি সাধারণ নিয়মেরই একটি বিশেষ উদাহরণ: যে স্টাইল দিয়ে যেকোনো স্ট্রাক্ট টাইপ ডিক্লেয়ার করা হয়, সেটি ইনস্ট্যানশিয়েট করতেও ঠিক সেই স্টাইলই লাগে।
