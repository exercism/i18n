# পরিচিতি

`Complex numbers` আসলে জটিল নয়।
এদের শুধু একটু কম ভয়ংকর একটা নাম দরকার।

এরা এতটাই কাজের, বিশেষ করে ইঞ্জিনিয়ারিং ও বিজ্ঞানে, যে Julia জটিল সংখ্যাকে ইন্টিজার ও ফ্লোটিং-পয়েন্ট সংখ্যার পাশাপাশি স্ট্যান্ডার্ড নিউমেরিক টাইপ হিসেবে রাখে।

## মূল বিষয়

Julia-তে একটি `complex` মান আসলে এক জোড়া সংখ্যা: সাধারণত ফ্লোটিং-পয়েন্ট, তবে সবসময় নয়।
দুর্ভাগ্যজনক কিছু ঐতিহাসিক কারণে এদের বলা হয় "বাস্তব" ও "কাল্পনিক" অংশ।
আবারও বলি, অদ্ভুত নামগুলো নয়, বরং ভেতরের সরলতাটুকু নিয়েই ভাবাই ভালো।

দুটি বাস্তব সংখ্যা থেকে জটিল সংখ্যা বানাতে, কাল্পনিক অংশের শেষে শুধু `im` প্রত্যয়টি যোগ করুন।

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im

julia> typeof(z)
ComplexF64 (alias for Complex{Float64})

julia> zi = 1 + 2im
1 + 2im

julia> typeof(zi)
Complex{Int64}
```

এভাবে সংশ্লিষ্ট ইন্টিজার বা ফ্লোটিং-পয়েন্ট টাইপ থেকে উদ্ভূত নানা রকম `Complex` টাইপ আছে।

বাস্তব ভ্যারিয়েবল থেকে জটিল সংখ্যা বানাতে চাইলে উপরের সিনট্যাক্সটি কাজ করবে না।
`a + bim` লিখলে পার্সার বিভ্রান্ত হয়ে ভাবে `bim` বুঝি একটি (অস্তিত্বহীন) ভ্যারিয়েবলের নাম।

`b*im` লেখা যায়, তবে সবচেয়ে পছন্দের উপায় হলো `complex()` ফাংশনটি, যা গুণ ও যোগের অপারেশন এড়িয়ে যায়।

```julia-repl
julia> a = 1.2; b = 3.4; complex(a, b)
1.2 + 3.4im
```

একটি জটিল সংখ্যার অংশগুলো আলাদা করে পেতে:

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im

julia> real(z)
1.2

julia> imag(z)
3.4
```

অথবা একসাথে:

```julia-repl
julia> reim(z)
(1.2, 3.4)
```

যেকোনো একটি অংশ শূন্য হতে পারে, আর তখন গণিতবিদেরা সংখ্যাটিকে "সম্পূর্ণ বাস্তব" বা "সম্পূর্ণ কাল্পনিক" বলতে পারেন।
তবে Julia-তে এটি তখনও একটি জটিল সংখ্যা।

```julia-repl
julia> zr = 1.2 + 0im
1.2 + 0.0im

julia> typeof(zr)
ComplexF64 (alias for Complex{Float64})

julia> zi = 3.4im
0.0 + 3.4im

julia> typeof(zi)
ComplexF64 (alias for Complex{Float64})
```

আপনি হয়তো শুনেছেন যে "`i` (বা `j`) হলো -1-এর বর্গমূল"।

আপাতত এর মানে শুধু এইটুকু যে, কাল্পনিক অংশটি _সংজ্ঞা অনুযায়ী_ নিচের সমতাটি মেনে চলে:

```julia-repl
julia> 1im * 1im == -1
true
```

এটি একটি সরল ধারণা, তবে এর থেকে মজার সব ফলাফল বেরিয়ে আসে।

## অ্যারিথমেটিক

ফ্লোট ও ইন্টিজারের সাথে ব্যবহৃত সব স্ট্যান্ডার্ড গাণিতিক `operators` এবং প্রাথমিক ফাংশন জটিল সংখ্যার সাথেও কাজ করে। একটি ছোট নমুনা:

```julia-repl
julia> z1 = 1.5 + 2im
1.5 + 2.0im

julia> z2 = 2 + 1.5im
2.0 + 1.5im

julia> z1 + z2  # addition
3.5 + 3.5im

julia> z1 * z2  # multiplication
0.0 + 6.25im

julia> z1 / z2  # division
0.96 + 0.28im

julia> z1^2  # exponentiation
-1.75 + 6.0im

julia> 2^z1  # another exponentiation
0.5188946835878313 + 2.7804223253571183im
```

## ফাংশন

`real()` ও `imag()` ছাড়াও আরও বেশ কয়েকটি ফাংশন আছে, যেগুলো জটিল সংখ্যার জন্য বিশেষভাবে কাজের।

- `conj()` শুধু একটি জটিল সংখ্যার কাল্পনিক অংশের চিহ্ন উল্টে দেয় (_+ থেকে - বা উল্টোটায়_)।
    - জটিল গুণ যেভাবে কাজ করে, তাতে এটি আপনি যতটা ভাবতে পারেন তার চেয়েও বেশি কাজের।
- `abs(<complex number>)` নিশ্চিতভাবে একটি বাস্তব সংখ্যা রিটার্ন করে, যার কোনো কাল্পনিক অংশ থাকে না।
- `abs2(<complex number>)` রিটার্ন করে `abs(<complex number>)`-এর বর্গ: `abs()`-এর চেয়ে দ্রুত হিসাব করা যায়, আর প্রায়ই কোনো হিসাবের ঠিক এটাই দরকার হয়।
- `angle(<complex number>)` রেডিয়ানে ফেজ কোণ রিটার্ন করে।

```julia-repl
julia> z1
1.5 + 2.0im

julia> conj(z1)
1.5 - 2.0im

julia> abs(z1)
2.5

julia> abs2(z1)
6.25

julia> angle(z1)
0.9272952180016122
```
গণিতে আগ্রহীদের জন্য একটি আংশিক ব্যাখ্যা:

- `z1`-এর `(real, imag)` রূপটি আসলে জটিল সমতলে কার্টেসিয়ান কোঅর্ডিনেট ব্যবহার করে।
- একই জটিল সংখ্যাকে পোলার কোঅর্ডিনেট ব্যবহার করে `(r, θ)` নোটেশনে প্রকাশ করা যায়।
- এখানে `r` ও `θ` যথাক্রমে `abs(z1)` ও `angle(z1)` দিয়ে পাওয়া যায়।

কিছু কনস্ট্যান্ট ব্যবহার করে একটি উদাহরণ:

```julia-repl
julia> euler = exp(1im * π)
-1.0 + 1.2246467991473532e-16im

julia> real(euler)
-1.0

julia> round(imag(euler), digits=15)  # round to 15 decimal places
0.0
```

পোলার `(r, θ)` নোটেশন এতটাই কাজের যে এটি আরও দক্ষভাবে গড়ে তুলতে সাহায্য করার জন্য বিল্ট-ইন ফাংশন রয়েছে: `cis` (`cos(x) + isin(x)`-এর সংক্ষিপ্ত রূপ) এবং `cispi` (`cos(πx) + isin(πx)`-এর সংক্ষিপ্ত রূপ)।

পোলার নোটেশনের উপকারিতা ধরা পড়ে অয়লারের চমৎকার সূত্রে, `ℯ^(iθ) = cos(θ) + isin(θ) = x + iy`, যেখানে `|x + iy| = 1`।
`|x + iy| = r` হলে আমরা আরও সাধারণ পোলার রূপটি পাই: `r * ℯ^(iθ) = r * (cos(θ) + isin(θ)) = x + iy`।
লক্ষ্য করুন, বিশেষ করে সূচকীয় রূপটি সংক্ষিপ্ত এবং সহজে নাড়াচাড়া করার মতো।

```julia-repl
julia> exp(1im * π) ≈ cis(π) ≈ cispi(1)
true
```

উপরের আসন্ন সমতাটি এজন্যই, কারণ `cis` ও `cispi` ফাংশন দুটি আরও সুন্দর সাংখ্যিক আউটপুট দিতে পারে, বিশেষ করে `cispi` যখন এমন আর্গুমেন্ট নিয়ে কাজ করে যেগুলো π-এর ইচ্ছামতো গুণনীয়ক (যেমন রেডিয়ান!)।

```julia-repl
julia> cis(π)
-1.0 + 0.0im

julia> cispi(1)
-1.0 + 0.0im

julia> θ = π/2;
julia> exp(im*θ)
6.123233995736766e-17 + 1.0im

julia> cis(θ)
6.123233995736766e-17 + 1.0im

julia> cispi(θ / π)  # θ/π == 1/2
0.0 + 1.0im
```

প্রসঙ্গত, এ কারণেই জটিল সংখ্যা 2D-তে রোটেশন আর রেডিয়াল ডিসপ্লেসমেন্ট করার জন্য খুবই কাজের।

রোটেশনের জন্য, `z = x + iy` জটিল সংখ্যাটিকে একটি সরল গুণ দিয়ে মূলবিন্দুকে কেন্দ্র করে `θ` কোণে ঘোরানো যায়: `z * ℯ^(iθ)`।
লক্ষ্য করুন, এখানে `x` ও `y` আসলে বাস্তব 2D কার্টেসিয়ান সমতলের চেনা কোঅর্ডিনেট, আর একটি ধনাত্মক কোণে ঘোরে ঘড়ির কাঁটার *উল্টো দিকে*, আর ঋণাত্মক কোণে ঘোরে ঘড়ির কাঁটার *দিকে*।

ঠিক তেমনি সহজে, পোলার রূপে থাকা একটি জটিল সংখ্যার ম্যাগনিচিউড `r`-এর সাথে যোগ করে একটি রেডিয়াল ডিসপ্লেসমেন্ট `Δr` তৈরি করা যায় (যেমন `z = r * ℯ^(iθ)` -> `z' = (r + Δr) * ℯ^(iθ)`)।
লক্ষ্য করুন, কোণের অংশটি যেমন ছিল তেমনই থাকে আর শুধু ম্যাগনিচিউড `r`-ই বদলায়, যেমনটা প্রত্যাশিত।
