# পরিচিতি

## ক্লাস

এখন সময় এসেছে C++-এর অন্যতম মূল প্যারাডাইম অবজেক্ট-ওরিয়েন্টেড প্রোগ্রামিং (OOP) শেখার। OOP-এর কেন্দ্রে থাকে `classes`, অর্থাৎ ব্যবহারকারীর তৈরি ডেটা টাইপ, যাদের নিজস্ব সম্পর্কিত ফাংশনের একটি সেট থাকে। আমরা শুরু করব একেবারে বেসিক দিয়ে, আর সিলেবাস ট্রি-তে আরও নিচে গিয়ে আরও অ্যাডভান্সড বিষয়গুলো নিয়ে আলোচনা করব।

### মেম্বার

ক্লাসে **মেম্বার ভ্যারিয়েবল** আর **মেম্বার ফাংশন** থাকতে পারে। এগুলো অ্যাক্সেস করা হয় **মেম্বার সিলেকশন** অপারেটর `.` দিয়ে। `classes`-এর বাইরের ভ্যারিয়েবলের মতোই, ডিক্লারেশনের সময়ই মেম্বার ভ্যারিয়েবলকে একটি মান দিয়ে ইনিশিয়ালাইজ করে দেওয়া বাঞ্ছনীয়। এরপর এই মানটিই এই ক্লাসের নতুন তৈরি হওয়া অবজেক্টগুলোর জন্য ডিফল্ট হয়ে যাবে।

### এনক্যাপসুলেশন ও ইনফরমেশন হাইডিং

ক্লাস তাদের মেম্বারগুলোর অ্যাক্সেস সীমিত করার সুযোগ দেয়। মূল `access specifiers` দুটি হলো `private` আর `public`। `private` মেম্বারগুলো ক্লাসের বাইরে থেকে অ্যাক্সেস করা যায় না। `public` মেম্বারগুলো অবাধে অ্যাক্সেস করা যায়। একটি `class`-এর সব মেম্বার ডিফল্টভাবে `private` থাকে। শুধু স্পষ্টভাবে `public` দিয়ে চিহ্নিত মেম্বারগুলোই ক্লাসের বাইরে থেকে অবাধে ব্যবহার করা যায়।

### একটি সাধারণ উদাহরণ

নিচের উদাহরণে একটি `class`-এর ডেফিনিশন দেখা যায়। ডেফিনিশনের পরে `;`-টি খেয়াল করুন:

```cpp
class Wizard {
  public:               // from here on all members are publicly accessible
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

আপনি ক্লাসের ভেতর থেকে সব মেম্বার ভ্যারিয়েবল অ্যাক্সেস করতে পারেন। `cast_spell` ফাংশনের ভেতরের `damage`-টি দেখুন। ক্লাসের বাইরে থেকে `private` মেম্বার আপনি পড়তে বা বদলাতে পারবেন না:

```cpp
Wizard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

### কনস্ট্রাক্টর

কনস্ট্রাক্টর অবজেক্ট তৈরির সময়ই মেম্বার ভ্যারিয়েবলে মান অ্যাসাইন করার সুযোগ দেয়। এদের নাম `class`-এর নামের মতোই হয়, আর এদের কোনো রিটার্ন টাইপ থাকে না। একটি ক্লাসে একাধিক কনস্ট্রাক্টর থাকতে পারে। সব ভ্যারিয়েবল সব সময় সেট করার দরকার না পড়লে এটি কাজে লাগে। কখনো হয়তো বাকি সবকিছু ডিফল্টে রেখেই শুধু `name` ভ্যারিয়েবলটি বদলাতে চাইবেন। আর একজন গুরুত্বপূর্ণ Wizard-এর ক্ষেত্রে damage-ও বদলাতে চাইবেন, তাই আপনার দুটি `constructors` দরকার।

```cpp
class Wizard {
  public:
    Wizard(std::string new_name) {
      name = new_name;
    }
    Wizard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizard el{"Eleven"};       // deals  5 damage
Wizard vecna{"Vecna", 50}; // deals 50 damage
```

কনস্ট্রাক্টর একটি বড় বিষয়, এর অনেক সূক্ষ্মতা আছে। আপনি যদি আপনার `class`-এর জন্য স্পষ্টভাবে কোনো `constructor` ডিফাইন না করেন, তাহলে (এবং শুধু তখনই) কম্পাইলার নিজেই কাজটি করে দেবে। উপরের প্রথম উদাহরণে ঠিক এটাই হয়েছে। _silverhand_ অবজেক্টটি তৈরি হয়েছে ডিফল্ট কনস্ট্রাক্টর কল করে, কোনো আর্গুমেন্ট দেওয়া হয়নি। সব ভ্যারিয়েবল ক্লাসের ডেফিনিশনে উল্লেখ করা মানেই সেট করা হয়েছে। ঐ ডেফিনিশনে যদি কোনো মান না দেওয়া হতো, তাহলে ভ্যারিয়েবলগুলো আনইনিশিয়ালাইজড থেকে যেত, যার পরিণতি অনভিপ্রেত হতে পারত।

## স্ট্রাক্ট

স্ট্রাক্ট এসেছে ভাষার শুরুর দিকের C থেকে, আর C++-এর মতোই পুরোনো। এগুলো কার্যত `classes`-এর মতোই একই জিনিস, তবে একটি গুরুত্বপূর্ণ ব্যতিক্রম আছে। ডিফল্টভাবে একটি `class`-এর সবকিছুই `private` থাকে। অন্যদিকে স্ট্রাক্ট, অন্যভাবে ডিফাইন না করা পর্যন্ত `public` থাকে। প্রচলিত রীতি অনুযায়ী, `struct` কিওয়ার্ডটি প্রায়ই **শুধু ডেটার স্ট্রাকচার**-এর জন্য ব্যবহার করা হয়। আর যে অবজেক্টগুলোর নির্দিষ্ট কিছু বৈশিষ্ট্য নিশ্চিত করা দরকার, সেগুলোর জন্য `class` কিওয়ার্ডটি পছন্দ করা হয়। এমন একটি ইনভ্যারিয়েন্ট হতে পারে যে আপনার `Wizard` `class`-এর `damage` কখনো ঋণাত্মক হতে পারবে না। `damage` ভ্যারিয়েবলটি private, তাই damage বদলানো যেকোনো ফাংশন ইনভ্যারিয়েন্টটি অটুট রাখা নিশ্চিত করবে।
