# ভূমিকা

## কমেন্ট

Exercism-এর x86-64 ট্র্যাকটি অ্যাসেম্বলার হিসেবে **NASM** (The Netwide Assembler) ব্যবহার করে।
NASM-এ কমেন্টের আগে একটি সেমিকোলন (`;`) বসানো হয়।

কমেন্ট প্রোগ্রামের যেকোনো জায়গায় রাখা যায়, এবং একটি `;` চিহ্নের পরে যা কিছু আসে তা অ্যাসেম্বলার উপেক্ষা করে।

## কনস্ট্যান্ট

**equ** ব্যবহার করে NASM-এ অ্যাসেম্বলার-টাইম কনস্ট্যান্ট ডিফাইন করা যায়।
যেমন, এটি `UNIVERSE` নামের একটি কনস্ট্যান্ট ডিফাইন করে, যার মান `42`:

```x86asm
UNIVERSE equ 42
```

কনস্ট্যান্ট ডিফাইন করার সময় একবারই মূল্যায়ন করা হয়, এবং পরে সেগুলো পুনরায় ডিফাইন করা যায় _না_।

## জেনারেল পারপাস রেজিস্টার (GPRs)

অ্যাসেম্বলিতে ভ্যারিয়েবলের বদলে আমরা সাধারণত মান সংরক্ষণ করতে রেজিস্টার ব্যবহার করি।
**CPU রেজিস্টার** হলো কম্পিউটারের প্রসেসরের ভেতরে থাকা এক টুকরো দ্রুতগতির মেমোরি।
বেশিরভাগ গণনাই CPU-এর রেজিস্টারগুলোতে সম্পন্ন হয়।

কিছু রেজিস্টার নানা ধরনের গণনায় ব্যবহৃত হয়, এদের **জেনারেল পারপাস রেজিস্টার (GPRs)** বলা হয়।
অন্যগুলোর বিশেষ বা নির্দিষ্ট কাজ থাকে।

x86-64-এ ১৬টি 64-বিট জেনারেল পারপাস রেজিস্টার (GPRs) আছে, যেগুলো 32-বিট, 16-বিট বা 8-বিট হিসেবেও অ্যাক্সেস করা যায়।
GPRs-গুলো নিচে বর্ণিত, যেখানে `rn`-এর `n` ৮ থেকে ১৫ পর্যন্ত: `r8`, `r9`, `r10`, `r11`, `r12`, `r13`, `r14` এবং `r15`।

| 64-bit | 32-bit | 16-bit | 8-bit |
| :----: | :----: | :----: | :---: |
|  rax   |  eax   |   ax   | ah/al |
|  rbx   |  ebx   |   bx   | bh/bl |
|  rcx   |  ecx   |   cx   | ch/cl |
|  rdx   |  edx   |   dx   | dh/dl |
|  rsi   |  esi   |   si   |  sil  |
|  rdi   |  edi   |   di   |  dil  |
|  rbp   |  ebp   |   bp   |  bpl  |
|  rsp   |  esp   |   sp   |  spl  |
|   rn   |  rnd   |  rnw   |  rnb  |

64-বিটের কম ব্যবহার করলে, যে বিটগুলো অ্যাক্সেস করা হয় সেগুলো সাধারণত রেজিস্টারের নিচের অংশের হয়।
এই নিয়মের ব্যতিক্রম হলো `ah`, `bh`, `ch` এবং `dh`, যেগুলো রেজিস্টারের 16-বিট অংশের উপরের 8-বিট অ্যাক্সেস করে।

`rax` রেজিস্টারের বিটগুলো কীভাবে অ্যাক্সেস করা হয় তার চিত্র:

```
+--------+---------------------------------------+
| 64-bit |                  rax                  |
+--------+-------------------+-------------------+
| 32-bit |                   |        eax        |
+--------+-------------------+---------+---------+
| 16-bit |                             |    ax   |
+--------+-----------------------------+----+----+
| 8-bit  |                             | ah | al |
+--------+-----------------------------+----+----+
```

এই রেজিস্টারগুলোর কয়েকটি ফাংশন কল জুড়ে সংরক্ষণ করতে হয়: `rbp`, `rsp`, `rbx`, `r12`, `r13`, `r14` এবং `r15`।
এগুলো সংরক্ষণ করতে ব্যর্থ হলে এরর বা অনির্ধারিত আচরণ হতে পারে।

বাকিগুলো সংরক্ষণ করতে হয় না এবং অবাধে ব্যবহার করা যায়: `rax`, `rcx`, `rdx`, `rdi`, `rsi`, `r8`, `r9`, `r10` এবং `r11`।

~~~~exercism/caution
সিলেবাসে পরে আপনি রেজিস্টার সংরক্ষণ করা শিখবেন।
আপাতত শুধু দ্বিতীয় ধরনের রেজিস্টার ব্যবহার করুন: `rax`, `rcx`, `rdx`, `rdi`, `rsi`, `r8`, `r9`, `r10` এবং `r11`।

## ইনস্ট্রাকশন

ইনস্ট্রাকশন হলো এমন কিছু গণনার অংশ যা একটি CPU করতে পারে।
এগুলোর সাধারণ রূপটি হলো:

```x86asm
name destination, source
```

তাই, প্রথমে ইনস্ট্রাকশনের নাম বসানো হয়, তারপর অন্তত একটি হোয়াইটস্পেস, এরপর ডেস্টিনেশন অপারেন্ড, একটি কমা (`,`) এবং সবশেষে একটি সোর্স অপারেন্ড।
সাধারণত ইনস্ট্রাকশন সোর্স অপারেন্ড পরিবর্তন করে না, শুধু ডেস্টিনেশন অপারেন্ড পরিবর্তন করে।

অন্যথা উল্লেখ না থাকলে দুই অপারেন্ডেরই একই সাইজ থাকতে হবে।
যেমন, সোর্স অপারেন্ডের যদি 16 বিট থাকে, তবে ডেস্টিনেশন অপারেন্ডেরও 16 বিট থাকতে হবে।

যেমন, একটি রেজিস্টারে মান সংরক্ষণ করতে আমরা `mov` ইনস্ট্রাকশন ব্যবহার করতে পারি:

```x86asm
mov rax, rdx  ; rax = rdx
              ; mov is the name, rax is the destination operand and rdx is the source operand
```

উপরের স্নিপেটটি সোর্স অপারেন্ড `rdx`-এর সব 64 বিটের বিষয়বস্তু ইনস্ট্রাকশনের ডেস্টিনেশন অপারেন্ড `rax`-এর সব 64 বিটে কপি করে।

বেশিরভাগ ইনস্ট্রাকশনে কনস্ট্যান্ট ইন্টিজার সংখ্যা সোর্স অপারেন্ড হিসেবে ব্যবহার করা সম্ভব (তবে ডেস্টিনেশন অপারেন্ড হিসেবে নয়):

```x86asm
mov rcx, 42 ; rcx = 42
            ; rcx is the destination operand and 42 is the source operand
```

মনে রাখবেন, একটি 32-বিট রেজিস্টারে লেখা হলে উপরের বিটগুলোও ক্লিয়ার হয়ে যায়, তাই `mov eax, 42` এবং `mov rax, 42` একই।
16-বিট ও 8-বিট রেজিস্টারের ক্ষেত্রে এটি সত্য নয়।

যোগ, বিয়োগ ও গুণের মতো গাণিতিক কাজে আমরা `add`, `sub` এবং `imul` ইনস্ট্রাকশন ব্যবহার করতে পারি:

```x86asm
add rax, rsi ; rax = rax + rsi
imul rax, rdi ; rax = rax * rdi
sub rax, r8 ; rax = rax - r8
```

## ফাংশন

ইনস্ট্রাকশনগুলো ফাংশনে সাজানো থাকে।
সব ফাংশন সোর্স ফাইলের **section .text** অংশে রাখা হয়।

একটি ফাংশন ডিক্লারেশন গঠিত হয়:

1. ফাংশনের নামের একটি লেবেল, তারপর একটি `:`।
2. ফাংশনটি ডিফাইন করে এমন ইনস্ট্রাকশন।
3. রিটার্ন ইনস্ট্রাকশন, `ret`।

এই ট্র্যাকটি System V AMD64 ABI কলিং কনভেনশন ব্যবহার করে এবং প্রথম ছয়টি ইন্টিজার আর্গুমেন্ট রেজিস্টারের মাধ্যমে ফাংশনে পাস করা হয়।
এগুলো নিচের ক্রমে পাস করা হয়: `rdi`, `rsi`, `rdx`, `rcx`, `r8` এবং `r9`।

ফাংশন থেকে একটি ইন্টিজার মান `rax` রেজিস্টারে রিটার্ন করা হয়।

একটি ফাংশন কল করতে আমরা `call` ইনস্ট্রাকশন ব্যবহার করি।
একই সোর্স ফাইলের যেকোনো জায়গা থেকে একটি ফাংশন কল করা যায়।
অন্য সোর্স ফাইলের কাছে একটি ফাংশন দৃশ্যমান করতে `global` ডিরেক্টিভ ব্যবহার করতে হয়।

যেমন, এটি একটি `sum` ফাংশন ডিক্লেয়ার করে:

```x86asm
section .text ; functions are placed here

global sum ; sum is visible to other source files

sum:
    ; first argument is passed in rdi
    ; second argument is passed in rsi
    ; return value is placed in rax

    mov rax, rdi ; rax is now equal to rdi
    add rax, rsi ; rax = rax + rsi

    ret ; function return
```

আর এটি ৩ ও ৫ আর্গুমেন্ট দিয়ে আমাদের `sum` ফাংশনটি কল করে:

```x86asm
mov rdi, 3  ; First argument in rdi
mov rsi, 5  ; Second argument in rsi
call sum

; The rax register now contains the value 8 (3 + 5), after sum returns
```
