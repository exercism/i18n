# পরিচিতি

## ভূমিকা

ওপেক টাইপ হলো Elm-এ এনক্যাপসুলেশনের একটি কৌশল।
অনেকে এটাকে ইনফরমেশন হাইডিং বা ইমপ্লিমেন্টেশনের বিবরণ গোপন করা বলেন।
ভ্যালিডেশন নিশ্চিত করতেও এগুলো সাধারণত ব্যবহৃত হয়, [Parse, dont validate][parse-dont-validate] প্যাটার্ন ব্যবহার করে।
উদাহরণস্বরূপ, আপনার একটি `EmailAddress` ওপেক টাইপ থাকতে পারে, যেটি কেবল বৈধ ইমেইল রাখতে পারে (যেকোনো কিছু রাখতে পারে এমন একটি `String`-এর বিপরীতে)।

## ওপেক টাইপ তৈরি করা

[কাস্টম টাইপ][custom-types]-এ এক বা একাধিক *ভ্যারিয়েন্ট* থাকে, আর কম্পাইলার স্বয়ংক্রিয়ভাবে প্রতিটি *ভ্যারিয়েন্ট* তৈরির একটি ফাংশন বানিয়ে দেয়, *ভ্যারিয়েন্ট*-এর নাম ব্যবহার করে।
কাস্টম টাইপ তৈরি করার একমাত্র উপায় এগুলোই।
কম্পাইলার এই ভ্যারিয়েন্টগুলো ডিস্ট্রাকচার করার সুযোগও দেয়।

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

ডিফল্টভাবে এগুলোর সবকিছু ফাইল বা মডিউলের ভেতরেই থাকে, আর কোনটা এক্সপোর্ট করবেন তা বেছে নিতে আমরা `exposing` কিওয়ার্ডটি ব্যবহার করি।
একটি ওপেক টাইপ তৈরি করতে, আপনি কেবল *ভ্যারিয়েন্ট*গুলো এক্সপোর্ট না করার সিদ্ধান্ত নেন।

এমন করলে, *ভ্যারিয়েন্ট* তৈরি ও পাওয়ার জন্য প্রায় সবসময়ই আপনাকে আরেকটি উপায় দিতে হবে, অর্থাৎ কাস্টম ফাংশন এক্সপোর্ট করে।
এই কাস্টম ফাংশনগুলো *ভ্যারিয়েন্ট* তৈরি ও পাওয়ার সময় কিছু লজিক প্রয়োগ করার সুযোগ দেয়।
এতে মডিউলের ভেতরের ইমপ্লিমেন্টেশনের বিবরণ লুকানো থাকে, আর এর মানে হলো, এক্সপোর্ট করা ফাংশনগুলো একই রকম থাকলেই আপনি ইমপ্লিমেন্টেশনের বিবরণ যত খুশি বদলাতে পারেন।

## Parse, don't validate

ওপেক টাইপের সবচেয়ে কমন ব্যবহার সম্ভবত ভ্যালিডেশন নিশ্চিত করা, [Parse, dont validate][parse-dont-validate] প্যাটার্ন ব্যবহার করে।
এই প্যাটার্নে আপনি এমন একটি ফাংশন এক্সপোর্ট করেন যা আপনার চেয়ে কম গঠন বা টাইপ সেফটি আছে এমন একটি ইনপুট নেয়, যেমন `String`, আর তারপর সেটিকে আরও গঠনবদ্ধ একটি টাইপে পার্স করে, যেমন `EmailAddress`, আর হয় ওই টাইপটি রিটার্ন করে, নাহয় একটি এরর রিটার্ন করে (সাধারণত `Maybe` বা `Result`)।

উদাহরণস্বরূপ, নিচের কোডে বাইরের মডিউলগুলোর জন্য `parseEmailAddress` ফাংশন দিয়ে `EmailAddress` টাইপ তৈরি করাই কেবল সম্ভব, তাই `EmailAddress` টাইপ নিয়ে কাজ করার সময় আপনি নিশ্চিত যে এটি বৈধ।

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
