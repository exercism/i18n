# ভূমিকা

রেগুলার এক্সপ্রেশন হলো স্ট্রিং _প্যাটার্ন ম্যাচ_ করার একটি অত্যন্ত বহুমুখী উপায়, যার জন্য বিশেষভাবে তৈরি একটি ডোমেইন স্পেসিফিক ল্যাঙ্গুয়েজ (DSL) ব্যবহার করা হয়।

অনেক রেজেক্স সুবিধাই Base R-এ অন্তর্ভুক্ত, আর পুরোনো কোডে আপনি এর উদাহরণ দেখতে পেতে পারেন।

নতুন কোডের জন্য [`stringr`][web-stringr] লাইব্রেরি ব্যবহার করা _দৃঢ়ভাবে_ সুপারিশ করা হয়।

[স্ট্রিং কনসেপ্টে][concept-strings] উল্লেখ করা হয়েছে, `stringr`-এর ভালো ডকুমেন্টেশন আছে, যা সাধারণত প্যাকেজের লেখক বা লেখকদের লেখা।

- একটি [রেফারেন্স ওয়েবসাইট][web-stringr]
- একটি [চিটশিট][cheat-stringr]।
- "R for Data Science"-এর একটি [স্ট্রিং অধ্যায়][book-strings] এবং একটি [রেজেক্স অধ্যায়][book-regex]।

[`Strings`][concept-strings] কনসেপ্টে আগেই আলোচনা করা অনেক ফাংশনই স্বাভাবিকভাবেই রেজেক্স সার্চের জন্য তৈরি।

আমরা স্ট্রিং কনসেপ্টটি তুলনামূলকভাবে সহজ রেখেছি, কেবল স্ট্রিং লিটারাল ম্যাচ করেই; তবে এর বদলে যেকোনো রেজেক্স প্যাটার্ন ব্যবহার করা যায়।

আনুষ্ঠানিকভাবে বলতে গেলে, R-এ [`regex()`][ref-regex] কল করে একটি রেজেক্স তৈরি করা হয়।
সুবিধার জন্য, `stringr`-এর ফাংশনগুলো যেকোনো প্যাটার্ন স্ট্রিংকেই একটি রেজেক্স হিসেবে গণ্য করে।
নিচের উদাহরণে প্রথম `str_replace_all()` হলো দ্বিতীয় সংস্করণের সিনট্যাক্টিক সুগার:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[চিটশিটটি][cheat-stringr] একটি কাজের গাইড: যে সব ফাংশনে `pattern` আর্গুমেন্ট আছে (লাল রঙে ছাপা), তারা সবাই রেজেক্স গ্রহণ করে, আর ২ নম্বর পৃষ্ঠায় রেজেক্স সিনট্যাক্সের সারসংক্ষেপ আছে।

মনে রাখবেন, কেস সেনসিটিভিটি বা লোকেলের মতো ডিফল্ট সেটিংস বদলাতে হলে [`regex()`][ref-regex] ফাংশনটি তখনও গুরুত্বপূর্ণ হতে পারে।

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

অনেক রেজেক্স কোডে ব্যাকস্ল্যাশ থাকে, যেমন ওপরে ব্যবহৃত `\s`।
সাধারণ R স্ট্রিংয়ে `\` লিখতে হলে ডাবল করে এস্কেপ করতে হয়, তাই `"\\s"`।

ব্যাকস্ল্যাশ বাড়তে বাড়তে বিভ্রান্তিকর হয়ে উঠতে পারে, তাই জটিল ক্ষেত্রে [র স্ট্রিং][book-raw] ব্যবহার করা সহায়ক হতে পারে।

ডিফল্টভাবে, একটি র স্ট্রিং ডিফাইন করার সিনট্যাক্স হলো `r"( )"`, তবে অন্য ডেলিমিটারও ব্যবহার করা যায়।
যেহেতু রেজেক্স সিনট্যাক্সে (ক্যাপচার গ্রুপ আর অপশন গ্রুপের জন্য) প্রথম বন্ধনী `( )` ও তৃতীয় বন্ধনী `[ ]` দুটোই প্রচুর ব্যবহৃত হয়, তাই দ্বিতীয় বন্ধনী `{ }` একটি ভালো পছন্দ হতে পারে।

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## ম্যাচ শনাক্ত করা

এখানে কিছু প্রশ্ন আছে, আর সেগুলোর উত্তর দিতে সহায়ক কিছু ফাংশনও আছে।

কিছু উদাহরণে `fruit` ব্যবহার করা হয়েছে, যা `stringr`-এর সঙ্গে অনুশীলনের জন্য দেওয়া ৮০টি ফলের নামের একটি ভেক্টর।

_স্ট্রিংয়ে কোনো ম্যাচ আছে কি?_
`str_detect()`, অথবা `^` বা `$` অ্যাঙ্কর ব্যবহার এড়াতে `str_starts()`, `str_ends()`।

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_শুধু যেসব স্ট্রিংয়ে ম্যাচ আছে সেগুলো ফেরত দিতে চান?_
স্ট্রিংগুলো পেতে `str_subset()` ব্যবহার করুন, ইনডেক্স পেতে `str_which()`।

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_প্রতিটি স্ট্রিংয়ে কতগুলো ম্যাচ আছে?_
`str_count()` ব্যবহার করুন।

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_ম্যাচটি কোথায়?_
ইন্টার্যাক্টিভভাবে দেখতে `str_view()`, আর সাধারণভাবে `str_locate()` বা `str_locate_all()`।

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## ক্যাপচার

সাধারণত আমরা জানতে চাই _কী_ ম্যাচ করেছে।
এটি করা হয় রেজেক্সের ভেতরে প্রথম বন্ধনীতে ক্যাপচার গ্রুপ যোগ করে।

একই রেজেক্সের ভেতরেই `\1`, `\2` ইত্যাদি ব্যবহার করে ক্যাপচারগুলোর দিকে আবার নির্দেশ করা সম্ভব।
যেমন, পরপর দুবার আসা অক্ষরের জোড়া খুঁজে বের করা:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

একই ধরনের সিনট্যাক্স দিয়ে রিপ্লেসমেন্ট স্ট্রিংয়েও ক্যাপচার ব্যবহার করা যায়:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

পরে কাজে লাগানোর জন্য ম্যাচগুলো জড়ো করতে শুধু প্রথম ম্যাচের জন্য `str_match()` ফাংশন, আর সব ম্যাচের জন্য `str_match_all()` ব্যবহার করুন।

ক্যাপচার গ্রুপ যেকোনো ভাষাতেই সাধারণত জটিল আউটপুট তৈরি করে।
R-এর পদ্ধতি হলো (_যা বাড়তি চ্যালেঞ্জ হিসেবে ভেক্টরাইজডও_) `str_match()` থেকে একটি ম্যাট্রিক্স তৈরি করা, যেখানে প্রতিটি ইনপুট স্ট্রিংয়ের জন্য একটি সারি থাকে, ১ নম্বর কলামে থাকে পুরো ম্যাচ হওয়া স্ট্রিং, আর বাকি কলামগুলোতে থাকে বিভিন্ন ক্যাপচার গ্রুপ।

নামযুক্ত গ্রুপ ব্যবহার করা সুবিধাজনক হতে পারে, কারণ এগুলো ফলাফলের ম্যাট্রিক্সে কলামের নাম হয়ে যায়।

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

~~~~exercism/note
এই সিলেবাসে আমরা ম্যাট্রিক্স নিয়ে বেশি কিছু বলিনি, যদিও [একটি কনসেপ্ট ডকুমেন্ট][concept-matrices-arrays] আছে যা আপনি দেখতে পারেন।
ম্যাট্রিক্স দীর্ঘদিন ধরে Base R-এর অংশ হলেও Tidyverse ইকোসিস্টেমের সঙ্গে ভালোভাবে মেলে না।

সংক্ষেপে: ম্যাট্রিক্সকে দুটি ইনডেক্সযুক্ত ভেক্টরের মতো ভাবুন, `[rows, cols]` এই ক্রমে।
যেকোনো একটি ইনডেক্স ফাঁকা রাখলে পুরো সারি বা কলাম পাওয়া যায়।

`m[r,]` দিয়ে একটি সারি `r` বা `m[,c]` দিয়ে একটি কলাম `c` নিলে, ফেরত আসা মানটি ডিফল্টভাবে একটি ভেক্টরে সমতল করে দেওয়া হয়।

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```
~~~~

অবশ্যম্ভাবীভাবেই, `str_match_all()` আরও বেশি গঠনযুক্ত আউটপুট তৈরি করে:

- ফলাফলটি একটি অ্যারে, যেখানে প্রতিটি ইনপুট স্ট্রিংয়ের জন্য একটি এলিমেন্ট থাকে।
- যদি কেবল একটি ইনপুট স্ট্রিং থাকে, তবে [অ্যারে কনসেপ্টে][concept-lists] বর্ণনা অনুযায়ী `[[1]]` ইনডেক্সিং দিয়ে আউটপুটটি unlist করুন।
- প্রতিটি এলিমেন্ট একটি ম্যাট্রিক্স, যার কলামগুলো `match()`-এর মতো।
- ম্যাট্রিক্সের প্রতিটি সারি একটি সফল ক্যাপচার।

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

অবশ্যই, ম্যাচ ব্যর্থও হতে পারে।
তখন ফলাফল হবে বিশেষ মান `NA`।
[নাথিংনেস কনসেপ্টে][concept-nothingness] বর্ণনা অনুযায়ী, এটি পরীক্ষা করার জন্য প্রস্তুত থাকুন।

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
