# ভূমিকা

## অ্যারে

Assembly-তে যেকোনো ডেটা আসলে বাইটের একটি ক্রম।
এর মানে হলো, যেকোনো ডেটাকে ওই অন্তর্নিহিত বাইটগুলোর একটি **অ্যারে** হিসেবে দেখা যেতে পারে।

### অ্যারের এলিমেন্টগুলো অ্যাক্সেস করা

মেমোরিতে যেকোনো মান অ্যাক্সেস করতে হলে তার **ইফেক্টিভ অ্যাড্রেস** হিসাব করা প্রয়োজন।
একটি ইফেক্টিভ অ্যাড্রেস হলো এমন একটি এক্সপ্রেশন, যা নিয়ে গঠিত হতে পারে:

- একটি _বেস অ্যাড্রেস_, যেমন ধরুন, কোনো ভ্যারিয়েবলের লেবেল দিয়ে যা বোঝানো হয়।
- একটি _ইনডেক্স রেজিস্টার_, যা সম্ভবত `1`, `2`, `4` বা `8` দিয়ে স্কেল করা।
- একটি সাইনড ৩২-বিট _ডিসপ্লেসমেন্ট_, যা হলো বেস অ্যাড্রেসের সাথে যোগ করা (বা বিয়োগ করা) এমন একটি সংখ্যা।

মনে রাখবেন, এই অ্যাড্রেসটি _০-ইনডেক্সড_, তাই কোনো অফসেট ছাড়া একটি বেস অ্যাড্রেস ভ্যারিয়েবলের প্রথম বাইটকে নির্দেশ করে।
এ কারণেই, আগের কনসেপ্টগুলোতে যেমনটি করা হয়েছে, সেভাবে কোনো অফসেট ছাড়া শুধু একটি লেবেল দিয়ে মেমোরি ডিরেফারেন্স করলে তার প্রথম বাইট থেকে শুরু হওয়া একটি মান পাওয়া যায়:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 হলো [লিটল এন্ডিয়ান][endianness]।
এর মানে হলো, একটি মাল্টিবাইট মানের সর্বনিম্ন তাৎপর্যপূর্ণ বাইটটি ক্ষুদ্রতম মেমোরি অ্যাড্রেসে সংরক্ষিত থাকে।

ফলস্বরূপ, একটি মাল্টিবাইট মানের পৃথক বাইটগুলো অ্যাক্সেস করার সময়, আরও তাৎপর্যপূর্ণ বাইটে পৌঁছাতে বেস অ্যাড্রেসের সাথে একটি ধনাত্মক অফসেট যোগ করা প্রয়োজন।

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

মানের একটি তালিকা দিয়ে ঘোষণা করা একটি ইনিশিয়ালাইজড ভ্যারিয়েবল হলো ওই মানগুলোর একটি অ্যারে, যার প্রতিটি এলিমেন্টের আকার নির্দিষ্ট করা থাকে।
তবে অফসেট সবসময় **_বাইটে_** হয়ে থাকে, এমনকি অ্যারের প্রতিটি এলিমেন্টের আকার বড় হলেও:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

মনে রাখবেন, যেহেতু অ্যাড্রেসগুলো বাইটে হিসাব করা হয়, তাই অ্যারের যেকোনো এলিমেন্টের একটি নির্দিষ্ট বাইট সরাসরি অ্যাক্সেস করা সম্ভব:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

একই কারণে, একটি ইনস্ট্রাকশনে একটি এলিমেন্টের আকারের চেয়ে বেশি অ্যাক্সেস করাও সম্ভব:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
Assembly অ্যারে অ্যাক্সেসের ক্ষেত্রে কোনো বাউন্ডস চেকিং করে না।
অ্যারের শেষ ছাড়িয়ে যাওয়া একটি ইনডেক্স তার বাইরের মেমোরি পড়ে বা লেখে।
এটি নীরবে ভুল ফলাফল দিতে পারে, অন্য ডেটা নষ্ট করতে পারে, এবং অ্যাক্সেস করা মেমোরি ম্যাপ করা না থাকলে রানটাইম ফল্ট ঘটাতে পারে।
প্রতিটি ইফেক্টিভ অ্যাড্রেস অ্যারের ভেতরে রাখার দায়িত্ব প্রোগ্রামারের।
~~~~

### একটি ইনিশিয়ালাইজড অ্যারের আকার হিসাব করা

NASM (The Netwide Assembler, এই ট্র্যাকের ব্যবহৃত অ্যাসেম্বলার)-এর একটি বিশেষ সিম্বল (`$`) আছে যা মেমোরিতে বর্তমান অবস্থান নির্দেশ করে।
এই সিম্বলটি একটি অ্যারে দখল করা মেমোরির মোট আকার হিসাব করার একটি সুবিধাজনক উপায় দেয়:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

`example`-এর ঠিক পরে ব্যবহার করা হলে, `$` হলো অ্যারের শেষের মেমোরি অ্যাড্রেস।
এর মানে হলো, `$ - example` হলো ওই অ্যাড্রেস আর `example` লেবেল দ্বারা নির্দেশিত অ্যাড্রেসের মধ্যে পার্থক্য।
এটাই হলো `example` দ্বারা নির্দেশিত অ্যারেটির দখল করা মোট আকার, বাইটে।

তাই, এই মান দিয়ে `example_length` ডিফাইন করে, আমরা একটি ৮-বাইটের ভ্যারিয়েবল তৈরি করেছি যা অ্যারের আকার, বা দৈর্ঘ্য, বাইটে সংরক্ষণ করে।

### Section .bss

আনইনিশিয়ালাইজড ডেটা **section .bss**-এ ঘোষণা করা হয়।
বেশিরভাগ প্ল্যাটফর্মে, প্রোগ্রাম শুরুর সময় OS এই ডেটা শূন্য দিয়ে ভরে দেয়।

NASM-এ, একটি আনইনিশিয়ালাইজড ভ্যারিয়েবলের থাকে একটি নাম, একটি ডিরেক্টিভ যা ডেটার আকার বোঝায়, এবং সংরক্ষিত রাখার জন্য এলিমেন্টের সংখ্যা।
এগুলোর প্রতিটিকে একটি স্পেস দিয়ে অন্যটি থেকে আলাদা করা হয়।

প্রধান ডিরেক্টিভগুলো এবং তাদের সংশ্লিষ্ট ডেটার আকার:

| ডিরেক্টিভ | আকার    |
| :-------: | :------ |
|   resb    | ১ বাইট  |
|   resw    | ২ বাইট |
|   resd    | ৪ বাইট |
|   resq    | ৮ বাইট |

উদাহরণস্বরূপ, এটি `example` নামের একটি ভ্যারিয়েবলে `3` বাইটের জন্য আনইনিশিয়ালাইজড জায়গা সংরক্ষণ করে:

```x86asm
section .bss
    example resb 3
```

আর এটি `arr` নামের একটি ভ্যারিয়েবলে `10` গুণ `8` বাইটের (অর্থাৎ `80` বাইট) আনইনিশিয়ালাইজড জায়গা সংরক্ষণ করে:

```x86asm
section .bss
    arr resq 10
```

`section .bss`-এর ভ্যারিয়েবলগুলো মিউটেবল, অর্থাৎ এগুলো পড়া ও লেখা যায়।

আনইনিশিয়ালাইজড ডেটা ইনিশিয়ালাইজড ডেটার মতোই তার ইফেক্টিভ অ্যাড্রেস ব্যবহার করে অ্যাক্সেস করা যায়।
একইভাবে, এগুলো স্ট্যাটিক স্টোরেজ ডিউরেশনেরও, এবং একই সোর্স ফাইলের যেকোনো ফাংশন থেকে অ্যাক্সেসযোগ্য (এবং `global` হিসেবে ঘোষণা করা থাকলে, অন্য সোর্স ফাইল থেকেও)।

### Lea ইনস্ট্রাকশন দিয়ে অ্যারের অ্যাড্রেস অ্যাক্সেস করা

আগের একটি কনসেপ্টে যেমনটি দেখা হয়েছে, `lea` ইনস্ট্রাকশনটি একটি ইফেক্টিভ মেমোরি অ্যাড্রেস হিসাব করে।
একই সেম্যান্টিক্স অনুসরণ করে এটি অ্যারের যেকোনো এলিমেন্টের অ্যাড্রেস হিসাব করতে ব্যবহার করা যায়।

মনে রাখবেন, রিলেটিভ অ্যাড্রেসিংয়ে আরও জটিল একটি অ্যাড্রেস গঠনের আগে প্রায়ই ভ্যারিয়েবলের অ্যাড্রেস একটি রেজিস্টারে লোড করা প্রয়োজন:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea`-এর একটি সুবিধা হলো, এটি ওই অ্যাড্রেসের মেমোরি আসলে অ্যাক্সেস না করেই একটি মান হিসাব করতে অ্যাড্রেস-হিসাবের অ্যারিথমেটিক ব্যবহার করে।
এতে কোনও রেজিস্টারে মেমোরি অ্যাড্রেস না থাকলেও অ্যারিথমেটিক হিসাব করতে এটি কাজে লাগে:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
