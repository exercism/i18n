# বেসিকস সম্পর্কে

Kotlin একটি স্ট্যাটিক টাইপড ভাষা, যা Java-এর সাথে সম্পূর্ণভাবে ইন্টারঅপারেবল হওয়ার জন্য ডিজাইন করা হয়েছে।

Java থেকে এটিকে যা আলাদা করে, Kotlin:

- আরও পরিচ্ছন্ন ও সংক্ষিপ্ত সিনট্যাক্স রয়েছে;
- ফাংশনাল ভাষার অনেক বৈশিষ্ট্য ধারণ করে;
- নালেবল মানের জন্য ব্যাপক সাপোর্ট রয়েছে।

## ভ্যারিয়েবল

যেহেতু Kotlin স্ট্যাটিক টাইপড, তাই কম্পাইল টাইমে প্রতিটি মানের টাইপ _জানা_ প্রয়োজন।

তবে Kotlin-এর [টাইপ ইনফারেন্স][inference] খুবই শক্তিশালী, তাই টাইপ _নির্দিষ্ট করা_ প্রায়শই ঐচ্ছিক।

একটি ভ্যারিয়েবল ডিক্লেয়ার করার দুটি উপায় আছে।

1. `val` একটি অপরিবর্তনযোগ্য ভ্যারিয়েবল তৈরি করে, আর এটি পরিবর্তন করার চেষ্টা করলে কম্পাইল-টাইম এরর হয়।

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. `var` একটি পরিবর্তনযোগ্য ভ্যারিয়েবল তৈরি করে।

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

যেহেতু অপরিবর্তনযোগ্য ভ্যারিয়েবল বাগের একটি কমন ধরন দূর করে, তাই যেখানে সম্ভব `val` ব্যবহার করতে উৎসাহ দেওয়া হয়।

এছাড়া, এমনকি একটি `var`-ও টাইপ বদলাতে পারে না:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

দৃষ্টি বিভ্রান্তি কমাতে, এই সিলেবাসে বেশিরভাগ ক্ষেত্রে স্পষ্ট টাইপ বাদ দেওয়া হবে।
তবুও, অন্তত নিচের ক্ষেত্রে টাইপ উল্লেখ করা বাঞ্ছনীয়:

- পাবলিক API
- ফাংশন সিগনেচার
- যেখানে ডকুমেন্টেশনের প্রয়োজন

কিছু কোম্পানি ও প্রতিষ্ঠান কঠোর টাইপ সেফটি দাবি করে টাইপ ইনফারেন্স নিষিদ্ধ করে, আবার অন্যরা এটি "সহজ" টাইপের মধ্যে সীমাবদ্ধ রাখে, বা টাইপ ইনফারেন্স পুরোপুরি গ্রহণ করে।

```kotlin
val x: Int = 42  // => 42
```

সাধারণভাবে, ভ্যারিয়েবল ও ফাংশনের নাম `camelCase` শৈলীতে হওয়া উচিত, `snake_case` নয়

## ফাংশন

`fun` কিওয়ার্ড দিয়ে একটি ফাংশন ডিক্লেয়ার করুন।
Java-এর বিপরীতে, ফাংশনকে একটি ক্লাসের অংশ হতে হয় না।

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

কয়েকটি বিষয় লক্ষণীয়:

- ফাংশনের নামের পরে বন্ধনী `()` দিতে হয়, এমনকি ফাংশনটি কোনো আর্গুমেন্ট না নিলেও।
- ফাংশনের আর্গুমেন্টে টাইপ উল্লেখ করতে হয়: এখানে টাইপ ইনফারেন্স নেই (ভ্যারিয়েবলের বিপরীতে)।
- ফাংশনের বডি `{ }` দ্বিতীয় বন্ধনীর মধ্যে আবদ্ধ থাকে (তবে নিচে দেখুন)।
- মান রিটার্ন করলে `return` কিওয়ার্ড অবশ্যই লাগবে।
- লাইনের শেষে সেমিকোলন `;` ঐচ্ছিক, এবং সাধারণত বাদ দেওয়া হয়।
- গাণিতিক অপারেটর `+`, `-`, `*`, `/` বেশিরভাগ প্রচলিত ভাষার মতোই।

তবে এই খুবই সরল, "সিঙ্গেল-এক্সপ্রেশন" ফাংশনগুলোর জন্য একটি সংক্ষিপ্ত সিনট্যাক্স আছে:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
ফাংশনে ডিফল্ট মানসহ প্যারামিটার থাকতে পারে।
ফাংশন যেখানে কল করা হয় সেখানে এগুলো বাদ দিলে এই মানগুলোই ব্যবহৃত হবে:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

Exercism-এর মধ্যে ফাংশন সাধারণত একটি মান রিটার্ন করে (টেস্ট রানার যেভাবে সাজানো থাকে তার কারণে)।
আরও 널ি Kotlin ব্যবহার করতে চাইলে জেনে রাখা কাজে লাগতে পারে যে, যে ফাংশন কোনো মান রিটার্ন করে না, সেটি রিটার্ন টাইপ ও return কিওয়ার্ড দুটোই বাদ দিতে পারে।

তখন এটিকে `Unit` রিটার্ন টাইপযুক্ত বলা হয়: যা Java ও আরও কয়েকটি ভাষার `void` টাইপের সমতুল্য।

## কমেন্ট

এক-লাইনের কমেন্ট `//` দিয়ে শুরু হয়, এরপর লাইনের বাকি অংশ উপেক্ষা করা হয়।

একাধিক লাইনের কমেন্ট `/*` দিয়ে শুরু হয় এবং `*/` দিয়ে শেষ হয়।

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

এটি Java-এর মতোই।
