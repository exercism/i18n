# পরিচিতি

রেগুলার এক্সপ্রেশন হলো স্ট্রিং _প্যাটার্ন ম্যাচ_ করার একটি অত্যন্ত বহুমুখী উপায়, আর এর জন্য বিশেষভাবে বানানো একটি ডোমেইন স্পেসিফিক ভাষা (DSL) ব্যবহার করা হয়।

Base R-এর মধ্যেই অনেক রেজেক্স সুবিধা বিল্ট-ইন করা আছে, আর পুরোনো কোডে আপনি এর উদাহরণ দেখতে পাবেন।

নতুন কোডের ক্ষেত্রে [`stringr`][web-stringr] লাইব্রেরি ব্যবহার করার _জোরালো_ সুপারিশ করা হয়।

[স্ট্রিং ধারণা][concept-strings] পাতায় যেমন উল্লেখ করা হয়েছে, `stringr`-এর ডকুমেন্টেশন ভালো, সাধারণত প্যাকেজের লেখক(রা) নিজেই তা লেখেন।

- একটি [রেফারেন্স ওয়েবসাইট][web-stringr]
- একটি [চিটশিট][cheat-stringr]।
- "R for Data Science"-এর একটি [স্ট্রিং অধ্যায়][book-strings] ও একটি [রেজেক্স অধ্যায়][book-regex]।

[`Strings`][concept-strings] ধারণায় আগেই আলোচনা করা অনেক ফাংশনই স্বাভাবিকভাবেই রেজেক্স সার্চের জন্য তৈরি।

স্ট্রিং ধারণাটি আমরা তুলনামূলক সহজ রেখেছিলাম, শুধু স্ট্রিং লিটারালের সাথে ম্যাচ করিয়ে, কিন্তু তার বদলে যেকোনো রেজেক্স প্যাটার্ন ব্যবহার করা যায়।

আনুষ্ঠানিকভাবে বললে, R-এ [`regex()`][ref-regex] কল করে একটি রেজেক্স তৈরি করা হয়।
সুবিধার জন্য, `stringr`-এর ফাংশনগুলো যেকোনো প্যাটার্ন স্ট্রিংকেই একটি রেজেক্স হিসেবে ধরে নেয়।
নিচের উদাহরণে প্রথম `str_replace_all()` হলো দ্বিতীয় সংস্করণের সিনট্যাকটিক সুগার:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[চিটশিট][cheat-stringr] একটি দরকারি গাইড: `pattern` আর্গুমেন্ট আছে এমন প্রতিটি ফাংশনই (লাল রঙে ছাপা) একটি রেজেক্স গ্রহণ করে, আর ২ নম্বর পাতায় রেজেক্স সিনট্যাক্সের সারসংক্ষেপ আছে।

মনে রাখবেন, ডিফল্ট সেটিং বদলানোর দরকার হলে, যেমন কেস সেনসিটিভিটি বা লোকেল, [`regex()`][ref-regex] ফাংশনটি তখনও গুরুত্বপূর্ণ হতে পারে।

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

অনেক রেজেক্স কোডে ব্যাকস্ল্যাশ থাকে, যেমন উপরে ব্যবহৃত `\s`।
সাধারণ R স্ট্রিংয়ে `\`-কে দুইবার লিখে এস্কেপ করতে হয়, তাই `"\\s"`।

ব্যাকস্ল্যাশ জমতে জমতে বিভ্রান্তিকর হয়ে উঠতে পারে, তাই জটিল ক্ষেত্রে [র স্ট্রিং][book-raw] ব্যবহার করা সহায়ক হতে পারে।

ডিফল্টভাবে একটি র স্ট্রিং ডিফাইন করার সিনট্যাক্স হলো `r"( )"`, তবে অন্য ডেলিমিটারও ব্যবহার করা যায়।
যেহেতু প্রথম বন্ধনী `( )` ও তৃতীয় বন্ধনী `[ ]` দুটোই রেজেক্স সিনট্যাক্সে (ক্যাপচার গ্রুপ ও অপশন গ্রুপের জন্য) খুব সাধারণ, তাই দ্বিতীয় বন্ধনী `{ }` একটি ভালো পছন্দ হতে পারে।

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## ম্যাচ শনাক্ত করা

এখানে কিছু প্রশ্ন আছে, আর সেগুলোর উত্তর দিতে সাহায্য করতে পারে এমন কিছু ফাংশনও।

কিছু উদাহরণে `fruit` ব্যবহার করা হয়েছে, যা `stringr`-এর সাথে অভ্যাসের জন্য দেওয়া ৮০টি ফলের নামের একটি ভেক্টর।

_কোনো স্ট্রিংয়ে ম্যাচ আছে কি?_
`str_detect()`, অথবা `^` বা `$` অ্যাংকর এড়াতে `str_starts()` ও `str_ends()`।

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_শুধু যেসব স্ট্রিংয়ে ম্যাচ আছে সেগুলো ফেরত দিতে চান?_
স্ট্রিংগুলো পেতে `str_subset()`, আর ইনডেক্সগুলো পেতে `str_which()` ব্যবহার করুন।

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_প্রতিটি স্ট্রিংয়ে কতগুলো ম্যাচ আছে?_
`str_count()` ব্যবহার করুন।

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_ম্যাচটি কোথায়?_
ইন্টার্যাকটিভ ব্যবহারের জন্য `str_view()`, আর সাধারণভাবে `str_locate()` বা `str_locate_all()`।

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## ক্যাপচার

সাধারণত আমরা জানতে চাই _কী_ ম্যাচ করেছে।
এটি করা হয় রেজেক্সের ভেতরে প্রথম বন্ধনীতে ক্যাপচার গ্রুপ যোগ করে।

একই রেজেক্সের ভেতরেই `\1`, `\2` ইত্যাদি দিয়ে আগের ক্যাপচারগুলোর দিকে আবার ইশারা করা সম্ভব।
যেমন, পুনরাবৃত্ত অক্ষরের জোড়া খুঁজে বের করা:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

একই ধরনের সিনট্যাক্স দিয়ে রিপ্লেসমেন্ট স্ট্রিংয়েও ক্যাপচার ব্যবহার করা যায়:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

পরে ব্যবহারের জন্য ম্যাচগুলো জমা করতে শুধু প্রথম ম্যাচের জন্য `str_match()` ফাংশনটি ব্যবহার করুন, আর সব ম্যাচের জন্য `str_match_all()`।

ক্যাপচার গ্রুপ যেকোনো ভাষাতেই সাধারণত জটিল আউটপুট তৈরি করে।
R-এর পদ্ধতি (_বাড়তি চ্যালেঞ্জ হিসেবে এটি ভেক্টরাইজডও_) হলো `str_match()` থেকে একটি ম্যাট্রিক্স তৈরি করা, যেখানে প্রতিটি ইনপুট স্ট্রিংয়ের জন্য একটি সারি থাকে, ১ নম্বর কলামে থাকে পুরো ম্যাচ হওয়া স্ট্রিং, আর বাকি কলামগুলোতে থাকে নানা ক্যাপচার গ্রুপ।

নেমড গ্রুপ ব্যবহার করা সুবিধাজনক হতে পারে, কারণ ফলাফলের ম্যাট্রিক্সে এগুলোই কলামের নাম হয়ে যায়।

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

এই পাঠ্যক্রমে ম্যাট্রিক্স নিয়ে আমরা বেশি কিছু বলিনি, যদিও আপনি দেখতে পারেন এমন একটি [ধারণা ডকুমেন্ট][concept-matrices-arrays] আছে।
ম্যাট্রিক্স Tidyverse ইকোসিস্টেমের সাথে ভালোভাবে মানায় না, যদিও এটি অনেক দিন ধরেই Base R-এর অংশ।

সংক্ষেপে: ম্যাট্রিক্সকে দুটি ইনডেক্সওয়ালা ভেক্টর ভাবুন, `[rows, cols]` ক্রমে।
পুরো সারি বা কলাম পেতে যেকোনো একটি ইনডেক্স ফাঁকা রাখুন।

`m[r,]` দিয়ে একটি সারি `r` বা `m[,c]` দিয়ে একটি কলাম `c` নেওয়ার সময়, ডিফল্টভাবে রিটার্ন করা মানটি ফ্ল্যাট হয়ে একটি ভেক্টরে পরিণত হয়।

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

অবশ্যম্ভাবীভাবেই, `str_match_all()` আরও বেশি গঠনযুক্ত আউটপুট দেয়:

- ফলাফলটি একটি অ্যারে, যেখানে প্রতিটি ইনপুট স্ট্রিংয়ের জন্য একটি এলিমেন্ট থাকে।
- যদি ইনপুট স্ট্রিং একটিই থাকে, তবে [অ্যারে ধারণা][concept-lists] পাতায় বর্ণিত `[[1]]` ইনডেক্সিং দিয়ে আউটপুটটি আনলিস্ট করুন।
- প্রতিটি এলিমেন্ট একটি ম্যাট্রিক্স, যার কলামগুলো `match()`-এর মতোই।
- ম্যাট্রিক্সের প্রতিটি সারি একটি সফল ক্যাপচার।

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

অবশ্যই, ম্যাচ ব্যর্থ হতে পারে।
তখন ফলাফল হবে বিশেষ মান `NA`।
এর জন্য টেস্ট করতে প্রস্তুত থাকুন, [শূন্যতা ধারণা][concept-nothingness] পাতায় যেমন বর্ণনা করা হয়েছে।

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
