# বুলিয়ান

`BOOL` দুটি মানের একটি ধারণ করে, `true` আর `false`.

```sather
   ready : BOOL is
      return true;
   end;
```

## তুলনা

| অপারেটর | জিজ্ঞাসা করে | উদাহরণ |
| --- | --- | --- |
| `=` | একই? | `age = 13` |
| `/=` | আলাদা? | `age /= 13` |
| `<` | ছোট | `age < 13` |
| `<=` | ছোট বা সমান | `age <= 13` |
| `>` | বড় | `age > 13` |
| `>=` | বড় বা সমান | `age >= 13` |

এগুলো সংখ্যার উপর কাজ করে, আর `=` ও `/=` স্ট্রিংয়ের উপরও কাজ করে।

## তিনটি অপারেটর

| অপারেটর | লেখা হয় | সত্য হয় যখন |
| --- | --- | --- |
| and | `a and b` | দুটোই সত্য |
| or | `a or b` | অন্তত একটি সত্য |
| not | `~a` | `a` মিথ্যা |

`and` আর `or` **শর্ট-সার্কিটিং**: `a` মিথ্যা প্রমাণিত হলে `a and b` আর `b` দেখে না, কারণ উত্তরটা ততক্ষণে স্থির হয়ে গেছে। একইভাবে `a` সত্য হলে `a or b` থেমে যায়। এটা তখন গুরুত্বপূর্ণ, যখন ডান দিকের অংশটি খরচসাপেক্ষ, বা চালালে ভুল হয়ে যেত।

## সরাসরি একটি তুলনা রিটার্ন করা

যে রুটিনের পুরো কাজটাই একটি প্রশ্ন করার, তার উচিত সেই প্রশ্নটাই রিটার্ন করা, শর্ত দিয়ে একটি উত্তর বেছে নেওয়া নয়:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

`if age >= 13 then return true else return false end` লিখতে তিনটি লাইন লাগে সেটাই বলতে, যা তুলনাটি এক লাইনেই বলে দিয়েছিল, আর অভিজ্ঞ পাঠকের চোখে এটা ধরা পড়বেই।

## অগ্রাধিকার

`~` সবচেয়ে শক্তভাবে বাঁধে, তারপর `and`, তারপর `or`. তাই

```sather
~a and b or c
```

মানে `((~a) and b) or c`। বন্ধনী লিখতে কিছুই খরচ হয় না, আর যখনই পাঠককে লাইনটি বুঝতে ওই ক্রমটা মনে করতে হতো, তখনই এগুলো কাজে দেয়।
