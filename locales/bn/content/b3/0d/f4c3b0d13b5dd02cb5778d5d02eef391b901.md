# While ও Until লুপ

লুপ হলো এমন একটি কন্ট্রোল স্ট্রাকচার, যা একটি নির্দিষ্ট শর্তের ভিত্তিতে কোড বারবার চালানোর সুযোগ দেয়।

## While লুপ

While লুপ হলো এমন একটি কন্ট্রোল স্ট্রাকচার, যা একটি নির্দিষ্ট শর্তের ভিত্তিতে কোড বারবার চালানোর সুযোগ দেয়।
While লুপের ভেতরের কোড ততক্ষণ চলতে থাকবে, যতক্ষণ শর্তটি ট্রুথি হিসেবে মূল্যায়িত হয়।
ইটারেশনের সংখ্যা আগে থেকে জানা না থাকলে While লুপ প্রায়ই ব্যবহার করা হয়, তবে যেখানে লুপ প্রয়োজন সেখানে যেকোনো পরিস্থিতিতেই এটি ব্যবহার করা যায়।

লুপের ভেতরের কোড চালানোর আগেই শর্তটি মূল্যায়ন করা হয়, অর্থাৎ শর্তটি ফলস হলে লুপের ভেতরের কোড কখনোই চালানো হবে না।

```crystal
i = 0
while i < 3
  puts i
  i += 1
end

# Output:
# 0
# 1
# 2
```

একটি স্ট্রিংয়ের ওপর ইটারেশন করতে চাইলে আপনি স্ট্রিংটির দৈর্ঘ্যের ওপর লুপ চালাতে পারেন।

```crystal
str = "Hello"
i = 0
while i < str.size
  puts str[i]
  i += 1
end

# Output:
# H
# e
# l
# l
# o
```

## Until লুপ

Until লুপ While লুপের মতোই কাজ করে, তবে পার্থক্য হলো লুপের ভেতরের কোড ততক্ষণ চলতে থাকবে, যতক্ষণ না শর্তটি ট্রুথি হিসেবে মূল্যায়িত হয়।
এটি `if` আর `unless`-এর মধ্যকার পার্থক্যের মতোই।

```crystal
i = 0
until i == 3
  puts i
  i += 1
end
```

### ইনফিনিট লুপ

While লুপের সাথে একটি কমন এরর হলো "ইনফিনিট লুপে" ঢুকে পড়া, যা কখনো শেষ হয় না।
শর্তটি _কখনোই_ ট্রুথি বা ফলসি হিসেবে মূল্যায়িত না হলে একটি ইনফিনিট লুপ তৈরি হতে পারে।
এটি প্রায়ই প্রোগ্রামারের ভুলের কারণে ঘটে; যেমন, লুপ ভ্যারিয়েবল বাড়াতে ভুলে যাওয়া।
কিন্তু কখনো কখনো একটি ইনফিনিট লুপই প্রোগ্রামের লজিক বাস্তবায়নের সবচেয়ে স্পষ্ট উপায়।
আবার কখনো চিরকাল লুপ চালানো অপরিহার্য; যেমন একটি HTTP সার্ভার একটি ইনকামিং কানেকশনের জন্য অপেক্ষা করে, সেটি হ্যান্ডেল করে, তারপর পরের কানেকশনের জন্য অপেক্ষা করে।

## Break

লুপ থেকে আগেভাগেই বেরিয়ে আসতে `break` কিওয়ার্ডটি ব্যবহার করা যায়।
নির্দিষ্ট কিছু শর্তে লুপ থেকে আগেভাগে বেরিয়ে আসতে চাইলে এটি সুবিধাজনক হতে পারে।

```crystal
i = 0
while i <= 3
  puts i
  i += 1
  if i == 2
    break
  end
end

# Output:
# 0
# 1
```

## Next

লুপের পরের ইটারেশনে চলে যেতে `next` কিওয়ার্ডটি ব্যবহার করা যায়।
লুপের নির্দিষ্ট কিছু ইটারেশন বাদ দিতে চাইলে এটি সুবিধাজনক হতে পারে।

```crystal
i = 0
while i <= 3
  i += 1
  if i == 2
    next
  end
  puts i
end

# Output:
# 1
# 3
```

## লুপের ভেতরে টাইপ

লুপের ভেতরে ভ্যারিয়েবলের টাইপ ভিন্ন হতে পারে।
নিচের উদাহরণে `a`-এর টাইপ `Int32 | String`, কারণ লুপের প্রথম অংশে এটি `Int32` বা `String` হতে পারে।
ভ্যারিয়েবল `a` কেবল লুপের প্রথম অংশেই `Int32 | String` টাইপ ধারণ করবে, কারণ লুপ শুরু হওয়ার সময় এটি `Int32` ধারণ করে, আর দ্বিতীয় ইটারেশনে এটি একটি `String` ধারণ করে।
এই মাল্টিপল-টাইপ সিস্টেমটি পরে বিস্তারিতভাবে ব্যাখ্যা করা হবে।
কিন্তু যেহেতু আমরা নিশ্চিত যে লুপের দ্বিতীয় অংশে কেবল `String` থাকবে, তাই লুপের দ্বিতীয় অংশে `a`-এর টাইপ `String`।
রানটাইমে এটি কখনোই একইসাথে `Int32` আর `String` ধারণ করবে না।

```crystal
i = 0
a = 4
while i < 3
  p typeof(a)
  # => Int32 | String
  a = "4"
  p typeof(a)
  # => String
  i += 1
end
```

# রিটার্ন

Crystal-এ একটি মেথডের শেষ এক্সপ্রেশনটি তার মান রিটার্ন করে।
তবে কখনো কখনো শেষ এক্সপ্রেশনের আগেই একটি মান রিটার্ন করা প্রয়োজন হয়।
এজন্য আপনি `return` কিওয়ার্ডটি ব্যবহার করতে পারেন, যা পরের এক্সপ্রেশনটির মান রিটার্ন করবে।
`return` কিওয়ার্ডের পরে লেখা কোড আর চালানো হবে না।

```crystal
def speed_limit(road_number)
    if road_number == 1
        return 50
        puts "This will not be executed"
    elsif road_number == 2
        return 80
        puts "This will not be executed"
    end
    100
end

p speed_limit(1) # => 50
p speed_limit(2) # => 80
p speed_limit(3) # => 100
```

~~~~exercism/note
একটি মেথডের শেষ এক্সপ্রেশনটিই যদি রিটার্ন করার মান হয়, তবে `return` কিওয়ার্ডটি বাদ দেওয়া উচিত।
~~~~
