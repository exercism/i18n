# পরিচিতি

## সাধারণ সিনট্যাক্স

for লুপ হলো কোনো লজিক বারবার চালানোর জন্য সবচেয়ে বেশি ব্যবহৃত স্টেটমেন্টগুলোর একটি। Go-তে একটি for লুপে থাকে `for` কিওয়ার্ড, একটি হেডার, আর একটি কোড ব্লক, যার দ্বিতীয় বন্ধনীর ভেতরে লুপের বডি থাকে। হেডারটি সেমিকোলন `;` দিয়ে আলাদা করা ৩টি কম্পোনেন্ট নিয়ে গঠিত: init, শর্ত আর post।

```go
for init; condition; post {
  // loop body - code that is executed repeatedly as long as the condition is true
}
```

- **init** কম্পোনেন্ট হলো কিছু কোড, যা লুপ শুরুর আগে একবারই চলে।
- **শর্ত** (ইংরেজিতে _condition_) কম্পোনেন্টটি এমন একটি এক্সপ্রেশন হতে হবে, যা বুলিয়ান মান দেয় এবং লুপ কখন থামবে তা নিয়ন্ত্রণ করে। এই শর্তের মান ট্রু থাকা পর্যন্ত লুপের ভেতরের কোড চলবে। এই এক্সপ্রেশনের মান ফলস হয়ে গেলেই লুপের আর কোনো ইটারেশন চলবে না।
- **post** কম্পোনেন্ট হলো কিছু কোড, যা প্রতিটি ইটারেশনের শেষে চলে।

**লক্ষ্য করুন:** অন্য ভাষাগুলোর মতো নয়, হেডারের তিনটি কম্পোনেন্টকে ঘিরে কোনো প্রথম বন্ধনী `()` থাকে না। আসলে এমন প্রথম বন্ধনী বসিয়ে দিলে সেটি একটি কম্পাইলেশন এরর হয়। তবে লুপের বডিকে ঘিরে রাখা দ্বিতীয় বন্ধনী `{ }` সবসময়ই লাগে।

## for লুপ - একটি উদাহরণ

init কম্পোনেন্ট সাধারণত একটি কাউন্টার ভ্যারিয়েবল তৈরি করে, শর্ত পরীক্ষা করে লুপটি চালিয়ে যাওয়া উচিত কি না, আর post কম্পোনেন্ট সাধারণত প্রতিটি পুনরাবৃত্তির শেষে কাউন্টারটি ইনক্রিমেন্ট করে।

```go
for i := 1; i < 10; i++ {
  fmt.Println(i)
}
```

এই লুপটি `1` থেকে `9` পর্যন্ত সংখ্যাগুলো প্রিন্ট করবে (`9` সহ)। উপরের উদাহরণে দেখানো হয়েছে, স্টেপ নির্ধারণ করা হয় সাধারণত একটি ইনক্রিমেন্ট বা ডিক্রিমেন্ট স্টেটমেন্ট দিয়ে।

## হেডারের ঐচ্ছিক কম্পোনেন্ট

হেডারের init আর post কম্পোনেন্ট ঐচ্ছিক:

```go
var sum = 1
for sum < 1000 {
	sum += sum
}
fmt.Println(sum)
// Output: 1024
```

উপরে দেখানো মতো for লুপে init আর post কম্পোনেন্ট বাদ দিলে আপনি Go-তে একটি while লুপ পান। এখানে `while` কিওয়ার্ড বলে কিছু নেই। Go-এর যে নীতি অনুযায়ী কনসেপ্টগুলো পরস্পর অর্থোগোনাল হওয়া উচিত, এটি তার একটি উদাহরণ। যেহেতু while লুপের আচরণ পাওয়ার জন্য ইতিমধ্যেই একটি কনসেপ্ট আছে, সেটি হলো for লুপ, তাই `while`-কে আলাদা কনসেপ্ট হিসেবে যোগ করা হয়নি।

## Break এবং Continue

লুপের বডির ভেতরে আপনি `break` কিওয়ার্ড ব্যবহার করে লুপের এক্সিকিউশন পুরোপুরি থামাতে পারেন:

```go
for n := 0; n <= 5; n++ {
  if n == 3 {
    break
  }
  fmt.Println(n)
}
// Output:
// 0
// 1
// 2
```

এর বিপরীতে, `continue` কিওয়ার্ড শুধু বর্তমান ইটারেশনের এক্সিকিউশন থামায় আর পরের ইটারেশন দিয়ে চালিয়ে যায়:

```go
for n := 0; n <= 5; n++ {
  if n%2 == 0 {
    continue
  }
  fmt.Println(n)
}
// Output:
// 1
// 3
// 5
```

## অসীম for লুপ

লুপ হেডারের শর্ত অংশটিও ঐচ্ছিক। আসলে আপনি হেডার ছাড়াই একটি লুপ লিখতে পারেন:

```go
for {
  // Endless loop...
}
```

এই লুপ কেবল তখনই শেষ হবে, যখন প্রোগ্রামটি বন্ধ হয়ে যায় বা এর বডিতে একটি `break` থাকে।

## লেবেল এবং goto

আমরা যখন `break` ব্যবহার করি, Go সবচেয়ে ভেতরের লুপটি চালানো বন্ধ করে দেয়। একইভাবে, আমরা `continue` ব্যবহার করলে Go সবচেয়ে ভেতরের লুপের পরের ইটারেশনটি চালায়।

তবে এটি সবসময় কাঙ্ক্ষিত নয়। কোন লুপ থেকে বেরিয়ে আসতে চাই আর কোন লুপ চালিয়ে যেতে চাই, তা যথাক্রমে ঠিকঠাক নির্দিষ্ট করতে আমরা `break` ও `continue`-এর সাথে লেবেল ব্যবহার করতে পারি।

এই উদাহরণে আমরা `OuterLoop` নামে একটি লেবেল তৈরি করছি, যা সবচেয়ে বাইরের লুপকে নির্দেশ করবে। সবচেয়ে ভেতরের লুপে আমরা যখন বোঝাতে চাই যে সবচেয়ে বাইরের লুপ থেকে বেরিয়ে আসতে চাই, তখন `break`-এর পরে সবচেয়ে বাইরের লুপের লেবেলের নামটি লিখি:

```go
OuterLoop:
    for i := 0; i < 10; i++ {
        for j := 0; j < 10; j++ {
            // ...
            break OuterLoop
        }
    }
```

`continue`-এর সাথে লেবেল ব্যবহার করলেও কাজ করবে; সেক্ষেত্রে লেবেলটি যে লুপকে নির্দেশ করে, Go সেই লুপের পরের ইটারেশনে চলে যাবে।

Go-তে `goto` কিওয়ার্ডও আছে, যা একইভাবে কাজ করে এবং কোডের এক অংশ থেকে অন্য একটি লেবেল দেওয়া অংশে লাফ দিতে দেয়।

**সতর্কতা:** Go লেবেল দিয়ে চিহ্নিত কোডের অংশে লাফ দেওয়ার সুযোগ দিলেও, ভাষার এই সুবিধাটি ব্যবহার করলে কোডকে সহজেই খুব দুর্বোধ্য করে তোলা যায়। এই কারণেই লেবেল ব্যবহার করা প্রায়ই সুপারিশ করা হয় না।
