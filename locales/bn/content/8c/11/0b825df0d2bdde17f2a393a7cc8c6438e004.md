# কমান্ড ও আর্গুমেন্টের পরিচিতি

এই ট্র্যাকের বিষয় bash-কে ইন্টারঅ্যাকটিভ শেল হিসেবে ব্যবহার করা নয়।
বরং এটি প্রোগ্রামিং ভাষা হিসেবে bash দিয়ে প্রোগ্রাম লেখা শেখার বিষয়ে।

একটি bash প্রোগ্রাম, বা _স্ক্রিপ্ট_, হলো একটি ফাইলে রাখা ধারাবাহিক কমান্ডের সমষ্টি।
bash (এক্সিকিউটেবলটি) ফাইলটি পড়ে আর কমান্ডগুলো ক্রমানুসারে কার্যকর করে।

## শিব্যাং

স্ক্রিপ্টের প্রথম লাইনটি সাধারণত একটি _ইন্টারপ্রেটার ডিরেক্টিভ_, যাকে _হ্যাশব্যাং_ বা _শিব্যাং_-ও বলা হয়:

```bash
#!/usr/bin/env bash
```

অপারেটিং সিস্টেম যখন কোনো নন-বাইনারি ফাইল চালায়, তখন সে ফাইলের প্রথম লাইনটি পড়ে।
লাইনটি যদি `#!` দিয়ে শুরু হয়, তবে কার্নেল সেটি দেখে ঠিক করে ফাইলটি কোন ইন্টারপ্রেটার চালাবে।
`#!` অবশ্যই ফাইলের একেবারে শুরুতে থাকতে হবে, তার আগে কোনো স্পেস বা খালি লাইন থাকতে পারবে না।

এখানে `env` `bash` এক্সিকিউটেবলটির জন্য `PATH`-এ খোঁজে।
আপনি আরও সহজ `#!/bin/bash`-ও দেখতে পারেন, যা ইন্টারপ্রেটারের অবস্থান হার্ডকোড করে দেয়; `env` রূপটি বেশি পোর্টেবল।

~~~~exercism/note
ইন্টারনেটে থাকা যে স্ক্রিপ্ট বা উদাহরণ ইন্টারপ্রেটার হিসেবে `/bin/sh` ব্যবহার করে, সেগুলোতে বিভ্রান্ত হবেন না।
**`sh` আর `bash` এক জিনিস নয়!**
Bash "sh-সামঞ্জস্যপূর্ণ" এবং বেশিরভাগ `sh` স্ক্রিপ্ট চালাতে পারে, তবে bash-এর কিছু বৈশিষ্ট্য `sh`-এ ভেঙে পড়বে বা অপ্রত্যাশিত আচরণ করবে।
~~~~

## কমেন্ট

`#` দিয়ে শুরু হওয়া লাইন হলো _কমেন্ট_, আর bash সেটি এড়িয়ে যায়।
একই লাইনে কমান্ডের পরেও কমেন্ট থাকতে পারে: `#` থেকে লাইনের শেষ পর্যন্ত সবকিছু এড়িয়ে যাওয়া হয়।
কমেন্ট থাকে স্ক্রিপ্ট পড়া মানুষের জন্য।

## শব্দ ও আর্গুমেন্ট

Bash তার ইনপুট (যা সাধারণত একটি টার্মিনাল বা একটি ফাইল) থেকে কমান্ড পড়ে।
সে যে ইনপুট লাইনই পড়ে, তাকে একটি _কমান্ড_ হিসেবে ধরা হয়, অর্থাৎ একটি নির্দেশ যা পালন করতে হবে।
(কয়েকটি অ্যাডভান্সড কেস আছে, যেমন একাধিক লাইনজুড়ে বিস্তৃত কমান্ড, যা পরে আলোচনা করা হবে।)

Bash প্রতিটি কমান্ডকে **শব্দে** ভাগ করে, যেগুলোকে হোয়াইটস্পেস ক্যারেক্টার (স্পেস ও ট্যাব) দিয়ে আলাদা করা হয়।
প্রথম শব্দটি হলো যে _কমান্ড_ কার্যকর হবে তার নাম।
বাকি সব শব্দ ওই কমান্ডের _আর্গুমেন্ট_ হয়ে যায় (অপশন, ফাইলের নাম ইত্যাদি)।

একটি কমান্ড হতে পারে bash _বিল্টইন_, যেমন `echo`, অথবা একটি _এক্সিকিউটেবল_ প্রোগ্রাম, যেমন `head`, `awk` বা `sed`।

## `echo` কমান্ড

`echo` তার আর্গুমেন্টগুলো একটি স্পেস দিয়ে আলাদা করে ছাপায়, আর শেষে একটি নিউলাইন দেয়:

```bash
echo flour sugar eggs
```

আউটপুট:

```text
flour sugar eggs
```

আর্গুমেন্টের মাঝে কতটা হোয়াইটস্পেস থাকছে, তা কোনো ব্যাপারই নয়:

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

কোনো আর্গুমেন্ট ছাড়া `echo` কল করলে একটি খালি লাইন ছাপা হয়।

## অপশন মানে আসলে আর্গুমেন্ট

অনেক কমান্ড _অপশন_ নেয়, যা তাদের আচরণ বদলে দেয়।
bash-এর কাছে অপশন বিশেষ কিছু নয়: এটি অন্য যেকোনো শব্দের মতোই, যা হোয়াইটস্পেস দিয়ে তার পাশের শব্দ থেকে আলাদা করা হয়।
কমান্ড নিজেই ঠিক করে তার আর্গুমেন্টগুলো কীভাবে ব্যাখ্যা করবে।
প্রথা অনুযায়ী, অপশন `-` দিয়ে শুরু হয়।

`head` কমান্ড একটি ফাইলের প্রথম কয়েকটি লাইন ছাপায়।
ধরা যাক, `list.txt` নামের একটি ফাইল আছে:

```bash
head -n 2 list.txt
```

Bash এই লাইনটিকে চারটি শব্দে ভাগ করে:

| শব্দ | ভূমিকা |
| ---------- | ------------------------------------------- |
| `head` | যে কমান্ডটি চালাতে হবে |
| `-n` | একটি অপশন, যা `head`-কে _লাইন_ গুনতে বলে |
| `2` | `-n` অপশনের মান |
| `list.txt` | যে ফাইলটি পড়তে হবে |

Bash শেষের তিনটি শব্দ অপরিবর্তিতভাবে `head`-কে পাঠায়।
`head` নিজেই বোঝে যে `-n`-এর পরে একটি সংখ্যা আসে, আর বাকি শব্দটি একটি ফাইল।

যেহেতু হোয়াইটস্পেসই শব্দগুলোকে আলাদা করে, তাই এটি কোথায় বসাচ্ছেন সেটি গুরুত্বপূর্ণ।
`head -n 2` `head`-কে দুটি আর্গুমেন্ট দেয় (`-n` আর `2`), আর `head -n2` দেয় একটি (`-n2`)।
অনেক কমান্ডই দুটি রূপই নেয়, তবে সেটি কমান্ডের উপর নির্ভর করে।
Bash-এর কিছু যায় আসে না; সে কেবল লাইনটিকে শব্দে ভাগ করে।

## আর্গুমেন্ট কোট করা

[কোট চিহ্ন][Quotes] শব্দগুলোকে একটি _একক আর্গুমেন্টে_ পরিণত করে।
কোটের ভেতরের হোয়াইটস্পেস অপরিবর্তিত থাকে, আর কোট চিহ্নগুলো নিজে আর্গুমেন্টের অংশ নয়:

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

যদি কোনো আর্গুমেন্ট, যেমন ফাইলের নাম, হোয়াইটস্পেস ধারণ করে, তবে সেটি কোটের মধ্যে রাখুন:

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## স্ক্রিপ্ট চালানো

স্ক্রিপ্ট চালাতে হলে সেটি `bash` কমান্ডে একটি আর্গুমেন্ট হিসেবে পাঠান:

```bash
bash myscript
```

এভাবে ব্যবহার করলে `#!` লাইনটি কেবল একটি কমেন্ট।
আপনি অপারেটিং সিস্টেমকে বলে দিচ্ছেন ফাইলটি কীভাবে চালাতে হবে।

বিকল্পভাবে, স্ক্রিপ্ট ফাইলটিকে এক্সিকিউটেবল হিসেবে চিহ্নিত করুন আর অন্য যেকোনো প্রোগ্রামের মতোই এটি চালান:

```bash
chmod +x myscript
./myscript
```

এখন অপারেটিং সিস্টেম `#!` লাইন দেখে ঠিক করে কোন ইন্টারপ্রেটার ব্যবহার করবে।
