# সম্পর্কে

Factor-এ ডেটা পাঠানোর একমাত্র প্রথা হল *ডেটা স্ট্যাক*: ওয়ার্ডগুলো তাদের ইনপুট পপ করে আর তাদের আউটপুট পুশ করে। প্রতিটি ওয়ার্ড ডেফিনিশন একটি *স্ট্যাক ইফেক্ট* ঘোষণা করে, যা সেই চুক্তিটি লিখে রাখে।

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

`( … -- … )`-এর ভেতরের নামগুলো পাঠকের সুবিধার জন্য; কম্পাইলার কিন্তু যাচাই করে ইনপুট ও আউটপুটের *সংখ্যা*। গরমিল হলে সেটি একটি কম্পাইল-টাইম এরর, আর এভাবেই এমন এক শ্রেণির বাগ ধরা পড়ে যা এই ধরনের ঘোষণা ছাড়া একটি ডাইনামিক্যালি টাইপড ভাষায় রানটাইম এরর হয়ে দাঁড়াত।

যেহেতু স্ট্যাকটি অবস্থানভিত্তিক, পরের ওয়ার্ডটি রান করার আগে আপনাকে বারবার তার ওপরের অংশটুকু সাজিয়ে নিতে হয়। `kernel`-এর **শাফল ওয়ার্ড**গুলো ঠিক এই কাজটিই করে:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

পুরো শাফল পরিবারটি এগুলোকে আরও বাড়ায়: `-rot` (উল্টো দিকে রোল করা), `d` প্রত্যয়যুক্ত আত্মীয়গুলো যেগুলো আরও এক ধাপ গভীরে কাজ করে (`dupd`, `swapd`), `2` উপসর্গযুক্ত আত্মীয়গুলো যেগুলো জোড়ার ওপর কাজ করে (`2dup`, `2drop`, `2nip`), আর `pick` ও `tuck`-এর মতো আরও কিছু। পরের অনুশীলনীগুলোর যেখানে দরকার, সেখানেই এগুলো এসে পড়ে; একসাথে অনেকগুলো শাফল ওয়ার্ড ব্যবহার করতে যাওয়াটা সাধারণত ইঙ্গিত দেয় যে একটি *লোকাল* (নামযুক্ত মান) ব্যবহার করলে কোডটি আরও ভালোভাবে পড়া যেত।

প্রথা অনুযায়ী, ওয়ার্ডের নামে `lowercase-kebab-case` ব্যবহার করা হয়, প্রেডিকেটের নাম `?` দিয়ে শেষ হয় আর সেগুলো একটি বুলিয়ান উৎপন্ন করে (`even?`, `empty?`), সেটার লেখা হয় `>>name` আর গেটার `name>>`, এবং একটি ওয়ার্ড ও তার পরিবর্তনকারী রূপ প্রায়ই একই নাম ভাগ করে নেয়, যাদের আলাদা করা যায় কেবল প্রসঙ্গ দিয়ে।
