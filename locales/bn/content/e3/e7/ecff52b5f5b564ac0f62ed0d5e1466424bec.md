# পরিচিতি

আমাদের প্রোগ্রামে নিজস্ব টাইপ ডিফাইন করা প্রায়ই কাজে লাগে।

নতুন প্রিমিটিভ টাইপ তৈরি করা সম্ভব, তবে খুব একটা করা হয় না।
বিল্ট-ইন প্রিমিটিভ টাইপগুলো খেয়ালখুশিমতো বাছা হয়নি: JIT কম্পাইলেশনের জন্য Julia যে LLVM কম্পাইলার ব্যবহার করে, তার স্ট্যান্ডার্ড টাইপগুলোর সাথে এগুলো বেশ ভালোভাবে মেলে।

আরও অনেক বেশি কাজে লাগে কম্পোজিট টাইপ ডিফাইন করার সুবিধা, যেখানে নামযুক্ত ফিল্ড থাকে।

অন্য ভাষাতেও এরকম কিছু আছে, সেগুলোকে `structs` বা `records` বলা হয়।
Julia-র ডকুমেন্টেশনে অবশ্য এদের `composite types` বলা হয়, যদিও (একটু অমিল রয়ে গেছে) ভাষার সিনট্যাক্সে এগুলো `struct` কিওয়ার্ড দিয়ে ডিফাইন করা হয়।

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

উপরের উদাহরণে কয়েকটি বিষয় খেয়াল করার মতো:

- `id`-এর জন্য কোনো টাইপ উল্লেখ করা হয়নি, তাই কম্পাইলার এটিকে `id::Any` হিসেবে ধরে নেয়।
  - বাস্তবে সবচেয়ে ভালো হয় ফিল্ডের টাইপ একটি কনক্রিট টাইপ হিসেবে উল্লেখ করে কম্পাইলারকে সাহায্য করা
- টাইপের নামটিই কনস্ট্রাক্টর হিসেবে ব্যবহার হয়, যেমন `Person(id, name, age)`, যা `Person` টাইপের একটি ইনস্ট্যান্স দেয়।
- আলাদা আলাদা ফিল্ড ডট নোটেশন দিয়ে অ্যাক্সেস করা যায়, নামযুক্ত টাপলের মতোই।

`Person` টাইপের মানগুলো ইমিউটেবল, তাই সেগুলো আপডেট করা যায় না।

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

পরিবর্তনযোগ্যতা প্রয়োজন হলে ডিফিনিশনে `mutable` যোগ করুন।

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

ডিফল্টভাবে কনস্ট্রাক্টরটি চায় ফিল্ডগুলো ডিফিনিশনের মতো একই ক্রমে থাকুক, আর জটিল টাইপের ক্ষেত্রে এটা অসুবিধাজনক হয়ে দাঁড়ায়।

`@kwdef` ম্যাক্রো ব্যবহার করলে দুটি নতুন সুবিধা পাওয়া যায়:

- কনস্ট্রাক্টরটি অবস্থান নয়, কিওয়ার্ড ব্যবহার করে।
- ফিল্ডের ডিফল্ট মান থাকতে পারে, আর চাইলে সেগুলো কনস্ট্রাক্টর থেকে বাদও দেওয়া যায়।

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## কম্পোজিট টাইপ হায়ারার্কি

এখন পর্যন্ত আমরা শুধু কনক্রিট কম্পোজিট টাইপ তৈরি করেছি।
খেয়াল করলে দেখা যাবে, সবগুলোই `Any`-এর সাবটাইপ।

একসাথে সম্পর্কিত একাধিক টাইপ তৈরি করার সময় এদের জন্য একটি হায়ারার্কি ডিফাইন করাই সম্ভবত বেশি যুক্তিসঙ্গত।
এটা করা খুবই সহজ।

প্রথমে একটি অ্যাবস্ট্রাক্ট টাইপ তৈরি করুন:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

এরপর টাইপ ডিফিনিশনে একটি `<:` অপারেটর যোগ করুন, যাতে সম্পর্কটা বোঝা যায়।

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

যতবার দরকার ততবার পুনরাবৃত্তি করুন, তবে মনে রাখবেন কনক্রিট টাইপের সাবটাইপিং অনুমোদিত নয়।

আরও জটিল হায়ারার্কির জন্য প্রয়োজন অনুযায়ী অ্যাবস্ট্রাক্ট সাবটাইপ তৈরি করুন।

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

এরকম একটি হায়ারার্কির উপকারিতা আরও স্পষ্ট হবে যখন আমরা `Multiple Dispatch` কনসেপ্টে পৌঁছাব, আর দেখব কীভাবে ফাংশন আর্গুমেন্টের টাইপগুলো সামলায়।
