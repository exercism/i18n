# পরিচিতি

বহু অবজেক্ট-ওরিয়েন্টেড ভাষায়, একটি প্যারেন্ট ক্লাসের [সাবক্লাস বানিয়ে][wiki-subclass] বিহেভিয়ার বাড়ানো খুব কমন ব্যাপার, যেখানে প্যারেন্ট থেকে মেথড ইনহেরিট হয়, আবার নতুন মেথডও যোগ করা যায়।
এভাবেই আমরা একটি অবজেক্ট হায়ারার্কি পাই।

Julia-এর _ক্লাস নেই_, তাই স্বাভাবিকভাবেই এর _সাবক্লাসও নেই_।
তাহলে আমরা কীভাবে আগে থেকে থাকা বিহেভিয়ার ইনহেরিট ও বাড়াব?

আগের ধারণাগুলোতে আমরা দেখেছি কীভাবে একটি টাইপ হায়ারার্কি তৈরি করতে হয়, আর শিখেছি কীভাবে Julia [মাল্টিপল ডিসপ্যাচ][concept-multiple-dispatch] ব্যবহার করে আর্গুমেন্টের টাইপ দেখে মেথড বেছে নেয়।

Julia-এর বেশ কিছু ইনফরমাল ইন্টারফেসও আছে, যেগুলো দিয়ে আপনার কাস্টম টাইপ স্ট্যান্ডার্ড টাইপের জন্য আগেই ডিফাইন করা বিহেভিয়ারের সাথে যুক্ত হতে পারে।

ইটারেটর ইন্টারফেস দিয়ে এটা সবচেয়ে সহজে বোঝানো যায়।

## ইটারেটর

পাঠ্যক্রমের আগের অংশে আমরা দেখেছি, Julia একটি কালেকশনের প্রতিটি এলিমেন্টের উপর কয়েকভাবে কাজ করতে পারে।

- [লুপ][concept-loops], যেমন `for item in items...`
- [ব্রডকাস্টিং][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [হায়ার-অর্ডার ফাংশন][concept-hof]: `map(√, [1, 4, 9])`
- [কম্প্রিহেনশন][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [জেনারেটর][concept-comprehensions]: `(x^2 for x in 1:1e6)`, যা লেজি ইভ্যালুয়েশন করে।

স্পষ্টতই, Julia স্ট্যান্ডার্ড কালেকশনগুলোর ভেতর দিয়ে এক এক করে ঘুরতে জানে: উপরের উদাহরণগুলোতে ভেক্টর আর রেঞ্জ, আরও আছে Set, Dict ইত্যাদি।

আমাদের নিজের কাস্টম কালেকশনে এই ক্ষমতাটা কীভাবে যোগ করব, বিশেষ করে যদি সেগুলো জেনারেটরের মতো লেজি ইটারেশন করতে পারে?

### ন্যূনতম যা যা দরকার

ইটারেশনের জন্য একটি সিকোয়েন্স বানাতে আমাদের (অন্তত) দুটি জিনিস দরকার:

1. _প্রথম_ এলিমেন্ট পাওয়ার একটি উপায়।
2. এখনকার স্টেট থেকে _পরের_ এলিমেন্ট পাওয়ার একটি উপায়।

Julia এই কাজগুলো করে `Base.iterate()` ফাংশনের মেথড দিয়ে, নিচের ধাপে ধাপে:

1. প্রথমে `Base.iterate(iter)` স্বয়ংক্রিয়ভাবে কল হয়।
    - ইটারেট করার মতো কিছু না থাকলে `nothing` রিটার্ন করে।
    - নাহলে প্রথম রিটার্ন করা এলিমেন্ট আর প্রথম স্টেটের `Tuple` রিটার্ন করে: `(firstitem, firststate)`.
2. আগের ইটারেশনে কোনো এলিমেন্ট রিটার্ন হলে `Base.iterate(iter, state)` স্বয়ংক্রিয়ভাবে কল হয়, আর তার `state` আর্গুমেন্ট হিসেবে পায় `firststate`।
    - ইটারেশন শেষ হয়ে গেলে `nothing` রিটার্ন করে।
    - নাহলে পরের এলিমেন্ট আর পরের স্টেটের `Tuple` রিটার্ন করে: `(nextitem, nextstate)`.
3. শেষ না হওয়া পর্যন্ত ধাপ ২ বার বার চলে।

এই ধাপগুলো সব "ভেতরে ভেতরে" হয়, মানে মেথড কল আর স্টেট ইটারেশন প্রোটোকল নিজেই সামলায় (স্টেট থাকে লুকানো), আর উচ্চ-স্তরের কনস্ট্রাক্ট, যেমন লুপ, শুধু এলিমেন্টটাই দেখতে পায়।
অন্য কথায়, আমরা কেবল `item`-টাই দেখি, বাকি সব থাকে একটি ব্ল্যাক বক্সের ভেতরে।

এখানে মূল ভূমিকায় আছে [মাল্টিপল ডিসপ্যাচ][concept-multiple-dispatch]।
`iter`-এর টাইপ ঠিক করে কোন মেথডগুলো কল হবে, আর আর্গুমেন্টের সংখ্যা ঠিক করে প্রথম না পরের এলিমেন্ট রিটার্ন হবে।

স্ট্যান্ডার্ড টাইপগুলোর জন্য মেথড আগেই ডিফাইন করা আছে: `Vector`, `Range`, `Set` ইত্যাদি ([বর্তমানে][ref-iterations-collections] মোট ১৪টি টাইপ)।

একটি কাস্টম `MyType` যাতে একই বিহেভিয়ার পায়, তার জন্য প্রথমে আমাদের ডিফাইন করতে হবে:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

শুনতে হয়তো সবটা খুব জটিল লাগছে, কিন্তু বাস্তবে এটা বেশ সহজ হতে পারে।
বোঝার সুবিধার জন্য ধরে নিন, আমরা এমন একটি টাইপ চাই যা একটি নির্দিষ্ট ইন্টিজার `n`-এর ঘাতগুলো দেবে, একটা সর্বোচ্চ সংখ্যা পর্যন্ত।

প্রথমে একটি কাস্টম টাইপ ডিফাইন করুন:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

এবার আমরা এই টাইপের জন্য `iterate` মেথডগুলো ডিফাইন করতে পারি, কিন্তু প্রথম এলিমেন্ট আর প্রথম স্টেট কী?

প্রথম এলিমেন্ট পেতে কিছু ইটারেটরের জটিল সেটআপ লাগে, কিন্তু এই ছোট উদাহরণে খেয়াল করুন, প্রথমে যে এলিমেন্টটা রিটার্ন হয় সেটা আসলে বেস সংখ্যাটাই, তাই আমাদের শুধু দেখতে হবে `count`-এর মান একের সমান বা তার চেয়ে বড় কি না।

এবার প্রথম স্টেটের কথা ভাবি, যেটা নিজের ভেতরে তথ্য বহন করে যা পরের ইটারেশনে কাজে লাগে।
এটা করার জন্য কোন তথ্য মনে রাখতে হবে, সেটা ঠিক করার দায়িত্ব আপনার, আর সেটা যেকোনো টাইপের হতে পারে।

এই ক্ষেত্রে আমরা শুধু "index"-টা মনে রাখতে পারি যেটা দিয়ে `n`-কে ঘাতে উন্নীত করা হয়, অথবা আরও ভালো পারফরম্যান্সের উপায় বের করতে পারি, যা সাম্প্রতিকতম ঘাতটি (অর্থাৎ রিটার্ন করা এলিমেন্ট) আর সিকোয়েন্সের পরের "index" ব্যবহার করে।
এই দুটি সংখ্যা একটি `Tuple`-এ মুড়ে `state` হিসেবে রিটার্ন করা যায়।

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

এই উদাহরণে প্রথম এলিমেন্ট (`p.n`) লুপে রিটার্ন হয়, আর প্রথম স্টেট `(p.n, 2)` পাস হয় `iterate(P::Powers, state)` মেথডে।
সেখানে আমরা স্টেট প্রক্রিয়া করে পরের এলিমেন্ট বানাতে পারি, বর্তমান এলিমেন্টকে বেস সংখ্যা দিয়ে গুণ করে, ফলে এর ঘাত `1` বেড়ে যায়।

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

index-এর মান যদি এখনও `count`-এর ভেতরে থাকে, তাহলে `next` এলিমেন্ট আর বাড়ানো স্টেট `Tuple` নিয়ে `Tuple` রিটার্ন হয়।
আর যখন `index`-এর মান `count` ছাড়িয়ে যায়, তখন বদলে `nothing` রিটার্ন হয়, যা বোঝায় ইটারেশন শেষ।

খেয়াল করে থাকবেন হয়তো, `iterate(p::Powers)` আর `iterate(p::Powers, state)` মেথড দুটির ফাংশন বডি মোটামুটি একই রকম।
আসলে একটু বুদ্ধি খাটালে এই মিলের সুবাদে আমরা শুধু দুটি আর্গুমেন্টের ভার্সনটাই ব্যবহার করে, স্টেটের জন্য একটি ডিফল্ট আর্গুমেন্ট দিয়ে, সরল একটা ইমপ্লিমেন্টেশন লিখতে পারি: `Base.iterate(p::Powers, state=(1, 1))`
এটা থাকলে আমাদের আলাদা করে একটি আর্গুমেন্টের `iterate(p::Powers)` লাগবে না।
বাস্তবে যেখানে সম্ভব, এটা করাই কমন।

এখন পর্যন্ত আমরা বেশ কিছু কাজের সুবিধা পেয়ে গেছি: 3-এর প্রথম ৪টি ঘাতের জন্য আমরা ফলাফলগুলোর ভেতর দিয়ে লুপ করতে পারি, কোনো সংখ্যা ফলাফলে আছে কি না দেখতে পারি, আর `sum()`-এর মতো অ্যাগ্রিগেট ফাংশন প্রয়োগ করতে পারি।

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### আরও মেথড

ভালো শুরু হলেও এখনও সবকিছু কাজ করে না।

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

ঠিক যেমন ভাবছেন, `length(Powers(3, 4))`-ও একই এরর মেসেজ দেয়।

এটা সহজেই ঠিক করা যায়, কারণ length টাইপ কনস্ট্রাক্টরেরই অংশ: এই ক্ষেত্রে ৪।
আমাদের শুধু এই টাইপের জন্য `Base.length()` ডিফাইন করতে হবে, তারপরই সিকোয়েন্সে কম্প্রিহেনশন আর `collect()` ব্যবহার করতে পারব।

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

দক্ষতার জন্য `Base.eltype()`-ও ডিফাইন করা ভালো: এটা ফলাফলের এলিমেন্ট টাইপ।
এতে `collect()`-এর মতো ফাংশন আগেই আউটপুট `Vector{Int}`-এর জন্য জায়গা বরাদ্দ করতে পারে, বার বার একটি `Vector{Any}`-এ `push!()` করার বদলে।

সিনট্যাক্সটা খেয়াল করুন, আগে হয়তো দেখেননি: এই মেথডটি ডিফাইন করা হয় টাইপের _উপর_, টাইপের কোনো _ইনস্ট্যান্সের_ উপর নয়।

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

ইটারেটরের সসীম length থাকা _বাধ্যতামূলক_ নয়।
"অসীম" সিকোয়েন্সের ব্যবহার বেশি সীমিত, তবে লুপ থেকে `break` করে বেরোনোর কোনো উপায় থাকলে ওগুলোর ভেতর দিয়ে লুপ করা কাজে লাগতে পারে।
উদাহরণস্বরূপ, আমরা `Powers`-এর একটি ভ্যারিয়েন্ট ডিফাইন করতে পারি যা একটি নির্দিষ্ট সীমার চেয়ে ছোট মান তৈরি করে (হতে পারে `typemax(Int)`, ইন্টিজার ওভারফ্লো এড়াতে)।

## সারসংক্ষেপ

ইন্টারফেস ব্যাখ্যা করা বেশ বিভ্রান্তিকর, কারণ Julia-র পদ্ধতি অন্য বেশিরভাগ ভাষার থেকে অনেক আলাদা।
বিশেষ করে, ইমপ্লিমেন্টেশনে ইন্টারফেসের নামটা কখনোই উল্লেখ না-ও থাকতে পারে: যা [সাবক্লাসিং][wiki-subclass] বা [মিক্সিন][wiki-mixins] থেকে একেবারেই আলাদা।

তবুও বাস্তবে এগুলো অবাক করার মতোই সহজ:

1. উপযুক্ত একটি টাইপ ডিফাইন করুন।
2. কোন মেথডগুলো দরকার, তা খুঁজে বের করুন।
3. আপনার কাস্টম টাইপের জন্য ওই মেথডগুলো ইমপ্লিমেন্ট করুন; সাধারণত মাত্র কয়েকটি মেথড, আর সেগুলো বেশ ছোট ও সহজ।
4. বাকিটা [মাল্টিপল ডিসপ্যাচ][concept-multiple-dispatch] নিজেই স্বয়ংক্রিয়ভাবে সামলে নেবে।
