# কোটিং পরিচিতি

নতুন bash প্রোগ্রামাররা বারবার যে পরামর্শটি শুনবেন:

> ভ্যারিয়েবলগুলো কোট করুন!

কেন এমন?

কোনো ভ্যারিয়েবল (যেমন `$name`) এক্সপ্যান্ড করলে আপনি প্রায় সবসময়ই ভ্যারিয়েবলটির _মান_-কে একটি একক স্ট্রিং (বা সংখ্যা) হিসেবে ব্যবহার করতে চান।
আপনি চান না যে মানটি অপ্রত্যাশিতভাবে দুই বা তার বেশি আলাদা স্ট্রিং হিসেবে গণ্য হোক।

## কোটিং

কোনো একটি টেক্সটকে একক শব্দ হিসেবে গণ্য করার প্রধান উপায় হলো কোটিং।
কোটের দুটি প্রধান ধরন আছে।

### ডাবল কোট

ডাবল কোটের ভেতরে প্যারামিটার এক্সপ্যানশন, অ্যারিথমেটিক এক্সপ্যানশন এবং কমান্ড সাবস্টিটিউশন কাজ করে।

```bash
echo "This is bash version $BASH_VERSION"
```

একটি ডাবল-কোটেড স্ট্রিংয়ের ভেতরে লিটারেল ডাবল কোট বসাতে চাইলে তার আগে একটি ব্যাকস্ল্যাশ দিন।

```bash
echo "She said \"Let me teach you about bash.\""
```

### সিঙ্গেল কোট

সিঙ্গেল কোটের ভেতরে কোনো এক্সপ্যানশনই _অনুমতি পায় না_।

```bash
echo 'This is bash version $BASH_VERSION'
# ...^..................................^
# prints exactly: This is bash version $BASH_VERSION
```

সিঙ্গেল-কোটেড স্ট্রিংয়ের ভেতরে একটি সিঙ্গেল কোট বসানো _সম্ভব নয়_।

## কোট করার গুরুত্ব

`echo $name` দিয়ে ঠিক কী সমস্যা?

শেল যখন কোডের একটি লাইন পার্স করে, তখন সে ধারাবাহিকভাবে [বিভিন্ন ধরনের এক্সপ্যানশন][expansions] চালায়।
শেষের দিকের দুটি এক্সপ্যানশন হলো _ওয়ার্ড স্প্লিটিং_ এবং _ফাইলনেম এক্সপ্যানশন_।

### ওয়ার্ড স্প্লিটিং

প্যারামিটার এক্সপ্যানশন, কমান্ড সাবস্টিটিউশন বা অ্যারিথমেটিক এক্সপ্যানশনের যে ফলাফলগুলো _ডাবল কোটের ভেতরে তৈরি হয়নি_, সেগুলোতে "ওয়ার্ড স্প্লিটিং" ঘটতে পারে।
শেল এক্সপ্যান্ড হওয়া ফলাফলটি নিয়ে, `$IFS`-এর মানে থাকা যেকোনো ধারাবাহিক ক্যারেক্টারের উপর সেটি ভাগ করে।
ডিফল্টভাবে এগুলো হলো স্পেস, ট্যাব এবং নিউলাইন।

শেল লুপ ব্যবহার করে এটি কাজ করতে দেখা যায়:

```bash
sentence="The quick brown fox jumps."
i=0
for word in "$sentence"; do echo "$((++i)) $word"; done
# ..........^.........^
```
আউটপুট:
```none
1 The quick brown fox jumps.
```

কিন্তু কোট না করলে:

```bash
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
আউটপুট:
```none
1 The
2 quick
3 brown
4 fox
5 jumps.
```

চলুন `$IFS`-এর একটি ভিন্ন মান দিয়ে এটি দেখি:

```bash
csv="first,second,third"
IFS=","
for word in $csv; do echo "$word"; done
```
আউটপুট:
```none
first
second
third
```

#### ওয়ার্ড স্প্লিটিং বন্ধ করা

ওয়ার্ড স্প্লিটিং বন্ধ করার একটি কৌশল হলো `$IFS`-কে একটি খালি স্ট্রিংয়ে সেট করা

```bash
sentence="The quick brown fox jumps."
IFS=    # or explicitly, IFS=""
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
আউটপুট:
```none
1 The quick brown fox jumps.
```

তবে, ফাইলনেম এক্সপ্যানশনও বন্ধ না করলে ভ্যারিয়েবল কোট না করে রাখা সুপারিশ করা হয় না।
কীভাবে করবেন তা নিচে দেখব।

### ফাইলনেম এক্সপ্যানশন

"গ্লব" প্যাটার্ন দিয়ে ফাইলের একটি সেটের সাথে মেলার জন্য সংক্ষিপ্ত প্যাটার্ন প্রকাশ করা হয়।
উদাহরণস্বরূপ, আপনি `*.md` দিয়ে একটি ডিরেক্টরির সব Markdown ফাইলের সাথে মিল করতে পারেন।
[গ্লব প্যাটার্ন][glob] ইউনিক্স আবিষ্কারের পর থেকেই আছে।

গ্লবের ওয়াইল্ডকার্ড ক্যারেক্টারগুলো হলো:

* `*` যেকোনো ক্যারেক্টারের শূন্য বা তার বেশি সংখ্যার সাথে মেলে,
* `?` যেকোনো ক্যারেক্টারের ঠিক একটির সাথে মেলে,
* `[...]` বন্ধনীর ভেতরে তালিকাভুক্ত ক্যারেক্টারগুলোর সেট থেকে ঠিক একটি ক্যারেক্টারের সাথে মেলে।

   ~~~~exercism/advanced
   <details><summary>
   ক্যারেক্টার সেট সম্পর্কে বিস্তারিত অনেক কিছু আছে।
   দেখতে এখানে ক্লিক করুন।
   </summary>

    * `[abc]` ঠিক একটি ক্যারেক্টারের সাথে মেলে, যেটি `a` বা `b` বা `c`-এর একটি।
        * এক্সপ্রেশনে একটি লিটারেল ক্লোজ ব্র্যাকেট রাখতে চাইলে এটিকে ওপেনিং ব্র্যাকেটের পরে (ঐচ্ছিক `^`-এর পরে) প্রথম ক্যারেক্টার বানান
            * `[][]` হলো এমন একটি ক্যারেক্টার সেট, যা ক্লোজ বা ওপেন ব্র্যাকেটের যেকোনোটির সাথে মেলে।
            * অথবা ব্যাকস্ল্যাশ দিয়ে এস্কেপ করুন: `[[\]]`
    * `[x-y]` ঠিক একটি ক্যারেক্টারের সাথে মেলে, যেটি `x` থেকে `y` পর্যন্ত _রেঞ্জ_-এর মধ্যে।
        * ক্যারেক্টার সেটে একটি লিটারেল হাইফেন ক্যারেক্টার রাখতে চাইলে সেটি হতে হবে ওপেনিং ব্র্যাকেটের পরে (ঐচ্ছিক `^`-এর পরে) প্রথম ক্যারেক্টার, অথবা ক্লোজিং ব্র্যাকেটের আগে শেষ ক্যারেক্টার।
            * `[-xy]` বা `[xy-]` প্রত্যেকে ঠিক একটি ক্যারেক্টারের সাথে মেলে, যেটি `-` বা `x` বা `y`-এর একটি
            * অথবা ব্যাকস্ল্যাশ দিয়ে এস্কেপ করুন: `[x\-y]`
        * একাধিক রেঞ্জ নির্দিষ্ট করা যায়, উদাহরণস্বরূপ `[0-9A-Fa-f]` একটি হেক্সাডেসিমাল ডিজিটের সাথে মেলে
    * `[^abc]` ঠিক একটি ক্যারেক্টারের সাথে মেলে, যেটি `a` বা `b` বা `c` **নয়**,
    * `[^x-y]` ঠিক একটি ক্যারেক্টারের সাথে মেলে, যেটি `x` থেকে `y` পর্যন্ত রেঞ্জে **নেই**
    * `[[:character_class:]]` নামকৃত "character_class"-এর মধ্যে থাকা একটি ক্যারেক্টারের সাথে মেলে
        * যে ক্যারেক্টার ক্লাসগুলো পাওয়া যায় সেগুলো হলো:
            * `lower` -- ছোট হাতের অক্ষর
            * `upper` -- বড় হাতের অক্ষর
            * `alpha` -- অক্ষর
            * `digit` -- ডিজিট
            * `alnum` -- অক্ষর ও ডিজিট
            * `space` -- হোয়াইটস্পেস
            * `blank` -- অনুভূমিক হোয়াইটস্পেস (স্পেস ও ট্যাব)
            * `xdigit` -- হেক্সাডেসিমাল ডিজিট
            * `word` -- একটি আইডেন্টিফায়ারে অনুমোদিত ক্যারেক্টার (অক্ষর, সংখ্যা, আন্ডারস্কোর)
            * `punct` -- যতিচিহ্ন
            * `cntrl` -- কন্ট্রোল ক্যারেক্টার
            * `graph` -- "দৃশ্যমান" ক্যারেক্টার
            * `print` -- দৃশ্যমান ক্যারেক্টার ও স্পেস
        * এগুলো একসাথে ব্যবহার করা যায়:
            * `[[:alpha:]]` ক্লাসটি `[[:lower:][:upper:]]` নিয়ে গঠিত
            * `[[:alnum:]]` ক্লাসটি `[[:alpha:][:digit:]]` নিয়ে গঠিত
            * `[[:word:]]` ক্লাসটি `[[:alnum:]_]` নিয়ে গঠিত
            * আন্ডারস্কোর (অক্টাল ১৩৭) একইসাথে `[[:word:]]` এবং `[[:punct:]]`
            * `[[:graph:]]` ক্লাসটি `[[:alnum:][:punct:]]` নিয়ে গঠিত
            * `[[:print:]]` ক্লাসটি `[[:graph:] ]` নিয়ে গঠিত -- শুধু স্পেস (অক্টাল ০৪০), অন্য কোনো হোয়াইটস্পেস নয়।
   </details>

#### ফাইলের একটি তালিকার উপর ইটারেশন

`for` লুপ দিয়ে ফাইলের একটি তালিকার উপর ইটারেশন করতে পারেন

```bash
for file in *.csv; do
    do_something_with "$file"
done
```

লক্ষ্য করুন, `"$file"` ভ্যারিয়েবলটি কোট করা আছে।
গ্লব প্যাটার্ন এমন ফাইলও ফেরত দিতে পারে যাদের নামে স্পেস আছে।
আমাদের ভ্যারিয়েবলটি কোট করতে হবে, যাতে `do_something_with` কমান্ডটি ঠিক একটি আর্গুমেন্ট পায়, যা হলো ফাইলের নাম।

#### গ্লব প্যাটার্ন কোনো রেগুলার এক্সপ্রেশন নয়

গ্লব প্যাটার্ন **রেগুলার এক্সপ্রেশন নয়**।

* ঠিক একটি ক্যারেক্টারের সাথে মেলে
   * regex `.`
   * glob `?`
* শূন্য বা তার বেশি ক্যারেক্টারের সাথে মেলে
   * regex `.*`
   * glob `*`
        * গ্লব প্যাটার্ন `.*` মানে "এমন একটি ফাইলনেমের সাথে মিল, যার প্রথম ক্যারেক্টার একটি লিটারেল ডট এবং তার পরে শূন্য বা তার বেশি যেকোনো ক্যারেক্টার"।
* এক বা তার বেশি ক্যারেক্টারের সাথে মেলে
   * regex `.+`
   * glob `?*`
* regex ক্যারেক্টার সেট আর গ্লব ক্যারেক্টার সেট একইভাবে কাজ করে।

#### কোটিং ও ফাইলনেম এক্সপ্যানশন

কখনো কখনো আপনি ফাইলনেম এক্সপ্যানশন দমন করতে চাইবেন।
ইউজার ইনপুট হ্যান্ডল করা এমনই একটি সময়।
এই কোড স্নিপেটটি দেখুন

```bash
read -p "Enter something: " user_input
echo $user_input
```

ইউজার যদি একটি অ্যাস্টেরিস্ক (`*`) লেখেন, তাহলে আউটপুট কী আসবে?
বর্তমান ডিরেক্টরির ফাইলের তালিকা।
সম্ভবত আপনি সেটিই করতে চান না।

আরেকটি উদাহরণ হলো, প্যাটার্ন প্রত্যাশা করে এমন প্রোগ্রামে আর্গুমেন্ট হিসেবে প্যাটার্ন পাঠানো।
`tr` প্রোগ্রামটি প্রায়ই টেক্সট ম্যানিপুলেশনের জন্য ব্যবহৃত হয়। একটি ভ্যারিয়েবলের মানকে ছোট হাতের অক্ষরে করতে চাইলে এভাবে করতে পারেন

```bash
var="My Puppet"
echo "$var" | tr '[:upper:]' '[:lower:]'
```
আউটপুট:
```none
my puppet
```

একটি কমন ভুল হলো `tr`-এর আর্গুমেন্টগুলো কোট করতে ভুলে যাওয়া: `tr [:upper:] [:lower:]`

~~~~exercism/caution
কেন এটা সমস্যা?
কোট না করা গ্লব প্যাটার্ন মিলে যাওয়া ফাইলের তালিকায় এক্সপ্যান্ড হয়ে যাবে।
ধরুন, আপনার স্ক্রিপ্ট ব্যবহারকারী ব্যক্তির বর্তমান ডিরেক্টরিতে `p`, `u` আর `w` নামের ফাইল আছে:

```bash
touch p u w
var="My Puppet"
echo "$var" | tr [:upper:] [:lower:]
```

এতে একটি এরর হয়!

কোট না করা `[:upper:]` প্যাটার্নটি `:`, `u`, `p`, `e` বা `r`-এর যেকোনোটির সাথে মেলে।
কোট না করা `[:lower:]` প্যাটার্নটি `:`, `l`, `o`, `w`, `e` বা `r`-এর যেকোনোটির সাথে মেলে।
Bash প্রথম প্যাটার্নের জন্য `p` ও `u` ফাইল দুটি মেলায়, আর দ্বিতীয় প্যাটার্নের জন্য `w` ফাইলটি, এবং `tr` এভাবে চালু হয়

```bash
echo "$var" | tr p u w
```

আর এটা `tr`-এর জন্য ভুল সংখ্যক আর্গুমেন্ট।
~~~~

#### ফাইলনেম এক্সপ্যানশন বন্ধ করা

ফাইলনেম এক্সপ্যানশন বন্ধ করতে [`set`][set] কমান্ডটি ব্যবহার করতে পারেন।

```bash
echo *      # prints a list of files
set -f      # disable filename expansion
echo *      # prints a literal asterisk
set +f      # enable filename expansion
```

#### ফাইলনেম এক্সপ্যানশন নিয়ন্ত্রণ করা

বিল্ট-ইন [`shopt`][shopt] কমান্ডের বেশ কিছু সেটিং আছে, যেগুলো ফাইলনেম এক্সপ্যানশন কীভাবে কাজ করে তা নিয়ন্ত্রণ করে।
কয়েকটি মজার সেটিং হলো:

* `shopt -s nocaseglob` -- কেস-সংবেদনশীল নয় এমন মিল করে
* `shopt -s extglob` -- এক্সটেন্ডেড প্যাটার্ন চালু করে
* `shopt -s nullglob` -- কোনো ফাইল না মিললে প্যাটার্নটিকে কিছুই দিয়ে প্রতিস্থাপন করে।
   ডিফল্ট আচরণ হলো প্যাটার্নটিকে একটি লিটারেল স্ট্রিং হিসেবে রেখে দেওয়া।
