# নির্দেশনা

আপনি লাইব্রেরিয়ান, যিনি পাঠকদের অ্যাকাউন্টের খাতা রাখেন। প্রতি সপ্তাহে দুই ধরনের কাজ আপনার ডেস্কে এসে পড়ে:

- **requests**-এর একটি সারি: পাঠক যে ক্রেডিটগুলো প্রয়োগ করতে চান (বই ফেরত, পরিশোধিত জরিমানা) এবং সিস্টেম যেসব নতুন ডেবিট লিপিবদ্ধ করেছে (নতুন জমা হওয়া বিলম্বিত জরিমানা)। পাঠকের অ্যাকাউন্টটি *ক্রেডিট-প্রোটেক্টেড*: যে ক্রেডিট পাঠককে ঋণাত্মকে ঠেলে দিতে পারে, তা কেবল বাকির পরিমাণ পর্যন্তই প্রয়োগ করা হয়, ফলে চলমান ব্যালেন্স কখনো শূন্যের নিচে নামে না।
- **transactions**-এর একটি তালিকা: অ্যাকাউন্টে আগেই লিপিবদ্ধ এন্ট্রি। ধনাত্মক অঙ্ক ডেবিট (নতুন জরিমানা), ঋণাত্মক অঙ্ক ক্রেডিট (পরিশোধ)।

প্রতি সপ্তাহে আপনি হিসাব মিলিয়ে দেখেন: অনুরোধগুলো পালন করার পর চূড়ান্ত ব্যালেন্স, লেনদেন থেকে প্রতিদিনের চলমান ব্যালেন্স, এবং জরিমানা যখন লাফিয়ে বেড়েছিল এমন সময়গুলো চিহ্নিত করার জন্য একটি চলমান সর্বনিম্ন সীমা।

## 1. অনুরোধের সারি পালন করুন

`protected-balance` ডিফাইন করুন, যা একটি `opening` ব্যালেন্স এবং `requests`-এর একটি অ্যারে (চিহ্নযুক্ত পরিমাণ) নেয়, এবং প্রতিটি অনুরোধ পর্যায়ক্রমে পালন করার পর চূড়ান্ত ব্যালেন্স রিটার্ন করে। যে উত্তোলন ব্যালেন্সকে শূন্যের নিচে নামিয়ে দেবে, তা কেবল উপলব্ধ পরিমাণ পর্যন্তই পালন করা হয়, ফলে চলমান ব্যালেন্স শূন্যে গিয়ে থামে।

```factor
100 { 50 -200 30 } protected-balance .
! => 30

500 { 100 -300 -250 } protected-balance .
! => 50

0 { -10 50 } protected-balance .
! => 50
```

## 2. চলমান ব্যালেন্স

`running-balance` ডিফাইন করুন, যা `transactions`-এর একটি অ্যারে নেয় এবং একই দৈর্ঘ্যের একটি ধারা রিটার্ন করে, যার `i`-তম এলিমেন্ট হলো প্রথম `i+1`টি লেনদেনের পরের ব্যালেন্স (শূন্য শুরুর ব্যালেন্সের সাপেক্ষে)।

```factor
{ 50 -30 -20 100 } running-balance .
! => { 50 20 0 100 }
```

## 3. এখন পর্যন্ত সর্বনিম্ন ব্যালেন্স

`least-balance-so-far` ডিফাইন করুন, যা `transactions`-এর একটি অ্যারে নেয় এবং একই দৈর্ঘ্যের একটি ধারা রিটার্ন করে, যার `i`-তম এলিমেন্ট হলো `i` অবস্থান পর্যন্ত (সহ) দেখা *সর্বনিম্ন* চলমান ব্যালেন্স। এটিই হলো চলমান সর্বনিম্ন সীমা, যা অ্যাকাউন্টটি যেসব দিনে ঝুঁকিপূর্ণ মনে হয়েছে সেগুলো চোখে ধরতে কাজে লাগে।

```factor
{ 50 -30 -20 100 } least-balance-so-far .
! => { 50 20 0 0 }

{ 200 -50 -100 -200 } least-balance-so-far .
! => { 200 150 50 -150 }
```

## 4. টার্গেট পর্যন্ত অর্ধেক করা

লাইব্রেরি একটি জরিমানা মওকুফ কার্যক্রম চালাচ্ছে: প্রতি পরিশোধ পর্বে একজন পাঠকের অপরিশোধিত ব্যালেন্স অর্ধেক করা হয়, যতক্ষণ না তা ক্ষমার সীমায় বা তার নিচে নেমে আসে। `halve-until` ডিফাইন করুন, যা একটি `principal` এবং একটি `target` নেয়, এবং প্রথম অর্ধেক করা থেকে শুরু করে অর্ধেক করা মানগুলোর ধারা রিটার্ন করে (ইন্টিজার ডিভিশন ব্যবহার করে), যতক্ষণ চলমান মান কঠোরভাবে `target`-এর উপরে থাকে ততক্ষণ তা চলতে থাকে। সর্বশেষ যে মানটি তৈরি হবে, সেটিই প্রথম মান, যা `target`-এ বা তার নিচে নেমে আসে।

```factor
100 5 halve-until .
! => { 50 25 12 6 3 }

64 1 halve-until .
! => { 32 16 8 4 2 1 }

3 5 halve-until .
! => { }
```
