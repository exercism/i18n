# নালেবিলিটি সম্পর্কে

একটি আদর্শ জগতে আমরা ভরসা করতে পারতাম যে সবকিছু সুন্দরভাবে সংজ্ঞায়িত, সুনির্দিষ্ট মান নিয়ে, কোনো ফাঁক ছাড়াই।

এটা আমাদের দৈনন্দিন অভিজ্ঞতার সাথে সংঘর্ষ করে, তাই অনেক প্রোগ্রামিং ভাষায় একটি মানের অনুপস্থিতি প্রকাশ করার একটি উপায় আছে: null বা NULL, nil, None, nothing...

এটি চালু করা সহজ ছিল (১৯৬৫ সালে), কিন্তু শীঘ্রই এর জন্য আফসোস করতে হয়।
উদ্ভাবক পরে এটাকে তাঁর ["বিলিয়ন ডলার ভুল"][web-mistake] বলে অভিহিত করেন।

সাম্প্রতিক কয়েক দশকে ভাষা-ডিজাইনাররা নালগুলোকে ব্যবহারযোগ্য কিন্তু (বেশিরভাগ ক্ষেত্রে) নিরাপদ করার অনেক উপায় খুঁজে দেখেছেন।

Kotlin-এর কয়েকটি [সাধারণ নীতি][ref-null-safety] আছে, যা [Java থেকে যথেষ্ট আলাদা][ref-java2kotlin]।
_এই পার্থক্যগুলোর মানে হলো, Java ইন্টারঅপ সামলানোর জন্য Kotlin-এ বিশেষ ফাংশনালিটি আছে, যদিও বিস্তারিত এই কনসেপ্টের আলোচনার বাইরে।_

- Kotlin-এ একটি বিশেষ `null` মান আছে।
- সব টাইপই _ডিফল্টভাবে_ নন-নালেবল (অর্থাৎ `null` হতে পারে না)।
- সব টাইপই _নালেবল_ হতে পারে, কিন্তু এটা স্পষ্টভাবে করতে হবে।
- যে ফাংশনগুলো এক্সেপশন দিয়ে ব্যর্থ হতে পারে, সেগুলোর সাধারণত নালেবল রিটার্ন ভ্যালুযুক্ত একটি ভ্যারিয়েন্ট থাকে।
- বিশেষ, খুবই সংক্ষিপ্ত সিনট্যাক্স নাল পরীক্ষা করা আর তার জবাব দেওয়াকে যতটা সম্ভব সহজ করার চেষ্টা করে।

## নালেবল ভ্যারিয়েবল তৈরি করা

একটি টাইপের শেষে `?` যোগ করে সেটিকে [নালেবল][ref-nullable-type] করা যায় (যেমন `String`-এর বদলে `String?`)।

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## দরকারি অপারেটর ও ফাংশন

### [সেফ কল অপারেটর][ref-safe-call] `?.`

একটি নন-নালেবল `String`-এর ক্ষেত্রে আমরা `.length` প্রপার্টি পেতে পারি।

নালেবল `String?`-এ একই সিনট্যাক্স কাজ করে না, কিন্তু `?.length` ব্যবহার করলে `null` হওয়ার সম্ভাবনা হিসাবের মধ্যে থাকে।
রিটার্ন টাইপ হয় `Int?`।

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

উপরের শেষ লাইনে যেমন দেখলাম, `?.` নন-নালেবল টাইপের সাথেও কাজ করে।

### [এলভিস অপারেটর][ref-elvis] `?:`

সেফ-কল অপারেটরের ধারণা বাড়িয়ে, [এলভিস অপারেটর][wiki-elvis] আমাদের `null`-এর জায়গায় একটি ডিফল্ট মান দিতে দেয়।

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### [নট-নাল অ্যাসারশন অপারেটর][ref-not-null] `!!`

এই অপারেটর দিয়ে একটি নালেবল টাইপকে জোর করে নন-নাল হিসেবে ধরে নেওয়া হয়, যখন প্রোগ্রামার এ ব্যাপারে নিশ্চিত।
হয়তো আমরা কখনো কখনো অতিরিক্ত সতর্ক কম্পাইলারের চেয়ে প্রোগ্রামের লজিক ভালো বুঝি?

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

এখন দায়িত্ব আমাদের কাঁধে: যদি `b` তখনো `null` থাকে, তাহলে আমরা একটি `NullPointerException` পাই।

### [let ফাংশন][ref-let] `?.let`

কোড ব্লকে একটি নালেবল আইটেম পাঠালে, আমরা নির্দিষ্ট নাল চেক করতে পারি: `if (item != null) { do something }`।

আরও সহজ ও বেশি আইডিওম্যাটিক হলো `item?.let { do something }` ব্যবহার করা,
`do something` কেবল তখনই চলবে যখন `item` null নয়।

### `somethingOrNone()` টাইপের ফাংশন

কিছু ফাংশন ব্যর্থ হতে পারে, যেমন স্ট্রিং বা অ্যারে থেকে একটি ইনভ্যালিড ইনডেক্স চাইলে।

এক্সেপশন থ্রো করার বদলে আমরা ফাংশনটির [`...OrNull` ভ্যারিয়েন্ট][ref-elem-at-or-null] ব্যবহার করতে পারি, যাতে (এক্ষেত্রে) একটি `Int?` রিটার্ন ভ্যালু পাওয়া যায়।

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
