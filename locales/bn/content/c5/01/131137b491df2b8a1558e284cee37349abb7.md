# পরিচিতি

Java প্রোগ্রামিং ভাষা এরর এবং অন্যান্য অস্বাভাবিক ইভেন্ট সামলাতে _এক্সেপশন_ ব্যবহার করে।

## এক্সেপশন কী

এক্সেপশন হলো প্রোগ্রাম চলার সময় ঘটে যাওয়া এমন একটি ইভেন্ট, যা নির্দেশনার স্বাভাবিক প্রবাহ ব্যাহত করে।
Java-তে এক্সেপশন স্পষ্টভাবেই উত্থাপিত হয়, আর এক্সেপশন উত্থাপনের কাজটিকে বলা হয় _এক্সেপশন থ্রো করা_।
আর এক্সেপশন সামলানোর কাজটিকে বলা হয় _এক্সেপশন ক্যাচ করা_।

Java-তে সব এক্সেপশনই `Exception` ক্লাসের সাবক্লাস, আর এই ক্লাসটি নিজেই `Throwable`-এর সাবক্লাস।

Java দুই ধরনের এক্সেপশন আলাদা করে:

1. চেকড এক্সেপশন
2. আনচেকড এক্সেপশন

### চেকড এক্সেপশন

_চেকড এক্সেপশন_ হলো এমন ব্যতিক্রমী অবস্থা, যা একটি অ্যাপ্লিকেশনের আগে থেকেই আন্দাজ করা এবং তা থেকে সেরে ওঠা উচিত।
এর একটি উদাহরণ হলো `FileNotFoundException`, যা ঘটে যখন কোনো মেথড এমন একটি ফাইল পড়তে চায় যেটি আসলে নেই।

এই ধরনের এক্সেপশন কম্পাইল-টাইমে যাচাই করা হয়: যে মেথডগুলো চেকড এক্সেপশন থ্রো করে, তাদের মেথড সিগনেচারে এটি উল্লেখ করা উচিত, আর যে কোড এমন কোনো মেথড কল করে যা চেকড এক্সেপশন থ্রো করতে পারে, তাকে তা হ্যান্ডেল করতেই হবে, নাহলে কোড কম্পাইল হবে না।

সব চেকড এক্সেপশনই `Exception`-এর সাবক্লাস, যারা `RuntimeException`-কে এক্সটেন্ড করে না।

### আনচেকড এক্সেপশন

_আনচেকড এক্সেপশন_ হলো এমন ব্যতিক্রমী অবস্থা, যা একটি অ্যাপ্লিকেশন সাধারণত আগে থেকে আন্দাজ করতে পারে না বা তা থেকে সেরে উঠতেও পারে না।
এর একটি উদাহরণ হলো `NullPointerException`, যা ঘটে যখন কোনো মেথড non-null মান আশা করছিল কিন্তু পেল `null`।

এই ধরনের এক্সেপশন কম্পাইল-টাইমে যাচাই করা হয় না: যে মেথডগুলো আনচেকড এক্সেপশন থ্রো করে, তাদের মেথড সিগনেচারে এটি উল্লেখ করা বাধ্যতামূলক নয়, আর যে কোড এমন কোনো মেথড কল করে যা আনচেকড এক্সেপশন থ্রো করতে পারে, তারও তা হ্যান্ডেল করা বাধ্যতামূলক নয়।

সব আনচেকড এক্সেপশন `RuntimeException` থেকে ইনহেরিট করে, যা নিজে `Exception`-এর একটি এক্সটেনশন।

## এক্সেপশন থ্রো করা

Java-তে একটি মেথড `throw` স্টেটমেন্ট ব্যবহার করে এক্সেপশন থ্রো করতে পারে।

### চেকড এক্সেপশন থ্রো করা

কোনো মেথড থেকে চেকড এক্সেপশন থ্রো করার সময়, নিচের উদাহরণে দেখানো মতো `throws` কিওয়ার্ড দিয়ে মেথড সিগনেচারে এটি উল্লেখ করা আবশ্যক।
এতে কল করা কোড বাধ্য হয় ধরে নিতে যে একটি এক্সেপশন থ্রো হতে পারে, এবং সেই অনুযায়ী তা হ্যান্ডেল করতে হয়।

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### আনচেকড এক্সেপশন থ্রো করা

কোনো মেথড থেকে আনচেকড এক্সেপশন থ্রো করার সময়, মেথড সিগনেচারে এটি উল্লেখ করা বাধ্যতামূলক নয়, যদিও এটি সাপোর্ট করা হয়।

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## এক্সেপশন হ্যান্ডেল করা

Java-তে এক্সেপশন হ্যান্ডেল করা হয় `try`, `catch` আর `finally` কিওয়ার্ড দিয়ে।

- যে কোড স্টেটমেন্টগুলো একটি এক্সেপশন থ্রো করতে পারে, সেগুলো একটি `try` ব্লকে রাখা উচিত।
- `try` ব্লকের পরে থাকে এক বা একাধিক `catch` ব্লক, যারা `try` ব্লকে থ্রো হওয়া এক্সেপশনগুলো ধরে।
- `catch` ব্লকগুলোর পরে ঐচ্ছিকভাবে থাকতে পারে একটি `finally` ব্লক, যা এক্সেপশন থ্রো হোক বা না হোক, `try` ব্লকের পর সবসময় এক্সিকিউট হয়।

নিচের উদাহরণটি দেখায় এই কিওয়ার্ডগুলো কীভাবে কাজ করে:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

এই উদাহরণে, যখন কোনো এক্সেপশন থ্রো হয় না, তখন নিচের লেখাটি প্রিন্ট হয়:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

তবে যদি `bankAccount.withdraw(amount)` স্টেটমেন্টটি একটি `InsufficientBalanceException` থ্রো করে, তাহলে নিচের লেখাটি প্রিন্ট হয়:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

আর যদি `bankAccount.withdraw(amount)` কোনো আনচেকড এক্সেপশন থ্রো করে, তাহলে নিচের লেখাটি প্রিন্ট হয়:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## এরর

Java-তে _এরর_ নামে আরেকটি আলাদা শ্রেণিও আছে, যেগুলো অ্যাপ্লিকেশনের বাইরের গুরুতর সমস্যা।
এর একটি উদাহরণ হলো `OutOfMemoryError`, যা ঘটে যখন কোনো অ্যাপ্লিকেশন সিস্টেমে থাকা মেমোরির চেয়ে বেশি মেমোরি ব্যবহার করতে চায়।

আনচেকড এক্সেপশনের মতোই, এররও কম্পাইল-টাইমে যাচাই করা হয় না।
পার্থক্য হলো এগুলো সিস্টেম-লেভেল সমস্যাকে বোঝায় এবং সাধারণত অ্যাপ্লিকেশনের বদলে Java Virtual Machine বা এনভায়রনমেন্ট থ্রো করে।
অ্যাপ্লিকেশনগুলোর সাধারণত এগুলো ক্যাচ বা হ্যান্ডেল করার চেষ্টা করা উচিত নয়।

Java-তে সব এররই `Error` ক্লাস থেকে ইনহেরিট করে।
