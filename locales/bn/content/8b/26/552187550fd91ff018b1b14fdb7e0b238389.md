# Instructions

সম্প্রতি একটি নিরাপত্তা পর্যালোচনার পর আপনাকে প্রতিষ্ঠানের আর্কাইভ করা লগ ফাইলগুলো পরিষ্কার করার কাজ দেওয়া হয়েছে।

## 1. বিকৃত লগ লাইনগুলো চিহ্নিত করুন

আপনার আর্কাইভে কতগুলো লগ লাইন বর্তমান মানদণ্ড মেনে চলে না, সে সম্পর্কে আপনার কিছুটা ধারণা প্রয়োজন।
আপনার মনে হয় একটি সাধারণ পরীক্ষা থেকেই বোঝা যায় একটি লগ লাইন বৈধ কি না।
বৈধ হিসেবে বিবেচিত হতে একটি লাইনের শুরুতে নিচের স্ট্রিংগুলোর একটি থাকা উচিত:

- `[DEBUG]`
- `[INFO]`
- `[WARNING]`
- `[ERROR]`

লগ লাইনটি বৈধ হলে `True` রিটার্ন করার জন্য `is_valid_line` ফাংশনটি ইমপ্লিমেন্ট করুন।

```gleam
log_parser.valid_line("[ERROR] Network Failure")
// -> True

log_parser.valid_line("Network Failure")
// -> False
```

## 2. লগ লাইনটি ভাগ করুন

লগ পার্সিং প্রকল্প শুরু করার অল্প পরেই আপনি বুঝতে পারেন যে একটি অ্যাপ্লিকেশনের লগ অন্যগুলোর মতো লাইনে বিভক্ত নয়।
এই প্রকল্পে যা আলাদা লাইন হওয়া উচিত ছিল, তা বদলে একটি একক লাইনে থাকে, যা `<--->` বা `<*~*~>`-এর মতো অভিনব তীরচিহ্ন দিয়ে যুক্ত থাকে।

আসলে, এমন যেকোনো স্ট্রিং, যার প্রথম ক্যারেক্টার `<`, শেষ ক্যারেক্টার `>`, এবং মাঝে `~`, `*`, `=`, এবং `-` ক্যারেক্টারগুলোর শূন্য বা তার বেশি থাকে, এই প্রকল্পের লগে বিভাজক হিসেবে ব্যবহার করা যেতে পারে।

এমন একটি `split_line` ফাংশন ইমপ্লিমেন্ট করুন যা একটি লাইন নেয় এবং স্ট্রিংয়ের একটি অ্যারে রিটার্ন করে।

```gleam
log_parser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
// -> ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. ব্যবহারকারীর নাম দিয়ে লাইন ট্যাগ করুন

আপনি লক্ষ্য করেছেন যে কিছু লগ লাইনে এমন বাক্য থাকে যা ব্যবহারকারীদের উল্লেখ করে।
এই বাক্যগুলোতে সবসময় `"User"` স্ট্রিং থাকে, তারপর এক বা একাধিক হোয়াইটস্পেস ক্যারেক্টার এবং এরপর একটি ব্যবহারকারীর নাম থাকে।
আপনি এমন লাইনগুলো ট্যাগ করার সিদ্ধান্ত নেন।

এমন একটি ফাংশন `tag_with_user_name` ইমপ্লিমেন্ট করুন যা লগ লাইন প্রসেস করে:

- যে লাইনগুলোতে `"User"` স্ট্রিং থাকে না, সেগুলো অপরিবর্তিত থাকে।
- যে লাইনগুলোতে `"User"` স্ট্রিং থাকে, সেই লাইনগুলোর শুরুতে `[USER]` এবং তারপর ব্যবহারকারীর নাম বসান।

```gleam
log_parser.tag_with_user_name("[INFO] User Alice created a new project")
// -> "[USER] Alice [INFO] User Alice created a new project"
```

আপনি ধরে নিতে পারেন যে:

- `"User"` স্ট্রিংয়ের প্রতিটি উপস্থিতির পরে এক বা একাধিক হোয়াইটস্পেস ক্যারেক্টার এবং ব্যবহারকারীর নাম থাকে।
- প্রতিটি লাইনে `"User"` স্ট্রিং সর্বোচ্চ একবার থাকে।
- ব্যবহারকারীর নাম খালি নয় এমন স্ট্রিং, যেগুলোতে হোয়াইটস্পেস থাকে না।
