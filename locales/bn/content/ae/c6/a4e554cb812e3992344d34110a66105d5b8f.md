# লুপিং পরিচিতি

Bash-এ লুপ করার দুটি রূপ আছে:

* _তালিকার প্রতিটি এলিমেন্টের জন্য_ কিছু কমান্ড পুনরাবৃত্তি করা,
* _কোনো শর্ত সত্য (বা মিথ্যা) থাকা পর্যন্ত_ কিছু কমান্ড পুনরাবৃত্তি করা।

## for লুপ

এলিমেন্টের একটি তালিকার উপর ইটারেশন করতে আমরা `for` লুপ ব্যবহার করি।

```bash
for varname in words; do COMMANDS; done
```

`words` ওয়ার্ড স্প্লিটিং ও ফাইলনেম এক্সপ্যানশন দিয়ে প্রসারিত হয় ([Quoting কনসেপ্ট][quoting] থেকে আমরা যা শিখেছিলাম)। প্রতিটি ওয়ার্ড একের পর এক `varname`-এ অ্যাসাইন করা হয়, আর COMMANDS চালানো হয়।

নিচের কিছু উদাহরণ দেখায় কখন `for` লুপ কাজে লাগতে পারে

* ফাইলের একটি গ্রুপের উপর কিছু কমান্ড চালানো।

    ```bash
    # source all the bash library files in the current directory
    for file in ./*.bash; do
        source "$file"
    done
    ```

* স্ক্রিপ্ট বা ফাংশনের প্রতিটি প্যারামিটারের উপর কিছু কমান্ড চালানো।

    ```bash
    for arg in "$@"; do
        echo "argument: ${arg}"
    done
    ```

* কোনো কমান্ডের আউটপুটে হোয়াইটস্পেস দিয়ে আলাদা করা প্রতিটি ওয়ার্ডের জন্য কিছু কমান্ড চালানো।

    ```bash
    for i in $(seq 10); do
        echo "${i} squared is $((i * i))"
    done
    ```

    এই স্টাইল নিয়ে পরে আমরা কিছু সতর্কবার্তা দেখব।

### গাণিতিক for লুপ

Bash-এ একটি গাণিতিক লুপও আছে। এটি অন্য প্রোগ্রামিং ভাষার কাছে কিছুটা পরিচিত মনে হবে।

```bash
for ((INITIALIZATION; CONDITION; INCREMENT)); do COMMANDS; done
```

Bash-এ ডাবল বন্ধনী একটি গাণিতিক কনটেক্সট বোঝায় (Bash-এর গাণিতিক বিষয়ে আরও বিস্তারিত আমরা পরে দেখব)। `seq` ব্যবহার করা উপরের উদাহরণটি এভাবে লেখা যায়

```bash
for ((i = 1; i <= 10; i++)); do
    echo "${i} squared is $((i * i))"
done
```

### কখন for ব্যবহার করা উচিত নয়

[`for` দিয়ে লাইন পড়বেন না][bashfaq1]।

এটি একটি অ্যান্টি-প্যাটার্ন, যা আপনি প্রায়ই দেখবেন: `cat`-এর আউটপুটের উপর ইটারেশন করা।

```bash
for line in $(cat some.file); do 
    do_something_with "$line"
done
```

এটি দুই দিক থেকে ভুল।

1. কমান্ড সাবস্টিটিউশনটি কোট করা নেই, তাই এতে ওয়ার্ড স্প্লিটিং প্রয়োগ হয়। ওয়ার্ড স্প্লিটিং ডিফল্টভাবে শুধু নতুন লাইন নয়, _হোয়াইটস্পেসেও_ ভাগ করে। এই `for` লুপ ফাইলের **লাইনগুলোর** উপর নয়, বরং **ওয়ার্ডগুলোর** উপর ইটারেশন করছে।
2. কমান্ড সাবস্টিটিউশনটি কোট করা নেই, তাই এতে ফাইলনেম এক্সপ্যানশন প্রয়োগ হয়। ফাইলের প্রতিটি ওয়ার্ড একটি গ্লোব প্যাটার্ন হিসেবে মেলানো হবে।

[Quoting কনসেপ্ট][quoting] থেকে আমরা যেমন শিখেছি, `IFS` ভ্যারিয়েবল দিয়ে ওয়ার্ড স্প্লিটিং নিয়ন্ত্রণ করা যায় এবং ফাইলনেম এক্সপ্যানশন বন্ধ করা যায়। কিন্তু এটি সাধারণত একটি ভঙ্গুর সমাধান। ফাইলের লাইনগুলোর উপর ইটারেশন করার জন্য `for` ভুল পদ্ধতি। একটি ফাইল পড়ার আইডিওম্যাটিক উপায় হলো `while` লুপ।

## while লুপ

কোনো শর্ত সত্য থাকে _যতক্ষণ_, ততক্ষণ কিছু কমান্ড পুনরাবৃত্তি করতে `while` ব্যবহার করুন।

```bash
while CONDITION_COMMANDS; do COMMANDS; done
```

`if`-এর মতোই ([Conditionals কনসেপ্ট][conditionals] থেকে আমরা যেমন শিখেছি, CONDITION_COMMANDS-এর জন্য কোনো বিশেষ সিনট্যাক্স নেই। কমান্ড লিস্টের এক্সিট স্ট্যাটাসই "সত্য" বা "মিথ্যা" নির্ধারণ করবে।

## লুপ নিয়ন্ত্রণ

`break` কমান্ড লুপ থেকে বেরিয়ে যায়। লুপের `done` টার্মিনেটরের পরের কমান্ড থেকে কার্যক্রম আবার শুরু হয়।

`continue` কমান্ড লুপের পরবর্তী ইটারেশনে চলে যায়।

## একটি ফাইলের লাইন পড়া

যেমন বলা হয়েছে, একটি ফাইল পড়ার আইডিওম্যাটিক উপায় হলো `while` লুপ।

```bash
while IFS= read -r line; do
    do_something_with "$line"
done < some.file
```

* `<` রিডাইরেকশন দিয়ে ফাইলের কনটেন্ট লুপে ইনপুট হিসেবে দেওয়া হয়।
* `read` কমান্ড তার ইনপুট থেকে একটি সম্পূর্ণ লাইন পড়তে পারলে "সত্য" রিটার্ন করে।
  ইনপুট শেষ হয়ে গেলে, বা শেষ লাইনটি শেষে নতুন লাইন ছাড়া শেষ হলে, তখন `read` "মিথ্যা" রিটার্ন করে।
  * একটি ফাইলের লাইনগুলো পড়ার _সত্যিকারের_ আইডিওম্যাটিক উপায়, এমনকি শেষ লাইনটি নতুন লাইন দিয়ে শেষ না হলেও, হলো

    ```bash
    while IFS= read -r line || [[ -n "$line" ]]; do ...
    ```

* `-r` অপশন `read`-কে ব্যাকস্ল্যাশ সিকোয়েন্স প্রতিস্থাপন না করতে বলে: ব্যাকস্ল্যাশ হলো শুধু একটি সাধারণ ক্যারেক্টার।
* `IFS=` শুধু `read` কমান্ড চলার সময়টুকুতে খালি স্ট্রিং IFS-এ অ্যাসাইন করে।
  এটি সাময়িকভাবে ওয়ার্ড স্প্লিটিং বন্ধ করে, যাতে আগত টেক্সট লাইনের শুরুতে বা শেষে থাকা যেকোনো হোয়াইটস্পেস সংরক্ষিত থাকে।

## until

`until` কনস্ট্রাক্ট কিছু কমান্ড পুনরাবৃত্তি করে যতক্ষণ কোনো শর্ত **মিথ্যা** থাকে। লুপটি পুনরাবৃত্তি হয় _যতক্ষণ না_ শর্তটি সত্য হয়।

```bash
until CONDITION_COMMANDS; do COMMANDS; done
```

`until` ব্যবহার করা বিরল। "while not" লুপ ব্যবহার করাই বেশি কমন।

```bash
while ! CONDITION_COMANDS; do ...
```

## অসীম লুপ

কখনও কখনও আপনি চিরকাল লুপ করতে চান। এটি করার দুটি উপায় আছে।

1. এমন একটি while লুপ যার শর্তের এক্সিট স্ট্যাটাস সবসময় সফল

    ```bash
    while true; do ...
    ```

2.  খালি এক্সপ্রেশনযুক্ত একটি গাণিতিক for লুপ

    ```bash
    for ((;;)); do ...
    ```

## Do-While

স্পষ্ট কোনো do-while কনস্ট্রাক্ট নেই, তবে আপনি একই প্রভাব অর্জন করতে পারেন:

```bash
while true; do
    COMMANDS

    if END_CONDITION; then
        break
    fi
done
```
