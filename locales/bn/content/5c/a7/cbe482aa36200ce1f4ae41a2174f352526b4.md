# Nil

Crystal-এ [`Nil`][nil] নামে একটি টাইপ আছে, যার একটিমাত্র মান থাকতে পারে: `nil`।
এটি কোনো মানের অনুপস্থিতি বোঝাতে ব্যবহৃত হয়, এবং অন্য ভাষার `null` বা `None`-এর সাথে এর মিল আছে।

বিভিন্ন মেথড থেকে nil মান রিটার্ন করা যেতে পারে, যেমন [`String#[]?`][string-index], যা ইনডেক্স সীমার বাইরে গেলে `nil` রিটার্ন করে।

```crystal
"foo"[10]? # => nil
```

Crystal-এ **NULL REFERENCE CHECKS** নামে একটি ব্যবস্থা আছে, যার অর্থ হলো সব টাইপই ডিফল্টভাবে nil গ্রহণ করে না।
এর মানে হলো আপনি কোনো ভ্যারিয়েবলে `nil` অ্যাসাইন করতে পারবেন না, যদি না আপনি সেটিকে স্পষ্টভাবে `Nil` টাইপ হিসেবে ঘোষণা করেন।
এর ফলে কম্পাইলার স্বয়ংক্রিয়ভাবেই নাল রেফারেন্স যাচাই করে।

## ফলসি মান

`nil` মান সামলানোর জন্য কিছু উপায় অবলম্বন করা যায়।
`nil` একটি [ফলসি][truthy-falsey] মান, ঠিক যেমন `false`-ও।
এর মানে হলো, স্টেটমেন্ট এবং যেসব জায়গায় ফলসি বা ট্রুথি মান প্রত্যাশিত, সেখানে এটিকে `false`-এর মতোই ধরা হবে।

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

অর্থাৎ, nil হতে পারে এমন কোনো ভ্যারিয়েবলের মান `nil` হলে ট্রুথি শাখাটি নেওয়া হবে না।

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## nil কি না তা যাচাই

কোনো মান `nil` কি না তা যাচাই করার জন্য Crystal-এ একটি মেথড আছে।
এর নাম [`nil?`][nil?], এবং এটি সব অবজেক্টেই পাওয়া যায়।

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

তবে `if` স্টেটমেন্টে সরাসরি মানটি ব্যবহার করলে বিষয়টি কিছুটা আলাদা, কারণ আগের উদাহরণগুলোতে `false` এবং nil দুটোকেই মিথ্যা ধরা হতো।
এখানে কেবল `nil`-কেই ফলসি ধরা হয়, কারণ মানটি যদি `false` হতো তাহলে সেটি nil হতো না, বরং ট্রুথি হতো।

## অর অপারেটর

`nil` মান সামলানোর সবচেয়ে সহজ উপায় হলো শুরুতেই নিশ্চিত করা যে সেগুলো কখনো `nil` হয় না।
অর অপারেটর ([`||`][or]) প্রায়ই `Bools` নিয়ে কাজ করার সময় ব্যবহৃত হয়, তবে সঠিকভাবে বুঝলে এটি `nil` মান সামলাতেও ব্যবহার করা যায়।
অর অপারেটর প্রথম মানটি ট্রুথি কি না তা যাচাই করে; যদি না হয়, দ্বিতীয় মানটি ব্যবহৃত হয়।
এভাবে ব্যবহার করলে মানটি `nil` হলে সেটি ফলসি হিসেবে গণ্য হবে এবং তখন দ্বিতীয় মানটি ব্যবহৃত হবে।

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
এই পদ্ধতিটিকে শেষ উপায় হিসেবে দেখা উচিত, এবং কেবল তখনই ব্যবহার করা উচিত যখন আপনি **নিশ্চিত** যে মানটি nil নয়।
সম্ভব হলে বরং অন্য উপায়গুলো ব্যবহার করুন।
~~~~

[`not_nil!`][not_nil] হলো এমন একটি মেথড যা দিয়ে আপনি কম্পাইলারকে জানাতে পারেন যে কোনো মান nil নয়, ফলে মানটি যে টাইপ ধারণ করে সেটি আর nil হতে পারবে না।
মানটি nil হলে এটি একটি এক্সেপশন রেইজ করে এই কাজটি করে।

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
