# কাস্টম ইটারেটর

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | রুটিন | ইটারেটর |
| --- | --- | --- |
| নাম | `foo` | `foo!` |
| মান ফিরিয়ে দেয় | `return` | `yield` |
| শেষ হয় | `return`, অথবা শেষ | `quit`, অথবা ফুরিয়ে যাওয়া |
| কল করা যায় | যেকোনো জায়গায় | শুধু একটি `loop`-এর ভেতরে |
| নিজের জায়গা ধরে রাখে | না | হ্যাঁ |

## yield

`yield` একটি মান দিয়ে দেয় এবং সাময়িকভাবে থেমে যায়। পরের বার সবকিছু আগের অবস্থায় ফিরে আসে: লোকাল ভ্যারিয়েবল, ইটারেটরের নিজের লুপগুলোতে তার অবস্থান, আর সে নিজে যেসব ইটারেটরকে কল করছে তাদের অবস্থান।

নেস্টেড লুপের ভেতরে থাকা `yield` আবার শুরু হয় সবচেয়ে ভেতরের লুপ থেকে, আর এ কারণেই নেস্টেড কোনো কিছুর ভেতর দিয়ে ঘুরে যাওয়ার কোড সহজে লেখা যায়:

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

`quit` ইটারেটরটির সমাপ্তি ঘটায়, আর তার সঙ্গে যেই লুপটি এটিকে কল করছে সেটিরও। এটি কোনো মান বহন করে না: `quit` কোনো শেষ ফলাফল নয়, বরং একটি ঘোষণা যে কোনো ফলাফলই নেই।

রিটার্ন টাইপযুক্ত একটি ইটারেটরকে প্রতিবার yield করার সময়ই একটি মান `yield` করতে হয়; আর `quit` হলো সেটি না করার উপায়।

## once

```sather
   markers!(once count : INT) : INT is
```

একটি `once` আর্গুমেন্ট লুপে ঢোকার সময় একবার হিসাব করা হয় এবং ধরে রাখা হয়। সাধারণ আর্গুমেন্ট প্রতিবার নতুন করে হিসাব করা হয়, যা গুরুত্বপূর্ণ তখন, যখন পাস করা এক্সপ্রেশনটিতে আরেকটি ইটারেটর কল থাকে:

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

বিশেষভাবে না চাইলে আর্গুমেন্টগুলো `once` হিসেবে চিহ্নিত করুন। পুরো লাইব্রেরি সেটাই করে।

## self ও ইটারেটর

ইটারেটরকে একটি অবজেক্টের উপর কল করা যায়, আর তখন `self` হল সেই অবজেক্ট। তার থেমে থাকা অবস্থাটি কল সাইটের, অবজেক্টের নয়, তাই একই অবজেক্টের উপর দিয়ে ঘোরা দুটি লুপ একে অপরের কাজে বাধা দেয় না।

## কখন একটি লিখবেন

ইটারেটর লিখুন তখন, যখন উত্তরটি হয় একটি সিকোয়েন্স, আর তার কতটুকু নেবে সেটি ঠিক করবে কলকারী। আগেভাগে থামাতে কোনো খরচ নেই, আর যা ব্যবহার করা হয় না তা তৈরি হয়ও না। অথচ একটি `ARRAY` রিটার্ন করা রুটিনকে আগে পুরোটাই তৈরি করতে হয়।
