# পরিচিতি

সাধারণত অপারেটিং সিস্টেম (OS) একটি প্রোগ্রামের জন্য মেমরিকে একটি সাধারণ বিন্যাসে ম্যাপ করে:

| অ্যাড্রেস | মেমরি অঞ্চল         |
| :-----: | :--------------------- |
|  উচ্চ   | স্ট্যাক                  |
|         | ...                    |
|         | হিপ                   |
|         | রিড-অ্যান্ড-রাইট সেগমেন্ট |
|         | কোড/রিড-অনলি সেগমেন্ট |
|   নিম্ন   | রিজার্ভড               |

সেগমেন্টে থাকা মেমরি বিভিন্ন পারমিশনসহ সেকশনে সাজানো থাকে।

এখন পর্যন্ত আমরা যেসব ফাংশন ডিফাইন করেছি, সেগুলো সবই ছিল **সেকশন .text**-এ।
এই সেকশনে রিড-অনলি এক্সিকিউটেবল ডেটা থাকে।
অন্য সেকশনগুলো ডেটা ভ্যারিয়েবল ঘোষণা করতে ব্যবহার করা হয়; এগুলো রিড-অনলি বা রিড-অ্যান্ড-রাইট হতে পারে, তবে এক্সিকিউটেবল নয়।

## সেকশন .data

ইনিশিয়ালাইজড ডেটা ঘোষণা করা হয় **সেকশন .data**-এ।

NASM-এ (The Netwide Assembler, এই ট্র্যাকে ব্যবহৃত অ্যাসেম্বলার) একটি ইনিশিয়ালাইজড ভ্যারিয়েবলের থাকে একটি নাম, ডেটার সাইজ নির্দেশ করে এমন একটি ডিরেক্টিভ, এবং কমা দিয়ে আলাদা করা মানের একটি তালিকা।
এগুলোর প্রতিটি একটি স্পেস দিয়ে অন্যটি থেকে আলাদা থাকে, আর লেবেলের পরে ঐচ্ছিকভাবে একটি `:` থাকতে পারে।

প্রধান ডিরেক্টিভগুলো এবং তাদের সংশ্লিষ্ট ডেটার সাইজ:

| ডিরেক্টিভ | সাইজ    |
| :-------: | :------ |
|    db     | ১ বাইট  |
|    dw     | ২ বাইট |
|    dd     | ৪ বাইট |
|    dq     | ৮ বাইট |

উদাহরণস্বরূপ, এটি `space` নামের একটি বাইট ভ্যারিয়েবল ঘোষণা করে, যার মান `10`:

```x86asm
section .data
    space db 10
```

`section .data`-এ ঘোষিত ভ্যারিয়েবলগুলো মিউটেবল, অর্থাৎ এগুলো রিড-অ্যান্ড-রাইট।
এগুলো _static_ স্টোরেজ ডিউরেশনও রাখে, অর্থাৎ প্রোগ্রাম চলাকালীন পুরো সময় জুড়ে এদের অস্তিত্ব থাকে।

## সেকশন .rodata

**সেকশন .rodata** `section .data`-এর মতোই।
দুটি সেকশনেই ইনিশিয়ালাইজড ডেটা থাকে, যা একইভাবে ঘোষণা করা হয় এবং যাদের স্টোরেজ ডিউরেশনও একই।

এদের মধ্যে মূল পার্থক্য হলো `section .rodata`-এর ডেটা ইমিউটেবল, অর্থাৎ রিড-অনলি।

~~~~exercism/note
`equ` দিয়ে ডিফাইন করা কনস্ট্যান্ট আর `section .rodata`-এ ডিফাইন করা কনস্ট্যান্ট এক নয়।

`equ` দিয়ে ডিফাইন করা কনস্ট্যান্ট মেমরিতে জায়গা নেয় না, অ্যাসেম্বলার সরাসরি তার মান বসিয়ে দেয়।
আসলে এটি ওই মানের একটি প্লেসহোল্ডার।

অন্যদিকে, `section .rodata`-এ ডিফাইন করা কনস্ট্যান্ট সত্যিই মেমরিতে সংরক্ষিত থাকে, যার একটি অ্যাড্রেস থাকে।
~~~~

## ডেটা অ্যাক্সেস করা

### লেবেল ও ইনডিরেকশন

ঘোষিত ডেটার সাথে অবশ্যই একটি নাম যুক্ত থাকতে হবে।
এই নামটিকে **লেবেল** বলা হয়।

লেবেল হলো একটি সিম্বল, যা মেমরিতে ডেটার নির্দিষ্ট অ্যাড্রেস এনকোড করে।
**x86-64-এ অ্যাড্রেসগুলো ৬৪-বিট মান**।

NASM-এ লেবেল দিয়ে সরাসরি ডেটা অ্যাক্সেস করার চেষ্টা করলে বরাদ্দ করা মেমরি পাওয়া যায় না, বরং পাওয়া যায় তার অ্যাড্রেস:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

একটি মেমরি অ্যাড্রেসের ভেতরের বিষয়বস্তু অ্যাক্সেস করতে হলে সেটিকে _dereference_ করতে হয়।
এটাকে **ইনডিরেকশন** বলা হয়।

NASM-এ এটি `[]` দিয়ে করা হয়:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

তবে এমন কিছু পরিস্থিতি আছে, যেখানে ডিরেফারেন্স করা মেমরির সাইজ নিয়ে অস্পষ্টতা থাকতে পারে।
সেসব ক্ষেত্রে সাইজ নির্দেশ করে এমন একটি প্রিফিক্স ব্যবহার করতে হবে।

একটি সাধারণ x86-64 প্রোগ্রামে সবচেয়ে গুরুত্বপূর্ণ প্রিফিক্সগুলো এবং তাদের সাইজ:

| প্রিফিক্স | সাইজ    |
| :----- | :------ |
| byte   | ১ বাইট  |
| word   | ২ বাইট |
| dword  | ৪ বাইট |
| qword  | ৮ বাইট |

সাইজ স্পষ্টভাবে উল্লেখ করে একই লোড লেখা যেতে পারে:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

মেমরি ডিরেফারেন্স করার সময় সবসময় একটি প্রিফিক্স ব্যবহার করা ভালো অভ্যাস।

### মেমরিতে লেখা

মেমরিতে লেখাও একইভাবে করা হয়, একটি অ্যাড্রেস ডিরেফারেন্স করে:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

লক্ষ্য করুন, বেশিরভাগ ইনস্ট্রাকশনে আগে রেজিস্টারে কনটেন্ট লোড না করেই আপনি মেমরি অপারেন্ড ব্যবহার করতে পারেন।
তবে সাধারণত সোর্স ও ডেস্টিনেশন, দুটি অপারেন্ডেই সেগুলো ব্যবহার করা সম্ভব নয়, দুটির মধ্যে কেবল একটি ব্যবহার করা যায়:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### LEA ইনস্ট্রাকশন

যদিও একটি ভ্যারিয়েবলের অ্যাড্রেস রেজিস্টারে রাখতে `mov` ব্যবহার করা যায়, এই নির্দিষ্ট কাজের জন্যই একটি ইনস্ট্রাকশন আছে: **lea**।

এই ইনস্ট্রাকশন একটি মেমরি-ফর্ম অপারেন্ড ব্যবহার করে, কিন্তু এটি মেমরি পড়ে না।
বরং এটি ইফেক্টিভ অ্যাড্রেস এক্সপ্রেশনটি হিসাব করে এবং ফলাফলটি ডেস্টিনেশন অপারেন্ডে লেখে:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

রেজিস্টারে মেমরি অ্যাড্রেস হিসাব করে রাখতে `lea` ব্যবহার করাই বেশি প্রচলিত।

### রিলেটিভ অ্যাড্রেসিং

মেমরি লোকেশন অ্যাক্সেস করার সময় NASM-এর ডিফল্ট আচরণ হলো **অ্যাবসোলিউট অ্যাড্রেস**, অর্থাৎ নির্দিষ্ট মেমরি অ্যাড্রেস তৈরি করা।

নিরাপত্তার কারণে এক্সিকিউটেবলগুলো প্রায়শই **PIE (Position Independent Executable)** হিসেবে তৈরি হয়, যেখানে মেমরি অঞ্চলগুলো র‍্যান্ডমাইজড লোকেশনে রাখা হয়।
একটি `PIE`-তে লিংক করার সময় ভ্যারিয়েবলের চূড়ান্ত অ্যাড্রেস জানা থাকে না।
তাই কোড বদলে `rip` নামের একটি বিশেষ রেজিস্টারের মান থেকে অফসেট হিসেবে অ্যাড্রেস হিসাব করে, যে রেজিস্টারটি পরবর্তী যে ইনস্ট্রাকশনটি চালানো হবে সেটির দিকে নির্দেশ করে।

এটাকে সাধারণত **RIP-রিলেটিভ অ্যাড্রেসিং** বলা হয়।

NASM-এ `rel` অপারেটর দিয়ে আপনি RIP-রিলেটিভ অ্যাক্সেস চাইতে পারেন:

```x86asm
mov rax, qword [rel variable]
```

সোর্স ফাইলের একেবারে উপরে `default rel` লিখে রিলেটিভ অ্যাড্রেসিংকে ডিফল্টও বানানো যায়।

এই ট্র্যাকের সব অনুশীলনী `PIE` হিসেবে কম্পাইল ও লিংক করা হয়, তাই রিলেটিভ অ্যাড্রেস তৈরি করতে `rel` ব্যবহার করা উচিত।

### ভিজিবিলিটি

যেকোনো সেকশনে (যেমন `.text`, `.data`, `.rodata`) ডিফাইন করা লেবেল (ফাংশন ও ডেটা) একই সোর্স ফাইলের ভেতরে ভিজিবল থাকে।
`global` দিয়ে ঘোষণা করা হলে সেগুলো অন্য সোর্স ফাইলেও ভিজিবল থাকে।

উল্টোদিকে, অন্য সোর্স ফাইলে ডিফাইন করা লেবেল `extern` দিয়ে ঘোষণা করা হলে বর্তমান সোর্স ফাইলে ভিজিবল থাকে।
এই ক্ষেত্রে অ্যাসেম্বলিতে ডেটার সাইজের কোনো ইঙ্গিত থাকে না, এটি আগে থেকেই জানা থাকতে হবে।

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
