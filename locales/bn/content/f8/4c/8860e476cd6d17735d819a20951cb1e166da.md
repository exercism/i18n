# সম্পর্কে

## জুলিয়ায় বুলিয়ান

সত্য বা মিথ্যা মান বোঝানো হয় `Bool` টাইপ দিয়ে।
এতে মাত্র দুটি মান থাকে: `true` এবং `false`।

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

অন্য অনেক ভাষার বিপরীতে জুলিয়ায় সচেতনভাবেই "ট্রুথিনেস" বলে কোনো ধারণা নেই, এবং কেবল যে এক্সপ্রেশনগুলো `true` বা `false` মানে মূল্যায়িত হয়, সেগুলোই `Bool` হিসেবে ধরা হয়।

বিশেষভাবে, খালি অ্যারে বা স্ট্রিং *কখনোই* `false` হিসেবে ধরে নেওয়া হয় না।
খালি মানের জন্য আলাদা কিছু করতে চাইলে `isempty()`-এর মতো উপযুক্ত একটি পরীক্ষা থাকা দরকার।

## বুলিয়ান অপারেটর

জুলিয়ায় তিনটি [বুলিয়ান অপারেটর][boolean-operators] আছে।

`&&` হলো বুলিয়ান "and"।
`&&`-এর *দুই* পাশের এক্সপ্রেশনই `true` হলে এটি `true` হিসেবে মূল্যায়িত হয়।

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||` হলো বুলিয়ান "or"।
`||`-এর *যেকোনো* এক পাশের এক্সপ্রেশন `true` হলে এটি `true` হিসেবে মূল্যায়িত হয়।

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!` হলো বুলিয়ান "not"।
এটি `true` ও `false` মানকে পরস্পরের সঙ্গে অদলবদল করে (উল্টে দেয়)।

```julia-repl
julia> !true
false

julia> !false
true
```

একই ধরনের অপারেটর অনেক অন্য ভাষার ব্যবহারকারীর কাছে ধারণাগতভাবে পরিচিত মনে হবে, যদিও ভাষা অনুযায়ী সঠিক সিনট্যাক্স আলাদা হতে পারে।

## অপারেটরের অগ্রাধিকার

আরও জটিল এক্সপ্রেশনে জানা দরকারি হতে পারে যে `&&`-এর [অগ্রাধিকার][operator-precedence] `||`-এর চেয়ে একটু বেশি *(যেভাবে পাটিগণিতের এক্সপ্রেশনে `+`-এর আগে `*` প্রয়োগ করা হয়)*।

এর ওপর নির্ভর করা বিভ্রান্তিকর হতে পারে এবং ভুলের সম্ভাবনাও বাড়ায়।
স্পষ্টতার জন্য বন্ধনী ব্যবহার করে আপনার উদ্দেশ্য পরিষ্কার করে দিন।

## শর্ট-সার্কিট মূল্যায়ন

`true || x` এক্সপ্রেশনটি কি `x`-এর মানের ওপর নির্ভর করে, নাকি কম্পাইলার `x` উপেক্ষা করতে পারে?

জুলিয়া বুলিয়ান এক্সপ্রেশন বাম থেকে ডানে মূল্যায়ন করে, আর দ্ব্যর্থহীন ফলাফল পেলেই থেমে যায়।

উদাহরণস্বরূপ, `x` যেমনই হোক `true || x` অবশ্যই `true`, তাই `x` মূল্যায়িত হয় না।
একইভাবে, `false && y` হলো `false`, আর `y` মূল্যায়ন করার দরকারই নেই।

উল্টোদিকে, `true && x` কেবল তখনই `true` হয় *যদি* `x` `true` হয়, তাই `x` অবশ্যই মূল্যায়ন করতে হয়।

একইভাবে, আমরা যদি একাধিক অপারেটর জুড়ে দিই:

```julia-repl
julia> true && false && something_else
false
```

যেহেতু `true && false` অবশ্যই `false`, তাই `something_else`-এর কোনো গুরুত্ব নেই এবং কম্পাইলার এটিকে উপেক্ষা করে।

এই ক্ষেত্রে `something_else` নামে কোনো ভ্যারিয়েবলই ছিল না, তবুও এখানে এভাবে ব্যবহার করায় কোনো এরর দেখা যায়নি *(সন্দেহ হলে REPL-এ নিজে পরীক্ষা করে দেখুন)*।

জুলিয়ার প্রোগ্রামাররা রানটাইম সমস্যা ও এজ কেস ধরে ফেলার এক ধরনের শর্টকাট হিসেবে এই শর্ট-সার্কিট মূল্যায়ন প্রায়ই ব্যবহার করেন:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

উদাহরণস্বরূপ, `all_ok` `false` হলে `do_something` হতে পারে ফাংশন থেকে আগেভাগেই `return` করা, কিংবা এগিয়ে যাওয়ার আগে কোনো ভ্যারিয়েবলে একটি ডিফল্ট মান অ্যাসাইন করা।

এটি বুলিয়ান সিনট্যাক্সের একটু অপব্যবহার বটে, তবে খুবই সুবিধাজনক হতে পারে।

## Bool ভেতরে ভেতরে কীভাবে কাজ করে

কোনো *পাটিগণিত* এক্সপ্রেশনে Bool থাকলে `true`-কে `1` এবং `false`-কে `0` হিসেবে ব্যাখ্যা করা হয়, যা আসলে এগুলো কীভাবে সংরক্ষিত হয় তারই প্রতিফলন।

আপনি যদি নিম্নস্তরের ভাষায় (C এবং অনুরূপ ভাষায়) অভ্যস্ত হন, তাহলে *অনুগ্রহ করে* এটি বারবার ব্যবহার করা এড়িয়ে চলুন।
এতে কোডের পঠনযোগ্যতা কমে যাবে এবং ডিবাগ করা আরও কঠিন হয়ে উঠবে।

মাঝেমধ্যে দেখতে পাবেন, কতগুলো জিনিস `true` তা দ্রুত গুনে বের করার জন্য সংখ্যাসূচক মানগুলো ব্যবহার করা হচ্ছে।

```julia-repl
julia> true + false + true
2
```
