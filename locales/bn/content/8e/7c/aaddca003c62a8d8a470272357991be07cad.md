# C স্টাইল গাইড

এই গাইডে C ট্র্যাকের অনুশীলনীর উদাহরণ ও টেস্ট ফাইলে যে স্টাইল ব্যবহার করার কথা, তা বর্ণনা করা হয়েছে।

এই গাইডের নিয়মগুলো [.clang-format][] ফাইলে নির্ধারিত নিয়মের অতিরিক্ত, অথবা সেগুলোকে বিশেষভাবে উল্লেখ করার জন্য।

## C স্ট্যান্ডার্ড

কোডটি C99 স্ট্যান্ডার্ড মেনে চলা উচিত, যার আনুষ্ঠানিক নাম ISO/IEC 9899:1999।
POSIX, কিংবা অন্যথায় নন-স্ট্যান্ডার্ড লাইব্রেরি ফাংশন, টাইপ বা ইমপ্লিমেন্টেশনের বাইরের অন্য কোনো রেফারেন্স ব্যবহার করা উচিত নয়।

## নাম

সাধারণভাবে, টাইপ, ভ্যারিয়েবল, স্ট্রাকচার ও ফাইলের নামে স্নেক কেস ব্যবহার করা উচিত, যেখানে সব অক্ষর ছোট হাতের হবে এবং নামের অংশগুলো আলাদা করতে আন্ডারস্কোর `_` ব্যবহার করা হবে।

```c
void some_foo_function(char * input_string, int input_string_length);
```

### এনাম

এনামের নাম সাধারণত বহুবচনের বদলে একবচনে হওয়া উচিত।

এনামের লেবেলগুলোতে স্নেক কেস ব্যবহার করা উচিত, যেখানে সব অক্ষর বড় হাতের হবে।

```c
enum heading {
    HEADING_NORTH,
    HEADING_EAST,
    HEADING_SOUTH,
    HEADING_WEST
}
```

### ম্যাক্রো

কনস্ট্যান্ট নির্ধারণকারী ম্যাক্রোর নাম স্নেক কেসে রাখা হয়, যেখানে সব অক্ষর বড় হাতের।

```c
#define CONSTANT 0x4000
```

ম্যাক্রোর নামে বড় হাতের স্নেক কেস প্রশংসনীয়, তবে ফাংশনের মতো ম্যাক্রোর নাম ছোট হাতের স্নেক কেসেও রাখা যেতে পারে।

### টাইপ

সাধারণ ইন্টিজার টাইপের চেয়ে স্ট্যান্ডার্ড নির্দিষ্ট-প্রস্থের টাইপগুলো (`stdint.h`-এ) বেশি পছন্দনীয়।

`_Bool`-এর চেয়ে `bool` টাইপ (`stdbool.h` থেকে) বেশি পছন্দনীয়।

একইভাবে, মেমরি-সংক্রান্ত পরিমাণ প্রকাশ করতে `size_t` ও `ptrdiff_t` (`stddef.h`-এর) বেশি পছন্দনীয়।

`typedef` ব্যবহার করে প্রোগ্রামে নির্ধারিত টাইপের নাম `_t` প্রত্যয় দিয়ে শেষ হওয়া উচিত।
POSIX `_t` প্রত্যয় সংরক্ষিত রাখে জেনেও, এই ট্র্যাক বর্তমানে POSIX ব্যবহার করে না।

## ইনক্লুড গার্ড

সব হেডার ফাইলে ইনক্লুড গার্ড ব্যবহার করা উচিত।

সাধারণভাবে, এক সেট ইনক্লুড গার্ড দিয়ে হেডারের সম্পূর্ণ বিষয়বস্তু ঘিরে রাখা উচিত।

উদাহরণ ইমপ্লিমেন্টেশন (`.meta/example.h`) ও অনুশীলনীর স্টাব (`exercise_name.h`)-এ গার্ডের ম্যাক্রো নাম অনুশীলনীর নাম অনুসরণ করে হওয়া উচিত।
গার্ড ম্যাক্রোর নাম কেসিং-সংক্রান্ত উপরের নিয়ম মেনে চলা উচিত।

উদাহরণস্বরূপ, `hello-world` অনুশীলনীর জন্য ব্যবহার করুন:

```c
#ifndef HELLO_WORLD_H
#define HELLO_WORLD_H

//...

#endif
```

## প্যারামিটার

সব ফাংশনের ডিক্লারেশন ও ডেফিনিশন, দুই জায়গাতেই ফাংশন প্যারামিটারের নাম থাকা উচিত।
এটি `.c` ও `.h` ফাইল দুটোর ক্ষেত্রেই প্রযোজ্য।
সব জায়গায় ব্যবহৃত নামগুলো একই হওয়া উচিত।
অর্থাৎ, নিচের ফাংশন প্রোটোটাইপটি বৈধ C হলেও স্টাইলটি ভুল, কারণ প্যারামিটারটির কোনো নাম নেই: `void foo(int);`।
সঠিক প্রোটোটাইপ হবে `void foo(int bar);`, তবে শর্ত হলো অন্য সব ডিক্লারেশন ও ডেফিনিশনেও প্যারামিটারের নাম `bar` থাকতে হবে।

যেখানে সহজ বা বেশি উপযুক্ত, সেখানে পয়েন্টারের বদলে ভ্যালু দিয়ে আর্গুমেন্ট পাঠাতে হয় এমন প্যারামিটার বেশি পছন্দনীয়।
বিশেষভাবে লক্ষ্য করুন, এর মধ্যে `struct` টাইপের প্যারামিটারও পড়ে।

যদি কোনো শিক্ষার্থীর ইমপ্লিমেন্টেশনে পয়েন্টার-টাইপ প্যারামিটারের মান পরিবর্তন করার কথা না থাকে, তবে সেই প্যারামিটারটি `const` যোগ্য হওয়া উচিত।

## ফরম্যাট

রেপোজিটরিতে `clang-format` টুল ব্যবহার করা হয়, যা [অবদান রাখার গাইড][contributing guide]-এ বর্ণনা করা হয়েছে।

## টেস্ট ফাইলের বিন্যাস

প্রতিটি অনুশীলনীর টেস্ট ফাইল একটি নির্দিষ্ট বিন্যাস অনুসরণ করে।
এই বিন্যাসের উদ্দেশ্য দুইটি: অবদানকারীদের ফাইলের বিভিন্ন অংশ চিনতে সাহায্য করা, এবং শিক্ষার্থীদের টেস্টগুলো কীভাবে কাজ করে তা বুঝতে সাহায্য করা।

বেশিরভাগ C সোর্স ফাইলের মতো, একটি টেস্ট ফাইলও include দিয়ে শুরু হয়।

```c
#include "vendor/unity.h"
#include "../src/file_under_test.h"
// any other includes here
```

এরপর include-গুলোর পরে আসে `setUp()` ও `tearDown()` ফাংশন।
এখন পর্যন্ত কোনো অনুশীলনী এগুলো ব্যবহার করে না (ফাংশন বডি খালি), তবুও সব প্ল্যাটফর্মে টেস্ট ফাইলগুলো সঠিকভাবে কম্পাইল হওয়ার জন্য এগুলো থাকতে হবে।

```c
void setUp(void)
{
}

void tearDown(void)
{
}
```

এরপর আসে টেস্ট ফাংশনগুলো যে হেল্পার ফাংশন ব্যবহার করে সেগুলো।
এমন হেল্পার ফাংশনের নামে `test_` প্রিফিক্স ব্যবহার করা উচিত নয়।

এরপর আসে টেস্ট ফাংশনগুলো নিজেরাই।
এই ফাংশনগুলোর নামে `test_` প্রিফিক্স থাকে।
প্রথমটি ছাড়া প্রতিটি টেস্ট ফাংশনের প্রথম স্টেটমেন্ট হিসেবে `TEST_IGNORE();` থাকা উচিত।
এর প্রথম উপস্থিতির পরে লাইন কমেন্ট `// delete this line to run test` থাকা উচিত।

উদাহরণস্বরূপ:

```c
static void test_the_first(void)
{
   test_first_foo();
}

static void test_the_second(void)
{
   TEST_IGNORE();               // delete this line to run test
   test_second_foo();
}

static void test_the_third(void)
{
   TEST_IGNORE();
   char grade = 'A';
   test_third_foo(grade);
}
```

ফাইলে সবার শেষে থাকে `main()` ফাংশন।
main-এর ফাংশন বডিও নিজে একটি নির্দিষ্ট বিন্যাস অনুসরণ করে।
প্রথমে `UNITY_BEGIN()`-এর একটি কল, তারপর একটি ফাঁকা লাইন, এরপর টেস্টগুলো।
শেষ টেস্টের পরে আরেকটি ফাঁকা লাইন থাকে, তারপর `UNITY_END()`-এর ফল রিটার্ন করা হয়।

```c
int main(void)
{
    UNITY_BEGIN();

    RUN_TEST(test_foo);
    RUN_TEST(test_bar);

    return UNITY_END();
}
```
