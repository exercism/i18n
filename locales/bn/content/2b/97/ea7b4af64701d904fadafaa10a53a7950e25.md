# পরিচিতি

হ্যাশ-সেট [`sets`][sets] [প্রোটোকল][set-protocol] ইমপ্লিমেন্ট করে, ভেতরে হ্যাশিং ব্যবহার করে, ফলে গড়ে O(1) ইনসার্ট, লুকআপ আর ডিলিট পাওয়া যায়। এগুলোকে জায়গাতেই বদলানো যায়, ফলে গ্রাফ ট্রাভার্সালের *ভিজিটেড সেট* প্যাটার্নের জন্য এগুলো আদর্শ।

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| ওয়ার্ড          | ইফেক্ট                                    |
|---------------|-------------------------------------------|
| `HS{ }`       | খালি হ্যাশ-সেট লিটারাল (শেয়ার করা, `clone` করুন!) |
| `>hash-set`   | `( seq -- set )`, একটি সিকোয়েন্স থেকে নতুন সেট তৈরি করে (ডুপ্লিকেট বাদ দেয়) |
| `adjoin`      | `( elt set -- )`, ডেস্ট্রাকটিভ ইনসার্ট     |
| `in?`         | `( elt set -- ? )`, মেম্বারশিপ           |
| `delete`      | `( elt set -- )`, ডেস্ট্রাকটিভ রিমুভ     |
| `cardinality` | `( set -- n )`, এলিমেন্টের সংখ্যা       |
| `null?`       | `( set -- ? )`, সেট খালি থাকলে ট্রু |
| `members`     | `( set -- seq )`, সিকোয়েন্স হিসেবে এনুমারেট করে  |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )`, `set`-কে `exemplar`-এর ক্লাসে কোয়ার্স করে |

আপনার কাছে আগে থেকেই থাকা ডেটা থেকে সেট তৈরি করতে `>hash-set` যেকোনো সিকোয়েন্সকে এক ধাপে রূপান্তর করে, ডুপ্লিকেটগুলো বাদ দিয়ে। `{ 2 3 2 5 } >hash-set` দেয় `HS{ 2 3 5 }`. বারবার `adjoin` দিয়ে সেট বাড়ানোর বাল্ক সংস্করণ এটি।

`in?` আর `member?` (যা `sequences` থেকে আসে) নিয়ে একটি সূক্ষ্ম বিষয়: দুটোই মেম্বারশিপ পরীক্ষা করে, কিন্তু `member?` একটি সিকোয়েন্সের উপর লিনিয়ার স্ক্যান করে, আর `in?` সেট টাইপের প্রোটোকল মেথড যেটাই হোক সেটিতে ডিসপ্যাচ করে। `HS{ }`-এর ক্ষেত্রে সেটা একটি হ্যাশ লুকআপ। আপনার “ভিজিটেড” কন্টেইনারে হাতেগোনা কয়েকটির বেশি এন্ট্রি থাকলে `in?` ব্যবহার করুন।

`null?` পুরো `cardinality` হিসাব না করেই উত্তর দেয় “এই সেটটি কি খালি?”। “প্রসেস করার মতো কিছু কি এখনো বাকি আছে?”-এর স্বাভাবিক গার্ড এটি। ওয়ার্কলিস্ট সেট হিসেবে রাখলে `[ set null? ] [ … ] until` এটিকে খালি হওয়া পর্যন্ত নিঃশেষ করে।

## হ্যাশটেবলের সাথে দারুণ মানায়

“X কি ভিজিটেড?”-এর জন্য `HS{ }` স্বাভাবিকভাবেই মানায় “X-এর প্রতিবেশী কারা?”-এর জন্য `H{ }`-এর সাথে। একটি পাঠ্যবইয়ের DFS হলো শুধু:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

ভিজিটেড সেট কাজের পুনরাবৃত্তি বাদ দেয়; স্ট্যাক ফ্রন্টিয়ার নোডগুলো বহন করে (`push`/`pop` দিয়ে LIFO); প্রতিবেশী ম্যাপ (একটি হ্যাশটেবল) গ্রাফ সরবরাহ করে। রিচেবিলিটির প্রশ্নে ভিজিটেশনের ক্রম গুরুত্বপূর্ণ নয়, তাই স্ট্যাক হিসেবে একটি ভেক্টরই যথেষ্ট। একই আকৃতির একটি সত্যিকারের BFS অবশ্য ভেক্টরের বদলে একটি [`<dlist>`][dlist] ব্যবহার করে এবং সামনের দিক থেকে ডিকিউ করে।
