# ভূমিকা

Elm-এ [কাস্টম টাইপ][custom-types] এক নির্দিষ্ট সংখ্যক নামযুক্ত কেস প্রকাশ করে। প্রতিটি মান এই নামযুক্ত কেসগুলোর ঠিক একটির সাথে মিলে যায়।

একটি কাস্টম টাইপ `type` কিওয়ার্ড দিয়ে ডিফাইন করা হয় এবং এতে খুব সামান্য সিনট্যাক্স লাগে। এগুলো Elm প্রোগ্রামিংয়ের সবচেয়ে গুরুত্বপূর্ণ কৌশলগুলোর একটি। এগুলো ব্যবহার করে কোডে সম্ভাব্য মানগুলোকে বাস্তব জীবনের বৈধ মানের সাথে হুবহু মিলিয়ে ফেলা হয়, যার ফলে অবৈধ ডেটার কোনো সুযোগই থাকে না, আর [কোডে অসম্ভব অবস্থা প্রকাশ করা অসম্ভব হয়ে পড়ে][impossible-states]।

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

একটি কাস্টম টাইপের প্রতিটি কেসের সাথে ঐচ্ছিকভাবে ডেটা যুক্ত থাকতে পারে, আর ভিন্ন ভিন্ন কেসে ভিন্ন ভিন্ন টাইপের ডেটা থাকতে পারে। কোনো কেসের সাথে যদি কোনো ডেটা যুক্ত না থাকে, তাহলে এই ডিসক্রিমিনেটেড ইউনিয়ন অন্য ভাষায় সাধারণত যাকে _এনুমারেশন_ (বা _এনাম_) বলা হয়, তার মতোই।

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

কোনো নির্দিষ্ট কেসের জন্য একটি মান তৈরি করা যায় এর নাম (`Spring`) উল্লেখ করে, যদি সেটি একই মডিউলে ডিফাইন করা থাকে বা `import SeasonModule exposing (Season(..))` ধরনের সিনট্যাক্স দিয়ে ইমপোর্ট করা হয়; অথবা এর সম্পূর্ণ কোয়ালিফায়েড নাম (`Season.Spring`) উল্লেখ করে, যদি `import SeasonModule exposing (Season)` ধরনের সিনট্যাক্স দিয়ে ইমপোর্ট করা হয়।

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Elm-এর সবকিছুর মতো কাস্টম টাইপেও _স্ট্রাকচারাল ইকুয়ালিটি_ আছে, যার মানে একই কেসের এবং একই (ঐচ্ছিক) ডেটাসহ দুটি মান সমতুল্য।

কাস্টম টাইপ নিয়ে কাজ করার সবচেয়ে পছন্দের উপায় হলো [প্যাটার্ন ম্যাচিং][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
