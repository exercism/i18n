# সম্পর্কে

C#-এর প্রধান অবজেক্ট-ওরিয়েন্টেড গঠন হলো _ক্লাস_, যা ডেটা ([_ফিল্ড_][fields]) ও আচরণের ([_মেথড_][methods]) সমন্বয়। একটি ক্লাসের ফিল্ড ও মেথডগুলোকে তার _মেম্বার_ বলা হয়।

অ্যাক্সেস মডিফায়ারের মাধ্যমে মেম্বারগুলোতে প্রবেশাধিকার সীমিত করা যায়, যার মধ্যে সবচেয়ে কমন দুটি হলো:

- [`public`][public]: যেকোনো কোড থেকে মেম্বারটিতে অ্যাক্সেস করা যায় (কোনো বিধিনিষেধ নেই)।
- [`private`][private]: কেবল একই ক্লাসের কোড থেকেই মেম্বারটিতে অ্যাক্সেস করা যায়।

সব মেম্বারের জন্য একটি অ্যাক্সেস মডিফায়ার উল্লেখ করার প্রথা রয়েছে। কোনো অ্যাক্সেস মডিফায়ার উল্লেখ না করা হলে এটি ডিফল্টভাবে `private` হয়ে যায়।

সংশ্লিষ্ট ডেটা ও আচরণের উপরোক্ত একত্রীকরণ এবং মেম্বারগুলোতে অ্যাক্সেস সীমাবদ্ধ করার প্রক্রিয়াটিকে [এনক্যাপসুলেশন][encapsulation] বলা হয়, যা অবজেক্ট-ওরিয়েন্টেড ধারণাগুলোর একটি মূল ভিত্তি।

কোনো একটি নির্দিষ্ট সময়ে একটি অবজেক্টের ফিল্ড ভ্যালুগুলোর সমষ্টিকে অবজেক্টটির [স্টেট][object-state] বলা হয়।

আপনি একটি ক্লাসকে ওই ক্লাসের ইনস্ট্যান্স তৈরির টেমপ্লেট হিসেবে ভাবতে পারেন। একটি ক্লাসের ইনস্ট্যান্স তৈরি করতে (যাকে _অবজেক্ট_ও বলা হয়) [`new` কিওয়ার্ড][new] ব্যবহার করা হয়:

```csharp
class Car
{
}

// Create two car instances
var myCar = new Car();
var yourCar = new Car();
```

[ফিল্ড][fields]-এর একটি টাইপ থাকে এবং এগুলো ক্লাসের যেকোনো জায়গায় ডিফাইন করা যায়।
পাবলিক ফিল্ড [PascalCase][pascal-case] পদ্ধতিতে ডিফাইন করা হয় আর প্রাইভেট ফিল্ড [camelCase][camel-case] পদ্ধতিতে ডিফাইন করে নামের আগে একটি আন্ডারস্কোর `_` বসানো হয়:

```csharp
class Car
{
    // Accessible by anyone
    public int Weight;

    // Only accessible by code in this class
    private string _color;
}
```

চাইলে একটি ফিল্ডে একটি প্রাথমিক মান অ্যাসাইন করা যায়। কোনো ফিল্ডে প্রাথমিক মান উল্লেখ করা _না_ থাকলে সেটি তার টাইপের [ডিফল্ট ভ্যালু][default-values]-তে সেট হয়ে যায়। ডট-নোটেশন ব্যবহার করে একটি ইনস্ট্যান্সের ফিল্ড ভ্যালু অ্যাক্সেস ও আপডেট করা যায়।

```csharp
class Car
{
    // Will be set to specified value
    public int Weight = 2500;

    // Will be set to default value (0)
    public int Year;
}

var newCar = new Car();
newCar.Weight; // => 2500
newCar.Year;   // => 0

// Update value of the field
newCar.Year = 2018;
```

সাধারণত একটি মেথড কল করার সাইড এফেক্ট হিসেবে প্রাইভেট ফিল্ড আপডেট হয়। এমন মেথড সাধারণত কোনো মান রিটার্ন করে না, সেক্ষেত্রে রিটার্ন টাইপ [`void`][void] হওয়া উচিত:

```csharp
class CarImporter
{
    private int _carsImported;

    public void ImportCars(int numberOfCars)
    {
        // Update private field
        _carsImported = _carsImported + numberOfCars;
    }
}
```

মনে রাখবেন, C# ক্লাসে পাবলিক ফিল্ড ব্যবহার করা প্রথাগত নয়। হয় প্রাইভেট ফিল্ড ব্যবহার করা হয়, নয়তো অন্য ধরনের মেম্বার, যা পরবর্তী অনুশীলনীগুলোতে আলোচনা করা হবে।

একটি ক্লাসের ভেতরে [`this` কিওয়ার্ড][this] বর্তমান ক্লাসকে বোঝায়। এটি বিশেষভাবে কাজে লাগে যখন কোনো প্যারামিটারের নাম কোনো ফিল্ডের নামের সাথে একই হয়:

```csharp
class CarImporter
{
    private int carsImported;

    public void SetImportedCars(int carsImported)
    {
        // Update private field from public method
        this.carsImported = carsImported;
    }
}
```

ক্লাস ও মেথডের এই গঠন ফিল্ড ও মেথডের মতো প্রোগ্রাম এলিমেন্টের ভিজিবিলিটি সীমিত করার এবং সুপরিচিত [গ্লোবাল স্টেটের সমস্যা][so-global-state-problem] এড়ানোর একটি স্বাভাবিক উপায় দেয়। ক্লাসের বাইরের কোড থেকে দেখা যাওয়ার জন্য পাবলিক ফিল্ড, মেথড ও অন্যান্য মেম্বারকে অবজেক্টের নাম দিয়ে কোয়ালিফাই করতে হয়, `object.field` বা `object.method()`, (স্ট্যাটিকের ক্ষেত্রে ক্লাসের নাম)। একটি মেথডের ভেতরে ডিক্লেয়ার করা ভ্যারিয়েবল ও প্যারামিটার কেবল ওই মেথডের ভেতরেই দেখা যায়।

এই পদ্ধতিতে সতর্ক থাকার একটি বিষয় হলো, যদি কোনো ফিল্ডের নাম এবং মেথডের ভেতরের কোনো ভ্যারিয়েবল বা প্যারামিটারের নাম একই হয়, তাহলে মেথডের ভেতরের কোড ফিল্ডের নামটি উপেক্ষা করবে, যা আপনি হয়তো চান না। সাধারণভাবে, যেখানে সম্ভব এটি এড়িয়ে চলা উচিত, যদিও কনস্ট্রাক্টরে এটি একটি কমন প্যাটার্ন। ফিল্ড ও ভ্যারিয়েবলের নাম একই হওয়া যদি যথাযথ হয়, তাহলে মেথডের ভেতরে ফিল্ডের নামটি `this` কিওয়ার্ড দিয়ে কোয়ালিফাই করুন।

এই [অ্যাক্সেস মডিফায়ারগুলো][access-modifiers] ব্যবহার করে ভিজিবিলিটি আরও সীমিত করা যায়।
