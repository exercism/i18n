# ভূমিকা

## স্ট্রিং

### ক্যারেক্টার

একটি **ক্যারেক্টার এনকোডিং** হলো একটি নির্দিষ্ট রীতি, যা দিয়ে কোনো স্বাভাবিক ভাষার টেক্সটের উপাদানগুলোকে বাইটের একটি ধারা হিসেবে প্রকাশ করা হয়। এখানে "টেক্সটের উপাদান" বলতে স্বাভাবিক ভাষায় অর্থবহ যেকোনো একক বোঝায়, যেমন বর্ণ, স্পেস, যতিচিহ্ন, ইমোজি, আইডিওগ্রাম ইত্যাদি।

NASM-এ (The Netwide Assembler, এই ট্র্যাকে ব্যবহৃত অ্যাসেম্বলার) **ASCII** দিয়ে ডেটা ডিফাইন করার সাপোর্ট আছে।

NASM-এ ক্যারেক্টার কনস্ট্যান্ট সর্বোচ্চ ৮ বাইট লম্বা হতে পারে এবং একক কোট (`'`), দ্বৈত কোট (`"`) বা ব্যাকটিক (`` ` ``) দিয়ে ডিফাইন করা যায়:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

বিশেষ ক্যারেক্টার ব্যাকটিকের মধ্যে ডিফাইন করতে হবে এবং `\` দিয়ে এস্কেপ করতে হবে:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

মনে রাখবেন, x86-64-এ আলাদা টাইপ হিসেবে কোনো ক্যারেক্টার এনকোডিংয়ের বিল্ট-ইন সাপোর্ট নেই। অ্যাসেম্বলিতে ডেটা হলো বাইটের একটি ধারা, আর ওই বাইটগুলোকে ক্যারেক্টার, সংখ্যা বা অন্য যেকোনো কিছু হিসেবে ব্যাখ্যা করা প্রোগ্রামারের উপর ছেড়ে দেওয়া হয়।

উদাহরণস্বরূপ, ASCII ক্যারেক্টার '0' হলো 48 মানের একটি একক বাইট। তাই একটি বাইটে 48 সংরক্ষণ করা আর ASCII ক্যারেক্টার '0' সংরক্ষণ করা একেবারে একই কাজ:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

ঠিক এই কারণেই, ক্যারেক্টার নিয়ে কাজ করা হয় ওই বাইটগুলোর মান সরাসরি পরিবর্তন করে:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### স্ট্রিং

একটি **স্ট্রিং** হলো ক্যারেক্টারের একটি ধারা। অ্যাসেম্বলিতে এটি সাধারণত একটি অ্যারে হিসেবে তৈরি করা হয়।

NASM-এ যেকোনো অ্যারে যেভাবে ডিক্লেয়ার করা যায়, ঠিক সেভাবেই একটি স্ট্রিং ডিক্লেয়ার করা সম্ভব:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

স্ট্রিং আর অন্য অ্যারের মধ্যে একটি পার্থক্য হলো, NASM-এ মানগুলোর মাঝে কমা (`,`) ছাড়াও স্ট্রিং ডিক্লেয়ার করার সাপোর্ট আছে। কমা দিয়ে মানগুলো মিশিয়েও লেখা যায়:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

মনে রাখবেন, আগেই বলা হয়েছে, ক্যারেক্টার আসলে শুধু বাইট (বা ইউনিকোড এনকোডিংয়ে বাইটের একটি ধারা):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

যেহেতু প্রতিটি ASCII ক্যারেক্টার এক বাইট জায়গা নেয়, তাই বড় আকারে নেওয়া হলে পরের প্রতিটি বাইট `0` হয়। যেমন, `'a'`-কে একটি কিউয়ার্ড (৮ বাইট) হিসেবে ডিক্লেয়ার করলে প্রথম বাইটটি হয় `'a'` (`97`) এবং বাকি সাতটি বাইট সবই `0`।

এই কারণেই, এগুলো সবই সমতুল্য:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
অ্যাসেম্বলিতে স্ট্রিং কোনো ASCII NUL ক্যারেক্টার (মান `0`) দিয়ে স্বয়ংক্রিয়ভাবে শেষ হয় না।

C-এর মতো উচ্চস্তরের ভাষার সাথে ইন্টারফেস করার সময়, স্ট্রিংয়ের শেষে সঠিক টার্মিনেটর (যদি থাকে) যোগ করা প্রোগ্রামারের দায়িত্ব।
~~~~

### স্ট্রিং ইনস্ট্রাকশন

যেহেতু স্ট্রিং হলো অ্যারে, তাই যেকোনো অ্যারের মতোই স্পষ্টভাবে মেমোরি ডিরেফারেন্স করে এগুলোর সাথে একইভাবে কাজ করা যায়:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

এর বাইরে, মেমোরিতে বাইটের ধারায় মান লোড, মুভ এবং স্টোর করার জন্য কিছু ইনস্ট্রাকশন আছে। যদিও এগুলোকে _স্ট্রিং ইনস্ট্রাকশন_ বলা হয়, এগুলো মেমোরিতে যেকোনো বাইটের ধারার সাথে, অর্থাৎ যেকোনো অ্যারের সাথে ব্যবহার করা যায়।

সবচেয়ে গুরুত্বপূর্ণ তিনটি স্ট্রিং ইনস্ট্রাকশন হলো `lods`, `stos` এবং `movs`:

| ইনস্ট্রাকশন | এটি যা করে |
| ----------- | -------------------------------------------------------------------------------------------------------------- |
| `lods`      | `rsi` দিয়ে নির্দেশিত একটি মেমোরি লোকেশন থেকে `rax`-এ একটি মান লোড করে                                       |
| `stos`      | `rax` থেকে `rdi` দিয়ে নির্দেশিত একটি মেমোরি লোকেশনে একটি মান স্টোর করে                                       |
| `movs`      | `rsi` দিয়ে নির্দেশিত একটি মেমোরি লোকেশন থেকে একটি মান কপি করে `rdi` দিয়ে নির্দেশিত একটি মেমোরি লোকেশনে স্টোর করে |

মনে রাখবেন, এই ইনস্ট্রাকশনগুলো কোনো স্পষ্ট অপারেন্ড নেয় না। এগুলোর অপারেন্ড অন্তর্নিহিত।

সাধারণ নিয়ম হিসেবে:

1. যখন এগুলোর সোর্স অপারেন্ড একটি মেমোরি লোকেশন হয়, তার অ্যাড্রেস `rsi`-তে রাখা উচিত (`s` মানে source)।
2. যখন এগুলোর ডেস্টিনেশন অপারেন্ড একটি মেমোরি লোকেশন হয়, তার অ্যাড্রেস বরং `rdi`-তে রাখা উচিত (`d` মানে destination)।
3. যদি কোনো অপারেন্ড মেমোরি লোকেশন না হয়, তবে সেটি `rax` রেজিস্টার।

মনে রাখবেন, এই ইনস্ট্রাকশনগুলো যে নির্দিষ্ট অপারেশন করে, সেই অনুযায়ী মেমোরি অ্যাড্রেস স্বয়ংক্রিয়ভাবে ডিরেফারেন্স করে।

এগুলো সবই ভিন্ন ভিন্ন আকারে কাজ করতে পারে। আকার বোঝাতে একটি সাফিক্স যোগ করা হয়:

| সাফিক্স | অর্থ | আকার    |
| :----: | ------- | :------ |
|  `b`   | বাইট    | ১ বাইট  |
|  `w`   | ওয়ার্ড   | ২ বাইট |
|  `d`   | ডুয়ার্ড   | ৪ বাইট |
|  `q`   | কিউয়ার্ড   | ৮ বাইট |

উদাহরণস্বরূপ:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

এগুলো যে অ্যাড্রেস ব্যবহার করে, সেটিও অপারেশনের আকার অনুযায়ী আপডেট করে। এই আপডেটটি করা হয় **ডিরেকশন ফ্ল্যাগ (DF)**-এর মান অনুযায়ী:

- যদি `DF` ক্লিয়ার থাকে, অ্যাড্রেসগুলো অপারেশনের আকার অনুযায়ী _বাড়ে_।
- যদি `DF` সেট থাকে, অ্যাড্রেসগুলো বরং একই পরিমাণ _কমে_।

System V ABI বলে, ফাংশনে প্রবেশের সময় ডিরেকশন ফ্ল্যাগ ক্লিয়ার থাকতে হবে। তাই, _ডিফল্ট আচরণ হলো মেমোরি অ্যাড্রেসের ঊর্ধ্বক্রমে পড়া ও লেখা হবে_।

`cld` ইনস্ট্রাকশন দিয়ে ডিরেকশন ফ্ল্যাগ ক্লিয়ার করা যায়, আর `std` ইনস্ট্রাকশন দিয়ে সেট করা যায়:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
System V ABI অনুযায়ী, কল করা কোনো ফাংশন ফিরে আসার পরে কলার আশা করে `DF` ক্লিয়ার থাকবে। আপনি যদি কখনো `DF` সেট করেন, `ret`-এর আগে সেটি ক্লিয়ার করা নিশ্চিত করুন।
~~~~

#### Rep

এগুলো ছাড়াও, **rep** ইনস্ট্রাকশনটি সরাসরি মেমোরির সাথে কাজ করে না। বরং, উপরে উল্লিখিত অন্য ইনস্ট্রাকশনগুলোর আগে এটি একটি প্রিফিক্স হিসেবে যোগ করা যায়, যা ওই ইনস্ট্রাকশনগুলোকে _পুনরাবৃত্তি_ করে।

`rep` প্রিফিক্স হিসেবে বসালে, স্ট্রিং ইনস্ট্রাকশনগুলো `rcx`-এর মানের সমান সংখ্যক বার পুনরাবৃত্তি হয়। প্রতিবার `rcx`-এর মান `1` কমে। মনে রাখবেন, ইনস্ট্রাকশনটি ব্যবহার করার আগে `rcx`-এর মান সেট করে নিতে হবে:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
আধুনিক CPU-তে, বড় ব্লকে ডেটা সরানোর সময় `rep movs` আর `rep stos` সাধারণত দ্রুত একটি বিকল্প। তবে অন্য স্ট্রিং ইনস্ট্রাকশনগুলো, এমনকি `rep` ছাড়া কাজ করা `movs` আর `stos`-ও সাধারণত সাধারণ একটি লুপের চেয়ে ধীর।
