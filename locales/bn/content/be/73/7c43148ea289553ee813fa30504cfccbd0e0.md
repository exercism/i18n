# সম্পর্কে

অন্যান্য অনেক ভাষার মতো Go-তেও পয়েন্টার আছে।
আপনি যদি পয়েন্টারে নতুন হন, তবে প্রথমে এগুলো একটু রহস্যময় লাগতে পারে, কিন্তু একবার অভ্যস্ত হয়ে গেলে এগুলো বেশ সোজাসাপ্টা।
এগুলো Go-র একটি অত্যন্ত গুরুত্বপূর্ণ অংশ, তাই এগুলো সত্যিই বুঝে নিতে একটু সময় নিন।

বিস্তারিত আলোচনায় যাওয়ার আগে পয়েন্টারের ব্যবহার বোঝা ভালো।
পয়েন্টার হলো আমাদের প্রোগ্রামের অন্যান্য অংশের সাথে মেমরি ভাগ করে নেওয়ার একটি উপায়, যা দুটি প্রধান কারণে কাজে লাগে:

1. যখন আমাদের কাছে প্রচুর পরিমাণ ডেটা থাকে, তখন ফাংশনের মধ্যে পাস করার জন্য কপি তৈরি করা খুবই অদক্ষ।
   এর বদলে ডেটা যেখানে সংরক্ষিত আছে সেই মেমরি লোকেশনটি পাস করে আমরা আমাদের প্রোগ্রামের রিসোর্স-ফুটপ্রিন্ট নাটকীয়ভাবে কমিয়ে আনতে পারি।
2. ফাংশনের মধ্যে পয়েন্টার পাস করার মাধ্যমে আমরা ডেটার একক কপিটি সরাসরি অ্যাক্সেস ও পরিবর্তন করতে পারি, অর্থাৎ একটি ফাংশন যে পরিবর্তনই করুক, ফাংশনটি শেষ হওয়ার সাথে সাথে তা প্রোগ্রামের অন্যান্য অংশের কাছে দৃশ্যমান হয়ে যায়।

## ভ্যারিয়েবল ও মেমরি

ধরা যাক আমাদের একটি সাধারণ ইন্টিজার ভ্যারিয়েবল `a` আছে:

```go
var a int
```

আমরা যখন একটি ভ্যারিয়েবল ডিক্লেয়ার করি, তখন তার মান সংরক্ষণের জন্য Go-কে মেমরিতে একটি জায়গা খুঁজে বের করতে হয়।
এটি মূলত আমাদের কাছ থেকে আড়ালে থাকে; যখন ওই মেমরি খণ্ডে সংরক্ষিত মানটি আনতে হয়, তখন আমরা শুধু ভ্যারিয়েবলের নাম দিয়েই তা উল্লেখ করতে পারি।

যেমন, আমরা যখন `a + 2` লিখি, তখন আসলে ভ্যারিয়েবল `a`-এর সাথে সংশ্লিষ্ট মেমরিতে সংরক্ষিত মানটি এনে তার সাথে 2 যোগ করছি।

একইভাবে, যখন `a`-এর মেমরি খণ্ডে থাকা মানটি পরিবর্তন করতে হয়, তখন অ্যাসাইনমেন্ট করতে আমরা ভ্যারিয়েবলের নাম ব্যবহার করতে পারি:

```go
a = 3
```

`a`-এর সাথে সংশ্লিষ্ট মেমরি খণ্ডে এখন `3` মানটি সংরক্ষিত থাকবে।

## পয়েন্টার

ভ্যারিয়েবল আমাদের মেমরিতে থাকা মান নির্দেশ করার সুযোগ দেয়, তবে মাঝে মাঝে ভ্যারিয়েবলটি যে **মেমরি অ্যাড্রেস**-এর দিকে নির্দেশ করছে সেটি জানা কাজে লাগে।
**পয়েন্টার** ওই মানগুলোর মেমরি অ্যাড্রেস ধরে রাখে।
আপনি একটি ভ্যারিয়েবল পয়েন্টার টাইপে ডিক্লেয়ার করেন, এর অন্তর্নিহিত টাইপের আগে একটি অ্যাস্টেরিস্ক বসিয়ে:

```go
var p *int // 'p' contains the memory address of an integer
```

এখানে আমরা `p` নামের একটি ভ্যারিয়েবল ডিক্লেয়ার করছি, যার টাইপ "int-এর পয়েন্টার" (`*int`)।
এর মানে হলো, `p` একটি ইন্টিজারের মেমরি অ্যাড্রেস ধরে রাখবে।
পয়েন্টারের শূন্য মান হলো `nil`, কারণ একটি `nil` পয়েন্টার কোনো মেমরি অ্যাড্রেস ধরে রাখে না।

### একটি ভ্যারিয়েবলের পয়েন্টার পাওয়া

একটি ভ্যারিয়েবলের মানের মেমরি অ্যাড্রেস খুঁজে বের করতে আমরা `&` অপারেটর ব্যবহার করতে পারি।
যেমন, আমরা যদি ভ্যারিয়েবল `a`-এর মেমরি অ্যাড্রেস খুঁজে বের করে পয়েন্টার `p`-তে সংরক্ষণ করতে চাই, তাহলে এভাবে করতে পারি:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### পয়েন্টারের মাধ্যমে মান অ্যাক্সেস করা (ডিরেফারেন্সিং)

আমাদের কাছে একটি পয়েন্টার থাকলে, পয়েন্টারটি যে মেমরি অ্যাড্রেস নির্দেশ করে সেখানে সংরক্ষিত মানটি আমরা জানতে চাইতে পারি।
এটি আমরা `*` অপারেটর দিয়ে করতে পারি:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p` অপারেশনটি `p`-তে সংরক্ষিত মেমরি অ্যাড্রেসে থাকা মানটি এনে দেয়।
এই অপারেশনটিকে প্রায়ই "ডিরেফারেন্সিং" বলা হয়।

পয়েন্টারটি যে মেমরি অ্যাড্রেস নির্দেশ করে সেখানে নতুন মান অ্যাসাইন করতেও আমরা ডিরেফারেন্স অপারেটর ব্যবহার করতে পারি:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa`-তে অ্যাসাইন করলে `pa` যে মেমরি অ্যাড্রেস ধরে রেখেছে সেখানে সংরক্ষিত মানটি বদলে যাবে।
যেহেতু `pa` `a`-এর মেমরি অ্যাড্রেস ধরে রেখেছে, তাই `*pa`-তে অ্যাসাইন করার মাধ্যমে আমরা আসলে `a`-এর মানই বদলাচ্ছি!

তবে একটি সতর্কবার্তা: ডিরেফারেন্স করার আগে সবসময় দেখে নিন পয়েন্টারটি `nil` নয় কি না।
একটি `nil` পয়েন্টার ডিরেফারেন্স করলে প্রোগ্রামটি রানটাইমে ক্র্যাশ করবে!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### স্ট্রাক্টের পয়েন্টার

এখন পর্যন্ত আমরা কেবল প্রিমিটিভ মানের পয়েন্টার দেখেছি।
স্ট্রাক্টের জন্যও আমরা পয়েন্টার তৈরি করতে পারি:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

আমরা নতুন একটি `Person` তৈরি করে সাথে সাথেই তার একটি পয়েন্টার সংরক্ষণও করতে পারতাম:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

স্ট্রাক্টের একটি পয়েন্টার থাকলে, কোনো ফিল্ড অ্যাক্সেস করার আগে পয়েন্টারটি ডিরেফারেন্স করার দরকার পড়ে না:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## স্লাইস ও ম্যাপ ইতিমধ্যেই পয়েন্টার

স্লাইস ও ম্যাপ বিশেষ টাইপ, কারণ এদের ইমপ্লিমেন্টেশনে আগে থেকেই পয়েন্টার থাকে।
এর মানে হলো, বেশিরভাগ ক্ষেত্রেই এদের মানের মেমরি অ্যাড্রেস ভাগ করে নিতে এই টাইপগুলোর জন্য পয়েন্টার তৈরি করার দরকার পড়ে না।
ধরা যাক আমাদের একটি ফাংশন আছে যা একটি ম্যাপের একটি কী (key)-এর মান বাড়ায়:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

আমরা যদি একটি ম্যাপ তৈরি করে এই ফাংশনটি কল করি, তাহলে ফাংশনটি ম্যাপে যে পরিবর্তন করেছে তা ফাংশন শেষ হওয়ার পরও টিকে থাকে।
পয়েন্টার ব্যবহার করলে আমরা একই রকম আচরণ পেতাম, কিন্তু লক্ষ্য করুন এই উদাহরণে আমরা রেফারেন্সিং/ডিরেফারেন্সিং বা পয়েন্টারের কোনো সিনট্যাক্সই ব্যবহার করছি না:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

স্লাইসে থাকা কোনো বিদ্যমান এলিমেন্ট পরিবর্তন করার ক্ষেত্রেও একই কথা প্রযোজ্য।

তবে `append`-এর মতো নতুন স্লাইস রিটার্ন করা কাজ একটি বিশেষ ক্ষেত্র, এবং সেগুলো ফাংশনের বাইরের স্লাইসটি **নাও** পরিবর্তন করতে পারে।
এটি স্লাইস অভ্যন্তরীণভাবে যেভাবে কাজ করে তার কারণে ঘটে, কিন্তু এটি আরও অ্যাডভান্সড একটি বিষয়, তাই আমরা এটা বিস্তারিত আলোচনা করব না।
আপনি যদি সত্যিই কৌতূহলী হন, তবে এ বিষয়ে [Go Blog: Mechanics of 'append'][mechanics-of-append] পোস্টে আরও পড়তে পারেন।

## পয়েন্টার অ্যারিথমেটিক

অন্যান্য ভাষার মতো নয়, Go পয়েন্টার অ্যারিথমেটিক সমর্থন করে না।
এর মানে হলো, পয়েন্টারের মান বাড়িয়ে আপনি এক মানের মেমরি অ্যাড্রেস থেকে আরেক মানের অ্যাড্রেসে যেতে পারবেন না।
তাই নিচের মতো স্নিপেটগুলো বৈধ নয়:

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
