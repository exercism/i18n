# পরিচিতি

## পার্শিয়াল অ্যাপ্লিকেশন ও ফাংশন কম্পোজিশন

### পার্শিয়াল অ্যাপ্লিকেশন

এলমের সব ফাংশনই [কারিড][currying], অর্থাৎ আপনি যদি সব আর্গুমেন্ট পাস না করে কোনো ফাংশন কল করেন, তাহলে সেটি একটি নতুন ফাংশন রিটার্ন করে।

এভাবে করার ফলাফলকে বলা হয় [পার্শিয়াল অ্যাপ্লিকেশন][partial-application] (আপনি ফাংশনটিকে সব আর্গুমেন্ট পাস করছেন না, বরং তার কয়েকটি আংশিকভাবে প্রয়োগ করছেন)।

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

পার্শিয়াল অ্যাপ্লিকেশন সবসময় ক্রমানুসারে আর্গুমেন্ট প্রয়োগ করে।

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

### পাইপ অপারেটর (`|>`)

`x |> f` লেখা ঠিক `f x` লেখার মতোই। একটি নির্দিষ্ট উদাহরণ হলো `"5" |> String.toInt`, যা `String.toInt "5"` এর সমান।

প্রথমে এটা খুব একটা কাজের মনে হয় না, কিন্তু এটিকে [পাইপ অপারেটর][pipe-operator] বলা হয় কারণ এটি দিয়ে আপনি "পাইপলাইন করা" কোড লিখতে পারেন।

উদাহরণস্বরূপ, ধরা যাক আমাদের একটি sanitize ফাংশন আছে, যা ব্যবহারকারীর ইনপুটকে ইন্টিজারে রূপান্তর করে:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

আমরা এটি এভাবে আবার লিখতে পারি:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

এতে বন্ধনীর ব্যবহার এড়ানো যায়, আর ফাংশনগুলো যে ক্রমে প্রয়োগ করা হয় সেই ক্রমেই দেখা যায় (প্রথমে `String.trim`, তারপর `String.toInt`), যা কোড পড়া সহজ করে।

এছাড়া একটি [রিভার্স পাইপ অপারেটর `(<|)`][reverse-pipe-operator]ও আছে।
`f <| x` লেখা ঠিক `f x` লেখার মতোই।
প্রথম দেখায় এটাও খুব একটা কাজের মনে হয় না, আর পাইপ অপারেটরের মতো এত বেশি ব্যবহৃতও হয় না, তবে কিছু কিছু ক্ষেত্রে এটি বন্ধনী এড়াতে সাহায্য করে।

### ফাংশন কম্পোজিশন / পয়েন্ট ফ্রি স্টাইল

[`(>>)`][forward-composition] অপারেটরের টাইপ `(a -> b) -> (b -> c) -> (a -> c)`, এবং এটি `a -> b ` ও `b -> c` টাইপের দুটি সামঞ্জস্যপূর্ণ ফাংশন কম্পোজ করে `a -> c` টাইপের একটি ফাংশন তৈরি করে।
এটি করে প্রথম ফাংশনের আউটপুট (টাইপ `b`) নিয়ে সেটিকে দ্বিতীয় ফাংশনের প্রথম আর্গুমেন্ট হিসেবে ব্যবহার করার মাধ্যমে (যার টাইপও একই `b` হতে হবে)।
তৈরি হওয়া ফাংশনটি প্রথম ফাংশনের মতোই একই ইনপুট (টাইপ `a`) নেবে, আর দ্বিতীয় ফাংশন যে `c` রিটার্ন করে সেটিই রিটার্ন করবে।

একটি নির্দিষ্ট উদাহরণ হলো `String.trim >> String.toInt`।
`String.trim` তার একমাত্র প্যারামিটার হিসেবে একটি স্ট্রিং নেয়, তাই তৈরি হওয়া ফাংশনও সেটিই নেয়।
`String.toInt` একটি `Maybe Int` রিটার্ন করে, তাই তৈরি হওয়া ফাংশনও সেটিই রিটার্ন করে।
`String.trim` একটি `String` রিটার্ন করে, যা `String.toInt` প্যারামিটার হিসেবে গ্রহণ করে, তাই উদাহরণটি কম্পাইল হয়।

এখন আমরা আমাদের `sanitize` ফাংশনটি এভাবে আবার লিখতে পারি:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

লক্ষ করুন, মূল উদাহরণে যে `input` প্যারামিটারটি দেখা যায়, আমরা আর সেটি ব্যবহার করছি না, যদিও কার্যকারিতা হুবহু একই।
নিজেদের প্যারামিটারের কোনো উল্লেখ না রেখে ফাংশন তৈরির এই পদ্ধতিকে বলা হয় "পয়েন্ট ফ্রি স্টাইল"।
এই স্টাইলের সুবিধা হলো কোড আরও সংক্ষিপ্ত হয়, আর অসুবিধা হলো এটি বোঝা কঠিন হতে পারে, বিশেষ করে নতুনদের জন্য।

মনে রাখা ভালো, এলমে সব ফাংশনই কারিড, তাই `String.length >> max` কম্পাইল হয়।

- [`(>>)`][forward-composition] অপারেটরের টাইপ `(a -> b) -> (b -> c) -> (a -> c)`।
- `String.length` এর টাইপ `String -> Int`, যা `(a -> b)` অংশটি, তাই `a` হলো `String` এবং `b` হলো - `Int`।
- `max` এর টাইপ `Int -> Int -> Int`, যা `b -> c` অংশটি।
- `b` হলো `Int`, তাই `max` পার্শিয়ালি অ্যাপ্লাইড হয়, তাই `c` হলো এই পার্শিয়াল অ্যাপ্লিকেশনের ফলাফল (`Int -> Int`)।
- তাই `String.length >> max` এর টাইপ `String -> (Int -> Int)`।
- তাই `((String.length >> max) "123") 2` রিটার্ন করে `3`, কারণ `"123"` এর দৈর্ঘ্য 3, যা `Int` আর্গুমেন্টের 2 থেকে বড়।

### ফাংশনের ডিজাইন

এলমে সহজে সুন্দর কোড লিখতে হলে, আপনার মূল ডেটা স্ট্রাকচারকে ফাংশনের শেষ প্যারামিটার করা উচিত।
স্ট্যান্ডার্ড লাইব্রেরির সব কমন ফাংশনই এটি করে, যেমন `List.map` (টাইপ সিগনেচার নিচে)।

```elm
map : (a -> b) -> List a -> List b
```

এখানে দেখা যাচ্ছে, `map` ফাংশনের শেষ প্যারামিটারটি `List a` এবং এটি `List b` রিটার্ন করে, তাই মূল ডেটা স্ট্রাকচার (`List`) শেষ প্যারামিটার।

এতে নিচের মতো সুন্দর পাইপলাইন করা কোড লেখা সম্ভব হয়।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

পাইপলাইনের বিকল্প হিসেবে ফাংশন কম্পোজিশন ও পয়েন্ট ফ্রি স্টাইল ব্যবহার করাও এতে সুবিধাজনক হয়ে ওঠে।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

ফাংশন কম্পোজিশন দিয়ে এই উদাহরণটিকে `List.map`-এর একটি মাত্র কলে নামিয়েও আনা যায়।

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
