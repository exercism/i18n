# পরিচিতি

Elixir [_বিহেভিয়ার_][behaviours] ব্যবহার করে সাধারণ জেনেরিক ইন্টারফেস দেয়, আর সেইসঙ্গে যে মডিউলগুলো বিহেভিয়ারটি ইমপ্লিমেন্ট করে, তাদের প্রত্যেকটির জন্য নির্দিষ্ট ইমপ্লিমেন্টেশন সহজ করে তোলে। এর মধ্যে একটি হলো _Access Behaviour_।

_Access Behaviour_ একটি ডেটা স্ট্রাকচার থেকে কী (key) দিয়ে সংশ্লিষ্ট ডেটা বের করার জন্য একটি সাধারণ ইন্টারফেস দেয়। এটি ম্যাপ ও কিওয়ার্ড লিস্টের জন্য ইমপ্লিমেন্ট করা হয়েছে।

[`Access`][access] মডিউলটি এই ইন্টারফেসের জন্য প্রয়োজনীয় কলব্যাকগুলো ডিফাইন করে। এরপর [`Map`][map] ও [`Keyword`][keyword] মডিউলগুলো প্রয়োজনীয় কলব্যাক [`fetch/2`][map-fetch], [`get_and_update/3`][map-get-and-update] আর [`pop/2`][map-pop] ইমপ্লিমেন্ট করে।

এই বিহেভিয়ারটি ব্যবহার করতে চাইলে আপনি কোনো বাউন্ড ভ্যারিয়েবলের পরে _স্কোয়ার ব্র্যাকেট_ বসাতে পারেন, তারপর সেই কী (key) দিয়ে তার সঙ্গে যুক্ত মানটি বের করতে পারেন। ম্যাপ যেকোনো টাইপের কী (key) সমর্থন করে, আর কিওয়ার্ড লিস্ট শুধু অ্যাটম কী (key)।

```elixir
# Atom as key
my_map = %{key: "my value"}
my_map[:key]
# => "my value"

# String as key
another_map = %{"key" => "my value"}
another_map["key"]
# => "my value"
```

ডেটা স্ট্রাকচারে যদি ওই কী (key) না থাকে, তাহলে `nil` রিটার্ন হয়। এটি অনিচ্ছাকৃত আচরণের উৎস হতে পারে, কারণ এটি কোনো এরর রেইজ করে না।

```elixir
my_map = %{key: "my value"}
my_map[:wrong_key][:other_wrong_key]
# => nil
```

মনে রাখবেন, `nil` নিজেই Access Behaviour ইমপ্লিমেন্ট করে এবং যেকোনো কী (key)-এর জন্য সবসময় `nil` রিটার্ন করে।

```elixir
nil[:key]
# => nil
```

স্ট্রাক্টগুলো Access Behaviour ইমপ্লিমেন্ট করে না।
