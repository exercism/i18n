# সম্পর্কে

একটি `GENERIC:` ডিক্লারেশন এমন একটি শব্দের সাথে পরিচয় করায়, যার আচরণ নির্ভর করে তার আর্গুমেন্টগুলোর একটির ক্লাসের উপর। নির্দিষ্ট আচরণ আসে নির্দিষ্ট ক্লাসকে লক্ষ্য করা *মেথড* (`M:`) থেকে।

```factor
GENERIC: stringify ( obj -- str )
M: integer stringify number>string ;
M: string  stringify ;
M: f       stringify drop "(none)" ;
```

`stringify` কল করা হলে Factor স্ট্যাকের একদম উপরের অংশটি দেখে, যার ক্লাস মিলে যায় এমন সবচেয়ে নির্দিষ্ট মেথডটি খুঁজে নেয় এবং সেটি রান করে। কোনো মেথড না মিললে একটি এরর থ্রো করা হয়।

## ডিসপ্যাচ ক্লাস

ডিফল্টভাবে ডিসপ্যাচ হয় সবার উপরের আর্গুমেন্টের উপর (স্ট্যাক ইফেক্টে যে ইনপুটটি প্রথমে লেখা থাকে)। একাধিক আর্গুমেন্টের উপর ডিসপ্যাচের জন্য দেখুন `HOOK:` ও `MATH:`, যারা যথাক্রমে দ্বিতীয় আর্গুমেন্টের উপর কিংবা সংখ্যাগত প্রমোশনের উপর ডিসপ্যাচ করে।

## জেনেরিকে মেথড যোগ করা

আপনি যেকোনো সময়ই একটি জেনেরিক বাড়িয়ে নিতে পারেন, এমনকি ভিন্ন কোনো ভোকাবুলারি থেকেও, শর্ত শুধু একটাই: জেনেরিক ও ক্লাস দুটোই যেন আপনি `USE:` করতে পারেন:

```factor
USING: math ;
M: ratio  area drop 0 ;     ! adds an `area` method for ratios
```

## বিল্ট-ইন ক্লাসের মেথড

জেনেরিক বিল্ট-ইন ক্লাসেও (`integer`, `string`, `array`, `f`, `t`) ঠিক তেমনি কাজ করে, যেমনটি করে ব্যবহারকারীর তৈরি টাপলের উপর। `f` ও `t`-এর মেথডগুলো "is-set?" ধরনের প্রেডিকেটের জন্য বিশেষভাবে কাজে লাগে, যাদের স্বাভাবিক ডিফল্ট থাকে।

## কখন জেনেরিকই সঠিক পছন্দ

নিচের ক্ষেত্রে `GENERIC:` বেছে নিন:

- একটি একক অপারেশনের জন্য ভিন্ন ভিন্ন ইনপুটে *সত্যিই আলাদা* ইমপ্লিমেন্টেশন থাকে (শুধু লেবেলের উপর একটি `case` নয়)।
- আপনি আশা করেন যে পরে অন্য কোড নতুন টাইপ যোগ করবে।
- আপনি চান টাইপ সিস্টেমটি নিশ্চিত করুক যে সব প্রাসঙ্গিক ক্লাসের জন্যই অপারেশনটি ডিফাইন করা আছে; Factor আপনার জন্য অনুপস্থিত মেথডগুলোর তালিকাও দিতে পারে।

যদি ভিন্নতা হয় ছোট, নির্দিষ্ট কয়েকটি লেবেলের তালিকা, তবে একটি `case`-ই সহজ।
