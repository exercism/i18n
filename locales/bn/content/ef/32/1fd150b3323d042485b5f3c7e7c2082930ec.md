# ভূমিকা

Factor-এর থ্রেডগুলো হলো *কো-অপারেটিভ কো-রুটিন*: তারা একটি OS থ্রেড ভাগ করে নেয়, I/O-তে এবং স্পষ্ট ইল্ড পয়েন্টে একে অন্যের কাছে নিয়ন্ত্রণ হস্তান্তর করে, আর কখনোই সত্যিকার অর্থে একসাথে চলে না। ইল্ডের *মাঝে* আপনি যা কিছু করেন, তা একটানা একটি অবিচ্ছিন্ন ধাপ হিসেবে ঘটে। কিন্তু কোনো যৌগিক অপারেশন (read-modify-write) যদি মাঝপথে ইল্ড করে, তবে আপনি শেষ করার আগেই আরেকটি থ্রেড ঢুকে পড়ে দুনিয়াটা বদলে দিতে পারে, আর সেটাই একট রেস।

এই অনুশীলনীতে এমন চারটি প্রিমিটিভ নিয়ে আলোচনা করা হয়েছে, যেগুলো বারবার সামনে আসে:

## `parallel-map`: সিকোয়েন্সের উপর ফর্ক/জয়েন

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

[`concurrency.combinators`][combinators]-এ। প্রতিটি এলিমেন্টের জন্য একটি করে থ্রেড স্পন করে, কোটেশনটি চালায়, আর ফলাফলগুলো একই ক্রমে একটি নতুন সিকোয়েন্সে সংগ্রহ করে আনে:

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`: একটি থ্রেড শুরু করা

```
spawn ( quot name -- thread )
```

[`threads`][threads]-এ। কোটেশনটি সমবর্তীভাবে চলে; `name` হলো ডিবাগিংয়ের জন্য একটি লেবেল। ফিরে আসা থ্রেড হ্যান্ডেলটি এই স্তরে বিশেষ কাজের নয়, `drop` করে দিন।

## প্রমিস: একবারই ব্যবহারযোগ্য মান হস্তান্তর

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

[`concurrency.promises`][promises]-এ। একটি প্রমিস হলো একবারই ব্যবহারযোগ্য মেইলবক্স: একটি থ্রেড এটিকে পূর্ণ করে, অন্যরা তা পড়ে। প্রমিসটি পূর্ণ হওয়া পর্যন্ত `?promise` ব্লক করে থাকে, তারপর মানটি রিটার্ন করে।

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

`spawn` আর `<promise>` দিয়েই `parallel-map` তৈরি; প্রতিটি কাজ যখন "একটি এলিমেন্ট হিসাব করা" ছাড়া অন্য কিছু করে, তখন এগুলো হাতে গড়ে নেওয়া কাজে লাগে।

সিকোয়েন্সের উপর সাধারণ ফ্যান-আউট/জয়েন কাঠামোটি হলো: প্রতিটি ইনপুটের জন্য একটি নতুন প্রমিস বানান, যে থ্রেড কাজটি করবে তাকে স্পন করুন আর প্রমিসটি `fulfill` করান, প্রতিটি প্রমিস একটি সিকোয়েন্সে জমা করুন, তারপর সম্পন্ন হওয়ার জন্য অপেক্ষা করতে প্রত্যেকটির উপর `?promise` করুন। Locals এটাকে পড়ার উপযোগী করে তোলে, অর্থাৎ `[| | ]` ল্যাম্বডার ভেতরে `:>` দিয়ে প্রমিসটিকে একটি নামের সাথে বেঁধে দিন, যাতে স্পন করা কোটেশনটি তার উপর ক্লোজার তৈরি করতে পারে:

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## লক: পারস্পরিক বর্জন

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

[`concurrency.locks`][locks]-এ। একটি নির্দিষ্ট লক একসাথে কেবল একটি থ্রেডই ধরে রাখতে পারে। `with-lock` লকটি অর্জন করে, কোটেশন চালায়, ছেড়ে দেয়, এমনকি কোটেশনটি থ্রো করলেও।

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

কোনো মান যখন *একাধিক থ্রেড পড়ে বা লেখে* আর তার উপর করা অপারেশনগুলো স্বাভাবিকভাবেই অ্যাটমিক নয়, তখনই একটি লক ব্যবহার করুন। পড়া আর লেখা দুটোরই লক দরকার, কারণ মাঝপথে ইল্ড করা একটি পড়া ভাঙা অবস্থা দেখতে পারে।
