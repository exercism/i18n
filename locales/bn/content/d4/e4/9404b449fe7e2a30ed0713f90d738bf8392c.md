# ভূমিকা

JavaScript-এ একটি বিল্ট-ইন অবজেক্ট `Date` আছে, যা তারিখ ও সময় সংরক্ষণ করে এবং সেগুলো পরিচালনার জন্য মেথড দেয়।

<!-- prettier-ignore -->
~~~exercism/caution
এটি Java-এর `java.util.Date` ক্লাসের ওপর ভিত্তি করে তৈরি হয়েছিল; ২০১০-এর দশকের গোড়ার দিকে এটিকে প্রতিস্থাপন করা হয়েছিল, তবে ব্যাকওয়ার্ড কম্প্যাটিবিলিটির জন্য JavaScript-এর `Date` এখনও টিকে রয়েছে।

সাধারণভাবে Date নিয়ে কাজ করা কতটা কঠিন, আর টাইমজোন হ্যান্ডলিং কতটা দুর্বল বা একেবারে অনুপস্থিত, তার কারণে `moment.js`, `day.js`, `date-fns` আর `luxon`-এর মতো অনেক লাইব্রেরি গড়ে উঠেছে।
এগুলোর কোনোটিই Exercism-এ পাওয়া যায় না।

আপনার নিজের প্রজেক্টে `moment.js`-এর মতো ডেপ্রিকেটেড বা আর মেইনটেইন করা হয় না এমন প্যাকেজ ব্যবহার করবেন না; বরং `luxon`-এর মতো আরও আধুনিক বিকল্প, কিংবা এখনও ব্যাপকভাবে পাওয়া যায় না এমন [Temporal][mdn-temporal]-এর ওপর নির্ভর করুন।
এই অনুশীলনীটিতে মূলত `Date` নিয়ে আলোচনা করা হয়েছে, যা JavaScript-এর শেষ দিন পর্যন্ত প্রাসঙ্গিক থাকবে।

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal
~~~

## তৈরি করা

একটি `Date` অবজেক্ট হলো `Date` ক্লাসের একটি ইনস্ট্যান্স।
কনস্ট্রাক্টর ফাংশনে কোনো আর্গুমেন্ট না দিয়েও এটি তৈরি করা যায়।
এতে বর্তমান তারিখ ও সময় নির্দেশ করে এমন একটি `Date` অবজেক্ট পাওয়া যায়:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### **ইউনিক্স টাইমস্ট্যাম্প (সংখ্যা)**

যদি কোনো সংখ্যা পাস করা হয়, তাহলে সেটিকে একটি `timestamp` হিসেবে ধরা হয়।
একটি টাইমস্ট্যাম্প হলো একটি ইন্টিজার সংখ্যা, যা **১৯৭০ সালের ১ জানুয়ারি [UTC][defn-utc]+0** থেকে যত **মিলিসেকেন্ড** পেরিয়ে গেছে, সেই সংখ্যা বোঝায়।

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

কেউ হয়তো আশা করতে পারেন `new Date(0)` "সবচেয়ে আগের" তারিখের অবজেক্ট তৈরি করবে, কিন্তু JavaScript তারিখটিকে আপনার স্থানীয় টাইমজোনে রূপান্তর করে; তাই কেবল [GMT / UTC+0][defn-gmt] টাইমজোনের আশপাশে থাকা মানুষরাই আসলে [ইউনিক্স এপক][defn-unix-epoch] মানটি পান।

### **ISO 8601 টাইমস্ট্যাম্প (স্ট্রিং)**

আপনি তারিখ নির্দেশ করে এমন একটি স্ট্রিং মান `Date` কনস্ট্রাক্টরে পাস করতে পারেন।
সব ইমপ্লিমেন্টেশনে একইভাবে কাজ করে এমন **একমাত্র** ফরম্যাট হলো আন্তর্জাতিকভাবে স্বীকৃত ও প্রমিত তথাকথিত [ISO 8601 টাইমস্ট্যাম্প স্ট্রিং][defn-iso8601]-এর [সরলীকৃত রূপ][mdn-date-string-format]।

[UTC][defn-gmt]-এ সময়ের একটি মুহূর্ত দেখতে এমন হয়:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

যেখানে নিচের প্রতিস্থাপনগুলো ঘটে:

| কী   | বিবরণ                                        | ডিফল্ট |
| ---- | -------------------------------------------- | ------- |
| YYYY | ক্যালেন্ডার বছর, ৪ সংখ্যায় প্রকাশিত          |         |
| MM   | ক্যালেন্ডার মাস, ২ সংখ্যায় প্রকাশিত          | 01      |
| DD   | ক্যালেন্ডার দিন, ২ সংখ্যায় প্রকাশিত          | 01      |
| T    | আক্ষরিক T অক্ষর, যা তারিখকে সময় থেকে আলাদা করে |         |
| HH   | ২৪-ঘণ্টার ঘড়িতে ঘণ্টা, ২ সংখ্যায়            | 00      |
| mm   | মিনিট, ২ সংখ্যায়                             | 00      |
| ss   | সেকেন্ড, ২ সংখ্যায়                           | 00      |
| mss  | মিলিসেকেন্ড, ৩ সংখ্যায়                       | 000     |
| Z    | আক্ষরিক Z অক্ষর, অথবা একটি অফসেট `+/-HH:mm`   |         |

আক্ষরিক `Z` অক্ষরটি UTC বোঝায় (কোনো টাইমজোন নেই, ডে লাইট সেভিংসও নেই)।

যেহেতু বেশিরভাগ কম্পোনেন্টেরই ডিফল্ট মান আছে, তাই শেষের দিকের অংশগুলো বাদ দিয়েও লেখা বৈধ:

```text
YYYY-MM-DD
```

ডিফল্ট হিসেবে সময় ধরা হয় 00:00:00.000।

যদি টাইমস্ট্যাম্পটি `Z` দিয়ে শেষ না হয়, আর `+HH:mm` বা `-HH:mm` (অর্থাৎ টাইমজোন অফসেট) দিয়েও শেষ না হয়, তাহলে ঐতিহাসিক কারণবশত নিচের নিয়মটি প্রযোজ্য হয়:

> যখন টাইমজোন অফসেট অনুপস্থিত থাকে, তখন শুধু তারিখের ফরমগুলো UTC সময় হিসেবে ব্যাখ্যা করা হয় আর তারিখ-সময়ের ফরমগুলো স্থানীয় সময় হিসেবে ব্যাখ্যা করা হয়।
> UTC সময় হিসেবে ব্যাখ্যা করার কারণ হলো স্পেসিফিকেশনে থাকা একটি ঐতিহাসিক এরর, যা ISO 8601-এর সঙ্গে সঙ্গতিপূর্ণ ছিল না, কিন্তু ওয়েব কম্প্যাটিবিলিটির জন্য বদলানো যায়নি।
> দেখুন [ভাঙা পার্সার – ওয়েব বাস্তবতার একটি সমস্যা][ref-broken-parser]।

[mdn-date-string-format]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date#date_time_string_format

### **Date অবজেক্ট**

আগে থেকে থাকা একটি Date অবজেক্টও কনস্ট্রাক্টরের আর্গুমেন্ট হিসেবে ব্যবহার করা যায়।
এতে একই তারিখ ও সময় নিয়ে বিদ্যমান `Date` অবজেক্টের একটি কপি তৈরি হয়।

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### **আলাদা করে তারিখ ও সময়ের কম্পোনেন্টের মান দেওয়া**

তিনটি সংখ্যা পাস করলে শুধু তারিখ বোঝানো Date তৈরি করা যায়।
ছয়টি সংখ্যা পাস করলে তারিখ ও সময় বোঝানো Date তৈরি করা যায়।

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

দ্বিতীয় মানটি হলো `month`, যা জানুয়ারিতে `0` থেকে শুরু হয়ে ডিসেম্বরে `11` পর্যন্ত যায়।

## `Date.parse()`

আপনি হয়তো `Date.parse` নামের একটি তারিখ পার্সিং ফাংশনের উল্লেখ বা রেফারেন্স দেখতে পারেন।
যেহেতু এই ফাংশনের জন্য মাত্র কয়েকটি ইনভেরিয়েন্ট (সত্য) আছে, আর বাকি ইমপ্লিমেন্টেশন নির্দিষ্ট করা নেই (তাই স্ট্যান্ডার্ডও নয়), এটি ব্যবহার করা উচিত নয়।

## `Date`-এর কম্পোনেন্টগুলো অ্যাক্সেস করা

ডেট অবজেক্টে এমন অনেক মেথড আছে যেগুলো তারিখের কম্পোনেন্টগুলো রিটার্ন করে:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

এগুলোর প্রতিটিরই মান হালনাগাদ করার জন্য একটি সংশ্লিষ্ট `set` ভ্যারিয়েন্ট আছে (যেমন `setFullYear`)।
সীমা ছাড়ানো যেকোনো মান পরের কম্পোনেন্টে গিয়ে রোল ওভার হয়:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

যেসব মেথড স্থানীয় টাইমজোন উপেক্ষা করে, সেগুলোর সবার জন্যই UTC ভ্যারিয়েন্ট আছে।

## তারিখ থেকে রূপান্তর

ডেট অবজেক্টে `getTime()` নামের একটি মেথড আছে, যা ইউনিক্স টাইমস্ট্যাম্প মিলিসেকেন্ডে রিটার্ন করে, অর্থাৎ ১৯৭০ সালের ১ জানুয়ারির গোড়ায় UTC-তে মধ্যরাত থেকে যত মিলিসেকেন্ড পেরিয়ে গেছে তার সংখ্যা।
এছাড়া একটি ডেট অবজেক্ট থেকে ISO 8601 টাইমস্ট্যাম্প স্ট্রিংয়ে রূপান্তর করার জন্য `toISOString()` মেথডটি আছে।

## তারিখ তুলনা করা

বড় (`>`) ও বড় বা সমান (`>=`), আর ছোট (`<`) ও ছোট বা সমান (`<=`) অপারেটর দুটি তারিখের মধ্যে বা একটি তারিখ ও একটি সংখ্যার মধ্যে সরাসরি ব্যবহার করা যায়।
এটি কাজ করে কারণ JavaScript তারিখটিকে একটি প্রিমিটিভে রূপান্তর করার চেষ্টা করে।
