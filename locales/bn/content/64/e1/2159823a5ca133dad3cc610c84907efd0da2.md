# পরিচিতি

`Complex numbers` জটিল নয়।
এদের শুধু একটা কম ভয়ের নাম দরকার।

এগুলো এতটাই কাজের, বিশেষ করে ইঞ্জিনিয়ারিং আর বিজ্ঞানে, যে R জটিল সংখ্যাকে integer, double, logical, character ও raw-এর পাশাপাশি একটা স্ট্যান্ডার্ড অ্যাটমিক টাইপ হিসেবেও রেখে দিয়েছে।

## মূল বিষয়

R-এ একটি `complex` সংখ্যা আসলে একটি একক মান।
তবে ব্যবহারের সময় এটাকে এক জোড়া সংখ্যা হিসেবেও ভাবা যায়।
দুর্ভাগ্যজনক ঐতিহাসিক কারণে এদের বলা হয় "বাস্তব" ও "কাল্পনিক" অংশ।
আবারও বলি, অদ্ভুত নামগুলো নিয়ে না ভেবে ভেতরের সরলতাটুকুতে মনোযোগ দেওয়াই ভালো।

দুটি বাস্তব সংখ্যা থেকে জটিল সংখ্যা বানাতে চাইলে কাল্পনিক অংশের শেষে শুধু `i` যোগ করলেই হয়।

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

বাস্তব ভ্যারিয়েবল থেকে জটিল সংখ্যা বানাতে গেলে উপরের সিনট্যাক্সটা কাজ করবে না।
`r + imi` লিখলে পার্সার বিভ্রান্ত হয়ে ভাবে `imi` নাকি একটা (অস্তিত্বহীন) ভ্যারিয়েবলের নাম।

তাহলে হয় কাল্পনিক অংশটিকে `1i` দিয়ে গুণ করুন, নয়তো [`complex()`][ref-complex] ফাংশনটি ব্যবহার করুন:

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

আপনার মনে প্রশ্ন আসতে পারে, `j`-এর বদলে `i` কেন?

বেশিরভাগ ইঞ্জিনিয়ার `j` পছন্দ করেন।
বেশিরভাগ বিজ্ঞানী আর গণিতবিদ _কাল্পনিক_-এর জন্য `i` গাণিতিক প্রতীকটি পছন্দ করেন, কিন্তু ইলেকট্রিক্যাল ইঞ্জিনিয়ারিংয়ে _কারেন্ট_ বোঝাতে `i` ব্যবহারের সঙ্গে ওই প্রতীকটির সংঘর্ষ বাধে।
R বেছেছে `i`, Python বেছেছে `j`, আর Julia বিতর্কটা এড়াতে গিয়ে বেছেছে `im`।
[STEM][wiki-STEM] প্রোগ্রামিং ভাষার মধ্যে যাওয়া-আসা করার সময় সাবধানে থাকুন।

জটিল সংখ্যার অংশগুলো আলাদা আলাদা করে পেতে চাইলে:

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

যেকোনো একটি অংশ শূন্য হতে পারে, তখন গণিতবিদেরা সংখ্যাটিকে "সম্পূর্ণ বাস্তব" বা "সম্পূর্ণ কাল্পনিক" বলতে পারেন।
তবুও R-এ এটা জটিল সংখ্যাই থাকে।

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

আপনি হয়তো শুনেছেন যে "`i` (বা `j`) হলো -1-এর বর্গমূল"।

আপাতত এর মানে শুধু এইটুকু, কাল্পনিক অংশটি _সংজ্ঞা অনুযায়ী_ নিচের সমতাটি মেনে চলে:

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

ধারণাটা সরল, কিন্তু এর থেকে মজার সব পরিণতি আসে।

## পাটিগণিত

ফ্লোট আর ইন্টিজারের সঙ্গে যে অপারেটরগুলো ব্যবহার করা হয়, তার বেশিরভাগই জটিল সংখ্যার ক্ষেত্রেও কাজ করে:

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

## ফাংশন

বেশিরভাগ গাণিতিক ফাংশনই জটিল ইনপুট নিয়ে কাজ করে।

`Re()` আর `Im()` ছাড়াও আরও কিছু ফাংশন আছে, যেগুলোর জটিল সংখ্যার ক্ষেত্রে বিশেষ প্রাসঙ্গিকতা রয়েছে।

- `Conj()` জটিল সংখ্যার কাল্পনিক অংশের চিহ্নটা কেবল উল্টে দেয় (_+ থেকে - বা উল্টোটাও_)।
  - জটিল সংখ্যার গুণ কীভাবে কাজ করে, তার কারণে এটা আপনার ধারণার চেয়েও বেশি কাজের।
- `abs(<complex number>)` নিশ্চিতভাবে একটি বাস্তব সংখ্যা রিটার্ন করে, যার কোনো কাল্পনিক অংশ থাকে না (এটার "পরম মান"), আর `Mod(<complex number>)` এর প্রতিশব্দ।
- `Arg(<complex number>)` রেডিয়ানে ফেজ কোণ রিটার্ন করে।

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
