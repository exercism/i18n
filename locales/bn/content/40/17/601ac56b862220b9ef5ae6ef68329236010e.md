# সম্পর্কে

`Option` টাইপটি স্ট্যান্ডার্ড লাইব্রেরি প্রদত্ত একটি এনাম। এমন একটি মান প্রকাশ করার জন্য এটি উপযোগী, যা না-ও থাকতে পারে।
যদিও এটি `null` বা `nil`-এর মতো শোনাতে পারে, তবুও এটি বেশ আলাদা এবং বিশেষ।

`Option<T>` অন্য টাইপ ধারণ করে এবং এর দুটি ভ্যারিয়েন্ট আছে: `Some(T)` এবং `None`।

উদাহরণস্বরূপ, `Option<u32>` `u32` টাইপ ধারণ করে।

## ব্যবহার

### `Option<T>`-এর ভিতরে `T` ব্যবহার করা

`Option`-এর মধ্যে থাকতে পারে এমন মান ব্যবহার করার জন্য বেশ কিছু কমন আইডিয়ম আছে:

- `if let Some(t) = optional { ... }`.

    `if let` আইডিয়মটি `Option<T>` থেকে মানটি বের করে এনে `t` ভ্যারিয়েবলের সাথে বাইন্ড করে। এর ফলে আপনি সেই ব্লক স্কোপের মধ্যে এটি সরাসরি ব্যবহার করতে পারেন।

- `match optional { Some(t) => {...}, None => {...}}`

    `match` অপারেটরটিও আপনাকে একটি স্টেটমেন্ট বা এক্সপ্রেশনের মধ্যেই `None` কেসগুলো আনপ্যাক করে হ্যান্ডেল করতে দেয়। এটি পরপর অনেকগুলো if ও else স্টেটমেন্টের বিকল্প। `match` ব্যবহার করলে কোডের কিছু অংশের পাঠযোগ্যতা বাড়তে পারে।
- `optional.map(|t| ...)`
   `Option::map` প্রদত্ত ফাংশন ব্যবহার করে একটি Option-কে জায়গায় রেখেই আপডেট করে, প্রয়োজনে নতুন টাইপে।

   **নোট**: উপস্থিত থাকলে ভেতরে থাকা মানের উপর কাজ করে। বাইন্ডিংটি একটি `Option<U>` হয়ে যায়, যেখানে প্রদত্ত ক্লোজারটি `FnOnce(T) -> U`।
- `optional.unwrap()`.
   `Option<T>` আনর্যাপ করলে `T` বেরিয়ে আসে, কিন্তু `T` সেখানে না থাকলে প্যানিক করবে। কিছু ক্ষেত্রে এটি সুবিধাজনক।

   **গুরুত্বপূর্ণ**: আনর্যাপ করা স্বল্পমেয়াদে বা টেস্ট কোডে ডেভেলপমেন্ট সহজ করতে পারে, কিন্তু এটি রানটাইম প্যানিকের সম্ভাবনা তৈরি করে। সম্ভব হলে এটি এড়িয়ে চলা উচিত।

- `optional.expect("Unexpected None found! Aborting program.)`.
   `Option<T>`-এর `expect` মেথডটি `unwrap()`-এর সাথে বেশ মিল, তবে এটি `None` হলে প্রদত্ত মেসেজ ব্যবহার করে প্যানিক করবে।

## উদাহরণ

যখন `Option<u32>`-এ কোনো মান থাকে:

```rust
let has_something: Option<u32> = Some(100);
assert_eq!(has_something.unwrap(), 100);
```

যখন `Option<u32>`-এ কোনো মান *থাকে না*:

```rust
let has_nothing: Option<u32> = None;
assert_eq!(has_nothing, None);
```
