# পরিচিতি

উপকূলীয় টহল জাহাজের এক *সিগন্যালার* বার্তার লগটি রক্ষণাবেক্ষণ করেন। কাঁচা সিগন্যাল ফ্ল্যাগ আসে মার্কার ক্যারেক্টার দিয়ে ফ্রেম করা অবস্থায়; পাঠগুলো ওয়্যারের জন্য রেন্ডার করতে হয়; পর্যবেক্ষণের জোড়া ও ত্রয়ী সঙ্গে সঙ্গে সংক্ষেপ করতে হয়। Factor-এর স্ট্যান্ডার্ড লাইব্রেরির কয়েকটি ইডিয়ম বেশিরভাগ কাজ সেরে দেয়।

## `unparse`, মান থেকে সোর্স

[`unparse`][unparse] (`prettyprint`-এ) যেকোনো মানের সোর্স-ফর্ম টেক্সট রিটার্ন করে:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` হলো পার্সারের বিপরীত। রাউন্ড-ট্রিপ `dup unparse parse` মানটিকে পুনর্গঠন করে। রিসিভার যে ওয়্যার ফরম্যাট আবার পার্স করবে, সেখানে সিরিয়ালাইজ করার জন্য এটিই সঠিক যন্ত্র, আর মানুষের পড়ার উপযোগী আউটপুটের জন্য ভুল যন্ত্র (স্ট্রিং নিজের কোটেশন ধরে রাখে, ভেক্টর নিজের `V{ ... }` ধরে রাখে, ইত্যাদি)।

## স্লাইস ভ্যারিয়েন্ট, কপি নয় বরং ভিউ

`sequences`-এর `head` ও `tail` আপনি যে অংশটি রাখছেন তা একটি নতুন সিকোয়েন্সে *কপি* করে। এদের `-slice` প্রতিরূপগুলো একটি `slice` অবজেক্ট রিটার্ন করে, অর্থাৎ একটি টুপল যাতে from-index, to-index আর অন্তর্নিহিত সিকোয়েন্স থাকে, যা কপি না করেই [সিকোয়েন্স প্রোটোকল][sequence-protocol] ইমপ্লিমেন্ট করে:

| word          | effect                                          |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )`, প্রথম n কপি করে           |
| `head-slice`  | `( seq n -- slice )`, প্রথম n-এর ভিউ             |
| `tail`        | `( seq n -- newseq )`, n ইনডেক্স থেকে শুরু করে কপি করে |
| `tail-slice`  | `( seq n -- slice )`, n ইনডেক্স থেকে শুরু করে ভিউ |
| `head*`       | `( seq n -- newseq )`, শেষ n ছাড়া বাকি সব কপি করে |
| `head-slice*` | `( seq n -- slice )`, শেষ n ছাড়া বাকি সবের ভিউ   |
| `tail*`       | `( seq n -- newseq )`, শেষ n কপি করে             |
| `tail-slice*` | `( seq n -- slice )`, শেষ n-এর ভিউ               |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

একটি `slice` *হলো* একটি সিকোয়েন্স, তাই যা কিছু একটি সিকোয়েন্স নেয় তা একটি স্লাইসও নেয়: `length`, `first`, `each` ইত্যাদি সবই কপি ছাড়াই কাজ করে। যে টেস্টগুলো একটি লিটারেল স্ট্রিংয়ের সাথে তুলনা করতে চায়, তারা `>string` দিয়ে কোয়ার্স করতে পারে।

## `?head` ও `?tail`, মার্কার থাকলে সরিয়ে ফেলা

ফ্রেম করা পাঠে এমন মার্কার টেক্সট থাকে যা থাকতেও পারে, নাও থাকতে পারে। `?head` ও `?tail` (`splitting`-এ) একটি প্রিফিক্স বা সাফিক্স সরিয়ে ফেলার চেষ্টা করে, এবং (সম্ভবত ছোট হয়ে যাওয়া) সিকোয়েন্সটি *এবং* একটি বুলিয়ান রিটার্ন করে যা জানায় মার্কারটি পাওয়া গেছে কি না:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

শেষের বুলিয়ানটি এদের একটি গার্ডের জন্য স্বাভাবিক উপযুক্ত করে তোলে: ফ্রেমটি উপস্থিত ছিল কি না তা নিয়ে ব্রাঞ্চ করতে `?head`-কে `if`-এর সাথে জুড়ুন, অথবা প্রত্যাশিত মার্কার নেই এমন ইনপুট প্রত্যাখ্যান করতে `unless`-এর সাথে জুড়ুন।

## `<repetition>`, কার্যত N কপি

[`<repetition>`][repetition] (`sequences`-এ) আরেকটি কপি-না-করা ভার্চুয়াল সিকোয়েন্স। `( len elt -- repetition )` এমন একটি সিকোয়েন্স তৈরি করে যার `len`-সংখ্যক এলিমেন্ট সবই `elt`, অথচ ঠিক ততগুলো স্লট বরাদ্দ করতে হয় না:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

`elt` নিজেই একটি সিকোয়েন্স হতে পারে, প্রতিটি কপি সেই একই সিকোয়েন্স। এরপর `concat` কপিগুলোকে পাশাপাশি জুড়ে দেয়:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

একটি `slice`-এর মতোই, ফলাফলটি *হলো* একটি সিকোয়েন্স: `length`, `each` আর এজাতীয় সবকিছু এর উপর সরাসরি কাজ করে। একটি সিগন্যাল কোডকে নির্দিষ্ট প্রস্থে প্যাড করতে বা পরপর একগুচ্ছ পুনরাবৃত্ত মার্কার বসাতে এটি ব্যবহার করুন; কেবল যখন সত্যিই একটি কংক্রিট সিকোয়েন্স দরকার, তখন `>string` (বা `>array`) দিয়ে কোয়ার্স করুন।

## `<clumps>`, কার্যত ওভারল্যাপিং উইন্ডো

[`<clumps>`][clumps] (`grouping`-এ) তৃতীয় কপি-না-করা ভার্চুয়াল সিকোয়েন্স। `( seq n -- clumps )` `seq`-কে তার উপর *ওভারল্যাপিং* দৈর্ঘ্য-`n` উইন্ডোর সিরিজ হিসেবে দেখে, প্রতিটি উইন্ডো একটি স্লাইস:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

`length` দৈর্ঘ্যের একটি সিকোয়েন্স `length - n + 1`-টি উইন্ডো দেয়। যেহেতু প্রতিটি উইন্ডো একটি স্লাইস, পরপর পাঠ জোড়া লাগাতে কোনো কপি লাগে না: প্রতিটি `2`-ক্লাম্পে `[ first2 ]` চালালেই আপনি প্রজেক্ট করার জন্য প্রতিটি ধারাবাহিক জোড়া পেয়ে যান। (ওভারল্যাপ না করা সংস্করণ `<groups>` বদলে সিকোয়েন্সটিকে আলাদা আলাদা ব্লকে কেটে ফেলে।)

## মাল্টি-ইনপুট ক্লিভ, `2bi`, `3bi`, `2tri`, `3tri`

সাধারণ ক্লিভ ওয়ার্ড `bi` ও `tri` দুটি বা তিনটি কোয়টেশন *একটি* ইনপুটে প্রয়োগ করে। `2`-প্রিফিক্স ও `3`-প্রিফিক্স ভ্যারিয়েন্টগুলো প্রতিটি কোয়টেশন *দুটি* বা *তিনটি* ইনপুটে প্রয়োগ করে:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

প্রতিটি কোয়টেশন *সব* ইনপুট পায়। এগুলো তখন ব্যবহার করুন যখন একই জোড়া (বা ত্রয়ী) মানের উপর একাধিক প্রজেকশন নির্ভর করে, কিন্তু তখন নয় যখন আপনি প্রতিটি ইনপুটে *একই* অপারেশন আলাদা আলাদা প্রয়োগ করতে চান (সেটি `bi@` বা `tri@`)।

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
