# পরিচিতি

শর্তসাপেক্ষ ধারণাটি `jcc`-এর সাথে পরিচয় করায়, যা কোনো শর্তের ভিত্তিতে ব্রাঞ্চ করার নির্দেশনার পরিবার। `jcc` কেবল তার শর্ত পূরণ হলেই প্রোগ্রামের অন্য একটি জায়গায় এক্সিকিউশন স্থানান্তর করে।

তবে আধুনিক CPU খুব দ্রুত এবং একসাথে অনেক নির্দেশনা সমান্তরালে এক্সিকিউট করতে সক্ষম। শর্তের রানটাইম চেকের জন্য CPU অপেক্ষা করতে করতে সব কাজ থামিয়ে রাখা খুবই ব্যয়বহুল হবে।

এই কারণেই ভেতরে ভেতরে CPU অপেক্ষা করে না। এটি একটি **ব্রাঞ্চ-প্রেডিক্টর** ব্যবহার করে শর্তের ফলাফল অনুমান করে এবং অনুমান করা পথটি _স্পেকুলেটিভভাবে_ এক্সিকিউট করা শুরু করে।

অনুমান সঠিক হলে এক্সিকিউশন এমনভাবে এগোয় যেন কোনো ব্রাঞ্চই ছিল না। কিন্তু অনুমান ভুল হলে CPU-কে অনুমান করা পথে _করা কাজটি বাতিল করে_ সঠিক পথে আবার শুরু করতে হয়।

এটাকে বলা হয় **ব্রাঞ্চ মিসপ্রেডিকশন**, আর এটি ব্যয়বহুল, যা বিলম্ব ডেকে আনে।

কোনো ব্রাঞ্চ অনুমান করা কঠিন হলে এই মিসপ্রেডিকশনগুলো সংখ্যায় বাড়তে থাকে। সেসব ক্ষেত্রে কখনও কখনও ব্রাঞ্চটি পুরোপুরি এড়িয়ে যাওয়াই ভালো, যাতে শর্ত যাই হোক একই নির্দেশনাগুলোই এক্সিকিউট হয়। `jcc` ছাড়াই মানগুলোর মধ্যে বাছাই করা কোডকে বলা হয় **ব্রাঞ্চলেস**।

কোড এমনভাবে সাজানোর বেশ কিছু উপায় আছে যাতে এটি কম ব্রাঞ্চ করে, অথবা যাতে এর যেসব ব্রাঞ্চ থাকে সেগুলো বেশি অনুমানযোগ্য হয়। বিশেষ করে x86-64 দুটি নির্দেশনার পরিবার দেয়, যেগুলো ব্রাঞ্চলেস কোড লেখার কাজে কমন।

## শর্তসাপেক্ষ মুভ

`cmovcc` নির্দেশনার পরিবার নির্দিষ্ট শর্ত পূরণ হলেই সোর্স অপারেন্ডটি ডেস্টিনেশনে কপি করে। অন্যথায় ডেস্টিনেশন অপরিবর্তিত থাকে।

`cc` প্রত্যয়ের নামকরণ `jcc`-এর মতোই, অর্থও একই:

| নির্দেশনা   | কখন মুভ করে                          |
|-------------|--------------------------------------|
| `cmove`     | `cmp A, B`-এর পর A == B হলে          |
| `cmovne`    | `cmp A, B`-এর পর A != B হলে          |
| `cmovl`     | `cmp A, B`-এর পর A < B (সাইনড) হলে   |
| `cmovb`     | `cmp A, B`-এর পর A < B (আনসাইনড) হলে |
| `cmovg`     | `cmp A, B`-এর পর A > B (সাইনড) হলে   |
| `cmova`     | `cmp A, B`-এর পর A > B (আনসাইনড) হলে |

নিয়মগুলো `jcc`-এর মতোই:

1. সাইনড তুলনার জন্য `l` ও `g` ব্যবহৃত হয়, আর আনসাইনড তুলনার জন্য `b` ও `a`।
2. প্রত্যয়ের সাথে `e` যোগ করলে সমতাও ধরা হয়।
3. `n` যোগ করলে শর্তটি উল্টে যায়।
4. এমন ভ্যারিয়েন্টও আছে যেগুলো ফ্ল্যাগ সেট হওয়া বোঝায়।
   যেমন `cmovz` ও `cmovc`।

`rdi`-তে থাকা একটি সাইনড ইন্টিজারের পরম মানের কথা ভাবুন, যা `rax`-এ রিটার্ন হবে। `jcc` দিয়ে লিখলে ফাংশনটি দুটি পথের একটি বেছে নেয়:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

`cmovcc` দিয়ে লিখলে দুটি সম্ভাব্য মানই শর্ত ছাড়াই হিসাব করা হয়, আর শর্তসাপেক্ষ মুভটি তার একটি বেছে নেয়:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

ব্রাঞ্চলেস সংস্করণে সবসময় একই নির্দেশনা এক্সিকিউট হয়। প্রেডিক্টরের অনুমান করার মতো কোনো `jcc` নেই।

`cmovcc`-এর ডেস্টিনেশন অবশ্যই একটি রেজিস্টার হতে হবে। সোর্স একটি রেজিস্টার বা মেমরি লোকেশন হতে পারে, তবে ইমিডিয়েট নয়।

~~~~exercism/note
উপরের কোডে `neg` নির্দেশনাটি ফলাফল অনুযায়ী বেশ কয়েকটি ফ্ল্যাগ সেট করে, যার মধ্যে সাইন ফ্ল্যাগ (SF)-ও আছে। এর মানে `cmp rdi, 0` সম্পূর্ণ বাদ দেওয়া যায়:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

ধনাত্মক `rdi`-এর জন্য `neg` ঋণাত্মক ফলাফল দেয় এবং SF == 1 হয়, তাই `cmovs` আবার `rdi` বসিয়ে দেয়। শূন্য বা ঋণাত্মক `rdi`-এর জন্য `neg` অঋণাত্মক ফলাফল দেয় এবং SF == 0 হয়, তাই `rax` নেগেট করা মানটিই ধরে রাখে (যা-ই সঠিক পরম মান)।

অ্যাসেম্বলি কোডে মান তুলনা করার মূল উপায় `cmp` হলেও, অনেক নির্দেশনাই নিজেদের ফলাফল অনুযায়ী ফ্ল্যাগ সেট করে। কোনো নির্দেশনা কোন কোন ফ্ল্যাগে প্রভাব ফেলে, তার পূর্ণ তালিকা সাধারণত তার [রেফারেন্স][reference]-এ দেওয়া থাকে। `neg`-এর ক্ষেত্রে সেগুলো হলো SF, ZF, CF, OF ও PF।

[reference]: https://www.felixcloutier.com/x86/
~~~~

## শর্তসাপেক্ষ সেট

`setcc` নির্দেশনার পরিবার নির্দিষ্ট শর্ত পূরণ হলে ডেস্টিনেশন অপারেন্ডকে `1` করে, অন্যথায় `0` করে। ডেস্টিনেশন সবসময়ই একটি _৮-বিট অপারেন্ড_।

`cc` প্রত্যয়ের নামকরণও `jcc` ও `cmovcc`-এর মতোই। যেমন, `ZF == 1` হলে `setz` ডেস্টিনেশনকে `1` করে, অন্যথায় `0`।

ডেস্টিনেশন যেহেতু ৮-বিট, তাই আরও চওড়া মান দরকার হলে `setcc`-এর পরে `movzx` বসানো কমন:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

এটি তুলনার ফলাফলকে ইন্টিজার `0` বা `1`-এ পরিণত করার একটি কমন কৌশল।
