# পরিচিতি

কিছু লুপকে "সিকোয়েন্সের প্রতিটি এলিমেন্টের জন্য এটা করুন" হিসেবে লেখা যায় না; কিছু শর্ত উল্টে যাওয়া পর্যন্ত আপনাকে চালিয়ে যেতেই হয়। Factor-এর `while` কম্বিনেটরই তার জন্য হাতিয়ার: একটা প্রেডিকেট কোয়োটেশন বলে "চালিয়ে যাব?", একটা বডি কোয়োটেশন এক ধাপের কাজ করে, আর প্রেডিকেট `f` দেওয়া পর্যন্ত `while` পুনরাবৃত্তি করে।

## `while` ও `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` ও `body` দুটোই কোয়োটেশন, যারা ডেটা স্ট্যাকের উপর কাজ করে। `pred` একটা ট্রুথি মান রেখে যাওয়া পর্যন্ত `while` লুপ চালিয়ে যায়; `until` ঠিক তার উল্টো: `pred` সত্য হওয়া *পর্যন্ত* এটা লুপ চালিয়ে যায় (অর্থাৎ, যতক্ষণ `pred` `f` রেখে যায়)।

একটা মাত্র স্টেট মান প্রেডিকেট আর বডির মধ্যে স্ট্যাকে চলাচল করতে পারে:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

ট্রেস: প্রেডিকেট `dup 0 >` চলমান কাউন্টারটার দিকে উঁকি দেয়; বডি `dup . 1 -` সেটা প্রিন্ট করে আর এক কমায়; কাউন্টার `0`-এ পৌঁছালেই লুপ থেমে যায়। শেষের `drop` ওই চূড়ান্ত `0`-টা স্ট্যাক থেকে মুছে ফেলে।

## `while*`: প্রেডিকেটের মান ধরে রাখা

```
while* ( pred body -- )
```

`while` শুধু খেয়াল করে তার প্রেডিকেট সত্য কোনো মান রেখে গেল কি না; বডি চালানোর আগে সে ওই মানটা নিজেই ফেলে দেয়। `while*` বদলে ওই মানটা *বডির হাতে তুলে দেয়*। যখন টেস্ট আর বডি একই নতুন-গণনা-করা জিনিস চায়, তখনই এটা বেছে নিন: একটা লুকআপ, একটা ম্যাচ, একটা পার্স করা টোকেন।

এখানে প্রতিটি নাম একটা চেইনের পরের নামটার দিকে ইশারা করে। প্রেডিকেট বর্তমান নামটা খুঁজে দেখে; যতক্ষণ পরের কোনো নাম থাকে, `while*` সেটা বডির কাছে পৌঁছে দেয়, আর বডি সেটা প্রিন্ট করে সেখান থেকেই এগিয়ে যায়:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at` পরের নামটা রিটার্ন করে, আর কোনো নামের এন্ট্রি না থাকলে `f` রিটার্ন করে। যতক্ষণ এটা একটা নাম রিটার্ন করে, `while*` সেই নামটা `dup .`-এর হাতে দেয়, যা সেটা প্রিন্ট করে আর পরের লুকআপের জন্য কী (key) হিসেবে রেখে দেয়। প্রথম `f`-ই লুপ থামিয়ে দেয়; `while*` সেটা ফেলে দেয়, তাই কিছুই বাকি থাকে না।

## লোকাল দিয়ে একাধিক স্টেট মান

যখন লুপ একাধিক মান বহন করে, যেমন একটা বাকি থাকা তালিকা আর একটা চলমান যোগফল, তখন স্ট্যাক নিয়ে খেলা করতে গেলে ঝামেলা বাড়ে। সবচেয়ে পরিচ্ছন্ন প্যাটার্ন হলো `::` দিয়ে *লোকাল* ঘোষণা করা:

```
:: word ( inputs -- outputs ) ... ;
```

বডির ভেতরে `:> name!` একটা পরিবর্তনযোগ্য লোকাল যোগ করে; পড়ার জন্য ব্যবহৃত হয় `name`, লেখার জন্য `name!` (যা স্ট্যাক থেকে নতুন মানটা নিয়ে সেটা অ্যাসাইন করে)।

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

এখানে দুটো লোকাল (`rest` আর `running`) পুরো লুপের স্টেট কভার করে: প্রেডিকেট সেগুলো পরীক্ষা করে, বডি সেগুলো আপডেট করে, আর শেষে চূড়ান্ত মানটা রিটার্ন করা হয়।

`unclip ( seq -- rest first )` একটা সিকোয়েন্সের প্রথম এলিমেন্টটা ছাড়িয়ে নেয়; লুপ যখন প্রতি ইটারেশনে একটা করে এলিমেন্ট খেয়ে ফেলতে চায়, তখন এটা কাজে লাগে। `[ rest! ] dip` ফর্মটা `rest`-কে বাকি টেইলে আপডেট করে, আর সদ্য পপ করা এলিমেন্টটা বডির ব্যবহারের জন্য স্ট্যাকে রেখে দেয়।
