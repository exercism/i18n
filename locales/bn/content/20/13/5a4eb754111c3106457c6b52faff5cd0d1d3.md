# পরিচিতি

যখন সিদ্ধান্ত নেওয়ার জন্য আপনার হাতে কিছু আলাদা আলাদা সম্ভাব্য মান থাকে, তখন একটার পর একটা `if` লেখার চেয়ে [`combinators`][combinators]-এর `case` অনেক পরিষ্কার সমাধান।

## `case`

```
case ( obj assoc -- )
```

`case` স্ট্যাকের একেবারে উপরে থাকা মানটি নিয়ে নেয়, সাথে নেয় ক্লজের একটি *assoc*। প্রতিটি ক্লজ হলো `{ value [ body ] }`। যে ক্লজের মান ইনপুটের সাথে `=` মেলে, সেটিই আগে জেতে; ইনপুট মানটি *আগেই খরচ হয়ে যাওয়া* অবস্থায় তার বডি চলে। শেষে শুধু `[ body ]` থাকা এন্ট্রিটি হলো ডিফল্ট; এটি চলার সময় ইনপুট *এখনও স্ট্যাকে* থাকে।

```factor
USING: combinators ;

: name-of ( n -- s )
    {
        { 1 [ "one" ] }
        { 2 [ "two" ] }
        [ drop "many" ]
    } case ;
```

সমানতা নির্ধারিত হয় `=` দিয়ে, তাই যা-ই `=` অনুযায়ী সমান হয় তা-ই কী (key) হিসেবে কাজ করে, যেমন সংখ্যা, স্ট্রিং আর সিম্বল।

## শর্তযুক্ত শাখার জন্য `cond`

যখন পছন্দটি সমতার বদলে কোনো *প্রেডিকেট*-এর উপর নির্ভর করে (যেমন `x > 11`), তখন `cond`-ই এর মানানসই সরঞ্জাম। [Cars, Assemble!][cars-assemble] অনুশীলনীতে আপনি `cond`-এর সাথে পরিচিত হয়েছেন।

## সিম্বল

একটি `SYMBOL:` এমন একটি ওয়ার্ড ঘোষণা করে, যা নিজেকেই স্ট্যাকে পুশ করে, অর্থাৎ একটি স্ব-ইভ্যালুয়েটিং ট্যাগ মান। `SYMBOLS:` একসাথে কয়েকটি ঘোষণা করে:

```factor
SYMBOLS: yes no maybe ;
```

এখন `yes` হলো একটি মান, যা `=` দিয়ে তুলনা করা যায়, আর যা আপনি কেসের কী (key) হিসেবে ব্যবহার করতে পারেন:

```factor
: invert ( ? -- ?' )
    { { yes [ no ] } { no [ yes ] } [ ] } case ;
```
