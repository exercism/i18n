# সম্পর্কে

## ক্যারেক্টার

একটি [ক্যারেক্টার এনকোডিং][char-encoding] হলো একটি নির্দিষ্ট রীতি, যা দিয়ে কোনো স্বাভাবিক ভাষার টেক্সটের উপাদানগুলোকে বাইটের সিকোয়েন্স হিসেবে প্রকাশ করা হয়।
এখানে "টেক্সটের উপাদান" বলতে স্বাভাবিক ভাষায় অর্থবহ যেকোনো একক বোঝায়, যেমন অক্ষর, স্পেস, যতিচিহ্ন, ইমোজি, আইডিওগ্রাম ইত্যাদি।

NASM (The Netwide Assembler, এই ট্র্যাকের ব্যবহৃত অ্যাসেম্বলার)-এ ASCII ব্যবহার করে ডেটা ডিফাইন করার সাপোর্ট আছে।

NASM-এ ক্যারেক্টার কনস্ট্যান্ট সর্বোচ্চ ৮ বাইট লম্বা হতে পারে এবং একক কোট (`'`), ডাবল কোট (`"`) বা ব্যাকটিক (`` ` ``) দিয়ে ডিফাইন করা যায়:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

বিশেষ ক্যারেক্টার ব্যাকটিকের ভেতরে ডিফাইন করতে হয় এবং `\` দিয়ে এস্কেপ করতে হয়:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASM-এ [ইউনিকোড ক্যারেক্টার][unicode]-ও [UTF-8][utf8]-এ লেখার সাপোর্ট আছে, যা `\u` বা `\U` দিয়ে এবং ব্যাকটিকের ভেতরে নির্দিষ্ট করা হয়:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

মনে রাখবেন, x86-64-এ আলাদা ডেটা টাইপ হিসেবে কোনো ক্যারেক্টার এনকোডিংয়ের বিল্ট-ইন সাপোর্ট নেই।
অ্যাসেম্বলিতে ডেটা হলো বাইটের সিকোয়েন্স, আর সেই বাইটগুলোকে ক্যারেক্টার, সংখ্যা বা অন্য যেকোনো কিছু হিসেবে ব্যাখ্যা করার দায়িত্ব প্রোগ্রামারের।

উদাহরণস্বরূপ, ASCII ক্যারেক্টার '0' হলো এক বাইট, যার মান ৪৮।
তাই একটি বাইটে ৪৮ রাখা আর ASCII ক্যারেক্টার '0' রাখা ঠিক একই কাজ:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

ঠিক এই কারণেই ক্যারেক্টার নিয়ে কাজ করা হয় সেই বাইটগুলোর মান সরাসরি বদলে দিয়ে:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## স্ট্রিং

একটি [স্ট্রিং][string] হলো ক্যারেক্টারের একটি সিকোয়েন্স।
অ্যাসেম্বলিতে এটি সাধারণত একটি অ্যারে হিসেবে তৈরি করা হয়।

যেকোনো অ্যারে ডিক্লেয়ার করার মতোই NASM-এ স্ট্রিং ডিক্লেয়ার করা সম্ভব:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

স্ট্রিং আর অন্য অ্যারেগুলোর মধ্যে একটি পার্থক্য হলো, NASM-এ মান আলাদা করার জন্য কমা (`,`) ছাড়াও স্ট্রিং ডিক্লেয়ার করার সাপোর্ট আছে।
আবার কমা দিয়ে মানগুলো মিশিয়েও লেখা যায়:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

মনে রাখবেন, আগেই বলা হয়েছে, ক্যারেক্টার আসলে শুধু বাইট (অথবা ইউনিকোড এনকোডিংয়ে বাইটের সিকোয়েন্স):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

যেহেতু প্রতিটি ASCII ক্যারেক্টার এক বাইট নেয়, তাই বেশি সাইজের ক্ষেত্রে এর পরের প্রতিটি বাইট `0` হয়।
উদাহরণস্বরূপ, `'a'` কে কিউওয়ার্ড (৮ বাইট) হিসেবে ডিক্লেয়ার করলে প্রথম বাইটটি হয় `'a'` (`97`) আর বাকি সাতটি বাইট সবই `0`।

এই কারণেই নিচের সবগুলো সমতুল্য:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
অ্যাসেম্বলিতে স্ট্রিং স্বয়ংক্রিয়ভাবে একটি ASCII NUL ক্যারেক্টার (মান `0`) দিয়ে শেষ হয় না।

C-এর মতো উচ্চ-স্তরের ভাষার সাথে কাজ করার সময় স্ট্রিংয়ের শেষে সঠিক টার্মিনেটর (যদি থাকে) যোগ করার দায়িত্ব প্রোগ্রামারের।
~~~~

## স্ট্রিং ইনস্ট্রাকশন

যেহেতু স্ট্রিং অ্যারে, তাই যেকোনো অ্যারের মতোই মেমরি সরাসরি ডিরেফারেন্স করে আপনি এগুলো নিয়ে কাজ করতে পারেন:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

এর পাশাপাশি, মেমরিতে বাইটের সিকোয়েন্সে মান লোড, মুভ আর স্টোর করার কিছু ইনস্ট্রাকশন আছে।
যদিও এগুলোকে _স্ট্রিং ইনস্ট্রাকশন_ বলা হয়, মেমরিতে যেকোনো বাইট-সিকোয়েন্সের সাথে, অর্থাৎ যেকোনো অ্যারের সাথে এগুলো ব্যবহার করা যায়:

| ইনস্ট্রাকশন  | এটি যা করে                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | `rsi` দিয়ে নির্দেশিত একটি মেমরি লোকেশন থেকে `rax`-এ একটি মান লোড করে                                              |
| [stos][stos] | `rax` থেকে একটি মান `rdi` দিয়ে নির্দেশিত একটি মেমরি লোকেশনে স্টোর করে                                             |
| [movs][movs] | `rsi` দিয়ে নির্দেশিত একটি মেমরি লোকেশন থেকে একটি মান কপি করে `rdi` দিয়ে নির্দেশিত একটি মেমরি লোকেশনে স্টোর করে    |
| [cmps][cmps] | `rsi` দিয়ে নির্দেশিত একটি মেমরি লোকেশনের মানের সাথে `rdi` দিয়ে নির্দেশিত একটি মেমরি লোকেশনের মান তুলনা করে        |
| [scas][scas] | `rax`-এর মানের সাথে `rdi` দিয়ে নির্দেশিত একটি মেমরি লোকেশনের মান তুলনা করে                                       |

মনে রাখবেন, এই ইনস্ট্রাকশনগুলো কোনো স্পষ্ট অপারেন্ড নেয় _না_।
এদের অপারেন্ড অন্তর্নিহিত।

সাধারণ নিয়ম হিসেবে:

1. যখন এদের সোর্স অপারেন্ড একটি মেমরি লোকেশন হয়, তার অ্যাড্রেস `rsi`-তে রাখা উচিত (`s` মানে source)।
2. যখন এদের ডেস্টিনেশন অপারেন্ড একটি মেমরি লোকেশন হয়, তার অ্যাড্রেস বরং `rdi`-তে রাখা উচিত (`d` মানে destination)।
3. যদি অপারেন্ডগুলোর একটি মেমরি লোকেশন না হয়, সেটি `rax` রেজিস্টার।

মনে রাখবেন, এই ইনস্ট্রাকশনগুলো যে নির্দিষ্ট কাজটি করে, সেই অনুযায়ী মেমরি অ্যাড্রেসগুলো স্বয়ংক্রিয়ভাবে ডিরেফারেন্স করে।

এগুলো সবই বিভিন্ন সাইজে কাজ করতে পারে।
সাইজ বোঝাতে নামের শেষে একটি সাফিক্স যোগ করা হয়:

| সাফিক্স | অর্থ | সাইজ    |
| :----: | ------- | :------ |
|  `b`   | বাইট    | ১ বাইট  |
|  `w`   | ওয়ার্ড    | ২ বাইট |
|  `d`   | ডওয়ার্ড   | ৪ বাইট |
|  `q`   | কিউওয়ার্ড   | ৮ বাইট |

যেমন:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

এগুলো যে অ্যাড্রেস ব্যবহার করে, সেটিও অপারেশনের সাইজ অনুযায়ী আপডেট করে।
এই আপডেটটি করা হয় **ডিরেকশন ফ্ল্যাগ (DF)**-এর মান অনুযায়ী:

- যদি `DF` ক্লিয়ার থাকে, অ্যাড্রেসগুলো অপারেশনের সাইজ অনুযায়ী _বাড়ে_।
- যদি `DF` সেট থাকে, অ্যাড্রেসগুলো বরং একই পরিমাণ _কমে_।

System V ABI অনুযায়ী, ফাংশনে প্রবেশের সময় ডিরেকশন ফ্ল্যাগ ক্লিয়ার থাকতে হবে।
তাই _ডিফল্ট আচরণ হলো, মেমরিতে পড়া ও লেখা হয় অ্যাড্রেসের ঊর্ধ্বক্রমে_।

ডিরেকশন ফ্ল্যাগ ক্লিয়ার করতে [cld][cld] ইনস্ট্রাকশন ব্যবহার করা যায়, আর সেট করতে [std][std] ইনস্ট্রাকশন:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
System V ABI অনুযায়ী, কল করা কোনো ফাংশন রিটার্ন করার পর কলার আশা করে `DF` ক্লিয়ার থাকবে।
আপনি যদি কখনো `DF` সেট করেন, তবে `ret`-এর আগে সেটি ক্লিয়ার করতে ভুলবেন না।
~~~~

### Lods

এই ইনস্ট্রাকশনটি যে মেমরি লোকেশনের অ্যাড্রেস `rsi`-তে আছে, সেখান থেকে _পড়ে_ এবং মানটি `rax`-এ কপি করে।

পড়া বাইটের সংখ্যা অনুযায়ী `rsi`-এর মান আপডেট হয়:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

এই ইনস্ট্রাকশনটি `rax`-এর মান কপি করে এবং সেটি যে মেমরি লোকেশনের অ্যাড্রেস `rdi`-তে আছে, সেখানে _লেখে_।

লেখা বাইটের সংখ্যা অনুযায়ী `rdi`-এর মান আপডেট হয়:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

এই ইনস্ট্রাকশনটি যে মেমরি লোকেশনের অ্যাড্রেস `rsi`-তে আছে, সেখান থেকে _পড়ে_ এবং মানটি যে মেমরি লোকেশনের অ্যাড্রেস `rdi`-তে আছে, সেখানে _লেখে_।
এই ইনস্ট্রাকশনে `rax`-এর মান বদলায় না।

এক মেমরি লোকেশন থেকে অন্যটিতে কপি হওয়া বাইটের সংখ্যা অনুযায়ী `rsi` আর `rdi` দুটোই আপডেট হয়:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

এই ইনস্ট্রাকশনটি যে মেমরি লোকেশনের অ্যাড্রেস `rsi`-তে আছে, সেখান থেকে _পড়ে_, আবার যে মেমরি লোকেশনের অ্যাড্রেস `rdi`-তে আছে, সেখান থেকেও _পড়ে_।
এরপর মানগুলো তুলনা করে এবং `cmp` অনুযায়ী ফ্ল্যাগ আপডেট করে।

দুটি লোকেশন থেকেই পড়া বাইটের সংখ্যা অনুযায়ী `rsi` আর `rdi` দুটোই আপডেট হয়:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

এই ইনস্ট্রাকশনটি `rax`-এর মানের সাথে সেই মান তুলনা করে, যা সে `rdi`-তে থাকা অ্যাড্রেসের একটি মেমরি লোকেশন থেকে _পড়ে_।
এরপর `cmp` অনুযায়ী ফ্ল্যাগ আপডেট করে।

পড়া বাইটের সংখ্যা অনুযায়ী `rdi`-এর মান আপডেট হয়:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

এগুলো ছাড়াও, [rep][rep] ইনস্ট্রাকশনটি সরাসরি মেমরির সাথে কাজ করে না।
বরং এটি উপরে উল্লিখিত অন্য ইনস্ট্রাকশনগুলোর আগে প্রিফিক্স হিসেবে যোগ করা যায়, যা ওই ইনস্ট্রাকশনগুলোকে _পুনরাবৃত্তি_ করে।

`rep` প্রিফিক্স দিলে স্ট্রিং ইনস্ট্রাকশনগুলো `rcx`-এর মানের সমান সংখ্যক বার পুনরাবৃত্ত হয়।
প্রতিবারই `rcx`-এর মান `1` কমে।
মনে রাখবেন, ইনস্ট্রাকশনটি ব্যবহারের আগে `rcx`-এর মান সেট করে নিতে হবে:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

কাউন্টার হিসেবে `rcx` ব্যবহার করা ছাড়াও, `repe` (বা `repz`) আর `repne` (বা `repnz`) যথাক্রমে `zero flag (ZF)` ক্লিয়ার বা সেট থাকলে এক্সিকিউশন থামিয়ে দেয়:

| ইনস্ট্রাকশন      | কোথায় যোগ করা যায়     | আগেই থামতে পারে        |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`, `lods`, `stos` | না                      |
| `repe`,`repz`    | `cmps`, `scas`         | হ্যাঁ, ZF ০ হলে থামে |
| `repne`, `repnz` | `cmps`, `scas`         | হ্যাঁ, ZF ১ হলে থামে |

তবে অন্য স্ট্রিং ইনস্ট্রাকশনগুলো, এমনকি `rep` ছাড়া চালানো `movs` আর `stos`-ও, সাধারণত একটি সাধারণ লুপের চেয়ে ধীর।
