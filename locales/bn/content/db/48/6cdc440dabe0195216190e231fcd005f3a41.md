# পরিচিতি

`LocalDate` ও `LocalDateTime`-এর মতো ক্লাস সময়ের একটি _বিন্দু_ বর্ণনা করে।
`java.time` প্যাকেজে আরও দুটি ক্লাস আছে, যারা সময়ের একটি _পরিমাণ_ বর্ণনা করে:

- [`Period`][period-docs] হলো বছর, মাস ও দিনে হিসাব করা তারিখভিত্তিক সময়ের পরিমাণ, যেমন "২ মাস ও ৫ দিন"।
- [`Duration`][duration-docs] হলো ঘণ্টা, মিনিট, সেকেন্ড, মিলিসেকেন্ড ও ন্যানোসেকেন্ডে হিসাব করা সময়ের পরিমাণ, যেমন "১ ঘণ্টা ৩০ মিনিট"।

এই পার্থক্যটি গুরুত্বপূর্ণ, কারণ ক্যালেন্ডারের এককগুলোর নির্দিষ্ট দৈর্ঘ্য নেই।
একটি মাসে ২৮, ২৯, ৩০ বা ৩১ দিন হতে পারে, তাই "এক মাস" নির্দিষ্ট সংখ্যক সেকেন্ড নয়।
একটি `Period` ক্যালেন্ডার অনুসরণ করে, আর একটি `Duration` সুনির্দিষ্ট সময় মাপে।

| | `Period` | `Duration` |
| --- | --- | --- |
| যা সংরক্ষণ করে | বছর, মাস ও দিন | সেকেন্ড ও ন্যানোসেকেন্ড |
| যাদের সাথে ব্যবহৃত হয় | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

দুটি ক্লাসই ইমিউটেবল।
`plusDays()` বা `multipliedBy()`-এর মতো মেথড একটি _নতুন_ ইনস্ট্যান্স রিটার্ন করে এবং মূলটি অপরিবর্তিত রাখে।

## `Period`

### পিরিয়ড তৈরি করা

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

`toString()`-এর ফলাফল [ISO-8601 ডিউরেশন ফরম্যাট][iso-8601-durations] ব্যবহার করে: `P`, তারপর বছরের সংখ্যা (`Y`), মাসের সংখ্যা (`M`) ও দিনের সংখ্যা (`D`)।
`Period`-এ সপ্তাহ বলে কিছু নেই: `Period.ofWeeks(2)` ১৪ দিন হিসেবে সংরক্ষিত হয়।
একই নোটেশন `Period.parse()` দিয়ে আবার পার্স করা যায়:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### তারিখে পিরিয়ড যোগ করা

`plus()` ও `minus()` দিয়ে কোনো তারিখে পিরিয়ড যোগ বা বিয়োগ করা হয়:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

একইভাবে `LocalDateTime`-এও পিরিয়ড যোগ করা যায়, আর দিনের সময় অপরিবর্তিত থাকে:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

`Instant`-এর কোনো ক্যালেন্ডার নেই, তাই এতে কেবল দিনের পিরিয়ড যোগ করা যায়।
বছর বা মাসযুক্ত পিরিয়ড এক্সেপশন থ্রো করে:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

প্রথমে বছর যোগ হয়, তারপর মাস, তারপর দিন।
যখন বছর বা মাস যোগ করার ফলে এমন একটি তারিখে পৌঁছানো যায় যা আসলে নেই, তখন ফলাফলটিকে সেই মাসের শেষ বৈধ দিনে ফিরিয়ে আনা হয়:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

এর মানে এইও যে, একটি পিরিয়ড যোগ করে আবার বিয়োগ করলে সবসময় আগের তারিখটি ফিরে পাওয়া যায় না:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### দুটি তারিখের মধ্যবর্তী পিরিয়ড

`Period.between()` একটি তারিখ (অন্তর্ভুক্ত) থেকে আরেকটি তারিখ (অন্তর্ভুক্ত নয়) পর্যন্ত পিরিয়ড রিটার্ন করে।
একই ফলাফল `LocalDate.until()`-এও পাওয়া যায়:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

পিরিয়ডের বিভিন্ন অংশ `getYears()`, `getMonths()` ও `getDays()`-এর মাধ্যমে পাওয়া যায়।
এই অংশগুলো একে অপরের থেকে স্বাধীন: `getDays()` কেবল দিনের অংশটি রিটার্ন করে, মোট দিনসংখ্যা নয়।
`toTotalMonths()` বছর ও মাস একত্রে মাসের সংখ্যা হিসেবে রিটার্ন করে, কিন্তু মোট দিনসংখ্যার জন্য কোনো মেথড নেই, কারণ তা কোন কোন মাস জড়িত তার ওপর নির্ভর করে।

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### পিরিয়ড নরমালাইজ করা

ফ্যাক্টরি মেথড দিয়ে তৈরি পিরিয়ড তার এককগুলো ঠিক যেমন দেওয়া হয়েছে তেমনই রাখে, আর `equals()` এককগুলো একটি একটি করে তুলনা করে।
`normalized()` মাসকে বছরে রূপান্তর করে, কিন্তু দিনগুলো অপরিবর্তিত রাখে:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## `ChronoUnit` দিয়ে একক গণনা করা

দুটি সময়বিন্দুর মধ্যে কোনো একক এককের মোট সংখ্যা পেতে [`ChronoUnit`][chronounit-docs]-এর একটি কনস্ট্যান্টের ওপর `between()` মেথড ব্যবহার করুন:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

কেবল পূর্ণ এককগুলো গণনা করা হয়, আর দ্বিতীয় আর্গুমেন্ট প্রথমটির আগে হলে ফলাফল ঋণাত্মক হয়:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit` সময়ভিত্তিক একক ও ডেট-টাইমের সাথেও কাজ করে:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### ডিউরেশন তৈরি করা

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

ISO-8601 নোটেশনে `T` তারিখের অংশকে সময়ের অংশ থেকে আলাদা করে।
`Duration`-এর কোনো তারিখের অংশ নেই, তাই এর `toString()` সবসময় `PT` দিয়ে শুরু হয়।
`Duration.ofDays()` একটি দিনকে ঠিক ২৪ ঘণ্টা হিসেবে ধরে।

`Duration.parse()` দিয়েও ডিউরেশন পার্স করা যায়:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### সময়ে ডিউরেশন যোগ করা

`plus()` ও `minus()` দিয়ে `LocalTime`, `LocalDateTime` বা `Instant`-এ ডিউরেশন যোগ বা বিয়োগ করা হয়:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

শেষ উদাহরণটি যেমন দেখায়, একটি `LocalTime` মধ্যরাত পেরিয়ে ঘুরে যায়।

`LocalDate`-এর কোনো সময় নেই, তাই এটির সাথে `Duration` মেলানো যায় না:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### দুটি সময়ের মধ্যবর্তী ডিউরেশন

`Duration.between()` দুটি সময় বা ডেট-টাইমের মধ্যে সময়ের সুনির্দিষ্ট পরিমাণ রিটার্ন করে:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()` দুটি `LocalDate` মান গ্রহণ করে না, কারণ তারিখে মাপার মতো কোনো সেকেন্ড নেই:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

তারিখের জন্য এর বদলে `Period.between()` বা `ChronoUnit.DAYS.between()` ব্যবহার করুন।

### ডিউরেশন রূপান্তর করা

`toXxx()` মেথডগুলো একটি ডিউরেশনকে একক এককের _মোট_ পরিমাণে রূপান্তর করে, নিচের দিকে রাউন্ড করে:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

`toXxxPart()` মেথডগুলো একটি ডিউরেশনকে ঘড়ির মতো তার অংশে ভাগ করে:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()` ২৩-এ থেমে যায়, কারণ তার বেশি ঘণ্টা `toDaysPart()` দিয়ে গণনা করা হয়।

### ডিউরেশন তুলনা ও গণনা করা

ডিউরেশন `compareTo()` দিয়ে তুলনা করা যায়, আর `isZero()` ও `isNegative()` দিয়ে পরীক্ষা করা যায়:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

এগুলো `plus()`, `minus()`, `multipliedBy()` ও `dividedBy()`-এর মতো গাণিতিক কাজও সমর্থন করে:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` নাকি `Duration`?

`LocalDate` বা `LocalTime`-এর ক্ষেত্রে পছন্দ আপনাকে করতে হয় না: তারিখে মাপার মতো সময় নেই, আর সময়ের কোনো ক্যালেন্ডার নেই।
`LocalDateTime`-এ দুটোই আছে, কিন্তু টাইম জোন নেই, তাই এতে `Period.ofDays(1)` বা `Duration.ofDays(1)` যোগ করলে একই ফলাফল দেয়।
টাইম জোনের ক্ষেত্রে পার্থক্যটি চোখে পড়ে।
ডেলাইট সেভিং টাইমের জন্য ঘড়ি সামনে গেলে একটি ক্যালেন্ডার দিন মাত্র ২৩ ঘণ্টা লম্বা হয়:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

এক দিনের `Period` যোগ করলে দিনের সময় অপরিবর্তিত থাকে, আর এক দিনের `Duration` যোগ করলে ঠিক ২৪ ঘণ্টা যোগ হয়।
মানুষ যখন ক্যালেন্ডারের হিসাবে ভাবে এমন পরিমাণের জন্য `Period` ব্যবহার করুন ("আগামী মাসে একই সময়ে"), আর অতিবাহিত সময়ের জন্য `Duration` ("পার্কিং টিকিট ২ ঘণ্টা বৈধ")।
