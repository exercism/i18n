# ভূমিকা

## রেজাল্ট

Gleam এরর হ্যান্ডলিংয়ের জন্য এক্সেপশন ব্যবহার করে না; বরং যে ফাংশনগুলো সফলও হতে পারে, আবার ব্যর্থও হতে পারে, তারা জেনেরিক `Result` টাইপ রিটার্ন করে।

`Result` টাইপটি ভাষার ভেতরেই বিল্ট-ইন করা আছে, তাই এটি ডিফাইন বা ইমপোর্ট করার দরকার নেই। তবে আপনি যদি নিজেই এটি ডিফাইন করতেন, তবে সেটি দেখতে এমন হতো:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

ফাংশন সফল হলে `Ok` ভ্যারিয়েন্ট রিটার্ন হয়, আর ফাংশন ব্যর্থ হলে `Error` ভ্যারিয়েন্ট রিটার্ন হয়।

রেজাল্ট Gleam-এ খুবই কমন, আর Gleam প্রোগ্রামাররা সাধারণত [`gleam/result` মডিউল](https://hexdocs.pm/gleam_stdlib/gleam/result.html) ব্যবহার করেন, যাতে এগুলো নিয়ে কাজ করা সহজ হয়।

কোনো রেজাল্টের ভেতরের মানটি `Ok` হলে তার উপর একটি ফাংশন কল করতে, আর `Error` হলে সেটি অপরিবর্তিত রেখে দিতে `result.map` ফাংশনটি ব্যবহার করা যায়।

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

`result.try` ফাংশনটিও একই রকম, তবে এখানে কলব্যাক ফাংশন থেকে রেজাল্ট রিটার্ন করার আশা করা হয়। একাধিক ফাংশন যেগুলো রেজাল্ট রিটার্ন করে, সেগুলো পরপর চেইন করতে এটি কাজে লাগে।

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
