# সম্পর্কে

## মডিউল

Gleam কোড মডিউলে সাজানো থাকে, আর প্রতিটি ফাইল একটি Gleam মডিউল।

এখন পর্যন্ত আমরা `pub fn` সিনট্যাক্স দিয়ে ফাংশন লিখেছি, যা এমন একটি ফাংশন ডিফাইন করে যেটি অন্য মডিউলগুলো ব্যবহার করতে পারে। `fn` দিয়ে ডিফাইন করা ফাংশন যে মডিউলে ডিফাইন করা হয়েছে তার কাছে প্রাইভেট থাকে, অন্য মডিউলগুলো সেগুলো ব্যবহার করতে পারে না।

```gleam
// This function is public
pub fn add(x, y) {
  x + y
}

// This function is private
fn subtract(x, y) {
  x - y
}
```

Gleam মডিউলের নাম থাকে, আর নামটি `src` বা `test` ডিরেক্টরির ভেতরে ফাইলের পাথের উপর ভিত্তি করে ঠিক হয়।

যেমন, `src\geometry\rectangle.gleam` (Windows-এ) বা `src/geometry/rectangle.gleam` (UNIX-ধরনের অপারেটিং সিস্টেমে) পাথে ডিফাইন করা একটি মডিউলের নাম হবে `geometry/rectangle`।

## অন্য মডিউল থেকে ফাংশন ইমপোর্ট করা

অন্য মডিউলে ডিফাইন করা ফাংশন ব্যবহার করা হয় ইমপোর্টের মাধ্যমে। কোনো মডিউল ইমপোর্ট করলে তার ভেতরে থাকা এবং তার দ্বারা উন্মুক্ত করা সব ফাংশনই ব্যবহারযোগ্য হয়ে যায়। তবে সেগুলো কীভাবে ব্যবহার করা যায়, তা নির্ভর করে মডিউলটি কীভাবে ইমপোর্ট করা হয়েছে তার উপর।

কোয়ালিফাইড ইমপোর্টই ডিফল্ট, আর এমন মডিউলের ভেতরের কোনো ফাংশন (যেমন `gleam/list` মডিউলের `map` ফাংশন) ব্যবহার করতে হলে মডিউলের নাম আগে বসিয়ে দিতে হয় (`list.map`)।

```gleam
// Import the int module
import gleam/int

pub fn run(x: Int) -> String {
  // Use the to_string function from the int module
  int.to_string(x)
}
```

ডিফল্টভাবে মডিউল বোঝাতে যে নামটি ব্যবহার করা হয় সেটি মডিউলের নামের শেষ অংশ, এই ক্ষেত্রে `int`, তবে `as` কিওয়ার্ড ব্যবহার করে এটি বদলানো যায়।

```gleam
// Import the int module and refer to it as i
import gleam/int as i

pub fn run(x: Int) -> String {
  i.to_string(x)
}
```

আনকোয়ালিফাইড ইমপোর্ট সেই মডিউলের উন্মুক্ত ফাংশনগুলো সরাসরি ব্যবহার করার সুযোগ দেয়, কোনো প্রিফিক্স ছাড়াই।

```gleam
// Import the to_string function from the int module
import gleam/int.{to_string}

pub fn run(x: Int) -> String {
  to_string(x)
}
```

কোয়ালিফাইড ইমপোর্টই বেশি পছন্দনীয়, কারণ এতে পাঠকের কাছে স্পষ্ট হয় ফাংশনটি কোথা থেকে আসছে, আর নামের সংঘর্ষও এড়ানো যায়।
