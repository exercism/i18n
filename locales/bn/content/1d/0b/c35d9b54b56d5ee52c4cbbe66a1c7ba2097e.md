# সম্পর্কে

C#-এ, একটি _ক্লাস_ হায়ারার্কি _ইনহেরিট্যান্স_ ব্যবহার করে সংজ্ঞায়িত করা যায়, যার মাধ্যমে একটি ডেরাইভড ক্লাস (`Car`) তার প্যারেন্ট ক্লাসের (`Vehicle`) আচরণ ও ডেটা ইনহেরিট করতে পারে। যদি কোনো প্যারেন্ট নির্দিষ্ট করা না থাকে, ক্লাসটি `object` ক্লাস থেকে ইনহেরিট করে।

প্যারেন্ট ক্লাসগুলো ডেরাইভড ক্লাসকে তিনটি উপায়ে কার্যকারিতা প্রদান করতে পারে:

- একটি সাধারণ মেথড ডিফাইন করা।
- একটি [`virtual` মেথড][virtual-keyword] ডিফাইন করা, যা সাধারণ মেথডের মতোই, তবে ডেরাইভড ক্লাসগুলো এটিকে _বদলাতে পারে_।
- একটি [`abstract` মেথড][abstract-keyword] ডিফাইন করা, যা ইমপ্লিমেন্টেশন ছাড়া একটি মেথড, আর ডেরাইভড ক্লাসগুলোকে _অবশ্যই_ ইমপ্লিমেন্ট করতে হয়। `abstract` মেথড আছে এমন একটি ক্লাসকেও [`abstract`][abstract-classes] হিসেবে চিহ্নিত করতে হবে। অ্যাবস্ট্রাক্ট ক্লাস ইনস্ট্যানশিয়েট করা যায় না।

[`protected` অ্যাক্সেস মডিফায়ার][protected-keyword] একটি প্যারেন্ট ক্লাসের মেম্বারকে ডেরাইভড ক্লাসে অ্যাক্সেস করার অনুমতি দেয়, কিন্তু অন্য ক্লাস থেকে অ্যাক্সেস ব্লক করে। এভাবে ডেরাইভড ক্লাসগুলো `public` এবং `protected` প্যারেন্ট ক্লাসের মেম্বার অ্যাক্সেস করতে পারে, কিন্তু `private` প্যারেন্ট ক্লাসের মেম্বার অ্যাক্সেস করতে পারে না।

ডেরাইভড ক্লাসগুলো [`base` কিওয়ার্ড][base-keyword] ব্যবহার করে প্যারেন্ট ক্লাসের মেম্বার অ্যাক্সেস করতে পারে।

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

একটি ডেরাইভড ক্লাসের কনস্ট্রাক্টর তার নিজের কনস্ট্রাক্টরের লজিক চালানোর _আগে_ [স্বয়ংক্রিয়ভাবে তার প্যারেন্টের কনস্ট্রাক্টর কল করবে][constructors]। প্যারেন্ট ক্লাসের কনস্ট্রাক্টরে [`base` কিওয়ার্ড][base-keyword-constructor] ব্যবহার করে আর্গুমেন্ট পাঠানো যায়। যেহেতু অ্যাবস্ট্রাক্ট ক্লাস ইনস্ট্যানশিয়েট করা যায় না, তাই তাদের কনস্ট্রাক্টর `protected` করা যেতে পারে।

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

যখন একাধিক ক্লাস একটি বেস ক্লাস থেকে ডেরাইভ করা হয়, তখন দুই (বা তার বেশি) সাব-ক্লাস প্রায়ই বেস ক্লাসের একটি মেথডের ভিন্ন ভিন্ন ভার্সন ইমপ্লিমেন্ট করে। এটি একটি অত্যন্ত গুরুত্বপূর্ণ নীতি, যাকে [পলিমরফিজম][polymorphism] বলা হয়। উদাহরণস্বরূপ, উপরের উদাহরণের একটি ভিন্ন রূপে আমরা দেখাই যে `Vehicle` ব্যবহার করা কোড, কোন ধরনের যানবাহন ইনস্ট্যানশিয়েট হয়েছে তার উপর নির্ভর করে, কীভাবে তার আচরণ বদলাতে পারে।

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

কোনো ক্লাস ইনহেরিট হওয়া আটকাতে [`sealed` মডিফায়ার][sealed-classes] যোগ করুন। কিছু প্র্যাকটিশনার কনক্রিট ক্লাস থেকে ইনহেরিট করা এড়াতে চেষ্টা করেন ([এই Stack Overflow প্রশ্নে][pro-sealed] আলোচনা করা হয়েছে) এবং _sealed_ মডিফায়ার এই পদ্ধতিকে সমর্থন করে। অন্যদিকে, অনেক C# ডেভেলপার এগুলোকে রক্ষণাবেক্ষণের জন্য বাধা বলে মনে করেন, যেমনটি [এই প্রশ্নের][anti-sealed] কিছু মন্তব্যে আলোচনা করা হয়েছে। পরামর্শ হলো, আপনার প্রয়োজন অনুযায়ী এগুলোর ব্যবহারে আত্মবিশ্বাস না আসা পর্যন্ত sealed মডিফায়ার সীমিতভাবে ব্যবহার করা।

নিচের [নিবন্ধটি][new-vs-override] `override` মডিফায়ারের বিকল্প হিসেবে `new`-এর বর্ণনা দেয়। এটি মাঝে মাঝে কাজে লাগে, হয়তো জটিল ক্লাস হায়ারার্কি এবং/অথবা লাইব্রেরিগুলোর মধ্যে কোনো ধরনের সংঘর্ষের ক্ষেত্রে।
