# সম্পর্কে

ট্রান্সমিশনের জন্য একটি মান তৈরি করার সময় একসাথে তিনটি কাজ করতে হয়:
সেটি সিরিয়ালাইজ করা, তার মধ্য থেকে ঠিক অংশটি বেছে নেওয়া, আর
প্রয়োজন না থাকলে কপি না করা। Factor-এর তিনটি আইডিয়ম এই কাজগুলো সামলে দেয়।

## `unparse`: মান থেকে সোর্স

[`unparse`][unparse] (`prettyprint`-এ) যেকোনো মানের সোর্স-ফর্ম টেক্সট রিটার্ন করে।
এটি পার্সারের ঠিক উল্টো কাজ করে, অর্থাৎ `dup unparse parse` করলে আবার সেই
মানটিই তৈরি হয়।

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

এর সাথে তুলনা করুন `>string`-এর (যা শুধু ক্যারেক্টার সিকোয়েন্সে কাজ করে)
আর `number>string`-এর (শুধু সংখ্যায়)। `unparse` হলো সার্বজনীন সমাধান,
তবে এর দাম হলো এটি Factor সিনট্যাক্স তৈরি করে (উদ্ধৃতি চিহ্নে লেখা স্ট্রিং
নিজের উদ্ধৃতি চিহ্ন ধরে রাখে)। তাই যে ক্ষেত্রে প্রাপক ওই টেক্সট আবার পার্স
করবে, সেখানে এটি সঠিক টুল; আর মানুষের পড়ার উপযোগী আউটপুটের জন্য এটি ভুল
পছন্দ।

## স্লাইস: কপি নয়, ভিউ

| ওয়ার্ড      | প্রভাব                                          |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`, প্রথম n কপি করে          |
| `head-slice`  | `( seq n -- slice )`, প্রথম n-এর ভিউ            |
| `tail`        | `( seq n -- newseq )`, ইনডেক্স n থেকে কপি করে   |
| `tail-slice`  | `( seq n -- slice )`, ইনডেক্স n থেকে ভিউ        |
| `head*`       | `( seq n -- newseq )`, শেষ n বাদ দিয়ে কপি করে  |
| `head-slice*` | `( seq n -- slice )`, শেষ n বাদ দিয়ে ভিউ        |
| `tail*`       | `( seq n -- newseq )`, শেষ n কপি করে            |
| `tail-slice*` | `( seq n -- slice )`, শেষ n-এর ভিউ              |

একটি `slice` হলো একটি টাপল, যাতে থাকে একটি from-ইনডেক্স, একটি to-ইনডেক্স
আর মূল সিকোয়েন্স। এটি [sequence protocol][sequence-protocol] ইমপ্লিমেন্ট করে,
তাই যেকোনো সিকোয়েন্স অপারেশন এর উপর কাজ করে। শুধু পড়ার জন্যই যদি নাহলে
আলাদা মেমোরি বরাদ্দ করতে হতো, তাহলে স্লাইস ভ্যারিয়েন্টগুলো বেছে নিন; আর মূল
সিকোয়েন্স বদলে যাওয়ার পরেও যদি ডেটা রেখে দিতে চান, তাহলে কপি করা
ভ্যারিয়েন্টগুলো নিন।

## মাল্টি-ইনপুট ক্লিভ: `2bi`, `3bi`, `2tri`, `3tri`

সাধারণ ক্লিভ ওয়ার্ড `bi` আর `tri` স্ট্যাকের *একটি* ইনপুটের উপর দুটি বা তিনটি
কোয়োটেশন প্রয়োগ করে। `2`-প্রিফিক্স আর `3`-প্রিফিক্স দেওয়া ভ্যারিয়েন্টগুলো
প্রতিটি কোয়োটেশন *দুটি* বা *তিনটি* ইনপুটে প্রয়োগ করে:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

প্রতিটি কোয়োটেশন *সব* ইনপুট পায়। তাই `2bi` ব্যবহার করুন যখন দুটি প্রজেকশনই
জোড়ার উপর নির্ভর করে, কিন্তু যখন একই প্রজেকশন আলাদা আলাদাভাবে প্রতিটি ইনপুটে
প্রয়োগ করতে চান তখন নয় (সেটার জন্য `bi@`)।

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

*একটি* কোয়োটেশন আলাদা আলাদাভাবে প্রতিটি ইনপুটে প্রয়োগ করতে হলে `bi@`
(দুই ইনপুট) বা `tri@` (তিন ইনপুট) ব্যবহার করুন। একই পরিবার, কেবল আকার আলাদা।
