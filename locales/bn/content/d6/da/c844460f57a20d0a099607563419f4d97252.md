# ভূমিকা

একটি *কোয়োটেশন* (`[ ]` বন্ধনীর ভেতরের কোড) Factor-এ নিজেই একটি মান, ঠিক একটি সংখ্যা বা স্ট্রিং-এর মতোই। আপনি একটি ভ্যারিয়েবলে এটি রাখতে পারেন, একটি অ্যারেতে রাখতে পারেন, অন্য একটি ওয়ার্ডে পাস করতে পারেন, আর পরে সেটি *কল* করতে পারেন।

## `call`

`call` ([`kernel`][kernel]-এ) একটি কোয়োটেশন রান করে:

```factor
3 4 [ + ] call .
! => 7
```

যখন আপনি এমন কোনো প্রসঙ্গে একটি কোয়োটেশন `call` করেন যেখানে Factor তার স্ট্যাক ইফেক্ট অনুমান করতে পারে না, তখন আপনাকে ইফেক্টটি স্পষ্টভাবে ঘোষণা করতে হবে:

```
call( stack-effect ) ! e.g. call( a b -- c )
```

```factor
: apply-binary ( a b op -- c )
    call( a b -- c ) ;

5 3 [ - ] apply-binary .
! => 2
```

এটি একটি রানটাইম চেক কম্পাইল করে, যা যাচাই করে কোয়োটেশনটির সত্যিই ঘোষিত ইফেক্টটি আছে কি না।

## সিকোয়েন্সে কোয়োটেশন

যেহেতু কোয়োটেশনগুলো নিজেই মান, একটি অ্যারে সংখ্যা আর কোয়োটেশনের মিশ্রণ ধারণ করতে পারে:

```factor
{ 3 4 [ + ] }
```

তাতে "একটি প্রোগ্রাম" একটি সাধারণ সিকোয়েন্স হয়ে যায়, আর সেটি চালানোর একটি স্বাভাবিক উপায় হয়ে ওঠে `each`:

```
each ( seq quot -- )
```

```factor
{ [ 1 + ] [ 2 * ] } 5 swap [ call( x -- y ) ] each .
! 5 -> 6 -> 12
```

## একটি সিকোয়েন্সের শেষাংশ কেটে নেওয়া

`head*` শেষ `n` সংখ্যক এলিমেন্ট বাদে বাকি সব রিটার্ন করে; `last2` শেষ দুটি রিটার্ন করে:

```
head* ( seq n -- headseq )
last2 ( seq -- penultimate last )
```

```factor
{ 1 2 3 4 5 } 2 head* .    ! => { 1 2 3 }
{ 1 2 3 4 5 } last2 .s
! => 4
! => 5
```

`suffix`-এর সঙ্গে মিলিয়ে, "উপরের দুটি নিয়ে একটি ফলাফল পুশ" ধরনের স্ট্যাক অপারেশন লেখার যা যা দরকার, তার সবই এতে আছে।
