# পরিচিতি

C ভাষায় একটি [struct][struct] হলো একটি কম্পোজিট টাইপ, যা বিভিন্ন ফিল্ড দিয়ে গঠিত। প্রতিটি ফিল্ডের নিজস্ব টাইপ ও সাইজ থাকে।

উদাহরণস্বরূপ, এটি তিনটি ইন্টিজার নিয়ে একটি টাইপ ডিফাইন করে, যার দুটি ৪ বাইটের এবং একটি ৮ বাইটের:

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

একটি struct-এ অন্য struct-ও থাকতে পারে:

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

struct-এর কোনো একটি ফিল্ড যদি অ্যারে হয়, তাহলে অ্যারের জন্য বরাদ্দ করা সব বাইট struct-এর অংশ। কিন্তু ফিল্ডটি যদি কেবল অ্যারেটির দিকে একটি পয়েন্টার হয়, তাহলে অ্যারেটি অন্য কোথাও সংরক্ষণ করতে হবে:

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## অ্যালাইনমেন্ট

একটি টাইপের [alignment][alignment] হলো দুইয়ের একটি অ-ঋণাত্মক ঘাত (১, ২, ৪, ৮, ...), যা তার অ্যাড্রেসের উপর একটি বাধ্যবাধকতা বোঝায়। ওই টাইপের প্রতিটি অবজেক্টকে এমন একটি অ্যাড্রেসে থাকতে হবে, যা তার অ্যালাইনমেন্টের গুণিতক।

প্রিমিটিভ টাইপের ক্ষেত্রে অ্যালাইনমেন্ট সাধারণত তার সাইজের সমান হয়, তাই উদাহরণস্বরূপ, একটি `int32_t`-এর অ্যালাইনমেন্ট সাধারণত ৪ বাইট। এর মানে হলো, `int32_t`-কে ৪ বাইটের সীমানায় বরাদ্দ করতে হয়।

তবে একটি struct-এর অ্যালাইনমেন্ট হলো তার যেকোনো ফিল্ডের মধ্যে সর্বোচ্চ অ্যালাইনমেন্ট। তাই উদাহরণস্বরূপ, উপরে ডিফাইন করা `struct example`-এর অ্যালাইনমেন্ট হবে ৮ বাইট, কারণ এটিই `uint64_t`-এর অ্যালাইনমেন্ট।

কোনো struct ফিল্ডের অ্যালাইনমেন্ট struct-এর চেয়ে ছোট হলে, ওই ফিল্ডের পরে প্যাডিং বাইট যোগ করা হতে পারে। এতে পরের ফিল্ডগুলো এবং সামগ্রিকভাবে struct-টি অ্যালাইনমেন্টের শর্ত পূরণ করে। বাস্তবে এর মানে হলো, ওই প্যাডিং বাইটগুলো struct-এর সাইজে যোগ হলেও struct-এর মানে সেগুলোর কোনো ভূমিকা থাকে না:

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

লক্ষ করুন, উপরে ডিফাইন করা struct-টিতে 'one_byte' ফিল্ডের অ্যালাইনমেন্ট ১ এবং এটি যেকোনো অ্যাড্রেসে রাখা যায়। যেহেতু 'four_byte' ফিল্ডের অ্যালাইনমেন্ট ৪, তাই struct-এর ফিল্ডগুলোকেও ৪ বাইটের সীমানা মানতে হবে। এর মানে হলো, struct-এর যেকোনো দুই ফিল্ডের মাঝে বাইটের সংখ্যা ৪-এর গুণিতক হতে হবে। যেহেতু 'one_byte' কেবল ১ বাইট জুড়ে থাকে, তাই এই সীমানা মানতে তার পরে ৩টি প্যাডিং বাইট যোগ করা হয়।

সম্ভব হলে পাশাপাশি ফিল্ডগুলোকে একসাথে গ্রুপ করা হয়, যাতে প্রয়োজনীয় প্যাডিং বাইটের সংখ্যা কম হয়:

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

এই গ্রুপিংয়ের সময় প্রতিটি ফিল্ডের অ্যালাইনমেন্টও মানতে হবে:

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

এর মানে হলো, struct-এ ফিল্ডের ক্রম বদলালে কখনো কখনো তার সাইজে পার্থক্য হতে পারে:

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

লক্ষ করুন, একটি অ্যারের অ্যালাইনমেন্ট তার অন্তর্নিহিত টাইপের অ্যালাইনমেন্টের সমান:

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

অ্যারের এলিমেন্টগুলোকে এমনভাবে গ্রুপ করা যায়, যেন সেগুলো অ্যারের অংশই ছিল না:

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

অ্যাসেম্বলিতে struct অ্যাক্সেস করার সময় সম্ভাব্য সব প্যাডিং বাইট হিসাবের মধ্যে রাখা জরুরি।

## কলিং কনভেনশন

সাধারণভাবে, ফাংশনে মান পাঠানো এবং ফাংশন থেকে মান ফেরত আসা প্রত্যাশিত নিয়মেই ঘটে:

- ইন্টিজার মান, যার মধ্যে মেমরি অ্যাড্রেস ও enum পড়ে, জেনারেল-পারপাস রেজিস্টারে (GPR) পাঠানো হয়।
- ফ্লোটিং-পয়েন্ট মানগুলো `xmm` রেজিস্টারে পাঠানো হয়।

তবে struct হলো একটি বিশেষ ক্ষেত্র। মোটামুটি নিয়ম হিসেবে, একটি struct-এর সব ফিল্ড মেমরিতে পাশাপাশি জায়গা নেয় এবং সম্ভব হলে একটি একক রেজিস্টারে রাখা উচিত:

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

একটি struct-এ ইন্টিজার মানের ফিল্ড এবং ফ্লোটিং-পয়েন্ট মানের ফিল্ড দুটোই থাকলে, struct-এর প্রতিটি ধারাবাহিক ৮ বাইট আলাদাভাবে শ্রেণিবদ্ধ করতে হবে:

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

ইন্টিজার ও ফ্লোটিং-পয়েন্ট মান একই ৮ বাইটে থাকলে, টাইপটি ইন্টিজার ধরা হয় এবং পুরো ৮ বাইট (ফ্লোটিং-পয়েন্ট মানটিসহ) একটি GPR-এ রাখা হয়:

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
`cvtss2si` বা `cvtsd2si` দিয়ে ফ্লোটিং-পয়েন্ট থেকে ইন্টিজারে কনভার্সন করলে, এর ফলে অন্তর্নিহিত বাইটগুলোর বিন্যাস বদলে যায়।

আপনি বিট রিপ্রেজেন্টেশন না বদলে `xmm` রেজিস্টার থেকে একটি GPR-এ কাঁচা বাইট সরাতে [movd][mov] (৩২-বিট মানের জন্য) অথবা [movq][mov] (৬৪-বিট মানের জন্য) ব্যবহার করতে পারেন।

[mov]: https://www.felixcloutier.com/x86/movd:movq
~~~~

তবে ১৬ বাইটের বেশি সাইজের struct সাধারণত মেমরিতে রাখা হয়, প্রতিটি ৮ বাইটের টাইপ যা-ই হোক:

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

কোনো struct-কে ফাংশনের আর্গুমেন্ট হিসেবে পাঠালে, তা যত রেজিস্টার দরকার ততগুলো ব্যবহার করে। এটি মেমরিতে রাখা হলে বদলে স্ট্যাক ব্যবহার করা হয়।

ফাংশন থেকে ফেরত আসা struct-এর ক্ষেত্রেও একই ধরনের নিয়ম প্রযোজ্য। এগুলো সাধারণত প্রথমে `rax` ও `rdx`-এ (ইন্টিজার মান হলে) অথবা `xmm0` ও `xmm1`-এ (ফ্লোটিং-পয়েন্ট মান হলে) ফেরত আসে। তবে মেমরিতে রাখা হলে, কলারকে এর জন্য জায়গা সংরক্ষণ করতে হয় এবং এই মেমরি লোকেশনটির অ্যাড্রেস ফাংশনের একটি অন্তর্নিহিত প্রথম আর্গুমেন্ট হিসেবে পাঠাতে হয় (`rdi`-তে)। এরপর ফাংশন struct-টি এই জায়গায় সংরক্ষণ করে এবং `rax`-এ তার অ্যাড্রেস ফেরত দেয়।
