# Unison বেসিকস

## টার্ম এবং ফাংশন

টার্ম এবং ফাংশন হলো একটি Unison প্রোগ্রাম লেখার মৌলিক একক।

"টার্ম" হলো যা আমরা একটি স্ট্যাটিক মান বলি। এটি `name = expression` দিয়ে ডিফাইন করা হয়, আর প্রয়োজনে এর আগে `name : MyType` আকারের একটি টাইপ সিগনেচার থাকতে পারে। Unison টাইপ ইনফারেন্স সমর্থন করে, তাই সহজ ডেফিনিশনের ক্ষেত্রে টাইপ সিগনেচার বাদ দেওয়া হতে পারে।

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison ফাংশন দেখতে `myFunctionName argument1 argument2 = myImplementation` এর মতো হয়; এরা ফাংশনের নাম দিয়ে শুরু হয়, তারপর স্পেস দিয়ে আলাদা করা আর্গুমেন্ট আসে।

```
getMax a b = Nat.max a b
```

ফাংশনে চাইলে একটি টাইপ সিগনেচার থাকতে পারে। ডান দিকের শেষ টাইপটিই সবসময় ফাংশনের চূড়ান্ত রিটার্ন টাইপ, আর প্রতিটি আর্গুমেন্ট আলাদা করা হয় ফাংশন অ্যারো `->` দিয়ে।

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

একটি ফাংশন কল করতে, তার নামের পরে শুধু স্পেস দিয়ে আলাদা করা আর্গুমেন্ট লিখুন।

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

ফাংশন কল করার সময়, Unison সঙ্গে সঙ্গে ডান দিকে যা আসে তাকেই তার আর্গুমেন্ট হিসেবে ধরার চেষ্টা করে, যার ফলে সবসময় ফাংশন মূল্যায়নের কাঙ্ক্ষিত ক্রম তৈরি নাও হতে পারে।

ধরা যাক আমরা নিচের এক্সপ্রেশন থেকে `1` মানটি পেতে চাই

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

লেখা অনুযায়ী, `shouldBe1` এর মান হয় `0`, কারণ এখানে অনুমিত ফাংশন প্রয়োগের ক্রমটি হলো `getMax 1 10`, যা `10`, আর তারপর `10 - 10`, যা `0`।

কাঙ্ক্ষিত অপারেশন-ক্রমে এক্সপ্রেশনটি আবার সাজাতে আপনি বন্ধনী ব্যবহার করতে পারেন।

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## ওয়াচ এক্সপ্রেশন

দ্রুত কোড মূল্যায়ন করার একটি উপায় Unison দেয়, যাকে বলা হয় "ওয়াচ এক্সপ্রেশন"। একটি ওয়াচ এক্সপ্রেশন `>` চিহ্ন দিয়ে শুরু হয়, তারপর যে এক্সপ্রেশনটি মূল্যায়ন করতে হবে সেটি আসে। ওয়াচ এক্সপ্রেশন যেকোনো `.u` এক্সটেনশনের ফাইলে লেখা যায়। ফাইলটি সেভ করলে Unison Codebase Manager (UCM) কনসোলে এক্সপ্রেশনটির মান কী হয় তা দেখতে পাবেন। এই ডকুমেন্টগুলোতে যেখানে সম্ভব, আমরা একটি এক্সপ্রেশন ও ওয়াচ এক্সপ্রেশনে মূল্যায়নের পর তার প্রত্যাশিত আউটপুট দেখানোর চেষ্টা করব।

```
> helloThere
  ⧩
  "Hello, World!"
```

## মাল্টি-লাইন ফাংশন

Unison-এর মাল্টি-লাইন ফাংশন কোডের সীমা নির্ধারণ করতে ইনডেন্টেশন বা `let` ব্লক ব্যবহার করে, যাকে "লেক্সিকাল স্কোপ" বলা হয়।

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

একই ইনডেন্টেশন স্তরের সবকিছু একই স্কোপ ভাগ করে নেয়, তাই শেষ লাইনে আমরা `newBeginning` ভ্যারিয়েবলটি রেফারেন্স করতে পারি।

## নেমস্পেস এবং `use` স্টেটমেন্ট

নেমস্পেস হলো Unison-এর ফাংশনগুলোকে দলবদ্ধ ও সাজিয়ে রাখার উপায়। এগুলোকে "ডিরেক্টরি"-র সমতুল্য ভাবতে পারেন। এরা কাঠামো ও যৌক্তিক দলবদ্ধতা দেয়।

একটি `use` স্টেটমেন্ট দিয়ে আপনি একটি নেমস্পেসের ফাংশনগুলো স্কোপে আনতে পারেন।

ধরা যাক আপনি এমন একটি ফাংশন লিখছেন যা Unison `List` মান ব্যবহার করে। আপনি জানেন আপনার `List.map` আর `List.flatMap` এর মতো ফাংশন লাগবে, যেখানে `List` হলো নেমস্পেস আর `map` ও `flatMap` হলো ফাংশন। নিজেকে বারবার না লিখতে, আপনি আপনার ফাংশনে `List` নেমস্পেসের সবকিছু এভাবে লেক্সিকাল স্কোপে আনতে পারেন:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List` লাইনটি `map` ও `flatMap` এর রেফারেন্সগুলোর অস্পষ্টতা দূর করে। [`use` স্টেটমেন্ট সম্পর্কে আরও পড়তে পারেন এখানে][use-statements]।

## Unison-এর স্ট্যান্ডার্ড লাইব্রেরি

Unison-এর স্ট্যান্ডার্ড লাইব্রেরির নাম `base`। আপনি যদি কুইকস্টার্ট গাইড অনুসরণ করে লোকালি একটি কোডবেস তৈরি করে থাকেন, তাহলে স্ট্যান্ডার্ড লাইব্রেরিটি স্বয়ংক্রিয়ভাবে ডাউনলোড হয়ে যাওয়ার কথা। আপনি অনলাইনে [Unison Share][unison-share-base] এ স্ট্যান্ডার্ড লাইব্রেরির ডকুমেন্টেশন ব্রাউজ করতে পারেন।

## কমেন্ট এবং ডকুমেন্টেশন লিটারেল

Unison-এ কমেন্ট একটু অদ্ভুত বৈশিষ্ট্য। Unison কোড লেখার সময়, আপনার `.u` এক্সটেনশনের ফাইলে এমন টেক্সট তৈরি করতে পারেন যা ইন্টারপ্রেট করা হয় না, নিচের সিনট্যাক্স দিয়ে:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_তবে_, যেহেতু Unison কোড ফাইল সিস্টেমে টেক্সট-ভিত্তিক ফাইল হিসেবে নয়, বরং তার অ্যাবস্ট্রাক্ট সিনট্যাক্স ট্রি-এর হ্যাশ হিসেবে সেভ করা হয়, তাই ফাইলের ভেতরে একটি নির্দিষ্ট Unison ফাংশন বা টার্মের টেক্সট-ভিত্তিক "সাজসজ্জা" যে কমেন্টগুলো, সেগুলো শেয়ার করার জন্য সেভ করে আবার রেন্ডার করা আসলে সম্ভব নয়। আপনি যদি আপনার Unison টার্মে এমনভাবে তথ্য যোগ করতে চান যা সংরক্ষিত থাকবে যাতে অন্যরা পড়ে বুঝতে পারে, তাহলে আপনি একটি ডকুমেন্টেশন লিটারেল ব্যবহার করতে পারেন।

Unison প্রোগ্রামিং ভাষায় ডকুমেন্টেশন একটি ফার্স্ট-ক্লাস মান। এর মানে হলো একটি `Doc` এলিমেন্টকে একটি মানে অ্যাসাইন করা যায়, ফাংশনে মান হিসেবে পাস করা যায়, বা ফাংশনের মান হিসেবে রিটার্ন করা যায়। ডকুমেন্টেশন লিটারেল এলিমেন্ট খোলা ও বন্ধ করা হয় ডাবল কার্লি ব্রেস দিয়ে। কমেন্ট হিসেবে আমরা কীভাবে `Doc` এলিমেন্ট ব্যবহার করতে পারি, তার একটি উদাহরণ:

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
