# পরিচিতি

Rust-এ মেথড হলো এমন ফাংশন, যা একটি struct (বা একটি `enum` বা `trait` অবজেক্ট)-এর জন্য ডিফাইন করা হয়। এতে কল করার প্যাটার্ন বদলে যায়: `frobnicate(foo)`-এর বদলে মেথডকে `foo.frobnicate()` হিসেবে কল করা হয়।

মেথড ফাংশনের মতোই: এগুলো `fn` কিওয়ার্ড দিয়ে ডিক্লেয়ার করা হয়, এগুলোর একটি নাম থাকে এবং এগুলোতে প্যারামিটার ও রিটার্ন ভ্যালু থাকতে পারে।

ফাংশনের বিপরীতে, মেথডের প্রথম প্যারামিটারটি সর্বদা `self` (বা তার একটি ভ্যারিয়েন্ট) হয়, যা সেই struct-এর ইনস্ট্যান্সকে বোঝায় যার ওপর মেথডটি কল করা হচ্ছে (বিস্তারিত নিচে)।

চলুন হগওয়ার্টসের হাউসগুলোর জন্য একটি `enum` এবং একজন উইজার্ডের `age` ও `house` বর্ণনা করে এমন একটি `struct` তৈরি করি:

```rust
#[derive(Debug)]
enum House {
    Gryffindor,
    Hufflepuff,
    Ravenclaw,
    Slytherin,
}

struct Wizard {
    age: u32,
    house: House,
}
```

## মেথড ডিফাইন করা

`Wizard` struct-এর জন্য মেথড ডিফাইন করতে হলে আমরা `Wizard`-এর জন্য একটি `impl` (implementation-এর সংক্ষিপ্ত রূপ) ব্লক শুরু করি।

```rust
impl Wizard { }
```

এই `impl` ব্লকের ভেতরের সবকিছুই `Wizard` টাইপের সাথে অ্যাসোসিয়েটেড থাকবে। মনে রাখবেন, একটি struct-এ একাধিক `impl` ব্লক থাকতে পারে।

### `self` ব্যবহার করা

একটি মেথডের প্রথম প্যারামিটার হিসেবে `Self` টাইপের `self` নামের একটি প্যারামিটার থাকতে হবে। `Self` টাইপটি হলো সেই টাইপের অ্যালিয়াস, যার জন্য `impl` ব্লকটি লেখা হয়েছে। আমাদের উদাহরণে `Self` বোঝায় `Wizard`-কে।

সুবিধার জন্য Rust আমাদের প্রথম প্যারামিটারের জায়গায় শুধু `self` নামটি লিখে এটিকে সংক্ষেপ করার সুযোগ দেয়। মেথডে `self`-এর সাধারণ টাইপগুলো হলো:

- `self`: এটি `self: Self`-এর সংক্ষিপ্ত রূপ। শুধু `self` সম্বলিত সিগনেচারটি ইনস্ট্যান্সটি কনজিউম করে।
- `&self`: এটি `self: &Self`-এর সংক্ষিপ্ত রূপ। এটি ইনস্ট্যান্সটি অপরিবর্তনীয়ভাবে বরো করে।
- `&mut self`: এটি `self: &mut Self`-এর সংক্ষিপ্ত রূপ। এটি ইনস্ট্যান্সটি পরিবর্তনযোগ্যভাবে বরো করে।

আরও অ্যাডভান্সড কোডে আপনি `self: Pin<&self>`, `self: Rc<Self>` ইত্যাদির মতো সিগনেচারও দেখতে পারেন। তবে এটি এই টিউটোরিয়ালের আওতার বাইরে।

### `&self` দিয়ে একটি মেথড ডিফাইন করা

উইজার্ডের মৌলিক তথ্য দেখানোর জন্য যদি আমরা একটি `info` মেথড ইমপ্লিমেন্ট করতে চাই, তাহলে `Wizard`-এর একটি `impl` ব্লকের ভেতরে এই মেথডটি ডিফাইন করতে পারি:

```rust
impl Wizard {
    fn info(&self) {
        println!(
            "A wizard of age {} who studies in House {:?} at Hogwarts",
            self.age,
            self.house,
        );
    }
}
```

লক্ষ্য করুন, `info`-এর সিগনেচারে আমরা `&self` দিয়ে ইনস্ট্যান্সটি অপরিবর্তনীয়ভাবে বরো করি। এভাবে আমরা সেগুলো পরিবর্তন না করেই কোনো `Wizard` ইনস্ট্যান্সের `age` ও `house` ফিল্ড পড়তে পারি। বরো করার বদলে যদি কনজিউম করা `self` ব্যবহার করতাম, তাহলে মেথডটি কল হওয়ার পর ইনস্ট্যান্সটি আর ব্যবহারযোগ্য থাকত না।

`info` মেথডটি ইমপ্লিমেন্ট করা থাকলে আমরা একটি উইজার্ডের মৌলিক তথ্য প্রিন্ট করতে পারি:

```rust
let harry = Wizard { age: 11, house: House::Gryffindor };
harry.info();
// => A wizard of age 11 who studies in House Gryffindor at Hogwarts
```

### `&mut self` দিয়ে একটি মেথড ডিফাইন করা

স্ট্রাক্ট ইনস্ট্যান্সের ফিল্ডগুলো পরিবর্তন করে এমন একটি মেথড ইমপ্লিমেন্ট করতে চাইলে আমরা মেথডের সিগনেচারে `&mut self` দিয়ে ইনস্ট্যান্সটি পরিবর্তনযোগ্যভাবে বরো করি।

ধরা যাক, হগওয়ার্টসে আমরা একটি নতুন নিয়ম চালু করতে চাই, যাতে শিক্ষার্থীরা হাউস বদলাতে পারে। তাহলে আমরা `switch_house` নামের একটি মেথড এভাবে ইমপ্লিমেন্ট করতে পারি:

```rust
impl Wizard {
    fn switch_house(&mut self, new_house: House) {
        self.house = new_house;
    }
}
```

এখন হগওয়ার্টসে পড়া কোনো উইজার্ডের হাউস বদলাতে পারি:

```rust
// Note that the variable must be mutable
let mut cedric = Wizard {age: 14, house: House::Hufflepuff};
cedric.info();
// => A wizard of age 14 who studies in House Hufflepuff at Hogwarts
cedric.switch_house(House::Slytherin);
cedric.info()
// => A wizard of age 14 who studies in House Slytherin at Hogwarts
```

## একাধিক 'impl' ব্লক

Rust-এ প্রতিটি আইটেমে একাধিক `impl` ব্লক থাকতে পারে। তাই আমরা সব মেথড একই `impl` ব্লকে একসাথে রাখতে পারি, অথবা মেথডের বিভিন্ন গ্রুপের জন্য একাধিক `impl` ব্লক রাখতে পারি। দুটি পদ্ধতিই বৈধ সিনট্যাক্স, তবে সাধারণ প্রকল্প-সংগঠনে প্রতিটি আলাদা `impl`-লেভেল `where` বাউন্ডের জন্য একটি করে `impl` ব্লক ব্যবহার করা হয়।

## অ্যাসোসিয়েটেড ফাংশন

এমন ফাংশনও একটি `impl` ব্লকের ভেতরে ডিফাইন করা যায়, যেগুলোতে `self` প্যারামিটার থাকে না। `self` প্যারামিটার না থাকার কারণে এগুলো মেথড নয়। তবুও এগুলো যে টাইপে ইমপ্লিমেন্ট করা হয়েছে তার সাথে অ্যাসোসিয়েটেড থাকে এবং ওই টাইপের নাম ধরে কল করা হয়। সে কারণেই এগুলোকে অ্যাসোসিয়েটেড ফাংশন (বা টাইপ-অ্যাসোসিয়েটেড ফাংশন) বলা হয়।

আপনি ইতিমধ্যে কিছু অ্যাসোসিয়েটেড ফাংশন দেখেছেন, যেমন `String::from()`:

```rust
let some_string = String::from("This is an associated function but not a method");
```

কনস্ট্রাক্টরগুলো প্রায়ই অ্যাসোসিয়েটেড ফাংশন হিসেবে ইমপ্লিমেন্ট করা হয়। চলুন `Wizard` টাইপের সাথে অ্যাসোসিয়েটেড একটি `new` ফাংশন তৈরি করি:

```rust
impl Wizard {
    fn new(age: u32, house: House) -> Self {
        Self {
            age,
            house,
        }
    }
}
```

লক্ষ্য করুন, ফাংশন থেকে যে টাইপ রিটার্ন হবে তা বোঝাতে আমরা `Wizard`-এর বদলে `Self` ব্যবহার করতে পারি। এভাবে `Self` টাইপ অ্যালিয়াস ব্যবহার করা বাধ্যতামূলক নয়, তবে জটিল বা লম্বা নামের টাইপের ক্ষেত্রে এটি ইমপ্লিমেন্টেশন সহজ করে দিতে পারে। এখন আমরা নিচের কোডটি রান করতে পারি:

```rust
let myrtle = Wizard::new(14, House::Ravenclaw);

myrtle.info();
// => A wizard of age 14 who studies in House Ravenclaw at Hogwarts
```
