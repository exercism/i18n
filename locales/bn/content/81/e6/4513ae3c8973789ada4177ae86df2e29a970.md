# নির্দেশনার সংযোজন

## `from_quote`-এর সুবিধা ও অসুবিধা
এই অনুশীলনীতে `DateOfBirth` টাইপে একটি `from_quote` ফাংশন ডিফাইন করা হয়েছে। এর ফলে এমন কোড লেখা সম্ভব হয়:

```roc
birthdate : DateOfBirth
birthdate = "2019-01-20"
```

এই কোডটি কম্পাইল টাইমে পরোক্ষভাবে `DateOfBirth.from_quote("2019-01-20")` কল করে। এতে সম্ভবত প্রোগ্রামের গতি বাড়তে পারে, কারণ রানটাইমে পার্সিং সামলানোর দরকার পড়ে না, আর এটি নিশ্চিত করে যে `from_quote` যে তারিখগুলো প্রত্যাখ্যান করে সেগুলো রানটাইমের বদলে কম্পাইল টাইমেই ধরা পড়ে। তাছাড়া এটি কোডকে সুন্দর ও সহজপাঠ্য করে তোলে। উদাহরণস্বরূপ, এই অনুশীলনীর একটি টেস্ট দেখুন:

```roc
# multiple birthdates with one shared birthday
expect {
	shared_birthday(["1966-07-29", "1977-02-12", "2001-07-29", "1980-11-10"])
}
```

তবে এই কোড পড়ে কেউ ধরে নিতে পারেন যে `shared_birthday` ফাংশনটি একটি `List(Str)` নেয়, অথচ আসলে এটি `List(DateOfBirth)` নেয়। এতে বিভ্রান্তি ও ভুল হতে পারে। তাই আপনি হয়তো একটু লম্বা কিন্তু বেশি স্পষ্ট ফরম্যাটটি পছন্দ করবেন: `"2019-01-20".DateOfBirth`, যা কম্পাইল টাইমেই `from_quote` কল করে।

আপনার নিজের প্রোগ্রামে আপনি হয়তো একটি সুবিধাজনক কনস্ট্রাক্টর দিতে চাইবেন, যেমনটি এখানে:

```roc
DateOfBirth := { year : I64, month : U8, day : U8 }.{
    from_ymd : I64, U8, U8 -> Try(DateOfBirth, [InvalidMonth, InvalidDay])
    from_ymd = |year, month, day| ...
}
```

আপনি এই কনস্ট্রাক্টরটিও কম্পাইল টাইমে কল করতে পারেন, এভাবে:

```roc
Ok(birthdate) = DateOfBirth.from_ymd(2019, 1, 20)
```

নোট: এই ডেফিনিশনটি টপ লেভেলে রাখলে এটি কম্পাইল টাইমে চলে (কারণ ফাংশনটি পিওর এবং ইনপুটগুলো কম্পাইল টাইমেই জানা থাকে)। কোনো ফাংশনের ভেতরে আপনি একই কনস্ট্রাক্টর রানটাইমে ব্যবহার করতে পারেন।
