# পরিচিতি

Gleam-এ কোনো মানের উপর প্যাটার্ন ম্যাচিং করার সময় আমাদের নিশ্চিত করতে হয় যে প্যাটার্নগুলো টাইপের সম্ভাব্য প্রতিটি মানের সাথে মেলে, অন্যথায় কোডটি কম্পাইল হবে না।

এই ফাংশনটি গ্রহণ করা উচিত নয়, কারণ এটি সেই কেসটি সামলায়নি যেখানে অ্যারেটি খালি:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Gleam প্রোগ্রামে বেশিরভাগ সময় আমরা প্রতিটি সম্ভাব্য কেস সামলাতে চাই, কিন্তু কিছু প্রোগ্রামে, যেমন প্রোটোটাইপ আর দ্রুত লেখা স্ক্রিপ্টে, আমরা কেবল হ্যাপি পাথের দিকেই মনোযোগ দিতে চাই এবং অন্য কেসগুলোর জন্য কোড লিখতে চাই না। এখানেই Gleam-এর `let assert` কাজে আসে।

লেট অ্যাসারশন ব্যবহার করলে একটি প্যাটার্ন টাইপের সম্ভাব্য মানগুলোর মধ্যে কেবল কয়েকটির সাথে মিলতে পারে, আর প্যাটার্নটি কোনো মানের সাথে না মিললে প্রোগ্রামটি ক্র্যাশ করবে। `let assert` ব্যবহার করে আমরা উপরের ফাংশনটি এভাবে লিখতে পারি:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Gleam লাইব্রেরিতে কখনোই লেট অ্যাসারশন ব্যবহার করা উচিত নয়, কারণ তা প্রোগ্রামটি ক্র্যাশ করাতে পারে; বরং সেখানে `Result` টাইপ ব্যবহার করা উচিত এবং কীভাবে এরর সামলানো হবে তা অ্যাপ্লিকেশন ডেভেলপারের ওপর ছেড়ে দেওয়া উচিত।
