# ভূমিকা

## এররের সাথে প্রসঙ্গ যোগ করা

Go-তে [এরর কনসেপ্টে][concept-errors] আমরা এররের বেসিক হ্যান্ডলিং নিয়ে আলোচনা করেছি।
সেখানে আপনি যেমন জেনেছেন, ডিফল্টভাবে এরর তার সাথে স্ট্যাক ট্রেস বহন করে না।
তাই সমস্যাটি শনাক্ত করার মতো যথেষ্ট তথ্য এররের নিজের মধ্যে আছে কি না, তা নিশ্চিত করা খুবই জরুরি।

আমাদের জানা টুল দিয়েই যদি কোনো বিদ্যমান এররে তথ্য যোগ করতে চাইতাম, তাহলে মূল এরর আর অতিরিক্ত তথ্যের সম্মিলিত টেক্সট দিয়ে নতুন একটি এরর তৈরি করতে আমরা এমন কিছু লিখতে পারতাম:

```go
err := errors.New(fmt.Sprintf("parsing age for user %d: %v", userID, originalError))
```

ভাগ্যক্রমে, স্ট্যান্ডার্ড লাইব্রেরির `fmt` প্যাকেজে এর একটি সংক্ষিপ্ত রূপ আছে, `Errorf` ফাংশনের আকারে।
এটি দিয়ে আপনি সহজেই, উদাহরণস্বরূপ, যে প্রসঙ্গে এররটি ঘটেছে সেই সম্পর্কে তথ্য যোগ করতে পারেন।

```go
originalError := errors.New("unexpected negative number")
userID := 123
err := fmt.Errorf("parsing age for user %d: %v", userID, originalError)
err.Error()
// => "parsing age for user 123: unexpected negative number"
```

অনেক সময় এররে এভাবে তথ্য যোগ করাই যথেষ্ট, তবে কিছু ক্ষেত্রে আপনি চান যে আপনার এররের ব্যবহারকারী মূল অন্তর্নিহিত এররটি যাচাই করতে বা উদ্ধার করতে পারুক।
এমনভাবে প্রসঙ্গ যোগ করা, যা এটির সুযোগ দেয়, Go-তে তাকে "এরর র‍্যাপিং" বলা হয়।

## এরর র‍্যাপিং এবং সেন্টিনেল এরর চেক করা

আমরা উপরে যে কোড দেখেছি, তার খুব ছোট একটি পরিবর্তনেই এরর র‍্যাপিং করা যায়।
একটি এরর র‍্যাপ করতে `%v`-এর জায়গায় `%w` ফরম্যাটিং ভার্বটি ব্যবহার করতে হবে।
পর্দার আড়ালে এটি নিশ্চিত করে যে ফলাফল হিসেবে পাওয়া এররটি একটি `Unwrap` মেথড ইমপ্লিমেন্ট করে, যা মূল এররটি রিটার্ন করে।
এর 덕ে... এই কারণে, একটি নির্দিষ্ট সেন্টিনেল এরর "এরর চেইন"-এর কোথাও আছে কি না, তা যাচাই করতে `errors.Is` ব্যবহার করা যায়।
এটি গোপনে বারবার `Unwrap` কল করতে থাকে, যতক্ষণ না প্রশ্নে থাকা এররটি খুঁজে পাওয়া যায় বা চেইনটি শেষ হয়ে যায়।

```go
originalError := errors.New("unexpected negative number")
err := fmt.Errorf("parsing age: %w", originalError)
errors.Is(err, originalError)
// => true
```

ডিফল্টভাবে `%v` ব্যবহার করা এবং শুধু তখনই `%w` ব্যবহার করা ভালো অভ্যাস, যখন আপনি স্পষ্টভাবে চান যে আপনার এররের ব্যবহারকারী একটি অন্তর্নিহিত এরর অ্যাক্সেস করতে পারুক ([Google Go Styleguide][google-go-styleguide])।

যদি এমন পরিস্থিতিতে পড়েন যেখানে সেন্টিনেল এরর চেক করতে চান কিন্তু স্পষ্টভাবে আনর‍্যাপ করতে চান না, তাহলে `errors.Is`-এর বদলে `==` ব্যবহার করতে পারেন।

```go
var originalError = errors.New("unexpected negative number")
func someFunc() error {
  return originalError
}

err := someFunc()
err == originalError 
// => true
```

ডিফল্টভাবে `errors.Is` নিয়ে কাজ করা ঠিক আছে, তবে আপনার সবসময় সচেতন থাকা উচিত যে এর মানে পুরো এরর চেইনটাই খোঁজা হবে।

## (কাস্টম) এরর টাইপ চেক করা

`errors.Is`-এর একটি সমতুল্য ফাংশন আছে, যা দিয়ে এরর চেইন থেকে নির্দিষ্ট টাইপের একটি এরর চেক করা ও উদ্ধার করা যায়।
সেই ফাংশনটি হলো `errors.As`, আর `errors.Is`-এর মতোই এটি পুরো চেইন জুড়ে প্রদত্ত এরর টাইপটি খুঁজবে।
`errors.As` তখনই টাইপের সাথে মেলে এমন এররটি বের করে দেয়, যাতে আপনি এটি নিয়ে আরও কাজ করতে পারেন, যেমন নির্দিষ্ট ফিল্ড উদ্ধার করা।

```go
type MyCustomError struct {
  Message string
  Details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.Message, e.Details)
}

func someFunc() error {
  originalError := &MyCustomError{
    Message: "some message",
    Details: "some details",
  }

  return fmt.Errorf("doing something: %w", originalError)
}

err := someFunc()
var customError *MyCustomError
errors.As(err, &customError)
// => true

// customError now contains the error that was found in the error chain.
customError.Details
// => "some details"
```

~~~~exercism/caution
উপরের পয়েন্টারগুলো সম্পর্কিত সিনট্যাক্সে সাবধান থাকুন।
কোডটি তখনই ঠিকভাবে কাজ করবে ও কম্পাইল হবে, যদি `customError`-এর টাইপটি ঠিক সেই টাইপ হয় যা এরর ইন্টারফেসটি ইমপ্লিমেন্ট করে।
আমাদের ক্ষেত্রে সেটি `*MyCustomError` (অর্থাৎ `MyCustomError`-এর একটি [পয়েন্টার][concept-pointers]), `MyCustomError` নিজে নয়।

তার উপর, দ্বিতীয় আর্গুমেন্টটি হতে হবে এরর ভ্যারিয়েবলের একটি পয়েন্টার।
যেহেতু আমাদের এররটি ইতিমধ্যেই একটি পয়েন্টার, তাই `errors.As`-কে আমরা যা পাঠাচ্ছি তা একটি পয়েন্টার, যা আরেকটি পয়েন্টারের দিকে (MyCustomError-এর দিকে) ইশারা করে।
ঠিক এভাবে সেটআপ করা থাকলেই Go খুঁজে পাওয়া এররটি দিয়ে ভ্যারিয়েবলটি পূরণ করতে পারে।
~~~~

আগের মতোই, `Errorf` কল করার সময় `%v` ব্যবহার করা হলে `errors.As` এরর টাইপটি খুঁজে পেত না।

কোনো কারণে যদি আনর‍্যাপ করতে না চান, তাহলে তার বদলে টাইপ অ্যাসারশন ব্যবহার করা যায় (উপরের `==`-এর সমতুল্য)।

```go
// MyCustomError defined as above.

func someFunc() error {
  return &MyCustomError{
    Message: "some message",
    Details: "some details",
  }
}

err := someFunc()
customError, ok := err.(*CustomError)
// "ok" is now true
customError.Details
// => "some details"
```

এররটি র‍্যাপ করা থাকলে টাইপ অ্যাসারশন এরর টাইপটি শনাক্ত করতে পারবে না।

## কাস্টম টাইপের এরর আনর‍্যাপ করার সুযোগ দেওয়া

কখনও কখনও শুধু কিছু অতিরিক্ত টেক্সট দিয়ে একটি এরর র‍্যাপ করা যথেষ্ট হয় না।
এর বদলে আপনি একটি কাস্টম এরর টাইপ তৈরি করতে পারেন, যেটি মূল এররটি এবং আপনার যোগ করতে চাওয়া অতিরিক্ত স্ট্রাকচার্ড ডেটা ধরে রাখে।
আপনার এরর টাইপের জন্য আনর‍্যাপিং চালু করতে চাইলে আপনাকে শুধু হাতে একটি `Unwrap() error` মেথড যোগ করতে হবে, যাতে `Unwrap` ইন্টারফেসটি সন্তুষ্ট হয়।

```go
type SpecialError struct {
  originalError error
  metadata string
}

func (e *SpecialError) Error() string {
  // The usual serialization code goes here.
}

func (e *SpecialError) Unwrap() error {
  return e.originalError
}
```
