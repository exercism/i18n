# পরিচিতি

অনেক অবজেক্ট-ওরিয়েন্টেড ভাষায় একটি প্যারেন্ট ক্লাসকে [সাবক্লাস][wiki-subclass] করে, প্যারেন্ট থেকে মেথড উত্তরাধিকার সূত্রে পেয়ে এবং নতুন মেথড যোগ করে বিহেভিয়ার বাড়ানো কমন একটি কাজ।
এভাবেই আমরা একটি অবজেক্ট হায়ারার্কি পাই।

Julia-এর _কোনো ক্লাস নেই_, তাই এর থেকে বলা যায় এর _কোনো সাবক্লাসও নেই_।
তাহলে আমরা কীভাবে বিদ্যমান বিহেভিয়ার উত্তরাধিকার সূত্রে পাই আর বাড়াই?

আগের কনসেপ্টগুলোতে আমরা দেখেছি কীভাবে একটি টাইপ হায়ারার্কি তৈরি করতে হয়, আর শিখেছি কীভাবে Julia আর্গুমেন্টের টাইপের ভিত্তিতে মেথড বাছাই করতে [মাল্টিপল ডিসপ্যাচ][concept-multiple-dispatch] ব্যবহার করে।

Julia-তে বেশ কিছু অনানুষ্ঠানিক [ইন্টারফেস][ref-interfaces]ও আছে, যেগুলো আপনার কাস্টম টাইপগুলোকে স্ট্যান্ডার্ড টাইপের জন্য আগে থেকেই নির্ধারিত বিহেভিয়ারের সাথে যুক্ত হওয়ার সুযোগ দেয়।

ইটারেটর ইন্টারফেস দিয়ে এটি সবচেয়ে সহজে বোঝানো যায়।

## [ইটারেটর][ref-iterators]

সিলেবাসে আগে আমরা দেখেছি, Julia একটি কালেকশনের প্রতিটি এলিমেন্টের উপর কয়েকটি ভিন্ন উপায়ে কাজ করতে পারে।

- [লুপ][concept-loops], যেমন `for item in items...`
- [ব্রডকাস্টিং][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [হায়ার অর্ডার ফাংশন][concept-hof]: `map(√, [1, 4, 9])`
- [কম্প্রিহেনশন][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [জেনারেটর][concept-comprehensions]: `(x^2 for x in 1:1e6)`, যা লেজিলি ইভ্যালুয়েট হয়।

স্পষ্টতই, Julia স্ট্যান্ডার্ড কালেকশনগুলোকে একটার পর একটা আইটেম ধরে ধরে ঘুরে দেখতে জানে: উপরের উদাহরণে ভেক্টর আর রেঞ্জ, সাথে Set, Dict ইত্যাদি।

কীভাবে আমরা নিজেদের কাস্টম কালেকশনে এই ক্ষমতা যোগ করব, বিশেষ করে যখন সেগুলো জেনারেটরের মতো লেজিলি ইটারেট করা যায়?

### ন্যূনতম যা যা দরকার

ইটারেশনের জন্য একটি সিকোয়েন্স তৈরি করতে আমাদের (অন্তত) দুটি জিনিস দরকার:

1. _প্রথম_ আইটেম পাওয়ার একটি উপায়।
2. বর্তমান স্টেট থেকে _পরের_ আইটেম পাওয়ার একটি উপায়।

Julia নিচের ধাপগুলোতে `Base.iterate()` ফাংশনের মেথড দিয়ে এই কাজগুলো করে:

1. প্রথমে স্বয়ংক্রিয়ভাবে `Base.iterate(iter)` কল হয়।
    - ইটারেট করার মতো কিছু না থাকলে `nothing` রিটার্ন করে।
    - নাহলে প্রথম রিটার্ন করা আইটেম আর প্রথম স্টেটের `Tuple` রিটার্ন করে: `(firstitem, firststate)`।
2. আগের ইটারেশনে একটি আইটেম রিটার্ন হলে স্বয়ংক্রিয়ভাবে `Base.iterate(iter, state)` কল হয়, যেখানে `firststate`-কে তার `state` আর্গুমেন্ট হিসেবে নেয়।
    - ইটারেশন শেষ হলে `nothing` রিটার্ন করে।
    - নাহলে পরের আইটেম আর পরের স্টেটের `Tuple` রিটার্ন করে: `(nextitem, nextstate)`।
3. শেষ হওয়া পর্যন্ত ধাপ ২ পুনরাবৃত্তি করে।

এই ধাপগুলো সবই "ভেতরে ভেতরে" ঘটে, অর্থাৎ মেথড কল আর স্টেট ইটারেশন প্রোটোকল নিজেই ভেতরে সামলায় (স্টেট থাকে অস্পষ্ট), আর শুধু আইটেমটিই লুপের মতো হাই-লেভেল গঠনের কাছে প্রকাশ পায়।
অন্য কথায়, আমরা কেবল `item`-টাই দেখি, বাকি সব একটা ব্ল্যাক বক্সে ঢাকা থাকে।

এখানে মূল ভূমিকায় আছে [মাল্টিপল ডিসপ্যাচ][concept-multiple-dispatch]।
`iter`-এর টাইপ ঠিক করে কোন মেথডগুলো কল হবে, আর আর্গুমেন্টের সংখ্যা ঠিক করে প্রথম আইটেম নাকি পরের আইটেম রিটার্ন হবে।

স্ট্যান্ডার্ড টাইপের জন্য মেথড আগেই নির্ধারিত আছে: `Vector`, `Range`, `Set` ইত্যাদি ([বর্তমানে][ref-iterations-collections] মোট ১৪টি টাইপ)।

একটি কাস্টম `MyType` যাতে একই বিহেভিয়ার পায়, সেজন্য প্রথমে আমাদের নির্ধারণ করতে হবে:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

এসব কথা শুনতে বিমূর্ত আর বিভ্রান্তিকর লাগতে পারে, কিন্তু আসলে বেশ সহজ হতে পারে।
বোঝার সুবিধার্থে ভাবুন, আমরা এমন একটি টাইপ চাই যা একটি নির্দিষ্ট পূর্ণসংখ্যা `n`-এর ঘাত দেয়, সর্বোচ্চ একটি নির্দিষ্ট সংখ্যা পর্যন্ত।

প্রথমে একটি কাস্টম টাইপ নির্ধারণ করুন:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

এখন আমরা এই টাইপের জন্য `iterate` মেথডগুলো নির্ধারণ করতে পারি, কিন্তু প্রথম আইটেম আর প্রথম স্টেট কী?

প্রথম আইটেম পেতে কিছু ইটারেটরের জটিল প্রস্তুতি লাগে, কিন্তু এই ছোট উদাহরণে খেয়াল করার মতো ব্যাপার হলো প্রথমে যে আইটেমটি রিটার্ন হয় সেটি আসলে বেস সংখ্যাটিই, তাই আমাদের কেবল দেখতে হবে `count`-এর মান এক বা তার বেশি কি না।

এখন আমরা প্রথম স্টেট নিয়ে ভাবতে পারি, যা পরের ইটারেশনে ব্যবহৃত তথ্য বহন করে।
এটি করতে আপনার কোন তথ্য মনে রাখা দরকার, তা ঠিক করা আপনারই হাতে, আর সেটি যেকোনো টাইপ হতে পারে।

এই ক্ষেত্রে, আমরা `n`-কে যে ঘাতে ওঠাতে হবে সেই "ইনডেক্স" শুধু মনে রাখতে পারি, অথবা `n`-এর সবচেয়ে সাম্প্রতিক ঘাত (অর্থাৎ রিটার্ন করা আইটেম) আর সিকোয়েন্সে পরের "ইনডেক্স" ব্যবহার করে আরও দক্ষ একটি উপায় বের করতে পারি।
এই দুটি সংখ্যা একটি `Tuple`-এ মুড়ে `state` হিসেবে রিটার্ন করা যায়।

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

এই উদাহরণে, প্রথম আইটেম (`p.n`) লুপে রিটার্ন হয় আর প্রথম স্টেট `(p.n, 2)` `iterate(P::Powers, state)` মেথডে পাঠানো হয়।
সেখানে আমরা স্টেট প্রসেস করে পরের আইটেম তৈরি করতে পারি, বর্তমান আইটেমকে বেস সংখ্যা দিয়ে গুণ করে, ফলে তার ঘাত `1` বেড়ে যায়।

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

ইনডেক্সের মান যদি এখনও `count`-এর মধ্যে থাকে, তাহলে `next` আইটেম আর বাড়ানো `(next, index + 1)` স্টেট নিয়ে `Tuple` রিটার্ন হয়।
যখন `index`-এর মান `count` ছাড়িয়ে যায়, তখন বদলে `nothing` রিটার্ন হয়, যা বোঝায় ইটারেশন শেষ হয়েছে।

আপনি হয়তো খেয়াল করেছেন, `iterate(p::Powers)` আর `iterate(p::Powers, state)` মেথড দুটির ফাংশন বডি বেশ একই রকম।
আসলে, একটু বুদ্ধি খাটালে এই মিলের সুবাদে শুধু দুই-আর্গুমেন্টের সংস্করণটি ব্যবহার করে, স্টেটের জন্য একটি ডিফল্ট আর্গুমেন্ট দিয়ে, একটি সরল বাস্তবায়ন করা যায়: `Base.iterate(p::Powers, state=(1, 1))`
এতে আলাদা করে এক-আর্গুমেন্টের `iterate(p::Powers)` আর দরকার হতো না।
সম্ভব হলে বাস্তবে এটাই সাধারণত করা হয়।

```julia-repl
julia> for p in Powers(3, 4)

3
9

```

### অতিরিক্ত মেথড

এই ভালো শুরু সত্ত্বেও, এখনও সবকিছু কাজ করে না।

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

ঠিক যেমনটা আশা করা যায়, `length(Powers(3, 4))`-ও একই এরর মেসেজ দেয়।

এটি সহজেই ঠিক করা যায়, কারণ দৈর্ঘ্যটি টাইপ কনস্ট্রাক্টরের অংশ: এই ক্ষেত্রে ৪।
আমাদের কেবল এই টাইপের জন্য `Base.length()` নির্ধারণ করতে হবে, তারপর আমরা সিকোয়েন্সে কম্প্রিহেনশন আর `collect()` ব্যবহার করতে পারব।

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

দক্ষতার জন্য সবচেয়ে ভালো হলো `Base.eltype()`-ও নির্ধারণ করা: ফলাফলের এলিমেন্ট টাইপ।
এতে `collect()`-এর মতো ফাংশন আউটপুট `Vector{Int}`-এর জন্য আগেই জায়গা বরাদ্দ করতে পারে, বারবার `Vector{Any}`-এ `push!()` করার বদলে।

সিনট্যাক্সটা খেয়াল করুন, যা আপনি আগে দেখেননি হয়তো: এই মেথডটি _টাইপের_ উপর নির্ধারিত হয়, টাইপের _ইনস্ট্যান্সের_ উপর নয়।

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

ইটারেটরদের সসীম দৈর্ঘ্য থাকা _বাধ্যতামূলক_ নয়।
"অসীম" সিকোয়েন্সের ব্যবহার আরও সীমিত, কিন্তু এগুলোর উপর লুপ চালানো কাজে লাগতে পারে, যতক্ষণ লুপ থেকে `break` করার কোনো উপায় থাকে।
উদাহরণস্বরূপ, আমরা `Powers`-এর একটি রূপ নির্ধারণ করতে পারি যা একটি নির্দিষ্ট সীমার চেয়ে ছোট মান তৈরি করে (হয়তো `typemax(Int)`, ইন্টিজার ওভারফ্লো এড়াতে)।

## অন্যান্য ইন্টারফেস

### [ইনডেক্সিং][ref-indexing]

ইটারেটর ইন্টারফেস আমাদের যেকোনো কাস্টম টাইপ নিয়ে সেটিকে কেবল কয়েকটি সরল মেথড নির্ধারণ করে একটি সিকোয়েন্সের মতো আচরণ করাতে দেয়।

ধরুন, আমরা সিকোয়েন্সে ইনডেক্স করতেও চাই:

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

আমরা এই বিহেভিয়ার যোগ করতে পারি, আর কীভাবে তা [ম্যানুয়ালে][ref-indexing] ব্যাখ্যা করা আছে।

ন্যূনতমভাবে, আমাদের `getindex()` নির্ধারণ করতে হবে।

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

আমাদের আরও নির্ধারণ করতে হবে:

- `P[begin]` আর `P[end]` সমর্থন করতে `firstindex()` আর `lastindex()`।
- ভেক্টর আর রেঞ্জ দিয়ে ইনডেক্সিং সমর্থন করতে `getindex()`-এর বিভিন্ন রূপ।
- তত্ত্বগতভাবে `setindex!()`, যদিও এই উদাহরণে এর অর্থ কী হবে তা ভেবে পাওয়া কঠিন।

তবে এই পর্যায়ে এসে আমরা কেবল আমাদের ইটারেটরকে আরেকটু ভেক্টরের মতো দেখাতে অনেক খাটনি করছি।

### [AbstractArray][ref-abstractarray]

হয়তো এমন বিকল্প ইন্টারফেসের কথা ভাবা উচিত যা আরও ভালো একটি সূচনা বিন্দু দেয়।

এই ক্ষেত্রে, আমরা `Powers`-কে [`AbstractArray`][ref-abstractarray]-এর একটি সাবটাইপ বানানোর কথা ভাবতে পারি, যা আমাদের অনেক অ্যারের মতো বিহেভিয়ার বিনা পরিশ্রমে দেয়।

`Powers` সিকোয়েন্সের জন্য সংশ্লিষ্ট অ্যারেটি ইন্টিজারের, এক মাত্রাবিশিষ্ট।
আপনি মাঝে মাঝে এটি `AbstractArray{Int, 1}` লেখা দেখবেন, তবে ১-ডি-র জন্য `AbstractVector{Int}` আর ২-ডি-র জন্য `AbstractMatrix{Int}` অ্যালিয়াসগুলো নতুন Julia কোডে বেশি কমন।

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

এখন `length()`-এর বদলে আমাদের প্রতিটি মাত্রা বরাবর দৈর্ঘ্যের একটি টাপল নিয়ে `size()` নির্ধারণ করতে হবে: এই ক্ষেত্রে কেবল একটিই মাত্রা।

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

এন্ট্রিগুলো আমরা কীভাবে ইনডেক্স করতে চাই?
[মাল্টি ডাইমেনশনাল অ্যারে কনসেপ্টে][concept-multi-dimensional-arrays] আমরা দুটি প্রধান পদ্ধতি চালু করেছিলাম:

- প্রতি মাত্রায় একটি ইনডেক্স, অর্থাৎ একটি ম্যাট্রিক্স `M`-এর জন্য `M[row, col]`।
- একটি একক ইনডেক্স, যা মেমোরিতে এন্ট্রিগুলোর বিন্যাসের সাথে মেলে

এদের যথাক্রমে `Cartesian` আর `Linear` বলা হয়।

উদাহরণে আমাদের কেবল একটিই মাত্রা আছে, তাই লিনিয়ার ইনডেক্সিং উপযুক্ত।

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

খেয়াল করুন, এই ক্ষেত্রে আমরা `iterate()` নির্ধারণ করিনি।
Julia আমাদের `getindex()`-এর সংজ্ঞার ভিত্তিতে স্বয়ংক্রিয়ভাবে একটি ডিফল্ট বাস্তবায়ন জোগায়।

নিজেদের `iterate()` সংস্করণ নির্ধারণ করাও এখনও সম্ভব, আর কিছু ক্ষেত্রে সেটি আরও দক্ষ হতে পারে।

উচ্চতর মাত্রার ইটারেশন চাইলে `AbstractArray` ইন্টারফেস ব্যবহার করা বিশেষভাবে মূল্যবান।
ছোট্ট উদাহরণটিকে তার সীমার বাইরে টেনে নেওয়ার ঝুঁকি নিয়ে বলা যায়, এর অর্থ হতে পারে `1:n`-এর সংখ্যাগুলোর প্রথম `m`টি ঘাত, যা ধাপে ধাপে একটি `(m, n)` আকারের অ্যারে তৈরি করবে।

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [রাউন্ডিং][ref-rounding]

আগের কনসেপ্টগুলোতে সংখ্যাসূচক টাইপের জন্য বিভিন্ন ধরনের রাউন্ডিংয়ের কথা বলা হয়েছে।

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

[`round()`][ref-round] ফাংশনটি এর চেয়ে বেশি নমনীয়, যা আপনাকে [`RoundingMode`][ref-roundingmode] (বর্তমানে সমর্থিত ৭টির মধ্যে), আউটপুটে দশমিক স্থান, আর সংখ্যার বেস নির্দিষ্ট করার সুযোগ দেয়।

আমরা চাইতে পারি একই ফাংশনগুলো আমাদের কাস্টম টাইপগুলো সামলাক।
সাধারণত এর অর্থ কোঅর্ডিনেটের মতো কম্পোজিট টাইপ।

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

অবাকের কিছু নেই, একটি `Rounding` ইন্টারফেস আছে, যা ন্যূনতমভাবে আমাদের টাইপের জন্য `round()` নির্ধারণ করতে বলে।

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

সংজ্ঞায় আমরা যেহেতু `RoundingMode` রেখেছি, `floor()` আর `ceil()` স্বয়ংক্রিয়ভাবে কাজ করে।

অবশ্যই, আমরা আরও জটিল ধরনের রাউন্ডিং নির্ধারণ করতে স্বাধীন।

- আমরা `Point3D`-কে মূলবিন্দু থেকে একই দিকে পূর্ণসংখ্যা দূরত্বে রাউন্ড করতে চাইতে পারি।
- কোণের ক্ষেত্রে, আমরা আবহাওয়ার পূর্বাভাসদাতারা ব্যবহার করা ১৬টি দিকে রাউন্ড করতে চাইতে পারি (_"wind SSW at 15 knots"_), অর্থাৎ π/8 রেডিয়ানের গুণিতক।
- আমরা `digits`, `sigdigits` বা `base` নির্দিষ্ট করার ক্ষমতা যোগ করতে চাইতে পারি।
- সময়কালের জন্য [বিশেষ অপশন][ref-round-periods] আছে

## সারসংক্ষেপ

ইন্টারফেস ব্যাখ্যা করা বেশ বিভ্রান্তিকর, কারণ Julia-র পদ্ধতি অন্য বেশিরভাগ ভাষার চেয়ে অনেক আলাদা।
বিশেষ করে, বাস্তবায়নে ইন্টারফেসের নাম হয়তো কখনোই উল্লেখ করা হয় না: [সাবক্লাসিং][wiki-subclass] বা [মিক্সিন][wiki-mixins]-এর থেকে একেবারেই আলাদা।

তবে বাস্তবে এগুলো আশ্চর্যজনকভাবে সহজ:

1. একটি উপযুক্ত টাইপ নির্ধারণ করুন, সাবটাইপিং কাজে লাগবে কি না তা ঠিক করে।
2. কোন মেথডগুলো দরকার তা বের করুন ([ডকুমেন্টেশন][ref-interfaces] থেকে)।
3. আপনার কাস্টম টাইপের জন্য সেই মেথডগুলো বাস্তবায়ন করুন; সাধারণত মাত্র কয়েকটি মেথড, আর সেগুলো বেশ ছোট আর সরল।
4. বাকিটা স্বয়ংক্রিয়ভাবে [মাল্টিপল ডিসপ্যাচ][concept-multiple-dispatch]-কে সামলাতে দিন।
