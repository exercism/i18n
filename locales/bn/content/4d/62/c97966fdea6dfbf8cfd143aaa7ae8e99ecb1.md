# পরিচিতি

স্টোরেজ ক্লাস স্পেসিফায়ার নির্ধারণ করে ভ্যারিয়েবলগুলো মেমরিতে কীভাবে সংরক্ষিত হয়। এগুলো একটি মানের স্টোরেজ ডিউরেশনের (যাকে লাইফটাইমও বলা হয়) সাথে ঘনিষ্ঠভাবে সম্পর্কিত।

## auto: ফাংশন বা ব্লক স্কোপের ভ্যারিয়েবলের ডিফল্ট স্টোরেজ ক্লাস

যেহেতু একটি ব্লক বা ফাংশনের ভেতরে ডিফাইন করা ভ্যারিয়েবল ডিফল্টভাবেই `auto`, তাই এই শব্দটি স্পষ্টভাবে ব্যবহার করা সাধারণ নয়। `auto` প্রায়ই এড়িয়ে যাওয়ার আরেকটি কারণ হলো C++-এ এর অর্থ ভিন্ন। C আর C++ একসাথে ব্যবহার করা কোডবেসে `auto` স্টোরেজ স্পেসিফায়ার এড়িয়ে গেলে বিভ্রান্তি কম হতে পারে। একটি `auto` ভ্যারিয়েবলের লাইফটাইম শুরু হয় তার ব্লকে প্রবেশ করার সময় এবং শেষ হয় ব্লক থেকে বেরিয়ে যাওয়ার সময়। একটি `auto` ভ্যারিয়েবলের জন্য ব্লকে প্রবেশ করার সময় মেমরি বরাদ্দ হয়, _তবে কোনো ডিফল্ট মান ছাড়াই_। ব্যতিক্রম হলো ভ্যারিয়েবল লেংথ অ্যারে (VLA)। একটি VLA-এর মেমরি বরাদ্দ ঘটে তার ব্লকে যেখানে এটি ডিক্লেয়ার বা ডিফাইন করা হয়েছে সেখানে, আর শেষ হয় ব্লক থেকে বেরিয়ে যাওয়ার সময়। একটি `auto` ভ্যারিয়েবল যেকোনো বৈধ এক্সপ্রেশন দিয়ে ইনিশিয়ালাইজ করা যায়।

## static: স্ট্যাটিক লিংকেজ টাইপের সাথে গুলিয়ে ফেলা উচিত নয় এমন স্টোরেজ স্পেসিফায়ার

একটি ব্লক বা ফাংশনের বাইরে ডিফাইন করা ভ্যারিয়েবলের স্কোপ হয় ফাইল স্কোপ এবং তার স্টোরেজ ডিউরেশন সবসময় স্ট্যাটিক। ফাইল স্কোপ মানে ফাইলের যেকোনো জায়গা থেকে এটি অ্যাক্সেস করা যায়। স্ট্যাটিক স্টোরেজ মানে প্রোগ্রামটি চালু হওয়ার শুরু থেকে শেষ পর্যন্ত এই ভ্যারিয়েবলটির অস্তিত্ব থাকে। স্পষ্টভাবে ইনিশিয়ালাইজ না করলে, একটি `static` ভ্যারিয়েবল তার ডিফল্ট শূন্য মান দিয়ে ইনিশিয়ালাইজ হয়। কোনো ফাইল স্কোপ ভ্যারিয়েবলকে `static` দিয়ে চিহ্নিত করলে, সেই `static` তার লিংকেজ বোঝায়। `static` চিহ্নিত একটি ফাইল স্কোপ ভ্যারিয়েবলের লিংকেজ ইন্টারনাল, অর্থাৎ ফাইলের ভেতরেই কেবল এটি অ্যাক্সেস করা যায়। কোনো ভ্যারিয়েবল যদি একটি ফাংশনের ভেতরে বা ফাংশনের ভেতরের কোনো ব্লকে ডিফাইন করা হয় এবং `static` চিহ্নিত থাকে, তবে তার স্টোরেজ ডিউরেশনও `static` হয়। `static` ভ্যারিয়েবলের মান ফাংশন বা ব্লকে বারবার কল করার মধ্যেও টিকে থাকে।

নিচের উদাহরণে দুটি `static` ভ্যারিয়েবল কাজ করতে দেখা যায়। প্রথম `count` ভ্যারিয়েবলটি `print_stuff` ফাংশনের ভেতরে ডিফাইন করা এবং ফাংশনে বারবার কলের মধ্যেও এর মান ধরে রাখে। দ্বিতীয় `count` ভ্যারিয়েবলটি একটি ইচ্ছামতো ব্লকে ডিফাইন করা এবং তার ব্লকের ভেতরে প্রথম `count` ভ্যারিয়েবলটিকে ঢেকে রাখে (অর্থাৎ শ্যাডো করে)। দ্বিতীয় `count` ভ্যারিয়েবলটি ব্লকে বারবার প্রবেশের মধ্যেও স্বাধীনভাবে তার মান ধরে রাখে।

```c
#include <stdio.h>

void print_stuff(void) {
    // static variable is initialized to 0
    static int count;
    count++;
    printf("function count is %d\n", count);
    {
        // static variable is initialized to 0
        static int count;
        count++;
        printf("block count is %d\n", count);
    }
}

int main() {
    // prints
    // function count is 1
    // block count is 1
    print_stuff();
    // prints
    // function count is 2
    // block count is 2    
    print_stuff();
}
```

কোনো `static` ভ্যারিয়েবল স্পষ্টভাবে ইনিশিয়ালাইজ করতে হলে তা একটি কনস্ট্যান্ট এক্সপ্রেশন দিয়েই করতে হবে। কনস্ট্যান্ট এক্সপ্রেশন হলো এমন একটি এক্সপ্রেশন, যা কম্পাইল টাইমে মূল্যায়ন করা যায়।

## extern: অন্য ট্রান্সলেশন ইউনিটের একটি ভ্যারিয়েবল কীভাবে অ্যাক্সেস করবেন

একটি ট্রান্সলেশন ইউনিট বলতে একটি সোর্স ফাইল এবং তা যে অন্য ফাইলগুলো `#include` করে, সেগুলোকে বোঝায়। ফাইল স্কোপের একটি ভ্যারিয়েবল `extern` হিসেবে ডিক্লেয়ার ও ইনিশিয়ালাইজ করা গেলেও, `extern` কিওয়ার্ডটি সাধারণত নতুন ভ্যারিয়েবল ডিফাইন করতে নয়, বরং আগে থেকেই থাকা কোনো ভ্যারিয়েবলকে বোঝাতেই ব্যবহৃত হয়। `extern` দিয়ে যে ভ্যারিয়েবলকে বোঝানো হয়, তার অবশ্যই ফাইল স্কোপ থাকতে হবে। ফাইল স্কোপের একটি ভ্যারিয়েবলের স্টোরেজ সবসময় `static` হয়। কোনো ইনক্লুড করা ফাইলের ভ্যারিয়েবলকে যে ফাইলটি এটি ইনক্লুড করছে সেখান থেকে অ্যাক্সেস করতে হলে, ভ্যারিয়েবলটির লিংকেজ এক্সটারনাল থাকতে হবে।

নিচের উদাহরণে আমরা `extern` হিসেবে ডিক্লেয়ার করা `val` ভ্যারিয়েবলটি ব্যবহার করেছি, যাতে এটি ফাইল স্কোপে ডিফাইন করা `val`-কে বোঝায়। `extern`-এর দুটি ব্যবহারকেই রেফারেন্সিং ডিক্লারেশন বলা হয়, কারণ এরা অন্য কোথাও ডিফাইন করা একটি ভ্যারিয়েবল রেফার করে।

```c
#include <stdio.h>

void set_val() {
    // this declares val which is defined elsewhere
    extern int val;
    val += 42;
    // prints val is 42
    printf("val is %d\n", val);
}

int main() {
    set_val();
    // this declares val which is defined elsewhere
    extern int val;
    val += 42;
    // prints val is 84
    printf("val is %d\n", val);
}
// this value could be defined in another source file.
// as a variable with static storage, it is initialized to zero
int val;
```

দুটি `extern` কিওয়ার্ডই সরিয়ে দিলে প্রোগ্রামটি হয়তো এরকম কিছু প্রিন্ট করতে পারে

```
val is 22038
val is 42
```

এমন আউটপুট দেখায় যে `extern` ছাড়া `val`-এর প্রতিটি ডিক্লারেশনই একেকটি ডিফাইনিং ডিক্লারেশন, এবং `val`-এর অন্য ডিক্লারেশনগুলোর থেকে স্বাধীন। `val`-এর ডিক্লারেশনগুলো `set_val` ও `main` থেকে পুরোপুরি মুছে ফেললে একটি কম্পাইল এরর হবে: `set_val` ও `main`-এ `val` ডিক্লেয়ার করা নেই।

`extern` হিসেবে বোঝানো ভ্যারিয়েবলটি যদি একই ফাইলে থাকে, তবে তার লিংকেজ ইন্টারনাল বা এক্সটারনাল, যেকোনোটিই হতে পারে। `val`-কে `static int val;` হিসেবে ডিফাইন করলে `set_val` বা `main`-এ `val`-এর ব্যবহারে কোনো প্রভাবই পড়বে না, শুধু কম্পাইল করার জন্য ডেফিনিশনটি এদের উপরে সরিয়ে নিতে হবে। কিন্তু `val` যদি ফাংশনগুলোর উপরে ডিফাইন করা থাকত, তবে এদের `val`-কে `extern` হিসেবে ডিক্লেয়ার করার দরকার পড়ত না।

নিচের কোডটি কাজ করবে

```c
#include <stdio.h>

// val defining declaration before the function definitions
static int val;

void set_val() {
    val += 42;
    // prints val is 42
    printf("val is %d\n", val);
}

int main() {
    set_val();
    val += 42;
    // prints val is 84
    printf("val is %d\n", val);
}
```

`static int val;` থেকে `static` সরিয়ে দিলে `val`-এর লিংকেজ এক্সটারনাল হয়ে যায়, আর `set_val` ও `main`-এ `val` আগের মতোই কাজ করবে। অন্য কোনো সোর্স ফাইল এই ফাইলটি ইনক্লুড করলে, সে `val` ব্যবহার করতে পারবে কেবল তখনই, যদি `val`-এর লিংকেজ এক্সটারনাল হয় (এবং `static` হিসেবে ডিক্লেয়ার করা না থাকে) এবং সেই অন্য ফাইলটি `extern int val;` ডিক্লেয়ার করে।

`extern` দিয়ে বোঝানো ভ্যারিয়েবলের কেবল `static` স্টোরেজ থাকলেই চলে না, তার ফাইল স্কোপও থাকতে হবে। নিচের উদাহরণটি সম্ভবত কম্পাইল হবে না, কারণ `val` `static` হলেও তার ফাইল স্কোপ নেই।

```c
#include <stdio.h>

void set_val() {
    // defined with static storage, but not in file scope
    static int val;
    val += 42;
    printf("val is %d\n", val);
}

int main() {
    set_val();
    extern int val;
    printf("val is %d\n", val);
}
```

## register: কীভাবে সম্ভবত একটি ভ্যারিয়েবলের অ্যাক্সেস দ্রুত করা যায়

`register` হিসেবে চিহ্নিত একটি ভ্যারিয়েবল প্রোগ্রামারের সেই ইচ্ছা প্রকাশ করে, যে মানটি দ্রুত অ্যাক্সেসের জন্য রেজিস্টারে রাখা হোক। একটি `register` ভ্যারিয়েবল অনেকটা `auto` ভ্যারিয়েবলের মতো, কারণ এটিকে ফাংশন বা ব্লক স্কোপে থাকতে হয়। যেহেতু মানটি মেমরির বদলে রেজিস্টারে রাখার কথা, তাই কম্পাইলারের উচিত ভ্যারিয়েবলটির অ্যাড্রেস অ্যাক্সেস করা নিষিদ্ধ করা, কারণ রেজিস্টারের অ্যাড্রেস নেওয়া যায় না। তবে একটি মেমরি অ্যাড্রেস নিজেই একটি রেজিস্টারে রাখা যায়। নিচের উদাহরণটি সেটিই দেখায়

```c
#include <stdio.h>

int main() {
    int i = 42;
    register int *i_ptr = &i;
    // prints i is 42, i_ptr is 0x7ffd0c2055c4 (or some other address)
    printf("i is %d, i_ptr is %p", i, i_ptr);
}
```

`register` মূলত একটি ইঙ্গিত ছাড়া আর কিছু নয়, কারণ কম্পাইলার চাইলে এই স্পেসিফায়ারটি মানতেও পারে, না-ও মানতে পারে; তাই মানটি সত্যিই রেজিস্টারে রাখা হবে কি না, তা নিশ্চিত নয়।

## typedef: যে স্টোরেজ ক্লাস স্পেসিফায়ার আসলে তা নয়

`typedef`-কে স্টোরেজ ক্লাস স্পেসিফায়ার বলা হয় শুধু সিনট্যাক্সের কারণে। কারণ কোনো স্টোরেজ ক্লাস স্পেসিফায়ার অন্য কোনো স্টোরেজ ক্লাস স্পেসিফায়ারের সাথে ব্যবহার করা যায় না। তাই `typedef auto int i = 42;` ঠিক ততোটাই বেআইনি, যতটা `static auto int i = 42;`।
