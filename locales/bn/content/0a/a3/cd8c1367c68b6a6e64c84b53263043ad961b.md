# সম্পর্কে

## `jq`-এ এরর

`jq` মূলত দুই ধরনের এরর রিপোর্ট করে:

1. **কম্পাইল-টাইম এরর**: প্রোগ্রামটাই ইনভ্যালিড, যেমন সিনট্যাক্স এরর, আনডিফাইন্ড ফাংশন বা ভ্যারিয়েবলের রেফারেন্স ইত্যাদি।
   `jq` প্রোগ্রামটি একেবারেই রান করতে অস্বীকার করে।

   ```sh
   $ jq -n '1 + $foo + 2'
   jq: error: $foo is not defined at <top-level>, line 1, column 5:
       1 + $foo + 2
           ^^^^
   jq: 1 compile error
   ```

2. **রানটাইম এরর**: প্রোগ্রামটি বৈধ, কিন্তু কোনো মান প্রসেস করার সময় কিছু একটা ভুল হয়ে যায়, যেমন স্ট্রিং দিয়ে একটি সংখ্যায় ইনডেক্স করা, `fromjson` দিয়ে ইনভ্যালিড JSON টেক্সট পার্স করা, ভুল টাইপের আর্গুমেন্ট দিয়ে ফাংশন কল করা ইত্যাদি।

   ```sh
   $ echo '42' | jq '.foo'
   jq: error (at <stdin>:1): Cannot index number with "foo"
   ```

এই আলোচনাটি **রানটাইম এরর** নিয়ে: সেগুলো কীভাবে রেইজ করতে হয়, কীভাবে ক্যাচ করতে হয় আর কীভাবে থামাতে হয়।

কেচ না করা রানটাইম এরর হলে `jq` _স্ট্যান্ডার্ড এরর_-এ একটি মেসেজ প্রিন্ট করে এবং স্ট্যাটাস `5` দিয়ে বেরিয়ে যায়।

## এরর রেইজ করা: `error` এবং `error(message)`

[`error`][man-error] ফিল্টারটি একটি এরর রেইজ করে।

- `error` এমন একটি এরর রেইজ করে যার মান হলো **ইনপুট** মানটি।
- `error(message)` এমন একটি এরর রেইজ করে যার মান হলো `message`-এর ফলাফল।

```jq
"bad input" | try error catch .
# => "bad input"

42 | try error("invalid value: \(.)") catch .
# => "invalid value: 42"
```

~~~~exercism/note
এররের মান _যেকোনো_ JSON মান হতে পারে, কেবল স্ট্রিং নয়।
স্ট্রাকচার্ড এরর রেইজ করলে `catch` হ্যান্ডলার এররের ভেতরের বিষয়বস্তুর ভিত্তিতে সিদ্ধান্ত নিতে পারে।

```jq
try error({kind: "range", msg: "age must be non-negative"})
catch (if type == "object" then "\(.kind) error: \(.msg)" else "unexpected: \(.)" end)
# => "range error: age must be non-negative"
```
~~~~

স্ট্রিং নয় এমন এররের মান কেচ না করা হলে `jq` সেটিকে JSON হিসেবে প্রিন্ট করে, সাথে `(not a string)` চিহ্ন দেয়।

```sh
$ jq -n 'error({code: 42, msg: "boom"})'
jq: error (at <unknown>) (not a string): {"code":42,"msg":"boom"}
```

## এরর ক্যাচ করা: `try` এবং `catch`

এরর ক্যাচ করা যায় [`try EXP catch HANDLER`][man-try-catch] দিয়ে।
প্রথম এক্সপ্রেশনটি এক্সিকিউট করা হয়; যদি এটি একটি এরর রেইজ করে, তাহলে `HANDLER` এক্সপ্রেশনটি **এররের মানটিকে তার ইনপুট হিসেবে** নিয়ে এক্সিকিউট করা হয়।
হ্যান্ডলারের আউটপুট এমনভাবে আউটপুট হয় যেন সেটি ট্রাই করা এক্সপ্রেশনটিরই আউটপুট ছিল।

```jq
true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]

true | try error("some exception") catch .
# => "some exception"
```

সংক্ষিপ্ত রূপ `try EXP` হলো `try EXP catch empty`-এর সমতুল্য: এররটি বাদ দেওয়া হয় এবং কোনো আউটপুট তৈরি হয় না।

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

~~~~exercism/note
একটি এরর `try`-এর ভেতরের **স্ট্রিমের বাকি অংশ বাতিল করে দেয়**।
ইতিমধ্যে উৎপাদিত মানগুলো রাখা হয়, কিন্তু এররের পরের কিছুই মূল্যায়ন করা হয় না।

```jq
jq -n 'try (1, error("x"), 3) catch "caught: \(.)"'
# outputs:
# 1
# "caught: x"
# (3 is never produced)
```
~~~~

একটি হ্যান্ডলার নতুন এরর রেইজ করতে পারে, অথবা শুধু `error` দিয়ে আসল এররটি আবার রেইজ করতে পারে। যেহেতু এররের মানটাই হ্যান্ডলারের ইনপুট, তাই এটি সেটিকে অপরিবর্তিতভাবে সামনে পাঠায়।

```jq
try repeat(f) catch
  if . == "break" then empty else error end
```

## এরর দমন করা: `?` অপারেটর

[`?` অপারেটর][man-question-mark], যা `EXP?` হিসেবে ব্যবহৃত হয়, তা `try EXP`-এর সংক্ষিপ্ত রূপ।
এটি ব্যর্থ হওয়া এক্সপ্রেশনকে এমন এক্সপ্রেশনে পরিণত করে যা কেবল কোনো আউটপুট দেয় না।

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]

true | [.a?]
# => []
```

এটি প্রায়ই ইনডেক্সিং অপারেটরগুলোর সাথে যুক্ত অবস্থায় দেখা যায়:

- `.foo?` হলো `.["foo"]?`
- `.[]?` ইনপুট একটি অ্যারে বা অবজেক্ট হলে তবেই ইটারেশন করে, নাহলে খালি থাকে

~~~~exercism/caution
`?` **প্রতিটি** এরর দমন করে, আপনি যেগুলো আগে থেকে ভাবেননি সেগুলোসহ।
`user` একটি অবজেক্ট না হলে `user.name?` চুপচাপ কিছুই উৎপাদন করে না, যা আপনার প্রোগ্রামের ডেটা সমস্যা বা টাইপো লুকিয়ে ফেলতে পারে।
কোনো কিছু _ব্যর্থ হয়েছে_ তা জানতে হলে, অথবা ইনপুট স্পষ্টভাবে ভ্যালিডেট করতে হলে `try ... catch` ব্যবহার করাই ভালো।
~~~~

## বিকল্প অপারেটর `//`

প্রোগ্রামাররা কখনও কখনও আশা করেন `a` ব্যর্থ হলে `a // b` যেন `b` উৎপাদন করে।
পুরোনো `jq` ভার্সনে তা সত্য ছিল, কিন্তু `jq` 1.6 থেকে আর নয়।
`//` অপারেটর এরর দমন করে না।
এটি কেবল তখনই `b` বসায় যখন `a` কোনো মান দেয় না, অথবা `false` বা `null` দেয়; `a`-এর ভেতরের এররগুলো তখনও ছড়িয়ে পড়ে।

```sh
$ jq -n '(error("x")) // 42'
jq: error (at <unknown>): x
```

এররের জন্য ফলব্যাক চাইলে `try a catch b` ব্যবহার করুন।

## ডিস্ট্রাকচারিং বিকল্প অপারেটর `?//`

[`?//` অপারেটর][man-question-mark-slash-slash] ডিস্ট্রাকচারিংয়ের সাথে এরর হ্যান্ডলিং মিলিয়ে দেয়।
এটি একের পর এক প্রতিটি বাইন্ডিং প্যাটার্ন চেষ্টা করে যতক্ষণ না একটি সফল হয়, আর ব্যর্থ হওয়া বিকল্পগুলোতে বাইন্ড হওয়া ভ্যারিয়েবলগুলো `null`-এ সেট হয়ে যায়।

```jq
# input:
#   [
#     {"a": 1, "b": 2, "c": {"d": 3, "e": 4}},
#     {"a": 5, "b": 6, "c": [{"d": 7, "e": 8}]}
#   ]

.[] as {$a, $b, c: {$d, $e}} ?// {$a, $b, c: [{$d, $e}]}
| {$a, $b, $d, $e}

# outputs:
# {"a": 1, "b": 2, "d": 3, "e": 4}    # first element: c is an object, first pattern matched
# {"a": 5, "b": 6, "d": 7, "e": 8}    # second element: c is an array, second pattern matched
```

এখানে প্রথম প্যাটার্নটি আশা করে `c` হবে `d` ও `e` কী (key) থাকা একটি _অবজেক্ট_, আর দ্বিতীয়টি আশা করে `c` হবে এমন একটি অবজেক্ট ধারণ করা একটি _অ্যারে_।
প্রথম ইনপুট এলিমেন্টটি প্রথম প্যাটার্নের সাথে বাইন্ড হয়; দ্বিতীয় এলিমেন্টটি ওই প্যাটার্নে ব্যর্থ হয়, তাই এর বদলে দ্বিতীয় প্যাটার্নটি চেষ্টা করা হয়।

এতে একটি প্রোগ্রামই এমন ইনপুট ডিস্ট্রাকচার করতে পারে যেগুলো নানা আকৃতির মধ্যে একটির রূপ নিতে পারে, স্পষ্ট `if type == ...` চেইন না লিখেই।

## প্রোগ্রাম থামানো: `halt` এবং `halt_error`

কখনও কখনও এররের সঠিক প্রতিক্রিয়া হলো প্রসেসিং পুরোপুরি বন্ধ করে দেওয়া।

- [`halt`][man-halt] `jq` প্রোগ্রামটিকে সাথে সাথে থামিয়ে দেয়, আর কোনো আউটপুট দেয় না; এক্সিট স্ট্যাটাস `0`।
- [`halt_error`][man-halt-error] প্রোগ্রামটি থামায়, এর **ইনপুট** _স্ট্যান্ডার্ড এরর_-এ কাঁচা টেক্সট হিসেবে (কোনো সাজসজ্জা ছাড়া, এমনকি নতুন লাইনও ছাড়া) প্রিন্ট করে, আর দেওয়া স্ট্যাটাস দিয়ে বেরিয়ে যায়; স্ট্যাটাস না দিলে ডিফল্ট `5`।

```sh
$ echo '"Error: something went wrong"' | jq 'halt_error(1)'
Error: something went wrong    # printed on stderr, exit status 1
```

মনে রাখবেন, এই ফিল্টারগুলো প্রোগ্রামকে সাথে সাথে থামিয়ে দেয়, যদিও পড়ার জন্য আরও ইনপুট বাকি থাকে।

### এক্সিট স্ট্যাটাস

রেফারেন্সের জন্য, `jq` এই এক্সিট স্ট্যাটাসগুলো ব্যবহার করে:

| স্ট্যাটাস | অর্থ                                             |
| :----: | ------------------------------------------------ |
| `0`    | সফল                                              |
| `2`    | ইউজেজ এরর (খারাপ কমান্ড-লাইন অপশন)               |
| `3`    | কম্পাইল এরর                                      |
| `5`    | রানটাইম এরর (বা আর্গুমেন্ট ছাড়া `halt_error`)    |

`--exit-status` / `-e` অপশন ব্যবহার করলে স্ট্যাটাস বদলে সর্বশেষ আউটপুট মানটি প্রতিফলিত করে: `true` বা সংখ্যার জন্য `0`, `false` বা `null`-এর জন্য `1`, আউটপুট না থাকলে `4`।

## ডিবাগিং সহায়ক

কোনো এরর কোথা থেকে আসছে তা খুঁজে বের করার সময় এই ফিল্টারগুলো কাজে লাগে:

- [`debug`][man-debug] এর ইনপুট অপরিবর্তিতভাবে পার করে দেয়, তবে স্ট্যান্ডার্ড এররে `["DEBUG:", <input>]` প্রিন্ট করে।
  `debug(msgs)`-ও `msgs`-কে ডিবাগ মেসেজ হিসেবে প্রিন্ট করে।
- [`stderr`][man-stderr] এর ইনপুট কাঁচা ও কম্প্যাক্ট আকারে স্ট্যান্ডার্ড এররে প্রিন্ট করে।
- [`input_line_number`][man-input-line-number] যে ইনপুটটি এই মুহূর্তে ফিল্টার হচ্ছে তার লাইন নম্বর আউটপুট দেয়। কোনো ফাইলে অনেকগুলো JSON টেক্সট থাকলে এবং তার মধ্যে একটি খারাপ থাকলে এটি দারুণ কাজে লাগে।
- [`$__loc__`][man-loc] এমন একটি অবজেক্ট আউটপুট দেয় যেখানে `file` ও `line` কী (key) আছে; এগুলো বলে দেয় এটি প্রোগ্রামের কোথায় আছে, আর এগুলো এরর মেসেজে ঢোকানো যায়।

```jq
def checked_div($d):
  if $d == 0
  then error("\($__loc__): division by zero")
  else . / $d end;

try (10 | checked_div(0)) catch .
# => "{\"file\":\"<top-level>\",\"line\":3}: division by zero"
```
