# সম্পর্কে

Elm টাইপ জেনেরিক টাইপ সমর্থন করে, যা সাধারণভাবে একটি ইন্টারফেসে নমনীয়তা যোগ করে।
উদাহরণস্বরূপ, `Maybe a` টাইপটি যেকোনো টাইপের একটি মান ধারণ করতে পারে।

```elm
type Maybe a = Nothing | Just a
```

লক্ষ্য করুন, উপরের উদাহরণে টাইপ প্যারামিটার `a` সমান চিহ্ন `=`-এর দুই পাশেই ব্যবহার করা হয়েছে।
আমরা বলি যে `a` টাইপ ডেফিনিশনের ভেতরের কিছু ডেটার সাথে আবদ্ধ।

## ফ্যান্টম টাইপ কৌশল

তবে কিছু কিছু ক্ষেত্রে টাইপ প্যারামিটারটি কেবল সমীকরণের বাম দিকে দেখা যায়।

```elm
type Distance unit = Distance Float
```

উপরের `Distance`-এর ডেফিনিশনে `unit` একটি ফ্রি টাইপ প্যারামিটার, টাইপের কোনো ডেটার সাথে আবদ্ধ নয়।
এই টাইপটিকে আমরা **ফ্যান্টম টাইপ** বলতেও পারি।

কম্পাইল টাইমে সীমাবদ্ধতা প্রয়োগ করতে চাইলে এটি অবাক করার মতোই কাজে লাগে।
উদাহরণস্বরূপ, আমরা নিশ্চিত করতে চাই যে একই এককের দূরত্বই কেবল যোগ করছি।

```elm
-- Distance is an opaque type, since the module does not expose its variants.
-- This means that users may only use the functions meter, foot and add to manipulate distances.
module Distance exposing (Distance, Meter, Foot, meter, foot, add)

-- The Distance type has a phantom type 'unit'.
type Distance unit = Distance Float

-- We define two types that will be used in place
-- of the phantom type 'unit' in our constructor functions.
type Meter = Meter
type Foot = Foot

-- Constructor for Meter
meter : Distance Meter
meter = Distance 1.0

-- Constructor for Foot
foot : Distance Foot
foot = Distance 0.3048

-- The add function cannot take two parameters of different types.
-- So we cannot add meters and feet by mistake.
add : Distance unit -> Distance unit -> Distance unit
add (Distance d1) (Distance d2) = Distance (d1 + d2)
```

ওই মডিউলের বাইরের কোড `Distance` টাইপের ভেতরের অংশে ঢুকতে পারে না।
ইউজাররা দুইটি `Distance Meter` যোগ করতে পারেন, কিন্তু একটি `Distance Meter`-এর সাথে একটি `Distance Foot` যোগ করতে পারেন না।

```elm
import Distance exposing (Distance)

-- Compiles
twoMeters = Distance.add Distance.meter Distance.meter

-- Does not compile
errDist = Distance.add Distance.meter Distance.foot
```

## ফ্যান্টম টাইপ হিসেবে এক্সটেনসিবল রেকর্ড

কোন টাইপগুলো ফ্যান্টম হতে পারে তা নিয়ে কোনো বাধা নেই, আর রেকর্ড টাইপও ব্যবহার করা যায়।
Elm রেকর্ডগুলো [এক্সটেনসিবল][extensible-records], অর্থাৎ এরা ঘোষণা করার চেয়ে বেশি ফিল্ড ধারণ করতে পারে।
ফ্যান্টম টাইপ হিসেবে ব্যবহার করলে রেকর্ডগুলো জটিল সীমাবদ্ধতা প্রকাশ করতে পারে, যেগুলো ফাংশনের মধ্য দিয়ে রূপান্তরিত হতে পারে।

চলুন `Distance` মডিউলের ভেতরে `LegoBlock` নামে একটি নতুন দূরত্বের একক যোগ করি।
ফিজিক্যাল ব্লক যেহেতু নিয়ন্ত্রিত বস্তু, তাই তাদের সবসময় দুটি প্রপার্টি থাকে: তাদের দূরত্ব নন-ফ্র্যাকশনাল এবং নন-নেগেটিভ হয়।

```elm
type LegoBlock = LegoBlock

fourStuds : Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
fourStuds = Distance 4.0
```

`nonFractional` এবং `nonNegative` এমন একটি রেকর্ডের ফিল্ড, যেটি টাইপ আর্গুমেন্টের বাইরে কোথাও নেই, তাই এদের `()` টাইপ দেওয়াই মানানসই, যাকে __ইউনিট টাইপ__ বলা হয় এবং যেটি তার উপস্থিতি ছাড়া আর কোনো তথ্য ধারণ করে না।

ইচ্ছেমতো `LegoBlock` দূরত্ব পাওয়া অবশ্যই সম্ভব, যেমন দূরত্বের পার্থক্য বা অনুপাত হিসাব করার পর।

```elm
negativeStud : Distance { properties | unit: LegoBlock, nonFractional : () }
negativeStud = Distance -1.0

threeFiddyStud : Distance { properties | unit: LegoBlock, nonNegative : () }
threeFiddyStud = Distance 3.50

crazyStud : Distance { properties | unit: LegoBlock }
crazyStud = Distance -13.37
```

উপরের সব মানই বৈধ এবং কম্পাইল হবে, তবুও `fourStuds`-এর মতো মানগুলোর প্রতি আমাদের বিশেষ আগ্রহ আছে, যেগুলোতে `nonFractional` এবং `nonNegative` দুটি প্রপার্টিই আছে, কারণ এগুলো এমন ফিজিক্যাল ব্লক বোঝায় যেগুলো একসাথে জোড়া লাগানো যায়

```elm
combineLegoBlocks
  :  Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
  -> Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
  -> Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
combineLegoBlocks = add
```

চলুন কিছু ফাংশন যোগ করি, যাতে ইউজাররা `LegoBlock` দূরত্ব তৈরি ও পরিমার্জন করতে পারেন।

```elm
newLegoBlock : Float -> Distance { properties | unit: LegoBlock }
newLegoBlock dist = Distance dist

floorDistance : Distance properties -> Distance { properties | nonFractional : () }
floorDistance (Distance dist) = Distance (toFloat (floor dist))

ceilingDistance : Distance properties -> Distance { properties | nonFractional : () }
ceilingDistance (Distance dist) = Distance (toFloat (ceiling dist))

absDistance : Distance properties -> Distance { properties | nonNegative : () }
absDistance (Distance dist) = Distance (abs dist)
```

লক্ষ্য করুন, `floorDistance`, `ceilingDistance` এবং `absDistance` `LegoBlock` ছাড়াও অন্য একক সামলাতে পারে, আর সাধারণভাবে ইনপুট প্রপার্টি নিয়ে কোনো অনুমান করে না; এরা কেবল গ্যারান্টি দেয় যে আউটপুটে একটি নির্দিষ্ট প্রপার্টি থাকবে, সেটি `nonFractional` অথবা `nonNegative`।

চলুন কয়েকটি ফলাফল দেখি।

```elm
import Distance exposing (Distance)

-- Compiles
distance1 = combineLegoBlocks fourStuds fourStuds

-- Does not compile
distance2 = combineLegoBlocks fourStuds threeFiddyStud

-- Compiles
distance3 = combineLegoBlocks fourStuds (floorDistance threeFiddyStud)

-- Does not compile
distance4 = combineLegoBlocks fourStuds negativeStud

-- Compiles
distance5 = combineLegoBlocks fourStuds (absDistance negativeStud)

-- Does not compile
distance6 = combineLegoBlocks fourStuds crazyStud

-- Compiles
distance7 = combineLegoBlocks fourStuds (floorDistance (absDistance crazyStud))

-- Compiles
distance8 = combineLegoBlocks fourStuds (ceilingDistance (absDistance crazyStud))
```

সাধারণভাবে `floorDistance` এবং `ceilingDistance` ভিন্ন ফলাফল দেয়, কিন্তু একই গ্যারান্টি দেয়।
এটাই ফ্যান্টম টাইপ কৌশলের শক্তি: শক্তিশালী গ্যারান্টি বজায় রেখে ইউজারকে নমনীয় বিকল্প দেওয়া।
