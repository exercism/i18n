# ভূমিকা

## এক্সেপশন

Java প্রোগ্রামিং ভাষা এরর এবং অন্যান্য অস্বাভাবিক ঘটনা সামলাতে _এক্সেপশন_ ব্যবহার করে।

### এক্সেপশন কী

এক্সেপশন হলো প্রোগ্রাম চালানোর সময় ঘটে যাওয়া এমন একটি ঘটনা, যা নির্দেশনার স্বাভাবিক প্রবাহকে ব্যাহত করে।
Java-তে এক্সেপশন স্পষ্টভাবে রেইজ করা হয়, আর একটি এক্সেপশন রেইজ করার কাজটিকে বলা হয় _এক্সেপশন থ্রো করা_।
একটি এক্সেপশন সামলানোর কাজটিকে বলা হয় _এক্সেপশন ক্যাচ করা_।

Java-তে সব এক্সেপশনই `Exception` ক্লাসের সাবক্লাস, আর `Exception` নিজেই `Throwable`-এর সাবক্লাস।

Java দুই ধরনের এক্সেপশন আলাদা করে:

1. চেকড এক্সেপশন
2. আনচেকড এক্সেপশন

#### চেকড এক্সেপশন

_চেকড এক্সেপশন_ হলো এমন অস্বাভাবিক অবস্থা, যা একটি অ্যাপ্লিকেশন আগে থেকেই আঁচ করতে পারে এবং তা থেকে সামলে উঠতে পারে।
একটি চেকড এক্সেপশনের উদাহরণ হলো `FileNotFoundException`, যা ঘটে যখন কোনো মেথড এমন একটি ফাইল পড়তে চায় যেটি নেই।

এই ধরনের এক্সেপশন কম্পাইল-টাইমে চেক করা হয়: যে মেথডগুলো চেকড এক্সেপশন থ্রো করে, তাদের মেথড সিগনেচারে তা উল্লেখ করা উচিত, আর যে কোড এমন কোনো মেথড কল করে যেটি চেকড এক্সেপশন থ্রো করতে পারে, সেটি সামলানো তার জন্য বাধ্যতামূলক, নাহলে কোডটি কম্পাইল হবে না।

সব চেকড এক্সেপশনই `Exception`-এর সাবক্লাস, যেগুলো `RuntimeException`-কে এক্সটেন্ড করে না।

#### আনচেকড এক্সেপশন

_আনচেকড এক্সেপশন_ হলো এমন অস্বাভাবিক অবস্থা, যা একটি অ্যাপ্লিকেশন সাধারণত আগে থেকে আঁচ করতে বা তা থেকে সামলে উঠতে পারে না।
একটি আনচেকড এক্সেপশনের উদাহরণ হলো `NullPointerException`, যা ঘটে যখন কোনো মেথড একটি নন-নাল মান আশা করে কিন্তু `null` পায়।

এই ধরনের এক্সেপশন কম্পাইল-টাইমে চেক করা হয় না: যে মেথডগুলো আনচেকড এক্সেপশন থ্রো করে, তাদের মেথড সিগনেচারে তা উল্লেখ করা বাধ্যতামূলক নয়, আর যে কোড এমন কোনো মেথড কল করে যেটি আনচেকড এক্সেপশন থ্রো করতে পারে, সেটি সামলানোও বাধ্যতামূলক নয়।

সব আনচেকড এক্সেপশনই `RuntimeException` থেকে ইনহেরিট করে, যা নিজে `Exception`-এর একটি এক্সটেনশন।

### এক্সেপশন থ্রো করা

Java-তে একটি মেথড `throw` স্টেটমেন্ট ব্যবহার করে একটি এক্সেপশন থ্রো করতে পারে।

#### একটি চেকড এক্সেপশন থ্রো করা

কোনো মেথড থেকে চেকড এক্সেপশন থ্রো করার সময় `throws` কিওয়ার্ড ব্যবহার করে মেথড সিগনেচারে তা উল্লেখ করা বাধ্যতামূলক, যেমনটা নিচের উদাহরণে দেখানো হয়েছে।
এতে কল করা কোড বাধ্য হয় আগে থেকেই ধরে নিতে যে একটি এক্সেপশন থ্রো হতে পারে, এবং সেই অনুযায়ী তা সামলে নিতে হয়।

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

#### একটি আনচেকড এক্সেপশন থ্রো করা

কোনো মেথড থেকে আনচেকড এক্সেপশন থ্রো করার সময় মেথড সিগনেচারে তা উল্লেখ করা বাধ্যতামূলক নয়, যদিও এটি সমর্থিত।

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

### এক্সেপশন সামলানো

Java-তে এক্সেপশন সামলানো হয় `try`, `catch` ও `finally` কিওয়ার্ড দিয়ে।

- যে কোড স্টেটমেন্টগুলো একটি এক্সেপশন থ্রো করতে পারে, সেগুলো একটি `try` ব্লকে মুড়ে দেওয়া উচিত।
- `try` ব্লকের পরে থাকে এক বা একাধিক `catch` ব্লক, যেগুলো `try` ব্লকে থ্রো হওয়া এক্সেপশনগুলো ক্যাচ করে।
- `catch` ব্লকগুলোর পরে ঐচ্ছিকভাবে থাকে একটি `finally` ব্লক, যা `try` ব্লকের পরে সবসময়ই চলে, এক্সেপশন থ্রো হোক বা না হোক।

নিচের উদাহরণে দেখা যায় এই কিওয়ার্ডগুলো কীভাবে কাজ করে:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

এই উদাহরণে, কোনো এক্সেপশন থ্রো না হলে নিচের লেখাটি প্রিন্ট হয়:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

কিন্তু যদি `bankAccount.withdraw(amount)` স্টেটমেন্টটি একটি `InsufficientBalanceException` থ্রো করে, তাহলে নিচের লেখাটি প্রিন্ট হয়:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

অথবা, যদি `bankAccount.withdraw(amount)` কোনো আনচেকড এক্সেপশন থ্রো করে, তাহলে নিচের লেখাটি প্রিন্ট হয়:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

### এরর

Java-তে _এরর_ নামে আরেকটি আলাদা শ্রেণিও আছে, যেগুলো অ্যাপ্লিকেশনের বাইরের গুরুতর সমস্যা।
একটি এররের উদাহরণ হলো `OutOfMemoryError`, যা ঘটে যখন কোনো অ্যাপ্লিকেশন সিস্টেমে থাকা মেমোরির চেয়ে বেশি মেমোরি ব্যবহার করতে চায়।

আনচেকড এক্সেপশনের মতোই, এররও কম্পাইল-টাইমে চেক করা হয় না।
পার্থক্য হলো, এগুলো সিস্টেম-স্তরের সমস্যা বোঝায় এবং সাধারণত অ্যাপ্লিকেশনের বদলে Java Virtual Machine বা এনভায়রনমেন্ট থ্রো করে।
অ্যাপ্লিকেশনগুলোর সাধারণত এগুলো ক্যাচ করার বা সামলানোর চেষ্টা করা উচিত নয়।

Java-তে সব এররই `Error` ক্লাস থেকে ইনহেরিট করে।
