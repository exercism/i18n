# টাপল

একটি [টাপল][tuple] হলো এলিমেন্টের একটি সসীম, ক্রমবদ্ধ তালিকা, যা ইমিউটেবল। টাপলে প্রতিটি পজিশনের একটি নির্দিষ্ট টাইপ থাকা আবশ্যক। এর ফলে কম্পাইলার জানে কোন পজিশনে কোন টাইপ আছে। একটি টাপলে ব্যবহৃত টাইপগুলো প্রতিটি পজিশনে আলাদা হতে পারে, তবে টাইপগুলো কম্পাইল টাইমে জানা থাকতে হবে।

## একটি টাপল তৈরি করা

টাপলের মানগুলোর টাইপ কম্পাইলের সময় বোঝা যায় কি না, তার উপর নির্ভর করে টাপল বিভিন্ন উপায়ে তৈরি করা যায়। যদি মানগুলো কম্পাইল টাইমে জানা থাকে, তবে টাপল লিটারাল সিনট্যাক্স ব্যবহার করে টাপল তৈরি করা যায়; অন্যথায় সেগুলো স্পষ্টভাবে ডিক্লেয়ার করতে হবে। এটাও গুরুত্বপূর্ণ যে মানগুলোর টাইপ টাপলে উল্লেখ করা টাইপের সাথে মেলে এবং মানের সংখ্যা উল্লেখ করা টাইপের সংখ্যার সাথে মেলে। নিচে টাপল লিটারাল সিনট্যাক্স দিয়ে ডিফাইন করার একটি উদাহরণ দেওয়া হলো:

```crystal
tuple = {1, "foo", 'c'} # Tuple(Int32, String, Char)
```

`Tuple` ক্লাস ব্যবহার করেও টাপল তৈরি করা যায়।

```crystal
tuple = Tuple(Int32, String, Char).new(1, "foo", 'c')
```

অন্যভাবে, টাপলে অ্যাসাইন করা ভ্যারিয়েবলের টাইপ আপনি স্পষ্টভাবে উল্লেখ করতে পারেন।

```crystal
tuple : Tuple(Int32, String, Char) = {1, "foo", 'c'}
```

টাপলের টাইপ স্পষ্টভাবে উল্লেখ করা কাজে লাগতে পারে, কারণ এতে বোঝানো যায় যে একটি পজিশনে একটি ইউনিয়ন টাইপ থাকবে। এর মানে হলো একটি পজিশনে একাধিক টাইপ থাকতে পারে।

```crystal
tuple : Tuple(Int32 | String, String, Char) = {1, "foo", 'c'}
```

## কনভার্সন

### একটি অ্যারে থেকে টাপল তৈরি করা

`Tuple` ক্লাসের `from` মেথড ব্যবহার করে একটি অ্যারে থেকে টাপল তৈরি করতে পারেন। এর জন্য টাপলের টাইপ উল্লেখ করা আবশ্যক।

```crystal
array = [1, "foo", 'c']
tuple = Tuple(Int32, String, Char).from(array)
```

### অ্যারেতে কনভার্সন

`to_a` মেথড ব্যবহার করে একটি টাপলকে অ্যারেতে কনভার্ট করতে পারেন। ফলে তৈরি হওয়া অ্যারের এলিমেন্ট টাইপ হবে টাপলের প্রতিটি ফিল্ডের টাইপের ইউনিয়ন।

```crystal
tuple = {1, "foo", 'c'}
array = tuple.to_a
array # => [1, "foo", 'c']
```

## এলিমেন্ট অ্যাক্সেস করা

অ্যারের মতোই, টাপলও জিরো-ইনডেক্সড, অর্থাৎ প্রথম এলিমেন্টটি থাকে ইনডেক্স 0-এ। তবে অ্যারের বিপরীতে, প্রতিটি এলিমেন্টের টাইপ নির্দিষ্ট এবং কম্পাইল টাইমে জানা থাকে, তাই টাপল ইনডেক্স করার সময় এলিমেন্টের টাইপ নির্ভর করে পজিশনের উপর। টাপলের একটি এলিমেন্ট অ্যাক্সেস করতে `[]` অপারেটর ব্যবহার করতে পারেন।

```crystal
array = [1, "foo", 'c']
array[0]         # => 1
typeof(array[0]) # => Int32 | String | Char

tuple = {1, "foo", 'c'}
tuple[0]         # => 1
typeof(tuple[0]) # => Int32
```

অ্যারে থেকে এলিমেন্ট অ্যাক্সেস করার ক্ষেত্রে আরেকটি পার্থক্য হলো, ইনডেক্স উল্লেখ করা থাকলে কম্পাইলার যাচাই করবে যে ইনডেক্সটি টাপলের সীমানার ভিতরে আছে কি না। এর মানে হলো আপনি রানটাইম এররের বদলে একটি কম্পাইল টাইম এরর পাবেন।

```crystal
tuple = {1, "foo", 'c'}
tuple[3]
# => Error: index out of bounds for Tuple(Int32, String, Char) (3 not in -3..2)
```

তবে ইনডেক্সটি যদি কোনো ভ্যারিয়েবলে রাখা থাকে, তাহলে কম্পাইলার কম্পাইল টাইমে যাচাই করতে পারবে না যে ইনডেক্সটি টাপলের সীমানার ভিতরে আছে কি না, এবং এর বদলে একটি রানটাইম এরর দেবে।

## সাবটাপল

একটি রেঞ্জের সাথে `[]` অপারেটর ব্যবহার করে টাপলের একটি সাবটাপল পেতে পারেন। যা ফেরত আসে তা হলো উল্লেখ করা রেঞ্জের এলিমেন্টগুলো নিয়ে তৈরি একটি নতুন টাপল। রেঞ্জটি কম্পাইল টাইমে দিতে হবে, অন্যথায় কম্পাইলার সাবটাপলের এলিমেন্টগুলোর টাইপ জানতে পারবে না। এর মানে হলো রেঞ্জটি একটি রেঞ্জ লিটারাল হতে হবে, কোনো ভ্যারিয়েবলে অ্যাসাইন করা যাবে না।

```crystal
tuple = {1, "foo", 'c'}
subtuple = tuple[0..1] # Tuple(Int32, String)

i = 0..1
tuple[i]
# Error: Tuple#[](Range) can only be called with range literals known at compile-time
```

## কখন টাপল ব্যবহার করবেন

টাপল কাজে লাগে যখন আপনি নির্দিষ্ট সংখ্যক মান একসাথে গ্রুপ করতে চান এবং সেই মানগুলোর টাইপ কম্পাইল টাইমে জানা থাকে। এর কারণ হলো টাপল ইমিউটেবল হওয়ায় অ্যারের তুলনায় এরা কম মেমরি নেয় এবং দ্রুততর। আরেকটি ব্যবহারের ক্ষেত্র হলো একটি মেথড থেকে একাধিক মান ফেরত দেওয়া। মানগুলোর টাইপ আলাদা হলে এটি বিশেষভাবে সহায়ক, কারণ টাপলের প্রতিটি পজিশনে আলাদা টাইপ থাকতে পারে।

যে ডেটা স্ট্রাকচারের আকার বাড়তে বা কমতে পারে, বা যেটি প্রায়ই পরিবর্তন করতে হয়, সেখানে টাপল ব্যবহার করা উচিত নয়।
