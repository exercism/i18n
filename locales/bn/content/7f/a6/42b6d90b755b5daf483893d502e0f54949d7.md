# শেলের মূল বিষয়গুলোর পরিচিতি

## শেল

_শেল_ হলো এমন একটি প্রোগ্রাম, যা আপনাকে কমান্ড লিখে অপারেটিং সিস্টেমের সাথে যোগাযোগ করার সুযোগ দেয়।
শেল গ্রাফিক্যালও হতে পারে; মাউস বা ট্র্যাকপ্যাড দিয়ে আপনি যে ডেস্কটপ এনভায়রনমেন্ট ব্যবহার করেন, সেটিও একটি শেল।
আমরা মূলত কমান্ড-লাইন ইন্টারফেস নিয়ে আলোচনা করব, যেখানে আপনি কমান্ড টাইপ করেন আর ফলাফল (সাধারণত) আপনার টার্মিনালে ছাপা হয়।

কমান্ড-লাইন শেলের ধরন অনেক।
Windows-এ আছে **cmd** আর **powershell**।
Mac আর Linux-এ থাকে "Unix শেল", যার আবার অনেক রকম আছে।
Mac-এর ডিফল্ট শেল **zsh**।
**csh** হলো C-এর মতো সিনট্যাক্সওয়ালা একটি পুরোনো শেল।
**bash** সবচেয়ে জনপ্রিয় শেলগুলোর একটি, বিশেষ করে Linux-এ।

সবচেয়ে প্রথম দিকের শেলগুলোর একটি হলো Bourne শেল, **sh**।
কালক্রমে এই শেলটি [স্ট্যান্ডার্ডাইজড][posix] হয়ে যায়, যাতে প্রতিটি Unix-সদৃশ সিস্টেমে এটি সরবরাহ করা হয়।
অনেক শেলই Bourne শেলের উপর ভিত্তি করে তৈরি, যারা প্রায়ই বাড়তি ইন্টারঅ্যাকটিভ বা প্রোগ্রামিং সুবিধা দেয়।

**Bash**-এর ভিত্তি হলো Bourne শেল।
সেজন্যই এটিকে বলা হয় "**B**ourne-**a**gain **sh**ell"।
অনেক Linux সিস্টেমে এটি ডিফল্ট শেল।
Bash অনেক সুবিধা দেয়, যা এটিকে একটি আনন্দদায়ক ইন্টারঅ্যাকটিভ শেল করে তোলে, যেমন:

* সম্পূর্ণ কাস্টমাইজযোগ্য প্রম্পট,
* হিস্টোরি থেকে কমান্ড ফিরিয়ে এনে পরিবর্তন করার সুবিধা,
* চলমান প্রসেস নিয়ন্ত্রণ করার সুবিধা,
* অ্যালিয়াস, যা টাইপিং কমিয়ে দেয়,
* এবং আরও অনেক কিছু।

এই ট্র্যাকের বিষয় bash-কে ইন্টারঅ্যাকটিভ শেল হিসেবে ব্যবহার করা নয়।
বরং এটি bash দিয়ে প্রোগ্রাম লেখা শেখার বিষয়ে।
সমস্যা সমাধানে _শুধু_ bash ব্যবহারের উপর জোর দেওয়া হবে, যদিও বাইরের টুল ব্যবহার করতে বাধা নেই।

## Bash-এর মূল বিষয়: কমান্ড ও আর্গুমেন্ট

Bash তার ইনপুট (যা সাধারণত একটি টার্মিনাল বা একটি ফাইল) থেকে কমান্ড পড়ে।
সে যে ইনপুট লাইনই পড়ে, তাকে একটি _কমান্ড_ হিসেবে ধরা হয়, অর্থাৎ একটি নির্দেশ যা পালন করতে হবে।
(কয়েকটি অ্যাডভান্সড কেস আছে, যেমন একাধিক লাইনজুড়ে বিস্তৃত কমান্ড, যা পরে আলোচনা করা হবে।)

Bash প্রতিটি লাইনকে **শব্দে** ভাগ করে, যেগুলোকে হোয়াইটস্পেস ক্যারেক্টার (স্পেস ও ট্যাব) দিয়ে আলাদা করা হয়।
লাইনের প্রথম শব্দটি হলো যে _কমান্ড_ কার্যকর হবে তার নাম।
বাকি সব শব্দ ওই কমান্ডের _আর্গুমেন্ট_ হয়ে যায় (অপশন, ফাইলের নাম ইত্যাদি)।

~~~~exercism/note
নিচের উদাহরণগুলোতে আমরা কিছু ইন্টারঅ্যাকটিভ কমান্ড দেখাব, যা আপনি চালাতে পারবেন।

* `#` ক্যারেক্টারটি একটি _কমেন্ট_ শুরু করে।
  কমেন্ট চিহ্নের পরে যা-ই লেখা থাকুক, শেল তা এড়িয়ে যায়; কমেন্টটি কেবল পড়ার জন্যই রাখা।
* `$` ক্যারেক্টারটি শেল প্রম্পট বোঝায়।
  আপনি যদি কমান্ডটি কপি করেন, তবে প্রম্পটটি সাথে নেবেন না।
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm` একটি অ্যাপ্লিকেশন, যা এর কাছে দেওয়া ফাইলগুলো মুছে ফেলে।
`*` একটি [গ্লব][glob] ক্যারেক্টার, একটি "ওয়াইল্ডকার্ড" প্যাটার্ন, যা বর্তমান ডিরেক্টরির সব ফাইলের সাথে মেলে।
গ্লব নিয়ে আমরা পরে আরও আলোচনা করব।

লক্ষ্য করেছেন কি, `a` আর `b`-এর মাঝে কয়েকটি স্পেস আছে, কিন্তু `b` আর `c`-এর মাঝে মাত্র একটি?
আর্গুমেন্টের মাঝে কতটা হোয়াইটস্পেস থাকছে, তা কোনো ব্যাপারই নয়!
যেমন:

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo` এমন একটি কমান্ড, যা তার আর্গুমেন্টগুলো স্ট্যান্ডার্ড আউটপুটে (আমাদের ক্ষেত্রে যা টার্মিনাল) ছাপায়।
Bash কমান্ডটিকে পাঁচটি শব্দে ভাগ করে, আর `echo` কমান্ডটি চারটি আর্গুমেন্ট নিয়ে ডাকে।
দ্বিতীয় উদাহরণের বাড়তি স্পেসগুলোতে কিছুই যায় আসে না।
`echo` জানে না, শব্দগুলোর মাঝে আসলে কেমন স্পেস ছিল।

বাড়তি হোয়াইটস্পেস ধরে রাখতে চাইলে পুরো বাক্যটিকে একটি একক আর্গুমেন্ট হিসেবে পাঠাতে হবে।
এটা করা যায় [কোট চিহ্ন][Quotes] ব্যবহার করে:

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

কোট চিহ্ন তার ভেতরের সবকিছুকে একটি _একক আর্গুমেন্টে_ পরিণত করে।
আর্গুমেন্টটি হলো `This    is    a    test.`, যার মধ্যে ওই নির্দিষ্ট স্পেস ক্যারেক্টারগুলোও আছে।
মনে রাখবেন, কোট চিহ্ন আর্গুমেন্টের অংশ নয়; `echo`-কে ওই একক আর্গুমেন্ট দেওয়ার আগে bash সেগুলো সরিয়ে দেয়।

আর্গুমেন্টগুলোকে কমান্ডের নাম থেকে এবং একে অপর থেকে হোয়াইটস্পেস দিয়ে আলাদা করা হয়।
এটা মনে রাখা জরুরি।
যেমন, নিচেরটি ভুল:

```bash
$ [-f file]
bash: [-f: command not found
```

এর উদ্দেশ্য ছিল `file` নামের একটি ফাইল আছে কি না তা পরীক্ষা করা।
ধরে নেওয়া স্বাভাবিক যে `[` আর `]`-এর আশপাশের স্পেসে কিছু যায় আসে না, কিন্তু আসলে `[` একটি কমান্ড, এবং এর শেষ আর্গুমেন্টটি অবশ্যই `]` হতে হবে।
(`[` কমান্ডটি নিয়ে আমরা পরে আরও বিস্তারিত আলোচনা করব।)
তাই `[`-কে `-f` থেকে এবং `]`-কে `file` থেকে আলাদা করতে হবে।
নইলে bash মনে করবে, আমরা `[-f` নামের একটি কমান্ড একটি মাত্র আর্গুমেন্ট `file]` দিয়ে চালানোর চেষ্টা করছি।
সঠিক কমান্ডে সব আর্গুমেন্ট হোয়াইটস্পেস দিয়ে আলাদা করা থাকে:

```bash
$ [ -f file ]
```

(অনেককে আমরা এই ব্যবহার দেখে বিভ্রান্ত হতে দেখি; তারা ভাবে `[...]` হলো "নিছক সিনট্যাক্স" আর স্পেসগুলো বাদ দেওয়া যায়; কিন্তু `[` একটি কমান্ড, এবং হোয়াইটস্পেস থাকা বাধ্যতামূলক।)

আমাদের ফাইলের নামে যদি হোয়াইটস্পেস বা অন্য বিশেষ ক্যারেক্টার থাকে, তবে সেটিকেও কোটের মধ্যে রাখতে হবে:

```bash
$ [ -f "my file" ]
```

## কমান্ডের ধরন

Bash কয়েক ধরনের কমান্ড চেনে: অ্যালিয়াস, ফাংশন, বিল্টইন, কিওয়ার্ড এবং এক্সিকিউটেবল।
এগুলো সবই _কমান্ড_, আর সবগুলোই প্রায় একইভাবে কাজ করে।

ডিফল্টভাবে অ্যালিয়াস কেবল ইন্টারঅ্যাকটিভ শেলে চালু থাকে, শেল স্ক্রিপ্টে নয়।
এখানে আমরা সেগুলো আলোচনা করব না।

### ফাংশন

একটি ফাংশনে শেল কমান্ড থাকে, এবং এটি অনেকটা ছোট স্ক্রিপ্টের মতো কাজ করে; এমনকি এরা আর্গুমেন্ট নিতে আর লোকাল ভ্যারিয়েবল তৈরি করতে পারে।
কোনো ফাংশন কল করা হলে তার ভেতরের কমান্ডগুলো কার্যকর হয়।
ফাংশন নিয়ে পরে বিস্তারিত আলোচনা করা হবে।

### বিল্টইন

Bash-এর ভেতরেই কিছু বেসিক কমান্ড বিল্ট-ইন করা আছে, যেমন: `cd` (ডিরেক্টরি পরিবর্তন), `echo` (আউটপুট লেখা), ইত্যাদি।
এগুলোকে আগে থেকেই দেওয়া ফাংশন হিসেবে ভাবা যায়।

### কিওয়ার্ড

কিওয়ার্ড অনেকটা বিল্টইনের মতো, তবে মূল পার্থক্য হলো কিওয়ার্ড আসলে bash-এর সিনট্যাক্স, আর বিশেষ নিয়মে এগুলো পার্স করা হতে পারে।
যেমন, `[` একটি bash বিল্টইন, আর `[[` একটি bash কিওয়ার্ড; দুটোই নানা ধরনের শর্ত পরীক্ষা করতে ব্যবহৃত হয়।
তবে `[[` কিওয়ার্ডে কিছু বাড়তি সুবিধা আছে।
যেমন, এটি `=~` অপারেটর দেয়, যা দিয়ে রেগুলার এক্সপ্রেশন পরীক্ষা করা যায়।

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

স্ট্রিং তুলনার অপারেটর `<` আর `>` হলো আরেকটি উদাহরণ, যেখানে কিওয়ার্ড কোডকে ভিন্নভাবে পার্স করে।
`[[...]]`-এর ভেতরে এই অপারেটরগুলোর জন্য বিশেষ কিছু করতে হয় না।

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

কিন্তু `[...]`-এর ভেতরে এগুলো কোট বা এস্কেপ করতে হবে, যাতে শেল এগুলোকে রিডাইরেকশন অপারেটর হিসেবে পার্স না করে।

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### এক্সিকিউটেবল

bash যেসব কমান্ড চালাতে পারে তার শেষ ধরনটি হলো _এক্সিকিউটেবল_।
এগুলো আপনার কম্পিউটারের ফাইলসিস্টেমে থাকা এক্সিকিউটেবল ফাইল (প্রোগ্রাম), যা আপনি চালাতে পারেন।
(এক্সিকিউটেবলকে _এক্সটার্নাল কমান্ড_ বা _অ্যাপ্লিকেশন_ও বলা হয়।)
এক্সিকিউটেবল সাধারণত শুধু তার নাম টাইপ করেই চালানো হয়; ফাইলের সম্পূর্ণ পাথ সাধারণত লাগে না।
এটা সম্ভব কারণ bash একটি পূর্বনির্ধারিত ভ্যারিয়েবল ব্যবহার করে, যা সাধারণ এক্সিকিউটেবল ফাইলের অবস্থান খুঁজে পেতে সাহায্য করে।
এই ভ্যারিয়েবলটির নাম `PATH`।
এটি কোলন দিয়ে আলাদা করা কিছু ডিরেক্টরির নামের সমষ্টি (যেমন `/usr/bin:/bin`)।
কোনো কমান্ড ফাইল পাথ ছাড়া দেওয়া হলে (যেমন `myprogram` বা `ls`), আর সেটি অ্যালিয়াস, ফাংশন, বিল্টইন বা কিওয়ার্ড না হলে, bash `PATH`-এর ডিরেক্টরিগুলোতে খোঁজে।
ডিরেক্টরিগুলো বাম থেকে ডান দিকে ক্রমানুসারে খোঁজা হয়, দেখার জন্য যে সেগুলোতে প্রদত্ত নামের কোনো এক্সিকিউটেবল আছে কি না।

এক্সিকিউটেবলটি যদি পরিচিত কোনো পাথের বাইরে থাকে, তবে তার ফাইল পাথ উল্লেখ করতে হবে।
বর্তমান ডিরেক্টরিতে থাকা `myprogram` এক্সিকিউটেবলের জন্য ব্যবহার করুন `./myprogram`; আর সেটি `/opt/somedirectory` ডিরেক্টরিতে থাকলে ব্যবহার করুন `/opt/somedirectory/myprogram`।

টিপ: কমান্ড সম্পর্কে বিস্তারিত জানতে `type` কমান্ডটি ব্যবহার করা যায়:

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## স্ক্রিপ্ট

একটি _স্ক্রিপ্ট_ হলো একটি ফাইলে রাখা ধারাবাহিক কমান্ডের সমষ্টি।
Bash ফাইলটি পড়ে আর কমান্ডগুলো ক্রমানুসারে প্রক্রিয়া করে।
বর্তমান কমান্ডটি শেষ হলেই এটি পরের কমান্ডে যায়।
ব্যতিক্রম কেবল তখনই, যখন কোনো কমান্ড অ্যাসিনক্রোনাসভাবে (ব্যাকগ্রাউন্ডে) চালানোর কথা বলা হয়েছে।
এই ক্ষেত্রটি নিয়ে এখন খুব বেশি ভাববেন না; এটা কীভাবে কাজ করে তা আমরা পরে শিখব।

এই গাইডের যেকোনো কমান্ড-লাইনের উদাহরণ স্ক্রিপ্টেও ব্যবহার করা যায়।

স্ক্রিপ্ট তৈরি করা সহজ।
শুরু করুন একটি নতুন ফাইল বানিয়ে, আর তার প্রথম লাইনে এটা লিখুন:

```bash
#!/bin/bash
```

এই লাইনটিকে _ইন্টারপ্রেটার ডিরেক্টিভ_ বলা হয় (একে _হ্যাশব্যাং_ বা **_শিব্যাং_**-ও বলা হয়)।
এটি বলে দেয় যে ফাইলটিকে কোনো কমান্ডে এক্সিকিউটেবল হিসেবে ব্যবহার করার সময় ইন্টারপ্রেটার হিসেবে `/bin/bash` ব্যবহার করতে হবে।
OS-এর কার্নেল যখন কোনো _নন-বাইনারি ফাইল_ চালায়, তখন সে ফাইলের প্রথম লাইনটি পড়ে।
লাইনটি যদি `#!` দিয়ে শুরু হয়, তবে কার্নেল ওই লাইন দেখে ঠিক করে ফাইলটি কোন ইন্টারপ্রেটারের কাছে পাঠাবে।
(এটা করার আরও কিছু বৈধ উপায় আছে, নিচে দেখুন।)
`#!` অবশ্যই ফাইলের একেবারে শুরুতে থাকতে হবে, তার আগে কোনো স্পেস বা খালি লাইন থাকতে পারবে না।
আমাদের স্ক্রিপ্টের কমান্ডগুলো এর নিচে আলাদা আলাদা লাইনে থাকবে।

টিপ: `#!/bin/bash`-এর বদলে আপনি ব্যবহার করতে পারেন

```bash
#!/usr/bin/env bash
```

`env` তার প্রথম আর্গুমেন্টে (এখানে "bash") দেওয়া নামের এক্সিকিউটেবলের জন্য `$PATH`-এ খোঁজে।
এই কৌশলটি সম্পর্কে আরও বিস্তারিত ব্যাখ্যা, এবং সাধারণ `#!/bin/bash` থেকে এটি কীভাবে আলাদা, তা জানতে দেখুন [StackOverflow-এর এই প্রশ্নটি][env bash]।

ইন্টারনেটে থাকা যে স্ক্রিপ্ট বা উদাহরণ ইন্টারপ্রেটার হিসেবে `/bin/sh` ব্যবহার করে, সেগুলোতে বিভ্রান্ত হবেন না।
**`sh` আর `bash` এক জিনিস নয়!**
Bash নিজেই একটি "sh-সামঞ্জস্যপূর্ণ" শেল, অর্থাৎ এটি বেশিরভাগ `sh` স্ক্রিপ্ট চালাতে পারে এবং অনেক একই রকম সিনট্যাক্স বহন করে।
তবে উল্টোটা সত্য নয়; bash-এর কিছু বৈশিষ্ট্য `sh`-এ ভেঙে পড়বে বা অপ্রত্যাশিত আচরণ ঘটাবে।
আসলে একটিমাত্র `sh` শেল বলে কিছু নেই।
POSIX-sh সিনট্যাক্স সমর্থন করে এমন অনেক শেল ইমপ্লিমেন্টেশন আছে।
আপনার OS-এর উপর নির্ভর করে, আপনি যখন `sh` চালান তখন আসলে bash, ash, dash বা অন্য কোনো শেল চলতে পারে।

স্ক্রিপ্ট ফাইলটি তৈরি হয়ে গেলে এভাবে চালানো যায়:

```bash
$ bash myscript
```

এই উদাহরণে আমরা _কমান্ড_ `bash` চালাই আর তাকে বলি _আর্গুমেন্ট_ হিসেবে দেওয়া স্ক্রিপ্টটি পড়তে।
এভাবে করলে `#!` লাইনটি কেবল একটি _কমেন্ট_।

বিকল্পভাবে, আমরা আমাদের স্ক্রিপ্টকে এক্সিকিউটেবল পারমিশন দিতে পারি।
এই পদ্ধতিতে bash হাতে হাতে কল না করে অন্য যেকোনো এক্সিকিউটেবলের মতোই স্ক্রিপ্টটি চালানো যায়:

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

এভাবে কমান্ড চালালে অপারেটিং সিস্টেম (OS) `#!` লাইন দেখে ঠিক করে আপনার স্ক্রিপ্ট চালাতে কোন ইন্টারপ্রেটার ব্যবহার করবে।
