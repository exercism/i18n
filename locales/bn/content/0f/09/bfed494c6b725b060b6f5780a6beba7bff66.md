# পাইপলাইন ও কমান্ড লিস্টের পরিচিতি

সাধারণ কমান্ড কীভাবে লিখতে হয় তা আমরা দেখেছি, যেখানে একটি কমান্ডের পরে কিছু আর্গুমেন্ট থাকে। এখন দেখব কীভাবে সাধারণ কমান্ড জোড়া দিয়ে আরও জটিল কমান্ড তৈরি করা যায়।

## ইনপুট ও আউটপুট

শুরু করার আগে ইনপুট/আউটপুট নিয়ে একটু পরিচিতি।

প্রসেসের কিছু "স্ট্যান্ডার্ড I/O চ্যানেল" থাকে।

* একটি প্রসেস "stdin"-এ _ইনপুট_ নিতে পারে।
* একটি প্রসেস "stdout"-এ _আউটপুট_ পাঠাতে পারে।
* একটি প্রসেস "stderr"-এ _এরর আউটপুট_ পাঠাতে পারে।

`tr` কমান্ডটি এর একটি খুব সরল উদাহরণ। এটি শুধু তার ইনপুট থেকে টেক্সট পড়ে, ক্যারেক্টার ট্রান্সলিটারেশন করে আর ফলাফল টেক্সটটি তার আউটপুটে প্রিন্ট করে।

"stdio" চ্যানেল নিয়ে আরও বিস্তারিত আমরা পাঠ্যক্রমে পরে দেখব।

## পাইপলাইন

এটি শেল প্রোগ্রামিংয়ের অন্যতম "কিলার ফিচার"। পাইপলাইনের সাহায্যে টেক্সটের একটি স্ট্রিমে জটিল রূপান্তর ঘটানো যায়।

ব্যবহারকারীদের একটি সাজানো তালিকা পেতে:

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

পাইপ চিহ্ন (`|`) একটি কমান্ডের আউটপুটকে আরেকটি কমান্ডের ইনপুটের সাথে যুক্ত করে। `cut` পড়ে `cat`-এর আউটপুট, আর `sort` পড়ে `cut`-এর আউটপুট।

~~~~exercism/advanced
* ডিফল্টভাবে, একটি পাইপলাইনের প্রতিটি কমান্ড আলাদা সাবশেলে চলে।
  (সাবশেল হলো একটি চাইল্ড প্রসেস, যা বর্তমানে চলমান শেলের একটি কপি।)

* পাইপলাইন চালাতে পারফরম্যান্সের খরচ থাকে।
  একই রকম কমান্ডের দীর্ঘ পাইপলাইন যদি তৈরি হয়ে যায়, তাহলে সেগুলো একটি একক কমান্ডে মিলিয়ে ফেলার কথা ভাবুন।
  উদাহরণস্বরূপ, `grep`, `cut`, `sed`, `awk` আর `tr`-এর একাধিক ইনস্ট্যান্স ব্যবহার করা পাইপলাইন সাধারণত দক্ষতার জন্য একটি একক `awk` কমান্ডে মিলিয়ে ফেলা যায়।

* একটি পাইপলাইনের এক্সিট স্ট্যাটাস হলো পাইপলাইনের শেষ কমান্ডের এক্সিট স্ট্যাটাস।
  তার মানে, আগের কোনো কমান্ড ব্যর্থ হলেও যদি শেষ কমান্ডটি সফল হয়, তবে পুরো পাইপলাইনের এক্সিট স্ট্যাটাস শূন্য।

  একটি শেল সেটিং আছে যা এটা বদলে দিতে পারে;
  যদি "pipefail" সেটিং চালু থাকে (`set -o pipefail` দিয়ে), তাহলে পাইপলাইনের এক্সিট স্ট্যাটাস হবে:
  * সব কমান্ড সফল হলে শূন্য, নাহলে
  * পাইপলাইনের কমান্ডগুলোর _**শেষ** অশূন্য এক্সিট স্ট্যাটাস_।
~~~~

## কমান্ড লিস্ট

কমান্ড লিস্ট হলো পাইপলাইনের একটি ক্রম, যা `;` (বা নিউলাইন), `&&` বা `||` দিয়ে আলাদা করা হয়।

* `A; B` একটি কমান্ড লিস্ট, যেখানে `A` শেষ হওয়ার পর `B` চলে।
* `A && B`, যেখানে `B` চলে শুধু যদি `A` সফল হয় (শূন্য স্ট্যাটাস নিয়ে এক্সিট করে)।
* `A || B`, যেখানে `B` চলে শুধু যদি `A` ব্যর্থ হয় (অশূন্য স্ট্যাটাস নিয়ে এক্সিট করে)।

একটি কমান্ড লিস্টের এক্সিট স্ট্যাটাস হলো সর্বশেষ যে কমান্ডটি চালানো হয়েছিল তার এক্সিট স্ট্যাটাস।

`&&` আর `||` অপারেটরগুলো একসাথে জুড়ে দেওয়া যায়, যাতে পরের কমান্ড আগের কমান্ডগুলোর স্ট্যাটাসের ওপর নির্ভর করে শর্তসাপেক্ষে চলে।
উদাহরণস্বরূপ

```bash
A && B && C && D || E
```

* A সফল হলে B চলে,
* A আর B সফল হলে C চলে,
* A, B আর C সফল হলে D চলে,
* A, B, C বা D-এর **যেকোনোটি** ব্যর্থ হলে E চলে।

~~~~exercism/caution
এই লজিক্যাল অপারেটরগুলো অল্প ব্যবহার করুন।
এগুলো খুব দ্রুত অপাঠ্য কোড, বা বোঝা কঠিন এমন লজিক তৈরি করতে পারে।

উদাহরণস্বরূপ, আপনার মনে হতে পারে এগুলো একই:

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

পার্থক্যটা হলো: C কখন চলে?

* প্রথম স্নিপেটে (if স্টেটমেন্টটি), C চলবে শুধু যদি A ব্যর্থ হয়।
* দ্বিতীয় স্নিপেটে C চলবে যদি A ব্যর্থ হয় _বা যদি A সফল হয় কিন্তু B ব্যর্থ হয়_!
~~~~

### কমান্ড লিস্টের ব্যবহার

এখানে কয়েকটি উদাহরণ দেওয়া হলো, যেখানে কমান্ড লিস্ট কোডকে সহজ করতে পারে।

#### ফাইল থেকে একগুচ্ছ লাইন পড়া

ধরুন আপনার কাছে ত্রিভুজ নিয়ে তথ্যের একটি ডেটা ফাইল আছে, এবং একটি ত্রিভুজকে তার তিন বাহু ধারণ করা তিনটি আলাদা লাইন দিয়ে প্রকাশ করা হয়।

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

আপনি একটি while লুপ ব্যবহার করতে পারেন, যেখানে শর্ত হিসেবে থাকে তিনটি আলাদা read কমান্ড:

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

ধরে নিলাম `is_pythagorean` এমন একটি কমান্ড যা নির্ধারণ করে তিন বাহু পিথাগোরীয় সমীকরণ মেনে চলে কি না, তাহলে আউটপুট হবে:

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### অ্যাসারশন

অনেক প্রোগ্রামিং ভাষায় এক ধরনের অ্যাসারশন থাকে, যেখানে কোনো শর্ত ব্যর্থ হলে একটি এক্সেপশন থ্রো করা হয়

```
assert(user == "Administrator", "wrong user");
```

Bash-এ একটি OR অপারেটর ব্যবহার করে ওই ফাংশনটি নকল করা যায়:

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## স্টাইল নিয়ে কিছু বিষয়

দীর্ঘ কমান্ড লিস্ট খুব দ্রুত পড়তে কঠিন হয়ে পড়ে।
উদারভাবে নিউলাইন ব্যবহার করলে অনেক সাহায্য হয়।

এই উদাহরণটি দেখুন, যেখানে দুটি শর্ত পূরণ হলে একটি অ্যারেতে একটি শব্দ যোগ করা হয়।

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

Bash আপনাকে একটি পাইপ বা লজিক্যাল অপারেটরের পরে নিউলাইন যোগ করার সুযোগ দেয়।

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

তবে, লাইনের শেষে থাকলে অপারেটরটি সহজেই চোখ এড়িয়ে যেতে পারে।
_লাইন কন্টিনিউয়েশন_ ব্যবহার করলে অপারেটরটি শুরুতে রাখা যায়, যা স্পষ্ট করে দেয় যে লিস্টটি এখনো চলছে:

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
_লাইন কন্টিনিউয়েশন_ হলো "ব্যাকস্ল্যাশ" আর "নিউলাইন" এই দুই অক্ষরের ক্রম (`\` + `\n`)।
Bash যখন এই ক্রমটি দেখে, তখন তা কোড থেকে কেবল মুছে যায়, আর এভাবে বর্তমান লাইনটি পরের লাইন দিয়ে _চলতে থাকে_।
খেয়াল রাখবেন, ব্যাকস্ল্যাশ আর নিউলাইনের মাঝে যেন কোনো স্পেস না থাকে।
~~~~

আরেকটি উদাহরণ দেখুন

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

অথবা

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
