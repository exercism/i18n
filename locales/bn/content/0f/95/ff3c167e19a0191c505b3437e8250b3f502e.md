# সম্পর্কে

এক্সেপশন হলো এরর হ্যান্ডলিংয়ের একটি রূপ।
এগুলোকে এক্সেপশন বলা হয়, কারণ সাধারণত কোনো অপ্রত্যাশিত ঘটনা সামলানোর সময়ই এগুলো দেখা যায়।

আমাদের কোডের যেকোনো জায়গায় আমরা একটি এক্সেপশন "raise" করতে পারি।
এটি আমরা `raise` মেথড দিয়ে করি, যেখানে একটি অবজেক্ট পাস করা হয়, সাধারণত একটি Exception অবজেক্ট, যদিও সাধারণ স্ট্রিংও ব্যবহার করা যায়।
উদাহরণস্বরূপ, অনুশীলনীর স্টাবগুলোতে আপনি দেখবেন যে আমরা বিল্ট-ইন `RuntimeError` ব্যবহার করে Ruby-কে জানাই যে একটি মেথড এখনো ইমপ্লিমেন্ট করা হয়নি।
আপনি `raise(ExceptionObject, params)` এই সংক্ষিপ্ত সিনট্যাক্সও ব্যবহার করতে পারেন।
এক্সেপশন ক্লাস বাদ দিলে ডিফল্টভাবে `RuntimeError` ব্যবহার করা হয়।

উদাহরণস্বরূপ:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

Ruby এটি দেখলে এররটি প্রোগ্রামের একেবারে উপরে তুলে দেয় এবং তারপর প্রোগ্রামটি শেষ হয়ে যায়।

উদাহরণস্বরূপ, আপনি যদি কোনো কিছুকে শূন্য দিয়ে ভাগ করার চেষ্টা করেন, তাহলে এরকম কিছু দেখতে পাবেন:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

এটা মনে রাখা জরুরি যে এক্সেপশন কেবল তখনই ব্যবহার করা উচিত যখন সত্যিই ব্যতিক্রমী কিছু ঘটে, অর্থাৎ এমন একটি এরর যা বিশেষভাবে সামলানো প্রয়োজন।
প্রোগ্রামের কন্ট্রোল-ফ্লোর জন্য এক্সেপশন ব্যবহার করা উচিত নয়, কারণ এটাকে খারাপ ডিজাইন ধরা হয়, যা প্রায়ই খারাপ পারফরম্যান্স ও মেইনটেইনেবিলিটির দিকে নিয়ে যায়।

## ক্লাস হায়ারার্কি

Ruby-তে এক্সেপশন একটি ক্লাস হায়ারার্কি অনুসরণ করে, যেখানে `Exception` হলো বেস ক্লাস।
Ruby-র সবচেয়ে কমন বিল্ট-ইন এক্সেপশনগুলো হলো:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

কোনো নির্দিষ্ট ক্লাসের এরর রেসকিউ করলে তার চাইল্ড ক্লাসগুলোর এররও রেসকিউ হয়।
এই কারণেই `Exception` থেকে রেসকিউ করা বিপজ্জনক হতে পারে।
Ruby অপারেটিং সিস্টেমের "Signals", যেমন `ctrl-c`, থেকে আসা মেসেজ হ্যান্ডল করতেও এক্সেপশন ব্যবহার করে।
এর মানে হলো, `Exception` থেকে রেসকিউ করলে এই সিস্টেম "Signals"-ও ধরা পড়বে।
তাই অপ্রত্যাশিত আচরণ এড়াতে "সব এরর" ধরার কমন প্র্যাকটিস হলো `StandardError` থেকে রেসকিউ করা।

## রেসকিউ সিনট্যাক্স
Ruby এমন পরিস্থিতির জন্যও বাড়তি রেসকিউ ক্লজ দেয় যেখানে বিশেষ ব্যবস্থা নেওয়া প্রয়োজন:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

এটি কাজে লাগে, উদাহরণস্বরূপ, নেটওয়ার্ক IO নিয়ে কাজ করার সময়, যেখানে কানেকশন বন্ধ করতে সবসময় মনে রাখতে হয়।

Ruby-র রেসকিউ ব্লক `retry` কিওয়ার্ডও ব্যবহার করতে পারে, যা begin আর rescue-এর মধ্যবর্তী সবকিছু আবার রান করে:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
