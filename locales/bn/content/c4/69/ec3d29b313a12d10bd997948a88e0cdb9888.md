# পরিচিতি

এরর সামলানোর জন্য Gleam এক্সেপশন ব্যবহার করে না; তার বদলে যেসব ফাংশন সফল বা ব্যর্থ হতে পারে, সেগুলো জেনেরিক `Result` টাইপ রিটার্ন করে।

`Result` টাইপটি ভাষার মধ্যেই বিল্ট-ইন, তাই এটি ডিফাইন করা বা ইমপোর্ট করার দরকার নেই। তবে আপনি যদি নিজে এটি ডিফাইন করতেন, তাহলে সেটি দেখতে এমন হতো:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

কোনো ফাংশন সফল হলে `Ok` ভ্যারিয়েন্ট রিটার্ন হয়, আর ফাংশন ব্যর্থ হলে `Error` ভ্যারিয়েন্ট রিটার্ন হয়।

Gleam-এ রেজাল্ট খুবই কমন, আর Gleam প্রোগ্রামাররা এগুলো নিয়ে কাজ করা সহজ করতে সাধারণত [`gleam/result` মডিউল](https://hexdocs.pm/gleam_stdlib/gleam/result.html) ব্যবহার করেন।

`result.map` ফাংশনটি দিয়ে রেজাল্টের ভেতরের মানটি `Ok` হলে তার ওপর একটি ফাংশন কল করা যায়, আবার `Error` হলে সেটিকে অপরিবর্তিত অবস্থায় পাস করা যায়।

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

`result.try` ফাংশনটিও অনেকটা একই রকম, তবে এখানে কলব্যাক ফাংশনটি একটি রেজাল্ট রিটার্ন করবে বলে ধরে নেওয়া হয়। যেসব ফাংশন রেজাল্ট রিটার্ন করে, সেগুলোকে পরপর জুড়ে দেওয়ার জন্য এটি কাজে লাগে।

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
