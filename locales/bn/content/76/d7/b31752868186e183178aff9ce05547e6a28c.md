# ভূমিকা

## পরিভাষা

আপনি ইতিমধ্যে কয়েকটি কনসেপ্টে C++ ফাংশন ব্যবহার করেছেন এবং লিখেছেন।
এখন একটু টেকনিক্যাল হওয়ার সময়।
নিচের কোড স্নিপেটে সহজে দেখে নেওয়ার জন্য সবচেয়ে বেশি ব্যবহৃত পরিভাষাগুলো দেওয়া হলো।
C++ হোয়াইটস্পেস উপেক্ষা করে, তাই ফরম্যাটিং বদলে প্রতিটি এলিমেন্টকে একটি করে লাইনে বসানো হয়েছে।

```cpp
// Function declaration:
bool                                              // Return type
admin_detected(string user, string password)      // Type signature
;                                                 // Don't forget the ';' for the declaration

// Function definition:
bool                                              // Return type
admin_detected                                    // Function name
(string user, string password)                    // Parameter list
{ return user == "admin" && password == "1234"; } // Function body
```
~~~~exercism/advanced
ডিক্লারেশন কম্পাইলারের কাছে এক ধরনের নোটের মতো কাজ করে, যেখানে জানানো হয় যে ওই নাম, রিটার্ন টাইপ ও প্যারামিটার লিস্টের একটি ফাংশন আছে।
ডেফিনিশন না থাকলে কোড কাজ করবে না।
ডিক্লারেশন ঐচ্ছিক; ফাংশনের ডেফিনিশনের আগে সেটি ব্যবহার করলে ডিক্লারেশন দরকার হয়।
ডিক্লারেশন সাইক্লিক রেফারেন্সের মতো সমস্যা সমাধান করতে পারে এবং ইন্টারফেসকে ইমপ্লিমেন্টেশন থেকে আলাদা করতেও ব্যবহার করা যায়।
~~~~

## const কোয়ালিফায়ার

কখনও কখনও আপনি নিশ্চিত করতে চান যে কোনো মান ইনিশিয়ালাইজ হওয়ার পর আর বদলানো যাবে না।
C++ ধ্রুবকের কোয়ালিফায়ার হিসেবে `const` কিওয়ার্ডটি ব্যবহার করে।

```cpp
const int number_of_dragon_balls{7};
number_of_dragon_balls--; // compilation error
```

~~~~exercism/note
ধ্রুবকগুলো প্রায়শই _UPPER_SNAKE_CASE_-এ লেখা দেখতে পাবেন।
অন্য কোনো কনভেনশন না থাকলে এই কেসিংটি ম্যাক্রোর জন্য সংরক্ষিত রাখার সুপারিশ করা হয়।
~~~~

সেট করার পর কোনো ধ্রুবক ভ্যারিয়েবল বদলাতে চাইলে আপনার কোড কম্পাইল হবে না।
এতে অনিচ্ছাকৃত পরিবর্তন এড়ানো যায়, আবার কম্পাইলারের জন্য অপ্টিমাইজেশনের সুযোগও তৈরি হয়।
একজন মানুষ হিসেবে কোড নিয়ে চিন্তা করাও সহজ হয়ে যায়, যদি জানা থাকে যে নির্দিষ্ট কিছু অংশ বদলাবে না।

ফাংশন প্যারামিটারের কোয়ালিফায়ার হিসেবেও আপনি `const` ব্যবহার করতে পারেন।

```cpp
string guess_number(const int& secret, const int& guess) {
    if (secret < guess) return "lower.";
    if (secret > guess) return "higher.";
    return "exact!";
}
```

ফাংশনে `const` রেফারেন্স পাস করলে আপনি নিশ্চিত থাকতে পারেন যে সেটি অপরিবর্তিত থাকবে।
কপি করা খরচসাপেক্ষ হতে পারে এমন অবজেক্ট, যেমন বড় স্ট্রিং, এর জন্য প্রায়শই `const` রেফারেন্স দেখতে পাবেন।
`const` কোয়ালিফায়ারের তৃতীয় ব্যবহার হলো এমন মেম্বার ফাংশন, যারা ক্লাসের ইনস্ট্যান্স বদলায় না।

```cpp
class Stubborn {
    public:
    Stubborn(string reply) {
        response = reply;
    }
    string answer(const string& question) const {
        if (question.length() == 0) { return ""; }
        return response;
    }
    private:
    string response{};
};
```

`Stubborn` ক্লাসের মেম্বার ফাংশন `answer` প্যারামিটার হিসেবে একটি `const string&` রেফারেন্স ব্যবহার করে।
এতে ফাংশনে পাস করা মূল অবজেক্ট থেকে কপি হওয়ার কাজটি এড়ানো যায়।

## ফাংশন ওভারলোডিং

প্যারামিটার লিস্ট আলাদা হলে একই নামে একাধিক ফাংশন থাকতে পারে।
এটাকে ফাংশন ওভারলোডিং বলা হয়, এবং সাধারণত তখনই করা হয় যখন এই ফাংশনগুলো খুব কাছাকাছি ধরনের কাজ করে।

রিটার্ন টাইপ বাদে ফাংশনের হেডারটাই হলো ফাংশনের __টাইপ সিগনেচার__।
টাইপ সিগনেচারে কোনো পরিবর্তন হলে সেটি নতুন একটি ফাংশন।

`play_sound` উদাহরণটিতে ভিন্ন ভিন্ন পরিস্থিতি সামলানোর জন্য ছয়টি আলাদা ওভারলোড আছে:

```cpp
// different argument types:
void play_sound(char note);         // C, D, E, ..., B
void play_sound(string solfege);    // do, re, mi, ..., ti
void play_sound(int jianpu);        // 1, 2, 3, ..., 7

// different number of arguments:
void play_sound(string solfege, double duration);

// different qualifiers:
void play_sound(vector<string>& solfege);
void play_sound(const vector<string>& solfege);
```

~~~~exercism/advanced
টাইপ সিগনেচার নির্ধারিত হয় ফাংশনের নাম, প্যারামিটারের সংখ্যা, তাদের টাইপ আর তাদের কোয়ালিফায়ার দিয়ে (তবে তাদের নাম দিয়ে নয়)।
রিটার্ন টাইপ স্পষ্টভাবে টাইপ সিগনেচারের অংশ নয়, আর শুধু রিটার্ন টাইপে আলাদা এমন দুটি ফাংশন থাকলে আপনি কম্পাইল এরর পাবেন।
কম্পাইলার অভিযোগ করবে, কারণ দুটির মধ্যে কোনটি ব্যবহার করা উচিত তা স্পষ্ট নয়।
~~~~

## ডিফল্ট আর্গুমেন্ট

কিছু ফাংশন বেশ লম্বা হয়ে যেতে পারে, আর তাদের অনেক কলেই হয়তো বেশিরভাগ প্যারামিটারের জন্য একই মান ব্যবহার করা হয়।
ডিফল্ট আর্গুমেন্ট দিয়ে সেই কলগুলোর পুনরাবৃত্তি এড়ানো যায়।

```cpp
void record_new_horse_birth(string name, int weight, string color="brown-ish", string dam="Alruccaba", string sire="Poseidon");

record_new_horse_birth("Urban Sea", 130); // color will be brown, dam "Alruccabam", sire "Poseidon"
record_new_horse_birth("Highclere", 175, "off-white", "Fall Aspen");   // sire will be "Poseidon"
```

ফাংশন ডিক্লারেশন প্রায়ই ডেফিনিশনের আগে পড়া হয়, তাই ডিফল্ট আর্গুমেন্ট সেট করার জন্য এটি ভালো জায়গা।
কোনো প্যারামিটারের ডিফল্ট ডিক্লারেশন থাকলে তার ডান দিকের সব প্যারামিটারেরও ডিফল্ট ডিক্লারেশন থাকতে হবে।
মাঝে মাঝে জটিল ফাংশন ওভারলোডগুলোকে ডিফল্ট আর্গুমেন্টসহ কম সংখ্যক ফাংশনে রিফ্যাক্টর করা যায়, যাতে রক্ষণাবেক্ষণযোগ্যতা বাড়ে।
