# পরিচিতি

কোনো ফাংশনকে [টেইল-রিকার্সিভ][recursion-tc] বলা হয় যদি ফাংশনটি যে কাজটি সবার _শেষে_ সম্পাদন করে তা হয় নিজেকে কল করা।

যেকোনো ফাংশন কল করা হলে প্রতিবার তার লোকাল ভ্যারিয়েবল ও আর্গুমেন্ট-সহ একটি _স্ট্যাক ফ্রেম_ [ফাংশন কল স্ট্যাকের][call-stack] উপরে রাখা হয়।
ফাংশন রিটার্ন করলে স্ট্যাক ফ্রেমটি স্ট্যাক থেকে সরিয়ে ফেলা হয়।

টেইল-রিকার্সিভ ফাংশন [টেইল কল অপটিমাইজেশন][tail-call-optimization] (বা টেইল কল এলিমিনেশন) সম্ভব করে।
এটি এমন একটি অপটিমাইজেশন, যা পরের ফাংশন কলকে আগের স্ট্যাক ফ্রেমটি আবার ব্যবহার করতে দেয়, যখন নিশ্চিত হওয়া যায় যে আগের ফাংশনটির আর সেটির দরকার নেই।
এতে ফাংশন কল স্ট্যাক উপচে পড়ার আশঙ্কা কমে, অর্থাৎ এমন পরিস্থিতি, যখন ফাংশন কল স্ট্যাকে এত বেশি ফ্রেম থাকে যে আরেকটি তৈরি করার মতো মেমরি অবশিষ্ট থাকে না।

## Elm-এ টেইল কল অপটিমাইজেশন

কিছু শর্তে, JavaScript-এ কম্পাইল করার সময় Elm কম্পাইলার স্বয়ংক্রিয়ভাবে একটি টেইল কল অপটিমাইজেশন করে দিতে পারে।

কোনো রিকার্সিভ ফাংশনের ক্ষেত্রে অপটিমাইজেশনটি ঘটতে পারে, যখন একটি ব্রাঞ্চের _শেষ_ অপারেশনটি হয় সরল ফাংশন অ্যাপ্লিকেশন আকারে ফাংশনটিকে নিজেই কল করা।
চলুন কয়েকটি উদাহরণ দেখি:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

উপরের ইমপ্লিমেন্টেশনটি টেইল রিকার্সিভ নয়, কারণ `else` ব্রাঞ্চের শেষ অপারেশনটি একটি গুণ, `n *`।

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

উপরের ইমপ্লিমেন্টেশনটি টেইল রিকার্সিভ এবং এটি অপটিমাইজ করা হবে, কারণ `else` ব্রাঞ্চের শেষ অপারেশনটি হলো `factorialHelper` নিজেকে কল করা।
`Int -> Int` টাইপ সিগনেচারযুক্ত কোনো ফাংশনের ক্ষেত্রে এটি সম্ভব হতো না, আর বাস্তবে টেইল কল অপটিমাইজেশন প্রায়ই হেল্পার ফাংশন ডিফাইন করে অর্জন করা হয়।

## এজ কেস

কিছু ক্ষেত্রে কম্পাইলার রিকার্সিভ ফাংশন অপটিমাইজ করতে পারে না, চলুন কয়েকটি উদাহরণ দেখি।

`f x = f (x - 1)` টেইল কল রিকার্সিভ হলেও `f x = (x - 1) |> f` নয়, কারণ `|>` ফাংশন অ্যাপ্লিকেশনটিই শেষ অপারেশন এবং সেটিকে `f` থেকে আলাদা হিসেবে ধরা হয়।
একইভাবে, বুলিয়ান শর্ত দিয়ে শেষ হওয়া ফাংশন `f x = x > 0 || f (x - 1)`-ও টেইল রিকার্সিভ নয়।

`f x = if f (x - 1) then 1 else 0` ফাংশনটি টেইল রিকার্সিভ নয়, কারণ `if`-এর ভেতরের এক্সপ্রেশনটিকে ব্রাঞ্চ হিসেবে ধরা হয় না।
একইভাবে, `case` স্টেটমেন্টে থাকা একটি রিকার্সিভ কলও অপটিমাইজ হবে না।

`f x = let y = f (x - 1) in y` ফাংশনটি টেইল রিকার্সিভ নয়, কারণ এটি `let` স্টেটমেন্টের ভেতরে নিজেকে কল করে, যাকে ব্রাঞ্চ হিসেবে ধরা হয় না।
তবে `f x = let g x = g (x - 1) in g x`-এ `g` ফাংশনটি টেইল রিকার্সিভ এবং `let` স্টেটমেন্টে ডিফাইন করা হলেও সেটি অপটিমাইজ হবে।

`f x = if x > 0 then f (x + 1) else 1 + f x` ফাংশনটি _আংশিকভাবে_ অপটিমাইজ হবে: `then` ব্রাঞ্চটি অপটিমাইজ করা যায়, কিন্তু `else` ব্রাঞ্চটি যায় না।
কিছু পরিস্থিতিতে, যেমন ট্রি-এর মতো স্ট্রাকচার ট্রাভার্স করা বা কো-রিকার্সিভ ফাংশন ডিফাইন করা, আংশিক অপটিমাইজেশনই সবচেয়ে ভালো যা অর্জন করা সম্ভব।
