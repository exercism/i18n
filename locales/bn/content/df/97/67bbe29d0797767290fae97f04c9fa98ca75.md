# এক্সেপশন

আদর্শ জগতে সবকিছু নিখুঁতভাবে কাজ করে।
কিন্তু বাস্তব জগতে ভুল হয়ে যেতে পারে, আর আমাদের সফটওয়্যার যাতে মজবুত ও নির্ভরযোগ্য হয় তা নিশ্চিত করতে এই পরিস্থিতিগুলো আমরা কীভাবে সামলাই সেটাই গুরুত্বপূর্ণ।
এক্সেপশন প্রোগ্রামিংয়ের একটি অত্যন্ত গুরুত্বপূর্ণ ধারণা, যা দিয়ে আমরা এরর এবং অপ্রত্যাশিত পরিস্থিতিগুলো সুন্দরভাবে সামলাতে পারি।

একটি এরর রেইজ করলে, যদি তা হ্যান্ডেল করা না হয়, তবে প্রোগ্রামটি থেমে যায় এবং একটি এরর মেসেজ দেখায়।
বেশিরভাগ ক্ষেত্রেই আপনি চান না যে এরর ঘটলে আপনার প্রোগ্রাম থেমে যাক; বরং আপনি চান এররটি হ্যান্ডেল করে প্রোগ্রামটি চালিয়ে যেতে।

## একটি এক্সেপশন রেইজ করা

Crystal-এ এক্সেপশন `raise` কিওয়ার্ড দিয়ে রেইজ করা হয়, আর এতে হয় একটি `String` অথবা একটি `Exception` অবজেক্ট দেওয়া যায়।
হ্যান্ডেল করা না হলে প্রোগ্রামটি থেমে যাবে এবং এরর মেসেজটি প্রিন্ট করবে।

```crystal
raise "This is an error"
```

Crystal-এ বেশ কয়েকটি বিল্ট-ইন এক্সেপশন আছে, যেমন `ArgumentError`, `IndexError`, `KeyError`, `IOError`, `SystemCallError`, `TypeError`, `ZeroDivisionError` এবং আরও অনেক।
এগুলোর ক্ষেত্রে আপনাকে এক্সেপশনের জন্য একটি মেসেজ পাস করতে হবে।

```crystal
raise ArgumentError.new("This is an argument error")
```

## [এক্সেপশন হ্যান্ডেল করা][exception-handling]

কোনো এক্সেপশন রেইজ হলে আমরা আমাদের প্রোগ্রাম ক্র্যাশ করাতে চাই না।
তাই, যখন আমরা জানি কোডের কোনো অংশ এরর-প্রবণ, তখন আমরা সেটিকে একটি `begin` ব্লকে মুড়ে দিতে পারি এবং `rescue` ব্লক দিয়ে এক্সেপশনটি রেসকিউ করতে পারি।
`begin` ব্লকটি এমন কোডের শুরু চিহ্নিত করে যা একটি এক্সেপশন রেইজ করতে পারে, আর `rescue` ব্লকটি এক্সেপশনটি হ্যান্ডেল করে।

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
end
```

`rescue` ব্লকের সাথে একটি ভ্যারিয়েবলও উল্লেখ করা যায়, যাতে এক্সেপশন অবজেক্টটি পাওয়া যায়।

```crystal
begin
 raise "This is an error"
rescue ex
 puts "An error occurred: #{ex.message}"
end
```

`rescue` ব্লকে নির্দিষ্ট একটি এক্সেপশন টাইপও উল্লেখ করা যায়, যাতে কেবল সেই এক্সেপশনটিই ধরা পড়ে।

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
end

# or

begin
 raise ArgumentError.new("This is an argument error")
rescue ex : ArgumentError
 puts "An argument error occurred: #{ex.message}"
end
```

বিভিন্ন ধরনের এক্সেপশন হ্যান্ডেল করতে একাধিক `rescue` ব্লক ব্যবহার করা যায়।
নিচের উদাহরণে প্রথম `rescue` ব্লকটি একটি `ArgumentError` ধরবে, আর দ্বিতীয় `rescue` ব্লকটি অন্য যেকোনো এক্সেপশন ধরবে।

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
rescue
 puts "An error occurred!"
end
```

`begin` ব্লকে একটি `else` ব্লকও থাকতে পারে, যা কোনো এক্সেপশন রেইজ না হলে চালানো হয়।

```crystal
begin
 puts "No error occurred"
rescue
 puts "An error occurred!"
else
 puts "No error occurred"
end
```

সবশেষে, একটি `ensure` ব্লক আছে যা এক্সেপশন রেইজ হোক বা না হোক সবসময়ই চালানো হয়।

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
ensure
 puts "This is always executed"
end
```

## মেথড কনভেনশন

কিছু মেথডের দুটি সংস্করণ থাকে, একটি `!` দিয়ে আর অন্যটি ছাড়া।
এর অর্থ দুটি ভিন্ন বিষয় হতে পারে।
একটি হলো মেথডটি অবজেক্টটি পরিবর্তন করে, আর অন্যটি হলো মেথডটি একটি এক্সেপশন রেইজ করতে পারে।

তবে বুলিয়ান ধারণায় উল্লেখ করা মেথডের শেষে `?` দেওয়ার আরেকটি কনভেনশনও আছে।
কিছু মেথড ডিফল্টভাবে একটি এক্সেপশন রেইজ করে, তবে তাদের আবার `?` দিয়ে শেষ হওয়া একটি সংস্করণও থাকে, যা এক্সেপশন রেইজ করার বদলে `nil` রিটার্ন করে।

আপনি যখন কোনো এরর রেইজ হওয়া এড়াতে চান, তখন এটি আদর্শ।
এটি পারফরম্যান্সের জন্য উপকারী হতে পারে, কারণ এতে একটি স্ট্যাকট্রেস তৈরি করতে হয় না, আর সঠিকভাবে সেট করা হলে এটি কোডকে আরও নিরাপদ করে তুলতে পারে।

## কাস্টম এক্সেপশন

আপনি [`Exception`][exception] ক্লাস থেকে ইনহেরিট করে নিজের এক্সেপশনও তৈরি করতে পারেন।
তা করতে গিয়ে আপনি ঐচ্ছিকভাবে `initialize` মেথড ওভাররাইড করে এক্সেপশনের মেসেজ সেট করতে পারেন।
এটি করতে মেসেজটি দিয়ে `@message` নামের একটি ইনস্ট্যান্স ভ্যারিয়েবলে অ্যাসাইন করা যায়।

```crystal
class MyException < Exception
 def initialize
   @message = "This is my exception"
 end
end

raise MyException.new
```
