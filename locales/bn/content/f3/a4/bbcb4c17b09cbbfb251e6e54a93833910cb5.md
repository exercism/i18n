# সম্পর্কে

রিকার্সিভ ফাংশন হলো এমন ফাংশন, যা নিজেকে কল করে।

একটি রিকার্সিভ ফাংশনে অন্তত একটি _বেস কেস_ এবং অন্তত একটি _রিকার্সিভ কেস_ থাকতে হয়।

একটি _বেস কেস_ ফাংশনটিকে আবার কল না করেই একটি মান রিটার্ন করে।
একটি _রিকার্সিভ কেস_ ফাংশনটিকে আবার কল করে এবং ইনপুট এমনভাবে বদলে দেয় যাতে একসময় তা বেস কেসের সাথে মিলে যায়।

Elm-এ রিকার্সিভ ফাংশন সাধারণত `case` এক্সপ্রেশন দিয়ে প্যাটার্ন ম্যাচিং করে ডিফাইন করা হয়।

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

একটি রিকার্সিভ ফাংশনে অনেকগুলো বেস কেস এবং/অথবা অনেকগুলো রিকার্সিভ কেস থাকতে পারে।
উদাহরণস্বরূপ, [ফিবোনাচি ক্রম][fibonacci] হলো দুটি বেস কেসযুক্ত একটি রিকার্সিভ ক্রম:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

লক্ষ্য করুন, এই নির্দিষ্ট ইমপ্লিমেন্টেশনটি এক্সপোনেনশিয়ালি ধীর, কারণ সম্পর্কিত ফিবোনাচি সংখ্যাগুলো দুটি আলাদা রিকার্সিভ কলে একেবারে শুরু থেকে হিসাব করা হয়।

একটি অ্যারেতে নির্দিষ্ট কোনো মান `x` কতবার আছে তা গোনার দুটি রিকার্সিভ কেস থাকে:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## রিকার্সনের মাধ্যমে লুপ

ইমিউটেবিলিটির কারণে Elm-এ লুপ ইম্পারেটিভ ভাষাগুলোর মতো লেখা হয় না।
উদাহরণস্বরূপ, লুপ সাধারণত এমন দেখতে হয়:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

Elm-এর মতো ফাংশনাল ভাষায় ভ্যারিয়েবল মিউটেট করা সম্ভব নয়।
তাই লুপ রিকার্সন দিয়ে ইমপ্লিমেন্ট করতে হয়।

Elm-এ একটি `for` লুপের সমতুল্য রূপ এমন দেখতে হবে:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

বাস্তবে Elm-এ অ্যারে ও অন্যান্য ডেটা স্ট্রাকচারের ওপর ইটারেশন করার কাজটি বেশিরভাগ ক্ষেত্রে [`List`][module-list] মডিউলের ফাংশন দিয়ে করা হয়, যেমন `List.map`, `List.filter` আর `List.foldl`।
ভেতরে ভেতরে এই ফাংশনগুলো রিকার্সন দিয়ে ইমপ্লিমেন্ট করা।

## অসীম এক্সিকিউশন

রিকার্সিভ ফাংশন ভুলভাবে ইমপ্লিমেন্ট করা হলে, বা খুব বেশি সংখ্যক রিকার্সিভ কল করলে, সেটি হয়তো কখনোই তার ফলাফল রিটার্ন করতে পারে না।
এটা সমস্যার কারণ হতে পারে, কারণ প্রতিবার একটি ফাংশন কল করার সময় মেমরিতে একটি রেফারেন্স সংরক্ষণ করা হয়, যেখানে রানটাইমের ফলাফলটি রিটার্ন করা উচিত ([কল স্ট্যাক][wiki-call-stack]-এ)।
একটি রিকার্সিভ ফাংশন যদি নিজেকে অতিরিক্ত বার, এমনকি অসীমবার কল করে, তবে মেমরি ফুরিয়ে গিয়ে রানটাইম ক্র্যাশ করতে পারে (একটি [স্ট্যাক ওভারফ্লো এরর][wiki-stack-overflow])।
Elm-এর রানটাইম রিকার্সন ও নির্ভরযোগ্যতার কথা মাথায় রেখে অপটিমাইজ করা, তবুও অসীম রিকার্সন সমস্যা তৈরি করতে পারে।

এই অসীম এক্সিকিউশনের সমস্যাটি যেসব কারণে হতে পারে:

- বেস কেস ইমপ্লিমেন্ট করতে ভুলে যাওয়া।
- প্যাটার্ন ম্যাচিংয়ে সম্ভাব্য সব কেস হ্যান্ডেল না করা।
- রিকার্সিভ কল করার সময় আর্গুমেন্ট ঠিকভাবে না বদলানো, ফলে কখনোই বেস কেসে পৌঁছানো না যায়।
