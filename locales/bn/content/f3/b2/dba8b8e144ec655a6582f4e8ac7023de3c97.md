# নির্দেশনা

আপনি একটি রেট্রো হ্যান্ডহেল্ড কনসোলের স্কোরিং সিস্টেমের জন্য ফার্মওয়্যার লিখছেন।
যন্ত্রটির CPU সাধারণ মানের, আর স্কোরবোর্ড ডিসপ্লেটি একটি নির্দিষ্ট হারে রিফ্রেশ হয়।
ছবি মসৃণ থাকার জন্য স্কোরিং রুটিনগুলোকে খেলোয়াড় যা-ই করুক না কেন, একটি পূর্বানুমেয় সংখ্যক সাইকেলে চলতে হবে।

আপনার সামনে চারটি কাজ আছে।

কাজগুলোর কোড ব্রাঞ্চলেস হওয়া উচিত।
শর্তসাপেক্ষ জাম্পের বদলে `cmovcc`, `setcc` এবং অ্যারিথমেটিক ব্যবহার করুন।
~~~~

## 1. ডিসপ্লে ওভারফ্লো না করেই একটি বোনাস যোগ করুন

হ্যান্ডহেল্ডের LCD-এর স্কোর অঞ্চলে ছয়টি দশমিক অঙ্কের জায়গা আছে।
এটি `999999`-এর ওপরে যেকোনো সংখ্যা দেখাতে পারে না।
যখন কোনো বোনাস চলমান টোটালকে ওই সীমার ওপরে ঠেলে দেবে, তখন প্রদর্শিত টোটাল ঘুরে গিয়ে নতুন করে শুরু না হয়ে সর্বোচ্চ মানেই আটকে থাকে।

একটি ফাংশন `add_bonus` ডিফাইন করুন, যা একটি চলমান টোটাল আর যোগ করার একটি বোনাস পেলে নতুন টোটালটিকে `999999`-এ ক্ল্যাম্প করে রিটার্ন করে।
আর্গুমেন্টগুলো ক্রমানুসারে:

1. `total`: বর্তমান স্কোর টোটাল (সর্বদা `0` ও `999999`-এর মধ্যে)
2. `bonus`: যোগ করার বোনাস (সর্বদা অ-ঋণাত্মক)

যোগফল `999999`-এর কম বা সমান হলে রিটার্ন ভ্যালু `total + bonus`, নাহলে `999999`:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

আর্গুমেন্ট দুটোই এবং রিটার্ন ভ্যালুটিও ৬৪-বিট সাইনড ইন্টিজার।

~~~~exercism/note
আপনি ধরে নিতে পারেন যে `total + bonus` একটি ৬৪-বিট সাইনড ইন্টিজারে ওভারফ্লো করে না।
~~~~

## 2. দুটি স্কোর তুলনা করুন

হ্যান্ডহেল্ডটি তার সেভ ফাইলে খেলোয়াড়ের সাম্প্রতিক সেরা স্কোরগুলোর একটি ছোট লিডারবোর্ড রাখে।
প্রতিটি খেলার পরে নতুন স্কোরটি লিডারবোর্ডের সঠিক জায়গায় ঢোকানো হয়।
সর্ট রুটিন জিজ্ঞেস করে দুটি স্কোরের মধ্যে কোনটি এগিয়ে আছে, আর উত্তরটি একটি ছোট ইন্টিজার হিসেবে আশা করে।

একটি ফাংশন `compare_scores` ডিফাইন করুন, যা দুটি স্কোর পেলে রিটার্ন করে:

- `+1`, যদি প্রথম স্কোরটি _বেশি_ হয়
- `-1`, যদি প্রথম স্কোরটি _কম_ হয়
- `0`, যদি দুটি স্কোর _সমান_ হয়

উদাহরণ:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

আর্গুমেন্ট দুটোই এবং রিটার্ন ভ্যালুটিও ৬৪-বিট সাইনড ইন্টিজার।

## 3. একটি কাঁচা স্কোর ভ্যালিডেট করুন

মাল্টিপ্লেয়ার ম্যাচের পরে স্কোর শেয়ার করার জন্য হ্যান্ডহেল্ডটি তার লিংক কেবলের মাধ্যমে অন্য একটি ইউনিটের সাথে সংযোগ করতে পারে।
কেবলটিতে বৈদ্যুতিক নয়েজ থাকে, আর আসা বাইটগুলো মাঝেমধ্যে নষ্ট হয়ে যায়, ফলে বৈধ সর্বনিম্নের অনেক নিচে বা বৈধ সর্বোচ্চের অনেক ওপরে মান তৈরি হয়।
সিস্টেমের বাকি অংশ এটি দেখার আগেই ভ্যালিডেটর প্রতিটি আসা স্কোরকে বৈধ সীমার মধ্যে ক্ল্যাম্প করে।

একটি ফাংশন `validate_score` ডিফাইন করুন, যা একটি কাঁচা স্কোর আর বৈধ সীমা পেলে স্কোরটিকে `[min, max]`-এ ক্ল্যাম্প করে রিটার্ন করে।
আর্গুমেন্টগুলো ক্রমানুসারে:

1. `score`: লিংক কেবল দিয়ে পাওয়া কাঁচা স্কোর
2. `min`: সবচেয়ে ছোট বৈধ স্কোর
3. `max`: সবচেয়ে বড় বৈধ স্কোর

`score < min` হলে রিটার্ন ভ্যালু `min`, `score > max` হলে `max`, আর বাকি ক্ষেত্রে `score`.
আপনি ধরে নিতে পারেন যে `min <= max`.

উদাহরণ:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

সবগুলো আর্গুমেন্ট এবং রিটার্ন ভ্যালু ৬৪-বিট সাইনড ইন্টিজার।

## 4. দুটি সর্বোচ্চ স্কোর ট্র্যাক করুন

প্রতিটি খেলার সেশনের শেষে হ্যান্ডহেল্ডটি তার সেভ ফাইলে থাকা সাম্প্রতিক-খেলার লগ স্ক্যান করে এখন পর্যন্ত রেকর্ড করা দুটি সর্বোচ্চ স্কোর খুঁজে বের করে।
লগটি মেমোরিতে ৬৪-বিট সাইনড ইন্টিজারের একটি সাধারণ অ্যারে।
স্ক্যানটি অ্যারেটি একবার পরিভ্রমণ করে আর দুটি চলমান সর্বোচ্চ ধরে রাখে: এখন পর্যন্ত দেখা সর্বোচ্চটি, আর দ্বিতীয় সর্বোচ্চটি।

মনে রাখবেন, দুটি সংখ্যাই অন্তত `0` হওয়া উচিত।
যেকোনো ঋণাত্মক সংখ্যা উপেক্ষা করা হয়।

ফাংশনটির একটি প্রথম সংস্করণ ক্যাসকেডিং শর্তসাপেক্ষ জাম্প দিয়ে লেখা হয়েছিল।
প্রতিটি প্রার্থীর জন্য কোডটি খোঁজে সেটি কোথায় বসে (প্রথমটির ওপরে, প্রথম ও দ্বিতীয়র মাঝে, নাকি কোথাও নয়) এবং সেই অনুযায়ী চলমান সর্বোচ্চগুলো সরিয়ে নেয়, যেকোনো ঋণাত্মক ফল বাদ দিয়ে।

এটা কাজ করে।
তবে ইনপুট মানগুলো যেহেতু র্যান্ডম, প্রতিটি শর্তসাপেক্ষ জাম্প অনেক ব্রাঞ্চ মিসপ্রেডিকশনের দিকে নিয়ে যায়।
এ কারণেই আপনি মূল লুপটি ব্রাঞ্চলেস করার জন্য রিফ্যাক্টর করার সিদ্ধান্ত নিয়েছেন।

নিচে ফাংশনটি দেওয়া আছে, যেখানে ব্রাঞ্চযুক্ত অংশটি কমেন্ট করে রাখা হয়েছে:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

কমেন্ট করা অংশটি একটি ব্রাঞ্চলেস বাস্তবায়ন দিয়ে প্রতিস্থাপন করুন।
নতুন কোডে একমাত্র অনুমোদিত জাম্প হলো সেটিই, যা অ্যারেতে একটি নতুন এলিমেন্ট যাচাই করতে লুপের শুরুতে ফিরে যায়।

ফাংশনটির কোনো রিটার্ন ভ্যালু নেই এবং এটি ব্রাঞ্চযুক্ত সংস্করণের মতো একই আর্গুমেন্ট নেয়:

1. `out`: আউটপুট বাফার, যেখানে ফাংশনটি শীর্ষ দুটি অ-ঋণাত্মক স্কোর অবরোহী ক্রমে ৬৪-বিট সাইনড ইন্টিজার হিসেবে লিখবে
2. `array`: ৬৪-বিট সাইনড ইন্টিজারের ইনপুট অ্যারে
3. `length`: অ্যারেতে এলিমেন্টের সংখ্যা, ৬৪-বিট আনসাইনড ইন্টিজার হিসেবে

~~~~exercism/note
অ্যারেতে ডুপ্লিকেট মান থাকলে, সেগুলো যদি শীর্ষ দুটি স্কোর হয়, তবে দুটো আউটপুট স্লটেই দেখা দিতে পারে।
