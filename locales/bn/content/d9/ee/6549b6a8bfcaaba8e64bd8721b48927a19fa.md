# কন্ডিশনালের পরিচিতি

## Bash-এ ট্রুথিনেস

Bash-এ বুলিয়ান মানের কোনো ধারণা নেই।
এখানে আছে স্ট্রিং আর সংখ্যা, এবং স্ট্রিং বা সংখ্যার অ্যারে।
তাহলে শর্তাধীন কমান্ডগুলো ট্রু আর ফলস নিয়ে কীভাবে কাজ করে?

## এক্সিট স্ট্যাটাস

কমান্ড শেষ হওয়ার সময় একটি _এক্সিট স্ট্যাটাস_ তৈরি করে।
এক্সিট স্ট্যাটাস হলো ০ থেকে ২৫৫ পর্যন্ত একটি ইন্টিজার (দুই প্রান্তসহ)।
Bash মনে করে **শূন্য** এক্সিট স্ট্যাটাস _সফলতা_ বোঝায়।
এর বাইরে যেকোনো এক্সিট স্ট্যাটাস _ব্যর্থতা_ বোঝায়।

এটা সব কমান্ডের ক্ষেত্রেই সত্য, যার মধ্যে আছে Bash-এর বিল্টইন কমান্ড, কিওয়ার্ড আর ফাংশন।

## "if" কমান্ড

`if` কমান্ডের মূল সিনট্যাক্স হলো

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

এটা শুরু হয় `if` দিয়ে; শর্তের কমান্ডগুলো "সফলতা"-র কমান্ড থেকে `then` দিয়ে আলাদা করা হয়; আর শেষ হয় `fi` দিয়ে।
`else` অংশটি ঐচ্ছিক।

CONDITIONAL_COMMANDS একটি একক কমান্ড হতে পারে, আবার [কমান্ডের একটি তালিকা][command-list]-ও হতে পারে।

CONDITIONAL_COMMANDS রান করা হয়, তারপর

* এক্সিট স্ট্যাটাস শূন্য হলে (সফলতা), TRUE_COMMANDS রান করা হয়।
* এক্সিট স্ট্যাটাস শূন্য না হলে (ব্যর্থতা), FALSE_COMMANDS রান করা হয়, যদি সেগুলো থাকে।

`elif` দিয়ে ধাপে ধাপে শাখা দেওয়া যায়
```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

`then`, `elif`, `else` আর `fi` শব্দগুলোর আগে অবশ্যই একটা সেমিকোলন বা নতুন লাইন থাকতে হবে।

জোর দিয়ে বলি: প্রবাহ নিয়ন্ত্রণ করে শর্তাধীন কমান্ডগুলোর **এক্সিট স্ট্যাটাস**।
উদাহরণ হিসেবে, মিল পাওয়া গেলে `grep` ০ রিটার্ন করে, আর মিল না পেলে ১ রিটার্ন করে।
`-q` অপশনটি আউটপুট চাপা দেয়, শুধু এক্সিট স্ট্যাটাস তৈরি করে।

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## "[" আর "test" কমান্ড

CONDITIONAL_COMMANDS-এর আশপাশে কোনো বিশেষ সিনট্যাক্স নেই।
আপনি হয়তো এমন `if` স্টেটমেন্ট দেখতে অভ্যস্ত, যেগুলো এরকম:

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

`[` কোনো বিশেষ সিনট্যাক্স নয়।
এটা একটা _কমান্ড_, যা শর্তাধীন এক্সপ্রেশনটি মূল্যায়ন করে এবং সফলতা/ব্যর্থতার স্ট্যাটাস নিয়ে শেষ হয়।
সব কমান্ডের মতোই, এটার আর এর আর্গুমেন্টগুলোর মাঝে হোয়াইটস্পেস **আবশ্যক**।

`[` আসলে `test` কমান্ডেরই সমার্থক।
দুটো একেবারে একই, শুধু এই পার্থক্য যে `[` কমান্ডের শেষ আর্গুমেন্টটি _অবশ্যই_ `]` হতে হবে।

### শর্তাধীন এক্সপ্রেশন

`[` আর `]` এর ভেতরে আপনি একটি শর্তাধীন এক্সপ্রেশন লেখেন।
কিছু সাধারণ শর্তাধীন এক্সপ্রেশন হলো:

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

আরও অনেক অপারেশন আছে; সেগুলো ম্যানুয়ালের [Bash Conditional Expressions][cond-expr] অংশে তালিকাভুক্ত করা আছে।

~~~~exercism/note
উপরের উদাহরণগুলোতে খেয়াল করুন, সব ভ্যারিয়েবল কোট করা আছে।
`test` আর `[` হলো সাধারণ কমান্ড, যেখানে অন্য যেকোনো কমান্ডের মতোই আর্গুমেন্টগুলো ওয়ার্ড স্প্লিটিং আর ফাইলনেম এক্সপ্যানশনের অধীন।

এটা উল্লেখ করা জরুরি, কারণ আপনি _কতগুলো আর্গুমেন্ট_ দিচ্ছেন তার উপর নির্ভর করে শর্তাধীন এক্সপ্রেশন ভিন্নভাবে মূল্যায়িত হয়:

* ০টি আর্গুমেন্ট: এক্সিট স্ট্যাটাস শূন্য নয় (ব্যর্থতা)
* ১টি আর্গুমেন্ট: আর্গুমেন্ট খালি না থাকলে এক্সিট স্ট্যাটাস শূন্য (সফলতা), খালি থাকলে শূন্য নয়।
* ২টি আর্গুমেন্ট: প্রথম আর্গুমেন্টটি হতে হবে একটি ইউনারি অপারেটর (যেমন `[ -z "$name" ]`), অথবা একটি `!` (১-আর্গুমেন্ট টেস্টের স্ট্যাটাস উল্টে দেয়)
* এবং [আরও][test]।

কোট করতে ভুলে গেলে অপ্রত্যাশিত ফল পেতে পারেন:

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## "[[" কিওয়ার্ড

[`[[...]]` শর্তাধীন গঠনটি][cond-construct] কোনো _কমান্ড_ নয়, এটি একটি **কিওয়ার্ড**।
এর মানে হলো, এটাকে অন্য যেকোনো কমান্ডের মতোই সামলানো হয়, তবুও এর পার্সিংয়ের নিয়ম আলাদা।
`[[` কমান্ডের বিশেষত্ব এই যে এর ভেতরে এক্সপ্যান্ড হওয়া ভ্যারিয়েবলগুলো ওয়ার্ড স্প্লিটিং বা ফাইলনেম এক্সপ্যানশনের অধীন **নয়**।
মানে এই কমান্ডটি আপনি যেমন আশা করেন তেমনই কাজ করে, কোট না করলেও।

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

`test` আর `[` যেসব শর্তাধীন এক্সপ্রেশন সামলাতে পারে, `[[` সেগুলো সবই সমর্থন করে।
এর সঙ্গে `[[` আরও দেয়

* `=~` রেগুলার-এক্সপ্রেশন ম্যাচিং অপারেটর,
* `==` আর `!=` গ্লব প্যাটার্ন ম্যাচিং অপারেটর হিসেবে কাজ করে,
* `&&` আর `||` লজিক্যাল অপারেটর হিসেবে (পার্সিংয়ের বিশেষ নিয়ম),
* `<` আর `>` "খালি" স্ট্রিং তুলনা অপারেটর হিসেবে (পার্সিংয়ের বিশেষ নিয়ম: এগুলো রিডাইরেকশন চিহ্ন হওয়ায় `[` কমান্ডে এগুলোর আগে এস্কেপ করতে হয়)।

সাধারণভাবে মনে করা হয়, এই বিশেষ সুবিধাগুলো এতটাই উপকারী যে `[[` একচেটিয়াভাবে ব্যবহার করা উচিত।
(যেমন, [Google Shell Style Guide][goog-test]।)

## "case" কমান্ড

[`case`][case] আরেকটি কন্ট্রোল ফ্লো কমান্ড।
এটা অন্য ভাষার "switch" স্টেটমেন্টের মতো।

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

WORD-কে প্রতিটি PATTERN-এর সঙ্গে মেলানো হয়।
কোনোটা মিললে COMMANDS রান করা হয়।

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

প্রতিটি COMMANDS অংশ **দুটি** সেমিকোলন দিয়ে শেষ করতে হবে, `;;`।

   বিস্তারিত জানতে [ম্যানুয়ালটি][case] দেখুন।
