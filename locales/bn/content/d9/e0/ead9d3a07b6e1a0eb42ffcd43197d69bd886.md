# সম্পর্কে

নেমস্পেস ব্যবহার করে না, এমন প্রোডাকশন কোড আপনার খুব একটা চোখে পড়ার সম্ভাবনা কম।

সিনট্যাক্সের একটি উদাহরণ:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

নেমস্পেস হলো সম্পর্কিত কোড একত্রে গোষ্ঠীবদ্ধ করার এবং নামের সংঘর্ষ এড়ানোর একটি উপায়।

[সরকারি ডকুমেন্টেশন][namespaces] অনুযায়ী নেমস্পেসের দুটি প্রধান ভূমিকা রয়েছে:

- প্রথমত, .NET তার অসংখ্য ক্লাস গোছানোর জন্য নেমস্পেস ব্যবহার করে
- দ্বিতীয়ত, নিজের নেমস্পেস ডিক্লেয়ার করলে বড় প্রোগ্রামিং প্রজেক্টে ক্লাস ও মেথডের নামের স্কোপ নিয়ন্ত্রণ করা সহজ হয়।

বেস ক্লাস লাইব্রেরি (BCL) তার কার্যকারিতা গোছানোর জন্য নেমস্পেস ব্যাপকভাবে ব্যবহার করে।

## নেমস্পেসভুক্ত টাইপের রেফারেন্স

নেমস্পেসের ভেতরে থাকা টাইপগুলোকে নেমস্পেসের বাইরে থেকে রেফারেন্স করতে হলে টাইপের নামের আগে ডট সিনট্যাক্স দিয়ে প্রিফিক্স বসাতে হয়। বিকল্পভাবে, এবং সাধারণত বেশি যা করা হয়, ফাইলের শুরুতে (বা কোনো নেমস্পেসের ভেতরে) একটি `using` ডিরেক্টিভ বসাতে পারেন, তাহলে ইমপোর্ট করা নেমস্পেসের যেকোনো টাইপ প্রিফিক্স ছাড়াই ব্যবহার করা যায়। একই নেমস্পেসের ভেতরে টাইপের নাম কোয়ালিফাই করার দরকার নেই।

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

`using` ডিরেক্টিভটি কোন কোন উপায়ে ব্যবহার করা যায়, এই [লেখাটিতে][using] তা সুস্পষ্টভাবে ব্যাখ্যা করা হয়েছে:

- `using`: নেমস্পেস দিয়ে টাইপ কোয়ালিফাই করার প্রয়োজন এড়ানো যায়
- `using static`: টাইপ দিয়ে মেম্বার কোয়ালিফাই করার প্রয়োজন এড়ানো যায় (ভালো একটি উদাহরণ হলো `Math.Max()`)।
- `using MyAlias = YourNamespace;`: নেমস্পেসের নামের জায়গায় আরও সহজে পড়া যায় এমন একটি নাম বসানো।

## নেমস্পেসের সংঘর্ষ

একই নামের দুটি নেমস্পেস আলাদা অ্যাসেম্বলিতে থাকলে সম্পূর্ণ কোয়ালিফায়েড আইডেন্টিফায়ার নামের সংঘর্ষ হতে পারে (হয়তো এমন পরিস্থিতি, যেখানে একটি অ্যাসেম্বলির একাধিক ভার্সন লোড করা হয়েছে)। .NET এই সমস্যার সমাধান করে [namespace alias qualifier][namespace-alias-qualifier] এবং [extern alias][extern-alias] দিয়ে।

এই বরং বিশেষায়িত বিষয়টি তোলার একটি কারণ হলো এতে [`::` অপারেটরটি][dot-dot-operator] ব্যবহৃত হয়। বিশেষ করে জেনারেট করা কোডে নেমস্পেসের শুরুতে `global::` কোয়ালিফায়ারটি আপনি প্রায়ই দেখতে পাবেন। এর উদ্দেশ্য হলো কোনো নেস্টেড নেমস্পেস বা ক্লাসের নামের সঙ্গে সম্ভাব্য সংঘর্ষ এড়ানো। নেমস্পেসের আগে `global::` বসিয়ে আপনি নিশ্চিত করেন যে একটি টপ-লেভেল নেমস্পেসই বেছে নেওয়া হচ্ছে।

## Java ডেভেলপারদের জন্য একটি নোট

Java-র `import` আর `packages`-এর সঙ্গে তুলনা করলে কিছু মিল ও অমিল লক্ষ করা উচিত:

- C#-এ নির্দিষ্ট টাইপ ইমপোর্ট করার কোনো সমতুল্য উপায় নেই।
- `using static` আর `import static` সমতুল্য।
- Java-তে jar-গুলোর মধ্যে অ্যাক্সেসিবিলিটির ওপর প্যাকেজের নামের প্রভাব থাকে। C#-এ অ্যাসেম্বলিই সবচেয়ে গুরুত্বপূর্ণ, আর একই নেমস্পেসে থাকলে অ্যাক্সেস লেভেলে কোনো প্রভাব পড়ে না।
- Java-তে ফাইল সিস্টেমের পাথ আর সম্পূর্ণ কোয়ালিফায়েড ক্লাসের নামের মধ্যে যে সম্পর্ক থাকে, তা C#-এর নেমস্পেসে নেই; যদিও সম্ভব হলে একটি ফাইলের নাম তার ভেতরে থাকা প্রধান ক্লাসের নামের সঙ্গে মিলিয়ে রাখা ভালো অভ্যাস।
