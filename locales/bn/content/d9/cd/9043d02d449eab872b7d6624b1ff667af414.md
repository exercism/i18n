# জেনেরিক টাইপের পরিচিতি

একটি **জেনেরিক টাইপ** হলো এমন একটি জেনেরিক ক্লাস বা ইন্টারফেস, যা টাইপের উপর প্যারামিটারাইজ করা থাকে। এটি কম্পাইলারকে ক্লাস বা ইন্টারফেসে টাইপ সেফটি প্রয়োগ করার সুযোগ দেয়।

এই নন-জেনেরিক `Container` ইন্টারফেসটি দেখুন:

```java
class Container {
    private Object object;

    public void set(Object object) { this.object = object; }
    public Object get() { return object; }
}
```

যেহেতু এটি Object টাইপ গ্রহণ করে এবং রিটার্ন করে, তাই যেকোনো নন-প্রিমিটিভ টাইপের সাথে এটি কাজ করে। তবে এর একটি দামও আছে, কারণ কিছু কোড `get` কল করার সময় `Integer` আশা করতে পারে, আবার অন্য কোড `set` কল করে `String` যোগ করতে পারে, ফলে রানটাইমে একটি এক্সেপশন ঘটে।

**জেনেরিক ক্লাস** এবং **জেনেরিক ইন্টারফেস**-এর ফরম্যাট নিচের মতো:

```java
class ClassName<T1, T2, ..., Tn> { ... }
interface InterfaceName<T1, T2, ..., Tn> { ... }
```

ক্লাস বা ইন্টারফেসের নামের পরে অ্যাঙ্গেল ব্র্যাকেট (`<>`) দিয়ে ঘেরা টাইপ প্যারামিটার অংশটি টাইপ প্যারামিটারগুলো (এদের টাইপ ভ্যারিয়েবলও বলা হয়) `T1`, `T2`, ..., এবং `Tn` নির্দিষ্ট করে। এগুলো ক্লাস বা ইন্টারফেসের বডির ভেতরে ব্যবহার করে জেনেরিক টাইপ সেফটি পাওয়া যায়।

এখানে `Container`-এর জেনেরিক সংস্করণ দেওয়া হলো:

```java
class Container<E> {
    private E object;

    public void set(E object) { this.object = object; }
    public E get() { return object; }
}
```

এখন তৈরি করার সময় আমাদের ডিক্লেয়ার করে দিতে হয় এটি কী টাইপ ধারণ করবে, আর কম্পাইলার সেই সীমাবদ্ধতা প্রয়োগ করে:

```java
// empty <> can infer from context
Container<String> stringContainer = new Container<>();
// compiler knows this is a String, so it is allowed
stringContainer.set("Some string");
// no cast needed, compiler knows it is a String
String result = stringContainer.get();
// this causes a compiler error:
stringContainer.set(42);
```
