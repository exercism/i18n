# ভূমিকা

`Complex numbers` আসলে জটিল কিছু নয়।
এদের শুধু একটা কম ভয়ংকর নাম দরকার।

বিশেষ করে ইঞ্জিনিয়ারিং ও বিজ্ঞানে এরা এতটাই দরকারি যে, জুলিয়া কমপ্লেক্স সংখ্যাকে ইন্টিজার ও ফ্লোটিং-পয়েন্ট সংখ্যার পাশাপাশি স্ট্যান্ডার্ড নাম্বারিক টাইপ হিসেবে রাখে।

## মূল বিষয়গুলো

জুলিয়ায় একটি `complex` মান আসলে দুটি সংখ্যার জোড়া: সাধারণত ফ্লোটিং-পয়েন্ট, তবে সবসময় নয়।
দুর্ভাগ্যজনক ঐতিহাসিক কারণে এদের বলা হয় 'বাস্তব' ও 'কাল্পনিক' অংশ।
আবারও বলি, অদ্ভুত নামগুলো নিয়ে না ভেবে ভেতরের সরলতাটাই ধরে রাখাই ভালো।

দুটি বাস্তব সংখ্যা থেকে কমপ্লেক্স সংখ্যা বানাতে চাইলে, কাল্পনিক অংশের শেষে শুধু `im` বসিয়ে দিন।

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im
julia> typeof(z)
ComplexF64 (alias for Complex{Float64})
julia> zi = 1 + 2im
1 + 2im
julia> typeof(zi)
Complex{Int64}
```

এইভাবে বিভিন্ন `Complex` টাইপ আছে, যেগুলো সংশ্লিষ্ট ইন্টিজার বা ফ্লোটিং-পয়েন্ট টাইপ থেকে তৈরি।

বাস্তব ভ্যারিয়েবল থেকে কমপ্লেক্স সংখ্যা বানাতে উপরের সিনট্যাক্স কাজ করবে না।
`a + bim` লিখলে পার্সার ধরে নেয় `bim` একটি (অস্তিত্বহীন) ভ্যারিয়েবলের নাম।

`b*im` লেখা সম্ভব, তবে বেশি পছন্দের পদ্ধতিতে `complex()` ফাংশন ব্যবহার করা হয়, যা গুণ আর যোগের কাজটি এড়িয়ে যায়।

```julia-repl
julia> a = 1.2; b = 3.4; complex(a, b)
1.2 + 3.4im
```

কমপ্লেক্স সংখ্যার অংশগুলো আলাদা আলাদা পেতে:

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im
julia> real(z)
1.2
julia> imag(z)
3.4
```

অথবা একসাথে:

```julia-repl
julia> reim(z)
(1.2, 3.4)
```

যেকোনো একটি অংশ শূন্য হতে পারে, তখন গণিতবিদেরা হয়তো সংখ্যাটিকে 'সম্পূর্ণ বাস্তব' বা 'সম্পূর্ণ কাল্পনিক' বলেন।
তবে জুলিয়ায় এটি তখনও একটি কমপ্লেক্স সংখ্যা।

```julia-repl
julia> zr = 1.2 + 0im
1.2 + 0.0im
julia> typeof(zr)
ComplexF64 (alias for Complex{Float64})
julia> zi = 3.4im
0.0 + 3.4im
julia> typeof(zi)
ComplexF64 (alias for Complex{Float64})
```

আপনি হয়তো শুনেছেন, "`i` (বা `j`) হলো -1-এর বর্গমূল"।

আপাতত এর অর্থ এইটুকুই, কাল্পনিক অংশটি _সংজ্ঞা অনুযায়ী_ নিচের সমতাটি মেনে চলে:

```julia-repl
julia> 1im * 1im == -1
true
```

ধারণাটি সহজ, তবে এর থেকে মজার ফলাফল আসে।

## পাটিগণিত

ফ্লোট আর ইন্টিজারের সাথে ব্যবহৃত সব স্ট্যান্ডার্ড গাণিতিক `operators` ও প্রাথমিক ফাংশন কমপ্লেক্স সংখ্যার সাথেও কাজ করে। ছোট একটা নমুনা:

```julia-repl
julia> z1 = 1.5 + 2im
1.5 + 2.0im
julia> z2 = 2 + 1.5im
2.0 + 1.5im
julia> z1 + z2  # addition
3.5 + 3.5im
julia> z1 * z2  # multiplication
0.0 + 6.25im
julia> z1 / z2  # division
0.96 + 0.28im
julia> z1^2  # exponentiation
-1.75 + 6.0im
julia> 2^z1  # another exponentiation
0.5188946835878313 + 2.7804223253571183im
```

## ফাংশন

`real()` আর `imag()` ছাড়াও আরও কয়েকটি ফাংশন আছে, যেগুলোর কমপ্লেক্স সংখ্যার ক্ষেত্রে বিশেষ প্রাসঙ্গিকতা আছে।

- `conj()` একটি কমপ্লেক্স সংখ্যার কাল্পনিক অংশের চিহ্ন শুধু উল্টে দেয় (_+ থেকে - অথবা উল্টোটাও_)।
    - কমপ্লেক্স গুণ যেভাবে কাজ করে, তাতে এটি আপনার ভাবনার চেয়ে অনেক বেশি কাজে লাগে।
- `abs(<complex number>)` নিশ্চিতভাবে একটি বাস্তব সংখ্যা রিটার্ন করে, যার কোনো কাল্পনিক অংশ থাকে না।
- `abs2(<complex number>)` ফাংশনটি `abs(<complex number>)`-এর বর্গ রিটার্ন করে: `abs()`-এর চেয়ে হিসাব করা দ্রুত, আর প্রায়ই কোনো হিসাবের দরকার হয় ঠিক এইটাই।
- `angle(<complex number>)` রেডিয়ানে ফেজ কোণ রিটার্ন করে।

```julia-repl
julia> z1
1.5 + 2.0im
julia> conj(z1)
1.5 - 2.0im
julia> abs(z1)
2.5
julia> abs2(z1)
6.25
julia> angle(z1)
0.9272952180016122
```
গণিতপ্রেমীদের জন্য একটি আংশিক ব্যাখ্যা:

- `z1`-এর `(real, imag)` রূপটি আসলে কমপ্লেক্স তলে কার্তেসীয় স্থানাঙ্ক ব্যবহার করে।
- একই কমপ্লেক্স সংখ্যাটিকে পোলার স্থানাঙ্ক দিয়ে `(r, θ)` প্রতীকে প্রকাশ করা যায়।
- এখানে `r` আর `θ` যথাক্রমে `abs(z1)` ও `angle(z1)` থেকে পাওয়া যায়।

কয়েকটি কনস্ট্যান্ট ব্যবহার করে একটি উদাহরণ:

```julia-repl
julia> euler = exp(1im * π)
-1.0 + 1.2246467991473532e-16im
julia> real(euler)
-1.0
julia> round(imag(euler), digits=15)  # round to 15 decimal places
0.0
```

পোলার `(r, θ)` প্রতীক এতটাই কাজের যে, জুলিয়ায় বিল্ট-ইন ফাংশন আছে: `cis` (`cos(x) + isin(x)`-এর সংক্ষিপ্ত রূপ) আর `cispi` (`cos(πx) + isin(πx)`-এর সংক্ষিপ্ত রূপ), যা এটি আরও দক্ষভাবে গড়ে তুলতে সাহায্য করে।

পোলার প্রতীকের কাজের দিকটি ধরা পড়ে অয়লারের চমৎকার সূত্রে, `ℯ^(iθ) = cos(θ) + isin(θ) = x + iy`, যেখানে `|x + iy| = 1`।
`|x + iy| = r` ধরলে পাওয়া যায় আরও সাধারণ পোলার রূপ, `r * ℯ^(iθ) = r * (cos(θ) + isin(θ)) = x + iy`।
লক্ষ্য করুন, বিশেষ করে সূচকীয় রূপটি সংক্ষিপ্ত আর নাড়াচাড়া করা সহজ।

```julia-repl
julia> exp(1im * π) ≈ cis(π) ≈ cispi(1)
true
```

উপরের আসন্ন সমতাটির কারণ হলো, `cis` আর `cispi` ফাংশন দুটি আরও পরিচ্ছন্ন সাংখ্যিক আউটপুট দিতে পারে, বিশেষ করে `cispi` যখন আর্গুমেন্ট হয় π-এর ইচ্ছামতো গুণিতক (যেমন রেডিয়ান!)।

```julia-repl
julia> cis(π)
-1.0 + 0.0im
julia> cispi(1)
-1.0 + 0.0im
julia> θ = π/2;
julia> exp(im*θ)
6.123233995736766e-17 + 1.0im
julia> cis(θ)
6.123233995736766e-17 + 1.0im
julia> cispi(θ / π)  # θ/π == 1/2
0.0 + 1.0im
```

প্রসঙ্গত, এ কারণেই 2D-তে ঘূর্ণন আর রেডিয়াল সরণ ঘটাতে কমপ্লেক্স সংখ্যা খুবই দরকারি।

ঘূর্ণনের ক্ষেত্রে, `z = x + iy` কমপ্লেক্স সংখ্যাটিকে মূলবিন্দুকে কেন্দ্র করে `θ` কোণে ঘোরানো যায় একটি সরল গুণের মাধ্যমে: `z * ℯ^(iθ)`।
লক্ষ্য করুন, এখানে `x` আর `y` আসলে বাস্তব 2D কার্তেসীয় তলের চেনা স্থানাঙ্ক, আর ধনাত্মক কোণে ঘূর্ণন হয় *ঘড়ির কাটার বিপরীতে*, ঋণাত্মক কোণে হয় *ঘড়ির কাটার দিকে*।

ঠিক তেমনি সহজে, পোলার রূপে থাকা একটি কমপ্লেক্স সংখ্যার পরম মান `r`-এর সাথে রেডিয়াল সরণ `Δr` যোগ করে সেটি ঘটানো যায় (যেমন `z = r * ℯ^(iθ)` -> `z' = (r + Δr) * ℯ^(iθ)`)।
লক্ষ্য করুন, কোণের অংশটি অপরিবর্তিত থাকে, শুধু পরম মান `r`-ই বদলায়, যেমনটি প্রত্যাশিত।
