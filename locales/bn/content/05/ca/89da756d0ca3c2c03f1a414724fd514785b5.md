# টেস্ট

প্রতিটি অনুশীলনীর সাথে একটি ইউনিট টেস্টের সেট আর সেগুলো বিল্ড ও রান করার জন্য যা যা দরকার সবকিছু দেওয়া থাকে।
ইমপ্লিমেন্টেশন আপনাকে লিখতে হবে।

## টেস্ট রান করা

অনুশীলনীর ফোল্ডারে একটি টার্মিনাল খুলুন, তারপর রান করুন:

```
make
```

এটি আপনার ইমপ্লিমেন্টেশন আর টেস্টগুলো কম্পাইল করে, তারপর টেস্টগুলো রান করে।
আপনার ইমপ্লিমেন্টেশন পরিবর্তন করলেই এটি আবার রান করুন।

যদি আপনার [Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally) থাকে, তাহলে এর বদলে এই কমান্ডটি ব্যবহার করতে পারেন, যা `make`-ও রান করে:

```
exercism test
```

বিল্ডে তৈরি হওয়া ফাইলগুলো মুছে ফেলতে `make clean` রান করুন।

### `make` ছাড়া

যদি আপনার `make` না থাকে (যেমন Windows-এ), তাহলে সরাসরি টেস্টগুলো কম্পাইল ও রান করতে পারেন।
"Bob" অনুশীলনীর জন্য:

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

তারপর Linux বা macOS-এ টেস্টগুলো রান করুন:

```
./run_tests
```

অথবা Windows-এ:

```
.\run_tests
```

## একটি অনুশীলনী ধরে এগোনো

প্রতিটি অনুশীলনীর ফাইলগুলোর নাম রাখা হয় অনুশীলনীর নামেই।
"Bob" অনুশীলনীর জন্য:

| ফাইল             | যাতে থাকে                                                        |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90`        | ইমপ্লিমেন্টেশনের একটি স্টাব, যা আপনার সম্পূর্ণ করার জন্য প্রস্তুত                 |
| `bob_test.f90`   | টেস্টগুলো                                                         |
| `TesterMain.f90` | টেস্ট লাইব্রেরি                                                  |
| `Makefile`       | `make`-এর জন্য ইনস্ট্রাকশন                                           |
| `CMakeLists.txt` | [CMake](#using-cmake-instead)-এর জন্য ইনস্ট্রাকশন, যা ঐচ্ছিক |

আপনাকে শুধু ইমপ্লিমেন্টেশন ফাইলটি এডিট করতে হবে।

সব টেস্ট পাস না হওয়া পর্যন্ত এই ধাপগুলো পুনরাবৃত্তি করেই প্রতিটি অনুশীলনী ধরে এগোতে হয়:

- কম্পাইল এরর থাকলে ঠিক করুন, তারপর টেস্ট চালিয়ে দেখুন কোনগুলো ফেইল করে।
- পরের ফেইল করা টেস্টটি পাস করানোর জন্য যতটুকু দরকার ততটুকুই ইমপ্লিমেন্ট করুন।
- রিডেবিলিটি বাড়াতে, ডুপ্লিকেশন কমাতে ইত্যাদির জন্য আপনার ইমপ্লিমেন্টেশন রিফ্যাক্টর করুন।
- আবার টেস্ট চালান, তারপর পরের ফেইল করা টেস্টে যান।

প্রতিটি ফেইল করা টেস্টের জন্য একটি মেসেজ প্রিন্ট হয়, তারপর একটি সারসংক্ষেপ আসে।
কোনো টেস্ট ফেইল করলে `make` একটি এরর দিয়ে শেষ হয়।

প্রতিটি টেস্টে টেস্টটির বর্ণনা দিয়ে একটি কমেন্ট থাকে, তারপর `call assert_equal` দিয়ে শুরু হওয়া আসল টেস্ট। যেমন

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

কোনো টেস্ট বন্ধ করতে চাইলে শুধু `'!'` দিয়ে সেটি কমেন্ট করে দিন। যেমন

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## এর বদলে CMake ব্যবহার করা

CMake আপনার দরকার নেই, তবে Visual Studio বা Xcode-এর মতো কোনো IDE-তে কাজ করলে, বা GFortran ছাড়া অন্য কোনো কম্পাইলার ব্যবহার করলে এটি কাজে লাগতে পারে।

অনুশীলনীর ফোল্ডারকে তার আসল নামেই রাখতে হবে, কারণ CMake সোর্স ফাইলগুলো খুঁজে পেতে এই নামটি ব্যবহার করে।
অনুশীলনীর ফোল্ডার থেকে শুরু করুন:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

আপনার ইমপ্লিমেন্টেশন পরিবর্তন করার পর শুধু শেষ দুটি কমান্ড চালালেই হবে।

**নোট:** `cmake` সবসময় আলাদা একটি ফোল্ডার থেকে রান করুন, যেমন `build`।
অনুশীলনীর ফোল্ডারে `cmake .` রান করলে অনুশীলনীর সাথে আসা `Makefile` প্রতিস্থাপিত হয়ে যায়।

CMake আপনার সিস্টেমের জন্য উপযুক্ত একটি জেনারেটর বেছে নেয়।
অন্য একটি বেছে নিতে `-G` অপশন ব্যবহার করুন, যেমন `cmake -G Xcode ..`।
আপনি কোন কোন জেনারেটর ব্যবহার করতে পারেন তার তালিকা দেখতে `cmake --help` রান করুন।
Visual Studio বা Xcode-এর ক্ষেত্রে `ctest -V -C Debug` দিয়ে টেস্টগুলো রান করুন।

আপনার অনুশীলনীর ফোল্ডারে যদি `Makefile` না থাকে, তাহলে বুঝতে হবে অনুশীলনীগুলোতে এই ফাইলগুলো যোগ হওয়ার আগেই সেটি ডাউনলোড হয়েছিল।
তবুও আপনি CMake ব্যবহার করতে পারেন।
