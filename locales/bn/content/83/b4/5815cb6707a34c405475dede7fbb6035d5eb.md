# পরিচিতি

স্কেলার কোড একটি নির্দিষ্ট শর্তের প্রেক্ষিতে ব্রাঞ্চ করার জন্য বিভিন্ন ইনস্ট্রাকশনের সেট করা ফ্ল্যাগের উপর নির্ভর করে।
কিন্তু প্যাকড মান একটি নয়, বরং সমান্তরালে অনেকগুলো মান প্রকাশ করে।
একটি একক শর্ত একটি লেনের জন্য ব্যর্থ হয়ে অন্যটির জন্য সফল হতে পারে।

এ কারণেই SIMD কোড ডিফল্টভাবে [ব্রাঞ্চলেস][branchless-code]।

ফ্ল্যাগের উপর নির্ভর করার বদলে, প্যাকড তুলনা সাধারণত ডেস্টিনেশন অপারেন্ডে একটি **মাস্ক** তৈরি করে।
প্রতিটি লেনের জন্য, তুলনাটি সত্য হলে পুরো লেনটি এক দিয়ে এবং মিথ্যা হলে শূন্য দিয়ে ভরিয়ে দেয়।
সাইনড ইন্টিজার হিসেবে পড়লে, একটি সত্য লেন `-1` এবং একটি মিথ্যা লেন `0`।

এরপর এই মাস্কটি নির্দিষ্ট লেন ফিল্টার করতে [বিটওয়াইজ অপারেশন][simd-bitwise] এর সাথে মিলিয়ে ব্যবহার করা যায়।

## প্যাকড তুলনা

একটি স্কেলার `cmp` এই অর্থে জেনেরিক যে এটি একই সাথে বিভিন্ন ফ্ল্যাগ সেট করতে ব্যবহৃত হয়।
তারপর আরেকটি ইনস্ট্রাকশন ওই ফ্ল্যাগগুলো ব্যবহার করে হয় ব্রাঞ্চ করতে পারে, নয়তো হিসাব করতে পারে।

কিন্তু, যেহেতু একটি প্যাকড তুলনা একই সাথে একটি শর্ত যাচাই করে এবং একটি মাস্ক হিসাব করে, এটি জেনেরিক নয়।
তুলনাটিকে পরীক্ষা করা সঠিক শর্তটিই দিতে হয়।

এটি করার দুটি উপায় আছে:

- ইন্টিজার তুলনায় শর্তটি সাফিক্স হিসেবে দেওয়া হয়: সমতার জন্য `eq`, আর বড়-থান-এর জন্য `gt`।
  অন্য ভ্যারিয়েন্টগুলো এগুলোর একটির ফলাফল সাজিয়ে তৈরি করা হয়।
- ফ্লোটিং-পয়েন্ট তুলনায় শর্তটি একটি ইমিডিয়েটে এনকোড করা থাকে।
  এই ইমিডিয়েটের বিভিন্ন মান পরীক্ষা করা বিভিন্ন শর্তকে নির্দেশ করে।

ইন্টিজার তুলনায় একটি নির্দিষ্ট কন্ডিশনাল সাফিক্স ব্যবহারের বাইরে, সিনট্যাক্স আমরা আগেই যে কাঠামো দেখেছি সেটাই অনুসরণ করে:

- ইন্টিজারের জন্য, `p` + `cmp` + শর্ত + সাইজ (`b`, `w`, `d` বা `q`)।
- ফ্লোটের জন্য, `cmp` + `p` + সাইজ (`s` বা `d`)।
  শর্তটি অতিরিক্ত অপারেন্ড হিসেবে একটি ইমিডিয়েটে পাঠানো হয়।

### ইন্টিজার তুলনা

উল্লেখ করা হয়েছে, সমতা আর বড়-থান-এর জন্য শুধু ইন্টিজার তুলনাই আছে:

| instruction                                | description                      |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | প্রতি-লেন সমতা                     |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | প্রতি-লেন **সাইনড** বড়-থান         |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

একটি ছোট-থান তুলনা তৈরি করতে, অপারেন্ড অদলবদল করে `gt` ব্যবহার করুন: `a < b` == `b > a`।

লক্ষ্য করুন, তুলনাটি **সাইনড**।
আনসাইনড তুলনা করতে, উভয় অপারেন্ডের টপ বিট উল্টে দিন।
এটি এমন একটি মাস্কের সাথে XOR করে করা যায় যেখানে শুধু টপ বিটটি সেট করা আছে।

~~~~exercism/note
দুটি কাজের আইডিয়াম হলো:

1. সব শূন্য তৈরি করতে একটি রেজিস্টারকে নিজের সাথে XOR করা।
2. সব এক তৈরি করতে একটি রেজিস্টারকে নিজের সাথে তুলনা করা।

যেমন:

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

সব-শূন্য আর সব-এক হলো যথাক্রমে "সর্বত্র মিথ্যা" আর "সর্বত্র সত্য" এনকোড করার কমন মাস্ক।
এগুলো প্যাকড `0` বা প্যাকড `-1` প্রকাশ করতেও ব্যবহার করা যায়, যেগুলো কমন সেন্টিনেল মান।
যেমন, একটি স্ট্রিংয়ের শেষ বোঝানো NUL হলো একটি `0`।
~~~~

### ফ্লোটিং-পয়েন্ট তুলনা

ফ্লোটিং-পয়েন্ট লেন ভিন্ন গড়ন ব্যবহার করে: একটি ইনস্ট্রাকশন, `cmpps` (আর ৬৪-বিট লেনের জন্য `cmppd`), শর্তটি ইমিডিয়েট হিসেবে থাকে:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM-এ এমন সিউডো-অপও আছে যেগুলো সঠিক ইমিডিয়েটে ম্যাপ হয় এবং মনে রাখা সহজ।
নিচের সবগুলোতে, `px`-এর `x` হতে পারে `s` (৩২-বিট ফ্লোট) বা `d` (৬৪-বিট ফ্লোট):

| pseudo-op    | immediate | comparison             |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a হলো NaN বা b হলো NaN |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | a-ও NaN নয়, b-ও NaN নয় |

~~~~exercism/caution
NaN আনঅর্ডারড হিসেবে তুলনা করে: এটি নিজেসহ কোনো কিছুর চেয়ে ছোট, সমান বা বড় নয়।
অর্ডারড প্রিডিকেট, যেমন `cmpltps`, কোনো একটি অপারেন্ড NaN হলে ফলস দেয়, আর আনঅর্ডারড প্রিডিকেট সত্য দেয়।
এ কারণেই `cmpordps` আর `cmpunordps` আছে, NaN পরিষ্কারভাবে পরীক্ষা করার জন্য।
~~~~

## মাস্ক দিয়ে নির্বাচন

একটি মাস্ক একটি শর্তের ফলাফল এনকোড করে।
এরপর ওই শর্ত অনুযায়ী দুই সেট মানের মধ্যে, লেন ধরে লেন, বেছে নিতে এটি ব্যবহার করা যায়।
যেখানে মাস্কটি সত্য সেখানে একটি মান থেকে লেন নিই, আর যেখানে মিথ্যা সেখানে অন্যটি থেকে:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

এই প্যাটার্নটি ব্রাঞ্চলেস নির্বাচনের প্যাকড রূপ।
প্রতিটি লেন হিসাব করা হয়, আর কোন মানটি টিকে থাকবে তা শুধু মাস্কই ঠিক করে, কোথাও কোনো `jcc` নেই।

## ডেডিকেটেড ব্লেন্ড

এমন ইনস্ট্রাকশনও আছে যেগুলো ওই একই নির্বাচন সরাসরি করে, একটি মাস্ক রেজিস্টার থেকে প্রতি এলিমেন্টে একটি করে বিট পড়ে।
এগুলোকে **ব্লেন্ড** ইনস্ট্রাকশন বলা হয়:

| instruction | element     | mask source     |
|-------------|-------------|-----------------|
| `pblendvb`  | বাইট         | ইমপ্লিসিট `xmm0` |
| `blendvps`  | ৩২-বিট লেন   | ইমপ্লিসিট `xmm0` |
| `blendvpd`  | ৬৪-বিট লেন   | ইমপ্লিসিট `xmm0` |

লক্ষ্য করুন, প্রথম ইনস্ট্রাকশনটি ইন্টিজার সিনট্যাক্স অনুসরণ করে, আর অন্য দুটি ফ্লোট সিনট্যাক্স।
তবে, যেহেতু এই ইনস্ট্রাকশনগুলো কেবল কাঁচা বাইট নির্বাচন করে, এগুলোর যেকোনোটি ইন্টিজার আর ফ্লোট দুটোর সাথেই ব্যবহার করা যায়।

প্রতিটি এলিমেন্টের জন্য, সংশ্লিষ্ট মাস্ক এলিমেন্টের টপ বিট ক্লিয়ার থাকলে ব্লেন্ডটি ডেস্টিনেশন রাখে, আর সেট থাকলে সোর্স নেয়।
শুধু ওই **টপ বিট**-ই দেখা হয়, যা একটি তুলনা মাস্ক পূরণ করে, কারণ এর লেনগুলো সব এক বা সব শূন্য।
মাস্ক রেজিস্টারটি সবসময় `xmm0`, যা ইমপ্লিসিট:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

অন্য যেকোনো সাইজের জন্য একটি তুলনা মাস্ক থেকে লেন নির্বাচন করতে `pblendvb`-ও ব্যবহার করা যায়।
যেহেতু একটি সত্য লেনের সব বাইট সব এক, `pblendvb` সেগুলোর সবগুলোই নির্বাচন করে।

~~~~exercism/note
এই ইনস্ট্রাকশনগুলোর সবগুলোই যে অপারেশনটি করা হচ্ছে তার (`blend`) পরে একটি `v` যোগ করে।
এই `v` মানে _ভ্যারিয়েবল_, কারণ নির্বাচনটি স্থির নয়: এটি একটি রেজিস্টারের উপর নির্ভর করে।

`v` ছাড়া ভ্যারিয়েন্টও আছে, যেগুলো একটি ইমিডিয়েট অনুযায়ী নির্বাচন করে।
এগুলো একই প্যাটার্ন অনুসরণ করে, ইমিডিয়েটের বিট `i` সেট থাকলে লেন `i` নির্বাচন করে।
~~~~

## মাস্ক থেকে আবার স্কেলারে

শক্তিশালী হলেও, SIMD কোড স্কেলার কোডের অনেক নমনীয়তার অভাব রাখে।
অনেক ক্ষেত্রেই একটি প্যাকড রেজিস্টার থেকে আবার স্কেলার ইনস্ট্রাকশনের জগতে ফিরে যাওয়া প্রয়োজন হয়।

`movmsk` ইনস্ট্রাকশন পরিবারটি এই দুই জগতের মধ্যে সেতু হিসেবে কাজ করে।
এই ইনস্ট্রাকশনগুলো প্রতিটি লেনের **টপ বিট** একটি জেনেরেল-পারপাস রেজিস্টারে বের করে আনে:

| instruction | gathers                     | result width |
|-------------|-----------------------------|--------------|
| `pmovmskb`  | ১৬ বাইটের প্রতিটির টপ বিট    | ১৬ বিট       |
| `movmskps`  | ৪ ডওয়ার্ডের প্রতিটির টপ বিট   | ৪ বিট        |
| `movmskpd`  | ২ কিউওয়ার্ডের প্রতিটির টপ বিট | ২ বিট        |

একটি তুলনার পরে ব্যবহার করলে, সেট করা প্রতিটি বিট একটি "সত্য" লেন বোঝায় আর ক্লিয়ার করা প্রতিটি বিট একটি "মিথ্যা" লেন।
এরপর এই ফলাফলটি স্কেলার ইনস্ট্রাকশন দিয়ে যথারীতি ব্যবহার করা যায়।
যেমন, একটি `popcnt` মিলের সংখ্যা গোনে, আর `tzcnt` প্রথমটি খুঁজে বের করে।

জেনেরেল-পারপাস রেজিস্টারটি ৩২-বিট বা ৬৪-বিট চওড়া হতে পারে।

## সম্পূর্ণ ভেক্টর পরীক্ষা

স্কেলার `test` ইনস্ট্রাকশনের একটি প্যাকড ভ্যারিয়েন্টও আছে: `ptest`।

এটি তার স্কেলার সমতুল্যের মতোই, কারণ এটি দুটি অপারেন্ডের মধ্যে একটি AND অপারেশন করে, সেগুলো পরিবর্তন না করেই।
`test`-এর বিপরীতে, `ptest` একটি ANDN অপারেশনও করে, যা প্রথম অপারেন্ডটিকে নেগেট করে।

অতএব, `ptest`-কে `pand` আর `pandn`-এর একটি নন-ডেস্ট্রাক্টিভ সংস্করণ ভাবা যায়, যা ফলাফল অনুযায়ী ফ্ল্যাগ সেট করে।
প্রায় এই দুটি ইনস্ট্রাকশনের মতোই, `ptest` পুরো SIMD রেজিস্টারটিকে একটি একক লেন হিসেবে বিবেচনা করে, তাই এটি কোনো সাইজ প্রিফিক্স নেয় না।

একটি AND অপারেশনের ফলাফল `0` হলে `ZF` সেট হয়, আর ANDN অপারেশনের ফলাফল `0` হলে `CF` সেট হয়।
এর মানে হলো, `ptest` দিয়ে সব-এক আর সব-শূন্য দুটি মাস্কই পরীক্ষা করা যায়:

1. একটি রেজিস্টারের উপর নিজের সাথেই `ptest` ব্যবহার করলে `ZF` সেট হয় কেবল যদি রেজিস্টারটি সব শূন্য হয়।
   এটি `0` পরীক্ষা করতে একটি রেজিস্টারের উপর নিজের সাথে `test` ব্যবহারের কমন স্কেলার আইডিয়ামের অনুকরণ করে।
2. একটি রেজিস্টারের উপর একটি সব-এক মাস্ক দিয়ে `ptest` ব্যবহার করলে `CF` সেট হয় কেবল যদি রেজিস্টারটি সব এক হয়।
   এছাড়া, এটি `ZF` সেট করে কেবল যদি রেজিস্টারটি সব শূন্য হয়, ফলে একবারেই দুটি মাস্ক পরীক্ষা করা সম্ভব হয়।

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

একটি `ptest`-এর ফলাফল যথারীতি ব্রাঞ্চ করতে বা `setcc` কিংবা `cmovcc`-এর মতো ব্রাঞ্চলেস ইনস্ট্রাকশনে ব্যবহার করা যায়।

## AVX এবং তার পরের

AVX তুলনা, ব্লেন্ড আর `ptest`-কে চওড়া রেজিস্টারে `v`-প্রিফিক্সযুক্ত রূপ দেয়।

ভ্যারিয়েবল ব্লেন্ডের গড়ন বদলে যায়।
মাস্ক আর ইমপ্লিসিট `xmm0` নয়, বরং একটি স্পষ্ট চতুর্থ অপারেন্ড:

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

AVX-512 এক্সটেনশনগুলো মডেলটিকে আরও গভীরভাবে বদলে দেয়।

প্রথমত, এটি `zmm` নামের ৬৪-বাইট SIMD রেজিস্টারের একটি নতুন শ্রেণি যোগ করে।
এগুলো সংশ্লিষ্ট `ymm` রেজিস্টারকে বড় করে, ঠিক যেভাবে `ymm` রেজিস্টার `xmm` রেজিস্টারকে বড় করে।

দ্বিতীয়ত, এই এক্সটেনশনগুলো **অপমাস্ক রেজিস্টার**, `k0` থেকে `k7`, এর একটি সম্পূর্ণ নতুন শ্রেণিও তৈরি করে, যাদের মূল উদ্দেশ্য SIMD ইনস্ট্রাকশনের মাস্ক হিসেবে কাজ করা।
তুলনাগুলো আর ভেক্টরে লেখে না, বরং এই নতুন রেজিস্টারগুলোর একটিতে লেখে।
এগুলো `{k}` রাইট-মাস্ক হিসেবে অনেক ইনস্ট্রাকশনে সরাসরি প্রিডিকেট হিসেবেও ব্যবহার করা যায়, যা লেনগুলোকে _সরাসরি_ নির্বাচন করে:

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

সবশেষে, এই নতুন রেজিস্টারগুলোর উপর কাজ করার জন্য নতুন ইনস্ট্রাকশন আছে, যার মধ্যে এগুলোকে জেনেরেল-পারপাস রেজিস্টারে কপি করাও রয়েছে।
এতে `movmsk` ইনস্ট্রাকশন অপ্রয়োজনীয় হয়ে যায়, আর `zmm` রেজিস্টারে `movmsk` ইনস্ট্রাকশনের কোনো সাপোর্ট নেই।

এই এক্সটেনশনগুলো সম্পূর্ণতার জন্য উল্লেখ করা হলো।
এই ট্র্যাকের অনুশীলনীগুলো SSE রূপগুলো ব্যবহার করে।
