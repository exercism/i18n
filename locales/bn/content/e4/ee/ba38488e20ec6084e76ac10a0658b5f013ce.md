# পরিচিতি

## ক্যারেক্টার

একটি **ক্যারেক্টার এনকোডিং** হলো এমন একটি নির্দিষ্ট রীতি, যা দিয়ে কোনো স্বাভাবিক ভাষার টেক্সটের উপাদানকে বাইটের ধারাবাহিকতা হিসেবে প্রকাশ করা হয়। এখানে "টেক্সটের উপাদান" বলতে স্বাভাবিক ভাষায় অর্থবহ যেকোনো একককে বোঝায়, যেমন অক্ষর, স্পেস, যতিচিহ্ন, ইমোজি, আইডিওগ্রাম ইত্যাদি।

NASM (The Netwide Assembler, এই ট্র্যাকের অ্যাসেম্বলার) **ASCII** দিয়ে ডেটা ডিফাইন করার সুবিধা দেয়।

NASM-এ ক্যারেক্টার কনস্ট্যান্ট ৮ বাইট পর্যন্ত লম্বা হতে পারে এবং সিঙ্গেল কোট (`'`), ডাবল কোট (`"`) অথবা ব্যাকটিক (`` ` ``) দিয়ে ডিফাইন করা যায়:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

স্পেশাল ক্যারেক্টার ব্যাকটিকে ডিফাইন করতে হয় এবং `\` দিয়ে এস্কেপ করতে হয়:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

খেয়াল করুন, x86-64-এ আলাদা ডেটা টাইপ হিসেবে কোনো ক্যারেক্টার এনকোডিংয়ের বিল্ট-ইন সাপোর্ট নেই। অ্যাসেম্বলিতে ডেটা হলো বাইটের একটি ধারাবাহিকতা, আর সেই বাইটগুলোকে ক্যারেক্টার, সংখ্যা, কিংবা অন্য যেকোনো কিছু হিসেবে ব্যাখ্যা করা প্রোগ্রামারের উপরে ছেড়ে দেওয়া হয়।

উদাহরণস্বরূপ, ASCII ক্যারেক্টার '0' হলো 48 মানের একটি একক বাইট। তাই একটি বাইটে 48 রাখা আর ASCII ক্যারেক্টার '0' রাখা একেবারে একই ব্যাপার:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

একই কারণে, ক্যারেক্টার নিয়ে কাজ করা হয় ওই বাইটগুলোর মান সরাসরি রূপান্তর করে:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## স্ট্রিং

একটি **স্ট্রিং** হলো ক্যারেক্টারের একটি ধারাবাহিকতা। অ্যাসেম্বলিতে এটি সাধারণত একটি অ্যারে হিসেবে ইমপ্লিমেন্ট করা হয়।

যেকোনো অ্যারে যেমনভাবে ডিক্লেয়ার করা যায়, একইভাবে NASM-এ একটি স্ট্রিং ডিক্লেয়ার করা সম্ভব:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

স্ট্রিং আর অন্য অ্যারেগুলোর মধ্যে একটি পার্থক্য হলো, NASM-এ কমা (`,`) দিয়ে মান আলাদা না করেও স্ট্রিং ডিক্লেয়ার করার সুবিধাও আছে। আবার কমা দিয়ে মানগুলো মিশিয়েও লেখা যায়:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

খেয়াল করুন, আগেই বলা হয়েছে, ক্যারেক্টার আসলে নিছক বাইট (অথবা ইউনিকোড এনকোডিংয়ে বাইটের একটি ধারাবাহিকতা):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

যেহেতু প্রতিটি ASCII ক্যারেক্টার এক বাইট জায়গা নেয়, বড় সাইজে পরবর্তী যেকোনো বাইট হয় `0`। উদাহরণস্বরূপ, `'a'` কে কিউওয়ার্ড (৮ বাইট) হিসেবে ডিক্লেয়ার করলে প্রথম বাইটটি হয় `'a'` (`97`) আর বাকি সাতটি বাইটই হয় `0`।

একারণে, এগুলো সবই সমতুল্য:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
অ্যাসেম্বলিতে, স্ট্রিং স্বয়ংক্রিয়ভাবে একটি ASCII NUL ক্যারেক্টার (মান `0`) দিয়ে শেষ হয় না।

C-এর মতো হায়ার-লেভেল ভাষার সাথে কাজ করার সময়, স্ট্রিংয়ের শেষে সঠিক টার্মিনেটর (যদি থাকে) যোগ করা প্রোগ্রামারের দায়িত্ব।
~~~~

## স্ট্রিং ইনস্ট্রাকশন

যেহেতু স্ট্রিং আসলে অ্যারে, আপনি যেকোনো অ্যারের মতোই মেমোরি স্পষ্টভাবে ডিরেফারেন্স করে সেগুলো নিয়ে কাজ করতে পারেন:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

এর বাইরে, মেমোরিতে বাইটের ধারাবাহিকতায় মান লোড, মুভ আর স্টোর করার জন্য কিছু ইনস্ট্রাকশন আছে। যদিও এগুলোকে _স্ট্রিং ইনস্ট্রাকশন_ বলা হয়, মেমোরিতে বাইটের যেকোনো ধারাবাহিকতা, অর্থাৎ যেকোনো অ্যারে, দিয়ে এগুলো ব্যবহার করা যায়।

সবচেয়ে গুরুত্বপূর্ণ তিনটি স্ট্রিং ইনস্ট্রাকশন হলো `lods`, `stos` এবং `movs`:

| ইনস্ট্রাকশন | এটি কী করে |
| ----------- | ---------- |
| `lods` | `rsi`-এর নির্দেশ করা মেমোরি লোকেশন থেকে একটি মান `rax`-এ লোড করে |
| `stos` | `rax` থেকে একটি মান `rdi`-এর নির্দেশ করা মেমোরি লোকেশনে স্টোর করে |
| `movs` | `rsi`-এর নির্দেশ করা মেমোরি লোকেশন থেকে একটি মান কপি করে `rdi`-এর নির্দেশ করা মেমোরি লোকেশনে স্টোর করে |

খেয়াল করুন, এই ইনস্ট্রাকশনগুলো কোনো স্পষ্ট ওপারেন্ড নেয় _না_। এদের ওপারেন্ডগুলো ইমপ্লিসিট।

সাধারণ নিয়ম হিসেবে:

১. যখন এদের সোর্স ওপারেন্ড একটি মেমোরি লোকেশন হয়, তখন তার অ্যাড্রেস `rsi`-তে রাখা উচিত (`s` মানে source)।
২. যখন এদের ডেস্টিনেশন ওপারেন্ড একটি মেমোরি লোকেশন হয়, তখন তার অ্যাড্রেস বরং `rdi`-তে রাখা উচিত (`d` মানে destination)।
৩. যদি ওপারেন্ডগুলোর একটি মেমোরি লোকেশন না হয়, তবে সেটি `rax` রেজিস্টার।

খেয়াল করুন, এই ইনস্ট্রাকশনগুলো যে নির্দিষ্ট অপারেশন করে, তা অনুযায়ী মেমোরি অ্যাড্রেসগুলো স্বয়ংক্রিয়ভাবে ডিরেফারেন্স করে।

এগুলো সবই ভিন্ন ভিন্ন সাইজে কাজ করতে পারে। সেই সাইজ বোঝাতে একটি সাফিক্স যোগ করা হয়:

| সাফিক্স | অর্থ | সাইজ |
| :----: | ------- | :------ |
|  `b`   | বাইট    | ১ বাইট  |
|  `w`   | ওয়ার্ড   | ২ বাইট |
|  `d`   | ডিওয়ার্ড   | ৪ বাইট |
|  `q`   | কিউওয়ার্ড   | ৮ বাইট |

উদাহরণস্বরূপ:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

এরা ব্যবহৃত প্রতিটি অ্যাড্রেস অপারেশনের সাইজ অনুযায়ী আপডেট করে। এই আপডেটটি করা হয় **ডিরেকশন ফ্ল্যাগ (DF)**-এর মান অনুযায়ী:

- `DF` ক্লিয়ার থাকলে, অ্যাড্রেসগুলো অপারেশনের সাইজ পরিমাণ _বাড়ে_।
- `DF` সেট থাকলে, অ্যাড্রেসগুলো বরং একই পরিমাণে _কমে_।

System V ABI অনুযায়ী, ফাংশনে ঢোকার সময় ডিরেকশন ফ্ল্যাগ ক্লিয়ার থাকতে হবে। তাই _ডিফল্ট আচরণ হলো, মেমোরি অ্যাড্রেসের ঊর্ধ্বক্রমে পড়া/লেখা হবে_।

`cld` ইনস্ট্রাকশন দিয়ে ডিরেকশন ফ্ল্যাগ ক্লিয়ার করা যায়, আর `std` ইনস্ট্রাকশন দিয়ে সেট করা যায়:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
System V ABI অনুযায়ী, কল করা যেকোনো ফাংশন রিটার্ন করার পরে কলার আশা করে `DF` ক্লিয়ার থাকবে। আপনি যদি কখনো `DF` সেট করেন, তাহলে `ret`-এর আগে সেটি ক্লিয়ার করা নিশ্চিত করুন।
~~~~

### Rep

এগুলো ছাড়াও, **rep** ইনস্ট্রাকশন সরাসরি মেমোরির সাথে কাজ করে না। বরং, এটিকে উপরে উল্লিখিত অন্য ইনস্ট্রাকশনগুলোর আগে প্রিফিক্স হিসেবে যোগ করা যায়, যার ফলে ওই ইনস্ট্রাকশনগুলো _রিপিট_ হয়।

`rep` প্রিফিক্স হিসেবে বসালে, স্ট্রিং ইনস্ট্রাকশনগুলো `rcx`-এ থাকা মানের সমান সংখ্যকবার রিপিট হয়। প্রতিবার `rcx`-এর মান `1` করে কমে। খেয়াল করুন, ইনস্ট্রাকশনটি ব্যবহার করার আগে `rcx`-এর মান সেট করে নিতে হবে:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
আধুনিক CPU-তে বড় ব্লকে ডেটা মুভ করার সময় `rep movs` আর `rep stos` সাধারণত দ্রুত অপশন। তবে অন্য স্ট্রিং ইনস্ট্রাকশনগুলো, এমনকি `rep` ছাড়া চালানো `movs` আর `stos`-ও, সাধারণত একটি সাধারণ লুপের চেয়ে ধীর।
