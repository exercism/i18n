# বিট সম্পর্কে

বাইনারি ডিজিট শেষ পর্যন্ত সরাসরি আপনার CPU বা RAM-এর ট্রানজিস্টরগুলোর সাথে মিলে যায়, আর প্রতিটি ট্রানজিস্টর "চালু" না "বন্ধ" সেটিই। 

নিচু স্তরের ম্যানিপুলেশন, যাকে অনানুষ্ঠানিকভাবে "বিট-টুইডলিং" বলা হয়, সিস্টেম ভাষায় বিশেষভাবে গুরুত্বপূর্ণ।

Kotlin-এর মতো উচ্চস্তরের ভাষাগুলো সাধারণত এসব খুঁটিনাটির বেশিরভাগই আড়াল করে রাখে। তবে বিট-স্তরের কিছু মৌলিক অপারেশন [পাওয়া যায়][ref-bitwise]।

~~~~exercism/note
মানুষের পড়ার উপযোগী বাইনারি আউটপুট দেখতে হলে নিচের প্রায় সব উদাহরণকে [`Integer.toBinaryString()`][web-binstring] ফাংশন দিয়ে মুড়ে দিতে হবে, অথবা `toString(radix = 2)` দিয়ে রূপান্তর করতে হবে।

এটি দেখতে বিভ্রান্তিকর লাগে, তাই এই ফাংশনের বেশিরভাগ ব্যবহারই সরিয়ে দেওয়া হয়েছে, আর ফলাফলগুলো `0b` নোটেশন দিয়ে দেখানো হয়েছে।

[web-binstring]: https://www.baeldung.com/kotlin/int-binary-representation
~~~~

## বিট-শিফট অপারেশন

`Int` বা `Long` টাইপ, সাইনড হোক বা আনসাইনড, ১ ও ০-এর স্ট্রিং হিসেবে প্রকাশ করা যায় এবং বিটের ধারা হিসেবে ম্যানিপুলেট করা যায়।

সম্ভবত আশ্চর্যজনকভাবে, Kotlin-এ `Byte` বা `Short` টাইপ বেশিরভাগ বিটওয়াইজ অপারেশনের সাথে মানানসই নয়। নিচের সব উদাহরণে ৩২-বিট ইন্টিজার (`Int` বা `UInt`) ব্যবহার করা হয়েছে।

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

বিট-শিফট নির্দিষ্ট সংখ্যক অবস্থান বরাবর সবকিছুকে বামে বা ডানে সরিয়ে দেয়। কিছু বিট এক প্রান্ত দিয়ে ঝরে পড়ে, আর অন্য প্রান্ত শূন্য বা এক দিয়ে প্যাড করা হয়।

- `shl` দিয়ে বাম শিফট: শূন্য দিয়ে প্যাডিং।
- `shr` বা `ushr` দিয়ে ডান শিফট: ধনাত্মক সংখ্যার জন্য শূন্য দিয়ে প্যাডিং (ঋণাত্মক সংখ্যার জন্য পরের অংশ দেখুন)।

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

প্রতিটি বাম শিফট মানটিকে দ্বিগুণ করে, আর প্রতিটি ডান শিফট এটিকে অর্ধেক করে (ট্রাঙ্কেশনের সাপেক্ষে)। দশমিকে প্রকাশ করলে এটি আরও স্পষ্ট হয়:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

এমন বিট-শিফট "যথাযথ" গাণিতিক হিসাবের চেয়ে অনেক দ্রুত, তাই নিচু স্তরের কোডিংয়ে এই কৌশল খুব জনপ্রিয়।

### ঋণাত্মক ইন্টিজার বিট-শিফট করা

_ঋণাত্মক ইন্টিজার_-এর ক্ষেত্রে আমাদের একটু বেশি সতর্ক থাকতে হয়।

ঋণাত্মক মান [টু'জ কমপ্লিমেন্ট][wiki-2complement] আকারে সংরক্ষণ করা হয়, যার মানে বাঁদিকের সবচেয়ে বাইরের বিটটি ১। বাম শিফটে কোনো সমস্যা নেই, কিন্তু ডান শিফট করার সময় বাঁদিকের বিটগুলো কী দিয়ে প্যাড করব?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

[`shr`][ref-shr] অপারেটরটি [অ্যারিথমেটিক শিফট][wiki-arithmetic] করে, যা সাইন বিট অক্ষুণ্ণ রাখে।

[`ushr`][ref-ushr] অপারেটরটি [লজিক্যাল শিফট][wiki-logical] করে, সংখ্যাটি আনসাইনড হলে যেমন হয় তেমনভাবে শূন্য দিয়ে প্যাড করে।

## বিটওয়াইজ লজিক

[বুলিয়ান কনসেপ্টে][concept-booleans] আমরা দেখেছি যে `&&` (and), `||` (or) এবং `!` (not) অপারেটরগুলো বুলিয়ান মানের সাথে ব্যবহার করা হয়।

দুটি ইন্টিজারের বিট তুলনা করার জন্য সমতুল্য অপারেটর `and`, `or`, `xor` ([এক্সক্লুসিভ-অর][wiki-xor]) আছে, আর সব বিট উল্টে দেওয়ার জন্য একটি `inv` (ইনভার্সন) ফাংশন আছে।

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
