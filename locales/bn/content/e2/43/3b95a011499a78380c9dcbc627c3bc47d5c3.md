# Nil

Crystal-এ [`Nil`][nil] নামের একটি টাইপ আছে, যার একটিমাত্র মান থাকতে পারে: `nil`।
এটি কোনো মানের অনুপস্থিতি বোঝাতে ব্যবহৃত হয়, এবং অন্য ভাষার `null` বা `None`-এর মতোই।

nil মান বিভিন্ন মেথড থেকে রিটার্ন হতে পারে, যেমন [`String#[]?`][string-index], যা ইনডেক্স সীমার বাইরে থাকলে `nil` রিটার্ন করে।

```crystal
"foo"[10]? # => nil
```

Crystal-এ তথাকথিত **নাল রেফারেন্স চেক** আছে, যার অর্থ হলো সব টাইপ ডিফল্টভাবে নন-নিলেবল।
এর মানে হলো, কোনো ভ্যারিয়েবলকে স্পষ্টভাবে `Nil` টাইপ হিসেবে ডিক্লেয়ার না করলে আপনি তাতে `nil` অ্যাসাইন করতে পারবেন না।
এর ফলে কম্পাইলার স্বয়ংক্রিয়ভাবে নাল রেফারেন্স যাচাই করে।

## ফলসি মান

`nil` মান সামলাতে কিছু পদ্ধতি অবলম্বন করা যায়।
`nil` একটি [ফলসি][truthy-falsey] মান, আর `false`-ও তাই।
এর মানে হলো, যেসব স্টেটমেন্ট বা অন্য জায়গায় ফলসি বা ট্রুথি মান প্রত্যাশিত, সেখানে এটিকে `false`-এর মতোই ধরা হবে।

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

এর মানে হলো, কোনো নিলেবল ভ্যারিয়েবলের মান `nil` হলে ট্রুথি শাখাটি নেওয়া হবে না।

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## `nil` যাচাই করা

কোনো মান `nil` কি না তা যাচাই করতে Crystal-এ একটি মেথড আছে।
এর নাম [`nil?`][nil?], এবং এটি সব অবজেক্টেই পাওয়া যায়।

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

কেবল একটি `if` স্টেটমেন্টে মানটি ব্যবহার করার চেয়ে এটি একটু আলাদা, কারণ আগের উদাহরণগুলোতে false এবং nil দুটোকেই false হিসেবে ধরা হয়েছিল।
এখানে কেবল `nil`-ই ফলসি হিসেবে ধরা হয়, কারণ মানটি false হলে সেটি `nil` হতো না, ফলে সেটি ট্রুথি হতো।

## অর অপারেটর

`nil` মান সামলানোর সবচেয়ে সহজ উপায় হলো শুরুতেই নিশ্চিত করা যে সেগুলো কখনো `nil` হবে না।
অর অপারেটর ([`||`][or]) প্রায়ই `Bools` নিয়ে কাজ করার সময় ব্যবহৃত হয়, তবে সঠিকভাবে বুঝলে এটি `nil` মান সামলাতেও ব্যবহার করা যায়।
অর অপারেটর দেখে প্রথম মানটি ট্রুথি কি না; না হলে দ্বিতীয় মানটি ব্যবহৃত হয়।
এভাবে ব্যবহার করলে মানটি `nil` হলে সেটি ফলসি হবে এবং তাই দ্বিতীয় মানটি ব্যবহৃত হবে।

```crystal
"foo"[10]? || "bar" # => "bar"
```
