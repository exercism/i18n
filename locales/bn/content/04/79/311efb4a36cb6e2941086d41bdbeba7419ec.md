# পরিচিতি

## এরর ইন্টারফেস

Go-তে এরর হ্যান্ডলিং এক্সেপশনের মাধ্যমে করা হয় **না**।
বরং, এরর হলো এমন টাইপের সাধারণ _মান_, যেগুলো বিল্ট-ইন `error` ইন্টারফেসটি ইমপ্লিমেন্ট করে।
`error` ইন্টারফেসটি খুবই সরল।
এতে মাত্র একটি মেথড `Error()` থাকে, যেটি এরর মেসেজটি একটি স্ট্রিং হিসেবে রিটার্ন করে।

```go
type error interface {
  Error() string
}
```

আপনি যখনই এমন একটি ফাংশন ডিফাইন করেন, যেখানে এক্সিকিউশনের সময় একটি এরর ঘটতে পারে, যেটি কলারের কাছে পৌঁছানো দরকার, তখন রিটার্ন টাইপের একটি হিসেবে `error` অন্তর্ভুক্ত করতে হয়।
ফাংশনের একাধিক রিটার্ন ভ্যালু থাকলে, প্রথা অনুযায়ী `error` সবসময় শেষটি হয়।

```go
func DoSomething() (int, error) {
  // ...
}
```

## একটি সরল এরর তৈরি ও রিটার্ন করা

আপনাকে সবসময় নিজে থেকেই এরর ইন্টারফেসটি ইমপ্লিমেন্ট করতে হয় না।
একটি সরল এরর তৈরি করতে আপনি `errors.New()` ফাংশনটি ব্যবহার করতে পারেন, যেটি স্ট্যান্ডার্ড লাইব্রেরির `errors` প্যাকেজের অংশ।
এখানে শুধু একটি স্ট্রিং হিসেবে এরর মেসেজটি পাস করতে হয়, আর `errors.New()` আপনার মেসেজটি ধারণ করে এবং `error` ইন্টারফেসটি ইমপ্লিমেন্ট করে এমন একটি মান তৈরি করার কাজটি সামলে নেবে।

ফাংশন যদি একটি এরর রিটার্ন করে, তবে বাকি সব রিটার্ন প্যারামিটারের জন্য শূন্য মান রিটার্ন করা ভালো অভ্যাস:

```go
func DoSomething() (SomeStruct, int, error) {
  // ...
  return SomeStruct{}, 0, errors.New("failed to calculate result")
}
```

~~~~exercism/caution
কোনো এরর থাকলে সব ফাংশনই বাকি রিটার্ন ভ্যালুগুলোর জন্য শূন্য মান রিটার্ন করে, এমন ধরে নেওয়া আপনার উচিত নয়।
কোনো এরর ঘটলে অন্য রিটার্ন ভ্যালুগুলোর কোনোটিই ব্যবহার করা নিরাপদ নয়, এটাই ধরে নেওয়া সর্বোত্তম।
একমাত্র ব্যতিক্রম সেসব ক্ষেত্রে, যেখানে ডকুমেন্টেশন স্পষ্টভাবে বলে যে এরর হলেও অন্য রিটার্ন ভ্যালুগুলো অর্থবহ।
~~~~

এমন সরল এরর যদি আপনি একাধিক জায়গায় ব্যবহার করতে চান, তবে সরাসরি `errors.New` ব্যবহার না করে এররের জন্য একটি ভ্যারিয়েবল ডিক্লেয়ার করা উচিত।
প্রথা অনুযায়ী, ভ্যারিয়েবলের নাম `Err` বা `err` দিয়ে শুরু হওয়া উচিত (এটি এক্সপোর্টেড কি না, তার উপর নির্ভর করে)।
এই এরর ভ্যারিয়েবলগুলোকে প্রায়ই _সেন্টিনেল এরর_ বলা হয়।

```go
import "errors"

var ErrNotFound = errors.New("resource was not found")

func DoSomething() error {
  // ...
  return ErrNotFound
}
```

ফাংশন এক্সিকিউশনের সময় কোনো এরর হয়নি বোঝাতে এররের জন্য `nil` রিটার্ন করুন:

```go
func Foo() (int, error) {
  return 10, nil
}
```

## এরর চেকিং

আপনি যদি এমন কোনো ফাংশন কল করেন যেটি একটি এরর রিটার্ন করে, তবে এরর ভ্যালুটি `err` নামের একটি ভ্যারিয়েবলে রাখা কমন ব্যাপার।
ফাংশনের প্রকৃত ফলাফল ব্যবহার করার আগে আপনাকে যাচাই করতে হবে যে কোনো এরর হয়নি।

আপনার কোডের "হ্যাপি পাথ"-কে নেস্টেড হওয়া থেকে বাঁচাতে আগে এরর কেসগুলো সামলানো উচিত।
`nil`-এর সাথে এরর তুলনা করতে আমরা `==` আর `!=` ব্যবহার করতে পারি, আর `err` যদি `nil` না হয় তাহলে আমরা জানি যে একটি এরর হয়েছে।

```go
func processUserFile() error {
	file, err := os.Open("./users.csv")
	if err != nil {
		return err
	}

	// do something with file
}
```

বেশিরভাগ সময়েই উপরের উদাহরণে দেখানো মতো ফাংশন স্ট্যাকের উপরে এররটি রিটার্ন করা হয়।
এরর সামলানোর আরেকটি উপায় হতে পারে এটি লগ করে অন্য কোনো কাজ চালিয়ে যাওয়া।
এররটি হয় রিটার্ন করা, নয় লগ করা, দুটোই নয়, এটাই ভালো অভ্যাস।

Go-তে বেশিরভাগ ফাংশনই রিটার্ন ভ্যালুর একটি হিসেবে এরর রাখে, তাই Go কোডে আপনি সর্বত্র `if err != nil` প্যাটার্নটি দেখতে পাবেন/ব্যবহার করবেন।

## কাস্টম এরর টাইপ

শুধু এরর মেসেজ স্ট্রিংয়ের চেয়ে বেশি তথ্য যদি আপনার এররে থাকতে চান, তবে আপনি একটি কাস্টম এরর টাইপ তৈরি করতে পারেন।
আগেই বলা হয়েছে, Go-তে যা কিছু `error` ইন্টারফেসটি ইমপ্লিমেন্ট করে (অর্থাৎ যার একটি `Error() string` মেথড আছে) তা একটি এরর হিসেবে কাজ করতে পারে।

সাধারণত কাস্টম এরর টাইপ তৈরি করতে একটি স্ট্রাক্ট ব্যবহার করা হয়।
প্রথা অনুযায়ী, কাস্টম এরর টাইপের নাম `Error` দিয়ে শেষ হওয়া উচিত।
এছাড়া, `Error() string` মেথডটি পয়েন্টার রিসিভার দিয়ে সেট আপ করা সবচেয়ে ভালো, এর যুক্তি জানতে এই [Stackoverflow মন্তব্যটি][stackoverflow-errors] দেখুন।
মনে রাখবেন, এর মানে হলো আপনাকে আপনার কাস্টম এররের একটি পয়েন্টার রিটার্ন করতে হবে, নইলে এটি `error` হিসেবে গণ্য হবে না, কারণ নন-পয়েন্টার মানটি `Error() string` মেথডটি প্রদান করে না।

```go
type MyCustomError struct {
  message string
  details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.message, e.details)
}

func someFunction() error {
  // ...
  return &MyCustomError{
    message: "...",
    details: "...",
  }
}
```
