# মিউটেবিলিটি

মিউটেবিলিটি হলো Rust-এ একটি নির্দিষ্ট বাইন্ডিংয়ের একটি বৈশিষ্ট্য। একটি বাইন্ডিং হয় ইমিউটেবল, নয় মিউটেবল। একটি ইমিউটেবল বাইন্ডিংয়ের মান পরিবর্তন করা যায় না; একটি মিউটেবল বাইন্ডিংয়ের মান পরিবর্তন করা যায়। ডিফল্টভাবে সব বাইন্ডিংই ইমিউটেবল।

## বাইন্ডিং

বাইন্ডিং হলো সোর্স কোডে যে রূপে দেখা যাওয়া একটি নির্দিষ্ট ভ্যারিয়েবল নাম, আর এক্সিকিউশনের সময় যে রূপে দেখা যাওয়া মেমরির একটি নির্দিষ্ট অংশ, তার মধ্যে সংযোগ। কঠোরভাবে বলতে গেলে, বাইন্ডিং কেবল কম্পাইলের সময়ই থাকে: কম্পাইলের আগে আসলে কোনো মেমরি বরাদ্দই হয় না, আর কম্পাইলের পরে মেশিন কোড নামযুক্ত ভ্যারিয়েবলের বদলে শুধুই মেমরি অ্যাড্রেস নিয়ে কাজ করে।

সাধারণত `let` কিওয়ার্ড দিয়ে বাইন্ডিং তৈরি করা হয়। এছাড়া ফাংশন প্যারামিটার থেকেও এবং আরও কিছু নির্দিষ্ট পরিস্থিতিতে বাইন্ডিং তৈরি হয়।

বাইন্ডিংয়ের নানা রকম বৈশিষ্ট্য থাকতে পারে, যার মধ্যে সবচেয়ে গুরুত্বপূর্ণ হলো মিউটেবিলিটি। একটি মিউটেবল বাইন্ডিং এমন একটি বাইন্ডিং, যার সাথে বাঁধা মেমরির মান পরিবর্তন করা বৈধ। প্রোগ্রামগুলো যেন সঠিক হয় তা নিশ্চিত করতে Rust প্রতিটি বাইন্ডিংয়ের মিউটেবিলিটি কঠোরভাবে ট্র্যাক করে ও বলবৎ করে; যে প্রোগ্রাম ভুলবশত এমন একটি বাইন্ডিং বদলাতে চায় যা ইমিউটেবল হওয়া উচিত, তা প্রত্যাখ্যান করে।

## মিউটেবিলিটি

বাস্তবে মিউটেবিলিটি প্রায়ই সহজ। বাইন্ডিংয়ের সংজ্ঞায় `mut` কিওয়ার্ড ব্যবহার করলে আপনি মান পরিবর্তন করার ক্ষমতা পান।

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### মিউটেবল থেকে ইমিউটেবলে ডিমোট করা

একটি বাইন্ডিংকে সবসময়ই মিউটেবল থেকে ইমিউটেবলে ডিমোট করা যায়। এই কাজটি স্বচ্ছ।

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### ইমিউটেবল থেকে মিউটেবলে প্রোমোট করা

সাধারণভাবে, ওনারশিপ হস্তান্তরিত হলে যেকোনো সময়ই একটি মানকে ইমিউটেবল থেকে মিউটেবলে প্রোমোট করা সম্ভব।

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

`(1)`-এ স্ট্রিংয়ের ওনারশিপ `x` থেকে `y`-তে হস্তান্তরিত হয়, যার ফলে আমরা মানটিকে মিউটেবলে প্রোমোট করতে পারি।

### ফাংশন প্যারামিটারে মিউটেবিলিটি

ফাংশন প্যারামিটার মিউটেবল করার দুটি ভিন্ন উপায় আছে। প্রথম ও বেশি প্রচলিত উপায়টি C-তে রেফারেন্স দিয়ে পাস করার মতো:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

এই উদাহরণে তিনটি জায়গায় মিউটেবিলিটি স্পষ্টভাবে অ্যানোটেট করা হয়েছে। মিউটেবল রেফারেন্স কাজ করার জন্য তিনটি মিউটেবিলিটি ঘোষণাই প্রয়োজন।
`(2)`-এ বাইন্ডিং `x`-কে মিউটেবল হিসেবে ঘোষণা করা হয়েছে। এই বাইন্ডিংটি মানটির টপ-লেভেল ওনার।
`(3)`-এ ওই মানটি মিউটেবলভাবে বরো করা হয়, যাতে তা `increment` ফাংশনে পাস করা যায়।
`(1)`-এ প্রাসঙ্গিক রেফারেন্সের জন্য একটি নতুন, মিউটেবল বাইন্ডিং `n` তৈরি করা হয়।

প্যারামিটার মিউটেবিলিটির আরেকটি ধরন আছে, যা কম প্রচলিত কিন্তু মাঝেমধ্যে এখনও কাজে লাগে। এই ধরনে মানটির ওনারশিপ থাকে, তবে বাইন্ডিংটি মিউটেবল।

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

এই উদাহরণে কম স্পষ্ট অ্যানোটেশনের দরকার হয়, কারণ এটি আসলে ওনারশিপ হস্তান্তরের সাথে বিল্ট-ইন মিউটেবিলিটি প্রোমোশন। এটি কাজ করে কারণ `i32` একটি `Copy` টাইপ, যা ডেটা স্বচ্ছভাবে কপি করে।
`(1)`-এ আমরা ঘোষণা করি যে `increment_internally` তার প্যারামিটার হিসেবে `n` নামের একটি মিউটেবল ওন করা `i32` গ্রহণ করে।
`(2)`-এ আমরা `x`-কে মান `1`-এর একটি ইমিউটেবল বাইন্ডিং হিসেবে ঘোষণা করি।
`(3)`-এ `x` মেমরির একটি নতুন অবস্থানে কপি হয়। `x` ইমিউটেবলই থাকে। `n` মিউটেবল।

অবশ্যই এই ধরনগুলো একসাথে মেলানো সম্ভব, অর্থাৎ একটি মিউটেবল রেফারেন্সের জন্য একটি মিউটেবল বাইন্ডিং দেওয়া (`mut n: &mut i32` ইত্যাদি), তবে আসলে এটাই খুব কম ক্ষেত্রে কাঙ্ক্ষিত হয়।

### `let` ছাড়া মিউটেবিলিটি

Rust-এর বেশ কিছু কনস্ট্রাকশন (`if let`, `match` ইত্যাদি) বাইন্ডিংও তৈরি করতে পারে। এই বাইন্ডিংগুলোও মিউটেবল হতে পারে।

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

এই উদাহরণটি প্রথমে `v = Some(2)` এবং পরে `v = None` দেয়।

## শ্যাডোয়িং

কোনো নির্দিষ্ট মান রূপান্তরিত হওয়ার সময় একাধিক `let` দিয়ে সেটি আবার ঘোষণা করে একই ভ্যারিয়েবল নাম পুনরায় ব্যবহার করা সম্ভব, আর প্রায়ই এটাই স্বাভাবিক রীতি। একে শ্যাডোয়িং বলা হয়।

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

তবে এটি মিউটেবিলিটির উদাহরণ নয়; মূল মানগুলো নীতিগতভাবে তখনও উপস্থিত থাকে। `Drop` ছাড়া টাইপের ক্ষেত্রে কম্পাইলার নতুন একটি মেমরি বরাদ্দ করার বদলে একটি মেমরি লোকেশন মিউটেট করা বেছে নিতে পারে। তবে `Drop` টাইপের ক্ষেত্রে বা পুরোনো বাইন্ডিং আবার ব্যবহৃত হলে এটি কখনোই তা করবে না।

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
