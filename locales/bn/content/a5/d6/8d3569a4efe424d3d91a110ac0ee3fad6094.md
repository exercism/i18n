# পরিচিতি

সিকোয়েন্সের যে শব্দগুলো আপনি এতক্ষণ দেখেছেন, সেগুলোর বেশিরভাগই *নতুন* সিকোয়েন্স রিটার্ন করে আর ইনপুট অপরিবর্তিত রাখে: `suffix`, `reverse`, `map` ইত্যাদি। কিন্তু অ্যারে ও ভেক্টর **ইন-প্লেস মিউটেশন**ও সমর্থন করে, আর সময়ের সাথে বদলে যায় এমন স্টেট সংরক্ষণ করতে চাইলে দুটোরই দরকার পড়ে।

## পরিবর্তনযোগ্য সিকোয়েন্সের দুই রকম

- **অ্যারে** (`{ … }`) এর দৈর্ঘ্য নির্দিষ্ট। `<array> ( n elt -- array )` ([`arrays`][arrays]-এ) `n` দৈর্ঘ্যের একটি নতুন অ্যারে তৈরি করে, যা `elt`-এর কপি দিয়ে ভরা থাকে।
- **ভেক্টর** (`V{ … }`) বড়-ছোট হয়। নতুন একটি খালি ভেক্টরের জন্য `V{ } clone` ব্যবহার করুন; `<vector> ( n -- vector )` ([`vectors`][vectors]-এ) `n` এলিমেন্টের জন্য ক্যাপাসিটির জায়গা আগেই বরাদ্দ করে।

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## স্লট পরিবর্তন করা

এই দুটি যেকোনো ধরনের সিকোয়েন্সেই কাজ করে, আর দুটোই ইনডেক্সের পরে সিকোয়েন্সটি আশা করে:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth` অ্যাসাইন করে; `change-nth` অবস্থান `n`-এর এলিমেন্টে একটি কোয়োটেশন প্রয়োগ করে। [`sequences`][sequences]-এর এই দুটি শব্দই স্ট্যাকে কিছু রিটার্ন করে না, এই মিউটেশনটাই এখানে ফলাফল।

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## বড় হওয়া ও ছোট হওয়া

এই তিনটি কেবল ভেক্টরেই অর্থবহ, কারণ অ্যারে দৈর্ঘ্য বদলাতে পারে না:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## ভেক্টর → অ্যারে

একটি ভেক্টর তৈরি করে শেষে নির্দিষ্ট দৈর্ঘ্যের একটি অ্যারে ফিরিয়ে দিতে চাইলে, `>array ( seq -- array )` ([`arrays`][arrays]-এ) একই এলিমেন্টযুক্ত একটি নতুন অ্যারে রিটার্ন করে:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`: একটি স্ন্যাপশট রেখে দিন

মিউটেশন সিকোয়েন্সটি জায়গাতেই বদলে দেয়। কোনো কলার আপনাকে একটি সিকোয়েন্স দেন আর আপনি সেটি বদলাতে যাচ্ছেন, এমন সময় `clone` ([`kernel`][kernel]-এ) আপনাকে একটি নতুন, স্বাধীন কপি দেয়, যাতে কলারের দেখা জিনিসটি তার অগোচরে বদলে না যায়:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

একই সতর্কতা `V{ }` ও অন্যান্য খালি লিটারেলের ক্ষেত্রেও খাটে। কিছু ভাষায় `[]` বা `vec![]` এক্সপ্রেশনটি মূল্যায়নের প্রতিবার নতুন একটি কনটেইনার বরাদ্দ করে। Factor-এ, আপনার সোর্সে লেখা `V{ }` লিটারেলটি *একটি* অবজেক্ট, যেটি এটি উল্লেখ করা প্রতিটি কল সাইটে ভাগ করা থাকে। আপনি যদি সরাসরি `V{ }`-এর উপর `push` করেন, পরের কলটি আগের অবশিষ্টাংশ দেখতে পায়। `V{ } clone` আপনার প্রায় সর্বদা দরকারি সেই নতুন কপিটি তৈরি করে।
