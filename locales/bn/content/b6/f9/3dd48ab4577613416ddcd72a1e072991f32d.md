# সম্পর্কে

সিলেবাসের এই পর্যায়ে এসে আপনি R-কে প্রায়শই ইম্পেরেটিভ ভাষা হিসেবে ব্যবহৃত হতে দেখেছেন, এবং ক্রমশ ফাংশনাল ভাষা হিসেবেও (বিশেষ করে [`purrr`][ref-purrr] এবং [`dplyr`][ref-dplyr] লাইব্রেরি দিয়ে)।

এখন R মূলত অবজেক্ট-ওরিয়েন্টেড, এমন দাবি করলে কিছুটা সন্দেহ প্রকাশ হতে পারে!

অদ্ভুতভাবে, এটি একটি সত্য বিবৃতি। অভ্যন্তরীণভাবে, R ক্লাস, ইনহেরিটেন্স, পলিমরফিজম এবং OOP প্রোগ্রামারদের বৈশিষ্ট্যপূর্ণ মনোভাব ব্যবহার করে বাস্তবায়িত।

তবে, Java বা Ruby (স্পষ্টভাবে OOP) এমনকি Python (কিছু দিক থেকে আধা-গোপনভাবে OOP) যাদের চেনা, তাদের কাছে R-এর পদ্ধতিটি ... _অপরিচিত_ লাগবে।

শুরুতেই বলি, এখানে একাধিক ক্লাস ডিজাইন আছে: সম্ভবত তিনটি বহুল ব্যবহৃত (S3, S4, R6), আরও কিছু যা প্রধানত তাত্ত্বিক আগ্রহের।

বিস্তারিত আলোচনা [Advanced R, 2e][book-advanced-r]-এর ১২-১৬ অধ্যায়ে পাওয়া যাবে। এই ২০১৯ সালের বইটি মূলত তাদের জন্য, যারা R-এর অভ্যন্তরীণ বিষয় বুঝতে ও রক্ষণাবেক্ষণ করতে চান, তাই OOP অপরিহার্য।

আরও ব্যবহারকারী-কেন্দ্রিক পাঠ্যবই ভিন্ন ভিন্ন।

- The Art of R Programming (২০১১, শুধুমাত্র মুদ্রিত संस्कরণ)-এ একটি OOP অধ্যায় আছে, যা S3 এবং (আরও সংক্ষেপে) S4 নিয়ে আলোচনা করে, যা সেই সময় গুরুত্বপূর্ণ ছিল। _"S3 ক্লাসগুলোর গঠন বরং জোড়াতালি দিয়ে সাজানো"_ এই মন্তব্যটি এখনও চোখে পড়ার মতো সত্য।
- R in Action (৩য় সংস্করণ, ২০২২) OOP-কে শেষ দিকে অ্যাডভান্সড প্রোগ্রামিং-এর একটি অধ্যায়ে মাত্র ৩ পৃষ্ঠায় সীমাবদ্ধ রেখেছে।
- [R for Data Science, 2e][book-r-data-sci] (২০২৩, মুদ্রিত সংস্করণে ৫৪৮ পৃষ্ঠা) OOP-এর কোনো উল্লেখই করে না।

এই কনসেপ্টটি S3 ক্লাসের উপর মনোযোগ দেবে, যেগুলো সবচেয়ে সহজ, সবচেয়ে কমন এবং Exercism-ধরনের সমস্যার জন্য সবচেয়ে প্রাসঙ্গিক। R ট্র্যাকের কিছু প্র্যাকটিস অনুশীলনীতে আপনাকে একটি S3 ক্লাস তৈরি করতে হয়, আবার কিছুতে এটি ঐচ্ছিক কিন্তু আলতোভাবে উৎসাহিত করা হয়।

## S3 ক্লাস

এগুলো পুরনো: S3 নামটির অর্থ শুধু এই যে এগুলো S ভাষার (R-এর একটি বাণিজ্যিক পূর্বসূরি) সংস্করণ ৩-এ চালু হয়েছিল।

একটি S3 ক্লাসও খুব সহজ: সাধারণত একটি [অ্যারে][concept-lists] যার অন্তত একটি অতিরিক্ত অ্যাট্রিবিউট থাকে।

[Advanced R][book-s3] থেকে উদ্ধৃতি: _"S3 অনানুষ্ঠানিক ও অ্যাড হক, কিন্তু এর মিনিমালিজমে এক ধরনের সৌন্দর্য আছে: এর কোনো অংশ সরিয়ে দিলে আপনি আর কাজে লাগার মতো OO সিস্টেম পাবেন না।"_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

তাই [`class(obj)`][ref-class]-এ একটি অ্যাসাইনমেন্ট করলে `obj`-এ কেবল একটি অ্যাট্রিবিউট যোগ হয়, এখানে যা pt2d-কে point2d ক্লাসের একটি ইনস্ট্যান্স হিসেবে চিহ্নিত করে।

তৈরি করার ধাপগুলো [`structure()`][ref-structure]-এর সাথে একসাথে করা যায়:

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

যদিও ফলাফল হিসেবে পাওয়া ইনস্ট্যান্সগুলো ধারণাগতভাবে অভিন্ন, R-কে এটি নিশ্চিত করার কোনো উপায় আমরা এখনও বাস্তবায়ন করিনি।

### জেনেরিক মেথড

অন্য ভাষায় OOP-এর সাথে পরিচিত কেউ ভাবতে পারেন: _"ক্লাসের তো কিছু করার ক্ষমতা থাকার কথা, তাই না?"_

আমরা `point2d` ইনস্ট্যান্সের জন্য উপলব্ধ মেথডগুলো পরীক্ষা করতে পারি, এবং দেখতে পাব যে (অন্তর্নিহিত `list`-এর বিপরীতে) বর্তমানে কোনোটিই নেই।

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

বেশিরভাগ OOP ভাষায় মেথড ক্লাস ডেফিনিশনের ভেতরেই ডিফাইন করা হয়। অল্প কিছু ভাষা (বিশেষত Ruby) পরে ক্লাস মেথড যোগ ও পরিবর্তন করার সুযোগ দেয়।

S3 ক্লাস অনেক আলাদা। ক্লাসে মেথড যোগ করার বদলে আমরা জেনেরিক মেথডে ক্লাসটি যোগ করি।

R কনসোলে ইন্টারঅ্যাকটিভভাবে কাজ করা যে কেউ সব সময় জেনেরিক মেথড ব্যবহার করেন, সাধারণত সেগুলো কীভাবে বাস্তবায়িত হয়েছে তা না ভেবেই।

একটি খুব কমন উদাহরণ হলো `print()`, যদিও আপনি খুব কমই ফাংশনের নাম টাইপ করেন। কনসোল প্রম্পটে শুধু একটি মান `x` লিখলে তা `print(x)`-এর জন্যই সিনট্যাকটিক শুগার।

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

আমরা ইতিমধ্যেই `pt2d` প্রিন্ট করতে পারি। যদিও `print()` `point2d` ক্লাস সম্পর্কে কিছুই জানে না, তবে বিভিন্ন ধরনের অবজেক্ট সামলানোর জন্য এর বুদ্ধিমান ডিফল্ট আছে।

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

এটি বেশ ভারবোস, এবং আমরা হয়তো বিন্দুটি সংক্ষেপে সুন্দরভাবে প্রিন্ট করার একটি উপায় চাইব।

সহজ: শুধু `print.point2d()` নামের একটি ফাংশন যোগ করুন। নামটি `methodname.classname` আকারে হতে হবে, যাতে ডিসপ্যাচার জানে কী খুঁজতে হবে।

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

এখন ধরা যাক আমরা একটি নতুন জেনেরিক মেথড তৈরি করতে চাই, যেমন `y` কোঅর্ডিনেটের চিহ্ন উল্টাতে `flipvert()`।

আবারও সহজ:

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

এটি একটি ডিসপ্যাচার তৈরি করে, যেখানে `x` হলো S3 ক্লাসযুক্ত আমাদের অবজেক্ট, আর `...` মেথড ডেফিনিশনের প্রয়োজন হতে পারে এমন যেকোনো অতিরিক্ত আর্গুমেন্ট সামলায় ("ডট আর্গস", যেমনটি [ফাংশন কনসেপ্ট][concept-functions]-এ বর্ণনা করা হয়েছে)।

এরপর আমরা `point2d`-এর জন্য মেথডটি ডিফাইন করে ব্যবহার করতে পারি।

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

R এখন জানে আমাদের বিন্দুটি কীভাবে ফ্লিপ করতে হয় এবং ফলাফল কীভাবে দেখাতে হয়।

আমরা 3D, পোলার কোঅর্ডিনেট ইত্যাদির জন্য ক্লাস তৈরি করে এবং প্রতিটির জন্য মেথড ডিফাইন করে এটিকে বাড়িয়ে তুলতে পারি।

ব্যবহারকারীর দৃষ্টিকোণ থেকে কেবল `flipvert(x, ...)` আছে, আর আমরা R-এর উপর নির্ভর করতে পারি যে এটি ইনপুট ক্লাস নির্ধারণ করে উপযুক্ত অন্তর্নিহিত বাস্তবায়ন ব্যবহার করবে।

~~~~exercism/caution
`verb.class` আকারের ফাংশন নাম ব্যবহারকারী এবং R পার্সার উভয়ের কাছেই S3 মেথডের মতো দেখায়। অন্য প্রসঙ্গে একই ধরনের নামকরণ এড়িয়ে চলুন।

স্বীকার করতেই হয়, বেস R মাঝে মাঝে এই নিয়ম ভাঙে। আমাদের এটিকে একটি দুর্ভাগ্যজনক ঐতিহাসিক দুর্ঘটনা হিসেবে দেখা উচিত (S3-এর চেয়েও পুরনো ফাংশনগুলোর ক্ষেত্রে), যা ব্যাকওয়ার্ড কম্প্যাটিবিলিটির জন্য সংরক্ষণ করতে হবে।

### ইনহেরিটেন্স

OOP উৎসাহীরা ইনহেরিটেন্স, সাবক্লাসিং, মিক্সিন এবং আরও অনেক কিছু নিয়ে একাধিক দীর্ঘ পাঠ্যবই অধ্যায় লিখতে পারেন।

R কেবল `class` অ্যাট্রিবিউটে একাধিক নাম দিতে দেয়: একটি একক স্ট্রিংয়ের বদলে স্ট্রিংয়ের একটি দীর্ঘতর ভেক্টর।

উদাহরণটিকে ভেঙে পড়ার মতো প্রসারিত করার ঝুঁকি নিয়েই ধরা যাক, আমরা একটি জেনেরিক `point` ক্লাস বানিয়েছি এবং এটিকে `point2d`, `point3d` ইত্যাদিতে সাবক্লাস করতে চাই।

তখন `point2d` ডেফিনিশনে কেবল `class = c("point2d", "point")` ব্যবহার করা হয়: নির্দিষ্ট ক্লাস এবং প্যারেন্ট ক্লাস (বা ক্লাসগুলো)।

`print()`-এর মতো জেনেরিক মেথড তখন ক্রমান্বয়ে `print.point2d()`, `print.point()` এবং (সম্ভবত) `print.default()` খুঁজবে, এবং ডিসপ্যাচার যে বাস্তবায়নটি প্রথমে পায় সেটিই ব্যবহার করবে।

### নিরাপত্তা

অনেক OOP ভাষা (Java, C# ইত্যাদি) ক্লাসের ভেতরে ডেটা এনক্যাপসুলেশনের সুবিধা নিয়ে সতর্ক কম্পাইল-টাইম চেক করে এবং টাইপ নিরাপত্তা নিশ্চিত করে।

মনে রাখবেন, S3 আপনাকে প্রায় যা খুশি করতে দেয়, এমনকি যদি তা অর্থহীন হয় (কোনো এরর বার্তা এলে সেটি পরে আসে, যদি আদৌ আসে)।

["Advanced R"][book-s3] (২য় সংস্করণ, সেকশন ১৩.৩) থেকে উদ্ধৃতি:

> _আপনি যদি অন্য OO ভাষা ব্যবহার করে থাকেন, এতে আপনার অস্বস্তি হতে পারে, কিন্তু বাস্তবে এই নমনীয়তা খুব কম সমস্যা করে। R আপনাকে নিজের পায়ে গুলি করতে বাধা দেয় না, কিন্তু যতক্ষণ আপনি বন্দুকটি আপনার পায়ের আঙুলে তাক করে ট্রিগার না টানেন, ততক্ষণ আপনার কোনো সমস্যা হবে না।_

আচ্ছা, _ঠিক আছে?_ R এক্সপ্লোরেটরি ডেটা সায়েন্স এবং পরিসংখ্যানের জন্য দুর্দান্ত, বিশেষ করে যখন ইন্টারঅ্যাকটিভভাবে কাজ করা হয়। কেউ বলছে না যে আপনি এটি দিয়ে উচ্চ-নিরাপত্তাসম্পন্ন কর্পোরেট ফিন্যান্স সিস্টেম লিখবেন!
