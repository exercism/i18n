# কমেন্ট নিয়ে অংশ

কমেন্ট কীভাবে লিখবেন তা নিয়ে Go-এর [দুর্দান্ত কিছু নির্দেশিকা](https://golang.org/doc/effective_go.html) আছে। ডকুমেন্টেশন কমেন্টের জন্য একটি স্ট্যান্ডার্ড ফরম্যাট ব্যবহার করতে পারেন, যা পরে `godoc` টুল স্বয়ংক্রিয়ভাবে সুন্দর ডকুমেন্টেশনে রূপান্তর করে দিতে পারে।

প্যাকেজ কমেন্ট শুরু হওয়া উচিত `Package` শব্দটি দিয়ে, তারপর প্যাকেজের নাম, এভাবে:

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

এক্সপোর্ট করা ফাংশন, মেথড, কনস্ট্যান্ট এবং প্যাকেজ ভ্যারিয়েবলের ক্ষেত্রে কমেন্ট শুরু হওয়া উচিত নামটি দিয়ে, আর এরপর চলবে একটি ভার্ব ফ্রেজ:

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

[CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences) উইকিতে আরও বলা হয়েছে যে ডক কমেন্ট হবে পূর্ণ বাক্য, যার শেষে থাকবে একটি ফুল স্টপ।

পাঠযোগ্যতার দিকে খেয়াল রাখার পাশাপাশি, এই সুপারিশগুলো মেনে চললে [Go-এর ডকুমেন্টেশন টুলগুলোতে](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/), যেমন [godoc.org](http://godoc.org), `godoc`, আর `go doc`, আপনার কোড আরও ভালো দেখায়।

অফিসিয়াল স্টাইল গাইড [Effective Go](https://golang.org/doc/effective_go.html)-তে ডক কমেন্ট নিয়ে অংশটি পড়তে একটু সময় দিন, যাতে এই সিদ্ধান্তগুলোর পেছনের যুক্তিটা বুঝতে পারেন।
