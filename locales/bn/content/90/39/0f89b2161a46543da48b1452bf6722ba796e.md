# Unison-এর বেসিক

## টার্ম ও ফাংশন

Unison প্রোগ্রাম লেখার মূল এককগুলো হলো টার্ম ও ফাংশন।

"টার্ম" বলতে আমরা স্ট্যাটিক মান বুঝি। এটি `name = expression` দিয়ে ডিফাইন করা হয়, আর চাইলে তার আগে `name : MyType` ফরম্যাটে একটি টাইপ সিগনেচার বসানো যায়। Unison টাইপ ইনফারেন্স সমর্থন করে, তাই সাধারণ ডেফিনিশনে টাইপ সিগনেচার বাদ দেওয়া হতে দেখতে পারেন।

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison ফাংশন দেখতে হয় `myFunctionName argument1 argument2 = myImplementation`-এর মতো; এগুলো শুরু হয় ফাংশনের নাম দিয়ে, তারপর আসে স্পেস দিয়ে আলাদা করা আর্গুমেন্ট।

```
getMax a b = Nat.max a b
```

ফাংশনে চাইলে একটি টাইপ সিগনেচারও থাকতে পারে। ডান দিকের শেষ টাইপটি সবসময় ফাংশনের চূড়ান্ত রিটার্ন টাইপ, আর প্রতিটি আর্গুমেন্ট আলাদা করা হয় ফাংশন অ্যারো `->` দিয়ে।

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

কোনো ফাংশন কল করতে তার নাম লিখুন, তারপর শুধু স্পেস দিয়ে আলাদা করা আর্গুমেন্ট।

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

ফাংশন কল করার সময় Unison ঠিক ডান পাশে যা-ই থাকে, সেটিকেই তার আর্গুমেন্ট হিসেবে ধরার চেষ্টা করে; এতে ফাংশন মূল্যায়নের কাঙ্ক্ষিত ক্রম সবসময় তৈরি নাও হতে পারে।

ধরা যাক, নিচের এক্সপ্রেশন থেকে আমরা `1` মানটি পেতে চাই

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

যেমনটা লেখা আছে, `shouldBe1`-এর মান দাঁড়ায় `0`, কারণ এখানে ফাংশন প্রয়োগের যে ক্রম ধরে নেওয়া হয় তা হলো `getMax 1 10`, যার মান `10`, আর তারপর `10 - 10`, যার মান `0`।

কাঙ্ক্ষিত ক্রমে অপারেশন সাজাতে বন্ধনী দিয়ে এক্সপ্রেশনটি আবার সাজিয়ে নিতে পারেন।

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## ওয়াচ এক্সপ্রেশন

কোড দ্রুত মূল্যায়ন করার একটি উপায় Unison দেয়, যার নাম "ওয়াচ এক্সপ্রেশন"। একটি ওয়াচ এক্সপ্রেশন শুরু হয় `>` চিহ্ন দিয়ে, তারপর থাকে যে এক্সপ্রেশনটি মূল্যায়ন করতে হবে সেটি। যেকোনো `.u` এক্সটেনশনের ফাইলে ওয়াচ এক্সপ্রেশন লেখা যায়। ফাইলটি সেভ করলেই Unison Codebase Manager (UCM) কনসোলে এক্সপ্রেশনটির মান কী দাঁড়ায় তা দেখতে পাবেন। এই ডকুমেন্টে যেখানে সম্ভব, আমরা একটি ওয়াচ এক্সপ্রেশনে এক্সপ্রেশন মূল্যায়ন করে তার প্রত্যাশিত আউটপুট দেখানোর চেষ্টা করব।

```
> helloThere
  ⧩
  "Hello, World!"
```

## মাল্টি-লাইন ফাংশন

Unison-এর মাল্টি-লাইন ফাংশন ইনডেন্টেশন বা `let` ব্লক ব্যবহার করে কোডের সীমানা ঠিক করে, যাকে "লেক্সিক্যাল স্কোপ"-ও বলা হয়।

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

একই ইনডেন্টেশন স্তরে থাকা সবকিছু একই স্কোপ শেয়ার করে; সে কারণেই শেষ লাইনে `newBeginning` ভ্যারিয়েবলটি রেফারেন্স করতে পারি।

## নেমস্পেস ও `use` স্টেটমেন্ট

নেমস্পেস দিয়ে আমরা Unison ফাংশনগুলো দলবদ্ধ করি ও সাজিয়ে রাখি। এগুলোকে "ডিরেক্টরি"-র মতো ভাবতে পারেন। এগুলো কাঠামো ও যৌক্তিক বিন্যাস দেয়।

`use` স্টেটমেন্ট দিয়ে কোনো নেমস্পেসের ফাংশনগুলো স্কোপে নিয়ে আসতে পারেন।

ধরা যাক, আপনি এমন একটি ফাংশন লিখছেন যেখানে Unison-এর `List` মান ব্যবহার হবে। আপনি জানেন আপনার `List.map` আর `List.flatMap`-এর মতো ফাংশন দরকার, যেখানে `List` হলো নেমস্পেস আর `map` ও `flatMap` হলো ফাংশন। নিজেকে বারবার না লিখতে আপনার ফাংশনে `List` নেমস্পেসের সবকিছু লেক্সিক্যাল স্কোপে নিয়ে আসতে পারেন, এভাবে:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List` লাইনটি `map` আর `flatMap`-এর রেফারেন্সগুলো স্পষ্ট করে দেয়। [`use` স্টেটমেন্ট সম্পর্কে আরও পড়তে পারেন এখানে][use-statements]।

## Unison-এর স্ট্যান্ডার্ড লাইব্রেরি

Unison-এর স্ট্যান্ডার্ড লাইব্রেরির নাম `base`। আপনি যদি কুইকস্টার্ট গাইড অনুসরণ করে স্থানীয়ভাবে একটি কোডবেস তৈরি করে থাকেন, তাহলে স্ট্যান্ডার্ড লাইব্রেরি স্বয়ংক্রিয়ভাবে ডাউনলোড হয়ে যাওয়ার কথা। [Unison Share][unison-share-base] সাইটে স্ট্যান্ডার্ড লাইব্রেরির ডকুমেন্টেশন অনলাইনে দেখতে পারেন।

## কমেন্ট ও ডকুমেন্টেশন লিটারেল

Unison-এ কমেন্ট একটু অদ্ভুত ব্যাপার। Unison কোড লেখার সময় `.u` এক্সটেনশনের ফাইলে নিচের সিনট্যাক্স দিয়ে এমন টেক্সট তৈরি করতে পারেন যা ইন্টারপ্রেট করা হয় না:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_তবে_, যেহেতু Unison কোড ফাইল সিস্টেমে টেক্সট-ভিত্তিক ফাইল হিসেবে নয়, বরং তার অ্যাবস্ট্রাক্ট সিনট্যাক্স ট্রির হ্যাশ হিসেবে সেভ হয়, তাই ফাইলে কোনো Unison ফাংশন বা টার্মের টেক্সট-ভিত্তিক "সাজসজ্জা" হিসেবে থাকা কমেন্ট সত্যিই সেভ করে রাখা যায় না, শেয়ার করার জন্য আবার রেন্ডারও করা যায় না। আপনি যদি আপনার Unison টার্মে এমনভাবে তথ্য যোগ করতে চান যা থেকে যাবে, যাতে অন্যরা পড়ে বুঝতে পারে, তাহলে একটি ডকুমেন্টেশন লিটারেল ব্যবহার করতে পারেন।

Unison প্রোগ্রামিং ভাষায় ডকুমেন্টেশন একটি ফার্স্ট-ক্লাস মান। এর মানে হলো একটি `Doc` এলিমেন্ট কোনো মানে অ্যাসাইন করা যায়, ফাংশনে মান হিসেবে পাস করা যায়, বা ফাংশনের মান হিসেবে রিটার্ন করা যায়। ডকুমেন্টেশন লিটারেল এলিমেন্ট খোলা ও বন্ধ হয় জোড়া কোঁকড়া বন্ধনী দিয়ে। কমেন্ট হিসেবে `Doc` এলিমেন্ট আমরা এভাবে ব্যবহার করতে পারি।

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
