# ভূমিকা

`Complex numbers` আসলে জটিল কিছু নয়।
এর নামটা শুধু একটু কম ভয়ংকর হলেই ভালো হয়।

এগুলো এতটাই কাজের, বিশেষ করে ইঞ্জিনিয়ারিং আর বিজ্ঞানে, যে R-এ ইন্টিজার, ডাবল, লজিক্যাল, ক্যারেক্টার আর raw-এর পাশাপাশি স্ট্যান্ডার্ড [অ্যাটমিক টাইপ][ref-atomic] হিসেবে [কমপ্লেক্স সংখ্যা][web-complex]ও রয়েছে।

## মূল বিষয়

R-এ একটি `complex` সংখ্যা হলো একটি একক মান।
তবে ব্যবহারের সময় এটিকে এক জোড়া সংখ্যা হিসেবে ভাবা যায়।
দুঃখজনক ঐতিহাসিক কারণে এদের "বাস্তব" আর "কাল্পনিক" অংশ বলা হয়।
আবারও বলি, অদ্ভুত এই নামগুলো নয়, বরং এর ভেতরের সরলতাটাই মাথায় রাখাই ভালো।

দুটি বাস্তব সংখ্যা থেকে কমপ্লেক্স সংখ্যা বানাতে কাল্পনিক অংশের শেষে শুধু `i` যোগ করলেই হয়।

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

বাস্তব ভ্যারিয়েবল থেকে কমপ্লেক্স সংখ্যা বানাতে উপরের সিনট্যাক্স কাজ করবে না।
`r + imi` লিখলে পার্সার বিভ্রান্ত হয়ে `imi`-কে একটি (অস্তিত্বহীন) ভ্যারিয়েবলের নাম ভেবে ফেলে।

হয় কাল্পনিক অংশটিকে `1i` দিয়ে গুণ করুন, নয়তো [`complex()`][ref-complex] ফাংশনটি ব্যবহার করুন:

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

আপনার মনে হতে পারে, `j` নয় কেন `i`?

বেশিরভাগ ইঞ্জিনিয়ার `j` পছন্দ করেন।
বেশিরভাগ বিজ্ঞানী ও গণিতবিদ _কাল্পনিক_ বোঝাতে গণিতের প্রতীক `i` পছন্দ করেন, কিন্তু ইলেকট্রিক্যাল ইঞ্জিনিয়ারিং-এ _কারেন্ট_ বোঝাতে `i` ব্যবহারের সাথে সেই প্রতীকটি সংঘর্ষে পড়ে।

R বেছে নিয়েছে `i`, Python বেছে নিয়েছে `j`, আর Julia বিতর্ক এড়াতে বেছে নিয়েছে `im`.

[STEM][wiki-STEM] প্রোগ্রামিং ভাষাগুলোর মধ্যে সুইচ করার সময় সাবধান থাকুন।

একটি কমপ্লেক্স সংখ্যার অংশগুলো আলাদা আলাদা পেতে:

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

যেকোনো একটি অংশ শূন্য হতে পারে, তখন গণিতবিদেরা সংখ্যাটিকে "সম্পূর্ণ বাস্তব" বা "সম্পূর্ণ কাল্পনিক" বলতে পারেন।
তবে R-এ এটি তবুও একটি কমপ্লেক্স সংখ্যা।

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

আপনি হয়তো শুনেছেন যে "`i` (বা `j`) হলো -1-এর বর্গমূল"।

আপাতত এর অর্থ শুধু এইটুকু, কাল্পনিক অংশটি _সংজ্ঞা অনুযায়ী_ নিচের সমতাটি মেনে চলে:

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

এটি খুব সরল একটি ধারণা, কিন্তু এর থেকে মজার সব ফলাফল আসে।

## পাটিগণিত

ফ্লোট আর ইন্টিজারের সাথে যেসব [`operators`][ref-operators] ব্যবহার হয়, তার বেশিরভাগই কমপ্লেক্স সংখ্যার সাথেও কাজ করে:

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

কমপ্লেক্স সংখ্যার গুণ আর ভাগের নিয়ম ব্যাখ্যা করা এই কনসেপ্টের আওতার বাইরে (_আর এই অপারেশনগুলো আপনাকে "হাতে" খুব একটা করতে হবে বলেও সম্ভাবনা কম_)।

বিষয়টি নিয়ে আরও গভীরে যেতে চাইলে কমপ্লেক্স সংখ্যা নিয়ে যেকোনো [গাণিতিক][web-math-complex] বা [ইলেকট্রিক্যাল ইঞ্জিনিয়ারিং][web-engineering-complex] পরিচিতি এগুলো নিয়ে আলোচনা করবে।

অথবা Exercism-এ [`Complex Numbers`][exercise-complex-numbers] নামে একটি প্র্যাকটিস অনুশীলনী আছে, যেখানে আপনি একেবারে গোড়া থেকে এই অপারেশনগুলো দিয়ে একটি কমপ্লেক্স সংখ্যার ক্লাস তৈরি করতে পারবেন।

কমপ্লেক্স সংখ্যায় পূর্ণসংখ্যা বিভাজন সাধারণত ___সম্ভব নয়___, তাই কমপ্লেক্স সংখ্যা টাইপের জন্য `%/%` আর `%%` অপারেটর কাজ করবে না।

## ফাংশন

বেশিরভাগ গাণিতিক ফাংশন কমপ্লেক্স ইনপুট নিয়ে কাজ করে।

তবে বাস্তব ইনপুট দিয়ে কমপ্লেক্স আউটপুট আশা করলে সাধারণত কাজ হবে না।

```r
sqrt(z1)
#> [1] 1.414214+0.707107i

sqrt(-1)  # fails!
#> Warning in sqrt(-1) : NaNs produced
#> [1] NaN

sqrt(-1 + 0i)  # succeeds with complex input
#> [1] 0+1i

sin(z1)
#> [1] 3.752771+0.256554i
```

`Re()` আর `Im()` ছাড়াও আরও কয়েকটি ফাংশন আছে, যেগুলো কমপ্লেক্স সংখ্যার জন্য বিশেষভাবে প্রাসঙ্গিক।

- `Conj()` শুধু একটি কমপ্লেক্স সংখ্যার কাল্পনিক অংশের চিহ্ন উল্টে দেয় (_+ থেকে - বা উল্টোটাও_)।
  - কমপ্লেক্স গুণ যেভাবে কাজ করে, তাতে এটি আপনাকে যতটা ভাবছেন তার চেয়েও বেশি কাজে লাগে।
- `abs(<complex number>)` সবসময় কাল্পনিক অংশবিহীন একটি বাস্তব সংখ্যা দেয় (এর "ম্যাগনিচিউড"), আর `Mod(<complex number>)` হলো এর সমতুল্য।
- `Arg(<complex number>)` রেডিয়ানে ফেজ কোণ রিটার্ন করে।

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
