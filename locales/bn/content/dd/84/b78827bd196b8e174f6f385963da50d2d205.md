# ভূমিকা

স্মার্ট পয়েন্টার হলো C++-এর একটি আধুনিক ফিচার, যা স্বয়ংক্রিয় মেমরি ম্যানেজমেন্ট নিশ্চিত করার জন্য তৈরি করা হয়েছে এবং র পয়েন্টারের সাথে সাধারণত যে মেমরি লিক ও ড্যাঙ্গলিং পয়েন্টার যুক্ত থাকে, তা প্রতিরোধে সাহায্য করে।
এগুলো র পয়েন্টারের চারপাশে র‍্যাপার হিসেবে কাজ করে এবং বাড়তি কিছু সুবিধা যোগ করে, যেমন পয়েন্টারের আর প্রয়োজন না থাকলে স্বয়ংক্রিয়ভাবে মেমরি ডি-অ্যালোকেট করা।

## সাধারণ সিনট্যাক্স

স্মার্ট পয়েন্টার সাধারণত C++ স্ট্যান্ডার্ড লাইব্রেরিতে ক্লাস টেমপ্লেট হিসেবে বাস্তবায়িত হয়।
সবচেয়ে বেশি ব্যবহৃত দুটি স্মার্ট পয়েন্টার হলো `std::unique_ptr` এবং `std::shared_ptr`.

## ইউনিক পয়েন্টার

`std::unique_ptr` এমন একটি স্মার্ট পয়েন্টার, যা কোনো অবজেক্টের একচেটিয়া মালিকানা রাখে।
এটি নিশ্চিত করে যে যেকোনো সময়ে কেবল একটি `std::unique_ptr` অবজেক্টই রিসোর্সটির মালিক থাকে।
মালিকানা রাখা `std::unique_ptr` ধ্বংস বা রিসেট হলে, এটি স্বয়ংক্রিয়ভাবে অবজেক্টগুলো ধ্বংস করে এবং তাদের মেমরি মুক্ত করে।

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## `std::make_unique()`-এর সুবিধা

`std::unique_ptr` তৈরি করার সময় সরাসরি `new` দিয়ে মেমরি অ্যালোকেট করার বদলে `std::make_unique()` ব্যবহার করা ভালো।
`std::make_unique()` বেশ কিছু সুবিধা দেয়:
1. **এক্সেপশন সেফটি**: `std::make_unique()` এক্সেপশন সেফটি নিশ্চিত করে।
  অবজেক্ট তৈরির সময় কোনো এক্সেপশন থ্রো করা হলে মেমরি স্বয়ংক্রিয়ভাবে ডি-অ্যালোকেট হয়ে যায়, ফলে মেমরি লিক প্রতিরোধ হয়।
2. **স্পষ্টতা**: `std::make_unique()` ব্যবহার করলে কোড আরও স্পষ্ট ও সংক্ষিপ্ত হয়।
  এতে যে টাইপটি অ্যালোকেট করা হচ্ছে তা স্পষ্টভাবে উল্লেখ করার দরকার পড়ে না, কারণ টেমপ্লেট আর্গুমেন্ট স্বয়ংক্রিয়ভাবে ডিডিউস করা হয়।
3. **অপ্টিমাইজেশনের সুযোগ**: `new` দিয়ে হাতে মেমরি অ্যালোকেট করার তুলনায় কম্পাইলার `std::make_unique()`-কে আরও কার্যকরভাবে অপ্টিমাইজ করার সুযোগ পায়, যার ফলে পারফরম্যান্স উন্নত হতে পারে।
4. **ভুল ব্যবহার এড়ানো**: `std::unique_ptr` হাতে তৈরি করা হলে ভেতরের রিসোর্সটি আলাদাভাবে ডিলিট করা সম্ভব হয়।
  এর ফলে, স্কোপের শেষে `std::unique_ptr` যখন সেটি ডিলিট করার চেষ্টা করে, তখন আনডিফাইন্ড বিহেভিয়ার দেখা দেয়।

## শেয়ারড পয়েন্টার

`std::shared_ptr` এমন একটি স্মার্ট পয়েন্টার, যা একাধিক `std::shared_ptr` অবজেক্টকে একই রিসোর্সের মালিকানা ভাগ করে নেওয়ার সুযোগ দেয়।
এটি হিসাব রাখে কতগুলো শেয়ারড পয়েন্টার রিসোর্সটিকে রেফার করছে, এবং কেবল তখনই মেমরি ডি-অ্যালোকেট করে, যখন রিসোর্সটির মালিকানা রাখা শেষ শেয়ারড পয়েন্টারটি স্কোপের বাইরে চলে যায় বা রিসেট হয়।

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

C++17 এবং তার নিচের ভার্সনে `std::make_shared<T[]>`-এর মাধ্যমে `std::shared_ptr`-এর সাথে অ্যারে ব্যবহার সরাসরি সমর্থিত নয়।
`std::make_shared<T[]>` দিয়ে অ্যারে অ্যালোকেট করা সম্ভব হলেও, সেগুলো থেকে সরাসরি শেয়ারড পয়েন্টার তৈরি করলে আনডিফাইন্ড বিহেভিয়ার দেখা দিতে পারে, কারণ একক অবজেক্ট আর অ্যারের মেমরি ম্যানেজমেন্টে পার্থক্য রয়েছে।
এর বদলে শেয়ারড পয়েন্টার দিয়ে অ্যারে কার্যকরভাবে ম্যানেজ করতে `std::vector` বা কাস্টম ডিলিশন ফাংশন ব্যবহার করার কথা ভাবতে পারেন।
C++17-এ অ্যারে অ্যালোকেশন আর শেয়ারড পয়েন্টার নিয়ে কাজ করার সময় সবসময় আপনার কম্পাইলার ও স্ট্যান্ডার্ড লাইব্রেরি ইমপ্লিমেন্টেশনের সাথে সাযুজ্য নিশ্চিত করুন।

## `std::make_shared()`-এর সুবিধা

`std::make_unique()`-এর মতোই `std::make_shared()`-ও উন্নত মেমরি এফিশিয়েন্সি, এক্সেপশন সেফটি আর পড়ার সহজতার মতো সুবিধা দেয়।
এটি কন্ট্রোল ব্লক আর ম্যানেজড অবজেক্টের মেমরি অ্যালোকেশনকে একটিমাত্র অপারেশনে একত্র করে, যা কার্যক্ষমতা বাড়ায় এবং মেমরি লিকের ঝুঁকি কমায়।
এ ছাড়া টেমপ্লেট আর্গুমেন্ট স্বয়ংক্রিয়ভাবে ডিডিউস হওয়ায় কোড সহজ হয় ও পড়তে সুবিধা হয়।
C++-এ `std::shared_ptr` অবজেক্ট নিয়ে কাজ করার সময় `std::make_shared()` ব্যবহার করলে কোড আরও পরিচ্ছন্ন, নিরাপদ ও কার্যকর হয়।

## উইক পয়েন্টার

`std::weak_ptr` হলো `std::shared_ptr`-এর একটি সঙ্গী ক্লাস, যা শেয়ারড পয়েন্টার দিয়ে ম্যানেজ করা কোনো অবজেক্টের প্রতি মালিকানাহীন একটি "উইক" রেফারেন্স দেয়।

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

মেমরি লিক ঠেকাতে সাইক্লিক রেফারেন্স ভেঙে দিতে যেসব ক্ষেত্রে প্রয়োজন হয়, সেখানে উইক পয়েন্টার কাজে লাগে।
`std::weak_ptr` তৈরি করা হয়েছে সাইক্লিক মালিকানা, যা সার্কুলার রেফারেন্স নামেও পরিচিত, সেই সমস্যা সমাধানের জন্য, যা `std::shared_ptr` ব্যবহারের সময় দেখা দিতে পারে।
সাইক্লিক মালিকানার পরিস্থিতিতে দুই বা তার বেশি `std::shared_ptr` অবজেক্ট পরস্পরকে রেফার করে, ফলে একটি চক্র তৈরি হয় যেখানে কোনো অবজেক্টই ডিলিট হতে পারে না, কারণ তারা একে অন্যের প্রতি স্ট্রং রেফারেন্স রাখে, এবং শেষে মেমরি লিক ঘটে।
`std::weak_ptr` এই সমস্যার সমাধান দেয়, কারণ এটি শেয়ারড অবজেক্টের প্রতি উইক রেফারেন্স রাখার সুযোগ দেয়, যা তাদের রেফারেন্স কাউন্টে যোগ হয় না।
অর্থাৎ এটি শেয়ারড অবজেক্টটি পর্যবেক্ষণ ও ব্যবহার করতে পারে, কিন্তু সেটি ডিলিট হওয়া আটকায় না।
~~~~

## ব্যবহারের পরামর্শ

ডিফল্ট হিসেবে স্মার্ট পয়েন্টার ব্যবহার করুন: একচেটিয়া মালিকানার জন্য `std::unique_ptr` আর ভাগ করা মালিকানার জন্য `std::shared_ptr`।
মালিকানাহীন রেফারেন্সের জন্য বা লিগ্যাসি কোডের সাথে ইন্টারফেস করার সময়ের জন্য র পয়েন্টার রেখে দিন।
বেশিরভাগ ক্ষেত্রে একচেটিয়া মালিকানার জন্য `std::unique_ptr`-ই যথেষ্ট, কারণ এটি রেফারেন্স কাউন্টিংয়ের বাড়তি ঝামেলা ছাড়াই হালকা মেমরি ম্যানেজমেন্ট দেয়।
`std::shared_ptr` অল্প ব্যবহার করা উচিত, কারণ সত্যিকারের ভাগ করা মালিকানার প্রয়োজন না থাকলে এটি বাড়তি ঝামেলা ও জটিলতা আনে।
`std::weak_ptr` বিশেষভাবে সাইক্লিক নির্ভরতা ভাঙতে বা শেয়ারড অবজেক্ট পর্যবেক্ষণ করতে ব্যবহৃত হয়, তবে এটি সাধারণত বেশি ব্যবহৃত হয় না।
