# ইঙ্গিত

## সাধারণ

- একটি কনট্র্যাক্ট রিটার্ন টাইপের পরে এবং `is`-এর আগে বসে:

  ```sather
     spare_capacity(load : INT) : INT
        pre load >= 0
     is
        ...
     end;
  ```

- একটি কনট্র্যাক্টের ভেতরে আপনি আর্গুমেন্ট এবং অবজেক্টের অ্যাট্রিবিউটগুলো ব্যবহার করতে পারেন, তাই `limit` পাওয়া যায়।
- টেস্টগুলো `-chk` ছাড়াই বিল্ড করা হয়, তাই ভুল কনট্র্যাক্ট তাদের ফেল করাবে না। পাঠকের জন্যই এগুলো লিখুন।

## 1. একটি হারনেস সাজান

- `create`-এ `pre kg > 0`।
- বডি হলো সাধারণ `new`, অ্যাট্রিবিউটটি সেট করুন, তারপর এটি রিটার্ন করুন।

## 2. কতটা বাড়তি আছে?

- `and` দিয়ে যুক্ত দুটি শর্ত: `pre load >= 0 and load <= limit`।
- `post result >= 0`। এটি `pre` থেকেই অনুসরণ করে, আর সেটাই এটিকে বলার মতো করে তোলে। এটি লিপিবদ্ধ করে কেন উত্তরটির উপর ভরসা করা যায়।

## 3. এটা কতটা পূর্ণ?

- `pre load >= 0` এবং `post result >= 0`।
- `load * 100 / limit`, এই ক্রমেই। আগে ভাগ করলে সবকিছু নষ্ট হয়ে যেত, যেমনটা `tuning-the-strings`-এ হতো।

## 4. এটা কি নিরাপদ?

- কোনো `pre` নেই: মূল কথাটাই হলো যেকোনো লোড সম্পর্কে জিজ্ঞাসা করা যেতে পারে।
- `post` প্রশ্নটিরই পুনরাবৃত্তি করে: `post result = (load <= limit)`। বন্ধনী, কারণ `=` দুটি ভিন্ন কাজে দুবার ব্যবহার করা হচ্ছে।
