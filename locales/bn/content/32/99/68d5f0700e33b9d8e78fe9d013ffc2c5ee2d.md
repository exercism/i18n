# পরিচিতি

## C++-এ `auto` কিওয়ার্ড

C++-এ `auto` কিওয়ার্ডটি C++11-এ যোগ হওয়া একটি শক্তিশালী ফিচার, যা দিয়ে অনুমিত ডেটা টাইপের ভ্যারিয়েবল ঘোষণা করা যায়।
কম্পাইলার ভ্যারিয়েবলটির ইনিশিয়ালাইজার দেখে তার টাইপ অনুমান করে, ফলে কোড আরও পাঠযোগ্য ও রক্ষণাবেক্ষণযোগ্য হয়ে ওঠে।

## ব্যবহারের উদাহরণ

নিচের উদাহরণটি দেখুন, যেখানে `auto` দিয়ে ভ্যারিয়েবল ঘোষণা করা হয়েছে:

```cpp
auto dragon_population{3};          // dragon_population is deduced as an integer
auto westeros{7.7777};              // westeros is deduced as a double
auto wedding_location{"The Twins"}; // wedding_location is deduced as a const char*, not std::string
```

প্রতিটি ক্ষেত্রেই ভ্যারিয়েবলের টাইপ তার যে মান দিয়ে আরম্ভ করা হয়েছে সেখান থেকেই অনুমান করা হয়।

## টাইপ ইনফারেন্স

`auto` কিওয়ার্ড স্পষ্ট টাইপ লেখার বাহুল্য কমিয়ে কোড আরও সংক্ষিপ্ত ও পাঠযোগ্য করতে সাহায্য করে।

```cpp
const std::vector<std::string> pigeon_pie{"flour", "butter", "pigeon", "salt"};
auto purple_wedding_pie{pigeon_pie};
purple_wedding_pie.emplace_back("the strangler");
```

এই লুপে `auto` `purple_wedding_pie`-এর টাইপ `std::vector<std::string>` হিসেবে অনুমান করে, ফলে টাইপটি আবার আলাদা করে লিখতে হয় না।

## সামঞ্জস্য

`auto` কিওয়ার্ড C++-এর নানা কনস্ট্রাক্টের সাথে সামঞ্জস্যপূর্ণ, যা এটিকে আধুনিক C++ প্রোগ্রামিংয়ে একটি বহুমুখী টুলে পরিণত করেছে।

```cpp
auto& element{array[0]};           // reference to an element
const auto object{otherObject};    // const type version of otherObject's type
auto* ptr{&x};                     // pointer to x with the same type as x, but as a pointer.
```

পরবর্তী কনসেপ্টে আমরা প্রায়ই `auto` কিওয়ার্ডটি ল্যাম্বডা এক্সপ্রেশন, রেঞ্জ-ভিত্তিক for লুপ আর ইটারেটরের সাথে দেখব।

## স্মার্ট পয়েন্টার

স্মার্ট পয়েন্টার হলো আধুনিক C++-এর একটি ফিচার, যা স্বয়ংক্রিয় মেমরি ম্যানেজমেন্টের সুবিধা দিতে তৈরি, এবং যা সাধারণত র' পয়েন্টারের সাথে যুক্ত মেমরি লিক ও ড্যাঙ্গলিং পয়েন্টার প্রতিরোধে সাহায্য করে।
এগুলো র' পয়েন্টারের চারপাশে র্যাপার হিসেবে কাজ করে এবং পয়েন্টারটির আর প্রয়োজন না হলে স্বয়ংক্রিয়ভাবে মেমরি মুক্ত করা জাতীয় অতিরিক্ত কার্যকারিতা যোগ করে।

## সাধারণ সিনট্যাক্স

স্মার্ট পয়েন্টার সাধারণত C++ স্ট্যান্ডার্ড লাইব্রেরিতে ক্লাস টেমপ্লেট হিসেবে তৈরি করা হয়।
সবচেয়ে বেশি ব্যবহৃত দুটি স্মার্ট পয়েন্টার হলো `std::unique_ptr` ও `std::shared_ptr`।

## ইউনিক পয়েন্টার

`std::unique_ptr` একটি স্মার্ট পয়েন্টার, যা অবজেক্টটির একচেটিয়া মালিকানা রাখে।
এটি নিশ্চিত করে যে যেকোনো সময়ে কেবল একটি `std::unique_ptr` অবজেক্টই রিসোর্সটির মালিক থাকে।
মালিকানা রাখা `std::unique_ptr` ধ্বংস বা রিসেট হলে এটি স্বয়ংক্রিয়ভাবে অবজেক্টগুলো ধ্বংস করে এবং তার মেমরি মুক্ত করে।

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## `std::make_unique()`-এর সুবিধা

একটি `std::unique_ptr` তৈরি করার সময় সরাসরি `new` দিয়ে মেমরি অ্যালোকেট করার বদলে `std::make_unique()` ব্যবহার করাই ভালো।
`std::make_unique()` কয়েকটি সুবিধা দেয়:
1. **এক্সেপশন সেফটি**: `std::make_unique()` এক্সেপশন সেফটির নিশ্চয়তা দেয়।
  অবজেক্ট তৈরির সময় কোনো এক্সেপশন ছোড়া হলে মেমরি স্বয়ংক্রিয়ভাবে মুক্ত হয়ে যায়, ফলে মেমরি লিক প্রতিরোধ হয়।
2. **স্বচ্ছতা**: `std::make_unique()` ব্যবহার করলে কোড আরও স্পষ্ট ও সংক্ষিপ্ত হয়।
  টেমপ্লেট আর্গুমেন্ট স্বয়ংক্রিয়ভাবে অনুমান করা হয় বলে কোন টাইপ অ্যালোকেট হচ্ছে তা আর আলাদা করে লিখতে হয় না।
3. **অপটিমাইজেশনের সুযোগ**: ম্যানুয়ালি `new` দিয়ে মেমরি অ্যালোকেট করার তুলনায় কম্পাইলার `std::make_unique()`-কে আরও কার্যকরভাবে অপটিমাইজ করার সুযোগ পায়, যার ফলে পারফরম্যান্স উন্নত হতে পারে।
4. **ভুল ব্যবহার এড়ানো**: `std::unique_ptr` হাতে হাতে তৈরি করা হলে এর অন্তর্নিহিত রিসোর্সটি ডিলিট করা সম্ভব হয়ে পড়ে।
  আর স্কোপের শেষে `std::unique_ptr` যখন সেটি ডিলিট করার চেষ্টা করে, তখন সেটি আনডিফাইন্ড বিহেভিয়ারের দিকে নিয়ে যায়।

## শেয়ার্ড পয়েন্টার

`std::shared_ptr` একটি স্মার্ট পয়েন্টার, যা একাধিক `std::shared_ptr` অবজেক্টকে একই রিসোর্সের মালিকানা ভাগ করে নিতে দেয়।
কতগুলো শেয়ার্ড পয়েন্টার রিসোর্সটির রেফারেন্স রাখছে তা এটি হিসাব রাখে, এবং রিসোর্সটির মালিকানা রাখা শেষ শেয়ার্ড পয়েন্টারটি স্কোপের বাইরে চলে গেলে বা রিসেট হলে তবেই মেমরি মুক্ত করে।

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
C++17 ও তার নিচের ভার্সনে `std::make_shared<T[]>`-এর মাধ্যমে `std::shared_ptr`-কে অ্যারের সাথে ব্যবহার করা সরাসরি সমর্থিত নয়।
`std::make_shared<T[]>` দিয়ে অ্যারে অ্যালোকেট করা সম্ভব হলেও, সেগুলো থেকে সরাসরি শেয়ার্ড পয়েন্টার তৈরি করলে আনডিফাইন্ড বিহেভিয়ার দেখা দিতে পারে, কারণ একক অবজেক্ট আর অ্যারের মেমরি ম্যানেজমেন্টে পার্থক্য রয়েছে।
বদলে, শেয়ার্ড পয়েন্টার দিয়ে অ্যারে কার্যকরভাবে ম্যানেজ করতে `std::vector` বা কাস্টম ডিলিশন ফাংশন ব্যবহার করার কথা ভাবুন।
C++17-এ অ্যারে অ্যালোকেশন ও শেয়ার্ড পয়েন্টার নিয়ে কাজ করার সময় সবসময় আপনার কম্পাইলার ও স্ট্যান্ডার্ড লাইব্রেরি ইমপ্লিমেন্টেশনের সাথে সামঞ্জস্য নিশ্চিত করুন।

## `std::make_shared()`-এর সুবিধা

`std::make_unique()`-এর মতোই `std::make_shared()` উন্নত মেমরি এফিশিয়েন্সি, এক্সেপশন সেফটি আর পাঠযোগ্যতার মতো সুবিধা দেয়।
এটি কন্ট্রোল ব্লক ও ম্যানেজড অবজেক্টের জন্য মেমরি অ্যালোকেশনকে একটিমাত্র কাজে মিলিয়ে দেয়, ফলে দক্ষতা বাড়ে এবং মেমরি লিকের ঝুঁকি কমে।
এছাড়া টেমপ্লেট আর্গুমেন্ট স্বয়ংক্রিয়ভাবে অনুমান হওয়ায় কোড সরল হয় ও পাঠযোগ্যতা বাড়ে।
C++-এ `std::shared_ptr` অবজেক্ট নিয়ে কাজ করার সময় `std::make_shared()` ব্যবহার করলে কোড আরও পরিচ্ছন্ন, নিরাপদ ও দক্ষ হয়।

## ব্যবহারের পরামর্শ

ডিফল্ট হিসেবে স্মার্ট পয়েন্টার ব্যবহার করুন: একচেটিয়া মালিকানার জন্য `std::unique_ptr` আর ভাগ করা মালিকানার জন্য `std::shared_ptr`।
র' পয়েন্টার রেখে দিন কেবল মালিকানাহীন রেফারেন্সের জন্য বা লিগ্যাসি কোডের সাথে ইন্টারফেস করার সময়।
বেশিরভাগ ক্ষেত্রেই একচেটিয়া মালিকানার জন্য `std::unique_ptr`-ই যথেষ্ট, কারণ এটি রেফারেন্স কাউন্টিংয়ের বাড়তি ঝামেলা ছাড়াই হালকা মেমরি ম্যানেজমেন্ট দেয়।
সত্যিকারের ভাগ করা মালিকানার প্রয়োজন না থাকলে `std::shared_ptr` অল্পই ব্যবহার করা উচিত, কারণ এটি বাড়তি ঝামেলা ও জটিলতা নিয়ে আসে।
