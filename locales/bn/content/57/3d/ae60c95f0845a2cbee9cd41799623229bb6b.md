# ভূমিকা

একটি `GENERIC:` ডিক্লারেশন এমন একটি ওয়ার্ড তৈরি করে, যার আচরণ তার একটি আর্গুমেন্টের *ক্লাসের* উপর নির্ভর করে। নির্দিষ্ট আচরণ আসে *মেথড* থেকে, যা `M:` দিয়ে ডিফাইন করা হয়।

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

যখন `area` কল করা হয়, তখন Factor স্ট্যাকের একেবারে উপরের অংশটি পরীক্ষা করে, যে মেথডের ক্লাসটি সবচেয়ে নির্দিষ্টভাবে মেলে সেটি খুঁজে বের করে এবং সেটি রান করে। লোকাল ব্যবহার করলে আপনি `M::` ব্যবহার করতে পারেন:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

জেনেরিক ব্যবহার করে আপনি পরে নতুন রিপ্রেজেন্টেশন যোগ করতে পারেন, কল করা কোড না বদলেই: `area` আগে থেকেই `square` ও `circle`-এর জন্য কাজ করত, আর `area` যেখানেই কল করা হোক, `rectangle` মেথড স্বয়ংক্রিয়ভাবে ধরা পড়ে।

## কখন জেনেরিক সঠিক পছন্দ

`GENERIC:` ব্যবহার করার কথা ভাবুন যখন:

- একটি একক অপারেশনের বিভিন্ন ইনপুটের জন্য *সত্যিই ভিন্ন* ইমপ্লিমেন্টেশন থাকে।
- আপনি আশা করেন, ভবিষ্যতের কোড নতুন টাইপ যোগ করবে।
- আপনি চান, টাইপ সিস্টেম প্রতিটি ক্লাসের জন্য আলাদা ডিফাইনিশন নিশ্চিত করুক।

যদি ভিন্নতাটি শুধুই লেবেলের ছোট একটি তালিকা হয়, তবে একটি `case` আরও সহজ।

## `INSTANCE:` দিয়ে একটি মিক্সিনে যুক্ত হওয়া

একটি *মিক্সিন* হলো একটি জেনেরিক ক্লাস যা *খোলা*: যে কেউ একটি নতুন ক্লাসকে সদস্য হিসেবে রেজিস্টার করতে পারে। Factor-এর অনেক বিল্ট-ইন প্রোটোকল (সিকোয়েন্স, সেট, স্ট্রিম, …) মিক্সিন হিসেবে প্রকাশ করা থাকে, তাই একটি কাস্টম টুপল নিজেকে একটি ইনস্ট্যান্স হিসেবে ঘোষণা করে প্রোটোকলের ডিফল্ট মেথডগুলোতে যোগ দিতে পারে:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

`INSTANCE:`-এর পরে, প্রতিটি ডিফল্ট মেথড `M: shape …` স্বয়ংক্রিয়ভাবে `my-shape`-এর উপর ডিসপ্যাচ করে, আর যে কোডই একটি `shape` চায়, সে একটি `my-shape` গ্রহণ করে। `M:` হলো জেনেরিকে মেথড যোগ করার জন্য; `INSTANCE:` হলো একটি ক্লাসকে মিক্সিনে যুক্ত করার জন্য।

## `TYPED::`: সাধারণ ওয়ার্ডের জন্য যাচাই করা ইনপুট

`GENERIC:`/`M:` একটি আর্গুমেন্টের ক্লাস দেখে একটি মেথড বেছে নেয়। কখনও কখনও আপনি ডিসপ্যাচ চান না, শুধু *একটি* ওয়ার্ড চান যা তার ইনপুটগুলো নির্দিষ্ট একটি ক্লাসের হতে জোর দেয়। `TYPED::` (`typed` ভোকাবুলারিতে) হলো `::`, যেখানে প্রতিটি ইনপুট নামের পরে একটি ক্লাস লেখা থাকে:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

`n: integer` ঠিক আপনার চেনা লোকালের মতোই পড়া যায়, শুধু কোলনের পরে ক্লাসটি লেখা থাকে। এখানে কোনো ডিসপ্যাচ নেই, একটি ডিফাইনিশন, একটি আচরণ; কিন্তু এখন প্রতিটি আর্গুমেন্ট তার ক্লাসের বিপরীতে যাচাই করা হয়: `"x" triple`-এর মতো অমিল চুপচাপ পার হয়ে যাওয়ার বদলে বাতিল হয়ে যায় (*expected input value of type integer but got string*)।

আউটপুটও একইভাবে অ্যানোটেট করা যায়। `yes?` তার ইনপুট ও রেজাল্ট দুটোই টাইপ করে:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## গণিতের ফাংশন ও ধ্রুবক

এই অনুশীলনীটি `math.constants` ও `math.functions`-এর কয়েকটি ওয়ার্ডের উপরও নির্ভর করে, যেগুলোর সাথে আপনার প্রথম পরিচয় এখানেই:

- `pi`: ধ্রুবক π, `math.constants` থেকে।
- `sin ( x -- y )`, `cos ( x -- y )`: রেডিয়ানে মাপা একটি কোণের সাইন ও কোসাইন।
- `e^ ( x -- y )`: `e`-কে `x` ঘাতে উন্নীত করা। (যেকোনো বেসের জন্য `^` ব্যবহার করুন।)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
