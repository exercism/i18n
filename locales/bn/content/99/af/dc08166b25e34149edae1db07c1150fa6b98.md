# পরিচিতি

অন্য অনেক ভাষার মতোই Go-তেও পয়েন্টার আছে।
আপনি যদি পয়েন্টারে নতুন হন, তবে প্রথমে এগুলো একটু রহস্যময় মনে হতে পারে, কিন্তু একবার অভ্যস্ত হয়ে গেলে এগুলো বেশ সহজ।
এগুলো Go-র একটি অত্যন্ত গুরুত্বপূর্ণ অংশ, তাই এগুলো সত্যিই বুঝতে একটু সময় দিন।

বিস্তারিত আলোচনায় যাওয়ার আগে পয়েন্টারের ব্যবহার সম্পর্কে বোঝা ভালো।
পয়েন্টার হলো আমাদের প্রোগ্রামের অন্যান্য অংশের সাথে মেমরি শেয়ার করার একটি উপায়, যা দুটি প্রধান কারণে কাজে লাগে:

1. যখন আমাদের কাছে প্রচুর পরিমাণ ডেটা থাকে, তখন ফাংশনের মধ্যে পাস করার জন্য কপি তৈরি করা খুবই অদক্ষ।
   এর বদলে ডেটা যেখানে সংরক্ষিত আছে সেই মেমরি লোকেশন পাস করে আমরা আমাদের প্রোগ্রামের রিসোর্স ব্যবহার উল্লেখযোগ্যভাবে কমাতে পারি।
2. ফাংশনের মধ্যে পয়েন্টার পাস করে আমরা সরাসরি ডেটার একক কপি অ্যাক্সেস ও পরিবর্তন করতে পারি, অর্থাৎ একটি ফাংশন যে পরিবর্তন করে তা ফাংশন শেষ হওয়ার সাথে সাথে প্রোগ্রামের অন্যান্য অংশের কাছে দৃশ্যমান হয়ে যায়।

## ভ্যারিয়েবল ও মেমরি

ধরা যাক আমাদের একটি সাধারণ ইন্টিজার ভ্যারিয়েবল `a` আছে:

```go
var a int
```

যখন আমরা একটি ভ্যারিয়েবল ডিক্লেয়ার করি, তখন Go-কে এর মান সংরক্ষণ করার জন্য মেমরিতে একটি জায়গা খুঁজতে হয়।
এই প্রক্রিয়াটি মূলত আমাদের কাছ থেকে আড়াল করা থাকে, অর্থাৎ ওই মেমরিতে সংরক্ষিত মানটি আনতে হলে আমরা শুধু ভ্যারিয়েবলের নাম দিয়ে সেটি উল্লেখ করলেই হয়।

উদাহরণস্বরূপ, যখন আমরা `a + 2` লিখি, তখন আমরা মূলত `a` ভ্যারিয়েবলটির সাথে সম্পর্কিত মেমরিতে সংরক্ষিত মানটি এনে তার সাথে 2 যোগ করি।

একইভাবে, যখন আমাদের `a` ভ্যারিয়েবলের মেমরিতে থাকা মানটি পরিবর্তন করার প্রয়োজন হয়, তখন অ্যাসাইনমেন্ট করতে আমরা ভ্যারিয়েবলের নামটি ব্যবহার করতে পারি:

```go
a = 3
```

এখন `a` ভ্যারিয়েবলের সাথে সম্পর্কিত মেমরিতে `3` মানটি সংরক্ষিত থাকবে।

## পয়েন্টার

ভ্যারিয়েবল আমাদের মেমরিতে থাকা মান উল্লেখ করার সুযোগ দেয়, তবে মাঝে মাঝে ভ্যারিয়েবলটি যে **মেমরি অ্যাড্রেস**-এর দিকে ইঙ্গিত করছে সেটি জানা কাজে লাগে। **পয়েন্টার** এই মানগুলোর মেমরি অ্যাড্রেস ধারণ করে।
আপনি মূল টাইপের আগে একটি অ্যাস্টেরিস্ক যোগ করে পয়েন্টার টাইপের একটি ভ্যারিয়েবল ডিক্লেয়ার করেন:

```go
var p *int // 'p' contains the memory address of an integer
```

এখানে আমরা `p` নামে একটি ভ্যারিয়েবল ডিক্লেয়ার করি, যার টাইপ "int-এর পয়েন্টার" (`*int`)।
এর মানে হলো `p` একটি ইন্টিজারের মেমরি অ্যাড্রেস ধারণ করবে।
পয়েন্টারের জিরো ভ্যালু হলো `nil`, কারণ একটি `nil` পয়েন্টার কোনো মেমরি অ্যাড্রেস ধারণ করে না।

### একটি ভ্যারিয়েবলের পয়েন্টার পাওয়া

একটি ভ্যারিয়েবলের মানের মেমরি অ্যাড্রেস খুঁজে বের করতে আমরা `&` অপারেটরটি ব্যবহার করতে পারি।
উদাহরণস্বরূপ, আমরা যদি `a` ভ্যারিয়েবলের মেমরি অ্যাড্রেস খুঁজে বের করে `p` পয়েন্টারে সংরক্ষণ করতে চাই, তবে আমরা নিচের কাজটি করতে পারি:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### পয়েন্টারের মাধ্যমে মান অ্যাক্সেস করা (ডিরেফারেন্সিং)

যখন আমাদের কাছে একটি পয়েন্টার থাকে, তখন পয়েন্টারটি যে মেমরি অ্যাড্রেস নির্দেশ করে সেখানে সংরক্ষিত মানটি আমরা জানতে চাইতে পারি।
আমরা `*` অপারেটর ব্যবহার করে এটি করতে পারি:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p` অপারেশনটি `p`-তে সংরক্ষিত মেমরি অ্যাড্রেসে থাকা মানটি আনে।
এই অপারেশনকে প্রায়ই "ডিরেফারেন্সিং" বলা হয়।

আমরা ডিরেফারেন্স অপারেটর ব্যবহার করে পয়েন্টারটি যে মেমরি অ্যাড্রেস নির্দেশ করে সেখানে নতুন মানও অ্যাসাইন করতে পারি:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa`-তে অ্যাসাইন করলে `pa` যে মেমরি অ্যাড্রেস ধারণ করে সেখানে সংরক্ষিত মানটি বদলে যাবে।
যেহেতু `pa` `a`-এর মেমরি অ্যাড্রেস ধারণ করে, তাই `*pa`-তে অ্যাসাইন করার মাধ্যমে আমরা আসলে `a`-এর মানই পরিবর্তন করছি!

তবে একটি সতর্কতা: ডিরেফারেন্স করার আগে সবসময় পরীক্ষা করে নিন যে পয়েন্টারটি `nil` নয় কি না।
একটি `nil` পয়েন্টার ডিরেফারেন্স করলে রানটাইমে প্রোগ্রামটি ক্র্যাশ করবে!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### স্ট্রাক্টের পয়েন্টার

এখন পর্যন্ত আমরা কেবল প্রিমিটিভ ভ্যালুর পয়েন্টার দেখেছি।
আমরা স্ট্রাক্টের জন্যও পয়েন্টার তৈরি করতে পারি:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

আমরা একটি নতুন `Person` তৈরি করে সাথে সাথে তার একটি পয়েন্টারও সংরক্ষণ করতে পারতাম:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

যখন আমাদের একটি স্ট্রাক্টের পয়েন্টার থাকে, তখন কোনো ফিল্ড অ্যাক্সেস করার আগে পয়েন্টারটি ডিরেফারেন্স করার প্রয়োজন হয় না:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## স্লাইস ও ম্যাপ আগে থেকেই পয়েন্টার

স্লাইস ও ম্যাপ বিশেষ ধরনের টাইপ, কারণ তাদের বাস্তবায়নে আগে থেকেই পয়েন্টার থাকে।
এর মানে হলো, বেশিরভাগ ক্ষেত্রেই এই টাইপগুলোর মানের মেমরি অ্যাড্রেস শেয়ার করার জন্য আমাদের পয়েন্টার তৈরি করার দরকার হয় না।
ধরা যাক আমাদের এমন একটি ফাংশন আছে যা একটি ম্যাপের একটি কী (key)-এর মান এক বাড়ায়:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

আমরা যদি একটি ম্যাপ তৈরি করে এই ফাংশনটি কল করি, তবে ফাংশনটি ম্যাপে যে পরিবর্তনগুলো করে তা ফাংশন শেষ হওয়ার পরও টিকে থাকে।
পয়েন্টার ব্যবহার করলে আমরা একই রকম আচরণ পাই, তবে লক্ষ্য করুন এই উদাহরণে আমরা কোনো রেফারেন্সিং/ডিরেফারেন্সিং বা পয়েন্টারের কোনো সিনট্যাক্স ব্যবহার করছি না:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

একটি স্লাইসে থাকা বিদ্যমান কোনো এলিমেন্ট পরিবর্তন করার ক্ষেত্রেও একই কথা প্রযোজ্য।

তবে `append`-এর মতো নতুন স্লাইস রিটার্ন করে এমন কাজ একটি বিশেষ ক্ষেত্র, যা ফাংশনের বাইরে স্লাইসটি **পরিবর্তন নাও করতে পারে**।
এর কারণ হলো স্লাইস কীভাবে ভেতরে কাজ করে, তবে এটি আরও অ্যাডভান্সড বিষয় হওয়ায় এই অনুশীলনীতে আমরা এ নিয়ে বিস্তারিত আলোচনা করব না।
