# নির্দেশনা

আপনি আপনার প্রতিষ্ঠানের নেটওয়ার্কের লগইন প্রক্রিয়া সহজ করার একটি সিস্টেম নিয়ে কাজ করছেন। কাজগুলো অথেন্টিকেশন অংশের সঙ্গে সম্পর্কিত। সিস্টেমটি পরিচয় প্রমাণের জন্য ফেসিয়াল রিকগনিশন ব্যবহার করে।

সব ক্ষেত্রেই চোখের রঙের প্যারামিটারটি নন-নাল থাকার নিশ্চয়তা রয়েছে।

## 1. নিশ্চিত করুন যে মুখের বৈশিষ্ট্যগুলো মিলে যায়

দুটি মুখ মেলে কি না তা যাচাই করতে `Authenticator.AreSameFace()` ইমপ্লিমেন্ট করুন।

`FacialFeatures` ক্লাসের জন্য ইকুয়ালিটি রুটিন যোগ করুন।

```csharp
Authenticator.AreSameFace(new FacialFeatures("green", 0.9m), new FacialFeatures("green", 0.9m);
// => true
Authenticator.AreSameFace(new FacialFeatures("blue", 0.9m), new FacialFeatures("green", 0.9m);
// => false
```

## 2. সিস্টেম অ্যাডমিনিস্ট্রেটরকে অথেন্টিকেট করুন

আপনার আপত্তি সত্ত্বেও সিস্টেম অ্যাডমিনিস্ট্রেটর জোর দিয়ে বলেছেন যে অ্যাকসেপ্টেন্স টেস্টিংয়ের সময় একটি বিল্ট-ইন পরিচয় থাকতেই হবে, যাতে তাঁকে সব সময় অথেন্টিকেট করা যায়।

অ্যাডমিনের ইমেইল admin@exerc.ism। তাঁর চোখ সবুজ এবং ফিল্ট্রামের প্রস্থ 0.9।

`Identity` ক্লাসের জন্য ইকুয়ালিটি রুটিন যোগ করুন।

পাস করা পরিচয়টি অ্যাডমিনিস্ট্রেটরের পরিচয়ের সঙ্গে মেলে কি না তা যাচাই করতে `Authenticator.IsAdmin()` মেথডটি ইমপ্লিমেন্ট করুন।

```csharp
var authenticator = new Authenticator();
authenticator.IsAdmin(new Identity("admin@exerc.ism", new FacialFeatures("green", 0.9m)));
// => true
authenticator.IsAdmin(new Identity("admin@thecompetition.com", new FacialFeatures("green", 0.9m)));
// => false
```

## 3. নতুন পরিচয় রেজিস্টার করুন

`Authenticator.Register()` মেথডটি ইমপ্লিমেন্ট করুন, যা অথেন্টিকেটরেই একটি পরিচয় সংরক্ষণ করে, যাতে এই পরিচয়ের জন্য `IsRegistered()` কল করলে `true` রিটার্ন করে; অন্যথায় `IsRegistered()` `false` রিটার্ন করে।

একই পরিচয় বারবার রেজিস্টার করার চেষ্টা শনাক্ত করতে, পরিচয়টি যদি আগেই রেজিস্টার করা থাকে তবে `Authenticator.Register()` `false` রিটার্ন করে, অন্যথায় `true`।

```csharp
var authenticator = new Authenticator();
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.IsRegistered(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => false
```

## 4. অবৈধ পরিচয় অথেন্টিকেট হওয়া প্রতিরোধ করুন

`Authenticator.IsRegistered()` মেথডটি ইমপ্লিমেন্ট করুন এবং নিশ্চিত করুন যে কোনো পরিচয় রেজিস্টার করা না থাকলে এটি false রিটার্ন করে।

```csharp
var authenticator = new Authenticator();
authenticator.IsRegistered(new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.8m)));
// => false
```

## 5. একাধিকবার অথেন্টিকেট করার চেষ্টা শনাক্ত করতে ডায়াগনস্টিক যোগ করুন

এমন একটি বাগ রিপোর্ট করা হয়েছে যেখানে একই পরিচয়ের জন্য দ্রুত পরপর একাধিকবার `Authenticator.IsRegistered()` মেথডটি কল করা হচ্ছে। আপনার ধারণা, এখানে একধরনের "বাউন্স" সমস্যা রয়েছে, যেখানে একই রেকর্ড বারবার সাবমিট করা হচ্ছে। আপনার কাজ হলো যেকোনো পরীক্ষা-নিরীক্ষা সমর্থন করার জন্য `Authenticator.AreSameObject()` নামের একটি ডায়াগনস্টিক রুটিন যোগ করা। রুটিনটি দুটি অবজেক্ট তুলনা করে এবং তারা যদি হুবহু একই ইনস্ট্যান্স হয় তবে `true` রিটার্ন করে, অন্যথায় `false`।

```csharp
var identityA = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityB = identityA;
Authenticator.AreSameObject(identityA, identityB);
// => true

var identityC = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityD = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
Authenticator.AreSameObject(identityC, identityD);
// => false
```
