# নির্দেশনা সংযোজন

## কাজটি

দুটি প্রসিডিউর বাস্তবায়ন করুন।

- `custom_error_message message` একটি এরর রেইজ করে, আর `message` হলো এরর মেসেজ।
- `handle_error script` প্রদত্ত স্ক্রিপ্টটি রান করে এবং কী ঘটেছে তা বর্ণনা করে এমন একটি স্ট্রিং রিটার্ন করে:

  | স্ক্রিপ্টটি যখন… | রিটার্ন |
  | --- | --- |
  | শূন্য দিয়ে ভাগ করে | `"division by zero"` |
  | এমন একটি ফাইল খোলে যা নেই | `"file does not exist"` |
  | এমন একটি প্রসিডিউর কল করে যা নেই | `"proc does not exist"` |
  | অন্য যেকোনো এরর রেইজ করে | `"unknown error"` |
  | সফল হয় | `"success"` |

## এরর রেইজ করা

Tcl-এ এরর রেইজ করার দুটি কমান্ড আছে।

```tcl
error "something went wrong"
throw {MYAPP BADTHING} "something went wrong"
```

`throw`-এর প্রথম আর্গুমেন্ট হিসেবে একটি _এরর কোড_ লাগে।
এরর কোড হলো একটি লিস্ট, যা হ্যান্ডলারকে বলে দেয় কী ধরনের এরর ঘটেছে, যাতে মেসেজের টেক্সট পার্স না করেই সে সাড়া দিতে পারে।
এর ভেতরে কী থাকবে তা আপনার ইচ্ছা: `{MYAPP BADTHING}` কেবল একটি উদাহরণ, খালি নয় এমন যেকোনো লিস্টই চলবে।
প্রথা অনুযায়ী এটি সাধারণ থেকে নির্দিষ্টের দিকে সাজানো থাকে।
হ্যান্ডলার মিলে যাওয়া `try ... trap` প্যাটার্ন দিয়ে এটি ধরে (নিচে বর্ণনা করা হয়েছে), যেমন `trap {MYAPP BADTHING}`, অথবা প্রতিটি `MYAPP` এরর ধরতে `trap {MYAPP}`।
`error` তৃতীয় আর্গুমেন্ট হিসেবে ঐচ্ছিক একটি এরর কোড নেয়: `error message ?info? ?code?`।

## `catch` দিয়ে এরর হ্যান্ডেল করা

[`catch`][catch] একটি স্ক্রিপ্ট রান করে এবং এরর রেইজ না করে বরং একটি ইন্টিজার _কমপ্লিশন কোড_ রিটার্ন করে:

| কোড | অর্থ |
| --- | --- |
| 0 | `ok` |
| 1 | `error` |
| 2 | `return` |
| 3 | `break` |
| 4 | `continue` |

```tcl
if {[catch {expr {1 / 0}} result options] == 1} {
    puts "error message: $result"
    puts "error code:    [dict get $options -errorcode]"
}
```
```none
error message: divide by zero
error code:    ARITH DIVZERO {divide by zero}
```

ঐচ্ছিক দ্বিতীয় আর্গুমেন্টটি ফলাফল (বা এরর মেসেজ) গ্রহণ করে।
ঐচ্ছিক তৃতীয় আর্গুমেন্টটি একটি _অপশন ডিকশনারি_ গ্রহণ করে, যাতে থাকে `-errorcode` এবং `-errorinfo` (স্ট্যাক ট্রেস)।

সুবিধা:

- এটি ছোট এবং নমনীয়।
- সহজ ক্ষেত্রে এটি সংক্ষিপ্ত, যেমন `if {[catch {open $f} fh]} {...}`।

অসুবিধা:

- কমপ্লিশন কোডটি আপনাকে নিজেই পরীক্ষা করতে হয়।
  অসতর্কভাবে লেখা `if {[catch ...] != 0} { handle error }` `return`, `break` ও `continue`-কেও এরর হিসেবে ধরে নেয়।
- আপনি যে এররগুলো হ্যান্ডেল করেন না, সেগুলো গিলে ফেলা হয়, যদি না আপনি নিজেই সেগুলো আবার রেইজ করেন।
- স্ক্রিপ্ট ব্যর্থ হোক বা না হোক, ক্লিনআপ কোড চালানোর কোনো বিল্ট-ইন উপায় নেই।

## `try` দিয়ে এরর হ্যান্ডেল করা

[`try`][try] একটি স্ক্রিপ্ট রান করে এবং ফলাফলটি প্রথম মিলে যাওয়া হ্যান্ডলারের কাছে পাঠায়।
ঐচ্ছিক `finally` ক্লজটি সব সময় রান হয়, তাই ফাইল চ্যানেলের মতো রিসোর্স ছেড়ে দেওয়ার জন্য এটি ভালো জায়গা।

```tcl
set fh [open $filename r]
try {
    set data [read $fh]
} on error {msg options} {
    puts "could not read $filename: $msg"
} finally {
    close $fh
}
```

সুবিধা:

- গঠনটি পরিষ্কার: প্রতিটি ধরনের ফলাফলের জন্য একটি হ্যান্ডলার।
- `finally` সব সময় রান হয়।
- কোনো হ্যান্ডলারের সাথে না মেলা ফলাফল অপরিবর্তিত অবস্থায় কলারের কাছে পাঠিয়ে দেওয়া হয়।

অসুবিধা:

- সহজ ক্ষেত্রে এটি `catch`-এর চেয়ে একটু বেশি লম্বা।

### `try ... on` বনাম `try ... trap`

হ্যান্ডলার দুই ধরনের।

`on code {msgVar optionsVar}` _কমপ্লিশন কোডের_ সাথে মেলে: `ok`, `error`, `return`, `break` বা `continue`।
প্রতিটি এররের কমপ্লিশন কোড `error`, তাই `on error` শূন্য দিয়ে ভাগ আর অনুপস্থিত ফাইলের পার্থক্য করতে পারে না।
তাহলে মেসেজের টেক্সট দেখতে হয়, যা ভঙ্গুর: মেসেজগুলো মানুষের জন্য লেখা, আর Tcl-এর ভার্সন বদলালে সেগুলো বদলে যেতে পারে।

```tcl
try {
    expr {$a / $b}
} on error {msg} {
    if {[string match "*divide by zero*" $msg]} { ... }
}
```

`trap pattern {msgVar optionsVar}` _এরর কোডের_ সাথে মেলে।
প্যাটার্নটি `-errorcode` লিস্টের প্রিফিক্স হলে হ্যান্ডলারটি মেলে।
এতে এররের ধরন নির্ভরযোগ্যভাবে শনাক্ত করা যায়।

```tcl
try {
    expr {$a / $b}
} trap {ARITH DIVZERO} {} {
    puts "division by zero"
} trap {} {msg} {
    puts "some other error: $msg"
}
```

খালি প্যাটার্ন `trap {}` যেকোনো এররের সাথে মেলে।
হ্যান্ডলারগুলো ক্রম অনুযায়ী পরীক্ষা করা হয়, তাই সবকিছু ধরার হ্যান্ডলারটি সবার শেষে রাখুন।

## এরর কোড খুঁজে বের করা

`ARITH DIVZERO` কোথায় ডকুমেন্ট করা আছে?
বেশিরভাগ ক্ষেত্রেই কেবল সোর্স কোডে, তবে Tcl আপনাকে এটি দেখিয়ে দেবে।
কোনো এররের পর গ্লোবাল ভ্যারিয়েবল `errorCode`-এ সর্বশেষ এররের এরর কোড থাকে:

```none
$ tclsh
% set a 1; set b 0
% expr {$a / $b}
divide by zero
% set errorInfo     ;# this is the stack trace
divide by zero
    while executing
"expr {$a / $b}"
% set errorCode     ;# this is what we're after
ARITH DIVZERO {divide by zero}
```

প্রোগ্রামের ভেতর থেকে এটি অপশন ডিকশনারি থেকে পাওয়া যায়:

```tcl
try {
    expr {$a / $b}
} on error {msg options} {
    puts [dict get $options -errorcode]
}
```

এরর কোডের শেষ এলিমেন্টটি প্রায়ই মানুষের পড়ার উপযোগী একটি মেসেজ, অথবা যে জিনিসটি এরর ঘটিয়েছে তার নাম।
এটি আপনার `trap` প্যাটার্নের বাইরে রাখুন: `{ARITH DIVZERO}` দিয়ে trap করুন, `{ARITH DIVZERO {divide by zero}}` দিয়ে নয়।

### কিছু কমন এরর কোড

এই টেবিলটি সম্পূর্ণ নয়।
অন্য যেকোনো এররের কোড খুঁজতে উপরের কৌশলটি ব্যবহার করুন।

| পরিস্থিতি | উদাহরণ | এরর কোড |
| --- | --- | --- |
| শূন্য দিয়ে ভাগ | `expr {1 / 0}` | `ARITH DIVZERO ...` |
| ম্যাথ ডোমেইন এরর | `expr {sqrt(-1)}` | `ARITH DOMAIN ...` |
| ফাইল পাওয়া যায়নি | `open nosuchfile r` | `POSIX ENOENT ...` |
| অনুমতি নেই | `open /root/x w` | `POSIX EACCES ...` |
| অজানা কমান্ড | `no::such::proc` | `TCL LOOKUP COMMAND name` |
| অজানা ভ্যারিয়েবল | `set nosuchvar` | `TCL LOOKUP VARNAME name` |
| আর্গুমেন্টের সংখ্যা ভুল | `string length a b` | `TCL WRONGARGS` |
| অবৈধ ডিকশনারি | `dict size {1 2 3}` | `TCL VALUE DICTIONARY` |
| অবৈধ লিস্ট | `llength "a \{b"` | `TCL VALUE LIST ...` |

`POSIX` এরর কোডগুলো অপারেটিং সিস্টেমের `errno` নাম ব্যবহার করে, যেমন `ENOENT`, `EACCES` এবং `EEXIST`।

## ইঙ্গিত: স্ক্রিপ্টটি কোথায় রান হয়

`handle_error` তার কলারের কাছ থেকে একটি স্ক্রিপ্ট পায়।
আপনি যদি এটি `try $script` দিয়ে রান করেন, তবে এটি কলারের স্কোপে নয়, `handle_error`-এর স্কোপে ইভ্যালুয়েট হয়।
এটি যেখানে লেখা হয়েছে সেখানে ইভ্যালুয়েট করতে [`uplevel`][uplevel] ব্যবহার করুন: `try {uplevel 1 $script} ...`।
