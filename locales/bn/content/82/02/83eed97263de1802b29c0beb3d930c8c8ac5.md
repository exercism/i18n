# প্র্যাকটিস অনুশীলনী

[প্র্যাকটিস অনুশীলনী](/docs/building/product/practice-exercises) হলো এমন অনুশীলনী যা শিক্ষার্থীদের যেকোনো সমস্যা সমাধান করার সুযোগ দেয়, যার উদ্দেশ্য হলো তারা এতদিন যে কনসেপ্টগুলো শিখেছে সেগুলো কাজে লাগাতে পারবে।

একটি ট্র্যাকে নিজের প্রথম প্র্যাকটিস অনুশীলনী যোগ করতে আগ্রহী? [প্র্যাকটিস অনুশীলনী যোগ করার ডকুমেন্টেশন](/docs/building/tracks/practice-exercises/add) দেখুন অথবা আমাদের ওয়াকথ্রু ভিডিওটি দেখুন 👇

[video:vimeo/906101866?h=2954ad331e]()

````exercism/note
ট্র্যাকের রুট ডিরেক্টরি থেকে নিচের কমান্ডগুলো চালিয়ে আপনি দ্রুত একটি নতুন প্র্যাকটিস অনুশীলনীর কাঠামো তৈরি করতে পারেন:

```shell
bin/fetch-configlet
bin/configlet create --practice-exercise <slug>
```

আরও তথ্যের জন্য [`configlet create` ডকুমেন্টেশন](/docs/building/configlet/create) দেখুন
````

## মেটাডেটা

প্র্যাকটিস অনুশীলনীর মেটাডেটা [config.json ফাইল](/docs/building/tracks/config-json)-এর `exercises.practice` কী-তে সংজ্ঞায়িত করা হয়। এই মেটাডেটা অনুশীলনীর UUID, স্লাগ এবং আরও অনেক কিছু নির্ধারণ করে।

### উদাহরণ

```json
{
  "exercises": {
    "practice": [
      {
        "uuid": "8ba15933-29a2-49b1-a9ce-70474bad3007",
        "slug": "leap",
        "name": "Leap",
        "practices": ["if-statements", "numbers", "operator-precedence"],
        "prerequisites": ["if-statements", "numbers"],
        "difficulty": 1
      }
    ]
  }
}
```

### `practices`

`practices` কী-তে সেই কনসেপ্টগুলোর স্লাগের তালিকা থাকা উচিত, যেগুলো এই প্র্যাকটিস অনুশীলনীটি একজন শিক্ষার্থীকে সক্রিয়ভাবে চর্চা করার সুযোগ দেয়।

- এগুলো UI-তে "Practice this Concept in: TwoFer, Leap, etc" হিসেবে দেখানো হয়
- প্রতিটি কনসেপ্ট চর্চার জন্য ৩ থেকে ৮টি অনুশীলনী বেছে নেওয়ার চেষ্টা করুন।
- এমন অন্তত দুটি অনুশীলনী বেছে নেওয়ার চেষ্টা করুন, যেগুলোতে কেউ একটি কনসেপ্টের মূল বিষয়গুলো চর্চা করতে পারে।
- কিছু কনসেপ্ট খুবই কমন (যেমন `strings`)। সেক্ষেত্রে আমরা এমন কয়েকটি ভালো অনুশীলনী বেছে নেওয়ার পরামর্শ দিই, যেগুলো মানুষকে মজার উপায়ে সেই কনসেপ্টগুলো নিয়ে ভাবতে বাধ্য করে। যেমন, যেসব অনুশীলনীতে UTF-8, স্ট্রিং কনক্যাটেনেশন, char এনুমারেশন ইত্যাদির প্রয়োজন হয়, সেগুলো সবই ভালো উদাহরণ হতে পারে।

### `prerequisites`

`prerequisites` কী-তে সেই কনসেপ্টগুলোর তালিকা থাকে, যা একজন শিক্ষার্থীকে এই প্র্যাকটিস অনুশীলনীটি পাওয়ার জন্য আগে শেষ করতে হবে।

- এগুলো UI-তে "Learn Strings to unlock TwoFer" হিসেবে দেখানো হয়
- এতে সেই সব কনসেপ্ট থাকা উচিত, যা একজন শিক্ষার্থীর অন্তত একটি আইডিওম্যাটিক উপায়ে অনুশীলনীটি শেষ করতে জানা দরকার। যেমন, Ruby-তে TwoFer অনুশীলনীর ক্ষেত্রে পূর্বশর্ত হিসেবে `strings`, `optional-params`, `implicit-return` থাকতে পারে।
- যে অনুশীলনীগুলো বিকল্প কনসেপ্ট ব্যবহার করে শেষ করা যায় (যেমন `loops` বা `recursion` দিয়ে সমাধানযোগ্য একটি অনুশীলনী), সেগুলোর ক্ষেত্রে মেইনটেইনার শিক্ষার্থীর ট্র্যাক জুড়ে যাত্রার কথা মাথায় রেখে এমন একটি অ্যাপ্রোচ বেছে নেবেন যা দিয়ে তারা সেই অনুশীলনীটি আনলক করতে চান। যেমন, লুপ/রিকার্সনের উদাহরণে তারা ভাবতে পারেন এই অনুশীলনীটি `loops`-এর শুরুর দিকের চর্চার জন্য ভালো, অথবা তারা এটিকে পরে রেখে রিকার্সন শেখাতে চাইতে পারেন। বিকল্প অ্যাপ্রোচ চেষ্টা করতে শিক্ষার্থীকে উৎসাহ দিতে তারা একটি অ্যানালাইজারও কাজে লাগাতে পারেন: "লুপ দিয়ে এটি সমাধান করার জন্য দারুণ কাজ। আপনি চাইলে রিকার্সন ব্যবহার করেও এটি সমাধান করে দেখতে পারেন।"

## ফাইল

প্রতিটি প্র্যাকটিস অনুশীলনীর জন্য ট্র্যাকের `exercises/practice` ডিরেক্টরির ভেতরে আলাদা ডিরেক্টরি থাকে। প্র্যাকটিস অনুশীলনীর ডিরেক্টরির নাম অবশ্যই অনুশীলনীর `slug` প্রপার্টির সাথে মিলতে হবে, যেমনটি [config.json ফাইল](/docs/building/tracks#concept-exercises)-এ সংজ্ঞায়িত করা আছে।

একটি প্র্যাকটিস অনুশীলনীতে চার ধরনের ফাইল থাকে:

### ডকুমেন্টেশন ফাইল

এই ফাইলগুলো শিক্ষার্থীকে দেখানো হয়, যাতে অনুশীলনীটি বুঝতে সাহায্য হয়।

- `.docs/introduction.md`: অনুশীলনীর পরিবেশ ও পটভূমি তুলে ধরে (ঐচ্ছিক)
- `.docs/introduction.append.md`: বিদ্যমান পরিচিতির পরে যোগ করার জন্য অতিরিক্ত পরিচিতি টেক্সট (ঐচ্ছিক)
- `.docs/instructions.md`: অনুশীলনীর নির্দেশনা দেয় (আবশ্যিক)
- `.docs/instructions.append.md`: বিদ্যমান নির্দেশনার পরে যোগ করার জন্য অতিরিক্ত পরিচিতি টেক্সট (ঐচ্ছিক)
- `.docs/hints.md`: অনুশীলনীতে আটকে গেলে শিক্ষার্থীকে এগিয়ে যেতে সাহায্য করার জন্য সংকেত দেয় (ঐচ্ছিক)

### মেটাডেটা ফাইল

এই ফাইলগুলো শিক্ষার্থীকে দেখানো হয় _না_, বরং অনুশীলনীর মেটাডেটা নির্ধারণে ব্যবহৃত হয়।

- `.meta/config.json`: অনুশীলনীর মেটা তথ্য ধারণ করে (আবশ্যিক)
- `.meta/design.md`: অনুশীলনীর ডিজাইন বর্ণনা করে (ঐচ্ছিক)
- `.meta/tests.toml`: কোন টেস্টগুলো বাস্তবায়ন করা হয়েছে তার তথ্য ধারণ করে (ঐচ্ছিক)

### অ্যাপ্রোচ ফাইল

এই ফাইলগুলো অনুশীলনীর অ্যাপ্রোচগুলো বর্ণনা করে।

- `.approaches/introduction.md`: অনুশীলনীর সবচেয়ে কমন অ্যাপ্রোচগুলোর পরিচিতি (ঐচ্ছিক)
- `.approaches/config.json`: অ্যাপ্রোচগুলোর মেটাডেটা (ঐচ্ছিক)
- `.approaches/<approach-slug>/content.md`: অ্যাপ্রোচের বর্ণনা (ঐচ্ছিক)
- `.approaches/<approach-slug>/snippet.txt`: অ্যাপ্রোচটি তুলে ধরা ছোট একটি স্নিপেট (ঐচ্ছিক)

### আর্টিকেল ফাইল

এই ফাইলগুলো অনুশীলনীর আর্টিকেলগুলো বর্ণনা করে।

- `.articles/config.json`: আর্টিকেলগুলোর মেটাডেটা (ঐচ্ছিক)
- `.articles/<article-slug>/content.md`: আর্টিকেলের বর্ণনা (ঐচ্ছিক)
- `.articles/<article-slug>/snippet.md`: আর্টিকেলটি তুলে ধরা ছোট একটি স্নিপেট (ঐচ্ছিক)

### অনুশীলনীর ফাইল

ভাষা-নির্দিষ্ট ফাইল, যেমন ইমপ্লিমেন্টেশন ও টেস্ট ফাইল। এই ফাইলগুলোর নাম ট্র্যাক-নির্দিষ্ট।

- টেস্ট স্যুট: একটি সলিউশনের সঠিকতা যাচাই করে।
- স্টাব ইমপ্লিমেন্টেশন: শিক্ষার্থীদের জন্য শুরুর একটি বিন্দু তৈরি করে।
- উদাহরণ ইমপ্লিমেন্টেশন: এমন একটি উদাহরণ ইমপ্লিমেন্টেশন দেয় যা সব টেস্ট পাস করে।
- অতিরিক্ত ফাইল: টেস্টগুলো যাতে চালানো যায় তা নিশ্চিত করে।

### ফাইল: `.docs/introduction.md`

**উদ্দেশ্য:** শিক্ষার্থীর কাছে অনুশীলনীর পরিবেশ ও পটভূমি তুলে ধরা।

**উপস্থিতি:** অনুশীলনীটি যদি `introduction.md` ফাইলসহ কোনো প্রবলেম স্পেসিফিকেশন অনুশীলনী বাস্তবায়ন করে, তবে আবশ্যিক

অনুশীলনীটি যদি একটি [প্রবলেম স্পেসিফিকেশন অনুশীলনী](https://github.com/exercism/problem-specifications/) বাস্তবায়ন করে, তবে এই ফাইলের বিষয়বস্তু প্রবলেম স্পেসিফিকেশন অনুশীলনীর `introduction.md` ফাইলের সাথে মিলতে হবে। configlet-এ স্বয়ংক্রিয়ভাবে এই ফাইলের [বিষয়বস্তু সিঙ্ক করার](/docs/building/configlet/generating-documents#document-practice-exercises-introductionmd-file) সুবিধা আছে।

অনুশীলনীটি যদি প্রবলেম স্পেসিফিকেশন অনুশীলনীর উপর ভিত্তি করে তৈরি _না_ হয়, তবে নিচের বিষয়গুলো ভেবে দেখুন:

Exercism-এর কনটেন্ট সবার জন্য নিরাপদ করা আমাদের কাছে খুবই গুরুত্বপূর্ণ, তাই কোনো গল্প উপযুক্ত কি না তা ঠিক করার সময় আমরা প্রায়ই বাড়তি সতর্কতা অবলম্বন করি। আমরা যা মার্জ করি সে বিষয়ে সতর্ক থাকলেও, কোনটা সমস্যাযুক্ত মনে হতে পারে তা বোঝা কঠিন, এটা আমরা স্বীকার করি; তাই আমরা সবসময় ধরে নেব আপনি ভালো উদ্দেশ্যেই কাজ করছেন এবং রিভিউয়ের সময় কোনো সমস্যা থাকলে তা সংঘাতমুক্তভাবে ধরার সর্বোচ্চ চেষ্টা করব। আপনি যদি আমাদের সাথে কোনো গল্প যাচাই করতে চান, তবে @exercism/leadership-কে মেনশন করুন, আমরা একসাথে দেখব। এখানে কয়েকটি নির্দেশনা:

- গল্পটি যেন সবার জন্য স্বাগতপূর্ণ হয় এবং সবাই বুঝতে পারে তা নিশ্চিত করার চেষ্টা করুন। গল্পে যদি শুধু একটি নির্দিষ্ট গোষ্ঠীর বোঝা রসিকতা বা আঞ্চলিক চলিত ভাষা থাকে, তবে বিকল্প বাক্যাংশের কথা ভাবুন।
- এমন উদাহরণ লেখার চেষ্টা করুন যা সবাইকে অন্তর্ভুক্ত করে। যেমন, ভিন্ন সংস্কৃতির নাম এবং নারী-পুরুষ মিশিয়ে ব্যবহার করার কথা ভাবুন।

- সংকেতগুলোতে কনসেপ্ট বোঝাতে কোড নমুনা ব্যবহার করা যেতে পারে, কিন্তু সলিউশনের রূপরেখা দিতে নয়। যেমন একটি লিস্ট-সংক্রান্ত অনুশীলনীতে কোনো নির্দিষ্ট লিস্ট ফাংশন কীভাবে কাজ করে তার একটি স্নিপেট দেখানো যেতে পারে, তবে এমনভাবে নয় যাতে সেটি সরাসরি সলিউশনে কপি/পেস্ট করা যায়।

````markdown
# Introduction

The key to this exercise is to deal with C# strings being immutable, which means that a `string`'s value cannot be changed.
Therefore, to reverse a string you'll need to create a _new_ `string`.

## Using LINQ

```csharp
public static string Reverse(string input)
{
    return new string(input.Reverse().ToArray());
}
```

If readability is your primary concern (and it usually should be), the LINQ-based approach is hard to beat.
````

### ফাইল: টেস্ট

**উদ্দেশ্য:** একটি সলিউশনের সঠিকতা যাচাই করা।

**উপস্থিতি:** আবশ্যিক

- কোডটি যতটা সম্ভব সহজ হওয়া উচিত।
- কেবল অনুশীলনীর পূর্বশর্তে (আর তাদের পূর্বশর্তে, এভাবে চলতে থাকবে) চালু করা ভাষার ফিচারগুলো ব্যবহার করুন।
- ব্রাউজারে কোডিং করার সময় টেস্ট ফাইলটি শিক্ষার্থীকে দেখানো হয় এবং CLI ব্যবহার করার সময় শিক্ষার্থীর ফাইল সিস্টেমে ডাউনলোড করা হয়।
- Exercism চায় প্র্যাকটিস অনুশীলনীগুলো Test Driven Development-এর মাধ্যমে সম্পন্ন হোক। এটি অর্জনের জন্য দুটি উপায় আছে:
  - টেস্ট রানারকে ফাইলে সংজ্ঞায়িত ক্রমে টেস্ট চালাতে হবে এবং টেস্ট স্যুটকে প্রথম ব্যর্থতাতেই থেমে যেতে হবে; অথবা
  - প্রথম টেস্ট ছাড়া বাকি সব টেস্ট ডিফল্টভাবে স্কিপ করা উচিত।
- টেস্ট ফাইলের আপেক্ষিক পাথ [`.meta/config.json` ফাইলের `"files.test"` কী](./#filemetaconfigjson)-তে উল্লেখ করতে হবে।

#### উদাহরণ

```csharp
using Xunit;

public class IsogramTest
{
    [Fact]
    public void Empty_string() =>
        Assert.True(Isogram.IsIsogram(""));

        Assert.True(Isogram.IsIsogram("isogram"));

        Assert.False(Isogram.IsIsogram("eleven"));
```

### ফাইল: উদাহরণ ইমপ্লিমেন্টেশন

**উদ্দেশ্য:** এমন একটি উদাহরণ ইমপ্লিমেন্টেশন দেওয়া যা সব টেস্ট পাস করে।

**উপস্থিতি:** আবশ্যিক

- এই ইমপ্লিমেন্টেশন দিয়ে যাচাই করা হয় যে টেস্ট পাস করে এমন একটি ইমপ্লিমেন্টেশন আছে। এটি ইচ্ছাকৃতভাবেই সেই লক্ষ্য কোড _নয়_ যা আমরা শিক্ষার্থীর কাছ থেকে আশা করি।
- প্রতিটি ট্র্যাকের উচিত তাদের Continuous Integration সেটআপে যাচাই করা যে উদাহরণ ইমপ্লিমেন্টেশনটি টেস্ট পাস করে।
- মেন্টরদের এই কোডটি দেখানো হবে না।
- ব্রাউজারে কোডিং করার সময় শিক্ষার্থীকে উদাহরণ ফাইলটি দেখানো হয় _না_ এবং CLI ব্যবহার করার সময় শিক্ষার্থীর ফাইল সিস্টেমে ডাউনলোডও করা হয় _না_।
- উদাহরণ ইমপ্লিমেন্টেশন ফাইলের আপেক্ষিক পাথ [`.meta/config.json` ফাইলের `"files.example"` কী](./#filemetaconfigjson)-তে উল্লেখ করতে হবে।

#### উদাহরণ

```csharp
using System.Linq;

public static class Isogram
{
    public static bool IsIsogram(string word)
    {
        var lowerCaseLetters = word.ToLower().Where(char.IsLetter).ToList();
        return lowerCaseLetters.Distinct().Count() == lowerCaseLetters.Count;
    }
}
```

### ফাইল: অতিরিক্ত ফাইল

**উদ্দেশ্য:** টেস্ট চালানোর জন্য প্রয়োজনীয় অতিরিক্ত প্রজেক্ট, বিল্ড বা সহায়ক ফাইল।

**উপস্থিতি:** টেস্ট চালানোর জন্য ডিফল্ট ফাইল যথেষ্ট না হলে আবশ্যিক

কিছু ভাষায় টেস্ট চালানোর জন্য অতিরিক্ত ফাইল লাগে। এর উদাহরণ হলো C#-এর প্রজেক্ট ফাইল এবং Node-এর `package.json` ফাইল, যা ছাড়া টেস্ট চালানো সম্ভব হবে না।
