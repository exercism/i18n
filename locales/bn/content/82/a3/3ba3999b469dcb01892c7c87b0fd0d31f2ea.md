# ইমিউটেবল ক্লাস

```sather
immutable class BEARING is
   readonly attr degrees : INT;
   create(d : INT) : SAME is
      b : SAME;
      return b.degrees(d);
   end;
end;
```

## কী কী বদলায়

| | সাধারণ ক্লাস | ইমিউটেবল ক্লাস |
| --- | --- | --- |
| অ্যাসাইনমেন্ট | অবজেক্ট শেয়ার করে | মান কপি করে |
| void হওয়া | হ্যাঁ | না |
| `attr` রাইটার | `x.a := v` | `x := x.a(v)` |
| `new` | হ্যাঁ | না; `x : SAME` আগে থেকেই আছে |

একটি ইমিউটেবল অবজেক্ট কখনও void হতে পারে না, তাই `void(b)` সবসময় ফলস, আর ইমিউটেবল অবজেক্টের কোনো রুটিন অবজেক্টের অভাবে ব্যর্থ হতে পারে না। এতে একগুচ্ছ ভুল একবারেই দূর হয়ে যায়, কিন্তু বিনিময়ে "এখনও কোনো bearing নেই" বলার সুযোগটা আর থাকে না।

## মানটি কোথায় থাকে

মানটি ভ্যারিয়েবল যেখানে আছে সেখানেই জমা থাকে, অর্থাৎ অন্য কোনো অবজেক্টের ভেতরে বা স্ট্যাকে, কোনো রেফারেন্স দিয়ে পৌঁছানোর বদলে। তাই একটি `ARRAY{BEARING}` bearingগুলোকে নিজেই ধরে রাখে, সেগুলোর পয়েন্টার নয়, যা আকারে ছোট এবং ঘুরে দেখতে দ্রুততর।

খরচটা হলো কপি করা: বড় একটি ইমিউটেবল অবজেক্ট পাঠালে প্রতিবারই সেটি কপি হয়। তাই এগুলো ছোট রাখাই ভালো।

## অ্যাট্রিবিউট রুটিনগুলো

`readonly attr degrees : INT` দুটি রুটিন দেয়:

```sather
   b.degrees          -- read: INT
   b.degrees(90)      -- answer a new BEARING with degrees changed
```

দ্বিতীয়টি `readonly` থাকা সত্ত্বেও থাকে, কারণ এটি কিছুই বদলায় না, বরং একটি নতুন মান তৈরি করে। সাধারণ `attr`-এর অধীনে এটি পাবলিক; `private attr`-এর অধীনে নয়।

## is_eq আর str

কোনোটিই দেওয়া নেই। `=` অপারেটরের জন্য `is_eq` লিখুন, আর `str` লিখুন যাতে অবজেক্টটি প্রিন্ট করা যায় এবং স্ট্রিংয়ের সাথে যোগ করা যায়:

```sather
   is_eq(other : SAME) : BOOL is return degrees = other.degrees; end;
   str : STR is return degrees.str + " degrees"; end;
```

`str` লিখলে ক্লাসটি `$STR`-এর সাথে কনফর্ম করে, আর এই কারণেই `+` এবং `#OUT` এটিকে গ্রহণ করে।

## বিল্ট-ইনগুলো

`INT`, `BOOL`, `CHAR`, `FLTD` এবং `TUP` সবই ইমিউটেবল ক্লাস। এদের নিয়ে বিশেষ কিছু নেই: লাইব্রেরিতে এগুলোও ঠিক একইভাবে Sather-এ লেখা, আর উপরের কারণগুলোতেই এরা যেমন আচরণ করে তেমনই আচরণ করে।
