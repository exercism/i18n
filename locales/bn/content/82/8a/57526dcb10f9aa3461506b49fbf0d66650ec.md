# সম্পর্কে

হাতে লেখা অ্যাসেম্বলি পুনরাবৃত্তিতে ভরা।
একই ছোট নির্দেশনা-সারি সামান্য ভিন্নতায় বারবার ফিরে আসে, আর বয়লারপ্লেট কমিয়ে আনার মতো অ্যাবস্ট্রাকশন খুবই কম।
শুধু তা-ই নয়, অ্যাসেম্বলিতে কোড লেখার সময় এমন মান সামলাতে হয় যাদের স্পষ্ট কোনো অর্থ নেই।
নামযুক্ত কোনো প্যারামিটার নেই, আর অন্তর্নিহিত কার্যপ্রণালীর বেশিরভাগ খুঁটিনাটি প্রোগ্রামারকে নিজ হাতে সামলাতে হয়।

এই ট্র্যাকে ব্যবহৃত অ্যাসেম্বলার NASM কিছু টুল দেয়, যা প্রোগ্রামারকে এই দুই সমস্যাতেই সাহায্য করতে পারে।
এই টুলগুলো কাজ করে _অ্যাসেম্বল টাইমে_, কোনো নির্দেশনা প্রসেসরে পৌঁছানোর আগেই।
মেশিন কোডে অনূদিত হওয়ার আগেই সোর্স টেক্সট কীভাবে নতুন করে লিখতে হবে, তা এগুলো অ্যাসেম্বলারকে দেখিয়ে দেয়।

এদের মধ্যে সবচেয়ে গুরুত্বপূর্ণ হলো **ম্যাক্রো**, যাকে অ্যাসেম্বলারের জন্য একটি রেসিপি ভাবা যায়।
এগুলো যেখানে ব্যবহার করা হয় সেখানেই প্রসারিত হয়, যেন কোডটি সেখানে হাতে লেখা হয়েছে।

[ম্যাক্রো][macro] প্যারামিটার হিসেবে বেশ কিছু লিটারাল টোকেন নিতে পারে, যা তাদের বিভিন্ন প্রসঙ্গে পুনর্ব্যবহারযোগ্য করে তোলে।
তবে এগুলো ফাংশন নয়: কোনো `call` নেই, কোনো `ret` নেই, কোডের অন্য কোনো বিন্দুতে নিয়ন্ত্রণ হস্তান্তরও নেই।

## এক-লাইন ম্যাক্রো

সবচেয়ে সরল সংজ্ঞা `%define` দিয়ে একটি মান বা ছোট এক্সপ্রেশনের একটি নাম দেয়:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

অ্যাসেম্বলির আগেই `WIDTH`-এর পরের প্রতিটি উপস্থিতি `8` দিয়ে প্রতিস্থাপিত হয়।
প্রতিস্থাপনটি টেক্সটভিত্তিক, তাই নামটি যেখানেই থাকুক না কেন প্রতিস্থাপিত হয়, তা অপারেন্ডে হোক বা অন্য কোনো সংজ্ঞার ভেতরে।

~~~~exercism/note
সংখ্যাগত _কনস্ট্যান্টের_ জন্য `%define`-এর বদলে `equ` ব্যবহার করাই ভালো।

`%define` দিয়ে ঘোষিত এক-লাইন ম্যাক্রো কেবল ব্যবহারের সময়ই প্রসারিত হয়, আর সেটি আবার অ্যাসাইন করা বা আনডিফাইন করা যায়।
অন্যদিকে একটি `equ` কনস্ট্যান্ট সংজ্ঞার জায়গাতেই মূল্যায়িত হয় এবং কখনো পরিবর্তিত হয় না।
~~~~

একটি `%define` _নামযুক্ত_ প্যারামিটারও নিতে পারে, যা ছোট একটি ইনলাইন ফাংশনের মতো আচরণ করে:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
পুরো বডি এবং প্রতিটি প্যারামিটার দুটোই বন্ধনীতে মুড়ে দিন।
`%define square(x) x*x` লিখলে `square(1+1)` কলটি প্রসারিত হয়ে `1+1*1+1` হয়, যার মান `3`।
`%define square(x) ((x)*(x))` লিখলে একই কলটি প্রসারিত হয়ে `((1+1)*(1+1))` হয়, যার মান `4`।
~~~~

`%define` দিয়ে সংজ্ঞায়িত নাম কেস-সেনসিটিভ।
ভ্যারিয়েন্ট `%idefine` চাইলে নামটিকে কেস-ইনসেনসিটিভ করে তোলে।

কোডের বিভিন্ন অংশকে অর্থবহ করে তুলতে এক-লাইন ম্যাক্রো কাজে লাগে।
সাবধানে ব্যবহার করলে এটি পড়ার সহজতা বাড়ায় এবং টাইপো হওয়ার সম্ভাবনা কমায়।
উদাহরণস্বরূপ, কোনো ফাংশনের ভেতরে নির্দিষ্ট কাজে ব্যবহৃত একটি রেজিস্টারকে তার উদ্দেশ্য দিয়ে সংজ্ঞায়িত করা যায়:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## মাল্টি-লাইন ম্যাক্রো

যেকোনো সংখ্যক লাইনসহ কোডের পুরো একটি ক্রম `%macro` দিয়ে ধরা হয়, আর শেষ হয় `%endmacro` দিয়ে।
নামের পরে একটি সংখ্যা বোঝায় ম্যাক্রোটি কতটি আর্গুমেন্ট নেয়, যা শূন্যও হতে পারে।
আর্গুমেন্ট পাস করা হলে সেগুলো কমা (`,`) দিয়ে আলাদা করা হয়:

```x86asm
%macro example_macro 0
...
%endmacro
```

মাল্টি-লাইন ম্যাক্রোর আর্গুমেন্টের নাম থাকে না।
পাস করার ক্রম অনুযায়ী এদের `%1`, `%2` ইত্যাদি নামে ডাকা হয়:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

মনে রাখবেন, ম্যাক্রোর বডিতে যে অপারেশনগুলো করা হয় তার জন্য আর্গুমেন্টগুলো বৈধ সিনট্যাক্স হতে হবে।
এখানে `mult_two eax, ecx` আর `mult_two r8, r9` দুটোই অ্যাসেম্বল হয়, কিন্তু `mult_two eax, cl` হয় না, কারণ `imul eax, cl` সংজ্ঞায়িত নয়।

ম্যাক্রো ইচ্ছামতো সংখ্যক আর্গুমেন্টও নিতে পারে।
এটি করা হয় `n-*` নোটেশন দিয়ে, যেখানে `n` হলো আর্গুমেন্টের সর্বনিম্ন সংখ্যা:

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

মাল্টি-লাইন ম্যাক্রোতে `%0` বোঝায় ম্যাক্রোর আর্গুমেন্টের _সংখ্যা_।
এটি বিশেষভাবে কাজে লাগে এমন ম্যাক্রোতে যা ইচ্ছামতো সংখ্যক আর্গুমেন্ট নিতে পারে।

### ম্যাক্রোর ভেতরে লেবেল

যে ম্যাক্রো একটি সাধারণ লেবেল সংজ্ঞায়িত করে, সেটি দুবার ব্যবহার করলেই ভেঙে পড়ে, কারণ তখন লেবেলটিও দুবার সংজ্ঞায়িত হয়ে যায়।
একাধিকবার কল হতে পারে এমন ম্যাক্রোর ভেতরে লেবেল ব্যবহার করতে হলে লেবেলটির সামনে `%%` বসাতে হয়।
এটি অ্যাসেম্বলারকে নির্দেশ দেয় প্রতিবার প্রসারণে এই লেবেলকে ভিন্ন, অনন্য একটি নাম দিতে:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## অ্যাসেম্বল টাইমে পুনরাবৃত্তি

[`times`][times] ব্যবহার করে এক লাইনের কোড ব্লক পুনরাবৃত্তি করা সম্ভব।
মেমোরিতে পুনরাবৃত্ত মান ঘোষণা করার সময় এটি বিশেষভাবে কাজে লাগে:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

একাধিক লাইনের কোড পুনরাবৃত্তির জন্য এর বদলে `%rep` ব্যবহার করা যায়:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

মনে রাখবেন, পুনরাবৃত্তির সংখ্যা `%rep`-এর ঠিক পরেই লেখা হয় এবং পুনরাবৃত্ত ব্লকটি বন্ধ করার জন্য একটি `%endrep` থাকে।

রান-টাইম লুপ যেভাবে একটি কাউন্টার ব্যবহার করে, অনেকটা সেভাবেই `%rep` ব্লকের ভেতরে অ্যাসেম্বল-টাইম কাউন্টার ব্যবহার করা সাধারণ ব্যাপার।
আমরা যেমন ইতিমধ্যে দেখেছি, অ্যাসেম্বল-টাইম ইন্টিজার কনস্ট্যান্ট `equ` দিয়ে ঘোষণা করা যায়, কিন্তু অ্যাসেম্বল-টাইম ইন্টিজার _ভ্যারিয়েবলের_ জন্য এর বদলে `%assign` ব্যবহার করি।
`%define`-এর মতো নয়, `%assign` সঙ্গে সঙ্গে একটি সংখ্যায় মূল্যায়িত হয় এবং আবার অ্যাসাইন করা যায়:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

প্রিপ্রসেসর চলার পর লুপটি আর থাকে না, চারটি `add` নির্দেশনা থেকে যায়, আর ইমিডিয়েট `0`, `1`, `2` ও `3` সেগুলোর ভেতরে গেঁথে যায়।
এটাই অ্যাসেম্বলারের করা লুপ আনরোলিং: কোনো কাউন্টার রেজিস্টার নেই, কোনো ব্রাঞ্চ নেই, শুধু সোজা লাইনের কোড।

ইচ্ছামতো সংখ্যক আর্গুমেন্ট নিতে পারে এমন ম্যাক্রোতে আর্গুমেন্ট সামলাতে `%rep`-এর আরেকটি সাধারণ ব্যবহার আছে।
সেক্ষেত্রে `%rep` সাধারণত `%rotate`-এর সঙ্গে জোড়া লাগানো হয়, যা ম্যাক্রোতে আর্গুমেন্টগুলো ঘুরিয়ে দেয়, যাতে দ্বিতীয় আর্গুমেন্টটি প্রথমটি হয়ে যায়।
বারবার `%rotate` প্রয়োগ করলে তৃতীয়, তারপর চতুর্থ, এভাবে পরের আর্গুমেন্টগুলো প্রথম হয়ে যায়, ফলে প্রতিটি আর্গুমেন্ট একে একে সামলানো যায়:

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## শর্তসাপেক্ষ অ্যাসেম্বলি

[প্রিপ্রসেসরের][preprocessor] জন্য নানা ধরনের কন্ডিশনাল আছে।
এগুলো কয়েকটি ভিন্ন পথের মধ্যে একটি বেছে নেয়, নিজেদের বডি সেখানেই প্রসারিত করে, তবে কেবল যখন তাদের শর্ত সত্য হয়।

`%if` ... `%elif` ... `%else` ... `%endif` একটি সংখ্যাগত পরীক্ষা থেকে একটি শাখা বেছে নেয়:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef` আর `%ifndef` অনুরূপ, তবে পরীক্ষা করে একটি নাম সংজ্ঞায়িত হয়েছে কি না।
উদাহরণস্বরূপ, এগুলো দিয়ে নিশ্চিত করা যায় একটি ফাইলের বিষয়বস্তু কেবল একবারই অন্তর্ভুক্ত হয়, এমনকি যখন ফাইলটি একাধিক সোর্স কর্তৃক টেনে আনা হয়:

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

হয়তো খেয়াল করেছেন, এই ট্র্যাকের প্রতিটি `.asm` ফাইলের শেষে এই কোডটুকু থাকে:

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn` দুটি টেক্সটের হুবহু মিল আছে কি না তা তুলনা করে।
বিল্ট-ইন `__OUTPUT_FORMAT__` বর্তমান আউটপুট ফরম্যাটে প্রসারিত হয়, তাই ওই কোডটি পরীক্ষা করে আউটপুট ফরম্যাট `elf64` কি না, যা Linux সিস্টেমে ব্যবহৃত ফরম্যাট।
তা হলে অবজেক্ট ফাইলে একটি নোট যোগ করা হয়, যা স্ট্যাকের যে অনুমতিগুলো থাকা উচিত তা ঘোষণা করে, এটি একটি কমন নিরাপত্তা ব্যবস্থা।
না হলে কিছুই বদলায় না।

## স্ট্রাকচার

মেমোরিতে একটি রেকর্ডের কোনো ফিল্ডে পৌঁছাতে হলে ফিল্ডটির বাইট অফসেট বেস অ্যাড্রেসের সঙ্গে যোগ করতে হয়।
ওই অফসেটগুলো কাঁচা সংখ্যা হিসেবে লিখলে ভুলের সম্ভাবনা থাকে এবং তাদের অর্থ ঢাকা পড়ে যায়।
এর বদলে [`struc`][struc] আর `endstruc` একটি লেআউটের নাম দেয়, প্রতিটি ফিল্ডকে অ্যাসেম্বল টাইমে হিসাব করা একটি সিম্বলিক অফসেটে পরিণত করে।

ব্লকের ভেতরে `resb`, `resw`, `resd` ও `resq` রিজার্ভেশন ডিরেক্টিভগুলো এক বা একাধিক বাইট, ওয়ার্ড, ডাবলওয়ার্ড বা কোয়াডওয়ার্ড আলাদা করে রাখে।
প্রতিটি ফিল্ডের সামনে একটি `.` দিলে তার নাম স্ট্রাকচারের মধ্যেই সীমাবদ্ধ থাকে:

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

এখন প্রতিটি ফিল্ডের নাম তার অফসেট বোঝায়, তাই `thread.color` হলো `0`, `thread.tension` হলো `4`, আর `thread.name` হলো `12`।
NASM `<struc>_size`-কে মোট আকার হিসেবে সংজ্ঞায়িত করে, যেখানে `<struc>` হলো `struc`-এর নাম।
উদাহরণস্বরূপ, এখানে `thread_size` হবে `4 + 8 + 16 = 28`।

বেস রেজিস্টারের সঙ্গে ফিল্ডের অফসেট যোগ করে ফিল্ডে পৌঁছানো হয়, আর `thread_size` হলো এক রেকর্ড থেকে পরেরটিতে যাওয়ার স্ট্রাইড:

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

একটি `struc` কেবল একটি গঠন বর্ণনা করে, নিজে থেকে মেমোরি বরাদ্দ করে না।
ইনিশিয়ালাইজ করা একটি ইনস্ট্যান্স তৈরি করতে কোনো লেবেলের পরে `istruc ... iend` ব্যবহার করতে পারেন।
একটি ইনস্ট্যান্সের ভেতরে `at` নামযুক্ত কোনো ফিল্ডে একটি মান বসায়:

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

মনে রাখবেন, `thread.name` ইনিশিয়ালাইজ করা হয়েছে `"warp", 0` দিয়ে, যা মাত্র 5 বাইট নেয়।
`struc`-এ এর জন্য সংরক্ষিত বাকি 11 বাইট `iend` স্বয়ংক্রিয়ভাবে শূন্য দিয়ে ভরিয়ে দেয়, যা ইনস্ট্যান্সটিকে `0` দিয়ে `thread_size` পর্যন্ত প্যাড করে।

একটি `struc` হলো এমন মেমোরির সিনট্যাক্টিক সুগার মাত্র, যা হাতে করেও ঘোষণা করা যায়।
উদাহরণস্বরূপ, উপরের কোডটি নিচেরটির সমতুল্য, যেখানে `times 11 db 0` নিশ্চিত করে শেষে 16 বাইট বরাদ্দ হয়:

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## ফাইলে ভাগ করা

ম্যাক্রো প্রায়ই আলাদা একটি ফাইলে রাখা হয় এবং যেসব সোর্সের প্রয়োজন সেগুলোতে `%include` দিয়ে টেনে আনা হয়:

```x86asm
%include "patterns.mac"
```

নামযুক্ত ফাইলটি অ্যাসেম্বলির আগে ঠিক ওই জায়গাতেই হুবহু ঢোকানো হয়, যেন তার বিষয়বস্তু সেখানেই টাইপ করা হয়েছে।
এটি সংজ্ঞাগুলো একই জায়গায় রাখে এবং একাধিক সোর্স ফাইলকে সেগুলো ভাগ করে নিতে দেয়।

ম্যাক্রো ফাইলটি যদি আলাদাভাবে অ্যাসেম্বল হতে পারে, তবে তার `.asm` ফাইল এক্সটেনশন থাকা উচিত।
মনে রাখবেন, ম্যাক্রোর কোনো লিংকেজ থাকে না।
ম্যাক্রো ফাইলটি অ্যাসেম্বল হলেও এর ম্যাক্রোগুলো কেবল সেই অন্য ফাইলের কাছেই দৃশ্যমান, যে ফাইলটি এটি `%include` করে।

অন্যথায়, কেবল `%include` করার জন্য ব্যবহৃত ফাইলের যেকোনো ফাইল এক্সটেনশন থাকতে পারে।
`.asm` বা `.mac` যেটি ব্যবহার করাই একটি কমন রীতি।
