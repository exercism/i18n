## <a name="virtual-environments"></a>ভার্চুয়াল এনভায়রনমেন্ট

Python-এর ভার্চুয়াল এনভায়রনমেন্ট হালকা রানটাইম ও প্যাকেজ আইসোলেশন দেয়।
 আপনি যে Python প্যাকেজগুলো ইনস্টল করেন, সেগুলোকে একটি নির্দিষ্ট এনভায়রনমেন্ট ডিরেক্টরির ভেতরে একসাথে রাখার মাধ্যমে এগুলো আপনার প্রজেক্ট গুছিয়ে রাখতে সাহায্য করে।
ভিন্ন ভিন্ন এনভায়রনমেন্টে Python রানটাইমের ভিন্ন সংস্করণ এবং প্রজেক্ট বা লাইব্রেরির যেকোনো নির্ভরতা একসাথে থাকতে পারে।
এটি একটি প্রজেক্টের জন্য কোনো লাইব্রেরি আপগ্রেড করার ফলে অন্য প্রজেক্টের নির্ভরতা "ভেঙে যাওয়া"-র মতো বাগ ও অসঙ্গতি এড়াতে সাহায্য করে।

আজ অনেক ধরনের *ভার্চুয়াল এনভায়রনমেন্ট* ও *ভার্চুয়াল এনভায়রনমেন্ট-সদৃশ* টুল ব্যবহৃত হয়, আর ভার্চুয়াল এনভায়রনমেন্টের বদলে [ইনলাইন স্ক্রিপ্ট মেটাডেটা][PEP723], [dev কন্টেইনার][dev containers] বা [docker][docker] ব্যবহারের প্রবণতাও বাড়ছে।
বিভিন্ন কৌশল চেষ্টা করে আপনার ডেভেলপমেন্ট স্টাইল ও প্রজেক্টের প্রয়োজন অনুযায়ী একটি বেছে নেওয়া জরুরি।
ধরে নেবেন না যে এখানকার কৌশলগুলো সবার জন্যই খাপ খায়, বা এগুলোই আপনার একমাত্র বিকল্প।
এখানে আলোচনা করা হয়নি এমন টুলের আরও সাধারণ বিবরণের জন্য [Bas Nijholt-এর এই ব্লগ পোস্টটি][bas nihholt] দেখুন আর কৌতূহলী থাকুন।


এখানে আমরা তিনটি প্রধান *ভার্চুয়াল এনভায়রনমেন্ট* টুল নিয়ে আলোচনা করব: Python স্ট্যান্ডার্ড লাইব্রেরির [`venv`][venv], থার্ড-পার্টি [`conda env`][condaenv] (যা [`conda`][conda] প্যাকেজ ম্যানেজার ও (_সাধারণত_) Anaconda Python ডিস্ট্রিবিউশন ব্যবহার করে), এবং থার্ড-পার্টি `pip` + `venv`-এর বিকল্প [`uv`][uv]।
তিনটিই ব্যবহার করা ও/বা ইনস্টল করা বেশ সহজ।

এছাড়া [`PyEnv`][pyenv], [`Poetry`][poetry] ও [virtualenvwrapper][virtualenvwrapper] হলো এমন টুল, যা একই মেশিনে Python-এর একাধিক সংস্করণ ও একাধিক Python এনভায়রনমেন্ট ম্যানেজ করতে সাহায্য করে।

<br>

### <a name="creating-a-virtual-environment-with-venv"></a>`venv` দিয়ে একটি ভার্চুয়াল এনভায়রনমেন্ট তৈরি করা

`venv` ব্যবহার করে একটি ভার্চুয়াল এনভায়রনমেন্ট তৈরি করতে, যে ডিরেক্টরিতে আপনার এনভায়রনমেন্টগুলো রাখতে চান সেখানে `cd` করুন।
এটি আপনার প্রজেক্টের কোড থেকে **আলাদা** একটি ডিরেক্টরি হওয়া উচিত, এবং এমন একটি ডিরেক্টরি যা আপনি সোর্স কন্ট্রোলে **চেক-ইন করবেন না**।
এরপর, যে ফোল্ডারে এই নির্দিষ্ট **এনভায়রনমেন্টটি** রাখতে চান তার নাম দিয়ে `venv` কমান্ডটি রান করুন।
সাধারণ রীতি হলো ওই ফোল্ডারটির নাম `<project-name-here>_venv` রাখা:

**Windows**

```powershell
PS C:\Users\foobar> py -m venv {name_of_virtualenv}
```
ভার্চুয়াল এনভায়রনমেন্টটি অ্যাক্টিভেট করতে নিচের কমান্ডটি রান করুন:

```powershell
PS> .\{name_of_virtual_env}\Scripts\activate.bat
(venv) PS> _
```

<br>

**Linux/MacOS**

```bash
$ python3 -m venv {name_of_virtualenv}
created virtual environment ... in 8568ms
```

ভার্চুয়াল এনভায়রনমেন্টটি অ্যাক্টিভেট করতে নিচের কমান্ডটি রান করুন:

```bash
$ source {name_of_virtual_env}/bin/activate
(venv) $ _
```

একটি `venv` অ্যাক্টিভেট হয়ে গেলে আপনি এনভায়রনমেন্টের "ভেতরে" প্যাকেজ ইনস্টল করার জন্য `pip` কমান্ড রান করতে পারেন।
ইনস্টল করা প্যাকেজগুলো `venv`-এর Python সংস্করণের সাথে যুক্ত হবে এবং `{name_of_virtual_env}/Lib`-এর ভেতরে থাকবে।

একটি ভার্চুয়াল এনভায়রনমেন্ট _ডিঅ্যাক্টিভেট_ করা যায় `activate`-এর মতো একই ডিরেক্টরিতে থাকা `deactivate` স্ক্রিপ্টটি কল করে।

<br>

### <a name="creating-a-virtual-environment-using-conda"></a>`conda` ব্যবহার করে একটি ভার্চুয়াল এনভায়রনমেন্ট তৈরি করা

*সর্বশেষ `conda` সংস্করণটি [miniconda][miniconda] দিয়ে ইনস্টল করা যায়।*
এই [`conda` চিটশিটটি][conda-cheatsheet] খুবই সহায়ক, যেমনটি [`conda` ডকুমেন্টেশনও][conda-docs]।

মূলত "সায়েন্টিফিক Python"-এর জনপ্রিয় [`Anaconda distribution`][anaconda]-এর জন্য একটি Python প্যাকেজ ম্যানেজার হিসেবে তৈরি করা হয়েছিল `conda`, পরে এটিকে আরও সাধারণ ও বিস্তৃত করা হয়।
Conda এনভায়রনমেন্টগুলো `venv`-এর মতোই, তবে মূল পার্থক্য হলো conda Python ছাড়াও আরও অনেক প্রোগ্রামিং ভাষার জন্য ভার্চুয়াল এনভায়রনমেন্ট তৈরি করতে ও প্যাকেজ ইনস্টল করতে পারে।

Conda যে ভাষাগুলো সাপোর্ট করে তার মধ্যে আছে `R`, `JavaScript`, `Ruby`, `Fortran`, `C/C++`, `Scala`, `Java` এবং আরও অনেক।
conda বনাম venv কমান্ডের তুলনার জন্য conda-র [কমান্ড রেফারেন্স][conda command ref] দেখুন।

<br>

### <a name="uv">UV

uv দিয়ে প্রজেক্টে কাজ করা: [uv][uv-docs]

`uv` হলো [Astral][astral]-এর তৈরি Python প্যাকেজ ও প্রজেক্ট ম্যানেজমেন্ট টুল, যা [Rust][rust programming language]-এ লেখা।
এটি `pip`, `venv`, `poetry` এবং Python-এর অন্যান্য প্যাকেজিং/ডিপেন্ডেন্সি ম্যানেজমেন্ট টুলের বিকল্প হিসেবে তৈরি করা হয়েছে।
`Conda` বা `Mamba`-র মতো নয়, uv শুধু Python-এর জন্যই বিশেষভাবে তৈরি।
 তবে uv Fortran-এর মতো অন্য ভাষায় লেখা Python এক্সটেনশন মডিউল বিল্ড করাও সাপোর্ট করে।
Astral জনপ্রিয় [Ruff][ruff] লিন্টার এবং Python টাইপ হিন্টের জন্য স্ট্যাটিক টাইপ চেকার [TY][ty]-এরও ডেভেলপার, দুটিই Rust-এ লেখা।


এখানে বিস্তারিত না গিয়ে বলি, ইনস্টলেশন ও সেটআপের জন্য [UV ডকুমেন্টেশন][uv documentation]-ই আপনার সেরা সূত্র।

### <a name="virtual-environment-wrapper">ভার্চুয়াল এনভায়রনমেন্ট র‍্যাপার

ডকুমেন্ট ও পটভূমি: [virtualenvwrapper][virtualenvwrapper]।

`virtualenvwrapper` প্যাকেজটি `venv`-এর উপর কাজ করে আপনার সব ভার্চুয়াল এনভায়রনমেন্ট এক জায়গায় ম্যানেজ করে।
 আপনি `lsvirtualenv` (_এনভায়রনমেন্টের তালিকা দেখতে_) ও `mkvirtualenv` (_এনভায়রনমেন্ট তৈরি করতে_) এর মতো লিনাক্স-সদৃশ কমান্ড দিয়ে এনভায়রনমেন্ট তৈরি, কপি, মুছে ফেলা ও একটির থেকে অন্যটিতে যাওয়া করতে পারেন।
  এটি এক্সটেনশন ব্যবহার করে আরও ম্যানেজমেন্ট টুল যোগ করার সুযোগও দেয়।
  এমনকি [এই টিউটোরিয়ালটি][venv wrapper tutorial] ব্যবহার করে আপনি টুলটির জন্য নিজের এক্সটেনশনও বানাতে পারেন।

<br>

### <a name="pyenv"></a>PyEnv

`pyenv` হলো জনপ্রিয় `rbenv`/`ruby-build` টুলের Python-এর জন্য পরিবর্তিত একটি ফর্ক।
এটি মূলত কিছু স্ক্রিপ্ট ও শিমের সংগ্রহ, যা দিয়ে Python-এর সংস্করণ গ্লোবাল ও ব্যবহারকারীভিত্তিকভাবে সেট করা যায়।
একটিমাত্র কাজ ভালোভাবে করা, লক্ষ্যভিত্তিক ও অনাড়ম্বর টুলের ইউনিক্স ঐতিহ্য মেনে চলার চেষ্টা করে এটি।

`pyenv` ও `pyenv`-এর ডকুমেন্টেশন [GitHub][pyenv on github]-এ পাওয়া যায়।

#### <a name="python-for-vs-code"></a>Python for VS Code

_Extension-id: ms-python.python_

![VS Code-এ Python এক্সটেনশনের হেডার](https://raw.githubusercontent.com/exercism/python/main/docs/img/VSCode-EXT-Python-Header.png)

[Microsoft-এর Python এক্সটেনশন][MS Python extension] হলো VS Code-এর জন্য Microsoft-এর অফিসিয়াল Python এক্সটেনশন, এবং ইনস্টল করার জন্য অত্যন্ত প্রস্তাবিত।
এতে এনভায়রনমেন্ট ম্যানেজমেন্ট, টেস্ট ম্যানেজমেন্ট, লিন্টিং ও ডিবাগিংসহ বিস্তৃত ফিচার রয়েছে।
[সর্বশেষ রিলিজ][vs code python latest release] অনুযায়ী, MS Python এক্সটেনশন ইনস্টল করলে [pylance][vs code pylance] (_Python কোড লিন্ট ও ভ্যালিডেট করার একটি জনপ্রিয় প্যাকেজ_) এবং [jupyter][vs code jupyter] (_Jupyter Notebook নিয়ে কাজ করার জন্য_)ও ডাউনলোড হয়ে যাবে।

- একটি সেটআপ টিউটোরিয়াল [এখানে][python extension setup tutorial] পাওয়া যায়, আর [সেটিংস রেফারেন্সটি][vs code python settings reference] খুবই সহায়ক।
- Python সংস্করণ সেটআপ ও ভার্চুয়াল এনভায়রনমেন্ট নিয়ে কাজ করার তথ্য [এখানে][virtual environments in vscode] পাওয়া যাবে।
- VS Code-এ unittest ও pytest সেটআপ ও ব্যবহারের তথ্য [এখানে][python testing in vscode] পাওয়া যাবে।

### <a name="vim"></a>Vim

[Vim][vimdotorg] হলো ইউনিক্সের স্ট্যান্ডার্ড `vi` টেক্সট এডিটরের একটি ফ্রি ও "উন্নত" সংস্করণ।
এটি বিভিন্ন ধরনের অপারেটিং সিস্টেম ও Linux/Unix ফ্লেভারে পাওয়া যায়।
Real Python-এ একটি দুর্দান্ত [ইনস্টলেশন ও সেটআপ গাইড][vim setup at real python] পাওয়া যায়, আর কাজের চিটশিট পাওয়া যায় [vimsheet][vim cheat sheet], [glump][glump vim cheatsheet] ও [rtorr][rtorr vim cheat sheet]-এ।


`vim`-এ Python কোড এডিট করা আপনার জন্য নয় বলে মনে হলেও, কিছু মৌলিক কমান্ডের সাথে পরিচিত হওয়ার পরামর্শ দেওয়া হয়।
Linux ও Unix ডিস্ট্রিবিউশনে `vim` বা `vi` প্রায়ই একটি "বেস" বা "ডিফল্ট" টেক্সট এডিটর, এবং ওই সিস্টেমগুলোতে `git` কমিট মেসেজের (_এবং আরও অনেক কিছুর_) ডিফল্ট এডিটর।
সম্ভাবনা আছে আপনি একদিন শুধু `vi` সম্বলিত কোনো *nix সিস্টেমে একটি কনফিগারেশন ফাইল এডিট করার প্রয়োজন পড়বেন, তাই [vim থেকে বেরোতে জানা][how do I quit vim] (_অন্তত_) ভালো আত্মরক্ষা।
