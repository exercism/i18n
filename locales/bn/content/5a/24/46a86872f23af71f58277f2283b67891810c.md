# হিয়ার ডকুমেন্টসের পরিচিতি

Bash স্ক্রিপ্টিংয়ে একটি "হিয়ার ডকুমেন্ট" (বা "হিয়ারডক") একাধিক লাইন ইনপুট একটি কমান্ড বা প্রোগ্রামে রিডাইরেক্ট করে, যেন আপনি সেগুলো সরাসরি টার্মিনালে টাইপ করছেন।
বাইরের ফাইল বা জটিল স্ট্রিং ম্যানিপুলেশন ছাড়াই আপনার স্ক্রিপ্টের ভেতরে বহু-লাইন টেক্সট বসানোর জন্য এটি একটি শক্তিশালী উপায়।

## প্রধান বৈশিষ্ট্য ও সিনট্যাক্স

1. ডেলিমিটার: একটি হিয়ারডক শুরু হয় `<<` অপারেটর দিয়ে, তার পরে থাকে একটি ডেলিমিটার শব্দ (যাকে প্রায়ই "মার্কার" বা "টার্মিনেটর" বলা হয়)।
   এই ডেলিমিটার আপনার ইচ্ছেমতো যেকোনো শব্দ হতে পারে, তবে স্পষ্টতার জন্য সাধারণত `EOF`, `END` বা `TEXT`-এর মতো কিছু ব্যবহার করা হয়।
   আরও পাঠযোগ্য কোডের জন্য আপনি ডেলিমিটার হিসেবে বর্ণনামূলক কিছু দিতে পারেন, যেমন `END_INSTALLATION_INSTRUCTIONS`।

1. কনটেন্ট: শুরুর `<< DELIMITER`-এর পরে আপনি যে কনটেন্টটি রিডাইরেক্ট করতে চান তা লেখেন।
   এটি একাধিক লাইন টেক্সট, কোড বা অন্য যেকোনো কিছু হতে পারে।

1. সমাপ্তি: ডেলিমিটার শব্দটি যখন নিজে একা একটি লাইনে, আগে বা পরে কোনো হোয়াইটস্পেস ছাড়া, আবার দেখা যায়, তখন হিয়ারডক শেষ হয়।

## সাধারণ সিনট্যাক্স

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## এটি কীভাবে কাজ করে

* Bash শুরু `<< DELIMITER` আর শেষ `DELIMITER`-এর মাঝের সব লাইন পড়ে।
* Bash এই কনটেন্টটি কমান্ডের স্ট্যান্ডার্ড ইনপুটের সাথে যুক্ত করে।
* কমান্ডটি এই ইনপুট প্রসেস করে যেন তা কিবোর্ড থেকে আসছে।

### উদাহরণ ১: সাধারণ টেক্সট আউটপুট

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

আউটপুট:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

এই উদাহরণে:

* `cat` হলো কমান্ড।
* `<< EOF` ডেলিমিটার হিসেবে `EOF` নিয়ে হিয়ারডক শুরু করে।
* টেক্সটের তিনটি লাইনই কনটেন্ট।
* নিজের লাইনে থাকা `EOF` হিয়ারডক শেষ করে।
* এরপর `cat` তার পাওয়া কনটেন্ট আউটপুট করে।

### উদাহরণ ২: wc (শব্দ গণনা) দিয়ে ব্যবহার

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

আউটপুট:

```plaintext
3
```

এখানে `wc -l` লাইনের সংখ্যা গণনা করে।
হিয়ারডক ইনপুট হিসেবে তিনটি লাইন দেয়।

### উদাহরণ ৩: একটি স্ক্রিপ্টে ডেটা পাঠানো

স্ক্রিপ্টটি:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

একটি ইন্টারঅ্যাকটিভ bash প্রম্পট থেকে হিয়ারডক দিয়ে স্ক্রিপ্টটি কল করুন:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

আউটপুট:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## বৈচিত্র্য ও উন্নত ফিচার

### লিটারাল কনটেন্ট

Bash একটি হিয়ারডকের ভেতরে ভ্যারিয়েবল এক্সপ্যানশন, কমান্ড সাবস্টিটিউশন এবং অ্যারিথমেটিক এক্সপ্যানশন করে।
এই অর্থে হিয়ারডকগুলো ডাবল কোটেড স্ট্রিংয়ের মতো আচরণ করে।

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

আউটপুট:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

ডেলিমিটার কোট করা থাকলে (একক বা দ্বৈত কোট ব্যবহার করে) এই এক্সপ্যানশনগুলো আর হয় না।
কনটেন্টটি হুবহু নেওয়া হয়।
এটি সিঙ্গেল কোটেড স্ট্রিংয়ের মতো।

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

আউটপুট:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### শুরুর ট্যাব সরানো

`<<` অপারেটরের বদলে `<<-` (শেষে একটি হাইফেন সহ) ব্যবহার করলে Bash হিয়ারডকের প্রতিটি লাইন থেকে শুরুর _ট্যাব ক্যারেক্টারগুলো_ সরিয়ে দেবে।
স্ক্রিপ্টের ভেতরে হিয়ারডকের কনটেন্ট ইনডেন্ট করার সময় আউটপুটে প্রভাব না ফেলার জন্য এটি কাজে লাগে।

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

সব শুরুর ট্যাব সরিয়ে আউটপুটটি ছাপা হয়:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

## কখন হিয়ার ডকুমেন্ট ব্যবহার করবেন

* বহু-লাইন ইনপুট: যখন একটি কমান্ডকে একাধিক লাইন টেক্সট দিতে হয়।
* কনফিগারেশন ফাইল: স্ক্রিপ্টের ভেতরে ছোট কনফিগারেশন স্নিপেট বসানো।
* কোড জেনারেট করা: স্ক্রিপ্টের ভেতরেই সাথে সাথে কোড তৈরি করা।
* স্ক্রিপ্টেড ইন্টারঅ্যাকশন: ইন্টারঅ্যাকটিভ প্রোগ্রামের জন্য ব্যবহারকারীর ইনপুট নকল করা।
* বাইরের ফাইল এড়ানো: যখন অস্থায়ী ফাইল তৈরি করা এড়াতে চান।

একটি সাধারণ ব্যবহার হতে পারে কিছু হেল্প টেক্সট দেওয়া:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## সম্ভাব্য অসুবিধা

* বড় এমবেডেড ডকুমেন্ট আপনার কোড পড়া কঠিন করে তুলতে পারে।
  ডকুমেন্টেশন আলাদা ফাইলে রেখে স্ক্রিপ্ট ডিপ্লয় করা বেশি ভালো হতে পারে।
* হিয়ার ডকুমেন্ট কোডের প্রবাহ ভেঙে দিতে পারে।
  আপনি হয়তো কোডের গভীরভাবে নেস্টেড কোনো অংশে আছেন, তখনই একটি প্রোগ্রামে কিছু টেক্সট পাঠাতে চান।
  আশপাশের কোডের তুলনায় হিয়ারডকের ইনডেন্টেশন অসংগত লাগতে পারে।

## হিয়ার স্ট্রিং

হিয়ার ডকুমেন্টের মতো, _হিয়ার স্ট্রিং_ (বা "হিয়ারস্ট্রিং") একটি কমান্ডকে ইনপুট দেয়।
তবে হিয়ারডক যেখানে টেক্সটের একটি ব্লক হিসেবে দেওয়া হয়, হিয়ারস্ট্রিং সেখানে টেক্সটের একটি একক স্ট্রিং হিসেবে দেওয়া হয়।
হিয়ার স্ট্রিং `<<< "text"` সিনট্যাক্স ব্যবহার করে।

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

আউটপুট:

```plaintext
UPPER CASE THIS STRING
```

হিয়ারডকের মতো নয়, এখানে শেষ করার ডেলিমিটার লাগে না।

### কেন হিয়ার স্ট্রিং ব্যবহার করবেন?

একটি হিয়ার স্ট্রিংয়ের বদলে পাইপলাইন ব্যবহার করা যায়:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

তাহলে কেন হিয়ার স্ট্রিং ব্যবহার করবেন?

ধরুন, একটি দীর্ঘ সময় ধরে চলা ক্যালকুলেশন থেকে আপনি আউটপুট হিসেবে একটি স্ট্রিং পেলেন, আর সেই ফলাফলটি দুটি আলাদা কমান্ডে দিতে চান।
পাইপলাইন ব্যবহার করলে ক্যালকুলেশনটি দুবার চালাতে হবে:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

আরও কার্যকর উপায় হলো ক্যালকুলেশনের আউটপুট ধরে রাখা (কমান্ড সাবস্টিটিউশন ব্যবহার করে), এবং পরের দুটি কমান্ডে ইনপুট দেওয়ার জন্য হিয়ার স্ট্রিং ব্যবহার করা:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

এই উদাহরণটির একটি বাস্তব প্রয়োগ দেখুন:

* একটি REST API কোয়েরির JSON রেসপন্স ধরে রাখা (যেটি পেজিনেটেড),
* ফলাফল পার্স করে একটি ফাইলে আউটপুট দিতে jq প্রোগ্রামে JSON ডেটা দেওয়া, এবং তারপর
* পরের কোয়েরির URL নির্ণয় করতে আরেকটি jq প্রোগ্রামে JSON ডেটা দেওয়া।

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

আউটপুট রিডাইরেকশনের অবস্থানটি লক্ষ করুন।
while লুপের সব আউটপুট `data.csv` ফাইলে যোগ হবে।

## রিডাইরেকশন হিসেবে হিয়ারডক ও হিয়ারস্ট্রিং

যেহেতু এগুলো কেবল রিডাইরেকশনেরই রূপ, তাই এগুলো অন্য রিডাইরেকশন অপারেশনের সাথে মেলানো যায়:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## সারসংক্ষেপ

হিয়ার ডকুমেন্ট (বা "হিয়ারডক") Bash স্ক্রিপ্টে বহু-লাইন ইনপুট সামলানোর একটি নমনীয় ও সুবিধাজনক উপায়।
এগুলো সরাসরি আপনার স্ক্রিপ্টের ভেতরে টেক্সট ও ডেটা বসানোর প্রক্রিয়াটি সহজ করে, ফলে স্ক্রিপ্ট আরও স্বনির্ভর ও পড়তে সহজ হয়।

হিয়ার স্ট্রিং (বা "হিয়ারস্ট্রিং") হিয়ার ডকুমেন্টের মতোই, তবে আরও সরল ও গতিশীল সিনট্যাক্স দেয়।
