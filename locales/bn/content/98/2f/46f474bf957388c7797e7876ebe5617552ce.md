# While ও Until লুপ

লুপ হলো একটি কন্ট্রোল স্ট্রাকচার, যা একটি নির্দিষ্ট শর্তের ভিত্তিতে কোড বারবার চালানোর সুযোগ দেয়।

## While লুপ

while লুপ হলো একটি কন্ট্রোল স্ট্রাকচার, যা একটি নির্দিষ্ট শর্তের ভিত্তিতে কোড বারবার চালানোর সুযোগ দেয়।
শর্তটি ট্রুথি হলে while লুপের ভেতরের কোড চলতেই থাকবে।
ইটারেশনের সংখ্যা আগে থেকে জানা না থাকলে প্রায়ই while লুপ ব্যবহার করা হয়; যেখানে লুপ দরকার, সেখানে এগুলো ব্যবহার করা যায়।

লুপের ভেতরের কোড চালানোর আগেই শর্তটি মূল্যায়ন করা হয়, অর্থাৎ শর্তটি ফলস হলে লুপের ভেতরের কোড কখনোই চালানো হবে না।

```crystal
i = 0
while i < 3
  puts i
  i += 1
end

# Output:
# 0
# 1
# 2
```

কোনো স্ট্রিংয়ের ওপর ইটারেট করতে চাইলে আপনি স্ট্রিংয়ের দৈর্ঘ্যের ওপর লুপ চালাতে পারেন।

```crystal
str = "Hello"
i = 0
while i < str.size
  puts str[i]
  i += 1
end

# Output:
# H
# e
# l
# l
# o
```

## Until লুপ

Until লুপ while লুপের মতোই কাজ করে, শুধু পার্থক্য হলো শর্তটি ট্রুথি না হওয়া পর্যন্ত লুপের ভেতরের কোড চলতে থাকে।
এটা ঠিক `if` আর `unless`-এর পার্থক্যের মতোই।

```crystal
i = 0
until i == 3
  puts i
  i += 1
end
```

### ইনফিনিট লুপ

while লুপের একটি কমন এরর হলো "ইনফিনিট লুপ"-এ ঢুকে পড়া, যা কখনো শেষ হয় না।
শর্তটি কখনোই ট্রুথি বা ফলসি হিসেবে মূল্যায়িত না হলে ইনফিনিট লুপ তৈরি হতে পারে।
এটা প্রায়ই প্রোগ্রামারের ভুলের কারণে হয়; যেমন, লুপ ভ্যারিয়েবল বাড়াতে ভুলে যাওয়া।
কিন্তু কখনো কখনো প্রোগ্রামের লজিক বাস্তবায়নের সবচেয়ে স্পষ্ট উপায় হলো ইনফিনিট লুপ।
আবার কখনো চিরকাল লুপ চালানো অপরিহার্য; যেমন একটি HTTP সার্ভার একটি আসা কানেকশনের জন্য অপেক্ষা করে, সেটি সামলায়, তারপর পরের কানেকশনের জন্য অপেক্ষা করে।

## break

`break` কিওয়ার্ড দিয়ে লুপ থেকে আগেভাগে বেরিয়ে আসা যায়।
নির্দিষ্ট কিছু শর্তে লুপ থেকে আগেভাগে বেরোতে চাইলে এটি সুবিধাজনক।

```crystal
i = 0
while i <= 3
  puts i
  i += 1
  if i == 2
    break
  end
end

# Output:
# 0
# 1
```

## next

`next` কিওয়ার্ড দিয়ে লুপের পরের ইটারেশনে চলে যাওয়া যায়।
লুপের নির্দিষ্ট কিছু ইটারেশন বাদ দিতে চাইলে এটি সুবিধাজনক।

```crystal
i = 0
while i <= 3
  i += 1
  if i == 2
    next
  end
  puts i
end

# Output:
# 1
# 3
```

## লুপ চলাকালীন টাইপ

লুপ চলাকালীন ভ্যারিয়েবলের টাইপ ভিন্ন হতে পারে।
নিচের উদাহরণে `a`-এর টাইপ `Int32 | String`, কারণ লুপের প্রথম অংশে এটি `Int32` বা `String` হতে পারে।
ভ্যারিয়েবল `a` শুধু লুপের প্রথম অংশেই `Int32 | String` টাইপ ধারণ করবে, কারণ লুপ শুরু হওয়ার সময় এতে `Int32` থাকে, আর দ্বিতীয় ইটারেশনে থাকে একটি `String`।
এই একাধিক-টাইপ ব্যবস্থা পরে বিস্তারিতভাবে ব্যাখ্যা করা হবে।
কিন্তু যেহেতু আমরা নিশ্চিত যে লুপের দ্বিতীয় অংশে শুধু `String` থাকবে, তাই লুপের দ্বিতীয় অংশে `a`-এর টাইপ `String`।
রানটাইমে এটি কখনোই একসাথে `Int32` আর `String` ধারণ করবে না।

```crystal
i = 0
a = 4
while i < 3
  p typeof(a)
  # => Int32 | String
  a = "4"
  p typeof(a)
  # => String
  i += 1
end
```
