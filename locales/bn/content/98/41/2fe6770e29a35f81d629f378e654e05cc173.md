# স্ট্রিং বিল্ডার

একটি `STR` কখনোই বদলায় না। তাই `+` দিয়ে এর সাথে কিছু যোগ করা যায় না, বরং দুটোরই বিষয়বস্তু নিয়ে একেবারে নতুন একটি স্ট্রিং তৈরি করতে হয়।

একবার হলে ঠিক আছে। কিন্তু লুপের ভেতরে নয়:

```sather
   -- don't
   script ::= "";
   loop
      script := script + lines.elt!;
   end;
```

প্রতিটি ধাপে এখন পর্যন্ত তৈরি হওয়া সবকিছু নতুন একটি স্ট্রিংয়ে কপি হয়, আর পুরোনোটি ফেলে দেওয়া হয়। দশটি লাইন মানে দশটি কপি, প্রতিটি আগেরটির চেয়ে বড়। একশো লাইন মানে একশোটি। কাজের পরিমাণ বাড়ে লাইনের সংখ্যার *বর্গ* অনুযায়ী, আর নিরীহ দেখতে লুপটিই হয়ে ওঠে প্রোগ্রামের ধীরগতির অংশ।

## FSTR

`FSTR` এমন একটি স্ট্রিং, যা বদলানো *যায়*, অর্থাৎ এক ধরনের **স্ট্রিং বিল্ডার**। এর সাথে কিছু যোগ করলে সাধারণত তা আগে থেকেই থাকা জায়গাতেই লেখা হয়, তাই একশো লাইনের লুপে একশোটি কপির বদলে প্রায় একশো লাইনের সমান কাজই হয়।

```sather
   script ::= #FSTR;
   loop
      script := script + lines.elt!;
   end;
   return script.str;
```

তিনটি বিষয় খেয়াল করার মতো।

**`#FSTR` একটি খালি বিল্ডার তৈরি করে।** `#FSTR(100)` এমন একটি বানায় যেখানে একশো ক্যারেক্টারের জায়গা আগেই আলাদা করে রাখা থাকে, আর আকার জানা থাকলে এটি করা লাভজনক।

**ফলাফলটি আবার অ্যাসাইন করতে হবে।** `script := script + ...`, কখনোই একা `script + ...` নয়। সাধারণত ফলাফলটি আগের ওই বিল্ডারটিই হয়, কিন্তু জায়গা শেষ হয়ে গেলে সেটি হয় আরও বড় একটি নতুন বিল্ডার, আর ফলাফলটি ফেলে দিলে আপনি পুরোনোটিতেই লিখতে থাকবেন।

**শেষে `.str`।** যে রুটিন `: STR` প্রতিশ্রুতি দেয়, তাকে একটি `STR` ফেরত দিতে হয়, আর `.str` বিল্ডার থেকে সেটি তৈরি করে।

## কী কী যোগ করা যায়

`FSTR`-এর উপর `+` স্ট্রিং, ক্যারেক্টার, ইন্টিজার কিংবা বুলিয়ান গ্রহণ করে, তাই সাধারণত আগে রূপান্তর করার দরকার হয় না:

```sather
   line ::= #FSTR;
   line := line + 1 + ". " + "Enter" + '!';   -- "1. Enter!"
```

## নতুন লাইন

স্ট্রিংয়ের ভেতরে `"\n"` মানে নতুন লাইন, একটি মাত্র ক্যারেক্টার, যা লেখা হয় দুটি দিয়ে।

```sather
   script := script + "Enter" + "\n" + "Exit";
```
