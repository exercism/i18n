# পরিচিতি

**ফ্লোটিং-পয়েন্ট** হলো এমন একটি সংখ্যা, যার একটি ভগ্নাংশ থাকতে পারে, যেমন `-1.23` বা `3.1415`।

এমন একটি সংখ্যাকে বাইটের ক্রম হিসেবে প্রকাশ করতে x86-64 [IEEE-754][ieee] স্ট্যান্ডার্ড ব্যবহার করে।
এই স্ট্যান্ডার্ডের সবচেয়ে কমন দুটি ফরম্যাট হলো সিঙ্গেল-প্রিসিশন ফ্লোটিং-পয়েন্ট আর ডাবল-প্রিসিশন ফ্লোটিং-পয়েন্ট সংখ্যা।
x86-64 দুটোই সাপোর্ট করে।

একটি সিঙ্গেল-প্রিসিশন ফ্লোটিং-পয়েন্ট সংখ্যা ৩২-বিট চওড়া, অন্যদিকে একটি ডাবল-প্রিসিশন ৬৪-বিট চওড়া।

## XMM রেজিস্টার

x86-64-এ ফ্লোটিং-পয়েন্ট অ্যারিথমেটিক করার জন্য ১৬টি ডেডিকেটেড রেজিস্টার আছে, যাদের নাম `xmm0` থেকে `xmm15`।

এই রেজিস্টারগুলো অন্তত ১২৮-বিট চওড়া, তবে সাম্প্রতিক প্রসেসরগুলো এটিকে ২৫৬-বিট বা ৫১২-বিট পর্যন্ত বাড়িয়ে দিয়েছে।
তবে বাস্তবে বেশিরভাগ ফ্লোটিং-পয়েন্ট সংখ্যা কাঙ্ক্ষিত প্রিসিশন অনুযায়ী শুধু নিচের ৩২-বিট বা ৬৪-বিট অংশ ব্যবহার করে।

## সংখ্যার মধ্যে কনভার্সন

সংখ্যার ফরম্যাটের মধ্যে কনভার্ট করার জন্য একগুচ্ছ ইনস্ট্রাকশন আছে: `cvtxx2yy`।

`xx` আর `yy` দুটোই লিটারাল নয়, প্লেসহোল্ডার:

- `xx` হলো সোর্স অপারেন্ডের টাইপের জন্য একটি প্লেসহোল্ডার।
- `yy` হলো ডেস্টিনেশন অপারেন্ডের টাইপের জন্য একটি প্লেসহোল্ডার।

এই প্লেসহোল্ডার অনেক রকমের রূপ নিতে পারে, তার মধ্যে:

| placeholder | meaning               |
| ----------- | --------------------- |
| `si`        | সাইনড ইন্টিজার        |
| `ss`        | ৩২-বিট ফ্লোটিং-পয়েন্ট |
| `sd`        | ৬৪-বিট ফ্লোটিং-পয়েন্ট |

যেমন:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

মনে রাখবেন, ৩২-বিট ইন্টিজারকে ৬৪-বিট ফ্লোটিং-পয়েন্টে বা ৬৪-বিট ইন্টিজারকে ৩২-বিট ফ্লোটিং-পয়েন্টে কনভার্ট করা সম্ভব।
একইভাবে, ৩২-বিট ফ্লোটিং-পয়েন্টকে ৬৪-বিট ইন্টিজারে বা ৬৪-বিট ফ্লোটিং-পয়েন্টকে ৩২-বিট ইন্টিজারে কনভার্ট করাও সম্ভব।
অন্য কথায়, `cvtxx2yy` ইনস্ট্রাকশনে দুই অপারেন্ডের আকার _একই হওয়া জরুরি নয়_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

যখন ফ্লোটিং-পয়েন্ট সংখ্যাটিকে সঠিকভাবে ইন্টিজার হিসেবে প্রকাশ করা যায় না, তখন `cvtxx2si` `mxcsr` নামের একটি বিশেষ রেজিস্টারে থাকা রাউন্ডিং কন্ট্রোল অনুযায়ী সংখ্যাটিকে রাউন্ড করে।
এটি নিয়ারেস্টে রাউন্ড, নিচে রাউন্ড, উপরে রাউন্ড বা ট্রাঙ্কেট হতে পারে।
ফাংশনে ঢোকার সময় কোনো নিশ্চিত ডিফল্ট থাকে না।

মনে রাখবেন, একটি সঠিক ফলাফল রাউন্ড করা হয় না, তাই রাউন্ডিং কন্ট্রোলও তাতে কোনো প্রভাব ফেলে না।
যেমন, `42.0` _সবসময়ই_ `42`-এ কনভার্ট হবে।

`cvttxx2si` ফরম্যাটের (বাড়তি একটি `t` সহ) একই রকম আরেকটি ইনস্ট্রাকশন পরিবার আছে, যা সবসময় ফলাফল ট্রাঙ্কেট করে।

## রাউন্ড

`roundxx` ইনস্ট্রাকশন পরিবার সোর্স অপারেন্ডের ফ্লোটিং-পয়েন্টকে রাউন্ড করে ডেস্টিনেশন অপারেন্ডে সংরক্ষিত একটি ফ্লোটিং-পয়েন্টে পরিণত করে।

এখানে `xx` আগের মতোই অপারেন্ডগুলোর টাইপের প্লেসহোল্ডার: সিঙ্গেল-প্রিসিশনের জন্য `ss` এবং ডাবল-প্রিসিশনের জন্য `sd`।

এই ইনস্ট্রাকশনগুলো তৃতীয় অপারেন্ড হিসেবে একটি কনস্ট্যান্ট সংখ্যা নেয়।
এই সংখ্যাটি রাউন্ডিং মোড নির্দেশ করে:

| Number | Mode         |
| :----- | :----------- |
| 0      | নিয়ারেস্ট    |
| 1      | ফ্লোর (নিচে) |
| 2      | সিল (উপরে)   |
| 3      | ট্রাঙ্কেট     |

যেমন:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

যেহেতু এই ইনস্ট্রাকশনগুলো সঠিক ফলাফল দেয়, তাই `cvtxx2si`-এর প্রস্তুতি হিসেবে এগুলো ব্যবহার করা যায়।

## অ্যারিথমেটিক ইনস্ট্রাকশন

ফ্লোটিং-পয়েন্ট সংখ্যা নিয়ে অনেক অপারেশনের ইনস্ট্রাকশনের নাম ইন্টিজারের সমতুল্য ইনস্ট্রাকশনের মতোই, শুধু শেষে প্রয়োজনীয় প্লেসহোল্ডার (`ss` বা `sd`) যোগ করা হয়।
এই ইনস্ট্রাকশনগুলো দুই-অপারেন্ডের, স্বাভাবিক সেমান্টিক্স মেনে চলে, এমনকি যেগুলো গুণ বা ভাগ করে সেগুলোও:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## মুভ

একটি XMM রেজিস্টার থেকে আরেকটিতে মুভ করার ইনস্ট্রাকশন হলো `movss` বা `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

একটি ইমিডিয়েট (একটি কনস্ট্যান্ট সাইনড ইন্টিজার) সরাসরি একটি xmm রেজিস্টারে মুভ করা **সম্ভব নয়**।
এই সংখ্যাটিকে প্রথমে একটি জেনারেল-পারপাস রেজিস্টারে মুভ করতে হয়, তারপর `cvtsi2xx` দিয়ে কনভার্ট করতে হয়:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## তুলনা

দুটি ফ্লোটিং-পয়েন্ট সংখ্যার মধ্যে তুলনা করার জন্য দুই দল ইনস্ট্রাকশন আছে।
এগুলোর রূপ `comixx` আর `ucomixx`, যেখানে `xx` হলো `ss` বা `sd`।
দুটোই স্বাভাবিকভাবে `rflags`-এ ফ্ল্যাগ সেট করে, `cmp`-এর মতো একই সেমান্টিক্স মেনে।

এদের মধ্যে পার্থক্য হলো, দুটি ফ্লোটিং-পয়েন্ট সংখ্যার একটির মান `NaN` হলে `ucomixx` `parity flag (PF)` সেট করে, অন্যদিকে `comixx` এই ক্ষেত্রে একটি এক্সেপশন তোলে।

ফ্লোটিং-পয়েন্ট মানের মধ্যে তুলনা _আনসাইনড_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## অন্যান্য ইনস্ট্রাকশন

ফ্লোটিং-পয়েন্ট সংখ্যা নিয়ে কাজ করার আরও অনেক ইনস্ট্রাকশন আছে, যেগুলো কমন অপারেশন বাস্তবায়ন করে।
এর মধ্যে কিছু হলো:

| Instruction | Description                                      |
| :---------- | :----------------------------------------------- |
| `sqrtxx`    | বর্গমূল হিসাব করে (`sqrt(x)`)                    |
| `rcpss`     | রেসিপ্রোকাল হিসাব করে (`1/x`)                    |
| `rsqrtss`   | বর্গমূলের রেসিপ্রোকাল হিসাব করে (`1/sqrt(x)`)     |
| `minxx`     | সর্বনিম্ন মান হিসাব করে (`min(x, y)`)             |
| `maxxx`     | সর্বোচ্চ মান হিসাব করে (`max(x, y)`)             |

যেখানে `xx` প্লেসহোল্ডার ব্যবহার করা হয়, সেখানে এটি আগের মতোই `ss` বা `sd` রূপ নিতে পারে।
তবে `rcpss` আর `rsqrtss` শুধু সিঙ্গেল-প্রিসিশন ফ্লোটিং-পয়েন্ট সংখ্যা নিয়েই কাজ করে।

এই ইনস্ট্রাকশনগুলো সবই দুই-অপারেন্ডের।

## কলিং কনভেনশন

System V ABI-তে প্রথম আটটি ফ্লোটিং-পয়েন্ট আর্গুমেন্ট ক্রমানুসারে `xmm0` থেকে `xmm7` পর্যন্ত ফাংশনে পাঠানো হয়।
ফাংশন থেকে ফ্লোটিং-পয়েন্ট মান `xmm0`-এ এবং প্রয়োজনে `xmm1`-এ রিটার্ন করা হয়।

সব `xmm` রেজিস্টারই অবাধে ব্যবহার করা যায়, এর কোনোটিই কলারের জন্য সংরক্ষিত নয়।

## মেমোরি

একই আকারের ইন্টিজারের মতো একই সেমান্টিক্স মেনে মেমোরিতে ফ্লোটিং-পয়েন্ট মান ডিফাইন করা যায়।
NASM (The Netwide Assembler, যা এই ট্র্যাকের ব্যবহৃত অ্যাসেম্বলার) সায়েন্টিফিক নোটেশনে ফ্লোটিং-পয়েন্ট মান ডিক্লেয়ার করার সুযোগও দেয়।

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```

## AVX/AVX2

x86-64 আর্কিটেকচারের AVX/AVX2 এক্সটেনশন ফ্লোটিং-পয়েন্ট ইনস্ট্রাকশনের জন্য নতুন তিন-অপারেন্ড রূপ নিয়ে আসে, যেখানে ডেস্টিনেশন আর সোর্স আলাদা থাকে।
উপরে দেখা লিগ্যাসি SSE রূপ থেকে আলাদা করতে এগুলো একটি `v` (যার অর্থ _vector_) প্রিফিক্স নেয়:

```x86asm
vaddss xmm0, xmm1, xmm2 ; xmm0 = xmm1 + xmm2 (32-bit floating-point)
vmulsd xmm2, xmm3, xmm4 ; xmm2 = xmm3 * xmm4 (64-bit floating-point)
```

এই ট্র্যাকে আমরা আগের SSE এক্সটেনশন পর্যন্ত ইনস্ট্রাকশন আর রেজিস্টারেই নিজেদের সীমাবদ্ধ রেখেছি।
এটুকুই মৌলিক বিষয় শেখানোর জন্য যথেষ্ট, আর এটি বিস্তৃত পরিসরের CPU-এর সাথে কম্প্যাটিবিলিটি নিশ্চিত করে।

তবে test-runner সম্পূর্ণভাবে AVX আর AVX2 সাপোর্ট করে।
আপনি নির্দ্বিধায় এগুলো ব্যবহার করতে পারেন।
