# নির্দেশনা

সাম্প্রতিক একটি নিরাপত্তা পর্যালোচনার পর আপনাকে প্রতিষ্ঠানের আর্কাইভ করা লগ ফাইলগুলো পরিষ্কার করার দায়িত্ব দেওয়া হয়েছে।

## 1. বিকৃত লগ লাইন চিহ্নিত করুন

আপনার আর্কাইভে কতগুলো লগ লাইন বর্তমান মানদণ্ড মেনে চলে না, সে সম্পর্কে আপনার কিছুটা ধারণা দরকার। আপনার বিশ্বাস, একটি সহজ পরীক্ষাই বলে দিতে পারে একটি লগ লাইন বৈধ কি না।
বৈধ হতে হলে একটি লাইনকে নিচের যেকোনো একটি স্ট্রিং দিয়ে শুরু হতে হবে:

- [DEBUG]
- [INFO]
- [WARNING]
- [ERROR]

লগ লাইনটি বৈধ হলে `true` রিটার্ন করার জন্য `valid_line?/1` ফাংশনটি ইমপ্লিমেন্ট করুন।

```elixir
LogParser.valid_line?("[ERROR] Network Failure")
# => true

LogParser.valid_line?("Network Failure")
# => false
```

## 2. লগ লাইনটি ভাগ করুন

লগ পার্সিং প্রকল্প শুরু করার কিছুক্ষণ পরেই আপনি বুঝতে পারেন, একটি অ্যাপ্লিকেশনের লগ অন্যগুলোর মতো লাইনে বিভক্ত নয়। এই প্রকল্পে যা আলাদা লাইন হওয়া উচিত ছিল, তা বদলে একটি একক লাইনে থাকে, যা `<--->` বা `<*~*~>`-এর মতো চটকদার তীর দিয়ে জোড়া লাগানো।

আসলে, যে স্ট্রিংয়ের প্রথম ক্যারেক্টার `<`, শেষ ক্যারেক্টার `>`, আর মাঝে `~`, `*`, `=` ও `-` অক্ষরগুলোর যেকোনো সমন্বয় থাকে, সেটিই এই প্রকল্পের লগে সেপারেটর হিসেবে ব্যবহার করা যায়।

একটি লাইন নিয়ে স্ট্রিংয়ের একটি অ্যারে রিটার্ন করার জন্য `split_line/1` ফাংশনটি ইমপ্লিমেন্ট করুন।

```elixir
LogParser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
# => ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. লগ থেকে আর্টিফ্যাক্ট সরান

আপনি দেখতে পেয়েছেন, লগের কিছু আপস্ট্রিম প্রসেসিং লগজুড়ে "end-of-line" টেক্সট এবং তার পরপর (মাঝে কোনো স্পেস ছাড়া) একটি লাইন নম্বর ছড়িয়ে দিয়েছে।

একটি স্ট্রিং নিয়ে সেখান থেকে সব end-of-line টেক্সট (কেস-ইনসেনসিটিভ) সরিয়ে ফেলে একটি পরিষ্কার লগ লাইন রিটার্ন করার জন্য `remove_artifacts/1` ফাংশনটি ইমপ্লিমেন্ট করুন।

যে লাইনগুলোতে end-of-line টেক্সট নেই, সেগুলো অপরিবর্তিত রিটার্ন করা উচিত।

শুধু end-of-line স্ট্রিংটি সরান, হোয়াইটস্পেস ঠিক করার দরকার নেই।

```elixir
LogParser.remove_artifacts("[WARNING] end-of-line23033 Network Failure end-of-line27")
# => "[WARNING]  Network Failure "
```

## 4. ইউজার নাম দিয়ে লাইন ট্যাগ করুন

আপনি লক্ষ্য করেছেন, কিছু লগ লাইনে এমন বাক্য আছে যা ইউজারদের নির্দেশ করে।
এই বাক্যগুলোতে সবসময় `"User"` স্ট্রিংটি থাকে, তারপর এক বা একাধিক হোয়াইটস্পেস ক্যারেক্টার, আর তারপর একটি ইউজার নাম।
আপনি সিদ্ধান্ত নেন এই ধরনের লাইন ট্যাগ করবেন।

লগ লাইন প্রসেস করার জন্য `tag_with_user_name/1` ফাংশনটি ইমপ্লিমেন্ট করুন:

- যে লাইনগুলোতে `"User"` স্ট্রিংটি নেই, সেগুলো অপরিবর্তিত থাকে।
- যে লাইনগুলোতে `"User"` স্ট্রিংটি আছে, সেই লাইনের শুরুতে `[USER]` এবং তার পরে ইউজার নাম যোগ করুন।

```elixir
LogParser.tag_with_user_name("[INFO] User Alice created a new project")
# => "[USER] Alice [INFO] User Alice created a new project"
```

আপনি ধরে নিতে পারেন যে:

- `"User"` স্ট্রিংটির প্রতিটি উপস্থিতির পরে এক বা একাধিক হোয়াইটস্পেস ক্যারেক্টার এবং ইউজার নাম থাকে।
- প্রতি লাইনে `"User"` স্ট্রিংটি সর্বোচ্চ একবার থাকে।
- ইউজার নাম খালি নয় এমন স্ট্রিং, যাতে হোয়াইটস্পেস নেই।
