# পরিচিতি

## ব্রাঞ্চলেস কোড

কন্ডিশনাল ধারণাটি `jcc`-এর সাথে পরিচয় করায়, যা একটি শর্তের ভিত্তিতে ব্রাঞ্চ করার জন্য ইনস্ট্রাকশনের একটি পরিবার। একটি `jcc` কেবল তখনই প্রোগ্রামের অন্য একটি জায়গায় এক্সিকিউশন স্থানান্তর করে, যখন তার শর্ত পূরণ হয়।

তবে আধুনিক CPU দ্রুত এবং সমান্তরালে অনেক ইনস্ট্রাকশন এক্সিকিউট করতে সক্ষম। কোনো শর্তের রানটাইম চেকের জন্য CPU অপেক্ষা করার সময় সব কাজ থামিয়ে রাখা খুবই ব্যয়বহুল হতো।

এ কারণেই ভেতরে ভেতরে CPU অপেক্ষা করে না। এটি একটি **ব্রাঞ্চ-প্রেডিক্টর** দিয়ে শর্তের ফলাফল অনুমান করে এবং অনুমান করা পথে _স্পেকুলেটিভভাবে_ এক্সিকিউশন শুরু করে।

অনুমান সঠিক হলে এক্সিকিউশন এমনভাবে এগোয় যেন কোনো ব্রাঞ্চই ছিল না। কিন্তু অনুমান ভুল হলে, CPU-কে অনুমান করা পথে _করা কাজটি বাতিল_ করে সঠিক পথে আবার শুরু করতে হয়।

একে বলা হয় **ব্রাঞ্চ মিসপ্রেডিকশন**, আর এটি ব্যয়বহুল এবং একটি বিলম্ব ডেকে আনে।

কোনো ব্রাঞ্চ অনুমান করা কঠিন হলে এই মিসপ্রেডিকশনগুলো জমতে থাকে। সে ক্ষেত্রে অনেক সময় ব্রাঞ্চটি পুরোপুরি এড়িয়ে যাওয়াই ভালো, যাতে শর্ত যাই হোক একই ইনস্ট্রাকশন এক্সিকিউট হয়। `jcc` ছাড়া মানগুলোর মধ্যে বাছাই করা কোডকে বলা হয় **ব্রাঞ্চলেস**।

কোড এমনভাবে সাজানোর বেশ কিছু উপায় আছে যাতে এটি কম ব্রাঞ্চ করে, অথবা যে ব্রাঞ্চগুলো থাকে সেগুলো আরও অনুমানযোগ্য হয়। বিশেষ করে x86-64 এমন দুটি ইনস্ট্রাকশন পরিবার দেয়, যেগুলো ব্রাঞ্চলেস কোড লেখার জন্য বহুল ব্যবহৃত হয়।

### কন্ডিশনাল মুভ

`cmovcc` ইনস্ট্রাকশন পরিবারটি কেবল একটি নির্দিষ্ট শর্ত পূরণ হলেই সোর্স অপারেন্ডটি ডেস্টিনেশনে কপি করে। অন্যথায় ডেস্টিনেশন অপরিবর্তিত থাকে।

`cc` সাফিক্স `jcc`-এর মতোই একই নামকরণ অনুসরণ করে, অর্থও একই:

| ইনস্ট্রাকশন | কখন মুভ করবে |
|-------------|--------------------------------------|
| `cmove`     | `cmp A, B`-এর পর A == B              |
| `cmovne`    | `cmp A, B`-এর পর A != B              |
| `cmovl`     | `cmp A, B`-এর পর A < B (সাইনড)      |
| `cmovb`     | `cmp A, B`-এর পর A < B (আনসাইনড)    |
| `cmovg`     | `cmp A, B`-এর পর A > B (সাইনড)      |
| `cmova`     | `cmp A, B`-এর পর A > B (আনসাইনড)    |

নিয়মগুলো `jcc`-এর মতোই:

1. সাইনড তুলনার জন্য `l` ও `g`, আর আনসাইনড তুলনার জন্য `b` ও `a` ব্যবহৃত হয়।
2. কোনো সাফিক্সের সাথে `e` যোগ করলে সমতা অন্তর্ভুক্ত হয়।
3. `n` যোগ করলে শর্তটি নেগেট হয়।
4. এমন ভ্যারিয়েন্টও আছে যেগুলো ফ্ল্যাগ সেট হওয়াকে বোঝায়।
   উদাহরণস্বরূপ, `cmovz` ও `cmovc`।

`rdi`-তে থাকা একটি সাইনড ইন্টিজারের অ্যাবসোলিউট ভ্যালু বিবেচনা করুন, যেটি `rax`-এ রিটার্ন করা হয়। `jcc` দিয়ে লিখলে ফাংশনটি দুটি পথের মধ্যে একটি বেছে নেয়:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

`cmovcc` দিয়ে লিখলে দুটি প্রার্থী মানই শর্তহীনভাবে হিসাব করা হয় এবং কন্ডিশনাল মুভ সেগুলোর একটি বেছে নেয়:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

ব্রাঞ্চলেস সংস্করণে সবসময় একই ইনস্ট্রাকশন এক্সিকিউট হয়। প্রেডিক্টরের অনুমান করার জন্য কোনো `jcc` নেই।

একটি `cmovcc`-এর ডেস্টিনেশন অবশ্যই একটি রেজিস্টার হতে হবে। সোর্স একটি রেজিস্টার বা মেমোরি লোকেশন হতে পারে, কিন্তু ইমিডিয়েট হতে পারে না।

~~~~exercism/note
উপরের কোডে, `neg` ইনস্ট্রাকশনটি ফলাফল অনুযায়ী বেশ কিছু ফ্ল্যাগ সেট করে, যার মধ্যে সাইন ফ্ল্যাগ (SF)-ও রয়েছে। এর মানে হলো, `cmp rdi, 0` পুরোপুরি বাদ দেওয়া যায়:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

ধনাত্মক `rdi`-এর ক্ষেত্রে `neg` একটি ঋণাত্মক ফলাফল দেয় এবং SF == 1 হয়, তাই `cmovs` আবার `rdi` ফিরিয়ে আনে। শূন্য বা ঋণাত্মক `rdi`-এর ক্ষেত্রে `neg` একটি অ-ঋণাত্মক ফলাফল দেয় এবং SF == 0 হয়, তাই `rax` নেগেট করা মানটিই ধরে রাখে (যা সঠিক অ্যাবসোলিউট ভ্যালু)।

যদিও অ্যাসেম্বলি কোডে মান তুলনা করার প্রধান উপায় `cmp`, তবুও অনেক ইনস্ট্রাকশন তাদের ফলাফল অনুযায়ী ফ্ল্যাগ সেট করে। কোনো ইনস্ট্রাকশন কোন কোন ফ্ল্যাগে প্রভাব ফেলে তার পূর্ণ তালিকা সাধারণত তার [রেফারেন্স][reference]-এ দেওয়া থাকে। বিশেষ করে `neg`-এর ক্ষেত্রে সেগুলো হলো SF, ZF, CF, OF এবং PF।

[reference]: https://www.felixcloutier.com/x86/
~~~~

### কন্ডিশনাল সেট

`setcc` ইনস্ট্রাকশন পরিবারটি একটি নির্দিষ্ট শর্ত পূরণ হলে ডেস্টিনেশন অপারেন্ডকে `1`-এ সেট করে, আর অন্যথায় `0`-এ। ডেস্টিনেশন সবসময়ই একটি _৮-বিট অপারেন্ড_।

`cc` সাফিক্স `jcc` ও `cmovcc`-এর মতোই একই নামকরণ অনুসরণ করে। উদাহরণস্বরূপ, `setz` ডেস্টিনেশনকে `1`-এ সেট করে যদি `ZF == 1` হয়, আর অন্যথায় `0`-এ।

যেহেতু ডেস্টিনেশন ৮-বিট, তাই বড় কোনো মান দরকার হলে `setcc`-এর পরে `movzx` ব্যবহার করা সাধারণ ব্যাপার:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

তুলনার ফলাফলকে `0` বা `1` ইন্টিজারে বদলে দেওয়ার এটি একটি কমন আইডিয়ম।
