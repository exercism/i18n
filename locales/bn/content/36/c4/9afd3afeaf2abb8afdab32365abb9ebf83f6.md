# ইটারেটর

ইটারেটর হলো একটি রুটিন, যার নাম `!` দিয়ে শেষ হয় এবং যা কেবল একটি `loop`-এর ভেতরেই কল করা যায়। লুপটি প্রতিবার ঘুরলে এটি তার পরের মানটি তৈরি করে; আর যখন এটি ফুরিয়ে যায়, লুপটিও সঙ্গে সঙ্গে শেষ হয়ে যায়।

```sather
   loop
      total := total + counts.elt!;
   end;
```

Sather-এ কোনো `for` স্টেটমেন্ট নেই। এটাই তার বদলি, আর এই বৈশিষ্ট্যের জন্যই ভাষাটি পরিচিত।

## শুরুতেই যেগুলো জানা দরকার

| ইটারেটর | কী দেয় |
| --- | --- |
| `a.elt!` | `a`-এর প্রতিটি এলিমেন্ট, ক্রমানুসারে |
| `a.ind!` | `a`-এর প্রতিটি অবস্থান: 0, 1, 2 … |
| `n.upto!(m)` | `n`, `n+1` … `m` |
| `n.downto!(m)` | `n`, `n-1` … `m` |
| `n.times!` | `n` বার চলে, কিছুই দেয় না |
| `n.up!` | `n`, `n+1`, … এবং কখনো শেষ হয় না |
| `s.elt!` | স্ট্রিংয়ের প্রতিটি ক্যারেক্টার |

`until!`, `while!` এবং `break!`-ও ইটারেটর। এজন্যই এগুলোর নাম `!` দিয়ে শেষ হয় এবং এজন্যই এগুলো কেবল লুপের ভেতরে কাজ করে।

## কলটি কোথায় বসে

একটি এক্সপ্রেশন যেখানেই বসতে পারে, একটি ইটারেটর কলও সেখানেই বসতে পারে, এমনকি একটি শর্তের মাঝখানেও:

```sather
   loop
      if counts.elt! > 10 then busy := busy + 1; end;
   end;
```

প্রোগ্রামে যেখানে যেখানে একটি ইটারেটর লেখা হয়, তার প্রতিটি *জায়গা* নিজের অবস্থান আলাদা করে ধরে রাখে। একটি লুপ বডিতে দুইবার `counts.elt!` লিখলে অ্যারেটির দুটি স্বতন্ত্র ভ্রমণ হয়ে যায়, যা প্রায় কখনোই কাঙ্ক্ষিত নয়:

```sather
   loop
      #OUT + counts.elt! + " and " + counts.elt!;   -- two separate walks
   end;
```

বরং একবারই কল করে মানটি একটি ভ্যারিয়েবলে রেখে দিন।

## লুপ শেষ করা

এর ভেতরের *যেকোনো* একটি ইটারেটর ফুরিয়ে গেলেই লুপটি শেষ হয়ে যায়, সবার ফুরিয়ে যাওয়ার জন্য অপেক্ষা করতে হয় না। একটি ইটারেটর থাকলে বিষয়টি স্পষ্ট। কয়েকটি থাকলে এই নিয়মেই সবাই ধরা পড়ে, আর পরের অনুশীলনীর বিষয়ও এটাই।

## কোনটি বেছে নেবেন

যখন মান দরকার তখন `elt!`, আর যখন অবস্থান দরকার তখন `ind!` বেছে নিন। একসঙ্গে দুটোই দরকার হলে, বা উত্তরটি মান নয় বরং একটি অবস্থান হলে, তবেই `0 .. a.size - 1`-এর বদলে `upto!`-তে ফিরে যান।
