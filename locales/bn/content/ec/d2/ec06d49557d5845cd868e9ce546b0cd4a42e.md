# পরিচিতি

Factor-এর I/O একটি একক [প্রোটোকল][stream-protocol]-এর ওপর গড়ে উঠেছে, যা যেকোনো ডেটা সোর্স বা সিঙ্ক ইমপ্লিমেন্ট করতে পারে। সাথে থাকা স্ট্রিমগুলো (`<file-reader>`, `<file-writer>`, `<string-reader>`, `<string-writer>`, নেটওয়ার্ক সকেট, বাইট অ্যারে, tty) সবই ক্লাস, যেগুলো [`io`][io] থেকে একই কয়েকটি জেনেরিক ইমপ্লিমেন্ট করে এবং [`destructors`][destructors] থেকে `disposable` এক্সটেন্ড করে।

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe` হলো লো-লেভেলের ব্যাচ রিড: কলারের দেওয়া একটি বাফার ভরে দেয় এবং কতগুলো এলিমেন্ট লেখা হয়েছে তা রিটার্ন করে। পাবলিক `stream-read` আর `stream-read-partial` এর ওপরেই তৈরি এবং অ্যালোকেশন সামলায়। বেশিরভাগ ইউজার-ডিফাইনড স্ট্রিম হয় `stream-read1` ইমপ্লিমেন্ট করে (যখন একবারে একটি এলিমেন্ট পড়া হয়), নয়তো `stream-read-unsafe` (যখন ব্যাচে পড়া যায়)।

`stream-element-type` দুটি সিঙ্গলটন টোকেনের একটি রিটার্ন করে: বাইট স্ট্রিমের (ফাইল রিডার, সকেট) জন্য `+byte+`, আর ক্যারেক্টার স্ট্রিমের (স্ট্রিং রিডার, tty) জন্য `+character+`। র‍্যাপার স্ট্রিম সাধারণত কেবল তার অন্তর্গত স্ট্রিমের কাছে দায়িত্ব ডেলিগেট করে।

## মিক্সিনে যুক্ত হওয়া

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

একটি ক্লাস একটিতে, অন্যটিতে, বা দুটিতেই থাকতে পারে। মিক্সিনে যুক্ত হলে `input-stream` / `output-stream`-এর ডিফল্ট মেথডগুলো আপনার ক্লাসে ডিসপ্যাচ করে, ঠিক `sets` ভোকাবের `set`-এর মতো ওপেন-মিক্সিন প্যাটার্ন।

## ডিসপোজেবল ফ্রেমওয়ার্ক

`new-disposable ( class -- disposable )` একটি নতুন ইনস্ট্যান্সকে বর্তমান ডিস্ট্রাক্টর স্কোপে রেজিস্টার করে, যাতে রিসোর্স সেটআপের মাঝপথে এক্সেপশন ঘটলে তা পরিষ্কারভাবে আনওয়াইন্ড হয়:

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose` হলো পাবলিক ওয়ার্ড; `dispose*` হলো সেই জেনেরিক, যা ক্লাসটি ইমপ্লিমেন্ট করে। সাবক্লাসে `dispose*` ওভাররাইড করলে সেখানে নিজের স্টেট পরিষ্কার করা উচিত, তারপর নিজের অধীনে থাকা রিসোর্সগুলো ডিসপোজ করা উচিত:

```factor
M: my-stream dispose* underlying>> dispose ;
```

ফ্রেমওয়ার্ক নিশ্চয়তা দেয় যে `dispose*` প্রতি অবজেক্টে সর্বোচ্চ একবার রান করে; `dispose` বারবার কল করলে কিছুই ঘটে না।

## স্কোপড অ্যাকসেসর

তিনটি কম্বিনেটর `print`, `read1` ইত্যাদির ব্যবহৃত গ্লোবাল “চলতি ইনপুট/আউটপুট স্ট্রিম” সেটআপ করে:

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

প্রতিটিই বেরোনোর সময় রিসোর্সটি ডিসপোজ করে, কোয়োটেশনটি এক্সেপশন থ্রো করলেও। বেশিরভাগ কোড কাস্টম স্ট্রিম ব্যবহার করে এভাবেই, প্রতিটি কলে সেটি পাস করার বদলে।
