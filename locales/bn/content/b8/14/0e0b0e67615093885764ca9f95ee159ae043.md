# পরিচিতি

সিলেবাসের এই পর্যায়ে এসে আপনি ইতিমধ্যেই দেখেছেন, R-কে প্রায়শই একটি ইম্পারেটিভ ভাষা হিসেবে ব্যবহার করা হয়, আর ক্রমশ একটি ফাংশনাল ভাষা হিসেবেও (বিশেষত [`purrr`][ref-purrr] ও [`dplyr`][ref-dplyr] লাইব্রেরির সঙ্গে)।

এখন যদি বলা হয় R মূলত অবজেক্ট-ওরিয়েন্টেড, তাহলে কিছুটা সংশয় জাগতেই পারে!

অদ্ভুত শোনালেও কথাটি সত্য।
ভেতরে ভেতরে R তৈরি হয়েছে ক্লাস, ইনহেরিট্যান্স, পলিমরফিজম আর OOP প্রোগ্রামারদের চিরচেনা মনোভাব দিয়ে।

তবে Java বা Ruby-র (যা স্পষ্টভাবে OOP) বা এমনকি Python-এর (যা কিছু দিক থেকে আধা-গোপনে OOP) সঙ্গে পরিচিত যে কেউ R-এর এই পদ্ধতিটিকে ... _অপরিচিত_ই মনে করবেন।

শুরুতে বলি, এখানে একাধিক ক্লাস-ডিজাইন আছে: সাধারণভাবে ব্যবহৃত হয় সম্ভবত তিনটি (S3, S4, R6), তার সঙ্গে মূলত তাত্ত্বিক গুরুত্বের আরও কয়েকটি।

বিস্তারিত আলোচনা পাওয়া যাবে [Advanced R, 2e][book-advanced-r]-এর ১২ থেকে ১৬ নম্বর অধ্যায়ে।
২০১৯ সালের এই বইটি মূলত তাদের জন্য, যারা R-এর অভ্যন্তরীণ কার্যপ্রণালী বুঝতে ও রক্ষণাবেক্ষণ করতে চান, তাই সেখানে OOP অপরিহার্য।

শেষ ব্যবহারকারীকে কেন্দ্র করে লেখা পাঠ্যবইগুলো অবশ্য ভিন্ন কথা বলে।

- The Art of R Programming (২০১১, কেবল মুদ্রিত সংস্করণ) বইটিতে একটি OOP অধ্যায় আছে, যেখানে S3 আর (সংক্ষেপে) S4 নিয়ে আলোচনা করা হয়েছে, যা তখন গুরুত্বপূর্ণ ছিল।
  _"S3 ক্লাসগুলোর গঠন বরং জোড়াতালি দিয়ে বানানো"_ — এই মন্তব্যটি আজও চোখে পড়ার মতো সত্য।
- R in Action (৩য় সংস্করণ, ২০২২) বইটি শেষ দিকের একটি Advanced Programming অধ্যায়ে OOP-কে মাত্র ৩ পৃষ্ঠায় ঠেলে দিয়েছে।
- [R for Data Science, 2e][book-r-data-sci] (২০২৩, মুদ্রিত সংস্করণে ৫৪৮ পৃষ্ঠা) OOP-এর কোনো উল্লেখই করে না।

এই ধারণায় আমরা মূলত S3 ক্লাস নিয়েই আলোচনা করব, কারণ এগুলোই সবচেয়ে সরল, সবচেয়ে বেশি ব্যবহৃত এবং Exercism-ধরনের সমস্যার জন্য সবচেয়ে প্রাসঙ্গিক।
R ট্র্যাকের কিছু প্র্যাকটিস অনুশীলনীতে আপনাকে একটি S3 ক্লাস তৈরি করতে হয়, আবার কিছুতে এটি ঐচ্ছিক, তবে হালকাভাবে হলেও উৎসাহ দেওয়া হয়।

## S3 ক্লাস

এগুলো বেশ পুরনো: S3 নামটির অর্থ শুধু এই যে S ভাষার (R-এর একটি বাণিজ্যিক পূর্বসূরি) ৩ নম্বর সংস্করণে এগুলো চালু হয়েছিল।

একটি S3 ক্লাসও খুবই সরল: সাধারণত একটি [অ্যারে][concept-lists], যার অন্তত একটি অতিরিক্ত অ্যাট্রিবিউট থাকে।

[Advanced R][book-s3] থেকে উদ্ধৃতি: _"S3 অনানুষ্ঠানিক আর তাৎক্ষণিক, তবে এর ন্যূনতমবাদে একধরনের সৌন্দর্য আছে: এর কোনো অংশ সরিয়ে নিলে আর এটি কাজের একটি OO সিস্টেম হিসেবে থাকবে না।"_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

তাই [`class(obj)`][ref-class]-এ অ্যাসাইনমেন্ট করলে `obj`-এর সঙ্গে কেবল একটি অ্যাট্রিবিউট যোগ হয়, এক্ষেত্রে যা pt2d-কে point2d ক্লাসের একটি ইনস্ট্যান্স হিসেবে চিহ্নিত করে।

তৈরির ধাপগুলো [`structure()`][ref-structure]-এর সঙ্গে মিলিয়ে করা যায়:

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

যদিও তৈরি হওয়া ইনস্ট্যান্স দুটি ধারণাগতভাবে অভিন্ন, তবু R-এর কাছে এটি যাচাই করার কোনো উপায় আমরা এখনও তৈরি করিনি।

### জেনেরিক মেথড

অন্য ভাষার OOP-এর সঙ্গে পরিচিত যে কেউ হয়তো ভাবছেন: _"ক্লাসের তো কাজ করতে পারার কথা, তাই না?"_

আমরা `point2d` ইনস্ট্যান্সের জন্য কোন মেথডগুলো পাওয়া যায় তা দেখতে পারি, আর দেখব যে (আসল `list`-এর বিপরীতে) এই মুহূর্তে কোনো মেথডই নেই।

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

বেশিরভাগ OOP ভাষায় মেথড ক্লাস ডেফিনিশনের ভেতরেই ডিফাইন করা হয়।
অল্প কিছু ভাষা (বিশেষত Ruby) পরে ক্লাসের মেথড যোগ ও পরিবর্তন করার সুযোগ দেয়।

S3 ক্লাস সম্পূর্ণ আলাদা।
ক্লাসে মেথড যোগ না করে আমরা বরং জেনেরিক মেথডে ক্লাসটি যোগ করি।

R কনসোলে ইন্টারঅ্যাক্টিভভাবে কাজ করা যে কেউ সারাক্ষণই জেনেরিক মেথড ব্যবহার করেন, সাধারণত সেগুলো কীভাবে বাস্তবায়িত হয়েছে তা না ভেবেই।

খুব পরিচিত একটি উদাহরণ `print()`, যদিও ফাংশনের নাম আপনি খুব কমই টাইপ করেন।
কনসোল প্রম্পটে শুধু একটি মান `x` লিখে দিলে সেটি আসলে `print(x)`-এর জন্য একধরনের সিনট্যাকটিক শুগার।

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

`pt2d` আমরা এখনই প্রিন্ট করতে পারি।
`print()` `point2d` ক্লাস সম্পর্কে কিছুই না জানলেও, নানা ধরনের অবজেক্ট সামলানোর জন্য এর যুক্তিসঙ্গত ডিফল্ট থাকে।

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

এটি বেশ ভার্বোজ, তাই বিন্দুটি সংক্ষেপে সুন্দরভাবে প্রিন্ট করার একটি উপায় আমাদের দরকার হতে পারে।

সহজ: শুধু `print.point2d()` নামে একটি ফাংশন যোগ করুন।
নামটি `methodname.classname` আকারে হতে হবে, যাতে ডিসপ্যাচার জানে কী খুঁজতে হবে।

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

এখন ধরুন আমরা একটি নতুন জেনেরিক মেথড বানাতে চাই, যেমন `y` স্থানাঙ্কের চিহ্ন উল্টে দেওয়ার জন্য `flipvert()`।

সেটিও সহজ:

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

এতে একটি ডিসপ্যাচার তৈরি হয়, যেখানে `x` হলো S3 ক্লাসযুক্ত আমাদের অবজেক্ট, আর `...` মেথড ডেফিনিশনের দরকার হতে পারে এমন অতিরিক্ত আর্গুমেন্ট সামলায় ("ডট আর্গ", যেমনটি [ফাংশন ধারণা][concept-functions]-তে বর্ণনা করা হয়েছে)।

এরপর আমরা `point2d`-এর জন্য মেথডটি ডিফাইন করে তা ব্যবহার করতে পারি।

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

এখন R জানে আমাদের বিন্দুটিকে কীভাবে উল্টাতে হয় আর ফলাফলটি কীভাবে দেখাতে হয়।

3D, পোলার স্থানাঙ্ক ইত্যাদির জন্য ক্লাস তৈরি করে, তারপর প্রতিটির জন্য মেথড ডিফাইন করে আমরা এটিকে আরও বাড়াতে পারি।

শেষ ব্যবহারকারীর দৃষ্টিতে কেবল `flipvert(x, ...)` আছে, আর ইনপুট ক্লাসটি নির্ণয় করে উপযুক্ত অন্তর্নিহিত বাস্তবায়ন ব্যবহার করার দায়িত্ব আমরা R-এর উপরেই ছেড়ে দিতে পারি।

~~~~exercism/caution
`verb.class` আকারের ফাংশন নাম ব্যবহারকারী এবং R পার্সার, দুজনের কাছেই S3 মেথডের মতো দেখায়।
অন্য প্রসঙ্গে একই ধরনের নামকরণ এড়িয়ে চলুন।

### ইনহেরিট্যান্স

OOP-প্রেমীরা ইনহেরিট্যান্স, সাবক্লাসিং, মিক্সিন আর এই ধরনের আরও অনেক কিছু নিয়ে একাধিক দীর্ঘ অধ্যায় লিখতে পারেন।

R শুধু `class` অ্যাট্রিবিউটে একাধিক নাম দিতে দেয়: একটিমাত্র স্ট্রিংয়ের বদলে স্ট্রিংয়ের একটি দীর্ঘতর ভেক্টর।

উদাহরণটিকে অতিরিক্ত টেনে ধরার ঝুঁকি নিয়েই ধরা যাক, আমরা একটি জেনেরিক `point` ক্লাস বানিয়েছি, আর সেটিকে সাবক্লাস করে `point2d`, `point3d` ইত্যাদি বানাতে চাই।

তাহলে `point2d`-এর সংজ্ঞায় কেবল `class = c("point2d", "point")` ব্যবহার করা হবে: নির্দিষ্ট ক্লাসটি এবং অভিভাবক ক্লাসটি (বা ক্লাসগুলো)।

তখন `print()`-এর মতো জেনেরিক মেথডগুলো ক্রমান্বয়ে `print.point2d()`, `print.point()` আর (সম্ভবত) `print.default()` খুঁজবে, আর ডিসপ্যাচার যে বাস্তবায়নটি প্রথমে পায়, সেটিই ব্যবহার করবে।

### নিরাপত্তা

অনেক OOP ভাষা (Java, C# ইত্যাদি) ক্লাসের ভেতরে ডেটা এনক্যাপসুলেশনের সুবিধা নিয়ে সতর্ক কম্পাইল-টাইম যাচাই করে আর টাইপ সেফটি নিশ্চিত করে।

মনে রাখবেন, S3 আপনাকে প্রায় যা খুশি তাই করতে দেয়, এমনকি অর্থহীন কিছু হলেও (তার জন্য এরর মেসেজ পেতে হলে পরে পাবেন, যদি আদৌ পান)।

["Advanced R"][book-s3] থেকে উদ্ধৃতি (২য় সংস্করণ, ১৩.৩ অনুচ্ছেদ):

> _আপনি যদি অন্য OO ভাষা ব্যবহার করে থাকেন, এতে আপনার অস্বস্তি লাগতে পারে, কিন্তু বাস্তবে এই নমনীয়তা খুব একটা সমস্যা তৈরি করে না। R আপনাকে নিজের পায়ে গুলি করতে থেকে বিরত রাখে না, কিন্তু বন্দুকটি নিজের পায়ের আঙুলে তাক করে ট্রিগার না টানলে আপনার কোনো সমস্যাই হবে না।_

আচ্ছা, _ঠিক আছে?_
অন্বেষণমূলক ডেটা সায়েন্স আর পরিসংখ্যানের জন্য R অসাধারণ, বিশেষত ইন্টারঅ্যাক্টিভভাবে কাজ করার সময়।
কেউই বলছে না যে অত্যন্ত সুরক্ষিত কর্পোরেট ফিন্যান্স সিস্টেম লিখতে আপনার এটি ব্যবহার করা উচিত!
