# ভূমিকা

কখনও কখনও একটি সিকোয়েন্স ধরে এগোনোর সময় আপনার এলিমেন্টটির নিজের পাশাপাশি তার *অবস্থান*-ও দরকার হয়। [`sequences`][sequences]-এ থাকা `*-index` পরিবারটি দুটোই প্রতি-এলিমেন্ট কোয়োটেশনকে দিয়ে দেয়। আর সাধারণ গণনাভিত্তিক ইটারেশনের ঘনিষ্ঠ আত্মীয় হলো `times`, যা কাজে লাগে যখন আপনার শুধু একটি গণনা দরকার, কোনো সিকোয়েন্স নয়।

## `each-index` এবং `map-index`: কোয়োটেশনে ইনডেক্স

```
each-index ( seq quot: ( elt index -- )       -- )
map-index  ( seq quot: ( elt index -- newelt ) -- newseq )
```

কোয়োটেশনটি ইনডেক্সের নিচে থাকা এলিমেন্টটি গ্রহণ করে, অর্থাৎ `index` থাকে স্ট্যাকের **উপরে**:

```factor
USING: io kernel math.parser sequences ;

{ "alice" "bob" "carol" } [
    number>string ": " glue print
] each-index
! prints:
! alice: 0
! bob:   1
! carol: 2

{ 10 20 30 } [ + ] map-index .
! => { 10 21 32 }       (index added to each element)
```

`each-index` কোয়োটেশনটি চালায় শুধু তার সাইড এফেক্টের জন্য, আর কিছুই রিটার্ন করে না। `map-index` প্রতি-এলিমেন্ট ফলাফলগুলো সংগ্রহ করে ইনপুটের মতো একই ধরনের একটি নতুন সিকোয়েন্সে।

## `times`: গণনাভিত্তিক ইটারেশন

[`math`][math]-এ থাকা `times` তার কোয়োটেশনটি `n` বার চালায়।

```
times ( n quot: ( -- ) -- )
```

প্রকাশিত `( -- )` আকারটি হলো *সর্বনিম্ন*। যেহেতু `times` `inline`, তাই `( str -- str )`-এর মতো এফেক্ট-ব্যালান্সড কোয়োটেশনও ভালোভাবে কাজ করে, আর স্ট্যাকটি এক ইটারেশন থেকে পরের ইটারেশনে বহন করা হয়। ফলে কোনো পরিবর্তনযোগ্য অবস্থা ছাড়াই আপনি একটি গণনাভিত্তিক অ্যাকুমুলেটর পেয়ে যান:

```factor
USING: kernel sequences ;

"" 3 [ "clop " append ] times .    ! => "clop clop clop "
```

প্রতিটি ইটারেশনের বডি চলমান স্ট্রিংটি দেখতে পায়, তাতে যোগ করে, আর পরের ইটারেশনের জন্য নতুন স্ট্রিংটি স্ট্যাকে রেখে দেয়। আপনি যখন একটি অ্যাকুমুলেটর পুরো প্রক্রিয়ার মধ্য দিয়ে বহন করতে চান, তখন একই কৌশল `each-index` আর `map-index`-এর ক্ষেত্রেও কাজ করে।
