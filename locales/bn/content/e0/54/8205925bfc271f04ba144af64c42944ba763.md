# বন্ধনী সম্পর্কে কিছু নোট

Tcl একটি [খুব সরল ভাষা](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm), কিন্তু ইন্টারপ্রেটার যেভাবে কোড পার্স করে তাতে কয়েকটি বিরক্তিকর জটিল পরিস্থিতি আছে।

## কোঁকড়া বন্ধনী

Tcl-এ কোঁকড়া বন্ধনী মূলত একটি লেখার ব্লক কোট করার উপায়; ওই লেখাটি কোড বা ডেটা হিসেবেও ব্যাখ্যা করা যায়। কোঁকড়া বন্ধনীর ভেতরে নেস্টেড কোঁকড়া বন্ধনী থাকতে পারে, তবে সেগুলোর ভারসাম্য অবশ্যই থাকতে হবে। Tcl-এর ম্যান পেজে বলা হয়েছে:

> কোঁকড়া বন্ধনী শব্দের ভেতরে নেস্ট হয়: প্রতিটি অতিরিক্ত খোলা বন্ধনীর জন্য একটি অতিরিক্ত বন্ধ বন্ধনী থাকতে হবে (তবে, শব্দের ভেতরে কোনো খোলা বা বন্ধ বন্ধনী যদি _ব্যাকস্ল্যাশ দিয়ে কোট করা_ থাকে, তাহলে মিলে যাওয়া বন্ধ বন্ধনী খুঁজতে সেটি গণনায় ধরা হয় না)।

এখানে কথাগুলো বেশ নির্দিষ্ট: আপনি যদি কোনো অমিল খোলা বা বন্ধ বন্ধনী অক্ষর রাখতে চান, তবে তা অবশ্যই ব্যাকস্ল্যাশ দিয়ে কোট করতে হবে। তাই এটি করবেন না:
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "{"}]
    # ......................^ will not work
}
```
আর এটি করতে হবে
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "\{"}]
    # ......................^^ will work
}
```

Tcl যেভাবে কমেন্ট পার্স করে তা বেশিরভাগ ভাষার থেকে আলাদা, আর এখানেই সমস্যা হতে পারে। [Tcl উইকিতে](https://wiki.tcl-lang.org/page/Why+can+I+not+place+unmatched+braces+in+Tcl+comments) আরও আলোচনা আছে।

## বর্গ বন্ধনী

একইভাবে, Tcl যেহেতু [কমান্ড সাবস্টিটিউশন](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M11)-এর জন্য বন্ধনী ব্যবহার করে, ডাবল কোট করা স্ট্রিংয়ের ভেতরেও খোলা বন্ধনী এস্কেপ করার সময় সাবধানে থাকতে হবে।

## বন্ধনী

[অ্যাসোসিয়েটিভ অ্যারে ভ্যারিয়েবল](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M12) ছাড়া বাকি ক্ষেত্রে বন্ধনী সাধারণ অক্ষর ছাড়া আর কিছু নয়।
