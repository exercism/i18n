# সম্পর্কে

`Result` টাইপ দিয়ে একটি ফাংশন একটিমাত্র মান রিটার্ন করতে পারে, যা নিচের সব বিষয় বোঝায়:
- অপারেশনটি সফল হয়েছে, নাকি ব্যর্থ হয়েছে
- সফল হলে, অপারেশনের ফলাফল হিসেবে পাওয়া মান
- ব্যর্থ হলে, ব্যর্থতার কারণ

যেসব অন্য প্রোগ্রামিং ভাষায় `Result` টাইপের মতো কিছু নেই, সেখানে উপরের লক্ষ্যগুলো পূরণ করতে নিচের প্যাটার্নগুলো কমন:
- একটি ফাংশন একটি সাংখ্যিক কোড রিটার্ন করে, যা সফলতা বা ব্যর্থতার কারণ বোঝায়, আর সফল হলে মানটি গ্রহণ করার জন্য একটি আউটপুট প্যারামিটার লাগে।
- একটি ফাংশন সফল হলে মান রিটার্ন করে, আর এরর হলে NULL, তারপর আলাদা একটি ফাংশন দিয়ে সেই এরর কোড পাওয়া যায়, যা ব্যর্থতার কারণ বোঝায়।

আরেকটি কমন এরর হ্যান্ডলিং পদ্ধতি হলো এক্সেপশন, যা কোনো ব্যর্থতা ঘটলে হঠাৎ করেই বর্তমান ফাংশন থেকে বেরিয়ে গিয়ে কল স্ট্যাকের প্রথম হ্যান্ডলারের কাছে নিয়ন্ত্রণ হস্তান্তর করে।  
যদি কোনো হ্যান্ডলার এক্সেপশনটি "ক্যাচ" না করে, তাহলে প্রোগ্রামটি অ্যাবর্ট হয়ে যায়।

## `Result` টাইপ ব্যবহারের সুবিধা

* __কম্পাইল-টাইম সেফটি__: ফাংশন কলের সফলতা বা ব্যর্থতা টাইপ সিস্টেমে স্পষ্টভাবে প্রকাশ করার মাধ্যমে কম্পাইলার নিশ্চিত করতে পারে যে কল করা কোড ব্যর্থতার সব কেস সামলাচ্ছে, ফলে null নিয়ে ঘটতে পারে এমন এক বিশাল শ্রেণির বাগ ঠেকানো যায়।

* __রান-টাইম সেফটি__: `null` ব্যবহার না করে `Result` টাইপ ব্যর্থতা বোঝাতে `Error` ব্যবহার করে, ফলে `NullReferenceException` ঘটার কোনো উপায়ই থাকে না।

* __স্পষ্ট এরর হ্যান্ডলিং__: `Result` রিটার্ন করা কোনো ফাংশন কল করলে কোডকে স্বীকার করতেই হয় যে কলটি ব্যর্থ হতে পারে; কল করা কোডকে এসব ব্যর্থতা সচেতনভাবেই সামলাতে হয়। এখানে কোনো নীরব ব্যর্থতা নেই, কোনো আকস্মিক এক্সেপশনও নেই।

* __পূর্বানুমেয় কন্ট্রোল ফ্লো__: যেকোনো অন্য মানের মতোই `Result` রিটার্ন করা হয়; এক্সেপশনের মতো এটি কল স্ট্যাক থেকে লাফিয়ে বেরিয়ে যায় না। এরর কোথা থেকে আসছে আর কীভাবে ছড়াচ্ছে, তা আপনি সবসময় জানেন।

* __উন্নত রিডেবিলিটি ও মেইনটেনেবিলিটি__: `Result` রিটার্ন করার ফলে একটি ফাংশনের সিগনেচার স্পষ্টভাবে জানিয়ে দেয় সফলতা ও ব্যর্থতার ক্ষেত্রে প্রত্যাশিত আচরণ কী।

## ব্যবহার

`Result` টাইপ একটি জেনেরিক টাইপ, যার ভেতরে দুটি অন্তর্নিহিত টাইপ থাকে:
- সফল অপারেশনে প্রাপ্ত মানের টাইপ
- ব্যর্থতার ক্ষেত্রে ব্যর্থতার কারণ বোঝানো টাইপ

`Result` টাইপটি আবার একটি [ডিসক্রিমিনেটেড ইউনিয়ন][discriminated-union], যার সম্ভাব্য কেসগুলো হলো:
* `Ok <value>` একটি সফল ফলাফল বোঝায়
* `Error <reason>` একটি ব্যর্থতা বোঝায়

নিচের ফাংশনটি দেখায় কীভাবে একটি `Result` মান তৈরি করতে হয়:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

এই উদাহরণে `Ok` মানটি একটি স্ট্রিং (প্রদত্ত নাম), আর `Error` মানটিও একটি স্ট্রিং (এররের কারণ, মানুষের পড়ার উপযোগী রূপে)।

## একটি `Result` মানের ভেতরের কনটেন্ট পড়া

নিচের টাইপ ডেফিনিশন ও ফাংশন সিগনেচারটি দেখুন:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

`openFile` ফাংশনটি কল করা কোড প্যাটার্ন ম্যাচিং ব্যবহার করে সফলতা ও ব্যর্থতার কেসগুলো সামলাতে পারে, যেমনটি নিচের উদাহরণে দেখানো হয়েছে:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
