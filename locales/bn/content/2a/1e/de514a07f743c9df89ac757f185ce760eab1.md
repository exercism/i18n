# সম্পর্কে

OS স্টেট ধরে রাখে এমন রিসোর্সগুলোর (ফাইল হ্যান্ডেল, সকেট, লক) *নিশ্চিত* ক্লিনআপ প্রয়োজন, এমনকি যখন কোনো এক্সসেপশন স্ট্যাক আনওয়াইন্ড করে তখনও। Factor-এর [`destructors`][destructors] ভোকাব এর জন্য একটি ছোট ফ্রেমওয়ার্ক দেয়, আর বেশিরভাগ বিল্ট-ইন রিসোর্স (`<file-reader>`, `<file-writer>`, সকেট, …) ইতিমধ্যেই এতে যুক্ত হয়ে যায়।

## ক্লাস এবং জেনেরিক

একটি ক্লাস `disposable` এক্সটেন্ড করে এবং `dispose*` ইমপ্লিমেন্ট করার মাধ্যমে যুক্ত হয়:

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )` টিউপলটি অ্যালোকেট করে *এবং* এটিকে বর্তমান ডেস্ট্রাক্টর স্কোপে রেজিস্টার করে, তাই অ্যালোকেশন এবং পরবর্তী নিরাপদ পয়েন্টের মধ্যে কোনো এক্সসেপশন ঘটলে রিসোর্সটি লিক করতে পারে না। ফ্রেমওয়ার্ক নিশ্চয়তা দেয় যে `dispose*` প্রতি অবজেক্টে **সর্বোচ্চ একবার** চলে; বারবার `dispose` কল করলে কিছুই হয় না।

## পাবলিক কলকারীরা `dispose` ব্যবহার করে

| ওয়ার্ড              | প্রভাব                                        |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )` রিলিজ করে; দুবার কল করা নিরাপদ    |
| `with-disposal`   | `( disposable quot -- )` একটি রিসোর্সের স্কোপ তৈরি করে |
| `with-destructors`| `( quot -- )` একটি রেজিস্ট্রি স্কোপ খোলে         |
| `&dispose`        | `( obj -- obj )` স্বাভাবিক *বা* ব্যর্থ প্রস্থানে ডিসপোজ করে |
| `|dispose`        | `( obj -- obj )` স্কোপ আনওয়াইন্ড হলে কেবল তখনই ডিসপোজ করে |

`with-disposal` হলো একক-রিসোর্স ফর্ম। একাধিক রিসোর্সের জন্য, একটি `with-destructors` স্কোপ খুলুন এবং প্রতিটি অ্যাকুইজিশন `&dispose` দিয়ে রেজিস্টার করুন (আপনি সবসময় এটি রিলিজ করতে চান) বা `|dispose` দিয়ে (শুধু ব্যর্থতার সময় রিলিজ করে; সফল পথে এটি ধরে রাখা হয়)।

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup` হলো বেয়ার প্রিমিটিভ

রেজিস্ট্রি ছাড়া একবারের try/finally-এর জন্য, `continuations` থেকে আসা [`cleanup`][cleanup] হলো নিম্নস্তরের ওয়ার্ড:

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` কঠোরভাবে আরও শক্তিশালী (রেজিস্ট্রি রানটাইমে বাড়তে পারে), কিন্তু যখন অ্যাকোয়ায়ার/রিলিজের জোড়া নির্দিষ্ট ও স্থানীয় হয়, তখন `cleanup`-ই স্বাভাবিক পছন্দ।

[destructors]: https://docs.factorcode.org/content/vocab-destructors.html
[cleanup]: https://docs.factorcode.org/content/word-cleanup%2Ccontinuations.html
