# পরিচিতি

Go-এর স্লাইস অন্য ভাষার অ্যারেগুলোর মতোই। এগুলো একটি নির্দিষ্ট টাইপের (বা ইন্টারফেসের) একাধিক এলিমেন্ট ধারণ করে।

Go-এর স্লাইস অ্যারের ওপর ভিত্তি করে তৈরি। অ্যারের আকার নির্দিষ্ট থাকে। অন্যদিকে স্লাইস হলো অ্যারের এলিমেন্টগুলোর একটি গতিশীল আকারের, নমনীয় ভিউ।

স্লাইস লেখা হয় `[]T` এর মতো, যেখানে `T` হলো স্লাইসের এলিমেন্টগুলোর টাইপ:

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

তৃতীয় বন্ধনী নোটেশন ব্যবহার করে নির্দিষ্ট জিরো-বেজড ইনডেক্সে একটি এলিমেন্ট পড়া বা সেট করা যায়:

```go
withData[1] = 5
x := withData[1] // x is now 5
```

এলিমেন্টের একটি রেঞ্জ নিয়ে বিদ্যমান স্লাইস থেকে নতুন স্লাইস তৈরি করা যায়। আবারও তৃতীয় বন্ধনী নোটেশন ব্যবহার করে, তবে এবার শুরুর (যেটি অন্তর্ভুক্ত) এবং শেষের (যেটি অন্তর্ভুক্ত নয়) ইনডেক্স দুটোই উল্লেখ করতে হয়। শুরুর ইনডেক্স উল্লেখ না করলে সেটি স্বাভাবিকভাবে 0 ধরা হয়। শেষের ইনডেক্স উল্লেখ না করলে সেটি স্লাইসের দৈর্ঘ্য ধরা হয়।

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

`append` ফাংশন ব্যবহার করে স্লাইসে এলিমেন্ট যোগ করা যায়। নিচে আমরা `a` স্লাইসে `4` ও `2` যোগ করছি।

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append` সর্বদা একটি নতুন স্লাইস রিটার্ন করে, আর যখন আমরা কেবল বিদ্যমান স্লাইসে এলিমেন্ট যোগ করতে চাই, তখন প্রথম আর্গুমেন্ট হিসেবে পাঠানো স্লাইস ভ্যারিয়েবলেই সেটি আবার অ্যাসাইন করে দেওয়াটাই কমন, যেমনটি আমরা উপরে করেছি।

`append` দিয়ে দুটি স্লাইস একসাথে মেলানোও যায়:

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## স্লাইসের ইনডেক্স

স্লাইসের ইনডেক্স নিয়ে কাজ করার সময় সবসময় কোনোভাবে যাচাই করে নিশ্চিত হওয়া উচিত যে ইনডেক্সটি আসলেই আছে। এটা না করলে পুরো অ্যাপ্লিকেশনটি ক্র্যাশ করবে।

## খালি স্লাইস

`nil`-স্লাইস হলো ডিফল্ট খালি স্লাইস। কোনো মান না থাকা স্লাইসের তুলনায় এদের কোনো অসুবিধা নেই। `len` ফাংশন `nil`-স্লাইসেও কাজ করে, সেটি ইনিশিয়ালাইজ না করেই আইটেম যোগ করা যায়, ইত্যাদি। নতুন স্লাইস তৈরি করতে হলে `s := []int{}` (খালি, `nil` নয় এমন স্লাইস) এর চেয়ে `var s []int` (`nil`-স্লাইস) কেই প্রাধান্য দিন।

## পারফরম্যান্স

ধাপে ধাপে পূরণ করার জন্য স্লাইস তৈরি করার সময়, স্লাইসের চূড়ান্ত আকার জানা থাকলে পারফরম্যান্স উন্নত করার একটি সহজ সুযোগ থাকে। মূল কথা হলো মেমরি অ্যালোকেট করার সংখ্যা যতটা সম্ভব কমানো, কারণ এটা বেশ খরচসাপেক্ষ এবং স্লাইস তার বরাদ্দ করা মেমরি স্পেস ছাড়িয়ে বড় হয়ে গেলেই এটা ঘটে। এটা করার সবচেয়ে নিরাপদ উপায় হলো `s := make([]int, 0, cap)` দিয়ে স্লাইসের জন্য একটি ক্যাপাসিটি `cap` উল্লেখ করা, তারপর যথারীতি স্লাইসে `append` করা। এভাবে স্লাইসের দৈর্ঘ্য শূন্য থাকা অবস্থাতেই `cap` পরিমাণ আইটেমের জায়গা সঙ্গে সঙ্গে বরাদ্দ হয়ে যায়। বাস্তবে `cap` প্রায়ই অন্য একটি স্লাইসের দৈর্ঘ্য হয়ে থাকে: `s := make([]int, 0, len(otherSlice))`।

## `append` কোনো পিওর ফাংশন নয়

Go-এর `append` ফাংশনটি পারফরম্যান্সের জন্য অপ্টিমাইজ করা, তাই এটি ইনপুট স্লাইসের একটি কপি তৈরি করে না। এর মানে হলো মূল স্লাইসটি (অর্থাৎ `append`-এর ১ম প্যারামিটার) মাঝেমধ্যে পরিবর্তিত হয়ে যাবে।
