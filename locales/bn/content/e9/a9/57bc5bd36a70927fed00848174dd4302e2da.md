# পরিচিতি

এবার C++-এর একটি মূল প্যারাডাইম নিয়ে আলোচনার সময় এসেছে: অবজেক্ট-ওরিয়েন্টেড প্রোগ্রামিং (OOP)। OOP-এর কেন্দ্রে থাকে `classes`, অর্থাৎ ইউজার-ডিফাইনড ডেটা টাইপ, যাদের নিজস্ব সম্পর্কিত ফাংশনের সেট থাকে। আমরা শুরু করব মৌলিক বিষয়গুলো দিয়ে, আর আরও উন্নত বিষয় নিয়ে আলোচনা করা হবে সিলেবাসের আরও গভীরে।

## মেম্বার

ক্লাসে **মেম্বার ভ্যারিয়েবল** ও **মেম্বার ফাংশন** থাকতে পারে। এগুলোতে অ্যাক্সেস করা হয় **মেম্বার সিলেকশন** অপারেটর `.` দিয়ে। `classes`-এর বাইরের ভ্যারিয়েবলগুলোর মতোই, ডিক্লারেশনের সময়ই মেম্বার ভ্যারিয়েবলগুলোকে একটি মান দিয়ে ইনিশিয়ালাইজ করা বাঞ্ছনীয়। এই মানটিই তখন এই ক্লাস থেকে নতুন তৈরি হওয়া অবজেক্টগুলোর জন্য ডিফল্ট হয়ে যাবে।

## এনক্যাপসুলেশন ও ইনফরমেশন হাইডিং

ক্লাস তাদের মেম্বারগুলোর অ্যাক্সেস সীমিত করার সুযোগ দেয়। দুটি মূল ক্ষেত্র হলো `private` এবং `public`। `private` মেম্বারগুলো ক্লাসের বাইরে থেকে অ্যাক্সেস করা যায় না। `public` মেম্বারগুলো অবাধে কল করা যায়। সব মেম্বার ডিফল্টভাবে `private`, আর ক্লাসের বাইরে ব্যবহার করতে হলে সেগুলোকে স্পষ্টভাবে চিহ্নিত করতে হয়।

## একটি সাধারণ উদাহরণ

নতুন `class`-এর ডেফিনিশন নিচের উদাহরণে দেখা যায়। ডেফিনিশনের শেষে `;`-টি খেয়াল করুন।

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

ক্লাসের ভেতর থেকে আপনি সব ভ্যারিয়েবলে অ্যাক্সেস করতে পারেন। `cast_spell` ফাংশনের ভেতরের `damage`-টি একবার দেখুন। ক্লাসের বাইরে থেকে `private` মেম্বার পড়া বা বদলানো যায় না:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## কনস্ট্রাক্টর

কনস্ট্রাক্টর অবজেক্ট তৈরির সময়ই মেম্বার ভ্যারিয়েবলে মান অ্যাসাইন করার সুযোগ দেয়। এগুলোর নাম `class`-এর মতোই হয়, আর এগুলোর কোনো রিটার্ন টাইপ থাকে না। একটি ক্লাসে একাধিক কনস্ট্রাক্টর থাকতে পারে। সব ভ্যারিয়েবল সব সময় সেট করার দরকার না থাকলে এটি কাজে লাগে।

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

কনস্ট্রাক্টর একটি বড় বিষয়, এতে অনেক সূক্ষ্মতা আছে। আপনার `class`-এর জন্য যদি আপনি স্পষ্টভাবে কোনো `constructor` ডিফাইন না করেন, তাহলে (এবং কেবল তখনই) কম্পাইলার আপনার হয়ে কাজটি করে দেবে। উপরের প্রথম উদাহরণে ঠিক এটিই ঘটেছে। _silverhand_ অবজেক্টটি তৈরি হয়েছে ডিফল্ট কনস্ট্রাক্টর কল করে, কোনো আর্গুমেন্ট পাঠানো হয়নি। সব ভ্যারিয়েবল ক্লাসের ডেফিনিশনে যে মান লেখা ছিল, সেটিতেই সেট হয়ে যায়। ঐ ডেফিনিশনে যদি কোনো মান না দেওয়া হতো, তাহলে ভ্যারিয়েবলগুলো আন-ইনিশিয়ালাইজড থেকে যেতে পারত, যার পরিণতি অনিচ্ছাকৃত হতে পারত।

## স্ট্রাক্ট

স্ট্রাক্ট এসেছে ভাষাটির আদি C শিকড় থেকে, আর C++-এর মতোই পুরনো। একটি গুরুত্বপূর্ণ ব্যতিক্রম ছাড়া এগুলো কার্যত `classes`-এরই সমান। ডিফল্টভাবে `class`-এর সবকিছুই `private`। অন্যদিকে স্ট্রাক্ট, অন্যভাবে ডিফাইন না করা পর্যন্ত `public` থাকে। প্রচলিতভাবে `struct` কিওয়ার্ডটি প্রায়ই **শুধু ডেটা ধারণকারী স্ট্রাকচার**-এর জন্য ব্যবহার করা হয়। আর যে অবজেক্টগুলোকে নির্দিষ্ট কিছু বৈশিষ্ট্য নিশ্চিত করতে হয়, তাদের জন্য `class` কিওয়ার্ডটিই বেশি পছন্দের। এমন একটি ইনভ্যারিয়েন্ট হতে পারে এই যে আপনার `Wizzard` `class`-এর `damage` কখনো ঋণাত্মক হতে পারবে না। `damage` ভ্যারিয়েবলটি private, আর ড্যামেজ পরিবর্তন করে এমন যেকোনো ফাংশনই এই ইনভ্যারিয়েন্ট অক্ষুণ্ন রাখা নিশ্চিত করবে।
