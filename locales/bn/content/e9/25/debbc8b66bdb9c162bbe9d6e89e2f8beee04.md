# শর্ত

```sather
   if score >= 5 then
      return "Recalled";
   else
      return "Thank you";
   end;
```

`if` আর `then`-এর মাঝের প্রশ্নটি অবশ্যই একটি `BOOL` হতে হবে। Sather সেখানে কোনো সংখ্যা গ্রহণ করে না, তাই শূন্যকে ফলস ধরে নেওয়ার মতো C-স্টাইলের অভ্যাস এখানে নেই।

## গঠন

```sather
   if first_question then
      ...
   elsif second_question then
      ...
   elsif third_question then
      ...
   else
      ...
   end;
```

প্রশ্নগুলো উপর থেকে নিচের দিকে করা হয়, আর যে প্রশ্নটি প্রথমে ট্রু উত্তর দেয় সেটিই জিতে যায়। তার নিচের সবকিছু জিজ্ঞাসা না করেই এড়িয়ে যাওয়া হয়। সেজন্যই একটি শৃঙ্খলকে সবচেয়ে নির্দিষ্ট পরীক্ষা থেকে ক্রমশ কম নির্দিষ্ট পরীক্ষার দিকে সাজাতে হয়: `score >= 5`-কে `score >= 8`-এর উপরে রাখলে দ্বিতীয়টিতে আর কখনও পৌঁছানো যায় না।

`else` ঐচ্ছিক। `elsif` যতবার প্রয়োজন, ততবার লেখা যায়।

## শর্তগুলো স্টেটমেন্ট, মান নয়

`if` নিজে কোনো মান তৈরি করে না, তাই নিচের কোডটি বৈধ Sather নয়:

```sather
   -- wrong
   grade := if score > 5 then "pass" else "fail" end;
```

হয় প্রতিটি শাখার ভেতর থেকে রিটার্ন করুন, নয়তো প্রতিটি শাখার ভেতরেই একটি ভ্যারিয়েবলে অ্যাসাইন করুন।

## কখন এটি ব্যবহার করবেন না

যে রুটিন একটি প্রশ্নের উত্তর দেয়, তার উচিত সেই প্রশ্নটিই রিটার্ন করা:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;

   -- not this
   old_enough(age : INT) : BOOL is
      if age >= 13 then return true; else return false; end;
   end;
```

দ্বিতীয়টি প্রথমটি যা বলে তার বাইরে কিছুই বলে না, অথচ তার দৈর্ঘ্য তিন গুণ।

## নেস্টিং

একটি `if`-এর ভেতরে আরেকটি `if` থাকতে পারে। অনেক সময় সেটির প্রয়োজন হয় না: যে দুটি প্রশ্নের দুটিই ট্রু হতে হবে, সেগুলোকে বদলে `and` দিয়ে জোড়া লাগানো যায়, যা পড়তে আরও ভালো লাগে।

```sather
   if score >= 8 and sings then
      return "Lead";
   end;
```
