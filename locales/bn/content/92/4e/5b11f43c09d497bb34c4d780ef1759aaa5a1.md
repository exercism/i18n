# নির্দেশনার সংযোজন

## Roc/হোস্টের দায়িত্ব

Roc কোডে আমরা সাধারণত বিজনেস লজিক নিয়ে কাজ করি, আর প্ল্যাটফর্ম কনকারেন্সি ও শেয়ার্ড স্টেট সামলায়। তাই এই অনুশীলনীতে আপনাকে শুধু `BankAccount.roc`-এ অ্যাকাউন্টের অপারেশনগুলো ইমপ্লিমেন্ট করতে হবে; কনকারেন্সি নিয়ে ভাবতে হবে না। অ্যাকাউন্টগুলো শুরুতে বন্ধ থাকে, আবার খুললে ব্যালেন্স রিসেট হয়, আর ডিপোজিট ও উইথড্রয়াল অবশ্যই পজিটিভ হতে হবে।

## ঐচ্ছিক সার্ভার ডেমো

সঙ্গে দেওয়া `bank-account-demo.roc` দেখায় কীভাবে আপনার ইমপ্লিমেন্টেশন একটি ছোট ওয়েব সার্ভিসে ব্যবহার করা যায়। আপনি এটি এডিটরে পড়তে পারেন, তবে এটি টেস্ট থেকে স্বাধীন এবং আপনার সমাধানের অংশ নয়।

ডেমোটি রান করতে হলে আপনাকে আপনার মেশিনে [Roc ইনস্টল করতে হবে](https://www.roc-lang.org/install/), [Exercism CLI](https://exercism.org/cli-walkthrough) ইনস্টল করতে হবে, তারপর টার্মিনালে এই কমান্ডটি রান করতে হবে:

```sh
exercism download --exercise=bank-account --track=roc
```

এরপর `BankAccount.roc` ইমপ্লিমেন্ট করুন এবং নিচের কমান্ড দিয়ে এটি টেস্ট করুন (CLI যে ডাউনলোড লোকেশন প্রিন্ট করে সেটি নিচের পাথ থেকে ভিন্ন হলে সেটি পরিবর্তন করুন):

```sh
cd ~/Exercism/roc/bank-account
roc test bank-account-test.roc
```

সব টেস্ট পাস হলে নিচের কমান্ড দিয়ে ডেমো সার্ভারটি চালু করতে পারেন:

```sh
roc bank-account-demo.roc
```

সার্ভারটি [basic-webserver প্ল্যাটফর্ম](https://github.com/roc-lang/basic-webserver) এবং এর বিল্ট-ইন SQLite সাপোর্ট ব্যবহার করে (প্রথমবার রান করার সময় Roc প্ল্যাটফর্মটি ডাউনলোড করে)। আলাদা কোনো ডাটাবেস সার্ভার প্রয়োজন নেই। সার্ভারটি `http://127.0.0.1:8000`-এ লিসেন করে এবং আপনার বর্তমান ডিরেক্টরিতে `bank-account-demo.db` তৈরি করে (ভিন্ন ডাটাবেস ফাইল ব্যবহার করতে `DB_PATH` সেট করুন)। Ctrl-C দিয়ে সার্ভারটি বন্ধ করুন। ডেটা রিস্টার্টের পরেও টিকে থাকে।

অন্য একটি টার্মিনালে আপনি `curl` দিয়ে ওয়েব সার্ভিসটি কল করতে পারেন (Windows-এ PowerShell-এর `curl` অ্যালিয়াস এড়াতে সব জায়গায় `curl.exe` ব্যবহার করুন)। উদাহরণস্বরূপ, #123 অ্যাকাউন্ট খুলতে, 50 ডিপোজিট করতে, 10 উইথড্র করতে এবং এর ব্যালেন্স দেখতে হলে ঠিক এভাবে করুন:

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/open
curl -X POST http://127.0.0.1:8000/accounts/123/deposit/50
curl -X POST http://127.0.0.1:8000/accounts/123/withdraw/10
curl http://127.0.0.1:8000/accounts/123/balance
```

ব্যালেন্স হয় `40`। অ্যাকাউন্ট ID এবং অ্যামাউন্ট অবশ্যই আনসাইন্ড ইন্টিজার হতে হবে। আপডেটগুলো সফল হলে `OK` এবং ব্যর্থ হলে আপনার অ্যাকাউন্ট ইমপ্লিমেন্টেশন থেকে একটি এরর রিটার্ন করে। #123 অ্যাকাউন্ট বন্ধ করতে:

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/close
```

Linux/macOS-এ কনকারেন্ট রিকোয়েস্ট চেষ্টা করতে, একটি নতুন অ্যাকাউন্ট ID ব্যবহার করুন এবং আটটি ক্লায়েন্ট থেকে ১০০টি ডিপোজিট পাঠান:

```sh
curl -X POST http://127.0.0.1:8000/accounts/456/open
seq 100 | xargs -P 8 -I '{}' curl --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1
curl http://127.0.0.1:8000/accounts/456/balance
```

Windows-এ প্যারালেল উদাহরণের জন্য [PowerShell 7+](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows) ব্যবহার করুন:

```powershell
curl.exe -X POST http://127.0.0.1:8000/accounts/456/open
1..100 | ForEach-Object -Parallel { curl.exe --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1 } -ThrottleLimit 8
curl.exe http://127.0.0.1:8000/accounts/456/balance
```

সব ডিপোজিটই সফল হওয়া উচিত এবং ব্যালেন্স হওয়া উচিত `100`।

## ডেমোটি কনকারেন্সি কীভাবে সামলায়

প্রতিটি রিকোয়েস্ট অ্যাকাউন্টটি পড়ে, আপনার Roc ফাংশনগুলো কল করে এবং একটি SQLite `Immediate` ট্রানজেকশনের মধ্যে ফলাফলটি সেভ করে। ব্যর্থ অপারেশনগুলো অ্যাকাউন্ট না বদলেই রোলব্যাক হয়। SQLite একসাথে একজন রাইটারকেই অনুমতি দেয়, ফলে কনকারেন্ট রিকোয়েস্টগুলো একে অপরের আপডেট ওভাররাইট করতে পারে না (এমনকি ভিন্ন অ্যাকাউন্টের ক্ষেত্রেও নয়)।

দ্রষ্টব্য: অনুশীলনীতে `U64` ব্যবহার করা হয়, কিন্তু ডেমো ব্যালেন্সগুলো SQLite ইন্টিজার হিসেবে সংরক্ষণ করে এবং সর্বোচ্চ `I64` মান (`9223372036854775807`) ছাড়িয়ে যাওয়া আপডেট প্রত্যাখ্যান করে।

সমান্তরালে স্বাধীন কম্পিউটেশন চালানোর উদাহরণের জন্য [সমান্তরাল অক্ষর-কম্পাঙ্ক অনুশীলনী](https://exercism.org/tracks/roc/exercises/parallel-letter-frequency) চেষ্টা করে দেখুন।
