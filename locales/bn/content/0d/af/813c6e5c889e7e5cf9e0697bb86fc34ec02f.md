# এক্সেপশন

কিছু রুটিন উত্তর দিতে পারে না। টেবিলে নেই এমন একটি prop চাওয়া হলে `count_of`-এর দেওয়ার মতো কোনো সংখ্যা থাকে না, আর শূন্য বললে সেটা মিথ্যা হয়ে যেত, কারণ শূন্যের অর্থ "আমাদের কাছে ওগুলোর একটিও নেই", "এমন কিছু আদৌ নেই" নয়।

একটি **এক্সেপশন** হলো রুটিনের সেই উপায়, যার মাধ্যমে সে বলে যে সে উত্তর দিতে পারবে না।

## রেইজ করা

`raise` রুটিনটি ছেড়ে দেয় আর যে ডেকেছে তার হাতে একটি মান তুলে দেয়।

```sather
   count_of(props : FMAP{STR,INT}, prop : STR) : INT is
      if ~props.has_ind(prop) then
         raise "Unknown prop: " + prop;
      end;
      return props.get(prop);
   end;
```

`raise`-এর পরের কোনো কিছুই রান হয় না। রুটিন রিটার্ন করে না, তাই যাচাই করার মতো কোনো উত্তর থাকে না, আর কলকারীর পক্ষে এমনভাবে এগিয়ে যাওয়ার উপায়ও থাকে না যেন উত্তরটা আছে।

রেইজ করা মানটি সাধারণত একটি স্ট্রিং, যা বলে দেয় কী ভুল হয়েছে।

## ক্যাচ করা

`protect` কোডের একটি অংশ রান করে, সেটি রেইজ করতে পারে ধরে নিয়েই।

```sather
   protect
      taken ::= count_of(props, prop);
      #OUT + "There are " + taken;
   when $STR then
      #OUT + "Cannot: " + exception.str;
   end;
```

যদি কিছুই রেইজ না হয়, `protect`-এর পরের অংশটি রান হয় আর `when` শাখাটি বাদ পড়ে। যদি কিছু রেইজ হয়, `protect` অংশের বাকিটা পরিত্যক্ত হয় আর তার বদলে মিলে যাওয়া `when` শাখাটি রান হয়।

`when $STR then` একটি রেইজ হওয়া স্ট্রিং ক্যাচ করে। `exception` হলো সেই মান, যা রেইজ করা হয়েছিল আর শাখার ভেতরে পাওয়া যায়।

## ভেতর দিয়ে যাওয়া

যে রুটিন একটি এক্সেপশন ক্যাচ করে না, তাকে তা নিয়ে কিছু করতে হয় না। সেটি বাইরের দিকে যেতে থাকে, প্রতিটি কলকারীর ভেতর দিয়ে, যতক্ষণ না কিছু একটা সেটি ক্যাচ করে:

```sather
   take_one(props : FMAP{STR,INT}, prop : STR) : INT is
      -- If this raises, take_one raises too. Nothing here says so.
      have ::= count_of(props, prop);
      ...
   end;
```

এটাই এক্সেপশনের আসল কথা। যে রুটিন সমস্যাটি লক্ষ্য করে আর যে রুটিন জানে এর সমাধানে কী করতে হবে, তারা সাধারণত একই রুটিন নয়, আর মাঝের সবকিছু সেটি উপেক্ষা করতে পারে।
