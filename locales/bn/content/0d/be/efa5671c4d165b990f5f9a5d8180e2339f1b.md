# পরিচিতি

Elm-এ [কাস্টম টাইপ][custom-types] বলতে নির্দিষ্ট সংখ্যক নামযুক্ত কেস বোঝায়। প্রতিটি মান এই নামযুক্ত কেসগুলোর ঠিক একটির সঙ্গে মেলে। অন্য ভাষায় বা প্রসঙ্গে এদের _সাম টাইপ_, _ডিসক্রিমিনেটেড ইউনিয়ন_, _ট্যাগড ইউনিয়ন_ ও _অ্যালজেব্রাইক ডেটা টাইপ_ নামে ডাকা হয়।

ডিসক্রিমিনেটেড ইউনিয়নের প্রতিটি কেসের সঙ্গে চাইলে ডেটাও যুক্ত থাকতে পারে, আর ভিন্ন ভিন্ন কেসে ভিন্ন ধরনের ডেটা থাকতে পারে। কোনো কেসের সঙ্গেই যদি ডেটা যুক্ত না থাকে, তবে ডিসক্রিমিনেটেড ইউনিয়নটি অনেকটা সেরকম কিছু হয়, যা অন্য ভাষায় সাধারণত _এনুমারেশন_ (বা _এনাম_) নামে পরিচিত।

কাস্টম টাইপ `type` কিওয়ার্ড দিয়ে ডিফাইন করা হয় এবং এতে সিনট্যাক্সের পরিমাণ খুবই কম। Elm প্রোগ্রামিংয়ের অন্যতম গুরুত্বপূর্ণ কৌশল হলো এগুলো, আর এগুলো ব্যবহার করে কোডে সম্ভব মানগুলোকে বাস্তব জীবনের বৈধ মানের সঙ্গে হুবহু মিলিয়ে দেওয়া যায়, ফলে অবৈধ ডেটার কোনো জায়গা থাকে না এবং [কোডে অসম্ভব অবস্থা প্রকাশ করাই অসম্ভব হয়ে পড়ে][impossible-states]।

```elm
-- Custom Type without associated data
type Season
    = Spring
    | Summer
    | Autumn
    | Winter

-- Custom Type with associated data
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

নির্দিষ্ট কোনো কেসের মান তৈরি করা যায় তার নাম উল্লেখ করে (`Spring`), যদি সেটি একই মডিউলে ডিফাইন করা থাকে, বা `import SeasonModule exposing (Season(..))` ধরনের সিনট্যাক্স দিয়ে ইমপোর্ট করা থাকে; অথবা `import SeasonModule exposing (Season)` ধরনের সিনট্যাক্সে ইমপোর্ট করা হলে তার পুরো কোয়ালিফায়েড নাম (`Season.Spring`) উল্লেখ করে।

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

কাস্টম টাইপে, Elm-এর বাকি সবকিছুর মতোই, _স্ট্রাকচারাল ইকুয়ালিটি_ থাকে, অর্থাৎ একই কেসের এবং একই (ঐচ্ছিক) ডেটাসমেত দুটি মান সমতুল্য।

কাস্টম টাইপ নিয়ে কাজ করার সবচেয়ে পছন্দের উপায় হলো [প্যাটার্ন ম্যাচিং][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
