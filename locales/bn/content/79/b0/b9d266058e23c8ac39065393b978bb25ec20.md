# সম্পর্কে

ডাইনামিক মেমোরি লাইব্রেরি ফাংশনের মাধ্যমে বাস্তবায়িত হয়, যা প্রোগ্রামার রানটাইমে মেমোরি অ্যালোকেট ও ডি-অ্যালোকেট করতে ব্যবহার করেন।
যেহেতু মেমোরির অ্যালোকেশনের ও ডি-অ্যালোকেশনের নিয়ন্ত্রণ প্রোগ্রামারের হাতেই, তাই প্রোগ্রামার মানুষের ভুল থেকে যতটা মুক্ত, ডাইনামিক মেমোরিও ততটাই নিরাপদ।
সেই কারণেই ডাইনামিক মেমোরি প্রোগ্রামিং bug-এর অন্যতম প্রধান উৎস এবং হ্যাকিং আক্রমণের একটি বড় লক্ষ্য।

ডাইনামিক মেমোরি এমন ভ্যারিয়েবলের জন্য ব্যবহার করা হয় যাদের সাইজ কেবল রানটাইমে জানা যায়।
এলিমেন্টের সংখ্যা এক রানটাইম থেকে পরের রানটাইমে বদলে যেতে পারে, এমন অ্যারের ক্ষেত্রে এটি সাধারণত কাজে লাগে।
ভ্যারিয়েবল লেংথ অ্যারে (VLA) হলো এমন অ্যারে সামলানোর আরেকটি উপায়, যাদের এলিমেন্টের সাইজ কেবল রানটাইমে জানা যায়।
একটি VLA অটোমেটিক স্টোরেজ ব্যবহার করে, অর্থাৎ যে ব্লকে এটিকে ডিফাইন করা হয়েছে সেটি ছেড়ে বেরিয়ে গেলেই তার মেমোরি ধ্বংস হয়ে যায়।
(স্টোরেজ সম্পর্কে আরও জানতে [storage class specifiers](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers) কনসেপ্টটি দেখুন।)
VLA-গুলো C99-এ C ভাষায় যুক্ত হয়েছিল, কিন্তু C11 থেকে VLA ঐচ্ছিক, তাই C11 ও তার পরবর্তী সংস্করণ সমর্থনকারী কম্পাইলারদের VLA সমর্থন করার বাধ্যবাধকতা নেই।
ভ্যারিয়েবল লেংথ অ্যারের বিস্তারিত বিশ্লেষণ এই লেখার পরিধির বাইরে।

## malloc

`malloc` হলো `stdlib.h`-এ ডিক্লেয়ার করা একটি ফাংশন, যা ডাইনামিক মেমোরি অ্যালোকেট করতে ব্যবহৃত হয়।
অ্যালোকেশন সফল হলে এমন একটি পয়েন্টার রিটার্ন করা হয়, যা অ্যালোকেট করা মেমোরির প্রথম বাইটের ঠিকানা নির্দেশ করে।
অ্যালোকেশন সফল না হলে `NULL` রিটার্ন করা হয়।
`malloc`-এর ফলাফল `NULL` কি না তা যাচাই করা এবং ব্যর্থ হলে সেটি সুন্দরভাবে সামলে নেওয়া বুদ্ধিমানের কাজ।
যে পয়েন্টারটি রিটার্ন করা হয় সেটি `pointer-to-void` টাইপের, যাকে মোটামুটি একটি "জেনেরিক" পয়েন্টার হিসেবে ভাবা যায়, যা মেমোরিতে ব্যবহৃত নির্দিষ্ট টাইপে রূপান্তর করা যায়।
`malloc`-এর একটি প্যারামিটার আছে, যা বাইরে হিসাবে কাঙ্ক্ষিত মেমোরির সাইজ।
প্রতিটি এলিমেন্টের ডেটা টাইপের সাইজকে এলিমেন্টের সংখ্যা দিয়ে গুণ করলে যে মান পাওয়া যায়, সেটিই একটি অ্যারে অ্যালোকেট করার মোট সাইজ।
প্রতিটি এলিমেন্টের ডেটা টাইপের সাইজ বের করতে সাধারণত `sizeof` অপারেটর ব্যবহার করা হয়।
নিচের উদাহরণটি এটি দেখায়

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

মনে রাখা জরুরি যে `malloc` দিয়ে নতুন অ্যালোকেট করা মেমোরি ইনিশিয়ালাইজ করা হয় না, বরং তাতে গার্বেজ মান থাকতে পারে।
লক্ষ করুন, `numbers` পয়েন্টারের `sizeof` অ্যারেটির এলিমেন্টের সংখ্যা নয়, অ্যালোকেট করা মোট মেমোরির পরিমাণও নয়।
`malloc` যে পয়েন্টার রিটার্ন করে তার সাইজ ওই নির্দিষ্ট সিস্টেমে যেকোনো পয়েন্টারের সাইজের সমান।
উদাহরণের কোডটি একটি ৬৪-বিট সিস্টেমে চালানো হয়েছিল, তাই পয়েন্টারটির সাইজ ছিল ৮ বাইত (প্রতি বাইটে ৮ বিট করে গুণ করলে = ৬৪ বিট)।
পয়েন্টার টাইপটি অন্তর্নিহিতভাবে pointer-to-void থেকে pointer-to-int-এ রূপান্তরিত হয়েছিল।
pointer-to-int টি একটি `int`-কে নির্দেশ করে নাকি `ints`-এর একটি অ্যারে-কে, সেটি প্রোগ্রামার তাঁর সুবিধামতো সামলাতে পারেন।
যেমন

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

পড়ার আগে মানগুলো নিশ্চিতভাবে লেখা হবে, এমন হলে মেমোরি অ্যালোকেট করার একটি কার্যকর উপায় হতে পারে `malloc`।
কিন্তু ইনিশিয়ালাইজ হওয়ার আগেই মানগুলো পড়ার সম্ভাবনা থাকলে `malloc` ব্যবহার করা ঝুঁকিপূর্ণ।
মেমোরি অ্যালোকেট করার আরও নিরাপদ উপায় হলো `calloc` ব্যবহার করা, যা নতুন অ্যালোকেট করা মেমোরিকে শূন্য দিয়ে ইনিশিয়ালাইজ করে।

উপরের উদাহরণগুলোতে লক্ষ করুন যে `free(numbers)` ব্যবহার করা হয়েছে।

## free

`free` হলো `stdlib.h`-এ ডিক্লেয়ার করা একটি ফাংশন, যা ডাইনামিকভাবে অ্যালোকেট করা মেমোরি ডি-অ্যালোকেট করতে ব্যবহৃত হয়।
ডাইনামিকভাবে অ্যালোকেট করা মেমোরি `free` দিয়ে ছাড়ার আগ পর্যন্ত মেমোরিতে দখল করা অবস্থায় থাকে।
কিছু অপারেটিং সিস্টেম প্রোগ্রাম শেষ হলে ডাইনামিকভাবে অ্যালোকেট করা মেমোরি স্বয়ংক্রিয়ভাবে ফ্রি করে দিতে পারে, তবে তার উপর নির্ভর না করাই সর্বোত্তম অভ্যাস।
`free`-এর একটি প্যারামিটার আছে, যা ডাইনামিকভাবে অ্যালোকেট করা মেমোরির একটি পয়েন্টার।
`free` ব্যবহার করা বা না করা একাধিক মেমোরি সমস্যার সঙ্গে জড়িত।

#### মেমোরি লিক

কোনো ডাইনামিকভাবে অ্যালোকেট করা মেমোরির রেফারেন্স তার লাইফটাইমের শেষে পৌঁছে যাওয়ার পর, বা অন্য কোনোভাবে ধ্বংস হয়ে যাওয়ার পর, সেই মেমোরি ফ্রি না করাকে মেমোরি লিক বলা হয়।
লিক হওয়া মেমোরি হলো এমন মেমোরি, যা সিস্টেম দখল করে রেখেছে কিন্তু প্রোগ্রাম আর সেটি অ্যাক্সেস করতে পারে না।
এটি বিশেষ সমস্যা হয়ে দাঁড়াতে পারে যদি কোনো লুপে মেমোরি অ্যালোকেট করা হয়, লুপের শেষে তা ফ্রি করা না হয়, আবার লুপের শুরুতে অ্যালোকেট করা হয়।
ফ্রি না করে যথেষ্ট পরিমাণ মেমোরি অ্যালোকেট করা হলে, অ্যালোকেট করার জন্য পর্যাপ্ত মেমোরি বাকি না থাকায় মেমোরি অ্যালোকেটের কলটি ব্যর্থ হবে।
মনে রাখা জরুরি যে ডাইনামিকভাবে অ্যালোকেট করা মেমোরি ফ্রি না হওয়া পর্যন্ত সিস্টেম দখল করে রাখলেও, যে পয়েন্টারে সেটি অ্যাসাইন করা হয়েছে তার হয়তো কেবল ব্লক স্কোপ থাকে।
যেমন, `malloc`-এর উদাহরণগুলোতে মেমোরি অ্যালোকেট করা হয় `my_function`-এ।
সেই মেমোরির পয়েন্টারটি রিটার্ন করে `main`-এর `numbers` পয়েন্টার সেট করতে ব্যবহার করা না হলে সেই মেমোরি লিক হয়ে যেত।
তাই, সেই `numbers` পয়েন্টারটি `free`-কে পাস করলে `my_function`-এ অ্যালোকেট করা মেমোরি ছাড়া হয়।

#### ফ্রি করার পর ব্যবহার (**UAF**)

মেমোরি ফ্রি হয়ে যাওয়ার পর সেটি অ্যাক্সেস করা হলে মানগুলো যেকোনো কিছু হতে পারে।
নিচের উদাহরণে `numbers` যে মেমোরিকে নির্দেশ করে সেটি ফ্রি করা হয়, তারপর `printf`-এ সেখান থেকে পড়া হয়।

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

`numbers` পয়েন্টারটি ফ্রি হওয়ার পর একটি ড্যাঙ্গলিং পয়েন্টার নামে পরিচিত হয়।
একটি ড্যাঙ্গলিং পয়েন্টার তার উদ্দিষ্ট মেমোরি ছাড়া অন্য মেমোরিকেও নির্দেশ করতে পারে।
তাই, একটি ড্যাঙ্গলিং পয়েন্টার ডেটা নষ্ট হওয়া এবং ইচ্ছেমতো কোড প্রতিস্থাপন ও এক্সিকিউশনের দিকে নিয়ে যেতে পারে।
`NULL` সেট করে পরিষ্কার করা হয়নি, এমন অ্যালোকেট করা মেমোরির পয়েন্টার দিয়ে প্রোগ্রাম হ্যাক করা যেতে পারে।
উপরের উদাহরণে, ফ্রি হওয়ার পর `numbers` যদি এভাবে `NULL` সেট করা হতো: `numbers = NULL;`, তাহলে পরের `printf`-টি প্রোগ্রাম বন্ধ করে দিত, সম্ভবত `numbers[0]` পড়তে গিয়ে segmentation fault রিপোর্ট করত।

#### ডাবল ফ্রি

ডাইনামিকভাবে অ্যালোকেট করা মেমোরির পয়েন্টারে `free` দুইবার কল করলে তা আনডিফাইন্ড বিহেভিয়ার (**UB**) ডেকে আনে।
এর মানে হলো কম্পাইলার ইচ্ছেমতো যেকোনোভাবে এটি হ্যান্ডেল করতে পারে।
নিচের উদাহরণটি দুটি ভিন্ন কম্পাইলার দিয়ে কম্পাইল করলে দুটি ভিন্ন ফলাফল আসতে পারে

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

প্রতিটি `free` কলের মাঝে `numbers` `NULL` সেট করা হলে প্রথম ও দ্বিতীয় কম্পাইলার কোনো রানটাইম এরর দেয়নি, কিন্তু তৃতীয় কোনো কম্পাইলারে তা কাজ করবে এমন নিশ্চয়তা নেই।
ডাবল ফ্রি-এর একটি কমন উৎস হলো একই ডাইনামিকভাবে অ্যালোকেট করা মেমোরির দিকে নির্দেশ করা দুটি পয়েন্টার থাকা।
একটি পয়েন্টার প্রোগ্রামের এক জায়গায় একটি অ্যারের শুরুতে নির্দেশ করতে পারে, আর অন্যটি প্রোগ্রামের অন্য জায়গায় অ্যারের ভেতরে ধাপে ধাপে এগোতে ব্যবহার করা হতে পারে।
প্রোগ্রামের ভিন্ন ভিন্ন জায়গায় প্রতিটি পয়েন্টার ফ্রি করা হয়, ফলে ডাবল ফ্রি ঘটে।

## calloc

`calloc` হলো `stdlib.h`-এ ডিক্লেয়ার করা একটি ফাংশন, যা একইসঙ্গে ডাইনামিক মেমোরি অ্যালোকেট করতে এবং নতুন অ্যালোকেট করা মেমোরিকে শূন্য দিয়ে ইনিশিয়ালাইজ করতে ব্যবহৃত হয়।
অ্যালোকেশন সফল হলে এমন একটি পয়েন্টার রিটার্ন করা হয়, যা অ্যালোকেট করা মেমোরির প্রথম বাইটের ঠিকানা নির্দেশ করে।
অ্যালোকেশন সফল না হলে `NULL` রিটার্ন করা হয়।
`calloc`-এর ফলাফল `NULL` কি না তা যাচাই করা এবং ব্যর্থ হলে সেটি সুন্দরভাবে সামলে নেওয়া বুদ্ধিমানের কাজ।
যে পয়েন্টারটি রিটার্ন করা হয় সেটি `pointer-to-void` টাইপের, যাকে মোটামুটি একটি "জেনেরিক" পয়েন্টার হিসেবে ভাবা যায়, যা মেমোরিতে ব্যবহৃত নির্দিষ্ট টাইপে রূপান্তর করা যায়।
`calloc`-এর দুটি প্যারামিটার আছে।
প্রথম প্যারামিটার নির্দিষ্ট ডেটা টাইপের কতটি অ্যালোকেট করতে হবে তা বলে দেয়।
দ্বিতীয় প্যারামিটার নির্দিষ্ট ডেটা টাইপের যে সাইজ অ্যালোকেট করতে হবে তা বলে দেয়।

নিচের উদাহরণে সব `printf` স্টেটমেন্ট সর্বদা `0` দেখানো উচিত, কারণ `calloc` নতুন অ্যালোকেট করা মানগুলো শূন্য করে দেওয়ার নিশ্চয়তা দেয়।

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` হলো `stdlib.h`-এ ডিক্লেয়ার করা একটি ফাংশন, যা বিদ্যমান অ্যালোকেট করা মেমোরি বড় বা ছোট করতে ব্যবহৃত হয়।
রি-অ্যালোকেশন সফল হলে এমন একটি পয়েন্টার রিটার্ন করা হয়, যা রি-অ্যালোকেট করা মেমোরির প্রথম বাইটের ঠিকানা নির্দেশ করে।
রি-অ্যালোকেশন সফল না হলে `NULL` রিটার্ন করা হয়।
`realloc`-এর ফলাফল `NULL` কি না তা যাচাই করা এবং ব্যর্থ হলে সেটি সুন্দরভাবে সামলে নেওয়া বুদ্ধিমানের কাজ।
`realloc`-এর দুটি প্যারামিটার আছে।
প্রথম প্যারামিটার হলো যে বিদ্যমান মেমোরিটি রি-অ্যালোকেট করতে হবে তার একটি পয়েন্টার।
দ্বিতীয় প্যারামিটার হলো রি-অ্যালোকেট করা মেমোরির বাইরে হিসাবে সাইজ।
মেমোরি বড় করার আগে যে মানগুলো সেট করা ছিল সেগুলো অটুট থাকে।
মনে রাখা জরুরি যে মেমোরি বড় করার সময় যুক্ত হওয়া মেমোরি শূন্য দিয়ে ইনিশিয়ালাইজ করা হয় না এবং তার মান যেকোনো কিছু হতে পারে।
আরও, মেমোরি ছোট করার সময় সরিয়ে ফেলা মেমোরিও ইনিশিয়ালাইজ করা হয় না এবং মান ধরে রাখতে পারে।
নিচের উদাহরণটি একটি অ্যারে বড় ও ছোট করা দেখায়

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## পাস করা সাইজ 0 হলে

`malloc`, `calloc` বা `relloac`-এ পাস করা সাইজ `0` হলে কী হবে তা নির্ভর করে কম্পাইলার এটি কীভাবে ইমপ্লিমেন্ট করে তার উপর।
কম্পাইলার হয়তো একটি `NULL` পয়েন্টার রিটার্ন করতে পারে, নয়তো একটি নন-নাল পয়েন্টার।
যেমন, `char`-এর পয়েন্টারের জন্য মেমোরি অ্যালোকেট করলে কম্পাইলার `NULL` অথবা একটি খালি স্ট্রিংয়ের দিকে নির্দেশ করা নন-নাল পয়েন্টার, দুটোর যেকোনোটি রিটার্ন করতে পারে।
ভিন্ন কম্পাইলারে ভিন্ন ফলাফল এড়াতে 0 সাইজ দিয়ে অ্যালোকেট না করাই সর্বোত্তম।
