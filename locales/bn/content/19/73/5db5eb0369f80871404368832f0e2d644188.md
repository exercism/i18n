# সম্পর্কে

সিলেবাসের এই পর্যায়ে এসে আপনি এরই মধ্যে অনেক ফাংশন ডেফিনিশন দেখে ফেলেছেন। সাধারণত REPL-এ আউটপুট নিয়ে বিশেষ কোনো মন্তব্য ছাড়াই এগুলো উপস্থাপন করা হতো:

```julia-repl
julia> f(x) = x^2
f (generic function with 1 method)
```

কেন _"১টি মেথডসহ জেনেরিক ফাংশন"_ ?

ধরুন, আমরা আর্গুমেন্টের টাইপ নিয়ে আরেকটু নির্দিষ্ট হতে চাই।

```julia-repl
julia> f(x::Integer) = x^2
f (generic function with 2 methods)

julia> f(x::Real) = x^2
f (generic function with 3 methods)
```

অথবা আমরা আর্গুমেন্টের সংখ্যা বদলে দিতে পারি:

```julia-repl
julia> f(x, y) = x * y
f (generic function with 4 methods)
```

দেখা যাচ্ছে, একই ফাংশনের নতুন ডেফিনিশনগুলোকে "মেথড" বলা হয়। পুরোনো ডেফিনিশন মুছে না দিয়ে, মেথডগুলো একটি তালিকায় যোগ করা হয়।

আমরা সহজেই মেথডগুলো তালিকাভুক্ত করতে পারি:

```julia-repl
julia> methods(f)  # output edited for brevity
# 4 methods for generic function "f" from Main:
 [1] f(x, y)
 [2] f(x::Integer)
 [3] f(x::Real)
 [4] f(x)
 ```

আমরা যদি `f` ফাংশনটি কল করি, Julia কোনোভাবে বুঝে নেয় কোন মেথড ব্যবহার করতে হবে:

```julia-repl
julia> f(2.5)  # Float64
6.25

julia> f(2)  # Int64
4

julia> f(2, 3)  # Int64, Int64
6
```

## ফাংশন আসলে কী?

[ম্যানুয়াল][function] অনুযায়ী, একটি ফাংশন হলো এমন একটি অবজেক্ট, যা আর্গুমেন্টের একটি টাপলকে একটি রিটার্ন ভ্যালুতে ম্যাপ করে। গণিতবিদেরা যে ডেফিনিশন ব্যবহার করেন, এর সাথে এটি প্রায় একই।

সাধারণত আমরা `f(2, 3)`-এর ফাংশন আর্গুমেন্টগুলোকে দুটি আলাদা জিনিস ভাবি, কিন্তু কম্পাইলার এগুলোকে একটি [টাপল][tuple] হিসেবে দেখে। একটি মাত্র আর্গুমেন্টের ক্ষেত্রেও এটি সত্য (তবে বিষয়টি স্পষ্ট করতে আমাদের একটি কমা যোগ করতে হয়):

```julia-repl
julia> typeof( (2, 3) )
Tuple{Int64, Int64}

julia> typeof( (2,) )
Tuple{Int64}
```

ফাংশনটিকে একটি ব্ল্যাক বক্স হিসেবে দেখলে বলা যায়, ভেতরে ঢোকে একটি টাপল, আর বেরিয়ে আসে একটি রিটার্ন ভ্যালু। আরও আনুষ্ঠানিকভাবে বললে, টাপলটি একটি রিটার্ন ভ্যালুতে _ম্যাপ_ করা হয়।

## ফাংশন কীভাবে ভিন্ন সংখ্যা ও টাইপের আর্গুমেন্ট সামলায়?

এটাকে সাধারণত ["পলিমরফিজম"][polymorphism] বলা হয়।

কয়েক দশক ধরে কম্পিউটার সায়েন্সে এটি একটি বড় বিষয়, আর বিভিন্ন ধরনের পদ্ধতি গ্রহণ করা হয়েছে।

Julia-র পদ্ধতিটি সাধারণ থেকে আলাদা, যদিও একেবারে অনন্য নয়।

- ফাংশন ["জেনেরিক"][generic], অর্থাৎ এদের সাথে একাধিক মেথড যুক্ত থাকতে পারে।
- মেথড যুক্ত হওয়ার আগে ফাংশন কেবল একটি নাম।
- প্রয়োজন অনুযায়ী মেথড যোগ করা যায়, প্রয়োজনে অনেকগুলোও (`+` অপারেটরটি এখন এমন একটি ফাংশন, যার ১৬১টি মেথড আছে)।
- কোনো ফাংশন কল করা হলে Julia কল সিগনেচার পরীক্ষা করে: আর্গুমেন্টের সংখ্যা এবং প্রতিটির বর্তমান টাইপ।
- কল সিগনেচারের সাথে সবচেয়ে বেশি মিলে যায় এমন মেথডটি বেছে নেওয়া হয়।
  - সাধারণভাবে, আর্গুমেন্টের সংখ্যা হুবহু মিলতে হবে (যদিও [স্প্ল্যাট/স্লার্প][splat] অপারেটর `...` আংশিকভাবে এটি এড়িয়ে যেতে পারে)।
  - কল সিগনেচারের সাথে হুবহু মিলে যায় এমন টাইপের মেথডদের অগ্রাধিকার দেওয়া হয়।
  - প্রয়োজনে Julia কল সিগনেচারের প্রতিটি আর্গুমেন্টের সুপারটাইপ দেখে সবচেয়ে বেশি মিলে যাওয়া, সবচেয়ে নির্দিষ্ট মেথডটি খুঁজে বের করে।
- বেছে নেওয়া মেথডটি প্রদত্ত আর্গুমেন্ট নিয়ে [`dispatched`][dispatch] হয় এবং একটি ফলাফল রিটার্ন করে।
- উপযুক্ত কোনো মেথড না পাওয়া গেলে একটি [`MethodError`][methoderror] উত্থাপিত হয়।

মনে রাখবেন, Julia ডাইনামিক্যালি টাইপড, তাই মেথড ডিসপ্যাচ ঘটে _রান টাইমে_।

## মাল্টিপল ডিসপ্যাচ: একটি উদাহরণ

আগের অংশে অনেক কথা ছিল, তাই চলুন সেই ভাবনাগুলো কোডে রূপান্তর করি। সহজ রাখতে নিচের ফাংশনগুলোর একটিই আর্গুমেন্ট, তবে ডজনখানেক আর্গুমেন্টওয়ালা ফাংশন পাওয়া খুব অস্বাভাবিক নয় (যেমন প্লটিং প্যাকেজ বা মেশিন লার্নিংয়ে)।

জ্যামিতিক আকৃতি বোঝাতে প্রথমে কিছু কাস্টম টাইপ ডিফাইন করুন।

```julia-repl
julia> abstract type Shape end

julia> struct Circle <: Shape
           radius::Float64
       end

julia> struct Square <: Shape
           side::Float64
       end

julia> struct Rectangle <: Shape
           length::Float64
           width::Float64
       end
```

এরপর প্রতিটি আকৃতির ক্ষেত্রফল হিসাব করার জন্য মেথড ডিফাইন করতে পারি। প্রত্যেকটি একটি করে আর্গুমেন্ট নেয়, আর প্রতিটি ক্ষেত্রেই সেটি আলাদা কনক্রিট, ব্যবহারকারী-নির্ধারিত টাইপের।

```julia-repl
julia> area(c::Circle) = π * c.radius^2
area (generic function with 1 method)

julia> area(s::Square) = s.side^2
area (generic function with 2 methods)

julia> area(r::Rectangle) = r.length * r.width
area (generic function with 3 methods)
```

এখন আমরা কিছু আকৃতি তৈরি করে ক্ষেত্রফল হিসাব করতে পারি, প্রতিটির জন্য সঠিক সূত্র বেছে নেওয়ার ভার Julia-র ডিসপ্যাচ মেকানিজমের উপর ছেড়ে দিয়ে।

```julia-repl
julia> circle = Circle(2.3)
Circle(2.3)

julia> area(circle)  # call signature Tuple{Circle}
16.619025137490002

julia> square = Square(1.6)
Square(1.6)

julia> area(square)  # call signature Tuple{Square}
2.5600000000000005

julia> rectangle = Rectangle(1.4, 2.1)
Rectangle(1.4, 2.1)

julia> area(rectangle)  # call signature Tuple{Rectangle}
2.94
```

## [প্যারামেট্রিক মেথড][parametric]

মেথড সিগনেচার প্যারামেট্রিক টাইপের মতোই মোটামুটি একইভাবে ডামি টাইপ মান নিতে পারে।

সিনট্যাক্সটি আলাদা ধরনের, এতে একটি `where` ক্লজ লাগে:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T} = true
same_type (generic function with 1 method)

julia> same_type([1, 2], 3)
true

julia> same_type([1, 2], "three")
ERROR: MethodError: no method matching same_type(::Vector{Int64}, ::String)
```

উপরের উদাহরণে দুটি আর্গুমেন্টকেই একই টাইপ `T` ব্যবহার করতে হয়, সেটি যা-ই হোক না কেন।

`T`-এর উপর একটি বাধা বসিয়ে আমরা আরও নির্দিষ্ট হতে পারি:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T<:Number} = true
same_type (generic function with 2 methods)
```

এই মেথডে কেবল একই রকম সংখ্যাসূচক টাইপই `true` রিটার্ন করে।

একাধিক ডামি ভ্যারিয়েবলও সম্ভব, `where` ক্লজে কমা দিয়ে আলাদা করা। নিচের দুটি মেথড দেখতে প্রায় একই রকম:

```julia-repl
julia> func(v::Vector{Number}, x::Number) = true
func (generic function with 1 method)

julia> func(v::Vector{S}, x::T) where {S<:Number, T<:Number} = true
func (generic function with 2 methods)
```

একটি পার্থক্য হলো, দ্বিতীয় মেথডের ফাংশন বডির ভেতরে `S` ও `T` টাইপ মান ব্যবহার করা যায়। এ ধরনের কৌশল হয়তো আপনি প্রায়ই ব্যবহার করেন না, তবে কিছু পরিস্থিতিতে এটি অনেক ঝামেলা বাঁচাতে পারে।

উদাহরণস্বরূপ, নিচের প্যারামেট্রিক টাইপ ডেফিনিশনে ফিল্ডগুলোর টাইপ একই হতে হবে, `T`, যেটি `Real`-এর সাবটাইপ হতে বাধ্য করা হয়েছে:
```julia
struct Point{T<:Real}
    x::T
    y::T
end
```
এই `Point` ডেফিনিশনটি একই টাইপের `x` ও `y` গ্রহণ করে, অথবা ভিন্ন টাইপের `x` ও `y`-ও নিতে পারে, তবে সেক্ষেত্রে একটি স্পষ্ট কনভার্সন টাইপ দিতে হবে।
```julia-repl
julia> Point(4, 5)
 Point{Int64}(4, 5)

julia> Point(3.5, 2)
 MethodError: no method matching Point(::Float64, ::Int64)    # Output truncated for brevity

julia> Point{Float32}(3.5, 2)
 Point{Float32}(3.5f0, 2.0f0)

julia> Point{Int64}(3.5, 2) 
 InexactError: Int64(3.5)      # Output truncated for brevity
```
টাইপের উপর এতটা নিয়ন্ত্রণ কখনো কাঙ্ক্ষিত হতে পারে, আবার একটু অ্যাবস্ট্রাকশনও কাজে লাগতে পারে।
```julia
Point(x::T, y::S) where {T<:Real, S<:Real} = Point{promote_type(T,  S)}(x, y)
```
এই আউটার কনস্ট্রাক্টর সেটিই দেয়: এটি `Point`-কে `x` ও `y`-এর জন্য ভিন্ন ধরনের টাইপ নেওয়ার সুযোগ দেয়, কনভার্সন টাইপ স্পষ্টভাবে না জানিয়েই। মূল ডেফিনিশনের জন্য স্পষ্ট কনভার্সন টাইপ দিতে ফাংশন বডিতে `promote_type(T, S)`-এ `T` ও `S` টাইপ মান ব্যবহৃত হয়।
```julia-repl
julia> Point(3.5, 2)
 Point{Float64}(3.5, 2.0)
```

## অন্য ভাষার সাথে তুলনা

মেথড বাছাই করার সময় Julia সব আর্গুমেন্ট পরীক্ষা করে, তাই এটাকে [`multiple dispatch`][multiple-dispatch] বলা হয়।

অল্প কিছু অন্য ভাষা মাল্টিপল ডিসপ্যাচ সমর্থন করে, যেমন Common Lisp, তবে Julia-র মতো ভাষার ডিজাইনে এটি খুব একটা কেন্দ্রীয় ভূমিকা রাখে না।

এর বিপরীতে, অবজেক্ট-ওরিয়েন্টেড (OO) ভাষায় (যেমন Ruby) মেথড সাধারণত একটি [ইনস্ট্যান্স][instance]-এর উপর কল করা হয়। তখন ডেফিনিশনে প্রথম আর্গুমেন্টটিই বিশেষ গুরুত্ব পায় (ডেফিনিশনে `self` বা `this`-এর মতো নাম থাকে), আর কল করার সময় ইনস্ট্যান্সের পরে ডট দিয়ে মেথডের নাম লেখা হয়:

```ruby
irb(main):004:0> "abc".sub("b", "*")
=> "a*c"
```

এটাকে [`single dispatch`][single-dispatch] বলা হয়, কারণ মেথড বাছাই করতে কেবল ইনস্ট্যান্সের ক্লাসটিই (উপরের উদাহরণে স্ট্রিং "abc"-এর) ব্যবহার করা হয়।

কিছু স্ট্যাটিক্যালি-টাইপড OO ভাষা মেথড পলিমরফিজম সমর্থন করে, যা মাল্টিপল ডিসপ্যাচের সাথে কিছুটা মিলে যায়। বড় পার্থক্য হলো, সেখানে মেথড বাছাই ঘটে কেবল _কম্পাইল_ টাইমে।

ফাংশনাল ভাষায় সাধারণত একটিই ফাংশন ডেফিনিশন থাকে, আর বিভিন্ন সম্ভাবনা সামলাতে কিছু একটা Select/Case/Match এক্সপ্রেশন। আপনি নিজের লজিক নিজেই লেখেন, সাধারণত সংক্ষিপ্ত প্যাটার্ন-ম্যাচিং সিনট্যাক্সের সাহায্যে, যা Julia-তে নেই। অবশ্যই Julia-ও এক ধরনের প্যাটার্ন-ম্যাচিং করে, তবে ফাংশন বডির ভেতরে নয়, ডিসপ্যাচের সময়।

## উপসংহার

Julia-তে মাল্টিপল ডিসপ্যাচ অত্যন্ত নমনীয় এবং খুবই পারফরম্যান্ট, তাই এটি ব্যাপকভাবে ব্যবহৃত হয়।

`+`-এর ১৬১টি মেথডের উদাহরণ যেভাবে ইঙ্গিত দেয়, Julia প্রোগ্রামাররা চেষ্টা করেন খুব নির্দিষ্টভাবে টাইপ উল্লেখ করে মেথড ডিফাইন করতে। বাইটকোডের স্তরে দুটি ইন্টিজার যোগ করা আর দুটি ফ্লোট যোগ করা পুরো আলাদা ব্যাপার, আর একটি ফ্লোটের সাথে একটি ইন্টিজার যোগ করলে টাইপ প্রোমোশনের বাড়তি জটিলতা যোগ হয়।

টাইপ যত নির্দিষ্ট, কম্পাইলার তত বেশি অপটিমাইজেশন করতে পারে: Exercism-এর ছোটখাটো একটি খেলনা-অনুশীলনীতে এর গুরুত্ব সামান্য, কিন্তু Julia যে বড় সংখ্যাসূচক সিমুলেশনগুলোর জন্য তৈরি, সেখানে পারফরম্যান্সের জন্য এটি জরুরি।

_আপনি যদি জানেন একটি মেথড কী ইনপুট পাবে, তাহলে দয়া করে কম্পাইলারকে জানান!_
