# পরিচিতি

## নাল-রেফারেন্স

আপনি যদি আগে কখনও অন্য কোনো প্রোগ্রামিং ভাষা (C/C++, Python, Java, Ruby, Lisp ইত্যাদি) ব্যবহার করে থাকেন, তাহলে সম্ভবত আগেই `null` বা `nil`-এর সাথে আপনার পরিচয় হয়েছে। কোনো নির্দিষ্ট ভ্যারিয়েবলের কোনো মান নেই বোঝাতে এই ভাষাগুলো `null` বা `nil` ব্যবহার করে। কিন্তু এর ফলে ভুলে `null` ভ্যারিয়েবল ব্যবহার করা সহজ (এবং ঘন ঘন ঘটে যাওয়া) একটি ভুল হয়ে দাঁড়ায়। আপনি নিশ্চয়ই অনুমান করতে পারছেন, যে ফাংশনটি নেই সেটি কল করার চেষ্টা করা, বা যে মানটি নেই সেটি অ্যাক্সেস করার চেষ্টা করা নানা রকম bug ও ক্র্যাশের কারণ হতে পারে। `null`-এর স্রষ্টা তো এটিকে তাঁর ['billion-dollar mistake'][billion-dollar-mistake] নামে ডেকেছেন।

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## `Option` টাইপ

এই সমস্যাগুলো এড়াতে Cairo-র ভ্যারিয়েবলগুলো একটি মানের অনুপস্থিতিকে নিরাপদভাবে প্রকাশ করতে `Option` এনাম ব্যবহার করতে পারে। এই এনামের দুটি ভ্যারিয়েন্ট আছে: `None`, যা Cairo-তে null-এর সমতুল্য; এবং `Some(T)`, যেখানে `T` যেকোনো টাইপের একটি মান।

এটি দেখতে এরকম:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

`Option`-কে আপনি আপনার আর নাল-রেফারেন্সের কারণে সৃষ্ট সমস্যাগুলোর মাঝে নিরাপত্তার একটি স্তর হিসেবে ভাবতে পারেন, যা একই সাথে নাল-রেফারেন্সের ধারণাগত উপযোগিতা ধরে রাখে।

## `Option` ব্যবহার করা

একটি ভ্যারিয়েবলকে `None`-এ সেট করা বেশ সহজ:

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

তবে, আপনি যদি চান `Option` টাইপ কোনো একটি মান বহন করুক, তাহলে সেই মানটি সরাসরি অ্যাসাইন করতে পারবেন না। একটি `Option` টাইপের ভ্যারিয়েবল আর ধরা যাক একটি `i32` টাইপের ভ্যারিয়েবল এক নয়। আপনাকে `Some` ব্যবহার করতে হবে:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

একই কারণে নিচের কোডটিও কাজ করবে না:

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

`Some`-এ থাকা মানটি পেতে হলে প্রথমে যাচাই করতে হবে যে এটি আছে কি না:

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

`Option`-এর ভেতরে থাকা মান যাচাই ও অ্যাক্সেস করার জন্য `match` ছাড়াও Cairo-র আরও কিছু টুল আছে, তবে `match` এখন আপনার কাছে পরিচিত হওয়ার কথা।

Cairo কেন নাল-রেফারেন্সের বদলে `Option` ব্যবহার করে, তার একটি প্রদর্শনী হিসেবে এটিকে দেখুন। মূল কথা হলো, `Option` ভ্যারিয়েবলটি `Some` (সেক্ষেত্রে আপনি এগিয়ে গিয়ে ভেতরে থাকা মানটি বের করে ব্যবহার করতে পারেন) নাকি `None`, তা **আপনাকে _অবশ্যই_ যাচাই করতে হবে**। অন্যথায় আপনার প্রোগ্রাম কম্পাইল হবে না; কম্পাইলার আপনাকে `null` থেকে নিরাপদ রাখে।
