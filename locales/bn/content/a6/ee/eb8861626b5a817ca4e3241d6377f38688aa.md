# সম্পর্কে

Ruby একটি ডাইনামিক ও স্ট্রংলি টাইপড ভাষা।
ডাইনামিক ভাষায় একটি ভ্যারিয়েবল বা অবজেক্টের টাইপ রানটাইমে নির্ধারিত হয়, অর্থাৎ এর মান বা টাইপ একেবারে শেষ মুহূর্ত পর্যন্ত (যখন ইন্টারপ্রেটার এটি পার্স করে) পরিবর্তন করা যায়।
আর স্ট্রংলি টাইপড বলতে আমরা কী বুঝি?
একবার আমরা একটি ভ্যারিয়েবল বা অবজেক্টের টাইপ জেনে গেলে, সেটি দিয়ে আপনি কী করতে পারবেন তা নিয়ে Ruby কঠোর থাকে, যেমন:

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**কিন্তু**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

মনে রাখবেন, Ruby-তে সবকিছুই অবজেক্ট।
এমনকি ক্লাসগুলোও `Class` ক্লাসের ইনস্ট্যান্স।

যেমন:

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

এর মানে হলো আমরা এভাবেও ক্লাস ডিফাইন করতে পারি:

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

সবশেষে মনে রাখবেন, `Integer` অবজেক্ট এমন মান ধারণ করে যা এক বা একাধিক (পরপর) অঙ্ক হিসেবে লেখা যায়, আর এর মেথডগুলো অনেক [গাণিতিক অপারেটর][integers-docs] সমর্থন করে।

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
ডকুমেন্টেশনে প্রায়ই ইনস্ট্যান্স মেথড বোঝাতে `Class#method_name`-এর মতো সিনট্যাক্স ব্যবহার করা হয়, আর ক্লাস বা মডিউল স্তরের মেথড বোঝানো হয় `Class::method_name` দিয়ে।
`::`-কে বলা হয় _স্কোপ রেজোলিউশন অপারেটর_, যা দিয়ে ক্লাস বা মডিউল স্তরের কনস্ট্যান্ট বা মেথড নির্দেশ করা হয়।
Ruby ডকুমেন্টেশনে, মেইলিং লিস্টে এবং সহায়তার অন্যান্য জায়গায় আপনি এটি দেখতে পাবেন।
আমাদের লেখায় অবশ্য আমরা এর বদলে ক্লাস ও মডিউল মেথড বোঝাতে `ClassName.method_name` বা `ModuleName.method_name` ব্যবহার করি।
~~~~
