# মৌলিক বিষয়

একটি Sather প্রোগ্রাম তৈরি হয় **ক্লাস** দিয়ে, আর প্রতিটি ক্লাসের ভেতরে থাকে **রুটিন**।

```sather
class GREETER is

   hello : STR is
      return "Hello!";
   end;

end; -- class GREETER
```

## ক্লাস

ক্লাসের নাম লেখা হয় বড় হাতের অক্ষরে, শব্দের মাঝে আন্ডারস্কোর দিয়ে: `GREETER`, `STAGE_DIRECTIONS`। ফাইলের নাম সাধারণত এর সাথে মেলে, ছোট হাতের অক্ষরে: `stage_directions.sa`।

প্রতিটি রুটিন থাকে একটি ক্লাসের ভেতরে। ক্লাসের বাইরে কোনো কোড থাকে না।

## রুটিন

যে রুটিন কোনো উত্তর দেয়, সেটি কোলনের পরে উত্তরটির ধরন ঘোষণা করে:

```sather
   hello : STR is
      return "Hello!";
   end;
```

`STR` হলো টেক্সটের টাইপ। যে রুটিন কোনো আর্গুমেন্ট নেয় না, সেটি লেখা হয় আর কল করা হয় বন্ধনী ছাড়াই।

একটি রুটিন আর্গুমেন্ট নিতে পারে, যেগুলো নামের পরে বন্ধনীর ভেতরে লেখা হয়:

```sather
   louder(word : STR) : STR is
      return word;
   end;
```

`return` উত্তর ফিরিয়ে দেয় আর সঙ্গে সঙ্গে রুটিন থামিয়ে দেয়, তাই এর নিচের যেকোনো লাইন বাদ পড়ে যায়।

## কল করা

ক্লাসের বাইরে থেকে লিখুন ক্লাসের নাম, তারপর `::`, তারপর রুটিন:

```sather
GREETER::hello
```

একই ক্লাসের ভেতরে থেকে ক্লাসের নাম বাদ দেওয়া যায়। একটি রুটিনকে দিয়ে আরেকটি রুটিন ব্যবহার করানোর স্বাভাবিক উপায় এটাই:

```sather
   greeting_again : STR is
      return hello;
   end;
```

## কমেন্ট

দুটি ড্যাশ দিয়ে এমন একটি কমেন্ট শুরু হয়, যা লাইনের শেষ পর্যন্ত চলে।

```sather
   -- Explain why, not what: the code already says what.
   hello : STR is
      return "Hello!";   -- a trailing comment is fine too
   end;
```

প্রথা অনুযায়ী ক্লাসের শেষে থাকে তার নাম লেখা একটি কমেন্ট। রুটিন, লুপ আর ক্লাস সবই `end;` দিয়ে শেষ হয়, তাই কমেন্টটি জানিয়ে দেয় এই `end;` কোনটির:

```sather
end; -- class GREETER
```

## সেমিকোলন

স্টেটমেন্ট শেষ হয় সেমিকোলন দিয়ে। রুটিনের শেষ স্টেটমেন্টের পরে সেমিকোলনটি না দিলেও চলে, তবে প্রতিবারই এটি লিখলে চিন্তার একটি বিষয় কমে যায়।
