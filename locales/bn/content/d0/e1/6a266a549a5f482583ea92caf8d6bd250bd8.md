# পরিচিতি

একটি **লুপ** হলো ইনস্ট্রাকশনের এমন একটি ক্রম, যা সম্ভাব্য একাধিকবার চালানো হয়, যতক্ষণ না শেষ হওয়ার একটি শর্ত পূরণ হয়।

x86-64-এ সাধারণত আগের একটি লেবেলে জাম্প করে লুপ তৈরি করা হয়:

```x86asm
example_loop:
    ...
    jmp example_loop
```

মনে রাখবেন, আগের কোনো লেবেলে শর্তহীন জাম্প দিলে এক্সিকিউশন সবসময়ই ওই লেবেলে চলে যায়।
এর মানে, পুনরাবৃত্ত হওয়া ক্রমটির বাইরে অন্য কোনো জাম্প না থাকলে লুপটি অনন্তকাল ধরে পুনরাবৃত্তি হতে থাকবে।

যেমন, এই লুপটি শেষ হয় না:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

আর শর্ত পূরণের উপর নির্ভর করে এই লুপটি শেষ হতে পারে:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## কাউন্টিং লুপ

একটি কাউন্টিং লুপ প্রায় সবসময়ই একইভাবে শেষ হয়: একটি ইনস্ট্রাকশন যা কোনো কাউন্টার আপডেট করে বা দুটি মান তুলনা করে, আর তার ঠিক পরেই থাকে একটি শর্তসাপেক্ষ জাম্প, যা ঠিক করে আবার একবার ঘুরবে কি না।

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
উপরের কোডে `cmp rsi, 0`-এর দরকার নেই, কারণ `sub rsi, 1` ফলাফল `0` হলেই `zero flag (ZF)` সেট করে দেয়।

অ্যাসেম্বলিতে শর্ত যাচাইয়ের মূল উপায় যদিও `cmp`, তবুও অনেক ইনস্ট্রাকশন ফ্ল্যাগ আপডেট করে।
যেমন, অনেক ইন্টিজার অ্যারিথমেটিক বা বিটওয়াইজ ইনস্ট্রাকশন ফলাফল `0` হলে `ZF` আপডেট করে, আর ফলাফল ঋণাত্মক হলে (অর্থাৎ, সবচেয়ে উঁচু বিটটি সেট থাকলে) `SF` আপডেট করে।

কোন কোন ইনস্ট্রাকশন কোন ফ্ল্যাগকে প্রভাবিত করে, তা দেখতে আপনি একটি [রেফারেন্স][reference] দেখে নিতে পারেন।

[reference]: https://www.felixcloutier.com/x86/
~~~~

মনে রাখবেন, উপরের উদাহরণে `rsi`-কে `0`-এর চেয়ে বড় ধরে নেওয়া হয়েছে।
যদি এটি `0` হতো, তাহলে `sub rsi, 1` `rsi`-কে কমিয়ে `-1` করে ফেলত, যা আসলে একটি বিশাল আনসাইনড সংখ্যা।
লুপটি অবশেষে শেষ হওয়ার আগে আরও `18,446,744,073,709,551,615` বার ইটারেশন লাগত।
আর যেহেতু অ্যারের দৈর্ঘ্য `0`, তাই যেকোনো মেমোরি অ্যাক্সেসই আউট-অব-বাউন্ডস হয়ে যেত।

যদি অ্যারের দৈর্ঘ্য নিয়ে কোনো নিশ্চয়তা না থাকে, তাহলে কমন দুটি পদ্ধতি আছে।

প্রথমটি হলো শেষ হওয়ার শর্তটি লুপের শুরুতে নিয়ে আসা, আর শেষে একটি শর্তহীন জাম্প রাখা:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

দ্বিতীয়টি হলো লুপ শুরু হওয়ার আগে শূন্য দৈর্ঘ্যের অ্যারের জন্য একবার পরীক্ষা করে নেওয়া:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

এই দ্বিতীয় পদ্ধতিটি সাধারণত প্রথমটির চেয়ে বেশি কার্যকর, কারণ লুপ বডিতে ব্রাঞ্চের সংখ্যা কম।
এ বিষয়ে আপনি ভবিষ্যতের একটি ধারণায় আরও জানতে পারবেন।

~~~~exercism/advanced
কিছু ক্ষেত্রে আধুনিক CPU দুটি ভিন্ন ইনস্ট্রাকশনকে একটিমাত্র অপারেশনে একত্রিত করতে পারে।
এই অপ্টিমাইজেশনটিকে বলা হয় **ম্যাক্রোফিউশন**।

`sub` আর `add`-এর মতো অনেক অ্যারিথমেটিক ইনস্ট্রাকশন, সঙ্গে `cmp` আর `test`, সাধারণত ঠিক পরে থাকা শর্তসাপেক্ষ জাম্পের সঙ্গে ফিউজ হয়ে যায়।
এর মানে, `cmp rax, rdx`-এর মতো একটি ইনস্ট্রাকশন, যার ঠিক পরেই একটি শর্তসাপেক্ষ জাম্প থাকে, CPU সাধারণত সেটিকে একটি একক অপারেশন হিসেবেই দেখতে পারে।

ম্যাক্রোফিউশন CPU-এর উপর নির্ভর করে, আর কোন ইনস্ট্রাকশন কোন শর্তসাপেক্ষ জাম্পের সঙ্গে ফিউজ হয়, তা নিয়ে কিছুটা ভিন্নতাও আছে।

একটি কাজের রেফারেন্স হলো [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]।
[Intel optimization reference manual][intel-opt]-এর 3.4.2.2 নম্বর অনুচ্ছেদে (Optimizing for Macrofusion) Intel CPU-গুলোর জন্য ফিউজযোগ্য জোড়ার তালিকাও রয়েছে।
