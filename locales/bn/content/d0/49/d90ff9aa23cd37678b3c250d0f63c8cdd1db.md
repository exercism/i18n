# পরিচিতি

প্রোগ্রামাররা সাধারণত নিখুঁত সফটওয়্যার লেখার চেষ্টা করেন, আর সাধারণত ব্যর্থ হন।

অনেক সময়ই অপ্রত্যাশিতভাবে কিছু ভুল হয়ে যায়, আর সেগুলো মোকাবিলা করার ক্ষমতা আমাদের থাকা চাই।

কিছু প্রোগ্রামিং ভাষার ডিজাইনার মনে করেন, অগ্রাধিকার হলো যত দ্রুত সম্ভব একটি এরর ধরা, তারপর ডিবাগিং সহজ করতে একটি তথ্যবহুল বার্তা দিয়ে এক্সিকিউশন শেষ করে দেওয়া।

ডেটা সায়েন্সের প্রোগ্রামিং ভাষাগুলো অবশ্য আরও সূক্ষ্ম একটি পথ নেয়।
কিছু এরর এতটাই গুরুতর যে সঙ্গে সঙ্গে প্রোগ্রাম বন্ধ করা ছাড়া উপায় নেই, কিন্তু অনেক সময়ই কোনো সমস্যাকে পরে সামলানোর জন্য চিহ্নিত করে রেখে এক্সিকিউশন চালিয়ে যাওয়াই ভালো।

নথিংনেস কনসেপ্টে আমরা দেখেছি, ঝামেলার মানের জন্য Julia নানা ধরনের প্লেসহোল্ডার দেয়: [`missing`][nothing], [`NaN`][NaN] এবং `Inf`.
কোনো নির্দিষ্ট পরিস্থিতিতে প্রোগ্রাম বন্ধ করে দেওয়ার চেয়ে এগুলো ভালো পথ কি না, সেটা প্রোগ্রামারের বিচারবিবেচনার ব্যাপার।

বিস্তারিত ঢোকার আগে _নামকরণ নিয়ে একটা কথা_: Julia-র ডকুমেন্টেশনে "error" আর "exception" শব্দ দুটিকে মোটামুটি বিনিময়যোগ্য ধরেই দেখা হয়।
নিচের লেখাও ঠিক একই রকম অসামঞ্জস্যপূর্ণ হতে পারে।

## স্ট্যান্ডার্ড এরর টাইপ

পাঠ্যক্রমের এই পর্যায়ে এসে আপনি নিশ্চয়ই Julia-র অনেক এরর বার্তা দেখেছেন।
যেমন:

```julia-repl
julia> Int(3.14)
ERROR: InexactError: Int64(3.14)
```

একটি ফ্লোটকে ইন্টিজারে কাস্ট করতে গেলে প্রিসিশন কিছুটা হারায়, তাই আমরা `InexactError` পাই।

`InexactError` একটি টাইপ, Julia-তে স্ট্যান্ডার্ড হিসেবে বিল্ট-ইন থাকা কয়েকটি টাইপের একটি ([বর্তমানে ২৫টি][errors])।
এগুলো সবই `Exception`-এর সাবটাইপ:

```julia-repl
julia> supertype(InexactError)
Exception
```

## `throw()`

স্ট্যান্ডার্ড এরর টাইপগুলোর কিছু কিছু আপনার নিজের কোডে তৈরি করার কাজে লাগতে পারে।

সব কনক্রিট টাইপের মতো এররগুলোরও কনস্ট্রাক্টর থাকে।
এগুলো নানা রকম আর্গুমেন্ট নেয়, তাই যে টাইপটি ব্যবহার করতে চান তার জন্য [ডকুমেন্টেশন][errors] দেখে নিন।

```julia-repl
julia> DomainError(42, "out of range")
DomainError(42, "out of range")
```

এররটি ব্যবহার করতে কনস্ট্রাক্টরটিকে একটি [`throw()`][throw] ফাংশনের ভেতরে মুড়ে দিন:

```julia-repl
julia> throw(DomainError(42, "out of range"))
ERROR: DomainError with 42:
out of range
```

## `error()`

এলোপাতাড়ি হলেও দ্রুত একটি সমাধান চাইলে [`error()`][error] ফাংশনটি কাজে লাগতে পারে।
এটি আর্গুমেন্ট হিসেবে একটি স্ট্রিং (বা একটি স্ট্রিংয়ের উপাদানগুলো) নেয়:

```julia-repl
julia> happy = false;
julia> happy || error("😞 something went wrong")
ERROR: 😞 something went wrong
```

## কাস্টম এরর

নতুন এরর টাইপ তৈরি করা নীতিগতভাবে খুবই সহজ।
শুধু `Exception`-এর আরেকটি সাবটাইপ যোগ করলেই হয়:

```julia-repl
julia> struct MyError <: Exception end

julia> throw(MyError)
ERROR: MyError
```

তবে উপরের উদাহরণে কোনো ফিল্ড নেই আর কনস্ট্রাক্টরও কোনো আর্গুমেন্ট নেয় না, তাই এরর বার্তার উপর আমাদের কোনো নিয়ন্ত্রণ থাকে না।
আমরা একটি মেসেজ ফিল্ড যোগ করতে পারি:

```julia-repl
julia> struct AnotherError <: Exception
           msg::String
       end

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError("Wrong!")
```

শুধু কনস্ট্রাক্টরটি প্রিন্ট করে দিলেই এখনো ঠিকঠাক হয় না।
আগের উদাহরণটির সাথে মিলিয়ে দেখুন, যেখানে আমরা একটি `DomainError` থ্রো করেছিলাম।

বিল্ট-ইন এররগুলোর মতোই যাতে একটি কাস্টম এরর সামলানো হয়, সেজন্য আমাদের একটি [`showerror()`][showerror] মেথড যোগ করতে হয়:

```julia-repl
julia> Base.showerror(io::IO, e::AnotherError) =
           print(io, "AnotherError: ", e.msg)

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError: Wrong!
```

বেশ অপ্রতুলভাবে ডকুমেন্ট করা এই ফিচারটি মূলত আমাদের কাস্টম এরর টাইপকে Julia-র স্ট্যান্ডার্ড এরর-হ্যান্ডলিং সিস্টেমের সাথে যুক্ত করে দেয়।

## অ্যাসারশন

অ্যাসারশনের মূল ধারণা হলো, "এই বিবৃতিটি সত্য হওয়া উচিত, তাই মিথ্যা হলে জোর গলায় জানান।"
এর মূল উপকারিতা ডিবাগিংয়ের সময়, কারণ প্রোডাকশন কোডে অ্যাসারশন কখনো ব্যর্থ হওয়া উচিত নয়।

টাইপ কনসেপ্টে আমরা দেখেছি, আমরা টাইপ অ্যাসারশন যোগ করতে পারি, যেমন কোনো ফাংশনের রিটার্ন টাইপ যাচাই করতে।

```julia-repl
julia> 42::Number
42

julia> "two"::Number
ERROR: TypeError: in typeassert, expected Number, got a value of type String
```

আরও সাধারণভাবে, [`@assert`][assert] ম্যাক্রো আমাদের যেকোনো এক্সপ্রেশন পরীক্ষা করতে দেয়, যার ফলাফল একটি বুলিয়ান মান হয়:

```julia-repl
julia> n = 22;
julia> @assert isodd(n) "n must be odd"
ERROR: AssertionError: n must be odd
```

## `try`...`catch`

কিছু এরর অনিবার্যভাবে মারাত্মক, কিন্তু অনেক সময়ই আমরা আশা করি প্রোগ্রামটি সুন্দরভাবে সামলে উঠবে।

ডিফল্টভাবে একটি এরর সঙ্গে সঙ্গে বর্তমান ফাংশনটি শেষ করে দেয়, আর এররটি (সঙ্গে তথ্যবহুল বার্তা থাকলে তা-ও) যে ফাংশন থেকে কলটি এসেছে তার কাছে চলে যায়।

কল স্ট্যাক বেয়ে এভাবে উপর পর্যন্ত চলতে থাকে, যতক্ষণ না টপ-লেভেল কোড একটি এরর বার্তা দিয়ে শেষ হয়।

যেকোনো ধাপেই [`try...catch`][try-catch] ব্লক দিয়ে এররটি ধরে ফেলা যায়, যে ব্লকটি সেটি সামলানোর চেষ্টা করে।

```julia-repl
julia> n = -1;
julia> try
           log_n = log(n)
       catch problem
           if problem isa DomainError # number out of range
               # See next section for more on @warn and @info
               @warn "you may have supplied a negative real number: $n"
               @info "trying with complex argument"
               log_n = log(Complex(n))  # fallback calculation

           elseif problem isa MethodError # no idea what n is
               @error "please supply a valid argument"
 
           else
              rethrow() # the error could be anything else
           end
      end
┌ Warning: you may have supplied a negative real number: -1
└ @ Main REPL[3]:5
[ Info: trying with complex argument
0.0 + 3.141592653589793im  # success
```

উপরের উদাহরণে `log(n)`-এর জন্য `n`-কে হয় ধনাত্মক একটি বাস্তব মান হতে হবে, নয়তো যেকোনো জটিল মান।
`try ... catch` ঋণাত্মক বাস্তব মানের সমস্যাগুলো ধরে ফেলে এবং গাণিতিক প্রতীকে সঠিক জটিল উত্তর `iπ` ফিরিয়ে দেয়।

যদি আপনি উদাহরণস্বরূপ একটি স্ট্রিং আর্গুমেন্ট দেন, তবে ব্যবহারকারীকে সেটি ঠিক করতে বলার ছাড়া আর কোনো উপায় থাকে না।

শেষ ভরসা হিসেবে, `DomainError` বা `MethodError` — দুটোর কোনোটিই নয় এমন যেকোনো কিছুর জন্য আমরা [`rethrow()`][rethrow] যোগ করেছি।

আরও কিছু ঐচ্ছিক ক্লজ আছে:

- [`else`][else], যা চলে যদি `try` ক্লজটি সফল হয়;
- [`finally`][finally], যা বাইরের রিসোর্স পরিষ্কার করার কাজে ব্যবহার করা যায়, `try` সফল হোক বা ব্যর্থ: ফাইল বন্ধ করা, ডেটাবেজ কানেকশন ছেড়ে দেওয়া...

***নোট:*** কখনো কখনো `try...catch`-ই আপনার দরকার, তবে অনুগ্রহ করে এটি বেশি ব্যবহার করা এড়িয়ে চলুন।
এর বদলে `if...else` ব্লক ব্যবহার করা গেলে, সেটি এক্সেপশন ধরে সামলানোর চেয়ে অনেক বেশি পারফরম্যান্ট হবে।

## লগিং

মনে রাখবেন, উপরে আলোচনা করা `error()` ফাংশনটিকে [`@error`][error_macro] ম্যাক্রোর সাথে গুলিয়ে ফেলা উচিত নয়।

ফাংশনটি একটি এক্সেপশন তৈরি করে, যেটি ধরা না পড়লে কল স্ট্যাক বেয়ে উপরে চলে যায়।

`@error` ম্যাক্রোটি, তার [`@debug`][debug_macro], [`@info`][info_macro] আর [`@warn`][warn_macro] সহযোগীদের সাথে, [`Logging`][logging] মডিউলের অংশ, আর এর উদ্দেশ্য হলো প্রোগ্রামের প্রবাহ না বদলে তথ্যবহুল বার্তা তৈরি করা।

আউটপুট ডিফল্টভাবে টার্মিনালে যায় (গুরুত্ব অনুযায়ী রঙে আলাদা করা), যদিও বাস্তব অ্যাপ্লিকেশনে আরও অনেক সম্ভাবনা থাকে।

```julia-repl
julia> @warn "Something looks not quite right"
┌ Warning: Something looks not quite right
└ @ Main REPL[55]:1

julia> @error "Panic!"
┌ Error: Panic!
└ @ Main REPL[56]:1
```

`try...catch` অংশের আগের উদাহরণটিও দেখুন।
