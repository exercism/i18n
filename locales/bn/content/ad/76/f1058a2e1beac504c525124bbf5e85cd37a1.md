# ভূমিকা

অ্যাসেম্বলিতে যেকোনো ডেটাই বাইটের একটি ক্রম।
এর মানে হলো, যেকোনো ডেটাকেই তার অন্তর্নিহিত ওই বাইটগুলোর একটি **অ্যারে** হিসেবে দেখা যায়।

## অ্যারের এলিমেন্ট অ্যাক্সেস করা

মেমোরিতে যেকোনো মান অ্যাক্সেস করতে হলে তার **ইফেক্টিভ অ্যাড্রেস** হিসাব করা প্রয়োজন।
একটি ইফেক্টিভ অ্যাড্রেস হলো একটি এক্সপ্রেশন, যা নিচের জিনিসগুলো দিয়ে গঠিত হতে পারে:

- একটি _বেস অ্যাড্রেস_, যেমন ধরুন, একটি ভ্যারিয়েবলের লেবেল যে অ্যাড্রেস বোঝায় সেটি।
- একটি _ইনডেক্স রেজিস্টার_, যা সম্ভবত `1`, `2`, `4` বা `8` দিয়ে স্কেল করা।
- একটি সাইনড ৩২-বিট _ডিসপ্লেসমেন্ট_, যা বেস অ্যাড্রেসের সাথে যোগ করা (বা তা থেকে বিয়োগ করা) একটি সংখ্যা।

মনে রাখবেন, এই অ্যাড্রেসটি _০-ইনডেক্সড_, তাই কোনো অফসেট ছাড়া একটি বেস অ্যাড্রেস একটি ভ্যারিয়েবলের প্রথম বাইট নির্দেশ করে।
এই কারণেই আগের কনসেপ্টগুলোতে যেমনটি করা হয়েছে, সেভাবে কোনো অফসেট ছাড়া শুধু একটি লেবেল ব্যবহার করে মেমোরি ডিরেফারেন্স করলে যে মান পাওয়া যায়, তা তার প্রথম বাইট থেকেই শুরু হয়:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 হলো [লিটল এন্ডিয়ান][endianness]।
এর মানে হলো, একটি মাল্টিবাইট মানের লিস্ট সিগনিফিকেন্ট বাইটটি সবচেয়ে ছোট মেমোরি অ্যাড্রেসে সংরক্ষিত থাকে।

ফলে, একটি মাল্টিবাইট মানের আলাদা আলাদা বাইট অ্যাক্সেস করার সময় আরও সিগনিফিকেন্ট বাইটে পৌঁছাতে বেস অ্যাড্রেসের সাথে একটি ধনাত্মক অফসেট যোগ করা প্রয়োজন হয়।

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

মানের একটি তালিকা দিয়ে ঘোষণা করা একটি ইনিশিয়ালাইজড ভ্যারিয়েবল হলো ওই মানগুলোর একটি অ্যারে, যেখানে প্রতিটি এলিমেন্টের আকার নির্দিষ্ট করা থাকে।
তবে অফসেট সবসময় **_বাইটের_** হিসাবেই হয়ে থাকে, এমনকি অ্যারের প্রতিটি এলিমেন্টের আকার আরও বড় হলেও:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

মনে রাখবেন, যেহেতু অ্যাড্রেস বাইটের হিসাবেই হয়, তাই অ্যারের যেকোনো এলিমেন্টের একটি আলাদা বাইট সরাসরি অ্যাক্সেস করা সম্ভব:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

একই কারণে, একটি মাত্র ইনস্ট্রাকশনে একটি এলিমেন্টের আকারের চেয়ে বেশি অ্যাক্সেস করা সম্ভব:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
অ্যাসেম্বলি অ্যারে অ্যাক্সেসের ক্ষেত্রে কোনো বাউন্ডস চেকিং করে না।
অ্যারের শেষের বাইরের কোনো ইনডেক্স অ্যারের বাইরের মেমোরি পড়ে বা লেখে।
এর ফলে নীরবে ভুল ফলাফল আসতে পারে, অন্য ডেটা নষ্ট হতে পারে, আর অ্যাক্সেস করা মেমোরি ম্যাপ করা না থাকলে রানটাইম ফল্টও ঘটতে পারে।
প্রতিটি ইফেক্টিভ অ্যাড্রেস অ্যারের ভেতরে রাখার দায়িত্ব প্রোগ্রামারের।
~~~~

## ইনিশিয়ালাইজড অ্যারের আকার হিসাব করা

NASM (The Netwide Assembler, অর্থাৎ এই ট্র্যাকের অ্যাসেম্বলার) একটি বিশেষ প্রতীক (`$`) ধারণ করে, যা মেমোরিতে বর্তমান অবস্থান নির্দেশ করে।
এই প্রতীকটি একটি অ্যারে মেমোরিতে যে মোট জায়গা দখল করে তার আকার হিসাব করার একটি সুবিধাজনক উপায় দেয়:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

`example`-এর ঠিক পরে ব্যবহার করা হলে `$` অ্যারের শেষের মেমোরি অ্যাড্রেস ধারণ করে।
এর মানে হলো, `$ - example` হলো ওই অ্যাড্রেস আর `example` লেবেল যে অ্যাড্রেস নির্দেশ করে তার পার্থক্য।
এটাই হলো `example` যে অ্যারের দিকে নির্দেশ করে, সেই অ্যারের দখল করা মোট আকার, বাইটে।

তাই এই মান দিয়ে `example_length` ডিফাইন করে আমরা একটি ৮-বাইটের ভ্যারিয়েবল তৈরি করেছি, যা অ্যারের আকার বা দৈর্ঘ্য বাইটে সংরক্ষণ করে।

## Section .bss

আনইনিশিয়ালাইজড ডেটা **section .bss**-এ ঘোষণা করা হয়।
বেশিরভাগ প্ল্যাটফর্মে প্রোগ্রাম শুরুর সময় OS এই ডেটা শূন্য দিয়ে পূর্ণ করে।

NASM-এ একটি আনইনিশিয়ালাইজড ভ্যারিয়েবলের থাকে একটি নাম, ডেটার আকার নির্দেশ করে এমন একটি ডিরেক্টিভ এবং সংরক্ষণ করার জন্য এলিমেন্টের সংখ্যা।
এগুলোর প্রতিটি একটি স্পেস দিয়ে অন্যটি থেকে আলাদা করা থাকে।

মূল ডিরেক্টিভগুলো এবং সেগুলোর সাথে সম্পর্কিত ডেটার আকার নিচের মতো:

| ডিরেক্টিভ | আকার    |
| :-------: | :------ |
|   resb    | ১ বাইট  |
|   resw    | ২ বাইট |
|   resd    | ৪ বাইট |
|   resq    | ৮ বাইট |

যেমন, এটি `example` নামের একটি ভ্যারিয়েবলে `3` বাইটের জন্য আনইনিশিয়ালাইজড জায়গা সংরক্ষণ করে:

```x86asm
section .bss
    example resb 3
```

আর এটি `arr` নামের একটি ভ্যারিয়েবলে `10` গুণ `8` বাইটের (অর্থাৎ `80` বাইট) আনইনিশিয়ালাইজড জায়গা সংরক্ষণ করে:

```x86asm
section .bss
    arr resq 10
```

`section .bss`-এর ভ্যারিয়েবলগুলো মিউটেবল, অর্থাৎ এগুলো থেকে পড়া যায় এবং এগুলোতে লেখা যায়।

আনইনিশিয়ালাইজড ডেটা ইনিশিয়ালাইজড ডেটার মতোই অ্যাক্সেস করা যায়, অর্থাৎ এর ইফেক্টিভ অ্যাড্রেস ব্যবহার করে।
একইভাবে, এগুলোরও স্ট্যাটিক স্টোরেজ ডিউরেশন থাকে এবং একই সোর্স ফাইলের যেকোনো ফাংশন থেকে অ্যাক্সেস করা যায় (আর `global` হিসেবে ঘোষণা করা থাকলে অন্য সোর্স ফাইল থেকেও)।

## lea ইনস্ট্রাকশন দিয়ে অ্যারের অ্যাড্রেস অ্যাক্সেস করা

আগের একটি কনসেপ্টে দেখা গেছে, `lea` ইনস্ট্রাকশন একটি ইফেক্টিভ মেমোরি অ্যাড্রেস হিসাব করে।
একই সেমান্টিকস মেনে এটি অ্যারের যেকোনো এলিমেন্টের অ্যাড্রেস হিসাব করতে ব্যবহার করা যায়।

মনে রাখবেন, রিলেটিভ অ্যাড্রেসিং-এ আরও জটিল কোনো অ্যাড্রেস তৈরি করার আগে অনেক সময় ভ্যারিয়েবলের অ্যাড্রেস একটি রেজিস্টারে লোড করা প্রয়োজন হয়:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea`-এর একটি সুবিধা হলো, এটি ওই অ্যাড্রেসের মেমোরি সত্যিকারভাবে অ্যাক্সেস না করেই অ্যাড্রেস-ক্যালকুলেশনের অ্যারিথমেটিক ব্যবহার করে একটি মান হিসাব করতে পারে।
এই কারণে, কোনো রেজিস্টারে মেমোরি অ্যাড্রেস না থাকলেও অ্যারিথমেটিক হিসাব করার জন্য এটি কাজে লাগে:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
