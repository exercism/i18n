# পরিচিতি

## লুপ

একটি **লুপ** হলো ইনস্ট্রাকশনের এমন একটি ক্রম, যা শেষ হওয়ার একটি শর্ত পূরণ না হওয়া পর্যন্ত সম্ভাব্যভাবে একাধিকবার চালানো হয়।

x86-64-এ সাধারণত আগের একটি লেবেলে জাম্প করে লুপ তৈরি করা হয়:

```x86asm
example_loop:
    ...
    jmp example_loop
```

খেয়াল করুন, আগের কোনো লেবেলে নিঃশর্ত জাম্প সবসময়ই এক্সিকিউশনকে সেই লেবেলে নিয়ে যায়। এর মানে, পুনরাবৃত্তি করা ক্রমটির বাইরে অন্য কোনো জাম্প না থাকলে লুপটি অনন্তকাল ধরে চলতেই থাকবে।

যেমন, এই লুপটি কখনো শেষ হয় না:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

আর এই লুপটি শর্ত পূরণ হওয়ার উপর নির্ভর করে শেষ হতে পারে:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### গণনাকারী লুপ

একটি গণনাকারী লুপ প্রায় সবসময়ই একইভাবে শেষ হয়: একটি ইনস্ট্রাকশন যা কোনো কাউন্টার হালনাগাদ করে বা দুটি মান তুলনা করে, আর তার ঠিক পরেই একটি শর্তসাপেক্ষ জাম্প যা ঠিক করে আবার ঘুরবে কি না।

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
উপরের কোডে `cmp rsi, 0` দরকার নেই, কারণ `sub rsi, 1` ফলাফল `0` হলে আগেই `zero flag (ZF)` সেট করে দেয়।

যদিও অ্যাসেম্বলিতে শর্ত পরীক্ষা করার মূল উপায় `cmp`, অনেক ইনস্ট্রাকশনই ফ্ল্যাগ হালনাগাদ করে।
যেমন, অনেক ইন্টিজার গাণিতিক বা বিটওয়াইজ ইনস্ট্রাকশন ফলাফল `0` হলে `ZF` এবং ফলাফল ঋণাত্মক হলে (অর্থাৎ সর্বোচ্চ বিট সেট থাকলে) `SF` হালনাগাদ করে।

কোন ইনস্ট্রাকশন কোন ফ্ল্যাগে প্রভাব ফেলে তা দেখতে আপনি একটি [রেফারেন্স][reference] দেখতে পারেন।

[reference]: https://www.felixcloutier.com/x86/
~~~~

খেয়াল করুন, উপরের উদাহরণে ধরে নেওয়া হয়েছে `rsi` `0`-এর চেয়ে বড়। যদি এটি `0` হতো, তাহলে `sub rsi, 1` `rsi`-কে কমিয়ে `-1` করত, যা একটি অত্যন্ত বড় আনসাইনড সংখ্যা। লুপটি শেষ হতে আরও `18,446,744,073,709,551,615` বার ইটারেশন লাগত। এছাড়া অ্যারেটির দৈর্ঘ্য `0` হওয়ায় যেকোনো মেমরি অ্যাক্সেসই সীমার বাইরে চলে যেত।

কোনো অ্যারের দৈর্ঘ্য সম্পর্কে কোনো নিশ্চয়তা না থাকলে দুটি কমন পদ্ধতি আছে।

প্রথমটি হলো লুপটি শেষ হওয়ার শর্ত শুরুতে নিয়ে আসা, আর শেষে একটি নিঃশর্ত জাম্প রাখা:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

দ্বিতীয়টি হলো লুপ শুরু হওয়ার আগে একবার পরীক্ষা করে নেওয়া যে অ্যারেটি শূন্য দৈর্ঘ্যের কি না:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

এই দ্বিতীয় পদ্ধতিটি সাধারণত প্রথমটির চেয়ে বেশি কার্যকর, কারণ লুপ বডিতে কম ব্রাঞ্চ থাকে।
এ বিষয়ে আপনি ভবিষ্যতের একটি কনসেপ্টে আরও জানতে পারবেন।

~~~~exercism/advanced
কিছু কিছু ক্ষেত্রে আধুনিক CPU দুটি ভিন্ন ইনস্ট্রাকশনকে একটি একক অপারেশনে একত্রিত করতে পারে।
এই অপ্টিমাইজেশনকে বলা হয় **ম্যাক্রোফিউশন**।

`sub` ও `add`-এর মতো অনেক গাণিতিক ইনস্ট্রাকশন, আর সঙ্গে `cmp` ও `test`-ও, সাধারণত ঠিক পরে আসা একটি শর্তসাপেক্ষ জাম্পের সঙ্গে ফিউজ হয়ে যায়।
এর মানে হলো, `cmp rax, rdx`-এর মতো একটি ইনস্ট্রাকশন যার ঠিক পরেই একটি শর্তসাপেক্ষ জাম্প থাকে, CPU সাধারণত সেটিকে একটি একক অপারেশন হিসেবে গণ্য করতে পারে।

ম্যাক্রোফিউশন CPU-এর উপর নির্ভর করে, আর কোন ইনস্ট্রাকশন কোন শর্তসাপেক্ষ জাম্পের সঙ্গে ফিউজ হয় তা নিয়ে কিছু ভিন্নতাও আছে।

সহায়ক একটি রেফারেন্স হলো [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]।
[Intel optimization reference manual][intel-opt]-এর বিভাগ 3.4.2.2 (Optimizing for Macrofusion)-এ Intel CPU-এর জন্য কোন কোন জোড়া ফিউজ করা যায় তার তালিকাও আছে।

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
