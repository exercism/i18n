# ভূমিকা

## এনামারেশন

এখন পর্যন্ত আমরা বেশিরভাগ ক্ষেত্রে সংখ্যা এবং স্ট্রিং নিয়ে কাজ করেছি।
বাস্তব জগৎকে মডেল করার জন্য আমরা চাইতে পারি একটি ভ্যারিয়েবল যেন সীমিত সংখ্যক মান নিতে পারে।
আপনি হয়তো একটি ডেডিকেটেড টাইপ চাইতে পারেন, যার কয়েকটি আলাদা আলাদা নামের আলাদা আলাদা মান থাকবে।
উদাহরণস্বরূপ, একটি স্কেটবোর্ড কারখানায় ডেকের উপাদান শুধু maple, bamboo বা plastic-এর মধ্যে একটি হতে পারে।

আপনি সেই মানগুলো এনকোড করতে ইন্টিজার ব্যবহার করতে পারেন, কিন্তু উপাদানের জন্য সিস্টেম থেকে কোনো অবৈধ মান আসছে কি না, তা যাচাই করতে অতিরিক্ত কোড লিখতে হবে।
সেই [_ম্যাজিক নাম্বার_][magic numbers]-এর মানে সোর্স কোড জুড়ে খুঁজে বের করা কষ্টকর, আর সেগুলো গুলিয়ে ফেলার সম্ভাবনাও বেশি।
`enumerations` ব্যবহার করে এক্সপ্রেসিভ কোড উৎসাহিত করা যায় এবং অনিচ্ছাকৃত তুলনার ভুল সীমিত করা যায়।

## ব্যবহারের উদাহরণ

এই ধরনের এনামারেশনের নির্দিষ্ট পরিভাষা হলো `scoped enumeration`.
নিচের স্নিপেটটি দেখায় কীভাবে একটি `DeckMaterial` `enumeration` লিখতে হয়।
ডেফিনিশনের শেষে `enum class` কিওয়ার্ড এবং `;` লক্ষ্য করুন:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
এখন, স্কেটের দোকানের একটি দাম নির্ধারণের ফাংশন দেখুন এবং লক্ষ্য করুন কীভাবে স্কোপ রেজোলিউশন অপারেটর (`::`) `enumeration` থেকে একটি `enumerator` নির্দিষ্ট করছে:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## স্কোপিং

কল্পনা করুন আপনার চাকার উপাদানের জন্য একটি দ্বিতীয় `enumeration` আছে:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
যদিও চাকা এবং ডেক দুটোই _প্লাস্টিক_ দিয়ে তৈরি হতে পারে, তবুও দুটোকে গুলিয়ে ফেলা যাবে না।
এগুলো আলাদা _টাইপ_: `DeckMaterial` plastic এবং `WheelMaterial` plastic.
প্রতিটি `enumeration`-এর `enumerators` নিজের স্কোপে থাকবে, নিজের `namespace`-এ।
এজন্যই এগুলোকে `scoped enumerations` বলা হয়।

## আনস্কোপড এনামারেশন
আপনি হয়তো ভাবছেন যে `scoped` নামটি থাকলে `unscoped` এনামারেশনও থাকবে, এবং আপনি ঠিকই ভাবছেন।
`Unscoped enumerations` কম জনপ্রিয় হয়ে উঠছে, কারণ তারা সবাই একই গ্লোবাল নেমস্পেস ভাগ করে নেয়।
এই ভাগাভাগির কারণে, উপরের উদাহরণে _plastic_-এর মতো একই `enumerators` দিয়ে দুটি `unscoped enumerations` রাখা সম্ভব হতো না।

এছাড়াও, `unscoped enumerations` অন্তর্নিহিতভাবে ইন্টিজারে রূপান্তরিত হয়।
একটি চমকপ্রদ ফলাফলের জন্য নিচের উদাহরণটি দেখুন:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

যদি আপনি `scoped enumerations`-কে ইন্টিজারে রূপান্তর করতে চান, তাহলে `static_cast<int>` ব্যবহার করতে পারেন।
