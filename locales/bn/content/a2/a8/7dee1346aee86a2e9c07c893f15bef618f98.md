# সম্পর্কে

## const

[`const`][constants] মডিফায়ারটি এমন যেকোনো ফিল্ডে প্রয়োগ করা যায় (এবং সাধারণত করা উচিত) যার মান কম্পাইল টাইমেই জানা থাকে এবং প্রোগ্রামের জীবনকালে বদলায় না।

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

কোন এক্সপ্রেশনগুলো কম্পাইল টাইমে হিসাব করা যায়, কম্পাইলারই সেটি আপনাকে দেখিয়ে দেবে। সাধারণ গাণিতিক অপারেশন যেমন অনুমোদিত, স্ট্রিং জোড়া লাগানোও তেমন। এর বাইরে পড়ে যায় এমন সব হিসাব, যার জন্য হিপ বা স্ট্যাক ব্যবহার করা লাগে; তাই সব মেথড কল এবং নন-প্রিমিটিভ টাইপের রেফারেন্স এখানে পাওয়া যায় না।

ভ্যারিয়েবলের তুলনায় `const`-এর পারফরম্যান্স সুবিধা নিয়ে ওয়েবে কিছু আলোচনা আছে। ইনস্ট্যান্স-ভিত্তিক নন-`const` ফিল্ডের সাথে তুলনা করলে মেমরিতে চোখে পড়ার মতো সাশ্রয় হতে পারে, কিন্তু স্ট্যাটিক ভ্যারিয়েবলের তুলনায় তা একেবারেই নগণ্য। আর CPU পারফরম্যান্স নিয়ে ভাবনাকে আপনার সহকর্মীরা [অকালীন অপটিমাইজেশন][premature-optimization] হিসেবেই দেখার সম্ভাবনা বেশি।

`const` ব্যবহারের আরও জোরালো কারণ হলো, এটি কোড নিয়ে যুক্তি করার জন্য মেইনটেইনারের ক্ষমতা বাড়ায়। কোনো ফিল্ড `const` বা `readonly` হিসেবে চিহ্নিত, কিংবা কোনো প্রপার্টির কোনো সেটার নেই, এটি এক ঝলক দেখেই মেইনটেইনার সেটিকে নিজের বিশ্লেষণ থেকে অনেকটা বাদ দিয়ে দিতে পারেন। বাগের উৎস হওয়ার সম্ভাবনা এখানে কম। রিফ্যাক্টরিং করার সময় এটি সমস্যা তৈরি করার সম্ভাবনাও কম। এই বিষয়ে আলোচনা করা হয়েছে [Stack Overflow-এর এই মন্তব্যে][so-consts]।

মেথডের ভেতরের মানেও `const` মডিফায়ার প্রয়োগ করা যায়:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

এভাবে `const` দিয়ে একটি মান চিহ্নিত করা উপকারী, যদি মেথডে সেটি একাধিকবার ব্যবহৃত হয় বা আপনি এর অর্থের দিকে মনোযোগ আকর্ষণ করতে চান। সরাসরি কোডে লিটারাল ব্যবহারের তুলনায় এতে পারফরম্যান্সের কোনো লাভ নেই।

## readonly

[`readonly`][readonly-fields] মডিফায়ারটি এমন যেকোনো ফিল্ডে প্রয়োগ করা যায় (এবং সাধারণত করা উচিত) যাকে `const` করা যায় না, যার মান প্রোগ্রামের জীবনকালে বদলায় না, এবং যা একটি ইনলাইন ইনিশিয়ালাইজার দিয়ে অথবা ইনস্ট্যানশিয়েশনের সময় (কনস্ট্রাক্টর দিয়ে বা কনস্ট্রাক্টর থেকে ডাকা কোনো মেথড দিয়ে) সেট করা হয়।

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

`const`-এর ক্ষেত্রে যে কারণগুলো খাটে, সেগুলোর জন্যই `readonly` মডিফায়ার ব্যবহারে উৎসাহ দেওয়া হয়। এভাবে ফিল্ডকে সীমাবদ্ধ রাখার অভ্যাস মেইনটেইনারদের কোড নিয়ে যুক্তি করতে সাহায্য করে।

মনে রাখবেন, কোনো ফিল্ডে `readonly` মডিফায়ার যোগ করলে কেবল ফিল্ডটির মান পরিবর্তন হওয়াই আটকায়। অ্যাগ্রিগেট টাইপের ক্ষেত্রে এটি ওই টাইপের ফিল্ড বা প্রপার্টি রক্ষা করে না। বিশেষ করে, এটি অ্যারের ভেতরের বিষয়বস্তু রক্ষা করে না।

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

একটি রেফারেন্স টাইপের সব মেম্বার যাতে সুরক্ষিত থাকে সেটি নিশ্চিত করতে ফিল্ডগুলো `readonly` করা যায় এবং `set` অ্যাকসেসর ছাড়াই অটোমেটিক প্রপার্টি ডিফাইন করা যায়।

Base Class Library-তে [রিড-অনলি কালেকশন][readonly-collections] দেখে নিতে পারেন।

অ্যারের ক্ষেত্রে রিড-অনলি সংস্করণের সবচেয়ে কাছাকাছি যা পাওয়া যায়, তা হলো [`Array.AsReadOnly<T>()`][as-read-only] মেথড।
