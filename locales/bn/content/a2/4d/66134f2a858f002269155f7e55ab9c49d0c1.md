# পরিচিতি

পার্সিং হলো টেক্সটকে অর্থবহ ডেটায় রূপান্তর করার প্রক্রিয়া।
এই কাজে `String` প্যাকেজের ফাংশনগুলো সীমিত আর রেগুলার এক্সপ্রেশন ব্যবহার করা কঠিন, তাই Elm-এ পার্সিং করার ইডিওম্যাটিক উপায় হলো `elm/parser` প্যাকেজ ব্যবহার করা।

চলুন প্রোগ্রামিং ভাষা [LOLCODE][lolcode]-এর (একটি উপসেটের) জন্য একটি পার্সার লেখার একটি উদাহরণ দেখি।
চলুন নিচের কমেন্ট করা প্রোগ্রামটি দেখি:

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

প্রথমে সম্ভাব্য কমান্ডগুলো প্রকাশ করার জন্য একটি Elm টাইপ লিখি:

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

তাহলে আমাদের LOLCODE প্রোগ্রামকে একটি `List Command` হিসেবে মডেল করা যায়।
চলুন `HAI 1` লাইনের জন্য একটি পার্সার দিয়ে শুরু করি:

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP` তৈরি করা হয়েছে একটি _পার্সার পাইপলাইন_ দিয়ে।
`(|.)` অপারেটরের অর্থ "স্ট্রিংটি পার্স করুন কিন্তু ফলাফলটি ফেলে দিন" আর `(|=)`-এর অর্থ "স্ট্রিংটি পার্স করুন এবং ফলাফলটি রেখে দিন"।
এই উদাহরণে `Parser.keyword "HAI"` একটি "HAI" গ্রহণ করবে, কিন্তু সেই ফলাফলটি উপেক্ষা করা হয়।
`Parser.spaces` যেকোনো সংখ্যক ' ', '\n', আর '\r' ক্যারেক্টার গ্রহণ করবে, কিন্তু সেটিও উপেক্ষা করা হবে।
`Parser.int` একটি ইন্টিজার পার্স করবে, এবং সেই ইন্টিজারের মানটি (ধরা যাক 1) একেবারে উপরের `Parser.succeed Version`-এ পাঠানো হবে এবং পার্সারটি `Version 1` মানটি রিটার্ন করে সফল হবে।

পাইপলাইনের কোনো একটি পার্সার ব্যর্থ হলে সেটি একটি `Parser.DeadEnd` রিটার্ন করবে এবং পুরো পার্সারটি ব্যর্থ হবে।
`Parser.run` দিয়ে একটি পার্সার রান করা যায়:

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

চলুন "CAN HAS STDIO?" লাইনটি এভাবে সামলাই

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP`-ও একটি পার্সার পাইপলাইন, তবে এবার এটি `Parser.symbol` দিয়ে শেষ হয়, যা "?"-এর মতো সিম্বল পার্স করার জন্য উপযুক্ত।
আমরা যে মানটি রাখতে চাই (ইমপোর্ট করার প্যাকেজের নাম) সেটি পার্স করা হয় এই দিয়ে

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

যেহেতু আমরা জানি না প্যাকেজের নাম কী হবে, তাই আমরা `Parser.keyword` ব্যবহার করতে পারি না; এর বদলে `Parser.chompWhile` ব্যবহার করি, যা একটি শর্ত পূরণ হওয়া পর্যন্ত (এখানে, অ্যালফানিউমেরিক ক্যারেক্টার হওয়া) একটি একটি করে ক্যারেক্টার গ্রহণ করে।
এরপর এই গ্রহণ করা ক্যারেক্টারগুলো `Parser.getChompedString` দিয়ে সংগ্রহ করা হয়, যা একটি `Parser String` রিটার্ন করে।
এই ক্ষেত্রে আমরা প্যাকেজের নামগুলো নরমালাইজ করতে চাই, তাই পার্সারের ভেতরে থাকা স্ট্রিংটি পরিবর্তন করে ছোট হাতের অক্ষরে করার জন্য `Parser.map` ব্যবহার করি।

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

এরপর, `VISIBLE "HAI WORLD!"` পার্স করা হয় এই দিয়ে

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

এখন আমাদের প্রতিটি কমান্ডের জন্য একটি পার্সার আছে।
অবশ্যই, সাধারণ একটি প্রোগ্রামে এই কমান্ডগুলোর ক্রম আগে থেকে বলা যায় না, তাই আমরা একটি জেনেরিক কমান্ড পার্সার বানাই

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf` প্রদত্ত ক্রম অনুযায়ী একটি একটি করে পার্সার চেষ্টা করে।
একটি পার্সার ব্যর্থ হলে পরেরটি চেষ্টা করা হয়, কিন্তু সফল হলে বাকি পার্সারগুলো চেষ্টা না করেই তার ফলাফল রিটার্ন করা হয়।
সবগুলো পার্সার ব্যর্থ হলে `Parser.oneOf`-ও ব্যর্থ হয়।

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

লক্ষ্য করুন, প্রতিটি ব্যর্থ প্রচেষ্টা একটি `Parser.DeadEnd` তৈরি করে, যা `Parser.oneOf` সংগ্রহ করে।

একটি সম্পূর্ণ প্রোগ্রাম পার্স করতে আমাদের একাধিক কমান্ড একের পর এক পার্স করতে হয় এই দিয়ে

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence` অনেক অপশনসহ খুবই কাস্টমাইজযোগ্য একটি পার্সার।
`start`, `separator` আর `end` স্ট্রিং নেয় যেগুলো সিকোয়েন্সের আইটেমগুলোকে আলাদা করে; Elm লিস্ট পার্স করতে আমরা "[", "," আর "]" ব্যবহার করতাম।
`spaces` নমনীয়তা দেয় এমন একটি পার্সার নিয়ে, যা আইটেম আর সেপারেটরের মাঝে সম্ভাব্য স্পেস সামলায়; Elm লিস্ট পার্স করতে আমরা `Parser.spaces` ব্যবহার করতাম, কিন্তু এই ক্ষেত্রে আমরা কোনো স্পেস গ্রহণ করি না, তাই `Parser.succeed ()` ব্যবহার করি, যা আসলে কিছুই গ্রহণ না করেই সঙ্গে সঙ্গে সফল হয়।
`item` আইটেম পার্সারটি নেয়, আর সবশেষে `trailing` দিয়ে আমরা ঠিক করি পেছনে থাকা সেপারেটর `Parser.Forbidden`, `Parser.Mandatory` নাকি `Parser.Optional` হবে।

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

পার্সারগুলো সফল হলে তারা স্ট্রিংটি গ্রহণ করা বন্ধ করে দেয়

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

তাই স্ট্রিংয়ের সবকিছু পার্স করা হয়েছে বলে নিশ্চিত হতে চাইলে আমরা `Parser.end` ব্যবহার করতে পারি

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

সবশেষে, কখনও কখনও পার্স করা কনটেন্টের ওপর নির্ভর করে একটি পার্সারকে ব্যর্থ করার সিদ্ধান্ত নিতে হয়।
উদাহরণস্বরূপ, পরপর দুটি "HAI" কমান্ড দিয়ে শুরু হওয়া প্রোগ্রাম ব্যর্থ করার মতো একটি পার্সার দরকার হলে আমরা ব্যবহার করতে পারতাম

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen` একটি পার্সারের কনটেন্ট পরীক্ষা করতে পারে এবং তার মান অনুযায়ী একটি নতুন পার্সার রিটার্ন করে।
এখানে এক ক্ষেত্রে আমরা `Parser.problem` দিয়ে একটি কাস্টম মেসেজসহ পার্সারটি ব্যর্থ করেছি, আর অন্য ক্ষেত্রে মূল মানটি রিটার্ন করেছি।

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
