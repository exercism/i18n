# Részletesen

A Swift beépített típusai számos problémát okoznak, amikor olyasmit szeretnénk modellezni, aminek mérsékelt számú lehetséges állapota vagy értéke van, mint például a 63 hivatalos HTTP-állapotkód vagy a NES-vezérlő 8 gombja.

Például megpróbálhatjuk a meglévő típusokat, például a stringeket vagy az inteket használni az értékeik ábrázolására, hasonlóan ahhoz, ahogy a HTTP-állapotkódokkal történt, de ez több különböző problémához vezet. Az egyik probléma, hogy bár a számítógép gond nélkül feldolgozza az olyan érvényes értékeket, mint a 103, a 226 és az 505, magának a programnak is folyamatosan ellenőriznie kell, hogy nem kap-e érvénytelen értékeket, például 213-at, 427-et, 512-t vagy 601-et. Ugyanakkor a _programozó_ felelőssége, hogy amikor egy kódot megvizsgál, hogy cselekedjen, minden érvényes értéket ellenőrizzen, így egyetlen érvényes kód se maradjon ki.

Egy másik probléma, hogy elveszik a szemantikai jelentés. Egy programot olvasó (vagy író) ember nehezen tudja felidézni, hogy a 103, a 226 és az 505 érték a „Early Hints”, az „IM Used” és a „HTTP Version Not Supported” jelentést hordozza. Hasonlóképpen modellezhetnénk egy kapcsolót `Bool` típussal, mivel mindkettőnek csak két állapota van, de mit jelent a kapcsoló számára a `true`: azt, hogy a kapcsoló nyitva van, vagy azt, hogy zárva?

Ezt enyhíthetjük, ha stringgel ábrázoljuk az állapotkód vagy a kapcsoló állapotának szöveges változatát, de ez hibákhoz vezethet, amikor egy beérkező állapotkódot a „HTTP Version not Supoorted” szöveghez próbálunk hasonlítani a várt „HTTP Version not Supported” helyett. Az ilyen hibák gyakoriak, és nehéz rájuk bukkanni.

A probléma megoldására a Swift, mint sok modern nyelv, kínál egy nyelvi megoldást, amelyet [_felsorolásnak_][enumerations] vagy röviden _enumnak_ nevez.

A felsorolások a Swiftben olyan mechanizmust jelentenek, amellyel új típusokat hozunk létre; ezeket véges számú elnevezett érték alkotja, amelyek további kapcsolódó információt hordozhatnak, és amelyek használatát a fordító fordítási időben ellenőrizni tudja teljesség és helyesség szempontjából. Ráadásul a felsorolásokhoz tulajdonságok és metódusok is tartozhatnak, amelyek a felsorolás aktuális értéke alapján nyújtanak további információt és funkcionalitást.

## Felsorolások definiálása

A legalapvetőbb felsorolásokat a Swiftben az `enum` kulcsszóval definiáljuk, amelyet a típus neve, majd a kapcsos zárójelek közé zárt törzs követ, benne a felsorolás értékeinek listájával, amelyeket a `case` kulcsszó vezet be. A [Swift stílusútmutatót][api-design-guidelines] követve a típus nevét UpperCamelCase formában, az értékekét pedig lowerCamelCase formában érdemes írni.

```swift
enum NESButton {
  case up
  case down
  case left
  case right
  case a
  case b
  case select
  case start
}
```

A rövidség kedvéért több eset egyetlen sorba is írható, vesszővel elválasztva, egyetlen `case` kulcsszóval.

```swift
enum NESButton {
  case up, down, left, right, a, b, select, start
}
```

Ez egy új, `NESButton` nevű típust definiál, amelynek lehetséges értékei `up`, `down`, `left`, `right`, `a`, `b`, `select` és `start`. Ezekre az értékekre úgy hivatkozhatunk, hogy a típus nevét egy pont (`.`) és az érték követi. Ha a típusnév kikövetkeztethető, csak a pontra és az értékre van szükség. Az értékek ezután úgy használhatók, mint bármely más érték a Swiftben.

```swift
var lastPressed = NESButton.up

// Now that the type of lastPressed is set as NESButton
lastPressed = .down

let konamiCode = [NESButton.up, .up, .down, .down, .left, .right, .left, .right, .b, .a]
```

Figyeld meg, hogy mivel egy tömb minden elemének azonos típusúnak kell lennie, csak az egyik elemnél kell megadnunk a típusnevet, a többinél elég csupán az érték. Egyiknél sem lenne szükség a típusnévre, ha a konstans megkapná a megfelelő típusannotációt, például: `let konamiCode: [NESButton] = …`.

## Felsorolások és `switch` utasítások

A felsorolásokat gyakran használjuk [`switch` utasításokkal][enums-and-switches] együtt, amelyekkel a felsorolás értéke alapján dönthetjük el, milyen műveletet hajtsunk végre.

```swift
lastPressed = .left
switch lastPressed {
case .up: print("You pressed the UP button")
case .down: print("You pressed the DOWN button")
case .left: print("You pressed the LEFT button")
case .right: print("You pressed the RIGHT button")
case .a: print("You pressed the A button")
case .b: print("You pressed the B button")
case .select: print("You pressed the SELECT button")
case .start: print("You pressed the START button")
}

// prints "You pressed the LEFT button"
```

Mivel a `switch` utasításoknak ki kell merítőeknek lenniük, a fordító figyelmeztet, ha nem szerepel bennük minden eset.

```swift
switch lastPressed {
case .up, .down, .left, .right:
  print("You pressed a direction button.")
}
// Error: Switch must be exhaustive
```

Ez különösen akkor hasznos, ha egy program fejlődése során új esetek kerülnek a felsorolásba. A fordító minden olyan helyre rámutat, ahol a nem kimerítő `switch` utasításokat frissíteni kell az új esettel.

Megjegyezzük, hogy a fenti hiba kijavítható egy `default` eset használatával a `switch` utasításban.

```swift
lastPressed = .select
switch lastPressed {
case .up, .down, .left, .right:
  print("You pressed a direction button.")
default:
  print("You pressed a non-direction button.")
}
// prints: "You pressed a non-directional button."
```

Ez azonban automatikusan kimerítővé tesz minden `switch` utasítást, így ha például átlós irányokat is hozzáadnánk a felsoroláshoz, mondjuk `.upAndLeft` néven, nem tudnánk, hogy frissíteni kell azt a `switch` utasítást, és tévesen azt a jelzést kapnánk, hogy egy nem iránygombot nyomtak meg. Ennek elkerülésére ahol csak lehet, jobb minden esetet explicit módon felsorolni.

```swift
lastPressed = .select
switch lastPressed {
case .up, .down, .left, .right:
  print("You pressed a direction button.")
case .a, .b, .select, .start:
  print("You pressed a non-direction button.")
}
// prints: "You pressed a non-directional button."
```

Mivel a fordító ismeri a felsorolás összes lehetséges értékét, az olyan hibákat is képes felismerni, mint az elgépelések, amelyek azokba a programokba lopóznak be, ahol stringekkel ábrázolják az értékeket.

```swift
lastPressed = .selcet
// Error: Type 'NESButton' has no member 'selcet'
```

## Metódusok

A Swift többi típusához hasonlóan a felsorolások is tartalmazhatnak metódusokat, amelyekkel a felsorolás az aktuális értéke alapján nyújthat funkcionalitást.

A metódusok a függvényekhez hasonlítanak, csak éppen a felsorolás törzsén belül definiáljuk őket, és az aktuális felsorolásértékhez kapcsolódnak. Elérésük _pont jelöléssel_ történik, ahol a felsorolásérték nevét egy pont (`.`) követi, majd a metódus neve és paraméterei.

A metóduson belül a felsorolásértékre `self` néven hivatkozhatunk, a típusszignatúrában pedig, ha paraméterként egy felsorolásértéket fogadunk vagy ilyet adunk vissza, a típusra `Self` néven hivatkozhatunk.

### Kezdőértékek

A kezdőértékek speciális metódusok, amelyekkel egy felsorolásértéket állítunk elő. Definíciójuk nagyon hasonlít egy metóduséhoz, csak éppen nincs `func` kulcsszó, nincs visszatérési típus, a nevük pedig `init` kell legyen, és a kezdőértéknek _mindenképpen_ a felsorolás egy értékét kell a `self`-hez rendelnie. A kezdőértékeket vagy pont jelöléssel hívjuk meg, vagy úgy, hogy a kezdőérték paramétereit a felsorolás nevének adjuk át.

A felsorolásoknak lehetnek bukó kezdőértékei is, amelyek opcionális felsorolásértékeket adnak vissza. Ezeket akkor használjuk, amikor a kezdőérték bemenete alapján lehet, hogy nincs érvényes érték, amire inicializálhatnánk, és ilyenkor a `self` helyett `nil`-t rendelhetünk. Ilyen esetekben a kezdőérték nevét `init?` alakban írjuk, bár a kérdőjelet elhagyjuk, amikor a kezdőértéket meghívjuk.

```swift
enum Coin {
  case heads
  case tails

  init(_ i: Int) {
    if i.isMultiple(of: 2) {
      self = .heads
    } else {
      self = .tails
    }
  }

  func flip() -> Self {
    switch self {
    case .heads: return .tails
    case .tails: return .heads
    }
  }
}

let tails = Coin.init(13)
// .tails
let heads = Coin(0)
// .heads
let anotherTails = heads.flip()
// .tails
```

### Nyers értékek

A felsorolások hordozhatnak magukkal egy belső értéket is, amelyet [_nyers értéknek_][raw-values] nevezünk. A nyers értékeknek mind ugyanolyan típusúaknak kell lenniük, amelyet a felsorolás definíciójában adunk meg. Így például `Character` értékeket rendelhetünk a `NESButton` felsorolásunkhoz, ha módosítjuk a definícióját:

```swift
enum NESButton: Character {
  case up = "⬆️"
  case down = "⬇️"
  case left = "⬅️"
  case right = "➡️"
  case a = "🅰️"
  case b = "🅱️"
  case select = "✅"
  case start = "🚦"
}
```

Itt a `: Character` tudatja a fordítóval, hogy a nyers értékek `Character` típusúak lesznek, és az egyes értékeket a nyers értékük hozzárendelése követi.

A nyers értékeket az egyes értékek automatikusan generált `rawValue` tulajdonságán keresztül érhetjük el.

```swift
NESButton.left.rawValue
// => "⬅️"
NESButton.b.rawValue
// => "🅱️"
```

A nyers értékekkel a felsorolástípus értékeit is inicializálhatjuk. Figyeljük meg, hogy a visszatérési érték opcionális, mivel érvénytelen nyers értéket is átadhatunk.

```swift
let upButton = NESButton.init(rawValue: "⬆️")
// => Optional(.up)
let invalid = NESButton.init(rawValue: "🙄")
// => nil
```

A Swift implicit módon is hozzárendelhet nyers értékeket `String` és `Int` típusú nyers értékekhez. Ha `String` a nyers érték típusa, akkor a nyers érték implicit módon az érték neve lesz stringként, kivéve, ha az implicit értéket egy explicit hozzárendeléssel felülírjuk.

Ha `Int` a nyers érték típusa, akkor a nyers érték implicit módon 1-gyel nagyobb lesz, mint az előző eset nyers értéke, kivéve, ha egy explicit hozzárendeléssel felülírjuk. Az első eset alapértelmezett nyers értéke 0, hacsak másképp nem adjuk meg.

```swift
enum Coin: String {
  case heads
  case tails = "eagle"
}

Coin.head.rawValue
// => "heads"
Coin.tails.rawValue
// => "eagle"

enum Dwarf: Int {
  case grumpy, sleepy, sneezy, happy = 8, bashful, dopey, doc
}

Dwarf.grumpy.rawValue
// => 0
Dwarf.sneezy.rawValue
// => 2
Dwarf.happy.rawValue
// => 8
Dwarf.bashful.rawValue
// => 9
```

### Kapcsolódó értékek

A Swift felsorolásai egy másik fajta információt is hordozhatnak, amelyet [_kapcsolódó értékeknek_][associated-values] nevezünk. A kapcsolódó értékekkel a felsorolás minden esetéhez más-más típusú érték is tartozhat, amelyet a felsorolásértékkel együtt hordozhatunk. A kapcsolódó értékek típusát a felsorolás deklarációjában adjuk meg. Ezeket az értékeket aztán mintaillesztéssel nyerhetjük ki és használhatjuk fel.

```swift
enum Suit: Character {
  case diamonds = "♦️", clubs = "♣️", hearts = "♥️", spades = "♠️"

  func print() {
    switch self {
    case .ace(let suit): print("A\(suit.rawValue)")
    case .king(let suit): print("K\(suit.rawValue)")
    case .queen(let suit): print("Q\(suit.rawValue)")
    case .jack(let suit): print("J\(suit.rawValue)")
    case let .number(suit, value): print("\(value)\(suit.rawValue)")
    }
  }
}

enum Card {
  case ace(Suit), king(Suit), queen(Suit), jack(Suit)
  case number(Suit, Int)
}

let aceOfSpades = Card.ace(.spades)
let twoOfHearts = Card.number(.hearts, 2)

aceOfSpades.print()
// prints "A♠️"

twoOfHearts.print()
// prints "2♥️"
```

Vegyük észre, hogy a felsorolásoknak vagy nyers értékeik, vagy kapcsolódó értékeik lehetnek, vagy egyik sem, de egyszerre a kettő nem.

### Rekurzív felsorolások

Ahogy az előző példában is láttuk, a felsorolás egy esetének kapcsolódó típusa bármilyen típus lehet, akár egy felsorolás is. Bizonyos esetekben szeretnénk, ha egy kapcsolódó érték típusa az őt tartalmazó felsorolás típusa lenne. Ezt a Swiftben úgy tehetjük meg, hogy az `indirect` kulcsszót minden olyan eset elé írjuk, amely ilyen [rekurzív kapcsolódó típusokat][recursive-enumerations] használ, vagy úgy, hogy az `indirect` kulcsszót az `enum` kulcsszó elé írjuk, így a felsorolás minden esete indirekt lesz.

```swift
enum BinaryTree {
  case leaf(value: Int)
  indirect case node(left: BinaryTree, value: Int, right: BinaryTree)
}

enum BinaryTree {
  case leaf(value: Int)
  indirect case node(left: BinaryTree, value: Int, right: BinaryTree)
}

let tree: BinaryTree = .node(left: .leaf(value: 1), value: 3, right: .node(left: .leaf(value: 5), value: 6, right: .leaf(value: 9)))
```
