# Bővebben a tömbökről

A tömböket a [Tömbök][arrays] fejezetben mutattuk be.
Ebben a dokumentumban további módokat mutatunk be a tömbök használatára.

## Egy tömb elemeinek összefűzése egyetlen stringgé

Az előző, tömbökről szóló fejezetben láttad a `"${myarray[@]}"` kifejezést az `@` indexszel, amellyel a tömböt az egyes elemeire lehet bontani.
Néha azonban az összes elemet egyetlen stringgé szeretnéd összefűzni.
Ehhez a `*` indexet használd:

```bash
echo "${myarray[*]}"
```

A kiterjesztést kötelező kettős idézőjelbe tenni.

A Bash az `IFS` beépített változó _első karakterét_ használja elválasztóként.
Alapértelmezés szerint a `$IFS` szóközből, tabulátorból és újsor karakterből áll.

```bash
myarray=(one two three four)
mystring="${myarray[*]}"
declare -p mystring
# => declare -- mystring="one two three four"
```

Az `IFS` változót módosítva más elválasztó karaktert is használhatunk:

```bash
myarray=(one two three four)
IFS=","
mystring="${myarray[*]}"
declare -p mystring
# => declare -- mystring="one,two,three,four"
```

~~~~exercism/advanced
<details><summary>
Ezt be is csomagolhatjuk egy függvénybe.
Kattints a részletekért.
</summary>

```bash
join() {
    local IFS=$1
    shift
    local elements=("$@")
    echo "${elements[*]}"
}

join ":" "${myarray[@]}"     # note, the "@" index
# => "one:two:three:four"
```

Ha az `IFS`-t a függvényen belül lokalizáljuk, nem kell elmentenünk a régi értékét, és visszaállítanunk az előző értékére a globális scope-ban.

Finomításként a speciális `"$*"` paraméter idézőjelben ugyanezt a funkciót nyújtja, így nem kell elmentenünk a függvény argumentumainak másolatát:

```bash
join() {
    local IFS=$1
    shift
    echo "$*"
}
```

</details>

<details><summary>
Ha nem használunk függvényt, az IFS módosítása egy alshellben jó módja annak, hogy elkerüljük a módosítását az aktuális shellben.
Kattints a részletekért.
</summary>

```bash
(IFS=","; echo "${myarray[*]}")
```

A zárójelek egy alshellt (az aktuális shell másolatát) hoznak létre. Amikor a zárójelek közötti parancsok befejeződnek, az alshell kilép, és a megváltozott IFS változó eltűnik.

Figyelem: ez nem fog működni: `IFS="," echo "${myarray[*]}"`, mert a paraméterkiterjesztés előbb történik meg, _mielőtt_ a shell alkalmazná a módosított IFS változót az `echo` parancsra.

</details>

## Tömbszeletek

Talán már láttad a `"${variable:offset:length}"` [paraméterkiterjesztést][parameter-expansion], amely a változó értékének egy _részstringjévé_ bővül.
Ugyanezt megtehetjük tömbökkel is, hogy a tömb egy szeletét kapjuk meg.

```bash
myarray=(one two three four)

subarray=("${myarray[@]:0:2}")
declare -p subarray
# => declare -a subarray=([0]="one" [1]="two")

subarray=("${myarray[@]:1:3}")
declare -p subarray
# => declare -a subarray=([0]="two" [1]="three" [2]="four")
```

A hossz rész elhagyása azt jelenti, hogy „a kezdőponttól a tömb végéig”:

```bash
subarray=("${myarray[@]:2}")
declare -p subarray
# => declare -a subarray=([0]="three" [1]="four")
```

## Tömb átadása függvénynek

Ez nem olyan egyszerű, mint más nyelvekben, amiket esetleg ismersz.
Két fő módszer van arra, hogy egy tömböt átadjunk egy függvénynek.

### Az elemek átadása

Az első módszernél a tömb összes értékét átadod, és a függvényben egy lokális tömbbe gyűjtöd őket.

```bash
myfunc() {
    local array_copy=("$@")
    # do stuff with array_copy
    declare -p array_copy
}

array_original=(11 22 33 44)
myfunc "${array_original[@]}"
```

A függvény tömbje az értékek _másolatát_ tartalmazza.
A függvényben a tömbön végzett módosítások nem jelennek meg a külső scope-ban.

### A tömb nevének átadása

Ez a módszer jobban hasonlít a „referencia szerinti átadás” lehetőségéhez, amit más nyelvekből ismerhetsz.
A tömb _nevét_ adod át stringként.
A függvény létrehoz egy lokális változót a „nameref” attribútummal.
Ez a lokális tömb és a globális tömb (amelynek a nevét átadtuk) _ugyanaz a tömb_.

```bash
myfunc() {
    # note the `-n` option
    local -n local_array=$1

    # do stuff with local_array
    for i in "${!local_array[@]}"; do
        printf '%d => %s\n' "$i" "${local_array[i]}"
    end

    # we can mutate it
    local_array+=(55 66 77)
}

array_original=(11 22 33 44)
myfunc "array_original"

# show the mutated array
declare -p array_original
# => declare -a array_original=([0]="11" [1]="22" [2]="33" [3]="44" [4]="55" [5]="66" [6]="77")
```

A nameref asszociatív tömbökkel és „skalár” változókkal (amelyek stringértéket tartalmaznak) is működik.

~~~~exercism/note
A függvényen belül a `declare -p local_array` nem túl hasznos.
Csak ennyit ír ki: `declare -n local_array="array_original"`.
A tömb részletes adatait úgy kapod meg, ha megvizsgálod az átadott tömb nevét: `declare -p "$1"`
~~~~

~~~~exercism/caution
Ügyelj rá, hogy a lokális tömb neve térjen el az átadott tömb nevétől.
A kód ettől még működik, de „körkörös névre hivatkozás” figyelmeztetéseket ír ki, például ilyeneket:

```bash
myfunc() {
    local -n a=$1
    local IFS=,
    echo "${a[*]}"
}

# same name as the function's local variable
a=(one two three)
myfunc a
```

## A pozicionális paraméterek „tömbszerűek”

Azokban a shellekben, amelyek csak a POSIX szabványnak próbálnak megfelelni (például az `ash` és a `dash`), nincsenek tömbök.
A legközelebbi megoldás a pozicionális paraméterek használata.

* A pozicionális paramétereket index alapján éred el: `$1`, `$2` stb.
* A `"$@"` kifejezéssel az egyes elemekre bonthatók
* A `"$*"` kifejezéssel egyetlen stringgé fűzhetők össze
* A paraméterek számát a `$#` adja meg

A `set` paranccsal rendelhetsz nekik értékeket:

```sh
set -- one two three
set -- "$@" four

for item in "$@"; do
    echo "do something with $item"
done
```

Ha a célod „hordozható” shell szkriptek írása, akkor a pozicionális paramétereket használod majd egy értékekből álló „lista” tárolására.
