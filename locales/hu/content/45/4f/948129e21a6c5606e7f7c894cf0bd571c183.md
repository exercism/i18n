# Bevezetés

A JavaScript rendelkezik egy beépített `Date` objektummal, amely dátumot és időt tárol, és metódusokat kínál a kezelésükhöz.

<!-- prettier-ignore -->
~~~exercism/caution
Ez a Java `java.util.Date` osztályán alapult, amelyet a 2010-es évek elején lecseréltek, de a visszafelé kompatibilitás miatt a JavaScript `Date` megmaradt.

Mivel a dátumokkal való munka általában véve nehéz, és mivel az időzónák kezelése rossz vagy egyáltalán nem létezik, sok könyvtár létezik, például a `moment.js`, a `day.js`, a `date-fns` és a `luxon`.
Ezek egyike sem érhető el az Exercism-ön.

A saját projektjeidben ne használj elavult / nem karbantartott csomagot, például a `moment.js`-t, hanem támaszkodj modernebb alternatívákra, mint a `luxon`, vagy a még nem széles körben elérhető [Temporal][mdn-temporal].
Ez a feladat a `Date`-re összpontosít, amely a JavaScript végéig releváns marad.

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal
~~~

## Létrehozás

A `Date` objektum a `Date` osztály egy példánya.
Létrehozható anélkül, hogy bármilyen argumentumot átadnál a konstruktorfüggvénynek.
Így egy olyan `Date` objektum jön létre, amely az aktuális dátumot és időt reprezentálja:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### Unix időbélyeg (szám)

Ha számot adsz át, azt `timestamp`-ként értelmezi a JavaScript.
Az időbélyeg egy egész szám, amely az **1970. január 1. [UTC][defn-utc]+0** óta eltelt **ezredmásodpercek** számát adja meg.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

Az ember azt várná, hogy a `new Date(0)` a „legkorábbi” dátumobjektumot hozza létre, de a JavaScript a dátumot a helyi időzónádra konvertálja, ami azt jelenti, hogy valójában csak azok kapják meg az [Unix-epoch][defn-unix-epoch] értéket, akik a [GMT / UTC+0][defn-gmt] időzónában vagy annak környékén vannak.

### ISO 8601 időbélyeg (string)

Átadhatsz egy dátumot reprezentáló string értéket a `Date` konstruktornak.
Az **egyetlen** olyan formátum, amely minden implementációban konzisztens, a nemzetközileg elismert és szabványosított, úgynevezett [ISO 8601 időbélyeg-stringek][defn-iso8601] [egyszerűsített változata][mdn-date-string-format].

Egy adott pillanat [UTC][defn-gmt] szerint így néz ki:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

Ahol a következő helyettesítések történnek:

| Kulcs | Leírás                                              | Alapértelmezés |
| ----- | --------------------------------------------------- | -------------- |
| YYYY  | A naptári év, 4 számjeggyel                         |                |
| MM    | A naptári hónap, 2 számjeggyel                      | 01             |
| DD    | A naptári nap, 2 számjeggyel                        | 01             |
| T     | Egy literál T betű, amely elválasztja a dátumot az időtől |           |
| HH    | Az órák 24 órás formátumban, 2 számjeggyel          | 00             |
| mm    | A percek, 2 számjeggyel                             | 00             |
| ss    | A másodpercek, 2 számjeggyel                        | 00             |
| mss   | Az ezredmásodpercek, 3 számjeggyel                  | 000            |
| Z     | Egy literál Z betű, vagy egy `+/-HH:mm` eltolás     |                |

A literál `Z` betű az UTC-t jelöli (nincs időzóna, nincs nyári időszámítás).

Mivel a legtöbb összetevőnek van alapértelmezett értéke, érvényes, ha a végéről kihagyunk részeket:

```text
YYYY-MM-DD
```

Alapértelmezésben az idő 00:00:00.000.

Ha az időbélyeg nem `Z`-re végződik, és nem is `+HH:mm`-re vagy `-HH:mm`-re (amely időzóna-eltolást jelez), akkor történelmi okokból a következő érvényes:

> Ha az időzóna-eltolás hiányzik, a csak dátumot tartalmazó formák UTC-időként, a dátumot és időt tartalmazó formák pedig helyi időként értelmeződnek.
> Az UTC-időként való értelmezés egy történelmi specifikációs hiba miatt van így, amely nem volt összhangban az ISO 8601-gyel, de a webes kompatibilitás miatt nem lehetett megváltoztatni.
> Lásd: [Broken Parser – A Web Reality Issue][ref-broken-parser].

### Date objektum

Egy létező dátumobjektum is használható konstruktorargumentumként.
Ez másolatot készít a létező `Date` objektumról, ugyanazzal a dátummal és idővel.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### Az egyes dátum- és időösszetevők megadása

Egy pusztán dátumot reprezentáló érték három szám átadásával hozható létre.
Egy dátumot és időt reprezentáló érték hat szám átadásával hozható létre.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

A második érték a `month`, amely januárnál `0`-tól indul, decembernél `11`-ig tart.

## `Date.parse()`

Találkozhatsz egy `Date.parse` nevű dátumértelmező függvényre való hivatkozással vagy említéssel.
Mivel ennek a függvénynek csak néhány invarianciája (igazsága) van, a többi része pedig nincs meghatározva (és így nem szabványos), nem érdemes használni.

## A `Date` összetevőinek elérése

Különféle metódusok vannak a dátumobjektumokon, amelyek a dátum összetevőit adják vissza:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

Ezek mindegyikének van egy hozzá tartozó `set` változata (például `setFullYear`), amellyel frissíthető az érték.
A túlcsorduló értékek átfordulnak a következő összetevőbe:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

Minden metódusnak van UTC-változata, amelyek figyelmen kívül hagyják a helyi időzónát.

## Átalakítás dátumból

A dátumobjektumoknak van egy `getTime()` metódusuk, amely az UNIX-időbélyeget adja vissza ezredmásodpercben, azaz az 1970. január 1-jei UTC szerinti éjfél kezdete óta eltelt ezredmásodpercek számát. Ezen kívül elérhető a `toISOString()` metódus is, amellyel egy dátumobjektumot ISO 8601 időbélyeg-stringgé alakíthatsz.

## Dátumok összehasonlítása

A nagyobb mint (`>`) és a nagyobb vagy egyenlő (`>=`), valamint a kisebb mint (`<`) és a kisebb vagy egyenlő (`<=`) közvetlenül használható két dátum között, vagy egy dátum és egy szám között.
Ez azért működik, mert a JavaScript megpróbálja a dátumot primitívvé konvertálni.

~~~exercism/advanced

Ez utóbbi ugyanaz, mint a [`date.getTime()`][mdn-date-get-time] meghívása.

Ha nem szeretnél erre a viselkedésre támaszkodni, először a `getTime()` segítségével alakítsd számmá.
