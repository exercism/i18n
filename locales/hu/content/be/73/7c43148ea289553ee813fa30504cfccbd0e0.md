# Névjegy

A Go, akárcsak sok más nyelv, rendelkezik mutatókkal.
Ha most találkozol először a mutatókkal, elsőre kissé rejtélyesnek tűnhetnek, de ha egyszer megszoktad őket, egészen egyszerűek.
A Go kulcsfontosságú részét képezik, ezért szánj rájuk időt, hogy igazán megértsd őket.

Mielőtt belemegyünk a részletekbe, érdemes megérteni, mire használjuk a mutatókat.
A mutatók segítségével memóriát oszthatunk meg a programunk más részeivel, ami két fő okból hasznos:

1. Ha nagy mennyiségű adatunk van, nagyon nem hatékony másolatokat készíteni belőle, hogy függvények között átadjuk.
   Ha ehelyett annak a memóriacímét adjuk át, ahol az adat tárolódik, drasztikusan csökkenthetjük programjaink erőforrásigényét.
2. Ha mutatókat adunk át a függvények között, közvetlenül elérhetjük és módosíthatjuk az adat egyetlen példányát, ami azt jelenti, hogy az egyik függvény által végzett változtatások azonnal láthatóvá válnak a program többi része számára, amint a függvény befejeződik.

## Változók és memória

Tegyük fel, hogy van egy közönséges egész típusú változónk, `a`:

```go
var a int
```

Amikor deklarálunk egy változót, a Go-nak helyet kell keresnie a memóriában, ahol tárolhatja az értékét.
Ez nagyrészt el van rejtve előlünk. Amikor le kell kérnünk az adott memóriaszakaszban tárolt értéket, egyszerűen a változó nevével hivatkozhatunk rá.

Például amikor `a + 2`-t írunk, valójában az `a` változóhoz tartozó memóriában tárolt értéket kérjük le, és adunk hozzá 2-t.

Hasonlóképpen, amikor az `a` memóriaszakaszában lévő értéket kell megváltoztatnunk, az értékadáshoz használhatjuk a változó nevét:

```go
a = 3
```

Az `a`-hoz tartozó memóriaszakasz mostantól a `3` értéket tárolja.

## Mutatók

Bár a változók segítségével hivatkozhatunk a memóriában lévő értékekre, néha hasznos tudni azt a **memóriacímet**, amelyre a változó mutat.
A **mutatók** ezeknek az értékeknek a memóriacímeit tárolják.
Egy mutató típusú változót úgy deklarálsz, hogy a mögöttes típus elé csillagot írsz:

```go
var p *int // 'p' contains the memory address of an integer
```

Itt egy `p` változót deklarálunk, amelynek típusa „mutató egy int-re” (`*int`).
Ez azt jelenti, hogy `p` egy egész szám memóriacímét fogja tárolni.
A mutatók zéróértéke `nil`, mert egy `nil` mutató nem tárol memóriacímet.

### Hogyan szerezzünk mutatót egy változóhoz

Egy változó értékének memóriacímét az `&` operátorral kereshetjük meg.
Például ha meg akarjuk keresni az `a` változó memóriacímét, és el akarjuk tárolni a `p` mutatóban, a következőt tehetjük:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Az érték elérése mutatón keresztül (dereferálás)

Ha van egy mutatónk, néha szeretnénk tudni, milyen érték tárolódik a mutató által képviselt memóriacímen.
Ezt a `*` operátorral tehetjük meg:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

A `*p` művelet lehozza a `p`-ben tárolt memóriacímen lévő értéket.
Ezt a műveletet gyakran „dereferálásnak” nevezik.

A dereferáló operátorral új értéket is adhatunk a mutató által hivatkozott memóriacímnek:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

A `*pa`-nak való értékadás megváltoztatja a `pa` által tárolt memóriacímen lévő értéket.
Mivel `pa` az `a` memóriacímét tárolja, a `*pa`-nak való értékadással valójában az `a` értékét változtatjuk meg!

Egy figyelmeztetés azonban: mindig ellenőrizd, hogy a mutató nem `nil`-e, mielőtt dereferálod.
Egy `nil` mutató dereferálása futásidőben összeomlasztja a programot!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Mutatók struktúrákra

Eddig csak primitív értékekre mutató mutatókat láttunk.
Struktúrákhoz is készíthetünk mutatókat:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

Úgy is csinálhattuk volna, hogy létrehozunk egy új `Person`-t, és rögtön eltárolunk rá egy mutatót:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Ha egy struktúrára mutató mutatónk van, nem kell dereferálnunk a mutatót ahhoz, hogy elérjük valamelyik mezőjét:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## A szeletek és a leképezések már eleve mutatók

A szeletek és a leképezések különleges típusok, mert a megvalósításukban már eleve mutatók vannak.
Ez azt jelenti, hogy ezeknél a típusoknál leggyakrabban nem kell mutatót létrehoznunk ahhoz, hogy megosszuk az értékeik memóriacímét.
Képzeld el, hogy van egy függvényünk, amely megnöveli egy leképezésben lévő kulcs értékét:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Ha létrehozunk egy leképezést, és meghívjuk ezt a függvényt, a függvény által a leképezésen végzett változtatások megmaradnak a függvény befejeződése után is.
Ez hasonló ahhoz, amit mutató használatával kapnánk, de figyeld meg, hogy ebben a példában nem használunk semmilyen hivatkozást vagy dereferálást, sem a mutatók szintaxisát:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

Ugyanez érvényes akkor is, amikor egy szeletben lévő meglévő elemet változtatunk meg.

Azonban az olyan műveletek, amelyek új szeletet adnak vissza, mint az `append`, különleges esetet jelentenek, és **lehet, hogy nem** módosítják a szeletet a függvényen kívül.
Ez abból adódik, ahogy a szeletek belül működnek, de ezt nem tárgyaljuk részletesen, mert ez egy haladóbb téma.
Ha igazán kíváncsi vagy, többet olvashatsz erről a [Go Blog: Mechanics of 'append'][mechanics-of-append] bejegyzésben.

## Mutatóaritmetika

Más nyelvekkel ellentétben a Go nem támogatja a mutatóaritmetikát.
Ez azt jelenti, hogy nem juthatsz el az egyik érték memóriacíméről egy másikéra úgy, hogy megnöveled a mutató értékét.
Ezért az alábbihoz hasonló kódrészletek érvénytelenek:

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
