# Módosíthatóság

A módosíthatóság egy adott kötés tulajdonsága a Rustban. Egy kötés vagy módosíthatatlan, vagy módosítható. Egy módosíthatatlan kötés értéke nem változtatható meg, egy módosítható kötés értéke viszont igen. Alapértelmezés szerint minden kötés módosíthatatlan.

## Kötések

Egy kötés egy adott, a forráskódban szereplő változónév és egy adott, futás közben létező memóriaterület közötti kapcsolat. Szigorúan véve a kötések csak a fordítás során léteznek: a fordítás előtt valójában nincs lefoglalt memória, a fordítás után pedig a gépi kód kizárólag memóriacímekkel dolgozik nevesített változók helyett.

A kötéseket jellemzően a `let` kulcsszóval hozzuk létre. Emellett függvényparaméterekből és bizonyos egyéb esetekben is keletkeznek kötések.

A kötéseknek többféle tulajdonságuk lehet, amelyek közül a legfontosabb a módosíthatóság. Egy kötés akkor módosítható, ha a hozzá tartozó memória értékét legálisan meg lehet változtatni. A Rust szigorúan nyomon követi és érvényesíti az egyes kötések módosíthatóságát, hogy segítse a programok helyességét, mégpedig úgy, hogy elutasítja azokat a programokat, amelyek helytelenül próbálnak módosítani egy olyan kötést, amelynek módosíthatatlannak kellene lennie.

## Módosíthatóság

A gyakorlatban a módosíthatóság gyakran egyszerű. Ha a kötés definíciójában használod a `mut` kulcsszót, megkapod a lehetőséget az érték megváltoztatására.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### Lefokozás módosíthatóból módosíthatatlanná

Egy kötést mindig le lehet fokozni módosíthatóból módosíthatatlanná. Ez a művelet transzparens.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### Előléptetés módosíthatatlanból módosíthatóvá

Általánosságban egy értéket bármikor elő lehet léptetni módosíthatatlanból módosíthatóvá, amikor a tulajdonjog átkerül.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

A `(1)` pontban a string tulajdonjoga `x`-től `y`-ra kerül, ami lehetővé teszi, hogy az értéket módosíthatóvá léptessük elő.

### Módosíthatóság függvényparaméterekben

Két különböző módon lehet egy függvényparaméter módosítható. Az első, egyben gyakoribb módszer a C-beli referencia szerinti átadásra hasonlít:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

Ebben a példában a módosíthatóságot három helyen jelöltük explicit módon. Mindhárom módosíthatósági jelölésre szükség van ahhoz, hogy a módosítható hivatkozások működjenek.
A `(2)` pontban az `x` kötést módosíthatóként deklaráljuk. Ez a kötés az érték legfelső szintű tulajdonosa.
A `(3)` pontban ezt az értéket módosíthatóan kölcsönözzük, hogy átadjuk az `increment` függvénynek.
Az `(1)` pontban egy új, módosítható `n` kötés jön létre a megfelelő hivatkozáshoz.

Létezik a paraméterek módosíthatóságának egy másik stílusa is, amely ritkább, de néha így is hasznos. Ebben a stílusban az érték a tulajdonunkban van, a kötés viszont módosítható.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

Ez a példa kevesebb explicit jelölést igényel, mert valójában tulajdonjog-átadásról van szó, beépített módosíthatóság-előléptetéssel. Azért működik, mert az `i32` `Copy` típus, amely transzparensen másolja az adatot.
Az `(1)` pontban deklaráljuk, hogy az `increment_internally` egy módosítható, saját tulajdonú, `n` nevű `i32`-t fogad paraméterként.
A `(2)` pontban az `x`-et az `1` értékhez tartozó módosíthatatlan kötésként deklaráljuk.
A `(3)` pontban az `x` egy új memóriabeli helyre másolódik. Az `x` módosíthatatlan marad. Az `n` módosítható.

Természetesen a formák kombinálhatók is, így módosítható kötést adhatunk egy módosítható hivatkozáshoz (`mut n: &mut i32` stb.), de erre ritkán van valóban szükség.

### Módosíthatóság `let` nélkül

A Rustban több szerkezet is (`if let`, `match` stb.) létrehozhat kötéseket. Ezek a kötések szintén lehetnek módosíthatók.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

Ez a példa először a `v = Some(2)`, majd a `v = None` értéket állítja elő.

## Változóárnyékolás

Lehetséges, sőt gyakran idiomatikus, hogy egy változónevet újra felhasználjunk, miközben egy adott értéket átalakítunk, több `let` utasítással újra deklarálva azt. Ezt nevezik árnyékolásnak.

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

Ez azonban nem a módosíthatóság esete: az eredeti értékek elvileg továbbra is jelen vannak. Nem `Drop` típusok esetén a fordító dönthet úgy, hogy egy memóriaterületet módosít új terület lefoglalása helyett. `Drop` típus esetén azonban soha nem teszi ezt, és akkor sem, ha a régi kötést ismét használjuk.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
