# Bevezetés

## Az `error` interfész

Go-ban a hibakezelés **nem** kivételekkel történik.
A hibák ehelyett olyan típusok hétköznapi _értékei_, amelyek megvalósítják a beépített `error` interfészt.
Az `error` interfész nagyon minimális.
Egyetlen metódusa van, az `Error()`, amely stringként adja vissza a hibaüzenetet.

```go
type error interface {
  Error() string
}
```

Amikor olyan függvényt definiálsz, amelynek futása közben olyan hiba történhet, amelynek el kell jutnia a hívóhoz, a visszatérési típusok közé fel kell venned az `error`-t.
Ha a függvénynek több visszatérési értéke van, a konvenció szerint az `error` mindig az utolsó.

```go
func DoSomething() (int, error) {
  // ...
}
```

## Egyszerű hiba létrehozása és visszaadása

Nem kell mindig neked megvalósítanod az error interfészt.
Egyszerű hiba létrehozásához használhatod az `errors.New()` függvényt, amely a szabványos könyvtár `errors` csomagjának része.
Egyetlen dolgot kell átadnod: a hibaüzenetet stringként, és az `errors.New()` gondoskodik róla, hogy létrejöjjön egy érték, amely tartalmazza az üzenetedet, és megvalósítja az `error` interfészt.

Ha a függvény hibát ad vissza, jó gyakorlat, ha minden más visszatérési értékre a zéróértéket adod vissza:

```go
func DoSomething() (SomeStruct, int, error) {
  // ...
  return SomeStruct{}, 0, errors.New("failed to calculate result")
}
```

~~~~exercism/caution
Ne feltételezd, hogy minden függvény zéróértéket ad vissza a többi visszatérési értékre, ha hiba történt.
A legjobb, ha abból indulsz ki, hogy hiba esetén egyik másik visszatérési érték használata sem biztonságos.
Kivételt csak azok az esetek jelentenek, amikor a dokumentáció egyértelműen kimondja, hogy a többi visszatérési értéknek hiba esetén is van jelentése.
~~~~

Ha egy ilyen egyszerű hibát több helyen is szeretnél használni, érdemes külön változót deklarálni neki, ahelyett hogy minden helyen az `errors.New`-t hívnád.
A konvenció szerint a változó neve `Err`-rel vagy `err`-el kezdődjön (attól függően, hogy exportált-e vagy sem).
Az ilyen hibaváltozókat gyakran _őrszem hibáknak_ nevezik.

```go
import "errors"

var ErrNotFound = errors.New("resource was not found")

func DoSomething() error {
  // ...
  return ErrNotFound
}
```

A hibára adj vissza `nil`-t, ezzel jelezve, hogy a függvény futása során nem történt hiba:

```go
func Foo() (int, error) {
  return 10, nil
}
```

## A hibák ellenőrzése

Ha olyan függvényt hívsz meg, amely hibát ad vissza, gyakori, hogy a hiba értékét egy `err` nevű változóban tárolod.
Mielőtt felhasználod a függvény tényleges eredményét, ellenőrizned kell, hogy nem történt-e hiba.

Hogy elkerüld a kódod „happy path” részének egymásba ágyazását, először a hibaeseteket kell kezelned.
A `==` és a `!=` operátorral összehasonlíthatjuk a hibát a `nil`-lel, és tudjuk, hogy hiba történt, ha az `err` nem `nil`.

```go
func processUserFile() error {
	file, err := os.Open("./users.csv")
	if err != nil {
		return err
	}

	// do something with file
}
```

A legtöbbször a hiba a hívási láncon felfelé visszaadódik, ahogy a fenti példában is látszik.
A hibát másképp is kezelheted: naplózhatod, és folytathatod valami mással.
Jó gyakorlat, ha a hibát vagy visszaadod, vagy naplózod, de soha nem mindkettőt.

Mivel a Go-ban a legtöbb függvény visszatérési értékei között szerepel egy hiba, az `if err != nil` mintával lépten-nyomon találkozni fogsz a Go-kódban.

## Egyedi hibatípusok

Ha a hibádban a hibaüzenet stringnél több információt szeretnél elhelyezni, létrehozhatsz egyedi hibatípust.
Ahogy korábban említettük, a Go-ban minden, ami megvalósítja az `error` interfészt (vagyis rendelkezik egy `Error() string` metódussal), használható hibaként.

Az egyedi hibatípus létrehozására általában egy structot használunk.
A konvenció szerint az egyedi hibatípusok neve `Error`-ral végződjön.
Az is a legjobb, ha az `Error() string` metódust pointer átvevővel definiálod; a magyarázatért nézd meg ezt a [Stackoverflow-hozzászólást][stackoverflow-errors].
Ez azt jelenti, hogy pointert kell visszaadnod az egyedi hibádra, különben nem fog `error`-nak számítani, mert a nem pointer érték nem biztosítja az `Error() string` metódust.

```go
type MyCustomError struct {
  message string
  details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.message, e.details)
}

func someFunction() error {
  // ...
  return &MyCustomError{
    message: "...",
    details: "...",
  }
}
```
